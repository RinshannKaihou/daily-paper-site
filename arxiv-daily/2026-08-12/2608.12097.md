> **一句话总结：** 提出 Graph-Structured Rubrics (GSR)，将评分规则在看到候选回答之前编译成一个带类型、含 criterion/operator 节点和唯一 sink 的有向无环评估图，用确定性算子 (Transform/Reduce/Gate) 按拓扑序组合各维度判断；在 GPT-OSS-120B 上，四个逐点数据集的 Exact Agreement 较最强 baseline 提升 0.62–6.75 个百分点，两个成对偏好基准上端到端准确率亦数值最高。

> **TL;DR:** GSR compiles a rubric into a response-independent typed evaluation DAG (criterion nodes + Transform/Reduce/Gate operators + unique sink) executed deterministically, then a no-LLM Readout maps the sink score to a pointwise grade or pairwise preference; under GPT-OSS-120B it lifts Exact Agreement over the best baseline by +5.44 points on UF–TruthfulQA (50.05% vs 44.61% G-Eval-style) and +4.78 on HelpSteer2 (43.75% vs 38.97% Prometheus-style), and reaches the numerically highest pairwise accuracy on MT-Bench (80.63% vs OpenRubric 79.86%) and RubricBench (83.62% vs 83.35%).

## 核心贡献

- **首个响应无关的编译框架**：在观察候选回答之前，把评分规则 (rubric) 编译成一个带类型的跨维度评估有向无环图 (DAG)，包含 criterion 节点、operator 节点、命名端口和唯一 sink。编译阶段拒绝环路、缺失端口、arity 不匹配以及类型不兼容的路由。
- **显式的组合语义**：criterion 级别的判断通过确定性的 Transform、Reduce、Gate 三类算子按拓扑序组合；Gate 算子可实现 cap/mask/veto 等非补偿性约束（例如安全违规强制封顶），避免后到的正面证据覆盖封顶。
- **逐点与成对共享同一接口**：pointwise (m=1) 与 pairwise (m=2) 仅在候选元数、任务契约和 Readout 上不同；pointwise 产出 1–5 分，pairwise 在固定 ε 契约下比较两条 sink 分数输出 winner/tie/abstain。Readout 不调用 LLM。
- **可审计、可重放**：编译出的程序是固定的，执行产生 audit trace（节点 id、槽序输入、输出、算子参数、证据引用），可从记录的 criterion 判断确定性重放整个组合过程。
- **统一的实证验证**：在 4 个逐点数据集 (UF–TruthfulQA, HelpSteer2, SummEval Relevance, BiGGen) 和 2 个成对基准 (MT-Bench, RubricBench) 上，GSR 在主指标上数值最优；并通过同 trace 消融证明增益来自图组合而非 criterion 激发。

## Key Contributions

- **First response-independent compilation framework** that turns a rubric specification into a typed cross-criterion evaluation DAG with rubric-derived criterion nodes, operator nodes, named ports, and a unique sink, compiled before any candidate response is observed.
- **Execution semantics** in which criterion-level judgments flow through deterministic TRANSFORM, REDUCE, and GATE operators in topological order; static validation rejects malformed graphs (cycles, missing ports, arity violations, type-incompatible routes, readout incompatibility).
- **Shared pointwise/pairwise interface**: the same criterion-node and operator semantics serve both regimes; only candidate arity (m=1 vs m=2), the task contract, and the deterministic Readout differ. Readout makes zero LLM calls.
- **Auditable and replayable composition**: the frozen graph yields an audit trace recording node ids, slot-ordered inputs/outputs, operator parameters, and evidence references, enabling deterministic replay of the decision path.
- **Unified empirical validation** across 4 pointwise and 2 pairwise benchmarks, plus same-trace ablations isolating the effect of graph composition from criterion elicitation, and a cross-model sensitivity study.

## Methodology

GSR is a three-stage interface: **Compile → Execute → Readout**.

**Problem partition (enforced at the invocation boundary).** The compile-time specification S = (x, r, z, τ) contains the task input x, rubric r, optional fixed reference material z, and task contract τ — but crucially excludes candidate responses Y and gold labels. Execution then receives X = (x, Y) with Y = (y1, …, ym). Compilation cannot access Y; execution cannot alter the accepted program. This separation is the key design choice: the composition policy is fixed before any response is seen.

**Compile.** Given a graph language Λ = (T, F, H, Π) — value types T, operators F, criterion-judgment procedures H, task defaults Π — an LLM synthesizes a declarative program (nodes, named-port edges, parameters, readout contract Rτ) restricted to catalogued types and operators. A deterministic validator V checks JSON parsing, acyclicity, sink reachability, ports, arity, routing type compatibility, and readout compatibility. If invalid, a repair loop feeds structured diagnostics δ(t) back to the compiler for up to K_rep rounds; the first structurally valid program is accepted with no manual semantic selection. The output program P = (G, Rτ), where G = (V, E, ρ) has criterion nodes C, operator nodes O, type-checked routing edges with port names and slots, and a unique sink ρ. Every node must reach ρ so no criterion judgment is dropped. Operators are grouped by composition kind: TRANSFORM (Ja → Jb), REDUCE (J1 × … × Jk → J), and GATE (J × Boolean → J, applying a declared cap/mask/veto).

**Execute.** Each criterion node c produces a candidate-aligned judgment vector jc = ((id(yi), jc,i)) for all m candidates (judgments may come from LLM calls, rule checks, verifiers, or human annotation, but must conform to the node's declared type; a criterion node never receives another node's judgment). Operators then run in topological order, consuming slot-ordered inputs at named ports and applying fixed parameters θω. Candidate identifiers are preserved through the graph, and the terminal node is type-checked to return aligned quality scores sρ,i ∈ Uτ.

**Readout.** Fixed during Compile, makes no LLM call. It checks identifier coverage, finiteness, and domain membership, then applies the deterministic task policy dτ. Pointwise → native score or ordinal label via fixed conversion/quantization. Pairwise → compare sρ,1 vs sρ,2 under an ε margin, resolving ties via a declared forced-choice/abstention rule. Scores are comparable only within the same program and task contract; GSR makes no cross-rubric or cross-model calibration assumption.

**Why a graph instead of prompt rules.** Leaving hierarchical composition inside LLM inference lets applicability checks be skipped, reductions applied out of order, or score caps enforced inconsistently. GSR externalizes that execution policy: e.g., factuality + completeness are reduced, then a safety flag gates the result so later positive evidence cannot override the cap.

## Results & Highlights

All main results use GPT-OSS-120B as judge, averaged over six runs.

- **Pointwise Exact Agreement (primary metric), Table 1.** On UF–TruthfulQA, GSR reaches **50.05%** vs the strongest baseline G-Eval-style **44.61%** (**+5.44 points**); MAE drops from 0.881 to 0.779. On HelpSteer2, GSR **43.75%** vs Prometheus-style **38.97%** (**+4.78 points**), MAE 0.845 vs 0.928. On SummEval Relevance, GSR **33.32%** vs Prometheus **32.70%** (**+0.62**); on BiGGen, GSR **44.51%** vs Prometheus **43.52%** (**+0.99**). GSR is best on Exact Agreement, Within-1 Accuracy, and MAE in every dataset block.
- **Pairwise end-to-end accuracy (primary metric), Table 2.** On MT-Bench, GSR **80.63%** vs OpenRubric **79.86%** (**+0.77**) at 99.87% coverage; TICK scores only **54.10%** because it produces a **34.66%** tie rate, and CheckEval **65.28%** with a 22.74% tie rate. On RubricBench, GSR **83.62%** vs OpenRubric **83.35%** (**+0.28**) at 99.91% coverage. The valid-only accuracy of TICK/CheckEval is actually higher (84–88%), but their heavy abstention means end-to-end accuracy collapses — GSR's advantage is as much about reliable decision-making as judgment quality.
- **Composition ablation (same criterion-level traces), Table 3.** Holding criterion judgments fixed and varying only composition: GSR beats Direct (one holistic score) by **3.51–9.25 Exact Agreement points**, and beats flat Weighted aggregation by **+5.79** on UF–TruthfulQA, **+3.26** on HelpSteer2, **+2.60** on BiGGen, **+0.36** on SummEval Relevance. This is the cleanest evidence that gains come from the compiled graph, not better criterion elicitation.
- **Cross-model sensitivity (HelpSteer2), Table 4.** With Qwen3.5-35B-A3B, GSR keeps a small Exact edge (+0.25 over Prometheus) and lowers MAE by 0.035. With GLM-4.7, GSR's Exact Agreement is **1.04 points lower** than Prometheus-style, though Within-1 is +3.58 higher and MAE lower by 0.071 — the graph transfers structurally but its metric profile is backbone-dependent.
- **Error geometry (Figure 3).** GSR's improvement is not a uniform correction: for reference score 5, mass shifts from mispredicting 4 to correct 5; for reference 4, some mass shifts from 4 to 5. This is consistent with Exact Agreement / MAE improving more uniformly than Pearson/Spearman.
- **Run stability.** Six-run standard deviations for Exact Agreement are 0.45–0.84 points (pointwise) and 0.30–0.51 (pairwise), so the larger pointwise margins exceed noise.

## Authors & Credibility

Authors are Xi Chen, Jie Mu, Mo Xuan, and Qun Shao from **Ant Group**. The paper is an arXiv preprint (v1, 12 Aug 2026), not yet peer-reviewed. The experimental protocol is unusually careful for an evaluation-methods paper: same-backbone controlled baseline adaptations (so gains are not from a stronger judge), six-run averaging with reported standard deviations, explicit metric definitions (Pairwise Accuracy counts ties/invalids as errors; Valid Accuracy conditions on coverage), provenance tracking, and no post-hoc forced choices. Baselines are contemporary and directly comparable (Prometheus-2, G-Eval, FLASK, OpenRubrics, TICK, CheckEval). The disclosure that generative AI assisted with language/formatting/consistency is transparent. The main credibility caveat is the single-judge-model main table (only GPT-OSS-120B) with cross-model checks limited to one dataset (HelpSteer2).

## Critical Assessment

- **Novelty is genuine but scoped.** The core idea — compiling a rubric into a response-independent typed DAG executed deterministically — is a real reframing of the "leave composition in the prompt" status quo, and the static type/validation discipline (rejecting cycles, arity mismatches, type-incompatible routes) plus audit-replay is a clean systems contribution. However, the operators themselves (weighted reduce, hard cap/mask/veto gates) are individually well-known aggregation primitives; the novelty is in the compilation framework and the unified pointwise/pairwise contract, not in new aggregation math.
- **Gains are real but uneven, and the headline overstates uniformity.** The large wins concentrate on UF–TruthfulQA (+5.44) and HelpSteer2 (+4.78); SummEval Relevance (+0.62) and BiGGen (+0.99) are within roughly 1–2 standard deviations of the six-run noise (σ = 0.45–0.84). The authors honestly label these as "competitive rather than decisively separated," but the abstract's "0.62–6.75" framing leans on the small-end numbers to claim breadth.
- **Pairwise margins are thin and partly a coverage artifact.** The +0.77 (MT-Bench) and +0.28 (RubricBench) wins over OpenRubric are small (≈2.5σ and ≈0.5σ respectively). More importantly, GSR beats TICK/CheckEval on *end-to-end* accuracy largely because those baselines abstain/tie 20–35% of the time while GSR has a ~0% tie rate — so part of the "win" is GSR's refusal to abstain under its native tie policy, not superior pairwise judgment. The authors are upfront that valid-only accuracy is higher for TICK/CheckEval, but a reader could easily misread Table 2 as a judgment-quality win.
- **Ablation has an honest negative.** On BiGGen and HelpSteer2 the flat Weighted variant has *better* Within-1 Accuracy / MAE / correlation than full GSR — GSR improves exact ordinal selection but does not dominate a flat rule on secondary metrics. The paper states this plainly rather than hiding it, which is commendable, but it tempers the claim that the compiled graph is uniformly better composition.
- **Missing ablations.** There is no operator-level ablation (which of Transform/Reduce/Gate drives the gain), which the authors acknowledge ("does not identify which operator or dependency accounts for the variation"). There is also no analysis of compilation failure rates or K_rep distribution — how often the LLM fails to produce a valid graph is unreported, despite being a core practical risk of the approach.
- **Cross-model evidence is one dataset deep.** The GLM-4.7 *negative* Exact Agreement result (-1.04) is a genuine red flag that the method's benefit is backbone-conditioned, yet cross-model testing is confined to HelpSteer2. Generalization to other judges and to smaller open models is unverified.
- **No faithfulness check of compiled graphs.** The paper explicitly notes that "whether the accepted graph captures the intended meaning of the natural-language rubric is tested through downstream agreement" — i.e., there is no direct verification that the LLM-synthesized DAG is semantically faithful to the rubric, only that it scores well. Given the compiler is itself an LLM invocation, this is a meaningful auditability gap.
- **Reproducibility is moderate.** Code/data release is not clearly stated in the paper body; metrics and seeds are documented, but the graph-synthesis LLM prompt and K_rep budget are not specified in the extracted text, which would block exact replication of the compile stage.

## Strengths

- Clean, well-motivated conceptual contribution: making cross-criterion composition an explicit, typed, statically-validated program rather than implicit prompt logic.
- Strong experimental hygiene: same-backbone baselines, six-run averaging, reported standard deviations, explicit metric definitions, and provenance tracking.
- The same-trace ablation (Table 3) is the right experiment to isolate composition from elicitation, and the flat-weighted comparison is a fair, strong control.
- Unified pointwise/pairwise interface via shared criterion nodes and arity-only differences is elegant and practically useful.
- Honest reporting of mixed results (confusion-shift trade-offs, secondary-metric losses to weighted aggregation, GLM cross-model reversal) rather than selective highlighting.

## Limitations

- Large pointwise gains concentrate on two of four datasets; SummEval Relevance and BiGGen margins are small and partly within noise.
- Pairwise improvements over OpenRubric are thin and partly attributable to GSR's near-zero tie rate vs heavy abstention by TICK/CheckEval.
- No operator-level ablation; the source of the composition gain is unidentified.
- Cross-model evaluation limited to a single dataset (HelpSteer2), with one backbone (GLM-4.7) actually hurting Exact Agreement.
- No direct semantic-faithfulness audit of the LLM-compiled graphs; compilation failure rates and repair-budget usage unreported.
- Main results use a single judge (GPT-OSS-120B); generalization to other judges and model sizes is unverified.
- The compile step adds an extra LLM call and its own nondeterminism per instance, increasing cost and latency over flat prompting.

## Relevance

对评估方法论与 LLM-as-a-judge 这一线研究高度相关：GSR 把"评分规则如何组合"从隐式的 prompt 内推理外化为可审计、可重放的类型化执行图，直接关系到奖励模型数据构造、基准评测的可复现性与模型选择流程的可靠性，属于 cs.CL/cs.AI 评估基础设施方向的前沿工作。

## Questions for Further Exploration

- Which operator (Transform vs Reduce vs Gate) accounts for the composition gain — does the non-compensatory Gate/cap mechanism drive most of the UF–TruthfulQA win, given its safety/factuality flavor?
- How often does compilation fail or exhaust K_rep, and what rubric characteristics predict failure? Is there a meaningful compile-failure rate on real-world, messy rubrics?
- Does the compiled graph remain semantically faithful to the authored rubric — can expert review or a held-out faithfulness probe validate that the DAG encodes the intended hierarchy?
- Would the pairwise advantage over OpenRubric survive a controlled tie-policy match (i.e., giving all methods the same forced-choice/abstention contract) rather than comparing under each method's native policy?
- Does the GLM-4.7 Exact-Agreement reversal generalize — is there a class of judge backbones (e.g., smaller or less instruction-tuned models) for which explicit graph composition systematically underperforms flat prompting?
- Can the framework extend to more than two candidates (listwise/ranking Readout with m > 2) without breaking the clean arity-only generalization?
