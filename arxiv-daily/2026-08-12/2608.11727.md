> **一句话总结：** Harness-IF 是首个在规则级别评估编码智能体多"指令面"（系统提示、工具描述、技能描述、项目文件、用户指令）遵循情况的基准，提出 Against-Prior Accuracy（AP-Acc）剥离"模型本来就会做"的混淆；在 12 个前沿模型上，每模型在反先验规则上都比总体低 3.6–7.4 个百分点，说明聚合分数系统性高估了真实遵从度。

> **TL;DR:** Harness-IF turns coding-agent instruction following into a rule-level measurement: 60 realistic multi-turn coding items instantiate 302 of a 642-rule library across 5 configurable instruction surfaces, scored over 2,160 runs (12 models x 3 rounds) with 40,104 verdict rows. Its Against-Prior Accuracy (AP-Acc) metric isolates rules that oppose a model's unprompted defaults; on the coding panel every one of the 12 frontier models (Claude-Opus-4.7 down to StepFun-3.5) scores 3.6-7.4 points lower on AP-Acc than on raw Acc (mean gap 5.81 over 37,616 verdicts), and prior control leaves the top build unchanged but swaps three adjacent rank pairs (2-3, 4-5, 11-12). A separate counterbalanced conflict pilot (E0, 9 builds) shows surface precedence does NOT follow prompt depth: system prompts, project files, and user instructions tie for first (rank 2.22) ahead of tool descriptions (3.78) and skill descriptions (4.56).

## 核心贡献

- **规则级而非任务级的评分基准**：构建了 642 条原子约束的规则库，其中 302 条被放置到部署编码智能体读取的 5 个可配置"指令面"上，覆盖 60 个真实多轮编码任务，最终 256 条规则获得执行证据驱动的逐规则判定（pass/fail/n/a），而非把整条轨迹压缩成一个任务成功与否。
- **控制"未提示默认行为"的新指标 AP-Acc**：只对那些被标注为"与模型默认行为相反（against-prior）"的规则计分；先验标签通过零注入探针（把目标规则抽掉、跑 9 个探针构建）或策展标注获得，从而把"真正遵从指令"与"本来就会这么做"区分开。
- **跨 12 个前沿模型的一致证据**：在整体面板和"公共支撑"子集上，所有模型的 AP-Acc 都低于 Acc；聚合分数因此按模型特异性地高估了遵从度（3.6–7.4 分的差距，跨模型两倍跨度）。
- **失败结构的细粒度刻画**：按"规则要求什么"分解 8,440 次失败——shortfall（要求行动/设下限）占 77.1%，overstep（禁止/设上限）占 20.8%；按家族分，output control 与 workflow 合计占 53.9%，output control 是 11/12 模型上得分最低的家族（70.9%，无一超过 79%）。
- **反平衡冲突实验 E0 揭示指令面优先级不遵循 prompt 深度**：system prompt / project file / user instruction 三者并列第一（rank 2.22），高于 tool description（3.78）和 skill description（4.56）；该排序在交叉 bootstrap、留一法、方向拟合、误差分配等多种稳健性检验下存活，但被解释为"跨构建的汇总趋势"而非普适层级。

## Key Contributions

- **Rule-level benchmark, not task-level**: A 642-rule library, of which 302 rules are placed across the five configurable instruction surfaces a deployed coding agent reads (system prompt, tool description, skill description, project file, user instruction; harness default held fixed), instantiated as 60 realistic multi-turn coding items. 256 rules receive at least one execution-grounded verdict (one per applicable rule per run) instead of a single task-success score.
- **Against-Prior Accuracy (AP-Acc) metric**: Scores only rules labeled as opposing a model's unprompted defaults. Prior labels come from a zero-injection probe (re-run the task with the target rule withheld across nine probe builds, consensus when >=5 of 9 agree; recoverable for 287 rules) and otherwise from curated annotation, separating genuine instruction following from coincidental alignment with what the model would do anyway.
- **Cohort-wide prior-alignment gap**: Across 12 frontier builds, every model scores lower on AP-Acc than on Acc under both the full panel and a common-support (identical observation keys) analysis with item-clustered intervals. The gap is model-specific (3.6-7.4 points, a twofold spread), so it does not cancel when builds are compared.
- **Failure localization**: Failures decompose along recoverable axes -- 77.1% are shortfalls of demanded behavior vs 20.8% oversteps, at comparable per-class failure rates (23.8% vs 20.8%), so the asymmetry is one of exposure (most operational rules ask for actions), not propensity. Output control is the lowest-scoring family (70.9%, lowest for 11 of 12 builds, no build clears 79%); commanding modalities (require/forbid) are hardest by modality (76.0%) vs preferences (90.6%).
- **Surface precedence pilot (E0)**: A counterbalanced conflict study on nine older builds (916 runs, four synthetic conflict pairs, deterministic-only scoring) finds a robust pooled ordering SP/PF/UI > TD > SD that is inconsistent with a prompt-depth account, surviving crossed-bootstrap (9,652/10,000), leave-one-pair/model-out, direction, weighting, and four error-assignment variants.

## Methodology

Harness-IF is built around **where a rule is delivered**, treating instruction surface as an evaluation dimension. It distinguishes six surfaces a deployed agent reads: Harness Default (HD, fixed and non-configurable), System Prompt (SP), Tool Description (TD), Skill Description (SD), Project File (PF, e.g., CLAUDE.md/AGENTS.md/CONTRIBUTING.md), and User Instruction (UI). A constraint is *admissible* on a surface only if that surface's authoring role could plausibly carry it (e.g., a branch-naming rule can sit in PF or SP but not in a tool schema); when several surfaces are admissible one is sampled uniformly with surface-appropriate phrasings that preserve semantics.

**Rule library (642 rules).** Rules are atomized from a manual survey of public GitHub project-instruction and contributor documents (CLAUDE.md, AGENTS.md, CONTRIBUTING.md, skill descriptions, tool schemas) plus LLM-assisted proposals under human review to fill under-covered taxonomy cells. Every rule is tagged along eight axes: Family (7: professional-writing, output-control, code-style, workflow, quantitative, conditional-logic, tool-use), Modality (7: require, forbid, conditional-require, limit-max, limit-min, prefer, allow), Prior (3: align/against/neutral), Observability (4), Verifiability (3), Universality (4), per-surface fit, and surface variants. Library prior mix is 18% align / 44% against / 38% neutral so the panel cannot be passed by defaults alone.

**Items.** From 80 candidates, quality/discriminativeness review retained 60 multi-turn items drawing on 8 of 13 scenarios (backend, frontend, systems, data/ML, automation, security testing, tool orchestration, technical documentation). Each item injects a pack of 25-35 rules, of which 10-27 are scorable given the opportunities the item creates; across the panel 302 distinct rules are instantiated and 256 receive >=1 verdict.

**Scoring.** Six methods selected at authoring time: regex, ast, cross-file, command-output, hybrid (deterministic pre-check + LLM refinement), and LLM-judge (rubric over full run, 3-vote majority at temperature 0.3 with GPT-5.2 as judge). Deterministic checks cover 13.3% of eligible verdicts; 86.8% of rows involve the judge. A cascade-dedup pass prevents one missing artifact from multiplying failures, and a cascade-fairness audit excludes design-gap rules missed by >=50% of agents.

**Metrics.** Acc (all eligible pass/fail instances), F-Acc (cohort-discriminative pairs only), DW-Acc (discrimination-weighted), and AP-Acc (against-prior subset only). A zero-injection auxiliary branch supplies prior evidence without entering core metrics. The main panel is 12 models x 60 items x 3 rounds = 2,160 runs and 40,104 verdict rows; E0 (surface precedence) and the non-coding extension use separate populations and metrics and are never pooled with the coding results.

## Results & Highlights

- **Headline leaderboard (Table 2, 12 frontier builds)**: Accuracy spans 72.1-85.9% (13.7-point range, std 4.2) and AP-Acc spans 66.1-78.6%. Claude-Opus-4.7 leads all four columns at Acc 85.9% / AP-Acc 78.6% (delta +7.3), ahead of GPT-5.5 (Acc 83.1% / AP-Acc 77.0%, delta +6.1) and Claude-Sonnet-4.6 (82.5% / 78.5%, delta +4.0, the smallest gap). Bottom: StepFun-3.5 (Acc 72.1% / AP-Acc 66.2%, delta +5.9) and Seed-2.0-Pro (73.6% / 66.1%, delta +7.4, the largest gap).
- **Against-prior gap is universal and model-specific**: Under the like-for-like binary definition the mean Acc-AP-Acc gap is 5.81 points over 37,616 eligible verdicts (including 19,449 against-prior) and is positive for all 12 models, ranging 3.6-7.4 points. A common-support analysis retaining 2,430/3,342 (72.7%) of observation keys keeps item-clustered 95% intervals for the paired gap positive model by model. Prior control leaves the top build unchanged but exchanges three adjacent rank pairs (2-3, 4-5, 11-12).
- **Deterministic-subset gap is larger**: In the fully deterministic subset the prior-alignment gap averages 13.09 points over 5,013 eligible verdicts (larger because that subset over-represents pattern- and command-checked families).
- **Failure decomposition (8,440 failures)**: Shortfall rules (require an action / set a floor) account for 77.1% of failures at a 23.8% per-class fail rate; overstep rules (forbid / cap) 20.8% at 20.8%; soft preferences 2.1% at 9.4%. By family: output control 27.6% (lowest pass rate, 70.9%, lowest for 11/12 builds, none clearing 79%), workflow 26.3%, code style 15.7%, conditional 12.4%, tool use 9.5%, quantitative 8.6% (highest at 82.6%).
- **Modality difficulty**: Commanding constraints (require/forbid) are hardest at 76.0% vs numeric bounds 79.4%, conditional 79.7%, and preferences 90.6%; the preference lead is consistent with default alignment.
- **E0 surface precedence (9 older builds, 916 runs)**: Pooled Bradley-Terry log-strengths SP +0.57, PF +0.65, UI +0.60, TD -0.53, SD -1.29; mean ranks SP/PF/UI = 2.22 (exact tie), TD 3.78, SD 4.56. Complete ordering appears in 9,652/10,000 crossed-bootstrap resamples (top-group-above-TD 98.81%, TD-above-SD 97.71%), and survives all leave-one-pair/model-out, direction, weighting, and four error-assignment variants.
- **Per-surface and reliability numbers**: Test-retest ICC is 0.725 across models and 0.599 across agent-item cells; a historical human-reference audit (a 5-vote configuration, not the released 3-vote panel) showed 69.0% agreement (kappa = 0.515 over 919 rows); a judge swap dropped agreement to 62.1% (kappa = 0.163).
- **Non-coding extension (40 cases, 5 domains, 1,428 trajectories)**: Case-macro pass rates span 65.8-84.8%, led by GPT-5.5 rather than the coding leader -- the instrument transfers beyond code, the ranking does not.

## Authors & Credibility

The work is a large collaboration led from ByteDance Seed, with co-first authors affiliated to Tsinghua University and Peking University (work done at ByteDance Seed), and a designated corresponding author (Shen Yan, sheny@bytedance.com). The benchmark scale is substantial and internally consistent: 2,160 agent-item-round runs and 40,104 rule-level verdict rows, with one script that recomputes every displayed number from the shipped verdict records. The authors commit to a public self-contained release (642-rule YAML library, 60 items with fixtures and scoring scripts, the full verdict panel, and analysis code) under Apache-2.0 (code) and CC-BY-4.0 (text/data). The paper is unusually forthright about measurement uncertainty -- it explicitly downgrades its own leaderboard to a "point ranking" because item-clustered intervals leave every adjacent comparison unresolved, and it labels the human-reference audit as "qualified evidence only" because the raw labels and sampling frame were not retained.

## Critical Assessment

- **Novelty**: Genuine and well-motivated. Reframing instruction following as a *rule-by-surface* measurement problem, and introducing a prior-control metric (AP-Acc), is a real methodological advance over IFEval/FollowBench/AgentIF (which concentrate rules in the user turn) and over SWE-bench/Terminal-Bench (which collapse to task success). The observation that 77.1% of failures are shortfalls, and that verifiers tuned to detect excess output address only ~a fifth of the failure mass, is a concrete, actionable finding.
- **Rigor**: Strong on robustness (common-support analysis, item-clustered intervals, crossed-bootstrap, leave-one-out, cascade-dedup, fairness audit) but the central measurement rests on a fragile judge. The authors disclose that 86.8% of verdict rows involve the LLM judge and that a judge swap yields only 62.1% agreement (kappa = 0.163) -- they are honest that this is "the dominant uncertainty in the measurement," which is why cross-model patterns (shared instrument) carry the claims and absolute levels are instrument-specific. The human-reference audit (69.0%, kappa = 0.515) was run under a *different* five-vote configuration on a related panel, and the raw joined labels, sampling frame, and adjudication record were not retained, so it is not a fully auditable calibration of the actual released three-vote panel.
- **Selection optimism (explicitly disclosed)**: The 60 evaluated items were selected from an 80-item working set using "observed difficulty and discriminativeness," which the authors admit may favor items that separate the pilot models. Combined with only 256 scored rules out of a 642-rule library (professional writing exercised only in the non-coding extension), the absolute rates should be read as conditional on this curated panel, not as population estimates.
- **AP-Acc interpretation**: The authors are careful to state AP-Acc is a *behavioral stratification* over observed/curated defaults, not a claim about training provenance; only 287 rules have a recoverable zero-injection consensus label (>=5 of 9 probe builds agree), the rest use curated labels of varying lineage. Five of the nine probe builds share an identifier with evaluated-panel models, an overlap the appendix quantifies but which slightly weakens the "independent prior" framing.
- **Per-surface caveat**: In Table 4, the user-instruction surface carries *only* against-prior placements (1,476 of 1,476 eligible verdicts), so its 54.5% pooled accuracy is explicitly not comparable to the other surfaces and is "reported for completeness." Readers comparing surfaces from the headline table alone could be misled; the caveat is buried in a footnote.
- **E0 generalizability**: The surface-precedence ordering comes from nine *older/different* builds (four of which are not in the main panel), four *synthetic* style conflicts, deterministic-only scoring, and a fixed temporal order (AB before BA) that "cannot be corrected retrospectively." The authors interpret it correctly as a pooled cross-build tendency, not a universal hierarchy, but the title-level "precedence does not follow prompt depth" claim rests on a narrow stimulus set.
- **Reproducibility**: High in principle (single recompute script, planned public release of verdict records and scoring scripts) but the headline numbers cannot be reproduced without API access to the 12 specific model snapshots (several were preview builds at collection time, e.g., qwen3.6-max-preview, hy3-preview) and the GPT-5.2 judge. Cross-model *patterns* are reproducible; absolute *levels* are tied to a specific judge.
- **Significance**: High for the agent-evaluation community. The "aggregate scores overstate compliance by a model-specific margin" finding and the failure-decomposition result are the kind of contribution that should change how coding-agent benchmarks report instruction compliance.
- **Red flags**: None severe. The main risks are (a) over-reading the leaderboard's fine ranks (the authors caution against this) and (b) generalizing the E0 surface ordering beyond synthetic style conflicts on older models.

## Strengths

- Conceptually clean reframing: instruction *surface* and instruction *hierarchy* are kept distinct, and the controlled-relocation design (same rule, move one surface) enables matched comparisons that no prior IF benchmark supports.
- AP-Acc directly addresses a real confound ("when a coding agent obeys a rule, it may simply have been going to do that anyway") that aggregate accuracy cannot.
- Exceptional measurement honesty: item-clustered intervals, judge-swap sensitivity, cohort-adaptive diagnostics, cascade handling, and an explicit "point ranking, not statistical ranking" caveat are all in the main text, not hidden.
- Failure decomposition is fully recomputable from released records (no tuned keywords, no catch-all bucket), and the retired twelve-bucket keyword taxonomy is openly discussed as a failed earlier attempt.
- Generous, self-contained release plan (verdict panel + scoring scripts + a single recompute script) lets readers verify every number offline without re-running agents.

## Limitations

- Small evaluated core: 60 items and 256 scored rules; the 642-rule library is only partially exercised and professional writing appears only in the non-coding extension.
- Judge dependence: 86.8% of verdicts rely on GPT-5.2; judge-swap kappa is only 0.163, so absolute compliance levels are instrument-specific.
- Human calibration is for a *different* five-vote configuration and lacks retained raw labels/sampling frame, so it is "qualified evidence only."
- Selection optimism from curating 60 items out of 80 for difficulty/discriminativeness.
- E0 surface ordering is from nine older builds and four synthetic style conflicts with an un-correctable fixed AB-then-BA temporal order; generalizing it beyond that regime is speculative.
- The non-coding extension uses a different metric (case-macro) and population and its ranking (led by GPT-5.5) does not match the coding ranking, so cross-domain transfer is unproven.
- AP-Acc prior labels are recoverable via zero-injection for only 287 rules; the rest rely on curated annotations of mixed lineage.
- Several model snapshots were previews at collection time; reproducing the exact panel requires access to those specific builds.

## Relevance

Harness-IF 直接命中"编码智能体在长程多轮工作流中是否真正遵守分散在各指令面上的操作性规则"这一评估盲点，对于构建/评测 Claude Code、Cursor 类智能体及多面指令栈（系统提示 + 工具/技能描述 + 项目文件 + 用户指令）的研究高度相关，AP-Acc 和 shortfall/overstep 失败分解可为智能体评测与 harness 设计提供可操作的度量。

## Questions for Further Exploration

- How stable is AP-Acc under a judge other than GPT-5.2, and would a human-validated three-vote panel materially change the leaderboard levels (given the disclosed kappa = 0.163 judge-swap sensitivity)?
- Does the 77.1%-shortfall failure asymmetry persist when the rule pack is rebalanced to equal exposure of shortfall and overstep rules, isolating propensity from exposure?
- Can the controlled-relocation design be run at scale (rather than only in E0's four synthetic conflicts) to estimate *paired* surface effects within the main panel, not just descriptive stratification?
- How do the surface-precedence results generalize beyond style conflicts (e.g., security- or correctness-relevant conflicts) and to current-generation builds rather than the nine older E0 models?
- Does prior-alignment training (explicitly instructing models on against-prior defaults) close the AP-Acc gap without hurting task success, and does it transfer across rule families?
- What is the interaction between instruction surface and rule family (the panel co-varies surface wording and family composition, so the surface x family cells are descriptive only)?
