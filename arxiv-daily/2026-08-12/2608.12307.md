> **一句话总结：** 本文提出"测试时强→弱能力迁移"范式——让强模型（builder）在不修改弱模型（target）参数的前提下，自动构建推理期脚手架（路由、确定性求解器、格式强制等），在四个心智理论基准（3900 题）上将 GPT-5.4-mini 的宏平均准确率从 0.49 提升到 0.91，且增益主要来自把不稳定推理卸载到确定性代码、按基准路由和答案格式强制，而非靠更长推理或更多采样。

> **TL;DR:** Instead of distilling capability through parameter updates, the authors let a strong builder model automatically construct an inference-time harness (routing, deterministic solvers, format enforcement) for a fixed weaker target model, using only a 5% validation slice. Across four Theory-of-Mind benchmarks (3,900-item hidden test set), the best scaffold lifts GPT-5.4-mini from a 0.488 macro-average to 0.912 (+0.423, +86.7% relative), with 100% of 57 runs beating baseline; the mean uplift is +0.275, approaching but not quite matching the human-designed UserHarness reference (0.939). Gains track cognitive-load offloading (determinism fraction vs. accuracy Pearson r=0.72) rather than longer reasoning or more sampling, and builder reasoning effort is a clean monotonic lever (Opus-4.7 Spearman ρ=0.77).

## 核心贡献

- **形式化"测试时强→弱脚手架"这一独立的能力迁移范式**：区别于知识蒸馏、on-policy 蒸馏、弱监督等通过更新弱模型参数的路线，本文研究强 builder 模型把可复用任务结构外化成推理期 harness，从而在不重训弱 target 的前提下提升其表现。
- **大规模系统实证（72 组运行）**：固定 target 为 GPT-5.4-mini（并补充 Gemini-3.5-flash 对照），覆盖 11 个 builder 配置、3 个平台（Cursor/Claude Code/GPT Codex）、每个设置重复 3 次，从效应量、稳定性、验证效率、平台效应、target 依赖、builder 推理努力、机制归因、认知负荷降低、剩余错误共 9 个维度做分析。
- **给出可操作的设计原则**：成功脚手架 = 近乎通用的"可靠性地基"（格式强制、贪心解码、路由）+ 高价值的"任务结构利用"（极性逻辑、结构化信念状态抽取、确定性求解）；builder 的内部推理努力是单调有效的杠杆，而平台效应只是二阶条件因素；脚手架对"有可纠正错误的弱 target"收益最大，对已接近天花板的强 target 反而可能产生干扰。
- **将脚手架构建重构为 builder 能力的评测维度**：在相同隐藏任务、相同验证预算、相同开放工作空间下，所得脚手架质量可衡量 builder 把推理外化成程序、工具、反馈回路和约束的能力。

## Key Contributions

- Formalizes **strong-to-weak scaffolding** as a distinct inference-time capability-transfer setting: a strong builder model constructs a persistent harness (routing, prompt templates, deterministic solvers, few-shot exemplars, verification passes, format enforcement) for a fixed weaker target, with the target's parameters frozen and the builder never seeing the hidden test set.
- Runs **72 controlled experiments** (11 builders × 3 platforms × 3 repeats, with two target models) on a 3,900-item aggregate of four Theory-of-Mind benchmarks (BigToM, Hi-ToM, MMToM-QA, MuMA-ToM), and analyzes the results along nine axes: effect size, run-to-run stability, validation efficiency, technique taxonomy, platform effects, target-model dependence, builder reasoning effort, mechanism attribution, cognitive-load reduction, and residual error structure.
- Shows that **every** builder configuration beats the no-scaffold baseline (100% of 57 GPT-5.4-mini runs; +0.275 mean uplift), with the best run (GPT-5.5 on GPT Codex) reaching 0.912 — surpassing raw GPT-5.4 (0.619) and GPT-OSS-120B, and approaching the human-designed UserHarness reference (0.939) on the same GPT-5.4-mini backbone.
- Distills **actionable design principles**: the reliability floor (format enforcement, greedy decoding, benchmark routing) is near-universal and enables higher performance, while task-structure exploitation (polarity/negation logic, structured belief-state extraction, deterministic solving) differentiates the strongest scaffolds; builder reasoning effort is a genuine monotonic lever (Spearman ρ=0.77), and platform choice is only a second-order, conditional factor.

## Methodology

The setting isolates a single builder `M_build` writing a harness for a fixed target `M_tar`. For each benchmark, 5% of examples are sampled as a labeled validation split `V` (195 items total) via a fixed random seed; the rest form a hidden test set `T` (3,705 items) that the builder never observes.

**Scaffold-building loop (Algorithm 1).** The builder is dropped into an agentic coding harness `H_build` (Cursor, Claude Code, or GPT Codex) with an initial workspace `W_0 = {R, C_demo, V}` containing a rule file, a target-call demo, and the validation set. It iteratively: (1) inspects resources, (2) proposes or revises a scaffold `S_k`, (3) runs `S_k(M_tar, V)` to get validation accuracy `a_k`, (4) diagnoses the error set `E_k` and appends `{S_k, a_k, E_k}` to the workspace. The builder is free to implement any inference-time procedure — prompt templates, benchmark routing, deterministic pre/post-processing, format enforcement, verification, few-shot retrieval, or symbolic solvers — as long as it exposes one entry point applicable to unseen examples. When done, it exports the entry point; a human evaluator runs it on `T` with no further builder intervention. Conceptually the builder searches `Ŝ = argmax Acc(S, M_tar; V)` as a proxy for the hidden `S★ = argmax Acc(S, M_tar; T)`.

**Benchmarks (text-only questions):** BigToM (1,200 binary belief/goal/action items), Hi-ToM (1,200 nested-belief items, recursion order 0–4, with deception and multi-room tracking), MMToM-QA (600 binary Bayesian goal/belief items), MuMA-ToM (900 3-choice multi-agent items). Primary metric is the unweighted macro-average of the four per-benchmark full-set accuracies; secondary metric is the number of validation evaluations (efficiency).

**Baselines:** (i) Vanilla — target called directly with a naive prompt (GPT-5.4-mini 0.488, Gemini-3.5-flash 0.761). (ii) Human-Inspired Harness — UserHarness (Qian et al., 2026), a human-designed ToM harness framework (0.939 / 0.941). The design yields 72 runs total: 3 platforms × 11 builders × repeats, with Opus-4.7 swept across four reasoning-effort tiers.

## Results & Highlights

- **Headline uplift (Table 1):** GPT-5.4-mini vanilla baseline macro-accuracy is **0.488**; mean over all 57 scaffolded runs is **0.763 (+0.275)**; the best single run (GPT-5.5 on GPT Codex) reaches **0.912**, an uplift of **+0.423 (+86.7% relative)**; 100% of runs exceed the baseline, and all 11 builder configurations improve on average.
- **Per-builder ranking (Fig. 3a):** best builders are GPT-5.5 (0.875 ± 0.036), Opus-4.7 x-high (0.856 ± 0.022), Gemini-3.5-flash (0.813 ± 0.047), Sonnet-4.6 (0.810 ± 0.069), Opus-4.7 high (0.807 ± 0.033); weakest are Codex-5.3 (0.675 ± 0.043) and Grok-0.1 (0.563 ± 0.036).
- **Per-benchmark vs. references (Fig. 3b):** the best scaffold beats raw GPT-5.4 (0.619) and GPT-OSS-120B on all four benchmarks; on BigToM it slightly exceeds the human-inspired UserHarness (**1.00 vs. 0.95**), but clear gaps remain on Hi-ToM (**0.80 vs. 0.87**), MMToM-QA (**0.84 vs. 0.98**), and MuMA-ToM (**0.88 vs. 0.96**).
- **Reproducibility (Aspect 1):** mean within-cell standard deviation is **0.036** — roughly an order of magnitude smaller than the +0.275 uplift — though the widest setting still has a repeat range of 0.201, concentrated in deterministic-solver strategies where one logic error can shift a 1,000+ item benchmark by tens of points.
- **Validation efficiency (Aspect 2):** builders use a median of **5** validation evaluations (range 2–15); best validation accuracy tracks final full-set accuracy with **Pearson r = 0.96** and only a small optimism gap (mean 0.021), whereas the number of refinement iterations is essentially uncorrelated with final accuracy (**r = 0.17**) — builder quality matters more than validation budget.
- **Technique prevalence (Fig. 6a):** format enforcement 100%, greedy/temp control 98%, benchmark routing 95%, forced CoT 79%, polarity/negation logic 79%, token-budget tuning 75%, hybrid fallback 60%, deterministic solver 54%, structured extraction 51%, few-shot 21%, verification/arbiter 12%, self-consistency 5%.
- **Platform effects (Aspect 4):** matched native-vs-Cursor comparison averages only **+0.013** with native winning 5/8 cells (paired permutation test **p = 0.484**); the platform×effort interaction shows the native advantage materializes only at higher reasoning effort (Opus-4.7 Claude Code vs. Cursor: −0.034 low, +0.045 medium, +0.038 high, +0.032 x-high).
- **Builder reasoning effort (Aspect 6, Table 3):** pooled across platforms, Opus-4.7 macro-accuracy rises monotonically from **0.711 (low)** → **0.793 (medium)** → **0.807 (high)** → **0.856 (extra-high)**, Spearman **ρ = 0.77**; the x-high tier significantly beats high (permutation **p = 0.013**) and low (**p = 0.002**); scaffold LOC grows from ~510–650 at low effort to ~1,000–1,300 at x-high.
- **Target dependence (Aspect 5):** scaffolding improves GPT-5.4-mini by **+0.262** (0.488 → 0.750) but Gemini-3.5-flash by only **+0.110** (0.761 → 0.871); realized uplift is strongly predicted by target headroom (1 − baseline) with **Pearson r = 0.75**; on the already-strong Gemini target, scaffolding regresses on 9/20 matched benchmark cases (Hi-ToM −0.04, MuMA −0.02 on average).
- **Self- vs. stronger-builder scaffolding (Fig. 10b):** GPT-5.4-mini building for itself still yields **+0.17 to +0.22**, but stronger builders add substantially more (up to **+0.31** on GPT Codex).
- **Item-level significance (Fig. 10a):** paired McNemar test on the 3,900 items gives **χ² = 1424.4, p < 10⁻⁴**; the best scaffold fixes **1,717** baseline errors while breaking only **105** previously-correct items; the union of top scaffolds covers **97%** of all baseline errors.
- **Cognitive-load reduction (Aspect 8, Fig. 11):** determinism fraction (share of items answered entirely by code/rules) correlates with final accuracy at **Pearson r = 0.72**; per-benchmark offloadability is BigToM ≈ 0.94, Hi-ToM ≈ 0.51, MMToM ≈ 0.44, MuMA ≈ 0.36; scaffold code size is only weakly related to accuracy (r ≈ 0.22).
- **Residual errors (Aspect 9, Table 5):** top scaffolds fix 83% of baseline-wrong items while breaking only 7% of baseline-correct items; BigToM is essentially solved (≥ 0.95 on every slice), but Hi-ToM accuracy falls from **0.999 at order 0** to **0.700 at order 4**, with deception dropping it further (0.772 vs. 0.829); MMToM qtype 2.1 ("which container/goal") is the hardest slice at **0.680**.

## Authors & Credibility

The work comes from **Salesforce AI Research** (Heinecke, Savarese, H. Wang, Zhao, Yang, Qiu, Qian's primary affiliation) with **UIUC** co-authors (Cheng Qian, Heng Wang, Heng Ji). The senior authors have a strong track record on agent evaluation and Theory-of-Mind harnesses: Cheng Qian and Heng Ji are authors of **UserHarness (Qian et al., 2026)**, the very human-designed ToM harness used here as the upper reference baseline — so the comparison to a 0.939 human-designed system is internally credible rather than a strawman. The experimental design is unusually thorough for an empirical paper: 72 controlled runs, pre-registered-style repeats (n=3), matched within-builder comparisons, paired McNemar tests, permutation tests with reported p-values, and a fixed 12-technique taxonomy coded across all runs. The paper is explicit about the associational (not strictly causal) nature of the technique-attribution analysis, and about the fact that builders exploit benchmark structure on BigToM. The use of frontier proprietary models (Opus-4.7, GPT-5.5, Gemini-3.5-flash, etc.) means exact numerical reproduction by third parties is essentially impossible, but the protocol itself (workspace contents, validation fraction, evaluation pipeline) is described in enough detail to reimplement with any comparable builder/target pair.

## Critical Assessment

- **Novelty:** The framing — strong-to-weak transfer *through the harness rather than the weights* — is a genuinely useful conceptual isolation of an idea that was implicit in DSPy, ADAS, Meta-Harness, and SWE-agent. The contribution is the *systematic study* (9 analysis axes, 72 runs), not the existence of scaffolding itself.
- **Rigor:** Strong on controls (matched comparisons, paired permutation/McNemar tests, fixed taxonomy coded across all 72 runs, three repeats per cell). Honest about the associational nature of technique attribution and about the small contrast groups (e.g., self-consistency n=3) that make some Δ values unreliable.
- **Reproducibility:** Mixed. The *protocol* is fully specified and uses only standard agentic coding tools, so a third party could rerun it. But every builder and target is a frontier proprietary model with no weights and no frozen snapshot, so the exact numbers (Opus-4.7 at 0.856, GPT-5.5 at 0.875) are not bit-reproducible — the paper does not discuss this drift risk.
- **Significance:** Practically meaningful for deployment: it quantifies that a well-designed harness can be worth more than upgrading to a much larger unscaffolded model (scaffolded GPT-5.4-mini beats raw GPT-5.4 on all four benchmarks). The headroom law (r=0.75) and the determinism-fraction mechanism (r=0.72) are reusable findings that should generalize beyond ToM.
- **Red flags / overclaiming:**
  - **Domain breadth is narrow.** All claims rest on four ToM benchmarks with heavy symbolic structure; the authors themselves flag this as future work, but the abstract's "nearly doubling average target-model performance" is a ToM-specific number that may not transfer to, say, code generation or open-ended reasoning.
  - **The BigToM "compilation" borders on benchmark exploitation.** On BigToM the builder discovers the answer is fully derivable from the observed/unobserved cue in the question and reaches **1.00 vs. UserHarness 0.95** — a near-perfect score that arguably measures how exploitable BigToM's templating is rather than any genuine ToM capability transfer. The authors defend this as legitimate builder capability, which is defensible, but readers should not interpret the BigToM number as evidence of improved *reasoning*.
  - **Stability is "strong but not perfect."** The widest setting has a repeat range of **0.201**, driven by single logic errors in deterministic solvers — a real deployment hazard that the "build two or three and pick the best" recipe only partially mitigates.
  - **The negative associations for greedy/temp control (−0.110) and verification/arbiter (−0.097) are explicitly noted as artifacts of tiny contrast groups (1 and 7 runs respectively)**, but they are still presented in the same table without being filtered, which a careless reader could misread.
  - **Scaffolding can backfire on strong targets (9/20 regressions on Gemini-3.5-flash)** — an important caveat that is somewhat buried in Section 5.6(iv) rather than surfaced in the abstract.
  - **No open-weight builder/target and no comparison to a non-LLM symbolic ToM solver**, so it is unclear how much of the gain is "LLM harness engineering" vs. simply rediscovering the inverse-planning machinery that classical Bayesian ToM models (Baker et al., 2009) already provided.

## Strengths

- Exceptionally systematic empirical design: 9 pre-specified analysis axes, 72 runs, matched within-builder comparisons, and statistical tests (McNemar, permutation) reported with actual p-values rather than just error bars.
- Clean, mechanistically interpretable headline findings: the headroom law (r=0.75), the determinism-fraction mechanism (r=0.72), and the monotonic builder-effort lever (Spearman ρ=0.77) are the kind of reusable empirical laws this literature has been missing.
- Intellectually honest about limitations: explicitly states that BigToM gains come from compiling the benchmark into rules, that attribution is associational, and that scaffolding can hurt already-strong targets.
- Reframes scaffold-building as an evaluation of builder capability (not just a deployment trick), which is a productive direction for the harness-engineering community.
- Practical, low-cost recipe (strong builder + high reasoning effort + modest validation + cognitive offloading + ensemble-and-select) that practitioners can apply immediately.

## Limitations

- **Single domain.** Only Theory-of-Mind benchmarks; generalization to math, code, retrieval, or open-ended agentic tasks is untested. The authors flag this as future work but the abstract's headline number is ToM-specific.
- **Proprietary, non-frozen models.** All builders and targets are frontier API models; exact numerical reproduction is impossible and results will silently drift as vendors update models.
- **Narrow validation slice.** Only 5% (195 items) is studied; the paper does not sweep validation fraction, so it is unknown whether the small optimism gap (0.021) holds at 10% or 20%, or whether builders would overfit a larger slice differently.
- **Associational attribution.** Techniques co-occur (format enforcement is in 57/57 runs), so the technique-vs-accuracy Δ values cannot support causal claims about which technique *causes* the gain.
- **Backfire on strong targets.** Scaffolding regresses on 9/20 Gemini-3.5-flash benchmark cases, so the recipe is not universally safe — it must be gated by measured headroom, which is an extra engineering burden.
- **No open-weight or symbolic-solver baseline.** Hard to disentangle "LLM-discovered harness" from "rediscovered classical inverse-planning."
- **Residual error floor is exactly where the task is genuinely hard** (Hi-ToM order ≥ 2 under deception, Bayesian goal inference), so scaffolding does not actually solve the core ToM problem — it compiles away the easy structure.

## Relevance

与用户对推理期计算、智能体 harness 工程和强→弱能力迁移的研究兴趣高度契合：本文把"让强模型自动为弱模型构建推理期脚手架"形式化为一种独立的能力迁移范式，并给出可量化的机制归因（认知负荷卸载 r=0.72、headroom 律 r=0.75），直接关联到 agentic 系统自演化、harness 即评测维度等前沿方向。

## Questions for Further Exploration

- Does the headroom law (uplift ∝ 1 − baseline, r=0.75) hold outside ToM — e.g., on GSM8K, HumanEval, or multi-hop QA where the "compilable structure" looks very different?
- How does the optimal validation fraction scale with benchmark size and question-type diversity? Is 5% robust because ToM templates are highly regular, and would noisier tasks require more?
- Can the "build N scaffolds and ensemble" recipe be made cheap by sharing a common reliability floor across builders and only ensembling the task-structure layer, reducing the 3× cost?
- The strongest builder (GPT-5.5) reaches 0.875 but the human-inspired UserHarness reaches 0.939 on the same backbone — what specific human harness features (e.g., explicit Bayesian inverse-planning modules) are the automated builders failing to discover, and could a targeted prompt close that gap?
- Since scaffolding backfires on near-saturated targets (9/20 Gemini regressions), can a *headroom-gated* scaffold that auto-disables on sub-tasks with baseline ≥ 0.9 recover the lost performance while keeping the gains?
- The determinism-fraction mechanism (r=0.72) implies a ceiling set by benchmark compilability — does adding a learned, non-deterministic belief-tracker (e.g., a small fine-tuned module) on top of the harness push past the residual error floor on Hi-ToM order ≥ 2?
- Could the strong-to-weak scaffolding setup itself become a standardized *builder benchmark* (as the paper proposes), and how would current open-weight builders (Llama, Qwen, DeepSeek) rank against the proprietary frontier on it?
