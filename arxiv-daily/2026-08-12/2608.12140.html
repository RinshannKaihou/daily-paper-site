01 Methodology

FQTree embeds quantization into training rather than applying post-training fixed-point conversion, so the model is optimized under the same numerical constraints used in hardware.

Tree topology and split thresholds are left untouched; only leaf outputs are quantized into a hardware-friendly form. Each newly fitted tree is quantized immediately, so later trees train against the residuals of the already-quantized ensemble — letting them compensate for quantization distortion instead of an ideal floating-point model.

A global step size s is fixed across the ensemble (classification depends only on relative output order). Each tree's range is handled individually, and the effective bitwidth bt = ceil(log2(max(vqint)+1)) emerges from its post-quant range — so high-impact early trees automatically get more bits, corrective later trees fewer. The per-tree offset removed during rebasing is folded into a single tree/class-level bias added once after accumulation, rather than carried as signed offsets through every path.

The QXGB compiler lowers the quantized ensemble through a DAIS IR extended with a MUX instruction (conditional selection instead of an unnatural multiply-accumulate template), then to a static dataflow graph: internal nodes → fixed-point compares → 1-bit decisions → MUXes; the ensemble → an adder tree with heterogeneous branch widths. Bit-exact emulation (Verilator) validates before implementation.

Leaf-value quantization (Eq. 1–3)
v' = round(max(s·(v − f(v)), 0))
global step s + tree-wise shift f(v), clipped non-negative
vqint = v' − min(v')
rebase → smallest leaf = 0 (the integer sent to hardware)
vqtrain = (vqint + min(v'))·s⁻¹ + f(v)

03 Strengths & limitations

Strengths

  • First end-to-end QAT + automatic hardware-generation flow for BDTs — closes the model↔FPGA gap.
  • BDT-specific math: magnitude-driven bitwidths emerge from training, not search or hand-tuning.
  • Bias folding is a small but high-leverage trick — removes signed offsets from the per-leaf datapath.
  • DAIS IR + MUX lowering is retargetable and gives bit-exact emulation for free.
  • Clean Pareto-frontier sweeps with a PTQ ablation isolating QAT's own contribution.
  • Open-source training algorithm and compiler framework.

Limitations

  • Only 3 small datasets; MNIST/NID use binarized features — feature quantization largely untested.
  • No regression, no large-scale tabular, only Virtex UltraScale+ family.
  • No component-level ablation of each quantization ingredient.
  • Fmax consistently lower than TreeLUT; latency wins = fewer cycles, not faster clock.
  • bmax pruning hyperparameter introduced but its accuracy–sparsity sensitivity unstudied.
  • TreeLUT metrics needed normalization; head-to-head JSC latency essentially tied.
  • Reproducibility leans on the authors' own compiler stack (da4ml/DAIS, HGQ, MetaML-Pro).
Credibility: architects of the prior da4ml/DAIS IR, HGQ/HGQ-LUT and MetaML-Pro lines — QXGB is a natural extension of an established stack, not a one-off. Code: github.com/ecs-bristol/FQTree + github.com/calad0i/qxgb. Funded by UK EPSRC, US DoE, NSF, AMD.

04 Questions for further exploration

  1. Behaviour on larger tabular benchmarks (Higgs, EPS) where features aren't binarized?
  2. Controlled ablation isolating global step vs. tree-wise shift vs. bias folding vs. magnitude bitwidth?
  3. Combine magnitude-driven bitwidths with HGQ per-parameter quantization in NN+BDT jet-tagging pipelines?
  4. Sensitivity to bmax, and auto-tuning under an explicit LUT budget?
  5. Does the lower Fmax compound unfavourably on smaller/older FPGA families?
  6. Reuse the DAIS MUX lowering for oblique trees, soft trees, or tree-based RL policies?
