> **一句话总结：** Spark-to-Paper 把"从研究想法到完整论文"的全流程实现为运行在现有编程助手（Claude Code）内的 13 个可组合技能，通过"预承诺实验设计 + 确定性门控 + 长程自我批判"在 8 个受控主题上达到 99.5% 引用有效性与 96.4% 图表可编辑性，并将捏造检测从单次草稿的 14% 提升到完整栈的 92%，单篇成本 8.1 美元、耗时 3.2 小时。

> **TL;DR:** Spark-to-Paper realizes end-to-end research-paper generation as 13 composable skills running inside an existing coding assistant (no separate agent platform), splitting model judgment from deterministic gates and pre-committing experiment design before results are observed. On 8 controlled topics it hits 99.5% citation validity and 96.4% figure editability, and a controlled ablation (36 injected fabrication probes) raises fabrication detection from 14% (single-pass draft) to 92% (full integrity+review stack) versus AI Scientist's 93% citation validity / 0% figure editability, at $8.1 and 3.2h per manuscript.

## 核心贡献

- **以"可组合技能"而非独立 Agent 平台的形式实现端到端论文生成**：13 个技能（规划、检索引用、写作、精修、评审、出图、汇编、实验执行等）在 Claude Code 内通过共享项目目录的工件协同，无需独立编排服务或图数据库，复用编程助手原生的读文件/执行代码/工具调用能力。
- **证据先行的实验设计与声明修订机制**：在看到结果前先冻结所需数据集、基线、指标、消融与结果表结构（轻量级预注册），实验只填补空缺证据；每条声明按 SUPPORTED / PARTIALLY-SUPPORTED / UNSUPPORTED / CONTRADICTED / NEEDS-CONFIRMATION 五级重新评估，负面与无效结果被保留而非删除。
- **确定性门控 + 长程自我批判双层纠错**：用六类确定性门（模板/蓝图/引用/稿件/图表/编译）强制可验证属性，再用 Self-Review（局部）与 Adversarial-Review（多视角、需引用具体段落且三向校验）处理语义层错误；并识别出"自我反驳循环"这一失效模式，将其限定为 7 轮，超限则记录为失败报告并换新想法，绝不强行把失败方向改写成"成功"。
- **可编辑矢量图表生成**：实验结果图直接由测量数据经绘图代码生成原生矢量 PDF；方法示意图先用图像生成模型出栅格视觉目标，再用 HTML 重建并迭代比对匹配，最终导出可编辑矢量 PDF，重建不可靠时回落栅格。
- **受控、可复现的评估**：在 8 个外部选定主题上预注册评估协议，从引用有效性、捏造检测、图表可编辑性、评审精度、跨模板鲁棒性到生成成本六个维度做量化评估，并提供消融与公开成本对照。

## Key Contributions

- **End-to-end paper generation as composable skills, not a standalone platform.** Thirteen skills (plan, cite, write, refine, review, figure, assemble, plus conditional experiment/data/figure-auxiliary skills) coordinate through persistent project artifacts inside Claude Code, requiring no separate orchestration server, graph DB, or scheduler — unlike AI Scientist, Agent Laboratory, Kosmos/Robin, or AutoResearchClaw.
- **Evidence-precommitted experiment design and claim revision.** Datasets, baselines, metrics, ablations, and result-table structure are frozen before any result is observed (a lightweight preregistration). The experiment stage only fills the minimal missing evidence; each major claim is then re-labeled on a five-level evidence scale and revised (retained / narrowed / removed / moved to limitations / queued for confirmation), with null and negative results preserved.
- **Two-tier correction: deterministic gates + long-horizon self-critique.** Six deterministic gates (Template, Blueprint, Citation, Manuscript, Figure, Compilation) enforce verifiable properties; Self-Review fixes local drift and Adversarial-Review mounts multi-perspective, passage-quoted, triply-checked challenges. The authors identify and bound a "Self-Refutation Loop" failure mode to 7 cycles, after which the trajectory is logged as a failure report and a new idea is tried rather than forcing a success narrative.
- **Editable vector figure pipeline.** Quantitative figures are plotted directly from measured data; method/explanatory figures are first rasterized by an image-generation model as a visual target, then reconstructed in editable HTML and iteratively matched before vector PDF export, with a fallback to raster when reconstruction is unreliable.
- **Controlled, pre-registered evaluation** across citation validity, fabrication detection, figure editability, review precision, cross-template robustness, and generation cost, with ablations and disclosed per-component cost.

## Methodology

Spark-to-Paper is organized by a lightweight `ts-paper` orchestrator into **Stage 0 (Input Routing)** plus **Stages 1–8**. Stage 0 inspects the input and selects one of two **result-integrity modes**: *Proposal Mode* (no measured results yet — unobserved values must stay unspecified) or *Data-Aware Mode* (quantitative statements must trace to supplied data/outputs). This mode propagates through every downstream stage so the same pipeline works before and after experiments.

- **Stage 1 Plan** converts input into a structured blueprint (research question, contributions, sections, notation, experimental design) read against the target venue's template spec.
- **Stage 2 Cite** retrieves and verifies references via DOI/arXiv metadata into a BibTeX file plus a claim–citation map — references are found, not recalled from memory.
- **Stage 3 Write** generates the full LaTeX manuscript from blueprint + bibliography under the active integrity mode.
- **Stage 4 Refine** revises the manuscript holistically (terminology, redundancy, length), then re-runs deterministic checks.
- **Stage 5 Review** runs multiple isolated adversarial passes (theoretical soundness, experimental design, systems validity); each proposed issue must quote a specific passage and survives three checks (problem actually present? already addressed elsewhere? out of scope?) before being returned for revision. Reviewing stops when an extra round yields no new surviving issues.
- **Stage 6 Figure** routes by role: measured-result figures → deterministic plotting code → vector PDF; method diagrams → image-gen raster → HTML reconstruction with iterative render-and-compare → vector PDF (fallback to raster).
- **Stage 7 Assemble** merges sections, bib, figures, and venue template into a compilable LaTeX project; the Compilation Gate bounds repair attempts.
- **Stage 8 Experiment (conditional)** maps manuscript claims to missing evidence, runs only feasible experiments, verifies provenance (config, dataset, seed, metric, logs, raw measurements), then re-evaluates claims and propagates revisions across abstract/intro/results/conclusion (abstract revised last).

The system runs on a Claude-family model inside Claude Code, but the design is stated to be model-agnostic given a coding assistant with comparable file/tool/code-execution abilities. Judgment (argumentation, relevance, evidence-vs-claim reasoning) stays with the model; mechanical operations (structure checks, citation validation, LaTeX compile, plotting, file checks) are deterministic scripts. The **Self-Refutation Loop** is explicitly bounded to 7 experiment–critique–revision cycles, after which the trajectory is terminated as a failure report (original idea, attempted methods, observed results, insufficiency reasons) and a new idea is started.

## Results & Highlights

- **Citation validity: 99.5% [98.4, 100]** over 384 references from 8 controlled-topic campaign papers, verified via *external* bibliographic metadata (not the pipeline's own citation checks). This beats the retrospectively audited released papers of **AI Scientist 93% (42/45)**, **AI Scientist-v2 91% (58/64)**, **Agent Laboratory 96% (27/28)**, the **single-pass LLM draft 81% (range 76–86)** on the same backbone, and even the **human-written-preprint reference 97.8% [94.6, 99.4]** over 320 references.
- **Figure editability: 96.4% [92.7, 98.6]** over ~1,900 ground-truth figure elements (excluding intentionally-rasterized figures) — versus **AI Scientist 0% (0/210)**, **AI Scientist-v2 3% (0–8)**, **Agent Laboratory 0% (0/30)**, and **human preprints 58% [44, 71]**. Spark-to-Paper exceeds humans here precisely because figures are vectorized by construction.
- **Fabrication detection ablation (36 injected probes, 10 failure families, fixed across configs):** single-pass draft **14% (5/36) [6, 29]** → gates-only **69% (25/36) [53, 82]** → gates+self-review **81% (29/36) [65, 90]** → full stack (gates+self-review+adversarial) **92% (33/36) [78, 97]** — a +78-point absolute gain over the single-pass baseline; the largest marginal detection gain (+55 pts) comes from adding deterministic gates.
- **Adversarial-review precision: 74% (42/57 verified) [61, 83]** — of 60 sampled raised issues (3 "cannot tell" excluded), 74% correspond to independently verifiable problems; i.e., ~26% are spurious critiques.
- **Generation efficiency:** full system uses **11.9M tokens [10.2, 13.7]**, costs **$8.1/manuscript [6.9, 9.6]**, and takes **3.2h wall-clock [2.6, 3.9]** — more expensive than the single-pass draft ($0.66 / 0.11M tokens / 16 min) but cheaper per-attempt than AI Scientist-v2 (~$20–25) and far faster than AI Scientist's ~12h/batch.
- **Ablation marginal cost (3 paired topics):** gates add +8.1M tokens / +$5.3 (the dominant overhead); self-review adds +1.1M / +$0.6; adversarial review adds +2.6M / +$1.6 — quality layers beyond gates are comparatively cheap.
- **Case study (Fig 6):** on a one-paragraph clinical-screening proposal, the generated paper corrected an injected wrong metric (Accuracy) by showing calibrated probabilities rarely exceed 0.5 at 0.049 prevalence so F1 collapses; on a PM2.5/energy-load forecasting proposal with an injected expectation that causal models would match plain recurrent nets, the system's empirical results contradicted that prior (VMD-GRU reached only 24.1 RMSE), prioritizing evidence over the misleading user prompt.

## Authors & Credibility

The work comes from the **Vast Intelligence Lab** (with a University of Technology Sydney affiliation for co-author Biao Wu) and lists a public code repository (`github.com/Spark-To-Paper-Skills/spark-to-paper-skills`). The corresponding author is Wenhao Wang. Four authors share equal contribution. The paper is unusually self-aware about overclaiming: it explicitly flags that positioning a new system "between two established poles is easy to assert and harder to substantiate, since it invites exactly the kind of overclaim this paper otherwise argues against," and presents Table 1 / Fig 1 as checkable against each compared system's own public docs rather than a measured benchmark. The evaluation methodology is pre-registered with an external timestamp, uses independent (external) verification for citation validity rather than the in-loop checker, and reports Wilson 95% intervals and cluster-bootstrap intervals rather than cherry-picked single runs. However, all of the central quality numbers (citation validity, fabrication detection, review precision) are measured by the authors' own instrumented runs on topics they selected, and no third-party or peer-review-based validation of the generated manuscripts is reported.

## Critical Assessment

- **Novelty:** Genuine and well-scoped. The contribution is not "another autonomous scientist" but the specific architectural bet that the full research-to-paper loop can be decomposed into skills running inside an *existing* coding assistant with no standing infrastructure — combined with two concrete mechanisms (pre-committed experiment tables as lightweight preregistration, and the named/bounded Self-Refutation Loop). The editable-vector figure pipeline (raster visual target → iterative HTML reconstruction) is a small but real novelty not present in AI Scientist / Agent Laboratory.
- **Rigor:** Strong on internal consistency and disclosure. The ablation holds the 36-probe injection set, injection point, and detection procedure fixed across all four configurations, so row-to-row differences isolate the quality stack. Cost deltas are explicitly measured on the 3-topic paired subset and the authors warn the cumulative ablation cost need not equal the 8-topic mean — an honesty rarely seen.
- **Weak baselines / comparability:** The head-to-head against prior systems is **retrospective audit, not controlled re-run**. AI Scientist / v2 / Agent Laboratory were *not* re-run on Spark-to-Paper's backbone, topics, or pricing; their numbers come from each system's own released artifacts and reported costs under different assumptions. The 99.5%-vs-93% citation-validity gap therefore conflates system quality with model backbone, topic difficulty, and era. The authors say this explicitly but a reader can still over-read Table 3 as a fair fight.
- **Small / artificial evaluation instruments:** Fabrication detection rests on **36 seeded probes** (10 failure families) — a useful but narrow probe set whose coverage of real hallucination modes is unmeasured. Review precision is computed over **57 issues** (60 sampled, 3 excluded) — a small denominator for a 74% [61, 83] claim. The Fig 6 case study's "incorrect expectations" are author-injected, so it demonstrates revision capability under a controlled prompt rather than organic scientific disagreement.
- **Missing ablations:** No ablation of the **Self-Refutation Loop bound (7 cycles)** — why 7? No measurement of how often the bound is hit, how many trajectories fail per successful paper, or the success rate of "new idea" restarts. No ablation isolating the **HTML figure-reconstruction** step (how often does it fall back to raster, and what is the per-figure match-convergence count?). No test of the **model-agnostic** claim — everything runs on Claude; the design-portability assertion is untested empirically.
- **What is NOT measured:** Whether the generated papers would pass peer review, whether their scientific claims are *correct* (citation validity ≠ correctness of the cited claim), or whether the contributed methods are novel versus prior art. Citation existence and figure editability are surface/Artifact-level metrics; they say little about scientific value. The showcase Fig 5 page/reference/figure counts are explicitly self-reported by the maintainers, "not an independent measurement."
- **Red flags:** None egregious. The 96.4% figure-editability exceeding the human 58% is not a fair "beats humans" win — it is structural (Spark-to-Paper vectorizes by construction). The $8.1 cost is Claude-pricing-specific. Adversarial-review precision of 74% means a quarter of raised issues are noise, which could waste revision budget on long papers.

## Strengths

- Infrastructure-light deployment is a real practical advantage: skills inside Claude Code with no orchestration server / scheduler / graph DB lowers the barrier to adoption and reproducibility versus AI Scientist-family systems.
- The **judgment-vs-execution separation** and the **six deterministic gates** make a large fraction of quality assurance directly checkable and model-independent, which is a clean and reusable design pattern.
- **Evidence-precommitment** (freezing table structure before results) is a principled, cheap anti-hacking mechanism borrowed from clinical preregistration and applied to LLM research generation — a genuinely good idea.
- Naming and bounding the **Self-Refutation Loop**, and refusing to rewrite failed trajectories as successes, is intellectually honest and directly counters the "forced success narrative" failure mode common in autonomous-research agents.
- Pre-registered protocol, external citation verification, disclosed costs, and explicit caveats on positioning raise the credibility bar for this subfield.

## Limitations

- **No controlled re-run of baselines**: head-to-head numbers mix system, backbone, topic set, and pricing era; the comparison is suggestive, not decisive.
- **Tiny probe/sample sizes** for fabrication detection (36 probes) and review precision (57 issues); generalization to broader hallucination/issue distributions is unestablished.
- **Unvalidated scientific value**: citation *existence* and figure *editability* are artifact metrics; whether claims are *true* or *novel* is not assessed, and no peer-review or expert-judgment evaluation is reported.
- **Single-model, single-platform empirical test**: only Claude in Claude Code; the model-/assistant-agnostic design claim is asserted, not demonstrated.
- **Arbitrary Self-Refutation bound** (7) and no published failure/restart statistics — the cost of the "try a new idea" recovery loop is opaque.
- **HTML figure reconstruction** quality and fallback rate are described qualitatively but not quantified (how often does it retain the raster?).
- Cost ($8.1) and runtime (3.2h) are specific to current Claude pricing and a single hardware setup; amortized cost including failed trajectories is not reported.

## Relevance

直接命中自主科研智能体（autonomous research agents）与 LLM agent 工具化这条主线，与本工作关注的 cs.CL/cs.AI 方向高度相关：它把"研究-到-论文"全流程做成可组合技能、用确定性门控 + 自我批判压制 LLM 幻觉与捏造引用，正是当前 Agent 可靠性长程推理与证据接地（evidence grounding）研究的核心议题，对设计可信的长程科研工作流有直接参考价值。

## Questions for Further Exploration

- How often is the 7-cycle Self-Refutation bound actually hit, and what is the end-to-end success rate (successful papers per attempted idea), including failed trajectories in the amortized cost?
- Would the fabrication-detection gains (14% → 92%) hold on a larger, independently constructed probe corpus, or do they reflect the specific 36-probe/10-family distribution?
- Can the claim-admission protocol's *semantic* labeling (currently model-based) be partially grounded by automated retrieval against the cited source text, to reduce reliance on the same model that wrote the claim?
- How does performance change across non-Claude backbones and non-Claude-Code assistants — is the skill-based decomposition robust to weaker tool-use ability?
- What is the HTML figure-reconstruction fallback rate, and how many match iterations are needed on average to reach an accepted vector PDF?
- Do the generated papers survive blind expert peer review, and how do expert-rated claim correctness and novelty compare to human-written preprints on the same topics?
