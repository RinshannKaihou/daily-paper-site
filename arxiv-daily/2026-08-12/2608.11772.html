Diagnose an agent's dominant failure mode first, then deploy a matched cost-aware recovery policy — not uniform context.

Methodology, distilled

How DARC is built

DARC models a task family X with a recovery-intervention library R (action guards, API procedures, induction rules, retrieval budgets). A harness for failure mode m is the tuple H_m = (m, R_m ⊆ R, π_m) — a mode, an admissible subset, and an ordered deployment policy.

STAGE 1 — FAILURE DIAGNOSIS. Run the base agent on development tasks and measure observable failure signatures (invalid actions in ALFWorld, missing cross-app procedures in AppWorld, exact-format violations in Finance). These pinpoint a single dominant mode and fix R_m. Diagnosis is frozen at the task-family level — auditable, no test-time updates, no observation of test labels. The output is a constrained recovery space, not a longer prompt.

STAGE 2 — POLICY DISTILLATION. On training tasks, fill an evidence matrix E_{i,j} = (success, cost) using the task verifier as the success signal — never answer labels. A short-circuit policy tries interventions in order and halts at the first success; the deployed π maximises J = succ(π) − λ·max(0, cost − τ). Because the success term is monotone submodular, short mode-matched policies capture most reachable recovery, and diagnosis shrinking the search space tightens the uniform-convergence rate.

Strengths & Limitations

Side by side

+ Strengths

  • Clean reframing of self-correction as recovery-interface design, with a formal harness tuple and explicit cost-success objective.
  • Diagnosis shrinks the policy search space (submodular coverage + uniform-convergence argument) — principled reason short policies suffice.
  • One protocol yields three structurally different harnesses across action-validity / procedural / format failures.
  • Cost-efficient, not just accurate: steps −54%, invalid actions −93%, latency 155s→10s.
  • Intellectual honesty: matched-info audit, 2×2 factorial, bootstrap CIs with Holm-corrected paired tests.
  • Clean cross-task transfer: frozen policies retain ~89–96% of target-tuned accuracy.

! Limitations

  • One dominant failure mode per benchmark is an idealisation; mixed-mode routing is left to future work.
  • Harnesses are substantially hand-engineered per domain — high engineering cost, limited out-of-box transfer.
  • AppWorld gains are not uniformly significant; ACE is competitive on several Test-Challenge metrics (Qwen backbones).
  • Weight-space extension is single-seed, small gains; OPSD does not beat standard GRPO.
  • Diagnosis is static and task-family-level — no online router, cannot adapt to distribution drift.
  • Relies on enumerated bounded policy class + resettable deployment semantics; non-resettable real environments untested.

Open questions for further exploration

  1. Can a learned instance-level router replace per-family diagnosis when multiple modes co-occur in one task?
  2. Restriction-alone collapses ACE — is there a principled ranked-action benefit for baselines lacking a diagnosis guard?
  3. How sensitive are Finance results to XBRL/FiNER tag distribution; does the non-monotonic k-curve replicate?
  4. Empirical link between library size, diagnosis tightness, and the n needed to stabilise π*?
  5. Could DARC-GRPO gains improve with more seeds / a stronger base, or does OPSD underperformance signal a fundamental mismatch?
