> **一句话总结：** 本文提出 Convergent Detour Hijacking (CDH)，一种仅需发布单个静态技能（coordinator）的供应链攻击，利用渐进式披露机制把"技能描述影响选择"与"技能正文影响规划"两个阶段耦合起来，在不破坏任务完成的前提下诱导 Agent 绕行多余的良性技能，在 DeepSeek-V4-Pro 上使 token 消耗增加 66.91%、端到端执行时间增加 92.45%，攻击成功率（ASR）在 6 个模型上达到 70.82%–80.51%。

> **TL;DR:** CDH is a publisher-only, runtime-independent supply-chain attack on progressive-disclosure skill agents (OpenClaw, 53 skills): a single static "coordinator" skill uses an optimized description to win co-selection and a semantically aligned body to fabricate bounded prerequisite/verification dependencies on benign native skills, then re-enters the original task. On a 491-task held-out benchmark, the matched coordinator is selected in 80.02% of DeepSeek-V4-Pro tasks, raising token consumption by +66.91% and wall-clock time by +92.45% versus the clean baseline while keeping task-completion within 1.5pp; ASR reaches 70.82%–80.51% (single-task) and 71.19%–82.81% (multi-turn) across six LLM backends — showing that a correct final answer does not imply trajectory integrity or cost safety.

## 核心贡献

- **跨阶段攻击的形式化定义。** 首次把"基于技能的 LLM Agent 渐进式披露（progressive disclosure）"中的两个顺序控制点——选择阶段的元数据（description）与规划阶段的指令正文（body）——耦合起来，提出并形式化了 Convergent Detour Hijacking (CDH)：一个发布者控制的静态技能如何在不替换原生技能、不破坏任务完成的前提下，诱导出一条"吸引—绕行—汇聚（attract–detour–converge）"的多余执行轨迹。给出了精确的四元指示函数定义（h 被加载、clean 路径技能全部保留、至少新增一个原生技能、两条件均完成任务）与 ASR 指标。
- **黑盒、仅靠静态文本的攻击方法。** 提出基于 pilot 反馈的黑盒描述优化流程：用每组 5 个 pilot 任务（共 45 个）迭代优化 coordinator 描述以获得"协同选择（co-selection）"而非"替换"原生技能；并设计一份有界的 coordination runbook（依赖拓扑、遗漏后果、强制框架、证据事件分解、有界验证、结构化打包六原则），把"局部看似合理但全局不必要"的依赖插入规划阶段。整个攻击不含可执行负载、不访问模型内部、不控制运行时响应、不在发布后与受害者交互。
- **可复现的基准与端到端评测。** 在 OpenClaw 默认 53 个原生技能上构造了 9 个功能组、536 个多技能任务（45 个 pilot + 491 个留出评测），并配套发布了 benchmark、mock 实现、任务本地化接口与执行脚本。评测覆盖 6 个主流 LLM 后端、单任务与多轮两种场景，并设计了 paired clean–injected 执行协议与四人盲评任务完成判定（一致率 96.3%）。
- **机制可解释的消融与泛化验证。** 通过 Attract-only / Detour-only / Full CDH 三组消融证明"描述吸引力"与"正文绕行能力"必须协同才能复现完整效果；另用 3 位独立作者撰写的 30 个跨组任务验证 CDH 对分布外任务仍有效（命中 33.33%，命中任务 token +45.3%、wall-clock +228.9%）。

## Key Contributions

- **Cross-stage attack formulation.** Identifies and formalizes CDH, the first publisher-only supply-chain attack that explicitly *couples* the selection stage (routing metadata/description) and the planning stage (instruction body) under progressive disclosure. The formal Definition 1 makes "task-preserving trajectory amplification" precise via four jointly-required conditions (coordinator loaded, clean-route skills all retained, at least one additional native skill invoked, both clean and injected runs complete the task), and defines ASR accordingly.
- **Attract–detour–converge methodology.** A black-box, pilot-guided procedure that builds one fixed coordinator per functional group: an optimized two-clause description (activation clause + coordination clause) wins co-selection without replacing native skills, and a bounded Markdown runbook (six design principles: dependency topology, edge justification, mandatory framing, evidence-event decomposition, post-execution verification, structured packaging) fabricates locally-plausible prerequisite/verification dependencies on benign native skills before an explicit return rule re-enters the original task. No executable payload, no runtime-response control, no post-publication interaction.
- **Benchmark and end-to-end evaluation.** Constructs a 491-task held-out benchmark (plus 45 strictly-separated pilot tasks) over OpenClaw's 53 native skills organized into nine functional groups, with paired clean–injected execution, four-annotator blinded completion judging (96.3% unanimous agreement), component ablations, and 30 independently-authored generalization tasks, across six LLM backends and both single-task and multi-turn settings.
- **Mechanism-level evidence.** Ablations isolate the roles of description vs. body: Attract-only matches Full CDH on hit rate (78.7%) but yields far less invocation growth (+0.22 vs +2.01 calls); Detour-only rarely gets its body exposed (3.4% hit). This demonstrates that selection attraction and body-driven trajectory expansion must compose to reproduce CDH.

## Methodology

CDH targets skill-based LLM agents that use **progressive disclosure**: a router first sees only each skill's front-matter description `ds` and selects a subset; only then are the instruction bodies `bs` loaded into the planner's context. The attack adds a single static "coordinator" skill `h = (dh, bh, fh)` to the clean registry `S0`, forming `Sh = S0 ∪ {h}`.

The threat model is deliberately minimal: the attacker is a malicious publisher who cannot access model internals, victim prompts, runtime tool observations, or execution states; cannot modify existing skills, platform infrastructure, system prompts, or other publishers' content; and cannot interact with a victim session after publication. The coordinator is an immutable natural-language payload fixed at publication time.

CDH instantiates a **shared coordination rationale** `ρg = (Tg, cg, Lg, qg)` per functional group `g` (target triggers, non-executing coordinator role, plausible inter-skill relations, non-replacement/return boundary). This single rationale is expressed in two consistent views:

1. **Description attraction (selection stage).** A generator produces two-clause candidate descriptions: an *activation clause* using target-domain concepts and an *coordination clause* presenting the skill as a workflow organizer complementary to (not replacing) native skills. Original native-skill bodies are never exposed to the generator. Candidates are screened on the 45 pilot tasks by isolated coordinator-selection rate `Ag(d)`, then refined under full agent runtime by activation rate `Eg(d)` (selected AND loaded). Only the activation clause may change during refinement; `ρg`, the coordinator role, and the non-replacement boundary stay fixed. The loop (generate–evaluate–retain, Eq. 10) stops when attraction plateaus, typically in 2–3 rounds. Crucially, the 491 held-out tasks are never exposed during screening or refinement.

2. **Coordination-rule body (planning stage).** Once loaded, the body becomes planner-visible and instantiates `Lg` as a bounded runbook `bg = Runbook(ρg, Πg, Jg, Vg, Bg, Rg)`: a bounded dependency path `Πg` over native skills, omission consequences `Jg` that frame each auxiliary call as necessary to avoid data loss/state inconsistency, at most one verification revisit `Vg`, per-skill and total invocation bounds `Bg`, and a return rule `Rg` that releases coordinator obligations and returns control to ordinary planning over the unchanged request (restarting the detour is prohibited).

This yields the **attract–detour–converge** trajectory: the description secures co-selection, the body fabricates plausible prerequisites that recruit benign native skills into a bounded detour, and the return rule re-enters the original task path — preserving task completion while inflating token, cache, latency, and invocation costs.

Evaluation uses a **paired clean–injected protocol**: for each task, clean runs use `S0` and injected runs use `Sh` with identical OpenClaw config, model settings, task inputs, mock environments, and a 600s timeout. All experiments run in an isolated Ubuntu VirtualBox VM with local mock backends replacing credential/platform-dependent skills. Resource amplification is reported only on coordinator-hit tasks where both runs complete.

## Results & Highlights

- **Coordinator hit rate (DeepSeek-V4-Pro, 491 held-out tasks):** the matched coordinator is selected and loaded in **80.02%** of single-task executions, rising to **88.98%** in multi-turn; MiniMax-M3 reaches the highest single-task hit rate of **96.60%** (94.69% multi-turn). Isolated-routing clean scores (router-only, no execution) range 86.58%–90.44%, while pilot attraction is only 4.80%–14.20%, showing the optimized descriptions establish routing relevance without execution context.
- **Task completion preserved:** across all six model–condition pairs, clean and injected completion rates differ by **at most 1.5 percentage points** (e.g., DeepSeek-V4-Pro 93.6% clean vs 94.3% injected single-task), confirming CDH is result-preserving.
- **Token amplification (DeepSeek-V4-Pro):** on coordinator-hit completing tasks, total token consumption rises **+66.91%** (single-task) and **+91.20%** (multi-turn) versus the paired clean baseline; cached-token usage rises **+54.33%** / **+80.71%**.
- **Latency amplification (DeepSeek-V4-Pro):** end-to-end wall-clock time increases **+92.45%** (single-task). Across all models, single-task token overhead ranges **+49.60% to +80.81%** and multi-turn ranges **+36.54% to +107.12%** (DeepSeek-V4-Flash multi-turn); cached-token overhead peaks at **+94.31%** (MiniMax-M3 multi-turn).
- **Invocation growth:** Avg. ΔCalls is positive in every configuration (**+1.36 to +2.20** additional skill invocations per hit task), directly demonstrating trajectory expansion.
- **Attack success rate (Table 3):** formal ASR (which additionally requires clean-route retention + native-skill detour + dual completion) reaches **70.82%–80.51%** single-task and **71.19%–82.81%** multi-turn across the six backends (e.g., DeepSeek-V4-Pro 73.82% / 82.81%; Qwen3.7-Plus 80.17% / 81.76%).
- **Ablation (DeepSeek-V4-Pro, 89 tasks, Table 2):** Full CDH hits 70/89 (78.7%) with +57.9% token / +76.7% time / +2.01 calls; **Attract-only** matches the 78.7% hit rate but only +0.22 calls — selection alone does not reproduce the detour; **Detour-only** is selected in just 3/89 (3.4%), rarely exposing its body. This decouples the two stages.
- **Out-of-distribution generalization (30 independently-authored cross-group tasks):** coordinator selected in 10 tasks (33.33%), all satisfying CDH; on those, tokens **+45.3%**, cached tokens **+39.8%**, wall-clock **+228.9%**, invocations **+2.6/task** — lower hit rate but still effective on unseen, cross-group compositions.

## Authors & Credibility

The work comes from the School of Computer Science and Software Engineering at Shenzhen University (with collaborators at CUHK and CUHK Shenzhen); Junliang Liu and Ruoyu Li are co-first authors and Laizhong Cui / Ruoyu Li are corresponding authors. The experimental rigor is above average for a security paper: a strictly separated 45-task pilot set vs. 491-task held-out set, a paired clean–injected protocol with identical configs and 600s timeouts, four-annotator blinded completion judging with 96.3% unanimous agreement and majority-vote resolution of the 3.7% three-to-one splits, isolated VirtualBox VMs with mock backends to avoid uncontrolled side effects, and a stated commitment to release the benchmark, mock implementations, task-localization interface, execution scripts, and the exact coordinator artifacts (descriptions + Markdown runbooks) as a supplementary VM image. The threat model is stated precisely and the attacker is kept to a genuinely minimal (publisher-only, static-text) foothold. References situate CDH against closely related 2025–2026 work (Attractive Metadata Attack, Clawdrain, MCP-ITP, SkillTrojan, Sponge Tool Attack, etc.) and explicitly disclaim that task-preserving amplification itself is not the novelty — the progressive-disclosure-specific coupling is.

## Critical Assessment

- **Novelty (genuine but scoped).** The paper is honest that result-preserving resource amplification (Clawdrain/Dong et al. 2026, Sponge Tool Attack, LoopTrap) and selection manipulation (Attractive Metadata Attack/Mo et al. 2025) already exist. The real contribution is the *cross-stage coupling* under progressive disclosure: using one static text artifact to act in two phases. This is a meaningful reframing but is a narrower delta than the abstract's framing might suggest; readers should not expect a new payload class.
- **Rigor — strengths.** Pilot/evaluation separation is enforced (no held-out task touches candidate generation), the ablation cleanly attributes the effect (Attract-only: 78.7% hit but +0.22 calls; Detour-only: 3.4% hit), and the paired protocol with blinded 4-annotator completion judging is a credible design for a metric (task success) that is otherwise easy to game.
- **Rigor — weaknesses.** (1) **Wall-clock time is an unreliable metric in this setup**: DeepSeek-V4-Flash shows *negative* time deltas (−10.53% / −27.97%) despite large token growth, and the authors concede latency is "strongly affected by backend-specific caching, scheduling, and inference optimization." Any claim that CDH "amplifies execution time" is therefore model-dependent and partly contradicted by their own table. (2) The **Detour-only ablation rests on only 3 hits** (the authors flag this), so its lower amplification is statistically fragile. (3) Resource metrics are reported **only on coordinator-hit tasks where both runs complete**, which conditions on a non-random subset and could upward-bias the deltas (a coordinator that causes failure or timeout is excluded from the cost accounting, though completion rates are reported over all tasks).
- **Reproducibility.** Good on paper (artifacts + VM image promised, stdlib-free description given), but the exact coordinator descriptions/runbooks are deferred to the supplementary ZIP rather than shown in the main text, so a reader cannot fully audit the "plausibility" claims from the PDF alone. The benchmark is auto-generated by GPT-5.5 and then human-filtered, introducing a generator-dependent distribution that may not match real user queries.
- **Significance.** The core takeaway — "final-answer correctness does not imply trajectory necessity or cost safety, and audits must jointly examine routing metadata + execution instructions + trajectory necessity" — is a sound and actionable security requirement for extensible agents. However, the attack requires the victim to *install* the attacker's skill, and the proposed defenses (pre-installation review, runtime invocation/token budgets) are only sketched, not implemented or measured.
- **Red flags.** Benchmark and coordinators are co-constructed by the same team, then "generalization" is checked on only 30 self-authored-but-independent tasks (33.33% hit rate, much lower than the 78–96% on the in-distribution benchmark) — the gap hints the in-distribution numbers may be optimistic. No real-world deployment or existing skill registry is tested; everything is on OpenClaw 2026.5.7 with mock backends.

## Strengths

- Precise, formal problem statement (Definition 1 + ASR) that makes the four jointly-required CDH conditions and the paired clean–injected comparison unambiguous — useful as a template for future trajectory-necessity work.
- Clean ablation design that successfully *decouples* selection attraction from planning-stage detour, turning a "does it work?" question into a mechanistic one.
- Strong experimental hygiene: pilot/evaluation separation, blinded multi-annotator completion judging with reported agreement, isolated VMs, fixed timeouts, and a stated artifact-release plan.
- The "local plausibility does not guarantee trajectory necessity" insight is a genuinely useful conceptual contribution that generalizes beyond this specific attack.

## Limitations

- Evaluated on a single platform (OpenClaw 2026.5.7) with mock backends; broader ecosystems, off-domain activation, and real external services are left to future work (acknowledged by the authors).
- Wall-clock latency results are inconsistent across models (including negative deltas for DeepSeek-V4-Flash), undermining time-amplification as a reliable claim; the most robust signals are token and invocation growth.
- No implemented or measured defense — the two proposed defense points (pre-installation review, runtime monitors) are discussed only at a sketch level, with no experiments on attack suppression, false-positive rate on legitimate multi-skill workflows, or defense overhead.
- The benchmark is LLM-generated (GPT-5.5) then human-filtered; the large gap between in-distribution hit rates (78–96%) and the 30 independently-authored tasks (33.33%) suggests distribution sensitivity that is under-explored.
- Detour-only ablation has only 3 hits, making its lower amplification statistically weak; the hit-conditional version (Table 9) is explicitly flagged as needing cautious interpretation.
- Resource-amplification metrics are conditioned on coordinator-hit-and-both-complete tasks, a non-random subset that may overstate average cost impact.

## Relevance

这项工作直接命中"LLM Agent 安全 / 工具与技能供应链攻击"方向，揭示了在技能化 Agent（如基于 MCP / skill registry 的系统）中，仅靠一个静态恶意技能就能在不破坏任务的前提下放大 token 与延迟开销——对评估 Agent 框架的健壮性、设计技能审核与运行时调用预算机制具有直接参考价值，也启发把"轨迹必要性"而非仅"最终答案正确性"作为 Agent 安全的验收标准。

## Questions for Further Exploration

- How does CDH transfer to non-OpenClaw progressive-disclosure registries (e.g., MCP-based skill marketplaces, Claude/ChatGPT plugin stores)? Is the attract–detour–converge pattern dependent on OpenClaw's specific routing prompt?
- Can a runtime monitor that flags *unexplained cross-skill transitions* (transitions not justified by the prior skill's observable output) detect CDH without suppressing legitimate multi-skill workflows — and what is its false-positive rate on the 491 clean executions?
- Since the coordinator description is optimized on only 5 pilot tasks per group yet achieves 78–96% hit rates, how does hit rate scale with pilot-set size, and is there a description-side detector (e.g., comparing declared role vs. body-introduced dependencies) that catches the cross-phase inconsistency?
- The independently-authored tasks drop to 33.33% hit rate: what task or query features (direct vs. ambiguous, within- vs. cross-group, skill-chain length) most predict coordinator co-selection, and can the attack be made robust to them?
- Given that wall-clock time is an unreliable amplification signal, what cost metric (token, invocation, or a composite "trajectory-necessity score") should be the canonical one for defense budgets and for comparing future amplification attacks?
- Does combining CDH with prior selection-manipulation or runtime-response attacks (which CDH explicitly forgoes) yield super-linear cost amplification, or does the bounded return rule conflict with sustained-execution attacks like LoopTrap?
