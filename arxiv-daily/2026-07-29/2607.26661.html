Why this matters

Structured knowledge can substitute for missing pretraining data on low-corpus hardware DSLs — a real, hardware-verified data point for whether LLM-written kernels can reach non-CUDA NPUs in production.

Critical edge

Attention and broadcast operators — both architecturally central to transformers — hit 0% feasibility across every configuration tested; the 90–100% headline applies only to elementwise and normalization kernels.

Sandboxed compile → numerical check (ε≤10⁻³) → NPU profiling → targeted correction

Agent interaction mode — click to compare exploration vs. convergence

  • Constrained optimization: x* = argminx T(x) s.t. C(x)=1, where T is measured NPU latency and C is a binary compile+correctness gate — feasibility comes before speed.
  • Phase-differentiated context: initialization injects all L0–L5 knowledge (~800 tokens); mutation/repair phases keep only compact L2–L4 guardrails (<100 tokens) — an 8× per-generation prompt-cost cut.
  • Backbones & hardware: DeepSeek-V4-Flash (6-op study) / DeepSeek-V4-Pro (54-op validation), temp 0.8, pop. size 5, 5 generations, on an 8×Ascend-910B1 cluster (CANN 8.1.RC1).

Strengths
  • Real physical-hardware evaluation (8× Ascend 910B1 NPUs) plus a production LLM deployment with measured end-to-end latency — not simulated or CPU-emulated.
  • Transparent about complete failure modes (attention, broadcast) rather than only showcasing favorable operators.
  • Clean ablation isolating which knowledge level (L0–L5) contributes most, and why.
  • Direct, token-matched comparison against a real prior evolutionary baseline (EoH), not an internal strawman.
Limitations
  • The 57%→86% feasibility curve is validated only on 14 elementwise operators; ~40 of the claimed "54 operators" exhausted the API budget without reportable results.
  • LLM backbone generalization untested beyond DeepSeek-V4 Flash/Pro; Qwen2.5-Coder/Llama-3/GPT-4o left as future work.
  • Knowledge taxonomy construction is manual and costly: 5–8 expert-hours per new operator pattern.
  • No code, dataset, or knowledge-asset release mentioned, despite detailed prompt/algorithm disclosure.
Authors & credibility. Junhao Qiu, Zidong Wang, Yansong Sun, Zhitong Ma, Ping Guo, Qingfu Zhang — Dept. of Computer Science, City University of Hong Kong (Ping Guo also with Hong Kong Yuwin Technology). Qingfu Zhang is an established figure in evolutionary computation. All experiments ran on physical Ascend 910B1 hardware, a meaningful credibility signal — but the paper discloses no explicit Huawei funding/collaboration despite being entirely scoped around Huawei's proprietary Ascend C / CANN toolkit and production Pangu model access.

Questions for further exploration

  • Would the knowledge taxonomy transfer to other low-corpus accelerator DSLs (Cerebras, Groq, other domestic NPU toolchains), or is it fundamentally Ascend-C-specific?
  • What would push attention and broadcast operators past 0% — hierarchical decomposition into matmul/softmax/elementwise primitives, or a tiling-simulator-in-the-loop?
  • How sensitive are the feasibility/speedup numbers to the specific DeepSeek-V4 version, and would a weaker or stronger backbone change the value of knowledge injection vs. tool use?
  • Could the 5–8 expert-hour taxonomy cost be cut by mining L2/L3 rules automatically from historical compilation-failure logs?
  • The embedding layer dominates Pangu inference latency (44.5%) but is architecturally very different (memory-bound gather) — does this knowledge-taxonomy approach even apply there?
