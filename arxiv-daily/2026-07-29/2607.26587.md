> **一句话总结：** 论文指出自动化科研系统常把"一次实现的评分"当作"整个想法（idea）的证据"，这是一种结构性偏差（implementation lottery）；作者设计的 Idea Reliability Audit 在 13 个 OpenML 表格任务、312 次评测中发现，实现方式带来的方差是同一实现重跑方差的 5–10 倍，且 25.6%（受限执行体）到 43.6%（Agentic 执行体）的"获胜想法"在换一次实现后会反转。

> **TL;DR:** Automated-research loops (AI Scientist, Dolphin, Agent Laboratory-style pipelines) treat one coding run's score as evidence about the parent research idea, but the authors show this conflates idea quality with implementation luck. Their Idea Reliability Audit freezes mechanism-level "idea cards," implements each three times in fresh sessions on 13 OpenML classification tasks (baseline: scikit-learn HistGradientBoostingClassifier), and measures variance decomposition plus leave-one-implementation-out (LOO) winner reversal. Across 312 assignments, implementation-choice variance exceeds same-artifact rerun variance by >5x (Bounded executor, ICC=.612) and >10x (Agentic/SDK executor, ICC=.511), and the "winning idea" flips in 25.6% and 43.6% of decisions respectively — a finding that survives outcome-blind portfolio filtering and an exploratory materials-science replication.

## 核心贡献

- 提出"implementation lottery"概念：把某个 idea 的一次实现（realization）的评分当作该 idea 本身的证据，是一种结构性的度量单位错配（idea-level vs. realization-level），只要自动化研究系统用单次运行结果来更新对某个机制的信念，这个问题就必然存在。
- 设计 Idea Reliability Audit（IRA）：冻结"机制卡片"（mechanism-level idea card，固定核心机制但保留验证集比例、耐心值、指标、接口等"合理实现自由度"）→ 用全新会话独立实现三次 → 用outcome-blind 的 LLM 裁判打"忠实度"标签 → 对已保存的可执行产物做逐字节重跑（隔离"实现方差"与"重跑噪声"）。
- 提出两个可操作的可靠性指标：idea ICC（组内相关系数，衡量任务内方差中有多少归属于 idea 本身 vs. 实现 vs. 重跑）和 LOO winner reversal（留一实现法，衡量单次实现选出的"赢家 idea"能否在另外两次独立实现的均值下依然获胜）。
- 在 13 个 OpenML 表格分类任务（312 次评测，Bounded 与 Agentic 两种执行体）上实证发现：实现方差是重跑方差的 5–10 倍，LOO 反转率高达 25.6%–43.6%，并在卡片级别的两种 outcome-blind 过滤规则下依然成立；在 3 个材料科学（Matbench）回归任务的探索性诊断中同样观察到实现方差主导（71%–82%的方差占比）。

## Key Contributions

- Names and formalizes the **implementation lottery**: crediting a single run's score as evidence about the idea that generated it, when in fact reasonable implementation choices (e.g., validation fraction, patience, monitored metric, library interface for an early-stopping mechanism) remain open even after the "idea" is fully specified.
- Introduces the **Idea Reliability Audit**: freeze mechanism-level idea cards → sample 3 independent fresh-session implementations per card → apply outcome-blind LLM-judge fidelity labels (with a second reviewer on a 30% subset and constructed drift/invalid controls) → rerun each saved, executable artifact with 3 frozen seeds to isolate rerun noise from implementation variance.
- Defines **idea ICC** (σ²_I / (σ²_I + σ²_M + σ²_R), from a balanced nested variance decomposition) and **LOO winner reversal** (does a one-draw winner survive the other-two-implementation mean?) as the two reliability estimands, formally distinguishing average-realization idea quality Q from best-of-N artifact utility B_N.
- Empirically shows the lottery is real and large: on 13 OpenML tasks (312 assignments, two independent coding-agent setups), implementation variance exceeds rerun variance by >5x/>10x, and winner reversal is 25.6%/43.6%; the effect persists after outcome-blind card-filtering sensitivity analyses and in an exploratory 3-task materials-science (Matbench) diagnostic with a deterministic evaluator.

## Methodology

The audit models an observed utility score as a nested random-effects decomposition: Y_siejk = μ_e + A_se (task) + I_sie (idea) + M_siej (implementation) + R_siejk (rerun), for task s, idea i, coding-agent setup e, implementation draw j, and rerun k. Task variance is excluded from the ICC because automated systems compare ideas within the same task.

**Idea cards.** For each of 13 public OpenML classification tasks (frozen eligibility: ≤8,000 rows, ≤60 features, ≤10 classes, no missing values, imbalance ≤10, ≥.03 development headroom), DeepSeek v4 Pro generates candidate "mechanism-level" cards from frozen code/task context — fixing the scientific intervention (e.g., early stopping for a booster with training-only validation, a stopping rule, and best-iteration restoration) while explicitly leaving open ordinary implementation choices, and excluding exact hyperparameters/seeds/line-by-line steps (which would make it a "recipe" rather than an idea). A lexical/mechanism-family classifier and a "recipe guard" filter duplicates and overly-pinned cards. Four cards per task are retained.

**Independent implementations.** Each card is implemented three times in fresh sessions under two coding-agent setups sharing the same card portfolio: **Bounded** (≤4 model calls, limited code inspection, 2 repairs, fixed token budget) and **Agentic** (one fresh Claude/DeepSeek-SDK Read/Edit session, max_turns=20, no external repair). This gives 13 tasks × 4 cards × 3 implementations × 2 setups = 312 assignments. Independence is checked via provider response/session identifiers rather than assumed (311/312 verified; one Bounded draw is reported as unverifiable).

**Blind fidelity and reruns.** A blinded DeepSeek v4 Flash judge labels each patch's adherence to its card (faithful/partial/drift/invalid) without seeing task identity, scores, or other labels; a second DeepSeek v4 Pro reviewer labels a preregistered 30% subset; constructed drift (swap another card's patch) and invalid (empty patch) controls calibrate the judge. Every executable patch is replayed byte-identically with 3 frozen seeds to estimate rerun variance σ²_R separately from implementation variance σ²_M. All 312 assignments — including failures and drift — remain in the intention-to-treat (ITT) analysis, using a frozen penalty schedule (−.10 for evaluation failure/fidelity-invalid, −.02 for drift/missing fidelity, 0 for faithful/partial).

**Metrics and inference.** Utility is relative held-out accuracy gain vs. a common one-thread scikit-learn HistGradientBoostingClassifier baseline (lr .08, 150 iterations, 31 leaves, min-leaf 20, ℓ2=1.0), on held-out OpenML fold 0. Variance components are estimated by balanced method-of-moments (negative estimates zero-bounded for ICC); confidence intervals use task-cluster bootstrap (46,656 draws for Phase 1, 200,000 for the pooled/extension analysis) plus leave-one-task-out (LOTO) estimates and exact paired sign-flip tests. A separate exploratory arm applies the same design to 3 Matbench-derived materials-regression workflows (steel yield strength, band gap, phonon frequency) with a deterministic evaluator (a 4th task, dielectric response, was excluded outcome-blind for lacking distinct mechanisms); Materials is never pooled with Tabular because its portfolio gate was not validly completed prospectively.

## Results & Highlights

- **Implementation variance vs. rerun variance (primary claim).** Pooled across 13 OpenML tasks (312 assignments), implementation choice accounts for 33% of within-task ITT variance under Bounded and 45% under Agentic, versus only 6% and 4% for same-artifact reruns — implementation SD is .0202 (Bounded) and .0295 (Agentic) vs. rerun SD of .00871 and .00917 (relative-held-out-gain scale), i.e., implementation variance exceeds rerun variance by more than 5x (Bounded) and more than 10x (Agentic).
- **Idea ICC and LOO reversal.** Idea ICC = .612 [95% task-cluster CI .477, .745] for Bounded and .511 [.248, .747] for Agentic. LOO winner reversal occurs in 10/39 decisions (25.6% [7.7%, 46.2%]) for Bounded and 17/39 (43.6% [20.5%, 66.7%]) for Agentic — nearly half of Agentic idea-selection decisions flip depending purely on which of three legitimate implementations was sampled.
- **Concrete illustrative case (Figure 3, OpenML task 146822, Bounded).** Three valid, blind-faithful implementations of the same frozen "interaction-feature" card (I02) span **+2.31% to −1.85%** relative held-out utility (with same-patch reruns exact across 3 seeds), while a competing card (I00) scores a stable **+0.46%**; against I00, *every one* of the three one-draw selections is reversed once the other two implementations are taken into account, and the implementations' prediction vectors disagree on up to 4.76% of held-out examples.
- **Robustness to card quality (Table 1).** After outcome-blind post-execution semantic filtering by an independent OpenAI Codex reviewer (external to the DeepSeek pipeline), reversal remains 33.3–43.6% across a "conservative" rule (38/52 cards admitted) and a "construct" rule (43/52 admitted) — degenerate/duplicate cards do not explain the reversal. LOTO ICC ranges .566–.627 (Bounded) / .459–.568 (Agentic) across a preregistered penalty-grid sensitivity, and reversal ranges 25.6–30.8% / 35.9–43.6%; deterministic (non-LLM) fidelity labels don't change the conclusion.
- **Execution/fidelity audit trail.** All 312 assignments remained valid for ITT; 147/156 assignments per setup were execution-valid (9 total evaluation errors, zero code-invalid patches); fidelity was faithful/partial for 150/156 (Bounded) and 152/156 (Agentic); double-labeled fidelity agreement was 47/49 and 43/49; the drift/invalid judge controls were detected at 50/52–52/52 rates.
- **Exploratory Materials diagnostic.** On 3 Matbench-derived regression tasks (72 assignments, deterministic evaluator so rerun variance is exactly zero), implementation still dominates the variance decomposition (71% Bounded, 82% Agentic), idea ICC is only .290 [.000, .824] (Bounded) and .177 [.040, .777] (Agentic), and LOO reversal is 33.3% and 55.6% — the same qualitative pattern as Tabular, though the authors flag this arm as exploratory (small n=3 workflows, historically exposed data, Bounded card validity 29/36=80.6% fell below their own preregistered .85 gate).

## Critical Assessment

**Novelty:** The core observation — that automated research loops conflate a realization-level score with idea-level evidence — is a genuinely useful conceptual contribution, filling a real gap between prior "repeated-run reliability" work (e.g., Mustahsan et al.'s ICC-based agent inconsistency study, cited directly) that repeats a *task*, and this paper's design that repeats the *translation of a fixed idea into code*. The reliability-theory framing (borrowing ICC from Shrout & Fleiss 1979) is appropriately grounded rather than invented from scratch.

**Rigor:** The study is unusually careful for this genre — it separately isolates rerun noise via byte-identical 3-seed replays, uses constructed drift/invalid controls to validate its LLM fidelity judge, brings in an *external* reviewer (OpenAI Codex, outside the DeepSeek generation/implementation pipeline) for a card-quality sensitivity check, reports a preregistered penalty grid, and runs LOTO/bootstrap/sign-flip inference rather than a single point estimate. The paper is also honest about a messy detail: one Bounded implementation draw lacks a provider response identifier and is explicitly reported as "unverifiable" rather than silently included as verified — a good-faith disclosure many papers would omit.

**Reproducibility/generalizability concerns (paper-specific, not generic):** The entire pipeline — card generation, both "independent" implementation setups (Bounded and Agentic), and the primary/secondary fidelity judges — all run on **DeepSeek v4 Pro/Flash**. There is no cross-model-family validation (e.g., GPT or Claude generating cards or implementations), so the reported 25.6–43.6% reversal rates are a property of this one model family's implementation diversity, not a universal constant — the authors do flag this scope limitation themselves ("The comparison concerns the full implementation processes rather than base models" / Section 7 limitations), which is commendable, but it does temper how far the headline numbers should be extrapolated. The task pool is also narrow by the authors' own admission ("OpenML is comparatively constrained" — ≤8,000 rows, ≤60 features, boosting-only baseline), and the Materials arm is explicitly exploratory because its preregistered human portfolio gate "was not validly completed" and the data was "historically exposed" in an earlier proof of concept — a data-quirk the authors surface candidly rather than hide. The two coding-agent "setups" being compared (Bounded vs. Agentic) also don't map onto any real published automated-research system by name, so it's unclear how directly these reversal rates transfer to, say, actual AI-Scientist or Agent-Laboratory deployments.

**Significance:** If the core finding generalizes, it has real implications for the automated-research and self-improving-agent literature (AI Scientist, Dolphin, Agent Laboratory, Co-Scientist, FunSearch/AlphaEvolve-style systems), since these systems routinely use one run's score to prune branches or update "research memory." The paper is careful not to overclaim a universal error rate ("25.6–43.6% is conditional rather than an error rate for arbitrary projects," Section 7) and explicitly separates this from best-of-N artifact search, which it says remains a legitimate and different objective. This kind of self-aware scoping is a strength relative to typical overclaiming in the "AI-for-science" hype space.

**Red flags:** None rising to the level of invalidating the core claim, but worth naming: (1) no human baseline for either idea-card generation or fidelity judging — everything is LLM-judged, which the paper itself notes ("Fidelity labels were blinded and stress-tested but were not provided by humans"); (2) sample sizes for LOO reversal are small (39 decisions per setup for Tabular, only 9 for Materials), so confidence intervals are wide (e.g., Materials Agentic reversal 55.6% [0.0%, 100.0%]); (3) the "other-two-attempt mean" used as the LOO reference is explicitly a finite-budget proxy, not ground truth, so reversal measures decision instability rather than being validated against a true idea ranking.

## Strengths

- Clear, well-motivated conceptual distinction (idea-level Q vs. best-of-N artifact utility B_N) that is likely to be citable/reusable vocabulary for the field.
- Strong methodological discipline: outcome-blind card freezing, fresh-session independence checks via provider identifiers, constructed judge-calibration controls, byte-identical reruns to isolate noise sources, and an external (cross-pipeline) reviewer for a robustness check.
- Extensive sensitivity analysis (penalty grids, two independent card-filtering rules, LOTO, deterministic fidelity labels) that all point the same direction, strengthening confidence the effect isn't an artifact of one modeling choice.
- Transparent about its own limitations and irregularities in the audit trail (unverifiable draw, two outcome-blind mid-study repairs, Materials arm's failed preregistration gate) rather than smoothing them over.
- The illustrative case study (Figure 3) makes the abstract statistic concrete and easy to communicate to practitioners.

## Limitations

- Single model family (DeepSeek v4 Pro/Flash) for card generation, both implementation processes, and fidelity judging — no cross-family replication.
- Narrow, "comparatively constrained" task domain (small-to-medium OpenML tabular classification with a single boosting baseline); explicitly does not test larger deep-learning workflows, which the authors argue would have even more implementation degrees of freedom.
- Materials diagnostic is exploratory only: preregistered human portfolio gate not validly completed, prior outcome exposure risk, only 3 workflows, wide CIs, and one setup's card validity (80.6%) fell below the paper's own .85 preregistered gate.
- No human implementers or human fidelity raters — full pipeline is LLM-mediated end to end.
- Does not evaluate best-of-N stability, full closed-loop tree search, or downstream gains from actually deploying the audit in a live automated-research loop — it measures the problem's magnitude but doesn't demonstrate a fix in production.
- LOO reversal is defined relative to a finite "other-two-mean" reference rather than a validated ground-truth idea ranking, so it measures decision instability, not calibrated error against truth.

## Relevance

与用户关注的自动化科研 / LLM agent 可靠性方向高度相关：该文为"自动化科研系统用单次运行结果做 idea 级决策"这一常见但少被系统检验的做法提供了严谨的量化反例和一套可复用的审计框架（idea ICC + LOO reversal），对设计或评估任何"AI Scientist"式闭环系统的可信度评估流程有直接参考价值。

## Questions for Further Exploration

- Would the 25.6–43.6% reversal rate hold if card generation, implementation, and fidelity judging used *different* model families (e.g., GPT/Claude generating cards, DeepSeek implementing, human fidelity review) rather than a single DeepSeek pipeline throughout?
- How does idea ICC scale with workflow complexity — the paper explicitly predicts larger deep-learning workflows (architecture, optimization, checkpointing choices) would show *more* implementation variance, but this is untested; would the same audit design even be tractable (cost/compute-wise) at that scale?
- Can the Idea Reliability Audit be integrated as a live gate inside an actual closed-loop automated-research system (rather than run as a post-hoc audit), and if so, does gating on ICC/reversal actually improve the quality of the "research memory" the system accumulates over many iterations?
- Given that Bounded and Agentic showed *no consistent reliability ordering* between them (pooled Agentic-minus-Bounded CI for both ICC and reversal include zero), what implementation-process design choices (token budget, repair passes, turn limits) actually drive idea reliability, and could a process be engineered to raise ICC without sacrificing artifact quality?
- How would the audit's LOO reversal metric behave with more than 3 implementation draws per card (e.g., 5 or 10), and what is the practical minimum number of fresh-session implementations needed before an idea-level decision can be trusted for research-memory promotion?
