Freezes an agent's tools but lets episodic memory and a workflow graph evolve every episode, gated by a fixed rulebook.

一句话总结：把每一轮任务的执行轨迹和评估反馈，通过人工编写的领域级 Evolution-SOP，转化为对情景记忆和状态图的有界更新——在 τ²-Bench 和 MultiWOZ-2.4 上分别比最强交互式基线高出 10.07 和 9.91 个百分点（Pass@1）。

Why This Matters
A concrete blueprint for agents that accumulate reusable procedural knowledge across episodes through gated memory and workflow updates.
Critical Edge
The Evolution-SOP causes the single largest score drop when removed (83.09 → 73.38) — yet it's hand-written per domain by humans, not learned by the system.

  • Harness state splits into frozen resources (tools, base context, domain rules, Evolution-SOP) and evolving state S=(R,G) — episodic memory + a workflow state graph.
  • The Evolution-SOP is hand-authored per domain (one per τ²-Bench domain, one per MultiWOZ domain), encoding laws like "identity resolution is a gate, not a side note."
  • Score-before-update: the evaluator scores episode n before any harness update, so a trajectory never contaminates its own score.
  • Update cadence: every scored episode on τ²-Bench; batched every 4 episodes on MultiWOZ-2.4.
  • Task-local reflection (Reflexion-style retries) is discarded at episode end — never written to persistent memory or the graph.
Theory aside: a POMDP proposition (proved in the appendix) shows adding an informative program-state variable cannot increase — and typically decreases — the Bayes estimation error, motivating why retrieved procedural context should help.

Strengths & Limitations

Where it holds up, where it doesn't

Strengths

  • Concrete commit gates (schema/scope/evidence/constraint/merge) make the update mechanism auditable rather than "append everything to memory."
  • Consistent gains across two benchmark families and multiple well-known self-evolving baselines (ReAct, Reflexion, AWM, ReasoningBank, EvoTest), all matched to the same backbone.
  • Ablation isolates the Evolution-SOP's contribution from memory and graph mechanics, and honestly reports that the SOP matters most.
  • Cross-model transfer (Table 3) shows the evolved state is genuinely backbone-agnostic, not prompt-engineering for one model.
  • Appendix includes a full proof of Proposition 1, reproducibility details (top-k, gate definitions, sync windows), and the actual Evolution-SOP prompts for all 8 domains.
  • Limitations section is candid, not perfunctory — names the manual-SOP caveat and the lack of rollback outright.

Limitations

  • Evolution-SOPs are hand-written per domain by the authors; zero-shot transfer of an SOP to an unseen domain is explicitly untested.
  • No rollback, stale-entry removal, or regression testing — a bad evaluator signal or an overly narrow repair can persist in the harness state indefinitely.
  • Evaluated only on two simulator-based benchmarks with finite tool sets; robustness to shuffled task streams or real unseen policy changes is untested.
  • No variance/seed analysis (single temperature=0.2 run) — hard to judge small deltas, e.g. the +0.17 pt edge over Gemini 3 Pro or Airline's −2.00 pt cycle-3 dip.
  • Post-episode computation (posterior generation, extraction, gated commit) adds non-trivial cost overhead beyond the scored rollout itself.
  • No code repository found in the reviewed material — reproduction currently depends on re-implementing from the prompt specs.
Open Questions

Questions for further exploration

  • Can the Evolution-SOP itself be learned or meta-learned across domains rather than hand-authored, and how much performance would that cost?
  • Under a shuffled or non-stationary task stream, does the lack of rollback/regression testing cause measurable drift on previously-solved task types?
  • What is the latency/token overhead of the post-episode posterior-generation and gated-commit pipeline versus a plain Reflexion retry loop?
  • Would a learned (rather than fixed) commit-gate policy close the gap on the 1-domain MultiWOZ subset, where Living-Harness still trails Reflexion?
  • How sensitive are results to the top-k=3 retrieval budget and the 4-episode MultiWOZ sync window — would adaptive scheduling tame the Airline cycle-3 dip?
