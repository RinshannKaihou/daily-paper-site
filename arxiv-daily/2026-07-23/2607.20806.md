> **一句话总结：** 提出 PTME（精度/时间/内存/能耗）联合测量框架，在受控桌面平台上对 6 个轻量 LLM（1.1B–7B）做直接硬件级测量，发现参数量/FLOPs 等静态代理指标能预测推理成本但完全无法预测任务精度，且收紧资源约束时大模型时延被放大得比能耗更剧烈——为边缘部署提供帕累托最优的选模型依据。

> **TL;DR:** The paper introduces PTME, a precision-aware profiling framework that jointly measures accuracy, execution time, peak memory, and energy (via Intel RAPL) for 6 lightweight LLMs (TinyLlama-1.1B to Mistral-7B, all Q4 via Ollama) on a constrained Intel i7-12700K desktop simulating 5 edge-class resource envelopes (E1–E5), across HumanEval/GSM8K/MMLU-Pro. Static proxies (params, FLOPs, loaded memory) strongly correlate with cost metrics (R≈0.95–1.0) but weakly with precision (R≈0.36–0.48); on MMLU-Pro Qwen2.5-1.5B reaches 28.2% precision at ~1/3 the time/energy of Mistral-7B's 34.6%; tightening the envelope E5→E1 cuts time/token to 15–19% but energy/token only to 28–36%, penalizing larger models hardest. A four-objective Pareto analysis exposes non-dominated mid-sized models that accuracy-only or efficiency-only views miss.

## 核心贡献

- **形式化 PTME 指标体系**：把 Precision（任务精度）、Time（执行时间）、Memory（峰值 RSS）、Energy（Intel RAPL CPU 包级能耗）作为一组联合报告的指标，强调"精度与物理成本绝不可解耦"，不聚合为单一标量分数。
- **静态代理指标的实证裁决**：通过 Pearson 相关（表 VII，E1–E5 五档）证明参数量/FLOPs/加载内存与成本类指标强相关（R≈0.95–1.0），但与精度几乎无关（R≈0.36–0.48），即"小就是省、小不等于准"。
- **四目标帕累托选模型方法论**：对每个 benchmark 给出非支配集合（HumanEval={TL, QW}；GSM8K={TL, QW, P3}；MMLU-Pro={TL, QW, P3, MS}），并证明单指标评估会塌缩到一个极端（最小或最准），中等模型（Qwen2.5、Phi-3）才是大多数边缘部署的最佳折中。
- **资源约束敏感性分析（RQ3）**：证明收紧约束不改变精度（确定性解码下输入输出 token 完全一致），但 E1 相对 E5 把时间/token 放大约 5.3–6.3 倍，能耗/token 只放大约 2.7–3.5 倍——即"省时间不等于省能耗"，且大模型敏感度更高。
- **可复现实验协议**：固定 Docker 环境下用 `cpupower`/`--cpuset-cpus`/`--memory` 强制 E1–E5 五档约束，提供热身抛弃、冷却间隔、Cochran's Q / McNemar / Friedman / Nemenyi 非参数统计检验，代码公开。

## Key Contributions

- **Formalizes the PTME metric set** — Precision, Time, peak Memory, and Energy are reported jointly and never aggregated into a single scalar; accuracy is treated as a first-class dimension decoupled from physical cost only conceptually, never in evaluation.
- **Empirically discredits static proxies for precision** — Across all five resource envelopes (E1–E5) on a constrained Intel i7-12700K + Ollama v0.23.2 setup, parameter count / FLOPs / loaded memory correlate with cost metrics at R≈0.95–1.0 but with precision only at R≈0.36–0.48 (Table VII), providing a concrete decision rule for when proxy-based model selection fails.
- **Four-objective Pareto model-selection methodology** — Reports non-dominated sets per benchmark (e.g., {TinyLlama, Qwen2.5, Phi-3, Mistral} on MMLU-Pro) and demonstrates that every single-metric optimum collapses to an extreme (cheapest TinyLlama or most-accurate Mistral), hiding practical mid-sized alternatives.
- **Resource-envelope sensitivity law (RQ3)** — Tightening E5→E1 cuts time/token to 15–19% and TTFT to 12–20% but energy/token only to 28–36%, showing that optimizing latency and optimizing energy diverge on constrained devices, with larger models penalized most.
- **Reproducible hardware-measured protocol** — Direct Intel RAPL CPU-package energy + RSS peak memory + wall-clock time, deterministic greedy decoding (temperature=0), warm-up discard, cool-down interval, paired non-parametric tests (Cochran's Q, McNemar, Friedman, Nemenyi), code released.

## Methodology

The PTME (Precision, Time, Memory, Energy) framework measures, for each configuration tuple `(model, dataset, resource envelope, decoding config)`:

- **Precision P** — dataset-specific: pass@1 for HumanEval (164 instances, all evaluated), exact-match on final numeral for GSM8K (200 of 1319 sampled), multiple-choice accuracy for MMLU-Pro (280 of 12032, i.e. 20 per each of 14 categories).
- **Time T** — wall-clock end-to-end inference time `t_end − t_start`, reported raw and normalized by total tokens.
- **Memory M** — peak resident set size (RSS) of the inference backend process + children + profiling process, capturing both static footprint and dynamic allocations.
- **Energy E** — Intel RAPL CPU-package cumulative energy delta `E_pkg(t_end) − E_pkg(t_start)`.

**Hardware/execution environment**: Ubuntu 24.04 desktop, Intel Core i7-12700K (8 P-cores + 4 E-cores, 20 threads), 64 GB DRAM. All inference restricted to P-cores, CPU-only (no GPU), in a fixed Docker container, via Ollama v0.23.2 with default quantized (Q4) variants.

**Resource envelopes E1–E5** approximate edge/mobile classes by capping P-core count (1→8), Ollama threads, CPU frequency (1.5 GHz → 2.5 GHz via `cpupower`), and RAM limit (5 GB → 16 GB via `docker --memory`):

| Env | Class | P-cores | Threads | Freq Cap (GHz) | RAM (GB) |
|-----|-------|---------|---------|----------------|----------|
| E1 | Tiny edge | 1 | 1 | 1.5 | 5 |
| E2 | SBC-like | 2 | 2 | 1.8 | 8 |
| E3 | Mid mobile | 4 | 4 | 2.0 | 12 |
| E4 | High mobile | 6 | 6 | 2.2 | 14 |
| E5 | Laptop-class | 8 | 8 | 2.5 | 16 |

**Models** (Table IV / S.II): TinyLlama-1.1B, Qwen2.5-1.5B, Gemma-2B, Phi-2 (2.7B), Phi-3-mini (3.8B), Mistral-7B.

**Statistical analysis**: Because each benchmark instance forms a matched block, paired non-parametric tests are used — Cochran's Q + McNemar for binary precision, Friedman + Nemenyi for continuous cost metrics, with 5% significance post-hoc.

**Three research questions** drive the design: RQ1 (proxy correlation), RQ2 (precision-cost trade-off + Pareto), RQ3 (envelope sensitivity).

## Results & Highlights

- **Proxy ↔ cost is near-perfect, proxy ↔ precision is broken.** Pearson R between loaded memory and measured memory is 0.998–1.0 across all envelopes; R between parameter count and energy/token at E5 is 0.981. By contrast, R between any proxy and precision stays at ≈0.357 (params/FLOPs) to 0.481 (loaded memory) — precision is unpredictable from scale (Table VII).
- **Qwen2.5-1.5B dominates HumanEval on the Pareto front at a fraction of Mistral-7B's cost.** Under E1, QW achieves 48.8% pass@1 in 25.81 s / 520 J / 1.28 GB, while Mistral-7B reaches only 42.7% in 131.49 s / 3372 J / 4.76 GB — QW is both faster, cheaper, smaller, *and* more accurate (Table V).
- **On MMLU-Pro, Qwen2.5 hits 28.2% precision at roughly 1/3 the time/energy of Mistral-7B's 34.6%, and is statistically non-significantly different from both Phi-3 and Mistral** in precision (Table VIII), making it a defensible non-dominated edge choice.
- **Tightening the envelope hits latency far harder than energy.** Going from E5 to E1 reduces time/token to 15–19% of E5 (i.e. E1 is 5.3–6.3× slower) and TTFT to 12–20% (4.8–8.1× slower), but energy/token drops only to 28–36% (E1 is 2.7–3.5× more energy-hungry), implying higher average power in relaxed envelopes (Fig. 6).
- **Time and energy grow ~linearly with total tokens; memory is flat.** Per Fig. 1, peak RSS is governed by model footprint, not sequence length, justifying token-normalization of T and E but not M.
- **Precision is envelope-invariant; the entire PTME variation under RQ3 comes from cost.** Input/output token counts are byte-identical across E1–E5 under greedy decoding, confirming determinism and isolating the resource envelope as the only varying factor (Table IX).
- **Larger models pay disproportionately under tighter envelopes.** Mistral-7B's 3D trajectory (Fig. 7) migrates sharply into the high-cost region as the envelope tightens, while TinyLlama stays pinned near the origin (low cost, low precision); Qwen2.5 stays low-cost *and* retains high precision — the empirical sweet spot.

## Critical Assessment

- **Novelty — moderate.** The PTME acronym and joint quality/cost evaluation are reused from the authors' own energy-aware metaheuristics line; the genuine contribution is the *application to lightweight LLM inference* with the explicit four-objective Pareto framing plus the RQ3 envelope-sensitivity law. The hardware-measurement methodology (RAPL + RSS) is standard; the value is in the systematic combination and the cross-envelope analysis.
- **Rigor — strong on statistics, weak on workload coverage.** The use of matched-block non-parametric tests (Cochran's Q, McNemar, Friedman, Nemenyi) with explicit significance underlining in tables is commendable and rare in LLM efficiency papers. However, **GSM8K is evaluated on only 200/1319 instances and MMLU-Pro on 280/12032**, relying on the tinybenchmarks claim of ~2% estimation error — this is a defensible cost-driven choice but weakens fine-grained model ranking and means the Pareto "knee" near MMLU-Pro 28.2% vs 34.6% (a 6.4-point gap on 280 samples) is within sampling noise, which the paper does not flag.
- **Reproducibility — high.** Fixed Docker image, exact `cpupower`/`docker` commands listed in Table III, Ollama v0.23.2 pinned, deterministic temperature=0 decoding, warm-up discard + cool-down interval documented in Algorithm 1, code released. The Q4 quantization variants are explicitly the *default Ollama* ones (Q4_0 for TL/GM/P2/P3, Q4_K_M for QW/MS) — heterogeneous across models and **not ablated**, which confounds any cross-model cost comparison with quantization-format differences.
- **Significance — practitioner-relevant, academically modest.** The headline finding ("proxies predict cost but not precision") is unsurprising to specialists but the precise correlation numbers, the divergence between time-amplification (5–6×) vs energy-amplification (2.7–3.5×) under envelope tightening, and the per-benchmark non-dominated sets are directly actionable for edge-deployment decisions.
- **Red flags / overclaiming — mostly contained.** The authors are careful to call the desktop-with-caps setup an *approximation* of edge envelopes and explicitly limit claims to relative trends, not device-specific predictions (Sec. VII-E). They honestly acknowledge CPU-only execution excludes the GPU-equipped edge reality that dominates 2025+ smartphones. The one mild overclaim is presenting RQ2's non-dominated mid-sized model recommendation as broadly applicable while sampling only 280 MMLU-Pro instances.

## Strengths

- Clean, self-consistent experimental design: same backend, same decoding, same Docker image, only the hardware envelope varies — a textbook controlled study.
- Statistical rigor rare in this subfield: matched-block tests, post-hoc significance annotations in every results table.
- Direct hardware measurement (RAPL + RSS) rather than the prevalent FLOPs-based estimation, with energy and time explicitly shown to diverge on constrained devices.
- Pareto/non-dominated framing is the right vocabulary for multi-objective deployment decisions and is operationalized per benchmark, not just averaged.
- Honest AI-authoring disclosure and code release.

## Limitations

- **Energy scope**: RAPL CPU-package domain only; excludes DRAM, storage, and peripheral power. Authors flag this but it materially understates total device energy, especially on SoC-class edge hardware.
- **CPU-only execution** — no GPU acceleration, despite GPU-equipped edge devices being the dominant 2025+ deployment target. Time/energy/memory numbers would shift substantially on a GPU.
- **Heterogeneous quantization formats** (Q4_0 vs Q4_K_M) across the six models with no quantization-format ablation, confounding cost comparisons.
- **Tiny workload samples**: 200/1319 GSM8K and 280/12032 MMLU-Pro; the 6.4-point MMLU-Pro precision gap between Qwen2.5 and Mistral is within plausible sampling error.
- **Six models, all in 1.1B–7B range**; results may not extend to 0.5B-class or 13B+ models, nor to fundamentally different tasks (open-ended generation, agentic loops, multimodal).
- **Single inference backend (Ollama v0.23.2) and single decoding config** (greedy, fixed max tokens); generalization to llama.cpp, vLLM, or sampling-based decoding is untested.
- **Desktop-with-caps ≠ real edge/mobile hardware**: absolute values will not match a Raspberry Pi or smartphone; the authors correctly limit claims to relative trends.
- **No total-cost-of-ownership or carbon analysis** despite the "sustainable AI" framing — only per-inference energy is reported.

## Relevance

对于关注边缘/端侧 LLM 部署与可持续推理的研究者，本文提供了把"精度"与"时间/内存/能耗"联合度量的可复现 PTME 协议和帕累托选模型工具，直接回答了"用参数量或 FLOPs 选模型在资源受限场景下何时会选错"这一关键问题；其方法学（约束化 Docker + RAPL 直测 + 非参数统计检验）可作为后续轻量 LLM 评测模板，但对 GPU 加速、更大模型规模及开放生成任务的扩展仍待补。

## Questions for Further Exploration

- How does the proxy-vs-precision correlation break change for GPU-accelerated inference (Jetson, mobile NPU) where memory hierarchy, parallelism, and power profile differ fundamentally from CPU + RAPL?
- Would a quantization-format ablation (e.g. all six models at uniform Q4_K_M, plus Q8 and FP16) preserve the Qwen2.5-dominates-Pareto conclusion, or is it partly an artifact of Q4_0 underperforming Q4_K_M on the smaller models?
- Can the RQ3 envelope-sensitivity law (time ×5–6, energy ×2.7–3.5) be predicted a priori from the model's FLOP density and arithmetic intensity, enabling an analytic envelope-aware scheduler?
- Do the per-benchmark non-dominated sets remain stable when sampling-based decoding (temperature > 0, top-p) replaces greedy, given that stochastic decoding perturbs both precision and token count?
- How does PTME extend to agentic / multi-turn workloads where KV-cache growth and repeated prompt processing dominate — does memory remain flat in sequence length, and does the Pareto ranking shift?
- Can total-system energy (CPU + DRAM + storage + accelerator) be measured cheaply enough to replace RAPL-only accounting without breaking the reproducibility contract?
