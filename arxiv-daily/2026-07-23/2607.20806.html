Profiling Lightweight Large Language Models

Tomohiro Harada·Enrique Alba·Gabriel Luque | Saitama Univ. & Univ. of Malaga | 2026-07-23

Core finding

Static proxies — parameter count, FLOPs, loaded memory — predict inference cost but completely fail to forecast task precision on lightweight LLMs.

◉Key metric · Pearson R
0.36
correlation of any static proxy with task precision across all five resource envelopes.
vs 0.95–1.0 for the same proxies against cost (time / memory / energy) — scale predicts cheapness, not correctness.
◆Why this matters

Edge deployment hides a Pareto sweet spot that scale-only selection misses — proxy picks cheap models that silently blow accuracy targets.

Mid-sized models (Qwen2.5, Phi-3), not the cheapest or most accurate, win most real deployments.
⚠Critical edge

The six models ship in mixed quantization formats (Q4_0 vs Q4_K_M) with no ablation — so every cross-model cost gap, including the headline Qwen2.5-vs-Mistral Pareto "win," is partly a quantization artifact.

Uncontrolled confound
03

Methodology — the PTME protocol

PTME measures four orthogonal axes for each (model, dataset, envelope, decode) tuple and refuses to collapse them into one scalar — accuracy stays first-class, never averaged away into efficiency.

PPrecision
pass@1 (HumanEval, 164), exact-match numeral (GSM8K, 200/1319), MC accuracy (MMLU-Pro, 280/12032).
TTime
wall-clock end-to-end inference t_end − t_start, reported raw and per-token.
MMemory
peak RSS of backend + children + profiler — static footprint plus dynamic allocation.
EEnergy
Intel RAPL CPU-package cumulative delta E_pkg(t_end) − E_pkg(t_start).

Hardware: Intel i7-12700K (8P+4E), 64 GB DRAM, CPU-only, fixed Docker, Ollama v0.23.2, default Q4. Five envelopes cap P-cores, threads, frequency and RAM to emulate edge classes:

Stats: matched-block paired non-parametric tests — Cochran's Q + McNemar (binary precision), Friedman + Nemenyi (continuous cost), 5% significance. Code: github.com/tharada0126/llm_ptme.

05

Trade-offs — strengths vs limitations

▲ Strengths

  • Controlled design — same backend, decoding, Docker image; only the hardware envelope varies.
  • Statistical rigor rare in this subfield — matched-block tests with significance marks in every table.
  • Direct hardware measurement (RAPL + RSS) instead of FLOPs estimation; explicitly shows energy ↔ time divergence.
  • Pareto framing operationalized per benchmark, not averaged — the right vocabulary for multi-objective deployment.
  • Honest disclosure of AI-authoring (GPT-5.5 / Claude Opus 4.8) plus public code release.

▽ Limitations

  • Mixed quantization (Q4_0 vs Q4_K_M) with no ablation — confounds every cross-model cost comparison.
  • CPU-only execution; GPU-equipped edge is the dominant 2025+ target and would shift all numbers.
  • Tiny samples — 200/1319 GSM8K, 280/12032 MMLU-Pro; the 6.4-pt QW↔MS gap sits within sampling noise.
  • RAPL scope covers CPU-package only — excludes DRAM, storage, peripherals; understates SoC energy.
  • Six models, 1.1B–7B, one backend (Ollama), greedy decode — generalization to 0.5B / 13B+, vLLM, sampling untested.
06

Open questions for further work

Does the proxy-vs-precision break survive on GPU / NPU (Jetson, mobile NPU) where memory hierarchy and power differ from CPU+RAPL?
Would a quantization-format ablation (uniform Q4_K_M, plus Q8 / FP16) preserve the Qwen2.5-dominates-Pareto conclusion — or expose it as a Q4_0 artifact?
Can the RQ3 envelope-sensitivity law (time ×5–6, energy ×2.7–3.5) be predicted analytically from FLOP density, enabling an envelope-aware scheduler?
Do the non-dominated sets stay stable under sampling-based decoding (temp > 0, top-p), which perturbs both precision and token count?
How does PTME extend to agentic / multi-turn workloads where KV-cache growth dominates — does memory stay flat in length?
Can total-system energy (CPU+DRAM+storage+accel) be measured cheaply enough to replace RAPL without breaking reproducibility?
