> **一句话总结：** 提出WML（Workflow-Localized Mechanism Learning），通过Node-Mechanism Attribution将Agent Skill的修复从"文档/层级粒度"细化到"工作流节点+机制关系"粒度，单机制缺陷路由到L3资源、跨机制关系缺陷路由到L2组合协议，在SpreadsheetBench上Hard Accuracy达90.33%、零额外训练迁移到WikiTableQuestions达84.00%，并在编译执行下实现显著的token/调用节省。

> **TL;DR:** WML reframes structured Agent Skill optimization as workflow-localized diagnosis: a Node-Mechanism Attribution state `(n, Γ, ρ, τ)` pinpoints the failed workflow node, implicated mechanisms, defect relation, and smallest legal edit address (L3 resource for single-mechanism, L2 composition protocol for multi-relation), and a six-module WGSO loop reuses third-party Skill knowledge only when needed, patches under bounded scope, and gates on post-patch evaluation. On SpreadsheetBench it reaches 90.33±1.53 Hard Accuracy with DeepSeek (+6.00 pp over the strongest baseline EvoSkill's 84.33) and 74.67±3.51 with Qwen3.6-Flash (+4.67 pp over Seed Skill's 70.00), and the optimized Skills transfer zero-shot to WikiTableQuestions at 84.00±2.00 and 83.00±2.00 Denotation Accuracy; under a unified compiler it solves 40/50 tasks on Compiler-Supported50 (17 more than the best non-WML method) while using 32.73% fewer tokens and 48.28% fewer calls per hard PASS.

## 核心贡献

- **Node-Mechanism Attribution（节点-机制归因）**：将Skill修复从"文档级/层级级"编辑推进到"工作流节点 + 机制关系 + L2/L3编辑地址"的类型化定位。提出归因状态 `A=(n, Γ, ρ, τ)`，并施加路由契约：单机制缺陷（single-guidance）必须路由到L3资源，跨机制关系缺陷（multi-relation）必须路由到L2组合协议，从而把模糊的"在哪一层改"细化为"在哪个节点、哪种机制关系、哪个最小合法地址改"。
- **WGSO（Workflow-Guided Skill Optimization）六模块闭环**：把执行证据转化为本地化修复提案，仅在已部署Skill与优化器记忆不足时才检索第三方Skill知识；所有补丁受边界与保留约束限制，只有通过同批次再评估、确认有改进才提交；外部记录永不整段进入已部署artifact。
- **Patch-Strategy Memory（PSM，补丁策略记忆）**：以归因签名为索引，记录"哪种编辑类型、作用域、保留约束、验证要求在某一类局部缺陷上成功过"，与executor可见的Skill分离，使优化器能学到"如何安全应用"而不会污染部署态或泄露优化器状态。
- **跨骨架、跨基准的一致性提升**：在DeepSeek与Qwen3.6-Flash两个骨架、SpreadsheetBench与WikiTableQuestions两个基准上均居首；消融显示三大组件缺一不可；在统一LLM workflow compiler下，WML产出最"compiler-consumable"的Skill，兼顾成功率与效率。
- **Learn-once, compile-many范式验证**：证明一个经过优化的Skill可作为"过程性中间表示"，被共享compiler编译为类型化workflow与可执行代码，编译执行相比直接SkillAgent保留87.0%成功任务的同时，token减少84.90%、LLM调用减少90.39%。

## Key Contributions

- **Node-Mechanism Attribution** moves Skill repair from document- or layer-level editing to typed localization over workflow nodes, mechanism relations, and L2/L3 edit addresses. The attribution state `A=(n, Γ, ρ, τ)` and its routing contract (single-guidance ⇒ one mechanism ⇒ L3 address; multi-relation ⇒ ≥2 mechanisms ⇒ L2 address) resolve the inside-a-layer ambiguity left by prior layer-aware patchers.
- **WGSO**, a six-module closed loop, converts execution evidence into a local knowledge need, consults third-party Skills only when deployed Skill and optimizer memory are insufficient, applies bounded patches under preservation constraints, and commits a candidate only after post-patch evaluation verifies improvement.
- **Patch-Strategy Memory (PSM)** is an optimizer-side store indexed by normalized attribution signature, recording which edit kind, scope, preservation constraint, and verification requirement succeeded for a localized defect — it lets the optimizer reuse repair strategies without placing optimizer history or third-party text into the deployed Skill.
- **Consistent cross-backbone/cross-benchmark gains** plus component-wise ablation degradation and favorable success–efficiency trade-offs under a unified compiler, establishing that workflow-localized attribution and constrained knowledge reuse produce Skills that are both effective for agents and operationally consumable by a compiler.
- **A learn-once, compile-many architecture**, where an optimized Skill serves as a procedural intermediate representation translated by a shared compiler into typed workflows and executable code under a restricted runtime.

## Methodology

A structured Skill is modeled as `S_t = (S_t^{L1}, S_t^{L2}, S_t^{L3})`, where L1 holds discovery/activation metadata, L2 is the always-loaded workflow body, and L3 = {r_1…r_m} are mechanism resources loaded on demand. WML abstracts tool-agent execution into six domain-general functional nodes — context acquisition, target binding, operation selection, execution/transformation, state commit, and verification/termination — which are role descriptions that each domain instantiates with its own state and tools (not spreadsheet-specific objects).

For task-level diagnosis D_{t,i}, the **Node-Mechanism Attribution** state is `A_{t,i} = (n_{t,i}, Γ_{t,i}, ρ_{t,i}, τ_{t,i})`: the failed workflow node n, a non-empty set of implicated reusable mechanisms Γ, a defect relation ρ ∈ {single-guidance, multi-relation}, and a typed edit target τ containing layer, file, and section. A routing contract ties the relation to the layer: single-guidance forces exactly one mechanism and an L3 address (the resource implementing that mechanism); multi-relation forces ≥2 mechanisms and an L2 address (the composition protocol coordinating selection, ordering, scope/conflict handling, and joint verification at that node). The schema explicitly does not claim mechanism count universally determines layer.

Operationally the **WGSO loop** runs each round: (1) `ExecuteAssess` produces evidence E_t (outcomes, trajectories, evaluator feedback, successful evidence used as preservation constraints); (2) a diagnoser proposes mechanism anchors with file/section evidence; (3) a deterministic **guarded resolver** classifies the defect by testing guidance coverage — a missing/incorrect rule internal to one mechanism is single-guidance, whereas individually-available mechanisms with missing selection/ordering/scope/joint-verification form a multi-relation defect — and assigns τ to the smallest registered section capable of expressing the missing rule, intersecting candidate locations with registry-valid addresses and abstaining when that intersection is empty or evidence is insufficient; (4) for each proposal, if `GuidanceInsufficient` is true, the system retrieves a bounded `X_t ⊆ K_t` from the procedural-knowledge index initialized from external corpus C, else sets X_t=∅; (5) a typed patcher applies `Patch_L3` for single-guidance or `Patch_L2-comp` for multi-relation, with only the attributed address permitted to change; (6) `StructuredDiff` checks the candidate against τ and preservation constraints, then `ValidateAndGate` re-executes on the same batch and accepts/rolls back based on a score guard.

**Third-party Skills** are never appended to the prompt; they are converted to records `x=(u, m, s, p, v, γ)` (provenance, mechanism, applicability scope, procedure/decision rule, verification requirement, confidence) held in the optimizer-side index K_t, retrieved by mechanism/anchor + scope + past edit outcomes, and adapted/merged/rejected under the attribution target. **PSM** entries are keyed by a normalized attribution signature (node, mechanism set, defect relation, target layer) with values recording the successful edit kind, permitted scope, preservation constraints, postconditions, and outcome; `ReadMemory` exposes compatible entries only to the patcher, and only verified improvements update PSM. The prototype makes the edit boundary mechanically inspectable via structured diff, and uses a non-evolutionary one-candidate-per-round path for the main study.

## Results & Highlights

- **SpreadsheetBench Hard Accuracy (Table 1):** WML reaches **90.33±1.53** with DeepSeek and **74.67±3.51** with Qwen3.6-Flash. The strongest non-WML baselines are EvoSkill at **84.33±2.08** (DeepSeek) and Seed Skill at **70.00** (Qwen), so WML leads by **+6.00 pp** and **+4.67 pp** respectively. Against Official SkillGrad (the closest structured-Skill optimizer), margins are **+8.33 pp** (DeepSeek, 82.00±1.00) and **+8.67 pp** (Qwen, 66.00±3.61).
- **Zero-additional-training transfer to WikiTableQuestions (Table 1):** the learned Skills transfer without re-optimization to **84.00±2.00** Denotation Accuracy (DeepSeek) and **83.00±2.00** (Qwen), beating the strongest non-WML baselines (SkillOpt 81.67±2.52; Seed Skill 77.50) by **+2.33 pp** and **+3.00 pp**, and Official SkillGrad by **+3.00 pp** and **+7.00 pp**.
- **Component ablations on SpreadsheetBench (Table 2, DeepSeek, seeds 42/123/456):** Full WML reaches 90.00±1.00 Hard / 95.78±0.01 Cell. Removing Node-Mechanism Attribution drops Hard/Cell by **−5.33 / −7.89 pp** (the largest Cell degradation) and introduces 2±1 retries; disabling procedural-knowledge enhancement costs **−5.33 / −5.53 pp**; removing the patch-strategy meta-policy costs **−3.33 / −1.01 pp**. Full WML beats every ablation at every seed.
- **Compiler-Supported50 cross-Skill efficiency (Table 3):** WML solves **40/50** hard tasks, **17 more** than the strongest non-WML result (23/50 for EvoSkill/SkillOpt) — an absolute lead of **34 points** — and leads Cell Accuracy by **21.30 points**, while using **32.73% fewer tokens per hard PASS** (33,352 vs EvoSkill's 49,576) and **48.28% fewer calls per hard PASS** (1.35 vs 2.91).
- **Same-Skill execution-mode trade-off (Table 3):** the direct SkillAgent completes 6 additional tasks (46/50) and improves Cell by 6.84 points, but compiled execution **retains 40 of its 46 successful tasks (87.0%)** while reducing tokens by **84.90%** and stack-level LLM invocations by **90.39%**.
- **Optimization budget (Figures 2–3):** one complete WML optimization uses **991 requests, 23.14M input tokens, 0.561M output tokens**, with **20.92M input tokens cached (90.42%)**. Round 5 first reaches 0.90 Hard / 0.9510 Cell Accuracy; doubling the budget to 10 rounds leaves Hard at 0.90 and only nudges Cell to 0.9526, justifying the fixed five-round operating point.

## Authors & Credibility

All six authors (Zibin Lin, Shengli Zhang*, Taotao Wang, Yihan Xia, Deen Ma, Guofu Liao) are from **Shenzhen University, Shenzhen, China**, with Shengli Zhang as corresponding author. The work builds directly on a coherent recent lineage — SkillGrad (Wang et al. 2026b, arXiv:2605.27760) and SkillOpt (Yang et al. 2026, arXiv:2605.23904) — and positions itself precisely against TextGrad/GEPA, Voyager/DSPy/AFlow/WorkflowLLM, and SkillFoundry/SkillX. The paper uses two standard public benchmarks (SpreadsheetBench from NeurIPS 2024 Datasets & Benchmarks Track; WikiTableQuestions from ACL 2015), reports mean ± sample SD over three independent runs, exposes the full Algorithm 1, and **releases code and artifacts** at https://github.com/xiaolin9595/workflow-localized-mechanism-learning. The contributions are clearly scoped and the limitations section is candid.

## Critical Assessment

- **Novelty (genuine):** The typed attribution state and the routing contract that ties defect relation (single-guidance vs multi-relation) to layer (L3 vs L2) is a real conceptual advance over layer-aware patchers like SkillGrad, which "answer which package layer to edit, but leave ambiguity inside a workflow." The idea that two failures at the same node can require different attribution states and different edit contracts is the paper's sharpest insight.
- **Rigor (mixed):** Results span two backbones and two benchmarks, but the authors themselves concede they report only **descriptive dispersion over three seeds** and "descriptive mean differences rather than significance tests" because three seeds are insufficient for significance. The ablation deltas (e.g., −5.33 pp Hard) are reported without confidence intervals, so some component contributions are within plausible noise.
- **Reproducibility concerns — Compiler-Supported50 is a red flag:** This benchmark is "constructed once from WML development trajectories **for which the compiler produced runnable artifacts**," then held fixed across methods. This is a WML-favorable operating envelope selected by WML's own development set, which risks favoring the method that defined the slice. The 40/50 vs 23/50 gap is striking but should be read as "within the compiler-supported regime WML curated," not a domain-general efficiency claim. The paper is transparent that this "evaluates the compiler-supported capability domain," but a reader could still over-read the headline.
- **Weak/odd baselines:** On Qwen WikiTableQuestions, the no-optimization **Seed Skill (77.50) already beats Official SkillGrad (76.00±3.00)**, and No Skill (24.00) is anomalously low compared to its SpreadsheetBench 63.00 — suggesting high variance in the weak-method regime that inflates WML's relative margins. Baselines also "retain native training and selection strategies," so the comparison evaluates complete optimizers rather than isolating individual operations, which the authors acknowledge but which weakens causal attribution of gains to any one mechanism.
- **Scope limits (acknowledged):** Evaluation is confined to spreadsheet agents; the six-node ontology, mechanism vocabulary, and L2/L3 schema are explicitly flagged as needing validation in software maintenance, browser control, and embodied tasks. WikiTableQuestions is converted to spreadsheet-form execution, so "transfer" is within this execution setting, not general out-of-distribution transfer — the authors correctly label this, but the framing could mislead a skimmer. The post-patch gate uses same-batch comparison with no independent long-horizon regression set.
- **Significance (real if scoped):** The learn-once/compile-many evidence (87.0% task retention at 84.90% fewer tokens) is a credible systems contribution and the attribution framework is plausibly transferable, but the empirical claims should be treated as "for spreadsheet-form agent tasks under a unified compiler" until broader validation appears.

## Strengths

- The typed `A=(n, Γ, ρ, τ)` attribution state and its routing contract give a principled, auditable answer to "where exactly should this Skill be edited," directly resolving the inside-a-layer ambiguity that prior layer-aware optimizers leave open.
- WGSO's design is disciplined: external records never enter the deployed artifact verbatim, edits are bounded to a single attributed address, preservation constraints are derived from successful trajectories, and the gate accepts a candidate only after verified same-batch improvement — a clean separation of optimizer-side state from executor-facing Skill.
- Cross-backbone (DeepSeek + Qwen3.6-Flash) and cross-benchmark results with component-wise ablation degradation across all seeds strengthen the claim that gains come from the proposed mechanisms rather than a single lucky configuration.
- The learn-once/compile-many experiment quantitatively shows compiled execution retains 87.0% of a direct agent's successful tasks at a small fraction of the cost (84.90% fewer tokens, 90.39% fewer LLM calls), supporting a concrete hybrid architecture.
- Honest limitations section, public benchmarks, released code, and explicit caveat that WikiTableQuestions transfer is within spreadsheet-form execution rather than general OOD transfer.

## Limitations

- Evaluation is restricted to spreadsheet agents; the six-node ontology and L2/L3 schema are unvalidated in software, browser-control, and embodied domains.
- Only three seeds; the authors explicitly avoid significance tests, so component-ablation deltas (e.g., −5.33 pp Hard for attribution removal) carry no confidence intervals and could partly reflect noise.
- Compiler-Supported50 is derived from WML's own compiler-runnable development trajectories, making its efficiency conclusions WML-regime-specific rather than domain-general.
- The comparison evaluates complete optimizers (each baseline keeps its native training/selection) rather than isolating individual operations, muddying causal attribution of the gains.
- The post-patch gate relies on same-batch comparison; no independent long-horizon regression set guards against overfitting to the training batch.
- High variance among weak baselines (e.g., Qwen No Skill = 24.00 vs 63.00 across benchmarks; Seed Skill beating Official SkillGrad on one column) inflates some relative margins.

## Relevance

对研究"如何让冻结大模型Agent通过可复用Skill持续提升能力、并兼顾效率与可审计性"的方向高度相关：WML提供的"节点-机制归因 + 类型化局部补丁 + 编译执行"框架，直接对应Skill优化、工作流编译与Agent知识复用这一核心议题，其learn-once/compile-many范式对高效可审计Agent系统设计具有直接参考价值。

## Questions for Further Exploration

- Does Node-Mechanism Attribution's single-guidance/multi-relation routing contract hold in non-spreadsheet domains (software engineering, browser control, embodied tasks), or does the six-node ontology need re-instantiation per domain?
- How do WML's gains behave with more than three seeds and under statistical significance testing — are the ablation deltas (e.g., −5.33/−7.89 pp) robust or partly noise?
- Would a Compiler-Supported50 slice derived from each method's own runnable trajectories (rather than WML's) erase the 40/50 vs 23/50 efficiency gap, and how does the method perform on a method-agnostic compiler-supported slice?
- Can the post-patch evaluation gate be strengthened with an independent long-horizon regression set to prevent same-batch overfitting across rounds?
- Does PSM's attribution-signature indexing transfer knowledge across distinct Skills/tasks, or does it mostly memorize within-Skill repair patterns?
- How sensitive are the results to the frozen executor choice beyond DeepSeek and Qwen3.6-Flash, and to the 40-example / 5-round optimization budget?
