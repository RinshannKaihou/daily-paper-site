01

Methodology

Skill model & attribution

A Skill is S = (L1 metadata, L2 workflow body, L3 on-demand resources). Failure diagnosis produces a typed attribution state:

A = ( n, Γ, ρ, τ )

failed node n, implicated mechanisms Γ, defect relation ρ, and the smallest typed edit target τ. A routing contract resolves the inside-a-layer ambiguity left by prior layer-aware patchers:

· single-guidance (one mechanism) ⇒ L3 resource
· multi-relation (≥2 mechanisms) ⇒ L2 composition protocol

WGSO — six-step loop

  1. ExecuteAssess — gather evidence, trajectories, preservation constraints.
  2. Diagnose — propose mechanism anchors with file/section evidence.
  3. Guarded resolver — classify single- vs multi-relation; assign τ or abstain.
  4. Bounded retrieval — fetch external knowledge only if guidance insufficient.
  5. Typed patcher — Patch_L3 or Patch_L2-comp, single attributed address only.
  6. ValidateAndGate — re-execute same batch; commit only on verified gain.

PSM (Patch-Strategy Memory) sits optimizer-side, indexed by attribution signature — reusable repair strategies that never leak into the deployed Skill. Third-party Skills become records, never appended to prompts.

Strengths & limitations

Strengths

What holds
  • Typed A=(n,Γ,ρ,τ) state + routing contract gives a principled, auditable answer to "where exactly to edit."
  • Disciplined WGSO: external records never enter the deployed artifact verbatim; edits bounded to one attributed address.
  • Cross-backbone + cross-benchmark wins with per-seed ablation degradation — gains look mechanism-driven, not lucky.
  • Learn-once/compile-many quantifies the hybrid architecture: 87.0% retention at a fraction of the cost.
  • Honest limitations section, public benchmarks, released code.

Limitations

Watch out
  • Restricted to spreadsheet agents; six-node ontology and L2/L3 schema unvalidated in software, browser, embodied domains.
  • Only three seeds; authors avoid significance tests, so ablation deltas carry no confidence intervals.
  • Compiler-Supported50 is derived from WML's own runnable dev set — efficiency claims are WML-regime-specific.
  • Baselines keep native training/selection, so complete optimizers are compared — causal attribution to one mechanism is muddy.
  • Post-patch gate uses same-batch comparison; no independent long-horizon regression set.
04

Open questions

  • Does the single-guidance / multi-relation routing contract hold outside spreadsheets, or must the six-node ontology be re-instantiated per domain?
  • Are ablation deltas (−5.33 / −7.89 pp) robust under significance testing with more than three seeds, or partly noise?
  • Would a method-agnostic compiler-supported slice erase the 40/50 vs 23/50 efficiency gap?
  • Can the gate be strengthened with an independent long-horizon regression set to prevent same-batch overfit?
  • Does PSM indexing transfer knowledge across distinct Skills, or mostly memorize within-Skill patterns?
  • How sensitive are results to the frozen executor choice and the 40-example / 5-round budget?
