Methodology — a four-step cognitive chain

entity → document → evidence → domain
entity
T1 · 39 tasks
Scientific Database Navigation
Reverse-trajectory construction: replace explicit IDs with nested attribute constraints, forcing multi-hop reasoning over DB records.
metric: Exact-Match (symmetric penalty)
document
T2 · 32 tasks
Ambiguous Literature Retrieval
Feature denoising + fuzzification obscure surface cues; validation-constraint injection keeps answer uniqueness verifiable.
metric: Exact-Match accuracy
evidence
T3 · 14 tasks
Missing Reference Completion
Citation-dense paragraphs rewritten to erase textual overlap; two-step LLM judge checks core work, then bibliographic attributes.
metric: accuracy (LLM-judged)
domain
T4 · 18 tasks
Cross-Source Structured Synthesis
Expert comparison tables; agents must fill a strict schema by fusing details scattered across many papers. Hierarchical recall.
metric: item-level + row-level recall

Three-stage quality control

  • Query difficulty calibration — explicit index blocking + long-tail entity preference to defeat memorization.
  • Human cross-validation — annotators must fail to solve a question via search within 10 minutes, or it's discarded.
  • Answer uniqueness verification — search-enabled LLMs (Gemini-3-Pro, o3) hunt for alternatives; any valid one kills the task.

Difficulty-aware overall score

Score = 0.2·T1 + 0.2·T2
        + 0.3·T3 + 0.3·T4
Up-weights evidence-grounding & synthesis. Four full re-runs per model; mean overall variance 0.78.

T4 — The Synthesis Cliff

Best agent fills only 30.14% of item-level cells and reconstructs 18.59% of complete rows. Primary-key recall < 60% for every system — essential entities are never retrieved, so alignment is infeasible downstream.

T3 — Missing Reference Completion

OpenAI Deep Research 59.91% vs Gemini-3-Pro+search 49.40% vs Gemini-3-Pro no-search 13.69%. Search buys a lot here.

Search Can Hurt

On T1, GPT-5.1+search (15.38%) underperforms GPT-5.1 (17.95%). Search amplifies "hypothesis-first" reasoning — the SCN10A/Nav1.8 case: no-search honored a 604-aa constraint, search-only fabricated a non-existent construct.

Hop Length ≠ Difficulty

On T1, accuracy doesn't decline with hops. Tongyi-DR-30B-A3B: 25.0% at 2-hop but 62.50% at 5-hop — agents "guess-and-verify", unlike humans (66.7% → 25.0%).

Strengths & Limitations

side by side

Strengths

  • Genuinely fills the gap between general deep-search benchmarks (BrowseComp, WideSearch) and closed-book scientific QA (SciBench, GPQA, HLE).
  • Anti-shortcut construction — index blocking, long-tail preference, fuzzification — materially harder to game than template- or LLM-synthesized tasks.
  • Negative results reported honestly: counterintuitive hop-length finding and search-degrades-performance cases, backed by concrete trajectories.
  • Difficulty-aware weighting (T3/T4 = 0.3 each) emphasizes what matters for real research assistance.
  • Four-run variance analysis + a five-case qualitative failure taxonomy go beyond typical benchmark papers.

Limitations

  • Scale: only 103 tasks; T3 (14) & T4 (18) so small that per-task metrics are noisy — no CIs reported.
  • LLM-judged T3/T4 metrics ship without a reported judge-accuracy spot-check.
  • No public task release — limits independent reproduction as closed-source agents drift ("trust-us-to-run-it").
  • Human baseline is thin — T1 multi-hop only; no overall human reference for T2–T4.
  • Coverage skew toward fields with structured DBs (chem, materials, bio); social-science / humanities workflows absent.
  • Failure-mode frequencies not quantified — only illustrated (Fig. 8–12).

Questions for Further Exploration

open threads
Q1 · T4 collapse

How much of the T4 collapse is retrieval breadth (primary-key recall <60%) vs schema-following vs cross-source alignment — and which dominates when retrieval is fixed (e.g., a curated candidate-paper set)?

Q2 · Scale

Would scaling T3/T4 to a few hundred tasks change the ranking, or do per-task noise concerns wash out at scale?

Q3 · Judge audit

Can a human spot-check of the LLM judge on T3/T4 quantify judge error, and does it differ by discipline?

Q4 · Hypothesis-first bias

Is the "search-degrades-performance" effect robust under controlled retrieval, or specific to noisy open-web? Could a verify-then-commit protocol close the gap (cf. the SCN10A case)?

Q5 · Difficulty proxy

Does "hop length ≠ difficulty" generalize beyond T1? Can a behavior-based difficulty predictor (search calls, guess-and-verify cycles) replace hop count?

Q6 · Open vs closed

How do open, hackable agents (WebSailor, WebThinker, xbench-style) perform given the same search budget as closed Deep Research products — separating model capability from product orchestration?
