GuardianAgentBench: Where Agents Fail and How to Guard Them

Vishal Ishwar Naik · Chenyu Xu · Donna Dong · Hussein Hassan · Abhishek Pradhan · Ofer Mendelevitch · Tallat Shafaat · Humayun Irshad / Jul 23, 2026 / Vectara, Inc. & Iowa State University
agent-safety llm-agents benchmark guardrails tool-use evaluation
Key finding

The first agent-safety benchmark on production frameworks — even the best frontier model fails one in four scenarios.

Key metric · results01
74.8%

Best Overall accuracy — Claude Opus 4.5 on Vectara. Across 580 scenarios, frontier agents still fail ~1 in 4 times.

19.9% recovered

Failures recovered by the guardrail at a 0.5% false-positive rate (Claude Opus 4.5 / LlamaIndex, 30 of 151).

−31.1pts

Accuracy fall from 1 → 7 turns (82.3 → 51.2). Long-horizon planning, not tool count, is the steeper bottleneck.

Why this matters02

Moves safety evaluation out of simulated sandboxes and onto the frameworks practitioners actually deploy — with an actionable under-call vs. mis-call diagnostic and a deployable execution-time guardrail.

Critical edge03

Vendor conflict. Vectara is both an author affiliation and the platform hosting the winning configuration — and the conflict is undisclosed.

  • Same-vendor judging: Claude Sonnet 4.5 judges a leaderboard topped by Claude Opus 4.5; validation covers only 60 cases.
  • Apples-to-oranges defense: the guardrail runs an extra Claude Sonnet 4.5 per call — the “+2.8 to +7.7” is partly extra-LLM vs. a static string.
  • No variance, no release: all deltas are point estimates; dataset & guardrail code not clearly open-sourced.
01 /Methodology

A two-stage pipeline run on three real frameworks.

Scenario construction. Stage 1 builds happy-path scenarios across five LLM-driven sub-stages — intent & prompt generation, parameterized tool-response simulation, dependency-annotated ground-truth DAGs, and response-quality rubrics. Stage 2 mutates tool responses along five adversarial modes (Massive Data, Error Conditions, Multiple Matches, Prompt Injection, Partial Data), regenerating ground truth each time.

Execution & scoring. Each scenario runs end-to-end on LangChain, LlamaIndex, and Vectara through a unified adapter — so behavioral gaps trace to the model, not the harness. A Claude Sonnet 4.5 judge scores response correctness and action correctness independently; failures fall into five taxonomy types (ITS / IMP / MTC / RTC / ITO).

Guardrails. Three rule-based checks — Argument Validation, Tool Coverage, Relevance & Cost — run concurrently before each tool step, issuing Pass / Corrective-Feedback / Block verdicts with up to two retries.

  • 580 scenarios · 6 domains · 81 tools
  • 1,177 sequential turns · mean tool-set 2.74 (1–7)
  • 398 happy-path (68.6%) + 182 adversarial (31.4%)
  • 6 frontier models × 3 frameworks
  • 5-stage generation + dual-annotator review + 3 refinement cycles
  • Judge–human alignment 93.3% (56/60)

Strong models

Under-call required tools

Fail predominantly by omitting needed calls — MTC 52–57% of failures (GPT-5.2 Pro, GPT-OSS-120B, Gemini-3-Pro).

Weak models

Mis-select & over-call

MTC only 36–40%, but high repeated calls RTC 29–33% and mis-selection ITS 14–25% (DeepSeek-V3.2, Qwen3-Max).

Execution-time guardrails beat system-prompt defense on every model — +2.8 to +7.7 vs. negligible-or-negative prompt gains for the strongest models (Claude Opus 4.5 +5.7 guardrail vs. +0.4 prompt). On Claude Opus 4.5 / LlamaIndex: 19.9% of failures recovered at a 0.5% false-positive rate. Tool-ordering errors (ITO) are essentially solved at 0.6–4.4%.
03 /Strengths & limitations
+ Strengths
  • Ecological validity: first safety benchmark on actual production frameworks, not Python sandboxes.
  • Clean design: unified adapter isolates model vs. framework effects.
  • Actionable diagnostic: the under-call vs. mis-call split maps directly to model-specific remediation.
  • Honest counter-finding: system-prompt safety text gives ~zero or negative gains for top models.
  • Falsifiable: full prompt templates disclosed; judge & human-alignment rate named.
− Limitations
  • Simulated tools: all responses mocked — cannot expose latency, auth drift, schema drift, or real data noise.
  • Thin long-horizon coverage: only a handful of 6–8 turn scenarios undercut the steepest part of the curve.
  • Single judge: no cross-model judge agreement; same-vendor top model invites bias.
  • No variance or significance on any headline number or delta.
  • Guardrail is a proof-of-concept on one framework; cost, latency, transferability unmeasured; no clear data/code release.
04 /Open questions
  1. Does the Claude-judging-Claude alignment inflate the leaderboard — and would a cross-vendor or human panel re-rank models, especially at 6–8 turns?
  2. How much of the “+2.8 to +7.7” guardrail gain survives if it is stripped of its backing LLM and reduced to pure schema/rule checks?
  3. Which of the three guardrails drives recovery — does Tool Coverage Check alone fix most of the MTC regime?
  4. Does the under-call vs. mis-call dichotomy hold on genuinely long-horizon tasks (15+ turns) with real, correlated tool-API failures?
  5. How do the failure regimes shift under optimized (e.g. gradient-based) prompt injection rather than LLM-generated perturbations?
  6. Can the 0.5% false-positive rate hold when tools overlap — where “redundant” calls may be legitimate fallbacks?
