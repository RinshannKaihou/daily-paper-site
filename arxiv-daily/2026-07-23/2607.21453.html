Test-Time Scaling via Error Localization

Rajiv Shailesh Chitale · Rahul Madhavan · Taneesh Gupta · Deepanway Ghosal · Aravindan Raghuveer · Google DeepMind · 23 Jul 2026
◆ Key Finding

TTEL localizes errors in failed LLM reasoning by comparing feedback-conditioned vs. null-baseline token probabilities, then re-generates only the faulty suffix.

Methodology

TTEL operates on a single frozen model πθ that acts as both generator and self-evaluator — no training, no auxiliary verifier.

  1. Generate & record student probs. Decode trajectory y normally, recording pt(S) = πθ(yt | x, y<t).
  2. Feedback re-score (teacher). Environment or terminal-failure check returns feedback f; re-score the same tokens → pt(T)(f). Raw spike Δt(f) = pt(S) − pt(T)(f).
  3. Null-feedback baseline. Append a non-diagnostic f∅ (“repeat the attempt, skip redundant thinking”) → baseline spike Δt(f∅).
  4. Filtered spike. gt = pt(B)(f∅) − pt(T)(f) isolates feedback-specific disagreement from generic context drift.
  5. Branch at the peak. t* = argmax gt; truncate at t*−1, retain the valid prefix, re-generate only the suffix (threshold τ=0.06).
  6. Restart fallback. If no spike passes τ, restart from root instead of over-committing to an uninformative failure.

  • RQ2 context ablation (LCB V6, k=16): dropping the full reasoning trace cuts GenFB pass@k 0.630 → 0.597 (−5.3%); rich env feedback (EnvFB) lifts it to 0.658 (+5.5%). The thought trace is strictly necessary.
  • RQ3 null-baseline ablation: removing the f∅ subtraction makes Turn-1 detected spikes explode 19.3 → 486.0 (~25× false-positive blow-up); pass@k falls to 0.592. The filter is load-bearing, not cosmetic.
  • Theorem 1 (branching advantage): under autoregressive prefix consistency, branching beats restart by (1−pa)(sa − s¬a) whenever reaching the correct prefix helps.

Strengths & Limitations

+ Strengths

  • Elegant, training-free with a clean lineage to self-distillation RL (SDPO / GKD / OPSD).
  • Null-baseline subtraction is the standout idea — evidenced by the 486-vs-19.3 spike blow-up when removed.
  • ~2× compute reduction on LiveCodeBench at higher accuracy.
  • Works in math with generic feedback alone, not only code with execution traces.
  • Clear RQ1–RQ3 ablation structure; formal (if assumption-laden) branching theorem.

− Limitations

  • N=30 math benchmarks (AIME/HMMT-25) — wide CIs; “strictly dominating” is stronger than error bars justify.
  • Only 8B & 4B open models; no frontier-model validation where self-correction may already be strong.
  • Hand-tuned, sensitive hyperparameters (τ=0.06) with no reported sensitivity study.
  • Thin baselines — no PRM-guided or Tree-of-Thoughts comparison despite surveying them.
  • Re-scoring ≈ doubles forward passes per failed trajectory; wall-clock cost not analyzed.

Questions for Further Exploration

?Does the spike signal stay discriminative on frontier-scale / RL-trained models (Gemini 2.5, DeepSeek-R1) that already self-correct — or does it collapse?
?Is there a principled, data-driven way to set τ instead of a fixed 0.06, and how sensitive is pass@k to the exact f∅ wording?
?Can the two extra re-scoring passes be amortized via speculative / cached KV reuse, and does TTEL still win on wall-clock?
?Could PRM scores replace or sharpen the probability-spike branch point?
?Does the prefix-consistency assumption hold for instruction-tuned models that rephrase, and can constrained decoding recover the theoretical gap?
?Does it extend to agentic / multi-tool settings where feedback is a trajectory of tool outcomes, not a single pass/fail?
