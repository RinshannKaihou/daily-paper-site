Key metric — probe separability

0.916 AUROC

A linear probe on first-token hidden states separates pressure-driven commits from healthy commits and productive continues — against a 0.5 random baseline.

PR-AUC 0.921 · replicates 0.841 (Qwen3-32B) · 0.921 (TravelPlanner)
PSPR lift: ReAct CP 29.3 → 33.2 on Qwen3-32B

Why this matters

PSPR is a zero-fine-tune plugin that senses agent pressure online and steers it away — a template for self-monitoring, reliability-aware agent loops.

零微调、即插即用：把探针信号变成智能体的在线自我监控与反思触发机制，直指长程任务可靠性这一核心痛点。

Critical edge

Strict case-level accuracy stays ≈ 0.0 for essentially every method — PSPR reduces a specific failure mode; it does not make agents solve tasks.

01 Methodology

  • Setting: DeepPlanning-Travel — 120 travel-planning tasks with verifiable hard constraints, offline tools; backbones Qwen3-14B / Qwen3-32B / OLMo-3.1-32B.
  • Three-way contrast set at action boundaries (first-token hidden state): PresC pressure commits (Ssat ≤ 0.3, polish ≥ 4) vs two controls — HealC healthy commits (Ssat ≥ 0.85, polish ≥ 4, kills the "detect submission form" shortcut) and ProdC productive continues (kills the "detect difficulty" shortcut). ~545 labeled states; human + external-LLM audits agree 96–100%.
  • Steering: CAA directions PresC−HealC and PresC−ProdC, residualized against the generic commit direction before intervening.

PSPR trigger ladder — probe score s at every action boundary, thresholds fixed across all backbones:

s < 0.4observe — no intervention
0.4 ≤ s < 0.65add pressure-relief direction (activation addition)
s ≥ 0.65explicit state organization — model-generated, ≤ 2× / trajectory

No fine-tuning, no gold labels at deployment; plugs into CoT, ReAct, and Reflexion unchanged.

CP = Composite Score · CS = Commonsense Score (0–100). Improvements hold across all 3 backbones × 3 base methods.

  • Probe vs targeted controls: AUROC 0.890 vs healthy commits, 0.929 vs productive continues — not just detecting submission or difficulty.
  • Mitigation diagnostics: constraint clarity + action map cut probe pressure 0.62 → 0.13, raise continuation 0.28 → 0.87 and repair 0.08 → 0.85; the appended span earns 19.1% of attention at 11.9% token share (~1.6×).
  • Timing drives the gain: random-boundary organization hurts (CS 29.4 vs 32.2); periodic-3 (34.2) still trails probe-timed PSPR (36.0).
  • Statistical honesty: paired bootstrap (3,000 resamples) ΔCS +4.2, 95% CI [0.4, 8.0] — barely excludes zero; Avg@3 gain (+2.1) is smaller than pass@3 (+3.8).
  • Generalization: TravelPlanner micro pass 60.5 → 72.3 but Final Acc flat at 2.5; Chinese Travel CP 19.4 → 23.2 — not English-specific.
  • Cost: turns 4.62 → 7.94, tool calls 7.57 → 8.95 (CoT) — the extra execution is the intended shift from premature finalization to continued verification.

03 Strengths

  • Falsifiable hypothesis with a well-controlled contrast set that rules out both obvious probe shortcuts (submission form, generic difficulty).
  • Validation discipline: label-reliability audits, held-out splits for probe and directions, replication across scale, language, and three benchmarks; non-probe trigger controls.
  • PSPR is genuinely practical: no fine-tuning, no deployment gold labels, thresholds fixed across backbones, explicit cost accounting.
  • Honest framing — claims an operationalized correlate of premature closure, not a cause; authors' own limitations section is unusually candid.

04 Limitations

  • LLM-teacher dependence: DPS and constraint labels come from Gemini 3.1 Pro; HealC threshold had to be relaxed on TravelPlanner — contrast-set construction is fragile off the home benchmark.
  • Oracle-assisted mechanism story: the 0.62 → 0.13 mitigation spans use gold-ish dataset parsing — read as upper bounds, not what deployed PSPR achieves.
  • No strict metric improves: all gains are partial-satisfaction metrics; pass@3 may inflate them; thresholds are hand-set and steering magnitudes modest.
  • White-box only: needs hidden-state access plus a per-model rollout/annotation phase; no code release mentioned.
  • Scope: textual, verifiable planning tasks — unknown for open-ended or multimodal agent environments.

05 Questions for further exploration

  1. Can pressure be detected in API-only models via behavioral proxies — e.g. online divergence between delivery polish and constraint progress?
  2. Would steering toward evidence gathering (a "constraint-completion" direction) compose better with PSPR than steering away from commitment?
  3. Does pressure sensing transfer to non-thinking or RL-trained agents, given the Qwen3 backbones ran in thinking mode?
  4. Could the probe score serve as a dense internal reward or curriculum signal for self-evolving agents?
  5. Would the same state appear in settings where abstaining — returning "unsolved" — is the correct closure?
