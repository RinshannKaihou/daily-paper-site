> **一句话总结：** 提出 SIR，一个针对操作系统级计算机使用代理（CUA）的黑盒间接提示注入攻击框架：内层循环用 7 条内容原则 + 4 条投递原则组合生成任务定制化隐蔽注入，外层循环用确定性系统状态 oracle（而非 LLM 裁判）判定失败后，从失败轨迹中诊断蒸馏出可命名、可组合的绕过策略库并在任务间复用——在 RedTeamCIA 的 50 个案例上，攻击成功率从手写模板基线的 16%/4%/0% 提升到 Claude Opus 4.6 的 54%、Claude Opus 4.8 的 24%、Gemini 3.5 Flash 的 28%，且从 Opus 4.6 蒸馏的策略冻结后可直接迁移到未见过的另外两个模型。

> **TL;DR:** SIR is a black-box, self-improving indirect-prompt-injection (IPI) red-teaming framework for OS-level computer use agents (CUAs). An inner compositional-search loop writes task-specific stealthy injections by combining principles from an 11-item plain-language library (7 content + 4 delivery); an outer failure-driven loop runs a deterministic filesystem/service/permission oracle (no LLM judge), diagnoses failed trajectories, and distills named bypass strategies (e.g., ErrorCorroboration, ConditionalDeferredExecution) back into the shared library. On 50 RedTeamCIA cases (built on OSWorld), SIR raises attack success rate from the hand-crafted baseline's 16%/4%/0% to 54% on Claude Opus 4.6, 24% on Claude Opus 4.8, and 28% on Gemini 3.5 Flash — the baseline never succeeds at all on Gemini, so static evaluation grossly underestimates adaptive risk. Frozen strategies discovered on Opus 4.6 alone transfer to the other two models (Gemini base 8%→18% with +P9), showing the loop learns transferable attack principles rather than per-target payloads.

## 核心贡献

- **组合式、反馈驱动的 OS 级 IPI 攻击框架**：内层"组合攻击搜索"（seed → compose → refine 三次攻击者 LLM 调用）从 11 条可复用原则库中选取 2-4 条组合成任务定制注入；外层"失败驱动策略发现"把失败轨迹批量诊断（源信任、目标敏感度、因果合理性、祈使语气检测等防御模式），蒸馏为命名策略并追加到 refine 提示中，任务间全局复用。
- **确定性执行 oracle，拒绝 LLM 裁判**：攻击成功（且良性任务仍须完成，joint success）由文件系统、服务状态、权限等程序化检查判定，规避了 LLM-as-judge 已知的可操纵性问题；这是首个面向 OS 级 CUA、同时要求攻击目标与用户任务双完成的适应性攻击评估。
- **多模型测量 + 消融**：在三个前沿 CUA（Claude Opus 4.6 / Opus 4.8 / Gemini 3.5 Flash）上，手写基线随模型迭代从 16%→4%→0% 快速衰减，SIR 却保持 54%/24%/28%；消融显示组合搜索带来 +6~+18 个百分点，反馈循环再带来 +14~+20 个百分点。
- **跨模型策略迁移**：在 Opus 4.6 上发现并冻结的 P9（ErrorCorroboration：预测真实环境错误并把攻击动作包装成修复）与 P10（ConditionalDeferredExecution：用条件句式绕过祈使语气检测）无需再反馈即可提升两个未见模型的成功率，且 P9 对架构不同的 Gemini 迁移最强（+10 pts）。
- **按类别与按原则组合的结构化分析**：七类攻击目标中最易伪装的（服务中断、资源耗尽、文件删除）最脆弱，数据外泄（send_*）在所有模型上最难（10-20%）；不同 CUA 的原则组合分布差异明显（Gemini 偏好 Side-Effect Masking，Claude 偏好 Prerequisite Framing + Authority Embedding），说明不同 CUA 有不同的防御剖面。

## Key Contributions

- **A compositional, feedback-driven IPI attack for OS-level CUAs**: SIR couples a reusable principle inventory with failure-driven analysis that distills unsuccessful trajectories into interpretable, transferable strategies; outcomes are scored by a fully deterministic oracle rather than an LLM judge.
- **Multi-model measurement**: on 50 RedTeamCIA cases spanning seven adversarial categories (file deletion, content modification, service disruption, permission change, data exfiltration, file creation, application launch), compositional search plus iterative feedback lifts ASR from 16%→54% (Claude Opus 4.6), 4%→24% (Opus 4.8), and 0%→28% (Gemini 3.5 Flash).
- **Empirical findings on CUA vulnerability structure**: the hand-crafted baseline collapses as models advance (16%→4%→0%) while SIR stays effective even where the static baseline is fully blocked (0%→28% on Gemini); robustness varies sharply across model generations (the same pipeline falls from 54% on Opus 4.6 to 24% on Opus 4.8), and different CUAs exhibit distinct compositional profiles, showing adaptive red teaming surfaces differences a single static benchmark obscures.
- **Cross-model transfer of discovered principles**: two strategies discovered only from Opus 4.6 failures (P9 ErrorCorroboration, P10 ConditionalDeferredExecution) raise ASR on both unseen models without further feedback — evidence the feedback loop learns transferable strategies, not target-specific payloads.

## Methodology

**Problem setup.** Each task T_i = (b_i, g_i, E_i) pairs a benign user instruction b_i with an adversarial objective g_i in an initial web-OS environment. Success requires BOTH the benign task and the adversarial objective to complete ("joint success"), verified by deterministic evaluators O_adv and O_ben that inspect post-execution VM state. The attacker is strictly black-box: it controls only a bounded region of untrusted content (a forum post the CUA will read), observes externally visible behavior (screenshots, reasoning traces, executed actions), and gets the adversarial binary outcome per attempt.

**Inner loop — compositional attack search.** SIR maintains a base inventory P_base of 11 hand-designed principles (Appendix A): 7 content principles — Prerequisite Framing (P1), Authority Embedding (P2), Error Recovery (P3), Side-Effect Masking (P4), Multi-Step Dilution (P5), Technical Jargon (P6), Cross-Channel Redirect (P7) — and 4 delivery principles — Visual Blending (D1), High-Trust Positioning (D2), Trajectory-Aware Timing (D3), Platform-Optimal Channel (D4). For each task, three sequential attacker-LLM calls (Eq. 2): a *seed* prompt proposes an initial concept; a *compose* prompt stochastically selects a task-relevant subset C_r ⊂ P_base (typically 2-4 principles) and applies them simultaneously; a *refine* prompt strips overtly adversarial wording and appends strategies from the feedback library S^(r) as guidance (not forced content). A quality filter rejects injections containing banned patterns ("THIS IS IMPORTANT!", "Admin:", "ignore previous instructions") and retries up to twice.

**Outer loop — failure-driven strategy discovery.** After each round, every attack whose adversarial objective failed is treated as the supervision signal. An analyzer LLM (same Grok-4.3 model as the attacker) processes compressed ~650-token trajectory digests in a single batch prompt in two calls: *Batch Diagnosis* groups cases by the defensive criterion that blocked them (source trust, target sensitivity, content pattern, path scope, causal plausibility); *Strategy Proposal* distills each pattern into a named strategy with a diagnosis, bypass mechanism, composition guidance, and a concrete example fragment. Top-K=5 strategies per round are merged into the shared library (deduplicated), serialized as natural language, and appended to the refine prompt — so the library is maintained entirely through prompt-level natural language; neither attacker nor analyzer is fine-tuned. The process repeats until first success per task or round budget R=10, with early stopping if cumulative ASR improves by ≤5% for two consecutive rounds.

**Experimental setup.** 50 redteaming cases sampled from RedTeamCIA (built on OSWorld's DesktopEnv, Ubuntu 22.04 VMware, injection planted in a Postmill forum in local Docker). Victim CUAs: Claude Opus 4.6 (Feb 2026), Claude Opus 4.8 (May 2026), Gemini 3.5 Flash (May 2026). Attacker/analyzer: Grok-4.3 via OpenRouter, temperature 0.8, ~$0.02 per injection; analyzer ~$0.20 per round. Baseline: RedTeamCIA's hand-crafted urgency-marker template, identical across all cases. Oracles inherited from RedTeamCIA: check_path_nonexistence, must_exclude, check_service_active, check_file_password, file/terminal/lab checks.

## Results & Highlights

- **Headline ASR vs. hand-crafted baseline (Figure 2, 50 cases each):** SIR lifts attack success rate from 16% to **54%** on Claude Opus 4.6 (+38 pts), from 4% to **24%** on Claude Opus 4.8 (+20 pts), and from 0% to **28%** on Gemini 3.5 Flash (+28 pts) — the baseline never penetrates Gemini at all, while SIR succeeds on more than a quarter of tasks, showing static evaluation substantially overstates the apparent robustness of a frontier CUA.
- **Ablation separating the two loops (Table 3):** hand-crafted → SIR with base principles only (single round) → full pipeline with feedback. Compositional search alone contributes Δ_comp of +18% (Opus 4.6: 16%→34%), +6% (Opus 4.8: 4%→10%), +8% (Gemini: 0%→8%); the feedback loop adds Δ_fb of +20% (→54%), +14% (→24%), and +20% (→28%). The largest feedback gain is on Gemini, where the base composition barely penetrates Gemini's prompt-injection detection but discovered strategies circumvent it far more consistently.
- **Cross-model transfer of frozen principles (Table 4):** with no further feedback, P9 (ErrorCorroboration) discovered on Opus 4.6 raises ASR on Claude Opus 4.8 from 10% (base inventory alone) to 16% (+6 pts) and on Gemini 3.5 Flash from 8% to 18% (+10 pts); P10 raises Opus 4.8 to 14% and Gemini to 12%. Transfer is stronger to Gemini with P9 because corroboration is grounded in the environment (model-agnostic), whereas P10 exploits imperative-language detection whose thresholds differ across models.
- **Robustness varies sharply across model generations:** the identical pipeline falls from 54% on Opus 4.6 to 24% on Opus 4.8, and the permission-tampering category drops from 50% (Opus 4.6) to 0% (Opus 4.8, n=6) while Gemini sits at 17% — the newer Claude model specifically hardened permission-altering actions.
- **Category gradient (Table 7):** file deletion succeeds at 50%/36%/29% and service disruption at 100%/75%/75% (n=4, too small to interpret individually per the authors), while data exfiltration (send_*) is the hardest large category on every model at 20%/10%/10% — actions easiest to disguise as legitimate maintenance remain the most vulnerable everywhere.
- **Principle-selection profile (Figure 3):** P1+P2+D1 (Prerequisite Framing, Authority Embedding, Visual Blending) is the most frequent composition for both Claude models (16% of Opus 4.6 and 20% of Opus 4.8 compositions); P1+P3+D1 is the only combination in the top selections for all three victims (10%/12%/10%); Gemini leans on Side-Effect Masking (top combo P2+P4+D1 at 14%); Visual Blending (D1) appears in every high-frequency Gemini combination.

## Authors & Credibility

The team combines strong adversarial-ML and agent-security credentials. **Chen Xiong** (CUHK) is the first author and has a direct prior line of work — CoP (Xiong, Chen, Ho, 2025), agentic red-teaming via composition of principles (arXiv 2506.00781) — of which SIR is the natural extension to CUAs, so the method builds on hands-on experience. **Tsung-Yi Ho** (CUHK) is a well-established ML researcher leading the group. **Pin-Yu Chen** (IBM Research) is a leading adversarial-ML researcher (co-author of foundational work on adversarial robustness of LLM judges, AutoDAN, etc.). **Stjepan Picek** (University of Zagreb FER & Radboud University) brings hardware/system security expertise. **Zhiyuan He** (CUHK) co-authored recent agent-security benchmarks. The paper is a preprint under submission (dated 31 Aug 2026), evaluates against very recent frontier systems (Claude Opus 4.6/4.8, Gemini 3.5 Flash) at the time of writing, and maintains a public project page (huggingface.co/spaces/TrustSafeAI/SIR) with appendices covering the full principle inventory, refine prompts, strategy catalog, and implementation details — a good reproducibility posture, though victim models are proprietary APIs.

## Critical Assessment

**Novelty is solid but incremental.** The individual ingredients are not new: compositional principle-based red-teaming is the authors' own CoP (2506.00781); adaptive/mutation-based IPI attacks exist in EVA, MUZZLE, and AgentVigil; lifelong strategy integration exists in AutoRedTeamer. SIR's genuine differentiators are (a) targeting OS-level CUAs with joint (benign + adversarial) success, (b) the deterministic execution oracle replacing the LLM judge, and (c) the cross-task shared principle library. These are well-chosen, and Table 1's comparison is fair about what EVA/MUZZLE already had — but the paper never empirically compares against any of these adaptive baselines, only against the hand-crafted template. Since EVA and MUZZLE target web agents, a direct port is nontrivial, yet even AgentVigil (Tool/Web setting) is not adapted; the claim "SIR is the first OS-level adaptive IPI with joint success" is doing a lot of work unaccompanied by an adaptive-baseline comparison.

**Statistical power is thin, and the paper says so.** 50 cases total, with three of seven categories having n≤4 (service disruption n=4, artifact planting n=2, resource exhaustion n=4); a single trajectory shifts such a category's rate by 25-50 points. No confidence intervals, no seed variance, no significance tests anywhere — with 50 Bernoulli trials, the difference between 24% and 28% is well within noise. The per-model headline deltas (+20 to +38 pts) are large enough to survive this, but the finer claims (e.g., Gemini's 14% P2+P4+D1 preference, P10 vs P9 transfer ordering) rest on very small counts.

**Missing ablations and unreported details.** Only one attacker/analyzer LLM (Grok-4.3) is used — no ablation of attacker-model sensitivity, even though EVA showed attacker-model choice materially changes outcomes. The round budget is R=10 with early stopping, but the paper never reports how many rounds were actually consumed per victim or the round-by-round ASR curve, so the reader cannot tell how much of the feedback gain came in the first round versus later. The stochastic compose stage is characterized only by selection frequencies, not by per-composition success rates conditioned on the model.

**Environment quirks both help and limit generality.** The feedback loop's flagship environment-grounded exploit relies on a specific quirk — the VM's Node.js 12 lacks fs/promises, producing a predictable "Cannot find module" error that ErrorCorroboration leverages. This is a genuinely clever demonstration that the loop mines the environment, but it also means a discovered strategy is tied to this build; the appendix catalog (e.g., debug_log_redirect, plausible_npm_cache_corruption) is operationally specific to the Postmill/Chrome/Node stack, and the paper does not quantify how many of the retained strategies are stack-specific versus generic.

**Dual-use posture is stated but the appendix is operational.** The authors restrict to a sandboxed VM and frame principle release as defensive, yet Appendix E's catalog reads as a practical bypass cookbook (recasting rm as mv, filename-as-fake-module to dodge sensitivity heuristics). This is a defensible trade for defensive research, but it is a real consideration.

**Cost limits replication.** Roughly $150-$250 per feedback round for the Claude victims (Table 6) means a full multi-round, multi-seed, multi-benchmark study is beyond most labs — the paper acknowledges this constrains external replication.

## Strengths

- **The deterministic oracle is the right evaluation choice.** Replacing an LLM judge with programmatic filesystem/service/permission checks removes a known manipulability channel and makes "joint success" (adversarial objective + benign task) crisp and reproducible.
- **Clean component attribution.** The three-way ablation (hand-crafted / base-principles-only / full feedback) cleanly separates the value of compositional search (+6 to +18 pts) from the value of failure-driven discovery (+14 to +20 pts), and shows feedback matters most exactly where static defenses are strongest (Gemini +20).
- **The transfer experiment answers the right question.** Freezing strategies discovered on Opus 4.6 and evaluating them unchanged on two unseen models demonstrates the loop distills reusable attack principles, not memorized payloads — and the asymmetric P9/P10 transfer is explained mechanistically (environment-grounded corroboration vs. model-specific heuristic thresholds).
- **Honest self-flagging.** The paper explicitly marks low-n categories as uninterpretable, reports its own costs, and names reproducibility and dual-use as limitations in Appendix F — unusual candor.
- **Actionable defensive insight.** The per-category and per-principle-composition analyses (e.g., which defense each strategy targets: source trust, target sensitivity, imperative-language detection) give defenders a concrete map of which failure modes an adaptive adversary actually exploits.

## Limitations

- **Small, single-benchmark evaluation**: 50 cases from one benchmark (RedTeamCIA), with three categories too small to interpret; no cross-benchmark validation, no variance estimates or significance testing.
- **No adaptive baselines**: comparison is only against the hand-crafted RedTeamCIA template; EVA, MUZZLE, and AgentVigil are discussed but never run, so the margin over other adaptive methods is unknown.
- **Single attacker/analyzer model** (Grok-4.3) with no attacker-model ablation; selection is stochastic but selection-frequency analysis is not tied to per-composition success.
- **Snapshot science**: victim CUAs are proprietary API models that change over time; results (e.g., Opus 4.6's 54%) may not reproduce even weeks later, as the authors concede.
- **Expensive pipeline** (~$150-$250 per feedback round for Claude victims; ~$0.02/case generation) — limits rounds, seeds, and external replication; the actual rounds consumed per victim are not reported.
- **Environment-specific strategies**: at least one flagship discovered strategy exploits a Node.js 12 quirk of the specific VM; generality of the strategy catalog beyond this stack is unquantified.
- **Dual-use risk**: the released strategy catalog is operationally specific enough to serve as a bypass cookbook against deployed systems.

## Relevance

这篇论文与你的最高优先级方向"自进化智能体与自动化研究"高度契合：SIR 本质上就是一个从自身失败中学习、把经验蒸馏为可复用策略库、并在任务与模型间迁移的自改进代理循环，其外层的 diagnose→distill→reapply 闭环是 failure-driven self-improvement 在对抗场景的一个干净实例。同时它对前沿 CUA 的安全性测量（含 Anthropic/Google 最新模型的防御剖面分析）也触及你关注的长时自主智能体系统的可靠性与信任问题，值得作为自适应攻击如何揭示静态评测盲区的案例存档。

## Questions for Further Exploration

- How does SIR behave against open-weight CUAs (e.g., UI-TARS, OpenCUA) where defense internals can be inspected — do the same principles win, and does the deterministic-oracle methodology transfer to less standardized OS environments?
- Would an adaptive defense that rotates its refusal heuristics (or fine-tunes on refused injections) re-close the gap SIR opens, i.e., is the 54%/24%/28% ASR a property of static defenses only?
- Can the failure-driven distillation loop be generalized from attack strategies to benign failure diagnosis — e.g., mining failed agent trajectories to improve agent reliability rather than to bypass it?
- What fraction of the discovered strategy catalog is stack-specific (Node.js 12 / Postmill / Chrome) versus architecture-generic, and can a strategy be automatically tagged with its transfer conditions?
- How does attack success interact with the benign-task completion requirement — do the successful injections degrade the user's task quality, and is joint success actually harder for the victim to prevent than pure hijacking?
- With only 50 cases and no variance reporting, are the finer findings (Gemini's P4 preference, P9>P10 transfer asymmetry) stable under resampling — a bootstrap or multi-seed replication would settle this cheaply relative to full re-runs.
