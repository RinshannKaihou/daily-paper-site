> **一句话总结：** 弗吉尼亚理工+亚马逊的 BCO 把"编码代理做优化器"时对环境的隐式信念显式写成一个持久的 Markdown 世界模型文档（world_model_calibration.md，含可证伪声明、置信度、confirmed/refuted 状态、证据路径与解释失败数的 mass 字段），并用"预测→观察→校正"循环在每轮评估后逐条修订信念；在五个基准（LongMemEval-s、LoCoMo、GAIA、AppWorld、Terminal-Bench 2.0）的严格匹配对照（两个方法仅差一行 include 引入的 169 行校准模块）下，held-out passrate 全面超过 vanilla（GAIA +0.152、LoCoMo +0.078、LME +0.075、AppWorld +0.030、TB2.0 +0.022），且离线对照实验（Intact vs Scrambled vs None 文档）证明增益来自文档内容而非格式。

> **TL;DR:** BCO makes the optimizer's implicit belief about how a scaffold-editing environment responds explicit: a persistent, per-belief structured Markdown world model (falsifiable claim, confidence, hypothesis/confirmed/refuted status, evidence paths, "mass" = failures explained) maintained by a predict–observe–correct loop — the proposer must record a task-level prediction before each evaluation, then grade that prediction against raw traces and Add/Revise/Merge/Remove beliefs. Against a matched vanilla control that differs by exactly one include line (a 169-line calibration module), BCO wins held-out passrate on all five benchmarks: GAIA 0.495 vs 0.343 (+0.152), LoCoMo 0.453 vs 0.375, LongMemEval-s 0.608 vs 0.533, AppWorld 0.796 vs 0.766, Terminal-Bench 2.0 0.492 vs 0.470. After swapping the frozen target to unseen gpt-5.6-luna, the BCO scaffold ranks first on all GAIA effort tiers, but loses the full-set AppWorld comparison (0.516 vs 0.685 at high effort) because its unbounded scratchpad reinjection overruns context on 99/372 tasks. An offline ablation with 40 candidates shows a fresh predictor given the intact document forecasts better than one given no document (downside precision 0.217 vs 0.142) or a same-form falsified copy (0.181), so the reusable information is in the content, not the format.

## 核心贡献

- **BCO 方法**：将迭代式代理优化（coding-agent 提案器反复编辑冻结模型周围的 scaffold）中本来隐式的"环境如何响应编辑"的信念，物化为一个持久 in-context 文档（`world_model_calibration.md`），并以 predict–observe–correct 循环持续校准。理论包装为 Bayes-Adaptive MDP：运行内环境响应固定不变，因此应当携带的是"信念"而非重新学习。
- **信念原子结构**：每条信念 β = (可证伪声明 φ, 适用条件 C, 置信度 c∈[0,1], 状态∈{hypothesis, confirmed, refuted}, 正/反证据 E±（存档轨迹的文件路径）, mass µ≈它解释的失败数)；区分 execution beliefs（编辑如何影响行为）与 evaluation beliefs（评估器何时不可靠）。文档初始为空、禁止预填猜测的失败模式；refuted 信念保留在 append-only History 中防止重复尝试；预测可点名任务 ID 但候选代码不得按任务 ID 分支。
- **严格匹配对照**：vanilla 与 bco 的提案器 SKILL.md 仅差一行 `<!-- INCLUDE: _calib_addon.md -->`（169 行校准模块）；两者共享同样的初始 scaffold、可编辑源码面、证据表面（diff、评估输出、轨迹、任务–得分矩阵）、目标模型、数据划分与迭代预算。
- **三层实证**：(1) 五个基准（横跨记忆 QA、工具使用 QA、code-as-action 应用代理、终端代理四族任务）上 bco 的 train 与 held-out passrate 全部更高；(2) 目标模型换成未见过的 gpt-5.6-luna 后，GAIA 三个推理档位 bco 全部第一；(3) 离线预测消融（None < Scrambled < Intact 严格排序）证明世界模型文档携带可复用的内容信息。
- **诚实的代价核算**：bco 在记忆/GAIA 上提案器总 token 反而下降（−27.4%/−24.7%/−12.4%），在 AppWorld/TB2.0 上为 +5.2%/+26.2%；原始轨迹读取量全线下滑 20–69% —— 反驳"bco 只是多了 prompt"的假说。

## Key Contributions

- **Belief-Calibrated Optimization (BCO)**: a minimal extension of the standard propose-and-evaluate agentic optimization loop that maintains the optimizer's belief about the environment's response as a persistent, structured, in-context Markdown world model, revised each iteration via an explicit predict–observe–correct protocol (prediction is graded against raw tool outputs and traces, never the agent's own final message).
- **A matched-control evaluation design**: the experimental isolation is unusually clean — vanilla and bco share everything (initial scaffold, evidence surface, proposer, target model, harness, budget) except a single include line adding a 169-line calibration module, so the measured effect is the calibration layer itself, not extra prompting or different tooling.
- **Gains across four task families on five benchmarks** (LongMemEval-s, LoCoMo, GAIA, AppWorld, Terminal-Bench 2.0): BCO ends higher on train and stays higher on every held-out split, with the largest gaps on GAIA (+0.152 held-out) and the smallest on TB2.0 (+0.022).
- **Evidence for the mechanism, not just the outcome**: (a) a target-model swap showing partial transferability (first on all GAIA tiers; on AppWorld's common completed-task set first by +0.007/+0.031/+0.091, but last on the full set due to context overruns); (b) an offline prediction ablation (None < Scrambled < Intact) isolating document *content* from document *form*; (c) a Notes ablation showing free-form persistent memory alone does not reproduce the gain (0.427 vs 0.467 on LME train).
- **A token-accounting analysis** that tests the "it's just additional prompting" hypothesis and finds bco *reduces* total proposer tokens on the three benchmarks whose evidence induces heavy history re-reading, while raw-trace reads drop 20–69% everywhere.

## Methodology

**Setting.** An LLM agent's performance is determined by the frozen target model plus the scaffold around it. A coding-agent proposer iteratively picks a parent from previously evaluated artifacts, applies a mechanism-level edit, and the environment evaluates the candidate on a fixed scored task set Q. Selection at the end maximizes the train estimate of population utility — the "optimizer's curse" setting (Smith & Winkler 2006), where hill-climbing on a finite Q overfits favorable evaluation noise; an explicit environment model is proposed as the antidote that helps the proposer distinguish real effects from favorable noise.

**The world model.** BCO's state W_t is a collection of atomic beliefs rendered as a Markdown file (`world_model_calibration.md`) with two sections: *Beliefs* (one entry per atom: falsifiable claim φ, conditions C, confidence c∈[0,1], status ∈ {hypothesis, confirmed, refuted}, supporting/contradictory evidence E+/E− given as paths into stored trajectories, and mass µ ≈ how many observed failures the belief explains, used to prioritize experimental budget) and *Experiments* (an append-only record of which edits probed which belief and with what verdict, so a dead edit is not retried; a refuted belief is retained, not deleted). Two belief kinds are distinguished: *execution beliefs* (how an edit affects agent behavior under conditions) and *evaluation beliefs* (when the grader/evaluation system itself is unreliable). The document starts empty; pre-seeding guessed failure modes is forbidden because that would place confidence on claims no observation supports.

**The loop (Algorithm 1).** Per iteration: (1) the proposer selects a parent from history and proposes an edit a_t ~ π_opt(·|h_t, W_t); (2) *before* evaluation it writes `prediction.md` naming the belief at stake, the edit's mechanism, and an aggregate claim about a task subset (predictions may name task IDs, but candidate code may not branch on them — keeping candidates general); (3) after evaluation, the prediction is graded against per-task results relative to the parent and raw execution traces (never the scaffolded agent's final message), and beliefs are updated one at a time via Add/Revise/Merge/Remove (ΔW_t); beliefs the outcome does not address are left unchanged.

**Matched control.** Each proposer is a SKILL.md assembled by textual inclusion from an environment-surface fragment and a base contract (read evidence, design one mechanism-level edit, write the candidate). BCO adds exactly one line including a 169-line calibration module; vanilla omits it. Both methods see the identical evidence surface: every prior iteration's diff, evaluation output, traces, full source snapshot, and the cross-iteration task–score matrix. Proposers: Kimi-K2.6 (memory benchmarks), Kimi-K2.7 (GAIA, AppWorld), Codex/GPT-5.6 at max reasoning effort (TB2.0); targets frozen within each pair: DeepSeek-V4-Flash (three benchmarks), MiniMax-M3 (TB2.0).

**Evaluation protocol.** Five benchmarks across four task families: LongMemEval-s (train 100 / test 400; memory-ontology scaffold), LoCoMo (80 / 1449), GAIA (40 / 99; function-calling loop), AppWorld (45 / 372, scenario-disjoint; ReAct code agent), Terminal-Bench 2.0 (20 / 66; Terminus-2 terminal agent). Standard per-benchmark graders, temperature 0, one repeat per task (k=2 on TB2.0). Reported number is held-out passrate of each method's top-1 train-frontier candidate; on the two memory benchmarks the best of each method's three highest-train candidates is reported (disclosed best-of-three, selection partly on held-out). AppWorld/TB2.0 train subsets passed a pre-optimization stability screen removing oscillating tasks. RQ2 swaps only the target to gpt-5.6-luna at three reasoning-effort tiers. RQ3 freezes 40 candidates and varies only the document given to a fresh predictor (None / Scrambled — same length, format, vocabulary but falsified mechanism verdicts / Intact — final document minus the candidate's outcome block), judged by two blind LLM judges against mechanically computed per-type deltas, with upside hit rate and downside precision as judge-free cross-checks.

## Results & Highlights

- **Held-out passrate (Table 1), bco vs vanilla, all five benchmarks favor bco**: GAIA 0.495 vs 0.343 (+0.152, the largest gap; train 0.575 vs 0.425, +0.150); LoCoMo 0.453 vs 0.375 (+0.078); LongMemEval-s 0.608 vs 0.533 (+0.075); AppWorld 0.796 vs 0.766 (+0.030); Terminal-Bench 2.0 0.492 vs 0.470 (+0.022). Train gaps range from +0.025 (TB2.0) to +0.150 (GAIA); the initial scaffolds start far below both (e.g., GAIA held-out initial 0.283, LME 0.148).
- **Target-model swap to gpt-5.6-luna (Table 6)**: on GAIA bco is first at all three effort tiers (high: 0.657 vs vanilla 0.475 and initial 0.586 — vanilla scores 0.111 *below* the initial scaffold at high effort, with traces showing long searches overwriting earlier correct answers). On AppWorld full-set, counting non-completions as failures, bco scores 0.516/0.524/0.532 (high/medium/low) vs vanilla 0.685/0.608/0.538 — bco is *last* at high and medium effort because its unbounded scratchpad reinjection overruns context on 99/77/65 of 372 tasks; restricted to tasks all three scaffolds complete, bco is first by +0.007/+0.031/+0.091.
- **Offline prediction ablation, 40 candidates (Table 2)**: ordering None < Scrambled < Intact on every measure — upside hit rate 0.441 (None) / 0.460 (Scrambled) / 0.538 (Intact); downside precision 0.142 / 0.181 / 0.217 (the largest mechanical gap). Both blind judges agree: Intact beats None 36–4 (Kimi-K2.6) and 35–2 (DeepSeek-V4-Flash), and beats Scrambled 26–12 under both. All 12 run-level comparisons (4 runs × 3 pairings × 2 judges) point the same way, but with 4 runs the two-sided sign test cannot go below p = 0.125.
- **Notes ablation (Table 3)**: on LongMemEval-s train, three independent 10-iteration trajectories give means 0.430 (vanilla), 0.427 (free-form persistent notes), 0.467 (bco) — persistence without calibration does not reproduce bco's mean, but the paper itself flags that within-method ranges (0.11/0.07/0.13) exceed all between-method gaps, so three trajectories cannot establish Notes is ineffective.
- **Proposer token cost (Table 7)**: total proposer tokens relative to vanilla: LME −27.4%, LoCoMo −24.7%, GAIA −12.4%, AppWorld +5.2%, TB2.0 +26.2%; raw-trace reads fall 20–69% on every benchmark (TB2.0 decomposition: bco emits +45% more output tokens — the surplus is belief writing, not evidence re-reading). The savings appear within the first 10 iterations, not via late amortization.
- **Worked example (GAIA iter 15→16)**: the world model's prediction that a quality-gated evidence-summary turn would lift the long-context subset by ≥0.10 was confirmed — 5 additional tasks passed, 0 regressions, train passrate 0.450 → 0.575; the Appendix B listings show a refuted belief (E4, conf 0.26) kept on record and a VOID-verdict experiment refused credit for a score change its mechanism left no signature for.
- **Disclosed diagnostics**: on Spider2-lite, 45/104 held-out tasks (43.3%) received both a pass and a fail across four identical-scaffold repeats, so the benchmark was excluded; on TB2.0's original uncurated split, bco did *not* beat vanilla (held-out 0.463 vs 0.455, both below initial 0.470) — the positive TB2.0 result comes from the re-screened 20-task split.

## Authors & Credibility

The core team is from Virginia Tech (Yuhan Chen, Zhihua Tian, Mahavir Dabas, Ming Jin, Feiyang Kang, Ruoxi Jia — the latter an established professor in ML/LLM reliability research), with two authors from Amazon (Charith Peris, Rahul Gupta — Amazon's applied/AGI research org) and two independent researchers (Siyuan Zhang, Nan Wang). The blend of an academic RL/ML-reliability group with industry agent practitioners fits the paper's scope, and the corresponding author is a Virginia Tech PhD student (yuhan@vt.edu). The paper's credibility is substantially boosted by its unusually transparent reporting practice: it publishes every held-out-evaluated candidate with train and held-out scores (Table 4), discloses two ineligible candidates that would have flattered either method, reports a failed benchmark (Spider2-lite), reports the original failed TB2.0 split, and openly states when its own statistics are too weak to support a conclusion (Notes ablation, sign-test floor). The framing connects to the Bayes-Adaptive RL literature (Duff 2002; Ghavamzadeh et al. 2015) and the optimizer's-curve literature correctly and modestly. No prior releases or code are mentioned beyond one reproducibility script path (`scripts/analysis/e1_base_rate_drift.py`), and no venue is stated (arXiv preprint, Sep 2026).

## Critical Assessment

**Novelty.** The core idea — write the optimizer's environment belief down as a persistent structured document and calibrate it against predictions — is a natural but genuinely underexplored point in the crowded scaffold-optimization space (ADAS, AFlow, Darwin Gödel Machine, Meta-Harness, HarnessX are cited as concurrent/adjacent lines). The related-work positioning is honest: prior self-reflection/memory methods (Reflexion, Voyager, Generative Agents) retain episodic or free-form memory; BCO's distinction is organizing persistent state around explicit falsifiable predictions and their verdicts. The Notes ablation is the right control for "is it just any persistent memory?" — though, as the authors concede, it is underpowered (means 0.427 vs 0.467 with within-method ranges of 0.07–0.13).

**Rigor.** The matched-control design (one include line of difference) and the Intact-vs-Scrambled content ablation are genuinely rigorous touches that most papers in this space lack. But three weaknesses temper the headline claims. (1) *One trajectory per method per benchmark*: the aggregate claim "higher on all five benchmarks" is consistency across environments, not statistical significance within any one of them — and the paper's own Notes data shows run-to-run dispersion (up to 0.13 on a 100-example train split) comparable to the AppWorld (+0.030) and TB2.0 (+0.022 held-out) gaps, so those two rows are within plausible noise. (2) *The TB2.0 result exists only on a re-screened split*: on the original split bco (0.463) actually scored below the initial scaffold (0.470), and the train subset was re-selected after inspecting initial-scaffold behavior — the authors disclose this as split-selection bias, but it means one of the five supporting benchmarks was effectively chosen post hoc for having "usable optimization headroom." (3) *The RQ3 ablation's statistics floor out at p = 0.125* with four runs, and one of the two blind judges (Kimi-K2.6) is from the same model family as the proposer, raising a mild correlated-bias concern.

**Reproducibility.** The protocol is specified to an unusual degree of verbatim detail (full SKILL.md fragment line counts, the calibration module's grading rules, the judge prompt verbatim, every memory candidate's scores), and one analysis script path is given. However, no code or artifact release is announced, the scaffolds depend on five proprietary/semi-proprietary model endpoints (Kimi-K2.6/K2.7, DeepSeek-V4-Flash, MiniMax-M3, GPT-5.6/Codex, gpt-5.6-luna) whose exact versions will drift, and 30-iteration optimization runs over 400–1449-task held-out sets are expensive to replicate independently.

**Red flags / overclaiming check.** The abstract's "leads on the tasks we test, except where context-window overruns leave it unfinished" carefully pre-qualifies the AppWorld full-set loss — accurate but easy to miss: under target swap, the bco scaffold is *worst* on AppWorld at high and medium effort (0.516 vs 0.685), a real practical regression caused by a design flaw (no scratchpad length bound) that vanilla's 16-exchange sliding window avoids. The memory rows are best-of-three with selection partly on held-out (disclosed, and Appendix C shows the selection moves each method by less than the between-method gap — e.g., LME eligible spread 0.5925–0.6075 for bco vs 0.4825–0.5325 for vanilla — but it is still test-informed). Missing ablations: no comparison against any external optimizer baseline (AFlow, ADAS, OPRO are discussed but never run), no sensitivity to calibration-module wording, and no test of whether a world model from one run transfers to a new trajectory (explicitly disclaimed). Finally, single-repeat temperature-0 evaluation (k=1 for four benchmarks) sits at the edge of the evaluation noise floor the authors themselves quantify on Spider2-lite.

## Strengths

- The cleanest ablation design seen in this literature: the two methods differ by exactly one include line, so the measured effect is attributable to the calibration protocol rather than to extra context, different tools, or proposer capability.
- The Intact/Scrambled/None offline ablation is a genuinely clever instrument — holding document length, format, and vocabulary fixed while falsifying content isolates *what* is written from merely *that* something is written; the 0.217 vs 0.142 downside-precision gap is the most mechanistic evidence in the paper.
- Exceptional reporting hygiene: full candidate-level tables, disclosure of an excluded benchmark, a failed original split, ineligible candidates, an underpowered null-adjacent ablation, and explicit statements of when its statistics cannot support a claim.
- The token analysis tests and partially refutes the "it's just more prompting" alternative hypothesis, and the write-vs-read decomposition (TB2.0: +45% output tokens, fewer reads) explains *when* BCO is cheaper.
- Breadth with structure: five benchmarks across four genuinely different task families (memory retrieval, tool-use QA, code-as-action agents, terminal agents) with per-benchmark standard graders rather than a single custom harness.
- Practical insight for practitioners: the AppWorld context-overrun failure is itself a transferable lesson — scaffolds optimized for one target's verbosity can silently fail on a more verbose one, motivating resource-envelope-aware candidate scoring.

## Limitations

- One optimization trajectory per method per benchmark; the paper measures consistency across five environments, not within-benchmark variance, and its own auxiliary data (Notes ranges 0.07–0.13) shows dispersion of the same magnitude as the smaller Table 1 gaps (TB2.0 +0.022, AppWorld +0.030 held-out).
- The TB2.0 train split was re-screened after inspecting initial-scaffold behavior; on the original split BCO showed no gain over vanilla (0.463 vs 0.455, both below initial 0.470), so one of five benchmarks carries a disclosed post-hoc-selection risk.
- The two memory rows are best-of-three with selection partly on the held-out split (disclosed, symmetric across methods, but not selection-free).
- No external optimizer baselines: the comparison universe is BCO vs its own vanilla ablation vs free-form Notes; claims of superiority over the broader scaffold-optimization literature (AFlow, ADAS, DSPy, Meta-Harness) are never tested.
- The world model is a heuristic natural-language summary, not a statistically calibrated posterior; the protocol assumes the environment's response is fixed within a run and has no mechanism for detecting target drift or tool drift (acknowledged by the authors).
- The BCO scaffold can overfit the target's resource envelope — the AppWorld swap shows unbounded scratchpad reinjection causing 99/372 non-completions under a more verbose target, and the protocol does not score resource use alongside passrate.
- Belief fidelity is validated only offline on candidates from four optimization runs (sign-test p = 0.125 floor), and the ablation does not test whether a world model transfers to a new optimization trajectory.
- Screening AppWorld/TB2.0 train subsets for stability narrows the claim to environments with repeatable failure mass and may favor benchmarks where score-guided optimization is easier (authors' own caveat).

## Relevance

与你最高优先级的"Self-Evolving Agents & Automated Research"方向直接对口：这篇正是关于自进化 LLM 代理的优化循环本身——如何让 coding-agent 优化器在长程自改进中可靠地积累环境认知，而不是每轮从原始轨迹重新推断。其"显式世界模型 + 预测-校正"协议、对优化器诅咒与评估噪声的处理，以及"代理 scaffold 对目标模型资源画像过拟合"的迁移失败案例，对构建可信长程自治代理系统都有直接参考价值。

## Questions for Further Exploration

- Does the world model transfer across optimization trajectories — i.e., can a world model accumulated on one benchmark or seed warm-start a fresh run, or is it disposable once its run ends (the paper explicitly does not test this)?
- Would the held-out gains on the two smallest-gap benchmarks (TB2.0 +0.022, AppWorld +0.030) survive within-benchmark repetition (e.g., 3+ seeds per method), given the paper's own measured run-to-run dispersion of 0.07–0.13?
- Can the calibration protocol be combined with an explicit resource-envelope score so that selected scaffolds avoid the AppWorld-style context-overrun failure under target swaps — e.g., optimizing against multiple targets simultaneously?
- The Scrambled condition beat None on upside hit rate (0.460 vs 0.441): how much of BCO's gain comes from the *structure* (naming regressions, forcing falsifiable claims) versus the calibrated *content* — and could a cheaper structured-but-uncalibrated template capture most of the benefit?
- How does BCO behave when the environment response genuinely drifts (tool API changes, target model updates mid-run) — does the append-only history of refuted beliefs help discount stale evidence, or does it anchor the proposer to an outdated world model?
- Would the protocol's gains persist with a weaker or smaller proposer (the calibration module itself is 169 lines of instructions — is its benefit contingent on a frontier-level proposer following it faithfully)?
