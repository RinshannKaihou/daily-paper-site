> **一句话总结：** 把光谱→分子结构解析从"直接端到端生成 SMILES"重构为"检索光谱学技能 + 执行分析代码 + 公式约束推理"的 skill-code agentic 过程：用 Claude Opus 4.6 自演化出 8 个模态专属 Markdown 技能，构造 50 万条工具调用轨迹（GPT-5.4 反向工程补思考链），对 Qwen3-4B 先 SFT 再做逐步（step-level）可验证奖励 GRPO——最终以不足 SpectraLLM 1/10 的训练数据和 1/8 的骨干规模，在 QM9S、Multimodal Spectroscopic Dataset、MassSpecGym 上全面超越 SpectraLLM（MS/MS Tanimoto 0.6382 vs 0.4554）。

> **TL;DR:** S3C-LLM reformulates spectrum-to-structure elucidation as a skill-guided, code-grounded agentic pipeline instead of direct spectrum-to-SMILES string mapping. A self-evolving library of 8 modality-specific Markdown skills (built by a Claude Opus 4.6 + Claude Code predict-verify-diagnose-revise loop over 20 iterations) plus executable analysis code is distilled into 500K tool-use trajectories for Qwen3-4B SFT, followed by a step-level GRPO variant whose per-step verifiable rewards (skill-modality match, error-free code execution, Morgan-fingerprint Tanimoto) back-propagate credit to early skill-retrieval steps. On QM9S Raman it reaches Tanimoto 0.3550 vs SpectraLLM's 0.2500 (+0.105); on MS/MS of the Multimodal Spectroscopic Dataset 0.6382 vs SpectraLLM 0.4554 (+0.183, DiffMS 0.3535); on ¹H NMR 0.2281 vs 0.0720 — all while using 500K SFT trajectories (<1/10 of SpectraLLM's 5.5M paired spectra) on a 4B backbone instead of SpectraLLM's Qwen3-32B. Gains shrink on the noisy experimental MassSpecGym (0.1832 vs 0.1533), a caveat to the SOTA claim.

## 核心贡献

- **范式重构**：将光谱→结构解析从直接的 spectrum→SMILES 映射改为 skill-guided、code-grounded 的 agentic 推理：检索模态专属光谱技能 → 执行自包含 Python 代码提取峰证据/枚举分子式 → 融合证据与化学约束后输出 SMILES，学习目标从 ρ(y|x) 变为 ρ(τ,y|x)（轨迹条件化预测）。
- **自演化技能库**：以 Claude Opus 4.6 + Claude Code 为外部自演化 agent，对每种模态执行 20 轮迭代、每轮 50 个训练谱的"预测-验证-诊断-修订"闭环，产出 8 个 Markdown 技能（IR、Raman、UV-Vis、¹³C NMR、¹H NMR、HSQC、模拟 NMR、MS/MS），把光谱信号映射为官能团/片段/分子式/子结构假设；技能进化 20 轮后显式断言精确率达 0.67–0.87（HSQC 0.87、¹³C 0.79、¹H 0.67）。
- **Agentic 数据构造**：Claude Code 为每条谱生成可执行分析代码（质量差计算、分子式枚举、峰位区间匹配），封装为 `read_skill` / `run_code` 两个工具的 50 万条轨迹；用 GPT-5.4 对抽样轨迹反向工程生成思考链（约 10 万条显式思考通过"重预测须命中参考答案"过滤，其余 40 万条保留空 `<think>` 块并在 SFT 中屏蔽损失）。
- **两阶段训练 + step-level RL**：SFT（掩蔽空思考 token）后，在 2 万条 RL 轨迹上用 GRPO 变体做 step-level 优化：技能检索步按模态匹配、代码执行步按无工具错误、最终预测步按 Morgan 指纹 Tanimoto 给可验证奖励；同 prompt 同步的组内归一化 reward-to-go 让下游结构奖励回传到早期步骤，且无需 KL 惩罚。消融显示 step-RL（MS/MS 0.6382）一致优于 trajectory-RL（0.5832），而无 SFT 直接 RL 几乎不学习（0.1310）。
- **数据效率与全面超越**：500K SFT 数据 < SpectraLLM 语料（5.5M 配对谱）的 1/10，Qwen3-4B 骨干 < SpectraLLM 的 Qwen3-32B，却在光学、NMR、MS/MS 全部基准上取得最优。

## Key Contributions

- **Reframe of the task**: spectrum-to-structure elucidation is re-cast as a skill-guided, code-grounded agentic reasoning process — retrieve a modality-specific spectroscopy skill, execute self-contained Python to extract peak evidence (mass differences, formula enumeration, diagnostic-region matching), then integrate evidence and chemical constraints before emitting SMILES; the model learns ρ(τ, y | x) rather than ρ(y | x).
- **Self-evolving skill library**: an external Claude Opus 4.6 + Claude Code agent runs 20 evolution iterations (50 training spectra each) in a predict-verify-diagnose-revision loop per modality, yielding 8 Markdown skills (IR, Raman, UV-Vis, ¹³C NMR, ¹H NMR, HSQC, simulated NMR, MS/MS) that map spectral signals to functional-group/fragment/formula/substructure hypotheses. Skill precision on explicit skill-supported claims climbs to 0.87 (HSQC), 0.79 (¹³C NMR), 0.67 (¹H NMR) by round 20.
- **Agentic trajectory synthesis**: Claude Code generates per-spectrum executable analysis code wrapped into 500K tool-use trajectories over two tools (`read_skill`, `run_code`); GPT-5.4 reverse-engineers thinking traces for sampled trajectories (~100K explicit-thinking trajectories kept after a re-prediction filter, remaining 400K keep empty `<think>` blocks whose loss is masked in SFT).
- **Two-stage training with step-level RL**: SFT followed by a GRPO variant on 20K RL trajectories where each assistant action step gets a verifiable stage reward (skill-modality match; code executes without tool error; final SMILES scored by Morgan-fingerprint Tanimoto); reward-to-go is group-normalized at the same step index so downstream structure rewards propagate to earlier skill-retrieval/code steps, with no explicit KL penalty.
- **Data-efficient SOTA**: 500K SFT trajectories (<1/10 of SpectraLLM's 5.5M paired-spectrum corpus) on a Qwen3-4B backbone outperform SpectraLLM (Qwen3-32B) across optical, NMR, and MS/MS benchmarks.

## Methodology

**Problem setup.** Inputs are compact peak-level textual representations of spectra (following SpectraLLM's data setting, built from the Multimodal Spectroscopic Dataset, QM9S, and MassSpecGym); the output is the molecular SMILES. Evaluation molecules/spectra are held out from all teacher-assisted construction steps (skill evolution, code generation, thinking-trace generation and filtering, SFT/RL construction).

**Stage 1 — Skill library construction.** For each modality an initial skill draft is written; the external agent (Claude Opus 4.6 + Claude Code) iterates 20 rounds × 50 samples per iteration: it applies the current skill to predict SMILES, checks whether implied functional groups/fragments/formula cues match the reference structure, diagnoses missing or misleading spectral rules, and revises the skill. A conservative writing criterion admits only deterministic or high-confidence spectral rules into the library (ambiguous peak-to-structure associations are left out). The result is 8 modality-specific Markdown skills.

**Stage 2 — Agentic data construction.** Claude Code generates executable analysis code per spectrum (e.g., for MS/MS: mass-difference computation, formula candidate enumeration under chemical-consistency constraints; for NMR: peak-list parsing, diagnostic-region matching). Two tools define the interface: `read_skill` (returns the Markdown skill for one of the 8 modalities) and `run_code` (executes self-contained Python and returns structured evidence). Single-modality inputs get one `read_skill` + one `run_code` step; multi-modality inputs issue parallel `read_skill` calls and aggregate cross-modal evidence in a single code step. This yields 500K instruction-mode trajectories. For sampled trajectories, GPT-5.4 is given the history plus the reference next action and asked to produce a thinking trace whose final re-prediction must match the reference SMILES (otherwise the trajectory is filtered out) — ~100K explicit-thinking trajectories; the remaining 400K keep empty `<think>` blocks for a unified schema.

**Stage 3 — Training.** Backbone: Qwen3-4B. (1) SFT on the 500K trajectories with all tool interactions in `<tool_call>` blocks; the loss on empty-thinking tokens is masked (m_j = 0), so the model learns tool usage without imitating empty reasoning. (2) Step-level RL: GRPO over 20K RL trajectories, 8 rollouts per prompt at temperature 1.0 (4 preliminary rollouts first discard prompts whose rollouts produce identical outcomes), γ = 0.35, learning rate 1e-6, no explicit KL penalty. Each rollout is decomposed into assistant action steps (skill retrieval, code execution, final SMILES prediction). Stage rewards: skill-retrieval step rewarded iff the selected skill matches the spectrum modality; code-execution step rewarded iff the Python executes without a tool error; final prediction scored by Morgan-fingerprint Tanimoto similarity (malformed tool calls, missing required skills, failed execution, invalid SMILES → zero reward). Reward-to-go G_i,t is normalized within the same prompt group at the same step index t (so only comparable actions — those playing the same role in the trajectory — are contrasted), and the resulting advantage is applied to the assistant-token span of each step in a clipped policy objective.

**Inference.** The trained model follows the learned format: `read_skill` for the input modality, `run_code` to execute generated analysis code, then a final analysis producing SMILES.

**Benchmarks and metrics.** QM9S single-spectrum tasks (Raman, UV-Vis, IR); Multimodal Spectroscopic Dataset (¹³C NMR, ¹H NMR, HSQC, MS/MS, plus a combined-NMR setting); MassSpecGym (experimental MS/MS). Metrics via RDKit: Tanimoto, cosine, MACCS Tanimoto, and Fraggle similarity — structure-level similarity rather than exact-match accuracy, since a single spectrum may not uniquely determine a molecule. Baselines: general LLMs (DeepSeek-V4-Pro, GPT-5.5, Gemini-3.1-Pro, Claude-Opus-4.7) and spectrum-specific models (IR-to-Structure, Spectra2Structure, Spec2Mol, DiffMS, SpectraLLM).

## Results & Highlights

- **QM9S single-spectrum (optical)**: S3C-LLM is best on all three modalities and all four metrics. Raman Tanimoto 0.3550 vs SpectraLLM 0.2500 (+0.1050) and Fraggle 0.5879 vs 0.4330; UV-Vis Tanimoto 0.1381 vs 0.0790 (+0.0751); IR Tanimoto 0.2534 vs SpectraLLM 0.1921 (+0.0613) and vs IR-to-Structure 0.0766. General-purpose LLMs are near-useless here (best Tanimoto 0.1004 for GPT-5.5 on Raman; Claude-Opus-4.7 0.0901).
- **MS/MS**: On the Multimodal Spectroscopic Dataset, S3C-LLM reaches Tanimoto 0.6382 vs SpectraLLM 0.4554 (+0.1828), DiffMS 0.3535, Spec2Mol 0.0988; MACCS 0.7757 vs 0.4929. On the noisier experimental MassSpecGym the margin shrinks sharply: Tanimoto 0.1832 vs SpectraLLM 0.1533 and DiffMS 0.1597 (only +0.030 over the best baseline) — the authors attribute this to measurement noise and peak shifts that break exact mass matching.
- **NMR**: ¹³C NMR Tanimoto 0.2508 vs SpectraLLM 0.1016 (+0.1492); ¹H NMR 0.2281 vs 0.0720 (+0.1561); HSQC 0.4016 vs 0.2058 (+0.1958); combined ¹³C+¹H+HSQC 0.5021 vs 0.4151 (+0.0870) and vs NMR2Struct 0.0962 — showing the approach generalizes beyond vibrational/mass spectra to chemical-shift and cross-peak evidence.
- **Data efficiency**: 500K SFT trajectories, less than 1/10 of SpectraLLM's reported 5.5M paired spectra, with a 4B vs 32B backbone — the central efficiency claim.
- **Training-stage ablation (Tanimoto)**: Only SFT 0.2069/0.1914/0.3580/0.5542 (¹³C/¹H/HSQC/MS-MS); SFT + Trajectory-RL 0.2231/0.1847/0.3632/0.5832 (mixed vs SFT-only on NMR); SFT + Step-RL 0.2508/0.2281/0.4016/0.6382 (best everywhere); Only Step-RL without SFT collapses to 0.0740/0.0310/0.0850/0.1310 — the model never learns the tool-use format, so step RL alone is nearly useless.
- **Toolset ablation (Tanimoto)**: Chat (no tools) 0.13/0.14/0.28/0.37 → +read_skill 0.1507/0.1718/0.3148/0.5128 → full agentic (+run_code) 0.2508/0.2281/0.4016/0.6382 — explicit spectral priors help everywhere, and executable computation matters most for HSQC and MS/MS where cross-peak relations and mass constraints benefit from code.
- **Skill quality**: precision over explicitly skill-supported claims improves steadily over 20 evolution rounds, with HSQC converging earliest (0.87 final vs 0.79 ¹³C, 0.67 ¹H), because cross-peaks provide more explicit structural evidence.

## Authors & Credibility

The authors are from the Key Laboratory of Cognition and Decision Intelligence for Complex Systems, Institute of Automation, Chinese Academy of Sciences (CASIA), and the School of Artificial Intelligence, UCAS; Bo Xu (corresponding author) leads a long-established CASIA lab. First author Xuanle Zhao has a credible track record in chemistry-focused multimodal LLMs — ChemVL (ACL 2026 Findings) and Tiny-chemvl (AAAI 2026) — so the domain expertise is genuine. The work is technically consistent and the appendix is unusually transparent (full skill files and rollout trajectories are printed). Caveats on credibility: the entire data engine depends on proprietary frontier models (Claude Opus 4.6 + Claude Code for skill evolution and code generation, GPT-5.4 for thinking-trace synthesis), so reproducibility outside an expensive API pipeline is unclear, and no code/skill-library/data release is mentioned in the paper.

## Critical Assessment

- **Novelty is solid but the "self-evolution" framing oversells.** The genuine contribution is the reframe (skill + code + formula constraints instead of end-to-end string mapping) and the step-level RL credit-assignment design. But the skill library is evolved by distilling Claude Opus 4.6's chemistry knowledge through a verification loop, and the thinking traces are GPT-5.4 reverse-engineered — this is frontier-model distillation into a 4B agent, closer to careful data engineering than to open-ended self-improvement; the 8 skills are neither discovered nor extended autonomously beyond what the designers defined.
- **The skill-quality metric is favorable by construction.** It measures precision over explicit skill-supported claims only: claims not written into the skill are "not counted as errors," and the authors themselves admit recall over all functional groups "remains substantially more underdetermined." A skill library could thus be conservative and still score 0.87 precision while missing much of what is needed — the metric cannot detect that.
- **The SOTA claim weakens exactly where it matters most.** The +0.183 MS/MS gain is on the Multimodal dataset whose spectra the authors concede are simulated with "cleaner mass constraints"; on experimental MassSpecGym the delta over SpectraLLM collapses to +0.030 (0.1832 vs 0.1533) and over DiffMS to +0.024. The headline gains come predominantly from clean/simulated spectra, and no error bars or significance tests are reported anywhere.
- **The trajectory-vs-step RL comparison is not a clean sweep.** SFT+Trajectory-RL actually hurts ¹H NMR relative to SFT-only (0.1847 vs 0.1914), and the trajectory-level baseline is described only briefly — no sensitivity analysis of the γ = 0.35 discount or the no-KL choice, both of which are load-bearing design decisions.
- **Evaluation sidesteps exact-match accuracy.** All headline numbers are similarity metrics (Tanimoto/MACCS/Fraggle); given the paper's own argument that a spectrum may not uniquely determine a molecule, reporting even a candidate-hits-top-k exact-match rate would have made the comparison with MassSpecGym-style evaluation more meaningful.
- **Inference cost is unexamined.** Every prediction requires a skill retrieval plus Python execution; latency, token cost, and failure rates of run_code at inference time are never measured, despite the Limitations section acknowledging tool-call scheduling as future work.

## Strengths

- Consistent, large empirical gains across three modality families (optical, NMR, MS/MS) against both general and spectrum-specific baselines, on the same splits as SpectraLLM.
- Striking data efficiency: <1/10 of the paired-spectrum corpus and 1/8 of the backbone size relative to SpectraLLM, plausibly because explicit skills plus code offload what end-to-end models must memorize.
- The intermediate evidence chain (retrieved skill + code output) makes predictions auditable — a real advantage over black-box spectrum-to-SMILES mapping for scientific use.
- The step-level RL design is well-motivated and cleanly implemented: per-step verifiable rewards with same-step group normalization solve the credit-assignment problem that plain GRPO has on heterogeneous tool trajectories; the ablation (Only-Step-RL collapse at 0.1310 vs SFT+Step-RL 0.6382) cleanly shows SFT bootstrapping is necessary.
- The three-pronged ablation (skill quality, training stages, toolset) plus full skill files and rollout trajectories in the appendix make the pipeline unusually inspectable.

## Limitations

- All inputs are compact peak-level textual representations; raw, noisy instrument spectra are out of scope (explicitly deferred to future work), which caps applicability to real analytical labs — consistent with the MassSpecGym gap collapse.
- The skill library covers only 8 common modalities; specialized spectroscopies require re-running the whole Claude-driven evolution loop.
- Training MS/MS evidence leans on simulated spectra with clean mass constraints; robustness to measurement noise and peak shifts is not solved.
- Skill quality is measured by a precision-only proxy that ignores recall of unsupported functional groups.
- Reproducibility depends on Claude Opus 4.6/Claude Code and GPT-5.4 API pipelines; no release of skills, trajectories, or code is mentioned.
- Inference-time tool-call latency and execution-failure handling are unaddressed for large-scale deployment.

## Questions for Further Exploration

- How does the pipeline degrade on fully experimental, noisy spectra — could the skill-evolution loop itself be run against noisy calibration data (e.g., MassSpecGym training split) to evolve noise-robust skills?
- Can skills transfer or compose across modalities (e.g., shared substructure-constraint skills), and can the library grow open-endedly beyond the 8 hand-defined modality slots?
- How does the step-level reward scheme (same-step group normalization, no KL penalty, γ = 0.35) compare against outcome-only GRPO as intermediate rewards get sparser or noisier in other tool-augmented scientific domains?
- Would an equal-data, equal-size control (SpectraLLM-style direct mapping SFT of Qwen3-4B on the same 500K paired examples) fully isolate the contribution of the skill-code formulation from that of data curation?
- What are the inference-time cost and failure profile (code-execution errors, retrieval mistakes) in production, and can skill staleness be detected and repaired continuously after deployment?
