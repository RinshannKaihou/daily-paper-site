> **一句话总结：** EDGE 从 agent 失败轨迹的语料级错误事件中构建"错误类别依赖图"（Suppes 筛查 + CAPRI 剪枝得到观测图，再用 LLM 修复式反事实 rollout 验证出因果子图），并把它作为两阶段 LLM-as-judge 检测器的引导上下文——在 TRAIL-GAIA 上将 Gemini-2.5-Pro 的加权 F1 从 33.51 提到 42.13（+8.62）、定位准确率从 35.68 提到 50.13，在 TRAIL-SWE-Bench 上将 GPT-oss-20B 的 F1 从 9.31 提到 29.89（+20.58）；验证过的因果子图（TRAIL 12 条边、MAST 11 条边）则作为解释与修复优先级分析的可靠依据。

> **TL;DR:** Agent failure traces usually contain cascades of related errors, but prior attribution methods treat each error in isolation. EDGE builds a corpus-level dependency graph over error categories — an observational correlation graph via Suppes screening plus CAPRI pruning, and a causally validated subset via LLM-repair counterfactual rollouts (patch the upstream error, hold tool outputs fixed, re-roll) — then feeds a thresholded inference graph to a two-stage LLM-as-judge detector. On TRAIL (span-level, GAIA + SWE-Bench) it lifts weighted-F1 by up to +14.17 for the Qwen Family on TRAIL-GAIA (12.40 → 26.57) and +20.58 for GPT-oss-20B on TRAIL-SWE-Bench (9.31 → 29.89) over the no-graph judge baseline, with Gemini-2.5-Pro reaching 42.13 F1 / 50.13 Loc on TRAIL-GAIA. The static-graph +CG ablation (underperforms EDGE on 14 of 15 backbone cells) and a held-out 80/20 rebuild (TRAIL Mistral F1 24.74 → 33.14) show the two-stage trace-conditioned consumption and the learned structure — not just extra context — drive the gains. MAST accuracy, however, drops on 7 of 8 backbones, and span localization on long-context SWE-Bench remains weak.

## 核心贡献

- **问题重构：** 首次将 agent 失败归因明确建模为"多错误依赖传播"问题——错误不是孤立标签，而是形成级联（e₁ → e₂ → e₃），与 TRAIL、AgentDebug 等只找单一根因/责任步骤的方法形成差异化定位。
- **三张图的可分离设计：** 观测相关图 G_S（Suppes 时间优先 + 概率提升，边权 w_S = √(Prec·Δ_PR)）、因果候选图 G_C（CAPRI 式 AIC 爬山剪枝，借用癌症进展建模的 TRONCO 工具链）、干预验证图 G_V（反事实 rollout 估计布尔风险差 Δ(A→B)）；推理图 G_τ = G_V ∪ 高分观测边，兼顾覆盖率和因果可解释性。
- **两阶段图引导检测器：** Stage-1 用全图上下文预测初始错误集，Stage-2 只验证"从已检出源类别经图可达、聚合边权超阈值 τ_C1"的下游假设——把被动上下文变成显式的假设精炼机制；消融证明静态拼图（+CG）在 15 个骨干单元中 14 个不如两阶段设计。
- **干预验证的因果子图作为解释工件：** 反事实 rollout 中固定所有工具输出，使下游变化可归因于被修补的 span（受控直接效应），得到如 TRAIL "Formatting Errors → Context Handling Failures"、MAST "Action-Reasoning Mismatch → Premature Termination" 等可复核的传播链，直接用于修复优先级排序。
- **跨 taxonomy、跨 prompt 策略的验证：** 框架对错误分类法不敏感（TRAIL 19 类 span 级 / MAST 13 类轨迹级均可构建），并适配 Who&When 式 ALL-AT-ONCE / STEP-BY-STEP 两种提示范式，图引导在 5 个开源骨干上均带来提升。

## Key Contributions

- Reframes multi-error attribution in LLM agent traces as **dependency-aware diagnosis**: errors form cascades (upstream triggers → downstream effects), and a corpus-level category dependency graph can guide detection — a gap left open by single-root-cause methods (Who&When, AgentDebug, CDC-MAS).
- Introduces a **three-graph pipeline**: an observational correlation graph G_S (Suppes temporal priority + probability raising, edge weight w_S = √(Prec·Δ_PR)), a CAPRI-pruned causal-candidate DAG G_C (AIC hill-climbing, adapted from cancer-progression modeling via TRONCO), and an intervention-validated graph G_V whose edges are kept only when a controlled counterfactual rollout shows a positive boolean risk-difference Δ(A→B).
- Designs a **two-stage LLM-as-judge detector**: Stage 1 predicts an initial error set with full-graph context; Stage 2 verifies only downstream hypotheses reachable via the trace-specific edge subset R^(T) (undetected targets, aggregated weight > τ_C1). A static-graph +CG ablation isolates the mechanism: prepending the same graph in one call underperforms EDGE on 14 of 15 backbone cells.
- Separates **prediction from explanation**: the thresholded inference graph G_τ (coverage) drives detection, while the intervention-validated G_V (interpretability) supports repair prioritization — e.g., TRAIL edge "Formatting Errors → Context Handling Failures" and MAST edge "Action-Reasoning Mismatch → Premature Termination" name recurring upstream causes.
- Demonstrates **taxonomy- and prompt-strategy transfer**: the pipeline reruns unchanged on TRAIL (19 categories, span-level) and MAST (13 categories, trace-level), and graph guidance improves Who&When-style ALL-AT-ONCE and STEP-BY-STEP attribution across five open-weight backbones.

## Methodology

**Problem setup.** A failed trace T = (s₁,…,s_N) is annotated with error events E(T) = {(e_j, l_j)} where e_j ∈ C is an error category and l_j the span where it first emerges. The goal is, per trace, to predict the full set of category-location pairs Ê(T). EDGE builds **one graph per taxonomy** from all annotated traces (no trace-specific labels, spans, or answers inside the graph; fixed at inference), making it taxonomy-level dependency-guided attribution.

**Observational graph construction.** (1) *Suppes screening*: for each ordered pair A → B, temporal priority is estimated directly from within-trace span order (PreC(A,B) = fraction of joint traces where A precedes B), and probability raising as Δ_PR(A,B) = P(X_B=1|X_A=1) − P(X_B=1|X_A=0). Edges passing both thresholds with sufficient joint support form G_S with weight w_S(A,B) = √(PreC · Δ_PR). (2) *CAPRI pruning*: hill-climbing over DAGs ⊆ G_S minimizing an AIC-style score (−2·log-likelihood + 2·dim(G)) yields the sparser causal-candidate graph G_C. Yields: TRAIL 27 Suppes edges → 13 CAPRI edges (148 traces, 19 categories); MAST 43 → 23 (393 AG2 traces, 13 categories, 1347 ordered pairs).

**Intervention-based validation.** For each candidate edge A → B, on traces where both occur with t_A < t_B, an LLM-based repair module applies a per-category patch (from a curated patch library with slot schemas, repair instructions, forbidden actions, and declarative postchecks — full TRAIL/MAST libraries in Appendix A) to the span s_A, choosing the minimal patch side (input or output). Counterfactual rollout re-executes with **all tool outputs held fixed**, so only the patched span and its downstream reasoning change; a resolver judge labels whether A is removed (resolved_A = 1 required), and Judge B labels whether B persists. The controlled direct effect is Δ(A→B) = E[X_B(T) − X_B(T;A)] over resolved traces; edges with Δ > τ_val form G_V (12 edges for TRAIL, 11 for MAST).

**Graph-guided detection.** The inference graph G_τ unions G_V with score-filtered observational edges (w_S ≥ τ; τ = 0.35 TRAIL, 0.50 MAST, selected by model-averaged weighted F1 over a small grid). Edge weights are max(Δ, 0) for validated edges and w_S otherwise, so a single threshold τ_C1 governs Stage-2 exposure. Stage 1 predicts E^(1)(T) with full-graph guidance; R^(T) = {A→B ∈ G_τ : A ∈ D(T), B ∉ D(T), Σ w_AB > τ_C1} retrieves downstream hypotheses; Stage 2 verifies only those, conditioned on the trace, and merges categories not already covered in Stage 1. A span-identifier index grounds predicted locations for span-level localization.

**Evaluation.** TRAIL (span-level multi-error attribution on GAIA + SWE-Bench subsets; weighted-F1, location accuracy, joint location-category accuracy) and MAST (trace-level multi-label classification over 13 categories on 393 AG2 traces; weighted-F1, macro precision/recall/accuracy). Eleven backbones including Mistral-Small-3.1-24B, GPT-oss-20B/120B, Gemma-3-27B-IT, Qwen Family (QwenLong-L1-32B / QwQ-32B), Gemini-2.5-Pro/Flash, GPT-4o, plus GPT-5 and Qwen3.6-35B-A3B in the appendix. Ablations: graph-richness (random-12 edge-count-matched control, causal-only G_V, corr-union G_τ), static +CG, held-out 80/20 graph rebuild, and Who&When-style prompting adaptation.

## Results & Highlights

- **TRAIL-GAIA (span-level, weighted-F1 / Loc / Joint, %):** Gemini-2.5-Pro reaches 42.13 / 50.13 / 15.26 vs baseline 33.51 / 35.68 / 13.74 (F1 +8.62, Loc +14.45) — the strongest overall. Open-weight gains are larger in relative terms: Qwen Family F1 12.40 → 26.57 (+14.17), GPT-oss-120B F1 25.76 → 37.20 (+11.44), GPT-oss-20B F1 23.28 → 33.28 (+10.00), Mistral-Small-3.1-24B F1 24.06 → 34.15 (+10.09). Joint accuracy stays very low for open-weight models (e.g., Gemma-3-27B 0.73 → 4.13), so full span+category attribution is far from solved.
- **TRAIL-SWE-Bench:** F1 improves across the board — GPT-oss-20B 9.31 → 29.89 (+20.58, the largest single-cell gain), Gemini-2.5-Pro 26.66 → 38.97 (+12.31), GPT-oss-120B 22.68 → 30.07 (+7.39), Mistral 9.80 → 14.40 (+6.60). But exact localization regresses on 7 of 8 backbones (Δ −0.33 to −3.74), confirming long-context span localization remains difficult even as category detection improves.
- **MAST (trace-level):** F1 rises by +0.42 to +15.61 on open-weight backbones (e.g., GPT-4o 22.87 → 29.96, +7.09; Gemini-2.5-Pro 34.99 → 41.57, +6.58), but accuracy is traded for recall: accuracy drops on 7 of 8 backbones (−0.33 to −3.74) while recall rises on the same 7 of 8 (+3.09 to +17.52). The authors note the imbalance — 13 binary decisions per trace with only 30.5% positives — and that an "always-no" classifier scores 69.5% accuracy, above every cell in the table.
- **Structure, not context, drives gains:** the random-12 edge-count-matched control underperforms the inference graph on 4 of 5 open-weight backbones, and the static +CG variant is inconsistent against the no-graph baseline (e.g., +6.8 F1 on Mistral TRAIL-GAIA but −10.8 on GPT-oss-20B TRAIL-GAIA) and loses to EDGE on 14 of 15 backbone cells.
- **Held-out validation:** with a stratified 80/20 split and the graph rebuilt from the training side only, EDGE still improves weighted-F1 in all four reported cells — TRAIL Mistral 24.74 → 33.14 (+8.40), TRAIL GPT-oss-120B 31.08 → 33.48 (+2.40), MAST Mistral 34.53 → 36.44 (+1.91), MAST GPT-oss-120B 32.49 → 34.50 (+2.01) — so gains are not from fitting the evaluation corpus.
- **Where the gains concentrate:** routing 638 gold TRAIL-GAIA error instances into attribution outcome buckets shows the largest +EDGE-only jump in Planning & Coordination — GPT-oss-120B 9.0% → 46.6%, Mistral 7.3% → 31.2%, Gemini-2.5-Pro 26.5% → 50.8% — matching the graph topology where Planning errors are downstream targets recovered by Stage 2; System Execution errors barely move.
- **Who&When-style transfer:** graph guidance consistently benefits both TRAIL splits across five open-weight backbones under ALL-AT-ONCE and STEP-BY-STEP regimes (STEP-BY-STEP+GRAPH yields uniform gains on SWE-Bench), and a graph-guided variant achieves the best MAST F1 across all model blocks shown in Appendix A.7.

## Critical Assessment

**Novelty.** The core idea — treating agent failure attribution as category-level error propagation and validating edges by counterfactual repair — is genuinely new in this subfield, and the transplant of CAPRI/Suppes machinery from cancer genomics to agent traces is a clever, well-motivated adaptation. That said, the individual components are all borrowed (Suppes-Bayes screening, CAPRI pruning, LLM-as-judge detection); the contribution is the pipeline composition and the two-stage consumption design, not new algorithms.

**Rigor.** The ablation suite is a strength: an edge-count-matched random control, a static +CG control, a causal-only variant, and an 80/20 held-out rebuild jointly support "structure matters" rather than "more context matters." However, several weak points remain. (1) The primary baseline is always the *same detector without the graph* — there is no head-to-head against competing attribution frameworks (e.g., AgentDebug's root-cause feedback or CDC-MAS's causal inference) under a shared metric, so "improves attribution" only means "improves our own detector." (2) The "causality" rests on an LLM repair module plus two LLM judges (resolver and verifier); a botched repair or lenient judge directly biases Δ, and no human audit of rollout labels is reported. (3) The thresholds τ and τ_C1 were selected by model-averaged weighted F1 *on the evaluation benchmarks* — a mild tuning-on-test concern that Table 3 only partially mitigates. (4) TRAIL skips bootstrap/shuffle edge controls due to small N (148 traces), so its graph is the less statistically vetted of the two.

**Honesty of reporting.** Refreshingly honest in places: the accuracy drops on MAST (7 of 8 backbones), the localization regressions on SWE-Bench, and the below-trivial 69.5% always-no accuracy are all printed rather than buried, and the abstract's "most evaluated models and settings" hedges appropriately (Gemini-2.5-Flash loses −6.81 F1 on TRAIL-GAIA). But the headline framing emphasizes category-level F1 while the practically harder joint location+category accuracy stays under 16 even for Gemini-2.5-Pro — a reader skimming the abstract could overestimate practical maturity.

**Red flags.** MAST event annotations are automatically produced, not human-validated, and co-occurrence position correctness is never measured — the very substrate from which the MAST graph is learned could be noisy in unknown ways. Intervention validation holds tool outputs fixed, so Δ measures propagation "along the agent's reasoning path," which is a weaker causal claim than the paper's vocabulary ("causal graph") sometimes implies. All numbers are single-run point estimates.

## Strengths

- The two-stage trace-conditioned graph consumption is well-motivated and convincingly isolated by the +CG ablation — the paper identifies its own operational lever rather than just adding context.
- Counterfactual rollout with fixed tool outputs is a clean identification strategy for reasoning-path propagation, and the patch library (with forbidden actions and postchecks) is a concrete, reusable engineering artifact.
- Held-out 80/20 graph rebuild and random-edge controls address the two most obvious confounds (memorization and edge count) head-on.
- Taxonomy-agnostic pipeline validated on two genuinely different benchmarks (span-level TRAIL vs trace-level MAST) plus a prompting-strategy transfer study — breadth beyond a single setup.
- The intervention-validated graph doubles as an explanatory artifact with actionable edges (upstream causes with many validated outgoing effects reduce more downstream symptoms when repaired directly).
- Released code, patch libraries, and honest limitations/risk sections.

## Limitations

- Attribution is taxonomy-level: the graph contains aggregate category dependencies, not trace-specific labels, spans, or answers, and stays fixed during detection — it cannot capture trace-unique failure chains, and graph guidance is applied uniformly with no gating on model confidence or task complexity.
- Localization gains are small or negative on long-context SWE-Bench (7 of 8 backbones lose up to −3.74 Loc), and joint location+category accuracy remains very low for open-weight models (0.73–4.89 on TRAIL-GAIA).
- MAST accuracy drops on 7 of 8 backbones (recall-precision trade), and every MAST accuracy cell sits below the trivial 69.5% always-no classifier — trace-level multi-label attribution is far from practically solved.
- The causal validation chain is LLM-mediated end-to-end (repair module, resolver judge, verifier judge) with no human audit; tool outputs are frozen, so mediation through downstream tool re-execution is out of scope.
- Low per-category support in scarce multi-error corpora (TRAIL: 148 traces) limits edge validation power; TRAIL skips bootstrap/shuffle controls for exactly this reason.
- Single-run point estimates; the authors explicitly do not guarantee exact reproduction due to LLM nondeterminism.

## Relevance

与你最关心的"长程自主 agent 系统的可靠性与可信性"直接相关：EDGE 提供了一个诊断型基础设施视角——把 agent 失败当作可建模的错误传播结构而非孤立故障，其干预验证子图可直接用于自修复循环（repair loop）的修复优先级排序，是自演化/自我修复 agent 架构中"失败归因 → 定点修复"环节的潜在组件。不过它属于模型侧的语义级故障诊断（非你核心的硬件/SDC 故障检测方向），价值在于方法论借鉴（反事实 rollout 验证依赖边）而非直接落地。

## Questions for Further Exploration

- How sensitive is Δ(A→B) to the quality of the LLM repair module — would a stronger repair model flip edge directions, and could an adversarially bad repair fabricate spurious "causal" edges?
- The graph is taxonomy-level and static: can a hybrid be built where trace-specific evidence dynamically reweights or prunes edges at inference time, especially for long-context SWE-Bench traces where localization currently regresses?
- Would fixing tool outputs differently (re-executing downstream tool calls with the patched inputs) yield a different propagation graph that better matches real repair outcomes after deployment?
- MAST accuracy sits below the always-no classifier for every configuration — is trace-level multi-label attribution the right formulation, or should the task be reformulated (e.g., ranked top-k error categories per trace)?
- The validated graph suggests repair prioritization, but the paper never closes the loop: does repairing high-Δ upstream errors actually improve end-task success rates when agents are re-run, compared to repairing errors sampled at random?
