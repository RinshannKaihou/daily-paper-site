> **一句话总结：** CAST 用"规则抽取 → 工具抽取 → 幻觉/领域违规/错误工具三路检查 → 总裁决"的多智能体验证流水线，把 τ-bench 轨迹的稀疏成败信号转成逐步动作级结构化标注（500 任务 × 5 条轨迹 = 2,500 条经验），先训出校准的 8B 批判模型 CAST-Critic，再用它在环收集的成功轨迹 SFT 出 CAST-Policy；在 τ-bench Retail 上 4B/8B 策略 pass^4 达 16.5%/14.8%（基座仅 6.1%/5.2%，RFT 对照 12.2%，GPT-OSS-120B 仅 5.9%），且 CAST-Critic-8B 把 Qwen3-32B 的四环境平均 pass^4 从 11.5% 提到 19.5%，而 GPT-4.1/Qwen3-235B/Qwen2.5-72B 当批判器反而把 pass^4 拖到 6.0%/3.4%/6.3%。

> **TL;DR:** CAST converts sparse trajectory-level rewards into action-level supervision: a multi-agent annotation pipeline labels every tool call as hallucination / domain violation / wrong tool (with a structured rationale, under partial observability), a fine-tuned 8B critic (CAST-Critic) learns these labels, and a policy (CAST-Policy) is SFT'd on successful critic-in-the-loop trajectories. On τ-bench Retail, CAST-Policy-4B/8B reach 16.5%/14.8% pass^4 vs 6.1%/5.2% for base Qwen3-4B/8B, 12.2% for the RFT control (+4.3/+2.6 pts), and 5.9% for GPT-OSS-120B (+10.6 pts). Paired with a Qwen3-32B actor, CAST-Critic-8B lifts 4-domain average pass^4 from 11.5% (ReAct, no critic) to 19.5%, whereas prompted GPT-4.1, Qwen3-235B and Qwen2.5-72B critics collapse it to 6.0%, 3.4% and 6.3%.

## 核心贡献

- **稀疏奖励 → 动作级监督的确定性转化**：提出三分类失败体系（幻觉 hallucination / 违反领域规则 domain violation / 错误工具 wrong tool），验证判定为 y_t = 1[¬hall ∧ ¬domain ∧ ¬tool]；标注时只允许使用当前步之前的上下文（不偷看未来观测），特权信息 Ω 仅在标注期可用，学生 critic 与部署策略永远看不到。
- **多智能体标注流水线**：规则抽取 agent（检索相关领域规则）+ 工具抽取 agent（候选工具短路列表）+ 三个专项检查器（幻觉/领域违规/错误工具）+ 总裁决 agent，产出结构化理由 ε_t 与二元标签 y_t；用 Qwen3.5-27B 做验证、Qwen3.5-122B-A10B 做理由重建（作者称后者标注质量更高）。
- **校准的批判模型**：CAST-Critic 联合优化理由生成损失与验证分类损失（L = λ_exp·L_exp + λ_ver·L_ver），把"有效动作被误报"率从 GPT-4.1 的 46.8% 降到 11.4–13.6%，critic 反馈后的修正成功率从 43–46% 提到 82–88%。
- **批判在环的数据生成与策略优化**：第二轮让 teacher 动作在交互中被学到的 critic 逐步验证、被拒动作按批判反馈修订，只保留 reward=1 的批判增强轨迹做 SFT 训练 CAST-Policy；支持两种推理模式（独立部署 / critic 引导修订环）。
- **关键实证发现**：4B/8B 微调策略在 Retail pass^4 上超过 GPT-OSS-120B 十个百分点以上；更重要的是一个可复用的负结果——GPT-4.1、Qwen3-235B、Qwen2.5-72B 等前沿模型做提示批判器会把 actor 的 pass^4 从 11.5% 拖到 3.4–6.3%，而 4B/8B 微调批判器反而提升到 15.9%/19.5%。
- **系统评测**：横跨 4 个动态工具调用环境（τ-bench Retail/Airline + τ-trait Telecom/Telehealth），含 RFT 对照、验证预算消融、误报/修正行为分析、完整 prompt 附录，并诚实给出一个验证失败案例（Appendix F.4）。

## Key Contributions

- A deterministic recipe for converting sparse trajectory outcomes into action-level verification supervision: a three-way failure taxonomy (hallucination / domain violation / wrong tool) with structured per-action rationales generated under partial observability — the annotator sees only step-local context, never future observations; privileged information Ω exists only at annotation time.
- An agentic annotation pipeline (rule-extractor agent, tool-extractor agent, three specialized checker agents, final-verdict orchestrator) that produces 2,500 critique-enriched experiences from the 500-task τ-Bench Retail training split (5 teacher rollouts per task).
- A calibrated critic (CAST-Critic) trained with a combined rationale-generation + verification-classification objective, which cuts false-positive flagging of valid actions from 46.8% (GPT-4.1) to 11.4–13.6% and raises post-feedback correction success from 43–46% to 82–88%.
- Critique-in-the-loop data generation: a second rollout round where teacher actions are verified/revised by the learned critic, with reward-1 trajectories used to SFT CAST-Policy; two inference modes (standalone policy, or policy + critic revision loop).
- An empirically strong negative result: prompted frontier critics (GPT-4.1, Qwen3-235B, Qwen2.5-72B) degrade a Qwen3-32B actor's average pass^4 from 11.5% to 3.4–6.3%, while fine-tuned 4B/8B critics improve it to 15.9%/19.5%.

## Methodology

**Problem setting.** A multi-turn tool-calling agent interacts with a simulated user under domain policies. A trajectory τ = {(o_t, a_t)} carries only a terminal outcome Y(τ) ∈ {0,1}. Because a single wrong action (e.g., refunding the wrong purchase) can be irreversible and failures emerge across repeated trials rather than in every run, CAST learns an action verifier g: (h_t, o_t, a_t, K) → (ε_t, y_t), where ε_t is a structured rationale and y_t a binary validity label. Verification is conditioned only on the step-local context (no access to future observations o_{t+1..T}), matching deployment-time verifiability.

**Stage 1 — Experience collection.** Teacher policy Qwen3-32B (ReAct mode) runs on the official τ-Bench Retail training split (500 tasks), 5 rollouts per task at temperature 0.7, with Qwen2.5-72B-Instruct as the user simulator, yielding a buffer of successful and failed trajectories.

**Stage 2 — Agentic verification (annotation).** For every action, a rule-extractor agent retrieves the relevant domain rules, a tool-extractor agent shortlists candidate tools, three adjudicator agents independently check hallucination (unsupported/fabricated arguments), domain violation (policy conflicts), and wrong tool use, and an orchestrator aggregates them into (ε_t, y_t). Qwen3.5-27B serves as the verification agent and Qwen3.5-122B-A10B performs reconstruction/rationale writing (reported to give higher-quality annotations). The annotated trajectories are reconstructed into multi-turn training examples with the tool list and domain policy in the system prompt. Result: 2,500 structured step-level feedback experiences.

**Stage 3 — Critique and policy learning.** CAST-Critic C_θ is fine-tuned with L_critique = λ_exp·L_exp + λ_ver·L_ver (rationale generation plus verification classification). A second round of data collection then runs the same 500 tasks for 5 trials with the teacher policy, but now every teacher action is verified by the learned critic during interaction; rejected actions are revised using the critique feedback. Only trajectories with reward 1 are retained (B_C^+) and used to SFT the policy: L_policy = −ΣΣ log π_φ(u_t | h̃_t, o_t, K), where the critique-augmented history h̃ includes the accepted actions and rationales. At inference CAST-Policy can run standalone or with CAST-Critic in a propose→verify→revise loop.

**Training setup.** Qwen3-4B and Qwen3-8B backbones for both critic and policy; H100 node, max sequence length 32,768, lr 5e-6, 3 epochs, total batch 16, AdamW with cosine schedule.

**Evaluation.** τ-bench Retail (in-domain, 114 tasks / 14 tools) and Airline (OOD, 50 tasks), plus τ-trait Telecom (18 tasks) and Telehealth (20 tasks), 30–50 turns each. Metric: pass^k = probability that all k independently sampled executions of a task succeed (pass^1 = single-run success; pass^4 = repeated-trial reliability). Baselines: prompting/FC variants, rejection fine-tuning (RFT), test-time agentic frameworks (IRMA, FAMA, EvoTool, PALADIN), and frontier models as critics (GPT-4.1, GPT-OSS-120B, Qwen3-235B, Qwen2.5-72B).

## Results & Highlights

- **In-domain reliability (τ-Bench Retail, Tables 1/11):** CAST-Policy-4B reaches 26.1% pass^1 / 16.5% pass^4 vs 7.2%/6.1% for base Qwen3-4B (+18.9 / +10.4 pts) and 27.6%/12.2% for RFT-4B (+4.3 pass^4). CAST-Policy-8B reaches 30.0%/14.8% vs RFT-8B 27.6%/12.2% (+2.4/+2.6) and base Qwen3-8B 14.1%/5.2% (+15.9/+9.6). The pass^4 gains exceed the pass^1 gains, i.e., critique SFT mainly buys repeated-trial reliability.
- **Frontier anchor (Tables 5/6, abstract claims verified):** on Retail, CAST-Policy-4B's 16.5% pass^4 beats GPT-OSS-120B's 5.9% by +10.6 pts; on Telehealth, 30.0% vs 21.0% (+9.0). Important caveat from the same tables: Qwen3-235B posts 27.8% Retail pass^4 and 27.0% four-domain average pass^4 — above every CAST model (Figure 1's best CAST point is 19.5% average).
- **Critic quality (Table 3, Qwen3-32B actor, 4-domain averages):** no-critic ReAct = 31.7% pass^1 / 11.5% pass^4; with GPT-4.1 as critic 22.8%/6.0%; with Qwen3-235B 24.1%/3.4%; with Qwen2.5-72B 17.9%/6.3%; with CAST-Critic-4B 31.8%/15.9%; with CAST-Critic-8B 30.4%/19.5% — +8.0 pass^4 over no critic and +13.2 over the best prompted frontier critic. Figure 4 confusion matrices: false flags on valid actions 46.8% (GPT-4.1) vs 13.6%/11.4% (CAST-Critic-4B/8B); valid actions correctly left unflagged 24.0% vs 62.2%/64.7%.
- **Error-type analysis (Figure 9):** hallucination detection 83%/82% (CAST-4B/8B) vs 73% (GPT-4.1); domain violation 78%/79% vs 74%; wrong tool call 62%/57% vs 59% — the one category where GPT-4.1 is comparable or slightly better. After critic feedback the actor corrects the fault in 82–88% of cases across all three error types vs 43–46% with GPT-4.1 feedback.
- **Agentic frameworks:** vs PALADIN, CAST-Critic-8B improves pass^1/pass^3/pass^4 by 20.9/15.3/14.9 pts; vs EvoTool by 2.6/4.5/4.3 (Figure 5). Vs IRMA on Airline: +3.0 pass^1 / +4.5 pass^4. Average OOD gains across Airline/Telecom/Telehealth: +3.7% pass^1 and +5.1% pass^4 (see Critical Assessment for FAMA counter-cases).
- **Behavior (Figures 7/8):** the optimal verification budget is actor-dependent and reliability is non-monotonic in refinement rounds (Qwen3-32B actor peaks at 3 rounds with 19.9% pass^4; CAST-Policy-4B peaks at 4 rounds with 14.1%). CAST critics flag only 33.2% of actions as unsuitable per pass, and CAST-Policy agents resist critique feedback roughly 2x less than non-fine-tuned agents (11% vs 21–23% on Retail).
- **Case study (Appendix F):** on Retail task 52, Qwen3-8B fails all 4 trials (0/4) while CAST-Policy-8B succeeds 4/4 by explicitly verifying the irreversible exchange step before executing it.

## Critical Assessment

- **The headline comparison is against a soft anchor.** GPT-OSS-120B is unusually weak on τ-Retail pass^4 (5.9%) — below even Qwen3-32B with plain function calling (13.1%) — so "+10% pass^4 over GPT-OSS-120B" is true but weak evidence of frontier-level reliability: Qwen3-235B (27.8% Retail pass^4, 27.0% average) towers over every CAST model (best average 19.5%). "Smaller models outperform substantially larger models" holds only versus GPT-OSS-120B, and Figure 1 itself shows the 235B point on top.
- **Critic-guided inference is not a uniform win, and the text soft-pedals this.** On Retail pass^4, Policy-4B+Critic-4B scores 9.6% vs 16.5% for Policy-4B alone — adding the critic at inference roughly halves in-domain reliability for the 4B. On τ-trait Telehealth, the actor-only 4B reaches 30.0% pass^4 vs 20.0% with the critic, and RFT-8B (37.5% pass^1 / 30.0% pass^4) beats Policy-8B+Critic-8B (32.5%/25.0%) across the board. The claim of "consistent gains in the remaining out-of-domain settings" is contradicted by the authors' own Table 12 on Telehealth.
- **"Comparable performance to resource-intensive agentic frameworks" leans on efficiency, not accuracy.** Per appendix Tables 7–8, FAMA posts higher pass^4 than the CAST critic-guided variants on Retail (15.3% vs 10.0%/13.0%), Airline (18.0% vs 12.0%/13.0%) and Telecom (28.9% vs 16.7%/27.8%), and IRMA wins Telehealth (35.0% vs 25.0%). CAST's clear main-text wins are against PALADIN and EvoTool; against FAMA/IRMA the advantage is token/latency cost (Figure 6), which the abstract-level framing blurs.
- **The RFT control is confounded by data provenance.** RFT trains on round-1 successful trajectories, while CAST-Policy trains on a second round of 5×500 rollouts collected with the learned critic in the loop and filtered to reward=1. The +4.3 pass^4 delta therefore mixes critique supervision with a fresher/larger dataset and critic-filtered interaction dynamics; no ablation separates these factors.
- **The annotation pipeline is never ablated.** The multi-agent decomposition (rule extractor / tool extractor / three checkers / orchestrator) is not compared against a single prompted verifier using the same teacher (Qwen3.5-122B-A10B), and the λ_exp/λ_ver weighting is unexamined. The taxonomy is plausible, but its necessity is asserted rather than shown.
- **Statistical fragility.** τ-trait Telecom and Telehealth have only 18 and 20 tasks (Table 2), so headline OOD gaps like Telecom pass^4 27.8% vs 11.1% rest on tiny task counts; there are no error bars, seeds, or significance tests, and several decision-relevant comparisons (Figures 5, 8, 9) exist only as figure bars with no underlying table, making exact cross-checking hard.
- **Distillation ceiling and cost opacity.** Labels and rationales come from stronger teachers (Qwen3.5-27B / 122B-A10B) with privileged annotation-time information; critic quality is bounded by teacher quality, and the token cost of annotating 2,500 experiences plus a full second rollout round is never reported.
- **Credit where due:** the paper includes a genuine failure case (Appendix F.4: the critic approves a wrong-tool call with swapped pending/delivered item IDs, the action deploys and the task fails) and states its limitations candidly — rare honesty at this level of specificity.

## Strengths

- Converts sparse trajectory rewards into dense, mechanically checkable action-level supervision with a concrete failure taxonomy — a recipe that transfers beyond τ-bench-style domains.
- The calibration analysis is the paper's best contribution: a quantified, mechanistic explanation (46.8% → 11.4% false-flag rate on valid actions) for why prompted LLM judges hurt agentic reliability while a fine-tuned 8B critic helps (+8.0 average pass^4).
- A genuinely useful negative result: GPT-4.1, Qwen3-235B, and Qwen2.5-72B as prompted critics all degrade the actor's pass^4 (11.5% → 3.4–6.3%) — directly actionable for anyone bolting an LLM judge onto an agent loop.
- RFT is the right control, and on the in-domain benchmark it isolates a real +4.3 pass^4 value of critique-rationale supervision at 4B scale.
- Practical serving story: two inference modes, lower token overhead and latency than IRMA/FAMA/PALADIN/EvoTool (Figure 6), and the standalone CAST-Policy needs no critic at run time.
- Unusual documentation quality: full annotation/agent system prompts, fine-tuning hyperparameters, benchmark licenses, and a failure case are all in the appendix.

## Limitations

- Supervised fine-tuning only; the critic is not yet used as a feedback model for on-policy RL (the authors' own stated future work), so the policy never learns to incorporate critique from its own exploration.
- Verification is myopic: step-local validity only, with no forward-looking rationale about how an action affects later task outcomes (acknowledged by the authors).
- The critic-guided mode can hurt (Retail 9.6% vs 16.5% pass^4 at 4B; Telehealth 20.0% vs 30.0%), so deployments must tune the verification budget per actor — and the optimal round count differs (3 for Qwen3-32B, 4 for CAST-Policy-4B).
- Annotation depends on stronger teacher models and privileged annotation-time information; generalization to domains whose policies are not enumerable text is untested.
- OOD evidence rests on 18–20-task τ-trait domains with no uncertainty quantification; several key comparisons appear only as figures; no code or data release is mentioned.
- All four environments are English customer-service simulations with a simulated user (Qwen2.5-72B); user-simulator bias in the reliability numbers is unexamined.

## Relevance

与你最高优先级的"自进化智能体与自动化研究"方向中"长程自主智能体系统的可靠性与可信性"直接相关：CAST 给出了把稀疏轨迹奖励转成可校验的动作级监督、再用学到的批判器在环生成训练数据的完整配方，其"前沿提示批判器会拖垮可靠性、8B 微调批判器反而更校准"的发现对构建可信赖的自动化科研 agent 很有借鉴价值。对"LLM 训练稳定性与可观测性"方向也有间接启发：用 pass^k 度量跨试验可靠性并做逐步失败归因，正是长时训练/长程任务可观测性思路在 agent 场景的映射。

## Questions for Further Exploration

1. Would using CAST-Critic as a reward/feedback model in on-policy RL (GRPO-style) close the remaining gap to Qwen3-235B, instead of SFT on teacher-derived trajectories?
2. Can the critic be extended to forward-looking verification (predicting downstream consequences of an action) — the authors' stated future work — and would that fix the Telehealth and in-domain Retail regressions of critic-guided inference?
3. Is the multi-agent annotation decomposition (rule/tool extractors + three checkers + orchestrator) actually necessary, or would a single Qwen3.5-122B verifier prompted with the same taxonomy produce equally usable labels at lower cost?
4. If RFT were given the same second-round, critic-in-the-loop data budget, how much of the +4.3 pass^4 delta over RFT would survive?
5. How do the gains transfer to settings where domain rules are not enumerable text (code agents, automated scientific-discovery loops), and how stable are the τ-trait results (18–20 tasks) under bootstrap resampling?
6. What is the end-to-end annotation cost (teacher tokens for 2,500 experiences plus a full second rollout round), and at what deployment scale does it amortize against plain rejection fine-tuning?
