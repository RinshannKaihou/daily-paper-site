MutMem V2: Cryptographically Authorized Mutation in Persistent Agent Memory — Portable Verification and Reproducible Evidence

Key metric

72/72

Independent Node & Python verifiers agree on verdict and exact primary failure reason across every structural & cryptographic terminal (10/10 exit criteria). Companion figures: 42/42 conformance cases · 60/60 canary hits · 0/60 false positives.

Why this matters

A design template for tamper-evident, externally auditable agent memory — a reference for anyone building trustworthy long-running autonomous agents.

A verification contract, not a new empirical result: all utility numbers remain historical V1 runs that were never re-executed.

Critical edge

The whole verification chain is single-author: “independent” means independent-language re-implementation — both verifiers can share the same author’s blind spots.

01Methodology

  • Standard primitives only — SHA-256, Ed25519, RFC 6962 Merkle trees, canonical JSON (JCS/RFC 8785); the paper claims none of them as new. The contribution is byte-exact specification and membership completeness.
  • Evidence bundle = 13 + 5r canonical objects (r ≤ 200): 13 singletons (trust anchor, identities, grants, decisions, receipts) plus 5 objects per disclosed result, deterministically ordered with domain-separated commitments.
  • No circular trust: the bundle commitment consumes a 32-byte master fingerprint supplied from outside the bundle — a bundle can never certify its own trust root.
  • Closed failure vocabulary of 37 reasons: cross-object predicates enforce exact equality at five boundaries; an undeclared failure reason is itself an error, making parity testable across implementations.
  • Mutation semantics: the verifier reconstructs V1 projection/transition hashes; quantized-unchanged weights yield a signed no-op, never a fabricated projection; Ed25519 signatures bound to signer epochs.
  • Dual-language verification: Node reference vs independent Python (no shared verifier code; offline; no network, database, or policy authority). Parity = exact terminal + exact reason over 72 vectors. O(n) membership, O(log n) Merkle depth.
  • Stats contract: Wilson 95% intervals, exact two-sided McNemar, Holm correction within families, Cohen’s κ at 1e-12 tolerance.

  • Ablation arms A1–A3 are nearly indistinguishable (65.0 / 71.0 / 69.0% attacked vs 68.0–69.0% clean), so no single defense mechanism is isolated.

+Strengths

  • Differential testing done right: verdict plus exact primary reason across two language-independent implementations; undeclared failure reasons are errors by construction.
  • Exceptional epistemic hygiene: every claim carries a CURRENT V2 / HISTORICAL V1 / OMITTED / PROHIBITED disposition (Table 4); failed installs stay in the ledger; unknowns stay unknown rather than zero.
  • External trust-anchor binding eliminates circular self-certification — in-bundle fingerprints are refused as trust roots.
  • Deterministic regeneration from a single self-hashed evidence root, failing a byte check if output changes; clean separation of verification, installation, and reproduction.
  • Honest, well-scoped threat model with anchor substitution, availability, and semantic truth explicitly out of scope.

−Limitations

  • No current V2 utility rerun — every accuracy and performance number is frozen V1 history on models (GPT-5.4 / GPT-5.6 Terra) that cannot be re-judged today.
  • The experiments are not independent — only the implementations are; the entire verification chain, corpus, and audit trace to one author.
  • Canary coverage is marker-specific, not a detector for poisoning or prompt injection; the PoisonedRAG fixture is adapted, N=100, and post-calibrated.
  • Qualification covers exactly one macOS machine on Node v26.8.1; other declared runtimes inherit nothing until release CI covers them.
  • Anchor distribution is unsolved: an attacker who replaces both evidence and every external anchor can present a different self-consistent world.

?Questions for Further Exploration

  • Does verdict/reason parity survive fuzzing or metamorphic testing of the canonical-JSON parser and length framing beyond the 72 released vectors?
  • Can a current-source V2 utility run on LongMemEval/LoCoMo be produced at all — and would it survive a judge chosen by someone other than the author?
  • How do 13+5r bundles behave at the r = 200 cap — bundle size, verification latency, storage overhead on real agent workloads?
  • Is the closed failure vocabulary and envelope membership portable to third-party memory engines, or structurally coupled to HOM-AIMOS?
  • What anchor-distribution mechanism (transparency log, witness co-signing, keyed transparency) closes the “replace everything” gap?
  • Could an outside team reproduce the historical V1 PoisonedRAG ablation from released hashes alone, given unavailable private rows?
