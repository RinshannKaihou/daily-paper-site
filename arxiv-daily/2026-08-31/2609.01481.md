> **一句话总结：** 上海AI实验室提出 Harness-of-Harness（HoH）：不修改现有 coding-agent harness（Codex/OpenCode/Pi），而是在其上套一层"元 harness"，把开发组织为 Planner–Developer–QA Tester 三角色循环，跨轮携带工件状态 A_t 与证据状态 E_t（渐进式披露替代记忆模块、冻结只读候选+黑盒/白盒独立验收、版本化历史支持回滚）；在 GameCraft-Bench/FrontierSWE/ProgramBench × 3 个 harness–model 组合上，HoH@3 对 Vanilla 平均相对提升 52.25%（最高 82.86%），其中 Codex+GPT-5.5 在 GameCraft-Bench 上 49.58→71.52（+21.93）、FrontierSWE Dominance 44%→71%；等 pass 对照实验显示 HoH@2 用更少 token（5.67M vs 6.33M）超过三轮 Vanilla Continuation（64.84 vs 58.24）；多日部署中 70 轮循环自主开发出可游玩的第一人称射击游戏 Fusepoint（81 个 issue 关闭 65 个、重开 17 个）。

> **TL;DR:** Harness-of-Harness (HoH) wraps existing coding-agent harnesses (Codex CLI + GPT-5.5, OpenCode + DeepSeek-V4-Pro, Pi + MiniMax-M3) in a planner–coder–tester loop that carries both the artifact and an execution-evidence state across iterations, turning one-shot code generation into continual, multi-day autonomous software development. On GameCraft-Bench (45 of 140 tasks), HoH@3 lifts mean Overall score from 49.58 to 71.52 for Codex (+21.93 over the Vanilla single-pass baseline), from 26.90 to 48.98 for OpenCode (+22.08), and from 42.16 to 58.78 for Pi (+16.62); on FrontierSWE (15 tasks), Codex's Dominance rises from 44% to 71% and keeps climbing to 72.67% at HoH@10 vs 27.33% for Vanilla; on ProgramBench, pass rates gain +6.09 to +16.85 points. A pass-controlled comparison against Vanilla Continuation shows the gain is not just "more passes" (HoH@2 scores 64.84 with 5.67M tokens vs 58.24 with 6.33M tokens for 3-pass continuation), and ablations confirm all three cross-loop mechanisms matter (removing plan update / evidence feedback / warm-start costs −8.13 / −6.28 / −7.85 points). A 70-loop multi-day deployment autonomously builds a playable Godot FPS game from a PRD, with 65 of 81 tracked issues closed.

## 核心贡献

- **元 harness 框架**：提出 Harness-of-Harness，在不改动现有 coding-agent harness 内部实现的前提下，将固定的 harness–model 配置组织为可无限重复的 planning–coding–testing 循环，把单次性的代码生成扩展为跨天、跨数十轮的自主软件开发。
- **双状态跨轮传递机制**：区分"工件状态" A_t（代码/配置/资源）与"证据状态" E_t（已验证行为、未解决失败、未满足需求），二者跨循环边界显式传递；规划读证据、开发写工件、测试产证据，职责与权限分离（单写者边界、QA 只读冻结候选）。
- **约束产物而非约束流程**：每个角色必须返回结构化工件（违反 schema 触发重试），但不规定推理过程与工具序列；用渐进式披露（文件系统持久化 + 分类索引按需检索）替代专用记忆模块，配以角色专属工具、Markdown skills、复用优先原则和版本化项目历史（支持大回退后回到已验证状态）。
- **三基准 × 三配置的一致增益**：在 GameCraft-Bench、FrontierSWE、ProgramBench 上，3 个 harness–model 组合的 HoH@3 全部显著超过 Vanilla，平均相对增益 52.25%、最高 82.86%，且 FrontierSWE 上增益可持续到 10 轮（Dominance 27.33%→72.67%）。
- **等预算对照与消融**：设计了 Vanilla Continuation（同 session 续跑）做 pass/token 受控对比，证明收益不来自"多跑几遍"；消融实验量化了 Plan Update、Evidence Feedback、Warm-Start 三个跨轮机制各自的贡献（−8.13 / −6.28 / −7.85 分）。
- **70 轮多日 FPS 案例研究 Fusepoint**：仅凭一份 PRD，在 Godot 4.7 中自主开发出剧情连贯、机制完整、可人工游玩、含音效的叙事射击游戏；全程 GitHub 版本化 + issue 追踪（81 个 issue、关闭 65、重开 17、遗留 16），人类仅介入网络/API 恢复。

## Key Contributions

- **A meta-harness over existing harnesses**: HoH organizes a fixed harness–model configuration (Codex CLI, OpenCode, or Pi) into repeated planning–coding–testing loops without modifying the underlying harness, extending bounded-episode coding agents to open-ended, multi-day autonomous development from scratch.
- **Two-state cross-loop continuity**: HoH explicitly separates the artifact state A_t (code, resources, config) from the evidence state E_t (verified behaviors, unresolved failures, unmet requirements); the Planner reads evidence and the artifact read-only, the Developer is the single writer, and the QA Tester evaluates a frozen, read-only candidate with black-box + white-box tests, so acceptance is independent of the implementer's completion claim.
- **Constrain verifiable outputs, not workflows**: roles must return structured artifacts (schema violations trigger retries) while retaining autonomy over reasoning and tool use; continuity is maintained via progressive disclosure over the file system (no dedicated memory module), role-specific tools and Markdown skills, reuse-over-recreation, and versioned project histories that support rollback after major regressions.
- **Consistent, budget-aware gains**: across three benchmarks and three harness–model pairs, HoH@3 beats Vanilla everywhere — average relative gain 52.25%, maximum 82.86% — and a pass-controlled Vanilla Continuation baseline plus three targeted ablations attribute the gain to the cross-loop mechanisms rather than merely more compute.
- **Multi-day deployment evidence**: a 70-loop case study autonomously develops Fusepoint, a playable narrative FPS in Godot 4.7, with the full development trajectory (commits, issue ledger, evidence packets) released on GitHub.

## Methodology

**Problem setup.** Given a software specification S, the task is to produce a complete artifact A satisfying functional and quality requirements. HoH applies a fixed harness–model pair (M, H) as HoH_{M,H}: S → A, without altering either M or H.

**Three-role loop.** Each iteration invokes the same harness–model configuration once per role, in a fixed order:
1. **Project Planner** — combines the fixed specification S with the prior evidence E_{t−1} and reads A_{t−1} read-only to emit a development document D_t: a *bounded but locally complete* objective (a coherent observable behavior, not a file count), the functionality that must be preserved, and observable validation conditions. It cannot modify the artifact.
2. **Developer** — the single writer; warm-starts from A_{t−1} and realizes the increment, embedding "shift-left" testing (baseline–change–retest cycles) during implementation. Developer self-tests gate candidate presentation but never establish acceptance.
3. **QA Tester** — receives A_t as a frozen, read-only candidate plus deterministic build/execution checks (Runtime.check). It derives scenario-specific checkable criteria from S and D_t, then runs complementary black-box tests (user-observable behavior through inputs and rendered outputs) and white-box tests (source, config, runtime state, logs). Failures, unmet requirements, and insufficient evidence are recorded as gaps in the evidence state E_t rather than inferred successes.

A deterministic **Runtime** freezes each invocation's inputs, enforces per-role tool and write permissions, requires structured output schemas (violations trigger retries), and binds every observation to a single candidate identity.

**Cross-loop state.** Formally, loop t maps (A_{t−1}, E_{t−1}) → (A_t, E_t) under S. Artifact continuity makes development incremental (warm-start instead of reconstruction); evidence-guided replanning makes it iterative (new observations re-prioritize work, verified behavior becomes a preservation constraint). Instead of a memory module, all plans, reports, and histories persist in the file system behind a concise categorized index with on-demand retrieval (progressive disclosure). Versioned histories at role and iteration levels allow returning to previously verified states after regressions.

**Benchmark protocol.** Three configurations: Codex CLI v0.142.5 + GPT-5.5 (high reasoning), OpenCode v1.14.30 + DeepSeek-V4-Pro, Pi v0.80.10 + MiniMax-M3. Vanilla = one standard development pass with the same harness–model pair; HoH@T = T full loops with artifact and evidence carried across. Evaluators run only after the complete run and never feed back into the loop. Metrics: GameCraft-Bench Overall (0–100; non-running games score 0), FrontierSWE official task rewards plus the official Dominance score (mean task-level win rate against the 12 harness–condition pool), ProgramBench Avg. Test Pass Rate on hidden behavioral tests.

## Results & Highlights

- **GameCraft-Bench (45 tasks, stratified 3 per game family, Overall 0–100):** HoH@3 raises Codex + GPT-5.5 (high) from 49.58 to 71.52 (+21.93), OpenCode + DeepSeek-V4-Pro from 26.90 to 48.98 (+22.08, an 82% relative gain), and Pi + MiniMax-M3 from 42.16 to 58.78 (+16.62); gains are monotonic across HoH@1→3 for all three configurations (e.g., OpenCode's margin over Vanilla grows 1.71 → 13.42 → 22.08).
- **FrontierSWE (15 of 17 tasks: 4 Implementation, 9 Performance, 2 Research):** mean reward rises 0.31→0.54 (Codex), 0.23→0.31 (OpenCode), and 0.26→0.55 (Pi, the largest gain at +0.29); Codex's Dominance climbs from 44% (Vanilla) to 71% at HoH@3 (+27 pts), and continues to 72.67% at HoH@10 (peaking 76.00% at HoH@9) versus 27.33% for Vanilla.
- **ProgramBench (cleanroom reconstruction from a compiled binary):** Avg. Test Pass Rate gains +6.09 (Codex, 60.41→66.50), +12.29 (OpenCode, 45.27→57.56), and +16.85 (Pi, 35.83→52.68) points.
- **Pass-controlled comparison (Codex, GameCraft-Bench, Table 2):** at 1/2/3 development passes HoH scores 59.71/64.84/71.52 vs Vanilla(-Continuation) 49.58/54.99/58.24 (+10.13/+9.85/+13.28); HoH@2 (64.84, 5.67M tokens) beats 3-pass Vanilla Continuation (58.24, 6.33M tokens) while using fewer tokens — the gain is not explained by extra inference budget alone.
- **Ablations (Codex, T=3, all 45 tasks, Table 3):** w/o Plan Update 63.39 (−8.13), w/o Evidence Feedback 65.23 (−6.28), w/o Warm-Start 63.67 (−7.85, with per-task tokens rising from 8.41M to 11.12M due to repeated reconstruction) — every cross-loop mechanism contributes materially.
- **Component-level gains (Figure 4):** all four GameCraft rubric components improve for every configuration; for Codex, Functional Visuals jumps 48.67→74.23 and Art & Presentation 45.28→65.28.
- **Overall (abstract):** average relative gain of 52.25% and maximum 82.86% across the nine benchmark–configuration cells after three iterations.
- **Fusepoint case study (70 loops, multiple days, Codex + GPT-5.6-Sol):** from a PRD alone, HoH builds a five-minute bomb-defusal FPS (2 ordered control points, 3-stage defusal, 18 enemies across 3 regions) in Godot 4.7; the issue ledger records 81 issues with 65 closed, 17 reopened after regressions, and 16 still unresolved at loop 70; development phases shift from capability construction (loops 1–27) to stabilization with a declining backlog. A source-blinded human playtest using the full 10-construct PXI instrument (−3..+3 scale) is reported in the appendix without collapsing it into a single score.

## Authors & Credibility

The paper comes from the Shanghai Artificial Intelligence Laboratory (上海人工智能实验室), with the first four authors (Haoyang Yan, Min-Le Su, Hangfan Zhang, Zhanhao Li) contributing equally and Shuyue Hu as a senior contact. The lab is a prolific producer of agent and open-model research, and the work is backed by substantial compute (three frontier harness–model pairs, a 70-loop multi-day deployment) plus a released GitHub repository (Flesymeb/HarnessOfHarness) containing the core implementation, role prompt templates, a GameCraft-Bench adapter, harness wrappers, and the Fusepoint project materials with commit/issue histories. The methodological care shown in the appendix — pass-controlled baselines, preregistered-justified PXI scoring, stratified task sampling with fixed seeds, explicit accounting of token/caching caveats, and published exclusion reasons for two FrontierSWE tasks — signals a team that understands rigorous agentic evaluation. The paper is a systems/engineering contribution from an industry lab rather than an academic theory group, which matches its "make it actually work at scale" orientation.

## Critical Assessment

**Novelty.** The core loop (plan → code → test, with role separation and evidence carry-over) is an assembly of well-known ideas — iterative-incremental development, shift-left testing, MetaGPT/ChatDev-style role workflows, AgileCoder sprints, EvoMAC's test-feedback adaptation. The genuine novelty is the positioning and the discipline of it: HoH operates *on top of unmodified third-party harnesses* (Codex/OpenCode/Pi) rather than replacing them, constrains verifiable artifacts instead of workflows, and — most importantly — is evaluated with the controls this kind of paper usually skips. That said, readers familiar with MetaGPT/EvoDev will find few conceptually new mechanisms; the contribution is a well-engineered synthesis plus unusually honest measurement.

**Rigor — genuinely above average, with caveats.** The pass-controlled Vanilla Continuation experiment (Table 2) is exactly the right control and rarely seen in multi-agent coding papers; the ablations isolate each cross-loop mechanism; the authors disclose non-monotonicity (Pi peaks at HoH@2 on ProgramBench: 53.57 at HoH@2 vs 52.68 at HoH@3) rather than hiding it. However: (1) **no repeated runs** — the appendix explicitly states fixed seeds control task sampling and statistical resampling, *not* model generation, and no significance tests are reported on the main tables (bootstrap CIs appear only in Figure 4); with temperature left at provider defaults, run-to-run variance on 15–45 tasks could be nontrivial. (2) **Small subsets**: 45 of 140 GameCraft tasks and 15 of 17 FrontierSWE tasks (two excluded for environment reasons — Tinker API auth and a CUDA-13-requiring Modular stack — disclosed in Table 12), so numbers are not directly comparable to official leaderboard figures. (3) **Token cost**: HoH@3 uses 8.41M vs Vanilla's 2.59M tokens per GameCraft task (3.25×); the pass-controlled comparison blunts this objection but HoH@3 itself is not token-matched, and cross-provider cache accounting means OpenCode/DeepSeek and Pi/MiniMax cost comparisons are only within-configuration. (4) **GameCraft scoring** relies on benchmark-defined rubric components (Content Depth, Art & Presentation) that are at least partly judged rather than unit-tested — a framework that produces richer visuals will score better almost by construction, so the visual-polish gains partially reflect the metric. (5) **The flagship Fusepoint case study is n=1 with no control**: it uses a different model (GPT-5.6-Sol) and an enhanced tool/skill stack (Godot MCP, asset generation) absent from the benchmark configurations, and there is no 70-loop Vanilla or ablated-HoH comparison, so the case demonstrates feasibility, not attribution.

**Reproducibility.** The released package contains core implementation, prompts, and adapters, but the appendix states benchmark repositories, task data, raw run artifacts, and hidden evaluator contents are *not* included, and all three configurations depend on proprietary frontier models. Faithful reproduction requires paid API access to GPT-5.5/DeepSeek-V4-Pro/MiniMax-M3 and the benchmark environments; the Fusepoint repo is the most inspectable artifact.

**Significance.** If the numbers hold up, the practical takeaway is strong and cheap to adopt: a harness-external protocol (no harness code changes) that yields +10–22 points across three heterogeneous benchmarks and three model families, with the strongest relative gains on the weakest models. The finding that evidence feedback and warm-start each contribute ~7–8 points is a useful, transferable design lesson for long-horizon agent systems.

## Strengths

- **Right baseline, right control**: Vanilla Continuation isolates the "more passes" confound, and HoH@2 beating 3-pass continuation with fewer tokens (64.84/5.67M vs 58.24/6.33M) is the paper's most persuasive single result.
- **Generality across model tiers**: gains hold for a frontier closed model (GPT-5.5), a strong open model (DeepSeek-V4-Pro), and a smaller open model (MiniMax-M3), with the weakest baseline (OpenCode) benefiting most — suggesting the protocol is model-agnostic scaffolding, not a fit to one model's quirks.
- **Mechanism-level ablations**: all three cross-loop mechanisms (plan update, evidence feedback, warm-start) are individually quantified (−8.13/−6.28/−7.85), and the warm-start token blow-up (8.41M→11.12M) gives a mechanistic explanation, not just a score drop.
- **Honest failure reporting**: 16 unresolved and 17 reopened issues in Fusepoint, Pi's HoH@2 peak on ProgramBench, excluded-task reasons, and token-caching caveats are all disclosed rather than smoothed over.
- **Traceability**: the entire Fusepoint trajectory (commits, issue ledger, evidence packets) is public on GitHub, and the deterministic Runtime contract (frozen inputs, permissions, schema checks) is specified at implementation level in the appendix.
- **Sustained-horizon evidence**: the HoH@10 FrontierSWE run (Dominance 27.33%→72.67%) shows the loop does not plateau or degrade at three iterations, addressing the most common failure mode of iterative agent schemes.

## Limitations

- **No variance quantification on headline results**: single runs per task–condition, no significance tests on Tables 1–2, and seeds explicitly do not control model generation — the +21.93 vs +22.08 style comparisons are within noise of each other.
- **Case study attribution gap**: Fusepoint uses a different (newer) model and a much richer tool/skill stack than the benchmark configurations, and has no controlled comparison, so the impressive demo cannot be decomposed into protocol vs model vs tools.
- **Benchmark subsets are small and partially judged**: 45 and 15 tasks respectively; GameCraft's Content Depth / Art & Presentation components reward visual richness in ways a text-driven rubric judge may overweight, and ProgramBench gains for the strongest config (+6.09) are modest.
- **Cost scaling unexamined**: per-task tokens grow ~3.25× from Vanilla to HoH@3 (2.59M→8.41M); nothing is said about where the marginal utility curve flattens (HoH@4..T is only explored for FrontierSWE Dominance), nor about wall-clock cost of QA loops.
- **Proprietary-model dependence and partial artifact release**: results may not transfer to smaller/open-weights models without frontier reasoning quality; benchmark repos, raw runs, and hidden evaluator contents are excluded from the release.
- **Domain scope**: all three benchmarks are game/software construction tasks; evidence states rely on executable checks (screenshots, smoke tests, hidden tests) — how the loop behaves where acceptance is genuinely subjective (e.g., non-game product software with fuzzier specs) is untested.

## Questions for Further Exploration

- How much of the gain survives with open-weights models of modest size (e.g., 7–30B coders), where the QA Tester may be too weak to produce trustworthy evidence states?
- What is the marginal-utility curve over T? ProgramBench already shows Pi peaking at HoH@2 — is there a principled early-stopping criterion based on evidence-state saturation (e.g., declining new-issue discovery)?
- Could the evidence state E_t be replaced or augmented by learned components (a trained verifier or issue-tracker embedding), and would that reduce the ~3.25× token overhead of re-reading evidence each loop?
- The Fusepoint case conflates protocol, model upgrade (GPT-5.6-Sol), and tool enrichment — what would a 70-loop Vanilla or w/o-ablation control on the same PRD show?
- Since GameCraft's rubric partially rewards visual polish, how does HoH perform on benchmarks scored purely by hidden unit tests (e.g., Commit0-style library construction), where "richer artifact" cannot buy points?
- Does the single-writer boundary become a bottleneck at scale — would parallel developer roles with merge conflicts and inter-component contracts preserve the candidate-lineage guarantees that make evidence binding sound?
- Can the same harness-external protocol transfer beyond code: e.g., autonomous research loops or automated experiment pipelines where the "artifact" is a paper/repo and acceptance requires reviewer-style independent verification?
