Key Finding · Agent Memory Systems

Cached agent fixes fail silently when API data drifts — a machine-readable invalidation contract makes the savings measurable: validity × compliance.

Invalidation Contracts for Cross-Episode Agent Memory · Michael Wu (South Dakota State Univ.), Arquimedes Canedo (Siemens Digital Industries Software) · 2026-08-31
LLM Agents Agent Memory Cache Invalidation API Protocol Design
Key Metric
+66.7 pp
First-try compliance lift from row-level invalidation (A2D vs memory-without-invalidation) — gpt-5-mini 33.3%→100.0%; +63.0 and +55.6 pp on two further models.
Why This Matters

Turns silent agent-memory failure under API drift into a measurable protocol problem — directly applicable to any agent infrastructure with cross-session memory.

把“服务器端数据漂移导致 agent 持久记忆静默失效”变成可度量、可分层解决的工程问题，对带跨会话记忆的 agent 基础设施有直接借鉴价值。

Critical Edge

Both evaluation domains are author-built synthetic APIs with hand-written reflection and no external baseline — a simpler timestamp-and-revalidate fix might recover much of the same gains.

— Critical Assessment

Methodology

  • Two synthetic API domains driven by a declarative harness (DriftRiver): Acme billing (Stripe-style; 36-episode stream, four constraint classes) and recipe conversion (48-episode stream, dietary ladder). Drift is fixed by schedule — the promo-code table rotates at episode 11, a benign rule-edge change lands at episode 23.
  • Protocol ladder L0→L6: raw feedback → structured suggestion with cache_hint + table version → patch protocol → amended input → per-suggestion dependency vectors → versioned knowledge graph → rules fingerprint — plus a structured diff on schema reload so clients evict stale entries without trial and error.
  • Client arms: A0 (no memory) → A1 (memory, no invalidation) → A2 (table-level stamps) → A2D (row-level diffs), extended by A2DC / A2DG / A2DO (consumer notification, subgraph propagation, rule-declaration oracle). Compliance channel fixed at L3 throughout.
  • Metrics: compliance (first-try rate over injection-eligible episodes, stale-injection slot excluded by a pre-registered list), eviction precision, retries per stream, vendor-billed tokens compared only within-model vs own A0.
  • Hygiene: preflight probe over 238 archived runs (no requested/served model mismatches), three seeds per drifted cell, 250 arm-level runs, 9,432 episodes total.

  • —Imprecise invalidation is worse than none: table-level eviction collapses post-drift funding first-try from 66.7% (A1) to 0.0% (A2) on four of seven models before recovering at A2D; eviction precision is 0.25 at table vs 1.00 at row granularity.
  • —Wire cost, byte-level: the contract adds a mean 123 bytes on a mean 817-byte response (15.1% of payload, max 251) — nearly all of it the per-table table_versions dictionary (~190 bytes) vs ~32 bytes for the two per-suggestion fields.
  • —Detection price sheet: the rule-declaration oracle alerts one episode earlier and saves 2.2–2.5 tokens/event at just +2.4% tokens vs lazy; stamp-only pays 140–143 extra tokens/event; lazy+stamp+vector costs +0.2% while matching the oracle’s eviction precision of 1.00.
  • —Controls hold — over-invalidation doesn’t: 1,023 no-constraint episodes stay at 83.3% in every arm; but claude-sonnet-4-6 drops from 100% (A1) to 54.5% (A2) on the governed class.
  • —Retries fall: 27.0 (A0) → 7.0 (A2D) per stream on claude-haiku-4-5; 82.7 → 55.0 on gemini-3.5-flash.

Strengths

  • The validity × compliance split assigns responsibility cleanly: API providers ship the contract without touching model behavior; a cheap “compliance preflight” (tens of calls with known-valid fixes) reads out the model factor before any memory investment.
  • Deterministic, exactly reproducible validity: byte-identical results across seven models, three serving paths, and all seeds — ~1 pp seed SD in most cells; rare rigor for an agentic systems paper.
  • Controls demonstrate specificity: no-drift episodes hold at 83.3% across every arm and the negative-control class does not move — effects are attributable to drift handling, not memory per se.
  • Unusually honest failure accounting: negative token deltas, opt-out models, the exhaustion-precision artifact, the failed pre-registered prediction, and three trust-surface exposures are all in the main text.
  • Actionable numbers end-to-end: byte-level wire cost, per-action-type compliance price sheet, and an eager-vs-lazy detection cost table within ~2.5% tokens.

Limitations

  • Synthetic, self-authored world: both domains and the reflective layer were built by the authors; transfer to production APIs (larger schemas, organic drift) is unknown by the authors’ own admission.
  • Validity is asserted, never verified: a server that never bumps versions pins stale fixes indefinitely — a cheap denial-of-savings attack; no threat model, and the L5 graph endpoint leaks internal derivation structure.
  • The compliance channel is itself a parameter-injection vector (L2 verbatim-merge, L3 pre-applied amendments); 100% compliance on claude-haiku-4-5 reads either way.
  • Measurement confounds: eviction precision is inflated by run exhaustion (gemini’s 1.00 is a starvation artifact); token accounting is vendor-billed, so all savings are within-model deltas only.
  • The pre-registered falsification criterion failed: the naive-governed gap plateaus at three drift rotations instead of growing monotonically — reported honestly, left unresolved.
  • Coverage: two domains, one base prompt each; L4’s isolated compliance effect is unmeasured, and L5/L6 are exercised only on the rule stream with three models.

The Equation

realized savings = validity × compliance(m, p, a)
validity — a protocol property
version stamps are deterministic: byte-identical results across 7 models × 3 serving paths, zero contract failures in ~9,400 episodes
compliance — a model property
spans 0–66.7 pp across seven models; the newest model tested (Claude Sonnet 5) refuses add-a-field fixes at 10% first-try even when told the exact field name
Implication
providers can engineer validity independently of model vendors — and the model factor is measurable in advance with a cheap preflight

Questions for Further Exploration

  1. Does the contract survive organic drift (schema migrations, deprecations, third-party API churn) and production-scale schemas where the reflective layer cannot be hand-written per endpoint?
  2. Can validity be verified rather than asserted — signed version stamps, rate-limited bumps, client-side spot re-derivation — to bound a malicious server’s denial-of-savings attack?
  3. What is the isolated compliance effect of Level-4 dependency vectors without graph propagation, and do the extra per-suggestion bytes pay for themselves?
  4. Is input-schema conservatism in Claude Sonnet 5 (10% add-a-field compliance despite explicit field names) a promptable behavior, a tool-schema design artifact, or a post-training artifact?
  5. How does the compliance plateau at three drift rotations decompose: ceiling effect, rotation-schedule artifact, or exhaustion of injection-eligible slots?
  6. Would a simpler engineering baseline (cache with timestamps + revalidate-on-use, no protocol change) recover most of the A2D gains, and how does the 15% payload overhead compare against its revalidation traffic?
