> **一句话总结：** MutMem V2 把 V1 的"加密授权记忆变更"从实现绑定的完整性声明升级为可移植验证协议——召回证据包恰由 13+5r 个规范对象构成（域分离 SHA-256 承诺 + RFC 6962 Merkle 排序 + 外部主指纹 + 37 个封闭失败原因），独立 Node 与 Python 验证器在全部 72/72 个结构/密码学终止向量上裁决与主因完全一致，生产一致性语料 42/42 覆盖 28 个必需类，金丝雀实验 60/60 标记单元检出且 0/60 干净单元误报；但所有效用数字（如 LongMemEval 91.80%）仍是不可重跑的历史 V1 结果，V2 本身未做任何效用实验。

> **TL;DR:** MutMem V2 (Saidi, independent researcher) converts the MutMem V1 agent-memory integrity system into a portable, externally verifiable protocol: recall evidence bundles of exactly 13+5r canonical objects with domain-separated SHA-256 commitments, RFC 6962 Merkle ordering, an externally supplied master fingerprint (preventing circular trust), a closed 37-reason failure vocabulary, and three exhaustive mutation terminals (authorized_transition / signed_noop / occurrence_observation). Independent Node and Python verifiers share no verifier code yet agree on verdict and exact primary reason for 72/72 vectors; a production-derived conformance corpus agrees on 42/42 cases across 28 classes; a canary lane flags 60/60 planted markers with 0/60 false positives on clean units. Utility numbers remain historical V1 runs: LongMemEval LLM-judged accuracy 459/500 = 91.80% (Wilson 95% CI 89.06–93.90%, GPT-5.4 generator / GPT-5.6 Terra judge), and a PoisonedRAG-style ablation where poison retrieval@5 drops from 94/100 (undefended arm A0) to 0/100 with attacked accuracy recovering from 40.0% to 65.0%. There is no current-source utility rerun, no comparison against any external memory system, and no independent replication — the deliverable is a verification contract, not a new empirical result.

## 核心贡献

- **可移植召回-披露协议**：定义版本化证据包，完整成员资格恰为 13 个单例对象 + 每条披露结果 5 个对象（N = 13 + 5r，r ≤ 200），具有确定性排序、精确规范字节、域分离 SHA-256 承诺（式 1）与 RFC 6962 Merkle 根；束承诺（式 5）把外部提供的主指纹作为验证输入，杜绝"证据包自证信任根"的循环信任。
- **跨对象谓词图与封闭失败词表**：在 Authority、Admission、Decision composition、Per-result evidence、Terminal receipt 五个边界上强制精确相等；37 个封闭召回失败原因——未声明的失败原因本身即错误，使"裁决 + 精确主因"可跨实现做奇偶校验。
- **可移植变更档案**：不引入新认知更新规则，保留 V1 原生 outcome schema 并给出三个穷举终态（authorized_transition / signed_noop / occurrence_observation），以 Ed25519 签名与签名者纪元绑定（式 6）。
- **独立验证与可复现性架构**：Node 参考实现与 Python 独立实现（不共享验证器代码）在 72 个终止向量上达成裁决与主因完全一致、10/10 退出准则；42/42 生产一致性语料覆盖 28 个必需类；120 单元显式标记金丝雀实验；Node v26.8.1 单次干净安装资格（首启+重启、调度器就绪、8 条 Guide 记忆、0 条实验记忆）；确定性证据再生成（`npm run evidence:regenerate`，字节校验失败即报错）；以及把每条声明标注为 CURRENT V2 / HISTORICAL V1 / OMITTED / PROHIBITED 的完整 claim-to-evidence 处置表。
- **刻意收窄的声明边界**：论文反复强调密码完整性 ≠ 内容为真、金丝雀 ≠ 通用投毒检测、验证器奇偶 ≠ 独立经验复现，并把这些过度声明直接列为 PROHIBITED。

## Key Contributions

- A versioned recall-disclosure envelope whose complete membership is exactly 13 + 5r canonical objects (r disclosed results, 0 ≤ r ≤ 200) with deterministic ordering, exact canonical bytes, and domain-separated SHA-256 commitments (Eq. 1); the bundle commitment (Eq. 5) takes the master fingerprint as an external verification input, so a bundle can never certify its own trust root.
- A cross-object predicate graph enforcing exact equality across five boundaries (authority, admission, decision composition, per-result evidence, terminal receipt) with a closed failure vocabulary of 37 recall failure reasons — an undeclared failure reason is itself an error, making verdict/reason parity testable between implementations instead of permitting semantically similar but incomparable exceptions.
- A portable mutation profile that preserves the native V1 mutation-outcome schema and exhaustively distinguishes an authorized transition, a signed no-op, and an occurrence observation (Eq. 6), with retained Ed25519 signatures and exact signer epochs.
- Independent Node and Python verifiers (no shared verifier code, four lanes: recall structure, mutation structure, recall cryptography, mutation cryptography) agreeing on verdict and exact primary reason for all 72 structural/cryptographic terminals; a production-derived conformance corpus agreeing on 42/42 intended cases across 28 required classes; a 120-unit explicit-marker canary lane; one clean-installer qualification on Node v26.8.1; deterministic publication regeneration from a single self-hashed evidence root; and a complete claim-to-evidence disposition table (Table 4: CURRENT V2 / HISTORICAL V1 / OMITTED / PROHIBITED).

## Methodology

The protocol layer builds on standard primitives — it explicitly claims none of them as new. Canonical objects commit to `o_j = H(D_o ∥ LP4(k_j) ∥ LP4(s_j) ∥ BE4(|b_j|) ∥ b_j)` where D_o is the domain string `hom.aimos.mutmem-portable-object/v2` plus a zero byte, LP4 is 4-byte big-endian length framing, and bodies reject unsupported floats, unsafe integers, over-deep nesting, and oversized payloads (a prefix-free framing + domain-separation discipline per Boneh–Shoup, with deterministic JSON per JCS/RFC 8785). A recall bundle's 13 singleton objects (trust anchor; actor identity+revocation; Housekeeper identity+revocation; effective grant; request envelope; request receipt; content-state decision; epistemic decision; final security closure; return projection; native recall receipt) plus 5 objects per result (memory state, provenance chain, occurrence, epistemic projection, receipt evidence) are Merkle-committed with the RFC 6962 leaf/node prefix construction, then bound into a bundle commitment that includes the externally expected 32-byte master fingerprint f — the structural evaluator explicitly reports signatures and external trust as unverified, delegating those to independent reviewers. Cross-object predicates check exact equality (e.g., POST /aimos/recall, nonce/signature/authorization-mutation agreement) and any mismatch resolves to one of 37 closed reasons.

For mutation, the verifier reconstructs V1 projection and transition hashes from memory identifier, integer millisecond-scale old/new weights, provenance mutation, predecessor projection, and company, requiring the retained Ed25519 signature and signer epoch; quantized-unchanged weights yield a signed no-op rather than a fabricated projection. Verification runs two implementations — a Node reference and an independent Python verifier with no shared verifier code, no runtime importer, database, network, signing, model, or policy authority — over 72 public vectors where the test is exact terminal + exact primary reason parity (a conformance denominator, explicitly not a benchmark accuracy metric). Complexity: O(n) membership via maps keyed by singleton kind/result ordinal, O(n) hash evaluations for the Merkle tree, O(log n) recursion depth, r capped at 200. The reproducibility architecture separates verification (read-only, offline), installation (one qualified clean install), and full reproduction (canonically signed SAVE/RECALL with the integer denominator invariant n_intended = n_selected = n_completed = n_evaluated, n_incomplete = n_failed = 0), and the statistical contract prescribes Wilson 95% intervals (z = 1.959963984540054), exact two-sided McNemar, Holm adjustment within declared families, and Cohen's κ at 1e-12 tolerance; V2 independently reconstructs 44 rate/Wilson rows and 28 McNemar/Holm rows from public agreement counts while omitting V1's private-row bootstrap intervals.

## Results & Highlights

- **Verifier parity (current V2):** the independent Node and Python implementations agree on the expected valid/invalid terminal and exact primary reason for all 72/72 structural and cryptographic vectors, meeting 10/10 exit criteria — a portability claim, not an accuracy claim.
- **Production conformance corpus (current V2):** all 42/42 intended production-shaped cases are observed and agree on terminal verdict and protocol reason, covering 28 required classes.
- **Canary explicit-marker lane (current V2):** across 120 terminal units, all 60/60 marked units were detected (100.0%, Wilson 95% lower bound 93.98%) and 0/60 clean units were flagged (0.0%, Wilson upper bound 6.02%) — evidence of explicit-marker traversal across the declared transport flags only, not of arbitrary poison or prompt-injection detection (the paper itself prohibits that reading).
- **Historical V1 utility (Table 2, not current-source):** LongMemEval LLM-judged accuracy 459/500 = 91.80% (Wilson 95% CI 89.06–93.90%) with GPT-5.4 as generator and GPT-5.6 Terra as judge; LoCoMo LLM-judged accuracy 1472/1986 = 74.12% (CI 72.15–76.00%), reported separately from a category-aware token F1 of 58.20.
- **Historical V1 PoisonedRAG adaptation:** induced attack success rate 1/98 = 1.02% against a baseline-aware effect of clean 2/100 vs attacked 3/100 target-match; poison retrieval@5 = 0/100 (Wilson upper 3.70%) vs 94/100 poison retrieval@5 in the undefended ablation arm A0, with attacked answer accuracy recovering from 40.0% (A0) to 65.0% (A1, +25 pts) — but the corpus is an adapted N=100 post-calibration fixture, and arms A1–A3 (65.0/71.0/69.0% attacked) are nearly indistinguishable.
- **Historical V1 mutation cost and integrity:** 7/7 authorization and 4/4 tamper cases over 20 measured native transitions; median transaction cost 4.865 ms, p95 5.674 ms, 966.35 logical bytes/transaction on a single historical machine.
- **Historical V1 blinded audit:** system-author agreement with judge verdicts 193/200 (96.5%, κ = 0.9108) — explicitly labeled an agreement diagnostic, not independent human validation.

## Authors & Credibility

Walid Saidi, self-described independent researcher, is the sole author of both MutMem V1 (arXiv:2608.02843) and this V2 manuscript. Credibility rests on artifact discipline rather than institutional standing: an AGPL-3.0-or-later public repository (github.com/wallidsaydi-creator/HOM-AIMOS) with an immutable v1.0.0 release tag, a published source-manifest root, evidence-root hashes printed in the manuscript, and deterministic `npm run verify` / `npm run evidence:regenerate` commands. The related-work section is honest about provenance — Certificate Transparency (RFC 6962), Ed25519 (RFC 8032), JCS (RFC 8785), Crosby–Wallach tamper-evident logging, and Boneh–Shoup are cited as the source of every primitive. The main credibility caveats are structural: no co-authors or institution to cross-check the work, the blinded agreement audit was performed by the system author, and the conformance corpus is evaluated "with the production protocol owners" — i.e., the same person on both sides of the parity check.

## Critical Assessment

- **Novelty is protocol discipline, not cryptography.** SHA-256, Ed25519, RFC 6962 Merkle trees, and canonical JSON are all standard; the paper concedes this. The genuine contribution is byte-exact specification, closed failure vocabulary, and membership completeness — valuable engineering rigor, but incremental relative to two decades of tamper-evident logging and transparency-log work, and applied to a single-producer system rather than a federated setting.
- **No external baselines anywhere.** There is no comparison to any other agent-memory system or any alternative verifiable-evidence design; the 72 vectors, 42 conformance cases, and 60/60 canary units are all self-defined denominators. The 91.80% LongMemEval number floats without context of what other memory architectures score under the same GPT-5.4/GPT-5.6 judge protocol, so its strength is uninterpretable.
- **The canary experiment is near-tautological as designed.** A lane built to traverse explicit markers detects 60/60 explicit markers and flags 0/60 clean units — a structural echo check, not a detection result; to the paper's credit it labels this "[V2-CANARY] explicit marker traversal only" and lists "universal defense" as PROHIBITED, but the 100%/0% framing in Table 1 invites overreading.
- **The historical ablation is weak evidence.** Table 3's arms A1–A3 are nearly identical (attacked accuracy 65.0%/71.0%/69.0% vs clean 68.0–69.0%), and the paper admits A2 "made no additional selection change after A1" and that active-context withholding "was not exercised" — so the fixed-corpus ablation cannot isolate which mechanism (save-time rejection, deletion, or proof-of-false labeling) does the work, and the N=100 adapted PoisonedRAG fixture says nothing about unseen attacks.
- **Self-referential verification chain.** Both verifier implementations, the conformance corpus, and the blinded audit come from the same author; "independent" here means independent-language re-implementation, not independent party. A differential-testing setup where both implementations share one author's mental model can systematically omit the same edge cases.
- **An ironic identity typo.** The reproducibility box prints V1's preprocessor as "arXiv:2008.02843" while reference [1] and the claim map say 2608.02843 — a two-digit slip in the identity-critical header of a paper whose entire subject is exact, hash-bound identity.
- **All utility evidence is frozen history.** No current-source V2 utility run exists, V1 private rows are unavailable (bootstrap intervals cannot be reconstructed), and the empirical numbers involve models (GPT-5.4, GPT-5.6 Terra) unavailable for re-judging — so the system's actual retrieval quality is unverifiable today.

## Strengths

- Verdict-plus-exact-primary-reason parity across two language-independent implementations, backed by a closed failure vocabulary where an undeclared reason is itself an error — differential testing done the right way.
- Exceptional epistemic hygiene: every claim carries a CURRENT V2 / HISTORICAL V1 / OMITTED / PROHIBITED disposition (Table 4), unknowns are explicitly unknown rather than zero, two failed installed-service attempts stay in the attempt ledger as failures, and SABER-derived numbers are omitted outright because the artifacts lack verified custody.
- External trust-anchor binding kills circular self-certification: the verifier consumes the master fingerprint from outside the bundle and refuses to treat in-bundle fingerprints as trust roots.
- Deterministic regeneration — publication tables rebuild from a single self-hashed evidence root and fail a byte check if output changes — plus a clean separation of verification, installation, and reproduction, with the integer denominator invariant (zero silent incompletes).
- Honest, well-scoped threat model: tamper evidence under SHA-256 collision resistance and Ed25519 unforgeability, with anchor substitution and availability/semantic-truth explicitly out of scope.

## Limitations

- No current V2 utility rerun: utility, mutation performance, PoisonedRAG, ablation, and human-agreement numbers all remain historical V1, and V2 does not relabel them as current.
- No independent empirical replication — the verifier implementations are independent, the experiments are not; the whole verification chain is single-author.
- Canary coverage is marker-specific and is not a general detector for poisoning, prompt injection, or false content; the PoisonedRAG experiment is adapted, bounded at N=100, and post-calibrated, so it does not establish unseen-attack generalization.
- Installation qualification covers exactly one macOS machine on Node v26.8.1 (first boot + restart only); other declared runtimes inherit nothing until release CI covers them.
- Private V1 rows are unavailable, so V1 bootstrap intervals cannot be independently reconstructed from V2 tables; SABER operational figures are omitted for custody reasons.
- An attacker who replaces both the evidence and every external trust anchor can present a different self-consistent world — the anchor-distribution problem is unsolved; availability, confidentiality, and semantic truth are out of scope, and archival identifier binding is still pending.

## Questions for Further Exploration

- Does verdict/reason parity survive adversarial inputs beyond the 72 released vectors — e.g., fuzzing or metamorphic testing of the canonical-JSON parser and length framing?
- Can a current-source V2 utility run on LongMemEval/LoCoMo be produced at all, and would the judged-accuracy protocol survive a judge chosen by someone other than the author?
- How do the 13+5r bundles behave at the r = 200 cap in practice — bundle size, verification latency, and storage overhead on real agent workloads?
- Is the closed failure vocabulary and envelope membership portable to third-party memory engines, or is it structurally coupled to HOM-AIMOS?
- What anchor-distribution mechanism (transparency log, witness co-signing, keyed transparency) would close the "replace everything" gap the threat model explicitly excludes?
- Could an outside team reproduce the historical V1 PoisonedRAG ablation from the released hashes alone, given that private rows and bootstrap intervals are unavailable?
