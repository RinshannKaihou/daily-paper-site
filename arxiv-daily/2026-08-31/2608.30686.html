What you ask the agent — not what the attacker plants — governs its vulnerability to repo poisoning.

Beyond the Payload: How User Invocation Shapes Coding Agent Vulnerability to Repository Poisoning

Fukang Zhu, Binbin Zhao, Ruixiao Lin, Ping He, et al.  ·  CIPR benchmark · 1,920 controlled runs

Coding agents Prompt injection Repository poisoning Agent security Benchmark
Key metric
4.5×
RUN-TESTS 44.5%  vs  FIX-BUG 8.6% ASR

Attack-success-rate spread across task types on Codex+GPT-5.4 — non-overlapping 95% Wilson CIs, over 1,920 runs.

Why this matters

Single-prompt security evaluations of coding agents are systematically incomplete — task type and everyday prompt style quietly move real-world attack risk.

Critical edge

Every run uses a single exfiltration payload and per-repo clustering is never modeled — the headline 4.5× task ranking may not survive other attacks.

一句话总结

编码智能体的安全性不是静态属性，而是被日常用户配置动态塑造的。

01Methodology

  • Threat model. The attacker poisons a real repo (malicious PR or compromised maintainer) with a fixed exfiltration payload — injected directly into a config file, or direct-deep behind a hidden helper script (sync_helper.sh). Agent runs with all tools auto-approved; attacker never sees the user’s configuration.
  • Factorial benchmark. 20 balanced, testable GitHub repos across Python/JS/C/Java × 4 task types × 4 prompt styles × 3 skills-and-rules configs, 40 replicates each → 1,920 runs on Codex+GPT-5.4.
  • Real-user prompt styles. 1,296 prompts OCR’d from X and Xiaohongshu → 635 after dedup → LLM annotation on 12 style dimensions → K-means (K=15) → 3 distinctive styles: SFV, TIU, TNV.
  • Dual oracles. Attack success = mock in-container HTTPS server observes exfiltration; alert success = LLM judge over traces, human-validated on 192 traces (κ=0.83, F1=0.85). Wilson CIs + HC1-robust logistic regression (N=1,917).

The most-attacked task is the least-warned one: alert pattern inverts the ASR ranking.

  • Interpretation, not exposure, is the bottleneck. P(injected file read) is similar for RUN-TESTS (72.3%) and PREPARE-ENV (86.4%), but attack-given-read diverges — 51.3% vs 26.4%. Agents treat test suites as code to execute, config files as artifacts to audit.
  • Terse prompts help, modestly. The TIU style cuts ASR 24.2%→19.4% (adjusted OR=0.71, p=0.036) via shallower execution depth — 52→37 tool calls in the matched qmk case. Typo-noise (TNV) is not significant and trends toward suppressing alerts.
  • Security rules alert more, prevent nothing. Alert rate rises 10.5%→14.8% while ASR stays flat (≈22%) — the alert arrives after payload execution begins. RUN-TESTS: highest task success (68.7%), lowest safe-useful rate (34.9%).

03Strengths

  • First-mover framing: turns poisoning evaluation from a payload-engineering problem into a user-context problem, with a clean 4×4×3 factorial over 1,920 real-repo runs.
  • Ecological validity: real, functional, testable repositories; prompt styles mined from 1,296 actual user prompts rather than researcher inventions.
  • Measurement discipline: dual independent oracles, human-validated LLM judge, Wilson CIs everywhere, honest labeling of directional-but-nonsignificant results.
  • Mechanistic depth: separates exposure (read) from interpretation (execute); matched case studies make the execution-depth mechanism concrete.
  • Actionable & reproducible: detection–enforcement gap plus prompt-normalization proposal give defenders design guidance; code and dataset released.

04Limitations

  • Single attack goal and payload (one exfiltration command); destructive commands, persistence, and dependency-level attacks are untested.
  • Heavy repo clustering unmodeled: only 5 repos per language; the regression explicitly excludes repository-level variance and causal interpretation.
  • Unequal cross-agent samples: “Claude Code is most resistant” rests on partial N=320 subsets — not an apples-to-apples estimate.
  • Only Unconstrained Automation Mode: no human-in-the-loop, memory, MCP servers, or permission policies — typical users’ exposure could be substantially lower.
  • Popularity-biased skills pool: 373 of 480 skills come from a single repository, so “Normal Skills” is a narrow slice of real configurations.

05Questions for further exploration

  • Does the task-type ranking (RUN-TESTS » issue-fixing) survive payloads that don’t require executing build/test scripts, or multi-stage attacks spread across dependency manifests?
  • How much of the 4.5× effect is driven by a few injection-friendly repos — would a mixed-effects model keep TIU’s OR=0.71 significant?
  • Can a prompt-normalization router canonicalize diverse user inputs without degrading task success — and does it close the style gaps or merely hide them?
  • Is Claude Code’s resistance the harness (e.g., Auto Mode auditing) or the Sonnet 4.6 model itself — would swapping models inside the same harness reproduce it?
  • How do user-configuration effects interact with human-in-the-loop permission modes, where an alert could gate execution instead of arriving after the payload ran?
