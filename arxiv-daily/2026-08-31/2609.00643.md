> **一句话总结：** 提出 REVISE——一个"有效性引导"的 agent 工作流运行时：当用户修订（revision）在执行途中到达时，将修订增量 Δ 与记录的数据/控制依赖求交、沿部分执行的 DAG 传播影响，从而取消无效工作、保留已证明有效的进度、只重算受影响区域，并在 commit 时用证书机制重验证；在 15,939 次执行中零过期输出/副作用，相对全量重启减少 40.6–56.0% 模型调用、相对后缀重算减少 31.3–43.6%，服务压力下修订到完成的 token 减少 13.26%。

> **TL;DR:** REVISE is a runtime for structured agent workflows (evaluated on unmodified LangGraph and LLMCompiler apps served with Qwen3-14B via SGLang) that recovers from user revisions arriving mid-execution. It intersects the revision's delta with recorded data/control provenance over the partially executed DAG, applies five lifecycle actions (cancel/avoid/recompute/continue/reuse), and revalidates reuse at commit time. Against the dynamic-suffix-recomputation baseline it cuts model calls by 31.3–43.6% (56.0% vs full restart on LangGraph), matches a latest-version oracle across 15,939 executions with zero stale outputs or tool effects, and under multi-tenant serving pressure (15,000 workflows, 64 tenants, 4×H100) reduces revision-to-completion tokens by 13.26% and pooled SLO goodput improves +2.79% (95% CI +1.29–4.40) vs suffix. Motivation is grounded in real SWE-chat coding-agent traces: 118 of 5,825 sessions retain observable work when a later user message arrives, with assistant-response overlap reaching 56.55 s at p95.

## 核心贡献

- **在线执行有效性抽象**：给出在部分执行的 DAG 上判定"哪些已完成/运行中/待处理工作在修订后仍有效"的形式化语义——工件带单调版本号、读选择器 (ω, p, c) 记录数据/控制读取、核心不变式 `reuse(π_u) ⇒ valid(π_u) ∧ effectSafe(π_u)`，证明不了就重算或阻塞，绝不猜测（fail-closed）。
- **失效闭环恢复协议**：通过节点入口的递归只读代理自动记录字段路径与集合成员关系，用旧/新结构化 diff 产生修订增量 Δ；沿活跃后代传播得到影响集与恢复计划，映射为五种生命周期动作（Cancel/Avoid/Recompute/Continue/Reuse）；溯源不完备时保守地退化为后缀甚至全量重启；commit 时用证书 `C_π=(id, v_start, R_data, R_control, P, mode)` 对账修订日志，堵住"修订先于最终读取"的竞态。
- **真实修订机会的实证刻画**：对 5,825 个 SWE-chat 真实编码 agent 会话做时间线重建 + 人工语义审计——657 个有排队修订信号、118 个在修订送达时仍有可观测工作、167 条重叠助手响应的排队到完成重叠时长中位 5.54 s / p95 56.55 s / 最大 853.16 s；30 个事件的抽样审计给出 L0 线性链 / L1 后缀 / L2 独立分支的局部性分类。
- **全面评测**：15,939 次执行全部匹配最新版 oracle（0 过期输出、0 过期副作用），含 300 个对抗性修订/提交时序用例；在 LangGraph 上模型调用相对全量重启降 56.0%、相对动态后缀降 43.6%；服务压力下修订到完成 token 降 13.26%、合并 SLO goodput +2.79%。

## Key Contributions

- An **online execution-validity abstraction** for deciding which completed, running, and pending work remains valid after a revision: versioned artifacts, typed read selectors over data and control, and the core invariant reuse(π) ⇒ valid(π) ∧ effectSafe(π) — when either condition cannot be proved, REVISE recomputes or blocks rather than guessing (fail-closed).
- A **fail-closed recovery protocol**: adapters wrap node state in a recursive read-only proxy so field/iteration accesses auto-record provenance; a structural old/new diff yields the revision delta Δ without application-supplied affected sets; impact propagates through active descendants into five lifecycle actions (Cancel, Avoid, Recompute, Continue, Reuse); incomplete provenance conservatively expands recovery to a suffix or full restart; commit-time certificates rechecked against the revision journal close the late-read race.
- A **workload study of real revision opportunities**: timeline reconstruction plus manual semantic audit of 5,825 SWE-chat coding-agent sessions — 657 with a queued-revision signal, 118 retaining observable work at delivery, overlap duration 5.54 s median / 56.55 s p95 / 853.16 s max across 167 overlapping assistant responses, and a 30-event audited taxonomy (3 linear-chain L0, 10 suffix-recoverable L1, 6 independent-branch L2 candidates, 1 no window).
- An **evaluation across correctness, recomputation, and serving**: 15,939 executions all oracle-equal with zero stale outputs/effects (including a 300-run adversarial matrix over revision/commit orderings, late reads, consecutive revisions, unknown provenance, membership changes, route invalidation); model calls −56.0%/−43.6% (LangGraph vs restart/suffix), −40.6%/−31.3% (48 LLMCompiler workflows); under serving pressure, revision-to-completion tokens −13.26% and pooled SLO goodput +2.79% relative to suffix.

## Methodology

**Model.** A workflow is a DAG G=(V,E) whose nodes invoke models, tools, verifiers, routers, or joins. Each semantic artifact ω carries a monotonically increasing version; a read selector (ω, p, c) identifies the artifact, a nested semantic path, and whether the read is data or control. A revision event e = (α, v, v+1, op, Δ) replaces/appends/cancels or changes control state, accepted only when v is current. An attempt is valid if no revision since its snapshot intersects any selector it consumed, all parent attempts remain valid, and it re-reads/re-intersects consumed artifacts.

**Dynamic impact.** Ordinary paths intersect under ancestor-descendant overlap; a #members marker records collection membership so member insertion/deletion intersects the member's marker. Adapters wrap structured state at node entry in a recursive read-only proxy (field access → leaf path; iteration → membership mark); a typed patch is merged and an old/new structural diff produces Δ with no application-provided affected set. REVISE indexes complete readers by path, coarse readers by artifact, and unknown readers conservatively; traversing active descendants yields the impact set and an evidence-annotated recovery plan.

**Lifecycle and fallback.** Five actions: Cancel (stop affected running work), Avoid (never start affected pending work), Recompute (rerun on the revised snapshot, plus required canceled/avoided nodes), Continue (proven-unaffected running work proceeds provisionally), Reuse (proven-unaffected completed result, revalidated at commit). Evidence grades the scope: full fine-grained provenance → recompute only the affected subgraph; only the earliest safe conflict → topological suffix; no safe boundary → full restart. Irreversible or incompletely covered effects are staged or block execution.

**Commit-time revalidation.** Each attempt accumulates a certificate (id, v_start, data/control reads, parents, mode ∈ {complete, coarse, unknown}); revisions append deltas to a journal. At commit, REVISE checks every post-v_start delta against the final certificate and verifies the parent chain is the current committed attempt; conflicting/unknown/obsolete attempts are rejected and tool effects stay staged until the check succeeds; a later revision invalidating a committed parent invalidates dependent outputs and revocable/versioned effects.

**Evaluation setup.** Unmodified LangGraph and LLMCompiler applications with local Qwen3-14B served via SGLang on four H100s; serving experiments run 64 tenants at 1.4–2.6 workflows/s (0.7–1.3× a measured 2.0-workflow/s capacity). Repository-grounded replays are built from SWE-Review-Traj (51 of 100 audited trajectories request patch changes; 5 locally reproducible workloads, 18 replay configurations) preserving repo, patch, reviewer evidence, and tests while controlling revision timing. Baselines: full restart, earliest-conflict dynamic suffix (given the same provenance as REVISE, isolating recovery granularity as the only difference), and REVISE selective recovery. Metrics: correctness vs latest-version/full-restart oracle, model calls, tokens, model-wall time, recomputation, 25-s SLO goodput, p99 latency.

## Results & Highlights

- **Correctness at scale (RQ1):** Across 15,939 executions (Table 1: 171 online/integration + 288 LLMCompiler portfolio + 180 repository-grounded replay + 300 adversarial + 15,000 GPU serving pressure), every run matches the latest-version/full-restart oracle with **0 stale outputs and 0 stale committed effects**; all 800 validity-certificate checks complete in under 0.04 ms. The 300-run adversarial matrix covers both revision/commit orders, late reads, consecutive revisions, unknown provenance, membership changes, and route invalidation — obsolete attempts never publish while valid siblings remain reusable.
- **Recomputation avoided (RQ2):** On LangGraph, REVISE cuts model calls **56.0% vs full restart and 43.6% vs dynamic suffix** (model-wall time −62.7% and −50.2%); across 48 LLMCompiler workflows, calls fall **40.6% / 31.3%** and tokens 7.9% / 5.8%. Because the suffix baseline receives identical provenance, the gains are attributable to finer recovery granularity, not better dependency information. Notably, all 48 LLMCompiler workflows lacking fine-grained provenance fall back and recover equivalently to full restart.
- **Repository-grounded replay:** Across 18 replay configurations from SWE-Review-Traj, REVISE performs **12.94% less recomputation than the suffix baseline (95% CI 7.77–17.70%)** and discards **10.38% less completed work (95% CI 2.74–18.81%)**, with all 180 executions equivalent in final output, pytest, file/patch state, and visible effects.
- **Serving gains under contention (RQ3):** Across 15,000 workflows with 50 revised requests, REVISE reduces revision-to-completion tokens **13.26% (95% CI 12.86–13.67%)** and model-wall time **14.70% (95% CI 14.28–15.11%)** vs suffix; pooled SLO goodput improves **+2.79% (+1.29 to +4.40)** with p99 latency −6.45% (−10.11 to −3.05). Per-load: −0.12% goodput at 1.0× frozen capacity, **+43.07% at 1.1× boundary pressure**, +5.43% at 1.3× intentional overload.
- **Single-request latency barely moves:** LangGraph E2E p50 improves only 5.9% over suffix, and repository replay changes E2E by −0.5% (95% CI [−4.00, +3.84]) — the benefit is explicitly pressure-dependent, not critical-path shortening.
- **Motivating trace evidence:** Of 5,825 analyzable SWE-chat sessions, 657 contain a queued-revision signal and **118 retain observable work** when the later message is delivered; across 167 overlapping assistant responses, enqueued-to-completion overlap reaches **5.54 s median / 56.55 s p95 / 853.16 s max**, and 62 sessions expose an intervention window ≥10 s.

This is a preprint ("Preprint" footer, 8 pages incl. references) with no stated venue acceptance. The work reads as a serious systems effort: the design has a clearly stated system boundary (backend-independent planner; physical KV allocation explicitly out of scope), the evaluation reports confidence intervals, publishes unfavorable results (single-request E2E essentially unchanged; unprovable-provenance cases degrade to full restart), and grounds motivation in a real interaction dataset (SWE-chat) plus a reproducible replay harness (SWE-Review-Traj). The citation base is current (2024–2026 agent-serving and rollback literature: AIOS, SGLang, Agentix, PASTE, Leyline, DeltaBox, Crab, DART, TraceLab). Overall credibility: good for a preprint; the industrial-lab setting is consistent with the serving-systems focus, but the paper has not yet survived external review.

## Critical Assessment

**Novelty is real but framed generously.** The genuinely new piece is mapping an *external semantic revision* onto leaf-level validity decisions across node lifecycles of a partially executed DAG — prior systems either roll back to the earliest conflict (Revisable by Design), checkpoint/rewind (DART, PASTE, DeltaBox, Crab), or protect external effects (Atomix, Cordon) without deciding what in-flight work stays valid. The authors themselves acknowledge the mechanism descends from classical self-adjusting computation; the contribution is the transplantation to LLM agent DAGs with a fail-closed validity protocol, which is fair but incremental in mechanism.

**A numerical inconsistency undermines the serving headline.** The abstract claims SLO goodput improves by "3.07–5.43%", but Table 2 reports per-load changes of −0.12% (1.0×), **+43.07% (1.1×)**, +5.43% (1.3×) and a pooled +2.79%. The +43.07% figure is 10× the abstract's upper bound and looks like a decimal-point error (43.07 vs 3.07); neither the pooled +2.79% nor −0.12% falls inside the abstract's range either. Because the serving benefit is the paper's RQ3 punchline, this inconsistency needs correction before the goodput claim can be trusted, and per-load rows carry no confidence intervals.

**The headline savings are conditional on adapter depth.** The 40.6–56.0% call-reduction range holds only where fine-grained provenance is provable: the paper's own numbers show all 48 LLMCompiler workflows lacking fine-grained provenance fall back to full restart (zero gain), and the LangGraph integration required a custom recursive read-only proxy over framework state. Most current agent frameworks do not expose this instrumentation, so out-of-the-box gains for a practitioner would likely sit at the bottom of the reported range.

**The motivation audit is small and admittedly non-prevalence.** The locality claim rests on 30 manually audited events (20 revisions) from SWE-chat, explicitly "intended for taxonomy construction, not prevalence estimation"; SWE-chat traces lack artifact versions, so the 6 independent-branch (L2) cases could only be treated as candidates for selective reuse, not evidence. The 118-session opportunity count comes from a single coding-agent dataset and says nothing about revision locality in browsing, data-analysis, or long-horizon agents.

**Baseline set is narrow for a systems paper.** The only recovery baselines are full restart and dynamic suffix (both coarse policies). None of the cited competing fine-grained systems (DART, stepwise/WebRollback, PASTE, DeltaBox) are run head-to-head, so the claim that fine-grained validity-guided recovery beats the best existing alternative is only indirectly supported via the suffix proxy.

**Scope caveats.** Single model (Qwen3-14B), one serving stack (SGLang on H100), five repository workloads from 100 audited trajectories, and individual-request latency essentially unchanged (−0.5%, CI [−4.00, +3.84]) mean the practical payoff is confined to multi-tenant contention scenarios. Irreversible tool effects are "staged or blocked," but how this composes with real side-effecting tools in production is untested.

## Strengths

- **Fail-closed correctness with scale evidence:** 15,939 executions oracle-equal with zero stale outputs or committed effects, including a 300-case adversarial matrix specifically targeting the race conditions (late reads, revision/commit orderings, consecutive revisions) that a revision-time-only design would get wrong; commit-time certificates make the safety argument airtight rather than heuristic.
- **Fair baseline engineering:** the dynamic-suffix baseline receives the same provenance as REVISE, cleanly isolating recovery granularity as the source of the 31.3–43.6% call savings — a control many systems papers skip.
- **Honest reporting:** confidence intervals on replay and serving deltas, explicit disclosure that single-request E2E is unchanged, that 48/48 unprovable-provenance workflows degrade to full restart, and that the trace audit is for taxonomy, not prevalence.
- **Real-data motivation:** the intervention-window analysis (118 sessions, 56.55 s p95 overlap) is measured on real user–agent interactions rather than synthesized revision schedules, and the repository replay preserves actual repo/patch/test state.
- **Principled degradation ladder:** complete provenance → subgraph; coarse → suffix; none → restart, with irreversible effects staged — the semantics degrade predictably instead of silently reusing stale state.

## Limitations

- **Integration cost is the gating factor:** without adapters exposing workflow topology, lifecycle events, and fine-grained reads (the recursive read-only proxy), REVISE collapses to full restart — the paper demonstrates this on 48 LLMCompiler workflows but offers no path to automatic adapter generation for arbitrary frameworks.
- **Narrow empirical base:** one model (Qwen3-14B), one serving stack, five repository workloads and 48 LLMCompiler workflows; no comparison against cited fine-grained recovery systems (DART, PASTE, DeltaBox), only restart/suffix proxies.
- **Serving-numbers hygiene:** the abstract's goodput range (3.07–5.43%) is inconsistent with Table 2 (−0.12% / +43.07% / +5.43%, pooled +2.79%); per-load rows lack CIs.
- **Benefit is contention-only:** with E2E p50 changes of +5.9% (LangGraph) and −0.5% CI [−4.00, +3.84] (replay), single-user agent sessions gain little; the value proposition requires multi-tenant pressure.
- **Motivation generality unproven:** the locality taxonomy derives from 20 audited revisions in one coding-agent corpus; no evidence on revision frequency/locality in other agent domains.
- **Physical effects out of scope:** KV allocation and cross-GPU reuse are excluded, and irreversible external tool effects are only staged/blocked, not managed end-to-end.

## Relevance

这篇工作属于长时运行自主 agent 系统的可靠性方向（用户最高优先级领域）：它用形式化的有效性/溯源语义保证用户修订到达后工作流输出的"最新版正确性"，其 fail-closed 恢复协议、证据分级回退和 commit 时重验证机制对构建可信 agent 基础设施有直接参考价值。服务压力下的 goodput 分析也与用户对推理可靠性与大规模 ML 计算基础设施的关注部分重叠。

## Questions for Further Exploration

1. Is the +43.07% goodput at 1.1× boundary pressure (Table 2) real or a decimal-point typo relative to the abstract's 3.07–5.43% range — and what does the true per-load goodput curve look like with confidence intervals?
2. Can provenance adapters (the recursive read-only proxy and structural diff) be auto-generated for arbitrary agent frameworks, given that all 48 unprovable-provenance LLMCompiler workflows degenerated to full restart?
3. How does validity-guided recovery compose with KV-cache management (e.g., Leyline-style cache directives), which the paper explicitly excludes from its system boundary?
4. Does the 20-revision locality taxonomy hold in non-coding agent domains (browsing, data analysis, long-horizon research), where revision semantics and artifact granularity differ?
5. What happens to staged irreversible tool effects under adversarial revision timing in production — does the block-until-check semantics remain practical when tools cannot be staged (emails, payments)?
