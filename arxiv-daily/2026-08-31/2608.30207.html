Why this matters

A clean working example of failure-driven self-improvement — and hard evidence that static evaluations wildly overstate how robust frontier agents actually are.

Critical edge

Statistical power is thin: with 50 Bernoulli trials, no confidence intervals and no seeds, fine-grained deltas like 24% vs 28% sit well within noise.

01Methodology

  • Threat model. 50 RedTeamCIA tasks on an OSWorld-style Ubuntu VM: each pairs a benign instruction with an adversarial goal hidden in a forum post the agent will read. Success = both tasks complete, checked programmatically — no LLM judge.
  • Inner loop — compositional search. Three attacker-LLM calls (seed → compose → refine) weave 2–4 of 11 hand-written principles (7 content + 4 delivery: Authority Embedding, Side-Effect Masking, Visual Blending…) into a task-specific injection; a filter strips banned urgency markers.
  • Outer loop — failure-driven discovery. Failed runs become ~650-token digests, batch-diagnosed by the defense that blocked them (source trust, target sensitivity, imperative detection…), distilled into named strategies (ErrorCorroboration, ConditionalDeferredExecution), and fed back into the refine prompt.
  • No fine-tuning anywhere. The whole strategy library lives as natural language inside prompts; budget is 10 rounds with early stopping. Victims: Claude Opus 4.6 / 4.8, Gemini 3.5 Flash; attacker Grok-4.3 at ~$0.02 per injection.

Attack success rate on 50 RedTeamCIA cases each; joint (benign + adversarial) success.

  • Clean attribution. Three-way ablation: compositional search alone adds +6 to +18 pts; the feedback loop adds +14 to +20 pts — and matters most exactly where static defense is strongest (Gemini +20).
  • Transfer, not memorization. P9 ErrorCorroboration, discovered only from Opus 4.6 failures, lifts Gemini 8%→18% and Opus 4.8 10%→16% with zero further feedback.
  • Generation gap. The identical pipeline scores 54% on Opus 4.6 but 24% on Opus 4.8; permission tampering falls from 50% to 0% — the newer Claude specifically hardened it.
  • Category gradient. Service disruption is easiest (up to 100%, though n=4); data exfiltration is hardest on every model (20% / 10% / 10%).

Strengths

  • Deterministic oracle is the right call. Programmatic filesystem/service/permission checks replace a manipulable LLM judge and make “joint success” crisp and reproducible.
  • Clean component attribution — the three-way ablation separates the value of composition from the value of failure-driven discovery.
  • The transfer experiment answers the right question: frozen principles beating unseen models shows the loop learns reusable attack principles, and the P9/P10 asymmetry is explained mechanistically.
  • Unusual candor: low-n categories flagged as uninterpretable, costs reported, dual-use named as a limitation.
  • Actionable for defenders: per-category and per-composition analyses map exactly which failure modes an adaptive adversary exploits.

Limitations

  • Small, single-benchmark evaluation: 50 cases, three categories with n≤4, no variance estimates or significance testing anywhere.
  • No adaptive baselines run: EVA, MUZZLE and AgentVigil are discussed but never compared, so the margin over other adaptive attacks is unknown.
  • Single attacker model (Grok-4.3), no attacker-model ablation; rounds actually consumed per victim are unreported.
  • Snapshot science: proprietary victims drift — 54% on Opus 4.6 may not reproduce weeks later.
  • Expensive: ~$150–250 per feedback round on Claude victims limits replication.
  • Stack-tied strategies: the flagship exploit leans on a Node.js 12 quirk of this VM; catalog generality beyond the stack is unquantified, and the appendix reads as a bypass cookbook.

03Questions for Further Exploration

01Do the same principles win against open-weight CUAs (UI-TARS, OpenCUA) where defense internals can be inspected?
02Would an adaptive defense that rotates its refusal heuristics re-close the gap — is 54/24/28 a static-defense-only property?
03Can failure-driven distillation flip from attack to benign reliability mining of failed agent trajectories?
04What fraction of the discovered strategy catalog is stack-specific (Node 12 / Postmill / Chrome) versus architecture-generic?
05Does joint success degrade the user’s benign-task quality — and is it genuinely harder to prevent than pure hijacking?
06Are the fine-grained findings (Gemini’s P4 preference, P9>P10 transfer) stable under bootstrap resampling?
