Why This Matters

Attacks the three failure modes that make self-evolving agents unreliable — credit assignment, shortcut learning, catastrophic forgetting — with one engineered mechanism each.

Critical Edge

The headline gain rests on proprietary, unreleased data; on public benchmarks wins shrink to +1.8–2.9 pts, and baselines searched strictly smaller action spaces.

一句话总结华为提出 HarnessEvolve：用带标准答案生成的"参考轨迹"定位首个分歧点解决 credit assignment，用质量门 + 性能门遏制走捷径与灾难性遗忘，在 CloudCoreNetwork-QA 上把准确率从 43.4% 提到 86.9%。

01 Methodology — distilled

Self-evolution is decoupled into four isolated agents so no component grades its own homework:

  • Execution agent runs tasks, and before optimization re-runs every training task with the ground-truth answer supplied (≤5 attempts) to produce verified "reference trajectories".
  • Evaluation agent checks accuracy and verifies references are genuine execution paths — not answer-copying shortcuts — before they enter the global cache.
  • Optimization agent diffs each failed trajectory against its reference to localize the first action divergence point as root cause, then clusters errors by cause (long-tail preserved, no fixed-K clustering).
  • Gate agent (isolated): a quality gate rejects data leakage (LLM-judge η=0.8) and prompt bloat (>5 injected examples); a performance gate accepts updates only if the current batch improves and none of the last 2 batches degrades >0.025.
  • Epoch-end selection picks the best snapshot on validation — final harness is never worse than the epoch's best.
  • Unlike GEPA (prompt-only) or SkillOpt (skill.md-only), it edits the whole harness: skills, scripts, prompts, tool specs, execution logic.

Strengths

  • One mechanism per named failure mode — credit assignment, shortcuts, forgetting — not a generic "optimize the prompt" loop.
  • Verified reference trajectories are a clean operationalization of counterfactual debugging; the −29.1 pt ablation confirms they're the load-bearing part.
  • Dual gates + epoch-end snapshot selection give a monotonicity guarantee most self-evolving systems lack.
  • Cross-framework transfer (4 frameworks, never below Base) shows learned edits encode general error patterns, not framework hacks.
  • Honest ablation granularity — each mechanism removed individually, and every removal hurts.

Limitations

  • The headline benchmark is proprietary; no code or data release, so the pipeline isn't externally reproducible.
  • No search-space-equalized comparison — part of the gain may come from the larger action space, not the mechanisms.
  • Single runs, no variance or significance tests; 1.8–2.9 pt public margins sit within plausible run-to-run noise.
  • The LLM-as-judge leakage gate is unvalidated; gate precision is never quantified.
  • No compute-cost accounting for the 4-agent, 20-epoch loop; verified-reference coverage undisclosed.

03 Questions for Further Exploration

  1. How much of the gain survives when HarnessEvolve is restricted to SkillOpt's skill.md-only search space — mechanism vs. action-space size?
  2. What are the precision/recall of the LLM-as-judge leakage gate, and how many good updates does it falsely reject?
  3. Can reference trajectories be generated without ground-truth answers (self-consistency, verifier models) to reach open-ended tasks?
  4. What fraction of tasks obtain a verified reference within 5 attempts, and how does performance degrade as that fraction falls?
  5. Would the same gains appear with a general-purpose model instead of the domain-fine-tuned Qwen3.6-27B executor?
  6. What is the end-to-end compute cost per point of accuracy gained, relative to GEPA / ACE / SkillOpt?
