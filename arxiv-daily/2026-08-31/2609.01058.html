01 Methodology — distilled

Two roles co-evolve through rubrics; a reward-gated self-distillation sharpens them locally:

  • Generator authors tool-grounded open-ended queries plus judging rubrics. Its reward is a product of three gates: real tool output must exist (R_tool), format must parse (R_fmt), and difficulty bonus R_diff peaks when ~half of K=8 rollouts succeed — pinning tasks to the Solver's capability frontier to fight advantage collapse.
  • Solver attempts queries via multi-step reasoning and tool use (≤40 tool rounds); an LLM judge (gpt-5.2) scores each rubric item, giving partial credit (α=0.8) plus a completion bonus.
  • RG-SED: a coach LLM distills group feedback into role-conditioned memory; the same policy under that memory acts as a transient teacher. Token-level reverse-KL distillation activates only when memory-augmented rollouts empirically beat standard ones (Δr > 0.05) — no blind imitation of noisy guidance.
  • ECR-Bench contribution: 100 expert-calibrated deep-research queries + 500 multi-tool travel-planning queries (5 sub-tasks, 7 tools), bilingual expert-written rubrics.
  • Training: 32 H20 GPUs, G=16 rollouts, 3 co-evolution cycles with the query pool refreshed every 120 steps; code released (github.com/Alibaba-NLP/qqr).

Strengths

  • Closes the loop: task generation, rubric construction, solving, and policy optimization are co-optimized — no static human-authored training queries.
  • The ~50%-success difficulty target is a principled, measurable answer to advantage collapse, with frozen-policy pass rates confirming the curriculum.
  • RG-SED is a well-motivated middle ground: same-policy teacher bounds distribution gap by construction; an empirical gate decides when to distill.
  • All baselines re-run under the identical judge and tool stack; prompts, hyperparameters, and code released.
  • Consistent gains across two backbones (8B, 9B); ablations show components are complementary, not redundant.

Limitations

  • Validated only on 8/9B backbones; larger-model scalability explicitly left unverified.
  • Heavy closed infrastructure: gpt-5.2 for all judging/coaching, Qwen3.5-397B user simulator, GPT-5-mini-simulated flight/train tools.
  • Single training run per backbone, no std anywhere; only 3 co-evolution cycles, so long-run stability is unknown.
  • ECR-Travel is Chinese-language-centric and partially simulated; the ECR-DR judge is instructed not to fact-check against tool returns.
  • RG-SED's coach-call overhead unquantified; coach memory degrades (the rollout-80–90 dip), which the gate retracts but never fixes.

03 Questions for Further Exploration

  1. Does the ~50%-success difficulty target remain optimal beyond 3 cycles, or does the loop plateau or diverge?
  2. How large is the judge-family effect — would an open-source judge or human-judged subset preserve the multi-tool gains, especially on self-built ECR-Bench?
  3. Can rubric-mediated rewards extend to domains without tool-verifiable facts, given the ECR-DR judge's explicit no-verification instruction?
  4. What is the full cost accounting of RG-SED relative to the 32-GPU budget, and does the gate stay calibrated when coach memory degrades?
  5. Would a hybrid of the gated same-policy teacher with a fixed external teacher win at larger scale — and does the 28% non-beneficial group fraction grow or shrink?
