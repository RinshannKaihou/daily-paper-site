> **一句话总结：** 提出 AutoSciRub：让自主科研智能体在执行前先自动"归纳"出一份可执行的任务专属评审量表（rubric）——通过量表骨架归纳、科学文献接地、任务数据探查和准则综合四步，把隐含的成功条件显式化——执行后再按准则逐一验证并针对性修订；在 ResearchClawBench 上跨 3 个骨干 LLM 平均 +2.08 分、跨 3 个智能体框架平均 +2.95 分，在 AstaBench 20 任务子集上平均 +16.78 分，且量表引导修订的收益（+2.05）约为无量表自由重写（+0.77）的 2.7 倍。

> **TL;DR:** AutoSciRub is an evaluator-first framework for autonomous research agents: before execution it induces a task-specific, executable scientific rubric from the instruction (via rubric-skeleton induction, literature grounding over arXiv/OpenAlex/Semantic Scholar, task-data exploration, and criterion synthesis), then uses it during execution for criterion-level verification and targeted revision of the report and supporting artifacts. On ResearchClawBench it improves the mean rubric score by +2.08 points averaged over three backbone LLMs under a fixed Codex harness (e.g., GLM-5.2 20.86 → 22.73) and +2.95 points over three agent harnesses with a fixed DeepSeek-V4-Flash backbone (OpenClaw 17.25 → 20.36), and on a 20-task AstaBench End-to-End Scientific Discovery subset it gains +16.78 points on average (Claude Code +19.36 vs. the vanilla baseline). A stage-wise ablation attributes the largest single gain (+2.05) to rubric-guided iterative revision, which outperforms rubric-free self-refinement roughly 2.7x (+2.05 vs +0.77 over the same checkpoint).

## 核心贡献

- **"先学会评估，再谈改进"的框架 AutoSciRub**：将开放式科研任务中隐含的分析、方法与成功标准，在智能体执行**之前**转化为显式的任务专属可执行量表，而不是像现有基准那样把 rubric 仅用于事后打分。
- **两阶段设计**：(1) *Automatic Rubric Induction*——量表骨架归纳（把指令分解为原子科学目标）→ 科学文献接地（web 检索 arXiv/OpenAlex/Semantic Scholar，保留 5–7 篇核心文献并按科学主题组织方法/协议/指标）→ 任务数据探查（轻量级盘点任务可见数据的文件、字段、单位与可行性约束）→ 准则综合（合成 M 条可执行准则，每条关联科学目标、所需实验/分析/指标与预期证据产物）；(2) *Rubric-Guided Iterative Revision*——初始产出后逐准则验证（满足/不满足 + 证据缺口），针对性修订（补实验、补对比、删无证据结论），最多 3 轮并自适应提前停止。
- **广泛的对照实验**：在 ResearchClawBench 全部 40 任务上做了 6 组"同指令、同数据、同工具、同框架"的配对比较（3 骨干 × Codex + 3 框架 × DeepSeek-V4-Flash），并在 AstaBench 20 任务子集上做了 3 组跨配置迁移验证；平均分别 +2.08 / +2.95 / +16.78 分。
- **机制分析**：量表质量四维评估显示可执行量表把 Specificity 从 1.65 提到 4.40、Evidence Verifiability 从 1.78 提到 4.08，但 Scientific Core Coverage 略降（3.55→3.07）；量表引导修订的累计收益约为无量表自由重写的 2.7 倍，且收益分布广泛（40 任务中 34 个改善，36/40 的改进来自初始报告，而非个别高分案例）。

## Key Contributions

- **AutoSciRub**, an evaluator-first framework that induces an *instruction-derived rubric skeleton* and a *task-specific executable rubric* **before** the agent executes an open-ended research task, making implicit analysis, evidence, and success conditions explicit guidance rather than post-hoc scoring instruments.
- **A two-stage method**: (1) Automatic Rubric Induction via four steps — Rubric Skeleton Induction (decompose the instruction into atomic, traceable scientific goals), Scientific Literature Grounding (broad retrieval over arXiv/OpenAlex/Semantic Scholar, full-text filtering, retain 5–7 core papers summarized by scientific theme), Task-Data Exploration (lightweight profiling of task-visible files, fields, units, and feasibility constraints), and Criterion Synthesis (M executable criteria, each linking goals to required experiments, analyses, metrics, and expected evidence artifacts); (2) Rubric-Guided Iterative Revision — per-criterion verification (satisfied 0/1 + evidence gap diagnosis) followed by targeted revision (add missing experiments/comparisons/artifacts, strengthen analysis, remove unsupported claims), capped at 3 rounds with adaptive early stopping.
- **Controlled paired evaluation** on all 40 ResearchClawBench tasks across six model–harness configurations (GPT-5.4/GLM-5.2/MiniMax-M3 under Codex; Claude Code/OpenClaw/OpenScience under DeepSeek-V4-Flash) plus three transfer configurations on a 20-task AstaBench subset — identical task inputs, data, workspace, and tools within each pair; +2.08/+2.95/+16.78 average gains respectively.
- **Mechanistic analysis**: a four-dimension rubric-quality study (MiniMax-M3 judge, 1–5 scale) showing executable rubrics raise Specificity 1.65→4.40 and Evidence Verifiability 1.78→4.08 while Scientific Core Coverage slightly *decreases* (3.55→3.07); and a controlled comparison showing rubric-guided revision yields ~2.7x the cumulative gain of rubric-free self-refinement (+2.05 vs +0.77 from the same checkpoint), with broad rather than outlier-driven improvements (34 of 40 tasks improve; 36 of 40 gains come from the initial report stage).

## Methodology

**Task formulation.** A research task τ_i = (x_i, E_i) pairs a high-level instruction x_i with the task-visible environment E_i (literature, data, search, code execution, domain tools). The agent π produces an artifact A*_i = π(x_i, E_i) = (r_i, S_i) — a report plus supporting code/results/tables/figures. The true specification T*_i = (G*_i, C*_i) (scientific goals + evidence requirements) is latent and unspecified; artifact quality is q*_i = Eval(A*_i, T*_i). The thesis: a reliable agent should *learn to evaluate before improving*, i.e., use rubrics as *intermediate scientific specifications*, not post-hoc grade sheets.

**Stage I — Automatic Rubric Induction.** Four steps turn the underspecified instruction into an executable rubric R_i:
1. *Rubric Skeleton Induction*: the agent observes only x_i and decomposes it into K_i atomic scientific goals G_i = {(n_i,k, s_i,k)} — each goal traceable to the instruction, covering its main requirements, without overlap or method/baseline prescriptions (the skeleton defines *what* should be addressed; later steps define *how* each goal is established).
2. *Scientific Literature Grounding*: for every goal, the agent forms broad retrieval queries (avoiding long instruction spans, task IDs, and filenames), ranks candidates by relevance to the induced goals, uses full-text access for top candidates, and applies a hidden-paper blocklist maintained by the evaluation harness plus an unusable-list for items unavailable to the induction agent; 5–7 core papers are retained and summarized as K_i,k = Φ_lit(i, E_i, Ẽ_k), organized by scientific theme (methods, protocols, typical analyses, metrics, baselines, controls, ablations, robustness checks) rather than as experimental evidence for the current task.
3. *Task-Data Exploration*: a lightweight inspection P_i = Φ_data(E_i) records available files/datasets, formats, dimensions, key fields, units, labels, experimental conditions, cross-source relations, and relevance constraints — used *only for planning* (which data sources support which goals, which literature-suggested analyses are feasible), with no assumption of unavailable labels/conditions.
4. *Criterion Synthesis*: Φ_syn combines skeleton, literature-grounded knowledge, and data profile into M_i criteria R_i = {p_j}; each criterion links one or more goals and specifies relevant sources, required experiments/analyses, evaluation metrics, expected evidence artifacts, and its satisfaction condition — aligning established scientific practice with the evidence actually producible from task-visible resources.

**Stage II — Rubric-Guided Iterative Revision.** The rubric is given to the backbone agent as execution-time specification. After the initial artifact A^(0), at revision round t a verifier computes z_j^(t), d_j^(t) = Verify(p_j, A^(t)) ∈ {0,1} × evidence gaps per criterion — checking required experiments, reported results, supporting artifacts, and whether conclusions are adequately supported (criterion-level diagnosis, not a holistic score). The agent then revises: A^(t+1) = π_rev(A^(t), Δ^(t), E_i, R_i), possibly adding experiments/comparisons/artifacts, strengthening analysis, or removing unsupported claims. The loop stops when all criteria are satisfied or the revision budget (max 3 rounds, adaptive early stopping when the verifier already passes) is reached.

**Evaluation protocol.** Paired vanilla vs. +AutoSciRub configurations share the same harness, backbone, instruction, task-visible data, workspace, and tools; each task configuration is executed once, and each submission is scored three times by the official benchmark evaluator (GPT-5.1 for ResearchClawBench; MiniMax-M3 for AstaBench's task-specific rubrics over report, code, and supporting artifacts), with the mean of three judge scores as the task score. Overall = mean over all 40 (RCB) or 20 (AstaBench) tasks; reported improvements are absolute paired differences. Rubric quality is judged separately by MiniMax-M3 with four standalone single-dimension prompts (Specificity, Actionability, Evidence Verifiability, Scientific Core Coverage; 1–5 ordinal, unweighted mean), where the benchmark checklist is visible only to the judge, never to the agent. No shared cap on tokens, tool calls, wall-clock runtime, or cost is imposed across heterogeneous harnesses — the stated focus is output quality rather than budget-normalized efficiency.

## Results & Highlights

- **ResearchClawBench, cross-model (fixed Codex harness, all 40 tasks):** AutoSciRub gains +2.38 points for GPT-5.4 (18.66 → 21.04), +1.87 for GLM-5.2 (20.86 → 22.73, the highest overall score of all configurations), and +1.99 for MiniMax-M3 (19.65 → 21.64) — an average of **+2.08** points, consistent across model families.
- **ResearchClawBench, cross-harness (fixed DeepSeek-V4-Flash backbone):** +2.14 for Claude Code (16.60 → 18.74), +3.11 for OpenClaw (17.25 → 20.36), +3.60 for OpenScience (14.49 → 18.09) — average **+2.95**; larger open-source harnesses (OpenClaw, OpenScience) benefit more. At the domain level, **49 of 60 paired comparisons improve**, with consistent gains in chemistry, energy science, and neuroscience across all six configurations; some degradations appear in information science and mathematics (e.g., MiniMax-M3 astronomy drops 28.01 → 27.10).
- **AstaBench End-to-End Scientific Discovery (fixed 20-task Easy subset, seed 20260707):** gains of +19.36 for Claude Code, +12.61 for Codex, and +18.38 for OpenClaw — average **+16.78** points. Claude Code and Codex raise successful-task counts from 18/20 to 20/20; OpenClaw completes 19/20 under both settings but gains +18.38 in output quality.
- **Stage-wise ablation (OpenClaw + DeepSeek-V4-Flash, 40 tasks, Table 2):** Base 17.25 → +Skeleton 17.61 (+0.36) → +Grounded rubric 18.31 (+1.06 over base) → Full 20.36 (**+3.11 over base**); Rubric-Guided Iterative Revision contributes the largest increment (+2.05 over the grounded-rubric setting), showing the rubric matters most when used to identify unmet criteria and drive targeted revision, not just to guide execution.
- **Rubric quality (MiniMax-M3 judge, 1–5):** mean across four dimensions rises 2.60 → 3.84 from skeleton to executable rubric; Specificity 1.65 → 4.40 (+2.75), Evidence Verifiability 1.78 → 4.08 (+2.30), Actionability 2.00 → 3.83 (+1.83) — but Scientific Core Coverage slightly *decreases* 3.55 → 3.07 (−0.48). Scientific core coverage remains positively associated with downstream report quality for both variants (ρ = 0.63 skeleton, ρ = 0.55 executable), and executable rubrics beat skeletons by a mean report-score gain of 0.70 across 40 tasks (improving 34).
- **Rubric-guided revision vs. rubric-free self-refinement (Table 3, from the shared checkpoint at 18.31):** three rounds of rubric-free "just improve your report" refinement reach only 19.00 (+0.77 cumulative, with a regression of −0.21 at checkpoint 2), while rubric-guided revision climbs monotonically 19.47 (+1.16) → 20.08 (+1.77) → 20.36 (**+2.05**) — roughly **2.7x** the gain. After round 1, 23 of 40 tasks already pass the verifier; the 17 (then 6) still-failing tasks still gain +1.43 and +1.89 per additional round, and 35 of 40 tasks pass within three revisions. Domain-level mean improvements concentrate in Mathematics (+4.12), Earth science (+3.73), and Information science (+3.32).

The work evaluates against two external, community benchmarks (ResearchClawBench, from the ResearchClawBench team; AstaBench, from the Allen Institute/CoRR ecosystem) rather than a self-built testbed, which strengthens external validity, and the code is released at https://github.com/zjunlp/AutoSciRub. The author list is entirely from Chinese academic institutions; no industry lab affiliation is claimed. Given the zjunlp group's track record in agent frameworks, the engineering execution appears competent, though the method itself is a training-free orchestration pipeline whose credibility rests mainly on the breadth and honesty of the evaluation rather than on algorithmic depth.

## Critical Assessment

- **Novelty is framing-and-system, not algorithm.** Rubric generation for LLM evaluation is a crowded space (the paper itself cites RubricRAG, AdaRubric, RubricRAG-style retrieval methods, DEEPRUBRIC, ThinkRubric, RubricReframe, etc.). The genuinely new elements are (a) using induced rubrics *before and during* agent execution as intermediate scientific specifications rather than post-hoc graders, and (b) grounding them in literature + task-visible data. The induction pipeline itself is standard prompt-orchestrated tool use (search, summarize, synthesize) with no learned component, no fine-tuning, and no principled criterion-selection objective — a replication with different prompts would likely work similarly.
- **No cost or compute accounting is a real weakness.** Appendix A.1 explicitly states "We do not impose a shared explicit cap on tokens, tool calls, wall-clock runtime, or monetary cost across heterogeneous agent harnesses." AutoSciRub adds literature retrieval, rubric induction, per-criterion verification, and up to 3 revision rounds — a substantial number of extra LLM calls and tool executions per task. Since the paired baselines get no equivalent extra compute, part of the +2.08/+2.95/+16.78 could be compute-per-task effects, and the paper cannot quantify how much. A token-matched or budget-matched baseline (e.g., vanilla + 3 self-refinement rounds is included and only partially addresses this) is missing.
- **LLM-judge dependence, with a same-family judge.** ResearchClawBench scoring uses GPT-5.1 as the evaluator while GPT-5.4 is one of the improved backbones under the same harness — a same-vendor-family judge could plausibly favor outputs whose structure it recognizes (both vanilla and +AutoSciRub are judged identically, so paired deltas are partially protected, but rubric-style explicit evidence artifacts are exactly what a rubric-following judge rewards). AstaBench's MiniMax-M3 evaluator is the same model family used as a backbone in the cross-model panel (though judged configurations differ). The rubric-quality judge is also a single model (MiniMax-M3) with no human agreement study.
- **Single execution per configuration, no significance testing.** Each paired configuration is executed *once*, then judged three times; the three-judge mean controls judge noise but not agent-execution stochasticity (long-horizon agent runs have high variance), and no error bars, confidence intervals, or significance tests are reported anywhere. The AstaBench subset is only 20 tasks sampled once with one seed (20260707), and AstaBench scores run near 67–87 where the deltas (+12.6 to +19.4) are suspiciously large relative to the +2 to +3 deltas on the same agents over 40 RCB tasks — the evaluator and protocol change, and the paper does not explain the discrepancy.
- **Honest negative signals are reported, which is commendable:** Scientific Core Coverage *drops* 3.55 → 3.07 after grounding/synthesis (the rubric operationalizes verifiable but possibly secondary criteria; high-level scientific framing is left to the backbone model); domain-level degradations occur (e.g., MiniMax-M3 astronomy 28.01 → 27.10 and materials 23.31 → 20.86); and absolute performance remains far from target-paper-level re-discovery (best overall 22.73 on RCB's 0–100 scale where ~50 is intended to represent re-discovery of the hidden target paper) — so AutoSciRub improves weak outputs but does not close the gap to real scientific competence.
- **Reproducibility is plausible but constrained:** code is released, benchmarks are external, but the evaluation depends on proprietary frontier models (GPT-5.4, GPT-5.1, GLM-5.2, MiniMax-M3, DeepSeek-V4-Flash), web-search services, and single-run protocols, so exact-number replication is unlikely; the GitHub release will need to document prompts and the hidden-paper blocklist mechanism for independent verification.

## Strengths

- **Correct and well-motivated thesis**: rubrics as *intermediate scientific specifications* guiding execution, verification, and revision — a genuinely useful reframing for open-ended research agents whose instructions under-specify success conditions.
- **Controlled paired design**: within each comparison, task inputs, data, workspace, tools, harness, and backbone are held fixed, isolating the rubric effect; cross-model (3 backbones) and cross-harness (3 harnesses) panels plus a third benchmark (AstaBench) demonstrate the gains are not idiosyncratic to one configuration.
- **Informative stage-wise ablation**: skeleton (+0.36) → grounding (+0.70 more) → revision (+2.05 more) cleanly decomposes where the value comes from, and the rubric-free self-refinement control (same checkpoint, same budget, +0.77 vs +2.05) directly supports the "evaluate before improving" claim rather than a generic "more iteration helps" explanation.
- **Mechanistic rubric-quality analysis** with four operationalized dimensions and single-construct judge prompts, including an honest report of the Scientific Core Coverage regression and its interpretation.
- **Distribution-level evidence**: 49/60 domain-level paired improvements, 34/40 tasks improved by executable rubrics, 35/40 tasks passing within 3 revisions, and a per-round gain breakdown (+1.16/+0.61/+0.28) supporting adaptive early stopping as a sensible cost lever.

## Limitations

- **No compute/cost normalization**: extra induction, verification, and revision calls are unaccounted for, so quality gains cannot be separated from added compute; wall-clock and monetary overhead of AutoSciRub are never reported.
- **Single run per configuration and no statistical testing**: long-horizon agent variance is uncaptured; the 20-task AstaBench subset (one seed) and the unexplained +16.78 vs +2.08 delta across benchmarks weaken precision of the headline claims.
- **LLM-judge-mediated evaluation throughout** (GPT-5.1 for RCB — same family as a backbone; MiniMax-M3 as both AstaBench evaluator and rubric-quality judge), with no human-annotated agreement check and a plausible structural bias toward rubric-conformant evidence artifacts.
- **Scientific Core Coverage regression (3.55 → 3.07)**: grounding and synthesis make rubrics more executable and verifiable but slightly less faithful to the scientific core; the paper diagnoses but does not fix this.
- **Absolute capability remains low**: best mean 22.73/100 on ResearchClawBench vs ~50 for target-paper-level re-discovery; the method improves badly-specified outputs rather than approaching real autonomous science, and domain degradations (info. science, math., some MiniMax-M3 domains) show the rubric can misdirect when grounding quality is poor.
- **Frontier-model dependence**: all backbones, the judges, and the verifiers are proprietary 2025–2026 models; no open-weights-only configuration is reported, limiting reproducibility and cost estimates.

## Relevance

这篇论文正中你的最高优先级方向「Self-Evolving Agents & Automated Research / Agentic Scientific Discovery」：它解决的是自主科研智能体最核心的可靠性问题——开放式任务成功标准不可见导致"看起来像报告但缺证据"——并提出"先学会评估再改进"的量表引导执行-验证-修订闭环，可作为自进化科研智能体（AI Scientist、ResearchClaw 类系统）的一个即插即用质量控制层。对你的「长时自主智能体系统可信性」关注点同样有价值：论文中关于 LLM-judge 依赖、无算力对账、以及量表提升可验证性却轻微牺牲科学核心覆盖率的发现，是评估这类系统的典型陷阱样本。

## Questions for Further Exploration

- How much of the +2.08/+2.95/+16.78 improvement survives under a **token- or dollar-matched budget** where the vanilla baseline receives an equivalent number of extra LLM calls and tool executions (e.g., budget-matched self-refinement or best-of-N sampling)?
- Would an **open-weights backbone** (e.g., DeepSeek-V4-Flash alone as both inducer and executor) close the loop without proprietary judges — and does the Scientific Core Coverage regression (3.55 → 3.07) persist or worsen when the grounding literature is retrieved by a weaker model?
- Can criterion-level verification signals be turned into a **training reward** (e.g., process-reward data for RL on research agents) rather than only inference-time guidance — the paper's framework produces per-criterion 0/1 + evidence-gap annotations that look like natural process supervision?
- Why is the AstaBench gain (+16.78 average) roughly 6x the ResearchClawBench gain (+2.08/+2.95) for the same agents — evaluator difference (MiniMax-M3 vs GPT-5.1), task-difficulty difference, or rubric-protocol sensitivity? A judge-swap ablation would settle it.
- Does inducing the rubric **once per task family** (amortized across similar tasks) retain most of the benefit, and can failed criteria across tasks be mined into a reusable, domain-level scientific-requirements library for self-evolving agents?
