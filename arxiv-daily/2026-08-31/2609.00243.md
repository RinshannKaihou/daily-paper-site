> **一句话总结：** 提出"失效契约（invalidation contract）"协议层——给每条 API 恢复建议附加 cacheability 提示与版本戳，并在 schema 重载时附带结构化 diff，把跨 episode 记忆收益分解为 `realized savings = validity × compliance`：在 2 个自建 API 域、7 个模型、3 条服务路径、约 9,400 episodes 上版本戳校验逐字节一致且零契约失效，行级失效（A2D）把 5/7 模型的首试合规率较无失效记忆（A1）提升 0–66.7 个百分点（gpt-5-mini 33.3%→100%），在 4/7 模型上收回 29–33% 的基线 token 开销，代价是响应负载增加 15%。

> **TL;DR:** LLM agents that cache recovery suggestions from API errors save tokens across episodes until server reference data drifts, turning cached fixes into silent failures. The paper introduces the invalidation contract, a protocol layer that attaches a cachability hint and version stamps to every suggestion plus a structured diff on schema reload, and decomposes savings into validity (protocol-controlled) × compliance (model-controlled). On two synthetic API domains (~9,400 episodes, 250 arm-level runs, seven models, three serving paths), row-level invalidation (A2D) lifts first-try compliance over memory-without-invalidation (A1) by +66.7 points on gpt-5-mini (33.3%→100.0%), +63.0 on claude-sonnet-4-6, and +55.6 on claude-haiku-4-5, recovering 29–33% of baseline token cost on four of seven models — whereas table-level invalidation collapses post-drift first-try rates from 66.7% to 0% on five of seven models, with eviction precision 0.25 at table vs 1.00 at row granularity. Compliance, however, is a model property: the newest model, Claude Sonnet 5, refuses add-a-field fixes (10% first-try) due to input-schema conservatism, and the wire cost is 15% of response payload.

## 核心贡献

- **失效契约协议**：一个机器可读的协议层，给每条恢复建议附加 `cache_hint`（cacheable/recompute）与版本戳（`[table, version]` 对），响应信封携带 `table_versions` 字典；高等级增加依赖向量（L4）、版本化知识图（L5）与 `rules_version` 指纹（L6），配合 schema 重载端点的结构化 diff，使客户端能在无试错的情况下逐行/逐表驱逐过期记忆。
- **Savings 分解公式**：`realized savings = validity × compliance(m, p, a)` —— validity 是协议属性（7 模型 × 3 服务路径结果逐字节一致，~9,400 episodes 零契约失效），compliance 是模型属性（跨 7 模型 0–66.7 pp），把 API 提供方能工程化的部分与模型厂商控制的部分清晰分开。
- **行级 vs 表级失效的实证对照**：行级失效是最强合规杠杆（3 个模型 +55.5~66.7 pp），而表级失效会摧毁同表未失效条目——4/7 模型 post-drift funding 首试率从 66.7%（A1）跌至 0%（A2）再回到 66.7%（A2D）；不精确的失效比不失效更有害。
- **检测策略价目表**：lazy vs stamp-only vs stamp+vector vs rule-declaration oracle 的逐事件成本对比——oracle 仅多花 2.4% token 就能早一个 episode 报警并少 2.2–2.5 个 token/事件；stamp+vector 驱逐精度 1.00 但只在失败路径可见（failure-gated）。
- **input-schema conservatism 观察**：最新的 Claude Sonnet 5 在被告知确切字段名的情况下仍拒绝添加其输入 schema 中不存在的字段（add-a-field 首试率仅 10%），为"协议能达成什么"划出了模型侧边界，且该现象与模型新旧程度负相关。

## Key Contributions

- The **invalidation contract**: a machine-readable protocol layer attaching a `cache_hint` (cacheable vs recompute) and version stamps (`[table, version]` pairs) to every recovery suggestion, with `table_versions` in every response envelope; higher levels add dependency vectors (L4), a versioned knowledge graph (L5), and a `rules_version` fingerprint (L6), plus a structured diff on schema reload so the client can evict stale entries without trial and error.
- The **savings equation**, `realized savings = validity × compliance(m, p, a)`: validity is a protocol property (byte-identical results across seven models and three serving paths, zero contract failures in ~9,400 episodes), while compliance is a model property (0–66.7 pp across seven models) — separating what an API provider can engineer from what the model vendor controls.
- **Row- vs table-level invalidation evidence**: row-level invalidation is the strongest compliance lever (+55.5 to +66.7 pp on three models, 0 to +66.7 across all seven), while table-level eviction destroys co-located valid entries — post-drift funding first-try collapses from 66.7% (A1) to 0.0% (A2) on four of seven models before recovering to 66.7% at A2D. Imprecise invalidation is actively harmful.
- A **price sheet for eager vs lazy rule-drift detection**: the rule-declaration oracle (A2DO) alerts one episode earlier and costs 2.2–2.5 fewer tokens per event at only 2.4% more tokens than the lazy arm; stamp+vector detection reaches eviction precision 1.00 but is failure-gated (vectors ride only on recovery feedback).
- The **input-schema conservatism observation**: Claude Sonnet 5 — the newest model tested — refuses to add a field its input schema did not contain even when told exactly which field to add (10% first-try on add-a-field), bounding what any protocol can achieve and inverting the expected recency ordering.

## Methodology

The evaluation runs two synthetic API domains driven by a declarative harness (DriftRiver) that automates table reloads from scenario manifests. **Acme billing** wraps a Stripe-style payment processor: six reference tables, five policies, a 36-episode stream with four constraint classes (governed class needing an add-a-field promo-code hint; funding class needing a conditional-rewrite token; a negative-control class; an unconstrained class). **Recipe conversion** uses a 48-episode stream with a four-rung dietary ladder and rewrite-a-value hints. Drift events are fixed by schedule: the promo code table rotates at episode 11 (and twice more in rotation-count runs), and a benign version bump / rule-edge change occurs at episode 23.

The protocol is arranged in seven levels (Table 1): L0 raw feedback, L1 structured suggestion with cache_hint + table version, L2 patch protocol (a consumption-level one-sentence instruction to merge suggestion parameters verbatim), L3 amended input (fixes presented as pre-applied amendments), L4 per-suggestion dependency vectors (`tables: [[table, version], ...]`), L5 a versioned knowledge graph (GET /admin/graph) with a pre-reload edge walk, and L6 a rules fingerprint on success responses. Client arms form a second ladder: A0 (no memory), A1 (memory, no invalidation), A2 (table-granularity stamps), A2D (row-level diffs from the reload endpoint), plus A2DC (consumer notification), A2DG (subgraph propagation), and A2DO (rule-declaration oracle). All arms hold the compliance channel fixed at L3, which subsumes L2.

Metrics: compliance = first-try rate over injection-eligible episodes (the stale-injection slot right after each rotation is excluded by a pre-registered fixed episode-index list); eviction precision = reciprocal of a run's eviction count; retries are summed per stream; token counts come from vendor billed usage and are compared only within a model against its own A0. Measurement hygiene includes a preflight probe that records requested vs served model across all 238 archived run artifacts (no mismatches), three seeds per drifted cell, and 250 arm-level runs over 9,432 episodes total.

## Results & Highlights

- **Compliance lift from row-level invalidation (Acme billing drifted stream, Table 3):** A2D vs A1 raises first-try compliance by +66.7 points on gpt-5-mini (33.3%→100.0%), +63.0 on claude-sonnet-4-6 (25.9%→88.9%), +55.6 on claude-haiku-4-5 (44.4%→100.0%), and +48.2 on gemini-3.5-flash (29.6%→77.8%). The two opt-out models barely move: claude-sonnet-5 gains only +11.1 (0.0%→11.1%) and deepseek-v4-flash / gpt-5.4-mini gain 0.0 (already at 100% for gpt-5.4-mini).
- **Table-level invalidation is destructive:** on four of seven models post-drift funding first-try collapses from 66.7% at A1 to 0.0% at A2 and returns to 66.7% at A2D; eviction precision is 0.25 at table granularity vs 1.00 at row granularity on every model under the row-level oracle.
- **Token savings (Table 6, within-model vs own A0):** contract + row-level memory recovers 29–33% of baseline token cost on four of seven models — gpt-5-mini 16.4%→32.1% (+15.7 pts over A1), gemini-3.5-flash 10.3%→22.5% (+12.2), claude-sonnet-4-6 18.6%→29.2% (+10.6), claude-haiku-4-5 22.3%→32.5% (+10.2) — while deepseek-v4-flash loses 1.0 pt (7.1%→6.0%). Retries per stream fall from 27.0 (A0) to 7.0 (A2D) on claude-haiku-4-5 and from 82.7 to 55.0 on gemini-3.5-flash.
- **Controls hold:** the 1,023 no-constraint episodes keep 83.3% first-try at every arm including A0, and the negative-control class stays at 83.3% on six of seven models — untouched classes do not move, and memory alone (no invalidation) is already worth 83.3% before any contract machinery. However, over-invalidation has a cost: claude-sonnet-4-6 scores 100% compliance at A1 but only 54.5% at A2 on the governed class.
- **Wire cost:** across 3,387 archived server responses (2,419 carrying contract fields), the contract adds a mean 123 bytes on a mean 817-byte response (15.1% of payload, max 251 bytes); nearly all overhead is the per-table `table_versions` dictionary (mean 190 bytes, 11.7% of all bytes) vs only ~32 bytes for the two per-suggestion fields.
- **Detection policy economics (rule stream, Table 5):** the rule-declaration oracle (A2DO) reads 27 first-try successes vs 9 retries with 3 evictions and 3 restamps at 2.4% more tokens than the lazy arm; stamp-only detection pays 140–143 extra tokens per event (22 first-try vs 14 retries) from blanket-clearing 4–5 entries; a combined lazy+stamp+vector policy costs only 0.2% more tokens than lazy alone while matching the oracle's eviction precision of 1.00.
- **Determinism:** version-stamp validity produced byte-identical results across all seven models and three serving paths with zero contract failures in the entire evaluation (~9,400 episodes); seed standard deviation never exceeds 18.3 points and most cells converge to ~1 pp.

## Critical Assessment

**Novelty is real but bounded.** Mapping HTTP caching semantics (Cache-Control, ETag, RFC 9110) onto agent memory over recovery suggestions is a genuinely fresh framing, and the validity × compliance factorization is a useful conceptual tool. But the "zero contract failures" headline is close to tautological: version stamps are deterministic by construction, so perfect validity is a property of the design, not an empirical surprise the evaluation could have refuted. The empirical content lives almost entirely in the compliance column.

**The evaluation base is the biggest weakness.** Both domains (Acme billing, recipe conversion) were authored by the authors for this study, and the reflective layer that emits `cache_hint` and `recovery_feedback` is hand-written — the paper itself admits (§6.4) it does not know whether the contract transfers to production APIs with larger schemas and organic drift. There is also no external baseline: the comparison is exclusively among the paper's own arms (A0/A1/A2/...). No semantic-cache or agent-memory baseline (e.g., GPTCache-style systems or Reflexion-style stores with heuristic eviction) is run, so the reader cannot tell how much a simpler engineering fix — timestamping cached fixes and re-checking on use — would recover of the same gains.

**Scoring choices move the headline numbers, and the paper says so.** Compliance excludes the stale-injection slot by a pre-registered fixed episode list (defensible, but a one-episode shift changes A1 compliance at cleared tables); eviction precision is confounded by run exhaustion — the paper flags that gemini-3.5-flash's 1.00 precision at A2 is a starvation artifact (its diff-carrying episodes never complete), not good eviction. Credit for disclosing these, but it means the 0.25-vs-1.00 precision contrast should be read with care.

**Measurement quirks worth noting:** all three Anthropic models score 0% first-try at A0 (no memory) on the governed class — the tasks are unsolvable without the server's recovery feedback — so "compliance" largely measures instruction-following on server-prescribed fixes rather than task-solving ability, and DeepSeek's non-zero A0 funding rate shows the floor is model-dependent. The Level-4 compliance effect is never isolated: dependency vectors are only measured bundled with graph propagation (A2DG) or as failure-gated detection (A2DRC). The pre-registered falsification criterion (the naive-governed gap growing monotonically) failed — the gap plateaus at three rotations — and is reported honestly but left unresolved. Token accounting is vendor-billed and not comparable across serving paths, restricting all token claims to within-model deltas.

**The trust-surface discussion is commendably honest** and doubles as a red-flag inventory: validity is asserted, never verified — a malicious or buggy server that never bumps versions pins stale fixes indefinitely, converting the 29–33% token saving into a surcharge (a cheap denial-of-savings attack the client cannot refuse); the L2/L3 compliance channels are parameter-injection vectors; the L5 graph endpoint publishes internal derivation structure. Signed stamps and rate-limited bumps are suggested but not implemented, and no threat model is given.

## Strengths

- The validity × compliance decomposition cleanly assigns engineering responsibility: API providers can ship the contract without touching model behavior, and a cheap "compliance preflight" (tens of API calls with known-valid fixes) reads out the model factor before any memory investment.
- Deterministic, exactly reproducible validity: byte-identical results across seven models, three serving paths, and all random seeds, with ~1 pp seed standard deviation in most cells — rare rigor for an agentic systems paper.
- Controls demonstrate specificity: 1,023 no-drift episodes hold at 83.3% across every arm, and the negative-control class does not move, so the measured effects are attributable to drift handling rather than memory per se.
- Unusually honest failure accounting: negative token deltas (deepseek −1.0), opt-out models, the exhaustion-precision artifact, the failed monotonicity prediction, and the three trust-surface exposures are all disclosed in the main text.
- Actionable numbers end-to-end: 15% payload overhead with a byte-level breakdown, per-action-type compliance price sheet (add-a-field vs rewrite-a-value vs conditional-rewrite), and an eager-vs-lazy detection cost table within ~2.5% tokens.

## Limitations

- Both evaluation domains are synthetic and author-built with a hand-written reflective layer; transfer to production APIs (larger schemas, organic drift, retrofitted reflection) is unknown, by the authors' own admission.
- Scale and coverage: two domains, one base prompt per domain, one task family per content class; prompt sensitivity is plausible but untested. Levels 1–3 tag only single-table dependencies, the isolated compliance effect of Level-4 dependency vectors is unmeasured, and L5/L6 are exercised only on the rule stream with three models.
- Validity is asserted, never verified: a server that never bumps versions pins stale fixes indefinitely (denial-of-savings), there is no threat model, and the L5 endpoint leaks internal schema structure.
- The compliance channel is itself a parameter-injection channel (L2 verbatim-merge instruction, L3 pre-applied amendments); 100% compliance on claude-haiku-4-5 reads either way.
- Eviction precision is confounded by run exhaustion (early budget exhaustion inflates precision), and token accounting is vendor-billed, so cross-path cost comparisons are impossible — all savings are within-model vs the model's own A0.
- The naive-governed gap saturates at three drift rotations against the pre-registered monotonic-growth prediction; whether this is a ceiling effect or a rotation-schedule artifact remains unresolved.

## Relevance

该论文与你关注的长时程自主 Agent 系统的可靠性与可信性直接相关：它把"服务器端数据漂移导致 agent 持久记忆静默失效"变成一个可度量、可分协议层解决的工程问题，validity×compliance 分解和逐模型合规预检（compliance preflight）对任何带跨会话记忆的 agent 基础设施（包括自进化 agent 的记忆层）都有直接借鉴价值。需要注意实验完全基于作者自建的两个合成 API 域，结论向生产环境迁移仍是开放问题。

## Questions for Further Exploration

1. Does the contract survive organic drift (schema migrations, deprecations, third-party API churn) and production-scale schemas where the reflective layer cannot be hand-written per endpoint?
2. Can validity be verified rather than asserted — e.g., signed version stamps, rate-limited bumps, or client-side spot re-derivation — to bound a malicious server's denial-of-savings attack?
3. What is the isolated compliance effect of Level-4 dependency vectors without graph propagation, and do the extra per-suggestion bytes pay for themselves?
4. Is input-schema conservatism in Claude Sonnet 5 (10% add-a-field compliance despite explicit field names) a promptable behavior, a tool-schema design artifact, or a post-training artifact — and can it be removed without fine-tuning?
5. How does the compliance plateau at three drift rotations decompose: ceiling effect, rotation-schedule artifact, or exhaustion of injection-eligible slots?
6. Would a simpler engineering baseline (cache with timestamps + revalidate-on-use, no protocol change) recover most of the A2D gains, and how does the 15% payload overhead compare against such a baseline's revalidation traffic?
