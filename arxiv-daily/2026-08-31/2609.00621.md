> **一句话总结：** 针对多智能体 LLM 系统中提示词同时承担"任务内容生成"与"执行协议（路由/格式/终止信号）"两种角色、导致提示词优化容易破坏协议使整条流水线崩溃的问题，本文提出控制-数据流分离（cdsep 库）：把每个 agent 的输出拆成由冻结类型化 schema 校验、优化器不可编辑的控制通道，和可自由优化、仍然可被优化器读写的数据通道，并在理论上给出协议稳定性保证（Lemma 1）；在 BBH、MARG 综述生成、合成与行业校验核保四类任务上，方法全部取得最高任务分数且 100% 协议有效，而朴素 TextGrad 在 MARG 上 Jaccard 崩到 0%（稳定性 0%）。

> **TL;DR:** In multi-agent LLM pipelines, a prompt edit meant to improve content can silently corrupt the routing/formatting/termination protocol the surrounding Python controller parses, collapsing the whole pipeline. The authors propose control-data flow separation (shipped as the `cdsep` Python library): each agent emits a schema-validated, typed control object (from a frozen prompt slot the optimizer cannot edit) plus a free-form data message (the only thing the optimizer edits), with bounded re-prompting on validation failure. On MARG review generation (ARIES corpus) it reaches 44.4 Jaccard vs 43.2 for the strongest DSPy+MIPROv2 baseline and 31.0 for fixed prompts, while keeping 100% protocol stability where Naive TextGrad collapses to 0% Jaccard / 0% stability; on BIG-Bench Hard (4-task subset) it averages 78.3% vs 74.3% for DSPy+BootstrapFewShot; on the partner-verified insurance underwriting task it hits 36.7% accuracy vs 31.7% for the industry partner's own prompt, with 100% vs 56.7% stability vs Naive TextGrad.

## 核心贡献

- **问题刻画（协议脆弱性）：** 指出多智能体系统中的提示词同时是 (a) 给其他 agent 读的任务内容生成器，和 (b) 给程序控制器解析的执行协议（路由目标、输出格式、终止信号）。当两者挤在同一个可被文本梯度优化的字符串里时，"提升内容质量"的编辑会顺带改坏协议——表现为解析失败、错路由、整条 episode 崩溃（Naive TextGrad 在 MARG 上 3 个种子全部崩到 0% 稳定性）。
- **控制-数据流分离设计：** 每个 agent 输出拆为 `y_i^t = (c_i^t, m_i^t)`——控制通道是由 Python dataclass/Pydantic schema 校验的类型化对象（路由只读它），数据通道是自由文本（供其他 agent 和优化器消费）。schema 脚手架由类型定义自动生成并放进优化器不可修改的冻结 prompt 槽位。
- **协议稳定性保证（Lemma 1）：** 在三个条件（C1 路由函数只消费类型化控制对象；C2 schema 脚手架位于冻结槽位；C3 解析/校验失败在有限次重试内修复或落入受控默认行为）下，episode trace 中不会出现未处理的解析/校验/路由违规。作者明确说明该保证是"刻意受限的"：只保证协议不被优化器破坏，不保证数据通道的语义正确性。
- **cdsep Python 库与实证：** 以 MIT 协议开源（github.com/yuntian-group/cdsep，77 个单元/集成测试，接口约 40 行 Python 即可搭完整多智能体流水线）；在 BBH 单 agent、MARG leader-worker 综述、合成核保、行业校验核保四类任务上系统评估，并做了消融（schema / retry / per-example feedback 三分量分解）与跨三家 LLM 厂商的鲁棒性实验。
- **崩溃机理的量化：** 通过统计"被编辑行中含控制相关 token（JSON、Output format、schema 字段名等）的比例"量化提示词漂移——Naive TextGrad 在综述任务上 16.6% 的编辑行触碰控制面，是本文方法的 4.2% 的近 4 倍，解释了崩溃为何集中于路由复杂的多智能体任务。

## Key Contributions

- **Identifies protocol fragility in multi-agent prompt optimization:** agent prompts play two entangled roles — producing task-relevant content and specifying execution-critical protocols (routing targets, output formats, termination signals). Textual-gradient edits that improve content can corrupt the protocol, and the failure mode is not a worse answer but a broken episode (misroute, parse crash, or infinite loop). Demonstrated empirically: Naive TextGrad reaches 0% stability on MARG review generation across all seeds.
- **Proposes control-data flow separation, implemented as `cdsep`:** every agent output is a pair (control object, data message). The control channel is a typed, schema-validated Python object whose auto-generated scaffolding lives in a frozen prompt slot the optimizer cannot touch; the controller routes only on validated control objects; the data channel is ordinary free-form text that remains fully optimizable. Parse/validation failures trigger bounded retries or a controlled default — never an unhandled crash.
- **Formalizes a protocol-stability guarantee (Lemma 1):** under three conditions (typed routing functions; frozen schema scaffolding; bounded re-prompt/fallback on invalid control), no unhandled parse, validation, or routing violation ever enters the episode trace. The authors are explicit that the guarantee is deliberately limited to the protocol layer and says nothing about the semantic correctness of data messages.
- **Comprehensive evaluation across four settings of increasing routing complexity** (BBH single-agent; MARG leader-worker review generation; synthetic underwriting; industry-verified underwriting with partner-supplied data from Manulife), with a component-wise ablation (schema / retry / per-example feedback), a multi-LLM-family robustness study (OpenAI, Anthropic, Google), and a mechanistic quantification of "prompt drift onto the control surface".
- **Releases the framework as a usable Python library** (MIT license, 77 unit/integration tests, multi-provider dispatch, disk-backed caching; a full leader-worker pipeline takes under 40 lines).

## Methodology

**Problem setup.** A multi-agent LLM system is modeled as a set of agents A = {1..N}, each parameterized by a prompt p_i and backed by a fixed LLM f_i, orchestrated by a Python program controller. At each step t the controller selects an agent, builds its textual context, and queries y_i^t = f_i(p_i, context_i^t). Prompt optimization treats {p_i} as editable parameters and minimizes a task loss over a training distribution, using feedback from downstream task performance (TextGrad-style textual gradients in their implementation).

**Failure mode.** Agent outputs are consumed by two different readers: other agents (task content) and the controller (protocol: e.g., a leader emits a JSON object with an `action` field and a `target_agent` field, or a rater emits a Literal bucket rating). When both live in one optimizable string, the optimizer can weaken, remove, or reformat the protocol instructions. The paper documents three concrete end-to-end failures in Appendix G: the optimizer deletes the JSON format block entirely; it renames schema fields away (`target_agent` vanishes); and it drifts onto control-relevant lines far more often than the separated method (Table 3).

**Control-data flow separation.** Each agent output is y_i^t = (c_i^t, m_i^t): a control-flow object c_i^t, structured and machine-readable, whose fields (action, routing target, termination flag, task category) are constrained by a per-agent control schema S_i expressed as Python dataclasses/Pydantic models with closed Literal types; and a data-flow message m_i^t, unstructured task content. The framework auto-generates schema scaffolding instructing the LLM to produce the control block, and places it in a frozen prompt slot. At runtime the controller parses the response into a candidate pair, validates c_i^t against S_i, re-prompts up to a finite bound (max 2 parse retries) on failure, else falls back to a default valid control object or surfaces a controlled failure. Only a validated control object drives state updates (routing, appending intermediate results, termination). The optimizer sees the full interaction trace and task-level feedback, and may edit data-channel prompts and even policy choices within the protocol — but never the schemas, allowed field values, or validation logic.

**Guarantee.** Lemma 1: under (C1) routing functions read only typed control objects and return values in A ∪ {terminate}; (C2) schema scaffolding is frozen against the optimizer; (C3) invalid candidates are re-prompted up to a finite bound then defaulted or surfaced as controlled failures — the episode trace contains no unhandled parse/validation/routing violation. The proof is a short case analysis; the authors frame it as formalizing a program-safety property, not a deep result.

**Experimental setup.** Four settings of increasing routing complexity: (i) BBH 4-task subset (LogicalDeduction-3obj, TrackingShuffledObjects-3obj, CausalJudgement, WordSorting), single agent, N_train=25/N_test=25 per task, K=6 iterations; (ii) MARG collaborative review generation on ICLR papers from the ARIES corpus (leader + 3 workers; metric: alignment Jaccard via LLM judge, gpt-5.4-mini substituted for GPT-4); (iii) synthetic underwriting (90 cases from a 12-impairment taxonomy; extractor→rater→aggregator chain; 10-bucket ladder); (iv) industry-verified underwriting (91 synthetic medical summaries each rated by an expert underwriter at the industry partner; 15-bucket ladder; 20 bucket-stratified test cases). Agents run gpt-5.4-nano; the optimizer runs gpt-5.4-mini. Baselines: Fixed prompts, Naive TextGrad (same optimizer code path, schema slot not frozen), DSPy (no compile), DSPy+BootstrapFewShot, DSPy+MIPROv2, and Partner-Fixed (the partner's own out-of-box system prompt on the industry task). All numbers are means over 3 seeds. Metrics: task accuracy (BBH, underwriting), alignment Jaccard (MARG), and Stability — the fraction of episodes that eventually complete with valid control and no unhandled parse/validation/routing error, permitting bounded retries (a "strict" pre-retry variant is also reported). Ablations vary three orthogonal components: schema scaffolding, parse retry, and per-example feedback (scalar batch loss vs per-example feedback). Multi-model robustness repeats MARG with Claude haiku-4-5/sonnet-4-5 and Gemini 2.5 Flash/Pro.

## Results & Highlights

- **Protocol stability: 100% eventual validity everywhere for Ours; Naive collapses on routing-heavy tasks.** Across all four settings Ours achieves 100% eventual protocol validity (and 100% strict stability per Table 1). Naive TextGrad's stability is 0% on MARG review generation (all seeds, all iterations — total pipeline collapse), 56.7% on industry-verified underwriting, 92.0% on BBH, and 100% on the low-routing synthetic underwriting task — collapse concentrates exactly where the control surface is largest.
- **BBH (4-task subset, 25 test examples/task, 3 seeds): Ours 78.3% avg accuracy vs 74.3% for the strongest baseline DSPy+BootstrapFewShot (+4.0 pts)**, 71.3% DSPy+MIPROv2, 51.7% fixed prompts, 45.9% Naive TextGrad. Per-task, Ours hits 100% on LogicalDeduction and TrackingShuffledObjects and 68.0% on CausalJudgement (tied with DSPy+BS), but fixed prompts actually beat it on WordSorting (48.0% vs 45.3%).
- **MARG review generation (ARIES corpus, N=14 test papers): Ours 44.4 Jaccard vs 43.2 for DSPy+MIPROv2 (+1.2) and 31.0 for fixed prompts (+13.4)**; DSPy (no compile) 41.8, DSPy+BootstrapFewShot 39.6, Naive TextGrad 0.0. On the Table 8 scaled split, DSPy+MIPROv2 actually posts better Recall (53.7 vs 46.0) and Precision (62.3 vs 50.7) — Ours wins on the Jaccard headline metric only.
- **Industry-verified underwriting (20 bucket-stratified test cases from the partner's 91 canonicalized summaries): Ours 36.7% accuracy vs 31.7% Partner-Fixed (+5.0 pts) and 23.3% best DSPy variant (+13.4); MAE 3.33 vs 3.42 Partner-Fixed.** Stability 100% vs 57% (Naive), 83.3% (both DSPy teleprompters); Naive's MAE balloons to 7.88. On synthetic underwriting, Ours 50.0% acc / MAE 0.90 vs Naive 47.8% / 1.16 and DSPy+MIPROv2 32.2% / 1.93.
- **Ablation (Table 2, reduced budget, review N=12): schema scaffolding alone takes review stability from 0% to 100% (Jaccard 0.0 → 26.8); parse retry adds ~1 point (26.9) and closes synthetic-underwriting strict stability 98.9% → 100%; per-example feedback drives the quality gains (review Jaccard 26.9 → 38.0, synthetic underwriting accuracy 37.8 → 51.1 at the same budget).** Stability and task quality therefore have distinct, separable causes.
- **Multi-model robustness (MARG, N=12, 1 seed): Ours keeps 100% stability on all three families while Naive is 0% on each; Jaccard 33.5 (Anthropic) and 40.3 (Google) beat fixed prompts (25.1, 33.7), but on OpenAI fixed prompts win 43.4 vs 42.2.**
- **Mechanism: prompt drift onto the control surface.** 16.6% of Naive's edited lines touch control-relevant tokens on the review task vs 4.2% for Ours (~4×), and Naive touches it more often on every task (27.0% vs 14.6% synthetic; 22.9% vs 18.6% BBH; 22.6% vs 12.6% insurance). Ours empirically stays at 100% validity at every optimization iteration (Figure 2).
- **Cost:** the headline MARG run (3 iterations, 3 seeds) costs about $3 in API spend; deterministic agent calls are disk-cached.

## Critical Assessment

- **The 100% stability number is partly true by construction.** "Eventual protocol validity" permits bounded retries and controlled fallbacks, and Lemma 1 guarantees no unhandled violation once C1-C3 hold — so the headline "100%" is close to a restatement of the design. The scientifically informative content is the contrast (Naive TextGrad collapsing to 0% on MARG) and the drift quantification (16.6% vs 4.2% control-touch rate), not the invariant itself. The paper is candid about the guarantee being "deliberately limited", which is appreciated, but reviewers should read the 100% as an engineering property demonstrated, not a discovered result.
- **The headline quality margins over the strongest baselines are thin and metric-fragile.** On MARG review generation the win over DSPy+MIPROv2 is +1.2 Jaccard (44.4 vs 43.2), and on the matched scaled split (Table 8) MIPROv2 posts substantially better Recall (53.7 vs 46.0) and Precision (62.3 vs 50.7) — the ordering flips depending on whether one rewards overlap (Jaccard) or per-comment quality. On the OpenAI-only multi-model run, fixed prompts beat Ours (43.4 vs 42.2), and on BBH WordSorting fixed prompts also win (48.0 vs 45.3) — the paper does not foreground either fact.
- **Small evaluation sets everywhere.** BBH uses 25 test examples per task; the industry-verified underwriting test is 20 bucket-stratified cases per seed from 91 total summaries; the MARG test split is 12-14 papers. With 3 seeds, a ±5-point swing on the underwriting table is within plausible noise, and the +5.0-point win over Partner-Fixed rests on a very small denominator. No significance tests are reported.
- **BBH barely exercises the actual mechanism.** The single-agent BBH setting has a one-field control schema and no routing, so the framework's central contribution (protecting routing under optimization) is mostly inert there; it functions as a sanity check that separation doesn't hurt simple tasks, and the BBH gain over DSPy+BS likely comes from the per-example-feedback component rather than separation itself (consistent with the ablation).
- **Naive TextGrad is implemented by the authors inside their own framework** (cdsep/optimizer.py, two modes: separated vs naive). That makes the comparison controlled and fair in code-path terms, but "naive" also means the optimizer is pointed at a known-broken objective with no format guardrails — a failure mode DSPy already partially mitigates (DSPy variants never collapse below 83.3% strict stability on the industry task). The strawman risk is moderate: the collapse is real and mechanistically explained, but the most practically relevant comparison is against DSPy+MIPROv2, where the deltas are small.
- **Absolute MARG numbers are not comparable to the published MARG literature** (gpt-5.4-mini substituted for GPT-4 in the LLM-judge alignment step; their Jaccard of ~41-44 vs published values of ~3.5-5.6 is a judge artifact the paper itself flags). The LLM-judge dependence is acknowledged as a limitation and the judge is held constant, but no human evaluation of the generated reviews is provided.
- **Rigor positives:** the three-component ablation cleanly decomposes stability (schema + retry) from quality (per-example feedback); the drift metric (Table 3) gives a mechanistic account rather than just a scoreboard; per-task tables and strict vs eventual stability are all disclosed, which is how I could find the weak spots above.

## Strengths

- Real, well-motivated failure mode with a crisp mechanistic explanation: the control-touch-rate analysis (Table 3) and the three end-to-end Naive failure transcripts (Appendix G) show exactly how unconstrained textual gradients delete or reformat protocol contracts, and why collapse concentrates on routing-heavy tasks (0% on MARG vs 100% on synthetic underwriting).
- Clean separation of concerns with an honest scope statement: the paper never claims stability implies correctness, and Lemma 1 is explicitly limited to the protocol layer.
- The ablation is genuinely informative — it shows schema scaffolding buys stability (0→100%), retry buys the last ~1%, and per-example feedback buys the accuracy gains (37.8→51.1% on synthetic underwriting), i.e., the stability and quality contributions are orthogonal.
- Industry grounding: the underwriting benchmarks (especially the 91 expert-rated synthetic medical summaries and the partner's own prompt as calibration) give the evaluation a production flavor most prompt-optimization papers lack; fully synthetic data avoids privacy issues and the checklist appendix documents licensing and PII checks.
- Usable artifact: MIT-licensed library, 77 tests, multi-provider support, ~$3 per headline run, deterministic caching — low barrier to adoption and reproduction of the non-industry settings.

## Limitations

- Stability ≠ correctness: a protocol-valid pipeline can still produce wrong or low-quality outputs; the guarantee says nothing about data-channel semantics (stated by the authors).
- Fixed, pre-declared schemas: no dynamic agent creation or runtime schema evolution; routing choices and episode depth must be known up front (stated by the authors) — a real constraint for self-organizing agent systems.
- MARG metric is LLM-as-judge (gpt-5.4-mini) with known biases; absolute numbers are not comparable to published MARG results, and there is no human evaluation.
- Small test sets (25 BBH examples/task, 20 industry underwriting cases/seed, 12-14 review papers), 3 seeds, no statistical significance testing.
- Evaluation is offline and mostly English; the single-agent BBH setting does not exercise routing, the core mechanism; the industry dataset is not redistributable, limiting independent verification of that setting.
- The separation principle constrains the optimizer to operate within a protocol the developer must specify correctly in the first place — a mis-specified schema or routing function is preserved perfectly by the guarantee.

## Relevance

与用户的高优先级方向"自进化/自改进 Agent 以及长时自主 Agent 系统的可靠性与可信性"高度契合：论文的核心命题正是"当优化器（或自改写循环）修改自身提示词时，如何保证不破坏执行协议"——这是任何自我修改 agent 架构都会撞上的安全边界，其"冻结接口 + 类型化校验 + 有限重试"的工程化思路可直接借鉴到自进化系统的自我修改模块设计中。对推理可靠性方向而言，它处理的是软件层（协议）而非硬件层故障，属于外围但有用的补充视角。

## Questions for Further Exploration

- Can the frozen-schema restriction be relaxed toward runtime schema evolution or dynamic agent creation while retaining a meaningful (weaker, probabilistic?) protocol-stability guarantee — the authors flag this as future work, and it is exactly what self-evolving agent systems would need?
- The quality gains come almost entirely from per-example feedback rather than separation itself; would combining cdsep-style frozen control channels with stronger optimizers (GEPA's reflective evolution, SAMMO) yield gains beyond the +1.2 Jaccard over MIPROv2 seen here?
- Does the 16.6% vs 4.2% control-touch drift metric generalize as a leading indicator of collapse across other optimizer families and task types, i.e., can it be monitored online to trigger intervention?
- How does the framework behave when the task loss legitimately requires changing the protocol (e.g., the optimal workflow needs more workers or a different routing topology), which the current guarantee forbids by design?
- With only 20 industry test cases and Jaccard-vs-Recall/Precision orderings that flip between metrics, would the underwriting and review conclusions hold with an order of magnitude more evaluation data or human raters?
