> **一句话总结：** 两位作者（独立研究员 + 华盛顿大学）提出 RIPA 架构：把"长寿 AI agent"拆为承载连续性的持久基底 P=(I, M, B)（已安装身份、私有持久记忆、可版本化可执行身体）与可替换的执行绑定（推理模型/编排框架/宿主）及交互面，用六条连续性不变量（I1–I6）和"静默围栏→检查点→校验→绑定→再水化→验证恢复"六阶段迁移协议治理迁移，并开源实现 Enoch（body.yaml+self.json、5 类 provider contract、Muse 适配器、epoch 围栏）；实证上，操作案例跨笔记本→台式机、Codex(gpt-5)→Claude Code(claude-opus-5)、Slack→Telegram 三次替换保住了身份/记忆哈希、body 修订与 22 个历史任务 ID（出站/回程检查点分别校验 76/77 个可移植文件，authority 代际 8→14），监督式 Codex–Muse–Codex 冻结研究中 1 资格轮+5 普通往返+5 同构对照共 11 例全部一次通过（26 条件验证器），计划内 SIGKILL 杀死 worker 后经原生任务 API 恢复：阶段一检查点原封不动、旧 nonce 被拒、任务恰好完成一次。

> **TL;DR:** A systems/position paper proposing RIPA: a persistent agent is a continuity-bearing substrate (installed identity I, private memory M, versioned executable body B) that must survive replacement of its reasoner/harness/host bindings and chat surfaces, governed by six continuity invariants and a six-phase quiesce–checkpoint–validate–bind–rehydrate–resume migration protocol, implemented in the open-source Enoch agent body. In the supervised frozen Codex–Muse–Codex study (snapshot B2), 1 qualification + 5 ordinary cross-runtime round trips and 5 matched same-runtime controls (C1–C5, 13 applicable checks each) all passed on first attempts under a 26-condition round-trip verifier plus 18 provenance/no-repair checks per ordinary trip; the operational case (B1) preserved identity/memory hashes, body revision and 22 historical task IDs across laptop→desktop, Codex (gpt-5)→Claude Code (claude-opus-5), and Slack→Telegram substitutions with 76/77 portable checkpoint files verified; a planned SIGKILL of the Muse worker recovered via the native task API with the stage-one checkpoint unchanged, exactly one task completion, and the stale nonce rejected. The evidence establishes mechanical continuity only — no behavioral equivalence, arbitrary-task portability, exactly-once external effects, or unattended reliability.

## 核心贡献

- **运行时无关的 agent 边界（概念框架）**：将持久基底 P_t = (I_t, M_t, B_t)——已安装身份（self-record/价值观/关系）、私有持久记忆与工作流状态、可复用可执行身体（代码/提示/工具/策略/契约）——与可替换执行基底 E_t = (R_t, H_t, D_t)（推理模型、编排 harness、宿主）及交互面 S_t（聊天账号、API、邮件、GUI）严格分离；部署 A_t = P_t ▷ (E_t, S_t) 中 ▷ 仅表示实例化而非所有权。配套给出七种生命周期操作（Restart / Resume / Migrate / Evolve / Identity update / Replicate / Descend-fork）及其连续性后果，指出"稳定 UUID 不足以防复制冒名"。
- **六条连续性不变量 + 六阶段迁移协议**：I1 身份版本与谱系保持；I2 记忆/工作流只能按谱系延展或有效迁移、绝不能被静默重置；I3 body 停留在同一提交或经授权演化；I4 治理边界内至多一个协作执行体持有延续权威；I5 能力增减必须显式可见；I6 执行/进程/表面标签不得覆盖已安装身份。迁移协议 μ: (E_s,S_s)→(E_t,S_t) 分六阶段（Quiesce+fence → Checkpoint → Validate → Bind → Rehydrate → Verify+resume），定义单一受治理晋升点，并明确这不是分布式共识或跨主机原子提交；复制/回滚的失败语义（源回滚需确认无目标激活）被显式声明。
- **开源参考实现 Enoch**：可复用软件身体（body.yaml 身体/包身份+仓库谱系；self.json 已安装身份+谱系元数据）；按"软件身体 / 私有状态 / 留存工件"三分托管边界；5 类 provider contract（Chat: Telegram/Slack/Muse；Runtime: Codex/Claude Code/Muse；VCS: Git；Review: GitHub/local；Service: launchd/systemd）隔离基础设施品牌；intent+幂等键+daemon fencing epoch、epoch token 代际、per-root 进程锁、导入代际下限等机制实现权威围栏；Muse 适配器把 Enoch 运行时契约桥接到异步文件邮箱（每次回复携带新 attempt nonce）。
- **分级的诚实实证与"不变量→证据"覆盖图**：三个冻结 body 快照（B0/B1/B2，含测试计数与哈希）支撑机制证据，三类活体研究（操作迁移案例、跨主机检查点续跑、监督式 Muse 往返）+ 一次计划内故障注入；Table 4 逐条映射 I1–I6 的已测断言与覆盖边界（如 I4 的 notice 检查是 attempt-local、I5 无针对性能力损失迁移试验），明确"这是现有证据的覆盖地图，不是新实验或完整契约的证明"。

## Key Contributions

- **A runtime-independent agent boundary**: the logical persistent substrate (I, M, B) is separated from the replaceable execution substrate (reasoner R, harness H, host D) and independently replaceable interaction surfaces S; a seven-operation lifecycle taxonomy (restart, resume, migrate, evolve, identity update, replicate, descend/fork) replaces the collapsed "resume vs fork" vocabulary, and shows why a stable name/UUID cannot by itself prevent a copied process from claiming sole authority.
- **Migration semantics with explicit failure modes**: six continuity invariants (identity/lineage, memory/workflow ancestry never silently reset, body commit-or-authorized-evolution, unique cooperating authority, explicit capability deltas, labels-don't-redefine-self) plus a six-phase quiesce–checkpoint–validate–bind–rehydrate–resume protocol with a single governed promotion point, source fencing during transfer, and operator-confirmed export-cancellation.
- **A reusable implementation**: Enoch loads body.yaml and self.json as separate inputs, keeps memory/queues/schedules/provider cursors in durable private state, isolates five provider kinds behind contracts (a Telegram update or Git branch never reaches the portable core), and realizes authority via idempotency keys, daemon fencing epochs, epoch-token generations, per-root process locks, and imported-manifest generation floors; the Muse adapter bridges the runtime contract to an asynchronous file mailbox with per-attempt nonces.
- **Bounded, honestly-scoped empirical evidence**: frozen snapshots (B0/B1/B2) with test-suite counts, three kinds of live study against actual deployment bindings, and an invariant-to-evidence coverage map (Table 4) that names, for each invariant, both the existing checks and the coverage boundary (e.g., I4 notice checks are attempt-local; I5 has no targeted capability-loss migration trial).

## Methodology

The paper defines the persistent substrate P_t = (I_t, M_t, B_t) and replaceable execution/interaction bindings (E_t, S_t) as formal objects, then derives required properties: continuity is lineage continuity, not bitwise immutability (Eq. 5: identity/memory versions stay equal and body version is ≤ across a pure runtime migration, unless the migration transaction carries separately authorized evolution). Migration μ: (E_s, S_s) → (E_t, S_t) replaces any nonempty subset of reasoner/harness/host/surface through six phases: (1) Quiesce and fence (authority epoch advance, reject work under stale epoch); (2) Checkpoint (identity, body revision, memory/workflow-state versions, cursors, artifact references — secrets referenced not exported); (3) Validate (schemas, hashes, declared lineage, target capability requirements); (4) Bind (provider resolution via body contracts); (5) Rehydrate (install state without admitting work, fresh harness sessions); (6) Verify and resume (mechanical continuity checks, new epoch, reconcile ambiguous effects). The source stays quiescent and fenced; a failed conversion restores target files or leaves them inert; after target activation the source remains fenced even if it reconnects.

The reference implementation Enoch realizes this: body.yaml (body/package identity, mission, principles, repository lineage) and self.json (installed identity, relationships, values, lineage metadata) are loaded separately so a fresh session cannot report environment labels as self; a recovery boundary backs up state, replaces files atomically, and writes the manifest last with validation-triggered restoration (admittedly not crash-atomic — SIGKILL bypasses exception rollback); five provider contracts (chat/runtime/VCS/review/service) isolate infrastructure; a managed launcher with a per-root lock prevents duplicate launches; the open-source Muse adapter transports events through an async file mailbox with fresh attempt nonces, fencing the source at export.

Evaluation methodology is deliberately tiered and self-audited: three frozen body revisions (B0: 31 Aug, c8013ed249bc; B1: 7 Sep, e40b28782f5c; B2: 19 Sep, 66781e209962) are held fixed within each study; evidence comes from (a) clean-room test suites, (b) an operational B1 case moving one established instance across host, joint model/harness, and chat-surface changes, (c) a synthetic two-stage cross-host task resumed from a verified artifact checkpoint, and (d) a supervised frozen Codex–Muse–Codex study with a qualification round trip, five ordinary round trips (R1–R5), five matched same-runtime controls (C1–C5) that run the same bounded workflow without migration, and one planned fault case F (SIGKILL before first reply). A round-trip verifier outside the target agent checks 26 conditions per migrated case (exact identity bytes, memory preservation+extension, body revision, checkpoint consumption, one completion per event, source-event prefix preservation, authority progression, both source fences, nonce-correlated replies, observed process exits); an author-run offline verifier checks hashes and arithmetic without model calls over the public B2 archive.

## Results & Highlights

- **Operational migrations preserve the instance (B1, RQ1)**: one established instance with nonempty long-term memory survived three successive substitutions — laptop→desktop (retaining Codex+Slack), Codex→Claude Code (retaining Slack; gpt-5 via Codex CLI 0.153.1 → claude-opus-5/high via Claude Code 2.1.258), Slack→Telegram (retaining Claude Code) — with identity and memory hashes, body revision, and 22 historical task IDs preserved; outbound and return host checkpoints verified 76 and 77 portable files respectively, and recorded authority generations advanced 8 through 14 across export, activation, and service starts. There is no accuracy-style baseline here — the claim is hash-level state preservation, not behavior preservation.
- **Frozen Codex–Muse–Codex study (B2, RQ1–RQ2): 11/11 first-attempt passes**: the qualification case Q, all five ordinary round trips R1–R5, and all five same-runtime controls C1–C5 passed on their first attempts under the 26-condition verifier (controls: 13 applicable workflow checks each; ordinary trips: 18 additional provenance/no-repair checks each), with no model-answer retries or unplanned state repairs in the supervised series; all seven migrating source roots and seven Muse return-export roots (14 fences) rejected post-export execution without advancing the authority epoch.
- **Planned worker interruption recovers cleanly (F, RQ3)**: killing the first Muse worker after request publication and before any reply (supervisor records return code −9, SIGKILL), native recovery paused the same task with the full stage-one checkpoint unchanged, a subsequent worker with a fresh attempt nonce completed the task exactly once, and submitting the old nonce produced a rejection on stderr; F passed 28 continuity/evidence checks plus 29 provenance/recovery checks (a fault-completion is explicitly not counted as an ordinary first-attempt success). The trace does not test a crash during an external side effect.
- **Cross-host checkpointed task resumes exactly (B1 synthetic, RQ2)**: a two-stage task started on a laptop and continued on a desktop (both stages Codex CLI 0.153.1, gpt-5, Python 3.12.14) imported nine portable files, resumed the same task ID, and computed category totals 28 and 28 with grand total 56 — an exact arithmetic witness of state fidelity; task attempts advanced 1→2 and authority 1→3, the exported source refused restart, and deterministic offline replay rejected missing or corrupt continuation artifacts.
- **Mechanism test volume**: B0's clean-room suite ran 833 core + 92 provider/library tests; B1's snapshots (original and anonymized) each passed 963 tests (857 core + 106 provider/library) with no failures or skips under CPython 3.12.13; B2 added 23 adapter tests exercising native daemon and workflow paths with deterministic mailbox responses — the authors note these test mechanism implementation, not model ability.

## Authors & Credibility

Zhenyu Zhao (Independent Researcher) and Roy Zhao (Paul G. Allen School of Computer Science & Engineering, University of Washington). This is the third installment of a self-built research line: their own "Code is the body: Agent-owned software bodies for recursive evolution and descent" (arXiv:2607.28691) is the declared closest precursor, and they also cite their PAI-Bench identity-fidelity benchmark (arXiv:2609.13637). The engineering effort is substantial and partly verifiable: Enoch is open source, and the B2 Muse study archive is published at a pinned commit (084e1b1c654af7f48fb2820e47450256ad0899) under Apache-2.0 with code, protocol, raw records, migration bundles, and an offline verifier. However, all live evidence is author-curated and operator-supervised, B1's private operational data (memory, conversations) is withheld, no independent replication exists, and the contact address is a gmail account — credibility rests on the released artifacts rather than external validation.

## Critical Assessment

- **Novelty is incremental within a self-referential cluster.** The (I, M, B) decomposition and lifecycle taxonomy are genuinely useful vocabulary, but the paper's own related-work section concedes that the Continuity Kernel (He & Yu, arXiv:2608.11632) already formalizes authorized state-head lineage, atomic activation, write-handoff, schema migration, and restoration; RIPA's delta is binding the authority layer to reasoner/harness/host/surface changes. The adjacent works (Portable memory, PAI-Bench, the precursor "Code is the body") are mostly 2026 preprints by the same or overlapping authors, so the "RIPA extends CK" framing is largely an in-house dialogue without independent adversarial review.
- **The headline studies are confounded or toy by design.** In the B1 operational case, the second step swaps model AND harness simultaneously (Codex/gpt-5 → Claude Code/claude-opus-5), so no model-only effect is isolated — the authors admit the 12 Claude probe responses are recorded client/runtime identifiers, not attestations, and establish no equivalent inference budgets. The Telegram step never tests a user-message-to-agent-reply round trip. The B2 task is tool-free arithmetic with fixed model results (28+28=56, a fixed multiplier) — ideal for exact witnessing, but it says nothing about migrating arbitrary repository workflows, active inference processes, or provider-native sessions, all explicitly out of scope.
- **Evidence hygiene is unusually good, which partly compensates.** The abstract and Section 9 pre-empt overclaiming ("do not establish behavioral equivalence, arbitrary-task portability, general exactly-once external effects or unattended reliability"), Table 4 maps every invariant to its coverage boundary (e.g., I4's fencing is attempt-local with no extended crash-trial or detached-copy trial; no combined live migration and body-evolution trial), and quirks are disclosed: Muse reports placeholder zero token counts treated as missing, wall times include operator/transport delay, F's first returned fault package omitted the recovery record and needed a supplement, the stale-reply helper's exit code 3 is operator-observed only, and B2's served Codex backend is "not independently attested" with provenance via tree equality (643dfa196e93f…) rather than commit IDs.
- **Authority guarantees are local, and the paper says so.** Fencing is enforced within the installed root; a detached copy with independently usable credentials is outside the boundary; enforcing authority against such copies requires provider-side fencing or an external authority service that does not exist here. The fault case uses one prescribed cut (before any reply), and the recovery boundary is not crash-atomic (SIGKILL bypasses exception rollback). No statistical reliability, operator burden, cost, or latency overhead of the six-phase protocol is measured — for a system whose value proposition is operational continuity, the absence of any overhead/cost numbers is the biggest practical gap.

## Strengths

- Crisp, reusable conceptual separations: session continuity vs agent continuity; "a transcript is raw interaction evidence, not automatically memory"; and especially "copying memory does not copy authority" — two copies can hold identical memories and answer identity questions identically, yet only the authorized successor may resume as sole continuation.
- Deterministic, checkable evidence: 26-condition verifier conditions, 18 provenance/no-repair checks per ordinary trip, 14 demonstrated source fences, exact arithmetic witnesses (56 = 28+28), and hash-level identity/memory preservation — a refreshingly mechanical standard compared with vibe-checked agent demos.
- The invariant-to-evidence coverage map (Table 4) is a model of scoped claims: every row names both the implemented check and the boundary of what it does not establish.
- Real end-to-end exercises across actual deployment bindings (Codex, Claude Code, Slack, Telegram, launchd/systemd, Git/GitHub), not just unit tests, plus a public, hash-pinned archive and offline verifier enabling partial third-party checking without model access.

## Limitations

- Single evolving Enoch body lineage; no causal isolation of any architecture axis and no ablations (e.g., what breaks without fencing epochs or generation floors is never shown).
- Synthetic tasks are toy, tool-free, driver-orchestrated arithmetic; migration of arbitrary repository workflows, live inference processes, and provider-native sessions is undemonstrated.
- All live studies are single-instance, supervised, and author-curated; private-state evidence is withheld; no statistical reliability estimates, no cost/latency/operator-burden measurements, no comparison against any alternative migration approach.
- Authority is enforced only locally: no distributed mutual exclusion, no provider-side rejection of detached copies, no coordinated multi-embodiment policy; the recovery boundary is not crash-atomic against SIGKILL, and automatic recovery from every partial-write state is undemonstrated.
- Behavioral identity fidelity is explicitly left to the companion PAI-Bench work — an authorized successor may behave differently, and the paper offers no data on how much.

## Relevance

与你最高优先级的"长程自主 agent 系统的可靠性与可信性"方向直接对口：论文处理的正是 agent 跨模型/框架/宿主替换时的身份、记忆与检查点连续性、fencing/幂等与"恰好一次"外部效应边界，对自演化 agent 的持久化基础设施和权威治理设计有直接参考价值。不过它是 cs.SE 系统架构/立场论文，与训练稳定性、数值精度或可解释性无关，且实证规模很小、无外部基线，价值主要在概念框架与开源实现本身。

## Questions for Further Exploration

- What happens on a crash during an external side effect — after an idempotency-keyed effect is published but before reconciliation? The planned fault F only cuts before any reply.
- Can PAI-Bench-style behavioral identity fidelity be composed with RIPA's mechanical continuity, to measure whether an authorized successor actually "behaves like" its predecessor (and whether an unauthorized copy that answers identity questions correctly can be caught)?
- What would a concurrent multi-embodiment authority policy look like — is there a CK-style activation layer that supports coordinated replicas with reconciliation instead of sole authority?
- Does the six-phase protocol extend to live inference sessions and provider-native conversation state (both explicitly excluded here), and what is its overhead (time, operator actions, cost) on tool-using, long-horizon workloads rather than fixed-result arithmetic?
- How does the migration machinery behave under an unauthorized detached copy that replays the exported bundle — the paper shows source fencing, but provider-side rejection of such copies remains an open systems problem.
