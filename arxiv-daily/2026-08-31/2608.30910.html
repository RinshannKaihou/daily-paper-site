S3C-LLM: Skill-Code Guided Agentic Language Models for Spectrum-to-Structure Elucidation

Key metric
+0.183
Tanimoto over SpectraLLM

MS/MS structure similarity: 0.6382 vs 0.4554 on the Multimodal Spectroscopic Dataset — DiffMS reaches only 0.3535.

500K trajectories (<1/10 of SpectraLLM's 5.5M spectra) · 4B vs 32B backbone
Why this matters

A concrete recipe for self-evolving agent skills and step-level verifiable-reward RL on long tool-use chains — directly reusable for training reliable scientific agents.

Critical edge

On experimental MassSpecGym the margin collapses to +0.030 over SpectraLLM — headline gains come predominantly from clean, simulated spectra, with no error bars or significance tests reported.

01 Methodology

spectra → read_skill → run_code → evidence + constraints → SMILES

  • Skill library. An external Claude Opus 4.6 + Claude Code agent runs 20 predict→verify→diagnose→revise iterations per modality (50 spectra each), yielding 8 Markdown skills — IR, Raman, UV-Vis, ¹³C/¹H NMR, HSQC, simulated NMR, MS/MS. Only deterministic, high-confidence spectral rules are admitted.
  • Trajectory synthesis. Claude Code writes executable analysis code per spectrum (mass differences, formula enumeration, diagnostic-region matching), packaged into 500K tool-use trajectories over two tools: read_skill and run_code. GPT-5.4 reverse-engineers thinking traces; ~100K pass a re-prediction filter, the other 400K keep loss-masked empty <think> blocks.
  • Training. Qwen3-4B: SFT first, then step-level GRPO on 20K trajectories — per-step verifiable rewards (skill–modality match, error-free code, Morgan-fingerprint Tanimoto), reward-to-go normalized within the same step index so structure rewards propagate back to early skill-retrieval steps. γ=0.35, no KL penalty.
  • Reframe. The model learns ρ(τ, y | x) — trajectory-conditioned prediction — instead of ρ(y | x).

  • General LLMs are near-useless on these tasks: best Raman Tanimoto is 0.1004 (GPT-5.5); Claude-Opus-4.7 reaches 0.0901.
  • Training-stage ablation (MS/MS): SFT-only 0.5542 → +trajectory-RL 0.5832 → +step-RL 0.6382. Step-RL without SFT collapses to 0.1310 — the model never learns the tool-use format.
  • Toolset ablation (MS/MS): chat-only 0.37 → +read_skill 0.5128 → +run_code 0.6382. Executable computation matters most for HSQC and MS/MS, where cross-peak relations and mass constraints benefit from code.
  • Skill quality climbs over 20 evolution rounds to 0.87 (HSQC), 0.79 (¹³C), 0.67 (¹H) precision on skill-supported claims.
  • Trajectory-RL actually hurts ¹H NMR vs SFT-only (0.1847 vs 0.1914) — the step-level advantage is real but not a clean sweep.

03 Strengths

  • +Consistent, large gains across optical, NMR, and MS/MS families against both general and spectrum-specific baselines, on SpectraLLM's own splits.
  • +Striking data efficiency: <1/10 the paired-spectrum corpus and 1/8 the backbone — explicit skills plus code offload what end-to-end models must memorize.
  • +The intermediate evidence chain (retrieved skill + code output) makes predictions auditable — a real advantage over black-box mapping for scientific use.
  • +Step-level RL is well-motivated and cleanly implemented; the Only-Step-RL collapse (0.1310 vs 0.6382) shows SFT bootstrapping is necessary.
  • +Unusually inspectable: three-pronged ablations plus full skill files and rollout trajectories in the appendix.

04 Limitations

  • −Inputs are compact peak-level text; raw noisy instrument spectra are out of scope, capping real-lab applicability.
  • −The SOTA claim weakens exactly where it matters: on experimental MassSpecGym the delta over SpectraLLM is only +0.030; MS/MS training leans on simulated spectra with clean mass constraints.
  • −Skill quality uses a precision-only proxy that ignores recall of unsupported functional groups — a conservative library can score 0.87 while missing much.
  • −"Self-evolution" oversells: the pipeline distills Claude Opus 4.6 chemistry knowledge and GPT-5.4 traces — careful data engineering, not open-ended self-improvement.
  • −Reproducibility depends on proprietary API pipelines; no release of skills, trajectories, or code is mentioned. Inference latency and code-failure rates are unmeasured.
  • −All headline numbers are similarity metrics; no exact-match top-k accuracy, no error bars or significance tests anywhere.

05 Questions for Further Exploration

  1. Could the skill-evolution loop be run against noisy calibration data (e.g., the MassSpecGym training split) to evolve noise-robust skills for fully experimental spectra?
  2. Can skills transfer or compose across modalities, and can the library grow open-endedly beyond the 8 hand-defined modality slots?
  3. How does the step-level reward scheme (same-step group normalization, no KL, γ=0.35) compare to outcome-only GRPO as intermediate rewards get sparser or noisier in other tool-augmented scientific domains?
  4. Would an equal-data, equal-size control (direct-mapping SFT of Qwen3-4B on the same 500K examples) isolate the skill-code formulation from data-curation effects?
  5. What is the production inference cost and failure profile (code-execution errors, retrieval mistakes), and can skill staleness be detected and repaired continuously after deployment?
