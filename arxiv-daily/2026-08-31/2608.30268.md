> **一句话总结：** 港科大团队用一个多智能体 LLM 发现框架（8 个并行 Hypothesis Agent + Critic + 3 条 Programmer–Verifier 链 + 固定 Evaluator）审查 SOTA 时序驱动布线树算法 SALT，发现其"逐 sink 修复"永远无法联合决定共享根部走线的分叉点，据此提出 FABO：把每条 root-to-sink 路径的合法断点表示为一个连续可行区间，在区间重叠处联合选择共享断点；在 129 万个 ICCAD15 网络上于全部 20 档 stretch 容差下平均 FLUTE 归一化线长全面优于 SALT（整体峰值 −0.83%，≥30 pin 网络峰值 −2.66%，样例网络最高 −10.85%），且不放宽任何 sink 的路径预算。

> **TL;DR:** The paper asks whether LLM-agent-guided search can beat SALT (ICCAD'17, the state-of-the-art constructive algorithm for shallow-light Steiner trees that minimizes wirelength under a per-sink stretch budget). A multi-agent framework — 8 isolated Hypothesis Agents, a Critic, 3 parallel Programmer–Verifier chains, and a fixed tree-checking Evaluator around a file-based single source of truth — uncovered a structural flaw in SALT: it repairs one violating sink path at a time, so it never jointly decides where paths sharing root-side wire should split, duplicating wire. FABO (Flow-Aware Breakpoint Optimization) fixes this by representing each path's legal breakpoints as one contiguous interval, selecting shared breakpoints from interval overlaps, and counting an edge as saved only when every flow using it leaves. On 1.29M ICCAD15 nets across SALT's 20-point ε schedule, FABO beats postprocessed SALT on mean FLUTE-normalized wirelength (β) at every setting — peak 0.83% overall (β 1.0312 → 1.0227 at ε=0.1125) and 2.66% for nets with ≥30 pins — with a worked example cutting one 8-pin net 10.85%. Because full FABO costs 10.66× SALT's runtime, FABO-FAST uses an XGBoost gain predictor to recover 99–100% of ≥25%-gain nets at 1.3× SALT runtime. Code: github.com/DevinShang/routing-FABO.

## 核心贡献

- **面向算法发现的多智能体框架**：针对串行单 agent 的两个弱点（路径依赖地修补同一构造、 unchecked 错误会污染后续所有决策），设计了"生成—检查"贯穿全流程的框架：8 个隔离上下文的 Hypothesis Agent 提出不同结构机制 → Critic 审查假设并固化为 3 份 New Idea Spec → 3 条并行 Programmer–Verifier 链独立验证实现 → 固定 Evaluator 校验完整布线树和每条路径预算 → 结果连同代码/日志/证据写入文件式 SSOT（单一事实源），由 Scheduler/Monitor 驱动恢复。每次运行被分类为实现失败 / 构造失败 / 已验证负结果，负结果的诊断驱动下一轮转向"共享根部结构的位置"问题，最终催生 FABO。
- **发现 SALT 的结构性瓶颈**：SALT 对超预算路径逐 sink 打开断点、为单个 sink 拉一条新最短路并保留后缀，其贪心修复和逐节点移动的后处理从不表示"一组共享根部走线的流应在何处停止共享"这一联合决策，导致过早分叉、重复布线；高扇出网络上未利用的共享随 fanout 增长。
- **FABO（Flow-Aware Breakpoint Optimization）**：把决策单元从单个 sink 改为一组共享根部线的流（flow）。核心机制：① Lemma 1 证明每条流的预算可行断点恰为一条以 sink 结尾的连续区间 I_t=[f_t, t]；② 贪心选取最小初始断点集覆盖所有区间（Theorem 1 证明其最小性）；③ 以"全有或全无"的逐边释放账目（Lemma 2）给更深断点打分——只有当使用某条支撑边的所有流都离开时该边才算被释放；④ 候选树只有通过固定 Evaluator 的完整预算校验且线长更短才被接受（Theorem 2 保证可行性），因此 FABO 返回的树不劣于其已验证的第一阶段树。
- **质量—运行时兼顾的 FABO-FAST**：完整 FABO 在 ε=0.1125 需 10.66× 全网 SALT 运行时；FABO-FAST 先全网跑 SALT，再用 22 特征、深度 4 的 96 棵树 XGBoost 预测器（八折 leave-one-design-out 训练）按期望增益排序选网优化，1.3× SALT 运行时即可找回 99.0%–100% 的高增益（≥25%）网络。

## Key Contributions

- **A multi-agent framework for reliable algorithm discovery** in an NP-hard EDA problem: parallel Hypothesis Agents broaden the structural search beyond one reasoning trajectory, while independent Critic / Verifier / Evaluator checks isolate implementation errors from algorithmic evidence at every stage handoff. Evidence (code snapshots, build logs, metric files, verification reports) accumulates in a file-based SSOT across rounds, and negative-result diagnoses are explicitly used to redirect the search.
- **Discovery of a structural bottleneck in SALT**: sink-by-sink repair never jointly chooses the breakpoint for paths sharing root-side wire, so SALT's trees can split these paths earlier than necessary and duplicate wire — the miss grows with fanout. A traced example (superblue18 net 323, 8 pins, ε=0.1125) shows SALT using none of the permitted 11.25% stretch.
- **FABO**, which changes the decision unit from one sink to the group of flows sharing root-side wire: feasible breakpoints form one exact contiguous interval per flow (Lemma 1), a provably minimum greedy cover initializes the breakpoint set (Theorem 1), a flow-aware all-or-nothing per-edge gain ranks deeper shared breakpoints (Lemma 2), and only complete realized trees that pass every sink budget and improve wirelength are accepted (Theorem 2) — so joint group-level savings become explicit while every sink's stretch guarantee is preserved.
- **Quality at scale with a practical runtime option**: dominance over SALT at all 20 tolerance settings on 1.29M nets, fanout-monotone gains (peak 2.66% at ≥30 pins), a mechanism test via a shared-trunk-fraction metric, and FABO-FAST, which recovers most high-gain nets within 1.3× SALT's runtime via a leave-one-design-out XGBoost predictor.

## Methodology

**Problem.** Given a root pin r and sinks P on the Manhattan plane, construct a rectilinear Steiner tree T minimizing wirelength WL(T) subject to per-sink budgets dT(r,t) ≤ Bt = (1+ε)·dM(r,t) — SALT's shallow-light formulation. Quality is reported as shallowness α (max normalized root-to-sink path length), FLUTE-normalized wirelength β = WL(T)/WL(T_FLUTE), and SALT's normalized Elmore-delay metric γ; ε=0 forces Manhattan-shortest paths to every sink (minimum arborescence limit), and as ε grows the optimum approaches a Steiner minimum tree.

**Agent-guided discovery loop.** Each round starts from the SSOT (verified conclusions + links to code and artifacts). A Web Search Agent retrieves relevant math (rooted-tree structure, geometric piercing). Eight Hypothesis Agents in isolated contexts propose mechanisms with explicit assumptions and measurable predictions; the Critic checks them against routing constraints, rejects inconsistent ones, and emits three fixed New Idea Specs. Three Programmer–Verifier chains implement them in parallel, each Verifier independently checking the implementation against the spec (one recorded catch: empty stubs in a SALT reproduction let the binary run after a missing dependency disabled required postprocessing — classified as implementation failure, not algorithmic evidence). A fixed Evaluator checks tree validity (connected, acyclic, contains every pin) and every root-to-sink budget before measuring exact wirelength. Results enter the SSOT labeled implementation failure / construction failure / verified negative; two implemented candidate families that produced no gain redirected the search from local attachment changes to shared root-side structure, producing the flow-level breakpoint formulation. An external Scheduler/Monitor polls files and restarts interrupted agents from their latest artifacts.

**FABO algorithm (per support tree, FLUTE-based).** (1) For every sink compute its feasible breakpoint interval I_t = T₀[f_t, t]: placing the breakpoint at x keeps the support suffix s_t(x) and rebuilds a Manhattan wire dM(r,x) from the root, so feasibility is dM(r,x)+s_t(x) ≤ Bt; moving x deeper never increases this bound (triangle inequality), giving one contiguous interval ending at the sink. (2) Greedily cover all proper intervals (f_t ≠ r) by their boundaries in non-increasing depth — Theorem 1 proves the resulting set has minimum size — then add the root. Each sink is assigned the deepest selected point in its interval. (3) Refinement proposes deeper breakpoints from a bounded constant-size pool, ranked by a fixed score dominated by the flow-aware gain G(a) = total length of support edges released (an edge counts only when *all* its flows leave — the all-or-nothing account), plus terms rewarding flow movement depth and proximity to existing breakpoints. (4) A candidate is realized as a rectilinear connector hitting each breakpoint at its Manhattan distance (FULL/FAST Realize variants), grafted with retained suffixes, passed through SALT's own postprocessing, and accepted only if valid, budget-feasible on every sink, and lexicographically better in (WL, α) than the incumbent. On nets with ≥31 pins FABO repeats the search on a second, higher-accuracy FLUTE support and keeps the better valid tree. The paper is explicit about what is proven (intervals, cover minimality, feasibility, release condition) versus heuristic (candidate ranking, connector construction, support choice — complete-tree evaluation is the only acceptance rule).

**FABO-FAST.** Run SALT on every net; a depth-4, 96-tree XGBoost predictor using 22 pre-computable features (pin count, bounding-box geometry, FLUTE wirelength/path statistics, SALT wirelength/stretch/delay) ranks nets by expected gain; FABO runs in that order until the runtime budget b = T_FAST/T_SALT is exhausted, and each selected net keeps the shorter of its feasible SALT and FABO trees. Predictors are trained per ε with eight-fold leave-one-design-out, so every net gets an out-of-design prediction.

## Results & Highlights

- **Dominance at every operating point.** On 1,294,541 ICCAD15 nets (≥3 pins, 8 superblue designs) across SALT's 20-point ε schedule, FABO achieves lower mean FLUTE-normalized wirelength than postprocessed SALT at all 20 settings without increasing mean α or γ. Peak full-benchmark reduction is 0.83% at ε=0.1125 (β 1.0312 for SALT → 1.0227 for FABO); at the strictest ε=0 both reach α=1.000 but FABO's β is 1.0388 vs SALT's 1.0429 (−0.39%). On the Pareto frontiers, FABO first reaches β<1.001 at α=1.2062 vs SALT's α=1.2298, and at γ=1.5235 vs SALT's γ=1.5340.
- **Gains grow monotonically with fanout.** Across the 20 tolerances the maximum per-ε reduction is 0.31% for 3–9-pin nets, 1.70% for 10–19, 2.15% for 20–29, and 2.66% for nets with ≥30 pins; 3–9-pin nets are 69.9% of the benchmark, which is why the overall peak (0.83%) is much smaller than the high-fanout peaks.
- **Mechanism test confirms the shared-trunk story.** FABO's mean shared-trunk fraction RT(50%)/WL at ε=0.1125 is 49.38% vs SALT's 48.74% over all 1.29M nets. Grouping nets into terciles by SALT's own sharing metric, FABO's reduction is 1.38% in the low-sharing tercile, 0.80% in the middle, and 0.12% in the high-sharing tercile — the largest savings land exactly where SALT preserves the least shared wire.
- **Worked cases.** Superblue18 net 323 (8 pins, ε=0.1125): SALT 1,042,970 → FABO 929,794, a 10.85% reduction under identical budgets (t₂ spends its full permitted detour, 67,488 extra path length, to release 180,664 via sharing). Superblue16 net 42 at ε=0: both α=1.000, FABO 5.06% shorter by moving the shared breakpoint deeper.
- **Runtime and FABO-FAST recovery.** Full FABO at ε=0.1125 costs 10.66× all-net SALT runtime (SALT 62.43 s; FABO adds 602.83 s; prediction 0.872 s). At budget b=1.3, FABO-FAST recovers 99.0%–100% of nets with ≥25% full-FABO gain and 96.0%–99.3% of the 20%–25% group across the four plotted ε values; recovery drops monotonically to 21.0%–45.3% for the 5%–10% group, evidencing correct high-gain-first ranking. At b=2, the ≥20% groups are recovered at 98.9%–100%.
- **Honest benchmark accounting.** A footnote discloses that the released benchmark (1.29M nets ≥3 pins, no 2-pin nets) differs from the SALT paper's reported 2.38M nontrivial nets, mostly in the 3–9-pin bucket — both methods use the same released files and evaluator, so the comparison stands.

## Critical Assessment

- **The average gain is real but small, and the headline relies on stratification.** The full-benchmark peak of 0.83% is modest; 69.9% of nets are 3–9 pins, where the maximum gain is only 0.31%. The 2.66% figure applies to the 58.3k nets with ≥30 pins (4.5% of the benchmark). To the authors' credit they report both views and explain the averaging effect, but a reader skimming the abstract could overestimate the practical impact.
- **Single benchmark family.** All evaluation is on the eight ICCAD15 superblue designs distributed with SALT's repository. No ISPD/other benchmark suites, and no comparison against the other cited timing-driven tree methods (PD-Rev, PatLabor, Wu et al.) — the paper argues they optimize complementary objectives and are "not a direct replacement," which is defensible but leaves the empirical landscape thin.
- **Runtime accounting for FABO-FAST is incomplete.** The budget multiplier b counts SALT on all nets plus FABO on selected nets, but the XGBoost predictor's labels come from running *full FABO on every net* at each ε (the recovery denominator requires it) — the offline cost of generating training data, training per-ε models (a separate predictor per tolerance), and the risk of predictor degradation on unseen designs are not charged. Leave-one-design-out is a good evaluation protocol, but deploying this in production means re-labeling on new netlists.
- **Geometry-only evaluation.** All metrics (α, β, γ under unit R/C Elmore) are pre-route geometry proxies. There is no detailed-routing experiment (congestion, DRC), no extracted parasitics, and no sign-off timing — so the downstream benefit of a 0.83% mean wirelength reduction on real timing closure remains asserted rather than demonstrated.
- **The agent framework is narrated, not audited.** The number of search rounds, LLM calls, token cost, and failure statistics across rounds are not reported, and the discovery of the SALT bottleneck is presented via a cleaned-up narrative (two failed candidate families, then the insight). A skeptical reader can ask whether a skilled human algorithm designer — or simply an ablation over FABO's own components — would reach the same point; there is no ablation isolating the contribution of the multi-agent scaffold versus a single-agent baseline on this task, despite the framework being a headline contribution.
- **Genuine strengths in rigor.** The paper is unusually careful for an "LLM discovers an algorithm" paper: proofs are given and their scope is honestly delimited (Theorem 1 minimizes only breakpoint count, G(a) ranks but does not guarantee net gain), every accepted tree is machine-checked against all budgets, ties are broken deterministically, the SALT-reproduction stub bug is disclosed as a motivation for verification, and the benchmark-size discrepancy with the SALT paper is footnoted rather than hidden.

## Strengths

- A crisp, provable core idea: feasible breakpoints form one contiguous interval per flow (Lemma 1), turning "where should a group of paths stop sharing a trunk" from an unrepresented joint decision into explicit interval-overlap selection, with feasibility of every realized candidate guaranteed by Theorem 2 and enforced by a fixed evaluator.
- Strong empirical methodology: 1.29M nets, all 20 of SALT's tolerance settings, same input and checker for both methods, fanout-stratified and sharing-tercile analyses that actually test the proposed mechanism (larger gains where SALT shares less) rather than just aggregating averages.
- The FABO-FAST predictor analysis is well designed: leave-one-design-out per ε, recovery measured against ground-truth full-FABO gains, and a monotone recovery-vs-gain curve that demonstrates the ranking works.
- Intellectual honesty: guarantees vs heuristics are explicitly separated; the benchmark discrepancy with the SALT paper and the caught SALT-reproduction bug are disclosed; code is released.
- The multi-agent design (isolation to avoid path dependence, independent verification to separate implementation bugs from algorithmic evidence, SSOT-based resumability) is a sensible, transferable template for algorithm-discovery agents in domains with cheap mechanical verifiers.

## Limitations

- Overall mean improvement is sub-1% on the full benchmark; value concentrates in high-fanout nets, so adopters must care about those (clock/power trunk nets) to justify integration.
- Full FABO costs 10.66× SALT runtime at the peak setting; the practical variant depends on learned per-ε predictors whose training-label generation is expensive and whose transfer to new designs is untested.
- Evaluated only on ICCAD15 geometry benchmarks with unit-RC Elmore delay; no detailed routing, congestion, or sign-off-timing evidence.
- No empirical comparison with other timing-driven tree constructions (PD-Rev, PatLabor, Wu et al.) even as a reference point.
- The agent framework's own cost, round count, and ablation against simpler search strategies are unreported, so its contribution relative to plain careful algorithm design is not quantified.
- Several search constants (pool size, refinement rounds, the ≥31-pin second-support rule, the weighted ranking score with two auxiliary terms) are fixed by hand and only "released with the code" — their sensitivity is not studied.

## Questions for Further Exploration

- How much of the gain comes from the multi-agent scaffold itself? An ablation replacing the 8-Hypothesis-Agent/Critic loop with a single serial agent (or random/greedy search over the same spec space) on the same task would substantiate the framework claim.
- Could FABO's interval-overlap selection be made optimal (minimum wirelength over breakpoint sets is a covering problem on paths — is the greedy-plus-refinement gap bounded)?
- Does the wirelength reduction survive detailed routing and real parasitics — e.g., on high-fanout clock nets, does the larger shared trunk reduce congestion hotspots or worsens them by concentrating demand?
- Can a single FABO-FAST predictor generalize across all ε values (one model, tolerance as a feature) instead of per-ε retraining, and how does it transfer to a completely new design family without re-labeling?
- Would the same generate–check agent framework transfer to adjacent EDA discovery problems with cheap verifiers (e.g., clock-tree synthesis, buffer insertion), where the structural-bottleneck pattern of a greedy baseline may also exist?
