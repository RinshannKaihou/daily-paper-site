> **一句话总结：** 单人完成的受控测量研究证明：在贪心解码、固定种子、batch size 1、串行请求下，关闭前缀缓存时重复执行逐比特一致（800 个 episode 中 0 次分歧），而开启缓存后同一请求会改变智能体轨迹（llama.cpp 上 Qwen2.5-7B 从 F16 的 36.2% 升到 Q4_K_M 的 70.0%、Q3_K_K_M 的 77.5%，Cochrane-Armitage 趋势检验 p=1.3×10⁻⁸），并进一步定位到 llama.cpp 默认开启的服务器级 host-memory prompt cache 才是 run-to-run 分歧的真正来源（单独一个开关就把重跑分歧从 38.8% 降到 1.2%，Δ37.5 个百分点），但任务正确性在双向翻转、总体准确率不动——是"不稳定"而非"变差"。

> **TL;DR:** On an 80-episode Berkeley Function Calling Leaderboard (BFCL) multi-turn agentic workload served greedily at batch size 1, cache-disabled reruns are bit-identical (0 of 800 episodes diverged across ten configurations on llama.cpp and vLLM), while enabling prefix caching changes the agent's trajectory on 36.2% of episodes at F16 and 77.5% at Q3_K_M for Qwen2.5-7B on llama.cpp (Cochrane-Armitage trend z=5.68, p=1.3×10⁻⁸) versus 62.5% cross-arm on vLLM FP16 — quantization amplifies but does not cause the divergence. Three isolation experiments pin run-to-run divergence not on the prefix cache but on llama.cpp's default-on server-level host-memory prompt cache: disabling it moves re-run divergence from 38.8% to 1.2% (-37.5 pp), and restoring cache state makes the cached path reproduce on 40/40 items while still differing from the recompute path on 14/40. A GSM8K single-turn bridge shows correctness flips occur in both directions (13 cached-favor vs 7 recompute-favor, McNemar p=0.26) with aggregate accuracy unchanged at 89-93% — cached serving is unstable, not worse.

## 核心贡献

- **干净的基线（RQ1）**：在贪心解码、温度 0、种子 42、batch size 1、串行请求的受控条件下，跨两个引擎（llama.cpp b10434、vLLM 0.11.0）和四种权重格式（F16 到三比特量化）的十个配置全部重复执行完整 80-episode 智能体工作负载：**800 个 episode 中 0 个分歧**，逐 episode 分歧率 95% 置信上界 1.6%，十个配置合并后上界 0.5% —— 证明其余一切差异都来自缓存。
- **量化放大效应（RQ3）**：开启缓存后，Qwen2.5-7B 在 llama.cpp 上的跨臂轨迹分歧随量化变粗单调上升：F16 36.2% → Q8_0 61.3% → Q4_K_M 70.0% → Q3_K_M 77.5%（Cochrane-Armitage z=5.68, p=1.3×10⁻⁸）；16 比特下分歧已经存在，量化是**放大器而非原因**——粗量化压缩候选 token 的 logit 差距，同样的数值扰动能翻转更多决策。
- **定位真正机制（RQ2）**：三个隔离实验证明 run-to-run 分歧不是执行顺序、而是 llama.cpp 默认开启的**服务器级 host-memory prompt cache**（2025 年 10 月引入，按最长公共前缀相似度选取、最旧优先淘汰、默认 8192 MiB）：仅改变执行顺序两次输出逐字节一致；关闭该层把重跑分歧从 38.8% 压到 1.2%（Δ37.5 个百分点）；恢复缓存状态后缓存路径 40/40 可复现、但两条路径仍在 14/40 上互相不同——缓存服务在给定缓存状态时是确定性的。
- **结果层面的"不稳定而非退化"（RQ5）**：GSM8K 单轮桥接实验中正确性翻转双向发生（20 次翻转中 13 次偏向缓存路径、7 次偏向重算路径，McNemar p=0.26），总体准确率（89–93%）不动；智能体工作负载成功率太低（1.2%–18.8%），12 对 vs 7 对翻转不足以做统计检验——作者明确拒绝从这些数据得出"缓存降低准确率"的结论。
- **可复现性基础设施**：公开完整 harness、逐请求原始日志（含 prompt hash、发射的 token 标识符、log 概率、时延、逐请求缓存暴露量）和分析脚本（github.com/aditi-pdl/cache-divergence-study），论文中每个数字都可由脚本重新生成；还披露并修正了自己打分器的一个格式化伪影（曾把 11%–38% 的回答错判为错误、使翻转计数虚增约四倍）。

## Key Contributions

- **A clean determinism baseline (RQ1):** under greedy decoding, temperature zero, fixed seed, batch size one, and serial requests, repeating the full 80-episode agentic workload is bit-identical in every one of ten configurations across llama.cpp and vLLM — 0 of 800 episodes diverged (per-episode rate bounded at 1.6% at 95% confidence; pooled upper bound 0.5%). Any divergence elsewhere in the paper therefore cannot be attributed to sampling, scheduling, or engine noise.
- **Quantification of cache-induced divergence and its quantization gradient (RQ3):** with caching enabled, cross-arm trajectory divergence for Qwen2.5-7B on llama.cpp rises monotonically with coarser weights — 36.2% (F16), 61.3% (Q8_0), 70.0% (Q4_K_M), 77.5% (Q3_K_M); Cochrane-Armitage z=5.68, p=1.3×10⁻⁸. Divergence exists already at 16-bit, so quantization is a multiplier, not the cause: coarser quantization compresses competing token logit gaps so the same numerical perturbation flips more decisions.
- **Isolation of the actual mechanism (RQ2):** three controlled experiments show the driver of run-to-run divergence is not execution order but llama.cpp's default-on server-level host-memory prompt cache (a second caching layer distinct from the per-request prefix cache, introduced October 2025, longest-common-prefix selection, oldest-first eviction, 8192 MiB default): reordering passes alone yields byte-identical output; disabling that layer moves re-run divergence from 38.8% to 1.2% (-37.5 pp); restoring cache state makes the cached path reproduce 40/40 while the two paths still differ on 14/40 — cached serving is deterministic given cache state, and irreproducible in practice because that state is invisible, unreported, and never reset.
- **Outcome-level result: instability without direction (RQ5):** on the GSM8K single-turn bridge, correctness flips occur in both directions (13 favor the cached path vs 7 the recompute path among 20 flips; McNemar p=0.26 pooled) while aggregate accuracy sits at 89-93% and does not move; the agentic workload's success rates (1.2%-18.8%) sit too near the floor for the 12-vs-7 paired flips to support a statistical test, and the authors explicitly decline to claim accuracy degradation.
- **Reproducibility infrastructure and unusual honesty:** released harness, raw per-request logs (prompt hash, emitted token identifiers, log probabilities, latency, per-request cache exposure), and analysis scripts that regenerate every number in the paper; the paper also discloses and corrects a scorer artifact of its own (a format-sensitive checker mis-scored 11%-38% of responses and inflated flip counts roughly fourfold).

## Methodology

**Paired, within-arm-controlled design.** A "cell" is one complete pass of the workload through one serving configuration; every configuration is run twice in full, so each arm is compared against itself. The cache-disabled within-arm comparison is an internal validity check: any difference there would mean an uncontrolled confounder. The only manipulated variable across arms is the cache setting; weights, engine build, sampling parameters (greedy, temperature zero, seed 42), request order, and hardware are frozen within a configuration. The KV cache is held at 16-bit floating point in every arm so cache precision never co-varies with weight format. Batch size is one and requests are serial, explicitly removing batch-composition nondeterminism [11] from the picture.

**Workloads.** (1) The multi-turn base category of the Berkeley Function Calling Leaderboard (BFCL): 80 episodes selected deterministically (first 80 entries in ascending numeric identifier order), each episode issuing roughly 7-13 requests (~10 average) as the agent re-sends its growing transcript — exactly the shape prefix caching accelerates. (2) A single-turn GSM8K bridge: models solve ~9 in 10 (accuracy 89-93%), leaving room for flips in both directions; each item is served four times, twice on the recompute path and twice on the cache-hit path, giving a per-path determinism check so a difference between paths is only counted as cache-attributable when each path agrees with itself.

**Engines and models.** llama.cpp (built from source, b10434, commit 764e098, CUDA offload) with GGUF weights F16/Q8_0/Q4_K_M/Q3_K_M, and vLLM 0.11.0 (PyTorch 2.8.0+cu128, transformers 4.57) with FP16. Models: Qwen2.5-7B, Qwen2.5-14B, Llama-3.1-8B. Hardware: one NVIDIA RTX 4090 (24 GB, compute capability 8.9), Ubuntu 24.04, CUDA 12.6, driver 570.211.01 (580.126.20 for the isolation experiments). SGLang was planned but dropped under a pre-registered budget rule ("first component dropped if the compute allowance required it") — disclosed, with no numbers reported.

**Isolating the cause (all on Qwen2.5-7B Q4_K_M, llama.cpp).** (1) Execution-order arm: an interleaved cache-disabled pass between the two cache-enabled passes to match ordering — divergence unchanged. (2) Prompt-cache-disable arm: llama.cpp maintains a server-level host-memory prompt cache (whole-conversation states selected by longest common-prefix similarity, oldest-first eviction, on by default at 8192 MiB since October 2025); disabling that layer with everything else fixed isolates its contribution. (3) Cache-state-restore control: each of 40 items served four times (twice recompute, twice cache-hit, cold state re-established before each recompute pass, zero cached-token counts verified from telemetry on cold requests); if both paths then reproduce internally while still differing from each other, the divergence is a function of cache state, not residual randomness. Because the engine's cache-clear endpoint is unreliable, cache state was controlled via the per-request recompute flag validated against reported cached-token counts.

**Measures.** Divergence on emitted token identifiers (llama.cpp) or token strings (vLLM) — a strict, de-minimis criterion where even semantically identical answers in different words count; an episode is divergent if any request differs or if the runs contain different numbers of requests (i.e., the agent took a different number of steps). Task outcomes use the benchmark's own checker. Wilson intervals throughout, plus a moving-block bootstrap that preserves neighboring-episode dependence (which widens one headline interval from 28.8-49.7% to 20.0-55.0% — the wider one is reported); exact McNemar tests on within-item paired flips, with multiplicity and power analysis (81% power against a net 1-point shift over 1300 items).

## Results & Highlights

- **Cache-disabled reruns are bit-identical (RQ1):** 0 of 800 episodes diverged across all ten configurations (both engines, F16 down to 3-bit weights), bounding the per-episode divergence rate at 1.6% with 95% confidence and at 0.5% pooled over ten configurations — greedy decoding with a fixed seed at batch size one is a deterministic function of the input on these stacks.
- **Enabling the cache changes agent trajectories at scale, and quantization widens the gap (RQ2/RQ3):** cross-arm divergence on llama.cpp for Qwen2.5-7B is 36.2% (F16) → 61.3% (Q8_0) → 70.0% (Q4_K_M) → 77.5% (Q3_K_M) — a 41.3-point spread with Cochrane-Armitage z=5.68, p=1.3×10⁻⁸; re-measured with the confounding server-level prompt cache disabled, the pattern holds (40.0% F16, 81.2% Q4_K_M, 77.5% Q3_K_M). Llama-3.1-8B rises 55.0% (Q8_0) → 70.0% (Q4_K_M) → 68.8% (Q3_K_M); Qwen2.5-14B at Q4_K_M hits 91.2%. On vLLM FP16 the cross-arm rate is 62.5% (Qwen2.5-7B) and 53.8% (Llama-3.1-8B) — the effect is not implementation-specific, though magnitudes differ (vLLM re-run divergence 8.8% vs llama.cpp 20.0% at 16-bit).
- **The server-level prompt cache, not the prefix cache, drives run-to-run divergence (RQ2):** with llama.cpp's host-memory prompt cache at its default, repeating the cache-enabled arm changes 38.8% of episodes (CI 28.8-49.7; moving-block bootstrap 20.0-55.0); disabling it drops that to 1.2% (CI 0.2-6.8) — a 37.5-point move from a single flag. Interleaving a cache-off pass raises default-configuration divergence to 77.5% (Table 1) because passes inherit different cache states; with the layer disabled, order changes nothing (1.2% both ways, byte-identical output). With cache state restored before each pass, both paths reproduce 40/40, yet still differ from each other on 14/40.
- **Single-turn bridge (GSM8K, Table 3):** the cache path changes the emitted output on 3.5% of items at 16-bit but on 41.5-48.0% of items under quantization (45.4% at Q4_K_M on a 500-item run, CI 41.1-49.8); accuracy sits at 89-93% and does not shift — of 20 correctness flips, 13 favor the cached path and 7 the recompute path (McNemar p=0.26 pooled), and a simulated exact test has 81% power against a net 1-point shift over 1300 items. At 16-bit, 3.5% of individual requests diverge while 36.3% of ~10-request agent episodes do under the same comparison: one changed token propagates through every remaining turn.
- **Outcome directionality: instability, not degradation (RQ5):** on the agentic workload, success rates run 1.2% (weakest configuration) to 18.8% (Qwen2.5-14B); paired flips total only 12 (cache-enabled) vs 7 (cache-disabled) across all ten configurations, far from significance, and the authors explicitly draw no accuracy conclusion from the agentic data.
- **A disclosed self-correction:** the original BFCL checker accepted only one answer format and mis-scored 11%-38% of responses on formatting alone, inflating flip counts roughly fourfold; the authors re-derived answers offline and compare numerically — Table 3 reports the corrected figures, and the repair pipeline ships in the artifact.

## Critical Assessment

**Novelty is real but narrower than the title implies, and the paper says so.** The mechanism — a cached and a recomputed path are not numerically equivalent because floating-point addition is not associative and the accumulation order in fused attention kernels changes — was already established by Choudhary and Xu [7] for FP16 single-turn arithmetic, and batch-invariance fixes exist (Thinking Machines [11], SGLang [12]). The genuinely new pieces are: (a) the first controlled measurement of the quantization × cache interaction in multi-turn agent episodes (prior work [8] quantified inference-backend variance but did not isolate caching); (b) the discovery that llama.cpp's second caching layer — the server-level host-memory prompt cache introduced October 2025, on by default — dominates run-to-run divergence; and (c) the outcome-level refutation (on their models and items) of the directional accuracy bias reported in [7], corroborated by concurrent independent work (Loru [27]). The paper frames (c) as "independent replication rather than a new finding," which is the right epistemic posture.

**Rigor is unusually high for a single-author study, with a few dents.** The paired within-arm design, the bit-identical 0/800 control, the cache-state restore experiment (which defuses the "this is a tautology" objection with an experiment rather than an argument), moving-block bootstrap over Wilson intervals, and explicit power analysis are all things most systems papers skip. The dents, mostly self-disclosed: the first ten configurations were collected with llama.cpp's server-level prompt cache left at default, so the within-arm re-run numbers in Table 2 conflate the prefix cache with the second layer — the corrected figures (Section IV-C) are reported, but the original grid's "8.8 to 77.5%" re-run range is only interpretable after reading the correction. The vLLM cache-enabled and cache-disabled arms of the Qwen2.5-7B configuration were launched by different scripts with an explicit GPU memory fraction set in one of them — checked not to matter for the cache-disabled arm (identical across three sessions), but a confound nonetheless, and the vLLM ordering-comparison session is incomplete (one cell without an end-of-run marker). Some controlled quantization cells (16-bit, Q3_K_M) ran once rather than twice, so within-arm values for those cells are not available.

**The "amplification" claim slightly outruns the data at the coarse end.** The trend test is significant and the F16→Q8_0→Q4_K_M climb is convincing, but Q4_K_M and Q3_K_M sit within a few points of each other with overlapping 95% intervals (70.0% vs 77.5%), and the paper's own explanation (below ~4 bits, outputs are constrained enough that cache-path perturbation has less room to change the argmax) means the relationship is saturating rather than cleanly monotone — a 2-point grid cannot distinguish amplification from a step function that plateaus after Q8_0.

**Statistical power on outcomes is honestly but visibly thin.** The agentic success floor (1.2%-18.8%) leaves 12-vs-7 paired flips, which cannot support any conclusion; the GSM8K bridge compensates with 1300 pooled items and 81% power against a 1-point net shift, but six uncorrected per-configuration McNemar tests with no significant result is exactly the situation where a nominal single "significant" test would have been over-read — the authors say so themselves, which is to their credit, but the outcome half of the paper is ultimately a null result on small-to-medium evidence.

**Reproducibility of the artifact is a strength, with caveats in scope.** The released logs include per-request cache exposure, prompt hashes, and emitted token identifiers, and pinned engine versions, model checksums, and launch flags — every figure regenerates. But external validity is narrow by design: three open-weight models (7-14B) on one consumer RTX 4090, two engines, one agentic benchmark plus GSM8K, all English, serial batch-size-one traffic. Nothing here speaks to frontier models, hosted endpoints, multi-tenant load, or cache eviction under pressure, and the authors say so rather than overclaiming. One red flag worth naming for practitioners: vLLM 0.11.0's completions endpoint leaves the cached-token field unpopulated, so a study trusting response telemetry alone would have measured zero cache exposure on a cache-active server — the paper caught this via engine logs, but it means cache-attributable irreproducibility is currently *undetectable after the fact* on one of the two most common serving stacks.

## Strengths

- **The cleanest published determinism baseline for LLM serving:** 0 of 800 bit-identical episodes across ten configurations converts the entire paper into a controlled experiment, not an observational one — every divergence afterward is attributable to the cache with no residual-noise asterisk.
- **Three-layer causal isolation (order → second cache layer → cache state) done with experiments, not arguments**, including the restore control that separates "cached path is a function of cache state" from "there is residual randomness."
- **Discovery with practical bite:** llama.cpp's default-on host-memory prompt cache (October 2025) is an uncontrolled, undocumented-in-evaluation-practice source of run-to-run divergence that a single flag removes (-37.5 pp), and the paper shows you can keep the prefix cache's throughput win while pinning configuration and resetting state at run boundaries.
- **Instrument-grade honesty:** a self-caught, self-corrected scorer artifact (11-38% format-induced mis-scoring, ~4x flip inflation), bootstrap-vs-Wilson interval discrepancy reported with the wider interval, missing end-of-run markers disclosed, and an explicit refusal to claim accuracy degradation the data cannot support.
- **Directly actionable reporting guidance:** evaluations and deployment records should state serving engine, version, and whether prefix caching was enabled; engines should report per-request cache exposure (one of the two tested stacks already does).

## Limitations

- **Scale and breadth:** three open-weight models (7B-14B), one consumer RTX 4090, two engines, one agentic benchmark (BFCL multi-turn base, first 80 episodes by identifier) plus GSM8K — no claims about frontier models, hosted/multi-tenant endpoints, or cache-eviction-heavy traffic (where the effect would likely be larger, as the author notes).
- **The agentic outcome analysis is underpowered by the workload's own floor:** success rates of 1.2%-18.8% yield 12-vs-7 paired flips; the directional conclusion (instability without bias) rests on the GSM8K bridge, not on agent task success.
- **Residual confounds, disclosed but unresolved:** ten original configurations collected with the second cache layer at default; vLLM arms launched by different scripts (GPU memory fraction differs in one); some cells run once rather than twice; one incomplete vLLM ordering cell; a 67-record remnant of an aborted 16-bit bridge attempt in the artifact.
- **Strict divergence criterion overstates semantic change:** counting token-identifier differences flags semantically identical answers in different words as divergent; readers interested in quality rather than reproducibility must rely on the separate task-outcome arm, which is the underpowered half.
- **No intervention evaluation:** batch-invariant kernels [11], [12] are discussed but never tested in this harness, so the paper cannot say how much of the gap a determinism layer actually closes, nor what the throughput cost of "pin configuration + reset state" mitigation is in production.
- **Single-run quantization cells and a saturating gradient** leave the exact shape of the quantization-amplification curve (amplifier vs plateau after Q8_0) unresolved.

## Relevance

这篇论文与你的"Inference Reliability & SDC Detection"核心方向几乎完全对口：它把"基础设施层（KV cache 复用 + 量化）造成的模型输出静默改变"做成了可测量、可隔离、可复现的实验，本质上是 LLM 推理版的 silent data corruption 检测与归因研究。同时也命中"Reliability under Extreme Performance Optimization"（量化精度与浮点非结合性对正确性的影响），并给出了对日常智能体工作负载可直接落地的复现性配置建议（固定缓存配置 + 运行边界重置状态）。

## Questions for Further Exploration

- Would batch-invariant kernels (Thinking Machines [11], SGLang's deterministic mode [12]) eliminate the cross-arm divergence entirely at Q3_K_M, or does quantization-era logit crowding make some divergence unavoidable even with bit-identical accumulation order? The harness released with this paper is ready to answer this.
- How does the effect behave under realistic multi-tenant load, where cache eviction and concurrent batching interact with the host-memory prompt cache the way serial batch-size-one traffic never can?
- Does the "instability without direction" result hold for reasoning models with long chain-of-thought, where a single early token flip could compound into qualitatively different reasoning chains rather than washing out at 89-93% accuracy?
- Can per-request cache-exposure telemetry (which llama.cpp already reports) be turned into a runtime detector that flags cache-attributable irreproducibility on vLLM, whose 0.11.0 endpoint leaves the field unpopulated — e.g., via prompt-hash fingerprinting at the proxy layer?
- Is the quantization amplification an amplifier or a plateau? A denser grid (Q6_K, Q5_K_M, Q2_K) plus logit-margin instrumentation could separate margin compression from output-constraint saturation.
