> **一句话总结：** 提出 SkillGLoW（Global-Local Weave），指出自进化 Agent 技能库缺失的复用单元是"一组相关任务共享的求解程序"——把每次执行产生的局部技能按程序家族聚类、压缩为去实例化的全局先验（每次执行后局部技能重新生成、永不写库），并只在真实下游执行验证不退化时才允许提交（verifier-grounded commit gate）；在 4 个基准 × 3 个模型的 12 条持续改进流上全部优于无技能基线（Wilcoxon p=0.000488，hard 平均 +17.2 分），库体积比逐任务技能池小 3.6 倍，且无需改动即可把 ALFWorld 未见任务成功率从 73.9% 提升到 83.9%。

> **TL;DR:** SkillGLoW reorganizes LLM-agent skill libraries around the "procedural family" — the solving procedure shared by a cluster of related tasks — instead of a single global document (collapses into generic discipline) or a flat per-task pool (inflates, stays instance-bound). Local skills regenerated from each task's own execution are clustered into families, compressed into de-instantiated global priors, and committed only when real downstream execution shows no regression (gate). Across 12 continual-improvement runs (DeepSeek-V4-Pro / MiniMax-M3 / GPT-5.4-mini on Terminal-Bench-Pro, SWE-bench Verified, ALFWorld, LiveMathematicianBench), it beats the No-Skill baseline in all 12 hard-score cells (+17.2 hard / +13.0 soft avg, Wilcoxon p=0.000488), e.g. SWE-bench hard 70.0 vs 45.0 for DeepSeek-V4-Pro, and leads a published single-document optimizer (SkillOpt) on 15 of 21 peak-peak cells while keeping a 3.6× smaller library; unmodified transfer lifts unseen ALFWorld success from 73.9% to 83.9%.

## 核心贡献

- **识别缺失的复用单元**：论证技能库的两种极端组织（单一全局文档 / 逐任务平铺池）在异构长时程任务流上同时失效——文档坍缩成泛泛而谈的学科常识，池子无限膨胀且每条技能绑定在写出它的实例上；真正应复用的单元是"由一群相关任务共享的求解程序"（procedural family）。
- **Global-Local Weave 框架**：局部技能（L_x，由当前任务自己的执行反馈经 Trajectory-Difference Localize 生成，只活一轮、永不写入长期库）负责实例细节；全局库（G）按家族聚类后压缩为去实例化的先验（只保留适用条件、核心求解骨架、常见失败模式），每家族一个先验，冻结于求解期间、仅离线修订。
- **Verifier-grounded commit gate**：候选先验修订不凭压缩时的文本评分入库，而是整轮作为一次修订在真实下游执行上打分（纯全局先验、不拼局部技能），只有 ≥ 锚点 A − ε（ε=0.02，锚点为当前库值与 No-Skill 基线的较大者，且不低于上一轮已测最高值）才提交；每轮只做一个整体接受/拒绝决定。
- **实证结果**：12 条持续改进流上 hard 平均 +17.2（加局部再生 +18.0），21 个 peak-peak 格中 15 个领先已发表的单文档优化器 SkillOpt；库比逐任务池小 3.6×；免改动迁移把 ALFWorld 未见任务从 73.9% → 83.9%。
- **结构性验证**：在 ALFWorld 官方标签（作者未参与构造）上，15 个先验中 13 个完全落在一个任务类内、零类漏覆盖、零类凭空发明——证明聚类恢复的是程序结构而非记任务。

## Key Contributions

- Identifies the missing unit of skill reuse — the solving procedure shared by a cluster of related tasks — and shows both extant organizations (single global document, flat per-task pool) fail on heterogeneous long-horizon streams for opposite reasons.
- Proposes SkillGLoW (Global-Local Weave): local skills are regenerated per task from its own execution feedback and never enter the long-term library; global priors are one compressed, de-instantiated skeleton per procedural family, frozen during solving and revised only offline.
- Introduces a verifier-grounded commit gate: a candidate library revision is admitted only if its execution value measured on real downstream deployment (pure global priors, no local skill appended) is within ε=0.02 of an anchor that floors at the previous round's best measured value.
- Empirically: positive hard-score gains over No-Skill in all 12 runs (+17.2/+13.0 hard/soft avg; +18.0/+14.6 with local regeneration), leads SkillOpt on 15/21 peak-peak cells, and the committed library is 3.6× smaller than the per-task pool.
- Shows transfer is procedural, not memorization: the unmodified library lifts unseen ALFWorld tasks from 73.9% to 83.9% and unseen SWE-bench instances from 40.9% to 45.6%.

## Methodology

**Problem setup.** A skill is a natural-language procedure inserted into the agent context. Given a frozen agent π, task x, and harness h, one execution h(π, x, s) returns a trajectory and a verifier score r_x(s) ∈ [0,1] — the only trusted measure of effect. The committed global prior library G = {G_base, G_1, …, G_K} holds one prior per procedural family (K tracks distinct procedures, not tasks). At test time Recall injects G_x = G_base ⊕ G_k(x) unconditionally (cosine top-1 over Qwen3-Embedding-8B under 4-bit quantization, injected only above a fixed similarity threshold shared across benchmarks), and the local skill L_x = Localize(Δτ_x, r_x) is regenerated fresh from the current task's execution feedback. Objective: max_G E[r_x(Recall(G, x) ⊕ L_x)].

**Stage 1 — local evidence (skill cards).** Each task execution produces a skill card c_x = (x, a_x, τ_x, r_x, L_x): instruction, abstract signature naming what the task did, trajectory text, verifier score, and local skill. Localize generates L_x by comparing trajectory differences across multiple real executions of the same task, judged jointly with verifier feedback, retaining only the operational hypotheses that actually advanced the task.

**Stage 2 — consolidation.** (a) *Procedural clustering*: four textual views (signature a_x, instruction x, trajectory text L_x, trajectory embedding) are fused with fixed weights into φ(c) — the signature weighted largest, L_x smallest, so grouping follows the procedure rather than either wording. Because single hierarchical clustering is link-rule-sensitive, they run it many times varying parameters, record how often each pair co-occurs in a group, build a consensus similarity matrix (Monti et al. 2003), and re-cluster on it; the number of clusters K is picked automatically by the Kneedle knee point on the silhouette curve. (b) *Prior compression*: each family is compressed into one candidate prior that keeps only applicability conditions, the core solving procedure, and common failure modes — instance-only bindings are filtered out (recoverable later via the regenerated local skill).

**Stage 3 — verifier-grounded commit.** Each round's candidates come from three routes: fresh compression, append-only repair (scope-restricted guards distilled from a degraded task's local skill are appended to the verified structure), and carry-forward of every family's best-so-far prior. The round's priors form one candidate revision G^(v), scored under V(G; D) = mean_x r_x(Recall(G, x)) — the recalled prior alone, so the measured value is attributable to the prior rather than task-local adaptation. Commit iff V_real = max_v V(G^(v), D) ≥ A − ε, where the anchor A = max(V*, V̄) (current library value vs No-Skill baseline), ε = 0.02 absorbs fluctuation, and A is floored at the highest previously measured value — so a round can change the library only by performing at least on par with the standing result, up to measurement noise. Admission is one decision per round, not per family.

**Execution-time weaving.** During an episode the committed library is frozen; recall completes before the task starts. The agent solves under G_x ⊕ L_x and keeps updating L_x within the episode; after the round, L_x feeds the next consolidation. Algorithm 1 runs one pass over the T-round stream with sub-rounds J.

**Protocol.** Four benchmarks ordered by cross-task procedure sharing: Terminal-Bench-Pro (32 tasks), SWE-bench Verified (20, via an agentic harness), ALFWorld (42), LiveMathematicianBench (53). Three models (DeepSeek-V4-Pro, MiniMax-M3, GPT-5.4-mini) as hosted APIs; recall runs on one 16 GB-VRAM GPU. Hard = verifier all-or-nothing flag; soft = partial credit (multiplicative on software repair, so breaking a passing test zeroes the score); LMB is binary. Every main-table cell is a single run at temperature 0.7; held-out software-repair tasks average three trials. SkillOpt is run from its authors' own implementation with internal hyperparameters untouched, matched launch protocol, and score-through-the-same-adapters; peak-over-rounds reading for both methods.

## Results & Highlights

- **All 12 runs improve over No-Skill.** Across 3 models × 4 benchmarks, both GLoW settings beat No-Skill in every one of the 12 hard-score cells (Wilcoxon signed-rank p = 0.000488, n = 12). Frozen priors gain +17.2 hard / +13.0 soft on average; +18.0 / +14.6 once local regeneration is added.
- **Concrete headline cells (Table 1, hard scores).** DeepSeek-V4-Pro: SWE-bench 70.0 (GLoW Global) vs 45.0 No-Skill (+25.0) and 60.0 for SkillOpt; Terminal-Bench-Pro 50.0 vs 34.4 (+15.6) vs SkillOpt 43.8; LiveMathematicianBench 37.7 vs 13.2 (+24.5). MiniMax-M3 on SWE-bench reaches 65.0 (Global+Local) vs 35.0 No-Skill (+30.0) and 55.0 SkillOpt — the largest gain anywhere in the table. GPT-5.4-mini on TBP: 50.0 vs 28.1 (+21.9) vs 40.6 SkillOpt.
- **Vs the published single-document optimizer.** Under peak-peak reading over all 21 cells, GLoW leads on 15, SkillOpt on 4, two tie; SkillOpt's four wins are all on ALFWorld — the one benchmark whose tasks share a single action space, where the whole set is already the right granularity. Elsewhere the margin runs the other way: +8.3 on TBP, +6.7 on SWE, +6.9 on LMB (hard, averaged over three models).
- **Organization ablations (Table 2, 12 runs, hard).** Base-only (one merged document) averages +2.0 and flips sign across benchmarks (−9.3 to +16.7), losing ground on 4 of 12 cells; AWM (flat pool + retrieval, first-round evidence pooled and retrieved per task) averages −1.5 vs GLoW's own family consolidation (+11.2); Local-only averages only +1.0, confirming the global layer carries cross-task value.
- **The gate earns its cost (Figure 3).** Across 12 runs the gate made 26 admission decisions (19 accepted, 7 rejected); 4 of the 7 rejections would have been admitted by consolidation-time score alone. Representative case: MiniMax-M3's mathematical-reasoning round-2 candidate scored 0.283 on the consolidation-time soft signal but only 0.151 in real deployment (−13.2 points, more than twice the largest measured run-to-run range). Averaged over 12 runs the gate keeps the library at +14.7 points by the final round vs +9.6 for unconditional admission.
- **Priors align with an external taxonomy.** On ALFWorld's own labels, consolidation returns 15 priors over 42 tasks; 13 sit wholly inside one labeled class, two straddle; no class uncovered, none invented. Solved tasks move 32 → 39 (Net +8/−1 Fix/Break). The largest TBP family (8 tasks) repaired one and broke another — the only large family with no net gain, and a second model drew ten families instead of five on the same 32 tasks, showing family granularity is a property of the drawn family, not the benchmark.
- **Compression without memorization.** A 989-word local skill (seven steps around a memorized location table) compresses to a 440-word, four-step prior for its seven-task class — the table is replaced by a rule ("scan the initial observation for the illuminator-class object; do not default to desk; verify against the visible object list").
- **Transfer to unseen tasks.** Injecting the unmodified library into 60 unseen ALFWorld tasks: DeepSeek-V4-Pro 71.7 → 88.3, GPT-5.4-mini 66.7 → 75.0, MiniMax-M3 83.3 → 88.3; mean 73.9% → 83.9%. On 30 unseen SWE-bench instances (MiniMax-M3, mean of 3 trials): 40.9% → 45.6%, where every instance is a different repository. For reference, Kim et al. (2026) report 8.7% average gain for cross-domain memory transfer in a pooled-domain setting.
- **Compactness.** Across the 12 runs the committed library is 3.6× smaller than the per-task skill pool by artifact count — one prior per family, not per task.

Ao Yan (National University of Singapore), Zhang Xin, Jiawei Du, and Joey Tianyi Zhou (Institute of Advanced Intelligence and Computing, IAIC, Singapore; corresponding author). Joey Tianyi Zhou is a well-established researcher in agent learning and evolutionary/continual computation (A*STAR-affiliated IAIC); the group's cited lineage includes Du et al. (2025) "Rethinking Agent Design: From Top-Down Workflows to Bottom-Up Skill Evolution", indicating this paper continues a focused research program on bottom-up agent skill evolution. The experimental hygiene is above average for the area: they re-run the published competitor (SkillOpt) from the authors' own implementation with matched launch protocol and shared scoring adapters, measure the commit gate in real deployment rather than simulation, validate cluster structure against an external labeling they did not produce, and test held-out-instance transfer for two benchmarks. The evaluation spread (3 models × 4 benchmarks × multiple ablations, 12 continual runs) is unusually thorough for a skill-organization paper.

## Critical Assessment

- **Single-run main table.** Every main-table cell is one run at temperature 0.7 ("seeds fix the splits and the task order"). With 20–53 tasks per benchmark and hard scores where one task on TBP is worth ~3.1 points, several ±5.0 swings (e.g., SWE 45.0 vs 40.0 for GPT-5.4-mini SkillOpt vs GLoW Global) are one-to-two-task effects. The paper knows this — ε=0.02 and the gate analysis explicitly reference the "largest run-to-run range measured" — but the headline table itself reports no variance, and only held-out software-repair tasks average three trials.
- **The SkillOpt comparison is fair but soft at the edges.** Running the competitor's own implementation with untouched hyperparameters and matched adapters is better practice than most, and they honestly report SkillOpt's 4 wins. However, "peak-over-rounds reading" (best round for each method) is a max-of-noisy-variables statistic that can favor either side, and SkillOpt's internal budget under a different organization is not necessarily equal-effort — the paper itself concedes the SkillOpt-vs-Base-only gap "measures optimization effort rather than organization."
- **ALFWorld does a lot of narrative work.** The strong structural-alignment analysis (15 priors, 13 class-pure) and the qualitative compression example both come from ALFWorld, the most homogeneous benchmark (single action space, shared skeletons) — exactly where SkillOpt also wins and where the paper's own theory says priors should work best. Terminal-Bench-Pro, the hardest organization case, gets less qualitative scrutiny.
- **Unquantified clustering sensitivity.** The consensus-clustering stack (fixed view weights, Ward linkage, Kneedle on silhouette) carries hyperparameters that are "in the appendix" and "fixed across benchmarks"; the observed model-dependence of family count (five vs ten families on the same 32 TBP tasks) is presented as a feature ("re-derived each round") but never ablated for its downstream effect.
- **Small-holdout transfer.** The SWE-bench transfer is 30 instances with a +4.7-point gain — encouraging, but with three-trial averaging only there and a different-repository confound, error bars around that delta are unknown; the Kim et al. (2026) 8.7% cross-domain reference is a different setting (pooled domains), so the comparison is directional, not head-to-head.
- **Honest red-flag disclosure.** To their credit, the paper reports its own failure cases: the only no-net-gain family (repaired one, broke another), Base-only's 10-of-12 dominance by SkillOpt, and the ceiling effect on the strongest-baseline model in transfer. Cross-model inheritance and genuine domain change are explicitly declared open, not claimed.

## Strengths

- The central claim is falsifiable and directly tested: if the procedural family is the right unit, organization ablations (Base-only, AWM, Local-only) should underperform on heterogeneous streams and hold only where one granularity fits — exactly the observed pattern (Base-only wins consistently only on ALFWorld).
- Verifier-grounded admission is measured in deployment, not simulated — the 0.283-consolidation-time vs 0.151-deployed case is a concrete demonstration that text-space scores mislead, and the gate analysis quantifies what a cheaper criterion would miss (4 of 7 rejections).
- Structural validation against an external, author-independent taxonomy (ALFWorld labels) is a rare and convincing check that clusters mean "procedure," plus a qualitative before/after (989-word memorized table → 440-word rule) showing what compression actually keeps.
- Complete architecture: generation, clustering, compression, admission, and execution-time weaving are all specified (Algorithm 1) with deterministic tie-breaking (anchor flooring, ε noise band), and recall runs on a single 16 GB GPU — no hidden infrastructure.
- Transfer is tested on held-out instances of the same benchmarks rather than pooled cross-domain, cleanly separating "procedure transferred" from "domain knowledge pooled."

## Limitations

- No variance on the main results: single-run cells, small task sets (20–53), and 1-task ≈ 3–5-point granularity make several per-benchmark deltas fragile; multi-seed main tables would materially strengthen the claims.
- Family-granularity sensitivity is acknowledged but uncontrolled: the number of families on identical tasks varies across models (5 vs 10 on TBP), and no ablation measures how consensus-clustering hyperparameters (view weights, Kneedle threshold) affect final scores.
- All four benchmarks are in-distribution procedure-sharing regimes by design; the paper itself states whether a prior survives genuine domain change "remains open," and cross-model library inheritance is untested.
- The verifier is trusted as the sole commit signal; on benchmarks without clean all-or-nothing verifiers (soft-only partial credit), the multiplicative SWE scoring is the only place this is stress-tested.
- Local skills are single-round and never persisted, so within-family instance quirks must be re-learned from scratch on every recurrence — the paper shows compression removes instance state but does not measure the re-learning cost on repeated near-duplicate tasks.
- Compute cost of consolidation (multiple executions per task for trajectory-difference localization plus re-scoring every candidate revision each round) is not reported in wall-clock or token terms.

## Relevance

这篇论文正中你的第一优先方向 Self-Evolving Agents & Automated Research：它给出了自进化 Agent 技能/记忆组织的第三个答案（程序家族粒度），其 verifier-grounded commit gate 用真实下游执行而非文本评分来决定记忆写库，对长时程自治系统的可靠性问题（库退化、噪声写入、错误提交）有直接借鉴意义。

## Questions for Further Exploration

- How does the commit gate behave when the verifier itself is noisy or adversarially gamed (e.g., reward hacking on soft partial credit) — does ε=0.02 still separate real regression from measurement noise?
- What is the sensitivity of the final score to the consensus-clustering hyperparameters (view weights, linkage, Kneedle knee) — is the five-vs-ten family discrepancy between models fixable or fundamental?
- Can a prior committed by one model family be executed by another (cross-model inheritance), and does the de-instantiated plain-text format survive the transfer?
- Does the procedural-family unit extend to research-automation loops (hypothesis → experiment → analysis), where "families" are experiment types rather than task classes and verifiers are far weaker?
- Would persisting failed-repair guards across rounds (the append-only route) eventually re-inflate the library — what stops the 3.6× compactness from degrading over much longer streams?
