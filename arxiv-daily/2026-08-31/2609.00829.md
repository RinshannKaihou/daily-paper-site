> **一句话总结：** 华为提出 HarnessEvolve，一个四智能体解耦（执行/评估/优化/门控）的自进化框架：用带标准答案生成的"参考轨迹"与失败轨迹定位首个分歧点来解决 credit assignment，用质量门（数据泄露+提示膨胀检查）与性能门（批内提升且不劣化近期批次+epoch 末验证集快照选择）遏制走捷径与灾难性遗忘，在 CloudCoreNetwork-QA 上用 Qwen3.6-27B 把准确率从 43.4% 提到 86.9%，比最强基线 GEPA 高 21.6 个百分点。

> **TL;DR:** HarnessEvolve is a multi-agent self-evolution framework that optimizes an LLM agent's entire harness (prompts, skills, tools, execution logic) by (1) comparing failed trajectories against ground-truth-verified "reference trajectories" to localize the first divergence point (fixing credit assignment), (2) a quality gate that rejects updates with data leakage or prompt bloat (fixing shortcut learning), and (3) a performance gate with epoch-end validation-set snapshot selection (fixing catastrophic forgetting). On the in-house enterprise benchmark CloudCoreNetwork-QA with Qwen3.6-27B it lifts accuracy from 43.4% (Base) to 86.9%, +21.6 pts over the strongest baseline GEPA (65.3%); ablations show removing reference-trajectory comparison drops it to 57.8% (−29.1 pts).

## 核心贡献

- **参考轨迹引导的误差诊断（Reference-Guided Error Diagnosis）**：先让执行 agent 拿着标准答案跑训练题生成"参考轨迹"，由评估 agent 验证其是真实执行路径（而非直接抄答案）后存入全局缓存；优化 agent 将失败轨迹与参考轨迹逐动作对比，定位**首个分歧点**作为根因，绕开"后续错误是前面错误级联结果"的 credit assignment 困境。
- **质量门对抗捷径学习（Quality Gate against Shortcut Learning）**：门控 agent 用 LLM-as-judge（阈值 η_leak=0.8）扫描候选 harness 改动是否内嵌了失败样例的标准答案（数据泄露），并统计新注入的 in-context 样例数（膨胀阈值 η_bloat=5，允许 3 轮修改后仍不合规则丢弃）。
- **性能门对抗灾难性遗忘（Performance Gate for Stable Evolution）**：候选更新只有在当前 batch 上提升 ≥δ 且对最近 R=2 个批次无超过 ε=0.025 的劣化才被接受并成为新快照；epoch 结束后在验证集上选最优快照，附带 batch/epoch 双 patience 提前终止。
- **整 harness 优化**：与 GEPA（只改 prompt）、ACE（只改 skill 描述）、SkillOpt（只改 skill.md）不同，HarnessEvolve 修改整个执行 agent——skill.md、Python 脚本、prompt、工具参数规格乃至执行逻辑代码。
- **跨框架迁移实验**：在 OpenClaw 上优化出的 skill 直接零再优化部署到 Hermes、OpenCode、LAMAgent、DeepSeek Harness 四个框架，均提升或持平，证明学到的是通用纠错模式而非框架特化捷径。

## Key Contributions

- **Reference-guided error diagnosis**: a diagnostic method that overcomes credit assignment failure by comparing failed executions against verified reference trajectories (generated by running the executor with ground-truth answers), localizing the *first action divergence point* as the root cause, then clustering errors by cause (not by distance-based methods like K-Means, preserving long-tail failure patterns).
- **Quality gate against shortcut learning**: a filtering mechanism that inspects every candidate harness update for data leakage (LLM-as-judge score with threshold η_leak = 0.8) and prompt bloat (count of newly injected in-context examples, threshold η_bloat = 5), with up to T_rev = 3 revision rounds before abandonment.
- **Performance gate for stable evolution**: an update is accepted only if it improves the current mini-batch by at least margin δ without degrading any of the R most recent batches beyond tolerance ε; accepted updates become snapshots in a pool, and the epoch-end validation step selects the best-performing snapshot, guaranteeing the final agent is never worse than the epoch's best.
- **Comprehensive whole-harness optimization**: built on a decoupled four-agent architecture (execution / evaluation / optimization / gating), HarnessEvolve edits the entire execution agent — skills, scripts, prompts, tool-argument specs, and execution logic — rather than a single component.
- **Empirical validation across 5 benchmarks, 2 models, and 4 transfer frameworks**, including a cross-framework transfer protocol that tests whether optimized skills generalize without re-optimization.

## Methodology

HarnessEvolve formalizes harness self-evolution over a task corpus T = {(q_i, a_i)} split into train/validation/test, and decouples the loop into four agents:

1. **Execution agent (A_exec)**: runs tasks using its harness (prompts, skills, tools, execution logic), producing trajectories τ = [(o_1,a_1),...,(o_T,a_T)]. Crucially, prior to optimization it also runs every training task **with the ground-truth answer provided**, attempting up to T_ref = 5 times, to produce *reference trajectories* — successful execution paths.
2. **Evaluation agent (A_eval)**: (i) scores task accuracy by comparing outputs to ground truth; (ii) *verifies reference trajectories are genuine* — checking the trajectory invokes the appropriate tools, processes intermediate observations, and follows a legitimate reasoning chain rather than trivially returning the known answer (a shortcut). Only verified references enter the global cache C.
3. **Optimization agent (A_opt)**: for each failed trajectory τ_f, emits a structured error signal F = (s_f, m_f, h_f) (severity, error cause, fix hint). When a verified reference τ_r exists, it identifies the **first action divergence point** — the earliest step where τ_f deviates from τ_r — and analyzes more from there; root-cause errors cascade downstream, so divergence-point analysis isolates the true cause. Errors are then grouped **by cause m** into clusters (Cause-Based Grouping, Root-Cause Priority, Long-Tail Protection — deliberately avoiding fixed-K distance clustering). Cluster-level diagnosis (aggregated severity, shared cause, representative trajectories, fix direction) drives candidate harness modifications Δ_harness, prioritizing clusters with more instances and higher severity.
4. **Gate agent (A_gate)**, isolated from the optimizer to prevent self-serving evaluation:
   - *Quality gate*: LLM-as-judge data-leakage score per modified file (reject if > η_leak = 0.8) plus a prompt-bloat count of injected in-context examples (reject if > η_bloat = 5); rejected updates return to A_opt with rejection reasons for up to 3 revisions, then are abandoned.
   - *Performance gate*: a candidate A_candidate is accepted iff Acc improves on the current batch B_j by ≥ δ and no recent batch in the replay buffer (R = 2) degrades by more than ε. Accepted snapshots join pool V and immediately become the active agent. With δ = 0.0 and ε = 0.025 this is a strict monotonic-improvement ratchet with a small forgetting allowance.
   - *Epoch-end selection*: argmax over V on T_val; training stops after E = 20 epochs or after P_ep = 5 epochs without validation improvement (batch patience P_batch = 10 enables early epoch exit).

**Experimental setup**: 3 open-source datasets — SearchQA (search-engine QA), OfficeQA (enterprise document reasoning), SpreadsheetBench (spreadsheet manipulation) — plus 2 in-house enterprise datasets from cloud-core-network and wireless-network domains (CloudCoreNetwork-QA: network QA + text-to-SQL; Wireless-QA), which "require selecting and combining multiple skills." Baselines: GEPA (reflective prompt optimization), ACE (context/skill-description evolution), SkillOpt (executive skill refinement, skill.md only), plus the unoptimized Base. Reasoning engines: Qwen3.6-27B (post-trained with domain-specific fine-tuning on the in-house datasets) and DeepSeek-V4-Flash; open-source runs use DeepSeek-V4-Flash under OpenClaw (harness = skills, AGENTS.md, SOUL.md, tools; HarnessEvolve optimizes the entire skill directory including reference files and scripts, while SkillOpt optimizes only skill.md). Batch size b = 40.

## Results & Highlights

- **CloudCoreNetwork-QA (in-house, Qwen3.6-27B), accuracy %**: Base 43.4 → GEPA 65.3 → SkillOpt 61.9 → ACE 59.3 → **HarnessEvolve 86.9** — +43.5 pts over Base and **+21.6 pts over the strongest baseline GEPA**, the paper's headline claim; with DeepSeek-V4-Flash it reaches 85.9 vs SkillOpt 65.5 (+20.4) and Base 47.5.
- **Wireless-QA (in-house, DeepSeek-V4-Flash)**: HarnessEvolve 92.8% vs best baseline ACE 90.1% (+2.7 pts) and Base 85.9%; with Qwen3.6-27B the gain is smaller — 89.7 vs SkillOpt 89.0 (+0.7).
- **Open-source benchmarks (DeepSeek-V4-Flash under OpenClaw)**: SearchQA 92.9 vs ACE 90.0 (+2.9) and Base 86.5; OfficeQA 70.9 vs ACE 68.9 (+2.0) and Base 62.8; SpreadsheetBench 76.4 vs SkillOpt 74.6 (+1.8) but Base only 44.3 (+32.1) — i.e., on open-source tasks HarnessEvolve beats baselines consistently but by small margins, unlike the dramatic in-house gaps.
- **Cross-framework transfer (skills optimized on OpenClaw, deployed zero-shot on 4 other frameworks)**: SpreadsheetBench accuracy jumps from 57.5 → 87.9 on OpenCode (+30.4), 45.0 → 80.0 on LAMAgent (+35.0), and 56.4 → 86.8 on DeepSeek Harness; SearchQA/OfficeQA see smaller consistent gains (e.g., OfficeQA 77.9 → 80.8 on Hermes). Never below Base on any of the 12 cells.
- **Ablations (CloudCoreNetwork-QA, Qwen3.6-27B)**: full system 86.9; w/o reference trajectory 57.8 (**−29.1**, the largest single component); w/o error clustering 68.6 (−18.3); w/o quality gate 80.1 (−6.8). Reference-guided diagnosis is clearly the load-bearing component.
- **Gating behavior**: self-evolution curves (Fig. 2) show a substantial fraction of candidate updates rejected by the two-tier gate, with peak snapshot-pool accuracy rising monotonically to the final harness — the authors offer this as evidence the gates filter low-quality modifications rather than stalling learning.

## Authors & Credibility

The paper comes from the **ICT AI Competence Center, Huawei Technologies (Shanghai)** — an industrial lab with direct access to cloud-core-network and wireless-network operational data, which explains the two in-house benchmarks. Wen Jiang, Mingmin Chu, Yimeng Tian, and Qianxin Zhang contributed equally; corresponding authors Rui Yang and Fangming Li. The author list is purely industrial (no university affiliation), and the work is positioned against very recent 2025–2026 self-evolution literature (GEPA, ACE, SkillOpt, AHE, Self-Harness), suggesting the team is actively working at this research frontier. No code or data release is mentioned. The in-house LAM framework and the proprietary datasets are plausible for a telecom-equipment company but limit external verification. Credibility: solid industrial research; the two models used (Qwen3.6-27B domain-fine-tuned, DeepSeek-V4-Flash) are current-generation, and baseline implementations follow each method's published setup under identical environment constraints.

## Critical Assessment

- **The headline +21.6 pt gain is only demonstrable on proprietary data.** The two datasets with dramatic gaps (CloudCoreNetwork-QA, Wireless-QA) are in-house and not released, and the Qwen3.6-27B executor was *post-trained with domain-specific fine-tuning on these same in-house datasets* — an interaction the paper never discusses. On the three public benchmarks the wins are real but modest (+1.8 to +2.9 pts over the best baseline), so the headline number should be read as an enterprise-domain result, not a general one.
- **Search-space unfairness is the biggest confound.** GEPA optimizes prompts, ACE skill descriptions, SkillOpt only skill.md, while HarnessEvolve optimizes the full harness including Python scripts and execution logic. Part of the gain — plausibly a large part on CloudCoreNetwork-QA, where multi-skill text-to-SQL tasks are involved — may come from the larger action space rather than from reference-guided diagnosis or gating. The missing ablation is HarnessEvolve restricted to SkillOpt's single-component search space; the M1–M3 ablations remove mechanisms but never equalize the search space.
- **No variance reporting.** All tables are single numbers with no seeds, std, or significance tests, despite LLM-driven optimization loops being notoriously high-variance (a different random batch order can change which errors get clustered). With ~5-point margins on public benchmarks, this matters.
- **The quality gate's LLM-as-judge is unvalidated.** The leakage detector (threshold 0.8) is itself an LLM whose precision/recall is never measured — false rejections would silently discard good updates, false acceptances defeat the paper's central anti-shortcut claim. No human audit of a sample of gate decisions is reported.
- **Compute cost is invisible.** Every training task needs up to 5 reference-trajectory attempts plus verification, and each batch triggers diagnosis, candidate generation, gating, and evaluation on B_j + R batches — a 4-agent loop over 20 epochs. No token/wall-clock/cost comparison against GEPA/ACE/SkillOpt is given, yet the per-iteration cost is plausibly an order of magnitude higher.
- **Positioning is somewhat self-serving but defensible**: the paper claims Self-Harness and AHE leave credit assignment "unresolved" and shortcut learning "unguarded" — accurate per their descriptions, but the comparison is only via the three re-implemented baselines, not against those two closest contemporaries experimentally.
- Genuine strengths worth crediting: the reference-trajectory idea is a clean operationalization of counterfactual debugging for agents; the verification step (rejecting references that shortcut to the known answer) anticipates the obvious failure mode; and the cross-framework transfer table is a generalization test most self-evolution papers skip.

## Strengths

- Directly attacks three named, concrete failure modes (credit assignment, shortcut learning, catastrophic forgetting) with one mechanism each, rather than a generic "optimize the prompt" loop.
- Reference trajectories with **verification** are a well-designed device: comparing failed vs. genuine successful paths localizes the first divergence point, which the −29.1 pt ablation confirms is the dominant contributor.
- The dual-gate design (static quality check + dynamic performance check) plus epoch-end snapshot selection guarantees the final harness is never worse than the best accepted snapshot — a monotonicity guarantee most self-evolving systems lack.
- Long-tail-preserving, cause-based error clustering (explicitly avoiding fixed-K distance clustering) is a thoughtful design choice for heterogeneous agent failures.
- Cross-framework transfer (4 frameworks, 12 cells, no re-optimization, never below Base) is strong evidence that learned harness edits encode general error patterns rather than framework-specific hacks.
- Honest granularity in ablations: each of the three mechanisms is removed individually and all three removals hurt.

## Limitations

- Two of five benchmarks (including the one carrying the headline claim) are proprietary; no code or data release is mentioned, so the full pipeline is not reproducible externally.
- Baselines operate on strictly smaller optimization spaces (prompt-only / context-only / skill.md-only); no search-space-equalized comparison isolates the framework's mechanisms from its broader action space.
- Single-run results with no variance or significance reporting; margins on public benchmarks (1.8–2.9 pts) are within plausible run-to-run noise.
- The LLM-as-judge leakage detector is unvalidated; gate reject/accept precision is never quantified.
- No compute-cost accounting for the 4-agent, multi-attempt, 20-epoch loop versus the cheaper baselines.
- Reference-trajectory coverage is not reported: when all T_ref = 5 attempts fail verification, diagnosis falls back to less precise single-trajectory analysis — the fraction of tasks affected is undisclosed.
- Evaluation is accuracy-only on QA/SQL/spreadsheet tasks; no measurement of harness bloat over time, edit quality, or behavior on open-ended (non-verifiable-answer) tasks where ground-truth-based reference generation is impossible.

## Questions for Further Exploration

- How much of the CloudCoreNetwork-QA gain survives when HarnessEvolve is restricted to SkillOpt's single-component (skill.md-only) search space — i.e., mechanism vs. action-space size?
- What is the precision/recall of the LLM-as-judge leakage gate, and how many genuinely useful updates does it falsely reject (or dangerously accept) in practice?
- Can reference trajectories be generated without ground-truth answers (e.g., via self-consistency or verifier models), extending the method to open-ended tasks where no canonical answer exists?
- What fraction of training tasks obtain a verified reference within T_ref = 5 attempts, and how does performance degrade as that fraction falls?
- How does the framework interact with the domain-fine-tuned Qwen3.6-27B executor — would the same gains appear with a general-purpose model on the in-house datasets?
- What is the end-to-end compute cost (tokens, wall-clock) per point of accuracy gained, relative to GEPA/ACE/SkillOpt?
