Why this matters

For long-running agents, user corrections arrive mid-run; fail-closed validity semantics make revised outputs trustworthy instead of stale or guessed.

Critical edge

The headline savings hold only where fine-grained provenance is provable — all 48 workflows lacking it fell back to full restart, zero gain.

01 Methodology

revision Δ ∩ provenance → impact set → Cancel / Avoid / Recompute / Continue / Reuse
  • Validity model. A workflow is a DAG whose artifacts carry monotonic versions; typed read selectors (artifact, semantic path, data-vs-control) record what each attempt consumed. An attempt is valid only if no revision since its snapshot intersects any consumed selector — otherwise recompute or block, never guess.
  • Automatic provenance. Adapters wrap node state in a recursive read-only proxy: field accesses record leaf paths, iteration records collection membership. An old/new structural diff yields the revision delta Δ with no application-supplied affected sets.
  • Five lifecycle actions — Cancel running work, Avoid pending work, Recompute on the revised snapshot, Continue proven-unaffected work, Reuse revalidated results. Evidence grades scope: fine-grained → affected subgraph; coarse → topological suffix; none → full restart. Irreversible effects are staged or blocked.
  • Commit-time certificates (id, v_start, reads, parents, mode) are rechecked against the revision journal, closing the late-read race; a revision invalidating a committed parent invalidates dependents.
  • Evaluation. Unmodified LangGraph and LLMCompiler apps on Qwen3-14B (SGLang, 4×H100); full-restart and dynamic-suffix baselines given identical provenance; 15,000-workflow serving runs across 64 tenants; motivation grounded in 5,825 real SWE-chat sessions (118 retain work at revision delivery; overlap 5.54 s median / 56.55 s p95).

03 Strengths

  • Fail-closed correctness at scale — 300-case adversarial matrix targeting late reads and revision/commit orderings; commit-time certificates make the safety argument airtight rather than heuristic.
  • Fair baseline engineering — the suffix baseline receives identical provenance, cleanly isolating recovery granularity as the source of the 31.3–43.6% call savings.
  • Honest reporting — confidence intervals, unchanged single-request E2E, the 48/48 fallback, and a taxonomy-not-prevalence audit are all disclosed.
  • Real-data motivation — intervention windows measured on actual user–agent interactions (118 sessions, 56.55 s p95 overlap), not synthesized schedules.
  • Principled degradation ladder — subgraph → suffix → restart, with irreversible effects staged; semantics degrade predictably instead of silently reusing stale state.

04 Limitations

  • Integration cost gates everything — without adapters exposing topology, lifecycle events, and fine-grained reads, REVISE collapses to full restart; no automatic adapter generation is offered.
  • Narrow empirical base — one model, one serving stack, five repository workloads; no head-to-head against cited fine-grained systems (DART, PASTE, DeltaBox), only restart/suffix proxies.
  • Serving-numbers hygiene — the abstract’s goodput range contradicts Table 2, and per-load rows carry no confidence intervals.
  • Contention-only benefit — single-user sessions gain essentially nothing; value requires multi-tenant pressure.
  • Motivation generality unproven — the locality taxonomy derives from 20 audited revisions in one coding-agent corpus.
  • Physical effects out of scope — KV allocation excluded; unstagable tools (emails, payments) untested.

05 Questions for further exploration

  • Is the +43.07% goodput at 1.1× boundary pressure real, or a decimal-point typo relative to the abstract’s 3.07–5.43% range — and what does the true per-load curve look like with CIs?
  • Can provenance adapters (read-only proxy + structural diff) be auto-generated for arbitrary agent frameworks, given the 48/48 degeneration to restart?
  • How does validity-guided recovery compose with KV-cache management (Leyline-style directives), explicitly excluded from the system boundary?
  • Does the 20-revision locality taxonomy hold in browsing, data-analysis, or long-horizon research agents with different revision semantics?
  • Do staged irreversible tool effects remain practical under adversarial revision timing when tools cannot be staged?
