> **一句话总结：** 杜克大学团队提出 **lazy grounding（惰性 grounding）** 这一新型攻击面：不注入任何虚假或恶意内容，只往搜索语料中植入"**完全属实但回答的是相邻改写问题**"的证据文档（经 GPT-5.4 生成+验证、人工抽检 Fleiss' κ=0.771 的答案改写 QA），即可让 ReAct 搜索代理把相邻问题的答案直接搬到原问题上；在 GAIA/XBench/BrowseComp+/HLE × 3 个模型（Tongyi-DeepResearch-30B-A3B、GPT-5 Mini、Gemini 3 Flash）共 12 个模型-基准对上，准确率平均下降 **5.9 分**、最大 **17.3 分**（Tongyi 在 XBench 上 69.3→52.0），Tongyi 在 XBench 上的相邻答案采纳率（RAA）高达 **27.0%**，而 Gemini 3 Flash 仅 7.7%——且证据出现得越晚、越"答案形状"，危害越大；一个约束检查 prompt 只能把 RAA 从 20.7 降到 14.3，无法根除。

> **TL;DR:** Search agents can be steered into wrong answers using *completely factual* evidence: the authors inject verified documents that truthfully answer an answer-changing rewrite q′ of the evaluated question q into the search corpus, and agents transfer the nearby answer b to q ("lazy grounding"). Across 12 model–benchmark pairs (Tongyi-DeepResearch-30B-A3B, GPT-5 Mini, Gemini 3 Flash × GAIA, XBench-DeepSearch, BrowseComp+, HLE; 100 questions each, 3 clean + 3 augmented runs), accuracy drops 5.9 points on average and up to 17.3 points (Tongyi on XBench: 69.3→52.0, paired-bootstrap 95% CI [10.7, 24.0]); rewrite-answer adoption (RAA) is 27.0% for Tongyi on XBench (RAA-F 41.3 on clean-wrong items) vs only 7.7% for Gemini 3 Flash, which opened injected documents in just 2/100 traces vs 74/100 for Tongyi. A simple constraint-checking prompt cuts GPT-5 Mini's RAA from 20.7 to 14.3 (−6.4, CI [0.7, 12.0]) without hurting clean accuracy (64.0 vs 64.3) — partial mitigation only.

## 核心贡献

- **识别并命名 lazy grounding 失败模式**：与以往 RAG 投毒（虚假/恶意文档）和间接 prompt 注入不同，本文证明搜索代理会被"**针对相邻问题但完全真实**"的证据带偏——代理不校验证据是否匹配当前问题的确切约束，直接把相邻问题的答案迁移到原问题上。问题不是"坏证据"，而是"坏 grounding"。
- **验证式附近证据构造流水线**：用 7 类答案改写家族（参数反转、属性轴转、范围收窄、组合关系链、限定词翻转、off-by-one、预设编辑）生成改写问题 q′，经独立验证器强制"b 对 q′ 成立且对 q 不成立、q′ 无歧义"，并做 40 项三人人工审计（40/40 满足答案改变条件、34/40 验证 b 对 q′ 正确；raw pairwise agreement 0.950、Fleiss' κ 0.771）。
- **RAA 指标体系**：除 clean/augmented 准确率外，定义 rewrite-answer adoption（RAA）= 增强运行输出相邻答案 b 的频率，并按 clean 正确/错误分解为 RAA-C/RAA-F——把"定向采纳相邻答案"与"一般性输出不稳定"区分开。
- **系统实证 + 机制消融**：12 个模型-基准对、每条件 3 次运行、配对聚类 bootstrap（10 万次重采样）置信区间；消融显示**后置出现**（晚 turn RAA 15.0 vs 早 turn 9.0）、**答案形状格式**（答案字段记录 RAA 23.0 vs 自然散文 19.0）放大攻击，**多样性证据库**降低精确采纳（RAA 20.2→15.0）但仍能误导不确定轨迹（RAA-F 28.6）。
- **诚实的双向发现与部分缓解**：附近证据偶尔有益（Gemini 3 Flash 在 BrowseComp+ 上 43.0→52.3 而 RAA 仅 5.0）或引发非定向的轨迹重定向（PubChem 案例中把分子量 325.8 当作中间假设搜出 CID 160966）；constraint-checking prompt 把 GPT-5 Mini 的 RAA 从 20.7 降到 14.3（clean 准确率不变）但残留 14.3%，证明纯 prompt 防御不足。

## Key Contributions

- **Identification of lazy grounding**, a new failure mode of retrieval-augmented search agents: unlike corpus poisoning (false documents) or indirect prompt injection, the injected evidence is factually correct but answers a *nearby* rewritten question; the failure is misapplication of true evidence — "not bad evidence, but bad grounding."
- **A verified nearby-evidence construction pipeline**: GPT-5.4 rewrites benchmark questions via 7 answer-changing edit families with bounded iterative repair (up to 3 accepted rewrites per item, ≤9 drafts), a separate verifier enforces (i) b is supported for q′, (ii) a is no longer correct for q′, (iii) q′ is unambiguous; a 40-item, 3-annotator human audit confirms 40/40 answer-changing and 34/40 verified-correct rewrites (raw pairwise agreement 0.950, Fleiss' κ 0.771).
- **The RAA metric family**: rewrite-answer adoption Pr[M(q; C∪D)=b], decomposed into RAA-C/RAA-F over clean-correct/clean-wrong trajectories, separating targeted answer transfer from generic instability — augmented accuracy alone conflates the two.
- **Systematic evaluation with uncertainty quantification**: 12 model–benchmark pairs × 3 runs per condition, paired cluster bootstrap 95% CIs over questions (100,000 resamples retaining all replicates), plus position/format/diversity ablations and a 100-trace tool-use analysis.
- **Honest two-sided findings**: nearby evidence sometimes helps (Gemini 3 Flash on BrowseComp+: 43.0→52.3 with RAA only 5.0) or redirects trajectories without exact adoption (PubChem case); a constraint-checking defense prompt reduces but does not eliminate adoption (RAA 20.7→14.3).

## Methodology

**Problem setup.** A search agent M answers question q by searching corpus C (clean) vs C ∪ D, where D is a bank of nearby-evidence documents supporting answer b for a rewritten question q′ (augmented). The attack does not fabricate anything about q: every document is true for q′ only. Robust behavior is answering a; the targeted failure is adopting b.

**Rewrite pipeline (Appendix B).** For each benchmark item, a GPT-5.4 planner proposes 3 edit plans from fixed families: argument reversal, attribute pivots, scope narrowing, compositional relation chains, qualifier flips, off-by-one shifts, presupposition edits (nearest-neighbor plans fill unused slots). A generator makes one semantic change while preserving wording/entities/answer type; failed attempts receive structured feedback in up to 3 repair iterations per family. A separate verifier accepts a rewrite only if the new answer is supported for q′, the original answer a is no longer naturally correct, and q′ has a single definite answer. Records that merely exclude a without establishing b, or that leak citations/URLs into the answer, are rejected.

**Nearby-evidence documents.** Each accepted rewrite yields 10 synthetic search results (title, displayed URL, snippet, webpage body, source-form question, rewritten answer, rationale) written as factual lookup pages, not commands; the webpage repeats b in the answer field, summary, source context, and conclusion, with the q′ paraphrase included so the record is true for the nearby question.

**Corpus augmentation (Appendix C).** Injection is implemented by patching only the search and visit tools of the ReAct environment. For web-search benchmarks, clean runs call the Serper Google Search API (gl=us, hl=en, num=10); augmented runs take the same real results, union them with the 10 injected records, rerank by dense similarity (google/embeddinggemma-300m embeddings of title+source+date+snippet vs the issued query), and return top-k=10 — injected records must survive dense reranking, and the user question, ReAct loop, and answer procedure are unchanged. BrowseComp+ uses its local corpus instead.

**Agents and compute.** A shared ReAct scaffold (search, visit, Google Scholar tools) over three base models: Tongyi-DeepResearch-30B-A3B (deployed locally on 4×A100), GPT-5 Mini (OpenAI Responses API), Gemini 3 Flash (Gemini API). 120-call ReAct budget, 2400 s timeout, temperature 0.6, top-p 0.95, presence penalty 1.1, 10,000-token cap per call. The rewrite generator/verifier and the answer judge (GPT-5.4) are separate from the evaluated agents.

**Metrics and statistics.** Clean accuracy, augmented accuracy, RAA (final answer matches b), and RAA-C/RAA-F on clean-correct/clean-wrong items; 3 runs per condition with mean±SD; paired cluster bootstrap 95% CIs with 100,000 resamples over the 100 questions per benchmark. Answers are judged by GPT-5.4 with normalization into CORRECT / CR-R (rewrite answer with observed evidence = RAA) / CR-P / CA-OW / NC-W; three authors unanimously endorsed the judge on 48/48 audited augmented responses (4 per model–benchmark pair).

## Results & Highlights

- **Accuracy degradation is large and significant where it matters.** Across all 12 model–benchmark pairs, adding nearby evidence drops accuracy by **5.9 points on average**; the largest drop is **17.3 points** for Tongyi-DeepResearch on XBench (clean 69.3±2.1 → augmented 52.0±6.1, paired-bootstrap 95% CI [10.7, 24.0]). GPT-5 Mini falls 65.0 → 52.7 on XBench (drop 12.3, CI [5.7, 19.0]); Gemini 3 Flash is far more robust on XBench (74.3 → 71.0, drop 3.3).
- **Targeted adoption occurs in every model–benchmark pair.** RAA reaches **27.0%** for Tongyi on XBench (RAA-C/F 20.7/41.3) and **23.0%** for GPT-5 Mini (RAA-F 30.5 on XBench, 32.5 on GAIA); even the robust Gemini 3 Flash shows RAA 13.7 on HLE. High RAA-F values show nearby evidence acts as an answer attractor for already-uncertain trajectories.
- **Clean accuracy does not predict robustness.** Tongyi and Gemini 3 Flash have similar XBench clean accuracy (69.3 vs 74.3), yet Tongyi drops 17.3 points with RAA 27.0 while Gemini drops 3.3 with RAA 7.7. In a 100-trace analysis, injected snippets surfaced in **all 100** augmented runs for both models, but Tongyi opened at least one injected document in **74** runs vs **2** for Gemini.
- **Ablations: position and format amplify the effect.** On GAIA with Tongyi, late-turn insertion yields RAA **15.0** vs 9.0 (early) and 10.0 (middle); answer-field records give RAA **23.0** vs 19.0 for natural prose (clean accuracy 60.0 in both). A diverse evidence bank of multiple distinct rewrites still induces RAA **15.0** (RAA-F 28.6), though exact adoption falls from 20.2 with a single rewrite.
- **Prompt-level defense is only partial.** A constraint-checking instruction on 100 XBench questions with GPT-5 Mini reduces RAA from **20.7 to 14.3** (−6.4, paired-bootstrap 95% CI [0.7, 12.0]) and RAA-C from 19.3 to 11.4, while clean accuracy is unchanged (64.0 vs 64.3) — but 14.3% adoption remains.
- **Not uniformly harmful.** Gemini 3 Flash *improves* on BrowseComp+ (43.0 → 52.3) with RAA only 5.0, using nearby evidence as an intermediate clue; 11 of 12 pair-level drops are positive, and the three that fail to exclude zero at 95% confidence include Tongyi on HLE (drop 2.0, CI [−5.0, 9.0]) and Gemini on XBench (3.3, CI [−2.0, 9.0]).

All seven authors are at **Duke University**; Yulin Zhang and Yukun Huang contributed equally. The senior author, **Bhuwan Dhingra** (Duke NLP), leads work on LLM faithfulness and factuality, and two co-authors bring directly relevant prior work: Yukun Huang and Sanxing Chen co-authored "To Trust or Not to Trust? Enhancing LLMs' Situated Faithfulness to External Contexts" (ICLR-area 2025) and the DeepFact deep-research factuality benchmark (2026), so the team has genuine expertise in retrieval grounding failure modes. The work is supported by NSF award IIS-2211526, the code is publicly released (github.com/frankyzha/lazy-grounding), and the paper discloses AI-assisted writing polish with author review. The methodology is unusually careful for an attack paper: verified rewrites with a 3-annotator human audit (κ=0.771), an LLM judge validated against 48/48 unanimous human agreement, paired bootstrap CIs, and an explicit ethics stance of not publishing benchmark-targeted pages to the real web to avoid contaminating future agent evaluations.

## Critical Assessment

The threat model is genuinely novel and the execution is careful, but several specifics deserve scrutiny. **(1) Sample size and variance.** Each cell rests on only 100 questions × 3 runs; several entries have very large dispersion (Tongyi's BrowseComp+ RAA is 36.3±24.0), and 5 of the 12 accuracy-drop CIs cross zero (e.g., Tongyi on HLE: 2.0, CI [−5.0, 9.0]). The "5.9-point average" headline is driven mainly by the XBench column; per-pair, the effect is much more heterogeneous than the abstract suggests. **(2) Rewrite quality is imperfect.** The authors' own audit found only 34/40 rewrites where b was verified correct for q′ (15% failed the stronger check), so a nontrivial fraction of injected records tests something slightly different from the idealized "true evidence for a nearby question" — the paper is transparent about this, but RAA numbers aggregate over the weaker 6 items too. **(3) GPT-5.4 circularity.** The same model family generates rewrites, verifies them, and judges final answers; the 48-response judge audit mitigates this, but rewrite-verification bias (accepting rewrites that are easier for the generator) cannot be ruled out by a 40-item audit. **(4) The "attack" is benchmark-targeted and simulated.** An attacker must know the evaluated question to craft q′; real-world feasibility requires the attacker's page to actually outrank organic results under production indexing/SEO/ranking dynamics, which the dense-rerank simulation (embeddinggemma-300m) abstracts away — the authors say so, but the "product providers could publish pages" scenario in the intro is asserted, not demonstrated. **(5) Narrow model coverage.** Three base models on one ReAct scaffold, all English/text-only; the interesting robustness gap (Tongyi opens 74/100 injected docs, Gemini 2/100) is observed but not explained mechanistically. **(6) The defense is a strawman-adjacent baseline**: a single generic prompt is the only mitigation tested; no retrieval-side, fine-tuning, or provenance-based defense is compared, so "prompting alone does not eliminate it" is shown against the weakest possible defense. To the authors' credit, they report the beneficial-effect case (Gemini on BrowseComp+ improving 9.3 points) prominently rather than hiding it, which strengthens rather than weakens the empirical credibility.

## Strengths

- **Novel, well-motivated threat model**: sits cleanly between corpus poisoning (false content) and distraction attacks (irrelevant content) — the distractors are highly retrievable, dual-use, and legitimate in isolation, making them hard to filter with existing reliability/factuality checks.
- **Verification-first attack construction**: rewrite acceptance requires the nearby answer to be supported for q′ *and* incorrect for q, plus human audit with reported inter-annotator statistics — far above the standard for adversarial-evidence papers.
- **Metric design that separates mechanisms**: RAA-C/F distinguishes targeted answer transfer on clean-correct vs clean-wrong trajectories from generic degradation, and the PubChem trace shows the authors look beyond their own headline metric (trajectory redirection without exact adoption).
- **Statistical hygiene**: three runs per condition, SDs, and paired cluster bootstrap CIs over questions — rare rigor in agent-attack evaluations.
- **Honest reporting of non-targeted and beneficial outcomes**, and an ethics section that deliberately avoids contaminating the live web.

## Limitations

- **No complete defense**: the only mitigation is a constraint-checking prompt that leaves 14.3% residual RAA; retrieval-side alignment verification, contrastive nearby-comparison, provenance-aware retrieval, and training-time defenses are left as future work.
- **Simulated augmentation**: nearby documents are unioned-and-reranked with the real Google results rather than actually indexed; real-world indexing, ranking, freshness, and source-reputation effects — which likely determine practical exploitability — are out of scope.
- **Small, high-variance evaluation cells**: 100 questions and 3 runs per cell; several pair-level CIs cross zero, and the ablations (position, format, diversity) are run on a single model (Tongyi) and mostly one benchmark (GAIA), so their generality is untested.
- **Rewrite ceiling**: the pipeline's dependence on GPT-5.4 means attack strength may track the rewriter's knowledge of each benchmark domain; 15% of audited rewrites failed the stronger correctness check.
- **Coverage**: text-only English search agents on one ReAct scaffold; longer-horizon research agents, enterprise RAG, browser/multimodal agents, and multilingual settings are explicitly future work.

## Relevance

这篇论文与你的首要方向"长时自主 Agent 系统的可靠性与可信性"高度相关：它揭示了一种现有 factuality/reliability 过滤器完全无法拦截的 grounding 失效模式——证据全真、问题错位——并给出了可复用的 RAA 评测指标与开源攻击套件。对于任何需要评估搜索/RAG Agent 鲁棒性的工作，"clean accuracy 不预测鲁棒性"（Tongyi vs Gemini：clean 69.3 vs 74.3，drop 却是 17.3 vs 3.3）是一个应当纳入评测设计的直接结论。

## Questions for Further Exploration

- Can retrieval-side defenses (provenance-aware retrieval, explicit evidence-question constraint alignment checks, contrastive comparison with nearby alternatives) close the residual 14.3% RAA that prompt-level constraint checking leaves behind?
- What mechanistically explains the robustness gap between Gemini 3 Flash (opened injected documents in 2/100 traces) and Tongyi-DeepResearch (74/100) at near-identical clean accuracy — tool-use policy, context tracking, or pre/post-training?
- Does lazy grounding persist in enterprise RAG and long-horizon research agents where the corpus is stable and attackers can optimize documents for ranking over time?
- Can the attack be made end-to-end realistic (adversarial optimization of answer-shaped documents that survive production retrievers and rankers), and what is the minimum attacker knowledge of the target question required?
- Can nearby evidence be systematically exploited as a *beneficial* intermediate clue — e.g., a scaffold that surfaces nearby answers for search guidance while blocking their use as final answers?
