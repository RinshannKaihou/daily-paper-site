> **一句话总结：** 本文首次系统诊断出代码级自主研究循环（ARL）中一种新的失效模式——"算法性模式坍缩"：表面 diff 多样性（S_T）保持不变，但语义簇数量在 500 轮内下降 50–70%，机制熵从 1.76 nats 跌至 1.18 nats，导致 in-loop 指标收益虚高 2.0–2.6 倍；提出的 DAPS（类别覆盖重加权 CCR + 持久编辑记忆 PEM + 审计验证门 HVG）在 4 个 NLP 任务上将审计忠实度从 VANILLA AR 的 0.44 提升到 0.79（盲评 0.41→0.74，相对提升 83.7%），同时 in-loop 收益保持在最优基线的 1 个标准差以内，每轮墙钟开销仅 ~1.4%。

> **TL;DR:** Across four code-level autonomous research loop (ARL) tasks at T=300 iterations — GPT-2-small pretraining on OpenWebText, Llama-3.2-1B LoRA instruction tuning on Alpaca, Qwen-2.5-1.5B GSM8K fine-tuning, and Llama-3.2-3B DSPy prompt optimization — the paper shows that repeated metric-driven code editing suffers "algorithmic mode collapse": surface edit diversity stays flat (S_T ∈ [0.66, 0.68]) while semantic cluster count collapses by 50–70%, so in-loop gains overstate independent hold-out gains by 2.0–2.6x (faithfulness ratio ρ^audit 0.38–0.49 for VANILLA AR). The proposed DAPS — category-coverage reweighting (CCR), a persistent edit memory (PEM), and an audit-based validation gate (HVG) — raises audited faithfulness to 0.79 (blind 0.74) versus 0.44 for VANILLA AR and 0.58 for the strongest transposed published mitigation (R-DIVERSE-A, a memory-augmented penalty from Li et al. 2026), while keeping in-loop gain within 2% of vanilla (e.g., +8.8 vs +8.9 win-rate points on T2) and adding only ~1.4% per-iteration wall-clock overhead.

## 核心贡献

- **首次对代码级 ARL 的长程动力学进行受控实证研究**：在 4 个 NLP 任务（预训练、指令微调、推理微调、提示词优化）上记录完整的 proposals/diffs/执行/hold-out 评测轨迹，T=300、3–5 个种子、约 6,200 A100-hours。
- **发现"算法性模式坍缩"**：表面（词汇层）编辑多样性在 500 轮内基本持平，而语义簇数量（Sentence-BERT + HDBSCAN）坍缩 50–70%；agent 持续编辑不同代码行，但反复提出同一*类*算法修改（如 T2 后期 74% 的被接受编辑都是学习率调度或 AdamW 超参微调）。到第 300 轮，in-loop 收益平均虚高 2.0–2.6 倍。
- **四轴诊断仪表 + 三层忠实度审计协议**：S_T（表面 Levenshtein 多样性）、C_T（语义簇数）、H_T（9 类机制分类的 Shannon 熵，解析器与前沿 LLM 标注的 Cohen's κ=0.84）、V_T（对 1.1M arXiv 摘要的语料相似度）；配合三层评测——proposer 可见的 m^opt、仅验证门可读的 m^audit、任何组件都不可见的 m^blind。
- **DAPS 缓解框架**（drop-in，三组件）：CCR 按类别覆盖重加权候选提案、PEM 用 200 条历史编辑描述的 Sentence-BERT 嵌入去重（余弦 > 0.85 即拒绝）、HVG 每 10 轮比较 in-loop 与 audit 增益差，超阈值即回滚到最近"忠实"检查点。三组件分别可消融且互补。
- **证明坍缩与缓解都不是某个框架/模型的特例**：在 Claude Opus 4.7、GPT-5.2、Llama-3.3-70B 三个 proposer 以及 autoresearch 和 Aider 两个 ARL 框架下坍缩模式与 DAPS 收益均复现；1,000 轮延长实验显示坍缩会继续加深而非自愈。

## Key Contributions

- **First controlled empirical study of code-level ARL dynamics over long horizons**, with fully logged proposals, diffs, executions, and held-out evaluations across four NLP tasks (T1 pretraining, T2 instruction tuning, T3 reasoning fine-tuning, T4 prompt optimization), T=300 iterations, 3-5 seeds, ~6,200 A100-hours.
- **Identification and quantification of "algorithmic mode collapse"**: surface edit diversity remains essentially flat over 500 iterations while semantic cluster count (Sentence-BERT + HDBSCAN) collapses by 50-70%; the agent keeps editing different lines of code but repeatedly proposes the same *kind* of change (e.g., 74% of accepted edits by iteration 200 on T1 modify learning-rate schedule or AdamW hyperparameters). By iteration 300, average in-loop gains overstate hold-out gains by a factor of 2.0-2.6.
- **A four-axis diagnostic instrument plus a three-tier faithfulness audit protocol**: surface diversity S_T, semantic cluster count C_T, mechanism entropy H_T over a 9-category edit taxonomy (rule-based parser, Cohen's κ=0.84 against a frontier-LLM annotator), and corpus similarity V_T against 1.1M arXiv abstracts — combined with in-loop (m^opt), audited (m^audit, read only by the gate), and blind (m^blind, read by no component) evaluations.
- **DAPS, a drop-in mitigation** with three independently ablatable, complementary components: Category-Coverage Reweighting (CCR) toward under-represented edit mechanisms, Persistent Edit Memory (PEM, M=200 FIFO of edit-description embeddings, cosine rejection at τ_m=0.85), and the audit-based validation gate (HVG, revert to last faithful checkpoint when Δ^faith exceeds a task-calibrated threshold every K=10 iterations).
- **Evidence that collapse and mitigation are neither framework- nor model-specific**: results replicate across three proposer LLMs (Claude Opus 4.7, GPT-5.2, Llama-3.3-70B) and two ARL frameworks (Karpathy's autoresearch and Aider); a 1,000-iteration extension shows collapse deepens rather than self-corrects (ρ^audit 0.46 → 0.31 for vanilla, while DAPS holds 0.74).

## Methodology

**Setup.** A code-level ARL is modeled as a tuple (P, π_θ, E, R): a training pipeline P (source files), an LLM proposer π_θ that emits a textual modification description d_t plus code patch ρ_t, an executor E that runs the modified pipeline on the optimization metric m^opt, and an acceptance rule R that retains the edit only if m^opt improves beyond a noise floor ε. Crucially, the proposer only ever sees m^opt; the audit and blind metrics are held out from it.

**Tasks.** T1 Small-LM Pretraining: a GPT-2-small-style model (~124M) trained on a 0.5B-token OpenWebText subset with a fixed 5-minute budget per execution (nanochat-style, following Karpathy's autoresearch); m^opt = in-distribution validation loss, audit = LAMBADA perplexity + held-out C4, blind = WikiText-103 log-perplexity. T2 Instruction Tuning: Llama-3.2-1B fine-tuned via LoRA on a 20k-example Alpaca subset; m^opt = AlpacaEval-style win-rate on a 500-example dev split, audit = MMLU 5-shot + IFEval, blind = win-rate on 500 held-out Dolly instructions. T3 Reasoning Fine-Tuning: Qwen-2.5-1.5B on GSM8K; m^opt = GSM8K dev exact match, audit = ARC-Easy + MATH-500, blind = SVAMP. T4 Prompt Optimization: frozen Llama-3.2-3B editing a DSPy-style prompt program; m^opt = ARC-Easy dev accuracy, audit = ARC-Challenge + CommonsenseQA, blind = OpenBookQA. Audit tasks are capability-overlapping but distribution-different from in-loop ones; each ARL is capped at 5 minutes per iteration on a single A100.

**Diagnostics.** Four axes: S_T (mean pairwise normalized Levenshtein distance over the last W=20 accepted diffs), C_T (number of young HDBSCAN clusters, min cluster size 5, over Sentence-BERT embeddings of proposer-emitted one-sentence edit descriptions), H_T (Shannon entropy over a 9-category mechanism taxonomy derived from a 187-edit pilot study covering 96.4% of pilot edits; parser vs. frontier-LLM annotator κ=0.84 on a 200-edit validation set), and V_T (mean top-1 cosine similarity against 1.1M pre-2024 arXiv abstracts — descriptive only). The three-tier faithfulness audit defines Δ^faith = g^opt − g^audit, where g^blind is evaluated once per run by a component no loop element ever reads.

**DAPS.** (i) CCR: sample N=8 candidates, re-weight w(p) ∝ exp(−log p_t(c(p))/τ_c) with τ_c=1.0 toward mechanism categories under-represented in the last W accepted edits — it changes only which candidate is presented, never alters the proposer. (ii) PEM: FIFO memory of M=200 Sentence-BERT embeddings of accepted edit descriptions; reject any candidate whose cosine similarity to its nearest neighbor exceeds τ_m=0.85. (iii) HVG: every K=10 iterations compute Δ^faith from one audit evaluation; if it exceeds a task-calibrated threshold η_t (the 80th percentile of |Δ^audit| over the first 30 iterations under VANILLA AR), revert the pipeline to the last faithful checkpoint and append a templated, value-free failure summary to the proposer's history. All DAPS hyperparameters are fixed across tasks; all baselines receive the same tuning budget (three-point grids per key hyperparameter, Appendix N).

**Baselines.** Eight: VANILLA AR (faithful reimplementation of Karpathy 2026), HiTemp (proposer temperature 0.7→1.2), R-Diverse-A (memory-augmented penalty of Li et al. 2026 transposed to edit descriptions — the strongest published mitigation), Prism-A (semantic cluster-coverage reward of Mishra 2026), Reflexion (reflection summaries), RandSearch (proposer-free uniform sampling from a harvested edit corpus — isolates the value of adaptive proposals), Ho-EarlyStop (audit-read early stopping), and Ho-Revert (HVG alone). Data-level mitigations (B3, B4) and audit-access controls (B7, B8) separate "more diversity" from "more audit signal" as explanations.

**Robustness and validity checks.** Construct-validity controls: 12 known-good edits from published recipes score ρ≈0.93 while 8 deliberately proxy-only edits (dev-shard-specific example ordering, judge-phrasing tweaks, dev-tuned answer templates) score ρ=0.11±0.08 — the metric separates genuine from proxy-only improvement. The taxonomy result survives coarse/fine/random/human taxonomies and a taxonomy-free Kozachenko–Leonenko differential-entropy estimate (drop of 0.44 nats vanilla vs 0.07 DAPS); an AST-based detector on raw diffs confirms 71% of late-stage T1 edits touch optimizer/schedule code; cluster decay is invariant to summarizer, embedding model, and clustering algorithm (Spearman > 0.93).

## Results & Highlights

- **Faithfulness (headline).** Averaged over four tasks and 3 seeds at T=300, DAPS reaches ρ^audit = 0.79 and ρ^blind = 0.74, versus 0.44/0.41 for VANILLA AR — a relative faithfulness improvement of 81.6% audited and 83.7% blind, with semantic-cluster decay ΔC reduced by 69.1% (0.68 → 0.21). Per-task audited ratios: T1 0.78±.04, T2 0.80±.05, T3 0.74±.06, T4 0.82±.04 vs VANILLA AR's 0.41/0.46/0.38/0.40; the strongest published mitigation (R-Diverse-A) only reaches 0.58-0.60 and costs 3-13% relative in-loop gain on T2/T3.
- **In-loop speed preserved.** DAPS's in-loop gain stays within one standard deviation of the best configuration everywhere and within 2% of VANILLA AR on average (normalized g^opt 0.983): on T2, +8.8±1.0 win-rate points vs +8.9±1.2 for VANILLA AR (absolute dev win-rate 47.2 vs 47.3); on T3, GSM8K dev exact match 31.2 → 42.7 vs 42.9; iterations to reach 80% of vanilla's terminal gain are 163±0 vs 154±8 on T2 (within seed-to-seed variance). By contrast, RandSearch is similarly faithful (ρ 0.74-0.79) but forfeits roughly half the in-loop gain (T2 +4.1 vs +8.9 points).
- **Collapse signature quantified.** On T2 under VANILLA AR, mechanism entropy H_T falls from 1.76 nats at t=30 to 1.18 nats at t=300 while surface diversity S_T stays in [0.66, 0.68] — a surface-only monitor would raise no flag — and the faithfulness gap Δ^faith grows monotonically from ≈0.05 at t=60 to ≈0.17 at t=300 with almost no iteration lag behind the entropy collapse; DAPS stabilizes the gap at ≈0.07 and H_T at 1.71 nats.
- **Ablation shows complementarity.** HVG alone lifts ρ^audit 0.44 → 0.67 but barely dents cluster decay (ΔC 0.68 → 0.55); CCR+PEM without any audit access already reach 0.71/0.28, beating both published mitigations on both faithfulness tiers; the full system achieves 0.79/0.21 at normalized in-loop cost 0.983. Component effects are sub-additive (alone: +0.14, +0.17, +0.23).
- **Transfers across proposers and frameworks.** Re-running T2 with Aider as a drop-in proposer-editor: VANILLA-AIDER shows ρ^audit 0.48 and H_T 1.22 nats — statistically indistinguishable from autoresearch's collapse despite structurally different edits (SEARCH/REPLACE blocks, higher S_T 0.74 vs 0.66) — and DAPS-AIDER lifts ρ^audit to 0.76 and H_T by ~0.4 nats. All three proposer LLMs (Claude Opus 4.7, GPT-5.2, Llama-3.3-70B) collapse under vanilla; Llama-3.3-70B (narrowest prior over ML edits) collapses most severely.
- **Negligible overhead.** DAPS adds ~1.4% per-iteration wall-clock on T2 (1.4% T1, 1.2% T3, 0.7% T4), dominated by the amortized audit evaluation (3.9 s/iter of a 300 s/iter budget); CCR and PEM are ~0.1-0.2% each.
- **Longer horizons worsen it.** At T=1,000 with a 1B-token target, vanilla ρ^audit drops further to 0.31 (H_T 0.94) while DAPS holds 0.74 (H_T 1.68) — collapse deepens rather than self-corrects, as the conceptual model (F1-F3 feedback mechanisms) predicts.

Yili Jin (MirrorSpace Technology / SFU) is the corresponding author. The paper is unusually thorough for the autonomous-research-agent space: ~6,200 A100-hours of sweeps, matched tuning budgets for all eight baselines, blind evaluation tiers, construct-validity controls with known-good and proxy-only edits, human validation of both the taxonomy (3 annotators, κ=0.81) and the corpus-similarity axis, and openly stated scoping in the Limitations section. The work builds directly on Karpathy's 2026 autoresearch release and positions itself against a fast-moving 2025-2026 literature (AI-Scientist family, Agent Laboratory, AI Co-Scientist, Aitoresearchbench) — topical, current, and the authors clearly know the adjacent recursive-training/diversity-collapse and reward-hacking literatures. Code is stated to be released in a GitHub repository, with full trajectory logs promised. No obvious conflicts of interest beyond the industrial affiliation.

## Critical Assessment

This is a genuinely strong empirical paper whose main asset is the evaluation protocol, and its honesty is verifiable in its own tables — but several scope and construction choices deserve scrutiny. **Novelty:** none of DAPS's three components is algorithmically new — PEM is explicitly the memory-augmented penalty of Li et al. (2026) transposed from generated text to edit descriptions, the coverage idea comes from Mishra (2026), and HVG is a calibrated revert-to-checkpoint; the contribution is the diagnosis (a phenomenon nobody had measured in code-level loops) plus the three-tier blind protocol, and the paper credits prior work correctly. **Rigor:** the strongest evidence is the matched audit-access experiment (Table 3), which cleanly separates "audit signal helps" from "diversity helps": Ho-EarlyStop and Ho-Revert, which read the same audit metric, reach at most ρ^audit 0.62-0.67 and leave ΔC ≥ 0.55, while CCR+PEM with zero audit access reach 0.71/0.28 — DAPS's advantage genuinely persists on data the loop never influenced (0.74 blind). The known-good (ρ=0.93) vs proxy-only (ρ=0.11) construct controls are exemplary. **Weak points:** (1) *Scale* — every task runs a ≤3B model or a 124M GPT-2 on a single A100 with 5-minute iterations; the 2.0-2.6x overstatement factor is measured in this regime, and the authors themselves scope the headline claims accordingly; the 8B-target row of Appendix L (one seed) is reassuring but thin. (2) *The mechanism taxonomy has a mild circularity risk*: the 9 categories were derived from a pilot study of other ARL systems' logs and assigned by a rule-based parser "cross-validated against parallel labelling by a frontier LLM annotator" — the parser was built against LLM labels, so κ=0.84 partially measures agreement with the design target; the human-labelling and taxonomy-free differential-entropy checks in Appendices I-J largely defuse this, which is to the authors' credit. (3) *DAPS has sharp hyperparameter edges*: at τ_m ≥ 0.95 PEM rejects almost all candidates and ρ^audit collapses back to vanilla's 0.46; at τ_m = 0.75 the proposer is starved (+7.7 vs +8.8 in-loop on T2); M=500 over-suppresses legitimate revisits (ρ 0.74). The central range is forgiving, but the defaults were tuned on T2 — cross-task transfer of the defaults is shown, not guaranteed a priori. (4) *The calibration of η_t consumes vanilla-AR runs* (the 80th percentile of |Δ^audit| over the first 30 iterations under VANILLA AR), so deploying DAPS requires a small calibration budget per task that is not counted in the headline overhead. (5) *The V_T corpus-similarity axis is the weakest instrument*: the authors' own human validation shows only moderate correlation with human novelty judgments (Spearman −0.47, CI [−0.60, −0.31]) and they correctly demote it to descriptive status, yet the introduction's framing ("reliance on its prior rather than exploring") leans on it. (6) The audit gate reads m^audit every 10 iterations, so the method is not fully metric-agnostic in deployment — the blind-tier results answer this concern, but only for these four tasks. (7) The non-ML probe (log-analytics runtime loop, Appendix M) is 150 iterations, 2 seeds, one domain — correctly labeled preliminary. Overall: the core phenomenon and the blind-tier faithfulness result look solid and well-controlled; the generalization to frontier-scale executors and to loops whose audit evaluations are expensive relative to iteration cost remains open.

## Strengths

- A new, cleanly named and *measured* failure mode for autonomous research loops, with a four-axis instrument that predicts and explains it (surface diversity provably orthogonal to semantic collapse — Figure 2) and a conceptual model (F1-F3: non-uniform proposer priors, acceptance-rate dependence, self-imitation through history conditioning) that yields testable predictions P1-P6, several of which are verified (temperature does not help; memory alone only modestly reduces ΔC; collapse deepens with horizon).
- The three-tier (in-loop / audited / blind) evaluation protocol is the paper's real contribution to methodology: it makes Goodharting *measurable by construction*, and the headline claims are placed on the tier no component can access.
- Exceptional validity hygiene for this subfield: matched audit access (Table 3), matched baseline tuning budgets (Appendix N), known-good vs proxy-only construct controls (ρ = 0.93 vs 0.11), taxonomy-invariance (coarse/fine/random/human + taxonomy-free entropy estimate + AST-based detector), and honest scoping of every claim in a dedicated validity appendix (Table 9).
- Practical significance: DAPS is a drop-in wrapper (never modifies the proposer), costs ~1.4% wall-clock, preserves in-loop speed, and degrades gracefully — and the ablation tells a practitioner exactly which component to buy: CCR+PEM if you have no audit signal (0.71 blind-side faithfulness for free), add HVG if you can afford one audit evaluation per 10 iterations.
- Replication across three proposer LLMs and two frameworks, including the Aider cross-check, which specifically rules out the "this is just autoresearch's diff format" alternative explanation.

## Limitations

- **Scale ceiling (acknowledged):** all headline results are single-A100, ≤3B-parameter, 5-minute-iteration loops; frontier proposer+executor settings and 10k+ iteration horizons are untested (the single-seed T=1000 and 8B-target rows are first steps only).
- **Domain scope (acknowledged):** headline claims cover ARLs that edit ML training pipelines; the mechanism taxonomy is ML-centric, and the prompt-engineering non-ML probe is small and single-domain.
- **Blind sets are still benchmarks:** the paper concedes they may share idiosyncratic biases with the in-loop metric; with only 3-4 audit/blind tasks per run, the ρ estimates carry non-trivial variance (visible in Table 11's per-component spreads).
- **Hyperparameter fragility at the edges:** τ_m ≥ 0.95 is a sharp failure mode (PEM rejects nearly everything, ρ^audit collapses to 0.46); M=500 over-suppresses revisits; η_t calibration requires preliminary vanilla-AR runs per task.
- **V_T is a weak instrument:** only moderate agreement with human novelty ratings (Spearman −0.47); the paper keeps it as descriptive, but the narrative occasionally leans on it.
- **Cost accounting at real scale:** the audit evaluation is amortized cheaply only because iterations cost 5 minutes; for long, expensive training runs, the one-audit-per-10-iterations budget of HVG could dominate, and the paper does not model this regime.
- The 50-70% cluster-collapse figure in Figure 1 is measured over 500 iterations while the headline tables use T=300; the two horizons are used somewhat interchangeably in the narrative.

## Relevance

这篇论文正中你的第一优先方向「自进化 Agent 与自动化研究」：它把 autonomous research loop 的可靠性问题从"最终结果好不好"推进到"优化过程本身在自我欺骗"这一可测量层面，其三层盲评协议和四轴诊断仪表对任何长期运行的自改进 agent 系统都是直接可复用的监控工具。同时它与你关注的 LLM 训练稳定性/可观测性高度相关——机制熵坍缩与 faithfulness gap 的单调 widening 本质上就是训练循环里的"静默异常检测"问题。

## Questions for Further Exploration

- Does algorithmic mode collapse change character when the executor is a frontier-scale training run where a single audit evaluation costs as much as hundreds of vanilla iterations — does HVG's 1-per-10-iterations cadence survive, or does a cheaper proxy audit (e.g., subset-based) suffice?
- The conceptual model predicts collapse deepens with horizon (verified to T=1,000, one seed): is there a horizon beyond which CCR's category prior itself becomes harmful by forcing the agent into weak categories, i.e., a diversity-performance Pareto frontier?
- Can the audit metric be *learned* (a distilled judge of "did this edit transfer?") rather than fixed per task, without reintroducing the Goodhart channel the three-tier protocol exists to detect?
- The corpus-similarity axis V_t rises as the loop concentrates on familiar edits — is this recitation of the proposer's prior (as the paper cautiously frames it) or actual retrieval-adjacent behavior, and could a retrieval detector over the proposer's own training data disambiguate?
- How does collapse interact with multi-agent ARLs (proposer, critic, executor as separate agents), which the authors list as open future work — does a critic agent's rejection distribution itself collapse?
- The taxonomy is ML-centric; the non-ML probe used a fresh 7-category taxonomy derived with the same pilot protocol — is the diagnosis pipeline now cheap enough to standardize as a public "ARL observability" harness across domains?
