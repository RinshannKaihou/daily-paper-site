> **一句话总结：** PRACTICE 在冻结的具身执行器（Qwen3-VL-32B-Instruct）之上训练一个 8B 的"技能学习者"，通过三阶段课程（oracle 成功轨迹 SFT → 成败对比的失败感知 SFT → 用 32B 教师对学习者自身生成的技能编辑 rollout 做在线策略蒸馏 Skill OPD）持续对持久技能库执行 ADD/REVISE/MERGE/REMOVE 编辑，把 EB-ALFRED 平均成功率从 24.3% 提到 49.7%，超过最强经验增强基线 MemCompiler（40.7%）9.7 个百分点，且训练总开销仅约 7 GPU 小时 SFT + 64 GPU 小时 OPD（8×A100）。

> **TL;DR:** PRACTICE treats an embodied agent's skill library as trainable procedural knowledge rather than a prompt-engineered artifact: a small skill learner (Qwen3-VL-8B-Instruct) learns to edit persistent skill cards (action-pattern sequences + usage specs) while the executor (Qwen3-VL-32B-Instruct) stays frozen. A three-stage curriculum — oracle-grounded SFT, failure-aware SFT contrasting successful vs failed trajectories from 8 heterogeneous executors, and Skill OPD (Top-K forward-KL on-policy distillation from a frozen 32B teacher over the student's own edit rollouts, no task reward) — lifts EB-ALFRED average success from 24.3% (no skill) to 49.7%, beating the strongest experience-augmented baseline MemCompiler (40.7%) by +9.7 points and EB-Habitat 58.3% vs 55.7% (+2.6). In cross-executor tests it adds +30.3 points to GPT-5.2, +25.4 to Qwen3-VL-32B, and +2.4 to GPT-5.4 on EB-ALFRED, for a total cost of ~7 GPU-hours SFT + 64 GPU-hours OPD.

## 核心贡献

- **把技能维护从"提示词工程"变成"可学习策略"**：与 Trace2Skill、AutoSkill、MemCtrl、SkillOS 等依赖固定人工流程来提炼/合并技能的方法不同，PRACTICE 将技能库视为可进化的过程性知识，将"如何更新库"本身建模为可训练的技能学习者 S（输出对技能卡的结构化编辑：ADD / REVISE / MERGE / REMOVE），与执行器解耦形成"学习者-库"协同进化闭环：库引导执行器产生轨迹 → 轨迹训练学习者 → 学习者更新库。
- **三阶段课程训练**：Stage 0 用成功 oracle 轨迹做技能生成/库编辑/跨批次库合并（去重、合并重叠动作模式、保留不同前置条件）三类监督冷启动；Stage 1 引入 8 个异构执行器在同一任务上的成败对比轨迹，教会学习者识别技能失效条件并生成恢复策略（failure-aware editing）；Stage 2 提出 Skill OPD——把 on-policy distillation（Top-K 前向 KL，教师 Top-K=32、学生 K=8）用于技能编辑，学生在自己生成的 rollout 前缀上对齐更强教师的 token 分布，绕开了 RL/PPO 的不稳定性，也修正了离线 SFT 的训练-推理分布失配。
- **失败感知监督的受控消融**：仅追加更多成功轨迹只把平均成功率从 42.3% 提到 42.7%，而失败感知编辑把它提到 45.3%（+2.6），其中 Long-horizon split 从 8% 升到 14%——证明改进来自"从失败中学习失效条件与恢复策略"而非单纯数据增量。
- **冻结执行器下的跨执行器泛化**：同一技能库/学习器流水线在 GPT-5.4、GPT-5.2、Gemini-3-Flash、Qwen3-VL-32B 四个执行器上都带来一致提升（EB-ALFRED 平均分别 +2.4 / +30.3 / +15.3 / +25.4 个百分点），是所有已报告经验增强方法中在 GPT-5.2 和 Qwen 上最大的匹配提升。
- **技能库演化分析**：最终 EB-ALFRED 库含 29 张技能卡（13 单动作 + 16 复合），EB-Habitat 15 张（5 + 10）；长技能如 HeatAndStoreFoodItem（15 个动作）、MultiObjectSearchAndTransfer（8 个动作）表明库能抽象出多步宏过程，且粒度随环境自适应（EB-ALFRED 偏长操作序列、EB-Habitat 偏紧凑的搜索-转移抽象）。

## Key Contributions

- Reframes skill evolution as a coupled learner-library self-evolution problem: a trainable skill learner S produces structured library edits (ADD/REVISE/MERGE/REMOVE) for a persistent skill library, while the task executor π_exec stays frozen — directly addressing the brittleness of fixed, prompt-engineered skill-maintenance workflows (Trace2Skill, AutoSkill, MemCtrl, SkillOS).
- A three-stage curriculum: (0) oracle-grounded SFT with three supervision types — skill generation from an empty library, editing an initialized library, and cross-batch consolidation that removes duplicates and resolves conflicting applicability conditions; (1) failure-aware SFT built from same-task success/fail contrast batches of trajectories from 8 heterogeneous executors, teaching invalid-condition identification and recovery strategies; (2) Skill OPD, an on-policy distillation objective (Top-K forward KL between a frozen 32B teacher and the student on student-generated edit rollouts, K_teacher=32, K_student=8) that needs no task reward or PPO machinery.
- A controlled ablation isolating failure-aware learning: adding more successful trajectories yields only +0.4 average (42.3→42.7) while failure-aware editing yields 42.3→45.3 (+2.6), with the Long split improving 8%→14%.
- Cross-executor generality under a matched multi-eval protocol (MemCompiler's setup): consistent EB-ALFRED gains of +2.4 (GPT-5.4), +30.3 (GPT-5.2), +15.3 (Gemini-3-Flash), +25.4 (Qwen3-VL-32B) — the largest reported matched improvements among experience-augmented methods on GPT-5.2 and Qwen.
- Detailed library and execution analyses: the final EB-ALFRED library has 29 skills (13 single-action, 16 composite; HeatAndStoreFoodItem expands to 15 actions), EB-Habitat 15 skills (5 single, 10 composite; MultiObjectSearchAndTransfer spans 8 actions), plus paired-episode evaluation showing skills recover 91 baseline failures at the cost of 15 regressions on EB-ALFRED (+25.3 pp net).

## Methodology

**Problem setup.** The system comprises a frozen embodied executor π_exec, a persistent skill library V = {v_j} of skill cards, and a trainable skill learner S. A skill card v_j = (p_j, u_j) pairs an action-pattern sequence p_j = [(a_1, φ_1), …, (a_L, φ_L)] (primitive actions with argument templates, e.g. `pick_up_object_target` for "picking up") with a usage specification u_j describing semantic scope, execution preconditions, expected effects, and recovery strategies from failure. Execution follows π_exec(·|I, h_t) augmented with the retrieved library; the learner sees trajectory sets T and predicts an edit set Δ = S(V, T), applied as V ← Apply(V, Δ), forming the coupled cycle V_i → T_i → S_{i+1} → V_{i+1} → T_{i+1}.

**Initial library construction (BPE-inspired).** Successful executor trajectories are augmented, converted to primitive-action sequences, and frequent adjacent action subsequences are iteratively merged (analogous to byte-pair encoding) to discover recurring multi-step patterns; a pretrained base model (S_0) then consolidates these patterns into structured skill cards, yielding V_0.

**Stage 0 — Oracle-grounded SFT.** Using only successful oracle trajectories, three supervision types are generated by a strong teacher (Qwen3-7-Max): (a) skill generation from an empty library, (b) editing the BPE-initialized library given trajectory evidence (add/revised/merge/preserve local edits), and (c) cross-batch library consolidation — a teacher merges edits from M independently sampled batches into a globally consistent target that removes semantic duplicates, merges compatible patterns, reconciles overlapping trigger conditions, and preserves distinct skills with different preconditions/effects. This trains S_0 → S_1, producing V_1.

**Stage 1 — Failure-aware SFT.** Trajectories are grouped by task across 8 heterogeneous executors (including Gemini-2.5-Flash, Gemini-3-Pro, Gemini-3.5-Flash, GPT-5.4, Qwen3.5-Flash, Qwen3-VL-8B/32B), so same-task success/fail pairs isolate behavioral differences as controlled evidence. The teacher jointly analyzes all trajectories in a batch to emit failure-aware edits that record invalid conditions for skill application and concrete recovery strategies. A control variant (Stage 1 Succ-Only) keeps everything but removes failure supervision.

**Stage 2 — Skill OPD (online skill-edit policy distillation).** At each OPD round, incoming executor trajectories are grouped into editing batches; the current student S_i samples edit rollouts from its own output distribution (one rollout per prompt, global batch 8). A frozen stronger teacher (Qwen3-VL-32B-Instruct) computes Top-K token distributions on the same student-generated prefixes, and the student minimizes truncated forward KL aggregated over response tokens — pure distillation, no task reward, no PPO/GRPO gradient terms, no auxiliary objectives. This matches the student's inference-time distribution and lets teacher, student, and library evolve together instead of anchoring to a fixed offline dataset.

**Implementation.** Student Qwen3-VL-8B-Instruct; SFT supervision from Qwen3-7-Max (3 epochs, lr 5e-7, bfloat16); OPD teacher Qwen3-VL-32B-Instruct frozen, 20 epochs, lr 5e-7 constant, AdamW. Training cost ≈ 7 GPU-hours for SFT (Stage 0 ~4 h, Stage 1 ~3 h) + 64 GPU-hours for OPD on 8×A100-40GB (FSDP + vLLM, bf16). Curriculum data volume: ~2,250 SFT examples per benchmark (EB-ALFRED: 1,885 success / 1,123 fail source trajectories → 1,700 edit + 550 consolidation samples). Code/resources at https://baai-agents.github.io/PRACTICE/.

## Results & Highlights

- **Main results (frozen Qwen3-VL-32B executor, Table 1).** PRACTICE reaches 49.7% average success on EB-ALFRED vs 40.7% for the strongest experience-augmented baseline MemCompiler (+9.7 points) and 24.3% for the no-skill executor (+25.4); on EB-Habitat it reaches 58.3% vs MemCompiler's 55.7% (+2.6) and no-skill 37.3%. It is best on five of six EB-ALFRED splits and four of six EB-Habitat splits, and with a GPT-5.4 executor it reaches 67.7% (EB-ALFRED) and 72.0% (EB-Habitat) vs GPT-5.4 no-skill 65.3% / 65.7% (+2.4 / +6.3), surpassing the proprietary Qwen3.5-Flash (37.0% / 38.0%).
- **Cross-executor generalization (Table 2, MemCompiler's multi-eval protocol).** PRACTICE improves EB-ALFRED average success by +30.3 points on GPT-5.2 (32.0→62.3) and +25.4 on Qwen3-VL-32B (24.3→49.7) — the largest reported matched improvements among the compared methods (BrainMem +10.7 on Claude-3.5-Sonnet, MemCtrl +2.2, MemCompiler +21.0 on Qwen3-VL-32B) — but only +2.4 on the already-strong GPT-5.4 (65.3→67.7).
- **Stage-wise ablation (Table 3, Qwen3-VL-32B executor, EB-ALFRED).** No skill 24.3% → BPE-initialized static library (17 cards) 40.7% → Stage 0 SFT 42.3% (27 cards) → Stage 1 failure-aware SFT 45.3% → Stage 2 Skill OPD 49.7% (29 cards), i.e. OPD contributes the largest single-stage jump (+4.4); failure-aware learning alone lifts the Long-horizon split from 6% to 14%.
- **Failure-aware supervision ablation (Table 4).** The success-only Stage 1 variant reaches 42.7% average (only +0.4 over Stage 0's 42.3%), while the full failure-aware variant reaches 45.3% (+2.6 over success-only, +3.0 over Stage 0), with the largest gain on Long (8%→14%) and +4 on Base and Complex.
- **Execution analysis (300 EB-ALFRED episodes, Fig 7).** With learned skills, failure-free episodes rise from 40/300 (13.3%) to 77/300 (25.7%) and overall success from 73/300 (24.3%) to 149/300 (49.7%); among episodes with rejected actions, final success rises from 35/300 (11.7%) to 76/300 (25.3%). Paired per-split evaluation: skills recover 91 no-skill failures at 15 regressions on EB-ALFRED (net ΔSR +25.3 pp; +36 pp on Base and Complex, +30 pp on Spatial, and 12 long-horizon episodes solved vs 0 for the baseline), and 58 recoveries vs 32 regressions on EB-Habitat (+8.7 pp; +20 pp Visual, +12 pp Complex, +10 pp Base, but 0 pp on Spatial and +4 pp on Long).
- **Efficiency.** Total training is ~7 GPU-hours of curriculum SFT plus ~64 GPU-hours of Skill OPD on 8×A100-40GB — no executor post-training, no RL rollouts against the environment reward.

## Authors & Credibility

The paper comes from the Beijing Academy of Artificial Intelligence (BAAI) and the Institute of Software, Chinese Academy of Sciences; Ziyi Bai and Siqi Li contributed equally, with Börje F. Karlsson (BAAI) as corresponding author. The team maintains a public project page (https://baai-agents.github.io/PRACTICE/) with resources, and the appendix is unusually transparent: full hyperparameters and system configs (Table 6), the complete data-generation recipe (batch sizes, candidate counts, teacher identities), pseudocode for both training loops, and an honest qualitative failure study (Figs 13, 16). The work positions itself carefully against a broad and current related-work set (EmbodiedBench-era executor-post-training methods and 2025–2026 experience/memory agents such as MemCompiler, MemCtrl, ELITE, SkillOS), and all headline comparisons use the same frozen executor for fairness. No prior red flags; the claims are scoped to "experience-augmented" baselines rather than all methods.

## Critical Assessment

- **The headline gain conflates static skill injection with learned maintenance.** Of the +25.4 points over no-skill on EB-ALFRED, +16.4 comes from the BPE-initialized static library alone (24.3→40.7) before any training; the three learning stages together add +9.0 (40.7→49.7), and failure-aware learning specifically contributes +3.0. "Learning to grow skills" is the paper's thesis, but a reader should know that most of the improvement is available from the unlearned initial library.
- **Absolute performance still trails executor post-training by a wide margin.** PRACTICE-augmented Qwen3-VL-32B reaches 49.7% on EB-ALFRED, whereas executor-post-trained ELITE reports 70.8% and ORBIT 72.4% on the same benchmark; on EB-Habitat, RoboAgent reaches 67.0% vs PRACTICE's 58.3%. The frozen-executor framing is honest about this, but the "self-evolving" narrative should not be read as closing the gap to post-trained executors — it is a cheaper, composable alternative within the experience-augmented class.
- **Gains shrink sharply as the executor strengthens**: +30.3 on GPT-5.2 and +25.4 on Qwen3-VL-32B, but only +2.4 on GPT-5.4 — and Table 2 shows LangMem on Gemini-3-Flash reaching a higher augmented score than PRACTICE on the same executor, so the "largest improvement" claim holds only for GPT-5.2 and Qwen, as the authors themselves word it. The method's value proposition is concentrated on weaker executors.
- **Missing ablations and single-teacher OPD.** There is no ablation over the OPD teacher (only Qwen3-VL-32B, which is also the executor model — a potential circularity the paper does not discuss), no comparison of BPE initialization against a random or LLM-only cold start, and no baseline of simply retrieving and pasting raw successful trajectories into the prompt. Table 1 averages are single-run numbers without variance or seeds (the paired skill-level analysis does include 95% bootstrap CIs, but headline averages do not).
- **Hidden data cost.** Stage 1 supervision is generated from 8 executors, most of them frontier proprietary models (GPT-5.4, Gemini-3-Pro/3.5-Flash, Qwen3.5-Flash, with Qwen3-7-Max as the SFT data teacher), producing ~3,000 trajectories per benchmark; the paper reports only the 7+64 GPU-hours of learner training, not the (substantial) API cost of generating the supervision data — an omission that flatters the "lightweight" framing.
- **Scope limits are visible in the authors' own analysis**: paired EB-Habitat Spatial shows 0 pp net improvement, EB-ALFRED Long-horizon still sits at 24.0% success, and the failure study identifies unresolved containment/holding-state consistency and incorrect source-receptacle hypotheses. Everything is evaluated in simulated, high-level (discrete-action) benchmarks; there are no real-robot experiments.

## Strengths

- Clean, well-motivated formulation: skill maintenance as a trainable update policy co-evolving with a persistent library, with the executor frozen — making the method orthogonal to and composable with any executor, including proprietary ones.
- Skill OPD is a genuinely interesting adaptation of on-policy distillation to a non-action generation task (structured library editing), sidestepping RL instability while fixing the train–inference distribution mismatch of offline SFT; no task reward engineering is needed.
- The failure-aware supervision idea is validated by a proper controlled ablation (success-only vs failure-aware at equal data volume), and the Long split 8%→14% result shows the learned invalid-condition/recovery fields carry real signal.
- Exceptional analysis depth: paired-episode evaluation with bootstrap CIs, per-skill benefit-risk quadrant analysis (flagging harmful low-frequency skills like Drop and HoldObjectWhileTurningOnLight), library hierarchy statistics, and candid failure case studies.
- Very low training cost (~71 GPU-hours total) with fully published hyperparameters and a public project page — easy to audit and re-implement.

## Limitations

- Evidence is confined to two simulated, high-level embodied benchmarks (EB-ALFRED, EB-Habitat) with discrete action spaces; transfer to continuous control or real robots is untested, and the skill-card formalism (primitive action patterns) may not extend directly.
- Absolute numbers remain well below executor-post-training methods (ELITE 70.8%, ORBIT 72.4% on EB-ALFRED vs 49.7% here), so the approach complements rather than replaces post-training; whether gains stack with post-trained executors is not measured.
- Benefit concentrates on weak executors (+2.4 on GPT-5.4 vs +30.3 on GPT-5.2), and 0 pp net on EB-Habitat Spatial — spatial grounding, persistent object identity, holding-state management, and long-horizon error accumulation remain unsolved (EB-ALFRED Long at 24.0%).
- The supervision pipeline depends on proprietary frontier models for trajectory generation and teacher labeling, making exact reproduction partially contingent on API access, and the true end-to-end data cost is not reported.
- Library growth is modest (29 cards on EB-ALFRED) and evaluated over a short horizon; long-run stability of the co-evolution loop (library bloat, drift, or collapse over many more OPD rounds) is uncharacterized.

## Relevance

这篇论文正中你的第一优先方向 Self-Evolving Agents：它把"智能体自我进化"具体化为一个可训练的技能库维护策略（learner-library 协同进化），并用在线策略蒸馏替代 RL 来稳定这个自改进循环，与 Voyager/Trace2Skill/SkillOS 一脉的经验增强方法形成直接对照。如果你关心自进化系统的可靠性与可扩展性，文中"失败感知监督 +2.6 分而堆成功数据仅 +0.4 分"的消融，以及对弱/强执行器收益不对称的分析，都是值得借鉴的实证结论。

## Questions for Further Exploration

- Can Skill OPD be combined with a task-reward signal (e.g., value-weighted edit acceptance) without reintroducing RL instability, or does pure teacher-KL cap the achievable library quality at the teacher's editing ability?
- Would the gains stack with executor post-training methods (ELITE, ORBIT, RoboAgent), or does a stronger executor shrink the marginal value of library evolution to zero, as the GPT-5.4 (+2.4) result suggests?
- How does the co-evolution loop behave over many more OPD rounds than reported — does the library keep improving, saturate, or accumulate noisy edits that eventually degrade execution (a key reliability question for long-running self-evolving systems)?
- The BPE-style cold start supplies +16.4 of the total +25.4 points; could the learned policy itself replace pattern-mining initialization, or is the static bootstrap essential?
- Can failure-aware skill cards extend to continuous/low-level action spaces and real robots, where "rejected action" feedback is noisier and recovery strategies are physically grounded?
