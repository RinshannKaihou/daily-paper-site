# Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills

> **一句话总结：** 来自 BAAI/USTC/人大团队的 DisCo 把自主科研智能体形式化为「模型 + harness + 操作性知识 K」三层结构，用任务无关蒸馏（1,000 个热门 ML 仓库 → 5,353 个经验证的技能图，约 $40/仓库）和任务导向蒸馏两条流水线自动生产技能库 AREX-Skill；在 GPT-5.5 Codex 骨干与 harness 完全固定、仅注入技能的对照设置下，MLE-bench（75 场比赛）Any-Medal 从 31.11% 升到 72.89%（+134.3%），PaperBench 从 29.45% 升到 39.59%（+34.4%），FrontierCS 从 70.63 升到 77.14（+9.2%，95% CI [3.41, 9.83]），PassNet AS 从 1.343 升到 1.5313（+14.0%），且在 FrontierCS 上以 3.1–3.3× 更少的 token Pareto 压制 Claude Code 配置。

> **TL;DR:** DisCo identifies "operational knowledge" (how to actually make ML methods work: package APIs, config pitfalls, recovery procedures) as a missing third component of autonomous research agents alongside the model and harness. It distills declarative sources — 1,000 popular GitHub repos plus papers — into 5,353 verified, provenance-grounded skill graphs organized into 20 areas / 178 capability families (the AREX-Skill Library, ~$40 of GPT-5.5/5.6-sol compute per repo). Attaching these skills to a fixed GPT-5.5 Codex agent raises MLE-bench Any-Medal from 31.11% to 72.89% (+41.78 pts), PaperBench replication score from 29.45% to 39.59% (+10.14 pts, beating the strongest public baseline Famous-Agent 2.0's 64.44% on MLE-bench by +8.45 pts), FrontierCS from 70.63 to 77.14 with 3.1–3.3× fewer tokens than Claude Code, and PassNet AS score from 1.343 to 1.5313 (above TorchInductor's 1.419).

## 核心贡献

- **提出「操作性知识」（operational knowledge）这一缺失层**：自主科研智能体通常被描述为 (M_θ, H)（模型 + harness），但决定"知道什么、何时知道、何时开始"的领域 know-how（选方法、用对包 API、配置训练管线、避开常见坑）两者都不承载。论文将其形式化为第三个组件 K，把研究智能体写作 A_res = (M_θ, H, K)，并区分 harness（决定 how）与 K（决定 what the agent knows）。
- **DisCo：既能造技能又能用技能的科研智能体**。技能蒸馏分两种：任务无关蒸馏（锚点是仓库/论文，提前批量生产可复用技能）与任务导向蒸馏（锚点是具体任务，按需现场生产技能）。每次蒸馏走统一的四阶段流程：scope → ground → construct → verify，未通过的缺口写入构造记录 R 而不是隐藏——验证是蒸馏与摘要的本质区别。
- **AREX-Skill Library**：对 1,000 个广泛使用的 ML 仓库跑任务无关蒸馏，产出 5,353 个技能、2,209 条精确的「区域→能力族」路由记录（20 区域 × 178 能力族，700 个仓库跨多族），外加 636 个论文衍生技能（153 篇源论文）与 MLE-bench / FrontierCS / PassNet 三个任务导向技能图。技能统一为三层格式 (SKILL.md, references/, scripts/)，经 progressive disclosure 按需加载。
- **在四个基准上、固定骨干/harness/下游预算的对照实验**：技能注入让 MLE-bench +134.3%、PaperBench +34.4%、FrontierCS +9.2%、PassNet +14.0%；分析显示增益随任务难度上升而扩大（MLE-bench High 档 +48.89 pts），且增益与额外 token 用量几乎不相关（Spearman ρ ≈ 0.006–0.015）。

## Key Contributions

- Formalizes **operational knowledge K** as the missing layer of autonomous research agents: A_res = (M_θ, H, K), where the harness governs *how* the agent researches but neither the model nor the harness supplies the domain content (which method, which package API, which pitfalls) that turns a known method into a working run.
- Presents **DisCo**, a skill-powered research agent with creator mode (distills skills) and researcher mode (solves tasks using them), built on a four-stage distillation run (scope → ground → construct → verify) that comes in two complementary forms: task-agnostic (source-anchored, reusable across tasks) and task-oriented (task-anchored, built on demand). No skill enters the library without verification; surviving gaps are recorded, not hidden.
- Builds the **AREX-Skill Library**: 5,353 verified skills distilled from 1,000 widely used ML repositories, organized into 20 areas / 178 capability families with a generated router (plus 636 paper-derived skills from 153 papers and benchmark-specific graphs), where each skill is a three-layer artifact (SKILL.md knowledge interface / references/ knowledge substrate / scripts/ execution interface) with provenance and progressive disclosure.
- Evaluates under a **matched backbone (GPT-5.5), matched harness (Codex), and matched downstream budget**, with skill construction completed before execution — isolating the skills as the only runtime variable — and reports consistent gains on MLE-bench (+134.3%), PaperBench (+34.4%), FrontierCS (+9.2%), and PassNet (+14.0%), with gains growing on harder tasks.

## Methodology

**Framing.** A research task τ = (q, D, E, g) is solved by an agent A = (M_θ, H); the paper augments this with operational knowledge K made available as explicit operating context, so actions become a_t ~ π_θ(a | τ, h_t, H, K). K is realized as a set of Agent Skills K = {S_1..S_m}, each skill a three-layer package S = (SKILL.md, references/, scripts/): SKILL.md is the only layer read up front (entry point, applicability, routing), references/ holds deep material loaded on demand (API docs, worked examples, failure modes), scripts/ wraps executable procedures. Since one source holds more know-how than one skill should, skills are organized into skill graphs G = (S, L) whose links encode routing/dependency/composition relations, enabling progressive disclosure: the agent opens an entry point and follows only the links its problem calls for.

**Four-stage distillation** (ζ --scope--> Q --ground--> X --construct--> Ĝ --verify--> (G, R)): which capabilities to cover, what evidence supports them, how they become skills, and whether they hold.
- *Task-agnostic distillation* (anchor ζ = source): Source Understanding + Capability Identification → Knowledge Extraction (encapsulating evidence from the source itself) → Tool Encapsulation + Skill Packaging → Skill Verification. Applied to 1,000 repos (chosen by open-source visibility/stars; model implementations, training systems, data/eval tools) using GPT-5.5 + GPT-5.6-sol at xhigh reasoning effort, ~$40 per repository, with an evidence boundary covering docs, tests, configs, and live inspection (no vendored deps, caches, or local artifacts).
- *Task-oriented distillation* (anchor ζ = task): Task Decomposition + Capability Gap Analysis → Source Discovery (web search, excluding the benchmark's own competition webpage and competition-specific content to prevent leakage) → Skill Generation → verification via execution feedback from bounded diagnostic trials. For MLE-bench, one descriptive skill graph per competition, built within an exploration budget of ≤24 GPU-hours per task and frozen before a second, matched ≤24 GPU-hour running phase; final skills are deliberately *descriptive* (no runnable training/inference scripts) so the runtime agent cannot replay a fixed solution.
- *Paper-derived skills* (PaperBench): for each of the 20 target papers, up to 10 representative prior papers are selected from its related-work section and decomposed into 3–5 module-level skills each (636 skills from 153 papers); every module gets an assertion-backed isolated test plus a bounded recovery experiment that excludes the original implementation repository. The target paper itself and its released code are excluded as skill sources.

**Verification and taxonomy.** Before a repository graph is accepted, gates check metadata, link integrity, self-containment, provenance, routing metadata, and local-path leakage; usability checks run assertion-backed cases plus safe repo-native examples, tests, CLI checks, or smoke scripts "when available"; a SKILL_GAP triggers local repair and re-running the affected checks. The two-level taxonomy (areas/families) is induced by an LLM pipeline over 1,000 repo summaries in 100 batches of 10, with separate judge reviews, an aggregator, and a convergence gate requiring ≥2 evaluation rounds; assignment requires rationale + confidence + repository evidence (keyword-only or example-only matches rejected), and 700 repos legitimately appear in multiple families. Accepted assignments compile into a router: request → area → family → repository graph → only the skills/references/scripts needed now.

**Evaluation protocol.** The harness (OpenAI Codex) and backbone (GPT-5.5, xhigh) are fixed everywhere; the only controlled factor is whether the agent is equipped with DisCo-distilled skills. Benchmarks: MLE-bench full suite (75 competitions, Any-Medal, official held-out grader, mean±SEM over 3 runs), PaperBench (all 20 papers, official replication grader), FrontierCS Agent Track (all 188 tasks via Harbor, 5-hour budget, 2 CPUs / 4 GB RAM), PassNet (200 eval samples on NVIDIA A100-SXM4-40GB, AS Score = weighted geometric mean of rectified subgraph speedups at t ∈ [−10, 4]).

## Results & Highlights

- **MLE-bench (full 75 competitions, Any-Medal %):** GPT-5.5 Codex goes from 31.11±2.22 without skills to **72.89±1.18** with AREX-Skill — +41.78 points, a 134.3% relative gain, with no change to backbone or harness. The gain widens with difficulty: Low 42.42 → 86.36 (+43.94), Medium 51.58 → 69.30 (+17.72), High 13.33 → 62.22 (+48.89, a 366.8% relative / 4.67× improvement). This surpasses the strongest public leaderboard entry (Famous-Agent 2.0, Gemini-3-Pro-Preview, 64.44%) by **+8.45 points**, and the best public High-tier score by +15.55 points.
- **PaperBench (all 20 papers, replication score %):** 29.45% → **39.59%** (+10.14 points, +34.4% relative). Skills improve 18 of 20 tasks and degrade only 2. Largest gains: rice 7.94 → 48.51 (+40.57, 6.1×), sequential-neural 41.67 → 65.37 (+23.70), what-will-my-model-forget 9.35 → 30.45 (+21.10), frtl 1.50 → 17.17 (11.4×); the two regressions are sample-specific-masks (57.11 → 52.04, −5.07) and stay-on-topic (32.31 → 27.79, −4.52).
- **FrontierCS Agent Track (188 tasks, 5-hour budget):** Codex 70.63 → **77.14** (+6.51 points, +9.22%; paired bootstrap 95% CI [3.41, 9.83]), beating Claude Code (Claude Opus 4.8, 74.5), Claude Code (Qwen3.7 Max, 61.9), and Gemini CLI (Gemini 3.1 Pro, 60.2) from the public leaderboard. Skills fire on 180 of 188 tasks; 74 tasks improve (mean +22.23), 66 are unchanged; the 47 tasks scoring below 50 without skills rise from mean 19.43 to 45.99 (+26.56), with 30 crossing the 50-point threshold.
- **Token efficiency on FrontierCS:** Codex + AREX-Skill uses 4.47M tokens per task vs 14.72M (Claude Code / Opus 4.8) and 13.85M (Qwen3.7 Max) — 3.29× and 3.10× fewer — with 24.5–27.9% fewer tool calls and 33.8–75.1% fewer steps, Pareto-dominating both Claude Code configurations across score, tokens, steps, and tool calls. Per-task gains are essentially uncorrelated with extra usage (Spearman ρ = 0.006 for tokens, 0.014 for steps, 0.015 for tool calls).
- **PassNet (200 samples, graph-compiler pass generation):** AS Score 1.343 → **1.5313** (+0.1883, +14.0% relative), exceeding even TorchInductor's 1.419; G-Mean Speedup 1.5891 → 1.6688; Correctness 81.33% → 90.76% (+9.41 pts); failed samples 14 → 5 (a 64.3% reduction). One counter-metric: Fast_1 slips 28.48% → 26.72%.
- **Library scale (task-agnostic core):** 5,353 skills from 1,000 repository graphs, 20 areas, 178 capability families, 2,209 exact area-to-family assignments (700 repos in more than one family), built for ~$40 of model compute per repository; plus 636 paper-derived skills from 153 papers and a shared FrontierCS graph of 9 nodes / 42 directed links / 8 recovery modules.
- **Construction-stage sanity check (Appendix, Table 6):** on 50 sampled PassNet training tasks (Claude Code harness, DeepSeek v4 pro backbone), geometric mean rises 0.5852 (no skill) → 0.6840 (skill v1) → 0.6941 (skill v2), match failures drop 10/50 → 1/50, and average solve time halves from 40 to 22 minutes.

## Critical Assessment

- **The headline relative gain flatters the contribution.** "+134.3% on MLE-bench" is computed against the paper's *own* no-skill Codex baseline of 31.11% — a weak anchor. Against the strongest public leaderboard entry (Famous-Agent 2.0, 64.44%), the margin is +8.45 points: real and large, but a fraction of the headline number. The paper does state both figures, but the abstract leads with the relative one.
- **Task-oriented construction quietly moves problem-specific search off the clock.** For MLE-bench, each competition gets a skill graph built with execution feedback from diagnostic trials within a ≤24 GPU-hour exploration budget; across 75 tasks that is up to ~1,800 GPU-hours of benchmark-adjacent iteration whose cost is explicitly excluded from the runtime comparison. The paper is upfront that this is one-time and amortizable, and it blocks competition-specific content leakage and freezes skills before the matched run — but the "skills are the only variable" framing understates that a substantial part of the solution search happened at construction time, per task, on the very benchmark being scored.
- **No ablation of what actually carries the gains.** There is no experiment isolating the three-layer skill format (SKILL.md vs references/ vs scripts/), the graph routing vs a flat skill list, or the number/size of skills; nor a comparison against the obvious cheap baseline of stuffing repo READMEs/documentation into the same context budget. Given that the core claim is "distilled *verified* skills beat raw declarative knowledge," the missing raw-context control is the most conspicuous gap.
- **Single harness, single backbone downstream.** All four benchmark results use Codex + GPT-5.5. Cross-harness portability is asserted ("any compatible harness"), and the appendix does show PassNet *construction* running on Claude Code + DeepSeek v4 pro, but no main benchmark measures skill transfer across backbones or harnesses.
- **Human prior enters the FrontierCS pipeline.** The shared FrontierCS skill graph is grounded in two *human-authored* catalogs of algorithms and heuristic-search guidance, so that result is not purely machine-distilled knowledge.
- **Genuine honesty where it counts.** The paper reports 2 of 20 PaperBench regressions with a plausible retrieval-precision mechanism, the PassNet Fast_1 drop, and a detailed error analysis of an over-broad skill rule (the conv3d stride == kernel_size case where a valid vendor-op rewrite was blocked by a "defeasible prior" warning) — this transparency is above the norm.
- **Verification depth is uneven by construction.** Native checks (tests, CLI, smoke scripts) run only "when available," so verification strength varies across the 1,000 repos; MLE-bench results are mean±SEM over only 3 repeated runs, though the FrontierCS bootstrap CI [3.41, 9.83] is properly done.

## Strengths

- **Clean conceptual contribution:** the (M, H, K) decomposition cleanly separates *how the agent explores* (harness) from *what it knows* (K), and skills attach to a fixed agent with no new control loop — making attribution of the gains straightforward.
- **Consistent, multi-domain evidence:** gains on four benchmarks spanning ML engineering (MLE-bench), paper replication (PaperBench), open-ended CS problem solving (FrontierCS), and compiler pass generation (PassNet) — a breadth few agent papers match, with the same fixed-backbone protocol throughout.
- **Scale with provenance and verification:** 5,353 skills over 1,000 repos, each graph carrying provenance (source commit, package version, evidence paths), gated verification, and recorded rather than hidden gaps; the two-stage taxonomy + router makes the library actually navigable via progressive disclosure.
- **Gains grow with difficulty and correlate with failure recovery:** +48.89 points on MLE-bench High tier, +26.56 mean on sub-50 FrontierCS tasks — strong evidence the skills act where unguided exploration stalls, not as a uniform prompt boost.
- **Efficiency, not just accuracy:** Pareto-dominance on FrontierCS (higher score at 3.1–3.3× fewer tokens) counters the worry that skills just induce more tool churn; the near-zero Spearman correlation between usage and gain supports this.
- **Honest negative reporting:** 2/20 PaperBench regressions, the Fast_1 slip on PassNet, and a root-cause analysis of a skill-induced false ban, each with a mechanism and a proposed fix.

## Limitations

- **No cheap-baseline or component ablations:** raw docs/README-in-context, flat skill lists without graph routing, and per-layer contributions are all unmeasured.
- **Downstream evaluation limited to one harness (Codex) and one backbone (GPT-5.5);** claimed harness-agnostic portability of skills is untested on the main benchmarks.
- **Construction cost accounting is favorable by design:** task-oriented graphs consume up to 24 GPU-hours of benchmark-task exploration each (excluded from runtime comparisons), and the library's ~$40/repo cost is amortized only in aggregate; the break-even point for a user with few tasks is not analyzed.
- **Retrieval-precision failure mode is real:** skills can actively pull the agent away from a better idiosyncratic approach (sample-specific-masks −5.07, stay-on-topic −4.52 on PaperBench); the proposed confidence-gated fallback to unguided reasoning is future work.
- **FrontierCS graph depends on human-authored grounding sources**, weakening the "fully automatic distillation" story for that benchmark.
- **Skill maintenance/versioning is unaddressed:** repositories drift with every release and skills are version-pinned snapshots; no staleness detection or refresh procedure is described.
- **Verification is best-effort:** native executable checks exist only where repositories provide them, so a nontrivial share of the 5,353 skills is validated by LLM review alone.

## Relevance

与你的最高优先级方向「自进化智能体与自动化研究」高度契合：DisCo 直接面向自主科研智能体（MLE-bench / PaperBench / FrontierCS 全套评测），提出把 GitHub 仓库与论文自动蒸馏成经验证、可复用的技能层，作为模型与 harness 之外的第三组件——这正是 agent 运行时知识外置、技能库自建与自动工程经验沉淀的代表性路线。其对长时程自主智能体失效模式（试错烧预算、经验不复用、检索误伤）的分析也与你关心的 agent 可靠性问题相关。

## Questions for Further Exploration

- How much of the gain would a cheap baseline capture — e.g., retrieving raw README/docs/issues into the same Codex context budget — given no such control is reported?
- Do the skills transfer across backbones (open-weights models) and across harnesses other than Codex, as the "portable operating context" claim implies?
- Which layer carries the value: SKILL.md usage policy, references/ evidence, or scripts/ executables — and does graph routing beat a flat list of skills at equal token cost?
- Can the 2 PaperBench regressions be eliminated by confidence-gated fallback to unguided reasoning when retrieved skills are a poor match?
- Does the task-oriented construction budget (≤24 GPU-h per MLE-bench task) amortize across families of similar tasks, or is it per-task sunk cost in practice?
- How should version-drifting repositories trigger skill refresh, and can the verification gates catch silently outdated procedures?
