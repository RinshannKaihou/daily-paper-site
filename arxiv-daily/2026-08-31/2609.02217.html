SkillGLoW: Procedural-Family Skill Consolidation for Self-Improving Agents on Long-Horizon Task Streams ↗

Key metric
+17.2

mean hard-score gain over No-Skill across all 12 runs (3 models × 4 benchmarks), Wilcoxon p = 0.000488 — +18.0 once local regeneration is added.

Why this matters

Third answer for agent skill organization: commit memory only when real downstream execution confirms no regression — guarding long-horizon autonomy against library degradation and wrong commits.

Critical edge

Every main-table cell is one run at temperature 0.7 — with one task worth ~3.1 points on Terminal-Bench-Pro, several ±5.0 swings are one-to-two-task effects, and no variance is reported.

Methodology 01

A skill is a natural-language procedure injected into the agent context; the verifier score r ∈ [0,1] is the only trusted measure of effect. The global library holds one prior per procedural family — K tracks distinct procedures, not tasks.

  • Global–local split — local skills are regenerated fresh from each task's own execution feedback (trajectory-difference localization) and never enter the long-term library; global priors are de-instantiated skeletons frozen during solving, revised only offline.
  • Stage 1 · skill cards — each execution yields instruction, abstract signature, trajectory, verifier score, and a local skill retaining only hypotheses that actually advanced the task.
  • Stage 2 · consolidation — four weighted textual views feed consensus clustering (many link-runs → co-association matrix → re-cluster; K picked by Kneedle on the silhouette curve); each family compresses to applicability conditions + core procedure + common failure modes, with instance bindings filtered out.
  • Stage 3 · verifier-grounded commit gate — each round's candidate revision is scored on real downstream deployment (priors alone, no local skills); commit only if it reaches anchor − ε (ε = 0.02, anchor floored at the previous best measured value). One accept/reject decision per round.
  • Protocol — Terminal-Bench-Pro (32), SWE-bench Verified (20), ALFWorld (42), LiveMathematicianBench (53) × DeepSeek-V4-Pro, MiniMax-M3, GPT-5.4-mini; SkillOpt re-run from its authors' implementation with matched launch and shared scoring adapters.

  • Vs SkillOpt: leads 15 of 21 peak-peak cells; SkillOpt's 4 wins are all on ALFWorld — the one benchmark sharing a single action space, where the whole set is already the right granularity. Elsewhere: +8.3 TBP, +6.7 SWE, +6.9 LMB.
  • Organization ablations: Base-only (merged document) averages +2.0 and flips sign across benchmarks; a flat pool with retrieval (AWM) scores −1.5 vs family consolidation's +11.2; Local-only +1.0 — the global layer carries the cross-task value.
  • The gate earns its cost: 26 admission decisions, 7 rejections — 4 of which consolidation-time scoring alone would have admitted. One candidate scored 0.283 on the soft signal but 0.151 deployed. Final library: +14.7 vs +9.6 for unconditional admission.
  • Structure, not memorization: against ALFWorld's own labels, 13 of 15 priors sit wholly inside one task class — zero classes uncovered, none invented. A 989-word memorized location table compresses to a 440-word four-step rule.
  • Transfer: the unmodified library lifts unseen ALFWorld tasks from 73.9% to 83.9% mean success (best model 71.7→88.3) and 30 unseen SWE-bench instances from 40.9% to 45.6% — every instance a different repository.
  • Compactness: the committed library is 3.6× smaller than the per-task skill pool by artifact count.

Strengths 03

  • The central claim is falsifiable and directly tested: if the procedural family is the right unit, organization ablations should underperform on heterogeneous streams — exactly the observed pattern (Base-only wins only on ALFWorld).
  • Verifier-grounded admission is measured in deployment, not simulation — the 0.283-vs-0.151 case concretely shows text-space scores mislead, and the gate analysis quantifies what a cheaper criterion would miss.
  • Structural validation against an external, author-independent taxonomy (ALFWorld labels) is a rare, convincing check that clusters mean "procedure."
  • Complete architecture with deterministic tie-breaking (anchor flooring, ε noise band); recall runs on a single 16 GB GPU — no hidden infrastructure.
  • Transfer tested on held-out instances rather than pooled cross-domain, cleanly separating procedure transfer from domain pooling.

Limitations 04

  • No variance on the main results: single-run cells, 20–53 task sets, and 1-task ≈ 3–5-point granularity make several per-benchmark deltas fragile; multi-seed tables would materially strengthen the claims.
  • Family-granularity sensitivity is uncontrolled — 5 vs 10 families on identical tasks across models, and no ablation of the consensus-clustering hyperparameters' downstream effect.
  • All four benchmarks are in-distribution procedure-sharing regimes by design; genuine domain change and cross-model library inheritance are explicitly open.
  • The verifier is trusted as the sole commit signal; multiplicative SWE scoring is the only stress test where clean all-or-nothing verification is absent.
  • Local skills are never persisted, so within-family instance quirks are re-learned from scratch on every recurrence — that re-learning cost is unmeasured, as is the consolidation compute cost.

Questions for Further Exploration 05

  1. How does the commit gate behave when the verifier itself is noisy or adversarially gamed (reward hacking on soft partial credit) — does ε = 0.02 still separate real regression from measurement noise?
  2. How sensitive is the final score to consensus-clustering hyperparameters (view weights, linkage, Kneedle knee) — is the five-vs-ten family discrepancy between models fixable or fundamental?
  3. Can a prior committed by one model family be executed by another (cross-model inheritance), and does the de-instantiated plain-text format survive the transfer?
  4. Does the procedural-family unit extend to research-automation loops (hypothesis → experiment → analysis), where "families" are experiment types and verifiers are far weaker?
  5. Would persisting failed-repair guards across rounds eventually re-inflate the library — what stops the 3.6× compactness from degrading over much longer streams?
