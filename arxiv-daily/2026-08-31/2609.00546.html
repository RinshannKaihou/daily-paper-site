Runtime-Independent Persistent Agents: Preserving Identity, Memory, and Code Across Models, Harnesses, and Servers

Zhenyu Zhao · Roy Zhao•Independent Researcher / Univ. of Washington•2026-08-31

llm agents agent persistence runtime migration systems reliability

Key metric

11/11

first-attempt passes in the supervised frozen Codex–Muse–Codex study under a 26-condition round-trip verifier (1 qualification + 5 migrations + 5 same-runtime controls).

Why this matters

Long-lived agents currently die with their runtime; RIPA offers open infrastructure for identity, memory, and authority that outlives any model or vendor.

⚠ Critical edge

Evidence is single-instance, author-curated and supervised on toy arithmetic — no overhead/cost numbers for the six-phase protocol, and authority fencing is local only.

Methodology— boundary, protocol, implementation

01

Formal boundary. A persistent substrate P=(I, M, B) — installed identity, private memory, versioned executable body — is separated from replaceable bindings E=(reasoner, harness, host) and interaction surfaces S. Continuity is defined as lineage continuity, not bitwise immutability; a seven-operation lifecycle taxonomy (restart / resume / migrate / evolve / identity-update / replicate / descend-fork) replaces the collapsed “resume vs fork” vocabulary.

02

Six invariants + migration protocol. I1 identity lineage preserved; I2 memory never silently reset; I3 body at same commit or authorized evolution; I4 at most one cooperating authority; I5 capability deltas explicit; I6 labels never redefine self. Migration runs quiesce+fence → checkpoint → validate → bind → rehydrate → verify+resume, with one governed promotion point and the source fenced throughout.

03

Enoch + tiered evaluation. The open-source body loads body.yaml and self.json separately, isolates five provider kinds behind contracts (chat / runtime / VCS / review / service), and enforces authority via idempotency keys, fencing epochs, and per-root locks; the Muse adapter bridges runtimes through an async file mailbox with per-attempt nonces. Evidence comes from frozen snapshots (B0/B1/B2), an operational migration, a cross-host resume, supervised round trips, and one planned SIGKILL fault.

  • Fencing held everywhere: all 14 migrating source and Muse return-export roots rejected post-export execution without advancing the authority epoch; authority generations advanced 8→14 across export, activation, and service starts.
  • Mechanism test volume: B1 snapshots passed 963 tests (857 core + 106 provider/library) with no failures or skips; B2 added 23 adapter tests; B0 ran 833 core + 92 provider tests.
  • Verifiers are external and offline-checkable: a round-trip verifier outside the target agent checks 26 conditions per migration; an author-run offline verifier re-checks hashes and arithmetic over the public B2 archive without model calls.
  • Honest scope: there is no accuracy-style baseline — the claim is hash-level state preservation, explicitly not behavioral equivalence, arbitrary-task portability, or unattended reliability.

Strengths

  • Crisp, reusable separations: “copying memory does not copy authority”; a transcript is raw evidence, not automatically memory; session continuity ≠ agent continuity.
  • Deterministic, checkable evidence: 26-condition verifier, 18 provenance/no-repair checks per trip, 14 demonstrated fences, exact arithmetic witnesses — a mechanical standard vs vibe-checked agent demos.
  • Table 4 coverage map: every invariant names both its implemented check and the boundary of what it does not establish — a model of scoped claims.
  • Real end-to-end bindings (Codex, Claude Code, Slack, Telegram, launchd/systemd, Git/GitHub) plus a public hash-pinned archive and offline verifier enabling partial third-party checking.

Limitations

  • Single evolving Enoch lineage; no ablations — what breaks without fencing epochs or generation floors is never shown.
  • Toy synthetic tasks: tool-free, driver-orchestrated arithmetic; arbitrary repository workflows, live inference processes, and provider-native sessions are undemonstrated.
  • All live studies single-instance, supervised, author-curated; private-state evidence withheld; no reliability statistics, no cost/latency/operator-burden measurements, no alternative-approach baseline.
  • Authority is local only: a detached copy with usable credentials sits outside the fence; recovery is not crash-atomic against SIGKILL.
  • Behavioral fidelity deferred to the companion PAI-Bench work — an authorized successor may behave differently, with no data on how much.

Questions for further exploration

  • What happens on a crash during an external side effect — after an idempotency-keyed effect is published but before reconciliation? Fault F only cuts before any reply.
  • Can PAI-Bench-style behavioral fidelity be composed with RIPA’s mechanical continuity — and can an unauthorized copy that answers identity questions correctly be caught?
  • What would a concurrent multi-embodiment authority policy look like — coordinated replicas with reconciliation instead of sole authority?
  • Does the six-phase protocol extend to live inference sessions and provider-native conversation state, and what is its overhead on tool-using, long-horizon workloads?
  • How does the machinery behave under an unauthorized detached copy replaying the exported bundle — provider-side rejection remains an open systems problem.
