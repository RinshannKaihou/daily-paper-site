Key Metric

31.1 → 72.9%

MLE-bench Any-Medal over all 75 competitions, +41.78 pts (+134.3%) with backbone (GPT-5.5 Codex) and harness frozen — beating the strongest public leaderboard entry (Famous-Agent 2.0, 64.44%) by +8.45.

Why This Matters

Agent know-how can live outside the model: auto-distill repos and papers into a verified, reusable skill layer instead of re-learning every task by expensive trial and error.

Critical Edge

The headline +134.3% is anchored to the authors’ own weak no-skill baseline, and per-task skill graphs spend up to 24 GPU-hours of benchmark-adjacent search off the clock.

Methodology

5,353verified skills
1,000repos distilled
20 × 178areas × families
~$40compute per repo
  • Framing: research agent Ares = (Mθ, H, K). The harness governs how the agent explores; neither model nor harness supplies the domain know-how — package APIs, config pitfalls, recovery procedures — that turns a known method into a working run. K is made explicit as Agent Skills.
  • Skill format: three layers — SKILL.md (entry point, read up front), references/ (deep material on demand), scripts/ (executable procedures) — organized into skill graphs with routing/dependency links for progressive disclosure.
  • Four-stage distillation: scope → ground → construct → verify. Task-agnostic mode (source-anchored, reusable) ran over 1,000 popular ML repos on GPT-5.5/5.6-sol; task-oriented mode (task-anchored, on demand) builds one descriptive graph per MLE-bench competition within ≤24 GPU-hours, frozen before the matched run — deliberately no runnable scripts, so the runtime agent cannot replay a fixed solution.
  • Verification gates: metadata, link integrity, self-containment, provenance, routing, local-path leakage; assertion-backed usability checks where repos provide them. Gaps become recorded SKILL_GAPs, never hidden.
  • Protocol: matched backbone, harness, and downstream budget everywhere; skill construction completed before execution — skills are the only runtime variable. Leakage controls exclude benchmark competition pages and target papers’ own code.

  • Token efficiency: on FrontierCS, Codex + skills uses 4.47M tokens/task vs 14.72M (Claude Code / Opus 4.8) and 13.85M (Qwen3.7 Max) — 3.1–3.3× fewer with a higher score: Pareto-dominance across score, tokens, steps, and tool calls. Per-task gains are essentially uncorrelated with extra usage (Spearman ρ ≈ 0.006–0.015).
  • Skills act where exploration stalls: 47 FrontierCS tasks scoring under 50 without skills rise from mean 19.43 to 45.99 (+26.56); 30 cross the 50-point threshold.
  • PaperBench detail: skills improve 18 of 20 papers — rice 7.94 → 48.51 (6.1×), frtl 1.50 → 17.17 (11.4×) — with two regressions (sample-specific-masks −5.07, stay-on-topic −4.52) attributed to retrieval precision.
  • PassNet: correctness 81.33% → 90.76%, failed samples 14 → 5 (−64.3%); the AS score even exceeds TorchInductor’s 1.419. One counter-metric: Fast_1 slips 28.48% → 26.72%.

Strengths

  • Clean conceptual contribution: the (M, H, K) split separates how the agent explores from what it knows, and skills attach to a fixed agent with no new control loop — attribution is straightforward.
  • Consistent multi-domain evidence across four benchmarks (ML engineering, paper replication, open-ended CS, compiler passes) under one matched protocol — breadth few agent papers match.
  • Scale with provenance: every graph carries source commit, package version, evidence paths; gated verification; gaps recorded rather than hidden; taxonomy + router make the library navigable.
  • Gains grow with difficulty and track failure recovery — evidence the skills act where unguided exploration stalls, not as a uniform prompt boost.
  • Honest negative reporting: 2/20 regressions, the Fast_1 slip, and a root-caused skill-induced false ban, each with a mechanism and proposed fix.

Limitations

  • No cheap-baseline or component ablations: raw README/docs-in-context, flat skill lists, and per-layer contributions are all unmeasured — the most conspicuous gap given the core claim.
  • Downstream evaluation uses one harness (Codex) and one backbone (GPT-5.5); claimed portability is untested on the main benchmarks.
  • Construction accounting is favorable by design: up to 24 GPU-hours of per-task exploration excluded from runtime comparisons; break-even for users with few tasks is unanalyzed.
  • Retrieval-precision failure mode is real — skills can pull the agent off a better idiosyncratic approach; the confidence-gated fallback is future work.
  • FrontierCS grounding includes human-authored catalogs; skill maintenance/versioning is unaddressed; verification is best-effort where repos lack native tests.

Questions for Further Exploration

  • How much of the gain would a cheap baseline capture — retrieving raw README/docs/issues into the same Codex context budget?
  • Do the skills transfer across backbones (open-weights models) and across harnesses other than Codex, as the “portable operating context” claim implies?
  • Which layer carries the value — SKILL.md policy, references/ evidence, or scripts/ executables — and does graph routing beat a flat skill list at equal token cost?
  • Can the two PaperBench regressions be eliminated by confidence-gated fallback to unguided reasoning when retrieved skills are a poor match?
  • Does the ≤24 GPU-hour task-oriented construction budget amortize across families of similar tasks, or is it per-task sunk cost in practice?
  • How should version-drifting repositories trigger skill refresh, and can the verification gates catch silently outdated procedures?
