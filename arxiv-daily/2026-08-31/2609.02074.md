> **一句话总结：** 厦门大学+阿里巴巴团队的 CHIME 直击自进化智能体记忆的"信用分配失真"痛点——现有方法把最终 outcome(成败)直接当反馈写入记忆库,使计划质量与执行错误、环境因素混为一谈,错误经验随复用不断累积;CHIME 提出 attribute-before-memorize 原则,将记忆拆成规划库+执行库,由 Credit Attribution Gate 结构化自反思把每次结果归因到 planning/execution/both/none 并只更新对应库(置信度加权价值更新、价值重排序、合并/插入/剪枝、误导记忆惩罚);在 τ²-bench、VitaBench、BrowseComp-ZH、BFCL-v4 四个长程基准 × Qwen3.5-Flash/DeepSeek-V4-Flash 两骨干上,冻结记忆的评测集平均分超出最强基线 +2.96/+3.68 分(对最近基线 A-MapReduce +5.37/+3.68),且在 τ²-bench 上仅保留 129 条记忆(A-MapReduce 3,585 条),跨骨干迁移记忆比 A-MapReduce 高 2.25–4.68 分。

> **TL;DR:** CHIME (Xiamen University + Alibaba) fixes a credit-assignment flaw in self-evolving agent memory: outcome-based methods (e.g., A-MapReduce) write every final success/failure into a shared memory bank, conflating plan quality with execution errors and environmental factors, so biased experience accumulates. CHIME splits memory into a planning bank and an execution bank; after each episode, an LLM Credit Attribution Gate (structured self-reflection) attributes the outcome to planning, execution, both, or none, and only the attributed bank is updated — with confidence-weighted value feedback, similarity+value reranked retrieval, merge/insert/discard content evolution, and pruning of low-value memories (the "attribute-before-memorize" principle). On four long-horizon benchmarks (τ²-bench, VitaBench, BrowseComp-ZH, BFCL-v4) with Qwen3.5-Flash and DeepSeek-V4-Flash backbones, CHIME raises the frozen-memory eval-split average over the strongest baseline by +2.96 (34.87 vs 31.91, WebAnchor) and +3.68 points (39.01 vs 33.13), and over the closest baseline A-MapReduce by +5.37/+3.68; on τ²-bench it retains only 129 memories vs 3,585 for A-MapReduce at higher accuracy, and its cross-backbone transferred memory beats A-MapReduce's by 2.25–4.68 points in all four transfer settings.

## 核心贡献

- **问题诊断(信用分配失真)：** 指出自进化记忆方法的共同缺陷——以最终 outcome s_t 作为唯一监督信号,但 outcome 同时由计划质量、执行过程与环境因素决定;"一次鲁棒计划下的执行器故障"与"错误计划侥幸成功"都会被同等写入记忆,错误归因经检索复用在系统内累积成系统性规划失误(lost-in-the-middle 类失败)。
- **attribute-before-memorize 框架：** CHIME 由三个组件构成:(1) 分层记忆库——规划库(子任务分解、依赖建模、约束引入等策略性经验)与执行库(工具选择/调用等操作性经验)分离,每条记忆为 (描述 c_i, 经验 e_i, 价值 v_i ∈ [-1,1], 复用次数 n_i);(2) Credit Attribution Gate——冻结策略的结构化自反思,输出归因标签 a_t ∈ {planning, execution, both, none}、置信度 γ_t ∈ [0,1]、误导记忆集合 M_t^mis 与各阶段新经验 e_t^new;(3) Credit-Aware Memory Evolution——只在被归因的库内更新。
- **两步记忆演化：** 价值演化按置信度加权反馈 δ 更新 v_i(成功且被归因则 +γ_t,被识别为误导则 −γ_t,否则不变),在线平均 v_i ← clip((n_i·v_i+δ)/(n_i+1));内容演化按 γ_t ≥ θ_conf 与相似度阈值决定 merge / insert / discard,新插入记忆价值中性、复用数为 0,其价值必须由未来复用验证而非继承 gate 判断;复用充分仍低价值的记忆被剪枝。
- **两段式检索：** 每阶段独立检索,先按相似度取 Top-N,再按 |1+clip(v̂_i,−β̂,β̂)| 加权重排取 Top-K;κ 收缩低复用记忆的价值估计使其退回纯相似度排序,β 限制价值影响幅度保证相似度主导。
- **六维实证分析：** 4 基准 × 2 骨干 × 5 基线的系统实验,外加记忆质量(外部 GLM-5.2 评审)、进化效率、价值-效用相关性、归因可靠性、更强归因模型增益、跨骨干迁移六个 RQ,支撑"记忆演化取决于经验是否被归因到能提供有效指导的决策阶段"这一结论。

## Key Contributions

- Identifies and formalizes an inherent **credit-assignment flaw** in outcome-based self-evolving memory: final outcomes conflate plan quality with execution errors and environmental factors, so a robust plan ruined by a faulty executor gets penalized and a flawed plan that luckily succeeds gets reinforced — and such misattributed memories accumulate systemically through retrieval reuse.
- Proposes **CHIME**, the first self-evolving memory framework with an explicit **attribute-before-memorize** principle: a hierarchical memory bank (separate planning and execution banks), a Credit Attribution Gate that assigns each outcome to planning / execution / both / none with confidence, and Credit-Aware Memory Evolution that only writes into the attributed bank (confidence-weighted value updates, merge/insert/discard content evolution, pruning, misleading-memory penalties).
- Designs **two-stage retrieval** (similarity Top-N then value-reranked Top-K) where learned value scores modulate but never dominate semantic similarity (κ shrinkage for rarely reused memories, β-bounded value effect).
- Delivers a **six-RQ empirical analysis** — memory quality (external GLM-5.2 judge), evolution efficiency (accuracy vs bank size), value-utility correlation, gate reliability (stability & rescue rate), credit-model scaling (stronger gate model), and cross-backbone transfer — that goes well beyond the usual headline table.

## Methodology

**Task formulation.** A frozen-policy agent solves a sequential stream of tasks; adaptation is carried entirely by an external memory M_t. Each episode: build a planning query q_plan from task x_t, retrieve stage-specific memories, generate plan p_t; build an execution query q_exec from (x_t, p_t), retrieve execution memories, execute to trajectory τ_t; environment returns binary outcome s_t. The episode closes with credit attribution and memory transition M_t → M_{t+1}. The eval split runs with the bank frozen (no updates), measuring pure transfer of accumulated memory to unseen tasks.

**Hierarchical Memory Bank.** M_t = (M_t^plan, M_t^exec). Each memory item m_i = (c_i, e_i, v_i, n_i): a task-description key c_i (used for retrieval and merging), distilled experience e_i, a value score v_i ∈ [-1, 1] maintained from reuse feedback, and reuse count n_i.

**Credit Attribution Gate.** A structured self-reflection of the frozen policy prompted to review the task, plan, trajectory, outcome, and retrieved memories, and assess plan sufficiency, execution correctness, and external factors, producing a diagnosis g_t = (a_t, {m_i^mis}, e_t^new, γ_t). Labels: planning (inadequate plan), execution (incorrect execution despite sufficient plan), both, none (external causes / insufficient evidence / no reusable experience); in successful episodes the gate instead credits the stage responsible. {m_i^mis} lists retrieved memories judged misleading.

**Credit-Aware Memory Evolution.** (1) *Value evolution*: the attribution label L(a_t) determines which stages update ({plan}, {exec}, {plan,exec}, or ∅); feedback δ_{i,t} = −γ_t if m_i ∈ M_t^mis, +γ_t if s_t = 1 and i ∈ L(a_t), else 0; online update v_i ← clip((n_i·v_i + δ_{i,t})/(n_i+1), −1, 1). Memories reused ≥ n_min times yet with v_i < θ_prune are removed. (2) *Content evolution*: for each attributed stage, new experience is merged into the most similar memory (sim > θ_merge), inserted as a new item with neutral value (0) and zero reuse count if accepted but dissimilar, or discarded; acceptance requires γ_t ≥ θ_conf and compact actionable content. New memories must earn value through future reuse rather than inheriting the gate's confidence.

**Retrieval.** Per stage: Top-N by similarity sim(q_ℓ, c_i); candidate values shrunk by v_i/(n_i+κ) so rarely reused memories fall back to similarity-only ranking; final Top-K re-ranked by similarity scaled with a β-clipped value multiplier so similarity stays dominant.

**Experimental setup.** Four long-horizon benchmarks: τ²-bench (multi-turn customer service), VitaBench (multi-turn life-service with shifting intents and large tool spaces), BrowseComp-ZH (long-horizon info-seeking), BFCL-v4 (live + agentic function calling). Backbones: Qwen3.5-Flash (35B total / 3B active) and DeepSeek-V4-Flash (284B total / 13B active); the same backbone serves planner, executor, and gate. Baselines ordered by proximity: No-Plan, WebAnchor (test-time plan search), TodoEvolve (meta-planner training, no experience), A-MapReduce (outcome-based memory, closest). Streams split 7:3 train/eval, Avg@3 over three random orderings; domains truncated to the smallest domain size for balance. Key hyperparameters: (N, K) = (20, 3), θ_conf = 0.5, θ_merge = 0.88, n_min = 3, θ_prune = −0.1; temperature 0.0 throughout (except WebAnchor planning at 0.6).

## Results & Highlights

- **Memory transfer (eval split, frozen bank):** CHIME achieves the best average across the four benchmarks on both backbones — 34.87 vs 31.91 for WebAnchor (+2.96 pts) on Qwen3.5-Flash, and 39.01 vs 33.13 for WebAnchor (+3.68 pts) on DeepSeek-V4-Flash. Against the closest baseline A-MapReduce the margins are larger: 34.87 vs 29.50 (+5.37) on Qwen3.5-Flash and 39.01 vs 35.33 (+3.68) on DeepSeek-V4-Flash.
- **Memory accumulation (train split):** CHIME averages 35.02 (Qwen3.5-Flash, +3.38 over WebAnchor's 31.64) and 38.00 (DeepSeek-V4-Flash, +0.90 over A-MapReduce's 37.10). Per-benchmark, gains are largest on VitaBench (16.19 vs 8.89 No-Plan / 6.67 A-MapReduce eval on Qwen3.5-Flash) — but CHIME *loses* BFCL-v4 to A-MapReduce on DeepSeek-V4-Flash (train 65.89 vs 69.18; eval 67.15 vs 69.98).
- **Evolution efficiency (τ²-bench train stream):** at full accumulation CHIME keeps only **129 memories vs 3,585 for A-MapReduce** while reaching the highest accuracy; the outcome-based counterpart's accuracy peaks at the 75% checkpoint and declines by 100%, as unattributed misleading memories flood the bank and distort retrieval.
- **Memory quality (GLM-5.2 judge, Qwen3.5-Flash train banks):** CHIME memories score 81.20% correctness vs 36.08% for A-MapReduce, with 93.60% non-redundancy and 90.13% generality; 81.04% pass all three criteria. Removing the Attribution Gate collapses this to 37.09% correctness and 21.38% pass-all.
- **Value scores track downstream utility (τ²-bench):** accuracy rises monotonically with memory value from 21.7% → 50.8% for planning memories and 23.7% → 35.4% for execution memories; the low→high-value planning gain (29.1 pts) is ~2.5× the execution gain (11.7 pts) — high-quality planning memories matter more on long-horizon tasks.
- **Gate reliability:** attribution labels are stable across repeated samples in 87.8–97.9% of cases (execution on VitaBench: 97.9%), and rerunning failed episodes with only the generated memory rescues 56.3–67.6% of attributed failures.
- **Credit-model scaling:** swapping the self-reflection gate for Qwen3.7-Flash (single run) lifts eval accuracy by +3.12 on τ²-bench (23.80 → 26.92), +2.50 on VitaBench (12.50 → 15.00), +2.25 on BFCL-v4 (72.45 → 74.70) — better attribution directly buys more effective experience.
- **Cross-backbone transfer:** CHIME's transferred memory beats A-MapReduce's in all four source→target settings by 2.25–4.68 pts (e.g., DeepSeek-V4-Flash → Qwen3.5-Flash on τ²-bench: 26.40 vs 21.72, and vs 24.45 with no memory at all — A-MapReduce's transfer actually *hurts* by 2.73 pts), and approaches or matches the self-accumulated upper bound (26.40 vs 25.92 on the Qwen target).
- **Ablations (Qwen3.5-Flash eval avg):** removing plan memory −3.26, execution memory −4.81, both −3.15, collapsing to one shared bank −3.60; reverting to outcome feedback (w/o Attribution Gate) −2.44; disabling credit rerank −2.04; disabling memory evolution −3.04.

## Critical Assessment

- **"Consistently outperforms" is an average-level claim, not a per-benchmark one.** On BFCL-v4 with DeepSeek-V4-Flash, A-MapReduce beats CHIME on both train (69.18 vs 65.89) and eval (69.98 vs 67.15); and on VitaBench-train with Qwen3.5-Flash, the *w/o Attribution Gate* ablation (17.02) outperforms full CHIME (16.19) — the paper honestly bolds both, but these are counterexamples the headline framing glosses over. CHIME's advantage concentrates on the benchmarks with weaker No-Plan floors (τ²-bench, VitaBench); on BFCL-v4 the margin over No-Plan (63.75 → 65.89 on DeepSeek) is thin.
- **An unexplained ablation anomaly:** w/o All Memory (31.74 avg) scores *higher* than w/o Execution Memory (30.06). Removing everything beating the removal of one bank suggests cross-bank interference or high run-to-run variance, yet no standard deviations are reported anywhere (Avg@3 only), and RQ5 uses a single run.
- **LLM-judged quality metrics are unvalidated.** RQ1's correctness/non-redundancy/generality come from GLM-5.2 with no human agreement check; since GLM-5.2 is external to the memory loop this mitigates self-preference, but a ~45-point correctness gap (81.20 vs 36.08) measured by one unevaluated judge is weaker evidence than it looks.
- **Many tuned thresholds, no sensitivity analysis in the main text:** θ_conf = 0.5, θ_merge = 0.88, n_min = 3, θ_prune = −0.1, (N, K) = (20, 3), λ = 3.0, α = 1.0, β̂ = 0.2. The gate's acceptance rule (γ_t ≥ 0.5 from a model grading its own plan) plausibly interacts with backbone calibration; the four-way label set is also coarse for cascaded failures where an early execution error causes a later planning mistake.
- **Backbone generality is narrow:** two "Flash"-tier models only, with the same model in all roles; the stronger-gate experiment (RQ5) is the right probe but covers just three benchmarks and one run. The gate's self-reflection dependence echoes the known weakness of weak models judging their own plans.
- **Evaluation protocol choices shrink the data:** multi-domain benchmarks are truncated to the smallest domain size to balance contributions, reducing effective eval sets; combined with the missing variance reporting, some ±1-pt margins (e.g., BFCL-v4 train 73.90 vs 73.84 on Qwen) are within plausible noise.
- **Novelty is solid but incremental:** the ingredients (LLM self-reflection for diagnosis, episodic memory banks, value-scored retrieval) all exist; the contribution is the stage-level attribution rule deciding *where* experience is written and *which* memories get credit. That is a genuine and well-motivated mechanism, but it is a refinement of A-MapReduce rather than a new paradigm, and the credit-gate prompt (in the appendix) is the load-bearing artifact whose robustness is untested.

## Strengths

- A crisp, correct diagnosis of a real failure mode (outcome-plan conflation) that applies to the whole outcome-based self-evolving memory family, with a minimal and principled fix: attribute first, memorize second, and never write into the wrong stage's bank.
- The efficiency result is striking and well-instrumented: 129 vs 3,585 memories at higher accuracy, with the accuracy-vs-bank-size trajectory showing the baseline's decline after 75% accumulation — direct visual evidence for the claimed mechanism.
- The value-utility analysis (monotonic accuracy across value terciles, 21.7→50.8 for planning vs 23.7→35.4 for execution) validates that the learned value scores mean something, rather than being an unused knob.
- Six-RQ analysis including gate reliability (stability + rescue rate) and credit-model scaling is unusually thorough for this paper class; cross-backbone transfer where transferred memory *beats* self-accumulated memory on the Qwen target (26.40 vs 25.92) is a genuinely interesting finding.
- Honest reporting conventions: baseline wins are bolded in tables, and the protocol (7:3 stream split, frozen-bank eval, Avg@3, same runtimes/tools/verifiers for all methods) is clean and comparable.

## Limitations

- Only two Flash-tier backbones, each serving all roles; no test with a stronger or heterogeneous planner/executor split, so the value-separation claim ("planning memories ~2.5× more useful") is not verified across model scales.
- No variance reporting; single-run RQ5; LLM-judge quality metrics unvalidated against human labels; benchmark domains truncated to the smallest size, shrinking eval sets.
- Four-way attribution plus a confidence scalar may be too coarse for entangled/cascaded failures; the gate depends on the backbone's self-reflection competence, and CHIME underperforms A-MapReduce exactly on BFCL-v4 with the DeepSeek backbone, suggesting the gate adds noise when the base model's introspection is weak.
- Hyperparameter sensitivity (nine thresholds) unreported in the main text; token/cost overhead of the extra attribution call per episode is never quantified.
- Code not yet available at publication time; reproduction currently requires re-implementing the gate prompt and evolution rules from the appendix.

## Questions for Further Exploration

- How sensitive are the results to θ_conf, θ_merge, n_min, θ_prune, and β̂ — and does the gate's confidence γ_t calibrate consistently across backbones, given that acceptance requires γ_t ≥ 0.5 from a model grading its own plan?
- Why does w/o All Memory (31.74) outperform w/o Execution Memory (30.06) — is there cross-bank interference, or is this within unreported run variance?
- Can the four-way label set handle cascaded failures (an early execution error that later manifests as a planning mistake), and would a per-step credit decomposition outperform the single episode-level attribution?
- What is the wall-clock and token overhead of the attribution self-reflection call per episode relative to A-MapReduce, and does the efficiency gain (129 vs 3,585 memories) survive when the baseline is given the same reflection budget?
- The value-utility gap (planning memories worth ~2.5× execution ones) — does it hold at larger backbone scale, or is it an artifact of Flash-tier planners needing more strategic guidance?
- Can attribute-before-memorize transfer to self-evolving scientific-research loops, where hypothesis quality and experiment execution conflate in exactly the same way as planning and execution here?
