Why This Matters

Gives long-context and KV-cache researchers a depth-axis compression strategy orthogonal to token pruning — open-sourced and heavily ablated, but not a free accuracy win.

Critical Edge

The paper's own j=0 ablation — full recompute over the same retrieved chunks, zero depth-reuse — scores 41.59 on LoCoMo, beating the flagship distilled CoMem's 38.27, showing depth-caching itself carries an accuracy cost that self-distillation only partially repairs.

Methodology

CoMem splits a frozen decoder along depth, not tokens. WRITE: each 512-token chunk is run through only layers 0→j (chunk-local RoPE restarting at 0), and the resulting residual tensor hj is cached — about 1/18th the bytes of a full bf16 KV cache per token. SELECT: iterative BM25 (top-12, hop width 4, up to 3 expansion rounds) retrieves a bounded, fixed-size set of relevant chunk tensors per query. READ: a BOS sink, the retrieved chunk tensors, and a fresh query chunk are packed together (~6.7k tokens), and only the upper layers j→L are run over this pack with full cross-chunk causal attention. Because pack size doesn't grow with stored context, read-time compute and memory decouple from context length. A rank-32 LoRA (58.2M params, 0.71% of backbone), trained only on PG-19 with no task supervision, then self-distills a j=12 student to match a frozen j=0 teacher's output distribution — repairing most of the fidelity lost to depth truncation.

Self-critique buried in the ablations (Table 8): a j=0 control — full recompute over the same retrieved pack, i.e. retrieval alone, zero depth-reuse — reaches 41.59 on LoCoMo, above the flagship distilled CoMem (38.27), while the untrained j=12 configuration drops to 24.52. Depth-caching costs real accuracy; distillation only partially recovers it.

Where CoMem loses: BABILong macro (50.43 vs. KV-Direct's 63.00) and BABILong qa2 specifically (27.0) stay weak; LongBench is matched, not beaten (12.15 vs. 12.17).
LoCoMo robustness checks: +4.81-pt gap over KV-Direct on 1,540 paired items, 95% bootstrap CI [2.34, 7.27]; 8/10 conversations favor CoMem under cluster bootstrap; an independent DeepSeek-V3 audit (κ=0.626) preserves the ordering.

Strengths

  • Clean, falsifiable mechanistic motivation (layer-wise probes + causal truncation) converted into a working system, not left as an observation.
  • Unusually thorough ablations: split-depth sweeps, retrieval-selector comparison (oracle/BM25/recency/reader-attention), chunk-interaction ablation, and cross-scale (0.6B–32B) / cross-architecture (two sparse MoE backbones) checks.
  • Statistical care on LoCoMo: item-level bootstrap CIs, a conversation-cluster bootstrap for the small-N (10 conversations) structure, and an independent DeepSeek-V3 judge audit.
  • Self-distillation needs no benchmark-specific data (plain PG-19 only), supporting the claim that the depth split is a general interface property, not task overfitting.
  • Honest, specific limitations section (BABILong qa2 weakness, unextended baselines, English-only, lexical-retrieval-only) rather than a generic disclaimer.

Limitations

  • Not an accuracy ceiling: full context remains stronger "whenever it fits" — BABILong qa2 (27.0) stays weak; LongBench is matched, not improved.
  • KV-Direct baseline runs without YaRN extension beyond Qwen3-8B's native 40,960-token window, so 64k/128k comparisons are against an "unextended stress reference," not a length-extended upper bound.
  • Retrieval is lexical only (BM25); dense/learned retrievers, dynamic index updates, and continually changing memory streams are out of scope.
  • Full cross-chunk attention (needed for reported accuracy) adds read compute versus block-diagonal reuse; retrieval latency on natural multi-hop workloads is unmeasured.
  • Evaluation is English-only and retrieval-style QA-focused; long-form generation, code, multilingual, and multimodal memory are untested.
  • Depth-caching itself has a measurable, only partially-repaired accuracy cost relative to full recompute over the same retrieved pack (Table 8) — the "efficiency-for-free" framing needs qualification.

Questions for Further Exploration

  1. How would CoMem compare against a properly YaRN-extended full-context Qwen3-8B baseline at 64k–128k, rather than the "unextended stress reference" KV-Direct used here?
  2. Since the j=0 (retrieval-only) ablation beats the final distilled CoMem on LoCoMo (41.59 vs. 38.27), is there a sweet-spot or adaptive split depth that recovers more of that gap while keeping most of the efficiency gain?
  3. Would a dense/learned retriever close the BABILong qa2 gap (27.0) or the BABILong-vs-KV-Direct macro gap (50.43 vs. 63.00)?
  4. How does end-to-end latency — including CPU-side BM25 retrieval — scale on real, non-synthetic multi-hop conversational workloads?
  5. Would applying self-distillation more fully to the HCache-style baseline (matching retrieval, not just readout) close the remaining gap in Table 11, and reshuffle the ranking of "depth caching" alone versus the full system?
