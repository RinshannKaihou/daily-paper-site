VeriSkill: A Self-Evolution Framework for Program Verification Skills ↗
Changguo Jia, Tianqi Zhao, Zhiyou Xiao, Weiming Zhang, et al. (5 authors) · 2026-07-30
Peking University, Zhongguancun Laboratory, and Shanghai Jiao Tong University; first two authors contributed equally; Minghui Zhou (PKU) is corresponding author. Single-submission arXiv preprint (cs.AI, posted 2026-07-30), no stated venue — read as unreviewed. Two of three benchmarks (Frama-C, VeriFast) are self-constructed by the authors and cross-validated by only two experts.

适用读者：关注 agentic self-evolution、程序综合与验证、可信 LLM 系统评估方法论的研究者——"先做失败责任归因、再用留出验证集严格准入"这一设计模式，可迁移到更广泛的 agent skill 演化场景。

Key Metric
+17.0 pp
VeriSkill's largest margin over the strongest baseline (SkillOpt-Lite): 93.0% vs. 76.0% PASS on VeriFast with Codex/GPT 5.6 Sol. Against the No-Skill floor of 41.7% on that same track, the gain is +51.3 pp.
Why This Matters

Naive skill self-evolution can update skills based on failures that aren't the skill's fault — wasting effort, or worse, degrading performance instead of improving it.

Critical Edge

No code, skill artifacts, or datasets are released; two of three benchmarks are self-constructed by the authors; and the full evaluation cost ~$15K in API spend — independent replication isn't really possible today.

Methodology

Three-stage closed loop, repeated until no evolvable failures remain
STAGE 1 · ATTRIBUTIONClassify each failure into 4 buckets — task unsatisfiable, prover limitation, skill noncompliance, skill knowledge gap. Only the last two count as evolution signal.
→
STAGE 2 · ABSTRACTIONCluster skill-attributable failures by diagnostic signature; abstract a portable "lesson" stripped of task IDs, filenames, variable names.
→
STAGE 3 · ADMISSIONRevise-test the candidate skill locally, then admit only if it strictly improves PASS on a frozen validation set without touching program semantics.

VeriSkill treats the skill text S as the object being optimized: J(S) = E[verifier acceptance under S], subject to a hard constraint M(x,a)=1 — no accepted revision may alter the target program's executable behavior. Instead of assuming every failure reveals a skill defect, Stage 1 first asks whose fault it is, discarding cases caused by SMT solver limits or genuinely unsatisfiable annotations. Stage 2 turns the survivors into reusable lessons (applicability conditions, proof steps, inapplicable cases), using human-verified references only as evidence — never as templates to copy. Stage 3 logs every accepted, rejected, or skipped revision to an evolution memory that stops later rounds from re-deriving already-falsified fixes.

Evaluated on Dafny (200 tasks, 4:1:5 split), Frama-C (85 tasks mined from GitHub, expert cross-validated), and VeriFast (200 tasks) against 7 baselines — No Skill, LLM Skill, Human Skill, Skill-Creator, EvoSkill, AutoSkill, SkillOpt-Lite — each run 3× and averaged.

Strengths

What holds up
  • +Verifier-specific problem decomposition (SMT solver limits, opaque VC feedback) — not a generic "collect more failures" fix.
  • +Comprehensive evaluation: 3 verifiers × 2 backbones × 7 baselines × component ablation × 5-model transfer study.
  • +Explicit semantic-preservation constraint M(x,a)=1 baked into local and global admission — guards against gaming "verification success" via behavior changes.
  • +Evolution memory prevents re-deriving already-falsified hypotheses across rounds.
  • +Cross-model transfer shows the extracted skill is portable knowledge, not a prompt tuned to one model's quirks.

Limitations

What to weigh against it
  • −Ablation covers only Dafny + Opus 4.8 — untested whether the same stage-importance ranking holds for Frama-C/VeriFast or Codex.
  • −No code, skill artifacts, or dataset release; two of three benchmarks are self-constructed with only two-expert review.
  • −No inter-round convergence data — only the final converged-skill PASS is shown, not how many rounds it took to get there.
  • −Human Skill's underperformance vs. No Skill is reported but never diagnosed.
  • −~$15K API cost plus a required human-verified reference artifact per task limits accessibility for new tools or codebases.

Questions for Further Exploration

Open threads from the paper's own discussion
  • How does PASS evolve across evolution rounds — convergence speed, diminishing returns, how many rounds before admission gates stop firing?
  • Why does expert-authored Human Skill sometimes underperform No Skill — verbosity/rigidity artifact, or something about how agents parse static vs. procedurally-validated guidance?
  • Would the four-category failure taxonomy generalize to other hard-verifiable domains (theorem proving, compiler correctness, exploit generation)?
  • What's the residual failure composition after convergence (57.3%–93.0% PASS) — genuine prover limitations vs. unresolved skill gaps?
  • How sensitive is the framework to the quality/availability of human-verified references — could weaker or synthetic references work?
