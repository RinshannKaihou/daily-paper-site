LLM Agents · Skill Distillation

Diffing a failed student run against a teacher's success yields 38 rules that lift agent scores from 43.5 to 66.8.

SKILL-KD: Contrastive Skill Distillation for LLM Agents
Qiming Shi et al. 2026-07-30 arXiv:2607.28048
LLM Agents Skill Distillation Knowledge Distillation Prompt-Based Adaptation Agent Benchmarks
Zhejiang University · Peking University · Alibaba Group — arXiv preprint, cs.AI, Jul 2026. No code/artifact release noted in the paper.
Key Metric
66.8
Average score across 5 agent benchmarks (Qwen3.5-4B student), up from 43.5 with no skill library and ahead of the strongest baseline, SkillOpt, at 63.5 — reached with only 38 rules, the smallest library of any method tested.
Why This Matters

Gives a frozen, cheap LLM a way to inherit a stronger model's know-how as auditable text rules instead of fine-tuning or exposing weights or logits.

Critical Edge

Every headline number comes from a single evaluation run with no variance across seeds, so on small test splits like ALFWorld (134 instances) a handful of flipped outcomes can swing scores by several points.

Methodology

SKILL-KD maintains one shared skill library as a living Markdown document, not a frozen prompt. For each training task, the frozen student first attempts it with the current library; only failures trigger action. A stronger teacher then attempts the identical task, and — because even teachers aren't oracle-correct — a consolidation agent diffs the two trajectories rather than assuming the teacher is right, drafting a candidate rule from where the decisions diverge.

student fails→ teacher attempts same task→ diff trajectories → draft patch→ student reruns→ success → commit (≤3 rounds)

That patch is tested, not trusted: the student reruns the same task against the patched library, and only a patch that actually flips the outcome to success is kept. A separate multi-turn consolidation agent tracks a trace-linked edit history so every new rule is checked against past edits before being added, merged into an existing rule, or discarded — the mechanism that keeps the library from drifting into redundant or contradictory advice over time.

  • ALFWorld generalization: held-out unseen environments jump from 30.6 → 86.6 (+56.0 pts), beating SkillOpt's 81.3 by +5.3 pts — the largest single-benchmark gain reported.
  • Validation drives the gain: training-set cumulative success climbs from 58.9% at round n=0 (no rerun) to 67.7% at n=1, then diminishes to 70.8% (n=2) and 72.7% (n=3).
  • Imperfect teachers still help: the teacher itself succeeds only 46.1% of the time on student-failed cases, yet 38.5% of accepted patches on average still come from teacher-failure rollouts.
  • Thinnest margin: SpreadsheetBench sees SKILL-KD edge SkillOpt only 24.3 vs. 23.9 — the paper notes this is also where drift-aware consolidation helps least.

Strengths vs. Limitations

Strengths

  • Clear conceptual framing: teacher-student behavioral diffing as the actionable learning signal, not one-sided experience summarization.
  • Targeted ablations isolate exactly what adaptive validation and drift-aware consolidation each contribute, not just an end-to-end score.
  • Concrete, paper-specific case studies of three failure modes (case-specific, skill-bloat, destructive-update drift) with real skill-library examples.
  • Validated across both homogeneous and heterogeneous teacher-student pairs, plus generalization to unseen ALFWorld environments.
  • Transparent about imperfect teachers: the method still works when the teacher itself only succeeds 46.1% of the time.
  • Produces markedly more compact libraries (38 rules) than every ablated alternative (up to 96 rules) while scoring higher.

Limitations

  • Single-run evaluation per benchmark with no variance across seeds, despite inherently stochastic agent rollouts.
  • Small test partitions (ALFWorld 134, LiveMath 124) let a handful of flipped instances swing headline scores by several points.
  • No comparison against a simple in-context baseline using raw teacher trajectories, so it's unclear how much comes from "skill" packaging vs. more teacher information.
  • Relies on non-deterministic, versioned API models (ChatGPT-5.5, Qwen3.7-plus) for teacher and consolidation, with no code release indicated.
  • Consolidation add/modify/delete/skip decisions are themselves LLM judgments with no independent correctness check beyond the student rerun.
  • Bounded to n=3 adaptive rounds by observed diminishing returns, without exploring compute/cost overhead or harder task families needing more rounds.

Questions for Further Exploration

  1. How would SKILL-KD compare against a simple in-context baseline that injects the teacher's raw successful trajectory directly, with no skill-abstraction step?
  2. Does the benefit hold across multiple seeds, especially on small test sets like ALFWorld (134) and LiveMath (124)?
  3. Does skill-library quality plateau, or eventually re-drift, as more training tasks accumulate beyond this paper's dataset?
  4. Can the consolidation agent's add/modify/delete/skip calls be validated against a human-audited "ideal" library, rather than only the downstream student rerun?
  5. What is the API-cost and compute overhead of iterative student reruns and multi-turn consolidation relative to one-shot summarization baselines?
  6. Would the framework work without a strictly stronger teacher — e.g., self-distillation from a committee of same-capability agents?
