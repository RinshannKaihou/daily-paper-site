> **一句话总结：** VeriSkill 通过"责任归因—失败模式聚类抽象—可执行验证准入"三阶段闭环，把形式化验证器的失败反馈转化为可复用的技能文本更新，在 Dafny/Frama-C/VeriFast 三个验证工具、Claude Code 与 Codex 两套智能体框架下相较最强基线 SkillOpt-Lite 最高再提升 17.0 个百分点的 PASS 率。

> **TL;DR:** VeriSkill is a self-evolution framework that turns LLM-agent program-verification failures into vetted, reusable skill updates via (1) failure responsibility attribution, (2) pattern-level lesson abstraction, and (3) executable revise-test-validate admission. On Dafny with Claude Code/Opus 4.8 it lifts PASS from 14.0% (No Skill) to 57.3% (+43.3 pp), beating the strongest baseline SkillOpt-Lite (42.3%) by +15.0 pp; on VeriFast with Codex/GPT 5.6 Sol it reaches 93.0% vs. SkillOpt-Lite's 76.0% (+17.0 pp).

## 核心贡献

- **提出问题：通用技能自演化方法不适用于程序验证。** 验证失败不一定意味着技能缺陷（可能是 SMT 求解器能力不足或程序/标注本身不可满足），而验证器输出的失败条件也不是直接可复用的过程性知识（如错误的循环不变式源于错误的数学推导，但失败的验证条件本身对修正推导帮助有限）。
- **责任归因（Stage 1）：** 将每次验证失败归为四类——任务不可满足（task unsatisfiability）、证明器能力局限（prover limitation）、技能未遵守（skill noncompliance）、技能知识缺口（skill knowledge gap），只保留后两类作为技能演化信号，并利用演化记忆（evolution memory）避免重复误判。
- **模式级缺陷聚类与教训抽象（Stage 2）：** 为每个失败提取"诊断签名"（哪里失败、缺失什么验证责任、技能文本为何失败三部分），按共享失败模式聚类，抽象出可复用的"教训"（lesson），并主动剥离任务 ID、文件名、具体变量名/常量等实例细节，只保留通用适用条件与不适用场景。
- **可执行验证与准入机制（Stage 3）：** 候选技能先在归因集（attribution set）和留出的迁移集（transfer set）上做"修订-测试"循环，通过局部检验后才在冻结的验证集上比较，只有严格提升验证集 PASS 率且不破坏程序语义（不修改可执行代码）的修订才被采纳，形成受控的技能迭代。
- **跨工具、跨框架、跨模型的一致提升：** 在 Dafny、Frama-C、VeriFast 三个验证工具、两套主力智能体框架（Claude Code+Opus 4.8、Codex+GPT 5.6 Sol）下全面超越 7 个基线；用 Codex 演化出的技能不做任何模型专属调整即可迁移到 5 个不同的骨干模型（GLM-5.2、Kimi-K2.7、Qwen3.7-Max、DeepSeek-V4-Pro、Qwen3-Coder），PASS 率提升 15.3–43.7 个百分点。

## Key Contributions

- **Problem framing:** Generic skill self-evolution methods fail on program verification because (a) a failed verification attempt does not necessarily indicate a skill deficiency — it could stem from SMT solver limitations or an unsatisfiable task/annotation — and (b) failed verification conditions reported by verifiers are not directly reusable procedural knowledge (e.g., a wrong loop invariant traces back to a flawed mathematical derivation that the failed VC alone does not reveal).
- **Stage 1 — Responsibility Attribution:** Classifies each failure into four categories — *task unsatisfiability*, *prover limitation*, *skill noncompliance*, *skill knowledge gap* — using the failed task, verifier feedback, current skill, generated artifact, human-verified reference, and evolution memory. Only the latter two categories become evolution signals.
- **Stage 2 — Lesson Abstraction via Pattern-Level Defect Clustering:** Extracts a three-part diagnostic signature per failure (proof-obligation localization, verification-responsibility abstraction, skill-failure mechanism), clusters failures sharing the same signature, and abstracts a generalizable lesson (applicability conditions, proof steps, inapplicable cases) while deliberately stripping instance-specific details (task IDs, file names, variable names, constants) — using human-verified references only as evidence, not as templates to copy.
- **Stage 3 — Executable Validation and Admission:** Runs a local revise-test loop on attribution cases (Ac) and held-out same-pattern transfer cases (Tc), rejecting pass-to-fail regressions or executable-code edits; only locally-valid candidates proceed to a frozen validation set, and are admitted only if they strictly improve validation PASS while satisfying the semantic-preservation constraint M(x,a)=1 for all validation tasks. Every outcome (accepted/rejected/skipped) is logged to evolution memory to steer future rounds.
- **Broad empirical validation:** Consistent state-of-the-art PASS rates across 3 verifiers × 2 agent/backbone configurations, an ablation isolating each stage's contribution, and a cross-model transfer study showing the evolved skill is portable knowledge rather than a model-specific prompt artifact.

## Methodology

**Formalization.** Let π(·|x,S) be the agent's solution policy conditioned on task x and skill S. The expected verification success rate is J(S) = E_x~D E_a~π(·|x,S)[V(x,a)], with V(x,a)∈{0,1} indicating verifier acceptance. The goal is S* = argmax_S J(S), subject to a semantic-preservation constraint M(x,a)=1 (the candidate solution must not alter the original executable program's behavior).

**Three-stage loop (Algorithm 1), repeated until no evolvable failures remain:**
1. *Attribution*: Roll out the agent under current skill S_t on the training set T, collect verifier outcomes, attribute each failure to one of the four categories above using artifact + verifier log + skill + reference proof + evolution memory (EM), and filter to skill-related failures F_skill.
2. *Abstraction*: Diagnose and cluster F_skill by diagnostic signature into clusters C; split each cluster into attribution cases A_C and transfer cases T_C; abstract a verification responsibility K from A_C (using S_t and EM); if no responsibility can be abstracted, record the cluster as skipped and continue.
3. *Admission*: Build a candidate lesson ℓ from K, construct a complete candidate skill S' = Revise(S_t, ℓ, EM) (a controlled, scoped revision — not a blind append — that can rewrite unclear steps, add conditional guidance, or make an abstract principle explicit while preserving unrelated sections), then evaluate locally via τ̂_attr and τ̂_trans (Eq. 5), which measure per-case pass/fail deltas on A_C and T_C respectively relative to S_t. This revise-test loop repeats until both local checks pass or a per-cluster budget is exhausted. Locally valid candidates are then evaluated on a frozen validation set V via Ĵ_V(S) (Eq. 6); S_t+1 = S' only if Ĵ_V(S') > Ĵ_V(S_t) AND M holds for every validation task, otherwise S_t+1 = S_t. All outcomes (accepted/rejected/skipped, with attribution, lesson, and applicability conditions) are stored in EM.

**Datasets.** Three verification tracks built as C→target-language translation/annotation tasks with disjoint train/validation/benchmark splits: Dafny (200 tasks from DafnyBench, manually paired with plain-C inputs and hidden Dafny references, split 4:1:5); Frama-C (85 C-to-ACSL tasks mined from 4 GitHub repositories, annotations stripped and cross-validated by two formal-verification experts, split 68/17 train/val with the separate Frama-C-Problems benchmark for testing); VeriFast (200 C-to-VeriFast tasks built the same way from GitHub sources, split 4:1:5).

**Baselines (7):** No Skill, LLM Skill (one-pass generated skill), Human Skill (GitHub-sourced/expert-authored, validated by a 7-year formal-verification expert), Skill-Creator (Anthropic's official skill-authoring framework), EvoSkill (Pareto-frontier mutation from failure batches), AutoSkill (skill derivation from dialogue/interaction traces), SkillOpt-Lite (trajectory-exploration + validation-gated skill text evolution).

**Metric.** PASS = % of benchmark tasks where the generated artifact is both accepted by the target verifier and passes a semantic-preservation check (no edits to executable behavior, no verification-bypass constructs; C-to-Dafny checks aligned callables/control flow/state updates/returns/assertions). Each method is run 3 times and averaged. The full evaluation cost ~US$15K in API spend.

## Results & Highlights

- **Main comparison (Table 1), Claude Code/Opus 4.8:** VeriSkill reaches Dafny PASS 57.3% vs. No Skill 14.0% (+43.3 pp) and vs. the strongest baseline SkillOpt-Lite 42.3% (+15.0 pp); Frama-C 74.5% vs. No Skill 56.9% (+17.6 pp) and vs. SkillOpt-Lite 65.4% (+9.1 pp); VeriFast 84.0% vs. No Skill 38.0% (+46.0 pp) and vs. SkillOpt-Lite 78.3% (+5.7 pp).
- **Main comparison, Codex/GPT 5.6 Sol:** Dafny PASS 66.0% vs. No Skill 17.0% (+49.0 pp) and vs. SkillOpt-Lite 62.7% (+3.3 pp); Frama-C 83.0% vs. No Skill 57.5% (+25.5 pp) and vs. SkillOpt-Lite 66.7% (+16.3 pp); VeriFast 93.0% vs. No Skill 41.7% (+51.3 pp) and vs. SkillOpt-Lite 76.0% (+17.0 pp).
- **Non-evolved skills are unreliable:** one-pass LLM Skill and expert-written Human Skill sometimes score *below* No Skill (e.g., Human Skill on Dafny/Claude: 7.7% vs. No Skill's 14.0%), while all self-evolution methods (including generic ones) beat No Skill — underscoring that evolution, not just prompt authorship, drives gains.
- **Ablation on Dafny/Opus 4.8 (Table 2):** Removing Executable Validation drops PASS from 57.3% to 36.0% (−21.3 pp, the largest single-component effect); removing Responsibility Attribution drops it to 44.3% (−13.0 pp); removing Lesson Abstraction drops it to 49.0% (−8.3 pp). All three stages are shown to be necessary and additive.
- **Cross-model transfer (Figure 2):** A skill evolved once with Codex, deployed unchanged via the Terminus agent wrapper on five other backbones, improves Dafny PASS by +43.7 pp (GLM-5.2: 12.0%→55.7%), +41.4 pp (Kimi-K2.7: 10.3%→51.7%), +36.6 pp (Qwen3.7-Max: 7.7%→44.3%), +35.0 pp (DeepSeek-V4-Pro: 6.0%→41.0%), and +15.3 pp (Qwen3-Coder: 2.0%→17.3%) — evidence the evolved skill is portable knowledge, not a model-specific artifact.
- **Case study (Table 3):** For a C null-pointer guard (`if (ptr==NULL){abort();}`), EvoSkill's generic evolution updates the skill to "preserve failure-guard branches" (mirroring source control flow literally), while VeriSkill's verification-specific attribution recognizes the branch as a host-level executability guard carrying no verified data-state behavior and instructs "do not fabricate branches for untranslatable failure guards" — the divergent lesson correlates with the reported Dafny PASS gap (32.3% vs. 57.3%, matching EvoSkill's and VeriSkill's Table 1 numbers).

## Authors & Credibility

Authors are affiliated with Peking University, Zhongguancun Laboratory, and Shanghai Jiao Tong University; the first two authors contributed equally, with Minghui Zhou (Peking University) as corresponding author. The paper is a single-submission arXiv preprint (cs.AI, posted 2026-07-30) with no stated venue/acceptance — it should be read as a preprint, not a peer-reviewed publication. The experimental design (three distinct verification tools, two production agent frameworks + five additional cross-model backbones, 7 competitive and recent baselines from 2026, disclosed ~$15K API cost) signals a serious empirical effort, though the datasets for Frama-C and VeriFast are self-constructed by the authors (with only manual cross-validation by "two experts," one of whom appears to be a co-author's contact rather than an independent panel), which warrants some caution about benchmark construction bias.

## Critical Assessment

**Novelty:** The core idea — distinguishing skill-attributable failures from environment/solver-attributable ones before allowing skill updates — is a genuinely domain-specific insight lacking in prior generic skill-evolution work (EvoSkill, SkillOpt-Lite, AutoSkill, Trace2Skill, SkillCAT, CoEvoSkills), and the four-way failure taxonomy (task unsatisfiability / prover limitation / skill noncompliance / skill knowledge gap) is a clean, reusable framing that could generalize beyond program verification to other tool-grounded, hard-verifiable domains.

**Rigor:** The ablation (Table 2) and cross-model transfer (Figure 2) experiments are well-designed controls that isolate specific claims (each stage matters; the skill is not a model-specific artifact). However, the ablation is run on only *one* track (Dafny) and *one* backbone (Opus 4.8) — it is not shown whether the same component ranking (validation > attribution > abstraction) holds for Frama-C/VeriFast or under Codex, which is a meaningful gap given the paper's own emphasis on cross-tool generality.

**Reproducibility:** No code, skill artifacts, or dataset release is mentioned in the paper body (no links to a repository), and the self-constructed Frama-C/VeriFast datasets rely on manual expert review rather than an open, auditable process — this makes independent replication difficult. The specific LLM versions cited (Opus 4.8, GPT 5.6 Sol, GLM-5.2, Kimi-K2.7, Qwen3.7-Max, DeepSeek-V4-Pro) are all future/unreleased-as-of-writing model designations relative to the paper's dated context, which is worth flagging as unusual (though consistent with the paper's stated 2026 timeframe).

**Significance / red flags:** The paper's own baseline table shows Human Skill — written by a domain expert with 7 years of formal-verification experience — sometimes performs *worse* than No Skill (e.g., Dafny/Claude: 7.7% vs. 14.0%; VeriFast/Claude: 24.3% vs. 38.0%), which is a striking and somewhat under-discussed finding; the paper treats it mainly as motivation for automation without probing why expert-authored skills backfire (e.g., could an overly verbose or overly rigid human skill actively mislead the agent on unfamiliar cases?). The case study (Table 3) is illustrative but a single anecdote rather than a systematic error analysis of *why* VeriSkill's attribution mechanism outperforms EvoSkill's across the full failure population. Additionally, PASS-rate deltas of 40–50 points over "No Skill" partly reflect how weak the no-skill baseline is on these tasks (14–41% base rates), so the practical ceiling and remaining error modes at ~60-90% PASS are not deeply analyzed (e.g., what fraction of remaining failures are prover limitations vs. unresolved skill gaps after convergence).

## Strengths

- Clear, well-motivated problem decomposition (why generic skill self-evolution fails for verification) grounded in concrete verifier-specific reasoning (SMT solver limits, opaque VC feedback).
- Comprehensive multi-axis evaluation: 3 verification tools × 2 primary agent/backbone pairs × 7 baselines × component ablation × 5-model cross-transfer study.
- Explicit semantic-preservation constraint (M(x,a)=1) baked into both local validation and global admission, guarding against the failure mode where "verification success" is gamed by altering program behavior.
- Evolution memory design (recording accepted/rejected/skipped outcomes) is a sensible mechanism to prevent repeated re-derivation of already-falsified hypotheses across rounds.
- Cross-model transfer result is a strong, non-trivial demonstration that the extracted "skill" is genuinely externalized procedural knowledge rather than a prompt tuned to one model's quirks.

## Limitations

- Ablation study covers only one verifier (Dafny) and one backbone (Opus 4.8); generality of the component-importance ranking across Frama-C/VeriFast and Codex is untested in the paper.
- No public code/artifact release is indicated, and two of the three benchmark datasets are self-constructed with limited independent validation (two experts, one from the author pool's network), raising reproducibility and potential selection-bias concerns.
- The paper does not report inter-round convergence behavior (how many evolution rounds are needed, or how PASS trends across rounds) — only final converged-skill PASS is shown.
- The surprising underperformance of expert-written Human Skill relative to No Skill in several settings is reported but not diagnosed, leaving open whether the result reflects genuine skill-authoring difficulty or peculiarities of the specific human skills used.
- The $15K API cost and requirement for a "human-verified reference artifact" per task limits accessibility — this is a resource-intensive pipeline not obviously cheap to run for new verification tools or codebases.

## Relevance

该工作提出了一个可迁移到"技能自演化 / agent skills"研究方向的关键设计模式——先做失败责任归因再决定是否更新技能，并用留出的验证集做严格准入——这与近期 agent skill 演化、self-improving agents、以及 LLM 辅助形式化验证等方向高度相关，适合关注 agentic self-evolution、程序综合与验证、以及可信 LLM 系统评估方法论的研究者参考。

## Questions for Further Exploration

- How does PASS evolve across evolution rounds (convergence speed, diminishing returns), and how many rounds/API calls are typically needed before admission gates stop firing?
- Why does expert-authored Human Skill sometimes underperform No Skill — is this an artifact of skill verbosity/rigidity, or does it reveal something about how LLM agents parse static human guidance versus procedurally-validated lessons?
- Would the four-category failure taxonomy (task unsatisfiability / prover limitation / skill noncompliance / skill knowledge gap) generalize to other hard-verifiable agentic domains (e.g., theorem proving, compiler correctness, security exploit generation) beyond program verification?
- What is the residual failure composition after VeriSkill converges (e.g., at 57.3%–93.0% PASS) — how much of the remaining gap is attributable to genuine prover limitations versus skill gaps that the framework's clustering/abstraction failed to isolate?
- How sensitive is the framework to the quality/availability of "human-verified reference artifacts," and could it operate with weaker or synthetic references when experts are unavailable?
