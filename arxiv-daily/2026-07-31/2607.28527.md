> **一句话总结：** MANTA让LLM多智能体系统在推理阶段动态规划并修复自己的通信拓扑（增删智能体、改变通信边、调整验证结构），在五个基准上平均得分74.0，比最强基线（ADAS，68.2）高5.8分，且推理阶段token消耗在所有被评测的多智能体系统中最低。

> **TL;DR:** MANTA treats multi-agent communication topology as an inference-time self-improvement target rather than a fixed design choice: a Topology Planner drafts a task-conditioned graph, a Trace Auditor flags process anomalies during execution, and a Controller applies at most one bounded structural repair (add/expand agent, rewire edges, change group pattern, adjust visibility) per run, with lessons distilled into a cross-run playbook. On Gemma 4 31B across BrowseComp, StableToolBench, PlanCraft, WorkBench, and MATH, MANTA reaches an average success rate of 74.0%, beating the strongest baseline (ADAS, 68.2%) by 5.8 points and beating Single Agent (59.3%) by 14.7 points, while using the fewest total tokens (77,652/run) among all evaluated multi-agent systems. It is not uniformly best, however: AgentSquare beats it on StableToolBench (88.9 vs 82.2) and ADAS beats it by a wide margin on WorkBench (66.7 vs 43.3), where MANTA barely edges out a single agent (41.1).

## 核心贡献

- **将拓扑本身视为推理阶段可自我改进的对象**（他们称为"topology-level self-improvement"，作者将其定位在Levels-of-Self-Improvement图谱的L6层），区别于以往在部署前离线搜索/优化拓扑（如AFlow、ADAS、AgentSquare、MASS）的做法。
- **MANTA框架**：由三个LLM组件——Topology Planner（任务条件化初始规划）、Trace Auditor（过程异常审计，不评判答案对错）、Controller（决定终止或触发一次有界拓扑修复）——加确定性代码（拓扑校验、消息路由、证据账本）共同构成；每次修复最多执行3个原子操作（add_agent、expand_agent_to_group、set_group_pattern、add/remove_edge、set_context_policy）。
- **双层playbook记忆**：run内的短期playbook记录本次每一轮的拓扑、审计发现与决策；跨run的长期playbook每12次运行由Skill Reflector用纯过程信号（无标准答案）批量重写，用于指导初始拓扑规划与修复选择，且可跨任务/跨基准迁移。
- **实证结果**：五个基准平均分74.0，超过最强基线5.8分，在BrowseComp和PlanCraft上取得单项最优；消融显示初始任务条件化规划贡献最大（从71.7降到57.5），拓扑修复次之（降到60.8）；MANTA是所有被评测多智能体系统里推理期token消耗最低的。
- **案例分析与可解释性**：论文展示了具体的拓扑修复案例（过载分支扩展为子组、串行化重复的状态改写调用、给低置信度singleton插入critic、给过早达成一致的debate补边），并统计了151次修复中操作类型分布（改变组模式27.2%、扩展为子组20.4%、新增agent仅9.3%），佐证"拓扑演化不等于简单加人加边"的论点。

## Key Contributions

- **Reframes communication topology as an inference-time self-improvement target** ("topology-level self-improvement", positioned as level L6 in the paper's self-improvement hierarchy), distinct from prior work that treats topology as an offline design/search target fixed before execution (AFlow, ADAS, AgentSquare, MASS).
- **The MANTA framework**: three LLM components — a Topology Planner (task-conditioned initial design), a Trace Auditor (flags process-observable anomalies without judging answer correctness), and a Controller (decides to finalize or trigger one bounded repair) — combined with deterministic code that validates topologies, routes messages via structured relay packets, and maintains an append-only evidence ledger. Each repair emits at most 3 atomic mutation operations (add_agent, expand_agent_to_group, set_group_pattern, add/remove_edge, set_context_policy), applied to a versioned, re-validated topology copy.
- **Two-horizon playbook memory**: a short-term, within-run playbook logs each turn's topology, audit findings, and controller decision; a long-term, cross-run playbook is rewritten in batches of 12 runs by a Skill Reflector using only process signals (never ground-truth correctness), and is shown to transfer both in-domain and cross-domain.
- **Empirical results**: average success of 74.0 across five benchmarks, 5.8 points above the strongest baseline, with the best result on BrowseComp and PlanCraft. Ablations show initial task-conditioned planning contributes the most (71.7→57.5 when removed) followed by topology repair (→60.8); MANTA also has the lowest inference-time token footprint of all evaluated multi-agent systems.
- **Interpretability via case studies and repair statistics**: concrete traces show branch expansion under tool-failure overload, serialization of duplicated state-changing calls, critic insertion for unchecked low-confidence answers, and edge-rewiring to break premature consensus. Across 151 repairs, changing group pattern (27.2%) and expanding an agent into a subgroup (20.4%) dominate, while simply adding an agent accounts for only 9.3% — supporting the claim that topology evolution is about reorganizing structure, not just growing team size.

## Methodology

MANTA has three phases per task, orchestrated by deterministic control code around three LLM meta-agents:

1. **Query-conditioned initial planning.** The Topology Planner receives the task text and the long-term playbook (never the benchmark identity or a hand-designed topology). It analyzes task type, ambiguity, verification needs, and failure risks, then emits a compact JSON plan (topology pattern, agent count, verifier flag) that deterministic code expands into a full, validated topology (roles, communication edges, context/visibility policies). Root interaction patterns are limited to singleton, star, chain, debate, or voting, with a max of 5 initial agents and 10 total after repair.

2. **Execution with trace auditing.** The target multi-agent system executes turn by turn; a shared-context controller enforces per-agent visibility over structured "relay packets" (not raw transcripts) and an append-only evidence ledger deduplicates tool calls. After each turn, an LLM Trace Auditor — combining a fixed deterministic "process-anomaly taxonomy" (11 named failure modes such as tool_error_cascade, duplicate_state_mutation, premature_consensus, missing_validator) with open-set LLM judgment requiring verbatim-quoted evidence — flags anomalies and recommends whether repair is warranted. A run is "flagged" if a medium/high-severity repairable issue surfaces.

3. **Bounded trace-backed repair.** If flagged, the Controller allows exactly one mutation (≤3 operations) per run, applied by the Planner and validated/compiled by deterministic code (structural validation: acyclicity, role legality, agent budget). A separate deterministic path handles retrieval-heavy tasks via a fixed "retrieval contraction" heuristic (collapse to the most successful non-coordinator searcher) that bypasses the Planner. Context management is designed to make mutation "cheap and lossless": agents are stateless, all state lives in append-only shared stores (packet store, evidence ledger, turn candidates), and mutating the topology simply re-points a shared context controller at the new spec without migrating or recomputing history.

Memory: a **short-term playbook** logs each turn's topology/findings/decision within the current run; a **long-term playbook** (a markdown "Topology Planning Skill" document with protected "standing principles" and a Reflector-editable "lessons from experience" section) is rewritten every 12 runs using only process-signal labels (audit-clean vs. flagged, consensus reached vs. not) — ground truth is never exposed to the Planner, Auditor, or Reflector.

Backbone: all methods use **Gemma 4 (Google DeepMind, 2026)** with "medium reasoning effort" as the single LLM backbone (task agents and all three meta-agents share it, meta-agents at temperature 0). No other backbone model is tested, so generalization across model families is unverified.

## Results & Highlights

- **Overall average success rate**: MANTA achieves **74.0±1.8** averaged across BrowseComp, StableToolBench, PlanCraft, WorkBench, and MATH (30 questions × 3 runs per benchmark, Gemma 4 31B), versus the strongest baseline **ADAS at 68.2±3.2** — a **+5.8 point** gap — and versus **Single Agent at 59.3±2.5** (+14.7 points).
- **Per-benchmark wins and losses are mixed, not uniform**: MANTA gets the best score on **BrowseComp (76.7 vs. Orchestrator w/ Discussion's 64.4, the best static baseline)** and **PlanCraft (76.7 vs. Orchestrator w/ Discussion's 73.3)**, but is **not** best on StableToolBench (MANTA 82.2 vs. **AgentSquare 88.9**), WorkBench (MANTA 43.3 vs. **ADAS 66.7**, a 23.4-point deficit — MANTA only marginally beats Single Agent's 41.1 here), or MATH (MANTA 91.1 vs. a three-way tie at **96.7** for AFlow/AgentSquare/Self-Refine).
- **Ablation (Table 2, averaged over BrowseComp/WorkBench/PlanCraft/StableToolBench)**: removing the initial task-conditioned Topology Planner (replacing it with a fixed coordinator-worker star) drops success from **71.7% to 57.5%** — the largest single-component contribution. Disabling topology mutation (repair) drops it to **60.8%**. Freezing or removing the long-term playbook gives smaller drops, to **67.5%** and **66.7%** respectively.
- **Token efficiency (Table 4)**: MANTA uses **77,652 total tokens/run** (63,724 in / 13,928 out) with **no offline cost**, the lowest among all multi-agent systems evaluated — cheaper than the cheapest static baseline (Voting, 80,781) and far cheaper than optimization-based baselines once offline search cost is counted (e.g., ADAS 275,403 total including 247,675 offline; AgentSquare 157,993 including 143,056 offline). Meta-level (planning/auditing/repair) operations account for only ~12% of MANTA's inference budget.
- **Cross-run/cross-domain playbook transfer (Table 3)**: at mutation budget zero (isolating pure playbook-guided initialization), MANTA's long-term playbook improves in-domain reuse by **+3.3 points each** (PlanCraft: 70.0→73.3; WorkBench: 43.3→46.7) and gives the **only positive mean cross-domain transfer** among tested adaptive baselines: **PlanCraft→WorkBench 43.3→50.0 and WorkBench→PlanCraft 70.0→70.0 (mean Δ +3.3)**, versus MASS's catastrophic **mean Δ −58.3** (WorkBench→PlanCraft collapses from 70.0 to 0.0) and AgentSquare's **mean Δ −13.3**.
- **Trace-auditing diagnostics reveal a domain-dependent weakness**: the audit-as-correctness-proxy has an aggregate **precision 0.38 / recall 0.64 / F1 0.47** across all 450 runs, but this varies hugely by benchmark — **F1 is only 0.09 on PlanCraft (recall 0.05)** and **0.20 on MATH (recall 0.13)**, meaning the auditor essentially fails to catch process problems on the two benchmarks with the least tool/retrieval structure, versus a much stronger **F1 of 0.78 on WorkBench**. Of 151 repairs, 60.9% reduced the number of flags in the next audit and repaired runs were correct in 69.5% of cases (vs. 74.0% overall average), suggesting repair alone is not a guaranteed accuracy fix.
- No quantitative human/LLM-judge inter-annotator agreement is reported for the process-anomaly taxonomy — the paper explicitly lists this as future work ("Complementary validation").

## Critical Assessment

**Novelty**: The core idea — treating topology as something the system revises online, mid-task, guided by trace-level process auditing rather than by benchmark feedback or offline search — is a genuinely distinct point in the design space compared to AFlow/ADAS/AgentSquare/MASS, which all fix the topology before test-time execution. The "process-signal-only" memory design (Reflector and Auditor never see ground truth) is a thoughtful choice that avoids benchmark overfitting in the long-term playbook, though it also means the system optimizes for "looks clean" rather than "is correct" — the paper is honest about this gap (69.5% correctness after repair, not near-100%).

**Rigor**: The ablation study and mutation-budget sweep are well-designed and isolate specific contributions cleanly. However, evaluation uses only **30 questions per benchmark** (90 runs per benchmark across 3 seeds), which is a small sample for benchmarks like BrowseComp and WorkBench that are known to have high variance — the reported standard deviations (e.g., ±4.7 to ±15.0) are sizable relative to the score gaps being claimed as improvements. A single backbone model (Gemma 4 31B) is used throughout; there's no evidence the topology-adaptation gains hold for a different model family or scale.

**Paper-specific weak spots**: MANTA is convincingly not a universal winner — it loses to ADAS by 23.4 points on WorkBench and to AgentSquare by 6.7 on StableToolBench, and sits behind three baselines tied on MATH. The paper's own diagnostic table (Table 8/10) shows the Trace Auditor is nearly blind on PlanCraft (F1=0.09, recall 0.05) and MATH (F1=0.20), which undercuts the "trace auditing drives repair" narrative specifically for the reasoning-heavy benchmarks — on PlanCraft, MANTA's win appears to come mostly from initial task-conditioned planning rather than from the audit-repair loop the paper spends most of its analysis on. The retrieval-heavy "retrieval contraction" repair path is a hand-coded heuristic, not something the Planner discovers, which is a partially fixed (not fully learned) design element the paper doesn't foreground as a limitation.

**Reproducibility**: Extensive appendix material (system prompts for all three meta-agents, mutation operator table, deterministic guard table, agentic-loop hyperparameters) is a strong plus for reproducibility, but no repository/code link is evident in the read pages, and the process-anomaly taxonomy's LLM-side judgments (open-set flags beyond the fixed taxonomy) depend on prompting details that could be brittle across backbone changes.

**Significance**: If the token-efficiency and cross-domain transfer findings hold up under larger-scale replication, the framework offers a practically appealing alternative to expensive offline workflow search (AFlow/ADAS/AgentSquare each pay substantial offline search cost that MANTA avoids entirely). The magnitude of average gain (5.8 points) is modest but consistent, and the mechanistic case studies (Figures 3, 5, 6) make the repair behavior interpretable rather than a black box.

## Strengths

- Clear, well-motivated positioning against a taxonomy of prior self-improvement levels (Figure 1), making the contribution's novelty legible.
- Strong ablation and mutation-budget analyses that isolate which component (initial planning vs. repair vs. long-term memory) drives the gain.
- Token-usage accounting (Table 4) that fairly separates offline search cost from inference cost for baselines — a comparison axis many multi-agent papers omit.
- Concrete, qualitative repair case studies (branch expansion, serialization, verifier/critic insertion, debate rewiring) that make the abstract mechanism tangible.
- Transparent reporting of the Trace Auditor's imperfections (aggregate F1=0.47, wide per-benchmark variance) rather than presenting it as a solved sub-problem.

## Limitations

- Small per-benchmark sample size (30 questions × 3 runs) with substantial variance, limiting statistical confidence in benchmark-level rankings.
- Single backbone model (Gemma 4 31B) tested; no cross-model generalization evidence.
- MANTA underperforms strong baselines by large margins on WorkBench (vs. ADAS) and StableToolBench (vs. AgentSquare), and ties/loses on MATH — the "consistent advantage across every benchmark" framing in the abstract is only true relative to Single Agent, not relative to the best specialized baseline per benchmark.
- Trace Auditor recall is very low on PlanCraft and MATH (0.05 and 0.13), meaning the audit-repair loop — the paper's central mechanism — is largely inactive on two of five benchmarks.
- Repair does not guarantee correctness: only 69.5% of repaired runs produce a correct final answer, and a "clean" audit is explicitly acknowledged as a reliability signal, not a correctness guarantee (agents can agree on the same wrong answer with no observable anomaly).
- No human-annotated ground truth for the process-anomaly taxonomy itself; precision/recall figures use benchmark-answer-incorrectness as a proxy, which the authors flag as an imperfect substitute for true process-defect labels.

## Relevance

该工作与多智能体系统的架构自适应/自我改进方向高度相关，尤其对关注LLM智能体编排、拓扑搜索与推理时自我修复机制的研究者有参考价值；其"过程信号驱动、不触碰真值"的记忆设计思路也可能对可解释智能体审计和低监督在线学习方向有借鉴意义。

## Questions for Further Exploration

- Would MANTA's advantage persist with a stronger or differently-sized backbone (e.g., a frontier closed model or a much smaller open model), given all results here use one Gemma 4 31B configuration?
- Why is the Trace Auditor's recall so poor on PlanCraft and MATH — is this a taxonomy-coverage gap (the 11 fixed failure modes are tool/retrieval-centric) or a fundamental difficulty in detecting reasoning-only process defects from structured relay packets?
- How sensitive is performance to the hard caps (max 5 initial agents, 10 total, 1 mutation per run, ≤3 operations per mutation) — would relaxing the single-mutation-per-run constraint close the gap with ADAS on WorkBench?
- Could the long-term playbook's cross-domain transfer generalize beyond the PlanCraft/WorkBench pair tested, e.g., to genuinely different task families (open-domain QA, code generation)?
- What is the actual cost/benefit of the "retrieval contraction" deterministic shortcut versus letting the Planner discover an equivalent repair — does hand-coding this path limit MANTA's claim of learning topology-selection skill purely from experience?
