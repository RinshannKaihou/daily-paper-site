01 Claimed Contributions

What the document says it contributes — presented narratively, not derived from experiments below.

文档自称的贡献——均为陈述性表达，并非源于下文任何实验结果。

  • Sparse MoE backbone: 30B total / 3B active params per token, claimed 3.2x inference speedup and 45% memory reduction vs. dense models.
  • "Hierarchical attention" for 128K-token context (local-window attention + higher-level aggregation), claimed +18.7% accuracy / +23.4% recall over unnamed baselines.
  • Dual-mode reasoning: ReAct for simple tasks, "IterResearch" for up to 20 iterative steps with self-reflection, claimed +31.2% accuracy over single-pass baselines.
  • Unified multi-tool coordination layer (retrieval, calculator, web search, file parsing), claimed 92.1% tool-use accuracy.
  • GRPO-based RL with token-level credit assignment + seed-based data synthesis (claimed 92.5% usability), claimed +35% training stability, +42% faster convergence.
  • 稀疏 MoE 主干：每 token 总参数 300 亿 / 激活 30 亿，声称较稠密模型提速 3.2 倍、显存降低 45%。
  • 面向 128K 上下文的"分层注意力"（局部窗口注意力 + 高层聚合），声称较未命名基线提升 18.7% 准确率 / 23.4% 召回率。
  • 双模式推理：ReAct 处理简单任务，"IterResearch" 支持最多 20 步迭代反思，声称较单次推理基线提升 31.2% 准确率。

02 Methodology — a description, not a method

The system is written at the level of a component inventory rather than a reproducible specification.

  • MoE routing: "learned gating function" with load-balancing regularization named but not formalized.
  • Hierarchical attention: partitions 128K context into unspecified "local windows," conceptually similar to Longformer/BigBird (both cited) — but no window size or hierarchy depth given.
  • Dual-mode engine: ReAct + "IterResearch" (up to 20 steps) described narratively, with no interface schema or per-tool failure-rate breakdown.
  • Training: SFT on synthesized trajectories, then GRPO RL with token-level advantage — no equations, hyperparameters, or dataset size stated.

04 Document provenance & authorship

Why this reads as a filing, not a paper.

  • Authors listed only as "Yong Huang, Yulu Huang, et al." / "for the team Collaboration" — no institutional affiliation, contact email, or acknowledgments section, unusual even for a preprint.
  • The document's own subtitle identifies it as a "Software Copyright Research and Development Document" (软件著作权研发文档) — a Chinese genre used to accompany software copyright registration filings, written to a formulaic template and not subject to technical review.
  • The system description (30B-A3B MoE, ReAct + "IterResearch," GRPO training, HLE / BrowserComp-Chinese / WebWalkerQA benchmark triplet) closely parallels publicly known open-source Chinese deep-research agents — yet the document neither cites nor differentiates itself from that lineage despite reusing its naming and specs almost verbatim.
  • Claims the system is "fully open-sourced," but gives no repository URL, license, model/checkpoint name, or contact point anywhere — making the claim unverifiable from the document alone.

+ Strengths

  • The component checklist — sparse MoE, hierarchical long-context attention, dual-mode reasoning, unified tool interface, GRPO RL, automated data synthesis, memory/inference optimizations — is sensible and comprehensive, even though none of it is validated here.
  • Clear writing, organized into well-separated functional modules, making the intended design easy to follow at a conceptual level.

− Limitations

  • No experimental tables, baselines, ablations, or statistical validation for any of the ~15 quantitative claims in the document.
  • No architectural specifics (expert count, top-k, layer count, window sizes, training data volume, hardware) beyond the headline 30B/3B figure.
  • No author affiliations, no accessible code/model link despite an "open-sourced" claim, and a genre not subject to peer review.
  • Implausibly high HLE score relative to publicly documented state of the art, with no evaluation methodology disclosed.
  • Two of 10+ cited references could not be corroborated as real publications.

? Questions for Further Exploration

  1. What is the actual evaluation protocol behind the 87.3% HLE score (subset size, scoring rubric, trial count, tool access during evaluation)? Without this, the number cannot be trusted or compared.
  2. What are the concrete architectural hyperparameters (expert count, top-k routing value, layer count, local window size) needed to reproduce the system?
  3. How does this system relate to existing open-source 30B-A3B MoE deep-research agents using the same ReAct/iterative-research paradigm, GRPO training, and HLE/BrowserComp/WebWalkerQA suite — independent system, reimplementation, or repackaging?
  4. Is there an actual public code/model release matching the "fully open-sourced" claim, and if so, do independently reproduced numbers match those stated here?
  5. What ablation would isolate the individual contributions of hierarchical attention, IterResearch mode, and GRPO training, since all three are currently bundled into single aggregate percentages?
