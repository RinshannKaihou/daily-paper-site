> **一句话总结：** 论文把扩散模型的"加噪-去噪"范式搬到文本领域，把专业短剧剧本压缩成故事大纲当作"噪声"，让智能体从大纲重建剧本，再用另一个智能体对比重建稿与人类原稿写出"语义损失"，据此以类反向传播的方式更新一个 MoE 式的外部技能记忆库（而非模型权重），在六部留出小说上使可归档指标 7/9 项优于空记忆基线，部分指标（冷开场 84% vs. 基线 64% vs. 人类 72%、道具激活 78% vs. 59%）甚至超过人类均值。

> **TL;DR:** The authors reframe agentic skill acquisition as diffusion-style self-supervised learning: corrupt professional short-drama screenplays into terse outlines (noising), have a script agent reconstruct them with access to an external MoE-organized skill memory, contrast the reconstruction against the human original via an LLM "loss agent," and route that textual loss back into memory edits via a "backward agent" — all without human scoring or model weight updates. On six held-out novels (385 episodes/group), the memory-equipped agent beats a Base agent (same model, empty memory) on 7 of 9 metrics, e.g., unfilmable action lines drop from 1.1/episode (Base) to 0.3/episode (+Memory), matching the human baseline of 0.3 (Wasserstein distance 0.83 → 0.03), and cold-open rate rises from 64% (Base) to 84% (+Memory) against a 72% human reference.

## 核心贡献

- 提出了一个受扩散模型"腐蚀-重建"范式启发的**无监督自演化智能体框架**：用现成的高质量人类作品（专业短剧剧本）自动构造自监督训练对，无需人工标注技能或依赖不可靠的 LLM-as-judge 打分。
- 将神经网络训练的"前向-损失-反向"三段式映射到纯文本智能体流水线：前向生成（脚本智能体读记忆卡写剧本）、损失计算（损失智能体对比重建稿与人类原稿写出密集文本损失报告）、反向更新（反向智能体做信用分配，编辑外部技能库）。
- 设计了一个 Mixture-of-Experts 式的**紧凑记忆架构**：规则卡片被路由进"通用原则/具体技巧/类型惯例"三个专家文件夹，并由长度和格式的"linter"（相当于正则化）强制卡片精简，避免记忆无限膨胀、退化为逐个案例的记录。
- 提出**分层归约 + 序列化微步**的反向更新机制，类比梯度累积：多部小说的损失报告先分组归约成跨小说共性摘要，再拆成一系列小而聚焦的微步更新，避免单次更新信息过载导致"文本梯度消失"（编辑变得模糊笼统）。
- 通过留出小说评测、训练过程曲线、跨模型迁移（Sonnet 训练的记忆库直接套用在 Opus 上）、外部生产流水线接入四个角度系统验证了该记忆库的有效性和可迁移性。

## Key Contributions

- A **diffusion-inspired self-supervised framework** for unsupervised skill acquisition: high-quality human artifacts (professional short-drama screenplays) are corrupted into terse outlines, and the agent learns to "denoise" (reconstruct) them, generating free training signal without human skill annotation or unreliable LLM-as-judge scoring.
- A mapping of the standard neural-network training loop (forward → loss → backward) onto a purely textual, agentic pipeline: a **script agent** generates from an outline while reading external memory cards; a **loss agent** produces a dense textual "loss report" by contrasting the reconstruction against the human original; a **backward agent** performs credit assignment, editing the memory library rather than model weights.
- A **compact Mixture-of-Experts memory architecture**: rule cards are routed into three expert folders (general principles, craft techniques, genre conventions), with a hard token-budget "linter" acting as a regularizer to prevent unbounded memory growth and overfitting to single-episode detail (an uncapped pool ballooned to 148 cards / >500K tokens with a 2,500-line card).
- A **hierarchical-reduce, serialized micro-step** update scheme (analogous to gradient accumulation) that digests many novels' loss reports into condensed cross-novel summaries before applying small, traceable edits, avoiding "vanishing textual gradients" from overloaded single updates; also a data-parallel scaling scheme (forward generation parallel across novels, backward updates serialized into a micro-step queue) that turned a previously stalled, multi-hour orchestration into ~10-minute micro-steps.
- Empirical demonstration across four angles — held-out generalization, in-distribution training dynamics, cross-model transfer (Sonnet-trained memory applied unchanged to Opus), and deployment inside an unseen third-party production pipeline — showing the learned skill library is portable and model-agnostic.

## Methodology

The framework treats an external textual memory library as the agent's "trainable parameters," optimized via a corruption-and-reconstruction loop (Figure 1):

1. **Corruption (Section 3.1):** A corruption agent compresses each professional short-drama episode into a condensed outline chapter, stripping dialogue, physical actions, and pacing (analogous to the forward/noising process in diffusion models). Each (outline, original episode) pair becomes a free self-supervised training example.

2. **Forward script generation (Section 3.2):** Given an outline chapter, a script agent scans one-line descriptions of all memory cards, selects relevant ones, and writes the episode back into a full Hollywood-format screenplay. The "read trace" (which cards were consulted) is logged for later credit assignment.

3. **Semantic loss (Section 3.3):** Since token-level matching is meaningless for creative writing, a loss agent reads the reconstruction and the human original side-by-side and writes a dense textual loss report identifying where the human version is structurally or stylistically superior (e.g., where an episode ends, how a confrontation escalates). This report, anchored to a concrete human artifact rather than free-form LLM taste, functions as the self-supervised contrastive signal.

4. **Backward credit assignment (Section 3.4):** A backward agent acts as the optimizer, reading the loss report plus the read trace to edit the memory library: reinforcing cards that guided good output, narrowing overly broad cards that misled the agent, creating new cards for uncovered recurring mistakes, and merging redundant cards. Two design choices mirror ML practice: (a) hierarchical reduction of multiple novels' loss reports into condensed cross-novel summaries before any single update (like gradient accumulation), and (b) splitting one global update into small, traceable micro-steps rather than one monolithic digest (to avoid "vanishing" edits from information overload).

5. **Compact MoE memory (Section 3.5):** Rule cards are routed into three expert folders (general principles, craft techniques, genre conventions), with a "linter" enforcing hard length caps (ultimately 1,200 tokens per card body, 200 for its description) as a regularizer. Early unconstrained runs saw the pool balloon to 148 cards and >500K tokens, with individual cards growing to 2,500 lines or more — effectively overfit incident logs rather than generalizable rules. The final, properly regularized pool stabilizes at roughly 18–20 cards and ~20K tokens total.

6. **Data-parallel scaling (Section 3.6):** Forward generation and loss computation run in parallel across novels, while backward memory updates are serialized into a queue of short-lived, single-agent micro-steps (median ~10 minutes each) — a design correction after an initial long-lived multi-agent orchestrator burned 2+ hours per step and frequently timed out. Staleness (later micro-steps consuming loss reports computed against an older memory snapshot) is handled simply by instructing the backward agent to re-validate any suggested edit against the current pool before committing; the full 174-micro-step training run completed with zero failed updates.

Training corpus: twenty production-quality short-drama novels (49–70 episodes each, 1,127 episodes/epoch total), trained for 3 epochs, with all agents instantiated as Claude Sonnet 4.6. Evaluation uses six held-out novels never seen in training, generating every episode twice under identical conditions (empty memory = "Base" vs. trained pool attached = "+Memory"), with human originals as a third reference group (385 episodes per group). Nine metrics (Table 1) are used: five rule-based direct counts (e.g., longest dialogue volley, unfilmable action lines, voice-over cue density) computed by a zero-LLM parser, and four binary craft-discipline verdicts (hard-cut endings, redundant voice-over, cold opens, prop activation) judged by Gemini 3.1 Pro with quoted evidence — a different model family from the generator to reduce judge bias; re-judging a 16-episode subset with Claude Opus 4.8 reproduced 84% of verdicts.

## Results & Highlights

- **Unfilmable action lines (rule-based, six held-out novels, 385 eps/group):** Base agent 1.1 lines/episode → +Memory 0.3 lines/episode, essentially matching the human reference of 0.3; the 1-Wasserstein distance to the human distribution collapses from 0.83 (Base) to 0.03 (+Memory) — the largest distance compression among the five rule-based metrics (Table 2).
- **Cold-open rate (LLM-judged, Gemini 3.1 Pro):** Base 64% → +Memory 84%, versus a 72% human reference — the trained agent not only closes the gap but surpasses the human rate by 12.5 points (vs. Base's −7.2-point deficit).
- **Hard-cut ending rate:** Base 40% → +Memory 59%, closely approaching the 61% human rate (gap shrinks from −21.5pp to −1.7pp).
- **Prop activation rate:** Base 59% → +Memory 78%, exceeding the 70% human reference (Base was −11.2pp below human; +Memory is +7.5pp above).
- **Longest dialogue volley (turns/episode):** Base 4.5 → +Memory 4.3 vs. human 3.6 (distance 0.89 → 0.67); danger-scene line length: Base 4.9 words → +Memory 6.5 words vs. human 11.8 words (distance 6.85 → 5.26). Overall, +Memory outperforms Base on 7 of the 9 metrics.
- **Honest regression:** redundant voice-over incidence rises from 1% (Base) to 5% (+Memory) against a 0% human rate — traced to a single memory card that teaches when voice-over is effective but not when it should be omitted entirely; the paper reports this without hiding it.
- **Training dynamics (in-distribution, Figure 4):** across 3 epochs on the 20 training novels, dialogue-volley distance to human shrinks monotonically (0.94 → 0.71 → 0.37 Wasserstein-normalized), voice-over cues show an "overshoot-and-return" (0.25 → 0.64 → 0.40 against human 0.36), and stimulus words show zero statistically significant change across epochs (the only rule-based dimension without a dedicated memory card in the final pool).
- **Cross-model transfer (Figure 5):** a memory pool trained entirely on Sonnet 4.6 is attached unchanged to Claude Opus 4.8. Both models converge to nearly identical craft-discipline levels once equipped: hard-cut endings 59% (Sonnet) and 59% (Opus) vs. 61% human; cold opens 84% and 87% vs. 72% human; prop activation 78% and 79% vs. 70% human — while each model retains its own "temperament" on metrics not explicitly targeted by the pool (e.g., Opus's redundant-VO regression is larger, 1%→5%, than Sonnet's 0%→1%).
- **Regularization ablation (Figure 6):** an uncapped pool (148 cards, >500K tokens) over-suppresses stimulus words (1.6/episode, the lowest of any configuration) and costs ~3x more inference; a line-capped pool (75 cards, 25-line cap) collapses on rule-based metrics (5.2-turn volleys and 1.02 unfilmable lines, both worse than Base); only the token-capped production pool (18 cards, 1,200-token cap) improves simultaneously on both rule-based and judge-based metric families.
- **External production pipeline case study (Section 4.6, Appendix A.2):** re-running the first five episodes of an unseen third-party title, the memory-equipped agent ends 4/5 episodes on a hard cut at the climax (vs. the control extending scenes with 5 extra shots after the climax), and drops voice-over lines from 15 to 4 on the most VO-heavy episode. A documented failure case (Episode 5) shows the agent read only 3 of the available rule cards and missed the ending-rule card entirely, causing voice-over to climb to 17/21 lines and the episode to end on a static shot rather than an action beat — isolating retrieval failure (not the memory content) as the residual bottleneck.

## Critical Assessment

**Novelty:** The core idea — treating an external skill/memory library as "trainable parameters" and mapping forward/loss/backward stages onto multi-agent LLM calls — is a clever and fairly thorough analogy (going as far as textual "gradient accumulation," "vanishing gradient," and MoE-style expert routing for memory cards). It's a genuinely creative synthesis of existing pieces (TextGrad/ProTeGi-style textual gradients [15,16], skill libraries à la Voyager/ExpeL [9,10], MoE-style skill routing [17]) applied to a new self-supervised construction (contrasting against human originals rather than relying on LLM-as-judge scores or task rewards). That said, it is worth being clear-eyed that this is a *metaphor* for training, not literal differentiable optimization — "gradients" are prompted LLM-generated critiques, and "regularization" is a hand-set token/line limit enforced by a linter. The paper is transparent about this framing but readers should not mistake the ML vocabulary for formal guarantees (e.g., no convergence analysis, no formal loss function).

**Rigor:** The evaluation design is reasonably careful for a systems/agent paper: held-out novels never seen in training, episode-paired bootstrap 95% CIs for training-dynamics claims, a judge model from a different family than the generator (Gemini 3.1 Pro judging Claude-generated text) to reduce self-preference bias, and a cross-model transfer check. However, the judge-verdict reliability check is a real limitation the paper surfaces itself: re-judging a 16-episode subset with Claude Opus 4.8 reproduces only 84% of Gemini's verdicts, meaning roughly 1 in 6 binary craft judgments could flip under a different judge — this caps how much weight the ~5-15 percentage-point judge-metric deltas can bear. The nine evaluation metrics (Table 1) are also entirely custom-built by the authors (rule-based parser counts + LLM-judged binary criteria) rather than validated against an established screenplay benchmark; the paper argues existing benchmarks (e.g., CML-Bench [34]) target feature-film aesthetics that are "orthogonal, and sometimes opposite" to vertical short-drama norms, which is a defensible argument but means the metrics' external validity is asserted rather than independently verified.

**Reproducibility:** The training corpus (twenty proprietary professional short-drama screenplays) and the external production pipeline used for the Section 4.6 case study are both non-public, industry-sourced artifacts, so independent replication of the exact numbers is not currently possible; the authors state they will open-source the framework and "representative memory examples," but the underlying screenplay corpus itself likely cannot be released. All experiments also use closed-source, prompt-orchestrated agents (Claude Sonnet 4.6 / Opus 4.8) rather than open-weight models, so cost and exact behavior may not transfer to other backends.

**Significance / red flags:** The paper is commendably honest about a real regression (redundant voice-over: 1%→5%, worse than Base's already-nonzero rate) and about a documented retrieval failure case (Episode 5, where the agent simply failed to read the relevant rule card) — this kind of failure-mode transparency is stronger than most agent papers. The main weak point is the absence of any comparison against alternative continual-learning/skill-library baselines that the related-work section itself cites as directly comparable (e.g., Reflexion, ExpeL, Voyager-style skill libraries, or the concurrently cited Skillopt/Skillgrad line of work) — the only baseline is "same model, empty memory," which isolates the effect of *having* memory but not whether this particular corruption-and-reconstruction acquisition method is better than simpler alternatives (e.g., directly summarizing expert critiques of the agent's own past outputs without the corruption/outline step). The domain is also narrow (one genre, one language/production style, one company's internal corpus), so generalization claims to "creative writing" broadly should be read cautiously.

## Strengths

- Elegant, well-motivated mapping of the standard supervised-training loop onto a fully textual, gradient-free agentic pipeline, with the corruption/reconstruction step providing a genuinely free (no human labeling) self-supervised signal anchored to real human artifacts rather than LLM self-judgment.
- Careful empirical ablation of the memory regularization mechanism (Figure 6: uncapped vs. line-capped vs. token-capped pools) that isolates *why* naive unbounded memory growth or naive line limits fail, and shows the chosen token-cap design is not arbitrary.
- Demonstrated cross-model transferability (Sonnet-trained pool → Opus, converging to near-identical craft-discipline levels) and successful deployment inside an entirely separate, previously-unseen third-party production pipeline — evidence the learned "skills" are genuinely externalized rather than overfit to one agent instantiation.
- Unusually candid failure analysis (the Episode 5 case study explicitly attributes a bad output to a retrieval miss, not a memory-content flaw), which strengthens rather than undermines the paper's credibility.

## Limitations

- No baseline comparison against other textual skill-acquisition/continual-learning methods (Reflexion, ExpeL, Voyager, or the cited Skillopt/Skillgrad approaches) — only against a no-memory Base agent.
- Judge-verdict reliability is modest (84% agreement between Gemini 3.1 Pro and Claude Opus 4.8 on a 16-episode re-judged subset), which bounds confidence in the magnitude of the four LLM-judged craft-discipline deltas.
- Training and evaluation are confined to a single niche genre (vertical short-drama screenwriting) using a proprietary, non-public corpus, limiting both reproducibility and generalization claims to other creative-writing domains.
- The method introduces a real regression on one metric (redundant voice-over), and the paper's own stated future work acknowledges two unresolved structural bottlenecks: the base model's capacity to actually follow multi-instruction memory (updating text yields no behavioral change if the agent ignores it), and unreliable retrieval (a rule that is never read cannot fire), the latter directly demonstrated in the Episode 5 failure case.
- All experiments rely on closed-source frontier models (Claude Sonnet 4.6, Opus 4.8) as both agents and judges; behavior on open-weight or smaller models is untested.

## Relevance

该工作提供了一个不依赖人工标注或权重访问的、面向闭源大模型的持续学习范式，对研究"外部技能记忆库"设计（MoE 式路由、正则化、类反向传播的信用分配）和自监督信号构造（对比人类原始作品而非 LLM 打分）的方向有直接参考价值，其"对比真实高质量人类产出以获得可靠训练信号"的思路可能可迁移到其他缺乏可验证奖励的开放式生成任务。

## Questions for Further Exploration

- How does this corruption-and-reconstruction acquisition method compare quantitatively against simpler skill-library baselines (e.g., ExpeL-style reflection on the agent's own past failures, or Voyager-style skill accumulation) on the same short-drama task and metrics?
- Would the retrieval bottleneck identified in the Episode 5 case study (rules that exist but aren't read) be better addressed by changing the read-trace/routing mechanism itself, or does it require a different memory representation entirely (e.g., embedding-based retrieval instead of one-line description scanning)?
- How sensitive are the reported gains to the choice of judge model — would a third judge family (e.g., GPT) corroborate the 84% agreement rate found between Gemini 3.1 Pro and Claude Opus 4.8, or reveal further judge-specific bias?
- Does the corruption granularity (how much detail is stripped when compressing a screenplay into an outline) meaningfully affect what skills get extracted, analogous to noise-schedule choices in image diffusion models?
- Can the same framework generalize beyond short-drama screenwriting to other domains with abundant high-quality human artifacts but no natural reward signal (e.g., technical writing, game level design, or long-form fiction), and would the same MoE folder structure (general/craft/genre) transfer, or would domain-specific expert categories be needed?
