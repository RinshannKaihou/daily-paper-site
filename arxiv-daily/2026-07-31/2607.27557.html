Why This Matters

Offers closed-source LLM agents a way to keep improving through an editable text memory — no fine-tuning, no human-labeled scores.

Critical Edge
Read Before You Trust The Deltas

Re-judging a 16-episode subset with a different model (Claude Opus 4.8) reproduced only 84% of the original judge's (Gemini 3.1 Pro) verdicts — roughly 1 in 6 craft-quality calls could flip under a different judge.

Methodology

Corrupt, reconstruct, critique, edit

outline (noise)→ script agent→ loss agent→ backward agent→ memory edit

The paper treats an external text file — not model weights — as the trainable object. Professional short-drama episodes are corrupted into terse outlines (the "noising" step, echoing diffusion models); a script agent then reconstructs full screenplays from the outline while consulting a library of rule cards, logging which cards it read. A loss agent compares the reconstruction to the real human episode and writes a dense textual "loss report" — no numeric score, no LLM-as-judge rubric, just concrete critique anchored to a real artifact. A backward agent uses that report plus the read-trace to edit the library: reinforcing helpful cards, narrowing misleading ones, creating new ones, merging duplicates.

Two ML habits are borrowed directly: loss reports from multiple novels are hierarchically reduced before editing (like gradient accumulation), and edits ship as small serialized micro-steps rather than one giant update, to avoid edits going vague ("vanishing textual gradients"). Cards are routed into three MoE-style folders — general principles, craft techniques, genre conventions — under a hard token-budget linter.

Regularization matters: an uncapped pool ballooned to 148 cards / >500K tokens (one card ran 2,500 lines) before the token-capped design settled at ~18–20 cards / ~20K tokens — the only setup that improved both rule-based and judge-based metrics at once (Fig. 6 ablation).

Cross-model transfer (Fig. 5): a Sonnet-4.6-trained pool applied unchanged to Opus 4.8 converges to nearly identical craft levels (cold opens 84% vs. 87%; prop activation 78% vs. 79%) — the skills travel with the memory file, not the model.

External pipeline case study: re-running an unseen third-party title, the memory-equipped agent hit a hard cut at the climax in 4/5 episodes and cut voice-over lines from 15 to 4 on the heaviest episode — except Episode 5, where the agent read only 3 of the available cards and missed the ending rule entirely, isolating retrieval (not memory content) as the residual bottleneck.

Strengths

  • Corruption/reconstruction against real human artifacts gives a genuinely free self-supervised signal — no human labeling, no LLM-as-judge scoring to train on.
  • Regularization ablation (uncapped vs. line-capped vs. token-capped) shows why naive memory growth or naive line limits fail, not just that the chosen design works.
  • Cross-model transfer and third-party deployment demonstrate the learned skills are externalized, not overfit to one model instance.
  • Unusually candid failure analysis — the Episode 5 retrieval miss is reported as a memory-content non-issue, strengthening rather than undermining the paper.

Limitations

  • No baseline against other skill-acquisition methods (Reflexion, ExpeL, Voyager) — only vs. a no-memory Base agent.
  • Judge agreement is modest: 84% between Gemini 3.1 Pro and Claude Opus 4.8 on re-judged episodes.
  • Training/eval confined to one niche genre on a proprietary, non-public screenplay corpus.
  • Introduces a real regression (redundant voice-over 1%→5%); retrieval and instruction-following remain open bottlenecks.
  • All agents and judges are closed-source frontier models; open-weight behavior is untested.

Questions for Further Exploration

  1. How does corruption-and-reconstruction compare quantitatively against simpler baselines like ExpeL-style reflection or Voyager-style skill accumulation, on the same task?
  2. Is the retrieval bottleneck (cards that exist but aren't read) better fixed by changing the routing mechanism, or does it need embedding-based retrieval instead of one-line description scanning?
  3. Would a third judge family (e.g., GPT) corroborate the 84% Gemini–Opus agreement rate, or reveal further judge-specific bias?
  4. Does corruption granularity (how much detail is stripped into the outline) shape which skills get extracted, analogous to noise-schedule choices in image diffusion?
  5. Does the same MoE folder structure (general/craft/genre) transfer to other high-artifact, no-reward domains like technical writing or game level design?
