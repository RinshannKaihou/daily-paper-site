> **一句话总结：** Albilich 用一个持久化的 SQLite "证明状态"数据库（含 claim/route/inference 图、债务台账、补丁式受控更新）取代线性的 LLM 数学研究流程，配合角色分权验证（研究者无权自我认证）、CAS 与文献检索 MCP 工具，以及可按需介入的 PhD-advisor 角色；在 RealMath Math_arXiv 十题上全部达到内部 solved_final（9/10 经人工核对无误），并在 Kourovka Notebook 21.142 题上给出一个（内部认证的）反例，同时消融显示启用 CAS 可减少 32.0% 的 token 消耗（Problem 17.91，6.784M vs 9.982M tokens），启用 advisor 角色可在更少算力（6.81h vs 10.44h，即所需时间约为不启用时的 1/1.53）下把该问题从"未解决"变为"已解决"。

> **TL;DR:** Albilich is an agentic math-research harness built around a versioned SQLite proof-state (claims, routes, inferences, a debt ledger, source/CAS artifact stores) with role-separated authority — only a Strict Verifier, Integration Verifier, and Counterexample Validator can change mathematical status, never the researcher agents themselves. On the RealMath Math_arXiv subset (10 problems), all 10 runs reached the system's internal solved_final state with CAS enabled, and human review confirmed 9/10 as clear matches to the reference (Problem 08's convolution-formula equivalence stayed unresolved). On Kourovka Notebook Problem 17.91, an ablation shows CAS availability cuts gross token use by 32.0% (6.784M vs. 9.982M tokens, with the drop concentrated in input tokens) without either condition solving the root problem. On Problem 21.142, a matched-model ablation shows the PhD-advisor role turns an otherwise-unsolved run (110 child sessions, 10.44h compute, 54.9M raw tokens, 0 root-concluding routes) into a solved one (80 sessions, 6.81h compute, 29.7M raw tokens, 1 integrated route) — even though the advisor-off run paradoxically produced more verified local claims (18 vs. 10).

## 核心贡献

- **持久化 SQLite 证明状态**：将证明尝试表示为带版本的图 St = (q⋆, Gt, Dt, Lt, At, Pt, Ht, Mt)，保留 claim/route/inference 及其依赖边，同时维护债务台账（未解决的空缺/缺失假设）、文献库、CAS/证明工件库、已接受补丁与状态转移历史；即使是被拒绝/被取代的对象也保留在事件溯源历史中，而非直接丢弃。
- **角色分权 + 补丁式受控更新**：Researcher、Adversarial Researcher、Literature Researcher、PhD Advisor 均无权改变数学状态（Authority: None），只能提交结构化补丁 π=(ρ,b,X,Ω,η)；只有 Strict Verifier（Verify）、Integration Verifier（Integrate）、Counterexample Validator（Refute）三种角色能真正改变 claim/route 的合法性，从而杜绝"自证自明"。
- **局部验证与整体整合分离**：局部验证只确认单条 claim/inference 本身成立，不代表它对根命题 q⋆ 有贡献；只有 Integration Verifier 才能判定一条 route 是否构成通向 q⋆ 的完整证明（含 exact/equivalent/stronger 关系判定），且当依赖项发生变化时会自动触发对已整合 route 的重新核查（reconciliation）。
- **CAS 与文献检索的 MCP 化**：通过 MCP server 异步调度 SageMath/GAP/Macaulay2/Singular 四种后端，工件记录问题范围、代码、输出与后端版本，但验证者并不重新执行计算，因此 CAS 支持的结论只具有其记录副本（transcript）的可信度；文献工具（TheoremSearch、Matlas）检索结果仅作为线索，需由 Literature Researcher 核对原始出处、假设匹配与记号转换后才能被验证者采信。
- **实证结果**：在 RealMath 十题上全部达到 solved_final；在 Kourovka Notebook 21.142 题上得到一个反例（对某些 p、q 及 m≥9，交错群 Am 不能嵌入任何以 p、q 阶元素不变生成的有限群），在 20.2 题上给出显式见证 G=PSL2(7)，并将后续研究推进到 PSLn(q) 族几乎完整的分类（仅 PSLn(2), n≥5 未决）。

## Key Contributions

- **Persistent SQLite proof-state architecture**: represents a proof attempt as a versioned graph St = (q⋆, Gt, Dt, Lt, At, Pt, Ht, Mt) with typed claims/routes/inferences and dependency edges, plus a debt ledger, literature library, artifact store, accepted-patch record, and state-transition history — rejected and superseded objects remain in an event-sourced history rather than being discarded (Table 1 claims this is unique relative to Danus, QED, and ProofCouncil).
- **Role-authorized, patch-only state transitions**: research roles (Researcher, Adversarial Researcher, Literature Researcher, PhD Advisor) hold zero authority to change mathematical status; they submit a structured patch π=(ρ,b,X,Ω,η) that is validated (role authorization, base-revision compatibility, schema, evidence) and applied atomically (Eq. 2–3), preventing an agent from certifying its own argument.
- **Local verification vs. root-level integration separation**: a Strict Verifier can mark a bounded claim `informally_verified`, but only a separate Integration Verifier can mark a route `integrated`, requiring every premise in the dependency closure to be verified, no blocking debt, and an explicit exact/equivalent/stronger relation to the immutable root q⋆; integrated routes are automatically reopened (reconciliation) if a dependency later changes.
- **MCP-mediated CAS and literature tools**: asynchronous CAS sessions route to SageMath, GAP, Macaulay2, or Singular under concurrency/timeout/output-size caps, with artifacts recording code, output, and backend version — the verifier trusts but does not re-execute the transcript; literature retrieval (TheoremSearch, Matlas) is treated as an unverified lead until a Literature Researcher records the primary-source statement, hypotheses, and required implication.
- **PhD-advisor role for test-time scaling**: a long-horizon planning role, invoked after stalls or repeated rejections, that can propose reductions, reprioritize routes, or reallocate budget but cannot itself verify, refute, or integrate anything — isolating "strategic steering" from "mathematical acceptance."
- Two Kourovka Notebook problems were attacked end-to-end: a reported counterexample to Problem 21.142 and an explicit witness (G=PSL2(7)) for Problem 20.2, plus a follow-on near-complete classification for PSLn(q) families (PSL2(q), PSL3(q), PSL4(q) resolved; only PSLn(2), n≥5 open).

## Methodology

Albilich frames a proof attempt as a shared, versioned SQLite database rather than a linear chat transcript. The canonical state St bundles the immutable root statement q⋆ with a proof graph Gt=(Ct∪Rt∪It, Γt) of claims, routes, and inferences connected by typed dependency edges, alongside a debt ledger Dt (open gaps/missing hypotheses), a literature library Lt, an artifact store At (proof arguments, source adaptations, CAS outputs, verification reports), accepted patches Pt, state-transition history Ht, and resource measurements Mt.

Nine roles interact with this state under strict authority boundaries (Table 2): Researcher, Adversarial Researcher, Literature Researcher, and PhD Advisor can propose but never certify; Strict Verifier (`Verify`), Integration Verifier (`Integrate`), and Counterexample Validator (`Refute`) are the only roles that can change mathematical status; Writer and Scheduler have no mathematical authority at all. A session never edits the database directly — it receives a snapshot at revision b (its assigned target, dependency subgraph, active debts, and relevant evidence, with older history omitted to bound prompt size) and returns a patch π=(ρ,b,X,Ω,η) specifying the submitting role, base revision, affected objects, requested operations, and supporting evidence. The transition St+1 = Apply(St,π) if Valid(St,π), else LogReject(St,π) is atomic; invalid patches are rejected but recorded in the event history, and patches based on a stale revision must be regenerated if their dependency closure changed.

Verification is two-tiered: local verification checks a single claim/inference's premises, quantifiers, hypothesis propagation, and any source/CAS interfaces, but establishes nothing about relevance to q⋆; route integration separately checks that a chain of locally-verified claims/inferences forms a sufficient, debt-free route to q⋆, with the type of conclusion (exact/equivalent/stronger) recorded explicitly. Reconciliation automatically reopens an integrated route if any dependency's status later changes.

A rule-based deterministic scheduler selects the next obligation (unproved premise, unchecked inference, open debt, claim awaiting verification, route awaiting integration) using a priority function that favors obligations blocking an active root route, accounts for parallel-session collisions, and draws research/verification budgets from separate pools so speculative search cannot starve verification. The PhD Advisor is invoked on stalls (a configured number of steps without root-relevant progress, repeated rejection of the same inference, several routes hitting the same debt, or a refuted central claim) and may propose reductions, reprioritize routes, pause branches, or set budgets — decisions recorded as planning history but with no verification/integration authority.

Two MCP tool families are exposed: (1) CAS access to SageMath, GAP, Macaulay2, and Singular, run asynchronously under per-session concurrency caps, timeouts, and output-size limits, with artifacts recording the mathematical question, scope, exact code, output, and backend version — critically, the Strict Verifier reads this artifact but does not re-execute the computation, so trust rests on the transcript, and a finite computation can only establish explicitly finite claims/counterexamples, not universal statements, without a separate covering argument; (2) literature retrieval via TheoremSearch and Matlas, treated purely as retrieval aids until a Literature Researcher records the exact theorem statement, its primary-source location, hypotheses, notational translation, and the implication needed by the current proof.

All reported experiments use a fictively-versioned model, `gpt-5.6-sol`, with `xhigh` reasoning effort, and compare matched configurations (same problem statement, model, reasoning effort, budgets) that differ only in the single ablated factor (CAS availability or advisor availability).

## Results & Highlights

- **RealMath benchmark (Math_arXiv subset, CAS enabled)**: all 10/10 attempts reached Albilich's internal `solved_final` state, using ~28.10M gross tokens total; human comparison against supplied references found 9/10 clear matches, with Problem 08's Albilich-derived convolution formula left unresolved against the reference expression. (Note: the abstract additionally states "9/10 with no CAS" for RealMath, but the body/tables provided do not report a separate no-CAS RealMath experiment — this claim is not traceable to a table in the visible text.)
- **CAS ablation (Kourovka Problem 17.91, Table 4)**: two matched one-hour, 20-child-session runs. CAS-on used 6.590M input + 0.194M output = 6.784M total tokens; CAS-off used 9.787M input + 0.195M output = 9.982M total tokens — a **32.0% reduction in gross tokens** concentrated almost entirely in input tokens (output tokens nearly unchanged: 0.194M vs 0.195M). Backend compute time was comparable (5244.145s vs 5410.717s). **Neither condition solved the root problem** — both reached only "certified partial."
- **PhD-advisor ablation (Kourovka Problem 21.142, Table 5)**: advisor-enabled run: 80 child sessions, 6.81h active compute, 29.7M raw / 6.00M charged tokens, 11 total/10 verified claims, 1% patch-rejection rate, **root solved with 1 integrated route**. Advisor-disabled run: 110 child sessions, 10.44h active compute (1.53× the advisor-on solve time), 54.9M raw / 9.67M charged tokens (1.85× raw, 1.61× charged), 20 total/18 verified claims, 8% patch-rejection rate, **root unsolved at stopping point** despite 16 integrated routes and more verified claims than the advisor-on run — none of those routes concluded the root.
- **Kourovka Problem 21.142 case study**: Albilich reported and internally certified a negative answer — for some m≥9 (depending on primes p,q), the alternating group Am cannot embed into any finite group invariably generated by elements of orders p and q. The accepted route used 80 child sessions, 5h51m lifecycle time, 6.81h active backend compute, 29,684,464 gross tokens, with 10 of 11 claims verified and one root-concluding route integrated.
- **Kourovka Problem 20.2 case study**: certified explicit witness G=PSL2(7) answering whether a nonabelian simple group of Lie type can be totally 3-closed. Advisor-on run: 23 sessions, 1h16m, 6,714,757 tokens, produced a theory-based direct argument. Advisor-off run: 18 sessions, 1h47m (~31 min longer), 6,306,998 tokens, reached the *same* witness but via an exhaustive GAP computational certificate rather than a conceptual argument — illustrating the advisor's effect on proof *character*, not just speed.
- **Follow-on classification**: further Albilich-assisted runs extended Problem 20.2 toward an almost-complete family-level classification for PSLn(q), resolving PSL2(q), PSL3(q), and PSL4(q) and establishing broad higher-rank obstructions, leaving only PSLn(2) for n≥5 open.
- **Anecdotal broader trials (explicitly not counted as benchmark results)**: solved 2/3 master's/early-PhD-level group theory and representation theory problems (repairing a gap in one associated paper), failed on a codegree-set construction problem (brute-force search performed poorly) and an open character-vertex problem (only preliminary ideas), and in paper-audit trials correctly identified a known flaw in a published argument, though some review comments on undergraduate drafts were "overly scrupulous."

## Authors & Credibility

Ting Gong and Michael Ruofan Zeng (University of Washington, UW Math AI Lab) and Yong Yang (Texas State University). The acknowledgements describe informal internal testing (advisor's interest, several named individuals testing the program) and note the project is affiliated with a math-focused AI lab, suggesting genuine domain expertise, but there is no indication of external mathematical peer review of the Kourovka claims beyond what is described in the paper itself. The paper states results were internally certified by Albilich's own verifier roles and separately reviewed by the authors ("verified by human experts" per the abstract), but the body text does not name independent group-theory referees or describe an external verification protocol for the 21.142 counterexample or the 20.2 witness — the strongest available evidence is the paper's own internal audit trail (proof dossiers, GAP certificates, debt ledgers) rather than a third-party confirmation.

## Critical Assessment

**Novelty**: The core architectural idea — a persistent, event-sourced SQLite proof state with an explicit debt ledger, role-authorized state transitions (research roles have zero authority; only three checker roles can change mathematical status), and automatic reconciliation when dependencies change — is a genuinely distinguishing design choice versus the concurrently-cited Danus, QED, and ProofCouncil systems (Table 1 makes this comparison explicit, and Albilich is reasonably careful to state exactly where it differs, e.g., retaining rejected/subsumed claims and separating local vs. root integration checks). The PhD-advisor-as-non-authoritative-planner role is a sensible design pattern that cleanly separates "strategic advice" from "acceptance," addressing a real failure mode (an agent grading its own homework) that plagues naive proof-search loops.

**Rigor**: The two ablations that carry the paper's central quantitative claims (CAS token reduction, advisor effect) are each based on a **single paired run per condition** on a **single problem** (17.91 for CAS; 21.142 for advisor). Given the paper's own statement that "the model output produced by the selected session remains stochastic," a sample size of n=1 per arm cannot separate a genuine architectural effect from run-to-run variance — the paper appropriately hedges this as "preliminary evidence" rather than a definitive claim, which is honest, but the headline 32.0% and 1.53×/1.85×/1.61× figures should not be over-interpreted as robust effect sizes. There is also a discrepancy between the abstract's claim of "9/10 [solved] with no CAS" on RealMath and the body/tables, which only report a single CAS-enabled RealMath run (10/10 solved_final, 9/10 human-confirmed) — the no-CAS RealMath condition referenced in the abstract is not traceable to any table or paragraph in the paper as provided.

**Reproducibility**: The CAS verifier explicitly does *not* re-execute the recorded computation ("the verifier does not independently rerun the computation... acceptance of the mathematical conclusion still depends on verification of the reduction to the reported computation"), so a CAS-backed claim's soundness rests on trusting a transcript rather than an independently checkable artifact — a real, self-acknowledged limitation. The paper promises an MCP server release "in accordance with the release of this paper" but no repository or artifact link appears in the visible text, so the harness itself is not yet independently verifiable by outside readers. All experiments run on `gpt-5.6-sol`, a model version not otherwise documented or externally available, which further limits third-party reproduction.

**Significance**: If the Kourovka Problem 21.142 counterexample and the PSLn(q) classification program hold up under independent mathematical scrutiny, this would be a genuinely notable result for AI-assisted research mathematics — most competing systems in this space (Aletheia, QED, AI Co-Mathematician, ProofCouncil) are cited only for architecture comparison, with no head-to-head benchmark numbers against Albilich on the same problems, so Albilich's claimed advantages (Table 1 feature checklist) are argued qualitatively rather than empirically demonstrated against those specific systems.

**Red flags**: (1) No external baseline comparison — despite an extensive Related Work section naming five directly competing 2026 systems, none are run on RealMath or the Kourovka problems for a head-to-head score; the only "baselines" are Albilich's own ablated variants. (2) The internal `solved_final`/`informally_verified` status is explicitly self-graded by the system's own verifier roles, and the paper is careful to flag that "internal informal verification remains distinct from formal verification, independent peer review, and external benchmark grading" — but this means the paper's most striking claim (a new counterexample to an open Kourovka problem) rests on the system's own audit trail rather than confirmed peer review. (3) Single-run ablations for both headline efficiency claims (CAS, advisor).

## Strengths

- Clear, principled separation of proposal/verification/integration authority that directly targets a known failure mode in agentic theorem proving (self-certification).
- Explicit, inspectable debt ledger and event-sourced history (including rejected/superseded objects) give genuine auditability that many competing systems lack per the paper's own comparison table.
- Honest hedging throughout: results are repeatedly called "preliminary," anecdotal trials are explicitly excluded from benchmark claims, and the CAS/literature trust boundaries (verifier does not re-execute CAS, retrieved theorems are untrusted until sourced) are stated plainly rather than glossed over.
- Concrete, named mathematical case studies (Kourovka 21.142, 20.2) with detailed compute/token/session accounting rather than only aggregate benchmark scores.

## Limitations

- Both key ablations (CAS token savings, advisor effect on solve rate) are single paired runs on single problems, with no repeated trials to quantify variance given acknowledged run-to-run stochasticity.
- No head-to-head comparison against the five explicitly-cited competing systems (Danus, QED, ProofCouncil, Aletheia, AI Co-Mathematician) on shared benchmarks.
- CAS-backed claims are only as trustworthy as an unexecuted transcript — the verifier does not independently rerun computations.
- Internal verification (`informally_verified`, `solved_final`) is distinct from formal (e.g., Lean-checked) verification, which the paper defers entirely to future work.
- The RealMath evaluation is a 10-problem convenience sample explicitly stated not to estimate full-benchmark performance, and Problem 08's correctness remains genuinely unresolved even under the paper's own review.
- The abstract's claim of a 9/10 no-CAS RealMath result is not substantiated by any table or discussion in the body of the paper.

## Relevance

该工作与 LLM 智能体做长程数学研究、多智能体状态管理和工具增强推理（CAS/文献检索 MCP 集成）密切相关，其角色分权验证与债务台账设计为构建可审计、可人工干预的自动化研究系统提供了具体可借鉴的架构范式。

## Questions for Further Exploration

- Would the 32.0% CAS token-reduction and the advisor's solve-rate improvement replicate across multiple problems and multiple stochastic runs per condition, rather than one paired run each?
- How would Albilich's RealMath and Kourovka results compare directly against Danus, QED, ProofCouncil, or Aletheia run on the identical problems under matched compute budgets?
- What would change if the Strict Verifier were required to independently re-execute CAS computations rather than trusting the recorded transcript — how often would that catch errors?
- Has the reported Kourovka Problem 21.142 counterexample and the PSLn(q) classification program undergone (or will they undergo) independent review by group theorists outside the author team, and will the underlying proof artifacts be released for public scrutiny?
- How sensitive is the debt-ledger/reconciliation mechanism to adversarial or buggy patches that pass schema validation but encode subtly incorrect mathematics — does the strict verifier catch these reliably in practice?
