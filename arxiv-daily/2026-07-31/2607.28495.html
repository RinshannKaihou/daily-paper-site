Stage-Replay Divergence Follows the KV Cache: Fixed-Prefix Precision Controls and Bidirectional Cache Transplantation ↗ arXiv:2607.28495

Fresh-prefill token prefixes aren't equivalent to live KV-cache state — the cache itself causally drives divergent reasoning trajectories.

Divergent continuations that fully followed their transplanted KV-cache donor after all 48 key/value layers were swapped — first at the primary checkpoint, then in a blind replication on a later checkpoint. 0/8 and 5/48 exact-match controls flipped.

Why This Matters

If you reconstruct intermediate LLM states via prefill for counterfactual analysis or distillation, the reconstruction can silently diverge from the true decoder state — and numerical precision decides whether you'd notice.

Critical Edge

The core cache-divergence phenomenon itself isn't new (credited to prior work), the underlying custom 14B checkpoint isn't public so nobody outside the author can rerun the core experiment, and jointly swapping all 48 key+value layers can't isolate which specific layer or tensor actually drives the divergence.

Methodology

The test bed is a Qwen2.5-14B-Instruct derivative fine-tuned for a three-branch generate → merge → answer reasoning pipeline. The object of study is decoder state right after the <|merge|> boundary token — a whole-reasoning-stage boundary, not a mid-sequence token.

Three cache constructions are kept strictly separate: live (retained from ordinary autoregressive generation), incremental (rebuilt token-by-token under teacher forcing), and prefill (built in a single forward call). A replica measures the within-construction noise floor.

Five experiments run on a frozen 200-item GPQA Main holdout (greedy decoding, HF Transformers + PyTorch SDPA, single NVIDIA B200): (1) matched live-vs-prefill fidelity in BF16, (2) the same 200 fixed token prefixes crossed against BF16 vs. FP32 arithmetic, (3) a 12-row live-to-incremental validation, (4) bidirectional 48-layer KV-cache transplantation between constructions, and (5) an outcome-blind replication on 48 rows from a distinct, later checkpoint. Wilson intervals, 20,000-replicate paired bootstrap, and exact McNemar tests back every comparison; the analysis plan was frozen before the full runs.

Strengths

  • Clean separation of four otherwise-conflated concepts — replica stability, token identity, live-state fidelity, causal sufficiency — into one reusable measurement protocol.
  • Direct causal intervention (KV transplantation) rather than only correlation, replicated blind on an independent later checkpoint (43/43) to rule out cherry-picking.
  • Pre-registered statistics (Wilson, bootstrap, McNemar) throughout, with explicit self-downgrading when a result narrowly misses its own registered threshold (5 vs. 6 exact controls).
  • Precision-crossing design (BF16 vs. FP32 on identical fixed prefixes) cleanly isolates numerical precision as a moderating variable rather than a confound.

Limitations

  • Single custom Qwen2.5-14B-derived multi-branch checkpoint (two checkpoints, same training family) — no architecture, task, or sampling-temperature diversity.
  • One benchmark only: GPQA Main, 200-item frozen holdout, itself pre-selected via an undisclosed earlier "breadth screen."
  • Neither arm uses a certified batch-invariant kernel, so the causal path from precision to divergence isn't traced to a specific reduction-order or kernel mechanism.
  • Keys and values are swapped jointly across all 48 layers — no per-layer or key-vs-value ablation to localize the effect.
  • The custom fine-tuned checkpoint and prompts aren't publicly released, so independent end-to-end reproduction is impossible — only the released digests and statistics can be audited.

Questions for Further Exploration

  • Would per-layer or key-only/value-only transplantation localize the divergence to fewer than all 48 layers?
  • Does the same divergence pattern hold under a certified batch-invariant kernel, given the paper's own 10-prompt side-check showed partial sensitivity even there?
  • What was the actual magnitude of the training-conclusion error that motivated this audit — was the "late merge-conversion barrier" claim false, or merely unverifiable?
  • Would the 83pp BF16 suffix-divergence rate reproduce on other model families or on mid-sequence, non-reasoning-boundary tokens?
  • With only 5/48 rows naturally exact in Experiment 5 (short of the pre-registered 6), would a larger blind panel move the exact-control recovery estimate away from its current wide interval?
