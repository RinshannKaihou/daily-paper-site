> **一句话总结：** SKILL-KD 通过对比同一任务下学生失败轨迹与教师成功轨迹之间的行为差异，将差异蒸馏成可迭代验证的文本技能补丁，并用带溯源的编辑历史做"防漂移"整合，在五个智能体基准上把 Qwen3.5-4B 从 43.5 提升到 66.8（平均分），且规则数仅 38 条。

> **TL;DR:** SKILL-KD reframes skill acquisition for frozen LLM agents as contrastive knowledge distillation: instead of summarizing a student's own trajectory or a teacher's demonstration in isolation, it diffs a student failure against a same-task teacher success, turns the actionable gap into a textual skill patch, validates the patch by re-running the student (up to n=3 rounds), and consolidates patches into a compact global skill library using trace-linked edit histories to avoid "skill drift." On five benchmarks (SearchQA, SpreadsheetBench, DocVQA, LiveMath, ALFWorld) with Qwen3.5-4B as student and Qwen3.7-plus as teacher, SKILL-KD reaches an average score of 66.8 vs. 43.5 for No-Skill and 63.5 for the strongest baseline SkillOpt — including a +56.0 point jump on ALFWorld (30.6 → 86.6) using only 38 total rules, roughly half the library size of the best ablation variant.

## 核心贡献

- **将技能定义为教师-学生之间的对比蒸馏媒介**：不是把技能当作经验摘要或记忆条目，而是显式比较"学生失败轨迹"与"同任务教师轨迹"之间的行为差异，把这个差异作为可迁移的学习信号（学生模型参数本身冻结不变）。
- **提出 SKILL-KD 框架**，包含三个模块：(1) Contrastive Skill Distillation 从教师-学生轨迹对中提炼出候选技能补丁；(2) Adaptive Skill Distillation 通过重跑学生并观察行为变化来迭代验证/精炼补丁（最多 n 轮）；(3) Drift-Aware Skill Consolidation 用带溯源链接的编辑历史决定每次补丁是新增规则、修改/删除已有规则，还是直接跳过。
- **系统性的消融实验**证明：仅靠更丰富的行为证据（如仅教师轨迹、仅学生轨迹、成对对比、批量聚合）不足以产生有效技能，自适应验证和防漂移整合才是产生"有效且紧凑"技能库的关键——SKILL-KD 用最少的规则数（38条）取得了最高分（66.8），比"仅学生自省"变体（96条规则，60.1分）更精简也更有效。
- **在同族（Qwen3.5-4B ← Qwen3.7-plus）和异构（Qwen3.6-35B-A3B ← ChatGPT-5.5）两种教师-学生配置下**均验证有效，说明该方法不依赖模型架构相似性，蒸馏载体是自然语言技能文档而非 logits 或隐藏表示。

## Key Contributions

- **Reframes skills as a distillation medium** rather than experience summaries or memory entries: skill-level knowledge transfer between frozen LLM agents of different capability, where teacher-student behavioral discrepancies (not either trajectory alone) provide the transferable learning signal.
- **Proposes the SKILL-KD framework** with three coupled mechanisms: Contrastive Skill Distillation (extract candidate patches from student-failure/teacher-trajectory pairs), Adaptive Skill Distillation (iteratively validate/refine patches via student reruns, up to n=3 rounds), and Drift-Aware Skill Consolidation (a multi-turn consolidation agent that uses trace-linked edit histories to decide add/modify/delete/skip operations, preventing case-specific overfitting, skill-bloat, and destructive overwrites).
- **Ablation study isolating the value of validation and consolidation**: Teacher-only (58.3, +14.8), Student-only (60.1, +16.6, but 96 rules/6,821 words), Pairwise (59.0, +15.5, longest library at 6,966 words), Batch (59.4, +15.9, 3,849 words) all underperform full SKILL-KD (66.8, +23.4) while using more rules — showing richer behavioral evidence alone is insufficient without adaptive validation and drift-aware consolidation.
- **Cross-regime generalization**: works in both a homogeneous teacher-student pairing (Qwen3.5-4B student, Qwen3.7-plus teacher, same family) and a heterogeneous pairing (Qwen3.6-35B-A3B student, ChatGPT-5.5 teacher, different families/tokenizers), and shows within-benchmark held-out generalization on ALFWorld's unseen-environment test split.
- **Provides a diagnostic analysis of "imperfect teacher signals"**: even when the teacher itself fails on 53.9% of student-failed training instances, 38.5% of accepted patches on average still derive from teacher-failure rollouts, showing SKILL-KD does not require oracle teacher supervision to extract useful contrastive evidence.

## Methodology

SKILL-KD operates on a shared, structured Markdown skill library K, with each skill represented internally as a tuple `p = (title, content, why, trace)` — title and content are rendered into the skill file visible to both agents at runtime; why (rationale) and trace (source trajectory pointers) are retained only in an internal edit history accessible to the consolidation agent, not shown to the student/teacher.

**Contrastive Skill Distillation.** For each training instance x, the frozen student S first attempts the task with the current library: τ_S^0 = S(x; K). A task evaluator scores the trajectory r(x,τ) ∈ [0,1]. If the student already succeeds, no update is needed. If it fails, the teacher T is run on the same instance to produce τ_T = T(x; K). Because even the teacher may not score perfectly, comparing the two trajectories (rather than assuming oracle teacher correctness) still exposes where intermediate decisions diverge, which the consolidation agent C uses to propose an initial patch p^1 = C(K, H, (τ_S^0, r_S^0), (τ_T, r_T)).

**Adaptive Skill Distillation.** Rather than treating skill extraction as one-shot summarization, the framework treats it as an iterative search in skill space. The patched library Apply(p^1, K) is used to rerun the student: τ_S^1 = S(x; Apply(p^1, K)). If the student now succeeds, the patch is committed to K; if it still fails, the consolidation agent observes the new trajectory and the accumulated evidence E^i = {(τ_S^j, p^j, r_S^j)}_{j=1}^i to propose a revised patch p^{i+1}, up to a maximum of n adaptive rounds (n=3 in main experiments). Only patches validated by an actual student success are committed to the persistent library; failed intermediate patches are kept only in the instance-level refinement record, not written to K.

**Drift-Aware Skill Consolidation.** The consolidation agent is implemented as a multi-turn tool-using agent (not a single forward pass) that maintains a hierarchical edit history H = {h_1,...,h_m}, each entry h_j = (op_j, p_j) with op_j ∈ {add, modify, delete, skip}. It has two tools: a trace-link tool to retrieve full historical trajectories referenced by past edits (trajectories themselves are stored externally, not loaded into context by default, to keep prompts compact), and a patch tool to commit an operation to K. By retrieving trace-linked trajectories behind related entries before deciding, the agent can detect conflicts, cross-instance patterns, and decide whether a new patch should merge into an existing rule rather than accumulate as a redundant addition — directly targeting three failure modes documented in the case study: case-specific drift (over-narrow edits from local evidence), skill-bloat drift (redundant, over-specific rules accumulating), and destructive-update drift (a later edit silently erasing a previously useful rule/behavior).

**Experimental protocol.** Two teacher-student pairs: Group 1 (Qwen3.5-4B student, Qwen3.7-plus teacher, homogeneous family) and Group 2 (Qwen3.6-35B-A3B student, ChatGPT-5.5 teacher, heterogeneous). Five benchmarks: SearchQA, SpreadsheetBench, DocVQA, LiveMath, ALFWorld, using each benchmark's native train/validation/test split (or a deterministic 2:1:7 split with seed 42 where no official split exists). SKILL-KD builds its skill library using only the training partition; baselines that require validation-set selection use the validation partition separately. Student models served locally on 4×A100 80GB GPUs; teacher and consolidation models accessed via official APIs.

## Results & Highlights

- **Main results (Table 1), Group 1 (Qwen3.5-4B student / Qwen3.7-plus teacher), average across 5 benchmarks:** No Skill 43.5 → SKILL-KD 66.8 (+23.3 points), beating the strongest baseline SkillOpt at 63.5 (+3.3 points over SkillOpt) and EvoSkill at 51.5, Trace2Skill at 53.6, SkillGen at 52.5.
- **ALFWorld generalization (held-out unseen environments), Group 1:** SKILL-KD improves Qwen3.5-4B from 30.6 → 86.6 (+56.0 points) and Qwen3.6-35B-A3B from 59.7 → 96.3 (+36.6 points) — the largest single-benchmark gain reported, versus the best baseline on this benchmark, SkillOpt, at 81.3 (Group 1) and 82.1 (Group 2), so SKILL-KD still beats SkillOpt by +5.3 and +14.2 points respectively.
- **SpreadsheetBench, Group 1:** SKILL-KD scores 24.3 vs. No Skill 9.3 and best baseline SkillOpt 23.9 — a modest edge over SkillOpt here, and the paper is transparent that this benchmark is where drift-aware consolidation shows the smallest advantage over the ablated "w/o Consol." variant (24.3 vs. 14.6, per Table 3).
- **Ablation on skill acquisition variants (Table 2, Group 1):** SKILL-KD reaches 66.8 average with only 38 rules / 3,010 words, versus Student-only at 60.1 with 96 rules / 6,821 words — i.e., SKILL-KD beats the next-best ablation variant by 6.7 points while using less than half as many rules, directly supporting the paper's claim that validation (not just richer evidence) is what makes distillation effective.
- **Drift-aware consolidation ablation (Table 3, Group 1):** removing the edit log/trace-link access ("w/o Consol.") ties full SKILL-KD on SearchQA (79.2 vs 79.2) but falls behind on SpreadsheetBench (14.6 vs 24.3), DocVQA (87.4 vs 89.3), LiveMath (27.4 vs 54.8 — the largest gap), and ALFWorld (85.1 vs 86.6), showing historical trace-link evidence is most critical for tasks requiring accumulated multi-step or numerical reasoning corrections.
- **Adaptive rounds sensitivity (Table 6, Figure 3, Group 1 training-set cumulative success):** round n=0 (no rerun) gives 58.9% average; n=1 jumps to 67.7% (dominant gain, accounting for most of the total improvement by n=3); n=2 reaches 70.8%; n=3 reaches 72.7% — diminishing but still meaningful returns, motivating the bounded n=3 default rather than unbounded search.
- **Teacher-outcome diagnostic (Table 4, Group 1):** on student-failed training instances, the teacher itself only succeeds 46.1% of the time; patch acceptance rate is 45.3% when the teacher succeeds vs. 23.2% when the teacher also fails; yet 38.5% of all accepted patches on average are derived from teacher-failure rollouts (100% on LiveMath specifically), demonstrating the method does not require oracle teacher supervision.

## Critical Assessment

**Novelty:** The core idea — treating teacher-student behavioral contrast (rather than either trajectory alone) as the distillation signal for prompt-level (not weight-level) skill transfer — is a reasonably clean and well-motivated reframing relative to prior skill-library work (Trace2Skill, SkillGen, SkillOpt, EvoSkill), which the paper cites and empirically outperforms. The drift-aware consolidation mechanism with trace-linked edit history is a genuinely useful systems contribution addressing a real failure mode (skill libraries growing incoherent over time) that prior skill-optimization papers acknowledge but don't solve as directly.

**Rigor:** The ablation design (Teacher-only, Student-only, Pairwise, Batch vs. full SKILL-KD) is a strong, targeted test that isolates exactly the two claimed mechanisms (adaptive validation, drift-aware consolidation) rather than just showing an end-to-end number. The case studies (case-specific drift, skill-bloat drift, destructive-update drift in Section "Case Study") give paper-specific, concrete illustrations (e.g., a DocVQA numeric-extraction rule whose boundary repeatedly shifts between preserving/dropping units like "10 mg" vs "kg" across edits) rather than generic claims — this is a genuine strength for intellectual honesty. However, each reported score is from "a single complete evaluation run on the fixed test split" (Appendix A) — there is no variance/seed analysis, which is a real limitation for benchmarks like SpreadsheetBench and ALFWorld where stochastic agent rollouts could introduce meaningful score variance, especially given the small test set sizes (e.g., ALFWorld test = 134 instances, LiveMath test = 124 instances per Table 5).

**Reproducibility:** Benchmark-specific settings, split sizes (Table 5), consolidation agent prompt template, and tool schemas (Appendix B) are all documented in reasonable detail, which is commendable. But no code/library release is mentioned in the visible text, and the consolidation/teacher models are accessed via "official APIs" (unspecified exact versions beyond names like ChatGPT-5.5 and Qwen3.7-plus, which are non-deterministic and may drift over time), making exact replication difficult for outside groups.

**Significance / red flags:** The headline ALFWorld gain (30.6 → 86.6) is impressive but also the single largest and most benchmark-specific-looking result; ALFWorld is a comparatively narrow embodied-task domain with a small held-out test set (134 instances) and reusable "if X then do Y" object-interaction skills (e.g., "pick clean then place in receptacle") that may be closer to memorizing task-family templates than genuine reasoning transfer — the paper's own "reusable interaction strategies rather than memorizing training trajectories or object layouts" claim is asserted rather than independently verified (e.g., no held-out object/receptacle novelty control beyond "unseen environments"). The SpreadsheetBench margin over SkillOpt (24.3 vs 23.9) is thin, and the paper is honest that drift-aware consolidation's benefit is smallest there — a useful counterpoint to the otherwise strong average-score story. Baselines (EvoSkill, Trace2Skill, SkillGen, SkillOpt) are all recent (2026) skill-library methods from the same broad research area rather than classical fine-tuning/RL baselines, so the comparison set, while relevant and reasonably strong, does not include a lower-effort/no-skill-library alternative like plain in-context few-shot exemplars from the teacher's trajectories, which would help isolate how much benefit comes from "textual skill" packaging per se versus simply exposing the student to more teacher information in any form.

## Strengths

- Clear conceptual framing: contrastive teacher-student trajectory diffing as the actionable learning signal, rather than one-sided experience summarization.
- Strong, targeted ablations that isolate the specific contribution of adaptive validation and drift-aware consolidation (not just end-to-end numbers).
- Concrete, paper-specific case studies of failure modes (case-specific drift, skill-bloat drift, destructive-update drift) with real examples from the skill library.
- Works across both homogeneous and heterogeneous teacher-student model pairs, and shows within-benchmark generalization to unseen ALFWorld environments.
- Transparent diagnostic showing the method tolerates imperfect teacher signals (teacher succeeds only 46.1% of the time on student-failed cases, yet still yields useful patches).
- Produces markedly more compact skill libraries (38 rules) than ablated alternatives (up to 96 rules) while scoring higher — a genuine efficiency/quality tradeoff win.

## Limitations

- Single-run evaluation per benchmark with no reported variance across seeds/runs, despite agent rollouts (especially ALFWorld, SpreadsheetBench) being inherently stochastic.
- Small test partitions for some benchmarks (ALFWorld: 134, LiveMath: 124), which inflates the effect of individual instance outcomes on headline percentage gains (e.g., a single-digit number of flipped instances moves the score by multiple points).
- No comparison against a simpler in-context few-shot baseline using raw teacher trajectories/exemplars directly (rather than any structured "skill" summarization), which would help attribute gains specifically to the contrastive-and-validated skill abstraction versus merely exposing more teacher information.
- Relies on API-based teacher and consolidation models (ChatGPT-5.5, Qwen3.7-plus/ChatGPT-5.5) whose behavior may not be stable/reproducible over time, and no code release is indicated in the visible text.
- The consolidation agent's decisions (add/modify/delete/skip) are themselves LLM judgments without an independent correctness check beyond the subsequent student rerun — errors in classifying a rule as "cover / partial / unrelated" could silently degrade the skill library, though the adaptive rerun does provide some empirical guardrail.
- Bounded adaptive rounds (n=3) is a practical choice justified by diminishing returns (Figure 3), but the paper doesn't explore whether harder task families would benefit from a larger budget, nor report compute/cost overhead of the iterative rerun process relative to baselines.

## Relevance

该工作与"用弱模型作为高效执行者、强模型按需提供指导"的思路密切相关，尤其是其"教师-学生对比驱动的技能库"设计对构建可复用、可审计的 agent 技能/记忆系统（而非纯参数微调）有较强的工程参考价值；Drift-Aware Consolidation 中"trace-linked 编辑历史决定 add/modify/delete/skip"的机制，对任何需要长期维护 prompt/规则库而不产生规则膨胀或冲突的场景（如个人知识库、agent 记忆系统）都具有可借鉴性。

## Questions for Further Exploration

- How does SKILL-KD compare against a simple in-context few-shot baseline that directly injects the teacher's raw successful trajectory (or a few teacher exemplars) into the student's prompt, without any skill abstraction step — is the textual "skill" packaging doing more than just exposing more information?
- Does the method's benefit hold with multiple random seeds/repeated evaluation runs, especially on small test sets like ALFWorld (134) and LiveMath (124), where a handful of flipped outcomes swing the headline numbers substantially?
- How does skill-library quality/compactness evolve past the training set used here — would continuing to add more training tasks eventually reintroduce skill-bloat or conflicting-rule drift despite the consolidation mechanism, and is there a saturation point?
- Can the consolidation agent's add/modify/delete/skip decisions be validated against a ground-truth or human-audited "ideal" skill library to quantify how often it makes an incorrect consolidation call that only gets caught (or missed) by the downstream student rerun?
- What is the computational/API-cost overhead of the iterative student-rerun and multi-turn consolidation process relative to the one-shot summarization baselines (EvoSkill, Trace2Skill, SkillGen), and how does this trade off against the accuracy gains in a deployment setting?
- Would the framework generalize to settings where no single stronger "teacher" model exists (e.g., self-distillation from a committee of same-capability agents, or from human demonstrations) rather than requiring a strictly stronger teacher LLM?
