Key Finding

Isolate each ViT layer, quantize it alone, measure the KL-divergence damage, then allocate bits with an exact knapsack solver.

MixFrag: Fragility-Guided Mixed-Precision Post-Training Quantization for Vision Transformers ↗
Md. Mehrab Hossain Opi, Robiul Islam Ryad, Md. Umar Faruk · 30 Jul 2026 · KUET, Bangladesh · single RTX 4070 GPU
Vision Transformers Post-Training Quantization Mixed-Precision Quantization Knapsack Optimization Model Compression
Key Metric
+9.6AP

COCO instance segmentation, MP3/MP3 (3-bit): MixFrag reaches 40.9 avg AP vs. 31.3 for the prior best mixed-precision method, LRP-AQViT — the paper's largest reported gain.

Why This Matters

A cheap, interpretable fragility signal plus an exact knapsack solver could guide future ViT compression, but weigh detection gains against a real classification weakness.

Critical Edge

At the most aggressive 3-bit setting, MixFrag trails non-mixed-precision SOTA FIMA-Q on ImageNet-1K classification by ~29 average top-1 points (42.3% vs 71.3%) — a gap the abstract's "competitive" framing understates.

Methodology

  1. Fragility estimation. Each quantizable component (QKV, output projection, FC1, FC2) is quantized alone, to one candidate bit-width (2/3/4/6-bit), while every other component stays full-precision. Fragility = the KL divergence between the full-precision model's softmax outputs and this single-component-quantized model's outputs, averaged over a small calibration set — a direct measurement, not a Hessian or relevance-score proxy.
  2. MCKP bit allocation. Each component must pick exactly one bit-width so total bit cost stays under a target average-bit budget, minimizing summed fragility. This 0/1 Multiple-Choice Knapsack Problem is NP-hard in general but solved exactly via dynamic programming — no greedy search or heuristics.
  3. AdaLog quantization. The resulting per-component precision map is fed into the existing AdaLog PTQ backend (adaptive logarithmic quantizer + FPCS calibration), which does the actual weight/activation quantization. LayerNorm and residual connections stay in floating point; the allocation step is presented as backend-agnostic.

Calibration: 1,024 ImageNet / 256 COCO images for AdaLog, but only 32 images for the fragility table itself — a 32× discrepancy the paper doesn't analyze. All runs on one RTX 4070.

Strengths

  • Fragility is measured directly from actual output-distribution shift, not a Hessian or LRP-relevance proxy.
  • MCKP/dynamic-programming solver is exact, not greedy — and an ablation shows it consistently beats greedy while both crush random allocation.
  • State-of-the-art among mixed-precision methods on COCO, across two detector families and two Swin backbone sizes.
  • Fragility-concentration analysis (attention QKV/projection, early blocks) has reusable diagnostic value beyond this specific method.
  • Honest negative-result reporting: the "marginal refinement" idea was tested, found to hurt, and reported anyway.

Limitations

  • Trails FIMA-Q by ~29 avg top-1 points on ImageNet-1K at 3-bit (42.3% vs 71.3%), not closed or deeply analyzed.
  • Fragility isolates one component at a time — doesn't model interactions among components quantized simultaneously.
  • Fragility-to-allocation correlation is only moderate (Pearson ≤0.55) and nearly vanishes at looser 6-bit budgets.
  • Tested only on mid-sized ViT/DeiT/Swin backbones — no large ViTs or vision foundation models.
  • No runtime or memory comparison for the fragility-estimation stage itself, despite calling the framework "lightweight."

Questions for Further Exploration

  • Is the ImageNet-vs-COCO gap a genuine classification/detection difference, or does FIMA-Q's costlier calibration just overfit to ImageNet?
  • How sensitive is fragility scoring to the tiny 32-image calibration subset, versus AdaLog's own 1,024-image set?
  • Would modeling pairwise or higher-order component interactions improve correlation at looser bit budgets, where it currently nearly vanishes?
  • What's the real compute overhead of the fragility stage (C components × B bit-widths of forward passes) versus FIMA-Q's Fisher-information approximation — does "lightweight" hold on larger backbones?
  • Would swapping AdaLog for a different PTQ backend preserve the fragility rankings and results, testing the claimed backend-agnostic generality?
