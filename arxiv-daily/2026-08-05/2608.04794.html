§ 02 · methodology

The lone SD objective, isolated

The authors study self-distillation as the only training signal — the student is the policy πθ, the teacher is the same model additionally conditioned on privileged information r, with stop-gradient so gradients flow only through the student. No reward or verifier term.

L_SD(θ) — symmetric Jensen-Shannon, per-token clipped E[(1/|ŷ|) · Σt D_JS( p_T(·|x, r, ŷ_<t) ‖ p_S(·|x, ŷ_<t) )]
τ = 0.001 · EMA teacher α = 0.001 · 8 rollouts · batch 32 · 3 epochs · lr 1e-5 · 8× B200

They first reproduce SDPO's published easy-regime gains on SciKnowEval with the original codebase — preempting the "your implementation is broken" objection — then apply the identical setup to four harder domains: MMLU-Pro (QA), DAPO-Math-17k, CodeForces, and BFCL v3 multi-turn agentic, with three PI forms (whole solution / 1–2 sentence hint / ≈500-token skill card).

✓ Strengths

  • Reproducibility-first. Re-reproduces SDPO's easy-regime gain before reporting the negative — rules out implementation error.
  • PI Bias Score is a novel, cheap, forward-pass-only diagnostic anyone can run before committing compute.
  • Causal, not correlational: recipe-independence (SDPO + OPSD) + specificity-dial ablation (whole / hint / skill).
  • Mechanistic depth — each chain link measured on the same runs with concrete numbers (loss, KL, token shares).
  • Honest scoping in Limitations — never claims SD is useless in general.

! Limitations

  • Single architecture. Qwen3 only — no Llama / Mistral / Gemma cross-family check.
  • Full chain measured only on 8B — 32B reports accuracy + bias score, not the mechanism.
  • No remedy tested. The reward+SD (RLSD) fix is explicitly left open — diagnosis, not prescription.
  • Hints/skills are LLM-generated, so weak-PI results conflate PI-form with generation quality.
  • PI Bias Score depends on chosen y′, ỹ, y⁻ — no canonical construction protocol released.
  • Small training sets (2k, 3 epochs); whether longer SD eventually learns is untested.
§ 04 · open questions

Where this leaves the field

  1. Does a verifiable reward + small-weight SD auxiliary (the RLSD fix) actually repair the failure — or does PI-bias contamination persist inside the auxiliary term?
  2. Does the PI Bias Score correlate with downstream Δ-accuracy strongly enough to become an automated PI-selection criterion before training?
  3. Would a teacher conditioned on the set of correct continuations (not one sampled trajectory) kill PI bias while preserving density — at what compute cost?
  4. Does the causal chain (loss on stopwords, exploration penalized, entropy rise) replicate on Llama 3 / Mistral / Gemma?
  5. Are the instruct-mode positive outliers (MBPP+ +12.6, BFCL Base V4 +7.5) a real short-rollout effect or noise?
  6. Can longer training ever cross lone SD from "flattening" into "learning" — or is decoupling from correctness a fixed point?
