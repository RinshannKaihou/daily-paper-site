> **一句话总结：** Argus 是一个持久化、可自我演化的通用智能体运行时，通过 Manager/Planner/Engineer/Reviewer 四角色分工与"验证门控"机制，让长程研究任务在模型权重固定的前提下，能够基于证据安全地持久、转向和积累被验证的方法；在 SWE-Bench Pro 731 任务上以 ~78% 准确率（vs Direct Copilot 的 59%）和 1.41× 总 Token 消耗达成，成熟期每任务比启动期节省 21% Token 和 15% 活跃时间。

> **TL;DR:** Argus is a persistent, pivot-capable agentic runtime whose central thesis is that long-horizon research requires *verified pivoting* — persisting while evidence supports a route and pivoting when verification exposes failure — rather than driving harder along a fixed plan. Four roles (Manager, Planner, Engineer, Reviewer) execute bounded missions over durable campaign state, with material contract changes admitted only through evidence-backed, role-owned, recorded gates (model weights stay fixed; only runtime state evolves). Across seven GPT-5.5 benchmark arenas it reaches ~78% on SWE-Bench Pro (731 tasks) versus 59% for Direct Copilot at 1.41× aggregate Tokens (+19 pts), 76.8% on AARRI-Bench (vs 68.3% reference), and a 28.0 gap on Math-Reasoning Data Synthesis (vs Arbor 20.83). Mature SWE-Bench Waves use 21% fewer solve Tokens and 15% less active time per task than startup, while 34/43 Reviewer-revised tasks recover at the official verifier. Evidence is observational (no matched frozen-state replay), and several headline verticals (a certified chip, a materials simplification) close only against narrow external checkers.

## 核心贡献

- **将长程研究形式化为"验证式转向"问题**：提出报告级工作契约 K_t = (ι, o_t, c_t, v_t)（稳定意图、当前目标、约束、验证标准）与显式用户决策状态 X_t，并用 ManagerAdmit 算子把契约精化所需的证据、权限、来源要求显式化——使"目标修订"与"目标漂移"可被区分。
- **运行时层面的角色分工与状态持久化**：通过 Manager / Planner / Engineer / Reviewer 四角色在控制、执行、记录三个平面上分工，把契约修订、Stage 转换、no-go 回滚、裁决来源等"重大变更"赋予作者、前置条件和审计轨迹，而非隐式重规划。
- **验证门控的固定模型运行时自演化**：模型参数 θ_t 不变，但候选 memory / skills / verifiers / routing / 被拒路由只有通过任务原生证据检查与授权提交后，才成为后续任务可复用的持久状态；这是"自演化"的窄义定义。
- **SWE-Bench Pro 上的纵向证据**：731 任务全轨迹显示成熟期（W19–22）每任务比启动期（W1–6）节省 21% solve input Tokens、15% 活跃时间；Reviewer 在 43 个任务请求修订，其中 34 个通过官方 verifier、22 个完成严格 review-loop rescue。
- **自主论文生产案例研究**：6 个研究项目（评估可靠性、视觉-语言匹配、测试时自适应、GUI 智能体、多模态幻觉、模型量化）全部走完研究→投稿全流程，累计 640 campaign-hours、254 个有界 mission、576 Engineer 轮、286 Reviewer 修订、16 次 Stage 回滚。
- **数学/硬件/材料三个"外部验证器"纵向**：Erős–Gyárfás 竞选保留 1 条被证伪路由和 6 个证明支撑的前沿更新；ACE-2 芯片在映射综合+静态时序下认证了一个 W4A8 推理加速器（明确列出未覆盖的排除项）；材料（MOF）竞选在分离了积分器与评分两个混淆变量后，发现 best-of-K 反而优于已发表的 Feynman–Kac steering。
- **能力基线统一表**：在一个表中保留七个基准各自的原生 backbone / backend / 协议 / 度量与参考值，证明验证机制不损害端任务性能。

## Key Contributions

- **Formulates long-horizon research as verified pivoting** over a compact report-level contract K_t = (ι, o_t, c_t, v_t) and explicit user-decision state X_t, with the analytical ManagerAdmit operator making the evidence, authority, and provenance requirements for material refinement explicit — so objective revision becomes distinguishable from goal drift.
- **A runtime with typed, logged, role-owned surfaces for contract refinement**: GoalContract revisions, Manager stage transitions, no-go rollbacks, and recorded verdict sources each give a material change an author, a precondition, and an audit trail, rather than an implicit consequence of replanning.
- **Verification-gated fixed-model runtime self-evolution**: model parameters θ_t remain fixed, but generated memories, skills, verifiers, routing decisions, and rejected routes become reusable only after task-native evidence checks and an authorized commit by the owning role.
- **A unified capability-floor table across seven benchmark arenas** (SWE-Bench Pro, SOL-ExecBench, nanochat B200/H100, nanoGPT speedrun, AARRI-Bench, Math-Reasoning Data) that preserves each benchmark's native backbone, backend, protocol, metric, and reference — establishing the verification machinery does not cost end-task performance.
- **A 731-task SWE-Bench Pro longitudinal trajectory** supporting analyses of Skill/Wiki evolution, verifier recovery (34/43 recoveries), strict Reviewer rescue (22/43), and a 21% / 15% mature-vs-startup reduction in solve Tokens / active time.
- **A six-project autonomous paper-production case study** spanning 640 campaign-hours, 254 missions, 576 Engineer rounds, 286 Reviewer revisions, and 16 Stage rollbacks, with all six canonical pipelines reaching submission completion.
- **External-checker verticals** that close against evaluators the runtime does not own: a mathematical campaign (one falsified route + six proof-backed frontier updates), the ACE-2 chip (certified against mapped synthesis + static timing with self-declared exclusions), a materials campaign that simplifies a published method, and a TileLang RWKV6 kernel merged upstream into fla-org:main.

## Methodology

Argus is built around a central abstraction: a **sequence of bounded missions executed against durable campaign state**. The long-lived object is the campaign, not a provider transcript; each mission has an explicit outcome and the scheduler advances only at clean mission boundaries (transactional assignment prevents duplicate work under concurrency).

**Four roles divide research authority** (Table 1 of the paper):
- **Manager** — commits the objective, lifetime, route, and campaign stage; authoritative over stage transitions (hold / advance / rollback).
- **Planner** — decomposes current research state into bounded tasks and dependencies; authors task specs and stage checklists.
- **Engineer** — modifies artifacts, invokes tools, runs experiments for one round; selects `review=skip|required`.
- **Reviewer** — independently inspects artifacts and execution records when required or requested; issues `done`/`continue`/`blocked` with grounded next action.

Mission completion always has an explicit source: allowed low-risk bounded work may use Engineer self-review, while vertical policy, stage-closing tasks, or Engineer requests force an independent Reviewer. Completion never comes from filenames, token volume, or prose keywords.

**Report-level contract model**: K_t = (ι, o_t, c_t, v_t) separates standing user intent ι (which the campaign must preserve) from the operational objective o_t, constraints c_t, and verification criteria v_t that evidence may refine. X_t holds user-visible clarifications/priorities. A material refinement is K_{t+1} = ManagerAdmit(X_t, K_t, K'_t, e_t, r_t, u_t) — a normative projection over several runtime surfaces, not one atomic API.

**Verification-gated fixed-model runtime self-evolution** is formalized as H_{t+1} = U(H_t, τ_t, E_t, K_{t+1}) with θ_{t+1} = θ_t. H_t = {Memory, Skills, Tools, Verifiers, Routing}. Each component has an explicit change source, commit owner, and persistent form (Table 2): e.g., memory is produced by Engineer trajectories but committed by the Reviewer; routing is Manager-committed. Activity that does not survive the commit-and-reuse path is not counted as self-evolution.

A **process-to-capability theory** ties these primitives to measurable quantities: process-data dominance (Proposition 1, a Blackwell-information ordering — R_q(P) ≤ R_q(Y) for every downstream decision q), a typed compression ψ(P) trading downstream risk against retrieval cost, a discounted counterfactual reuse value G_L, a verified-reusable yield Y^PRI_R, and a Bayesian selective-error-correction model of review (Pr(C|A=1) = αp / (αp + β(1−p))).

Cross-session continuity uses an ordinary shared `CHECKPOINT.md` with durable state, evidence references, open questions, and the next step; the full event history stays in an append-only tape separate from the bounded working checkpoint. Engineers/Reviewers use fresh provider sessions per round.

## Results & Highlights

- **SWE-Bench Pro (731 tasks)**: Argus reaches **~78% accuracy versus 59% for Direct Copilot**, at **1.41× aggregate Tokens** (R_tok = N^Argus / N^Copilot ≈ 1.41) — a +19 percentage-point gap. Raw Copilot per-Wave Token/time traces were not retained, so the longitudinal analysis is Argus-only.
- **Reviewer routing on SWE-Bench Pro**: of 731 tasks, **466 (63.7%) invoke an independent Reviewer and 265 (36.3%) use Engineer self-review**. The Reviewer requests revision on 43 tasks; after another Engineer round, **34 pass the official verifier (79.1% recovery) and 22 complete the strict continue→revision→done loop (51.2%)**. A further 35 tasks receive a `blocked` verdict rather than an unsupported completion. Reviewer-routed tasks consume 2.75× solve input tokens and 1.80× active time on average.
- **Longitudinal self-evolution (SWE-Bench Pro)**: mature window W19–22 uses **21% fewer solve input Tokens and 15% less active workflow time per task than startup W1–6** (2.33M vs 2.95M Tokens; 7.25 vs 8.52 min). The trajectory is non-monotone: W13–18 hits a 50% Token reduction but with longer active time (10.42 min), and the late W23–24 window rebounds to 3.72M Tokens / 9.01 min on harder tasks.
- **AARRI-Bench (82 research-intern tasks)**: Argus solves **63/82 = 76.8%** versus a paper best of **68.3%**.
- **Math-Reasoning Data Synthesis (AIME-style)**: Argus achieves a **28.0 pass@4−pass@1 gap** versus **Arbor 20.83, Claude 8.33, Codex 6.25**.
- **nanochat (5-min training)**: B200 **0.9636 BPB** vs human best **0.9646**; H100 **0.9855 BPB** vs human best **0.9879** (BPB lower is better).
- **nanoGPT speedrun (8×H100, target val-loss 3.28)**: **79.77 s** mean over N=10 verifier runs vs same-device human **80.18 s**.
- **SOL-ExecBench (B200 GPU kernels)**: Global **#6**, **2× #1**, **7 top-3 placements**, with two head-to-head wins over Recursive.
- **Autonomous paper production**: **6/6 projects reach submission completion** spanning 640 campaign-hours, 254 missions, 576 Engineer rounds, 286 Reviewer revisions, 89 session rolls, 16 Stage rollbacks. The multimodal-hallucination campaign uses 7 no-go rollbacks to reframe a failed method search as a 4,500-row negative-results study.
- **Mathematical (Erős–Gyárfás) vertical**: one falsified route retained plus **six proof-backed frontier updates**, including a 27→25 strengthening of a degree bound and two bridge lemmas.
- **ACE-2 chip**: certified at 62,283 cells, 0.614 mm² non-SRAM area (vs 2.0 mm² cap), +0.6966 ns setup slack, 0.00 ns negative slack, 100 MHz floor — passing without relaxation, but the certificate self-declares exclusions (no routed timing, no power signoff, no DRC/LVS, no GDS/tapeout, no silicon).
- **Materials (MOF) vertical**: best-of-K beats published Feynman–Kac steering at matched compute — K=8: **55.21% vs 52.38% (+2.83)**, K=16: 59.76% vs 57.94%, K=32: 61.38% vs 59.96%; the K=8 difference survives a paired test (p=0.0486). The score-vs-integrator confound attributes +1.92 (p=0.238, n.s.) to the integrator and +9.00 (p=2.0×10⁻⁹) to the score.
- **Upstream adoption**: a TileLang RWKV6 kernel was reviewed by a Moonshot-AI-affiliated FLA collaborator and merged into fla-org:main (PR #1045, commit c70f11c, 2026-07-20), reporting 1.18× forward latency (0.199→0.168 ms) and 1.21× forward+backward (0.900→0.747 ms).
- **MLE-Bench Lite (partial, in progress)**: 9 medals to date (3 gold, 3 silver, 3 bronze), each awarded by the external Kaggle grader; e.g., transparent-conductors certified at 0.06402 RMSLE vs 0.06582 bronze threshold after a verification-gated method replacement.

## Authors & Credibility

The work is a multi-institution technical report (Microsoft; Shanghai Jiao Tong University; Fudan University; Nanjing University; Tsinghua University; The University of Hong Kong; Peking University; CUHK-Shenzhen; Donghua University) led by co-first authors Boxiu Li, Zimo Wen, and Yijia Fan, with corresponding authors Xian Zhang (Microsoft) and Zhijie Deng (SJTU). The framing is unusually disciplined for an agentic-runtime paper: it explicitly labels its longitudinal evidence as **observational rather than causal**, names the missing controlled experiments (matched frozen-state replay, randomized task order, randomized review routing), and self-reports internal inconsistencies (a stale blocked assurance snapshot in one paper project). A genuine external-adoption artifact (the merged FLA kernel PR) and externally-graded outcomes (MLE-Bench medals, MOFChecker) provide some independent corroboration that the runtime produces real, verifiable artifacts rather than self-graded narratives. However, this is a single technical report with no peer review, and several headline numbers rest on in-house harness instrumentation that is only partially released.

## Critical Assessment

- **Novelty**: The core conceptual move — separating *standing intent* ι from *operational contract* (o_t, c_t, v_t) and admitting pivots only through evidence-gated ManagerAdmit — is a genuinely useful reframing of a real problem (unrestricted pivoting is indistinguishable from rationalized failure). The four-role / three-plane architecture itself is incremental over Agent Workflow Memory, Arbor's hypothesis tree, and Reflexion/Voyager-style persistence; the contribution is the *admission-discipline* layered on top, not a new model or a new search algorithm.
- **Rigor**: Honest about its own weaknesses. The paper repeatedly distinguishes "consistent with self-evolution" from "causally attributable to it": the startup→mature −21% Token / −15% time comparison has **no matched frozen-state replay**, **one task order**, **adaptive (not randomized) Reviewer routing**, and missing per-Wave Copilot traces. The 79.1% verifier-recovery and 51.2% strict-rescue rates are the most defensible causal-ish claims because they sit inside a single task.
- **Reproducibility**: Mixed. Public assets exist (argusbot.cn, github.com/lbx154/Argus, machine-readable aggregates, editable figure sources, supplementary trace bundle). But the full SWE-Bench Pro comparison depends on a specific Copilot backend with GPT-5.5/xhigh whose raw per-Wave traces were not retained, the six-paper case study shares one research environment with overlapping calendar time and evolving logging, and several verticals (ACE-2 chip certification, MOF 989-crystal subset) use hardware/data the reader cannot trivially reproduce.
- **Significance**: If the verified-pivoting discipline holds up under controlled study, it addresses a real gap in the autonomous-research literature (AI Scientist, AutoSci, FARS, Arbor all assume the objective is given). The breadth — software, GPU kernels, model training, math, chip RTL, materials — is impressive for a single harness, but each individual result is "competitive" rather than SOTA-shattering, and several are single-run.
- **Red flags**: (1) The headline SWE-Bench Pro comparison reports **"≈78%"** and **"≈59%"** with the ≈ qualifier and no exact counts or confidence intervals — loose for a +19-pt centerpiece claim. (2) The 1.41× Token cost is presented without a wall-clock or dollar-cost normalization, masking whether the accuracy gain is economical. (3) The GLM-5.2/Claude-Code transfer run (70.94%) is mentioned in-text but excluded from tables and has no matched baseline — it is suggestive but proves nothing about transfer. (4) The paper-production case study conflates "submission completion" with research value — the authors flag this, but readers may still over-read. (5) Reviewer sensitivity α and false-acceptance β are formalized (Eq. 15) but never measured with randomized routing, so the "selective error-correction" claim is asserted, not quantified. (6) The materials vertical explicitly admits its 989-crystal subset is the same data the score was designed on (no independent holdout) and that the matched-compute comparison was interrupted by a parameter error — a candid but real threat to that vertical's conclusion.

## Strengths

- **Conceptual clarity on the pivot/drift problem**: the K_t / X_t separation and ManagerAdmit operator give a usable vocabulary for something the field has hand-waved.
- **Intellectual honesty**: the paper volunteers its own counterexamples (non-monotone W23–24 rebound, stale assurance snapshot, in-progress/un-baselined GLM run, self-declared chip exclusions) rather than burying them.
- **Breadth without forced normalization**: keeping each benchmark in native units and refusing to average incompatible metrics is methodologically correct.
- **Real external checkpoints**: FLA upstream merge, Kaggle-graded medals, MOFChecker, static-timing engine — these are not self-graded.
- **Verification as a first-class output**: the ACE-2 certificate enumerating its own exclusions is a model for how agentic systems should report scope.

## Limitations

- **Observational, not causal**: the central runtime-self-evolution claim (−21% Tokens, −15% time) lacks matched frozen-state replay, randomized routing, and randomized task order; the authors name these gaps but do not close them.
- **Single backbone, single harness**: seven arenas all use GPT-5.5 (six via Codex); the GLM-5.2 transfer run is incomplete and un-baselined.
- **Loose headline numbers**: "≈78% vs ≈59%" with no confidence intervals or exact task counts; 1.41× Tokens without cost normalization.
- **Verification soundness bounded by the verifier**: an executable test, formal checker, or model Reviewer can encode the wrong property; the runtime records/revises verifiers but cannot guarantee their correctness.
- **No public prospective user-study**: user-guided pivots are motivated only by undisclosed internal cases.
- **Paper-production ≠ acceptance**: six manuscripts reach submission Stage, but this says nothing about novelty, peer review, or superiority to human teams; review snapshots are model-generated.
- **Verticals close against narrow scopes**: ACE-2 is certified only at mapped synthesis + static timing (no silicon); the MOF result is scored on the same validator selection optimized against (the exact verifier-shaped-objective failure mode the paper itself names in §8).

## Relevance

这篇论文对关注"智能体运行时 / 长程自主研究 / 自演化智能体"方向高度相关：它把"何时转向"和"如何让持久化状态被验证后才积累"形式化为可操作的运行时机制（K_t 契约、ManagerAdmit、验证门控自演化），与 ReAct/SWE-agent/OpenHands、AI Scientist/Arbor/FARS、以及 memory 系统（Voyager/MemGPT/Agent Workflow Memory）形成直接对话，对设计自己的长程 agent / 自动研究 pipeline 有直接借鉴价值。

## Questions for Further Exploration

- What would a **matched frozen-state replay** of the 731 SWE-Bench Pro tasks show — i.e., re-running the *same* task order against (a) the startup runtime state and (b) the mature runtime state — to isolate the causal contribution of accumulated Skills/Wiki/routing versus task-difficulty and composition drift?
- How sensitive is the **79.1% verifier-recovery / 51.2% strict-rescue** rate to randomized (non-adaptive) Reviewer routing? The current routing concentrates review on harder tasks, which confounds the error-correction estimate (α, β).
- Can the ManagerAdmit operator be stress-tested with **adversarial contract refinements** — e.g., a Manager or operator deliberately proposing a goal-drifting refinement — to measure whether the evidence-and-authority gate actually refuses, versus rubber-stamping?
- Does the **process-data dominance** claim (Proposition 1) translate into measurable downstream model-training gains? The paper proposes but does not run held-out SFT/RL splits to test how much of the long-horizon control loop a model can internalize from Argus trajectories.
- How does Argus behave when the **verifier itself is wrong** (specification bug vs. implementation bug)? The paper names this as future work but provides no controlled study of whether the runtime localizes the faulty side or merely satisfies the current check.
- Is the **1.41× Token cost** on SWE-Bench Pro economically justified at the +19-pt accuracy gain once dollar cost and wall-clock latency (including orchestration wait, which is excluded from the active-time metric) are normalized?
- Can the ACE-2 / materials pattern of **self-declared scope exclusions** be made into a general certification format that other agentic systems adopt, so "chip" / "SOTA" claims always come with an explicit evidence perimeter?
