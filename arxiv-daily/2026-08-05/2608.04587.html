The evolution loop

STAGE 0
Modular agent
5 interface-stable modules A=(S,L,P,W,R); each edit confined to one module + dependencies.
STAGE 1
Distribution-aware init
5 frames + queries → distribution requirements → design evidence → agent A₀, then smoke-tested.
STAGE 2
Teacher review
Builds evidence-grounded Gold Path, finds earliest unsupported step, isolates a minimal validation task.
STAGE 3
Diagnosis
Clusters recurring causal failures across samples; picks one primary responsible module + code-scope constraints.
STAGE 4
Evolution
Responsibility-constrained code edits; gates: engineering → minimal probe → full evolution-split comparison.
STAGE 5
Blind eval
Held-out archived externally; analyzed post-hoc only, never drives promotion, early-stop, or rollback.
STAGE 6
VA-EvoBench
8 video-disjoint distributions from CG-Bench; reports accuracy, tok/q, frames/q, best-so-far curve.

03

Strengths & limitations

＋ Strengths

what holds up
  • First-mover framing of distribution-specific video-agent evolution, with a clean three-agent Teacher→Diagnosis→Evolution loop.
  • Exemplary blind protocol — held-out never enters diagnosis, promotion, early-stop, or rollback; guards against the leakage that plagues "evolution" papers.
  • Modular contract (S,L,P,W,R) with stable interfaces is a broadly reusable abstraction for code-level agent edits.
  • Wins on accuracy AND efficiency simultaneously — fewest tokens and fewest frames per question of any compared agent.
  • VA-EvoBench with 8 distribution-specific splits and separate evolution/held-out partitions is a concrete, reusable artifact.
  • Honest reporting of CI (48.63–55.78) and a clear distinction between final accuracy (51.47%) and best-so-far curve (52.21%).

－ Limitations

what to probe
  • Ablations confined to one distribution (Course Lecture, 119 q) — component sensitivity across the other 7 is unknown.
  • VA-EvoBench is re-sliced from CG-Bench, inheriting its annotation biases; "8 distributions" are re-slicings of one source.
  • Headline gain starts from MVA's own from-scratch agent — a potentially weak baseline that inflates the +13 pt narrative.
  • Relies on closed-source frontier coding agents (Claude Code, OpenAI Codex) — reproducibility contingent on external systems.
  • ~3.54M evolution tokens/distribution excluded from deployment-cost reporting, understating total system cost.
  • No variance or significance on the main table; fixed-agent competition is bunched (WorldMM only ~1 pt above DVD/Symphony).
04

Open questions

Q1 · TRANSFER

Does evolution still help when the initial agent is already adaptive (VideoSeek, LensWalk) rather than DVD or from-scratch — does the +3.37 Course Lecture gain generalize?

Q2 · ABLATIONS

Would ablations across all 8 distributions show Diagnosis or Deep Research is critical for some and dispensable for others?

Q3 · GOLD PATH

Can the Teacher's Gold Path be validated against human annotations beyond the provided evidence intervals — to measure Gold Path quality itself?

Q4 · CODER BACKBONE

Is the responsibility-constrained update robust to weaker open-source coders, or does evolution stability collapse without Claude Code / Codex?

Q5 · BENCHMARK DRIFT

How sensitive is VA-EvoBench to its CG-Bench provenance — would rankings shift if sourced from Video-MME, LongVideoBench, or newly collected video?

Q6 · COST

Can the 3.54M tok/distribution evolution cost be cut via minimal-validation task reuse across distributions, enabling joint multi-distribution evolution?
