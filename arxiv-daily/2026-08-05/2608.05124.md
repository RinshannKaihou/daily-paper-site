> **一句话总结：** 提出 Chained RLM，一种推理时架构——用同一个底层模型以"全新根节点"链式多次调用，仅通过纯文本的黑板、摘要与持久化 artifact 传递状态；在 GPT-5-mini 上四个长上下文基准平均提升 13.75 个百分点（OOLONG-real 上从 14% 跃升至 38%），代价是平均推理成本约 2.5 倍。

> **TL;DR:** Chained RLM is a training-free, inference-time architecture that solves long-context tasks by calling the same underlying LLM as a chain of fresh "roots," passing continuity only through plain-text summary/blackboard and durable disk artifacts (no JSON). On GPT-5-mini it lifts pass@1 accuracy across four benchmarks—RULER 87%→92%, BABILong 44%→59%, LongBench v2 41%→52%, OOLONG-real 14%→38% (avg +13.75 pts vs. a single-trajectory Regular LLM baseline)—at the cost of ~2.5× more inference spend ($0.315 vs. $0.125/task) and 2.6× more model calls, with the largest gains on tasks requiring aggregation/record-keeping rather than simple retrieval.

## 核心贡献

- 提出 Chained RLM：一种线性、推理时架构，把同一模型作为一连串"全新根节点"反复调用，每个根都重新拿到原始问题与上下文，但只继承一个紧凑的纯文本延续状态，而非完整对话历史。
- 设计了极简的纯文本交接机制（SUMMARY / BLACKBOARD / NEXT + 可选 Recent Work Excerpt），刻意不使用 JSON/XML/YAML，避免对脆弱格式解析的依赖。
- 引入持久化的纯文本 artifact 工作区：根节点创建、读取、审计候选证据台账、抽取表、推导与清单，后续根在保留结构的前提下修正/扩展，使 artifact 成为推理阶段间的主要延续对象。
- 给出系统模型（链状态 s_r = (B_r, A_r, H_r, E_r)）与对照评估协议，在固定模型（GPT-5-mini）与相同输入下，与单轨迹 Regular LLM 基线做受控比较，并给出 Algorithm 1 的完整伪代码。
- 实证表明：增益随任务难度上升而增大——在需要跨远距离证据聚合/记账的 OOLONG-real 上从 14% 提升到 38%（+24 pts），而在偏检索型的 RULER 上仅 +5 pts。

## Key Contributions

- Proposes **Chained RLM**, a linear inference-time architecture where a single underlying model is invoked as a chain of fresh "roots," each re-receiving the original problem/context but inheriting only a compact plain-text continuity state rather than full conversational history.
- Introduces a deliberately simple **plain-text handoff format** (SUMMARY / BLACKBOARD / NEXT, with an optional raw Recent Work Excerpt), explicitly avoiding JSON/XML/YAML/host-parsed schemas to keep continuity close to "notes to one's future self."
- Defines a durable **plain-text artifact workspace**: roots create candidate ledgers, extraction tables, derivations, audit notes, and verification checklists; later roots must `list_artifacts()`, read, preserve structure, and correct/audit/extend the content—making the artifact the primary object of continuation across stages.
- Formalizes the system model (chain state s_r = (B_r, A_r, H_r, E_r): blackboard, artifacts, predecessor-summary, optional recent-work excerpt) and a controlled evaluation protocol comparing Chained RLM against a single-trajectory Regular LLM under the same model and inputs, with full pseudocode in Algorithm 1.
- Empirically shows the method is **training-free, RL-free, and verifier-free by default**, yet yields accuracy gains that scale with task difficulty—largest on aggregation/record-keeping benchmarks, smallest on retrieval-style ones.

## Methodology

Chained RLM is an **inference-time, training-free** architecture built on top of a tool-using Recursive Language Model (RLM). The system treats a long-context task as a pair (q, c) and, instead of producing y ~ f_θ(q, c) in one call, defines a sequence of roots r = 0 … R−1:

- **Roots (§3.1):** Each root is a fresh RLM call with a Python REPL-like environment—it can inspect the context, run code, call sub-LLMs, read/write artifacts, and submit either a FINAL answer or a HANDOFF. Crucially, a later root does **not** inherit the previous root's conversational trajectory; it sees only the curated continuity state plus the original inputs. Raw trajectories T_r are saved to disk but injected only on demand.
- **Chain state (§3, Eq. 3):** s_r = (B_r, A_r, H_r, E_r) — B_r plain-text blackboard, A_r artifact set, H_r compact predecessor handoff summary, E_r optional bounded recent-work excerpt.
- **Blackboard (§3.2):** A compact plain-text working memory holding current best answer, verified facts, assumptions, open questions, contradictions, evidence pointers, and reusable procedures. The host does not parse it; it is written for the next fresh root.
- **Artifacts (§3.3):** Persistent plain-text files (preferred `.txt`/`.tsv`, not JSON/markdown tables) whose type/number/format are chosen by the model itself. Root 0 establishes structure; later roots preserve structure while correcting/extending/auditing; if structure must change, a clearly named superseding artifact is written and the migration logged in the blackboard.
- **Handoff & Finalization (§3.4, §4.3):** A non-final root submits a plain-text HANDOFF with exactly three sections (SUMMARY/BLACKBOARD/NEXT); an optional fourth "Recent Work Excerpt" is flagged as non-authoritative scratch. Before FINAL, a root is instructed to audit entity mappings, event definitions, ordering, and count logic in the artifact. The last root is forced to emit the best-supported FINAL.
- **Artifact-mediated handoff pattern (§4.2):** For a counting/aggregation task the intended behavior is: Root 0 extracts candidate rows → Root 1 audits entity mappings and event definitions → Root 2 recomputes counts from the audited artifact and answers. The host stores only text; task understanding lives entirely in the model.
- **Loop (Algorithm 1):** For r = 0…R−1, build s_r, run fresh root, save T_r; if FINAL, return; if HANDOFF, parse the three sections, update B_{r+1}, keep artifacts A_{r+1}, append summary to H_{r+1}, optionally append bounded excerpt E_{r+1}.

The evaluation protocol (§5.2) uses pass@1 exact accuracy as the primary metric, plus secondary resource metrics (avg root calls, handoffs, input/output tokens, cost per task) computed from GPT-5-mini API pricing. Both the Regular LLM baseline and Chained RLM use the **same** underlying GPT-5-mini and the same (q, c), so the comparison isolates the architecture.

## Results & Highlights

- **RULER (Hsieh et al., 2024):** Regular LLM (GPT-5-mini + tool-call) 87% → Chained RLM 92% (**+5 pts**). The smallest gain, because many RULER subtasks are solvable by localized retrieval/pattern match where a single trajectory already suffices.
- **BABILong (Kuratov et al., 2024):** 44% → 59% (**+15 pts**). Requires preserving partial evidence across a long reasoning-in-a-haystack context.
- **LongBench v2 (Bai et al., 2025):** 41% → 52% (**+11 pts**). Requires deeper multi-task understanding and aggregation over realistic long contexts.
- **OOLONG-real (Bertsch et al., 2025):** 14% → 38% (**+24 pts**). The largest gain—OOLONG-real forces comparing/aggregating events across distant context spans, exactly the record-keeping regime Chained RLM targets.
- **Headline aggregate:** Chained RLM beats the Regular LLM baseline on all four benchmarks with an **average absolute gain of 13.75 percentage points** at pass@1.
- **Resource trade-off (Table 2, averages):** Regular LLM uses 1.0 root call / 0.0 handoffs / 48.8k input tokens / 5.8k output tokens / **$0.125 per task**; Chained RLM uses 2.6 root calls / 1.6 handoffs / 98.8k input tokens / 21.8k output tokens / **$0.315 per task** (≈2.5× the cost). Per-benchmark, the most expensive is OOLONG-real at 3.4 roots / 132k input tokens / $0.44 per task—also where the accuracy gain is largest.
- **Where chaining pays off:** The authors explicitly frame a practical trade-off—on retrieval-heavy tasks (RULER) chaining may not justify its cost, whereas on long-context record-keeping / multi-step aggregation tasks (OOLONG-real, BABILong) the additional roots produce a much larger accuracy gain.

## Critical Assessment

- **Novelty:** Moderate and honestly scoped. The core idea—re-invoking the same model as fresh roots with an externalized text memory—is an incremental but non-trivial synthesis of RLM (Zhang et al., 2025), Reflexion's episodic memory, and DSPy-style module composition. The genuinely novel piece is the **artifact-as-first-class-continuation-object** design plus the insistence on plain-text (no JSON) handoffs; this is a real engineering contribution but not a new learning signal.
- **Rigor:** The controlled single-model protocol is a strength, but several gaps weaken the claims:
  - **No compute-matched baseline.** The paper acknowledges a "compute-matched setting" is left to a future version. The fairest test would be a Regular LLM given the same total token budget (e.g., self-consistency with k≈2.6 samples, or a longer single trajectory with more tool iterations). Without it, part of the gain may simply be "more compute," not "fresh roots + artifacts." This is the single biggest threat to the headline +13.75 pts.
  - **No ablations.** There is no experiment isolating the contribution of (a) the blackboard alone, (b) durable artifacts vs. blackboard-only, (c) chain length R, (d) the "must read artifacts before FINAL" instruction, or (e) the recent-work excerpt E_r. The architecture has four state components (B, A, H, E) but only the whole package is evaluated.
  - **Single model.** Only GPT-5-mini is tested. Generalization to open models (e.g., a Llama/Qwen-class model) or a stronger model (where single-trajectory performance may already saturate) is unverified.
  - **Weak baseline label.** The "Regular LLM" is a single greedy-ish tool-calling trajectory; a stronger baseline like self-consistency or a single RLM call (the direct predecessor) would tighten the comparison.
- **Reproducibility:** Reasonably good for a system paper. Algorithm 1, the full Root Instruction prompt, and the exact handoff format are all provided; benchmarks are public; the model is a named API. However, no code release is mentioned, per-task sample sizes L are not reported, variance/confidence intervals on the accuracy numbers are absent, and the maximum chain length R and per-root iteration/sub-LLM caps are stated to exist ("we record the maximum chain length…") but their actual values are not given.
- **Significance:** Practically useful as an inference recipe for hard aggregation tasks, and the artifact-mediated-handoff framing is a clean, transferable idea. But the magnitude of the OOLONG-real jump (14%→38%) on a benchmark where the baseline is near chance suggests the baseline is the weak point as much as Chained RLM is strong; the result is informative but should be read as "single-trajectory GPT-5-mini fails OOLONG-real, chaining rescues it," not as evidence of a general capability breakthrough.
- **Red flags:**
  - The 14% Regular-LLM baseline on OOLONG-real is low enough that the +24 pts headline is partly an artifact of a fragile baseline; the paper does not discuss this asymmetry critically.
  - The cost table shows chaining is 2.5× more expensive on average, yet no cost-normalized accuracy metric (e.g., accuracy per dollar) is reported, which is the metric a practitioner actually needs.
  - Typos ("teh resoning", "resoyrce", "Y AML") suggest a rushed preprint; minor, but it lowers confidence in detail-orientation across the experimental setup.

## Strengths

- Training-free, RL-free, and verifier-free by default: drops in on any tool-using LLM without weight changes or extra training data.
- The plain-text, no-JSON handoff and artifact design is elegant and robust to formatting drift—a genuinely useful engineering insight.
- Clean single-model controlled protocol isolates the architecture as the variable.
- Largest gains land exactly where the authors predict (aggregation/record-keeping), and they honestly state chaining may not be worth it on retrieval-heavy tasks like RULER.
- Full system prompt and pseudocode (Algorithm 1) are included, lowering the barrier to reimplementation.

## Limitations

- **No compute-matched baseline:** the headline gains conflate "fresh roots + artifacts" with "≈2.5× more tokens." Self-consistency or a token-matched single trajectory is missing.
- **No ablations** over the four state components, chain length R, or the artifact-read instruction.
- **Single model (GPT-5-mini only):** generalization to open/stronger models unknown.
- **Host does not enforce** that a root reads artifacts before finalizing—allows premature answers.
- **Error propagation / drift:** if Root 0 writes a flawed event definition or artifact structure, later roots may preserve the wrong structure; the chain can also drift by ignoring a good artifact and restarting from a worse state (acknowledged in §6).
- **Cost:** 2.5–3× more inference spend; no accuracy-per-dollar analysis.
- **Missing statistical detail:** no sample sizes L, no variance/CI, no reported values for R or per-root iteration/sub-LLM caps.

## Relevance

与长上下文 LLM 推理、智能体（agentic）架构及推理时（inference-time）方法增强直接相关：Chained RLM 提供了一种"以全新根节点 + 持久化 artifact 做阶段化审计"的工程范式，可启发多步推理、RAG 记忆管理与 agent 工作流设计中关于"状态外化与可审计交接"的思路，对关注 long-context benchmark 评测与 agent memory 的研究者具有参考价值。

## Questions for Further Exploration

- Under a **compute-matched** budget (same total input/output tokens), does Chained RLM still beat self-consistency or a single longer RLM trajectory? This is the decisive test for the "fresh roots" claim.
- How much of the gain comes from the **artifact** specifically vs. the **blackboard/summary** alone? An ablation removing artifacts would isolate the core contribution.
- Does the method **transfer to open models** (e.g., Llama-3, Qwen2.5), and does the gain shrink or vanish on a stronger model (e.g., GPT-5-class) where single-trajectory OOLONG-real accuracy may already be high?
- How sensitive is accuracy to the **maximum chain length R**, and is there a sweet spot beyond which extra roots stop helping (diminishing or negative returns)?
- Can a lightweight **host-side check** (e.g., require `list_artifacts()` + read before FINAL) reduce premature answers without sacrificing generality?
- What is the **accuracy-per-dollar** picture, and on which benchmark families is Chained RLM actually Pareto-efficient vs. the baseline?
- How robust is the chain to **Root-0 errors**—does artifact auditing reliably recover from a wrong initial event definition, or does the structure persist incorrectly?
