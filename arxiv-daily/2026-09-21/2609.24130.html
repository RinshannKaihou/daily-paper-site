Key finding

55% of agent-authored rules that fix their target failure silently break behavior the agent had already mastered — self-modification needs admission control.

PaperSelf-Healing Harness for Runtime Oversight of Agent Self-Modification

01 Key metric

Each fixed its triggering failure yet regressed a protected case — per-case drops of 0.60 task_completion, 0.25 outcome_correct. A target-only admission test would have admitted all 211.

02 Why this matters

First quantified answer to why “keep every self-improvement” fails — a must-read empirical warning for anyone building self-improving LLM agents.

A Methodology — the Detect → Notice → Heal → Validate loop

A runtime envelope around an unmodified agent: the model keeps proposal rights, an external gate owns persistence. No weight access — works with closed-weight models.

DETECT

Per-turn metric ladder M₁ progress/coherence, M₂ tool-call correctness, M₃ explanatory, M₀ outcome. Gate fires stall (w=10, γ=0.02) or regression (δ=0.15).

→
NOTICE

Findings land in a workspace inbox; rules live as scope-partitioned files pulled via tool calls — never injected wholesale.

→
HEAL

The agent drafts a natural-language candidate rule — provisional authority for the current turn only.

→
VALIDATE · the gate

Replay ≤3 failure + 2 protected sessions. Admit iff target Δ ≥ +0.05 and every metric Δ > −0.05. Forward-trial fallback; a corpus-level guard periodically re-scores the whole active rule set.

  • Deterministic gate. Admission is a code-level predicate (Algorithm 2) — whole-program properties like “gate never fires” are provable; verdicts are promote / retire / pending.
  • Context hygiene. Standing context grows with rule-file count, not learned volume; notices, rules and traces are fetched on demand.
  • Corpus guard. Periodically re-tests the accumulated rule set against captured cases; fails the corpus if any previously-evaluated case drops ≥ 0.05.
  • Fair pairing. Both arms share identical execution order, prompts, seeds and metric definitions (PandaProbe); gate constants frozen across all 16 runs.
Protocol  16 matched Baseline–Harness pairs = {AppWorld 168, Terminal-Bench 10, τ² airline 50 / retail 114} × {GPT-5-terra, GPT-Luna, Claude-Haiku-4.5, Claude-Sonnet-5}, k=4 trials, seed 1, 100-turn budget, task-level bootstrap (10,000 resamples).

+ Strengths

What this paper gets right.

  • A real safety-relevant measurement: the 55% collateral-regression rate is the field’s first quantified answer to “why not keep every self-improvement?”
  • Closed-weight friendly: no gradients or logits; rules are explicit, inspectable, reversible, composable; the gate is deterministic.
  • Strict hygiene: paired arms share execution order, seed, prompts, metrics; frozen gate constants; 10,000-resample bootstrap.
  • Exceptional transparency: an “Experiments not run” appendix, full hyperparameter table, and a self-audit of judge bias (14% → 0.17%) with both arms re-run.
  • Useful negatives: corpus erosion and replay unavailability on Terminal-Bench reported plainly, not buried.

− Limitations

Where to press before adopting.

  • Thin statistical strength: 2/16 CIs exclude zero; single seed (seed 1); Terminal-Bench has just 10 tasks.
  • Missing key control: the B′ arm (immediate admission ± corpus guard) was designed but never run — pre-admission validation vs. downstream guard is not isolated.
  • Bounded coverage: ≤5 replays per event, 2 protected cases per round — 211 conflicts are a lower bound; unmeasured behaviors and safety properties sit outside the guarantee.
  • Replay confound: Terminal-Bench resolves 0% of verdicts by replay; replay availability is entangled with benchmark+model.
  • Heavy tax: 1.7–7× wall-clock and ≈52% more spend for a +0.022-class effect; the async variant is implemented but not benchmarked.
  • Scope: non-adversarial threat model; three text-only benchmark families.

? Questions for further exploration

  1. How much of the benefit comes from pre-admission validation vs. the corpus guard, given the B′ ablation was never executed?
  2. Can per-case replayed deltas be aggregated into a corpus-level statistical test with proper power analysis?
  3. What surrogate evidence can replace replay in non-deterministic, side-effectful environments (Terminal-Bench resolved 0% by replay)?
  4. Do findings transfer to held-out tasks? Freezing the corpus and testing on unseen tasks would separate durable improvement from within-stream intervention.
  5. Does the 55% collateral-regression rate hold when safety/permission violations — not task metrics — route through the gate?
  6. Does the asynchronous barrier variant preserve the same retention decisions at acceptable latency?
