> **一句话总结：** 北大团队提出"智能体脚手架蒸馏"：让一个 harnessing agent 挂在学生模型响应边界上，依据从进化脚手架 h* 适配而来的私有参考脚手架 K，逐条审查并最小化修正学生在极简目标脚手架（单 Bash 工具 mini-SWE-agent）下提出的动作，把修正后的轨迹做 LoRA SFT 蒸馏进 Qwen3.5-9B 权重——部署时完全卸掉 h* 和审查者，宏平均任务成功率从 23.3% 升至 44.3%（+21.0 分），反超带着 h* 部署的 41.7%，且 28 个脚手架独有行为模式平均恢复 82.3%；训练时 agent-as-harness 在前沿模型上也以 81.1% 平均成功率胜过 code-as-harness 的 78.1%。

> **TL;DR:** Harness-Zero introduces "agent harness distillation": a harnessing agent reviews each proposal from the student (Qwen3.5-9B) running under a minimal Bash-only mini-SWE-agent harness, correcting it on-policy using guidance from an evolved DeepAgents-style harness h* (adapted into a private reference harness K), then LoRA-SFT distills the reviewed trajectories into the student's weights. At deployment — with h*, K, and the reviewer removed — the distilled 9B model raises three-benchmark macro-average success from 23.3% to 44.3% (+21.0 pts, +90.1% relative), beating the 41.7% of the same base model with h* still attached, the 20.5% of DeepAgents, and the 15.9% of Claude Code. Ablations on USPTO Retrosynthesis show the mechanism matters: SFT on GPT-5.6 Sol teacher rollouts or on student-under-h* trajectories yields only 12.0% (no gain), oracle-answer review only 15.0%, while harness-guided review reaches 30.0% — and the distilled model recovers 82.3% of 28 h*-exclusive behavior patterns that the base model scores 0% on by construction.

## 核心贡献

- **问题形式化——脚手架蒸馏（agent harness distillation）：** 首次把"进化脚手架带来的收益能否写进模型权重、从而在部署时卸掉专用脚手架"定义为一个独立研究问题；此前 harness 优化（meta-harness 等）只改进外部脚手架，收益始终与部署时的脚手架绑定。
- **方法——agent-as-harness：** 源脚手架与目标脚手架在动作空间和信息可见性上不同，h* 的指导无法直接监督 h 下的学生。Harness-Zero 用一个 harnessing agent 在学生的响应边界处逐条审查（PASS 或以目标动作空间内完整响应做最小相干替换），把 h* 适配成的私有参考脚手架 K 转译为可执行纠正；审查是私有的（不进学生可见上下文），审查者不可见隐藏答案或验证器反馈。
- **训练配方：** 对审查后的 rollout（含未改动的 PASS 响应与替换响应）做 LoRA SFT，并掩盖审查者视角的推理痕迹（REPLACE 决策的 reasoning 按审查者语气模式打码）、过滤私有字符串，保证轨迹"像学生自己写的"。
- **三域实验证据链：** (1) 推理时 agent-as-harness 在 6 个基准×模型组合上平均 81.1%，胜过 code-as-harness 的 78.1%；(2) 蒸馏后 Qwen3.5-9B 在裸脚手架下宏平均 23.3%→44.3%，超过带 h* 的 41.7%，而 DeepAgents（20.5%）和 Claude Code（15.9%）反而伤害 9B 基座；(3) 消融证明有效监督来自"脚手架引导的审查"而非更强示范者或答案访问；(4) 28 个 h* 独有行为模式平均恢复 82.3%。

## Key Contributions

- **Formalizes agent harness distillation:** the first framework that transfers behaviors induced by an optimized (evolved) harness into model parameters, so deployment needs only a fixed minimal target harness (single-Bash mini-SWE-agent style) instead of a retained-and-routed collection of specialized harnesses.
- **Proposes agent-as-harness** to solve the action-space/information mismatch between source and target harnesses: a harnessing agent wraps the student at its response boundary and converts private guidance from the adapted reference harness K into minimal coherent corrections expressed natively in the target harness's action space, turning harness guidance into on-policy SFT demonstrations.
- **Demonstrates across three domains** (SpreadsheetBench Verified, AppWorld, USPTO Retrosynthesis) that (a) agent-as-harness beats code-as-harness at inference time on frontier models (81.1% vs 78.1% average over six benchmark-model settings), (b) distillation lifts Qwen3.5-9B from 23.3% to 44.3% macro-average under the bare harness, exceeding 41.7% with the evolved harness still attached, and (c) 82.3% of 28 harness-exclusive behavioral patterns are recovered.
- **Provides an unusually careful ablation suite** (Table 3) separating review quality from demonstration strength: teacher rollouts, student-under-h* trajectories, empty-K review, and oracle-answer review all collapse to 5–15% on USPTO vs 30.0% for the full recipe, isolating "harness-guided on-policy review" as the active ingredient.

## Methodology

The method has three stages (h = fixed minimal target harness, h* = evolved student-side harness, K = private reference harness used only by the harnessing agent):

1. **Harness evolution & adaptation.** On each benchmark's training split, a three-round, failure-driven evolution loop (Kimi K3 under Kimi Code) grows a DeepAgents-style harness h* with tools, middleware, skills, and memory; components must address failure patterns shared across tasks. A harnessing agent then adapts each component of h* into K: tools become *action recipes* (specifications for constructing student-native bash/Python equivalents), student-side middleware becomes *review middleware* (privately alerting the reviewer when a condition is met), and skills/memory become review guidance and failure patterns. A domain prompt states the review policy.
2. **Agent-as-harness trajectory collection.** The student runs under h and proposes a response each turn. The harnessing agent (GPT-5.6 Sol) reviews it using K with strictly limited privilege: it reads only K, cannot inspect hidden solutions or verifier feedback, and cannot act on the environment — additional evidence must be obtained by proposing an action under h (e.g., replacing a premature finish with a script that checks the student's work, so both check and result enter the student-visible trajectory). Decisions are PASS (execute unchanged) or REPLACE (rewrite the full response as the smallest coherent correction valid under h, preserving the student's line of thought). A REPLACE budget (3–5 per trial) rewards selectivity. Only accepted responses enter the student-visible trajectory; the review stays private.
3. **SFT on reviewed trajectories.** LoRA SFT (rank 32, batch 8, 65,536-token sequences, lr peak 2×10⁻⁴ with 5% warmup, 2 epochs, Tinker recipe, seed 42) on accepted responses; reviewer-perspective reasoning spans are masked and private strings filtered. Training sets: 487 rollouts for SpreadsheetBench (kept only if verifier reward = 1.0 and no execution exception), 282 for AppWorld, 500 for USPTO (all kept, so ablations train on identical data).

Evaluation: SpreadsheetBench Verified (100 held-out tasks, pass@1), AppWorld (168 test_norm tasks / 56 scenarios, scenario goal completion), USPTO Retrosynthesis (100 held-out tasks, pass@1), all single-run in the Harbor framework. Behavioral internalization is measured with deterministic trajectory detectors mined from h*'s components over 28 patterns (18 SpreadsheetBench, 6 USPTO, 4 AppWorld), each scored only on tasks where the base model exhibits the pattern under h* but never under h.

## Results & Highlights

- **Distillation beats the harness itself (Table 2):** On the three-benchmark macro-average, Harness-Zero lifts Qwen3.5-9B under the bare mini-SWE-agent harness from 23.3% to 44.3% (+21.0 pts, +90.1% relative), surpassing the 41.7% the same base model achieves with the evolved harness h* still attached; generic harnesses hurt the 9B model instead — DeepAgents 20.5% (−2.8) and Claude Code 15.9% (−7.4).
- **Per-benchmark breakdown:** AppWorld SGC jumps 26.8% → 58.9% (+32.1); SpreadsheetBench pass@1 31.0% → 44.0% (vs 49.0% with h*); on USPTO pass@1 the distilled model reaches 30.0% vs 12.0% base but trails h*'s 38.0% — the paper attributes the gap to h* also encoding chemical priors (reaction templates, executable SMILES validation) that SFT on ~500 trajectories cannot internalize.
- **Inference-time: agent-as-harness > code-as-harness (Table 1):** Averaged over six benchmark-model settings with GPT-5.6 Sol and DeepSeek-V4-Pro, agent-as-harness with adapted K scores 81.1% vs 78.1% for code-as-harness (meta-harness) and 68.6% for bare mini-SWE-agent (+27.6% vs +12.5% relative); the empty-K control averages only 69.2%, showing review alone explains little of the gain. Notably h* itself hurts GPT-5.6 Sol on AppWorld (94.6% vs 96.4% bare), so the advantage is not uniform.
- **The ablation isolates the mechanism (Table 3, USPTO test pass@1 under h):** Harness-Zero 30.0% vs 12.0% for SFT on GPT-5.6 Sol teacher rollouts (despite the teacher succeeding on 52.0% of collection tasks), 5.0% for teacher-under-h* rollouts, 12.0% for student-under-h* trajectories, 11.0% for review with empty K, and just 15.0% for review given the oracle answer (98.6% collection success) — collection success does not predict distillation value; oracle access teaches non-generalizable shortcut corrections.
- **Behavioral internalization (Table 4):** The distilled model recovers 82.3% of 28 harness-exclusive behavior patterns on average (base model is 0% by construction), e.g., "Validate with RDKit" 60/60 (100%), "Avoid fragile coordinates" 19/19 (100%), "Canonicalize SMILES" 73/73 (100%), but weakly for "Retrieve complete pages" on AppWorld at 21/53 (40%) and "Read cached formulas" at 28/43 (65%).
- **Cost:** agent-as-harness collection on USPTO takes 237.2 s/trial, about 2.4× mini-SWE-agent's 100.1 s; the overhead exists only during trajectory collection, not after distillation.

## Authors & Credibility

The team is from Peking University's State Key Laboratory of General Artificial Intelligence (Haoran Ye, Haonan Dong, Zhaochen Su, Guojie Song) with Yuxing Lu (PKU College of Future Technology / Google) and HKUST affiliation listed. Senior author Guojie Song leads the group; first author Haoran Ye has a track record in this exact area (ReEvo at NeurIPS 2024 on LLM hyper-heuristics, and Meta Context Engineering via Agentic Skill Evolution at ICML 2026 — both self-cited). The work is frank about failure cases: the paper voluntarily reports that the method fails on weaker reviewer models (Appendix F), that USPTO distillation trails h*, and that its own collection costs 2.4× latency. Code is released at github.com/metaevo-ai/harness-zero, and an AI-use statement discloses assistant roles. Overall credibility is high; the only caution is that several compared systems (Claude Code, DeepAgents, mini-SWE-agent) and commercial models (GPT-5.6 Sol, DeepSeek-V4-Pro, Kimi K3) are configured by the authors, so harness-fairness depends on their tuning effort.

## Critical Assessment

- **Novelty is real but layered on prior art.** The response-boundary review idea is a clean generalization of privileged-guidance distillation (OPHSD, EvoHarness-RL), and the paper itself positions it that way; the genuinely new bits are (a) distilling a *complete tool-using agent harness* rather than a single mechanism, and (b) the component-level h*→K adaptation (tool→action recipe, middleware→review middleware). The "Harness-Zero" name oversells slightly — the target harness is not zero, just minimal.
- **Rigor is above average for this subfield, with two caveats.** The Table 3 ablation (teacher rollouts vs student rollouts vs empty-K vs oracle-answer review) is exactly the experiment most distillation papers skip, and Obs 6 (action-space mismatch: teacher-under-h* rollouts *degrade* the student to 5.0%) is a genuinely instructive negative result. However, every headline number is a **single run with seed 42 fixed** — no variance or error bars anywhere, on modest test sets (100 tasks for SpreadsheetBench and USPTO, 168 for AppWorld), so a 2–3 point margin like agent-as-harness's 81.1% vs 78.1% could be noise.
- **Missing ablations.** All distillation uses LoRA rank 32, 2 epochs, ~300–500 trajectories, on exactly one base model (Qwen3.5-9B); there is no scaling experiment in model size, data size, or full fine-tuning, and no second student to support the claim that the recipe generalizes across base models. The behavioral-recovery detectors are authored by the same team that built h*, so the 82.3% figure, while cleverly grounded by the 0%-by-construction baseline, is only as meaningful as the detector design.
- **Data quirk worth noting:** SpreadsheetBench trajectories are filtered to verifier reward 1.0 while USPTO keeps *all* 500 trials — the paper flags that USPTO full-data training beats success-only training, but this asymmetry means the two domains' training distributions are not comparable across the ablation table.
- **The reviewer is a stronger model than the student (GPT-5.6 Sol vs Qwen3.5-9B).** The empty-K control (11.0%) convincingly shows generic frontier review is not the source of the gain, but the framework's dependence on a *capable* reviewer is severe: Appendix F shows that with the same model as both student and reviewer, agent-as-harness flips to **−12.0% on Qwen3.6-35B-A3B** relative to meta-harness (weakest reviewer replaces 66% of steps), and −1.0% on DeepSeek-V4-Flash. "Harness distillation" is thus currently a *frontier-model-assisted* training recipe, not a self-contained pipeline.
- **Red flag, mildly:** the frontier-model rows of Table 1 reuse h* that was evolved on Qwen3.5-9B training tasks, acknowledged in the paper, so the 81.1% vs 78.1% comparison may understate code-as-harness if h* had been evolved per-model.

## Strengths

- A well-motivated and previously unformulated problem: converting harness-optimization gains into weights instead of paying deployment-time routing/scaffolding costs forever.
- The agent-as-harness design elegantly sidesteps the action-space mismatch that makes naive cross-harness distillation fail, and the failure of the naive baselines (Obs 6) is shown empirically, not assumed.
- Ablation quality is the paper's best feature: five alternative supervision sources on identical USPTO data, an oracle-answer control that proves answer access is the wrong supervision signal (98.6% collection success → 15.0% test), and a behavioral analysis with per-pattern recovery rates.
- Honest limitations section: the paper quantifies its own collection overhead (2.4× latency), names the weaker-reviewer failure mode, and concedes the USPTO knowledge-transfer gap instead of hiding it.
- Practical significance for agent engineers: AppWorld +32.1 and macro +21.0 on a 9B model with only ~300–500 trajectories and LoRA is a very favorable data/compute-to-gain ratio.

## Limitations

- Requires a strong harnessing model; with weak reviewers the review becomes harmful (−12.0% for Qwen3.6-35B-A3B relative to meta-harness), and review without evolved guidance falls below the bare harness (11.0 vs 12.0 base pass@1 on USPTO).
- Collection is expensive: an extra review model call per step, 237.2 s vs 100.1 s per USPTO trial; the paper itself notes reviewing every proposal with pass/replace-only actions is coarse-grained control, leaving selective review, token insertion, and preference learning to future work.
- Deep domain knowledge does not transfer: on USPTO the distilled model (30.0%) stays 8 points below deployment with h* (38.0%); some harness mechanisms (e.g., context management) are not expressible as student responses at all.
- Single base model (Qwen3.5-9B), LoRA only, single run per number with no variance reported; test sets of 100–168 tasks.
- The method does not eliminate the harness — it narrows what the deployment harness must provide — so the "Zero" in the name should be read as "zero specialized harness retained," not "no harness."

## Questions for Further Exploration

- Would the recipe survive a second, weaker or different-family student (e.g., a 4B or a non-Qwen model), or does the harnessing-agent-to-student capability gap have a hard floor?
- The oracle-answer control shows answer access yields non-generalizable corrections (98.6% → 15.0%); what is the minimal subset of K's procedural guidance that explains most of the 30.0% vs 15.0% gap?
- Can preference learning exploit the (rejected proposal, accepted replacement) pairs already produced by the review loop, as the authors suggest, instead of discarding rejections?
- Does iterative distillation compose — i.e., can the distilled student's h* be re-evolved and re-distilled (recursive self-improvement) without degradation, given the single-run noise and the USPTO knowledge ceiling?
- How much of the USPTO gap (30.0% vs 38.0% with h*) closes with more trajectories versus requiring pretraining-time chemical knowledge, e.g., by mixing distilled trajectories with continued pretraining on reaction corpora?
