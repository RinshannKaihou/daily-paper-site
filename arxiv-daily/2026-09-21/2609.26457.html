Why this matters

The strongest empirical evidence yet that AI agents can sustainably improve their own search and context-management — with mechanisms you can borrow today.

「智能体改进自身」迄今最扎实的实证之一；被发现的 bandit 搜索与有界上下文压缩机制有直接的工程借鉴价值。

Critical edge

The recursion is one level deep — only the inner agent improves; the 3-seed ignition test can’t show a discovered agent drives the loop better.

3 of 4 “held-out” benchmarks share task families with the selection set; true OOD evidence is a single WeatherBench 2 task.

01

Methodology — bi-level RSI at the harness layer

Outer loop · rewrites the harness AIDE_human (Claude Opus 4.7)

Reads the incumbent agent and its grade, proposes a rewrite of its harness code.

rewrite accepted only if private grade g(a) improves
Inner loop · the improved artifact AIDE₀ (Gemini 3 Flash)

Draft · improve · debug on task code under a fixed dollar budget; sees only the public signal rpub.

solutions scored on private held-out data → averaged into g(a)
Selection benchmark · sole acceptance signal

Three AI R&D task families — ML engineering · heuristic algorithm engineering · harness engineering. Equal per-task budgets: a win means a better algorithm, not more compute.

the accepted incumbent becomes the codebase the next rewrite edits
  • Signal decoupling: the inner loop optimizes r_pub, the outer selects on r_priv — the agent can’t directly fit its own selector.
  • Discovered mechanisms: UCB1 bandit over 5 draft strategies; fork the global best every 5 steps; failure memory injected when bug rate ≥ 15%.

03

Strengths

  • Fixed per-task dollar budgets make this an efficiency claim, not a compute claim — the right control for “the loop found a better algorithm.”
  • r_pub / r_priv decoupling is a clean, well-motivated guard against the obvious failure mode of self-referential loops.
  • Largest gains land on the only truly OOD benchmark — and the in-distribution vs OOD distinction is labeled transparently, not hidden.
  • The human baseline is no strawman: AIDE_human beats all six FML-Bench-scored agents (19.6% vs 19.3 for the runner-up).
  • Honest self-reporting: inconclusive ignition test, non-monotonic checkpoints, and a full appendix of rejected proposals with deltas.
  • The loop once repaired a broken held-out scoring script instead of exploiting it — a concrete, verifiable instance of the anti-hacking claim.
04

Limitations

  • Only the inner agent improves; the outer loop stays human-engineered — “recursive” gains are one level deep.
  • 3 of 4 generalization benchmarks share task families with the selection set; true OOD is one WeatherBench 2 task with huge baseline error bars.
  • No per-rewrite ablation: which of the 7 accepted rewrites drives the gains — or the hacking drop — is unknown; AIDE₈₅ is “difficult to interpret.”
  • Acceptance rides on a noisy private grade; ~25% of rejected rewrites actually beat the incumbent on the agent-visible signal.
  • Everything load-bearing is proprietary (selection benchmark, AIDE_human, AIDE²); no stated code or checkpoint release.
  • Yield varies widely across runs (7 / 2 / 4 accepted rewrites), so the 8-day loop’s cost-effectiveness isn’t established.
05

Questions for further exploration

  1. Can the reward-hacking drop be attributed to specific rewrites, or is it aggregate drift? A per-rewrite ablation would separate mechanism from correlation.
  2. Does the grade trajectory keep rising past 100 nodes — what does it look like at 500 or 1000 steps?
  3. Would a public selection benchmark preserve the gains, making the loop reproducible outside Weco?
  4. How many seeds and outer-loop steps does the ignition test need before a discovered agent can claim to out-drive AIDE_human?
  5. Do the bounded-prompt / compression mechanisms transfer to agent architectures beyond AIDE’s draft–improve–debug tree search?
  6. Both checkpoints converged on the same WeatherBench numerics — a signature of a general policy, or of the selection benchmark’s harness-engineering bias?
