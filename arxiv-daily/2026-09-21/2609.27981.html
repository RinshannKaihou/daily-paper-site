Key metric

5–10pp

more KV retention chosen by certification than by naive empirical thresholding

All four Llama LongBench candidates passed the ≤5% empirical gate (4.00–4.83%) yet none certified. Finite-sample cutoff: 47/1200 = 3.92% vs the nominal 5%.

Why this matters

Swaps “how much does average quality drop” for “what fraction of requests materially degrade” — a certified reliability wrapper for any existing eviction method.

Critical edge

The certificate covers only a task-uniform mixture — the paper’s own Table 4 shows per-task risks of 10–29% once one task dominates.

Methodology — fixed-sequence Learn-then-Test

Compressor-agnostic outer layer: the eviction algorithm is untouched; only its deployment point is certified.

01 — CONTRACT

Risk, not budget

Per-request degradation Δπ = Ufull − Uπ; a request fails when Δ > τ. Require failure rate ≤ ε with confidence 1−δ. Main setting: τ=.10, ε=.05, δ=.05.

02 — TEST

Certify down the grid

Candidates pre-ordered conservative → aggressive; task-stratified CAL set scored with binomial lower-tail p-values (Hoeffding-bounded); stop at the first non-rejection. For n=1200 the cutoff is 47 events = 3.92%.

03 — FALLBACK

Full KV if nothing passes

If no candidate certifies, return full KV — risk 0 by definition, so the contract is trivially satisfied. No monotonicity of risk in retention is assumed.

04 — SETUP

Grids & benchmarks

Retention .80→.20 step .05; ReFreeKV thresholds .0005→.03. LongBench 12 tasks × 100 (n=1200); RULER-32K 13 × 100 (n=1300). Deterministic greedy decoding; RTX A6000, FlashAttention-2.

Strengths

  • Clean statistics: task-stratified calibration gives an exactly binomial count; Hoeffding bounds handle strata; equality kept in the null; no monotonicity assumed.
  • Noise-free paired protocol: same prompt, deterministic greedy decoding — Δπ is well-defined and sampling-free.
  • Compressor-agnostic: one framework calibrates fixed-ratio, layer-adaptive, and request-adaptive allocation alike.
  • Honest reporting: candid limitations plus a post-hoc Bonferroni + Clopper-Pearson analysis that surfaces per-task risks against the paper’s own certificate.
  • Usable tuning map: Tables 1–3 read directly as a (τ, ε) → retention deployment reference.

Limitations

  • Mixture-bound guarantee: no per-task certificates, no robustness to distribution shift or traffic skew.
  • Narrow empirical base: only 7–8B models; coarse 0.05 retention grids; transfer to larger or GQA/MLA architectures untested.
  • Pre-registration required: contract, grids, and order fixed before CAL inspection; post-hoc selection (Table 3) is descriptive only.
  • Relative, not absolute: a 0%-risk policy can still have poor absolute utility; τ=.10 means different things across ROUGE / accuracy / edit metrics.
  • No system measurements: latency, throughput, and serving-stack benefit are unmeasured — “deployment” rests on the retention-ratio proxy.
  • Offline cost: ~1200–1300 paired generations per model-compressor-benchmark setting, repeated per contract change; no code release mentioned.

Questions for further exploration

  1. Q1How fast does coverage break when production traffic deviates from the uniform task mix — and can task-weighted or re-stratified calibration restore it?
  2. Q2Can continuous / anytime-valid searches replace the 0.05-step grid and avoid artifacts like SnapKV’s RULER fallback?
  3. Q3Is a τ=.10 normalized-metric drop a semantically meaningful definition of “material” across LongBench’s mixed metrics?
  4. Q4Can per-task guarantees be obtained with stratified multiplicity control at acceptable calibration cost?
  5. Q5What end-to-end latency / throughput savings appear in a real serving stack, and how does the ~1300-request calibration amortize across model updates?
  6. Q6Does the framework extend to GQA, MLA, and sliding-window + KV hybrids, where per-head eviction dynamics differ?
