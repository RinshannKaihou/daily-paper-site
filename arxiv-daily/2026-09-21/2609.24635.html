Key finding

An operation's KV cache stores recoverable state — but the base model reads it as a routing address, almost never as a value.

Queried box bindings answered with every state line masked (OP_ONLY), across Llama-3.2-1B / 3.1-8B / Mistral-7B. On 300 unseen code items: 0.152 → 0.627–0.688, a >4× gain. Ordinary fine-tuning stays ≤0.25 — the control does not close the gap.

Why this matters

The cleanest recent causal evidence that transformers keep world state in the KV cache — plus a reusable frozen-writer / trained-reader recipe for probing it.

“近期最干净的机制证据之一：模型如何在上下文中维护和读取世界状态（而非仅路由）。” — Relevance

Critical edge

No capacity-matched control adapter was run, so it remains open whether isolation training exposes a pre-existing record or computes a new lookup over the carrier.

Compounded by an NF4-quantized 8B writer with no bf16 control — non-trivial when the object of study is the numerical K/V content itself.

Methodology

A frozen writer leaves the cache untouched; only the reader trains — so anything it recovers must already be in the cache.

  1. 01Writer. The base model (LoRA off) reads prefix + state lines + operation line; the K/V it leaves at every position and layer is the carrier, recomputed without gradients.
  2. 02Reader. Same weights plus a rank-16 LoRA active only at query/answer rows — it can never modify the cache it reads.
  3. 03Views. Attention to chosen prefix positions set to −∞: OPEN / OP_ONLY (only the operation visible) / BLOCKED (zero-information floor).
  4. 04Two arms. Isolation training (ISO) trains under the mask; ordinary fine-tuning (ORD) sees everything — the optimization control.
  5. 05Transplants. Swap in a donor world's carrier (D_ROLE / D_SAME / UNREL controls) to test causality; metrics: donor binding, redirection, payload readout.
  6. 06Tasks & models. Box swaps, four code assignments, ToMi, GSM8K on Llama-3.2-1B, Llama-3.1-8B (NF4), Mistral-7B; three seeds per core claim.

The bill — where it breaks

  • Payload localizes to a single operand-name token, layers 12–15 of 32 (Mistral: 14–17) — transplanting only that token reproduces readout (0.475–0.525); overwriting it costs 0.35–0.43.
  • Trained on values 10–25 → collapses on 30–45 (0.030–0.168); a held-out fourth operation fails 256/256.
  • Open-book cost: GSM8K drops 0.970 → 0.460–0.885 — a scientific probe, not a deployable improvement.

▸ how far this generalizes → Limitations
Strengths
  • Clean causal design — frozen writer + gradient-free cache recomputation makes “anything recovered was already in the cache” almost axiomatic; the ORD arm rules out “more optimization”.
  • Claims survive their own ablations — BLOCKED floors (0.040–0.047), mismatched donors, filler lines (0.055), source-line masking zeroes redirection (0.642 → 0.000).
  • Rare two-sided localization — single-token site shown sufficient (transplant alone: 0.475–0.525) and necessary (overwrite: −0.35 to −0.43).
  • Second-family replication — Mistral-7B reproduces routing, payload and the layer site (14–17); three seeds throughout the core experiments.
  • Unusually candid limitations section naming its own seed variance, quantization gap and scope limits.
Limitations
  • Trained access vs pre-existing record unresolved — no capacity-matched adapter or rank sweep (App. J); only Mistral-7B shows a weak native payload (0.192).
  • Coverage-bound — values 10–25 → 30–45 collapses (0.030–0.168), 200–299 stays near zero (0.015/0.025/0.000) even after 10–99 training.
  • Not deployable — open-book accuracy cost (GSM8K 0.970 → 0.460–0.885; unseen code −0.017 to −0.168).
  • Scale & precision — 1B–8B models only; NF4-quantized 8B writer with no bf16 control; single-step synthetic tasks, sequential write-after-write untested.
  • GSM8K is the weakest breadth link — 0.205–0.253 under masking is far from useful; no transplant/localization analysis on ToMi or GSM8K.
Questions for further exploration
  • Q1Does the layers 12–15 operand-token site survive deeper models, multi-hop operation chains, or bf16 writers (removing the NF4 confound)?
  • Q2Exposing a pre-existing record, or computing over the carrier? A capacity-matched control adapter and rank sweep would settle it.
  • Q3Can payload access be elicited without training — activation steering, prompt formatting, inference-time?
  • Q4How does the record behave under sequential write-after-write updates, where current readers break (256/256)?
  • Q5Is the open-book cost (GSM8K 0.970 → 0.460–0.885) inherent to mask-trained adapters, or removable with mixed-view training?
  • Q6MMLU still scores 0.598 with the question masked — is the gap specific to operation-local state, and which applications actually need it?
