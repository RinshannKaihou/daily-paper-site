# Silent Failures in Agent–Tool Interaction: An Audit of ToolUniverse

> **一句话总结：** 作者在 ToolUniverse（MCP 接口的科学工具平台）上对 15 个生物学工具、198 个测试用例做了一轮"LLM 候选发现 + 人工复核"的审计，确认 91 起**静默失败**——工具调用表面成功、无任何报错，但返回的信息不完整/被改写/语义漂移，且限制未向下披露；其中 API 部分缺口（L3，47 例）与 Wrapper 部分缺口（L5，23 例）合计占约 77%，而 Agent 可用性缺口（L6）为 0 例，7/15 个工具在其测试用例上失败率超过 50%（Expression Atlas 达 75%），据此提出"上下文可靠性（contextual reliability）"概念及 7 条测试/披露/监控建议。

> **TL;DR:** This paper audits "silent failures" — tool invocations that return HTTP-success but incomplete, transformed, or semantically shifted information that the agent silently treats as complete evidence — across 15 biological tools (Expression Atlas, BV-BRC, AMPSphere, CTIS, ChIP-Atlas, KEGG, Reactome, CIViC, ClinicalTrials.gov, BiGG Models, EMDB, ClinVar, CryoET, ClinGen, InterPro) inside the ToolUniverse MCP environment. Using a Cursor-agent-driven candidate discovery plus human verification of 198 test cases, the authors confirm 91 failures and localize them with a 7-locus taxonomy (Tool Limitation → API Gap/Partial Gap → Wrapper Gap/Partial Gap → Agent Usability/Interpretation). The distribution is strikingly asymmetric: API partial gap (L3) accounts for 47 of 91 and wrapper partial gap (L5) for 23 — together ~77% — while agent usability gap (L6) counts 0; 7 of 15 tools show confirmed failures on >50% of their test cases (Expression Atlas 75%, BV-BRC 67%, AMPSphere 67%, CTIS/ChIP-Atlas/KEGG/Reactome 53% each). The paper proposes "contextual reliability" — whether qualifiers, provenance, scope, and meaning survive the whole Agent→Wrapper→API→Tool chain — rather than binary task success. Worth reading if you build or evaluate agents that call domain APIs; skip if you need benchmarks, baselines, or a fixable method (there are none — it is an empirical audit).

## 核心贡献

- **定义并命名"静默失败"：** 工具调用 (1) 表面成功、(2) 返回信息对目标任务而言不完整/被转换/有歧义、(3) 该限制未向下游用户或 agent 披露——与"响亮失败"（如 API 超时）相对。并提出**静默放大**：上游工具层的部分限制被 agent 当作完整证据，转化为更强的下游科学结论（如 collapsing phospho-SMAD3→SMAD3 抹平磷酸化状态、EMDB 每页 1000 行的截断被当作全集）。
- **提出 7 类失败区位（Failure Locus）分类法：** L1 工具固有限制、L2 API 完全缺口、L3 API 部分缺口、L4 Wrapper 完全缺口、L5 Wrapper 部分缺口、L6 Agent 可用性缺口（输出可用但 agent 未用）、L7 Agent 解释缺口（agent 误读输出）。沿 User intent → Agent → Wrapper → API → Tool/Data 链路定位失败.origin。
- **在 ToolUniverse 上完成实证审计：** 从 63 个主工具（含 285+ 关联工具）中抽 15 个（104 个关联工具），用 Cursor agent 从工具文档/Web UI/API 文档/GitHub issues 中挖掘候选失败，自动 + 人工复核后确认 **91 起失败**；L3(47) + L5(23) 占 77%，L6 为 0；7/15 工具失败率 >50%（Expression Atlas 75%）。
- **按 10 个分析维度量化问题类型：** 91 个失败产生 134 次问题计数——Completeness 最高（28），其次 Ranking & Relevance（21）、Result Appropriateness（20）、Source & Data Attribution（18）；按问题类型，Missing Data/Fields 最多（38），Agent Misinterpretation 仅 5。
- **提出"上下文可靠性"概念与 7 条工程建议：** 可度量的上下文可靠性指标、qualifier 保持性的自动化测试、运行时越界告警与披露、限制沿 wrapper→agent 的传播机制、部署时与周期性测试、机器可读的能力差异披露、工具生态监控。

## Key Contributions

- **A crisp definition of "silent failure" in agent–tool interaction:** an invocation that (1) appears successful, (2) returns information incomplete, transformed, ambiguous, or otherwise insufficient for the intended task, and (3) does not disclose this limitation downstream — distinct from "loud failures" (e.g., an API timeout). The companion concept of **silent amplification** describes how an upstream partial response becomes a stronger downstream scientific claim when the agent treats it as complete evidence.
- **A 7-locus failure taxonomy** localizing where along the chain (User intent → Agent → Wrapper → API → Tool/Data) the failure originates: L1 Tool Limitation, L2 API Gap, L3 API Partial Gap, L4 Wrapper Gap, L5 Wrapper Partial Gap, L6 Agent Usability Gap, L7 Agent Interpretation Gap.
- **An empirical audit of ToolUniverse:** from 63 main tools (285+ associated tools), 15 tools (104 associated ToolUniverse tools) were sampled; LLM-driven (Cursor agent) candidate discovery from docs/WebUI/API/GitHub issues, automated re-execution, and human verification of 198 test cases yielded **91 confirmed silent failures**. L3 (47) + L5 (23) account for ~77%; L6 counts 0; 7/15 tools fail on >50% of their cases (Expression Atlas 75%).
- **Quantification across 10 analysis dimensions:** 91 failures produce 134 issue occurrences — Completeness dominates (28), then Ranking & Relevance (21), Result Appropriateness (20), Source & Data Attribution (18); by issue type, Missing Data/Fields leads (38) while Agent Misinterpretation is only 5.
- **A "contextual reliability" proposal plus 7 engineering directions:** measurable contextual-reliability indicators, automated tests for qualifier preservation/provenance/scope, runtime triggers and disclosures when an interaction crosses a reliability boundary, limitation propagation through wrappers, deployment-time + periodic testing, machine-readable disclosure of API-vs-WebUI capability differences, and tool-ecosystem monitoring.

## Methodology

**Environment and sampling.** ToolUniverse (an open platform of 285+ scientific tools exposed via MCP) was set up with the AntiGravity CLI agent as the executing agent. From 63 main tools, 15 were selected for deep analysis (104 associated ToolUniverse tools) covering biological databases and computational resources: Expression Atlas, BV-BRC, AMPSphere, CTIS, ChIP-Atlas, ClinGen, ClinVar, ClinicalTrials.gov, CryoET Data Portal, EMDB, Expression Atlas, InterPro, KEGG, Reactome, BiGG Models, CIViC. ToolUniverse itself is positioned as the *experimental environment*, not the object of study.

**Failure candidate discovery.** For each sampled tool the authors assembled a "tool context" — extracted content, structured JSON, extracted URLs, tool documentation, WebUI details, API documentation, user manuals, release notes, and reported GitHub issues — and gave it to a Cursor agent instructed to find conflicts, disagreements, implementation issues, and Web/API wrapper inconsistencies. The comparison targeted functionality, fields, parameters, filtering, ranking, pagination, formats, semantics, provenance, and temporal changes (e.g., API/WebUI drift across tool releases).

**Test-case generation.** Candidate failures were converted to concrete test cases under five disciplines: tool-level specification (identify the main tool, not the exact ToolUniverse wrapper); exact tool names restricted to ToolUniverse; complete inputs (real accessions like DP0086 rather than "TPS3"); concrete scientific inputs (real biological entities, not hypothetical examples); and failure isolation (the query targets the suspected failure rather than asking the agent to diagnose completeness itself — e.g., "Use DisProt_get_entry with accession=DP0086; report the full tool output, listing every field returned. Do not invent fields.").

**Repeated execution.** Each candidate ran once; if classified as a failure, four additional queries targeted the same failure; if it passed, two additional queries were executed, with different concrete scientific inputs where possible, to check generalization beyond a single test case.

**Automated evaluation.** A Cursor agent acted as judge over execution traces, labeling each run Fail / False Positive / Unverified–Needs Additional Validation, then mapped confirmed failures to the L1–L7 loci.

**Manual validation.** Two authors manually reviewed 15 main tools / 198 test cases, re-performing the Cursor-agent-driven verification via the API and ToolUniverse-in-AntiGravity-CLI, checking (1) Fact Checking — is the candidate appropriate for the scenario, verified against WebUI availability — and (2) Judgment Validation — is the LLM's judgment valid and are there alternative tool functionalities that could explain the outcome without a real failure. Only human-verified outcomes are reported in the results.

**Measurement rubric.** Each failure was classified along 10 analysis dimensions (completeness, correctness, appropriateness, consistency, reliability, attribution, interpretation, relevance, context, purpose alignment), with rubrics in Appendix A and dimension→locus→instance tables in Appendix B.

## Results & Highlights

- **Scale and locus distribution:** 91 confirmed failures across the 15 manually validated tools (198 test cases reviewed). API partial gap (L3) is the dominant locus with **47 of 91** failures and wrapper partial gap (L5) adds **23**, together **70/91 ≈ 77%** of human-verified failures — versus **0** confirmed cases of agent usability gap (L6) and only 6 at agent interpretation gap (L7); tool limitations (L1) and API gaps (L2) contribute 5 each, wrapper complete gaps (L4) 2.
- **Per-tool failure rates:** 7 of 15 tools exhibit confirmed failures on more than 50% of their test cases — Expression Atlas **75%**, BV-BRC **67%**, AMPSphere **67%**, and CTIS, ChIP-Atlas, KEGG, Reactome at **53%** each; the remaining 8 tools stay at or below 50% (e.g., ClinVar 8%, CryoET 7%, ClinGen 8% per Figure 3A). Within the L3/L5-dominated tools, BiGG Models, BV-BRC, and CIViC route **100%** of their failures through L3/L5 and Reactome **88%**.
- **Analysis dimensions (91 failures → 134 issue occurrences, multi-label):** Completeness is the most frequent dimension at **28** occurrences, followed by Ranking & Relevance (**21**) and Result Appropriateness (**20**), with Source & Data Attribution at **18**; by issue type, Missing Data/Fields accounts for **38** occurrences vs. Agent Misinterpretation at only **5** and Error Handling/False Success at **4** — i.e., partial information dominates over outright retrieval failure or agent-side error.
- **Representative confirmed cases (each manually verified):** EMDB caps rows per page at **1000** and presents truncated results as complete; Expression Atlas legacy E-MTAB-xxxx accessions return **0 results** after the GTEX rebranding with no alias table; BiGG's "Glucose" substring search returns non-glucose-metabolizing genes in top hits; BiGG model RC1080 returns a null `organism` field via the API despite being shown on the web; the CryoET GraphQL API links child datasets to deposition 10014 but the `CryoET_list_depositions` wrapper schema omits the field entirely; ClinVar's `ContributesToAggregateClassification` XML attribute is parsed but not exposed by `ClinVar_get`, preventing contributing vs. non-contributing distinction; the ChIP-Atlas agent misreads MACS2's −10·log10(Q-value) as a raw confidence score; KEGG's agent misapplies AND vs OR logic on module completeness rules.
- **No baselines by design:** this is an audit, not a comparative method paper — the numbers above are frequencies within a single environment, and the authors explicitly state the proportions are "not to be considered as representative of typical silent failures" because the candidate-discovery process shapes them.

## Authors & Credibility

- All three authors — Shreya Gopalan, Devansh Singh, and Sundarapirapurnan Narayanan — share a single generic affiliation, "AI Tech Ethics" (aitechethics.com emails). No institutional lab, no funding statement, and no prior-work pointer specific to these authors is given, so external credibility signals are thin.
- Methodological credibility is helped by the audit discipline: LLM-proposed candidates were re-executed with repeated runs (4 extra queries on failure, 2 on pass), judged Fail/False-Positive/Unverified, and only human-verified cases (two authors, Fact Checking + Judgment Validation) enter the results. The paper is honest that ToolUniverse is the environment, not the target, and has an unusually candid Limitations section.
- However, no code, prompts, test-case suite, or per-case evidence traces are stated as released, and no inter-annotator agreement statistic is reported — reproducibility of the audit itself rests entirely on the prose description.

## Critical Assessment

- **Novelty is real but framing-dependent.** Prior agent-failure work (Where LLM agents fail, AgentDebug, ToolFailBench) targets planning/memory/system-level or hallucinated-call failures; isolating the *information-preservation* question across the Agent→Wrapper→API→Tool boundary — success-without-completeness — is a genuinely under-examined axis, and the 7-locus taxonomy is a useful vocabulary. But "silent failure" overlaps heavily with long-known API-undermining and partial-results problems in the provenance/Web-API-evolution literature ([22],[33] are cited), so the conceptual delta is mostly the agentic framing.
- **The 77% L3+L5 headline is partly an artifact of where the authors looked.** Candidate generation explicitly targeted contract disagreements, wrapper inconsistencies, and field-level mismatches between WebUI and API — exactly the signatures of L3/L5. The authors admit the proportions "are not to be considered as representative," which is commendable, but it also means the central quantitative claim should be read as "in a search biased toward API/wrapper mismatches, most confirmed failures were API/wrapper mismatches" — near-circular.
- **Tiny denominators behind per-tool percentages.** Figure 3A shows per-tool totals of 8–12 test cases (e.g., "10 (67%)" for AMPSphere, "9 (75%)" for Expression Atlas); the sharp-sounding per-locus percentages (CryoET 33% L7, ClinicalTrials.gov 25% L4) are computed over single-digit case counts with no confidence intervals. The repeated-run protocol is also non-uniform (4 extra runs on fail vs 2 on pass), which inflates evidence depth for presumed failures relative to passes.
- **Manual validation is two authors, unblinded, no agreement statistic.** Judgment Validation asks whether alternative tool functionalities might explain the outcome — the most error-prone call in the whole pipeline — yet no Cohen's kappa, no adjudication protocol, and no release of the 198 test cases is provided, so the "human-verified" guarantee cannot be independently checked.
- **The proposed remedy is a research agenda, not a mechanism.** "Contextual reliability" is defined but never operationalized: no metric, no scoring function, no experiment showing that measuring it catches failures the task-success metrics miss. The 7 recommendations are sensible but generic (test more, disclose more, monitor more).
- **Red flags:** generic affiliation with no institutional anchor; no artifact release despite the audit being trivially packageable (the test cases and rubrics would be the paper's most valuable artifact); Figure 3/4 numbers are read off bar charts rather than tabulated in the main text for the 15 tools.

## Strengths

- The **silent failure vs loud failure** distinction is crisp, memorable, and immediately actionable for anyone building agent+API pipelines; the silent-amplification mechanism (partial evidence → stronger claim) is well motivated with concrete biology examples (phospho-SMAD3→SMAD3 collapsing; EMDB 1000-row cap).
- The **7-locus taxonomy** localizes failures along the full chain and cleanly separates tool-side from wrapper-side from agent-side causes — a vocabulary missing from current agent-failure benchmarks.
- **Evidence discipline unusual for audit papers:** candidate failures were re-executed multiple times with varied concrete inputs, machine-judged, then human-verified; only human-verified outcomes are reported, and Unverified cases are excluded rather than counted.
- The **case studies are specific and checkable** (RC1080 null organism field; CryoET deposition 10014 child datasets; ClinVar ContributesToAggregateClassification XML attribute; MACS2 −10·log10(Q) misreading; KEGG AND/OR module logic), giving the qualitative claims verifiable grounding.
- An unusually **honest limitations section**: the authors explicitly disclaim exhaustiveness, acknowledge LLM-driven candidate generation biases the proportions, and state the results are an empirical characterization of observed risks, not an estimate of failure rates.

## Limitations

- **Scope:** 15 of 63 main tools, single environment (ToolUniverse + AntiGravity CLI), single domain (biology); no evidence the distribution transfers to other tool ecosystems or agent frameworks.
- **LLM-in-the-loop at both ends:** Cursor agent generates candidates *and* serves as the automated judge; only final adjudication is human, over 198 cases, by two unblinded authors with no reported agreement metric.
- **Non-representative sampling admitted by the authors:** the candidate-discovery bias toward API/wrapper contract mismatches makes the L3+L5 dominance (77%) partly self-fulfilling.
- **Small per-tool samples:** 8–12 test cases per tool, no confidence intervals, non-uniform re-run protocol (4 extra queries on fail vs 2 on pass).
- **No artifacts released (as stated in the text):** no test suite, no prompts, no per-case traces, no ToolUniverse configuration — the audit cannot be reproduced or extended as-is.
- **Contextual reliability is undefined operationally:** no metric, threshold, or validation that measuring it would have caught the 91 failures; temporal drift ("evolutionary audit") is proposed but only 1 occurrence was observed.
- APIs and wrappers evolve continuously, so the snapshot decays; the authors note the same E-MTAB→E-GTEX pair was independently verified earlier, hinting at temporal churn in the findings themselves.

## Relevance

这篇论文直击 agent 工具调用可靠性评估的盲区——"调用成功 ≠ 信息完整"，其 7 类失败区位分类法可直接用于设计更严苛的 agent 基准与评测维度（超越任务成功率），对构建科学工作流 agent（尤其依赖领域 API/wrapper 的场景）非常有参考价值。其"上下文可靠性"思路与你关注的 agentic AI 评测、benchmark 方法论方向高度契合。

## Questions for Further Exploration

- Can the 7-locus taxonomy be turned into an automated benchmark that *samples the full chain* uniformly (not biased toward contract mismatches) to estimate an unbiased silent-failure rate — and does L6=0 survive that unbiased sampling?
- What is a minimal operational metric for "contextual reliability" (qualifier preservation, provenance, scope) that an agent harness could compute per call, and does thresholding it catch the 91 audited failures without drowning users in false alarms?
- Should tool limitations propagate as structured metadata through wrappers into the agent's context (machine-readable disclosure), and how much does that cost in tokens/latency versus the downstream rework it prevents?
- How do these findings transfer beyond biology — e.g., to finance, law, or code APIs — where the WebUI-vs-API capability gap may be larger or smaller?
- Do stronger agents (better tool-use training) reduce L7 interpretation failures, or do they amplify silent failures by trusting partial outputs more confidently? The audit found only 5 agent-misinterpretation cases — is that the agent's skill or the test design?
