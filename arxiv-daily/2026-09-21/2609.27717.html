Why this matters

An open, verifiable recipe for turning crowdsourced skill docs into agent training environments — directly reusable for quality-controlling custom agent data pipelines.

Critical edge

SkillsBench — a headline benchmark — and the “strongest comparable baseline” both come from the authors’ own lab: a win that is suggestive, not neutral, evidence.

Methodology — skill docs → verified environments → SFT

  1. Skill cards → templates. Human-written OpenClaw skills (12 categories / 63 sub-categories) are distilled into skill cards; each sub-category gets one hand-built template fixing the task blueprint, input assets, runtime, and checker spec — only the skill varies the workflow.
  2. Environment + verifier. Each instantiation pairs instruction, input assets, and a Docker-packaged runtime with a code-based outcome verifier that guards against input tampering, answer copying, bypassed requirements, and fabricated outputs.
  3. Two-level acceptance. Feasibility plus reference-solution execution first; then a contrastive run with vs. without the skill — only (1,0) outcomes earn Skill-Dep. (1,081 of 2,756 environments, 39.2%); the rest remain Verifier-Passed fallbacks. ≈4.5 h construction per accepted task.
  4. Multi-harness sampling. Claude Code × DeepSeek V4 Pro / GLM-5.2 and Codex × GPT-5.4 / Nex-N2-Pro run inside the Docker environments; each rollout is judged by the task’s own verifier, keeping failures for failure-mode analysis.
  5. SFT. Full-parameter long-context SFT of Qwen3.5-35B-A3B (16× H200) on the verified trajectories → SkillGym-Agent.

48,152 trials → 8,364 verified trajectories (17.4%) · avg 49.0 tool calls · 63.4k tokens · 35.2 steps · peak 318 steps

Strengths

  • New data source — crowdsourced skill registries as procedural workflows; a concrete, reusable skill-to-task recipe.
  • Verification-first design — code checkers with explicit anti-shortcut tests plus a contrastive (1,0) acceptance run, more principled than most auto-generated agent environments.
  • Scale with diversity — 2,756 environments, 8,364 trajectories, 4 harness–teacher pairs; long-horizon statistics rare in open agent corpora.
  • Honest reporting — Skill-Dep. vs Verifier-Passed kept distinct, failures kept and analyzed, harness confounds spelled out in the appendix.
  • The right control — gains persist without inference-time skills, supporting the internalization claim.

Limitations

  • SFT-only — the promised outcome-reward RL is infrastructure, not a validated result in this paper.
  • Weak dependency evidence — skill labels rest on one reference configuration, and no ablation separates skill-specific learning from generic long-horizon practice.
  • Home-team evaluation — SkillsBench and the Agents-AI baseline share the authors’ lab; Codex comparisons carry a system-prompt confound; no confidence intervals.
  • Uneven coverage — business/development dominate; culinary-arts has one accepted task and zero successful trajectories.
  • One base model, one scale — construction is costly (4.5 h/task with GPT-5.4, 63 hand templates, 16 H200 GPUs).

Questions for further exploration

  1. Would RL on the released verifiers close the GDPval gap to frontier models (SFT peaks at 1179 vs Sonnet 4.6’s 1295), or does SFT cap out?
  2. Do the +199 Elo / +28 pp gains replicate on a different base model, or is the effect Qwen-specific?
  3. Skill-specific workflows or generic long-horizon exposure? A control SFT on difficulty-matched non-skill trajectories would answer it.
  4. Do contrastively-certified Skill-Dep. environments (39.2%) contribute disproportionate training value vs Verifier-Passed ones?
  5. Do skill-dependency labels transfer to stronger or weaker agents than the reference configuration that certified them?
