> **一句话总结：** 提出"自愈外骨骼"（Harness）：让 LLM 智能体可以自行起草行为规则（修改自身操作指令），但由一个模型无关的外部运行时层通过 Detect→Notice→Heal→Validate 闭环做准入控制——用重放（replay）历史失败与受保护会话做"多指标不回退"测试，只有既修复触发失败、又不损害任何已成功行为的规则才能跨 episode 持久化；16 组配对实验发现 383 条被否决规则中 211 条（55%）修复了触发失败却损害了受保护行为，而只看目标指标的提升会让这 211 条全部准入，直接实证了"局部改进 ≠ 可持久化的改进"。

> **TL;DR:** The paper reframes persistent LLM-agent self-modification as admission control: an unmodified agent authors natural-language behavioral rules, but an external, model-agnostic runtime (the Harness) decides persistence via replay-based multi-metric non-regression tests plus a corpus-level guard. On AppWorld with GPT-5-terra the Harness raises the task-completion score from 0.701 to 0.723 (Δs = +0.022, 95% CI [+0.006, +0.040], p = 0.010) and pass@1 from 0.018 to 0.054 versus the unmodified baseline loop; across 16 matched pairs (AppWorld, Terminal-Bench, τ²-bench × 4 models) the key empirical finding is collateral regression — 211 of 383 (55%) replay-rejected rules fixed their triggering failure while degrading a previously succeeded protected case, all 211 of which a target-only retention rule would have admitted. The cost is real: ~1.25× context, 1.7–7× wall-clock, and only 2 of 16 paired confidence intervals exclude zero.

## 核心贡献

- **将持久自改形式化为"准入控制"（admission control for self-modification）**：智能体生成与保留解耦——agent 只拥有"提案权"（起草行为规则），跨 episode 的持久化由外部运行时决定；保留条件是"修复触发失败 + 在受保护行为上多指标不回退"，而非仅仅"有改进"。
- **模型无关的运行时架构**：Detect（轨迹级 stall/regression 检测，逐 turn 的指标阶梯 M₁ 进度/coherence、M₂ 工具调用正确性、M₃ 解释性、M₄ 结果校验）→ Notice（写入外部工作区）→ Heal（agent 起草候选规则）→ Validate（重放已捕获失败会话 + 最多 2 个受保护会话，要求目标指标提升 ≥ δ_prom=0.05 且所有已测指标回退 ≤ δ_reg=0.05）；重放不可用时退化为前向试跑（forward trial），另有语料级回归守卫重测累计活跃规则集。
- **"附带损害"（collateral regression）的实证发现**：383 条重放否决的规则中 211 条（55%）修复了触发失败但使受保护行为回退（单个重放用例上 task_completion 降 0.60、outcome_correct 降 0.25）；只按目标指标保留规则会把这 211 条全部准入——说明按准入测试衡量的 agent 提案大多是"局部正确但对受保护行为有害"。
- **三基准 × 四模型的配对评测**：16 组 Baseline–Harness 配对（AppWorld、Terminal-Bench、τ²-bench airline/retail × GPT-5-terra、GPT-Luna、Claude-Haiku-4.5、Claude-Sonnet-5，k=4 次重试，任务级 bootstrap），覆盖可复现性、验证路径、累计规则效应与开销（约 1.25× 上下文、1.7–7× 墙钟）。
- **与 11 个代表性系统的新颖性边界对比**（Table 7）：Reflexion、Voyager、AutoManual、Agent Workflow Memory、A-MEM、STOP、Darwin Gödel Machine 等均不同时满足"经度量验证（V）+ 回退守卫（R）+ 运行时触发（T）"，Harness 是唯一三者兼备的持久自改机制。

## Key Contributions

- **Admission control formulation**: separates update generation (agent-authored rules) from retention (external runtime), where a self-authored update persists only after demonstrating improvement ≥ δ_prom on its triggering failure while satisfying a multi-metric non-regression constraint on protected behavior.
- **Model-agnostic runtime architecture**: a Detect → Notice → Heal → Validate loop with a tiered per-turn metric ladder, replay scoring of captured failure/protected sessions, forward-trial fallback when replay is unavailable, and a corpus-level regression guard that periodically re-tests the accumulated active rule set — all without touching model weights and compatible with closed-weight models.
- **Empirical evidence of collateral regression**: 211 of 383 replay-based rejections (55%) improved their triggering failure while degrading protected behavior (observed per-case drops of 0.60 in task_completion and 0.25 in outcome_correct); a target-only retention rule would have admitted all 211.
- **Paired evaluation over 16 matched Baseline–Harness runs** across three benchmark families, four models, and four splits (k=4 trials, seed-controlled, task-level bootstrap with 10,000 resamples), covering reliability, rule lifecycles (2,306 proposed / 1,244 promoted / 1,062 retired), validator robustness, and overhead.
- **Novelty boundary**: per its Table 7, no prior system (Reflexion, Voyager, Generative Agents, ExpEL, AutoManual, Agent Workflow Memory, A-MEM, RAG memory, STOP, Darwin Gödel Machine, Constitutional AI) simultaneously provides validated, regression-guarded, runtime-triggered persistent self-modification.

## Methodology

**Overview and control model.** The Harness is a runtime envelope around an *unmodified* agent (fixed policy + prompt; the model itself never changes). The agent can author natural-language behavioral rules in an external rule workspace, but only validated revisions become durable. Four stages alternate: (1) **Detect** — a trace-level evaluation service E scores every trajectory on a metric ladder: tier-1 (progress M₁ and embedding-based coherence; judged per trace), tier-2 (tool-call/argument correctness M₂, last trace only), tier-3 (explanatory, opt-in), plus an optional outcome verifier M₀. A trajectory gate keeps a running peak per metric and fires a `stall` (window w=10 traces without gain ≥ γ_gain=0.02) or `regression` (drop below peak by δ_drop=0.15) condition; only corroborated findings become evidence for retention decisions. (2) **Notice** — findings are written to a workspace inbox; rules live as scope-partitioned files behind a compact index (c(R) = c₀ ⊕ i(R)), so standing context grows with rule-file count, not learned volume (RQ4-style mechanics: notices/rules/traces are pulled via tool calls, never injected). (3) **Heal** — after a notice, the agent drafts a candidate rule (provisional authority during the turn). (4) **Validate** — the evidence gate controls *cross-episode* persistence: replay session on M₁∪M₂, check the admission rule ∃j: Δ_j(s_i) ≥ δ_prom=0.05 (improvement on the target metric) AND ∀j: Δ_j(s_i) > −δ_reg=0.05 (no regression on any measured metric), over at most 3 failure cases + 2 protected cases per round; inconclusive replay falls back to a forward trial (n=3 sessions, promote if flagged rate p̂ = 0 or p̂ ≤ p₀ − δ_prom). Retention verdicts are promote / retire / pending. A **corpus-level regression guard** periodically re-scores the whole active rule set against captured cases and fails the corpus if any previously evaluated case drops by ≥ δ_reg.

**Protocol.** Paired A/B: identical agent loop, task set, prompts, and execution order in both arms; the only difference is Detect/Notice/Heal/Validate enablement. Four splits (AppWorld test_normal 168 tasks, Terminal-Bench sample2.0 10, τ² airline 50, retail 114), four models (GPT-5-terra, GPT-Luna, Claude-Haiku-4.5, Claude-Sonnet-5), k=4 trials, seed 1, 100-turn budget → 16 matched pairs. Statistics: paired per-task bootstrap intervals over 10,000 task-level resamples; every gate constant is held fixed across all benchmarks and models (hyperparameter table with package defaults vs study values in the appendix).

## Results & Highlights

- **Headline gain (RQ1)**: AppWorld + GPT-5-terra: task-completion score s = 0.701 → 0.723 with the Harness (Δs = +0.022, 95% CI [+0.006, +0.040], p = 0.010), and pass@1 rises 0.018 → 0.054 — the study's largest paired evaluation and one of only two pairs whose CI excludes zero (the other: AppWorld + Claude-Sonnet-5, Δs = +0.032, CI [+0.003, +0.061], p = 0.03). Across all 16 pairs the Harness leads on pass@1 in 14 (one tie) and on all-k-trials pass^k in 12 (tying 4); the τ² family shows the smallest gains (+0.012 to +0.032).
- **Collateral regression (RQ2, the central finding)**: of 383 replay-decided retirements, 211 (55%) improved their triggering failure but regressed a protected case; per replayed case, observed regressions include a 0.60 decrease in task_completion and a 0.25 decrease in outcome_correct. Under the observed replay evidence, a target-only retention rule would have admitted **all 211** — i.e., most agent-authored proposals are locally correct but harmful to previously succeeded behavior.
- **Rule lifecycle scale (RQ3)**: across 16 runs the agent proposed 2,306 rules; 1,244 were promoted and 1,062 retired. Per-run promotion rates span 0.41–0.63; promotion verdicts distribute across metrics (task_completion 48%, tool_correct 17%, outcome_correct 17%, coherence 14%, argument_correctness 4%) rather than concentrating on one signal.
- **Repeatability over first-try success**: on Terminal-Bench + Claude-Haiku-4.5, pass@1 is flat (0.600 → 0.600) while pass^k rises 0.000 → 0.200; for Claude-Sonnet-5 pass@1 actually *drops* (0.571 → 0.429) while pass^k rises 0.000 → 0.533 (Table 9: Δpass@1 = −0.143 vs Δpass^k = +0.333) — only 3 of 16 pairs satisfy Δpass^k > Δpass@1, reported as suggestive, not validated.
- **Corpus-level erosion (RQ4)**: AppWorld + GPT-Luna's gain decays monotonically from +0.017 in execution quartile Q1 to −0.016 in Q4 (p = 0.022) while its input tokens per turn rise 1.50× → 2.52× over the baseline — per-candidate admission alone does not control accumulated-state degradation (context dilution / rule interference).
- **Evaluator-noise audit**: 14% of sampled judge rationales blamed read-only Harness meta-tools and produced 31 spurious zero scores; after neutrality guidance, 0.17% and 1 respectively (over 4,800 sampled rationales), with both arms re-run under corrected prompts.
- **Overhead (RQ5)**: mean context usage 1.25× baseline (per-pair 0.90×–1.77×), agent turns 1.0 → 1.8 per trial, execution spend $177.06 → $211.46 across 16 pairs plus $92.90 repair spend, and wall-clock up 1.7–7× due to the synchronous per-turn barrier.

## Authors & Credibility

The core group — Sina Tayebati, Divake Kumar, Nastaran Darabi, and Amit Ranjan Trivedi — is from the University of Illinois Chicago, with Ranganath Krishnan from AI Labs, Capital One. The team has a visible track record on exactly this problem family: they cite their own prior work on TRACER (trajectory risk aggregation for critical episodes), EigenShield (inference-time jailbreak defense), and adaptive conformal risk management, and they built PandaProbe, the tracing/evaluation infrastructure that supplies identical metric definitions and gate parameters to both arms. The methodology disclosure states Capital One does not use and has no plans to use this methodology, which partially mitigates industry-conflict concerns. Credibility is further raised by unusually candid reporting: an appendix section literally titled "Experiments not run", a full hyperparameter table (defaults vs study values), and an evaluator-bias audit of their own judge prompts.

## Critical Assessment

The strongest asset is the collateral-regression finding, and it is genuinely novel: 55% of rejected rules being "locally correct, globally harmful" is a concrete, falsifiable statistic that no prior self-modification paper (STOP, Darwin Gödel Machine, AutoManual) measures, and it directly justifies the admission-control framing. The fixed-gate discipline (one constant tuned across all benchmarks and models) and the paired same-execution-order protocol are also above the bar for this subfield.

However, the reliability gains themselves are thin. Only **2 of 16 paired CIs exclude zero**; everything else is directional, and the headline AppWorld/terra delta (+0.022 on a 0–1 score) would not survive much scrutiny without the bootstrap machinery. Terminal-Bench has just **10 tasks**, making its pass-rate swings (e.g., sonnet-5 pass@1 falling 0.571 → 0.429) statistically fragile, and all runs use **seed 1 only** with no seed variation — the authors admit this, but it means the pass^k repeatability story rests on single-seed evidence. The decisive ablation is missing: the B′ arm (immediate admission with the same corpus guard, with and without the corpus guard) was designed but **not run**, so the paper cannot isolate how much of the benefit comes from pre-admission validation versus the downstream guard — RQ2's 211-conflict evidence substitutes for it only indirectly. Replay availability is confounded with benchmark+model (Terminal-Bench resolves 0% of verdicts by replay because its sandbox cannot re-run tasks), so the replay-vs-forward-trial comparison in RQ3 is observational, not causal. The guard's coverage is bounded — at most 2 unranked protected cases per round — so the 211 conflicts are a lower bound on incidence, and the corpus guard explicitly does not control degradation on *unmeasured* behaviors or safety properties. Finally, the cost side is under-sold relative to the benefit side: 1.7–7× wall-clock from a synchronous barrier and roughly 52% more spend ($211.46 + $92.90 repair vs $177.06) is a heavy tax for a +0.022 median-class effect, and no latency-amortized variant (e.g., the async barrier they implement but do not evaluate as a headline) is benchmarked.

## Strengths

- **A real safety-relevant measurement**: the 55% collateral-regression rate and the target-only-vs-multi-metric admission contrast give the field its first quantified answer to "why not just keep every self-improvement?"
- **Architectural honesty about closed-weight models**: no gradient or logit access needed; rules are explicit, inspectable, reversible, and composable, and the gate is deterministic (Algorithm 2) — whole-program properties like "gate fires never" are provable from code.
- **Strict experimental hygiene**: paired arms share identical execution order, seed, prompts, and metric definitions (PandaProbe), task-level bootstrap with 10,000 resamples, and gate constants frozen across all 16 runs.
- **Exceptional transparency**: "Experiments not run" appendix, complete hyperparameter table, per-run cost tables, and a self-audit of LLM-judge bias (14% → 0.17% blaming rate) with both arms re-run on corrected prompts.
- **Useful negative results**: context dilution / rule interference causing gains to erode by Q4 (AppWorld/luna +0.017 → −0.016) and replay unavailability on Terminal-Bench are reported plainly rather than buried.

## Limitations

- **Statistical strength**: only 2/16 paired intervals exclude zero; most effects are directional; Terminal-Bench (10 tasks) and single-seed (seed 1) runs limit precision, especially for the pass^k repeatability claim.
- **Missing key control**: the B′ arm (immediate admission ± corpus guard) was not executed, so the marginal benefit of pre-admission validation is not isolated.
- **Coverage bounds on the guard**: at most 5 sessions replayed per event and 2 protected cases per round; the 211 conflicts estimate incidence under that coverage, and unmeasured behaviors/safety violations are entirely outside the guarantee.
- **Replay dependence**: Terminal-Bench resolves 0% of verdicts by replay (non-replayable sandbox), and replay availability is confounded with benchmark+model, weakening causal attribution in RQ3.
- **Overhead**: synchronous per-turn barrier costs 1.7–7× wall-clock; total spend rises ~52% including repair; a 1.25× mean context increase erodes gains as the corpus grows (Q1→Q4 decay).
- **Threat model scope**: the agent is assumed non-adversarial within its tool surface; persistent edits via other channels and adversarial circumvention are open; evaluation is limited to three text-based benchmark families.

## Relevance

这篇工作直击当前 agent 研究的核心痛点：让智能体自我改进（写规则/记忆/workflow）时，如何在不重训模型、不信任模型自知的前提下做持久化把关。它把"经验性学习/记忆类 agent 系统"（A-MEM、AutoManual、SGD 一类）普遍缺失的"回归守卫"变成了可度量的准入测试，并给出了 55% 附带损害这一对所有做 agent self-improvement 的人都有警示意义的数字；对关注 agent 安全与可靠性的研究者是必读级实证。

## Questions for Further Exploration

- The B′ arm (immediate admission + corpus guard, and immediate admission with no guard at all) was designed but not run — how much of the observed benefit actually comes from pre-admission validation versus the downstream corpus guard?
- The corpus guard cannot register degradation that falls below δ_reg but is distributed across tasks (granularity limit) — can per-case replayed deltas be aggregated into a corpus-level statistical test with proper power analysis?
- Replay is unavailable in non-deterministic or side-effectful environments (Terminal-Bench resolved 0% by replay); what surrogate evidence (forward trials, canonical traces, simulators) can substitute without losing the non-regression guarantee?
- Do the findings transfer to held-out tasks? The protocol measures online reliability during adaptation only; freezing the validated corpus and evaluating on unseen tasks would separate reusable behavioral improvement from within-stream intervention.
- The 55% collateral-regression rate is measured under this metric ladder (M₁–M₄) — how does it change when safety- or permission-violation properties, rather than task performance metrics, are routed through the gate?
- With 1.7–7× wall-clock overhead from the synchronous barrier, does the asynchronous variant (timeout-marked turns, concurrent evaluation) preserve the same retention decisions at acceptable latency?
