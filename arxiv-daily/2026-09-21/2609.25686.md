> **一句话总结：** 作者提出"状态耦合阶梯"（state-coupling ladder）：固定任务规则、模型和配对 episode，只改变任务状态到达 agent 的强度——原始对话记录（raw transcript）→ 每轮展示精确状态的文本清单（checklist）→ 由 LLM 编译的任务状态机每轮下发指令（directive gate）→ 在 agent 与执行通道之间拦截违规操作的强制门（enforcement gate）——并用执行回执（receipt）驱动的精确载荷匹配（无 LLM 裁判）打分。在 3 个模型 × 2 种推理模式 × 2 个域上得出四个无逐轮推理时恒成立的发现：展示准确状态并不可靠（Qwen3-235B 无思考模式下 raw transcript 严格 episode 成功率仅 0.38–0.50）；agent 自己写的未验证 ledger（0.70/0.79）反而胜过被展示的始终准确的清单（0.52/0.59）；directive 的收益与模型服从度成正比；enforcement 不需要服从度（Qwen3-235B 达 0.98 vs raw 的 0.38，+60 pts）但受制于其状态与请求匹配器的正确性（损坏状态使成功率从 0.98 跌至 0.72/0.41/0.06）。同一门从 τ²-bench 航空政策编译后把 235B agent 的 pass¹ 从 0.39 提到 0.54；但在 PM-Bench 上——成败取决于识别线索而非状态——展示记录反而是最佳档位，强制执行 matcher 的判断把 35B agent 拖到低于其 raw transcript（0.55 vs 0.63）。

> **TL;DR:** This paper isolates *how strongly* task state (done/blocked/cancelled/open steps) should reach an LLM agent by fixing everything else and varying only the coupling: raw transcript → displayed oracle checklist → per-turn directives from an LLM-compiled task-state machine → an enforcement gate that refuses state-violating bookings, all scored by exact payload matching against dynamic ground truth (no LLM judge). On a synthetic procurement testbed (128 paired episodes/cell, McNemar + Holm), the ladder is monotone without per-turn reasoning: at Qwen3-235B (no-think) strict episode success goes 0.38 (raw) → 0.53 (checklist) → 0.84 (directive) → 0.98 (enforcement) at S=10, while the agent's own unverified ledger (0.70/0.79) beats the always-accurate displayed checklist (0.52/0.59) at Qwen3-6.35B — writing binds behavior more than reading. Thinking compresses the ladder (Qwen3-235B raw rises to 0.63–0.82) without letting the text rungs catch the gates. Transfer: a gate compiled from τ²-bench's airline policy lifts Qwen3-235B pass¹ from 0.39 to 0.54 (95% CI [+0.04, +0.26]) and cuts wrong-write episodes from 54% to 36%; on a LangChain real-tool harness Qwen3-235B climbs 0.34 → 0.66 → 0.96. But on PM-Bench, where success turns on recognizing a cue rather than on state, showing the record is the best rung and judgement-bound enforcement drops the 6.35B agent below its raw transcript (0.55 vs 0.63). Rule of thumb: enforcement pays when failures are state-decidable and frequent, does nothing when rare, and hurts when the gate's judgement is wrong.

## 核心贡献
- **状态耦合阶梯（测量框架）：** 首次把"任务状态以多强的方式到达 agent"作为唯一自变量——raw transcript（状态只是提示中的文本）、text checklist（每轮展示由 oracle 渲染的精确状态）、directive gate（LLM 从用户 brief 编译出的任务状态机每轮注入一行指令：ELIGIBLE/BLOCKED/ALREADY-DONE/CANCELLED/REDO AUTHORIZED）、enforcement gate（模块坐在 agent 与执行通道之间，直接拒绝违规 booking）——四个档位共享同一任务、模型与配对 episode。
- ** receipts 驱动的评分协议：** 状态机只被可验证的执行回执（带完成码 RC 与新工作单号的 booking 行）推进；主指标是 strict episode success，用精确字符串匹配对照动态 ground truth 打分——完全不使用 LLM 裁判；配对种子上做 McNemar 精确检验并做 Holm 校正，报告 Wilson 95% CI。
- **四个恒成立的发现（无逐轮推理）：** ① 文本状态在两个开源 agent 的所有图规模上都无法实现生命周期语义（re-execution 是首要失败通道）；② agent 自己写、无人验证的 ledger 胜过被展示的始终准确的 checklist——"写"比"读"对行为的约束更强；③ directive 的收益与模型服从度成正比（Qwen3-235B S=10 的 36 个错误中 32 个是无视 CANCELLED/BLOCKED/ALREADY-DONE 指令的执行）；④ enforcement 不需要服从度、稳定在 0.93–0.98，但受制于其状态正确性与请求→步骤匹配器。
- **阶梯上限的定量刻画：** 损坏门的状态（丢 DONE 边、丢边）使 strict 成功率从 0.98 沿剂量-响应跌至 0.72/0.41/0.06（ε=0.8/1.9/4.5 次损坏/episode）；matcher 误路由一个请求使 directive gate 从 0.92 崩到 0.38、enforcement 从 1.00 到 0.78，而两个文本档位纹丝不动（raw 0.41→0.50，checklist 0.62→0.61，Holm p≥0.75）。
- **真实工具与外部基准迁移 + 适用边界：** 在 LangChain 真实工具分发 harness 上复现阶梯（Qwen3-235B：0.34→0.66→0.96）；从 τ²-bench 航空政策编译同一门使 Qwen3-235B pass¹ 从 0.39 → 0.54、wrong-write episode 从 54% 降到 36%；在 PM-Bench 上发现反转——展示记录是最佳档位，且强制执行 matcher 的判断（每轮拒绝约 22 个选择、其中 17 个本属正当）把 35B agent 拖到 raw transcript 之下。由此给出 enforcement 何时有效何时有害的两个判据：失败质量是否状态可判定、是否高频。

## Key Contributions
- **The state-coupling ladder:** a controlled measurement design that holds task rules, model, and paired episodes fixed and varies only how strongly task state reaches the agent — raw transcript (state as prompt text), text checklist (exact oracle state displayed every turn), directive gate (per-turn directive from an LLM-compiled task-state machine), enforcement gate (a module between agent and execution channel that refuses state-violating bookings).
- **Receipt-driven, judge-free scoring:** the shared state machine is advanced only by verifiable execution receipts (booking lines carrying a completion code plus a fresh work-order nonce), and every episode is scored by exact payload string matching against dynamic ground truth — no LLM judge anywhere in the primary metric; paired-seed McNemar exact tests with Holm correction and Wilson 95% CIs throughout.
- **Four findings that hold without per-turn reasoning across 3 models × 2 regimes × 2 domains:** (1) text-borne state fails the task lifecycle at every graph size, with re-execution the dominant error channel; (2) the agent's own unverified ledger beats an always-accurate checklist it is shown — writing binds behavior more strongly than reading; (3) directives help in proportion to the model's obedience; (4) enforcement needs no obedience but is bounded by the correctness of its state and by the request→step matcher.
- **Quantified bounds on the top rung:** corrupting the gate's state drops strict success 0.98 → 0.72 / 0.41 / 0.06 at ε = 0.8 / 1.9 / 4.5 corruptions per episode (dose-response); a single misrouted request rewrite collapses the directive gate 0.92 → 0.38 and enforcement 1.00 → 0.78 while both text rungs are statistically unmoved (Holm p ≥ 0.75); a memoryless policy that books every request scores 1.00 behind the gate, proving the enforcement ring is the ladder's ceiling by design.
- **Transfer and the boundary of validity:** the ladder replicates on a real-tool LangChain harness (0.34 → 0.66 → 0.96 at Qwen3-235B); a gate compiled from τ²-bench's airline policy raises Qwen3-235B pass¹ 0.39 → 0.54 and halves wrong-writes (54% → 36%); on PM-Bench the ordering reverses — showing the record is the best rung and judgement-bound enforcement hurts — yielding two conditions for when enforcing pays: failures must be state-decidable and frequent.

## Methodology
**Task-state machine.** An assigned project builds obligations in conversation; the state to track is small and discrete: a directed graph G=(V,E,σ,α) of steps with prerequisite edges, statuses DONE/TODO/CANCELLED/BLOCKED, and explicit re-execution authorization. The machine is *compiled by the agent's own model* from the brief every arm receives (the module never sees the generator's graph; compile errors flow into its state uncorrected), revised in place from one mid-episode message (cancellations, rewrites, prerequisite relaxations), and advanced *only on verifiable execution receipts*: a step becomes DONE solely on a valid "booking" — a line in the agent's reply carrying the step's completion code (visible only in the brief) and a fresh per-request work-order nonce, so re-displays of earlier receipts book nothing. A per-turn *matcher* (one LLM call) resolves each request to a step and flags redo intent; it agrees with the scripted step on 0.957–1.000 of turns with redo precision 1.000 and recall ≥ 0.992. Mid-project revisions create six error channels partitioning every violation: re-execution, premature, omission, unrequested, superseded, refused-redo; *per-turn correctness* resolves each request to exactly one step executed exactly once or none.

**The ladder (four couplings, one shared machine).** *Raw transcript*: state lives only in growing conversation text the model re-reads. *Text checklist*: the generator's exact state rendered every turn as a plain-text checklist (oracle-state baseline — accurate but unconstraining). *Directive gate*: the matcher resolves the request and the module injects one directive line (ELIGIBLE: EXECUTE NOW / BLOCKED / ALREADY-DONE / CANCELLED / REDO AUTHORIZED) — the agent is told what state implies and remains free to disobey. *Enforcement gate*: same directive, but the module also sits between agent and execution channel — a violating booking is not entered, the agent is told next turn, and the attempt is logged (state-*bound* enforcement refuses bookings iff the step is CANCELLED/DONE-without-authorization/BLOCKED; a *request-bound* variant additionally refuses unresolvable requests). A *self-ledger* arm has the agent maintain its own state via LEDGER code lines rendered back each turn (no matcher, no directives), and two retrieval arms (top-k cosine, Mem0, replace/augment) place deployed memory systems on the ladder.

**Testbed and evaluation.** Episodes are generated deterministically from a seed: S ∈ {5,10,15,18} steps from an 18-template procurement pool, dependency DAGs at edge density ρ=0.15, a 44-turn schedule holding size separate from context length, and four trap budgets (two premature asks, two redo probes — one interleaved with a fresh work order at a finished step, one superseded cue, one legitimate redo). Ground truth is dynamic (labels follow the realized state). Scoring is *strict episode success* by exact string match on receipt lines — an LLM judge is never used; failures decompose over the six channels. Each cell = one arm × model × S × regime at 128 paired episodes (Wilson 95% CIs; adjacent-ladder contrasts via exact McNemar on shared seeds, Holm-corrected). A scripted perfect agent scores 200/200 as an oracle regression suite. Models: Qwen3-6.35B, Qwen3-235B (main grid), DeepSeek V4 Pro (closed anchor, 32 episodes/cell); both no-think and thinking regimes.

**Transfer.** (a) A LangChain-based real-tool dispatch harness where each step is a tool call; (b) the τ²-bench airline domain, where the same gate is compiled from the released policy text; (c) PM-Bench, where success turns on recognizing when a finished intention leaves the menu. Additional controls: state-corruption dose-response on the gate (drop DONE bits / drop ε edges), matcher-misrouting ablation via a held-out request rewriter, retrieval-memory baselines, and per-configuration compile-accuracy audits (0.995–1.000 on dependencies/codes; 0.812–0.984 on rewrites; 0.680 on one relaxed-prerequisite cell).

## Results & Highlights
- **Text-borne state fails without reasoning (Table 2, amended brief, strict episode success):** at Qwen3-235B no-think the raw transcript scores 0.38 (S=10) and 0.50 (S=15 dense) vs 0.84/0.86 for the directive gate and 0.98/0.98 for the enforcement gate (+0.60 and +0.48 over raw); at Qwen3-6.35B raw is 0.25/0.32 vs enforcement 0.98/0.97. Under the original brief that never says "performed once," raw drops to 0.27 (Qwen3-235B) and 0.12 (Qwen3-6.35B), while DeepSeek V4 Pro manages only 0.69. Re-execution leads failures at every size (Appendix E.1).
- **The self-written ledger beats the accurate checklist:** the agent's unverified ledger scores 0.70 (replacing the transcript) and 0.79 (augmenting) at Qwen3-6.35B vs the displayed oracle checklist's 0.52/0.59 — binding behavior through writing outperforms displaying an always-accurate record; it leaks 21–27 re-executions per 128 episodes yet still sits beside the directive gate. Retrieval memory fails almost every episode (0.00–0.02 for top-k and Mem0, mostly omission); augmenting reaches 0.67, still below the directive gate (p=0.005).
- **Obedience vs enforcement:** the directive rung is bounded by obedience — 32 of 36 Qwen3-235B S=10 errors are executions against CANCELLED, BLOCKED, or ALREADY-DONE directives — while the enforcement gate holds 0.93–0.98 across all three capability points without relying on obedience; its residual errors are mostly omissions it cannot force (68 omissions, 35 over-blocks, 17 declines, 16 wrong-code/order bookings across ten Qwen3-235B cells). A memoryless policy booking every request scores 1.00 behind the gate (generator graph 0.99), so enforcement is the ladder's ceiling by design.
- **The gate inherits its state's fragility:** dropping DONE bits / edges at ε = 0.8 / 1.9 / 4.5 expected corruptions per episode takes strict success from 0.98 to 0.72 / 0.41 / 0.06; a held-out request rewriter that misroutes one rewrite (matcher agreement 1.000 → 0.976–0.977) collapses the directive gate 0.92 → 0.38 and enforcement 1.00 → 0.78 over 64 shared seeds, while raw (0.41→0.50) and checklist (0.62→0.61) are unmoved (Holm p ≥ 0.75).
- **Per-turn reasoning compresses but does not repair:** thinking lifts Qwen3-235B's raw transcript to 0.63–0.82 across five sizes (0.80 at S=10 vs raw no-think 0.38) yet it stays below both gates in every cell; the two gates separate from each other in no thinking cell, and the directive-over-checklist contrast survives Holm in none.
- **Transfer:** on the real-tool LangChain harness Qwen3-235B climbs 0.34 → 0.66 → 0.96 (raw → directive → enforcement; the two gates tie at 50 episodes); on τ²-bench airline the policy-compiled gate raises Qwen3-235B pass¹ from 0.39 to 0.54 (paired difference 95% CI [+0.04, +0.26]) and cuts wrong-write episodes from 54% to 36%, while Qwen3-6.35B — which rarely violates the policy — is unchanged. On PM-Bench the order reverses: checklist and directive tie 0.72 vs 0.70–0.72 for the gates, judgement-bound enforcement falls below the raw transcript (0.55 vs 0.63), refusing ~22 selections per run (17 of them due); the state-bound gate ties the ledger (0.66 vs 0.65).

## Critical Assessment
**Novelty is real, not cosmetic.** Prior work evaluates agent-memory or workflow systems as wholes (Table 1: ReAct/MemGPT-style agents own state as raw transcript; LangGraph checkpoints it; Temporal/Airflow enforce it by construction) — none isolates the coupling strength as the independent variable. The ladder design, shared LLM-compiled machine, and receipt-only advancement make "shown vs told vs enforced" a measurable quantity, and the judge-free exact-match scoring removes the LLM-judge confound that plagues most agent benchmarks. The ledger-over-checklist inversion (agent's own unverified 0.70/0.79 beating an accurate displayed record at 0.52/0.59) is a genuinely counterintuitive, actionable finding.

**Rigor is above average for the area, with a few soft spots.** Strengths: paired episodes with McNemar+Holm, Wilson CIs, an oracle-agent suite, compile-accuracy audits, and a state-corruption dose-response that directly probes the enforcement gate's dependence on its own state. Soft spots: (1) the headline "enforcement = 0.98" is partly an artifact of the environment's design — the paper itself shows a memoryless book-everything policy scores 1.00 behind the gate, so the top rung measures the module's state correctness, not agent capability, and the ceiling is essentially unreachable-by-construction; (2) the payload testbed is a single synthetic generator (procurement templates) plus one real-tool re-implementation — two domains, but both share the same one-shot/explicit-redo lifecycle semantics with a *single cooperative user*, and request wording is stressed by only one held-out rewriter plus one ambiguity pattern, so linguistic robustness is barely sampled; (3) directives and tool results are injected as plain user-role strings, and the authors admit spoofing is untested — an obvious adversarial hole for exactly the architecture they advocate; (4) the closed frontier model (DeepSeek V4 Pro) and Qwen3-6.35B thinking cells are small (32 episodes), and several directive-vs-enforcement separations are single-digit episodes in sparse sweeps (top contrast narrows to 0.07–0.10, n.s., in sparser cells).

**Significant boundary conditions the abstract states but headlines can bury.** The enforcement win does not generalize to judgement-based domains: on PM-Bench, enforcement drops the 6.35B agent below its raw transcript (0.55 vs 0.63) because the matcher's judgement — not state — is wrong ~17 times per run, and refusals are *silent* (70 of 86 refused bookings at Qwen3-6.35B read as completed work), so a wrong gate deletes work without the agent ever knowing. Per-turn thinking at 235B eliminates most gate separations entirely, meaning the practical benefit of enforcement shrinks as base models reason better. The "amended vs original brief" distinction adds a degree of freedom (both are reported, to the authors' credit, and the brief moves the raw rung by up to 0.16–0.20).

**Reproducibility:** strong on paper — fixed seeds, per-cell serving/decoding logs, promised release of all scripts and the scrubbed launch-job logs; PM-Bench was unreleased at submission time (acknowledged), which makes that one result community-unverifiable for now.

## Strengths
- A clean factorial measurement design (the ladder) that turns a vague systems question — "how strongly should state reach the agent?" — into four comparable rungs with shared machinery and paired statistics.
- Primary metric is exact payload matching against dynamic ground truth with a scripted perfect agent (200/200) as regression control — no LLM judge, no prompt-sensitive grading.
- Honest, quantified treatment of the top rung's own failure modes: state-corruption dose-response (0.98 → 0.72/0.41/0.06), matcher-misrouting collapse (0.92 → 0.38 directive), compile-accuracy audits per configuration.
- Findings are stated with their validity conditions rather than oversold: enforcement pays when failures are state-decidable and frequent (lifecycle testbed 0.88–0.99, τ²-bench pass¹ +0.15), does nothing when catchable failures are rare (3.5% at Qwen3-6.35B), and actively hurts when the gate's judgement is wrong (PM-Bench 0.55 < 0.63).
- The self-ledger vs oracle-checklist inversion (0.70/0.79 vs 0.52/0.59) is a surprising, deployable insight for agent-harness designers.
- Exceptional transparency: disclosed LLM assistance with a blind rater study, and an explicit statement that no LLM touches primary scoring.

## Limitations
- Task semantics restricted to one-shot or explicit-redo obligations over a dependency DAG; budgets, expiry, conflicting obligations, and multi-agent / multi-session state are out of scope.
- Both testbed domains come from one episode generator family; a single cooperative user; only one held-out rewriter and one ambiguity pattern stress request wording — linguistic and adversarial robustness are minimally sampled.
- The matcher and compiler inside the directive/enforcement gates are themselves LLM calls whose errors bound the top rung (one misrouted rewrite: enforcement 1.00 → 0.78); a miscompiled graph refuses correct work with no override path in the current design.
- Several cells are small: 32 episodes for DeepSeek V4 Pro and Qwen3-6.35B thinking; directive-vs-enforcement separations vanish in sparse sweeps (0.07–0.10, n.s.).
- Refusals are silent (70/86 refused bookings read as completed work); a same-turn notice fixes it (0 of 89) but is only validated in one appendix probe.
- Directives and tool results are plain user-role strings; spoofing attacks are untested. PM-Bench was unreleased at writing time, and τ²-bench covers one domain with an internal user simulator.
- Per-turn reasoning at 235B compresses the ladder's separations, so conclusions are most crisp for the no-think regime; the paper's own data suggests they erode as models get stronger.

## Relevance
这项工作正中 LLM Agent 可靠性与评测的方法论核心：它把"记忆/状态管理"从系统设计直觉变成可测量的耦合强度阶梯，其"自己写的 ledger 胜过被展示的准确清单"与"enforcement 何时有效何时有害"的结论对任何做多步 agent、工作流引擎或 agent 基准的人都有直接的设计指导意义。其无 LLM 裁判、回执驱动的严格评分协议也值得正在构建 agent 评测的团队借鉴。

## Questions for Further Exploration
- The gates compile and match via LLM calls; would a hybrid that shows the agent the resolved step and asks back when no step resolves (the authors' own suggestion) recover the enforcement rung's robustness without its silent-refusal failure mode?
- How does the ladder behave under an adversarial user or a prompt-injection attempt against the injected directive strings, given the authors concede spoofing is untested?
- Does the ledger-over-checklist inversion persist for frontier reasoning models, where per-turn thinking already lifts the raw transcript to 0.63–0.82 and compresses all separations?
- Can the two conditions for enforcement (state-decidable, frequent) be turned into a cheap pre-hoc diagnostic that decides, per deployment, whether to attach an enforcement gate at all?
- What happens with budgets, expiry, and conflicting obligations — states whose correctness is a judgement call rather than a set-membership test, where PM-Bench suggests enforcement currently hurts?
