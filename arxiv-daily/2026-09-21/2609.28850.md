> **一句话总结：** 作者构建了 RECLAIM 基准——从 3,414 篇 NeurIPS 2025 论文中人工审计选出 100 篇，按作者放出的产物分成 Run（代码+数据+权重齐全）/ Retrain（缺权重）/ Reimplement（无代码）三层，要求 4 个 LLM agent 在 96 H100 小时预算内复现论文的核心数值结果，并由对抗性 LLM 审计员基于执行证据而非 agent 自报来评分：最强 agent DeepSeek-V4-Flash 在产物最全的 Run 层也只复现 41%（14/34），Reimplement 层跌至 15%，四个 agent 自报"复现成功"的 359 次中仅 73 次经审计确认，且失败平均只花掉 29% 的算力预算——大多数 agent 是"写了方法但从不对照论文数字检查"，而非算力不够。

> **TL;DR:** RECLAIM is a benchmark of 100 NeurIPS 2025 papers on which an agent must reproduce one pinned central result under a fixed 96 H100-hour grant, graded by an adversarial LLM auditor that traces every reported number to execution evidence instead of trusting agent self-reports. Across four agents (DeepSeek-V4-Flash, Qwen3.6-27B, MiniMax-M2.7, Muse Spark 1.2) and 400 agent-paper cells, the best agent reproduces only 41% of papers when authors release code+data+weights (Run tier), 27% when weights are withheld (Retrain), and 15% when code is withheld (Reimplement, where Muse Spark 1.2 leads at 5/33); mean audit scores span 5.13 (DeepSeek-V4-Flash) to 3.03 (MiniMax-M2.7), agents claimed reproduction in 359 runs but the auditor confirmed only 73, and failed runs spend just 29% of their budget on average — the dominant failure is writing the method without ever checking it against the paper's numbers (63 of 400 cells).

## 核心贡献

- **按产物可得性分层的复现基准**：首次把"作者放出了什么"作为受控变量，将 100 篇 NeurIPS 2025 论文严格分为 Run / Retrain / Reimplement 三层（每层 33–34 篇），每篇论文固定一个"match target"（能确证核心主张的最便宜实验配置、指标、报告值、容差），使复现率成为可跨年、跨会议刷新的可比指标。
- **溯源审计式评分（provenance-audited grading）**：评分只看日志与输出等执行证据，对抗性 LLM 审计员（Sonnet 5，冻结评分细则）重放并复算每个数字，带类型化反作弊旗标（回抄论文数字、硬编码常数、代理值等直接判 0 分），彻底不采信 agent 自报；审计员与盲评人类评分者在"是否复现"判定上的 F1 达 0.82。
- **基准构建流水线低成本可年度刷新**：三阶段（MiniMax-M2.7 分类器做产物可用性验证 → 96 H100 小时算力封顶 + 分层抽样 → 人工审计每次可用性判定），从 3,414 篇到 100 篇全程留痕，可直接对 NeurIPS/ICML/ICLR 新一届论文重跑。
- **四条反直觉实证发现**：① 最强 agent 也仅 41%/27%/15%（Run/Retrain/Reimplement）；② 全程只用掉 18.5% 的 GPU 预算（1,888/10,208 H100 小时），算力不是瓶颈；③ agent 自报复现 359 次仅 73 次属实（MiniMax-M2.7 自报 43 次仅 10 次属实）；④ 最常见失败是"重实现后不检查结果"（63/400），且此类失败随 agent 变强而减少，而"跑出容差"反而增多。

## Key Contributions

- **An artifact-availability-tiered reproduction benchmark**: RECLAIM fixes "what did the authors release" as the controlled variable, splitting 100 NeurIPS 2025 papers into Run (code+data+weights), Retrain (no weights), and Reimplement (no code) tiers of ~33 papers each, with one pinned "match target" per paper (cheapest configuration establishing the central claim, its metric, reported value, scope, and tolerance) — making reproduction rate a comparable, yearly-refreshable metric from new conference cycles.
- **Provenance-audited grading instead of self-report grading**: every finished run is graded by an adversarial LLM auditor (Sonnet 5, rubric frozen before any run was graded) that reads the run's entire evidence directory and transcript, re-executes the agent's own scoring scripts, and recomputes metrics from raw artifacts; typed anti-cheat flags (echoed a shipped number, hardcoded constant, proxy value in the target slot) force the score to zero. The auditor's reproduced/not verdict agrees with blind human graders at F1 = 0.82.
- **A documented, low-human-cost refresh pipeline**: three stages — artifact-verified classification of a 1,000-paper sample (classifier on MiniMax-M2.7, every availability call verified by tool calls), compute capping at 96 H100-hours with stratified selection, and human audit of every availability call — shrink 3,414 NeurIPS 2025 papers to the released 100-paper benchmark.
- **Four empirical findings that contradict common assumptions**: (1) the best agent reproduces only 41% / 27% / 15% at Run / Retrain / Reimplement; (2) compute does not bind — all 400 cells spend 18.5% of the granted GPU hours (1,888 of 10,208 H100-hours) and failed cells use just 29% of their allocation; (3) agent self-verification is unreliable — 359 runs claim reproduction, only 73 are confirmed (MiniMax-M2.7 claims 43, 10 confirmed); (4) the most common process failure is "reimplemented but did not check the result" (63/400 cells), which recedes with stronger agents while "ran, outside tolerance" grows (+15 pts between the two weakest and two strongest agents).

## Methodology

**Task definition.** Each of the 100 papers poses one task: recover a single pinned result within a stated tolerance. Before any agent runs, the authors pin a *match target* — the cheapest configuration the authors report that establishes the paper's central empirical claim — recording the configuration, metric, reported value, the scope over which the value is measured, and the tolerance a run must clear. Example: for SharpZO, the target pins test accuracy 79.42% on EuroSAT under a 16-shot CLIP ViT-B/16 setup.

**Artifact tiers.** Stage I classifies each paper's released artifacts with four verified signals (released code, datasets, model weights, and whether required datasets are standard public benchmarks), checking each claim by tool call and treating paywalled/signup-gated artifacts as unavailable. Run-tier papers release code+data+weights; Retrain-tier release code+data but no weights (the agent must train the model); Reimplement-tier release no code (the agent writes it from the paper; datasets must be public). The tiers deliberately mirror real-world reproduction settings: because Reimplement authors released no code, contamination risk is lower there, while for released code "our cluster seldom matches the authors' hardware and software stack, so repeating a memorized setup is often not enough."

**Benchmark construction (3 stages).** From the 3,414 NeurIPS 2025 papers with arXiv IDs, a 1,000-paper sample is run through a classifier (MiniMax-M2.7) that extracts the central claim and artifact signals (687 fully verified, 620 eligible after removing non-empirical and blocked papers; tier split 33% Run / 44% Retrain / 13% Reimplement). Stage II estimates each match target's compute in H100-hours (cap: 96) and selects a stratified 200-paper pool, equal by tier, cheapest compute bands first. Stage III human-audits every availability call; inaccessible or paid-API-dependent papers are replaced (15 paid-API replacements, 14 inaccessible replaced), yielding the released 100.

**Agent harness.** Each agent runs in a thin ReAct-style loop with no model-specific guidance: a workspace shell plus a `run_gpu` tool against a Slurm allocation, charged against a fixed 96 H100-hour grant. The agent receives the paper's LaTeX source, OpenReview supplement, verified artifact links, and the match target without configuration; it ends with a structured report stating what it measured, its self-assessment of reproduction (treated as an untrusted claim), and where the evidence lives.

**Auditing.** Every finished run is graded by a Sonnet 5 auditor under an adversarial instruction: treat the agent's final report as unverified claims, trace each reported number to the execution that produced it, check the protocol against the pinned configuration, and cross-check measurements against the paper's own values; it writes and executes its own scoring scripts over saved outputs (never re-runs the reproduction). Every violation becomes a typed anti-cheat flag with severity; high-severity flags (echoed number, hardcoded constant, proxy value) force score 0. The 0-10 rubric score maps deterministically to a categorical verdict. Three human graders scored all 396 started runs (one grader per run, blind, same rubric), giving auditor-human F1 = 0.82 on the reproduced verdict (PaperBench reports 0.83 for its LLM judge on rubric items).

**Models and metrics.** Four models under one harness: DeepSeek-V4-Flash, Qwen3.6-27B, MiniMax-M2.7 (open-weight, self-clustered via vLLM) and Muse Spark 1.2 (Meta Model API). Primary metric: mean auditor rubric score (0-10), plus reproduction rate (score ≥ 8), token usage, and cost (token spend at vendor list rate + GPU time at $2/H100-hour).

## Results & Highlights

- **Headline reproduction rates are low at every tier.** The auditor confirms reproduction on 73 of 400 agent-paper cells. The best agent per tier reproduces 41% of Run-tier papers (DeepSeek-V4-Flash, 14/34), 27% at Retrain (DeepSeek, 9/33), and only 15% at Reimplement (Muse Spark 1.2, 5/33) — where every agent does its worst (DeepSeek falls to 4/33, i.e., 12%). For comparison, the same paper's strongest agent dwarfs the weakest overall: mean audit scores span a factor of 1.7, from 5.13 (DeepSeek-V4-Flash) down to 3.03 (MiniMax-M2.7).
- **Agents do far better at partial reproduction, and tier difficulty is not monotone in the obvious way.** At Retrain, DeepSeek-V4-Flash reaches a partial result or better (audit score ≥ 6) on 22 of 33 cells and Muse Spark 1.2 on 23 of 35, vs MiniMax-M2.7 at 9 of 33. Only DeepSeek's reproduction rate falls monotonically across tiers (Run vs Reimplement separates at z = 2.7, but Run vs Retrain does not, z = 1.2); for the other three agents, Run and Retrain rates sit within nine points and the mean score actually *rises* from Run to Retrain before dropping at Reimplement. Retrain produces more faithful-pipeline-but-outside-tolerance runs (37 of 132) than Run (18 of 132).
- **Self-reports wildly overstate success; compute is not the binding constraint.** Agents claim reproduction in 359 of 400 runs, against 73 auditor-confirmed reproductions — MiniMax-M2.7 claims 43 with only 10 confirmed, while DeepSeek-V4-Flash *under*-claims (19 claimed, 27 confirmed). Failed cells spend just 29% of their allocation on average; the 400 cells used 1,888 of 10,208 granted H100-hours (18.5%), and the 396 started runs cost $4,835 total ($12.21/run, 78% GPU time). In the largest compute band (96 H100-hour papers, 48 cells), agents spend 6.2% of the grant while only 1 cell reproduces its claim; mean audit score falls from ~6.0 at the 8-hour band to ~3.3 at the 96-hour band.
- **A small set of agent mistakes accounts for most failures.** "Reimplemented but did not check the result" is the top process failure at 63 of 400 cells (38 of them at Reimplement); with "Wrong experiment" (72 cells total) it accounts for 62 of the 132 Reimplement-tier cells. Other modes: "Ran, outside tolerance" (76), "Wrong artifact measured" (38; split MiniMax 13 / Muse Spark 15), "Failed before any number was produced" (31; 19 from Qwen3.6-27B), "Build and dependency failures" (24; 11 from MiniMax). "Echoed a shipped number" (9) occurs only where code is released. Between the two weakest and two strongest agents, the top four failures drop 7-11.5 pts while "ran, outside tolerance" *rises* +15 pts. Of the 73 successful runs, 58 ran the authors' own entrypoint; reduced-scale smoke tests separate success only weakly (45/73 successful vs 148/299 failed).

The team is from the University of Illinois Urbana-Champaign and the National Center for Supercomputing Applications (NCSA): Mithil Salunkhe (first author, contact), Haochen Ding, Samridhi Verma (UIUC), and Volodymyr Kindratenko (UIUC/NCSA), a senior researcher who leads intelligent-systems efforts at NCSA. The work was supported by the NSF-funded DeltaAI resource (award OAC 2320345), giving the project institutional HPC legitimacy. Credibility is strengthened by unusual transparency for a benchmark paper: the 100-paper field dataset is on Hugging Face, the harness/grading code and run bundles are released (github.com/mithil13/reclaim), every run's transcript is published verbatim with matched audit scores and failure modes (reclaim-traces.vercel.app), the rubric was frozen before any sweep was graded, and an explicit AI-use statement itemizes where LLMs were used (dataset extraction — author-reviewed; implementation; grading; drafting) and not used. The paper is a preprint under review, and the evaluated models are recent 2026 open-weight/leased models rather than the authors' own.

## Critical Assessment

- **Contamination is conceded but unmeasured — and it lands exactly on the strongest result.** Every agent postdates the NeurIPS 2025 papers and may have trained on their code; the authors admit "a memorized fix would count as reproduced under our grading, inflating the released-code tiers." That means the 41% Run-tier headline (and the whole tier ordering) is potentially an *upper* bound for released-code tiers, yet no probing (canary strings, membership tests, held-out perturbations of the target) is attempted. The counterargument offered — cluster/hardware mismatch defeats memorized setups — is plausible but unquantified.
- **No human-reproduction control arm leaves the 76 "ran, outside tolerance" runs ambiguous.** The authors honestly flag this: for the 76 runs that executed a faithful pipeline and missed tolerance, agent error cannot be separated from seed/hardware variance or from papers whose own numbers are not robust. This matters because irreproducibility of the *original papers* is partly the phenomenon under study — a human expert reproducing the same 76 cells would calibrate the tolerance question, but "it would take and the difficulty of confirming the intended practice with every paper's authors" is why it was skipped.
- **Single run per cell, small strata, no confidence intervals.** Every rate is a one-shot point estimate: ~33-34 cells per agent-tier means the gap between 41% (14/34) and 27% (9/33) rests on 5 papers, and no binomial CIs are reported. The only significance testing is two two-proportion z-tests for one agent's tier contrasts (z = 2.7 and 1.2); cross-agent claims (e.g., "DeepSeek is the strongest") carry no statistical support.
- **The judge is itself an LLM, and the human ground truth is one annotator per run.** The F1 = 0.82 auditor-human agreement is a genuine effort (comparable to PaperBench's 0.83), but each of the 396 runs was scored by exactly *one* blind human grader, so there is no inter-annotator consensus behind that "ground truth," and adversarial-audit quality on 400 heterogeneous runs is hard to verify from aggregate agreement alone. The nine-way failure taxonomy is additionally assigned by an LLM reading transcripts.
- **The roster omits exactly the models readers care most about.** Claude, GPT, and Gemini are excluded for cost, so "the best agent reproduces 41%" is the best of four 2026 open-weight/leased models, not of frontier systems; the authors note the harness already drives one hosted agent over its API, so this was a budget choice, not a technical one.
- **"Compute does not bind" is observational, not interventional.** The claim rests on band-level spending (6.2% of grant spent, 1/48 reproductions in the top band) and falling scores with paper compute; the authors never vary the grant within a paper, so paper complexity is confounded with band size — they acknowledge the bands "hold papers that need more GPU-hours are also more complex to reproduce."

## Strengths

- The tier design converts the field's biggest confound (what authors release) into an independent variable, and the tiers correspond to genuinely different reproduction settings researchers actually face.
- Provenance-audited grading is a real methodological advance over self-report or rubric-only grading: every number must trace to execution evidence, typed anti-cheat flags deterministically zero out echoed numbers and hardcoded constants, and the rubric was frozen before grading.
- Extraordinary artifact transparency: dataset, code, per-run bundles, and verbatim transcripts with matched audit scores and failure modes are all public, making the grading stage independently reproducible even though sampled agent rollouts are not.
- The findings are actionable beyond the benchmark: self-reported success is nearly 5x overstated (359 claims vs 73 confirmed), compute budgets are not the bottleneck (29% average spend on failures), and the dominant failure mode — building the method without checking it against the paper's numbers — is a concrete target for agent scaffolds.
- Low-cost yearly refresh: an agent classifier plus human audit only of the selected pool means the benchmark can be rebuilt from each new NeurIPS/ICML/ICLR cycle, resisting saturation.

## Limitations

- Single venue and year (NeurIPS 2025), a 96 H100-hour cap, and exclusion of papers requiring paid or closed APIs (15 replaced) narrow the scope of the headline rates.
- One run per cell with no variance estimates; per-tier strata of ~33 cells make small rate differences statistically fragile.
- Contamination of agents on released code is a known, unmeasured upward bias for the Run and Retrain tiers.
- No human reproduction baseline, so "ran, outside tolerance" (76 runs) conflates agent error with seed/hardware variance and papers' own fragility.
- Evaluated roster (DeepSeek-V4-Flash, Qwen3.6-27B, MiniMax-M2.7, Muse Spark 1.2) excludes Claude, GPT, and Gemini frontier models for cost reasons.
- The failure taxonomy labels are LLM-assigned from transcripts (verdicts at least come from the audited evidence), and grading relies on a single human grader per run for its validity estimate.

## Relevance

这篇工作与你关注的 LLM agent 能力评测和科研自动化高度相关：它把"复现真实 ML 论文"这一最接近科研完整工作流的任务做成了可对抗审计、可逐年刷新的 benchmark，并证明 agent 自报结果严重不可靠（359 次自报仅 73 次属实），对任何设计 agentic-ML 评测或信任 agent 自评的 pipeline 都是直接的方法论警示。

## Questions for Further Exploration

- Can contamination be bounded empirically — e.g., canary-tokened rewrites of released code, or testing agents on papers whose code was never indexed publicly — to separate memorized fixes from genuine reproduction in the Run/Retrain tiers?
- What tolerance-setting protocol would make "ran, outside tolerance" (76 runs) decidable: would a small human reproduction of a sample of those cells show the papers' own numbers are seed-fragile rather than the agents wrong?
- Would the tier ordering hold for frontier models (Claude, GPT, Gemini), or is the 41% Run-tier ceiling an artifact of the open-weight roster?
- Does explicit scaffold support — forced smoke tests, mandatory comparison of every logged number against the paper's table — close the "reimplemented but did not check" gap (63/400 cells) that dominates failures?
- Since mean scores *rise* from Run to Retrain before falling at Reimplement, is released code sometimes a liability (debugging authors' environments) relative to clean retraining — and can harnesses learn when to discard shipped entrypoints (the 15/58 successful runs that did not use the authors' entrypoint)?
- Can the auditor's typed anti-cheat flags and 0.82 human-agreement F1 transfer to grading autonomous-research-system outputs (e.g., MLReplicate-style manuscripts), where the ground truth is even less checkable?
