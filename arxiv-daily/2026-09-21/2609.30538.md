> **一句话总结：** 作者在两块 Zynq UltraScale+ ZCU104 上构建了"分布式环形振荡器(RO)阵列 + AXI 互联基准 + 非辐照金标准参考板"的跨层测量平台，在 TRIUMF 中子束下（累积注量 6.0×10¹⁰ n/cm²）首次于真实辐照环境中把配置存储器 SEU 引起的路由延迟漂移与 AXI 层故障关联起来：248 万笔正确事务之外记录了 21 次可用性失效、14 次可检测协议错误和 18 次静默数据损坏（SDC），且路由延迟事件之后 ΔT 窗口内发生 SDC 的条件概率达 0.500（4/8），SDC 截面为 3.00×10⁻¹⁰ cm²——证明只靠 watchdog/超时监控的系统会漏掉静默数据损坏。

> **TL;DR:** This single-author study bridges two previously disconnected literatures — FPGA routing-delay shift characterization and AXI-interconnect fault injection — by irradiating a fully operational Zynq UltraScale+ ZCU104 AXI benchmark at TRIUMF (total fluence 6.0×10¹⁰ n/cm²) while a ring-oscillator array monitors routing delay and a non-irradiated board checks every transaction against a golden reference. Compared against a 24-hour pre-beam baseline (100,000 transactions, all correct, RO noise within ±0.005 normalized frequency), the beam run produced 21 availability failures, 14 detectable protocol errors, and 18 silent data corruption (SDC) events out of 2.48M transactions; 4 of 8 detected routing-delay events were followed by SDC within the ΔT association window (P̃(SDC|D)=0.500), with fluence-normalized cross-sections of 1.33×10⁻¹⁰ cm² (routing-delay) and 8.83×10⁻¹⁰ cm² (all AXI failures, Table III). Frame-level ICAP fault injection reproduced the same per-region failure taxonomy, supporting a timing-margin-erosion mechanism in which transactions complete while silently returning wrong data.

## 核心贡献

- **跨层实验闭环（首次实测）**：把此前彼此割裂的两条研究线——RO 传感器测到的路由延迟漂移（作者自己的 TNS 系列 [1][3]–[5]）与 AXI 互联的可用性失效/SDC（De Sio 等 [7][8]，仅基于配置故障注入）——在同一台真实运行、真实中子辐照的 ZCU104 MPSoC 上联合观测，建立了"配置位翻转 → 路由延迟漂移 → AXI 层故障"的证据链。
- **双板金标准架构**：辐照 DUT 板通过 FMC 连接束外参考板，事务正确性由未受辐照的金标准参考独立判定，从架构上排除了"校验通路被同一扰动污染"的共模失效，使 SDC（事务无错误标志但数据错误）得以被可信地识别。
- **帧级 RO-帧映射**：8 个双 LUT 路由主导型 RO 被放置在 AXI 互联布线区内并逐个映射到配置帧地址（Fig. 6），使每次频率漂移能定位到具体帧区域；帧级 ICAP/SEM 故障注入复现了与中子观测一致的逐区域失效模式（RO1/RO6→SDC，RO3→需复位的可用性失效，RO7→协议错误）。
- **可复用的事件分类学与统计框架**：定义了 Routing Delay Event / Availability Failure / SDC / Detectable Protocol Error / Correlated Event 五类事件（Table I），给出泊松截面 σ=N/Φ 与条件概率 P̃(F|D)=N_FD/N_D 的估计方法（Table II/III）。
- **对可靠性测试实践的直接告诫**：SDC 在总失效中占比最高（18 次），此类事件不触发任何超时/协议错误，说明 AXI 系统的辐射测试必须加入独立于系统挂起检测的数据金标准校验。

## Key Contributions

- **First experimental, beam-level link between the two silos**: simultaneous observation of routing-delay perturbations (distributed RO array) and transaction-level failures (AXI benchmark with external golden reference) on one fully operational ZCU104 under real neutron irradiation at TRIUMF (6.0×10¹⁰ n/cm²), rather than fault injection alone ([7],[8]) or timing-only sensing ([1],[3]–[5]).
- **A dual-board architecture** that places the correctness oracle outside the neutron field via an FMC link, preventing common-mode corruption of the checking path and enabling credible detection of silent data corruption — transactions that complete on time with wrong data and no AXI error signal.
- **Frame-localized attribution**: an RO-to-configuration-frame map (Fig. 6) plus SEM/ICAP frame-level fault injection shows that only a subset of interconnect frame regions (RO1, RO3, RO6, RO7) produce both measurable delay shifts and AXI degradation, while RO2/RO5 regions stay inert — i.e., vulnerability is spatially non-uniform (Fig. 14).
- **A reusable measurement methodology**: deterministic event taxonomy (Table I), Poisson cross-section estimation σ_X = N_X/Φ with confidence intervals, and conditional association metrics P̃(F|D) within a predefined ΔT window, all extracted from synchronized cross-layer event records.
- **Actionable reliability guidance**: availability-only monitoring (watchdogs, timeouts) misses SDC entirely (18 events observed); radiation testing of AXI-based systems must include independent golden-reference checking of returned data.

## Methodology

**Platform.** Two Xilinx ZCU104 boards (Zynq UltraScale+ MPSoC): the irradiated DUT inside the TRIUMF neutron beam and a supervisory/reference board outside the beam, connected by a deterministic FMC interface carrying transaction records, checker outputs, event markers, and synchronization. The reference board hosts the golden reference so correctness computation is not exposed to the same radiation field, reducing common-mode corruption of the validation path.

**DUT design.** The PS acts as AXI master, issuing deterministic transactions through an AXI Interconnect to replicated AXI slave accelerator IPs, plus AXI GPIO and AXI UARTLite. A custom AXI checker IP captures returned data, AXI response condition, timeout state, and checker flag. A distributed array of 8 routing-dominated ring oscillators (each just two LUTs — inverter + enable-controlled buffer — with the feedback deliberately routed through long chains of switch matrices so oscillation period is dominated by programmable routing rather than LUT delay) is placed in and around the AXI interconnect routing region. Each RO is associated with a localized set of configuration frames (Fig. 6 frame map), so a measured frequency deviation can be attributed to upsets in specific interconnect frames. A Soft Error Mitigation (SEM) Ultra controller monitors configuration errors and, via the ICAP/PCAP path, provides frame-level configuration fault injection with configuration restore between injections.

**Event taxonomy (Table I).** Routing Delay Event = statistically significant deviation of a monitored RO from its ±0.005 normalized-frequency baseline noise band with persistent/step-like behavior; Availability Failure = transaction stall/timeout/bus hang; Silent Data Corruption = transaction completes on time and with no explicit error flag but data mismatches the golden reference; Detectable Protocol Error = AXI SLVERR/DECERR or interrupt; Correlated Event = failure within the predefined ΔT window following a routing-delay event.

**Statistics.** Events are modeled as a Poisson process; cross-sections σ_X = N_X/Φ (Φ = 6.0×10¹⁰ n/cm² accumulated fluence) with Poisson confidence intervals on counts; conditional failure probability given a preceding delay event estimated as P̃(F|D) = N_FD/N_D. The paper stresses these are statistical associations within ΔT, not causality proofs.

**Procedure.** (1) 24-hour pre-beam baseline: RO frequencies normalized and verified inside the ±0.005 noise band; 100,000 baseline transactions all correct; SEM clean. (2) Beam exposure with continuous AXI traffic; all RO measurements, SEM status, frame/injection IDs, AXI outcomes, timestamps, and fluence stored in synchronized cross-layer event records; recovery (module reset / reinitialization / configuration restore) applied on persistent stalls, each recovery logged. (3) Post-run validation distinguishing transient vs persistent configuration effects. (4) A complementary frame-level fault-injection campaign perturbing selected RO-associated frames to compare controlled upsets against stochastic beam events.

## Results & Highlights

- **Failure counts under beam (Fig. 12):** during 6.0×10¹⁰ n/cm² of neutron exposure, the AXI benchmark completed **2,480,000 correct transactions** and logged **21 availability failures, 14 detectable protocol errors, and 18 silent data corruption events** — failure counts three to four orders of magnitude below the correct-transaction count, which is why the log-scale top panel and linear-scale expanded panel are both needed. For calibration, the 24-hour pre-beam baseline produced **0** failures of any class over 100,000 transactions.
- **Fluence-normalized cross-sections (Table III):** routing-delay-event cross-section **1.33×10⁻¹⁰ cm²** (8 RO-detected events, D1–D5 shown in Fig. 13); availability failure **3.50×10⁻¹⁰ cm²**; detectable protocol error **2.33×10⁻¹⁰ cm²**; **SDC 3.00×10⁻¹⁰ cm²** — SDC has the largest per-class cross-section of the architectural failure modes; aggregate AXI-failure cross-section **8.83×10⁻¹⁰ cm²** (53 events). (Note: the body text misprints all of these as ×10⁻¹²; Table III's ×10⁻¹⁰ is the arithmetically correct N/Φ.)
- **Conditional association (ΔT windows, Table III):** of the 8 detected routing-delay events, **4 were followed by SDC** (P̃(SDC|D) = **0.500**), **3 by availability failures** (P̃ = **0.375**), and **2 by detectable protocol errors** (P̃ = **0.250** per the body text); aggregate N_FD/N_D = **1.125** (9 associated failures after 8 delay events). SDCs clustering near RO frequency-shift transitions is the paper's core evidence for the timing-margin-erosion mechanism.
- **Baseline vs beam contrast (Fig. 10 vs Fig. 11):** all 8 RO traces stayed inside the ±0.005 noise band for 24 h pre-beam, while the beam run produced step-like frequency drops (e.g., RO_1 dropping to ≈0.994 normalized frequency and persisting) in specific ROs (RO_1, RO_3, RO_6) while RO_2/RO_4/RO_5 remained quiet — evidence that perturbations localize to specific interconnect frame regions rather than acting globally.
- **Neutron vs injection agreement (Fig. 14):** frame-level injection reproduced the beam taxonomy per region — **RO1- and RO6-associated frames → SDC (recovered)**, **RO3 → availability failure (reset required)**, **RO7 → detectable protocol error (recovered)**, RO0/RO4 → RO shift but correct transactions — matching the spatial pattern seen under neutron exposure and supporting the frame-localized interpretation; RO2/RO5 showed no shift and correct transactions under both modes.

## Critical Assessment

- **The headline correlation rests on very thin counts.** P̃(SDC|D)=0.500 is computed from **4 events out of 8** delay events; P̃=0.375 from 3, P̃=0.250 from 2. With Poisson counts this small, confidence intervals are enormous, and although Section III-E carefully derives the Poisson CI machinery, **no confidence intervals are actually printed for any conditional metric**, and no test is shown that the association exceeds chance (e.g., what fraction of fluence-time lies inside ΔT windows, or a shuffled-window control). The paper honestly labels the metrics "statistical association measures rather than deterministic causality proofs," but the title's "From Routing Delay Shifts to Silent Data Corruption" reads far more causally than 4 co-occurrences can support.
- **Internal numerical inconsistencies undermine confidence in the numbers.** The body text (Section V-E) reports every cross-section as ×10⁻¹² cm² (e.g., "1.33 × 10⁻¹² cm²"), while Table III — and the trivially checkable arithmetic N/Φ (8/6.0×10¹⁰ = 1.33×10⁻¹⁰) — says ×10⁻¹⁰ cm². Worse, Table III lists P̃(F_P|D) = 0.375 for detectable protocol errors, contradicting the body text's 0.250 (which matches the table's own associated count of 2/8). These are likely typos, but in a paper whose entire contribution is a set of measured numbers, that is a real defect.
- **The ΔT window is never quantified.** The entire correlation methodology hinges on a "predefined temporal association window of duration ΔT," yet its actual width is not reported anywhere in the experimental sections, and no sensitivity analysis varies it. As printed, the conditional probabilities are not reproducible.
- **Sparse observability, acknowledged but consequential.** Only 8 ROs sample a subset of interconnect frames; the author concedes that failures not preceded by an RO event may stem from unmonitored regions, so the RO array provides "localized observability... not exhaustive fault coverage." RO placement also necessarily perturbs the routing under test — the paper admits the observability/intrusiveness tradeoff but does not quantify it.
- **The mechanism is argued, not directly measured.** Timing-margin erosion (Fig. 2) is a plausible physical story, but the paper never measures setup slack or sampling misalignment on an actual AXI path; the link "delay shift → marginal sampling → SDC" is inferred from RO proxies adjacent to, not on, transaction paths.
- **Scale and generality:** one device (ZCU104), one AXI topology, one workload, one beam run, self-funded — all disclosed in Scope and Limitations, but they mean the reported cross-sections are a single-sample characterization, and other FPGA families or topologies could distribute sensitivity differently. The paper is also not yet peer-reviewed (IEEE Access under review).

## Strengths

- **Genuinely careful experimental design:** the dual-board golden-reference architecture (oracle outside the neutron field) is the right way to catch SDC and eliminates the most obvious objection — that the checker itself was corrupted; the 24-hour, ±0.005-band, 100k-transaction clean baseline establishes a defensible noise floor before any event is attributed to radiation.
- **Combining stochastic beam exposure with deterministic ICAP/SEM frame-level injection in one frame-aware framework** is the paper's real methodological contribution: the per-region agreement between beam and injection responses (Fig. 14) is more convincing than either mode alone.
- **The frame map (Fig. 6) turns raw RO frequencies into spatially interpretable evidence**, enabling localization of sensitive interconnect regions rather than a single aggregate failure rate.
- **Deterministic, machine-checkable event taxonomy and statistics** (Tables I–III) make the analysis auditable and reusable by other groups.
- **An unusually honest Scope-and-Limitations subsection** and a practically valuable takeaway: systems evaluated only via timeouts/watchdogs can look robust while silently corrupting data — 18 of 53 observed failures were exactly of this type.

## Limitations

- **Statistical power:** 8 routing-delay events and ≤53 failures from a single beam campaign; conditional probabilities rest on 2–4 events each, with no printed confidence intervals and no chance-level control.
- **Unreported ΔT:** the association window width is never given, blocking reproduction of the correlation metrics and any sensitivity analysis.
- **Partial observability:** 8 ROs cover only selected frames near the interconnect; unmonitored regions can host invisible perturbations, and adding RO coverage perturbs the design under test.
- **Single-platform, single-workload, single-run:** one ZCU104, one AXI interconnect benchmark, one neutron campaign; no repeated runs, no other FPGA families, clock frequencies, or AXI topologies (all listed by the author as future work).
- **Injection ≠ beam:** frame-level injection cannot reproduce physical charge deposition or multi-bit upset patterns, so it complements but cannot fully validate the beam results.
- **Editorial quality:** the ×10⁻¹²-vs-×10⁻¹⁰ cross-section discrepancy between text and Table III, and the P̃(F_P|D) 0.375-vs-0.250 mismatch, need correction.

## Relevance

对在辐射环境（航空航天、高能物理）中以 FPGA/MPSoC 承载推理加速硬件的可靠性设计极具参考价值：本文证明 Zynq UltraScale+ 的 AXI 互联会以 18 例 SDC 的形式"无声地"返回错误数据、完全绕过 watchdog/超时类监控，因此面向 ML 加速器的容错方案必须引入束外金标准数据校验、帧感知布局隔离与 RO 运行时监控的组合。

## Questions for Further Exploration

1. What is the actual width of the ΔT association window, and how do P̃(F|D) values change under a shuffled-window or varied-ΔT control — would the 4/8 SDC association survive a chance-level test?
2. Can the timing-margin-erosion mechanism be confirmed directly by instrumenting setup/hold slack on the affected AXI paths themselves (delay sensors on transaction routes), rather than inferring it from adjacent ROs?
3. How do the cross-sections and the SDC fraction scale with clock frequency, AXI topology (Interconnect vs SmartConnect), transaction rate, and device family (e.g., Versal, Kintex Ultrascale+)?
4. Would candidate mitigations — isolation design flow (IDF), selective scrubbing, transaction replay, RO-triggered scrubbing — reduce P̃(SDC|D) specifically, rather than merely lowering total failure counts?
5. What proportion of SDCs arise from data-path delay erosion versus valid/ready handshake skew, and can a single-frame multi-bit upset generate them?
6. What is the quantitative observability-versus-intrusiveness tradeoff of increasing RO spatial coverage in the interconnect fabric?
