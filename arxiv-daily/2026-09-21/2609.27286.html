Before an agent acts, its hidden state already encodes when to compress history — and when to recall evidence.

Memory Control Signals Emerge Before Action in Long Horizon Agents

Mingxuan Wang, Guorun Yao, Fei Luo, et al. (9 authors) · TierFlow Team · Gaoling School of AI, Renmin Univ. & Tsinghua · external benchmark: Tencent WorkBuddyBench

  • long-horizon agents

Key metric

−73.2%

Token usage collapses: 2.69M → 0.72M per task on WorkBuddyBench (260 tasks, DeepSeek-V4-Flash) with PaMER — avg reward 69.9 → 69.4. PaMER+ variant: +1.7 reward at −71.7% tokens.

Why this matters

Turns “when to compress, when to recall” into a probe-predictable decision — a blueprint for memory controllers and low-cost long-horizon agents.

把“何时压缩、何时召回”形式化为隐状态可预测的决策，token 降 70%+ 而任务分基本持平 — 对长程 agent 记忆控制器与低成本推理有直接参考价值。

Critical edge

The headline recall signal (0.765 AUROC) is never deployed: the online controller retrieves via plain cosine Top-3, so PaMER validates only the compression half of the thesis.

Methodology01

  1. Probing corpus. 72,912 decision points from 2,521 trajectories on 600 held-out questions; an LLM annotator labels compress-vs-recall need at each step. Features: frozen Qwen3.5-9B last-token state (d=4096, post-RMSNorm) — no future actions leak in.
  2. Probe protocol. Per-decision linear probes (MLP as control); question-grouped 70/15/15 splits × 5 seeds; threshold by validation F1, AUROC primary. Layerwise + mean-pooling variants localize the signal.
  3. Context ablation. Recent2 = task prefix + 2 latest blocks (26.0% of tokens) vs Full Context; decision distillation from the full-context teacher; spliced-back raw evidence (Selective Top5 / embedding retrieval).
  4. PaMER controller. 5 compression heads vote on the final state (≥3 fire → compress candidates ≥1,024 tok); summaries embedded (Qwen3-Embedding-8B), Top-3 cosine re-injected later. PaMER+ adds step-level raw-evidence selection. Failure-safe: keep original history on any memory-op failure.

Where the signal forms — AUROC by layer, stylized from reported layerwise results: compression rises monotonically 0.57 → 0.831; recall peaks mid-network (block 16, 0.780) then settles at 0.765.

Strengths03

  • Question posed before existing work — does the model already represent its own memory needs? Not just another compression policy.
  • Careful probing: metadata/length controls rule out “context got long”; layerwise + pooling analyses localize the signal; question-grouped splits × 5 seeds guard against leakage.
  • Analysis → system coherence: every PaMER design choice (Recent2, last-token readout, distillation) traces to a Table 1/2 finding.
  • Evaluation breadth: 260-task full benchmark, 13 competing methods, 6 backbones, clean component ablation.
  • Honest framing: predictive-not-causal disclaimers, recall probe kept offline-only, domain-level losses reported visibly.

Limitations04

  • Effects are model- and domain-dependent: Code/Office drop for PaMER (−1.7/−2.0); GPT-5.6-Luna loses ~2 points — per-model validation required before deployment.
  • Online recall is cosine Top-3, not the probed signal — the most interesting finding is only half-exploited.
  • No significance tests or CIs on Pilot40 deltas, mostly ≤1.4 points on 10-task domains.
  • Ground truth is LLM-annotated; label quality asserted, not measured against human judgment.
  • Same-family trajectories built the probe corpus; representation-level transfer to unseen backbones untested.
  • No code or data release stated, despite a detailed reproducibility statement.

Questions for further exploration05

  1. Would a learned recall gate (0.765 AUROC) actually beat the deployed Top-3 cosine retrieval — and by how much?
  2. Do memory-decision probes transfer across backbone families at the representation level, not just behaviorally?
  3. Do the LLM-annotated labels survive human validation, and does probe accuracy drop once annotator bias is controlled?
  4. Recall peaks at block 16 — would a per-model calibrated mid-layer readout improve the deployed compression decisions too?
  5. How does the “two most recent blocks” Recent2 heuristic hold up with long interleaved tool outputs and multi-session memory?
