> **一句话总结：** ChipMEM 为 EDA 智能体加了"验证门控"的双记忆层——只有通过综合/等价性检查/隐藏测试（PASS）的轨迹才被蒸馏成可复用技能（程序性记忆），并用分层 Beta-Bayes 模型统计每次工具调用的成败以指导重试与故障恢复（统计性记忆）；在 RTL-OPT 上把平均面积增益从 6.18% 提到 8.79%（+2.61pp），在 RTLRewriter-Bench 上等价通过 39/54 对 35/54、平均面积改进 8.69% 对 5.66%，冻结记忆库迁移到 20 个未见 CVDP 任务上达到 20/20 对 18/20。

> **TL;DR:** ChipMEM is a memory layer for LLM-based EDA agents that combines (1) a procedural skill library distilled only from tool-verified trajectories (synthesis + equivalence checks or hidden simulation/coverage tests, never LLM self-assessment) and (2) a Bayesian statistical memory that tracks tool-call success/failure and ranks recovery strategies after repeated failures. Using GPT-5.5 on Cadence ChipStack 2.0, it raises mean audited area improvement on RTL-OPT from 6.18% to 8.79% (+2.61pp over the same agent with memory off), lifts RTLRewriter-Bench equivalence-passing outputs from 35/54 to 39/54 with mean area gain 5.66%→8.69% on the 49-design short suite, and transfers with a frozen read-only library from 18/20 to 20/20 accepted outcomes on held-out CVDP tasks — while cutting OpenTitan per-session tool calls from 27.4 to 23.3 (−15%).

## 核心贡献

- **验证门控的程序性记忆（Procedural memory）**：以任务嵌入为 key 的技能库，只在确定性评测 harness 判定 PASS（综合 + 功能等价 + 正向 PPA 改进；CVDP 则要求隐藏仿真/覆盖率/变异测试）后才把本次会话蒸馏成技能写入；FAIL/INVALID 不写技能，杜绝"自我感觉良好"的假经验。支持 evolving（持续写入）与 frozen（只读迁移）两种模式。
- **贝叶斯统计性记忆（Statistical memory）**：对每次工具调用做在线更新，用三层分层的 Beta-Bernoulli 后验（全局 → 错误类别 → 提示错误类型 × 重试桶，先验强度 K=8）估计重试成功概率 P_retry；当 P_retry < 0.20 时激活恢复预测器，按 q₁(action) → q₂(action×error) → q₃(×retry bucket) 对历史成功恢复策略排序，交给 LLM 恢复规划器生成有界建议方案（advisory-only）。
- **Agent 无关的适配器**：在智能体、EDA 工具与确定性评测 harness 之间提供统一接口，记录任务表示、检索上下文、执行轨迹与验证裁决，使同一记忆层可同时服务 RTL 优化与 testbench 生成两类任务而不改动底层 agent 或工具。
- **以"迁移"为核心的评测协议**：明确批评既有方法都在产生经验的那批任务上自评；用 frozen 只读库在未见 CVDP 任务上测跨任务迁移，用五设计的组件消融、OpenTitan 50 会话配对成本对比和 SWE-bench Pro 先导实验补充证据。

## Key Contributions

- A verification-grounded procedural memory for EDA agents: skills are distilled and stored **only after** the deterministic domain harness returns PASS (synthesis + formal equivalence + positive audited PPA improvement, or hidden simulation/coverage/mutation checks for CVDP) — never on model self-assessment; the library supports evolving and frozen (read-only) modes.
- A Bayesian statistical memory with two hierarchical Beta models (a retry predictor over error class / prompt-error-type / retry-bucket, and a recovery predictor ranking historically successful recovery actions), gated at P_retry < 0.20 and feeding an advisory-only LLM recovery planner.
- An agent-agnostic adapter connecting any EDA agent, its tools, and its domain evaluation harness, so both memory components attach to RTL optimization and testbench-generation agents without modifying the agent or scoring procedure.
- A transfer-centric evaluation: frozen-library transfer on unseen CVDP tasks, a four-configuration memory ablation on five RTL-OPT designs, a 50-session paired cost study on OpenTitan, and a SWE-bench Pro pilot extending the layer beyond EDA.

## Methodology

**Architecture.** ChipMEM sits between an EDA agent and its tool/evaluation stack through an adapter that (a) retrieves and supplies procedural skills, (b) supplies Bayesian recovery advice, (c) records each tool call's result, and (d) returns the final artifact to a deterministic domain evaluation harness V (explicitly not an LLM judge).

**Procedural memory.** The library is a key-value map keyed by task embedding φ (text-embedding-3-large for the GPT-5.5 group, Qwen3-Embedding-0.6B for OpenTitan). At session start, the top-2 skills with cosine similarity above threshold 0.6 are retrieved and injected. After a session, an LLM distiller summarizes the trajectory into a skill (name/summary/body with DO and AVOID sections); storage happens only if the harness verdict is PASS. In evolving mode the library grows; in frozen mode it is read-only (used for the held-out transfer study).

**Statistical memory.** After every tool call, the context x_t = (e_t, c_t, b_t) is recorded: error class e_t (e.g., syntax-error, unknown-module, liberty-missing, timing-fail, rc-nonzero), prompt error type c_t, and retry bucket b_t = min(r_t, 3). The retry predictor is a hierarchical Beta posterior p₀ → p₁(c_e) → p₂(c_t, e_t) → p₃(c_t, e_t, b_t) with p_j = (s_j + K·p_{j−1}) / (s_j + f_j + K), prior strength K = 8. If a repeated failure yields P_retry < τ_fail = 0.20, the recovery predictor ranks candidate strategies via an analogous hierarchy q₁(action) → q₂(action, e_t) → q₃(action, e_t, b_t) and passes the ranked list to an LLM recovery planner that returns a bounded advisory plan. Every completed tool call atomically persists evidence for the next decision.

**Experimental setup.** Benchmarks: RTL-OPT (38 design-level RTL optimization tasks), RTLRewriter-Bench (59 cases: 54 short, 5 long), CVDP (40 testbench tasks: 20 training + 20 held-out, split evenly between CID012 stimulus generation and CID013 checker generation), OpenTitan (10 IP blocks × 5 attempts per mode), plus a custom 20-design open-source PPA suite. Agents/models: GPT-5.5 on Cadence ChipStack 2.0 (a proprietary production EDA agent) for RTL-OPT, RTLRewriter, custom PPA, and CVDP; Qwen3.8-27B for OpenTitan. Reasoning set to medium; OpenTitan budget 40 tool steps, 600 s model timeout, 7200 s session limit. PPA measured with Yosys + ABC synthesis/equivalence (first-pass mapped area for the two public benchmarks) and OpenROAD full flows for OpenTitan; CVDP uses hidden simulation, coverage, and mutation checks. Total controlled grid: 200 proprietary PPA executions + 100 OpenTitan + 240 CVDP executions.

## Results & Highlights

- **RTL-OPT (38 designs, GPT-5.5):** mean audited area improvement rises from **6.18% → 8.79%** (+2.61pp) with ChipMEM, at identical 33/38 equivalence-passing; among equivalence-passing outputs, suboptimal-RTL area wins go 19/33 (57.6%) vs 14/23 (42.4%) and golden-RTL accepted gains 13/33 (39.4%) vs 10/33 (30.3%). For context, the same table reports DeepSeek R1 at 4.80%, DeepSeek V3 at 3.68%, and GPT-4o at 3.58%.
- **RTLRewriter-Bench (short suite, 49 scored designs):** equivalence-passing outputs **37/49 vs 33/49** (abstract headline: 39/54 vs 35/54), area wins **15/49 vs 12/49**, and mean area improvement **8.69% vs 5.66%** (+3.03pp); cell/wire geometric-mean ratios improve to 0.894/0.897 vs 0.927/0.923. On the 5 long designs, ratios reach 0.872/0.858 vs 0.903/0.892.
- **Held-out CVDP transfer (frozen read-only library, single evaluation per setting):** CID013 checker generation **10/10 vs 8/10** (+20pp), CID012 stimulus **10/10 vs 10/10** (0pp), overall **20/20 vs 18/20**. On the 20 training tasks with five passes each, the aggregate moves 88/100 (88%) → 90/100 (90%), driven by CID013 (+6pp) while CID012 slips 49/50 → 48/50 (−2pp).
- **OpenTitan (Qwen3.8-27B, 10 IP blocks × 5 attempts):** full-gate PPA passes rise **4/10 vs 1/10** with equivalence maintained at 6/10 in both modes; mean area improvement 0.2431% vs 0.0519% and mean power 2.5373% vs 0.0000%. Per-design, memory unlocks pattgen, spi_host, and keymgr (0→1 passes each), though aon_timer drops 2→1 passes.
- **Interaction cost (50 OpenTitan sessions per mode):** mean LLM calls **26.1 vs 29.4** (−11.2%), tool calls **23.3 vs 27.4** (−15.0%), tool time **369.8 s vs 420.2 s** (−12.0%), input tokens −6.8% — but output tokens **+55.0%** (1.304M vs 0.841M), and the paper's own paired clustered-bootstrap 95% CIs cross zero for every cost metric except the output-token increase.
- **Memory ablation (five RTL-OPT designs, matched settings):** Procedural+Bayesian achieves **5/5 strict passes and 10.36% audited gain** vs Memory OFF's 3/5 and 8.41%, at the lowest cost (1.49M/72k total tokens, 312k tool tokens, 119/133 LLM calls) and 49.2 min vs 111.5 min wall time; procedural-only and Bayesian-only each get 4 passes.
- **SWE-bench Pro pilot (100 tasks):** SWE-agent + ChipMEM resolves **43/100 (43.0%) vs 32/100 (32.0%)** for the SWE-agent baseline (+11pp), with overlapping Wilson 95% CIs ([33.7, 52.8] vs [23.7, 41.7]) and no paired significance test.

## Critical Assessment

- **No external memory baselines.** Every comparison is the same agent with memory disabled. ReasoningBank, Trace2Skill, SkillOP, and Voyager are cited as related memory methods, but none is run on these benchmarks, so the claim that *verification-grounded* memory is the right design rests on argument, not measurement.
- **The headline cost savings are not statistically significant.** Figure 4 and the text advertise −11.2% LLM calls / −15.0% tool calls / −12.0% tool time on OpenTitan, but the paper's own Table 11 shows clustered-bootstrap 95% CIs crossing zero for all of them (total tokens [−54.7, +29.8]; wall seconds [−196.5, +1062.8]); the only significant paired delta is output tokens **increasing** +55%. The "cheaper sessions" story is directional at best.
- **Small-n, single-shot key evidence.** The memory-component ablation uses only five RTL-OPT designs, and the frozen-library transfer headline (20/20 vs 18/20) is one evaluation per setting on 20 tasks — the +10pp equals exactly two designs, with no variance reported.
- **An unreconciled appendix result.** On the 20-design custom PPA suite, aggregate cumulative Pass@1–5 (Table 5) favors memory-OFF at every k (Pass@1 30.0±47.0 vs 20.0±41.0; Pass@5 85.0±36.6 vs 80.0±41.0), which sits oddly beside Table 3c's claim of 8/20 → 10/20 equivalence-accepted designs; the paper never explains the tension.
- **Honest but narrow gains.** CID012 stimulus transfer is saturated (10/10 both modes) and the training aggregate regresses 49/50 → 48/50; essentially all transfer value comes from CID013 checker generation. The paper reports these regressions openly, which is commendable, but it also shows the memory helps where compilation/checker know-how transfers, not universally.
- **Hand-set hyperparameters.** K=8, τ_fail=0.20, top-2 retrieval at cosine 0.6 are fixed with no sensitivity analysis; the Limitations section concedes the fixed retrieval setting but does not sweep it.
- **Reproducibility gaps.** The main model (GPT-5.5) and agent (Cadence ChipStack 2.0) are proprietary, and the custom-design/Flow studies use internal flows; the released repo cannot fully re-create the headline numbers. The Bayesian component itself is a smoothed Beta-Bernoulli hierarchy — appropriate, but conceptually simple; the novelty is the verification gate plus the combination, not the learning method.

## Strengths

- The verification gate is a clean, domain-correct fix to a real failure mode of agent memory: storing a skill requires a tool-checked PASS artifact, so memory cannot be poisoned by LLM self-assessment, and Bayesian guidance is advisory-only.
- Consistent positive results across four distinct EDA settings (two public RTL benchmarks, a proprietary custom suite, OpenTitan) plus a cross-domain SWE-bench Pro pilot, all under matched model, prompt, tool, and budget settings.
- Unusually honest reporting for a systems paper: negative rows are kept (CID012 −2pp, aon_timer 2→1 passes, CIs crossing zero, a Pass@k table favoring the baseline), and the interaction-cost study is backed by complete per-attempt audit data in the appendix.
- The frozen-library protocol directly tests the question the paper opens with — whether skills transfer across tasks and unseen designs rather than just replaying the same benchmark — and the skill inventory (Table 7) exposes exactly what was retrieved where.
- Practical payoff shown in the ablation: the combined memory simultaneously raises strict passes (5 vs 3), raises audited gain (10.36% vs 8.41%), and cuts wall time (49.2 vs 111.5 min) on matched five-design runs.

## Limitations

- The component ablation covers only five designs and the frozen-transfer result is a single evaluation per setting; neither carries variance estimates.
- Only an on/off ablation of its own memory — no comparison against alternative memory or skill-distillation methods under the same harness.
- Fixed retrieval (top-2 @ 0.6) and hand-tuned Bayesian constants (K=8, τ=0.20) without sensitivity studies.
- The two public benchmarks are measured first-pass area-only (no power/timing characterization in that loop); power claims rest on the OpenTitan and custom flows.
- All GPT-5.5 results depend on the proprietary Cadence ChipStack 2.0 agent, limiting external replication despite the code release.
- Cost benefits are mixed: output tokens grow +55% with memory, and paired efficiency deltas are not statistically significant.

## Relevance

与你关注的 LLM 智能体记忆与自进化技能库方向高度相关：ChipMEM 是 ReasoningBank / Voyager / Trace2Skill 一脉的 agent memory 思想在硬件设计（EDA）领域的落地实例，其"工具验证通过才写入技能 + 贝叶斯统计指导重试恢复"的设计对任何带可验证奖励信号的 agent 域（代码、形式化验证、科学计算）都有直接借鉴价值。

## Questions for Further Exploration

- How would ChipMEM fare head-to-head against ReasoningBank or Trace2Skill on the same RTL-OPT / RTLRewriter-Bench harness, rather than only against memory-off?
- The authors call for paired, skill-level ablations — which individual stored skills drive the +20pp CID013 checker gain, and do any retrieved skills actively hurt (as Table 7's negative-result skills suggest)?
- At matched token budgets, does the Bayesian retry model beat a simple rule-based retry cap, given K=8 and τ=0.20 were never swept?
- How does embedding-based top-2 retrieval scale as the library grows across many design families — do skill collisions degrade transfer?
- Would the frozen-library transfer results (20/20 vs 18/20) hold with repeated sampling and confidence intervals instead of a single evaluation per setting?
