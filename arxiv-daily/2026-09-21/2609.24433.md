> **一句话总结：** FoldQuantVLA 提出"一致折叠（consistent folding）"训练后量化框架——把校准期学到的一次激活变换（逐通道缩放 + 块 Hadamard 旋转）同时折叠进每个消费权重、并在运行时对激活原样执行，配合自研 TensorRT INT4 插件（CUTLASS m16n8k64 MMA、INT32 累加、逐 token 激活缩放），在不重训的前提下把 GR00T/π0.5 类 VLA 策略压到原生 W4A4：LIBERO 上 GR00T N1.7 平均成功率 95.5%、仅比 BF16 参考低 0.3 个百分点（先前的 HoloQ-VLA/DuQuant 掉 2.5–2.6 个点）；真机 ALOHA/SO-101 汇总成功率从均匀 W4A4 的 80.0% 提到 92.5%（代价仅 +1 ms 的选择性 INT8），Jetson Orin 观测到动作延迟 119 ms（较 eager PyTorch 快 2.24–5.01×）。

> **TL;DR:** FoldQuantVLA makes native 4-bit weight/4-bit activation (W4A4) inference practical for vision-language-action (VLA) robot policies by enforcing one "folding contract": a single activation transform (SmoothQuant-style channel scaling + block Hadamard rotation) is folded into every consuming weight at calibration time and executed identically at runtime, so the quantized graph provably computes the same function. With custom TensorRT INT4 plugins on GR00T N1.5/N1.6/N1.7 and π0.5, it reaches 95.5% average success on LIBERO (−0.3 pp vs the 95.8% BF16 reference, where prior W4A4 recipes HoloQ-VLA and DuQuant lose 2.5–2.6 pp), and adding selective INT8 at o_proj/down_proj (+1 ms on Jetson Orin) lifts pooled real-robot success on ALOHA/SO-101 from 80.0% (uniform W4A4) to 92.5% — above even BF16 PyTorch (87.5%) and float TensorRT (90.0%). Latency: 1.66–2.22× (desktop) and 2.24–5.01× (Orin) faster than eager PyTorch. Notably honest limitations: some architectures (SmolVLA, Evo-1) still fail badly under W4A4.

## 核心贡献

- **一致折叠契约（Consistent Folding）：** 给每个共享激活位点分配一个可逆变换 T_v（限制为对角缩放 × 旋转 × 对角缩放，才能穿过 ReLU/残差/注意力点积等不动算子），校准期确定后同时折叠进所有消费它的权重（W̃ = W T⁻¹）并在运行时对激活执行同一 T，命题 1 证明整数执行下与原图逐位等价；实验显示折叠不匹配会把 N1.6 动作模块余弦相似度拉低到 0.9923。
- **VLA 策略的 W4A4 配方：** 通道缩放（SmoothQuant 式 α 混合）+ 块 Hadamard 旋转（FWHT，β=64，O(d log d)）+ 每 token 动态激活量化 + 变换坐标系内的 GPTQ（8-bit 权重用 RTN）；动机数据：N1.6 ALOHA 审计中最差语言层 down_proj 的激活分布 max|x|/median|x| 达 587,588×/token（中位层仅 8,650×/token），故必须逐 token 缩放。
- **选择性 o/d INT8：** 在语言注意力输出投影（o_proj）和 FFN down_proj 两处保留 W8A8——它们直接喂残差流且激活散布最大；仅 +1 ms（Orin）就把真机 N1.7 汇总成功率从 80.0%（均匀 W4A4）提到 92.5%，四个 checkpoint 的留出集最小动作余弦全面提升（如 N1.6 从 0.461 → 0.850）。
- **原生低比特引擎：** 自定义 TensorRT 插件在语言骨干和动作专家（flow-matching 去噪）中都执行 W4A4/W8A8 GEMM（packed INT4 权重、INT32 累加、per-token 缩放），桌面 RTX 4070 Ti SUPER 上 1.66–2.22×、Orin 上 2.24–5.01× 于 eager PyTorch；并指出 ModelOpt W4A16 AWQ 在全部四个 checkpoint 上反而比 float 引擎慢（batch-1 下仅省权重存储不省延迟）。
- **跨 4 个 checkpoint、3 种硬件、模拟 + 真机的系统评测：** LIBERO（N1.7/N1.6/N1.5/π0.5）、SimplerEnv Bridge（WidowX）、真机单臂 ALOHA 与 SO-101（5 任务 × 20 回合），并诚实报告了失败案例（SmolVLA 37.1% vs BF16 71.1%）与统计功效不足之处。

## Key Contributions

- **A folding contract for VLA quantization:** one invertible transform per shared activation site (restricted to D^T·R·D forms, since only T = I passes nonlinearities untouched), fixed at calibration, folded into every consuming weight, and executed identically at runtime. Proposition 1 proves exact functional equivalence under integer execution; a mismatched fold empirically drops N1.6 action-module cosine to 0.9923.
- **A W4A4 recipe for action experts:** channel scaling, block Hadamard rotations via FWHT (β=64), per-token dynamic activation quantization, and GPTQ in transformed coordinates — motivated by extreme per-token activation spreads (587,588× max/median at the worst N1.6 language down_proj vs 8,650× median). Proposition 2 shows the loss is timestep-invariant under action homogeneity, matching flow-matching denoising.
- **Selective INT8 at o_proj and down_proj:** two W8A8 sites (largest activation spread, feeding the residual stream) that cost 1 ms on Orin yet raise pooled real-robot N1.7 success from 80.0% (uniform W4A4) to 92.5%, and raise held-out minimum decoded-action cosine on all four checkpoints (N1.6: 0.461 → 0.850; π0.5: 0.847 → 0.9985).
- **Deployable native engines:** custom TensorRT plugins (CUTLASS v3.6.0, m16n8k64 MMA for INT4, m16n8k32 for INT8, INT32 accumulation) execute low-bit GEMMs in both backbone and action expert; 1.66–2.22× desktop and 2.24–5.01× Orin speedups over eager PyTorch, with HoloQ-VLA-style emulation reaching only 1.03× for comparison.
- **Broad, honest evaluation:** 4 checkpoints (GR00T N1.5/N1.6/N1.7, π0.5), LIBERO + SimplerEnv Bridge + real ALOHA/SO-101, with failure archives (SmolVLA 37.1% vs 71.1% BF16; Evo-1 83.0% vs 91.6%) and explicit statistical caveats.

## Methodology

**Scope.** The framework quantizes attention and feed-forward GEMMs in the language backbone L and the iterative flow-matching action expert E of VLA policies (GR00T N1.5/N1.6/N1.7, π0.5); vision encoders, non-projection attention ops, normalization, residual arithmetic, and the action decoder stay floating point. In W4A4 engines, GR00T's adaptive layer-norm modulation uses weight-only INT8.

**Consistent fold.** For a shared activation site v with transform T_v, every consumer folds W̃ = W·T_v⁻¹ while the runtime quantizes z = T_v·x with the same T_v (Proposition 1: identity output transforms preserve the external function exactly). Because general rotations cannot pass through nonlinearities, T_v is restricted to T = D₂ᵀ·R·D₁ (positive diagonals × orthogonal rotation). Two foldings are supported: *fold-before* (default; scaling calibrated in original coordinates, W̃ = W·S·Rᵀ, division fuses into the load loop) and *fold-after* (calibrated unnormalized rotation, W̃ = W·Rᵀ·P). Any mismatch between calibration and runtime coordinates is visible as a pre-rounding error and empirically degrades action fidelity (N1.6 cosine 0.9923).

**Transform choices.** Rotations use the normalized block Hadamard transform R = I_{d/β} ⊗ β^{-1/2}·H_β with β = 64 (FWHT, O(d log d), Sylvester Hadamard, norm-preserving); the action expert uses the same block Hadamard by default. Channel scaling follows SmoothQuant, s_c = a_c^α / w_c^{1-α}, α ∈ [0,1], with bounded positive scales after rotation. Normalization gains are folded so D₁ᵀ·Γ_v stays outside the RMS denominator; down_proj folds into the gated MLP's linear branch without crossing the gate nonlinearity.

**Quantization and runtime.** Four-bit: GPTQ approximately minimizes reconstruction error in the transformed coordinates (calibration tokens propagated through the policy forward pass); eight-bit weights use RTN. The W4A4 backend packs signed INT4 weights, dynamically quantizes signed INT4 activations with per-token scales, and accumulates in INT32 (ŷ = s_w·s_a·q_wᵀq_a + b). Custom TensorRT 10.3 plugins (CUTLASS v3.6.0; m16n8k64 INT4 MMA, m16n8k32 INT8) execute all targeted projections as integer GEMMs; scales/transforms/clipping ratios are fixed at build time, and folding absorbs neighbors' parameters (fusions reduce launches and intermediates). Clipping ratio b_a ∈ [4,8] with per-token scale δ_t = r·‖z_t‖_∞/q.

**Selective INT8.** In FQ W4A4 + o/d INT8, language attention output (o_proj) and FFN down_proj run W8A8 because they feed the residual stream and have the largest activation spread; every targeted projection remains an integer GEMM, no retraining. Proposition 2 (timestep invariance): since the quantization loss is positively homogeneous in the input and inputs across denoising steps share a distribution, the optimal transform is shared across steps — the theoretical hook for quantizing flow-matching action experts without per-step scales.

**Evaluation protocol.** Fidelity: P1 (32 seeded observations, H100 MIG, vs BF16 PyTorch), P2 (32 held-out observations, min cosine + median max-abs coordinate error of flattened decoded action chunks), P3 (LIBERO, 4 suites × 5 tasks, 800 episodes/cell, paired per-task p-values); latency: 60 obs-to-action iterations after warmup on RTX 4070 Ti SUPER and Jetson AGX Orin (batch 1); real robots: single-arm ALOHA (T1) and SO-101 (T2–T4), GR00T N1.7 fine-tuned per embodiment, 20 episodes per task per arm, interleaved within a session with matched object placements.

## Results & Highlights

- **LIBERO, GR00T N1.7:** FQ W4A4 averages 95.5% success vs the 95.8% BF16 reference (Δ = −0.3 pp), while prior W4A4 recipes lose far more in the same comparison — HoloQ-VLA ≈93.0 and DuQuant ≈93.2–93.3 (Δ ≈ −2.5 to −2.6 pp). FQ W4A4 + o/d INT8 also lands at 95.5% (−0.3 pp).
- **LIBERO, π0.5:** FQ W4A4 reaches 97.3% (+0.1 vs its 97.1% reference) and with o/d INT8 97.8%, versus HoloQ-VLA's reported 98.0% (their re-run of the released pack gives 94.0% vs the reported 96.0%, p = 0.44); SmoothQuant collapses to 56.3% (−37.0 pp) and QuantVLA to 82.0% (−15.1 pp).
- **Real robots (GR00T N1.7, ALOHA T1 + SO-101 T2–T4, 80 pooled trials/arm):** FQ W4A4 + o/d INT8 hits 92.5% pooled success vs 80.0% for uniform FQ W4A4 (+12.5 pp), and beats BF16 PyTorch (87.5%), FQ W8A8 (87.5%), and float TensorRT (90.0%) — for +1 ms on Orin (120 vs 119 ms). An exploratory two-sided Fisher test on the pooled counts gives p = 0.037 (the authors flag it ignores matched placements).
- **Latency (batch 1):** desktop W4A4 is 1.66–2.22× faster than eager PyTorch and 1.25–1.52× faster than float TensorRT (N1.7: 32.2 ms vs 41 ms TRT BF16 and 67.3 ms eager; π0.5: 74.7 ms vs 113 ms and 165.7 ms); Orin speedups are 2.24–5.01× vs eager (N1.7: 119 ms vs 351 ms) and 1.20–1.33× vs the float engine. W4A4 is 10.3–15.3% faster than W8A8; compilation alone accounts for 83–92% of the eager-to-W4A4 gap; ModelOpt W4A16 AWQ is slower than the float engine on all four checkpoints.
- **Held-out action fidelity (P2):** selective INT8 raises minimum decoded-action cosine on all four checkpoints: N1.6 0.461 → 0.850, N1.7 0.802 → 0.912, N1.5 0.970 → 0.973, π0.5 0.847 → 0.9985; median max-abs coordinate error falls 0.074 → 0.039 (N1.6) and 0.099 → 0.058 (N1.7).
- **SimplerEnv Bridge (GR00T N1.6, WidowX, 200 episodes/task):** mean success 64.2% for o/d INT8 vs 61.2% for W4A4 and BF16 (paired p = 0.89 / 0.70); selective INT8 shrinks the mean per-task |Δ| vs BF16 from 13.6 to 10.1 pp and lifts basket 58.0% → 70.5% and open drawer 81.5% → 92.0%.
- **Memory:** N1.6 weight storage falls from 3802 MB (float TRT) to 2104 MB (W8A8) and 1011 MB (W4A4; 1150 MB with o/d INT8); resident memory 8349 → 4673 MB on the no-materialization serving path.

## Authors & Credibility

The team spans VinRobotics (Vietnam robotics company; first four authors), the AICV Lab at the University of Arkansas, Peking University's School of Advanced Manufacturing and Robotics, VinUniversity's Center for AI Research, and TUM — a credible academia-industry mix with direct access to robot hardware (single-arm ALOHA and SO-101 cells) and to serious embedded targets (Jetson AGX Orin, RTX 4070 Ti SUPER, H100 MIG). They build on public checkpoints (NVIDIA GR00T N1.5/N1.6/N1.7, Physical Intelligence's author-released π0.5) and standard benchmarks (LIBERO, SimplerEnv). A project page and public code repository (github.com/vunnamtrung/FoldQuantVLA) are provided. The paper is unusually candid: it reports competitor re-run discrepancies (HoloQ-VLA 94.0 vs reported 96.0), labels its Fisher test "exploratory," publishes architecture-failure archives (SmolVLA, Evo-1), and states that simulator gains do not establish superiority.

## Critical Assessment

- **Novelty is real but incremental in the theory:** Proposition 1 (fold an invertible transform into weights, execute on activations) is standard equivalence folding from the QuaRot/SmoothQuant/DuQuant lineage; the actual delta is the *deployment-level consistency requirement* — every shared consumer must carry the same transform through calibration, rounding, and native integer execution — plus the timestep-invariance argument (Prop 2) tailored to flow-matching action experts. The engineering (native INT4 TensorRT plugins executing inside the action expert, 2.22× measured vs HoloQ-VLA's emulated 1.03×) is where the paper clearly separates from prior VLA quantization work.
- **The headline real-robot gain is task-weighted and partially negative per task:** the 92.5% vs 80.0% pooled improvement is driven by SO-101 tasks; on ALOHA T1 the selective-INT8 configuration actually scores 75.0% vs 85.0% for uniform W4A4 and 95.0% for BF16 (Table VI). The paper does not explain this regression. Worse, on SO-101 T4, ModelOpt W8A8 SmoothQuant hit 30.0% with jerky motion that risked hardware and was excluded from aggregates — evidence that edge cases and small samples (20 trials/task) dominate this benchmark's conclusions.
- **Statistical power is thin where the claims are strongest:** most simulator arms use a single campaign with 40 initial states; the LIBERO gain from selective INT8 is not resolved by paired tests (p = 0.17–0.82), and the pooled real-robot Fisher test (p = 0.037) is exploratory and ignores matched placements. The stark TRT BF16 (100%) vs BF16 PyTorch (80%) gap on π0.5 T4 with 20 trials illustrates the noise floor. Fidelity metrics rest on only 32 observations and cosine ignores magnitude.
- **o/d INT8 is a bundle, not an ablation:** o_proj and down_proj are switched to W8A8 together and "the two o/d types are evaluated together, leaving their individual effects unresolved"; N1.6/N1.7 were additionally deployed with calibration changes, so only preset-matched controls isolate precision.
- **Generalization to other VLA architectures is open and partially refuted:** archived campaigns show W4A4 catastrophically failing on SmolVLA (37.1% vs 71.1% BF16) and degrading Evo-1 (83.0% vs 91.6%), and the authors have "not established that o/d INT8 restores either" — consistent folding is not a universal recipe.
- **Baseline fairness is handled reasonably but not perfectly:** HoloQ-VLA and DuQuant LIBERO rows are emulated (keeping their own projection coverage), and the authors' re-run of HoloQ-VLA underperforms its reported number by 2 pp (94.0 vs 96.0, p = 0.44) — a discrepancy they disclose but cannot explain. The inspected H100 backend lowers 4-bit to INT8, so native-INT4 latency claims are Ada/Orin-specific. A single desktop timing run cannot quantify run-to-run variability.

## Strengths

- **True native deployment, not emulation:** custom CUTLASS-backed TensorRT plugins execute INT4 GEMMs in both the language backbone and the iterative action expert — the measured 2.22× (RTX 4070 Ti SUPER) and 2.24–5.01× (Orin) speedups over eager PyTorch are real engine numbers, vs HoloQ-VLA's 1.03× for native INT4+INT4.
- **Practically decisive finding:** 1 ms of selective INT8 buys +12.5 pp pooled real-robot success over uniform W4A4 and overtakes both BF16 PyTorch and float TensorRT — a strong, actionable cost/benefit point for edge robot deployment.
- **Principled treatment of flow-matching action experts:** Prop 2's timestep-invariance (homogeneity + stable input directions) gives a clean reason per-token dynamic quantization works without per-step scale tables; the 587,588× activation-spread audit concretely motivates it.
- **Honest negative results and self-auditing:** publishes architecture-failure archives (SmolVLA −34.0 pp), competitor reproduction gaps, exploratory-test caveats, and explicitly declines to claim simulator superiority.
- **Breadth with matched controls:** 4 checkpoints, 2 robot embodiments, paired per-task seeds and preset-matched arms, plus deterministic gates (every deployed configuration is rebuilt on the assembled engine before closed-loop evaluation).

## Limitations

- **Architecture dependence:** consistent folding does not guarantee W4A4 accuracy for every VLA; SmolVLA (37.1% vs 71.1%) and Evo-1 (83.0% vs 91.6%) fail, and no diagnostic or fix (e.g., o/d INT8) is established for them.
- **Statistical scope:** one campaign / 40 initial states for most simulator arms; 20 physical trials per task; π0.5 tested on a single real task; pooled Fisher test is exploratory; P1/P2 fidelity uses 32 observations; binary success ignores smoothness and contact forces.
- **Unresolved attribution:** o_proj-INT8 and down_proj-INT8 effects are confounded (evaluated jointly); N1.6/N1.7 deployment included calibration changes beyond preset-matched precision swaps.
- **Hardware coverage:** native-INT4 latency claims hold on Ada (RTX 4070 Ti SUPER) and Orin only; H100 lowers to INT8, so datacenter-native INT4 remains unproven; one desktop timing run per checkpoint.
- **Coverage gaps:** vision encoders, normalization, residual arithmetic, and the decoder stay in floating point; speedup depends on projection coverage and does not transfer automatically to other architectures or GPUs.

## Relevance

对同时关注低比特量化/推理加速与具身智能（VLA）部署的读者，这篇是目前少见的"从量化理论一路做到原生 INT4 TensorRT 引擎 + 真机闭环"的完整工作：如果你想在自己的机器人栈上跑 4-bit 策略推理，它给出的"折叠一致性 + o_proj/down_proj 保 INT8 + 逐 token 激活缩放"配方和失败案例（SmolVLA/Evo-1）都有直接参考价值。

## Questions for Further Exploration

- Do o_proj-INT8 and down_proj-INT8 contribute independently, and can the ALOHA T1 regression under selective INT8 (75.0% vs 85.0% uniform W4A4, 95.0% BF16) be attributed to a specific site?
- Is there a cheap offline diagnostic predicting which VLA architectures survive W4A4 (why SmolVLA collapses 34 pp while GR00T loses 0.3 pp), before running 800-episode campaigns?
- Does the timestep-invariance argument (Prop 2) extend to action experts whose conditioning changes per denoising step, or to non-flow (autoregressive / diffusion) policies?
- Can native INT4 be preserved on H100/B200-class hardware, and how do the folding transforms interact with FlashAttention-style fused kernels that currently block plugin fusion?
- Would behavior-aware metrics (action smoothness, contact-force profiles) change the ranking between W4A4, o/d INT8, and float engines that binary success rates cannot resolve?
