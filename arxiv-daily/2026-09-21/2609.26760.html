— Critical Assessment

01Methodology — the growth loop

Model weights never change. An offline optimizer grows orchestration code from an empty scaffold through a localize → repair → gate loop.

  1. Seed

    A strategy-free scaffold: a main(task) stub with fixed LLM/tool interfaces and no controller — any inference-time agent stays representable.

  2. Localize

    Every failure records a function-level execution DAG; edits are confined to main + traced functions under budget L=10. No task IDs, no expected answers.

  3. Repair jointly

    A window of K failures is repaired together by GPT-5.6-terra / GPT-5.4 (offline, deliberately stronger than deployment models). Deterministic control becomes code; semantic judgment stays an LLM call.

  4. Gate

    After every Q repaired tasks, re-run the held-out 50-task gate set. Success-first: lower cost can’t buy acceptance.

  5. Commit or roll back

    Any gate drop transactionally rolls back code, task cursor, window and counters.

200 train / 50 gate / 50 final tasks per benchmark · 3 independent runs · cluster-bootstrap 95% CIs · cost counts deployed-agent calls only (judge & optimizer excluded)

03Strengths

  • Deployment-honest metrics. Calls and dollars as first-class results — the clearest success–cost frontier in recent agent literature.
  • The gate rollback earns its keep. Without it, gate success decays 30% → 16%: direct evidence that the safeguard pays, rare in agent papers.
  • Same seed, two different controllers. The most convincing qualitative evidence for low-prior growth — and the learned code stays inspectable.
  • Small-model robustness. Flat 44.7–45.3% from 4 B–120 B, directly useful for on-device agents.
  • Engineering hygiene. Atomic checkpoints, full-state rollback, anti-cheat constraints on the optimizer, stated budgets.

04Limitations

  • Thin statistics. 50-task final sets → ±11–13 pp CIs; several headline comparisons statistically unresolved.
  • Unpriced optimizer. Frontier-model cost excluded everywhere; the amortization break-even is acknowledged, never computed.
  • Narrow ablations, missing rivals. Single-run, one benchmark, one model; no AutoHarness / Meta-Harness / GEPA at matched budgets.
  • Flattering scope. WebArena-Verified capped to 3 sites; baselines re-implementations (AgentOccam anomalously low).
  • Transfer & safety open. Environment-tuned constants (e.g. 9,000-char snippet cap); sandboxing unaddressed; no code release.

05Questions for further exploration

  • Break-even: how many reused tasks repay the offline optimizer’s token bill?
  • Transfer: does a harness grown on one task family help a related one — or fail fast under shift?
  • Gate noise: at Q=1 with 50 gate tasks, what are the false-accept rates?
  • Head-to-head: trace-local growth vs AutoHarness / Meta-Harness / GEPA under identical budgets?
  • Drift: does trace-localization degrade as the harness outgrows its traces?
  • Composition: can per-family specialists merge into one harness, or does shared main fight it?
