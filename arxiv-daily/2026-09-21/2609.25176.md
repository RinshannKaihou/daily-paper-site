> **一句话总结：** 阿里巴巴 Token Foundry 的 Qwen-Audio-3.1-Realtime 技术报告：用 Core-Cocktail SFT + M²-OPD（文本教师+冻结音频参考的多模态 on-policy 蒸馏、多教师专家整合）打基础，再用自进化可执行环境 + 对话/里程碑/回合三级 GRPO 反馈教模型"边说边做事"，将 τ-Voice 半双工任务成功率从 78.4% 提到 82.0%，SpeechFCEval 从 83.28% 升至 86.00%，AMC 从 47.12 升至 52.21（超过 GPT-Realtime-2 的 50.33），背景语音误响应率从 73% 降到 13%。

> **TL;DR:** Alibaba's Qwen-Audio-3.1-Realtime report upgrades its full-duplex voice model from "fast talking" to "reliable acting." Foundation training transfers text-LLM capabilities into the AudioLM via Core-Cocktail SFT plus M²-OPD (Multimodality OPD against a Text Teacher + frozen Audio Reference, and Multi-Teacher OPD consolidating GRPO-trained domain experts); agentic training rolls out the model in self-evolving executable environments (tool pool + JSON database + natural-language business policy) with GRPO feedback at dialogue, milestone, and turn granularity. On the half-duplex S2T adaptation of τ-Voice, overall task success rises from 78.4% (Qwen-Audio-3.0) to 82.0% (+3.6 pts, Airline +10.0 pts); SpeechFCEval improves 83.28% → 86.00% vs SeedDuplex-1.2.6.1's 54.73% and GPT-Realtime-2's 70.74%; Multi-Challenge AMC goes 47.12 → 52.21, above GPT-Realtime-2's 50.33. Full-duplex behavior also improves: background-speech false response rate drops 0.73 → 0.13 on FDB v1.5 while resume rate rises 0.26 → 0.87, and FDB v3.0 filler rate falls 0.759 → 0.296. The report is candid that comparisons are descriptive, with no component ablations or significance tests, and several metrics regress (EVA-A Mean 70.50 → 66.26, retrieval F1 −2.26 pts).

## 核心贡献

- **提出"Think / Act / Speak and Coordinate"三层框架**：把实时语音助手拆成音频推理与多轮指令跟随（Think）、把语音意图转成受任务与政策约束的可执行决策（Act）、以及决定"是否/何时/如何"说话的会话策略（Speak and Coordinate），Act 与 Speak 可并发（边执行工具边汇报进度）。
- **M²-OPD 双路径 on-policy 蒸馏**：Multimodality OPD 用 Text Teacher（只给文本等价 prompt）+ 冻结的 Audio Reference（给原始音频上下文）在学生自己生成的轨迹上逐 token 提供监督，把文本推理/工具决策能力迁到音频侧；Multi-Teacher OPD 先用 GRPO 训出共情、语用意图、声学场景等领域专家，再把专家分布整合回单一主模型，推理时只需部署一个 AudioLM。
- **自进化可执行环境训练**：环境 = 工具池 + 有状态 JSON 数据库 + 自然语言业务政策（负面约束是一等测试目标），任务区分 write / justified refusal / unsupported 三类期望终态；rollout 结果自动标注任务难度并驱动下一代环境生成（困难案例入 ledger，坏环境先修复），无效 rollout 重采样而不给人工零奖励。
- **三级粒度 GRPO 反馈**：对话级（整段对话终态比较）、里程碑级（从保存的前缀状态续采样再比较）、回合级（单个决策点的局部检查），可跨训练阶段组合。
- **把语音交互形式化为会话策略**并配套 Voice Harness 系统设计（前台交互 / 后台持久任务 / 有界记忆），用 134 例座舱任务集单独评估了前后台混合路由：任务成功率 91.04%，比纯前台高 18.66 个百分点。

## Key Contributions

- A three-layer decomposition of realtime voice interaction — Think (audio reasoning/multi-turn instruction following), Act (tool use under task and policy constraints), and Speak & Coordinate (a conversational policy over whether/when/how to speak) — supporting concurrent action and speech.
- M²-OPD: two on-policy distillation paths that operate on student-generated trajectories — Multimodality OPD (Text Teacher + frozen Audio Reference supply complementary token-level distributions) and Multi-Teacher OPD (GRPO-trained audio-domain experts consolidated into one deployable AudioLM).
- Self-evolving executable training environments (tool pool + stateful JSON database + natural-language business policy where negative constraints like "never take payment details" are first-class test targets), with construction checks, three terminal-outcome classes (write / justified refusal / unsupported), invalid-rollout resampling, and difficulty-driven task generation.
- Three-granularity GRPO feedback (dialogue / milestone / turn level) plus specialized rewards for search-query quality-and-count (r_query = q·min(1, n_ref/n_pred)) and progress reporting before tool calls (required/disallowed/optional acknowledgment labels).
- A separate Persistent Voice Harness (foreground interaction / background durable execution / bounded memory), evaluated independently: hybrid foreground-background routing reaches 91.04% task success vs 72.39% foreground-only on a 134-case cockpit set, at 4.729 s vs 6.495 s overall mean latency.

## Methodology

**Foundation training (Section 3).** The audio-pretrained AudioLM (three-stage recipe from Qwen-Audio-3.0-ASR: self-supervised + supervised encoder pretraining, then adapter-based connection to a frozen Qwen LLM) undergoes four stages: (1) Core-Cocktail SFT re-anchors the AudioLM to the source Text LLM as a language-parameter anchor via controlled SFT and parameter reconciliation, on million-hour-scale paired audio-text data spanning understanding, instruction following, multi-turn interaction, tool-oriented requests, emotion, and acoustic scenes; (2) Multimodality OPD lets the Audio Student sample trajectories y ~ πθ(·|x_a), on which a Text Teacher (given the text-equivalent prompt) and a frozen Audio Reference (given the original audio) both provide token-level distributions — behavior alignment along generated trajectories rather than input-feature similarity; (3) domain expert training applies GRPO with domain data to create specialists (empathy, pragmatic intent, acoustic scenes); (4) Multi-Teacher OPD consolidates expert token-level distributions on student trajectories into the single main AudioLM.

**Agentic training (Section 4).** Each executable domain bundles tools (plain functions with mechanically derived JSON schemas, failures returned as data), a JSON database (fresh private copy per episode, "no change" is a first-class outcome), and a natural-language business policy placed in the system prompt. A task tuple specifies initial state, user script (facts and when to reveal them), expected terminal condition (write / justified refusal / unsupported), behavioral assertions (e.g., confirm before write, truthful status reporting), and a reference tool chain. Construction checks replay the reference solution model-free before rollout; an LLM-based user simulator follows the script but never sees tool calls or internal state. Scoring applies terminal-state checks, write-set checks, and behavioral assertions in order; infrastructure failures are resampled, never scored as zero reward. Rollout aggregates label tasks solved/failed/near-boundary and drive generation of harder environments. GRPO then receives feedback at three scales: complete dialogues, continuations from saved milestone prefixes, and local turn-level checks with distractor-tool filtering. Two specialized behaviors are trained: speech-conditioned search (whether to search, what to query, faithfulness to retrieved evidence, with a query count penalty) and progress reporting before tool calls without premature success claims.

**Conversational policy (Section 5).** Whether to speak/act (capability boundaries, permissions — "a spoken promise is neither proof of execution nor an authorization token"), when to speak (a duplex decision policy a_t = π(o_≤t, h_≤t, s_t) over continue/begin/stop/resume, with distinct semantics for takeover, interruption, and backchannel), and how to speak (length-neutral rewards, persona-key-matching not rewarded, audio-dependent empathy trained from hesitation/fatigue/crying cues without restating them verbally).

**Evaluation (Section 6).** S2T (speech in, text out) protocol unless stated; comparisons are descriptive release-level deltas vs Qwen-Audio-3.0-Realtime, GPT-Realtime-2, SeedDuplex-1.2.6.1, and Gemini models, on public benchmarks (AMC/MC, LongBench v2, MMAU, FLEURS, τ-Voice, SpeechFCEval, FDB v1.0/v1.5/v3.0, CharacterEval, RMTBench, EchoMind, HalluQA, TruthfulQA, DNA/CDNA) and in-house sets (14-language multilingual BBA, Long-AMC, VoiceChat/VoiceChat-L, WebSearch1K, Qwen-Audio-FDB, PersonaCross, 20+ Turns).

## Results & Highlights

- **Agentic tool use:** On the half-duplex S2T adaptation of τ-Voice (Retail/Airline/Telecom), overall task success rises from 78.4% (Qwen-Audio-3.0) to 82.0% (+3.6 pts), with Airline +10.0 (64.0 → 74.0) and Telecom +3.5 (90.4 → 93.9); SeedDuplex-1.2.6.1 scores 40.3 overall but under a different protocol (GPT-Realtime-2's 43.8 uses the official full-duplex S2S setting, explicitly flagged as not directly comparable). On SpeechFCEval, 3.1 reaches 86.00% vs 83.28% for 3.0, 70.74% for GPT-Realtime-2, and 54.73% for SeedDuplex.
- **Spoken reasoning/instruction following:** AMC rises 47.12 → 52.21 (+5.09 pts, above GPT-Realtime-2's 50.33 and SeedDuplex's 41.91); text-in/text-out Multi-Challenge 52.38 → 53.85; in-house 14-language multilingual BBA macro-average 81.7 → 88.1 (+6.4 pts); FLEURS macro-average WER drops 9.01 → 3.98 (better than Gemini-3.7-Flash's 4.58), with LibriSpeech clean/other WER at 1.19/2.31.
- **Long context:** LongBench v2 43.14 → 49.90 (+6.76 pts), MiniLongBench 55.70 → 60.10 (+4.40), in-house Long-AMC (25–45-turn instruction following) 44.44 → 52.48 (+8.04); VoiceChat-L is flat at 4.61 → 4.58 (−0.03).
- **Full-duplex interaction:** FDB v1.5 Background Speech false-response rate falls 0.73 → 0.13 while resume rate rises 0.26 → 0.87; Talking to Others response rate 0.13 → 0.03 with resume 0.82 → 0.96; FDB v3.0 filler rate 0.759 → 0.296 and interruption error 0.1110 vs 3.0's 0.1170; in-house Qwen-Audio-FDB semantic-control session pass jumps 0.07 → 0.68.
- **Retrieval discipline:** On in-house WebSearch1K (1,000 single-turn examples, incl. 99 no-search negatives), mean proposed queries drop 4.37 → 1.05 (−76.0% relative), within the judge-estimated 1–5 target — but retrieval-triggering F1 also decreases 60.87 → 58.61 (−2.26 pts).
- **Empathy/persona:** EchoMind 3.70 → 4.03; PersonaCross 3.46 → 3.73; both synthetic empathy scores reach 4.99. On VoiceChat (218 Chinese conversations), 3.1 posts the highest displayed overall Spoken (4.100) and Rubric (0.961) scores, with the largest gain on voice/persona switching (3.469 → 4.106) — though Daily Chat persona interaction slips 3.685 → 3.571.
- **Safety:** HalluQA 68.44 → 71.33, CDNA 83.49 → 90.57 (+7.08), capability-boundary accuracy 94.51 → 96.77; in-house multi-turn attack success falls 54.50 pts (Chinese) and 40.00 pts (English); 3.1 leads six of seven metrics but GPT-Realtime-2 keeps the top TruthfulQA (83.92 vs 82.28), and the 50-session human red-team pass rate is 92.00% vs GPT-Realtime-2's 96.00%.
- **Voice Harness routing (separate system, 3.0 foreground):** hybrid routing 91.04% task success vs 72.39% foreground-only (+18.66 pts) and 80.60% all-delegated; multi-step latency 43.430 s vs 67.705 s foreground-only — but multi-step subset is only 6 turns and the reply judge shares a model family with the background executor.

## Authors & Credibility

Authored by the Alibaba Token Foundry, Alibaba Group, with a deliberately alphabetical 17-person author list (Lujia Bao through Qiquan Zhang) — a team-credit convention typical of industrial model releases. The team builds directly on the published Qwen-Audio-3.0-ASR, Fun-Audio-Chat, and DrVoice lineages from Alibaba, and cites external work it extends (GRPO from DeepSeekMath, on-policy distillation from Thinking Machines Labs, τ-Voice, Full-Duplex-Bench v1–v3, EVA-Bench). Credibility is high for engineering execution: the report is unusually honest about protocol caveats (EVA-A covers 200 of 213 sessions; τ-Voice results are a half-duplex adaptation, not the official full-duplex protocol; bold marks "best displayed result... not direct statistical significance"; "release-level comparisons do not isolate individual training components"). No code or training data is released alongside, but the model itself is served via Alibaba Cloud Model Studio and the appendix documents environment construction in reproducible detail.

## Critical Assessment

- **It is a release report, not a methods paper.** The core scientific claim — that M²-OPD plus self-evolving environments causes the gains — is never tested: Section 8 openly states "Controlled ablations are needed to attribute changes to Core-Cocktail SFT, either OPD path, environment evolution, or rollout granularity." Every number is a release-level delta confounded by data, compute, and recipe changes at once.
- **In-house benchmark dominance undermines verifiability.** The biggest wins (multilingual BBA extension, Long-AMC, VoiceChat, VoiceChat-L, WebSearch1K, Qwen-Audio-FDB, PersonaCross, 20+ Turns) are proprietary and unreleased, so the headline +6.4 multilingual and +8.04 Long-AMC gains cannot be independently checked; public-benchmark gains are comparatively modest (AMC +5.09, LongBench v2 +6.76). LLM judges (GPT-4o-mini, GPT-5.6-luna, Gemini-3.1-pro-preview) score most conversational metrics, with no judge-bias analysis.
- **Baseline comparability is uneven, though flagged.** On τ-Voice, 3.1's 82.0% is a half-duplex S2T adaptation of the benchmark's full-duplex task aggregate, while GPT-Realtime-2's 43.8% uses the official full-duplex S2S protocol — placing both in one table invites over-reading; the same applies to EVA-A, where 3.1's configuration "differs slightly from the official setup." The honest framing is welcome, but the layout still flatters the 3.1 numbers.
- **Several metrics regress and are under-discussed:** EVA-A Mean drops 70.50 → 66.26 even as Pass rises; MMAU slips 82.21 → 81.60; retrieval F1 loses 2.26 pts while the −76% query reduction is partly achieved by data-side pruning plus a GRPO count penalty (the paper concedes it "does not establish measured savings in search latency"); VoiceChat Daily Chat Spoken falls 4.046 → 3.946; and the human red-team pass rate (92.00%) trails GPT-Realtime-2 (96.00%).
- **Small-sample and single-run evidence:** the multi-step latency comparison rests on 6 turns, EVA-A drops 13 sessions after inference failures/scoring timeouts, τ-Voice excludes 13 of 213 sessions, and no repeated-seed, confidence-interval, or contamination analysis exists anywhere in the report.
- **The Voice Harness routing result is about system design, not the 3.1 model:** the foreground is Qwen-Audio-3.0-Realtime and the text-background baseline gets the same synthesized speech, so the +18.66 pts is a routing-architecture claim evaluated on the previous model.

## Strengths

- The executable-environment formulation is genuinely well-engineered: negative business-policy constraints as first-class test targets, the write / justified-refusal / unsupported outcome taxonomy, model-free construction checks via reference-solution replay, and per-episode private database copies are concrete, transferable design patterns for training spoken (or text) agents.
- Three-granularity GRPO feedback (dialogue/milestone/turn) directly addresses the credit-assignment weakness of outcome-only rewards, and the milestone scorer's rule — hold pending actions to their deadline and never reward a completion claim before it is true — is a crisp anti-hallucination reward design.
- Breadth of evaluation across intelligence, action, interaction, real-time, and safety (450-item HalluQA, 939 DNA, 2,726 CDNA, 50-session human red-team) far exceeds typical audio-model reports, and the report's self-criticism section is specific rather than boilerplate.
- Honest, explicitly-labeled deltas in both directions (gains and regressions are both tabulated), with per-table protocol caveats.
- The full-duplex behavior results are practically meaningful: cutting background-speech false responses 0.73 → 0.13 while raising resume rate to 0.87 is the difference between an assistant that barges in and one that waits and yields.

## Limitations

- No ablations or statistical testing: component attribution (SFT vs OPD paths vs environment evolution vs rollout granularity) is deferred to future work, and all comparisons are single-run descriptive deltas.
- Heavy reliance on unreleased in-house benchmarks and LLM judges limits reproducibility; several key tables cannot be recomputed by outsiders.
- Cross-model protocol mismatches (half-duplex adaptation vs official full-duplex τ-Voice; modified EVA-A configuration) weaken the headline comparisons even though they are disclosed.
- The persistent-agent Voice Harness is evaluated only on a 134-case prototype with a 3.0 foreground model, synthetic speech, and a same-family reply judge; formal async lifecycle and runtime permission guarantees remain unvalidated.
- No long-horizon executable spoken-task evaluation, no real-recording duplex testing, no end-to-end latency/cost measurements, and no large-scale human red-team beyond 50 sessions.

## Relevance

这篇报告是"语音模型从能听会说走向能做事"的代表性工业实践：M²-OPD 的 on-policy 蒸馏、自进化可执行环境与三级粒度 GRPO 反馈，对做多模态 agent 后训练与 RL 奖励设计的读者都有直接可借鉴的工程细节；同时它对协议可比性、无消融、私有评测集等问题的坦诚标注，也是阅读同类技术报告时值得对照的方法论样本。

## Questions for Further Exploration

- Which component contributes most — Core-Cocktail SFT, Multimodality OPD, Multi-Teacher OPD, or environment evolution? A component-wise ablation (acknowledged as missing) would decide whether M²-OPD is the driver or the environment feedback is.
- How do the gains transfer when duplex evaluation uses real recordings and deployment conditions instead of synthesized speech, and does the 0.73 → 0.13 background-speech reduction hold in noisy far-field settings?
- Does the −76% search-query reduction translate into measured latency/cost savings, or does the lower retrieval F1 (−2.26 pts) surface as more wrong-source answers downstream?
- Can the write / justified-refusal / unsupported task taxonomy and reference-replay construction checks be released as a public benchmark for spoken agent reliability?
- Would the hybrid Voice Harness routing result persist with the 3.1 model as foreground, and with a reply judge independent of the background executor's model family?
