> **一句话总结：** 本文发现 LLM agent 在每次行动前的"前动作隐状态"已经线性可读出压缩与召回需求（AUROC 分别 0.831/0.765，显著高于仅用上下文长度 0.751/0.552 的元数据基线），据此提出 PaMER/PaMER+：用冻结 Qwen3.5-9B 的隐状态触发历史压缩、并用嵌入检索回注历史证据，在 WorkBuddyBench 260 个任务上把 DeepSeek-V4-Flash 的 token 消耗从 2.69M 降到 0.72M（−73.2%），平均分 69.9→69.4（PaMER）/71.6（PaMER+，+1.7）。

> **TL;DR:** Linear probes on the pre-action hidden state of a frozen Qwen3.5-9B predict when a long-horizon agent should compress history (0.831 AUROC) and when it needs earlier evidence recalled (0.765 AUROC), beating length/turn-count (0.751/0.552) and richer metadata (0.758/0.549) controls on a 72,912-decision-point corpus. The authors build PaMER, which uses the final hidden state (5-head committee) to trigger compression of old trajectory blocks, stores Qwen3-Embedding-8B-encoded summaries, and retrieves Top-3 summaries on later turns; PaMER+ adds step-level raw-evidence selection. On WorkBuddyBench (260 tasks), PaMER cuts DeepSeek-V4-Flash token usage by 73.2% (2.69M→0.72M) at −0.4 avg reward, and PaMER+ achieves +1.7 reward (69.9→71.6) at −71.7% tokens, outperforming PACE (−9.1), LLMLingua-2 (−5.5), SelfCompact (−1.6), and Sculptor (−8.3) on Pilot40 — though Periodic Summary (n=5) still scores higher (70.2 vs 68.9) at 2.4× the token cost, and GPT-5.6-Luna loses ~2 points under both variants.

## 核心贡献

- **前动作信号的存在性证明**：在 agent 产生下一个动作之前，其末层隐状态已线性编码了"该不该压缩历史"与"要不要找回早期证据"两类记忆决策信息——压缩 AUROC 0.831、召回 0.765，均超过上下文长度/轮数（0.751/0.552）与元数据（0.758/0.549）等可观测对照；非线性 MLP 几乎无额外增益（0.827/0.763），说明信息线性可读。
- **信号随深度形成的刻画**：压缩信号随层数单调增强（最早层仅约 0.57 → 末层 0.831），而召回信号在中间层（第 16 块）达到峰值 0.780 后回落到 0.765；末 token 表示一致优于 mean pooling（压缩 0.831 vs 0.712，召回 0.765 vs 0.696）——两种记忆需求在网络中以不同模式形成。
- **历史信息量的量化**：仅保留任务前缀 + 最近两个完整交互块（Recent2，约 26.0% token 预算）即可保留大部分预测性能（压缩/召回 AUROC 0.776/0.761，全上下文为 0.829/0.780）；而回注选择性原始历史证据可将压缩 AUROC 恢复到 0.832（甚至超过全上下文），证明"近期上下文承载工作状态、外部历史补足长程依赖"的设计原则。
- **PaMER / PaMER+ 系统**：将上述发现转化为在线记忆控制器——冻结 Qwen3.5-9B 的前动作末态经 5 个独立压缩头投票（≥3 超阈值即触发）决定何时压缩；压缩摘要经 Qwen3-Embedding-8B 编码入库，后续轮次按余弦相似度检索 Top-3 回注；PaMER+ 进一步做步级证据选择，只回注当前任务真正需要的原始历史步骤。
- **系统性评测**：在 WorkBuddyBench 全量 260 任务与 Pilot40 上，与 5 种滑窗/周期摘要基线、9 种已发表上下文管理方法（PACE、LLMLingua-2、SelfCompact、ACON-Core、Self-GC、LRE、CoMem、SAM、SWE-Pruner、Sculptor）及 ACM 对比，并跨 6 个模型骨干验证。

## Key Contributions

- **Evidence of pre-action memory signals:** The final-layer hidden state immediately before an agent action linearly encodes both compression need (0.831 AUROC) and recall need (0.765 AUROC), exceeding length/turn (0.751/0.552) and metadata (0.758/0.549) controls; a nonlinear MLP adds almost nothing (0.827/0.763), showing the information is linearly accessible without adapting the model.
- **Depth-wise characterization:** Compression signal strengthens monotonically with depth (~0.57 at earliest measured layer → 0.831 at final), while recall peaks mid-network (block 16, 0.780 vs 0.765 final); last-token readout consistently beats mean pooling (compression 0.831 vs 0.712; recall 0.765 vs 0.696) — the two memory needs develop differently during computation.
- **Quantification of how much history matters:** Recent2 (task prefix + two most recent complete interaction blocks, 26.0% of the Full Context token budget) preserves most predictive performance (0.776/0.761 vs 0.829/0.780 full-context AUROC), and restoring selectively chosen raw historical evidence recovers compression AUROC to 0.832 — above Full Context — supporting the principle: recent context carries the working state, external history restores missing long-range evidence.
- **PaMER / PaMER+ systems:** An online memory controller where the frozen Qwen3.5-9B pre-action final state, read by five independent compression heads (compress when ≥3 exceed validation thresholds), decides when to compress; summaries are embedded with Qwen3-Embedding-8B and Top-3 retrieved later; PaMER+ adds step-level raw-evidence selection (raw_steps_needed).
- **Comprehensive evaluation:** Full WorkBuddyBench (260 tasks) plus Pilot40 comparisons against sliding-window/periodic-summary controls, nine published context-management methods, and cross-backbone evaluation over six models.

## Methodology

**Probing corpus.** The authors collect 72,912 decision points from 2,521 long agent trajectories covering 600 questions (disjoint from WorkBuddyBench). An LLM annotator (procedure in Appendix A.1, reviewed by authors) labels, at each step, whether the trajectory needs compression (older context should be condensed) or recall (earlier evidence, assumed present in an external memory, is needed again). For each decision point they extract the frozen model's final hidden sequence representation after output RMSNorm, using the last input token (d=4096) as h_t; neither the annotation nor future actions leak into the input.

**Probe protocol.** Independent linear probes (plus a one-hidden-layer MLP control) are trained per memory decision with class-weighted binary cross-entropy; question-grouped 70/15/15 train/val/test splits (all states of one question stay in one split) over five seeds; thresholds chosen by validation F1; AUROC is the primary metric (AUPRC in appendix). Layerwise probes are trained at every decoder layer for both last-token and mean-pooled representations, plus a positive-minus-negative logit-gap analysis.

**Context-ablation analysis.** Recent2 = task/system prefix P_t ⊕ two most recent complete interaction blocks R_t (26.0% of Full Context tokens). Decision distillation (KD) transfers Full-Context teacher predictions into the Recent2 probe. Recovered-history conditions splice selected historical evidence E_t back in: Selective Raw Top5 (oracle-ish selection of raw steps), Qwen Retrieval (embedding-based, practical), and Hidden Bank Recent5.

**PaMER online controller.** The active context keeps P_t and R_t; older complete blocks become compression candidates. For a candidate ≥1,024 tokens, five independently trained compression heads read the final state of P_t ⊕ R_t; compression fires when ≥3 heads exceed their validation-selected thresholds. Each head is trained on Recent2 with both the compression annotation and the Full-Context teacher prediction (loss = WBCE + 0.5·BCEWithLogits on teacher soft label, Eq. 9). On trigger, older blocks are summarized; summaries are encoded with Qwen3-Embedding-8B and stored with links to the covered history; raw blocks are deleted only after storage succeeds. The fresh summary is not inserted into the same request, and no recall is performed on it, so the context reduction cannot be immediately undone. On later requests, the task + Recent2 form an embedding query; Top-3 summaries by cosine similarity are inserted between prefix and recent blocks. The learned recall probe is explicitly NOT used as the online retrieval gate — analysis and deployment stay separate. On any memory-operation failure, the controller keeps the original history (no incomplete updates). **PaMER+** records step_details per summary linking content to original historical steps; a selector specifies raw_steps_needed and only those complete blocks enter the recall path, so retrieved summaries identify candidate memory but raw steps carry the actual evidence.

**Evaluation.** WorkBuddyBench: 260 tasks (80 Code, 50 Office, 60 Security, 70 Web); Pilot40: 10 fixed tasks per domain. Metric: mean task reward ×100; tokens = mean total input+output per task. Base agent: DeepSeek-V4-Flash for the main tables; cross-model table covers GPT-5.6-Luna, GLM-5.3-Flash, HY-3, MiMo-V2.5, Qwen3.8-Flash.

## Results & Highlights

- **Probing beats observable controls (Table 1):** Final hidden state gives 0.831 compression / 0.765 recall AUROC vs 0.751/0.552 for Length/Turn and 0.758/0.549 for Metadata — a +0.073/+0.207 edge over the strongest observable control (Metadata); the MLP variant adds no gain (0.827/0.763).
- **Recent context carries most of the signal, but not all (Table 2):** Recent2 uses 26.0% of Full Context tokens and retains 0.776/0.761 AUROC (vs 0.829/0.780 Full Context); adding decision distillation nudges compression to 0.781 but recall drops to 0.753. Selective Raw Top5 restores compression AUROC to 0.832 — above Full Context's 0.829 — at 66.2% of the token budget, while practical Qwen Retrieval reaches 0.804/0.764 at 53.9%.
- **Full benchmark token collapse with flat-to-better reward (Table 3):** On all 260 WorkBuddyBench tasks with DeepSeek-V4-Flash, +PaMER cuts tokens 2.69M→0.72M (−73.2%) at 69.4 avg (−0.4 vs base 69.9); +PaMER+ reaches 71.6 avg (+1.7) at 0.76M (−71.7%), with domain gains in Security (+3.8 to +4.5) and Web (+4.2 for PaMER+) offsetting Code/Office dips.
- **Pilot40 vs published methods (Table 4):** Base 67.5 avg / 1.89M tokens → +PaMER 68.0 (+0.5) at 0.90M (−52.4%), +PaMER+ 68.9 (+1.3) at 0.98M (−48.1%). Every API-based baseline loses more reward at higher token cost: PACE 58.4 (−9.1), LLMLingua-2 62.0 (−5.5), SelfCompact 65.9 (−1.6) at 1.57M, SAM 65.9 (−1.7) at 1.35M, Sculptor 59.3 (−8.3), CoMem 44.2 (−23.3) at 0.77M, ACM 33.7 (−33.8). Caveat: Periodic Summary (n=5) scores 70.2 (+2.6), higher than PaMER+, but at 2.37M tokens (2.4× PaMER+).
- **Component ablation (Fig. 3b):** PaMER 70.09 reward / 0.89M tokens / 92.5K peak context vs base agent 68.08 / 3.06M / 290.1K; removing recall drops reward to 63.70 (−6.4), removing compression explodes tokens to 3.18M with peak context 252.3K — confirming the two components play complementary roles.
- **Cross-backbone results are mixed (Table 5):** Token savings are universal (−27.6% to −88.0%), but reward moves wildly: MiMo-V2.5 +8.8/+15.8 (52.9→68.8 with PaMER+), Qwen3.8-Flash +6.8 (77.4→84.2), GLM-5.3-Flash +3.1 with PaMER but −0.3 with PaMER+, HY-3 +2.6 only with PaMER+, and GPT-5.6-Luna −2.3/−2.1 (57.2→54.9/55.1).

## Critical Assessment

- **The headline "recall signal" is not actually deployed.** The probing result (0.765 AUROC) is the paper's most novel claim, yet the online controller retrieves via plain Qwen3-Embedding-8B cosine similarity Top-3; the authors admit "the current implementation does not use the learned recall probe as a gate." So the deployed system validates only the compression half of the thesis — a disconnect between the analysis narrative and what PaMER does.
- **Probe labels come from an LLM annotator.** The 72,912 memory-decision labels are generated by an LLM, with authors "reviewing" but no human-annotation agreement statistic reported in the main text. The probes may partly be learning to predict the annotator's labeling quirks rather than genuine memory need; a control-task or human-subset validation is deferred to appendices and not quantified here.
- **A simple baseline beats PaMER+ on reward at Pilot40.** Periodic Summary (n=5) scores 70.2 avg vs PaMER+ 68.9. The paper's defense is token cost (2.37M vs 0.98M), which is fair, but it means the "maintains competitive task performance" claim holds only on the Pareto frontier, not as an outright win — and sliding window K=20 also edges PaMER (68.7 vs 68.0) at 2.2× the tokens.
- **Cross-model results undercut universality.** GPT-5.6-Luna loses ~2 points under both variants and GLM-5.3-Flash loses 0.3 with PaMER+; the impressive +15.8 on MiMo-V2.5 starts from a weak 52.9 base. The consistent claim is token reduction, not performance preservation — the abstract's "maintaining competitive task performance" is accurate but the per-model variance deserves equal billing.
- **Unablated design constants.** The ≥1,024-token candidate threshold, the 5-head committee with a ≥3 majority, and Top-3 retrieval are all fixed without main-text ablations; the reward deltas being within ±1–2 points on a 40-task Pilot40 (10 tasks/domain) also raises variance concerns — no confidence intervals or significance tests are reported.
- **Genuine strengths of the rigor:** question-grouped splits preventing leakage, five seeds, observable-control baselines for the probe, honest separation of predictive vs causal claims, and the failure-safe design (keep original history on any memory-op failure) show careful engineering.

## Strengths

- The research question is well-posed and prior to existing work: rather than proposing yet another compression policy, it asks whether the model already represents the need for memory operations — a question adjacent to Probing RAG but transplanted to the agent-trajectory setting with two coupled decisions (compress + recall).
- The probing methodology is careful: metadata/length controls rule out the trivial "context got long" explanation, layerwise and pooling analyses localize where the signal forms, and question-grouped splits with five seeds guard against leakage and variance.
- The analysis→system pipeline is coherent: each PaMER design choice (Recent2 context, final-token readout, distillation from Full Context teacher) traces directly to a Table 1/2 finding.
- Evaluation breadth is above average: 260-task full benchmark, 40-task fixed comparison set, 13 competing methods, six backbones, plus a component ablation that cleanly attributes reward to recall and token savings to compression.
- Honest framing throughout: predictive-not-causal disclaimers, explicit statement that recall probing is offline-only, and visible reporting of domain-level losses.

## Limitations

- Performance effects are model- and domain-dependent: Code and Office scores drop for PaMER on the full benchmark (−1.7, −2.0), GPT-5.6-Luna degrades ~2 points, and GLM-5.3-Flash does not benefit from PaMER+ — deployment requires per-model validation.
- The online recall mechanism is embedding similarity, not the probed signal, so the paper's most interesting scientific finding is only half-exploited; whether a learned recall gate would beat Top-3 cosine retrieval is untested.
- No statistical significance testing or confidence intervals on the Pilot40 reward deltas, which are mostly ≤1.4 points on 10-task domains.
- The memory-decision ground truth is LLM-annotated; label quality is asserted rather than measured against human judgment.
- The probing corpus is built from trajectories generated by the same family of frozen models used in deployment; transfer of the memory signal to arbitrary unseen backbones is shown only behaviorally (Table 5), not at the representation level.
- No code or data release is stated in the main text, despite a detailed reproducibility statement.

## Relevance

该文与用户对 LLM agent 记忆与上下文管理的研究兴趣高度相关：它把"何时压缩、何时召回"形式化为可从隐状态探针预测的决策问题，并用外部实验验证了该信号能驱动实用的上下文压缩系统（token 降 70%+ 而任务分数基本持平），对设计长程 agent 的记忆控制器和低成本推理都有直接参考价值。

## Questions for Further Exploration

- Would an online controller that actually gates retrieval with the learned recall probe (0.765 AUROC) outperform the deployed Top-3 cosine-similarity retrieval, and by how much?
- How well do the memory-decision probes transfer across backbone families — e.g., train the probe on Qwen3.5-9B states and evaluate AUROC on DeepSeek or GPT-5.6-Luna trajectories?
- Can the LLM-annotated compression/recall labels be validated against human judgments, and does probe accuracy drop when the annotator's biases are controlled for?
- The recall signal peaks at intermediate layer 16 — would reading the controller's readout from a mid-layer (per-model calibrated) improve the deployed compression decisions as well?
- How does PaMER behave under agentic settings with interleaved long tool outputs and multi-session memory, where the "two most recent blocks" heuristic for Recent2 may be too coarse?
