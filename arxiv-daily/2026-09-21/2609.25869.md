> **一句话总结：** 新加坡国立大学的 TESSERA 是首个面向视频扩散 Transformer 动态块稀疏注意力（BSA）的"内核级物理规划"专用运行时：它把稀疏化器给出的逻辑掩码（块几何 B）与 GPU 执行（物理 tile T + 任务组织方式）解耦成两层物理计划（Direct/Coarsened/Refined 三种映射 × 分组遍历/split-K/流水深度等组织选项），离线在 4 代 NVIDIA GPU（A100/RTX 4090/H100/RTX 5090）上用 4 万个用例预剖析并按"性能 regime"排好计划序，运行时仅做一次低开销查表（dispatch 均值 19.25 µs，比 FlashInfer 的逐请求规划 12.16 ms 低两个数量级以上）；在来自 Wan2.1/Wan2.2-14B 和 HunyuanVideo-1.5 的 2,315 个真实掩码上，完整请求延迟几何均值相对 FlashInfer 提升 1.85–5.11×、相对 FlexAttention 提升 1.62–33.73×，在 H100 的 Wan2.1 720p 与 HunyuanVideo-1.5 720p 上注意力内核加速 2.95–6.79×，但 50 步完整扩散循环仅 1.22–2.08×。

> **TL;DR:** TESSERA decouples the logical block geometry chosen by video sparsifiers (VSA, SpargeAttn, SPADE) from GPU execution: a two-layer physical plan (mapping layer: Direct/Coarsened/Refined tiles that preserve the mask's interaction set; organization layer: grouping, split-K, pipeline depth) plus profile-guided regime selection over precompiled native CUDA catalogs for 4 NVIDIA generations. Evaluated on 2,315 real masks from Wan2.1-T2V-14B, Wan2.2-T2V-14B, and HunyuanVideo-1.5, it beats FlashInfer by 1.85–5.11× (geomean complete-request speedup) and FlexAttention by 1.62–33.73×, reaches 2.95–6.79× attention-kernel speedup on H100 for 720p Wan2.1 and HunyuanVideo-1.5 inference (vs FlashInfer/flex-block-attn), and cuts per-request dispatch from FlashInfer's 12.16 ms to 19.25 µs — but the full 50-step diffusion loop only speeds up 1.22–2.08× because non-attention compute dominates.

## 核心贡献

- **两层物理计划抽象**：提出把逻辑稀疏掩码 M 的"有效交互集 E(M)"与其 GPU 执行分离的语义保持抽象——映射层（Direct T=B / Coarsened T>B 用大 tile 覆盖多个逻辑块并掩掉非激活项 / Refined T<B 把逻辑块细分为更小物理 tile）+ 任务组织层（把物理 tile 组成 CUDA task：active-block-run 分组与遍历、跨 CTA 的 split-K 并行 K/V 归约、缓冲预取的流水深度），同一掩码可在不同 GPU 上组合出不同最优计划。
- **按架构的原生 CUDA 内核目录**：为 A100 (SM80)、RTX 4090 (SM89)、H100 (SM90)、RTX 5090 (SM120) 各预编译 14–26 个计划（覆盖 3–9 种物理 tile 形状），实现约 18K 行 Python + 19K 行 C++/CUDA（不含第三方依赖）。
- **剖析引导的 regime 选择**：离线对每 GPU 用 4 万个剖析用例按请求特征（架构、块几何、张量属性；二段划分再按 batch/头数/序列长度/mask 统计量如 active-block 密度与 run 覆盖率分桶，决策树边界经交叉验证、每叶 ≥32 用例）构建"性能 regime → 按几何均值延迟排序的计划表"，运行时只传标量 mask 摘要查表并选第一个可行计划，命中失败回退到 base plan——避免逐请求穷举搜索。
- **TESSERA 运行时与全面评估**：在 4 代 GPU × 3 类基线 × 9 个负载族的全部 76 个组合上全部取胜；完整请求几何均值加速 1.85–5.11×（vs FlashInfer）、1.62–33.73×（vs FlexAttention）、3.90×（H100 上 vs flex-block-attn），并在 720p Wan2.1 与 HunyuanVideo-1.5 端到端推理中验证注意力内核 2.95–6.79× 加速。
- **实证设计洞见**：最优映射随掩码几何与 GPU 架构同时变化——同一 Q32K16 的 250 个掩码在 A100 上 100% 偏好 Coarsened 而在 RTX 4090 上全部偏好 Direct；H100 上 Coarsened 在低强度 Q16/Q28 族占优、Q28 族 220/250 偏好 Coarsened，而 Q16 族偏好 Refined（匹配 64 行 BF16 Tensor Core 指令形状）——单一固定内核无法跨场景最优。

## Key Contributions

- A semantics-preserving abstraction that decouples a logical BSA mask's interaction set E(M) from GPU execution via two-layer physical plans: a mapping layer (Direct T=B, Coarsened T>B, Refined T<B) and a task-organization layer (grouping/traversal over active-block runs, split-K parallel K/V reduction, buffered pipeline depth).
- Architecture-specific catalogs of precompiled native CUDA kernels for four NVIDIA generations (A100, RTX 4090, H100, RTX 5090; 14–26 plans each), implemented as ~18K lines of Python plus 19K lines of C++/CUDA.
- Profile-guided regime selection: offline profiling of 40k cases per GPU compiles a plan table that ranks plans per performance regime; online selection is a low-overhead lookup over scalar mask summaries (block-CSR + active-block statistics) with a base-plan fallback, avoiding exhaustive per-request search.
- TESSERA, the first specialized runtime for kernel-level physical planning of dynamic BSA in video generation: it wins in all 76 evaluated platform–baseline–family combinations, with 1.85–5.11× geomean complete-request speedup over FlashInfer, 1.62–33.73× over FlexAttention, and 3.90× over flex-block-attn on H100.
- An empirical demonstration that the fastest mapping type co-varies with both mask geometry and GPU architecture (e.g., identical Q32K16 masks favor Coarsened on A100 but Direct on RTX 4090 for all 250 aligned masks), motivating the plan portfolio.

## Methodology

**Problem setup.** A video sparsifier (VSA, SpargeAttn, SVG/SVG2, SPADE) produces, per attention head/layer/denoising step, a logical block-sparse mask M over query blocks B_Q × key/value blocks B_KV, defining the effective interaction set E(M). Attention cost remains ~85% of vDiT runtime (a 5-second 720p clip ≈ 115K tokens ≈ 16 minutes on one H100), so BSA execution quality and dispatch overhead directly bound generation speed. Existing runtimes either hard-code pre-tuned kernels (Block Sparse Attention, flex-block-attn), which cannot adapt tile shapes per GPU/mask, or plan at runtime (FlexAttention, FlashInfer), whose compilation/probing/metadata preparation dominates cold-request latency (FlashInfer's exhaustive online search reaches 12.52× the Direct baseline's cold-request latency on H100).

**Two-layer physical plans.** A plan P = (g_Q, g_KV, σ, ε) binds a mapping (how physical tiles T = (T_Q, T_KV) cover logical blocks) to a task organization σ (grouping, traversal order, split-K partitions, pipeline depth) and a precompiled native kernel ε. Direct (T=B) gives exact indexing but small tiles; Coarsened covers several logical regions per physical tile, amortizing Q/KV loads and indexing while performing redundant arithmetic on inactive entries (masked before the softmax update); Refined subdivides logical blocks into smaller tiles, saving registers/shared memory at the cost of more tiles and re-loaded state (query-side refinement keeps independent per-tile softmax states; K/V-side refinement threads tiles through a shared online-softmax state). The organization layer groups consecutive active-KV "runs" into tasks, optionally splits a query tile's K/V reduction across CTAs (split-K, with a rescale-and-merge kernel over a workspace), and tunes pipeline depth for data-movement/compute overlap.

**Offline deployment and online path.** For each target architecture, Tessera filters the portable plan portfolio into a native CUDA catalog, validates each plan numerically against a masked-attention reference and records median latency over a 40k-case profiling corpus, then partitions cases into performance regimes (coarse partition by request key k_A = architecture + logical geometry + tensor properties; finer bucketing by batch/head count/sequence length and scalar mask statistics such as active-block density and active-block-run coverage, with decision-tree boundaries chosen by cross-validation and ≥32 cases per leaf). Each regime stores a latency-ranked plan list ending in a base plan. At runtime, the GPU builds a shared mask state (block-CSR indices + active K/V column indices + scalar summaries), the host looks up the regime and scans the ranked list for the first eligible plan, performs launch preparation (metadata derivation) only for that plan, and invokes its native CUDA kernel.

**Evaluation setup.** 2,315 block-sparse masks from four sources (Wan2.1-T2V-14B, Wan2.2-T2V-14B, 40 generated + 5 official sparse-distilled HunyuanVideo-1.5), forming nine workload families over seven block geometries (B_Q×B_KV from 16×16 to 128×128, including high- and lower-density Q40×K64 variants; mean densities 5.35%–18.20%). Measurement is paired per case ID across RTX 4090, RTX 5090, A100 PCIe, and H100 SXM; plan tables come from 40k profiling cases with evaluation files distinct from profiling. Metrics span complete-request latency (preprocessing + kernel), kernel-only latency, and model-level 50-step diffusion latency; speedups are reported as geometric means over nine family means, with a regret metric (selected plan vs fastest measured eligible plan) and 95% confidence intervals in the organization ablation.

## Results & Highlights

- **Complete-request speedup (microbenchmarks, 2,315 masks, 4 GPUs):** nine-family geomeans span 1.85–5.11× over FlashInfer and 1.62–33.73× over FlexAttention across the four GPUs; on H100 the geomean over flex-block-attn's four supported families is 3.90×. Tessera wins all 76 platform × baseline × workload-family combinations.
- **Kernel-only speedup (H100, nine-family GM, Table 4):** 1.94× vs FlashInfer and 2.60× vs FlexAttention on H100 (1.12–6.38× and 1.70–6.38× across all four GPUs); flex-block-attn trails at 4.22× on its four supported H100 families.
- **End-to-end models (H100, 720p, B_Q=B_KV=64):** Wan2.1 text-to-video with SPADE sparsity and HunyuanVideo-1.5 with its official sparse-distilled model see BSA attention-kernel speedups of 2.95–6.79× over FlashInfer and flex-block-attn, but the full 50-step diffusion loop only 1.22–2.08× — the paper is explicit that loop gains are smaller because each step's non-attention computation is unchanged.
- **Dispatch overhead (H100, Q40×K64, Table 6):** Tessera dispatch mean 19.25 µs / P95 19.94 µs vs FlashInfer plan preparation mean 12,160.27 µs (12.16 ms) / P95 37,038.77 µs — more than two orders of magnitude lower mean and P95.
- **Plan-selection quality:** geomean regret vs the fastest measured eligible plan is ≤1.039 on every platform (P99 regret 1.04–1.17), with selected plans within 3% of minimum latency on 95–99% of the 2,315 cases per platform; on cold unique requests Tessera serves 14.67× faster than exhaustive online search (A1) and 1.172× faster than the fixed Direct mapping (A0), while A1 manages only 0.080× speedup over Direct cold; warm repeats are 1.288× faster than A1, and 5.374× faster over the full four-pass request including the cold pass.
- **Ablations attribute the gains:** at fixed mapping, Tessera's task organization yields a 1.105× paired-case GM kernel speedup over a fixed 2×2-cover organization on H100 Q40×K64 (95% CI [1.083, 1.127], 99/151 wins, regret 1.0005 — within 0.04× of the oracle); the best mapping type alone yields 1.38× GM kernel speedup over a fixed Direct baseline on H100; combined plans reach the 1.12–6.38× kernel totals above.
- **Mapping co-variation evidence (Figure 8):** within the H100 Q32×K16 family, 220/250 masks favor Coarsened and 30 favor Direct; the same Q32×K16 masks favor Coarsened on A100 but Direct on RTX 4090 for all 250 aligned masks (RTX 5090 mostly Direct); Coarsened holds 96.8%/98.1%/99.6% share across the three A100 Q40×K64 densities; H100's highest compute-to-bandwidth ratio makes Refined (64-row BF16 MMA tiles) fastest for Q16×K16.

## Authors & Credibility

The authors are from the National University of Singapore, with Wenqi Jiang as corresponding author (wenqi.jiang@nus.edu.sg). The group works at the intersection of AI systems and computer architecture: Wenqi Jiang has prior published work on hardware/algorithm co-design for sparse attention (SMDiv / Sparse Diffusion at MICRO'25, CriticPrune on LLM critic-based profiling), and the paper builds directly on an established video-diffusion-efficiency literature, citing the sparsifiers (VSA, SpargeAttn, SVG, SPADE) and video models (Wan, HunyuanVideo) whose masks it consumes. The engineering evidence is substantial and internally consistent: an 18K-line Python + 19K-line C++/CUDA implementation, four GPU generations, a 2,315-mask paired-case benchmark with cross-validated regime partitioning, numerical validation of every profiled plan against a reference output, and honest separation of request-, kernel-, and model-level speedups. The systems methodology (regret analysis, CIs in ablations, profiling/eval split) is above the bar for GPU-systems papers. No artifact or code release is mentioned in the paper, which is the main credibility gap for reproducibility.

## Critical Assessment

- **Novelty is real but scoped.** The mapping taxonomy (Direct/Coarsened/Refined) is a clean formalization of practices that kernel engineers do ad hoc, and the regime-table approach is a sensible transplant of autotuning cache ideas (the paper itself notes plan-rankings-by-regime vs mask-specific caching as a key difference). It is a strong systems-engineering contribution rather than a new algorithm — the two-layer plan abstraction and the profile-guided lookup over 2,315 real masks are, to the authors' and this reader's knowledge, new for dynamic video BSA.
- **The 33.73× FlexAttention number is baseline-flattered.** FlexAttention's complete-request latency includes cold-start compilation and launcher overhead, which the paper itself measures at 12.52× the Direct baseline for exhaustive planning; a large share of the headline spread comes from that cold-path weakness, not from Tessera's kernels being 30× faster (kernel-only GM vs FlexAttention is 1.70–6.38×). The honest comparison set is FlashInfer warm (1.85–5.11× request, 1.12–1.94× kernel per GPU) and flex-block-attn.
- **End-to-end evidence is thin.** Model-level evaluation covers exactly two settings (720p Wan2.1 + SPADE, 720p HunyuanVideo-1.5 sparse-distilled), both on H100 only, both with B_Q=B_KV=64. There is no multi-GPU or multi-resolution end-to-end run, and no measurement of visual quality (FVD/VBench) — presumably unchanged since E(M) is preserved, but the paper never shows a quality metric to back that claim beyond the Algorithm-1 numerical validation of kernel outputs.
- **Generalization is asserted, not tested.** The regime tables are compiled from 40k cases drawn from the same four video models as the evaluation (only the file/chunk split differs), so there is no out-of-distribution experiment with a new sparsifier, block geometry, or architecture; new GPUs or mask distributions require a fresh offline profiling pass, and the paper does not quantify profiling or table-compilation cost for a practitioner adopting it.
- **Small tail risk from selection.** P99 regret reaches 1.04–1.17, i.e., the worst 1% of selections can be up to ~17% slower than the best plan on some platform; acceptable, but for latency-SLO serving the tail, not the geomean, matters and is only lightly discussed.
- **Reproducibility gap.** Despite ~37K lines of implementation, no code, plan-table artifact, or mask-corpus release URL appears in the paper; reproducing the 2,315-mask corpus (Wan2.1/2.2 and HunyuanVideo masks) and per-GPU catalogs independently would be a significant undertaking.
- **Scope limits.** NVIDIA-only, BF16-only workloads, and baselines restricted to three BSA executors — no comparison with dense FlashAttention-style tile-skipping kernels beyond FlashInfer's planning, and no mention of AMD or other accelerators.

## Strengths

- Clean, reusable abstraction: separating mask semantics (E(M)) from execution (tiles, task organization) is the right fix for a real problem — sparsifier-chosen block sizes and GPU tile shapes genuinely conflict (FlexAttention forces divisibility; BSA/flex-block-attn fix tile shapes at compile time).
- Unusually thorough empirical design: 2,315 real masks from production video models, four GPU generations, paired per-case measurement, three latency definitions (request/kernel/model), regret with P95/P99, and CIs on the key ablation.
- Two-orders-of-magnitude dispatch reduction (19.25 µs vs 12.16 ms) directly addresses the cold-request pathology of planning-based systems, with a simple ranked-lookup mechanism and a base-plan fallback that guarantees progress.
- Honest accounting: the paper separately reports kernel-only vs full-loop gains and explicitly states the diffusion-loop speedup is only 1.22–2.08× because non-attention compute dominates — no conflation of attention wins with wall-clock wins.
- The mapping co-variation findings (mask geometry × GPU architecture determine the winner) are independently useful to anyone writing sparse attention kernels.

## Limitations

- End-to-end validation restricted to two 720p model settings on a single H100; diffusion-loop speedups (1.22–2.08×) are far below the attention-kernel headline (2.95–6.79×), so the practical wall-clock benefit is bounded by Amdahl's law in current vDiTs.
- Per-architecture offline profiling and table compilation are required; adaptation to new GPUs, new sparsifiers, or shifted mask distributions demands re-profiling, and its cost is not reported.
- Regime lookup depends on scalar mask statistics matching pre-defined bucket boundaries (min 32 cases/leaf); behavior for masks outside the profiled families is untested and only covered by the base-plan fallback, which forfeits the tuning gains.
- P99 selection regret up to 1.17 leaves a nontrivial tail; NVIDIA/BF16 only; no quality (FVD/VBench) evaluation; no public artifact release despite the 37K-LOC implementation.

## Relevance

这篇论文与用户的兴趣高度相关：它属于 cs.AR 体系结构方向，同时直接服务于视频扩散模型（cs.CV/cs.LG）的高效推理——把稀疏化器（VSA、SpargeAttn、SPADE）产出的动态块稀疏掩码高效映射到 GPU 执行，是当前视频生成降本的关键系统环节。对关注"注意力稀疏化 + GPU 内核/运行时优化"的研究者而言，文中"逻辑掩码与物理执行解耦 + 剖析引导的 regime 选择"的抽象和 2,315 个真实掩码上的映射共变分析都很有参考价值。

## Questions for Further Exploration

- How does Tessera behave on mask distributions well outside the profiled corpus (e.g., a new sparsifier with irregular or token-learned block boundaries)? Does the base-plan fallback degrade gracefully or fall off a cliff?
- What is the actual end-to-end quality story: does preserving E(M) bit-for-bit translate to unchanged FVD/VBench across the four denoising configurations, and can the freed compute budget be traded for more sparsity?
- Can the offline profiling/table-compilation cost be amortized or updated incrementally (e.g., bandit-style online re-ranking) as mask distributions drift during serving?
- Would the two-layer plan abstraction port to other accelerators (AMD MI300, TPUs) or to multi-GPU sequence-parallel video inference, where dispatch overhead and plan portability matter even more?
- The diffusion loop only gains 1.22–2.08× — can Tessera be composed with non-attention optimizations (caching, step distillation, FP8/FP4 quantization) and does the optimal sparsity level shift once attention is no longer the bottleneck?
