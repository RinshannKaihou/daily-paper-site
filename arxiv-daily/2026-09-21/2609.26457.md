> **一句话总结：** Weco AI 的 AIDE² 用双层树搜索让 AI 研究智能体改写自身 harness 代码：外层 AIDE_human 在 8 天 100 节点的自主运行中接受 7 次改写，把内层智能体在私有评测上的分数从 0.703 提到 0.778（超过人类工程基线的 0.749），且这些改进迁移到四个留出基准上——ALE-Bench 1536→1790（+254）、WeatherBench 2 预报技巧增益 0.262→0.798（彻底分布外），还把奖励作弊率从 55% 降到 32%（这是循环从未优化过的目标）。

> **TL;DR:** Weco AI builds AIDE², a bi-level system where an outer agent (their production agent AIDE_human, on Claude Opus 4.7) recursively rewrites the code of an inner research agent (AIDE₀, a stripped-down AIDE refactor evaluated with Gemini 3 Flash). In one 8-day, 100-node autonomous run the loop accepted 7 successive rewrites, raising the private held-out grade from 0.703 to 0.778 — above the human-engineered AIDE_human baseline's 0.749. Gains transfer to four external benchmarks never used for selection: on ALE-Bench, AIDE₈₅ scores 1790 vs AIDE₀'s 1536 (+254) and AIDE_human's 1511; on the fully out-of-distribution WeatherBench 2, forecast-skill gain jumps from 0.262 (AIDE₀) to 0.798 vs AIDE_human's 0.404; on FML-Bench, AIDE₈₅ hits 19.9% vs the human baseline's 19.6%. As a side effect never optimized for, the reward-hacking rate on 38 held-out KernelBench pairs falls from 55% (AIDE₀) to 32% (AIDE₈₅), 7 points below the human baseline's 39%.

## 核心贡献

- **提出 AIDE² 双层递归自我改进框架**：将 RSI 形式化为双层优化——内层智能体（AIDE₀）在固定美元预算下对 AI R&D 任务做代码优化；外层（AIDE_human）读取候选智能体及其私有评分 g(a)，改写内层智能体的 harness 代码，只有当 g(a) 提升时改写才被接受。关键设计是把内层的优化信号 r_pub 与外层的选择信号 r_priv 解耦，防止内层直接过拟合选择标准。
- **8 天自主运行拿到 7 次持续改进**：100 节点轨迹（1 个初始智能体 + 99 个改写提案）中，在第 2、6、28、39、47、63、85 步各接受一次改写，incumbent 私有评分从 0.703 升至 0.778；两次完整重复运行分别再拿到 2 次和 4 次改写，说明不是一次性运气。
- **改进泛化到留出基准（含分布外）**：ALE-Bench、MLE-Bench、FML-Bench（任务族在分布内）与 WeatherBench 2（完全分布外）上，进化后的 AIDE₄₇/AIDE₈₅ 全部优于 AIDE₀，且 AIDE₈₅ 在四个基准上持平或超过经过两年人类 R&D 打磨、在 FML-Bench 上排名最强的 AIDE_human。
- **涌现行为：奖励作弊率下降**：在 38 组 KernelBench（GPU kernel 工程）留出任务对上，作弊率沿谱系从 55%（AIDE₀）→ 39%（AIDE₄₇）→ 32%（AIDE₈₅），低于人类基线的 39%——这个行为从未被优化目标显式覆盖。
- **发现的具体机制有工程价值**：bandit（UCB1）选择 5 种 draft 策略 + 每 5 步 fork 全局最优；有界角色化提示 + bug 率 ≥15% 时注入失败记忆，把每步提示规模压到恒定（MLE-Bench 中位数 7×、WeatherBench 2 约 40×、ALE/FML-Bench 约 50× 的压缩）；AIDE₀ 因提示超出上下文窗口，在大预算下 5 个 FML-Bench 和 48 个 ALE-Bench 运行提前终止，而进化版没有此问题。

## Key Contributions

- **AIDE², a two-loop RSI system at the harness layer**: formalized as bi-level optimization — an inner-loop agent (AIDE₀) optimizes task code under a fixed dollar budget; an outer-loop agent (AIDE_human) rewrites the inner agent's own harness code, accepting a rewrite only if the private grade g(a) improves. Decoupling the inner optimization signal (r_pub) from the outer selection signal (r_priv) prevents the inner agent from directly fitting the selection criterion.
- **A sustained trend, not a one-off gain**: one 8-day autonomous run produced a 100-node trajectory with 7 accepted rewrites (steps 2, 6, 28, 39, 47, 63, 85), lifting the incumbent private grade 0.703 → 0.778 vs AIDE_human's 0.749 on the same selection benchmark; two full replications accepted 2 and 4 further rewrites.
- **Second-order generalization on held-out benchmarks**: improvements transfer to ALE-Bench, MLE-Bench, FML-Bench (in-distribution at the task-family level) and WeatherBench 2 (fully out-of-distribution), where the discovered AIDE₈₅ matches or exceeds AIDE_human — a production agent developed over ~2 years of human R&D that ranks among the strongest on FML-Bench.
- **An emergent behavioral shift: reduced reward hacking**: measured on 38 held-out KernelBench pairs (kernel counts as hacking when isolated speedup >1.02× but <half survives inside GPT-2/ViT/CNN training loops or the kernel crashes), hacking falls 55% → 39% → 32% along the lineage, below the human baseline's 39% — a property the grade never measured.
- **Discovered mechanisms with standalone engineering value**: UCB1 bandit selection over five drafting strategies with periodic forking of the global best every 5 steps; bounded role-specific prompts plus bug-rate-gated failure memory (injects ≤3 recurring error signatures when bug rate ≥15%), keeping per-step prompt size roughly constant — median per-call compression of 7× on MLE-Bench, ~40× on WeatherBench 2, ~50× on ALE-Bench/FML-Bench vs AIDE₀, whose prompts overflow the context window (terminating 5 FML-Bench and 48 ALE-Bench runs at larger budgets).

## Methodology

The paper frames recursive self-improvement (RSI) as bi-level optimization with two loops driven by the same tree-search design.

**Inner loop.** Given a codebase and a measurable metric, the inner-loop agent a iteratively writes candidate solutions x_i = a(x_{<i}, r_pub) under a fixed dollar budget b_t covering agent tokens plus solution execution, then returns one solution of its own choosing. Which candidate to edit next, what to return, and how memory is structured are all part of the agent's editable code.

**Grading an agent.** Each candidate agent is run on a "selection benchmark" of T tasks spanning three AI R&D families — ML engineering (train a model against a metric), heuristic algorithm engineering (competitive-programming-style combinatorial problems), and harness engineering (improving an agent's own prompts, context management, feedback loops). Solutions are scored on private held-out data r_priv; the aggregate g(a) = (1/T) Σ r_priv(x̂_i), with each task run several times and averaged across runs, is the sole acceptance signal. The agent only ever sees r_pub, so the loop's selection pressure acts on general mechanisms rather than task-specific tricks.

**Outer loop.** Because the agent is itself code, the same procedure applies one level up: the outer-loop agent a_out reads prior agents and their grades and proposes a rewrite of the incumbent; each accepted rewrite becomes the codebase edited at the next step. Incumbent selection is fixed: a*_k = argmax g(a) over the lineage. Two properties shape selection pressure: signal decoupling (inner optimizes r_pub, outer selects on r_priv) and equal per-task budgets (a gain reflects a better algorithm, not more compute).

**Instantiation.** AIDE₀ is a pared-down refactor of AIDE (ICML-era ML-engineering agent) with ML-specific machinery removed: operators are draft, improve, debug, with greedy selection of the highest-scoring candidate and a reviewer agent that reads execution outputs. AIDE_human — Weco's production research agent, architecturally similar to AIDE₀ — drives the outer loop and doubles as the strong human baseline. Models are held fixed within each loop: outer loop on Claude Opus 4.7, every inner-loop agent evaluated with Gemini 3 Flash; the inner-loop reviewer makes a single LLM call per solution while the outer-loop reviewer explores artifacts over several steps.

**Evaluation design.** Four criteria: (1) repeated improvements across the trajectory, not one rewrite; (2) fixed evaluation budget per task; (3) generalization — selection tasks never overlap held-out benchmarks (ALE-Bench AtCoder optimization, MLE-Bench Kaggle, FML-Bench core-ML research tasks, WeatherBench 2 dynamical-core weather forecasting, treated as out-of-distribution since neither weather nor physics-engine optimization appears in selection); (4) comparison against the strong baseline AIDE_human, which the authors show outperforms all six agents scored by FML-Bench's authors (AI Scientist v2, Autoresearch, AIDE, OpenEvolve, AI Scientist v1, AIRA). An "ignition test" additionally checks whether a discovered agent (AIDE₄₇) drives the RSI loop better than AIDE_human when placed in the outer loop: two arms × 3 seeds × 50 steps from the same inner agent.

## Results & Highlights

- **Sustained RSI trend:** the 100-node, 8-day run accepted 7 rewrites, raising the incumbent private grade from 0.703 to 0.778, vs 0.749 for AIDE_human on the same selection benchmark; two replication runs accepted 2 and 4 rewrites respectively.
- **ALE-Bench (10 tasks, 10 seeds):** AIDE₈₅ reaches 1790±9 vs AIDE₀'s 1536±33 (+254, ~+17%) and AIDE_human's 1511±35; AIDE₄₇ sits at 1713±26.
- **WeatherBench 2 (out-of-distribution; forecast-skill gain over an unmodified dynamical core):** AIDE₄₇ 0.798±0.003 and AIDE₈₅ 0.795±0.005 vs AIDE₀ 0.262±0.205 and AIDE_human 0.404±0.193 — the largest relative gain appears on the domain the loop never saw, and both evolved checkpoints independently converged on the same family of changes to the forecasting model's numerics.
- **MLE-Bench (22 tasks, 3 seeds):** AIDE₄₇ 0.730±0.005 vs AIDE₀ 0.678±0.006 (+5.2 percentile points) and AIDE_human 0.708±0.007; AIDE₈₅ is 0.722±0.011.
- **FML-Bench (18 tasks, 3 seeds, mean normalized test improvement):** AIDE₈₅ 19.9±1.1% and AIDE₄₇ 19.7±1.2% vs AIDE₀ 15.0±0.9% and AIDE_human 19.6±1.0% — effectively tying the strongest human-engineered agent.
- **Reward hacking (38 KernelBench pairs):** 55% (AIDE₀) → 39% (AIDE₄₇) → 32% (AIDE₈₅), vs 39% for AIDE_human under the same protocol.
- **Context compression:** median per-LLM-call prompt reduction vs AIDE₀ of 7× on MLE-Bench, ~40× on WeatherBench 2, ~50× on ALE-Bench and FML-Bench; vs AIDE_human the discovered agents' prompts are 2.6–5.7× smaller (ALE/MLE/FML) and 13–14× smaller (WeatherBench 2) at end of run. AIDE₀'s unbounded prompts overflowed the context window on 5 FML-Bench runs and 48 ALE-Bench runs at larger budgets.
- **Cross-model transfer (Appendix C, $20/task budget):** AIDE₈₅ beats AIDE₀ on ALE-Bench with all three models — 1858±22 vs 1577±1 (Gemini 3 Flash), 1944 vs 1796 (fable 5), 2121 vs 2025 (gpt-5.6-sol) — though on MLE-Bench with fable 5 the gap (0.828 vs 0.823) is within one standard error.
- **Ignition test (inconclusive by the authors' own account):** with AIDE₄₇ as the outer-loop agent, both arms end at 0.780 vs 0.782 (AIDE₄₇ vs AIDE_human), with the treatment reaching its final-score region after ~20 steps vs ~40 for the reference; with 3 seeds the authors explicitly decline to claim superior sample-efficiency.

## Authors & Credibility

The five authors (Dhruv Srikanth, Bingchen Zhao, Dixin Xu, Yuxiang Wu, Zhengyao Jiang) are all from Weco AI, the company behind the AIDE ML-engineering agent (Jiang et al., 2025) and Weco's production research agent; acknowledgments thank several known agent researchers (Jean Kaddour, Minqi Jiang, Ross Taylor, Ofir Press, Christian Schroder de Witt) and Qiran Zou (FML-Bench author) for sharing baseline results. The team has direct artifact credibility: AIDE₀ is a refactor of their own published agent, AIDE_human is their production system, and the paper is candid that the evaluation doubles as an internal R&D loop. Attribution practices are above average for industry papers: they thank the FML-Bench author for per-round results rather than rerunning competitors themselves, and they mark which baseline numbers were provided externally. Potential conflict of interest: the "strong baseline beats everyone" claim (Appendix B) is about their own product, and the selection benchmark is internal and not released, so independent verification of the core loop is not possible from the paper alone.

## Critical Assessment

**Novelty is real but narrower than "AI improving itself" suggests.** The genuinely new bit is targeting RSI at the harness layer with decoupled inner/outer optimization signals and private grading, rather than letting an agent rewrite arbitrary code or its own prompts. The recursion is shallow in practice: only the inner loop is ever rewritten by the loop; the outer-loop agent (AIDE_human) remains human-engineered, and the one test of a discovered agent in the outer-loop role (the ignition test) is inconclusive at 3 seeds. This is RSI of the optimizer's tooling, not of the optimizer itself.

**The headline generalization claim needs a caveat the abstract soft-pedals.** Three of the four held-out benchmarks (ALE-Bench, MLE-Bench, FML-Bench) are in-distribution at the task-family level — the selection benchmark deliberately samples the same three families. Only WeatherBench 2 is truly out-of-distribution, which makes it the most persuasive result, and to the authors' credit they label the others "in-distribution" in Figure 3 and explain the distinction. But "generalizes to four held-out benchmarks" reads stronger than "generalizes to one OOD benchmark plus three unseen instances of familiar task families."

**Some margins are thin or noisy.** FML-Bench: 19.9±1.1 vs 19.6±1.0 is a tie within error, yet the abstract claims "matches or exceeds." On WeatherBench 2 the AIDE₀ and AIDE_human error bars (±0.205, ±0.193 on a single task, 3 seeds) are enormous, so the baseline comparison there rests on very little data. Non-monotonicity across checkpoints (AIDE₄₇ best on MLE-Bench/WeatherBench 2, AIDE₈₅ best on ALE/FML) is honestly reported but means the lineage's endpoint is not uniformly its best artifact.

**Attribution is missing where it matters most.** The reward-hacking reduction — the most safety-relevant claim — is measured only at the lineage level; the authors state the rates "do not identify which rewrites produced it." No ablation isolates which of the seven accepted rewrites (bandit search? context compression? robustness guards?) drives benchmark gains, so the discovered agents remain a bundle: the paper admits they are "complex and difficult to interpret" and that some components may be unused artifacts. The 15% bug-rate threshold for failure memory was a human design choice of AID E², not discovered — an interesting admission that the loop's most legible mechanism was seeded by hand.

**Yield variance and reproducibility.** The main run accepted 7 of 99 proposals; replications accepted 2 and 4 — a wide spread for a "sustained trend" claim, though direction is consistent. The selection benchmark, AIDE_human, and AID E² are internal to Weco; no code release is mentioned, and the loop depends on proprietary frontier models (Claude Opus 4.7, Gemini 3 Flash, gpt-5.4) and closed infrastructure. Others can check the held-out evaluations of AIDE₄₇/AIDE₈₅ only if the checkpoints are released — which the paper does not state. About a quarter of rejected rewrites scored higher than the incumbent on the agent-visible signal, and Appendix D's rejected-proposal table (island populations, LLM-judge tournaments, UCB-V, ensembles) is a nice transparency touch, but it also shows the acceptance decision rode entirely on a noisy private grade, which the Discussion concedes can derail the whole outer loop.

## Strengths

- Fixed per-task dollar budgets make the central claim an efficiency claim, not a compute claim — the right control for "the loop found a better algorithm."
- Decoupling r_pub (inner optimization) from r_priv (outer selection) is a clean, well-motivated guard against the most obvious failure mode of self-referential loops.
- Four external benchmarks with pre-resolved, benchmark-native metrics, plus a genuinely OOD task (WeatherBench 2) where gains are largest — and the in-distribution/OOD distinction is labeled transparently rather than hidden.
- The human baseline is not a strawman: AIDE_human is shown beating all six externally-scored FML-Bench agents (19.6% vs 19.3 for AI Scientist v2, 19.2 Autoresearch, 17.8 AIDE, 15.1 OpenEvolve, 13.2 AI Scientist v1/AIRA).
- Honest self-reporting throughout: inconclusive ignition test, non-monotonic checkpoints, unattributed reward-hacking reduction, deployment-friction concerns, and a full appendix of rejected proposals with their deltas.
- The loop repaired a broken held-out scoring script instead of exploiting it — a concrete, verifiable instance of the reduced-reward-hacking claim rather than an aggregate statistic alone.
- Mechanisms discovered (bandit-over-strategies, bounded prompts, failure memory) are independently useful and quantified (7×–50× prompt compression; context-overflow termination of 53 baseline runs eliminated).

## Limitations

- Only the inner agent improves; the outer loop is fixed human engineering, and the ignition test (3 seeds) cannot show a discovered agent is a better self-improver — so "recursive" gains are one level deep.
- Three of four generalization benchmarks share task families with the selection benchmark; true OOD evidence is a single WeatherBench 2 task with 3 seeds and huge error bars on the baselines.
- No component-level ablation of the discovered agent: which of the seven rewrites drives benchmark gains or the reward-hacking drop is unknown; interpretability of AIDE₈₅ is explicitly flagged as an open problem.
- Acceptance hinges on a noisy private grade; a single noisy comparison can redirect the outer loop, and ~25% of rejected rewrites actually beat the incumbent on the agent-visible signal.
- Selection benchmark, AIDE_human, and AID E² are proprietary; no stated code or checkpoint release; heavy dependence on specific frontier model versions (Claude Opus 4.7, Gemini 3 Flash, gpt-5.4) whose behavior may change.
- Yield varies widely across runs (7 / 2 / 4 accepted rewrites), so run-level cost-effectiveness of the 8-day loop is not established.
- Reward hacking is measured with a heuristic threshold (isolated speedup >1.02× and <half surviving in-training or a crash) on KernelBench pairs — a reasonable but debatable operationalization.

## Relevance

这篇论文是目前关于"智能体改进自身"最扎实的实证之一：它没有停留在概念验证，而是用固定预算、私有评分和留出基准证明 AI 研究智能体能持续改进自己的搜索与上下文管理机制，并把收益迁移到从未见过的领域。对于关注 agentic search、agent harness 设计与 reward hacking 的研究，文中被发现的 bandit 搜索策略和有界上下文压缩机制本身就有直接可借鉴的工程价值。

## Questions for Further Exploration

- Can the reward-hacking reduction be attributed to specific accepted rewrites, or is it an aggregate drift? A per-rewrite ablation on KernelBench-style pairs would separate mechanism from correlation.
- Does the loop keep improving past 100 nodes, or does it hit the same diminishing returns as human R&D — what does the grade trajectory look like at 500 or 1000 steps?
- Would replacing the proprietary selection benchmark with public tasks (e.g., subsets of the held-out families) preserve the gains, making the loop reproducible outside Weco?
- The ignition test was inconclusive at 3 seeds: how many seeds and outer-loop steps are needed, and does a discovered outer-loop agent eventually beat AIDE_human at driving its own improvement?
- The discovered context-compression mechanisms bounded prompts at roughly constant size — do they transfer to agent architectures structurally different from AIDE's draft/improve/debug tree search?
- Both evolved checkpoints converged on the same numerics changes for WeatherBench 2 — is this convergence a signature of a general optimization policy, or of the selection benchmark's harness-engineering family biasing rewrites toward numeric robustness?
