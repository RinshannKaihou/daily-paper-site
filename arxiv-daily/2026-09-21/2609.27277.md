> **一句话总结：** 作者诊断出工具型时间序列智能体的两大失效模式——"人机工具错配"（装上 21 个 TimeART 专家工具反而让三个骨干在异常检测任务上掉 5.8–8.8 分）和"隐性伤害"（一轮 Self-Refine 改动 147 个答案、修好 49 个却弄坏 56 个原本正确的答案，而总分几乎不动），据此提出 TimeEvo：把智能体自身诊断出的失败聚类为"能力缺口"，为每个缺口规划"测量契约"并合成只返回数值证据的确定性 Python 工具，候选工具库必须先过 32 样本的逐工具画像、再过带 95% 置信下界的配对准入门（δ_lb = δ − 1.96·√(max(h+m,1))/n > 0），否则回滚；从空工具库出发，TimeEvo 在 10 个时间序列 QA 任务 × 3 个骨干（GPT-5.6-luna/terra、GPT-5.4-mini）的**全部 30 个单元**上均为正增益，均值提升 +7.21 至 +8.79 分，且在便宜模型（mini）上长出的库装进更强模型（Claude-opus-5 / sonnet-5 / GPT-5.6-sol）仍带来 +8.27 至 +10.65 的十任务均值增益。

> **TL;DR:** On ten time-series QA benchmarks (TemporalBench T1–T4, TimeSeriesExam, Merill, Time-MQA Anomaly/Classification, MMTS Match, TSAAQA-DT) across three frozen backbones, TimeEvo turns an agent's own diagnosed failures into evidence-only Python tools and admits a candidate library only if a paired validation gate with a 95% lower confidence bound proves it repairs more than it breaks. It beats an empty library on all 30 task-backbone cells (mean +8.79 on GPT-5.6-luna, +8.73 on GPT-5.4-mini, +7.21 on GPT-5.6-terra), whereas the 21 expert-curated TimeART tools average −1.49 on luna and drop anomaly accuracy 5.8–8.8 points on every backbone, and one Self-Refine pass fixes 49 answers but breaks 56 for a net score move under one point. A library evolved on the cheapest model (GPT-5.4-mini's peer tier; specifically grown on GPT-5.6-luna) transfers to Claude-opus-5 with a +26.25-point anomaly gain versus +14.69 on luna itself — the tools, not model-specific habits, carry the task knowledge.

## 核心贡献

- **识别并量化两大失效现象**：
  - *人机工具错配（Human–Agent Tool Misalignment）*：给冻结智能体装上 21 个 TimeART 专家策划工具，在三个骨干上"最大收益与最大损失出现在同方向"——库里有专门的异常检测工具，但 TimeMQA Anomaly 准确率反而在所有骨干上下降 5.8–8.8 分（luna −6.2 / terra −8.8 / mini −5.8），而同家族的 T2、T4 任务却被 T3 的工具促进；结论是"工具由人预先决定、任务由问题运行时决定"的结构性错配。
  - *隐性伤害（Silent Harm）*：一轮通用 Self-Refine 在十个任务上改动 147 个答案——49 个修好、56 个原本正确的被改坏、42 个从错换成另一种错，而平均分移动不足 1 分；伤害在算术上被平均分"静默擦除"，最终分数永远无法反映这类破坏（terra 在 T4 上改动 14 个答案：修好 0 个、弄坏 11 个）。
- **TimeEvo 自进化框架**：每轮四阶段——(1) 失败驱动分析：在训练折上重放当前工具库，把错误聚类为失败桶（工具触发的错 = 工具误用/缺陷，无工具触达的错 = 能力缺口）；(2) 规划：局部规划器为每个桶产出"测量契约"（所需测量、签名、成功判据、scope），动作限 CREATE/REFINE/RESCOPE/RETIRE，全局规划器合并重复契约；(3) 候选合成：最多 3 次尝试合成**只返回数值证据**的确定性 Python 工具（禁 while 循环、零参数签名、沙箱执行；可用 Chronos-2 作为裸预测原语；决策边界需携带仅在训练行上拟合的浅层校准树，内部均衡准确率 ≥0.55 才准入）；(4) 双层验证。
- **双层验证 + 配对准入门（核心机制）**：第一层逐工具画像——在桶内 32 个留出错误上，候选必须至少修复 1 个可归因错误、真实执行且有迹可查，修复率 <0.40 早停；第二层整库配对门——候选库与现有库在同一验证折上逐题配对比较，净修复率 δ=(h−m)/n 的 95% 置信下界 δ_lb = δ − 1.96·√(max(h+m,1))/n 必须严格为正（小折上的 3-胜-0 败有补充规则：净修复 ≥max{3, ⌈0.02n⌉} 且绝对伤害率 ≤0.10）；失败库做一次"单轮归因剪枝"后复验，仍不行则整体回滚——被拒轮次不改变任何东西。
- **冻结残差推理（Frozen Residual Inference）**：部署时冻结智能体先作答，工具仅在 scope 匹配的问题上介入（每题至多审阅 3 个入围工具），工具出错或未触发则保留原答案——修复可能的之外，绝不伤害范围外问题。
- **转移实验**：luna 上长出的库装进 Claude-opus-5、Claude-sonnet-5、GPT-5.6-sol，30 个任务结果仅 1 个为负——证明缺失的是"正确的工具"而非"模型特定习惯"，且工具生长不必发生在昂贵模型上。

## Key Contributions

- **Two quantified failure phenomena**: (1) *Human–Agent Tool Misalignment* — installing the 21 expert-curated TimeART tools drops TimeMQA Anomaly accuracy by 5.8–8.8 points under all three backbones despite containing a dedicated anomaly detector, while the largest gains and losses co-occur in the same task family; (2) *Silent Harm* — one Self-Refine pass changes 147 answers across ten tasks (49 fixed, 56 previously-correct broken, 42 wrong-to-different-wrong) while the pooled score moves by less than one point, so a single average hides the damage.
- **TimeEvo**, a self-evolving agent that clusters its own diagnosed failures into capability-gap buckets, plans a *measurement contract* per bucket (CREATE/REFINE/RESCOPE/RETIRE), synthesizes evidence-only deterministic Python tools (sandboxed, no while loops, train-only calibrated decision trees at balanced accuracy ≥0.55), and admits the candidate library only through two validation levels: a 32-sample per-tool profiler, then a whole-library paired admission gate requiring the 95% lower bound δ_lb = δ − 1.96·√(max(h+m,1))/n > 0, with one-shot attribution pruning and rollback on failure.
- **Frozen Residual Inference**: the frozen agent answers first; admitted tools review at most three shortlisted, in-scope questions and may only keep or replace the answer — out-of-scope questions are structurally protected.
- **Empirical validation**: uniform positive gains across all 30 task-backbone cells on ten benchmarks, plus a transfer study showing a library grown on a cheap model yields further gains (+10.50/+10.65/+8.27 ten-task means) when installed into three stronger models, with only 1 of 30 transferred results negative.

## Methodology

**Problem setup.** Each question is a triple (q, S, O): a natural-language question, one/two primary series plus named covariates, and a closed option set. An agent is a frozen LLM L with an executable tool library L; accuracy is checked against the observed input alone. Updates are judged by paired counts helped(D) = {x : v(x)=0, v'(x)=1} and harmed(D) = {x : v(x)=1, v'(x)=0} on the same questions.

**Round pipeline (frozen protocol, one evolution round per reported run).**
1. *Failure-driven analysis*: replay the current library on the training split; errors F_r = {x ∈ D_train : v_{r-1}(x)=0} are partitioned by whether a tool fired, then an LLM clusters each partition (≤8 categories, ≤150 sampled errors, two retries); buckets >64 errors are split, buckets <2 errors are dropped as unassigned. Tool-fired errors are clustered separately from no-tool errors so "defective tool" never merges with "missing capability".
2. *Two-level planning*: a local planner per bucket returns a measurement contract (required measurement, signature, success criterion, scope, anti-scope, matcher); a global planner merges duplicate measurements, narrows overlapping scopes, and mechanically rejects contracts after two failed merges. Planning is committed to *measurements*, not answers.
3. *Candidate synthesis*: up to three sequential attempts per contract with structured feedback; the synthesizer must emit a deterministic, zero-argument Python function (no while loops) in a sandbox; tools returning verdicts, option strings, or dataset-specific constants are discarded as non-evidence. A tool may call raw Chronos-2 as a forecasting primitive; decision-boundary tools may carry *train-only calibration* — a shallow decision tree fit on training rows, AST-compiled into the source, accepted only at internal balanced accuracy ≥0.55 (≥16 samples per class, 80/20 fingerprint-grouped split). Thresholds are *measured* on training rows, not invented by the agent.
4. *Per-tool profiler (level 1)*: the first 32 held-out errors of the tool's bucket; survival requires ≥1 attributable repair (tool bound, executed, visible in the trace), and early-stops if the repair rate falls below 0.40.
5. *Paired admission gate (level 2)*: current vs candidate library answer the full validation split, compared on identical questions. Strict pass: h>0 and δ_lb > 0 (Z=1.96); a single-round supplementary path admits δ>0 with net repair ≥ max{3, ⌈0.02n⌉} and absolute harm rate ≤0.10; execution error rate >2% invalidates the measurement. On failure, one bounded prune removes clearly harmful updates and their dependents, re-verified in exactly one more full paired run; otherwise rollback. Test split is answered once per round for reporting only — a rolled-back library may receive one diagnostic test run that participates in no selection.
6. *Deployment*: accepted libraries first re-validate their declared scopes against their own tools, then pass the gate a final time; at inference the frozen agent answers first and tools review only in-scope questions (≤3 shortlisted), keeping or replacing the answer.

**Experiments.** Ten tasks from six public sources with frozen train/val/test splits grouped at the series level (e.g., Time-MQA Anomaly restructured from 37,000 source rows into a two-way normal-vs-anomaly choice task; Merill downsampled from 5,779/1,000/1,036 to 240/120/240). Three backbones (GPT-5.6-luna, GPT-5.6-terra, GPT-5.4-mini) with all four LLM roles on the same backbone. Baselines: fixed Chronos-2 tool, 21 TimeART expert tools, Self-Refine, five-sample self-consistency voting, and few-shot ICL (k=4). Every reported number is a within-run paired delta; Appendix C freezes every hyperparameter before the first run.

## Results & Highlights

- **Uniform improvement over an empty library**: TimeEvo improves every task on every backbone — all 30 cells positive. Ten-task means: 63.8 vs 56.6 base on luna (+8.79 mean paired delta), 63.5 vs 55.8 on mini (+8.73), 63.9 vs 56.6 on terra (+7.21). Per-task luna deltas range from +2.50 (Merill) to +26.25 (Time-MQA Classification).
- **Expert tools can hurt, self-revision is a wash**: the 21 TimeART tools average 55.11 on luna (−1.49 vs base) and drop Anomaly by −6.2/−8.8/−5.8 points on luna/terra/mini respectively; a single Self-Refine pass averages −1.62 on luna, changing 147 answers (49 fixed, 56 broken) for a net move under one point. Voting costs 5× budget for means of +0.79/−0.21/1.64; few-shot ICL (k=4) is negative on Merill and TSAAQA-DT under all three backbones despite reading the same training split the tool teams use.
- **Ablations isolate the gate**: without the admission gate, the mini run on Anomaly deploys a library ending −1.25 below its own base where the full method ends +16.25 above; without train-only calibration the same cell scores 0.00 (rejected round, −16.25 vs full); removing structured scopes costs 1.00–9.25 points across cells. A pre-installed Chronos-2 root captures only 3.04 of the 18.50 points an empty root reaches on Anomaly/mini; the 21 TimeART root ends 8.25–21.50 below the empty root in all four ablation cells.
- **Transfer to stronger models**: installing the luna-evolved library lifts ten-task means by +10.50 (Claude-opus-5), +10.65 (Claude-sonnet-5), and +8.27 (GPT-5.6-sol), with only 1/30 negative; on Anomaly the Claude models gain +26.25/+26.50 vs +14.69 on luna itself — deeper models exploit the same evidence better.
- **Gate behavior and honest errors**: every strict-region acceptance (δ_lb>0) lands test-positive; the borderline band contains exactly one false positive (a T1 library at validation −1.27, the only accepted library that is test-negative), and the rejected region contains one conservative false negative (a Merill library whose report-only diagnostic scored +5.00). A three-round run (terra, Anomaly) admits tools in R1 (+18.50), usage guidance in R2 (+2.75), and rejects R3 outright.
- **Process funnel over 30 runs**: 4,910 training-split errors → 4,898 bucketed (99.76%) → 203 buckets → 194 contracts → 483 synthesis attempts → 227 pass the profiler (47.0%) → 113 deployed artifacts (49.78%); final outcomes: 22 direct passes, 7 passes after one-shot pruning (17 artifacts removed), 1 rollback. 25 of 29 deployed libraries are pure tools; the other four admit a textual usage patch, because the gate arbitrates by measured repair/harm rather than artifact type.

## Critical Assessment

- **The diagnosis is the strongest part; the "evolution" is one-shot.** Every reported headline number uses a *single* evolution round ("Every number we report is a within-run paired delta"; the root run is "a single round with at most three synthesis attempts per work group"). The only multi-round evidence is one three-round case study (terra/Anomaly, Fig. 5c) where R2/R3 add +2.75 and get rejected. Calling this "self-evolution" oversells what is, in the reported results, failure-driven one-shot tool synthesis with a safety gate — genuine multi-round dynamics, library decay, or error cascades are untested at scale.
- **Benchmarks were heavily re-engineered by the authors, in a direction that favors the method.** Time-MQA's 37,000 rows were reduced to one representative row per unique series and converted to explicit option sets with machine-readable series "so tools can compute on it"; Merill was downsampled 24×; MMTS Match was converted from free-form output to four-way choice. All ten tasks are closed-set multiple choice — precisely the regime where a deterministic measurement tool flips an answer. No open-ended forecasting/reporting task is evaluated, so the claim of fixing "time series agents" writ large rests entirely on choice-format QA. Test sets are also small (126–400 questions), so per-task deltas of 1–2 points are within noise, even if pooled means (+7 to +9) are more robust.
- **Baselines skip the most relevant competitors.** The comparisons are fixed tools, Self-Refine, voting, and few-shot ICL — but the related work itself names SkillOpt, CoEvoSkills, Agent-K, and EvoLveR as skill/library-growing frameworks that "further test learned skills before deployment." None is run head-to-head, so the paired admission gate is never benchmarked against another verification mechanism, only against no verification at all. Similarly, the Human–Agent Tool Misalignment claim is built on exactly *one* external tool library (TimeART) plus one Chronos-2 wrapper; misalignment could be a property of that particular library rather than a general phenomenon.
- **The gate's margin depends on small-sample statistics.** The single-round supplementary path (net repair ≥ max{3, ⌈0.02n⌉}, harm ≤10%) admits libraries on as few as three net repairs; the calibration plot honestly shows one false positive (validation −1.27 → test-negative on T1) and one false negative. With validation splits of a few hundred questions, δ_lb's 95% guarantee is only as good as the val/test distribution match — which the authors assert (series-level splits) but cannot prove for future distributions.
- **Train-only calibration is a quiet form of task-specific fitting.** Decision thresholds are fit on training rows at balanced accuracy ≥0.55 — a low bar — and calibrated tools are barred from calling the forecasting primitive, but the tree still encodes dataset-specific boundaries. The paper is transparent about this, and the w/o-calibration ablation shows why it is needed (Anomaly/mini goes from +16.25 to 0.00/rejected), yet it means a deployed "evidence-only" tool is not purely evidence.
- **No cost accounting.** 483 synthesis attempts and full training-split replays per run are described only relatively ("most cost occurs at executable synthesis"); no token/clock/dollar figures are given, which matters for judging practicality of running the loop per task-backbone pair.

## Strengths

- The Silent Harm analysis is a genuinely useful, quantified diagnosis (147 changed / 49 fixed / 56 broken / net <1 point) that explains *why* score-only self-imputation loops are untrustworthy, and it motivates the design rather than serving as decoration.
- The paired admission gate with a confidence lower bound, one-shot attribution pruning, and rollback is a clean, reproducible safety mechanism — and the paper reports its own errors (one false accept, one false reject) instead of hiding them.
- Strict evaluation hygiene: frozen protocol table fixed before the first run, report-only test access, within-run paired deltas, series-level leakage control on splits.
- The transfer result is practically valuable: libraries grown on a cheap model keep working (and grow larger gains) on stronger models, meaning evolution need not run on the expensive tier.
- 30/30 positive cells plus component ablations on four cells give the headline claim unusually broad support for an agent paper.

## Limitations

- Only one evolution round is evaluated in the main results; multi-round behavior, library growth limits, and staleness are explored in a single case study.
- All ten tasks are closed-option multiple-choice QA on author-restructured public datasets; results are not comparable to original benchmark leaderboards, and open-ended analysis tasks are absent.
- No head-to-head comparison with other self-evolving skill/tool frameworks (SkillOpt, CoEvoSkills, EvoLveR, Agent-K) despite being directly related; the misalignment phenomenon is demonstrated on a single expert tool library.
- Validation-split statistics are small; the gate's single-round path can pass on three net repairs, and the observed val→test mismatch cases, while few, show the margin is not airtight.
- Evolution cost (synthesis attempts, training-split replays) is never quantified in absolute terms.
- Gains concentrate in tasks with clear measurement gaps (Anomaly +19.75, Classification +26.25, Match +18.75 under luna); T3 (+7.43) shows 31 synthesis attempts buying six artifacts for a modest return — failure diversity does not translate linearly into payoff.

## Relevance

这篇文章正切合你对 LLM 智能体与自进化/工具学习方向的关注：它把"时间序列 QA + 工具调用"作为试验场，核心贡献其实是一个领域无关的机制——用配对统计准入门为智能体自我改进提供可审计的质量闸门，并以严谨的失败诊断（Silent Harm）解释了为何朴素的 Self-Refine 不可信。其"冻结骨干 + 外置工具库 + 显式验证门"的路线对设计可靠的领域智能体（金融时序、异常检测等）有直接参考价值。

## Questions for Further Exploration

- Does the paired admission gate retain its val→test fidelity over *multiple* evolution rounds as the library grows and the training split's residual errors become harder (the paper's own R2 added only +2.75 before R3 was rejected)?
- How does TimeEvo compare head-to-head with SkillOpt / CoEvoSkills / EvoLveR-style verification mechanisms on the same benchmarks — is the specific statistical gate the differentiator, or simply *having* any held-out verification?
- Would the gains survive on open-ended tasks (free-form forecasting, report generation) where a single deterministic measurement cannot flip an answer, or is the method fundamentally tied to choice-format QA?
- The Human–Agent Tool Misalignment was shown with one library (TimeART, 21 tools) — does it replicate across independently curated tool sets, and can misalignment be predicted *before* deployment cheaply enough to replace trial-and-error?
- Can the train-only calibration trees be replaced by conformal or distribution-free thresholds to keep tools evidence-only while preserving the observed +16.25-point contribution on Anomaly/mini?
