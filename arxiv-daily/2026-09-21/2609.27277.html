Why this matters

The gate, not the tools, is the contribution: an auditable statistical mechanism for trusting agent self-improvement — reusable for reliable domain agents such as financial time-series and anomaly detection.

Critical edge

Every headline number comes from a single evolution round — “self-evolution” oversells what is, in the reported results, one-shot tool synthesis behind a safety gate.

How one evolution round works

Six frozen stages; a rejected round changes nothing.

  1. 01Diagnose. Replay the library on the training split; cluster errors into buckets. Tool-fired and no-tool errors cluster separately — a “defective tool” never merges with a “missing capability”.
  2. 02Plan. A local planner writes a measurement contract per bucket (measurement, signature, success criterion, scope); a global planner merges duplicates. Planning commits to measurements, not answers.
  3. 03Synthesize. ≤3 attempts per contract: deterministic, zero-argument Python in a sandbox. Verdicts and option strings are rejected; Chronos-2 is allowed as a raw primitive; decision boundaries come from train-only calibrated trees (balanced acc ≥ 0.55).
  4. 04Profile each tool. First 32 held-out errors of its bucket; needs ≥ 1 attributable repair; early-stops below a 0.40 repair rate.
  5. 05Gate the library. Current vs candidate answer the same validation questions; admit only if the 95% lower bound is strictly positive — else one attribution prune, one re-run, then rollback. Test split touched once, report-only.
  6. 06Deploy, frozen. The frozen agent answers first; admitted tools review ≤ 3 shortlisted in-scope questions and may only keep or replace the answer. Out-of-scope questions are structurally protected.

Where it holds

  • Silent Harm is quantified and load-bearing — 147 answers changed, 49 fixed, 56 broken, net < 1 point — explaining why score-only self-improvement loops can’t be trusted.
  • The paired admission gate with pruning and rollback is a clean, reproducible safety mechanism — and the paper reports its own errors instead of hiding them.
  • Strict hygiene: protocol frozen before run 1, report-only test access, within-run paired deltas, series-level leakage control.
  • Transfer is practically valuable: libraries grown on a cheap model gain more on stronger hosts — evolution needn’t run on the expensive tier.
  • 30/30 positive cells plus four-cell ablations give the headline unusual breadth for an agent paper.

Where it creaks

  • Only one evolution round in the main results; multi-round dynamics appear in a single case study (R2 +2.75, R3 rejected).
  • All ten tasks are closed-set MCQ on author-restructured datasets — no open-ended forecasting; not comparable to original leaderboards; test sets of 126–400 put 1–2-pt deltas within noise.
  • No head-to-head vs SkillOpt / CoEvoSkills / EvoLveR / Agent-K; the misalignment claim rests on a single expert library (TimeART).
  • The gate’s margin rests on small validation splits — it can admit on three net repairs, and one false positive was observed.
  • Train-only calibration trees quietly encode dataset-specific boundaries — “evidence-only” tools are not purely evidence.
  • No cost accounting for 483 synthesis attempts and full training-split replays.

Questions for further exploration

  1. Does the gate keep its val→test fidelity over multiple rounds as residual errors harden?
  2. Head-to-head vs other verification mechanisms — is the statistical gate the differentiator, or just having any held-out verification?
  3. Do gains survive open-ended tasks where a single deterministic measurement can’t flip an answer?
  4. Does Human–Agent Tool Misalignment replicate across independently curated libraries — and can it be predicted before deployment?
  5. Could conformal, distribution-free thresholds replace calibration trees while keeping the +16.25-point contribution?
