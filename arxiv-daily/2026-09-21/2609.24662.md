# DUMA-Bench: A Dual-Control Multi-Agent Benchmark for Evaluating LLM Agent Security

> **一句话总结：** 该工作在 τ²-bench 的双控（dual-control）交互框架上叠加 8 类对抗性安全域（35 个可执行多轮任务、65 条确定性状态断言 + 37 条 LLM 评审断言），评测 OpenAI/Anthropic/DeepSeek/Qwen/Z.ai 五个家族的 14 个模型后发现：从被动用户（solo）切换到双控交互使整体攻击成功率（ASR）从 26.9% 升至 41.1%（+14.2 个百分点，Fisher 精确检验显著），其中营销钓鱼域从 2.2% 暴涨至 61.5%，GPT-5-nano 的 ASR 从 31.4% 升至 79.3%，而基于检索投毒的 mail_rag_phishing 域基本不变（61.0%→57.9%）——即 agent 安全并非模型固有属性，而是模型-用户-环境交互的涌现结果。

> **TL;DR:** DUMA-Bench extends τ²-bench's dual-control interaction protocol with an adversarial security layer: 8 vulnerability domains, 35 executable multi-turn tasks, 65 deterministic state assertions plus 37 LLM-judged communication assertions. Evaluating 14 models from 5 families (OpenAI, Anthropic, DeepSeek, Qwen, Z.ai) under n=5 repeated trials, moving from solo (passive-user) to dual-control evaluation raises aggregate ASR from 26.9% to 41.1% (+14.2 pp, Fisher-exact significant; pass^1 drops 0.731→0.589). The effect is highly domain-dependent: mktg_phishing explodes from 0.022 to 0.615 ASR while retrieval-driven mail_rag_phishing stays flat (0.610→0.579), and the GPT-5 family collapses (GPT-5-nano 0.314→0.793) while Claude Sonnet 4.5 is unchanged (0.090→0.086). Static, passive-user security benchmarks systematically underestimate agent risk — but note the headline number is a whole-regime effect, not an isolated causal factor.

## 核心贡献

- **提出 DUMA-Bench**：首个将"双控交互"（agent 与用户模拟器都能影响共享环境状态）与对抗性安全场景结合的 LLM agent 安全基准，覆盖 8 个漏洞域、35 个可执行多轮任务（非 prompt-only 测试项），共 65 条确定性状态断言 + 37 条自然语言通信断言。
- **统一评测协议**：以 ASR（攻击成功率）为主要指标，辅以 τ-bench 的 pass^k 无偏估计刻画重复交互下的可靠性；每个配置跑 n=5 次，用 Fisher 精确检验与 Wilson 区间做统计推断；主研究共 14 模型 × 8 域 × 2 评测 regime = 每 regime 1,960 次试验。
- **核心实证发现**：双控交互使总体 ASR 从 26.9%（solo）升至 41.1%（dual-control，+14.2pp），pass^1 从 0.731 降至 0.589；且该效应"重新分布"了漏洞——交互驱动域（mktg_phishing +0.593、collab +0.206、crm_leak +0.193）急剧恶化，而检索驱动域（mail_rag_phishing −0.031）几乎不变。
- **模型层面反直觉结论**：能力≠鲁棒性。GPT-5 家族在双控下退化最严重（GPT-5-nano +0.479、GPT-5-mini +0.450、GPT-5 +0.390），而 Claude Sonnet 4.5 反而略微改善（−0.004）；用户模拟器温度（0.0/0.5/1.0）对总体结果无显著影响。
- **方法论贡献**：以"可重放的确定性状态断言"为主要评分机制（避免 LLM 评审偏差），奖励为各断言类型的严格合取（连积），杜绝"拒绝了未授权操作却在回复文本中泄露敏感数据"的部分合规得 0 分；代码、种子与轨迹全部开源（github.com/ai-security-lab-itmo/duma-benchmark）。

## Key Contributions

- **DUMA-Bench**: the first benchmark combining dual-control interaction (both the agent and an LLM user simulator can mutate shared environment state) with adversarial security scenarios — 8 vulnerability domains, 35 executable multi-turn tasks (not prompt-only items), 65 deterministic state assertions and 37 natural-language communication assertions.
- **Unified evaluation protocol**: ASR as the primary metric plus the pass^k unbiased estimator for reliability under repeated interaction; n=5 runs per configuration; Fisher exact tests and Wilson intervals; 1,960 trials per regime across 14 models × 8 domains × 2 regimes.
- **Headline empirical finding**: dual-control interaction increases aggregate ASR from 26.9% (solo) to 41.1% (+14.2 pp; pass^1 0.731→0.589), and redistributes rather than uniformly inflates vulnerability: interaction-driven domains surge (mktg_phishing +0.593, collab +0.206, crm_leak +0.193) while the retrieval-driven mail_rag_phishing domain is flat (−0.031).
- **Counter-intuitive model-level result**: capability does not transfer to security robustness — the GPT-5 family degrades most under dual control (GPT-5-nano +0.479 ASR) while Claude Sonnet 4.5 is unchanged (−0.004); user-simulator temperature (0.0/0.5/1.0) has no significant aggregate effect.
- **Methodological care**: scoring is primarily deterministic replay-based state assertions with a strict conjunctive reward (product over assertion types), preventing partial compliance (e.g., refusing an unauthorized refund while leaking protected data still scores 0); code, seeds and trajectories are released publicly.

## Methodology

**Evaluation framework.** DUMA-Bench adopts the dual-control (Dec-POMDP-style) structure of τ²-bench: the environment is a partially observable shared state S; the agent observes S-derived observations and acts via tool invocations and communication acts; the user (an LLM simulator) also receives S-derived observations, chats over multiple turns, and can invoke user-scoped tools. Both parties' actions condition the environment transition, so the trajectory is jointly shaped. Two regimes are compared: **solo** (predetermined static request, no user participant — approximating classic prompt-only benchmarks) and **dual-control** (an LLM user simulator with persona/goal/task instructions participates in the loop).

**Security domains.** Eight domains target common LLM-agent vulnerability classes: `mail_rag_phishing` (RAG poisoning via a poisoned email disguised as an SOP, 7 tasks), `collab` (cross-agent manipulation via malicious collaborator notes, 6), `output_handling` (unsafe downstream output: XSS/SQL/redirect payloads, 3), `crm_leak` (trusted-data oversharing of restricted CRM fields, 4), `infra_loadshed` (infrastructure/quota abuse, 5), `mktg_phishing` (coercing a marketing agent into phishing-style campaigns, 3), `auth_spoof_support` (identity spoofing for refunds/email changes, 3), and `tool_shadow_poison` (shadow tools mimicking signed tools, 4). Each task is an executable multi-turn scenario with a security policy, mutable environment state, domain tools, adversarial artifacts, and user-side instructions.

**Assertion design.** Two complementary assertion types: (1) *state assertions* — deterministic functions replayed over the post-execution environment (tool calls reconstructed from the trajectory), immune to LLM-judge bias (e.g., `assert_no_refund_without_verification` fails if any refund was verified=false); (2) *communication assertions* — natural-language expectations over the assistant's textual behavior, graded by a GPT-4o judge at temperature 0.0 returning per-outcome JSON verdicts. Each task specifies a reward basis B (subset of assertion types); the per-type score is 1 only if every assertion of that type succeeds, and the task reward is the product r = ∏_{i∈B} r_i ∈ {0,1} — a strict conjunction that prevents partial compliance (an agent that correctly refuses an action but leaks protected data in its reply still gets 0).

**Metrics.** ASR = successful attacks / total attempts, where an attack succeeds if the agent violates the task's security assertions. Reliability under repeated trials uses the τ-bench pass^k unbiased estimator pass~_i^k = C(c_i,k)/C(n_i,k), the estimated probability that all k independent trials succeed.

**Protocol.** Each configuration is (model, domain, regime, T_user); n=5 independent runs each; 14 models × 8 domains × 2 regimes = 1,960 trials per regime (3,920 total). Agent decoding is deterministic; stochasticity comes from the user simulator, which uses a fixed GPT-4o-mini backbone for all targets (comparability) with temperature varied over {0.0, 0.5, 1.0} for the sensitivity study (on a reduced 9-model cross-vendor subset, 1,575 trials per temperature). Significance via Fisher exact test; Wilson intervals for proportions.

**Diagnostics.** Appendix E analyzes trajectory lengths (median dual-control run: 16 messages vs 8 in solo; 90th percentile 63 vs —), termination causes (94.5% of dual runs ended via simulator stop condition; 2.8% tool-execution errors; 2.7% step-cap), failure composition (81.9% of non-passing dual runs failed environment/state assertions, 18.1% failed communication assertions), and a manual audit of 60 stratified communication-assertion decisions (out of 1,775 judge decisions over 894 runs) finding 56/60 agreement with the GPT-4o judge.

## Results & Highlights

- **Headline regime gap (Table 1)**: across 1,960 trials per regime (14 models × 8 domains × n=5), aggregate ASR rises from **26.9% under solo (passive-user) evaluation to 41.1% under dual-control interaction (+14.2 pp)**, statistically significant under Fisher's exact test; equivalently pass^1 drops from 0.731 to 0.589. The authors' conclusion: passive-user benchmarks systematically overestimate agent robustness.
- **The effect redistributes vulnerability across domains (Table 2)**: the largest degradation is `mktg_phishing`, where ASR jumps from **0.022 (solo) to 0.615 (dual-control, +0.593)**; large increases also in `collab` (0.043→0.249, +0.206), `crm_leak` (0.056→0.249, +0.193), and `tool_shadow_poison` (0.111→0.264, +0.153). In contrast, retrieval-based `mail_rag_phishing` barely moves (**0.610→0.579, −0.031**), suggesting retrieval-pipeline vulnerabilities are regime-independent while persuasion/impersonation attacks depend on interaction dynamics.
- **Model family divergence (Table 4)**: capability does not predict robustness. The GPT-5 family shows the largest shifts — **GPT-5-nano ASR 0.314→0.793 (+0.479), GPT-5-mini 0.279→0.729 (+0.450), GPT-5 0.257→0.647 (+0.390)** — whereas **Claude Sonnet 4.5 is flat (0.090→0.086, −0.004)** and GPT-4o moves moderately (0.314→0.393, +0.079). Appendix E cautions these GPT-5 numbers were obtained with reasoning enabled at its minimum setting (could not be disabled via API), so they are a family-level diagnostic, not a causal claim.
- **Robustness to user-behavior variability (Table 3, RQ2)**: on the 9-model reduced subset, varying simulator temperature T_user ∈ {0.0, 0.5, 1.0} yields pass^1 of 0.716/0.719/0.730 and ASR of 0.284/0.281/0.270 — Fisher tests show **no significant differences** between temperature pairs (a localized exception: crm_leak pass^1 varies ~15 pp between T=0.0 and T=1.0). Benchmark conclusions are stable under moderate user-behavior stochasticity.
- **Reliability under repeated interaction (Appendix C, Table 8)**: under dual control the aggregate pass^k decays from **0.722 at pass^1 to 0.596 at pass^5**, with domain-dependent decay — `auth_spoof_support`, `collab`, and `tool_shadow_poison` stay relatively reliable at high k, while `infra_loadshed`, `mktg_phishing`, and `output_handling` drop steeply, i.e., many successes are trajectory-specific rather than consistent behavior.
- **Failure-mode composition (Appendix E)**: among non-passing dual-control runs, **81.9% fail deterministic environment/state assertions vs 18.1% failing natural-language communication assertions**; communication failures concentrate in `output_handling` and `tool_shadow_poison`. The manual audit of the LLM judge agreed with 56/60 sampled decisions, with disagreements concentrated in borderline `output_handling` cases where the judge applied expected wording literally.

The four authors are affiliated with the **AI Security Lab at ITMO University (Saint Petersburg)** and **Hive Trace Lab** (one author also independent). The work was carried out within ITMO's AI Talent Hub with infrastructure support from industry partners (HiveTrace, Vselem.ru CEOs acknowledged). This is an industry-lab/university benchmark paper rather than an academic-group output; the team's focus is agent security tooling. Credibility signals are good: the benchmark extends the peer-reviewed τ²-bench/τ-bench line of work, the evaluation protocol is statistically careful (repeated trials, Fisher exact tests, pass^k), the judge is manually audited, and the full repository (task definitions, prompts, seeds, evaluation scripts, qualitative trajectories) is released at https://github.com/ai-security-lab-itmo/duma-benchmark. No prior top-tier publications by this author group are cited in the paper itself, so track record is thin but the artifact-centric transparency partially compensates.

## Critical Assessment

- **The headline +14.2 pp is a confounded regime-level effect, and the authors admit it.** Solo→dual-control changes many things at once: multi-turn structure, presence of a user simulator, tool-mediated state mutation. The Discussion explicitly states this is "not a factorial ablation" and the aggregate shift "should be interpreted as a property of the full interaction regime" — honest, but it means the abstract's framing ("dual-control interaction increases attack success rate") cannot be decomposed into which component causes the increase. A factorial design (user-influence-only, multi-turn-only, mutable-state-only arms) is deferred to future work.
- **`mktg_phishing`'s +0.593 rests on only 3 tasks**, and its adversarial pressure (KPI urgency, campaign-manager framing) is delivered substantially through the operator/user channel — so that domain partially measures the GPT-4o-mini simulator's persuasiveness against the target model, not just the model's intrinsic vulnerability. With 3 tasks × 5 runs × 14 models, per-domain ASR estimates are high-variance, and no per-domain confidence intervals appear in the main tables despite Wilson intervals being advertised in the protocol.
- **The GPT-5-family collapse is confounded by reasoning mode.** GPT-5 models were evaluated with reasoning enabled at its minimum available setting because it could not be fully disabled through the API. The authors properly downgrade the finding to a "model-family diagnostic" (Table 9 is qualitative), but this means the paper's most striking numbers (0.314→0.793) may partly be a reasoning-mode × interaction artifact, unresolved by any controlled ablation.
- **No defenses are actually evaluated.** Appendix F proposes candidate mitigations (retrieval provenance tagging, policy-gated tool allowlists, mandatory verification gates, output sanitization, Llama Guard-style independent guardrails) as prose only. The Conclusion's claim that DUMA-Bench provides "a practical framework for evaluating defenses under realistic agent workflows" overstates what is demonstrated — no guardrail's ASR reduction (or utility cost on τ²-bench-style task success) is measured anywhere in the paper.
- **Judge coverage is a minority but real weakness**: 37 of ~102 assertions are LLM-judged, and the authors' own audit found the GPT-4o judge failed borderline `output_handling` trajectories that were actually safe (it required the exact object name, e.g., raw-SQL constraints, to be echoed). 56/60 agreement is decent, but the failure direction (false positives on safe behavior) inflates ASR in exactly the domains where communication assertions dominate.
- **Fixed simulator (GPT-4o-mini) for all targets** aids comparability but leaves open whether a stronger or adaptive adversary-simulator would shift both the level and the model ranking; simulator-model sensitivity is not studied (only temperature is).

## Strengths

- **Deterministic-first scoring**: replay-based state assertions as the primary reward mechanism avoid the LLM-judge bias that plagues most agent-safety evaluations, and the strict conjunctive reward elegantly kills partial-compliance loopholes (refuse-but-leak scores 0).
- **The sharpest insight is distributional, not aggregate**: dual-control does not merely raise ASR — it changes *which* vulnerabilities are visible (interaction-driven domains explode while the retrieval-poisoning domain is regime-invariant, 0.610→0.579). This domain-level dissociation is more actionable than the headline number.
- **Statistical hygiene unusual for benchmark papers**: n=5 repeated trials with the pass^k unbiased estimator, Fisher exact tests, temperature-sensitivity control, and an explicit manual audit of the LLM judge (56/60 agreement, disagreement mode characterized).
- **Breadth with comparability**: 14 models across 5 vendor families (frontier to lightweight), identical task definitions and tool interfaces, one fixed simulator backbone — the cross-family GPT-5-vs-Claude divergence could not have been observed under a single-model setup.
- **Transparency and honesty**: public code/seeds/trajectories, a Limitations section that names its own confounds (size, simulator realism, judge variance, factor isolation), and a Discussion that pre-empts over-reading the regime gap as causal.

## Limitations

- **Scale**: 35 executable tasks across 8 unevenly sized domains (3–7 tasks each); per-domain and especially per-model-per-domain estimates are noisy, and the benchmark cannot exhaust the space of agent-security risks (acknowledged by the authors).
- **Simulator realism**: user behavior is generated by a fixed GPT-4o-mini simulator, which may not capture the diversity and unpredictability of real human users; results are conditioned on one simulator persona design.
- **Evaluator variance**: 37 communication assertions rely on the GPT-4o judge; the audit shows borderline safe trajectories can be scored as failures (false positives in `output_handling`).
- **No factor isolation**: the solo-vs-dual gap aggregates multi-turn structure, user influence, and mutable state; no factorial ablation is provided.
- **Reasoning-mode confound** for the GPT-5 family (reasoning could not be disabled), limiting the strongest per-model claims.
- **No defense evaluation**: mitigations are discussed qualitatively; measuring guardrail effectiveness under dual control is left as future work. Main-text results are pass^1 only; the stricter pass^k analysis is appendix-only.

## Relevance

该工作与用户对 LLM agent 安全与评测基准的兴趣高度契合：它定量证明了"被动用户下的静态安全评测会系统性低估 agent 风险"（ASR 26.9%→41.1%），并给出可复用的确定性断言 + 双控交互评测框架，对评估多智能体/工具调用系统（RAG、客服、内部运维 agent）的暴露面有直接参考价值；其"漏洞随交互 regime 重新分布"的结论对防御设计（工具白名单、验证门控、输出消毒）的优先级排序也有指导意义。

## Questions for Further Exploration

- Under a full factorial design (multi-turn × user influence × mutable state), which component contributes most to the +14.2 pp ASR increase, and does the domain-level redistribution pattern survive?
- Would replacing the fixed GPT-4o-mini operator with an adaptive LLM red-team simulator raise ASR further, and would the GPT-5-vs-Claude robustness ranking change?
- Do the proposed mitigations (retrieval provenance tagging, policy-gated tool allowlists, verification gates, Llama Guard-style output guardrails) actually reduce dual-control ASR, and at what task-utility cost on the underlying τ²-bench workflows?
- Is the GPT-5 family's collapse robust when reasoning mode is a controlled variable (fully on/off), or is it an artifact of minimum-reasoning evaluation?
- How do LLM-simulator findings transfer to human-in-the-loop studies with real users applying pressure and impersonation in the same domains?
