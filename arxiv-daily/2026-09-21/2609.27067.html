Why this matters

A blueprint for trustworthy agent self-improvement in any domain with checkable rewards — code, formal verification, chip design: memory that cannot be poisoned by the model grading itself.

ReasoningBank / Voyager 一脉的 agent memory 思想在硬件设计领域的落地实例，对一切带可验证奖励信号的 agent 域都有直接借鉴价值。

Critical edge

The advertised efficiency gains sit inside confidence intervals that cross zero — the only statistically significant paired change is output tokens rising +55%.

Also unresolved: no external memory baselines (every comparison is memory-off) · the 20/20 vs 18/20 transfer headline is a single evaluation, n=20, no variance · an appendix Pass@k table favors memory-off and goes unexplained.

Methodology

Agent⇄ ChipMEM adapterskills · Bayesian advice · audit log⇄ EDA tools→ Harness Vdeterministic PASS/FAIL — never an LLM judge
  • Procedural memory — key–value skill library keyed by task embedding; top-2 skills retrieved at cosine ≥ 0.6 and injected at session start. An LLM distiller writes name / summary / DO / AVOID — stored only on harness PASS (synthesis + formal equivalence + positive audited PPA; hidden simulation / coverage / mutation checks for CVDP). Evolving and frozen read-only modes.
  • Statistical memory — every tool call logs (error class, prompt-error type, retry bucket ≤ 3). A 3-level hierarchical Beta-Bernoulli posterior (prior strength K = 8) predicts retry success; when Pretry < 0.20, a recovery predictor ranks historically successful fixes for an advisory-only LLM planner.
  • Setup — GPT-5.5 on Cadence ChipStack 2.0: RTL-OPT (38 designs), RTLRewriter-Bench (54 short + 5 long), CVDP (20 train + 20 held-out), custom 20-design PPA suite; Qwen3.8-27B on OpenTitan (10 IPs × 5). Yosys+ABC / OpenROAD PPA measurement. 540 controlled executions.

Strengths

  • Poison-proof gate — a skill is stored only with a tool-checked PASS artifact; memory cannot be inflated by LLM self-assessment, and Bayesian guidance stays advisory-only.
  • Consistent across settings — positive results in four distinct EDA regimes plus a cross-domain SWE-bench Pro pilot, all under matched model, prompt, tool, and budget.
  • Unusually honest reporting — negative rows kept in print: CID012 −2 pp, aon_timer 2→1 passes, CIs crossing zero, one table favoring the baseline.
  • Transfer-centric protocol — the frozen-library study tests unseen tasks rather than benchmark replay, with the full skill inventory exposed.
  • Ablation payoff — combined memory raises passes (5 vs 3) and gain (10.36% vs 8.41%) while halving wall time on matched runs.

Limitations

  • No external baselines — only its own memory-off; superiority over ReasoningBank / Trace2Skill-style methods rests on argument, not measurement.
  • Small-n evidence — ablation on 5 designs; the 20/20 vs 18/20 transfer is one evaluation per setting with no variance reported.
  • Hand-set constants — K = 8, τ = 0.20, top-2 retrieval at cosine 0.6 fixed, no sensitivity sweeps.
  • Proprietary stack — headline numbers need GPT-5.5 on Cadence ChipStack 2.0 and internal flows; the released repo cannot fully re-create them.
  • Mixed cost story — output tokens +55%, paired efficiency deltas not significant; public benchmarks measured first-pass area only (no power/timing in the loop).
  • Unreconciled appendix — a Pass@k table on the 20-design suite favors memory-off at every k, never explained against Table 3c’s 8/20 → 10/20 claim.

Questions for further exploration

  • Head-to-head vs ReasoningBank or Trace2Skill on the same RTL-OPT / RTLRewriter harness, not just memory-off?
  • Which individual stored skills drive the +20 pp CID013 checker gain — and do any retrieved skills actively hurt?
  • At matched token budgets, does the Bayesian retry model beat a simple rule-based retry cap, given K = 8 and τ = 0.20 were never swept?
  • Does embedding-based top-2 retrieval scale across many design families, or do skill collisions degrade transfer?
  • Would the 20/20 vs 18/20 frozen-transfer result hold under repeated sampling with confidence intervals?
