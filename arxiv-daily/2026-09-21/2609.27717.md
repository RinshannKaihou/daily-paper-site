# SkillGym: Internalizing Large-Scale Human Skills into LLMs for Real-World Problem Solving

> **一句话总结：** 提出 SkillGym 框架，把 OpenClaw 等社区沉淀的人工撰写 agent 技能文档，经"类目模板实例化 + Docker 可执行环境 + 代码校验器 + 有/无技能对照测试"转化为 2,756 个可验证训练环境（12 大类、63 子类），并用 4 种 harness×teacher 组合采样出 8,364 条平均 49 次工具调用、6.3 万 token 的成功长程轨迹；对 Qwen3.5-35B-A3B 做 SFT 后，Claude Code 下 GDPval-AA v2 Elo 提升 199（974→1173）、Terminal-Bench 2.1 提升 19.10 个百分点（39.33→58.43%）、SkillsBench v1.1 技能辅助成绩达 51.47%（+28.13），超过 Claude Sonnet 4.6（47.2%）等公开模型，且在无推理时技能辅助下仍反超基座（26.81% vs 12.13%），说明流程性能力已"内化"进权重。

> **TL;DR:** SkillGym converts ~2,756 human-written agent skills (from the OpenClaw registry, 12 categories / 63 sub-categories) into executable, Docker-packaged training environments with code-based outcome verifiers and a contrastive with-skill/without-skill acceptance test, then samples 8,364 verified long-horizon trajectories (avg 49.0 tool calls, 63.4k tokens) from 4 harness–teacher pairs (Claude Code/Codex × DeepSeek V4 Pro/GLM-5.2/GPT-5.4/Nex-N2-Pro). Supervised fine-tuning of Qwen3.5-35B-A3B on these trajectories yields SkillGym-Agent, which gains +199 Elo on GDPval-AA v2 (974→1173), +19.10 pp on Terminal-Bench 2.1 (39.33→58.43%), and +28.13 pp on skill-assisted SkillsBench v1.1 (23.34→51.47%), beating the strongest comparable-scale baseline Agents-AI by +189 Elo and reaching 51.47% vs Claude Sonnet 4.6's 47.2% on SkillsBench; crucially, without inference-time skills it still outperforms its skill-assisted base (26.81% vs 12.13%), evidence that external skill workflows were internalized as procedural competence.

## 核心贡献

- **技能→任务（skill-to-task）框架**：首次系统性地把人工编写的 agent 技能文档（工作流说明、脚本、执行约束）转化为可执行、可校验的训练环境，而非推理时检索的外部知识；技能卡片（Skill Card）与人工设计的子类目模板分离，模板规定任务蓝图、输入资产、文件结构、运行时依赖与校验器规格，技能决定具体流程。
- **两级验收 + 对照式技能依赖检验**：环境先过可行性检查与"校验器 + 参考解"的可执行性验收（含防作弊检查：输入篡改、答案拷贝、绕过要求、伪造输出）；再让参考 agent 分别**带技能**与**不带技能**执行，仅当 (1,0)（带技能成功、不带技能失败）才标为 Skill-Dep.，否则降级为 Verifier-Passed 后备环境，失败则丢弃——共 2,756 个环境，其中 1,081（39.2%）为 Skill-Dep.。
- **多 harness 多教师轨迹语料**：Claude Code×DeepSeek V4 Pro / GLM-5.2 与 Codex×GPT-5.4 / Nex-N2-Pro 共 4 种组合，在 48,152 次采样中获得 8,364 条成功轨迹（成功率 17.4%），覆盖 62/63 个子类；每条平均 49.0 次工具调用、63.4k token、35.2 步，峰值达 350 次调用、342.9k token、318 步；36.8% 的轨迹显式调用了目标技能。
- **内化有效性的实证**：SFT 后的 35B 模型在 GDPval-AA v2、Terminal-Bench 2.1、SkillsBench v1.1（含/不含技能）四个设定下全面超越基座，且无技能辅助时也反超"带技能的基座"， Teacher/harness 混合消融显示：同 harness 内混教师提升终端与技能类任务（如 GPT-5.4+Nex-N2-Pro 使 SkillsBench +5.91 pp），但会牺牲 GDPval（-98 Elo）；跨 harness 池化对 Codex 学生增益最大（Terminal-Bench +35.96 pp）。
- **资源全开源**：环境、校验器、构建管线、轨迹数据、模型权重均发布在 GitHub（ECNU-ICALK/SkillGym）与 Hugging Face（ecnu-icalk/SkillGym / SkillGym-Agent）。

## Key Contributions

- **Skill-to-task framework**: transforms human-written agent skills (descriptions, scripts, execution constraints from the OpenClaw registry) into executable, verifiable training environments — decoupling skill cards from 63 manually designed sub-category templates that specify task blueprints, input assets, runtime requirements, and checker specifications.
- **Two-level acceptance protocol**: environments must pass feasibility/execution checks with a working verifier and reference solution (with anti-shortcut checkers against input tampering, answer copying, bypassed requirements, and fabricated outputs), then a contrastive test — reference agent run with vs. without the target skill — labels a task Skill-Dep. only on a (1,0) outcome; the rest become Verifier-Passed fallbacks (1,081 Skill-Dep. = 39.2% of 2,756 accepted environments).
- **Multi-harness trajectory corpus**: 8,364 successful trajectories from 4 harness–teacher configurations (Claude Code × DeepSeek V4 Pro/GLM-5.2; Codex × GPT-5.4/Nex-N2-Pro) over 48,152 trials (17.4% success), averaging 49.0 tool calls, 63.4k logged tokens, and 35.2 steps per trajectory (maxima: 350 calls, 342.9k tokens, 318 steps), covering 62 of 63 sub-categories; failed executions are kept for failure-mode analysis.
- **Evidence of internalization**: SkillGym-Agent (SFT of Qwen3.5-35B-A3B) surpasses its skill-assisted base under both harnesses without any inference-time skills, and ablations quantify teacher-mixing effects (mixing helps terminal/skill tasks but can cost up to 98 Elo on GDPval-AA v2; cross-harness pooling benefits the Codex student most).
- **Full release**: environments, verifiers, construction pipeline, trajectory data, and trained models on GitHub and Hugging Face.

## Methodology

**A. Skill-aware template construction.** The pipeline starts from an online registry of human-written agent skills (OpenClaw, 2026), organized into 12 major categories and 63 sub-categories. High-star skills are distilled into **skill cards** K_c (descriptions, usage examples, pseudocode/scripts, execution constraints). For each sub-category, the team **manually constructs a reusable template** T_c specifying a task blueprint, input assets, file structure, runtime requirements, checker specifications, and execution constraints. Templates capture the common workflow of the sub-category so that inputs, instructions, expected outputs, and success conditions vary per skill, while the verification scaffold stays constant. Templates encode **outcome-oriented** specs (sections/length/keyword coverage for content tasks; executable tests, schema validation, final-state checks for software/data tasks) rather than judging output wording.

**B. Environment construction and validation.** Given K_c and T_c(i), each task is instantiated as E_i = (x_i, A_i, ρ_i, V_i): task instruction, input assets, Docker-packaged file structure/runtime, and a code-based outcome verifier. **Two-level acceptance**: F_i = 1 requires passing design/structure/end-to-end execution checks with a working verifier and verified reference solution. Then the reference agent runs contrastively with (r_i^+) and without (r_i^-) the target skill under a fixed reference configuration; label (1,0) → **Skill-Dep.**, other verifier-passed outcomes → **Verifier-Passed fallback**, F_i = 0 → discarded. A **failure-driven refinement loop** groups validation failures (environment errors, checker errors, difficulty mismatch, weak skill dependency) and iterates with a construction budget per task; average construction time is 4.5 h per accepted task using GPT-5.4 (research 2.6 h to documentation 6.3 h).

**C. Multi-harness trajectory sampling.** Four harness–model configurations sample rollouts: Claude Code + DeepSeek V4 Pro (1,722 successful), Claude Code + GLM-5.2 (1,769), Codex + GPT-5.4 (1,967), Codex + Nex-N2-Pro (2,906). Agents work inside the Docker environment — inspect inputs, execute actions, observe results, submit an artifact — and each trajectory is judged by the same task-specific verifier V_i, yielding outcome rewards for RL and demonstrations for SFT. Records keep final executions, task prompts, skill metadata, environment configuration, and failure reasons.

**Training & evaluation.** SkillGym-Agent is a full-parameter long-context SFT of Qwen3.5-35B-A3B (Megatron, ~swa-fit, 16 NVIDIA H200 GPUs) on the 8,364 trajectories. Evaluation: GDPval-AA v2 (Elo from blind pairwise comparisons, self-hosted on OpenSandBox via NVIDIA NeMo Gym), Terminal-Bench 2.1 (success rate, 89 tasks), SkillsBench v1.1 (87 tasks, 8 domains, three trials per task, evaluated with and without official skill packages; both via official Harbor implementations). Claude Code uses temperature 0.6 / top_p 0.95 / top_k 20; Codex uses its defaults; max_tokens 65,536 with a 262,144-token context.

## Results & Highlights

- **GDPval-AA v2 (Elo)**: SkillGym-Agent (Claude Code) reaches **1173 vs 974** for the Qwen3.5-35B-A3B base (**+199 Elo**); under Codex, 979 vs 942 (+37). Against the strongest comparable-scale baseline **Agents-AI (984)**, it leads by **+189 Elo**, and it beats MiniMax-M2.7 (1087) on all four metrics, while Claude Sonnet 4.6 sits at 1295.
- **Terminal-Bench 2.1 (success rate)**: **58.43% vs 39.33%** base under Claude Code (**+19.10 pp**); under Codex **46.07% vs 10.11%** (**+35.96 pp**, though this comparison also changes the system prompt). Vs Agents-AI (43.82%) the delta is +14.61 pp; the 35B agent nearly matches Claude Sonnet 4.6 (58.5%).
- **SkillsBench v1.1**: skill-assisted **51.47% vs 23.34%** base (**+28.13 pp**) and skill-free **26.81% vs 12.13%** (**+14.68 pp**) under Claude Code; the skill-assisted score **exceeds Claude Sonnet 4.6 (47.2%), GPT-5.4 Mini (41.4%), and DeepSeek V4 Pro Preview (50.1%)**. Under Codex: 33.02% (+27.69) and 21.08% (+20.39).
- **Internalization claim**: without inference-time skills, the trained agent (26.81% / 21.08%) still beats the *skill-assisted* base under both Claude Code (23.34%) and Codex (5.33%).
- **Teacher/harness ablations (Table 5)**: mixing teachers within a harness improves Terminal-Bench/SkillsBench (GPT-5.4+Nex-N2-Pro: +6.74/+5.91/+0.98 pp over the best single teacher) but costs GDPval (-98 and -51 Elo vs the strongest single-teacher students); two-teacher DeepSeek+GLM under Claude Code hits 57.30% TB / 47.33% / 28.41% — its skill-free 28.41% even beats All Teachers (26.81%) — while adding Codex data to it gains +12 Elo and +1.13/+4.14 pp but drops skill-free SkillsBench to 26.81%.
- **Dataset difficulty & scale**: only 8,364 of 48,152 sampled trials (17.4%) pass the verifiers; development tasks have the longest trajectories (70.1 avg tool calls, 85.1k tokens, 52.2 steps); Skill-Dep. share varies by category from 15.6% (blockchain) to 58.3% (business); 36.8% of trajectories (3,077) explicitly invoke the target skill, with configuration-level invocation rates 17.1%–57.4%.

## Authors & Credibility

The paper comes from the **ICALK lab at East China Normal University** (Shanghai), a well-established NLP group led by Liang He (corresponding author) with senior co-authors Jie Zhou, Kai Chen, Qin Chen, and Xin Li; the first four authors (Zhilong Ge, Yuting Shao, Yutao Yang, Yuxuan Cai) contributed equally. The group has adjacent prior work in this exact space — AutoSkill (skill self-evolution, arXiv:2603.01145) and SkillsBench (benchmarking agent skills, arXiv:2602.12670) — so the team has both domain expertise and a stake in the skill-learning ecosystem. All artifacts (environments, verifiers, construction code, trajectories, model weights) are publicly released on GitHub (ECNU-ICALK/SkillGym) and Hugging Face, which materially supports reproducibility. The evaluation protocol relies on established third-party harnesses (Harbor, OpenSandBox/NeMo Gym) for Terminal-Bench 2.1, SkillsBench v1.1, and GDPval-AA v2, and the appendix is unusually candid about evaluation confounds.

## Critical Assessment

- **Self-referential benchmark risk**: SkillsBench v1.1 — one of the three headline benchmarks — is authored by the same lab (Li et al., 2026, shares the ECNU ICALK team), and the strongest "comparable-scale baseline," Agents-AI, is also from the same group (Bai et al.). The model being best-in-group on a home-grown benchmark (51.47% vs Sonnet 4.6's 47.2%) is suggestive but not neutral evidence; independent adoption of SkillsBench would strengthen the claim.
- **The Codex-harness gains are confounded by a system-prompt change**: Appendix D.1 admits the Codex base uses the standard system prompt while SkillGym-Agent uses the no-appsystem prompt, so the eye-catching +35.96 pp Terminal-Bench jump under Codex "cannot be attributed solely to fine-tuning." Only the Claude Code column is a clean same-prompt comparison — fortunately it also shows large gains (+199 Elo, +19.10 pp).
- **Cross-harness public-model comparisons are apples-to-oranges**: public reference numbers for Claude Sonnet 4.6, GPT-5.4, and DeepSeek V4 Pro come from different harnesses, inference budgets, and snapshot settings (STRR/DEEPSEEK/TERMINUS/CODEX CLIs, etc.), so "exceeds reported scores for Claude Sonnet 4.6" is context, not a controlled head-to-head.
- **Skill-dependency labels are weak evidence**: the contrastive (1,0) test runs one reference configuration only; the paper itself notes this is "empirical evidence of dependence... not proof that the skill is necessary for every agent," and a task's Skill-Dep. label doesn't guarantee sampled agents solve it. There is also no ablation isolating whether gains come from skill-specific content versus generic long-horizon tool-use exposure (e.g., an SFT on difficulty-matched non-skill trajectories is missing).
- **No RL despite the RL framing**: environments ship verifiers for outcome-reward RL, but all reported results are SFT-only; RL is deferred to future work, so the "reinforcement learning with outcome-based rewards" part of the pitch is infrastructure, not results.
- **Class imbalance and SFT-on-success bias**: business+development hold 1,094 of 2,756 environments while lifestyle (22), databases (38), and blockchain (45) are thin; training uses only the 8,364 successful trajectories (17.4% pass rate), and per-configuration task coverage differs, so the teacher/harness comparisons "describe the collected records... not... a matched task set" — the authors say this themselves.
- **Single base model**: only Qwen3.5-35B-A3B is trained; generality across model families/scales is untested. No variance/std-err reporting for Elo or success rates (SkillsBench uses three trials, but spread is not shown).

## Strengths

- **Genuinely new data source**: human-written skill registries (OpenClaw-style) are an underexplored, naturally crowdsourced source of procedural workflows, and the skill-to-task conversion with per-sub-category templates is a concrete, reusable recipe.
- **Verification-first environment design**: code-based outcome checkers with explicit anti-shortcut tests (input tampering, answer copying, bypassed requirements, fabricated outputs) plus a contrastive with/without-skill acceptance run — a more principled task-acceptance protocol than most auto-generated agent environments.
- **Scale with diversity**: 2,756 environments / 8,364 verified trajectories across 12 categories, 4 harness–teacher configurations, with long-horizon statistics (avg 49 tool calls, up to 318 steps) rare in open agent-training corpora.
- **Honest reporting**: the fallback (Verifier-Passed) vs Skill-Dep. distinction is maintained throughout, failures are kept and analyzed, and the appendix spells out harness/system-prompt confounds rather than hiding them.
- **Strong, multi-facet results**: improvements appear on professional deliverable generation (GDPval), terminal execution (Terminal-Bench), and skill-based problem solving (SkillsBench), with gains persisting without inference-time skills — the correct control for an "internalization" claim.

## Limitations

- Training is SFT-only; the promised RL with outcome rewards is unvalidated in this paper.
- Skill-dependency certification rests on a single reference configuration's contrastive run, and no ablation separates skill-specific learning from generic long-horizon tool-use practice.
- Evaluation headwinds: SkillsBench and the Agents-AI baseline originate from the same lab; Codex comparisons carry a system-prompt confound; public-reference comparisons vary in harness and budget; no confidence intervals are reported.
- Category coverage is uneven (business/development dominate; lifestyle and databases are marginal), and one sub-category (culinary-arts) has an accepted task but zero successful trajectories.
- Only one base model (Qwen3.5-35B-A3B) and one scale are trained; cost is nontrivial (4.5 h average construction per accepted task with GPT-5.4, plus 63 hand-designed sub-category templates and 16 H200 GPUs for training).

## Relevance

这篇工作与你关注的 agent 能力训练方向高度相关：它给出了"把外部技能/工作流文档转化为可验证训练环境 → 通过 SFT 将流程性能力内化进模型权重"的完整开源范式，且两级验收与防作弊校验器设计可直接借鉴到自建 agent 数据管线的质量控制中。

## Questions for Further Exploration

- Would RL with the released outcome verifiers close the GDPval gap to frontier models (All-Teacher SFT reaches 1179 Elo vs Sonnet 4.6's 1295), or does SFT cap out?
- Can the +199 Elo / +28 pp gains be replicated on a different base model (e.g., a non-A3B or smaller MoE) to show the skill-internalization effect is not Qwen-specific?
- Is the improvement driven by skill-specific workflows or simply by exposure to long-horizon tool-use data? A control SFT on difficulty-matched trajectories from non-skill-derived environments would answer this.
- How do Skill-Dep. and Verifier-Passed subsets differ in training value — does the contrastively-certified 39.2% of environments contribute disproportionately?
- Does the contrastive skill-dependency label transfer across agents: do tasks certified with one reference configuration remain skill-dependent for stronger or weaker solvers?
