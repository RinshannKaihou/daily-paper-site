Why This Matters

Strips security judgment out of LLM reasoning into formally verified runtime checks — a key reference for the 2026 agent-defense landscape and its policy-generalization gap.

把安全判断从 LLM 推理中剥离为形式化验证的运行时策略检查，是理解 agent 防御格局与策略泛化难题的重要参照。

Critical Edge

0.767 → 0.100

clean utility when policies cross from AgentDojo to AgentDyn

Policies don't transfer: out-of-domain policy sets keep ASR at 0.000 but crater utility — a per-benchmark whitelist, not yet a general defense.

Methodology

Threat model — indirect prompt injection: attacker-controlled content (emails, webpages, tool output) steers the agent into proposing unauthorized tool calls. The user task, tool specs, and the enforcement layer stay trusted.

Two-phase architecture

Propose · offlineLLM drafts layered policies from tool specs + benign/attack traces
→
Verify · Z3SAT witness = concrete policy gap → rewrite; all UNSAT → freeze & deploy
→
Enforce · runtimeevery candidate call abstracted to records → deterministic allow/deny

Layered policies

  • Task-Perm — trusted task ↔ minimum required tool permissions.
  • Hard-Invariant — global red lines (e.g. no outbound actions from untrusted content).
  • Procedural-Obligation — preconditions when binding or provenance is weak.

2-D record space

L1 deterministicL2 LLM-extracted, boundedL3 boolean composition actionpermissionparameterhistorybindingexternaldomain

Formation level × semantic scope: unstructured runtime context becomes a finite, policy-checkable state — the LLM only fills categorical features, never judges security. Zero online SMT cost.

Evaluation

AgentDojo (629 security cases) + AgentDyn (560), four backends (Qwen3.6-flash, MiniMax-M2.5, DeepSeek-v4-pro, GPT-4o mini), vs Progent / DRIFT / CaMeL / ACE. Main configs: GPT-5.5 proposer, 10 refinement rounds + human review.

AgentDojo: ASR 0.000 on all four backends, clean utility ≥ 0.612; strongest baseline Progent·DeepSeek-v4-pro reaches clean 0.816 but retains ASR 0.008 — ActGov halves it. CaMeL/ACE zero-utility rows follow the native benchmark scorers (see Questions).

Strengths

  • Deterministic, low-latency enforcement — a finite-state check over abstracted records, zero LLM/SMT cost on the critical path.
  • Strongest utility–security trade-off shown: near-zero ASR at flat clean utility, where CaMeL/ACE buy security at exactly 0.000 utility.
  • Reusable formal vocabulary — the 2-D record schema and three-layer policy decomposition.
  • Honest self-reporting: quantifies out-of-domain collapse and data-scale sensitivity instead of hiding them.
  • Broad, disciplined evaluation: 2 benchmarks × 4 backends, policies frozen before test.

Limitations

  • No policy generalization — cross-benchmark deployment craters clean utility to 0.100–0.224.
  • Data-hungry pipeline: weaker policy generators halve utility (0.533 → 0.283–0.317 clean).
  • L2 records are still LLM-extracted; the error rate is unmeasured — a misread provenance label can silently flip allow/deny.
  • Headline configs use human-in-the-loop review (10 rounds); fully automated generation scores markedly lower.
  • Low no-defense ASR baselines cap demonstrable security headroom; no code release; VerGuard excluded for lack of public code.

Questions for Further Exploration

  1. Can policies generalize across tool ecosystems — learned over a tool corpus, not per-benchmark splits — instead of collapsing to 0.100–0.224 out of domain?
  2. What is the real L2 extraction error rate — and can low confidence trigger procedural obligations instead of silent allow/deny?
  3. Can adversarial policy fuzzing (auto-generated SAT counterexamples as new attack traces) replace human review, closing the 0.600 → 0.283–0.533 gap?
  4. Does enforcement compose with CaMeL-style information flow, so security never hinges on extraction fidelity?
  5. Are CaMeL/ACE's uniform 0.000 utility scores a scoring-protocol artifact or genuine design incompatibility?
