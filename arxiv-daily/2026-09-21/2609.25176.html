02Why This Matters

Voice models move from hearing-and-talking to acting; the distillation, executable-environment, and reward recipes here are directly reusable for multimodal agent post-training.

→ see Methodology

03Critical Edge

The causal claim is never tested: no ablations, no significance tests — every headline number is a release-level delta confounded by data, compute, and recipe changes at once.

→ see Limitations

How it's builtMethodology

  1. Core-Cocktail SFT — re-anchors the AudioLM to its source text LLM on million-hour-scale paired audio-text data.
  2. Multimodality OPD — a Text Teacher + frozen Audio Reference supervise tokens on student-sampled trajectories: behavior alignment, not input-feature similarity.
  3. GRPO domain experts — specialists trained for empathy, pragmatic intent, acoustic scenes.
  4. Multi-Teacher OPD — consolidates experts into one deployable AudioLM.

Agentic training

  • Executable environments: tool pool + stateful JSON database + natural-language business policy — negative constraints ("never take payment details") are first-class test targets.
  • Terminal outcomes: write / justified refusal / unsupported; invalid rollouts are resampled, never scored as zero reward.
  • Three-granularity GRPO feedback — dialogue / milestone / turn. Milestone rule: never reward a completion claim before it is true.

Speak policy

  • Duplex decision over continue / begin / stop / resume; capability boundaries — "a spoken promise is neither proof of execution nor an authorization token."

What holds upStrengths

  • Transferable environment recipe: negative policies as first-class tests, write/refusal/unsupported taxonomy, model-free reference-replay construction checks, per-episode private database copies.
  • Anti-hallucination reward design: milestone scorer holds pending actions to their deadline and never rewards a completion claim before it is true.
  • Unusually broad evaluation: 450-item HalluQA, 939 DNA, 2,726 CDNA, 50-session human red-team — far beyond typical audio-model reports; gains and regressions both tabulated.
  • Practically meaningful duplex gains: the difference between an assistant that barges in and one that waits and yields.

Where it wobblesLimitations

  • No ablations or statistical testing; component attribution is deferred to future work, all comparisons are single-run descriptive deltas.
  • In-house benchmark dominance: the biggest wins (multilingual +6.4, Long-AMC +8.04) sit on unreleased proprietary sets with LLM judges — outsiders cannot recompute them.
  • Protocol mismatches flatter headlines: half-duplex τ-Voice vs official full-duplex; modified EVA-A configuration — disclosed, but layout invites over-reading.
  • Under-discussed regressions: EVA-A 70.50 → 66.26, MMAU 82.21 → 81.60, retrieval F1 −2.26 pts; the −76% query cut "does not establish measured savings."
  • Thin evidence in places: 6-turn latency subset, 13 dropped EVA-A sessions, no seed repetition, confidence intervals, or contamination analysis anywhere.

Open threadsQuestions for Further Exploration

  1. Which component drives the gains — Core-Cocktail SFT, either OPD path, or environment evolution? The missing ablation would decide.
  2. Do duplex gains hold on real recordings in noisy far-field settings, or only on synthesized speech?
  3. Does the −76% query reduction yield measured latency/cost savings, or does −2.26 F1 surface as more wrong-source answers?
  4. Can the task taxonomy and reference-replay checks be released as a public spoken-agent reliability benchmark?
  5. Would hybrid routing persist with the 3.1 model foreground and a reply judge independent of the executor's model family?
