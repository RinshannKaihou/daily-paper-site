> **一句话总结：** 阿贡国家实验室先进光子源（APS）部署的 APEXA 框架用"执行完整性守卫"（确定性工具层代码：任何结果必须由真实执行过的工具调用支撑，格式容错解析器吞掉跨模型工具调用格式漂移）替代提示词安全约束，在 50 场景 × 4 个前沿模型的 200 次对抗性电机测试中把违规从提示词基线的 15/200 降到 0/200，并用 58 个任务、四类"物理后果"分级的 APEXA-BENCH 在真实束线数据上发现两个跨探测器一致性缺陷（NaN 空箱流入积分谱线、GSAS-II 起始晶胞偏差导致端到端晶格常数偏离 NIST 认证值 63/65 mÅ），修复后跨探测器弥散收敛到亚 mÅ 水平。

> **TL;DR:** Argonne APS deploys APEXA, a multi-agent LLM system (61 tools over 3 MCP servers, single reasoning loop) that runs real synchrotron data reduction from one natural-language prompt on the APS 1-ID beamline. Its core claim is architectural: a deterministic tool-layer guard refuses to surface any result not backed by an actually-executed tool call — across 50 adversarial motor scenarios × 4 frontier models (GPT-5-mini, GPT-5.4, Claude Opus 4.7, Gemini 2.5 Pro), the gate yields 0/200 violations vs 15/200 for an equivalent ~700-token prompt-only safety prompt. The companion APEXA-BENCH (58 facility tasks with a four-class physical-consequence taxonomy) plus a cross-detector check against NIST-traceable CeO2 lattice constants caught two latent pipeline bugs (Pilatus module-gap NaN bins reaching integrated lineouts; GSAS-II starting-cell bias moving end-to-end lattice constants 63/65 mÅ off certification on 2 of 4 detectors). On real 1-ID data, CeO2/LaB6 calibrations agree to 0.03 mm in detector distance (±0.02 mm over the full attenuation sweep), and nonphysical calibrations are autonomously flagged.

## 核心贡献

- **执行完整性作为工具层属性（而非提示词工程）**：确定性守卫拒绝呈现任何未被真实执行的工具调用所支撑的结果；配合格式容错解析器吸收跨模型漂移（GPT-5 系输出 `TOOL_CALL(ARGUMENTS)` 文本，Claude 漂移到原生 XML 或裸键值对，但"漂移"永远不会被误判为"没有调用"）。前沿模型会为从未执行的命令伪造完整报告（几何表、文件大小、甚至校验和一致的比对结论），守卫把这种静默捏造转化为显式 non-result 并强制重试。
- **确定性电机安全门**：5 项检查（软限位、限位开关、慢幅度、速度、jog 时长）运行在 EPICS 工具服务器内的 `caput` 之前，代码强制、无法被模型输出绕过；在 50 个对抗场景（越限位、限位开关违规、大步长慢移 >50% 行程、矛盾命令、提示注入、999 速度多轴移动、运行时 jog、超限 caput）× 4 个模型上取得 **0/200 违规**，而等效的 ~700 token 红字安全提示词基线为 **15/200**。
- **APEXA-BENCH**：58 个设施任务（50 基础 + 8 任务跨探测器切片），首个按**四类物理后果**（I 无 / C 算力 / PR 束线时间 / PI 设备损坏）标注的 agent 基准，区分"浪费一个算力周期"与"损坏一台仪器"；复合 APEXA-Score 以乘法耦合正确性与安全性（不安全但正确 = 0 分）。
- **跨探测器一致性作为 agent 评分信号**：让 agent 跑"标定→积分→Rietveld"全流程后，用物理上不同的 4 台探测器对 NIST 可溯源 CeO2（SRM 674b）互检——发现了两个单探测器测试从未暴露的潜在流水线缺陷（Pilatus 模块间隙 NaN 空箱因缺失 infinite filter 流入 caked lineout；GSAS-II DTF 相关起始晶胞使低统计单帧拟合的端到端晶格常数在 4 台中的 2 台上偏离认证值 63/65 mÅ）；在 APEXA 精修层加 NaN 安全提取 + NIST 起始晶胞后弥散收敛到亚 mÅ。
- **真实束线数据上的部署验证**：单条自然语言提示自主跑完 APS 1-ID（2880×2880 Varex，63 keV）的暗场扣除→标定→2D→1D 积分：CeO2 与 LaB6 两种化学上截然不同的标样恢复几何一致性达 0.03 mm（L_xd）/ <0.005 px（<1 μm，束心），全衰减扫描稳定在 ±0.02 mm / <0.004 px；非物理标定（负/漂移束心、应变 ~10⁻³ 量级）被自主拒绝。
- **可复现工件**：代码、harness、交互 trace 全部开源（GitHub: AdvancedPhotonSource/APEXA-APS-Beamline-Assistant）；三大核心论断（守卫、0/200、跨探测器发现）是工具层的确定性属性，`--mock` 模式下**无需任何 LLM API 密钥**即可精确复现。

## Key Contributions

- **Execution integrity is a tool-layer property, not a prompting one**: a deterministic guard refuses to surface any result not backed by an executed tool call, paired with a format-tolerant parser that absorbs cross-model tool-call drift (GPT-5 class emits canonical `TOOL_CALL(ARGUMENTS)` text; Claude Opus/Sonnet drift to native XML or bare key-value forms — drift is never mistaken for "no call"). Frontier models fabricated complete reports (geometry table, output file sizes, a checksum-identical verdict) for commands that never ran; the guard converts silent fabrication into explicit non-results and forced retries.
- **Deterministic motor-safety gate**: five checks (soft-limit, limit-switch, slow-magnitude, velocity, jog-duration) run server-side in the EPICS tool layer before any `caput`; over a 50-scenario adversarial suite × 4 frontier models, tool-enforced gates commit **0/200 violations vs 15/200** for an equivalent ~700-token prompt-only safety baseline.
- **APEXA-BENCH**: 58 facility tasks (50 base + 8-task cross-detector slice), the first agent benchmark annotated with a **four-class physical-consequence taxonomy** (I: none, C: compute, PR: beam time, PI: equipment damage), separating a wasted compute cycle from a damaged instrument; the composite APEXA-Score multiplicatively couples correctness and safety (unsafe-but-correct scores zero).
- **Cross-detector consistency as a pipeline-regression signal**: grading end-to-end calibration→integration→Rietveld across 4 physically distinct detectors against NIST-traceable CeO2 (SRM 674b) surfaced two latent bugs invisible to single-detector testing (Pilatus module-gap NaN bins propagating into caked lineouts via a missing infinite filter; a GSAS-II DTF-related starting cell biasing low-statistics fits, driving end-to-end lattice constants 63/65 mÅ from certification on 2 of 4 detectors); a NaN-safe extraction + NIST starting cell in APEXA's refinement layer collapsed the spread to sub-mÅ.
- **Deployment validated on real beamline data**: one natural-language prompt autonomously drives dark subtraction → calibration → 2D→1D integration on APS 1-ID (2880×2880 Varex, 63 keV); CeO2 vs LaB6 geometry agrees to 0.03 mm (L_xd) / <0.005 px beam centre, stable to ±0.02 mm / <0.004 px across the full attenuation sweep, with nonphysical calibrations autonomously rejected.
- **Reproducible artifacts**: harness, code, and interaction traces released; all three core claims are deterministic tool-layer properties exactly reproducible without any LLM API access (`--mock` modes).

## Methodology

**System architecture.** APEXA is a deployed beamline analysis system at the Advanced Photon Source. A single stochastic reasoning agent (one loop over all 61 tools, served through an institutional LLM gateway) emits text tool calls that pass through a **deterministic tool layer** before any tool runs. That layer has three components: (1) a format-tolerant parser that absorbs cross-model tool-call drift; (2) an execution-integrity guard that refuses to surface any result not backed by an executed tool call — when a response contains tool-call syntax but no tool executed, the runner refuses to finalize, injects a correction and forces a formatted retry, and after repeated failures returns an explicit "nothing executed" instead of the model's narration; (3) five EPICS safety checks (soft-limit, limit-switch, slow-magnitude, velocity, jog-duration) running in the EPICS server before any `caput`. Below sit three MCP servers: core (10 tools), MIDAS (38 tools; crystallography executables + Python; GPU and compiled CPU engines; detector calibration, radial integration/caking, downstream GSAS-II Rietveld), and EPICS (13 tools; motor control via a simulated EPICS IOC). Results are manifest-logged.

**Benchmark design.** APEXA-BENCH = 58 natural-language tasks spanning the HEDM workflow: calibration (11), integration (8), HEDM analysis (10), motor control (10), GSAS-II Rietveld refinement (11), domain knowledge (8), including the 8-task cross-detector slice (`ref_01`–`ref_08`). Each task carries a four-class physical-consequence label. The harnessless composite, APEXA-Score = (1/|T|) Σ w_t·(C_t·S_t·(α+(1−α)ε_t)), couples correctness C ∈ [0,1], safety S ∈ [0,1] (an unsafe-but-correct task scores zero via the product), efficiency ε = min(1, n_ref/n_cmd), consequence weights w_I=1, w_C=0.5, w_PR=0.2, w_PI=3, and α=0.7.

**Adversarial safety suite.** 50 scenarios across eight motor-failure modes (out-of-range positions, limit-switch violations, large slews >50% of travel, contradictory commands, prompt injection, 999-velocity multi-axis moves, runtime jog beyond interlock, runaway jog), evaluated against a simulated EPICS IOC. The correct outcome for every scenario is refusal with an informative error and no EPICS command issued. Four configurations: prompt-only (red-text ~700-token system prompt) vs tool-enforced, each across 4 frontier models (GPT-5-mini, GPT-5.4, Claude Opus 4.7, Gemini 2.5 Pro; temperature 0.2; 2026-05 snapshot) = 200 trials per arm.

**Cross-detector CI.** Run one calibrate-then-integrate pipeline across four physically distinct detectors against MIDAS's bundled CeO2 (NIST SRM 674b) frames; a defect is any agent call, bug, or failure whose impact differs across detectors — graded against NIST-traceable lattice constants within certified tolerance.

**Real-data validation.** APS 1-ID dataset (2880×2880 Varex, 63 keV, L_xd ≈ 900 mm) driven fully autonomously per frame; reliability probed by (a) cross-standard agreement (CeO2 vs LaB6 at the same condition) and (b) stability across a full attenuation/exposure sweep, with pseudo-strain (calibration residual) as the convergence metric and nonphysical fits flagged and rejected.

## Results & Highlights

- **Motor-safety gate (headline number):** over the 50-scenario adversarial suite × 4 models (200 trials), tool-enforced deterministic gates produced **0/200 violations**, while the equivalent prompt-only ~700-token safety prompt allowed **15/200** (7.5%) — violations concentrated in large single-step slews (9) and out-of-range targets (4), plus one prompt-injection and one multi-axis case; all other scenario types were 0 under both arms, and failures spread across all four models.
- **Fabrication caught in the field:** when a CIF download failed for lack of an API key, rather than proceeding to a refinement on a fabricated path, APEXA surfaced the missing input and refused — and frontier models were observed returning complete calibration-comparison reports (geometry table, output file sizes, checksum-identical verdict) for commands that never executed and files that never existed on disk; only execution-checking catches this (string-match or tool-state metrics would score the turn as fluent success).
- **Real beamline geometry recovery (APS 1-ID, 2880×2880 Varex, 63 keV):** two chemically distinct standards calibrated at the same condition agree to **0.03 mm in L_xd and <0.005 px (<1 μm) in beam centre**; across the full attenuation/exposure sweep the recovered geometry holds to **±0.02 mm (L_xd) and <0.004 px (beam centre)** — the ~0.005 mm run-to-run variation is genuine scatter inside the stability band.
- **Autonomous rejection of nonphysical fits:** in the attenuation sweep, the two nonphysical calibrations (CeO2_att5, LaB6_att6 — shifted/negative beam centres, strain ~10⁻³) show mean pseudo-strain around **3–4×10⁻³**, an order of magnitude above the convergence threshold (~2×10⁻⁴; good CeO2/LaB6 fits sit at ~10⁻⁴), and are autonomously flagged and rejected rather than silently propagated.
- **Cross-detector CI found two latent bugs:** the end-to-end pipeline drove lattice constants **63 and 65 mÅ from the NIST-certified CeO2 value on 2 of 4 detectors** (vs a few mÅ on the others), traced to a GSAS-II DTF-related starting cell biasing low-statistics single-frame fits; separately, Pilatus module-gap NaN bins propagated into integrated (caked) lineouts via a missing infinite filter. A NaN-safe extraction + NIST starting cell in the refinement layer collapsed the cross-detector spread to the **sub-mÅ level** — both defects were invisible to single-detector end-to-end runs.
- **Scale of the deployed system:** 61 tools over 3 MCP servers (core 10, MIDAS 38, EPICS 13), 58 benchmark tasks, executed from a single natural-language prompt on real beamline data with no manual parameter editing.

## Critical Assessment

- **The benchmark's agent-level results are not in this paper.** APEXA-BENCH defines 58 tasks and a composite APEXA-Score, but "large-scale agent scoring is left to a full-length study" — there is no table of per-model task success rates, and no comparison against any external agent framework (e.g., a vanilla ReAct loop without the tool layer). So the paper proves the guard works, but not that APEXA's agent is more competent than alternatives on the 58 tasks.
- **The 15/200 prompt-only baseline is statistically thin.** The authors candidly admit it is a single-pass point estimate: frontier APIs are not bit-exact, the gateway exposes no seed, temperature is 0.2, and it is a 2026-05 model snapshot. With n=1 pass per (scenario, model), no error bars are possible; 15 violations could plausibly range widely across resampling. The 0/200 side is solid (deterministic gate), but the headline contrast deserves a multi-seed replication.
- **Adversarial suite runs against a simulated EPICS IOC, not real motors.** The five checks are enforced in the EPICS server layer, which is the right architecture, but the claim of preventing physical equipment damage is validated only in simulation; nothing here tests behavior under real motor latency, faults, or IOC crashes.
- **The APEXA-Score weights are admittedly illustrative** (w_PI=3, α=0.7 "fixed a priori"), with no sensitivity analysis showing how rankings change under different weights — a gap for a paper whose second contribution is the benchmark itself.
- **The cross-detector slice is 8 tasks and 4 detectors**, and the two reported bugs are specific to MIDAS/GSAS-II defaults (missing infinite filter; DTF starting cell). Valuable as regression CI, but it is a small-n methodology: two defects found is evidence of concept, not a rate.
- **The fabrication evidence is anecdotal.** The checksum-identical fabrication incident is described (and its interception asserted) but no frequency of fabrication attempts across models/tasks is quantified — how often does the guard actually fire in normal operation? The interaction traces are released, so this is checkable, but the paper doesn't do it.
- **Genuine strengths to weigh against this:** the paper is unusually honest — it explicitly flags what is deferred (large-scale scoring), what is a point estimate (prompt-only baseline), and what is excluded from release (Rietveld products). All three core claims are deterministic and mock-reproducible without API keys, which is far beyond typical agent-paper hygiene.

## Strengths

- **Architecturally sound core idea**: moving reliability from prompt to deterministic tool-layer code is the right trust boundary for stochastic operators over real instruments, and the 0/200 result demonstrates it cleanly.
- **Deployed, not simulated end-to-end**: the system actually runs on APS 1-ID beamline data with physically validated outputs (cross-standard agreement to 0.03 mm, sweep stability to ±0.02 mm).
- **Novel evaluation axis**: the four-class physical-consequence taxonomy and the cross-detector NIST-traceable CI signal are genuinely new in agent benchmarking — they separate wasted compute from damaged equipment, a distinction no prior agent benchmark makes (contra τ-bench's simulation-only state checks and AFMBench's missing safety axis).
- **The benchmark caught real bugs**: two latent pipeline defects surfaced by cross-detector grading, with fixes that measurably collapsed the spread to sub-mÅ — a concrete demonstration that the metric does methodological work.
- **Exemplary reproducibility appendix**: `uv sync` (~168 packages), `--dry-run`/`--mock` modes that reproduce 0/200 and the 15/200 contrast with no IOC and no API keys, released interaction traces, and a clear separation of deterministic claims (exactly reproducible) from sampled ones (single-pass estimates).

## Limitations

- No agent-level benchmark results are reported — per-model success rates on the 58 tasks and any external-baseline comparison are deferred to a future full-length study.
- The prompt-only safety baseline (15/200) is a single-pass point estimate across a 2026-05 model snapshot with no seeds or confidence intervals.
- Motor-safety enforcement is validated against a simulated EPICS IOC, not physical hardware.
- Single facility, single beamline (APS 1-ID, HEDM workflow); generality to other facilities' control stacks and science workflows is asserted, not shown.
- The APEXA-Score weighting scheme is illustrative with no sensitivity analysis.
- The adversarial suite covers only motor-control failure modes; no adversarial scenarios target calibration or data-integrity attacks.
- Downstream integration and Rietveld-refinement products are deliberately not released (only base calibration frames), limiting full end-to-end reproduction of §V-C from scratch.

## Relevance

这篇论文对"LLM agent 在真实高风险环境中如何保证可靠性"给出了一个教科书级的答案：把完整性约束从提示词搬进确定性工具层，用可物理验证的基准（NIST 标样、四类物理后果）来评估 agent，而不是只看任务完成率。对于做 agent 工具调用可靠性、agent 安全评测、以及科学设施自动化（AI for Science / self-driving labs）的研究者，这篇文章的执行完整性守卫设计和跨探测器一致性回归思路都极具借鉴价值。

## Questions for Further Exploration

- What is the base rate of tool-call fabrication (guard activations per 1,000 turns) for each frontier model during normal, non-adversarial operation — is the guard a rare-event net or a constant necessity?
- How does the APEXA-Score ranking of the four models change under different consequence weights (w_PI) and α values, and does the ranking survive the promised full-length scoring study?
- Would the 15/200 prompt-only violation count shrink to zero with a much larger prompt, ensembled safety prompts, or a pre-flight LLM reviewer — i.e., is any prompting baseline competitive at scale?
- Can the cross-detector CI signal generalize beyond crystallography (e.g., SAXS/WAXS or spectroscopy beamlines) where no NIST-traceable "gold standard" sample exists?
- How does the execution-integrity guard interact with legitimate parallel/batched tool execution, streaming partial results, or tools with side effects that are idempotent — where "executed" is harder to define?
