Why This Matters

「用可对齐的稠密 rubric 代理昂贵 rollout」对 Agent 提示优化、test-time 适应等任何昂贵评估场景都有直接参考价值。

The recipe — a cheap dense proxy for expensive evaluation, aligned by ranking rather than scores — transfers to any costly-evaluation loop.

Critical Edge

With K=3, Kendall's τ is computed over just 4 skills — 6 pairwise comparisons, 7 possible values — so the θB=0.9 "aligned" rubric could be aligned by luck.

Methodology

Bilevel evolution, one cheap verifier call per candidate

Distilled from the paper's Mode A / Mode B formulation (defaults: L=3 rounds, K=3 branches).

Rubric R 5–15 binary criteria, signed points (+1..+5 / −5..−1)
→Mode Arevise K skills, 0 rollouts
Skills ×K dense hit-vector feedback per criterion
→Mode BK rollouts, Kendall τ
Oracle true rollout score; τ<0.9 ⇒ rubricator revises R

The rubric is bootstrapped from the seed skill's execution trace; a temperature-0 LLM verifier judges every criterion in a single call, so the generator sees which criteria failed, not just a scalar. Mode A (inner) accepts an edit only if the frozen rubric score doesn't drop — zero oracle cost. Mode B (outer) spends exactly K rollouts to compare the rubric-induced ranking with the oracle ranking; on τ<θB, the rubricator adds only evidence-bounded criteria until aligned.

Champion selection is always by true oracle score, so a misaligned rubric degrades guidance but never corrupts the output — a safe-failure property. Oracle complexity amortizes from O(LT) to O(L).

Beyond the headline

  • Static ceiling broken: +8.8 to +11.5 pp over human/LLM-written one-shot skills on WildClawBench; +16.7 to +24.2 pp on SkillsBench.
  • Ablations: removing the oracle-aligned rubricator collapses GPT-5.4 to 42.5% (+1.1 pp over static skills); swapping ranking-alignment for score regression costs 2.7–5.3 pp at identical oracle budget; no seed skills, −3.8 to −6.5 pp.
  • Case study: a paratransit task stuck at 0.0 until the rubricator installs dial-a-ride audit criteria — Round-1 skill hits a 1.0 verifier score.

Strengths

Why the numbers are credible

  • +Safe-failure design: misaligned rubrics can only hurt inner-loop guidance — the champion is always picked by true oracle score.
  • +Fair setup: baselines get 2× the token budget; generator and rubricator run on the same backbone as the agent under test.
  • +Supervision target isolated: score regression degrades 2.7–5.3 pp at identical oracle budget — the ranking choice is causally validated.
  • +Exceptional transparency: full prompt suite, both methods' hyperparameters, token-accounting protocol, K×L sensitivity grid, per-task heatmaps, code released.
  • +Motivation first: a pilot study (10 tasks × 10 rounds × 3 seeds) grounds the supervision bottleneck before the fix is proposed.
Limitations

Where the claim thins out

  • −Subjective tasks barely move (Creative +3.1 pp): the method amplifies existing oracle signal rather than creating capability.
  • −Coarse alignment signal: τ over 4 skills has 7 possible values; larger K sharpens it but returns diminish past K=4.
  • −Possibly under-tuned baselines: SkillOpt runs at reduced scale with three components disabled; only two evolved baselines compared — six surveyed systems never run.
  • −Add-only rubrics: the rubricator may never remove criteria, biasing evaluation ever stricter — acknowledged, not ablated.
  • −Small per-category n (Social n=6, Media n=5) with 3 seeds — category-level numbers carry high variance.
Open Questions

Where this could go next

Q1

Would confidence-weighted or graded (non-binary) criteria unlock the subjective categories where binary criteria stall?

Q2

Does Kendall's τ over only 4 skills reliably detect misalignment — would a pairwise-preference formulation with partial rollouts be more sample-efficient?

Q3

Can rubrics transfer across tasks toward multi-task skill libraries, or does oracle alignment make them irreducibly task-specific?

Q4

Does the add-only rubric constraint interact badly with drifting task distributions — monotone strictness eventually over-constraining the generator?

Q5

Could a genuinely stronger auxiliary model (currently same-backbone by design) break the current ceiling, and at what cost trade-off?

Q6

Can the learned rubric be distilled into the agent's weights, amortizing per-task search cost entirely?
