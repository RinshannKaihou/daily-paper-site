> **一句话总结：** 提出 Forge 框架，把 LM 程序的执行失败同时视为"如何修改提示词"和"缺少什么训练证据"的双重信号：失败被抽象为可复用的失败模式记忆，并驱动四种变异（正例/反例/边界/压力）生成经工具验证的新训练样本回流优化循环；在 8 个异构基准上，Forge 将平均得分从 55.66% 提升到 72.18%（较未优化基线 +16.52 个百分点，较最强 APO 基线 Ace +4.92 个百分点），其合成数据还能让其他提示词优化器提升 2–9 个百分点、让 GRPO 强化学习提升 4–8 个百分点。

> **TL;DR:** Forge co-evolves prompts and training data for frozen-weight LM programs: execution failures both drive reflective prompt revision (a Gepa-style backbone) and populate a failure memory that guides synthesis of new training instances via four mutation intents (positive / negative / boundary / stress), each admitted only after a tool-grounded verifier confirms validity and faithfulness. Across 8 heterogeneous benchmarks (HotPotQA, IFBench, HoVer, FiNER-139, LawBench, AIME-2025, MMLU-Pro, AppWorld) with the Qwen3.5-35B-A3B task model, Forge reaches a 72.18% aggregate score vs 55.66% for the unoptimized baseline (+16.52 pts) and beats the best APO baseline (Ace, 67.26%) by 4.92 pts; on the dense Qwen3-8B it scores 50.97% vs Gepa's 45.59% (+5.38). The synthesized data transfer beyond Forge: they improve all 9 prompt-optimizer pairings by 2–9 pts (e.g., LawBench + MiroV2: 38% → 47%) and all 3 GRPO comparisons by 4–8 pts (e.g., HotPotQA GRPO: 57% → 65%) under matched budgets.

## 核心贡献

- **将训练数据形式化为 APO 的可变优化状态**：提出"自适应数据 APO"（adaptive-data APO）的形式化定义——训练集以只追加（append-only multiset）方式随优化进程演化，固定数据 APO 是其特例；验证集目标保持不变，测试集只用于报告。
- **失败记忆（failure memory）机制**：把不完美执行抽象为可复用的失败模式（机制描述 + 支撑执行记录），由 LM 分配器负责归类（assign）、新建（create）或精炼（rename）模式，从而把"可复用的失败机制"与"暴露它的具体实例"解耦，避免合成退化为近重复改写。
- **四种变异意图的失败导向合成**：positive（良性变化下保持目标技能）、negative（构造不应触发该修复策略的对照样本）、boundary（探查决策边界附近条件）、stress（加入干扰项与交互约束），配合工具接地的生成器与验证器（validity + faithfulness 双重门槛），只有通过双重验证的实例才进入训练集。
- **大规模实证与迁移研究**：在 8 个异构基准、2 种任务模型、2 种优化器模型上评估；并通过配对实验证明合成数据对 MiroV2 / Ace / Gepa 三个外部提示词优化器和 GRPO 权重优化均有迁移价值。

## Key Contributions

- Formalizes **adaptive-data APO**: training data as a mutable, append-only optimization state coupled to prompt search, generalizing fixed-data APO (the special case where the synthesis operator is empty) while keeping the validation objective and test protocol untouched.
- Introduces a **failure memory** that clusters imperfect executions into reusable, decontextualized failure modes with supporting evidence, preventing near-duplicate synthesis and letting later prompts/data expose genuinely new weaknesses.
- Proposes **failure-mode-guided data synthesis with four mutation intents** (positive, negative, boundary, stress) that probe invariance, contrast, decision boundaries, and robustness respectively — rather than paraphrasing the source failure — gated by a tool-capable verifier checking both validity and faithfulness.
- Delivers an **eight-benchmark evaluation** spanning retrieval, instruction following, structured prediction, law/finance, math reasoning, and interactive agents, plus a **paired transfer study** showing the synthetic instances improve three external prompt optimizers and GRPO-based weight optimization under matched budgets.

## Methodology

The paper targets LM programs with frozen weights and M optimizable module prompts. In conventional fixed-data APO, an optimizer (drawing minibatches from a static D0) searches prompt candidates and selects by aggregate validation score. Forge generalizes this with a coupled update: prompt search over the current data, plus an append-only data update that admits verified synthetic instances.

The optimization loop has two branches fed by the same imperfect executions:

1. **Prompt branch** — a reflective-search backbone inspired by Gepa. Each iteration samples a minibatch, executes the program, and a reflector agent rewrites one module's system prompt from the failed traces and module-level feedback. A proposal is admitted only if it beats its parent on the same minibatch, then is scored on the fixed validation set. Parent selection is frontier-based: candidates on the per-instance Pareto front are sampled proportionally to how many validation instances they lead.
2. **Data branch (failure-guided synthesis)** — triggered after p completed prompt-search steps without strict improvement in the best aggregate validation score. Active failure modes (those accumulated since the last synthesis event) receive a generation budget K via largest-remainder allocation proportional to supporting observations. A multi-step generator agent, conditioned on the mode description, a supporting failed execution, and a mutation intent, produces a new instance — using benchmark-provided tools (e.g., the same full-Wikipedia ColBERT index as the HotPotQA task program) so gold supervision is grounded in retrievable evidence rather than optimizer parametric knowledge. A separate verifier agent with the same tools independently judges validity (schema, task coherence, gold-supervision correctness) and faithfulness (to the failure mode and mutation intent); only instances passing both are appended to D, and sampling order is refreshed so new data are visited before already-consumed real data.

The four mutation intents are illustrated with a concrete HotPotQA failure (the program returned "Michael J. Fox" where the gold canonical form was "Michael Andrew Fox"): positive preserves the canonical-answer-form requirement with new entities; negative constructs a sibling where returning the full biographical name would be wrong; boundary flips the requested name type so the alias becomes correct; stress adds distractor articles about other people named "Prince". The failure assigner, reflector, generator, and verifier prompts are given verbatim in the appendix, along with split construction (seeds, sizes), budget alignment (matching completed per-example task-program evaluations across optimizers), and the paired GRPO protocol (identical 100-step runs differing only in whether Forge-admitted instances are appended; LoRA rank 8, 8 generations per prompt, seeds 42).

## Results & Highlights

- **Main comparison (Table 1, Qwen3.5-35B-A3B task model, GPT-5.5 optimizer)**: Forge reaches a 72.18% aggregate score over the 8 benchmarks vs 55.66% for the unoptimized baseline (**+16.52 pts**), 67.26% for the best baseline Ace (**+4.92 pts**), 65.33% for Gepa, and 63.36% for MiproV2; Forge is best on 6 of 8 benchmarks. Largest per-benchmark gains: AppWorld 84.69% vs baseline 66.64% (+18.05), HotPotQA 76.00% vs 52.00% (+24.00).
- **Honest losses**: Forge is not uniformly best — on IFBench it trails Ace 54.52% vs 61.63% (−7.11), and on MMLU-Pro it trails MiproV2/Gepa 89.00% vs 90.00% (−1.00).
- **Ablation (Table 2, mean over the 8 benchmarks)**: prompt search alone lifts 55.66 → 64.17 (+8.51); adding **random** synthesis *hurts* (62.38, −1.79); adding failure memory raises it to 68.24 (+5.86 over prompt search); adding mutation guidance reaches 72.18 (+3.94). Full Forge beats random synthesis by 9.80 pts — failure- and mutation-guidance, not mere data volume, drive the gains.
- **Cross-architecture replication (Table 3, dense Qwen3-8B)**: Forge 50.97% aggregate vs baseline 36.88% (+14.10) and vs strongest competitor Gepa 45.59% (+5.38), leading 6 of 8 benchmarks.
- **Transfer to other optimizers and GRPO (Table 4)**: Forge-augmented data improve **all 12** dataset–optimizer pairs — the 9 prompt-optimization gains span 2–9 pts (e.g., LawBench + MiroV2: 38 → 47; HotPotQA + Gepa: 66 → 75), and GRPO gains at step 100 are +8 on HotPotQA (57 → 65), +4 on FiNER-139 (69 → 73), and +8 on LawBench (43 → 51) under identical configurations.
- **Synthesis accounting (Figure 3)**: admission rates of 73–98% across four audited benchmarks (AIME-2025: 22/30; AppWorld: 39/40; HotPotQA: 80/100; FiNER-139: 93/100); the prompt–data loop also rebalances failure memory, shrinking the most-to-least-frequent mode ratio from 11:1 to 4:1 on AIME-2025, 20:1 to 6:1 on AppWorld, 22:1 to 11:1 on HotPotQA, and 8:1 to 4:1 on FiNER-139.
- **Optimizer-model robustness (Table 7)**: swapping the optimizer from GPT-5.5 to DeepSeek-V4-Pro changes six-benchmark scores by only 1.66 points on average (max 3.93).
- **Leakage audit (Appendix D.2)**: a two-stage AI + 10% manual audit found no semantic overlap between generated examples and the fixed validation/test partitions.
- A qualitative artifact: on AppWorld, Forge's evolved system prompt (candidate 25) lifts the aggregate validation score from 60.20% to 92.50% over the seed prompt.

## Authors & Credibility

Tianyu Yuan and Zhuzhong Qian (corresponding author) of Nanjing University. The paper is listed under cs.SE, is 26 pages, and reads as a careful systems/ML paper: full verbatim prompts for all four optimizer-side agents (failure assigner, reflector, generator, verifier), an explicit dataset-construction table with seeds and split sizes, a documented budget-alignment protocol across heterogeneous optimizers, a complete GRPO configuration, synthesis accounting that partitions every generation attempt, and a data-leakage audit. Experiments use current strong models (Qwen3.5-35B-A3B and Qwen3-8B as frozen task models; GPT-5.5 and DeepSeek-V4-Pro as optimizer models) and compare against three recent, strong APO systems (MIPROv2, ACE, GEPA) under a shared evaluator and aligned task-model evaluation budgets.

## Critical Assessment

- **Novelty**: The core idea sits in a crowded 2024–2026 space (SIPDO's closed-loop synthetic-data feedback, Data-Prompt Co-Evolution, CoEvolve, DataEnvGym). Forge's genuinely distinctive elements are (a) the failure-memory abstraction that separates reusable mechanism from instance, (b) the four-intent mutation taxonomy probing invariance/contrast/boundary/robustness, and (c) tool-grounded generation + dual-gate verification. The transfer study to other optimizers and to GRPO is more thorough than typical.
- **Rigor concerns**: Budget alignment matches *task-program evaluations*, not total optimization cost — Forge runs four additional optimizer-side agents (reflector, assigner, generator, verifier) per step, so it consumes substantially more GPT-5.5 compute than MIPROv2/Ace/Gepa; no token or dollar accounting is reported, and part of the +4.92 margin may be extra optimizer compute. The paper itself concedes the alignment is approximate (MIPROv2 trial counts are estimates; GEPA may overshoot).
- **Statistical strength**: single seed (seed 0), no variance or significance testing anywhere; several test splits are small (AIME-2025 test is 30 problems scored 3×; most others 100), so per-benchmark differences of a few points are noisy. The headline aggregate is an unweighted mean of eight benchmark percentages, which lets big-domain gains (AppWorld +18.05) dominate.
- **Missing ablations/comparisons**: the component ablation is cumulative, not factorial, so the conditional deltas conflate interactions; and despite motivating against learner-aware synthesis systems (SIPDO, DataEnvGym, LLM2LLM, PromptWizard, STAT) in related work, none is run empirically — the closest data-synthesis baselines are absent from the comparison.
- **Verification reliability is unquantified**: the verifier's validity/faithfulness judgments are never calibrated against human labels, and malformed assigner outputs silently no-op; the leakage audit is AI-first with only a 10% manual sample, a reasonable but not exhaustive safeguard given HotPotQA synthesis draws from the same Wikipedia corpus as the test set.
- **Redeeming honesty**: the paper reports where Forge loses (IFBench to Ace by 7.11, MMLU-Pro by 1.0), shows random synthesis actively hurting (−1.79), and acknowledges in its conclusion that dataset-size / example-selection / sampling-distribution effects remain entangled.

## Strengths

- Clean formalization of adaptive-data APO as a strict generalization of fixed-data APO, with an append-only update that provably leaves the validation/test protocol untouched.
- The failure memory directly attacks the known failure mode of naive synthesis (near-duplicate paraphrases), and the AppWorld "incomplete paginated search" example (Spotify follow list + Venmo requests collapsing into one mode) concretely demonstrates cross-task mode reuse.
- The four mutation intents are principled — each targets a distinct generalization axis (invariance, contrast, decision boundary, robustness) rather than surface diversity.
- Tool-grounded generation and verification anchor gold supervision in benchmark evidence (e.g., the same ColBERT wiki index used by the task program) instead of optimizer parametric memory.
- Unusually broad evidence: 8 heterogeneous benchmarks, 2 task-model architectures, 2 optimizer models, 12/12 successful transfer pairs, plus GRPO — and the negative control (random synthesis) that isolates the value of failure guidance.

## Limitations

- No multi-seed runs, error bars, or significance tests; several test sets are small (≤100 examples, AIME 30), making fine-grained per-benchmark claims fragile.
- Optimizer-side compute is not equated or even reported; Forge's advantage is partly attributable to a heavier multi-agent optimization pipeline (the trade is discussed for task-model evaluations only).
- The transfer study covers only three benchmarks (HotPotQA, FiNER-139, LawBench) and one task model; the authors themselves call for broader tasks and model families.
- Cumulative-only ablation leaves interaction effects between failure memory and mutation guidance unmeasured; the assigner/verifier error rates and their downstream impact are not quantified.
- Append-only data growth raises long-run cost and risks eventual distribution imbalance — acknowledged but unresolved (the paper lists disentangling dataset size, example selection, and sampling distribution as future work).

## Relevance

这篇论文属于"自进化 LLM 智能体/自动化优化闭环"方向的核心工作：它构建了一个由失败信号驱动的提示词-数据共同演化循环，本质上是让 LM 程序在没有权重更新的情况下自我改进，其失败记忆与自动合成验证机制对自进化智能体和自动化研究循环的设计有直接参考价值。

## Questions for Further Exploration

- How much of Forge's +4.92 aggregate margin over the strongest baseline survives when optimizers are matched on total optimizer-LLM tokens or dollar cost rather than task-program evaluations?
- Which of the four mutation intents carries the gains — a factorial ablation (and intent-frequency analysis) would clarify whether stress/boundary instances are pulling weight or mostly positive variants matter?
- How reliable is the verifier's validity/faithfulness gate against human labels, and what is the false-admission rate on downstream optimization?
- Does failure memory transfer across task models or related benchmarks (e.g., HoVer modes reused for HotPotQA), enabling cross-task mode libraries?
- Can the loop extend to open-ended generation tasks lacking verifiable metrics or benchmark tools, where validity cannot be checked against retrievable evidence?
- Would replacing the append-only multiset with balanced sampling or curriculum ordering over admitted instances change the failure-mode rebalancing dynamics (11:1 → 4:1) and final scores?
