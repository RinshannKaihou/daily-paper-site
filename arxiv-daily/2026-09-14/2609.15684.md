> **一句话总结：** RESKILL 把交互式语言智能体的"技能失败后修复"形式化为"假设条件下的修复选择"问题：由 LLM 显式维护一组失败假设及其权重、生成多个候选技能补丁并用覆盖矩阵打分选择，再以环境重测结果更新假设状态；在 ALFWorld 与 TextCraft 上、三种小型 Qwen 模型（1.7B–4B）全部六个设置中取得最高最终成功率，平均比直接修复高 3.7 个百分点、比假设条件修复高 3.3 个百分点。

> **TL;DR:** When an LLM agent with a reusable skill file fails a task, one-shot reflection (Reflexion-style rewriting) conflates diagnosis, patch generation, and patch selection. RESKILL separates them: it maintains a weighted set of failure hypotheses, generates a pool of candidate skill patches from four sources (trace-anchored, hypothesis-anchored, targeted proposals, interface guards), scores each patch by weighted hypothesis coverage, applies the winner, retests in the environment, and carries failed-retest evidence into the next round. On ALFWorld (274 tasks, budget R7) and AgentGym TextCraft (budget R4) with frozen Qwen3-1.7B / Qwen2.5-3B / Qwen3-4B, RESKILL wins all six benchmark-model settings, lifting average final success by +3.7 pp over Direct Repair and +3.3 pp over Hypothesis Repair; its largest margins appear where failure causes are ambiguous, e.g., TextCraft D1 with Qwen2.5-3B reaches 85.8% vs 50.7% (Direct) and 61.2% (Hypothesis) from a 29.9% first-pass pool.

## 核心贡献

- **把失败修复形式化为"修复信用分配"问题**：指出一次失败 rollout 可能对应多个并存原因（缺失前置条件、错误对象操作、非法动作等），而现有的一次性反思方法（Reflexion、Self-Refine 等风格）把诊断、补丁生成与补丁选择压缩进单次生成，导致反复施加无效编辑或过拟合到虚假诊断。
- **显式结构化修复状态**：跨修复轮维护（1）带权重的活跃失败假设集 Ht（每条假设含失败解释、轨迹证据、受影响技能范围与修复提示）；（2）候选技能补丁池 Qt（轨迹锚定、假设锚定、定向提案、接口保护四类来源）；（3）二值覆盖矩阵 C(q,h) 标记每个补丁解决哪些假设；（4）已尝试补丁与重测结果历史。
- **覆盖加权的选择规则**：补丁得分 covt(q) = Σ_h ŵt(h)·Ct(q,h)，取加权覆盖最大者，平局时偏向更局部、证据更扎实的编辑——把"选哪个补丁"从 LLM 自由生成变成显式可比较的决策。
- **结果条件化更新**：首轮假设均匀加权；重测失败后由修复后归因生成 Ht+1 并按结果更新权重（同因同范围的假设跨轮对齐，无法对齐的视为新假设），使失败的重测成为下一轮修复的信号而非浪费。
- **系统实证**：在 ALFWorld 和 TextCraft 两个基准、三个模型规模共六个设置下全部取得最强最终成功率，并通过预算曲线、逐任务族分析与修复轨迹案例说明"归因只有与修复选择、持久化重测更新结合才产生持续收益"。

## Key Contributions

- Formalizes post-failure skill repair as **hypothesis-conditioned repair selection under environment feedback**, making explicit the repair credit-assignment problem that one-shot reflection handles implicitly.
- Introduces a **structured repair state**: weighted failure hypotheses, a four-source candidate patch pool (trace anchor / hypothesis anchor / targeted proposals / interface-preserving guards), a binary patch–hypothesis coverage matrix, and a history of attempted patches with retest outcomes.
- Proposes **coverage-based selection**: the patch maximizing covered hypothesis weight is applied; ties break toward more local, evidence-grounded edits. Patch generation (LM) is deliberately decoupled from the selection decision (explicit rule).
- Proposes **outcome-conditioned update**: failed retests trigger post-repair attribution that produces the next hypothesis set and re-weights it, so unsuccessful repairs redirect rather than repeat.
- Shows empirically that attribution alone is insufficient: across all six ALFWorld/TextCraft × model settings (frozen Qwen3-1.7B, Qwen2.5-3B, Qwen3-4B), RESKILL beats both Direct Repair (+3.7 pp average final success) and Hypothesis Repair (+3.3 pp) under fixed repair budgets.

## Methodology

The agent policy πθ(·|S) is a **frozen** LLM conditioned on an editable external skill set S; repair only modifies S, never weights. A full rollout produces trajectory τ⁰ and success y⁰; repair triggers only after a completed failed rollout. At each repair round t (bounded by budget R):

1. **Hypothesis state**: the LM converts the latest failed trajectory into a finite support of hypotheses Ht = {h₁,…,h_K}, each with an explanation, supporting trace evidence, affected skill scope, and a repair hint. Weights start uniform (ŵ₁(h)=1/|H₁|) and are updated from retest outcomes; hypotheses representing the same cause in the same scope are aligned across rounds, others are treated as new.
2. **Candidate pool**: Qt = Q^trace ∪ Q^hyp ∪ Q^prop ∪ Q^guard — a patch written from observed failure evidence, one written with access to Ht, extra targeted proposals covering different (possibly overlapping) hypotheses, and interface-preserving guard candidates for grounding/admissibility/format fixes. Candidates are screened for reusability beyond the episode, grounding in the trajectory, action-interface compatibility, and locality (no rewriting unrelated skills).
3. **Coverage-based selection**: the LM assigns binary Ct(q,h) = 1 only when patch q directly addresses cause h in the relevant scope; the selector computes covt(q) = Σ_h ŵt(h)Ct(q,h) and applies the argmax via a local Apply operator that inserts the patch into its target skill section.
4. **Retest and update**: the task is re-executed under St. Success stops repair; failure converts the post-repair trace into Ht+1 with outcome-conditioned weights (if no usable hypotheses emerge, the previous state is carried forward). Metric: cumulative Succ@r counts first-pass successes plus tasks recovered within r rounds.

**Setup**: ALFWorld (274 household tasks, 140 seen/134 unseen; families Pick/Look/Clean/Heat/Cool; initial skill file adapted from the SKILL0 substrate) with budget R7, and AgentGym TextCraft (exact-action crafting over visible recipe graphs, stratified by depth D1/D2; compact LLM-authored recipe-free skill file) with budget R4. Models are deliberately small open-weight (Qwen3-1.7B, Qwen2.5-3B, Qwen3-4B) because informative repair comparison needs a large residual failure pool. Baselines — No skills, With skills (unrepaired first pass), Direct Repair (one local patch per round from the trace), Hypothesis Repair (hypotheses first, then one patch; no pool, coverage matrix, or persistent state) — share task pools, first-pass trajectories, decoding configs, and budgets; appendix documents per-stage temperatures (e.g., hypothesis 0.2, coverage 0.1–0.0), context/action limits, and seed 0.

## Results & Highlights

- **Headline (all six settings)**: RESKILL achieves the strongest final cumulative success in every ALFWorld/TextCraft × {Qwen3-1.7B, Qwen2.5-3B, Qwen3-4B} setting, improving **average final success by +3.7 percentage points over Direct Repair and +3.3 points over Hypothesis Repair**.
- **ALFWorld, Qwen3-4B overall**: final success 95.6% (+14.9 over the with-skills first pass of 80.7%) vs Direct Repair 93.8% (+13.1) and Hypothesis Repair 93.4% (+12.7); the largest RESKILL gain in this setting is the Heat family, 89.1% vs 82.6% for both baselines (+6.5 over baselines, +15.2 over with-skills 73.9%).
- **TextCraft D1, Qwen2.5-3B**: RESKILL reaches **85.8% final success vs 50.7% for Direct Repair and 61.2% for Hypothesis Repair** — a +25.1 pp margin over the best baseline — starting from a 29.9% repair-pool (R0) first pass; the same model's D2 goes 4.9% → 15.6% (RESKILL) vs 9.4% (Direct).
- **Repair-budget dynamics, TextCraft Qwen2.5-3B**: all methods start from the same 9.9% first-pass success; after ONE repair round RESKILL is at **21.9% vs 14.3% (Direct) and 14.0% (Hypothesis)**, and the gap persists through R4 — direct/hypothesis curves flatten because their next prompt has no structured record of which explanation was tried.
- **ALFWorld, smallest model (Qwen3-1.7B) overall**: 33.2% (+16.4 over with-skills 16.8%) vs Direct 30.7% and Hypothesis 27.7%; the Look family shows the clearest attribution benefit, 58.1% vs 48.4% for both baselines.
- **Honest regime boundary**: Direct Repair still wins specific single-cause families — Qwen3-1.7B Heat (30.8% vs RESKILL 23.1%) and Qwen2.5-3B Clean (67.2% vs 58.6%) — consistent with the paper's claim that one-shot repair suffices when the trace localizes a single concrete edit, while RESKILL dominates when failure explanations are underdetermined.

## Authors & Credibility

The work comes from the Information Hub at HKUST (Guangzhou) and HKUST (Hong Kong), with Zhijiang Guo and Wei Wang as corresponding/co-senior authors — a group active in LLM-agent reasoning, uncertainty, and evaluation (the bibliography co-lists their prior work on uncertainty-aware clarification and tool-use agent training). The paper is transparent about scope choices (why only 1.7B–4B models: repair evaluation needs a large residual failure pool), shares first-pass trajectories, skill files, decoding settings, and budgets across all compared methods, and documents per-setting reproduction configuration (temperatures per repair stage, token caps, seed 0) in an appendix with per-budget success tables. Claims are stated with the qualifying regime analysis (where Direct wins and why), which lends credibility. This is an arXiv v1 preprint (14 Sep 2026, cs.CL), so it has not yet passed peer review.

## Critical Assessment

- **Novelty**: moderate-to-good. The individual pieces — failure hypotheses, candidate pools, coverage scoring, iterative retest — echo ideas from Reflexion/Self-Refine, credit-assignment literature, and abductive diagnosis; the contribution is the *composition* into an explicit, persistent repair state with a decoupled selection rule. The framing of repair as a credit-assignment problem over hypothesis coverage is the genuinely fresh part.
- **Rigor**: controlled and mostly fair — identical first-pass trajectories, budgets, and decoding across methods; the two baselines function as component ablations (Direct removes hypotheses; Hypothesis removes the pool/coverage/persistent state). However, there is **no fine-grained ablation isolating coverage-based selection from outcome-conditioned weight update from the multi-candidate pool**, so which component drives the +3.3 pp over Hypothesis Repair is not pinned down. The LM-assigned binary coverage matrix is never validated against ground truth (how accurate is C(q,h)?), and hypothesis alignment across rounds is heuristic.
- **Reproducibility**: strong on paper — frozen open-weight models, seed 0, per-stage sampling parameters, and per-budget tables in the appendix; no code release is mentioned in the main text, so full replication still requires reimplementing the prompt suite.
- **Significance**: gains over Hypothesis Repair are real but modest in several settings (e.g., Qwen2.5-3B TextCraft D2: 15.6% vs 14.2%), and several ALFWorld family columns flip to Direct Repair (Qwen3-1.7B Heat 30.8% vs 23.1%; Qwen2.5-3B Clean 67.2% vs 58.6%). The average +3.3/+3.7 pp hides this heterogeneity, though the paper itself openly discusses it. Compute accounting is missing: RESKILL makes substantially more LM calls per round (pool generation, coverage annotation, post-repair attribution) than the single-patch baselines, and this cost asymmetry under a fixed *retest* budget is not reported.
- **Red flags**: only two text-based, short-horizon benchmarks (ALFWorld, TextCraft with visible recipe graphs); the deliberate exclusion of frontier/larger models (justified by ceiling effects) means external validity for the models practitioners actually deploy is untested; the cumulative Succ@r metric blends first-pass skill quality with repair ability, slightly inflating absolute numbers relative to "recovered-failure" rates.

## Strengths

- Clean conceptual decomposition: generation (LM proposes patches and coverage) is separated from decision (explicit weighted-coverage selection rule), making repair choices inspectable and auditable from the recorded state.
- Principled handling of ambiguity: multiple weighted hypotheses plus a coverage matrix directly address the credit-assignment problem that one-shot reflection ignores; failed retests systematically redirect later edits instead of triggering another unconstrained rewrite.
- Well-controlled comparison: shared failure pools, frozen models, matched retest budgets, and baselines designed as stepwise ablations; per-budget curves (Fig. 2) show *when* each approach wins, not just final numbers.
- Honest regime analysis: the paper explicitly identifies where Direct Repair is stronger (single-cause failures, e.g., specific Heat/Clean families) rather than claiming universal dominance.
- Practical takeaway: repair strategy can be chosen by inspecting budget curves and failure ambiguity, and repairs stay local/reusable rather than overwriting unrelated skills.

## Limitations

- Evaluated only in interactive environments with immediate, observable action feedback and matched retest budgets; delayed feedback, noisy failure signals, and long-horizon cross-episode effects of skill edits are left to future work (acknowledged by the authors).
- Model scale capped at 4B and benchmarks limited to ALFWorld/TextCraft; no web, OS, or API tool-use settings, and no evidence the gains transfer to frontier-scale models where failure pools are smaller and failure modes differ.
- Component-level attribution is coarse: no ablation separating the candidate pool, the coverage-based selector, and the outcome-conditioned update; coverage-matrix reliability and hypothesis-alignment accuracy are unmeasured.
- Extra per-round LM calls (pool + coverage + attribution) increase latency and token cost versus one-shot baselines, and this is not quantified.
- Cumulative success conflates initial skill quality with repair efficacy; reported percentages should not be read as repair-only recovery rates.

## Relevance

本文直接切中"LLM 智能体自我改进 / 技能自我演化"这一核心方向：它把 Reflexion 式一次性反思升级为带显式失败归因、覆盖打分与重测反馈的结构化修复闭环，对构建可持久演进技能库的 agent 系统很有参考价值。其"假设—补丁—覆盖矩阵—结果更新"的框架也可迁移到工具调用、代码修复等需要诊断多因失败的自我改进场景。

## Questions for Further Exploration

- How accurate is the LM-assigned coverage matrix C(q,h) against ground-truth failure causes, and would replacing binary coverage with calibrated probabilities or learned scorers improve selection?
- Which component — the multi-candidate pool, coverage-based selection, or outcome-conditioned re-weighting — contributes most to the +3.3 pp over Hypothesis Repair, and does the ordering change with model scale?
- Do the gains persist with frontier-scale models (where residual failure pools are smaller and failures more compositional) or in settings with delayed/noisy feedback such as web agents or API tool use?
- Do repaired skills generalize to unseen tasks and remain stable over long horizons (skill-file bloat, conflicting patches, catastrophic skill drift), rather than just recovering the triggering task?
- Can the repair state be shared across tasks within a round (batch attribution) to amortize the extra LM calls, and what is the token-cost per recovered task versus Direct Repair?
