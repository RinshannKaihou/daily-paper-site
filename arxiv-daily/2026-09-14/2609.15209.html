Key metric

+16.52 pts

8-benchmark aggregate, unoptimized baseline 55.66% → 72.18% (task model Qwen3.5-35B-A3B). Still +4.92 pts over the strongest APO baseline, Ace at 67.26%.

Why this matters

A failure-driven loop that lets frozen-weight LM programs improve themselves — directly informing the design of self-evolving agents and automated research loops.

让 LM 程序在不更新权重的前提下自我改进；其失败记忆与自动验证合成机制，对自进化智能体与自动化研究循环的设计有直接参考价值。

Critical edge

Compute is matched on task-program evaluations, not total optimizer cost — Forge runs four extra optimizer-side agents per step, reports no token or dollar accounting, and is single-seed throughout, so part of the +4.92-pt margin may simply be extra optimizer compute.

▸ Read this paper critically

Authors & credibility — 26 pages · verbatim prompts for all four optimizer-side agents (assigner, reflector, generator, verifier) · explicit seeds & split sizes · budget-alignment protocol across optimizers · full GRPO configuration · data-leakage audit (two-stage AI + 10% manual: clean).

Methodology — the loop, distilled

↓  ↓↓  ↓

Prompt branch

Gepa-style reflective search. A reflector rewrites one module's system prompt from failed traces; a proposal must beat its parent on the same minibatch, then faces the fixed validation set. Parent selection is Pareto-frontier-based.

Data branch

Failure-guided synthesis, triggered after p stagnant steps. Active failure modes get budgets (largest-remainder); a tool-grounded generator creates instances; an independent verifier checks validity + faithfulness. Dual-pass only → append.

Training data becomes a mutable, append-only optimization state coupled to prompt search — a strict generalization of fixed-data APO. Validation objective and test protocol stay untouched. Gold supervision is grounded in benchmark tools (e.g., the same full-Wikipedia ColBERT index the task program uses), not optimizer parametric memory.

positivekeep the target skill under benign change — new entities, same canonical-answer form
negativecontrast: a sibling case where the repair strategy must not fire
boundaryprobe conditions near the decision boundary — flip the requested name type
stressrobustness: inject distractors and interaction constraints

Worked example (HotPotQA): the program answered "Michael J. Fox" where gold was "Michael Andrew Fox" — each intent mutates this one failure along a different generalization axis (stress adds articles on other people named “Prince”).

Honest losses — IFBench trails Ace 54.52 vs 61.63 (−7.11); MMLU-Pro trails MiproV2/Gepa 89.00 vs 90.00 (−1.00). Random synthesis actively hurts (−1.79), isolating the value of failure guidance.

Strengths

  • Clean formalization: adaptive-data APO strictly generalizes fixed-data APO, with an append-only update that leaves validation/test protocol untouched.
  • Failure memory attacks near-duplicate synthesis head-on — separating reusable mechanism from exposing instance; the AppWorld example shows cross-task mode reuse.
  • Principled mutation taxonomy: each intent targets a distinct generalization axis (invariance, contrast, boundary, robustness) rather than surface diversity.
  • Tool-grounded generation + dual-gate verification anchors gold supervision in retrievable evidence, not parametric memory.
  • Unusually broad evidence: 8 benchmarks, 2 task architectures, 2 optimizer models, 12/12 transfer pairs + GRPO, and a random-synthesis negative control.

Limitations

  • Single seed, no error bars or significance tests; several test sets are small (≤100 examples; AIME-2025 has 30), making fine-grained per-benchmark claims fragile.
  • Optimizer-side compute neither equated nor reported — the heavier multi-agent pipeline may explain part of the margin.
  • Transfer study is narrow: 3 benchmarks, 1 task model; authors themselves call for broader coverage.
  • Cumulative-only ablation leaves memory × mutation interactions unmeasured; assigner/verifier error rates unquantified.
  • Append-only growth raises long-run cost and distribution-imbalance risk — acknowledged but unresolved.

Questions for further exploration

Q1Does the +4.92 margin survive when optimizers are matched on total optimizer-LLM tokens or dollar cost?
Q2Which mutation intent carries the gains? A factorial ablation would show whether stress/boundary pull weight or mostly positive variants matter.
Q3How reliable is the verifier's validity/faithfulness gate against human labels — and what is its false-admission rate downstream?
Q4Does failure memory transfer across task models or related benchmarks, enabling cross-task mode libraries?
Q5Can the loop extend to open-ended generation tasks lacking verifiable metrics or benchmark tools?
Q6Would balanced sampling or curriculum ordering over admitted instances change the rebalancing dynamics (11:1→4:1) and final scores?
