01Methodology — a two-stage adversarial funnel

SoL-Pi organizes harness research as a funnel. The outer stage mines execution trajectories of the base Pi harness with map–reduce analyzers, yielding 152 hypothesis directions across six proposal families — each must name a concrete overhead source and a harness change that addresses it. The inner stage develops each direction as an isolated, disposable lineage running propose → implement → fixed experiment → retain/discard, extended with a Ralph-Loop-style reviewer that gates each candidate against an explicit completion criterion.

Acceptance is deliberately adversarial to overfitting. Capability metrics and tolerances are frozen before experimentation and isolated from the optimizing agent; candidates pass two sequential gates (capability within tolerance + at least one efficiency metric improved), and only Pareto-nondominated candidates survive. EdgeBench stays fully held out — 11 tasks for one-way acceptance of already-frozen candidates, 40 for final generalization. A failed validation rejects the candidate outright; it never feeds back into search.

Four surviving mechanisms

  1. Action Fusionedit + follow-up test/build/run merged into one tool call — 3 API calls → 2.
  2. Online Context Compactgated compaction at plan-step boundaries: fires only when projected savings beat the cache-rewrite cost.
  3. ObservationPackobservations >10 KiB archived locally; full text for 2 requests, then a ~1 KB head/tail excerpt + stable handle, retrieved on demand.
  4. Evidence-Preserving Reducerlogs ≥4 KiB distilled into receipts by a cheap model, deterministically verified (schema, hash, exit code, exact quotes); any doubt → fall back to the original.

Secondary findings

  • Terminal-Bench 4 (63 tasks): solves 15 vs 18 for Pi/Codex — a real capability cost — but total model cost −26.3% ($211 vs $286).
  • IMO 2026 (Lean 4-verified): 3/6 passed at $20.90 / problem — cheapest per pass (Codex 5/6 at $22.89; Pi 3/6 at $25.32).
  • 20-worker kernel swarm (2h budget): 1,127 cycles at $60 vs 1,366 at $82 (−26.8% cost), passes 8/8 official speed thresholds (Pi: 7/8). A single Codex agent is still cheaper ($39.20).
  • Per-mechanism ablation: every mechanism cuts tokens on both backends; Online Context Compact alone −40.2%. Cache-read traffic halves (2.13B → 1.06B) while cache-write doubles — total cost still falls.
  • Action Fusion lineage: 27 recorded iterations; 100% trigger rate, 0 invalid calls, −11.5% tokens (3.74M) under full triggering.
  • Best single point: Action Fusion on Opus 5 actually raises score +12.8% to 50.48.

03Strengths

  • Four orthogonal mechanisms — action execution, compaction, observation storage, delegated reading — each with a precise trigger and a safe fallback path.
  • Exemplary evaluation hygiene for auto-research: pre-registered tolerances isolated from the optimizer, frozen acceptance rules, held-out benchmark, reject-without-patching.
  • Evidence-Preserving Reducer is a template for safe LLM compression in agent loops: deterministic verification with fallback to the original log.
  • Honest cache accounting: cache-read halved, cache-write doubled, total cost still down 33% — reported rather than hidden.

04Limitations

  • Capability cost undersold in the abstract: Terminal-Bench 4 15/63 vs Pi's 18/63; IMO 3/6 below Codex's 5/6.
  • Single-run point estimates everywhere — no seeds, variance, or significance testing, even on the 40-task generalization set.
  • Single-backend search: trigger rates drop from 39–92% (GPT-5.6 Sol) to 10–36% on Opus 5; only two backends tested.
  • Not independently reproducible: 535 environments and orchestration unreleased; the scaling claim rests on one run of the funnel, with no breadth/depth ablations.

05Open questions for further exploration

  1. Do the mechanisms compose on harnesses other than Pi (OpenHands, SWE-agent-style ACIs), or is the gains profile an artifact of Pi's minimal loop?
  2. How much of the −49% traffic reduction survives non-code domains — data analysis, web agents, scientific pipelines — where observation distributions differ?
  3. Can the search itself be made backend-diverse cheaply (e.g., interleaving Opus-5 trajectories) to close the held-out trigger-rate gap?
  4. What is the funnel's marginal yield curve — environments 535 → 5,000, directions 152 → 1,000 — under a fixed compute budget?
  5. Since a single agent beat both swarms on cost in the kernel run, when does the SoL-Pi swarm actually dominate in cost-adjusted verified progress?
