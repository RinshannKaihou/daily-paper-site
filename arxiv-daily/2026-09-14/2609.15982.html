01 Methodology · distilled

Read the router out of the forward pass

Two trained linear projections on frozen Qwen3-32B; everything else untouched.

Glance — full-library coarse rank

A grafted attention head reads the mid-layer at the matrix-entropy floor (~70% depth, layer 44): Wq maps task-token states, Ws maps skill-token states to key banks built in one installation forward pass (zero training per new skill). Trained contrastively (InfoNCE, τ=40) on 51,104 SkillRet queries over 9,084 skills — gradients stop at the hidden states. Each token votes for its top-k skills by max-similarity, recency-decayed mid-rollout. Banks are thinned to ε-covers: ~8.5× smaller, with Proposition 1 bounding distortion (scores drop ≤ ε, never inflate).

Verdict — shortlist re-rank (~9 candidates)

Within margin Δ=0.133 of the glance's best, the skill render is continued with the task appended. One causal forward pass yields L (mean task log-likelihood, generative) and V (yes/no log-odds, discriminative).

Ruling — product of experts

g, L, V each estimate the same log posterior — contrastively, generatively, discriminatively — so they fuse as a product of experts; any single expert can veto.

S = g + αL + γV  ·  (α, γ) = (1.0, 0.025)
Why graft at all? Native read-outs fail first: the best of 24 native attention-key configs reaches Hit@1 .001 vs .918 for the trained head — the signal exists natively, but one to two orders of magnitude too faint (Appendix A). Rebuilt end-to-end on Gemma-4-31B; the shape survives (Appendix E).

  • Glance alone is the strongest retrieval stage — R@20 .9675 vs Qwen3-Emb-8B's .9117 on SRA-Bench; routing accuracy climbs monotonically from a 0.6B to a 32B backbone and across Qwen generations.
  • Ablations isolate the win — swapping the glance for Jina-ColBERT-v2 loses everywhere (raw .5968 vs .8459 on SkillRet); verdict-only pointwise rerank collapses to .4068; dropping one verdict signal costs 1.9–4.6 points; ε-cover compression costs ≤1.6 for 8.5× smaller banks.
  • Cost — ~$0.080 per gate firing (nine ~2.2K-token verdict prefills), independent of library size; cheaper than progressive disclosure once the library exceeds ~2000·m/T skills, and verdict forwards never touch the rollout's context window.
03 · What holds up

Strengths

  • Solves the trilemma — clean context, no external model, no per-skill training — with 7.9M parameters and four scalars, transferred zero-shot to every other library.
  • Compression with guarantees — the ε-cover scheme ships proved distortion and bank-size bounds (covering/packing numbers), rare rigor in retrieval engineering.
  • Insightful negatives — native keys carry the signal but too faintly (.001 vs .918), precisely motivating trained projections; retrieval-token failure is attributed to data, not the idea.
  • Off-path by design — verdict prefills keep the rollout context untouched, skill prefixes are KV-cacheable, and a concrete cost model backs it (Appendix J).
  • Diagnostic benchmark — SkillTraj's four scenarios isolate exactly where mid-rollout routing is hard (tool evidence, agent plan).
04 · Read with care

Limitations

  • Needs white-box access to mid-layer hidden states; behind a cloud API the provider must host the router (Appendix K) — speculative.
  • Verdict overhead — ~9 prefills (~$0.08) per firing; the gate's false-positive rate multiplies this, and the gate was trained on only 372 trajectories.
  • Hand-crafted recency decay — the learned alternative failed for data reasons and is left to future work.
  • Fixed (α, γ) is a compromise — the likelihood L helps three benchmarks but slightly hurts both Eval-Core pools.
  • LLM-judge dependent — scoring and SkillTraj admission both rest on judges; human checks cover only 200 pairs (86% agreement).
  • Single-skill commits only — routing multiple skills per task, and tools/memories/MCP servers, remain open.
05 Open questions · for further exploration
  1. Does the same two-projection read-out route tools, memories, or MCP servers — and does the entropy-floor layer choice transfer to sparser-signature domains?
  2. How does the glance scale to 10⁵+ skill libraries — does the ε-cover sweep stay millisecond-scale, does k=0.1N voting saturate?
  3. Can the hand-crafted recency decay become learned aggregation once trained on data that rewards selectivity?
  4. Would the gate fire reliably on real rollouts (actual SWE-agent sessions), where skill needs arise less cleanly than in simulated trajectories?
  5. Is the product-of-experts fusion robust when the verdict's signals disagree systematically (as on Eval-Core) — per-domain calibration, an abstention head?
  6. Do mid-layer states at the compression-valley floor stay linearly readable under INT8/INT4 quantization?
