> **一句话总结：** 提出 ModularRSI，通过"对比式轨迹分析 + 五模块独立进化 + 验证门"把 CLI agent 的 harness 自我改进从粗糙的任务级奖赏转化为局部化、可泛化的模块级修改信号，并在与评测基准完全不相交的 2000 个自建进化任务上演化；冻结后的 harness 在 TerminalBench 2.0 上把准确率从 47.57 提升到 52.43（Pass3 从 30.34 升至 35.96），在 SWE-Bench Verified 上从 73.40 升至 76.45，且能跨任务域、跨底层模型迁移，而整-harness 联合进化反而把准确率拉低到 44.19（低于 47.57 的基线）。

> **TL;DR:** A harness-RSI framework that decomposes a CLI agent's harness into five independently evolvable modules (Agent Loop, Tool Use, Observation Management, Context Management, Task Completion Detection), evolves them via contrastive analysis of success/failure trajectory pairs on a 2,000-task benchmark-disjoint evolution set, then merges them with conflict resolution. Against a no-evolution baseline on TerminalBench 2.0 (DeepSeek-V4-Flash backbone) it lifts accuracy 47.57 → 52.43 (+4.86) and Pass3 30.34 → 35.96; on SWE-Bench Verified 73.40 → 76.45; the frozen harness also transfers cross-domain (TB-evolved → 75.80 on SWE-Bench Verified) and cross-model (GLM-5.2: 59.55 → 61.80 on TB 2.0). Notably, joint whole-harness evolution drops TB 2.0 accuracy to 44.19 — below baseline — while modular evolution is the only strategy that clearly beats it, and it outperforms adapted AHE (62.54) and Meta-Harness (62.92) at 67.42 under the same benchmark-disjoint budget.

## 核心贡献

- **模块化 harness 进化框架**：将 CLI agent 的 harness 行为机制分解为五个功能模块（Agent Loop、Tool Use、Observation Management、Context Management、Task Completion Detection），每个模块在受限修改范围内独立进化（可并行），再通过跨模块整合阶段合并、消除冲突——把单体的 credit-assignment 问题拆解为五个小的局部问题。
- **对比式轨迹分析**：对同一任务的成功/失败轨迹配对比较，并用 Trajectory Memory 跨 epoch 补充历史证据，把粗糙的任务级成败信号转化为函数级（function-level）的 harness 缺陷诊断，剥离任务特有的推理细节；负面组可查历史成功轨迹配对，正面组则分析冗余动作以提升效率。
- **基准不相交的进化协议与 2000 个进化任务数据集**：从 GitHub、Hugging Face、Kaggle、Linux 内核文档等外部来源人工构建 1000 个 Terminal 相关 + 1000 个 SWE 相关的可执行任务（Harbor 格式），经环境完整性/实用性/评测器有效性三重 LLM 过滤、可执行验证（参考解须过测试、空操作不得得分）、人工复审和与下游基准的语义相似度筛查，首次让"泛化性 harness RSI"可以被干净地评测。
- **验证门与函数库管理**：程序静态检查（AST/导入/协议合规）+ LLM Diff Review 拒绝任务特定的过拟合修改 + 随机抽样任务的实际执行验证，配合 Function Merge 去冗余和 Task-Aware Function Composition 按任务激活相关函数，保证进化产物可执行且库规模可控。
- **全面的泛化实证**：在 TerminalBench 2.0 与 SWE-Bench Verified 上验证了域内、跨域（TB↔SWE）、跨模型（DeepSeek/GLM/MiniMax）三类迁移，并用消融证明模块化独立进化显著优于联合进化与非模块化进化。

## Key Contributions

- **Modular harness evolution**: decomposes the harness's behavioral mechanisms into five functional modules (Agent Loop, Tool Use, Observation Management, Context Management, Task Completion Detection), each evolved independently within a restricted modification scope, then combined via a cross-module integration epoch that resolves duplicates and conflicts — turning one monolithic credit-assignment problem into five localized ones.
- **Contrastive trajectory analysis**: pairs successful and failed trajectories of the *same* task (supplemented by a cross-epoch Trajectory Memory) to isolate function-level harness deficiencies from task-specific reasoning; all-fail groups get single-sided diagnosis of execution pathologies (repetitive loops, wrong tool usage, premature termination), all-success groups get efficiency analysis.
- **Benchmark-disjoint evolution protocol + 2,000-task dataset**: 1,000 terminal-related and 1,000 SWE-related executable Harbor-format tasks curated from GitHub/HF/Kaggle/kernel docs (downstream benchmarks contribute only high-level domain guidance for retrieval), passed through LLM filtering (environment completeness, practicality, evaluator validity), executable validation (reference `solution.sh` must pass; no-op must fail), manual review, and LLM semantic-similarity screening against downstream benchmarks.
- **Validation gates + function library management**: static program checks (AST, imports, protocol compliance, discovery contract), an LLM Diff Review that rejects task-specific modifications, and execution validation on sampled tasks; Function Merge prunes redundancy while Task-Aware Function Composition activates only task-relevant functions per task.
- **Comprehensive generalization evidence**: consistent gains on unseen in-domain, cross-domain (TB↔SWE), and cross-model (DeepSeek → GLM-5.2 / MiniMax-2.5) evaluations, plus ablations showing modular evolution beats joint and non-modular evolution, which fall below baseline.

## Methodology

ModularRSI converts coarse task-level rewards into localized harness-modification signals through three stages:

1. **Contrastive Trajectory Sampling and Analysis.** For each evolution task, rollouts are grouped by reward evidence into a Contrastive group (both successes and failures), a Negative group (all fail), and a Positive group (all succeed). Same-task success/failure pairs are compared to find function-level factors correlated with outcome; the Negative group first queries a Trajectory Memory of prior epochs for a historical success to pair against, falling back to single-sided diagnosis; the Positive group is mined for efficiency improvements (redundant actions, unnecessary tool calls). The agent under evolution itself acts as the **Code-Modify Agent**, consolidating per-batch diagnoses into structured JSON findings (module, evidence, rationale, proposed change).

2. **Module-wise Harness Evolution.** Semantically similar diagnoses targeting the same function are consolidated into candidate modifications, each voted by the number of *distinct tasks* supporting it (favoring cross-task evidence over instance-specific failures). An Evolution History per function exposes prior diffs so new edits preserve earlier improvements and avoid oscillation. The five modules are evolved independently (in parallel, no shared intermediate updates), each for 3 epochs.

3. **Validation Gates and Integration.** Every function update must pass (i) static program checks (AST validation, import checks, protocol compliance, discovery-contract verification, self-attribute audits) with diff-based rollback; (ii) an LLM Diff Review rejecting task-specific heuristics; and (iii) execution validation on two randomly sampled batch tasks. After all modules finish, a **cross-module integration epoch** runs the combined harness, detects inter-module conflicts/duplication, and refines coordination; the resulting function library is **frozen** before evaluation. Function Merge keeps the library compact and Task-Aware Function Composition selects a task-relevant subset per task.

**Evolution setup.** Only 120 TB-related + 120 SWE-related instances (of the 2,000 curated) are sampled for evolution, for 3 epochs each, using DeepSeek-V4-Flash-Preview / -0731 as both evolving and (mostly) inference backbone, under the Harbor framework with 2M TPM and batch size 10. Evaluation uses Acc, Pass@3, Pass3 (all-3-consistent success), and average StepNum on TerminalBench 2.0 (89 tasks) and SWE-Bench Verified (500 tasks).

## Results & Highlights

- **In-domain gains (DeepSeek-V4-Flash-Preview backbone):** on TerminalBench 2.0, the evolved harness improves Acc from 47.57 (no-evolution baseline) to 52.43 (+4.86), Pass@3 from 58.43 to 65.17, and Pass3 from 30.34 to 35.96; on SWE-Bench Verified, Acc improves from 73.40 to 76.45 (+3.05), Pass@3 from 83.20 to 85.30, Pass3 from 62.80 to 66.80.
- **Cross-domain transfer:** the harness evolved only on TB-related data lifts SWE-Bench Verified Acc to 75.80 (+2.40 over the 73.40 baseline), and the SWE-evolved harness lifts TerminalBench 2.0 Acc to 49.40 (+1.83), showing improvements are mechanism-level rather than benchmark-specific.
- **Cross-model transfer (frozen TB-evolved harness, TerminalBench 2.0):** GLM-5.2 Acc 59.55 → 61.80 and Pass3 46.07 → 49.44; MiniMax-2.5 Acc 41.57 → 44.94 with Pass3 24.72 → 30.34 (+5.62), alongside the original DeepSeek-V4-Flash 47.57 → 52.43 — consistent gains on every backbone tested.
- **Modularity is load-bearing (ablation, TB 2.0):** ModularRSI reaches 52.43 Acc, whereas Joint All-Module Evolution drops to 44.19 and Non-modular Evolution to 46.44 — both *below* the 47.57 baseline — while ModularRSI also achieves the best Pass3 (35.96 vs 24.72 for both alternatives).
- **Per-module contributions:** every single-module variant beats baseline (Acc 49.44–50.56); Agent Loop gives the largest single-module accuracy gain (50.56), while Observation Management alone cuts average steps from 34.70 to 22.50 (−35%), and integration composes them to 52.43.
- **Against existing RSI methods under the benchmark-disjoint protocol (DeepSeek-V4-Flash-0731, Terminus-2 harness, 16 evolution epochs for baselines to match budget):** ModularRSI scores 67.42 Acc / 78.65 Pass@3 / 56.18 Pass3 on TB 2.0 vs Meta-Harness 62.92, AHE 62.54, and baseline 61.79 — a >5-point margin while prior methods gain only ~1 point over baseline off-benchmark.
- **Evolution-data quality matters:** a Medium-centered difficulty distribution reaches 76.45% on SWE-Bench Verified vs 74.25% for a Hard-&-Easy mix (+2.20 pp), supporting the hypothesis that informative success/failure contrasts drive generalizable evolution; the usable contrastive-pair ratio declines by 7.50 percentage points across the three epochs (36.67% at epoch 1), consistent with recurring weaknesses being progressively fixed.

## Authors & Credibility

A 14-author team spanning Beihang University, University of Manchester, IQuest Research, M-A-P, Langboat, and Hohai University, led by Siwei Wu (Manchester/IQuest) and Jincheng Ren (M-A-P/Hohai), with senior oversight from Chenghua Lin and Jian Yang — the same group behind terminal-agent trajectory generation (ICML 2026), TACO observational context compression, and IQuest-Coder. The work is methodologically self-aware: it cites and contrasts eleven concurrent harness-evolution systems in a positioning table, adapts two of the strongest (AHE, Meta-Harness) under a unified protocol rather than quoting their numbers, disables web search for all methods to prevent solution leakage, and releases code plus the 2,000-task evolution dataset at github.com/IQuestLab/ModularRSI. Framing is honest — limitations (missing contrastive-analysis ablation, subset-only use of the curated data) are stated by the authors themselves.

## Critical Assessment

- **Novelty**: The individual ingredients — modular decomposition, contrastive success/failure analysis, localized diagnosis — each have close relatives in concurrent work (HarnessFix does localized diagnosis; TACO evolves observation compression; Meta-Harness does end-to-end harness optimization). The genuine novelty is the *combination* plus the benchmark-disjoint protocol, which is the first clean answer to "is harness RSI learning anything transferable?" — most competitors evolve on the very benchmarks they report on.
- **Rigor**: The modular ablation (joint evolution 44.19 < baseline 47.57 < modular 52.43) and the cross-domain/cross-model transfer tables are exactly the right experiments, and the AHE/Meta-Harness comparison controls evolution budget (16 epochs) and backbone. However, no variance or significance tests are reported anywhere, and TerminalBench 2.0 has only 89 tasks — a +4.86 Acc delta is roughly 4–5 tasks, within plausible run-to-run noise; the 3-rollout averaging helps but is not a substitute for reported error bars.
- **Reproducibility**: Good — public code and dataset, named models, TPM/batch/epoch settings, frozen-harness protocol. Weak points: only 240 of the 2,000 evolution instances are used (selection procedure for the 120+120 sample is not fully specified), and the baseline comparison re-implements AHE and Meta-Harness in Harbor, which may disadvantage methods designed around their own harnesses and data assumptions.
- **Significance**: The headline OOD deltas are modest (SWE-evolved → TB 2.0 is +1.83 Acc with Pass3 unchanged at 30.34, identical to baseline), so cross-domain transfer is demonstrated more convincingly in the TB→SWE direction than SWE→TB. Still, the negative result that whole-harness evolution underperforms no evolution is valuable for the field.
- **Red flags**: (i) The Diff Review gate uses the same LLM family that proposes edits to judge overfitting — a circularity risk with no human audit of retained diffs reported; (ii) execution validation samples only 2 tasks per modification, a thin regression guard; (iii) evolution compute cost is never quantified (no token/FLOP/dollar accounting despite acknowledging "computational and time constraints"), so the cost-per-point of harness RSI vs simply prompting better is unknown; (iv) the paper's own admission that no ablation isolates contrastive analysis means its titular mechanism is supported only by case studies and the declining-pair-ratio trend.

## Strengths

- Directly attacks the most important confound in harness RSI — benchmark contamination during evolution — with a curated, released, 2,000-task disjoint dataset and a frozen-harness evaluation protocol.
- The modular credit-assignment design is validated by a decisive ablation: it is the only evolution strategy that beats baseline, while joint/non-modular evolution actively hurt.
- Strong external validity: cross-benchmark (TB↔SWE) and cross-backbone (DeepSeek/GLM/MiniMax) transfer both hold, which is rare evidence that harness improvements are mechanism-level.
- Practical engineering detail: validation gates with diff-based rollback, Evolution History against oscillation, Function Merge, and task-aware function composition make the system deployable, not just a paper artifact.
- Complementary module analysis (Agent Loop → accuracy; Observation Management → −35% steps) gives actionable insight for harness designers.

## Limitations

- No ablation isolating the contribution of contrastive trajectory analysis (acknowledged by the authors); its causal role is inferred from case studies and an indirect trend.
- Only 240 of 2,000 curated instances are used for evolution due to compute constraints, so scaling behavior of harness evolution remains untested.
- OOD transfer is asymmetric and modest: SWE→TB yields +1.83 Acc and a 0.00 delta on Pass3 (30.34 vs 30.34); TerminalBench 2.0's 89 tasks make all TB deltas statistically fragile, and no significance testing is reported.
- The comparison against AHE and Meta-Harness relies on the authors' own re-adaptations under a protocol (benchmark-disjoint, Harbor, no web search) those methods were not designed for.
- Self-review circularity in the Diff Review gate and a 2-task execution-validation sample leave residual overfitting and regression risk; evolution cost is unreported.

## Relevance

直接命中"Self-Evolving Agents"这一最高优先级方向：这是对 harness 级递归自我改进（RSI）如何泛化这一核心问题的系统研究，其基准不相交进化协议、模块化 credit-assignment 和跨模型迁移证据，对构建可靠的自进化 agent 系统具有直接方法论价值。

## Questions for Further Exploration

- How do the gains scale with evolution data — does using all 2,000 tasks (vs the 240 sampled) push TerminalBench 2.0 beyond 52.43, or does harness evolution saturate quickly?
- Would an explicit ablation with non-contrastive (failure-only or single-sided) analysis on identical modules reproduce the gap, finally isolating the causal contribution of contrastive pairing?
- Do the evolved modules remain beneficial as backbone models improve (e.g., on DeepSeek-V4-Flash-0731 the baseline was already 61.79 — much higher than on -Preview), or do stronger models obviate specific harness mechanisms like Observation Management compression?
- Can the Diff Review overfitting gate be replaced or augmented with a held-out-task regression suite larger than the current 2-task execution check, and would that change which modifications survive?
- What is the amortized cost (tokens, GPU-hours, dollars) of modular harness evolution relative to the accuracy gained, compared with spending the same budget on prompt optimization or model fine-tuning (e.g., GEPA-style or RL)?
- Since joint whole-harness evolution degraded below baseline, is there an intermediate granularity (e.g., 2–3 co-evolved module clusters) that trades off credit assignment against cross-module coupling better than full independence?
