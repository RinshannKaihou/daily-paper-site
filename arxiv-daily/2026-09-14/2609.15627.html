A2 Why this matters

A rare first-hand record of running FP4/FP8 MoE inference on non-NVIDIA hardware — reusable kernel fixes and strict measurement discipline for AMD CDNA2 deployers.

对在非 NVIDIA 硬件上部署超大规模 MoE 模型的推理系统工程直接相关：完整落地路径 + 大量可复用的内核级经验，也示范了严格的性能测量方法论。

A3 Critical edge

Correctness validation is bounded — fixed-token oracles, hash checks, string-level integrity only; no accuracy benchmark, no long-context quality evaluation.

All baselines are the author’s own earlier configurations: no vLLM, no NVIDIA comparison — so no cross-platform claims are possible.

— Limitations / Critical Assessment

The centerpiece fix

The CKTile FP4 expert W2 output permutation wrote each 128-wide N tile in 16-row blocks mapped [0,2,4,6,1,3,5,7] — leaving stage-2 cosine similarity at ~0.24 while stage-1 already scored 0.999996. Applying the inverse permutation [0,4,1,5,2,6,3,7] to raw weights at load time restored correct output for top-k=1 and top-k=6, with zero decode hot-path cost.

01 Methodology

One host, eight GCDs, everything gated by oracles

A single Supermicro host — dual EPYC 7763, 1 TiB DDR4, four dual-GCD MI250 accelerators (eight gfx90a GCDs, ~64 GiB HBM each) — runs one TP8/EP1 SGLang instance over PyTorch 2.12, Triton 3.7.1, AIter, Composable Kernel, and custom HIP kernels. The mixed FP4/FP8 checkpoint is kept unmodified; a one-time load-time W2 permutation is the only weight transform.

Because CDNA2 has no native FP4 matrix core, the engineering targets small-M utilization, online unpacking, scale handling, and layer-level sync rather than raw HBM bandwidth.

Every step is gated: correctness against a fixed-token “France” oracle (hash 6f41fe2f01d52507) under a kernel → layer → model hierarchy, then optimizations admitted only after component equality plus an A1→B1→B2→A2 ABBA screen with independently restarted controls. Formal numbers are three-round medians over ≥30 s resident windows; prefill uses ~8K-token prompts with fresh cache salts.

03 Strengths

What holds up

  • Caught silent numerical corruption (W2 permutation, E8M0 layout, attention-sink rank mapping) before it poisoned benchmarks — invalidated its own early 60 tok/s claim rather than hiding it.
  • Kernel work grounded in the real CDNA2 constraint set: no FP4 matrix core, wave64, 64 KiB LDS, small-M decode regime.
  • Best-in-class measurement discipline: resident vs HTTP boundaries, ABBA controls, medians with outliers retained, evidence-class taxonomy.
  • Publishes negative results and rejected directions — rare and valuable for practitioners.
  • Complete provenance: checkpoint commits, SHA256-hashed evidence archive (278 formal + 92 pilot files).
04 Limitations

What doesn’t

  • Correctness rests on a single trivial QA sentinel; 2/16 of 16K C16 rounds changed their first token — a flagged but unresolved crack.
  • The 1,048,576-token KV pool is allocated but never filled or certified; memory ceiling only sampled (83.55%).
  • All baselines internal; no matched TP4-vs-TP8 matrix, so scaling efficiency is unquantified.
  • Historical vs current measurement boundaries shift — old figures can’t be read as regressions of new ones.
  • Cold-shape compilation: >20 s first request (~23.1 s of JIT across four builds).
  • Single-author, single-node, dirty-tree local modifications to SGLang/AIter/CK.
05 Questions for further exploration
  1. How does TP8 native-AR compare against an equivalent-class NVIDIA deployment (H100/B200, same FP4/FP8 checkpoint, same corpus)?
  2. Can the W2 permutation and E8M0 scale-layout issues become upstream conformance tests in AIter / Composable Kernel?
  3. What happens at a genuinely filled ~1M-token context — does sparse attention + mHC hold up, and where does the 83.55% memory ceiling break?
  4. Would the DSpark +5–6% survive a fresh matched experiment under the Sep 18 protocol, and does the C32 down-consumer’s +1.54% generalize?
  5. Can cold-shape compilation (>20 s first request) be eliminated via shape-key pre-warming or AOT coverage?
  6. Is whole-model batch invariance achievable at all with mixed FP4/INT8 paths, or is the 16K first-token instability inherent to the numerics?
