> **一句话总结：** 本文提出 LSREP——一种通过有序重放、检查点状态重建、演化参考答案与机制保真度审计来纵向评测对话记忆系统的协议，并以本地优先的记忆中间件 ICE v2 为案例：在私有重放语料上 ICE v2 与纯向量 RAG 平均分打平（4.26 vs 4.25）但少用 32% 片段、在高密度数据集上击溃无预算基线（4.33 vs 1.23），却在公开 LongMemEval 上惨败（full-S 43.0% vs 69.5%），揭示两种评测体制结论相互矛盾这一核心发现。

> **TL;DR:** A single-author paper introducing LSREP, a longitudinal replay-based evaluation protocol for conversational memory (1,985 private turns, 219 probes, 1,211 probe–checkpoint observations), audited on ICE v2, a local-first memory middleware (PostgreSQL/pgvector, typed stores, weighted RRF fusion, dynamic token budgets). On three ordinary-density LSREP datasets ICE v2 ties pure vector-RAG on mean score (4.26 vs 4.25, paired Δ +0.002, CI [−0.07, +0.07]) while selecting 32% fewer fragments (20.4 vs 30.0) but using 6.6% more prompt tokens, and crushes the unbudgeted top-30 baseline on a dense dataset (4.33 vs 1.23; baseline fails 94.2% of probes by injecting ~88K tokens). Yet on matched LongMemEval (500 oracle + 500 full-S questions, same gpt-5.6-luna answerer and Muse judge) ICE v2 loses decisively to vector-RAG: 50.8% vs 72.8% (oracle, paired Δ −22.0 points, CI [−26.6, −17.4]) and 43.0% vs 69.5% (full-S, Δ −26.5), with multi-session accuracy of 21.5% vs 74.4% — while using far less context (median 5 fragments / 2,222 input tokens vs 30 / 11,718). The paper's real contribution is methodological honesty: a fidelity audit shows procedural retrieval was outright defective, several mechanisms never executed, and graph utility is unestablished, so near-zero ablation deltas "measure nothing" for those components.

## 核心贡献

- **LSREP 评测协议（主要贡献）**：首个以"状态轨迹"为评测单元的系统无关协议——按序重放历史、在 52 个检查点重建记忆状态、用随时间演化的参考答案（当前真相探针 vs 历史探针）反复追问同一问题，并强制执行机制保真度审计（组件是否真的执行、输出是否进入最终提示）。静态端点 QA 无法观察状态如何累积、老化与被修订，LSREP 补上这一维度。
- **ICE v2 架构与被审计的案例研究**：本地优先的记忆中间件（OpenAI 兼容代理），四类存储（情景转向、时间版本化知识图谱 Codex、程序性模式、文档 RAG）+ 持久记忆槽 + 上下文簇，全部在单个 PostgreSQL/pgvector 中；两阶段意图分类（规则 + 冻结 Qwen3-0.6B 编码器上的 MLP）、加权倒数排名融合（RRF）、访问加权衰减与动态 token 预算。快照冻结于 v2-paper-eval 标签。
- **双体制评测 + 保真度审计的元方法论**：LSREP（继续对话内纵向行为）与匹配的公开 LongMemEval（新会话跨会话聚合 + 干扰项）结果**相互矛盾本身即是发现**；组件审计将机制分为"缺陷 / 未被行使 / 有贡献 / 无结论"四类，论文明确给出可证伪的方法论主张——"组件无帮助"的结论只有在组件被验证存活且交互 regime 触达它时才成立，并坦承自己的评测在何处未达此标准。
- **诚实的负结果报告**：ICE v2 在公开基准上大败（full-S 落后 26.5 个百分点），多会话合成与时间推理是重灾区；作者主动推翻了早期草稿"RRF 是影响最大的组件"的说法（配对置信区间不支持），降级为"RRF 修复了加词法腿造成的伤害"。

## Key Contributions

- **LSREP (primary contribution)**: a system-independent protocol specification for evaluating conversational memory longitudinally — ordered history replay, state reconstruction at successive checkpoints (52 checkpoints, 1,211 probe–checkpoint observations over 219 distinct probes), repeated probes scored against *evolving* reference answers (a current-truth probe changes its reference when a fact is revised; a historical probe keeps it), plus mechanism-fidelity checks tracing whether each claimed component executes and reaches the final prompt. Endpoint QA alone cannot observe how persistent state accumulates, ages, or incorporates revisions.
- **ICE v2 as an audited architectural case study**: a local-first, OpenAI-compatible memory middleware with four typed stores in one PostgreSQL/pgvector database (episodic turns, the temporally-versioned "Codex" knowledge graph with a three-bucket relation vocabulary — overwrite / accumulate / auto-expire prior edges via `valid_until`, procedural patterns, ingested documents), persistent server-enforced memory slots, and context clusters; a two-stage intent classifier (rule cascade + MLP over a frozen Qwen3-Embedding-0.6B encoder), six retrieval legs fused with weighted RRF (s(f) = Σ αℓ/(60 + rankℓ(f))), access-weighted decay (~5%/2%/1% per-day multipliers, retrieval restoring +0.15 to the decay score), and a dynamic context budget (nominal 23,000 estimated tokens with a 2,000-token growth cap for fresh conversations).
- **A two-regime evaluation whose disagreement is itself a result**: within-conversation longitudinal replay (LSREP) vs. fresh-session endpoint QA with distractors (matched LongMemEval oracle and full-S), showing that conclusions from one regime do not transfer to the other.
- **A falsifiable methodological claim backed by a fidelity audit**: a near-zero ablation delta supports "does not help" only when the component is verified live and the interaction regime reaches it. The audit finds procedural retrieval defective (untyped embedding bind raising a pgvector operator error, returning an empty list), document/batch-summary stores empty, HyDE disabled and constant across ablation arms, and graph utility inconclusive — so those deltas "measure nothing about the mechanism."

## Methodology

The paper runs three coordinated experiments:

1. **LSREP replay (RQ1–RQ2).** A single user's private history (1,985 turns, ~1.98M estimated tokens) is split into four datasets: A (creative writing, 290 turns), B (long-form world-building, 1,119 turns, 93-day simulated decay horizon), C (technical planning with 8K+-token turns — the density stress case), D (academic planning, 251 turns). History is replayed chronologically into one fresh deployment; between checkpoints the full memory lifecycle runs (decay, edge decay, procedural decay, reflection, clustering, consolidation). Probes are generated leg-aware from history windows using only pre-checkpoint information, each requiring a unique temporal anchor, plus 72 hand-written probes inherited from a pilot. A three-stage temporal-refinement pipeline (forensic regeneration, temporal anchoring, forward propagation with anchor-preservation checks) produces *evolving* reference dossiers, so a system that correctly updates a fact is not penalized against a stale reference. Four conditions are compared: Vector RAG (generalist / MoE) — single-leg pgvector top-30, no decay/fusion/budget — vs Full ICE (generalist / MoE). Scoring uses a 1–5 rubric judged by an independent Gemma-4-12B-AWQ judge on SGLang at temperature 0, anonymized four-condition tournaments, 10,000 paired bootstrap resamples with probe-clustered sensitivity analyses.
2. **Cumulative ablation (RQ2).** A fifteen-step feature buildup on fully-mature Dataset B (67 probes, every condition scored under every arm, Qwen3-14B-AWQ answerer), with paired within-probe bootstrap CIs; only steps whose intervals exclude zero are reported as robust.
3. **Matched LongMemEval (RQ3).** All 500 oracle and 500 full-S questions. An adapter wipes the store per question, ingests each session as a separate auto-scoped conversation, and asks from a fresh empty conversation; both arms share the same stored vectors, the same cloud answerer (gpt-5.6-luna, 4,096-token output cap), and the same Muse Spark 1.3 judge with official LongMemEval task prompts (explicitly *not* the official GPT-4o judge — within-study comparisons only). Twenty-thousand question-level paired percentile bootstrap resamples (seed 20260911). The pure vector arm retrieves top-30 turn representations with no token ceiling — deliberately a strong high-context comparison, not a matched-budget arm.

Throughout, the mechanism-fidelity audit traces input eligibility → execution → output → selection → final prompt inclusion, and a "quality attribution" additionally requires a controlled contrast in which the mechanism actually changes.

## Results & Highlights

- **Ordinary-density tie with fragment economy (LSREP, Datasets A/B/D, 1,057 probe–checkpoint observations):** Full ICE (generalist) mean score 4.26 vs 4.25 for Vector RAG (generalist) — paired Δ = +0.002, record-level 95% CI [−0.07, +0.07]; probe-clustered sensitivity [−0.148, +0.158]. ICE selects 32.0% fewer fragments (20.4 vs 30.0) but uses 6.6% *more* estimated prompt tokens (22,411 vs 21,025) because its recent window, slots, and instruction scaffolding are included. Ordinal comparison: ICE higher on 216 observations, vector on 215, 626 ties. Tournament first-place rate 30.6% (ICE) vs 21.2% (vector), bootstrap CIs [27.9, 33.4] vs [18.8, 23.7]. Audited hallucination rates 19.6% vs 20.5%.
- **Density stress collapse of the unbudgeted baseline (LSREP, Dataset C, 154 observations):** the top-30 vector baseline injects a mean of 88,061 tokens (failed cases reach 100,505), receives score 1 on 94.2% of observations, and averages 1.23; ICE v2's dynamic budget caps context at a mean of 19,953 tokens (77% fewer) with mean score 4.33 (score distribution: 66.9% at score 5). The all-data paired difference is +0.40 (95% CI [+0.31, +0.49]); Dataset C alone +3.10 ([+2.85, +3.33]). ICE's 41.4% hallucination rate on C remains a substantial limitation; the baseline's 0% is an artifact of producing no usable answers.
- **Decisive loss on matched LongMemEval:** overall oracle accuracy 50.8% (254/500) for ICE v2 vs 72.8% (364/500) for pure vector-RAG, paired difference −22.0 points (95% CI [−26.6, −17.4]); full-S 43.0% (215/500) vs 69.5% (347/499), paired difference −26.5 (CI [−31.3, −21.8]). Worst categories (full-S): multi-session 21.5% vs 74.4% (Δ −52.9, CI [−62.8, −43.0], n=121) and temporal reasoning 20.5% vs 47.2% (Δ −26.8, CI [−35.4, −18.1], n=127). The evidence-only deficit of 22.0 points shows distractors are not the root cause.
- **Quality–cost trade-off, not efficiency win (LongMemEval full-S):** ICE v2 supplies a median of 5 fragments and 2,222 provider input tokens per answer vs 30 fragments and 11,718 tokens for vector-RAG — roughly 5x less context at much lower accuracy; correct and incorrect ICE answers have nearly identical median inputs (2,224 vs 2,219 tokens), refuting a simple "more context fixes it" reading.
- **Conservative abstention as the one descriptive strength:** full-S abstention 83.3% (25/30) for ICE vs 63.3% (19/30) for vector, +20.0 points (CI [+3.3, +36.7]) — but with only 8 discordant pairs, exact McNemar p = 0.0703, so the authors claim only cautious abstention, not superiority.
- **Ablation (Dataset B, 67 probes):** adding an unfused lexical leg is harmful (paired Δ −0.74, CI [−1.14, −0.36]); adding RRF on top is corrective (+0.82, CI [+0.39, +1.24]); the full system (3.38) is statistically indistinguishable from the single-leg vector baseline (3.27 bare / 3.42 reference). All other steps span zero — and several of those toggles were broken or constant, so their deltas measure nothing.
- **Longitudinal signal:** in the deepest turn bin of Dataset B (turn 1,100), both vector conditions drop to 3.80/3.87 while ICE holds 4.18/4.14 — a descriptive, single-conversation hint that budgeted curation ages better than raw top-30 accumulation.

## Authors & Credibility

Single author: Deepesh Sonar, Computer Engineering, Thakur College of Engineering and Technology, Mumbai, India. This is striking for a paper of this scope — protocol design, a full middleware implementation, three experiment families, and a forensic self-audit — and it cuts both ways: there is no independent co-author oversight, no second annotator, and the evaluation corpus is the author's own private conversational history (explicitly acknowledged as a selection/authoring risk even for negative results). Credibility positives are unusual and noteworthy: the paper publishes its own fidelity audit admitting defective components, explicitly retracts an earlier overclaim about RRF, reports the unflattering LongMemEval loss in the abstract with CIs, avoids leaderboard-comparable framing (Muse vs official GPT-4o judge flagged), and pins the evaluated snapshot to a tag (v2-paper-eval) with an archival artifact package (scripts, configs, adapter/harness code; raw private data and answers excluded — exact private LSREP scores are not independently reproducible). The stack is heterogeneous but fully disclosed (local Gemma/Qwen for LSREP, cloud gpt-5.6-luna + Muse for LongMemEval).

## Critical Assessment

- **Novelty:** The longitudinal replay idea (evolving references, repeated probes, lifecycle schedules) is a genuine and useful addition over static endpoint benchmarks like LongMemEval and Multi-Session Chat, though its ingredients (versioned references, memory-updating QA) echo prior work on knowledge editing and temporal QA. The architecture itself is an integration of known ideas (MemGPT-style external memory, Mem0-style update operations, Zep/Graphiti-style temporal graphs, RRF fusion) — the author says so explicitly, which is honest but means the architectural novelty is modest. The *fidelity-audit discipline* is arguably the most novel and exportable part.
- **Rigor:** High in self-scrutiny, weak in external validity. All four LSREP datasets come from one author; the 1,211 observations are repetitions of 219 questions; the 72 hand-scored records (favoring ICE by +1.21, CI [+0.81, +1.61]) are from the same single scorer and are merged into the headline aggregate; the judge is an LLM with known position/verbosity biases; the LongMemEval answerer was selected using a small sample from that same benchmark (a disclosed confirmation risk). The "near-zero difference" is absence of a detected difference, not an equivalence test — the author states this, but readers may still over-read the tie.
- **Reproducibility:** The private corpus makes exact LSREP replication impossible by design; the public diagnostic is reproducible in principle (adapter, scripts, seeds recorded) but depends on a non-official judge and a specific cloud stack. The retraction-and-audit trail is exemplary for a solo preprint.
- **Significance:** The headline lesson — a system that looks fine (even wins) in continuing-use replay loses by 22–27 points on fresh-session endpoint QA, and half the advertised mechanisms never ran — is exactly the kind of negative, falsifiable evidence the agent-memory field needs more of. ICE v2 itself should not be adopted on this evidence; the protocol and the audit methodology should.
- **Red flags:** (1) The density-stress "win" is against a strawman unbudgeted top-30 baseline — the author concedes this does not show an advantage over a *properly budgeted* vector baseline, which was never run. (2) The baseline's 0% hallucination rate on Dataset C is meaningless (94.2% total failures). (3) Procedural retrieval crashing with a pgvector operator error and HyDE sitting disabled across the whole ablation mean several advertised mechanisms are simply unevaluated. (4) Token counts are word-count estimates (⌊1.33×words⌋), not tokenizer outputs. (5) The 41.4% hallucination rate on the density dataset is alarming for a memory system whose job is faithfulness. (6) Comparisons with published systems (Zep 63.8–71.2%, Hindsight 83.6–91.4% on LongMemEval-S) are rightly fenced off as non-matched context, but their shadow makes ICE v2's 43.0% look worse still.

## Strengths

- Identifies and operationalizes a real gap: endpoint QA cannot distinguish a system that retrieves well once from one that maintains state correctly over time (updates, aging, revision).
- The evolving-reference design (current-truth vs historical probes, forward propagation with anchor preservation) elegantly fixes the perverse incentive where correctly updating a fact would be scored wrong against a frozen reference.
- Exceptional transparency: the mechanism-fidelity audit (episodic 62.3% of selections, Codex 3.3%, 34.5% unattributable; procedural leg broken; document store empty) and the explicit retraction of the earlier RRF overclaim model how negative-result papers should be written.
- The two-regime disagreement is treated as the finding, not hidden — the abstract leads with both the private tie and the public loss.
- Thorough sensitivity analysis: probe-clustered bootstraps, ordinal comparisons, manual-score-removal checks, phase-transition analysis, McNemar tests on small subsets, and honest reporting of imputation chains for missing scores.

## Limitations

- Single-author, single-user, private corpus: no cross-user generalization; probe repetition creates dependence that record-level bootstrap understates; the hand-scored slice shares the corpus author as scorer.
- The LSREP tie is against a deliberately simplistic single-leg vector baseline with no budget — a matched-budget or matched-prompt vector arm (never run) is the comparison a deployment decision actually needs.
- Several ICE v2 mechanisms are unevaluated rather than validated: graph utility inconclusive, procedural/document/batch-summary retrieval defective or empty, HyDE disabled, decay never independently switched off; the fragment reduction cannot be attributed to any single assembly choice.
- LongMemEval judging uses Muse (73% agreement on a 15-item external calibration) rather than the official GPT-4o judge, the answerer does not support the requested temperature, and the answerer was picked on the same benchmark — scores are within-study only.
- Replay cannot model how generated answers change future user turns, and evaluation probes themselves reinforce memory, perturbing the trajectory being measured.
- Lower token use with lower accuracy is a trade-off, not efficiency; latency excludes retrieval/ingestion; dollar costs are not computed.

## Relevance

这篇论文直接命中"LLM Agent 长期记忆与评测"这一研究方向：它提供了记忆系统纵向评测协议（LSREP）与机制保真度审计的方法论模板，并用扎实的负结果揭示了"继续对话内表现"与"跨会话端点 QA"两个 regime 的结论分裂——对任何要构建或选用持久记忆中间件（Mem0/Zep/MemGPT 一类）的工作都是必读的评测方法论参照。

## Questions for Further Exploration

- How much of the LongMemEval deficit is attributable to the 2,000-token fresh-conversation growth cap rather than retrieval quality? A budget-swept vector-RAG baseline at matched context would disentangle this.
- Would the graph store (Codex) show positive utility on historical/as-of queries — the probe type LSREP specifies but this instantiation never ran?
- Does the two-regime disagreement (replay tie vs endpoint loss) replicate with independent users, public replayable corpora, and official LongMemEval judging?
- Can the evolving-reference construction be automated reliably without anchor drift, and how sensitive are conclusions to judge family (Gemma vs Muse vs GPT-4o) crossed with answerer family?
- Since access-weighted decay was never independently ablated, does retrieval-reinforced forgetting (+0.15 per access) help or hurt long-horizon accuracy in lived (non-replayed) use?
- Would repairing the defective procedural/document legs and re-running the cumulative ablation change the conclusion that most mechanisms beyond fusion and budgeting add nothing?
