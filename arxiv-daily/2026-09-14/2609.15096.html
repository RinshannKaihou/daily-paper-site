Why This Matters

An MIT-licensed blueprint for long-horizon scientific agents — persistent kernels, session-level provenance, and a deterministic-first benchmark protocol others can reuse.

其「代码即动作 + 持久内核 + 会话级溯源」的设计与确定性优先的仓库级评测协议，对构建长时程 LLM Agent 系统（尤其是科学计算类 Agent 框架与基准设计）有很强的参考价值。

Critical Edge

The headline comparison is unmatched: OpenAI4S runs the cheaper doubao-pro while all baselines run frontier models — so the +1.47 margin cannot be attributed to the harness itself.

Also: benchmark, evaluator and system are co-designed by the same group, and full rerunnability remains weak for every system evaluated — theirs included.

01 Methodology — how the system works

Plane AJSON control planeProvider-native calls for planning, permissions, metadata
Plane BCode-cell runtimeOne full Python/R cell per action in persistent kernels
Mid-cellSynchronous host RPChost.llm / delegate / compute, block-and-resume
RecordAction LedgerAppend-only · SHA-256 artifacts · checkpoints · verified recovery

A scientific action is a complete code cell in a persistent kernel, so datasets, fitted models and simulation objects survive across turns instead of being re-materialized — avoiding one observation boundary per elementary operation. A provider-neutral stdlib engine (SQLite state; OpenAI / Anthropic / Gemini adapters) dispatches both planes through one dispatcher with permission checks, screening and audit; there is no registered shell tool — shell lives inside kernel workers.

Session provenance is explicit: content-addressed artifact versions, environment generations, workspace checkpoints, and "verified recovery" that replays eligible cells and reports incomplete coverage honestly. Layered safeguards: Seatbelt/bubblewrap sandboxing, a permission broker, heuristic code screening, and a keyword-triggered bio/chem trajectory screener. Evaluation: 36 scenarios × 6 tasks, binary criteria with deterministic checks taking precedence over a constrained zero-temperature LLM judge (AND-merged); withheld-data violations cap the score at 2.0.

  • Delivery reliability drives the gap: final artifact + report in 15/15 MD & binder scenarios vs 0/15 (Kimi-K3), 3/15 (GLM-5.2), 8/15 (Opus-4.8).
  • Only 6.5% of OpenAI4S scenarios score below 5, vs 45.2–61.3% for baselines; paired diffs +3.09 / +2.20 / +2.54 (W/T/L 25/3/3, 24/0/7, 28/1/2).
  • 95% of numbers in the audited lysozyme MD report trace to machine-readable evidence.
  • Robustness: ranking stable under leave-one-task-out (weakest task 7.01) — but removing the protein domain shrinks the GLM margin to ≈0.04.

03 Strengths

  • Clean architectural thesis with precisely articulated observation-boundary argument — novelty claims scoped honestly to the integration, not the ingredients.
  • Provenance as first-class engineering: append-only ledger, content-addressed artifacts, hashed session packages, recovery that reports partial coverage instead of overclaiming.
  • More defensible evaluation than typical LLM-judge scoring: binary criteria, deterministic precedence, hard-failure caps — plus a disclosed evaluator bug-fix (17 false positives → syntax-tree detection, all 155 runs rescored).
  • Exceptional self-criticism: publishes its own losing catalyst scenario and the ≈0.04 no-protein margin with stage-level detail.
  • Fully open stack: MIT source, PyPI + desktop, benchmark and eval pipeline, >6,000 offline tests.

04 Limitations

  • The headline confounds model, harness, 604 bundled Skills, tools and compute simultaneously — no causal attribution to any runtime component.
  • Benchmark, evaluator and system are co-designed; the scoring dimensions reward this system's design choices by construction.
  • Paired analysis omits the 5 protein-mutation scenarios — a task where it loses to Kimi-K3 (7.96 vs 8.11).
  • Reproducibility remains partial for all systems: in-memory state dies with workers, no cross-machine environment reconstruction yet.
  • Safety fails open by design: screener errors return ALLOW, degraded sandbox continues visibly, ESCALATE is advisory only.
  • Aggregate separation concentrates in protein workloads; on short-horizon retrosynthesis the best baseline still leads.

05 Questions for Further Exploration

  • Does the +1.47 margin survive matched models — OpenAI4S running Kimi-K3 / GLM-5.2 / Opus-4.8, or Claude Code augmented with the same 604 Skills?
  • Which single mechanism drives the long-horizon wins: persistent kernels, mid-cell host RPC, the ledger, or the delivery contract?
  • Can verified recovery extend to true cross-machine session reconstruction — rebuilding environments from the hashed package?
  • Is the LLM-judge portion of the evaluator stable under judge-model, prompt-template or criterion-order variation?
  • Would the default-off review-and-repair layer raise accuracy without inflating unsupported claims?
  • How do the fail-open safety defaults behave under adversarial prompt injection — and what is the cost of flipping them fail-closed?
