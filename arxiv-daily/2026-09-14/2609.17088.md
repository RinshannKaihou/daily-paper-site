> **一句话总结：** 提出 ICML（InteraCtive Memory Learning），把长期对话中的记忆从"被动存档"变成"可学习策略"：一个 Planner 小模型在线决定哪些信息值得存、一个 Trigger 小模型决定何时检索哪条记忆，两者通过跨会话延迟真值奖励（Cross-Session Truth Reward）用 PPO 共同进化，并配合反向故事线合成专家数据解决冷启动；在 MSC、CC、GapChat 三个长期对话数据集上全面超越 Mem0、A-Mem、MemoryOS、THEANINE、LD-Agent 及长上下文基线（如 GPT-4o 下 CC 的 BLEU-4 从最强基线 1.79 提到 2.44，GapChat 的 Mauve 从 28.97 提到 36.42），且随交互轮次增加持续自我提升、记忆构建延迟仅约 63ms。

> **TL;DR:** A multi-agent online-RL framework that turns long-term conversational memory from a static heuristic archive into a learnable policy: a small open-source Planner model decides per turn whether to Save/Discard information, a Trigger model decides which memory (or none) to retrieve, and both co-evolve via PPO with a Cross-Session Truth Reward that propagates future response-quality feedback back to earlier storage decisions; a retrospective session-synthesis pipeline (backward storyline generation + forward dependency annotation) supplies 0.25K–0.5K expert episodes to beat cold-start. On MSC, Conversation Chronicles (CC), and GapChat (GC) it beats all baselines — e.g., under the GPT-4o backbone on CC, BLEU-4 rises from 1.79 (Long Context 128K, the strongest baseline) to 2.44 (Gemma3-4B Planner) and Mauve from 55.73 to 61.66; on GC, Mauve goes from 28.97 (THEANINE) to 36.42; under Gemini2.5-Pro, CC Mauve reaches 80.33 vs 75.42 for THEANINE. Human evaluators prefer its generations over THEANINE 66% of the time, and Planner precision / Trigger recall keep climbing over 10 online sessions while inference tokens stay flat (~63ms memory construction, ~13ms retrieval vs THEANINE's ~10.8s / ~893ms).

## 核心贡献

- **可学习的记忆范式**：首次把长期开放域对话的记忆管理形式化为 POMDP，并用在线强化学习（PPO）优化"存什么（Planner 的二值 Save/Discard 动作）"与"何时触发（Trigger 在记忆索引 + "不检索"上的 categorical 策略）"，取代静态启发式存档。
- **跨会话真值奖励（Cross-Session Truth Reward）**：用 Pending Reward Buffer 把未来某轮 Trigger 实际用到某条记忆时的响应质量分数 r_qual 回传到该记忆当初的存储决策（r_truth = r_proxy + λ·r_qual·I(triggered)），解决了"存储时无法知道记忆真值"的延迟验证难题，使 Planner 与 Trigger 共同进化。
- **反向会话合成（Retrospective Session Synthesis）**：以新用户首次暴露约束/偏好的种子会话为锚，用 LLM 反向递归生成逻辑自洽的前置故事线，再前向标注 Planner 的二值标签与 Trigger 的检索索引（掺入难负例与软负例），以极少量（0.25K–0.5K 集）专家数据完成监督热身，解决稀疏奖励下的冷启动。
- **即插即用 + 自我进化**：Planner/Trigger 用 1B–12B 开源小模型训练，生成端可无缝接入 GPT-4o / Gemini2.5 等闭源长上下文模型（无需其权重）；测试时无需人工干预即可随交互持续自适应，且 Planner 精度与 Trigger 召回在 10 个会话内持续上升。
- **效率优势**：严格的噪声过滤使推理 token 与存储 token 随会话深度基本恒定（基线线性增长），记忆构建/检索延迟毫秒级。

## Key Contributions

- Formulates interactive memory learning for long-term open-domain conversation as a POMDP ⟨S, A, O, R, γ⟩ with a joint action a_k = (a^p_k, a^t_k): a binary memory-planning action (Save/Discard) and a categorical memory-triggering action over memory indices plus a "no retrieval" option.
- Proposes ICML, a two-agent (Planner + Trigger) online RL framework trained end-to-end with a shared Actor-Critic via PPO (clipped surrogate objective + entropy bonus), turning memory from a passive archive into a learnable, self-evolving policy aligned with user expectations.
- Introduces the Cross-Session Truth Reward: a Pending Reward Buffer traces a triggered memory back to its creation turn and propagates the future quality reward to the Planner, aligning storage decisions with long-term memory utility rather than immediate heuristics.
- Designs a Retrospective Session Synthesis pipeline (backward storyline generation from a seed session + forward dependency annotation with hard/soft negatives) that generates dense, causally grounded expert data, solving the cold-start problem with only ~0.25K–0.5K episodes.
- Demonstrates plug-and-play deployment: small open-source Planner/Trigger models (Llama-3, Gemma-3, Qwen3 at 1B–12B) equip closed-source GPT-4o/Gemini2.5 backbones with evolving long-term memory without access to their weights.

## Methodology

The method has three pillars. (1) **Problem formulation**: memory management is cast as a POMDP where the state is the user's latent intent plus full history, the observation is the current query, recent context, and external memory M_k, and the joint action space decomposes into Planner (save vs. discard) and Trigger (which memory index, or 0 = none). (2) **Retrospective Session Synthesis**: starting from a seed session where a user first reveals a constraint, backbone LLMs act as user simulators to recursively generate logically consistent preceding sessions (reverse causality, e.g., inventing a past event where coffee caused heart race), then the storyline is traversed forward to annotate Planner binary labels (information-gain-based) and Trigger retrieval indices, augmented with hard negatives (irrelevant turns from the same session) and soft negatives (random global memories). (3) **Online co-evolution**: at deployment, the Planner receives an immediate LLM-judged proxy reward r_proxy ∈ [0,1] on the intrinsic value of a turn (plus a miss-penalty −α·r_proxy for discarding high-value turns); the Trigger's selected memory is concatenated with context for the backbone LLM to generate a response scored by a multi-dimensional LLM quality reward r_qual. The Cross-Session Truth Reward then retro-propagates r_qual to the Planner's original storage decision (r_truth = r_proxy + λ·r_qual·I(triggered)). Both agents' policies are optimized with PPO over collected trajectories, with a shared critic minimizing MSE to returns and a clipped actor objective with entropy regularization. Responses are generated by conditioning the backbone LLM on history, query, and the retrieved memory.

## Results & Highlights

- **State-of-the-art automatic metrics across all three benchmarks.** Under the GPT-4o (128K) backbone on Conversation Chronicles (CC): ICML (Gemma3-4B) reaches BLEU-4 2.44 and Mauve 58.39 vs the strongest baselines Long Context 1.79 BLEU-4 / 55.73 Mauve and THEANINE 1.27 / 54.23 (Llama3-3B pushes Mauve to 61.66, +5.93 over Long Context). On GapChat (GC): ICML-8B attains Mauve 36.42 vs THEANINE's 28.97 (+7.45) and BLEU-4 1.25 vs 0.79. Under Gemini2.5 (1M) on CC: ICML Qwen3-8B hits Mauve 80.33 vs THEANINE 75.42 and Long Context 72.04; on MSC, Mauve 66.86 (Gemma3-4B) vs Long Context 55.61 (+11.25).
- **Ablations confirm every component matters, with the delayed reward being the most critical.** On GC (Qwen3-8B/Gemini), removing the Cross-Session Truth Reward drops BLEU-4 from 1.28 to 0.97 and (on CC) Mauve from 80.33 to 76.19; removing Evolution (no test-time adaptation) drops CC BLEU-4 from 2.21 to 2.16 and GC from 1.28 to 1.16; removing synthetic data drops CC Mauve from 80.33 to 79.57 and MSC Mauve from 66.01 to 62.56.
- **Human evaluation shows clear preference.** Against THEANINE, human raters prefer ICML generations in 66% of cases (18% tie, 16% baseline wins) and ICML's memories in 70% of cases; against Long Context, generation wins are 72%. ICML also achieves the best memory-retrieval win rate in the pool (80% vs MemoryBank).
- **Continuous self-evolution is empirically demonstrated.** Over 10 extended online sessions, Planner precision and Trigger recall both show a consistent upward trend, supporting the central claim that the policy improves as interactions accumulate rather than plateauing.
- **Efficiency gains are substantial.** Memory construction latency is ~63 ms and retrieval ~13 ms, versus THEANINE's ~10,820 ms construction and ~893 ms retrieval and MemoryOS's ~3,921 ms construction; inference-token usage and storage-token growth stay nearly flat across 5 sessions while baseline costs scale linearly with session depth.
- **Scaling analysis**: matched Planner/Trigger sizes sit on a performance diagonal (balanced pairs beat mismatched larger configs on CC, e.g., 1.7B/1.7B Mauve 75.48 vs 1.7B/8B 70.60), and the synthetic-data sweep shows 0.25K–0.5K episodes is optimal (CC BLEU-4 peaks at 2.62 with 0.5K, falling to 2.02 at 1K — over-supervision causes overfitting to static patterns).

## Authors & Credibility

The work comes from Harbin Institute of Technology (Shenzhen) and Pengcheng Laboratory — Ruifeng Xu's group, a long-established dialogue/NLP lab with an extensive publication record in open-domain conversation; the first author Cai Ke cites their own prior line of work on long-term conversation memory (Ke et al., 2025, 2026a,b), indicating this is a sustained research direction rather than a one-off. The paper follows recognized evaluation protocols (MSC/CC/GapChat, metrics and baselines adopted from prior work by Xu et al. 2022, Jang et al. 2023, Ong et al. 2025/THEANINE), compares against six recent memory/dialogue-agent systems (Mem0, A-Mem, MemoryOS, MemoryBank, LD-Agent, THEANINE) plus two long-context baselines (GPT-4o 128K, Gemini2.5-Pro 1M), spans nine backbone-model configurations (1B–12B), and includes ablations, scaling studies, policy visualizations (decision landscapes, t-SNE), a case study, latency/token cost analyses, and a Limitations section. Supported by NSFC 62576120 and Pengcheng Laboratory projects. Prompts and pseudocode are deferred to appendices; no public code release is stated in the main text.

## Critical Assessment

- **Novelty**: The core reframing — memory management as an online RL policy with a delayed cross-session reward, rather than a heuristic archive — is a genuine conceptual step beyond management-centric agents (Mem0, A-Mem, MemoryOS) and generation-centric agents (LD-Agent, THEANINE). The two-agent co-evolution design with a Pending Reward Buffer is the most original piece; PPO/POMDP machinery itself is standard.
- **Rigor caveats on automatic metrics**: absolute BLEU-4 values are tiny (~1–2.5%), and the gains are not uniform across metrics — under GPT-4o, Long Context actually beats all ICML variants on BertScore for MSC (49.17 vs 48.04) and CC (47.79 vs 47.65–47.88), and under Gemini2.5 THEANINE beats ICML on GC ROUGE-L (11.45 vs 10.64). The headline superiority therefore rests most solidly on Mauve/BLEU-4 plus LLM-judge and human evaluations, and the paper does not discuss these cross-metric inconsistencies.
- **Reward-model circularity risk**: both the proxy reward and the quality reward are produced by backbone LLM judges, and the LLM-as-a-judge evaluation uses GPT-4o and Gemini2.5 — the same model families that appear as backbones and generators. This creates a real (undiscussed-in-main-text) risk of judge preference for self-generated or judge-aligned outputs; the human evaluation partially mitigates it, but annotator counts/kappa are relegated to the appendix.
- **Reproducibility**: no code release is mentioned; the method has many moving parts (user simulators, backward storyline generation, CoT annotation, PPO hyperparameters λ/α/γ/ε, judge prompts) all deferred to appendices, so independent replication would be hard. The synthetic expert data is itself LLM-generated, so expert-label quality bounds the warm-start.
- **Significance and scope**: validated only on open-domain companionship-style conversation; the authors explicitly exclude reasoning, QA, and coding tasks. The latency figures (~63 ms construction) exclude the per-turn LLM judge calls needed to compute r_proxy/r_qual during online learning, so the true added inference cost of test-time RL is understated.
- **Red flags**: mild ones — the abstract's "significantly outperforms" is supported mainly on Mauve and LLM/human preference while several classic lexical/semantic metrics are mixed; and the cold-start fix rests on synthetic data whose distributional match to real users is asserted, not measured.

## Strengths

- Clean conceptual contribution: converts memory management from heuristic archiving to a closed-loop learnable policy with a principled delayed-credit assignment mechanism (Cross-Session Truth Reward).
- The retrospective session-synthesis pipeline is an elegant, resource-efficient answer to sparse-reward cold-start (0.25K–0.5K episodes suffice, with an instructive overfitting tipping point at 1K).
- Broad and fair empirical coverage: three human-to-human datasets, six memory/dialogue-agent baselines plus two long-context baselines, nine open-source policy-model sizes, three evaluation families (automatic, LLM-judge, human).
- Strong efficiency story: flat token consumption and millisecond-level memory operations make the approach practically deployable where THEANINE-style pipelines cost seconds-to-tens-of-seconds per memory operation.
- Co-evolution is directly evidenced (rising Planner precision and Trigger recall over 10 sessions) rather than only implied.

## Limitations

- Scope is limited to open-domain, companionship-oriented conversation; no evaluation on task-oriented dialogue, QA, or reasoning benchmarks (explicitly acknowledged by the authors).
- Reward signals depend entirely on LLM judges, inheriting their biases and creating potential coupling with the LLM-as-a-judge evaluation; robustness to adversarial or out-of-distribution users is untested.
- Automatic-metric gains are uneven: BertScore (MSC/CC under GPT-4o) and ROUGE-L (GC under Gemini2.5) still favor some baselines.
- Online PPO training at test time requires per-turn judge calls and rollouts; the reported latency covers only memory construction/retrieval, so total system cost during adaptation is higher than presented.
- Synthetic expert data quality and its match to real user distributions are not quantified; no code release is stated, complicating reproduction.
- Only relatively small policy models (≤12B) are studied, and dataset-scale/session-count limits (e.g., 10 sessions for the evolution study) leave very-long-horizon behavior unexplored.

## Relevance

与长期对话记忆管理、LLM Agent 记忆架构及测试时自我进化（test-time self-evolution）方向高度相关：把"存什么/何时取"变成可学习策略并用延迟奖励对齐用户偏好，对构建个性化终身助手和 agentic memory 系统有直接的方法论参考价值。

## Questions for Further Exploration

- How sensitive is the Cross-Session Truth Reward to LLM-judge bias — would training with a learned, frozen reward model (or human preference data) change the co-evolution dynamics, and can the judge be decoupled from the evaluation model?
- Can the Planner's save/discard policy handle memory *updates and deletions* (not just append), e.g., overriding an outdated preference rather than accumulating conflicting fragments?
- What is the true end-to-end latency and dollar cost during online adaptation once per-turn proxy/quality judge calls are included, and can judge calls be amortized or distilled?
- Does the framework transfer beyond open-domain chat — to task-oriented dialogue, tutoring, or coding assistants — where memory utility is verifiable and the truth reward could be grounded in task success rather than LLM opinion?
- How does the policy behave on adversarial or shifting users (preference drift within a session, contradictory statements), and what happens at 50+ sessions — does the Trigger's retrieval space become a bottleneck?
- Since balanced Planner/Trigger sizes outperform mismatched larger pairs, is there a theoretical account (capability alignment in the co-evolution loop) that predicts the optimal pairing?
