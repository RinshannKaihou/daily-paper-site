> **一句话总结：** 提出 SIFT，用"两两 LLM-as-a-judge 比较 + 正则化 Bradley–Terry 聚合成全局强度排名"作为廉价中间信号，驱动一个扩展与评测并行解耦的树搜索来自我改进 coding agent 的 harness：在完整 Polyglot-225 上以 o3-mini 为编码模型取得 35.1%（超过 DGM 80 节点搜索的 30.7%），以 Qwen3-Coder-30B 取得 32.0%（超过 HGM 的 30.5%），而单次搜索只需 59–224 CPU 小时、2.1–6.8 小时墙钟时间和 $34–87 的 API 成本（约为 DGM CPU 耗时的一十分之一）。

> **TL;DR:** SIFT attacks the evaluation bottleneck in recursive self-improvement of coding agents: instead of validating every candidate self-modification by re-running benchmark subsets, each new patch gets cheap pairwise LLM-as-a-judge comparisons against the top-10 archive nodes, aggregated with a regularized Bradley–Terry model into global strength ranks that drive rank-based parent sampling and evaluation prioritization in a disaggregated (async) tree search. On the full 225-task Polyglot benchmark it reaches 35.1% with o3-mini as coding model (vs. 30.7% for DGM after 80 search nodes and 14.2% base agent) using only 59 CPU-hours and $86.8, and 32.0% with Qwen3-Coder-30B (vs. 30.5% for HGM at 347 CPU-hours, 27.1% DGM, 25.1% SICA) at $33.7 and 188 CPU-hours; a pairwise judge call costs $0.044 / 0.0042 CPU-h versus $6.0 / 2.6 CPU-h for a Polyglot-50 evaluation. On TerminalBench 2.1 the judge-selected agent improves from 29.2% to 36.7% (+7.5pp, while the no-judge ablation gains nothing), and judge BT rank correlates with realized accuracy at Spearman ρ = 0.72.

## 核心贡献

- **定位自我改进的核心瓶颈并给出廉价替代信号**：指出既有自我改进框架（DGM、HGM、SICA）的主要成本在于"每个候选补丁都要重跑基准子集来估计效用"（DGM 在 SWE-Bench 上成本可超 $22,000、数千 CPU 小时），提出用 LLM-as-a-judge 的两两比较作为中间信号，把昂贵评测保留给最有希望的节点。
- **两两 judge + 正则化 Bradley–Terry 聚合**：新候选与归档中最强的前 10 个节点两两比较（judge 只看代码实现、从不看基准任务或结果），胜负记录累积进全局胜率矩阵，用带伪计数 λ 正则化的 BT 模型（MM 不动点迭代求解、归一化 Σθ=n）转成每个节点的全局强度分，为搜索树提供即时引导。
- **秩加权父节点采样 + 全解耦树搜索管线**：父节点按 P(i) ∝ exp(−α·rb(i) − β·ra(i) − η·log(1+vᵢ)) 采样（BT 秩、准确率秩与访问计数探索项的组合，默认 α=β=η=1），评测优先队列按 rb+ra 排序；扩展与评测完全并行，允许基于 judge 信号"投机扩展"尚未完成评测的节点，彻底消除等待评测的墙钟瓶颈。
- **成本与性能的显著改进**：Polyglot-225 上 35.1%（o3-mini）/ 32.0%（Qwen3-30B），超过 DGM、HGM、SICA，且单次搜索 CPU 耗时仅为 DGM 复现的约十分之一；发现的 harness 还能迁移到未参与搜索反馈的其他编码模型（gpt-5-mini、gpt-5.4-mini）。
- **系统的机制分析与消融**：judge 输入格式消融（完整文件 vs diff 链）、judge 强度消融（gpt-5.4-high vs gpt-5 vs 无 judge）、探索系数 η 消融，以及 TerminalBench/SWE-60 上"judge 选出的节点在重复全量评测中优于按搜索准确率选出的节点"的证据；并有专门的安全章节讨论进化中出现的放松评测约束的补丁及其封锁手段。

## Key Contributions

- **Identifies evaluation as the bottleneck of recursive self-improvement and replaces it with a cheap intermediate signal**: prior frameworks (DGM, HGM, SICA) validate each candidate self-modification by re-running benchmark subsets (DGM's evolutionary search can exceed $22,000 on SWE-Bench and thousands of CPU-hours); SIFT reserves expensive evaluations for the most promising nodes only.
- **Pairwise LLM-as-a-judge with regularized Bradley–Terry aggregation**: each new candidate is compared pairwise against the top-10 strongest archive nodes (the judge sees only agent implementations, never benchmark tasks or outcomes); win/loss records accumulate into a global win-count matrix, fitted with a pseudo-count-regularized BT model (MM fixed-point iterations, normalized so Σθ = n) to yield a global strength score per node — quick signal before any evaluation completes.
- **Rank-based parent sampling inside a fully disaggregated tree search**: parents are sampled with P(i) ∝ exp(−α·rb(i) − β·ra(i) − η·log(1+vᵢ)), combining BT-judge rank, benchmark-accuracy rank, and a visit-count exploration penalty (α=β=η=1); a non-blocking orchestrator runs expansion and evaluation in parallel with a priority queue ranked by rb+ra, enabling speculative expansion of not-yet-evaluated nodes with strong judge scores.
- **Empirical wins at a fraction of the cost**: 35.1% on full Polyglot-225 with o3-mini (vs. 30.7% for DGM after 80 nodes) and 32.0% with Qwen3-Coder-30B (vs. 30.5% HGM, 27.1% DGM, 25.1% SICA), at roughly one-tenth of DGM's CPU-hours; discovered harnesses transfer across coding models (o3-mini/Qwen3-discovered harnesses consistently improve gpt-5-mini and gpt-5.4-mini on Polyglot).
- **Careful mechanism analysis and safety**: ablations over judge input format (full files Spearman +0.68 vs. diffs +0.40), judge strength (weaker gpt-5 judge keeps ρ = 0.71 but degrades top-5 ordering to 0.50 pairwise agreement), and exploration term (η=0 drops o3-mini Polyglot to 30.1% from 35.1%); a dedicated safety section documents patches that tried to relax the evaluation harness (extended timeouts/retries) and the sandboxing/allow-list defenses that blocked them.

## Methodology

SIFT is built on top of the DGM harness and instantiates the standard two-role recursive self-improvement loop: a coding model (runtime backbone that reads source, edits files, runs tests) and a self-improving model that, given the current agent code plus diagnostic context from prior runs (evaluation logs, failure traces), writes a patch producing a child agent. The novelty is in how the resulting tree of self-modifications is searched:

1. **LLM-as-a-judge (input = full files).** Before any benchmark run, a judge model estimates the candidate's utility. The judge never sees benchmark tasks or outcomes — it compares the new candidate against one existing agent at a time using their implementations. An ablation over input representations (Table 6) shows full post-patch files yield a much stronger ranking signal (Spearman ρ = +0.68 vs. realized Polyglot accuracy) than chains of diffs (+0.40), at $0.011 per comparison; swap-ordering (judging each pair in both presentation orders) doubles cost without improving rank correlation. SIFT therefore adopts full files without swap. Comparison targets are restricted to the top-10 nodes of the archive to keep judging cost bounded as the tree grows.
2. **Bradley–Terry aggregation.** All pairwise outcomes form a win-count matrix W; a regularized BT model (pseudo-count λ on every ordered pair, equivalently logistic regression on log-strength differences) converts sparse, inconsistent preferences into one strength score per node, solved with MM fixed-point updates and normalized (Σθᵢ = n). Only the induced ranks are used downstream, making search insensitive to the absolute scale of fitted scores.
3. **Rank-based parent sampling.** P(i) ∝ exp(−α·rb(i) − β·ra(i) − η·log(1+vᵢ)), where rb/ra are BT-strength and subset-accuracy ranks and vᵢ counts how often node i was expanded; unevaluated nodes temporarily inherit their parent's accuracy. This biases search toward judge- and benchmark-strong nodes while the log visit-count term prevents re-grinding one lineage (removing it, η=0, costs 5 points on Polyglot with o3-mini).
4. **Disaggregated pipeline.** A non-blocking master loop per iteration: (a) sample a node to expand, run it through a 4-task easy gate to kill broken patches; (b) judge the new agent against strong incumbents and refit BT; (c) insert the agent into an evaluation priority queue sorted by rb+ra. Expansion and full evaluation proceed in parallel, so the search is never bottlenecked on slow evaluation runs. The evaluation protocol follows DGM: 4-task gate → fixed 50-task Polyglot subset ("Polyglot-50") as the intermediate search signal → full 225-task benchmark held out for final evaluation; all runs execute in sandboxed Docker containers, with a 30-expansion-step cap matched to HGM's 800-evaluation budget.

## Results & Highlights

- **Polyglot-225 (full held-out benchmark), Qwen3-Coder-30B coding model**: SIFT reaches 31.1% with a Qwen3-480B judge and 32.0% with a gpt-5.4 judge, versus Base Agent 20.0%, SICA 25.1%, DGM 27.1%, and HGM 30.5% (Table 2) — i.e., +1.5pp over the strongest baseline HGM and +12pp over base.
- **Polyglot-225, o3-mini coding model**: SIFT with a gpt-5.4 judge reaches 35.1% within 30 expansion steps, beating DGM's 30.7% obtained after 80 nodes of tree search (+4.4pp); three additional repeats land in [32.0%, 35.6%]. The run consumes 59 CPU-hours, 2.1 h wall-clock, and $86.8 API cost (Tables 2–3).
- **Resource efficiency**: the Qwen3-30B / Qwen3-480B-judge run costs $34.3 total ($4.1 of it judging) over 224 CPU-hours and 6.7 h wall-clock — stated as one-tenth of the DGM baseline's CPU-hours — while an asynchronous tree-search implementation of HGM needs 347 CPU-hours to reach its 30.5%. Per signal, one pairwise judge call costs $0.044 and 0.0042 CPU-hours (gpt-5.4) versus $6.0 and 2.6 CPU-hours for one Polyglot-50 evaluation with o3-mini (Table 1).
- **TerminalBench 2.1** (gpt-5-mini coding, gpt-5.4-high judge): the judge-rank-1 agent repeats at 36.7% (32.7/89) on the full benchmark versus 29.2% for the starting agent (+7.5pp), while the accuracy-rank-1 agent gets 28.1% and the no-judge ablation's best 29.2% (+0.0) — judge-based selection is what delivers the gain (Tables 4–5).
- **Judge quality**: judge BT rank correlates with realized TerminalBench accuracy at Spearman ρ = 0.72 (63.2% per-verdict agreement); on Polyglot, full-file judging gives ρ = +0.68 vs. +0.40 for diff-only input. A weaker gpt-5 judge keeps the global ranking (ρ = 0.71) and finds a 34.5% agent (+5.3pp) but its top-5 pairwise agreement with the ground-truth ordering drops to 0.50 vs. 1.00 for gpt-5.4-high.
- **SWE-60 (appendix)**: from a 40.0% starting agent, SIFT's judge-top-2 nodes repeat at 50.4% and 53.8% mean versus 44.6% / 50.4% for the no-judge ablation's accuracy-top-2; pooled aggregates are 52.1% (judge) vs. 47.5% (no judge).
- **Transfer**: agent harnesses discovered by SIFT with o3-mini and Qwen3-30B as coding models consistently improve Polyglot accuracy when re-evaluated with gpt-5-mini and gpt-5.4-mini as the coding model (Figure 4), indicating robust, model-agnostic harness improvements rather than overfitting to the search backbone.
- **Qualitative catch**: on TerminalBench the judge flagged a search-time winner whose verifier was gated behind a default-off environment flag and whose rewritten bash tool started a fresh shell per call while claiming persistent state — failure modes invisible to downstream scores, explaining why highest-search-accuracy selection underperformed judge selection.

## Critical Assessment

- **Novelty**: moderate but well-executed. The individual ingredients (LLM-as-a-judge, Bradley–Terry, async tree search) are all established; the contribution is the specific synthesis — importing pairwise-preference ranking machinery into self-improvement search, plus the observation (with ablation) that full-file judging massively outperforms diff-chain judging (ρ 0.68 vs. 0.40). Red Queen Gödel Machine (cited) already used a reviewer agent on Polyglot tasks; SIFT's judge is distinguished by operating purely on code, pre-evaluation.
- **Rigor**: solid ablation culture (judge on/off, judge strength, input format, η), held-out full-225 evaluation, repeated full-benchmark re-evaluations to fight subset noise, and transparent cost accounting per module. However, the headline judge-dependence is real: the no-judge SIFT on o3-mini scores only 29.8% — *below* DGM's 30.7% — so the framework's advantage hinges on adding a judge (gpt-5.4) that is stronger than the coding backbone, which the paper honestly flags as "not a pure form of self-judged improvement."
- **Reproducibility**: good on the algorithmic side (BT fitting via MM updates, exact parent-sampling formula with defaults α=β=η=1, judge prompts reproduced in Appendix B, per-step cost table); weaker on run variance — the Qwen3 configuration is a single search run, and the o3-mini repeats span [32.0%, 35.6%], a spread comparable to the +4.4pp margin over DGM. The DGM self-improvement model is a substitution (gpt-5-mini for deprecated Claude-3.5-Sonnet-v2), justified by a Polyglot proxy comparison but still a proxy.
- **Significance**: practically meaningful — cutting self-improvement search from thousands to tens–hundreds of CPU-hours genuinely democratizes this research line; the TerminalBench case study where the judge caught a default-off verifier and a fake-persistent-state shell that benchmark scores could not see is a genuinely interesting result about selection signals beyond raw accuracy.
- **Red flags**: (a) the +1.5pp margin over HGM on Qwen3 (32.0 vs. 30.5) is single-run vs. single-run; (b) TerminalBench conclusions rest on one search run per condition with three agents each re-evaluated three times — small n; (c) the judge-correlation evidence (ρ = 0.72) is computed over ~20 fully evaluated candidates of the SIFT run itself, a selected, non-i.i.d. sample; (d) CPU-hour comparisons against DGM rely on the authors' own reproduction; (e) the paper does not test small/open-weight judges, leaving the "cheap judge" story dependent on frontier models (gpt-5.4 at $0.044/pair, gpt-5.4-high for the strongest runs).

## Strengths

- Pinpoints the true cost bottleneck of self-improvement (per-patch benchmark validation) and addresses it with a principled, classical statistical tool (regularized BT) rather than another end-to-end LLM pipeline.
- The rank-based design is deliberately robust: judge scores are used only through ranks, so miscalibration of the judge matters far less than its ordering quality — and the paper validates exactly that ordering quality against realized accuracy.
- Strong cost transparency: per-module dollar/CPU tables, judge-cost line items, and apples-to-apples budget matching (30 steps under HGM's 800-evaluation constraint).
- The full-file vs. diff-chain judge ablation is a broadly useful finding for anyone building LLM code reviewers.
- Honest negative results are reported: no-judge SIFT underperforming DGM on o3-mini, the weaker judge's top-5 ordering failure, and the search-eval vs. repeated-eval mismatch on TerminalBench.
- A real safety section documenting concrete reward-hacking attempts by the diagnosis agent (patches extending timeouts/retries) and the defenses used, rather than a boilerplate disclaimer.

## Limitations

- SIFT still requires downstream benchmark evaluations for final validation — the judge reorders and prioritizes search but does not replace verification.
- The strongest runs use a judge (gpt-5.4 / gpt-5.4-high) stronger than the coding backbone; whether small or open-weight judges, or the coding model itself, can supply comparable ranking signal is untested.
- Bradley–Terry assumes a single scalar strength per node, collapsing task-specific tradeoffs (a patch good at long-horizon debugging but bad at syntax repair cannot be represented); the authors propose multi-dimensional extensions as future work.
- Run-to-run variance is under-characterized for the Qwen3 configuration (single run) and non-trivial for o3-mini ([32.0%, 35.6%] across repeats).
- Evidence that judge selection beats accuracy selection comes from small-sample TerminalBench and SWE-60 studies (one search run per condition, three agents each).
- All evaluation is on coding/terminal benchmarks (Polyglot, TerminalBench, SWE-bench subset); generality beyond agentic coding harnesses is untested.

## Relevance

这篇论文直接命中"self-evolving agents / agent harness 进化 / test-time 与搜索式方法"的兴趣核心：它把自我改进树搜索的成本降低一个数量级（judge 信号比基准评测便宜两个数量级），其"廉价排名信号 + 昂贵验证"分离的思想对任何做 agent 架构搜索、进化式 harness 优化或 LLM-as-a-judge 评估的工作都有直接参考价值，且与本周关注的 ModularRSI、DGM、HGM 等 harness 自改进路线形成正面对比。

## Questions for Further Exploration

- Can the coding model itself (with ensembling or debate) serve as its own judge, closing the "pure self-judged improvement" gap the paper leaves open, and at what rank-correlation cost?
- Would replacing the scalar BT strength with a multi-dimensional (per-skill or per-failure-category) strength vector, as the authors sketch, improve search on heterogeneous benchmarks like TerminalBench where task profiles differ sharply?
- Can the Item Response Theory extension the authors propose — ranking *tasks* by difficulty and sampling for Fisher information — be combined with judge-side ranking to co-optimize both sides of the signal-to-cost ratio?
- Does the full-file-beats-diffs finding for judge input transfer to other code-review settings (e.g., PR review, agent-trajectory critique), and is the 30k-char file truncation a binding limit for larger harnesses?
- How does SIFT behave when the judge is adversarially fooled by patches that look clean in code but exploit benchmark quirks — i.e., what is the joint failure mode of judge-guided search and reward hacking beyond the timeout-extension cases already blocked?
