> **一句话总结：** SkillLift 把 LLM Agent 的技能自进化建模为双层优化：内层用"与打分 Oracle 排序对齐的二元评分量表（rubric）"作为零 rollout 成本的稠密代理评估器引导技能文本修订，外层用极少量真实 rollout 通过 Kendall τ 排序相关性校准量表，在 147 个任务、3 个骨干模型上以比 SkillOpt / CoEvoSkills 低 40–70% 的 token 成本取得全部 6 个"模型×基准"组合的第一名（如 SkillsBench+GLM-5.1 达 75.1%，比无技能基线 +42.4 pp）。

> **TL;DR:** Skill self-evolution is bottlenecked by oracle rollouts — every candidate skill edit needs a full agent execution to score. SkillLift replaces per-edit rollouts with a learned rubric (5–15 binary, signed-point criteria) that is cheap to query (one LLM call), and re-aligns the rubric to the oracle's *ranking* (Kendall's τ, not absolute scores) with only K=3 rollouts per outer round. On WildClawBench (60 tasks) and SkillsBench (87 tasks) with GPT-5.4/mini, GLM-5.1, and DeepSeek-V4-Pro, it wins all 6 model×benchmark combinations over SkillOpt and CoEvoSkills even when baselines get 2× token budget — e.g., SkillsBench overall on GLM-5.1: 75.1% vs SkillOpt's 70.5%; DeepSeek: 74.3% (+47.4 pp over no-skill) vs SkillOpt's 69.0%. Baselines need 2.13–2.74× its tokens to reach the same 0.9-quantile pass rate, and ablations show removing the oracle-aligned rubricator collapses gains to within ~1 pp of static skills.

## 核心贡献

- **识别并实证了"监督瓶颈"**：在 10 个 WildClawBench 任务、10 轮进化、3 个种子的先导实验中，直接基于执行反馈改写技能文本的方法分数方差极大（best–worst 差距始终存在）、无法随轮数扩展，且 oracle token 开销远超框架本身并持续增长——现有方法只能做保守的"失败修补式"局部更新。
- **提出以"排序"代替"绝对分数回归"作为更平滑的监督目标**：判断哪个技能更好所需的 oracle 评估次数远少于预测精确分数，且排序对噪声和跨任务不可比的分数值天然鲁棒（继承自偏好学习 RLHF 的思想，首次迁移到技能文本空间优化）。
- **将技能进化形式化为双层优化并交替求解**：内层（Mode A）冻结 rubric，用它作为零 oracle 成本的稠密评估器引导 K 条技能分支的修订；外层（Mode B）冻结技能，仅用 K 次 oracle rollout 按 Kendall τ 重对齐 rubric 与真实排序。oracle 调用复杂度从 O(LT) 降到 O(L)。
- **全量实证与开源**：147 个任务、3 个骨干模型、6 个"模型×基准"组合全部第一，token 成本降低 40–70%；消融验证 rubricator、种子技能、排序对齐三个组件缺一不可；提示词、超参、token 计量协议全部公开并放出代码。

## Key Contributions

- **Identifies and empirically grounds the supervision bottleneck** in skill self-evolution: a pilot study (10 WildClawBench tasks, 10 rounds, 3 seeds) shows direct text revision from execution feedback has high variance, fails to scale, and lets oracle rollout cost dominate and grow — confining search to failure-patching edits.
- **Reframes the supervision target from score regression to ranking**: identifying which skill is better is cheaper than predicting exact scores, and relative order survives noisy, non-comparable oracle values — a preference-learning insight (Christiano et al. 2017) brought into text-space skill optimization.
- **Formalizes skill evolution as bilevel optimization** solved by alternating updates: an inner loop scores and revises skills against a frozen rubric (a set of binary, signed-point criteria checked by an LLM verifier at one call per candidate, no rollout), while an outer loop spends only K oracle rollouts per round to re-align the rubric-induced ranking with the oracle ranking (Kendall's τ threshold θB=0.9), amortizing oracle cost from O(LT) to O(L).
- **Comprehensive evaluation**: wins all six model×benchmark combinations across WildClawBench and SkillsBench over evolving baselines (SkillOpt, CoEvoSkills) that receive 2× its token budget, with 40–70% token savings, plus ablations isolating the rubricator, seed skills, and ranking-based alignment as necessary components. Full prompts, hyperparameters, and code are released.

## Methodology

SkillLift maintains a population of K skills and a shared rubric R for a task t, alternating two modes for L rounds (defaults: L=3, K=3, ≤2 inner steps, ≤2 outer steps, θA=0.85, θB=θstop=0.9):

1. **Rubric structure.** R is bootstrapped from the seed skill's execution trajectory plus the task description: 5–15 binary criteria, each a yes/no question about the skill's behavior, weighted by signed integers (+1..+5 merits, −5..−1 flaws, no zero). An LLM verifier (temperature 0) judges each criterion from (t, S, R), producing a hit vector h; the score normalizes to [0,1]. Because the hit vector exposes *which* criteria failed, the generator gets dense, criterion-level feedback rather than a scalar.

2. **Inner loop (Mode A, no oracle cost).** The verifier scores the champion skill under the frozen rubric; the generator (same backbone as the agent under test, temperature 0.7) derives K diverse revision directions (strategy, tool use, error handling, etc.) and refines each branch, accepting a local edit only if its rubric score does not decrease. Mode A runs until the worst branch clears θA or the inner budget is exhausted.

3. **Outer loop (Mode B, oracle).** The K refined branches plus the cached champion are scored by the oracle (K new rollouts). The rubric-induced ranking σR is compared to the oracle ranking σO via Kendall's τ; if τ < θB, a rubricator LLM — given the two rankings, per-skill scores and hit vectors, i.e., a *systematic discrepancy pattern* rather than a single misjudged case — revises R (only adding or strengthening evidence-bounded criteria) until τ ≥ θB or budget exhaustion. The champion is then selected *directly by oracle score*, so a misaligned rubric degrades guidance but never corrupts the final output.

The design keeps the rubricator from encoding oracle answers as evaluation rules via evidence-boundedness constraints, and the token accounting protocol counts all traffic (oracle rollouts + framework LLM calls) uniformly.

## Results & Highlights

- **Overall pass rate, all 6 model×benchmark wins** (Table 2): On SkillsBench with GLM-5.1, SkillLift reaches 75.1% overall vs 32.7% no-skill (+42.4 pp), beating SkillOpt (70.5%) and CoEvoSkills (66.6%); with DeepSeek-V4-Pro it reaches 74.3% vs 26.9% no-skill (+47.4 pp) vs SkillOpt's 69.0%; with GPT-5.4-mini 62.5% vs SkillOpt's 58.2%. On WildClawBench, SkillLift scores 68.4% (GPT-5.4), 66.5% (GLM-5.1), 62.4% (DeepSeek-V4-Pro) overall — beating SkillOpt (64.3% / 62.0% / 59.5%) and CoEvoSkills in every backbone.
- **Static-skill ceiling broken**: SkillLift surpasses one-shot Human-written and LLM-written skills by +8.8 to +11.5 pp on WildClawBench and +16.7 to +24.2 pp on SkillsBench (1.5–2.8× ratio), with larger gains on SkillsBench where deterministic verifiers give crisper oracle signal.
- **40–70% token savings** even against over-provisioned baselines (both get 2× SkillLift's budget): baselines need 2.13×–2.74× SkillLift's cumulative tokens to first reach the 0.9 pass-rate quantile on SkillsBench (e.g., GLM-5.1: SkillOpt 2.74×, CoEvoSkills 2.22×; DeepSeek: 2.62× / 2.13×).
- **Ablations (Table 3, SkillsBench)**: removing the rubricator (naïve self-evolution with dense but unaligned feedback) collapses pass rates to 42.5% (GPT-5.4, only +1.1 pp over static skills), 59.8% (GLM-5.1), 65.5% (DeepSeek); replacing ranking-based alignment with direct score regression costs 2.7–5.3 pp (e.g., GPT-5.4: 59.8% vs 62.5%) at identical oracle budget; removing seed skills drops 3.8–6.5 pp.
- **Category heterogeneity**: on GLM-5.1, Search jumps 40.9%→75.0% (+34.1 pp) on WildClawBench and Network Security 36.8%→92.9% (+56.1 pp) on SkillsBench, while Creative barely moves (+3.1 pp) — binary criteria help exactly where correctness is verifiable.
- **Case studies**: on a SkillsBench paratransit task (515 paired trips, 32 vehicles), the seed scores 0.0; Round-0 rubric criteria miss the root cause (all candidates stay 0.0); after oracle-revealed misalignment, the rubricator installs dial-a-ride audit criteria and the Round-1 skill hits a 1.0 verifier score at 7.37M tokens. On tictoc-unnecessary-abort-detection, the skill goes 0.00 → 0.85 (Round 0) → 1.00 terminal (Round 1) at 8.4M total tokens, with all 3 post-stop trials confirming 1.00.

## Authors & Credibility

Haoxiang Kang is an independent researcher; Ming Wen (corresponding author) is at Fudan University. This is an academic-style paper, not a big-lab industrial report. Credibility is strengthened by: releasing code (github.com/WalteR-MittY-pro/SkillLift); an unusually complete appendix (all four role prompts — bootstrapper, verifier, generator, rubricator — full hyperparameter tables for both their method and baselines, the token-accounting protocol, a K×L sensitivity grid, per-task heatmaps, and two detailed case studies); a fairness setup where the generator/rubricator use the *same* backbone as the agent under test (so gains are attributable to the framework, not a stronger auxiliary model); and baselines given 2× SkillLift's token budget. All experiments are on public benchmarks (WildClawBench, SkillsBench) with 3 rollout seeds.

## Critical Assessment

- **Novelty: moderate, cleanly synthesized.** The core building blocks are all known: ranking over regression from preference-based RL (Christiano et al. 2017), rubrics-as-reward (Gunjal et al. 2025), bilevel/alternating optimization (standard). The contribution is the *composition* — applying them to decouple skill-text search from rollout cost — plus a solid empirical demonstration. This is honest synthesis work rather than a fundamentally new technique.
- **Rigor: mostly good, with real caveats.** (1) The alignment signal is statistically thin: with K=3, τ is computed over K+1=4 skills, giving only 7 discrete values, so θB=0.9 demands near-perfect agreement on just 6 pairwise comparisons — the rubric could be "aligned" by luck. (2) SkillOpt runs "at reduced scale relative to its published defaults" with its slow-update, optimizer-meta-skill, and rejected-edit-buffer components disabled, and CoEvoSkills is run at turns 1/20 with several fixed policies — the evolved baselines may be under-tuned even with 2× budget. (3) Several competing systems discussed in Related Work and Table 1 (Trace2Skill, MUSE-Autoskill, SkillCAT, SkillGrad, SkillClaw, SkillForge) are never empirically compared; only two evolved baselines are run. (4) The 40–70% token-savings figure comes from the 0.9-quantile crossing protocol, which excludes tasks whose anchor already qualifies and tasks that never reach the threshold — a filtering step that could flatter the method.
- **Reproducibility: strong.** Full prompts, JSON schemas, hyperparameters, cost ratios, and code are public; the token accounting is defined precisely. The pilot study, however, covers only 10 WildClawBench tasks, and several referenced works (e.g., WildClawBench, SkillOpt) are very recent arXiv preprints, so the ecosystem is fast-moving.
- **Significance: real but scoped.** The 40–70% cost reduction and the O(L) oracle complexity address a genuine, well-motivated bottleneck in agent skill evolution. But gains concentrate in verifiable/procedural categories (Creative +3.1 pp), and the paper itself shows rubric value depends on oracle quality — on noisy, open-ended WildClawBench tasks the ceiling is much lower (+18 pp overall vs +32–47 pp on SkillsBench).
- **Red flags: minor.** The rubricator may only add/strengthen criteria and never remove them (evidence-boundedness), biasing rubrics toward ever-stricter evaluation — acknowledged but not ablated. Per-category n is small (Social n=6, Media n=5, Cyber n=7) with only 3 seeds, so category-level numbers carry high variance. The authors transparently admit K=3 is a cost–quality operating point, not the grid optimum (K=4 often wins by 0.6–4.2 pp).

## Strengths

- A crisp, well-motivated problem statement (oracle-rollout supervision bottleneck) backed by a pilot study before proposing the fix.
- The bilevel decomposition is principled: misaligned rubrics can only hurt inner-loop guidance, never the final champion selection, because the champion is always picked by true oracle score — a safe-failure property.
- Ranking-based alignment is convincingly validated: score regression degrades 2.7–5.3 pp at identical oracle budget, isolating the supervision-target choice.
- Exceptional experimental transparency: full prompt suite, baseline hyperparameters, token-accounting protocol, sensitivity grids, per-task heatmaps, and code.
- Baselines get 2× the token budget and all roles use the same backbone as the agent under test — fairness choices that make the headline numbers more credible.

## Limitations

- Little benefit on subjective/creative tasks (Creative +3.1 pp on WildClawBench): binary, verifiable criteria mirror deterministic verifiers, so the method mostly amplifies existing oracle signal quality rather than creating new capability.
- Kendall's τ over 4 skills is extremely coarse (7 possible values), making the alignment threshold weak evidence; larger populations would sharpen it but raise rollout cost, and returns diminish beyond K=4 (K 4→8 loses 4.2 pp on SkillsBench/GLM at L=4).
- The seed ablation conflates seed quality with population size (K=1 vs K=3), so its 3.8–6.5 pp drop is not attributable to seeds alone — the authors note this but do not disentangle it.
- Only two evolved baselines (SkillOpt, CoEvoSkills) are empirically compared; the six other skill-evolution systems surveyed are not.
- As the authors acknowledge: the method relies on compute-time rollouts (subject to model stochasticity), iteration latency may affect user experience, and extending to multi-task skill libraries, weight-space adaptation, and lower-variance rollouts is left open. Per-branch early stopping in Mode A is also deferred to future work.

## Relevance

技能自进化是当前 LLM Agent 研究的前沿方向，本文提出的"用可对齐的稠密 rubric 代理昂贵 rollout"思路对任何涉及 Agent 上下文/提示优化、test-time 适应或自动化提示工程的工作都有直接参考价值，且其排序式监督（排序优于回归）的思想可迁移到其他昂贵评估场景。

## Questions for Further Exploration

- Would confidence-weighted or graded (non-binary) criteria improve alignment on subjective categories like Creative writing, where binary criteria demonstrably stall?
- How sensitive is the outer loop to oracle noise — does Kendall's τ over only 4 skills reliably detect misalignment, and would a pairwise-preference formulation with more (partial) rollouts be more sample-efficient?
- Can the rubric transfer across tasks (toward multi-task skill libraries), or does oracle alignment make it irreducibly task-specific?
- What happens when the rubricator's add-only/strengthen-only constraint interacts with drifting task distributions over many rounds — does the rubric become monotonically stricter and eventually over-constrain the generator?
- Since the generator and rubricator run on the same backbone as the agent, could a genuinely stronger auxiliary model break the current ceiling, and at what cost trade-off?
- Could the learned rubric be distilled back into the agent's weights (weight-space adaptation) to amortize the per-task search cost entirely?
