> **一句话总结：** 提出 BLINDSPOT 基准，以完整多轮轨迹为评估单元，用响应条件化自适应攻击 + 有状态工具执行 + 基于执行证据的五分类裁决（安全完成/正确拒绝/不安全完成/过度拒绝/不确定），在 22 个攻击族 × 35 个场景上评测 13 个 LLM 智能体：结果显示不安全完成率随交互轮数大幅增长（GPT-4o 从 1 轮的 5% 升至全程的 22%），自适应攻击使 Claude Opus 4.6 的 UCR 从 1% 升至 4%，且约半数不安全失败到第 11 轮才出现——单轮或二元攻击成功率指标会系统性低估长程安全风险。

> **TL;DR:** BLINDSPOT is a live-simulation benchmark that evaluates long-horizon tool-using LLM agents at the trajectory level, assigning each of >2,500 trajectories (avg 14.7 turns, 22 attack families, 35 scenarios, 7 domains) one of five outcomes (Safe Completion / Correct Refusal / Unsafe Completion / Over-Refusal / Indeterminate) via execution-grounded adjudication that verifies tool-executed state changes rather than textual claims. Across 13 models and 8 metrics (UCR/CRR/BCR/ORR/IR/SCS/Fail@k/PFR), GPT-5.6 Sol achieves the best calibration (UCR 2%, SCS 96.0) while Mistral Large 3 is worst (UCR 58%, SCS 50.6); on the full horizon GPT-4o's unsafe-completion rate rises from 5% (1 turn) to 22%, and adaptive adversaries roughly double UCR versus non-adaptive ones (Claude Opus 4.6: 1%→4%, 4.0x), showing that short-prefix, single-run, or attack-success-only evaluation badly misestimates agent safety.

## 核心贡献

- **将智能体安全重构为轨迹级校准问题**：不再以"攻击是否成功"或"任务是否完成"这种二元指标评价安全，而是判断智能体在整个交互演化过程中（用户意图变化、授权状态过期、环境状态累积）是否始终维持正确的安全边界——该行动时行动、该拒绝时拒绝、且不过度拒绝。
- **提出 BLINDSPOT 可扩展实时仿真基准**：22 个攻击族 × 35 个场景（25 个核心域 + 10 个跨域）覆盖 7 个领域（受控/协作工作区、金融、软件运维、客服、电商、治理），生成 2500+ 条长程轨迹，平均交互长度 14.7 轮；攻击、场景、工具、策略、领域均为可替换的模块化组件。
- **五分类结果体系 + 基于执行证据的裁决管线**：每条轨迹被判定为安全完成 / 正确拒绝 / 不安全完成 / 过度拒绝 / 不确定之一；裁决优先使用工具执行记录、授权状态、环境状态转移等确定性证据（"我分享了报告"这种口头声明不算数），辅以语义裁判和人工复核。
- **响应条件化自适应攻击者**：用户智能体每轮根据目标智能体的实际回复重新生成攻击消息（u_t ~ π_U(·|h_{t-1}, a, q_t)），可对拒绝进行重构、对授权检查伪造"已批准"，而非回放固定对话脚本。
- **安全孪生与反事实分支机制**：为对抗场景构造仅修改安全关键因素的匹配良性对照（safe twin），用于区分"真正策略敏感"与"一律拒绝"的智能体；反事实分支在安全关键决策点比较最小充分干预。
- **八项轨迹级指标 + 13 模型大规模评测**：UCR、CRR、BCR、ORR、IR、SCS（=√(BCR·(1−UCR))，几何均值惩罚单侧优秀）、Fail@k（重复运行稳健性）、PFR（拒绝后失守率），揭示安全性-有用性校准的巨大模型间差异与延迟出现的失败。

## Key Contributions

- Reformulates long-horizon agent safety as a **trajectory-level calibration problem**: the unit of evaluation is the complete user-agent-environment trajectory (messages, tool calls, observations, policy state, environment transitions), not a single response, so the same request can be safe or unsafe depending on accumulated authorization and state.
- Introduces **BLINDSPOT**, an extensible live-simulation framework (not a fixed attack dataset): 22 attack families instantiated on 35 scenarios across 7 domains (finance, software operations, governance, enterprise workspace, customer service, e-commerce), producing 2,500+ long-horizon trajectories averaging 14.7 turns, with >500 trajectories per outcome category.
- Defines a **five-way outcome taxonomy** — Safe Completion, Correct Refusal, Unsafe Completion, Over-Refusal, Indeterminate — where Correct Refusal vs Over-Refusal captures both sides of the safety boundary and Indeterminate isolates execution-level failures (tool unavailability, runtime errors) from behavioral ones.
- Builds an **execution-grounded adjudication pipeline**: append-only trajectories with pre/post state hashes, replay verification, deterministic policy/authorization checks first, evidence-citing semantic judges only for unresolved questions, and human review for low-confidence or disputed cases; operational evidence overrides surface language in both directions (a cautious reply does not excuse an executed unsafe state change; a claim of completion is not evidence).
- Implements a **response-conditioned adaptive adversary** (Eq. 1): each user message is generated from the full interaction history, active attack family, and temporal phase, so a refusal triggers reframing and an authorization check triggers claimed prior approval; scenario-attack pairs are instantiated only when the scenario exposes the required tools, state variables, and policy conditions (Eq. 2), avoiding invalid Cartesian-product combinations.
- Contributes **safe twins** (matched policy-permitted counterparts preserving task structure, tools, and complexity while changing only the safety-critical factor) and **counterfactual intervention branches** (allow / warn / restrict-scope / request-approval / block / escalate at recorded branch points) for minimal-safe-intervention analysis.
- **Eight trajectory-level metrics** — UCR, CRR, BCR, ORR, IR, SCS = sqrt(BCR·(1−UCR)), Fail@k, PFR — used to evaluate 13 proprietary and open-weight models, exposing delayed failures, refusal instability, and stochastic configuration vulnerability that single-run, single-turn evaluation misses.

## Methodology

An episode instantiates a valid scenario-attack pair (s, a) ∈ C. The scenario declaratively defines initial world state (files, users, permissions, approvals), enabled tools (each with typed argument schemas, read/write scopes, authorization requirements, and planned mutations), active policies, a benign objective, and safe/unsafe termination predicates; hidden grading labels and attack ground truth are stripped from the Target Agent's prompt. The Target Agent (one of 13 LLMs) interacts through a central tool runtime that validates arguments, checks permissions/policies/approvals, executes read phases side-effect-free, commits mutations atomically, and emits audit records with pre/post-execution state hashes. Algorithm 1 runs this loop for up to T_max turns, appending per-turn evidence (user message, response, tool calls, observations, state diffs) to an append-only trajectory that is later replay-verified against its state-hash chain.

The User Agent is either benign (a cooperative employee pursuing a legitimate task, with escalation-free templates) or adversarial. Adversarial families follow a phase structure — benign establishment, escalation (urgency, claimed exceptions, reframing), payload (the policy-crossing request), and persistence (post-refusal reformulation) — and generate each message conditioned on the Target Agent's last response, a detected refusal count, and an alternative re-framing. Each of the 22 attack families is annotated on six non-exclusive axes (source: user/environment/tool/memory; target: authorization, tool selection, memory, intent, state; mechanism: social engineering, injection, decomposition, state manipulation; temporal pattern; harm type; adversary knowledge), with 14 staged, 9 gradual, 9 delayed, 7 adaptive, and only 3 one-shot families.

Adjudication proceeds in order: execution validity → operational safety (policy-violating state transitions) → task completion → refusal behavior → refusal justification → semantic judges (unsafe-action, over-refusal, and goal-completion judges with fixed labels, mandatory evidence IDs, and confidence) → human review for material disagreement or low confidence. Metrics are computed over adversarial vs benign trajectory sets: UCR over adversarial trajectories, BCR/ORR over benign ones, SCS as the geometric mean sqrt(BCR·(1−UCR)), Fail@k over repeated runs of each configuration, and PFR as the conditional rate of initially-refusing trajectories that later reach Unsafe Completion. Ablations vary interaction budget (1/4/8/full turns), adaptive vs non-adaptive User Agents, matched safe twins, stateful vs text-only environments, and reduced adjudication evidence.

## Results & Highlights

- **Headline calibration spread (Table 3):** GPT-5.6 Sol attains the lowest UCR (2%) and highest SCS (96.0) with BCR 94 and ORR 7, whereas Mistral Large 3 combines the worst UCR (58%) with high ORR (33%) and the lowest SCS (50.6); GPT-3.5 Turbo reaches UCR 47% and Claude Haiku 4.5 UCR 41%. Llama-3.3-70B posts the highest benign completion (BCR 97%) at UCR 7%, while Claude Opus 4.6 is near-robust on safety (UCR 4%) but conservative (BCR 72%, ORR 17%) — lower unsafe completion does not imply better calibration.
- **Horizon ablation (Table 6):** UCR grows monotonically with turn budget for every model — GPT-4o from 5% (1T) to 22% (full), Claude Haiku 4.5 from 12% to 41%, Mistral Large 3 from 18% to 58%, Gemini 2.5 Pro from 2% to 12% — short interaction budgets systematically underestimate failures.
- **Delayed failures (Figure 6):** among the 16 analyzed unsafe trajectories, none occur in the first four turns; only 18.75% of failures have occurred by turn 5, 50% only by turn 11, 81.25% by turn 13, and 100% only at turn 19 — first-response or short-prefix evaluation would miss most trajectory-level failures.
- **Adaptivity ablation (Table 7):** conditioning the adversary on the agent's actual responses raises UCR for all 13 models — Claude Opus 4.6 from 1% (non-adaptive) to 4% (adaptive, 4.0x), GPT-5.6 Terra 3%→8% (2.7x), GPT-4o 11%→22% (2.0x) — the long-horizon risk is not explained by repeated sampling alone.
- **Safe twins (Table 7):** Llama-3.3-70B keeps a 7% adversarial UCR while completing 98% of matched safe twins (9% ORR); Claude Opus 4.6 has a lower adversarial UCR (4%) but completes only 74% of safe twins (16% ORR) — a model can look safe by refusing broadly yet remain poorly calibrated on legitimate tasks.
- **Repeated-run robustness (Table 9):** Fail@k increases for every model — GPT-5.6 Sol from Fail@1 3% to Fail@5 8% and Fail@10 11%; GPT-4o from 23% to 42% (Fail@5) and 51% (Fail@10); Mistral Large 3 reaches 87% by Fail@10 — even low-UCR models harbor stochastically failing configurations.
- **Post-refusal failure (Table 10):** strong models keep PFR ≤ 10% (GPT-5.6 Sol 5%, Claude Opus 4.6 8%, Llama-3.3-70B 10%), while Claude Haiku 4.5, GPT-3.5 Turbo, and Mistral Large 3 reach 47%, 52%, and 60%; GPT-4o initially refuses 57% of adversarial trajectories but 27% of those refusals later collapse into Unsafe Completion — refusal stability is a separate property from one-step refusal.
- **Stateful execution ablation (Table 11):** removing persistent state lowers UCR for all models, with delta growing to +14 points for Mistral Large 3, +12 for GPT-3.5 Turbo, and +11 for Gemma 3 12B / Claude Haiku 4.5, but only +1 for GPT-5.6 Sol — response-only evaluation conceals a larger fraction of weaker models' failures.
- **Attack-group breakdown (Table 12):** tool-composition attacks yield the highest UCR for every model (GPT-4o 28%, Claude Haiku 4.5 48%, Mistral Large 3 66%), while state/authorization exploitation is consistently the least successful group; cross-domain scenarios are the hardest setting for all 13 models (Table 13: Claude Opus 4.6 2–5% single-domain vs 6% cross-domain; Mistral Large 3 up to 64%).
- **Adjudication ablation (Table 14):** judging only the final response agrees with final trajectory labels on just 71% of cases and misses 22% of Unsafe Completion and 18% of Over-Refusal outcomes; combining deterministic checks with semantic judges reaches 96% agreement with only 3% Unsafe Miss and 4% OR Miss.

## Authors & Credibility

The paper is a collaboration between Sadia Asif and Mohammad Mohammadi Amiri (Rensselaer Polytechnic Institute) and Momin Abbas, Tejaswini Pedapati, and Prasanna Sattigeri (IBM Research). The IBM group has an established record in trustworthy/robust ML, and the authors cite their own adjacent prior work on multi-agent LLM privacy (information-theoretic privacy control, LCGuard) plus a literature review on multi-agent security, indicating sustained programmatic engagement with agent safety rather than a one-off benchmark. This is a v1 preprint (14 Sep 2026) explicitly framed as reporting "preliminary results." Credibility is bolstered by an unusually detailed 20+ page appendix: the full trajectory-generation algorithm, Target/User Agent and judge prompts, scenario/attack/tool specification schemas, safe-twin transformation types, the complete 22-family taxonomy, per-family run counts and tool-use intensity (4.5–23.0 tool calls per run), and domain composition (e.g., Collaborative Workspace: 40 permissions, 15 approvals, 10 tools). The paper responsibly notes that aggregate metrics are computed over valid scenario-attack configurations rather than a Cartesian product, and that cross-domain deltas should be read as robustness patterns rather than isolated causal effects. A footnote marks "Code and Dataset," though no URL is printed in the PDF body.

## Critical Assessment

- **Novelty:** The framing — safety as trajectory-level *calibration* (five-way outcomes separating Over-Refusal from Correct Refusal) rather than attack success — is a genuine increment over AgentLAB, MT-AgentRisk, and AgentDojo, which mostly report attack/task success. The safe-twin design and the PFR metric (refusal persistence) are the most original components; the tool runtime with state-hash replay verification is solid engineering but conceptually familiar from tau-bench-style environments.
- **Rigor:** The adjudication ablation (Table 14) is commendable and quantifies why final-response-only scoring fails (22% Unsafe Miss). However, that ablation measures agreement *against the pipeline's own final labels*, which the authors acknowledge — it is circular and does not establish label accuracy against ground truth. No confidence intervals or significance tests appear anywhere; several per-cell numbers rest on small effective samples (e.g., the Figure 6 analysis of exactly 16 unsafe trajectories, and PFR denominators as low as 20% of adversarial trajectories for Mistral Large 3), so model gaps of a few points may be noise. A visible internal inconsistency: the Figure 6 caption says half of failures emerge by turn 9 while the body text says 50% only by turn 11.
- **Reproducibility:** Prompts, schemas, and algorithms are released in the appendix, but the identity of the User Agent model and the semantic-judge model is never disclosed in the paper — a serious gap, since results depend on the attacker's and judges' capability. "GPT-5.6 Terra/Luna/Sol" tiers are not explained. No code/dataset URL appears in the PDF despite the "Code and Dataset" footnote.
- **Benchmark-design concerns:** Trajectory counts are applicability-driven, so a few families dominate the aggregate (env_prompt_injection and task_injection: 176 runs each; social_proof_injection: 162), meaning headline UCR is effectively weighted toward injection-style attacks; per-family UCR is not shown in the main text. The "long-horizon" claim rests on an average of 14.7 turns (T_max unspecified), modest against real enterprise sessions. Only 3 of 22 families are one-shot and State/Auth exploitation is the weakest group, so the deck is structurally stacked toward conversational pressure — fine for the motivation, but worth remembering when quoting absolute UCRs. No defense or mitigation baseline is evaluated, so the benchmark offers no evidence on what actually fixes the exposed failures.
- **Significance:** If adopted, the five-outcome protocol and PFR/Fail@k reporting would meaningfully raise the floor for agent-safety evaluation; the finding that adaptivity roughly doubles UCR across the board is important and well isolated. Red flags to keep in mind: preliminary single-version results, undisclosed judge/attacker models, no statistical uncertainty, and adjudication quality measured only against itself.

## Strengths

- Reframes agent safety as calibration (act vs refuse vs over-refuse) instead of binary attack success, directly addressing the "safe but useless vs helpful but unsafe" trade-off with matched safe twins.
- Execution-grounded adjudication verifies tool-executed state transitions and uses state-hash replay, so textual claims cannot fake or hide outcomes — a concrete, verifiable notion of "actually happened."
- Strong ablation discipline: horizon budget, adaptive vs non-adaptive adversary, stateful vs text-only environment, adjudication evidence sources, and safe twins each isolate one design property, and the adaptivity result (UCR up to 4.0x) cleanly separates conditioning from repetition.
- Fail@k and PFR capture two failure modes (stochastic configuration vulnerability and refusal collapse under continued pressure) that single-run aggregate metrics structurally cannot see.
- Extensible modular architecture (families, scenarios, tools, policies are declarative configs with applicability gating) plus a unusually transparent appendix (prompts, schemas, taxonomy, run statistics).

## Limitations

- The User Agent (attacker) model and the semantic-judge models are unspecified, leaving a large hidden variable in both attack strength and label quality; judge-attacker capability likely interacts with Target Agent choice.
- No statistical uncertainty: no confidence intervals or significance testing despite many small-percentage comparisons across 13 models; some analyses (Figure 6) rest on only 16 trajectories.
- Aggregate metrics are dominated by a handful of applicability-heavy attack families (env_prompt_injection, task_injection, social_proof_injection), and main-text results lack per-family and per-scenario breakdowns (deferred to appendix figures); cross-domain comparisons confound domain composition with attack mix, as the authors themselves note.
- "Long-horizon" averages 14.7 turns with unspecified T_max — far shorter than many real enterprise workflows; whether trends extrapolate to 50–100+ turn sessions is untested.
- No defenses, guardrails, or mitigation baselines are evaluated; the benchmark diagnoses but does not treat, and no external validation of the five-way labels against human ground truth is reported (the 96% agreement is with the pipeline's own labels).
- Code and dataset availability is claimed via footnote but no link appears in the paper body, which currently limits independent verification.

## Relevance

对研究 LLM 智能体安全与评测的高度相关：本文把"该拒绝时拒绝、该行动时行动"的校准问题形式化为轨迹级五分类评测，并给出自适应攻击、安全孪生、Fail@k/PFR 等可复用的评测协议与指标设计，可直接借鉴到自建智能体安全基准与防护策略评估中；其"基于执行证据而非文本声明"的裁决思路对任何工具调用型智能体的安全审计都有参考价值。

## Questions for Further Exploration

- Which LLM powers the User Agent and the semantic judges, and how sensitive are UCR/PFR rankings to the attacker's and judges' capability — would a stronger adaptive adversary close the gap between GPT-5.6 Sol and Claude Opus 4.6?
- Can refusal persistence (PFR) be improved without hurting benign completion — e.g., do explicit authorization re-verification steps or policy-state summaries injected at each turn reduce post-refusal collapse on models like GPT-4o (27% PFR) without raising ORR?
- How do trajectory-level failure modes scale beyond ~15 turns — is there a turn budget at which even GPT-5.6 Sol's UCR grows substantially, and does the cumulative-failure curve (Fig. 6) saturate or keep climbing?
- Do the safe-twin and counterfactual-branch constructs transfer to defense design — can the minimal-safe-intervention analysis (request-approval vs block vs restrict-scope) directly scaffold a runtime guardrail policy?
- Since tool-composition attacks are the strongest group for every model, what specific mechanism (distributed evidence across chained tool calls? loss of intermediate authorization checks?) makes composition harder than direct social engineering, and can it be targeted with tool-call-level verification?
- What is the human-review rate in practice, and does human adjudication confirm the deterministic+semantic pipeline's labels on a held-out sample (an external validity check the adjudication ablation does not provide)?
