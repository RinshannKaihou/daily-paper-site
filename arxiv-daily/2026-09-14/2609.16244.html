Key metric — frozen acceptance gate

0.0433

Final-latent MSE ratio vs a frozen requirement of ≤ 0.1 — ≈23× better than the gate (16×16 config; 8×8 hits 0.0434), with zero failures across 237,214,881 checked values.

Why this matters

A reusable recipe for trusting low-precision generative accelerators: a frozen “must truly denoise” gate, conservative tolerance bands, and a live negative control.

该论文的“语义验收门 + 保守容差模型 + 阴性对照”验证方法论，对任何低精度生成式加速器的可信评估都有直接借鉴价值。

Critical edge

No external hardware baseline appears anywhere — no GPU, TPU, or rival diffusion accelerator — and the shipped compiler leaves the array ~16% occupied, weight-bandwidth-bound at every tested shape.

Also: single-author; flagship DiT-XL/2 (dh=72) is excluded from the fused attention path by the paper's own memory sizing and runs 1.58× slower.

Methodology

Freeze the spec, then earn the silicon

Specification-first, freeze-before-build: a micro-architecture document was frozen before any RTL, then attacked through five rounds of adversarial review (blocking findings fell 78 → 2); post-freeze changes were only ever RTL bugs or 22 dated errata.

The machine: a VLIW sequencer issues one 256-bit word packing four engine slots — 16×16 weight-stationary dual-dot array, vector VPU, two DMA channels — plus a zero-overhead loop tail. Dependences are compile-time wait masks: no scoreboard, no register renaming. Memory splits into four banked regions behind a crossbar whose port budget is an enforced contract; engine latencies are pinned constants bound by assertions.

Numerics (FP8 E4M3 / BF16, FP32 accumulation) are checked against a double-precision replay of the same instruction stream, under a conservative composable tolerance model policed by a deliberately perturbed negative control. A 34-row UVM suite runs at both synthesized configurations; the sky130 flow feeds the netlist back through UVM before layout.

  • Application benchmarks (scaled shapes): Wan 2.1 video block runs 3,384,210 cycles at 70.3% load-DMA vs 16.1% array — weight-bandwidth-bound at every token count; isolated attention reaches 47.1% array occupancy with zero interlock stalls; the DDPM guidance combine needs just 51,647 cycles with 0% array use.

Strengths

Claims built to be checked

  • The frozen semantic gate generalizes: “the device must demonstrably denoise, MSE ≤ 1/10 of starting noise” — and the all-zero-network argument for why element-wise tolerance is insufficient is crisp.
  • Trustworthy performance claims: bit-identical busy cycles before/after pipelining, an explicit deleted-work bound, and a named limiter (1.403× remaining headroom) for the next iteration.
  • Exceptional disclosure: measured occupancy never mixed with analytical projections; a “What we do not claim” section refuses TOPS and full-chip frequency numbers.
  • Auditable process: five review rounds (78 → 2 findings), pre-committed fallbacks, 22 dated errata, and both configurations verified as a hard rule.

Limitations

Where the argument stops

  • Weight-bandwidth-bound at the block level: the stripe-outer GEMM loop re-streams weights at 16 MACs/byte, pinning array occupancy near 16% at every shape and batch.
  • The headline config misses the fast path: the resident K/V ring fits only dh = 64/128, so DiT-XL/2 (dh = 72) runs the slower single-group route at 1.58× cycle cost.
  • No full-chip physical realization: synthesis-only; no fabricated silicon, no end-to-end time-to-image, no throughput number.
  • Area is distorted by the flow: with no memory macros, 318 inferred memories lower to flip-flops (crossbar alone → 530 k flops), inflating 68.355 mm².
  • Self-referential benchmarks: all comparisons are against the device's own projections, at scaled shapes on a small testbench memory.

Questions for further exploration

  1. Would weight residency across stripes (or doubling region W) lift array occupancy from ~16% toward the isolated-attention 47%, and what per-step latency results at production shapes?
  2. How does per-step latency compare against a modern GPU or existing diffusion accelerators on the same trajectory — the paper has no external baseline at all?
  3. Does iterative denoising's error-absorption argument survive few-step flow-matching / rectified-flow schedules (SD3's 4–28 steps), where per-step error has less trajectory to average out?
  4. Can the sequencer's 255-level ripple-carry chains be restructured (carry-select / prefix adders) to close layout on a commodity host?
  5. How much of the 68.355 mm² flop-dominated area disappears once the 318 inferred memories map to macros — and does that flip the crossbar-vs-array sizing for the next revision?
  6. Could the frozen “denoise by 10× or fail” gate become a standard regression criterion for software-side low-precision diffusion kernels, where the same element-wise blind spot exists?
