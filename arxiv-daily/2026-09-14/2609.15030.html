Why this matters02

Cache-hit counters were positive and byte checks passed, yet outputs silently diverged — a cautionary, well-documented case for anyone serving hybrid-attention models.

缓存命中全为正、字节校验通过，输出却静默偏离——正是推理侧静默损坏与数值正确性问题的典型样本。

⚠ Critical edge · external validity03

Every result rests on one model revision, one four-rank host, synthetic prompts, and strictly serial requests — no concurrency, no cross-model evidence, no public artifact.

04Methodology

↑ metric

A production debugging case study run as a controlled experiment.

  • Rig45-layer GLM-5.3-Flash (sparse + linear attention), RedHatAI NVFP4 checkpoint; vLLM 0.1.dev + LMCache 0.5.4; TP = 4 on four RTX PRO 6000 Blackwell GPUs; checkpoint interval C = 1,792.
  • BugOn a complete hit, the connector restored a checkpoint for all N tokens (B = N) while the scheduler credited N − 1. Recurrent state updates in place, so it could not roll back — continuations diverged.
  • RepairStrict-prefix lookup: exclude the final known token before lookup, select B = C·⌊(N−1)/C⌋, recompute the suffix [B, N) — guaranteeing B = p.
  • ControlPinned per-rank FLA autotuner profiles (7 configs/rank), shared computation corrections, matched checkpoint scheduling — because fixed seeds do not survive batching changes.
  • ArmsNine-length boundary matrix · instrumented run (byte observers, poisoned destinations, injected 500 ms save delays) · preregistered 3-template fresh-container extension · 120-request paired serial latency study.

05Results — beyond the headline

↑ metric
  • Pre-fix failures were confined to exact-boundary reloads: first divergence at generated-token index 11 (N = 3,584) and index 0 (N = 5,376).
  • Per-rank transferred bytes fell 69,625,856 → 54,809,600 (N = 3,584) and 84,442,112 → 69,625,856 (N = 5,376) — corroborating the shifted checkpoint selection, labeled metadata, not a latency claim.
  • Serial reload cuts TTFT 46–64% and total request latency 1.9–7.0% with byte-identical outputs; decode rates essentially unchanged (23.38–24.80 vs 23.08–24.76 tok/s).
  • Enabled-path overhead is modest: ON-cold / OFF-cold TTFT ratio 1.01–1.04.
  • Honestly reported quirk: only 6/18 OFF immediate repeats achieved local prefix reuse, so a complete five-path comparison was unavailable.

06Strengths

  • Catches a failure class that positive cache-hit counters and byte-identical page checks cannot detect: state/position mismatch in hybrid attention + in-place recurrent models.
  • The repair is minimal and principled (B = p alignment), validated exactly at the boundaries where the off-by-one manifests.
  • Exemplary experimental hygiene: pinned kernel profiles, poisoned-buffer verification, injected-delay completion checks, preregistered extensions, preserved failed assertions.
  • Quantifies both benefit (46–64% TTFT cut with token-identical outputs) and overhead (1.01–1.04 ON/OFF cold) under matched controls.
  • Exceptionally honest framing that pre-empts the likeliest misreadings of the numbers.

07Limitations

  • One model, one checkpoint revision, one quantization (NVFP4), single host with TP = 4 — no evidence for other hybrid architectures or parallelism configurations.
  • Synthetic templates only; no natural workloads, no standard benchmarks, and task-answer quality explicitly not evaluated.
  • Strictly serial evaluation: no concurrency, preemption, memory pressure, or SLO measurements; capacity beyond GPU memory untested.
  • The repaired path recomputes more than the (incorrect) one-token pre-fix schedule at exact boundaries — that incremental cost was never measured.
  • No ablation of the eleven-file cumulative patch or individual FLA kernels; no public artifact or code release.

08Open questions

  • Does the B = p strict-prefix requirement generalize to other hybrid architectures (Mamba/RWKV-style) and stacks (SGLang, TensorRT-LLM) — and can it be enforced as a production invariant rather than a two-entry-point patch?
  • What does the repaired path truly cost versus the faulty one-token schedule at exact boundaries, and can adaptive checkpoint-interval selection (C) amortize the recomputed suffix?
  • Could a lightweight runtime verifier — sentinel tokens or checksummed recurrent-state snapshots — catch state/position mismatches without instrumented runs?
  • Which pinned FLA kernel choice actually caused the earlier cross-batching divergence (the unrun single-kernel ablation), and is the fixed profile a throughput ceiling?
  • Does token-ID equality over 64–256-token continuations predict longer-horizon or logit-level equivalence — and how does the repair behave under concurrent serving, preemption, and memory pressure?
