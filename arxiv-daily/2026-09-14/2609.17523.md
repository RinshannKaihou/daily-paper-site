> **一句话总结：** ScienceBuddy 发布了一个面向科研人员的交互式科学工作区（224 个工具、22 个模块），并提出"递归中递归"自改进范式——内层递归在固定模型下由辅助模型诊断失败并提出有界的 harness（指令/技能）编辑，外层递归在选定 harness 下用协作衍生的 rubric 奖励做 GRPO 强化学习；在 LAB-Bench/Biomni-Eval1 的 895 个生物医学任务上，三轮协同进化将 Qwen3.5-4B 的单次尝试测试准确率从 42.2% 提升到 73.3%。

> **TL;DR:** This paper releases ScienceBuddy, an interactive biomedical research workspace (224 tools across 22 modules, Python/R/Bash, a frozen data lake), and proposes recursive-in-recursive self-improvement: an inner loop evolves the agent harness (instructions/scoped skills) with the task model fixed and a fixed GPT-6 Astra auxiliary model proposing bounded edits accepted only on paired-eval gains, while an outer loop trains the model with GRPO on rubric-derived rewards under the selected harness. On an 895-task collection from LAB-Bench and Biomni-Eval1 (LitQA2, DbQA, ProtocolQA, GWAS), three coupled cycles lift Qwen3.5-4B single-attempt test accuracy from 42.2% to 73.3% (vs. its own initial system as baseline; +31.1 pp, with 33.3% of problems flipping incorrect-to-correct); harness-only adaptation adds +20.0 pp validation accuracy (31.1% to 51.1%) and model-only RL adds +19.5 pp pass@4 coverage (48.3% to 67.8%). There are no external method baselines (GEPA/ACE/DGM etc.) — all comparisons are self-before/after — so read it as a well-instrumented system/case-study paper rather than a rigorous benchmark win.

## 核心贡献

- **发布了一个可交互的科研工作区产品**：多模态输入（文档、表格、序列、图像）、Python/R/Bash 执行环境、22 个功能模块共 224 个科学工具（覆盖基因组学、分子/肿瘤生物学、药理学、生物影像、文献检索、数据库查询），以及可检视的执行轨迹与持久化工作区；模型与 harness 均可插拔。
- **从协作中构造任务与评分标准（rubric）**：把研究者的请求、追问、执行证据整合为自包含的可执行 Harbor 任务及任务专属 rubric；明确强调研究者的回复不被当作无条件的正确性标签。
- **提出"递归中递归"自改进范式**：内层递归固定任务模型，由固定辅助模型（GPT-6 Astra）诊断轨迹失败并提出有界 harness 编辑，仅当编辑合法且配对开发集评估提升（ΔS > 0）时接受；外层递归在选定 harness 下做环境难度校准、新鲜 on-policy 采样，并用 rubric 奖励驱动 GRPO 更新模型权重。两者双向耦合：harness 塑造训练经验，模型更新改变 harness 的有效性。
- **分解式案例研究证据**：通过固定模型测 harness、固定 harness 测模型的对照实验，把整体增益拆解为程序性改进与模型学习两条独立机制，并用真实研究者交互案例（JAK1、ARL4C）说明任务/标准如何从协作中产生。
- **工程上的异步部署设计**：后台改进与在线服务并行，更新后的模型-harness 对经再评估后部署，所有历史版本保留。

## Key Contributions

- **A released interactive research workspace**: 224 scientific tools across 22 modules spanning genomics, molecular/cancer biology, pharmacology, bioimaging, literature retrieval, and database queries; Python/R/Bash runtimes; a persistent multimodal workspace with inspectable trajectories; pluggable frontier models and harnesses (tool catalog derived from Biomni).
- **Interaction-grounded tasks and rubrics**: researcher requests, clarifications, execution records, and artifacts are consolidated into self-contained executable Harbor tasks paired with task-specific evaluation rubrics; researcher replies inform criteria but are explicitly not treated as unquestioned ground truth.
- **Recursive-in-recursive self-improvement**: the inner recursion evolves the harness with the task model fixed (a fixed auxiliary model diagnoses failures and proposes schema-constrained single-scope edits, accepted only if valid and improving paired development evaluation, with regression checks on previously successful tasks); the outer recursion calibrates environment difficulty and trains the model with GRPO on task-adaptive rubric rewards R_x(τ) = Σ w_c v_c / Σ w_c, with harness and rubrics frozen during RL.
- **Decoupled case-study evidence**: separate experiments isolating harness adaptation (model weights fixed) and model learning (harness fixed), plus a three-cycle coupled co-evolution run and two real researcher-interaction studies showing how task objectives and evaluation criteria emerge from collaboration.
- **Asynchronous product operation**: background harness/model updates proceed while the online service keeps serving researchers; all harness and environment versions are retained for subsequent evolution.

## Methodology

ScienceBuddy formalizes the agent as a joint policy μ_θ,H over a ReAct-style loop, where the harness H constructs model context C_H(h_t) from history, memory, skills, and tool descriptions, and may inject scheduled deterministic actions (e.g., input inspection). Interactions are segmented into self-contained tasks; a ConstructRubric step derives task-specific criteria from the full collaboration trajectory (scope, methodological requirements, evidence, expected artifacts), which are packaged as executable Harbor tasks (instruction + assets + environment + rubric-based tests).

**Inner recursion (harness evolution, θ_k fixed).** A fixed auxiliary model (GPT-6 Astra) reviews recent trajectories and rubric evaluations, links unmet criteria to specific actions/observations, and proposes exactly one bounded edit — add/remove/revise one scoped skill, edit an instruction, or change one context setting — validated by a schema check. Parent and candidate are evaluated on identical development tasks, seeds, and budgets with frozen rubrics; the acceptance rule is H_{k,j+1} = candidate iff Valid and ΔS > 0, ties retain the parent, and previously successful tasks are included to catch regressions. The concrete harness-adaptation run restricts edits to instruction/skill text in a single-file harness, uses a bounded reference-assisted user simulator (fixed Qwen3.8-27B) whose allowed replies never reveal the correct answer, and a feedback interpreter classifying replies into acceptance/correction/new-information/new-requirement with a ternary diagnostic score q_t ∈ {−1, 0, +1} that guides diagnosis but is explicitly distinct from the policy-training reward.

**Outer recursion (model RL, harness fixed).** Environment difficulty is calibrated via pilot execution with the current model+harness (augmenting researcher-derived tasks by varying inputs/conditions or extending inter-step dependencies), then fresh on-policy rollouts are scored with task-adaptive rubric rewards (executable checks plus a fixed judge), and the task model is updated with token-level GRPO using group-relative advantages Â_i = (r_i − mean)/ (std + δ), clipped ratios, and a sampled KL surrogate to a frozen reference. Researcher messages, tool outputs, and deterministic harness actions are excluded from optimized tokens; historical interactions supply task definitions and diagnostics rather than training samples. After training, the inherited harness is re-evaluated under the updated model before the pair (θ_{k+1}, H_{k+1}) is deployed. The coupled experiment runs three cycles (k = 0, 1, 2), each with 10 harness-evolution steps selecting H_k★ by validation accuracy followed by 20 RL updates, starting from Qwen3.5-4B.

## Results & Highlights

- **Coupled three-cycle co-evolution (Qwen3.5-4B; 895-task collection from LAB-Bench and Biomni-Eval1)**: overall single-attempt test accuracy on held-out tasks rises from **42.2% to 73.3%** (+31.1 pp vs. the initial system); **33.3%** of test problems transition from incorrect to correct while only **2.2%** regress from correct to incorrect, with gains across all four task families (DbQA, GWAS, LitQA2, ProtocolQA).
- **Per-cycle inner-loop gains**: harness refinement raises validation accuracy from 38.9% to 44.4% (cycle 1), 34.4% to 46.7% (cycle 2), and 61.1% to 70.0% (cycle 3); mean training reward over the RL phases rises from 33.3% to 38.8%, 44.1% to 60.5%, and 57.8% to 69.8% between the first and second halves of each phase — evidence that both mechanisms keep improving across repeated cycles rather than stalling after cycle 1.
- **Harness adaptation alone (model weights fixed at Qwen3.5-4B; 24 update steps over 288 simulated adaptation conversations; edits proposed by GPT-6 Astra)**: first-response validation accuracy improves from **31.1% to 51.1% (+20.0 pp)** over the initial empty harness H0; the best adaptation batch reaches 75.0% batch accuracy; the selected harness H24 ends with 4 instruction entries and 9 scoped skills (e.g., gene-set membership checks, cytoband lookup, database-specific evidence extraction).
- **Model learning alone (initial harness H0 fixed; ~2 hours of GRPO)**: problem coverage measured by pass@4 on the same task panel increases from **48.3% to 67.8% (+19.5 pp)**, showing RL expands the set of solvable distinct problems under an unchanged procedural interface.
- **Task inventory**: 895 tasks across 16 subtopics — 96 LitQA2 (literature reading), 511 DbQA (database judgments, 10 subtopics), 108 ProtocolQA (protocol troubleshooting), 180 GWAS (causal-gene/variant assessment, 4 subtopics) — with adaptation, validation, and held-out test roles kept separate (validation tasks never guide editing or selection).

## Critical Assessment

- **Novelty**: moderate-to-good. The individual ingredients — reflective prompt/harness evolution (GEPA, ACE, Meta-Harness), rubric-based RL (Rubrics-as-Rewards), GRPO, environment evolution — are all established; the contribution is the *nested coupling* (harness evolution inside model RL cycles, with tasks/rubrics mined from deployed-product interactions) and its honest decomposition into isolated case studies. The related-work section itself concedes that SIA and HELIX already co-update harness and weights.
- **Rigor / baselines — the main weakness**: there are **no external method baselines anywhere**. Every headline number is a self-comparison (initial harness/model vs. adapted), so one cannot tell whether 20 pp of harness gain exceeds, say, GEPA-style prompt evolution or simply a better-written static system prompt on the same budget; nor is Qwen3.5-4B compared against any off-the-shelf stronger model. The 895-task inventory is small, biomedical-QA-shaped, and drawn from just two benchmark families (LAB-Bench, Biomni-Eval1), with heavily imbalanced subtopics (511 DbQA vs. 96 LitQA2).
- **Simulated "researchers"**: the quantitative harness-adaptation study uses 288 conversations from a bounded Qwen3.8-27B user simulator whose replies exclude correct answers — a defensible design for control, but it means the headline "learning from researcher collaboration" claim is quantitatively supported only by *simulated* collaboration; the two real interactions (JAK1 study design, ARL4C presentation) are qualitative and contain "illustrative derivations, not archived rubric packages or scored outputs" per the paper's own caption.
- **Dependence on a strong fixed reflector**: all harness intelligence comes from GPT-6 Astra; the paper candidly notes the reflector stays fixed so "improved task performance does not imply that the improvement mechanism itself has become stronger." A meaningful fraction of the +31 pp may be GPT-6 Astra's procedural knowledge distilled into skills rather than any recursion effect — an ablation the paper lacks (it admits "effects of individual skills and feedback sources are not separately isolated").
- **Statistical rigor**: single runs, no variance or significance tests; validation-set sizes per comparison are not stated in the main text; per-family numbers in Figure 8c are only visually reported. The three coupled cycles are a short horizon for a "continual" learning claim.
- **Reproducibility**: mixed. Code and product are released, prompts and math (acceptance rule, reward, GRPO objective with clipped ratios and sampled-KL surrogate) are fully specified, and model/version bookkeeping is meticulous; but the pipeline depends on proprietary GPT-6 Astra as the editor, so exact replication is bounded.
- **Red flags / overclaiming**: mostly avoided — the abstract sells a paradigm and case studies rather than SOTA claims. Still, "continually improving" rests on three cycles, and no catastrophic-forgetting or safety analysis is provided for repeated GRPO on a deployed model.

## Strengths

- Clean decomposition of the self-improvement claim into four falsifiable research questions, with fixed-model and fixed-harness controls that isolate *where* gains come from — rare discipline for a system paper.
- Rigorous information boundaries (Table S2): private answers are hidden from the policy, simulator, interpreter, and harness proposer; the diagnostic ternary score q_t is explicitly separated from the trajectory reward used for GRPO, preventing subtle reward leakage.
- Gated, regression-aware harness evolution (schema-validated single-scope edits, paired evaluation, ΔS > 0 acceptance, previously successful tasks retained) is a sensible safeguard against degenerate prompt hacking.
- The harness-only (+20.0 pp) and model-only (+19.5 pp pass@4) gains are of comparable magnitude, lending real support to the "both loops matter" thesis rather than one mechanism dominating.
- Ships as an actually deployed product with asynchronous background updates, inspectable trajectories, and honest UI-figure reconstruction disclosures; rubric derivation from real collaboration trajectories (not post-hoc expert annotation) is a practical contribution.

## Limitations

- No external baselines (GEPA, ACE, Reflexion, DGM, or a frontier model under the same harness) and no per-edit/per-feedback-source ablations, so attribution of gains within each loop is open.
- Small task inventory (895 tasks, two benchmark sources, biomedical QA formats) and a 4B backbone; generalization to other sciences, longer horizons, and frontier-scale models is untested.
- The quantitative interaction data is simulated (bounded Qwen3.8-27B simulator); real-researcher evidence is qualitative only (two case studies).
- Core editing/diagnosis depends on a fixed proprietary auxiliary model (GPT-6 Astra), so the "self-improvement" is not self-contained and its ceiling is the reflector's capability.
- Single-run results without variance estimates; three co-evolution cycles is a short demonstration of "continual" learning; no analysis of forgetting, cost, or failure modes of rejected-edit archives.

## Relevance

本文与"LLM 智能体自改进 / 持续强化学习"方向高度相关：它给出了把真实（及模拟）用户交互转化为可执行任务与 rubric 奖励、再驱动 harness 进化与 GRPO 权重更新的完整闭环设计，对研究 agent 记忆、上下文工程与 RL 训练数据构造均有直接参考价值。

## Questions for Further Exploration

- How much of the +20.0 pp harness gain survives if the GPT-6 Astra editor is replaced with an open-weights model of similar size to the task model, or if edits are replaced by GEPA/ACE-style prompt search under identical budgets?
- Does the recursion remain stable and monotonic beyond three outer cycles (e.g., 10–20 cycles), or do harness drift, reward overfitting, or forgetting emerge once easy rubric criteria saturate?
- Can the rubric-construction step be validated against human expert rubrics — how often do collaboration-derived criteria diverge from expert criteria, and does that divergence bound final accuracy?
- Do the harness-only gains transfer across model scales (4B to 70B+/frontier), where strong models may already internalize the learned procedures?
- What happens with genuinely adversarial or noisy researcher feedback, rather than the bounded simulator whose replies never contain the answer?
- How does pass@4 coverage growth trade off against first-attempt accuracy and inference cost after RL — is the model learning to solve new problems or to hedge across attempts?
