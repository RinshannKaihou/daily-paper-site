01

Methodology

ModularRSI converts coarse task-level rewards into localized, module-level edit signals. For every evolution task, rollouts are grouped as contrastive (mixed success/failure), negative, or positive; same-task success/failure pairs — supplemented by a cross-epoch Trajectory Memory — isolate function-level harness defects from task-specific reasoning. The agent under evolution consolidates diagnoses into structured JSON findings.

Semantically similar findings become candidate edits, each voted by the number of distinct tasks supporting it, favoring cross-task evidence over instance-level failures. Five modules evolve independently and in parallel (3 epochs each), with a per-function Evolution History preventing oscillation. Every edit must pass static checks (AST, imports, protocol compliance) with diff-based rollback, an LLM Diff Review that rejects task-specific heuristics, and execution on 2 sampled tasks. A final cross-module integration epoch resolves conflicts before the harness is frozen; Function Merge and Task-Aware Composition keep the function library compact.

Evolution uses only 240 of the 2,000 curated benchmark-disjoint tasks (120 terminal + 120 SWE) · DeepSeek-V4-Flash backbone · Harbor framework · 3 epochs · eval: TB 2.0 (89 tasks) & SWE-Bench Verified (500 tasks)

Modularity is load-bearing: modular is the only strategy that beats baseline; joint and non-modular evolution both actively hurt.

Every single-module variant beats baseline (Acc 49.44–50.56); Agent Loop gives the largest accuracy lift, Observation Management alone cuts steps 34.70 → 22.50 (−35%).

Evolution-data quality matters: a Medium-centered difficulty mix reaches 76.45 vs 74.25 (+2.20 pp) for a Hard&Easy mix — informative contrasts drive generalization.

Usable contrastive-pair ratio declines 7.50 pp across epochs (36.67% at epoch 1), consistent with recurring weaknesses being progressively fixed.

03

Strengths & Limitations

Strengths

  • +Attacks the central confound of harness RSI — benchmark contamination — with a released 2,000-task disjoint dataset and frozen-harness evaluation.
  • +Decisive ablation: modular evolution is the only strategy beating baseline while joint/non-modular actively hurt.
  • +Strong external validity: cross-benchmark (TB↔SWE) and cross-backbone (DeepSeek/GLM/MiniMax) transfer both hold — rare mechanism-level evidence.
  • +Deployable engineering: rollback-capable validation gates, Evolution History, Function Merge, task-aware function composition.
  • +Complementary module analysis (Agent Loop → accuracy; Observation Mgmt → −35% steps) gives actionable design insight.

Limitations

  • –No ablation isolates contrastive trajectory analysis (authors' own admission); its causal role rests on case studies and an indirect trend.
  • –Only 240 of 2,000 curated tasks used; scaling behavior untested and evolution cost (tokens/GPU-hours/dollars) never quantified.
  • –OOD transfer is asymmetric and modest: SWE→TB is +1.83 Acc with Pass3 flat at 30.34; 89-task TB makes all deltas statistically fragile; no significance tests.
  • –AHE and Meta-Harness comparisons rely on the authors' own re-adaptations under a protocol those methods were not designed for.
  • –Self-review circularity in the Diff Review gate; 2-task execution validation is a thin regression guard.
04

Questions for Further Exploration

Q1Do gains scale with evolution data — does using all 2,000 tasks (vs 240) push TB 2.0 beyond 52.43, or does harness evolution saturate quickly?

Q2Would failure-only, single-sided analysis on identical modules reproduce the gap — finally isolating the causal role of contrastive pairing?

Q3Do evolved modules stay beneficial as backbones improve (baseline was already 61.79 on -0731), or do stronger models obviate mechanisms like Observation compression?

Q4Would a larger held-out regression suite (vs the 2-task check) change which modifications survive the Diff Review gate?

Q5What is the amortized cost of modular harness evolution per accuracy point, versus spending the same budget on prompt optimization or fine-tuning?

Q6Since joint evolution fell below baseline, is there an intermediate granularity (2–3 co-evolved module clusters) that balances credit assignment against cross-module coupling?
