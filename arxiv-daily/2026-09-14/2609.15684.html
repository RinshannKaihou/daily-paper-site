Why This Matters · 为何重要

Upgrades one-shot agent reflection into a structured diagnose–patch–retest loop — a directly transferable blueprint for self-improving skill libraries and multi-cause failure repair.

对构建可持久演进的技能库与自我改进 agent 系统直接有参考价值；该框架可迁移到工具调用、代码修复等需要诊断多因失败的场景。

Critical Edge · 批判视角

No fine-grained ablation isolates the candidate pool, the coverage-based selector, and outcome-conditioned re-weighting — which component actually drives the gains is not pinned down.

Supporting caveat: RESKILL's extra per-round LM calls (pool generation, coverage annotation, post-repair attribution) are never costed against single-patch baselines.

Methodology · 方法

repair loop · click steps

RESKILL repairs an agent's external skill file — never model weights. After a completed failed rollout, each bounded repair round runs four decoupled stages:

→ → →
The LM converts the latest failed trajectory into a finite set of failure hypotheses — each with an explanation, supporting trace evidence, affected skill scope, and a repair hint. Weights start uniform (1/|H₁|); same-cause, same-scope hypotheses are aligned across rounds, others treated as new.
A candidate pool of skill patches is built from four sources, screened for reusability beyond the episode, trajectory grounding, action-interface compatibility, and locality (no rewriting unrelated skills).
trace-anchoredhypothesis-anchoredtargeted proposalsinterface guards
The LM marks a binary coverage matrix C(q,h) — does patch q directly address cause h in scope? The selector applies argmax Σh ŵ(h)·C(q,h); ties break toward more local, evidence-grounded edits. Generation stays with the LM — the decision is an explicit, auditable rule.
The task re-executes under the patched skill set. Success stops repair; failure converts the post-repair trace into the next hypothesis set with outcome-conditioned weights — so failed retests redirect the next round (↻) instead of repeating it. Metric: cumulative Succ@r.

SETUP  Frozen policy πθ — only skill set S changes. ALFWorld (274 tasks, budget R7) · AgentGym TextCraft (R4) · frozen Qwen3-1.7B / Qwen2.5-3B / Qwen3-4B. Baselines share first-pass trajectories, budgets, decoding (seed 0) and function as stepwise ablations.

Honest regime boundary · 适用边界

Direct Repair still wins single-cause families — Qwen3-1.7B Heat 30.8% vs RESKILL 23.1%; Qwen2.5-3B Clean 67.2% vs 58.6%. One-shot repair suffices when the trace localizes a single concrete edit.

Strengths · 优势

5
  • LM proposes, rule decides — patch generation is decoupled from weighted-coverage selection, making every repair choice inspectable and auditable from recorded state.
  • Principled ambiguity handling — weighted hypotheses plus a coverage matrix directly attack the credit-assignment problem one-shot reflection ignores; failed retests redirect rather than repeat.
  • Well-controlled comparison — shared failure pools, frozen models, matched budgets; baselines double as stepwise ablations; budget curves show when each approach wins.
  • Honest regime analysis — explicitly reports where Direct Repair is stronger instead of claiming universal dominance.
  • Local, reusable repairs — edits stay scoped rather than overwriting unrelated skills; strategy choosable from budget curves and failure ambiguity.

Limitations · 局限

5
  • Narrow environments — only immediate-feedback text worlds (ALFWorld, TextCraft); delayed feedback, noisy failure signals, and long-horizon effects of skill edits are untested.
  • Scale & scope cap — models ≤4B; no web, OS, or API tool-use settings; frontier-model transfer unknown.
  • Coarse component attribution — no ablation separating pool / selector / re-weighting; coverage-matrix reliability and hypothesis-alignment accuracy unmeasured.
  • Uncosted overhead — extra per-round LM calls (pool + coverage + attribution) add latency and tokens versus one-shot baselines; not quantified.
  • Metric conflation — cumulative Succ@r blends first-pass skill quality with repair efficacy; percentages are not repair-only recovery rates.

Questions for Further Exploration · 延伸问题

open threads
  • Q1How accurate is the LM-assigned coverage matrix C(q,h) against ground-truth causes — would calibrated probabilities or learned scorers improve selection?
  • Q2Which component — pool, coverage selection, or re-weighting — drives the +3.3 pp over Hypothesis Repair, and does the ordering change with scale?
  • Q3Do gains persist with frontier-scale models, or under delayed / noisy feedback such as web agents and API tool use?
  • Q4Do repaired skills generalize to unseen tasks and stay stable long-horizon (skill bloat, conflicting patches, drift)?
  • Q5Can repair state be batched across tasks to amortize LM calls — what is the token cost per recovered task versus Direct Repair?
