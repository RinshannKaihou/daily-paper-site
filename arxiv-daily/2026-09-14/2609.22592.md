> **一句话总结：** AutoGym 用"蓝图先行"的顺序自动生成智能体训练场（任务+可执行环境+验证器）：先定义有效解空间与验证标准、再实例化环境并从环境中执行解路径得到 ground truth，配合显式难度参数（拓扑/交互深度/混淆梯度/干扰项预算）与基于模型表现的主动课程合成；在生产力场景下将困难任务占比从 Agent World Model 基线的 4% 提升到 39%（Claude Opus 4.6, 8-rollout 协议），单批 50 任务成本约 $100–200、54 分钟（对比专家手工 $25K–50K、2–4 周）。

> **TL;DR:** Amazon AGI proposes AutoGym, a framework that generates complete agent gyms (task + executable environment + verifier) "blueprint-first": the valid solution space and verification criteria are fixed before the environment is materialized, and ground truth is computed by executing the blueprint's derivation against the built environment rather than trusting LLM-proposed answers. Explicit generation parameters (topology, interaction depth, obfuscation, distractor budget) steer difficulty — in the 7-tool productivity gym, the hard-task share for Claude Opus 4.6 rises from 4.0% under the Agent World Model baseline (and 21.5% for a human expert-authored suite) to 39.0% under AutoGym's C2 configuration, while gpt-oss-120b finds 70% of the same C2 gym hard (vs 40% for Opus). A failure-driven temporal-reasoning gym (92 tasks retained from 100) stays 89.2% easy for Opus 4.6 but is hard-or-medium for gpt-oss-120b on 41.3% of tasks. Cost: $100–200 per 50-task batch in ~54 minutes at 20-way parallelism, vs $25K–50K and 2–4 weeks for expert authoring; an appendix GRPO run on an 8B model over a 600-task instruction-following gym shows a steadily improving reward curve over 500 steps, but no downstream benchmark transfer is reported.

## 核心贡献

- **蓝图先行（Blueprint-first）的生成顺序**：颠倒"先出题、后找答案"的常规流程——先构造规定有效解空间、环境需求与验证标准的蓝图，再把蓝图实例化为带受控干扰项的可执行环境，使"可解性/可验证性"成为构造前提而非事后检查。
- **Ground truth 由环境执行得出，而非信任生成值**：对实例化后的环境执行蓝图的解推导来计算标准答案，并做独立校验（使用权威资源、不受干扰项影响、不存在另一个同样成立的答案），配合"可回答性不变量"（任务+环境联合包含满足验证标准的充分信息）。
- **显式生成参数实现难度可控**：任务拓扑、交互深度、能力轴、混淆梯度、干扰项组合（陈旧记录、冲突版本、误导资源、分页边界、工具层干扰）与领域解耦，同一平台/工具接口下可系统性调节难度。
- **主动课程合成（Active curriculum synthesis）**：按能力维度聚合模型表现，成功率 <0.30 的维度放松、>0.80 的加强，有界更新防震荡，随模型能力演化持续再校准生成分布；可从失败轨迹直接冷启动。
- **四类验证器**：结果正确性（程序化比对）、过程质量、干扰项韧性（如不得使用 POL-089 的 85% 错误阈值、必须翻页取全 96 条记录）、个性化约束。

## Key Contributions

- **Blueprint-first generation order**: reverses the conventional "pose a question, then search for an answer" pipeline — a blueprint specifying the valid solution space, environment requirements, and verification criteria is constructed and reconciled *before* the environment is instantiated, making solvability and verifiability construction prerequisites rather than post-hoc checks.
- **Ground truth computed by execution, not trusted from the generator**: the answer derivation is walked against the materialized environment; a validation pass checks it uses authoritative resources, is unaffected by distractors, and admits no equally defensible alternative. An *answerability invariant* guarantees difficulty comes from finding/filtering/reconciling information, never from inaccessible hidden state.
- **Explicit, domain-decoupled difficulty parameters**: task topology, interaction depth, capability axes, obfuscation gradient, and distractor budget can shift difficulty while holding platform and tool interface fixed; distractors (stale records, conflicting versions, competing thresholds, pagination boundaries, tool-level complications) must preserve at least one valid solution route.
- **Active curriculum synthesis**: aggregates rollout performance by capability dimension, relaxes dimensions below 0.30 success, strengthens those above 0.80, with bounded updates; can start directly from prior model trajectories' failure analysis instead of a domain seed.
- **Four derived verifier families** (outcome correctness, process quality, distractor resilience, personalization) plus an iterative repair loop that fixes defective gyms — crucially, agent failures on valid gyms do not trigger repair, preventing "repair away the difficulty" degeneracy.

## Methodology

The pipeline (Figure 1) has six stages: (1) **Blueprint initialization** — a scenario and persona (with rich operational context) are sampled, along with generation parameters (reasoning tier, capability axes, obfuscation gradient, distractor budget); (2) **Blueprint construction** — the solution space, obfuscated constraints (which values appear in the question vs. must be recovered from the environment), distractors, and verification criteria are written down, then a reconciliation check verifies all solution-relevant entities exist, withheld information is discoverable, and the tool interface supports the intended solution; (3) **Maze materialization** — the blueprint induces an executable environment (primary experiments: relational store behind 7 tool wrappers; a live cloud-emulator substrate is shown in Appendix E); (4) **Ground truth + verifier assembly** — ground truth is computed by executing the blueprint derivation against the environment (e.g., the procurement running example yields OTD rate 81.25% = 78/96 on-time deliveries vs. threshold 90.0% from policy POL-027, with distractors POL-089's 85% fill-rate threshold, 8 mid-quarter region overrides, 12 retired "Precision Metals" labels, and a 50-rows-per-page boundary splitting 96 relevant records); (5) **Evaluation** — the agent sees only the task, environment, and tools; 8 independent rollouts per task, scored by the four verifiers; (6) **Failure analysis** — recurring capability gaps and distractor hits feed revised generation parameters. Generation uses Claude Sonnet 4.6; evaluated models are Claude Opus 4.6 (frontier reference) and gpt-oss-120b. Tasks are banded by mean verifier score: hard (<0.30), medium (0.30–0.80), easy (≥0.80). Evaluation spans a seed-driven productivity gym (2×350 candidates, 297/280 retained after repair, compared to a human expert-authored suite and Agent World Model on the same 7-tool interface) and a failure-driven temporal-reasoning gym (100 candidates, 92 retained, targeted at gpt-oss-120b's observed temporal-reasoning failures).

## Results & Highlights

- **Difficulty steering (productivity gym, Claude Opus 4.6, 8 rollouts)**: AutoGym's hard configuration C2 yields **39.0% hard / 10.0% medium / 51.0% easy** tasks, vs **4.0% hard / 90.0% easy** for the Agent World Model baseline (N=217 after manual review) and **21.5% hard** for the human expert-authored suite (N=300); the low configuration C1 yields 10.0% hard / 34.7% medium / 55.3% easy — C1 and C2 differ only in topology weights, obfuscation gradient, and distractor budgets.
- **Cross-model discrimination**: on the same C2 gym, **61% of tasks are medium-or-easy for Claude Opus 4.6 but only 30% for gpt-oss-120b (70% hard)** — the gap indicates the tasks measure genuine capability demands rather than evaluation noise from broken tasks.
- **Failure-driven targeting (temporal-reasoning gym, 92 tasks)**: **89.2% easy for Claude Opus 4.6 vs only 58.7% easy for gpt-oss-120b** (41.3% hard-or-medium, reported as 41.4% in text); all 10 tasks outside Opus's easy band fall in gpt-oss-120b's hard band, and no task is harder for the frontier model — a strictly one-sided ordering consistent with targeted curriculum generation.
- **Repair yield and its effect on difficulty**: iterative repair retained 297/350 C1 candidates (84.9%) and 280/350 C2 candidates (80.0%); for C2, repair moved the distribution from 57.0% hard (pre-repair, 350 tasks) to 39.0% hard (280 retained), removing defect-driven rather than capability-driven hardness; the temporal gym retained 92/100 (92%).
- **Certification audit (0–100, independent LLM rubric)**: productivity gym scores 92.7 scope compliance and 91.4 groundedness but only **78.0 interface realism** (tool-mocking layer) and 86.0 environment realism (unnaturally integrated distractors); the temporal gym scores higher (96.7 / 93.4 / 99.0 interface realism).
- **Cost and scale**: a six-domain suite of **600 tasks in under 10 hours**; **$100–200 per 50-task batch at 20-way parallelism (~54 minutes)** vs **$25K–50K and 2–4 weeks for expert authoring**; 86% of tasks retained after repair across the scale study.
- **RL signal**: a 600-task instruction-following gym built from observed failure modes (format compliance, constraint adherence, verbosity) and trained with GRPO on an 8B checkpoint shows **consistent reward improvement over 500 steps** (Appendix G, Figure 2) — evidence of a learnable, non-degenerate training signal, though no external benchmark deltas are given.

## Authors & Credibility

Three authors — Aarati Andrea Noronha, Kavya Ravikumar, and Carly Xiaoyu Lin — all at Amazon AGI; acknowledgments thank four named Amazon colleagues and Amazon AGI for resources. The work is candid about lineage: the Agent World Model framework (Wang et al., 2026) "directly inspired our initial prototype," and Agent World Model is used as the strongest compared baseline. Evaluation hygiene is above average for this genre: 8 rollouts per task, an explicit cross-model check to rule out low scores caused by broken tasks, human inspection of all retained tasks (ground-truth reachability, no distractor blocks all routes, verifier semantics), and a separate LLM certification audit with a fixed 7-dimension rubric whose scores — including unflattering ones (interface realism 78.0) — are reported verbatim. No code or data release is mentioned; groundedness leans on an internal Amazon domain corpus.

## Critical Assessment

- **Novelty**: The blueprint-first inversion is a genuine design contribution, but the components are individually familiar: τ²-bench already demonstrated compositional task generators with programmatic assertion functions defined at construction time, and the paper concedes Agent World Model "directly inspired our initial prototype" and already decomposed gym creation into scenario/task/data/verification stages. The defensible delta is the conjunction — explicit difficulty parameters, distractor taxonomy with resilience verifiers, and closed-loop curriculum — rather than any single mechanism.
- **Rigor**: Generally strong (multi-rollout protocol, cross-model discrimination, human validation, pre/post-repair difficulty comparison), but the discrimination claims rest on only two models (Claude Opus 4.6, gpt-oss-120b) with a large capability gap, so "separates models by capability" is weakly sampled; the strict one-sided ordering in the temporal gym is over just 19 relevant tasks. The human "expert-authored suite" (N=300, 21.5% hard) is underspecified — who authored it, over what time, against what rubric — making it a soft baseline.
- **Baseline fairness**: the Agent World Model comparison is arguably under-powered for the setting — only 217/300 AWM tasks survived "manual review for verifier correctness and environment consistency," and AWM was not designed around this 7-tool interface; a 4.0%-hard baseline partly reflects interface mismatch rather than pure generator quality.
- **Circularity risk**: the paper's core motivation is distrust of LLM judges, yet gym quality (Q3) is certified by "an independent LLM certification pipeline" — the 0–100 rubric scores inherit exactly the adjudication noise the paper criticizes, softened only by the complement of human per-task validation.
- **Reproducibility**: low-to-moderate. No code/data release mentioned; groundedness (91.4) explicitly depends on "an internal domain corpus" unavailable to outsiders; generation and evaluation are tied to specific Claude checkpoints whose behavior will drift.
- **Significance / red flags**: the RL claim is the thinnest part — one 8B model, 500 GRPO steps, a reward curve on the gym's own verifier, and **no transfer to any external benchmark**, which is the step that would justify "gym" (training) rather than "benchmark" (evaluation) framing. The frontier-challenge claim also needs care: 39% hard means 61% of C2 tasks are still medium/easy for Claude Opus 4.6. Contamination — a headline motivation — is argued but never measured (e.g., no canary or n-gram-overlap analysis of generated tasks against pretraining corpora).

## Strengths

- Ground truth computed by executing the blueprint derivation against the materialized environment (not trusting generator-proposed answers) is a clean, principled answer to the "LLM judges its own homework" problem for deterministic tasks.
- The distractor taxonomy (competing thresholds, region overrides, retired labels, pagination boundaries) with dedicated distractor-resilience verifiers is unusually concrete — most synthetic-task papers never operationalize what "hard" means.
- Difficulty steering is demonstrated with a proper controlled comparison: C1 vs C2 differ only in parameter weights while domain and tool interface are held fixed.
- Repair loop explicitly excludes agent failures as a repair trigger, and the pre/post-repair difficulty shift (57% → 39% hard) transparently shows how much apparent difficulty was actually defects.
- Honest reporting of weak certification dimensions (interface realism 78.0) and of the prototype's debt to Agent World Model.

## Limitations

- Interface and environment realism are the weakest certified dimensions (78.0 / 86.0) due to the tool-mocking layer with per-task databases — rewards may not transfer to production interfaces.
- Open-ended task components still rely partly on LLM-based semantic judgment; the process-quality signal mitigates but does not eliminate LLM adjudication.
- RL evidence is limited to a single 8B model over 500 GRPO steps with no downstream/external evaluation; the cloud-emulator substrate (Appendix E) is demonstrated but not empirically evaluated for difficulty or discrimination.
- Only two evaluated models; the temporal-reasoning gym is single-axis and, by design, easy (89.2%) for the frontier reference model.
- 15–20% of candidates are discarded after repair (84.9% / 80.0% / 92% yields), and no public release is mentioned, limiting external reuse.

## Relevance

与"LLM 智能体训练与评测"方向高度相关：AutoGym 直接针对智能体 RL 的瓶颈——可验证奖励环境的自动化构建，其蓝图先行+可执行解路径求 ground truth 的设计对自动基准生成、难度可控评测与课程合成均有直接参考价值。

## Questions for Further Exploration

- Does GRPO training on AutoGym-generated gyms transfer to external benchmarks (e.g., τ-bench, AppWorld, WebArena), or does the reward gain reflect overfitting to the gym's own verifier structure?
- How stable are the difficulty bands across generator-model swaps — if Claude Sonnet 4.6 is replaced by another generator, do the C1/C2 distributions and certification scores hold?
- Can the LLM-based certification audit be replaced with execution-grounded statistics (e.g., solver-agreement rates across N diverse models) to remove the circular reliance on LLM judges?
- What happens to the active-curriculum loop in the long run — does the bounded update rule converge, or does it oscillate around the 0.30/0.80 thresholds as the target model trains?
- How much of the 39%-hard share survives on the live cloud-emulator substrate, where distractor injection and ground-truth execution are harder to control?
- Can contamination of synthesized tasks be measured directly (canary strings, n-gram overlap with pretraining corpora) to validate the de-contamination motivation?
