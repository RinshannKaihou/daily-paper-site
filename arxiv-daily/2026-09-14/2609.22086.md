> **一句话总结：** Adobe 提出一个围绕冻结前沿模型的"程序性记忆"持续进化框架：让 agent 通过"拓宽（挖掘未覆盖子任务的新技能）+ 深化（对照成败轨迹修订既有技能）"两条轴从真实用户流量中演化 76→139 个自然语言设计技能库，并由受安全策略改进启发的"匹配回放门"保守准入，五轮无人工标注进化后把 Claude-Sonnet-4 在 GenEval2 上的执行成功率从 72.7% 提升到 99.3%，且两种机制结合（58.5% 胜率）远强于任一单独使用（约 49%）。

> **TL;DR:** The paper evolves an external bank of natural-language design skills (SKILL.md playbooks) around a frozen LLM driving 230+ Photoshop/Illustrator/InDesign-equivalent tools. Two mechanisms — widening (minting skills for recurring uncovered subtasks, gated at ≥3 recurrences) and deepening (contrastively rewriting failure-prone skills against their own successful/failed executions) — are admitted only through a matched replay gate that forbids any regression on replayed contexts. Over 5 rounds / 1,406 user briefs / 1,869 auto-graded trajectories with zero weight updates and zero human labels, the bank grows 76→139 skills; on Claude-Sonnet-4, GenEval2 execution success rises 72.7%→99.3% (quality +11.99 over the no-skill baseline) and DPG-Bench success 82.7%→100%, with 61.8%/67.6% overall win rates over the no-skill agent on four design benchmarks (Sonnet/Opus) and only 3.4–6.2% latency overhead. The ablation is the key scientific finding: widening alone (49.4% win rate) or deepening alone (48.6%) barely beats baseline, but combined they reach 58.5% (p=0.025) — a superadditive +3.85 completeness gain.

## 核心贡献

- **把"程序性记忆"当作学习对象**：在不更新任何模型权重的前提下，让冻结的前沿模型（Claude-Opus-4.6 / Claude-Sonnet-4 / Qwen3.6-27B）通过 230+ 专业设计工具执行长程设计任务，而把可复用的自然语言设计流程（SKILL.md 技能）作为外部记忆持续进化——这是在无程序化成功判据（design 没有 unit test）的开放域中做 agent 持续适配的系统化尝试。
- **"拓宽 + 深化"双轴进化机制**：拓宽（Widening）从没有技能覆盖的重复子任务中聚类、蒸馏出新技能（出现 ≥3 次才触发）；深化（Deepening）用同一技能自身成功与失败轨迹的对比做针对性修订（失败计数 ≥2 触发，屡次失败则升级为整体重写，再触发探索式"更新/删除/保留"裁决）。
- **匹配回放门（Replay Gate）**：受安全策略改进（safe policy improvement）启发，把"提议"与"准入"分离。针对 VLM 评分器的漂移与位置偏差，门禁完全不用绝对分数，而是在冻结的相同上下文（相同素材、相同上游状态）下成对回放、随机化呈现顺序，只有"至少赢一个 prompt 且一个都不输"才准入——显式承认部署系统中回归的代价远高于错失改进。
- **双机制耦合的实证**：五轮真实用户流量进化（1,406 个 brief、1,869 条自动评分轨迹、无人工标注）后，在 200 个留出 brief 上，单独拓宽或深化的胜率仅 49.4% / 48.6%（与无技能基线无显著差异），二者结合达 58.5%（p=0.025）且完整性得分超加性提升 +3.85——证明"覆盖"与"可靠性"必须协同进化。
- **诚实的失败模式分析**：附录 I 系统刻画了检索-注入范式的三个边界——模型有强默认策略时文本技能无法覆盖（需偏好条件检索+工具裁剪）、细粒度几何操作受感知/验证上限约束（Droste 效应）、长程多步构造逐级泄漏保真度（"vibe drawing"与完整镶嵌图案失败案例）。

## Key Contributions

- **Procedural memory as the learning object**: a continual adaptation framework where a frozen frontier model operates professional design software (230+ tools spanning raster, vector, and page layout) and all learning happens in an external, versioned bank of natural-language skills — a deliberate answer to long-horizon credit assignment and the absence of any programmatic success oracle in graphic design.
- **Widening**: uncovered subtasks are canonicalized into a persistent coverage pool; once a label recurs k_min=3 times, a frozen LLM distills those cases into a candidate SKILL.md. Rejected candidates keep their evidence in the pool for later rounds, so coverage gaps accumulate evidence across rounds rather than being forgotten.
- **Deepening**: a deliberately asymmetric design — cheap permissive selection (failure-count ≥ m=2 on any trajectory scoring below τ=0.6 that retrieved the skill) but conservative shipping. The Reflector receives the current SKILL.md, per-requirement "why-bad" rationales, and a contrastive set of the same skill's successful executions (tool sequences, waypoints, thinking tokens), then emits targeted section edits, escalating to major rewrites and an exploration cycle (update/delete/keep) after repeated gate rejections.
- **Matched replay gate**: candidate changes never ship on absolute scores. Each context (prompt + retrieved assets + upstream state) is frozen and replayed fresh in the same batch under both arms, judged pairwise under order randomization with a tie band δ; a change ships iff it wins at least one prompt by majority-of-contexts and loses none. This cancels judge drift (both arms shift together) and controls for lucky asset retrieval.
- **Coupled-mechanism evidence**: across 5 evolution rounds on real user traffic, the two mechanisms are individually near-neutral but jointly superadditive — the paper's central scientific claim, backed by a controlled ablation with significance testing.

## Methodology

The system separates a frozen solver from an evolving memory. The agent runtime provides iterative tool calling, parallel tool execution, parameter repair, multimodal previews of intermediate document states, and deterministic offline re-rendering of recorded XML snapshots for evaluation. Assets come from Adobe Stock, enriched with visual attributes and diversified via MMR; rendering uses a production engine (Knuth–Plass typography, U²-Net segmentation, Unicode bidi layout, WCAG-style contrast checks).

**Skill representation**: each skill is a SKILL.md with YAML frontmatter — a 200–600 character description of trigger phrases (the *sole* retrieval signal), an app mode (raster/vector/page-layout/any), a 5–10 tool critical path, prerequisites, and status/version. The body has five required sections: when to use, clarify before starting, steps (tool + parameters), tips, and an error-handling table. The bank is partitioned into three sub-banks by app mode.

**Retrieval and injection**: two-stage. First, a frozen LLM distills the brief into ≤6 operation keywords (explicitly ignoring subject matter, brands, colors) — making queries operation-centric like the skill descriptions. Second, token-overlap scoring (not embeddings — deliberately, so the cold-start seeding pipeline and runtime retriever share one tokenizer and authored trigger phrases are guaranteed retrievable) ranks the bank; 2–4 skills are starred per turn. Skills enter context only via progressive disclosure: a compact catalog is always appended to the system prompt, and the model must call `load_skill(name)` to pull a body — only skills the agent chooses to read consume context.

**Evolution loop**: four roles — Prompter (poses briefs from user traffic + LLM-augmented variants), Solver (the agent), Grader (Graphic-Eval), Reflector (turns failures into skill edits). Rounds fire every 50 new graded records. Graphic-Eval scores rendered PNGs on three axes: completeness (decompose brief into 3–10 judgeable requirements, then met/partial/not-met per requirement; the per-requirement reasons for unmet items are the reflector's input), aesthetics (anchored 1–10, deliberately brief-blind), and critique (counted major/minor problems over 8 dimensions). The scalar is s = 0.7·completeness + 0.3·aesthetics with success threshold τ = 0.6; absolute scores are used *only* to select what to revise, never to decide what ships.

**Replay gate**: for rewrites, the replay set is 2 well-scoring + 2 poorly-scoring trajectories that retrieved the skill (the good half is the do-not-regress baseline); for mints, trajectories from the triggering gap cluster, replayed against the no-skill agent. Acceptance requires no record below the tie band and at least one above it. Cold start (before any traffic) seeds 76 skills from product help documentation via a four-phase pipeline with human review checkpoints.

**Evaluation**: internal benchmark = 200 fixed human-authored held-out briefs, re-scored after each round with the bank frozen. External: GenEval2 (Soft-TIFA geometric mean), DPG-Bench (Soft-TIFA arithmetic mean), OneIG-EN/ZH (VQAScore under Qwen3-VL-8B-Instruct) for general T2I; OpenCOLE, GraphicBench, CreatiDesign, BannerRequest400 (300 prompts each) for design, scored as blind two-order pairwise win rates judged by GPT-5.4.

## Results & Highlights

- **Execution reliability (headline)**: on GenEval2 with Claude-Sonnet-4, success rate rises from 72.7% (BASE, no skills) to 99.3% (EVOLVE, +26.6 points) and generation quality from 34.26 to 46.25 Soft-TIFA (+11.99); on DPG-Bench, success goes 82.7%→100% (+17.3 points) with quality 68.28→83.79 (+15.51).
- **Design benchmarks (win rates vs no-skill, GPT-5.4 judge)**: overall 67.6% for Claude-Opus-4.6 (+17.6 over the 50% tie baseline; peaking at 71.7% on CreatiDesign), 61.8% for Claude-Sonnet-4, and 62.8% for Qwen3.6-27B. On BannerRequest400, Sonnet's completion rate jumps from 74.7% to 100% (+25.3 points) — the skill bank eliminates catastrophic tool-use failures on typography/layout-heavy briefs.
- **Internal held-out benchmark (200 briefs, Sonnet)**: after round 5, briefs meeting completeness ≥0.9 rise from 43% to 56% (the largest survival gap, +13 pp), ≥0.5 from 86% to 93%, and perfect 1.0 from 24% to 32%.
- **Ablation (the causal claim)**: on the 200 held-out briefs, cold start alone scores 68.62 completeness (46.4% win rate — actually *below* BASE's 69.08); +rewrite-only 69.02 (48.6%); +new-skills-only 69.79 (49.4%); combined EVOLVE 74.04 (+5.42 over cold start) with 58.5% win rate (p = 0.025) — a superadditive interaction of +3.85 completeness.
- **Evolution dynamics**: 5 rounds over 1,406 briefs and 1,869 graded trajectories grow the bank 76→139 skills; the gate rejects 100/231 rewrite proposals and 67/136 mint candidates. Minted skills are measurably non-redundant: their nearest-neighbor distance to the seed bank exceeds the seed bank's internal spacing (0.215 vs 0.158 median; Mann–Whitney p < 10⁻⁸, Cliff's δ = 0.58).
- **Cost**: mean latency overhead is only 3.4–6.2% across backbones (and occasionally negative, e.g., 113→82 s for Sonnet on DPG-Bench); despite retrieval adding ~28% prompt tokens over BASE, EVOLVE uses *fewer* total tokens than cold start (436.6k prompt / 5,167 output vs 445.2k / 5,298) — skills yield more direct execution and fewer corrective retries.
- **Honest warts**: Opus regresses on GenEval2 quality (61.24→57.92, −3.32); round 4 dips below the no-skill agent at completeness ≥0.3 (90% vs 94%) before round 5's rewrite-heavy mix recovers; Qwen's success-rate movements (+22.7% on GraphicBench but −14.0% on OpenCOLE) are confounded by local-serving timeouts and connection drops.

## Authors & Credibility

The work is from Adobe (Hongyang Du — Adobe Research and Brown University; Lan Yan, Christian Flores, Asim Kadav — Adobe), which is exactly the right institution for a study operating Photoshop/Illustrator/InDesign-equivalent tools at this scale: the 230+-tool environment, production render engine, and Adobe Stock asset pipeline are not reproducible in academia. The paper is unusually transparent for an industrial report: it publishes gate rejection counts (100/231 rewrites rejected), per-round non-monotonicity (the R4 regression), uncurated galleries of all 193 held-out prompts for both backbones, and an entire appendix of mostly-negative personalization results. The framing is well-grounded in the literature — safe policy improvement (Laroche et al.; Thomas et al.) for the gate, LLM-judge position bias (Wang et al.; Zheng et al.) for the pairwise design, and a detailed related-work appendix differentiating the system from Reflexion, ExpeL, Dynamic Cheatsheet, ACE, Voyager, MACLA, Skill-Pro, SkillAudit, and COMFYCLAW. An ethics statement covers data governance of pre-existing user traffic.

## Critical Assessment

- **Novelty**: The individual ingredients (natural-language skill libraries, reflection, replay-verified admission) each have precedents (Voyager, ACE, SkillAudit, MACLA). The novelty is the *composition*: a deployed multi-user skill bank with regression-free admission under a noisy VLM judge, plus the demonstration that acquisition and refinement are superadditive in a domain with no success oracle. The matched-context replay gate (freezing retrieved assets and upstream state so both arms see identical inputs) is a genuinely careful piece of design, directly addressing a confound most self-evolution papers ignore.
- **Rigor**: Strong on controls — no-skill ablation is exact (disabling skill retrieval recovers the original agent), ablation arms share identical prompts and evaluation, win rates use blind two-order pairwise judging, and the superadditivity claim carries a significance test (p=0.025). But the win rate is only 58.5% and the ablation delta (+5.42 completeness on a 0–100 scale) is modest; the p-value is borderline, and no multiple-comparison correction is discussed.
- **Circularity of the judge**: the same Graphic-Eval rubric drives evolution *and* reports progress — the paper states this is deliberate ("a skill is only rewritten against the criterion it will later be measured on"), and cross-backbone/external-benchmark results partially de-risk it, but internal-benchmark gains could partly reflect fitting the judge's decomposition habits. The design-benchmark win rates lean on GPT-5.4 as the arbiter, with no human study in the main experiments (one is only "planned").
- **Reproducibility**: weak, and acknowledged. The internal 200-brief benchmark, user traffic, tool environment, and skill bank are all withheld (content policy / proprietary), and the closest public baselines (ACE, Dynamic Cheatsheet, COMFYCLAW) are cited but never compared against head-to-head — every comparison is EVOLVE vs its own no-skill twin, so the reader cannot tell whether this beats simpler existing memory-evolution schemes in the same setting.
- **Red flags worth noting**: the cold-start bank of 76 documentation-derived skills *underperforms* the no-skill agent (68.62 vs 69.08 completeness), which the ablation table shows but the narrative soft-pedals; Opus's GenEval2 quality regression (−3.32) and the R4 lower-tail regression show the gate's locality — it only protects replayed cases, as the authors concede. Qwen results are dominated by local-serving instability and should not be read as evidence either way.

## Strengths

- A principled, deployment-motivated admission rule: separating proposal from admission, banning absolute scores, and requiring zero regressions across matched replay contexts is the right conservative stance for production agents, and is well connected to the safe-policy-improvement literature.
- The ablation is the paper's best science: neither mechanism alone separates from baseline, but together they are superadditive — a clean, tested causal story about why skill libraries need both coverage growth and reliability refinement.
- Engineering honesty: gate rejection statistics, non-monotonic per-round curves, per-benchmark regressions, latency/token accounting as first-class outcomes, and full uncurated output galleries.
- The failure-mode appendix (method preference, Droste-effect precision limits, "vibe drawing," and the compounding fidelity leaks when scaling to long constructions) is a rare, valuable negative-results section that maps exactly where retrieval-and-injection stops working.

## Limitations

- Textual skills cannot override a model's strong default strategy by retrieval alone — personalization required preference-conditioned retrieval *plus* tool-set scoping to remove the default shortcut.
- Fine geometric operations are bottlenecked by both model perception and automated verification; the Droste-effect case shows the VLM verifier passing visibly wrong placements, with human-in-the-loop remaining the fallback.
- Long, many-step procedures lose fidelity as instructions accumulate: annotation effort, distillation from noisy trajectories, and frozen-model adherence all "leak," and the losses compound — the full tessellated-pattern target visibly degrades even with a correct hand-annotated skill.
- The replay gate is local to its replay set; passing it does not guarantee monotonic improvement over the full user-traffic distribution.
- No human evaluation in the main results, no head-to-head against external skill-evolution baselines, and the primary internal benchmark, traffic, and skill bank are all non-public.

## Relevance

对关注"自进化 agent / 免训练持续适配"的方向高度相关：本文给出了在无验证判据的开放域（专业平面设计）里，用"拓宽+深化"双轴技能库进化加回归安全门控做部署级持续学习的完整方案与实证，其"两种机制必须耦合才有效"的结论对设计任何经验记忆型 agent 系统都有直接参考价值；同时对工具调用型 agent 的技能检索（渐进披露、操作关键词蒸馏）与 LLM 评审偏差控制的工程细节也很值得借鉴。

## Questions for Further Exploration

- How would the evolved bank fare against external memory-evolution baselines (ACE, Dynamic Cheatsheet, SkillAudit, COMFYCLAW) run in the same design environment, rather than only against the no-skill twin?
- Does the Graphic-Eval-driven evolution overfit the judge — e.g., would a small human preference study on the 200 held-out briefs confirm the +13 pp gain at completeness ≥0.9?
- Can the replay gate be made distributionally safe (e.g., high-confidence off-policy bounds over the traffic distribution) instead of case-local, and at what sample cost?
- Would replacing token-overlap retrieval with embedding or graph-of-skills retrieval (the paper's own cited work) change the widening dynamics, since mints currently need refined descriptions just to be surfaced?
- The superadditive interaction is observed at 5 rounds — does it persist, saturate, or collapse as the bank and traffic grow by another order of magnitude, and does the failure-count heuristic (m=2) scale with library size?
- Can the precision/verification ceiling (Droste case) be closed with numeric verifiers or deterministic macros embedded in skills, as the authors speculate, and would that extend skill distillation to the long constructions where it currently fails?
