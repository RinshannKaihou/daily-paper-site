> **一句话总结：** 提出 DRPG 框架，在流式任务流中让一个独立的"策略生成器"从环境二元反馈和历史成败案例中持续蒸馏出可执行的策略要点（≤5 条），叠加在检索式少样本记忆之上；在 6 个基准、7 个 LLM 上以 29/42 的配置胜过最强基线 Self-StreamICL（Wilcoxon p=0.005），其中 text-to-SQL 平均提升 +4.9 个百分点（Spider），但在需要实例级知识的任务（医疗诊断、Python 编程）上与基线持平。

> **TL;DR:** DRPG augments memory-based streaming ICL (Self-StreamICL) with a separate policy generator that continually distills environment-feedback-conditioned, ≤5-bullet actionable policies from retrieved correct+incorrect past cases. Across 6 benchmarks (Spider, CoSQL, BIRD, HotpotQA, DDXPlus, DS-1000) and 7 LLMs, it beats Self-StreamICL in 29/42 configurations (Wilcoxon one-sided p=0.005), with mean gains of +4.9 pts on Spider and +3.9 on BIRD, but is statistically indistinguishable from the baseline on DDXPlus (−0.2) and DS-1000 (−0.3) — policy guidance helps only where errors have recurring, generalizable structure. Cost: ~3x the tokens and ~2 extra components per query vs Self-StreamICL (1,676 in/143 out tokens vs 585/17 on mistral-medium × Spider).

## 核心贡献

- 提出 **DRPG（Dynamic Retrieval-based Policy Generation）**框架：在流式（在线）设置下，将记忆增强检索与一个独立的动态策略生成器结合。策略生成器从检索到的正确与错误历史案例（对比式检索）中合成不超过 5 条可执行策略，注入 agent 的提示词中，从而把"个别案例参考"升级为"跨案例可复用的纠错策略"。
- 严格区分于已有方法：MemPrompt / Self-StreamICL 只检索个别正确案例做少样本参考；Dynamic Cheatsheet 只依赖模型内部信号、不用环境反馈；Reflexion / Self-Refine 不跨查询累积策略；LEAP / Induct-Learn 等离线归纳方法只生成一次固定指导。DRPG 的定位是**在数据流中持续利用环境二元反馈合成策略**。
- 大规模实证：6 个基准（Spider、CoSQL、BIRD、HotpotQA、DDXPlus、DS-1000）、4 类任务、7 个 LLM（Gemini×2、Llama×3、Mistral×2，附录再补 Qwen3.5 与 Gemma4），对 Self-StreamICL 取得 29/42 配置胜率，总体 Wilcoxon 单侧 p=0.005。
- 关键科学发现——**策略生成的收益是任务依赖的**：在错误具有系统性、可复用结构（text-to-SQL 的 JOIN/聚合错误、多跳 QA 的干扰项处理）时大幅有效；在需要实例特定知识（49 选 1 的医疗诊断、跨 7 个 Python 库的 API 细节）时策略会退化为过窄的实例级启发式，收益消失。
- 丰富的消融：策略生成对检索策略（对比/仅对/仅错）鲁棒、可无状态运行（不需要上一轮策略作输入）、可用更小或跨家族模型当策略生成器；无反馈消融证明收益确实来自环境反馈条件化而非"多了一段总结文本"。

## Key Contributions

- **DRPG framework**: continual, feedback-conditioned policy synthesis on top of memory-based streaming ICL. At each step the agent answers with retrieved correct exemplars plus a freshly generated policy; a separate generator reads a contrastive retrieval set (k/2 correct + k/2 wrong) and emits ≤5 actionable bullets; binary environment feedback on each answer is stored and reused.
- **Clear positioning vs. prior art**: unlike per-instance reflection (Reflexion, Self-Refine), one-shot offline induction (LEAP, Induct-Learn), internal-signal-only memory (Dynamic Cheatsheet), and exemplar-only memory (MemPrompt, Self-StreamICL), DRPG continually distills transferable strategies grounded in environment correctness labels within a stream.
- **Broad evaluation**: 6 benchmarks × 7 LLMs (plus Qwen3.5-122B-A10B and Gemma-4-31B in the appendix), 4 task categories, with pairwise Wilcoxon significance tests — unusually rigorous statistical hygiene for this genre.
- **Task-dependence finding**: policy-level guidance pays off exactly where error patterns are compositional and recurring (text-to-SQL, multi-hop QA), and degenerates into narrow instance-specific heuristics on tasks needing instance-level knowledge (DDXPlus diagnosis, DS-1000 library APIs) — actionable guidance for practitioners on *when* to deploy policy adaptation.
- **Modularity ablations**: robustness to retrieval composition, stateless operation (feeding P_{t−1} does not help), and cross-model policy generation where a small model (scout, mistral-small) as generator for a stronger agent (maverick) even repairs the same-model failure mode on HotpotQA (63.73 vs 50.60).

## Methodology

DRPG runs in the StreamBench online protocol: a stream of instances x_1..x_T arrives one at a time, and each answer ŷ_t receives binary correctness feedback fb_t from the environment h(x_t, ŷ_t). The memory database stores triplets (x_i, ŷ_i, fb_i).

Per step:
1. **Agent retrieval**: top-k past examples with positive feedback only, R_t = r(x_t, {correct past}, k), mirroring Self-StreamICL (k=16 for Spider/CoSQL/BIRD/DDXPlus; k=4 for HotpotQA/DS-1000 to fit context windows).
2. **Contrastive policy retrieval**: a second retriever r′ fetches k/2 correct and k/2 incorrect cases (R′_t = R′_{t,1} ∪ R′_{t,0}).
3. **Policy generation**: a (possibly different) LLM g synthesizes P_t — at most five concise, actionable bullet points — from R′_t, using a task-adapted template (role + reference materials + instructions; full templates in Appendix I).
4. **Answering**: ŷ_t = f(x_t, R_t, P_t) — the agent conditions on question, retrieved successes, and the policy.
5. **Feedback + memory update**: fb_t stored; the loop continues.

Infrastructure is deliberately un-tuned: the retriever (BAAI/bge-base-en-v1.5, cosine similarity via FAISS, question-only embedding key) is StreamBench's pipeline reused verbatim and shared by all methods; prompts follow StreamBench's structure; temperature 0, max 1,024 output tokens, fixed shuffle seed 42. Metrics are dataset-standard: execution accuracy (text-to-SQL), exact match (HotpotQA), accuracy (DDXPlus, 49-way), pass@1 (DS-1000). Baselines: Zero-shot, Self-Refine, and Self-StreamICL (the main baseline, which itself dominates GrowPrompt and MemPrompt). ToolBench is excluded (LLM-judge metric); Dynamic Cheatsheet is not run (implementation does not cover these datasets) — a no-feedback DRPG variant serves as the controlled stand-in.

## Results & Highlights

- **Overall vs. the strongest baseline**: DRPG beats Self-StreamICL in 29/42 model–dataset configurations, Self-Refine in 35/42, and Zero-shot in 35/42; across all 42 paired configurations the win over Self-StreamICL is significant (one-sided Wilcoxon p = 0.005).
- **Text-to-SQL is where the gains live**: 18/21 configurations beat Self-StreamICL; per-dataset mean deltas (DRPG − Self-StreamICL) are +4.9 pts on Spider (two-sided p = 0.016), +2.0 on CoSQL (p = 0.031), +3.9 on BIRD (p = 0.078). Largest single cells: llama-4-scout on Spider 76.85 vs 68.33 (+8.5 pts), llama-4-scout on BIRD 39.50 vs 31.23 (+8.3 pts), llama-3.3-70b on BIRD 41.98 vs 33.77 (+8.2 pts).
- **No significant harm on instance-specific tasks, but no gain either**: mean deltas −0.2 pts on DDXPlus (p = 0.938) and −0.3 on DS-1000 (p = 0.734), with only 3/7 wins each; HotpotQA averages −1.0 (p = 0.547) despite 5/7 wins, dragged down by llama-4-maverick collapsing to 50.60 vs 62.73 for Self-StreamICL (−12.1 pts) — the policy occasionally overrides correct multi-hop reasoning.
- **Environment feedback is the active ingredient** (no-feedback ablation, llama-3.3-70b): DRPG beats its label-free variant on all six datasets — BIRD 41.98 vs 35.07, DDXPlus 70.24 vs 57.43, DS-1000 72.90 vs 61.50 — showing the gains come from feedback-conditioned policies, not from appending any summarized text.
- **Cross-model policy generation**: with maverick as agent, using scout or mistral-small as the policy generator restores HotpotQA to 63.73 / 63.07 vs 50.60 with self-generated policies, so cheaper cross-family generators are viable (agent capability remains the dominant factor).
- **Generality on two more families** (thinking mode disabled): qwen3.5-122b-a10b — DRPG beats Self-StreamICL on 4/6 datasets (e.g., BIRD 35.72 vs 32.10); gemma-4-31b-it — DRPG wins 5/6 (BIRD 38.01 vs 27.51, DS-1000 72.80 vs 64.60), notably where Self-StreamICL itself falls *below* zero-shot (BIRD 27.51 < 36.70), suggesting policy guidance is more robust than raw exemplar accumulation for some models.
- **Cost**: per query (mistral-medium × Spider, N=2,147) DRPG uses 2 retrievals + 2 LLM calls and 1,676 in / 143 out tokens at ≈9.3 s, vs Self-StreamICL's 1 + 1, 585/17 tokens, ≈5.3 s — roughly 3x the tokens and ~1.75x latency for the gains above.

## Critical Assessment

- **Novelty**: moderate and honestly framed. The authors themselves state the novelty "lies less in its individual components than in the capability their combination enables" — retrieval memory (MemPrompt/Self-StreamICL), LLM principle induction (LEAP, Induct-Learn), and streaming evaluation (StreamBench) all pre-exist; the contribution is *continual, feedback-conditioned* policy synthesis. This is a real delta but an incremental one, and the closest feedback-conditioned competitor, Dynamic Cheatsheet, is absent from the comparison because "its implementation supports only specific datasets" — a self-serving exclusion, even if partially compensated by the Appendix F no-feedback ablation.
- **Rigor**: above average. Paired Wilcoxon tests over all 42 configurations, per-dataset tests, per-cell deltas visualized, prompt structure held constant across methods, retriever reused unmodified from StreamBench, and an explicit limitation that pooled significance is driven by text-to-SQL (three of six datasets are text-to-SQL, i.e., half the configurations). But: a single fixed ordering (seed 42) with temperature 0 and **no variance reported across runs** — in a streaming method where order effects plausibly matter, that is a genuine gap they acknowledge.
- **Reproducibility**: good on paper (fixed seed, temperature, shared retrieval config, full prompts in Appendix I, exact model version strings like mistral-small-2503 and gemma-4-31b-it), but no code release is mentioned, and the idealized setting (dense, clean, binary, instantaneous correctness feedback on *every* step) is far from deployment — as they concede, execution accuracy on SQL doesn't even certify semantic correctness.
- **Significance**: the headline "outperforms strong baselines across most datasets and models" needs unpacking — on 3 of 6 datasets (HotpotQA, DDXPlus, DS-1000) the difference is not significant in either direction, and on those same tasks DRPG loses nearly half the model configurations (e.g., llama-4-scout DDXPlus 50.79 vs 61.05, −10.3). The useful, durable contribution is the *when-it-works* characterization, not universal superiority.
- **Red flags**: (1) the maverick-on-HotpotQA −12.1 pt collapse shows the policy can actively harm and is only "hypothesized" to be over-triggered reasoning overrides — no mechanism analysis; (2) the Gemma appendix reveals the main baseline itself is brittle (Self-StreamICL below Zero-shot on BIRD/DS-1000), so some DRPG "wins" partly ride on baseline fragility rather than policy quality; (3) no reasoning LLMs evaluated (GPT-o3, DeepSeek R1 excluded for budget), which matters because policy bullet points may be redundant for models that already self-critique; (4) ~3x token cost per query vs Self-StreamICL is nontrivial for a method whose mean gain outside text-to-SQL is ≈0.

## Strengths

- Attacks a precise, well-motivated gap: prior streaming memory methods re-supply *examples* but never synthesize *what to do differently*, so identical error types recur.
- The task-dependence analysis (Section 5.2) is the paper's best science — concrete generated-policy excerpts show *why* Spider policies ("Validate Schema and Relationships") generalize while DDXPlus policies ("Consider Cardiovascular Diseases for Chest Pain") collapse into narrow disease heuristics.
- Ablation coverage is thorough: retrieval composition, policy continuity (stateless works fine), cross-model generators, and a no-feedback control that cleanly isolates the causal ingredient.
- Statistical testing (Wilcoxon, per-dataset and pooled) with negative results reported in-table rather than buried — DDXPlus/DS-1000 parity is stated plainly.
- Cost transparency: full per-configuration token counts (Appendix B) and a score-vs-output-tokens plot let readers judge the price of the gains.

## Limitations

- Idealized feedback: dense, clean, binary, per-step correctness labels — real deployments face sparse, delayed, noisy, or partial feedback; robustness under degraded feedback is untested (acknowledged).
- Single data ordering (seed 42), temperature 0, no variance across runs; streaming order sensitivity unexplored.
- No reasoning LLMs (no GPT-o3 / DeepSeek R1), no OpenAI/Claude families in the main table; thinking modes of Qwen/Gemma had to be disabled, so behavior with reasoning traces is unknown.
- Dynamic Cheatsheet — the most conceptually similar feedback-free baseline — is not empirically compared.
- Per-query cost roughly triples relative to Self-StreamICL (1,676 vs 585 input tokens, 143 vs 17 output tokens, 2 vs 1 LLM calls on mistral-medium × Spider), which buys nothing on instance-specific tasks.
- Known failure mode left undiagnosed: policies can override correct agent reasoning (maverick HotpotQA −12.1), with only a hypothesis offered.
- Prompt-paraphrase sensitivity untested despite policies being injected into prompts.

## Relevance

高度契合"Self-Evolving Agents"方向：DRPG 本质上是一个在数据流中借助环境反馈持续自我改进的 LLM Agent 架构，其"何时策略级指导有效/失效"的任务依赖性结论，对设计长期运行的自进化 agent 记忆与反思机制有直接参考价值。

## Questions for Further Exploration

- How does DRPG behave when feedback is sparse (only a random ρ fraction of steps labeled) or delayed — does the advantage over feedback-free methods like Dynamic Cheatsheet scale with feedback density, as the authors' own limitation section hypothesizes?
- Would an explicit confidence gate that drops or down-weights the policy when the agent's retrieval set is highly confident have prevented the llama-4-maverick HotpotQA collapse (50.60 vs 62.73)?
- Do reasoning models (o3-style, DeepSeek R1) that already perform internal self-critique benefit at all from injected policies, or does policy text merely consume context?
- Can the policy generator be made hierarchical — general task-level rules plus instance-cluster-specific sub-policies — to fix the degeneration into narrow heuristics observed on DDXPlus and DS-1000?
- Since policies are stateless and regenerated per step, is there a cheaper amortization (e.g., regenerate only when retrieval distribution shifts, or every N steps) that preserves the gains at Self-StreamICL-level cost?
- How sensitive are the results to stream ordering and non-stationary task mixtures (e.g., interleaved SQL and QA), given the single-seed, single-dataset-stream evaluation?
