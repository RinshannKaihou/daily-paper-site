Why this matters

If agent-built memory can substitute for fine-tuning, open models become credible in new environments — and trustworthy self-verification becomes the field's bottleneck.

⚠ Critical edge

The headline is not a full re-run: only 41 of 82 OSWorld tasks (19 of 67 on ALE) were re-run under RSI — the rest retain baseline scores — and cross-system numbers come from unmatched leaderboard protocols.

DRS also practices on the target itself, blurring environment-level adaptation vs. verifier-guided per-task retries; on ALE binary (50.75) it still loses to GPT-6 Astra (52.24).

01 Methodology — the recursive loop

CURRICULUM
decides what to practice next
→
ACTOR
code-as-policy + evolvable memory
→
VERIFIER
reads raw env feedback only
verdict gates ▸ MEMORY (causal rules, scripts, lessons) — frozen at test time ▸ feeds next curriculum
BRS · broad
parallel waves, ≤8 projects, 4 concurrent — coverage
DRS · deep
serial self-escalation — corner cases, hidden constraints
❄ FREEZE
memory locked; actor only retrieves at test time

No gold labels, no humans, no parameter updates. The curriculum agent invents practice tasks (prerequisites, informative variants, stress tests) from the target query and accumulated memory. The actor executes every action as an executable program (e.g. FreeCAD Part.makeCylinder + doc.recompute()), carrying memory that is added-to, corrected, and pruned after each verified outcome. The verifier is isolated from the actor's private reasoning to avoid correlated errors; only its pass/fail verdict consolidates memory. Stack: GLM-5.3 actor, Kimi-K3 verifier/curriculum, GPT-5.4 reference grading.

03 Strengths

  • Clean formulation — adaptation as causal discovery consolidated into reusable memory, mapped onto a human identify → interact → distill analogy.
  • Design validated, not just told — the ablation shows deep-only exploration can fall below the no-memory baseline.
  • Training-free and model-agnostic — the same frozen memory improves different open-source backbones.
  • Exceptionally honest reporting — mixed aggregates, unmatched protocols, and an audited failure-mode taxonomy are disclosed in appendices.
  • Broad scope — beats the Play2Code continual-improvement baseline on game generation too.

04 Limitations

  • Heavy test-time compute — recursive exploration and per-target practice grow memories to ~140–317 KB per task lineage; cost is the paper's own first limitation.
  • Aggregation protocol weakens claims — mixed 41/82 and 19/67 RSI-vs-baseline sets, headroom-based task selection, unmatched budgets.
  • Verifier fragility — wrongly verified experience ("missing-data markers are valid answers") gets consolidated and reused; quantified, but unsolved.
  • Components not isolated — small-n ablation assembled from historical runs; stopping and budget policies unexamined.
  • Narrow domain coverage — two computer-use benchmarks plus games; science domains untested.

05 Questions for further exploration

  • Q1Do gains survive a full matched re-run of all 82/67 tasks with equal baseline compute, instead of the mixed aggregate?
  • Q2How much is reusable environment memory vs. plain repeated attempts on the target? A frozen-memory A→B transfer test would settle it.
  • Q3Can the verifier be hardened (rubric checklists, ensembles, ground-truth probes) so bad rules never enter memory?
  • Q4What is the marginal value of causal action–condition–consequence memory vs. flat trajectory storage past ~300 KB?
  • Q5Does the curriculum's stopping criterion track real knowledge coverage — or just saturate the 8-project budget?
