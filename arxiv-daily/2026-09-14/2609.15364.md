> **一句话总结：** RSIAgent 是一个免训练的多智能体自提升框架，通过"课程-执行-验证"递归循环对新环境进行先广后深的自主探索，把可复用的因果经验沉淀为冻结记忆，使 GLM-5.3 + Kimi-K3 在 OSWorld 2.0（78.98 vs 72.60 partial）和 Agent's Last Exam（84.82 vs 82.26 partial）上以 partial 分数超过 GPT-6 Astra 等前沿闭源模型。

> **TL;DR:** RSIAgent is a training-free multi-agent framework (curriculum + actor + verifier agents) that autonomously explores a new digital environment in a broad-then-deep recursive loop and consolidates verified experience into a frozen, reusable memory — no parameter updates. On OSWorld 2.0 (0808 offline, 82 tasks) it lifts its own GLM-5.3/Kimi-K3 harness from 71.97 to 78.98 partial score (and 37.80 to 42.68 binary), beating the reported GPT-6 Astra baseline of 72.60 by 6.38 points; on Agents' Last Exam Near-term (67 tasks) it reaches 84.82 partial (+2.56 over GPT-6 Astra's 82.26), though its binary accuracy (50.75) still trails GPT-6 Astra (52.24). Caveat: the headline aggregates mix RSI-rerun scores (41/82 OSWorld, 19/67 ALE tasks) with retained baseline scores, and cross-system numbers come from unmatched leaderboard protocols.

## 核心贡献

- 提出 **RSIAgent**，一个面向新环境的免训练递归自提升（recursive self-improvement）多智能体框架：课程智能体（curriculum agent）决定探索方向并生成练习任务，执行智能体（actor agent）以 code-as-policy 方式与环境交互并维护可演化记忆，验证智能体（verifier agent）独立地基于环境反馈判定成败——三者构成递归闭环，无需金标签或人工监督。
- 设计**先广后深**（broad-then-deep）两阶段探索策略：广度递归自探索（BRS）并行铺开多个方向以快速建立环境整体理解（名义预算 8 个探索项目、最多 4 个并发）；深度递归自探索（DRS）串行递进地冲击困难案例、隐藏约束与边界条件——类比 LLM 的"预训练-后训练"范式。
- 探索产出的记忆（含动作-条件-后果的**可复用因果关系**）最终冻结，测试时直接复用于下游任务，不改模型参数；实验显示该框架让开源模型（Kimi-K3、GLM-5.3）在 OSWorld-v2 与 Agent's Last Exam 上反超 GPT-6 Astra、Claude Opus 5 等闭源前沿模型（partial 分数口径）。
- 给出诚实的失效模式分析：定位了**探索不够聚焦、验证不完整、记忆固化不可靠**三类相互作用的失效机制（例如验证器在字段无依据时仍判 PASS、错误规则"缺失数据标记可当有效答案"被固化进记忆并被后续复用）。

## Key Contributions

- **RSIAgent**: a training-free multi-agent framework for recursive self-improvement in new environments, coordinating a curriculum agent (decides what to practice next), an actor agent with evolvable persistent memory (executes code-as-policy actions), and a verifier agent that grounds pass/fail judgments in raw environment feedback while being isolated from the actor's private reasoning to reduce correlated errors — no gold labels, no human supervision, no parameter updates.
- **Broad-then-deep exploration strategy**: Broad Recursive Self-exploration (BRS) runs parallel task waves across diverse directions (nominal budget of 8 exploration projects, up to 4 concurrent) to build broad environment coverage; Deep Recursive Self-exploration (DRS) then sequentially escalates task difficulty to expose corner cases, hidden constraints, and boundary conditions — explicitly framed as analogous to the pretraining-then-posttraining paradigm.
- **Causal, reusable memory that is frozen at test time**: the memory stores environment-specific knowledge, reusable procedures/scripts, and failure lessons (including causal relations between actions, conditions, and consequences); after exploration it is frozen and directly reused, with curriculum agent and memory writes disabled.
- **Empirical reversal of the open/closed-source gap (on partial score)**: with GLM-5.3 as actor and Kimi-K3 as verifier/curriculum, RSIAgent surpasses reported frontier-model scores on both benchmarks, and an honest failure-mode audit identifies three interacting mechanisms (insufficiently targeted exploration, incomplete verification, unreliable memory consolidation) that limit further self-improvement.

## Methodology

The framework formalizes a digital agent as a policy generating code-formatted actions conditioned on the interaction history and a persistent memory that survives across tasks (Section 2). Three roles form the recursive loop (Section 3.2): (1) the **curriculum agent** generates practice tasks from the target query, accumulated memory, and prior outcomes — choosing prerequisite skills, informative variants, failure-driven practice, and stress tests — until further tasks are unlikely to add knowledge; (2) the **actor agent** is the primary policy (code-as-policy: every action is an executable program, e.g., FreeCAD's `Part.makeCylinder` + `doc.recompute()`), equipped with an evolvable memory that is revised (added to, corrected, pruned) after each verified outcome and inherited by subsequent actor instances; (3) the **verifier agent** independently inspects environment feedback (execution results, interface states) — not the actor's reasoning — and returns a success/failure verdict plus feedback that gates memory consolidation.

Exploration proceeds in two stages (Section 3.3). **BRS** iterates: propose multiple tasks spanning different directions → execute and verify in parallel → use accumulated experience to identify knowledge gaps → propose more informative tasks. **DRS** is sequential and self-escalating: propose a challenging task likely to expose hidden constraints → attempt it with current memory → verify → consolidate → propose a harder follow-up. Implementation uses a shared code-as-policy harness with GLM-5.3 as the default actor and Kimi-K3 as verifier and curriculum agents in separate contexts; the reference evaluator uses GPT-5.4 where model-based grading is required (GPT-4o user simulator). At test time the memory is frozen and the actor simply retrieves and applies stored procedures, constraints, and lessons under verifier checking. The design builds on StructAgent's unified state and structured workflow.

## Results & Highlights

- **OSWorld 2.0 (0808 offline, 82 tasks), partial score**: RSIAgent reaches 78.98% vs 71.97% for the same harness without RSI (+7.01 points) and 42.68% vs 37.80% binary (+4.88); this exceeds the reported GPT-6 Astra partial score of 72.60 by 6.38 points and Claude Opus 5's 70.19.
- **Agents' Last Exam (Near-term, 67 tasks), partial score**: RSIAgent reaches 84.82% vs 83.75% without RSI (+1.07) and 50.75% vs 49.25% binary (+1.50); partial is 2.56 points above GPT-6 Astra (82.26), but binary (50.75) remains below GPT-6 Astra's 52.24 — the paper itself flags that the partial-credit advantage does not extend to every metric.
- **Stage ablation (4 OSWorld tasks: T080/T085/T089/T106)**: Full RSI achieves a mean partial score of 74.54% vs 65.52% for broad-only (w/o DRS) and 56.50% for deep-only (w/o BRS); deep-only exploration actually falls below the no-memory baseline on T085 and T089, supporting the broad-then-deep combination.
- **Per-task RSI dynamics**: by RSI step 8, tasks T044 (video editing), T049 (presentation repair), and T065 (railway booking) reach 100%, 80%, and 100% partial score respectively from their w/o-RSI baselines (T080 baseline was 68.69, T106 5.00 → 54.06 under full RSI in the ablation set).
- **GameCraft-Bench (40 sampled game-development tasks)**: across all four base generators, full RSIAgent beats both the frozen baseline game and Play2Code on Overall quality — e.g., Codex+GPT-5.5-generated games: 52.77 baseline → 51.05 with Play2Code (a regression) → 61.28 with RSIAgent; Kimi-K2.6-generated games: 31.28 → 36.02 (Play2Code) → 46.37 (RSIAgent). Play2Code's benefit shrinks or reverses on strong base games, while RSIAgent improves both weak and strong ones.

## Authors & Credibility

Authors are from Aether AI (an industry lab), UC San Diego, and University of Illinois Chicago; Sibo Zhu, Shicheng Fan, and Xinyue Wang are equal contributors who did the work during Aether AI internships, with Kun Zhou as corresponding author/project lead and Biwei Huang as senior author. Code (github.com/AetherLabsAI/RSIAgent) and a project website are released. The 50-page paper includes unusually transparent appendices: Appendix C.3/C.4 documents exactly which tasks were re-run under RSI versus retaining baseline scores, how the expansion cohort was selected, and that cross-system comparisons use unmatched protocols; Appendix E provides journal-linked memory snapshots (file counts and byte totals verified against journals). The self-critical failure-mode analysis (with audited percentages per subtype) further strengthens credibility, though the intern-driven structure and partial use of "historical" runs suggest an engineering-heavy, less controlled evaluation process.

## Critical Assessment

- **Novelty**: Moderate-to-good. The curriculum-actor-verifier loop, code-as-policy actions, and frozen reusable memory individually have clear precedents (Voyager's automatic curriculum, CodeAct, EchoTrail-GUI/ZhuLong exploration, CoEvoSkills/Recuris verification-driven skill refinement — all cited). The genuine novelty is the disciplined two-stage BRS→DRS curriculum plus the explicit framing of memory as causal knowledge (action-condition-consequence), and the demonstration that this alone flips an open-vs-closed-source leaderboard comparison.
- **Rigor / headline-number caveats (the biggest issue)**: the reported RSI aggregates are *not* full benchmark re-runs. Per Appendix C.4, the OSWorld RSI row replaces baseline scores with only 41 of 82 task results (the other 41 retain baseline scores), and the ALE row combines 19 RSI scores with 48 baseline scores. Exploration was explicitly directed at tasks "with remaining room for improvement" (below full credit), so the aggregate partially reflects selected reruns of tasks with headroom rather than uniform re-evaluation. The comparison to GPT-6 Astra, Claude Opus 5, etc. copies leaderboard/official-report numbers under different harnesses and budgets ("the cross-system comparison does not use a matched evaluation protocol"), and on ALE binary accuracy RSIAgent (50.75) still loses to GPT-6 Astra (52.24).
- **Test-time practice on the target itself**: Appendix E states "In these runs, DRS includes practice on the target itself," and the curriculum agent uses the target query as a reference during both stages. This blurs the line between *environment-level* adaptation (the paper's claim) and *per-task* test-time practice with verifier-guided retries — a regime closer to repeated attempts with self-grading than to generalizable skill acquisition. The memory-growth stats (e.g., T044's frozen memory of 316,541 bytes accumulated across ~10 BRS projects plus DRS on one task family) underline that the gains are bought with heavy per-task compute.
- **Ablation weakness**: the stage ablation covers only 4 tasks; "Full RSI bars average two historical evaluations," the w/o-RSI condition reuses "the recorded historical baseline," and w/o BRS is capped at two practice projects — a small-n, historically-assembled comparison rather than a controlled rerun. The paper admits the experiments "do not fully isolate the contribution of every" component.
- **Verifier reliability**: the verifier is a model (Kimi-K3) reading environment feedback, and the paper's own audit found it returning PASS on unsupported field values and artifact discrepancies — incorrect verdicts propagate into memory (rules such as "treat missing-data markers as valid answers" were retained and reused), which is the framework's central fragility, honestly documented but unsolved.
- **Reproducibility**: code is promised, prompts and budgets are documented in appendices, and memory snapshots are hash-verified — good. But results depend on GLM-5.3/Kimi-K3 (GLM-5.3 is one of the framework's own lab models, and "GLM-5.3-Flash" also appears as a game generator in Appendix D), on GPT-5.4-based reference grading, and on historical evaluation records that will be hard for third parties to regenerate exactly.
- **Significance**: if the partial-score gains survive a matched, full re-run protocol, agent-level memory construction as a substitute for fine-tuning is a significant result for the field; as reported, it is a strong but softened claim.

## Strengths

- Clean, well-motivated formulation: adaptation to new environments as causal discovery consolidated into reusable memory, with a human-learning analogy (identify → interact → distill) that maps directly onto the curriculum-actor-verifier loop.
- The broad-then-deep decomposition is validated by the ablation (deep-only exploration can fall below the no-memory baseline on T085/T089), giving real evidence for the design rather than just architecture storytelling.
- Training-free and model-agnostic in principle: the same harness improves different open-source backbones, and the frozen memory transfers to downstream execution without further updates.
- Exceptionally honest reporting for a leaderboard-focused paper: explicit accounting of mixed RSI/baseline aggregates, unmatched protocols, the ALE binary loss to GPT-6 Astra, and an audited failure-mode taxonomy with concrete bad-memory examples.
- Broad evaluation scope beyond the two headline benchmarks (game development on GameCraft-Bench, where it beats the Play2Code continual-improvement baseline and consistently improves both weak and strong base games).

## Limitations

- Substantial test-time compute cost: recursive exploration and per-target deep practice (memories growing to ~140–317 KB per task lineage) make the method expensive per task; the paper lists computation cost as its first limitation.
- Aggregation protocol weakens the headline claims (mixed 41/82 and 19/67 RSI-vs-baseline score sets, headroom-based task selection, unmatched cross-system budgets).
- The verifier agent can approve executions that fail the official rubric, and wrongly verified experience is consolidated into memory and reused — the failure-mode analysis quantifies this but offers no mechanism-level fix.
- Performance depends on finite exploration budgets, stopping policies, and memory quality; different environments may need different tools, verification signals, and exploration strategies, and component contributions are not fully isolated.
- Only two main computer-use benchmarks plus one game benchmark; generalization to other interactive domains (the paper's own future-work list: AI for Science, broader games) is untested.

## Relevance

高度契合"自我进化智能体与自动化研究"这一首要兴趣方向：RSIAgent 正是免训练的递归自提升智能体框架，覆盖自主探索循环、可演化记忆与长程自主系统的可靠性/可信性（论文自身的失效模式分析——错误验证如何污染记忆——正是自主智能体可信赖性问题）。它不涉及训练稳定性或 SDC 检测等基础设施主题，但作为 self-evolving agent 方向的代表性工作值得精读。

## Questions for Further Exploration

- How much of the OSWorld/ALE gain survives if *all* 82/67 tasks are re-run under RSI with a matched compute budget for the baselines, rather than the documented mixed aggregate?
- Since DRS practices on the target itself with verifier feedback, how do gains decompose between genuinely reusable environment memory and simple repeated-attempt effects? A frozen-memory-transfer test (build memory on task set A, evaluate on held-out set B within the same environment) would settle this.
- Can the verifier be hardened against the documented PASS-on-discrepancy failures (e.g., rubric-grounded checklists, ensembles, or environment-side ground-truth probes) so that bad rules do not enter memory?
- What is the marginal value of the causal (action-condition-consequence) memory structure versus flat trajectory/rule storage, and how does retrieval scale as memory grows past ~300 KB per environment?
- Does the curriculum agent's stopping criterion (practice until "unlikely to contribute substantial new knowledge") correlate with measured knowledge coverage, or does it just saturate the budget — and how sensitive are results to the 8-project BRS cap and 2-project DRS caps used in the ablations?
