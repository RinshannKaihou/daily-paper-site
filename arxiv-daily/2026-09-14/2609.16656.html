⚠ Critical edge

“W4A4” here quantizes only the backbone linear layers — state-space ops, convs, and softmax all stay FP32 — so the headline numbers are a mixed-precision result, and the closest Mamba-family PTQ rivals never appear in the comparison.

The W4A4 win over PTQ4VM is also thin: +0.1 to +0.9 pts; MambaQuant / QMamba / Quamba / SSDi8 are cited but not benchmarked.

Methodology distilled

CTOAC quantizes a deliberately narrow slice of VSSD: backbone linear layers’ weights (signed symmetric, per-output-channel) and the activations entering them (static affine, one scale/zero-point per layer). Everything else — state-space computation, convolutions, normalization, softmax, residuals — stays FP32.

  1. Quantize & freeze weights; record the FP reference output for each target layer.
  2. Initialize per-input-channel clipping bounds α, β from calibration activations (shared across batch and tokens).
  3. Iterate: clip per channel → refit the shared scale/zero-point → quantize → measure the token-balanced loss on linear outputs → update only the bounds (straight-through estimator).
  4. Refit & freeze everything for fully static inference — no dynamic quantizers at runtime.

TB-NMSE: each token’s output error is normalized by that token’s FP output norm before averaging uniformly over tokens — so high-energy token positions cannot dominate calibration.

256 unlabeled calibration images (ImageNet-1K); task heads stay FP32 with per-task recalibration. Deliberately avoids AdaRound weight rounding, Hessian/Fisher surrogates, and task-level losses.

Strengths

  • Clean, well-motivated diagnosis — the weight-vs-activation split ties the observed pathology directly to the two design axes.
  • Model ablation practice — shared range → channel clipping → output-aware optimization attributes gains to specific components, not just end numbers.
  • Simple, static method — token-balanced loss is well-argued and needs no dynamic quantizers at inference.
  • Broad validation — 3 scales × 5 precisions × 3 downstream tasks, with real GPU kernel measurements instead of estimated FLOPs.
  • Candid deployment framing — openly reports W8A8 slowdowns and non-arithmetic latency behavior.

Limitations

  • Partial quantization scope — state-space ops, convs, softmax stay FP32; a fully quantized VSSD is left unaddressed.
  • Missing rival comparison — no empirical results vs MambaQuant, QMamba, Quamba, or SSDi8; the niche’s practical ranking is unresolved.
  • Relative, not absolute, 3-bit robustness — W4A3 on VSSD-Tiny still loses 36.7 pts; small backbones suffer large drops.
  • VSSD-only, vision-only — no ViM / VMamba / Mamba LMs; generality is asserted rather than demonstrated.
  • Reproducibility gaps — optimizer, learning rate, iteration count K unstated; no code release mentioned.
  • Modest speedup — 1.42× is configuration-specific (RTX 4090, batch 32); edge scenarios untested.

Questions for further exploration

  1. How much of CTOAC’s advantage survives if the scope extends to the full VSSD block (state-space ops, convs, softmax) — toward a genuinely integer-only model?
  2. Would combining channel-wise clipping with rotation / smoothing methods (MambaQuant-style variance-aligned rotations, Hadamard transforms) close the W4A3/W3A3 gap on Tiny/Small?
  3. Why is VSSD-Base far more quantization-tolerant (76.9% at W4A3) than Tiny (47.0%) — wider channels smoothing outliers, or different token-extreme distributions?
  4. Can TB-NMSE extend to block-level or end-to-end reconstruction without giving up static inference — and would that fix the non-monotonic W4A3/W3A3 behavior on VSSD-Small?
  5. Does the same activation pathology appear in causal Mamba language models, where token positions carry semantic rather than spatial meaning?
  6. What are the energy/latency trade-offs on edge accelerators (INT4 NPUs, mobile SoCs), where the 1.42× RTX 4090 result may not transfer?
