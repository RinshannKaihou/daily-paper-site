Why this matters

A blueprint for self-improving agent knowledge bases: typed, verifiably-gated edits — not free-form prompt rewrites.

对构建自改进的数据智能体知识库有直接参考价值：以可验证门控的类型化编辑取代自由改写 prompt，同时打通 text-to-SQL 语义鸿沟与 agent 记忆机制。

Critical edge

Every edit must pass paired validation on labeled tasks with an automatic scorer — evolution compute is unreported and likely the dominant expense.

Methodology

An ontology as a runtime service, built and repaired by agents

Ontology state L = (Content S, Schema Γ, Tools R); only a compact session manifest ever enters the prompt.

Content STyped semantic graph — Terms · Mappings · Constraints · Evidence, linked by Semantic Relations and Structural References.
Schema ΓObject model + admissible reference patterns, so capacity grows without rewriting content.
Tools RMCP endpoints browse(q,k,n) and resolve(I,c) — the agent pulls only task-relevant semantics, per step.
01
Diagnose
Cluster recurring failure signatures from trajectories.
02
Attribute
Map each signature to one level: Content / Tool / Schema.
03
Patch
A localized, typed edit at that single level only.
04
Gate
Paired validation, same budgets; below margin τ → rollback + log.

Builder: candidates mined from the training workload are committed only after probe queries verify type, filters, and value distributions — every entry is evidence-anchored, no manual authoring.
Protocol: reciprocal two-fold evaluation (A→B, B→A averaged); 70% of a fold builds/evolves, 30% validates; ontology frozen before testing on the held-out fold. Each backbone evolves independently from the same L₀.

Credibility
ruc-datalab (RUC) — established text-to-SQL / data-agent group code released at github.com/ruc-datalab/EvoOntology leakage-conscious two-fold protocol, official benchmark settings negative results reported honestly, not buried
Strengths
  • Semantic layer as a versioned runtime service — actively queried via MCP instead of passively stuffed into prompts; the −15.0 static-prompt result is direct evidence.
  • Gate with rollback + rejection log is a genuinely principled safeguard against self-modification regressions — confirmed most load-bearing (−11.2 without it).
  • Evidence-grounded commitment: entries anchored by probe results, not natural-language claims; Mappings/Evidence prove load-bearing (−13.4 / −8.7 when masked).
  • Complete empirical story: builder-vs-evolver decomposition, monotonic convergence, content-growth control, token accounting, worked case study.
Limitations
  • Needs labeled workload + automatic scorer for paired validation; open-ended domains without ground-truth evaluators unaddressed.
  • Evolution compute never quantified (builder + evolution + 2× paired runs per candidate) — likely substantial.
  • Gains are benchmark-skewed: InsightBench only +1.9 Overall; short-reference scoring saturates.
  • N backbones → N divergent ontologies (Jaccard ≤ 0.62; cross-use costs ≥ 6.6 pts) — maintenance multiplies.
  • Weaker open-source backbones excluded from all ablations (Qwen3.5-Flash: 19.1 Traj-Wise even with EvoOntology); no Spider 2.0-style enterprise test.
Open questions
  1. Can a cheaper proxy — small critic model, execution-based self-consistency — replace the Gate when no labeled validation set exists, without reintroducing regressions?
  2. What is the full training-time cost (builder + evolution + 2× paired validation per candidate), and how does it amortize as the workload grows?
  3. Would one backbone-agnostic ontology plus lightweight per-backbone tool manifests recover most of the gains, avoiding N divergent stores?
  1. How does it behave under schema drift or adversarial evidence — does the Gate detect semantic corruption, not just score regressions?
  2. Does the approach transfer beyond data analytics — coding or web agents — where “evidence grounding” is harder to define than probe queries?
  3. Can attribution be verified causally, e.g. by cross-applying patches attributed to one level but applied at another?
