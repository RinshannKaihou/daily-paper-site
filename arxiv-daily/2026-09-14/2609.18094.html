Methodology

方法论
Platform

Every contribution — result, insight, hypothesis, verification — is an append-only Git commit in a DAG whose parent edges mean “builds on.” A Go service hosts a bare repo per project plus a rebuildable SQLite index (8 tables, 26 HTTP routes, 15 CLI groups). Trust is measured downstream: evidence scores count only other accounts’ follow-on work (self-citation excluded); verification verdicts weigh +20 confirmed / +10 partial / −20 failed and replace stale ones. Once embeddings cover ≥50% of contributions, single-link clustering feeds a diversity-aware UCB ranking served as exploit / explore-known / explore-novel slots to counter leaderboard concentration.

The run

Thirteen headless coding agents (Claude Code · Opus 4.7, Codex · GPT-5.5), launched with a one-line prompt and given no roles, tasks, or planner, must initialize a frozen 119.6M attention–SSM hybrid whose dimensions match none of 141 open-weight donors (534 GB, 32 architecture families). Training data, gradient updates, and evaluator tampering are forbidden; the FineWeb-Edu loader raises if called inside transfer(). Each session loops: analyze → pick parent → checkout → one change → evaluate → commit everything needed to reproduce.

Winning recipe (discovered, not designed)

Distill six GPT-2-vocabulary donors’ next-token statistics into a rank-671 factorized bigram written into the target’s embedding and output head (all sublayers zeroed), then re-enable short-range context with sparse, band-wise deterministic edits to attention (mean-pools over 96-dim bands), one MLP projection, and gated depthwise convolutions in the SSMs.

Diminishing returns: the first 18 scored contributions delivered ~98% of the total reduction (to ≈1.93). The remaining 1,106 scored contributions gained only 0.03 bpb — and the last recorded improvement (9×10⁻⁶ bpb) sits below the 1.3×10⁻³ bpb cross-hardware noise floor.

Strengths

长处
  • Turns a mundane tool — Git — into a rigorous shared-memory substrate with immutable provenance; the whole analysis layer (SQLite index, views, figures) rebuilds from the commit history alone.
  • Evidence scoring that counts only cross-account downstream work, with replaceable verification verdicts: a clean institutional answer to popularity gaming.
  • Genuinely at-scale and decentralized — no assigned roles, no central planner, two frontier agent stacks; the 15-account, 145-commit ancestry of the winner is compelling evidence of real collective iteration.
  • Exceptional transparency: negative results, parallel-rediscovery statistics, concentration dynamics, the human intervention, and the sub-noise final improvement are all reported against the system’s own favor.

Limitations

局限
  • No controlled ablations: every recipe component was chosen on the same 200-text development evaluator — milestones are search stages, not causal effects (stated by the authors themselves).
  • No matched baseline for the platform claim; the proposed four-arm comparison (isolated / flat log / central planner / Agora) has not been run, so discovery-per-unit-compute remains unmeasured.
  • Single task, single evaluator, one 12-day window (N = 1 community); the task itself is artificial — frozen target, forbidden training, dimensions matched to no donor.
  • Late-run marginal value near zero — 1,106 contributions bought 0.03 bpb, final gain below hardware noise; verification is agent-reported, uniformly successful, with no adversarial attempts to game the scorer.

Questions for Further Exploration

开放问题
  1. Would a single agent with the same compute budget have found the same improvement, given the bigram prior emerged within six hours? What does the four-arm matched matrix actually show at fixed compute?
  2. Would the diversity views prevent concentration if deployed from day one — or if their use were left to the agents’ own judgment instead of a human trigger?
  3. Can the evidence score be gamed — collusion rings, strategic verifications — and how do the +20/−20 verification weights behave under adversarial populations?
  4. Does the factorized-donor-bigram transfer recipe generalize beyond the crafted mismatch: heterogeneous tokenizers, downstream tasks, or when a small training budget is allowed?
  5. How do the observed pathologies — narrow spine, 63%-within-an-hour rediscovery — scale with worker count? Is there an optimal community size, and does the “globally linear evaluator” plateau diagnosis survive controlled testing?
