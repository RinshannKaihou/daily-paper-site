Methodology · 方法论04

A loop where only the prompt learns

Daily long-only trading over 15 US blue chips + cash. The Trading Agent is a frozen LLM (GPT-5-mini or Gemini-2.5-Flash) whose entire behavior — evidence gathering, tool-calling protocol, signal verification, risk control, output format — is steered by a natural-language system prompt π. Tools (price lookup, news search, persistent Python kernel) enforce temporal cutoffs: the agent must retrieve, not peek.

Each day yields a decision trace (allocation + per-asset rationale) paired with realized feedback (daily & per-asset returns, state). Every 5 trading days, a Policy Agent makes one LLM call over these refinement records and rewrites the full policy text with grounded, trace-linked edits. Nothing but the prompt text is learned.

baselines: Static Base→Static TC→EvolveBase→EvolveStrategy→EvolveTrade

Strengths · 优势06
  • Clean conceptual frame — the reusable procedure (prompt), not the decision or the model, is what learns; drops onto any frozen LLM agent with zero training.
  • Measurable motivation — static agents compute the same 5 metrics on 90–100% of days and never invoke RSI / EMA / VaR in any regime: “analytic-vocabulary lock-in” made falsifiable.
  • Behavior-level evidence — metric-activation maps, tool-call shifts, and matched-day return attribution decomposed to +0.638 pp across four named positions.
  • Honest negatives — dedicated appendix on why it loses the April windows; 3 seeds with stds, cost robustness, interval sensitivity, 50-day horizon.
Limitations · 局限07
  • Statistically thin — ~21 daily returns per regime, 3 seeds, stds up to half the mean (Apr 2026 CR 3.69 ± 1.83%), no significance testing.
  • Regime-fragile — wins 3/6 pairs; all LLM configs trail trivial rules when it matters: Apr 2025 SPY +8.22% vs best LLM −4.71%; Nov 2025 KDJ&RSI +0.92% vs all-negative LLMs.
  • Over-defensive evolution — excess cash (27.1% / 40.1%) misses the V-recovery and the rally; diagnosed, never mitigated.
  • Idealized setting — 10 bps proportional costs only, long-only, 15 mega-caps, proprietary backbones; N = 5 tuned on the same windows used to report headline results.
Questions for Further Exploration · 待探问题08
Q1Do the gains survive proper statistics — overlapping-window bootstraps, many more regimes — given SR stds of ±1.68 on 21-day windows?
Q2Can the framework itself fix the excess-cash failure (e.g., a Policy Agent objective penalizing under-exposure in recoveries), or is an outer validator required?
Q3How sensitive are evolved policies to the initial prompt π₀ and the Policy Agent’s update instruction — the two hand-written artifacts that stay fixed?
Q4Would a constrained edit space (typed policy slots, version control with rollback) reduce variance while keeping adaptivity?
Q5Does analytic-vocabulary lock-in generalize to non-trading tool-using agents — and could periodic “capability probes” substitute for full self-evolution?
Q6How does it fare against learned RL baselines (e.g., FLAG-Trader) rather than only static LLM and rule-based agents?
