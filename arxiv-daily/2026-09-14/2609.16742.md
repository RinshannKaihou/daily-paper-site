> **一句话总结：** 提出carry-through checksum：在每个CONV层剪掉最不重要的输出通道并替换为一个中心为1的"直通滤波器"，让CNN用自身前向运算逐层累加并传递输入特征图校验和，最后只需在输出端做一次阈值比较即可检测软错误——在Jetson Orin NX上以近乎为零的推理开销检测FP32平均95.86%、FP16平均86.56%的临界故障（含重执行的端到端开销仅2.27%）。

> **TL;DR:** A lightweight alternative to classical per-operation ABFT for soft-error detection in CNN inference on embedded GPUs: prune the least-important output channel of each layer and replace it with a "carry-through filter" (a 3×3 kernel with a single center 1) that sums IFMaps across the channel dimension and propagates the checksum through the whole network to one extra FC neuron, giving one-shot end-to-end verification with zero added CONV compute. On six CNNs (VGG-11/19, ResNet-20/56, MobileNet-V2-x0.5/x1.4) over CIFAR-10/CIFAR-100 on an NVIDIA Jetson Orin NX with TensorRT, it detects on average 95.86% (FP32) and 86.56% (FP16) of critical bit-flip faults (distribution-based threshold, α=1%) while keeping accuracy within 1% of unmodified baselines; pure inference overhead averages <0.1% versus baseline CNNs, and full detection+re-execution mitigation costs 0.93% (fault-free) / 2.27% (under fault injection) run-time overhead — versus classical ABFT schemes whose per-CONV checksum recomputation is prohibitively expensive for embedded GPUs (no direct quantitative head-to-head is provided).

## 核心贡献

- **提出carry-through checksum（直传校验和）这一全新软错误检测框架**：不依赖经典ABFT的矩阵增广与逐算子校验和重算，而是修改CNN自身结构，让每一层的前向计算顺带累加输入特征图（IFMaps）的元素和，并把校验和一路传递到网络输出，实现**单次输出端验证（one-shot verification）**即可覆盖整条推理链路。
- **设计专用carry-through滤波器，实现CONV层零开销嵌入**：滤波器核仅在中心放一个1（配合padding=1、stride=1保证不重叠、不重复计数），利用CONV天然跨通道求和的性质生成校验和图；做法上**剪掉每层L1范数最小的输出通道**并把carry-through滤波器补为最后一个输出通道，同时在下一层把对应输入通道的2D核切片置零，使网络形状与计算量完全不变。
- **提出两种互补的阈值选取方法**：FI-based（用训练集做故障注入 campaigns 选阈值，FPR<α%）与distribution-based（只需刻画无故障推理下累加校验和神经元的统计分布，无需故障注入）；经Youden's J统计量确定α=1%为最佳工作点，且distribution-based以极低的标定成本达到与FI-based几乎相同的检测效果。
- **覆盖多种架构细节的完整工程方案**：ResNet残差块首层不放置直通滤波器以避免重复累加；MobileNet的ReLU6会饱和校验和，需换回普通ReLU；BN层对校验和通道置为恒等映射（E=0, Var=1, γ=1, β=0）；剪枝后精度下降超1%时用25个epoch的轻量微调恢复。
- **在真实嵌入式GPU上完成系统性评估**：六种CNN × 两种数据集 × 两种精度（FP32/FP16），在Jetson Orin NX上用TensorRT部署，用95%置信度、1%误差界的故障注入实验测得检测率与开销。

## Key Contributions

- Introduces **carry-through checksum**, a fundamentally new soft-error detection scheme for CNNs on resource-constrained embedded GPUs: instead of classical ABFT's matrix augmentation and per-operation checksum verification, the CNN's own forward operations compute and propagate an IFMap summation checksum layer by layer, enabling **single-shot, end-to-end error detection** with one output-side comparison.
- Proposes **dedicated carry-through filters** embedded at zero overhead: each is a kernel with zeros everywhere except a single center 1 (non-overlapping summation with stride=1/padding=1, avoiding the double counting an all-ones kernel would cause); the scheme structurally prunes the least-important output channel per layer (smallest combined L1-norm across the current layer's output and next layer's input filters) and appends the carry-through filter as the new last channel, zeroing the matching input-channel kernel slice in the next layer so the incoming checksum never leaks into normal computation — layer shapes, filter counts, compute, and memory are all preserved.
- Provides **two complementary threshold-selection methods**: an FI-based method (fault-injection campaigns on the training set, constrained by FPR < α%) and a lightweight **distribution-based** method (characterizes the fault-free distribution of the accumulated-checksum neuron; no FI needed). Using Youden's J statistic (TPR − FPR), α = 1% is identified as the best operating point, and the distribution-based method matches FI-based detection performance at a fraction of the calibration cost.
- Delivers a **complete engineering recipe across architectures**: ResNet blocks skip the carry-through filter on the first (residual-input) layer of each block to prevent double accumulation; MobileNet's ReLU6 (which saturates the checksum above 6) is replaced with plain ReLU; BatchNorm layers are set to identity on the checksum channel (E(x)=0, Var[x]=1, γ=1, β=0); FC layers prune the lowest-L1 neuron and add an all-ones-weight neuron; accuracy drops >1% from pruning trigger lightweight fine-tuning (25 epochs, lr 0.001, SGD).
- **Extensive on-device evaluation**: fault injection (single bit-flips in CNN parameters, 95% confidence / 1% error margin) in PyTorch across VGG-11/19, ResNet-20/56, MobileNet-V2-x0.5/x1.4 on CIFAR-10/100 in FP32 and FP16, with deployment via TensorRT 8.5.2 / CUDA 11.4 / C++ on an NVIDIA Jetson Orin NX (16 GB).

## Methodology

The core idea is to accumulate the element-wise summation of each CONV layer's input feature maps and carry it forward through inference, verifying it once at the output against a threshold τ.

**Carry-through filter.** For a regular CONV (kernel 3, padding 1, stride 1), the filter's 3×3 kernel is all zeros except a 1 at the center, replicated across all input channels. Because convolution inherently sums products over the channel dimension, the resulting single-channel OFMap element equals the sum of co-located IFMap values across depth. Placing the 1 at the center (rather than an all-ones kernel) ensures each input element contributes to exactly one output element — a clean, non-overlapping, one-to-one summation with no double counting.

**Embedding into a CNN (Fig. 2).** Each CONV layer is modified at two levels: (1) *output-channel level* — the least important 3D output filter (chosen by the smallest combined L1-norm of its filters in this layer's output and the next layer's input) is pruned and replaced by the carry-through filter as the new last output channel; the matching 2D filter slice in the next layer's input is pruned too; (2) *input-channel level* — since the previous layer's checksum arrives as the last input channel, the 2D kernel slice multiplying that channel is zeroed in every normal output filter, so the incoming checksum passes through without contaminating normal computation. Filter dimensions and channel counts are preserved, so CONV layers incur no additional compute or memory. The same idea extends to FC layers (prune the lowest-L1-norm neuron, add a neuron with all-ones weights). If test accuracy drops more than 1% from pruning, a lightweight fine-tuning (25 epochs, lr 0.001, SGD) restores it.

**Architecture-specific handling.** ResNet: carry-through filters are applied to all CONV layers except the first layer of each residual block (which receives the residual input), whose least-important channel is still pruned; MobileNet: ReLU6 is replaced with plain ReLU because accumulated checksums can exceed 6 and saturate; BatchNorm: the last-channel statistics are fixed to E(x)=0, Var[x]=1, γ=1, β=0, making BN an identity on the checksum channel.

**Detection and mitigation.** The final FC layer is augmented with one *accumulated-checksum neuron* whose incoming weights are all fixed to 1, so it sums all FC inputs including the propagated checksums. In a fault-free inference it takes an expected reference value; a soft error perturbs the carried checksum and shows up as a deviation. If the deviation exceeds threshold τ, an error flag is raised and the inference is re-executed (the re-execution ignores the detection result, assuming faults in two consecutive inferences are unlikely).

**Threshold optimization.** (1) FI-based: run FI campaigns on the training set and pick τ such that FPR < α% (α explored over {0.1%, 1%, 5%}); (2) distribution-based: characterize the accumulated-checksum neuron's value distribution over fault-free training-set inferences and pick τ so that < α% of fault-free runs are falsely flagged — requiring no FI at all. Youden's J statistic (TPR − FPR) selects α = 1% as the best trade-off, valid across both methods and both precisions.

**Experimental setup.** Fault model: random single bit-flips injected into CNN parameters during inference in PyTorch on the test set, to 95% confidence with a 1% error margin. Metrics: TPR = fraction of *critical* faults (those changing the golden classification) correctly detected; FPR = fraction of non-critical faults wrongly flagged. Models: VGG-11/19, ResNet-20/56, MobileNet-V2-x0.5/x1.4 (pretrained from chenyangfo/pytorch-cifar-models) on CIFAR-10 and CIFAR-100, FP32 and FP16. Deployment: NVIDIA Jetson Orin NX 16 GB, TensorRT 8.5.2 engines executed via CUDA 11.4 / C++; overhead measured over full test-set passes with and without FI.

## Results & Highlights

- **Detection coverage (FP32):** with the distribution-based threshold at α=1%, TPR for critical faults ranges **85.96%–99.7% (average 95.86%)** across all six CNNs on CIFAR-10/CIFAR-100, with FPR confined to **0.68%–1.35% (average 1.05%)**. For example, VGG-19 on CIFAR-10 reaches TPR 99.29% / FPR 0.95%; MobileNet-V2-x1.4 on CIFAR-10 reaches TPR 99.70%.
- **Detection coverage (FP16):** TPR ranges **75.02%–96.05% (average 86.56%)**, FPR **0.67%–1.67% (average 1.15%)** — the FP16 average TPR is **9.3 percentage points lower than FP32** (86.56% vs 95.86%), attributed to FP16's smaller representable range and rounding error letting sub-threshold errors escape; the worst case is MobileNet-V2-x1.4 on CIFAR-100 at TPR 75.02%.
- **Accuracy cost of the modification (Table I):** all fine-tuned carry-through models stay within 1% of baseline Top-1 accuracy, but pruning alone can be destructive — ResNet-56 on CIFAR-100 falls from a 72.60% baseline to **18.61%** after pruning, recovering to **71.65%** after 25 epochs of fine-tuning; ResNet-20 on CIFAR-100 drops from 68.83% to 38.11% (recovered to 67.88%). VGG variants need no fine-tuning at all (e.g., VGG-11 CIFAR-10: 92.79% → 92.61%). FP16 accuracy differs from FP32 by only ~0.1%.
- **Threshold calibration:** at α=1%, FI-based vs distribution-based are statistically tied (FP32 average TPR 95.78% vs 95.86%; FP16 86.34% vs 86.56%), but the distribution-based method avoids expensive FI campaigns entirely; Youden's J peaks at α=1% (e.g., 94.81% FP32 distribution-based vs 95.59% at α=0.1% where FI-based TPR collapses to 77.76% average).
- **Execution-time overhead (Fig. 3, Jetson Orin NX):** the modified CNNs themselves run within **−0.5% to +0.5% (average <0.1%)** of baseline latency — effectively noise — and memory overhead is **< 10⁻³ %**. The complete detection+re-execution pipeline costs **0.66%–1.35% (average 0.93%)** over the full test set in fault-free operation, rising to **1.2%–3.8% (average 2.27%)** under fault injection where each detection flag triggers one re-execution.
- **Generality:** detection stays consistently high across shallow and deep networks (no dependence on depth or parameter count); CIFAR-100 yields marginally lower TPR than CIFAR-10 because 100 classes spread activation distributions wider, raising the threshold and masking more critical faults.

## Critical Assessment

- **Novelty:** genuinely clever core trick — funding the checksum "for free" by spending one structurally pruned channel per layer instead of adding per-operation checks is a real conceptual advance over classical ABFT (FT-CNN, Sanity-Check, etc.), and the architecture-specific handling (ResNet residual blocks, MobileNet ReLU6 saturation, BN identity) shows the scheme was engineered past toy cases. The claim to be the first to tackle per-operation-free checksum verification integrated with the standard GPU pipeline is plausible given the cited literature.
- **Rigor — no baseline comparison:** the paper's central selling point (lighter than prior ABFT) is never demonstrated quantitatively; FT-CNN, Sanity-Check, and FT-Sparse are cited but no head-to-head detection-rate or overhead comparison is provided, so "prohibitively expensive for embedded GPUs" remains an assertion carried over from the literature rather than a measured result on the Orin NX.
- **Rigor — fault model is narrow:** only single bit-flips in CNN *parameters* injected in PyTorch on a host; no faults in activations/intermediate feature maps, GPU registers, or on-device memory during TensorRT execution. There is also a logical tension between the fault model (bit-flips in stored weights, which would persist) and the mitigation strategy (re-execution, which only helps if the fault is transient) — the paper does not discuss when re-execution would reproduce the same corrupted output.
- **Data quirks / accuracy fragility:** the pruning step collapses CIFAR-100 ResNet-56 from 72.60% to 18.61% and ResNet-20 from 68.83% to 38.11% before fine-tuning, showing the "zero overhead" claim silently depends on offline retraining infrastructure (25 epochs/SGD) that a deployment-only user may not have; the safety-critical motivation (autonomous vehicles, space) is evaluated only on 32×32 CIFAR classification, not ImageNet, detection, or segmentation workloads.
- **Reproducibility:** good in setup detail (public pretrained models, stated confidence margins for FI, exact threshold method, hardware/software versions), but no code or FI framework release is mentioned, and the expected "reference value" of the accumulated-checksum neuron (dataset-dependent) is not spelled out as an artifact.
- **Significance:** if the approach survives larger models and realistic workloads, it is a practical contribution for edge functional safety; the weakest empirical spot is that coverage degrades exactly in the deployment-relevant configuration — FP16 on the harder dataset (75.02% TPR for MobileNet-V2-x1.4 on CIFAR-100) — and detection is defined only against classification-changing ("critical") SDCs, silently accepting corrupted-but-top-1-unchanged outputs.

## Strengths

- Zero structural overhead: the checksum rides inside the existing layer shapes by replacing one pruned channel, so CONV compute, memory footprint (<10⁻³ %), and TensorRT compatibility are all preserved — measured pure overhead averages <0.1%, i.e., within run-to-run noise.
- End-to-end single-shot verification replaces per-operation checksum recomputation, removing the mismatch with the standard GPU execution flow that blocks classical ABFT on embedded GPUs.
- The distribution-based threshold calibration is a genuinely practical contribution: it matches FI-based detection (95.86% vs 95.78% average FP32 TPR) while requiring only fault-free profiling, no injection campaigns.
- Thorough empirical sweep: 6 architectures × 2 datasets × 2 precisions × 3 α values × 2 threshold methods, with a principled operating-point choice (Youden's J), and honest reporting of negative results (FP16 degradation, CIFAR-100 gap, the α=0.1% FI-based TPR collapse).
- Real deployment target (Jetson Orin NX, TensorRT, C++/CUDA), not just simulation; mitigation cost measured under actual FI campaigns (average 2.27%).

## Limitations

- Only single bit-flips in weights are injected (in PyTorch, host-side); activation faults, multi-bit upsets, and on-device GPU logic/memory errors are out of scope, so end-to-end on-edge coverage is extrapolated rather than measured.
- FP16 — the precision most likely used on Jetson-class hardware — shows materially weaker coverage (average TPR 86.56%, worst case 75.02%), and the paper offers no FP16-specific remedy beyond noting rounding error.
- Evaluated only on CIFAR-10/100 image classification with relatively small models; no ImageNet-scale models, no detection/segmentation heads, no transformer architectures.
- "Critical fault" = changes the top-1 classification; SDCs that alter confidence or intermediate features without flipping the label are treated as acceptable false-positive territory.
- The scheme requires per-network calibration (threshold τ, expected checksum reference from the training set) and possibly fine-tuning after pruning; behavior under test-time distribution shift (which could inflate FPR and thus re-execution cost) is not studied.
- Re-execution-based mitigation assumes the fault does not recur; persistent weight corruption would defeat it, a scenario the fault model arguably includes but the mitigation does not address.

## Questions for Further Exploration

- How does coverage scale to ImageNet-sized models and to dense-output tasks (object detection, semantic segmentation) where "critical fault" is harder to define than a top-1 label flip?
- Can the checksum channel survive quantization to INT8, and does the distribution-based threshold remain stable under test-time distribution shift or adversarial input perturbations?
- What is the actual on-device coverage when faults are injected into the TensorRT engine's memory/compute on the Orin NX itself, rather than into PyTorch weights on a host?
- How does carry-through checksum compare quantitatively against FT-CNN / Sanity-Check / FT-Sparse on the same hardware — detection rate, memory, and latency — to substantiate the "prohibitive overhead" claim about classical ABFT?
- Since a bit-flip in a stored weight persists across re-executions, what complementary mechanism (e.g., periodic golden-checksum refresh or weight-scrubbing) would close the persistent-fault gap in the mitigation path?
- Does the pruned-channel capacity cost have a cumulative effect in very deep networks or already channel-efficient architectures (e.g., depthwise-separable MobileNet variants), where every channel may matter more than the L1-norm heuristic suggests?
