> **一句话总结：** 本文在受控合成环境中证明，GRPO 强化学习训练的工具型 Agent 会把与工具语义相关的表面提示（如 `<answer>` 标签、网页索引标记）误学为"调用搜索"的捷径信号——在不需要搜索的数学题上多余搜索调用率最高暴涨 39.2 个百分点；捷径只在 Agent 已熟练掌握该工具的任务上形成，且一种基于 GPT-5 Nano 裁判的逐决策"工具必要性奖励"可将伪调用压回零而不损失任务准确率。

> **TL;DR:** RL-trained tool-use agents (Qwen2.5-7B-Instruct + GRPO via VerlTool, trained on 500 Natural Questions + 500 DeepMath examples) learn shortcut tool-selection policies: superficial cues spuriously correlated with the search tool during training raise unnecessary search calls on math benchmarks by up to +39.2 percentage points on GSM8K (and +21.7 on DeepMath for the `<answer>` tag) versus the cue-absent counterfactual and the no-cue baseline, while semantically misaligned code cues produce no such effect. Shortcuts form only for tools the agent has actually mastered (NQ accuracy rose ~45%→~75% while DeepMath stayed flat), and emerge only above ~80% cue–tool correlation. A dense per-call tool-necessity reward from a GPT-5 Nano LLM judge suppresses spurious calls to ΔSearch ≈ 0 while preserving or improving accuracy (e.g., GSM8K 92.8/88.8 vs. 86.8/89.2 no-cue).

## 核心贡献

- **首次形式化并度量"伪工具使用"（spurious tool use）**：将群组鲁棒性框架（Sagawa et al., 2019）扩展到工具型 Agent 的中间决策层——给出"工具伪相关"的定义（Definition 1：线索存在使工具选择概率远超任务特征所能解释的水平，且该工具对解题无益），并用反事实评估组把因果效应量化为 ΔToolY-N（线索在场 vs. 不在场时目标工具调用率之差）。
- **发现捷径形成与任务能力的强耦合**：在与代码线索完全相同的群组不平衡条件下，只有已被 Agent 熟练掌握的工具（搜索，NQ 验证准确率 30 步内从约 45% 升至约 75%）才形成线索捷径（GSM8K 上多余搜索调用最高 +39.2 个百分点）；Agent 没学会的任务（DeepMath 上的代码执行，准确率始终停在约 45–50%）完全不产生对应捷径——说明"能力越强、越易被捷径利用"。
- **交换线索实验分离两个因子**：把代码语义线索注入已被学会的事实任务只产生 ≤ +3.5% 的边缘效应，把搜索语义线索注入未学会的数学任务则无任何捷径（ΔPy ≤ 3.2%）——任务能力是捷径形成的"使能"条件，线索与工具的语义对齐强度则调制捷径强度。
- **提出逐决策的稠密"工具必要性奖励"并验证有效**：用 GPT-5 Nano 裁判对每次工具调用打必要性标签，对非必要调用施加 α=0.5 的惩罚叠加在任务奖励上，可把伪工具调用压回 ΔSearch ≈ 0，同时保持甚至提升任务准确率。
- **发现相关性强度阈值效应**：线索–工具相关度在 80–100% 时捷径明显（DeepMath 上 ΔSearch +21.7/+12.1/+11.7），降至 70% 及以下时捷径基本消失（≤ +2.1）。

## Key Contributions

- **Formalizes and operationalizes spurious tool use.** Extends the group-robustness framework (Sagawa et al., 2019) to an intermediate policy decision — tool selection — via Definition 1 (cue presence inflates selection probability of a functionally useless tool) and a counterfactual evaluation measure ΔToolY-N comparing cue-present vs. cue-absent tool-call rates on the same question.
- **Identifies task competence, not group imbalance, as the enabling factor for shortcuts.** Under identical group imbalance, search-semantic cues injected into NQ training produce large spurious search usage on math tests, while code-semantic cues injected into DeepMath produce essentially none — and the asymmetry tracks learning progress (NQ validation accuracy climbs ~45%→~75% over 30 steps; DeepMath stays flat at ~45–50%).
- **Disentangles competence from semantic alignment via a swapped-cue experiment.** Code cues paired with the well-learned factual task yield only marginal spurious search (ΔSearch ≤ +3.5%); search cues paired with the poorly learned math task yield no spurious Python use (ΔPy ≤ 3.2%). Competence enables shortcut formation; semantic alignment amplifies it.
- **Proposes a dense tool-necessity reward that eliminates the failure mode.** A GPT-5 Nano LLM judge labels each tool call necessary/unnecessary; adding a −0.5 penalty per unnecessary call to the GRPO task reward reduces cue-driven search to ≈ 0 (ΔSearch +0.0 to +0.3) without sacrificing — sometimes improving — final accuracy.
- **Characterizes a correlation-strength threshold.** Varying the fraction of cue-aligned training examples shows shortcuts emerge clearly at 80–100% cue–tool correlation and largely vanish at ≤ 70%.

## Methodology

The study runs fully controlled synthetic training environments. **Data:** 500 questions from Natural Questions (NQ; answered well via web search) and 500 from DeepMath-103k (needing a Python interpreter), a balanced 1,000-example training set. **Cue injection:** causally irrelevant cues are added to one task subset per run — search-semantic cues on NQ ([WEB INDEX 742], [REFERENCE], and an appended `<answer></answer>` format instruction) or code-semantic cues on DeepMath (a Jupyter `# Cell [1] | kernel: python3 | status: idle` header, `#!/usr/bin/python3`, `[CODE]`). **Agent & training:** Qwen2.5-7B-Instruct (no extra SFT), GRPO within VerlTool; tools emitted via `<search>`/`<python>` tags; 30 training steps, 8 rollouts per prompt, 4×H100, one seed per run. **Measurement:** counterfactual test pairs (cue-present "Y" / cue-absent "N" variants of the same question) on the training-task side (DeepMath) and held-out benchmarks (GSM8K for math, 2Wiki for factual), reporting ΔToolY-N = empirical tool-call-rate difference. **Mitigation:** for each tool invocation, a GPT-5 Nano judge receives the question, tool type, and tool input and outputs a binary necessity label; the total reward becomes rtask + Σ r_nec with r_nec = −0.5 for unnecessary calls. The design deliberately trades scale for control so any behavioral difference is attributable to the injected cue.

## Results & Highlights

- **Spurious search on math tasks (Table 1):** with the [WEB INDEX 742] cue, cue-present vs. cue-absent search rates on GSM8K are 40.1% vs. 0.9% (ΔSearch = +39.2 points, vs. +0.1 for the no-training model and +1.4 for the no-cue RL baseline); on DeepMath 22.6% vs. 2.7% (ΔSearch = +19.9). The `<answer>` tag gives ΔSearch = +21.7 on DeepMath (23.4% vs. 1.7%) and +9.5 on GSM8K; [REFERENCE] gives +7.7 and +20.1 respectively.
- **No symmetric effect for code cues (Table 2):** code-semantic cues on DeepMath training produce ΔPy of only −0.3 (Cell) and +0.7 ([CODE]) on NQ factual tasks and at most +3.8 ([CODE]) on 2Wiki — versus up to +39.2 in the search-cue condition — despite identical group imbalance.
- **Task competence evidence (Figure 2):** NQ validation accuracy rises from ~45% to ~75% over 30 GRPO steps while DeepMath accuracy stays flat at ~45–50%, matching exactly which tool develops a cue-driven shortcut.
- **Swapped-cue controls (Tables 3–4):** code cues on the well-learned NQ task yield ΔSearch ≤ +3.5% (Cell on DeepMath); search cues on the unlearned math task yield ΔPy ≤ +3.2% — both far below the +39.2% ceiling of aligned cues.
- **Tool-necessity reward (Table 1, "+ Reward" rows):** ΔSearch drops to +0.0 across all three search-cue conditions (e.g., 0.0% vs. 0.0% on DeepMath for both [WEB INDEX] and `<answer>`), while accuracy is preserved or improved (GSM8K 92.8% cue-present / 88.8% cue-absent under +Reward vs. 86.8/89.2 for the no-cue baseline).
- **Correlation threshold (Table 5, `<answer>` cue):** ΔSearch on DeepMath is +21.7 / +12.1 / +11.7 at 100% / 90% / 80% cue–tool correlation but +0.0 / +1.4 / +2.1 at 70% / 60% / 50%.

## Critical Assessment

- **Novelty:** Genuine and well-motivated. Spurious correlation is a classic topic, but transplanting it from final predictions to *intermediate tool-selection decisions* of RL agents — where unnecessary calls don't change the final answer and thus evade standard eval — is a fresh, sharp observation. The competence–vulnerability coupling ("better at the tool ⇒ more shortcut-prone") is the most interesting finding.
- **Rigor:** The controlled design (cue-injection + counterfactual Y/N evaluation + swapped-cue control + correlation-strength sweep) is clean and internally consistent. However, **every run uses a single seed** (Table 6: "Number of seeds: 1 (per run)"), so no error bars are available; several headline comparisons (e.g., ΔPy = +3.8 for [CODE] on 2Wiki, or accuracy differences of 1–3 points between +Reward and no-cue runs) sit within plausible run-to-run variance. The threshold claim ("shortcuts vanish below ~80%") rests on single runs at each correlation level.
- **A structural confound in the competence story:** the "poorly learned" task is always math/code — the agent simply never learned competent Python use within 30 steps — so the code side lacks a positive control where the code tool *is* mastered. The claimed causal role of task competence vs. other differences between the search and code conditions (tool-tag format, reward shaping, rollout budget) is supported only correlationally by the swapped-cue experiment.
- **Judge unaudited:** the GPT-5 Nano necessity judge is central to the mitigation, yet no human-agreement measurement of its labels is reported; a biased judge could either mask or fake the mitigation effect. The mitigation is also only evaluated in the search-cue condition (Table 1), the one place where shortcuts existed.
- **Scale and realism:** 1,000 training examples, 30 steps, one 7B model, deliberately synthetic cues — the authors are transparent that naturalistic training distributions remain untested, but readers should not treat the 39.2% figure as representative of production agents.
- **Significance:** as a mechanism study it is valuable and the metric (ΔToolY-N) is a reusable diagnostic; practical impact is indirect (spurious calls didn't hurt accuracy here, so the cost shows up only as wasted tool calls/latency, which is not quantified).

## Strengths

- Crisp formalization (Definition 1) plus a simple, causally interpretable measurement (counterfactual ΔToolY-N) that others can adopt directly.
- The asymmetry finding — identical group imbalance, divergent outcomes — is a genuinely surprising result, and the paper investigates *why* rather than stopping at the phenomenon.
- The swapped-cue experiment is a well-designed control that separates competence from semantic alignment.
- The mitigation is lightweight (one small LLM judge + a −0.5 penalty), requires no group labels, and is shown not to trade away task accuracy.
- Excellent reporting hygiene: full hyperparameters, judge prompts verbatim, per-condition tables including accuracy alongside tool-call rates.

## Limitations

- Single seed per run, single base model (Qwen2.5-7B-Instruct), tiny training budget (1,000 examples, 30 steps) — statistical strength and generality (larger models, longer training, multi-tool regimes beyond two) are unverified.
- Synthetic cues only; whether natural cue–tool correlations in real web-scale agent training data (user formatting quirks, source markers) reach the ~80% correlation threshold is unknown.
- The competence claim is confounded: the code-tool condition never had a competent agent, so "shortcuts form only for well-learned tools" cannot be fully dissociated from tool-specific factors.
- The LLM-judge necessity labels lack validation against human judgment, and the necessity reward is only demonstrated in the search-cue setting.
- Spurious tool calls did not measurably hurt answer accuracy in this setting, so downstream cost (latency, API spend) is asserted qualitatively rather than measured.

## Relevance

本文直击工具型 Agent 强化学习（搜索/代码增强推理，如 Search-R1、ReTool 一类工作）中"只看最终答案奖励"范式的盲区，其反事实 ΔToolY-N 诊断方法和逐决策必要性奖励对任何需要鲁棒工具选择策略的 Agent 训练管线都有直接参考价值，与关注 LLM Agent 训练动力学与鲁棒性的研究兴趣高度契合。

## Questions for Further Exploration

- Would shortcuts still form for the code tool if training ran long enough (or on an easier math mix) for the agent to master Python use — i.e., is the competence–shortcut coupling causal or an artifact of the truncated training budget?
- Do natural cue–tool correlations in real agent training data (e.g., source metadata, output-format instructions in user queries) reach the ~80% correlation threshold the paper identifies?
- How reliable is the GPT-5 Nano necessity judge against human labels, and does judge bias systematically favor certain tool types or query styles?
- Does the tool-necessity reward remain safe when a tool call is genuinely borderline-necessary (e.g., verification searches), or does the −0.5 penalty eventually suppress beneficial tool use at scale?
- Can cue-driven shortcuts be detected in deployed agents without counterfactual test pairs, e.g., via activation-level probes or per-decision logit analysis on the tool-selection tokens?
