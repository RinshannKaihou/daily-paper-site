Methodology

A five-stage control loop around one idea: memory must be an auditable callable, not prompt filler.

  1. Execute. ActionLens wraps local/remote desktops into nine normalized primitives, recording an immutable evidence directory — screenshots, timing, coordinate context.
  2. Retrieve & gate. Intent scoring (λ = 0.18), then binary gates plus a weighted compatibility threshold θ = 0.75 decide whether a memory applies.
  3. Bind. Pointer actions are re-aimed by IBTR — multi-scale ZNCC template matching accepted only above confidence 0.78 with an ambiguity margin of 0.02; otherwise rejected before any click fires.
  4. Fall back. Bounded tiers: step-local grounding repair vs. task-level replanning.
  5. Consolidate. Only artifact-validated traces are promoted through a Git-style lifecycle (branch / repair / merge / deprecate / quarantine); flexible inputs are declared for rebinding.

Design of the evaluation: paired two-pass study on OSWorld-Verified. Pass 2 reruns the same 159 tasks at a deliberately shifted 1600×900 resolution (from 1920×1080), so success must come from visual re-aiming — not coordinate copying.

Strengths

What the design gets right.

  • Clean separation of three conflated decisions: whether a run becomes memory, whether memory is retrieved, and whether a retrieved program can be safely bound to the current GUI state.
  • Reject-by-default replay safety: pointer actions never fire unless both match confidence and the ambiguity margin pass, with audited rejection causes.
  • Model-agnostic by construction — validated across Codex, Claude Code, and Kimi Code clients — and cheap to run (CPU-only).
  • Honest, well-scoped claims: states explicitly what its diagnostics do and do not establish; all prompts and thresholds published.
  • Secondary analyses others skip: storage scaling, retrieval latency under library clutter, state-gate calibration.

Limitations

Where the evidence runs out.

  • Same-task replay only — no test of transfer to genuinely new task instances, new parameter regimes, or cross-machine/cross-user settings.
  • Drift evidence is narrow: uniform resolution change plus offline rescaling — precisely what multi-scale template matching handles best; toolbars, localization, and themes untested.
  • Expensive acquisition: memory construction needs a full, failure-prone first-pass agent run rather than interactive demonstration.
  • 78% incompatible-start rejection leaves a nontrivial false-accept path; single visual probe is weak on repeated controls.
  • Single baseline (Synapse) — closest 2025–26 GUI-memory systems not run empirically; no error taxonomy of the 8–13% second-pass failures.

Questions for Further Exploration

Open threads distilled from the paper's own critical assessment.

  1. How does replay fidelity degrade on new task instances — different documents, accounts, data volumes — and what share of real enterprise workloads is actually parameter-isomorphic?
  2. Can the 22% false-accept rate be closed by combining visual probes with cheap structured signals (window titles, process context, DOM/accessibility cross-checks)?
  3. What is the break-even recurrence count given the ~572k-token first pass — and do hundreds of promoted memories produce ambiguous retrievals or conflicting branches?
  4. IBTR vs. learned grounding models (SeeClick, OS-Atlas, OmniParser) at equal latency — can template matching survive localization and theme changes?
  5. Can acquisition shift to user-guided demonstration without losing artifact validation — and what governance is needed before memories become shared organizational assets?
