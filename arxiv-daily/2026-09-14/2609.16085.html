BWhy this matters

"Quantize once, deploy anywhere" fails on heterogeneous edge fleets — anyone shipping INT8 across mixed CPUs, GPUs and NPUs must re-validate per target.

对异构 CPU/GPU/NPU 混合部署 INT8 模型的系统工作（尤其是冗余安全设计）是直接的实证依据。

CCritical edge

Every claim rests on n = 1 device per class, single-run p50 latencies, and 200–1000-image subsets the paper itself shows inflate top-1 by +9.77 pp.

01Methodology

Controlled-comparison principle (§3.3): one ONNX artifact with embedded QDQ scales runs on every target, leaving the integer kernel/ISA the only free variable — with a bit-identical FP32 control on the same harness.

  • Hardware — 8 targets, 7 classes: Raspberry Pi 5 (Cortex-A76), Jetson AGX Orin (A78AE + iGPU + 2× NVDLA), i.MX8M-Nano (A53), Core i9-10900K, RTX 3080, Qualcomm Hexagon HTP, DEEPX DX-M1 (M.2 PCIe).
  • Models: ResNet-18/50 (ImageNet-1k); DETR-ResNet-50 & YOLO26n/YOLOv5s (COCO); BEVFormer/BEVDet for latency only (init weights).
  • Agreement = identical top-1 on a fixed 1000-image bundle; batch size 1; event-timed on accelerators, wall-clock on CPU — never mixed within a claim.
  • Targets that cannot accept external scales (vendor NPUs) are explicitly downgraded to deployment observations.
Artifacts: scripts + 32 HTML measurement reports + a claim-to-artifact map, public on GitHub (embedded-ai-quantization-guide).

03Strengths
  • Falsifiable design: one artifact, fixed scales, ISA as sole free variable, FP32 bit-identical control on the same harness.
  • Invariance, not noise: agreement is bimodal — 1000/1000 iff the integer kernel is shared, regardless of where the hardware boundary sits.
  • Deployable guidance: re-validate INT8 per target; treat vendor-native quantization as mandatory; provision edge NPUs by output size with a closed-form threshold.
  • Silent-failure catalog (§9) — subset inflation, preprocessing dominance, SQNR non-predictiveness, zero-copy aliasing, EP fallbacks — independently valuable.
  • Exceptional transparency: threats quantified, negative results reported with mechanism probes.
04Limitations
  • n = 1 device per class, single-run p50 latencies, no confidence intervals — small effects are directional only.
  • Accuracy rests on 200–1000-image subsets; the paper's own §9 shows +9.77 pp mean inflation and flipped significance verdicts.
  • ORT versions differ across CPUs (1.17.1 / 1.23.2 / 1.28.0) — two clever controls bound the confound, none removes it.
  • The C2 mechanism is borrowed from concurrent single-GPU LLM work; the power-of-two counter-evidence covers one model, one boundary, two rounding modes.
  • Vendor scope: Qualcomm + DEEPX only (no TI/Renesas automotive parts); BEV models latency-only; §7 thresholds extrapolated for one PCIe Gen2×1 link.
05Questions for further exploration
  1. Does kernel-invariance hold for generative/LLM edge workloads, where a ~4% per-input flip rate compounds autoregressively?
  2. Could a kernel-level contract — standardized requantization epilogue, fixed rounding, M = 2^k as exact shift — restore cross-target bit-identity?
  3. Do QAT, per-channel scales, or INT16 accumulation widen kernel portability?
  4. Does the output-size / band-width = N provisioning rule generalize to multi-tenant NPUs and faster links (Gen3/Gen4)?
  5. What flips-per-1000 threshold is tolerable under ISO 26262 safety cases — and can divergence-aware voting be certified?
  6. Would a minimal on-device golden-set check catch the Qualcomm silent BYO-QDQ failure as standard practice?
