Key metric

5.3%

of 492 judged call sites satisfy their whole expected contract — while 82% have code checks before and after the call. Median site meets just 33% of its contract.

Corpus: 40 open-source systems · 13.4 MLOC · 4 languages · 496 call sites · 2,699 expected constraints

Why this matters

First large-scale quantification of how agent harnesses pass unchecked model output into real decisions — plus ten recurring gap patterns and minimal code fixes.

首次大规模量化智能体 harness 如何「悄悄放行」未经检查的模型输出，并提供缺口分类学、人工校验数据集与最小代码修复的完整证据链。

⚠ Critical edge

83% of gaps fail feasibility screening; only 7% (114 / 1,697) sit on a threat chain — the practically dangerous slice is an order of magnitude smaller than the headline numbers.

Also: the "expected contract" is normative, derived by GPT-5.6 agents and reviewed by the paper's own authors — agreement ≠ ground truth.

Methodology — distilled

I

Map the calls

Tree-sitter front ends find 1,226 model-API candidates; an agent classifier keeps 496 real call sites, splits replies into 917 typed outputs, and traces 1,222 consumption edges to flag decision-relevant outputs (48%).

II

Reconstruct two contracts, blind

For 579 responsibility units: a derivation agent that never sees the code admits only necessary, behavior-preserving constraints (the expected contract); a separate agent blind to that extracts the implemented one with file:line evidence. A comparison agent verdicts every expected constraint:

  • satisfied
  • partial
  • misplaced
  • missing
  • conflicting
III

Exploit & fix (manual)

Feasibility screening (7 exclusion rules + 4 threat-chain conditions), guided PoCs against real downstream code in sandboxes, CVSS v3.1 grading, trigger testing on a live model (≤10 framings ×5 reruns), then minimal contract-enforcing patches re-attacked with original + variant payloads.

Validation: 17,428 double-reviewed human judgments · Gwet's AC1 0.91–0.99 · audited code-blind reviewers · leakage audit shifts the gap rate <1pp.

Strengths

  • Makes missing checks measurable — code-blind expected-contract derivation with an audited information-visibility matrix; omissions leave no trace in code, and this sees them.
  • Unusually thorough validation: frozen coding schemes, 17,428 double-reviewed judgments with adjudication, quantified leakage audit.
  • Moves from description to causality: gaps trigger at runtime, and code fixes — not prompts — stop them (prompt-labeling negative control included).
  • Ten gap patterns + per-pattern exploitability are directly actionable: fail closed, validate tool names, parsers that raise instead of falling back.
  • All 38 triggered mechanisms responsibly disclosed to maintainers with patches; case studies (Gemini CLI, gpt-researcher, khoj, STORM) are verifiable.

Limitations

  • The expected contract is normative — derived by GPT-5.6 agents, reviewed by the authors themselves; the 63% gap rate partly reflects admission strictness, and AC1 0.95 measures consistency, not truth.
  • Trigger tests use one substitute model (deepseek-v4-flash) and ≤10 framings — real-world frequency under each system's default model is unknown; single-commit snapshots may already be fixed upstream.
  • Feasibility screening is manual, so 290 exploitable gaps is a lower bound; a wrong exclusion could hide an exploit.
  • Fixes validated for security, not utility — no systematic benign-task check; 15 of 38 fixes stay partial vs variants; unit tests ran for only 19.
  • The whole pipeline depends on one proprietary LLM; sensitivity of extracted contracts to the analyzing model is unmeasured.

Questions for further exploration

  1. Do gap rates survive swapping the derivation model — or voting across diverse open-weight models — and can maintainers validate the normative reference?
  2. Can the ten gap patterns become static/dynamic CI detector rules, and at what false-positive rate on the released 496-site corpus?
  3. Do trigger rates generalize to each system's default model (OpenManus recognized injections 0/10; Codewhale triggered in 1/10 framings)?
  4. What utility cost do contract-guided fixes impose on benign tasks, and can capability-bound enforcement be retrofitted without breaking plugin ecosystems?
  5. Could expected contracts run as runtime monitors or CI test oracles, catching drift when a system swaps its underlying model?
