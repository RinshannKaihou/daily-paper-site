Why this matters

Serving stacks that share KV caches silently feed one agent another agent's task bias — this work exposes that failure mode and repairs it for ~0.2 ms.

「跨 agent 的非前缀 KV cache 复用正是服务层为省算力而“静默改写”模型实际接收上下文的典型案例。」

Critical edge

Recovery is far from complete in the very regime the paper motivates: on ArgKP without reasoning, LatentRemedy still trails full prefill 44.55% vs 85.91% (Qwen3-4B).

Also: only the Qwen3 family is tested, and benchmark labels are validated by the same class of model being evaluated.

Methodology — diagnose, then fix

When two agents share a context block but pursue conflicting tasks, splicing agent A's cached KV into agent B's forward pass collapses B's accuracy (2.27% vs 85.91% full prefill on ArgKP). Trace analysis shows why: the source task's variables (utility V, share S) leak into the target's reasoning — and simply repeating the target instruction after reuse repairs much of the damage. The need is target×context interaction, not cache cleansing.

Latent tokens are appended after the reused block, so causal attention binds target instruction to reused context. Only the MLP trains — KL distillation from the full-prefill next-token distribution, 30 epochs, 3–5 pairs per task family, on ConflictInstruct (240 conflicting task families, 7,200 pairs).

Strengths

  • Clean diagnose→fix decomposition: preliminary study, failure taxonomy, prompt-level probe, learned remedy — each step empirically grounded.
  • Genuinely cheap: frozen LLM, one MLP, ~0.2 ms inference overhead, near-direct-reuse TTFT scaling to 4,096-token shared blocks.
  • Consistent margins over all four published repair baselines across three model scales, reasoning and no-reasoning reported separately.
  • Data-efficient (3 pairs per task family suffice) and generalizes to three real-world OOD tasks unseen in training.
  • Public code and data; transparent TTFT decomposition with locked clocks, 10-run averages.

Limitations

  • Single model family (Qwen3-1.7B/4B/8B); cross-family generalization untested.
  • On ArgKP without reasoning it recovers only about half the gap at 4B (44.55% vs 85.91%) — task conditioning alone does not finish the job.
  • ConflictInstruct is synthetic, label-validated by the same class of model being evaluated; real-world evaluation limited to three dialogue/negotiation tasks.
  • Short contexts (mean shared block 260.6 tokens, latency tested to 4,096); no long-context, batched, or multi-tenant serving experiments.
  • The trainless "repeat the instruction" baseline stays competitive — even winning one setting — and its latency is never benchmarked against LatentRemedy.

Questions for further exploration

  1. Would a single corpus-trained, task-agnostic latent adapter retain the conflicting-task recovery, or is per-distribution training essential?
  2. How does it behave at 32k+ shared contexts (real code repositories, documents) and under continuous batching / multi-tenant serving?
  3. Can it handle chains of reuse — agent C reusing a cache already remedied for agent B — without compounding interference?
  4. Is the ArgKP no-reasoning residual gap a capacity limit of 16 latent tokens, a distillation artifact of the 64-token teacher cap, or intrinsic task confusion?
  5. Does the failure taxonomy (source V/S mixing) transfer to RAG prefix reuse, system-prompt sharing across users, or production cache-matching stacks?
