> **一句话总结：** 提出 Rondo——首个针对深度学习编译器"有状态 bug"的系统化测试方法：把测试用例表示为⟨模型, 调用序列⟩，用 13 个变异算子 + MCMC 稀有行为反馈搜索调用序列，再用"未编译 / 编译但重置状态 / 编译且保留状态"三方差分预言机定位、用"保留 vs 重置编译器状态重放同一调用"确认有状态 bug；在 PyTorch 2.12.1 / TensorFlow 2.21.0 / JAX 0.10.2 / MindSpore 2.9.0 上检出 117 个 bug（35 个有状态），获开发者确认 35 个报告、修复 18 个，告警精度 99.26%，并把 44 个复现序列平均缩短 83.34%。

> **TL;DR:** DL compilers (torch.compile, jax.jit, tf.function, MindSpore graph mode) lazily compile and cache artifacts, and cached state from earlier invocations can silently corrupt later ones (e.g., PyTorch issue #197811 returns 9 instead of 18 for mul(6,3) because it reuses the cached add(6,3) code). After analyzing 26 such public issues, the authors build Rondo, which represents tests as ⟨model, invocation sequence⟩, explores sequences with 13 mutation operators plus SMT-based synthesis of guard-flipping inputs, guides search with an MCMC sampler that scores rarely observed compilation behaviors, and detects bugs via three-way differential testing (without compilation / compiled with state reset / compiled with state retained). On 4 frameworks and 24 model architectures it finds 117 bugs (35 stateful; 22 of the stateful in PyTorch); 39 reports submitted, 35 developer-confirmed, 18 fixed. Against the strongest baseline RandomHistory it raises Input coverage from 0.109 to 0.356 (+227.99%) and HBC from 0.117 to 0.242 (+106.66%), though compiler Python source-line coverage improves only from 14.17% to 14.94% (+1,727 lines). On 50,074 labeled test cases the full oracle reaches 539 TP / 4 FP (99.26% precision), and delta-debugging-style minimization shrinks 44/117 reproducer sequences by 83.34% on average.

## 核心贡献

- **提出并形式化"编译器状态"与有状态编译器 bug**：分析 PyTorch/JAX/TensorFlow/MindSpore 的 135 个候选 issue（严格过滤后保留 26 个），发现其中 17/26 的 bug 源于"编译代码的适用条件已不成立却仍被复用"、9/26 源于"复用了与当前程序状态不匹配的旧值/旧结构"——这类 bug 单独调用时不暴露，必须先建立编译器状态、再在后续调用中触发。
- **以⟨模型, 调用序列⟩表示测试用例**：由于编译器内部状态不可直接观测，用"可重放的调用序列前缀"来表征并复现编译器状态（定义 4.1/4.2），使测试既能探索不同状态也能重建同一状态。
- **Rondo 测试方法**：13 个变异算子（shape/dtype/layout/device/resample/rescale/special-values/update/mode/restore/backward/return/truncate）+ 基于 SMT 的守护条件翻转合成 + 以稀有编译行为为分数的 MCMC 采样（分数 S(X)=Σ 1/(1+count)，按 Proposal 概率比的 Metropolis 准则接受）。
- **三方差分预言机 + 有状态 bug 确认协议**：比较"未编译 / 编译但每次重置编译器状态 / 编译且保留状态"三种模式下的输出、梯度与可观测程序状态（含 NaN/Inf 符号、±0、subnormal 的 IEEE-754 整数标尺等表示感知数值比较 + 6 类独立语义检查）；再从对齐的程序状态出发，同一调用在"保留编译器状态时错误、重置后正确"才判定为有状态 bug（状态见证，定义 4.4；命题 4.5 证明序列条件与状态条件等价）。
- **保持见证类的序列最小化**：扩展 delta debugging 的失败谓词，在删除调用/化简输入时同时保持原 bug 的调用身份、失败模式、症状签名与见证类（stateful / history-exposed / point-wise），输出 1-minimal 复现脚本。

## Key Contributions

- **Concept — compiler state and stateful compiler bugs.** A filtered analysis of 26 public issues (from 135 candidates on PyTorch/JAX/TensorFlow/MindSpore trackers, 2020+) shows these bugs need an earlier invocation to establish compiler state (cached code, guards, specializations) and a later invocation to expose wrong outputs, gradients, or observable program state. In 17 of 26 cases compiled code is reused although its preconditions no longer hold.
- **Test representation.** Test cases are ⟨model, invocation sequence⟩; since compiler state is not directly observable, it is characterized by replayable invocation prefixes (Definition 4.2), making states both explorable and reproducible.
- **Rondo, a stateful testing method.** Test-space exploration uses 13 mutation operators (input mutations: shape, dtype, layout, device, resample, rescale, special FP values; state operations: update, mode, restore, backward; sequence operations: return, truncate) plus optional SMT-based synthesis that solves guard constraints to hit unexplored outcomes; an adaptive MCMC sampler favors rarely observed compilation behaviors (score Σ_k 1/(1+c_t(k)), Metropolis acceptance with proposal-probability correction).
- **Three-way differential oracle and stateful-witness confirmation.** Each test runs in three modes — Without compilation (eager/PyNative/non-jit), Compiled without state (callable rebuilt, caches cleared at a reset boundary), Compiled with state — with structured observations (return value trees plus declared observable state) compared under representation-aware numeric rules (exact discrete; NaN positions, Inf signs, signed zeros, zero-vs-nonzero; subnormals on an integer scale from raw IEEE-754 encodings), plus 6 independent semantic checks (precision requirements, determinism stability, bit-pattern consistency, mathematical identities, 3-implementation consensus, bounds). A bug is *stateful* only when the same invocation, from aligned program state and alias relations, is wrong with compiler state retained and correct after it is reset.
- **Witness-class-preserving minimization.** Delta debugging is extended with a failure predicate Φ that preserves validity, the witness class, the exposing invocation, failing modes, and symptom signatures, yielding 1-minimal reproducers.

## Methodology

The method has three modules. (1) **Test-space exploration** mutates the current invocation sequence (append/replace/truncate with the 13 operators) or, when framework guards or input constraints are available, asks an SMT solver for inputs that drive a not-yet-explored guard outcome; every generated test must satisfy scenario preconditions. Compilation behavior is summarized into behavior keys (e.g., "compile", "ordinary reuse", "reuse after state operation U"); each key contributes 1/(1+count) to a sequence's score, and a Metropolis-Hastings-style acceptance rule min(1, exp(β[S_t(X′)−S_t(X)])·q_t(X|X′)/q_t(X′|X)) decides whether to continue from the new sequence, so the search drifts toward rare behaviors. (2) **Test oracle** runs the same sequence from the same initial program state in the three modes; each mode carries its own program state forward, only compiler-state retention differs. Result comparison traverses paired value trees, first requiring identical containers/shapes/dtypes, then comparing leaves with representation-aware numeric rules (floats serialized as raw bits so FP-mode changes cannot corrupt comparisons); independent semantic checks catch bugs shared by all three modes. (3) **Stateful candidate refinement** replays the prefix h to reach (s_h, κ_h), re-runs the exposing invocation a twice from aligned program state (inputs, parameters, alias relations, even RNG state aligned) — once with κ_h retained, once reset to fresh compiler state — and classifies the witness as stateful, history-exposed, or point-wise; Proposition 4.5 proves the sequence-based and state-based statefulness conditions coincide at the reached configuration. Minimization then deletes invocation blocks or simplifies inputs, accepting a reduction only if Φ holds. Implementation targets torch.compile+Inductor, tf.function (with/without jit_compile), jax.jit+XLA, and MindSpore graph mode, evaluated with 24 model architectures (MLPs, CNNs, Transformers) on PyTorch 2.12.1, TensorFlow 2.21.0, JAX 0.10.2, MindSpore 2.9.0 (RTX 4090, i7-14700K, 32 GB RAM); coverage comparisons use three runs and 600 test cases per method.

## Results & Highlights

- **Bug yield (RQ1):** 117 bugs detected across four frameworks — PyTorch 30, TensorFlow 30, JAX 17, MindSpore 40 — of which 35 are stateful (22 PyTorch, 8 TensorFlow, 2 JAX, 3 MindSpore). 39 reports submitted (18 stateful); developers confirmed 35 (16 stateful) and fixed 18 (11 stateful). Concrete stateful examples: PyTorch sharing compiled code between add- and mul-structured functions (issue #197811); tf.function reusing one compiled graph for +0.0 and −0.0 although the function can distinguish them.
- **Coverage vs. baselines (RQ2, 600 test cases, 3 runs):** Rondo beats the strongest baseline RandomHistory on Input coverage 0.356 vs 0.109 (+227.99%) and Path 0.370 vs 0.106 (+249.58%), Guard 0.384 vs 0.154 (+148.51%), HBC 0.242 vs 0.117 (+106.66%); NNSmith/AlignGuard trail far behind (Input 0.107/0.061, HBC 0.000/0.023). Compiler Python source-line coverage (torch._dynamo/._inductor/._functorch) is highest too but modest: 14.94% (33,591 lines) vs 14.17% (31,864 lines) for RandomHistory, i.e., +0.77 pp / 1,727 extra lines.
- **Ablation (RQ3):** removing compilation-behavior feedback is the biggest hit to Input/Path/Guard (−44.44%/−48.00%/−48.19%, HBC −31.30%); removing state operations causes the largest HBC drop (−49.01%); removing the return operator costs Guard −40.42% and HBC −34.06%; SMT synthesis matters least (Input −5.31%, Path −4.89%, HBC −4.21%, and Guard actually rises slightly from 0.3837 to 0.3849 without it).
- **Oracle effectiveness (RQ4, 50,074 labeled test cases):** cumulative true positives climb from 31 (crash-only) → 354 (two-mode numerical) → 382 (three-mode) → 487 (three-mode structured, +27.49% over three-mode numerical) → 539 (full oracle, semantic checks add 52 TP); full oracle issues 543 alarms with 4 false positives = 99.26% alarm precision, 0.74% FDR.
- **Sequence refinement (RQ5):** effective shortening succeeds for 44/117 test cases (37.61%); for those 44, mean invocation count drops from 22.18 to 1.73 (median ~13 → 1), an 83.34% mean compression (median 89.44%). Overall mean compression is 31.34%; refinement costs on average 7.32 oracle checks and 184.55 s per test case (357.78 s for the successfully shortened ones).

## Authors & Credibility

The team is from the State Key Laboratory for Novel Software Technology at Nanjing University (Ge, Qian, Hu, Zou, Liu, Chen, Fang; corresponding author Chunrong Fang) with one coauthor at UNIST — a group with a long track record in deep learning system and compiler testing (prior work on DL framework testing, e.g., data-flow-grounded testing, arXiv:2610.15808). The paper reads as an ICSE/FSE-style software-engineering submission (CCS: software testing and debugging; anonymized artifact at anonymous.4open.science). Credibility is high: bugs are counted only after deduplication, 39 were actually reported upstream, 35 were confirmed by framework developers and 18 already fixed — the strongest possible ground truth for testing research. The oracle evaluation is done on 50,074 labeled test cases, and the empirical study of 26 public issues uses transparent inclusion criteria with a documented filtering funnel (135 → 26).

## Critical Assessment

- **Novelty:** Genuinely new problem framing for DL compiler testing. Prior tools (NNSmith, NeuRI, Tzer, WhiteFox, AlignGuard) test single invocations or mutate models/IRs; AlignGuard comes closest (it extracts repeated-invocation-with-state-change patterns from bug reports), but none separate *program state* from *compiler state* or define a formal stateful-witness condition. The retain-vs-reset replay protocol (Definition 4.4 + Proposition 4.5) is the paper's sharpest idea.
- **Rigor:** Strong on oracle evaluation and ablations; weak spots remain. The behavior-coverage metrics (Input/Path/Guard/HBC) are *defined for this evaluation* — the authors admit "their absolute values depend on the selected total sets" — so the +228%/+250%/+149%/+107% gains over RandomHistory are relative to a self-designed space, while the only externally interpretable metric, compiler Python source-line coverage, moves just 14.17% → 14.94%. Baselines are re-implementations adapted to this setting ("We adapt their testing strategies"), not their original pipelines, which inflates comparability risk. The 99.26% alarm precision is measured on test-case counts, not on the 117 deduplicated bugs, and the 82 non-stateful bugs overlap heavily with what existing single-invocation tools already find — the headline "117 bugs" conflates the stateful contribution (35) with routine fuzzing yield.
- **Reproducibility:** Good in principle — versions pinned (PyTorch 2.12.1, TensorFlow 2.21.0, JAX 0.10.2, MindSpore 2.9.0), hardware documented, three seeds per coverage run, anonymized artifact with implementation, bug-discovery and experiment results. But the artifact is anonymous (under review), and MindSpore/JAX users need specific device support to reproduce.
- **Significance:** Silent wrong-result bugs in the compilation path are exactly the class that corrupts training/inference without any exception — 16 confirmed stateful reports (11 fixed) in production frameworks is a real contribution. Long-term value depends on whether the retain/reset confirmation protocol gets adopted by others.
- **Red flags:** (1) Stateful-bug distribution is extremely skewed — 22 of 35 in PyTorch, only 2 in JAX and 3 in MindSpore, and MindSpore has just 1 fix — so cross-framework generality of the *stateful* claim rests mostly on one framework whose guard machinery (torch.compile) is the most aggressive cacher. (2) SMT-based synthesis is heavily oversold in the design section yet contributes ≤5.31% on any metric and even slightly hurts Guard. (3) Only 24 hand-picked common architectures (MLP/CNN/Transformer); no evidence about huge real models, multi-GPU, or training loops beyond the tested patterns. (4) Refinement succeeds on only 37.61% of cases at ~3 min per test case — acceptable for bug triage, but a cost the paper's abstract omits.

## Strengths

- First systematic study and formalization of stateful bugs in deep learning compilers, grounded in a reproducible analysis of 26 real public issues (all 26 reproduced on affected versions).
- The retain-vs-reset confirmation protocol cleanly separates compiler-state effects from program-state effects — the recurring confound in all prior repeated-invocation testing — and is backed by a formal sequence-state correspondence proposition.
- Practical end-to-end tooling: guard-targeted SMT synthesis, rare-behavior MCMC guidance, representation-aware numeric comparison (subnormals on integer scale, raw-bit serialization), and witness-class-preserving minimization that yields small developer-friendly reproducers (median 1 invocation after shrinking).
- Real-world validation: 39 upstream reports, 35 confirmed, 18 fixed across four major frameworks; oracle precision measured on 50,074 labeled cases rather than anecdote.
- Comprehensive ablations isolating feedback, SMT, the return operator, and state operations, each with a mechanistic explanation of why it matters.

## Limitations

- Compiler source-line coverage gain is marginal (+0.77 pp over RandomHistory); the dramatic gains appear only on the paper's own behavior-coverage metrics, whose total sets are evaluation-specific.
- Stateful findings are concentrated in PyTorch (22/35); JAX and MindSpore contribute only 5 stateful bugs combined, so cross-framework strength of the stateful-bug phenomenon is under-evidenced.
- SMT-based synthesis adds substantial machinery for ≤5% metric gains and no Guard gain.
- Only 24 small-to-medium model architectures on a single machine with one GPU; scaling behavior, distributed settings, and large real workloads are untested.
- Bug search cost is nontrivial (600 test cases per coverage run; refinement ~184.55 s per test case, 7.32 oracle checks), and effective minimization succeeds in under 40% of cases.
- The 26-issue empirical basis, while carefully filtered, is small and biased toward issues rich enough in keywords (guard, cache, stale, recompile) to be found by the search queries.

## Relevance

与"Inference Reliability / 静默错误检测"方向高度相关：torch.compile、jax.jit、tf.function 等编译缓存层会静默篡改模型输出与梯度（无异常抛出），正是"模型下方 serving/编译栈导致的输出损坏"这一核心关切；其"保留 vs 重置编译器状态"的差分确认协议也可迁移到训练/推理栈其他有状态缓存（如 kernel cache、autotune 缓存）的可靠性审计中。

## Questions for Further Exploration

- Can the retain-vs-reset confirmation protocol be integrated as a cheap runtime assertion in production serving stacks (e.g., periodically replaying a canary invocation with caches cleared) to catch stateful corruption online rather than at testing time?
- Why do JAX and MindSpore yield so few stateful bugs (2 and 3) — stricter guard invalidation, or weaker oracle/mode support (PyNative reset granularity) in Rondo's implementation for those frameworks?
- Do stateful caching bugs also affect performance-relevant knobs such as autotuned kernel caches, CUDA graph capture, and quantization/fused-kernel caches introduced by aggressive inference optimization, where the same stale-specialization mechanism could silently change numerics?
- How does bug yield scale with model size and realistic training loops (multi-GPU, DDP/FSDP), where invocation sequences are longer and guards are invalidated far more often?
- Could LLM-guided mutation (as in WhiteFox/AlignGuard) replace or complement the SMT guard solver, given that SMT synthesis contributed ≤5.31% to coverage in the ablation?
