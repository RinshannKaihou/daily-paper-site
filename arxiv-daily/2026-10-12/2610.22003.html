Why This Matters

Compile caches can silently corrupt model outputs and gradients — no exception raised. The retain-vs-reset audit transfers to kernel and autotune caches too.

torch.compile / jax.jit / tf.function 等编译缓存层会静默篡改输出与梯度；保留 vs 重置差分协议可迁移到 kernel cache、autotune 缓存等有状态栈的可靠性审计。

⚠ Critical Edge

The dramatic +228% / +250% coverage gains are relative to a self-designed coverage space — the only externally interpretable metric, compiler source-line coverage, moves just 14.17% → 14.94%.

01Methodology · How Rondo Works 方法

  1. 1
    Explore — tests are ⟨model, invocation sequence⟩
    Replayable call prefixes stand in for unobservable compiler state. 13 mutation operators (shape, dtype, layout, device, special FP values; update / mode / restore / backward; return / truncate) rewrite the sequence; optional SMT synthesis solves guard constraints to reach unexplored outcomes.
  2. 2
    Guide — chase rare compilation behaviors
    Each behavior key (“compile”, “ordinary reuse”, “reuse after state op”) contributes 1/(1+count) to a sequence’s score; a Metropolis–Hastings sampler drifts the search toward rarely seen behaviors.
  3. 3
    Oracle — three-way differential testing
    Every sequence runs in three modes: uncompiled · compiled + state reset · compiled + state retained. Value trees and observable state are compared under bit-aware rules (NaN positions, Inf signs, ±0, subnormals on the raw IEEE-754 integer scale) plus 6 semantic checks.
  4. 4
    Confirm — the stateful witness
    The exposing invocation is replayed twice from aligned program state: wrong with state retained, correct after reset ⇒ stateful bug (Defs 4.1–4.4; Prop 4.5 proves sequence- and state-based conditions coincide).
  5. 5
    Shrink — witness-preserving minimization
    Delta debugging extended to keep the witness class, failing modes and symptom signature → 1-minimal, developer-friendly reproducers.

03Strengths 优点

  • First formalization of compiler state and stateful bugs, grounded in 26 real public issues — all 26 reproduced on affected versions.
  • Retain-vs-reset replay cleanly separates compiler-state effects from program-state effects — the confound in all prior repeated-invocation testing — backed by Prop 4.5.
  • Practical end-to-end tooling: bit-level numeric comparison, MCMC guidance, witness-class-preserving minimization (median reproducer: 1 invocation).
  • Strong ground truth: 39 upstream reports, 35 developer-confirmed, 18 fixed; oracle precision measured on 50,074 labeled cases, not anecdote.
  • Comprehensive ablations isolating feedback, SMT, state ops and the return operator, each with a mechanistic explanation.

04Limitations 局限

  • Marginal external coverage gain: +0.77 pp source lines over RandomHistory; the dramatic gains exist only on evaluation-specific behavior metrics.
  • PyTorch-skewed evidence: 22 of 35 stateful bugs in one framework; JAX + MindSpore contribute 5 combined (and 1 MindSpore fix).
  • Oversold SMT synthesis: heavy machinery for ≤ 5.31% on any metric, and Guard rises slightly without it.
  • Narrow workload scope: 24 small/medium architectures, single GPU — no multi-GPU, DDP/FSDP, or large real models.
  • Cost & small basis: ~185 s and 7.3 oracle checks per refinement, succeeding on < 40% of cases; empirical study built from 26 keyword-findable issues.

05Questions for Further Exploration 延伸问题

  1. Can retain-vs-reset become a cheap runtime canary — periodically replaying one invocation with caches cleared — to catch stateful corruption online in production serving?
  2. Why do JAX (2) and MindSpore (3) yield so few stateful bugs — stricter guard invalidation, or weaker reset granularity in Rondo’s implementation?
  3. Do stale-specialization bugs also corrupt autotuned kernel caches, CUDA graph capture, quantization caches introduced by aggressive inference optimization?
  4. How does yield scale to realistic training loops (multi-GPU, DDP/FSDP) with longer sequences and far more guard invalidations?
  5. Could LLM-guided mutation replace the SMT guard solver, given SMT contributed ≤ 5.31% to coverage?
