Key metric

2×+

Long-phonebook retrieval accuracy from prepending a single flag word (0–2 tokens) to the target entry — Nvidia-Mamba 8B, 150–200 entries.

Oracle gate scaling, same prompt, 10 values edited:
3× → ~100%  ·  0.8× → ~0%

Why this matters

A mechanistic account of why efficient SSMs fail at long-context retrieval — pointing to gate-input redesign, not bigger states, as the fix.

⚠ Critical edge

No Transformer baseline is run — the “Mamba lags Transformers” claim is imported from prior work (Waleffe et al. 2024), and all evidence lives on one synthetic phonebook task.

Methodology — working backward from the output

Query-first phonebook: target name given up front, then a list of Name → 10-digit number entries (20–500); the model completes the target's number. Flagged variant differs by one prefix word only. Models: Nvidia-Mamba 8B (56 layers) · Codestral-Mamba 7.3B (64 layers) · 500 samples/point, greedy, regex-scored.

  1. 1 · BehaviorAccuracy vs list length, flagged vs unflagged
  2. 2 · State probesLayer-wise linear probes on 1M-dim recurrent states
  3. 3 · Gate analysisPre-activation Δt, target vs distractor digits
  4. 4 · Causal testsPatching + oracle scaling of 10 target-token gates

Probes are treated as correlative; patching is the causal arbiter, following activation-patching best practice. Cumulative layer-prefix patching then localizes where in depth the effect lives.

Strengths

  • Query-first + one-word flag cleanly separates capacity from relevance availability — model experimental design.
  • Exemplary causal methodology: bidirectional patching, oracle scaling, layer-prefix localization.
  • Replicates across two independently trained Mamba-2 checkpoints (NVIDIA base, Mistral instruct).
  • Actionable diagnosis: gates computed from the token's own under-contextualized representation motivate alternative gate inputs.
  • Candid reporting — limitations, AI-use, reproducibility statements; Softplus averaging artifact explicitly dodged.

Limitations

  • Synthetic phonebook only — no natural-language retrieval (needle-in-a-haystack, MQAR, long-context QA).
  • No Transformer analyzed in the same framework; the comparative claim is borrowed.
  • Only Mamba-2 at 7–8B scale; Mamba-1 / Mamba-3 dynamics untested.
  • Oracle scaling needs ground-truth target indices — a demonstration of sufficiency, not a deployable fix.
  • Central quantitative claims stated relatively (“more than doubles”), not tabulated.
  • Flagged variant is an artificial input edit; deployment relevance undiscussed.

Questions for further exploration

  • Do the late-emergence dynamics appear on natural-language retrieval, where relevance is fuzzier than an exact key match?
  • Do attention layers (in Transformers or hybrids like Jamba/Zamba) show relevance-aligned behavior in the early-to-middle layers where Mamba's gates fail?
  • Can a training-time intervention — auxiliary objectives pushing relevance into early layers, or query-first curricula — close the gap without oracle knowledge?
  • Would cross-token or query-conditioned gate inputs eliminate the depth delay, at what cost to linear-time inference?
  • Do Mamba-3's redesigned gates exhibit the same representation-vs-gate lag once large checkpoints exist?
  • Is the ~10-layer emergence constant a function of depth fraction, data locality, or absolute layer index — does it scale to 60+ layers?
