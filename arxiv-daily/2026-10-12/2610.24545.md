> **一句话总结：** 对 40 个热门开源智能体系统（13.4 MLOC）中 496 个 LLM 调用点做首个大规模"调用点契约"实证研究——用代码盲（code-blind）多智能体流水线推导每个调用点的期望契约再与代码实际实现对比，发现 82% 的调用点虽有调用前后的代码检查、却只有 5.3% 完整满足期望契约（63% 的期望约束未落实）；对 38 个可实际触发的漏洞机制，1-366 行的极小代码补丁即可阻断全部原始攻击载荷。

> **TL;DR:** The first large-scale empirical study of what 40 popular open-source agentic systems (496 LLM call sites, 13.4 MLOC, 4 languages) actually enforce around their LLM calls. A blind multi-agent pipeline (validated by 17,428 human judgments, Gwet's AC1 0.91–0.99) derives each call site's *expected* contract without seeing the code and compares it with the *implemented* one. On the 496-site corpus, a conventional "is it guarded?" audit would rate 82% of call sites as checked before and after the call, but contract-level analysis shows only 5.3% satisfy their whole expected contract (63% of 2,699 expected constraints unmet; post-condition gap rate 72%). Of 60 exploitable mechanisms (9 critical on CVSS), 38 trigger at runtime, and a minimal code fix enforcing the missing constraint stops the original exploit for 38/38 (variant payload: 35/38), while prompt-only "label the untrusted content" fixes worked for only 1 of 2 testable mechanisms. Concrete victims include Gemini CLI's fail-open policy gate, gpt-researcher's unsanitized innerHTML renderer, and khoj's missing URL allowlist.

## 核心贡献

- **首个针对 LLM 调用点契约的大规模实证研究**：覆盖 40 个热门开源智能体系统（GitHub 星标中位数 29k，全部 >5k）、13.4 MLOC、四种语言、六大任务域（软件工程、计算机/网页操作、科研、通用助手、个人助理、领域专用），共 496 个调用点、917 个类型化输出、5,017 个已实现约束与 2,699 个期望约束。
- **提出 LLM 调用的"契约"视角与代码盲重建方法**：借鉴 Hoare 逻辑与按契约设计，把每个调用点责任单元的契约分为前置条件、提示约束、后置条件三阶段，并定义三级保证强度（prompt-only ≺ code-checked ≺ capability-bound）。关键设计是"期望契约"由从未见过代码的推导智能体从功能规约独立得出，与"已实现契约"对比，从而让"缺失的检查"变得可测量——这是单纯读代码或规约挖掘做不到的。
- **"有检查 ≠ 检查到位"的核心量化结论**：82% 的调用点在调用前后都有代码检查，但只有 5.3% 完整满足期望契约，中位调用点只满足契约的三分之一；十个反复出现的缺口模式解释了 99% 的差距（如失败即放行 fail-open、未验证动作、仅检查格式不检查语义）。
- **运行时后果验证与修复有效性**：17% 的缺口在技术上可利用，其背后 60 个机制中 38 个在真实模型下触发（CVSS 评 9 个 critical）；用最小代码补丁强制执行缺失约束后，全部 38 个原始攻击被阻断、23 个机制被完全封死，而已向维护者负责任披露。
- **发布了经人工校验的数据集**：含 496 个调用点、917 个类型化输出、两级契约及逐条 file:line 证据与 17,428 条审查记录，可供后续研究与工具构建复用。

## Key Contributions

- **First large-scale empirical study of call-site contracts in agentic systems**: 40 popular open-source agentic systems (median 29k GitHub stars, all >5k), 13.4 MLOC, four languages, six task domains; 496 call sites, 917 typed outputs, 5,017 implemented and 2,699 expected constraints.
- **A contract view of LLM calls plus a blind reconstruction method**: following Hoare logic and design-by-contract, each responsibility unit gets a contract with pre-condition, prompt, and post-condition phases and a three-level assurance order (prompt-only ≺ code-checked ≺ capability-bound). The expected contract is derived by an agent that never sees the code, so gaps against the implementation are measurable — something neither code reading nor specification mining can do, since a missing check leaves no trace in code.
- **The central "presence ≠ adequacy" quantification**: 82% of call sites have code checks before and after the call, yet only 5.3% satisfy their whole expected contract and the median site satisfies one third; ten recurring gap patterns explain 99% of the 1,697 gaps (e.g., fail-open handling, unvalidated actions, format-checked-but-not-content-checked replies).
- **Runtime exploitability and fix validation**: 17% of gaps are technically exploitable; 38 of the 60 mechanisms behind them trigger against a real model (9 critical by CVSS v3.1); a minimal patch enforcing the missing constraint stops all 38 original exploits and blocks 23 mechanisms completely; all 38 were responsibly disclosed to maintainers.
- **A validated public dataset**: 496 call sites, 917 typed outputs, both contract layers with file:line evidence and 17,428 review judgments (Gwet's AC1 0.91–0.99).

## Methodology

The study runs in three stages over the 40 systems, each analyzed at a fixed commit; all Stage I/II agents run on GPT-5.6 Sol in isolated contexts, and every automated step is checked by human reviewers before use.

- **Stage I (call-site analysis)**: tree-sitter-based static front ends per language locate 1,226 candidate sites that can reach a model API (following wrappers across files); an identification agent classifies each as real invocation/wrapper/relay, yielding 496 call sites. A decomposition agent splits replies into 917 typed outputs labeled with one of ten operations (generate, select, classify, …), and a tracing agent follows each output to 1,222 consumption relations labeled with one of seven edge types (control-flow, executed, machine-value, model-context, …). An output is *decision-relevant* if it reaches control flow or execution.
- **Stage II (blind contract reconstruction)**: for each of 579 responsibility units, a specification agent writes a code-free functional specification (passing a mechanism-independence test); a derivation agent that never sees the code enumerates failure modes (invalid invocation, task deviation, malformed output, semantic error, harmful effect) and admits an expected constraint only if *necessary* (shown by a counterexample), *behavior-preserving*, and *non-redundant*; an extraction agent that never sees the expected contract extracts the implemented constraints with mechanism/phase/assurance/file:line evidence; a comparison agent assigns each expected constraint one verdict: satisfied / partial / misplaced / missing / conflicting. Information visibility is enforced by an explicit matrix.
- **Stage III (exploitability and fix validation, manual)**: feasibility screening applies seven exclusion rules (e.g., gap arises before any reply exists, downstream check stops the value) plus four threat-chain conditions (defect exists, reachable, bad value possible, consumer acts); guided PoCs pass the predicted bad value into the real downstream code in sandboxes; severity is graded with CVSS v3.1 and OWASP LLM Top 10; trigger testing sends up to ten payload framings to a real model (deepseek-v4-flash, each system's own requests/sampling), reruns hits five times, with a positive control; contract-guided fixes write the smallest patch enforcing the missing constraint, rerun the PoC with original payload plus a variant, and run existing offline unit tests.
- **Reliability**: three authors serve as reviewers R1/R2 (independent labels) with R3 adjudicating 604 disagreements; spec/expected-contract reviewers work code-blind (audited). 17,428 total judgments; Gwet's AC1 0.91–0.99 across steps (Cohen's κ also reported, low under label skew).

## Results & Highlights

- **Contract satisfaction vs. guard presence (the headline result)**: across the 496-site corpus of 40 systems, 82% of call sites (91% of decision-relevant ones) have code checks both before and after the call, yet only 26 of 492 judged sites (5.3%) satisfy their whole expected contract (5.8% for decision-relevant sites); the median call site satisfies 33% of its contract. Overall gap rate: 63% of 2,699 expected constraints, ranging 33%–85% per system (median 64%), with 33 of 40 systems missing more than half.
- **Post-conditions look protected but are the weakest**: post-call constraints are 97% code-checked (RQ2), yet the post-condition gap rate is 72% vs. 62% for pre-conditions and 47% for prompt constraints; verdict breakdown of the gaps: 39% partial, 15% missing, 5% conflicting, 4% misplaced. 29% of all expected constraints are enforced more weakly than required — of constraints requiring capability-bound assurance, only 25% get it (40% downgraded to a code check, 8% to a prompt instruction).
- **Delegated logic flows into decisions, mostly invisible to users**: 48% of the 917 outputs are decision-relevant; free-text `generate` outputs account for 502 (55%) of outputs and 175 of the 437 decision-relevant ones (40%); 71% of outputs (73% of decision-relevant ones) never reach a person; counting model-to-model hand-off chains (up to 12 steps in STORM) raises the decision-relevant share from 48% to 54%.
- **Enforcement is skewed toward recovery over validation**: 78% of the 5,017 implemented constraints are enforced by the program (70.5% code-checked + 7.6% capability-bound), but 67% of prompt-phase constraints are prompt-only, including 268 syntactic, fully code-decidable constraints across 27 systems (e.g., TradingAgents' "at most eight indicators with exact names" is never checked in code); 18 of 23 systems with both site kinds give decision-relevant call sites no stronger protection than others.
- **Ten patterns explain 99% of the 1,697 gaps** (1,685 covered), each recurring in 12–34 systems; fail-open handling alone causes 44% of conflicting verdicts (57/130) — e.g., Gemini CLI's policy enforcer returns ALLOW on empty/unparseable/errored replies (5 of 6 return paths allow).
- **Runtime consequences and fix efficacy**: feasibility screening excludes 1,407 gaps (83%); 290 (17%) are exploitable and 114 lie on the threat chain (48 direct, 66 partial); the 60 mechanisms behind them score 9 critical / 21 high / 26 medium / 4 low on CVSS, and 38 of 60 trigger (36 against a real model, 2 deterministically). Patches of 1–366 lines across 19 systems stop the original payload for 38/38 and the variant for 35/38, with 23 mechanisms (32 gaps) blocked completely; unit tests run offline for 19 patched mechanisms and all pass. Prompt-only labeling fixes removed the effect for only 1 of 2 testable mechanisms. No quantitative comparison to a learned defense baseline is reported — the baselines compared are the guard-counting audit (82%) and labeling-based mitigation, both of which the contract-level analysis and code fixes dominate.

## Authors & Credibility

A nine-author team spanning Nanjing University (Weng, Feng, Liu), Xi'an Jiaotong University (L. Wang, Shen), Singapore Management University (Cheng, Xie), and University College London (Ye, Sarro) — groups with strong records in software engineering, software testing/security, and LLM-system reliability (Sarro and Feng are well-known SE professors; Xiaofei Xie's group works on LLM program analysis). The paper is written in ACM TOSEM/FSE style with CCS Concepts and a 22-page full format including a detailed, per-step validation protocol. Credibility is strengthened by the unusually careful methodology for an empirical SE paper: pre-registered-style frozen coding schemes developed on six pilot systems, 17,428 human judgments with both Gwet's AC1 and Cohen's κ reported, an explicit information-visibility matrix to enforce blinding, a leakage audit (48 non-neutral specifications excluded changes the gap rate by <1 percentage point), lower-bound framing for exploitable gaps, and responsible disclosure of all 38 triggered mechanisms to maintainers along with their patches.

## Critical Assessment

- **Novelty: high.** Reframing LLM calls as contract-bearing responsibility units and measuring *adequacy* rather than *presence* of checks is genuinely new relative to prior work on prompt injection defenses, agent failure studies, and specification mining — none of which can see missing checks, because absence leaves no trace in code. The blind two-contract reconstruction is an elegant solution to the reference problem.
- **Rigor: strong but with self-validation at the core.** The expected contract is a normative artifact derived by GPT-5.6 Sol agents and reviewed by three of the paper's own authors rather than independent external raters or the systems' maintainers; the agreement statistics (AC1 0.95) measure reviewer-consistency, not ground truth. The leakage audit and the fact that 15% of expected constraints have no code counterpart partly defend against circularity, but the 63% gap rate remains partially a function of how strict the derivation agent's admission criteria are. Also, the two largest steps (consumer tracing, implemented-contract extraction) were double-reviewed only on samples of up to 40 items per system, not in full.
- **Reproducibility: good.** Dataset (call sites, both contracts, evidence, review records) is released; all analysis steps, exclusion rules, threat-chain conditions, and the ten gap patterns are documented in tables. However, the multi-agent pipeline runs on a proprietary GPT-5.6 Sol model, and no prompt transcripts are included in the paper itself, so exact replication of contract derivation is not possible.
- **Significance and a headline-vs-slice gap to keep in mind.** The dramatic numbers (63% unmet, 5.3% fully satisfying) coexist with the paper's own finding that 83% of gaps are excluded by feasibility screening and only 7% (114/1,697) sit on a threat chain — the practically dangerous slice is an order of magnitude smaller than the headline, which the abstract could be read as eliding. The "stops all 38 exploits" claim is precise but worth unpacking: the *original* payload is stopped 38/38, the *variant* for only 35/38, and 15 of 38 fixes remain partial (e.g., Voyager's in-process sandbox without a hard boundary, deer-flow's semantic goal loop); unit tests were runnable for only 19 of 38 patched mechanisms.
- **Trigger testing generalization.** All model tests use one substitute endpoint (deepseek-v4-flash) with each system's own requests, and at most ten payload framings — the authors honestly note this shows a mechanism *can* trigger, not how often it does under each system's default model (OpenManus's injection was recognized in 10/10 runs; Codewhale triggered in only 1/10 framings). Single-commit snapshots also mean some gaps may since be fixed upstream.
- **Red flags: minor.** One subject ("CodeWhale", 41k stars, since 2026) is treated as a major case study (Figure 1) but is the least-established system in the corpus; the 4 call sites dropped from the ρ(s) analysis (492 of 496) are unexplained. Nothing suggests overclaiming beyond the headline-emphasis issue above.

## Strengths

- Solves the reference problem for measuring *missing* checks via code-blind expected-contract derivation, with an explicit information-visibility matrix and audited blinding — methodologically the cleanest way to make omissions visible.
- Unusually thorough validation for an empirical study: frozen coding schemes, 17,428 double-review judgments with adjudication, both AC1 and κ reported with a principled reason for the skew correction, and a quantified leakage audit.
- Goes beyond description to causality: Stage III shows each exploitable gap actually triggers (or why not, with miss causes recorded), and that enforcing the expected constraint in code — not prompting harder — stops the exploits, including a negative control for prompt-labeling fixes.
- The ten gap patterns, the consumer-type triage rule, and the per-pattern exploitability table (Table 9) are directly actionable for agent developers and framework maintainers (fail closed, validate tool names against offered sets, parsers that raise rather than fall back).
- Real-world impact path: all 38 triggered mechanisms disclosed privately to maintainers with patches; per-system case studies (Gemini CLI, gpt-researcher, khoj, Codewhale, STORM, JARVIS, skyvern) are concrete and verifiable.

## Limitations

- The expected contract is normative; different analysts (or agent models) might admit different constraints, so absolute gap rates carry that uncertainty even with AC1 0.95 agreement among author-reviewers.
- Trigger tests use a single substitute model (deepseek-v4-flash) and ≤10 framings, so trigger frequency under each system's default model is unknown; results are one commit per system, and closed-source agents and pure agent frameworks are out of scope.
- Feasibility screening is manual — a wrong exclusion could hide an exploit (mitigated by mandatory source-line citations), making the 290 exploitable gaps a lower bound rather than an exact count.
- Patch validation covers the security dimension but not a systematic utility check that fixed agents still complete benign tasks well (only the three label-only fixes were compared on a real model), and 15 of 38 fixes remain partial against variants or sibling paths.
- Stage I/II automation depends on one proprietary LLM (GPT-5.6 Sol) with isolated contexts; sensitivity of the extracted contracts to the analyzing model is not measured.

## Relevance

与"Agent & Pipeline Silent Failures"方向高度契合：本文正是对模型与世界之间的软件层（智能体 harness、工具调用分发、回复解析与执行）如何"悄悄放行"未经检查的模型输出所做的首次大规模量化，并给出可检测（缺口模式、消费端分类、契约作为测试预言）与可修复（最小代码补丁）的完整证据链。对任何需要评估或加固 LLM 智能体系统可靠性与安全性的工作，这是一篇提供分类学、数据集和方法论基线的核心参考文献。

## Questions for Further Exploration

- How stable are the expected contracts and gap rates when the derivation agent is swapped (e.g., an open-weight model or multiple diverse models voting), and can maintainers of the studied systems be recruited as external validators of the normative reference?
- Can the ten gap patterns be turned into static/dynamic detector rules (e.g., flagging handlers that return approval on parse failure, or verdicts tested by string prefix) that run in CI, and what false-positive rates would they hit on the released 496-site corpus?
- Do the trigger rates generalize to each system's default model — e.g., does OpenManus's 0/10 injection-recognition rate hold for stronger or weaker models, and does the Codewhale "refusal mentioning the fence executes as code" second trigger depend on the model's refusal phrasing?
- What is the utility cost of the contract-guided fixes on benign tasks (only three label-only fixes were evaluated on a real model), and can capability-bound enforcement (scoping tools per call site) be retrofitted into agent frameworks without breaking their plugin ecosystems?
- Could expected contracts serve as runtime monitors or test oracles in continuous integration, catching drift when a system swaps its underlying model — given the paper's observation that refusals (15 of 22 never-triggered mechanisms) are model-dependent while code-enforced constraints are not?
