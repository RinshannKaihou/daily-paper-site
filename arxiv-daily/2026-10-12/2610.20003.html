What Coding Agents Leave Unsaid: Measuring Task-State Gaps Between Execution and Reports

Guoyang Xu · Rui Zhang · Xiuyu Wu · Hao Chen — Tencent | 2026-10-14 | 37 SWE-bench Verified tasks · 4,799 probes

Key metric · recoverability gap
40.7pts

Report-only readers recover 52.0% of task-state probes vs 92.7% with full execution context. 95% CI [37.3, 43.8] · identical questions, same observer, different views · 4,799 valid probes / 37 tasks

Why this matters

Turns agent-report auditability into a measurable benchmark — anyone delegating long tasks to coding agents needs structured state reporting, not terminal scrollback.

Critical edge

One pipeline family — “HY4-preview” — extracts the atoms, writes the probes, observes, and grades, structurally favoring execution-grounded detail that report views lack by construction.

Methodology · paired-view measurement
checkpoint▸fact atoms▸probes▸U · V · T views▸observer▸judge▸Gapview

Built on SWE-bench Verified: a 37-task headline subset (148 checkpoints; 23 dev / 14 held-out, split by issue). Each session follows a fixed protocol — investigate, implement, test & report, assess residual risk — with trajectory prefixes and workspace snapshots recorded at every checkpoint; hidden tests label outcomes.

At each checkpoint three information views are defined: U (accumulated reports, ≈6.6k chars), V (terminal scrollback, ≈25.5k), Tfull (complete recorded context). A pipeline model extracts factual atoms (state category + importance 2–3) and generates probes with reference answers; a validity filter keeps probes answerable from full context but not from the task description alone (4,799 / 4,855). The same observer answers each probe under its assigned view; an independent judge awards full / partial / no credit; accuracies are category-weighted with issue-cluster bootstrap CIs.

Headline statistic: Gapview = Acc(T) − Acc(U); an isolated actor fork lets the agent itself answer as an auxiliary control.

Tencent · 36 pp · benchmark + code public (github.com/Kaguraaaaaa/Ctxgap) · dual human annotators κ = .632 / .638 · replicated across 3 harnesses, an independent executor, and an independent measurement chain

Mention is not recoverability: a mention-only edit changes nothing (Δ = −0.002, CI [−.027, +.025]); adding reference-guided evidence adds +0.189. Exemplar: the agent found that a Django password change triggers HTTP 500 with custom user models — its reports never conveyed it (U 0/3 vs T 3/3).

Even the best matched-length rewrite recovers only ~⅕ of the gap — and it was written with access to the full context, so it is a counterfactual ceiling, not a deployable policy.

Strengths
  • Clean paired-view design: identical questions, same observer, fixed grading — isolates the reporting channel.
  • Exceptional robustness battery: cross-harness, cross-executor, cross-measurement-chain, generator×observer factorial, paraphrase and rubric audits.
  • Human-grounded anatomy (dual annotators, κ reported) turns “agents underreport” into an actionable diagnosis.
  • Interventions honestly framed as offline upper bounds, not autonomous policies.
  • Public benchmark and code — a concrete target for future reporting-policy research.
Limitations
  • No human supervisors: decision relevance and instruction-change effects are model-assessed.
  • Single-family primary pipeline (anonymized “HY4-preview”) across extraction, probing, observation, grading.
  • Non-random, Python-only, SWE-bench-Verified-only cohort that underrepresents harder issues — headline gap plausibly inflated.
  • Matched-length rewrites were built from full context; not an autonomous reporting effect.
  • Reasoning-bearing trajectory texts withheld pending review; replication is statistical, not textual.
  • Measures recoverability, not intent — cannot separate deliberate omission from lossy communication.
Questions for further exploration
  1. Would “report everything relevant” training shrink the gap — and at what verbosity cost?
  2. How much can adaptive human follow-up questions recover, versus any static report rewrite?
  3. Does the gap persist outside Python SWE-bench — web agents, data analysis, longer horizons?
  4. Can “mentioned but insufficient” states be predicted online, before a supervisor asks?
  5. Would a fully third-party, human-written probe set reproduce the 40.7-point magnitude?
  6. Does better recoverability improve downstream outcomes — fewer faulty merges, faster review?
