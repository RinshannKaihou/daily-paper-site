Prefill expert reduction in MoE models breaks answer form at a handful of boundary tokens — not content, not attention sinks.

一句话总结：半数 routed experts 削减造成的短答案 F1 损失，主要不是"找不到答案"，而是"不会按指令简短作答"；损失集中在极少数紧邻答案边界的 prompt token 上——保住约 4% 的任务接口 token 即可把 F1 保持在与原模型 1 分以内。

Where Prefill Expert Reduction Hurts MoE Models: A Few Prompt Tokens Carry Most of the Short-Answer F1 Loss ↗

Key metric
−8.07 F1
two tokens, whole loss

Reducing only the two chat-template tokens before the answer (8→2 experts, Qwen3, HotpotQA) costs −8.07 F1 — as much as reducing the last eight together. Keeping those two full shrinks the uniform loss from −3.38 to −1.06.

Why this matters

A concrete placement rule for MoE serving: keep full experts on the task interface — directly relevant to long-context RAG and agentic deployment.

Critical edge

The central practical claim — reading application marks beats positional rules — is not supported by the paper's own data: KeepEnds 32+32 is statistically indistinguishable from Interface-Full.

Methodology three-tier causal dissection

Setup: prefill-only expert reduction — each prompt token keeps its k′ highest-weight routed experts (Qwen3: 8→4, DeepSeek-V2-Lite: 6→3), generated tokens always run all K, shared experts untouched. Primary task: HotpotQA distractor, ~1,800-token prompts, short-answer F1, reasoning off; LongBench, code completion and GSM8K as checks.

WHATToken/span/layer/attention interventions via HF forward hooks (validated against vLLM: −8.02 vs −8.05); F1 split into precision / recall / answer length to separate form from content.
WHERESingle-token isolation + prefix sweeps — reduce or keep-full one span at a time; families compared on a shared prompt ruler.
WHYPrespecified mechanism tests against attention-sink / super-expert / massive-activation hypotheses, scored by share of the answer-NLL increase each repair removes.
SPENDEqual-budget placement batches in vLLM 0.31 on real marked prompts — Interface-Full, KeepEnds, template-role, positional and negative controls, one fused-MoE hook each.

Statistics well above genre norm: four prespecified batches with decision rules written into analysis scripts beforehand, paired bootstrap intervals, Holm correction, full-budget code-path and unmarked-prompt controls; post-hoc comparisons labelled as such.

Strengths
  • Clean three-tier design (what → where → why) linking token-level interpretability to a serving-level rule on real prompts in vLLM.
  • Statistical hygiene above the norm: prespecified primaries with decision rules, paired bootstrap CIs, Holm correction, negative / inverted / full-budget / unmarked controls, claim-to-batch appendix.
  • Genuine falsification: sink / super-expert / massive-activation hypotheses tested directly and excluded — not gestured at.
  • Form-vs-content decomposition (precision / recall / length, containment, marker compliance) is a simple, reusable diagnostic.
  • Unusual candour — negative and undecided results reported with the same prominence as confirmatory ones.
Limitations
  • Task and metric narrowness: short-answer QA with reasoning off; F1 is length-sensitive and the “form loss” framing partly depends on it.
  • Only aggressive reduction tested (halving, 8→2) — milder pruning known to suffice is out of scope; models ≤35B.
  • Mechanism traced only in Qwen3; partial repairs non-monotone; the key clean-keys-and-values patch fails outright (NLL → 6.68).
  • Placement variance (~1.8 pts between identical random placements) is as large as several reported effects and excluded from intervals.
  • Interface-Full leaves an unlocated −1.6…−2.4 residual on question-first, tool-output and code layouts.
  • Serving measured single-GPU, one request at a time, no prefix caching; 2K-token TTFT null and Qwen3.6 slowdown unexplained.

Questions for further exploration open threads

  1. Does the boundary-token localisation survive milder reduction (⅔ experts), larger models, or reasoning-enabled workloads — and does it reappear when traces are cached and replayed as prompts?
  2. Can the “instruction written into boundary tokens by mid-layer experts” account be uniquely identified with causal scrubbing that avoids the non-monotone mixed-state failures?
  3. Where does Interface-Full’s residual 1.6–2.4-point loss on question-first / tool-output / code layouts come from — and can a content-token budget close it without gold labels?
  4. Is the negative control’s failure purely positional, or do document-internal full tokens actively harm via inconsistent expert-width states?
  5. Does the form-loss diagnostic transfer to other serving-time perturbations — quantization, KV-cache compression, speculative decoding — as a cheap early-warning signal?
