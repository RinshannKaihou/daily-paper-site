Why this matters

Deployed medical AI must keep its uncertainty honest: compression that preserves Dice while degrading calibration and failure detection is a silent safety risk.

Critical edge red flag

The headline 7.29× is a storage metric, not deployment speedup — the runtime-deployable TensorRT policy reaches only 1.58× on AMOS22, vs MedPTQ's 3.90×.

Methodology post-training, no retraining

SGAV-MP (Score-Guided, Aggregate-Validated Mixed Precision) takes a trained FP32 segmenter plus a labeled calibration split, and outputs a per-layer precision policy greedily — but acceptance is decided by the whole model, never by layer scores alone.

  1. Score every candidate

    Benefit U = parameters saved, Nℓ(32 − rb), divided by single-layer reliability impact plus a connection-aware architectural risk; Pareto-filter the actions.

  2. Propose greedily

    Highest S = U / (I + λM·M + ε) picks the next action (layer, precision ∈ FP32 / FP16 / INT8 / INT4 / INT2).

  3. Validate the FULL model

    Every candidate policy is evaluated end-to-end on the calibration split against all four aggregate gates:

  4. Accept or reject permanently

    No layer-additivity assumption, no backtracking — layer scores only rank proposals.

Dice ≥ FP32 − εD ECE ≤ FP32 + εC ρU ≥ τU AURC ≤ FP32 + εR

Scoring uses 10% of the calibration data by default. Hessian/Fisher risk terms exist (Eq. 21) but run disabled (ηH = ηA = 0). Storage compression (mixed INT4/INT2) and TensorRT runtime measurements are reported separately — never conflated.

  • Pareto frontier — relaxing ρU tolerance buys compression: 4.89× @ 0.970 → 5.91× @ ≈0.94–0.95 (MosMedPlus/RN50); 4.86× @ 0.968 → 6.23× @ ≈0.947 (DenseNet121).
  • Ablation — the UQ term drives compression (7.17× @ ρU 0.9545 alone); the connection-aware term lifts ρU 0.9500 → 0.9697 at 7.29×.
  • Cross-dataset — calibrated on PROMISE12, tested on MosMedPlus: Dice 0.779–0.791, ρU 0.942–0.968, 4.06–5.73× across all five backbones.
  • Runtime (TensorRT, RTX 6000 Ada) — deployable policy: 1.58× / 1.580 ms on AMOS22/UNet3D (MedPTQ: 3.90× / 0.843 ms) but best ρU 0.9972; in 2D, faster and smaller-context than INT8 (0.791 ms / 34.72 MB vs 0.903 ms / 37.13 MB).

Proposition 1 why Dice lies

quantized logits (a−δ, δ), 0 < δ < a/2  ⇒  argmax preserved, entropy ↑

A two-class logit perturbation proves hard-mask stability and uncertainty stability are mathematically distinct. Empirically: INT4 on PROMISE12/EfficientNet-B0 moves Dice only 0.8892 → 0.882, while ρU falls 1.000 → 0.428 and ECE worsens 0.0982 → 0.112.

Strengths

  • Identifies a genuine safety blind spot, backed by both a clean proposition and striking collapses (ρU 1.000 → 0.119 under INT4).
  • Full-model validation gate is the right design — skips the false "layer damages add up" assumption where Hessian Greedy (0.4547) and score-only (0.2549) fail at ~7.9×.
  • Broad protocol: 2D + 3D, MRI + CT, five backbones, five datasets, six metric families, real TensorRT hardware runs.
  • Unusual honesty: separates storage from runtime, reports MedPTQ winning on latency, INT4 competitive on AMOS22, and its own build costs.
  • Clean ablation attributes each gain; the Pareto analysis reframes precision choice as a reliability–compression frontier.

Limitations

  • No automatic speedup: INT4/INT2 policies are storage-only; the runtime-legal config compresses less than uniform INT8 in 2D (2.25× vs 3.81×).
  • Expensive search: ~510 s to ~28,253 s per policy, up to ~19.9 GB peak GPU memory.
  • Inherits the FP32 teacher's calibration — ρU 0.94 against a miscalibrated reference (ECE 0.2064) faithfully reproduces miscalibration; only one cross-dataset shift tested.
  • Deployment story weakened: MedPTQ not compared on the studied SegResNet (backend swap to UNet3D); no foundation segmenters (VISTA3D, MedSAM); ImageNet encoders, not nnU-Net-style architectures.
  • Details deferred: thresholds, five-backbone grids, BTCV (6 test volumes), and calibration sweeps live in a supplementary not included.

Questions for further exploration

  1. Target-aware constraints — do calibration-set gates survive real scanner / site / protocol shift, where the FP32 reference's own calibration may drift?
  2. Search efficiency — would backtracking, lookahead, or enabling the Hessian risk terms cut the ~7.9 h BraTS build?
  3. Foundation segmenters — does the argument transfer to VISTA3D / MedSAM-style models, and to other uncertainty sources (ensembles, MC dropout, probabilistic U-Net)?
  4. Absolute budgets — should the target be a reliability floor (e.g. post-quantization recalibration) rather than matching a possibly-miscalibrated FP32 teacher?
  5. Real INT4 kernels — which paths (weight-only INT4 + FP16 compute, upcoming TensorRT support) turn 7×-class storage into genuine latency wins?
