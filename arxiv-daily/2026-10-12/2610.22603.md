> **一句话总结：** Google DeepMind 构建了一条 Gemini 3.1 Pro 驱动的四阶段智能体流水线（模式检测 → 自动猜想 → 非正式证明 → Lean 4 形式化验证），把 BB(6) 剩余 1,094 个 holdout 图灵机当作"灰盒"做开放式的自主数学发现：仅凭 5×10^6 步模拟轨迹猜想并证明描述长期动力学的 Collatz 类加速规则，为 11 台此前无人分析过的机器产出了经 Lean 内核检验（0 sorry、无未授权公理）的新加速，另为 15 台社区已猜想过的机器补上了形式化证明。

> **TL;DR:** Rather than solving predefined problems, this DeepMind paper points AI at the uncomputable Busy Beaver frontier, where BB(6)'s search space of 2.32×10^17 machines has been whittled by community deciders to 1,094 unresolved holdouts (18 recognized as Cryptids, per bbchallenge Wiki). A Gemini 3.1 Pro pipeline treats each machine as a "grey box" — simulating it for 5×10^6 steps, compressing tape configurations into block exponents, having the LLM conjecture executable Python transition rules (filtered at 100% empirical accuracy), then prove them informally and finally verify them in Lean 4.28.1 with a multi-persona agent (72-hour budget, adversarial Critic, 0 sorry required). Outcome: novel, formally verified Collatz-like accelerations for 11 previously-unanalyzed BB(6) holdouts (provisional new Cryptids, +11 vs the 18 known) plus formal proofs for 15 community rediscoveries (2 exact, 8 equivalent, 3 different decomposition, 2 undetermined) and 1 BB(2,5) acceleration. Caveats: no machine's halting is actually resolved (acceleration ≠ resolution), the method only finds Collatz-like structure, novelty is judged against informal Discord/Wiki analysis, and several discoveries came from a second-stage Gemini 3.8 Flash auto-research run whose contribution split is not cleanly reported.

## 核心贡献

- **把"自主数学发现"的测试床搬到不可计算的前沿**：不同于 IMO 奖牌或解决既定猜想等"预定义问题"，作者选择 Busy Beaver 域——BB(n) 不可计算、增长快于任何可计算序列，天然提供永不枯竭的开放问题流；BB(5)=47,176,870 刚由 bbchallenge 社区人工协作确定（STOC 2026），BB(6)/BB(2,5)/BB(3,3) 仍有 Cryptid 挡路。
- **四阶段端到端流水线（全程 Gemini 3.1 Pro）**：(1) 模式检测——定制贪心压缩算法（简单性得分 = 重复次数/块大小，含一步前瞻）把原始纸带解析为块指数表示，取模拟 5×10^6 步中出现频率最高的 K=100 个抽象模式；(2) 自动猜想——LLM 为每个模式写出可执行的 Python 转移函数，把"猜想"变成可自动评测的代码；(3) 交互式精化——给 LLM 一个模拟工具，可对自选的合成指数（如 x=0, z 奇数）主动探测轨迹上可能永远遇不到的边界情形，补齐停机分支等缺失规则（N=5 轮）；(4) 非正式证明 + Lean 4 形式化——生成器-评估器循环（正确性评分与格式评分各 0/0.5/1，M=4 轮迭代）后，由多角色（Problem Setter / Planner / Writer / Critic）智能体在 Lean 中完成机器检验证明。
- **反常规的形式化策略**：不同于把非正式证明当真值逐句翻译的 autoformalization，该智能体允许在证明过程中修改被形式化的命题本身——为规则补上缺失的变量边界、增补遗漏的转移规则，但图灵机定义与起始格局固定不变；最终系统的合法性由两条铁律保证：每条规则都对固定机器证明过，且系统封闭（起始格局与每条规则的输出要么停机要么命中某条规则的输入），并在独立的对抗式审计（0 sorry、无作弊公理）下通过。
- **实证产出**：对 1,094 个 BB(6)、65 个 BB(2,5)、4 个 BB(3,3) holdout 的扫描识别出 52 个候选机器（BB(6) 占 50），最终产出 11 项全新发现（含 Lean 证明的 Collatz 类加速）与 15 项再发现（为社区在 Wiki/Discord 上的猜想补上形式化证明），另加 1 项 BB(2,5) 加速。
- **方法上的通用性主张**：因为只观察模拟行为而不静态分析转移函数，方法原则上适用于任何图灵完备语言（Python/C++），是面向"自主发现数学结构并形式化"的通用蓝图。

## Key Contributions

- **Repositions autonomous mathematical discovery on an uncomputable frontier.** Instead of predefined benchmarks (IMO medals, Navier-Stokes), the target is the Busy Beaver domain: BB(n) is uncomputable, BB(6)'s residual holdouts are tied to open Collatz-like problems, and the question supply is provably endless — a testbed for open-endedness that no future algorithm can exhaust.
- **A four-stage grey-box pipeline (Gemini 3.1 Pro throughout).** Pattern detection compresses 5×10^6-step execution traces into block-exponent patterns (top K=100 by frequency); automated conjecturing has the LLM write executable Python transition functions so conjectures are cheaply testable; interactive refinement gives the LLM a simulator to probe synthetic configurations unreachable on the blank-tape trajectory (up to 128,000 steps per probe, N=5 turns), which is how missing halting branches get discovered; informal proving uses a generator-evaluator loop with correctness and format scores (M=4 iterations); formal proving is done by a multi-persona Lean 4 agent.
- **Autoformalization as revision, not translation.** The Lean agent (building on the BusyLean repository) may modify the seeded theorem statements — adding parameter bounds or new transition rules — while the Turing machine definition and start configuration stay fixed; validity is anchored in per-rule proofs plus system closure, verified by an adversarial Critic with a 0-sorry, no-unauthorized-axioms acceptance criterion and a 72-hour cap.
- **Concrete new mathematics.** Eleven BB(6) holdouts with no prior documented analysis received novel, formally verified Collatz-like accelerations (provisional Cryptids); fifteen previously-studied machines got formal proofs of community-conjectured rules; one BB(2,5) machine (first analyzed by mxdys, Mar 2025) got a new acceleration with proof.
- **A second-stage auto-research system.** After the main pipeline, a general-purpose auto-research agent (Gemini 3.8 Flash, with access to all paper results and code) was unleashed on the remaining suspects, incentivized by points for compressed accelerations — an early demonstration of an AI system re-using a paper's own artifacts to extend it.

## Methodology

The pipeline treats each Turing machine as a **grey box**: full visibility of execution state, agnostic to the transition code.

1. **Pattern detection.** Simulate for S = 5×10^6 steps with a simulator from the busy-beaver repository, recording every configuration. A custom greedy compression algorithm (simplicity score = repetitions / block size, one-step lookahead for boundary conflicts) parses tapes like 0∞ 11011111111 E> 0∞ into block form 0∞ 1² 0 1⁸ E> 0∞, which abstracts to patterns ((1,0,1,E), RIGHT) with exponents stripped. The top K = 100 most frequent patterns isolate the machine's dominant cyclic behavior.
2. **Automated conjecturing.** For each pattern, observed consecutive instances give exponent mappings, e.g. (2,1,8) → (4,1,14) for Antihydra. The LLM synthesizes a Python function mapping input exponents to output exponents; correctness is measured by execution over the full transition dataset. Conjectures must hit **100% prediction accuracy** to advance.
3. **Interactive refinement.** Because rare edge cases (e.g., z odd with x = 0, which triggers halting in Antihydra) may never occur in billions of steps, the LLM queries a simulation tool with synthetic exponents of its choosing (128,000-step cap per probe), discovers missing branches, and revises the rule over N = 5 turns — then rewrites it as a clean piecewise-affine (Collatz-like) mathematical function, composing multiple steps where possible.
4. **Informal proving.** Each case of the rule is proved separately in a generator-evaluator loop: a Proof Generator drafts step-by-step proofs; a Correctness Evaluator (score 0/0.5/1: fatal errors vs minor omissions vs fully correct) and a Format Evaluator critique; only proofs scoring c = f = 1 proceed, within M = 4 iterations.
5. **Formal proving in Lean 4.28.1.** Seeded with an equivalence statement, a closure statement, and target theorems, four personas (Problem Setter, Planner, Writer, Critic) work round-robin over a shared workspace. The Problem Setter may repair unprovable statements using simulation tools; the Critic audits for unproven steps, illegal axioms, and reward hacking. Termination: all theorems compile with zero `sorry`, or a 72-hour timeout. All final Lean statements were additionally manually validated by the authors; proofs are on a public GitHub repository.

## Results & Highlights

- **Candidate discovery rate on the BB(6) holdout set:** from 1,094 BB(6) holdouts (out of an initial space of 2.32×10^17 machines) plus 65 BB(2,5) and 4 BB(3,3) holdouts, a single conjecturing attempt per pattern surfaced **52 candidate machines** (50 in BB(6), 2 in BB(2,5)) each with ≥2 conjectures passing the 100% empirical-accuracy threshold — against a pre-existing baseline of **18 community-recognized Cryptids in BB(6)** (Table 2).
- **New discoveries:** **11 BB(6) machines** with **no prior documented community analysis** received novel Collatz-like accelerations, each with the machine's halting problem formally reduced in Lean to an arithmetic question (halt iff the Collatz-like system reaches a halting configuration) — a provisional increase of BB(6) Cryptids from 18 to 29 (+61%), subject to community acceptance (Tables 1–2).
- **Rediscoveries:** for **15 previously-studied machines** (e.g., BMO1/BMO5/BMO8 machines analyzed by mxdys, Shawn Ligocki, and Racheline on the bbchallenge Wiki/Discord), the pipeline produced formal Lean proofs of similar rules; Table 3 classifies them as **2 exact, 8 equivalent-reformulated, 3 different decomposition, 2 undetermined** (the latter because community rules existed only as Discord posts the authors could not reproduce). A further **1 BB(2,5) acceleration** was proven for the machine first analyzed by mxdys on 12 Mar 2025.
- **End-to-end verification budget per machine:** S = 5×10^6 simulation steps for pattern detection, K = 100 patterns, 128,000-step cap per synthetic probe, N = 5 refinement turns, M = 4 informal-proof iterations, and a 72-hour limit on the Lean agent — with acceptance requiring 100% empirical accuracy, c = f = 1 evaluator scores, and 0 `sorry` in compiled Lean.
- **Context baseline:** BB(5) = 47,176,870 was determined by the human bbchallenge collaboration (STOC 2026) with no AI; this work is the first systematic AI contribution to the BB(6) holdout analysis, and relatedly Claude Opus 4.6 was recently used to resolve the FRACTRAN BB_f(21) cases (per Wiki, cited as concurrent work).

## Authors & Credibility

Google DeepMind authors (Marco Dos Santos — also University of Cambridge, work done at DeepMind; Vivek Veeriah; Alex Havrilla; Andrew Bolt; Goran Zuzic; Satinder Singh; Tom Zahavy). The team sits squarely in DeepMind's AI-for-mathematics line (AlphaEvolve is cited as related work with authors overlapping the AlphaEvolve citation list). Credibility signals are strong: every claimed acceleration is backed by a machine-checked Lean 4 proof (publicly released), final Lean statements were manually validated, correspondences with community-published rules were checked by direct simulation (Table 3), and the paper is unusually candid that its Cryptid classifications are "subject to community acceptance" and that its Definition 2.1 (Cryptid) is deliberately broader than the community's stricter usage. Attribution against informal community sources (Discord, Wiki) is documented machine-by-machine in Table 1 — including cases where a Discord comment by a user prefigured the result.

## Critical Assessment

- **Novelty is real but narrower than the headline.** The autonomous pipeline is genuinely new for BB(6), but the discovered mathematics is deliberately confined to Collatz-like piecewise-affine systems — a family the community already studies; the authors themselves state the system "currently accelerates machines exhibiting Collatz-like functions" and frame broader open-endedness as future work. The 11 "new discoveries" are new *accelerations + proofs*, not resolutions of any halting question.
- **Novelty attribution rests on informal sources.** "No prior documented analysis" is judged against the bbchallenge Wiki and Discord; the paper's own Table 3 lists 2 rediscoveries as "Undetermined" because community rules posted only on Discord could not be reproduced — demonstrating exactly how soft the new-vs-rediscovery boundary is. The 11 machines marked † were mentioned by dyuan01 as high-"complexity score" holdouts without rules, which the paper does disclose.
- **A two-stage provenance blur.** Several discoveries (marked ★) came from a second-stage general-purpose auto-research system using a *different* model (Gemini 3.8 Flash) with access to all of the paper's results and code; the paper never breaks down how many of the 11 new Cryptids came from the flagship pipeline vs. this follow-on agent, making the headline pipeline harder to credit and evaluate.
- **No failure statistics, no ablations.** There is no report of how many conjectures failed the empirical filter, how many informal proofs were rejected, how many Lean attempts timed out at 72 hours, or the aggregate compute/API cost — so pipeline yield (52 candidates → 26 verified) cannot be decomposed by stage. No ablations over S, K, N, M or over the persona architecture.
- **Reproducibility is partial.** Lean proofs are public and manually audited (excellent), and the stage-2 prompt is in Appendix E, but the whole pipeline depends on proprietary Gemini 3.1 Pro / 3.8 Flash with no released prompts for the main stages or the conjecturing/refinement loop, so independent replication of the *discovery* half is not possible; only the *verification* half is.
- **Coverage outside BB(6) is thin.** BB(3,3) contributed 0 candidates from 4 holdouts and BB(2,5) 2 candidates (1 verified) — evidence that the Collatz-shaped prior fits BB(6) holdouts but does not transfer broadly. Significance is also honestly flagged: whether progress on these Cryptids illuminates Collatz itself "remains speculative."

## Strengths

- Machine-checked ground truth: every acceleration is verified by the Lean 4 kernel with zero `sorry`, an adversarial Critic auditing for reward hacks and unauthorized axioms, and post-hoc manual validation of final statements — claims cannot silently overreach their proofs.
- The grey-box, simulation-only design decouples the method from Turing-machine specifics and should transfer to any Turing-complete language.
- Interactive probing of *unreachable* configurations is a clean solution to the "edge cases never occur on the observed trajectory" problem that pure trace-fitting suffers from.
- Autoformalization-as-revision (allowing the Problem Setter to fix the statement while the machine definition stays fixed) mirrors real mathematical practice and avoids the classic unprovable-translation failure mode.
- Exceptional honesty: provisional-Cryptid framing, Table 1's per-machine attribution to community members, and explicit acknowledgment that the broader significance of Busy-Beaver-derived questions is not guaranteed.

## Limitations

- No halting behavior is actually resolved — the pipeline accelerates and structures the open problem; BB(6), BB(2,5), BB(3,3) remain open, and halting for the new Cryptids reduces to unresolved Collatz-like questions (as with Antihydra's trajectory from A(0,4)).
- The Collatz-like prior is baked in: machines whose structure is not block-exponential piecewise-affine will yield no conjecture, and the paper offers no mechanism for discovering *novel* classes of open problems.
- Stage composition and cost are unreported (no failure counts, no compute accounting, split between main pipeline and the Gemini 3.8 Flash second stage undisclosed).
- Reliance on proprietary frontier models makes the discovery half non-reproducible; only the Lean proofs are independently checkable.
- Empirical filtering at 100% accuracy over finite (and partly synthetic) data is necessary but not sufficient for coverage of all congruence classes — the burden falls entirely on the Lean closure proof, which is sound, but conjecture *generation* may simply stall for other machines.

## Relevance

这篇论文是"Self-Evolving Agents & Automated Research"方向的典型案例：它展示了一个无需人类提出问题的自主研究闭环——从模拟数据中猜想数学结构、自我批判式地写证明、再用形式化工具自我验证，并用独立的对抗审计器防奖励作弊；其"猜想即代码 + 交互式探测 + 可修订形式化"的流水线设计对构建可靠的长期自主科研智能体有直接借鉴意义。

## Questions for Further Exploration

- How many of the 11 new Cryptids were found by the flagship Gemini 3.1 Pro pipeline versus the second-stage Gemini 3.8 Flash auto-research agent, and how do the two systems' yields compare per unit of compute?
- Can the pattern library be extended beyond block-exponential/Collatz-like structure (e.g., to tag systems, cellular-automaton encodings, or Fractran-style dynamics), and would BB(3,3) or BB(2,5) holdouts then yield candidates?
- What fraction of the 52 candidates failed at each subsequent gate (informal proof, Lean closure), and which pipeline stage is the bottleneck — conjecture quality, statement repair, or proof search?
- Can the discovered accelerations be exploited by deciders or inductive-closure search to actually resolve any of the 11 new Cryptids, or do they all bottom out in genuinely open Collatz-like problems like Antihydra?
- Does the autoformalization-as-revision protocol (statement repair under a fixed machine definition) transfer to other formalization targets where informal proofs are known to be subtly wrong, e.g., published proofs with gap reports?
- What stopping/completeness guarantees can be stated for the Critic's audit — in particular, can "closure + per-rule proofs" be strengthened to also certify that no simpler acceleration exists?
