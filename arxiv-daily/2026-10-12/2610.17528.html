Why this matters

Expert-level training-recipe tuning is now unattended agent work on real 64–128 GPU clusters — and the agent-search + deterministic-gate pattern generalizes to LLM systems automation.

Critical edge — read before citing

The headline +33.9% measures improvement over a public recipe written for H100 and ported to their B200 stack — some gain is porting friction, not tuning genius.

— Critical Assessment, caveat #1 · their stack reaches 397.3 vs the published 661 tok/s/GPU on Llama-3.1-405B

Methodology

Agent-driven search, deterministic checks outside the agent.

diagnose run→ state hypothesis→ change ONE lever→ 14-step run (4–13)→ beats noise band?→ gate: config + 20-step loss→ ship / revert

Campaign & measurement

One model, one cluster, fixed GPU count, GPU-hour budget. Workload shape held identical across candidates; 14 optimizer steps, steps 4–13 measured as sum-then-divide tokens/s/GPU; baseline run ≥5×, noise band max(3%, 3σ).

Agent discipline

One coding agent (Claude Opus 4.8, web disabled) in a reason–act loop: hypothesis before launch, one lever or one coupled parallelism set per candidate, read a flag's source before using it, retry OOM layouts with the leader's memory savings before ruling them out.

Correctness gate (agent-independent)

Layer 1: config check on fully resolved args — refuses objective-changing flags and silent overrides. Layer 2: 20-step loss-curve comparison vs baseline (per-step tol 2–10%, final Δ ≤5%, corr ≥0.95). Only structural or same-math levers may ship.

Harness

Stop hook until budget spent; deny-by-default shell; append-only ledger for crash-resume. Every job — including failures — is charged its GPU-hours.

Four held-out models, strongest public recipe as baseline, identical budgets and gate.

Strengths

What the paper genuinely delivers.

  • Diagnoses like an expert, not a sampler — reached a winning recipe in ≤8 launches while black-box search with the same levers mostly OOMed or got pruned.
  • Gate enforced by the control plane, not the agent, with measured error rates and re-checks on resolved args to catch silent flag overrides.
  • Honest negatives — ships Mixtral unchanged when nothing clears the noise band; reports the band itself.
  • Autonomy engineering that survives crashes — stop hooks, deny-by-default shell, append-only ledger resume.
  • Releases the tool and TrainingThroughputBench — a correctness-gated, cost-annotated recipe leaderboard (MoE up to 744B params).

Limitations

Where the claim weakens.

  • Baselines tuned for other hardware, run on the authors' stack — gains measure improvement in their setting, and their absolute throughput sits well below published figures.
  • Only the models were held out — stack, accelerators, and agent model are exactly those used in development; possible family-prior leak (GLM-5.2 → GLM-4.5).
  • Skill rules are advisory — skipping the OOM-retry rule cost 2 of 3 GLM campaigns roughly half the achievable gain.
  • n = 3 campaigns per arm — permutation p = 0.05–0.125; campaign-to-campaign variance swamps most arm differences.
  • Config-only scope, and the 20-step gate is a short-horizon proxy (long-run convergence verified for just one shipped recipe, 1,000 steps).

Questions for Further Exploration

  • Would enforcing the six search rules in the harness make the +54.7% outcome the norm instead of the lucky 1-of-3?
  • How does ATTUNE behave on held-out stacks, clusters, and agent models — Qwen3/DeepSeek-V3, AMD, cheaper agents?
  • Can a cheap long-horizon guarantee (gradient-statistics fingerprints?) catch the four subtle fault types the 20-step check misses?
  • Does the approach extend to RL rollout/generation phases or ZeRO/FSDP stacks with different flag-interaction graphs?
  • With multiple teams feeding a shared skill, does the catalog compound or go stale?

Credibility

Amazon systems team with real 64–128 GPU H100/B200 clusters; multi-hundred-GPU-hour campaigns that cannot be faked on a workstation.

Agent model named, not hidden: Claude Opus 4.8, web tools disabled, frozen skill for evaluation arms.

Code + TrainingThroughputBench: github.com/amazon-science/attune · mean-rule decisions with exact permutation p-values · randomized interleaved re-measurement
