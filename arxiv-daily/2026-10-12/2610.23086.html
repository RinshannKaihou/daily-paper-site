Why this matters

A 5.3 µs, pre-colocation latency predictor directly drives co-location scheduling and SLO admission decisions in multi-tenant GPU inference.

把 SM 分区下的算子级干扰归因到共享 L2/DRAM 通路，给出共置前即可用、微秒级查询的延迟预测器，直接服务于推理共置决策与 SLO 保障。

⚠ Critical edge

In-distribution Llama HP error is 10.3% — 2.4× the headline 4.3% — so the headline number is dominated by CNN/BERT pairs.

Methodology

measure → attribute → predict

  1. PARTITION

    SMs split at TPC granularity via libsmctrl masks: registers, L1, warp schedulers isolated — L2 + DRAM stay shared. One latency-critical HP task + one best-effort LP task.

  2. MEASURE

    Co-execute operators and operator pairs across splits. Slowdown δ = T_share(p,q) / T_solo(p) strips out the “simply fewer SMs” effect.

  3. ATTRIBUTE

    T ≈ T_compute + N_miss·(L_base + Q_shared): only the queueing term grows with a co-runner. 7.7k pairs × 10 Nsight counters confirm every target-side counter correlates (p<0.05; |r|>0.9 for duration & L2 traffic).

  4. PREDICT

    Two XGBoost regressors on log δ (one per side), each reading per-operator tokens of both tasks: standalone latency at its allocation, DRAM bytes, long-scoreboard / LG-throttle / MIO-throttle stalls, plus the TPC split (p, q).

  5. COMPOSE & ADAPT

    ≤16-operator windows summed to 96-op segments; 20–100 new samples adapt to unseen models / batch sizes in ≤5 s on CPU.

What the measurement broke
  • Interference is directional: memory-heavy operators (BatchNorm) slow beside both compute- and memory-heavy co-runners — invalidating the compute/memory complementarity rule behind Orion and USHER.
  • Within one intensity class, a single HP operator’s slowdown spans negligible → >2× across co-runners.
  • Even at a fixed SM quota, ResNet-50 runs up to 1.31× longer beside ResNet-101 than beside BERT.

Strengths
  • Clean cause-and-effect narrative: measurement → analytical model → counter correlation → predictor; every design choice traces to an observation.
  • The two-sided, per-operator input is the key idea — ablations (remove co-runner tokens, sum tokens, drop counters) prove each piece earns its place.
  • Interpretable by construction: trees branch on un-hidden memory latency, so compute- and memory-bound segments take different paths.
  • Realistic redeployment: 100 samples + ≤5 s CPU updates drop unseen-Llama error from 30.2% to 13.5%.
  • Serving cost is honest and tiny: microsecond queries, one offline profile per model, 79 s training.
Limitations
  • One GPU type (A100-SXM4-40GB) and one partitioning mechanism; no cross-GPU (H100/L4), MIG, or temporal-slicing validation.
  • Strictly two-task, static SM splits — interference among 3+ residents and dynamic re-partitioning unaddressed.
  • 16-operator window cap with index-paired composition is a heuristic, measured only up to 96 operators and 80 asymmetric cases.
  • Needs an Nsight profile per model + a standalone-latency profile per TPC count — a recurring burden for evolving models (LoRA swaps, growing KV-cache decode shapes).
  • Llama errors (10.3% in-distribution, 30.2% before adaptation) show memory-path features do not fully capture transformer decode interference.
Questions for further exploration
  1. Does PairSight transfer across GPU generations (train on A100, test on H100/L4) and partitioning mechanisms (TPC masks vs MIG vs temporal sharing), or does the queueing-model structure need per-platform retraining?
  2. Can the two-operator interaction features compose to three or more co-located tasks, where Q_shared aggregates traffic from several co-runners — or must the model be retrained at higher arity?
  3. For autoregressive LLM serving, do decode-phase windows (durations growing with KV-cache length) break index-paired composition — and would progress-rate-aware pairing cut the 10.3% Llama error?
  4. Can cheap PMU-sampled substitutes for Nsight counters be exploited online, so adaptation skips the per-model offline profile?
  5. End-to-end scheduler value: when PairSight drives admission control and SM-split selection inside an Orion/USHER-style system, how much do LP throughput and HP SLO attainment improve over the 19.0%-error rule?
