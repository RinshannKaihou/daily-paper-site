Why this matters

A ready-to-use rule for TP vs PP: pick parallelism by workload mix, SLO tightness, and context length — instead of defaulting to TP everywhere.

⚠ Critical edge

One model, one 8×H200 node, one engine, four configs — no tables, no error bars; every number is read off log-scale figures.

01 Methodology

A measurement-and-modeling characterization — no new system is built; every result comes from one fixed testbed.

Model
Qwen2.5-14B-Instruct (BF16)
Hardware
8× NVIDIA H200 (141 GB), single node
Engine
vLLM v0.15.0 · chunked prefill · mem util 0.8
Load
Batch 128 · configs TP8 / TP4PP2 / TP2PP4 / PP8, with NTP·NPP = 8
  1. FRONTIER. Fix Lseq = 1200, vary the input/output split. Decompose per-phase latency T = τ + η + γ (compute + comm/sync + scheduling); build each config's (TTFT, ITL) feasible set → Pareto frontier.
  2. GOODPUT. Define Gp = λp·Fp(Ts) — throughput × empirical TTFT-attainment; sweep SLO Ts ∈ {5,10,20,25} s. Crossover rule: Fi/Fj = λj/λi.
  3. SCALE. Hold Lout = 1000, C = 128; grow Lseq → ~30K and track both throughput decay and SLO-attainment decay under 5 s and 2 s SLOs.

03 Strengths

  • Clean formalization: TTFT-ITL feasible sets / Pareto frontiers give a reusable "operating region" language; fixing Lseq elegantly isolates composition from scale.
  • Goodput rule G = λ·F with an explicit crossover inequality — a checkable selection rule practitioners can apply directly.
  • Long-context insight: scalability is governed by the rate of SLO-attainment decay, not just throughput decay — explains why PP wins as contexts grow.
  • Three independent lenses (frontier, goodput, context scaling) converge on the same TP↔PP transition.
  • Unusually thorough, current related-work coverage.

04 Limitations

  • Single model (Qwen2.5-14B), single node (8×H200), single engine — only 4 configs; no DP, CP, EP, or prefill-decode disaggregation measured.
  • No exact numbers, tables, error bars, or repetition statistics.
  • Synthetic closed-loop workloads; no trace-driven arrivals, burstiness, or mixed lengths.
  • TTFT-only SLO; ITL, end-to-end, and multi-SLO cases unaddressed.
  • "Long context" stops at ~30K — the 128K+ regime where CP binds is discussed, never measured.
  • No adaptive controller delivered; dynamic parallelism selection remains future work.

05 Questions for further exploration

  1. Do the crossovers shift with model size (7B / 32B / 70B) or multi-node interconnects, where TP collectives cost far more?
  2. Where does context parallelism enter the frontier — do TP+CP or PP+CP dominate in the 128K+ regime the paper never measures?
  3. Can the goodput rule become an online controller: how fast, and at what reconfiguration cost, can a system track p*(w, Ts)?
  4. Does the PP-favorable conclusion survive prefill-decode disaggregation, where each phase picks its own parallelism?
  5. Would two-sided (TTFT, ITL) SLO formulations favor hybrids more often than the TTFT-only analysis?
  6. Do bursty, trace-driven arrivals with mixed lengths preserve the fixed-concurrency goodput ranking?
