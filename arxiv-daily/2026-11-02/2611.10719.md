> **一句话总结：** 作者认为"propose→run→measure→update"这个 RSI 闭环在前沿预训练上根本合不上（一次 run 数月、数十万 GPU 时、不可重跑，目标又是无法用单一分数读出的 post-training headroom），于是把它拆成六条能合上的小闭环（两条 debugging + 一条 recipe/headroom + 三条 experience-to-metric），用它们带一个新建团队在三个月里从零训出 801-30B-A3B-Base（30B-A3B MoE，11.8T token）；base 13 项基准均分 73.13，超过 Qwen3-30B-A3B 的 66.16（+6.97）并与 Nemotron-3.5-Lightning 的 73.07 基本打平（+0.06），但落后更大的 Qwen3.5-35B-A3B（76.67）。

> **TL;DR:** A full technical account of one from-scratch frontier-scale pre-training run (801-30B-A3B-Base, Qwen3-MoE architecture, 30B total / 3B active, 11.8T tokens, three months, ~10.5T unique tokens through 6 pipelines / 1,053 subsets) in which LLM agents are put inside the pre-training loop rather than the post-training loop. The organizing claim is that the standard RSI cycle cannot close over an unrepeatable run, so it is decomposed into six cheap loops sharing a "context infrastructure" that stores negative results. Evidence is a case study, not a controlled experiment: on 13 base benchmarks 801 averages 73.13 vs 66.16 for Qwen3-30B-A3B (+6.97) and 73.07 for Nemotron-3.5-Lightning-30B-A3B (+0.06, i.e. a tie), behind Qwen3.5-35B-A3B at 76.67; after one shared 6.33B-token SFT it reaches AVG5 28.70 vs 20.54 for Qwen3.5 (+8.16, driven by SimpleQA-verified 34.50 vs 12.00) and AVG13 81.34 vs 83.76. The most transferable contributions are methodological: layer-wise MaxVio as an earlier warning signal than downstream eval, tiny-SFT re-ranking of checkpoints (Spearman ρ drops to 0.438 late in training — step 159k ranks 1st on base but 3rd after SFT, step 210k goes 6th→1st), a learning-aptitude slope (8.62 vs 3.33 pts per 10× SFT steps on BFCL), and a 2.26× throughput win (1,126→2,543 TGS) from attention-cost-balanced data ordering. Read it for the operational detail and the honest negative results; discount the RSI framing and the "highest agentic average" headline, which rests on one 33.6-point KernelBench outlier.

## 核心贡献

- **把"RSI 能不能进预训练"当成一个可操作的工程问题来回答，而不是概念文章。** 论文明确列出预训练破坏 RSI 闭环的三个条件（一次 run 数十万 GPU 时且不可重跑；目标是 post-training headroom 而非任何单一分数；要改进的是"生产系统 + 组织"而非模型），然后给出替代方案：把闭环**换地方合**——debugging 闭环把 run 挪到可廉价重跑的基础设施/数据栈上，headroom 闭环修复 measure，experience-to-metric 闭环在原本没有度量的地方造出度量。
- **六条具体闭环 + 一个跨团队 context infrastructure。** infra debugging、data debugging、recipe（headroom）、classifier development、site discovery、crawl-coverage；共享的 context infrastructure 把 per-layer loss、per-module gradient norm、expert load-balance 统计、超参改动、数据配比改动、infra diff、checkpoint 评测整合在一起，并**保存失败方案及其原因**——作者把"负结果持久化"当作递归真正发生的地方。
- **五条跨栈诊断，约一个月完成**：MoE 负载均衡（全局 vs 逐 micro-batch）、优化器分配（哪些模块用 Muon / 哪些用 AdamW）、数据质量（模型生成广告 → 追溯到语料里的广告页）、weight decay（router logits 异常 → norm/bias 排除 weight decay）、data loader（换 DP size 恢复训练时 per-step 样本顺序丢失）。每一条都跨越了至少两个团队的证据边界。
- **三条衡量 post-training headroom 的新指标，并用它们推翻了 base 评测的两个直觉**：(1) tiny-SFT 揭示"假停滞"——Stage1-1 在 4.1T–7T 之间 base 均分几乎不动（约 61），SFT 后均分却从 65.34 涨到 66.83；Stage1-3 在 8.1T–11.5T 之间 base 在 64–66 徘徊，SFT 后从 70.54 涨到 72.93。(2) checkpoint 排名不可互换——23 个 checkpoint 的分组 Spearman 相关只有 0.796 和 0.438，step 159k base 第 1（61.41）但 SFT 后第 3（66.22），step 210k base 第 6（60.76）但 SFT 后第 1（66.83）。
- **learning aptitude（学习斜率）作为跨模型比较量**：拟合 s(N)=b+k·log10(N/N0)，用 N*(s*)=N0·10^((s*−b)/k) 折算"达到同一目标所需 post-training 数据量"。BFCL Full 上 801 起点更低（31.32 vs Qwen3-30B-A3B 40.04）但斜率 8.62 vs 3.33（约 2.6 倍），step 697 之后每个共享 checkpoint 都领先，终点 48.65 vs 46.26；SWE-bench Pro 上则是起点与斜率同向（26.95 vs 0，斜率 9.15 vs 5.03）。
- **把 agentic 数据做成预训练的一等数据源**：260K 原始 PR → 220K 可执行任务（>84%）→ 九种 harness 各跑一遍（约 2M 条轨迹）→ 验证通过率 55% → 1.1M 条、>100B token、平均约 91K token/条，加上其他来源共 134B token，在 Stage3 占 15% 采样配比。配套给出六类 anti-hack 行为清单（从 git 历史捞参考补丁、联网拉上游代码、装已修复版本、读磁盘上已解好的副本、改测试、先推理再外传）。
- **一个可复用的系统工程结果**：attention 成本 C(p)=Σℓ²_{p,j} 的 pack 排序 + 分组，在 256 GPU / CP=4 / 64 个 DP 副本 / 排序窗口 W=8 下把吞吐从 1,126 提到 2,543 TGS（2.26×），并诚实说明排序窗口过大会改变 per-step 数据配比、早期 loss 抖动加剧。
- **三级对照的评测设计**（从最公平到最不利于自己）：base 对 base、同一份 SFT 数据下 Base+SFT、以及只用 6.33B token 无 RL 的轻量 SFT 去对厂商完整 post-training 模型；第三级被作者自己标注为"headroom 参考点，非 like-for-like"。

## Key Contributions

- **Reframes RSI for pre-training as a loop-relocation problem.** Rather than arguing about whether pre-training "is" self-improving, the paper specifies the two preconditions a useful RSI loop needs (cheap repeatable iteration; a measure aligned with the true goal), shows frontier pre-training violates both, and then closes six smaller loops around the parts that do satisfy them. This is a cleaner contribution than the usual "we applied agents to X" claim because each loop is mapped onto the four RSI steps in Table 2, including what plays the role of `measure`.
- **A concrete institutional-memory substrate.** The context infrastructure is the load-bearing element: it links internal metrics (per-layer loss, per-module gradient norms, expert load-balance statistics) to hyperparameter changes, data-mixture edits, infrastructure diffs and checkpoint evaluations produced by four separately-owned stacks. The paper's argument is that in this regime the bottleneck is not compute but recall — "re-investigating a question settled weeks earlier" — and the artifact is designed against exactly that failure.
- **Five cross-stack diagnoses with named mechanisms**, each of which would have been invisible to any single team: aggregate MoE MaxVio hiding layer-15/18 violations; weight-norm and gradient-norm divergence across modules pointing at the Muon/AdamW split; advertisements in generations traced back to ad pages surviving in the web corpus; router-logit drift traced to weight decay on norm/bias; and a dataloader that failed to preserve per-step sample order when resuming with a different DP size.
- **Three headroom measurements plus the empirical case that base scores mislead.** Tiny-SFT (6.33B tokens: 2.00B math / 2.00B science / 2.00B code / 0.331B instruction-following), the learning-aptitude log-linear fit, and max-over-protocols evaluation. The checkpoint re-ranking result (ρ = 0.796 early, 0.438 late) is the single most useful empirical finding for anyone selecting checkpoints.
- **A working agentic-data factory**, including the validation-gate design (policy / execution / semantics, plus "initial FAIL, reference PASS" on the same eval) and the anti-hack taxonomy in Table 4 — practically the most reusable artifact in the paper for other labs.
- **An unusually complete disclosure of a real run's plumbing**: 130+ infrastructure code versions, 106 hyperparameter fields, five training stages with exact sequence lengths, RoPE bases, batch size (33,554,432 tokens), LR schedule, and load-balancing coefficients.
- **A throughput result with a stated cost model and a stated side effect**: 2.26× on 256K-context training, with the mixture-bias caveat that aggressive sorting couples document length to data source and difficulty.

## Methodology

**Framing.** RSI is defined operationally as propose → run → measure → update, with the "recursive" case requiring that `update` also revise the loop machinery. Two preconditions are asserted: cheap repeatable iteration, and a measure aligned with the true goal. Frontier pre-training breaks both (one run ≈ hundreds of thousands of GPU-hours over months; the true objective is post-training headroom, which no single score reads off), and the entity that must improve is an organization rather than a model. Hence three loop types, six instances:

- **Debugging loops (Section 3).** *Infra loop*: detect → attribute → fix → verify, driven by internal metrics. Detection compared aggregate vs layer-wise MaxVio across 48 MoE layers. Attribution searched 130+ code versions and 106 hyperparameter fields, correlating metric trajectories with commits and optimizer configs. *Data loop*: an eight-step process over three stages — (1) detection and pattern extraction, with agents writing detectors and matching against all 1,053 subsets; (2) attribution and localization, tracing candidate subsets to one of six pipelines and inspecting intermediate data at >30 stages; (3) resolution and verification, with humans holding exactly two decision points (investigation priority, fix approval) and rejected proposals returned for revision.
- **Headroom loop (Section 4).** Three measures. *Tiny-SFT*: apply a small fixed SFT budget to each checkpoint and score it on post-training benchmarks. *Learning aptitude*: fit s_m(N) = b_m + k_m log10(N/N0) by OLS over SFT checkpoints (excluding the untuned base), then compute the data required to hit a target score, N*_m(s*) = N0·10^((s*−b_m)/k_m), and compare N*_base/N*_m across models. *Max-over-protocols*: evaluate each checkpoint under every available protocol (PPL-normalized, 5-shot, 4-shot Minerva, 8-shot CoT, 3-shot CoT, 0-shot answer-is, 0-shot boxed; three code protocols) and take the per-benchmark maximum as a capability-ceiling estimate. The recipe loop consumes these to revise the mixture between pilots and to monitor within the main run.
- **Experience-to-metric loops (Section 5).** *Classifier development*: human defines the task → a strong model labels a reference eval set → an agent analyzes errors and tunes the labeling prompt → the strong model labels training data → a compact classifier is distilled → evaluate; deploy as tuned prompt (Option A) or distilled model (Option B). *Site discovery*: SEO related-site expansion from seeds, agent verification, metric = verified yield per round, verified sites become new seeds, stop when a round yields nothing. *Crawl coverage*: agent writes a crawler, metric = retrieved pages / SEO estimated pages, investigate gaps and revise.

**Training recipe (Section 7).** Qwen3-30B-A3B MoE architecture, 30B total / 3B active. Global batch 33,554,432 tokens throughout; Muon for expert and attention matrices, AdamW for embeddings, output head, norms, biases and routers. Stage1 at 4,096 tokens: Stage1-1 to step 210,000 (≈7T), Stage1-2 to 240,000 (≈8T), Stage1-3 to 345,000 (≈11.5T); RoPE base 10⁴ → 5×10⁵ → 5×10⁶ at the transitions; LR 5×10⁻⁴ after 2,000 warmup steps, no re-warmup on resume; load-balance coefficient 10⁻⁴ (global-batch scope) and router z-loss 10⁻³. Stage2: 32,768 tokens, 3,000 steps (≈100B). Stage3: 262,144 tokens, 6,000 steps (≈200B), LR cosine-decayed to 5×10⁻⁵, length-aware packing, penalties disabled. Total ≈11.8T tokens.

**Data.** 10.5T unique tokens across web, code, math, PDF, QA and agentic. Web is cross-classified into a Cartesian product of ad-presence × content type × domain × language as atomic mixture-tuning cells. Math is model-rewritten; PDFs go through OCR → VLM repair → multi-stage filters; QA uses a context-completeness judge plus CoT rollouts bucketed by pass rate. Stage1-1 sampling is 48% web / 20% code; Stage1-2/1-3 drop web to 23% and raise papers/books/QA to 20/17/10%; Stage2 removes the dedicated web component and raises QA to 32%; Stage3 introduces 15% agentic and 11% capability-targeted data.

**Agentic data pipeline (Section 6).** Five stages: task inputs (260K raw PRs), environment synthesis (Docker/OCI, toolchain, activation script), evaluation synthesis (builder prompt preferring E2E/integration tests against public entrypoints), validation gates (policy + execution + semantics; initial code must FAIL and reference must PASS on the same eval), sanitization (strip reference patch and original git history from the solver image). Rollouts run through a unified adapter over nine harnesses (Claude Code, Codex, Pi-Agent, OpenCode, OpenHands, Droid, Hermes, OpenClaw, SWE-agent), three API protocols normalized by a Bifrost gateway onto one serving backend, with inference config injected centrally. Trajectories were generated by small/medium open-weight models (DeepSeek-Flash, GPT-OSS).

**Evaluation (Section 8).** Base: 13 benchmarks, zero-shot except BBH (3-shot) and AGIEval-EN (5-shot); greedy for non-code, Avg@4 at T=0.2/top-p=0.95 for HumanEval/EvalPlus/MultiPL-E (10 languages, problem-weighted). Post-training: 13 classic benchmarks (AVG13) plus 5 specialized ones (AVG5: AA-LCR v1.1, AA-Omniscience public set, SimpleQA-verified, CL-bench, CL-bench Life). Agentic: SWE-bench Verified and Pro (SWE-agent harness, T=0.7, 300 steps), CyberGym (Claude Code harness, T=1.0, 2-hour limit), KernelBench (T=0.6, 20 rounds, 65,536 output tokens/turn, compression at 150K).

**Systems (Section 7.1–7.2).** Attention-balanced sampling estimates each pack's cost as the sum of squared segment lengths, sorts within a bounded window (buffer ≈ 2× world size), groups similar-cost packs into global microbatches, and assigns packs in descending cost to the least-loaded rank. Optimizer allocation was chosen from a four-arm pilot at 604B tokens (all-AdamW; Muon on experts; Muon on experts+attention; the same with local load balancing), one run per arm.

## Results & Highlights

- **Base-model average (13 benchmarks, Table 7): 801 scores 73.13, second of seven.** Qwen3.5-35B-A3B 76.67 (−3.54), Nemotron-3.5-Lightning-30B-A3B 73.07 (+0.06), Nemotron-3-Nano-30B-A3B 68.49 (+4.64), Qwen3-30B-A3B 66.16 (+6.97), Kimi-Linear-48B-A3B 64.37 (+8.76), Gemma-4-26B-A4B 55.73. The profile is spiky rather than uniformly strong: best-in-table on GSM-8K (92.80 vs Qwen3.5's 87.72) and HumanEval (78.81 vs 71.80), but clearly behind Qwen3.5 on MATH-500 (73.20 vs 83.00), MultiPL-E (57.74 vs 66.48), EvalPlus (75.46 vs 83.08), AGIEval-EN (58.98 vs 66.56) and SuperGPQA (39.16 vs 47.68).
- **Matched-SFT, specialized capabilities (Table 8): AVG5 28.70 vs 20.54 for Qwen3.5-35B-A3B (+8.16), first on four of five.** The gap is dominated by factual knowledge — SimpleQA-verified 34.50 vs 12.00 (+22.50, and the corpus was decontaminated against SimpleQA by 8-gram overlap) — plus AA-LCR v1.1 61.00 vs 52.00 (+9.00) and AA-Omniscience 31.30 vs 21.70 (+9.60). It loses CL-bench Life, 3.46 vs 4.20 for Qwen3.5 and 3.95 for Nemotron-3-Nano.
- **Matched-SFT, classic benchmarks: AVG13 81.34 vs 83.76 for Qwen3.5 (−2.42), second place, consistent with base ranking.** Ties the best MATH-500 (98.40), and reaches 95.75 on GSM8K and 95.12 on HumanEval, but trails on LiveCodeBench v5 (69.53 vs 77.37), IFEval Strict (85.54 vs 89.33), MMLU (84.62 vs 88.75) and AIME 2026 (86.77 vs 87.60).
- **Agentic, 6.33B-token SFT vs fully post-trained vendors (Table 9): AVG 58.43, highest in the table**, ahead of Flint-40B-A2.5B (50.23), K2-Horizon-MoVA-36B-A4B (45.32), Qwen3.6-35B-A3B (44.59), Gemma-4-26B-A4B-it (36.05), Qwen3.5-35B-A3B (34.75) and Nemotron-3.5-Lightning (29.13). The average is carried by KernelBench at 77.60 vs the best baseline's 44.00 (+33.60); on the other three it trails Flint-40B (SWE-bench Verified 68.95 vs 72.80, SWE-bench Pro 48.29 vs 53.01) while winning CyberGym (38.90 vs 33.91). Excluding KernelBench, 801 averages 52.05 across three benchmarks vs Flint's 53.24.
- **Post-training headroom changes the checkpoint ranking (Figure 11).** Across 23 paired checkpoints, base-vs-SFT Spearman ρ is 0.796 for 13 Stage1-1 checkpoints (2 SFT epochs) but only 0.438 for 10 Stage1-2/1-3 checkpoints (1 epoch). Concrete inversion: step 159,000 ranks 1st on base (61.41) but 3rd after SFT (66.22), while step 210,000 ranks 6th on base (60.76) but 1st after SFT (66.83).
- **Learning aptitude reverses a first-checkpoint deficit.** On BFCL Full, 801 starts at 31.32 vs 40.04 for Qwen3-30B-A3B but has slope k = 8.62 vs 3.33 points per tenfold SFT steps (≈2.6×), leads at every shared checkpoint from step 697, and finishes 48.65 vs 46.26 at step 3,485. On SWE-bench Pro it starts ahead (26.95 vs 0 at step 30) with a steeper slope (9.15 vs 5.03) and reaches 43.37 vs 8.76 at step 1,922.
- **Training-progress trajectory over 22 monitoring benchmarks:** mean score at a matched 1T-token budget rises 47.78 (initial pilot) → 51.96 (revised pilot) → 56.83 (main run); at 3T the main run reaches 59.94 vs the revised pilot's 56.48 (+3.46). Layer-15 MaxVio at a matched 3T budget was >14 in the revised pilot vs ≈5 in the main run.
- **Attention-balanced sampling: 2.26× throughput** (1,126 → 2,543 TGS) on 256 GPUs with CP=4 (64 DP replicas), one pack per replica, W=8; smoothed loss curves track closely and benchmark differences stayed "within run-to-run fluctuations." Motivation: adding only 10% long samples can halve training speed, and the 256K corpus has a max/mean rank-cost ratio of 5.38 unsorted vs 1.03 at W=128.
- **Optimizer allocation at 604B tokens (single run per arm):** Overall Avg 45.60 (all-AdamW) → 47.89 (Muon on experts) → 48.28 (Muon on experts+attention); mean LM loss 1.768 → 1.746 → 1.737. Local vs global load balancing: 48.52 vs 48.28, i.e. indistinguishable downstream.
- **Classifier loop compounds across three iterations, with a dip at v2 for all three classifiers.** Ad intent accuracy 82.00 → 79.65 → 90.00 (+8.00 acc, +9.62 F1); computing subject 95.00 → 89.00 → 100.00 (+5.00/+5.00); clinical health subject 96.00 → 93.00 → 97.00 (+1.00/+1.01).
- **Agentic data funnel:** 260K raw PRs → 220K executable tasks (>84%) → ~2M rollouts over 9 harnesses (≈9 per task) → verification pass rate 55% overall, with a 0%–100% spread across harnesses → 1.1M kept trajectories → >100B tokens at ≈91K tokens/trajectory; 134B tokens including other sources.

## Authors & Credibility

Fifty-nine contributors listed alphabetically, from **Shanghai Innovation Institute (SII) and Xinxu AI**, with the artifact released under the `GAIR-NLP/801-30B` GitHub org — i.e. Pengfei Liu's GAIR group, the same line of work that produced Data Darwinism, DataEvolve, daVinci-Env, daVinci-Agency and ASI-Evolve, all of which are cited as the methodological ancestors of the loops described here. That matters for reading the paper: the "experience-to-metric" and "agentic data" sections are not first attempts but the industrial-scale continuation of a research program the authors have been publishing in smaller pieces.

Credibility signals are strong on disclosure and mixed on verification. On the positive side: the paper reports exact hyperparameters, the five-stage schedule, the four-arm optimizer pilot, the number of infrastructure versions and hyperparameter fields, the harness-level verification spread (including a 0% harness), the fact that each optimizer setting is a single run, the fact that SFT was not repeated with multiple seeds, and the fact that several recipe changes were made simultaneously so no single fix is isolated. It also labels its least-fair comparison as not like-for-like rather than burying it. On the negative side: no cost accounting anywhere (neither the run's GPU-hours nor the agents' token spend), no released code for the loops or the context infrastructure, no measurement of agent attribution precision, and the model itself is promised (base weights + SFT data) but the review copy contains no artifact links beyond the repo URL. The claims that would most need independent replication — "five diagnoses in about one month vs months without such infrastructure" — are self-reported counterfactuals with no baseline arm.

## Critical Assessment

**Novelty.** The framing contribution is real: nobody has published a detailed account of agents operating inside a frontier-scale pre-training run, and the decomposition into loop types that each repair a specific broken step of the RSI cycle is a genuinely useful analytical move, not a rebranding. But the individual mechanisms are mostly known engineering: layer-wise expert-load monitoring, tiny-SFT checkpoint probing, log-linear learning-curve extrapolation, SEO-page-count crawl coverage, and agent-written data classifiers all have antecedents, several of them the authors' own. What is new is the assembly and the scale, not any single component.

**The RSI claim does not meet the paper's own definition.** Section 2 states that the recursive case requires `update` to "revise the loop machinery that produced the change," and that persistence is what makes a loop recursive rather than a one-off search. By that test, none of the six loops qualifies: the classifier loop revises a prompt, the site loop revises a crawler, the debugging loops revise a config, and what accumulates is a log of negative results that humans read. The paper is candid that humans hold the two decision points in the data loop and that the model is "the byproduct and the account the contribution," but the title still asks whether RSI stops at pre-training, and the honest answer from the evidence is narrower: *agent-assisted ML engineering with institutional memory works at this scale*. That is a worthwhile claim; it is not the same claim.

**No counterfactual, so the causal story is untestable.** There is exactly one arm. The 47.78 → 51.96 → 56.83 trajectory at a matched 1T budget bundles debugging fixes, a new data mixture, a 5.4× lower learning rate, a 100× lower load-balance coefficient and a router-optimizer swap — the authors say so explicitly ("several factors changed together, the comparison does not isolate the contribution of any single adjustment"). We therefore cannot tell how much of the gain came from the loops versus from ordinary recipe iteration by experienced ML engineers, and the "months without such infrastructure" counterfactual has no measurement behind it.

**The headline "outperforms Nemotron-3.5-Lightning" is a 0.06-point difference.** 73.13 vs 73.07 on a 13-benchmark unweighted mean, with no seed variance, no confidence interval, and no per-benchmark significance testing, is a tie. The abstract's phrasing ("outperforms Qwen3-30B-A3B and Nemotron-3.5-Lightning-30B-A3B, trailing only the larger Qwen3.5-35B-A3B") reads as a clean ordering that the numbers do not support. The +6.97 over Qwen3-30B-A3B is large enough to be real; the Nemotron comparison is not.

**The agentic average is one outlier wearing a table.** KernelBench at 77.60 against a best baseline of 44.00 is 1.76× the next-best number in a benchmark where every other model clusters between 5.60 and 44.00. That is either a genuine capability jump or a protocol effect — 801 is run with 20 interaction rounds, 65,536 output tokens per turn and context compression at 150K, and the paper does not report whether baselines were re-run under the identical harness or quoted from vendor cards. On the three benchmarks where the comparison is less exotic, 801 trails Flint-40B-A2.5B (52.05 vs 53.24 average). Reporting "highest average on four agentic benchmarks" without noting that the average flips when one benchmark is removed is the paper's clearest instance of letting a mean hide a profile.

**Selection asymmetry in the base table.** Gemma-4-26B-A4B is the only model evaluated with max-over-protocols ("the maximum score obtained for each benchmark", marked ∗), justified by its weak instruction following. The asymmetry happens to work against the authors' own ranking (Gemma still finishes last at 55.73), so it is not self-serving — but it means Table 7 mixes two evaluation regimes, and a reader cannot reconstruct what Gemma would score under the default protocol.

**The tiny-SFT signal is under-powered exactly where it is load-bearing.** The "false stagnation" claim rests on +1.49 and +2.39 points in a 13-benchmark mean, with a single SFT seed per checkpoint, on benchmarks whose per-benchmark noise is easily 1–2 points. The authors flag this ("SFT was not repeated with multiple random seeds, so small differences between adjacent checkpoints should be interpreted with caution") and then still build a recipe-loop recommendation on it. The rank-disagreement result is more robust because ρ = 0.438 is far from 1.0 regardless of noise, but the specific inversions at 159k and 210k could be noise.

**No cost accounting in a paper whose thesis is about cost.** The entire motivation is that pre-training trials cost hundreds of thousands of GPU-hours and cannot be repeated. Yet the paper never reports the run's total GPU-hours, the agents' token consumption, the wall-clock overhead of the loops, or a comparison of "agent spend" against "saved GPU-weeks." Without that, the central economic argument — that these loops are worth their cost in a regime where experiments are expensive — is asserted rather than demonstrated. This is the single largest gap.

**Attribution quality is never measured.** The debugging loops are the most distinctive contribution, and their output is a root-cause hypothesis. The paper reports five that were right, plus the general claim that negative results are preserved, but never reports how many hypotheses agents proposed, how many were wrong, or how the wrong ones were caught. A precision number (say, 5 correct out of 19 proposed) would make the "agents earn their place by recalling and attributing" thesis far more credible than five anecdotes.

**A disclosed privacy incident with no follow-up.** The data-debugging section shows the model emitting what looks like an API key plus proxy configuration, traced to insufficiently cleaned config files in the code corpus. The fix is a pipeline change going forward. The paper does not say whether the released base checkpoint — trained on that corpus before the fix — still reproduces such secrets, nor whether a memorization audit was run before release. For a model that is being open-sourced, that omission matters more than most of the benchmark deltas.

**Smaller issues.** One training run per optimizer setting, and the local-vs-global load-balancing choice (48.52 vs 48.28) is resolved by appealing to "internal metrics are more stable" — a judgment call presented alongside quantitative arms. At least one of the nine harnesses produced a 0% verification pass rate, and the paper does not say which or whether its data was dropped. Baseline training-token budgets are not reported, so "11.8T tokens beats Qwen3-30B-A3B" cannot be converted into a token-efficiency claim. And the base-vs-base comparison uses the Qwen3-MoE architecture for 801 itself, which is good for isolating the recipe but means the result is partly "we trained Qwen3's architecture better than Qwen3's own recipe at this scale."

## Strengths

- **The most detailed public account of a from-scratch 30B-A3B run.** Exact schedule, batch size, RoPE progression, per-stage mixture, load-balance coefficients, optimizer split, and the number of code/hyperparameter revisions. This is the kind of document that is normally internal.
- **The three-loop taxonomy is analytically useful and survives contact with the evidence.** Each loop is mapped onto all four RSI steps in Table 2, including what plays the role of `measure` and why the headroom loop can only close a few times per project. That table alone is worth citing.
- **Tiny-SFT + learning aptitude + max-over-protocols is a real methodological contribution.** The ρ = 0.438 late-training rank disagreement is a concrete, checkable argument that base-model scores are a bad checkpoint selector, and the BFCL result (lower start, 2.6× steeper slope, overtakes by step 697) is a clean demonstration that intercept and slope can point in opposite directions.
- **Honest three-tier evaluation with the least-fair tier explicitly labelled.** Many papers would have led with "beats fully post-trained models" and stopped; this one separates base-vs-base, matched-SFT, and lightweight-SFT-vs-full-post-training, and states the third is a headroom probe.
- **Systems results that are independently verifiable.** The 2.26× throughput number comes with the cost model (Σℓ²), the exact parallelism configuration (256 GPUs, CP=4, 64 DP replicas, W=8), and the honest side effect (sorting couples length to source and biases the per-step mixture). The load-balance diagnosis — aggregate MaxVio looking fine while layers 15 and 18 blow past 14 — is a genuinely transferable monitoring lesson.
- **The anti-hack table is immediately reusable.** Six categories of concrete cheating behavior (git fsck for unreachable objects, raw.githubusercontent fetches, pip install of a pinned fixed version, grepping site-packages, pytest --deselect, reason-then-exfiltrate) with the pipeline design that blocks each. Anyone building agentic training data should read Table 4 before designing their validation gate.
- **Negative results are reported, not buried.** 801 loses CL-bench Life, LiveCodeBench, IFEval, EvalPlus, MultiPL-E and MATH-500, and the paper says so in the results text rather than only in a table.

## Limitations

- **Single arm, no ablation of the loops.** There is no run without agents, no run with only some loops, and no measurement of what each loop contributed. The causal claim that the loops produced the gains is not tested.
- **No cost data.** Neither GPU-hours for the run nor token/dollar spend for the agents. The economic argument for the loops is unquantified.
- **No agent-attribution precision or recall.** Five successful diagnoses are reported; the denominator (how many hypotheses were proposed, how many were wrong) is missing.
- **Confounded recipe revisions.** Learning rate 2.7e-3 → 5e-4, load-balance coefficient 1e-2 → 1e-4, router Muon → AdamW, global-batch balancing and the weight-decay exclusion all changed between the initial and revised pilots; the authors state that no single adjustment is isolated.
- **Tiny-SFT uses one seed per checkpoint and one 6.33B-token mix.** The mix (2.00B math / 2.00B science / 2.00B code / 0.331B IF) is itself a design choice, and headroom rankings may depend on it.
- **Learning aptitude is fitted on 2–3 SFT checkpoints per model in some cases** (the BFCL curve spans steps 55 to 3,485 but the fit is log-linear over a handful of points), and the paper explicitly leaves within-run checkpoint selection by aptitude to future work.
- **Evaluation coverage is admitted to be narrow** ("we have focused our initial evaluation and optimization on the settings reported in this section, with particular emphasis on agentic tasks"), which means the agentic emphasis and the agentic-heavy training data may be co-adapted.
- **No memorization/privacy audit** after the credential-leak finding, and no statement about whether the released checkpoint reproduces secrets from the pre-fix corpus.
- **Reproducibility is partial.** Base weights and SFT data are promised; the context infrastructure, the loop implementations, and the agentic-data pipeline are not.
- **One harness in nine produced a 0% verification pass rate**, undisclosed as to identity, and 45% of all rollouts were discarded — so the "220K tasks × 9 harnesses" figure overstates usable diversity.

## Relevance

正中"Self-Evolving Agents & Automated Research"：这是目前唯一一篇把 agent 真正放进**前沿预训练**闭环、并给出可核查运行细节的报告，其核心负面/正面结论（端到端 RSI 闭环合不上，必须拆成 debugging / headroom / experience-to-metric 三类小闭环）对任何做 self-improving agent、自动化 ML 研究、agent 驱动的实验循环的工作都是必读的边界条件。同时强命中"LLM Training Stability & Observability"：layer-wise MaxVio 早于下游指标平台期发出信号（2.2–6T 区间上升，6T 后高位平台而评测走平）、aggregate 指标掩盖 layer 15/18 失衡、换 DP size 恢复训练丢失 per-step 样本顺序、router logits 异常追溯到 norm/bias 上的 weight decay——这些是可直接搬进训练监控清单的具体故障模式。附带命中"Compute Infrastructure"：attention 成本感知的 pack 排序带来 2.26× 吞吐。

## Questions for Further Exploration

1. What would a no-agent control run look like, and can one be approximated from the pilot logs? Without it, is there any way to bound the loops' contribution — e.g. by counting how many of the five diagnoses would have been found by the ordinary weekly metric review?
2. What did the loops cost? A per-diagnosis accounting (agent tokens, engineer hours, GPU-hours of re-run pilots) against the GPU-weeks each diagnosis is claimed to have saved would turn the paper's central economic argument into a number.
3. Why is KernelBench 77.60 when the best baseline is 44.00 and the same model is mid-pack on SWE-bench Pro? Re-running two baselines under the identical 20-round / 65K-token / 150K-compression harness would settle whether this is capability or protocol.
4. Does the ρ = 0.438 late-training rank disagreement survive multiple SFT seeds? If the inversions at 159k and 210k are noise, the practical recommendation ("select checkpoints by tiny-SFT") weakens considerably.
5. Does the released base checkpoint still emit credentials from the pre-fix code corpus, and was any memorization audit run? The data-debugging section documents the leak but not its residue.
6. How sensitive is the headroom ranking to the SFT mixture? A second tiny-SFT mix weighted toward code or toward long-context would test whether "post-training headroom" is a property of the checkpoint or of the probe.
7. If the recursive case requires revising the loop machinery, what would that actually look like here — an agent that edits the context infrastructure's schema, or one that proposes new loop types? The paper defines the bar but does not attempt to clear it.
8. Which harness produced the 0% verification pass rate, and did its exclusion change the trajectory-length distribution (mean 91K tokens) that the long-context stage depends on?
