> **一句话总结：** 作者把"artifact 变成能力"拆成五个顺序依赖的性质（artifact 形成 → 行为激活 → 任务关系实现 → 边界安全复用 → 能力扩展），用"状态 / 对局 / 版本谱系"三层诊断在 15×15 无禁手五子棋里冻结并解剖 Reflexion、Voyager、DGM（同一 DeepSeek-V4-Flash 底座、同一批程序化对手）：三者都满足"artifact 累积 + 行为改变 + 指标上升"这三个常用代理信号，却分别断在**合法化增益**（Reflexion 合法率 49.8%→83.5%，但 P(pass\|legal) 16.0%→12.3%，12 个记忆×状态集组合里无一改善）、**组合覆写**（Voyager 20/20 局都走到一步必胜点却 0/20 成五，删掉 `create_open_three` 反而 20/20 全胜）、**通过检查点后的纯损耗漂移**（DGM 的 OB-5/OB-6 新增通过状态为 0、胜局 19→9→0，而内部进化分数仍从 347.0 涨到 357.8）。

> **TL;DR:** This paper asks what verifiable task capability the artifacts a self-evolving agent writes actually leave behind, and answers with a five-property definition plus a three-scale diagnosis (1,876 rule-labelled Gomoku states, 20 complete games per configuration against a two-ply search opponent, and adjacent-version comparison along a code lineage). Under one base model (DeepSeek-V4-Flash), Reflexion, Voyager and DGM all show the three proxy signals yet each breaks at a different property. Reflexion on set B (n=1,756) lifts the legality rate 49.8%→83.5% and the overall pass rate 8.0%→10.3%, but the legal pass rate P(pass\|legal) *falls* 16.0%→12.3% (−3.7 pts) and improves in 0 of 12 memory×state-set combinations — a legalization gain, not a selection gain. Voyager beats its round-1 control by 459 newly passing states (73 lost) and raises open-four formation from 0/20 to 20/20 games, yet completes five at 0/20 immediate-win states and loses 0–20; deleting its `create_open_three` skill flips this to 20/20 wins with mean game length 129.0 vs 20.0 moves. DGM's OB-3 passes the checkpoint (+522/−139 states vs P0, 19/19 immediate wins, 19/20 games) but OB-5 and OB-6 add zero newly passing states and lose 103 and 29, with wins 19→9→0 while the internal evolutionary score still rises 347.0→357.8. Worth reading if you evaluate or build self-evolving agents: the P(pass)=P(legal)×P(pass\|legal) decomposition alone is a reusable audit that catches a common false positive. The cost is scope: one base model, one game, one evolution run per mechanism.

## 核心贡献

- **提出"能力形成"（capability formation）的可判定定义**：把 artifact 到能力的转化拆成五个**顺序依赖**的性质——(1) artifact 形成并接入决策、(2) 行为激活（同状态下有无 artifact 的动作差异超过采样噪声）、(3) 任务关系实现（动作整体上更满足任务关系，而不仅是"变了"）、(4) 边界安全复用（已建立的正向效应不被系统其它部分在实际决策中推翻）、(5) 能力扩展（后续版本在保留既有正向效应的同时新增效应）。依赖结构为 1 → 2 → (3 且 4) → 5，其中 3+4 合称"检查点"（checkpoint），二者同时成立才算"能力已形成"；诊断按序进行，**第一个失败的性质即为断点**，其下游不再判定。
- **提出三层诊断（three-scale diagnosis）**：状态层在 1,876 个可精确复现的固定状态上做配对比较（有/无 artifact 的动作、规则程序独立判定的可接受动作集 G(s)）；对局层让冻结系统与程序化对手 `search_2` 打 20 局完整对局，只判"已建立的一步必胜关系是否被推翻"（k/n 个一步必胜点里成五几次），不判输赢本身；谱系层沿版本链逐版本比较状态级新增/丢失，并核对胜局。
- **给出三个"信号齐备但能力未形成"的反例，且断点各不相同**：Reflexion 断在性质 3（合法化增益：整体通过率上升完全来自 P(legal) 上升，P(pass\|legal) 反而下降）；Voyager 断在性质 4（组合覆写：每个组件单独正确，组合后的调用顺序在冲突状态下提前返回，把已成之局送掉）；DGM 断在性质 5（通过检查点后，后续版本只丢不增，最后一次修改几乎没进入决策路径）。
- **把"系统"而非"组件"作为分析单元**：技能提出候选、调用脚本决定先问哪个技能、接受哪个答案，最终动作由多组件联合产生。作者主张单组件归因只能得出"某个技能写得不好"，无法回答"系统整体是否形成了能力"，因此性质 1–4 一律在冻结系统上判定，组件定位只作解释。
- **环境设计上的方法论贡献**：论证了为何需要"状态可重放 + 规则可独立判定 + 对局与版本全记录"的受控环境，并说明五子棋虽规则简单但任务并不简单（模型只看到坐标序列，需自行重建行列斜的空间关系；无记忆时约一半落子落在已占点），因此仍留有真实的进化空间。
- **一组可复用的诊断产物**：P(pass)=P(legal)×P(pass\|legal) 的分解、7,234 状态差分池、以及"进化分数与诊断结论局部错位"的实证（OB-3→OB-5 分数 347.0→357.8 而胜局 19→9，因评分函数中的平均局长项补偿了胜率项）。

## Key Contributions

- **A falsifiable definition of capability formation.** Five sequentially dependent properties replace the three proxy signals (accumulation, behavior change, metric gain). The checkpoint is Properties 3 ∧ 4 — a positive task effect *and* no overturning of an already-established one — which makes "capability formed" a claim that can fail, rather than a restatement of "the metric went up."
- **Three-scale diagnosis with independent evidence per property.** State level: 1,876 fixed states (set A = 120 states from 22 hand-built tactical positions under rotation/reflection; set B = 1,756 deduplicated states sampled from 472 archived DGM evolution games, balanced across task-relation categories), paired with/without the artifact, judged by a rule program that enumerates the acceptable set G(s) without consulting any model. Game level: 20 complete games vs `search_2`, board rebuilt after every move, every immediate-win state identified, k/n completions recorded. Lineage level: adjacent versions compared state-by-state plus wins, with a 7,234-state differential pool.
- **A decomposition that exposes a specific evaluation fallacy.** Because P(pass) = P(legal) × P(pass | legal), a rising pass rate is not evidence of better play if legality is also rising. The paper makes this the operational test for Property 3: only P(pass | legal) counts, and newly passing states are classified as "illegal→pass" (not a task effect) versus "legal non-pass→pass" (a task effect).
- **Three counterexamples, each breaking at a different property, under one base model and one opponent set.** This is the empirical core: it shows the properties are not redundant — a system can pass 2 and fail 3 (Reflexion), pass 3 and fail 4 (Voyager), pass 3 and 4 and fail 5 (DGM). No single property stands in for another.
- **Causal localization rather than correlation.** The Voyager break is traced to a concrete branch order in the agent-written `auto_player` (opponent-immediate-win check first, own-immediate-win check second, early `return`), and confirmed by an intervention: removing `create_open_three` — the skill that manufactures conflict states — turns 0/20 wins into 20/20.
- **A documented failure of the optimizer's own objective.** DGM's composite score S = 50·WR_RB + 100·WR_TA + 150·WR_SD2 + 20·max_o B_o + L_SD2 + 2·Σ_o F_o rises from 347.0 (OB-3) to 357.8 (OB-5) while wins against `search_2` fall 19→9, because the mean-game-length term grows as games are prolonged. The paper uses this to argue that a higher evolutionary score does not guarantee better task capability, and that retention decisions built on such a score can lock in drift.

## Methodology

**Framework.** An artifact (textual memory, executable skill, or code version) passes through five properties: (1) *artifact formation* — a persistent structure exists and is wired into decision making, confirmed from call records; (2) *behavioral activation* — on identical states and interfaces, actions with and without the artifact differ more than sampling noise (for stochastic mechanisms the noise baseline is the disagreement rate between two independent control runs; Voyager and DGM are deterministic in code, so any change counts); (3) *task-relation realization* — the pass rate among legal moves increases, where a move passes iff it belongs to G(s), the set of legal moves satisfying the primary task relation; (4) *boundary-safe reuse* — in complete games, every immediate-win state is converted (k/n with k=n), so no established win is overturned by another part of the system; (5) *capability extension* — between adjacent versions, |newly passing| > 0 while |lost| does not grow and wins do not decline; an iteration with |N|=0 and |L|>0, or with declining wins, fails, and one with |N|+|L|≈0 is classed as stagnant.

**Why the environment must be controlled.** Three requirements map onto the three scales: replayable states (state level — any board restored exactly, so the artifact is the only difference), rule-judged task effects (state and game level — a rule program enumerates acceptable moves independently of the system under diagnosis, separating "changed for the better" from "merely changed"), and fully recorded games and versions (game and lineage level — conflict states and per-version gains/losses can be located).

**Environment.** 15×15 freestyle Gomoku (no forbidden-move restrictions), win by five in a row horizontally, vertically or diagonally; playing on an occupied point or off-board is illegal; 200-move cap, longer games recorded as undecided. An immediate winning point is a point where one move completes five; an immediate-win state is the agent's turn with such a point available; a conflict state is one where the opponent also has one. Note the rule asymmetry the paper leans on: at a conflict state, completing five ends the game immediately, so the uniquely correct move is to take your own win, not to block.

**Three mechanisms, one base model (DeepSeek-V4-Flash), three programmatic opponents** (rule-based, threat-aware, `search_2` two-ply). *Reflexion*: one memory cell per opponent, one textual lesson appended per game, ≤7 entries per cell; at decision time all entries of the current cell go into the prompt and the model emits the move directly — deliberately no retrieval, filtering or weighting. *Voyager*: the agent writes executable Python skills (seven in the frozen configuration) plus `auto_player`, a calling script that queries skills in a fixed order and returns as soon as one fires; skills detect features or propose candidates but never emit the final move. *DGM*: the agent edits the strategy source directly; every version exposes `select_move(board, player)`; each candidate plays 5/10/5 games against the three opponents and a composite score decides retention and parentage, yielding the main lineage P0 → OB-1 → OB-2 → OB-3 → OB-5 → OB-6 → OB-7 (OB-4 is a side branch off OB-3).

**Controls.** Reflexion: empty memory, plus a second empty-memory run as the noise baseline (moves differ on 46.7% of set B — an unusually high floor, which is why Property 2 is judged against it rather than against zero). Voyager: `round1`, i.e. only first-round tactical skills with `auto_player` unchanged, isolating what evolution added. DGM: P0, the initial strategy. All three also get component ablations (Voyager: −`create_open_three`, −`minimax_search`, `round1`).

**Statistics and protocol.** Reflexion queries each state once per condition at temperature 0.2, max_tokens 512; paired state-level outcomes tested with exact McNemar. Game-level: 20 games per configuration with different random seeds. Lineage: adjacent versions on set B plus the 7,234-state differential pool (472 archived games → 7,212 deduplicated states + 22 tactical states), used to check whether a version's code change actually reaches behavior. Judgments rely only on experimental data and rules; no LLM judge is used anywhere in the diagnosis.

## Results & Highlights

- **Reflexion: a legalization gain, not a selection gain.** On set B (n=1,756), loading the `trace` memory for the threat-aware opponent raises the legality rate from 49.8% (empty memory) to 83.5% and the overall pass rate from 8.0% to 10.3%, but P(pass | legal) drops from 16.0% to 12.3% (−3.7 pts); across all 12 memory-condition × state-set combinations the legal pass rate improves in **none**, and on set B it falls 1.6–4.4 pts. Paired McNemar on that same condition looks like a win (111 newly passing vs 71 lost, p=0.0037) until the newly passing states are classified: 72 of the 111 are illegal→pass transitions, and among states where both conditions yield a legal move the net change is **−19** (outcome feedback: −12).
- **Voyager: 459 more passing states, 0/20 games won.** From `round1` to the full system, 459 of 1,756 B states become passing and 73 are lost (Property 3 holds), pass counts rise 690→1,076, and open-four formation goes from 0/20 to 20/20 games. In game-level diagnosis the full system reaches an immediate-win state in all 20 games and completes five in **0/20** — every one is a conflict state at move 19 — and loses 0–20. Removing `create_open_three` (the skill that drives attacks into open fours) gives **20/20 wins** with mean game length 129.0 moves versus 20.0 for the full system, and raises set-B pass count to 1,345 (274 newly passing, 5 lost).
- **DGM: the checkpoint is passed, then everything is lost.** OB-3 versus P0: +522 newly passing / −139 lost on set B (48.7%→70.5%), 19/19 immediate-win states converted, 19/20 games won — the paper's one positive instance of capability formation. OB-5 then adds **0** newly passing states and loses 103 (wins 19→9); OB-6 adds 0 and loses 29 (wins 9→0); OB-7 differs from OB-6 on **1 of 7,234** states (wins stay 0/20, 11 undecided). Meanwhile the evolutionary score rises 347.0→357.8 from OB-3 to OB-5 before settling at 312.6.
- **The two directions of decoupling.** P0 wins 20/20 games against `search_2` with a set-B pass rate of only 48.7%, while OB-1 wins **0/20** with the highest pass rate in the lineage (78.6%). State-level pass rate and game strength therefore diverge in both directions, not just the one the paper emphasizes — a fact that cuts against reading the pass-rate criterion as a proxy for playing strength (see Critical Assessment).
- **The activation floor is high, and the paper measures it rather than assuming it.** Two independent empty-memory Reflexion runs disagree on 46.7% of set B states, so Property 2 cannot be satisfied by small perturbations; the six frozen memories move 59.8%–78.2% of states, above that floor, with every condition showing a positive net change (p = 0.0031–0.0548 uncorrected).
- **Component ablations separate "bad skill" from "bad composition."** Voyager −`minimax_search` collapses open-four formation to 0/20 and wins to 0/20 (mean length 18.0), while −`create_open_three` keeps 20/20 open fours and wins 20/20 — so the failure is neither a single weak skill nor a generally broken library, but one specific interaction between a sound attack skill and a sound defense-first call order.

## Authors & Credibility

Nine authors from Tianjin University, the International Digital Economy Academy (IDEA), and one independent researcher; no prior landmark work in this specific niche is evident from the paper, and it is a single cs.AI preprint (arXiv:2611.04952v1, 3 Nov 2026) with no venue. The work is unusually self-critical for the genre: three dedicated "Alternative Explanations" appendices (C.1, D.1, E.2) pre-empt the obvious objections — sampling noise, legal-pass-rate dilution, memory/state mismatch, cherry-picking OB-3 as the reference version, score/diagnosis misalignment, "a single ineffective component explains it," and set-B bias toward DGM — and the rebuttals are quantitative rather than rhetorical (e.g. using OB-1 as an alternative reference yields the same monotone decline; the legal-subset net change stays negative at −12/−19; the A-set direction agrees with B at 80.0%→66.7%). The design choice to judge with rules only, with no LLM judge in the loop, is a real methodological strength. Against that: no code or artifact release is stated anywhere in the paper, the three mechanisms are re-implementations that "preserve the core update paradigm" rather than the official codebases, and everything rests on one base model with one evolution run per mechanism.

## Critical Assessment

**Novelty.** The framing is genuinely new in its unit of analysis. Prior work evaluates self-evolution at the episode level (EvoPathBench's paired on/off held-out episodes), the checkpoint level (Agent Plasticity), the artifact-loading level (Lin et al. 2026b's loading/following rates), or the single-query level (Misevolution, SkillApt, Counterfactual Memory Audit); Table G.1 in the appendix makes this comparison explicit and, as far as I can tell, fairly. What is new here is (a) making the artifact→capability transition itself the object, (b) the 3∧4 checkpoint formulation, and (c) the P(pass)=P(legal)×P(pass|legal) split as an operational test. Point (c) is the most portable idea in the paper and would be worth adopting even by people who reject the five-property ontology.

**Rigor.** Strong where it counts: rule-based ground truth with no model in the judging loop, paired same-state comparisons, an explicit noise baseline, exact McNemar, and interventions that localize each break to a concrete mechanism (a branch order, a call-order interaction, a code change that never reaches the decision path). The alternative-explanation appendices are better than most published papers manage. But the statistics have soft spots. Each Reflexion state is queried **once** per condition at temperature 0.2, so the McNemar tests treat generation noise as absent and the only estimate of that noise comes from a single duplicate empty-memory run; with 12 combinations reported at p = 0.0031–0.0548 and no multiplicity correction, the borderline ones (0.0478, 0.0548) should not carry weight. Set B's 1,756 states are drawn from 472 DGM games and deduplicated, so states within a game are not independent — the effective sample size is smaller than the p-values assume. And each mechanism is evolved exactly once: "DGM drifts after OB-3" is a single lineage, and the D.1 rebuttal answers the cherry-picking objection (choice of reference version) but not the run-to-run variance of evolution itself.

**The P0/OB-1 decoupling is the paper's most interesting unexamined fact.** P0 wins 20/20 with a 48.7% pass rate; OB-1 wins 0/20 with 78.6%. The paper reports both numbers in Table D.1 but never reconciles them with the framework's own logic. If capability formation is defined by the checkpoint (Properties 3 ∧ 4), then OB-3 "has formed a capability" while winning one fewer game than the unevolved P0 — so "capability formed" does not imply stronger play, which is exactly the kind of proxy failure the paper is arguing against, just one level up. Either the pass-rate criterion is measuring task-relation satisfaction rather than strength (in which case the framing should say so and the "capability" label is doing too much work), or the game-level criterion is too narrow. The paper needs a paragraph here; its absence is the biggest conceptual gap.

**The Voyager result is a three-line bug presented as a general phenomenon.** The mechanism is real and cleanly demonstrated — `auto_player` checks the opponent's immediate wins first and `return`s, so at a conflict state the own-win branch is unreachable — and the intervention (delete `create_open_three`, get 20/20) is a genuinely striking causal demonstration. But the generalization to "wherever artifacts are reused through a fixed interface" rests on a conjectured GUI-agent example the authors explicitly say they have not tested. A compositional override that is really "the generated calling script had a branch-ordering bug" is a software-engineering finding about LLM-written control flow, not necessarily a law of skill libraries. The honest version of the claim is narrower than the section title suggests.

**Reflexion's implementation may manufacture its own negative result.** All seven memory entries are dumped into every prompt with no retrieval, filtering, weighting, or recency handling — the paper says so plainly, but then does not ablate it. A state-conditioned retrieval Reflexion could plausibly show a selection gain, in which case the "legalization gain" is a property of memory *dumping*, not of reflection. Since the whole point is that a proxy signal misleads, the missing ablation of the memory interface is a real hole: the break is attributed to the mechanism when it may be attributable to the prompt construction.

**Scope and significance.** One game, one base model, one run per mechanism, and task relations that are "local and enumerable" — the authors admit the last point and it is the load-bearing one, because the entire diagnostic depends on a rule program that can enumerate G(s). That is precisely what open-ended agent tasks lack. The Discussion's GUI example is an existence proof of a concept, not a method. So the contribution is best read as a **measurement framework for controlled settings plus a set of cautionary case studies**, not as an evaluation protocol that transfers to open-ended benchmarks today. That is still valuable — the three breaks are memorable and the legality/selection split is immediately usable — but the abstract's "signal-based evaluation cannot determine whether a capability has formed" is stronger than three Gomoku counterexamples can support; "cannot determine" should be "does not establish," and the conclusion does soften to "useful but insufficient," which is the right claim.

**Red flags, ranked.** (1) No code or data release, and the three mechanisms are bespoke re-implementations — reproducing the specific breaks requires re-implementing three agent scaffolds exactly. (2) Single evolution run per mechanism, so drift claims are n=1. (3) Set B, the main evidence set, is DGM-derived and category-balanced by the authors, with no sensitivity analysis on that curation. (4) Single sample per state at T=0.2 undermines the paired tests' independence assumptions. (5) The DGM composite score is used both as the agent's retention signal and as the thing being critiqued, without an ablation showing what happens if retention used pass rate instead — which would have been the natural experiment for the "score misalignment" claim.

## Strengths

- The five-property definition has real teeth: it is ordered, it names a checkpoint, and it forbids judging downstream properties after an upstream failure — which is what makes "which property broke" a meaningful answer rather than a score.
- P(pass) = P(legal) × P(pass | legal) is a small, sharp, immediately reusable audit. Any agent benchmark that reports a rising pass rate alongside a rising legality/format-compliance rate is vulnerable to the same artifact, and this paper gives the exact test.
- The controlled environment is chosen for the right reasons and defended explicitly: replayable states, rule-judged effects, complete records, and a task that is rule-simple but not cognitively trivial (about half of no-memory moves land on occupied points).
- Each of the three breaks is localized to a concrete mechanism and then confirmed by intervention — the Voyager −`create_open_three` result (0/20 → 20/20 wins) is the kind of causal evidence most agent papers never produce.
- The appendix treatment of alternative explanations is exemplary, including the ones that hurt (the score/diagnosis mismatch from OB-3 to OB-5 is reported against the authors' own framing).
- Honest negative results throughout: distillation-trained gates, single ineffective components, set-B bias, and the fact that OB-7's code change reaches only 1 of 7,234 states are all reported rather than buried.
- The related-work table (G.1) is a useful map of the process-evaluation literature on its own, with the same-state-pairing column doing real analytical work.

## Limitations

- **One environment.** Freestyle Gomoku only; task relations are local and enumerable, which is exactly the property that makes G(s) computable and exactly what open-ended tasks lack. The paper says so, but it means the framework's transferability is untested rather than merely uncertain.
- **One base model, one evolution run per mechanism.** DeepSeek-V4-Flash throughout, with no repeated evolution seeds, so the DGM drift and the Voyager override are single observations of stochastic processes.
- **Three mechanisms, three artifact forms.** Textual memory, executable skills, code lineage — but not multi-agent co-evolution or direct parameter updates, which the authors concede may break at other stages.
- **Property 5 is only judgeable for mechanisms with a version lineage**, which excludes Reflexion-style memory accumulation from the last stage of the framework by construction.
- **Reflexion is implemented without retrieval or filtering**, so its break may be a property of the memory interface rather than of reflection.
- **Statistical power.** Single generation per state, correlated states within games, 12 uncorrected comparisons, and a noise baseline estimated from one duplicate run.
- **No released code or artifacts**, and bespoke re-implementations of all three mechanisms, so the specific numbers are hard to reproduce without rebuilding three scaffolds.
- **The conceptual gap around P0/OB-1**: a 20/20 win rate at 48.7% pass rate and a 0/20 win rate at 78.6% are never reconciled with the claim that the checkpoint defines capability.

## Relevance

直接命中"自进化 Agent 与自动化科研"这条主线：它质疑的正是该领域最常用的三段论证据（artifact 越攒越多、加载后行为变了、指标涨了 ⇒ 方法有效），并给出一套可执行的诊断协议与三个可复现的反例，做 self-evolving / memory / skill-library 方向时可以直接拿来审计自己的评测。次级相关是"Agent 与 Pipeline 的静默失败"：Voyager 的组合覆写（每个组件单独正确、调用顺序在冲突状态下提前 return 把必胜局送掉）是典型的 harness 层静默失效——系统照常运行、指标看着还行，但已建立的正向效应被另一段代码悄悄推翻。

## Questions for Further Exploration

- Would a state-conditioned retrieval Reflexion (selecting 1–2 of 7 memories per state instead of dumping all) show a selection gain, or does the legalization gain survive better memory interfaces? This is the single ablation that would most change how the paper should be read.
- How variable is the DGM post-checkpoint drift across independent evolution seeds? If 3 of 5 runs show loss-only drift, it is a property of the objective; if 1 of 5, it is a lineage-level accident.
- Can the framework be operationalized where G(s) cannot be enumerated — partial rule checkers, programmatic application-state assertions for GUI agents, or verified rubrics — and what is lost when G(s) becomes a heuristic?
- Is the compositional-override rate predictable from the call graph (branch order, early returns, number of skills consulted) rather than discovered post hoc? A static check on agent-written dispatch code might catch the Voyager failure before any game is played.
- What happens to DGM if retention uses the rule-judged pass rate instead of the composite score — does the lineage stop drifting, and does it then actually exceed P0's 20/20?
- At temperature 0.2 the Reflexion noise floor is 46.7% move disagreement, which makes Property 2 nearly vacuous for stochastic mechanisms; how should the activation threshold scale with temperature, and does a lower temperature make the legality/selection split cleaner?
- Do the same five properties, applied to parameter-level self-evolution (SEAL-style or weight-updating agents), break at the same stages or at different ones?
