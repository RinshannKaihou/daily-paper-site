01

How it works

route by similarity, not position

The kernel is untouched; only candidate selection changes.

Each query scores C cluster representatives instead of every key, fills a candidate budget B, then rescores just those B keys with the model's native indexer. Per-query cost falls from N to roughly C + B — about 128 keys per cluster on GLM-5.3. All approximation lives in routing: a key is lost only if its cluster never reaches the candidate set.

Why not contiguous blocks? Neighboring tokens aren't similar in indexer space. HiSA's recall of the exhaustive top-k falls from 83.9% to 41.8% (LongBench-v2) between 16K and 256K at a fixed 8K budget.

The index is built causally inside one request. New keys enter an open window and are searchable immediately. Every 1,024 keys the window is sealed into eight k-means clusters; every 16,384 tokens a warm-started refit regroups the prefix, reusing Elkan/Hamerly bounds so only new or uncertain keys search all centers. Refits run on a separate CUDA stream and publish a version only to queries whose prefix contains every key behind it. A small per-layer encoder corrects cluster means at seal time; query scoring is unchanged.

Selection pipeline

  1. 01 / Route Score C cluster reps. Learned representative: r_c = µ_c + Δr_c.
  2. 02 / Shortlist Fill budget B. ~128 keys per cluster on GLM-5.3.
  3. 03 / Refine Rescore B candidates with the native indexer.
  4. 04 / Attend Unchanged DSA kernel takes the top-k.

The fine print

The abstract's 18.4 pp is a 16K-budget RULER cell. At 24K it is +14.9; at matched throughput +11.0. On LongBench-v2 — the benchmark behind the recall analysis — the gain is +0.7 (GLM) and +0.4 (V4).

03

Strengths & limitations

what holds, what narrows

Strengths

  • Right diagnosis. Per-component accounting shows selection, not attention, is the cost.
  • Causality is engineered. Versioned lists, reps and windows, visible only to prefixes that built them.
  • Maintenance is real. Elkan/Hamerly bounds, warm-started refits, a separate CUDA stream.
  • Honest losing regimes. Slower decode and slower than HiSA past ~512–768K are reported, not buried.
  • Replay-verified recall. Captured indexer operands are replayed; HiSA must reproduce its served selections.

Limitations

  • Missing strongest baseline. No stack with IndexCache's cross-layer reuse; every speedup and recall comparison is unstacked.
  • Decode untouched. TPOT speedup is 1.40–1.45× vs HiSA's 1.54–1.65×.
  • Maintenance grows with prefix. Advantage holds from ~384K (GLM) / ~512K (V4), not at 256K for every budget.
  • Narrow accuracy win. Gains concentrate on RULER; LongBench-v2 moves +0.4 to +0.7 pts.
  • Heavy, narrow evaluation. Per-layer offline training, zero gain on 3/5 V4 layers; 5 layers, 12 inputs, final 2,048 queries, single-stream.
