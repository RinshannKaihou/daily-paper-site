Sparse attention's kernel already computes the softmax mass it discards. Gate each head on that number; repair only the failures.

Coverage-Verified Sparse Attention: Closed-Loop Quality Control for Long-Context LLM Decoding
Yan-Cheng Li, Chun-Yi Lee / National Taiwan University / 02 Nov 2026 / NeurIPS 2026 submission / arXiv:2611.10634

Key metric
40.70/ 41.83 dense

LongBench 16-task mean at 11.7% measured KV read — best baseline 38.78. The gap to dense narrows from 3.05 to 1.13.

Why it matters

Approximate inference silently changes model output. A cheap in-kernel signal can catch and repair the damage before it reaches the user.

Critical edge

At matched cadence and dense layer 0, ungated uniform 9%/10% controls score 41.19/41.16 — above CVSA's 40.70 — so the gate's quality benefit is not established.

01

Method

deployed point · CVSA-c4
01 / DRAFT

Page-select first16-token pages, page-max score

Score pages, pick a base set at a 5% budget, run the paged kernel. Keep the draft output and the selected-set normalizer LSE_sel.

02 / VERIFY

One subtractionthe signal was already there

Per KV head, coverage ĉ = exp(LSE_sel − LSE_all). Accept every head with ĉ ≥ τ = 0.90. Cost: 0.45 ms, under 2% of attention-path time.

03 / CORRECT

Repair only the tailno dense fallback

Recompute failing heads over a 4× expanded page set and mask-replace their outputs. Cache the base set, not the repair. Layer 0 stays dense; score and verify every M = 4 steps.

Proposition 1 — exact, token-level
O_dense = c · O_draft + (1 − c) · O_comp
‖O_draft − O_dense‖₂ = (1 − c) · ‖O_draft − O_comp‖₂

Coverage is simultaneously the acceptance test and the interpolation weight, so correction is a weighted blend rather than a dense recompute. The proofs are three lines and hold for any selection rule; production runs a page-max proxy of this token-level c.

03

Assessment

read adversarially

Strengths

  • +A genuinely free signal, correctly spotted: LSE_sel − LSE_all is already computed, and 0.45 ms is under 2% of the attention path.
  • +Per-head recovery is real, not a disguised dense fallback — only 21% / 23% / 14% of heads are repaired on Llama / Mistral / Qwen.
  • +Uncommon transparency: the paper publishes aligned controls that beat its own method, its own false-accept rates, and a 16.5-pt MATH-500 failure.
  • +The Twilight audit is adversarial, self-contained evidence that open-loop coverage misses never surface in output quality.
  • +Deployment realism: hybrid scheduling, dense layer 0, CUDA-graph notes, roofline and total-traffic accounting that charges page scoring against the method.
  • +τ ∈ [0.80, 0.97] moves the three-model mean by 0.14 pts, so the operating point needs no per-model tuning.

Limitations

  • −The verifier is a page-max proxy, not the quantity the theorems describe: 31% / 33% / 39% false accepts, worst in Qwen's late layers.
  • −At matched cadence, ungated 9% and 10% controls (41.19 / 41.16) beat CVSA's 40.70 — the gate's quality benefit is unproven.
  • −The guarantee covers scoring steps only; three of every four reuse steps run on a stale selection, with no compositional error bound.
  • −Speed is modest where deployments live: 1.09–1.12× at 8K/B=1, and 1.19× for Llama/Mistral at 128K/B=1.
  • −Reasoning-length generation breaks: MATH-500 64.0 vs 80.5, and the M=1 fix runs at 0.93× dense — slower than dense.
  • −No memory savings (full KV cache retained) and no head-to-head against vAttention or Vegas, the two concurrent verifiers.
  • −The M-vs-depth rule (4 at 7B, 2 at 70B) is manual, and the code repo is still "prepared for public release."

Open questions

what would change the verdict
Q1

If ungated uniform 9% at matched cadence already reaches 41.19, is the gate a quality ceiling or a safety net for weak selectors?

Q2

Can a GQA-aware or token-aware estimator replace the page-max proxy and close Qwen's −1.64 gap?

Q3

Is drift across the M-step reuse window bounded, or only empirically small on these three models?

Q4

How does it compare head-to-head with vAttention's sampling verifier and Vegas on the same harness, on quality and total traffic?
