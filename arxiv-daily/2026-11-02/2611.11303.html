Method

One bandit per context, seeded by the model it is trying to beat

Closed loop: profiler → reward → tuner

One independent bandit per context — (collective, node count, message size) — created lazily on first visit. No parameter sharing: a Llama3 trace collapses 719 collective calls onto 9 contexts, so samples concentrate where traffic does.

  1. 01

    Filter. Drop any arm the cost model predicts >2× slower than its best; exploration nearly halves and the measured-best arm is never removed.

  2. 02

    Warm start. Seed each arm's pseudo-count from r(μ̂(a)), so the policy starts where AUTO would choose.

  3. 03

    Reward. r = μ̂min / t. Latency is normalized by the model's own prediction, so rewards compare across contexts; r = 1 means “as fast as AUTO expected”.

  4. 04

    Choose. Deterministic UCB1, α = 0.093, clipped-SGD mean. Every rank computes the same arm without shared randomness.

  5. 05

    Score. Forced-arm sweep, 100 iterations per arm; tune on 4/8 nodes, test on 154 held-out 16/32-node + trace contexts.

Three roles, one cost model

  • Arm filterμ̂(a) > 2·μ̂min is dropped; exploration nearly halves, best arm never removed.
  • Warm-start priorPseudo-counts seeded from r(μ̂(a)).
  • Reward scaler = μ̂min / t makes rewards context-independent.

The loop was missing: NCCL's tuner v3 returns a predicted cost table but never the measured latency. SPCX adds a profiler→tuner reward channel, durable per-context state, and cross-rank sync.

Strengths

What earns trust

  1. 01Seven claim boundaries declared before the results; the abstract itself says no end-to-end win.
  2. 02Scenario-level sign-flip tests and clustered CIs — 154 correlated contexts are not treated as 154 samples.
  3. 03The failure mode is located, not just counted: all 19 tail contexts are crossovers at the wrong message size, predicted margin 0.06–0.57.
  4. 04Both TRLT accountings reported; the lazy-init replay artifact is controlled three separate ways.
  5. 05Deployment numbers practitioners rarely get: a 5.7–7.8 s NVLS stall, 2.1% profiling bandwidth, a 7.5% sync tax.
Limitations

Where it stops

  1. 01No stock-NCCL row in the primary sweep — AUTO is priced on forced-arm jobs, a counterfactual.
  2. 02The scale-shift claim fails Holm correction on the six real 16/32-node scenarios (p=0.125).
  3. 03No end-to-end step time, no CUDA graphs, no compute–communication overlap.
  4. 04Plugin, harness, and data unreleased; the reward channel may require patching NCCL.
  5. 05Post-hoc choices: the 10% threshold, the NVLS exclusion, the size gate — all disclosed.

Open questions

  1. 01How much of 6.08% → 1.61% survives a stock-NCCL row and a pass-through-plugin control?
  2. 02Why does AUTO win on GB200 with MNNVL on — the fabric, or H100-tuned knobs?
  3. 03Would exploring only low-margin contexts (m ≥ 0.50) dominate both AUTO and the full bandit?
