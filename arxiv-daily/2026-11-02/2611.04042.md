> **一句话总结：** 论文把"投机解码时 logits processor 必须看到该验证位置的逻辑前缀与顺序解码状态"形式化为 processor-prefix contract，提出 BADC 测试框架（小模型枚举精确参考 + 结构见证 + 同时置信界 + 可执行机制假设 + 冻结补丁复现），在 Transformers 5.17.0 与 llama-cpp-python 0.3.19/0.3.35 上确认了两类真实缺陷（processor 读到未验证草稿、状态未回滚），并在 SmolLM2-135M-Instruct 上测到普通解码与 prompt-lookup 投机解码首个返回 token 事件率相差 66.21 个百分点（同时 95% 下界 60.26 个百分点）。

> **TL;DR:** Speculative decoding is supposed to be lossless, but only if logits processors (CFG guidance, SynthID watermarking, min-length, grammars) see the *logical* prefix and the *sequential* processor state at every verification position. The authors turn that assumption into an explicit contract, then test it with BADC on pinned builds. On llama-cpp-python 0.3.19/0.3.35 a prefix-parity processor emits a forbidden token in 23,335/200,000 speculative draws (vs 0 with speculation off; TV lower bound 0.1131), and `MinTokensLogitsProcessor(3)` shifts the returned-completion law by 0.1490 — both repair-confirmed on fresh seeds. On a SmolLM2-135M-Instruct checkpoint with CFG 1.5, a fixed 1,021-token first-token event fires 80.37% of the time under ordinary decoding vs 14.16% under native prompt lookup — a 66.21-point gap (simultaneous 95% lower bound 60.26), while a functional prefix-history control sits at 81.35% (gap upper bound 6.95 pts). The honest part: the paper's own controlled comparison finds **no** cause-recovery advantage over random configuration selection, and a plain permutation chi-square test detects every family at least as often as BADC. Read it for the contract, the two confirmed mechanisms, and the unusually disciplined negative results — not for a deployable diagnostic.

## 核心贡献

- **形式化 processor-prefix 契约**：把投机采样的无损性从"目标分布正确"推进到"每个验证位置上 processor 看到的是逻辑前缀、且状态与顺序解码不可区分"，并给出条件复合引理（Lemma 1）及其四项采样器前提。
- **给出缺陷分类学**：D1 上下文（读到过长/过短的 buffer）、D2 状态（在顺序解码不会发生的调用上前进而无回滚）、D3 停止（按 block 而非按位置判定停止）、D4 记录（返回的 log-prob 与文档值不符），每一类都做成可执行的机制假设（executable hypothesis）。
- **BADC 测试方法**：在小随机模型上枚举出精确的顺序解码参考分布，用结构见证（P=0 的契约违反）加 Clopper–Pearson 同时置信下界估计两臂总变差距离，再用冻结补丁在全新种子上做复现确认。
- **两个经干预确认的真实成因**：llama-cpp-python 的 processor 回调读取 `self.input_ids`（含未验证草稿，`llama.py:742`），以及 Transformers 的候选过滤在验证前推进有状态 processor（CFG、SynthID）而无回滚。
- **诚实的阴性结果**：定向选择相比随机选择在成因回收上没有优势；置换卡方比较器在每个族上检出次数不低于 BADC；作者自己预注册的"BADC 在 guidance 上优于比较器"这一预测被数据推翻。

## Key Contributions

- **A processor-prefix contract plus a conditional composition lemma.** Lemma 1 states the four sampler conditions under which model-free (prompt-lookup) speculative sampling is exact, plus the requirement that every reached verification position — including the bonus position — uses the target kernel at its *logical* prefix, that a stateful processor's state be observationally indistinguishable from the sequential state at that prefix, and that the sequential stop rule be applied to the committed prefix before every emission. A counterexample shows the conditions are not vacuous.
- **An executable defect taxonomy (D1–D4).** Context, state, stopping, and record classes are turned into simulators that enumerate a predicted law µ_H from the same kernel, so a failure can be checked for *compatibility* with a named mechanism rather than merely observed.
- **BADC itself.** Three channels: (S) structural witnesses and simultaneous lower bounds on total-variation distance between the speculation-on and speculation-off returned-output laws; (R) per-token record checks against a teacher-forced reference; (H) hypothesis compatibility. Calibration on the speculation-off arm can *void* a configuration (A5), and non-rejection is explicitly reported as "not rejected," never as conformance.
- **Two source-linked, intervention-confirmed causes**, each counted once after deduplication by code site, plus a frozen-repair confirmation protocol (fresh seeds, recurrence > 0.01 on the frozen event, repaired-arm gap upper bound ≤ 0.01, witness rate upper bound ≤ 1e-4).
- **A transfer study to vLLM 0.8.5.post1** with unchanged rules, which detects all 52 exposed configurations but adds no *new* counted defect — every family is already public.

## Methodology

**Setup and notation.** For a pinned engine `E`, model, prompt, horizon `L` and sampling config `c`, the sequential kernel `K_E(·|h)` is the processed next-token distribution after committed prefix `h`, with every stateful processor replayed from its initial state. Sequential decoding yields a trace `T` with termination code `ω`; the engine returns `ρ_E(T)`. The speculation-off law is `P = ρ_E#Law_K(T)`, the speculation-on law is `µ`, and both are laws over *returned outputs* — not over a consumer's policy. Two prefixes are distinguished throughout: the **logical prefix** (prompt + committed tokens + this block's earlier drafts) and the **evaluation buffer** (every token fed to the model for the block, unverified drafts included). The contract is that processors see the former.

**Kernel oracle.** On tiny random models (vocabularies of 7–10 tokens, horizon 3 or 4) the authors enumerate the exact speculation-off distribution and its kernel log-probabilities. Engine-specific adapters make this meaningful: the Transformers adapter reuses the very processor and stopping objects that `generate()` prepares; the llama-cpp-python adapter mirrors the vendored C sampler chain for each probed feature, with every mirrored line recorded. Exactness is therefore relative to the mirror and to floating-point evaluation, and the paper says so.

**Channel S (differential bounds).** Before any draw, a finite complement-closed event family is fixed: singletons over the support of `P` and the registered hypotheses, an "other" event, length-1 and length-2 token prefixes, output lengths, termination codes, a crash event, the contract-violation event, and one event `A_H` per hypothesis. One-sided Clopper–Pearson bounds give `D = max_A [L_on(A) − U_off(A)]`, which lower-bounds `TV(µ, µ_off)`. A configuration fails if a witness exists or `D > 0.01`. Each bound gets level `α/(mB)` for `m` configurations and `B` bounds, so all bounds hold jointly at `1 − α` under within-arm i.i.d. Bernoulli indicators — no between-arm or between-event independence is assumed. Crashes are kept as outcomes but do not count as silent corruption, which is why the xgrammar result is downgraded (see below).

**Channel H and confirmation.** A registered hypothesis simulates a suspected faulty schedule of drafter/processor calls, state updates and loop exit, enumerating `µ_H` from the same kernel; `H` is compatible if every event's two-sided interval contains `µ_H(A)` within 0.005. Confirmation then requires a *frozen* minimal patch (which may not disable speculation, bypass the processor, or change the returned-output contract), fresh seeds, recurrence of the frozen event, and simultaneous upper bounds of 0.01 on the repaired arm's residual gap and 1e-4 on its witness rate. Eligibility rules E1–E9 exclude record-only, crash-only and publicly-known findings, and dedupe by code site across versions.

**Study design.** 26 configurations across 5 builds (Transformers 5.17.0, 5.17.0 + xgrammar 0.2.8, 5.12.0 as a public control, llama-cpp-python 0.3.19 and 0.3.35), all on one CPU in network-disabled containers pinned by image digest. Models are locally generated tiny random networks — a one-layer Llama-style net (V=7, L=3) and a GGUF net (V=10, L=4) — with prompt `abcdabcdab`, whose repeated n-grams encourage drafting; matches of length ≤ 2 propose up to 3 (HF) or 4 (LCP) tokens. 200,000 draws per arm in S1/S2, 1,000,000 per unrepaired arm in S3, multiplicity family m=26 at α=0.05, 17.8M decision draws and 33.7 CPU core-hours total. Configurations, seeds, events, thresholds, hypotheses, repairs and decision rules were sealed with harness hashes before confirmatory draws; a post-run audit re-derived the decisions.

**Follow-ups.** Held-out transfer on 6 tiny model/prompt variants per confirmed probe (no retuning); a trained-checkpoint mechanism pilot on SmolLM2-135M-Instruct (134,515,008 parameters, vocab 49,152) with four deliberately repetitive prompts and CFG 1.5; a one-event returned-output study at 1,024 requests/arm; a second-host reproduction; and a vLLM transfer study (5 campaigns, held-out tiny Qwen2 V=8/L=3, CPU fp32 NumPy mirror against the fp16 engine, 8.3 GPU-hours).

## Results & Highlights

- **llama-cpp-python reads unverified drafts into user processors.** With a harness processor that allows different token sets at even and odd absolute positions, the speculative arm emitted a forbidden token in **23,335 of 200,000 draws on 0.3.19** (23,407 on 0.3.35) versus **0 of 200,000 with speculation off**, giving a simultaneous TV lower bound of **D = 0.1131 / 0.1135**. This is a structural witness, not a statistical artifact: the predicate is a documented contract on allowed-token membership.
- **The built-in `MinTokensLogitsProcessor` is broken under speculation.** A minimum of 3 tokens shifted the law of returned completions by **D = 0.1490 (0.3.19) and 0.1475 (0.3.35)**, with 1,143,741–1,145,577 draft tokens proposed. No minimum-length predicate is registered (the completion API hides internal tokens), so the evidence is the bound alone. After the frozen repair — passing the logical prefix — the repaired arm's residual gap to the speculation-off arm was bounded by **0.0020 (0.3.19) / 0.0023 (0.3.35)** while recurrence on the frozen event was **0.1549 / 0.1548**.
- **Transformers' stateful processors leak state across uncommitted calls.** The SynthID watermark produced the single largest silent shift in the main study, **D = 0.6417**; classifier-free guidance at scale 1.5 gave **D = 0.0142**, barely clearing the 0.01 threshold (post hoc, removing the hypothesis event drops it to 0.0017, below threshold). On confirmation the guidance case recurred at **0.0195** and the repaired arm's gap was bounded at **0.0032** with a witness-rate upper bound of **6.8 × 10⁻⁶**. Third-party xgrammar 0.2.8 failed channel S at **D = 0.4060**, but **48,543 of 200,000** speculative generations raised an assertion inside the grammar matcher and the crash-free bound is only **0.0091** — correctly reported as a robustness finding, not silent corruption.
- **The trained-checkpoint effect is large but narrow.** On SmolLM2-135M-Instruct with the pilot-selected Paris factual-sentence prompt, a fixed 1,021-token-ID first-token event fired in **80.3711% of ordinary decodes (823/1,024)** versus **14.1602% under native prompt lookup (145/1,024)** — a **66.2109-point** observed gap with simultaneous 95% bounds **[60.2649, 71.6080]**, which also lower-bounds returned-sequence TV at that configuration. A functional prefix-history control reached **81.3477%**, i.e. it restored the event rate to within **0.9766 points** of ordinary decoding (upper bound 6.9487). Initial committed-prefix conditional-score TV was **65.8317%** on that prompt but only **4.1911%** and **3.8606%** on two of the other three prompts — the mechanism fires on *some* prompts, not all.
- **Retrospective marginals show which observable moves.** For the LCP minimum-length case, faulty/off TV is **14.1202% on output length** (lower bound 13.7314%) but only **0.2686% on the first token** (upper bound 0.7162%); the length lower bound exceeds the first-token upper bound, so a first-token-only test would have missed the defect entirely. Termination TV is 13.4372% and drops to 0.1730% after intervention.
- **No diagnostic advantage over simpler baselines.** In RQ3 (10 campaigns on held-out models), directed and random configuration selection recovered the same number of causes in **9–10 of 10 campaigns** (`d_A = 0` wherever determined; exact 95% upper bound on `P(d_A ≠ 0)` is 0.26–0.39). The permutation chi-square comparator **C** detected guidance in **10 directed / 9 random** configurations versus BADC's **3 / 5** with the hypothesis event and **1 / 2** without — refuting the authors' own registered prediction that C would do worse.
- **vLLM transfer is a wash.** All **52 exposed configurations (29 directed, 23 random)** were detected by both BADC and C on vLLM 0.8.5.post1, **28 of 29** directed detections recurred on fresh draws, and **45 valid exposed V1 configurations** passed with clean controls — but every family is already public, so RQ4 adds no counted defect. V0's controls failed outright (plain sampling rejected in **5 of 5** campaigns, row-path checks in **4 of 5**), so its 7 detections are explicitly left unattributed.

## Authors & Credibility

Five authors, all listed under a single "Independent Researcher" affiliation, with correspondence to `tid16@pitt.edu` (a University of Pittsburgh address, though no Pitt affiliation is printed). Primary category is cs.SE with cs.LG cross-listing, which matches the paper's actual genre: a software-testing paper about ML systems rather than an ML-systems paper. There is no prior track record visible in the paper itself, and the artifact is a *privately prepared* replication package that "will be archived publicly after acceptance" — so independent verification is currently impossible. What the paper does have, unusually, is procedural credibility: sealed protocols, harness hashes, a disclosed pilot, dated prior-art searches (32 and 46 queries logged before confirmation data), INVALID rather than silently-dropped units, and an audit that re-derived decisions. The tone is defensive to the point of self-sabotage — the abstract and conclusion spend as much space disclaiming what was *not* shown as stating what was. That is the right instinct, but it makes the paper harder to read than it needs to be.

## Critical Assessment

**Novelty.** The individual ingredients are not new — differential testing (McKeeman 1998), finite enumeration as an exact oracle, metamorphic relations, and Clopper–Pearson simultaneous bounds are all standard. What is new is the *domain instantiation*: naming the processor-prefix contract explicitly, showing that equal token support / frequency ordering / greedy outputs do not imply equal sampling laws, and building the D1–D4 taxonomy into executable simulators. The Lemma 1 counterexample is a real contribution to how people reason about "lossless" claims. The framing is more novel than the machinery.

**Rigor — genuinely strong in places.** The statistics are done properly: a single multiplicity family across all 26 configurations, joint coverage without independence assumptions, calibration that can void a configuration, and separate error budgets for compatibility versus confirmation. The refusal to call non-rejection "conformance" is rarer than it should be. The xgrammar case is handled exactly right — a 0.4060 bound that is really a crash rate gets demoted to a robustness finding with a 0.0091 crash-free bound. The V0 controls failing and the resulting detections being marked unattributed is the kind of thing most papers would quietly omit.

**Rigor — where it thins.** (1) *The headline 60.26-point number rests on one prompt and one event.* The prompt and the 1,021-token event set were both chosen from the same pilot on the same checkpoint, so the estimate is conditional on a selection the authors made; they acknowledge this, but the abstract leads with the number anyway, and "one pilot-selected prompt on a trained checkpoint" is doing a lot of work. (2) *The event is coarse.* A 66-point swing in "is the first returned token in this 1,021-ID set" lower-bounds TV but says nothing about whether outputs got better or worse, or whether a user would notice. No benchmark, no perplexity, no task accuracy — the paper is explicit that it does not measure quality, but readers will over-read the number. (3) *The largest effect has no dedicated repair.* SynthID's D = 0.6417 is confirmed "only through its shared cause" because the registered priority picked guidance (HF17-6) over SynthID (HF17-7); the single biggest silent corruption in the study was never repaired and re-tested on its own. (4) *Within-arm i.i.d. is assumed, not established.* The second-host run reuses seeds, so all 3,072 first tokens matching is reproducibility evidence for one implementation, not independent replication — the paper says this, but the interval widths still inherit the assumption.

**The elephant: BADC does not beat simpler tests.** RQ3 is the paper's most important result and it is negative on both axes. Directed selection recovers no more causes than random selection (9–10 of 10 campaigns identical). The permutation chi-square comparator C detects every family at least as often as BADC, and on guidance it detects 10/10 versus BADC's 3/10 — a 3× gap in the *opposite* direction from the preregistered prediction. The authors report this cleanly, which deserves credit, but it means the "branch-aware" apparatus (event families, structural witnesses, hypothesis simulators, frozen repairs) buys detection *parity* at substantially higher engineering cost. The one place BADC's machinery demonstrably mattered is the guidance case's threshold crossing (0.0142 with `A_H`, 0.0017 without) — i.e. the method's marginal value is a hand-designed event that a two-sample test did not need. The workflow comparison that was supposed to settle "added diagnostic value" is uninformative by the authors' own account: n = 1 eligible defect, 0/2 validated repairs in *both* arms, every session stopped at the token cap (T_cap = 243,751) after 1.3–4.7 minutes, and neither BADC session ever ran the ported oracle within the 90-minute budget.

**Baselines and scope.** The reference is the engine's own speculation-off arm, which is the correct reference for a distribution-preservation claim but means no comparison against Token-DiFR, GRIEF, Ekka or FlashInfer-Bench — those appear only in related work, with a one-line argument for why each is different. External validity is thin by construction: vocabularies of 7–10 tokens, horizons 3–4, the string `abcdabcdab`, one 135M checkpoint, four constructed repetitive prompts, CFG 1.5, at most 8 new tokens, and CPU-only pinned builds. The two counted causes are both prompt-lookup paths, one per implementation family, and one of them (LCP-1) is triggered by an author-written harness processor rather than a shipped feature — legitimate as a contract test, but not evidence that users hit it. There is no prevalence estimate and no production-model evidence, and the paper says so repeatedly.

**Red flags.** None of the usual kind — no cherry-picked benchmark table, no undisclosed baseline, no overclaiming in the conclusion. The risks are the inverse: an artifact that is not yet public, a replay that returned INCONCLUSIVE at exact receipt equality (float differences of ~4.2 × 10⁻¹⁹ on two score-control floats), an unauthenticated Torch wheel digest, and a `ΔB` RL-bias analysis whose three sealed intervals all include zero (so it establishes nothing about RL consequences). Also worth flagging: `HF17-3` (top-k 3 + top-p 0.9 + repetition 1.3) proposed **zero** draft tokens, meaning speculation was silently disabled and the configuration was inconclusive — a reminder that a nontrivial share of "speculative decoding" configurations in the wild may not be speculating at all.

## Strengths

- The contract formulation is the right abstraction and will outlive the specific tool: "processors see the logical prefix and a sequential-equivalent state" is checkable, teachable, and directly actionable for engine maintainers (a position-indexed view plus per-position state, not just cropping the target KV cache).
- Two causes confirmed with *interventions*, not correlations: source line cited (`llama.py:742` in 0.3.35), mechanism simulator, frozen minimal patch, fresh-seed recurrence, and a bounded residual. That is a much higher bar than "we found a distribution shift."
- Statistical hygiene is exemplary — one multiplicity family, joint coverage without independence assumptions, calibration that can void a config, explicit "not rejected ≠ conformant" language, and an assurance-boundary table (Table 1) that separates detection, compatibility, repair and exercise.
- The negative results are reported with the same care as the positive ones, including a failed preregistered prediction and a 3× loss to a simpler comparator. This is what preregistration is for.
- Practical findings that engine authors can act on immediately: prompt-lookup drafters must not expose drafts to user callbacks; stateful processors need rollback; min-length and stop rules must be evaluated per position, not per block.

## Limitations

- **Scale and realism.** Tiny random models (V = 7–10) carry most of the statistical weight; the only trained model is 135M parameters on four hand-written repetitive prompts with ≤ 8 new tokens. No 7B+ model, no natural workload, no long context, no model-based drafter (EAGLE, DeepSeek-V4.1-style dynamic verification), no SGLang.
- **No prevalence, by design.** Selection was source-informed and pilot-informed, so nothing here estimates how often real users hit these paths. The paper is candid, but a reader wanting "how bad is this in production?" gets no answer.
- **No quality or end-to-end consequence.** The 66-point event gap is a distributional fact, not a measured degradation; no benchmark accuracy, no human eval, and the RL analysis (ΔB) is a fixed hashed reward probe with intervals spanning zero and no trainer–engine run.
- **The diagnostic claim is unsupported.** No advantage over random selection, no advantage over a permutation chi-square test, and an n = 1 workflow comparison in which neither workflow produced a validated repair. The method's incremental value over "run a two-sample test on full outputs" is left open.
- **Operational cost.** The oracle must be ported per engine version; median porting time hit the 90-minute ceiling and no BADC session in the comparison actually ran the ported oracle. 17.8M draws and 33.7 CPU core-hours for 26 configurations is not cheap for CI.
- **Reproducibility is promised, not delivered.** Private replication package, one INCONCLUSIVE exact-receipt replay, unauthenticated wheel digest, and a recorded output-directory relocation in the returned-event study.
- **Presentation.** Dense, heavily hedged, and structured around assurance boundaries rather than around findings; the main text is hard to skim and the supplement carries load-bearing qualifications.

## Relevance

直接命中 **Inference Reliability & SDC Detection**：不是模型幻觉，而是 serving stack 之下（logits processor 接口、投机验证循环、状态管理）静默改变输出分布的那类缺陷——正是"模型之上、模型之下"的软件层腐蚀。同时也落在 **Reliability under Extreme Performance Optimization**：投机解码这个纯加速优化在特定 processor 组合下破坏了分布无损性，且首个 token 事件率能从 80% 掉到 14%。对做推理引擎正确性、RL rollout 分布一致性、或"优化是否改变了语义"这类审计工作的人，这篇的契约定义与置信界协议可以直接借用。

## Questions for Further Exploration

1. Does the 66-point first-token event gap survive at 7B+ scale on natural prompts, and does it translate into measurable benchmark accuracy loss (MMLU, GSM8K, code pass@1) rather than a distributional statistic?
2. What is the actual prevalence? A source-informed probe selection cannot answer this — what would a random sample of production request traces (à la GRIEF) say about how often a stateful processor is combined with speculation?
3. Why did the permutation chi-square comparator match or beat BADC on every family, including guidance (10/10 vs 3/10)? Is the structural-witness machinery worth its complexity, or is a two-sample test on full outputs the better default with witnesses as a debugging aid?
4. Can the processor-prefix contract be enforced *cheaply at runtime* — an assertion that the processor's input ids equal the logical prefix, plus a state digest — instead of requiring an enumeration oracle? What is the overhead?
5. The SynthID case (D = 0.6417) was never repaired separately because guidance won the priority tie. Does the shared-cause repair actually restore SynthID's law, or does watermarking have an independent state bug?
6. Would TRL's sequence-mask importance weighting absorb this bias in a real PPO/GRPO run? The sealed ΔB intervals all include zero at the tested sample size — what N would be needed to detect a 0.5-point reward bias?
7. The later vLLM 0.30.0/main run went inconclusive because the candidate bonus-row cause matched a public report. Is that rule (any public overlap ⇒ zero) too strict for a field where most defects eventually get reported?
