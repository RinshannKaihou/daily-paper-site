Why it matters

The last hand-written half of an agent system — its reasoning strategy — becomes searchable, and the library measurably improves later tasks.

Critical edge

The 0.61× is inference cost alone — roughly 20,000 candidate-sample executions per search are excluded, so “39% cheaper” describes steady state, not the cost of getting there.

Methodology

A blueprint is a Python program that captures the structure of a reasoning procedure — which models are called, in what order, at which tier, under what control flow — with task prompts stripped out. Every node implements execute(llm, task) → str, so blueprints can call older blueprints; four protocols (shared interface, no forward calls, no cycles, no duplicates) keep the library a growing DAG.

Strategies route across fast / balanced / complex tiers × nothink / thinking modes: cheap calls classify and route, expensive calls are spent only where they change the answer.

  1. 01 Retrieve

    Two hybrid queries return 5 relevant + 5 deliberately off-task “inspiration” blueprints.

  2. 02 Propose

    K = 5 candidates per iteration, quota-bound to include new / composed / reuse and accuracy / efficiency / balanced slates.

  3. 03 Evaluate

    Full traces on train, aggregates on validation, nothing on hidden. A 200-sample test split is never touched.

  4. 04 Accumulate

    Write back the blueprint + accuracy/cost card + one experience note. Deduped by AST hash, string literals elided.

Strengths
  • Structure without prompts. One design decision — strip prompts on write-back — is what makes both composition and cross-task reuse possible.
  • Retrieval by measured behaviour. Cards and experience notes beat name similarity: a 0.6B router sends computable BBH items to a tool agent, the rest to self-consistency.
  • Protocol at scale. 30 benchmarks, 108 baseline cells each, four disjoint splits, one shared answer extractor across every method.
  • Honest accounting. Two losses and two mixed results are reported, and the selection gap is disclosed: +4.3 pt on hidden, +0.7 on test.
Limitations
  • No variance anywhere. One search run per benchmark, no seeds. At 200 test samples the binomial SE is ~3.5 pt near 50%, so most +1 pt wins sit inside the noise band.
  • The baseline is an accuracy-only argmax over 108 cells measured on 100 samples — it deliberately picks the expensive accurate cell. A Pareto-frontier BL is absent.
  • Search cost is excluded from every headline number: ~20,000 candidate-sample executions per benchmark, with no break-even task count.
  • No task-order experiment. “The library compounds” rests on one-shot retrieval transfer, not measured accumulation; the no-library ablation isolates retrieval, not accumulation.
  • Frontier-dependent and narrow. A GPT-6 strategist, executors capped at 4B, and no long-horizon agentic benchmark (SWE-bench, WebArena, OSWorld).
Questions for further exploration

Does the library compound with order? Run the 30 tasks in reverse and in several random orders; plot per-task gain against library size at the moment of search.

What is the break-even task count? Total cost (search + inference) versus per-task ADAS search and a human-written strategy, as a function of shared tasks.

How much of the 39% survives a Pareto baseline? Re-select BL for accuracy per unit cost on the training split and re-run the comparison.

Can the library be poisoned? An over-optimistic measurement card or a mis-specified experience note would propagate silently; no audit or decay is described.
