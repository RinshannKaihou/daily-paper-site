When File Ingestion Misleads Language Models: Measuring and Mitigating Divergences in Office Documents
Penghui Li ·NTU Singapore ·2026-11-02

Key metric
64%

attack success over 400 end-to-end trials against 8 products — chat assistants 75%.

Why this matters

Anyone shipping document upload, RAG, or file-reading agents is exposed: the file is valid, the extractor innocent, the attack invisible.

Critical edge
n = 1 document per attack

Five documents carry the entire 400-trial evaluation — ten repeats of one document per attack — so per-system rankings are not interpretable.

01

The gap, in four real files

Same bytes, two readers. Each pair below is a measured divergence, not a hypothetical: a legal OOXML file whose extracted text differs from the Office rendering a human approves.

Cell stores 1000000 under $#,##0,. All six Python extractors emit the stored value; only Tika/POI applies the format. 7% of benign spreadsheets carry value-altering formats.

python-docx and unstructured omit headers, footers and footnotes. Footers appear in 561 of 1,000 sampled Word documents, so the omission is routine, not exotic.

Human seesauthorized
Model readsunauthorized

All six Word extractors concatenate un + authorized across runs. Hide the prefix in w:vanish and the meaning inverts without an instruction.

PPTX · reading order
Human seesA → B → C → D
Model readsC → A → D → B

Four of five PPTX extractors emit a non-visual order (three distinct sequences on one slide). Only Docling recovers the visual sequence; Tika follows XML sibling order.

02

How the gap was measured and closed

A measurement study first, a defense second: enumerate every channel, then reconstruct what the human would have seen directly from the specification.

SelectionWhich atoms exist and are visible → hidden injection, silent omission
InterpretationWhat a stored value means → number-format tampering
SerializationWhat order and boundaries the reader gets → spatial inversion, sub-word fusion
  • Corpus and extractors. 2,229 public files (917 XLSX / 1,000 DOCX / 312 PPTX) through 10 extractors at default settings, versions recorded.
  • Two analyses that check each other. Descriptor-aware static analysis recovers 179 elements + 67 attributes in python-pptx, versus 2 selectors from call-graph/string analysis (≈90×). Canary strings at every text location plus zipfile instrumentation catch direct XML reads; raw XML is ground truth.
  • Five instruction-free attacks. Hidden injection, silent omission, number-format tampering, spatial order inversion, sub-word recombination — each paired with a clean control. 8 products × 5 scenarios × 10 trials = 400.
  • Isolating the cause. Hold model and prompt fixed, swap only the extracted text (markitdown vs clean control): 3 models × 4 scenarios × 10 = 120 trials.
  • Defense. Prism interprets ECMA-376 directly — visibility, number formats, part inclusion, paragraph order — and sends only genuinely layout-dependent residue to a LibreOffice + Quick Look render oracle.
Prism · human-view reconstruction C(f) = serialize(order(display(visible(atoms(f)))))
atoms / visible — injection & omission display — ECMA-376 number formats order / serialize — reading order & run joins oracle — only what the spec leaves open

04

What holds up, what doesn’t

The measurement is careful and the causal experiment is decisive; the product-level claims are thinner than the headline number suggests.

Strengths

  • Measurement first. Static selectors and dynamic canaries cover each other’s blind spots, with raw XML as the ground truth for “dropped.”
  • A small, sharp idea. Descriptor-framework analysis goes from 2 to 179 selectors and transfers across the Python OOXML ecosystem.
  • A taxonomy, not a bug list. Selection / interpretation / serialization maps each failure class to a defense operation.
  • Decisive causal test. Swapping only the extracted text flips every model, every trial, zero crossover.
  • Honest reporting. The 50% attack, the 22% system, the 0% backend and the 0.5-point-font evasion are all in the paper.

Limitations

  • Five documents. Per-system ASR has no confidence intervals, and the 28-payload set never touches the 8 products.
  • Never deployed. Prism is tested as a text substitution for three API models, not inside a real product; checking-mode false negatives are unmeasured.
  • Coverage stops with the implementation. No PPTX content channels, XLSX chart text, legacy formats or images — and presentations are the least covered.
  • Spec visibility ≠ perceptibility. 0.5-point text or background-colored text evades the static interpreter.
  • One VLM, one snapshot. The render oracle uses Gemini 4 with no ablation; product results describe October 2026 and will age.
05

Open questions

Three tests that would change how much weight the 64% deserves.

Q1

At 20 documents per scenario, does the 24% vs 22% coding-agent cluster survive — or is it sampling noise?

Q2

In a RAG corpus, how far does one poisoned document amplify once it is indexed for every subsequent query?

Q3

Is “render to PDF, then read the page image” a cheaper and more complete baseline than Prism’s oracle path?
