> **一句话总结：** Meta2 把离线优化从"学一个共享的 harness"上移一层，改为用同一任务在三种配置下的 A/B/C 对比 rollout（无 evolver / 当前 Meta-Skill 引导的 evolver / 有训练期特权 verifier 信息的 evolver）蒸馏出一份文本化的 Meta-Skill，在线时冻结该知识、只在每个 run 内按检查点做任务局部的 KEEP/EVOLVE 决策，在 Terminal-Bench 2.1（GPT-5.6-Terra）上取得 81.00% vs 种子 harness 66.33%（+14.67），在 DeepSWE 1.1 上取得 44.44% vs 34.67%（+9.77），均为所比较方法中最高。

> **TL;DR:** Meta2 learns *how to adapt* rather than *what to deploy*: offline, it contrasts three rollout conditions per training task (agent alone, evolver guided by the current Meta-Skill, evolver with training-only verifier privileges) and distills the outcome contrasts into a textual library of `act`/`hold`/`avoid` rules; online, that library is frozen and an evolver uses it at every 5-step checkpoint to either KEEP the harness or apply a task-local edit that never outlives the run. On Terminal-Bench 2.1 (mean@5, 60 held-out tasks) with GPT-5.6-Terra it scores 81.00% ± 0.91 vs 66.33% ± 2.17 for the shared NexAU seed (+14.67 pts) and 73.33% ± 4.41 for the strongest harness-evolution baseline Meta-Harness (+7.67 head-to-head); on DeepSWE 1.1 (mean@3, 75 tasks) it scores 44.44% ± 0.77 vs 34.67% ± 1.33 (+9.77 pts), where five of six evolution baselines fail to beat the seed at all (ACE 32.00%, ReasoningBank 33.33%, Continual Harness 33.78%). Full cost is $174.91 (TB) / $367.86 (DeepSWE), cheaper than AHE ($248.35 / $862.89) and Meta-Harness ($198.85 / $870.75) at higher performance — but roughly 1.9× the seed's online-only cost, and no compute-matched control is run.

## 核心贡献

- **提出 harness 演化的时序分类法**：按"编辑何时被选择、可用证据是什么、影响哪些执行"把既有工作划分为离线优化与 pre-run / within-run / after-run 三类在线适配，并指出只有 within-run 能在暴露问题的那次 run 内做出反应，但其决策看不到该 run 的 verifier 结果。
- **把离线优化上移一层**：不学一个所有任务共享的 harness `h*`，而是学一份可复用的文本化 **Meta-Skill** `ℳ`，记录"何时该干预（act）、何时该放手（hold）、哪种干预有害（avoid）"。
- **A/B/C 三重 rollout 对比**：用"无 evolver（A）""当前 Meta-Skill 引导的 evolver（B）""带训练期特权 verifier 信息的 evolver（C）"三组终端结果配对，构造 act / avoid / hold 五类对比方向，使粗粒度的 pass/fail 变得有方向性；C 组在 A、B 都失败的难题上提供成功样本。
- **冻结全局知识、局部化编辑**：部署时 `ℳ` 冻结、每次 run 都从同一 `h(0)` 重启，harness 编辑只影响当前 run 的剩余部分并在结束后丢弃，从而避免把一个任务的修正带到无关任务上。
- **在两个长程基准上给出性能、成本、组件与检查点频率的完整评估**，并给出 act/hold/avoid 三类条目的具体案例（含 58/60 隐藏测试、74 vs 75 胜场这类"差一点"的失败）。

## Key Contributions

- **A taxonomy of harness evolution** by edit-selection time, available evidence, and the executions an edit affects — separating offline optimization from pre-run, within-run, and after-run online adaptation, and isolating within-run as the only regime that can act on evidence before the motivating attempt ends.
- **Moving offline optimization one level up.** Instead of emitting a single shared harness, Meta2 emits a textual, versioned **Meta-Skill** `ℳ`: reusable decision knowledge about when to intervene, when to leave the harness alone, and which interventions to avoid. The optimization target is the evolver's knowledge, not the agent's scaffold.
- **A contrastive construction procedure (A/B/C rollouts).** Terminal pass/fail is too coarse to attribute credit to individual checkpoint decisions; Meta2 instead runs each training task under three conditions and reads five outcome-contrast directions off them (`B-pass/A-fail` and `C-pass/B-fail` → `act`; `B-fail/A-pass` and `C-fail/B-pass` → `avoid`; `A-pass/B-pass` → `hold`). Condition C is the key trick for hard tasks where both A and B fail and A–B yields no positive example at all.
- **Freeze globally, adapt locally.** `ℳ` is frozen at deployment and every run restarts from the same seed harness `h(0)`; edits are applied through bounded channels (one-turn notice, standing instruction, read-only hook, added tool) and discarded at run end. This is the mechanism that lets verified offline experience transfer without dragging task-specific hacks across runs.
- **An empirical case that the knowledge, not the harness, is the transferable object** — supported by a self-distilled-knowledge control and a retain-edits-across-tasks control, plus full offline/online cost accounting.

## Methodology

**Problem framing.** A task instance is `ξ = (x, E_x, V_x)`: public instruction, interactive environment, and a verifier whose criteria and outcome are invisible to both the task agent and the evolver. A harness `h` bundles prompts, context policy, tools, skills, memory, and hooks. Evolution is `δ(k) ~ g(· | h(k−1), I(k))`, `h(k) = Apply(h(k−1), δ(k))`, where `I(k)` is the evidence available at decision `k`.

**Online component: checkpoint-based within-run evolution.** Two roles are instantiated from the *same* frozen model: a task agent that starts from a minimal seed harness `h(0)`, and an evolver that observes the run at deterministic checkpoints and may edit the harness. The evolver's information accumulates chronologically:

```
I(k) = (x, Δτ(1), ω(1))                          for k = 1
I(k) = I(k−1) ⊕ (Δτ(k), ω(k), σ(k−1))            for 1 < k ≤ K
```

where `Δτ(k)` is the new trajectory delta, `ω(k)` is permitted read-only workspace observation, and `σ(k−1)` records whether the previous edit was loaded, retained, or rolled back. At each checkpoint the evolver makes a binary top-level choice: `u(k) ∈ {KEEP, EVOLVE(δ(k))}`. A terminal checkpoint is triggered by the agent's completion claim, at which point the evolver additionally receives mechanically collected state (task-referenced paths, created/modified files, newly listening TCP ports, still-alive processes). Terminal KEEP accepts the artifact; terminal EVOLVE applies a bounded correction and sends the agent back into the *same* run and sandbox, consuming a send-back from a bounded budget. Crucially, neither ordinary checkpoints nor send-backs reset the environment or discard accumulated progress.

**Offline component: precomputing the Meta-Skill.** Three conditions per training task, all with the same model and seed harness: **A** agent alone, **B** evolver guided by the current `ℳ`, **C** evolver with privileged training-time verifier information. Condition C's system prompt forbids passing privileged verifier content to the task agent, and post-hoc trajectory audits exclude violating rollouts. Contrasts feed three LLM stages: **REFLECT** writes candidate entries per contrast group using a fixed schema; **AGGREGATE** merges recurring patterns across tasks, strips instance-specific details, and requires support from **at least two distinct tasks**; **UPDATE** adds / merges / refines / deletes entries relative to `ℳ(r−1)`, preserving provenance. Formally `ℳ(r) = f_upd(ℳ(r−1), f_agg(f_ref(G(r), V(r))))`. A and C rollouts are collected once and reused; B rollouts are recollected each batch with the then-current `ℳ(r−1)`.

**Meta-Skill entry schema.** Each entry carries ID/title, **type** (`act` | `hold` | `avoid`), **time point** (`start` | `during` | `end`), **when to refer** (an observable condition the evolver can actually match — e.g. "a claim contradicted by command output", "repeated attempts producing no new evidence"), **guidance** (the action plus channel and message content), **why** (the cross-task pattern and its qualifications), and up to three **reference examples** from distinct training tasks. Triggers are deliberately written as *relations* rather than file names or commands, which is what keeps them matchable on unseen tasks. The Terminal-Bench Meta-Skill in the appendix has 14 entries (E-01…E-14); `start` entries are injected in the first checkpoint message, the rest live in the system prompt, and the evolver must cite the entry IDs it acted on (or state that none applied).

**Deployment protocol.** `ℳ` is frozen, `h(0)` is reset per run, and no held-out verifier feedback or LLM-as-judge signal is ever written back. Online decisions, task-specific edits, and outcomes do not update the library.

**Evaluation setup.** Terminal-Bench 2.1 (89 tasks; 29 train / 60 test; containerized CLI workflows) and DeepSWE 1.1 (113 tasks across 91 OSS repos; 38 train / 75 test; repository-level SWE), randomly split 1:2 and fixed across methods. mean@5 on TB (300 runs per method) and mean@3 on DeepSWE (225 runs per method), executed in E2B cloud sandboxes. Backbones: GPT-5.6-Terra (medium reasoning) and DeepSeek-V4-Flash-0731 (high reasoning) on TB. Baselines: human-designed harnesses (NexAU seed, Codex CLI, mini-swe-agent, Pi agent, DeepSeek Harness), self-evolution (ReasoningBank, ACE, TF-GRPO), and harness evolution (AHE, Meta-Harness, Continual Harness). All evolution methods share the NexAU seed; no test-time-adapting method may see held-out verifier outcomes.

## Results & Highlights

- **Terminal-Bench 2.1, GPT-5.6-Terra, mean@5 (60 held-out tasks):** Meta2 reaches **81.00% ± 0.91** vs **66.33% ± 2.17** for the shared NexAU seed (**+14.67 pts**) and **73.33% ± 4.41** for Meta-Harness, the strongest harness-evolution baseline (**+7.67 head-to-head**). Every other method lands between 67.33% (mini-swe-agent) and 74.67% (TF-GRPO), so the top six baselines are compressed into 7.3 points while Meta2 sits 6.3 points clear of the best of them.
- **DeepSWE 1.1, GPT-5.6-Terra, mean@3 (75 tasks):** **44.44% ± 0.77** vs **34.67% ± 1.33** for the seed (**+9.77 pts**), vs **37.33% ± 2.67** for Meta-Harness (**+7.11 head-to-head**). The separation is qualitative here: five of six evolution baselines do not beat the seed at all — AHE ties it (34.67%, 0.00), ReasoningBank is below (33.33%, −1.34), Continual Harness below (33.78%, −0.89), ACE well below (32.00%, −2.67). Only TF-GRPO improves (+1.77, 36.44%) before Meta2's +9.77.
- **Backbone swap (Terminal-Bench 2.1, DeepSeek-V4-Flash-0731, mean@5):** **77.67% ± 3.84** vs **70.00% ± 2.64** for the seed (**+7.67 pts**), vs 74.67% for Continual Harness (+4.67 over seed) and 71.33% / 71.00% for AHE / Meta-Harness. All three self-evolution baselines fall *below* the seed here (ACE 65.00%, −5.00). The headline margin roughly halves (14.67 → 7.67), so the method's advantage is real but backbone-dependent.
- **Cost (full = one-time offline + online, aggregated USD):** TB **$174.91** at 81.00% vs **$248.35** for AHE at 70.67% and **$198.85** for Meta-Harness at 73.33%; DeepSWE **$367.86** at 44.44% vs **$862.89** (AHE, 34.67%) and **$870.75** (Meta-Harness, 37.33%). Against the closest online competitor, Continual Harness, Meta2 pays more offline ($110.19 vs $28.75 on TB; $238.52 vs $46.11 on DeepSWE) but less online ($64.72 vs $83.48; $129.34 vs $155.61) — the precomputation is amortizable, but online cost is still ~1.9× the seed's $34.09.
- **Component ablation (TB / DeepSWE):** task agent alone **66.33 / 34.67** → +evolver with no distilled knowledge **74.67 / 36.44** (+8.34 / +1.77) → +**self-distilled** Meta-Skill **77.00 / 35.56** (+2.33 / **−0.88** — self-distillation actively hurts DeepSWE) → +**contrastive** Meta-Skill **81.00 / 44.44** (**+4.00 / +8.88** over self-distillation). This is the cleanest evidence in the paper: the contrastive signal, not merely having a knowledge library, is what produces the DeepSWE gain.
- **Locality ablation:** retaining online edits across later tasks instead of resetting to `h(0)` drops **81.00% → 78.33%** on TB and **44.44% → 39.11%** on DeepSWE (−2.67 / −5.33), directly supporting the "task-local edits" design choice.
- **Checkpoint frequency (TB):** `L = 5` is the optimum at **81.00% / $64.72** online; `L = 3` gives 80.33% at $74.22 and `L = 1` gives 79.00% at $83.41 — more supervision is *not* monotonically better, and the paper reports that Meta2 beats every baseline at every evaluated `L`.

## Critical Assessment

**Novelty.** The reframing is the real contribution and it is a good one: the community has spent two years optimizing *what scaffold to deploy*, and Meta2 argues the transferable object is *the policy for editing the scaffold*, which sidesteps the standard failure mode where an evolved harness overfits the training tasks and then gets frozen. The A/B/C contrast trick — using a verifier-privileged evolver as an upper-bound condition so that hard tasks still yield positive examples — is a genuinely clever way to get learning signal out of binary terminal rewards, and it is the mechanism that plausibly explains the DeepSWE result, where five of six baselines cannot beat the seed. The act/hold/avoid taxonomy is also more operational than "reflexion-style" memory: `hold` entries ("the agent is already recovering; do not spend a notice") are the kind of thing practitioners know but rarely formalize, and the case study in Figure 8 — where the no-Meta-Skill evolver burns both notices on an isolated `file`-command failure and has none left when a real image mismatch appears — is a concrete, believable failure mode.

**Rigor.** The ablation design is better than most papers in this genre. The self-distilled-knowledge condition is exactly the right control (it isolates "having a library" from "having a *contrastive* library"), and it is revealing that self-distillation *reduces* DeepSWE performance by 0.88 points while contrastive learning adds 8.88 — that asymmetry is the paper's most convincing single number. The reset-vs-retain ablation tests the paper's own locality claim rather than a strawman. Standard deviations are reported for every cell (Table 5), and Meta2's is by far the tightest (0.91 on TB vs 2.17–5.14 for everything else). Costs are split offline/online and computed from LiteLLM response headers rather than estimated. The paper also does the honest thing of stating that the L=1 result is *worse* than L=5, which cuts against a "just add more evolver calls" reading.

**Reproducibility.** Mixed. The algorithms, prompts, and full Meta-Skill texts are all in the appendix, which is more than most. But several quantities that determine whether the result replicates are simply absent: the number of offline batches `R`, the number of rollouts per training task per condition, the send-back budget, and the evolver's tool/token budget are never stated in §4.1 or Appendix C.3. The condition-C leakage audit — the one mechanism standing between "privileged verifier information" and "contamination of `ℳ`" — is described only as "audit condition-C trajectories after execution and exclude those that violate this restriction", with no auditor specified (LLM judge? rule-based? human?) and no exclusion rate reported. Given that the entire offline signal is built from those trajectories, an unquantified audit is the weakest link in the pipeline. Training sets are also tiny: 29 tasks for TB and 38 for DeepSWE, with an "at least two distinct tasks" support rule, so a single entry can rest on two rollouts of two tasks.

**Significance.** The performance claim is solid within its scope: highest point estimate on both benchmarks, on both backbones, with a clean cost story against the offline-heavy baselines. But the scope is narrower than the title suggests. Four separate Meta-Skills are built (2 benchmarks × 2 backbones), and the paper explicitly says the DeepSeek experiment "evaluates robustness across backbones rather than zero-shot transfer of a frozen Meta-Skill between models." No cross-benchmark transfer cell exists — a TB-trained `ℳ` evaluated on DeepSWE, or vice versa — which is precisely the experiment that would test whether the knowledge is *reusable* in the sense the paper's framing promises. Reading the appendix entries makes the concern concrete: they cite `dna-assembly`, `regex-chess`, `sqlite-with-gcov`, `mteb-leaderboard`, `install-windows-3.11` — Terminal-Bench task families. The knowledge is reusable across tasks *of the same benchmark distribution*, distilled from 29 of that benchmark's own tasks. "Reusable" here means within-distribution, not general.

**Red flags.** Three, in descending order of seriousness. (1) **No compute-matched control.** Meta2's online cost is $64.72 vs $34.09 for the seed on TB — 1.9× — because it runs a full frontier-model evolver every five steps plus send-backs. The paper never gives NexAU the same online budget (best-of-2 attempts, a self-critique retry, or an extra 30 dollars of test-time compute). The L-sweep is partial evidence against pure compute-scaling (L=1 at $83.41 scores *worse* than L=5 at $64.72), but it is not the same experiment, and a reader cannot rule out that some of the +14.67 is bought rather than learned. (2) **Baseline hyperparameter asymmetry.** Continual Harness — the closest method and the only other within-run system — uses a 25-step warmup followed by refinement every 25 steps, while Meta2 gets a checkpoint immediately after the agent's first step and every 5 steps thereafter. The claim that "Meta2 outperforms every baseline at every evaluated `L`" mitigates this, but it is asserted in prose and shown as a scatter plot without per-`L` baseline numbers, and Continual Harness's schedule was never tuned for these benchmarks. (3) **The variance anomaly is undiagnosed.** Meta2's 0.91 std against 4.41 for Meta-Harness and 4.65 for Continual Harness is a 5× difference, and the most likely explanation is not flattering to the baselines: ACE, ReasoningBank, and Continual Harness all carry state across the test stream and can suffer negative transfer from task *n* to task *n+1*, whereas Meta2 resets to `h(0)` every run. If that is the cause, part of the baseline gap is a design choice the paper imposed on its competitors rather than a capability difference — and the paper, which is otherwise scrupulous about such things, never says so. A secondary concern: the "Pareto frontier" claim is a point-estimate claim among eleven systems, and Pi agent reaches 39.11% on DeepSWE for $82.50 against Meta2's 44.44% for $367.86 — 4.5× the cost for +5.33 points. That is a legitimate frontier point, but "extends the frontier toward higher performance" reads more favorably than "$66 per point."

## Strengths

- The reframing from "optimize the harness" to "optimize the knowledge for evolving the harness" is a genuine conceptual contribution, and it dissolves a real problem (offline-evolved harnesses overfit and then cannot react) rather than relabeling it.
- The A/B/C contrast design is the paper's best idea: using a verifier-privileged evolver as condition C manufactures positive examples on tasks where both A and B fail, which is exactly where naive contrastive learning has nothing to learn from. The DeepSWE result — where the method works and five of six baselines regress — is consistent with that mechanism doing real work.
- The self-distilled-vs-contrastive ablation is a sharp, well-chosen control, and the fact that self-distillation *hurts* on DeepSWE (+2.33 / −0.88) while contrastive learning helps (+4.00 / +8.88) is the strongest single piece of evidence in the paper.
- The reset-vs-retain ablation tests the paper's own central design claim rather than a weak alternative, and the drop (81.00 → 78.33; 44.44 → 39.11) is large enough to matter.
- Honest reporting: per-cell standard deviations, offline/online cost split, a negative result on `L = 1`, and a limitations section that admits the contrasts are run-level rather than causal and that the guidance is an abstraction whose applicability is not guaranteed.
- The Meta-Skill entries themselves are unusually concrete and readable — "reported success with unchanged observation", "failure output carries its own correction", "completion shown only indirectly" — and the four case studies name real tasks and near-miss counts (58/60 hidden tests, 74 vs 75 wins), which makes the mechanism inspectable rather than hand-waved.

## Limitations

- **No cross-benchmark or cross-model transfer experiment.** Four Meta-Skills are built, one per (benchmark, backbone) cell. The paper's own framing — "precompute how to adapt, then adapt locally" — implies the knowledge should transfer; the experiments only show within-benchmark reuse. This is the single largest gap between claim and evidence.
- **No compute-matched control.** The evolver is an extra frontier-model call every five steps plus send-backs, roughly doubling online cost. Whether the gain survives an equal-budget comparison (best-of-N, self-critique retry, or simply more attempts for the seed harness) is untested.
- **Small training and test sets.** 29 training tasks for TB and 38 for DeepSWE, with entries requiring support from ≥2 tasks; 60 and 75 held-out tasks respectively, so the 14.67-point TB gap corresponds to roughly nine tasks. No confidence intervals or significance tests are reported anywhere, and Meta2's unusually tight 0.91 std is never explained.
- **No per-entry attribution.** The 14-entry Terminal-Bench Meta-Skill is never ablated. The paper mentions an internal "entry credit" mechanism (entries judged helped/misled) in the UPDATE prompt but never reports which entries were cited how often or which ones carry the gain. A leave-one-entry-out study would tell us whether the method is 14 rules or 2 rules and 12 decorations.
- **Unquantified leakage audit.** Condition C is the source of the positive examples, and the audit that keeps privileged verifier information out of `ℳ` is asserted without specifying the auditor or the exclusion rate.
- **Underspecified offline hyperparameters.** `R` (number of batches), rollouts per condition per task, send-back budget, and evolver token budget are absent, which blocks faithful reimplementation.
- **Narrow domain coverage.** Both benchmarks are artifact-verifiable terminal/SWE tasks. The authors acknowledge that embodied control and open-ended research have different interaction structures and less explicit completion criteria, and nothing here tests those.
- **Cost profile is only favorable against expensive offline methods.** Against cheap human-designed harnesses (Pi agent $82.50 on DeepSWE, Codex CLI $56.59 on TB) Meta2's dollars-per-point is poor, and the amortization argument depends on a deployment volume the paper does not characterize.

## Relevance

直接命中 **Self-Evolving Agents & Automated Research**：它把"自我改进"的对象从 agent 的 scaffold 上移到"如何改 scaffold"的知识，并用 A/B/C 对比把粗粒度的 pass/fail 变成可迁移的 act/hold/avoid 规则，是递归自我改进（RSI）路线上一份少见的、带完整成本账和消融的实验性论证。同时对 **Agent & Pipeline Silent Failures** 高度相关：它学到的 14 条 Meta-Skill 里大半本质上是"静默失败"检测器（报告成功但外部观测未变、交付物与自身 trace 矛盾、完成只被间接验证），可直接借用作 agent harness 的运行时校验规则库。

## Questions for Further Exploration

1. What happens with a **zero-shot cross-benchmark transfer** cell — a Terminal-Bench-trained `ℳ` applied unchanged to DeepSWE, and the reverse? If the answer is "it degrades to the seed", the paper's central noun ("reusable") is doing less work than the framing implies, and that is a one-experiment question the authors were positioned to answer.
2. How much of the +14.67 on TB survives a **compute-matched control** — e.g. NexAU with two attempts and a self-critique pass at the same $64.72 online budget? The L=1 result hints that raw supervision volume is not the driver, but the direct experiment is missing.
3. Which of the 14 entries actually matter? A leave-one-out or cite-frequency analysis would reveal whether the gain concentrates in two or three high-value rules (`act` on unverified completion claims, `hold` on self-correcting failures) and whether the `avoid` entries ever fire.
4. Is the low variance (0.91 vs 2.17–5.14) a property of the method or an artifact of resetting to `h(0)` while competitors accumulate state? Re-running ACE / ReasoningBank / Continual Harness *without* cross-run persistence would separate method quality from state-drift penalty.
5. How does the approach behave when the evolver is a **weaker model** than the task agent? The paper uses one model for both roles; a cheap evolver supervising an expensive agent (or vice versa) is the economically interesting configuration and is untested.
6. Does `ℳ` grow monotonically? UPDATE supports add/merge/refine/delete with no cap and no target size ("there is no cap on the number of entries"), so does the library plateau, or does it accumulate stale rules as training batches proceed — and does entry credit ever successfully delete a rule that was once useful?
7. What is the false-negative rate of the **condition-C leakage audit**, and would an independent (non-LLM) check on the privileged-information channel change the DeepSWE result, given that DeepSWE is where condition C is claimed to matter most?
