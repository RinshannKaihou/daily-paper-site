Why it matters

If you build self-improving agents, this is the boundary condition: full RSI loops fail at frontier scale; cheap headroom proxies are what work.

Read for the loops, not the framing
Critical edge

By the paper's own test — that update must revise the loop machinery — none of the six loops qualifies: what accumulates is a log of negative results that humans read.

More caveats ↓
Methodology

Relocate the loop, don't argue about it

RSI is defined as propose → run → measure → update. Frontier pre-training breaks the first two preconditions: a run costs hundreds of thousands of GPU-hours and cannot be repeated, and the real target — post-training headroom — has no single score. So the loop is closed somewhere cheaper, six times over, around one shared memory.

Read with care

One arm. No run without agents, no per-loop ablation, and five recipe changes landed together.

No cost accounting — not GPU-hours, not agent tokens — in a paper whose whole argument is economic.

The tie is a tie. 73.13 vs 73.07, no seeds, no confidence interval.

Strengths

What survives scrutiny

  • The most detailed public account of a from-scratch 30B-A3B run — exact schedule, RoPE progression, per-stage mixtures, optimizer split, 130+ code revisions. Normally this stays internal.
  • A loop taxonomy that maps onto all four RSI steps, including what plays the role of measure and why headroom can only be probed a few times per project.
  • Tiny-SFT + aptitude + max-over-protocols is a real methodological contribution, and the ρ result is checkable rather than rhetorical.
  • Honest three-tier evaluation, with the least-fair tier explicitly labelled a headroom probe instead of a win.
  • Systems numbers with a cost model and a stated side effect; the anti-hack table is immediately reusable by anyone building agentic data.
Limitations

Where the claim thins out

  • Single arm, no ablation. No agent-free control run, no measurement of what each loop contributed — the causal story is untested.
  • No cost data at all. GPU-hours, agent spend and loop overhead are absent, so "worth the cost" is asserted.
  • Confounded revisions. LR 2.7e-3 → 5e-4, load balance 1e-2 → 1e-4, router Muon → AdamW, all between pilots.
  • Tiny-SFT is under-powered where it is load-bearing: one seed per checkpoint, one 6.33B mix, ±1.5–2.4 pt effects against 1–2 pt noise.
  • A disclosed credential leak with no follow-up — no memorization audit of the checkpoint trained on the pre-fix corpus.
  • Partial reproducibility. Loops and context infrastructure unreleased; one of nine harnesses hit a 0% pass rate and is unnamed.
Open questions

What would settle it

What would a no-agent control run look like — and can one be approximated from the pilot logs?

What did the loops cost per diagnosis, in agent tokens and engineer hours, against the GPU-weeks they saved?

Why is KernelBench 77.60 when the best baseline is 44.00 and the same model is mid-pack on SWE-bench Pro?

Does the ρ = 0.438 rank disagreement survive multiple SFT seeds, or are the 159k/210k inversions noise?

Does the released checkpoint still emit credentials from the pre-fix code corpus?

Is "post-training headroom" a property of the checkpoint or of the 6.33B-token probe?
