Why it matters

Most agent failures are the scaffolding, not the model. This makes the runtime itself a trainable object — and shows how to catch it breaking.

Distilled from Relevance

Read it critically

Every number is a single training run — no seeds, no confidence intervals — so the WebShop (+2.4) and DBBench (+2.3) margins sit inside the noise floor.

ALFWorld's test split is 134 tasks: 97.0 vs 90.5 is ≈ 9 tasks, and the control's own curve moves 90.5 → 91.5 between checkpoints.

01 Methodology

Two policies, one scalar reward, no gradients through code

The unit of learning is a complete attempt: the generated program, the multi-turn rollout under it, and the terminal reward.

01
Engineer πE reads historical feedback — prior code, scores, traces — and samples a program proposal.
02
A validator turns it into an executable harness h; invalid proposals fall back to the base executor (h = ∅).
03
Solver πS runs a full episode under h and returns one terminal reward R (binary on ALFWorld).
04
Both actors update only on their own tokens, with separate critics and separate KL references. R is the sole coupling.
Context critics

A collaboration summary goes to the critics only — it shapes the baseline, never the actors' behaviour.

ValueNorm

Per-role return normalization: one program vs. many turns means very different return scales.

Peer weighting

Partner-trajectory likelihood ratio, clipped to [0.5, 2]. Stale pairs count less.

Asymmetric schedule

joint / joint / Solver-only, at a 2:3 Engineer:Solver update ratio.

↳ Field note · the bug

A dotted key that froze the world

ctx["action"]["final_action"]

The harness writes the completed action into a nested field, then reads it back with a literal dotted key. The state never updates — so the agent keeps re-planning against a world it already changed.

Same Solver, same task. The runtime is the only variable — a bug class practitioners can actually hunt for.

03 Strengths

What survives scrutiny

  • A controlled diagnosis, not a correlation. Holding one saved harness byte-identical while swapping Solver checkpoints yields an additive decomposition.
  • A concrete bug taxonomy. Dotted-key lookup, overwritten inventory evidence, stale "go clean it" guidance after cleaning already succeeded.
  • Honest internal controls. Frozen Engineer gets its best checkpoint, not its final one; programs and Solvers are cross-evaluated in both directions; Pick2 is reported, not buried.
  • A clean formalization — separate critics, separate KL refs, no differentiation through execution — reusable by anyone building on SAO.
  • Sharp positioning against WHALE and Harness-R1 by naming the architectural difference: who trains the proposer.
04 Limitations

What the paper does not show

  • Single run per configuration. No seeds, no error bars; the +2.4 and +2.3 margins are indistinguishable from noise.
  • One base model. No evidence the learned harness transfers across Solvers or model families — which undercuts "harness as reusable runtime".
  • No leave-one-out ablation. The 2:3 schedule, the [0.5, 2] Peer clip and the 144-round budget are all fixed with zero sensitivity analysis.
  • Baselines are quoted, not re-run. Cross-paper comparisons conflate method with compute budget.
  • ALFWorld is near-saturated and dominates the average; there is no compute or token accounting for the Engineer's per-round code generation.
05 Open questions

What to ask before building on it

  1. Does 97.0% survive three seeds — and what is the minimum detectable difference on a 134-task split?
  2. Does the learned harness transfer to a different Solver at fixed weights (4B, 30B, another family)? That is the case that would make it a reusable artifact.
  3. What does leave-one-out from the full method give, especially for ValueNorm, whose add-one-in result sits below Joint-only + Context?
  4. Why is the combination superadditive — +8.5 from four parts worth +3 to +4 each? Is it the schedule interacting with Peer weighting, or just a longer effective Solver budget?
  5. How sensitive is the result to the 2:3 ratio and the 144-round budget — does the alternating baseline recover with matched Solver updates?
  6. Can compatibility loss Δh be monitored online and used as a training signal, rather than only as a post-hoc diagnostic?
