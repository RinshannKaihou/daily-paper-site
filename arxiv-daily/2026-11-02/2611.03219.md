> **一句话总结：** 作者把三种软件工程任务（SWE-Bench 代码修复、SWT-Bench 测试生成、FeatureBench 特征实现）排成六个"持续进化方向"，用 AHE 与 Meta-Harness 依次进化 Mini-SWE-Agent 的 harness，发现后一个任务的进化会灾难性摧毁前一个任务的能力——例如 Meta-Harness 在 SWE-Bench 上从 94.0% 跌到 32.0%（相对下降 66%），并把原因归为 harness 层面的验证/工件冲突（占 87.1% 的 pass-to-fail 案例）、工作流冲突与预算策略冲突。

> **TL;DR:** This is an empirical stress test of *continual* harness self-evolution (evolving the agent scaffold across task types, not within one), run on SWE-Bench Verified (50 sampled instances), SWT-Bench (50, prompt-paraphrased), and FeatureBench (30) with DeepSeek-V4-Flash-0731. Both AHE and Meta-Harness look great in isolation — AHE lifts SWE-Bench from 82.0% to 96.0% over 9 rounds and both hit 100.0% on SWT-Bench — but in all six two-stage directions the second stage wrecks the first: SWE→SWT drops SWE-Bench by 100% (AHE) and 98% (Meta-Harness) after 5 rounds, and SWE→Feature costs 29% and 66% respectively, versus the abstract's headline 94.0%→32.0% (−62 pts). An ablation pinpoints the mechanism: injecting the evolved artifact-submission gate alone collapses SWE-Bench from 96.0% to 0.0%, while workflow constraints cut it to 66.0% and inflate runtime by 235%.

## 核心贡献

- **提出"harness 持续自进化"（continual harness self-evolution）这一新问题设定**：以往的自进化工作都只在一个任务类型上独立进化 harness，本文把它形式化为在数据集序列 D₀, D₁, …, D_K 上反复更新 H，并借用持续学习的 stability–plasticity 框架给出遗忘度量 Δ_forget 与相对遗忘率 ρ_forget。
- **用 3 个数据集 × 6 个方向 × 2 种方法的受控实验证明灾难性遗忘是系统性的、而非个例**：六个方向里几乎每一个都在第二轮进化后显著损害第一轮的能力。
- **对 520 条执行轨迹做人工分析，提出 harness 冲突三分类**（verification / workflow / budget-strategy），并统计其在 pass-to-fail 案例中的占比：验证冲突 87.1%、工作流冲突 8.2%、预算冲突 0.6%。
- **用受控注入实验（Table 1）分离三类冲突的因果影响**：验证（工件门）冲突把 SWE-Bench 打到 0.0%，工作流冲突降到 66.0% 且耗时 +235%，预算策略几乎不影响正确率（96.0% 不变）但耗时 +79%。
- **一个方法论副作用发现**：SWT-Bench 原始 prompt 是固定句式，进化出的 harness 会学到一个纯字符串匹配的分类器（`_TEST_DELIVERABLE_HINTS`）来区分任务类型；作者改写（paraphrase）prompt 后该捷径消失。这既是他们实验设置的必要处理，也是对"自进化会薅 benchmark 表面形式"的一个具体证据。

## Key Contributions

- **Defines the problem.** Formalizes continual harness self-evolution as H_{i+1} = Ω(H_i, trajectories from D_i) over an ordered dataset sequence, and adapts the continual-learning stability–plasticity framing to harnesses: after evolving on D_i, the harness must both improve on D_i (Eq. 2) and not regress on any earlier D_j (Eq. 3), with absolute (Δ_forget) and relative (ρ_forget) forgetting metrics.
- **Establishes that forgetting is real and large.** Two representative methods (AHE, Meta-Harness), three SE task types, six ordered directions, all evaluated on held-out splits of the earlier dataset.
- **Localizes the cause at the harness level.** Manual diff-and-trajectory analysis of 520 trajectories yields a three-way conflict taxonomy, plus a prevalence breakdown over pass-to-fail cases (87.1% / 8.2% / 0.6%).
- **Quantifies per-type causal impact** via controlled injection of representative modifications into the best SWE-Bench harness (Table 1), separating accuracy damage from latency damage.
- **Documents a benchmark-artifact hazard**: an evolved harness that learned to classify tasks by SWT-Bench's fixed prompt template, and the paraphrase fix that removed the shortcut.

## Methodology

**Problem setup.** An agent is A = ⟨M, H⟩: foundation model M (frozen) plus harness H (prompts, control flow, tools). A self-evolution operator Ω reads execution trajectories and emits H′. Continual evolution chains Ω over D₀ → D₁ → … → D_K. Forgetting is measured on the *source* dataset after the *target* evolution: Δ_forget = Eval(H_{j+1}, D_j) − Eval(H_{i+1}, D_j), and ρ_forget the same difference normalized by the pre-transfer score.

**Benchmarks (all subsampled).** SWE-bench Verified (500 instances; 50 used) for issue-driven code repair; SWT-Bench (50) for generating fail-to-pass regression tests; FeatureBench (30) for implementing new features under F2P + P2P test evaluation. The authors deliberately paraphrase SWT-Bench's prompts (semantics preserved, surface form varied) because the original template is a single fixed sentence structure — Appendix B shows the un-paraphrased version lets the evolver learn a literal keyword classifier.

**Initial harness.** Mini-SWE-Agent v2.4.6 (~100 lines of Python, >74% on SWE-bench Verified), extended with a tool registry. The evolvable surface is restricted to three things — the system prompt (`mini.yaml`), the agent control flow (`agents/**`), and tools/parsers/observations (`models/utils/**`) — so the evolver cannot touch the environment contract or evaluation harness.

**Evolution methods.** AHE (Lin et al., 2026): closed loop of rollout → Agent Debugger summarizing success/failure root causes from trajectory files → Evolve Agent rewriting harness code; 9 rounds, 10 evaluated harnesses. Meta-Harness (Lee et al., 2026): maintains a Pareto frontier of harnesses, proposes new variants from frontier + accumulated experience, evaluates on the current dataset; 5 rounds. Because neither public implementation supports Mini-SWE-Agent, **both were reimplemented by the authors** against the original codebases.

**Protocol.** DeepSeek-V4-Flash-0731 for both task execution and evolution; E2B sandbox; 1-hour per-task limit; rollout temperature 0; each round executes the same task batch twice. Two-stage design: first evolve independently on each dataset, take the best harness found (first harness to reach the max score in case of ties), then transfer it to a second dataset and continue evolving, re-evaluating on the source dataset at Iter 3 and Iter 5.

**RQ2 analysis.** For each direction, diff the initial harness against the harness after 5 continual rounds, hand-inspect the modifications, then trace the 520 trajectories belonging to tasks that flipped from pass to fail and attribute each failure to a conflict class. Finally, inject one representative modification per class into the best SWE-Bench harness to measure isolated impact.

## Results & Highlights

- **Single-dataset evolution works, and works big.** AHE raises SWE-bench Verified from 82.0% (H₀, Mini-SWE-Agent) to 96.0% after 9 rounds (+14 pts); Meta-Harness reaches 94.0% (+12 pts). On the 50-instance SWT-Bench sample *both* methods go from 82.0% to 100.0% (+18 pts, i.e. a saturated ceiling). On FeatureBench both gain >10 pts, with AHE's best harness at 30.0% by round 3. As a framing number: with the model fixed, different harnesses span 82.0%–96.0% on SWE-Bench — a 14-point spread that is entirely scaffold.
- **Catastrophic forgetting is near-total in the cross-task-type directions.** SWE→SWT after 5 rounds: SWE-Bench falls by 100% relative for AHE (96.0% → 0.0%) and 98% for Meta-Harness (94.0% → ~2%). The paper's headline case, SWE→Feature with Meta-Harness, is 94.0% → 32.0% (−62 pts, −66% relative); AHE degrades more gracefully at −29% (96.0% → ~68%). In the reverse direction, Meta-Harness's SWT-Bench score falls from 100.0% to 62.0% after evolving on FeatureBench (−38 pts, −38% relative).
- **Forgetting tracks task relatedness, not method choice.** SWE-Bench ↔ FeatureBench (both require editing repository source) forget far less than any pair involving SWT-Bench (test-only artifacts): the SWT-involving directions produce 98–100% relative drops versus 29–66% for SWE↔Feature. This is the paper's most transferable empirical regularity.
- **Conflict prevalence is extremely skewed.** Of the pass-to-fail cases analyzed across the 520 trajectories, verification conflicts explain 87.1%, workflow conflicts 8.2%, budget-strategy conflicts 0.6%, with the remainder unclassified. Artifact conflicts (submission-gate polarity flips) dominate within the verification bucket.
- **Isolated injection shows the damage is mechanical, not gradual (Table 1, AHE's best SWE-Bench harness as base).** Base: 96.0% at 245.5 s/task. +Verification (artifact) conflict: **0.0%** (↓100%) at 415.7 s (↑69%). +Workflow conflict: **66.0%** (↓31%) at 821.5 s (↑235%). +Budget strategy: **96.0%** (↓0%) at 439.7 s (↑79%). So one added submission gate can zero out a 96% agent, and the most expensive conflict class in wall-clock terms is workflow, not verification.
- **The SWT-Bench shortcut is a concrete artifact of self-evolution.** Un-paraphrased, Meta-Harness's evolved harness contains `task_requests_test_deliverable()`, matching substrings like `"implement only test cases"` / `"don't try to fix the issue"` — a classifier over the benchmark's prompt template, not over task semantics. Paraphrasing removes it.

## Authors & Credibility

Shangziqi Zhao, Yitong Zhang, and Jia Li, Tsinghua University (banner: "Tsinghua AI Agent Group"; Jia Li corresponding, jia_li@mail.tsinghua.edu.cn). The paper is a short empirical/analysis paper (14 pages including appendix, no venue listed on the PDF — arXiv preprint dated 2 Nov 2026, v1). Code is released at `github.com/THU-Agent/continual-harness-evolution`, which is the right move for a paper whose value is entirely in the experimental protocol. The group's framing is careful in one important respect: they explicitly do *not* claim a method contribution, only a diagnosis, and they scope the evolvable surface so the comparison is apples-to-apples. The work is positioned as a critique of AHE and Meta-Harness, both of which they reimplemented themselves — an honest disclosure that also weakens the strength of the claims about those specific methods (see Critical Assessment).

## Critical Assessment

**Novelty.** The framing is genuinely new and useful: nobody has asked whether harness self-evolution *chains*, and the answer ("no, it collapses") is the kind of negative result the subfield needs. The three-way conflict taxonomy is a reasonable first cut, and the artifact-gate example (a submission check that flips polarity between test-only and source-fix tasks) is a crisp, memorable mechanism. But the *analysis machinery* is borrowed wholesale from continual learning — stability–plasticity, Δ_forget, ρ_forget — with no adaptation to the discrete, code-level nature of harness edits. There is no method proposed, no mitigation attempted, and no baseline beyond "the two methods we ported."

**Rigor — the sample sizes are the weak point.** 50/50/30 instances means each SWE-Bench instance is worth 2 points and each FeatureBench instance 3.3 points. A 96.0% score is 48/50; a 0.0% is 0/50. No confidence intervals, no standard errors, no repeated evaluation seeds are reported, and temperature 0 with a single eval pass means the 94.0 → 32.0 headline rests on roughly 31 task flips out of 50. The direction-level ordering (SWT-pairs forget more than SWE↔Feature) is plausible and consistent across both methods, which partly rescues it — but the specific magnitudes should not be read as precise. The 100.0% ceiling on SWT-Bench is a measurement artifact that mechanically inflates relative forgetting: any drop from a perfect score is a large ρ, so the −38% SWT number is not comparable to the −29%/−66% SWE numbers.

**Rigor — the 0.0% ablation is suspicious in a way the paper does not interrogate.** Table 1's "+Verification Conflict → 0.0%" is a degenerate result: an artifact gate that rejects any patch touching non-test files should still let through the subset of SWE-Bench tasks solvable by test-file-only edits, and it should certainly not produce exactly 0/50. Either the injected gate is broader than the real evolved one, or it breaks the agent's loop (e.g. rejects submission repeatedly until the 1-hour budget expires) rather than merely mis-filtering artifacts. The paper reports the number and moves on; a failure-mode breakdown of those 50 tasks would have told us whether this is "forgetting" or "the harness is now non-functional." Relatedly, the ablation injects three modifications sourced from *two different* directions (verification from SWE→SWT, workflow and budget from SWE→Feature) into one base harness, and each class is represented by a **single** hand-picked modification — n=1 per class, chosen by the authors after seeing which ones were dramatic.

**Rigor — reimplementation confound.** Both AHE and Meta-Harness were re-implemented because neither supports Mini-SWE-Agent. "Aligning as closely as possible" is not verified: there is no fidelity check against the published AHE/Meta-Harness numbers on their own benchmarks, and no ablation of implementation choices (e.g. how the Agent Debugger's evidence is summarized, how the Pareto frontier is maintained). A reader cannot tell whether the forgetting is a property of these *methods* or of these *ports*. The single-model restriction (DeepSeek-V4-Flash-0731 only) compounds this: the evolver's competence at editing code is itself model-dependent, and a stronger evolver might produce less brittle harnesses.

**Rigor — the "generalizes to multi-dataset sequences" claim is asserted, not shown.** Section 4.1 states that conclusions from two-stage sequences "can also be generalized to multiple sequential datasets" by induction. That is exactly the kind of claim continual-learning research treats as an empirical question — forgetting can compound, or the harness can converge to a task-agnostic core after the second transfer. Only 2-stage chains were run.

**Rigor — the manual analysis has no reliability protocol.** 520 trajectories, hand-labeled into three conflict classes with a 12.4% residual "not associated with a specific conflict type." No second annotator, no inter-annotator agreement, no labeling rubric beyond the prose definitions, no per-direction breakdown of the 87.1%. Since the taxonomy is the paper's main analytical product, this is a real gap — a single annotator's judgment call is doing a lot of work.

**Significance.** High as a warning shot, medium as science. The practical takeaway ("don't let your harness evolve across task types without a retention check") is immediately actionable and, notably, cheap to test — which makes the paper's silence on mitigations (replay of earlier trajectories, freezing verified components, multi-task Pareto selection) the most conspicuous omission. Meta-Harness already maintains a Pareto frontier; the obvious experiment is "keep the frontier across datasets, not within one," and it is not run.

**Red flags, ranked.** (1) n=30 on FeatureBench with 3.3 pts/instance granularity. (2) 100% ceiling on SWT-Bench. (3) A 0.0% ablation that is never explained mechanistically. (4) n=1 injected modification per conflict class. (5) Both compared methods reimplemented by the authors, unvalidated. (6) No CIs, no seeds, single model. None of these invalidate the qualitative conclusion — six directions, two methods, consistent direction of effect — but they mean the numbers in the abstract should be read as existence proofs, not effect sizes.

## Strengths

- **The question is the right question.** "Does harness evolution chain?" is an obvious-in-hindsight gap that the entire self-evolving-agent literature skipped, and the answer is a clean no.
- **Six directions, not one.** Running all ordered pairs of three task types (rather than cherry-picking SWE→SWT) is what turns this from an anecdote into a pattern, and it produces the genuinely interesting relatedness finding.
- **The conflict taxonomy is mechanistically satisfying.** "The harness learned that submissions must be test-only, and then you asked it to fix source code" is a failure mode anyone who has shipped an agent can picture. The artifact-gate polarity flip (Figure 4b) is the paper's best single exhibit.
- **Table 1 separates accuracy damage from cost damage.** Showing that budget conflicts cost +79% wall-clock at *zero* accuracy loss is a useful corrective — most harness-evolution papers report accuracy only.
- **The SWT-Bench paraphrase finding is a standalone contribution.** Catching that an evolved harness had encoded `"implement only test cases"` as a task-type detector, and fixing it by paraphrasing, is a benchmark-hygiene lesson that applies far beyond this paper. Publishing the fix in an appendix rather than burying it is good practice.
- **Honest framing.** The authors call for attention to the problem rather than claiming a solution, disclose the reimplementation, and release code.

## Limitations

- **Tiny evaluation sets.** 50/50/30 instances, no confidence intervals, no multiple seeds — the reported deltas (especially the FeatureBench ±10 pts claim on 30 tasks) carry large uncertainty.
- **Ceiling effects.** SWT-Bench hits 100.0%, so relative forgetting there is mechanically inflated and not comparable across datasets.
- **Two-stage only.** The claim that findings extend to longer dataset sequences is an assumption, not an experiment; compounding vs. saturating forgetting is untested.
- **Single foundation model.** Everything runs on DeepSeek-V4-Flash-0731; whether a stronger or weaker evolver shows the same forgetting profile is unknown.
- **Only two evolution methods, both reimplemented.** Newer whole-harness evolvers (Self-Harness, HarnessX) and component-level evolvers (GEPA-style prompt evolution, memory/skill evolution) are named in related work but not tested — and the paper's own taxonomy suggests prompt-only evolution would exhibit mostly *workflow* conflicts, a prediction left unexamined.
- **No mitigations attempted.** No replay buffer, no component freezing, no cross-dataset Pareto retention, no regularization — the paper diagnoses but does not treat.
- **Conflict prevalence has no reliability protocol** (single annotator, 12.4% unclassified, no per-direction breakdown of the 87.1%).
- **The 0.0% verification ablation is unexplained** — plausibly a broken harness rather than a mis-filtered one, which would change its interpretation.
- **Task-type coverage is narrow.** Code repair, test generation, feature implementation — all Python-repo, all patch-graded. Doc writing, refactoring, code review, and multi-language settings are absent, and those may have very different conflict profiles.

## Relevance

直接命中「Self-Evolving Agents & Automated Research」：它讨论的正是自修改 agent 架构在长期运行中的可靠性——harness 每进化一轮就可能悄悄废掉上一轮学到的能力，这是"自进化"从单任务 demo 走向真实部署时最容易被忽略的失效模式。同时对「Agent & Pipeline Silent Failures」有交叉价值：文中那个把提交门极性写反的 artifact gate，就是一个典型的 harness 层静默篡改模型输出的例子，而且它不会报错，只会让 96% 的 agent 变成 0%。

## Questions for Further Exploration

1. **Is the 0.0% verification ablation a filtering failure or a functional failure?** Instrument the 50 SWE-Bench tasks under the injected artifact gate: how many produced a plausible patch that was rejected at submission, versus never converged within the 1-hour budget? The answer determines whether the paper's headline mechanism is "wrong artifact" or "harness deadlock."
2. **Does forgetting compound or saturate over longer sequences?** Run SWE→SWT→Feature→SWE and measure whether the third and fourth transfers cost as much as the first. The paper's induction argument is testable in a single afternoon and would substantially strengthen or weaken the framing.
3. **Would cross-dataset Pareto retention fix it?** Meta-Harness already keeps a frontier; simply evaluating candidates on *all* seen datasets and retaining only Pareto-non-dominated harnesses is the obvious baseline the paper omits. If that recovers most of the loss, the contribution shifts from "fundamental dilemma" to "engineering oversight."
4. **How much of the forgetting is task-type conflict versus prompt-template conflict?** The SWT-Bench paraphrase experiment suggests surface-form shortcuts matter a lot. Systematically varying prompt templates (same task, N paraphrases) would separate "the harness learned the wrong procedure" from "the harness learned the wrong regex."
5. **Does the taxonomy transfer to non-code agents?** Verification/workflow/budget conflicts should exist in web agents and research agents too. Is the 87.1% verification dominance a property of patch-graded SE benchmarks, or of harness evolution in general?
6. **What is the variance floor?** Re-running the same evolved harness 3–5 times at temperature > 0 on the same 50 instances would tell us whether a 94.0 → 32.0 drop is 10σ or 2σ. Without that, every number in Figure 3 is a point estimate of unknown reliability.
