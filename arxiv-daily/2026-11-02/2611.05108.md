> **一句话总结：** 作者搭了一个"持续 AutoResearch"环境，用完全配对的 stateful / stateless 两条轨迹（同任务流、同数据、同 30 分钟预算）跑五个前沿 CLI agent，在九类任务、每个 agent 32 个可迁移任务上发现：持久会话让全部五个 agent 的固定预算研究效率都提升（时间收敛增益 +3.0 到 +21.3 归一化分），但最终解质量基本不涨（−0.9 到 +7.6，只有 Sonnet 4.6 显著为正）——"能记住经验"和"会用经验"是两种能力。

> **TL;DR:** Continual AutoResearch pairs a persistent agent session against a fresh-session reset on the same ordered task stream (nine families across synthetic AutoML, symbolic regression, ETT/PEMS/energy time-series forecasting, and SELA/MLE-Bench tabular AutoML; 32 transfer-eligible tasks per agent; 30-min per-task budget; hidden private test). Against the reset baseline, mean time-convergence gain is positive for all five agents — Kimi K3 +21.3, Sonnet 4.6 +20.9, Opus 5 +7.5, GPT-5.6-Sol +6.1, GPT-5.4 +3.0 normalized points — driven mostly by reaching a first valid solution sooner (Kimi 9.5 vs 18.7 min; Sonnet 7.7 vs 16.3 min). But final outcome gain is +7.6 for Sonnet, +0.4 Kimi, +0.2 GPT-5.4, and −0.8/−0.9 for GPT-5.6-Sol/Opus 5, and the mean search advantage decays from +24.0 points at 25% of budget to +1.2 at the deadline. A card-based memory ablation on the energy-system stream shows matched insights help initialization but not final performance, and shuffled cards help just as much over no memory (+14.9 vs +14.7 for Sonnet).

## 核心贡献

- **提出 Continual AutoResearch 环境**：把"自动科研"从单题孤立评测改成有序任务流评测，用同一 agent、同一模型、同一数据、同一墙钟预算配对跑 stateful（复用原生 CLI 会话与工作区）和 stateless（每题全新会话 + 干净工作区）两条轨迹，得到同题因果对照。覆盖 4 个设定、9 个任务族：合成 AutoML（shared-latent / shared-sparse / shared-regime 各 5 题）、符号回归（canonical-coordinates 5 题，含一个反对称控制题）、时序预测（ETT 跨分辨率、PEMS 路网、能源系统）、表格 AutoML（SELA 评测子集 5 题 + MLE-Bench Lite 3 题）。
- **拆出三个互补指标**：final outcome（最终提交解的隐藏测试奖励）、initialization（第一个有效提交的奖励）、time-convergence（预算内 best-so-far 曲线归一化面积，即"多快找到多好"）。三者分开报告，正是本文最有价值的方法论贡献——只报最终分会把"更快"和"更好"混为一谈。
- **发现"效率涨、效果不涨"的解耦**：持久状态让五个 agent 全部更早拿到有效解（五个 agent 的首次有效解时间都下降，Kimi −9.2 min、Sonnet −8.6 min），且多数 agent 的有效候选数反而更少——增益不是"多试几次"堆出来的；但最终解只在 Sonnet 4.6 上有实质提升。
- **用三层控制拆穿自己的头条结论**：候选数匹配控制后 Sonnet 仍 +6.5 分，Kimi/GPT-5.4 只剩 +1.7/+1.2，Opus 与 GPT-5.6-Sol 掉到 ~0；再把每条轨迹的起点平移到自己的首个有效解（扣掉首解奖励）后，**所有 agent 的增量面积增益都转为负值**（−0.2 到 −3.2）。即：持久化改善的是"启动"，不是"启动之后的优化"。
- **显式记忆消融**：用 agent 自写的 insight cards（claim / 证据 / 置信度 / 适用范围 / 建议动作 / 失效条件）在能源流上做 matched vs shuffled vs no-memory 三条件对照，证明"内容相关"改变初始化与搜索节奏，但不稳定改善最终表现；并给出 matched cards 造成锚定（anchoring）的具体案例。
- **失败模式分类学**：从轨迹里归纳出三类跨任务失败——把早期教训过度泛化（Opus 的 safe-first 策略把探索预算压死）、在 dev 集上打磨掉真正能外推的候选（Kimi 把 hidden R²=0.593 的解优化成 hidden R²=−1.354）、以及"找到好候选但选错"（GPT-5.6-Sol 选中 RMSE 1.049 的集成，丢掉自己 4.5 分钟时找到的 0.545）。

## Key Contributions

- **An open-ended, agent-agnostic continual-research environment.** Ordered task streams whose consecutive tasks share *reusable structure* but differ in target, dataset, or sampling process, so the previous solution cannot be resubmitted verbatim — the agent must identify what transfers and re-estimate what is task-specific. Four settings / nine families, from controlled synthetic generators with known recurring structure to real ETT/PEMS/energy forecasting and SELA/MLE-Bench tabular tasks.
- **A paired stateful-vs-stateless causal design.** Same model, same task, same data splits, same wall-clock budget, same private evaluator; only the working state `s_i` differs. Runs are matched per task, so the unit of analysis is a within-task difference rather than a cross-run comparison.
- **Three-factor decomposition of "research progress".** Final reward, first-solution reward, and fixed-horizon search utility (area under the post-hoc best-so-far curve, normalized by budget). The paper's central empirical claim is precisely that these three move differently.
- **Evidence that persistence buys latency, not optimization.** All five agents get positive time-convergence; the gain survives candidate-count matching only for Sonnet (+6.5), and vanishes or inverts once first-solution reward is subtracted.
- **A controlled memory ablation plus trace-level case studies** separating "session continuity" from "semantic insight transfer", with concrete anchoring and mis-selection failure cases.

## Methodology

**Task formulation.** A stream is an ordered sequence `T = (T_1..T_K)`. Each task ships a description, train/dev data, and a fixed wall-clock budget `B_i` (30 min default). The agent may submit many candidates but must designate one final artifact; all submissions are scored on a hidden test set *after* the run, and intermediate test scores are never shown — an explicit anti-reward-hacking measure. Agents run through their native CLI harnesses (Claude Code for Sonnet 4.6 / Opus 5, Codex for GPT-5.4 / GPT-5.6-Sol, OpenCode for Kimi K3) with no harness-provided planner or memory manager.

**Stateful vs stateless.** Stateful resumes the same native session and workspace across the stream (transcript, files, experimental results, execution traces all carry over). Stateless launches a fresh session and clean workspace per task, with everything else matched. Because `T_1` has no predecessor, all transfer statistics are computed over `i = 2..K`.

**Metric normalization.** Raw metrics (accuracy, F1, RMSE, R²) are mapped to a common [0,1] scale following SELA: identity for accuracy/F1, `(1+m)^{-1}` for RMSE (standardized by train-set channel std first), and `(2 − min{m,1})^{-1}` for R². Gains are reported as `100 × (M_stateful − M_stateless)` "normalized reward points", averaged within stream then across streams (equal family weight).

**Time-convergence.** `U_{i,c} = (1/B_i) ∫_0^{B_i} max_{j: t_ijc ≤ t} r_ijc dt` — the normalized area under the best-so-far curve, set to 0 before the first valid submission and flat-carried to the budget end if a run finishes early. This jointly rewards quality and earliness; it is computed only post hoc and never shown to the agent.

**Task families.** (1) *Synthetic AutoML* — one 6000×150 feature matrix per family split 2000/2000/2000, five binary/multiclass targets each: shared-latent (24 latent factors, 6 causal, noisy 24×150 projection, targets rotating over a shared causal pool), shared-sparse (targets drawn from `x000..x007` with `x020..x029` as noisy copies, testing feature-screening procedure transfer), shared-regime (a visible regime indicator `r` whose conditional rule flips between odd/even tasks). (2) *Symbolic regression* — five equations that simplify under centering/rescaling/radial coordinates, 384 train + 384 dev + 2000 interpolation + 2000 extrapolation rows, 16 generic features, restricted expression grammar evaluated arithmetically (no LLM judge); Task 4 adds a cubic term as an asymmetric control against blindly reusing an even-symmetry assumption. (3) *Time series* — ETTm1/ETTh1/ETTh2/ETTm2 (same system, different station and sampling rate), PEMS03/04/07/08 (different sensor networks), and a heterogeneous energy stream (Electricity Hourly, Australian Electricity Demand, Solar 10 Minutes, ETTh1, ETTh2); RMSE on private chronological splits. (4) *Tabular AutoML* — SELA subset (credit-g, kick, Click_prediction_small, software-defects, smoker-status) with F1, and MLE-Bench Lite (spaceship-titanic, tabular-playground May-2022, Dec-2021) with accuracy/ROC-AUC under competition submission protocol.

**Anonymization.** Dataset names are replaced with neutral identifiers during evaluation so agents cannot recall a known leaderboard solution from memory.

**Memory ablation.** Every task starts a fresh session; information passes only through agent-authored insight cards. Three conditions: matched (cards from earlier tasks in the same stream), shuffled (same number of cards from an unrelated stream), no-memory (no cards).

## Results & Highlights

- **Time-convergence is positive for all five agents, but the spread is 7×.** Mean gain over 32 transfer tasks: Kimi K3 **+21.3** [+27.5 median], Sonnet 4.6 **+20.9** [+20.6], Opus 5 **+7.5** [+10.3], GPT-5.6-Sol **+6.1** [+7.4], GPT-5.4 **+3.0** [+2.0] normalized points (Table 2). Note the baseline is the agent's own reset run, not another model: Opus 5 has the highest *absolute* reset outcome (79.9 vs 70.3 for Sonnet), so "gain" and "quality" rank differently.
- **The efficiency advantage is front-loaded and mostly gone by the deadline.** Best-hidden-reward gap at budget checkpoints: **+24.0** points at 25%, **+15.7** at 50%, **+6.5** at 75%, **+1.2** at 100% (Table 8). Only two agents stay positive at 100% — Sonnet +6.9 and Kimi +1.7; Opus −0.8, GPT-5.6-Sol −1.2, GPT-5.4 −0.5. Reset agents largely catch up through within-task search.
- **Final-outcome transfer is weak and mostly indistinguishable from zero.** Outcome gain: Sonnet 4.6 **+7.6**, Kimi K3 **+0.4**, GPT-5.4 **+0.2**, GPT-5.6-Sol **−0.8**, Opus 5 **−0.9**. Outcome win rate spans **34.3%** (Opus — i.e. persistence *loses* on two thirds of tasks) to **66.7%** (Sonnet). On Opus's shared-sparse family the win rate is **0.0%** with −3.5 points, and on MLE-Bench its time-convergence is **−44.5** points.
- **The mechanism is latency, not better optimization.** Time to first valid solution, stateful/reset: Kimi **9.5/18.7 min**, Sonnet **7.7/16.3**, Opus **7.7/11.1**, GPT-5.4 **8.4/9.2**, GPT-5.6-Sol **6.1/8.5** (Table 7). Valid candidate counts are *lower* stateful for four of five agents (e.g. GPT-5.6-Sol 6.7 vs 11.8), so the gain is not "more attempts". Under candidate-count matching the gain drops to Sonnet +6.5, Kimi +1.7, GPT-5.4 +1.2, GPT-5.6-Sol +0.1, Opus −0.5; after also subtracting each run's first-valid reward, incremental area gain is **negative for all five** (−0.2 to −3.2, Table 10).
- **Matched memory helps initialization but not outcomes — and "any card" beats "no card".** On the four transfer-eligible energy tasks, matched-minus-shuffled init gain: Opus **+2.6**, GPT-5.4 **+5.9**, GPT-5.6-Sol **+3.9**, Sonnet **−2.9**; but time-convergence matched-minus-shuffled is **−15.5** (Opus) and **−27.3** (GPT-5.6-Sol) while Sonnet is **+25.6**. Matched-vs-no-memory outcome gains are +14.7 (Sonnet) and +5.0 (GPT-5.4), yet shuffled-vs-no-memory gives **+14.9 and +4.8** — semantically irrelevant cards do just as well, so relevance is not what drives the improvement.
- **Stream length saturates, then hurts.** GPT-5.4 on a common Weather task: 3/5/7 prior tasks give init gain **+3.56 / +5.53 / +5.34**, time-convergence **−1.75 / −3.61 / −31.44**, outcome **−1.82 / −0.05 / −0.27** (Table 11, one run per condition). Final RMSE first/selected: 0.432/0.427, 0.393/0.392, 0.396/0.396 — i.e. the selected solution barely beats the first solution in every condition.
- **Persistence can reduce operational failures, but not uniformly.** Failure fraction on transfer tasks drops 30.7% → 7.7% for Sonnet and 11.4% → 1.8% for Kimi, but *rises* 1.7% → 8.3% for GPT-5.6-Sol (Appendix B.3).
- **Aggregates hide family-level reversals.** Sonnet's symbolic-regression outcome gain is **+41.2** and energy-system **+18.5**; Kimi's symbolic is **−10.9**; GPT-5.4's traffic-network time-convergence is **−29.2**; Opus's energy-system outcome is **−6.6**. Symbolic regression overall has mean **+5.2** but median **−2.9** — the mean is one agent's win.

Jeremy Qin (RBC Borealis; work done during an internship there, also ELLIS Tübingen / MPI-IS Tübingen AI Center), Ruizhi Deng, Mohamed Osama Ahmed, Frederick Tung, and Leo Feng — all RBC Borealis (the bank's Montreal AI research lab). The group publishes on efficient ML, AutoML and agentic evaluation; Tung is a well-known name in continual learning and efficient inference. This is a benchmark/evaluation paper from an industrial research lab rather than a frontier lab, which fits the artifact: no new model, no training, but substantial engineering (five agent harnesses, private evaluators, four task domains, anonymized streams). Credibility signals are good: a Reproducibility Statement promising code at camera-ready, a 27-page appendix with the exact synthetic generators (latent-factor scales, coefficients, noise stds, splits), a stated ethics/AI-use disclosure, and — unusually — a run-to-run variability check (three repeats for GPT-5.6-Sol) plus four progressively stricter controls that argue *against* their own headline. The paper is honest about the model/scaffold confound. The main credibility caveat is that most numbers come from a single matched run pair per model, and the authors say so.

## Critical Assessment

**Novelty.** The framing is a real gap: autoresearch benchmarks (PostTrainBench, InferenceBench, AutoLab, Claudini) all reset the agent per problem, and continual-learning benchmarks for agents (ExpeL, LifelongAgentBench, Continual Learning Bench, AgentCL, SWE-Bench-CL) do not use an *executable, iterative ML research loop* as the unit of transfer. Combining the two is a legitimate contribution, and the stateful-vs-stateless pairing is the right causal design. It is an evaluation paper, not a method paper — the intellectual payload is the metric decomposition, and that part is genuinely useful.

**Rigor — strong where it matters, thin where it is cheap to be thin.** The three-way metric split plus the candidate-matched, post-first-latency, and first-reward-subtracted controls (Table 7/10) is exactly the ablation most benchmark papers skip; the authors use it to demolish their own "+21.3 points" headline down to "negative for all agents". That is commendable. But the statistical base is one matched run pair per model for four of five agents. They report GPT-5.6-Sol's three-repeat variability as "at most 0.75 points" for outcome/init and "at most 7.14" for time-convergence — which means the reported outcome gains of −0.9, −0.8, +0.4, +0.2 for four agents are **inside their own noise band**, and GPT-5.4's +3.0 time-convergence is under half the 7.14 noise. The paper's *negative* finding ("gains do not consistently translate to final performance") is thus a null result presented without confidence intervals, while the *positive* finding ("improves efficiency of all five") leans on means that two agents barely clear the noise floor. Both directions deserve error bars; only one agent got them.

**A normalization choice that quietly does the work.** The reward transform `(1+m)^{-1}` for RMSE and `(2−min{m,1})^{-1}` for R² is monotone but strongly non-linear and compressive near the top. A 0.05 RMSE improvement at RMSE≈0.4 is worth far more points than the same absolute improvement at RMSE≈2.0, and R² values below 0 get squashed toward 0 (Kimi's hidden R²=−1.354 maps to ≈0.30, while 0.593 maps to ≈0.71). Because aggregate "reward points" are then averaged with equal family weight across RMSE, F1 and R² tasks, the paper implicitly assumes an interval scale it has not established. Family-level cells like Opus's −44.5 on MLE-Bench and Sonnet's +41.2 on symbolic regression are partly artifacts of where each task sits on this curve. A rank-based or per-task-z-scored aggregate would be a cheap robustness check and is absent.

**The 30-minute budget makes "research efficiency" partly "environment warm-up".** Time-to-first-valid-solution differences of 9–11 minutes are a third to a half of the entire budget, and much of what stateful agents reuse is boilerplate: package installs, data loaders, a working DLinear/NLinear/iTransformer pipeline (Appendix C.1 is literally "I can reuse the exact same code"). The authors' own budget ablation (15/30/60 min on Shared Regime) shows the advantage shrinking as budget grows, which they interpret as reset agents catching up — but it is equally consistent with the advantage being setup-latency amortization that vanishes once setup is a small fraction of the budget. A "copy the previous task's final artifact, then adapt" stateless baseline — which would isolate pure code reuse from insight — is missing and would be the single most informative control.

**The memory ablation is one stream, four tasks, and its own numbers undercut the framing.** Matched vs shuffled vs none on the energy stream is 4 transfer tasks × 4 models, with cells like "matched-minus-shuffled time-convergence −27.3" and checkpoint values swinging from −51.8 to +3.0 (Table 13). With n=4, these are anecdotes with error bars drawn from noise. More importantly, the paper reports that shuffled cards give Sonnet +14.9 and GPT-5.4 +4.8 over no memory, essentially identical to matched cards' +14.7 and +5.0 — so the "matched vs no-memory" contrast measures *having any structured card at all*, not relevance. The authors admit this ("does not establish a semantic-relevance benefit"), which is honest, but it leaves the section's stated purpose — separating insight transfer from session continuity — only half-achieved. Separating transcript-only, code-only, and insight-only conditions is explicitly deferred to future work.

**Anonymization is weaker than claimed.** Section A.1 says neutral identifiers prevent agents from recognizing ETTh1 or PEMS07. But the memory cards themselves re-identify the dataset: Appendix C.3 quotes a card reading "this exact dataset (7-channel hourly energy, 8640 train rows)". Feature counts, channel counts and row counts are enough to fingerprint most public benchmarks. This does not invalidate the stateful-vs-stateless comparison (both arms see the same leak), but it does mean "first-solution quality" may include recall of published leaderboard solutions, and the claimed anti-shortcut protection is partial.

**The time-convergence metric has an early-finish bias.** `U` is set to zero before the first valid submission and flat-carried to `B_i` if a run ends early. Both conventions reward finishing early *twice*: once by starting the integral later, once by not being penalized for the idle tail. Since stateful runs are exactly the ones that finish early (fewer valid candidates for four of five agents), part of the measured "efficiency" is an artifact of the metric's treatment of idle time. A per-unit-time normalization that penalizes unused budget, or reporting utility only over the active window, would separate "faster" from "quits sooner".

**Overclaiming, mild.** "To our knowledge, the first study of a continual AI R&D setting" is defensible given the citations, but Continual Learning Bench and AgentCL already test stateful cross-task behavior in executable environments; the delta is the ML-research loop, and the abstract would be stronger saying so. The Discussion's leap to "provenance tracking, explicit applicability conditions, evidence-based memory revision" as safeguards is reasonable but is motivated by three hand-picked trace figures that the authors themselves label "selected for interpretability… not a systematic or causal decomposition". Also worth flagging: the Opus MLE-Bench case study (Figure 17) admits "host contention also affected this stream, so the timing gap cannot be attributed to memory alone" — an uncontrolled confound sitting inside a headline failure example.

**What is genuinely good.** The paired design, hidden intermediate scores, dataset anonymization attempt, post-hoc curve construction, and the four-tier control ladder are better methodology than most agent benchmarks ship with. The negative result is the interesting one and it is reported clearly rather than buried: the decomposition into "reach a valid solution sooner" vs "optimize better after initialization" is a clean, falsifiable distinction, and Table 10's uniformly negative incremental area gain is the paper's most convincing single table.

## Strengths

- **The right control ladder.** Candidate-count matching, post-first-latency truncation, and first-reward subtraction progressively remove exactly the confounds a skeptical reader would raise, and the authors follow the evidence to a conclusion that weakens their own abstract.
- **Metric decomposition that generalizes.** Splitting outcome / initialization / time-convergence is reusable well beyond this benchmark; "process-level evaluation" is the correct lesson for agent evaluation generally.
- **Paired within-task design** with matched data, budget, evaluator, and model — the strongest feasible causal setup when full retraining is off the table.
- **Anti-gaming hygiene**: hidden intermediate test scores, post-hoc curves never shown to the agent, neutral dataset identifiers, private interpolation *and* extrapolation splits for symbolic regression, arithmetic expression evaluation instead of an LLM judge.
- **Nine task families spanning controlled synthetic generators to real AMLB/Kaggle/MLE-Bench data**, with the full generator specification (coefficients, noise scales, splits) in the appendix — rare and valuable for reproduction.
- **Failure taxonomy grounded in traces**: over-generalized operational lessons, dev-set overfitting that destroys extrapolation, and correct-candidate-wrong-selection are three distinct, actionable failure modes, each with a concrete trajectory.
- **Honest reporting of heterogeneity** (Figure 8's per-agent × per-family grid, mean-vs-median divergence in symbolic regression) rather than a single flattering average.

## Limitations

- **Single run pair for four of five agents**; the one repeated condition (GPT-5.6-Sol, 3 repeats) shows ±7.14 points of time-convergence noise, larger than two agents' headline gains. No confidence intervals on any aggregate.
- **Model and scaffold are confounded**, as the authors acknowledge: Claude Code vs Codex vs OpenCode differ in context management, compaction, and tool affordances, and each model is tested on exactly one scaffold. "Persistence helps Kimi most" cannot be separated from "OpenCode's session resumption is the most faithful".
- **Short streams and short budgets**: 3–5 tasks per stream, 30 minutes per task. Nothing here tests the regime the paper's motivation invokes — hundreds of tasks, or 10-hour post-training jobs (PostTrainBench scale), where compaction and memory decay would dominate.
- **Memory ablation is underpowered and single-domain** (energy stream, 4 transfer tasks); no separation of transcript vs code vs insight vs execution state.
- **No "reuse previous artifact" baseline**, so pure code reuse and genuine insight transfer remain entangled; nor is there a "stateless with K× budget" baseline to test whether persistence is just a compute multiplier.
- **Normalization is ad hoc and unvalidated**; cross-family averaging assumes an interval scale the transform does not obviously provide.
- **Reward scale is coarse and family-imbalanced in practice**: 32 transfer tasks total, with families contributing 2–4 tasks each, so one bad task can move a family cell by tens of points (Opus's MLE-Bench −44.5 rests on 2 tasks).
- **No adversarial or provenance threat model**, despite the Discussion raising it; the "misleading content injected in one task persists into later tasks" risk is asserted, not measured.
- **Selection regret is measured but only in aggregate** (−0.7 to +1.3 points), while individual tasks show 41.3-point regret — the tail risk is acknowledged in a figure but not quantified as a distribution.

## Relevance

直接命中"自演化智能体与自动化科研"这条主线：它问的正是自演化系统最核心的假设——跨任务积累的经验到底能不能变成能力，并给出了一个干净的否定性/条件性答案（提速可以，提质不行），对设计长期运行的 research agent 与其记忆机制很有参考价值。同时它对"长时自治系统的可靠性"也有直接意义：失败模式（过度泛化教训、dev 集过拟合、选错最终候选）和"过程指标必须与结果指标分开评"的结论，都可以直接搬到任何持续运行的 agent pipeline 评测里。

## Questions for Further Exploration

1. How much of the time-convergence gain survives a **"copy the previous task's final artifact and adapt"** stateless baseline? That control would separate boilerplate reuse (pipelines, loaders, package setup) from insight transfer, and it is the missing experiment that decides how to read the whole paper.
2. Does persistence still help when the per-task budget is 2–10 hours rather than 30 minutes? The 15/30/60-minute ablation suggests monotone decay; does the sign ever flip, and at what horizon?
3. Why does Sonnet 4.6 transfer and Opus 5 not, when Opus has strictly higher absolute reset performance (79.9 vs 70.3)? Is it capability saturation ("less room to gain"), a scaffold difference in session resumption fidelity, or a policy difference in how aggressively each agent re-verifies inherited assumptions?
4. What does the *distribution* of selection regret look like per task, not just its mean? Kimi's 41.3-point single-task regret suggests a heavy tail that an aggregate mean of −0.7 completely hides.
5. Would a "portfolio of structurally distinct candidates + extrapolation-robustness selection objective" (the fix the authors propose in Appendix D.1) actually convert Sonnet-style efficiency gains into outcome gains? That is a testable intervention, not just a recommendation.
6. Does the memory-ablation conclusion change with more tasks? Matched vs shuffled on 4 tasks cannot distinguish "relevance doesn't help" from "relevance helps on 2 of 4 tasks in opposite directions"; a 20-task energy stream with per-task breakdown would settle it.
7. How do these results scale to multi-agent research teams, where knowledge spreads through a topology rather than a single session? The authors flag this as future work but it is arguably the more realistic deployment setting.
