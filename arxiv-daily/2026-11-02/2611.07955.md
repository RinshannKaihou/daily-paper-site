> **一句话总结：** 论文指出旋转/平滑类 PTQ 方法在数学上都是"逐 token 同一变换"的重参数化群元素，因此只能带来共模 SNR 增益、无法改变特殊 token 与 patch token 之间的相对信噪比；作者据此为 MapAnything 这类前馈度量几何 Transformer 设计 QMapAnything——用随机 Hadamard 旋转处理通道重尾、用标准 bias 校正处理共性偏移、只在全局块上对 scale token 那一行加选择性仿射项，并用一个只需一次前向+一次反向的筛查统计量 Γ 判断是否需要该行选择项。W4A4 两视图平均 pose AUC@30° 从 QuaRot 的 88.0 提到 92.8，而 W4A8 下与全精度基本持平（98.6 vs 98.9）。

> **TL;DR:** Rotation-based PTQ (QuaRot, SpinQuant, SmoothQuant) applies the *same* linear map to every token row, so it buys a common-mode SNR gain but provably cannot change any pairwise token-norm ratio (Prop. 1) — the group has no row-indexed degree of freedom at all (Lemma 1). That matters for feed-forward geometry Transformers because MapAnything's single scale token `h_s` carries the global metric factor `m` multiplicatively (`‖X̂−X‖/‖X‖ = |m̂−m|/m` for *every* pixel), shares one per-tensor activation grid with `N·n` patch tokens whose range is ~6× larger (`1/κ_s = 6.02`, deficit growing two orders of magnitude with depth), and is written by only the 8 global blocks (S4). The paper turns this into Γ = (λ_s/λ̄_patch)·(max_t‖h_t‖/‖h_s‖ − 1), a pre-quantization screen costing one forward + one backward per scene: Γ = 1.35×10⁵ for MapAnything vs exactly 0 for VGGT (high leverage, no grid disadvantage, `1/κ_s = 0.94`) and DA3 (grid disadvantage, no leverage, `λ_s = 0`). The resulting recipe — RHT rotation + token-uniform bias β + a single-row affine term `b_s` inserted only in global blocks — reaches **92.8 vs 88.0 AUC@30° for QuaRot (+4.8) at W4A4, 2 views**, averaged over ETH3D/ScanNet++v2/TartanAirV2-WB; at 16 views the margin is +2.8 (86.5 vs 83.7) but the gap to FP32 widens from 6.1 to 12.3 points, exactly as S1 predicts. The falsification test is the best part: instantiating `b_s` on VGGT/DA3 where the audit says omit it changes AUC by −0.02 and +0.04, versus +3.2 on MapAnything. Caveat for deployment: all accuracy is W4A4 *fake* quantization, and all measured memory/latency is W8A8 (2.2–3.1× memory, 0.32× FP32 latency), where the honest comparison is BF16/AMP at 0.52× and 98.7 AUC.

## 核心贡献

- **把"旋转/平滑"重新定义为一个群，并证明它的天花板。** 所有保持浮点映射不变的重参数化写成 `x′=(x+a)M, W′=M⁻¹W, b′=b−aW`（`M∈GL(d)`）。关键在于 `M` 是右乘、`a` 是广播行向量，所以**整个群没有"按行索引"的自由度**（Lemma 1）。Prop. 1 给出：正交旋转后 `SNR_{Δ_R}(t) = (Δ/Δ_R)²·SNR_Δ(t)` 对所有 token 成立，任意两个 token 的 SNR 比值完全不变；增益上界 `(Δ/Δ_R)² ≤ d`。因此 `κ_s = ‖h_s‖₂/max_t‖h_t‖₂` 是**学到的表示本身的属性，不是正交基的属性**——这句话是整个方法的立论基础。
- **把"特殊 token 有害"拆成两个可独立测量的轴（S1–S4）。** S1 共享量化栅格（`b_eff(t) = b − log₂(1/ρ_t)`，类型级 range ratio 随深度增长两个数量级，scale token 在部署位宽下只剩不到 1 bit）；S2 单 token 的**乘性、全局**杠杆（不是"梯度集中"，而是误差直接乘到所有输出上）；S3 通道能量重尾（旋转本来就是为了这个）；S4 稀疏路由（frame block 直通 scale token，只有 global block 更新它，插入点减半）。论文反复强调 S1 是"脆弱性"、S2 是"后果"，两者**独立且必须同时成立**才产生差异化退化——这也是它能把 MapAnything 与 VGGT/DA3 分开的原因。
- **Γ：一个免量化、免 benchmark 的筛查统计量。** `Γ = (λ_s/λ̄_patch) · max(max_t‖h_t‖/‖h_s‖ − 1, 0)`，即"输出关键性 × 差异化栅格劣势"，只需一个 scene 的一次前向+一次反向。三个模型的取值把结论一刀切开：MapAnything 1.35×10⁵、VGGT 0、DA3 0。作者明确声明它是 screening statistic 而非 calibrated error bound，并配了第二个统计量 `η_{s|β} = ‖E[r_s]‖²/E‖r_s‖²` 来检验"仿射校正到底能不能补回来"（Prop. 3 给出仿射校正的精确收益 `(1−η)E‖e‖²`）。
- **机制与性质一一对应，而不是堆 trick。** S3→RHT 旋转（App. C 证明在恒等/DCT/固定 Hadamard/Haar/RHT 五者中 RHT 最强，且把"群能达到的上限"定在 86.9）；S1+S2→行选择仿射项 `b_s`；S4→只插在 8 个 global block，且是单行 `O(m_ℓ)` 加法、不改整数 GEMM；共性偏移→可折叠进 layer bias 的 β。总存储 `|B_g|(5d+2d_ff)` 个标量。
- **一个真正做对的证伪实验。** 在 VGGT 与 DA3 上，尽管 audit 说应当省略 `b_s`，作者仍**故意把完整的 B 装上**做保守检验：结果 `b_s` 的贡献是 −0.02 与 +0.04，而 β 贡献 +3.11 与 +4.09。这分离了"通用 bias 校正"与"行选择校正"，也说明 Γ 预测的是后者而非前者。
- **评估协议上的一个正确决定：指标分两族报告。** metric 族（scale 相对误差、ATE）与 up-to-scale 族（点图/深度相对误差、τ、AUC@30°、ray error）分开列表，使得 `m` 崩塌不会被尺度对齐后的漂亮分数掩盖——这正是 S2 的可检验预言。

## Key Contributions

- **A negative result with teeth.** Floating-point-preserving rotation and smoothing form a token-blind reparameterization group; Prop. 1 shows the gain is common-mode and the pairwise SNR ratio is invariant, Prop. 2 bounds what a general ill-conditioned `M` could do by `cond(M)` (at the cost of `W′=M⁻¹W` conditioning), and Lemma 1 proves no element of the group can condition on token identity. This is a clean explanation of *why* the whole rotation family plateaus on this model class, not just an empirical observation that it does.
- **A four-property audit (S1–S4) that is measurable before quantization**, with an explicit measurement protocol in App. B: S1 from the deployment config plus the type-level range ratio, S2 from the output factorization (deliberately *not* from gradient magnitude), S3 from the per-token max/P99 channel ratio, S4 by checking which blocks actually change `h_s`.
- **Γ, a one-forward-one-backward screen** that separates "needs token-selective treatment" from "needs only common-mode treatment", plus `η_{s|β}` to test whether the affine remedy is materially recoverable rather than merely well-motivated.
- **QMapAnything**, the instantiated recipe: RHT rotation folded offline into `W`, token-uniform bias correction, and a single-row affine term applied only at the 8 global blocks — a correction that leaves the integer GEMM untouched.
- **A transfer study on two models the method was not designed on** (VGGT, DA3), run with the *same* quantizer, granularity, rotation construction, calibration source and W4A4 setting, where the audit's prediction (omit `b_s`) is confirmed by deliberately violating it.
- **A quantified explanation of why token-averaged calibration losses miss this failure mode**: on held-out folds, fitting `(β, b_s)` cuts scale-token MSE by 34.2% while whole-block MSE moves by 0.010%.

## Methodology

**Host model and quantization scope.** MapAnything predicts a factored representation `{m, (R_i, D̃_i, P̃_i)}`: a frozen DINOv2 backbone produces `n` patch tokens per image, a learnable scale token `h_s ∈ R^{1×d}` is appended, and a 16-layer alternating-attention Transformer interleaves frame blocks (within-view) with global blocks (cross-view); DPT and pose heads decode patch tokens into up-to-scale geometry while a 2-layer MLP on the final scale token regresses `m`, with `X_i^metric = m·X̃_i`. PTQ covers the four linear maps per block (QKV, attn.proj, mlp.w12, mlp.w3) — 64 modules for MapAnything, 192 for VGGT, 160 for DA3 — with per-output-channel weight scales and a **per-tensor static activation scale** (so all token rows share one grid by construction). Multi-modal encoders, LayerNorm, softmax, DPT/pose heads and the scale MLP stay in floating point. Calibration minimizes block-wise output reconstruction error `‖F(W,X) − F(Ŵ,X̂)‖²` over 64 two-view 518×518 samples from the MegaTrain mixture (BlendedMVS, MPSD, ScanNet++v2, Spring, TAV2-WB, UnrealStereo4K), **with no ETH3D scenes**, so ETH3D doubles as a cross-dataset test.

**The theory in four steps.** (i) Every rotation/smoothing method is an element of `x′=(x+a)M, W′=M⁻¹W, b′=b−aW`; `M` right-multiplies every row identically and `a` broadcasts, so the group commutes with row relabelling — hence zero row-indexed freedom. (ii) Under the high-resolution proxy `SNR_Δ(t) = ‖h_t‖²/(dΔ²/12)`, orthogonality gives `‖h_tR‖ = ‖h_t‖`, so the proxy scales by `(Δ/Δ_R)²` for every token and all pairwise ratios are invariant; the bound `(Δ/Δ_R)² ≤ d` follows from `‖x‖_∞ ≥ ‖x‖₂/√d`. (iii) A general `M` can move the ratio only within `[cond(M)⁻¹, cond(M)]`, and an ill-conditioned `M` degrades `W′` — a trade-off the authors explicitly decline to overclaim as a hard theorem. (iv) Prop. 3: with `e = ē + ε`, the optimal constant correction is `c = ē`, worth `(1−η)E‖e‖²` where `η = ‖ē‖²/E‖e‖²`; a token-uniform correction removes only `‖E_t[ē_t]‖²`, leaving the type-specific residual `ē_s − E_t[ē_t]` — the exact quantity `b_s` targets.

**From diagnosis to mechanism.** Γ multiplies output criticality `λ_s/λ̄_patch` (with `λ_t = ‖∂L/∂h_t‖₂`) by the differential grid deficit `max_t‖h_t‖/‖h_s‖ − 1`, both measured on FP checkpoints. Neither factor alone is sufficient: high leverage with matched norms (VGGT) is just dedicated-head routing and exists in FP too; a small norm that the output path never reads (DA3) is harmless. Rotation is instantiated as a randomized Hadamard transform `R = DH` with head-sized blocks (as in QuaRot) and a full transform on the FFN hidden axis, `RᵀW` folded offline so the online transform remains only at QKV and the two FFN projections. The correction is `B(H) = Uβᵀ + u_s b_sᵀ`, applied after all four linear maps for β and, per S4, only in the global-block set `B_g` for `b_s`. On MapAnything the biases are further refined with Adam (lr 1e-4, 40 steps, three stages: blocks 0–7, 8–11, 12–15); on VGGT/DA3 they are closed-form over three rounds of 32 samples with no gradient refinement.

**Evaluation design.** ETH3D, ScanNet++v2, TartanAirV2-WB, macro-averaged, at `N=2` and `N∈{8,16}` views with the official MapAnything sampling; main tables images-only. Baselines are RTN, SmoothQuant and QuaRot **re-implemented on MapAnything** with identical quantized layers and calibration data — justified by Sec. 3.3, since all three are elements of the same group, so the comparison tests the group ceiling rather than implementation quality. Efficiency is measured on a single H20 (96 GB) with TensorRT 10.8.0.43 for latency/peak memory, while accuracy uses PyTorch fake quantization.

## Results & Highlights

- **W4A4 camera pose, macro-averaged over ETH3D/SN++v2/TAV2 (AUC@30° ↑), 2 views: 92.8 vs 88.0 for QuaRot (+4.8)**, vs 98.9 full precision. At 8 views 87.4 vs 84.8 (+2.6) and at 16 views 86.5 vs 83.7 (+2.8). The *absolute* gap to FP32 grows monotonically with view count — 6.1 → 11.8 → 12.3 points — which is the paper's own S1 prediction (more patch tokens compete for the shared absmax, further starving the scale token) and is the most convincing single piece of evidence in the paper, because it is a trend the method was not tuned to produce.
- **W4A4 two-view reconstruction, macro-averaged over the three datasets: scale relative error 0.12 vs 0.20 (QuaRot) and 0.05 (FP); point-map inlier τ 43.4 vs 33.2 (QuaRot) and 60.3 (FP); ATE 0.02 vs 0.05 (QuaRot); depth τ 41.0 vs 34.5; ray error 0.45° vs 0.71°.** The metric-family errors (scale 0.12, ATE 0.02) degrade proportionally more than the up-to-scale family (point τ 43.4/60.3 = 72% of FP), exactly the differentiated-degradation signature S2 predicts — and the reason a scale-aligned-only benchmark would have scored this method as nearly lossless.
- **W4A8 is a tie, not a win.** Pose AUC@30° at 2/8/16 views: QMapAnything 98.6/98.6/98.1 vs QuaRot 98.5/98.5/98.1 vs FP 98.9/99.2/98.8. Two-view reconstruction at W4A8: scale 0.05 vs 0.05, point τ 59.2 vs 59.1, ray 0.19 vs 0.22. So the abstract's "W4A8 closely matches full precision" is true but is equally true of plain QuaRot — the contribution is specifically a W4A4 story, and the paper is honest enough to show the numbers that make this visible.
- **Component ablation, W4A4 two-view AUC@30° (Table 3).** On ETH3D: naive 77.0 → +R 83.7 → +R+β 88.2 → +R+β+b_s **91.4**. On SN++v2: 74.3 → 86.9 → 90.4 → **93.7**. On TAV2: 64.0 → 86.1 → 89.4 → **93.2**. Adding `b_s` on top of `R+β` is worth +3.2/+3.3/+3.8 across all three datasets, and `R+b_s` without β (87.3/88.5/89.1) is *worse* than `R+β` — so the two corrections remove genuinely distinct residual components rather than one subsuming the other. Rotation alone accounts for the largest single jump (+6.7 to +22.1 depending on dataset), consistent with S3 dominating the error budget.
- **The group ceiling is located empirically (App. C, SN++v2, W4A4, bias disabled): identity 74.3 → DCT 84.2 → fixed Hadamard 85.7 → Haar random 86.0 → RHT 86.9.** Orthogonality alone buys 9.9 points, exact block-flatness adds only 1.5, random de-alignment adds 1.8, and only all three together reach 86.9. The subsequent +6.8 from the combined correction B (to 93.7) is the paper's cleanest argument that additive correction is *complementary* to maximal rotation rather than a substitute for it.
- **Cross-model falsification (W4A4, two-view ETH3D pose AUC@30°).** VGGT: FP 88.36, naive 68.42, +R 75.9, +R+β 79.01, +R+β+b_s **78.99** (`b_s` = −0.02). DA3: FP 90.33, naive 71.1, +R 77.12, +R+β 81.21, +R+β+b_s **81.25** (`b_s` = +0.04). MapAnything: FP 98.9, naive 77.0, +R 83.7, +R+β 88.2, +R+β+b_s **91.4** (`b_s` = +3.2). The audit's Γ is 0 / 0 / 1.35×10⁵ respectively, and the `b_s` deltas track it. Rotation restores VGGT and DA3 to 85.9% and 85.4% of their FP AUC; β adds +3.11 and +4.09.
- **Efficiency (W8A8, real TensorRT kernels).** Peak memory vs FP32: 2.9× at 2 frames, 2.7× at 8/16/24/32, **3.1× at 50 frames, 2.2× at 100 frames** — the ratio contracts because FP components and intermediate buffers scale with `N·n+1`, so the headline 3.1× is at 50 frames while the deployment-relevant 100-frame case gives 2.2× (FP32 already occupies 88% of the H20 there). Latency on two-view TAV2 at 518×518: **0.32× FP32 with AUC 98.9 (fully restored), vs naive INT8 at the same 0.32× but only 91.9, and vs BF16 AMP at 0.52× and 98.7.**
- **Held-out diagnostic (App. D), the paper's sharpest single number.** Fitting `(β, b_s)` on one half of the calibration scenes and evaluating on the other reduces scale-token MSE by **34.2%** while moving directly measured whole-block MSE by **0.010%**. Median `η_{s|β}` = 0.311 (IQR 0.187), energy-weighted 0.387. In other words, a third of the error on the one row that multiplies the entire metric output is systematically predictable yet invisible to any token-averaged reconstruction objective — a concrete, transferable warning for PTQ calibration design beyond this paper.

## Critical Assessment

**Novelty.** The framing is the contribution, and it is a good one: "rotation is token-blind" is a one-sentence reframing that retroactively explains a pile of empirical results, and Lemma 1 (a row-uniform map commutes with row relabelling, hence cannot condition on token identity) is the right abstraction. But the individual pieces are less novel than the abstract implies. Prop. 1 is a two-line norm-preservation argument — orthogonality preserves `‖h_t‖`, therefore ratios are invariant — and calling it a "proof" of a structural criterion is a mild inflation. Prop. 2 is the standard `σ_min‖h‖ ≤ ‖hM‖ ≤ σ_max‖h‖` sandwich. Prop. 3 is the bias–variance decomposition of the mean, i.e. "subtract the average error." What is genuinely new is not the mathematics but the *composition*: noticing that S1 (shared grid) and S2 (multiplicative leverage) are independent axes, that only their conjunction produces differentiated degradation, and that this conjunction is cheaply measurable via Γ. That is a real contribution and the paper should probably lead with it more confidently rather than dressing it in propositions.

**Rigor.** Two things are done very well. First, the falsification design: applying the full `B` to VGGT and DA3 where the audit prescribes omission, and reporting −0.02/+0.04, is exactly the experiment a skeptical reviewer would ask for, and it was run pre-emptively. Second, the metric/up-to-scale split is a methodological choice that makes the S2 prediction falsifiable rather than rhetorical — and the predicted asymmetry does appear (scale error 0.12 vs FP 0.05, i.e. 2.4× worse, while point inlier τ retains 72% of FP). The view-count trend in Table 1 (gap 6.1 → 11.8 → 12.3) is likewise a prediction the authors did not tune for.

But the statistical hygiene is thin. Every number is a single point estimate: **one rotation seed (seed 0)**, no confidence intervals, no repeated calibration draws. The ablation deltas (+3.2 to +3.8) are large enough to survive noise, but the W4A8 rows where QMapAnything "beats" QuaRot by 0.1 (98.6 vs 98.5) are not distinguishable from zero, and the paper does not claim otherwise — though the abstract's "W4A8 closely matches full-precision performance" reads more strongly than a tie with an existing method warrants.

**The most serious weakness: no comparison to the geometry-specific PTQ baselines.** The paper names QuantVGGT (Feng et al., ICLR 2026), QVGGT (Pan et al., CVPR 2026) and FGQ (Zhang et al., 2026) in related work, describes their mechanisms accurately (rotation + smoothing + fine-grained activations; mixed precision + token filtering + PCA compensation; diagonal Fisher affine calibration), and then compares only against RTN, SmoothQuant and QuaRot — three methods the authors themselves re-implemented. The stated justification is elegant: by Sec. 3.3 all three are elements of Eq. (5), so the comparison isolates the group ceiling rather than implementation quality. That is a valid *scientific* control but not a valid *competitive* one. A reader deciding what to deploy learns that QMapAnything beats a rotation-only recipe by 4.8 AUC, but not whether it beats FGQ — which, being Fisher-guided affine calibration, is conceptually the nearest neighbor to the `b_s` idea and might capture much of the same residual. The 4.8-point margin could shrink substantially against that baseline, and the omission is the single thing most likely to change a practitioner's decision.

**A second, subtler protocol asymmetry.** MapAnything's biases get a 40-step Adam refinement over three block stages; VGGT and DA3 get closed-form estimation over three rounds of 32 samples, no gradient refinement. The paper frames this as "no accuracy-driven tuning is performed on either transfer model," which is a fair guard against overfitting the transfers — but it confounds the headline transfer result. When `b_s` yields −0.02 on VGGT, is that because Γ = 0 correctly predicts no need, or because a closed-form single-row correction without refinement is too weak to help? The theory says the former, and the fact that β (also closed-form) *does* help by +3.11/+4.09 is decent evidence that the closed-form estimator is not simply broken. But a clean test would apply the same closed-form protocol to MapAnything and show `b_s` still helps there; that number is not reported. As written, the transfer experiment varies two things at once.

**Where the audit gets circular.** DA3's `λ_s = 0` is reported to four significant figures as a discovered property, but App. B reveals it is definitional: leverage is evaluated "on the same output path used at test time (for DA3 this is the dense-ray pose path, on which the camera token is not read)." So DA3 is assigned zero leverage because the chosen evaluation path bypasses its camera token. That is a legitimate modeling choice if you accept that dense-ray pose is how DA3 is actually deployed — but it makes S2 a property of the *evaluation protocol*, not purely of the architecture, and a different downstream head could flip the audit. The paper is commendably explicit about this in the appendix but does not carry the caveat into the main claim that S1–S4 are "family-level properties." Relatedly, **n = 3 models** is very thin support for a family-level law, and the one model with Γ ≫ 0 is the model the method was designed on — the separation is real but the sample is chosen, not sampled.

**Efficiency claims are measured in the wrong regime.** This is the gap I would press hardest on in review. The paper's entire accuracy story is W4A4, justified by "W4 configurations use fake quantization for accuracy evaluation" because TensorRT lacks fused INT4 kernels — but then the deployment claims are all W8A8, a regime where the method's advantage over QuaRot is 0.1 AUC. So the paper demonstrates *accuracy* where it has no *kernels*, and *kernels* where it has no *accuracy advantage*. The two halves never meet. Worse, the honest efficiency baseline is not FP32: BF16 AMP runs at 0.52× latency with 98.7 AUC (Table 4), so the real speedup over a sane deployment is 1.6×, not 3.1×, and INT8's 0.32× is matched exactly by naive PTQ — meaning QMapAnything's contribution to latency is precisely zero, and its value is entirely "recover the 7 AUC points that naive INT8 loses, for free." That is a legitimate and useful result, but it is a different and much smaller claim than "3.1× speedup," and the abstract's phrasing lets a reader conflate them. The identical 0.32× for naive and Ours also deserves a breakdown: RHT costs `O(d log d)` per token and `b_s` adds a per-token branch, so either the overhead is genuinely negligible inside a memory-bound kernel (plausible, and worth stating) or it is being absorbed somewhere unmeasured.

**Smaller but real issues.** (i) The 3.1× memory headline is at 50 frames; at 100 frames — the regime that motivates the paper — it is 2.2×, and the abstract's "2.2–3.1×" is honest but the figure invites cherry-picking the peak. (ii) Γ's threshold is qualitative ("Γ ≈ 0" vs "Γ ≫ 0") with only three data points spanning 0 to 1.35×10⁵; there is no sensitivity analysis, no ROC, no intermediate-Γ model to test where the boundary actually lies. (iii) Calibration is fixed at 64 two-view samples with no study of how calibration view count affects `η_{s|β}` or Γ — notable because the method is evaluated at 16 views, and `b_s` is fit at 2. (iv) The 40-step Adam refinement introduces a hyperparameter (three stages split at blocks 7/11) that is asserted, not ablated. (v) The calibration mixture is an internal MapAnything recipe string (`megatrain 6d 518 many ar 36ipg 64g`) whose reproduction depends on a training mixture outsiders may not have exactly. (vi) The paper never reports what `b_s` costs at inference in the TensorRT engine, only that it "leaves integer GEMM unchanged" — true of the GEMM, silent about the epilogue.

**Significance.** For anyone quantizing a feed-forward geometry model, the practical takeaway is cheap and immediately actionable: check whether your model has a token whose norm is far below the patch tokens *and* which multiplies the output; if so, a one-row bias correction is nearly free and worth several AUC points at W4A4. The diagnostic Γ costs one forward and one backward. That is a genuinely useful piece of engineering advice backed by a correct (if shallow) theory, and the held-out result — 34.2% of scale-token MSE recoverable while whole-block MSE moves 0.010% — is the kind of insight that changes how people design calibration losses. The paper is honest about what it does not show, which is more than most in this space.

## Strengths

- **The central abstraction is correct and load-bearing.** Lemma 1 is not decoration: it explains why QuaRot, SpinQuant and SmoothQuant all plateau at the same place on this model class, and it predicts in advance that no amount of rotation tuning will close the remaining gap. The empirical group ceiling in App. C (74.3 → 86.9 across five rotations, then +6.8 from correction) is that prediction confirmed on a curve rather than a point.
- **The falsification experiment on VGGT and DA3 is exemplary.** Deliberately instantiating a mechanism your theory says to omit, on models you did not design on, and reporting −0.02/+0.04, is the strongest form of evidence in a methods paper. It converts "our method works" into "our criterion predicts when our method is unnecessary," which is a much harder and more useful claim.
- **The metric / up-to-scale evaluation split** directly tests the S2 mechanism instead of assuming it, and the predicted asymmetry shows up. Most quantization papers would have reported only AUC@30° and declared near-lossless performance at W4A4 — which, for a metric predictor, would have been actively misleading.
- **App. D's 34.2% vs 0.010%** is a small table with outsized implications: it quantifies why block-wise reconstruction objectives are blind to the exact failure mode that matters, and it generalizes to any model with a low-dimensional output-critical pathway.
- **Genuine efficiency engineering**, not just fake quantization: `RᵀW` folded offline, rotation only at QKV and two FFN projections, `b_s` restricted to the 8 global blocks by S4, β foldable into an existing layer bias. The storage accounting (`5d+2d_ff` per block, `|B_g|(5d+2d_ff)` explicit) is the kind of detail that suggests the authors intend this to be deployed.
- **Intellectual honesty in the reporting.** W4A8 ties with QuaRot are shown rather than hidden; the 2.2× at 100 frames is reported next to the 3.1× at 50; BF16 AMP at 0.52×/98.7 is included as a baseline when omitting it would have made the speedup look better; the AI-use statement is specific and disclaims exactly the things that need disclaiming.

## Limitations

- **No real W4A4 kernel.** All W4A4 numbers are PyTorch fake quantization. The paper's accuracy contribution and its efficiency contribution live in disjoint regimes (W4A4 accuracy, W8A8 kernels), and no experiment closes the loop. Whether the 92.8 AUC survives an actual INT4 TensorRT engine — with real rounding, fused epilogues and the `b_s` row add — is untested.
- **No comparison to QuantVGGT, QVGGT or FGQ**, the three geometry-specific PTQ methods the paper itself identifies as the closest prior work. The self-reimplemented RTN/SmoothQuant/QuaRot baselines test the group ceiling, not the state of the art. FGQ's Fisher-guided affine calibration in particular overlaps conceptually with `b_s` and is the comparison a reviewer will demand.
- **n = 3 models, one of which is the design target**, supporting a claim about "family-level properties." VGGT and DA3 were chosen because they conveniently realize the two pure cases (leverage without disadvantage; disadvantage without leverage) — a selection that makes the 2×2 table look cleaner than a random sample would.
- **DA3's `λ_s = 0` is definitional**, derived from evaluating leverage on the dense-ray pose path where the camera token is not read. The audit is therefore partly a property of the evaluation protocol; a different head would give a different Γ.
- **Asymmetric transfer protocol.** MapAnything gets 40-step Adam bias refinement in three stages; VGGT/DA3 get closed-form estimation. The `b_s`-is-negligible result on the transfers is confounded with estimator strength, and the obvious control (closed-form on MapAnything) is missing.
- **Single seed, no error bars, no variance reporting** anywhere, including the calibration-set half-split in App. D (which reports a median and IQR for `η` but a single number for the 34.2%/0.010% pair).
- **Γ has no calibrated threshold.** Three values (0, 0, 1.35×10⁵) and a qualitative rule. No intermediate-Γ model, no sensitivity curve, no statement of what happens at Γ = 10² or 10³. The authors call it a screen rather than a bound, which is fair, but a screen with an uncalibrated threshold is hard to apply to a new architecture without re-deriving the decision by hand.
- **Inference cost of the corrections is not isolated.** `b_s` "leaves integer GEMM unchanged" but adds an epilogue branch; RHT adds `O(d log d)` per token. Since Ours and naive PTQ both report exactly 0.32× latency, the overhead is either negligible or unmeasured — the paper does not say which.
- **Reproducibility is conditional**: code "upon acceptance," calibration drawn from an internal MegaTrain mixture recipe, and efficiency numbers tied to TensorRT 10.8 internals ("its internal INT GEMMs provide the low-bit kernels," no CUTLASS, no fast-Hadamard package) that an outside group may not reproduce identically.

## Relevance

直接命中"Reliability under Extreme Performance Optimization"：它研究的是低比特量化在**度量几何**模型上引入的数值退化，并且给出了一个非平凡的可靠性发现——量化误差在 token 维度上是不均匀的，一个只占序列 <0.1% 的 token 因为乘性作用于全部输出，其误差会被"尺度对齐"类指标完全掩盖（scale 相对误差 0.05→0.12，而点图 inlier 仍保留 72%）。对关注"精度优化如何悄悄破坏正确性"的读者，App. D 那个 34.2% vs 0.010% 的对比是最有价值的一条：block-wise 重建损失对输出关键行几乎完全不敏感。

其次，它提供了一个可迁移的方法论模板：先用便宜的诊断量（Γ，一次前向+一次反向）判断某种优化手段是否适用，再去实现它——这与"先量化再测 benchmark"的常规流程相反，对做推理可靠性筛查的人有直接借鉴意义。

## Questions for Further Exploration

1. **What does W4A4 actually cost at runtime?** The paper measures W8A8 kernels only. An INT4 TensorRT engine with the `b_s` epilogue would settle whether 92.8 AUC and a real speedup can coexist — and would reveal whether the row-selective add is free in a memory-bound kernel or a measurable tax.
2. **How does QMapAnything compare to FGQ?** FGQ's diagonal-Fisher affine calibration is the nearest conceptual relative of `b_s`. If FGQ captures most of the +3.2, the contribution shrinks to a *criterion* (useful) rather than a *mechanism* (less so). If it does not, the token-axis argument is much stronger.
3. **Where is Γ's decision boundary?** With only 0, 0 and 1.35×10⁵, the screen is untested in between. A model with Γ ~ 10²–10³ (moderate norm deficit, moderate leverage) would show whether the criterion is a threshold, a smooth dose-response, or a coincidence of three well-separated points.
4. **Does `b_s` still help on MapAnything under the closed-form protocol used for VGGT/DA3?** This is the missing control for the transfer experiment. If closed-form `b_s` gives ~+0 on MapAnything too, the VGGT/DA3 result is about the estimator, not about Γ.
5. **Is the audit stable under a different output path for DA3?** Computing `λ_s` against a head that does read the camera token would test whether `λ_s = 0` is an architectural fact or an artifact of choosing dense-ray pose as the deployment target.
6. **How does calibration view count interact with the correction?** `(β, b_s)` are fit on two-view samples and evaluated up to 16 views, where the gap to FP32 doubles. Does fitting at higher view counts shrink that residual gap, or is the degradation irreducible because it is a grid-occupancy effect rather than a calibration bias?
7. **Does the 34.2%-vs-0.010% blindness generalize?** The same diagnostic — per-row systematic residual versus block-averaged MSE — could be run on LLM quantization (e.g. BOS/attention-sink tokens, which share the "tiny norm, large leverage" profile). If the same invisibility appears there, the paper's real contribution may be a general calibration-loss critique rather than a 3D-vision recipe.
8. **What happens at W4A4 with per-token activation scaling instead of `b_s`?** The paper notes these are different remedies (changing the quantizer vs. reparameterizing the map) with different backend costs, but never measures the alternative. A comparison would clarify whether row-selective *grids* or row-selective *biases* are the better use of the same bit budget.
