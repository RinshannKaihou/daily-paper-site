Why it matters

If a self-improving agent can read the benchmark's scoring code, part of its reported gain is verifier-fitting — a validity problem for every self-improvement claim.

Relevance · self-improving agents / benchmark & reward design

Critical edge

C_faith is the authors' own construct: in build_tower the “faithful” criteria are “replaced wholesale… a different task, not a de-noised version of the same one.”

Critical Assessment · rigor, weak part 1

01

How the switch was isolated

One loop, one actor, one learner. The only variable is what the learner can see.

rollout→evidence ± criteria→learner revises library↺5 rounds
  • Frozen actor. GPT-6 Astra writes one PyRUA-Lean Python cell per call — RGB perception (SAM 3), motion primitives. No VLA, no depth, no simulator state.
  • Learner. Claude Code / Opus 5.5 revises a callable-skill + memory library once per round; five rounds, 40k-character cap, one library per task.
  • The switch. Success-only sees trajectories and binary success. CE (Criteria Exposure) also sees the criteria source, per-episode score and passed stages. The actor never reads criteria; scoring is frozen.
  • Pre-registered groups. 25 tasks split into 16 criteria-limited and 9 faithful before any result. Test: layouts 0–19 of seed 0, 500 episodes per arm.
  • Counterfactual. Rewrite only run_reward/get_score — never the instruction — then judge the identical episodes under both criteria sets.
  • Transfer. Distill 10 source tasks into one shared library; apply to 10 disjoint RoboDojo tasks, LIBERO-PRO and RoboCasa365.

Noise floor 4% verdict flips on rerun · ≥13% episode disagreement between identical round-0 batches.

05

Strengths

  • Dual judging is the right instrument. Identical episodes, both verdicts, episode ends only once both are known; flips hand-checked on a second seed.
  • The swap result survives disagreement. Each library wins only under the criteria it read — evidence about the learner, not the authors' rewrite.
  • The audit stands alone. 42 tasks, a 7-type defect taxonomy and a 26-row change table other benchmark authors can reuse.
  • Mechanism, not just scores. Memory citations, gripper arguments and action-budget accounting show how verifier-shaped rules hurt.
  • Unusual honesty about noise. 4% verdict flips and ≥13% round-0 disagreement are reported, making the negative results interpretable.
06

Limitations

  • C_faith is a team-authored proxy. build_tower is redefined; fasten_screws is tightened from 9 mm to 35 mm.
  • Difficulty is confounded. Criteria-limited tasks start at 8.4%, faithful at 53.3% — “criteria-limited” is also “hard”.
  • Negative transfer claims are underpowered. 20 layouts per task and a 13% episode disagreement cannot rule out small transfer.
  • One actor, one learner, no replication. Code and criteria are not released; the pathologies may be Opus-5.5 idiosyncrasies.
  • Only two exposure extremes. Partial criteria — rule text, scoring tables — is what most systems use, and is untested.
07

Open questions

  1. Is the damage monotone in exposure? Does partial criteria — a rule description or scoring table — help or hurt, versus the full source?
  2. Would the practitioners reproduce it? Run EmbodiedEvo or HexaShell under the same dual-judging protocol: is the inflation in their published numbers too?
  3. Can a prior fix the learner? If told “the verifier is a proxy”, does it recover transferable, physics-grounded entries instead of thresholds?
  4. Is the instruction the cheaper fix? Can closing the 33/42 arms-home gap at the instruction level alone remove most of the CE advantage?

Read this if

You report self-improvement numbers on a simulation benchmark whose verifier the agent can inspect.

Significance: high for methodology. The fix — judge by instruction-faithful criteria and report both — is cheap and immediately adoptable. The criteria audit alone is worth citing; the caveat is that someone must author the faithful criteria, and this paper shows how much judgment that takes.
