> **一句话总结：** 提出 GDPevo，一个面向 GDP 相关企业工作流的"进化原生"基准与全自动构建流水线，通过"规则混合化"机制将隐藏业务规则拆分到训练任务、再重组到测试任务中，使得 agent 在 24 个任务组、240 个任务上的自我进化提升可归因，并在 GPT-5.5/Opus-4.8/GLM-5.2/DeepSeek-V4 四个 agent 上观察到最多 +16.44 pp 的提升，但仍远低于 91.6% 的全知情上界。

> **TL;DR:** GDPevo is an evolution-native benchmark plus a fully automated construction pipeline for evaluating agent self-evolution on GDP-related enterprise workflows (CRM, ERP, Finance, Healthcare, Legal, Data Analysis). Its core mechanism, *rule hybridization*, decomposes each workflow into atomic business rules, distributes subsets across 5 training tasks per group, and recombines them in 5 held-out test tasks, so that test-time gains are attributable rather than memorization. On the 240-task, 24-group benchmark, every evolved agent (4 agents = harness + model) surpasses its base by 2.59–16.44 pp (best: Opus-4.8 fewshot 67.07% vs base 50.63%, +16.44 pp on GDPevo), yet all remain far below a fully-informed oracle ceiling of 91.6%.

## 核心贡献

- 提出 **规则混合化（rule hybridization）** 机制：将企业工作流分解为原子业务规则，分散到 5 个训练任务、再重组到 5 个测试任务中，使"测试时提升可归因于训练经验"这一性质从设计上得到保证，而非事后挖掘。
- 构建首个面向 **GDP 相关企业工作流** 的自我进化评测基准 GDPevo，覆盖 CRM、ERP、财务、医疗、法律、数据分析 6 大领域共 24 个任务组、240 个任务，且每个任务采用确定性规则评分器（拒绝 LLM-as-judge）。
- 提供 **全自动数据构建流水线**：在两天内即可从 V1（120 任务）扩展到 V2（240 任务），为数据污染提供务实的"再生成"应对策略。
- 在 4 个 agent（harness + model）× 4 种监督类型（base / fewshot / reflect / self）上做了系统评测，并附带 cost、token、turns 一等公民指标，及 rubric 级、雷达图、跨域迁移热力图等诊断视图。
- 通过受控实验给出三个反直觉发现：① 弱模型并不一定有更大进化空间；② fewshot（类 SFT）会过拟合源域、reflect（类 RL）跨域迁移更鲁棒；③ 简陋的 Naive skill creator 与复杂的现成 creator 表现相当甚至更好，说明进化的"量级"主要由模型自身智能决定。

## Key Contributions

- **Rule hybridization**: a construction-time mechanism that decomposes each enterprise workflow into atomic, independently checkable business rules, scatters subsets across 5 training tasks, and recombines them in 5 held-out test tasks, so that any test-time gain can be causally attributed to learning from training experience rather than memorization or template reuse.
- **GDPevo**, the first evolution-native benchmark targeting GDP-related enterprise workflows (CRM, ERP, Finance, Healthcare, Legal, Data Analysis) with 24 task groups / 240 tasks, every task scored by a deterministic rule-based grader derived from weighted binary rubric points rather than an LLM judge.
- **A fully automated construction pipeline** (seed discovery → task-group generation → calibration & independent review) that scaled V1 (12 groups) to V2 (24 groups) in under two days, offering a practical answer to data contamination by regenerating fresh versions whenever a release is exposed.
- **A comprehensive 4×4 evaluation** (GPT-5.5/Codex, Opus-4.8/Claude-Code, GLM-5.2/Claude-Code, DeepSeek-V4-Pro-Preview/Claude-Code under base/fewshot/reflect/self) that treats token, turn, and dollar cost as first-class metrics, plus diagnostic rubric-level views and transfer heatmaps.
- **Three counterintuitive findings**: (i) a weaker base model does not imply larger evolution headroom; (ii) fewshot (SFT-like) overfits its source domain while reflect (RL-like) transfers more robustly across domains; (iii) a minimal hand-written "Naive" skill creator matches or beats off-the-shelf creators, suggesting evolution magnitude is governed by model intelligence rather than by the harness's evolution method.

## Methodology

**Benchmark unit and design.** The unit of GDPevo is a *task group*: one shared stateful business environment (e.g., a medical-records system, employee DB, court case system), 5 training tasks, and 5 held-out test tasks. Training tasks expose subsets of the group's hidden atomic business rules; test tasks recombine them so that success requires compositional application of learned rules.

**Rule hybridization (the core novelty).** For each scenario, the pipeline (1) decomposes business logic into atomic, independently-checkable decision rules that are *deliberately absent from world knowledge* (e.g., one company's sponsor-status priority, an invoice expiration date); (2) scatters subsets across the 5 training tasks so each exposes only a fragment; (3) recombines rules across the 5 test tasks in novel combinations no training task contained. Only an agent that has actually inferred the rules and can compose them succeeds.

**Automated three-stage pipeline (Figure 1).** Stage 1 *seed discovery* takes public benchmarks (GDPval, SOP-Bench, JobBench, SaaS-Bench, τ²-Bench, CHI-Bench, Harvey LAB, etc.) and an agent proposes candidate scenarios. Stage 2 *task-group generation* has an orchestrator agent produce a blueprint (env spec, 10 task statements, atomic rules, task-rule matrix), then spawns one env builder + 10 task builders. Stage 3 *calibration & review* requires base accuracy 0.4–0.6, fewshot lift 0.1–0.3, post-evolution accuracy < 0.8, plus a 5/6 majority vote from six independent reviewer agents checking output completeness, rubric diversity, and absence of answer leakage. The pipeline itself is run by Codex + GPT-5.5.

**Evaluation setup.** An agent is defined as `Harness + Model`. Two harnesses (Codex, Claude Code) × four models (GPT-5.5, Opus-4.8, GLM-5.2, DeepSeek-V4-Pro-Preview). Four supervision types: `base` (no training), `fewshot` (training Q + gold A, SFT-like), `reflect-3` (training Q + grader feedback over 3 rounds, RL-like), `self` (training Q only, unsupervised-like). Evolution method is fixed to skill-based: a portable `SKILL.md` artifact distilled from the 5 training tasks is loaded by a fresh agent for the 5 test tasks. Each test task runs 3× in isolated Docker containers with allowlisted files; means are reported.

**Metrics.** Accuracy from deterministic rubric-based grader (LLM only translates rubric points into code-based test cases); cost in tokens, agent turns, and USD; plus diagnostic radar charts, per-rubric breakdowns, and source×target transfer heatmaps.

**Oracle ceiling.** Approximated (not by domain experts, who were unavailable) by a fully-informed condition: a non-expert human + Codex + GPT-5.5 receives all hidden rules, training inputs, gold answers, rubrics, and evaluator files. Over 360 attempts (24 groups × 5 test tasks × 3 runs), this condition reaches 91.6%.

## Results & Highlights

- **Headline accuracy gains**: Every agent–supervision combination improves over its base, by 2.59 to 16.44 pp. The largest single gain is **Opus-4.8 fewshot = 67.07% vs Opus-4.8 base = 50.63% (+16.44 pp)** on the full 240-task GDPevo benchmark (Table 3, Figure 2a). Other fewshot lifts: GPT-5.5 +15.14 pp (49.37% → 64.51%), GLM-5.2 +13.97 pp (46.12% → 60.09%), DeepSeek-V4-Pro-Preview +5.21 pp (43.58% → 48.79%).
- **Fewshot dominates**: fewshot attains the highest accuracy for all four agents; the Pareto frontier in accuracy–cost space consists of four fewshot agents plus GLM-5.2 reflect and DS-V4-Pro-Preview reflect.
- **Evolution can substitute for model training at extreme cost ratios**: DeepSeek-V4-Pro-Preview fewshot (48.79%) matches GPT-5.5 base (49.37%) at roughly **1/28 of the amortized end-to-end cost**; GLM-5.2 fewshot (60.09%) beats GPT-5.5 base and Opus-4.8 base by **+10.72 and +9.46 pp** at about half the cost.
- **Weaker base ≠ larger headroom**: DeepSeek-V4-Pro-Preview has the lowest base (43.58%) yet the *smallest* fewshot gain (+5.21 pp); Opus-4.8 has the *highest* base (50.63%) and the *largest* gain (+16.44 pp), contradicting the intuitive "low base, high headroom" assumption.
- **Evolution can also reduce test-time cost**: GPT-5.5 fewshot raises accuracy +15.14 pp while **cutting test-time cost by 20.88%** ($1.29 → $1.02 per task); amortized over 5 held-out tasks, per-task cost ($1.296) is nearly identical to base ($1.294). Opus-4.8 buys the largest gain at essentially unchanged test-time cost (−0.57%) but its amortized end-to-end cost rises from $1.37 to $1.87 per task.
- **Best evolved agents remain far below oracle**: even the best configuration (Opus-4.8 fewshot, 67.07%) sits well below the fully-informed oracle ceiling of **91.6%**, indicating substantial unrealized headroom in current self-evolution ability.
- **Cross-domain transfer (Figure 3, RQ2)**: fewshot behaves like SFT and overfits its source domain — 5 of 6 off-diagonal cells are negative, worst case −5.0 pp (train Finance → test ERP). Reflect-3 behaves like RL and transfers more robustly: half its off-diagonal cells are positive (up to **+6.5 pp** from ERP → Finance), worst case only −1.0 pp. Under reflect, evolving on CRM even helps Finance (+5.9 pp) more than it helps CRM itself (+2.6 pp).
- **Evolution method vs. model (Table 1, RQ3)**: with agent and supervision fixed (fewshot), swapping the skill creator barely changes results — the Naive one-sentence creator *matches or beats* off-the-shelf creators (GPT-5.5: Naive 65.12% / +15.46 pp vs Codex creator 62.19% / +12.53 pp vs DeepAgents 62.69% / +13.03 pp; DeepSeek-V4: Naive 48.01% / +5.54 pp vs OpenCode 47.84% / +5.36 pp). Conclusion: magnitude of evolution is governed by model intelligence, not by harness-encoded guidance.
- **Diagnostic case studies (Appendix F, Table 5)**: positive transfer cases (TG024 GPT-5.5 51.16% → 80.21%; TG014 GLM-5.2 51.00% → 68.00–71.33%) and negative-transfer cases (TG018 DS-V4-Pro-Preview 48.36% → 39.83% fewshot, due to dropped scope conditions; TG016 GLM-5.2 64.25% → 58.92%, due to narrow rules without branch conditions) demonstrate that the rubric-level breakdowns surface *which* rules were learned, dropped, or over-generalized.

## Authors & Credibility

- Twelve authors led by Leijun Zhou, with corresponding authors Junhao Hu and Yaowei Zheng; primary affiliation **PrismShadow**, with Xi Chen at **New York University**. PrismShadow is not (as of the paper) a widely recognized public benchmarking lab, so institutional track-record is thin; credibility rests on the artifact rather than prior brand.
- Strong transparency posture: full pipeline, 240-task benchmark, deterministic graders, and full evaluation results released at https://github.com/Prism-Shadow/GDPevo. Every test task is run three times; means and standard deviations are reported per group.
- The evaluation uses models labeled GPT-5.5, Opus-4.8, GLM-5.2, and DeepSeek-V4-Pro-Preview at "xhigh"/"max" reasoning settings; readers should treat these as the authors' named access points to frontier systems and verify availability/identity when reproducing.
- The benchmark *itself* was constructed by Codex + GPT-5.5, the same family as one of the evaluated agents — a potential circularity the authors do not fully discuss.

## Critical Assessment

- **Novelty (high).** Rule hybridization is a genuine methodological advance over evolution-native predecessors (EvoAgentBench, SkillFlow, SEA-Eval, BenchTrace) that derive train–test relationships *post hoc* from existing benchmarks. Designing the train–test split from atomic rules at construction time makes the "is the gain attributable?" question answerable by design, which is the central methodological gap in this subfield.
- **Rigor (mixed).** Positive: deterministic rule-based graders (no LLM judge), three-runs-per-task averaging, isolated Docker containers with allowlisted files, separate skill-generation vs. test-time cost accounting, and an impressive set of diagnostic views (per-rubric heatmaps, transfer matrices). Weaknesses:
  - *Calibration as selection bias.* Task groups are retained only if base accuracy is 0.4–0.6, fewshot lift is 0.1–0.3, and post-evolution accuracy stays < 0.8. This explicitly *filters out* groups where evolution fails or saturates, which mechanically inflates the apparent reliability of evolution gains and removes negative-result groups from the published benchmark.
  - *Oracle ceiling is not a real human-expert ceiling.* The authors candidly admit they "lack experts across all covered domains" and approximate the ceiling with a non-expert human + Codex + GPT-5.5 given all rules and gold training answers. The 91.6% number therefore measures "frontier model with full information," not "skilled professional," and the framing of headroom against human experts is looser than the prose suggests.
  - *Construction-model circularity.* Codex + GPT-5.5 builds the environments, tasks, rubrics, evaluators, calibration attempts, and reviewer votes — and is then one of the four evaluated agents. Any systematic bias in how GPT-5.5-friendly the generated rules/environments are would advantage that agent in the leaderboard, though this risk is not analyzed.
  - *Cross-domain experiment is tiny.* RQ2 restricts to 3 of 6 V1 domains (CRM, ERP, Finance) and *one task group each* (tg02, tg06, tg10), then draws broad claims about SFT-like vs. RL-like transfer behavior. With n = 3 source-target pairs off-diagonal per supervision type, the conclusions are suggestive but underpowered.
  - *Only two harnesses.* "Harness + Model" framing notwithstanding, only Codex and Claude Code are evaluated; generalization to OpenCode/deepagents/other harnesses as *evaluated agents* (not just as skill creators in RQ3) is not shown.
  - *Skill-based evolution only.* The paper repeatedly notes GDPevo is agnostic to the form of persistent state, but all headline results use a single skill-based method. Memory-, prompt-, harness-code-, or weight-based evolution are untested.
- **Reproducibility (high).** Public pipeline, benchmark, graders, traces, and a natural-language-driven evaluation orchestrator; per-attempt unique run IDs and retained failed/contaminated attempts for audit. The main reproducibility risks are access to the specific (future-dated) model versions and reasoning settings.
- **Significance (medium-high).** The benchmark fills a real gap — economically valuable, rule-governed enterprise workflows with attribution — and the automation + anti-contamination story is well-timed. However, the small per-domain sample (4 groups/domain, 5 test tasks/group) and the calibration filter mean the benchmark is better suited for *relative* agent comparison than for absolute claims about self-evolution capability.
- **Red flags.** (a) No human expert oracle despite framing headroom in those terms; (b) calibration thresholds that systematically exclude negative-transfer groups from the release; (c) 3 of 6 domains entirely missing from the cross-domain transfer study while that study's conclusions are stated broadly.

## Strengths

- Rule hybridization is a clean, well-motivated construction that makes "test-time gains are attributable" a *property of the benchmark* rather than a hope.
- Fully automated pipeline with calibration + 6-reviewer independent review + answer-leakage checks is a serious engineering effort and a credible anti-contamination mechanism.
- Deterministic rule-based graders (LLM only writes test code, not scores) remove the reproducibility and bias problems of LLM-as-judge.
- Cost is a first-class metric — token, turn, and USD columns accompany every accuracy, and one-time skill-generation cost is reported separately from test-time cost.
- Diagnostic depth: per-rubric heatmaps, radar profiles, and source×target transfer heatmaps let readers see *why* a configuration wins or loses, not just by how much.
- The four qualitative case studies (Appendix F) and the cross-case synthesis (F.5) elevate the paper from a leaderboard report to a genuine analysis of when skills transfer vs. when they overfit or interfere.
- Honest about the central negative finding: even the best evolved agent is far below the fully-informed ceiling, so current self-evolution ability is *not* close to realized.

## Limitations

- **Stated by authors.** Lack of human domain experts forces an approximate oracle ceiling; experiments use only skill-based evolution despite GDPevo being method-agnostic.
- **Sample size.** 4 task groups per domain × 5 test tasks per group is small; per-domain rankings are noisy (e.g., Table 3 standard deviations of 5–9 pp across groups).
- **Calibration filter.** Groups failing base-acc / fewshot-lift / post-evolution-acc thresholds are revised or dropped, so the released benchmark is biased toward "evolution works here."
- **Narrow cross-domain study.** Only CRM/ERP/Finance, one group each — claims about SFT-like vs. RL-like transfer are underpowered.
- **Two harnesses, four models.** Harness diversity is thin; all Claude-Code configurations share one harness.
- **Construction circularity.** The same frontier model family builds and is evaluated on the benchmark; bias in rule/environment phrasing cannot be ruled out.
- **Closed/future model identifiers.** GPT-5.5, Opus-4.8, GLM-5.2, DeepSeek-V4-Pro-Preview at "xhigh"/"max" settings are not independently verifiable from the paper alone.
- **Automation cost not zero.** The "two days to V2" claim omits the underlying API spend and the dependence on a specific frontier model; smaller labs may not reproduce the pipeline cheaply.

## Relevance

对评估 agent 自我进化、构建企业级 benchmark 与"训练经验可归因迁移"这一研究方向的读者高度相关：GDPevo 的"规则混合化"机制为 self-evolving agent 提供了可设计、抗污染、确定性评分的评测范式，与对你关注的 Agent / Benchmark / 自我改进主题直接对齐，适合作为后续工作的基线和评测平台。

## Questions for Further Exploration

- Does the calibration filter (base 0.4–0.6, fewshot lift 0.1–0.3, post-evolution < 0.8) systematically bias the benchmark toward "evolution-friendly" groups, and how would reported gains change if all generated groups were retained?
- How sensitive are the relative rankings to the construction model? If the pipeline were rebuilt with, say, Opus-4.8 or GLM-5.2 as the builder instead of GPT-5.5, does the GPT-5.5/Codex agent still lead?
- How do non-skill evolution methods (memory-based, prompt-evolution like GEPA, harness-code editing like Darwin Gödel Machine, or actual weight updates) perform on GDPevo, given the paper only studies skill-based evolution?
- Can the cross-domain transfer claims be reproduced with all six domains and multiple groups per source-target pair, instead of 3 domains × 1 group?
- What is a *true* human-expert oracle ceiling on the legal, medical, and finance groups, and how much of the 91.6%-vs-best-evolved gap is "agent cannot evolve" vs. "fully-informed condition is unrealistically informative"?
- Does the "Naive creator matches off-the-shelf creators" finding (Table 1) survive on harder/older frontier models, or is it an artifact of models already being skilled at distillation regardless of prompt scaffolding?
- How does GDPevo correlate with existing evolution-native benchmarks (EvoAgentBench, SkillFlow, SEA-Eval) — do they rank agents consistently, and where do they disagree?
