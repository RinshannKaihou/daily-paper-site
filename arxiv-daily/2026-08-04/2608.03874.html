Benchmark Continual Learning LLM Agents Skill Evolution

ContinualSkillBench: Can LLM Agents
Truly Evolve Their Capabilities?

Tianyi Guan · Yiding Wang (equal contribution) · Haotong Yang · Siyuan Cao · Shirui Liu · Yi Hu · Jiaqi Li · Muhan Zhang Institute for Artificial Intelligence, Peking University · Beijing Institute for General Artificial Intelligence

Key
Finding
Sequential agents beat memoryless ones in 14 of 15 model–domain pairs (+16.9% normalized reward) — but a pure in-context-learning baseline matches explicit skill maintenance (0.605 vs 0.602). The gain is mostly context & feedback adaptation, not transferable skill abstraction.
Key Metric
14/15
Model–domain pairs where Sequential execution raises normalized reward vs the memoryless Independent baseline.
+16.9% normalized reward · +0.078 macro Δ
Why This Matters

The first benchmark for in-context continual skill evolution over long, heterogeneous task streams — and it delivers an uncomfortable result: today's "skill evolution" mechanisms largely do not consolidate transferable skills. Direct read for anyone designing agent memory or skill libraries.

Critical Edge

The headline null result — "explicit skills ≈ ICL" — is tested on one model × three of five domains only. Office and Math never enter the ablation, so the central claim may not generalise.

Scope: GPT-5.3-Codex only · Law / Finance / Healthcare
Independent baseline loads the full skill repo on turn 1 — Δ may be inflated.

02

The surprise: skills ≈ in-context learning

GPT-5.3-Codex · Law / Finance / Healthcare
Independent 0.466 Memoryless baseline — context and skill repo reset per task.
no skills Pure ICL 0.605 Same context + feedback, but no skill creation at all.
Sequential 0.602 Retains context, feedback and an updatable skill library.
Verdict: explicit skill maintenance provides no consistent aggregate advantage over pure ICL. Sequential wins Law & Finance; ICL wins Healthcare. Skills only help on rigid-output tasks (Exact Match, Programmatic 0.250 → 0.500); ICL wins Rubric-judged tasks everywhere.

05

How it was built — and where it bends

Construction pipeline

  1. Pool ~30,000 tasks from ClawBench, OneMillionBench, GAIA + domain suites (InvestorBench, PhysicianBench, LegalBench, OlympiadBench, OfficeQA…).
  2. Label each task with 1–8 reusable skills (knowledge / reasoning / tool / workflow / output; core / support) + difficulty tier, via LLM.
  3. Graph 200 unordered pairs/domain (400 directional judgments) by GPT-5.4 with strict JSON a_helps_b prompts; YES edges form a DAG.
  4. Order via curriculum-constrained greedy topological sort (largest out-degree first); 100 tasks/domain, easier → harder.
  5. Validate with a blind Qwen3-32B re-annotator + cosine ≥ 0.85 skill matching; permutation tests with Holm correction.
  6. Run 3-turn protocol per task: Introduction → Execution (Codex CLI / Claude Code harness) → Reflection with create-skill / modify-skill.

Where it bends

  • 3 models only. GPT-4o, GPT-5.3-Codex, Opus 4.7. No Gemini, no open-weights, no small models — where consolidation might matter most.
  • Inflated Δ? The Independent baseline already loads the full skill repo on turn 1 ("prompted to review available skills").
  • No causal skill test. Skill utility is inferred from invoke frequency + an LLM judge — no "ablate-this-skill" experiment.
  • No Reflexion / no parametric CL baseline, despite continual-learning framing.
  • Noisy small cells. Normalized reward = intersection of valid tasks; per-evaluator regressions can hide inside an aggregate gain.
  • Reproducibility. Closed frontier models + GPT-5.4 judge; third-party full reproduction impossible.
06

Open questions worth chasing

Feedback vs long context. Does the null result survive when ICL is also denied feedback — is it the feedback or the context doing the work?
Consolidation mechanisms. Skill merging, auto-deletion of low-reuse skills, embedding-based retrieval — can they close the GPT-4o ↔ GPT-5.3 gap?
Position curve. Do Sequential returns saturate, accelerate, or degrade late in the 100-task stream?
Generalise the null. Reproduce ICL-vs-Sequential on Qwen3 / Llama 4 and on Office & Math — the untested half.
Distribution shift. Inject a new source benchmark mid-stream — do skills transfer or over-specialise (cf. Opus Math −0.192)?
Causal utility. Replace the LLM quality judge with an ablate-this-skill delta — does the ranking of load-bearing skills change?
