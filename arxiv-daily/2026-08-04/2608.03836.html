Resume Means Resume

Sajjad Khan · independent · London  ·  A machine-checked conformance contract for checkpoint, interrupt & resume semantics in workflow persistence layers
Key Finding

Across five mainstream LLM-agent frameworks, no two share the same checkpoint / resume conformance profile — and "exactly-once" silently degrades to "at-least-once" the moment a process dies.

The persistence API is the seam that every framework routes durability through, and today it states no obligation. A six-property RESUME CONTRACT, machine-checked in TLA+ and probed deterministically in 47 LLM-free campaigns, charges each framework only with contradicting its own citable semantics.
01Key Metric
2,628 / 400
Cross-process consume-once: gated effect fires 2,628 times where exactly-once predicts 400. Saturation 1.0 in 36 / 40 cells; at k=16 the distribution is {16:10} — sixteen fires from one approval, ten times out of ten.
02Why This Matters
Agent frameworks now gate payments, messages and file writes behind checkpoint / resume. The belief that "the framework has checkpointing" licenses nothing about what happens to completed effects after a crash. Conformance belongs in CI, not in user-filed issues.
03Critical Edge
Single author, single-institution review surface — no co-author cross-check, cross-host replication by the same team. Five frameworks ≠ prevalence (AG2, OpenAI / Claude Agent SDK, Agno still under construction). And rung 8 is absent: no mechanized refinement binds the Verus model to the compiled binary — bridged by differential suite, not proof.

The contract six properties · one impossibility

Derived not from a bug list but from the six questions any caller gating a non-idempotent effect must answer across an interrupt / crash / resume boundary. Stated purely over public observables — effects, checkpoints, interrupts, resume values, recovery decisions — so verdicts are decidable without reading the source.

PC
prefix cont.
Completed prefix is never re-executed after recovery.
EO
effect once
Each gated effect fires exactly once per run.
FD
fork determ.
Same checkpoint + two resumes ⇒ two distinct continuations.
CV
checkpoint val.
Persisted state satisfies the documented schema.
CO
consume once
One interrupt consumed by ≤1 resume; stray resume is inert.
RD
recovery det.
Recovery decision is a function of the durable log.
Proposition 1: on a discriminator-free wire, FD and CO are jointly unsatisfiable. Fork-intent expressibility (FI) is therefore a necessary protocol precondition — not a feature.

Fragmentation, measured pinned releases · deterministic

Every probe drives the persistence API with pure-Python tasks. Crashes are either exception-based or a barrier-synchronized SIGKILL; the oracle is a process-local counter cross-checked by an on-disk SQLite ledger independent of the checkpointer. No verdict depends on timing, sampling, or model behaviour.

REMIT — the repair verus-verified · <5% overhead

A reference sequencer interposed at BaseCheckpointSaver — the narrow waist every probed framework routes durability through. Append-only effect ledger written transactionally with the completion checkpoint; per-thread sequencer orders the persistence ops whose unenforced ordering produced #8039.

  1. FD repair (probe 125 → 134): a matched write-path / read-path pair. Write-path fork-keying fails to restore FD; a read-path fork-intent filter succeeds — on the identical failing protocol.
  2. CV repair (probe 123): a validity gate converts silent schema-invalid persist into loud rejection.
  3. CO repair (probe 165 / 174): shipped opt-in cross-process gate (v0.1.2) takes a (thread, checkpoint) claim under a uniqueness constraint and refuses the loser with RemitConsumeConflict — flips the cell from 10/10 duplication to {1:10}, on both durable backends and across two hosts.
  4. Cost (probe 139): within 5% of stock in the container, within ±1.7% on the dev host (committed per-cell deltas −0.34% to +0.38%). At k=64 the shim adds +19% median / +16% p95 in the container.
