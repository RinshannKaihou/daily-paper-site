SFT Conflicts, RL Coexists.

The first systematic account of why multi-stage supervised fine-tuning collapses in multi-task LLM post-training while multi-stage reinforcement learning holds together — and a recipe, Parallel-RL, that trains task specialists fully in parallel, then merges with 5% adaptation data, retaining 103.2% of single-task RL performance.

Key Metric

The two-order-of-magnitude gap

≈100×smaller & sparser

RL's per-task weight update ΔWRL is roughly two orders of magnitude smaller than SFT's, with only ~20% of parameters exceeding 10⁻⁵ in magnitude (vs 93% for SFT). Different tasks' RL updates sit at cosine ≈10⁻⁵ — effectively orthogonal — while SFT updates overlap at ≈10⁻¹, with Math↔Code sometimes pointing opposite (cos ≈ −0.97).

measured on ΔW = Wtrained − Wbase, §3 / Fig. 2
Why This Matters

Parallelize the post-training pipeline

5%adaptation budget

If tasks barely interfere in parameter space, you can stop chaining them. Parallel-RL runs N independent RL specialists on separate timelines, then merges ΔWi with a short 5%-data adaptation phase — decoupling teams and GPU budgets that sequential Multi-Stage RL forces into a single critical path.

Critical Edge

Where the story frays

LoRA → full-paramunbridged

The orthogonality claim is established in a LoRA subspace, but Table 4's headline numbers use full-parameter GRPO — the bridge is asserted, not proven. And "RL coexists" is not universal: the authors' own SynLogic Game task breaks the merge (Math −4.0%, Code −3.3%), and the only coexistence test is qualitative t-SNE eyeballing.

01 · Mechanism

Why RL updates forget to collide

Two empirical observations on ΔW, then a closed-form reason.

  • Magnitude. ‖ΔW‖₂ ≈ 3×10⁻² (RL) vs ≈7.4 (SFT). RL touches ~20% of parameters above 10⁻⁵; SFT touches ~93%.
  • Direction. Pairwise cos(ΔWi,ΔWj) ≈ 10⁻⁵ across RL tasks — near-orthogonal — vs ≈10⁻¹ for SFT, with some pairs anti-correlated.
  • Score-function diagnostics (Table 3). ‖S‖₂ ≈ 7.1 (SFT) vs ≈10⁻¹ (RL); ‖δS‖₂ ≈10⁻² (RL only); cos(Si,Sj) ≈10⁻¹ vs ≈10⁻³.
  • t-SNE of S = ∇θ log πθ(y|x) shows cleanly separated clusters per task for RL — a practical (if operator-dependent) coexistence predictor.

|ISFT(i,j)| ≤ Mi·Mj   (norm-limited)
|IRL(i,j)| ≤ Vi·Vj   (variance-limited) Under bounded E‖S*‖²≤Mᵢ² and E‖δS‖²≤Vᵢ². 02 · Recipe

Parallel-RL in four moves

Train, merge, adapt — each stage optional.

  • 1 · Train. Launch N independent GRPO runs → ΔW1…ΔWN. No shared critical path.
  • 2 · Merge. Wfinal = Wbase + M(ΔW1,…,ΔWN); choices span Naive sum, TIES, and an SVD rank-1 variant.
  • 3 · Adapt. A short phase on 5% of the original data after a Naive sum.
  • 4 · Select. Use t-SNE separability of score functions (App. D.1) to decide which tasks belong in the same merge — the Game counter-example shows this gate matters.

04 · Decoupling & Caveats

Are the modules really independent?

An ablation and a counter-example.

  • Drop-ΔWi ablation (Table 5). Removing a task's update drops only that task by −7.1% avg (Math −3.6, Science −10.5, Logic −9.0, Code −5.3), while other tasks rise +0.6% — strong evidence of disentangled modules.
  • The Game counter-example. SynLogic "Game" breaks orthogonality: merging Game+Math drops Math by 4.0%, Game+Code drops Code by 3.3%. "RL always coexists" is too strong.
Scope & limits — read before deploying

LoRA → full-param gap unformalized. Mechanism (§3) is LoRA; main numbers (Table 4) are full-parameter.

Edge over Multi-Stage RL is thin. +10.7% vs +10.2% ΔBase on 1.5B — and no "Multi-Stage RL + 5% extra data" control is reported.

No wall-clock / GPU-hour numbers. "Efficiency" is measured only in adaptation-sample count, not throughput.

Theory is GRPO/PPO-specific. Depends on zero-sum standardized advantages; vanilla REINFORCE / unnormalized DAPO aren't covered.
