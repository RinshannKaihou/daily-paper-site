> **一句话总结：** 作者提出 RESUME CONTRACT——针对 LLM Agent 工作流持久化层（checkpoint/interrupt/resume）的六条机器可检查性质（PC、EO、FD、CV、CO、RD）加 fork-intent 协议义务，用 TLA+ 模型、39 格故障矩阵和确定性（无 LLM）测试框架，证明 LangGraph 1.2.9、CrewAI 1.15.2 等五大框架行为互相矛盾且违反自身文档语义，并交付 Verus 验证的 REMIT 参考序列器在检查点接口处修复 fork 与合法性缺陷（开销低于 5%）。

> **TL;DR:** The paper defines the RESUME CONTRACT (six machine-checkable properties — prefix continuation, effect exactly-once, fork determinism, checkpoint validity, consume-once, recovery determinism — plus a fork-intent protocol obligation), verifies a reference TLA+ semantics exhaustively (87/59 states; scaled to 14.7M/7.4M states unchanged), and measures five LLM-agent workflow frameworks (LangGraph 1.2.9, LlamaIndex Workflows 2.22.2, CrewAI 1.15.2, pydantic-graph 1.107.1, AutoGen AgentChat 0.7.5) with a deterministic, LLM-free harness: no two frameworks share a conformance profile, LangGraph silently ignores a durably-recorded second resume value (FD violation, issue #6663, on all three backends), CrewAI re-executes completed effects (counter reads 12 vs exactly-once's 11) against its own documentation, and cross-process consume-once fails with saturation 1.0 in 36/40 cells. REMIT, a Verus-verified reference sequencer, repairs the fork and validity cells and ships an opt-in cross-process gate that flips duplication from 10/10 to {1:10}.

## 核心贡献

- **提出 RESUME CONTRACT 形式化规约**：在持久化 API（checkpoints / interrupts / resume 命令）这一抽象边界上定义六条性质——前缀续接 (PC)、effect 恰好一次 (EO)、fork 决定性 (FD)、检查点合法性 (CV)、consume-once (CO)、恢复决定性 (RD)——外加 fork-intent 协议义务 (FI) 与活性义务。该性质集并非事后整理的 bug 清单，而是从"调用方跨越中断/崩溃/resume 边界时必须能回答的六个问题"导出。
- **机器验证的 TLA+ 模型**：参考语义通过 TLC 模型检查（87 生成状态 / 59 不同状态，零错误）；通过六个故障开关模拟部署框架中观察到的各类违例。在 39 格（每个故障 × 每条性质）矩阵中，TLC 自动*发现*每个故障的完整违例足迹，而非人为指定；缩放到 14.7M 生成 / 7.4M 不同状态（R8）时裁决不变。
- **形式化的偏独立性结果（机器检查）**：通过有限模型展示证明了 EO、PC、FD、CV、RD 以及 CO 的"消耗计数"子句各自独立于其余性质的合取；CO 的"effect 惰性"子句是 EO 在受控任务上的定义性推论；并证明无判别符的协议上 FD 与 CO 不可同时满足（Proposition 1）。
- **确定性、无 LLM 的跨框架一致性测试工具**：47 个编号探针在 11 个 campaign 中执行；崩溃通过异常注入或经文件系统 barrier 同步的真实 SIGKILL（probe 133/137/160），所有裁决与 timing 解耦；采用进程内 effect 计数器 + 磁盘 SQLite 外部账本双 oracle。
- **五大主流框架的测量结果**：在 pinned release 上系统测量 LangGraph 1.2.9、LlamaIndex Workflows 2.22.2、CrewAI 1.15.2、pydantic-graph 1.107.1、AutoGen AgentChat 0.7.5，**没有两个框架共享同一一致性画像**；多个违例直接复现了第三方 GitHub issue（#6663、#6491、CrewAI restore replay）。
- **REMIT 参考序列器（含可验证修复）**：在 `BaseCheckpointSaver` 接口处介入，Verus 证明的恢复核心与可执行发货核心逐行一致并在 CI 中守护；将 LangGraph 的 fork 违例与静默非法持久化修复为"显式拒绝"，并把跨进程 consume-once 从 10/10 重复修复为 {1:10}，开销在容器内 5% 以内。

## Key Contributions

- **A named, machine-checkable contract** — the RESUME CONTRACT — over the *surface* of the agent-framework resume plane (checkpoints, interrupts, resume commands, state-inspection API). Six properties (PC, EO, FD, CV, CO, RD) are derived from the six questions any caller gating a non-idempotent effect must be able to answer across an interrupt/crash/resume boundary, rather than reverse-engineered from a bug list.
- **A TLA+ reference model with exhaustive verification.** The reference configuration satisfies all six invariants (87 generated / 59 distinct states, no error); six fault switches, each transcribing a deployed-mechanism violation class (not a negation of a target property), produce depth 4–6 counterexamples. A 39-cell per-invariant fault matrix *discovers* each fault's full violation footprint; ForkIgnore and InvalidPersist are full separating models (Proposition 2). Everything re-derives identically at 14.7M generated / 7.4M distinct states.
- **A formal partial-independence result, machine-checked.** The paper exhibits finite separating witnesses that EO, PC, FD, CV, RD, and CO's consumption clause are logically independent of the conjunction of the other properties; CO's effect clause is shown to be the gated restriction of EO (structural dependence). Proposition 1 proves FD and CO are jointly unsatisfiable on a discriminator-free wire, making FI (fork-intent expressibility) a necessary protocol precondition.
- **A deterministic, LLM-free conformance harness** that drives each framework's persistence API with pure-Python protocol sequences. Crashes are either exception-based or a barrier-synchronized SIGKILL (probe 133/137/160); the oracle is a process-local effect counter cross-checked against an on-disk SQLite ledger independent of the checkpointer. No verdict depends on timing, sampling, or model behavior.
- **A fragmentation finding across five frameworks.** At pinned releases, LangGraph 1.2.9 silently discards a durably recorded second resume value (FD ✗, #6663, on InMemorySaver/SqliteSaver/PostgresSaver and both invocation forms), persists schema-invalid state silently (CV ✗, #6491 class), and splits exactly-once by path (EO ✓ across interrupts, ✗ across crashes); CrewAI 1.15.2 re-executes completed effect-bearing methods against its written exactly-once claim (counter reads 12 vs exactly-once's 11); pydantic-graph 1.107.1 cannot resume after a mid-node crash (safety vacuous, progress dead); no two frameworks share a profile (9 of 10 pairs separate behaviorally).
- **A characterized cross-process consume-once failure.** k processes resuming one parked interrupt fire the gated effect k times — saturation 1.0 in 36/40 cells, never below 0.933, no ceiling observed to k=16 — on both SQLite and live PostgreSQL, crossing hosts. The admitting window is measured by dose–response to track the gated node's own execution time.
- **REMIT — a reference repair with a Verus-verified recovery core.** REMIT interposes at the checkpointer interface; its recovery-decision core is line-identical to the shipped executable under a CI gate. A read-path fork-intent filter repairs #6663 on the identical protocol (probe 134 against the failing write-path probe 125); a validity gate converts silent CV violation to loud rejection (probe 123); the shipped opt-in cross-process gate (v0.1.2) flips the duplication cell from 10/10 to {1:10} on both durable backends and across two hosts.

## Methodology

The paper proceeds in four mechanically audited layers.

**(1) The contract (Section 3).** Definition 1 introduces an abstract *resume plane*: a run executes tasks 1..N, each carrying a non-idempotent external effect; one task IP is interrupt-gated, firing only after a resume value v ∈ V is consumed. Completing a task appends a checkpoint record to a durable log and advances the durable frontier; a crash erases volatile state and recovery chooses a continuation as a function of the durable log. The six properties (PC, EO, FD, CV, CO, RD) are stated purely over this surface — effects, checkpoints, interrupts, resume values, outcomes, recovery decisions — so verdicts are decidable from public observables. A two-clause CO splits the *consumption count* (CO-c, an interrupt is consumed by at most one resume) from *effect inertness* (CO-e, a stray resume is effect-inert); the split carries the paper's headline composition result. FI (Property 7) requires the wire to carry a branch discriminator; Definition 2 gives three equivalent forms (resume ordinal, explicit fork flag, branch-creating address). Proposition 1 proves that without a discriminator no responder — deterministic or randomized — can satisfy both FD and CO.

**(2) The machine-checked model (Section 4).** ResumeContract.tla (251 lines) formalizes Definition 1 and Properties 1–6 as state invariants over actions ExecTask, EmitInterrupt, Consume, ForkResume, CrashRecover, ExtraResume. Six Boolean fault switches (Replay, ForkIgnore, InvalidPersist, NondetRecovery, DoubleConsume, PrefixReplay) each transcribe an observed deployed-mechanism class. TLC 2.19 (single worker for BFS-minimal counterexamples) verifies the reference configuration R0 (N=3 tasks, IP=2, |V|=2) and each single-fault configuration R1–R5, R9. A companion module R11_ConsumeCount.tla carries a consumption counter and a second racer, closing the gap where the base module's atomic Consume cannot express CO-c; the cross-process failure's footprint {EO, CO-e, CO-c} matches probe 159 cell-for-cell. LangGraphFork.tla models LangGraph's resume path as the recorded-write rule (pending writes are served at a checkpoint already carrying a resume write rather than re-recorded) — a rule that makes same-value replay idempotent by design and breaks forking by the same design choice; the fork-keyed repair verifies idempotence + FD jointly (LGF-B). Scaled bounds R8 (10 tasks, IP=5, |V|=4, 5 resumes, 4 crashes) re-check all six invariants over 14.7M generated / 7.4M distinct states.

**(3) The conformance harness (Section 5).** Three design constraints make every verdict deterministic and portable: LLM-free (every probe drives persistence APIs with pure-Python tasks); timing-free crash injection (matrix crashes are exception-based; SIGKILL probes are barrier-synchronized; probe 160 exhausts every persistence operation as a kill point with no sleep windows); effect-ledger oracle (process-local counters cross-checked by on-disk SQLite independent of the checkpointer, with the effect *being* the ledger append on durable probes so every counted duplicate is a floor, never a hidden loss). Pilot environment pins Python 3.12.3, LangGraph 1.2.9, llama-index-workflows 2.22.2, CrewAI 1.15.2, pydantic-graph 1.107.1, AutoGen AgentChat 0.7.5; the durable-backend environment adds langgraph-checkpoint-sqlite/postgres 3.1.0 against a live PostgreSQL 16 server. 47 numbered probes in 11 campaigns, plus a key-gated live-replication matrix (probe 148) spanning two models per provider and two hosts (240 runs, zero harness errors). Provenance is explicitly tracked (Table 4): four findings reproduce third-party filed issues; two are new observations; the rest are deterministic reproductions.

**(4) REMIT (Section 7).** REMIT interposes at `BaseCheckpointSaver`, the narrow waist every probed framework routes durability through. Its state is (i) an append-only effect ledger of ⟨branch, task, effectId⟩ records written transactionally with the completion checkpoint, and (ii) a per-thread sequencer that totally orders the persistence operations whose unenforced ordering produces #8039. Six properties map to local invariants. Verus proofs (toolchain 0.2026.05.03.8b81855) discharge the ledger/frontier core (10 verified, 0 errors), CV gate lemmas (2), FD behavioral half by inductive invariant (5), RD order-independence (6), an executable recovery core line-identical to the shipped function (7), and the executable EO admission / PC-CV commit gate (11); two negative certificates restate the obligations under the stock #6663 serve rule and the order-sensitive #8039 recovery rule and are rejected, certifying the positives have content. A model-conformance check (rung 5) transliterates the TLA+ action alphabet against the Rust core and exhaustively enumerates 6,110 distinct states / 13,035 transitions at R0 (414,675 states / 1.07M transitions at scaled bounds); rung 6 stresses 64-thread admission/fork/sequencing (probe 157: 6,400 end-to-end protocol executions, per-protocol exactly-once in all). The honestly-stated gap (rung 8): no mechanized refinement connects the Verus model to the compiled core.

## Results & Highlights

- **TLC verification matrix (Table 2).** Reference configuration R0 satisfies all six invariants over **87 generated / 59 distinct states**; scaled configuration R8 (10 tasks, IP=5, 4 values, 5 resumes, 4 crashes) re-checks all six invariants plus TypeOK over **14.7M generated / 7.4M distinct states at depth 24**, with the fork fault's counterexample deepening from depth 5 (R2) to depth 8 (R8-F single-worker). Every fault's target invariant is violated at depth 4–6 in its single-fault run.
- **Cross-process consume-once failure (probe 159/168).** Two OS processes sharing one on-disk SqliteSaver, each issuing Command(resume=...) against the same parked interrupt: the gated effect fires twice in **10/10 repetitions on the developer host** and **3/3 in the container**, byte-identical re-delivery being the duplicating arm. The wider sweep (probe 168) covers **40 cells / 400 executions**, firing the gated effect **2,628 times where exactly-once predicts 400**; **saturation is 1.0 in 36/40 cells and never below 0.933**, and at k=16 with zero jitter the distribution is **{16:10} on SqliteSaver and on live PostgresSaver** — sixteen fires from one approval, ten times out of ten. The same protocol on PostgresSaver 3.1.0 against a live server duplicates in **10/10 repetitions on both hosts**.
- **CrewAI 1.15.2 counter arithmetic (probe 115).** With method s1 completing and persisting (counter 1), s2 raising, and re-kickoff from the latest checkpoint: the s1 effect counter reads **2** and the final state counter reads **12 where exactly-once predicts 11** — "task 1 persisted, crash in task 2, resume, and the completed task re-fires, landing the counter on 12 where exactly-once predicts 11." This directly contradicts CrewAI's documented claim that restore "resume[s] without re-running completed work."
- **LangGraph EO path split.** Interrupt-resume memoizes completed task results (#6792, fixed) while crash-resume does not: same-process retry preserves completed siblings on retry while process-death resume re-executes. After SIGKILL barrier-synchronized past the durable write, the completed task re-executes identically (ledger **1→2**), replicated on SqliteSaver and PostgresSaver with the durable ledger agreeing.
- **Live ecological replication (probe 148).** At N=40 per (probe, model, host), 240 runs, zero harness errors: the fork violation reproduces in **40/40 runs on each Claude model (80/80 overall, 95% Wilson [0.91, 1.0])**, on every model-host combination — "a read-path defect no model choice can mask"; the interrupt-approve cell fires 0/40 on both Claude models (95% Wilson upper bound 0.09).
- **REMIT interposition overhead (probe 139).** Full interrupt protocol, **N=200 fresh-database iterations per configuration**, on two hosts: **within 5% of stock in the container, within ±1.7% on the developer host** (committed per-cell deltas −0.34% to +0.38%). At k=64 concurrency the shim adds +19% median / +16% p95 in the container, ±2.5% on the dev host.
- **REMIT cross-process gate repair (probe 165/174).** Shipped opt-in gate (v0.1.2) takes the (thread, checkpoint) claim in the saver's own database under a uniqueness constraint and refuses the loser with `RemitConsumeConflict` before any node executes: **{1:10} on both durable backends**, and with racers on two hosts (one a WAN link away at ~450 ms/query) **the stock path duplicates in 10/10 while the gate refuses the losing racer in 10/10**. Probe 125 vs 134 establishes the matched-pair asymmetry: write-path fork-keying fails to restore FD, read-path filtering succeeds.
- **DBOS engine baseline (probe 147).** All probed cells conform on DBOS 2.27.0 as an embedded worker (exactly-once across SIGKILL, explicit `fork_workflow` branch-creating address, consume-once via idempotency key), at **2.9–5.0× the checkpointer path's gate-answer latency** — pricing the "just use Temporal/DBOS" alternative the contract does not oppose.

## Authors & Credibility

Sole author **Sajjad Khan**, an independent researcher in London (no institutional affiliation). The work is unusually rigorous and self-aware for a single-author paper: it explicitly itemizes what is *proved* vs *machine-checked* vs *measured* vs *verified* vs *not claimed*, names its one unqualified verification gap (no mechanized refinement from the Verus model to the compiled core, rung 8 of Table 10), records withdrawn observations and earlier tautological lemmas with dates in VERIFICATION.md, and includes two negative Verus certificates that fail by design to demonstrate the positive obligations have content. The lineage claims are credible: the author's prior work (SoundGate, arXiv:2607.14166; Token Budgets, arXiv:2606.04056; the consistency lattice, arXiv:2606.17182) is referenced as the upstream source of the RD ordering hazard (#8039) and the verification methodology. Reproducibility infrastructure is unusually strong: a single-command `reproduce.sh` re-derives every headline number from committed data, every probe emits raw + stable-view JSON with a generated manifest, and cross-host replication uses a mechanical guard (no two receipts with different host identifiers may share a timestamp) precisely because a container receipt was once produced by copying its developer-host twin — a near miss the paper discloses.

## Critical Assessment

- **Novelty:** High and well-positioned. The paper explicitly distinguishes its layer from Crab (below the API, OS-level sandbox checkpointing) and DART (above the API, rollback admissibility), and from ACRFence (the adversarial face of EO/CO) and AgentConform (which tests agent *communication* protocols, not the resume plane). The assembly of classical notions (rollback-recovery determinism, distributed snapshots, exactly-once state management, Helland's idempotence line) into a checkable obligation set for an API that currently states none is genuinely new, and Table 11 honestly flags where DBOS/Temporal already state these obligations (PC, RD as restatements; EO as *stronger* than Temporal's caller-keyed at-least-once). The CO two-clause split and Proposition 1's FD–CO impossibility are the load-bearing formal novelties.
- **Rigor:** The strongest aspect. TLA+ verification is exhaustive (BFS over the full reachable space at stated bounds, not sampling), fault footprints are *discovered* by TLC rather than stipulated, the harness is timing-free and LLM-free with two independent oracles, and the dose–response measurement of the consume-once window traces the gated node's own execution time. The verification claims are meticulously stratified across 8 rungs (Table 10).
- **Reproducibility:** Excellent in principle — pinned releases, single-command audit, committed lockfiles, raw JSON per probe, cross-environment replication, source-level mutation study (probe 156: 8 hand-derived mutants, all killed on both hosts). The artifact is private pending publication but available on request; the `remit-contract` package ships on PyPI with a prebuilt manylinux wheel. One real caveat: the LangGraphFork.tla mapping is **expert-established rather than mechanically extracted**, and the paper says so plainly; the trace-conformance check (probe 143) and the out-of-sample probe 171 (four pre-registered predictions, all confirmed) mitigate but do not eliminate this.
- **Significance:** Practitioner-relevant and timely. LLM-agent frameworks now gate payments, messages, and file writes behind checkpoint/resume, and the finding that "the framework has checkpointing" licenses nothing about completed effects is actionable. The recommendation that the contract become a CI conformance suite is concrete.
- **Red flags and honest weaknesses:**
  - **Single-author, single-institution review surface** — though the rigor is high, there is no co-author cross-check; the cross-host replication is by the same team, not independent.
  - **Sample of five frameworks** is not the ecosystem; the paper repeatedly and correctly says prevalence is not claimed and never generalizes from the sample. AG2, OpenAI Agents SDK, Claude Agent SDK, and Agno are listed as "in the full matrix under construction."
  - **Live cells are existence/stability replications, not rarity estimates.** At N=40 a true violation rate as high as 0.09 is consistent with observing zero — the paper states this and assigns the generalization weight to the deterministic harness.
  - **The most material CrewAI claim** (task skipping for *crews*, distinct from the probed flows) requires live agents and is deferred to the full matrix, so the headline CrewAI EO ✗ rests on the @persist and CheckpointConfig paths only.
  - **CO-c's representability gap in the base TLA+ module** is real: Consume(v) is atomic and guarded by `pc = NTasks + 1`, so the cross-process lost-update shape requires the separate companion module R11_ConsumeCount.tla — which the paper flags and closes.
  - **Dose–response arm ran on the developer host alone**, and the backend columns of the D-sweep share a jitter seed (paired comparison, not independent evidence of backend invariance).
  - **Production-scale engine head-to-head against Temporal/DBOS is scoped out**, not owed; the engine baseline (probe 147) prices the alternative rather than refuting it.
  - **Verification does not reach the compiled binary** (rung 8 absent); the PyO3 boundary and the decision-free Python veneer are unverified Python code, mitigated only by construction and audit.

## Strengths

- Treats the contract as a *proposed* standard rather than an adopted one, and labels divergence (D) distinctly from violation (✗) — a framework is charged only with contradicting its own citable semantics, never with contradicting the contract.
- The TLA+ fault switches transcribe *deployed mechanisms*, not negations of target properties; TLC then discovers each fault's full footprint, deflecting the "circular switches" objection with four non-clean off-diagonal cells.
- The harness contains no timing, no randomness, and no model calls — verdicts change only with package versions, which are pinned and audited against committed lockfiles.
- The matched write-path/read-path pairs (probes 125/134 for FD; Section 7.2 for CO) are the ablations a reviewer would ask for, and they localize *where* a conformance repair can bind in a checkpointer-shaped architecture.
- Intellectual honesty about the limits of verification: Table 10's rung 8 ("absent") and the explicit retirement of earlier tautological lemmas and a withdrawn CV/RD file with placeholder `assume(false)` bodies, all dated in VERIFICATION.md.
- Honest treatment of a withdrawn observation (an exploratory run suggested CrewAI wrote no checkpoint files; in the pinned, lock-file-resolved environment the same configuration writes checkpoints — the zero-file observation is withdrawn, the regression guard retained).

## Limitations

- **Five frameworks is not prevalence.** The study explicitly disclaims ecosystem-wide prevalence rates; generalization rests on the deterministic harness and the mechanism accounts, not on the sample.
- **The cross-process consume-once characterization is one concurrency shape.** The paper exhibits the anomaly at k≤16 with jitter ≤25 ms and one two-host topology (probe 174); partitions, wider topologies, and k>16 remain unmeasured, and the paper does not classify the plane's isolation level (the natural vocabulary is Adya et al. / Elle).
- **No mechanized refinement to the compiled core.** This is the one unqualified verification gap, and the paper states it once and does not relitigate it. The Verus model and the shipped Rust executable are bridged by a differential suite and exhaustive model-conformance enumeration, not by proof.
- **Real payment-style APIs are out of scope.** The oracles audit framework invocation discipline; end-to-end delivery under partition or duplication is delegated to the effect layer's idempotency-key composition (Remark 4).
- **LangGraphFork.tla is expert-established, not mechanically extracted.** The mapping is grounded in reproduced behavior and a source reading at pinned versions, and is checked by a trace-conformance probe and out-of-sample predictions, but it remains an abstraction a maintainer could contest.
- **CrewAI's strongest claim** (task skipping for crews as opposed to flows) is deferred to the full matrix.
- **Single author.** The cross-environment replication is by the same team, not an independent reproduction.

## Relevance

对研究 LLM Agent 系统可靠性、形式化验证与崩溃恢复语义的工作高度相关：本文首次为 LangGraph/CrewAI/LlamaIndex 等主流 Agent 工作流框架的 checkpoint/interrupt/resume 层给出机器可检查的契约与跨框架一致性测量，揭示了 gate 支付/消息/文件写入等非幂等效应时"恰好一次"在崩溃路径上悄然退化为"至少一次"的系统性缺陷，对设计可信赖 Agent 编排系统、为 Agent 框架构建 CI 一致性测试套件具有直接方法论价值。

## Questions for Further Exploration

- How do the six properties compose under deeper DAG nesting, multi-checkpointer fan-in, and parallel fan-out racing beyond the two-gate/two-branch cases probed — does the FD–CO impossibility propagate, and does the consume-once window widen nonlinearly with branch concurrency?
- Can a TLAPS inductive invariant (exhibited in the artifact as IndCheck.tla but not yet discharged) upgrade the universal claims — reference conjunction and each fault footprint's completeness — from bound-relative to unbounded, and what is the proof-engineering cost relative to the bound-relaxed sufficiency the paper already establishes?
- Does the consume-once cross-process anomaly generalize to a specific isolation level in the Adya / Elle taxonomy, and can the Elle inference framework be applied to client-observable resume histories to classify the plane without hand-built probes?
- For frameworks that *do* adopt a discriminator (DBOS's `fork_workflow` address + idempotency key, Restate's durable promises), how much of the contract is satisfied by construction versus by verification, and what is the minimal FI-carrying wire extension for LangGraph's `Command(resume=...)` to close the #6663 class without a read-path shim?
- What is the empirical prevalence of each violation class across a wider ecosystem survey (AG2, OpenAI Agents SDK, Claude Agent SDK, Agno, Mastra, Inngest), and do the regression pairs (#7361, #6792 broken in 1.1.x, fixed in 1.2.9) imply that a conformance suite in CI would have caught them at the PR rather than at the user-issue stage?
