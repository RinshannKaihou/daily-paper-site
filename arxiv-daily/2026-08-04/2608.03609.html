Formal Verification of Agentic Systems over Operational Data

Alejandro J. Mercado  ·  Alessio Lomuscio — Imperial College London · Safe Intelligence

Key finding

Verifying an LLM tool-orchestration deployment against first-order temporal specs over evolving data is undecidable — yet a single symmetry condition on the agent (equivariance under identifier relabeling) collapses it to PSPACE-complete exact finite verification. LLMs provably violate that symmetry, so a deployment wrapper must enforce it.

对带工具编排与持久关系数据的 LLM 智能体部署（STEAD），在 FO-CTL 规约下验证不可判定；但只要智能体策略对标识符重命名等变，即可在有限域上做 PSPACE 完备的精确验证——而 LLM 天然违反等变，因此需要规范化包装器在部署边界强制之。

Why this matters

First pre-deployment formal verification of an LLM-driven agent over relational operational data.

Pinpoints one precise obstacle — agent equivariance — as the bridge between neural LLM behaviour and classical finite-abstraction model checking.

A constructive, deployment-level fix (the canonical wrapper) makes verification applicable without retraining or post-hoc certification — infrastructure for verifiable agents.

Critical edge
  • Toy-scale empirics. Single LLM family (Qwen3), one 12-value domain, custom 2-service workflow. No multi-model / multi-benchmark study.
  • Wrapper changes behaviour on non-canonical presentations — "verifying the agent" really means verifying a wrapped variant.
  • Canonicalization is GI-hard (graph-isomorphism-hard) but is never benchmarked for runtime as the active domain grows.
  • Action-rigidity is a real restriction; symmetric offered calls make the wrapper set-valued and over-approximate.
01 · The problem

STEADs are undecidable to verify

A STEAD — Stateful Tool-Enabled Agentic Deployment — is one LLM, a tool harness, and a relational operational state that evolves. The authors give its semantics and prove that checking FO-CTL specs against it is undecidable.

Thm. 8 (Undecidability). Any relational data-centric dynamic system (Hariri 2013) with invariant G p encodes as a STEAD with one always-offered nullary tool; G p holds in the source iff AG p holds in the STEAD.

FO-CTL = sorted first-order active-domain quantifiers + branching-time CTL (AX, A U, E U, derived AG/EF/EG) — expressive enough for safety and progress.

02 · The bridge

Agent equivariance is the hinge

Classical finite-abstraction results need three symmetries. Two are easy; the third — the agent policy — is exactly where LLMs break.

if D₁ ≃_C D₂ via ι, then   Π(D₂, ι(A)) = ι(Π(D₁, A))

When this holds plus C-boundedness by b, a finite subdomain with at least 2b_S + |C∩U_S| + var_S(φ) values per sort gives exact preservation — verdicts on the finite fragment transfer exactly to the infinite deployment.

Thm. 13 (Exact finite verification). M_A ⊨ φ ⇔ M_A↾U_f ⊨ φ, PSPACE-complete in combined complexity.
03 · The counterexample — equivariance, broken on contact

Rename one opaque user. Qwen3-1.7B picks a policy-violating reservation it did not pick before.

A τ-bench airline-cancellation task, single-turn, greedy structured (prefix-trie) decoding. Everything held fixed except the username.

user = amelia_davis_8890

Context B · relabelled only
user = ea0q883c_00yla6i6

Because the permutation ρ fixes reservation identifiers, ρ(A) = A and ρ(a₀) = a₀ — so the observed a₁ ≠ ρ(a₀) is a formal C-equivariance violation, not measurement noise. The ineligible r2 is additionally selected only in the renamed context.

04 · The fix

Canonical deployment wrapper

At the deployment boundary: rename each decision context to its canonical representative, query the base LLM once, transport the selection back to the original identifiers.

Thm. 18. Πcan is B-equivariant for every base agent, and identity on already-equivariant ones.

Computing the canonical rep is graph-isomorphism-hard (Lemma 19). Action-rigidity (Prop. 21) keeps output singleton-valued.

Strengths

What lands cleanly

  • Pinpoints a specific, non-trivial obstacle (agent equivariance) instead of hand-waving "LLMs are unreliable."
  • The canonical wrapper is constructive, deployment-level, needs no retraining, and is provably conservative (identity on already-equivariant agents).
  • Honest verdicts — the framework is shown refuting a safety property, not only certifying.
  • Excellent reproducibility: code repo, exact prompts, decoding details, environment, control experiment.
Limitations

What to watch

  • Small-scale, single-family empirics (Qwen3 only); generalization untested.
  • Undecidability & PSPACE results are largely inherited; the wrapper is the new mechanism, and its GI-hard cost isn't benchmarked.
  • Wrapper can alter behaviour on non-canonical presentations — "verified agent" ≠ "agent as deployed."
  • Single-LLM only; multi-agent, persistent memory, richer environment interaction left to future work.
Methodology 7 steps · formal-methods

A formal-methods contribution combining (a) model-theoretic semantics from data-aware verification with (b) a deployment-level intervention for neural agents.

  1. System model — STEAD. Typed relational structure (sorted domain U, typed schema D, initial instance D₀); tools Ω; offered calls Offer(D); tool semantics τ(D,a); LLM agent policy Π(D,A). Induced transition system M_A is serial; the LLM is Markovian in the decision context.
  2. FO-CTL. Sorted first-order active-domain quantification + CTL modalities; expresses safety (φ_auth) and progress (φ_prog).
  3. Undecidability (Thm. 8). Reduction from relational data-centric dynamic systems with invariant G p.
  4. Symmetry conditions (Defs. 9–11). C-equivariance of Offer, C-tool-uniformity of τ, C-equivariance of Π — the agent is the obstacle.
  5. Exact finite verification (Thm. 13). C-boundedness + 3 symmetries ⇒ exact preservation on a finite subdomain; PSPACE-complete.
  6. Canonical wrapper (Defs. 14–15, Thm. 18, Prop. 21). can_B(D) = least B-labelling; Π_can unions over canonical witnesses; always B-equivariant; GI-hard to compute; action-rigidity ⇒ singleton-valued.
  7. Verification algorithm. Forward BFS over U_f, canonicalize each context, query base agent once, apply τ, retain in-domain successors; bottom-up FO-CTL satisfaction-set computation.

Open questions for further work
Q1How do wrapper runtime and LLM-query count scale with the number of isomorphism classes in realistically large operational states, given GI-hard canonicalization?
Q2Does equivariance hold, break, or vary across model scale and family (GPT-class, Claude-class, Llama) on the same task — and can the behaviour-change on non-canonical presentations be quantified?
Q3Can action-rigidity be relaxed via an equivariant symmetry-breaking convention, avoiding Π_can's set-valued blow-up for workflows with persistent symmetric objects?
Q4How does the framework extend to multi-turn, multi-agent deployments with persistent memory, where the Markov-in-decision-context assumption breaks?
Q5Can the finite-restriction machinery yield maximally-permissive, data-aware tool restrictions reusable across base agents, and how does it compare empirically to interface-level enforcers like Agent-C on the same FO-CTL specs?
