> **一句话总结：** 该工作提出 ContinualSkillBench——一个覆盖 5 个领域、每域 100 个按难度与技能复用机会排序的互联子任务的动态评测框架，系统对比了 LLM 智能体的顺序执行（持续更新技能库）与无记忆独立执行；发现顺序执行在 15 个"模型-领域"组合中有 14 个提升归一化奖励（整体相对增益 16.9%），但纯上下文学习与显式技能维护平均打平（0.605 vs 0.602），且弱模型（GPT-4o）倾向于堆积 384 个碎片化技能而少被复用，强模型（GPT-5.3-Codex）仅维护 205 个高质量技能。

> **TL;DR:** ContinualSkillBench is a dynamic benchmark for in-context continual skill learning across 5 domains (Healthcare, Law, Math, Finance, Office), each with 100 interconnected subtasks ordered by difficulty and skill-reuse potential. Sequential execution beats memoryless Independent execution in 14 of 15 model-domain pairs with a 16.9% aggregate normalized-reward gain (e.g., GPT-5.3-Codex on Healthcare rises from 0.380 to 0.620 normalized reward), but a pure in-context-learning (ICL) baseline matches explicit skill maintenance on average (0.605 vs 0.602 normalized reward), and weaker models (GPT-4o) fragment their skill libraries (384 low-quality skills vs 205 for GPT-5.3-Codex).

## 核心贡献

- **构建 ContinualSkillBench：** 首个面向"长程、异构领域内任务流"上 in-context 持续技能演化的动态评测框架，覆盖 Healthcare、Law、Mathematics、Finance、Office 五大领域，每域 100 个子任务，源自约 30,000 个原始任务，经 LLM 辅助过滤、技能依赖图谱排序与人工复核三阶段精筛。
- **任务流设计的可验证性：** 通过两两任务依赖判定 + 图排序构造按难度递增且高复用的任务序列；结构验证显示 69.5% 的任务会复用序列中已出现的核心技能，平均核心技能覆盖率达 35.5%，并在 15 个领域-窗口对比中显著优于随机排列（10 个通过 Holm 校正）。
- **统一的顺序 vs 独立评测协议：** 基于 Harbor 框架并扩展出 Codex CLI / Claude Code 两种顺序智能体 harness，每个子任务采用"任务介绍—执行—反思并更新技能"三回合协议，并以 raw / normalized reward + 4 类评估器（Exact Match、F1、Numeric、Programmatic、Rubric Judge）量化"持续经验保留"的净增益。
- **核心负面发现：** 显式技能库并不显著优于纯上下文学习（ICL 与 Sequential 归一化奖励分别为 0.605 vs 0.602）；增益主要来自上下文与反馈的适应，而非可复用技能抽象；显式技能仅在需要可复用流程或严格输出的任务（如 Exact Match、Programmatic）上提供选择性收益。
- **技能库动态行为分析：** 弱模型（GPT-4o）倾向堆积大量碎片化任务特异技能（共 384 个，平均质量 5.68/10），强模型（GPT-5.3-Codex）维护更紧凑且更常被调用的技能库（205 个，平均质量 7.94/10），揭示了"技能碎片化"是弱模型长期适应受限的关键原因。

## Key Contributions

- **ContinualSkillBench, a new dynamic benchmark** explicitly designed to test in-context continual skill evolution (not isolated tasks or fixed skill documents). It covers five consequential domains (Healthcare, Law, Math, Finance, Office), each with 100 interconnected subtasks built from ~30,000 candidate tasks drawn from a three-tier (foundational / agent / human-evaluated) pool of source benchmarks.
- **A reproducible task-stream construction pipeline**: LLM skill labeling and filtering → pairwise skill-transfer judgments converted into a directed dependency graph → curriculum-constrained greedy topological ordering (preferring tasks with larger out-degree) → human review, producing sequences with verified opportunities for cross-task skill reuse.
- **A clean evaluation protocol** distinguishing three conditions on identical task orders: Independent (memoryless baseline), Sequential (retains context, feedback, and an explicit updatable skill library), and pure In-Context Learning (same context/feedback, no skill creation). Built on the Harbor infrastructure with Codex CLI and Claude Code harnesses; results aggregated as raw reward and normalized reward across four evaluator types.
- **A surprising negative result on skill abstraction**: explicit skill maintenance yields no consistent aggregate advantage over pure ICL (0.602 vs 0.605 normalized reward averaged over Law/Finance/Healthcare with GPT-5.3-Codex); much of the Sequential-vs-Independent gain comes from retained context and feedback rather than reusable skill abstraction. Explicit skills only win on rigid-output tasks (Exact Match in Law/Finance, Programmatic in Healthcare: 0.250 → 0.500).
- **Behavioral diagnostics of skill libraries**: invoke-frequency and final-pool-size statistics plus an LLM-judged quality audit show weaker models (GPT-4o: 384 skills, quality 5.68) accumulate fragmented task-specific skills while stronger models (GPT-5.3-Codex: 205 skills, quality 7.94) consolidate experience into compact, reusable procedures.

## Methodology

**Benchmark construction (Phases 1–2).** The authors pool roughly 30,000 tasks from cross-domain benchmarks (ClawBench, OneMillionBench, GAIA) plus domain-specific suites (e.g., InvestorBench/FinBen/TAT-QA in Finance; PhysicianBench/MedAgentsBench/HealthBench in Healthcare; LegalBench/LawBench/harvey-labs/Lexam in Law; OlympiadBench/OmniMath/Putnam_Axiom/MathCoder/RealMath in Math; OfficeQA/WritingBench in Office). An LLM labels each task with 1–8 reusable skills (knowledge/reasoning/tool/workflow/output, core/support), filters out benchmark-interface artifacts, and assigns a difficulty tier. For each domain, 200 unordered task pairs (400 directional judgments) are made by GPT-5.4 with a strict JSON "a_helps_b / b_helps_a ∈ {YES, PARTIAL, NO}" prompt; YES edges form a directed dependency graph. A curriculum-constrained greedy topological sort (largest out-degree first, cycle-breaking on out-degree) orders 100 tasks per domain from easier to harder, preserving skill-transfer dependencies. Human reviewers validate trajectories, difficulty progression, and skill-transfer plausibility.

**Structural validation of skill continuity.** A separate Qwen3-32B annotator (temp 0, no sequence index visible) re-tags each task with core skills. Using sentence-transformers/all-mpnet-base-v2 embeddings, two skills are "semantic counterparts" if cosine similarity ≥ 0.85. Macro-averaged across domains: 69.5% of eligible tasks reuse at least one previously encountered core skill; mean core-skill coverage is 35.5%. Compared against 10,000 random permutations over windows of 1/5/10 preceding tasks, the curated order wins in all 15 domain-window comparisons and remains significant after Holm correction in 10 of them, with Finance showing the largest gains (+5.6 / +5.1 / +3.9 pp).

**Three-turn sequential agent protocol.** Each subtask runs (1) Task Introduction (instruction + current skill repository, with a memory-hint prepend for non-first tasks), (2) Execution by the Codex/Claude harness, (3) Reflection where the agent reads the external judge's JSON feedback and may invoke `create-skill` / `modify-skill` meta-skills (each SKILL.md must begin with valid YAML frontmatter). Updated skills become available from the next subtask onward.

**Models and conditions.** Three foundation models are evaluated with matched harnesses: GPT-4o, GPT-5.3-Codex, and Claude 4.7 Opus. Two main conditions: **Independent (Ind.)** resets history and skill repository before each task; **Sequential (Seq.)** retains both across the 100-task stream. Ablations add **pure ICL** (GPT-5.3-Codex on Law/Finance/Healthcare, same feedback but no skill creation), a **RAG trajectory-memory baseline** (Opus 4.7 on Healthcare), and an **LLM-judged skill-quality audit** (GPT-4.1-mini scoring format × content).

**Metrics.** Raw reward (R_raw) averages over all 100 tasks; normalized reward (R̃_norm) is computed only over the intersection of tasks producing valid output under both Seq. and Ind., removing parsing/format-failure bias. Gains are reported as Δ_raw and Δ_norm; relative gain uses the aggregate Independent baseline.

## Results & Highlights

- **Headline aggregate gain:** Sequential execution increases normalized reward in **14 of 15** model–domain combinations and raw reward in **13 of 15**, with macro-averaged absolute gains of **+0.078 normalized / +0.071 raw**, corresponding to **+16.9% relative improvement in normalized reward (16.2% raw)** versus the aggregate Independent baseline.
- **Healthcare is by far the most sequential-friendly domain:** average normalized improvement of **+0.149** across models, driven by GPT-5.3-Codex (Healthcare normalized reward 0.380 → 0.620, +0.240) and Opus 4.7 (0.481 → 0.662, +0.181). The largest single-task-type swing in the paper is GPT-5.3-Codex Healthcare Exact Match: **0.321 → 0.857 (+0.536)**.
- **Skill-maintenance vs pure ICL is essentially a tie:** on GPT-5.3-Codex across Law/Finance/Healthcare, average normalized rewards are **Independent 0.466, ICL 0.605, Sequential 0.602** — Sequential beats ICL in Law and Finance but loses in Healthcare, so explicit skill maintenance provides **no consistent aggregate advantage over pure ICL**. Explicit skills still help Exact Match (Law, Finance) and lift Healthcare Programmatic from **0.250 → 0.500**, while ICL wins on Rubric-judged tasks in all three domains.
- **Evaluator-type pattern:** structured tasks benefit most from sequencing. GPT-5.3-Codex improves by **+0.416 on Numeric** and **+0.091 on Exact Match** in Finance versus only +0.038 on Rubric — though Opus 4.7 Healthcare Rubric shows a +0.234 gain and Opus Math Rubric shows a −0.192 drop, so the pattern is not universal.
- **Skill-library fragmentation tracks model capability:** GPT-4o accumulates **384 skills** across the five domains (avg. quality score 5.68/10) while GPT-5.3-Codex accumulates only **205** (avg. quality 7.94/10). Per-domain extremes: GPT-4o builds 97 Math skills at 5.74 quality and 81 Healthcare skills at 5.36, whereas GPT-5.3-Codex builds 48 Math skills at 7.43 and 38 Healthcare skills at 8.19 — i.e., weaker models produce larger, lower-quality, less-reused skill pools.
- **Structural reuse is real:** 69.5% of post-first tasks reuse a previously encountered core skill (macro-average; Office 77.8%, Mathematics 70.7%, Law 67.7%, Finance 67.7%, Healthcare 63.6%); curated order beats random permutations in **all 15 domain-window comparisons** (significant after Holm correction in 10), with Finance coverage exceeding random-order means by +5.6/+5.1/+3.9 pp at windows of 1/5/10.
- **RAG trajectory-memory ablation (Opus 4.7, Healthcare):** RAG reaches 0.617 normalized reward vs 0.635 for explicit-skill Seq. — similar to the ICL pattern, suggesting part of the Rubric gain is adaptation to prior feedback rather than reusable skill acquisition, while explicit skills remain stronger on exact-match-style outputs.

## Authors & Credibility

The work is authored by Tianyi Guan, Yiding Wang (equal contribution), Haotong Yang, Siyuan Cao, Shirui Liu, Yi Hu at the Institute for Artificial Intelligence, Peking University, with Jiaqi Li and Muhan Zhang (corresponding authors) jointly affiliated with the Beijing Institute for General Artificial Intelligence. Muhan Zhang is a well-known graph/data-centric ML researcher, which lends credibility to the graph-based task-ordering methodology. The paper is transparent about limitations (limited model coverage, fixed source datasets, no Cursor/Google-CLI ports) and releases code at `github.com/gtynnn060110-hash/continual-skill-bench-final`. Source datasets are well-established (GAIA, LegalBench, HealthBench, OlympiadBench, InvestorBench, etc.), and the methodology section discloses the exact LLM judge (GPT-5.4 for pair judgments, Qwen3-32B for skill annotation, GPT-4.1-mini for quality audit) and threshold choices (cosine ≥ 0.85).

## Critical Assessment

- **Novelty:** Genuinely fills a gap. Unlike SkillsBench (externally provided curated skills, no evolution), SkillLearnBench (single-task refinement), CL-Bench (in-context/memory architectures over shared latent structure), and SkillCraft (executable tool composition), ContinualSkillBench is the first to study skill evolution over long, heterogeneous, multi-source streams within broad domains connected by recurring core skills. The three-condition contrast (Independent / ICL / Sequential) is a clean and under-used design.
- **Rigor:** Strong on construction validation (permutation tests with Holm correction, sensitivity to the cosine threshold, separate annotator blind to sequence position). However, the central ICL-vs-Sequential ablation is run on only **one model (GPT-5.3-Codex) and three of five domains** — Law/Finance/Healthcare — leaving Office and Math untested for the headline "explicit skills ≈ ICL" claim. Readers cannot verify whether the null result generalizes.
- **Baseline concerns:** The "Independent" baseline already has the full skill repository loaded on turn 1 of each task (the agent is "prompted to review the available skills"), which may understate the Independent number and inflate Δ. The RAG ablation is reported for a single (model, domain) pair. There is no comparison against memory / self-reflection baselines like Reflexion or against parametric continual-learning baselines, despite the related-work positioning next to continual learning.
- **Missing ablations:** No breakdown of gains by how many skills were actually retrieved for the target task, no learning-curve analysis over position in the 100-task stream, no analysis of skill *deletion* or *revision* events, and no human evaluation of whether the LLM-judged "quality score" predicts downstream task reuse.
- **Data quirk:** Normalized reward is computed only on tasks valid under both settings, so on small domains (e.g., GPT-4o Math with only ~6 Numeric tasks, Ind. 0.208 → Seq. 0.125, i.e. a −0.083 Numeric regression that is hidden by an overall +0.088 normalized gain) the per-cell numbers are noisy and the +0.078 macro Δ leans on a handful of tasks.
- **Overclaiming risk:** The framing "Can LLM Agents Truly Evolve Their Capabilities?" is more provocative than the data supports. The authors' own ICL ablation shows much of the gain is **not** from skill abstraction but from retained context/feedback; the honest answer is "agents adapt continually but rarely consolidate transferable skills," which the conclusion does state but the abstract undersells.
- **Reproducibility:** Code is promised; exact prompts are in the appendix; closed frontier models (GPT-5.3-Codex, Claude 4.7 Opus) and the GPT-5.4 judge are proprietary, so a third party cannot fully reproduce; cost is acknowledged as the reason coverage is limited.

## Strengths

- The three-condition design (Independent / pure ICL / Sequential-with-skills) is exactly the right decomposition for isolating what *skills* contribute beyond *context* — a question prior agent-skill benchmarks have sidestepped.
- Honest negative findings (explicit skills ≈ ICL on average; weaker models fragment their skill libraries; gains are domain- and evaluator-type-dependent) are more scientifically useful than the typical "our framework wins" paper.
- Task-stream construction is principled and validated: pairwise dependency graph + curriculum-constrained topological ordering + permutation tests with Holm correction establish that the sequences have genuine local skill-continuity structure rather than just being "hard tasks later."
- Per-evaluator-type breakdowns (Exact Match / F1 / Numeric / Programmatic / Rubric) reveal *where* skills help — rigid-output tasks — instead of reporting only a single aggregate number.
- The skill-quality audit (format × content, with concrete examples of GPT-4o's terse 12-line `date-range-filter` vs GPT-5.3-Codex's structured `tatqa-metric-alignment` workflow) makes the "stronger models consolidate, weaker models fragment" claim tangible.

## Limitations

- Only three models evaluated (GPT-4o, GPT-5.3-Codex, Opus 4.7); no Gemini variants, no open-weight models, no Claude 3.x, no smaller models where skill consolidation might matter most. The authors flag this but it materially limits the generalizability of every cross-model claim.
- The headline ICL-vs-Skill ablation covers only GPT-5.3-Codex on Law/Finance/Healthcare — three of five domains — so the central conclusion rests on a narrow slice.
- Tasks are curated from a *fixed* set of source benchmarks; the authors explicitly note real deployments face rare edge cases, distribution shift, and instruction-format drift not covered here.
- High API/time cost prevented broader infrastructure coverage (no Cursor, no Google CLI), even though memory/skill-retrieval behavior plausibly differs across agent frameworks.
- Some per-cell numbers (e.g., GPT-4o Math Numeric with very few eligible tasks) are noisy, and the normalized-reward metric's "intersection of valid tasks" definition can mask evaluator-specific regressions.
- Skill *utility* is inferred from invoke frequency and an LLM quality judge, but there is no end-to-end causal test (e.g., disable a specific skill and measure the delta) to confirm that high-quality skills are actually the source of the Sequential gains.

## Relevance

对于关注 LLM 智能体（Agent）、持续学习（Continual Learning）与自我演化能力评测的研究者，该工作提供了首个面向"长程任务流上技能演化"的公开基准，并给出了一个反直觉但重要的结论：当前 in-context 技能演化机制主要靠上下文/反馈适应而非可迁移技能抽象，这对设计 Agent 记忆/技能管理系统与评测协议有直接参考价值。

## Questions for Further Exploration

- Does the "explicit skills ≈ ICL" null result hold when ICL is also denied *feedback* — i.e., is it the feedback or the long context doing the work?
- Would stronger skill-consolidation mechanisms (skill merging, automated deletion of low-reuse skills, retrieval-by-embedding rather than by name) close the gap between GPT-4o's fragmented library and GPT-5.3-Codex's compact one?
- How do the Sequential gains evolve as a function of position in the 100-task stream — do returns saturate, accelerate, or degrade late?
- Can the ICL-vs-Sequential ablation be reproduced on open-weight models (e.g., Qwen3, Llama 4) and on Office/Math to test the generality of the central claim?
- What happens under distribution shift (new source benchmark injected mid-stream) — do accumulated skills transfer or do they over-specialize, as the Rubric degradation in Opus Math (−0.192) hints?
- Does replacing the LLM skill-quality judge with a causal "ablate-this-skill" test change the ranking of which skills are actually load-bearing for downstream performance?
