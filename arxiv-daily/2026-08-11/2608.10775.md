> **一句话总结：** SkillLens 把异构 GUI 交互轨迹归一化成"视觉技能卡"（VSC：过程文本 + 适用性线索 + 视觉证据 + 验证信号），推理时先用轻量文本索引检索、再只展开被选中卡片的高分辨率证据喂给**冻结**的 VLM 执行器，使 GPT-5.4-mini 在 Multimodal-Mind2Web 的 Step SR 从 77.2 提到 88.8（+11.6）、OSWorld-G 定位准确率从 45.0 提到 66.5（+21.5）；同一套卡片作为教师特权上下文做 on-policy 蒸馏（CardDistill）后，Qwen3-VL-2B 学生在**无需运行时检索**的情况下 Mind2Web Step SR +12.0、WebLINX-BG Overall +3.2。

> **TL;DR:** SkillLens turns heterogeneous GUI traces into retrievable "Visual Skill Cards" that a frozen VLM executor conditions on at test time. Against a No-skill baseline with the same frozen executor, it lifts GPT-5.4-mini Multimodal-Mind2Web Step SR from 77.2 to 88.8 (+11.6), WebLINX-BrowserGym Overall from 12.8 to 15.7 (+2.9), and OSWorld-G Grounding Acc. from 45.0 to 66.5 (+21.5). CardDistill reuses the same cards as privileged teacher context and gives a Qwen3-VL-2B student +12.0 Step SR on Mind2Web (95% CI [7.5, 17.5]) and +3.2 Overall on WebLINX-BG with no runtime retrieval — though the paper's own modality ablation shows text-only cards actually beat the full visual configuration on both web benchmarks.

## 核心贡献

- **VSC 表示**：把技能形式化为 `s = (p, z, v, κ)`——可复用过程 `p`、适用性/完成线索 `z`、视觉证据 `v`（整屏视图、目标裁剪、Before/Target/After）、可选恢复字段 `κ`。三个层级（meta 长程任务模式 / core 可复用子目标 / exec 短程落地操作），本文主实验只用 execution 级卡片。
- **Trace-to-VSC 构建流水线**：source record → 轨迹归一化 → 分段 → 过程摘要 → 绑定视觉证据 → 审计（检查卡片自包含、且 held-out 评测不会把答案坐标当模板泄漏）。结构化 benchmark 可确定性绑定目标，非结构化演示用 LLM/VLM 摘要。
- **检索与选择性展开解耦**：先用确定性 token 重叠打分做粗排 TopK_c，再对候选紧凑记录重排并取 TopK_s / TopK_e，最后只对入选卡片调用确定性展开函数 `e(·)` 加载有界证据（卡片预算 K_e、图像预算 K_v）。成本从 `C_full = Σ C(v_i)`（全量加载）降到 `C_lens = C(B(C_t)) + C(E_t)`。
- **CardDistill**：同一套卡片改作训练期特权上下文。教师看 `(ξ_t, S_t^priv, E_t^priv)`，学生只看 benchmark 原生上下文 ξ_t，在**学生自己生成的动作前缀**上优化 teacher-confidence 加权的 reverse KL，权重 `w = 1 − H(P_φ)/log|V|`，T=1.0，且不加额外 SFT 动作损失。
- **诊断套件**：selector 消融（text-indexed vs VLM-board vs OCR+Text board）、模态消融（w/o visual、w/o procedure）、随机卡/无关卡负对照、以及与 GUI-Actor / UGround / UI-TARS 的 grounding 参照。

## Key Contributions

- Formulates Visual Skill Cards as a *state-conditioned* interface that separates three roles usually conflated in text-only skills: procedure text (what to do), state cues (when it applies), and visual evidence (what the screen should look like) — motivated by the observation that two screens can share text but need different controls, and two controls can look alike but sit in different workflow states.
- Decouples low-cost retrieval from expensive high-resolution evidence expansion, keeping the live screenshot (not the card) as the final grounding source; retrieved evidence is explicitly "reference material, not a coordinate template."
- Shows the same representation serves two consumption modes: external runtime memory for a frozen executor (SkillLens) and privileged training-time supervision for a parameterized student (CardDistill).
- Provides negative controls (random and irrelevant cards) that isolate relevance from prompt-length/extra-image confounds.
- Builds a card corpus of 600 (Mind2Web), 576 (WebLINX-BG), and 510 (OSWorld-G) cards, with an evaluation role split of ~70% web-action / 30% grounding.

## Methodology

Computer use is modeled as a partially observable trajectory τ = (x, o₁, a₁, …, o_T, a_T) conditioned on a natural-language instruction. At step t the benchmark-native context is ξ_t = (x, o_t, h_t). A selector ρ_sel returns a bounded set S_t = ρ_sel(ξ_t; L) with |S_t| ≤ K_e from a library L = L_meta ∪ L_core ∪ L_exec; a deterministic expansion function loads E_t = e(S_t) with |E_t^img| ≤ K_v; and the **frozen** executor predicts a_t = π_θ0(ξ_t, S_t, E_t) with θ₀ unchanged throughout evaluation.

The default selector is purely lexical and deterministic: the query Q(x, h_t, c_t) serializes the instruction, recent history, and selector-visible interface metadata; the coarse score is a clipped token-count overlap Σ min(n(u; q_t), n(u; d_i)) plus a metadata prior b_i(c_t) (site/operation compatibility, zero when unavailable); reranking uses unique-token support overlap |M_t,i| + 0.1·r_i^(0); an optional compatibility gate χ_i(c_t) (default 1) filters the expanded set. Two *diagnostic* selectors render candidates on a "board": VLM-board asks GPT-4o to pick a row directly; OCR+Text board uses DeepSeek-OCR to transcribe up to five candidate rows and reranks textually. Both map back to stable card IDs through the same e(·).

CardDistill trains on-policy: the student samples ŷ_t ∼ π_θ(·|ξ_t), the teacher (with cards) scores those same student-generated prefixes, and the loss is Σ_t Σ_j w_t,j · KL(P_θ,t,j^(T) ‖ P_φ,t,j^(T)), i.e. reverse KL with per-token weights that discount high-entropy (uncertain) teacher targets. At evaluation the teacher and all cards are removed.

Evaluation covers three settings: Multimodal-Mind2Web (offline web action prediction; Step SR, Action F1, Element Acc.), WebLINX-BrowserGym (multi-turn conversational browsing; Overall, Intent Match, Element IoU), and OSWorld-G (desktop UI *grounding only*, not full interactive desktop tasks; Grounding Acc., BBox Hit, Valid Output). Executors span Qwen2.5-VL-3B, Qwen3-VL-2B, Gemini 3.1 Flash-Lite, Gemini 2.5 Flash, GPT-4o, and GPT-5.4-mini. The controlled comparison changes **only** the runtime context: No-skill vs retrieved VSCs.

## Results & Highlights

- **Mind2Web Step SR (GPT-5.4-mini):** 77.2 (No-skill) → **88.8** with VSCs, **+11.6 points**; Action F1 90.1 → 96.4 (+6.3); Element Acc. 88.1 → 92.0 (+3.9).
- **OSWorld-G Grounding Acc. (GPT-5.4-mini):** 45.0 → **66.5** (+21.5), with BBox Hit 43.0 → 65.0 (+22.0). For Qwen3-VL-2B the same metric moves 28.5 → 41.0 (+12.5).
- **WebLINX-BG Overall (GPT-5.4-mini):** 12.8 → **15.7** (+2.9), Intent Match 55.3 → 67.0 (+11.7), Element IoU 17.3 → 19.0 (+1.7). Absolute Overall stays under 16 points for every model tested, so the "improved" regime is still very weak in absolute terms.
- **GPT-4o Mind2Web Step SR:** 65.7 → 82.4 (**+16.7**, the largest Step SR delta in Table 1), yet its OSWorld-G Grounding Acc. only moves 1.5 → 3.5 — a near-floor baseline that suggests GPT-4o cannot emit valid desktop coordinates at all under this protocol.
- **Qwen2.5-VL-3B Valid Output on OSWorld-G:** 68.0 → 99.5 (**+31.5**), i.e. a large share of the small-model "gain" is format/schema compliance induced by the card prompt rather than procedural knowledge.
- **Negative controls (GPT-5.4-mini, 200 cases/condition):** Mind2Web exact Step Acc. 92.0 (retrieved VSC) vs 72.0 (random card, −20.0) vs 71.0 (irrelevant card, −21.0) vs 76.5 (No-skill); OSWorld-G Grounding Acc. 66.5 vs 10.5 (random, −56.0) vs 12.5 (irrelevant, −54.0) vs 45.0 (No-skill). Mis-retrieved cards are *worse than no cards at all* — a strong distraction effect.
- **Selector ablation (200 WebLINX-BG turns, frozen Qwen3-VL-2B):** text-indexed 17.45 Overall / 67.44 IM / 54.50 Dialog Acc. / 1.5s latency vs VLM-board 13.58 / 63.95 / 50.00 / 4.0s; VLM-board wins only on Element IoU (18.98 vs 16.96). The cheap lexical selector beats the GPT-4o-driven one end-to-end at ~2.7× lower latency.
- **Retrieval-only coverage (Table 3):** VLM-board improves Hit@1 from 0.86 → 0.93 (Mind2Web) and 0.40 → 0.55 (WebLINX-BG); OCR+Text board *hurts* WebLINX-BG (0.40 → 0.32, −0.08). On OSWorld-G the plain text-indexed selector already achieves Hit@1 = 1.00, i.e. retrieval is trivially saturated there.
- **Modality ablation contradicts the headline (Table 4):** for Qwen3-VL-2B on Mind2Web, "w/o visual" (text-only cards) reaches **14.0 Step SR vs 10.3 for Full SkillLens**, and 67.5 vs 62.2 Element Acc.; for Gemini 2.5 Flash, "w/o visual" reaches **75.0 vs 66.2 Step SR** and 12.8 vs 10.3 WebLINX Overall. Visual evidence only pays off on OSWorld-G grounding (Gemini 2.5 Flash: 27.5 full vs 10.5 text-only).
- **CardDistill (student-only Qwen3-VL-2B, no runtime retrieval):** +12.0 Step SR on Mind2Web (95% CI [7.5, 17.5]) and +3.2 Overall on WebLINX-BG (95% CI [0.88, 5.85]); vs a shuffled-VSC control the Mind2Web gap is +10.5 (95% CI [5.5, 15.5], p < .001). Plain on-policy distillation without cards and the shuffled-card control are both statistically indistinguishable from the base student on the 200-step evaluation.
- **Grounding reference (Figure 4):** CardDistill lands between GUI-Actor and UI-TARS under a center-in-target-box rescoring — roughly 63.5 vs GUI-Actor 50.5 and UI-TARS 78.0 on Mind2Web, and ~80.5 vs 78.0 and 84.0 on WebLINX-BG. It does *not* beat UI-TARS.

Peking University (Wentao Zhang's group, corresponding author) with ByteDance and Shanghai Jiao Tong University co-authors. Wentao Zhang's lab has a substantial track record in data-centric ML and multimodal systems, and the ByteDance affiliation is consistent with access to the API budget needed to run GPT-5.4-mini, GPT-4o, and two Gemini variants across three benchmarks. The write-up is AAAI-formatted, notation is careful (every retrieval/expansion/cost term is defined), and the related-work section correctly positions the paper against text-centric skill libraries (CUA-Skill, Mirage-1, MMSkills, VisualSkill), optical/visual memory work (DeepSeek-OCR, OCR-Memory, MemOCR, VizoMem, LensVLM), and multimodal on-policy distillation (Vision-OPD, Zhang et al. 2026b). ## Critical Assessment

**Novelty (moderate).** The individual ingredients are all recent prior art: skill libraries for CUAs, selective visual context expansion, and privileged-teacher on-policy distillation. The genuinely new piece is the *unified interface* claim — that one card schema can serve both bounded runtime retrieval and privileged training context — plus the state-cue/verification fields. That is an engineering-integration contribution more than an algorithmic one; the retrieval scorer itself is a hand-tuned lexical overlap (`|M| + 0.1·r^(0)`) with no learned component.

**Rigor (mixed, with one serious internal contradiction).** The negative controls are genuinely good and rare in this literature. But Table 4 undercuts the paper's own framing: on both *web* benchmarks and for both tested executors, removing visual evidence **improves** results (Gemini 2.5 Flash Mind2Web: 75.0 text-only vs 66.2 full; Qwen3-VL-2B: 14.0 vs 10.3). Table 1's headline numbers are reported for Full SkillLens, which is therefore *not* the best configuration on 2 of 3 benchmarks. The paper acknowledges this only obliquely ("modality contributions are task- and executor-dependent") and never reports a text-only column in the main table. For a paper whose title is "*Visual* Skill Cards," this is the central unresolved issue.

**Baselines are thin.** The only comparison is No-skill with the same frozen executor. Every prior skill-library system the paper cites (Mirage-1, CUA-Skill, MMSkills, VisualSkill) is discussed in related work and then never run. A naive retrieval-augmented baseline (e.g. retrieving raw k-shot demonstration steps, or BM25 over trace text without the card schema) is also absent, so we cannot tell how much of the gain comes from the *card schema* versus from "any relevant retrieved context." Similarly, no ablation over card-library size, K_c/K_s/K_e budgets, or number of expanded images.

**Contamination risk / data quirk.** Cards for each benchmark are built from that benchmark's own traces. The construction section mentions an audit that "held-out evaluations do not expose answer coordinates as templates," but no quantitative leakage measurement is reported. The OSWorld-G retrieval numbers make this concrete: Oracle Coverage is 1.00 and text-indexed Hit@1 is **1.00** — a lexical selector that retrieves the exactly-right card on 100% of instances strongly suggests a near one-to-one card↔instance mapping, in which case the +21.5 grounding gain measures "was the answer in the retrieved card" more than reusable procedural memory. Cross-benchmark transfer (Mind2Web cards applied to WebLINX-BG, or vice versa) is never tested, which is exactly the experiment that would settle this.

**Weak-baseline artifacts.** GPT-4o at 1.5% OSWorld-G Grounding Acc. and Qwen2.5-VL-3B at 68.0% Valid Output are broken baselines; deltas measured against them (+2.0, +31.5) say more about output-format compliance than about visual procedural memory. WebLINX-BG Overall never exceeds 15.7 for any model, so a +2.9 absolute delta sits in a regime where the metric itself is barely functional.

**Reproducibility (low).** No code link, no card-library release, no prompt templates in the main text, and no training hyperparameters beyond T = 1.0 and "no additional supervised action loss" (pseudocode is deferred to unreleased supplementary material). Several diagnostics use only 200 turns/cases. Two of the executors — "GPT-5.4-mini" and "Gemini 3.1 Flash-Lite" — are proprietary endpoints that will drift, making the headline +11.6 unreproducible in principle.

**Red flags.** (1) Table 4 contradicting the title, as above. (2) The paper has **no limitations or discussion section at all** — the conclusion is five lines. (3) OSWorld-G is quietly reduced to a grounding-only diagnostic ("the model localizes the target element rather than completing a full interactive desktop task"), so despite three benchmarks there is *zero* end-to-end online task-success evaluation. (4) Cost claims (`C_lens` vs `C_full`) are written as formulas but never instantiated with measured token/latency numbers for the main path — the only latency figure (1.5s vs 4.0s) is from a selector diagnostic.

**Significance (moderate).** If the leakage question is answered cleanly, the CardDistill result is the more durable one: a 2B student gaining +12.0 Step SR from card-conditioned teachers *without runtime retrieval*, with the shuffled-card control at +1.5 equivalent, is a clean demonstration that privileged procedural evidence can be internalized into parameters. That is useful to anyone shipping a small on-device GUI agent where retrieval latency is unaffordable.

## Strengths

- Clean frozen-executor protocol: the executor, prompt template, and expansion budget are held fixed and only the runtime context changes, which makes the No-skill deltas interpretable.
- The random/irrelevant-card negative controls directly rule out "longer prompt + more images" as the explanation, and the finding that mis-retrieved cards fall *below* No-skill (72.0/71.0 vs 76.5 on Mind2Web; 10.5/12.5 vs 45.0 on OSWorld-G) is an honest and practically important negative result about retrieval precision.
- Breadth of executors: 6 models spanning 2B open-weight to frontier proprietary, with a consistent directional trend.
- CardDistill uses proper controls (plain OPD, shuffled VSC) and reports 95% CIs and a p-value rather than bare point estimates.
- Separating retrieval-only coverage (Table 3) from end-to-end utility (Table 2) surfaces a genuinely useful insight: better Hit@1 (VLM-board, 0.40→0.55 on WebLINX-BG) does not translate into better downstream Overall (13.58 vs 17.45).
- The cost decomposition and the "live screen remains the grounding source" design rule are the right architectural commitments for this problem.

## Limitations

- The paper itself contains no limitations section; everything below is inferred from the tables.
- Visual evidence is net-harmful on both web benchmarks (Table 4), which undermines the core "visual" premise and is left unexplained and unaddressed.
- No comparison against any published skill-library or retrieval baseline — the only control is No-skill.
- Card libraries are benchmark-specific and benchmark-derived (600/576/510 cards); no cross-domain transfer, no library-size scaling curve, and no quantified leakage audit despite Hit@1 = 1.00 on OSWorld-G.
- OSWorld-G is grounding-only; no interactive multi-step task success rate is reported anywhere, so claims about "workflows" and "long-horizon patterns" (meta/core cards) go entirely untested — the experiments only use execution-level cards.
- Diagnostics run on 200 turns/cases; some deltas (e.g. WebLINX-BG +2.9 Overall) are small relative to plausible sampling noise at that scale, and no CIs are given for Table 1.
- Retrieval scorer is a hand-tuned lexical heuristic; no embedding-based retriever is compared, so the selector story may not survive a stronger dense baseline.
- Frontier-model results depend on proprietary endpoints (GPT-5.4-mini, Gemini 3.1 Flash-Lite) and no code/data release is announced.

## Relevance

如果关注 GUI/computer-use agent 的记忆与技能复用，这篇给出了一个可审计的模块化接口（构库 / 检索 / 展开 / 执行四段可分别评估），其"错检索的卡片比不给卡片更糟"的负对照结论对任何 RAG-for-agents 系统都有直接工程价值。CardDistill 部分对"把外部记忆蒸馏进小模型参数、推理期免检索"这条路线是一个带对照组和置信区间的正面证据，适合做 2B 级端侧 GUI agent 的参考。

## Questions for Further Exploration

- Given that text-only cards beat Full SkillLens on Mind2Web and WebLINX-BG, what would a learned gate that decides *per step* whether to expand visual evidence achieve — and would it recover the OSWorld-G grounding gain without the web-benchmark regression?
- Is the OSWorld-G Hit@1 = 1.00 the result of near one-to-one card↔instance mapping? Deduplicating cards by target element, or evaluating with cards built from a disjoint set of applications, would settle the leakage question.
- How does SkillLens compare against a schema-free baseline that retrieves raw trace snippets with BM25 or a dense retriever? That isolates the value of the VSC schema from the value of retrieval per se.
- Do the meta and core card levels help at all? Every reported experiment uses execution-level cards, so the hierarchy is currently untested machinery.
- Does CardDistill's advantage persist at larger student scales (7B, 32B), or does it shrink as the student's own priors improve — and does distilling from card-conditioned teachers degrade out-of-distribution GUI generalization?
- What is the actual measured token and wall-clock cost of the main path (C_lens) versus No-skill, and does the +11.6 Step SR survive a compute-matched comparison against simply giving the No-skill executor more reasoning tokens?
- The verification cues (z) define observable postconditions but are never evaluated — can they be used for closed-loop retry, and does that convert step-level gains into task-level success?
