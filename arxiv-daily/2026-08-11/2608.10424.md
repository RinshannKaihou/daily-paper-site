> **一句话总结：** 论文诊断了 AIDE / ML-Master 等 autoresearch 智能体在表格 ML 任务上浪费算力的四种失效模式，并用「全局 debug consultant（跨搜索树共享 bug 注册表）+ 超参调优控制回路 + Thompson Sampling 回溯」三个纯 scaffold 级干预，在冻结底座 GPT-5-mini 的前提下把 AIDE 的 MLE-bench 金牌数从 22 提到 38、有效提交率从 81% 提到 100%、冗余 bug 复现率从 46.0% 降到 7.8%。

> **TL;DR:** On 9 tabular MLE-bench/Kaggle competitions (10 seeds each, GPT-5-mini backbone, 2h budget), a shared "debug consultant" lifts AIDE's gold medals from 22 to 38 and its valid-submission rate from 73/90 to 90/90 (ML-Master: 18 → 29 golds); hyperparameter-tuning guidance adds up to +0.388 graded score on Playground S5E8 over vanilla AIDE; and Thompson-Sampling backtracking cuts null runs from 33/90 to 15/90 (−54.5%) against an AIDE+more-drafts baseline and beats MLEvolve on 5 of 9 competitions (GNSS 0.953 vs 0.928). All gains come from agentic design alone, with the LLM held fixed.

## 核心贡献

- **诊断出四种算力浪费模式**：(1) 搜索树各分支独立重复解同一个 bug（context isolation）；(2) 预算未用尽就因浅层收敛判据提前终止，跳过超参调优阶段；(3) 树搜索实际上不探索，随机回溯困在死路；(4) 智能体会"表演"探索性数据分析（EDA）但不据此做下游决策。
- **Context-aware debug consultant**：把崩溃节点的 traceback 压缩成 (错误类型, 简短签名, 触发策略) 记录，累积进全局共享 bug registry，蒸馏出 BANNED patterns / PROVEN fixes 列表，在 drafting 与 debugging 两级注入 prompt；另加确定性规则（execution timeout、空日志一律判定为终止死路而非可重试噪声）。
- **Budget-aware 超参调优强制机制**：prompt 级指令（additional_notes.txt）+ control-loop 级奖励塑形。每个节点执行后由 LLM rubric 打 0–3 分 HPO 质量分，AIDE 里以 metric_adj = metric_base + 0.1 × s × (r_hpo + r_div + r_corr) 调整节点选择用的指标；弱调优全程惩罚，强调优只在搜索后期奖励（课程式），从而先广度探索、后精细开发。
- **Thompson Sampling + 相似错误回溯**：每个兄弟节点带一个 Beta(α, β) 质量分布（Beta(1,1) 先验），选择时按 θ_i ~ Beta(α_i, β_i) 采样取 argmax，执行后以归一化奖励 r ∈ [0,1] 更新 α ← α + r、β ← β + (1−r)；检测到同一错误沿路径重复出现时，回溯到该错误首次出现的分叉点重采样兄弟节点。
- **对抗性 EDA 诊断实验**：把刻意误导的低保真 EDA 结论注入 agent 上下文，发现性能差异不显著、AIDE 仅在 21% 的运行中承认看到该 EDA、仅 5% 影响特征选择——说明现有 agent 并未把数据分析纳入建模决策。

## Key Contributions

- A failure taxonomy for tree-search MLE agents framed as *wasted compute*: context isolation across branches, premature convergence that abandons unused budget, non-exploratory tree search, and performative-but-unused EDA.
- A **debug consultant** that turns per-branch failures into a global, compressed bug registry with BANNED/PROVEN-fix distillation, injected before every generation and debug step, plus deterministic dead-end rules for timeouts and empty logs.
- **Budget-aware HPO enforcement** at two levels of invasiveness (prompt directive vs. control-loop reward shaping with an LLM 0–3 rubric judged by gpt-4o-2024-08-06), with curriculum reward shaping that penalizes weak tuning always but rewards strong tuning only late in the search.
- **Thompson Sampling node selection with similar-error backtracking**, replacing random sibling choice, plus a widened initial draft pool (5 → 20 nodes) so TS has candidates to allocate across.
- A negative/diagnostic result: injecting adversarial EDA into AIDE and ML-Master changes performance inconsistently and insignificantly; the agents largely ignore analysis they did not themselves produce.
- Cross-scaffold evidence that interventions do **not** transfer for free: the same control-loop HPO intervention that helps AIDE degrades ML-Master, traced to ML-Master's memory module logging crashes as `is_bug: True` without propagating *why*.

## Methodology

The study fixes the backbone LLM (GPT-5-mini) and varies only the agentic scaffold, on two open-source MLE agent frameworks: **AIDE** (deterministic greedy policy π over draft/debug/improve, with a summarization operator Σ) and **ML-Master** (UCT-based MCTS with parallel workers and a reasoning-memory module). Both are evaluated on 9 tabular tasks — Cirrhosis Outcome Prediction, GNSS Classification, Spaceship Titanic, Wine Quality Ordinal, and Kaggle Playground Series S5E3, S5E6, S5E7, S5E8, S5E12 — chosen so their release postdates the LLM knowledge cutoff (leakage control), with moderate dataset size and diverse metrics (accuracy, AUC, RMSE, QWK, log-loss). Scoring uses the official MLE-bench grading scripts on held-out test sets; a run earns a gold medal if it lands in the top 10% of the human leaderboard. Every configuration is run with 10 seeds under a fixed 2-hour, 22-CPU-core budget.

The debug consultant is a four-step control loop: (1) error compression of raw tracebacks into short records; (2) accumulation into a shared registry tracking which strategies failed and, once some node succeeds, which worked; (3) two-level constraint injection — the distilled banned-pattern list appended at drafting/improving, and targeted retrieval of relevant failed strategies plus proven fixes at debugging; (4) deterministic rules halting branches on timeouts and empty logs. A canonical registry entry looks like `BANNED: lgb.train(..., verbose_eval=N) → TypeError` paired with `USE: callbacks=[lgb.log_evaluation(period=N)]`.

For Thompson Sampling the authors are careful about confounds. Because TS is introduced alongside a larger initial draft pool and a new `similar_error_backtracking_threshold`, they run two controlled studies: (a) on AIDE, they set the native `max-debug-depth` equal to the backtracking threshold (rendering it inert) and compare AIDE+20 drafts vs. AIDE+20 drafts+TS, isolating the selection rule; (b) on MLEvolve (Du et al., 2026), an independent strong open-source agent, baseline and TS variants share identical configs and differ only in the candidate-selection strategy.

## Results & Highlights

- **Debug consultant, AIDE (Table 1):** gold medals rise from **22 → 38** out of 90 runs, and valid submissions from **73/90 (81%) → 90/90 (100%)** — all 17 baseline null runs eliminated; win/loss across competitions is 6:3. The largest single-competition gain is Playground S5E3, **0.954 ± 0.015 vs. 0.888 ± 0.010** baseline (baseline earns 0 medals there, treatment 10/10).
- **Debug consultant, ML-Master (Table 1):** gold medals **18 → 29**, with GNSS jumping from **0.813 ± 0.002 → 0.953 ± 0.012** (both conditions valid on 90/90 seeds, so this gain is not a survivorship artifact).
- **Mechanism metrics (Appendix A):** redundant bug re-encounters among AIDE nodes drop from **46.0% → 7.8%**; fraction of nodes that execute without error rises **54.7% → 79.0%** (2,464/4,507 → 2,889/3,655 nodes); first-attempt fix rate after a bug streak rises **41.4% → 72.4%** with mean attempts falling **6.43 → 1.40**; median steps to first valid submission drops **6 → 0** (means 6.8 → 0.4). Pooled Pearson correlation between per-seed valid-node count and OOS score is **r = +0.22 across 163 seeds** (positive in 7 of 9 competitions; Wine r = +0.63).
- **HPO guidance on AIDE (Table 2):** graded score improves on **7 of 9** competitions, with the largest effects **+0.388 ± 0.0005 on S5E8** and **+0.218 ± 0.0006 on S5E12** (prompt+code condition), plus **+0.098 on Spaceship** and **+0.081 on Wine**; GNSS regresses (**−0.030 ± 0.0010**).
- **HPO guidance on ML-Master (Table 11):** effectively null or harmful — largest magnitude is **−0.078 ± 0.0034 on GNSS**, and most deltas are ≤ 0.002. The authors attribute this to the directive pushing ML-Master toward `RandomizedSearchCV`/`GridSearchCV` with XGBoost, triggering an `AttributeError: 'super' object has no attribute '__sklearn_tags__'` version incompatibility that ML-Master's memory logs as a plain bug, causing **up to 12 consecutive identical API failures in a single run**.
- **Thompson Sampling, controlled study on AIDE (Table 16):** with drafts held at 20 in both arms, **null runs fall from 33/90 to 15/90, a 54.5% reduction**, while peak scores are maintained (e.g. Spaceship 0.822 ± 0.002 vs. 0.818 ± 0.005 for the draft-augmented baseline). Per-competition score std also shrinks on 6 of 9 (Cirrhosis 0.014 vs. 0.035; Spaceship 0.006 vs. 0.067).
- **Thompson Sampling on MLEvolve (Table 3):** TS wins **5 of 9** competitions and ties a sixth (S5E7), with the two largest margins **GNSS 0.953 ± 0.005 vs. 0.928 ± 0.011 (+2.5%)** and **S5E12 0.726 ± 0.001 vs. 0.711 ± 0.004 (+1.5%)**, both well outside SEM; the one substantial loss is Wine (**0.406 vs. 0.425**, −1.9%).
- **Case study (Appendix B.3):** on S5E3 seed 6, the baseline burns 74 nodes with only 2 valid (2.7%) re-hitting the same `early_stopping_rounds` TypeError 72 times and ships a single LGBMClassifier (OOS 0.8748); the treatment uses 39 nodes with 31 valid (79.5%) and converges to a 3-model ensemble with Platt scaling and greedy weight optimization (OOS 0.9515, **Δ = +0.077 AUC**). Wine seed 1 shows the same pattern, 2/10 valid → 51/57 valid, **Δ = +0.099 QWK**.
- **EDA diagnostic (Section 4.5, Appendix C.4):** injecting deliberately erroneous EDA produces inconsistent, statistically insignificant performance differences; an LLM judge (gpt-5-2025-08-07) finds agents **never** conducted EDA on their own in baseline runs, acknowledged the injected malicious EDA in only **21%** of AIDE runs, and let it affect feature selection in just **5%**.

## Critical Assessment

**Novelty (moderate).** None of the three ingredients is individually new — shared error memory is close to Agentic Context Engineering (Zhang et al., 2025), and Thompson Sampling for node selection is standard bandit machinery already implicit in MCTS. The contribution is empirical: showing that these cheap scaffold edits recover large amounts of headroom under a frozen LLM, plus the honest cross-scaffold non-transfer finding.

**Rigor (mixed, with one real measurement problem).** The Table 1 headline comparison is contaminated by survivorship: AIDE baseline means are computed only over *valid* seeds, so several baseline columns have n < 10 (Cirrhosis n=9, Wine n=8, S5E6 n=8, S5E8 n=6, S5E12 n=7) while treatment always has n=10. Since null runs are exactly the failures the consultant fixes, the baseline score is conditioned on the baseline having gotten lucky — the reported 6:3 win/loss is therefore a *conservative* score comparison but the medal count (22 → 38) mixes score improvement with null-run elimination and should not be read as pure modeling gain. The ML-Master comparison (90/90 valid in both arms) is the cleaner one.

**Missing ablations.** The debug consultant is evaluated as a monolith, but Step 4 — the deterministic rule that hard-halts branches on timeouts and empty logs — is a trivial engineering fix that could plausibly account for a large share of the valid-rate improvement independently of the LLM-facing bug registry. There is no error-compression-only vs. registry-only vs. injection-only breakdown. Similarly, the TS study on AIDE bundles two changes (5 → 20 initial drafts, plus TS); the authors do disentangle them (Table 16) and to their credit report that more drafts alone already helps, but the headline Table 12 comparison (TS vs. plain AIDE) conflates both and in fact loses on 4 of 9 competitions.

**Cherry-picking / effect-size concerns.** Several "wins" are within noise at the reported precision: S5E7 treatment 0.969 ± 0.001 vs. baseline 0.968 ± 0.000, S5E3 HPO delta +0.014 ± 0.0052, MLEvolve Spaceship 0.815 vs. 0.814. Five of nine tasks are Kaggle *Playground Series* synthetic competitions with extremely dense leaderboards, where a 0.001 metric change can move percentile rank substantially — this makes the medal-count metric more volatile than it looks. There is also no comparison against a classical AutoML baseline (AutoGluon, Auto-sklearn, TPOT, FLAML) even though those are discussed in related work, which would be the obvious sanity check on whether a bug-free LLM agent actually beats a tuned pipeline on tabular data.

**Reproducibility (good but budget-limited).** Code is released, the exact 9 Kaggle competitions are listed with links (Table 19), all prompts (HPO directive, both LLM rubrics, adversarial EDA injection, judge prompts) are given verbatim, per-seed OOS scores are dumped in Tables 7–8, and hyperparameters for TS vs. baseline are tabulated (Table 13). The severe caveat is the **single backbone**: every result uses GPT-5-mini, which the authors openly justify on cost (>1,000 two-hour runs; a frontier model would cost ~10× per token). Whether a stronger model would already avoid the deprecated-API loops — collapsing the consultant's headroom — is untested and is the single biggest external-validity gap.

**Overclaiming to watch.** "Large gains achievable through agentic design alone" is supported for AIDE but explicitly not for ML-Master on the HPO axis, and the ML-Master failure is partly an *environment artifact* (a sklearn/XGBoost version mismatch), not a clean statement about memory architectures. The EDA section is also framed as an agent failure ("agents fail to act on injected EDA"), but the injected EDA was deliberately misleading — an agent that ignores adversarial low-fidelity analysis is arguably behaving correctly. The paper's own control (agents never run EDA at all in baseline runs) is the stronger evidence for the claim; the adversarial-injection result is weak support for it.

## Strengths

- Attacks a genuinely under-measured axis — **reliability and wasted budget** — rather than only mean leaderboard score, and quantifies waste directly (46.0% → 7.8% redundant bugs, 54.7% → 79.0% valid nodes, null-run rates per competition in Table 15).
- Interventions are cheap, model-agnostic, and require no fine-tuning, so they are immediately actionable for anyone running AIDE/ML-Master-style scaffolds.
- Validates TS on a **third, independent agent** (MLEvolve) with all other settings held fixed, which is far stronger evidence than tuning one framework.
- Reports negative and asymmetric results (ML-Master HPO degradation, TS losing on Wine and Cirrhosis) instead of hiding them, and diagnoses the mechanism with actual log excerpts.
- Search-tree visualizations plus full generated code for two case studies make the causal chain (fewer redundant bugs → more valid iterations → ensembles/calibration/threshold optimization emerge) concrete rather than hand-waved.

## Limitations

- Single LLM backbone (GPT-5-mini); no frontier-model replication, so the magnitude of every gain may shrink with a stronger coder that does not repeatedly hit deprecated LightGBM/XGBoost APIs.
- Restricted to **tabular** prediction on 9 competitions, 5 of which are synthetic Playground Series; nothing about vision, NLP, or genuinely open-ended research tasks despite the "autoresearch" framing.
- Baseline means for AIDE are computed over non-null seeds only, so score comparisons are conditioned on baseline success.
- No component-level ablation of the debug consultant; no ablation isolating the deterministic timeout/empty-log rule.
- The bug registry accumulates *environment*-specific constraints (installed library versions in one container); generalization to a different runtime, or registry growth/staleness over long runs, is untested.
- No accounting of the extra LLM-call cost of the consultant and the HPO rubric judge (the 2-hour wall-clock budget is held fixed, but token cost is not reported).
- The authors note in the Discussion that LLMs write near-identical programs repeatedly, so "the tree is wide only on paper" — better selection helps only so much until proposal diversity is fixed, which this work does not address.

## Relevance

对关注 LLM agent scaffold 设计、AutoML/MLE-agent 与 agentic memory 的读者高度相关：它给出了「冻结底座模型、只改 scaffold」这一干预维度的干净量化证据，并且明确指出跨 scaffold 的干预不可自由迁移（同一 HPO 干预帮了 AIDE 却拖垮 ML-Master）。其对 null run（静默失败）率的强调，也为评估 agentic 系统时该不该只报成功运行均值提供了直接的方法论警示。

## Questions for Further Exploration

- Does the debug consultant's advantage survive a frontier backbone (GPT-5.5, Claude Opus 4.8)? If a stronger coder rarely hits deprecated APIs, does the registry collapse to a no-op, or does it shift to encoding higher-level modeling failures?
- Which of the four consultant steps carries the effect? Specifically, how much of the 81% → 100% valid rate is explained by the deterministic timeout/empty-log halting rule alone, with no LLM-facing registry?
- Can the registry be persisted *across* tasks (an environment prior reused on the next competition), and does it become stale or actively harmful when the container changes?
- Since the paper shows valid-node count correlates only weakly with score (pooled r = +0.22), what is the marginal value of the 20th vs. 50th valid node — i.e. where does the iteration-to-quality curve saturate?
- How do these scaffolded agents compare against AutoGluon or Auto-sklearn under the same 2-hour, 22-core budget on the same 9 tasks?
- Would a proposal-diversity intervention (e.g. explicitly forcing structurally distinct drafts) compound with TS, given the authors' observation that LLMs generate near-identical programs and thus that better selection has a low ceiling?
- Is the EDA finding a capability gap or a prompt-design artifact? Injecting *correct, high-fidelity* EDA and measuring whether it improves scores would separate "agents ignore analysis" from "agents correctly discount untrusted context".
