01

How the loop works

SKILLER never touches weights. The optimization variable is the natural-language skill bundle K (a SKILL.md plus optional helper scripts), run on a frozen compact executor (Qwen3.5-9B/4B) inside an OpenCode agent harness. A frontier model (GPT-5.4) plays both actor and critic, used only offline during skill construction.

Each step forms a state si = (x, τi, τ*, vi): the task, the executor's own trajectory, a privileged reference trajectory, and verifier diagnostics. The critic contrasts the two trajectories, localizes the earliest causal error, and emits bounded INSERT / REPLACE / CREATE / DELETE edits (≤30 changed lines). A replay memory plus snapshot-and-rollback guards against regressions.

The winning policy turns out to be structural, not algorithmic: determinism is offloaded out of prose and into short helper scripts (534 words, TF-IDF similarity 0.07, highest LOC of any method). Anti-oracle guardrails reject any merged edit that reuses solver code, precomputed answers, or oracle wrappers.

03

Strengths & limitations

Strengths

  • The optimized artifact is a human-readable, hand-editable file — failures can be inspected and patched directly, not hidden in weights.
  • Ablations are unusually honest about which signal matters: removing the task or trajectory collapses performance to near no-skill.
  • Structural analysis gives a mechanism, not just a leaderboard: low verbosity + low template similarity + high script LOC.
  • Cost accounting does not flatter the method — it openly costs 3.5× EvoSkill at generation time.
  • Negative transfer of baselines is reported, not hidden (Manus, SkillX fall below no-skill on 4B GAIA).

Limitations

  • No variance or significance testing — yet run-to-run swings (±4 pp on SkillLearnBench) match the claimed gains.
  • Abstract overclaims: on 4B, SKILLER loses to SkillX on SkillsBench & GAIA and ties Manus on EarthBench; 9B GAIA is also a tie.
  • Privileged τ* used at optimization time with no proof baselines got equivalent supervision — worth ~15–21 pp.
  • Skill generation & evaluation share the same task on 3/5 benchmarks; true held-out gains (9B) shrink to +1.6 to +1.9 pp.
  • Single executor family (Qwen3.5), single harness (OpenCode), single actor/critic (GPT-5.4) — no ablation on any axis.
04

Open questions

  1. Did AutoSkill, EvoSkill, SkillX, and Manus receive τ*? If not, a strictly τ*-free SKILLER scores ~58.7 on SkillsBench — right next to SkillX's 60.87.
  2. How much of the gain survives swapping GPT-5.4 for an open-weight critic? A 30B driver would make the whole pipeline self-hostable.
  3. Do executor-specific skills transfer across model families (Qwen3.5 → Gemma/Llama), or must the loop re-run per model version?
  4. Given the Step-2 peak then degradation, what is the principled stopping rule — and is the reported number best-step-selected on the test set?
  5. How much of SWE's 82.80% comes from helper scripts that borderline memorize the reference solution vs. genuinely reusable constraints?
  6. Would tied/batched skill optimization (mentioned but not evaluated) close the GAIA gap, where per-instance specialization has no purchase?
