> **一句话总结：** MEGA 把「优化 agent 系统」和「积累可复用知识」合成同一个闭环——三层架构把 agent session 蒸馏成经 A/B 行为验证的 wisdom，再拆成原子 PCR（Primary-Context-Resultant）三元组存入带充分性/必要性双分数的 typed Wisdom Graph，用 PCST（Prize-Collecting Steiner Tree）做组合式检索并把优化证据回灌图谱；在 SkillsBench（84 任务）上通过率 46.5% 对比 SkillNet 41.7%/AgentSkillOS 41.1%/无技能 31.5%，且 token 更省（822k vs 983k/1189k）、curation 延迟仅 11.8s（对手 37.8s/403.4s），在 GPT-4.1 Mini 四基准聚合分 76.55 超过最强基线 GEPA 的 69.52（+7.03，HoVer 单项 +18.00）。

> **TL;DR:** MEGA is a three-layer, self-evolving infrastructure for optimizing agent systems: Layer 1 distills sessions into A/B-validated "wisdom", Layer 2 decomposes it into atomic PCR triplets inside a typed Wisdom Graph (WG-DB) with Pearl-style sufficiency/necessity edge scores and retrieves compositionally via Prize-Collecting Steiner Tree, and Layer 3 runs multi-agent, fixed-seed ("Seed-Epoch") workflow optimization whose evidence flows back to reshape the graph. On SkillsBench (84 tasks, 11 domains, Gemini 3 Flash) it hits 46.5% pass rate vs SkillNet's 41.7% and AgentSkillOS's 41.1% (No-Skills baseline 31.5%) while using fewer tokens (822k vs 983k/1189k per task) and 3.2x/34x lower curation latency; on four GEPA-suite benchmarks with GPT-4.1 Mini it scores 76.55 aggregate vs GEPA's 69.52 (+7.03) and Feedback Descent's 66.56 (+9.99), with the largest single gain on HoVer (74.67 vs 56.67, +18.00). Caveat: it is a company tech report with deliberately partial algorithmic disclosure and zero ablations.

## 核心贡献

- **提出 Wisdom Graph (WG-DB) 作为推理基底**：把每条 wisdom 拆成原子 PCR 三元组 ω = (v_P, v_C, v_R, m)（主动作 / 上下文条件 / 预期结果 / 实现方法），边上带 Pearl 因果演算启发的双轴分数 σ(e) = (Sufficiency, Necessity) ∈ [0,1]²，并采用 role-fluid 节点池（同一概念在一处当 Primary、另一处当 Context），从而在减少节点数的同时形成跨技能连接。
- **在图上做三类逻辑推理补边**：演绎（P→C、C→R 传递推出 P→R，逐跳乘性衰减抑制假阳性）、溯因（P→R 与 C→R 共享结果时反推隐含的 P→C，要求 C→R 的 Necessity 足够高，用贝叶斯后验定置信度）、归纳（多个 P 同连 C 与 R 时用超几何检验判定 C→R 是否显著）。边集单调增长，直到某轮零新增边达到不动点。
- **PCST 组合式检索取代 embedding top-k**：在 WG-DB 的无向投影上求解 Prize-Collecting Steiner Tree（prize 正比于查询相关度、cost 正比于因果弱度），显式捞出与查询相似度低但作为连接器不可或缺的 "bridging wisdom"，并且因为四类 wisdom 共处一图，检索天然是混合类型子图装配。
- **Layer 1 的行为式 A/B 验证准入门**：每条候选 wisdom 由教师-学生协议同时生成配套测试集，在「注入 wisdom」与「不注入」两组下并行执行，用可观测的行为变化（准确率提升 + token 成本变化两条 ROI 轴）而非 LLM 主观打分决定接受/拒绝。
- **Seed-Epoch 归因纪律**：同一 epoch 内所有迭代都在由确定性种子 ξ_e 固定的同一评测子集上打分，使 Δ_i = Acc(D_e, v_i) − Acc(D_e, v_{i−1}) 消除数据方差，把提升归因到策略变更本身；连续 m 次 |Δ_i| < ε 判定饱和后换种子进入新 epoch，天然充当过拟合检验。
- **把数据本身纳入优化范围**：先把评测结构分为离散 checker / rubric / 连续指标三类，各自发现评测维度，再按密度、多样性、基线表现三轴区分「数据覆盖缺口」与「工作流本身问题」，只对前者做定向合成增强（合成比例上限 50%）。

## Key Contributions

- **A unified loop where optimizing an agent and evolving the knowledge that guides optimization are the same process**, formalized as W^(t) = L1(T^(t) ∪ T3^(t−1)), Π^(t) = L2(W^(t), E^(t−1)), (E^(t), T3^(t)) = L3(Π^(t)) — Layer 3 emits both evidence E and new session traces T3 that re-enter Layer 1.
- **Four coexisting wisdom types under shared PCR semantics**: skills (procedural), strategies (decision rules), curation patterns (which items worked in what order under what conditions), and optimization trajectories (which optimization paths succeeded/failed) — the last two are what most skill-library work never stores.
- **Atomic sub-skill decomposition**, positioned explicitly against AgentSkillOS (hierarchical capability tree + DAG) and SkillNet (typed 4-relation skill graph), both of which compose at whole-skill granularity and never infer unrecorded relations.
- **Heterogeneous workflow optimization**: the target is the full tuple (prompt, tool configuration, code logic, orchestration structure) over a graph A = (N, E) containing deterministic code nodes, single LLM calls, and tool-using agent nodes — not just the π-component of LLM-call nodes as in DSPy/MIPROv2/GEPA.
- **ROI-based self-evolving curation**: predicted utility p_i = τ(sim_i, stage_i) × η(ω_i) with a historical transfer rate τ that anneals from prior to empirical mean, an adaptive cold-gate/warm-LCB-gate switch, four-axis composite scoring (similarity, evidence, stage fitness, benchmark), and a Correction Factor CF = E[δ_actual/δ_predicted] that calibrates the system against its own past prediction error.
- **Graph hygiene as a first-class subsystem**: PCR-level deduplication, contradiction resolution via polarity analysis (same P and C but opposing R → keep the stronger-evidence variant, demote the other to a context-bounded judgment), and evidence-triggered content update with external validation.

## Methodology

**Layer 1 (Session-based Wisdom Generation).** Raw agent traces pass client-side privacy filtering (secret masking, path anonymization) before any network egress, then task labeling and evidence grounding. Clustering is two-stage: greedy embedding-similarity domain pre-clustering (domains emerge from data, not predefined), then BIRCH within each domain. BIRCH is chosen for its Clustering Feature tuple CF = (N, LS, SS) whose O(1) additive merge enables a single-pass O(n) sweep over the whole session set, and whose radius threshold R(CF') ≤ T yields an adaptive number of sub-clusters without pre-specifying k — motivated by the argument that the number of behavioral patterns in agent sessions is not knowable a priori. Critically, this separates sessions that are semantically similar but behaviorally distinct (same bug fixed by different strategies) into independent wisdom assets. An LLM then synthesizes each cluster into structured wisdom (generalizing the common pattern plus explicit exception conditions), followed by hash dedup, LLM conflict detection, cross-run embedding dedup, self-evaluation scoring (objective countable properties aggregated by a weighted harmonic mean that penalizes any weak dimension, with self-reported counts cross-checked against an independent parse to prevent self-inflation), and finally behavioral A/B validation.

**Layer 2 (Reasoning and Curation).** A security screening gate first inspects each package for instruction-level threats (prompt injection, workflow hijacking) and execution-level threats (exfiltration, destructive commands). Build-time: PCR decomposition, node normalization, then deductive/abductive/inductive edge expansion with stage-specific acceptance thresholds (minimum causal strength with a log-scaling in-degree penalty for deduction; Bayesian posterior bounds for abduction; hypergeometric significance for induction). Query-time: PCST retrieval produces a mixed-type reasoning subgraph, which is then converted into an execution plan Π(q) by role differentiation — skill nodes become execution candidates, strategy nodes become gating rules and priority constraints, curation patterns supply topological ordering, trajectories bias conservative vs exploratory branches. The output is a linearized plan graph with assigned execution rules, not a top-k list. Post-session, per-wisdom attributions drive three self-evolution axes: individual τ calibration (prior → blended → empirical as observation count crosses k), compositional promotion (promote(c) ⟺ |S(c)| ≥ n_min ∧ r̄(c) ≥ r_min), and content evolution triggers (evolve(ω) ⟺ |U(ω)| ≥ θ_evo), plus offline batch pattern consolidation.

**Layer 3 (Evaluation-Driven Optimization).** The "Adapt" pipeline runs Asset Scan → Adaptive Entry (skip stages whose outputs already exist) → conditional Research Agents (only when eval data or eval code is missing) → Reverse PRD / Data Synthesis (a Reverse Engineer agent reconstructs a Pipeline Requirement Document; a Data Agent can synthesize a stratified evaluation set behind a mandatory human approval gate on seed scenarios) → Seed-Epoch optimization loop → Meta-learning Agent. Over a dozen bounded-responsibility agents participate (Scientist, Code Reviewer, Optimization Agent, Redesign Agent, data workers). Iteration 0 diagnoses: error classification by fixability (prompt-fixable / code-fixable / architecture-required), per-node root-cause vs. downstream-victim separation via error propagation tracing, ROI prioritization by (error rate × case count)/cost, and a five-signal architectural verdict (error concentration, context loss ratio, error type diversity, uniform failure rate across LLM nodes, user goal gap) where ≥3 signals — or the goal-gap signal alone — trigger full redesign. Iterations 1+ apply up to three targeted fixes per round, gated by a Code Reviewer performing static analysis and dry-run testing. Safeguards: anti-heuristic enforcement (only structural transforms like JSON parsing, encoding normalization, null handling, type coercion, error recovery are allowed; regexes matching specific answer formats, per-question-type branches, and input→output lookup tables are prohibited), train/val gap monitoring that restricts the next epoch to prompt-only fixes when the gap is too large, and fixability-based goal calibration that computes a realistic ceiling instead of an arbitrary target. Validation is momentum-triggered — run at baseline, epoch boundaries, and momentum events (regression recovery or new best) — rather than every iteration. Every strategy change yields a Verdict (Δ_acc, Δ_lat, Δ_tok) that updates η(ω) and τ(·) in Layer 2.

## Results & Highlights

**Axis 1 — Wisdom curation quality (SkillsBench, 84 tasks across 11 domains, deterministic pytest verification in isolated Docker containers, binary pass/fail).** Setup: GCP n2d-standard-128, Gemini CLI with Gemini 3 Flash as the agent *and* as the LLM inside every curation pipeline (so no condition gets a stronger model at any stage), 5 attempts per task, 43 concurrent Docker trials, and a shared pool of 4,207 assets that includes SkillsBench's golden skills for all systems. Only the discovery/orchestration method varies.

1. **Pass rate: MEGA (WG) 46.5% vs SkillNet 41.7% (+4.8 pts), AgentSkillOS 41.1% (+5.4 pts), No Skills 31.5% (+15.0 pts).** The two prior skill-orchestration systems land within 0.6 pts of each other despite very different mechanisms, which the authors read as evidence that curation *method*, not skill availability, is the binding constraint.
2. **Token cost per task: MEGA 822k vs SkillNet 983k and AgentSkillOS 1189k — MEGA is the only method that uses *fewer* tokens than the No-Skills baseline (894k) while scoring 15 points higher.** Attributed to injecting only role-differentiated atomic PCR units rather than whole-skill procedural text or a linearized DAG with per-step skill references.
3. **Efficiency (pass rate per megatoken): MEGA 0.566 score/Mtok vs SkillNet 0.424 (+33% relative), AgentSkillOS 0.345 (+64% relative), No Skills 0.353.** Notably AgentSkillOS is *below* the No-Skills efficiency baseline — its accuracy lift does not pay for its token bill.
4. **Curation latency: MEGA 11.8 s/task vs SkillNet 37.8 s (3.2x faster) and AgentSkillOS 403.4 s (34x faster).** Mechanistic explanation given: PCST runs over a pre-indexed graph with subgraph pruning and needs *zero* LLM calls during retrieval, while SkillNet needs 2 LLM calls/task and AgentSkillOS needs a sequential call at each of up to six capability-tree levels plus a DAG planning call.

**Axis 2 — Optimization performance (four GEPA-suite benchmarks on gpt-4.1-mini-2025-04-14).** Each benchmark is paired with a compound AI system from GEPA's released artifact (multi-hop retriever, instruction-following rewriter, claim verifier, privacy-aware delegator), stripped of DSPy/GEPA optimizer scaffolding. Splits (train/val/test): HotpotQA 150/100/300, IFBench 150/100/294, HoVer 150/100/300, PUPA 111/111/221. MIPROv2, TextGrad, and GEPA numbers are cited from the GEPA paper; Feedback Descent from its own paper.

5. **Aggregate score: MEGA 76.55 vs GEPA (best of GEPA and GEPA+Merge) 69.52 → +7.03; vs Feedback Descent 66.56 → +9.99; vs TextGrad 61.08, MIPROv2 59.71, and the unoptimized baseline 52.67 (+23.88 over baseline).**
6. **Per-benchmark: HoVer 74.67 vs GEPA 56.67 (+18.00, the largest gain, attributed to chaining retrieval strategies across hops); IFBench 61.05 vs 55.95 (+5.10); HotpotQA 72.67 vs 69.00 (+3.67); PUPA 97.81 vs 96.46 (+1.35).** The authors concede HotpotQA and PUPA are near the ceiling reachable by workflow/prompt optimization on GPT-4.1 Mini.
7. **Data efficiency claim: MEGA uses smaller validation sets than GEPA's original splits (100 vs 300 on HotpotQA)** and still converges, which the paper reads as needing less validation data — though this is asserted, not measured against a matched-validation-size MEGA run.

## Authors & Credibility

Three authors — Jung Hwan Lee, Kyu Ho Lee, Gwang Hoon Yoo — all with `@megacode.ai` addresses, publishing under the banner "Mind AI Tech Report". This is a commercial lab release, not an academic submission: there is no university affiliation, no funding statement, no acknowledgment section, and no prior publication record established in the document. The related-work section is genuinely well-read and current (GEPA, ACE, ReasoningBank at ICLR 2026; HippoRAG 2 at ICML 2025; AgentSkillOS, SkillNet, ProcMEM, SWE-Exp, Optimas, Feedback Descent), and the authors correctly identify and cite the specific open problem ReasoningBank flags (compositional memory) and Press et al.'s compositionality gap as their motivating framing. Benchmark configurations and per-benchmark results are promised at `github.com/mega-edo/mega_benchmark`, and baseline reproductions cite the exact upstream prompt functions used (`retrieve_relevant_skills_prompt`, `generate_overall_procedure_prompt`, `build_planner_prompt`), which is above-average transparency for a corporate report. The MEGA system itself is not released.

## Critical Assessment

**Novelty (moderate-to-good, but incremental at the component level).** Every individual ingredient has precedent: BIRCH is 1996, PCST retrieval over a knowledge graph is essentially the G-Retriever formulation, sufficiency/necessity scoring is Pearl, fixed-seed evaluation is standard experimental hygiene. The genuinely new claim is the *composition*: sub-skill-granularity PCR decomposition plus three-mode logical edge inference plus evidence write-back, all in one loop. The paper is honest that AgentSkillOS and SkillNet already established structured composition beats flat invocation; MEGA's delta is atomicity + inferred (never-recorded) relations + self-refinement.

**Rigor (the weakest dimension).** *There is not a single ablation in the paper.* Nothing isolates PCST retrieval from embedding top-k, nothing measures how many edges deduction/abduction/induction actually add or whether the inferred edges help, nothing tests Seed-Epoch against resampled evaluation, nothing tests whether the anti-heuristic enforcement or the fixability-based goal calibration matters. Worse, the conclusion pre-empts this by asserting "these results are not attributable to any single layer in isolation" — which converts a missing experiment into a design claim. No seeds, no variance, no confidence intervals, and no significance tests are reported for either table; with 84 binary-verdict tasks, the 46.5% vs 41.7% gap is roughly 4 tasks and could plausibly be within noise across the 5 attempts/task. Section 7.1 states that Table 4 reports "curation ROI — defined as pass-rate improvement per additional megatoken relative to the No Skills baseline", but the table actually reports a differently-defined "Efficiency (score/Mtok)"; since MEGA consumes *fewer* tokens than No Skills, the stated ROI denominator would be negative, so the metric as defined is undefined for the headline method.

**Comparison fairness (mixed).** Section 7.1 is a controlled comparison and is the stronger half. Section 7.2 is not: MEGA is run by the authors while MIPROv2/TextGrad/GEPA/Feedback Descent numbers are *transcribed from other papers*, on validation splits that MEGA deliberately does not match (100 vs 300 on HotpotQA). There is also an internal tension — the baseline row is described both as "cited from GEPA [2]" and as the authors' own DSPy/GEPA-stripped pure workflow used as MEGA's starting point; these cannot both be exactly true, and if MEGA's starting workflow differs from GEPA's, the deltas are not directly comparable. The +18.00 on HoVer is large enough that it should have been the subject of a dedicated investigation rather than a one-sentence hypothesis about hop chaining.

**Contamination risk that is never addressed.** MEGA's 4,207-asset Wisdom Graph is shared between Section 7.1 and Section 7.2, and the paper never states where those assets came from or whether any were distilled from sessions on these same benchmarks. Given that Layer 1's entire premise is distilling wisdom from agent sessions, and that the graph carries "optimization trajectories" recording what worked, a wisdom graph built on HotpotQA/HoVer-like sessions would leak. The competing systems retrieve from the same pool, which mitigates the skill-content side of this — but not the curation-pattern and trajectory side, which only MEGA can use.

**Reproducibility (poor for the system, partial for the evaluation).** The "Scope of Disclosure" section explicitly states that algorithmic details are "selectively disclosed" because parts are proprietary; the ROI section likewise says "detailed parameter settings and statistical assumptions are omitted". Nearly every formula has unspecified constants (T, k, n_min, r_min, θ_evo, θ_cold, θ_warm, θ_c, ε, m, the deduction decay factor, the four-axis weights). No code for MEGA is released. Independent reproduction of the method is effectively impossible; only the benchmark harness is shared.

**Significance.** If the numbers hold, the SkillsBench result is the more interesting one: it says a graph-structured, LLM-free retrieval path beats LLM-driven orchestration on accuracy, cost, *and* latency simultaneously — a rare three-way win, and the 34x latency gap over AgentSkillOS is large enough to survive considerable measurement slop.

**Red flags.** (1) Zero ablations plus an explicit rhetorical defense of having none. (2) Cross-paper baseline transcription with deliberately mismatched validation splits. (3) Proprietary-by-design method disclosure in a document that asks to be evaluated as science. (4) The metric-definition mismatch in Section 7.1. (5) Marketing-adjacent framing throughout ("the optimizer optimizes itself", "collective intelligence substrate"), and a DIKW-pyramid rebranding of "knowledge" as "wisdom" that carries no formal content beyond the PCR tuple itself. (6) The claim that the graph "matures toward delivering effective optimization guidance from the first query alone" is stated as an architectural intention and never tested — there is no cross-project transfer experiment anywhere in the paper, despite transfer being the central thesis.

## Strengths

- The controlled SkillsBench protocol is well-designed: same agent, same 4,207-asset pool (including golden skills), same tasks, same deterministic pytest verifiers, same Docker environment, same model for every LLM component in every pipeline — the only variable is the orchestration method. Using original upstream prompt functions for the baselines is the right call.
- The three-way win (accuracy + tokens + latency) is mechanistically explained rather than merely reported, and the explanation is falsifiable: PCST needs no LLM calls at retrieval time, whereas AgentSkillOS needs up to seven sequential calls.
- Reporting that AgentSkillOS costs 1189k tokens and 403.4 s for a pass rate statistically indistinguishable from SkillNet's much cheaper two-call approach is a useful negative result about the field that the authors were not obliged to surface.
- Seed-Epoch is a genuinely sensible piece of experimental discipline for iterative agent optimization, and the anti-heuristic enforcement list (banning answer-format regexes, per-question-type branches, and input→output lookup tables) shows the authors anticipated the obvious way an LLM optimizer cheats on a training set.
- The distinction between "data coverage gap" and "workflow problem" — a dimension with dense, diverse data but low performance is *not* an augmentation target — is a clean, actionable heuristic.
- The related-work section is unusually good: it correctly locates the gap in each of three literatures rather than strawmanning them, and it names the specific limitation of each competitor (whole-skill composition granularity, static relation labels, no inference of unrecorded relations).

## Limitations

- No ablations at all, so the contribution of PCR atomicity, the three inference modes, PCST bridging, ROI curation, Seed-Epoch, and Layer 3's agent roster cannot be separated.
- No statistical treatment: no seeds, no variance, no CIs, no significance tests, on 84 binary tasks and four benchmarks.
- The central thesis — cross-project compounding, cold-start mitigation, "guidance from the first query" — is entirely untested. Everything reported is single-project performance.
- Section 7.2 baselines are transcribed from other papers under non-identical validation splits and an ambiguous baseline row.
- Method disclosure is intentionally partial; hyperparameters and statistical assumptions are omitted; the system is closed-source.
- Data synthesis is text-only by construction — images, audio, and video are explicitly out of scope, which limits Layer 3 to text pipelines.
- The pipeline is not autonomous: mandatory human gates at intent confirmation, data strategy approval, and architectural feedback. Framed as a virtue, but it means the reported gains include unquantified human input.
- Provenance of the 4,207-asset graph is undocumented, leaving a contamination question open.
- Only two model families are tested (Gemini 3 Flash for curation, GPT-4.1 Mini for optimization), and only small/fast tiers of each — no evidence on whether the gains persist with frontier-tier base models, where the authors themselves note two of four benchmarks are already near ceiling.

## Relevance

这篇直接命中你在「Self-Evolving Agents & Automated Research」方向的兴趣：它给出了一个把 agent 优化证据（verdict 三元组 Δacc/Δlat/Δtok）回灌到知识结构、进而改变下一轮优化起点的具体闭环设计，比多数只谈 memory 或只谈 prompt 优化的工作更接近「recursive agent optimization」的完整形态。同时它也算半个 company technical report（megacode.ai 的 Mind AI Tech Report，且明确声明选择性披露），可以对照你关注的官方技术报告类文档来看——尤其是 Seed-Epoch 那套「固定种子消除数据方差以做归因」的纪律，对做 LLM 评测可复现性的人有直接借鉴价值。

## Questions for Further Exploration

- What fraction of WG-DB edges are *inferred* (deduction/abduction/induction) rather than observed, and what happens to the 46.5% pass rate if all inferred edges are deleted? This is the single most important missing ablation.
- Where did the 4,207 assets come from? Were any distilled from sessions on SkillsBench, HotpotQA, HoVer, IFBench, or PUPA? Without this, the transfer story cannot be separated from contamination.
- Does MEGA still win on SkillsBench if the baselines are given the same token budget (822k) rather than being allowed to inflate context — i.e., is the accuracy gain from better composition or just from a longer effective context that the baselines waste?
- Replace PCST with plain embedding top-k over the same PCR node set: how much of the +4.8 pts is the graph *structure* versus the atomic decomposition alone?
- How does the HoVer +18.00 decompose? Is it a genuine multi-hop composition effect, or a difference in the starting workflow after DSPy/GEPA scaffolding was stripped?
- Does the Correction Factor CF = E[δ_actual/δ_predicted] actually converge in practice, or does it oscillate when the wisdom distribution shifts across projects? No calibration curves are shown.
- Seed-Epoch fixes the eval subset within an epoch — but with only n samples per epoch (Figure 8 suggests 50), how much does the epoch-to-epoch seed change inflate apparent variance, and how is "saturation" (|Δ| < ε for m iterations) distinguished from being stuck in a local optimum?
- Contradiction resolution keeps the variant with "stronger operational evidence" — what protects against an early-lucky wisdom item permanently suppressing a correct competitor via evidence-count feedback loops?
- Can the compositional retrieval half (Layer 2) be released or reimplemented independently? It is the component with the cleanest evidence and the broadest applicability, and it is currently unusable by anyone outside the company.
