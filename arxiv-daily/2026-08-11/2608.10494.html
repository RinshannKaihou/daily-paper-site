Why This Matters

A testable case for layered agent memory: remove the SOP and accuracy falls, remove the graph and trajectory quality falls. Gains hold across five backbones — no fine-tuning required.

Critical Edge

Memory is distilled from trajectories on the very benchmark the system is then scored on — and no held-out, cross-benchmark transfer test exists.

01

Methodology

distilled · ~130 words

GeoForge treats an Earth-observation task as (query, data, answer-space) over a tool library, and demands trajectories respect remote-sensing dataflow: identify modalities and observations before generating products, propagate artifacts downstream, and aggregate only after spatial/temporal compatibility checks. Instead of fine-tuning, each completed trajectory is distilled into three non-parametric memories — a Workflow Graph (order-preserving compressed tool sequence with success/failure counts), Action-Level Experiences (trigger→correction pairs grounded in real tool calls), and an Adapted Skill SOP (procedure, data constraints, sensor semantics). At inference, a hybrid retrieval score (tool-sequence + lexical Jaccard, a task-type bonus, minus a length penalty) injects these as planning priors only; execution is ReAct over a perception-filtered MCP tool space. A safety gate admits only complete, tool-grounded, non-redundant episodes.

Strengths & Limitations

side by side

Strengths

  • Domain-grounded dataflow prior — modality grouping, product-path propagation, and spatial/temporal checks map to real EO pipeline failures, not generic prompting.
  • Clean, testable decomposition — order (graph) / local fixes (experience) / procedure (SOP) fail in different ways under ablation, stronger evidence than a monotone curve.
  • Trajectory metrics reported alongside accuracy — Tool-Any-Order / In-Order / Exact-Match attribute gains to planning, not answer-format luck.
  • Sensible self-evolution guards — the |a_i| > 0 indicator and completeness gate filter ungrounded self-reflections.

Limitations

  • No transfer experiment — memory distilled on Earth-Bench is never tested on ThinkGeo / GeoPlan-Bench; generality is unmeasured.
  • No learning curve, no task-order sensitivity — the three questions that matter most for any self-evolving system.
  • Parameter grounding unsolved — gets worse on 3 of 5 backbones; residual failures concentrate in execution-trace and parameter errors.
  • Uneven modality coverage — strong on Spectrum & derived products, notably weak on plain RGB.
  • No memory-poisoning analysis — a plausible-but-wrong complete trajectory can pass the gate and be reused, unmeasured.

Open Questions

for further exploration
  1. Why does GPT-4o regress (57.98% vs GeoEvolver's 65.59%, Tool-In-Order 37.31 vs 53.20)? Is injected memory exceeding a usable context budget, or is GPT-4o over-literally following the SOP?
  2. Does the memory transfer? Train on Earth-Bench, evaluate zero-shot on ThinkGeo / GeoPlan-Bench, and report the delta against in-domain memory.
  3. How does performance scale with episodes seen, and how sensitive is the final memory to task ordering (shuffle seeds × 5)?
  4. Can the completeness-based safety gate be attacked — inject a confidently-wrong-but-complete trajectory and measure downstream contamination.
  5. Why do the ablation table's full-model trajectory metrics (85.89 / 70.01 / 51.18) disagree with Table 1's GPT-5 row (79.39 / 61.98 / 47.39) at identical accuracy?
  6. Recall_key = 1.00 at Precision_key = 0.70 on GeoPlan-Bench: is the planner over-generating tools, and does the parsimony penalty actually bind at inference?
