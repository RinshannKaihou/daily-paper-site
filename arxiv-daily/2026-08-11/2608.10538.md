> **一句话总结：** SKILLER 把「Agent Skill」文本本身当作可优化的策略，用前沿大模型（GPT-5.4）当 actor 和 critic、把小模型（Qwen3.5-9B/4B）的 agent loop 当作环境，全部 RL 信号（state / reward / policy update）都用自然语言传递、不更新任何权重；在 SkillsBench 上把 Qwen3.5-9B 从 60.87（最强基线 SkillX）推到 73.91，在 SWE-Skills-Bench 上从 62.40（Manus）推到 82.80，且技能生成成本仅 $8.95（SkillX 为 $14.55）。

> **TL;DR:** SKILLER treats a textual agent skill as the RL policy: a frontier model acts as actor+critic, the small model's agent loop is the environment, and all states/rewards/updates flow as natural language with zero weight updates. On SkillsBench with Qwen3.5-9B it reaches 73.91% vs 60.87% for the strongest baseline SkillX (+13.0 pp) and 57.97% for closed-source Manus; on SWE-Skills-Bench it hits 82.80% vs 62.40% for Manus (+20.4 pp), while costing $8.95 in frontier-model tokens versus SkillX's $14.55 for a higher average score (62.86 vs 52.60).

## 核心贡献

- **把技能文本当策略的语言级 RL 框架**：提出 SKILLER，用前沿模型（GPT-5.4 / Claude Opus 4.8 级别）担任 actor 与 critic，把冻结的小模型 agent loop 当作交互环境，benchmark 官方 verifier 作为 reward 来源，全程不做任何梯度更新。
- **结构化状态四元组 + 自然语言 policy iteration**：状态 s_i = (x, τ_i, τ*, v_i)，其中 τ* 是优化期才可见的参考轨迹（运行时对小模型不可见）；critic 做「评估→对比双轨迹→定位最早因果错误→生成有界修改建议」四步，actor 用 Insert/Replace/Create/Delete 四种有界编辑操作施加更新。
- **回放记忆与快照回滚**：Replay memory 保存失败签名、critic 诊断历史、已接受编辑及其结果；每轮存快照，若更新导致回归则回滚到最近通过的版本。
- **面向小模型的「代码外包」范式**：技能被优化成简短提示 + 任务本地 helper 脚本（SKILLER 词数 534、TF-IDF 相似度 0.07、脚本数 2.96、LOC 15,747），把确定性过程从自然语言挪进外部工具，规避小模型的上下文过载。
- **五个 benchmark 的系统评测与成本分析**：SkillsBench、SkillLearnBench、SWE-Skills-Bench、GAIA、EarthBench，对比 AutoSkill / EvoSkill / SkillX 三个开源方法与闭源 Manus，并给出 token 与美元成本对照。

## Key Contributions

- **Skill-as-policy formulation.** The optimization variable is the natural-language skill bundle K (SKILL.md plus optional helper scripts), not model weights: `π_K(a_t | h_t, x) ≜ π(a_t | h_t, x, K)`, with the objective `K* ∈ argmax_K E[r]` where r is the official benchmark verifier score in [0,1].
- **Language-level actor-critic.** Critic `g_i = C_φ(s_i, r_i, K_i, M_i)` emits localized, evidence-backed edit suggestions; actor `Δ_i = A_θ(x, K_i, τ*, g_i, M_i)` applies them via four bounded editing primitives with an explicit diff budget (≤30 changed lines, replacements ≤4 lines).
- **Anti-oracle guardrails.** The reference trajectory τ* is privileged optimization-time evidence only; the released prompts treat references to `solve.sh`, oracle wrappers, pasted solver code, or precomputed answers as critical defects, and merged updates are rejected if they use oracle solver content directly.
- **Component ablations for state, critic, and actor prompts**, isolating which signal actually carries the learning.
- **Cost-performance framing.** Figure 1 positions Qwen3.5-9B + SKILLER at +4.4 pp over Opus 4.7 Max with curated skills at ~167x cheaper output-token price, and Qwen3.5-4B at ~71x cheaper.

## Methodology

The framework is a five-part loop over optimization steps i = 0..I-1. **Environment**: an adapter wraps each benchmark's tool interface, workspace, and official verifier around a frozen compact executor π running inside the OpenCode agent harness; one rollout under skill K_i yields `(τ_i, r_i, v_i) = E(x, K_i; π)`, where τ_i is the trajectory, r_i is binary success or normalized test pass rate, and v_i is verifier diagnostics (per-test outcomes, error messages). **State**: the controller forms `s_i = (x, τ_i, τ*, v_i)`; x is fixed across steps, and pairing τ_i with the reference trajectory τ* exposes not just *that* execution failed but *where* the action sequence first diverged. **Critic**: a frontier model evaluates the skill against x/r_i/v_i, contrasts τ_i with τ*, localizes the earliest causal error (citing the tool-call step index and output snippet, plus the SKILL.md line that should have prevented it), and converts the diagnosis into mechanically applicable INSERT/REPLACE/CREATE/DELETE instructions. **Replay memory** M_i is a compact textual history — failure signatures with diagnostics, critic-summary history, and accepted edits with observed outcomes — fed to both critic and actor, enabling retention or rollback after a regression. **Actor**: applies the bounded edits, preserves content marked effective, and may synthesize deterministic task-local helper scripts invoked from SKILL.md via a single `run_shell` call; it returns one JSON object with complete contents of modified files.

The environment also uses **progressive skill disclosure** so the compact model is not overwhelmed by long context, and supports **batch optimization** over B = {x^(n)} with either per-instance skills or a tied skill updated from aggregated evidence.

Experimental setup: executors are Qwen3.5-9B and Qwen3.5-4B; the frontier actor/critic is GPT-5.4, used *only* offline during skill generation (evaluation tokens consumed by the compact models are excluded from reported generation costs). Benchmarks are a 26-task single-skill subset of SkillsBench, 117 instances across 10 high-difficulty tasks of SWE-Skills-Bench, 100 instances of SkillLearnBench, 165 GAIA validation tasks, and 248 EarthBench samples. GAIA and EarthBench are each treated as one task with a stratified 50/50 split (83 and 124 generation instances respectively) so held-out zero-shot transfer can be measured; for the other three benchmarks a single instance per task generates the skill, which is then evaluated on all instances of that task. All numbers are three-run averages. Appendix E reports 3 optimization rounds for the released SkillsBench config, ≤30 tool steps per rollout, executor temperature 0.2, actor/critic temperature 0.3.

## Results & Highlights

- **SkillsBench (Qwen3.5-9B, pass rate):** SKILLER **73.91%** vs strongest baseline SkillX **60.87%** (**+13.04 pp**); closed-source Manus 57.97%, AutoSkill 53.62%, EvoSkill 50.72%, human-authored 10.14%, no-skill 1.45%.
- **SWE-Skills-Bench (Qwen3.5-9B, pass rate):** SKILLER **82.80%** vs Manus **62.40%** (**+20.40 pp**), SkillX 58.80%, human-authored 52.00%, no-skill 26.20%. On Qwen3.5-4B: SKILLER **66.70%** vs Manus **53.40%** (**+13.30 pp**) — notably higher than 9B running any baseline skill (best 9B baseline is 62.40%).
- **SkillLearnBench (accuracy):** 9B SKILLER **32.11%** vs SkillX **27.78%** (**+4.33 pp**) and human-authored 30.00%; 4B SKILLER **33.00%** vs Manus 31.17% (+1.83 pp).
- **EarthBench:** 9B SKILLER **76.08%** vs AutoSkill 71.77% (**+4.31 pp**) and Manus 71.24%; 4B SKILLER **71.51%**, exactly **tied** with Manus 71.51%.
- **GAIA:** 9B SKILLER **49.40%**, exactly **tied** with SkillX 49.40% (no gain); 4B SKILLER 43.78% **below** SkillX 44.18% (-0.40 pp). SkillsBench on 4B is also a loss: **42.03% vs SkillX 43.48%** (-1.45 pp).
- **Zero-shot held-out splits (Table 2):** 9B GAIA 49.59% vs AutoSkill 47.97% (+1.62 pp), EarthBench 72.31% vs Manus 70.43% (+1.88 pp). 4B GAIA 40.65% vs EvoSkill 34.15% (+6.50 pp), but 4B EarthBench 69.62% **loses** to Manus 70.97%. Both Manus (33.33%) and SkillX (28.86%) fall *below* the 4B no-skill baseline of 34.55% on GAIA.
- **Cost-effectiveness (Table 4, 9B, five-benchmark average):** SKILLER $8.95 / 62.86 avg score vs SkillX $14.55 / 52.60, AutoSkill $2.53 / 48.02, EvoSkill $1.95 / 46.39. SKILLER uses 2.68M input and 0.15M output frontier tokens vs SkillX's 3.61M / 0.37M.
- **Skill structure (Table 3, SkillsBench):** SKILLER 534.33 words with TF-IDF inter-task similarity 0.07 (matching human authors' 0.07) vs AutoSkill 1887.41 words / 0.93 and EvoSkill 1256.98 / 0.89; SKILLER has the most scripts (2.96/task) and highest LOC (15,747).
- **State ablation (Table 5, 9B):** removing x collapses SkillsBench 73.91 → **1.45** (i.e., to the no-skill level) and SWE 82.80 → 20.51; removing τ_i → 2.44 / 24.87; removing τ* → 58.71 / 62.16; removing v_i → 60.87 / 64.50.
- **Critic ablation (Table 6):** w/o Generation is catastrophic — SkillsBench 36.44, SWE 24.90; w/o Locate-Error 58.71 / 64.46; w/o Compare 60.87 / 64.50; w/o Evaluate 60.87 / 68.20.
- **Actor ablation (Table 7):** w/o Scripts is the largest drop — SkillsBench 55.34, SWE 52.30; w/o Preserve 59.18 / 68.20; w/o bounded Operations 68.45 / 77.90.
- **Learning dynamics are non-monotonic (Table 8, SkillLearnBench, 9B):** Step 1 30.33%, Step 2 peaks at 32.11%, then 30.17 / 30.06 / 30.17 for Steps 3-5, with per-run passed-instance counts swinging 25-33 out of 100.

## Critical Assessment

**Novelty (moderate-high).** Textual-gradient / verbal-RL frameworks are a crowded space (Reflexion, TextGrad-style optimizers, and the cited SKILLRL / Skill-Pro / SkillX line). The genuinely new framing here is *executor-specific* optimization: the optimized artifact is explicitly conditioned on which small model will run it, and the paper backs this with the observation that human-authored skills score 10.14% on SkillsBench for 9B while automated ones score 50-74% — the mismatch claim is empirically grounded, not just rhetorical. The most interesting finding is structural rather than algorithmic: the winning policy shifts procedural reasoning *out* of prose and *into* helper scripts (highest LOC, lowest verbosity), and the actor ablation confirms script synthesis is the single largest contributor.

**Rigor (mixed).** Three runs per cell, but **no standard deviations, confidence intervals, or significance tests anywhere**. This matters concretely: Table 8 shows SkillLearnBench run-level counts ranging 25-33/100 for the same skill, i.e. roughly ±4 pp of noise, which is the same magnitude as the headline +4.33 pp SkillLearnBench gain and larger than the +1.8 pp 4B gain. The abstract's claim of "1.8 to 13.3 points for the 4B model" is **not supported by Table 1**: on 4B, SKILLER is *below* SkillX on SkillsBench (42.03 vs 43.48) and on GAIA (43.78 vs 44.18), and exactly tied with Manus on EarthBench (71.51). The 9B GAIA result is also a tie, not a gain. This is straightforward overclaiming in the abstract relative to the authors' own table.

**The privileged reference trajectory is the biggest methodological asymmetry.** SKILLER's state includes τ*, a successful reference solution, at optimization time. The paper never establishes that AutoSkill, EvoSkill, SkillX, or Manus received the same privileged signal — and the state ablation shows that removing τ* alone costs 15 pp on SkillsBench and 21 pp on SWE-Skills-Bench, so this is not a minor input. The authors are clearly aware of the leakage hazard (the critic prompt's very first operation is an anti-oracle audit, and merged updates are rejected for direct oracle use), but "no *direct* oracle use" is a weaker guarantee than "no oracle information," especially when the actor is instructed to "preserve necessary constants, formulas, and schemas."

**Evaluation protocol quirks.** For SkillsBench, SWE-Skills-Bench, and SkillLearnBench, a skill is generated from one instance of a task and then evaluated on *all instances of that same task* — this is closer to per-task fitting than generalization, and only GAIA/EarthBench have true held-out splits (where margins shrink to +1.6 to +1.9 pp on 9B). The SWE-Skills-Bench subset is explicitly filtered to the 10 tasks "for which the original benchmark reports that adding a skill changes performance" — the authors commendably flag that this should not be read as an estimate over the full benchmark, but the 82.80% headline number nonetheless comes from a selection-biased slice, and 20.4 pp is the paper's largest claimed gain.

**Weak baselines and missing comparisons.** The human-authored baseline is remarkably weak (10.14% on SkillsBench, 5.80% on 4B) and is simply absent on GAIA and EarthBench. No-skill on SkillsBench is 1.45%/0.00%, so nearly any structured skill wins there. More importantly: **there is no ablation over the actor/critic model.** Every result uses GPT-5.4; we cannot tell how much of the gain requires a frontier critic versus a mid-tier one, which is the key question for anyone hoping this pipeline is itself cheap. Nor is there an ablation over executor family — everything is Qwen3.5, so "executor-specific" is demonstrated across two sizes of one model family and one harness (OpenCode), never across architectures.

**Internal inconsistency.** The main text says "SKILLER is configured with a five-step reinforcement learning schedule across all tasks," while Appendix E says "the released SkillsBench configuration runs three optimization rounds." Given Table 8 shows the best checkpoint at Step 2 and degradation afterward, the effective number of rounds and the checkpoint-selection rule are load-bearing details that should not be ambiguous — and if the reported number is a *best-step* checkpoint selected using evaluation performance, that is selection on the test set.

**Reproducibility (good-to-fair).** Full critic/actor prompts, temperatures, tool-step limits, split construction, and a code URL are provided. Against that: proprietary GPT-5.4 as actor/critic makes exact reproduction dependent on a closed API snapshot; Manus token usage is admitted to be unavailable, so its $ cost is absent from Table 4; and the benchmark subsets are custom.

**Terminology red flag.** The paper repeatedly calls Qwen3.5-9B/4B "small-scale LVLMs" (Large Vision-Language Models), yet every benchmark used — SkillsBench, SWE-Skills-Bench, SkillLearnBench, GAIA, EarthBench — is evaluated through text/code agent loops with no vision-specific evidence presented. This reads as loose framing rather than a demonstrated multimodal claim.

**Significance (high if it holds).** If a $9 offline optimization can move a 9B model from 26.20% to 82.80% on an SWE agent benchmark, the practical implication — spend frontier tokens once at skill-construction time, then run cheap models forever — is a genuinely useful deployment recipe, and the artifact is interpretable and directly editable by humans.

## Strengths

- The optimized artifact is a human-readable, directly deployable file, not opaque weights; failures can be inspected and hand-patched.
- Ablations are unusually informative and honest about *which* signal matters: removing the task instance or current trajectory collapses performance to near no-skill levels, showing the loop is genuinely grounded in execution evidence rather than generic frontier-model advice.
- The structural analysis (Table 3) offers a mechanistic explanation rather than just a leaderboard: low verbosity + low template similarity + high script LOC, i.e. offloading determinism to code.
- Cost accounting is included and does not flatter the method arbitrarily — SKILLER is 3.5x more expensive than EvoSkill at generation time, and the paper says so.
- Explicit snapshot-and-rollback machinery, plus an acknowledgment in Appendix G that "the final update need not be the most transferable policy," shows the authors noticed and documented their own non-monotonicity.
- Negative transfer of baselines is reported rather than hidden (Manus and SkillX fall below no-skill on 4B GAIA).

## Limitations

- No variance reporting or significance testing, despite run-to-run swings (25-33/100 on SkillLearnBench) comparable to the claimed gains.
- Abstract overclaims: on Qwen3.5-4B, SKILLER loses to SkillX on SkillsBench and GAIA and ties Manus on EarthBench; on 9B it ties on GAIA.
- Privileged reference trajectory τ* is used during optimization with no demonstration that baselines received equivalent supervision; τ* is worth ~15-21 pp per the ablation.
- Skill generation and evaluation share the same task on 3 of 5 benchmarks; true held-out gains (GAIA/EarthBench zero-shot, 9B) are only +1.6 to +1.9 pp.
- SWE-Skills-Bench subset is pre-filtered to skill-sensitive tasks, which inflates the headline +20.4 pp.
- Single executor family (Qwen3.5), single harness (OpenCode), single actor/critic model (GPT-5.4) — no ablation on any of these axes.
- Non-monotonic optimization with an ambiguous stopping rule (3 vs 5 rounds; best checkpoint at Step 2) raises checkpoint-selection concerns.
- Procedural constraints cannot supply missing factual knowledge or math — the authors concede this explains the flat GAIA results, which is the one benchmark testing open-ended multi-hop retrieval.
- Reported generation costs exclude all executor rollout tokens, so the true end-to-end optimization cost is higher than $8.95.
- "LVLM" framing is unsupported by any vision experiment.

## Relevance

如果你关注「用小模型 + 结构化技能/提示替代昂贵闭源模型」的落地路线，这篇提供了一个可直接复用的配方：一次性花前沿模型 token 做离线技能优化，产出可读、可手改的 SKILL.md + helper 脚本，之后推理端全跑 9B/4B。其中「把确定性流程从自然语言外包到脚本」和「critic 必须输出有界可执行编辑而非诊断」两个发现，对任何做 prompt/skill 自动优化、agent harness 工程或 LLM-as-judge 反馈闭环的工作都有直接借鉴价值。

## Questions for Further Exploration

- Do the baselines (AutoSkill, EvoSkill, SkillX, Manus) receive the reference trajectory τ*? If not, what does SKILLER score in a strictly τ*-free setting across all five benchmarks — the ablation suggests roughly 58.71 on SkillsBench, which would put it close to SkillX's 60.87.
- How much of the gain survives swapping GPT-5.4 for a mid-tier or open-weight critic? If a 30B open model can drive the loop, the whole pipeline becomes self-hosted and the cost argument gets much stronger.
- Does an executor-specific skill transfer across model families (Qwen3.5-9B → Gemma 4 or Llama-class), or is the specialization brittle in a way that would require re-running the loop per model version?
- Given the Step-2 peak on SkillLearnBench, what is the principled stopping criterion? Would a validation-split-based early stop change the headline numbers?
- How much of the SWE-Skills-Bench 82.80% comes from helper scripts encoding task-specific solutions that borderline memorize the reference solution, versus genuinely reusable procedural constraints? A diff-level audit of generated scripts against τ* would settle the oracle-leakage question.
- Would tied/batched skill optimization across related instances (mentioned in the method but not evaluated separately) close the gap on GAIA, where per-instance specialization has no purchase?
- Since human-authored skills score 10.14% on 9B, would a human given the same critic diagnostics do better — i.e., is the frontier actor necessary, or is the *feedback channel* the real contribution?
