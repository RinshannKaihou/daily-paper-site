01Methodology

Once a faulty memory record has been consumed, the method treats it as a provenance root. A directed heterogeneous graph G is built over user-input, execution-step, and memory nodes from runtime fields (used_ids, derived_from, supersedes, timestamps) — construction is fault-agnostic and never touches benchmark annotations. Pure temporal “chain” edges are excluded: occurring later is not evidence of contamination.

From each faulty memory’s provenance seed, forward reachability yields an over-approximate candidate set A₀. Independent-support checking then prunes it: a node survives iff it has an admissible trusted predecessor — a current-turn instruction, an undiagnosed memory, a successful tool observation, or an unaffected verified claim — lying outside the fault set. Diagnosed faults are never preservable, and preservation is deliberately non-recursive (so mutually dependent nodes can’t bootstrap each other’s validity).

A deterministic planner (no optimization, no LLM deciding what to undo) deletes the faults, quarantines unsupported dependents, and replays only the answer-relevant closure: nodes that still reach the final answer once severed memories are removed. Observations are never regenerated directly — the generating tool action is re-issued. The scope is agent-maintained state only; irreversible external side effects need resettable or compensating tool interfaces.

03The trade-off

Strengths

  • Clean problem framing. “Fault removal is not state recovery” separates this from the crowded memory-detection and self-refinement literatures.
  • Deterministic, rule-guided planner — not an LLM deciding what to undo. Auditable, and the reason cost lands below the LLM-judge baseline instead of above it.
  • Cost as a first-class metric (replay ratio, LLM calls, tokens). The selective-replay ablation exposes the recurrence-vs-cost trade-off instead of hiding it: 0.071 recurrence at 24.0 calls vs 0.266 at 5.7.
  • Unusually candid. Reports the recurrence caveat, a backbone where the baseline wins, and the poisoned-fault explanation for the transfer F1 win — rather than burying them.

Limitations

  • Needs a fully instrumented runtime emitting typed provenance. No robustness study on noisy or partial provenance; raw-NL-log inference is out of scope.
  • Diagnosis assumed given. Real deployments must pair this with a detector whose false positives/negatives compound — none of that error is modeled.
  • Claim-inv F1 of 0.566 on the controlled set: it recovers answers without faithfully reconstructing traces — 0.38 below the LLM-judge baseline.
  • Cannot undo irreversible external side effects; re-execution needs resettable / idempotent / compensating tool interfaces.
  • Small, partly author-constructed benchmarks (150 / 50); multi-fault buckets (n=17, n=5) too small. Single run, no variance; no MemoRepair comparison; no code release visible.
