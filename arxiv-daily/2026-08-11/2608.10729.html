Why this matters

A provably optimal, seconds-to-calibrate threshold for when to stop spending compute on LLM refinement — a drop-in rule for any verifier-in-the-loop agent pipeline.

▲ Critical edge

The headline theorem follows almost trivially from the best-so-far state definition — and the evaluation metric is identical to the objective the threshold was tuned on.

Theoretical collapse — three propositionsProps. 2 → 4

Prop. 2

The optimal stopping set is an upper-closed interval [αk, 1] — the policy is a threshold.

→

Prop. 3

That threshold is non-increasing in the stage k — waiting gets cheaper late.

→

Prop. 4

Best-so-far retention pins it: one stage-independent scalar α* suffices.

Net effect: the policy search shrinks from a sequence of functions μ₀…μN−1 to a single 1-D optimization — solvable in seconds with SPSA / cross-entropy / differential evolution.

Methodologydistilled

Each refinement iteration emits code, scored x̃ ∈ [0,1] by a fused correctness + runtime + memory metric — a hard zero if any test fails. The state is the best-so-far score xk = max{xk−1, x̃k}, fed back to a stopping policy.

The paper identifies three primitives from real EFFIBENCH runs (N = 10 iterations, 50 tasks × 3 frontier models): per-iteration cost c at actual March-2026 token pricing; payoff g(x) = βx (β is a design knob, not estimated); and transition dynamics f via a Gaussian-process regression — Matérn-5/2 kernel, prior mean m(x) = x.

Two empirical properties fall out of the GP: monotonicity (quality never decreases) and diminishing returns (gains shrink at high scores). Treated as exact, these collapse the DP recursion Vk*(x) = max{g(x), −c + E[V*k+1(f(x,w))]} into a single scalar. The threshold α* is then found by 1-D stochastic optimization over the GP simulator, evaluated on 50 disjoint problems with 3 seeds.

Assessmenttwo-sided

Strengths

  • Turns a hidden knob (iteration count) into an explicit, dollar-tied decision variable.
  • Scalar-threshold reduction makes optimization trivially cheap — seconds on an M4 Pro.
  • Grounded in real per-token pricing from three commercial models, not a synthetic cost model.
  • Proper identification/evaluation split on disjoint EFFIBENCH problems; 3 seeds; variance reported everywhere.
  • Useful standalone finding: gains saturate after 3–4 iterations while cost grows linearly.

Limitations

  • Single benchmark (EFFIBENCH), single modality (code), only 50 evaluation tasks.
  • Linear payoff g(x) = βx with β unestimated — no principled procedure to choose it in deployment.
  • Constant cost c ignores the growing context length across refinement iterations.
  • Best-so-far state assumes a perfect verifier; noisy/gameable judges break monotonicity and Prop. 4.
  • Policy acts on a scalar only — richer feedback (error messages, partial test results) is discarded.

Questions for further exploration7 open

  1. Does the threshold still win when the metric is not the training objective — e.g. pass rate or speedup at matched dollar budget?
  2. How much of the gap to UCB vanishes if UCB is given a continuous, not 0.1-resolution, threshold grid?
  3. What happens under a noisy or partially adversarial verifier, so xk = max{xk−1, x̃k} no longer holds — does stage-independence survive a POMDP belief-state reformulation?
  4. Can GP posterior variance certify the threshold structure with probability 1 − δ, instead of assuming Observations 1–2 exactly?
  5. Does a single global α* transfer across task-difficulty strata, or would a feature-conditioned threshold do materially better?
  6. How does the framework extend to multi-stop / branch settings (sample k candidates) closer to modern best-of-n + refine agents?
  7. How brittle are the learned thresholds to the fast-moving price/quality frontier of frontier-model APIs?
