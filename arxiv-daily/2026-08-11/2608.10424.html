81%→100%

Valid MLE-bench submissions, AIDE

73/90 → 90/90 — every silent null run eliminated.

Why this matters

Cleanest evidence yet that scaffold edits — not bigger models — recover wasted LLM-agent compute, with the stark caveat that gains don't transfer between frameworks.

Critical edge

Every result rests on one backbone — GPT-5-mini; a stronger coder might never hit those deprecated LightGBM loops, collapsing the consultant's headroom entirely.

01 Methodology

The backbone LLM is fixed at GPT-5-mini; only the agentic scaffold varies.

Evaluated on two open MLE-agent frameworks — AIDE (greedy draft / debug / improve policy) and ML-Master (UCT-based MCTS with a reasoning-memory module) — plus a third, MLEvolve, used only as an independent control for Thompson Sampling. Nine tabular Kaggle / MLE-bench tasks were chosen to postdate the LLM's knowledge cutoff (leakage control); scoring uses the official MLE-bench graders, and a run medals if it reaches the top 10% of the human leaderboard. Every configuration runs 10 seeds under a fixed 2-hour, 22-CPU-core budget.

Three interventions, all scaffold-level: (1) a context-aware debug consultant sharing a compressed bug registry across the whole search tree; (2) budget-aware hyperparameter-tuning enforcement via prompt directive plus a reward-shaped control loop; (3) Thompson-Sampling node selection with similar-error backtracking.

02 Four modes of wasted compute

The paper's diagnosis — where tree-search MLE agents burn budget for nothing.

01
Context isolation

Each branch independently re-solves the same bug; failures don't propagate.

02
Premature convergence

Shallow criteria quit early, abandoning unused budget and skipping HPO.

03
Non-exploratory search

Random backtracking gets stuck in dead ends; the "tree" doesn't explore.

04
Performative EDA

Exploratory analysis is staged but never informs downstream modeling decisions.

04 Strengths

  • Quantifies an under-measured axis — reliability & wasted budget — not just mean leaderboard score.
  • Interventions are cheap, model-agnostic, and need no fine-tuning: immediately actionable.
  • Validates Thompson Sampling on a third, independent agent (MLEvolve) with settings held fixed.
  • Reports negative & asymmetric results (ML-Master HPO degrades) and diagnoses the mechanism with real log excerpts.

05 Limitations

  • Single backbone (GPT-5-mini); no frontier-model replication — every gain may shrink with a stronger coder.
  • Only 9 tabular tasks (5 synthetic); no vision / NLP despite the "autoresearch" framing.
  • AIDE baseline means condition on non-null seeds → survivorship bias in headline comparisons.
  • No component ablation of the debug consultant; the deterministic timeout / empty-log rule is unisolated.
  • Bug registry encodes environment-specific library versions; cross-runtime generalization untested.

06 Open questions

  1. Does the consultant's edge survive a frontier backbone (GPT-5.5, Claude Opus 4.8), or does the registry collapse to a no-op?
  2. How much of the 81%→100% valid rate is the deterministic timeout / empty-log rule alone — with no LLM-facing registry?
  3. Can the registry persist across tasks as an environment prior, or does it go stale when the container changes?
  4. Given valid-node count correlates weakly with score (pooled r = +0.22), where does the iteration-to-quality curve saturate?
  5. How do these scaffolded agents compare to AutoGluon / Auto-sklearn under the same 2h, 22-core budget?
  6. Would a proposal-diversity intervention compound with TS, given that LLMs emit near-identical programs?
