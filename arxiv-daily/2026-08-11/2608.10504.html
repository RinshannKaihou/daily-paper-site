01

Method — one closed loop, three layers

distilled from §Methodology

Layer 1

Wisdom generation

Agent traces are privacy-filtered, then two-stage clustered: an embedding pre-cluster plus a BIRCH single-pass O(n) sweep whose radius threshold sets the cluster count without a preset k.

An LLM synthesizes each cluster into structured wisdom; hash + embedding dedup and conflict detection follow. Admission is a behavioral A/B gate: a teacher–student pair generates a matched test set, and a wisdom is kept only if "with" beats "without" on both accuracy and token cost — never on an LLM self-score.

Layer 2

Reasoning & curation

Wisdom is decomposed into atomic PCR triplets (Primary action, Context, Resultant) with sufficiency/necessity edge scores, then three inference modes — deductive (transitive), abductive, inductive (hypergeometric test) — add edges to a fixed point.

Retrieval solves a Prize-Collecting Steiner Tree on the undirected projection, explicitly surfacing low-similarity "bridging" wisdom — with zero LLM calls at query time.

Layer 3

Evaluation-driven optimization

A multi-agent "Adapt" pipeline: Research → Reverse-PRD / human-gated data synthesis → Seed-Epoch loop → Meta-learning.

Seed-Epoch fixes the eval subset per epoch so each Δ attributes to the strategy change, not data variance; a Code Reviewer gates every fix; anti-heuristic rules ban answer-format regexes and input→output lookup tables.

W(t) = L1(T(t) ∪ T3(t−1))  ·  Π(t) = L2(W(t), E(t−1))  ·  (E(t), T3(t)) = L3(Π(t))   — the loop's recurrence: Layer 3 emits evidence E and new traces T3 that re-enter Layer 1.

03

Trade-offs — strengths vs. caveats

side by side

◢ Strengths

  • Controlled protocol. SkillsBench holds agent, 4,207-asset pool (incl. golden skills), tasks, deterministic pytest verifiers, Docker, and model fixed — only orchestration varies. Original upstream prompt functions used for baselines.
  • A falsifiable three-way win. Accuracy + tokens + latency explained mechanistically: PCST needs zero LLM calls at retrieval, vs AgentSkillOS's up to seven sequential calls.
  • Real experimental discipline. Seed-Epoch attribution + an anti-heuristic list (banning answer-format regexes, per-type branches, lookup tables) show the authors anticipated how an LLM optimizer cheats.
  • Useful negative result. AgentSkillOS costs 1189k tokens / 403s for a pass rate indistinguishable from SkillNet's far cheaper two-call approach.

◣ Caveats

  • No ablations at all. PCR atomicity, the three inference modes, PCST bridging, ROI curation, Seed-Epoch, and the agent roster are never isolated — and the paper pre-empts the absence as a design claim.
  • No statistics. No seeds, variance, CIs, or significance tests; on 84 binary tasks, 46.5% vs 41.7% is ≈ 4 tasks and could sit inside noise.
  • Central thesis untested. Cross-project compounding / cold-start is the whole point — every reported result is single-project.
  • Transcribed baselines. Axis-2 numbers come from other papers under mismatched validation splits (100 vs 300 on HotpotQA) and an ambiguous baseline row.
  • Partial disclosure. Hyperparameters and statistical assumptions omitted; system is closed-source; the 4,207-asset graph's provenance is undocumented → open contamination risk.
04

Open questions for further exploration

the missing experiments
Q1 · key ablation What fraction of WG-DB edges are inferred (deduction/abduction/induction) vs observed — and what happens to the 46.5% pass rate if all inferred edges are deleted?
Q2 · contamination Where did the 4,207 assets come from? Were any distilled from sessions on SkillsBench, HotpotQA, HoVer, IFBench, or PUPA? Without this, transfer can't be separated from leakage.
Q3 · fair budget Does MEGA still win if baselines get the same 822k token budget rather than inflating context — i.e., is the gain better composition or just a longer effective context the baselines waste?
Q4 · structure vs atoms Replace PCST with plain embedding top-k over the same PCR node set: how much of the +4.8 pts is the graph structure versus atomic decomposition alone?
Q5 · HoVer decomposition How does the +18.00 on HoVer break down — a genuine multi-hop composition effect, or a difference in the starting workflow after DSPy/GEPA scaffolding was stripped?
Q6 · calibration Does the Correction Factor CF = E[δ_actual/δ_predicted] actually converge in practice, or oscillate when the wisdom distribution shifts across projects? No calibration curves are shown.
