> **一句话总结：** AWS AI Labs 的 FreeEvolve 把"进化器怎么组织搜索"这一最后仍由人手写的环节也交给 LLM：进化器（Claude Code）在一次调用内自主决定评什么任务、花多少算力、何时停止（campaign autonomy），并通过元进化把这套组织策略练成一个可冻结、可跨环境复用的 evolution skill——在 τ³-bench、ARC-AGI-2、ARC-AGI-3、Terminal-Bench 2.1 上，held-out 主指标相对 base agent 平均提升 13.6 分，其中 τ³-bench 均值 33.3→51.7（最强手工进化器基线 EvoX/HyperAgents 仅 36.8）。

> **TL;DR:** Agent evolvers (GEPA, OpenEvolve, EvoX, HyperAgents) automate *what* gets edited in an agent harness but keep a human-designed search loop that fixes which tasks to evaluate, how to compare candidates, and when to stop. FreeEvolve removes that loop: an evolver agent (Claude Code + a markdown "evolution skill") is invoked once inside a bounded environment and autonomously organizes the whole improvement campaign; the skill itself is then improved by meta-evolution, where candidate skills are judged by complete worker campaigns they run. On four held-out benchmarks it averages +13.6 points over the base agent — e.g., τ³-bench mean 51.7 vs 36.8 for the best expert-designed evolver (EvoX/HyperAgents, +14.9) — and the frozen meta-evolved skill transfers to fresh workers, adding 6.9 points on average over a seed skill (+13.8 on τ³-bench mean: 47.1 vs 33.3).

## 核心贡献

- **指出并填补"最后一块人工环节"**：现有 agent evolver 只自动化 harness 本身（prompt/skill/workflow），而搜索循环（评哪些任务、评估预算、接受规则、分支与停止）仍由人预先设计。FreeEvolve 提出核心问题："优化过程本身能否被进化器自己组织并从经验中学会？"
- **Campaign autonomy（有界自主）**：形式化一个有界环境 `E[x₀] = (g, D, x₀, R_E, C_E)`——目标、数据、可编辑对象、执行函数、合法请求都被环境固定；进化器作为普通 agent 被调用**一次**，此后每一次执行请求（选任务、重复次数、并发、超时、分支、停止）都由它自己决定，没有外部循环。
- **Meta-evolution（元进化）**：把 campaign 策略表示为可编辑的 evolution skill（一份 SKILL.md markdown 文件）。外层进化器用完全相同的 Evolve 接口编辑该 skill，候选 skill 的评分是它所跑出的完整 worker 进化战役的结果（worker 及其 trace），而非孤立打分。学到的 skill 可冻结并安装到全新的 worker/环境/模型上，不携带源 worker 或 campaign 状态。
- **实证结论**：无手工循环的自主学习达到或超过专家设计的进化器；元进化让过程本身随经验变强（seed skill 几乎无效、元进化后显著有效），且 skill 可跨环境、跨模型迁移；模型能力存在明显门槛（约 Sonnet 4.6 起才有效）。

## Key Contributions

- Conceptually identifies the hand-designed search loop as the last manual component of agent evolution and recasts it as a **campaign policy that the evolver executes and that can be learned from experience**, rather than a fixed piece of engineering.
- Technically, gives the evolver **campaign autonomy** via a bounded environment interface (goal, editable target, data, execution function, valid-request constraints are fixed; every execution request is the evolver's choice), and makes that control improvable through **meta-evolution**: the campaign policy is a self-contained, editable "evolution skill" (a SKILL.md file) judged by the complete worker campaigns it organizes.
- Empirically, without any hand-designed loop, FreeEvolve matches or exceeds four expert-designed evolvers (GEPA, OpenEvolve, EvoX, HyperAgents) across seven held-out metrics over four environments (+13.6 points on average on primary metrics vs the base agent); the meta-evolved skill is reusable and transfers across environments and to cheaper worker models, and token-efficiency analysis shows it reaches a worker quality no baseline attains at twice the token cost (ARC-AGI-3).

## Methodology

**Bounded environment interface.** An environment initialized with target x₀ is a tuple `(g, D, x₀, R_E, C_E)`: improvement goal g, available data D, initial editable target x₀, execution function `R_E(x, u)` which runs candidate x under an execution request u and returns an artifact bundle (scores, trajectories, logs), and constraint set C_E bounding resources (concurrency, timeouts). Crucially, the interface fixes *what* interactions are possible but does not prescribe *when or in what order* they are used.

**Campaign autonomy.** The evolver is an agent (instantiated as Claude Code equipped with a self-contained evolution skill — a markdown SKILL.md) that receives this interface and runs the entire campaign in a single invocation: `x* = Evolve(s, E[x₀])`. Every environmental execution — which tasks to evaluate, how many repetitions, concurrency, timeouts, branching, when to accept or stop — is chosen by the evolver as evidence arrives; there is no external loop fixing the number of executions or the stopping decision. Only two human-designed components remain, neither an evolution loop: Claude Code's generic agent loop, and the seed skill that fixes dispositions only (treat the environment as source of truth, keep all evidence, continue from the best-supported target, use the time budget).

**Meta-evolution.** The same machinery is applied one level up: a meta-environment whose editable target is the evolution skill s₀ and whose data are worker environments. The outer evolver edits a copy of s₀, launches complete worker-evolution campaigns (each running an inner Evolve), and judges candidate skills only through the workers and traces they produce (`R_m(s, u) = EvaluateWorkers(...)`). Candidate skills are excluded from the inner environments' catalogue, bounding nesting at two levels. Meta-evolution receives a 24-hour outer campaign on a Slurm cluster with five worker nodes (≤5 concurrent inner campaigns); standalone worker evolution gets a 12-hour budget on one 128-CPU machine.

**Evaluation protocol.** All benchmarks use fixed evolution/held-out splits created before any run (τ³-bench banking-knowledge: 68/29 tasks; ARC-AGI-2: 56/111; ARC-AGI-3: 17/8 games; Terminal-Bench 2.1: 61 held-out). Each method searches only on the evolution partition; the final artifact is selected by its own rules before the held-out set is revealed. Held-out evaluation is repeated three times (mean ± s.d.), plus pass@3 where defined. ARC-AGI-3 reports RHAE (Relative Human-Action Efficiency, a human-normalized efficiency score); the others report mean score and pass@3. All partitions of a benchmark are shared across all compared methods; experiments use Claude models throughout (e.g., τ³-bench worker on Opus 4.8, ARC-AGI-2 solver on Claude 4.7 Opus, ARC-AGI-3 agent on Claude Opus 5).

## Results & Highlights

- **Headline (Table 1, held-out, vs best expert-designed baseline):** FreeEvolve reaches τ³-bench mean **51.7±6.0** / pass@3 **69.0** vs 36.8±3.5 / 58.6 for the best baselines (EvoX/HyperAgents); ARC-AGI-2 mean **69.1±5.4** / pass@3 **86.5** vs 64.0±0.4 / 80.0 for EvoX; ARC-AGI-3 RHAE **81.6±3.0** vs 72.1±2.8 for HyperAgents. On Terminal-Bench 2.1 it scores mean **82.5±2.5** vs GEPA's **84.7±2.4** (trailing GEPA) but achieves the best pass@3 **93.4** vs 91.8. Across the four primary metrics this is **+13.6 points on average over the base agent** (base: 33.3 / 55.4 / 61.0 / 80.9).
- **Meta-evolution beats autonomy alone (Table 6 / Figure 3, fresh workers):** the hand-written seed skill gains only **0.6 points on average** over the base worker across the four mean metrics; the meta-evolved skill adds a further **6.9 points over the seed** (τ³-bench 47.1±8.7 vs seed 33.3, +13.8; RHAE 70.3±3.2 vs 61.7, +8.6; ARC-AGI-2 59.8 vs 56.5; TB2.1 83.1 vs 81.4) and outperforms a no-data LLM rewrite of the skill in all four environments (e.g., τ³-bench 47.1 vs 37.9).
- **Cross-environment transfer (Table 2):** a skill meta-evolved on τ³-bench, frozen and installed on fresh workers, reaches **64.3±2.8** mean on ARC-AGI-2 (exceeding the 58.0±1.9 of the skill meta-evolved in-env) and **71.0±6.4 RHAE** on ARC-AGI-3. Single-source transfer degrades Terminal-Bench mean (74.3–76.5 vs seed 81.4); jointly meta-evolving on τ³-bench + TB2.1 improves every target metric (e.g., TB2.1 82.5±4.1 / pass@3 91.8 vs seed 81.4 / 86.9).
- **Cross-model transfer (Figure 4a / Table 10):** frozen harnesses evaluated with Sonnet 4.6 and Haiku 4.5 — FreeEvolve is the strongest evolved harness in all six settings, e.g., τ³-bench with Haiku 4.5: **30.7** vs base 17.2 and EvoX 9.9; average +5.3 points over base across the four non-native settings where several baselines shrink or reverse.
- **Token efficiency (Figure 4b):** by **0.71B tokens** of total evolver budget on ARC-AGI-3, FreeEvolve's skill produces a worker whose training RHAE (86.9 at ~1.4B) is a score no baseline attains with more than twice the token cost.
- **Evolver-model ablation (Table 7, τ³-bench):** Haiku 4.5 as evolver yields 32.2 held-out mean (no gain vs 33.3 base); Sonnet 4.6 → 47.2; Opus 4.6 → 40.2 (notably *worse* than Sonnet 4.6); Opus 4.7 → 49.4; Opus 4.8 → 51.7 — a clear capability threshold with one inversion.
- **Fixed-decision ablation (Table 4):** forcing each campaign decision (always full evaluation set: 39.1; fixed concurrency 24: 43.7; no timeout: 44.8) yields a worse worker (evolver-controlled: **47.1**) at fewer or more tokens — the benefit is adaptive reorganization, not a single optimal configuration.

## Authors & Credibility

The paper comes from **AWS AI Labs** (Lecheng Kong, Like Hui, Nikos Kanakaris, Sahika Genc, Narayanan Sadagopan) with Prithwish Jana (Georgia Tech, intern). Kong and Hui contributed equally. The team works on agentic AI and automated agent design; the evaluation spans four external, independently published benchmarks (τ³-bench, ARC-AGI-2/3, Terminal-Bench 2.1) rather than self-built tasks, and the baselines (GEPA, OpenEvolve, EvoX, HyperAgents) are established 2025–2026 systems, several run under their published or native settings (SkyDiscover settings for GEPA/OpenEvolve/EvoX). The paper includes AI-use, ethics, and reproducibility statements, and an anonymous code submission is referenced. Credibility is strengthened by a large appendix (12 tables/figures of ablations, wall-clock accounting, seed-skill prompts), but the deep entanglement with Claude Code and the Anthropic model family means results are vendor-ecosystem specific in practice.

## Critical Assessment

- **Budget fairness is the weakest point of the comparison.** Baselines stop after 5 stall iterations and used 6.9–36 wall-clock hours depending on benchmark (Table 9), while FreeEvolve always consumes its full **24-hour** budget (and its held-out gain on τ³-bench comes with ±6.0 s.d.). The authors acknowledge autonomous vs prescribed loops "allocate evaluations and search effort differently, making exact cost matching difficult," but a cost-matched sweep (e.g., baselines given the same 24 h, or FreeEvolve stopped at each baseline's budget) is missing — the headline +13.6 average conflates algorithm and budget.
- **Single model family, single agent scaffold.** Every worker, evolver, judge, and simulated user is a Claude model, and the evolver is Claude Code itself. The cross-model "transfer" (Sonnet 4.6, Haiku 4.5) stays within Anthropic's lineup; nothing shows the learned skill survives a different vendor's model or a non-Claude agent scaffold. Given the claim is that "the process" is learned, this is a significant external-validity gap.
- **Small held-out sets inflate variance.** ARC-AGI-3's held-out partition is **8 games** and τ³-bench's is 29 tasks; with s.d. of ±5–8 points on the means (e.g., 51.7±6.0), the τ³-bench margin over EvoX is roughly 2–3 s.d. but single-game RHAE swings could be large. No significance tests are reported anywhere.
- **The seed-skill baseline is nearly a no-op (0.6 points), which makes the meta-evolution delta look larger than it is.** The informative contrast is meta-evolved (47.1) vs no-data rewrite (37.9) on τ³-bench — a solid +9.2, but the paper's framing ("autonomy alone gives at most 1.1") leans on a deliberately weak seed. The seed's prompts are shown in Appendix G and are indeed minimal, yet it is a self-chosen baseline.
- **One unexplained inversion:** Opus 4.6 as evolver (40.2) underperforms Sonnet 4.6 (47.2) on τ³-bench, which the authors note but do not explain; this hints the capability story is not monotone and the mechanism behind "sufficient model capability" is not understood.
- **Honest strengths:** the fixed-decision ablation (Table 4) directly tests the autonomy claim, the two-level containment (meta-environments excluded from inner catalogues) avoids runaway recursion, keyword scans for held-out task IDs guard against leakage, and the token-efficiency plot is a genuine attempt at cost-aware comparison. The qualitative campaign trace (Figure 5) showing the evolver undoing a regression and confirming branches is convincing evidence the autonomy is being used non-trivially.

## Strengths

- Attacks a real and previously unaddressed layer of the agent-improvement stack: the search-loop policy itself, cleanly formalized as an environment–evolver boundary that also yields practical benefits (Slurm scaling via a single environment-specific execution shim).
- Meta-evolution design is elegant and cheap: because the campaign policy is just text, no new machinery is needed — the same Evolve interface applies one level up, and the learned skill is frozen, inspectable, and portable (Appendix G shows what meta-evolution actually wrote into the skill: task-selection, regression-control, and search rules).
- Evaluation discipline is above average: pre-registered held-out splits shared by all methods, three-fold held-out repeats with s.d., pass@3, leakage scans, wall-clock and token accounting in the appendix.
- The evidence structure maps cleanly onto five explicit experimental questions (Q1–Q5, Appendix Table 11), including a negative-sounding result (Haiku 4.5 cannot exercise campaign autonomy) reported transparently.

## Limitations

- Compute-heavy and budget-favoring: 24 h × 5 Slurm nodes for meta-evolution (plus 12 h per worker campaign), always fully consumed, vs 6.9–36 h stall-triggered baselines; no cost-matched comparison.
- Claude-only ecosystem: models, agent scaffold (Claude Code), and judge all from one vendor; transfer claims tested only across Claude tiers.
- Small held-out partitions (8 games on ARC-AGI-3, 29 tasks on τ³-bench) and no statistical significance testing; τ³-bench gain carries ±6.0 s.d.
- Transfer boundary is real: single-source skills *reduce* Terminal-Bench 2.1 mean (74.3–76.5 vs 81.4 seed), and the fix requires a second meta-evolution run on a joint environment pair.
- Requires a capable evolver model (below Sonnet 4.6 nothing works: Haiku 4.5 → 32.2 vs base 33.3), and the Opus 4.6 inversion is unexplained.
- Terminal-Bench results are confounded by CPU-intensive shared-concurrency evaluation (the authors' own explanation for trailing GEPA on mean); on TB2.1 the headline "matches or exceeds" holds only on pass@3.
- Safety posture is acknowledged but unresolved: the ethics statement concedes autonomous improvement is not safe for high-stakes deployment.

## Relevance

这项工作与你关注的 LLM agent 自动化设计与自我改进方向高度相关：它把"如何组织进化搜索"本身变成可学习、可迁移的 skill，是 GEPA/OpenEvolve/EvoX 这条 agent-evolver 路线的直接下一环，其有界环境接口与两层嵌套的元进化设计对自演化系统（self-evolving pipelines）的工程实现很有参考价值。

## Questions for Further Exploration

- Does the meta-evolved skill survive a non-Anthropic model family or a non-Claude-Code scaffold, or does it encode Claude-Code-specific tool-use habits?
- What exactly explains the Opus 4.6 < Sonnet 4.6 evolver inversion — is there a capability sweet spot, or an artifact of one campaign run (no error bars across seeds are given for the ablation)?
- Can meta-evolution be made cheaper — e.g., judging candidate skills on truncated or replayed campaigns instead of full 24-hour runs — and how correlated is such a proxy score with full-campaign outcome?
- The 8-game ARC-AGI-3 held-out set: would results hold on the full game suite, and is RHAE stable at that sample size?
- Campaign autonomy is bounded at two levels by construction; is there evidence the learned skill would exploit deeper recursion if allowed, and does the two-level cap cost performance?
- Since the skill is plain markdown, how sensitive is it to wording — would paraphrasing the meta-evolved skill degrade performance, i.e., is the "process knowledge" robust or brittle?
