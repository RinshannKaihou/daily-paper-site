> **一句话总结：** 本文发现在滚动文档（rolling-agent）工作负载中，非前缀 KV-Cache 复用 + 选择性重计算的结果依赖于请求历史：在同样 5% 重计算预算下，把 CacheBlend 的 token top-k 换成文档对齐（document-aligned）重计算后，跨 5 种请求顺序的答案变化率从 69.0% 降到 26.1%，且在打乱顺序下对全量 prefill 的保真度提升 34.5–52.5 个百分点，同时保持约 5.7× 的中位 TTFT 加速——核心结论是"重计算预算花在少数连续区间上远比撒在高偏差 token 上鲁棒"。

> **TL;DR:** On a rolling-agent workload of 7,735 updates over 8,995 real financial records (15 U.S. equities, ~7.2–7.7K-token prompts, Qwen3-8B + LMCache 0.5.1/vLLM), the same prompt can yield different answers depending on which requests were served before it: CacheBlend's token top-k selective recomputation shows 69.0% answer variation across five request orders, while the authors' document-aligned recomputation (recomputing whole contiguous document spans at the same 5% token budget) cuts this to 26.1% and improves fidelity to full prefill by 34.5–52.5 percentage points under shuffled orders — with both policies achieving ~5.7× median TTFT speedup (415–426 ms vs 2,408 ms full prefill on an NVIDIA L4). The ablation shows contiguity, not deviation-capture or document boundaries, drives robustness: token top-k captures 99.7% of KV deviation yet reaches only 38.6% fidelity, while random-document spans capturing just 4.8% still gain +50.8 points.

## 核心贡献

- **揭示"缓存历史依赖"这一新失效模式**：首次系统证明非前缀 KV-Cache 复用中的选择性重计算是**历史相关**的——在滚动工作负载中，同一 prompt 的输出取决于之前服务过哪些请求（一个 closed-loop serving 问题：每次 LLM 调用既消费又更新缓存状态）。
- **提出 document-aligned 重计算策略**：用 5% 的相同 token 预算，把重计算分配给按平均 KV 偏差排序的完整文档 span（外加最终 query 的连续窗口），替代 CacheBlend 逐 token 独立打分散点的 top-k 选择。
- **等预算五策略消融**：在 token 数完全对齐（每请求中位 386–387 个重计算 token）的条件下对比 token top-k、single-window、fixed-chunk、random-document、document-aligned 五种策略，分离出"连续性（contiguity）"是鲁棒性的主因，而文档边界对齐和偏差排序本身**没有**统计显著的额外收益。
- **缓存重置对照实验**：500 请求对照中每请求清空缓存后两策略差异消失（94.0% vs 92.6%, p=0.23），证明该效应来自跨请求累积的缓存状态——警示孤立的、从干净缓存出发的评测会漏掉这类失效。

## Key Contributions

- **Identifies cache-history dependence as a real failure mode**: in rolling-agent serving, non-prefix KV reuse with selective recomputation is history-dependent — an unchanged prompt produces different answers depending on the requests processed before it, because each call inherits cache state created by prior calls.
- **Proposes document-aligned recomputation**: at a matched 5% recomputation budget, it recomputes complete document spans (ranked by mean KV-deviation) plus a contiguous window for the final query, instead of CacheBlend's scattered token top-k.
- **Equal-budget ablation across five policies**: token top-k, single-window, fixed-chunk, random-document, and document-aligned all recompute exactly the same token counts (median 386–387/request), isolating contiguity as the main robustness factor; document boundaries and deviation-based span ranking add **no** statistically significant benefit (p = 0.076–0.85).
- **Cache-reset control**: with cache cleared before each of 500 requests, the fidelity gap between policies disappears (94.0% vs 92.6%, p = 0.23), proving the effect stems from persistent cache state — evaluations on isolated requests from a clean cache can miss it entirely.

## Methodology

**Workload.** A rolling document agent holds a bounded window of 84 documents built from 8,995 real records for 15 U.S. equities: 7,515 Yahoo Finance daily price records, 792 FNSPID news headlines, and 688 SEC EDGAR filing titles, interleaved while preserving per-channel order. Each LLM call evicts the oldest document, retains 83, and appends one new one (window [D1..D84] → [D2..D85]), producing 7,735 rolling updates; prompts are ~7.2K–7.7K tokens. The task is a deterministic verbatim extraction (copy a requested field from one observation), enabling exact answer comparison.

**System.** Qwen3-8B with greedy decoding (temperature 0, fixed seed) served by LMCache 0.5.1 on vLLM 0.23.0 with the vLLM prefix cache disabled, so the experiment measures LMCache's non-prefix reuse path (CacheBlend-style).

**Recomputation policies (all at a 5% budget).** At a configured selection layer, CacheBlend computes per-token deviation d_i = ||K_i_current − K_i_cached||₂² and token top-k recomputes the k = max(1, ⌈rN⌉) largest-deviation tokens. The four span policies use average span deviation ρ_j = (1/|S_j|)Σd_i: (1) **single-window** picks the contiguous k-token window with greatest total deviation; (2) **fixed-chunk** uses 92-token spans crossing document boundaries ranked by ρ_j; (3) **random-document** uses whole-document spans in deterministic random order; (4) **document-aligned** uses whole-document spans ranked by ρ_j plus a contiguous highest-deviation window for the final query containing exactly k tokens.

**Cache-history sensitivity protocol.** The identical request sequence is served in five orders — chronological, reversed, and three fixed-random shuffles — each run starting from empty LMCache state and retaining cache across requests. Metrics: **answer variation** (fraction of the 10 pairwise order comparisons where exact answers differ) and **fidelity to full prefill** (exact agreement with the full-prefill answer). A 500-request **cache-reset control** clears cache per request; the TTFT benchmark reports request-level median/P95 on an NVIDIA L4.

**Selection-pattern ablation.** All five policies run on the same 500-request cohort under chronological and one fixed-random order, matching the exact realized recomputed token count per order (188,562 chronological / 188,721 fixed-random; median 386/387 per request), so fidelity differences are attributable purely to *where* tokens are recomputed.

## Results & Highlights

- **Answer variation across request orders**: token top-k = **69.0%** vs document-aligned = **26.1%** on the 7,735-update rolling workload — the same prompt gives a different answer in ~7 of 10 order pairings under CacheBlend's default policy, versus ~1 in 4 with document-aligned. An independent repeat of the chronological order reproduced every answer exactly, ruling out run-to-run randomness.
- **Fidelity to full prefill under shuffled orders**: under chronological order there is no significant gap (86.8% top-k vs 85.4% document-aligned, p = 0.12), but under the other four orders token top-k collapses to **19.8–41.5%** while document-aligned holds **54.3–91.7%** (all p < 0.0001) — a 34.5–52.5 point advantage. Document-aligned is more robust but not immune: it drops to 54.3% under the reversed-order stress test.
- **Latency is a wash**: on the NVIDIA L4, median TTFT is 415 ms (document-aligned, **5.74×** vs full prefill) and 426 ms (token top-k, 5.68×) vs 2,408 ms for full prefill; P95 TTFT 477 / 459 ms vs 2,524 ms — document-aligned buys robustness at equal speed.
- **Ablation — contiguity is the driver**: under the fixed-random order, token top-k falls to **38.6%** fidelity while all four span policies sit at **89.4–92.8%** (each +50.8 to +54.2 points over top-k, p < 0.0001). Single-window is best (92.8%); document-aligned is statistically indistinguishable from single-window (p = 0.076), fixed-chunk (p = 0.85), and random-document (p = 0.37).
- **Capturing deviation ≠ fidelity** (Table 2): token top-k spreads its budget over a median 180.5 segments and captures **99.7%** of total selection-layer KV deviation yet achieves only 38.6% fidelity; random-document captures just **4.8%** of the deviation and still improves fidelity by **+50.8 points** (p < 0.0001).
- **Cache-reset control**: per-request cache clearing erases the gap — 94.0% (top-k) vs 92.6% (document-aligned), p = 0.23 — confirming the divergence comes from cache state accumulated across requests, not from the current prompt alone.

## Critical Assessment

- **Task realism is the main caveat**: the workload is a deterministic verbatim string-extraction task ("copy the requested field verbatim"), chosen so fidelity to full prefill is exactly measurable. That makes the evaluation clean but also favorable — a copy task may be more sensitive to corrupted cross-chunk attention than generative agent tasks (summarization, tool planning), where "fidelity" is ill-defined and where answer variation might be partly attributable to legitimate decoding-path sensitivity rather than cache-history damage. All headline numbers come from this single task on a single domain (financial records).
- **Single model, single budget, single GPU**: everything runs on Qwen3-8B with a fixed 5% recomputation ratio on one NVIDIA L4. The paper does not test whether the token-top-k collapse (e.g., 38.6% fidelity) persists at 10–20% budgets where scattered recomputation might repair itself, nor on larger/smaller models or different attention patterns.
- **The headline policy's advantage is partly rhetorical**: the ablation shows document boundaries and deviation-based ranking add nothing significant over random-document spans or a plain contiguous window (p = 0.37–0.85) — so the real finding is "recompute contiguous spans," and "document-aligned" is presented as a convenient instantiation rather than a mechanism. The paper is transparent about this, but the framing ("document-aligned recomputation improves fidelity") slightly oversells what is essentially a contiguity effect.
- **Weakest condition is underreported in the abstract**: document-aligned itself falls to 54.3% fidelity under the reversed order and answer variation is still 26.1% — a 1-in-4 chance the same prompt yields a different answer. For agents requiring reproducibility (financial monitoring, audits), that may still be unacceptable, and the paper defers mitigation to future work.
- **Ablation scope**: the five-policy comparison covers only 500 requests under 2 of the 5 orders, and the cache-reset control is a separate 500-request cohort; sensitivity analyses over window size (84 documents), prompt length, and inter-arrival patterns are absent.
- **No end-to-end agent-quality metric**: fidelity to full prefill is a proxy; the paper never measures downstream task quality (e.g., trading signal accuracy) or how answer variation translates into agent failure in practice.

## Strengths

- A crisp, novel, and practically important question: persistent KV-cache reuse makes serving a **closed-loop** system, and request order is an uncontrolled confounder that prior work (CacheBlend, EPIC, KVLink) never evaluated.
- Impeccable experimental hygiene: exact token-count matching across policies (188,562 vs 188,721 tokens), deterministic greedy decoding with a reproduced identical run, cache-reset causal control, pairwise answer-variation metric with 95% CIs, and explicit significance tests.
- The deviation-capture paradox (99.7% captured deviation → 38.6% fidelity vs 4.8% → +50.8 points) is a memorable, actionable insight that directly contradicts the intuition behind deviation-ranked token selection.
- Honest negative results: no chronological-order advantage (p = 0.12), no added value from document boundaries or deviation ranking, and a policy that is "more robust but not immune."
- Realistic data provenance: 8,995 real market/news/filing records with a deterministic 7,735-update stream, plus a strong ~5.7× TTFT speedup measured end-to-end on LMCache/vLLM.

## Limitations

- One model (Qwen3-8B), one task type (verbatim extraction), one domain (U.S. equity records), one recomputation ratio (5%), and one GPU (NVIDIA L4); generality beyond this envelope is untested.
- Document-aligned fidelity degrades to 54.3% under the reversed-order stress test and 26.1% answer variation remains — the fix reduces but does not eliminate history dependence.
- The ablation is limited to a 500-request cohort under chronological and one fixed-random order; the other two fixed-random orders and the reversed order are not ablated.
- No mechanism-level explanation of *why* contiguous recomputation repairs cross-document attention better than scattered tokens (only an association via Table 2), and no analysis of which layers/heads are responsible.
- Reproducibility artifacts (code, the exact request orders, the interleaved dataset build) are not mentioned as released; the pipeline depends on LMCache 0.5.1/vLLM 0.23.0 version pinning.
- Findings apply to non-prefix reuse systems; workloads with a stable shared prefix (where exact prefix caching works) are out of scope.

## Relevance

这篇论文直接命中 LLM 推理系统与 KV-Cache 优化的核心痛点：对于长期运行的 agent（滚动文档、RAG、监控类应用），它证明 CacheBlend 式 token 级选择性重计算在持久缓存下不可靠，并给出"按连续 span 重算"这一几乎零成本的替换方案（同等 TTFT 加速）。对你的 serving systems / agent infra 兴趣而言，这是一篇把"缓存历史"确立为新评测维度的必读实证工作。

## Questions for Further Exploration

- Does the token-top-k fidelity collapse (38.6%) vanish at higher recomputation budgets (10–20%), and is there a budget-contiguity trade-off curve per workload?
- Does the effect transfer to generative agent tasks (tool-calling, multi-step planning) where outputs are not verbatim copies, and how should "fidelity" be defined there?
- Why does contiguous recomputation repair cross-chunk attention so much better — is the damage concentrated in attention-sink positions near document starts (as EPIC/LegoLink suggests), and can a mechanism-level analysis predict which spans matter?
- Can schedulers make cache-history part of the API — e.g., pinning request-to-cache-state assignments, or exposing cache lineage so agents can reason about reproducibility?
- Would training-time interventions (fine-tuning with reused-chunk noise, as CacheClip-style approaches suggest) combined with span-level recomputation close the remaining gap to full prefill?
