# Evo²: Evolving the Evolver through Weight-Harness Co-Evolution

> **一句话总结：** Google DeepMind 提出 Evo²，让同一个共享策略同时扮演 Proposer（对 agent harness 提出代码修改）和 Reflector（诊断执行效果并指导修订），并用 EvoTIDE 管线（编辑抽取 + 前缀续写修复轨迹 → SFT 热启动 → 双角色交错 GRPO）训练"进化器"本身的权重，最终在 Polyglot 上取得 82.1% pass@1（最强基线 GEA 仅 62.6%，+19.5 分），SWE-bench Verified 48.3%（HGM 41.0%），且冻结权重的双角色搜索就能把 GPT-5-mini 在 60 题 SWE 子集上从 24.4% 提到 48.3%。

> **TL;DR:** Evo² co-evolves an LLM agent's harness (the executable program managing prompts, tools, context and control flow) with the weights of the evolver itself. A single shared Qwen3.8-27B policy serves as both Proposer (autonomous Type-A edits and directive-following Type-B revisions) and Reflector (REVISE / CROSSOVER / KEEP decisions) over a tree of harness variants; the edits and their measured execution outcomes then become training data via EvoTIDE — trajectory recovery (edit extraction + prefix continuation), an SFT warm start, and interleaved GRPO across the two roles with a frozen counterpart snapshot. On Polyglot the evolved harness reaches 82.1% pass@1 vs 62.6% for the strongest of four self-evolution baselines (GEA); on SWE-bench Verified it resolves 48.3% vs 41.0% for HGM; and with weights frozen, the dual-role search alone nearly doubles GPT-5-mini's resolved rate on a 60-task SWE-bench Verified subset (24.4% for the best baseline → 48.3%).

## 核心贡献

- **权重–harness 协同进化框架**：首次把 harness 进化（self-modifying agent 架构）与进化器自身的权重训练闭环连接——每次 harness 修改及其执行结果（分数变化、trace）都成为训练 Proposer/Reflector 共享策略的数据，"更好的进化器构建更好的 harness，更好的 harness 经验又训练出更好的进化器"。
- **统一双角色管线**：一个策略经两种 role prompt 同时充当 Proposer（Type A 自主编辑 / Type B 按指令修订）与 Reflector（诊断后给出 REVISE / CROSSOVER / KEEP 三种动作），参数共享、共同进化。
- **EvoTIDE 训练管线**：通过 edit extraction（从 reasoning/chat 记录中抽取未落盘的编辑）与 prefix continuation（截断到最后一个成功编辑处再续写）修复无效 rollout 中的可用轨迹；SFT 热启动后进行双角色交错 GRPO；以跨越不同深度与分数层的父代池（root 固定份额 ρ + 按 w(h)=ε_P+|V(h)−½| 加权采样）维持训练分布多样性。
- **Crossover searching**：维护从已评估 harness 抽取的策略库 S，Reflector 可从其他分支选择 donor 策略并由 Type B Proposer 移植到当前候选，实现跨分支有用机制的组合。
- **广泛的实证**：3 个编程基准上全面超越 SICA/DGM/HGM/GEA 四个自进化基线；进化出的 harness 无需再进化即可跨基准迁移（6 个方向中 5 个最优）；冻结权重即可改进 GPT-5-mini 与 Claude Haiku 4.5；扩展到记忆任务后在 LoCoMo 与 LongMemEval 上均为最佳。

## Key Contributions

- **Weight–harness co-evolution**: connects harness evolution with training of a unified Proposer–Reflector policy — harness modifications and their execution outcomes supply the training signal for the evolver, closing the loop between the two previously separate directions of self-evolution (weight updates vs. harness rewriting).
- **Unified dual-role pipeline**: one shared policy writes harness edits as the Proposer and diagnoses their effects as the Reflector; the Reflector's action set (REVISE, CROSSOVER, KEEP) lets it also learn when further modification is unlikely to help.
- **EvoTIDE**: a training pipeline for the evolver that recovers usable trajectories from partially invalid rollouts (edit extraction; prefix continuation from the last successfully applied edit), then applies SFT warm start + interleaved GRPO across both roles, with a bounded parent pool spanning different tree depths and performance levels.
- **Crossover searching**: a library of strategies extracted from evaluated harnesses across branches lets the Reflector import a donor mechanism into the current candidate, combining discoveries made elsewhere in the tree.
- **Reusable framework and evolved harnesses**: demonstrated on three coding benchmarks, six transfer directions, two proprietary models with fixed weights, and memory tasks (LoCoMo, LongMemEval), with an ablation (Table 5) isolating the contribution of weight evolution.

## Methodology

**Setup.** A harness h is the executable program managing an agent's prompts, tools, context and control flow; a task executor M_exec runs inside each candidate harness and stays fixed during co-evolution, so candidate score changes measure the effect of the harness alone. A language-model policy π_θ acts as the evolver through different role prompts.

**Harness evolution as tree search.** Each node stores a harness plus task evaluation records; edges record the edits applied. Per iteration: sample a parent, let the Proposer modify it (Type A: autonomous edit given parent performance; Type B: implement a Reflector directive d), evaluate the candidate, then let the Reflector examine the edit diff, performance change and execution traces to recommend REVISE (concrete directive), CROSSOVER (integrate a donor strategy s_j from library S) or KEEP. Both roles share parameters θ; during training, counterpart calls use a frozen snapshot θ̄.

**Reward design.** Both roles are rewarded by the induced change in task score: r_P^exec = Ṽ(h′) − Ṽ(h), r_R^exec = Ṽ(h₁) − Ṽ(h₀), evaluated on the same tasks under matched conditions. Malformed outputs, unapplied edits, no-op edits, unusable harnesses and invalid crossover directives receive negative rewards; Type B gets a small bonus/penalty for touching (or not) the file named in the directive; Reflector gains are credited only if traces contain evidence the added mechanism actually ran.

**Trajectory recovery.** Edit extraction searches recorded reasoning/chat messages for concrete file edits when the rollout ended without an explicit edit action; prefix continuation truncates the rollout after the last successfully applied edit and resumes generation from that prefix, preserving valid earlier edits. Recovered proposals pass the same application, startup and evaluation checks as all other candidates. Reflector trajectories are generated by implementing each proposed directive t_i and recording the outcome, yielding supervision for REVISE, CROSSOVER and KEEP cases.

**Training.** SFT initializes the shared policy on a mixture of successful autonomous edits, directed edits and Reflector responses balanced across roles/modes. Online training then alternates: at round start θ̄ ← θ (frozen counterpart); Proposer GRPO steps use the frozen model to sample Reflector behaviors and vice versa; group-relative advantages with fixed-length token-loss normalization; one update per sampled batch averaged over both role groups. Parent sampling keeps the root at a permanent share ρ ∈ (0,1) and weights non-root parents by w(h) = ε_P + (|V(h) − ½|)₊, deliberately exposing both high- and low-scoring parents so the model learns to improve strong candidates and repair weak ones. The pool refreshes each round with harnesses produced by the updated model.

## Results & Highlights

- **Coding self-evolution (Table 1, Qwen3.8-27B executor+evolver, held-out):** Evo² reaches 82.1% pass@1 on Polyglot vs 62.6% for the strongest baseline GEA (+19.5 pts; SICA 60.2, DGM 60.2, HGM 61.8); 48.3% resolved on SWE-bench Verified vs 41.0% for HGM (+7.3); 58.0% pass@1 on LiveCodeBench vs 56.0% for HGM (+2.0, with baselines spanning 39.0–56.0).
- **Transfer without further evolution (Table 2):** Evo² is best in 5 of 6 directions, e.g. the LCB-evolved harness scores 74.0 on Polyglot vs 63.4 for DGM/HGM, and the SWE-evolved harness scores 72.4 on Polyglot vs 69.9 for DGM; margins range 2.5–18 points (the one loss: Polyglot→LCB, 44.0 vs 45.0 for DGM/GEA).
- **Proprietary models with frozen weights (Table 3, 60-task SWE-bench Verified subset):** GPT-5-mini jumps to 48.3% resolved vs 19.4–24.4% for all four baselines (nearly 2× the best, SICA 24.4%); Claude Haiku 4.5 reaches 47.8% vs 45.0% for HGM.
- **Memory tasks (Table 4):** LoCoMo F1 60.4 vs 56.2 for HGM (SICA 54.6, DGM 55.8, GEA 53.2); the same LoCoMo-evolved harness scores 71.5 on unseen LongMemEval-S vs 64.4 for HGM, with every independent Evo² search landing in 67.9–73.9.
- **Ablation of weight evolution (Table 5):** the EvoTIDE-trained evolver beats the untrained base evolver by +16.3 on Polyglot (78.0 vs 61.8, p=.001), +5.0 on SWE-bench Verified (51.0 vs 46.0), +9.3 on LoCoMo (56.5 vs 47.2) and +10.6 on LongMemEval (67.7 vs 57.1); crossover searching adds a further +4.1 on Polyglot (78.0 → 82.1).
- **Inference cost (Figure 3):** the Evo² harness attains the highest LiveCodeBench accuracy while using 3.6K completion tokens and 10.2 LLM calls per task, vs 6.6K–6.9K tokens and 26–37 calls for HGM/DGM with lower accuracy; on Polyglot the champion needs 36 calls / 3.6K tokens vs the unevolved harness's 43 calls / 4.0K.

## Authors & Credibility

The work comes from Google DeepMind, with first author Chejian Xu (University of Illinois Urbana-Champaign, contributing as a student researcher at Google DeepMind) and co-authors including Bo Li (UIUC). The remaining authors (Shujian Zhang, Wenxuan Zhou, John Lambert, Beck Chen, Andrew Hard, Rajiv Mathews) are Google DeepMind researchers. The team has access to large-scale RL infrastructure (GRPO training of a 27B model, FP8 serving, repeated task evaluations across thousands of harness candidates), and the paper engages closely with the current self-evolving-agent literature (SICA, Darwin Gödel Machine, Huxley-Gödel Machine, GEA, GEPA). Institutional resources and consistent experimental hygiene (held-out evaluation, repeated runs, a dedicated weight-evolution ablation) make the core claims credible, though no code release is mentioned.

## Critical Assessment

- **Novelty.** The individual ingredients are known: tree-structured self-modification is DGM/SICA/HGM territory, SFT+GRPO is standard, and CoNL/EvoLM already co-train generation and feedback roles. The genuine delta is the closed loop — using every evaluated harness edit (including failures) as training experience for the evolver policy, plus evidence-conditioned Reflector credit (gains count only if traces show the added mechanism ran, a nice anti-reward-hacking guard). That framing is a real contribution, not just engineering.
- **Thin margin where it matters least, huge margin where it matters least explained.** On LiveCodeBench the win is only +2.0 (58.0 vs HGM 56.0) and on Polyglot→LCB transfer Evo² actually loses (44.0 vs 45.0). The +19.5 Polyglot headline likely benefits from an unusually weak baseline field there (all four baselines cluster at 60.2–62.6, suggesting a ceiling), while the paper offers no analysis of why gains vary so much across benchmarks.
- **Evaluation asymmetry in the proprietary experiment.** Table 3's "nearly doubling" GPT-5-mini claim rests on a 60-task subset where each baseline reports the mean over 3 seeds of its single top-ranked harness, while Evo² "reports the better result of its two top-ranked harnesses" — a best-of-2 selection advantage on a small, noisy benchmark. The GPT-5-mini gap (48.3 vs 24.4) is too large to be pure selection, but the Haiku 4.5 gap (47.8 vs 45.0) is within what such asymmetry could plausibly inflate.
- **Missing ablations.** Crossover gets a +4.1 attribution and weight evolution gets Table 5, but there is no sensitivity analysis for the parent-pool hyperparameters (ρ, ε_P), no ablation of the reward-shaping components (the file-matching bonus, the negative rewards for no-ops), and no comparison against a cheaper non-RL evolver (e.g., prompting a much larger model as Proposer/Reflector) to justify the cost of training a 27B evolver.
- **Reproducibility.** No code release is mentioned; reproducing requires tree search with thousands of evaluated harnesses plus GRPO training of a 27B model, a compute budget far beyond most labs. The same-model executor/evolver design (Qwen3.8-27B for both) also leaves open whether the trained evolver generalizes to unseen executor models — the only cross-model evidence is the fixed-weight proprietary setting where weight evolution is disabled.
- **Transfer caveat.** Polyglot→SWE transfer is only 21.0 (best baseline HGM: 20.0), so the evolved harnesses remain benchmark-specific in the hardest direction; "transfer" claims should be read as holding for 5 of 6 directions, not universally.

## Strengths

- Consistent, large improvements across five benchmarks and two domains (coding and memory), with the strongest gains exactly where prior self-evolution methods plateau (Polyglot +19.5, LoCoMo +4.2 over HGM).
- The dual-role search alone (frozen weights) improves GPT-5-mini from 24.4% to 48.3%, cleanly demonstrating that the harness-side mechanism is valuable independently of weight evolution.
- Better results at lower inference cost: highest LiveCodeBench accuracy with roughly half the tokens and a third of the LLM calls of HGM/DGM — the harness improvements are about efficiency of agent design, not prompt bloat.
- Honest accounting: held-out evaluation, a dedicated Table 5 isolating weight evolution, p-value on the main ablation, and per-search ranges reported for memory tasks (67.9–73.9) rather than only means.
- Thoughtful reward engineering: evidence-conditioned Reflector credit and penalties for no-op/unusable edits directly target the degenerate-edit failure mode of self-modifying agents.

## Limitations

- Compute cost is high and unstated in wall-clock terms: thousands of harness evaluations plus GRPO training of a 27B policy, with no released code or harness artifacts mentioned.
- Gains are uneven: only +2.0 on LiveCodeBench and a transfer loss on Polyglot→LCB suggest diminishing returns as the baseline harness saturates a benchmark.
- The proprietary study is confined to a 60-task SWE subset with a best-of-2 selection asymmetry favoring Evo² over the seed-averaged baselines.
- Executor and evolver are the same model in all weight-evolution experiments; cross-model generalization of the trained evolver is untested.
- Domain coverage is coding plus conversational memory; nothing about tool-rich web agents, long-horizon scientific workflows, or safety of self-modifying harnesses (the Reflector can insert arbitrary mechanisms, and no security/sandboxing analysis is given).

## Questions for Further Exploration

- Does the EvoTIDE-trained evolver transfer to executor models it never evolved harnesses for (different family or scale), or does weight evolution overfit the co-evolved Qwen3.8-27B pair?
- How does the crossover strategy library S behave as the tree grows to thousands of nodes — does retrieval saturate, and does the +4.1 crossover gain persist at larger search budgets?
- How sensitive is the pipeline to the parent-pool hyperparameters (root share ρ, ε_P) and to the reward-shaping terms (file-matching bonus, no-op penalties)?
- Could the evidence-conditioned Reflector reward be gamed by a harness mechanism that runs but is causally inert — is trace-evidence sufficient against a reward-hacking evolver?
- What would a compute-matched comparison against a strong non-evolving baseline (e.g., GPT-5-mini writing the harness once with a long prompt) show — how much of the gain comes from search over many candidate harnesses versus the co-evolution itself?
