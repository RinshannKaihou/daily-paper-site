> **一句话总结：** 在 Berkeley Function-Calling Leaderboard 多轮可执行任务上向工具层注入 4 类故障（超时/工具消失/参数改名/返回值损坏），跑 1,920 次试验、6 个模型（3 对推理/instruct 同门配对）：agent 对显式报错的检出率 91.3%，对"格式完美、内容错误"的静默损坏仅 58.8%（无故障基线 26.8%）——检测看的是报错通道而非内容正确性；推理模型比同门 instruct 检出低 9.3 分、改道多 10.4 分，恢复率却无差异，系统提示里加"检查每个结果"最多 +2.5 分且不显著。

> **TL;DR:** Injecting four typed faults (timeout, tool removed from registry, renamed parameter, corrupted return value) once per trial into the tool layer of the Berkeley Function-Calling Leaderboard (BFCL) multi-turn split, and running 1,920 trials over six models in three matched reasoning/instruct pairs, the study shows detection tracks the error channel, not the content: agents treat 91.3% of loud explicit errors as problems vs 58.8% of quiet corruptions, against a 26.8% false-alarm baseline on clean runs. Reasoning models detect less than their instruct siblings (−9.3 points pooled, p < .001) while replanning more (+10.4 points), with no recovery difference (−2.4 points, n.s.); only missing-tool clearly hurts recovery (39.9% vs the 63.3% two-clean-run agreement baseline), and a "briefly check each result" system prompt adds at most +2.5 points (n.s.).

## 核心贡献

- **可复现的故障注入层：** 在 BFCL 多轮切分上构建一次性的、类型化的故障注入层，直接钩住工具调用而非走官方评测 harness；配套自检 harness 保证"无故障条件必不出错、每类故障恰好在目标步或之后触发一次、损坏保持类型且不动环境状态、同输入产生同故障行为"，并冻结 24 个任务的套件完整开源（harness、轨迹、打分数据、分析脚本，github.com/obadaKraishan/brittle-agents）。
- **把故障响应拆开度量：** 首次将"注意到（detection）→ 改道（replanning）→ 恢复（recovery）→ 重复（repetition）"分开打分；恢复以模型自身无故障运行的环境状态完美一致为参照，而非基准 ground truth——从而把"本来就不会做"与"故障后没恢复"解耦，并用两次无故障运行仅 63.3% 一致这一事实作为度量的噪声下界。
- **可见性而非严重性决定检出：** 1,920 次试验、6 个模型：三条响亮故障（报错字符串）检出率 91.2–91.6%，一条安静故障（格式完美的损坏返回值）仅 58.8%，无故障误报基线 26.8%——agent 盯着通道，不看内容。
- **推理模型"会动不会看"：** 与同门 instruct 配对比较，推理变体检出更低（合并 −9.3 分）、故障后改道更多（合并 +10.4 分）、恢复无差异（−2.4 分）；在系统提示中加一行"每次工具调用后检查结果是否符预期"，instruct +0.6 分、推理 +2.5 分，均不显著——第一直觉的补救无效。

## Key Contributions

- A reproducible fault-injection layer on the BFCL multi-turn executable split: four typed faults (timeout, missing tool, renamed parameter, silent corruption) fire exactly once at a controlled point in the trajectory, never leaving the environment half-changed; a self-test harness verifies all invariants, and the harness, frozen 24-task suite, full trajectories, scored dataset, and analysis scripts are released.
- A measurement scheme that separates noticing, replanning, recovery, and repetition. Recovery is scored as perfect agreement with the model's own clean-run end state rather than benchmark ground truth, decoupling baseline competence from fault response, and is calibrated against the finding that two fault-free runs of the same model and task agree only 63.3% of the time.
- Evidence from 1,920 trials across six models (Claude Haiku 4.5 thinking/instruct, DeepSeek-R1/V3, Qwen3 thinking/instruct) that detection depends on failure visibility, not severity: 91.3% detection on loud explicit errors vs 58.8% on quiet corruptions, over a 26.8% false-alarm baseline.
- A dissociation between acting and noticing: reasoning variants notice less (−9.3 points pooled vs matched instruct siblings) but change their next action more (+10.4 points) with no recovery gain; adding a one-line "check each result" instruction to the system prompt does not close the gap (+0.6 instruct / +2.5 reasoning, both n.s.).

## Methodology

**Tasks and environment.** Tasks come from the multi-turn split of the Berkeley Function-Calling Leaderboard, where scenarios pair with Python classes holding state and exposing tools. Of 400 candidate tasks, 312 passed three filters (every environment class usable directly, runs locally, 3–10 user turns, executable ground-truth call sequence available); 24 tasks were sampled with a fixed seed, balanced across domains, and the suite was frozen. The frozen set spans 16 domain combinations (file system, trading interface, travel booking, vehicle control, messaging, ticketing) with a median of five user turns per task. The authors drove the environment classes directly rather than through the official harness — this is what makes placing a fault at a chosen step possible.

**Fault taxonomy.** Four faults separate failures an agent can read from failures it must infer, plus a no-fault baseline: *timeout* (report a timeout error; fires in 99% of trials), *missing tool* (remove the tool from the registry; 71%), *schema drift* (reject with an unknown-argument error after renaming a parameter; 74%), and *silent corruption* (return a same-typed but wrong value — number shifted by 20–60%, element dropped, field replaced, or a placeholder string when the true result is empty; 97%). Loud faults surface an explicit error string; corruption does not. The first three corruption variants place an error string in front of the agent; the fourth does not (loud vs quiet). The fault fires once, on the first eligible call at or after step ⌈T/2⌉ of the user turns (median firing step 3 vs median 7 calls in reference solutions; 42.1% of faults fire at step 1–2), leaving later calls normal — recovery is available by construction.

**Agent protocol and design.** Trials follow the benchmark's multi-turn structure with the standard system prompt; models act via native JSON function-calling, temperature 1.0, each cell run twice (provider sampling unseeded). Trials cap at 15 tool calls; hitting the cap is an outcome, not a hidden failure. Six models form three matched reasoning/instruct pairs, all routed through one gateway; two additional models (a Nemotron pair) were dropped after repeated rate-limit failures. The full design gives 240 trials per model plus a 480-trial prompt arm for one pair: 1,920 trials in total, of which 1,694 are analysed (faults never fired in the rest).

**Measures.** Detection = the agent treated the result as a problem, coded by an LLM judge (shown one tool call, its result, and the agent's message) and validated against the author's blind hand-coding of 100 trials (three-way κ = .47; collapsing to binary "problem vs not" gives 85.9% agreement, κ = .69). Recovery = perfect agreement between the trial's end state and the same model's clean-run end state on the same task and seed; replanning = the first action after the fault differs from the action that failed; repetition = three or more consecutive identical calls after the fault (strictly identical = same tool and arguments); budget exhaustion = ending at the 15-call cap.

**Statistics.** Trials are not independent (24 tasks recur), so inference uses binomial generalized estimating equations clustered on task plus bootstrap intervals resampling tasks; per-family contrasts and the secondary prompt analysis use Holm-corrected paired tests and t-tests within matched pairs.

## Results & Highlights

- **Detection depends on visibility, not severity (RQ1).** Agents treated a fault as a problem in 91.3% of loud-fault trials (95% CI [88.5, 94.1], n = 936) vs 58.8% under silent corruption (CI [45.7, 71.2], n = 374), against a 26.8% false-alarm baseline on clean runs (CI [17.8, 36.5], n = 306) — loud is +64.5 points over baseline (h = 1.46), quiet only +32.0 (h = 0.66). Within the loud faults the spread is ≤0.4 points (timeout 91.6%, missing tool 91.2%, schema drift 91.2%), while corruption sits 32 points below all three; a task-clustered GEE puts loud faults at OR = 28.61 (z = 12.14) and quiet at OR = 3.96 vs baseline (both p < .001 after Holm). Under corruption the agent does not treat the result as a problem in 41% of trials — reading the wrong value forward, sometimes reconciling it with what the conversation had established. Notably, clean runs whose target call returned "none" were acknowledged 90% of the time, so part of the baseline is correct behavior, not noise.
- **Reasoning models act more and notice less (RQ2).** Paired within family on fault trials, reasoning variants detect less in all three families: −6.2 points for Claude (OR = 0.61, p_Holm = .042), −4.0 for DeepSeek (OR = 0.43, p_Holm = .003), −16.6 for Qwen (OR = 0.40, p_Holm < .001); pooled over 450 pairs: −9.3 points (95% CI [−14.3, −5.3]). Replanning goes the other way: +10.4 pooled (CI [+5.6, +15.7]; OR = 2.02, p < .001), reliable only for Qwen (+17.8, OR = 4.23, p_Holm < .001; Claude +10.4 and DeepSeek +8.7 not significant, p ≥ .209). Recovery shows no family difference anywhere (p_Holm = 1.000 throughout; pooled −2.4 points, CI [−9.3, +4.5]) — however far the extra deliberation shifts behavior after a fault, it does not change how often agents end where they were going.
- **What faults cost (RQ3).** Two fault-free runs of the same model and task end in the same state in only 63.3% of trials (CI [53.1, 73.2]), varying from 84.4% (Claude instruct) down to 41.7% (DeepSeek-R1/V3, Qwen3 thinking) — the recovery yardstick itself is noisy. Against it, only missing tool clearly lowers recovery: 39.9% (CI [28.1, 52.4], OR = 0.34, p_Holm < .001) vs 59.6% timeout, 59.2% schema drift, 60.4% corruption, which fall within run-to-run variation (OR 0.80–0.88, p_Holm ≥ .117). Noticing does not buy recovering: 55.6% of trials where the agent flagged the problem recovered vs 55.7% where it did not (p = .974); holding fault type fixed, noticing is associated with recovery (OR = 1.51, p = .004), but the association weakens once model is fixed (OR = 1.29, p = .098).
- **Effort, not loops.** After a fault, agents called the same tool three or more times in a row in 12.5–22.2% of trials (most under corruption, 22.2%, and timeouts, 21.4%), but these are mostly retries with changed arguments — strictly identical repetition is rare (0.8–1.8%). Trials end at the 15-call cap in 24.8–31.7% of fault trials vs 23.2% clean. Extra steps over clean runs: +0.55 (timeout) and +0.56 (corruption), but +1.47 (missing tool) and +1.85 (renamed parameter) — rebuilding a plan costs more than retrying.
- **Asking the agent to check does not work (secondary).** Adding "after every tool call, briefly check whether the result is what you expected" to the system prompt (480 trials, one family): instruct +0.6 points (t(161) = 0.30, p = .764), reasoning +2.5 points (t(161) = 0.94, p = .347); detection under quiet failures moved 60.6% → 59.6% (interaction p = .176) — none of it significant.

## Authors & Credibility

Single author: Obada Kraishan, College of Media and Communication, Texas Tech University. The paper is accepted at the 2026 IEEE 8th International Conference on Cognitive Machine Intelligence (CogMI). The work is unusually disciplined for a solo effort: a self-test harness that verifies the injection layer's invariants (clean runs never fault; each fault fires exactly once, at or after its target step; same inputs produce the same fault behavior), explicit handling of the 26.8% baseline ambiguity (e.g., the 90% acknowledgment figure for genuine environment errors), and a full release — harness, frozen suite, trajectories, scored dataset, and analysis scripts (github.com/obadaKraishan/brittle-agents). The author grounds the noticing/acting split in the human-factors literature (automation surprise, Parasuraman/Sheridan/Wickens; Bainbridge's ironies of automation) rather than only the LLM-evaluation literature, which strengthens the framing.

## Critical Assessment

- **The "detection" construct is relative, and the headline rates flatter it.** Because the judge-coded baseline is a 26.8% false-alarm rate, the meaningful quantity is the gap over baseline; for quiet corruption that gap is +32 points with a CI whose lower bound ([45.7, 71.2]) leaves real sensitivity near 46%. The paper is honest about this (it even shows agents acknowledging genuine environment errors 90% of the time), but abstract-level readings of "91.3% vs 58.8%" overstate how sharp the instrument is.
- **Detection is coded from what the agent wrote, by an LLM judge with only moderate human agreement.** An agent that noticed but said nothing counts as not noticing, and the validation is one author hand-coding 92/100 trials at binary κ = .69. No behavioral signals (re-reading state, revisiting a tool) are used, so the reasoning-models-notice-less result partly rests on reporting style differences between model families.
- **The recovery measure is noisy by the paper's own numbers.** Recovery = agreement with a single independent clean run, yet two clean runs agree only 63.3% of the time — and for three of six models the clean-run agreement is 41.7%. Recovery figures for those models are close to noise, and the 15-call cap (hit by 27% of trials) conflates slow recovery with budget exhaustion.
- **Conditioning on the affected tool.** Missing tool and schema drift fire only when the agent calls the affected tool (71% and 74% of trials), so the analysed subset is selected on the agent having behaved normally before the fault; trials where the agent avoided the broken tool — arguably the best outcomes — are excluded by construction. 226 trials were dropped for non-firing faults.
- **A known interface artifact touches one model.** DeepSeek-R1 wrote tool-call syntax inside message text in 1.8 turns per trial on average; those calls never execute, so its action-rate contrasts partly reflect a formatting quirk of this gateway rather than fault behavior (acknowledged as a limitation).
- **The null prompt result is one prompt on one family.** The 480-trial arm covers a single matched pair; "metacognitive prompting doesn't help" should be read as one null on two models, not a verdict — and the author says so. No training-based remedy (e.g., PALADIN-style fine-tuning on fault traces) is tested, so the loud/quiet gap is diagnosed but not treated.
- Single benchmark family (BFCL), simulated environments, and a solo author round out the external-validity caveats — but the paper's limitations section states all of this plainly, which is to its credit.

## Strengths

- The noticing / replanning / recovery / repetition decomposition is the right cut, and scoring recovery against the model's own clean run removes the baseline-competence confound that plagues most agent fault studies.
- Calibrating every fault effect against the 63.3% two-clean-run agreement — instead of assuming determinism — is exactly the kind of measurement honesty the field lacks.
- The injection layer never leaves the environment half-changed, faults fire once at a controlled step, and a self-test harness verifies determinism; the frozen suite and full release make the study genuinely reproducible.
- Matched reasoning/instruct pairs within family, shared seeds, task-clustered GEEs, and Holm correction give the RQ2 contrasts real statistical footing.
- The loud/quiet visibility framing yields a crisp, actionable result: the faults agents catch are the ones monitoring dashboards already catch.

## Limitations

- One benchmark family (BFCL) with simulated, executable environments; the four fault types are chosen, not exhaustive, and production failure modes (auth walls, partial outages, schema churn) may behave differently.
- Two of the four faults are conditional on the agent calling the affected tool, so analyses exclude trials where the agent steered around the fault; 226 of 1,920 trials were dropped.
- Trials cap at 15 tool calls (27% hit the cap), so recovery rates are recovery within a bounded effort budget.
- Recovery is judged against a single independent fault-free run while two such runs agree only 63.3% of the time — the measure is noisy, especially for models at 41.7% clean agreement.
- Detection is judge-coded from the agent's text (binary κ = .69); the three-way schema (no reaction / acknowledged / explained away) reached only κ = .47 and no claim rests on it.
- The prompt arm runs on one model family only, and the DeepSeek-R1 tool-call-formatting artifact lowers its effective action rate in a way the fault analysis cannot fully separate.

## Relevance

这篇论文与用户关注的 LLM agent 可靠性与评测方向直接相关：它给出了一个可复用的故障注入 + 检测/改道/恢复分离度量框架（代码全开源）。核心结论——agent 只认报错字符串、对静默损坏过半放行、推理模型自检反而更弱——对设计 agent 评测基准和上线监控（先监控工具返回值而非只监控报错）都有直接指导意义。

## Questions for Further Exploration

1. Would typed result validators (schema-level range/type checks on return values, checked outside the model) close the quiet-failure gap without relying on the agent's judgment?
2. Does PALADIN-style fine-tuning on fault traces teach content checking or just error-string matching — would a trained agent reproduce the loud/quiet asymmetry on these four faults?
3. Is the reasoning models' detection deficit an allocation issue (deliberation effort collapsing as tasks harden, per Skjaeveland et al.) or a reporting-style artifact? Coding detection from behavioral signals (state re-reads, revisits) rather than language would settle it.
4. How does the noticing–recovery dissociation behave under cascading or repeated faults, where the 15-call budget binds harder and rebuilds compound?
5. Would recovery measured against a distribution of clean reference runs (multiple seeds) overturn the "reasoning gains no recovery" conclusion for the low-agreement models at 41.7%?
