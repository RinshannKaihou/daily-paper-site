> **一句话总结：** 斯坦福/SambaNova 等提出 SLA（Stateless Language Agents）框架，遵循"有状态搜索、无状态智能体"原则——harness 自己持有研究状态（候选解与实测结果），每次调用都为 Advisor 和 Worker 重建全新的角色化上下文，而不是让对话历史跨调用累积；在最高 10 亿累计 token 的预算下，SLA 在全部 9 个评测任务上取得最佳最终结果，其中 Anthropic VLIW SIMD 内核优化任务上达到 1112.0±8.9 cycles，显著优于最强基线 SwarmResearch 的 1275.7±133.9，且只需 67.9M token（对比 986.3M，减少 93.1%）即可达到最强基线的最终性能，同时 Advisor 协调开销仅占 0.24–0.51% 的 token。

> **TL;DR:** LLM-driven automated research runs degrade over long horizons because agents replay growing conversation histories, duplicate each other's work, or stop experimenting. SLA (Stateless Language Agents) separates *state* (candidates + measured outcomes, owned by the harness) from *context* (rebuilt fresh and role-specific for a stateless Advisor and parallel stateless Workers at every invocation), with evidence-driven work assignments. Evaluated at budgets up to 1B cumulative tokens with Codex/GPT-5.5 and Claude Code/Opus 4.8, SLA achieves the best full-budget result on all 9 tasks (Anthropic kernel optimization, FrontierSWE, SOL-ExecBench, FrontierCS): on Anthropic kernel optimization it reaches 1112.0±8.9 cycles vs 1275.7±133.9 for the strongest baseline SwarmResearch, matching that baseline's final performance with 93.1% fewer tokens (67.9M vs 986.3M), and on FrontierSWE it trails all baselines at 25% of the budget but leads on all four tasks at full budget (+4.95 points on average). Ablations from shared checkpoints show removing Advisor assignments cuts continued progress by 10.5–84.2%, while coordination costs only 0.24–0.51% of tokens — and short-horizon evaluations would have ranked the methods in the opposite order.

## 核心贡献

- 提出 **SLA 原则："有状态搜索 + 无状态智能体"**：将智能体的 *state*（跨调用持久，由 harness 持有：候选解、评分、证据记录）与其 *context*（单次调用内所见）严格分离；对话历史不再是系统记忆，每次 Advisor epoch 和 Worker trial 都从研究状态重建全新上下文。
- 设计了两个互补机制：**harness 主导的上下文重建**（Advisor 看到按搜索方向归组的结构化证据摘要，区分"实测无改进"与"不确定的失败"；Worker 只看到自己的任务、保留的本地候选与紧凑反馈），以及**证据驱动的任务分配**（无状态 Advisor 每轮基于当前证据把具体实验分配给并行 Worker，避免重复劳动）。
- **长周期评测方法论**：以"累计输入+输出 token"为预算轴（而非迭代数或 wall-clock），在 25% 和 100% 预算处及"追平最强基线所需 token"三个口径上报告结果，并演示了排名随评测预算反转的现象。
- 在三个任务族、9 个问题上系统评测（预算至 1B token）：SLA 在所有任务的全预算结果上第一；Anthropic 内核任务上三次独立运行全部击败九次基线运行；消融实验（从共享 checkpoint 续跑）证明聚焦上下文与显式分配各自贡献显著且效应随周期复利放大。
- 给出**协调成本量化**：Advisor 仅消耗 0.24–0.51% token / 1.2–2.3% 成本，远低于 SwarmResearch Shepherd 的 8.39–10.70% / 6.14–7.35%，并附 CORAL 轨迹的失败模式分析（丢失已验证特征、两智能体重复实现同一特性）作为动机证据。

## Key Contributions

- **The SLA principle — "stateful search with stateless agents"**: the harness owns all durable research state (candidate solutions, scores, outcome evidence) and reconstructs a fresh, role-specific context for every agent invocation, so conversation history never accumulates across calls; what each agent sees is an explicit design choice rather than a by-product.
- **Two mechanisms realizing the principle**: harness-controlled context reconstruction (the Advisor sees a structured, direction-grouped evidence summary that separates measured non-improvements from inconclusive failures; each Worker sees only its assignment, retained local candidate, and compact local feedback) and evidence-driven work assignment (the stateless Advisor turns global evidence into concrete, non-overlapping experiments for parallel Workers each epoch).
- **A token-based long-horizon evaluation protocol**: budgets measured in cumulative input+output tokens (reproducible across systems), reported at 25% and 100% of budget plus the tokens needed to first match the strongest baseline's final result — revealing that method rankings reverse with the horizon.
- **Results at up to 1B tokens across 9 tasks in 3 task families**: SLA achieves the best full-budget result on every task; on Anthropic kernel optimization all 3 SLA runs beat all 9 baseline runs; checkpoint-based ablations show focused contexts, Worker isolation, and explicit assignments each contribute, with effects that compound over the full run.
- **Coordination-cost analysis and failure-mode case studies**: the Advisor consumes 0.24–0.51% of tokens (vs 8.39–10.70% for SwarmResearch's Shepherd), and appendix trace analyses of CORAL document the two motivating failures — a validated feature being dropped from the leading candidate for 33 attempts, and two agents independently implementing the same feature twice within 13 minutes.

## Methodology

**Architecture.** SLA alternates global planning with local experimentation. Each *Advisor epoch*, the harness rebuilds the Advisor's context from the research state: task specification, current global best code + score, and an evidence summary grouped by search direction (Worker statuses, recent progress, task-specific diagnostics), which distinguishes measured non-improvements from inconclusive implementation/runtime errors — a failed execution is not treated as evidence a direction is exhausted. The Advisor (itself stateless, so it re-derives plans from current evidence rather than its own earlier reasoning) assigns concrete experiments to W parallel Workers, choosing to diversify across directions or concentrate on a promising bottleneck. Each *Worker trial*, the harness builds a fresh Worker context containing only the task spec, its assignment, its retained local candidate, and compact feedback from the previous trial. Workers cannot access each other's workspaces or the full record; cross-Worker evidence flows only through assignments. The harness keeps every Worker's *local* best even when it trails the global best (so young approaches get time to mature); when redirected, a Worker restarts from the global best and its first successful candidate becomes the new local baseline. An independent evaluator scores every candidate outside Worker environments with protected evaluator code.

**Enforced statelessness and isolation.** Statelessness is enforced, not requested: the harness starts each epoch in a new session, runs Workers as unprivileged processes under Linux Landlock filesystem restrictions with restricted network access, clears saved sessions between trials, and disables Codex's built-in multi-agent feature. Checkpoints of the full research state enable recovery and controlled ablations.

**Setup.** Two coding-agent configurations: OpenAI Codex CLI v0.152.1 with GPT-5.5, and Claude Code v2.1.258 with Claude Opus 4.8 (reasoning effort high, default context compaction, which now acts only within a single invocation). Default W=3 Workers, 3 local trials per Worker per epoch. Tasks: (1) long-horizon software engineering on FrontierSWE — libexpat→x86-64 assembly, Git→Zig, Dart→Haskell, Lua Native Compiler; (2) kernel optimization — Anthropic's VLIW SIMD kernel task and 3 SOL-ExecBench NVIDIA GPU kernels (#1, #58, #210); (3) algorithm design — FrontierCS Structured-LWE (recovering valid secret vectors from structured learning-with-errors instances). Budgets: 1B tokens (Anthropic kernel), 700M (FrontierSWE), 500M (SOL-ExecBench), 200M (FrontierCS). All methods share the same coding agents, models, seed solutions, public task materials, and sealed evaluators, stopped by an external cumulative-token counter; baselines (EvoX, CORAL, SwarmResearch) run from pinned upstream commits with unmodified search logic.

**Ablations.** From shared SLA checkpoints at 10%/20% of each task's budget, continue for +100M tokens (3 runs per configuration) with one component removed: without Advisor context reconstruction (Advisor reads the full chronological record via a bounded read-only interface: ≤32 calls, 320K characters per epoch), without Worker context isolation (Workers see the full record and every other Worker's current candidate), or without Advisor assignments (Workers run independent trials). This isolates each design choice from an identical starting state.

## Results & Highlights

- **Anthropic VLIW SIMD kernel optimization (Codex, 1B tokens, 3 runs each):** SLA reaches 1112.0±8.9 cycles vs 1275.7±133.9 for SwarmResearch, the strongest baseline (−12.8%; every SLA run beats every baseline run — worst SLA 1122 vs best baseline 1191). To first match the strongest baseline's final performance, SLA needs 67.9M tokens vs SwarmResearch's 986.3M — a 93.1% reduction (14.5× fewer tokens). Under Claude Code the pattern holds: 1039 vs 1143 cycles and 138.5M vs 888.3M tokens (−84.4%).
- **FrontierSWE (Codex, 700M tokens):** SLA trails the strongest per-task baseline on all four tasks at 25% of the budget (e.g., −11.27 on Dart→Haskell, 15.43 vs 26.70) but leads on all four at full budget: libexpat 31.33 vs 24.58 (+6.75 over SwarmResearch), Dart→Haskell 45.27 vs 38.59 (+6.68), Lua Native Compiler 96.15 vs 90.66 (+5.49), Git→Zig 28.94 vs 27.98 (+0.86) — +4.95 points on average. Tokens to match the strongest baseline's final score drop by 36.8% (354.1M vs 559.9M), 61.5% (263.6M vs 684.1M), and 48.0% (354.6M vs 682.3M) on those three tasks.
- **SOL-ExecBench GPU kernels (Codex, 500M tokens):** SLA improves average SOL score by 5.5% across #1/#58/#210, e.g., #58: 0.862 vs EvoX's 0.764 (+7.2%) and matching the target with 14.5M vs 354.1M tokens (−95.9%). The exception is #1, where EvoX reaches the target sooner (46.1M vs 152.7M tokens, +231.2%) though SLA ends higher (0.763 vs 0.710); on low-headroom #210 gains shrink to +1.8% (0.393 vs 0.386).
- **FrontierCS Structured-LWE (200M tokens):** SLA scores 48.5 vs SwarmResearch's 44.0 at 25% budget (+10.2%) and 59.5 vs 58.0 at full budget (+2.6%), matching the target with 169.6M vs 197.0M tokens (−13.9%).
- **Ablations from shared checkpoints (+100M continuations):** removing Advisor context reconstruction reduces continued progress by 23.3–72.2%; removing Worker context isolation costs 5–11 cycles over 100M-token continuations but 224 cycles over a full 1B run (1336 vs the 1112.0 three-run mean) — unfocused contexts compound over longer horizons; removing Advisor assignments cuts progress by 10.5–84.2% in every comparison, with traces showing unassigned Workers independently implementing the same missing feature from identical starting code.
- **Coordination is cheap and scaling is task-dependent:** the Advisor consumes 0.24–0.51% of tokens and 1.20–2.29% of estimated cost, versus 8.39–10.70% / 6.14–7.35% for SwarmResearch's Shepherd. Going from 1 to 15 Workers cuts elapsed time by 6.6× (kernel) / 7.3× (FrontierSWE); the quality penalty of wide pools (W=7 trails W=1 by 337 cycles at 25%) vanishes at full budget (all widths finish within 4 cycles, 1107–1113). At matched $100 cost, GPT-5.4-mini Workers beat GPT-5.5 Workers on Git→Zig (20.88 vs 19.68) while GPT-5.5 wins on the kernel task — the optimal Worker model is task-dependent.

## Authors & Credibility

The 18-author team spans Stanford (Qizheng Zhang, Yoonho Lee, Genghan Zhang, Kunle Olukotun — a senior computer architecture figure), Carnegie Mellon, University of Washington (Radha Poovendran's group), SambaNova Systems, and UC Berkeley. First author Qizheng Zhang has prior work on agent context engineering (PEEK at NeurIPS, Agentic Context Engineering at ICLR 2026) and plan caching (NeurIPS 2025), which directly grounds this paper's context-management claims. The evaluation builds on benchmarks the co-authors know intimately — FrontierSWE (whose authors include collaborators cited here) and FrontierCS (an ICML 2026 paper with overlapping authors, e.g., Qiuyang Mang) — which lends implementation credibility but also means the team evaluates on tasks adjacent to their own prior work. Statements about kernel optimization benefit from Olukotun's and SambaNova's hardware expertise; the writing is unusually candid about single-run limitations.

## Critical Assessment

- **Novelty is architectural, not algorithmic.** No new learning or search algorithm is proposed; the contribution is a harness design principle (state/context separation) plus an evaluation protocol. That is a genuine and useful contribution — the CORAL trace analyses (a validated string.format feature dropped from the leading candidate for 33 attempts and recovered only because Agent B chose to audit old notes; two agents implementing the same namespace-prefix feature twice in 13 minutes) are compelling motivating evidence — but the idea is adjacent to existing memory/context-management work (PEEK, ACE, ReasoningBank), and the paper's own related-work section concedes these are composable rather than contrasting.
- **Statistical rigor is thin where rankings are asserted.** Only Anthropic kernel optimization with Codex has 3 seeds; every FrontierSWE, SOL-ExecBench, and FrontierCS number is a single run with no error bars. Claims like "+0.86 on Git→Zig" are well within plausible run-to-run variance — the kernel-task baselines alone vary by ±133.9 cycles across seeds — so per-task wins on the order of 1 point should be read as anecdotal even though the 93.1%-fewer-tokens and all-3-vs-all-9 kernel results are robust.
- **Baselines are unmodified upstream configurations while SLA's prompts are heavily task-engineered.** EvoX/CORAL/SwarmResearch run at pinned commits with default search logic, but SLA's Appendix E dedicates ~7 pages to task-specific Advisor/Worker prompts with hand-tuned rules (e.g., "assign at most one incremental lane," regime re-pivot semantics, comparison discipline). The comparison therefore measures framework + prompt effort jointly; a baseline granted equivalent per-task prompt engineering might close part of the gap, and this confound is not ablated.
- **Task selection is small and headroom-filtered.** Nine problems total, explicitly chosen because they "have headroom at our budgets." The authors honestly show the consequence: on SOL-ExecBench #210 nothing improves by more than 0.02 between 25% and 100% budget. How SLA behaves on saturated problems — where the motivating Figure 2a shows current systems merely race to a ceiling — is untested.
- **The "w/o Advisor reconstruction" ablation is an alternative, not an absence.** The variant still gets a bounded read-only interface over the full record (≤32 calls, 320K chars/epoch), so the ablation quantifies one specific alternative, not the value of curation in general; and per the limitations section, all ablations change what agents see, never whether they keep conversations across invocations — the headline principle itself is never directly ablated against a conversation-carrying harness under matched prompts.
- **Cost accounting favors token parity.** Matching on cumulative tokens with ~90% cached-input share understates roles with limited cache reuse (the authors note this themselves), and cost estimates exclude evaluator compute; the strongest baseline's 986.3M tokens vs SLA's 67.9M is a fair token claim but the dollar gap will differ by provider caching behavior.
- **Red flags:** none serious — the paper reports its own negatives (SLA loses to EvoX on tokens-to-match for SOL-ExecBench #1, trails at 25% budget everywhere on FrontierSWE), which is more honest than typical system papers.

## Strengths

- The state/context separation is a clean, implementable principle that directly attacks documented failure modes (context rot, premature stopping, duplicated work) with mechanism-level evidence, including elegant trace-level case studies of baseline failures.
- Token-based budgeting plus three reporting cutpoints (25%, 100%, tokens-to-match) is the right evaluation methodology for this area, and the demonstrated rank reversal (SLA last on all four FrontierSWE tasks at 25%, first on all four at 100%) is a genuinely important caution for the field.
- Enforced statelessness (Landlock sandboxes, cleared sessions, disabled subagents, protected evaluators) makes the design claims verifiable rather than aspirational, and checkpoint-continuation ablations isolate each component from identical starting states.
- Genuinely strong headline numbers at unprecedented budgets (1B tokens; all-3-vs-all-9 kernel dominance; 93.1% token reduction), with honest reporting of losses and single-run caveats.
- Practical corollaries: coordination is nearly free (0.24–0.51% of tokens), the Worker model can be chosen per task at matched cost, and Worker trials are shaped like bounded RL episodes, opening a concrete post-training pathway.

## Limitations

- Most main-result configurations are single runs (only Anthropic kernel + Codex and the checkpoint ablations are replicated); a long-horizon run costs hundreds to thousands of dollars, so per-task point estimates on FrontierSWE/SOL-ExecBench carry no uncertainty quantification.
- Ablations change only what each agent sees — not whether agents keep conversations — so the paper tests context curation, not the full statelessness principle against a stateful-harness control.
- All tasks have executable, fast evaluators; open-ended goals with vague or slow evaluation (the harder AutoResearch frontier) remain untested, and evaluator gaming remains a live risk the authors only mitigate with protected evaluators.
- Cost comparisons are token-matched; evaluator compute is excluded and cached-input share differs by role, so dollar-cost conclusions are approximate.
- Optimal Worker width is task-dependent (W=1 for Lua, W=3 for Dart, W=7 for libexpat), so practitioners still need per-task tuning; the default W=3 is safe but rarely optimal.

## Relevance

这篇工作与当前 LLM agent 研究的核心痛点——长周期运行下的上下文退化与多智能体重复劳动——直接相关，其"状态归 harness、上下文按调用重建"的原则可以立即借用到 autoresearch、SWE-agent 和多智能体编排系统的设计中；同时它用"排名随预算反转"的实证结果为如何评测长周期 agent 提供了方法论警示，是 context engineering 与 agent evaluation 两个方向都值得一读的系统性工作。

## Questions for Further Exploration

- The principle is validated only on tasks with executable evaluators — does harness-owned state + fresh contexts still help when feedback is noisy, slow, or subjective (hypothesis-driven science, paper-quality objectives)?
- Can the Worker trials (bounded contexts ending in a measured score) actually be used as RL episodes to post-train Workers or the Advisor, as Section 5 suggests — and would a trained Worker then obsolete the explicit-assignment mechanism?
- How much of the gap comes from SLA's ~7 pages of task-specific prompt engineering (Appendix E)? An ablation giving baselines equivalent per-task prompts would disentangle framework from prompt effort.
- Rankings reverse between 25% and 100% budgets — is there a cheap early-horizon signal that predicts "tokens-to-match," so practitioners can pick methods without running full budgets?
- Can SLA's outcome records serve as the substrate for cross-task memory (e.g., seeding the Advisor's context with an ACE-style playbook of kernel-optimization strategies), and does the stateless principle extend to Advisors split across partial views of a very large research state?
