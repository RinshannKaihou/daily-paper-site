> **一句话总结：** RaReCache 针对"小模型 KV 缓存线性映射到大模型后精度崩塌"的问题，提出 rank disagreement（全秩与截断秩预测之差）来挑出少数信息密集、映射失败的 token 只在目标模型端重算：Qwen3-0.6B→14B 的 23× 差距下仅重算 30% 的位置就把 GSM8K 从 plain transfer 的 76.3% 恢复到 93.8%（14B 原生 95.1%），Llama-3-8B→70B 的 8.8× 差距下重算 40% 达到 92.0% vs 70B 原生 95.3%，并在 A100 在线服务中把 p99 TTFT 降低 6.4×。

> **TL;DR:** Linear maps can translate KV caches between models of the same family, but accuracy collapses when the size gap is large — mapping Qwen3-0.6B's cache into Qwen3-14B yields only 76.3% on GSM8K vs the 14B's native 95.1%. RaReCache closes this gap by scoring each token with a novel "rank disagreement" metric (the squared gap between full-rank and rank-128 reduced-rank predictions of the fitted cache map), which flags out-of-calibration-distribution tokens that plain transfer gets wrong, and recomputing only the top ρ fraction in the target. On GSM8K with the 23× Qwen3-0.6B→14B gap, recomputing 30% of positions reaches 93.8% vs 76.3% for plain transfer (95.1% target-only); it beats attention- and ℓ2-error-based selectors (90.3% vs 82.3% random / 80.7% ℓ2-oracle at the same budget) and cuts single-request prefill latency by up to 2.31× (and 3.04× under batching), with 5.0×/6.4× median/p99 TTFT reduction in live serving.

## 核心贡献
- **发现并定位失败模式：** 跨模型 KV 缓存线性映射（Heo et al. 2026 的 closed-form map）的精度损失高度集中在少数"信息密集"token 上——校准子空间之外的内容 token——而不是均匀分布；GSM8K 全集中仅 0.23% 的重算位置落在共享模板前缀里。
- **提出 rank disagreement 度量：** 对每层/每侧的映射，用校准协方差的前 r=128 个主方向定义"well-described subspace"，以全秩预测 ŷ=xW+b 与 reduced-rank 预测 ŷ^(r)=xW_r+b_r 之差的平方和给 token 打分；可化简为 ‖z_i‖²−‖z_i V_r‖²，每次打分只需一次 d_s×r 投影，无需在目标模型上前向。
- **实证解释了常见启发式为何失效：** 14B 模型 72% 的注意力集中在 ⟨im_start⟩ sink token、24% 在模板/指令上、留给问题的仅 4%，因此注意力选择器在 ρ=0.2 时甚至不如随机；ℓ2 映射误差则混淆了"校准覆盖区内无害的插值误差"与"真正 OOD 的内容 token"。
- **广泛的跨规模验证 + 端到端系统收益：** 在 Qwen3（0.6B/1.7B/4B→14B，最高 23×）和 Llama-3（3.2B→8B、8B→70B，最高 8.8×）上验证，单请求 prefill 最高 2.31× 加速、批量饱和下 3.04×，在线 Poisson 负载下中位 TTFT 降低 5.0×、p99 降低 6.4×。

## Key Contributions
- A rank-disagreement metric: for each mapped layer and key/value side, the squared gap between the full-rank map prediction and a reduced-rank (rank-128) prediction refit on the calibration subspace identifies which tokens the linear map cannot represent — computable in closed form as ‖z_i‖² − ‖z_i V_r‖² with no target-model forward passes.
- An analysis showing why standard heuristics fail for selective recomputation: the target's attention concentrates on sink/template tokens (72% on the sink token of a GSM8K prompt), and raw ℓ2 mapping-error magnitude conflates harmless interpolation error with out-of-distribution content; at ρ=0.2 attention-based selectors score below random selection.
- Empirical evidence that failure is token-concentrated: recomputing a 30% minority of positions restores 95–99% of target accuracy across a 23× parameter gap (Qwen3-0.6B→14B), and 40% restores 96.5% across the 8.8× Llama-3-8B→70B gap.
- An end-to-end system evaluation on an A100 GPU (PyTorch eager) with BF16 map execution and block sharing: up to 3.04× prefill throughput vs full target prefill, and under Poisson load, a 1.80× higher saturation request rate (77.0 vs 42.7 req/s) with median TTFT reduced 5.0× and p99 reduced 6.4× at a 30% recompute budget.

## Methodology
**Base linear map.** Following Heo et al. (2026), for each target layer ℓ and each tensor type (key, value), a ridge regression maps a source cache entry x ∈ R^{d_s} (concatenation of K selected source layers, chosen by R² explained variance; K=8 for Qwen3 and Llama-3B, K=20 for Llama-8B→70B) to the target entry y ∈ R^{d_t}: W = (XᵀX + λI)⁻¹XᵀY, fitted offline over ~128k–350k calibration tokens drawn from the train split of the downstream task (disjoint from evaluation). Keys are de-rotated before fitting. The maps are large but cheap relative to the target (671M parameters for Qwen3, ~5% of the 14B target).

**Rank disagreement scoring.** Calibration predictions ŷ_n = x_n W + b define a distribution whose covariance Σ_ŷ = VΛVᵀ yields orthogonal directions; the span of the first r directions (r=128) is the "well-described subspace" V_r. Reduced-rank regression (Izenman 1975) refits the map restricted to this subspace: W_r = WV_rV_rᵀ with refitted bias b_r. A token's score is s_i = Σ_ℓ ‖ŷ_i − ŷ_i^(r)‖² summed over all mapped layers and both key/value sides. Since the two predictions agree inside the calibration subspace (the bias terms cancel: ŷ−ŷ^(r) = z_i(I−P_r)), the score equals ‖z_i‖² − ‖z_i V_r‖² — the energy a token's mapped entry places outside the directions the calibration data covers. Tokens recurring in every prompt (templates, task instructions) score near zero; content tokens with unique entities, quantities, or reasoning steps score high. The score costs one d_s×r projection per layer and side, which the map already computes, so selection overhead is small.

**Selective recomputation.** With budget ρ ∈ (0,1], RaReCache recomputes the top ⌈ρT⌉ positions (by score) with a real target-model forward pass and reads the linearly mapped cache everywhere else. A single shared position set is used across all layers (per-layer overlap with the pooled set ≥ 0.87 for rank disagreement vs 0.68 on average for the ℓ2 oracle), which keeps the target pass efficient.

**System optimizations.** The naive FP32 map implementation is slower than the target prefill it replaces (0.63–0.85×) because A100 FP32 GEMMs bypass Tensor Cores; executing the map in BF16 and caching the 50 de-rotated source blocks (otherwise reconstructed 640× per prompt across layers/heads) brings the pipeline to 1.16–1.95× single-request speedup. The evaluation assumes the source model has already prefilled the prompt (cascade / model-switch scenarios), matching the deployment setting of Heo et al. (2026).

## Results & Highlights
- **Cross-family headline (Qwen3-0.6B→14B, 23× gap, GSM8K n=1319):** plain transfer (ρ=0) gets 76.3% vs the 14B's native 95.1% and the 0.6B's own 56.1%. Recomputing 20% of positions reaches 90.2% (94.8% retention), 30% reaches 93.8%, and 50% reaches 95.3 — slightly above the 14B alone. At ρ=0.5 it also hits 72.6% on MMLU-Redux (n=5700; 14B alone 78.6%, plain transfer 47.4%) and 59.7 F1 on LongBench-E QA (14B alone 65.9, plain transfer 25.4, source alone 33.5).
- **Llama-3-8B→70B (8.8× gap, GSM8K, first 300 items):** plain transfer scores 81.0 (retention 85.0) vs the 70B's 95.3 and the 8B's own 82.7; recomputing 40% raises this to 92.0 (96.5% retention, ~10 pp above the 8B alone). The close-gap 3.2B→3.1-8B pair (2.5×) actually exceeds the target at ρ=0.4 (86.4 vs 85.8).
- **Selector ablation (30% budget, 300 GSM8K items, Qwen3-0.6B→14B):** rank disagreement reaches 90.3%, beating random (82.3), source-attention (75.0), target-attention (73.7), and even the ℓ2 mapping-error oracle (80.7) — attention selectors underperform random because 72% of the 14B's attention sits on the ⟨im_start⟩ sink and only 4% on the question.
- **Vs. existing reuse systems (matched 30% budget, GSM8K, 0.6B→14B):** RaReCache 90.3% vs a CacheBlend-style ℓ2-error oracle at 80.7% and DroidSpeak-style layer-prefix recomputation at 79.0%; no-recompute is 73.5% and the 14B alone 94.1%. Layer-prefix scaling fails because mapping errors concentrate in a minority of tokens at all depths rather than in isolated early layers.
- **Reverse direction (14B→smaller, MMLU-Redux n=5700):** transfer lifts the 1.7B by +14.4 pp (57.5→71.9) and the 4B by +3.1 (70.2→73.3), but hurts the 0.6B (−7.8, 27.2 vs 35.0 alone); recomputation does not help in reverse (moves accuracy ≤0.7 pp) because the 14B source's map refits cleanly (R² 0.90–0.91) — the instability the score detects is specific to the small-source direction.
- **System performance (A100 80GB, PyTorch 2.6 eager, GSM8K mean T=149):** single-request prefill speedup 1.38×/1.95×/2.31× at ρ=0.5/0.3/0.2; with batching (device saturation) up to 3.04× at ρ=0.2, with prefill throughput reaching 12,378 tok/s vs the target's ~6.5k saturation. Under Poisson load at λ=42 req/s, end-to-end TTFT is 173 ms vs 870 ms for the baseline (5.02×) and p99 is 284 ms vs 1805 ms (6.35×); saturation throughput is 77.0 vs 42.7 req/s (1.80×).

The authors are from USC (Sreetama Sarkar, Peter A. Beerel), UC Irvine (Saptarshi Mitra, Sitao Huang), and Intel Labs (Souvik Kundu) — an academic-hardware-lab collaboration well positioned for LLM-serving systems work; Sarkar and Beerel have prior track records in efficient inference hardware, and Kundu's group has published extensively on efficient transformer inference (e.g., at Intel). Equal-contribution notation marks Sarkar and Mitra. Claims are carefully hedged (e.g., the theoretical speedup ceiling analysis in Appendix B.4 openly reports that naive FP32 mapping is *slower* than the prefill it replaces), which raises trust in the headline numbers.

## Critical Assessment
- **Calibration leakage concern by design, not misuse:** the linear map is calibrated on the train split of each *specific downstream benchmark* (e.g., GSM8K train split, formatted like evaluation prompts, 128k–350k tokens per task). The authors are upfront (Appendix D) that the map is "sensitive to the distribution of the calibration data" and that task-agnostic calibration is future work — but this means every headline number assumes the deployment site knows, per-task, what kind of prompt is coming. In a mixed-traffic server this advantage may shrink, and the paper does not measure cross-task transfer of a map.
- **The reverse-direction result undercuts generality of the "recompute OOD tokens" story:** mapping 14B→0.6B *hurts* MMLU-Redux (27.2 vs 35.0 alone), and rank disagreement cannot fix it (moves ≤0.7 pp) because the score finds no instability when the source is large. So RaReCache is specifically a "small-source→large-target" tool; the abstract's framing as general cross-model KV reuse is somewhat broader than what the evidence supports.
- **Baselines for the system comparison were re-implemented, not run as-is:** CacheBlend and DroidSpeak were not designed for cross-model transfer, so the comparison adapts their selection rules into the authors' pipeline. This is a fair apples-to-apples choice but not a head-to-head against the actual systems; the oracle-grade ℓ2 baseline at 80.7% is the more honest reference.
- **Efficiency gains are kernel-limited and partially self-inflicted:** the naive FP32 map runs at 0.63–0.85× (slower than full target prefill) and the reported speedups depend on BF16 execution plus source-block caching fixes; also, recomputed tokens attend over the full context with an explicit mask rather than a causal-aware sparse kernel, so the 2.28×–2.74× ceiling at T=2048 falls short of the 1/ρ asymptote (custom kernels deferred to future work). Honest reporting, but it means current gains are implementation-contingent.
- **Small-sample or subset evaluations in places:** the Llama-3 8B→70B numbers are on only the first 300 GSM8K items, and Figure 7/8 selector comparisons use 300 samples — adequate for the large gaps shown but with non-overlapping confidence not reported for every cell (Table 5 does mark significance at ±0.86 for one benchmark).
- **Same-family assumption:** transfer requires shared tokenizer/vocabulary and architecture family (Qwen3↔Qwen3, Llama-3↔Llama-3); cross-family transfer remains open, as the authors acknowledge.

## Strengths
- A genuinely novel selection signal: rank disagreement is cheap (one d_s×r projection), training-free, and provably reduces to an OOD-energy measure via a clean derivation (Appendix A); beating *both* oracles built on ℓ2 mapping error and raw attention is a strong, counterintuitive result with a convincing mechanistic explanation (72%/24%/4% attention split on sink/template/question).
- The problem is real and timely: coding agents and routing cascades routinely switch models mid-session, forcing full re-prefill of long shared contexts.
- Unusual thoroughness on the systems side: an honest accounting of why the naive implementation is slow (FP32 Tensor-Core bypass), a phase-by-phase cost breakdown (Figure 10, Table 3), an analytical FLOP speedup ceiling, and live-server queuing evaluation with wall-clock TTFT rather than GPU-busy time only.
- Comprehensive coverage of scale gaps (3.5×–23×), two model families, five benchmarks, and both transfer directions, with paired comparisons showing e.g. the 0.6B at ρ=0.4 beating the 4B with no recomputation by 4.6 F1 on LongBench-E.

## Limitations
- Requires per-task calibration data closely matching the deployment distribution; a task-agnostic, universally representative calibration corpus is left to future work (Appendix D).
- Confined to the same model family (shared tokenizer and vocabulary); heterogeneous-family KV transfer is unsolved.
- Recomputation does not help the large-to-small direction, and transfer can actively degrade the smallest targets (0.6B: −7.8 pp on MMLU-Redux).
- Efficiency depends on engineering mitigations (BF16 map, block sharing) and currently forgoes the custom sparse causal attention kernels that would approach the theoretical 1/ρ ceiling; long-sequence ceiling degrades from 2.74× (T=2048) to 2.28× (T=32,768) with standard kernels.
- The largest-gap headline (8B→70B) is evaluated on a 300-item GSM8K subset rather than the full test set.
- Code is promised "upon de-anonymization and publication" — not yet available for independent verification.

## Relevance
与用户关注的 LLM 推理效率与多模型服务系统方向高度相关：它把"跨模型 KV 缓存复用"从同规模模型推进到 23× 规模差距，用无需训练的 rank disagreement 打分实现选择性重算，并同时给出精度与在线服务延迟（TTFT p99 6.4×）双维度证据。对构建 model cascade、coding agent 中途换模型或共享前缀缓存基础设施的工作，这篇提供了可直接借鉴的选择性重算思路与系统开销分析。

## Questions for Further Exploration
- Can a single task-agnostic calibration corpus (or a small mixture) support maps that generalize across unseen task types, and how much accuracy/retention is lost relative to per-task calibration?
- Would a sparse causal attention kernel (skipping masked query-key pairs) push the long-sequence regime to the theoretical 1/ρ ceiling, and does the optimal recompute budget ρ shift with context length?
- The rank-disagreement score finds no instability in the large-to-small direction — is there a complementary signal that could rescue the 0.6B reverse-transfer case, or is the 0.6B's representational capacity simply the binding constraint?
- How does rank disagreement behave under domain shift between calibration and serving traffic (e.g., calibrated on GSM8K, served code or conversational prompts)?
- Could the score be extended to select tokens per-layer rather than with a shared position set (overlap with the per-layer ℓ2 oracle is only 0.68 in deep layers), and would that close the remaining 3.8-point gap to the 14B at ρ=0.3?
