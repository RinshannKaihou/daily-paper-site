Why this matters02

Everyday training and inference ride on PyTorch/MindSpore, which silently misbehave — these 41 developer-confirmed cases are a practical debugging reference for framework-level anomalies.

Critical edge03

Of 55 submitted reports only 7 were fixed (12.7%) — on PyTorch, 8 confirmations yielded 0 fixes; the “79 vs 28” headline counts detections and confirmations, not fixed defects.

MethodologyTFG → FlowMuT

01

Profile into a Tensor Flow Graph

One profiling run records per-edge tensor state F(e) — shape, dtype, layout, aliasing, gradient — plus operator input requirements R(v) mined from docs. TFG = topology G + F + R.

02

Mutate = constrained subgraph replacement

A 147-operator pool (99 CG-only · 21 shared · 27 TFG-only); each operator is pattern + replacement + input/internal/output constraints.

03

Filter illegals by data-flow constraints

Operators pair with tensor-edge-anchored sites in O(|E|); the three constraint classes reject candidates that would fail for non-bug reasons.

04

Select with a contextual bandit

LinUCB scores candidates on 3 coverage + 2 impact features, rewarded by DFSD novelty; accepted mutants re-seed the next round.

Evaluation: 14 seed models (ConvNeXt-V2 → Qwen2.5-0.5B) × PyTorch / MindSpore — 112 bug-discovery campaigns plus 280 ablation runs (10 × 250 rounds each), 95% intervals.

  • Report outcomes: 55 filed (14 PyTorch / 41 MindSpore) → 41 confirmed, 7 fixed; symptoms: 31 crashes, 18 numerical errors, 6 state errors.
  • Legality: constraints lift the legal-mutant rate 86.4% → 96.7%; filter precision 89.2% but recall 78.7% on a 1,000-candidate manual audit.
  • Selection: LinUCB vs random search lifts C++ coverage 33.3% → 48.1% despite near-equal DFSD (+1.1%).
  • Cost: 10.63 s/test case — cheaper than COMET (11.36 s), ~2× DevMuT (5.18 s) and LEMON (4.04 s). Pool ablation: the CG-only 120 ops beat the TFG-only 48 ops on every metric; the full 147 is best overall.

Strengths04

  • Crisp problem decomposition — three data-flow challenges (description, legality, diversity) motivated by one running example (SDPA).
  • TFG is a clean, reusable abstraction; constrained subgraph replacement unifies previously ad-hoc mutation taxonomies.
  • Systematic pool construction with explicit provenance (19 source studies) and positive/negative validation of every operator.
  • Real-world impact evidence — 41 confirmations, 7 fixes, 2 security-acknowledged DoS vulnerabilities, not just crash counts.
  • Comprehensive ablations with repeated runs and confidence intervals; fully open artifact including mutants and triggering tests.

Limitations05

  • Only PyTorch + MindSpore on x86 CPU/single GPU — no TensorFlow/JAX/XLA, no distributed or accelerator-diverse settings.
  • 7 of 55 reported bugs fixed; PyTorch confirmations produced 0 fixes so far — long-horizon impact open.
  • Diversity metrics are tiny in absolute terms; their link to defect-finding power is asserted, not causally established.
  • Legality ground truth is a 1,000-sample manual audit; filter recall 78.7% leaves ~21% illegal-mutant leakage.
  • ~2× per-case cost of cheapest baselines; largest seed model is 0.5B params — nothing near frontier scale tested.
  • Operator requirements R(v) are manually extracted from docs/source and may lag framework API changes.

Questions for further exploration06

  1. Does TFG-style grounding transfer to compiler stacks (TorchInductor / TVM / XLA), where fusion and layout decisions hide data-flow bugs?
  2. Can the 27 TFG-only operators — e.g. via LLM-mined requirements from docs — be expanded to close the gap with the CG-derived pool?
  3. Does +43.4% DFSD causally drive detection, or does constraint-filtered legality do the work? A detection-per-legal-mutant analysis would tell.
  4. How does profiling cost scale beyond 0.5B-parameter seeds — is the per-round TFG rebuild practical at LLM scale?
  5. Could learned legality classifiers trained on the 1,000 labeled candidates lift filter recall above the hand-written constraints’ 78.7%?
