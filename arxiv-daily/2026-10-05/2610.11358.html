RaReCache: Bridging the Gap in Cross-Model KV Cache Reuse via Rank disagreement-based Selective Recomputation

Sreetama Sarkar, Saptarshi Mitra, Sitao Huang, Souvik Kundu, et al. — USC · UC Irvine · Intel Labs

Key metric

93.8%

GSM8K accuracy on Qwen3-0.6B → 14B (23× gap): 76.3% plain linear transfer → 93.8% with 30% recompute · 14B native: 95.1%.

Why this matters

为 model cascade、coding agent 中途换模型与共享前缀缓存 infra 提供可直接借鉴的选择性重算思路——精度与在线 TTFT 双维度证据齐全，无需训练。

Critical edge

Every headline number assumes the server knows which task is coming — the map is calibrated on each benchmark's own train split, and cross-task transfer in mixed traffic is never measured.

Methodology

Source KV cache (e.g. Qwen3-0.6B) — K selected source layers, keys de-rotated
↓ ridge map per target layer × {K,V}
Linear map W = (XᵀX+λI)⁻¹XᵀY, fitted offline on 128k–350k calibration tokens; ~5% of target size
↓ score every token
Rank disagreement — si = ‖zi‖² − ‖ziVr‖² : energy outside the rank-128 calibration subspace; one ds×r projection, no target forward pass
↓ split positions
Recompute top ⌈ρT⌉ with a real target pass (one shared position set, per-layer overlap ≥ 0.87) · mapped cache elsewhere
  • Why heuristics fail: 72% of the 14B's attention sits on the ⟨im_start⟩ sink, 24% on template — only 4% on the question; raw ℓ2 error conflates harmless interpolation with true OOD content.
  • Made fast: naive FP32 map runs at 0.63–0.85× (slower than the prefill it replaces); BF16 execution + caching 50 de-rotated source blocks bring 1.16–1.95× single-request.

Reverse direction (14B→small): transfer lifts 1.7B +14.4 pp and 4B +3.1 on MMLU-Redux, but hurts the 0.6B (−7.8 pp) and recomputation moves ≤0.7 pp — the signal is specific to small-source→large-target.

Strengths

  • Genuinely novel, cheap signal — training-free, one projection per token, with a clean derivation showing it is an OOD-energy measure; beats both attention- and ℓ2-oracle selectors.
  • Real, timely problem — cascades and coding agents re-prefill long shared contexts on every model switch.
  • Unusual systems honesty — openly reports the naive FP32 map is slower than the prefill it replaces; evaluates wall-clock TTFT on a live server, not just GPU-busy time.
  • Wide coverage — 3.5×–23× gaps, two model families, five benchmarks, both transfer directions.

Limitations

  • Per-task calibration leakage — map fitted on each benchmark's own train split; task-agnostic calibration is future work.
  • Small→large only — reverse 14B→0.6B transfer degrades accuracy (−7.8 pp) and the score cannot detect it.
  • Same family only — requires shared tokenizer/vocabulary; cross-family transfer unsolved.
  • Engineering-contingent gains — depend on BF16 + block sharing; without a sparse causal kernel the ceiling is 2.28×–2.74×, not 1/ρ.
  • Verification gaps — 8B→70B headline on a 300-item subset; code promised only "upon de-anonymization".

Questions for further exploration

  1. Can a task-agnostic calibration corpus (or small mixture) support maps that generalize across unseen task types — at what accuracy cost vs per-task calibration?
  2. Would a sparse causal attention kernel push the long-sequence regime to the theoretical 1/ρ ceiling, and does optimal ρ shift with context length?
  3. Is there a complementary signal to rescue the large-to-small direction, or is the 0.6B's representational capacity the binding constraint?
  4. How does the score behave under domain shift between calibration and serving traffic (calibrated on GSM8K, served code or chat)?
  5. Could selection be per-layer rather than one shared position set (per-layer ℓ2-oracle overlap is only 0.68 deep), closing the remaining 3.8-point gap at ρ=0.3?
