Paper Dashboard · Agentic DS Failure Audit

Every agent×LLM configuration commits silent methodological failures in ≥43% of pipelines — and accuracy alone rewards the leakage.

The Silent Failures in Agentic Data Science

Xue Li, Hongqian Xia, Daniel Gomm, Acácio Santos et al. · CWI Amsterdam | 2026-10-05 | arXiv:2610.14115 LLM Agents Agentic Data Science Data Leakage Evaluation Benchmark

Key Metric

≥43%

of pipelines carry at least one silent failure mode — true of every one of the 9 agent×model configurations audited across 220 tasks.

Why This Matters

Benchmarks that judge agentic data science by accuracy alone systematically reward data leakage; this taxonomy and test suite enable stricter agent evaluation.

只看准确率的 agentic DS 评测会系统性奖励数据泄漏——这套失败分类法与可控测试套件可直接用于更严格的 agent 评测设计。

Critical Edge

The headline numbers rest on an LLM judge with precision 0.71 / recall 0.65 — roughly a third of failures missed, ~29% of flags false positives.

Also: the leakage↔rank link is observational, not causal — leaking pipelines aren’t randomly assigned, so confounding is not ruled out.

01Methodology

Three evaluation angles, triangulated.

  1. 1

    Large-scale sweep (LLM-as-judge)

    220 tabular tasks from 5 sources × 9 configurations (ReAct, AIDE, MLE evolve × Qwen-3.5-4B, Qwen-3.8-27B, Gemini-3.7-Flash). A two-stage judge first reconstructs each pipeline’s structure to drop inapplicable modes, then issues binary verdicts with code-line pointers over a 15-mode taxonomy spanning formulation → preprocessing → splitting → features → model selection → evaluation.

  2. 2

    Controlled test suite

    6 unit-test-style tasks (17 tasks, 3 datasets, 5 runs each), each embedding exactly one pitfall — imbalance, messy formatting, spurious correlation, missing transformation, selection leakage, wrong metric — with hint levels from none to explicit, separating “didn’t recognize” from “couldn’t execute”.

  3. 3

    Expert reference (Kaggle)

    Agent submissions to 5 challenges, scored against AutoGluon and each challenge’s 1st-place human solution; case study on the leaked PCIAT_Total feature.

judge reliability · 89.5% human agreement, κ=0.62, P=0.71 / R=0.65 · memorization controls (column renaming + Wilcoxon): all p n.s.

  • Leakage tracks better rank. In the rank-residual analysis every data-leakage mode pushes rank positive while non-leakage modes push negative; skipping the validation split costs on average >1 full rank position, and a single eval metric is paradoxically associated with a better rank.
  • Capability covers the stages, not the practices. Gemini-3.7-Flash ignores temporal order in >⅓ of applicable pipelines for all three agents; 50% of MLE evolve + Gemini pipelines leak validation→train despite built-in leakage checks.
  • The taxonomy is incomplete by design. 37% of pipelines carry judge-flagged failures outside the fixed 15 modes (mostly validation→train leakage).
  • Model gains don’t transfer uniformly to methodological decisions: gpt-5.6-sol beats Gemini-3.7-Flash only on some controlled tests.

Strengths

  • First methodology-level (not execution-level) failure audit of DS agents at scale — 220 tasks × 9 configs with published judge reliability.
  • Central finding is quantified, not asserted: leakage modes track better test rank; skill modes track worse — directly motivating beyond-accuracy evaluation.
  • Triangulated evidence: naturalistic sweep + hint-leveled controlled suite + expert-referenced Kaggle leaderboards, with memorization controls.
  • Concrete design guidance from the expert case study: problem formulation, task-specific objectives, late threshold optimization, multi-seed 10-fold CV, model diversity.
  • Reproducibility posture: public project resources, budget-matched agents, AI-use statement, human-validated artifacts.

Limitations

  • Judge precision 0.71 / recall 0.65 bounds every downstream prevalence and correlation claim; no large-scale human re-annotation.
  • Leakage↔rank association is observational; confounders unruled, no intervention study (only evidence: MLE evolve’s built-in checks still fail 50%).
  • Narrow coverage at scale: 3 frameworks, 3 LLMs (one closed); frontier models appear only on the 17-task suite; agents capped at 10 steps, unablated.
  • Curated suite is thin — 6 tests over 3 datasets; the striking 1.0 failure rates rest on n=3.
  • 37% “other”-category failures analyzed only qualitatively; applicability filters shape per-mode denominators.
  • Tabular regression/classification only; evaluation labels and splits taken as given; no time-series or text tasks.

03Questions for Further Exploration

Open threads the paper itself points at.

  1. Can the leakage↔rank link be made causal via controlled injection (same pipeline ± the leaked feature)?
  2. Would a verifier agent with veto power catch what MLE evolve’s built-in checks miss (50% leak rate)?
  3. Do GPT-5-class / Claude models show the same “capacity covers stages, not practices” pattern on all 220 tasks?
  4. Can code-grounded unit tests push the judge past P/R 0.9, making silent-failure detection cheap enough to run in every eval?
  5. Hints fix ReAct/AIDE but not MLE evolve — is “recognition vs constraint propagation” testable by instrumenting the search loop’s memory?
