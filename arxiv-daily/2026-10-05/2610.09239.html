LLM self-improvement loops overstate their gains by 13–20 points on small validation sets — and no acceptance rule beats greedy.

The Winner’s Curse in LLM Self-Improvement Loops: Selection Noise, Lock-in, and Acceptance Rules

Litao Hu (Meta) · Yutong Tang (Microsoft)

Key metric · reported-gain inflation
13–20 pts

Self-reported proxy minus held-out accuracy for greedy loops at n = 16 selection items (e.g. +15.9 ± 2.7 on 1.5B TREC, Holm p=0.002). Shrinks to 1–5 pts at n = 256 — a paired ~15-point reduction.

Why this matters

Anyone running GEPA, MIPROv2, or self-improvement loops: small validation sets systematically overstate gains — report held-out scores with uncertainty alongside.

小验证集上“好一点就保留”会系统性虚报收益，常见验收规则救不回来。

Critical edge

The paper’s own 64-item audit still leaves 5.7 points RMSE on reported gains — as large as a typical true gain.

Scope is narrower than the headline: instruction rewriting on three tasks; stochastic-rollout noise — the practically dominant case — is predicted but never measured.

Methodology

seed instruction→ proposer draws K=4 rewrites→ score on n-item set→ argmax Δ̂, keep iff Δ̂ > 0→ incumbent reused ↻ lock-in

The model. Keep-if-better is best-of-K selection under correlated noise: all candidates in a generation share a common error (same incumbent, same items) plus idiosyncratic noise — a Gaussian selection model whose variances are identifiable from item-level logs. Three propositions: (1) winner’s-curse size via a breeder’s-equation factor h²w plus shared error; (2) the Bayes-optimal commit is a threshold τ* = −μe²/s² — greedy is optimal only when proposals are harmless on average; (3) a Goodhart regime where pure-noise loops commit more as K grows while held-out drifts down.

The empirics. Qwen2.5-1.5B/7B loops rewrite their own instructions on TREC-50, Banking77, GSM8K, with every candidate also scored on a 600-item held-out gold set (oracle instrumentation, n ∈ 8..256). A pre-registered confirmatory study (4 settings × 9 arms × 8 seeds; design archived ten minutes into the runs) separates evaluation-set size from proposer context. GEPA and MIPROv2 runs are instrumented, with every GEPA metric call reconstructed from saved state. Acceptance rules compared: greedy, McNemar, PACE, select-then-confirm, calibrated Bayes gates.

GEPA’s held-out gain never grows with nval (18.5 / 20.4 / 19.0) — the small set allowed 10× more search. MIPROv2 pairing: +5.6 ± 0.7, p=0.001, 6/6 seeds.

  • Curse size matches theory: true-to-measured selection-differential ratio tracks the noise model with MAE 0.034 across nine oracle settings (200 gold-set splits); at n=16 the winner’s held-out differential is only 1–51% of its measured value.
  • No acceptance rule wins: Bayes gate ends 2.1 ± 1.1 pts below greedy pooled at n=16 (−5.7 ± 1.6 on GSM8K); select-then-confirm −1.6 ± 1.2; McNemar forfeits −7.4 / −12.3 TREC pts. Incumbent inflation acts as an unmodeled implicit threshold — the “lock-in” mechanism.
  • Most rewrites are harmful: only 4–39% of post-generation-1 candidates beat the incumbent; Qwen3.5-4B’s first rewrite delivers 90–112% of the final gain.
  • Cheap audit works: scoring seed + incumbent on 64 never-used items costs 128 evals (~10% of the n=16 budget), removes average bias, cuts reported-gain RMSE from 15.5 to 5.7 pts.
  • “Bigger n helps” is not universal: held-out gains grow with set size on TREC (13.7 → 24.2 pts at 1.5B) but not on GSM8K (+1.6 ± 2.2, p=0.483).

Strengths

  • Rare rigor: pre-registered hypotheses, archived analysis scripts, Holm-corrected seed-paired tests, disjoint fresh gold sets, explicit deviation reporting.
  • Clean, practitioner-mappable toolkit: inflation vs overstatement, shared vs idiosyncratic error, lock-in — all identifiable from item-level logs.
  • Honest negative results: none of five rules improves whole runs; the exploratory Goodhart effect failed to replicate and the authors say so.
  • Extends beyond toy loops to GEPA and MIPROv2, with exact reconstruction of every GEPA metric call.
  • Actionable, quantified guidance: the 64-item audit at ~10% of nominal budget; report held-out score + SE alongside selection score.

Limitations

  • Instruction rewriting only: no agentic or code tasks, proposers ≤27B; stochastic-rollout noise analyzed as prediction, never measured.
  • Held-out validation checks require oracle instrumentation native loops don’t have; the native-loop check is post hoc, four settings.
  • Rules tested at one error level, one budget; Bayes gates need a pilot with a large evaluation set — an oracle-flavored input.
  • Lock-in measured only associationally; long-recursion dynamics and recursive self-improvement explicitly not modeled.
  • Per-setting prediction errors of several points even where averages match; the audit still leaves RMSE ≈ 5.7 pts.

Questions for further exploration

  1. Does the winner’s-curse size transfer to stochastic rollouts (agentic tasks, code execution), where per-candidate noise is much larger and Proposition 1 predicts a bigger curse?
  2. Can acceptance thresholds be calibrated from the loop’s own item-level logs alone — no oracle pilot — and at what sample size does that beat greedy?
  3. Is lock-in net beneficial or harmful? Can the incumbent’s error, an accidental implicit threshold, become a principled free acceptance rule?
  4. How does the set-size vs search-budget trade-off behave in optimizers like GEPA, where more validation items bought no held-out gain?
  5. Do the conclusions hold for population-based search and multi-incumbent loops, where the shared-error structure breaks?
