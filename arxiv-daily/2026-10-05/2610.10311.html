MIT 团队花费 40,000 GPU 小时在模拟故障硬件上训练数千个 Llama2 风格 transformer，发现与故障共同训练+推理的“故障加固”模型遵循带新二次曲率项 α₂ 的修正 Chinchilla 缩放律——大模型自发学出开销有界的“好”纠错码，而未加固的基线在推理期故障下出现回退缩放与 logits “升温”。

Key metric
40,000 GPU-hours

Thousands of Llama2-style transformers (7.9×10⁵–9.3×10⁸ params) trained under 17 fault rates, up to p = 0.2 — the largest fault-hardening study to date.

Why this matters

First fault-hardened scaling law gives a testable basis for running LLMs on unreliable, low-energy hardware — reshaping the cost calculus of low-voltage inference.

Critical edge

Every result is a simulated i.i.d. block-drop fault in exact arithmetic — no experiment touches real low-voltage silicon, so the energy-savings story remains a projection.

— Critical Assessment / Limitations

01Methodology — distilled

Definitions. A fault-hardened model is trained and evaluated with hardware fault rate p; the fault-blind baseline is the conventional fault-free model. Computational capacity η is the fault-blind size needed to match a fault-hardened model at equal data — so η/N is the fraction of parameters doing useful work, the analog of a code’s rate.

LN = e α₀(p) − α₁(p)·n − α₂(p)·n²   (Eq. 4 — modified Chinchilla; α₂ ≡ 0 at p = 0)
  1. Inject faults like real hardware. Only matrix-product operands (>99% of FLOPs): contiguous k=4 blocks zeroed with probability p each forward pass — exactly LENNA’s RRNS check, which detects errors and drops the connection, turning arbitrary-magnitude faults into benign drop-connect.
  2. Train a wide ladder. 16 log-spaced Llama2-style sizes, token budgets to 3.5×10¹⁰ on a 350B-token FineWeb slice, 2 seeds per cell; one fixed-N model grid (8 budgets × 6 rates × 8 seeds) for inference-time analysis.
  3. Fit the modified scaling law per fault cohort (Huber loss, multi-start, 1,500 bootstrap resamples), with α₂ pinned to zero only for the fault-free cohort.
  4. Read out the code. Solve for η/N: a parabola in log-size with minimum at critical size N* — the signature of a “good” code like the brain’s grid code. Decompose fault-blind collapse into logit “heating” + irreparable scrambling via an exact exponential-family KL split (Eq. 8).

03Strengths

  • Largest, cleanest evidence to date for error-correction-enhanced evolvability in LLMs — a falsifiable, closed-form law with a mechanistic, cohort-measured α₂.
  • Physically grounded fault model: matmul-only faulting justified by measured >99% FLOP share; injection semantics mirror a specified accelerator (LENNA RRNS).
  • Two-sided value: constructive (hardening gets relatively easier with scale) plus diagnostic (collapse exactly decomposed into heating + scrambling).
  • Honest epistemics: measured vs. extrapolated curves visually distinguished; the 10⁶ GPU-hour decisive experiment costed openly; full code + multi-terabyte weights released.

04Limitations

  • No physical hardware: all faults are simulated in exact arithmetic — the energy-efficiency narrative is a projection, not a measurement.
  • Loss-only evaluation: pretraining loss on FineWeb alone; whether a fault-hardened model remains a useful model is untested.
  • Conjecture untested at scale: max size 9.3×10⁸ is ~100× below the ~10¹¹ scale where Eq. 3 would be decided; the decisive term A(p,N) is indistinguishable from zero in range.
  • Gauge ambiguity: floor E, N₀, D₀ fixed by fiat — absolute η/N and N* values are conditional on those choices. Single architecture family, k=4 i.i.d. faults, mostly 2 seeds.

05Questions for further exploration

  1. Does fault-hardening preserve instruction-tuned and downstream capabilities — and what happens to α₂ after SFT/RLHF?
  2. Does the conjecture survive correlated fault modes (stuck-at rows, noise on the check circuitry) rather than i.i.d. block drops? Can “model organism” runs predict 10¹¹-scale behavior?
  3. How does block drop-connect interact with MoE routing, grouped-query attention, and quantization?
  4. What is the measured end-to-end energy win of LENNA-style detection + a hardened model vs. an FP8/FP4 GPU at matched accuracy, including the token premium from β₁(p)?
  5. Is the fault-tolerance threshold p_th measurable as a function of scale, and does it connect quantitatively to Eigen-style error thresholds?
