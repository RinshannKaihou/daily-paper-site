Read the failure composition: harness evolution lifts agents until planning failures (F4) dominate — then train the weights.

Harness Evolution Hits a Ceiling: When Weight Training Should Begin

Yuan Tian, Bing Hu, Hao Wang, et al. 2026-10-05 · preprint LLM agents harness evolution failure taxonomy LoRA fine-tuning

Key metric

+0.133

Qwen3.5-4B held-out gain from harness self-evolution (0.164 → 0.297), far above the measured 0.035 noise floor — then the curve plateaus, with F4 as the residual.

9B: +0.119 · LoRA alone under seed harness: +0.126 / +0.131

Why this matters

For anyone evolving agent harnesses or fine-tuning on trajectories: a noise-aware, executable rule for which lever to pull next — no new infrastructure.

Critical edge

Much of the 4B “gain” is delivery, not better plans — on WebArena-Lite, accuracy among delivered answers fell 0.47 → 0.44 while the headline +0.088 was banked.

Methodology how they know

  1. Label by first failure signal. A deterministic checker tags each trajectory healthy / F1 evidence / F2 harness friction / F3 execution control / F4 planning capability — no LLM or human annotator.
  2. Measure against a noise floor. DeepPlanning: 120 programmatic-scored travel-planning tasks (48 dev / 72 held-out), 4 rollouts per cell; per-rollout σ 0.023 → differences under 0.035 are noise. Fresh anchor after every accepted edit.
  3. Evolve the harness. AHE-style loop: evidence package → Kimi K3 proposes edits → 4-rollout eval vs anchor → fixed accept rule (4B: 13 rounds / 10 accepts; 9B: 5 / 3).
  4. Train the weights. LoRA rank 32 on best evolved-harness trajectories (82–98), with a placebo adapter control on 9B; full-parameter FT on a second textbook.

checker labels → evolve harness (dev only) → plateau at F4 → LoRA on evolved trajectories → rule validated on 9 model lines + WebArena-Lite

  • The rule predicts all nine lines. Where seed delivered-plan quality ≥ 0.27 and F4 isn’t the largest class (5 lines), the harness paid +0.053…+0.136; where quality is 0.13–0.17 (three sub-8B lines), it paid nothing; Gemma 4 12B (F4 largest) is correctly routed to weights.
  • WebArena-Lite (117 unseen tasks): same shape, +0.088 (0.256 → 0.344) — but the gain lives in what the model sees (one interface edit = +0.12 of dev), and adapters add nothing.
  • Capability grants carry the gain, enforcement doesn’t: removing evolved tools costs −0.067/−0.120 and the lessons file −0.049/−0.076; hard blocks sit within noise.

Strengths

  • A falsifiable rule, not vibes. Taxonomy-by-lever makes the claim testable — and each LoRA adapter moves exactly the failure class the rule assigns it: a clean cross-over validation.
  • Exemplary measurement hygiene. Measured noise floor, same-night paired comparisons, fresh anchors, a selection-optimism bound (Prop. 1), and a placebo adapter that alone demolishes “any trajectories help.”
  • Honest negatives. Three of nine lines where the harness paid nothing get full detail; the WebArena non-stacking is presented, not hidden; Appendix G documents the authors’ own measurement bugs.
  • Directly actionable. Needs only a deterministic scorer, process signals, and one noise measurement; the two-textbook result is a useful design hint for trajectory training.

Limitations

  • Delivery ≠ quality. The 4B gain is largely Δr (delivery 59 → 88%; quality among delivered only 0.266 → 0.332); on WebArena among-delivered accuracy slightly degrades.
  • F4 is residual by construction — “none of F1–F3 fired” — with hand-set checker thresholds, no sensitivity analysis, and the proposed fix never demonstrated to succeed.
  • Measurement gaps. Placebo only on 9B; 2-rollout ablation cells; two cross-night comparisons; ~0.025 LLM converter bias in all absolute scores; no matched-budget search baseline; frontier API cells without controls.
  • Narrow generalization. Both deep lines are Qwen3.5; DeepPlanning is one domain with a programmatic scorer; the sub-8B models where the rule says “harness pays nothing” are exactly the least-tested.

Questions for further exploration

  • Does surfacing the scorer’s per-check failure composition to the proposer ever restart harness gains past F4 — and on which model classes?
  • Is the stack-vs-substitute switching point predictable from seed failure composition alone, or does it need a probe adapter first?
  • Can “what the model sees” gains ever be internalized into weights — e.g., training on state-representation transformations rather than assistant outputs?
  • Would a matched-budget test-time-search baseline beat 13 rounds × 4 rollouts of harness search on DeepPlanning?
  • How sensitive are F1–F4 labels to the checker thresholds — and can the taxonomy work without a deterministic scorer?
