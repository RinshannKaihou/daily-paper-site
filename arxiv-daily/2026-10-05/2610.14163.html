Turning RL environment design into a terminal task lets the agent build its own curriculum — and improve itself on it.

AutoEnvScaling: Automating the Data Flywheel with Terminal Agents

Simon Yu · Baolin Peng · Bo Liu · Zhengyuan Shi, et al.  ·  Microsoft Research  ·  2026-10-05

terminal-agents environment-generation reinforcement-learning self-improvement data-flywheel

Key metric

39%→86%

mean valid-environment rate across 8 frontier proposers vs prompt-only generation. Weakest model gains most: DeepSeek-V4-Flash 3.5% → 89% (~25×); cost per valid env drops for 6 of 8.

Why this matters

Training-environment supply is the bottleneck of agent RL. This hands environment building to the agent itself — a working recipe for self-improvement loops.

Critical edge

Validation is self-referential: the same model that wrote the task reviews whether it is sound, so self-consistent errors can pass every gate.

Methodology distilled

assignment: parent env + pass rate + top failure→ build Harbor env in sandbox→ validate→ calibrate 0.25–0.75→ DPPO co-train→ new rollouts ↻ next round
  • Proposer in a sandbox: reads the solver’s past rollouts + verifier outputs, prior environments, persistent memory/tools, restricted web access. Builds simpler variants where the solver keeps failing, harder ones (longer horizon, extra skills) where it succeeds.
  • End-to-end build: writes the full Harbor environment (instruction, execution image, reference solution, tests), launches child containers, iterates until the oracle check passes.
  • Admission gate: reference solution gets full reward, empty solution fails, 13-gram contamination check, plus a harbor_check rubric run; then calibration — mean reward on the current solver must land in 0.25–0.75.
  • Rewards: solver = fraction of tests passed; proposer = −1 validation fail / −0.25 calibration fail / +1 both pass. Open-weight policies play both roles, trained with DPPO (group 16, 128k tokens).
  • Cold start: the base model alone yields valid envs only 32.3% of the time, so RSI begins from 600 curated frontier proposer trajectories (→ 86.8%). Proposers also do harness optimization (merged validation scripts, cached images as skills).

  • Recursive self-improvement: one Qwen3.6-35B-A3B as both proposer and solver climbs 41.1 → 53.3 on Terminal-Bench 2.1 over ~300 RL steps — +12.2 vs its cold start, but +6.1 vs the matched static Tmax (47.7). Terminal-Bench 4.0: 1.6 → 3.2 (Tmax stays 1.4).
  • Solver feedback is load-bearing: removing past rollouts from the proposer’s workspace costs −3.6 (GPT-5.6-sol) / −6.7 (Opus 5) on 35B-A3B; dropping proposer training entirely eventually collapses the loop.
  • Envs are richer and harder: 20.4 data files vs 3.5 (5.8×), 47.2 vs 33.8 solver turns, pass rate 61.0% → 51.0% — though “harder” is partly by construction of the calibration band.
  • Help-seeking (HiL-Bench): trained on 500 generated SWE tasks: 33.9% success / 55.3 Ask-F1, vs Claude Opus 5 at 7.5% / 14.4 in the same setting.
  • Cross-domain feasibility: 1,061 / 1,489 generation runs accepted (71.3%) across 7 domains — admission-only, not a quality claim.

Caveats on the numbers: the +12.2 RSI headline is measured against the paper’s own cold-start checkpoint (matched-baseline gain is +6.1); the RSI run is a single run with no seed variance; cost per valid env rises for the two strongest proposers (e.g. Claude Opus 5 $0.72 → $1.18).

Strengths

  • Unifying design and solving as terminal tasks lets one policy improve both; the harness-optimization path works even for closed-weight frontier models.
  • Assignment-from-failures is a concrete, inspectable curriculum signal — and the ablation shows it is load-bearing.
  • Matched comparisons throughout: Tmax pools regenerated with identical proposers, CIs on main tables, same cold-start for RSI.
  • Honest failure analysis: the no-proposer-training collapse is reported as evidence, limitations stated candidly (Appendix A.1).
  • Breadth: 8 proposers, 2 solver scales, 7 domains, plus a qualitative protocol study.

Limitations

  • No independent verifier: the fallback reviewer is the proposer’s own model; no post-admission measurement of environment error rates.
  • RL gains shown only for the terminal domain plus one HiL-Bench behavior study; cross-domain results are admission-only.
  • RSI is one run of one model at ~300 steps, no seed replication; Terminal-Bench 4.0 stays near floor.
  • Heavy frontier bootstrap: 600 curated trajectories for cold start; cost per valid env rises for the strongest proposers.
  • Substantial compute (128k-token DPPO, group 16, repeated sandbox builds); pipeline is specific to the Harbor task format.

Questions for further exploration

  1. How would an independent verifier (different model family, held-out human review) score the accepted environments — how many are wrong or reward-hackable?
  2. Does the RSI loop survive multiple seeds and horizons beyond ~300 steps, or does Terminal-Bench 4.0 plateau near the floor?
  3. Can the loop start without the 600-trajectory frontier cold start — e.g. self-play from the raw 32.3%-valid-rate base model?
  4. Does solver-relative calibration drift the pool toward the solver’s frontier while starving long-horizon diversity?
  5. For closed-weight proposers, how much of the gain is harness optimization (scripts, cached images, memory) versus the terminal sandbox itself?
