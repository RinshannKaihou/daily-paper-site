> **一句话总结：** 华为团队量化发现相邻 query 的稀疏 Top-K KV 集合高度重叠（2-query 分组下 Qasper/GovReport 全层重叠率超过 85.91%/78.06%），提出按组共享执行的 QUILT：用 Shift-and-Compare Set Decomposition（SCSD）把不规则集合求交拆解为移位+比较+布尔掩码的数据并行原语、与 attention 矩阵计算流水线化重叠、再经级联共享和 tile 感知重要性裁剪对齐硬件 tile——在 16 卡 Ascend 910C 上对 GLM-5.3/DeepSeek-3.2 稀疏 prefill kernel 平均延迟降低 53.8%（TP）/43.4%（SP），处理 KV 量减少 54.7%/30.4%，TTFT 最高降 36.8%，21 个 LongBench 任务平均精度变化仅 0.42/0.75 分。

> **TL;DR:** Existing query-parallel sparse-attention kernels load and dequantize the same KV entries once per query, missing that neighboring queries' Top-K sets overlap heavily (e.g., >85.91% on Qasper at group size 2). QUILT groups neighboring queries and jointly executes their correlated sparse workloads on Ascend 910C NPUs, built on Shift-and-Compare Set Decomposition (SCSD — set intersection/difference recast as shifts, compares, and Boolean masks on vector units), pipelined with QK/PV attention, plus cascaded multi-granularity sharing and tile-aware importance clipping. On LongBench (Qasper, GovReport, Musique, NarrativeQA) with GLM-5.3 and DeepSeek-3.2, QUILT cuts average sparse-kernel latency by 53.8% (TP) / 43.4% (SP) for GLM-5.3 and 28.7% / 17.1% for DeepSeek-3.2 versus the optimized OPS-Transformer kernel in XYServe, processes 54.7% / 30.4% fewer KV entries, and reduces TTFT by up to 36.8% (GLM-5.3, TP), with mean accuracy within 0.42/0.75 points of the exact baseline across 21 LongBench datasets.

## 核心贡献

- **量化跨 query KV 复用机会：** 在 GLM-5.3 上系统剖析 LongBench 各数据集/层/分组大小的 Top-K 重叠率——2-query 分组时 Qasper、GovReport 全层平均重叠率分别超过 85.91% 和 78.06%，首层超过 90.03%；并证明现有 workload-agnostic 的 query-parallel kernel 在 Ascend 910C 上把大量时间花在重复的 KV 加载与反量化上。
- **提出 QUILT 执行机制：** 将相邻 query 分组、按其稀疏 workload 的共享结构联合执行，KV 条目只在 HBM 加载和反量化一次后组内复用，对现有训练无关/模型原生稀疏化（GLM-5.3、DeepSeek-3.2 的 Top-2048 索引器）均透明适用。
- **SCSD 算法：** 把两个 Top-K 集合的求交/求差改写为"拼接+带源标签排序+双向移位比较+布尔掩码提取"的固定数据并行序列（D=C=C_r、F=C=C_l、共享集 C[D]=A∩B、私有集 ~[D∨F] 按源标签分离），消除标量循环与分支，映射到向量单元。
- **流水线化执行：** SCSD 主要消耗向量管线资源，与矩阵管线的 QK/PV 计算重叠（生产者-消费者预热 + 多级细分工），使集合分解的额外开销基本离开关键路径（naive 实现会比 baseline 慢 21.84×/33.65×，而完整设计平均反而快 35.5%）。
- **级联共享 + tile 感知执行：** 默认从 8-query 组开始逐级（8→4→2→1）提取各级共享条目，避免固定分组粒度次优（示例中处理 KV 从 16 降到 8，即 −50%）；对与原生 tile 尺寸不对齐的尾段按 50% 利用率阈值决定补齐或下沉，末端 query 私有条目按 indexer 重要性分数裁剪掉最不重要的尾部，消除低利用率 tile。
- **系统实测：** 在 16 卡 Ascend 910C（64GB HBM、CANN 9.10、XYServe 引擎）上完成 kernel 级与端到端 TTFT 评测、组件消融和数值保真度分析。

## Key Contributions

- Quantifies cross-query Top-K overlap in sparse-attention prefill: at group size 2, overall overlap exceeds 85.91% (Qasper) and 78.06% (GovReport) across all GLM-5.3 layers, exceeding 90.03% in the first layer, while profiling shows KV loading and dequantization dominate existing query-parallel kernels on Ascend 910C.
- Proposes QUILT, a workload-aware group-based query execution mechanism where shared KV entries are loaded from HBM and dequantized once per group; it operates on the resulting sparse workload and is agnostic to the upstream sparsifier (works with both GLM-5.3 and DeepSeek-3.2's trainable Top-2048 indexers).
- Introduces Shift-and-Compare Set Decomposition (SCSD), a data-parallel formulation of set intersection/difference — concatenate with source labels, sort, bidirectional shift-and-compare, extract via Boolean masks (shared = C[D] = A∩B; query-specific = ~[D∨F] split by source label) — that eliminates scalar loops and branch-heavy membership checks and maps onto vector execution units.
- Pipelines SCSD on the vector pipeline concurrently with matrix-pipeline QK/PV attention (producer-consumer warm-up plus multi-stage splitting), hiding set-decomposition overhead that a naive implementation would expose (naive Torch set-intersection is 21.84×/33.65× slower on GLM-5.3 TP/SP, whereas the full design is 35.5% faster than baseline on average).
- Adds cascaded sharing (hierarchical 8→4→2→1 decomposition so each KV entry is processed at the largest granularity at which it can be shared; running example: 16 → 8 processed KVs) and tile-aware execution with importance-aware clipping (50% tile-utilization threshold; least-important indexer-scored residual entries pruned at the final level) to align sharing granularity with native attention tile sizes.
- Validates end-to-end on 16 Ascend 910C NPUs under tensor and sequence parallelism with kernel latency, TTFT, ablation, and output-fidelity studies.

## Methodology

**Motivation and profiling.** The authors profile GLM-5.3 (and DeepSeek-4.1) sparse-attention prefill kernels on an Ascend 910C NPU and show that KV loading and dequantization account for a large fraction of execution time under both tensor parallelism (TP) and sequence parallelism (SP), because query-parallel kernels treat each query's Top-K set independently. Measurement of Top-K overlap across neighboring queries on Qasper and GovReport (varying dataset, layer, and query-group size) confirms substantial, dataset- and granularity-dependent sharing: overlap decreases as group size grows but remains considerable across all layers.

**Group-based query execution.** QUILT groups neighboring queries and executes their correlated sparse workloads jointly. Three challenges are identified: (1) set-decomposition overhead, (2) heterogeneous sharing granularity, and (3) tile underutilization.

**SCSD.** For two Top-K lists A and B of N unique indices each, SCSD computes (C, T) = Sort(A|B), where T tracks the source list. Because duplicates are adjacent after sorting, it builds right- and left-shifted views C_r, C_l and computes D = (C = C_r) and F = (C = C_l); the intersection is C[D], and query-specific entries are G = ~(D ∨ F), separated by source label (A−E = C[G ∧ T=0], B−E = C[G ∧ T=1]). This is a fixed sequence of shifts, element-wise comparisons, Boolean ops, and masked selections — all data-parallel primitives that run on vector units without scalar traversal, explicit loops, or irregular membership checks.

**Pipelined execution.** Rather than running SCSD as a standalone pre-pass, QUILT interleaves it with attention: a small initial Top-K primes the pipeline; thereafter the matrix pipeline performs QK/PV on the current sparse segment while the vector pipeline simultaneously constructs the next shared/private segments. A complete set-decomposition is split into finer stages scheduled across attention pipeline slots to avoid scalar-side slack. Effective latency becomes the overlapped sum rather than T_SCD + T_Attn.

**Cascaded sharing.** Starting from a default group of 8 queries, QUILT extracts entries shared by all queries in the group, removes them from each query's Top-K set, recursively repartitions into smaller subgroups (4, 2, then 1), and processes query-specific residuals independently. Each KV entry is thus processed at the largest granularity over which it can be shared. In the 4-query/Top-4 running example, no sharing processes 16 KVs, fixed group 2 or 4 both process 10, and cascaded sharing processes 8 (50% reduction).

**Tile-aware execution and importance-aware clipping.** Shared and query-specific segments rarely match the native attention tile size T. For a segment of size |S| = qT + r, if the remainder r ≥ r_th (50% threshold) the tail is padded to a full tile (with masking); otherwise the tail is pushed down to the next cascade level to be merged with finer-grained workloads — an exact transformation trading a small amount of sharing for tile utilization. At the final query-specific level, residual entries concentrate near the tail of the original Top-K ranking (already likely captured by shared segments), so QUILT prunes the r_s least-important entries by indexer score, eliminating the final underutilized tile. Fidelity is measured by cosine similarity of attention outputs against unclipped execution, comparing importance-aware versus random clipping.

**Evaluation setup.** 16 Ascend 910C NPUs (64 GB HBM each, 784 GB/s bidirectional D2D, CANN 9.10) running the XYServe serving engine; models GLM-5.3 and DeepSeek-3.2 (both select Top-2048 KV entries per query via trainable indexers); LongBench with four representative workloads (Qasper, GovReport, Musique, NarrativeQA) for latency and all 21 datasets for accuracy; baseline is the optimized OPS-Transformer sparse-attention kernel integrated into the same XYServe framework, so only the kernel differs.

## Results & Highlights

- **Kernel latency (LongBench, vs. OPS-Transformer):** For GLM-5.3 under TP, QUILT reduces average sparse-attention kernel latency by 53.2%, 55.1%, 54.5%, and 52.4% on Qasper, GovReport, Musique, and NarrativeQA respectively (average −53.8%); under SP the average reduction is 43.4% (44.6%/45.0%/43.3%/41.9%). For DeepSeek-3.2, reductions average 28.7% under TP (37.9%/29.6%/24.5%/22.8%) and 17.1% under SP — but only 1.0% on NarrativeQA under SP, the weakest workload/platform combination reported.
- **Processed KV entries (Table 3):** QUILT processes 54.7% fewer KV entries on average for GLM-5.3 (53.8%/55.9%/54.6%/54.3% across the four workloads) and 30.4% fewer for DeepSeek-3.2 (39.6% on Qasper down to 24.8% on NarrativeQA) versus the baseline kernel, directly reflecting the exploited cross-query sharing.
- **End-to-end TTFT (XYServe):** For GLM-5.3, TTFT reductions under TP are 34.6%/36.5%/36.8%/34.5% (average −35.6%); under SP they average only 10.4% (7.0%–11.9%). DeepSeek-3.2 averages ~23.0% under TP (30.2%/23.7%/20.0%/18.1%) but just 2.4%–4.3% under SP — kernel-level gains translate far less than proportionally to user-visible latency under SP.
- **Accuracy retention (Table 2, 21 LongBench datasets):** Mean absolute score difference vs. the exact sparse-attention baseline is 0.42 points for GLM-5.3 and 0.75 points for DeepSeek-3.2 (mean absolute percentage differences 2.01% and 0.90%); per-task swings exist in both directions (e.g., +1.14 on 2wikimqa and −1.45 on hotpotqa for DeepSeek-3.2).
- **SCSD/pipelining ablation (Figure 12):** A naive Torch-based set-intersection is 21.84× (TP) and 33.65× (SP) slower than the GLM-5.3 baseline; vectorized SCSD alone brings latency to 96.1%/97.3% of baseline, and pipelined execution further cuts it by 45.0%/36.9%; for DeepSeek-3.2 (22.18×/27.53× naive) the full design averages −35.5% vs. baseline across both models and parallel modes.
- **Cascaded sharing vs. fixed groups (Table 4, GLM-5.3 processed KVs normalized to baseline):** group 2 = 65.7%, group 4 = 57.2%, group 8 = 50.0%, cascaded = 45.3%, i.e., 20.6%–30.8% fewer KVs than any fixed group size, translating into up to 29.6% (TP) additional kernel-latency improvement over fixed grouping.
- **Importance-aware clipping:** removing tail pruning costs 23.71% (TP) and 22.68% (SP) kernel latency for GLM-5.3 (24.44%/14.13% for DeepSeek-3.2); importance-aware clipping preserves attention outputs far better than random pruning of the same count (head-level mean cosine similarity 0.9999 vs. 0.9990; minimum 0.546 vs. 0.312; hidden-level minimum 0.719 vs. 0.664).
- **Motivating overlap statistics:** at group size 2, cross-query Top-K overlap exceeds 85.91% (Qasper) and 78.06% (GovReport) across all layers, exceeding 90.03% in the first layer; synthetic sharing-length sweeps show kernel latency drops by 42.74%/33.25% (GLM-5.3 TP/SP) as sharing length grows from 0 to 2048.

## Critical Assessment

- **Novelty:** The core observation — neighboring queries select overlapping KV entries — is simple and arguably folk knowledge among kernel engineers, but the paper is the first (to its credit) to quantify it systematically across datasets, layers, and group sizes and to build a complete execution strategy around it. SCSD itself is a clean contribution: recasting set operations as branch-free data-parallel primitives is the kind of trick that matters in practice, and the 21.84× slowdown of the naive implementation convincingly demonstrates it is not gratuitous.
- **Single-vendor, single-baseline evaluation:** All results are on Ascend 910C with CANN 9.10 inside Huawei's own XYServe engine, and the only baseline is OPS-Transformer integrated into that same stack. Despite the claim that "the proposed techniques can also be applied to GPUs where similar functionality is provided by Tensor Cores," no GPU/Tensor Core numbers are reported, and no external sparse-prefill system (e.g., FlashPrefill-class or other published sparse kernels) is compared. Absolute competitiveness outside Huawei's stack is therefore unverified.
- **The "negligible accuracy" claim bundles two approximations:** Table 2 compares QUILT (with importance-aware clipping enabled) against the OPS baseline kernel, not against an unclipped QUILT variant. The clipping's task-level effect is only characterized via cosine similarity of attention outputs (Figure 15), so a per-task accuracy decomposition of clipping versus sharing rearrangement is not reported. Per-task swings up to −1.45 (DeepSeek-3.2 hotpotqa) and the authors' own note that clipping is "the only approximate step" leave the tail risk unquantified.
- **End-to-end gains are much weaker under SP:** kernel-latency reductions of 43.4% (GLM-5.3 SP) shrink to 10.4% TTFT, and DeepSeek-3.2 SP TTFT improvements are only 2.4%–4.3% (NarrativeQA kernel latency: −1.0%). The abstract's "up to 36.8% TTFT" headline is the best case (TP), and the paper attributes SP's weaker gains to fixed pipeline warm-up overhead under shorter per-kernel sequences — an honest but practically important caveat for SP-heavy deployments.
- **Latency evaluated on only 4 of 21 datasets:** the four LongBench workloads (Qasper, GovReport, Musique, NarrativeQA) are shown to have high overlap, so the chosen latency workloads are favorable cases; overlap statistics (Figure 1) indicate sharing varies by dataset, and low-overlap workloads are not stress-tested for the break-even point where SCSD overhead exceeds sharing gains.
- **Reproducibility:** no code, kernel, or artifact release is mentioned; Ascend 910C + CANN 9.10 + XYServe is not publicly accessible, so independent replication is currently impractical. Fixed defaults (group size 8, tile threshold 50%) are stated but not tuned/justified via sensitivity studies.

## Strengths

- Well-motivated: the workload characterization (overlap ratios, NPU latency breakdown) directly justifies the design, and profiling evidence links the redundant KV loading/dequantization to real kernel time rather than speculation.
- SCSD is an elegant, general primitive — a fixed sequence of shifts/compares/masks with abundant data-level parallelism — and the naive-vs-vectorized-vs-pipelined ablation cleanly isolates why each layer of engineering is needed.
- The system thinking is strong: pipelining exploits the vector/matrix idle asymmetry of sparse attention; cascaded sharing removes the arbitrary commitment to one group size; tile-aware clipping connects logical KV savings to actual hardware tile utilization.
- Workload-agnostic positioning is convincing: QUILT operates on the Top-K workload produced by any sparsifier, demonstrated on two different model-native indexers (GLM-5.3 and DeepSeek-3.2's DSA/Lightning Indexer) without modifying them.
- Comprehensive ablations (SCSD, pipelining, cascaded sharing, clipping, sharing-length sweeps, numerical fidelity) with consistent numbers across models and parallel configurations.

## Limitations

- Evaluation is confined to one vendor platform (Ascend 910C/CANN/XYServe) with an in-house baseline; no GPU results and no third-party sparse-kernel comparisons, limiting external validity of the headline numbers.
- Kernel-level latency is reported for only four LongBench workloads; accuracy spans 21 datasets but latency and overlap generalize only by proxy.
- End-to-end TTFT benefit degrades sharply under sequence parallelism (average 10.4% for GLM-5.3, 2.4%–4.3% for DeepSeek-3.2), and NarrativeQA under DeepSeek-3.2 SP shows essentially no kernel gain (−1.0%), indicating the approach is sensitive to workload overlap and pipeline amortization.
- Importance-aware clipping is a lossy approximation whose task-level (as opposed to output-similarity) impact is not isolated; benefit–risk on tasks sensitive to dropped tail KV entries is unexplored.
- No sensitivity study on the group-size-8 default or the 50% tile threshold, and no analysis of how overlap behaves at Top-K values other than 2048 or at context lengths beyond those tested; no code release.

## Relevance

这篇工作属于"大规模 ML 的算子/内核基础设施"方向：它把稀疏 attention prefill 的执行策略从 query 独立改为跨 query 共享，在真实 NPU 生产栈上拿到了可观的 kernel 与 TTFT 收益，对做长上下文推理 kernel 优化的读者很有参考价值。与你"极端性能优化下的可靠性"关注点也相关——其收益有一部分来自 importance-aware clipping 这一有损近似，论文用注意力输出余弦相似度论证数值保真，但未在任务层面单独消融该近似的精度风险，是评估这类激进优化时值得追问的点。

## Questions for Further Exploration

- How does QUILT perform on GPU/Tensor Core architectures as claimed — does SCSD's shift/compare primitive mix map efficiently onto warp-level operations, and do the 53.8%/28.7% kernel gains hold on non-Ascend memory hierarchies?
- What is the task-level (not cosine-similarity) accuracy contribution of importance-aware clipping alone — i.e., an ablation of unclipped QUILT vs. clipped QUILT across all 21 LongBench datasets, especially on retrieval-heavy tasks like hotpotqa where a −1.45 swing already appears?
- How does the benefit breakdown look on workloads with intrinsically low cross-query overlap (e.g., code generation or highly heterogeneous contexts) — where is the break-even point at which SCSD overhead exceeds sharing gains, and does the pipeline warm-up cost dominate there?
- Can the SP warm-up amortization problem (TTFT gains collapsing from ~35.6% TP to ~10.4% SP for GLM-5.3) be removed by overlapping SCSD setup across sequence-parallel chunks, or is it structural to short per-kernel sequences?
- Does the cascaded-sharing hierarchy interact with the indexer's training — e.g., could models be trained to produce more shareable Top-K patterns across neighboring queries, turning QUILT's execution-side observation into a co-design opportunity?
