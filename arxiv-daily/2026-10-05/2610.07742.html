Why this matters

A compiler now auto-generates kernels at FlashAttention-grade quality and compiles once for all dynamic shapes — a practical path for LLM serving kernel layers.

自动生成媲美手写内核的 GPU 算子，一次编译覆盖全部动态 shape，对推理 serving 的内核层有直接参考价值。

Critical edge

Equivalence of discovered rewrites rests on probabilistic random-input testing — no formal proof, no measured false-positive rate — so an unsound rewrite could reach production serving kernels.

01 · Methodology

CLEAVE splits kernel optimization along a natural seam: whether a graph rewrite is valid depends only on the graph — never on shapes or schedules — so the expensive search runs once over symbolic shapes, and a separate scheduler binds concrete shapes per candidate.

subgraph→symbolic shapes→algebraic search + Split(s)→probabilistic check→enumerate split s→itGraph tiling + fusion→TileLang codegen→profile top-k

  1. 1Symbolic algebraic search Every tensor dimension becomes a symbol; an extended Mirage-style superoptimizer enumerates equivalent graphs with a new Split(A, dim, s) operator whose split count s stays symbolic — deciding where to split (Split-K), not how much. “Eventually-reduced” pruning only allows splitting dimensions that feed a reduction.
  2. 2Cheap equivalence checks Random-input testing runs on tiny instantiated tensors, decoupling check cost from real shapes — reaching head_dim=128 MHA where concrete-shape search (Mirage) fails.
  3. 3itGraph scheduling Output tiles partition across threadblocks; reductions tile into explicit iteration loops keeping one tile of each intermediate live (SMEM from [b_O, N] to [b_O, b_R]); reductions sharing an upstream producer — Rowsum and the V-Matmul over one Exp tile — are horizontally fused into a single loop.
  4. 4Planning, codegen, profiling RMEM/SMEM placement with swizzled layouts and hoisted loop-invariants; TileLang lowers each itGraph level. For dynamic ops, loop bounds are re-emitted symbolically — one cubin serves all shapes; an analytical cost model picks top-k candidates to profile.

03 · Strengths

  • Simple, well-motivated decoupling that demonstrably tames the search space that makes Mirage OOM or time out.
  • Symbolic-shape equivalence testing elegantly lifts superoptimization’s scaling wall — reaching head_dim=128 attention graphs that concrete-shape search cannot.
  • The scheduler automatically reproduces expert kernel structure (FlashAttention-style fusion); the itGraph/tmap formalism is precise enough to reimplement.
  • One compile serves all 303 real captured shapes from FlashInfer-Bench — validated on production-traced workloads, not synthetic ones.
  • Layered evaluation (subgraph, end-to-end, dynamic, compile time, ablation, cross-compiler grafting) with unusually candid negative results.

04 · Limitations

  • NVIDIA-only evaluation (A100/H200) with a single TileLang backend; other DSL backends are only “planned.”
  • Correctness rests on probabilistic testing — no formal verification fallback and no soundness measurement.
  • “Eventually-reduced” dimension annotation is manual, so applying CLEAVE to a new operator needs expert input.
  • Coverage limited to 9 transformer-style subgraphs and attention operators — no convolution, MoE routing, or quantized kernels.
  • Compile cost grows with top-k profiling; the SMEM-only cost-model assumption may misrank memory-heavy kernels.
  • Gains shrink to ~1.43× at Qwen3-32B scale, and MLA-class decode still trails FA3’s hand-tuned cooperative kernel.

05 · Questions for further exploration

  1. Can “eventually-reduced” annotation be fully automated via data-dependency analysis — and would automation ever mislabel dimensions into unsound or missed rewrites?
  2. Could probabilistic equivalence testing be replaced or augmented with SMT / e-graph formal certificates, and at what search-time cost, given symbolic shapes already shrink test inputs?
  3. How does the pipeline transfer to non-NVIDIA targets or Triton / CUTLASS DSL backends, given Tensor Core layout propagation is currently hand-derived per backend?
  4. Can the Split operator generalize beyond reduction-dimension parallelism — e.g. to quantized / mixed-precision kernels where split partial results change accumulation precision?
  5. What minimal scheduling-interface contract lets a downstream compiler consume algebraically transformed graphs without losing its own fusion patterns (torch.compile’s failure mode)?
