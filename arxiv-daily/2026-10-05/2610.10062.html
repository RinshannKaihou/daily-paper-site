Why this matters

Agents wave through well-formatted but wrong tool results, and reasoning models self-check even less — so monitor return values, not just error strings.

Agent 只认报错字符串、对「格式完美、内容错误」的静默损坏过半放行；上线监控应盯工具返回值本身，而非只盯报错通道。

Critical edge

Detection is judge-coded from what agents wrote, with only moderate human agreement (binary κ = .69) — the “reasoning models notice less” result partly rests on reporting style, not perception.

from Critical Assessment

Methodology

fault fires once ≥ midpoint step → agent reacts → judge codes noticing → end state vs own clean run
  • Testbed. 24-task frozen subset of the BFCL multi-turn executable split (312 of 400 passed filters; 16 domain combos, median 5 user turns). Environment classes are driven directly — that is what lets a fault be placed at a chosen step.
  • Four typed faults, each firing exactly once at/after step ⌈T/2⌉: timeout, missing tool, schema drift (renamed parameter), silent corruption (same-typed wrong value, e.g. number shifted 20–60%). First three put an error string in front of the agent; corruption does not.
  • Design. 6 models in 3 matched reasoning/instruct pairs, native JSON function-calling, temperature 1.0, 15-call cap; 1,920 trials, 1,694 analysed (faults never fired in the rest).
  • Measures. Detection = judge-coded “treated as a problem” (κ = .69 vs author); replanning = first post-fault action differs; recovery = end state agrees with the model’s own clean run; repetition = 3+ strictly identical calls.
  • Stats. Task-clustered GEE + bootstrap over tasks; Holm-corrected paired tests within families.

  • Reasoning models act more, notice less. Paired within family, pooled: detection −9.3 pts (p < .001; all three families negative, Qwen −16.6), replanning +10.4 pts (p < .001), recovery −2.4 pts (n.s.) — extra deliberation changes behavior, not outcomes.
  • Only missing tool clearly hurts recovery: 39.9% (OR = 0.34, p < .001) vs 59.2–60.4% for the other faults — all within run-to-run noise, since two clean runs of the same model agree only 63.3% of the time.
  • Noticing ≠ recovering. Recovery 55.6% when the agent flagged the fault vs 55.7% when it did not (p = .974).
  • Effort, not loops. Strictly identical retries are rare (0.8–1.8%); plan rebuilds cost more (+1.47 to +1.85 calls) than retries (+0.55).
  • The intuitive fix fails. A “briefly check each result” system prompt moves detection +0.6 (instruct) / +2.5 (reasoning) — both n.s. on 480 trials.

Strengths

  • The right cut: noticing / replanning / recovery / repetition scored separately, with recovery measured against the model’s own clean run — removing the baseline-competence confound.
  • Measurement honesty: every effect is calibrated against the 63.3% two-clean-run agreement instead of assumed determinism.
  • Genuinely reproducible: self-test harness verifies injection invariants; environment never left half-changed; frozen suite, trajectories, data and scripts all released.
  • Real statistical footing: matched reasoning/instruct pairs, task-clustered GEEs, Holm correction.
  • Actionable framing: the faults agents catch are exactly the ones monitoring dashboards already catch.

Limitations

  • One benchmark family (BFCL, simulated environments); four chosen fault types — production failures (auth walls, partial outages, schema churn) may behave differently.
  • Selection by construction: two faults require calling the affected tool; 226 of 1,920 trials dropped — agents that steered around the break (the best outcome) are excluded.
  • Noisy recovery yardstick: judged against one clean run, yet clean-run agreement is 41.7% for three of six models; 27% of trials hit the 15-call cap.
  • Judge-coded detection from agent text (binary κ = .69); no behavioral signals used.
  • Narrow null result: the prompt arm covers one family on two models; DeepSeek-R1’s tool-call formatting artifact partly contaminates its action-rate contrasts.

Questions for Further Exploration

  1. Would typed result validators (range/type checks outside the model) close the quiet-failure gap without relying on the agent’s judgment?
  2. Does PALADIN-style fine-tuning on fault traces teach content checking — or just error-string matching that reproduces the loud/quiet asymmetry?
  3. Is the reasoning models’ detection deficit an attention-allocation issue or a reporting-style artifact? Coding from behavioral signals (state re-reads, revisits) would settle it.
  4. How does the noticing–recovery dissociation behave under cascading or repeated faults, where the 15-call budget binds harder?
  5. Would recovery measured against a distribution of clean reference runs overturn the “no recovery gain” conclusion for the 41.7%-agreement models?
