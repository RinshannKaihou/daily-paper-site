# CurveTQ: Rotation-Free Trellis Quantization of LLM Weights via Curvature-Weighted Search

> **一句话总结：** 提出 CurveTQ，把 Hessian 的 LDL 对角元直接放进 Viterbi 分支度量（曲率加权搜索），证明"曲率加权"与 QTIP/Proteus 的随机旋转在理论上互为替代品，从而完全去掉推理时必须撤销的旋转；在 Llama-3.1-8B-Instruct 等 4–8B 模型 2 比特下，平均下游准确率比 QTIP 和 Proteus 高 1–3 点（即使给基线配上它们自己的 start state），并首次给出 35B MoE（Qwen3.5-35B-A3B）上的 trellis 编码结果，解码吞吐在所有测试 batch size 下都是三者最快。

> **TL;DR:** State-of-the-art 2-bit trellis quantizers (QTIP, Proteus) rotate each weight matrix with a random orthogonal transform that must be undone at every decode step. CurveTQ shows this rotation is unnecessary: placing the Hessian's LDL diagonal as the weight in the Viterbi branch metric exploits exactly the within-block variation the rotation removes (proved via a high-resolution relaxation, Proposition 1). With a 14-bit stored start state per 64-column block, a factored int8 scale field, and a 128-entry closed-form quantile table, CurveTQ at 2.29 bpw beats both QTIP and Proteus at 2.00 bpw on WikiText-2 perplexity across all four Instruct models (e.g., 11.50 vs 15.46 for QTIP on Llama-3-8B), leads mean downstream accuracy by +2.5 to +5.2 points on the three 4–8B Instruct models, wins by +0.6 to +2.8 points on the Qwen3.5-35B-A3B MoE, and its rotation-free CUDA decoder is 1.05–1.09× QTIP and 1.12–1.30× Proteus at batch 1 on an RTX 3090.

## 核心贡献

- **理论：旋转与曲率加权互为替代。** 在误差反馈框架下，逐坐标加权搜索的损失上界由 Hessian LDL 对角元的几何平均决定（Proposition 1），而随机旋转恰好抹平了块内对角元的锯齿变化——旋转去掉的正是加权所利用的。因此在高分辨率近似下，加权原生基搜索 ≈ 旋转后欧氏搜索（SUB 对比：+1.10±0.63 / +0.39±0.66 / +0.07±0.84）。
- **方法：无旋转 trellis 编解码。** CurveTQ = LDL 加权 Viterbi 搜索 + 每 64 列块存 14-bit 起始状态（0.22 bpw）+ 行×列两级因式分解的 int8 scale 域（Qwen3-4B 上 0.068 bpw）+ 由校准集闭式推导的 128 项 int8 等概率量化表（Mealy 形式边发射，2^14 幸存路径 vs QTIP 的 2^16）。构建对给定校准集完全确定性。
- **实验：** 6 个公开 checkpoint（Llama-2-7B、Llama-3-8B、Llama-3.1-8B-Instruct、Qwen3-VL-4B、两个 ~32B-Instruct、Qwen3.5-35B-A3B MoE）。2 比特下游平均领先 QTIP/Proteus 1–3 点（基线补上 start state 后仍领先 0.9–3.1 点）；35B MoE 上为业界首个 trellis 编码结果且胜出。
- **系统：** 无旋转意味着解码端无需撤销变换，融合 dequantize+GEMM 的 CUDA kernel 在 RTX 3090 上所有 batch size、所有比特宽度下都快于两个基线。
- **诊断性发现：** 给 QTIP/Proteus 补一个块级 start state 本身就值 +1.0~+3.3 点下游准确率——此前它们用 tail-biting 终止，块首继承了错误的残差约束，这是它们与 CurveTQ 差距的最大单一来源。

## Key Contributions

- **Theory — weight and rotation are substitutes:** Under block error feedback the loss is a weighted sum of per-coordinate rounding errors with the LDL diagonal as weights (Eq. 1). Proposition 1 bounds the Euclidean search's excess loss by the block-local anisotropy Γ(H); a rotation flattens exactly this quantity. Empirically the rotated Euclidean search and the weighted native search agree within about one point (SUB contrasts in Table 3).
- **Codec — CurveTQ:** LDL-weighted Viterbi search over QTIP's bitshift trellis (G=64 columns), a block-local trellis with an explicit 14-bit stored start state (0.22 bpw, the largest single rate component they add), a two-way factored int8 scale field (~0.067–0.068 bpw), and a deterministic 128-entry equiprobable quantile table emitted Mealy-form (2^14 survivors vs QTIP's 2^16; an exact Viterbi run confirms identical costs/reconstructions).
- **A fair-rate upgrade for the baselines:** Equipping QTIP and Proteus with their own stored start state lifts them +1.0 to +3.3 downstream points — the paper reports CurveTQ's lead against these *strengthened* baselines, not just the published versions.
- **First trellis-coded result on a mixture-of-experts model** (Qwen3.5-35B-A3B, 256 experts, top-8 routing), where per-expert Hessians are estimated from a few thousand routed tokens.
- **Fastest decoder of the three codecs at every tested batch size and bit width**, since there is no transform to undo at inference.

## Methodology

**Error feedback as the foundation.** Weight-only PTQ minimizes the damped Hessian loss Σ e_c^T H e_c. With a coding order and LDL^T factorization of H, column-by-column error feedback turns the loss into Σ D_i η_i² (Eq. 1), where D_i is the LDL diagonal and η_i the feedback-corrected rounding residual. QTIP computes these D_i in its feedback step but never reads them inside the block's search; CurveTQ's first move is to place 1/d_i² as the Viterbi branch-metric weight (the ideal weight is the inverse Cholesky factor H^{-1}; the diagonal is the additive, feedback-compatible approximation).

**The code.** Rows are coded in blocks of G=64 columns. Each block runs a Viterbi search over QTIP's bitshift trellis (L-bit state, k-bit code per weight, 2^L survivors), minimizing Σ ω_i [z̃_i − T(k_i(P))]². Three explicitly modeled factors of the objective: (1) amplitude — the absmax scale of each 64-group; (2) marginal shape — a closed-form 128-entry equiprobable quantile table indexed by a 7-bit hash, derived deterministically from the calibration set (matches an EM fit within twice the seed noise); (3) curvature — the LDL diagonal weight.

**Block-local trellis with stored start state.** Instead of QTIP's tail-biting (which ties each block's first ⌈L/k⌉ coordinates to its last ones — the wrong constraint when the block's first columns carry the inherited residual), CurveTQ lets each block start in any trellis state and stores the chosen 14-bit boundary state (0.22 bpw). The decoder loads it, nothing else changes.

**Emission.** A Mealy-form emission from the *edge* of the 14-bit state: an exact Viterbi run confirms identical costs and reconstructions to QTIP's node-emitting form while quartering the survivors. A table-free variant (computed emission, like QTIP's 1MAD) isolates the table's role in ablations.

**Factored scale field.** Rather than second-level quantization that flattens the scale field (flat over rows and columns), CurveTQ factorizes s_bg = μ + σ_r + β_g + ε_bg: row and column-group factors stored as fp16 geometric means plus a 4-bit linear grid (255-step absmax), with all builds rounded to guarantee stored ≥ actual scale. Costs 0.068 bpw on Qwen3-4B, 0.067 on Llama-3 (vs 0.125 for int8 second-level or 0.25 for fp16 per-group).

**MoE extension.** Each expert e gets its own Hessian H^(e) over the tokens the router sends it. Under top-8-of-256 routing this is a few thousand tokens for a 2048-dim input, so the LDL diagonal is damping-dominated and the weight is nearly inert — the codec applies unchanged.

**Evaluation protocol.** Six checkpoints; 128 calibration segments of 2048 tokens from C4; L=16 trellis; lm-eval-harness at context 4096, mean accuracy over a fixed suite (4–34 tasks per model; 30 for MoE); paired differences with 95% bootstrap CIs; *no post-quantization fine-tuning anywhere*, to isolate the code; all rates include every piece of side information.

## Results & Highlights

- **2-bit perplexity (WikiText-2), all four Instruct models:** CurveTQ at 2.29 bpw has lower perplexity than QTIP at 2.00 bpw and Proteus at 2.00 bpw on every model — e.g., Llama-3-8B 11.50 vs 15.46 (QTIP) and 14.21 (Proteus); Llama-2-7B 6.44 vs 6.86/6.73; Qwen3-32B 9.16 vs 10.31/7.21. Its QTIP reproduction is within 0.05 perplexity of QTIP's published number. GPTQ collapses (105.95 on Llama-3-8B at 2.25 bpw) and HIGGS trails (21.23).
- **2-bit downstream accuracy:** leads by +2.5 to +5.2 points on the three 4–8B Instruct models (e.g., Llama-3-8B 58.6 vs 48.8 QTIP / 48.8 Proteus) and by +0.5 to +1.3 on Qwen3-32B (66.3 vs 65.4/65.0). Against the strengthened baselines with their own start state, the lead is +0.9 to +3.1 points, five of six contrasts excluding zero, concentrated on generative tasks (GSM8K, IFEval).
- **Attribution of the lead:** the stored start state alone is worth +1.0 to +3.3 points to the baselines — "the dominant contrast surviving" — while the group scale adds only ~0.4 to +2.7 points and the scale adds little over the start state alone (Appendix D).
- **3 bits:** at 3.29 bpw CurveTQ leads the 3.00-bpw rows downstream on every model; once baselines carry the start state (3.16–3.20 bpw), CurveTQ is ahead or level in twelve of sixteen model-metric-baseline comparisons, all paired contrasts within ±0.7 points. At four bits all trellis codecs are within 0.35 perplexity and one point downstream.
- **MoE (Qwen3.5-35B-A3B, 30 tasks):** at exact element-weighted 2.29 bpw, CurveTQ beats Proteus at 2.00 bpw by +2.1/+1.4/+3.0 (ppl and paired accuracy contrasts) and +2.5/+1.9/+3.3; at equal side information it is still ahead by +0.6/+1.1/+1.5 over QTIP+start and +1.5/+0.5/+2.8 over Proteus+start, winning 18 and 21 of 30 tasks. The 64-group scale gains the baselines nothing downstream; the start state is worth +0.6 to +2.0.
- **Rotation × metric 2×2 design (2.29 bpw, 4-dim slices, n=4):** native-basis weighting gains +2.44±0.57 (Qwen3-4B) and +4.29±1.04 (Llama-2-7B) points; after rotation the same weighting's gain collapses to +0.36/+0.08/−0.13 — substitution confirmed. The rotated Euclidean search beats the native weighted search by +1.10±0.63 (Qwen3-4B), +0.39±0.66 (Llama-2-7B), +0.07±0.84 (Llama-3-8B). On Llama-3-8B the native Euclidean search collapses entirely ("-").
- **End-to-end recipe ablation (Qwen3-4B, 2 bits):** the build-up from a bare 128-entry EM-fit table saves 0.18 bpw, 1.82 perplexity, and 1.4 [+0.5,+2.4] downstream points; the edge-indexed emission is the largest single step (−1.27 perplexity at equal bits, ~one downstream point). Removing error feedback costs 0.34 perplexity and −2.5 [−4.3,−1.4] downstream points; replacing the 1/d_i² metric with Euclidean one costs −3.3 [−4.5,−2.3] downstream points while *lowering* WikiText-2 perplexity by 0.24. Chained/tail-biting terminations (no stored state) lose 4.10 and 4.2–2.22-ppl-equivalent downstream points.
- **Decode throughput (RTX 3090, batch 1):** CurveTQ 139.0 tokens/s vs QTIP 127.0 and Proteus 105.9 on Llama-2-7B at 2 bits (1.05–1.09× QTIP, 1.12–1.30× Proteus); still ahead by 1–13% at batch 64/128. The rotation costs QTIP 5–9 tokens/s on Llama-2-7B and 13–17 on Qwen3-4B (4–11%). Removing the stored start state gains only 1–3 tokens/s (1–3%).

## Authors & Credibility

The four authors (Guanhua Ding, Zi Wang — equal contribution, Ruichao Li, Jack Liu) are at Black Sesame Technologies, a Chinese automotive-grade SoC/chip vendor; running in-house quantization research for on-device inference is a natural fit, and the systems work (a fused CUDA dequantize-GEMM kernel benchmarked on an RTX 3090 in QTIP's own setting) reflects genuine deployment motivation. The paper's scholarship is unusually careful for an industry note: it re-derives the loss identity used by GPTQ/QuIP#, cites the classical trellis/lattice literature (Fisher & Wang 1992, Zador 1982, Huang & Schultheiss 1963), reproduces QTIP within 0.05 perplexity of its published number, and uses paired differences with 95% CIs plus a fixed harness and calibration across all methods. Weaknesses: no released code is mentioned anywhere in the main text, and the author list has no academic collaborations to signal external vetting.

## Critical Assessment

**Novelty.** The individual ingredients are all known — the LDL diagonal is GPTQ's error-normalization constant, weighted trellis search is classical (Fisher & Wang), block start states appear in communications coding, and factored scale fields descend from QLoRA/SpQR. The paper is candid about this ("the loss identity... and weighted trellis search are both known; what is new is that together they make the rotation unnecessary"). The genuinely new claims are the substitution thesis (Proposition 1 + the 2×2 test) and the start-state finding that reframes where QTIP/Proteus actually lose accuracy. That is a solid conceptual contribution, though it is an *analysis-led* rather than architecture-led advance.

**Rigor.** Mostly high: equal calibration, one harness, paired CIs, rates that count all side information, no fine-tuning on either side, and honest reporting of places where perplexity and downstream accuracy disagree (the Euclidean-metric swap *improves* WikiText-2 perplexity by 0.24 yet loses 3.3 downstream points — they report both and refuse to pick a winner). Two caveats: (1) the substitution test — the paper's central hypothesis — is run on only three models at a single rate (2.29 bpw) with n=4 calibration slices, and on Qwen3-4B the *rotated* Euclidean search is actually ahead on 25 of 34 tasks by 1.1 points on average (SUB = +1.10), which is at the edge of what "within about a point" tolerates; (2) Llama-3-8B's native Euclidean search collapses, so one cell of the 2×2 is missing exactly where a substitution claim would be most tested.

**Reproducibility.** The build is deterministic given the calibration set and the quantile table is closed-form, which helps. But no code release is stated, the kernel is compared only on their hardware (one RTX 3090), and the MoE experiments depend on their own expert-Hessian estimates over router-routed tokens — details that live in appendices rather than a runnable artifact.

**Significance & red flags.** If the substitution thesis holds broadly, the whole "rotate-then-code" lineage (QuIP#, QTIP, Proteus, and transform-in-activation-path successors like SpinQuant-style pipelines) is doing work a branch-metric weight could do for free — that is a significant reframing for 2-bit PTQ. Red flags worth noting: gains shrink on the largest dense model (Qwen3-32B: +0.5 to +1.3 only); downstream gains concentrate on generative tasks while multiple-choice tasks barely move; on MoE the curvature weight is admitted to be "nearly inert" (damping-dominated expert diagonals), so the headline MoE win comes mostly from the start state + scale machinery, not the paper's namesake idea; and the headline comparisons put CurveTQ at 2.29 bpw against baselines at 2.00 bpw — the equal-side-information rows exist and still favor CurveTQ, but the abstract's "1–3 points" is not at equal rate.

## Strengths

- A crisp, testable theoretical claim (rotation ≡ weighting within the high-resolution relaxation) backed by a targeted 2×2 experiment, not just end-to-end scores.
- Exceptional fairness engineering: strengthened baselines (QTIP+start, Proteus+start, +g64), paired differences with 95% CIs, all rates accounting for side information, and zero fine-tuning on any method.
- The start-state discovery is independently valuable: it explains a large share of the 2-bit accuracy gap among trellis codecs and is transferable to QTIP/Proteus at a stated 0.22 bpw.
- Thorough component ablation (Table 4 builds the codec up one piece at a time and takes it apart), including negative and non-monotone results reported verbatim.
- Practical payoff: fastest decoder at every tested batch size/bit width, deterministic builds, and the first trellis-coded MoE result.

## Limitations

- The substitution test spans three models, one rate, and n=4 slices; one native-Euclidean cell collapses on Llama-3-8B, and on Qwen3-4B the rotated search is ahead on 25/34 tasks — the "within a point" equivalence is fragile exactly where it matters.
- Downstream lead shrinks with scale: +0.5 to +1.3 on Qwen3-32B vs +2.5 to +5.2 on the 4–8B Instruct models; no 70B-class dense model is tested.
- Gains concentrate on generative tasks (GSM8K, IFEval); multiple-choice suites move far less, so mean accuracy overstates the breadth of the improvement.
- On MoE the curvature weight — the paper's titular idea — is nearly inert because expert Hessians are damping-dominated; the MoE win is carried by the start state and scale field.
- No code or kernel release mentioned; throughput claims rest on one GPU and their own kernel implementations for Proteus.
- No comparison against non-trellis extreme-compression lines (AQLM, additive quantization) at these rates beyond GPTQ/HIGGS rows — the paper explicitly restricts to trellis codes on decode-speed grounds.

## Relevance

这篇工作直接命中你对 LLM 极致低比特量化的兴趣：它用理论+实验证明当前 2-bit 最优配方中的随机旋转可以被 Hessian 加权搜索替代，并指出块级 start state 才是精度差距的主因，对任何在做 W2/W3 权重量化或端侧解码 kernel 的人都是必读的分析型论文。

## Questions for Further Exploration

- Does the substitution thesis survive at 70B+ scale and at sub-2-bit rates, where the high-resolution relaxation underlying Proposition 1 is least accurate?
- Can QTIP/Proteus absorb the stored-start-state fix alone and erase most of CurveTQ's lead, making the contribution primarily diagnostic rather than a codec win?
- On MoE, if expert Hessians are damping-dominated, is there a routing-aware weighting (e.g., token-count-corrected diagonals) that would reactivate the curvature term?
- The Euclidean-metric swap lowers WikiText-2 perplexity yet costs 3.3 downstream points — what upstream property makes perplexity and generation quality diverge under weighted search, and can it be predicted before deployment?
- Would a learned (rather than closed-form equiprobable) quantile table interact positively with the native-basis weighting, given that the table currently matches an EM fit only within twice the seed noise?
