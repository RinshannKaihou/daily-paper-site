> **一句话总结：** 提出 SAGE——一种基于轨迹的定位方法，把 LLM Agent 修复漏洞时"首次偏离任务安全意图"的起源追溯到具体轮次；在 95 个确认的静默失败中成功定位 93 个（97.89%），发现 76.84% 的漏洞继承自输入文件而非 Agent 引入，且在 19 个 Agent 自引入漏洞的案例中有 14 个（73.68%）的起源早于写入漏洞代码的那一轮——即问题出在规划与决策，而非编码本身。

> **TL;DR:** SAGE is a trace-based localization method that finds the earliest canonical turn where an LLM repair agent's recorded reasoning or artefact history first diverges from the task's security intent. It combines per-turn, quotation-anchored scoring on four security dimensions (by GPT-5.6 Sol as an external judge), reconstructed artefact histories, and a fixed decision rule. On 95 confirmed silent failures mined from 3,684 valid traces (6 agent frameworks × 6 base models on SecurityEval + CVEfixes), SAGE assigns an origin in 93/95 (97.89%): 53.68% are unaddressed security requirements and 38.95% inadequate defence choices, while only 5 cases coincide with the code-writing step. Repeatability is stronger for origin type (96.49% across repeated runs, Krippendorff's α = 0.96) than for the exact turn (87.72%, α = 0.82), and SAGE's agreement with human annotators on code provenance (88.33%, κ = 0.74) comes within ~1.7 points of the annotator-annotator ceiling (90.00%, κ = 0.78) — evidence that final-patch and diff-based analyses miss where the repair process actually went wrong.

## 核心贡献

- **提出"静默失败起源定位"问题并给出 SAGE 方法：** 区分"引入漏洞的写入（introducing write）"与"最早可归因于轨迹的安全意图偏离（origin turn）"，用逐轮安全推理评分 + 重建的工件历史 + 显式决策规则，在单条通过功能验证的轨迹内定位起源（不需要标签失败步或多轨迹对比）。
- **多源可靠性评测协议：** 通过重复评分（3 次）、跨裁判对比（Claude Opus 5）、1,000 次任务不相交重采样、leave-one-task-out 以及人工标注（R1 全部 95 例、R2 60 例）分别评估判据相关输出与工件相关输出的稳定性。
- **定位边界的实证刻画：** 起源一致性随失败类别（防御缺失 vs 防御不足）、框架、基座模型与工件重建粒度而变化；只保留最终文件的轨迹在三类评测中一致性最低，说明中间工件快照对可审计性至关重要。

## Key Contributions

- A trace-based localization method (SAGE) that formulates silent-failure localization as identifying the earliest trace-attributable divergence from the task's security intent, using quotation-anchored four-dimension reasoning scores, reconstructed artefact histories, and an explicit decision rule.
- A multi-source reliability evaluation: repeated scoring, cross-judge comparison, task-disjoint resampling, and human annotation, deliberately separating judge-dependent outputs (origin type/turn) from artefact-derived outputs (provenance, introducing write).
- A characterization of localization boundary conditions: reliability varies with the confirmed deficiency type, agent framework, base model, and artefact granularity, with final-only traces consistently the least localizable.

## Methodology

**Phase I — Silent-failure dataset.** From 1,236 eligible security-repair tasks (121 SecurityEval, 1,115 CVEfixes), 150 tasks are sampled with a fixed seed, stratified by CWE. Six open-source frameworks (CAMEL, AG2, Deep Agents, Aider, MiniSWE-Agent, OpenHands) × six base models (GPT-5.5, Claude Opus 4.8, Gemini 3.1 Pro, DeepSeek-V4-Pro, Kimi K3, Qwen3.8-Max) = 36 configurations × 150 tasks = 5,400 runs (temperature 1.0, 600 s timeout, isolated 5-core/16 GB environments). 3,684 traces (68.22%) are valid. Patches pass multi-level verification: L0 syntax → L1 functional → L2 Bandit static security → L3 rule-based exploitability screening (score R ≥ 15), yielding 331 candidates; manual TP/Partial/FP confirmation (inter-rater Cohen's κ = 0.73, 90.00% agreement on a 60-case subset) leaves **95 confirmed silent failures** from 19 tasks (87 from 15 CVEfixes tasks; the largest, a server-side request forgery CVE, contributes 16 cases).

**Phase II — SAGE localization.** Traces are normalized into canonical turns (agent message + associated tool calls/results/artefact changes). A primary judge (GPT-5.6 Sol, outside the evaluated model set) scores each turn, seeing only the task context and the trace prefix up to that turn (anti-hindsight), on four dimensions — Threat Recognition, Defensive Intent, Verification Rigour, Scope Awareness — on a common 0–3 anchored scale; every non-zero score must cite a verbatim quotation. In parallel, per-write artefact snapshots establish code provenance (inherited vs agent-introduced) and the introducing write. A fixed decision rule then selects the origin as the earliest qualifying turn: (i) *inadequate defence selected*, (ii) *unaddressed requirement*, or (iii) *defect in the code change* (the introducing write, only when no turn qualifies under i/ii). Later implementation/review turns with Verification Rigour or Scope Awareness ≤ 1 are flagged as missed detection opportunities. Automated checks verify that fragment history, provenance, and origin-vs-write ordering are mutually consistent.

**Phase III — Evaluation.** Repeated scoring (3 runs on a stratified 60-case subset), cross-judge replication (Claude Opus 5, blind to all prior outputs), human annotation of provenance and introducing-write labels (R1 on all 95; R2 independently on 60), 1,000 task-disjoint random partitions plus leave-one-task-out resampling; metrics are percent agreement, Cohen's κ, and Krippendorff's α.

## Results & Highlights

- **Coverage:** SAGE assigns an origin in 93/95 confirmed silent failures (97.89%); only 2 cases (2.11%) remain Undetermined. Provenance: 73 (76.84%) inherited from the input file, 19 (20.00%) agent-introduced, 3 (3.16%) with no identifiable code location.
- **Origins are mostly decisions, not code:** Unaddressed requirement 51 (53.68%), inadequate defence selected 37 (38.95%), defect in the code change only 5 (5.26%). For the 73 inherited cases a diff shows no change at the vulnerable location, yet SAGE still assigns an origin in 72 of them from recorded reasoning — code-level analysis alone would explain none of these.
- **Timing:** Among the 19 agent-introduced cases, the origin turn precedes the introducing write in 14 (73.68%); the 5 coinciding cases are all single-message Aider traces. SAGE flagged at least one missed detection opportunity in 59/95 (62.11%) of cases (e.g., AG2 29/32, Deep Agents 13/13, MiniSWE-Agent 11/15, OpenHands 4/9, but 0/22 for Aider's single-message traces).
- **Repeatability vs precision (60-case subset):** Origin-type agreement is 96.49% (57/60) across three scoring runs and 92.00% across judges, versus exact-turn agreement of 87.72% and 78.00% respectively (Krippendorff's α: 0.96 vs 0.82 repeated; 0.86 vs 0.59 cross-judge). A one-turn tolerance raises agreement to 91.23% (repeated) and 84.00% (cross-judge); per-dimension score agreement drops to α = 0.68–0.76 between judges (lowest for Verification Rigour and Scope Awareness).
- **Human agreement:** SAGE vs annotator R1 on the 60-case subset reaches 88.33% (κ = 0.74) for provenance, near the R1–R2 human ceiling of 90.00% (κ = 0.78), and 85.00% (κ = 0.70) for the introducing-write label — above the human-human agreement of 75.00% (κ = 0.58) on that label. On all 95 cases, SAGE vs R1: provenance 84.21% (κ = 0.62), introducing write 81.05% (κ = 0.58). Task-disjoint medians are 84.21% (provenance) and 81.06% (introducing write), but central 95% intervals are wide (74.42–96.88% and 69.39–93.33%), showing sensitivity to task composition.
- **Boundary conditions:** Absent-defence cases agree with R1 at 93.75% (60/64) on both labels, versus only 61.54% (16/26) provenance and 53.85% (14/26) introducing-write for insufficient-defence cases. Final-only traces (no intermediate snapshots) show 57.14% (4/7) introducing-write agreement vs 86.36% (57/66) for single-write traces, and exact-turn agreement of 50.00%/25.00% vs 92.31%/90.91% for single-write traces under repeated scoring/cross-judge. By base model, Gemini 3.1 Pro traces agree most with humans (96.43% provenance), whereas GPT-5.5 traces get only 62.50% on both labels despite SAGE assigning the identical origin turn to all 10 consistently-localized GPT-5.5 cases — internal consistency can coexist with disagreement over code evidence.

The group built the precursor study this paper extends (Bai et al., "When Passing Tests Hides Vulnerabilities: An Empirical Study of Silent Failures in Agentic Systems," arXiv:2609.10548), so the corpus, verification levels, and failure definitions carry over from their own prior empirical work — a coherent, specialized research line in empirical software engineering and LLM-agent security. Waseem and Abrahamsson are established empirical-SE researchers; Peltonen bridges ML and human-centered computing. The paper is formatted for an ACM venue (FSE/ICSE style), and the dataset is released on Zenodo (10.5281/zenodo.23108830), supporting reproducibility.

## Critical Assessment

**Novelty.** The origin-vs-introducing-write distinction is a genuine conceptual step beyond the group's own prior taxonomy: prior failure-attribution work (AgenTracer, FAMAS, DuoTrace, Zhang et al.) requires observable failures, multiple trajectories, or step labels, none of which exist for silent failures; SAGE is designed for the single-trace, test-passing regime. That said, the method is an LLM-as-judge pipeline over transcripts — the novelty is in the problem formulation, decision rule, and evaluation discipline rather than in any new modeling technique.

**Rigor — strong but with real caveats.** The reliability protocol (repeated scoring, blind cross-judge, resampling, human annotation, prefix-only anti-hindsight prompting, mandatory quotations, automated consistency checks) is well above the norm for LLM-judge studies. However: (1) *the central construct has no gold standard* — humans label only provenance and the introducing write; origin type/turn are validated solely for self-consistency, so repeatability (α = 0.96) should not be read as correctness, a limit the authors themselves state but which tempers the headline; (2) *corpus concentration*: 87 of 95 cases come from just 15 CVEfixes tasks and one SSRF CVE alone contributes 16 cases, which is why the task-disjoint 95% interval for provenance agreement is as wide as 74.42–96.88%; (3) *judge-family and designer overlap*: the primary judge GPT-5.6 Sol shares a family with evaluated GPT-5.5, the second judge Claude Opus 5 with evaluated Claude Opus 4.8, and annotator R1 participated in corpus construction and localization-rule design — the authors acknowledge both and mitigate the latter by reporting R2 separately, but both biases plausibly inflate agreement; (4) *the missed-opportunity headline (59/95) rests on the two least-stable dimensions* (cross-judge α = 0.68 for Verification Rigour and Scope Awareness), so that count is the most judge-dependent number in the paper.

**Reproducibility.** Good on paper: Zenodo dataset, external judges, fully specified decision rule and scoring rubric, automated post-hoc checks. The 95-case corpus is, however, bounded by candidate screening thresholds (L3 R ≥ 15) inherited from prior work, and all subgroup comparisons with n < 10 (CAMEL n = 4, OpenHands n = 9, Qwen3.8-Max n = 1 — reported at 0.00% agreement on a single case) are descriptive only.

**Significance.** The actionable finding — that most silent failures become observable as unaddressed requirements or inadequate defence choices *before* the vulnerable write, and that frameworks discarding intermediate artefact states measurably degrade localization — is directly useful for agent-framework design and for placing safeguards in repair pipelines. The paper is careful to note it is observational: whether interventions at origins actually prevent silent failures is left to future work.

## Strengths

- Well-motivated, precisely operationalized problem: localizing divergence in *test-passing* patches, where no failure signal exists for conventional attribution methods.
- Strict separation of judge-dependent outputs (origin type/turn) from artefact-derived outputs (provenance, introducing write), with honest discussion that repeatability and human agreement measure different things.
- Multi-source reliability evaluation (repeated scoring, blind cross-judge, 1,000 task-disjoint partitions, leave-one-task-out, dual human annotators) that reports confidence intervals rather than single aggregate numbers.
- Deterministic, auditable decision rule with mandatory verbatim quotations and automated consistency checks linking origin turn, provenance, and introducing write.
- Concrete engineering implication backed by data: preserve per-write artefact snapshots — final-only traces are consistently the least localizable across all three evaluations.

## Limitations

- Small and concentrated corpus: 95 confirmed silent failures from 19 tasks, 87 from CVEfixes; one SSRF CVE yields 16 cases; subgroup analyses (CAMEL n = 4, Qwen3.8-Max n = 1) are too small to support framework/model conclusions.
- Python repair tasks and security-focused benchmarks only; generalization to other languages, task types, or deployed agents is untested.
- No ground truth for the origin turn itself; human validation covers only provenance and the introducing write, and the two annotators agree relatively weakly on the introducing write (κ = 0.58).
- Potential judge-family overlap (GPT-5.6 Sol vs GPT-5.5; Claude Opus 5 vs Claude Opus 4.8) and R1's dual role in corpus construction and rule design may inflate agreement estimates.
- The paper is observational: it identifies where divergence becomes observable but provides no evidence that safeguards placed at origins reduce silent-failure rates, nor any cost analysis of such interventions.

## Questions for Further Exploration

- Would an explicit security-requirement checkpoint inserted at the flagged missed-opportunity turns (59/95 cases) measurably reduce silent-failure rates, and what token/latency overhead does it add?
- Can origin-turn localization be validated against controlled perturbations (injected faults with known positions) instead of only repeatability and provenance agreement?
- Does a cross-family judge ensemble with disagreement-triggered human review close the α = 0.68 cross-judge gap on Verification Rigour and Scope Awareness scoring, which drives the missed-opportunity flags?
- How does artefact-history reconstruction behave on repository-level, multi-file repairs where snapshotting every write is expensive or unavailable?
