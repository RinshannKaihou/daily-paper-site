Why This Matters

Fixes a real, CVE-numbered incident

Targets the prompt-injection credential-exfiltration failure behind OpenClaw / CVE-2026-25253 — a five-minute key theft via email injection — with a reproducible PKCS#11 + Zero-Trust stack.

Critical Edge

Headline 0/192 barely exercises the AI judge

The result is dominated by deterministic Chist + architectural Layer 5. The RAV semantic judge stands on only a small n=10 ablation (Wilson upper bound 27.8%).

Methodology two complementary guarantees

Hardware confinement (Layer 5) removes the private key from any software-readable location. Keys are generated inside the HSM/TPM/smart-card boundary, addressed only via opaque handles scoped to a SAGA session; the host receives only signature bytes.

Behavioural enforcement (Layers 1–4) stops a compromised-but-legitimate agent from abusing signing access. SAGA binds a verbatim user-intent string Iuser (set before any external source is read) to identity + policy via X25519 DH + HKDF → AES-256-GCM. The deterministic Kernel then enforces scope allow-lists, quota, SHA-256 commitment matching, and taint tracking.

Evaluation: 12 injection scenarios (3 user tasks × 4 attacker goals) + 4 benign tasks; identical "follow-all-instructions" system prompt in both modes; T=0.

Key Contributions drop-in · vendor-neutral

  • PKCS#11 adapter as primary contribution. Replaces .env / ~/.ssh/id_rsa / container-memory keys with hardware-confined keys; host gets only signature bytes via opaque session handles.
  • Transparent drop-in. One PKCS11Provider line routes git/SSH signing through the HSM; validated on SoftHSMv2 + Infineon SLB9670 TPM 2.0 with zero code change.
  • Operator / agent plane split. Operator-plane tools are invisible to the System Agent, so an injected agent cannot reset the commitment anchor or forge session context.
  • Externally authored evaluation. MIT-licensed AgentDojo ImportantInstructionsAttack template rather than self-constructed attacks.

Critical Assessment · sharpest edge Taint laundering via fetch_url → write_file → read_file → sign_file is an unpatched gap — only "closed" because write_file isn't exposed. Any deployment adding a writable scratchpad reopens the hole unless xattr/eBPF/SELinux propagation is added.

Limitations what the 0% does & doesn't prove

  • RAV contribution under-isolated. Headline 0/192 is dominated by deterministic Chist (IT-01/02) + architectural Layer 5 (IT-04); RAV independently tested only at n=10.
  • Shallow taint model. Set on fetch_url but does not propagate to files written in-session.
  • HITL approval fatigue acknowledged but unmitigated — no per-session escalation cap.
  • Latency. ~1 s warm / ~1.9 s cold per sign request (RAV-bound) — out of scope for per-request JWT/HMAC loops.
  • Single benchmark. InjecAgent (1,054 cases) only a planned extension; GAR is an in-memory registry.

Strengths why it lands

  • Threat model grounded in a real CVE-numbered production incident, not a toy.
  • Clean separation of deterministic, probabilistic, and architectural claims.
  • RAV input isolation: kernel_action built only from observable call parameters, defeating critic-evasion priming.
  • Honest exclusion of Minimax-M27 confound and honest small-sample RAV reporting.

Open Questions for further work

  • Does RAV hold up on InjecAgent's 1,054 cases across 17 tools, with far more diverse injection framings?
  • Can filesystem-level taint (xattr on write / eBPF on VFS) close the laundering path without prohibitive complexity?
  • What is the empirical HITL escalation rate in a real multi-day autonomous pipeline — does approval fatigue materialise?
  • Does swapping selene-mini for a stronger judge materially change the RAV-only result, and at what latency/privacy cost?
