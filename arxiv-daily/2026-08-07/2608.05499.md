> **一句话总结：** APQF 用五个协作的 LLM 智能体（Profiling/Pruner/Quant/FineTuning/Evaluation）在实测的逐层敏感度证据驱动下，自动完成结构化剪枝、混合精度量化感知训练与精度恢复，在 ImageNet 上把计算量压到原始 BOPs 的 5.6%–7.7%（13–18× 压缩），并在 CIFAR-10 五个架构中的四个上比 GETA 压得更狠、精度更高。

> **TL;DR:** APQF is the first framework to combine LLM-guided, profiling-grounded decisions with a fully training-aware pipeline of structured pruning + mixed-precision quantization-aware training (QAT) + accuracy recovery, working across both CNNs and vision transformers. On ImageNet-1K (200K-image training budget) it cuts compute to 5.6–7.7% of original bit-operations (13–18× reduction) while staying ~17 Top-1 points above the joint pruning+quantization baseline GETA; on CIFAR-10 it beats GETA on 4 of 5 architectures in relative BOPs and reaches lower BOPs on DeiT-Tiny (8.49% vs 11.90%), Swin-Tiny (5.11% vs 15.12%), and ResNet-50 (7.65% vs 7.68%), with three models ending more accurate than their uncompressed originals.

## 核心贡献

- **Profiling 智能体**：用 ptflops 测量逐层 MACs 与参数分布，用 torch.profiler 记录 CPU/GPU 执行时间，并对每个依赖图结构组在多个剪枝比例下做经验性敏感度扫描，汇总成一份紧凑的"架构简报 + 逐组敏感度 CSV"，作为后续所有压缩决策的实测证据。
- **LLM 引导的多阶段结构化剪枝**：在 DepGraph 之上，让 LLM 根据敏感度数据为每个依赖组分配独立的剪枝比例；采用"从原始模型累积重放"的方式避免在已剪枝 checkpoint 上再次剪枝导致停滞；按 δ 阈值（τ₁=2%, τ₂=4%）自适应触发恢复。
- **LLM 引导的混合精度 QAT + 蒸馏**：LLM 从 {2,4,6,8,16,32} 中为每层选定位宽，用 Brevitas 注入伪量化，以冻结的全精度教师做知识蒸馏（L = α·T²·KL(q_t‖q_s) + (1−α)·CE），并支持可选的 QAT 后 KD 恢复阶段。
- **架构无关、即插即用**：同一套流程无需架构特化规则即可作用于 ResNet、VGG、ViT、DeiT、Swin，覆盖 CNN 与 Transformer 两类。
- **数据高效与 LLM 无关**：直接从预训练模型按实测敏感度剪枝并以 PEFT/KD 恢复，而非像 GETA 那样对整个网络做端到端重优化，因此在 200K 图像预算下大幅领先；六种 LLM（含 DeepSeek、Gemma 免费开源模型）在 Swin-Tiny 上精度都稳定在 97.4–97.9%，不依赖某一款高端模型。

## Key Contributions

- **Profiling agent** that produces a per-group sensitivity map and a compact architecture brief (via ptflops + torch.profiler + a DepGraph sensitivity sweep over user-supplied pruning ratios), grounding every later decision in measured evidence rather than hand-tuned heuristics.
- **LLM-guided multi-stage structured pruning** built on DepGraph: the LLM assigns a per-group pruning ratio, stages are accumulated and replayed from the original model (avoiding the "prune-on-pruned" stall), and adaptive recovery is triggered by Top-1 drop thresholds τ₁=2%, τ₂=4%.
- **LLM-guided mixed-precision QAT with knowledge distillation**: per-layer bit-width chosen from {2,4,6,8,16,32} via Brevitas, trained under a frozen full-precision teacher with combined T²-scaled KL + cross-entropy loss, plus an optional post-QAT KD recovery pass kept only if it helps.
- **Adaptive FineTuning agent** shared by pruner and quantizer: supports full fine-tuning, five PEFT variants (LoRA, DoRA, rsLoRA, PiSSA, LoRA+), and a two-stage PEFT→full recovery for the strongest final-stage drops; every LLM-proposed plan is validated against the real surviving modules before execution (e.g., PiSSA rejected for conv-only models).
- **Architecture-agnostic, LLM-agnostic, data-efficient pipeline** spanning CNNs (ResNet, VGG) and transformers (ViT, DeiT, Swin), accessed via the OpenRouter standard API so the planner can be freely swapped.

## Methodology

APQF orchestrates five cooperating agents around a pretrained vision model:

1. **ProfilingAgent** performs (a) static cost profiling — ptflops measures per-layer MACs and parameter counts, torch.profiler records CPU/GPU execution time, and an LLM aggregates the verbose traces into a compact architecture brief; and (b) a DepGraph sensitivity sweep that prunes each dependency-aware structural group at each user-supplied pruning ratio, evaluates the pruned model, and records the accuracy drop together with the achieved parameter/MAC cut into a per-group sensitivity CSV. These two artifacts (brief + CSV) are the only architecture-specific input to every downstream decision.

2. **PrunerAgent** performs multi-stage target-seeking structured pruning. At each stage the LLM is prompted with the profiling data, the user's target reduction ρ*, the current reduction ρ, the remaining gap, and the history of prior selections, and proposes a set of dependency groups with per-group pruning ratios. APQF validates the proposal against the real model (rejecting invalid group/layer names and ratios, with one repair retry) and then **replays the cumulative set of selected groups from the original model** rather than pruning on top of the already-pruned checkpoint — this is the key trick that avoids DepGraph's "stall before target" failure. After each stage the Top-1 drop δ is measured and recovery is decided: δ<τ₁ skip; intermediate δ≥τ₁ do PEFT; final stage δ≥τ₂ do two-stage (PEFT then full fine-tune). The final checkpoint is the "keep-better" of the pruned and recovered candidates.

3. **QuantAgent** takes the pruned checkpoint plus the same profiling evidence, verifies the parameter count matches the pruning result, and asks the LLM to propose a per-layer bit-width assignment (from {2,4,6,8,16,32}, 2-bit reserved for specific architectures like VGG) conditioned on a user-chosen prompt type (conservative / balanced / aggressive). The proposal is validated against the real surviving modules. Brevitas then instruments the model with fake-quant nodes, calibrates on a small sample, and trains the quantized student against a frozen full-precision teacher with L = α·T²·KL(q_t‖q_s) + (1−α)·CE(z_s, y); the LLM selects the QAT hyperparameters (lr, epochs, warmup, weight decay, batch size, calibration samples). An optional post-QAT KD pass can be run afterward and kept only if it improves accuracy.

4. **FineTuningAgent** is the shared recovery component invoked by both pruner and quantizer. Post-pruning it supports full fine-tuning, five PEFT variants (LoRA, DoRA, rsLoRA, PiSSA — linear-only, LoRA+), and a two-stage PEFT-then-full procedure for the strongest final-stage drops. Post-quantization it runs the same KD objective on the already-quantized student against a configurable teacher (pruned model or original). All proposed plans are validated before execution.

5. **EvaluationAgent** is deterministic (no LLM): it loads a checkpoint and evaluates on a fixed, class-balanced validation manifest drawn once with a fixed seed, so baseline / pruned / fine-tuned / quantized models are compared on identical examples. It reports Top-1, Top-5, parameter count, and relative bit-operations (Rel. BOPs = Σ M̃_l·b_w·b_a / (322·Σ M_l) × 100%), a single architecture-normalized number that captures both pruning (reduces MACs) and quantization (reduces bit-widths).

## Results & Highlights

- **ImageNet-1K, 200K-image training budget, conservative quant, no post-QAT KD (Table 1):** APQF cuts compute to **5.63% Rel. BOPs on DeiT-Tiny (66.52→67.90 Top-1, +1.38)**, **7.74% on ResNet-50 (80.13→72.73, −7.40)**, **6.17% on Swin-Tiny (80.61→74.16, −6.45)**, and **5.93% on ViT-Small (79.87→76.50, −3.37)** — a 13–18× reduction in bit-operations.
- **ImageNet vs GETA under the same 200K budget (Fig. 5):** APQF retains **68–77% Top-1** whereas GETA's joint pruning–quantization optimizer collapses to **51–59% Top-1** — roughly a **17-point** gap attributable to APQF's data-efficient recover-from-pretrained design vs GETA's re-optimize-from-scratch approach.
- **ImageNet full-data comparison (Table 2, APQF adds ~5 epochs post-QAT KD):** ViT-Small APQF **78.26% at 5.73% Rel. BOPs** vs GETA **80.12% at 19.37% Rel. BOPs** (~3× lower BOPs, −1.61 vs −1.31 Δ); DeiT-Tiny APQF **69.51% (+2.99) at 6.11%** vs GETA **72.88% (+0.87) at 16.95%**; Swin-Tiny APQF **77.59% at 7.23%** vs GETA **80.09% at 21.84%**.
- **CIFAR-10, baseline-matched (Table 3):** APQF reaches lower Rel. BOPs on **4 of 5** models and improves over its own baseline on **3 of 5**. Standouts: DeiT-Tiny **95.01% (+3.11) at 8.49%** vs GETA 91.05% (−0.70) at 11.90%; Swin-Tiny **97.92% (+1.14) at 5.11%** vs GETA 91.46% (−5.74) at 15.12%; ResNet-50 **96.62% (+0.79) at 7.65%** vs GETA 93.09% (−3.46) at 7.68%. DeiT-Tiny, ResNet-50, and Swin-Tiny all end more accurate than their uncompressed originals.
- **VGG7/CIFAR-10 (Table 4):** at **0.41% Rel. BOPs APQF reaches 93.15% (+0.20 vs its own FP32 baseline)** vs GETA 92.57% (−0.48) at the same budget — a **0.58-point** win — and is **the only method below 0.5% Rel. BOPs that improves on its own FP32 baseline**. It lands within 0.08 points of the best Bayesian Bits config (93.23% at 0.51%) while using ~20% fewer BOPs. Quantization-only baselines (TWN, LR-Net, RQ, WAGE) sit at 1.56–6.24% Rel. BOPs, i.e. 4–17× the cost.
- **Ablation (Fig. 6):** at matched compute, Uniform (single ratio + single bit-width) loses the most accuracy on all four models, and removing the measured profiling data from the LLM ("w/o profiling") still causes a smaller but **consistent accuracy drop on every model tested**, isolating the value of both adaptive per-layer decisions and grounded profiling.
- **LLM-planner robustness (Fig. 7):** six different LLMs on Swin-Tiny/CIFAR-10 all land in **97.4–97.9% Top-1**, including free/open-weight planners (DeepSeek, Gemma) that match the default Claude Opus 4.8 within a narrow band, so the framework is not coupled to a premium model.

## Authors & Credibility

Authors are from the Department of Computer Science at Iowa State University (Jafari, Bilwal, Zhou, Jannesari) with a co-author from Agricultural and Biosystems Engineering (Gelder). The group previously published **ProfilingAgent** (arXiv:2509.05584, 2025), a profiling-guided multi-agent LLM system for structured pruning + post-training dynamic quantization — APQF is presented as the next step that adds a fully training-aware pipeline (mixed-precision QAT + recovery). The work was supported by NCSA Delta GPU allocations (ACCESS grants AGR250012, CIS250538, CIS240379), and experiments ran on NVIDIA H200 (141 GB) and A100 (40 GB) nodes, lending hardware credibility. The paper reads as a thesis-derived preprint ("the main contributions of this thesis"), which explains its breadth and its honest, somewhat cautious tone in the limitations section.

## Critical Assessment

- **Novelty:** Genuine. The combination of LLM-as-planner over *measured* per-layer profiling evidence, executed inside a fully training-aware pruning→QAT→recovery loop, and validated across both CNN and transformer families, is not something existing agentic work (ProfilingAgent did pruning + PTQ only) or joint optimizers (GETA, DJPQ, Bayesian Bits — none use an LLM) deliver. The "cumulative replay from the original model" pruning trick is a small but concrete engineering contribution that addresses a real DepGraph failure mode.
- **Rigor:** The ablation cleanly isolates two factors (uniform vs adaptive; with vs without profiling) at matched compute, and the LLM-planner robustness study across six models is a meaningful test of the framework's central claim of model-independence. The EvaluationAgent's fixed-seed, class-balanced validation manifest is a sound design for fair within-pipeline comparison.
- **Reproducibility concerns:** The headline ImageNet numbers are produced under a deliberately constrained 200K-image subset with conservative quantization and post-QAT KD *disabled* — a setting chosen to showcase data-efficiency, not the best achievable accuracy. ResNet-50 (−7.40) and Swin-Tiny (−6.45) drops on ImageNet are large in absolute terms, and the paper does not report what these become with full-data training + post-QAT KD (only ViT-Small, DeiT-Tiny, Swin-Tiny appear in the full-data Table 2, and Swin-Tiny there is still −3.02). Code release is not clearly committed to in the preprint. The LLM planner is acknowledged to be non-deterministic (same prompt → different plan), controlled only by prompt design and temperature, with "failures more frequent with cheap or free models."
- **Baseline confound (the biggest caveat):** The authors candidly disclose that they could enable only **weight-only quantization** in GETA's released code for ResNet/transformer backbones — joint weight+activation quantization in GETA "exposed pruning-dependency and subnet-construction failures" and would require "nontrivial modifications" that "would no longer be the authors' original method." APQF, by contrast, quantizes both weights and activations. This means the central comparison is not apples-to-apples on the quantization axis, and the Rel. BOPs advantage of APQF partly reflects a stronger (and harder-to-optimize) quantization regime that the baseline was simply not configured to use. The authors argue this makes APQF's win *more* convincing, but a reader should weigh that GETA at its intended joint-W+A configuration might close part of the BOPs gap.
- **Metric limitations:** All efficiency claims rest on the **theoretical Rel. BOPs** number; there are **no measured on-device latency, memory, or energy numbers** on an actual edge target, which is striking for a paper whose motivation is deployment on "smartwatches, IoT nodes, intelligent sensors." BOPs correlate with but do not equal wall-clock speedup, especially for mixed 2/4/6/8-bit graphs on commodity integer hardware.
- **Scope:** Only image classification; no detection/segmentation/LLM/VLM experiments despite these being named as future work. The "architecture-agnostic" claim rests on five classification models.
- **Significance:** If the code is released, APQF is a practical, extensible blueprint for LLM-guided compression and a credible data-efficient alternative to joint optimizers under limited training budgets.

## Strengths

- First genuine integration of LLM-guided planning over *measured* profiling evidence with a full pruning + mixed-precision QAT + recovery pipeline, across both CNN and transformer architectures.
- Data-efficient: dramatically outperforms the data-hungry joint optimizer GETA under a 200K-image budget (≈17-point Top-1 gap on ImageNet).
- Engineering details are well-motivated — cumulative-replay pruning, threshold-gated adaptive recovery, plan validation against real modules — and directly address known failure modes of the underlying DepGraph/Brevitas tools.
- Strong, honest ablations isolating the contribution of both adaptive per-layer decisions and grounded profiling, plus a multi-LLM robustness study that supports the "future-proof / planner-agnostic" claim.
- Several compressed models (DeiT-Tiny, ResNet-50, Swin-Tiny on CIFAR-10; VGG7 at 0.41% BOPs) actually *exceed* their uncompressed baselines.

## Limitations

- Large absolute accuracy drops on the more heavily compressed ImageNet models (ResNet-50 −7.40, Swin-Tiny −6.45) under the headline constrained setting; full-data + post-QAT KD results are reported for only three of the four ImageNet models.
- GETA baseline is compared in a weight-only quantization regime because the released GETA code could not stably enable joint weight+activation quantization on these backbones — a non-trivial confound on the central comparison.
- All efficiency results are theoretical Rel. BOPs; no measured latency/energy/footprint on a real edge device, despite the edge-deployment motivation.
- LLM planner non-determinism: the same request can yield a different plan; failures are more frequent with cheap/free models and when profiling evidence is withheld. Mitigations (prompts, temperature) are empirical, not formal.
- Scope limited to image classification; the segmentation/detection/LLM/VLM extensions are stated as future work.
- Compute-limited exploration: the authors note the available GPUs constrained how many configurations and repeated runs they could afford, so variance/error bars are largely absent.

## Relevance

直接命中"模型压缩/高效推理"与"LLM 智能体自动化机器学习流程"两条主线：APQF 把 LLM 作为 planner，用实测 profiling 数据自动决策逐层剪枝比例与位宽，对希望在资源受限硬件上部署 CNN/ViT 且不愿手工调参的研究者具有很高参考价值，其 profiling-grounded 多智能体编排思路也可迁移到其它自动化 ML pipeline。

## Questions for Further Exploration

- How do APQF's compressed models perform on **measured on-device latency and energy** (e.g., on an ARM mobile CPU or an INT8/INT4-capable NPU), as opposed to the theoretical Rel. BOPs metric? Does the mixed 2/4/6/8-bit graph actually run faster, or does the bit-width heterogeneity hurt kernel efficiency?
- What happens when GETA (or DJPQ / Bayesian Bits) is **re-implemented to support joint weight+activation quantization** on these backbones — how much of APQF's Rel. BOPs advantage survives a true apples-to-apples comparison?
- Can the profiling-evidence prompt be made **deterministic enough** (or cached) to eliminate run-to-run plan variance, and what is the failure-rate/cost trade-off curve across LLM planners beyond the six tested on Swin-Tiny?
- Does the framework extend to **dense prediction** (segmentation with SAM-style models) and to **large language / vision-language models**, where the layer count and the cost of the QAT+KD recovery loop are far larger?
- How sensitive are the results to the **recovery thresholds τ₁/τ₂ and the prompt aggressiveness**, and is there a principled (non-manual) way to set them per architecture?
- The paper prunes a pretrained model and recovers it; how does APQF behave when the **pretrained checkpoint is weak or out-of-distribution** relative to the target dataset, where the recover-don't-reoptimize assumption may break?
