Activity Frames: Deterministic Screen-Activity Compilation for Agent Memory and Replay

A deterministic, zero-model compiler turns passively captured screen activity into typed "activity frames," shrinking one day's capture into a prompt block an agent can read with 98.4% QA accuracy — and reading two agent-cost parameters no one had measured before.

Nossa Iyamu · Independent Researcher MIT-licensed · MCP server 61-day corpus · 128,756 frames macOS · Apple Silicon
① Key Finding
A deterministic, zero-model compiler turns one day of screen capture into a 1,469-token block that lets an agent answer daily-activity questions at 98.4% accuracy.
② Key Metric
86×
context-token reduction (126,812 → 1,469 tokens) in a 68 ms compile — zero model calls.
④ Critical Edge
Single-user, single-machine, single-platform study (the author's own 51–61 days) — every absolute number is one professional's property, not a population estimate.

Core Contributions 核心贡献

  • Two-tier activity-frame schema — tier-1 measured fields only; inferred labels quarantined in a strippable inferred namespace with evidence pointers, a structural defense against memory poisoning.
  • Six zero-learning compilation rules — dwell credit min(Δt, 90s), 300s session gaps, flicker merge (A→B→A, B≤20s logged as interruption), nearest-snapshot re-attribution, 3-tier click resolution, layered URL typing.
  • Open reference implementation — zero-dependency Python compiler, on-device SQLite capture, CLI, and a hand-written stdio MCP server exposing 6 tools to any MCP client.
  • Demand-side cost instrument — reads Routine Overhead Ratio R (60× guarded / 343× minimal) and delegable recurrence h (9.0% in-sample / 7.7% held-out) from pre-delegation human activity, parameters cost models assume but never measure.
