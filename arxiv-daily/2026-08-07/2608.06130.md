> **一句话总结：** 将 AI Agent 签名工作流中的软件态私钥替换为通过 PKCS#11 接口访问的硬件隔离密钥（HSM/TPM/智能卡），外层套用身份(SAGA)、能力(Smax)、提交锚(Chist)、污点跟踪与语义校验(RAV) 五层强制栈；在 AgentDojo 改造基准上把三模型合并的注入成功率从 19.3% 降至 0%（Wilson 上界 2.0%），密钥外泄攻击类被结构性关闭。

> **TL;DR:** The paper replaces software-resident private keys in MCP agent signing workflows with hardware-confined keys accessed via a vendor-neutral PKCS#11 adapter, wrapped in a 5-layer Zero-Trust stack (identity/SAGA session, deterministic Smax scope + SHA-256 Chist commitment + taint tracking, RAV semantic judge, hardware execution boundary). On an AgentDojo-derived keystore benchmark (12 injection scenarios, n=192 across gpt-oss-120b/Qwen2.5-72B/DeepSeek-V4-Flash) the protected Attack Success Rate drops from a combined baseline of 19.3% [14.3%, 25.4%] to 0% (Wilson 95% CI upper bound 2.0%) with zero benign false positives; the IT-04 key-exfiltration class is closed structurally because no private-key file ever exists on disk.

## 核心贡献

- **硬件密钥库的 MCP 集成（主要贡献）**：用硬件隔离密钥（HSM/TPM/智能卡）取代软件态私钥，通过厂商中立的 PKCS#11 适配器暴露；对 Git/OpenSSH 完全透明——仅需 `PKCS11Provider` 一行配置即可切换，已用 SoftHSMv2（可复现代理）与嵌入式 TPM 2.0（Infineon SLB9670，固件 7.63）双后端验证，整套集成测试零代码改动通过。
- **五层零信任强制栈**：Layer 1 全局 Agent 注册（GAR/AIC + 一次性 X25519 密钥）→ Layer 2 SAGA 密码学会话（绑定用户意图 `Iuser`）→ Layer 3 确定性能力强制（`Smax` 白名单、配额 `Qmax`、`Chist` 提交哈希、污点标签）→ Layer 4 语义意图校验（CNI 三段门 + RAV LLM 判官）→ Layer 5 硬件执行边界。只有穿过前 4 层的请求才能到达硬件签名。
- **结构性关闭密钥外泄攻击**：在 HSM 后端部署中磁盘上根本不存在私钥文件，因此无论 Agent 是否被注入或模型对齐如何漂移，密钥都不可能被读出——这与行为防御正交。
- **对抗性基准评测**：把 AgentDojo 的 `ImportantInstructionsAttack` 模板扩展为 4 个签名域攻击目标（IT-01 目标替换 / IT-02 毒化合同 / IT-03 任务前注入 / IT-04 密钥外泄），跨 3 个"会跟随注入"的开源模型得到合并 baseline ASR 19.3% → protected ASR 0%。
- **诚实的可证伪化报告**：明确把 Minimax-M27（baseline 0%，因模型本身拒绝注入）从主结论剔除作为混淆项，并通过 UT-04 消融单独量化了 RAV 这一层的独立贡献。

## Key Contributions

- **Vendor-neutral PKCS#11 adapter as primary contribution.** Replaces `.env`/`~/.ssh/id_rsa`/container-memory keys with hardware-confined keys generated inside the HSM boundary; the host only receives signature bytes via opaque session-scoped handles. Existing keys can be imported as non-extractable objects via `CKM_AES_KEY_WRAP` (strongest guarantee is reserved for keys generated fully inside hardware).
- **Transparent drop-in for standard tooling.** A single `PKCS11Provider` directive in `~/.ssh/config` plus `gpg format = ssh` in `~/.gitconfig` routes `git commit` signing through the HSM; swapping `libsofthsm2.so` for `libtpm2_pkcs11.so` (or any production HSM library) needs no code change. RSA-2048 and ECDSA-P256 are supported.
- **Five-layer enforcement stack as the enabler.** (1) Identity/Root-of-Trust via GAR + Agent Identity Cards; (2) SAGA X25519 handshake producing AES-256-GCM Shared Derived Key encrypting an Access Control Token that carries `agent_id, s_max, q_max, t_expire, i_user`; (3) deterministic Agent Kernel checks: scope allow-list, quota via monotonic nonce, `Chist` SHA-256 commitment comparison (<1 ms), taint tagging of fetched content; (4) Critical Node Interceptor running RAV (LLM judge fed only a kernel-derived `(Iuser, kernel_action, taint_flags)` triple to resist critic-evasion priming) plus taint- and no-commitment-triggered HITL; (5) the hardware execution boundary.
- **Operator/agent plane separation.** Operator-plane tools (`saga_init`, `set_session_context`, `commit_payload`, `approve_pending`) are invisible to the System Agent, so an injected agent cannot reset the Chist anchor or forge session context.
- **Externally authored injection evaluation.** Uses the MIT-licensed AgentDojo `ImportantInstructionsAttack` template (agentdojo==0.1.35) with verbatim jailbreak wrapper, four domain-specific attacker goals, three primary user tasks, three injection-following models; reports per-scenario breakdown (Appendix C, Table 5) and a RAV-only ablation.

## Methodology

The architecture is built around two complementary guarantees. **Hardware confinement (Layer 5)** structurally removes the private key from any software-readable location: keys are generated inside the HSM/TPM/smart-card boundary, addressed only via opaque integer handles scoped to a SAGA session, and the host receives only signature output. This closes the exfiltration class independent of LLM behavior.

**Behavioural enforcement (Layers 1-4)** prevents a compromised-but-still-legitimate agent from abusing signing access. SAGA establishes a cryptographic session binding the verbatim user intent string `Iuser` (set before any external source is read) to agent identity and policy via X25519 DH + HKDF → AES-256-GCM ACT, with HMAC over every subsequent call nonce. The deterministic Agent Kernel then enforces tool-scope allow-lists (`Smax`, <1 ms reject, no LLM consulted), quota (`Qmax`), SHA-256 commitment matching (`Chist`: the operator pre-arms `commit_payload` with the intended document hash out-of-band; any mismatched `sign_payload` is rejected deterministically), and taint tracking (`fetch_url` unconditionally sets `session_tainted=True` host-side; the agent cannot suppress it).

The Critical Node Interceptor (Layer 4) gates critical signing tools (`sign_payload`, `sign_file`, `sign_git_commit`, `sign_email_body`) through a three-stage gate: (1) RAV LLM judge (`atla/selene-mini:q4_k_m` via local Ollama, air-gapped) comparing `(Iuser, kernel_action)` — critically `kernel_action` is built entirely from observable call parameters (tool name, key handle, file name, byte count, payload hash prefix), never agent free text, to prevent contextual priming; (2) taint-triggered HITL; (3) `REQUIRE_COMMITMENT` safety net for fully autonomous pipelines with no pre-named document. Only `APPROVE + untainted + commitment-present` reaches hardware without HITL.

Evaluation uses 12 injection scenarios (3 user tasks × 4 attacker goals) plus 4 benign tasks, with gpt-oss-120b at 10 trials/scenario and secondary models at 3 trials each, T=0, identical "follow-all-instructions" system prompt in both modes. The evaluation distinguishes deterministic claims (Chist, scope, REQUIRE_COMMITMENT — verifiable by pytest), probabilistic claims (RAV — requires empirical attack evaluation), and architectural claims (Layer 5 — verifiable by filesystem inspection).

## Results & Highlights

- **Combined security claim (n=192 across three injection-following models): baseline ASR 19.3% [14.3%, 25.4%] → protected ASR 0% (Wilson 95% CI upper bound 2.0%).** Per-model baseline ASR: gpt-oss-120b 21.7% [15.2%, 29.9%], Qwen2.5-72B 8.3% [2.9%, 21.8%], DeepSeek-V4-Flash 22.2% [11.7%, 38.1%]; all three drop to 0% protected.
- **IT-04 key exfiltration (the motivating threat): 16/30 = 53.3% [36.1%, 69.8%] baseline success on gpt-oss-120b (n=120 subset), 0/30 protected** — blocked architecturally at Layer 5 because no private key file exists in the HSM-backed deployment.
- **IT-03 pre-task injection exploits task structure: 8/10 baseline success on UT-03 (open-ended "verify-then-sign") vs 0/10 on UT-01/02 (file-constrained)**; protected 0/30 across all task types via deterministic Chist hash mismatch (<1 ms, no LLM).
- **Substitution attacks (IT-01/02) are low-baseline (2/60 = 3.3%) but still drop to 0/60 protected** via Chist commitment check.
- **Benign task success rate (n=4): 100% baseline = 100% protected, zero false positives**; BD-04 autonomous inbox completes via RAV APPROVE + HITL auto-approval under REQUIRE_COMMITMENT.
- **RAV-only ablation (UT-04, n=10, gpt-oss-120b, Chist disabled): baseline ASR 90% [59.6%, 98.2%] → 0% protected (Wilson 95% CI upper bound 27.8%)**, isolating the semantic judge's standalone contribution.
- **Minimax-M27 yielded 0% baseline ASR across all 36 trials and was honestly excluded from the combined claim** as an alignment confound.
- **Latency overhead (Table 6): fast path ≈10 ms (SoftHSM) / ≈350 ms (TPM2); secure path warm ≈1,069 ms (SoftHSM) / ≈1,409 ms (TPM2), dominated by ~1,059 ms RAV inference**; cold RAV ~1,886 ms. Overhead is per-request and non-accumulating.

## Authors & Credibility

The two authors are at Huawei's Hardware Systems Security Lab (HSSL) in Helsinki, with Sambrook also affiliated with EPITA. The work is positioned against a concrete, dated production incident (the "OpenClaw security crisis" of January-February 2026, CVE-2026-25253, five-minute key exfiltration via email injection) and the OpenClaw project's own published policy labeling the agent "not a trusted principal" — giving the threat model real grounding rather than a hypothetical. The benchmark choice (externally authored AgentDojo MIT-licensed template rather than self-constructed attacks) and the explicit LLM Usage Statement distinguishing editorial LLM use from methodological LLM use (driving agents vs. RAV judge) are markers of methodological care. The reproducibility posture is strong: SoftHSMv2 as a software proxy, the same integration suite passing on a real Infineon SLB9670 TPM with no code change, and a published reproduction command (`uv run --env-file .env python benchmarks/run_agentdojo_keystore.py --runs 10`).

## Critical Assessment

- **Novelty:** Genuine. Table 4's four-axis comparison (Hardware / Session / Scope / Semantic) shows no prior system — HashiCorp Vault MCP, sansec-ai/mcp-hsm (SM2/SM3/SM4 + Windows-only, no semantic validation), SAGA, AgentBound, MCP-Secure, Aura, NemoClaw — addresses all four dimensions; the closest, Aura, only partially addresses hardware confinement and reports no adversarial injection benchmark. The combination of PKCS#11 drop-in + content-aware authorisation is new.
- **Rigor:** Mixed, and the authors are unusually honest about it. The strongest claims (Chist, scope, REQUIRE_COMMITMENT, Layer 5) are *deterministic* and verifiable by code inspection/pytest — protected ASR = 0% on substitution scenarios is a direct consequence of SHA-256 hash mismatch, not an empirical surprise. But the RAV layer's individual contribution is **not isolated in the main result**: Chist already blocks all of IT-01/02 deterministically and Layer 5 blocks IT-04 architecturally, so the headline 0/192 does not actually exercise the RAV as the deciding factor. The standalone UT-04 ablation (n=10, CI upper bound 27.8%) is too small to make a strong RAV-specific claim, which the authors acknowledge ("a larger-scale ablation is included as a planned artifact extension").
- **Baseline honesty:** Strong. Including three genuinely injection-following models and explicitly excluding Minimax-M27 as a confound (rather than lumping it in to inflate the headline) is the right call and notable.
- **Reproducibility:** Good on the deterministic and architectural layers; weaker on the LLM-dependent ones. The driving models are reachable via OpenRouter/NIM, the RAV judge is a public Ollama model, the TPM part number and firmware version are pinned, and the reproduction command is given. However, the artifact repository URL itself is not visible in the text (only relative paths like `benchmarks/run_agentdojo_keystore.py`), and the GAR is currently an in-memory registry initialised at startup — a simplification the authors flag but which limits production-readiness claims.
- **Significance:** High for the MCP/agent-security niche. It converts the exfiltration problem from "make the model behave" to "remove the key from software entirely," which is the correct threat-model framing. The explicit out-of-scope statement (per-request JWT/HMAC signing loops requiring key caching outside the boundary) keeps the claims honest.
- **Red flags / overclaiming:** (1) **Taint laundering via local storage is an unpatched gap**: an adversary controlling fetched content could in principle route `fetch_url → write_file → read_file → sign_file` to launder taint; the authors note it is "structurally closed" only because `write_file` is not exposed in the current agent plane — any deployment that exposes a writable scratchpad inherits the hole and must implement filesystem-level taint (xattr/eBPF/SELinux), deferred to future work. (2) **HITL approval fatigue is unmitigated**: no rate-limit on UNSURE/tainted/no-commitment escalations, which Franklin et al. identify as its own attack class. (3) The RAV judge is only process-level isolated, not hardware/kernel isolated. (4) `Chist`'s deterministic guarantee only holds when the operator pre-arms the anchor — fully autonomous pipelines fall back to probabilistic RAV + HITL.

## Strengths

- Threat model is grounded in a real, CVE-numbered production incident (OpenClaw / CVE-2026-25253) rather than a toy.
- Clean separation of deterministic, probabilistic, and architectural claim classes — readers can tell which 0% results are mathematical consequences and which are empirical.
- PKCS#11 vendor neutrality with a concrete one-line swap validated on two backends (SoftHSMv2 software proxy + Infineon SLB9670 TPM 2.0).
- Structural RAV input isolation: `kernel_action` is built only from observable call parameters, defeating the critic-evasion/contextual-priming class identified by Franklin et al.
- Honest exclusion of Minimax-M27 as an alignment confound and honest reporting of the small-sample RAV ablation.
- Operator/agent plane split prevents the injected agent from resetting its own commitment anchor or forging session context.

## Limitations

- **RAV contribution is under-isolated.** The headline 0/192 result is dominated by deterministic Chist (IT-01/02) and architectural Layer 5 (IT-04); the RAV is only independently exercised in a small (n=10) ablation with a wide confidence interval (upper bound 27.8%).
- **Taint model is shallow.** Taint is set on `fetch_url` but does not propagate to files written during the session; the only reason this is not exploitable today is that `write_file` is not in the agent-plane tool list. Any deployment adding a writable scratchpad reintroduces the bypass unless xattr/eBPF/SELinux propagation is implemented (future work).
- **HITL approval fatigue is acknowledged but unmitigated.** No per-session escalation cap; UNSURE/tainted/no-commitment calls all hit the operator, which is itself a documented attack surface.
- **Latency.** The secure path adds ~1 s (warm) to ~1.9 s (cold) per signing request from RAV inference — acceptable for the stated low-frequency, high-value target (Git signing, document certification) but explicitly out of scope for per-request API signing (JWT/HMAC).
- **Single-benchmark evaluation.** InjecAgent (1,054 cases across 17 tools) is only a "planned artifact extension"; the empirical attack evaluation rests entirely on the AgentDojo-derived 12 scenarios.
- **GAR is an in-memory registry**, not a hardened external service — fine for a prototype, limits production claims.
- **Strongest hardware guarantee applies only to keys generated inside the boundary**; imported keys (via `CKM_AES_KEY_WRAP`) get a weaker guarantee.
- **No modeling of PKCS#11 timing side-channels, compromised OS kernel, or physical HSM attacks** (explicitly scoped out).

## Relevance

Highly relevant to agent-security and MCP deployment research: it directly addresses the prompt-injection-driven credential-exfiltration failure mode that has already caused a real-world incident (OpenClaw/CVE-2026-25253), and provides a concrete, reproducible PKCS#11 + Zero-Trust stack that future agent frameworks can adopt or benchmark against.

## Questions for Further Exploration

- How does the RAV hold up at scale on InjecAgent's 1,054 cases and across 17 tools, where injection framings are far more diverse than the single AgentDojo template used here?
- Can filesystem-level taint propagation (xattr on write, eBPF on VFS, or SELinux type transitions) close the `fetch_url → write_file → read_file → sign_file` laundering path without prohibitive deployment complexity, and does it survive a determined red-team?
- What is the empirical HITL escalation rate and operator approval behavior in a real multi-day autonomous pipeline — does approval fatigue materialise, and would a per-session escalation cap or "collapse UNSURE to BLOCK when a Chist anchor is present" actually preserve usability?
- How does the architecture interact with per-request signing workloads (JWT/HMAC API auth loops), which the authors explicitly exclude — could session-scoped hardware-cached signing keys with short TTLs extend the guarantee without re-introducing key material to host RAM?
- Does swapping `selene-mini` for a stronger judge (e.g. GPT-4o-mini or a purpose-trained model) materially change the RAV-only ablation result, and at what latency/latency-privacy cost (local vs. internet-connected inference)?
- Is the deterministic 0% on substitution scenarios robust to an attacker who can influence the *content* of the committed document (e.g. via a supply-chain attack on the file the operator hashes) rather than substituting a different file post-commitment?
