> **一句话总结：** 提出 MERIT，一种免训练的 Text-to-SQL 修复智能体，通过在线维护"双极性"（已验证正确 vs. 失败方向）的跨查询情景记忆并按错误类型检索，在冻结的 Qwen2.5-7B-Instruct 上将 Spider 执行准确率从 66.34% 提升至 69.79%（+3.45 pp，95% CI 不含 0），但在 BIRD 上提升微弱且未能稳定胜过无类型化的动态检索。

> **TL;DR:** MERIT is a training-free Text-to-SQL repair agent that accumulates an online dual-polarity memory (oracle-verified corrections as positives, final unsuccessful directions as negatives) indexed by a deterministic error classifier, then retrieves via hybrid lexical-dense ranking over only causally-available (earlier-finalized) episodes. Using a frozen Qwen2.5-7B-Instruct with identical initial predictions and a budget of K=7, it lifts execution accuracy on Spider from 66.34% (stateless Iterative) to 69.79% (+3.45 pp, paired 95% CI [+1.97, +4.96]), but on BIRD the gain is only +1.09 pp with interval [0.00, +2.17], MERIT ties an untyped Dynamic RAG on Spider, and Reflexion-style memory wins BIRD (51.24%) at roughly 1.3x the token cost; the most consistent single benefit comes from schema-local memory (removing cross-database retrieval costs 0.93 pp on Spider, 2.74 pp on BIRD).

## 核心贡献

- **将 Text-to-SQL 修复形式化为"因果情景记忆"问题**：当前查询只能检索来自更早、已终止的"已完成 episode"的记忆，当前未完成的本地轨迹不进入全局检索池，从而严格隔离训练-free 跨查询经验复用与参数更新。
- **设计双极性在线记忆结构**：每条记忆以 ⟨context, failure-type, transformation, polarity, provenance⟩ 表示，正极性记录 oracle 确认的 "failed-to-correct" 转移，负极性仅记录未解决 episode 的"最后失败方向"（不臆断失败原因）；每个完成的 episode 至多贡献一条记忆。
- **提出错误类型条件化的混合检索**：用一个确定性规则分类器（基于可观测 DBMS 文本）将失败分为 RESULT MISMATCH / SCHEMA LINKING / AGGREGATION / FILTER/VALUE / EXECUTION / SYNTAX / UNKNOWN 七类，作为检索先验；候选先用极性与类型筛选，再用 0.75×dense + 0.25×BM25 排序，最多取 3 正 1 负。
- **在受控协议下做了一次诚实的消解实验**：固定初始预测、固定 K=7、固定 backbone，三种流序（seed 0/1/2）下用 query-cluster bootstrap 给出配对置信区间，明确指出 MERIT 未能稳定胜过无类型化的 Dynamic RAG。

## Key Contributions

- Reformulates feedback-driven Text-to-SQL correction as **causal episodic memory**: only memory entries from earlier finalized episodes (and different queries) are eligible for retrieval at position *t*, and global memory is updated only after an episode terminates — so the current query cannot peek at its own unfinished trajectory.
- Introduces an **online dual-polarity memory** that separately stores oracle-verified failed-to-correct transitions (positives, used as confirmed successful directions) and the final unsuccessful direction of unresolved episodes (negatives, used only as observed-failed warnings), with at most one entry written per finalized episode.
- Builds an **error-type-conditioned hybrid retriever**: a deterministic rule-based classifier (operating purely on observable DBMS error text and execution status) tags each failure with a coarse type used as a retrieval prior; candidates are then ranked by a fixed 0.75 dense + 0.25 BM25 mixture, with a same-polarity/same-type fallback when the typed pool has fewer than 3 entries.
- Provides a **rigorous, honestly-reported controlled study** over three stream orders, holding the cached initial prediction, frozen Qwen2.5-7B-Instruct backbone, K=7 budget, and execution feedback fixed across Iterative, Dynamic RAG, Reflexion-style, and MERIT, and reports paired query-cluster bootstrap confidence intervals rather than only point estimates.

## Methodology

MERIT runs as an online correction-accumulation loop. At stream position *t* the agent receives a question *q_t*, schema *S_t*, optional BIRD evidence, a database *D_t*, and a shared greedy-decoded initial SQL *y_t^(0)* produced once and reused by every method (isolating the effect of repair strategy). Initial accuracy of this shared predictor is 58.90% on Spider (609/1,034) and 38.40% on BIRD (589/1,534); queries initially correct are finalized without creating memory.

For each initially incorrect query the system enters a repair loop bounded by K=7 generations:

1. **Deterministic failure classification.** A rule-based classifier maps the current failing query *y_t^(k-1)* to one of {RESULT MISMATCH, SCHEMA LINKING, AGGREGATION, FILTER/VALUE, EXECUTION, SYNTAX, UNKNOWN} using only execution status and observable DBMS error text. The label is recomputed after every unsuccessful revision and serves only as a retrieval prior (no AST inspection, no semantic diagnosis such as wrong joins).

2. **Causal, type-conditioned candidate construction.** For each polarity *p ∈ {+, −}* the legal pool *L_t,p* is restricted by temporal (sourcePos < t), query (sourceQuery ≠ q_t), and database constraints; its same-type subset *T_t,p* is used when |T_t,p| ≥ 3, otherwise the full legal same-polarity pool is used.

3. **Hybrid lexical-dense ranking.** Dense and BM25 scores are independently min-max normalized within each polarity pool; the final score is r(x,u) = 0.75·b_d + 0.25·b_bM25. At most 3 positive and 1 negative entries are retrieved, with positives shown as confirmed successful directions and negatives as observed-failed directions (reference SQL/rows never exposed to the model).

4. **Repair generation.** A single user message containing question, schema, current SQL, attempt status, DBMS error, predicted error type, local history, and retrieved precedents is sent through the frozen backbone's chat template (no separate system prompt, no local verbal reflections in MERIT Full); greedy decoding produces one revision, which the benchmark oracle evaluates.

5. **Episode finalization and memory update.** On success at step *k\**, MERIT stores one positive entry from the final failed-to-correct transition; on budget exhaustion it stores at most one negative entry from the last direction attempted. The entry becomes visible to later queries only at position t+1.

The paper also evaluates a **type-reliability-aware variant** that applies hard type filtering only to predefined high-reliability types (SYNTAX, SCHEMA LINKING, EXECUTION) and otherwise uses type agreement as a soft +0.10 ranking bonus — without learning any confidence score.

## Results & Highlights

- **Spider execution accuracy**: MERIT reaches 69.79 ± 0.59% versus 66.34 ± 0.14% for stateless Iterative repair, a paired Δ of **+3.45 pp** with 95% CI **[+1.97, +4.96]** (clear evidence — interval excludes zero). MERIT ties untyped Dynamic RAG at 69.79% and beats Reflexion-style (68.38%) by +1.42 pp but with interval [−0.19, +3.03] crossing zero.
- **BIRD execution accuracy**: MERIT reaches 48.44 ± 0.46% versus 47.35 ± 0.04% for Iterative, a paired Δ of **+1.09 pp** with interval **[0.00, +2.17]** (weaker evidence — lower bound touches zero). Reflexion-style is the strongest BIRD method at 51.24%, with MERIT − Reflexion interval [−4.15, −1.46]; MERIT leads Dynamic RAG by only 0.28 pp.
- **Repair productivity on Spider**: MERIT repairs 112.7 failures on average vs. 77.0 for Iterative, 98.0 for Reflexion-style, and 112.7 for Dynamic RAG; MERIT also has the lowest trajectory length (5.611 steps/failure) and oscillation rate (31.95%).
- **Inference cost trade-off**: on Spider MERIT uses 5.274M tokens / 3,419 calls vs. 2.529M / 3,619 for Iterative; on BIRD, 17.569M tokens / 7,325 calls vs. 9.325M / 7,429 for Iterative. Reflexion-style is most expensive (22.407M tokens, 13,568 calls on BIRD). MERIT is cheaper than Reflexion-style but **does not reduce absolute token use** relative to stateless repair because retrieved memories lengthen each prompt.
- **Schema-local memory is the most consistent ablation win**: restricting retrieval to other databases drops accuracy by **−0.93 pp on Spider and −2.74 pp on BIRD** — the single clearest effect across all ablations, highlighting the value of same-database join paths and domain terminology.
- **Negative memory contributes only modestly**: removing it costs −0.13 pp on Spider and −0.09 pp on BIRD, indicating verified corrections carry most of the useful signal.
- **Type-conditioning is dataset-dependent**: removing the type filter lowers Spider by 0.58 pp but raises BIRD by +0.13 pp; the type-reliability-aware variant gains +0.39 pp on Spider but loses 0.20 pp on BIRD — both CIs cross zero.
- **Deterministic classifier operating regime**: population-weighted accuracy ~48% on both Spider (Macro-F1 0.317) and BIRD (Macro-F1 0.355); failure composition differs sharply — Spider is 84.71% RESULT MISMATCH vs. BIRD's 57.99% RESULT MISMATCH + 33.65% SCHEMA LINKING — which explains why schema-linking-aware typing helps less on BIRD.

## Authors & Credibility

Authors are from MBZUAI (Khang Nhat Hoang Vo, corresponding) and HCMUT/VNU-HCM (Tam Minh Chu, Anh Trac Duc Dinh, Thuyen Vinh Ha Bui, Tho Quan). The work is positioned not as a state-of-the-art Text-to-SQL claim but as a controlled study of cross-query memory design, and the experimental protocol reflects that discipline: shared cached initial predictions, identical frozen backbone (Qwen2.5-7B-Instruct), identical K=7 budget, three stream orders, and a query-cluster bootstrap that preserves per-query outcomes across seeds. The error-classifier characterization (Table 5) and the explicit acknowledgment that MERIT does not reduce total token use are signs of careful, non-cherry-picked reporting. The framing of "causal" as temporal memory availability (not absence of supervision) is clearly stated up front to avoid overstating autonomy.

## Critical Assessment

- **Novelty**: Moderate. Cross-episode memory (Reflexion, ExpeL), retrieval-augmented Text-to-SQL (DAIL-SQL, ACT-SQL), and execution-guided repair (Self-Debugging, CRITIC) all pre-exist; the genuinely new piece is the joint organization of repair memory by *both* outcome polarity and a coarse deterministic error type, plus the strict causal-availability constraint. The honest finding that this organization ties an untyped Dynamic RAG undercuts the headline framing.
- **Rigor**: Strong on internal validity — shared initial predictions and paired bootstrap intervals are exactly the right controls and are rarely seen in this subarea. Weak on the classifier: the deterministic labeler has only ~48% accuracy and Macro-F1 ≈ 0.32–0.36, and the dominant RESULT MISMATCH bucket lumps together many distinct semantic errors (wrong joins, wrong ordering, wrong aggregation), which the authors admit limits how strongly the type-conditioning results can be interpreted.
- **Reproducibility**: Reasonable. stdlib-style claims, named backbone (Qwen2.5-7B-Instruct), fixed retrieval weights (0.75/0.25), fixed K=7, public benchmarks (Spider/BIRD dev sets), and prompt templates + memory serialization provided in appendices B–D. However, no code release is mentioned, the three stream-order seeds are reported only as mean ± std without per-seed tables, and the dense encoder used for retrieval is unspecified in the main text.
- **Significance**: The Spider gain is real and well-evidenced, but the BIRD gain is borderline and MERIT is dominated by Reflexion-style there. Because MERIT is not cheaper than stateless repair in total tokens, the practical deployment story (lower-cost agent improvement) is weaker than the abstract implies.
- **Red flags**: (1) The abstract leads with the headline Spider/BIRD deltas but buries that MERIT is **not reliably separable from untyped Dynamic RAG on either benchmark** — a reader skimming the abstract would over-estimate the contribution of error typing and polarity separation. (2) The "causal" branding is somewhat oversold given that the setting still uses a denotation-level oracle for termination and polarity assignment, which is stronger feedback than most production databases provide — a limitation the authors themselves flag. (3) Only one backbone (7B) and only dev sets are evaluated, so generalization to other model scales, multilingual/conversational Text-to-SQL, or production schemas with security constraints is unestablished.

## Strengths

- Exemplary experimental hygiene: shared initial SQL, frozen backbone, identical budget, three stream orders, and paired query-cluster bootstrap CIs make the claims falsifiable rather than anecdotal.
- Honest negative findings are reported inline (MERIT ties Dynamic RAG; Reflexion wins BIRD; classifier accuracy ≈ 48%; no token-cost reduction) instead of being buried.
- The schema-locality ablation isolates a genuinely actionable insight: same-database repair patterns matter far more than question-similarity or coarse failure type, especially on BIRD's larger domain-specific schemas.
- The deterministic classifier is cheap, interpretable, and explicitly characterized — including its 48% accuracy — so readers can judge how much to trust the type-conditioning results.

## Limitations

- Requires a **denotation-level correctness oracle** during repair, which is stronger than the execution-error-only feedback available in most deployed databases.
- Evaluated with a **single frozen backbone** (Qwen2.5-7B-Instruct) on **Spider/BIRD dev sets only**; no multilingual, conversational, or production-schema experiments.
- The deterministic error classifier is **coarse (~48% accuracy)**, and RESULT MISMATCH conflates many semantic errors; this caps how much type-conditioning can help and may explain the BIRD null result.
- Three stream orders capture only a limited slice of order sensitivity; memory contents depend on query order, so results may not generalize to other orderings.
- MERIT is **not cheaper than stateless repair** in total tokens — retrieved memories lengthen each prompt enough to offset the slight reduction in LLM calls.
- Retrieval weights, memory allocation (3 pos / 1 neg), and fallback policy are fixed rather than tuned per benchmark, so no comprehensive sensitivity study is provided.

## Relevance

This paper directly targets the user's interest in LLM agents, iterative/self-correction, and retrieval-augmented generation, with concrete Text-to-SQL evidence on Spider/BIRD. Its careful causal-memory formulation and paired statistical analysis also make it a useful methodological reference for anyone building memory-augmented repair agents beyond SQL.

## Questions for Further Exploration

- Would replacing the coarse deterministic classifier with a learned/calibrated labeler (or simply using the model's own error diagnosis) close the gap between hard type filtering and the type-reliability-aware variant?
- How does MERIT's benefit scale with backbone size — does the cross-query memory advantage grow or shrink relative to stateless repair on Qwen2.5-32B/72B or on a reasoning model?
- Since schema-local experience dominates the ablation, can a single cross-database memory store be replaced by per-database indices with negligible loss, and what does that imply for cold-start on unseen schemas?
- Is the Spider gain (clear) vs. BIRD gain (borderline) difference driven by failure-mix composition (84.71% vs. 57.99% RESULT MISMATCH), by schema size, or by the presence of external evidence in BIRD — and would a BIRD-specific retrieval policy recover the gap to Reflexion-style without its token cost?
- Can the causal-availability constraint be relaxed to allow retrieval from *partial* earlier trajectories once they have been verified step-by-step, and does that change the polarity/separation trade-offs the paper reports?
