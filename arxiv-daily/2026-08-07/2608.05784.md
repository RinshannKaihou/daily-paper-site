> **一句话总结：** 本文提出一个零模型、确定性的"活动帧(Activify Frames)"编译器，将本地采集的屏幕活动流(快照+输入事件)分段为带类型、可审计的活动帧，使一天的原始采集压缩成可直接放入系统提示的上下文块(86× token 缩减，68 ms 编译)，并在自建 61 天语料上将 Agent 回答用户日活动问题的准确率推到 98.4%；同一编译器还把"被动的、委派前的人类活动"读出为 Agent 成本模型一直假设但从未测量的两个参数——Routine Overhead Ratio R(60–343×)与桌面例行重复率 h(样本内 9.0%、样本外 7.7%)。

> **TL;DR:** A single-author paper introduces a deterministic, zero-model compiler that turns passively captured screen activity into typed "activity frames" for agent episodic memory: on the author's own 61-day / 128,756-frame corpus it shrinks one day of raw capture (126,812 tokens) into a ~1,469-token prompt block in 68 ms (86× reduction at zero inference cost), and lets an agent answer 64 oracle-graded questions about the user's day at 98.4% accuracy (Wilson 95% CI 91.7–99.7%) at both Sonnet 4.5 and Opus 4.5 tiers — versus 66–80% for an LLM summary of the same capture and 82–91% for raw rows; on the busiest day the raw/summary baselines are infeasible (257k tokens overflow the context window) while the ~2k block still works. The same compiler reads two demand-side cost parameters from pre-delegation human activity: a Routine Overhead Ratio R of 60× (guarded plan) to 343× (minimal script) and a delegable recurrence h of 9.0% in-sample / 7.7% out-of-sample, implying a realistic all-fleet token saving ceiling near 8%.

## 核心贡献

- **两层活动帧 Schema(测量层 vs. 推断层)：** 标准文档每个字段都可由确定性代码从采集数据推出(无意图标签)；推断内容(如任务标签)只能放在命名空间化的 `inferred` 块里，必须带 confidence 标签和证据指针，剥掉它仍是一份完整的纯测量文档。文档强制包含 `blind_spots` 列表与覆盖缺口(>300 s 的 gap)，把"未采集"明确标注为未知而非静默。

- **六条零学习分量的编译规则：** 驻留计费 `min(Δt, 90 s)`、会话 gap(>300 s 断帧)、flicker 合并(A→B→A，B≤20 s 折叠并把 B 记为中断而非丢弃)、最近快照重归因(修复陈旧 application 标注)、坐标点击解析(精确包含→±40 px 容差→屏幕分区三级回退)、分层 URL→实体类型化(20+ 站点解析器 + 总回退保证 URL 不丢)。

- **开放参考实现：** 零运行时依赖的 Python 编译器，配套按需 provisioned 的本地采集引擎(SQLite，全设备内)、CLI、以及手写的 stdio JSON-RPC **Model Context Protocol (MCP)** 服务器，向任意 MCP 客户端暴露 `get_context / get_activity / get_day_summary / get_patterns / get_communications / get_steps` 六个工具。

- **单用户 61 天语料上的实证刻画：** 86× 上下文压缩(126,812 → 1,469 tokens)、68 ms 全天编译、字节级可复现、81.3% 的 URL 得到非通用类型化、活动时长分布(中位 0.5 min，但 52% 的亚分钟帧是单快照 transits；排除后中位 0.9 min，与中断科学的"工作 sphere"一致)。

- **下游 QA 基准(独立 SQL oracle，64 题，两档模型)：** 编译块在 Sonnet 4.5 与 Opus 4.5 上都到 98.4%、duration error 7.3%；同一档模型读 raw rows 是 82.1%/91.1%，读 LLM summary 是 66.1%/80.4%。更关键的是读编译块时两档模型不可区分——便宜模型借此追平 frontier 模型。

- **需求侧成本工具：** 把"委派前的人类被动活动"读成 Agent 成本模型一直假设却没人测过的两个参数——Routine Overhead Ratio R(模型化分子 + 测量分母，guarded plan 60×、minimal script 343×)与 delegable recurrence h(样本内 9.0%、时间 held-out 7.7%)；并给出一个参数化 replay 执行器，在 guard-matched hit 上以 0 模型 token 现场跑通了一次两步例程(打开 compose、键入草稿，未实际发送)。

## Methodology

The work is a **systems/compilation paper**, not a learning paper. The pipeline is deterministic code with no learned component in the memory-construction path (the only learner anywhere is on-device OCR at capture time, which the determinism claim explicitly does not cover back to pixels).

**Capture engine (input):** event-driven with a ~30 s heartbeat. A snapshot row is stored on interaction, on screen/application change, and after ~30 s of no input (heartbeat rows are 19% of the corpus, keeping input-free stretches like reading/watching credited). Each monitor records its own stream; median intra-monitor gap 6.1 s, 90th pct 30.7 s. Rows carry timestamp, application, window title, URL (for browsers), and input events (keystrokes, clicks, clipboard, element-tree signatures).

**Segmentation (Algorithm 1):** one pass over each monitor's stream, grouping consecutive snapshots sharing the same `(application, site)` key; dwell credit per frame is `min(Δt, 90 s)`; a gap > 300 s closes the frame and becomes a candidate coverage gap (no dwell across it). A second pass performs flicker merge: pattern A→B→A where B's wall ≤ 20 s and no session gap intervenes collapses B into A, but B is **recorded as an interruption with its measured seconds** and its time is not added to A's active duration (nothing hidden, nothing double-counted).

**Enrichment (three reliability repairs, all deterministic):** (1) stale-attribution repair — each event re-attributed to the temporally nearest snapshot via binary search, attribution distance kept in ms; (2) anonymous click resolution — coordinate clicks resolved against the snapshot's element tree by exact containment → ±40 px tolerance ring → coarse screen-zone, each tagged `exact/tolerance/zone/unresolved`; (3) keyboard-layout mismatch repaired via operator-supplied translation map (identity by default, never inferred).

**Entity typing:** layered URL parsers — bespoke host parsers (>20, covering professional networks, code hosting, search, docs, mail, video, social, events, dashboards, AI chat, local dev) → generic search-parameter detector → subdomain-and-path heuristic → total fallback (generic page reference with domain). 81.3% of 5,120 distinct URLs get a non-generic type across 46 kinds; coverage grows one pure function per site (reviewable line by line), never by a learned component.

**Two-tier schema enforcement:** tier-1 measured fields only; tier-2 inferred content must live in a namespaced `inferred` block with a confidence tag from {high, medium, speculative} and named evidence. Stripping tier-2 always leaves a valid measured document. A schema-level privacy rule excludes typed-text content by default (counts are fine, content needs operator opt-in).

**Replay/R as instrument:** recurring action n-grams (3 ≤ k ≤ 60, ≥3 recurrences, ≥2 distinct named targets — the two-target rule prevents degenerate single-symbol repeats) are mined; for each routine the compiler emits two deterministic artifacts — a guarded skill plan (per-step typed action with expected-element/role/application guards, median 247.5 tokens) and a minimal replay script (median 40 tokens). `R = Cagent(k)/Creplay(k)`, where the numerator is *modeled* (screenshot-driven agent: `k·(wh/750 + 350 + 180)` tokens ≈ 2,500/step at 1512×982) and the denominator is *measured* via tiktoken cl100k_base.

**Evaluation methodology:** downstream QA uses an **independent SQL oracle** (60 s-capped inactivity-timeout dwell, deliberately not the compiler) over 8 selected days; 64 generated questions across 5 categories (dominant app, minutes, distinct apps, pairwise ranking, domain visited/start time) + 16 absent-fact probes; graded at fixed tolerances (numeric within 30%, times within 45 min); two Claude tiers (Sonnet 4.5, Opus 4.5), one answering pass each, temperature/seed unpinned.

## Results & Highlights

- **Context compression (Section 6.1, Figure 4):** For one representative full day (2,066 snapshot rows), the raw-row JSON serialization costs **126,812 tokens**; the compiled schema-v1 document costs **34,815 tokens (3.6× reduction)**; the compact context block costs **1,469 tokens — an 86× reduction**, small enough to include in every system prompt. Both compiled forms are produced with **zero model calls**.

- **Downstream QA (Section 6.2, Table 3), 8 days / 64 oracle-graded questions:** Activity-frames block reaches **98.4% accuracy and 7.3% duration error at BOTH Sonnet 4.5 and Opus 4.5**; raw rows reach **82.1% / 39.7%** (Sonnet) and **91.1% / 25.7%** (Opus); LLM summaries reach **66.1% / 135.7%** (Sonnet) and **80.4% / 25.2%** (Opus). The block is the **only representation that runs on all 8 days** — on the busiest day raw rows serialize to **257k tokens, overflowing the context window**, so both raw and summary baselines are infeasible while the ~2k block is unaffected.

- **Determinism / latency (Sections 6.3, 7.5):** Full-day end-to-end compile (segmentation + enrichment + entity typing + emission) takes a **median of 68 ms** (range 65–72 ms) on Apple Silicon. Re-compiling any window twice produces **byte-identical** documents once the `generated_at` timestamp is excluded (certified by `certify_ivm.py` over the 51-active-day corpus). Compile cost is **O(|Δ|)**: mean over the second half of the corpus is 0.86× the first half (216.4 ms vs 251.8 ms).

- **Routine Overhead Ratio R (Section 7.2, Table 4):** Against the guarded skill plan the compiler actually emits, median **R_inject = 60×** (IQR 59–62×, across 20 most frequent action routines; plans compile in median 0.5 ms at zero token cost). Against the minimal replay script, median **R_info = 343×** (IQR 297–390× action granularity; recurrence-weighted mean 337×; min–max 167–509×). The ceiling is robust to the two likely cherry-picking objections: it rises mildly with routine length (301× at k=3–4 → 401× at k≥16) and re-pricing the numerator across resolutions stays in a **259×–425× band**. URL granularity ceiling median is **198×**.

- **Recurrence h (Section 7.4):** Raw rate h_raw = **83.1%** of action steps inside any recurring n-gram, but the **delegable** rate h_specific = **9.0%** (action granularity; 13.1% URL granularity) — the gap is the difference between "the keyboard repeats" and "the work repeats." Temporal holdout (train on first 40 active days, test on held-out 11 days): out-of-sample hit rate **7.7%** vs in-sample 8.6%. The honest all-fleet ceiling saving is therefore **h·(1−1/R_info) ≈ 7.7%**.

- **Modeled three-arm comparison (Section 7.3), 20 routines at Sonnet list rates:** arm A (memoryless re-derive) **32.8 Mtok / $125.81**; arm B (plan-in-context) saves **83.3%** ($20.96, 6.0× per-occurrence); arm C (parametric local replay) saves **40.8%** ($74.46, 1.7×). On a guard-matched step, local replay recovers **~99%** (exactly 99.7% at R_info=343) of that step's re-derivation cost.

- **Live replay proof-of-concept (Section 8.4):** One owner-authorized live execution of a compiled two-step routine (open compose, type a draft; nothing posted), matched to a natural-language request by a small local model and executed in a live authenticated browser session with **zero model tokens at execution**, both steps grounded by a11y role+name. On a wrong page the same plan grounded nothing and performed zero actions (intended fail-safe).

## Critical Assessment

- **Novelty:** Genuine and well-positioned. The "missing middle" framing is accurate: every 2025–2026 competitor (MIRIX, FOCAL, ProAgentBench, SummAct, OmniQuery) puts a model inside the memory-construction loop, inheriting per-run cost, non-determinism, and hallucination risk. Quarantining interpretation into an evidence-linked tier-2 while keeping tier-1 a pure projection of capture is the real contribution, and the measured/inferred boundary as a structural defense against memory poisoning (citing [35]) is a non-trivial trust property. The demand-side reading of R and h — parameters that cost frameworks (FrugalGPT, Cost-of-Pass, AI Agents That Matter, HAL) *assume* but never measure on pre-delegation human activity — is a clean reframing.

- **Rigor (strong):** The independent SQL oracle (60 s-capped, deliberately not the compiler) prevents circular evaluation. The author validates the compiler against the oracle *before* using the oracle to grade competitors, reports the multi-monitor divergence (435.8 vs 346.1 min, 26%) rather than averaging it away, and explicitly excludes two question types (longest-session, per-profile recall) with the reason on the books. The 99% replay ceiling is correctly reported as a *per-covered-step* ceiling, not a fleet saving, and the realized arm-C saving (40.8%) is honestly attributed to the 0.415 guard-coverage deopt. The "specificity rule" (≥2 distinct named targets) to prevent granularity inflation of h is a real methodological contribution, and the gap h_raw 83.1% → h_specific 9.0% is reported rather than the inflated headline.

- **Rigor (weak — the central external validity problem):** This is a **single-user study (the author's own machine, 51–61 days)**, stated plainly but never mitigated within the paper. Every systems number (86× compression, 68 ms compile, 81.3% typing coverage, the 0.9-min median frame, R=60–343×, h=9.0%/7.7%) is a property of one professional's desktop work on one platform (macOS, Apple Silicon). Entity typing coverage (81.3%) is measured on 5,120 URLs dominated by this user's sites; a different role (e.g., a designer on Figma/Windows, a trader on Bloomberg) could shift it materially. The downstream QA benchmark evaluates **two Claude tiers only, one answering pass each, temperature/seed unpinned** — so the non-deterministic baseline numbers (raw 82–91%, summary 66–80%) vary across re-runs while the block's 98.4% is structurally fixed; a single unpinned pass slightly flatters the deterministic contender. No GPT/Gemini comparison is run.

- **Reproducibility:** Excellent on the deterministic half. Byte-identical output is a *certified* property (CI-checkable), and the capture corpus is frozen. The cost/measurement half is reproducible in mechanism (the compiler, the n-gram miner, the token counter are all released) but **not in population** — no second user, no public dataset replication. The live replay "confirmation" is a single two-step routine seeded from live a11y names (the click-level grounding of the recorder is "still under validation"), the guard-miss deopt path was not exercised, and the full live three-arm billing is reserved. Match precision (q) is acknowledged as <1 because typing is ~82% accurate, but q is not measured directly — it propagates into fleet saving as an unbounded factor.

- **Significance:** If the determinism and trust properties hold across users, this is a plausible infrastructure primitive (the MCP server makes it immediately consumable by Claude Desktop / any MCP client). The R and h reframing is conceptually valuable for the agent-cost literature regardless of multi-user validation. But the headline "all-fleet token ceiling near 8%" is a single-user number and should not be cited as a population estimate.

- **Red flags:** (1) The 83.3% three-arm saving is **modeled, not billed**, and the one live in-loop comparison against an a11y-tree agent saved only ~14% — the paper says so openly, but a careless reader could still quote 83.3% as measured. (2) Screen presence ≠ attention: heartbeat-terminated intervals carry **45% of all credited active time**, and uninterrupted heartbeat runs reach 42 minutes, so "active minutes" includes time the user stepped away from an awake display; the dwell cap does not bound this. (3) Multi-monitor double-counting (27% of captured minutes) inflates per-application ledgers. (4) Single author, single user, no peer review at time of posting — the claims rest entirely on the released harness and the author's own disciplined self-reporting.

## Strengths

- Deterministic, zero-model compilation makes episodic memory free to rebuild, safe to cache, mechanically auditable, and CI-testable — a structurally different proposition from any LLM-summarization competitor.
- The measured/inferred two-tier boundary is a genuine trust contribution: it quarantines hallucinated/poisoned labels into a strippable namespace with evidence pointers, addressing emerging memory-poisoning and membership-inference attack surfaces.
- Honest accounting throughout: three explicit disciplines prevent double-counting (never stack R with the 86× compression; never combine with cache discounts; modeled numerators flagged as ceilings). The 83.1% → 9.0% specificity correction and the temporal holdout are exemplary.
- The independent SQL oracle (deliberately not the compiler) + grading at fixed tolerances + release of the full harness is a clean evaluation design.
- Open implementation (MIT), MCP server, CLI, and certification harness lower the adoption barrier to zero for any MCP-capable agent.
- The downstream QA result — a mid-tier model reading the block matches a frontier model, and the block is the only representation feasible on the busiest day — is the most policy-relevant finding for cost-conscious deployment.

## Limitations

- **Single-user, single-machine, single-platform corpus** (author's own, 51–61 days). No multi-user replication, no public-dataset second subject; all absolute magnitudes (compression, latency, h, R) are this user's properties, not population estimates.
- **Modeled numerator and modeled three-arm dollars** — R's numerator is what a memoryless screenshot-driven loop would spend under stated per-step budgets, not a billed figure; the only live in-loop comparison saved ~14%, so the 83.3% plan-in-context saving is an upper bound.
- **Single QA pass, two Claude tiers, temperature/seed unpinned** — statistical strength of the comparison is limited; the harness must be rerun with confidence intervals and other model families.
- **Screen presence ≠ attention** — 45% of credited active time is heartbeat-terminated; dwell measures tenure on an awake display, not engagement. Multi-monitor days double-count (27% of captured minutes).
- **Reference implementation reads one capture engine's DB layout** — schema is engine-agnostic but each new source needs an adapter.
- **Measured tier is structurally silent on intent** — it reports two profile views and a people search, never "prospecting"; intent needs opt-in tier-2 inference.
- **OCR is a model** — byte-level reproducibility holds from stored OCR text forward, not back to pixels; a different OCR model or re-scan could yield different text.
- **Live replay confirmation is one two-step routine** with click-level grounding still under validation; guard-miss deopt path unexercised; full live billing reserved.

## Questions for Further Exploration

- How do R and h change across roles and platforms (designer on Figma/Windows, trader on Bloomberg, dev on Linux)? Is the 9.0% delegable recurrence a stable cross-population constant or an artifact of one professional's task structure?
- Can the deterministic tier-1 be extended with a tier-2 inference layer whose confidence tags are *calibrated* against the oracle, so that inferred task labels carry honest uncertainty rather than a {high, medium, speculative} ordinal?
- The live in-loop comparison against an a11y-tree agent saved only ~14% vs the modeled 83.3% — what is the structural gap between modeled screenshot-baseline cost and actual a11y-grounded agent cost, and does prompt caching close it?
- How does the activity-frames representation interact with long-context degradation (Lost in the Middle, [9])? Does the 1,469-token block's benefit come from compression alone or from being small enough to avoid the "middle" entirely?
- The two-target specificity rule separates "keyboard repeats" (83.1%) from "work repeats" (9.0%) — how sensitive is h_specific to the n-gram window (3 ≤ k ≤ 60) and to the 90 s inter-action session cut? Is 9.0% robust or an artifact of this user's routine granularity?
- Could the measured/inferred boundary be enforced cryptographically (e.g., signed tier-1 hashes) so a compromised tier-2 tool provably cannot inject labels as fact, strengthening the memory-poisoning defense beyond "strippable namespace"?
