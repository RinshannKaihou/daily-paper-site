> **一句话总结：** SkillHEX 是一个面向测试时按需演化的智能体技能闭环框架，通过把可证伪的失败假设转成可执行测试来生成稠密诊断证据，再用证据引导的持久化技能补丁树搜索来平衡探索与利用，在 SkillsBench 的 87 个任务上以 GPT-5.3-Codex / Claude Opus 4.7 取得 55.9% / 57.9% 的通过率，超越最强自演化基线 9.5 / 8.5 个百分点并高于人工技能。

> **TL;DR:** SkillHEX tackles test-time skill evolution for LLM agents under sparse binary rewards by coupling a hypothesis-driven self-verifier (which turns falsifiable failure hypotheses into executable tests replayed over cached outputs) with an evidence-guided PUCT-style tree search over persistent skill-revision branches. On SkillsBench's 87 tasks it reaches 55.9% (GPT-5.3-Codex) and 57.9% (Claude Opus 4.7) pass@5, beating CoEvoSkills by +9.5/+8.5 pp and human-curated skills while using 18.0% fewer tokens than the strongest baseline.

## 核心贡献

- **假设驱动的自验证器（Hypothesis-Driven Self-Verification）：** 把任务级失败（仅给出 0/1 稀疏奖励）分解为一组可证伪的失败原因假设 $h_i=(d_i,q_i,\sigma_i,C_i)$，再为每个假设生成可执行测试，回放到已缓存的历史执行输出上，从而在不消耗额外环境尝试的前提下得到稠密的"语义梯度"。
- **动态证据库（Dynamic Evidence Bank）：** 维护一个证据矩阵 $M[v,j]=\phi(c_j,Y_v)$，新补丁自动扩展行、新测试自动回放扩展列；被驳斥的假设触发列剪枝，从而既稠密又自适应去噪。
- **证据引导的持久化补丁树搜索（Evidence-Guided Tree Search）：** 把演化策略变成对技能补丁树的 PUCT 搜索，用反射智能体给出的序排名作先验 $P(v,u)$，用 max-backup 估值 $Q(v)$，避免贪婪就地改写陷入局部最优，并保留可回访的替代分支。
- **跨主干一致且高性价比：** 在 GPT-5.3-Codex 与 Claude Opus 4.7 两种异构模型上均超越自演化基线和人工技能，同时比最强基线 CoEvoSkills 少用约 18% 的 token。

## Key Contributions

- A **hypothesis-driven self-verifier** that converts sparse binary task failure into falsifiable hypotheses, synthesizes executable public tests for each, and replays them over cached agent outputs to yield dense, self-supervised diagnostic evidence (semantic gradients) without spending extra executor attempts.
- A **dynamic evidence bank** that maintains an evolving evidence matrix: new skill patches add rows (every existing test is replayed on the new output) and new tests add columns (retrospective replay over all historical executions); refuted hypotheses trigger targeted column pruning, keeping the signal both dense and self-correcting.
- An **evidence-guided PUCT-style tree search over persistent skill-revision branches**: reflection provides an ordinal policy prior $P(v,u)$ from candidate patch rankings, a max-backup value $Q(v)$ aggregates the best subtree evidence, and a PUCT rule (Eq. 10) balances exploitation of supported edits with exploration of plausible alternatives — explicitly avoiding the greedy in-place "exploitation trap" of prior self-refinement methods.
- **Complementary, robust components**: ablation shows removing self-verification costs 11.1 pp and removing the patch tree costs 6.8 pp on GPT-5.3-Codex, confirming each contributes distinct gains; initialization from no-skill, LLM-skill, or human-skill all converge to strong results.

## Methodology

SkillHEX is a closed-loop framework for **on-demand test-time skill evolution**, formalized as maximizing $G_T(S)=\mathbb{E}_{\tau\sim P_{\text{exec}}(\cdot|T,S;\pi_{\text{agent}})}[V_\xi(Y(\tau))]$ over an admissible skill space $\mathcal{S}$, under three constraints: (1) only a binary terminal reward from a hidden verifier $V_\xi$, (2) a strict budget of evolution iterations (five), and (3) no training/validation set. The agent policy $\pi_{\text{agent}}$ conditions on the task, the trajectory history, and the current skill $S$; the evolution policy $\pi_{\text{evo}}$ iteratively revises $S$.

To break the **exploitation trap** caused by sparse rewards, the framework's first core component is **Hypothesis-Driven Self-Verification** (Section 3.1). A reflection agent maintains a set of hypotheses $H_k=\{h_i\}$, each a tuple `(description, target behavior, lifecycle state, linked tests)`. Three operators drive hypothesis lifecycle: **Add** (a new falsifiable claim on a distinct failure surface), **Refine** (narrow an existing claim), and **Refute** (discard a wrong/non-discriminating claim). For each active hypothesis the self-verifier's **generator** synthesizes executable public tests (using only the task instruction, public inputs, and restored answer artifacts — never hidden oracles); a **rule-based validator** checks syntactic correctness and executability, returning defective tests for regeneration. Test outcomes populate a **dynamic evidence bank**: $M[v,j]=\phi(c_j,Y_v)\in\{0,1\}$ for every evaluated node $v$ and validated test $c_j$, where $\phi$ runs the test against the cached terminal output files $Y_v$. The matrix expands symmetrically (Eq. 6): a new patch replays all existing tests (new row), a new test replays over all cached outputs (new column). When a hypothesis is refuted, its now-obsolete tests are pruned from $M$ (Eq. 7), preventing misleading self-bias from contaminating the gradient.

To address the **exploration constraint**, the second component is the **Evidence-Guided Tree Search** (Section 3.2). The state is a persistent **skill-patch tree** $G_k$ rooted at $S^{(0)}$; each node $v$ caches the agent's output files $Y_v$ and reward $R_v$. When expanding a node, the reflection agent proposes up to $K$ candidate patches, each conditioned on active hypotheses and accumulated evidence; instead of trusting uncalibrated LLM confidence, it provides an **ordinal ranking** $\rho_u$ converted to a softmax policy prior $P(v,u)=\exp[-\beta(\rho_u-1)]/\sum_w\exp[-\beta(\rho_w-1)]$ (Eq. 8). Crucially, **all valid children are preserved** — nothing is irreversibly pruned. Node evaluation uses a **hierarchical gating** mechanism: hard constraints (syntax, deterministic output format) must all pass before semantic metrics count, steering search toward fundamental errors first. The backed-up value uses **max-backup** $Q(v)=\max(s(v), \max_{u} Q(u))$ (Eq. 9) so failed exploratory branches do not penalize a strong parent. Selection follows a PUCT-style rule (Eq. 10): $u^*=\arg\max_u [\bar Q(u) + c_{\text{puct}}P(v,u)\sqrt{\max\{1,N(v)\}/(1+N(v,u))}]$, dynamically trading off evidence-supported branches against under-explored alternatives. The overall loop executes the selected skill, observes binary outcome, and on failure triggers reflection → self-verification → evidence-bank update → tree expansion.

## Results & Highlights

- **Overall on SkillsBench (87 tasks, 8 domains, pass@5 over 5 iterations, 3 seeds):** SkillHEX reaches **55.9±1.8%** with GPT-5.3-Codex vs. CoEvoSkills **46.4±0.7%** (+9.5 pp), SkillRevise **44.4±3.7%** (+11.5 pp), Skill Creator **39.5±1.8%**, No Skill **33.3±4.1%** (+22.6 pp), and Human **52.9±5.0%** (+3.0 pp). On Claude Opus 4.7 it reaches **57.9±2.4%** vs. CoEvoSkills **49.4±5.0%** (+8.5 pp) and Human **54.4±1.3%** (+3.5 pp).
- **Mathematics & OR domain:** the clearest win over human skills — SkillHEX scores **83.3%** (GPT-5.3-Codex) and **79.2%** (Claude Opus 4.7) vs. Human **50.0%** and **41.7%**, i.e. **+33.3 pp** and **+37.5 pp** respectively.
- **Office & White Collar:** SkillHEX beats Human by **+19.0 pp** (61.9% vs 42.9%, GPT) and **+21.4 pp** (71.4% vs 50.0%, Claude), domains characterized by interdependent multi-step workflows that benefit from preserving alternative skill branches.
- **Ablation (GPT-5.3-Codex, Table 2):** full SkillHEX **55.9±1.8%**; removing the self-verifier collapses pass rate to **44.8±2.0%** (−11.1 pp, down to SkillRevise level); replacing the patch tree with in-place refinement drops it to **49.1±1.3%** (−6.8 pp) — confirming self-verification is the larger contributor but both components are necessary.
- **Token efficiency (Table 3):** SkillHEX (full) uses **2,356.1K** tokens/task vs. CoEvoSkills **2,874.3K** (**18.0% fewer** tokens at higher accuracy); removing the patch tree and reverting to in-place refinement *increases* token use by 6.2% while *lowering* accuracy, indicating greedy refinement wastes compute on unproductive trajectories.
- **Initial-skill robustness (Fig. 3):** starting from no skill, SkillHEX still reaches ~51.7% (+17.2 pp over No-Skill), close to the LLM-skill init result (55.9%, +16.4 pp), and human-skill init reaches 73.6% (+20.7 pp) — strong initializations help but the framework can build useful skills from scratch.

## Authors & Credibility

The work is authored by a Microsoft-led team (Yuru Feng, Yaoqi Chen, Beidi Zhao, Qianxi Zhang, Xinjiang Wang, Jianan Lu, Zhirui Wang, Shusen Xu, Zengzhong Li, Qi Chen) with academic affiliations at UC San Diego, USTC, and University of British Columbia. They evaluate on the recent **SkillsBench** benchmark (Li et al. 2026a) — a purpose-built, controlled-evaluation suite that isolates the installed skill as the primary variable by holding base model, harness, task container, and verifier constant across methods, which directly matches the paper's on-demand test-time adaptation setting. Two LLM backbones from different families (GPT-5.3-Codex from OpenAI 2026, Claude Opus 4.7 from Anthropic 2026) are used, both with "medium" reasoning effort for executor, self-verifier, and reflection roles, and a custom lightweight harness isolates task success from framework-level interventions. All experiments are reported over **3 independent seeds with standard deviations**, and the prompt templates (reflection system prompt, self-verifier system prompt, assertion-strength taxonomy) are reproduced in the appendix — a level of operational transparency that supports reproduction. The framing as PUCT/Rosin(2011) + AlphaGo-style max-backup is technically literate and the related work cleanly separates text-space optimization from experience-based distillation.

## Critical Assessment

- **Novelty:** Genuine. The combination of falsifiable-hypothesis-driven test synthesis + a persistent skill-patch tree (rather than a transient reasoning trace) is a meaningful reframe of skill evolution as a search problem with replay-based dense reward, distinct from CoEvoSkills (surrogate co-evolution) and SkillRevise (trace-conditioned sequential revision). The evidence-matrix symmetric expansion idea is elegant.
- **Rigor of baselines — the main caveat:** the authors note that **CoEvoSkills' source code is not publicly available, so they reimplemented it from the paper's description**. This is a fairness risk for the headline +9.5/+8.5 pp deltas; a weak reimplementation would inflate SkillHEX's lead. No reimplementation-verification or author consultation is reported. SkillRevise is similarly close in performance to CoEvoSkills (44.4 vs 46.4 on GPT), which is a slightly surprising tie worth probing.
- **Single benchmark, small N:** All claims rest on SkillsBench's 87 tasks. No cross-benchmark validation (e.g., on ASB, MLE-bench, or a web-agent suite) is provided, so domain-generalization claims rest on one suite from the same broader research line.
- **Metric generosity:** Evolution methods are evaluated as **pass@5** (best of five iterations), while static baselines (No Skill, Skill Creator, Human) are reported at pass@1-equivalent. This structurally advantages any evolution method; the absolute "beats human skills" framing should be read under that caveat (human skills at pass@1 vs. evolved skills at pass@5).
- **Honest negative results (a strength):** the authors openly concede SkillHEX *falls short* of human skills in **Natural Science** (61.9 vs 76.2 GPT; 66.7 vs 81.0 Claude) and **Finance & Economics** (29.6 vs 37.0 GPT; 40.7 vs 51.9 Claude), and is notably weak on **Media & Content Production** on Claude (40.0 vs Human 66.7). They attribute this to a knowledge-acquisition bottleneck rather than a search limitation — a plausible, non-defensive explanation.
- **Missing ablations:** no sensitivity analysis on $c_{\text{puct}}$, $\beta$, $K$, or the evidence-round limit; no analysis of how often hypotheses are refuted vs. confirmed (which would quantify whether the refutation/pruning machinery actually fires); no held-out test of whether evolved skills *transfer* to unseen tasks in the same domain (the on-demand framing sidesteps this, but it limits the practical claim).
- **Red flags:** none severe. The use of very-recent closed models (GPT-5.3-Codex, Claude Opus 4.7, both 2026) means independent reproduction will be model-version-sensitive, and the appendix prompts reference `current_case_root` and machine-specific paths, indicating some harness coupling.

## Strengths

- Principled reformulation of sparse-reward skill evolution as replay-based dense evidence + tree search, with each design choice (max-backup, ordinal-ranking prior, hierarchical gating) clearly motivated and individually validated by ablation.
- Strong and consistent gains across **two model families** and across most of the eight SkillsBench domains, including substantial wins over human-curated skills in workflow-heavy domains (Math & OR, Office & White Collar).
- Better **token efficiency** than the strongest baseline (−18%) while achieving higher accuracy, addressing a practical deployment concern.
- Transparent reporting: 3 seeds with std, full prompt templates in the appendix, explicit baseline-implementation caveats, and honest domain-level negative results.

## Limitations

- Headline baselines depend on a **reimplementation of CoEvoSkills** (original code unavailable); the +9.5/+8.5 pp margin is therefore not directly verifiable.
- Evaluation is **pass@5 for evolution methods vs. effectively pass@1 for static baselines**, which structurally favors SkillHEX in the "beats human skills" comparison.
- **Single benchmark (SkillsBench, 87 tasks)**; no transfer/generalization test of evolved skills to unseen tasks, and no second benchmark to confirm cross-suite robustness.
- **No hyperparameter sensitivity** ($c_{\text{puct}}, \beta, K$, evidence-round cap) and no statistics on hypothesis-lifecycle events (refute rate, add rate), leaving the empirical behavior of the hypothesis machinery under-characterized.
- Skill evolution is **per-task / on-demand**: the paper does not demonstrate that evolved skills compose into a reusable library that improves future tasks, which is the longer-term promise of skill-based agents.
- Reliance on very recent closed-weight models (GPT-5.3-Codex, Claude Opus 4.7) makes reproduction model-version-fragile.

## Relevance

Highly relevant to research on self-evolving LLM agents and agent-skill libraries: it directly addresses the test-time adaptation / sparse-reward problem that limits autonomous skill maintenance, a central concern for building agents that improve from their own execution traces. The hypothesis-as-test + tree-search formulation is also methodologically transferable to broader LLM self-refinement and prompt-optimization settings.

## Questions for Further Exploration

- How sensitive is SkillHEX to $c_{\text{puct}}$, the ranking temperature $\beta$, the candidate cap $K$, and the evidence-round limit — and is there a regime where the patch tree degenerates back to in-place refinement?
- What fraction of proposed hypotheses are ultimately **refuted** vs. confirmed, and does refutation-driven pruning measurably reduce misleading gradients in practice?
- Do skills evolved on one SkillsBench task **transfer** to held-out tasks in the same domain, or does the on-demand setting produce narrowly overfit skills?
- How would SkillHEX perform on a second, independent agent benchmark (e.g., MLE-bench, ASB, OSWorld) under identical backbone and budget — does the +9.5 pp margin survive outside SkillsBench?
- Can the CoEvoSkills comparison be made verifiable by obtaining the original code or by inviting the CoEvoSkills authors to confirm the reimplementation, given it underpins the headline delta?
- Does the pass@5 vs. pass@1 asymmetry fully explain the "beats human skills" result, or would a pass@1 evaluation of the *final* evolved skill still exceed human skills?
