When Do Prompt-Side Agent Playbooks Transfer?

Key Finding

Frozen prompt-side playbooks transfer only conditionally: strongly positive on ALFWorld under greedy decoding (+23.6 pp), but fragile — 1/135 routes survive Holm correction on TAU2 and runtime shift destabilizes cost.

◆ Methodology

No new learning algorithm. A playbook = a compact procedural checklist distilled from a source agent's repeated failures, inserted verbatim into the prompt at deployment, then frozen before transfer.

  • Distill: run source agent K=8×, hand fail/mixed bundles to a stronger teacher (Claude Opus 4.6 via Claude Code, or GPT-5.4 via Codex).
  • Validate on the source side, then freeze.
  • Transfer across domain / model family / runtime regime.

Three benchmark roles:

  • ALFWorld — controlled existence test (scene-OOD, 7B/32B scale, Qwen↔Llama), 400-run temperature audit.
  • TAU2-Bench — heterogeneous service agents; global Holm over 135 Pass1 routes.
  • XBench-DeepSearch — runtime-shift stress test ({32K,128K} × {Tongyi-DR,Qwen3-32B}), 100 problems.

Placebo control rules out a pure length/format explanation: transferred playbook reproduces the signed effect (positive or negative) while a same-length generic placebo tracks baseline.

Behavioral audit (150 paired trajectories) localizes the 128K destabilization to re-querying + delayed stopping — submit-within-10-tool-calls collapses 78%→30%.

◆ Key Contributions

  • 01Defines a deployment-oriented distill–validate–transfer protocol — an audit framework, not a new algorithm or a validated compatibility selector.
  • 02Shows transfer is real but non-uniform: uniformly positive on ALFWorld under greedy decoding; robustness is jointly set by decoding regime × target capacity × artifact specificity.
  • 03Main heterogeneous service-agent evidence on TAU2: a prespecified matched-vs-mismatched contrast holds, but only 1/135 routes survives multiplicity correction.
  • 04A runtime-shift stress test quantifying accuracy-flat but cost-explosive failure; a deployment checklist frames playbooks as deployment artifacts, not universal knowledge modules.

◆ Critical Assessment

  • Novelty: diagnostic, not mechanistic — the workflow resembles existing experience-replay work (ExpeL, PromptAgent, A-Mem); value is the transfer audit.
  • Rigor: strong statistics (global Holm, exact permutation, paired bootstrap 500k); honestly reports 134/135 non-surviving routes.
  • Reproducibility: good surface, but depends on closed proprietary distillers (Opus 4.6, GPT-5.4); no public artifact release.
  • Significance: immediately actionable deployment checklist; scientifically modest — cartography of failure modes, not a predictive selector.

◆ Strengths

  • Rare intellectual honesty: foregrounds where transfer fails rather than burying it.
  • Statistically disciplined: global Holm + exact permutation/McNemar + paired bootstrap CIs + three content controls.
  • The validate accuracy + termination + protocol-compatibility + cost quadruple is a genuinely useful operational artifact.
  • Complementary benchmark roles well-motivated; full verbatim playbook (P14R) makes artifacts inspectable.

◆ Limitations

  • TAU2 has limited per-cell power; most of the heatmap is descriptive.
  • XBench runtime-shift hinges on one artifact × one 100-problem benchmark — a stress test, not a law.
  • No comparison vs human-authored playbooks or dynamic retrieval baselines (the realistic production alternatives).
  • No code, data-analysis, or SWE agents evaluated; generalization beyond embodied/service/search is untested.

◆ Questions for Further Exploration

Could a cheap pre-transfer compatibility screen (tool-schema overlap, decoding-regime match, stopping-rule alignment) predict which of the 135 TAU2 routes transfer positively?

Does the “larger targets benefit more” ALFWorld finding hold on SWE-bench / real code agents, or is it an artifact of the 50-step ceiling?

Would an explicit stopping-rule guard (or hard tool-call budget) recover bounded behavior on the 128K shift without sacrificing the +4–8 pp Pass@1 gain?

Is there a Pareto frontier between accuracy gain and cost inflation that a multi-objective selector could exploit?

★ Relevance

Directly relevant to anyone deploying or improving LLM agents with prompt-side experience, skill libraries, or agentic memory — the “agent self-improvement / experience replay” thread. Its negative-result orientation (when does transferred guidance fail or inflate cost) is especially valuable for production, where cost and termination stability matter as much as accuracy.
