> **一句话总结：** 本文审计 ChatGPT 的聊天界面与 API 在 BBQ/SafetyBench 两套安全基准上的表现，发现即使准确率差距仅约 2-3 个百分点，启用网页检索会使准确率最多下降 8 个百分点并反转模态排名，同一提示在重复运行中最高有 21% 出现不一致回答，两模态引用来源几乎不重叠，揭示出单一准确率指标严重遮蔽了部署相关的安全行为变异。

> **TL;DR:** An empirical audit of GPT-5.3 Instant showing that, on BBQ and SafetyBench (401 prompts, 4,812 responses, 3 repeated runs), chat UI vs API and search on/off produce only ~2-3 pp accuracy gaps but large behavioral differences: enabling web search cut accuracy by up to 8 pp (API OR=0.36, p<0.001) and reversed the modality winner on SafetyBench, repeated runs disagreed in up to 21% of prompts, and the two modalities shared only ~4% of cited URLs. The paper argues AI safety benchmarks must measure modality, multi-run consistency, search condition, and response-level behaviors, not just accuracy.

## 核心贡献

- 系统审计"模态 × 检索"两个维度的隐性假设：在同一模型族（OpenAI GPT-5.3 Instant）内，对比消费者端聊天 UI 与 API，并分别在启用/关闭网页检索的四种条件下，对 BBQ 与 SafetyBench 共 401 个分层抽样提示各运行 3 次，采集 4,812 条响应。
- 超越准确率，定义并测量四类被现有基准忽视的"响应级行为"维度：跨重复运行的一致性、响应文本的词法（Jaccard）与语义（embedding 余弦）相似度、引用来源的 URL/领域级重叠，以及弃答（abstention）行为。
- 量化证明单一准确率会掩盖风险：检索开启后准确率下降且反转模态排序，跨模态引用重叠仅约 4%，弃答行为在同一提示的重复运行间不稳定。
- 提出面向部署真实性的"模态+检索感知"评估方法论，并指出基础设施缺口（聊天 UI 审计门槛高、成本大）本身就是有效性缺口，需要开发者与政府层面提供稳定测试床。

## Key Contributions

- A 2×2 audit design crossing access modality (ChatGPT chat UI vs OpenAI API) with web search (on/off), on the same GPT-5.3 Instant model, using 401 stratified prompts from BBQ (198) and SafetyBench (203) with 3 runs each (4,812 responses total).
- Extends the evaluation surface beyond accuracy to four response-level dimensions: repeated-run consistency, lexical (Jaccard) and semantic (cosine) text similarity, citation grounding at URL and domain level, and abstention behavior.
- Demonstrates that accuracy-only reporting hides deployment-relevant variance: search reverses the modality winner on SafetyBench, between-modality disagreement consistently exceeds within-modality noise, and citation overlap is only ~4% of URLs.
- Frames AI evaluation as a measurement-design and infrastructure problem, arguing that single-modality, single-run, accuracy-only benchmarks cannot validly certify deployed system behavior for safety-critical or governance use.

## Methodology

The authors run a controlled 2×2 audit on one of the most widely deployed LLMs, OpenAI's GPT-5.3 Instant (the chat UI accessed as logged-out chatgpt.com; the API accessed as `gpt-5.3-chat-latest` at default temperature 1.0). They cross two factors: access **modality** (chat UI vs API, where "modality" includes the full user-facing stack — system prompts, moderation, the chat interface) and **web search** (enabled "online" vs disabled "offline"). Each prompt is run three times per cell to measure consistency; all 4,812 responses were collected inside a single one-week window to limit temporal drift.

Prompt sampling comes from two widely cited AI safety benchmarks: **BBQ** (11 social-bias categories, 18 questions each = 198) and **SafetyBench** (7 safety categories, 29 each = 203). Sample size was justified by an a priori power analysis (Cohen's h=0.2, alpha=0.05, power=0.80 → 197 minimum) and is treated as a conservative floor. They use zero-shot prompting with no system prompt, deliberately auditing each modality "as deployed" rather than trying to make API and chat behave identically.

Chat-UI data was gathered with automated browser sessions, rotating proxies, staggered sessions, and inter-request delays; the API pipeline is a Python script using default parameters. Beyond accuracy (proportion correct among non-abstaining responses), they measure: consistency (all three runs pick the same answer, ignoring correctness); response similarity (mean pairwise Jaccard on tokens, and cosine similarity of `text-embedding-3-small` embeddings on the answer text with the answer-choice prefix stripped); citation rate and overlap (URL- and domain-level unions across the 3 runs per modality, restricted to search-enabled cells); and abstention rate (responses declining outside the option set entirely).

Statistical inference uses mixed-effects models in R (GLMM for binary outcomes, LME for continuous), each with a `(1 | prompt ID)` random intercept to absorb repeated observations. Benjamini–Hochberg FDR correction is applied to the primary inferential family (pair-level disagreement, consistency, Jaccard, citation-rate, and the accuracy model's main + interaction effects); benchmark-specific refits and the cosine model are reported as exploratory with raw p-values.

## Results & Highlights

- **Modality accuracy gap is small but real without search, and search reverses it on SafetyBench.** On BBQ (no search), API 81.9% vs chat UI 79.1% (−2.8 pp); on SafetyBench (no search), API 88.5% vs chat UI 85.9% (−2.6 pp). With search enabled, the SafetyBench ordering flips to chat UI 84.4% vs API 80.6%. A SafetyBench GLMM puts chat-vs-API at OR=0.53, CI [0.30, 0.92], raw p=0.025 with search off.
- **Web search reduces accuracy for both modalities on both benchmarks.** Search effect OR=0.36, CI [0.26, 0.51], p<0.001; the drop is significantly larger for API than chat UI (modality×search interaction OR=1.92, CI [1.20, 3.06], p=0.009) and steeper on SafetyBench (OR=0.18, raw p<0.001) than BBQ. On BBQ the gap between search-off and search-on chat UI is ~8 pp (79.1% → 75.9%, with API falling 81.9% → 77.8%).
- **Repeated runs of the identical prompt are inconsistent.** On BBQ, chat-UI/search inconsistency reached 21.2% (CI [15.5, 26.9]) — i.e., roughly one in five prompts got a different answer across three runs — and API/search reached 19.2%. A binomial GLMM confirms search as a significant driver of inconsistency (OR=0.51, p=0.004).
- **Between-modality disagreement exceeds within-modality noise.** The same prompt disagreed more often across API-vs-chat than across runs inside either modality by factors of 1.14–1.30, and a pair-level GLMM gives between-modality OR=1.51, CI [1.19, 1.92], p=0.002 for disagreement; the gap is significantly larger on SafetyBench (OR=1.43, raw p=0.015).
- **API and chat UI construct answers differently.** Between-modality Jaccard similarity is ~0.15–0.16 vs within-API 0.59–0.77 — roughly 3–5× lower. Semantically (cosine), between-modality similarity is 0.626 vs within-API 0.802 and within-chat 0.863 (BBQ Cohen's d=−1.33, SafetyBench d=−1.76). On SafetyBench, 39.1% of API/no-search responses contained only the answer choice with no explanation, vs 1.5% for chat UI.
- **Citation grounding barely overlaps.** Restricted to search-enabled cells, the two modalities shared only ~4% of URLs (7% of domains). The chat UI cited more sources on BBQ (46.8% vs 32.2% citation rate) but fewer on SafetyBench (60.6% vs 73.9%) — a significant modality×benchmark interaction (OR=0.17, CI [0.12, 0.26], p<0.001). On BBQ the chat UI drew from 356 unique sources vs 179 for the API.
- **Abstention is unstable.** SafetyBench produced zero abstentions. On BBQ, only 6 abstentions across 4 prompts appeared, all in no-search; three of four prompts abstained on only one of three runs. All four prompts touched protected characteristics (age, religion×2, race/ethnicity), echoing prior higher-refusal findings on identity-related content.

## Authors & Credibility

The authors are from University of Pennsylvania (Encarnación, Lurie, Metaxa) and Stony Brook University (Behzad). Danaé Metaxa co-leads work on trustworthy computing and has co-authored prior auditing studies on identity-related speech suppression in generative AI (Proebsting et al. 2025, cited here), giving the team direct prior experience with the abstention/refusal phenomena they measure. The work is positioned for AAAI 2026 (the copyright line is present) and is written in a careful measurement-science register (a priori power analysis, BH FDR correction, prompt-level random intercepts, pre-registered-style separation of primary vs exploratory tests). Datasets are publicly released at `https://github.com/seerocode/aies-llm-modality-audit`, supporting reproducibility of the analysis layer.

## Critical Assessment

- **Novelty:** The core framing — that API-based, single-run, accuracy-only benchmarks are an invalid proxy for deployed chat-UI behavior on safety benchmarks — is genuinely useful and empirically supported, especially the result that search *reverses* the modality winner on SafetyBench and that the citation overlap between modalities is only ~4%. This goes beyond Wang, Ho & Koyejo (2025, personalization) and Kirgis et al. (2026, sycophancy), which compared modalities but not search × modality.
- **Rigor:** The statistical machinery is solid for an audit: mixed-effects models with per-prompt random intercepts, BH correction on the primary family, and a clear pre-registered split between primary and exploratory tests. However, the authors are honest that the sample is an *exploratory* audit of one model family in one one-week window; the headline 197-question power floor is computed only for accuracy Cohen's h=0.2, and several of the most interesting effects (e.g., the SafetyBench modality reversal, the cosine similarity model) are reported as *raw* p-values outside the BH family, so some "significant" claims rest on uncorrected exploratory tests at n≈200.
- **Scope limitations that matter:** (a) A single model family (OpenAI/GPT-5.3) and a single snapshot — generalization to Claude/Gemini/open models is asserted, not shown. (b) Two benchmarks only, both multiple-choice; the authors note BBQ/SafetyBench questions are likely in web-scraped training data, which both inflates absolute accuracy and may suppress modality differences that would surface on novel or open-ended items. (c) API temperature was fixed at 1.0 (the API default) — a reasonable "as-deployed" choice, but it guarantees nontrivial within-API run-to-run noise and makes the within-vs-between comparison partly an artifact of that temperature decision; no ablation over temperature is reported. (d) The chat-UI collection uses rotating proxies and staggered sessions, but the paper does not report how often the chat UI silently switched model routing, applied personalization heuristics on logged-out sessions, or throttled the audit, which are exactly the opaque system-layer behaviors the audit wants to expose.
- **Reproducibility:** Good on the analysis side (public dataset, code link, explicit model version `gpt-5.3-chat-latest`). Weak on the data-collection side: a third party re-running the chat-UI arm cannot reproduce the exact deployed system (it will have changed), and the paper acknowledges this as a call for stable government/developer testbeds rather than solving it.
- **Significance:** High for the AI-evaluation and governance community — it directly critiques the CAISI (2026b) draft automated-benchmark guidelines and provides concrete, actionable dimensions (modality, multi-run, search, citation, abstention) that a benchmark standard should mandate.
- **Red flags / overclaiming:** The abstract's "up to 8 percentage points" search drop is the BBQ chat-UI cell; the average search effect is smaller and the headline reverses on SafetyBench for the chat UI (whose accuracy *rose* with search). The "guardrail is functionally useless" line in the Discussion overstates a finding built on just 6 abstentions across 4 prompts — directionally interesting, but n is too small to support that strong a claim.

## Strengths

- Clean 2×2 design that isolates modality from search for the first time on safety benchmarks, with an a priori power justification rather than ad-hoc sampling.
- Measures genuinely under-studied response-level dimensions (consistency, lexical/semantic similarity, citation overlap, abstention) with appropriate mixed-effects statistics and FDR control.
- The ~4% URL-overlap and modality-dependent citation-rate reversal are striking, concrete findings that any benchmarking standard must now reckon with.
- Honest framing of the infrastructure gap as a validity gap, with a public dataset release for independent re-analysis.

## Limitations

- Single model family (OpenAI GPT-5.3), single one-week collection window — magnitude and even direction of effects may not transfer to other providers or future versions.
- Only two multiple-choice benchmarks, both plausibly contaminated by inclusion in training data; open-ended or unseen prompts may show larger (or different) modality gaps.
- API temperature fixed at 1.0 with no ablation, so within-modality noise — and hence the within-vs-between comparison — partly depends on that choice.
- Several headline effects (SafetyBench reversal, cosine similarity) are reported with raw, non-BH-corrected p-values as exploratory tests.
- The abstention analysis rests on only 6 events across 4 prompts, yet is used to support a strong "guardrails are useless" claim.
- No assessment of the *quality* or authority of cited sources, only their overlap.

## Relevance

与用户对 LLM 评估、AI 安全与可信赖 AI 系统的研究兴趣高度相关：它从测量科学角度揭示了"准确率至上"基准的盲区，并给出了模态、检索、多轮一致性等可操作的审计维度，对构建更严格的安全评测协议和检索增强系统的可靠性分析有直接参考价值。

## Questions for Further Exploration

- Does the modality/search gap replicate on Claude, Gemini, and open-weight models, and does the SafetyBench "search reverses the winner" effect survive with different deployed system stacks?
- How much of the within-API inconsistency is an artifact of temperature=1.0, and what temperature (or decoding config) would make the API a valid proxy for the chat UI's deployed behavior?
- Would the effects grow or shrink on novel, open-ended, or out-of-distribution prompts not present in web-scraped training corpora?
- Can a source-authority / retrieval-quality metric (beyond URL overlap) explain *why* the two modalities cite different sources, and whether one set of sources is systematically more credible?
- How should CAISI/NIST-style automated benchmark guidelines be amended to mandate modality-, multi-run-, search-, and abstention-aware reporting without making independent audits prohibitively expensive?
