Learning Globally Reusable Skills for Coding Agents

Chen Yang, Jiashuo Tian, Ziqi Wang, Xinyin Liu, Meiru Ye, Junjie Chen — Tianjin University & Tsinghua, with ByteDance

!Key Finding

Reframes agent skill evolution as a global optimization over a Skill Relation Graph that co-evolves dependency, co-usage, and conflict edges — turning local trace fixes into reusable skills.

↑Key Metric

★Why This Matters

A new paradigm: treat skill libraries as relation-graph systems for global optimization, with strong gains on a real industrial agent — a key reference for self-evolving agents.

iTL;DR

Existing methods (Live-SWE-agent, Trace2Skill) treat skill evolution as a sequence of independent local updates, ignoring how skills couple — so the bank drifts into conflict and over-specialization. GSE runs a three-stage loop (trace collection → DSL-constrained evolution proposals → cluster-based generalization with replay validation) over a Skill Relation Graph whose dependency / co-usage / conflict edges are first-class objects of evolution. A relationship-aware propagation step emits auxiliary proposals so a local change can't silently break its neighbors.

!Critical Edge

"It's unclear how much of the SRG's benefit is structural vs. simply forcing the update agent to re-read neighbor skills."
No statistical significance testing or multi-seed runs despite high agent variance. Single LLM backbone (DeepSeek-V4-Flash only) — model-axis generalization unverified. IndustrialBugs is closed, so the headline +61.4% F1 cannot be independently reproduced. SRG edges are LLM-generated with no human audit, and the recall range "+31.8%~180.0%" is a small-absolute-number artifact presented without caveat.

2Methodology

  • Trace Collection. Base agent (OpenHands / mini-SWE-agent) records reasoning + tool calls; a simplification step strips token-heavy low-value output, keeping a semantic-rich trace.
  • Evolution Proposals. DeepSeek-V4-Flash does hierarchical failure diagnosis (navigation / reasoning / execution), consults the SRG for affected neighbors, and emits auxiliary proposals. Each proposal is serialized in a DSL (target / operation / content / rationale / expected behavior / relationship updates) and locally replayed before admission.
  • Skill Generalization (Alg. 1). Proposals are clustered (by affected-skill set for updates; by semantic similarity for new skills), a merge agent strips case-specific detail, and the candidate is replayed on historical activations — accepted only if it preserves or improves performance.

Counterintuitive: at execution time GSE is the cheapest skill method (593K tokens/case vs 620K Human / 613K Live-SWE / 619K Trace2Skill) — generalized skills induce more efficient trajectories. Ablation confirms both the SRG (w/o graph ↓F1) and generalization (w/o gen ↓F1) are individually necessary.

+Strengths

  • Motivation maps cleanly onto mechanisms; ablation confirms both pull weight.
  • Honest that 6 senior engineers' hand-written skills gave near-zero or negative gains on the stronger agent.
  • Execution-token reduction is a practitioner-friendly finding.
  • One-project-held-out genuinely tests cross-project transfer.

−Limitations

  • Closed IndustrialBugs blocks external verification of the headline numbers.
  • SRG construction, edge typing, and merge-agent prompts are under-specified.
  • Scope limited to two SE tasks; transfer to bug fixing / code review asserted, not shown.
  • No wall-clock / $ cost of full evolution, nor SRG scaling analysis as the bank grows.
