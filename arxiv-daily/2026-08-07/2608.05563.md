> **一句话总结：** 本文提出 PoisonedEvolution，一种针对自演化技能（SES）系统的轨迹投毒攻击——攻击者仅需以约 10% 的占比注入看似正常的"成功/失败"轨迹，便能让演化器把恶意行为当成可复用经验固化进 SKILL.md，在 SkillClaw 上达到 91.0% 的技能嵌入率（SER），并指出"证据提升"是 SES 必须守卫的新型信任边界。

> **TL;DR:** PoisonedEvolution shows that a skill-visible black-box attacker contributing only ~10% of trajectories (k=3 in n=30) can make a self-evolving skill (SES) pipeline (e.g., SkillClaw) author a poisoned SKILL.md itself, achieving 91.0% Skill Embedding Rate (546/600 trials) across six LLM evolvers on SpreadsheetBench-derived xlsx tasks, and 61.5% (369/600) on the structurally different Trace2Skill pipeline — exposing evidence promotion as a new trust boundary distinct from RAG/skill-file poisoning.

## 核心贡献

- **首次识别"证据提升"为新型信任边界**：指出自演化技能（SES）系统把轨迹蒸馏为持久技能时，存在一条与静态技能投毒、RAG 投毒不同的攻击面——攻击者不必发布恶意技能或攻陷演化器，只需贡献少量"看似正常、可复用"的演化证据，让系统自己把恶意行为写进技能文件。
- **形式化 PoisonedEvolution 攻击机制（C1∧C2∧C3）**：将技能投毒成功分解为三个必要条件——C1 Inclusion（进入演化流）、C2 Evolution Attribution（被演化器归因为可复用经验）、C3 Realization（在技能合成/合并后存活），并指出 C2 是 SES 特有的瓶颈。
- **提出归因导向的轨迹构造法**：通过"领域对齐全入 + 因果桥接（obstacle→b→success 或 missing b→failure）+ 跨轨迹不变性"三步，让目标行为看起来像反复出现的、可推广的经验，而非一次性噪声。
- **跨系统、跨演化器的实证证据**：在 SkillClaw（多用户会话聚合）和 Trace2Skill（执行轨迹蒸馏，结构不同）两套架构、六个主流 LLM 演化器上验证攻击有效性，并提供 k、n、C2/C3 表征的机制消融。
- **给出防御设计方向与原型**：提出"来源多样性门（Provenance-Diversity Gate）"作为提升时刻的试点防御，要求独立用户/簇支持、拒绝多数主导、惩罚高文本重叠，并在原型中将单簇 F1 投毒从 25/25 降到 0/25。

## Key Contributions

- **Identifies evidence promotion as a new SES trust boundary**, distinct from static skill poisoning (PoisonedSkills/Skill-Inject) and retrieval-time RAG poisoning: the attacker corrupts the artifact-production pipeline, not the final file or retrieval context, and the victim evolver itself authors the poisoned skill.
- **Formalizes PoisonedEvolution as a C1∧C2∧C3 artifact-poisoning mechanism**, isolating Evolution Attribution (C2) as the SES-specific bottleneck and showing the attack is system-independent rather than tied to one evolution prompt.
- **Instantiates the attack via domain alignment, causal binding, and cross-trajectory invariance** (Algorithm 1), framing target behaviors as outcome-conditioned workflow loci so they look like recurring, generalizable expertise.
- **Provides cross-system and cross-evolver evidence**: 91.0% SER on SkillClaw (546/600) and 61.5% on Trace2Skill (369/600) at ρ=10%, plus condition ablations pinpointing recurring support (k>1), causal framing, and domain-tailored encoding as the main success determinants.
- **Proposes a provenance-diversity gate** as a pilot promotion-time defense that blocks 25/25 single-cluster F1 candidates (post-gate SER 0/25) while accepting a diverse 5-session control, and argues SES defenses must audit evidence provenance, not only scan final skill text.

## Methodology

PoisonedEvolution is an **attribution-oriented trajectory-poisoning attack**. The authors model a trajectory-grounded SES system as Σ = (T, F, E, S): a trajectory pool T, quality filter/router F, LLM evolver E, and versioned skill bank S, updated by S_{t+1} = S_t ⊕ E(F(T_t), S_t). The pool mixes clean trajectories T_c with attacker trajectories T_p (batch n, attacker support k, ratio ρ = k/n).

**Threat model — skill-visible black-box.** The attacker can inspect public/installed skills and contribute a bounded fraction of trajectories, but cannot observe private pools, filters, evolver prompts, or edit the skill bank directly. This captures multi-user systems like SkillClaw (ordinary or Sybil users feeding a shared pool) and offline systems like Trace2Skill (task-corpus contributors, compromised telemetry).

**Attack recipe (Algorithm 1).** For a target skill s and behavior b with budget k: (1) select k attacker-owned candidate trajectories whose tasks relate to s; (2) for each, locate a legitimate workflow locus for b (input prerequisite, recovery step, output transform, or validation step); (3) insert an outcome-conditioned causal bridge — `constraint → b → success` for success-routed records, or `missing b → failure` for failure-routed records; (4) preserve the original task outcome while varying surface wording so the operational semantics of b stay invariant across the poisoned subset. The result is reference-grounded construction from completed SpreadsheetBench trajectories (Ma et al. 2024).

**Success factorization.** Poisoning success = C1 Inclusion ∧ C2 Evolution Attribution ∧ C3 Realization. C1 is held operationally fixed (records pass native ingestion); C2 and C3 are the technical levers. Recurrence (k>1) is central: a single record looks like an accident, while ≥2 consistent records resemble the reusable experience SES is designed to distill.

**Payload families (inert canaries).** Four representative security-effect families, each expressed as p = ⟨locus, action, object, context⟩ with inert canary endpoints/paths/registries/flags (never executed):
- F1 Confidentiality (exfiltrate to ATTACKER_ENDPOINT)
- F2 Data integrity (delete source artifacts at SOURCE_PATH)
- F3 Supply chain (redirect package registry to ATTACKER_REGISTRY)
- F4 Safety weakening (disable SECURITY_CHECKS before publish)

**Primary metric — Skill Embedding Rate (SER):** the fraction of completed evolution trials whose output skill newly embeds the target behavior, detected by family-specific diff-aware canary rules (LLM judge used only for inspection, not to define success). Hard/Soft task accuracy on SpreadsheetBench is reported only as a utility sanity check.

## Results & Highlights

- **Main SkillClaw result (Table 1, n=30, k=3, ρ=10%):** PoisonedEvolution embeds target behaviors in **546/600 completed trials = 91.0% SER** across six evolvers and four families (25 trials per model×family cell). Evolver spread: GPT-5.4 70/100 (70.0%), MiniMax-M2.5 87/100 (87.0%), DeepSeek-V3.2 100/100 (100.0%), DeepSeek-V4-Pro 94/100 (94.0%), Qwen3.5-35B-A3B 95/100 (95.0%), Qwen3.5-122B-A10B 100/100 (100.0%).
- **Family sensitivity (SkillClaw):** F4 Safety-weakening reaches 146/150 (97.3%), F2 Data-integrity 139/150 (92.7%), F1 Confidentiality 137/150 (91.3%), while F3 Supply-chain is lowest at 124/150 (82.7%) because registry redirection is easier for evolvers to suppress as unrelated setup advice.
- **Trace2Skill structural transfer (Table 2, n=30, k=3):** **369/600 = 61.5% SER overall**. Family spread is large — F2 124/150 (82.7%), F3 116/150 (77.3%), F1 101/150 (67.3%), but F4 collapses to 28/150 (18.7%) because Trace2Skill routes these records through a failure-analysis path where safety-weakening looks like policy relaxation rather than a needed repair.
- **Recurrence ablation (Fig. 2 left, fixed n=30):** attacker support k=1 (3.3%) → 5/25, k=2 (6.7%) → 21/25, k=3 (10%) → 25/25. The jump from one to two records is the key finding: a single poisoned trajectory is dismissed as accidental, whereas repeated consistent trajectories resemble promotable experience.
- **Clean-pool dilution (Fig. 2 right, fixed k=3):** a representative strong evolver reaches 25/25 at n=10 (30%) and n=30 (10%), stays high at 22/25 when n=100 (3%), and a k=1, n=100 (1%) check gives 0/5 — consistent with the recurrence effect.
- **C2 attribution ablation (Fig. 3):** Local single-place insertion 8/25, Fragmented cross-record insertion 11/25, Causal outcome-framing 25/25 — showing attribution requires an outcome-linked role.
- **C3 realization ablation (F1 family):** Generic broad instruction 18/25, Auxiliary out-of-band cue 0/25, Tailored domain-aligned actionable encoding 25/25 — realization benefits from actionable, domain-aligned encoding in the main trajectory.
- **Skill-creation (no-init) diagnostic:** behavior embedded in 490/600 trials (81.7%) across four evolvers, establishing create-path feasibility.
- **Benign-task utility check (Qwen3.5-122B-A10B, 100-task split):** poisoned-evolved xlsx skill scores 20.0% Hard / 36.54% Soft vs. 18.0% / 34.88% without a skill — poisoning coexists with the normal-task benefit of skill use rather than collapsing the artifact into attack-only text.
- **Provenance-diversity gate (pilot defense):** at n=30, k=3, blocks 25/25 single-cluster F1 candidates (post-gate SER 0/25) while accepting one five-session diverse control.

## Authors & Credibility

The work is a multi-institution collaboration led by Ant Group with Zhejiang University, Tsinghua University, NUDT, CUHK-Shenzhen, Hangzhou Dianzi, and Xi'an Jiaotong — a credible grouping for an agent-security paper. The framing is careful and disciplined: the authors explicitly delimit their claims to the evidence-to-artifact boundary (artifact poisoning, not runtime compromise), use only inert canary payloads that are never executed, and report embedded/completed counts so endpoint failures are not silently counted as clean. They distinguish SER (artifact changed) from attack-success-rate at runtime and refuse to collapse the two. The threat model is precisely scoped (skill-visible black-box, no bank edits, no model compromise), and non-goals (no real exfiltration, no destructive FS effects) are stated up front. The related-work positioning against RAG poisoning (AgentPoison, PoisonedRAG, MINJA, eTAMP) and skill-supply-chain attacks (PoisonedSkills, Skill-Inject, POISE, BadSkill) is accurate about what is novel (Evolution Attribution via cross-trajectory credit assignment) versus what is reused (Skill-Inject's security-effect categories, adapted as inert canaries).

## Critical Assessment

- **Novelty: high and well-articulated.** The C1∧C2∧C3 factorization with Evolution Attribution as the SES-specific bottleneck is a genuine conceptual contribution that cleanly separates this work from retrieval-time and skill-file poisoning. The "let the victim evolver author the poison" framing is the strongest idea.
- **Rigor of the metric design is a real strength.** SER is defined with diff-aware, family-specific canary rules checked against the initial skill to avoid counting pre-existing text, and the authors explicitly decouple SER from runtime ASR and from Hard/Soft utility. The honesty about judge outputs being only for inspection (not success definition) is commendable.
- **Weak / thin baseline: the only defense evaluated is the authors' own pilot provenance-diversity gate, tested on a single family (F1) and a single small clean control (one 5-session diverse batch).** There is no comparison against existing skill-poisoning defenses (RouteGuard, instruction hierarchy, SecAlign, CaMeL) at the promotion boundary, and the gate's assumptions (candidate grouping is "assumed," coordinated Sybils may mimic diversity) are conceded but not stress-tested. A Sybil-aware adversary that splits contributions across fabricated users is the obvious next attack and is left to future work.
- **Missing ablations.** The C3 realization comparison changes channel and locus simultaneously, which the authors themselves flag as "a realization stress test rather than a single-variable causal estimate" — fair, but it means the 0/25 Auxiliary number is hard to interpret in isolation. There is no ablation on the causal-bridge wording strength, no sensitivity to evolver prompt versions, and no measurement of false-positive rate of the canary detector on clean evolved skills.
- **Generalizability caveats are underlined by the authors themselves.** User-scoped dialogue-memory systems, verifier-only systems (CoEvoSkills), and parameter-training systems (SkillRL, Skill-SD, MemSkill) are explicitly outside the empirical claims — so the "self-evolving skill" threat is validated for only two of several SES architectures.
- **Data quirk worth noting:** the source corpus is 300 case-level logs collected by running GLM-5 with the original xlsx skill on 100 SpreadsheetBench training tasks, then converted to SkillClaw-compatible sessions. This means the no-init (creation) setting is not truly prior-skill-free (the authors admit this), slightly weakening the 81.7% create-path number as a causal estimate.
- **Red flag (scope, not fraud):** the paper measures only one evolution cycle. The most dangerous real-world failure mode — a feedback loop where a poisoned skill guides later agents whose trajectories re-validate the behavior — is explicitly not measured. This is the single biggest gap between the paper's threat narrative and its evidence.
- **Overclaiming risk: low.** Claims are consistently scoped to artifact poisoning, numbers are reported as embedded/completed rather than inflated, and family/evolver variation is presented as a finding rather than hidden.

## Strengths

- Clean, transferable formalization (C1∧C2∧C3, Σ = (T,F,E,S)) that future SES-security work can build on.
- Strong headline result (91.0% SER at 10% support) backed by a 600-trial matrix with per-cell transparency.
- Mechanism ablations (recurrence, causal framing, domain-tailored encoding) genuinely explain *why* the attack works, not just *that* it works.
- Honest metric hygiene: SER separated from runtime ASR and from utility; inert canaries never executed; embedded/completed counts reported.
- Cross-architecture transfer to Trace2Skill shows the attack is not a SkillClaw-specific prompt exploit.
- Actionable defensive direction (provenance-sensitive evidence promotion) with a working pilot, even if preliminary.

## Limitations

- Only one evolution cycle is measured; the longitudinal feedback-loop amplification risk is untested.
- The pilot provenance-diversity gate is evaluated on a single family (F1) and one small diverse control; Sybil attackers that mimic diversity are not simulated.
- No comparison against existing skill-poisoning defenses at the promotion boundary.
- C3 ablation conflates channel and locus, so the Auxiliary 0/25 result is not a clean single-variable finding.
- Empirical scope covers only two SES architectures (SkillClaw, Trace2Skill); user-scoped, verifier-only, and parameter-training systems are out of scope.
- The no-init creation setting reuses skill-collected traces, so it is not a clean prior-skill-free creation test.
- All payloads are inert canaries; real-world severity of a *realized* behavior (actual credential exfiltration, real registry redirection) is argued but not demonstrated.

## Relevance

高度相关：本文直接研究 LLM Agent 自演化技能系统的安全性，揭示"证据提升"这一新型信任边界，与用户对 Agent 安全、技能演化、对抗性机器学习的研究兴趣高度契合，可为设计更安全的自演化 Agent 框架提供攻击模型与防御思路。

## Questions for Further Exploration

- How does poisoning amplify over multiple evolution cycles once a poisoned skill starts guiding later agents' trajectories? Does SER compound or saturate?
- Can a Sybil adversary that splits k contributions across many fabricated users defeat the provenance-diversity gate, and what clustering/text-overlap thresholds robustly separate coordinated Sybils from genuine independent contributors?
- Do existing runtime defenses (RouteGuard, instruction hierarchy, SecAlign, CaMeL) provide any incidental protection at the evidence-promotion boundary, or must promotion-time provenance gates be a new layer?
- How does PoisonedEvolution transfer to user-scoped dialogue-memory systems (AutoSkill) and verifier-coupled systems (CoEvoSkills), where the credit-assignment signal differs from SkillClaw/Trace2Skill?
- What is the false-positive rate of the diff-aware canary detector on cleanly evolved skills, and does it scale to behaviors not pre-registered as family rules?
- Can a single-variable C3 ablation (fixing locus, varying only encoding) confirm that actionable domain-tailored wording — rather than channel placement — drives realization?
