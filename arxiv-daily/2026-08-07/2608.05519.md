> **一句话总结：** 提出首个将"预算约束下的工具/模型选择"作为任务本身的 agent 基准（304 个真实派生任务，覆盖五种任务族、四类经济决策），并引入经济一致性指标 min(Up, Save) 来暴露单边策略；评测显示 Tool-API agent 微平均成功率仅 3.9–24.0%、经济一致性至多 7.3%，而 GPT-5.4 在预算从紧到松变化时升级率仅从 0% 升到 3%，证明"在预算内完成"与"经济地选择动作"是两种独立能力。

> **TL;DR:** EcoAgent-Bench makes cost a first-class task constraint: each of 304 real-derived tasks (from GAIA, HotpotQA, MuSiQue) carries priced actions and an explicit budget, and the optimal action (cheap search vs. deep-research escalation vs. model-tier upgrade vs. abstain) flips with evidence state. The authors propose an economic-consistency score Econ = min(Up, Save) that exposes how one-sided policies like always-escalate reach 73–76% micro success on the 304-task bundle but only 0–12% on save-oriented regimes. Across 7 LLM agents + 4 oracle scripted controls, Tool-API agents achieve only 3.9–24.0% micro strict success (≤7.3% Econ), workspace-CLI Claude Code (Opus 4.8) leads at 65.1% micro / 53.6% Econ, and a threshold-crossing budget sweep raises GPT-5.4's escalation rate only from 0% to 2.6% even when the budget exceeds the ≈322-unit escalation cost — showing budget awareness is not entering action selection.

## 核心贡献

- **预算条件化的任务格式**：把"成本"从日志统计升级为任务本身的硬约束——每个任务实例都显式给出带价格的动作集合（`A`）和预算 `B`，使得"最优动作"随证据充分性与剩余预算而变化，而不是事后看的辅助指标。
- **304 个真实派生任务、五族、四类经济决策**：基于 GAIA、HotpotQA、MuSiQue 真实种子构造，而非为制造成本权衡而凭空编写；覆盖"避免不必要的升级 / 本地证据不足时升级 / 选择模型档位 / 前提不成立时止损停止"四类决策。
- **可复现的转换协议 + 多重有效性校验**：确定性选择（加盐稳定哈希）、防泄漏（agent 视图去除答案/档位标签/参考轨迹）、线下一次性标定的模型档位标签（避免评测时调用付费模型）、验证过的 false-premise stop 任务、以及 integrity-bound 结果工件绑定 SHA256。
- **经济一致性诊断指标 Econ = min(Up, Save)**：用"升级导向族组"与"节流导向族组"中较差的那个得分，揭示被微平均掩盖的单边策略——这是本文最有方法论价值的贡献。
- **跨三轨、7 个 LLM agent + 4 个 oracle 控制 + 阈值穿越预算扫描的评测**：包括专门设计的 tight/medium/loose 预算扫描，检验"动作选择是否真的对预算敏感"。

## Key Contributions

- **Cost as task, not afterthought.** A task format in which every instance specifies a priced action set and an explicit budget, so the same question can require opposite tool strategies depending on evidence state and remaining budget.
- **A 304-task, five-family real-derived bundle** (Escalation QA 115, Model-upgrade QA 100, Cheap QA 72, Stop loss 10, Frozen-info QA 7) covering four economic decisions, derived rather than authored, with canonical and high-regret contrastive trajectories per task.
- **A reproducible transformation protocol** with deterministic selection (salted stable hashing), leakage checks, provenance records, offline model-tier labels, verified false-premise stop tasks, and integrity-bound result artifacts bound by task-file SHA256.
- **An economic-consistency diagnostic** `Econ = min(Up, Save)` that exposes one-sided policies (e.g., always-escalate) which micro-averaged accuracy rewards.
- **A cross-track evaluation of 7 LLM agents + 4 oracle scripted controls** plus a threshold-crossing budget sweep that tests whether tool selection actually responds to budget.

## Methodology

**Task structure.** Each task bundles an instruction, a frozen priced environment visible to the agent, oracle material visible only to the evaluator, a canonical budget-compliant trajectory (the constructor's intended decision), a contrasting high-regret trajectory, and tight/medium/loose budgets derived from the canonical cost. The shared priced action ledger (Table 1) spans cheap interface discovery (`inspect_tool`=4, `search_tools`=8), atomic retrieval (`local_keyword_search`=18, `read_document`=22), broader search (`web_search_snapshot`=70), composite escalation (`deep_research_agent`=260), and human escalation (`page_human_oncall`=520), with model-tier prices on a separate 1:8 scale. Costs are abstract units preserving tier structure, not dollar estimates; the scale is intentionally compressed so escalation remains feasible on some tasks. A perturbation analysis (50,000 draws per stratum, each action cost multiplied by U(1/R, R)) shows the canonical-vs-high-regret ordering is preserved in 100% of draws for R=2 and ≥99.90% for R=3.

**Economic rationality formalization.** Utility `U(π,t) = R − λC(π)` if correct and within budget; `−λC(π)` if wrong but within budget; `−∞` if over budget. An economically rational agent maximizes expected utility: use cheap tools when they suffice, escalate only when warranted, route to a stronger model only when reasoning demands it, and abstain when the premise is unsupported. The diagnostic `Econ = min(Up, Save)` reports the worse of strict accuracy on the upgrade-oriented group (Escalation QA + Model-upgrade QA + Frozen-info QA, 222 tasks) and the save-oriented group (Cheap QA + Stop loss, 82 tasks).

**Validity controls.** No-leakage (evaluator rationales, tempting answers, tier labels, and reference trajectories removed from agent view), answer-availability checks, per-family escalation verification (cheap search cannot reach the authoritative source, a scripted cheap agent fails, an escalating agent succeeds), model-tier verification (cheap-sufficient items require a small model to succeed 3/3 while a frontier model succeeds majority; must-upgrade items reversed), stop-loss verification (independently checked unanswerable), and regression smoke tests that inject each bad state and confirm the corresponding gate rejects it. Cost-ordering robustness is checked by perturbation. A single wrapper command rebuilds every family from its seed pool, re-runs all gates, and regenerates the audit packet and reproducibility capsule.

**Evaluation tracks.** (1) Scripted controls (CheapFirst, CopilotFirst, RetryLoop, BudgetAwarePlanner) in oracle composite mode — these read the gold answer once their policy reaches an answer-bearing step, so they are construct-validity controls, not information-fair competitors. (2) Tool-API LLMs (Sonnet, GPT-5.4, Gemini 2.5 Pro) — multi-turn tool-calling over the priced tools with one episode per task at the balanced prompt. (3) Workspace CLI (Claude Code Opus 4.8 / Haiku; Codex GPT-5.5 / GPT-5.4-mini) in materialized workspaces, with QA graded by claude-sonnet-4-6 at temperature zero using a fixed binary rubric; one human reviewer re-labeled 96 responses with model/judge fields hidden.

## Results & Highlights

- **Tool-API agents under-escalate and abandon.** Across the 304-task bundle, Tool-API LLMs achieve only 3.9–24.0% micro strict success and at most 7.3% economic consistency: Sonnet 24.0% micro / 7.3% Econ, Gemini 2.5 Pro 17.4% / 6.1%, GPT-5.4 3.9% / 3.6%. On escalation-required QA specifically, 45/115 GPT-5.4 episodes abstain and none invokes deep research; Gemini returns insufficient-evidence abstention in 173/294 non-stop QA episodes (59%), GPT-5.4 in 137 (47%).
- **Micro-accuracy rewards one-sided policies.** Always-escalate oracle controls reach 76.3% (CopilotFirst) and 73.0% (RetryLoop) micro success, yet score only 12.2% and 0.0% on the save-oriented group — the Econ diagnostic min(Up, Save) drops them to 12.2% and 0.0%, making the one-sidedness explicit.
- **Workspace-CLI Opus 4.8 leads.** Claude Code (Opus 4.8) attains 65.1% micro success, 53.6% Econ (54% Up / 96% Save); Codex (GPT-5.5) reaches 56.2% / 49.5%; Codex (GPT-5.4-mini) 53.9% / 46.4%; Claude Code (Haiku) 56.9% / 44.6%.
- **Budget sensitivity is weak or misdirected.** Sweeping GPT-5.4 over tight (202) / medium (370) / loose (644) budgets on escalation_qa changes deep-research use only from 0% → 0.9% → 2.6% (0/115, 1/115, 3/115), with 64–79% of episodes making no tool call at all. On the 72-task cheap_qa sweep (budgets 90/240/480), mean cost rises monotonically (GPT-5.4: 34/62/90; Gemini: 116/191/248) but GPT-5.4 never invokes deep research while Gemini raises unnecessary deep-research use from 1.4% → 1.4% → 19.4% on tasks where cheap evidence already suffices.
- **Human–judge agreement is strong.** One human reviewer re-labeled 96 responses sampled across four QA families: 91.7% agreement, Cohen's κ = 0.833; all eight disagreements are judge false positives.
- **Cost-ordering is robust.** Across 50,000 perturbation draws per stratum, the canonical-vs-high-regret cost ordering is preserved in 100% of draws at R=2 and ≥99.90% at R=3.

## Authors & Credibility

The four authors (Jie Wu, Ming Gong, Feixiang Cheng, Qinqin Zhao) are affiliated with Atlassian, a context that plausibly motivates studying real deployment cost trade-offs (escalation to human on-call is explicitly priced at 520 units, the highest tier). The work is methodologically careful: it distinguishes construct-validity oracle controls from information-fair LLM competitors, refuses to cross-compare workspace vs. tool-API costs because their accounting differs, ships integrity-bound result artifacts (every episode bound by task-file SHA256, canonical task SHA256, task IDs, family counts, agent names, and budget labels), and provides a regression smoke-test layer that injects each failure mode (leaked answers, tampered bindings, over-broad redistribution) and verifies the gate rejects it. The paper is transparent about what its numbers do and do not mean — e.g., explicitly noting that the workspace execution proxy `10 + 0.5T + 10M + 5N` is a systems-effort diagnostic, not a measure of economical tool choice.

## Critical Assessment

- **Novelty: high and well-positioned.** The framing — cost as a first-class task constraint with paired opposite-regime families — is genuinely distinct from GAIA/SWE-bench/WebArena/τ-bench (completion-focused) and complementary rather than redundant to CostBench (which targets dynamic cost-optimal planning rather than evidence-conditioned escalation and model-tier routing). The Econ = min(Up, Save) diagnostic is the standout methodological idea.
- **Rigor: strong on construct validity, weak on statistical power.** Main LLM runs are single-shot at temperature zero (one episode per task), so no variance or prompt-robustness is reported; the budget sweeps use one episode at each family-specific budget. Human realism review covers only 45/304 tasks (14.8%), and judge calibration uses a single human reviewer, so the paper estimates human–judge agreement but cannot estimate human–human agreement. Sonnet and GPT-5.4 happen to share the same +12.5-point judge-minus-human positive-rate gap in the calibration sample, which the authors correctly flag as not equivalence.
- **Reproducibility: unusually strong.** Single-wrapper rebuild, deterministic salted-hashing selection, SHA256-bound artifacts, offline model-tier labels (no live model calls at evaluation time), and public seed datasets (GAIA, HotpotQA, MuSiQue) make the bundle independently reconstructible. The perturbation analysis of cost ordering is a nice robustness check.
- **Significance: a real gap-filler.** The central negative result — that budget compliance is not budget conditioning, and that micro-accuracy systematically rewards one-sided policies — is actionable for agent-controller design (estimate marginal value of the next action, separate "is evidence sufficient" from "can I afford it"). The paper does not overclaim: it explicitly states the families are regime-level diagnostics, not item-level counterfactual pairs.
- **Red flags / specific weaknesses.** (1) For several QA families "grounded" means the episode accessed evidence, not that a cited span entails the answer — the grounding check is deliberately coarse, which inflates strict-success relative to a true entailment check. (2) Stop-loss scoring accepts evidence-backed abstention without requiring the canonical deep-research confirmation, so a cheap-stop policy can score without exhibiting the intended verify-then-abstain behavior. (3) Workspace templates differ by family and may cue the action class (e.g., revealing the escalation interface), so workspace results are interface-level measurements, not prompt-independent routing estimates — the authors acknowledge this but it limits how far the Opus-leads result generalizes. (4) The 222/82 Up/Save split is a grouping of families, not a count of optimal action directions (the answerable subset is actually 57.5% costlier / 42.5% cheaper / 10 stop), which a careless reader could misread. (5) Costs are abstract units calibrated to 2026 Google/Perplexity public prices; the authors are explicit that claims are about relative action cost, not transfer to a specific deployment's billing.

## Strengths

- The Econ = min(Up, Save) diagnostic elegantly exposes one-sided policies that micro-averaged accuracy rewards — this is the paper's most exportable idea and should be adopted by other cost-aware benchmarks.
- Real-derived tasks (not authored to illustrate a trade-off) with paired opposite-regime families make the benchmark harder to game than single-direction suites.
- Honest separation of three failure sources (selection error, execution error, budget error) per episode enables action-level diagnosis rather than a single score.
- Exceptional reproducibility infrastructure (wrapper rebuild, integrity-bound artifacts, regression smoke tests, offline model-tier labels, perturbation robustness analysis).
- The threshold-crossing budget sweep is a clever experimental design that directly tests the paper's core hypothesis (does action selection respond to budget?) rather than reporting cost only post hoc.

## Limitations

- Statistical power is thin: single-shot, temperature-zero runs with one episode per task; no variance, no prompt robustness, no seed variation.
- Human realism review covers only 14.8% of the bundle (45/304); the remaining 85% rely on automated gates whose coverage of subtle realism issues is unverified.
- A single human reviewer for judge calibration cannot bound human–human agreement.
- Episode-level grounding is coarse for QA families — it verifies evidence access, not entailment from a cited span.
- Costs are abstractions (intentionally), so absolute deployment-cost claims are out of scope; only relative action-cost claims are licensed.
- Workspace-CLI results cannot support cross-track cost, Pareto, or tool-economy claims because the workspace harness does not recover the agent-visible priced action sequence (it uses a post-hoc runtime/edit proxy).
- Workspace templates may leak the available escalation interface by family, confounding prompt-independent routing.
- The 10-task stop-loss family is small relative to the 294 answerable QA tasks, so abstention behavior is the least-powered measurement.

## Relevance

与"成本感知的 LLM agent / 工具选择 / 模型路由"这一研究方向高度契合：本文把"预算约束下的动作选择"提升为一类可评测的独立能力，并提供了诊断单边策略的 Econ 指标和真实派生的对照实验床，对研究"何时升级到更强的工具/模型、何时止损"的 controller 设计有直接价值。

## Questions for Further Exploration

- How does Econ = min(Up, Save) behave under prompt and seed variation — would the Tool-API vs. workspace gap shrink with multi-shot averaging or a routing-specific prompt?
- Can a controller that explicitly estimates marginal value of the next action (as the discussion proposes) recover both regimes, and does EcoAgent-Bench's per-episode selection/execution/budget breakdown predict where such a controller helps most?
- Would replacing the coarse episode-level "grounded = accessed evidence" check with span-level entailment change the leaderboard ordering, especially for Gemini and GPT-5.4 which frequently abstain?
- Is GPT-5.4's near-zero escalation rate (0% → 2.6%) an artifact of the balanced prompt, or a robust property of the backbone — and does explicit budget-awareness injected into the action-selection rule (not just the prompt) move it?
- How do results transfer when abstract units are replaced with a real deployment's dollar prices, given the 100% / ≥99.90% cost-ordering preservation under R=2/R=3 perturbation?
- Does the asymmetric-and-misdirected budget response (GPT-5.4 under-buys required escalation while Gemini over-buys unnecessary escalation) persist across model generations, or is it specific to the 2026 backbones tested?
