> **一句话总结：** SkillZip 把 Agent 技能库从"整包检索 + 文本压缩 + 任务期构图"改为统一的"节级过程子图"，用 MotifZip 在保留接口/依赖/验证器契约的前提下把重复子图重写为可逆宏，在 SkillsBench / ALFWorld 上比最强基线 SkillDAG 最高提升 12.2 分，同时把活跃存储压缩 71.0%、把在线渲染上下文压到 1,941 tokens。

> **TL;DR:** SkillZip reframes agent skill libraries as source-grounded, contract-bearing section-level procedural graphs, then compresses recurring contract-valid motifs into reversible macros (preserving boundary ports, dependency closure, verifier reachability, and source pointers) and hydrates only the minimal dependency-closed context per task; on SkillsBench it lifts reward from 27.3 (SkillDAG) to 33.3 with MiniMax-M2.7 (and 36.8→43.0 with gpt-5.2-codex), on ALFWorld it lifts success from 67.1% to 79.3% (+12.2 points), while achieving a 3.46× compression ratio with 99.2% dependency preservation and 98.7% verifier reachability, and 71.0% active-storage reduction.

## 核心贡献

- **统一的节级过程单元（Sec2Graph）**：把每个技能包拆成 9 种执行角色（Intent/Trigger/Input/Precondition/Operation/Resource/Failure/Verifier/Output）的类型化节，连成带依赖、资源、验证、修复边的可执行过程子图，解决"检索粒度=整包"的不匹配问题。
- **契约保持压缩（MotifZip）**：用带类型的属性图语法挖掘重复 motif，仅当接口稳定、依赖闭包、验证器可达、源指针可还原时才把它提升为可逆的 ported 宏，用 MDL 式增益评分（含 Reuse 奖励、Cut/Risk 惩罚）筛选；并以 Proposition 1（结构化可复合还原）证明宏重写 + 源展开是同构保持的。
- **预算化可执行上下文（PathHydrate）**：任务锚定 → 双层（节级/技能级）RRF 融合种子 → 约束子图搜索 → 向前/向后补全验证器与输入 → 按需以 name/contract/outline/source 四档水合宏；预算是"允许额"而非"配额"，达到可执行充分性即终止。
- **执行感知增量维护（ReZip）**：新技能到来时按端口契约匹配复用既有宏，跨技能支持数 ≥ m 才提升新宏；用执行证据（展开率、验证失败率、下游修复代价）对高风险宏做 demote/split/retire，使压缩库随库演化保持可执行。
- **可扩展 + 即插即用**：在 6 个 LLM backbone 上无微调即用；库从 200 扩到 100K 技能时相对 SkillDAG 的 Ret@1 优势从 6.2 扩大到 23.3，在线检索+水合延迟在 100K 仍 <250ms（248.3 ms）。

## Key Contributions

- **Section-level procedural memory unit (Sec2Graph).** Decomposes each skill package into nine typed execution roles and builds executable procedural subgraphs with typed dependency, resource, verifier, and repair edges plus skill-membership edges — making internal reuse visible without manually splitting the library.
- **Contract-preserving compression (MotifZip).** A typed attributed graph grammar mines recurring motifs and promotes them to *ported* macro nodes only when interface stability, dependency closure, verifier reachability, and reversible source expansion all hold. Proposition 1 (Compositional Structural Lifting) proves that simultaneous macro rewriting followed by source expansion is identity-preserving up to typed-dependency and operation-to-verifier isomorphism.
- **Budgeted executable hydration (PathHydrate).** Task anchoring, dual-level seed fusion via reciprocal-rank fusion (skill-description + node-max rankings), constrained subgraph search, scaffold closure repair (backward for Input/Precondition/Resource, forward for Failure/Verifier/Output), and four-level progressive macro hydration (name → contract → outline → full source). Hydration is sufficiency-gated, not budget-filling.
- **Execution-aware incremental maintenance (ReZip).** New-skill assimilation reuses existing macros via typed-port matching and only promotes new macros after cross-skill support threshold *m* is met; execution traces (expansion rate, verifier-failure rate, downstream repair cost) drive demotion, splitting, or retirement of risky macros, so the compressed library stays executable as it evolves.
- **Plug-and-play procedural-memory layer.** Works without backbone-specific fine-tuning across MiniMax-M2.7, gpt-5.2-codex, Qwen 3.5, Kimi K2.5, Claude Sonnet 4.5, and Gemini 3 Pro, on both technical (SkillsBench) and embodied (ALFWorld) benchmarks; scales from 200 to 100K skills with sub-250ms online retrieval+hydration latency.

## Methodology

SkillZip is organized as a four-stage pipeline over a shared **unified procedural graph** (Figure 2):

1. **Sec2Graph — building procedural subgraphs.** A skill package is segmented using headings, lists, code blocks, warnings, argument descriptions, tool references, and tests as boundary cues; a model-assisted parser refines boundaries while preserving source pointers. Each candidate section is assigned an execution role `τ = InferRole(b)` (e.g., "infer the delimiter" → Operation, "verify row counts unchanged" → Verifier). Contract extraction populates typed I/O signatures (X^v, Y^v), resources R^v, and guards/verifier conditions G^v. Edges: weak-order (local order), dependency (Requires/Binds/UsesResource), verifier, repair, and skill-membership. Cross-skill reuse is exposed by linking compatible occurrences to canonical *prototype* nodes (without erasing occurrence identity or source pointers).

2. **MotifZip — contract-preserving compression.** Avoids unrestricted frequent-subgraph mining: candidate generation starts from *execution interfaces* — sections are bucketed by role signature, resource family, and I/O shape, then grown along dependency and weak-order edges (`C = GrowMotifs(BucketBySignature(G), G)`). Each candidate motif must pass **contract validation**: (a) interface stable across occurrences, (b) execution closed (dependencies internal or exposed as ports), (c) every state-changing operation keeps a reachable verifier. Accepted motifs become typed graph-grammar production rules `M_g[I_g, O_g] ⇒ (V_g, E_g, π_g, χ_g)`. A compression-gain score
   `Δ(g) = freq(g)·L(g) − L(M_g) − L(rule_g) + α·Reuse(g) − λ·Cut(g) − μ·Risk(g)`
   selects macros greedily (descending Δ, conflict-aware). Macros can be rendered at name / contract / outline / full-source levels.

3. **PathHydrate — budgeted executable context.** `AnalyzeTask(q, p)` produces a task object `z_q = (g_q, O_q, Γ_q, I_q, D_q, {d_i})`. Dual-level seed fusion scores each section node by `max{cos(e(d_i), e(v)), cos(e(q), e(v))}` then fuses section- and skill-level rankings by reciprocal-rank fusion. A constrained subgraph search minimizes `η·T(P) + β|P| + γ·E(P) − δ·Match(P, q)` subject to anchor coverage, dependency closure, verifier reachability, and `T(P) ≤ B`. Scaffold repair walks backward for Input/Precondition/Resource and forward for Failure/Verifier/Output; closure returns `(P, ξ_q)` recording restored or infeasible roles. Macro hydration picks the lowest sufficient level and expands only when a needed input, guard, verifier, or source pointer is missing.

4. **ReZip — incremental maintenance.** Models update as a transition `Z_{t+1} = ReZip(Z_t, u_t)` where `u_t` is a new skill or execution trace. New skills are matched against existing macros via typed ports and contract aspects; unmatched regions enter a residual buffer `B^res_t`. A residual motif *r* is promoted only when `supp_t(r) ≥ m ∧ Δ(r) > 0 ∧ Valid_χ(r) = 1`. Execution-aware revision scores each macro by `ρ_t(M) = λ_e·n_exp/n_use + λ_v·n_fail/n_use + λ_d·c_repair/n_use`; persistent risk triggers demotion (raise hydration → split into narrower rules → retire to source sections). Every revision retains source-grounded expansion so the executable-subgraph lifting invariant holds at every step.

A key theoretical result (Proposition 1) links compression to execution: MotifZip rewrites only regions whose recorded source structure can be recovered compositionally, and PathHydrate relies on this guarantee. The guarantee is structural, not semantic — it recovers recorded interfaces/dependencies/verifier paths/provenance, but does not validate the correctness of unrecorded behavior or of a verifier itself.

## Results & Highlights

**End-task performance (Table 1):**
- On **SkillsBench** with **MiniMax-M2.7**, SkillZip reaches **33.3 reward** vs the strongest baseline **SkillDAG 27.3 (+6.0)**; with **gpt-5.2-codex**, SkillZip reaches **43.0 vs SkillDAG 36.8 (+6.2)**.
- On **ALFWorld** with MiniMax-M2.7, SkillZip reaches **79.3% episode success** vs SkillDAG 67.1% — a **+12.2 point** gain, the largest delta reported; with gpt-5.2-codex the gap narrows to **96.4% vs 93.6% (+2.8)** because SkillDAG already saturates the benchmark.
- **Ret@1 on SkillsBench (MiniMax)** rises from SkillDAG's 66.7 to **73.6**, and Ret@5 from 78.2 to **92.0** (MRR 71.3 → 81.3, +10.0).

**Compression & structural fidelity (Table 2):**
- SkillZip achieves a **3.46× compression ratio** with **DPR (dependency preservation) = 99.2%** and **VR (verifier reachability) = 98.7%**, while average rendered context drops to **1,941 tokens** (vs 6,716 for the raw section graph).
- Text-only compression (LLMLingua-2) reaches the same 3.46× ratio but collapses DPR to **65.0** and VR to **60.0**, with **45.0% of queries** requiring recovery from source — vs SkillZip's 14.8%. Its reward falls to 25.5, proving "shorter context alone is not executable context."

**Active storage (Table 4):** SkillZip reduces active storage from **18.6 MB → 5.4 MB (71.0% reduction)** while keeping the 112.4 MB source library unchanged for reversible expansion; downstream inflation (DI) is only **2.7%** vs 23.4% for SkillZip-without-checks.

**Scalability (Table 6):** As the library grows 200 → 100K skills, SkillDAG's Ret@1 drops 30.3 points (72.1 → 41.8) while SkillZip drops only 13.2 (78.3 → 65.1); the gap widens from **6.2 to 23.3 points**; similar-skill confusion stays at 12.4% (SkillDAG reaches 48.2%); online retrieval+hydration latency reaches **248.3 ms at 100K skills** (4.77M section nodes).

**End-to-end agent cost (Table 11):** On 1K-skill SkillsBench with MiniMax-M2.7, SkillZip cuts total prompt tokens by **47.0%** (2.78M → 1.47M), tool calls by **21.7%** (36.9 → 28.9), and per-task wall time by **21.1%** (429.7s → 339.0s) relative to SkillDAG — while raising reward 27.3 → 33.3.

**Streaming maintenance (Table 12):** ReZip matches full recompression (3.64× vs 3.71× CR; 33.2 vs 33.6 reward; 98.6 vs 99.1 VR) at only **0.22× the cost**, and recovers from injected contract drift within 1.4 batches on average; static and append-only baselines degrade to 28.7/30.1 reward.

**Cross-backbone (Table 14):** Outperforms Vector Skills in **all 12 benchmark×backbone settings**; on SkillsBench the relative gain ranges **2.0×–3.2×** (e.g., MiniMax-M2.7 10.4 → 33.3 = 3.2×; Claude Sonnet 4.5 26.2 → 52.4; Gemini 3 Pro 19.3 → 44.4).

**Reliability (Table 13):** Over five matched runs with paired bootstrap CIs, SkillZip improves over SkillDAG by **+6.0 [3.8, 8.1]** on SkillsBench (MiniMax), **+12.2 [7.5, 16.8]** on ALFWorld (MiniMax), **+6.2 [4.4, 8.0]** on SkillsBench (gpt-5.2-codex), and **+2.8 [0.4, 5.2]** on ALFWorld (gpt-5.2-codex, p = .031); every CI excludes zero.

**Ablations (Table 3):** Removing section-level nodes is the most damaging variant — Ret@1 −6.9, reward −5.4, context +59.9%; removing dependency closure drops DPR to 82.3; removing verifier constraints drops VR to 76.4.

## Authors & Credibility

The paper is authored by a joint **UNSW + CSIRO** team (Xingyu Tan, Xiaoyang Wang, Wenjie Zhang at UNSW; Qing Liu, Xiwei Xu, Xin Yuan, Liming Zhu at CSIRO, several with dual affiliations). The same UNSW group previously published *Paths-over-Graph* (Web Conf 2025, ref [42]) on knowledge-graph-augmented LLM reasoning, which directly informs the PathHydrate design (reciprocal-rank fusion, constrained subgraph search). CSIRO's software/systems lineage (Liming Zhu) shows in the engineering rigor: atomic pseudocode in Appendix A, Proposition 1 with proof sketch, deterministic graph-grammar rewriting, and an unusually thorough 18-RQ experimental appendix that includes streaming maintenance, repeated-run statistics with paired permutation tests, failure attribution, and three illustrative case studies. Baselines are well-chosen and recent (SkillDAG arXiv:2606.03056, GoS arXiv:2604.05333, SkillsBench arXiv:2602.12670, SkillOps arXiv:2605.13716 — all 2026). The claim of "plug-and-play across six backbones without fine-tuning" is supported by Table 14. Credibility is high overall; the main caveat is that the field is moving fast and several cited comparators (SkillOps, SkillGraph, SkillRAE) are not directly benchmarked against.

## Critical Assessment

- **Novelty:** Genuinely novel framing. The "unit mismatch" diagnosis (skills retrieved as packages, compressed as text, graph-built only after retrieval) is sharp, and the section-level contract-bearing graph as a single object across all three stages is a real conceptual advance over whole-package retrievers (GoS, SkillDAG) and over text compressors (LLMLingua-2, SkillReducer). The MDL-style gain with explicit Risk/Cut penalties and the structural lifting guarantee (Proposition 1) are above the bar for the area.
- **Rigor:** Strong. Proposition 1 has a proof sketch with identification/expansion/composition steps; contract validation is broken into three independently-checkable conditions; the paired-bootstrap + permutation-test protocol in Appendix B.7 is the right statistical tool and is rare in this literature. Failure attribution (Appendix B.8) honestly assigns 42% of residual failures to the executor/infra rather than SkillZip.
- **Reproducibility concerns.** (a) The ALFWorld library has only **37 skills** and the headline "+12.2 points" lives there — a single, small, near-saturated setting; the SkillsBench numbers (1K skills) are more convincing. (b) SkillDAG already hits **93.6% on ALFWorld with gpt-5.2-codex**, so the +2.8 gain (p = .031) is real but the practical headroom is small and the authors acknowledge this. (c) The **LLM-assisted contract extraction** step (Sec2Graph) is provider-dependent and the authors concede preconditions/guards are extracted at only **88.7 F1 / 79.6 exact match**; under 40% synthetic corruption reward collapses from 33.3 to 24.1 and VR to 77.2, so the system's ceiling is bounded by extraction quality that the paper itself cannot fully control. (d) Offline construction cost at 100K (Table 9: 178 s for graph+MotifZip) is measured on **cached** records, explicitly excluding the LLM extraction stage — so the "scales to 100K" claim is structural-only. (e) The MotifZip greedy rewriting explicitly "does not claim global optimality over all overlapping motifs."
- **Missing ablations / weak points.** No direct head-to-head with SkillOps, SkillGraph, SkillRAE, or SkillReducer despite citing them; no comparison against an oracle contract extractor (would isolate the extraction-quality ceiling from the compression algorithm); the three case studies are self-described as "illustrative constructions rather than additional quantitative samples"; no real-world production-scale agent deployment (only two academic benchmarks).
- **Significance:** High if the contract-preserving idea holds up — it reframes skill-library compression from a token-count problem to a verifiable-executability problem, which is the right axis for agent reliability.
- **Red flags:** None severe. The framing of "outperforms the strongest baseline by up to 12.2 points" leans on the smaller ALFWorld benchmark; the SkillsBench numbers (+6.0/+6.2) are the more defensible headline.

## Strengths

- Principled, formally-grounded compression: typed graph grammar + three independent contract checks + structural lifting proof, rather than ad-hoc text rewriting.
- Reversibility baked in: every macro carries source pointers and an expansion rule, so compression never destroys information needed for execution or auditing.
- Excellent empirical breadth: 18 RQs, six LLM backbones, scaling from 200 to 100K skills, streaming maintenance, repeated-run statistics, failure attribution, and budget-sensitivity curves.
- Honest engineering: PathHydrate treats the budget as an allowance rather than a quota (1,941/3,000 tokens used; 51.7% of tasks under 2K tokens); ReZip costs 0.22× of full recompression for near-identical endpoint.
- The cost reduction is *coupled* with quality gain — total prompt tokens −47.0% while reward rises 27.3 → 33.3 — which is the ideal outcome for a compression method.

## Limitations

- Only two benchmarks; ALFWorld is small (37 skills) and saturating for strong backbones, so the largest headline delta (+12.2) is on the least stress-testing library.
- Whole pipeline hinges on Sec2Graph contract extraction, which is itself LLM-driven, provider-dependent, and weakest exactly where it matters most (implicit preconditions/guards: 79.6 exact match).
- Structural lifting guarantee (Proposition 1) does **not** validate the correctness of recorded contracts or verifiers — it only guarantees recovery of recorded structure. Bad contracts survive compression faithfully.
- Greedy MotifZip disclaims global optimality; no theoretical bound on approximation ratio.
- No comparison against several directly-relevant cited baselines (SkillOps, SkillGraph, SkillReducer, SkillRAE); no oracle-extractor control.
- Contract-corruption sensitivity (Table 5) shows graceful but real degradation: at 40% noise, reward 33.3 → 24.1, VR 98.7 → 77.2, fallback 7.2% → 34.7% — so the system is brittle under noisy upstream extraction.
- Evaluation is offline/academic; no deployment evidence under a real production agent workload with adversarial or out-of-distribution skills.

## Relevance

This paper is highly relevant to research on **LLM agent skill libraries and procedural memory at scale**: it directly tackles the central tension between compression efficiency and execution reliability when libraries grow to tens of thousands of overlapping skills, an open problem for building dependable long-horizon agents. The contract-preserving compression angle (interface + dependency closure + verifier reachability) and the section-level retrieval unit are immediately applicable to anyone designing retrievable, evolvable skill stores for tool-using LLM agents.

## Questions for Further Exploration

- How does SkillZip behave when Sec2Graph's contract extractor is replaced with an oracle, or with a much weaker model — i.e., how much of the headline gain is extraction quality vs. compression algorithm?
- Can MotifZip's greedy rewriting be replaced with a bounded-approximation algorithm, and does global optimality matter empirically given that the current greedy already hits 99.2% DPR?
- How does the system perform on out-of-distribution skills (e.g., a CSV-trained library evaluated on web-automation or scientific-computing tasks at arrival time, before ReZip has a chance to promote new macros)?
- Does the verifier-reachability guarantee actually reduce downstream verifier-failure rates in execution, or do recorded verifiers simply get recovered without being correct (the Proposition 1 caveat)?
- What happens under adversarial skill injection (skills crafted to look contract-compatible but with subtly different verifier semantics)?
- Can the section-level unit be combined with learned skill embeddings (rather than the current dense cosine matching) to improve the 26% retrieval-stage failure share identified in Appendix B.8?
