# StateGuard: Analytical-State Management with Validity-Aware Intervention for Long-Horizon Data Agents

> **一句话总结：** 针对长程数据分析 agent 中"上游中间产物（约束/变量/结论）失效后静默污染下游"的问题，来自人民大学高瓴人工智能学院的作者提出外置管理器 StateGuard：把分析过程外化为由约束、版本化变量、中间结论和五种关系（INIT/PROGRESS/BRANCH/INVALIDATE/COMBINE）构成的显式状态图，用可执行证据（语法编译、代码检查、执行检查、独立探针）做一致性验证，并按轻/重两级修复拦截错误传播；管理器本身是经过"反事实轨迹 SFT + 有效性奖励 DAPO 强化学习"训练的 Qwen3-8B 模型，挂接到 DeepSeek-V4-Pro 等 worker 上，把 LongDS 均值准确率从 44.53 提到 54.05（+9.52），并把依赖污染率 DCR 从 62.60 降到 56.70。

> **TL;DR:** StateGuard is an external runtime manager that turns an LLM data-analysis agent's implicit analytical progress into an explicit state graph (constraints, versioned variables, conclusions, typed relations), verifies each state against runtime evidence (compile, code inspection, execution check, independent probe), and applies hierarchical light/heavy repair before errors propagate. A Qwen3-8B manager is cold-started on 3K counterfactually-synthesized trajectories (teacher: DeepSeek-V4-Pro) and refined with DAPO using a validity-shaped reward (0.35 intervention + 0.30 grounding + 0.20 lifecycle + 0.15 action). Plugged into four frontier backbones, it lifts DeepSeek-V4-Pro's LongDS-Bench average accuracy from 44.53 to 54.05 (+9.52, 95% CI [1.69, 14.13]) and cuts Dependency Contamination Rate from 62.60 to 56.70, beating the no-manager baseline of the same worker+harness. Notably, only 74 repairs fire across all runs — most of the gain comes from persistent state hints, not error interception — and gains shrink to marginal/mixed on weak open-weight backbones like Qwen3-8B.

## 核心贡献

- **可执行分析状态外化：** 把长程数据分析的中间进展表示为显式状态 S_k=(I_k, C_k, V_k, N_k, R_k)——当前议题、约束、版本化变量、中间结论、与先前状态的语义关系（INIT/PROGRESS/BRANCH/INVALIDATE/COMBINE），构成状态关系图，使每个状态成为可执行、可验证、可依赖追踪的对象，而非文本记忆。
- **证据驱动的有效性验证与分层修复：** 状态生命周期 OPEN→UPDATE→验证→FINALIZE→COMMIT/REPAIR 由 harness 强制执行；验证结合 syntax_compile、code_inspection、execution_check、independent_probe 四类证据；检测到不一致时先给轻量修复提示，必要时由 harness 物理删除失效产物（重修复），失败则回滚或弃置状态。
- **管理器导向的反事实监督：** 从 DSBench/BIRD-INTERACT/IDA-Bench 原始任务合成带状态关系图的长程任务，再用 replay-then-live 反事实注入（修改上游状态、强教师模型修复、可执行运行时校验因果链）得到 3K 条轨迹，混合"原子决策样本+完整轨迹"做冷启动 SFT。
- **有效性引导的策略优化：** RL 阶段用 DAPO（8 rollouts/prompt），奖励分解为 R_action(0.15)+R_lifecycle(0.20)+R_support(0.30)+R_intervention(0.35)，并设 β_fp=1.0 > β_fn=0.3 重罚"误修复"轻于"漏干预"，把运行时有效性证据转成细粒度监督信号而非只看任务成败。
- **系统性实证：** 在 3 个基准、4 个前沿闭源 backbone + 3 个开源 backbone + 1 个专用 agent 上验证增益与 DCR 下降，附带聚类 bootstrap 置信区间、消融、运行开销测量和诚实的逐 turn 归因分析。

## Key Contributions

- **Executable analytical-state externalization:** Analytical progress is represented as states S_k = (issue, constraints, versioned variables, intermediate conclusions, relations) with five typed relations (INIT/PROGRESS/BRANCH/INVALIDATE/COMBINE) forming a state relation graph — each state is an executable, verifiable, dependency-traceable object rather than textual memory.
- **Evidence-grounded validity management + hierarchical repair:** A harness-enforced lifecycle (OPEN → UPDATE → verify → FINALIZE → COMMIT, else REPAIR) combines four complementary evidence tools (syntax_compile, code_inspection, execution_check, independent_probe); light repair sends a hint, heavy repair removes invalid artifacts, with rollback/ABANDON as fallback. The manager only hints — it never plans or answers.
- **Manager-oriented counterfactual supervision:** Long-horizon tasks are synthesized by instantiating state-relation graphs over raw DSBench/BIRD-INTERACT/IDA-Bench tasks; counterfactual interventions are replayed with a strong teacher (DeepSeek-V4-Pro) in an executable runtime, retaining execution-verified (τ+, τ−, τr) triplets (benign interventions as hard negatives) to yield 3K trajectories for cold-start SFT (atomic decisions + full trajectories).
- **Validity-guided policy optimization:** DAPO with a runtime-evidence reward R(τ) = 0.15·R_action + 0.20·R_lifecycle + 0.30·R_support + 0.35·R_intervention, where β_fp = 1.0 > β_fn = 0.3 deliberately over-penalizes false repair — turning validity evidence into fine-grained signals instead of outcome-only supervision.
- **Comprehensive empirical study:** Consistent gains and DCR reductions across 3 benchmarks and 8 backbones, with a paired cluster bootstrap CI, training/state ablations, measured runtime overhead, and an unusually honest turn-level attribution analysis.

## Methodology

**Problem and state model.** A long-horizon data-analysis task T = (q, D) is executed by a worker agent π producing trajectory τ = {(r_t, a_t, o_t)}. StateGuard replaces implicit history with a sequence of committed states S_k = (I_k, C_k, V_k, N_k, R_k): current issue, constraints, variables with versions, intermediate conclusions, and semantic relations to prior states. Relations come from {INIT, PROGRESS, BRANCH, INVALIDATE, COMBINE} and induce a state relation graph used for dependency tracing (e.g., a revised COGS value INVALIDATEs prior artifacts derived from the old one).

**Runtime architecture.** The manager is decoupled from task solving: the worker stays the sole executor; StateGuard maintains states and communicates only through a restricted interface (state hints / error hints). The action space splits into control actions A_ctrl = {OPEN, UPDATE, FINALIZE, REPAIR, COMMIT, RESUME, ABANDON, ABSTAIN} and tool actions A_tool = {CheckExecution, Compile, Probe, Trace}. The harness executes decisions and enforces valid transitions. Verification collects evidence e from the trajectory, related states N_k, and the executable runtime (up to 8 actions per activation, 3 repair attempts per state, 40,960-token context); the final judgment z_k ∈ {consistent, inconsistent} routes the state to COMMIT or REPAIR. Hierarchical repair: light repair injects a hint; heavy repair removes identified invalid artifacts via the harness; repeated failure triggers rollback to the last valid state or ABANDON, preventing contamination of downstream states.

**Training stage 1 — Manager-Oriented Counterfactual Supervision (SFT).** Relation-graph-based task synthesis takes raw tasks from DSBench, BIRD-INTERACT, and IDA-Bench, synthesizes a latent state-relation graph G*, and instantiates a long-horizon task covering progression, branching, invalidation, and composition. Executable counterfactual runtime synthesis then follows a replay-then-live procedure: the clean prefix is replayed exactly, a controlled intervention replaces a worker action at t*, and behavior after t* is generated live by the teacher (DeepSeek-V4-Pro); a trajectory is kept only if replay fidelity, intervention activation, demonstration consumption, lifecycle validity, and task completion all pass validation — yielding 3K manager-oriented trajectories. SFT trains the Qwen3-8B manager for 3 epochs at lr 5×10⁻⁵, batch 32, mixing atomic decision samples with full state-lifecycle trajectories.

**Training stage 2 — Validity-Guided Policy Optimization (RL).** Because outcome-only reward conflates manager quality with worker ability, the reward uses runtime validity evidence: R(τ) = 0.15·R_action (tool executions succeed) + 0.20·R_lifecycle (control actions legal at each lifecycle stage) + 0.30·R_support (state contents grounded in runtime evidence) + 0.35·R_intervention (repair issued exactly when an inconsistency exists, with q_i grading repair quality and β_fp=1.0 > β_fn=0.3 penalizing false repair more than missed intervention). Optimization uses DAPO with 8 rollouts per prompt, lr 5×10⁻⁷, batch 64, on VeRL with 8 NVIDIA A100 GPUs.

**Evaluation protocol.** Baseline and StateGuard runs share the identical worker, harness, adapter, and prompts — the baseline is literally the same stack with the manager disabled (Baseline = Worker + Harness; StateGuard = Worker + Harness + Manager). Backbones: GPT-5.5, Claude Sonnet 5, Kimi-K2.6, DeepSeek-V4-Pro (proprietary); Qwen3-30B-A3B/32B/8B (open-weight); DataMind (specialized), all under a unified ReAct-style interface.

## Results & Highlights

- **LongDS-Bench (68 tasks, 2,225 turns, 6 domains):** Attaching StateGuard lifts average turn-level accuracy for every capable backbone: DeepSeek-V4-Pro 44.53 → 54.05 (+9.52), Claude Sonnet 5 44.33 → 53.16 (+8.83), Kimi-K2.6 35.91 → 44.36 (+8.45), GPT-5.5 47.14 → 54.12 (+6.98). A paired cluster bootstrap over the 68 LongDS tasks puts the DeepSeek-V4-Pro micro-accuracy gain at +9.44 points with 95% CI [1.69, 14.13] over 10,000 resamples; only 0.59% of resamples are non-positive.
- **Dependency Contamination Rate (DCR, lower = better):** On DeepSeek-V4-Pro, average DCR across LongDS + DAComp-DE drops from 60.25 to 55.90 (LongDS: 62.60 → 56.70); GPT-5.5 improves 55.34 → 51.25. Ablations show DCR explodes without state maintenance: removing state validity maintenance raises DCR to 68.45 — worse than the plain ReAct baseline (62.60) — while LongDS accuracy falls to 40.77 vs 54.05 for full StateGuard.
- **DABstep (450 multi-step tasks; 72 easy / 378 hard):** Hard-subset accuracy rises for all frontier backbones — GPT-5.5 36.77 → 43.65 (+6.88), Kimi-K2.6 23.02 → 32.01 (+8.99), DeepSeek-V4-Pro 25.66 → 30.42 — with easy-subset accuracy also up (e.g., DeepSeek-V4-Pro 81.94 → 84.72).
- **DAComp-DE (repo-level data engineering, 4,000+ LOC, 30+ files):** Cascading-evaluated CFS improves for all four proprietary backbones (e.g., GPT-5.5 implementation CFS 24.68 → 28.91; implementation CS 62.14 → 67.32; DeepSeek-V4-Pro implementation CS 57.92 → 64.32).
- **Ablations (DeepSeek-V4-Pro worker, LongDS avg):** full model 54.05; prompt-only (no training) 47.50; w/o RL 51.78; w/o SFT (RL only) 31.65 — SFT is essential and RL alone disrupts execution; free-form memory manager reaches only 43.16 (≈ ReAct's 44.53), showing structured state maintenance — not extra model capacity or generic memory — drives the gain.
- **Honest attribution and overhead:** On LongDS, 350 turns improve and 140 regress (net +210), but only 73 turns (3.28%) are manager-attributable under a broad propagation criterion and 23 (1.03%) under a strict one; only 74 REPAIR actions fire across all four settings (0.20–0.52 per task), and 1,827 of 1,863 LongDS hints are state hints, not error hints. Manager cost: 33.1 reviews and 134.5 manager calls per LongDS task at ~18.4 s per call (Qwen3-8B served locally).
- **Weak-backbone caveat:** Gains are marginal or mixed for small models — Qwen3-8B improves LongDS avg 3.46 → 4.62 but regresses on Education (18.98 → 16.94) and DABstep-easy (47.22 → 44.45); several DAComp cells are undefined for weak models because DCR becomes uninformative when almost every unit is already wrong.

## Authors & Credibility

The paper comes from the Gaoling School of Artificial Intelligence, Renmin University of China — one of China's most established IR/LLM-agent groups. Zhicheng Dou (corresponding author) is a full professor with a long record in information retrieval and LLM-based agents; Yimeng Xu is also an author of LongDS-Bench, the primary evaluation benchmark used here, which gives the team direct familiarity with the evaluation protocol (and creates a self-evaluation proximity worth noting). The work is technically deep: it spans benchmark design sensibilities, trajectory synthesis infrastructure, and RL training on VeRL across 8 A100s, and the appendix (36 pages total) documents reward coefficients, prompts, DCR math, runtime measurement methodology, and failure cases with unusual care. An AI-use statement discloses that generative AI assisted language editing, code development, and generation of the synthetic training trajectories. No prior-release artifacts or code link is mentioned in the main text.

## Critical Assessment

- **Novelty is real but narrower than the framing suggests.** The reframing of analytical state as an executable, verifiable, dependency-traceable object — "memory tracks what was found; StateGuard tracks whether it is still valid" — is a genuinely useful distinction over memory-management and process-verification lines (AgentRax, memory-as-execution-state work). But the paper's own numbers reveal that the flagship "validity-aware intervention" mechanism is barely exercised: 74 repairs across all settings, 23 strictly manager-attributable turns (1.03% of 2,225), versus 1,827 state hints. In practice StateGuard behaves mostly as a *structured persistent-context manager*; the intervention story — and the 0.35 reward weight on R_intervention — supervises a pathway responsible for roughly 1% of the measured turn gains. A cleaner title would be "state maintenance with occasional intervention."
- **DCR gains are modest relative to the headline framing.** The paper positions error propagation as the core problem, yet DCR improves by only ~4–7 points (e.g., 62.60 → 56.70). And by the authors' own admission, DCR is low-information exactly where propagation matters most for weak models (|U₀| ≈ 0 makes it undefined), which is why several open-weight and DataMind DAComp cells are "—".
- **The gain structure is backbone-gated.** Gains are large only for frontier proprietary models (+7 to +9.5 LongDS points) and shrink to noise or negative for Qwen3-8B/32B (Education and DABstep-easy actually regress for Qwen3-8B). The paper is upfront about this ("complements rather than substitutes capability"), but "consistently improves" in the abstract glosses over regressions on two of three metric families for the weakest backbone.
- **Metric sensitivity is acknowledged but flattering.** The authors note LongDS's turn-level micro-average lets one early-turn fix lift many downstream turns simultaneously — precisely the setting where their state-hint mechanism (which keeps context consistent) shines; the manager-attribution analysis confirms this interpretation.
- **Rigor is above average.** Shared worker+harness for baseline and treatment, a cluster bootstrap CI, prompt/SFT/RL/state ablations, and a trace-based overhead decomposition (rather than raw wall-clock attribution) are all methodologically sound. LongDS turn scoring uses LLM judgment, however, which introduces judge variance the paper does not quantify, and DABstep paired case analysis is excluded because ground truth is withheld.
- **Reproducibility is partial.** Hyperparameters, hardware, and framework are documented, but the 3K SFT trajectories are generated by proprietary DeepSeek-V4-Pro under a replay-then-live pipeline with many hand-tuned gates, and no code/data release is stated; the counterfactual synthesis engine is the hardest part to reimplement.
- **Red flags are few but real:** the self-evaluation proximity to LongDS-Bench (shared author), the intervention-weighted reward never stress-tested (too few repairs to validate β_fp/β_fn tuning), and one honest failure case (Kaggle Survey 2019) showing a semantically-wrong-but-internally-consistent state sails through all four evidence checks and still propagates — the core limitation of local evidence-grounded verification.

## Strengths

- Clean problem abstraction: stale derived artifacts under evolving dependencies, with a concrete mechanism (typed relations like INVALIDATE/COMBINE) that maps naturally onto data-analysis workflows.
- Strictly controlled evaluation: baseline is the identical stack with the manager disabled — no confound from different prompts or scaffolds across compared systems.
- Two-stage training recipe (counterfactual SFT cold start → validity-shaped DAPO) is well-motivated: the ablation showing RL-only collapses to 31.65 while SFT-only reaches 51.78 is a genuinely useful finding about training orchestration-ordering for protocol-heavy agents.
- Transparency: paired bootstrap CI, explicit attribution of how few gains come from repair, published failure cases, and a per-benchmark runtime cost table (calls/task, seconds/call) that lets practitioners budget the review cadence.
- The manager-as-advisor design (hints only, harness owns execution) keeps the method composable across eight heterogeneous backbones without touching worker prompts.

## Limitations

- The external manager serializes at every review boundary: ~134.5 manager calls (≈18.4 s each) per LongDS task — the authors themselves flag internalization, distilled managers, and adaptive/event-triggered cadence as needed future work.
- Verification is local and evidence-based: no formal guarantees over the full dependency graph; semantically wrong but internally consistent states survive all four evidence tools and propagate (documented failure case).
- Effectiveness is strongly backbone-dependent: negligible-to-negative gains on weak open-weight models; DCR degenerates precisely where error propagation should matter most.
- Only one manager model (Qwen3-8B) and one teacher (DeepSeek-V4-Pro) are tested; no study of manager-size scaling or cross-teacher robustness of the synthesized trajectories.
- Training-data construction (relation-graph synthesis + replay-then-live counterfactuals) is complex and proprietary-model-dependent; no released code, data, or trajectories are mentioned.
- LongDS correctness relies on LLM-judge scoring; DABstep excludes paired case analysis due to withheld ground truth.

## Relevance

这篇论文正中你"长时程自主系统的可靠性与可信性"这一最高优先级方向：它把 agent 长程运行中最隐蔽的失败模式——上游产物失效后的静默错误传播——变成了可外化、可验证、可修复的对象，并给出了完整的训练方法（反事实轨迹合成 + 有效性奖励 RL）与诚实的归因分析。对于关注 self-evolving agents 在多阶段研究/数据分析流程中如何自我纠错的读者，其"状态即可验证对象"的设计模式和"干预信号稀少、收益主要来自持久状态上下文"的实证发现都值得借鉴。

## Questions for Further Exploration

- Could the 1.03% strictly manager-attributable turns be raised by an order of magnitude with stronger semantic verification (typed invariants, provenance-aware checks), or is the bottleneck the worker's willingness to act on repair hints?
- The reward puts 0.35 weight on R_intervention, yet only 74 repairs fire — is this reward term actually learnable, or is it starved by the harness's conservative repair gating?
- Would an adaptive review cadence (event-triggered on state uncertainty or dependency depth) retain the +9.5 LongDS gain at a fraction of the 134.5 calls/task cost?
- Does the counterfactual synthesis pipeline transfer to a fully open teacher (e.g., Qwen3-32B generating trajectories), and how large is the teacher-quality sensitivity?
- Can INVALIDATE-style relations compose with the agent's own planning — i.e., internalizing state awareness into the worker policy — rather than remaining an external serialized manager?
- How does StateGuard interact with naturally non-deterministic workers at temperature > 0, given that 140 regressing turns were partly attributed to worker stochasticity?
