01

How it works

方法速览

The harness — executable code around a frozen backbone — is decomposed as H = Compose(m1..m5) over five modules. A failure audit on D_evo trajectories abstracts recurring errors into capability gaps; two-tier arXiv retrieval queries run per module; TopicGPT-style prompted topic modeling clusters retrieved papers into semantically orthogonal mechanism families, with candidate budget allocated round-robin so it isn't wasted on near-duplicates.

A research agent (GPT-5.4) reads each full paper and emits a mutation blueprint — source mechanism, target interface, required state, termination conditions — which Codex implements behind unchanged interfaces, gated by executable health probes. Mutations score on held-out D_val; combinations are shortlisted by additive predicted gain, then jointly evaluated with an interaction residual z(c). A champion is retained only when the paired-bootstrap lower bound is positive; D_test stays frozen until every selection decision is made. Each new publication window restarts the search from the retained champion — that is the lifelong loop.

Strengths & Limitations

强弱对照

Strengths 优势

  • +Crisp problem framing — three failure modes of trajectory-only evolution (limited exploration, limited design knowledge, delayed adaptation), each mapped to a concrete mechanism.
  • +Exemplary evaluation hygiene — frozen D_test, budget-matched baseline, paired-bootstrap retention, 3 runs (finals checked over 9).
  • +Full provenance — every module traces to a named source paper + topic; three harmful candidates are excluded and named.
  • +The crossover analysis is a real finding — standalone scores mispredict compositional value, justifying joint evaluation.
  • +Honest negatives — residual failures catalogued, 106 regressions reported alongside 200 improvements for Mini.
  • +Lifelong results test the thesis directly — new publications yield monotone gains while the trajectory-only baseline stalls on identical windows.

Limitations 局限

  • −Only 3 runs — SDs up to ±4 points; several ablation deltas sit within one SD, and Table 2 has no significance testing.
  • −One interaction mode — both benchmarks are API-calling; no coding, web, or OS agents.
  • −Mid-tier backbones only — whether a frontier model (which may already internalize the design space) still benefits is untested.
  • −"Lifelong" is simulated — three offline, curated publication windows; no continuous deployment, no per-cycle token/compute cost accounting.
  • −Research-model confounder — no ablation isolates GPT-5.4's paper comprehension from the framework's structure.
  • −Proprietary dependencies — the loop needs GPT-5.4/5.5 via Codex despite the code release; failure-taxonomy labels lack human agreement stats.

Open questions

延伸追问
  1. Q1Frontier backbones: does the benefit vanish once the model already knows the design space (e.g. GPT-5.4 itself)?
  2. Q2Model vs framework: swap GPT-5.4 for a weaker reader/retriever — how much gain is the literature, how much the model in the loop?
  3. Q3Beyond API calls: does the module × topic search transfer to SWE-bench-style coding, web navigation, or OS agents?
  4. Q4Cost per cycle: tokens, wall clock, failed candidates — how does it compare with simply fine-tuning on D_evo trajectories?
  5. Q5Residual failures: can constraint violations (91→89) and incomplete retrieval (77→70) be targeted, or does the literature not yet describe the needed capabilities?
  6. Q6Better screening: can the additive score be replaced by a cheap learned interaction model to spend crossover budget better?
  7. Q7True deployment: how should publication windows be scheduled and deduplicated against trajectory-derived improvements (e.g. combined with Evo-Harness)?
