Method方法

An action, not a string: what “the call changed” should mean, how to observe it, and how to repair it.

emitted call →
  1. HOP 1serialization
  2. HOP 2host wrapper
  3. HOP 3shell parse
  4. HOP 4process interface
  5. HOP 5target parser
→ executed action

Any hop may rewrite the text — and the first tampering hop hides every later change: 38 of 69 path-caused failures appear only after the first hop is repaired, so single-hop observers undercount.

Define. A call's intended action is what its text denotes under the receiver's own language semantics, not the LLM's goal. Intent–execution correspondence (IEC) holds only if every hop receives that action; the first hop that doesn't is the first divergence, and it is silent when the tool result still reports success.

Observe. Witnesses read the text at each hop without executing anything — a BASH_ENV parser for Bash, documented command-line reconstruction for PowerShell, an argv probe at the process interface. The receiver's own parser decides, because string equality misclassifies 15 of 35 unchanged pairs (a\b vs a\\b) and LLM judges cost 20k+ tokens to be wrong.

Repair. IntAct re-renders the call into a channel the named hop cannot parse — native per-argument argv, Base64 -EncodedCommand, a sourced file — or refuses when none exists. The channel changes; the call, its cwd, environment, and side effects do not. See the repair ledger →

Strengths优势

Why the paper holds up.

  • Measured where it hurts — 47,828 production calls, 261 sessions, 203,710 public trajectories, not a synthetic hazard suite.
  • Deterministic and LLM-free — zero tokens per verdict, 0.1 s per Bash witness, receiver-native semantics that string comparison gets wrong.
  • Statistical discipline — negative control 0/187 (Fisher p<.001), exact McNemar, double-annotated human reference (κ 0.79/0.89).
  • The hiding-hop finding re-frames why single-hop monitors and trajectory judges systematically mis-attribute — the most transferable idea here.
  • End-to-end credibility — four deployed forms, 2.1–396 ms overhead; a commercial kernel went 197 changed invocations → 0.
  • Honest reporting — per-hop/per-harness tables, explicit non-results, a real threats-to-validity section.

Limitations局限

Where the claim stops.

  • Windows-shaped — on Linux only typed-interactive-Bash harnesses change calls; a POSIX-only agent may see almost none of the 10–12% headline.
  • Qwen/Hermes-only benchmark — no Claude, GPT, or Gemini on the 6 transports; the generality claim is untested on frontier models.
  • Small human reference — 102 failures / 115 pairs, 2 annotators, possibly aligned with the protocol's own conventions (mild circularity in κ=0.77).
  • Non-reproducible centerpiece — the production corpora are hashed company data; 10.0%/12.0%/80.7% cannot be independently re-derived.
  • Hand-engineered repairs — one rendering per known launch/hop; some calls must be refused (multi-line under cmd.exe), shifting cost back to the agent.
  • Scope — shell-family + structured JSON tools only; browsers, REPLs, and long-running processes are out.

Open questions待探索

Pulled from the summary's exploration agenda.

  1. Do Claude, GPT, and Gemini agents degrade the same way across the 6 transports — or do their harnesses already repair some hops?
  2. Could witnesses become a standard MCP-level contract where hops self-report the text they received, ending per-harness engineering?
  3. When does a loud divergence help an agent recover versus trap it? Retries fixed only 162/306 production failures, at 3.9× token cost.
  4. How should benchmarks combine “launch held fixed” reporting with the field's habit of comparing agents across heterogeneous harnesses?
  5. Do hidden-change dynamics exist for non-shell tools — browser automation, Python REPL state, database clients — where no formal grammar defines the contract?
