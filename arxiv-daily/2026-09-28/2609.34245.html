Key metric

0%

Why this matters

Lifts irreversible agent-action safety from prompt-level patches to certified guarantees — evidence must be counted by corruption domain, not by copy count.

Critical edge

The account field that actually moves money is secured by an allowlist, not the certificate — and the adaptive-attacker guarantee was never tested against a live LLM.

01

Methodology

threat model → per-field rules → counting → validation

Threat model. An agent proposes a payment built from action-critical fields — payee identity, amount, account. Each field rests on attestations from evidence classes with distinct corruption modes. An adversary corrupts up to k control domains, may launder copies, and rewrites after every refusal (adaptive). A trusted obligation skeleton from user intent bounds what untrusted evidence may fill — closing “sound for the wrong object” attacks.

Counting. Redundancy is a minimum hitting set over attestation dependency sets: laundered copies inherit their upstream corruption root and cast no extra vote (Prop. 3). Theorem 1: safe execution ⇔ singleton feasibility; the certifier meeting this bound is maximally live.

Validation. Model-free ablation harness; prevalence measurement over OpenSanctions, npm and PyPI; and a live OpenRouter loop — five models × 80 episodes (54 attacked, k=1 of N=5; 26 clean), plus a k=3 head-to-head against faithful CaMeL/FIDES and PCAS reimplementations.

  • agreement-or-escalateAll N corruption-distinct classes agree, else escalate — conservative, (N−1)-safe-with-abstention.
  • unique-thresholdA value clearing support ≥ N−k uniquely; safe iff N > 2k — the Byzantine bound per-predicate.
  • reconciliationDeterministic constraint bounding one field by another: invoice ≤ order + tolerance.
  • anchor gateSingle-sourced account field executes only on an onboarding-allowlist name match.

04

Strengths

  • Rare theory–experiment coupling: Theorem 1 and Props. 1–3 each instantiated by a specific experiment; ablation shows every mechanism load-bearing.
  • Corruption-distinct hitting-set count fixes copy laundering in prior counting-based certified defenses, with Prop. 3 giving the matching authentication requirement.
  • The prevalence study stands alone: SLSA provenance and repo back-references share the GitHub root — a concrete, checkable finding for supply-chain trust systems.
  • Honest scoping: four limitations stated up front, TCB enumerated, exact-value vs. safe-with-abstention carefully separated.
  • Faithful baseline reimplementations (not strawman refusal-only comparisons); code and data released; five frontier models, not one.
05

Limitations

  • No live-model adaptive attacker: the 2,000-world study attacks a model-free harness, not a live LLM optimizing injections against the full stack.
  • All corroboration counts are upper-bound proxies; true corruption-distinct coverage on sanctions data may sit below the reported ~25%.
  • Heavy TCB: unforgeable authentication, trusted anchors, a trusted join key, a sound extractor — each a deployment prerequisite.
  • The money-moving account field is allowlist-gated, not certificate-protected; novel-payee utility leans on a briefly described onboarding process.
  • Modest scale and scope: one action schema (payment), 80 episodes/model, 54/44 attacks; baselines are defense logic, not deployed systems.
  • Prevalence settings never run through the live agent loop; the end-to-end claim is validated only on the synthetic payment domain.
06

Questions for Further Exploration

Q1How does the certifier fare when a live LLM attacker adaptively crafts injections against the full stack — extractor included — rather than the model-free harness adversary?
Q2Can exact dependency sets be recovered in practice (e.g., provenance aligned to funding authority) to replace the upper-bound mapped-domain proxies?
Q3With ~75% single-domain sanctions coverage, what is the operational availability cost — and can anchors and corruption radii combine adaptively per field?
Q4Does the framework extend to free-text or semi-structured fields where canonicalization is unavailable and the extractor is itself a contested control domain?
Q5How would the certificate compose with single-source benchmarks like AgentDoom — is there a middle regime between gating and multi-source admission?
