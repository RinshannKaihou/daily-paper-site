> **一句话总结：** 提出 HADA——用"超代理 + 任务代理"双 LLM 编码代理做递归自改进（任务代理改 MetaBBO 代码，超代理改任务代理的提示词乃至自身），把元黑盒优化器（MetaBBO）的设计本身自动化：从一个仅用 DQN 调节 DE 的 F/Cr 参数的朴素 MetaBBO 出发，经 100 步开放式代码演化（Perf 从 0.577 升至 0.971），在 24 个 COCO-BBOB 留出函数上平均得分 0.9674，超过最强 MetaBBO 基线 GLEET 的 0.8942（+7.3 分），并在 4 项分布外泛化设置中全部领先。

> **TL;DR:** HADA reframes the design of Meta-Black-Box Optimization (MetaBBO) algorithms as an open-ended coding task for two LLM agents: a task agent continuously edits the MetaBBO codebase while a hyper agent edits the task agent's prompt — and itself — yielding recursive self-improvement in the Darwin Gödel Machine lineage, with history kept in an Algorithm Evolution Tree (AET). Starting from a naive DQN-DE MetaBBO (DQN configuring DE's F/Cr) and using DeepSeek-V4 as backbone over a 100-step evolution budget, the evolved optimizer scores 0.9674±0.0078 average Perf on 24 held-out COCO-BBOB instances vs 0.8942±0.0086 for the strongest MetaBBO baseline GLEET (+7.3 points; the paper's eye-catching "+121.7% leap" normalizes this gain by the GLEET-vs-CMAES gap) and beats GLEET in all four out-of-distribution settings (e.g., UAV path planning 0.798 vs 0.767). Ablations show the modifiable meta-policy is the key ingredient (0.9674 vs 0.9039 frozen), and step-by-step logs reveal an interpretable design trajectory culminating in a step-63 "aha moment" (0.918→0.971).

## 核心贡献
- **范式创新（首个自动化 MetaBBO 设计的框架）**：此前的元黑盒优化（MetaBBO）中，元层策略架构、决策特征、RL 训练管线、低层优化器均由人类专家逐例手工设计；HADA 把"设计 MetaBBO"本身变成编码任务，引入开放性（open-endedness），是自动设计"学习型优化算法"的首次探索。
- **双代理递归自改进机制**：任务代理（task agent）按超代理的指示修改 MetaBBO 工程代码（演化算法层 + 元学习层）；超代理（hyper agent）可修改任务代理的提示词并修改自身——即"学会如何改进"的能力本身也被演化，作者展示了演化前后 prompt 的显著差异（如强制"必须替换搜索算子、禁止只调参数"的硬规则）。
- **算法演化树（AET）+ 统一评估协议**：类 git 的树状历史管理，父代按"性能得分 + 子代数量"加权采样（平衡探索/利用，借鉴 Darwin Gödel Machine）；所有问题域统一为 0–1 归一化 Perf 分数（跨问题、跨域可比），并记录代码、补丁、领域知识、日志与得分的 Info 字典供代理反思。
- **实证闭环**：4 个优化域（单目标 BBOB、约束优化、多目标 WFG、真实无人机路径规划 MeBox-v2）、17 个 BBO/MetaBBO/LLM 基线、分布外泛化、跨域迁移、3 组消融（元策略可改性、初始优化器、5 种 LLM 后端）与同 token 预算下的 LLaMEA 对比；并开源完整演化日志，逐步解读出"低层优化器替换 → 结构新颖性约束 → 元学习层设计 → 局部搜索融合"的设计原理。

## Key Contributions
- **Paradigm innovation — first framework to automate the design of MetaBBO itself**: removes the hand-crafted, subjective human design of meta-level policies (network architecture, decision features, training pipeline, low-level optimizer) by recasting the MetaBBO design loop as a coding task for advanced LLM coding agents.
- **Bi-agent recursive self-improvement**: the task agent refines the target MetaBBO codebase; the hyper agent opens up open-endedness by editing the task agent's prompt *and its own instructions/code*, with before/after prompts (Appendix B) showing evolved hard rules like mandatory optimizer replacement and rejection of parameter-only tweaks.
- **Algorithm Evolution Tree (AET) + unified evaluation**: a git-like history where parents are sampled by performance score and number of children (exploration/exploitation trade-off borrowed from Darwin Gödel Machine), plus a domain-agnostic 0–1 normalized Perf metric and an Info dictionary (code, patches, domain knowledge, logs, scores) that grounds agent reflection.
- **Comprehensive empirical validation**: 4 optimization domains and 17 baselines show the evolved MetaBBO reaches 0.9674 avg Perf on held-out COCO-BBOB vs 0.8942 for SOTA MetaBBO GLEET, leads all four OOD generalization settings, transfers positively across domains, and the paper releases complete evolution logs enabling the step-by-step interpretability analysis (0.577 → 0.920 → 0.877 → 0.918 → 0.971).

## Methodology
**Setting.** MetaBBO is a bi-level scheme: a meta-level learnable policy π_θ (trained over a distribution P of training problems) makes online design decisions for a low-level optimizer, maximizing expected performance improvement J(θ) = E Σ R(s_t, π_θ(s_t; θ); p). All existing MetaBBO variants (RL-based, pretrained-model-based, LLM-based, meta-evolution-based) still require humans to design the meta-policy architecture and low-level optimizer.

**HADA workflow.** HADA takes two editable inputs: (1) a target MetaBBO Python project M (meta-level policy + low-level optimizer + problem interfaces + training logic + testing procedure, ~4 file types as in MetaBox platforms), and (2) two LLM coding agents: a *hyper agent* A_hyper and a *task agent* A_task. For H = 100 evolution steps: (i) sample a parent project from the Algorithm Evolution Tree (AET) — parent selection probability ∝ performance score, penalized by number of children, with all non-zero-score nodes getting non-zero probability; (ii) the hyper agent, given the in-execution Info dict (current sourcecodes, all patches, domain knowledge, evaluation logs, scores {Perf_{i,j}}), modifies its own and the task agent's prompts (and may modify the project itself, though it rarely does); (iii) the task agent modifies the sampled parent project into a child M^(t); (iv) the child is evaluated and inserted into the AET with its Info.

**Evaluation protocol.** Per-run score Perf_{i,j} = (f_i* − f_{i,j,t}) / (f_i* − f_i) for minimization — a 0–1 normalized, domain-agnostic metric (syntax/runtime errors score NA). During evolution the project is trained 5 epochs and tested over 3 independent runs (proxy); the final best project is re-trained 20 epochs and tested over 10 independent runs. Backbone: DeepSeek-V4 for both agents; max output length 2e4; runs on an 8-core Intel Xeon Platinum CPU with 16 GB RAM.

**Naive start ("zero" baseline).** The initial MetaBBO project M^(0) is DQN-DE: a 3-layer MLP Q-network (128 hidden units, 36,761 parameters, 25 discrete actions = 5 F × 5 Cr values) that adaptively configures the mutation factor F and crossover rate Cr of DE/rand/1/bin (population 5d), trained with experience replay (binary improvement reward, buffer 1000, batch 64, γ=0.99).

**Testbeds.** (1) Single-objective: 24 rotated/shifted COCO-BBOB instances (20D, 1e4 FEs); (2) Constrained: 54 COCO-constrained instances (20D, 1e4 FEs); (3) Multi-objective: nine 5-objective WFG functions (3D, 2e3 FEs, normalized hypervolume); (4) UAV path planning: 56 instances from MeBox-v2 (30D, 1.5e3 FEs), reduced to single-objective by weighted sum. Baselines span handcrafted BBOs (DE, SHADE, JDE21, MADDE, CMAES; L-SHADE-BOC, al1-CMA-ES, BP-tMag-ES, MDE-CGO; GDE3, SPEA2, NSGA-III, RVEA, MOEA/D, C-TAEA, R-MOMAD), MetaBBOs (RL-DAS, DQN-DE, LDE, GLEET; MetaCO, LAMDE; MADAC), and the LLM-based design framework LaMaBAO/LLaMEA (van Stein & Bäck) — with baseline hyperparameters tuned via hybrid search.

## Results & Highlights
- **Main single-objective result (Tables 1–2, 24 held-out COCO-BBOB instances, 20D/1e4 FEs, 10 runs):** HADA averages **0.9674±0.0078** vs **0.8942±0.0086** for the strongest MetaBBO baseline GLEET (+7.3 points, +8.2% relative) and 0.8831 for its own DQN-DE starting point; the weakest baseline CMAES scores 0.8342. The headline "121.7% performance leap" is computed as (HADA − GLEET)/(GLEET − CMAES) = 0.0732/0.0600, i.e., the gain over GLEET measured in units of the CMAES→GLEET gap; the intro reports analogous leaps of 114.7% (constrained) and 104.3% (multi-objective).
- **Hardest composite functions show the largest gains:** on f23 HADA reaches 0.9189 vs GLEET 0.5924 (+0.33); f19 0.9382 vs 0.8200; f24 0.9175 vs 0.8017 — Griewank/Rosenbrock/Katsuuras/Lunacek bi-Rastrigin composites where all baselines struggle. HADA is column-best on most but not all functions: it loses f21 to MADDE (0.9358 vs 0.9963) and f22 to SHADE (0.9420 vs 0.9755).
- **Out-of-distribution generalization (Fig. 2, zero-shot transfer, 3 MetaBBO baselines):** HADA leads all four settings — 10D/5e4 FEs: 0.985 vs GLEET 0.973; 20D/1e5: 0.978 vs 0.967; 40D/2e5 FEs: 0.954 vs GLEET 0.939 / RL-DAS 0.931; realistic UAV path planning (30D): 0.798 vs GLEET 0.767 / RL-DAS 0.741.
- **Ablations (Table 4, unified evaluation):** making the meta-level policy modifiable is the single most important component: 0.9674 with vs 0.9039 without (+6.4 points); DE beats PSO as the initial low-level optimizer (0.9674 vs 0.9421); among LLM backbones DeepSeek-v4-pro is best (0.9674) ahead of GPT-5.5 (0.9617), Grok-4 (0.9588), Kimi-k3 (0.9542), Qwen3.7-Max (0.9521).
- **Evolution trajectory (RQ3, single-objective):** Perf climbs 0.577 → 0.920 by step #4 (hyper agent forces low-level optimizer replacement, yielding a SHADE-like variant), dips to 0.877 (#9) then recovers to 0.918 (#24) after a rollback with formal "structural novelty" criteria, and hits 0.971 at step #63 — the paper's "aha moment", where the meta-policy is fed optimization-progress information and the low-level optimizer integrates local search with multiple optimizers (PSO/ES variants). Under the same token budget, HADA reaches ~0.971 while LLaMEA plateaus around ~0.93 (Fig. 5).
- **Cross-domain adaptation (RQ4):** initializing HADA's constrained/multi-objective runs from the single-objective optimum transfers positively; the adapted variants top the box plots on COCO-BBOB-Constrained (vs LAMDE, MetaCO, MDE-CGO, etc.) and the WFG suite (vs MADAC, R-MOMAD, etc.).

## Critical Assessment
- **The headline percentages are a framing choice, not raw gains.** The "+121.7%" is (HADA − GLEET)/(GLEET − CMAES); the plain relative improvement over GLEET is +8.2% (0.9674 vs 0.8942). The sentence "using the worst-performing CMAES as baseline, HADA improves upon the SOTA MetaBBO (GLEET) by 121.7%" is genuinely confusing on first read, and the constrained/multi-objective leaps (114.7%/104.3%) cannot be checked from the paper because those domains are reported only as box plots (Fig. 4) with no numeric tables.
- **"From zero" is overstated.** The starting point is not a blank slate but DQN-DE, a competent MetaBBO already averaging 0.8831 on the official benchmark (0.577 is the noisier 3-run proxy score during evolution). The evolution's net official-benchmark gain over its own starting configuration is roughly +0.08 — real, but far from "evolving from zero".
- **No statistical significance testing anywhere.** All comparisons are 10-run means ± std with shaded column-bests; several per-function gaps are within ~1 std, and HADA demonstrably loses f21 (0.9358 vs MADDE 0.9963) and f22 (0.9420 vs SHADE 0.9755). A Wilcoxon-style analysis over the 24 functions would substantially strengthen the claims.
- **Single evolution run.** The entire framework's outcome rests on one AET trajectory of H=100 steps; variance across independent HADA evolution runs (different seeds/samples) is never reported, so the reliability of the search process itself is unquantified. Proxy evaluation (5 epochs/3 runs) also selects what the final 20-epoch/10-run eval re-measures — a mild selection-bias channel the paper does not analyze.
- **Reproducibility nits.** The LLM backbone is named inconsistently (DeepSeek-V4-Pri in Sec. 4.1, DeepSeek-v4-pro in Table 4, "deepseek-v3.2" in Algorithm 1's pseudocode); the code link is an anonymous 4open.science repository, and the compute cost of the 100-step evolution (tokens, wall-clock, dollars) is only partially addressable via the Fig. 5 token comparison (~2.5M tokens on the single-objective domain).
- **Novelty is real but compositional.** The parent-sampling rule, AET-style history, and self-modifying-agent template are explicitly borrowed from the Darwin Gödel Machine line (Zhang et al.); the contribution is the first careful instantiation and empirical validation of open-ended recursive self-improvement *for optimization algorithm design*, plus the unified evaluation harness — not a new search mechanism.

## Strengths
- First-mover on a well-motivated question: MetaBBO design itself was still hand-crafted; HADA removes the human from that loop with minimal input (a naive codebase + two agents).
- Unusually thorough empirical protocol for this literature: 4 domains, 17 baselines with tuned hyperparameters, OOD generalization, cross-domain transfer, 3-axis ablations (policy modifiability, initial optimizer, 5 LLM backbones), and a token-matched comparison against LLaMEA.
- The interpretability analysis is a model for the field: complete evolution logs released, with an honest narrative including the 0.877 dip and rollback, and concrete emergent design principles (mandatory structural novelty, optimization-progress features in the meta-policy, local-search hybridization).
- The ablation isolating policy modifiability (0.9674 vs 0.9039) directly substantiates the central "open-endedness matters" thesis rather than leaving it as philosophy.
- Robustness across backbones is encouraging: every tested LLM yields ≥0.95, so the framework is not chasing a single vendor's quirks.

## Limitations
- Confined to continuous optimization domains (single-objective, constrained, multi-objective, UAV path planning); combinatorial/neural combinatorial optimization is left as future work.
- The exploration/exploitation behavior of the AET search is governed by a simple hand-set heuristic rule — the very thing the paper criticizes elsewhere; learning or self-modifying this rule is unexplored.
- Evidence quality is uneven across domains: single-objective gets full tables; constrained and multi-objective results are box plots only; all quantitative claims rest on one evolution run.
- Each evolution step is expensive (retraining + multi-run evaluation of a full MetaBBO project), and the paper reports no wall-clock or monetary budget for the 100-step search.
- The evolved artifact is benchmark-coupled: generalization is tested on scaled/varied BBOB settings and UAV planning, but not on genuinely different problem families (e.g., discrete or expensive surrogate-based optimization).

## Questions for Further Exploration
- How much variance does HADA itself exhibit across independent evolution runs (different seeds for parent sampling and agent temperature) — is 0.9674 a typical outcome or a lucky trajectory?
- Can the hyper agent learn or rewrite the AET parent-sampling heuristic itself, closing the loop on the one remaining hand-crafted component?
- Does the framework's advantage persist in expensive optimization where the proxy-evaluation budget (5 epochs / 3 runs) would need to shrink drastically, and how does selection-on-proxy bias behave there?
- What is the full token/dollar cost per evolution step per domain, and where is the compute-optimal stopping point on the 0.577→0.971 curve compared to single-agent baselines like LLaMEA?
- Do the hyper agent's self-edited prompts remain stable over horizons well beyond 100 steps, or do they drift toward over-constrained rules that plateau novelty (the paper's Appendix B shows rules hardening considerably by the end)?
