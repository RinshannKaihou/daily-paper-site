> **一句话总结：** AWS AI Labs 提出 MILO，把 agent harness（智能体外围控制层）的自动设计建模为"策略级进化搜索"，用孤岛式谱系记忆（保留被拒绝变异作为负证据）+ 每岛专属的编码 agent 变异器 + 一个元进化 orchestrator（可重派变异器、跨岛嫁接、分裂新岛、调整任务课程）让搜索策略与 harness 共同进化：在 Terminal-Bench 2.1 / PaperBench / DeepSWE 上，Opus 4.8 的分辨率率比初始 harness 分别 +12.0、+28.3、+10.3 个百分点（最优先前搜索仅 +4.5 / +18.3 / 0），TB2.1 达 86.1±2.0% RR@5（超过官方榜单第一 83.8±2.3%）且 token 少 26%；在 EinsteinArena 上还刷新了三个公开数学问题的已知界。

> **TL;DR:** MILO is a self-adaptive, multi-agent evolutionary search that automatically rewrites an LLM agent's harness (control flow, prompts, tools, sub-agents) while simultaneously evolving the search strategy itself. With Opus 4.8 it lifts resolution rate over its Best-of-3 initial harness by +12.0 pts on Terminal-Bench 2.1 (86.1% RR@5 vs 74.1%, where the best prior search GEPA gains only +4.5, and above the official leaderboard top of 83.8±2.3), +28.3 pts on PaperBench-CodeDev (55.0 vs 26.7 RR@3; best prior Meta-Harness +18.3), and +10.3 pts on DeepSWE where no prior search improved at all — while using 26% fewer tokens; with open-weight gpt-oss-120b on DeepSWE it reaches 15.6% PR@1, ~20× its initial harness (0.8), where all six prior search methods stay below 1%. A component ablation walks TB2.1 RR@5 from 76.4 to 86.1, and its harnesses set three new best-known bounds on EinsteinArena math problems verified by the arena.

## 核心贡献

- **问题形式化**：把"harness 工程"定义为自动化 harness 发现（AHD）——模型固定，搜索一个可运行的 harness `h'`（入口为 `build_agent`，可以是 Python/YAML/工具仓库），在精度–token–延迟的 Pareto 前沿上超越初始 harness 与最强人工 harness；与"实例级"搜索（FunSearch、AlphaEvolve 解单个问题）不同，这是"策略级"搜索（泛化到整个任务分布）。
- **三大组件**：(i) **层次化谱系记忆**——K 个孤岛各持一棵 append-only 的树，同时记录被接受与**被拒绝**的子代（含补丁、Δ精度、Δ成本、裁决），失败证据用于剪枝、迫使变异器做更大胆的结构性改写；孤岛之间只共享思想不竞争，保住多样性。(ii) **证据驱动的变异器 agent**——每岛一个多轮编码 agent（Claude Code、Codex 及 4 个定制 DeepAgents 变体），拿到父代源码、失败 trace 与全岛快照（均以磁盘路径传入），先诊断后改写，可重写控制流而非只调 prompt。(iii) **元进化 orchestrator agent**——孤岛停滞时（patience=3）先诊断瓶颈（变异器不力 / 谱系枯竭 / 小众生态位被挤占 / 全群触顶），再施加 ≤2 个动作：REASSIGN（换变异器）、GRAFT（跨岛杂交）、SPECIATE（把被挤占子树迁出为新岛）、CURRICULUM（按 regret 重组搜索任务集）。
- **多目标准入 + 防过拟合**：子代只有在扩大支配区域（hyper-volume 增量 > 0，容差 ε=0.02）时才被录取；每轮在 held-out 切分上重评分以监控过拟合；泛化约束 C 明确禁止针对单个任务的硬编码。
- **结果**：在 TB2.1 / PaperBench-CodeDev / DeepSWE 上击败 8 个 SoTA 人工 harness 与 6 个进化搜索基线（Opus 4.8 与开源 gpt-oss-120b 双骨干）；TB2.1 进化出的 harness 迁移到更难的 Frontier-Bench 无需再搜索仍领先；EinsteinArena 实例级变体刷新三个公开数学问题的最优已知界（超过 AlphaEvolve、TTT-Discover、EvoX）。

## Key Contributions

- Formalizes **Automated Harness Discovery (AHD)** as strategy-level evolutionary search over solver-agnostic harness space (any runnable `build_agent` artifact), optimizing a multi-objective accuracy–token–latency Pareto frontier with held-out validation.
- Proposes **MILO**, the first ES framework whose *search strategy itself is self-adaptive* via an orchestrator agent (stages 0–II methods fix the strategy; stage-III methods adapt by hard-coded rules; MILO rewrites memory, mutators, and curriculum online).
- Introduces **failure-aware hierarchical lineage memory**: append-only per-island trees retaining rejected mutations as negative evidence, inducing pruning and bolder structural mutations; islands exchange ideas only via orchestrator-initiated GRAFT/SPECIATE.
- Demonstrates **state-of-the-art results on three long-horizon agent benchmarks plus scientific discovery**: beats 8 SoTA harnesses and 6 ES baselines under a uniform 72-hour protocol, transfers zero-shot to Frontier-Bench, and tightens three best-known bounds on EinsteinArena (officially verified).

## Methodology

**Problem (AHD).** An agent A = ⟨M, h⟩ pairs a frozen model M with a harness h. Given a task distribution with benchmark split into B_search ⊂ B_val, constraints C (runnable, general — no task-tailored logic —, user restrictions, budget), AHD searches the harness space for h* advancing the accuracy–cost frontier, evaluated with k stochastic rollouts per task (per-task accuracy, token cost, execution traces/evidence).

**Component 1 — Hierarchical lineage memory.** The population is a forest of K islands; each island j is a node- and edge-labeled tree L_j: nodes store a harness's (Acc, Cost, Evidence, admission verdict), edges store the source patch plus deltas Δacc/Δcost. Memory is **append-only** — rejected children persist with their verdict, so mutators see which edits paid off and which failed, and are pushed toward structural redesign when local refinements keep failing. Islands evolve in isolation (no cross-island parent selection), which preserves behavioral diversity; GRAFT edges (cross-island co-parents) later turn the forest into a DAG.

**Component 2 — Evidence-driven mutator agents.** Each island is assigned a mutator from a pool G of six coding agents (Claude Code w/ Opus 4.8, Codex w/ GPT-5.5, plus four custom DeepAgents-based agents pairing Opus 4.8 / GPT-5.5 / gpt-oss-120b / Qwen3-Coder-480B). The mutator receives (a) the parent's source, (b) its failure evidence (traces, verifier reports), and (c) the full island snapshot as an indented directory listing — all as on-disk paths it can open selectively with coding tools — and follows a diagnose-first workflow before rewriting the whole harness.

**Component 3 — Meta-evolutionary orchestrator.** When an island stalls for P_s=3 rounds (no held-out gain), the orchestrator (itself a Claude Code agent with Opus 4.8) diagnoses the bottleneck — weak mutator, inert lineage, exhausted lineage, crowded-out niche, or whole-population plateau — and applies at most two of: REASSIGN (swap mutator), GRAFT (breed the two islands' best harnesses), SPECIATE (promote a suppressed subtree to a new island), CURRICULUM (replace the search set favoring high-regret tasks, where regret = best-attainable minus population-mean accuracy).

**Loop.** Per round and island: parent selection via softmax(−Σ Dom·Sim / T) favoring few dominators and distinct behavior vectors; whole-harness mutation (45-min cap per call); k=3 rollouts on every B_search task; admission iff the child enlarges the island Pareto front's dominated hyper-volume (tolerance ε=0.02, costs normalized by per-task caps of 20M tokens / 7,200 s); held-out re-scoring of admitted harnesses; stall counters feed the orchestrator. Configuration: K=3 islands, T=1, 72-hour wall-clock budget identical for every search method; final harness re-evaluated at the benchmark's leaderboard k. The harness genome is a single DeepAgents/LangGraph Python file (Python deliberately chosen over YAML for a larger mutation surface); all inference via Amazon Bedrock on a single CPU-only 192-vCPU instance.

## Results & Highlights

- **Terminal-Bench 2.1 (Opus 4.8):** MILO reaches 86.1 ± 2.0% RR@5 vs its initial Best-of-3 harness at 74.1% (+12.0 pts); the best prior search, GEPA, gains only +4.5 pts (78.6), and Meta-Harness 78.2 — while MILO also beats the official leaderboard's top entry (83.8 ± 2.3%) and consumes 26% fewer tokens than its initial harness (0.74× Best-of-3's tokens).
- **PaperBench-CodeDev (Opus 4.8):** RR@3 55.0 vs Best-of-3 26.7 (+28.3 pts); the best prior search, Meta-Harness, gains +18.3. Notably, 7 of the 8 SoTA hand-built harnesses *underperform* the minimal harness on PaperBench RR@3, and prompt/skill-only mutators (GEPA, A-Evolve) gain at most +6.6 there — structural redesign is what pays.
- **DeepSWE:** with Opus 4.8, MILO gains +10.3 pts RR@5 over Best-of-3 whereas no prior search method improves on Best-of-3 at all; with open-weight gpt-oss-120b, MILO reaches 15.6% PR@1 ≈ 20× its initial harness (0.8%), while all six prior search methods stay below 1%. With gpt-oss-120b overall, MILO's PR@k gains are +11.8/+8.6/+14.8 (TB2.1/PB/DeepSWE) vs +8.2 (ShinkaEvolve), +4.8 (Meta-Harness), +0.1 (OpenEvolve).
- **Ablation ladder (TB2.1 RR@5, Opus 4.8):** flat-memory single LLM call 76.4 → +agentic mutator 79.1 → +lineage memory 79.3 → +multiple islands 80.5 → +orchestrator 86.1 — the orchestrator is the single largest jump (+5.6). Under an artificial 4K per-call output cap, all 12 expert harnesses collapse to 20.2–34.4 RR@5 and Best-of-3 to 34.4, while the MILO harness still reaches 81.1 — a stronger harness compensates for a handicapped model.
- **Reusability without further search:** the TB2.1-evolved harness run unchanged on the harder Frontier-Bench (70 tasks) scores RR@3 13.8 vs Best-of-3 10.0 (+3.8) and Mini-SWE-Agent 5.2 (+8.6), with pass@3 24.3 vs 12.9.
- **Scientific discovery (EinsteinArena, instance-level variant, M = Opus 5):** new verified best-known bounds on three open problems — Erdős minimum-overlap upper bound 0.3808586 → 0.3808566, 1st autocorrelation inequality 1.50274365 → 1.50274360, 3rd autocorrelation 1.45081 → 1.44889 — each confirmed by the arena's official verifier, surpassing AlphaEvolve, TTT-Discover, and EvoX.
- **Search dynamics:** with gpt-oss-120b on TB2.1 every island stalls in rounds 6–14 until orchestrator GRAFT/REASSIGN interventions resume progress (rejected grafts persist as negative evidence); the weakest seed island (39.2%) produces the run's best harness (59.9% population best) at round 27 — evidence the island design lets even weak seeds win. Cost-wise with gpt-oss-120b, EvoX spends 1.46× Best-of-3's tokens for +6.1% RR@5 while MILO gains +10.7% with 0.70× tokens.

## Critical Assessment

- **The search space is one framework genome.** Despite the representation-agnostic framing (Definition 3.1 admits YAML, tool repos, OpenHands SDK…), every experiment instantiates H as a single DeepAgents Python file, and the authors explicitly chose Python over YAML "because code exposes a far larger mutation surface." So the headline gains measure MILO's search on the genome the authors picked, not a demonstrated ability to search heterogeneous harness spaces — the framework-agnostic claim is by construction, not by experiment.
- **Wall-clock parity is not compute parity.** All methods share a 72-hour limit, but MILO runs 3 islands in parallel with a 6-mutator pool of frontier coding agents plus its own orchestrator agent, while GEPA is a single-LLM prompt tuner and Best-of-3 doesn't search at all. The search-side token/compute bill per method is never reported, so part of the +12.0/+28.3 deltas could be bought with more search compute rather than a better search algorithm.
- **No variance over the search itself.** Each (method, benchmark) appears to be one 72-hour run; error bars are task-clustered 95% CIs of the final evaluation, not across independent evolutionary runs. Given stochastic LLM-driven search (and their own anecdote that the weakest seed happened to win), the DeepSWE +10.3 could shift under a different seed; a 3-seed search-variance experiment is missing.
- **Some closest competitors are absent.** Self-Harness, DarwinX, and AIDE² are skipped because code is unavailable — yet Self-Harness and DarwinX are exactly the prior strategy-level self-improving systems MILO claims to subsume; the Darwin Godel Machine lineage is likewise uncited in the tables.
- **PaperBench is LLM-judged.** PR@3/RR@3 come from a GPT-5.5 rubric judge (RR thresholded at score ≥ 0.9); the +28.3 headline delta deserves human-audited replication, and rubric-judge noise is not quantified.
- **Rigor where it counts:** to the authors' credit — same expert-designed seeds (B10–B12) for every method, pinned baseline versions, held-out split guarding overfitting, a generality constraint plus manual inspection of evolved harnesses, an additive component ablation, and refreshingly honest negative findings (7/8 SoTA harnesses worse than a 60-line minimal loop on PaperBench). There is no dedicated limitations section, however.

## Strengths

- Genuinely self-adaptive search: the orchestrator's diagnose→intervene loop (REASSIGN/GRAFT/SPECIATE/CURRICULUM) is a real mechanism, not a slogan — the round 6–14 stall-and-recover trace and the weakest-seed-wins outcome (39.2% seed → 59.9% best) are concrete evidence it matters.
- Retaining rejected mutations as first-class negative evidence is a clean, cheap idea that directly counters LLM mutators' exploitation bias and diversity decay.
- Comprehensive, disciplined evaluation: three long-horizon benchmarks with different network regimes, frontier + open-weight backbones, 8 harness + 6 search baselines under identical seeds/budget/evaluator, official verifier confirmation for the math records.
- Honest systems findings independent of MILO itself: harness gains do not transfer across backbones (4/8 harnesses flip sign on gpt-oss-120b), SoTA harnesses can be counterproductive (PaperBench), and token spend does not predict accuracy (Mini-SWE-Agent ≈ 2× Goose's tokens for 73.9% vs 74.5% RR@5).
- Strong cost story: better accuracy *and* fewer tokens (0.74×/0.70× vs baselines), plus 4K-output-cap robustness (81.1 vs 34.4 RR@5) showing the evolved harness compensates for model handicap.

## Limitations

- Empirical scope confined to one harness genome (single-file DeepAgents Python); no cross-framework search experiment despite the general framing.
- Equal wall-clock hides unequal search compute; per-method search-side token/cost accounting is absent.
- Single search run per configuration; no seed-level variance for the evolutionary process itself.
- Self-Harness, DarwinX, and AIDE² not compared (code unavailable), weakening the "no prior ES self-adapts this broadly" empirical claim.
- PaperBench metrics depend on a GPT-5.5 rubric judge; no judge-reliability analysis.
- The orchestrator's four actions are hand-mapped to four diagnoses; scaling the intervention vocabulary beyond this curated set is untested.
- No explicit limitations section; code release is implied via a project page but not clearly committed in the text.

## Relevance

这篇论文精准命中你的第一优先方向 Self-Evolving Agents & Automated Research：它让搜索策略本身（记忆、变异器、课程）随 harness 一起被 LLM 进化，是"自改进 agent 架构 + 自动化发现"的代表性系统工作，EinsteinArena 刷新数学问题已知界的部分也直接对应 agentic scientific discovery。对长期自主 agent 系统的可靠性也有参考价值（held-out 防过拟合、失败证据剪枝）。

## Questions for Further Exploration

- Does the lineage memory's prune-inducing effect survive when the genome spans heterogeneous artifacts (YAML configs, tool repos, multi-framework sub-agents), or does the tree structure depend on a single-file code representation?
- Under equal *compute* rather than equal wall-clock, how much of the +12.0/+28.3/+10.3 advantage over GEPA/Meta-Harness remains?
- What is the run-to-run variance of a full 72-hour MILO search (different RNG seeds) on DeepSWE, where the margin is smallest and the "no prior gain" baseline makes the claim most fragile?
- Can the orchestrator's diagnosis→action mapping be learned or expanded (e.g., a CURRICULUM that adapts the *verifier* or rollout count k), or does performance degrade once interventions are no longer hand-designed?
- Do the EinsteinArena optimizer-writing harnesses transfer to other instance-level domains (TimeSeriesGym, AutoML), or are they tuned to mathematical optimization traces?
- The 4K-output-cap result (81.1 vs 34.4 RR@5) suggests harnesses can substitute for model capability — can MILO-evolved harnesses be composed with model quantization/distillation for cheap-but-reliable agents, and does the harness hide numeric-precision failure modes or amplify them?
