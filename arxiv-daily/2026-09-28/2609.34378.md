# MARATHONER: Ultra-Long-Horizon Autonomous Intelligence

> **一句话总结：** Ant Group + 澳门大学提出 Marathoner：从 1 万个 GitHub 仓库挖掘 10 万个大版本发布 PR 合成超长程任务（Easy/Medium/Hard = 2:3:5，另用 Multi-Task Chaining 把 5 个任务串成 3000 道"Frontier"链式任务），用 Kimi K3 在 Claude Code/Codex/OpenClaw 三种 harness 下拒绝采样出 40,820 条成功轨迹做 SFT（256k 序列长度冷启动），再用 GRPO 强化学习并新增"后期阶段奖励"（LLM 评审轨迹后半段的关键操作，额外 +0.5 奖励），使 Qwen3.5-9B 在 5 个长程基准全面跃升（SWE-Bench Verified 45.8→77.5、Terminal Bench 2.0 27.3→57.2、SWE-Marathon 0→8.2），并在 FrontierSWE（26.4 vs 25.9）和 SWE-Marathon（8.2 vs 5.9）上小幅超过 Gemini3.1-Pro。

> **TL;DR:** Marathoner-9B is a Qwen3.5-9B post-trained for 10+-hour agentic execution via a three-stage pipeline: (1) Ultra-Long-Horizon Task Synthesis — 100,000 tasks mined from major-release PRs (1,000+ new lines for "Hard") across 10,000 GitHub repos, plus Multi-Task Chaining that concatenates 5 random tasks into 3,000 harder "Frontier" tasks; (2) rejection-sampling SFT on 40,820 reward-1 trajectories from teacher Kimi K3 run across three harnesses (Claude Code, Codex, OpenClaw) at 256k sequence length; (3) GRPO with a novel Later Stage Bonus Reward (+0.5 for LLM-judged valuable actions in the second half of a trajectory). Against the base model it gains +31.7 pts on SWE-Bench Verified (45.8→77.5), +29.9 on Terminal Bench 2.0 (27.3→57.2), and +8.2 on SWE-Marathon (0→8.2), and it edges Gemini3.1-Pro on FrontierSWE (26.4 vs 25.9) and SWE-Marathon — but remains far below its own teacher Kimi K3 (79.8 on FrontierSWE) and GPT-6-Astra (89.1).

## 核心贡献

- **超长程任务合成管线**：从覆盖前端/后端/CUDA/数据库内核/LLM 推理库（vLLM、SGLang）等领域的 10,000 个 GitHub 仓库挖掘 100,000 个 major-release PR，按新增代码行数构造三级难度课程（Easy 100–200 行、Medium 200–1000 行、Hard 1000+ 行，比例 2:3:5）；每个任务以 PR 前一个 commit 为代码库、PR 首条评论（缺失时回退到 release notes、再回退到 LLM 生成）为指令、PR 的 fail-to-pass 测试 + 既有 pass-to-pass 测试为二元奖励验证器，统一封装为 Harbor 格式沙箱（Ubuntu 24.04，4 CPU/10GB 内存/40GB 磁盘，可联网）。
- **Multi-Task Chaining**：将 15,000 个 Hard 任务中随机抽取 5 个原子任务串成一个统一任务（软件 = 多仓库、指令 = 指令拼接、验证器 = 验证器并集），合成 3,000 道"Frontier Task"，专门训练"完成中间目标后继续推进"的长程能力。
- **多样化 harness 的拒绝采样 SFT**：以 Kimi K3 为教师，在 Claude Code/Codex/OpenClaw 三种 harness 上对同一任务生成轨迹，仅保留 reward=1 的轨迹（Claude Code 14,159 条、Codex 13,583 条，合计 40,820 条），在 Qwen3.5-9B 上做 256k 序列长度全参数 SFT，防止对单一 harness 过拟合。
- **Later Stage Bonus Reward + GRPO 强化学习**：训练时每个任务随机配一种 harness 在独立沙箱中真实执行；用 LLM 把轨迹分阶段总结并评判，若轨迹后半段存在"高价值操作"则额外 +0.5 奖励，与二元正确性奖励相加（R = R_correctness + R_bonus），显式鼓励长程执行后期的持续有效行为。
- **评测与扩展性分析**：在 FrontierSWE、NL2Repo、SWE-Marathon、Terminal Bench 2.0、SWE-Bench Verified 5 个基准上验证；给出环境数量扩展实验（RL 环境从 1,000 扩到 8,000 持续涨点）、RL 奖励/熵曲线和执行过程统计（平均连续执行数小时、数百次工具调用）。

## Key Contributions

- A deterministic, test-verified task synthesis pipeline: 100,000 unit-test-verifiable tasks from major-release PRs of 10,000 diverse GitHub repos, with a difficulty curriculum (20k Easy / 30k Medium / 50k Hard PRs at a 2:3:5 ratio) where each task = pre-PR repo checkout + PR-comment instruction + fail-to-pass / pass-to-pass test suite as a binary reward, packaged in the Harbor harness format.
- Multi-Task Chaining: chaining 5 random atomic tasks (union of repos, instructions, and verifiers) into 3,000 "Frontier Tasks", explicitly targeting the ability to keep making progress after intermediate objectives are complete — a proxy for frontier-level ultra-long-horizon difficulty.
- Diverse-harness rejection-sampling finetuning (RFT): Kimi K3 teacher trajectories collected via Claude Code, Codex, and OpenClaw on the same tasks, filtered to 40,820 reward-1 trajectories, used to full-parameter SFT Qwen3.5-9B at 256k sequence length as a cold start.
- Later Stage Bonus Reward for GRPO: an LLM summarizer/judge decomposes each trajectory into phases and grants +0.5 bonus when "exceptionally valuable operations" occur in the later half of execution, giving denser supervision over long rollouts than the binary correctness reward alone.
- Comprehensive evaluation on 5 long-horizon benchmarks plus an environment-scaling study (1,000→8,000 RL environments), RL reward/entropy dynamics, and execution statistics (avg 3.56h and 648.3 tool calls per FrontierSWE task).

## Methodology

**Task synthesis.** The authors select 10,000 GitHub repositories spanning frontend (e.g., facebook/react), backend frameworks, low-level CUDA programming, database kernels, mature codebases (SciPy), trending repos, and LLM-serving repos (vLLM, SGLang), deliberately covering both common and rarely-trained programming languages. Major-release PRs (substantive new functionality) are mined and bucketed by added lines: Easy (100–200), Medium (200–1,000), Hard (1,000+), sampled at 2:3:5 → 20k/30k/50k. Each task clones the repo at the commit immediately preceding the PR; the instruction uses a three-level fallback (first PR comment → release notes → LLM-generated from the diff); the reward verifier combines the PR's tests as fail-to-pass and existing unit tests as pass-to-pass, with binary reward 1 only if all tests pass. Sandboxes are Dockerized Ubuntu 24.04 with 4 CPUs, 10 GB RAM, 40 GB disk, and internet access enabled. All tasks are emitted in Harbor format. Multi-Task Chaining additionally fuses 5 random atomic tasks into 3,000 unified Frontier Tasks whose verifier is the union of the constituent verifiers.

**Rejection sampling finetuning.** Kimi K3 is used as the teacher because of its strong ultra-long-horizon execution; it "consistently runs for hours" on the synthesized tasks. Trajectories are generated through three harnesses (Claude Code, Codex, OpenClaw) to prevent harness overfitting; 14,159 (Claude Code) and 13,583 (Codex) reward-1 trajectories are collected, 40,820 in total from the 50,000-task pool. RFT is full-parameter SFT on Qwen3.5-9B with sequence length 256k, lr 5e-6, 5 epochs, cosine schedule, warmup 0.05, DeepSpeed ZeRO-3.

**Reinforcement learning.** The cold-started policy interacts with real sandboxes; each task is paired with a random harness per rollout to preserve harness generality. GRPO is used (batch size 32, 8 rollouts per task, lr 1e-6, temperature 0.6, top-p 0.95) on 5,000 atomic + 3,000 Multi-Task-Chaining tasks (8,000 total), on the AREAL framework with 32 H800 GPUs. The Later Stage Bonus Reward: a proprietary Qwen Max-class model summarizes the finished trajectory into major phases, a judge LLM flags phases containing exceptionally valuable operations (fixing hidden bugs, key optimizations), and if any flagged phase lies in the later half of execution the agent receives +0.5; final reward R_t = R_correctness (binary 0/1) + R_bonus.

**Evaluation.** Five benchmarks: FrontierSWE (17 highly challenging technical problems), NL2Repo (build complete repos from scratch), SWE-Marathon (20 human-crafted tasks where most strong proprietary models score <40%), Terminal Bench 2.0 (89 terminal-use tasks), SWE-Bench Verified (500 tasks). Marathoner-9B is evaluated with the Claude Code harness.

## Results & Highlights

- **SWE-Bench Verified:** Marathoner-9B reaches 77.5 vs 45.8 for its base model Qwen3.5-9B (+31.7 pts), also beating the largest open baselines Qwen3.6-27B (73.3) and Qwen3.6-35B-A3B (71.8), but still below Gemini3.1-Pro (80.1) and Claude Fabile 5.1 (91.8).
- **Terminal Bench 2.0:** 57.2 vs 27.3 for the base model (+29.9 pts) and vs 50.4 for Qwen3.6-27B (+6.8); it surpasses Gemini3.1-Pro's 60.3? No — 57.2 remains below it, while crushing the base model's 27.3.
- **FrontierSWE:** 26.4 vs 10.7 for the base model (+15.7 pts), narrowly surpassing Gemini3.1-Pro (25.9) — but the teacher Kimi K3 scores 79.8 and GPT-6-Astra 89.1 on the same benchmark, so the "surpasses strong proprietary models" claim holds only against the weakest proprietary entry.
- **SWE-Marathon:** 8.2 vs 0.0 for the base model and vs 5.9 for Gemini3.1-Pro; all other open models are ≤2.6. GPT-6-Astra leads at 48.7.
- **NL2Repo:** 34.7 vs 17.9 for the base model (+16.8 pts), the best among all open models listed (Qwen3.6-27B: 32.6).
- **Ablations (FrontierSWE / Terminal Bench 2.0):** vanilla RFT+RL pipeline 22.2/51.2; +Multi-Task Chaining 24.9/54.9 (+2.7/+3.7); +Diverse-Harness Trajectory Generation 24.1/53.7 (+1.9/+2.5); +Later Stage Bonus Reward 24.6/54.4 (+2.4/+3.2). Each component contributes, but the sum of individual gains (+7.0 FrontierSWE) exceeds the full model's total delta (+4.2), indicating overlapping benefits.
- **Environment scaling:** increasing RL training environments from 1,000 to 8,000 yields consistent gains on FrontierSWE and Terminal Bench 2.0, suggesting environment diversity is a live scaling axis.
- **Execution statistics:** on FrontierSWE, Marathoner-9B averages 3.56h execution time, 426.2 steps, and 648.3 tool calls per task (Terminal Bench 2.0: 0.58h, 104.8 steps, 239.4 tool calls) — genuine multi-hour, hundreds-of-calls rollouts, though below the headline "10+ hours / 1000+ tool calls" phrasing.
- **RL dynamics:** training reward increases consistently and policy entropy remains stable across RL steps, i.e., no observed entropy collapse during GRPO.

## Authors & Credibility

The team spans Ant Group (Jinpeng Ou, Yifan Xie, Jingang Zhou, Lirui Pan, Qingpei Guo — co-corresponding) and the University of Macau's FIC (Ruiyang Zhang; Zhedong Zheng — co-corresponding), with Peking University affiliation for two authors. This is an industry-academia collaboration with credible resources: 32 H800 GPUs, access to a frontier teacher (Kimi K3) and proprietary judge models, and in-house familiarity with agentic harnesses. The methodology is described with unusually concrete engineering detail (sandbox specs, test-based verifiers, per-harness trajectory counts, hyperparameters), which supports credibility of the reported numbers. No prior-work red flags among the cited venues (Harbor, GRPO, ReAct lineages). Caveat: the paper is a preprint with no stated code or data release, so independent verification is currently limited to the reported tables.

## Critical Assessment

- **The "surpasses proprietary models" claim is overdrawn.** Marathoner-9B beats exactly one proprietary system — Gemini3.1-Pro — on exactly two of five benchmarks (FrontierSWE 26.4 vs 25.9; SWE-Marathon 8.2 vs 5.9), and Gemini3.1-Pro is by far the weakest proprietary row in Table 1 (it scores 25.9 on FrontierSWE where GPT-6-Astra scores 89.1). Against GLM-5.2, Qwen3.5-Max, Kimi K3, GPT-6-Astra, and Claude Fabile 5.1 it loses on every benchmark, often by 40–60 points. The abstract's careful singular phrasing ("even surpasses performance of strong proprietary model") is technically accurate but rhetorically misleading.
- **Two of the five benchmarks are statistically tiny.** FrontierSWE has 17 problems and SWE-Marathon has 20; at n=17, a single flipped task moves the score by ~5.9 points — larger than the entire 26.4-vs-25.9 margin over Gemini3.1-Pro. No confidence intervals or multiple-run variance are reported anywhere in the paper.
- **Internet-enabled sandboxes on public-PR-derived tasks are a reward-integrity hazard the paper never discusses.** Every task is built from a public GitHub PR, with the repo checked out one commit before it; since sandboxes have internet access, an agent could in principle retrieve the reference diff or solution from GitHub. The paper offers no decontamination or blocking analysis for either teacher trajectory collection or RL rollouts.
- **The Later Stage Bonus Reward invites reward hacking that goes unexamined.** The +0.5 bonus is assigned by an LLM judge (a proprietary Qwen Max-class model, same family as the Qwen3.5-9B base — a self-preference risk), and it is paid even on failed trajectories; within a GRPO group where all 8 rollouts fail the task, bonus-only rewards become the entire advantage signal, which could train "plausibly busy" behavior rather than task completion. No hacking audit or judge-reliability check is reported.
- **Ablations are single-additive only.** Each proposed component is added to a vanilla RFT+RL pipeline in isolation; there is no leave-one-out or full-combination grid, and the individual deltas summing to +7.0 on FrontierSWE versus the full model's +4.2 over vanilla (22.2→26.4) suggests interaction effects that the ablation design cannot resolve.
- **Harness generalization is claimed but not evaluated.** Diverse-harness training is a core selling point, yet Table 1 reports only the Claude Code harness; no per-harness (Codex/OpenClaw) evaluation is shown to substantiate that the model actually transferred across harnesses rather than merely avoiding overfitting.
- **The "10+ hours / 1000+ tool calls" headline is not directly substantiated.** Table 2 reports averages of 3.56h and 648.3 tool calls on the hardest evaluated benchmark; the 10h/1000+ figures presumably describe tails or Frontier Tasks but no supporting table or distribution is given.
- **Open-baseline selection is narrow:** all open-source comparisons are Qwen-family models; no Llama, DeepSeek, MiniMax, or other families are included, so it is hard to judge how much of the gain is pipeline versus starting from a particularly RL-trainable base.

## Strengths

- Deterministic, tamper-resistant reward: unit-test verifiers (fail-to-pass + pass-to-pass) are far harder to hack than LLM-judged task correctness, and the difficulty curriculum by diff size is a sensible proxy for horizon length.
- Multi-Task Chaining is a cheap, clever knob for manufacturing harder long-horizon tasks (union of verifiers keeps the reward objective), and the environment-scaling experiment (1,000→8,000) is a genuinely useful finding for practitioners.
- Diverse-harness trajectory generation and random harness-task pairing during RL directly target a real failure mode (harness overfitting) that most agentic post-training papers ignore.
- Unusually complete engineering disclosure: sandbox specs, three-level instruction fallback, exact SFT/RL hyperparameters, per-harness trajectory yields, and execution-process statistics.
- RL is performed on real sandboxed execution (not static traces), and the entropy-stable training curves support the claim of robust optimization.

## Limitations

- Evaluation variance is unaddressed on benchmarks with 17 and 20 tasks; no multi-seed or confidence-interval reporting for any result.
- Distillation gap is large: Marathoner-9B (26.4 FrontierSWE) recovers only about a third of its teacher Kimi K3's score (79.8), and the ceiling imposed by a 9B base is not probed (no 27B/35B Marathoner variants).
- Later Stage Bonus Reward depends on proprietary LLM summarization/judging of every trajectory — costly, opaque, and un-audited for hacking; the binary correctness signal it augments is the only rigorously verified component.
- FrontierSWE and SWE-Marathon availability/proprietary status limits third-party reproduction; no code, data, or model release is mentioned.
- Internet access in sandboxes on public-PR tasks is a potential contamination channel that is neither mitigated nor discussed.
- The 10+ hour / 1000+ tool-call capability claim is supported only anecdotally; reported averages are 3.56h / 648 calls on the most demanding benchmark.

## Relevance

这篇论文正对你最高优先级的"Self-Evolving Agents & 长时程自主系统"方向：它给出了一套把开源 9B 模型训练成可连续数小时、数百次工具调用执行真实工程任务的可复现后训练配方（任务合成 + RFT + GRPO + 过程奖励），对长时程自主 agent 的可靠性与训练方法有直接参考价值；其中的 RL 熵稳定性与环境扩展实验也与你对 LLM 训练稳定性的兴趣相关。

## Questions for Further Exploration

- Does Marathoner actually transfer across harnesses? A per-harness evaluation (Codex, OpenClaw) versus the Claude Code numbers would directly test the diverse-harness claim.
- How much of the Later Stage Bonus Reward is gamed? Auditing flagged "valuable operations" against ground-truth diffs, and testing whether failed trajectories earn bonus-heavy rewards, would expose or clear the reward-hacking risk.
- Do agents exploit internet-enabled sandboxes to look up the public reference PRs, and does disabling network change RFT/RL yields?
- Does Multi-Task Chaining create genuinely sequential long-horizon tasks, or do the 5 chained atomic tasks remain trivially decomposable and parallelizable?
- How does the pipeline scale with base-model size (e.g., the same recipe on Qwen3.6-27B), and what fraction of the teacher-student gap (26.4 vs 79.8 FrontierSWE) is capacity versus data?
- With n=17 (FrontierSWE) and n=20 (SWE-Marathon), do the reported rankings survive multiple evaluation runs with different seeds?
