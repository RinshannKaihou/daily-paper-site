> **一句话总结：** UC Santa Barbara 与 Microsoft 提出的 SCHOLAREVOLVE 把最新研究论文变成 agent harness（围绕固定骨干模型、管理工具/上下文/技能/记忆/工作流的执行代码）的进化方向——按五大功能模块组织搜索空间、用主题建模保证机制正交、以"突变—选择—交叉"进化循环自动改写 harness 代码：不更新任何模型权重，Qwen3.5-27B 在 AppWorld Challenge 的 TGC 从 49.6% 升至 63.6%（+14.0）、Normal 从 69.0% 升至 81.4%（+12.4），GPT-5.4-mini 在 τ²-Bench Telecom 的 pass¹ 从 72.7% 升至 81.9%（+9.2）；且在等量搜索预算下比只看自身轨迹的 Meta Harness 高出 9–10 个点，三轮"文献刷新"让 Qwen harness 持续涨到 81.5% TGC / 66.7% SGC，而 Meta Harness 原地踏步（69.6 / 51.2）。

> **TL;DR:** SCHOLAREVOLVE evolves an LLM agent's *harness* — the executable code around a frozen backbone that governs tool use, context management, skills, memory, and workflows — by mining the research literature instead of relying only on the agent's own execution trajectories. A research agent (GPT-5.4) audits failures on training tasks, retrieves arXiv papers per functional module, uses prompted topic modeling to keep mutation directions orthogonal, and a coding agent (Codex) turns selected papers into executable module mutations; a mutation–selection–crossover loop then picks a champion on held-out validation tasks, and periodic literature refreshes restart the cycle for lifelong evolution. Under an identical search-rollout budget, it beats trajectory-only Meta Harness by +9.0 (Qwen3.5-27B) and +10.0 (GPT-5.4-mini) TGC points on AppWorld Challenge, raises Qwen3.5-27B AppWorld Normal TGC from 69.0% to 81.4% (+12.4, matching Kimi-K2.6's 81.3% with fixed weights), and lifts GPT-5.4-mini on τ²-Bench Telecom from 72.7% to 81.9% pass¹ (+9.2) where Meta Harness actually *degrades* to 66.5%. Three successive publication windows push the Qwen harness to 81.5% TGC / 66.7% SGC while Meta Harness stalls at 69.6 / 51.2.

## 核心贡献

- **提出"从文献学习"的 harness 进化范式**：区别于 DGM、Meta Harness、Evo-Harness 等只依赖 agent 自身执行轨迹的自我改进方法，SCHOLAREVOLVE 把 arXiv 论文作为设计知识的来源，回答"经验研究者如何发现 agent 自身经验尚未暴露的改进"这一问题；论文级来源（source paper + topic）全程保留，每条改动可溯源、可解释。
- **模块 × 主题的二维搜索空间组织**：把 harness 分解为工具接口、上下文管理、技能、记忆、智能体工作流五个模块（与 modular agent post-training 视角一致），再对每个模块用 TopicGPT 式的提示式主题归纳与精炼，把检索到的论文聚成语义正交的机制家族，并按 round-robin 分配变异预算，避免预算浪费在重复机制上。
- **论文→可执行变异的自动化流水线**：失败审计（在 D_evo 轨迹上归因能力缺口）→ 模块化检索查询 → 主题分配 → 研究模型读全文写"变异蓝图"（源机制、目标模块接口、状态与产物、终止条件）→ Codex 实现并通过可执行健康探针（可导入性、接口兼容、产物构建、合法动作产出）→ 进入进化循环；技能库与情景记忆等持久产物只从训练/开发轨迹构建，评估期间冻结。
- **带交互项校正的交叉与保守选择规则**：用加性预测增益短名单组合，再整 harness 联合评估并记录残差 z(c)（捕捉模块交互与奖励天花板）；冠军保留采用配对 bootstrap 置信下界 > 0 的规则，测试集在所有选择决策冻结前从不触碰。
- **主动终身进化（proactive lifelong evolution）**：以三个 arXiv 发表窗口（2025-12、2026-01–04、2026-04–08）为"文献刷新"，每轮从保留冠军出发重新搜索；实验显示新论文驱动 Qwen harness 三连涨（TGC 69.0→73.4→79.8→81.5），而 Meta Harness 在同样窗口内不升反震荡（69.0→71.0→70.4→69.6）。
- **诚实的残留失败分析**：对全部 1,336 个失败回合做两级 LLM 标注（5 个失败家族、16 个子类型），显示进化主要消灭"响应格式"类失败（492→206），而约束违背（91→89）与检索不全（77→70）几乎未动，为后续工作指出明确靶子。

## Key Contributions

- **A literature-grounded harness evolution framework**: rather than searching harness code from the agent's own trajectories alone (DGM, Meta Harness, Evo-Harness), SCHOLAREVOLVE uses recent research papers as the source of design knowledge, directly addressing the "delayed adaptation" problem where a deployed agent must wait for its own failure evidence to accumulate. Every mutation retains its source paper and topic provenance.
- **A two-axis search space (module × topic)**: harnesses are decomposed into five modules (tool interface, context management, skills, memories, agentic workflows), and per-module prompted topic modeling (TopicGPT-style induction + refinement) groups retrieved papers into semantically orthogonal mechanism families so the mutation budget covers distinct mechanisms instead of near-duplicates.
- **An automated paper→executable-mutation pipeline**: failure audit → capability-gap abstraction → module-specific arXiv retrieval → topic allocation (round-robin over clusters) → research agent reads the full paper and emits a mutation blueprint → Codex implements the module mutation behind fixed interfaces, gated by executable health probes (importability, interface compatibility, persistent-artifact construction, valid action production).
- **Crossover with interaction residuals and a conservative retention rule**: combinations are shortlisted by an additive predicted-gain score, then jointly evaluated as complete harnesses; the residual z(c) captures module interactions and reward ceilings. The champion is retained only when the lower bound of a paired bootstrap gain interval is positive, and D_test is never touched until all selection decisions are frozen.
- **Proactive lifelong evolution**: three arXiv publication windows (Dec 2025, Jan–Apr 2026, Apr–Aug 2026) each restart the search from the retained champion. Literature refreshes drive monotone Qwen gains (TGC 69.0→73.4→79.8→81.5; SGC 48.8→54.2→61.9→66.7) while Meta Harness over the same windows ends at 69.6/51.2 — final advantages of +11.9 TGC and +15.5 SGC.
- **An honest residual-failure audit**: two-pass LLM annotation of all 1,336 failed Qwen episodes (5 families, 16 subtypes) shows evolution eliminates invalid-response failures (492→206 episodes) but barely moves constraint violations (91→89) and incomplete retrieval (77→70), giving concrete open problems rather than a victory lap.

## Methodology

**Problem formulation.** A harness H is an executable program managing model inputs, action execution, and state updates around a fixed backbone f_θ whose weights never change. SCHOLAREVOLVE represents H = Compose(m1..m5) over five modules: (1) Tool interface (actions available and proposal→execution translation), (2) Context management (instruction/history/memory/skill assembly, compression, ordering), (3) Skills (induction, retrieval, curation of reusable procedures), (4) Memories (episodic experience formation, retrieval, consolidation), (5) Agentic workflows (planning, action coordination, subagent delegation). Data is split into disjoint D_evo (failure mining and artifacts), D_val (candidate evaluation and champion selection), and a frozen D_test used only once after all decisions.

**Motivating diagnosis.** The paper argues trajectory-only meta-agent evolution suffers: (1) *limited exploration* — repeated local edits plateau (e.g., adding verification rounds that block needed tool calls); (2) *limited design knowledge* — the coding agent can only propose mechanisms within its backbone's capability; (3) *delayed adaptation* — evolution reacts to already-encountered failures, so deployed weaknesses persist until evidence accumulates.

**Research-guided module mutation.** (a) A failure audit on D_evo trajectories attributes failures to agent vs. environment causes; a research model abstracts recurring agent-attributable failures into benchmark-agnostic capability gaps. (b) For each of the five modules, two-tier retrieval queries (broad capability phrase + narrower mechanism phrase) are issued to arXiv, deduplicated by title. (c) Prompted topic modeling: a base model inducts topics per batch (name + one-sentence description), and a refinement model merges paraphrases, absorbs specific variants, and removes vague topics — encouraging semantic orthogonality; each paper gets an ordered topic list with abstract excerpts, and its primary topic defines its selection cluster. The candidate budget K_j is allocated round-robin over clusters by decreasing size. (d) A research agent reads the full paper + appendix and emits a *mutation blueprint* (source mechanism and assumptions, target module and interface, required state/artifacts, runtime operations, termination conditions); a coding agent (Codex) implements m_j^(g) behind unchanged interfaces while all other modules stay fixed. Lightweight executable health probes check importability, interface compatibility, artifact construction/reloading, and valid action production; the coding agent repairs until checks pass. Persistent skill libraries and memories are built only from D_evo trajectories and frozen during evaluation.

**Crossover and selection.** At generation g, mutations are evaluated on D_val; per-task gains y_ij feed an additive combination score Δ̄(c); configurations are shortlisted within budget, then each assembled harness is jointly evaluated, with residual z(c) = Δ(c) − Δ̄(c) capturing interactions and reward ceilings. The retention rule keeps H_g+1 = Ĥ_g only if the lower bound of the paired bootstrap gain interval vs. H_g exceeds 0 at level 1−α; a search cycle stops on s_stop=1 generation without confirmed validation gain or budget exhaustion.

**Lifelong loop.** Periodic literature refreshes start new cycles from the retained champion; new publications supply candidate improvements *before* the deployed agent's own failures accumulate. Backbone weights, D_evo trajectories, and derived artifacts stay fixed throughout.

**Experimental setup.** AppWorld: 90 training tasks (D_evo), 57 dev tasks (D_val), frozen test Normal=168 / Challenge=417; metrics TGC (task goal completion) and SGC (scenario goal completion, success in all three variants). τ²-Bench Telecom: 250/74/40 tasks, pass^k over four internal trials (k up to 4). Backbones: Qwen3.5-27B (vLLM, thinking enabled) and GPT-5.4-mini. Evolution agents: GPT-5.4 (research selection) + Codex GPT-5.4 (implementation), identical allocated search-rollout budget for SCHOLAREVOLVE and Meta Harness; the main AppWorld search requests 4 paper-derived candidates per module (20 total), Telecom 3 per module (15). Results are means ± SD over 3 independent evaluation runs (Mini finals checked over nine runs).

## Results & Highlights

- **AppWorld, Qwen3.5-27B backbone (3 runs):** TGC rises from 69.0±2.4 to 81.4±1.2 on Normal (+12.4) and from 49.6±2.9 to 63.6±0.4 on Challenge (+14.0); SGC rises from 48.8 to 69.0 on Normal (+20.2) and from 28.3 to 44.8 on Challenge (+16.5). Against Meta Harness at the *same rollout budget*, the Challenge TGC advantage is +9.0 points (63.6 vs 54.6).
- **GPT-5.4-mini backbone:** AppWorld Normal TGC 67.1→72.4 (+5.3) and Challenge TGC 46.1→55.6 (+9.5, +10.0 over Meta Harness's 45.6). On τ²-Bench Telecom, pass¹ goes 72.7→81.9 (+9.2), pass² 61.1→71.5 (+10.4), pass³ 54.4→64.2 (+9.8), pass⁴ 49.2→58.3 (+9.1). Notably, Meta Harness *degrades* the same backbone on Telecom (pass¹ 72.7→66.5, −6.2; pass⁴ −10.0), so the honest like-for-like gap vs. Meta Harness on Telecom pass¹ is +15.4.
- **Closing the frontier gap with frozen weights:** the evolved Qwen3.5-27B harness reaches 81.4% TGC on AppWorld Normal, matching Kimi-K2.6's 81.3% and reducing the gap to GPT-5.4 (85.7%) from 16.7 to 4.3 points — approximately 74% of the gap closed without any weight update. On Telecom, evolved Qwen3.5-27B hits 98.1% pass¹ and 94.8%/93.3% pass³/pass⁴, meeting or exceeding DeepSeek-V4-Flash (98.1/94.4/92.5).
- **Lifelong evolution (Table 5, AppWorld Normal, Qwen):** across three publication windows TGC goes 69.00→73.41→79.76→81.55 and SGC 48.80→54.17→61.91→66.67, while Meta Harness over identical windows reaches only 69.64 TGC / 51.19 SGC — final advantages of +11.9 and +15.5 points, with the baseline non-monotone across windows.
- **Cumulative ablations (Table 2, AppWorld Normal):** removing topic-guided selection (replaced by relevance ranking) costs 1.4 TGC / 2.3 SGC for Qwen (81.4→80.0) and 2.6 / 5.4 for Mini (72.4→69.8); additionally replacing module-wise mutation with joint editing costs a further 1.4 TGC (Qwen, 80.0→78.6); removing research guidance entirely collapses to Meta Harness (Qwen 76.8, Mini 67.5). TGC declines at every step for both backbones.
- **Module interactions under crossover (Table 3, 57 dev tasks):** Qwen's combined five-module harness scores 84.8 TGC / 73.7 SGC vs. 67.8 / 43.9 initial — beating its strongest single constituent (memory-only, 81.3 TGC) by 3.5 TGC / 12.3 SGC. Standalone scores mispredict composition: replacing a 75.4%-TGC standalone skills candidate with a 73.7% one *raised* the combination from 80.7% to 84.8%.
- **Transfer and reliability:** Challenge TGC gains stay positive beyond the training split's maximum reference-API count (>12 APIs: +9.5 for Qwen, +7.2 for Mini). Task-level, Qwen improves 221 of 585 tasks vs. 57 regressions (Mini: 200 vs. 106); 73.3% of Qwen's gains come from tasks that succeeded only intermittently initially, and tasks solved in all three runs rise from 205 to 333. Among evolved-harness Qwen episodes that hit an execution error on Challenge, 59.9% still ultimately succeed (vs. 44.9% initially) — evidence of better recovery rather than error avoidance.
- **Candidate pool transparency (Table 7):** of 20 paper-derived Qwen/AppWorld candidates, 17 raise standalone dev TGC, 8 with a 90% paired-bootstrap interval above zero; 3 sharply negative candidates (e.g., MLP-free compression, −8.5) are excluded from the final harness.

## Critical Assessment

**Novelty.** The core idea — using the research literature, organized by topic modeling, as the mutation source for harness evolution — is a genuine and well-positioned complement to trajectory-only self-improvement (DGM, Meta Harness, Evo-Harness, AgentSquare), and distinct from Per2Agent-style paper→tool conversion because papers here steer a *search over harness code* rather than becoming callable tools. However, the evolutionary skeleton (mutation, crossover, champion retention) and the modular decomposition are both inherited from prior work; the contribution is the literature interface and the exploration structure, not a new optimization algorithm.

**Rigor — strong in evaluation discipline, soft in component attribution.** The train/val/test separation is exemplary: D_test is frozen, artifacts are built only from D_evo, and the comparison to Meta Harness is budget-matched. But the ablation evidence is thinner than the headline: component contributions are 1.4–5.4 points while run-to-run SDs reach ±4.1 (e.g., Qwen SGC 69.0±4.1 full vs. 66.7±4.1 without topic-guided selection), over only 3 runs, and no significance test is reported for Table 2 specifically. Notably, the full-framework gain over Meta Harness on Qwen Normal (+4.6 TGC) exceeds any single component's measured contribution, so the parts do not obviously sum to the whole — plausibly via interactions, but the paper does not demonstrate this.

**Red flags worth naming.**
1. *Benchmark narrowness:* everything is tool/API-calling (AppWorld, τ²-Bench Telecom). No web agents, no SWE-bench-style coding, no OS agents — the claim that literature-guided evolution generalizes as a paradigm is untested outside one interaction mode.
2. *Backbone ceiling effects cut both ways:* the big Telecom win is for GPT-5.4-mini, whose baseline Meta Harness result *collapsed* (−6.2 pass¹); some of SCHOLAREVOLVE's relative advantage there is the baseline failing, not this method excelling. Conversely, for Qwen on Telecom the absolute gain is only +1.4 pass¹ from a 96.7 near-ceiling start.
3. *The research model is a hidden confounder:* GPT-5.4 reads papers and writes blueprints; the paper never ablates the strength of this research model (e.g., swapping in a weaker retriever/reader), so part of the gain may simply be "a stronger model in the loop" rather than the literature itself.
4. *"Lifelong" is simulated and curated:* three publication windows chosen from arXiv submission dates, run offline with a fixed budget — not a deployed agent continuously ingesting literature; there is no cost accounting (tokens, wall-clock, failures) per evolution cycle, which matters a lot for a claimed deployment story.
5. *LLM-annotated failure taxonomy:* the 5-family/16-subtype audit is annotated by a model (via OpenRouter) with calibration and two-pass review but no human agreement statistics, so the residual-failure percentages (39.5% response delivery, 29.3% goal & reasoning) should be read as approximate.

None of these undermine the main result — the budget-matched +9.0/+10.0 Challenge TGC gaps vs. Meta Harness and the monotone lifelong curves are convincing — but they do bound how far the conclusions generalize.

## Strengths

- **Clear, well-motivated problem framing:** the three failure modes of trajectory-only evolution (limited exploration, limited design knowledge, delayed adaptation) are crisply articulated and each maps to a concrete mechanism in the framework.
- **Exemplary evaluation hygiene:** disjoint D_evo/D_val/D_test with a frozen test set, budget-matched baseline comparison, paired bootstrap retention rules, means ± SD over 3 ( finals: 9) runs, and confidence intervals for subgroup analyses.
- **Provenance and interpretability:** every module in the final harness traces to a named source paper and topic (Tables 7-8), which trajectory-only search cannot offer; per-candidate bootstrap intervals and explicit exclusion of harmful candidates build trust.
- **The crossover analysis is a real finding:** standalone candidate quality mispredicts compositional value (a 73.7% candidate beating a 75.4% one inside the combination), justifying joint evaluation and interaction residuals.
- **Honest negative reporting:** residual failures are catalogued (constraint violations and incomplete retrieval barely improve), three harmful candidates are named, and Mini's tasks that regress (106) are reported alongside the 200 improvements.
- **Lifelong results directly test the thesis:** new publications produce monotone gains while the trajectory-only baseline stalls across the same windows — the cleanest evidence that literature is a complementary signal, not a rehash of the agent's own experience.

## Limitations

- **Only 3 evaluation runs** for headline numbers with SDs up to ±4 points; several ablation deltas (1.4-2.6 TGC) sit within one SD of noise, and Table 2 reports no significance testing.
- **Two benchmarks, one interaction mode:** both are API-calling environments; no evidence of transfer to coding, web, or OS agent settings.
- **Mid-tier backbones only** (Qwen3.5-27B, GPT-5.4-mini); whether literature-guided evolution still helps a frontier model (GPT-5.4 itself) — where design knowledge may already be internalized — is untested.
- **Lifelong claim is narrow:** three offline, curated publication windows; no continuous deployment, no per-cycle cost (token/compute) accounting, and publication windows cannot be re-run under different orderings.
- **The research-model confounder is not ablated:** no experiment isolates how much of the gain comes from GPT-5.4's paper comprehension vs. the framework structure.
- **Failure-taxonomy labels are LLM-generated** without human agreement statistics; subgroup percentages (e.g., 39.5% response-delivery) inherit that uncertainty.
- **Evolution depends on proprietary models** (GPT-5.4/GPT-5.5 via Codex), so full replication requires the same oracles despite the code release; the search is also nondeterministic across runs.

## Relevance

这篇论文正命中你最高优先级的 Self-Evolving Agents & Automated Research 方向：它是一个不更新权重、靠外部文献驱动的 agent 自我改进闭环，且罕见地同时覆盖了自动化研究循环（论文→机制→代码）与长程自主 agent 的可靠性审计（1,336 个失败回合的五家族分类）。其中"standalone 评分无法预测组合价值"与"残留失败集中在约束违背/检索不全"两个发现，对你关注的长时自主系统可信性问题也有直接参考价值。

## Questions for Further Exploration

- Does literature-guided evolution still yield gains on a frontier backbone (e.g., GPT-5.4 itself), or does the benefit vanish once the model already knows the design space?
- How much of the improvement comes from the research model's strength rather than the literature? An ablation swapping GPT-5.4 for a weaker reader/retriever would isolate the framework's contribution.
- Would the same module × topic search transfer to non-API agent domains — SWE-bench-style coding, web navigation, or OS agents — where the five-module decomposition may not align as cleanly?
- What is the actual cost per evolution cycle (tokens, wall clock, failed candidates), and how does it compare with simply fine-tuning the backbone on D_evo trajectories?
- Can the residual failure families the method barely touches (constraint violations 91→89, incomplete retrieval 77→70) be addressed by targeted retrieval queries, or do they require capabilities the literature does not yet describe?
- Since standalone candidate quality mispredicts compositional value, can the additive screening score be replaced by a cheap learned interaction model to spend the crossover budget better?
- In a true deployment, how should publication windows be scheduled and deduplicated against an agent's own trajectory-derived improvements (e.g., combining literature-guided mutation with Evo-Harness-style experience updates)?
