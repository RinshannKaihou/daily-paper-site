Critical edge

All headline results are single runs with no error bars — several wins sit within noise. And no analysis shows which strategies agents actually use, so “the agent owns the search” stays mechanistically unverified.

01 Methodology — the algorithm becomes the agent

A sandboxed Claude Code instance plans its own evolutionary search. Classical selection rules are demoted to single read-only queries the agent may use, combine, or replace.

  • ASearch agent. Each session starts from a task brief, a database briefing (best fitness, targets, quota) and the current strategy; it queries the graph, runs local experiments, and submits candidates to a server-side evaluator that returns fitness plus steering notes. MAP-Elites and UCT are one Cypher query each.
  • BLong-term memory. A Neo4j graph of typed nodes — ideas, candidates keyed by SHA-256, sessions, lessons — with fact-vs-claim provenance on edges; the database rejects direct agent writes, so the store stays tamper-resistant.
  • COptional meta agent. Distills session transcripts into per-session lessons, saved Cypher query tools, and a branch strategy injected into future sessions — never touching genomes or the evaluator.

Sessions reset context on stall — capping input-token cost and escaping local optima. Evaluation: 24 problems, five frameworks, cost-matched at published API list prices.

02 Evaluator reward-hacking audit

Three recurring failure modes found in prior frameworks’ evaluators — a measurement-integrity contribution independent of AgentDiscover itself.

  • Incomplete output validationA degenerate two-sample Signal Processing candidate scored 0.9250 under the original evaluator vs the 0.727 honest optimum.
  • Candidate-controlled scoringA candidate rebound pearsonr to return a constant 1e9; an LLM-SQL evaluator even executed candidate code via pickle deserialization.
  • Training-boundary leakageWorkload leakage inflated the EPLB balance score from 0.25 to 0.44.

All main tables are re-scored under corrected evaluators — original and corrected reported side by side. Implicit warning: several published baseline numbers were set by exploitable evaluators.

04 Strengths

  • +Unusually broad evaluation: 24 problems across kernels, biology, algorithm design, mathematics, competitive heuristics and systems, cost-matched where spend data exists.
  • +Spend–performance curves instead of single-point leaderboard scores — more decision-useful.
  • +Honesty-conscious infrastructure: evaluator isolation, read-only typed graph access, fact-vs-claim provenance.
  • +Reward-hacking taxonomy with concrete exploit numbers — a contribution beyond the framework itself.
  • +Clean fork-pair ablation design that removes run-to-run randomness from the meta-agent comparison.

05 Limitations

  • −Single run per main-table entry; no variance, and wins like Erdős overlap (0.38077 vs 0.38089) are within noise.
  • −Heterogeneous setups across tables (Opus 4.6 / Opus 5 / GPT-6 Sol; re-run vs imported baselines) muddy apples-to-apples reading.
  • −No backbone swap on a fixed task — scaffold vs model-family attribution untested.
  • −No analysis of which strategies agents actually employ — the mechanistic claim behind the headline is unverified.
  • −Spend estimated at list prices (runs used subscriptions); ablations ran on weaker Haiku 4.5, transfer untested.

06 Questions for further exploration

  1. Q1Do agents rediscover MAP-Elites/UCT via their Cypher queries — or synthesize novel strategies? Can strategy usage be logged across tasks?
  2. Q2Would the headline margins survive 5–10 seeds per entry, especially the noise-level wins (Erdős overlap, Cloudcast)?
  3. Q3Can the reward-hacking findings become a public adversarial suite stress-testing future discovery-framework evaluators?
  4. Q4How do the meta agent’s written strategies compare against hand-tuned harnesses (AdaEvolve/EvoX) in the same adaptation space?
  5. Q5Does the context-reset benefit (25.2% → 35.3%) transfer to non-discovery long-horizon agent loops, e.g. automated research?
