01 · Key metric

+13.14pts

average success-rate gain over RAO — the strongest recursive baseline — on TextWorld-Sync (65.07% vs 51.93%).

  • +5.38 on TextCraft-Synth (74.31% vs 68.93%)
  • 2.1–5.1× fewer external verifier / judge calls & tokens
  • +2.43 further at test time via rubric-guided tree search

02 · Why this matters

Agents that learn to grade their own work in shared weights — a core mechanism for reliable self-improving agent systems.

自学习「评估自身产物」，并以经验证结果锚定的排序目标抵御自我评估漂移——自我改进型智能体系统的核心机制，且学到的裁判还能在探理时做树搜索选择器。

03 · Critical edge

Trained and evaluated on a single 4B model across two synthetic text-game benchmarks — and the TextWorld headline partly re-scores Hard/Extreme difficulty levels the policy already trained on.

The safety net is a training-time verified anchor, itself a noisy LLM judge on TextWorld — and where no outcome is verifiable at all, SERA has no grounding signal.

01

Methodology

SERA trains a single shared policy (Qwen3-4B-Instruct-2507) that either solves a task or emits a delegation action, recursing into a tree of itself — max depth 3, K = 8 independent trees per root task. Three rewards, optimized by alternating CISPO updates (execution : decomposition : rubric = 16 : 2 : 2) with leave-one-out advantages and inverse-frequency depth weighting:

  1. Execution. Before delegating, the parent freezes a weighted natural-language rubric, conditioned only on delegation-time information. After the child finishes, a separate gradient-free invocation of the same policy scores the frozen rubric against the trajectory: a binary success gate times the weighted criterion sum — incomplete work earns zero. The root gets the verified environment outcome; every other node gets its rubric score.
  2. Decomposition. Each delegation is credited by leaf coverage — the fraction of the root task’s leaf-level work inside its subtree, times the root outcome. Failed trees score zero; execution and rubric tokens receive none of it.
  3. Rubric training. Cloning the state and sampling B−1 counterfactual rollouts, a margin ranking loss pulls verified successes above failures on the same subtask. The external judge/verifier anchors only this loss — it is never the task reward, blocking co-adaptation and score inflation.

Training: full fine-tune, Adam 1e-6, batch 8 root tasks, 2×8 H200; 250 updates (TextCraft-Synth) / 400 (TextWorld-Sync). Benchmarks: TextCraft-Synth — procedural crafting, deterministic program verifier, 632 test tasks across four recipe depths. TextWorld-Sync — new, 7 coordination-structured families over a shared world (1,500 train / 1,400 test); an LLM judge supplies binary labels only for rubric training.

03

Strengths vs Limitations

Strengths

  • Crisp separation of what the reward is (continuous rubric score), who supervises (verifier only during rubric training), and which tokens each signal updates — maps one-to-one onto the ablation table.
  • Rubric-as-ex-ante-commitment: frozen before the child runs, generator blind to its trajectory; the success gate denies unearned partial credit.
  • Falsifiable core finding: rubric training, not rubric use, is the driver — a one-change comparison worth +9.16 pts on TextWorld; the Rank+Disc collapse (−9.07) shows why verified anchoring matters when evaluator and solver share weights.
  • Strong hygiene: identical optimization pipeline for all baselines, deterministic success verification, auditable supervision-cost tables — and honest reporting that the untrained policy judge loses 0.22 pts.

Limitations

  • One 4B model (Qwen3-4B-Instruct-2507), two synthetic text-game benchmarks — no real-world agent tasks, no larger or cross-model runs.
  • Needs some verified outcome at training time for the ranking anchor; fully unverifiable domains are out of scope by construction.
  • Self-preference is mitigated, not eliminated — the TextWorld anchor is itself a noisy LLM judge, and no experiment varies label quality.
  • Leaf-coverage reward is importance-blind (leaf-padding unpunished) and slightly hurts TextCraft (−0.53).
  • TextWorld training split already contains Hard/Extreme tasks; code and benchmark only promised for release at v2; TextWorld training runs ~2× slower than RAO.
04

Questions for further exploration

  1. Does rubric-trained self-evaluation survive a noisy training-time judge — a controlled label-noise injection would probe the failure mode the authors acknowledge.
  2. Do the gains transfer to a 32B+ base model, or to real-world delegation (code repositories, web research) where subtask success is not programmatically checkable?
  3. Can subtask-level importance weights replace uniform leaf coverage — closing the pad-the-leaf-count loophole without hurting TextCraft?
  4. How do other label-free rubric rewards fare when score spread conflates difficulty and quality? Rank+Disc collapsed −9.07 pts in this tree setting.
  5. Can learned rubrics generalize across unseen task families — enabling self-evaluation where even the root outcome is only fuzzily verifiable?
