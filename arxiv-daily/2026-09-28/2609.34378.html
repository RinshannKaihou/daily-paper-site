01

Pipeline — from GitHub PRs to a marathon agent

→ STAGE 1

Ultra-long-horizon task synthesis

100,000 test-verifiable tasks mined from major-release PRs across 10,000 repos (React → CUDA → vLLM). Difficulty by added lines: Easy/Medium/Hard = 2:3:5. Each task = pre-PR checkout + PR-comment instruction + fail-to-pass/pass-to-pass unit-test verifier in a networked Harbor sandbox. Multi-Task Chaining fuses 5 Hard tasks into 3,000 “Frontier” chains whose verifier is the union.

→ STAGE 2

Diverse-harness rejection-sampling SFT

Teacher Kimi K3 — it “consistently runs for hours” — solves the same tasks through three harnesses: Claude Code, Codex, OpenClaw, to prevent harness overfitting. 40,820 reward-1 trajectories (14,159 + 13,583 + OpenClaw) full-parameter SFT Qwen3.5-9B at 256k sequence length.

STAGE 3

GRPO + Later Stage Bonus Reward

Real sandboxed rollouts, a random harness per task. An LLM judge splits each trajectory into phases and pays +0.5 when “exceptionally valuable operations” land in the later half: R = R_correctness + R_bonus. 8,000 environments (5k atomic + 3k chains) on 32 H800 GPUs; entropy stays stable throughout.

03

Strengths vs. open questions

Strengths

  • Tamper-resistant reward: unit-test verifiers (fail-to-pass + pass-to-pass), far harder to hack than LLM-judged correctness; diff-size curriculum is a sensible horizon proxy.
  • Multi-Task Chaining is a cheap knob for harder long-horizon tasks — the verifier union keeps the reward objective intact.
  • Random harness–task pairing in RL targets harness overfitting, a real failure mode most agentic post-training papers ignore.
  • Unusually complete engineering disclosure: sandbox specs, three-level instruction fallback, exact hyperparameters, per-harness trajectory yields.
  • Real sandboxed RL with stable reward/entropy curves — robust optimization, not static traces.

Limitations & risks

  • Tiny benchmark variance unaddressed: n=17 and n=20; no multi-seed or confidence intervals for any result.
  • Large distillation gap: 26.4 vs teacher’s 79.8 on FrontierSWE (~1/3); no 27B/35B variants probe the ceiling.
  • Reward-hacking risk: the +0.5 bonus comes from a proprietary, same-family LLM judge, paid even on failed runs — un-audited.
  • Contamination channel: internet-enabled sandboxes on public-PR tasks — the reference diff is one search away; never discussed.
  • Headline overstated: “10+ h / 1000+ calls” supported only anecdotally; reported averages are 3.56 h / 648 calls.
  • No release: no code, data, or model; per-harness (Codex/OpenClaw) evaluation missing despite being a core selling point.
04

Questions for further exploration

  1. Does Marathoner actually transfer across harnesses? A per-harness eval (Codex, OpenClaw) would directly test the diverse-harness claim.
  2. How much of the Later Stage Bonus is gamed? Audit flagged “valuable operations” against ground-truth diffs; test bonus-heavy rewards on failed trajectories.
  3. Do agents exploit networked sandboxes to look up the public reference PRs — and does disabling network change RFT/RL yields?
  4. Does Multi-Task Chaining create genuinely sequential tasks, or do the 5 chained atoms stay trivially decomposable?
  5. How does the recipe scale with base size (e.g., Qwen3.6-27B), and how much of the 26.4-vs-79.8 gap is capacity vs data?
  6. With n=17 and n=20, do the reported rankings survive multiple evaluation seeds?
