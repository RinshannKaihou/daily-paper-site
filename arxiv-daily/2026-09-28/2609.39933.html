01

Methodology

ConflictGuide-Skill (offline, once per model) + two-stage evolution

The blind spot. An AutoResearch loop judges each code edit by a scalar task gain Gt alone — which says nothing about behaviors that compete for the same mechanism. Within task-gain quartiles, behavior-outcome entropy averages 0.892: a good scalar score does not predict what happened to the model’s other behavior.

ConflictGuide-Skill. A five-stage workflow screens a literature-grounded Root–Axis–Mechanism taxonomy (9 roots · 6 axes · 110 mechanisms) against architecture, data, and objective evidence to instantiate one conflict c = (BA, BB, Mc) — two desirable behaviors coupled through a shared mechanism — then designs a minimal probe set and freezes its thresholds. Screening sees only pre-evolution information, so a conflict can never be chosen retrospectively to explain an outcome; if evidence is thin, the skill abstains rather than force one.

Two-stage schedule. Stage I runs standard scalar-only AutoResearch (default 100 iterations). Stage II conditions each proposal on probe readings and extends the retention rule: negative gains are never kept, and marginal task gains survive only when probes certify sufficient conflict alleviation.

03

Strengths

  • S1The blind spot is quantified, not anecdotally asserted — 7.2% joint-improvement share and 0.892 outcome entropy within scalar-gain quartiles put a number on what scalar feedback cannot see.
  • S2Disciplined experimental design: shared Stage-I branch points, matched budgets, paired seeds, from-scratch retraining, held-out data touched only after search, frozen probe thresholds.
  • S3The early-vs-delayed feedback study is the negative control most agent papers skip — and it directly justifies the two-stage schedule (100/100 split best at fixed 200).
  • S4Baselines isolate the active ingredient: multi-metric feedback and trade-off-prompt-only both lose — a generic caution or generic extra metrics do not substitute for instantiated probes.
  • S5Abstention semantics + machine-checkable Probe Cards — refusing to force a conflict on thin evidence is a thoughtful reliability pattern for long-running agent systems.
04

Limitations

  • L1Conditional applicability: the method needs an evidence-backed conflict with probe-measurable behaviors — when the skill abstains, ConflictGuide degenerates to plain AutoResearch.
  • L2One conflict per family, five families, all hand-designed probes — no taxonomy-free or automated probe-design baseline, so broader applicability is unestablished (authors’ own admission).
  • L3Per-model probe setup effort is excluded from cost accounting — the matched-budget comparisons ignore the human/agent overhead that dominates in practice.
  • L4A quiet negative result: SNGP CIFAR-10 OOD AUPR (0.7487/0.7497) never recovers the unmodified reference’s 0.7804 — the “improvement” is relative to a degraded baseline. Guidance-only also actively harms SNGP OOD before retention rescues it.
  • L5No significance testing anywhere; several wins (GCNII on a 251-node graph) ride on high-variance small data. Public code release is gated on paper acceptance.
05

Questions for further exploration

Q1

Is the 110-mechanism taxonomy load-bearing or decorative — how would a taxonomy-free baseline (agent-proposed conflicts, same qualification gates) compare?

Q2

Can probe construction and qualification be automated and amortized across models — and what is the true end-to-end cost once per-model setup effort is included?

Q3

What guardrail makes probe guidance safe to inject without the auxiliary retention rule, given that guidance-only harms SNGP OOD AUPR below baseline?

Q4

Would adaptive Stage I→II timing (driven by diminishing scalar gains) remove per-model budget tuning — and does delayed feedback hold for LLM training loops where behaviors are harder to probe?

Q5

SNGP CIFAR-10 OOD never recovers the unmodified reference: does conflict-driven search systematically trade one OOD axis for another, and how should multi-conflict settings be handled?
