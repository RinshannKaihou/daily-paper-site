Why this matters

Shows where 4-bit MX inference is trustworthy: ViTs hold within 5%, while compact convnets and EfficientViT collapse — a representation mismatch, not just a speed problem.

02

Method — every fix answers one measured failure

VisionMX-LW layerwise · VisionMX-BW blockwise

VisionMX reads like a repair manual. The paper first isolates why block-scaled MXFP4 breaks vision models, then builds one component per cause — in two variants: VisionMX-LW (AdaRound-style, layer by layer) and VisionMX-BW (BRECQ-style, whole executable blocks with learned bias updates).

Failure — nonuniform gridFP4’s element grid is nonuniform (spacings 0.5 / 1 / 2), so choosing between the two nearest levels is provably suboptimal: Theorem 4.1 keeps the guarantee for INT4 but not FP4 — a 2-weight counterexample reaches 0.315 loss where adjacent-pair rounding only manages 0.365.

Fix — RangeRoundLearn each weight’s choice inside a bounded window that provably contains the optimum: δ ≥ 2·gmax, i.e. δ=4 for unscaled E2M1 (Prop 5.1). Rectified-sigmoid gating, multi-well regularizer annealed β 20→2.

Failure — coarse block scalesPower-of-two-only UE8M0 scales underperform richer exponent formats: UE5M3 beats it by +3.44 pts on weight-only ResNet-18 RTN (65.87 vs 62.43). A full UE0M8–UE1M7 sweep pins exponent bits as the dominant factor.

Response — format evidenceNo new format is proposed; instead VisionMX evaluates UE8M0, UE5M3, NVFP4 and MXFP8 side by side, and accuracy returns as exponent bits grow — evidence aimed straight at hardware scale-format choices.

Failure — wasted negative codesPost-ReLU activations are nonnegative, so roughly half the signed codebook sits permanently idle regardless of block scale — an effective loss of ~1 bit of code space (code-occupancy histogram, ResNet-18).

Fix — AACPer-channel shift + scale calibrated per MX block, re-centering activations onto the negative codes, then folded into the next layer for free; plus learned bias updates and block-granular QDrop.

05

Strengths vs limitations

from the critical assessment

Strengths

  • +Unusually broad coverage: 15+ models across CNN / Transformer / hybrid families, 4 tasks, 4 MX formats — all with 5-seed mean±std.
  • +Mechanistic, actionable diagnosis: scale-format sweep, FP4 rounding counterexample with exhaustive enumeration, ReLU code-occupancy histogram — each maps onto exactly one method component.
  • +Real theory with proofs that constrains design: the δ=4 window is derived, not tuned arbitrarily.
  • +Spectacular recoveries where it matters: EfficientViT-L2 2.54→81.89 (UE8M0) and 0.08→83.82 (NVFP4) — nearly full float accuracy at W4A4.
  • +Honest tables: losing cells printed with per-cell standard deviations.

Limitations

  • −RangeRound, the nominally novel optimizer, adds +0.69 pts at best and can hurt layerwise (see 04); the practical recipe is dominated by affine correction + bias + blockwise reconstruction.
  • −Best results need costly BRECQ-style blockwise optimization: 10k–20k steps per block on an H100 with 2,048 calibration images — not compared against cheaper settings.
  • −No MX-specialized competitor compared despite being cited; GPTQ/SpinQuant appear only for ViT classification.
  • −Purely an accuracy study: no hardware-measured latency, memory or energy; AAC’s overhead asserted negligible, never quantified.
  • −No code release; the factor-two diagonal-dominance Hessian assumption is unverified for the networks the method is applied to.
06

Open questions

for further exploration
  1. Does AAC transfer to LLMs? The wasted-negative-codes diagnosis targets post-ReLU activations; SwiGLU/GELU outputs are signed but asymmetric — and does the folded shift disturb downstream KV-cache statistics?
  2. Is bounded-window rounding ever justified on uniform grids? Theorem 4.1 says adjacent pairs suffice there — is FP4 the only regime where the window pays for its optimization cost?
  3. Hardware on trial. If real MX pipelines mandate UE8M0 power-of-two scales, does EfficientViT-L2’s 2.54% collapse become an argument against the hardware choice rather than the model?
  4. Predicting collapse before quantizing. MobileNetV2’s −97.46% weight-only failure is attributed to small conv weights misaligned with the grid — can the HW spectrum yield a closed-form pre-deployment sensitivity test?
  5. Compose with rotations? Can SpinQuant-style rotations rescue DeiT-B — and is block-granular QDrop still necessary once rotations whiten activations?
