01

Methodology — the trace-recycling loop

frozen model · no labels · 10–80 fitting requests / task
Step 1

Serve & record

Run requests under the fixed menu; record tool calls, outputs, and the realized answer.

Step 2

Score (leave-one-out)

Excise one tool's output evidence, re-score the same frozen answer; the log-likelihood drop is the tool's worth.

Step 3

Aggregate

Average request-level scores into a task-level ranking over the registry.

Step 4

Prune & deploy

Keep Top-K as the task's persistent space; later batches revise it with the same rule.

Lx(s) = Lθ(yx | hx) − Lθ(yx | hx¬s)  // teacher-forced, same frozen answer

LOTS treats the agent's own execution trace as its own evaluation set. Each tool is valued by how much removing its recorded output lowers the likelihood of the answer the model already produced — no rollouts, no correctness labels, and the tool is scored alongside the full execution context, preserving compositional dependencies.

Theorem 1: under bounded second-order tool interactions (|Δs,tF| ≤ β), Top-K exactly maximizes an additive approximation of the fixed-output likelihood, with error bounded by C(r,2)·β. The evidence-removal operator is benchmark-specific: re-execute chains without the tool (TGB), delete the calling assistant message (BFCL), delete the candidate's output line (GTA-Atomic).

03a

Strengths

  • Clean framing — output-unaware selection, statelessness, per-request cost — with one method addressing all three.
  • Consistent gains across 8 models and 3 heterogeneous benchmarks: not cherry-picked to one setting.
  • Beats label-using upper references (TTO†, Beam Search†) at a fraction of the cost; the scoring-target ablation directly justifies the label-free design.
  • Unusually thorough appendix: deletion-rule ablation, Shapley and trace-judge comparisons, corruption robustness, honest token accounting with break-even counts.
  • Fitted spaces are reusable artifacts (18/20 cross-model transfer), not per-model tuning.
03b

Limitations

  • Thin scale: 112 pooled GTA-Atomic requests, 160 BFCL records; TGB is synthetic and author-designed; scaling diagnostic caps at 240 tools vs real registries with thousands.
  • Evidence removal is hand-engineered per benchmark, down to hand-picked scored-token regexes — generality to new environments is asserted, not shown.
  • Needs open-weight logprobs; closed models can only consume spaces fitted elsewhere.
  • Cold start: 10–80 fitting requests plus a clustering router; selection is slow at scale (176 s at 15 tools → 8,158 s at 120 on one L40S).
  • Inherits the model's blind spots: score retention falls to 0.620 at 50% wrong answers and 0.102 at 75%; Qwen2.5-14B is better off unpruned.
04

Questions for further exploration

  1. Does the clustering-based router degrade gracefully toward Keep-all under task drift — or catastrophically?
  2. Can the evidence-removal operator be automated for arbitrary MCP-style environments, or does every tool API need a hand-crafted intervention?
  3. At 10k+ tools, would persistent spaces compose with deferred retrieval — and does Theorem 1's additive-interaction assumption survive?
  4. Gold answers still score higher (0.796 vs 0.724): could a tiny labeled holdout or verifier close the gap without giving up label-freeness?
  5. Under API drift, can the same likelihood machinery detect and prune broken tools, not merely irrelevant ones?
