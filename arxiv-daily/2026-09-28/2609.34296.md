> **一句话总结：** 提出 Dr.Credit：不依赖标准答案，而是把任务 rubric 当作共享参照系，为深度研究 agent 的每个工具调用轮次维护「按 rubric 分组的证据支持历史」，由 LLM judge 评定每轮新证据的增量贡献作为过程信用，归一化为过程优势后叠加到 GRPO 结果优势上；仅用 Qwen3-8B 骨干就在 4 个深度研究基准上取得 61.7 平均分，超过同配置 GRPO 基线 3.5 分，并击败 DeepSeek-V4-Pro（60.2）、Opus 4.8（60.2）等前沿专有模型。

> **TL;DR:** Dr.Credit fixes the "everyone gets the same outcome reward" problem in rubric-based RL for deep research agents: for each rubric it keeps a per-rubric evidence history, an LLM judge scores each Search/Visit turn by the *additional* rubric support it adds (capped, history-aware), and these turn credits are group-normalized into process advantages added to GRPO outcome advantages. On the DeepRubric validation set, ResearchQA, DeepResearchBench, and ResearchRubrics, an 8B agent trained this way scores 70.6/79.8/46.7/50.3 (61.7 avg) vs 67.4/76.8/40.9/48.1 (58.2 avg) for a compute-matched GRPO baseline (+3.5 avg), beating frontier proprietary systems like DeepSeek-V4-Pro (60.2) and Opus 4.8 (60.2). Ablations show removing the process signal costs -3.5 avg and removing the evidence history costs -3.0 avg; the agent also acquires evidence 47.2% more efficiently per turn (0.53 vs 0.36 proxy at 8 turns) and beats GRPO's best 12-turn report quality (66.41) within an 8-turn budget (67.69).

## 核心贡献

- **Rubric-grounded credit（无标准答案的过程信用）：** 针对开放式 rubric 任务没有 canonical answer 的问题，提出把 rubric 本身当作过程监督的参照系：每条 rubric 独立维护一个「支持历史」H_{t,k}（已积累的证据点集合），LLM judge 只评估当前轮次信息相对历史的**增量**支持 g_{t,k}，轮次信用为其各 rubric 贡献之和，避免重复奖励既有证据。
- **深度研究场景的具体化：** 在仅有 Search / Visit 两个工具的 ReAct 式 agent 上，Visit 轮由 judge 按 0 / 0.2 / 0.5 三档打分；Search 轮采用双分支复合信用——(a) URL 匹配归因（后续实际 Visit 的信用回传为 navigation credit），(b) 由独立 judge 直接评估摘要片段的 rubric 支持（snippet credit，每次 rubric 命中 η=0.1），两部分相加且封顶为 1。
- **与 GRPO 的优势融合：** 过程信用在 rollout group 内做标准化得到过程优势 A^ry，与 GRPO 结果优势 A^O 相加只作用于非最终轮（最终轮仅保留结果监督），在不放弃最终报告质量监督的前提下引导中间决策。
- **实证验证：** 在 4 个基准（DeepRubric 验证集、ResearchQA、DeepResearchBench、ResearchRubrics）上全面超过开放基线，8B 模型平均分与前沿专有模型持平；并给出证据获取效率、有限轮次预算下的报告质量、训练时间三个维度的深入分析。

## Key Contributions

- **Rubric-grounded process credit without canonical answers.** Instead of grounding turn-level rewards in a ground-truth answer (the standard recipe, inapplicable to open-ended tasks), Dr.Credit uses the task's rubric set as the shared reference: per-rubric support histories H_{t,k} track evidence already accumulated, and an LLM judge assigns per-rubric contributions for only the *newly added* support, so redundant retrieval is not re-rewarded.
- **A concrete instantiation for deep research.** For a ReAct agent with Search and Visit tools: Visit turns get 0/0.2/0.5 judge scores per rubric; Search turns get composite credit from (a) URL-matched navigation attribution (Visit credits flowing back to the search that surfaced the page) and (b) an independent snippet judge (η=0.1 per accepted rubric match), summed and capped at 1.
- **Advantage fusion with GRPO.** Turn credits are normalized within the rollout group into process advantages and added to GRPO outcome advantages on non-final turns only, retaining final-report supervision — Table 3 shows the two signals are complementary (removing process: -3.5 avg; removing outcome: -2.3 avg across the three external benchmarks).
- **Evidence and efficiency findings.** The trained agent reaches a cumulative evidence-proxy score of 2.994 within 6 turns vs GRPO's 2.83 within 8 turns, and exceeds GRPO's best-observed report quality (66.41 at 12 turns) with an 8-turn budget (67.69), while saving 11.18 h (14.9%) of cumulative training time over 200 steps despite an early scoring overhead.

## Methodology

**Setting.** An open-ended question q is answered by a policy π_θ via T ReAct-style turns of [think]/[tool call]/[tool response], ending in a final answer ã evaluated by a weighted rubric set R_q (K rubrics, weights w_k, judge satisfaction s_k ∈ [0,1]) — the RaR rubric reward of Equation (1). GRPO shares this outcome advantage across all turns, so a high-scoring turn can reinforce ineffective decisions; existing credit assignment fixes this using ground-truth answers, which open-ended tasks lack.

**Rubric-grounded process credit.** For each rubric k, the method maintains a support history H_{t,k} ⊆ S_k(q), the set of evidence-grounded support points established before turn t (initially empty, evolving per-rollout). At each non-final turn, an assessor ℐ examines the new information e_t against (R_q, e_t, H_t) and outputs per-rubric contributions g_t = (g_{t,k}) with g_{t,k} ≥ 0 measuring support *relative to* the existing history (zero when no additional support), plus accepted support increments ΔH_{t,k} that update each history by union: H_{t+1,k} = H_{t,k} ∪ ΔH_{t,k}. The turn's rubric-grounded credit is c_t^ry = Σ_k g_{t,k}. Reading the history before the update is what prevents repeated evidence from accumulating credit.

**Deep-research instantiation.** For the basic agent (Search = discover candidate URLs + snippets; Visit = read a webpage):
- *Visit credit:* the LLM judge (Qwen3-35B-A3B) scores additional support per rubric as no / partial / high-value new evidence → g ∈ {0, 0.2, 0.5}; positive assessments also extract support points into the histories.
- *Search credit:* two branches added together. (a) *Navigation credit:* normalized result URLs are matched to later Visits within the same rollout and the matched Visit credits are aggregated — the search that surfaced a page is rewarded for what the page yielded. (b) *Snippet credit:* an independent judge assesses rubric support directly in results that receive no later visit, contributing η = 0.1 per accepted rubric match. The sums defining c^nav and c^snip are capped at 1 to keep turn-level credit on a shared scale.

**Policy optimization.** For G rollouts per (q, R_q), process credits are group-normalized with mean/σ over all non-final turn credits (zero-credit turns included) into A^ry; outcome rewards are GRPO-normalized into A^O. The fused advantage is Ã_t = A^O + A^ry for t < T_I and A^O alone at the final turn; all tokens of a turn share that turn's Ã. The objective is the clipped GRPO surrogate with KL regularization to a reference policy; environment observations are masked out of the loss.

**Training setup.** Data from DeepRubric (evidence-grounded rubric sets paired with research queries; 128 examples held out for validation). RL starts from Qwen3-8B after 2 epochs of SFT on 1,505 filtered research trajectories, then 200 steps on 7,149 query–rubric pairs (batch 32 queries, G = 8 rollouts). Qwen3-35B-A3B serves as the judge for both process credit and final-answer evaluation.

## Results & Highlights

- **Headline: beats frontier proprietary systems with 8B parameters.** Four-benchmark weighted rubric-score average (100-point scale): Dr.Credit (Qwen3-8B) 61.7 vs the compute-matched GRPO baseline 58.2 (+3.5, same SFT init / data / outcome reward / budget). It surpasses DeepSeek-V4-Pro (60.4), Opus 4.8 (60.2), and GLM-5.3 (59.8), edges past Kimi K3 (61.6), sits below GPT-5.1-luna (63.0) and Gemini-3.1-Pro Research (66.7). Per benchmark: DeepRubric val 70.6 vs GRPO 67.4 (+3.2); ResearchQA 79.8 vs 76.8; DeepResearchBench 46.7 vs 40.9 (+5.8, the largest gain); ResearchRubrics 50.3 vs 48.1. All open baselines lag: DeepRubric-8B 55.2, DR Tulu-8B 55.5, Tongyi DeepResearch-30B-A3B 50.4, best Naive RAG 49.5.
- **Credit-design ablation (Table 2).** Visit-only credit: 59.7 avg; +navigation attribution: 60.4; +snippet scoring (final config): 61.7 — the best four-benchmark average, though snippet scoring costs 0.2 on DeepRubric (70.8 → 70.6). Discounted credit propagation with γ = 0.93 *lowers* all four benchmarks (61.7 → 59.9 with snippets), supporting undiscounted attribution with credit capping.
- **Supervision-source ablation (Table 3).** Removing the process advantage A^ry costs -3.2 (DeepRubric), -4.4 (ResearchQA), -2.9 (DeepResearchBench), -3.5 avg; removing the outcome advantage (process-only training) costs -1.2 / -3.6 / -2.1, -2.3 avg — each signal alone is worse, confirming complementarity. Removing the evidence history from credit computation costs -3.0 avg (-3.0 / -3.9 / -2.1), validating history-aware incremental scoring.
- **Evidence acquisition efficiency (Fig. 4).** On DeepRubric validation, Dr.Credit's cumulative credit-based evidence proxy reaches 2.994 within 6 turns vs GRPO's 2.83 within 8 turns; per-turn proxy score 0.53 vs 0.36 at 8 research turns (+47.2%).
- **Quality under constrained budgets (Fig. 4c).** With an 8-turn inference budget Dr.Credit scores 67.69 on report rubrics, exceeding GRPO's best-observed score of 66.41 achieved only at 12 turns — i.e., GRPO's peak quality with one-third fewer allowed turns.
- **Training cost (Fig. 5).** Dr.Credit pays an early process-scoring overhead (costlier until step 34), but from step 34 onward has lower cumulative training time, saving 11.18 hours (14.9%) over the 200 steps (63.97 h vs GRPO's 75.15 h); it also surpasses GRPO's *final* validation score by step 120 and finishes +3.2 ahead at step 200.

## Critical Assessment

- **Judge-policy homogeneity is unexamined.** Both the process-credit judge and the outcome judge are Qwen3-35B-A3B, the same model family as the trained Qwen3-8B policy. Family self-preference could inflate both training signal quality and evaluation scores; the paper reports no judge-model ablation (Appendix B.5 only varies credit-parameter settings), so the sensitivity of the +3.5 gain to the judge's identity is unknown.
- **All four benchmarks are LLM-judged rubric scores from the same ecosystem.** There is no human evaluation in the main text; the "out-of-domain" benchmarks (ResearchQA, DeepResearchBench, ResearchRubrics) are still rubric-based deep-research evaluations stylistically close to the in-domain DeepRubric data, so the generalization claim is narrower than it sounds.
- **Frontier baselines are partly inherited, not re-run.** The DeepRubric and ResearchRubrics columns for proprietary models are marked as numbers taken from the DeepRubric and ResearchRubrics papers rather than re-evaluated under the authors' tools and judge — the comparison to Kimi K3 / GPT-5.1-luna / Gemini-3.1-Pro rests on cross-paper comparability.
- **The final configuration is not uniformly best.** Snippet scoring lowers DeepRubric from 70.8 (Visit+Nav) to 70.6; the discarded discount (γ=0.93) row shows the design is sensitive to propagation choices. The pipeline carries many hand-set constants (0/0.2/0.5 visit scores, η=0.1 snippet weight, credit caps of 1) ablated only coarsely (4 rows in Table 2), with finer settings relegated to an appendix.
- **No variance reporting.** Results are single 200-step runs; no seeds, error bars, or significance tests are given for the +3.5 avg headline, although RL-for-agent runs are known to be high-variance.
- **Honest caveats worth crediting:** the authors explicitly note Dr.Credit's proxy for research-turn counts degrades during training, that early scoring overhead exists (step < 34), and that process supervision alone (without outcome) underperforms — the efficiency claims are measured, not overclaimed.

## Strengths

- Removes the canonical-answer dependency that blocks most credit-assignment methods on open-ended rubric tasks — a clean conceptual contribution with a precise formalism (per-rubric histories, union updates, history-before-scoring).
- The dual-branch Search credit (URL-matched navigation attribution + independent snippet judging) is a well-motivated decomposition of "source discovery" vs "directly usable evidence."
- Unusually thorough main-text ablations for this venue class: credit design (Table 2), supervision source (Table 3), and evidence history are each isolated with quantitative deltas.
- Practical analyses beyond leaderboards: evidence-acquisition curves, report quality under inference-time turn budgets, and honest wall-clock accounting including the method's own early overhead (14.9% net saving).
- Strong result credibility markers: 8B model competitive with frontier systems, gains on all four benchmarks including three never seen in training, and training-time parity or better than GRPO.

## Limitations

- Heavy dependence on a 35B LLM judge for every Visit turn and snippet, adding scoring cost and coupling result quality to judge capability/bias (and per the paper's own Figure 5, scoring dominates early training time).
- Evaluation confined to rubric-satisfaction metrics; no downstream human study, no factuality/citation-accuracy audit beyond judge-assessed citation quality, and no non-rubric benchmark to test transfer.
- Single model scale (Qwen3-8B) and single policy family; the 35B-judge / 8B-policy ratio may not transfer to larger policies or weaker judges.
- Hyperparameter-heavy design (three-tier visit scores, η, caps, rejected discount) with only coarse main-text ablation; the navigation branch depends on exact URL matching, which may break with redirect/tracking-URL noise in the wild.
- Search/Visit-only toolset — the credit machinery is demonstrated for one agent archetype; extension to code execution or other tool types is asserted via the general framework but not measured.

## Questions for Further Exploration

- Does the +3.5 average gain survive a judge from a different model family (e.g., an open judge unrelated to Qwen), and how does credit quality degrade with smaller judges?
- How does Dr.Credit behave when rubrics are noisy or partially wrong (rubric quality ablation), since the entire process signal is rubric-relative?
- Can the URL-matching navigation branch be replaced with learned or embedding-based attribution for environments where exact URL matching is unreliable?
- Does rubric-grounded process credit transfer to non-search tool actions (code execution, file editing) in broader agentic settings, as the general framework suggests?
- Is the outcome advantage still necessary at larger scales, or does process supervision alone close the -2.3 gap as rubric coverage grows?
