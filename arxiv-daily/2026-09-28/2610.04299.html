01

Diagnose the collapse

GPT-5.6-Sol audits 200 sampled questions per round across five R-Zero iterations, judging validity and grouping questions by underlying task type. Two failure modes emerge: invalid questions accumulate, and lexical diversity control misses disguised repetition. A matched repair experiment (766 shared valid + 507 repaired questions) isolates invalid data as a direct cause.

02

Teach the solver to refuse

GRPO on 2,240 annotated questions (923 valid / 1,317 invalid: contradiction 28.9%, no-solution 27.5%, ambiguity 23.9%…) trains the solver to answer or output INVALID, with λ=0.5 penalty for false refusals. 10% replay each round keeps the refusal skill alive.

03

Gate the questioner twice

A candidate question earns reward only if it passes a validity gate (9 solver votes; majority INVALID → 0) and a novelty gate: a frozen base model compares it to K=8 sampled batch peers — any “same exercise type” match rejects. Pr(pass|p) ≈ (1−p)K; cost O(BK), not O(B²).

≈160 words, distilled from the paper’s Methodology. Uncertainty reward on survivors: R = min(s, 1−s), s ∈ [0.3, 0.8]; 10,000-question budget per round. Full protocol ↗

03

Strengths & Limitations

优势与局限对照

Strengths

  • Diagnosis before treatment: the matched-budget repair test (+3.37) is a clean causal experiment most self-play papers skip; the anti-selection finding (consistency filtering picks more invalid questions) is transferable on its own.
  • Each failure mode maps to a targeted mechanism — validity decay → refusal training, disguised repetition → sampled novelty gate — not a generic regularizer.
  • Analytical care: closed-form pass probability Pr(pass|p) ≈ (1−p)K plus explicit O(BK) vs O(B²) cost analysis.
  • Mechanism tied to outcome: invalid recall, validity rate, pseudo-label accuracy, and type concentration all move the right way — across two model families and three task domains.
  • Reproducibility: all prompts, hyperparameters, and baseline configs released; code + project page public (NSF #2541822).

Limitations

  • Frontier-model dependence: GPT-5.6-Sol provides labels, answers, and the judging metric itself — a shared-utility bias favoring R-Quest’s notion of validity; label-noise review coverage unquantified.
  • Scale untested: two 3–4B base models, math-only curriculum; whether validity feedback stays load-bearing at 7B–70B is open.
  • Reporting flatters all methods: best-checkpoint-per-domain selection, pass@32 (AMC/AIME) mixed with greedy decoding, single-seed runs, no error bars — the +0.92 general margin over R-Diverse is within plausible noise.
  • Probabilistic novelty gate: at 10% same-type fraction, K=8 still passes 43% of duplicates; K trade-off explored only to 16; “diversity sweet spot” is post hoc.
  • Unitemized compute: 9 validity votes + up to 10 solutions per accepted question — no FLOPs-per-final-point comparison against R-Zero/OCNR.
04

Open Questions

待探索
  1. Teacher-free bootstrap? Can GPT-5.6-Sol labels be replaced by solver self-consistency or code-execution verification without losing the initialization’s benefit?
  2. Does validity feedback survive scale? At 7B–70B, invalid questions are rarer — does the bottleneck shift entirely to novelty control?
  3. Adaptive K: can the novelty-gate budget be set per round from the measured same-type fraction, instead of a fixed K?
  4. Beyond math: do the top-5 concentration metric and validity taxonomy transfer to code or agentic tool-use self-play, where “same task type” is harder to adjudicate?
  5. True compute accounting: end-to-end FLOPs per benchmark point vs R-Zero/OCNR — and does 10% validity replay ever anchor the solver to early-round distributions?
