03  Critical edge

The missing baseline is the elephant in the room.

Never compared against a simple patience heuristic (“stop after k flat rounds”) — the betting machinery’s marginal value is unquantified. One trajectory per cell, no seed variance; OfficeQA’s CI spans 15 pp, so “no loss” there is close to unmeasurable.

01

Methodology

zero touches to the host system

The module wraps any propose–evaluate–gate loop without modifying its internals. Each round the system already scores candidate vs incumbent on the same validation items; the detector consumes those per-item paired outcomes X ∈ {−1, 0, +1} directly — no extra evaluations.

When to stop. Evolution should continue only while expected round-gain stays above ε. For every starting round s, a betting wealth process accumulates evidence — outcomes worse than ε multiply wealth up, better ones down — with fractions from aGRAPA or a fixed mixture. A CUSUM-style max over restarts keeps the strongest current evidence; crossing 1/δ raises the alarm. Under the pre-change hypothesis each process is a nonnegative supermartingale, so false alarms are guaranteed rare:

Mt = maxs W(s)t,  alarm at T = inf{t : Mt ≥ 1/δ},  E[Talarm] ≥ 1/δ

What to return. Restarts begun before the true transition hold the most wealth at alarm time, so ν̂ = argmaxs W(s)T estimates when meaningful improvement ended; the incumbent just before it, θν̂−1, is shipped back. Under a fixed pre/post gap, localization error shrinks at rate 1/n (Prop. 2).

Reward-hacked artifact avoided

The full run accepts a degenerate skill at round 16 — “answer ‘A’ without reasoning”, exploiting a skewed answer distribution. The detector alarms at T=8, estimates ν̂=2, and returns the round-1 artifact, never entering the degraded regime.

Honest caveat from the authors: the detector flags cessation of improvement — it does not explicitly identify hacking.

03

Assessment

strengths vs limitations

Strengths

  1. Genuinely plug-and-play — consumes paired outcomes the gate loop already computes; zero config changes; transfers across SkillOpt and GEPA unchanged.
  2. Principled statistics — anytime-valid guarantee E[Talarm] ≥ 1/δ plus a 1/n change-point bound, not ad-hoc patience rules.
  3. Experimental hygiene — a negative-control benchmark where it should stay silent (and does), a real reward-hack stress test, one-factor-at-a-time ablations.
  4. Honest framing — separates when it stops from what it returns; admits it detects “cessation of worthwhile improvement,” not hacking itself.
  5. Elegant pairing trick — per-item candidate-vs-incumbent differences turn a noisy scalar monitor into an n-sample-per-round test at zero extra cost.

Limitations

  1. No simpler baseline — never benchmarked against patience heuristics, so the betting machinery’s marginal value is unquantified.
  2. Single trajectory per cell — no seed variance for alarm rounds, ν̂, or token counts on stochastic LLM-driven loops.
  3. Theory–practice gap — localization guaranteed only for fixed-λ, single change point; the main runs use adaptive aGRAPA.
  4. ε hand-set to 0.01 everywhere — may mis-scale on low-accuracy benchmarks (OfficeQA, 14.5% baseline); no data-driven calibration.
  5. Small test sets (172–1400 items) — “no loss” deltas are statistically fragile; OfficeQA’s CI spans 15 pp.
  6. Reproducibility — no code release stated; 2 of 3 models are closed APIs; GEPA tokens estimated, not measured.
04

Questions for further exploration

Q1

Head-to-head against a k-round patience rule on validation gain — in both token savings and final artifact quality?

Q2

How variable are Talarm and ν̂ across LLM sampling seeds — is the round-4 stop on SearchQA typical or lucky?

Q3

Can restart wealth explicitly score downward jumps (reward hacking) — e.g., a two-sided CUSUM over Zt?

Q4

How should ε be calibrated from data — say, tied to the token cost of one round — and how sensitive is OfficeQA at its 14.5% baseline?

Q5

Does validity survive a refreshed validation set over time — a common anti-overfitting practice that breaks the fixed-pairing assumption?
