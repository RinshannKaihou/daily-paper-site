Why this matters

Frozen, task-spec-derived capabilities plus a two-sided acceptance gate turn skill self-evolution into an auditable revision loop — a blueprint for reliable long-horizon self-improving agents.

Critical edge

Every headline number comes from a single run — one optimizer–target pair, no seeds, no error bars. LiveMath’s test set is ~37 tasks, so its +2.5-pt margin sits within one flipped task (~2.7 pts) of noise.

01

How it works

Induce the requirement structure once, then focus every revision round through it.

  1. 1

    Freeze

    Before any execution, three frozen perspectives read task specs only — instruction, input structure, environment contract. A consensus call induces a binary task–capability matrix (C, Q); support ≥ 3 prunes noise, K lands at 9–22. Frozen for the entire run.

  2. 2

    Focus

    Each round, capability scores from training outcomes pick the capability with the largest unresolved task mass: c* = argmax πd(1−q̂d).

  3. 3

    Edit

    Evidence comes only from training tasks assigned to c* — stratified failures, a success contrast, related skill text, past edits. Three diagnosis + three edit Explorers merge into one whole-skill candidate.

  4. 4

    Gate

    A fixed selection set screens the candidate, then the training set re-rates it. Accept only if both paired changes are positive: Δsel > 0 ∧ Δtr > 0. Max 5 rounds; the 70% test split is never touched.

04

Strengths

  • Right question: execution traces show what the skill did, never which requirements recur across tasks — freezing the requirement structure fixes both blindness and comparability.
  • Deterministic, auditable machinery: frozen (C, Q), a fixed selection set, evidence-boundary enforcement, and the two-sided Δsel > 0 ∧ Δtr > 0 acceptance gate.
  • Attribution done properly: capability-source controls, degree-preserving randomization, a 2×2 crossover on held-fixed states — all pointing the same direction.
  • Accuracy and efficiency together: best on 4/4 benchmarks with 24% fewer average evolution tokens than the strongest iterative baseline.
  • Reproducibility-by-description: pseudocode for all stages, XML prompt schemas, a full per-benchmark token ledger, and a fairness table — though no code release.
05

Limitations

  • Assumption-heavy framing: recurring requirements must be visible in task specs before execution and fixable by editing skill text; environment faults are excluded by construction.
  • No ground truth for capabilities: ARI 0.883–0.973 shows self-consistency across perspectives sharing one input schema — correlated errors remain possible.
  • Single configuration, no variance: one optimizer–target pair; small pools (LiveMath 53, IFBench 89) make the smallest margins fragile.
  • Protocol-relative efficiency: the 24% token saving is measured at each method’s native budget and reverses on IFBench (+7.5%); the 5-round horizon is never sensitivity-analyzed.
  • By design, some capabilities stay unresolved under the conservative gate + horizon cap, and binding frequency is unmeasured; cross-domain evolution is future work.
06

Open questions

  1. Would the induced (C, Q) survive a second target model — or is it silently tuned to DeepSeek-V4-Flash’s failure distribution even though induction never sees executions?
  2. Why does every iterative method lose to One-shot Skill on IFBench: the add/replace/remove edit vocabulary, or the acceptance gate rejecting constraint-for-verbosity trades?
  3. Does unresolved task mass keep falling after round 5 — and would multiple candidates per round shift the token–accuracy frontier?
  4. Can capability induction re-close into the loop (re-inducing on pool changes) without losing the comparability benefits of a frozen space?
  5. Does the +4.4-pt candidate gain translate uniformly into held-out accuracy, or only on benchmarks dense with multi-capability tasks?

The induced space

Shape and reproducibility of the frozen capability decomposition.

  • ≥86%of tasks require multiple capabilities on SearchQA / SSB / LiveMath — vs only 36% on IFBench, its thinnest regime (1.29 capabilities/task).
  • 9–22capabilities induced per benchmark; 1.29–5.11 capabilities per task.
  • ≤0.17median pairwise support-set Jaccard — capability scopes are near-disjoint.
  • 0.883–0.973ARI (NMI 0.953–0.989) across three independent induction runs — the decomposition is self-consistent without any ground truth.
