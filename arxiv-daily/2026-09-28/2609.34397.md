# SkillFocus: Evolving Agent Skills via Capability Decomposition

> **一句话总结：** 针对 LLM Agent 技能演化中"每次修订只看执行轨迹、跨任务的重复性程序化要求被隐式绑定在当前技能行为上"的问题，SkillFocus 在演化开始前从任务规格(指令/输入结构/环境契约)中归纳出一个冻结的"能力空间"(任务-能力二值矩阵)，每轮用"未解决任务质量"最大的能力同时决定"改什么"和"用哪些证据改"，并以选择集+训练集双重配对正值门控做整技能验证——在 SearchQA/SpreadsheetBench/LiveMath/IFBench 四个基准上全部取得最高 held-out 准确率(平均 70.7% vs 最强基线 SkillOpt 63.3%)，且平均演化 token 少 24%。

> **TL;DR:** SkillFocus restructures agent-skill evolution: instead of revising a shared skill purely from execution traces, it first induces a frozen capability space (a task-capability matrix) from task specifications alone, then each round selects the capability with the largest unresolved task mass and uses that same capability to choose both the revision target and the matched execution evidence. On four heterogeneous benchmarks (SearchQA, SpreadsheetBench, LiveMathematicianBench, IFBench) with DeepSeek-V4-Flash as target model, it achieves the best held-out accuracy on all four — 70.7% average vs 63.3% for the strongest iterative baseline SkillOpt (per-benchmark margins 1.4–15.0 pts, e.g. 77.1 vs 62.1 on SpreadsheetBench) — while spending 24% fewer evolution tokens on average. Controlled studies show task-spec-derived capabilities beat task-semantic grouping by 8.2–18.8 pts and execution-derived grouping by 6.6–12.9 pts, randomizing task-capability assignments costs up to 20.2 pts, and evidence matched to the selected capability raises candidate training gain from +4.97 to +9.37 under prioritized focus.

## 核心贡献

- **问题重构：** 把共享技能演化分解为两层——"任务反复要求什么"(演化前从任务规格归纳、随技能演化保持冻结的能力空间 C,Q)与"当前技能表现如何"(每轮变化的执行结果)，使修订不再被当前技能的行为绑死；现有方法(Trace2Skill、SkillOpt、GEPA 等)的修订证据只来自轨迹/回滚，无法揭示任务间共享的程序化要求。
- **能力引导的修订机制：** 每轮用当前训练结果计算各能力得分，选出"未解决任务质量" m_d = π_d(1−q̂_d) 最大的能力 c*；证据包只从要求 c* 的训练任务中组装(失败按原因分层 + 成功对照 + 相关技能内容 + 该能力的历史修订)；同一能力既决定"改什么"又决定"读哪些证据"。
- **确定性、可审计的验证门控：** 一次性贪心构建的选择集(按覆盖率>多样性>改进机会排序)做整技能筛选，再对训练集重评估，仅当两处配对变化均为正(Δ_sel>0 ∧ Δ_tr>0)才接受候选；≤5 轮、每轮 1 个候选。
- ** unusually 扎实的受控研究：** 三种能力来源对照(任务语义/执行派生/随机化保持度数序列的任务-能力指派)、15 个冻结历史状态上的 2×2 focus-evidence 交叉实验、随机选择集对照与端到端消融，把收益归因到"能力分解本身"与"能力-证据配对"两个部件。
- **结果：** 四个基准全部 SOTA，平均超出最强对手 5.7 分，同时平均演化 token 减少 24%(SearchQA 上 −54.3%)。

## Key Contributions

- **Reformulation of skill evolution:** separate "what tasks repeatedly require" from "how the current skill behaves" by inducing a capability space (C, Q) — a binary task-capability matrix in the style of cognitive diagnosis models — from task specifications (instruction, input structure, environment contract) BEFORE any execution, and freezing it for the whole run; existing trace-based methods (Trace2Skill, SkillOpt, GEPA, SkillRollout) cannot expose requirements shared across superficially different tasks.
- **Capability-guided revision:** each round, capability scores computed from current training outcomes select the capability with the largest "unresolved task mass" m_d = π_d(1−q̂_d) among eligible candidates; an evidence bundle is assembled only from training tasks assigned to that capability, and the same capability determines both what to revise and which evidence the editor sees; edits that cite out-of-bundle evidence, duplicate existing rules, or copy task-specific entities are deterministically discarded.
- **Conservative whole-skill validation:** a fixed selection set (greedy: coverage weighted by support share > diversity over task family/input structure/environment contract > improvement opportunity) screens every candidate, followed by training-set re-evaluation; a candidate is retained only if both paired changes are positive (Δ_sel > 0 ∧ Δ_tr > 0), because a whole-skill edit can move tasks outside its target capability.
- **Controlled attribution studies:** (a) capability-source control comparing task-spec-derived vs task-semantic vs execution-derived groupings vs degree-preserving randomized assignments under a fixed downstream pipeline; (b) a 2×2 focus-evidence crossover rerun over 15 frozen historical revision states; (c) selection-set randomization and end-to-end ablations.
- **Results:** best held-out accuracy on all four benchmarks (avg 70.7% vs 63.3% SkillOpt), with 24% fewer evolution tokens on average than SkillOpt.

## Methodology

**Problem formulation.** One shared skill S_t (textual procedural guidance) is evolved over a fixed task pool D; each task i executed with S_t yields a normalized score γ_i ∈ [0,1]. Starting from an initial skill S_0, round t proposes a candidate S'_t; validation decides acceptance (Eq. 1). Horizon T_max = 5 rounds, one screened candidate per round. The split is |D_tr| : |D_sel| : |D_test| = 2 : 1 : 7, with the test set never touched during evolution.

**Capability induction (once, pre-execution, then frozen).** Capability induction reads only task records — instruction, input structure, environment contract — never execution outcomes or the current skill. Three independent proposal calls with frozen perspectives (Requirement-Centric, Intervention-Centric, Boundary-Centric) extract required behaviors; a consensus call merges registries, an assignment call maps each task to its required capabilities (binary matrix Q, cf. cognitive diagnosis models), and support filtering (min support n_min = 3) removes low-support capabilities. Induced K ranges 9–22 across the four benchmarks. The selection set D_sel is built greedily once: coverage first (support share π_d weighting unresolved mass), then diversity over static task features, then improvement opportunity (share of initial executions failing for diagnosable task-logic reasons, with environment faults excluded by deterministic checks); a one-fifth reserve of stably-solved tasks keeps regressions visible; every capability keeps ≥1 supporting task in D_tr so revision evidence stays available.

**Capability-guided revision (per round).** (1) Compute capability scores q̂_d = mean of γ_i over training tasks with Q_{i,d}=1. (2) Restrict to eligible capabilities U_t = {d : diagnosable failure in D_tr ∧ supporting task in D_sel} and select c_t = argmax π_d(1−q̂_d). (3) Assemble the evidence bundle only from training tasks requiring c_t: failure examples stratified by observed reason, a successful contrast, related current-skill content, and earlier edits of the same capability. (4) Three diagnosis Explorers (frozen perspectives: missing guidance / ineffective guidance / behavior organization) propose hypotheses; an integrator selects one; three edit Explorers propose edit concepts; an integrator merges them into a single candidate edit (add/replace/remove) targeting the complete skill. (5) Whole-skill validation: paired change Δ_X(S',S) = mean over X ∈ {D_sel, D_tr} of Y_i(S')−Y_i(S); ACCEPT iff Δ_sel > 0 ∧ Δ_tr > 0. An accepted candidate's training executions become the next round's outcome record; rejected candidates and revisions are logged to history without changing the skill.

**Experimental setup.** Four heterogeneous benchmarks, each evolving its own skill: SearchQA (600 tasks, Jeopardy-style closed-domain QA), SpreadsheetBench (120, real-workbook manipulation with target-cell verification), LiveMathematicianBench (53, research-level multiple-choice math, code execution disabled), IFBench (89, verifiable instruction constraints). Baselines share evaluator, task pool, held-out split, initial skill (where applicable), and models: No Skill, One-shot Skill, Trace2Skill, GEPA (160 metric calls, Pareto selection), SkillOpt (official implementation). DeepSeek-V4-Flash is the fixed target model (temperature 0); GPT-5.4 is the optimizer-side model for all skill-optimization methods. Metrics: held-out test accuracy and cumulative evolution tokens (inference tokens until the final skill is fixed; final test inference excluded).

## Results & Highlights

- **Best accuracy on all four benchmarks (Table 1):** SkillFocus averages 70.7% vs SkillOpt 63.3%, GEPA 61.2%, Trace2Skill 55.1%, One-shot Skill 54.0%, No Skill 42.1%. Per-benchmark: SearchQA 80.1 (SkillOpt 76.1, +4.0), SpreadsheetBench 77.1 (SkillOpt 62.1, +15.0 — the widest margin), LiveMath 43.6 (SkillOpt 41.1, +2.5), IFBench 82.0 (best competing result is the *non-iterative* One-shot Skill at 80.6; SkillOpt only 73.9). Margins over the strongest competing result per benchmark span 1.4–15.0 pts (avg 5.7); on IFBench SkillFocus is the only iterative method that exceeds One-shot Skill.
- **24% fewer evolution tokens than SkillOpt on average (Table 16):** SearchQA 20.66M vs 45.21M (−54.3%), SpreadsheetBench 29.06M vs 40.55M (−28.3%), LiveMath 6.36M vs 8.14M (−21.9%); but IFBench is +7.5% (3.45M vs 3.21M), so the average is carried mostly by SearchQA. SkillFocus reaches its gains with fewer accepted revisions (Figure 3) — one accepted revision can move many tasks because a capability spans tasks.
- **Where capabilities come from matters a lot (Table 5):** with the downstream pipeline fixed, task-spec-derived capabilities beat task-semantic grouping by 18.8/8.2/17.8 pts on SearchQA/SSB/LiveMath (e.g., 80.1 vs 61.3 on SearchQA) and execution-derived grouping by 6.6/11.0/12.9 pts (e.g., LiveMath 43.6 vs 30.7). Randomizing task-capability assignments while preserving task/capability degree sequences drops final accuracy by 11.1/17.5/20.2 pts (LiveMath 43.6 → 23.4) — the gain comes from *which task carries which requirement*, not matrix statistics.
- **Focus-evidence crossover over 15 frozen historical states (Table 2):** Top-priority capability + matched evidence achieves 40.0% acceptance, Δ_sel +4.10, Δ_tr +9.37, vs Top+Mismatched +4.97 Δ_tr, Random+Matched +5.33, Random+Mismatched +4.39 (20% acceptance) — matched evidence adds 4.4 pts of candidate training gain under prioritized focus, and per-benchmark matched evidence raises gain by 7.08/5.62/0.52 pts (SearchQA/SSB/LiveMath).
- **Ablations (Table 8):** removing capability-matched evidence lowers test accuracy from 80.1→71.4 (SearchQA), 77.1→58.6 (SSB), 43.6→20.8 (LiveMath); removing capability prioritization gives 68.7/38.3/20.8. Replacing the constructed selection set with a uniform random sample of the same size costs 5.1/3.9/17.2 pts of final test accuracy (SearchQA/SSB/LiveMath).
- **Capability-space structure (Tables 3-4, Fig. 4):** ≥86% of tasks require multiple capabilities on SearchQA/SSB/LiveMath (vs 36% on IFBench); mean capabilities per task 1.29–5.11; median pairwise support-set Jaccard ≤ 0.17. Three independent proposal calls recover near-identical assignments (ARI 0.883–0.973, NMI 0.953–0.989), so the decomposition is reproducible without ground truth.

The group's profile fits the topic: Zhou's lab works on evolutionary optimization and LLM-driven search (co-author Bingdong Li appears in the cited GEPA work on reflective prompt evolution), and the referencing of very recent skill-evolution literature (Trace2Skill, SkillGrad, SkillOpt, SkillOpt-Lite, ReasonSignal, SkillForge, 2026) is precise and first-hand. ## Critical Assessment

- **Single configuration, no variance reporting.** All formal runs use one optimizer-target pair (GPT-5.4 optimizer, DeepSeek-V4-Flash target) with temperature-0 target execution; no seeds, error bars, or significance tests appear anywhere. This matters because several margins are small relative to plausible noise: the LiveMath pool has only 53 tasks, so its held-out test set is roughly 37 tasks, and the headline "best on all four" rests on a +2.5-pt margin over SkillOpt there (43.6 vs 41.1); a single flipped task moves that number by ~2.7 pts.
- **The token-efficiency claim is confounded with protocol.** Optimization budgets "follow each method's native protocol" (GEPA: 160 metric calls; SkillOpt: official setting; SkillFocus: capped at 5 rounds, 1 candidate/round). The 24% average saving is therefore measured post-hoc under unequal budgets rather than at matched cost, and it is not uniform: on IFBench SkillFocus actually spends *more* tokens than SkillOpt (3.45M vs 3.21M, +7.5%), so the average is carried largely by SearchQA's −54.3%.
- **IFBench is an unexplained weak regime.** Every iterative baseline (SkillOpt 73.9, GEPA 73.4, Trace2Skill 76.3) fails to beat a single non-iterative One-shot Skill (80.6), and the induced capability space is thin there (1.29 capabilities per task; the paper's own Table 4 lists requirements like "end every sentence with an emoji" supported by 3 tasks). The authors report this but offer no analysis of why iterative evolution stalls on constraint-following tasks, and SkillFocus's +1.4-pt margin over One-shot Skill is the least robust headline number.
- **No ground truth for capabilities.** The stability evidence (ARI 0.883–0.973 across the three proposal perspectives) shows the pipeline is self-consistent, not that the decomposition is correct — and the three perspectives share one canonical input schema, so correlated errors are possible. Capability quality is validated only downstream via the source-control ablation, which is well designed but indirect.
- **Genuine strengths worth crediting:** the degree-preserving randomized-assignment control is unusually careful — it isolates the assignment itself from matrix statistics (accuracy still drops 11.1–20.2 pts) — and the 2×2 focus-evidence crossover over frozen historical states is a properly controlled mechanism study rather than the usual end-to-end ablation only.

## Strengths

- Clear, well-motivated problem framing: execution evidence shows *what the current skill did*, not *which requirements recur across tasks*; freezing the requirement structure makes rounds comparable and revisions composable.
- Deterministic, auditable machinery: frozen (C, Q), a fixed selection set, evidence-boundary enforcement (edits citing out-of-bundle evidence are discarded), and a two-sided paired acceptance gate (Δ_sel > 0 ∧ Δ_tr > 0) that guards against edits repairing one capability while degrading others.
- Attribution is done properly: three capability-source alternatives, a randomized-assignment control preserving degree sequences, a focus-evidence crossover on held-fixed states, a selection-set randomization control, and end-to-end ablations all point the same direction.
- Simultaneous accuracy and efficiency: best accuracy on all four benchmarks with 24% fewer average evolution tokens than the strongest iterative baseline.
- Exceptional documentation for reproducibility-by-description: pseudocode for all four stages, full prompt interfaces with XML schemas (Appendix D), a complete token ledger, and a fairness table of shared vs method-specific conditions.

## Limitations

- Assumes recurring procedural requirements are identifiable from task specifications alone before execution, and that every requirement is addressable by editing the skill text; environment faults are excluded by construction, and capabilities are never validated against any external ground truth.
- Evaluated under a single optimizer-target configuration (GPT-5.4 / DeepSeek-V4-Flash) with no variance reporting; small task pools (LiveMath 53, IFBench 89) make the smallest claimed margins fragile.
- The token saving is protocol-relative (each baseline at its native budget) and reverses on IFBench (+7.5% vs SkillOpt); the 5-round horizon with one candidate per round is fixed and never sensitivity-analyzed.
- The conservative double-positive acceptance gate plus the 5-round cap means some capabilities may remain unresolved by design; the paper does not measure how often the horizon binds.
- Cross-domain and longer-horizon evolution are explicitly left as future work (stated in the Limitations section).

## Relevance

这篇论文正中你的第一优先级方向 Self-Evolving Agents：它研究 LLM Agent 可复用技能的自动迭代演化，并用相当规范的受控实验回答"演化循环里改什么、读什么证据、如何验收"这一自改进系统的核心机制问题，其中的冻结能力空间与配对验收门控对任何长时程自演化 Agent 系统的可靠性设计都有直接借鉴价值。

## Questions for Further Exploration

- Would the capability space survive a second target model (e.g., a weaker executor where failure modes differ), or is the induced (C, Q) partially an artifact of DeepSeek-V4-Flash's failure distribution even though induction never sees executions?
- Why do all iterative methods lose to a One-shot Skill on IFBench? Is the bottleneck the edit vocabulary (add/replace/remove on a single text) or the acceptance gate rejecting candidates that trade constraint violations for verbosity?
- How does performance scale with horizon — does unresolved task mass keep decreasing after round 5, and would allowing multiple candidates per round change the token-accuracy frontier?
- Can capability induction and revision be closed into a single loop (re-inducing capabilities when the pool changes) without losing the comparability benefits of a frozen (C, Q)?
- The focus-evidence crossover measures candidate quality on the training set; does the 4.4-pt candidate gain translate into final held-out accuracy uniformly, or only on benchmarks with many multi-capability tasks?
