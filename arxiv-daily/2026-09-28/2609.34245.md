> **一句话总结：** 针对 LLM 智能体执行付款等特权结构化动作时被提示注入篡改证据的问题，本文提出一个"认证器"：每条证据源被隔离读取，每个动作关键字段必须按其证据结构对应的规则（跨"腐蚀-区分"证据类的拜占庭多数票 N>2k、确定性对账、可信锚点）独立过关，且独立性按依赖集最小命中集计数而非副本数计算——在 5 个模型 × 80 集的真实 agent 回环中，朴素 agent 在 72%–100% 的注入攻击上执行了欺诈付款，而认证器在全部 5 个模型上 0% 不安全执行、错误弃权最多 3.8%，同时以 96–100% 的正确率保留了对能力门控（0% 效用）和策略监控器（最高 18% 不安全、新收款方 0% 效用）基线的效用优势。

> **TL;DR:** LLM agents that take irreversible structured actions (e.g., paying invoices) assemble each field from multi-source evidence that indirect prompt injection can corrupt. The paper formalizes when such an action is *safely certifiable*: each source is read in isolation, every field must clear the rule its evidence supports, and redundancy is counted over **corruption-distinct control domains** (a minimum hitting set), so laundered copies cannot fake a quorum. Safe execution is characterized exactly as singleton feasibility (Theorem 1); multi-source value fields use unique-threshold admission, safe iff N > 2k. On a real OpenRouter agent loop (80 episodes × 5 models, k=1 corruption of N=5 sources), the naive agent executes the fraudulent payment on 72% (GPT-5.5) to 100% (Gemini 3.1 Pro, Haiku 4.5) of attacks while the certifier admits **0% unsafe actions on all five models** with ≤3.8% false abstention; against faithful CaMeL/FIDES-style capability gating (0% unsafe but 0% utility) and a PCAS-style policy monitor (up to 18% unsafe, 0% utility on novel payees), the certifier is simultaneously 0% unsafe and 96–100% correct, paying 100% of legitimate novel payees. A prevalence study (OpenSanctions 70,966 entities; 450 npm + 300 PyPI packages) shows corruption-distinct corroboration is scarce: the apparent 16% three-witness npm packages all collapse to two GitHub-rooted domains.

## 核心贡献

- **安全性可认证的刻画（定理 1）**：在有界腐蚀预算 k 下，一个结构化动作可被安全执行当且仅当 k-可行动作集是单例（singleton feasibility）；满足该界的认证器是"最大活的"（maximally live）——其弃权集合内在于问题本身，任何认证器都无法在放弃更少弃权的情况下保持安全。由此推出拜占庭安全半径与精确值半径（精确值容忍需 N > 2k，半径 ⌊(N−1)/2⌋）。
- **腐蚀-区分计数（minimum hitting set）**：冗余不是按证据条目数、而是按"最少腐蚀多少个控制域才能抹掉该事实"来度量——republic/relabel 的副本继承其上游的腐蚀根，因此单域沦陷只能算一票。这堵住了"洗副本制造假法定人数"的攻击；命题 3 证明按域名（而非 provenance 根）认证投票可将 k 个被腐蚀域的贡献严格限制在 ≤k 票。
- **字段结构感知的证书规则组合**：多源恒等字段用"唯一阈值准入"（N−k 个类支持且唯一），互补字段（发票金额 vs 采购单）用确定性对账界定上限，单源字段（收款账户）用可信锚点把关；四项 TCB 假设（认证、锚点、事务连接键、可靠抽取）被显式声明。
- **机制级消融**：移除事务连接键、可信锚点或强制源规则，各自恰好打开一个攻击家族（金额拼接 / 改名匹配 / 单源决策），完整认证器一个不漏；副本洗白只在去掉域绑定计数时成功，Sybil 注入只在去掉认证时成功——与命题 3 的经验对应。
- **前提条件在真实数据中的稀缺性测量**：OpenSanctions 70,966 个被列名实体中仅约 25%（控制域级别）有两方以上独立列名、约四分之三为单域；450 个 npm 包中表观三见证结构（registry + SLSA provenance + 仓库回指）占 16%，但每个都塌缩为两个 GitHub 根的腐蚀-区分域——这是对"多源佐证假设在现实中多不成立"的首次系统测量。
- **真实 agent 回环端到端评估**：注入攻击在 5 个当前模型中的 4 个上 100% 得手，朴素 agent 在 72%–100% 的攻击上执行欺诈付款；认证器在所有模型上 0% 不安全、且同时保持高效用，而能力门控与策略监控器基线各有所失。

## Key Contributions

- **An exact characterization of certifiability (Theorem 1):** under a corruption budget k over control domains, a structured action is safely executable iff the k-feasible action set is a singleton; the certifier meeting this bound is *maximally live* — its abstentions are intrinsic to the problem, not design timidity. Byzantine safety and exact-value radii (exact value requires N > 2k, radius ⌊(N−1)/2⌋) follow as specializations.
- **Corruption-distinct counting (minimum hitting set):** redundancy is measured by the fewest control domains an attacker must corrupt to erase a fact, not by attestation or copy counts — republished copies inherit their upstream's corruption root, so a single-domain compromise casts one vote. Proposition 3 shows authenticating votes to their originating domain caps k corrupted domains at ≤k votes regardless of copied records.
- **Structure-aware per-field certificate rules:** unique-threshold admission for multi-source identity fields (≥ N−k classes, unique value); deterministic reconciliation for complementary fields (invoiced amount bounded by the order amount); a trusted anchor for single-sourced fields (payee account). Four trusted-computing-base assumptions (authentication, anchors, join key, sound extraction) are stated explicitly rather than hidden.
- **Mechanism-level ablation:** removing the transaction join key, the onboarding anchor, or the mandatory-source rule opens exactly one attack family each (amount splicing / name-matched swap / single-source decision) while the full certifier admits none; copy laundering succeeds only without domain-bound counting and Sybil additions only without authentication — the empirical face of Proposition 3.
- **First systematic measurement of the precondition on real data:** on OpenSanctions' 70,966 designated entities only ~25% (control-domain level) carry ≥2 mapped issuing domains (~75% single-domain); on 450 npm packages the apparent three-witness structure (registry + SLSA provenance + repo back-reference, 16%) collapses in every case to two corruption-distinct domains rooted at GitHub — same collapse for 32% of 300 PyPI packages.
- **End-to-end evaluation in a real agent loop:** injection redirects 4 of 5 current models on 100% of attacked episodes and the naive agent executes the fraudulent payment on 72–100% of them; the certifier is 0% unsafe on all five models while remaining high-utility, where capability gating and policy-monitor baselines each fail on one side.

## Methodology

**Threat model.** An agent proposes a privileged structured action a = (a₁,…,a_J) of action-critical fields (payee identity, payee amount, payee account). Each field is supported by attestations (v, c): a value v drawn from an evidence class c with its own corruption mode (buyer document, seller document, bank verification, designation authority). The adversary selects a set C ⊆ U of control domains with |C| ≤ k and may set values arbitrarily, emit laundered copies attributed to roots it controls, and rewrites after each refusal (adaptive); it cannot forge attestations outside C (authentication), and untrusted evidence may only fill values within a trusted obligation skeleton Γ fixed from user intent (operation, transaction key, mandatory relations, amount cap) — closing selection attacks where the certificate would be "sound for the wrong object."

**Certifier rules.** Distinct field structures get distinct rules: *agreement-or-escalate* (all N corruption-distinct classes agree, conservative, (N−1)-safe-with-abstention), *unique-threshold admission* (a value clearing support ≥ N−k uniquely; safe iff N > 2k — the Byzantine bound applied per-predicate over a dependency-aware electorate), *reconciliation* (deterministic constraint bounding one field by another, e.g., invoice ≤ order + tolerance), and the *anchor gate* (single-sourced account field executes only on an onboarding-allowlist name match). Two robustness notions are kept apart: k-exact-value-tolerance (certified value invariant under any budget corruption) versus k-safety-with-abstention (correct value or refusal, never wrong) — the latter is reachable with far less redundancy, which matters because real corroboration is scarce.

**Theory.** Definition of corruption-distinct count m as the minimum hitting set of attestation dependency sets (Def. 1–2); budgeted influence b_k for shared-class electorates; Theorem 1 proves safe execution equals singleton feasibility via an indistinguishability argument; Propositions 1–3 establish the conservative rule, the exactly-live threshold rule, and vote-identity bounding.

**Validation pipeline.** (1) A model-free harness ablates each mechanism against an adversary controlling one evidence class. (2) Prevalence measurement: OpenSanctions (70,966 entities, mapped-domain hitting sets as an upper-bound proxy), plus 450 npm and 300 PyPI packages with actual SLSA/PEP-740 provenance and repository back-references. (3) Live-model study: five models (Claude Opus 4.8, GPT-5.5, Gemini 3.1 Pro, Gemini 3.5 Flash, Haiku 4.5) via OpenRouter, 80 episodes each (54 attacked, k=1 of N=5 sources; 26 clean), payment action, certifier protocol vs naive agent. (4) Head-to-head vs faithful CaMeL/FIDES-style capability gating and PCAS-style policy monitor (44 attacked episodes, k=3), plus a white-box model-free adaptive attacker over 2,000 worlds.

## Results & Highlights

- **Live agent loop (Table 1):** the injected instruction is followed on 100% of the 54 attacked episodes by GPT-5.5, Gemini 3.1 Pro, Gemini 3.5 Flash, and Claude Haiku 4.5 (Opus 4.8: 0%), and the naive agent executes the fraudulent payment on 72% (GPT-5.5), 98% (Gemini 3.5 Flash), and 100% (Gemini 3.1 Pro, Haiku 4.5) of attacks — while the certifier records **0% unsafe executions on all five models**, with honest-world false abstention of 3.8% at worst (Opus 4.8) and 0–12% under the agreement rule vs only 0–6% under the unique-threshold rule (N=5 > 2k).
- **Baseline head-to-head (k=3, 44 attacked episodes per model):** CaMeL/FIDES-style capability gating is safe but executes nothing (0% unsafe, 0% utility — blanket refusal is structural when decisive fields derive from untrusted evidence); the PCAS-style policy monitor stays unsafe on up to **18%** of in-policy attacks and pays **0%** of novel (non-pre-registered) payees; the certifier alone is **0% unsafe with 96–100% correct overall and 100% novel-payee payment**. On the injection-vulnerable Haiku 4.5 (Figure 3): naive 100% unsafe / 28% utility, policy monitor 18% / 29%, certifier 0% / 98%.
- **Adaptive attacker:** a model-free white-box attacker that rewrites one source's fields, launders copies, and revises against each refusal never forces an unsafe execution across **2,000 worlds**, while breaking both baselines in every world (in the harness, action-gating admits every attack family except one and provenance-only checking every family except a currency swap; the certifier admits none).
- **Prevalence is scarce (Section 4):** among 70,966 OpenSanctions entities, ~15% show ≥3 raw-dataset sources but only ~25% show ≥2 mapped control domains and ~three-quarters are single-domain — an upper-bound proxy. On 450 npm packages, the apparent three-witness structure (16%) collapses to two corruption-distinct domains in **every** case (GitHub Actions provenance and the repo back-reference share the GitHub root); ~90% of well-attested packages have exactly two witnesses, none reach three; on 300 PyPI packages the apparent 32% three-witness rate likewise reduces to two GitHub-rooted domains.
- **Provenance attack caught where the baseline fails:** under a registry compromise substituting a malicious source, the certifier certifies no malicious source on **0 of 450** corroborated packages while a registry-trusting baseline accepts the substitution every time.
- **Ablation (Section 3, App. B Table 3):** each removed mechanism opens exactly one attack family — join key → amount splicing, onboarding allowlist → name-matched swap, mandatory-source rule → single-source decision — and the full certifier opens none; copy laundering succeeds only without domain-bound counting and Sybil inflation only without authentication.

## Critical Assessment

**Novelty is genuine but adjacent.** The core move — counting corruption-distinct control domains through a minimum hitting set rather than raw attestations — is a real advance over RobustRAG-style passage counting, which duplicated copies can inflate. Generalizing Byzantine quorum voting to an electorate that must be *inferred from provenance* (rather than given as a fixed peer set) is the paper's most original idea. However, the per-field rules themselves (threshold voting, deterministic reconciliation, allowlist anchoring) are standard tools; the contribution is their disciplined composition and the characterization theorem, not new field mechanisms.

**The utility win over capability gating is partly by construction.** The authors themselves note AgentDoom-style benchmarks give one source per fact, so they deliberately evaluate on a multi-source domain where any corroboration-needing gate must abstain throughout. That is a fair domain for their thesis, but the dramatic 98% vs 0% utility gap should be read as "capability gating is inapplicable here," not as a refutation of gating on single-source benchmarks.

**Part of the safety story is an allowlist.** The account field — the one that actually moves money — is secured by a trusted anchor (onboarding allowlist + bank name match), i.e., the same allowlist device the PCAS baseline is criticized for, just applied to a different field. The certifier's 100% novel-payee utility claim therefore leans on how novel payees get onboarded, a process the paper describes only briefly.

**The adaptive guarantee is not end-to-end.** The 2,000-world adaptive attacker is model-free: it attacks the aggregation mechanism, not a live LLM crafting injections against the full stack (certifier + extractor + protocol). The authors flag this as limitation one, but it means the strongest security sentence in the abstract ("recovers the correct value where corroboration permits") is proven for the harness, not for a deployed agent. The sound-extraction assumption is a second soft spot — the canonicalizer is itself a potential shared control domain, and Appendix B only samples extractor faults rather than proving independence.

**The prevalence numbers are upper-bound proxies that undercut the headline mechanism.** Exact dependency sets are unavailable; mapped control domains fold co-funded/coordinated lists into one authority, but shared upstream data can still inflate the count (the 15% → 25% raw-vs-domain gap on sanctions is acknowledged as proxy sensitivity). With ~75% of sanctions entities single-domain and zero npm packages reaching three corruption-distinct witnesses, the exact-value regime (N > 2k with k ≥ 1 needs N ≥ 3, k=2 needs N ≥ 5) is essentially unreachable outside trivial budgets — in real deployments this system would mostly abstain or fall back to anchors, which the paper admits but does not quantify operationally.

**Evaluation scale is modest.** One action schema (payment), 80 episodes per model, 54 attacks at k=1, and a 44-attack k=3 comparison — enough to instantiate the propositions, not to characterize failure modes at larger k or with correlated honest-source errors. The baselines are faithful reimplementations of defense *logic*, explicitly "not the full engineering of a deployed system," which is honest but leaves room for the comparison to flatter the certifier.

## Strengths

- Rare theory-experiment coupling: Theorem 1 and Propositions 1–3 are each instantiated by a specific experiment, and the ablation shows every mechanism is load-bearing (exactly one attack family per removal).
- The corruption-distinct hitting-set count is a crisp, reusable concept that fixes a real flaw (copy laundering) in prior counting-based certified defenses, with Proposition 3 giving the matching authentication requirement.
- The prevalence study is independently valuable: the demonstration that SLSA/PEP-740 provenance and repository back-references share the GitHub root — collapsing "three witnesses" to two domains on all 450 npm and 300 PyPI packages — is a concrete, checkable finding for anyone building supply-chain trust systems.
- Explicit, honest scoping: four limitations stated up front in the conclusion, the TCB enumerated, and the two robustness notions (exact-value vs safe-with-abstention) carefully separated, avoiding a common source of overclaiming.
- Simultaneous safety-and-utility evaluation against *faithful* reimplementations of competing defenses, rather than strawman refusal-only comparisons.
- Code and data released; five current frontier models evaluated rather than one.

## Limitations

- No fully adaptive *live-model* attacker: the adaptive study is a model-free harness; an LLM-driven attacker optimizing injections against the whole certifier stack remains untested.
- All corroboration counts are upper-bound proxies (mapped control domains, not recovered hitting sets); true corruption-distinct coverage on sanctions data may be lower than the reported ~25%.
- Heavy trusted computing base: unforgeable origin authentication, trusted anchors, a trusted transaction join key, and a sound (honest) extractor — each is a deployment prerequisite, and the anchor-gated account field means one of three action fields is protected by an allowlist, not by the certificate.
- Corroboration is scarce in practice (~75% single-domain sanctions entities; zero npm packages with three witnesses), so the exact-value regime is rarely reachable and availability will often depend on abstention or anchors.
- Modest scale and scope: one action type (payment), 80 episodes per model, 54/44 attacked episodes, and baselines that reproduce defense logic rather than full deployed systems.
- The sanctions and supply-chain prevalence settings are measured but not run through the live agent loop — the end-to-end claim is validated only on the synthetic payment domain.

## Relevance

该文与你关注的长时自主智能体系统的"可靠性与可信性"直接相关：它把"agent 不可逆动作的安全执行"从提示词级防御提升为带定理保证的认证机制，并给出了独立计数须按腐蚀域而非证据副本计算的通用原则；虽属模型侧对抗安全而非 SDC/硬件故障主线，但其"证据独立性 + 最小命中集计数"思路对任何依赖多源观测判断系统状态的可靠性监控设计都有借鉴价值。

## Questions for Further Exploration

- How does the certifier behave when a live LLM attacker adaptively crafts injections against the full stack (extractor included), rather than the model-free harness adversary?
- Can exact dependency sets be recovered in practice (e.g., aligning provenance to funding/program authority for sanctions lists) to replace the upper-bound mapped-domain proxies?
- Given ~75% single-domain coverage on sanctions data, what is the operational availability cost, and can anchors and corruption radii be combined adaptively per-field instead of statically?
- Does the framework extend to free-text or semi-structured fields where deterministic canonicalization f is not available and the extractor itself is a contested control domain?
- How would the certificate compose with single-source benchmarks like AgentDoom, where corroboration is structurally unavailable — is there a middle regime between gating and multi-source admission?
