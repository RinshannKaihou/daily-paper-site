01Method

Recursive self-improvement (RSI) of the agent harness — retrieval, tools, control flow, verification — organized as competing branches over evolving development objectives, then routed at deployment.

Shared proposer Claude Opus 4.6 one candidate harness per branch per iteration, scored by execution feedback
→
Branch 1 dev subset X₁ + guidance SKILL₁ head H₁ = best mean reward on X₁
Branch 2 dev subset X₂ + guidance SKILL₂ head H₂ = best mean reward on X₂
→
Router = action model GEPA-optimized instruction head-exclusive dev cases + both experts' source code
→
Deploy 1 head per new input no test outcomes, ever
B = 2 branches N = 20 iterations q = 5 frontier size Δ = 2 ownership margin subset update C_p = 1 guidance update C_s = 5

Prior work evolves against one fixed dev set. Meta-Harness (Lee et al. 2026) lets an agentic proposer rewrite harness code against a static development set and static instructions — one trajectory, prone to local optima.

Two branches, two objectives. Here B=2 branches each hold their own dev subset, candidate population, and proposal guidance. Per branch-frontier (top q=5), every dev case gets a coverage vote each cycle.

Cases migrate to specialists. A case every frontier solves is deleted; a case one branch out-solves by Δ=2 is re-owned by the leader and stripped from rivals — specialization is enforced by a deterministic rule, not a diversity prompt.

Guidance co-evolves. Every 5 iterations the same proposer rewrites each branch's SKILL.md from its own execution record: what worked, what keeps failing, what remains unsolved.

Routing closes the loop. After search, one head per branch survives. A router — the action model itself, tuned with GEPA — picks one head per new input from development-derived evidence only.

Frontier membership is recomputed at every update, so a case can change owners even when implementations don't — rankings track current strength, not history. When a subset update and a guidance update fall due together, the subset update goes first.

03Strengths / Limitations

Verbatim-faithful distillation of the summary's critical assessment.

  • Wins everywhere tested: beats Meta-Harness in all 4 settings — 2 action models, 3 task families (math, terminal, repo-level SWE).
  • Mechanism, not vibes: deterministic coverage-vote + ownership-margin rule; the ablation shows pruning unlocks guidance adaptation (54.0 / 50.0 alone → 62.0 together).
  • Test-clean routing: the router never touches test data, yet beats the test-selected-best harness (62.0 vs 58.0 on Math-Gemini).
  • Honest bookkeeping: token appendix, admitted routing losses, named case studies — verification_once_gate 50.0% TB2, test_aware_edit 66.4% SWE.
  • Compute confound: 1.5–2.2× tokens, no compute-matched baseline; the "neither" ablation (51.0) already outspends Meta-Harness.
  • Statistical fragility: single run per setting, no error bars; +1.5 (Math-Sonnet) and +2.4 (SWE) are 3 problems / 6 tasks — plausible noise.
  • B=2 never ablated: no evidence on scaling branch count; q=5 and Δ=2 fixed.
  • Router ceiling: recovers only 75% of exclusive successes and loses to the stronger head in 2 of 4 settings — the "mixture" story rests mainly on Math-Gemini.
  • Frontier-model dependence: Opus 4.6 proposer, action-model routers; no code release stated; ~4B tokens per TB2 run is out of reach for most labs.

04Questions for further exploration

  1. Do the gains survive a compute-matched comparison — a 40-iteration Meta-Harness, or two independent Meta-Harness searches combined by the same router?
  2. How does performance scale with B > 2 branches — and should the ownership margin Δ and frontier size q grow with B?
  3. Why are dev-subset pruning and guidance adaptation so super-additive (54.0 / 50.0 alone → 62.0)? Is guidance-alone's 50.0 < 51.0 real, or noise?
  4. Can the router move past 75% exclusive-success recovery — abstention, or executing both heads on ambiguous inputs — to close the 5-pt union gap?
  5. Do the discovered mechanisms (gap_directed_construction, verification_once_gate, test_aware_edit) transfer across action models, or are they benchmark-specific artifacts?
