Methodology

MemHarm scores every candidate edit by Counterfactual Memory Regret J = 𝔼[L_edit − L_clean]: the expected paired loss increase when the same episode runs with an edited versus a clean memory write. Both branches start from an identical initial state and every non-target channel is stripped, so the target read path is the only difference — a memory-only paired intervention.

Typed semantic factors (type, anchor, rel, value) are extracted from clean writes by deterministic parsers; an edit replaces at most K = 3 factors with grounded, plausible values. The candidate class — including a zero-edit arm — is frozen before any outcome feedback. An LCB/UCB allocator driven by empirical-Bernstein confidence sequences (η = δ = 0.05) then adaptively samples incumbents and challengers, eliminating arms whose UCB falls below the best LCB minus η; a resolved selection earns a class-conditional (η, δ) near-optimality certificate.

Budget: ≤ 800 paired rollouts per instance, five primary seeds, and attacks evaluated only on held-out tasks with disjoint construction / optimization / test splits see 02 · Results →

Strengths & Limitations

+Strengths

  1. CMR is a clean potential-outcomes quantity that provably retains what ASR discards (sign/magnitude decomposition).
  2. Rigor rare in attack papers: class frozen pre-feedback, memory-only paired interventions, anytime-valid confidence sequences.
  3. Theory earns its place — a testable directional prediction is confirmed, and the attribution-ambiguity proposition is validated by factor removal.
  4. Fair-support, contract-matched baselines answer the objective-mismatch objection head-on.
  5. Dual-use handled seriously: isolated environments, withheld exploit code, released validators, paid blinded human audits.

−Limitations

  1. Certification is class-conditional — nothing bounds severity over edits outside the frozen candidate class.
  2. Construction demands an offline oracle (resettable copies, paired feedback, ≤ 800 rollouts) that is unrealistic against production agents.
  3. The empirical edge rests on 2 benchmarks × 2 backbones; the severity claim effectively rests on two adapted baselines, and single-cell CMR intervals overlap.
  4. CMR measures benchmark task loss — real-dollar or policy-violation harm is never directly quantified.
  5. Backbone-dependent success (Llama-3.1-70B ASR 42.1% on AgentDojo); transfer weakens on schema-constrained profile and graph stores.
04

Open Questions

  1. Defensive flip: can CMR-style severity evaluation run as a red-team stress test inside an agent's own memory lifecycle — write-time validation, anomaly scoring on semantic-factor edits?
  2. Distribution shift: how does frozen-class certification degrade when deployment users present task mixes and memory contents unseen at construction time?
  3. Detection signal: could the consequence/realization decomposition flag high-κ, poorly-realized edits as “incoherent memory”, isolating the truly dangerous high-κ high-realization tail?
  4. Self-evolving loops: does severity-guided poisoning compound in agents that rewrite their own instructions and skills, rather than acting once?
  5. Cost: the 800-rollout budget is large — can amortized or surrogate-model CMR prediction preserve most of the certified severity at a fraction of the cost?
