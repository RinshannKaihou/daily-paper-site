> **一句话总结：** APEX 把间接提示注入（IPI）防御从"识别攻击模式"转移到"执行边界"这一必经之路：在执行前把用户任务编译成一份授权契约（DAG），再用 WRAP（证据门控预防：反向追溯契约 + 正向解析运行时回执，仅放行契约可证明授权的效果）和 PLANT（欺骗式暴露：在无授权路径可经过的信道上布设探针，被探针污染的参数即证明注入已被采纳）双机制在效果提交前拦截攻击，在 6 个基准、13 个基线下于 5 个基准取得 0% ASR、最后一个仅 0.56%（如 ASB-OPI 上 ASR 0.00% vs 无防御 59.80%、最强基线 CaMel 4.80%），且在三类自适应攻击下仍保持 0% ASR。

> **TL;DR:** APEX defends LLM agents against indirect prompt injection by checking the *execution boundary* — the single point where internal state becomes an external action — instead of trying to recognize attack patterns across Tools, MCP servers, and Skills. It compiles the user task into a frozen authorization contract before untrusted content arrives, then enforces it with two mechanisms: WRAP (admits an effect only if its authorization can be reconstructed from the contract plus runtime receipts) and PLANT (plants adversary-carried probes on channels no endorsed path can traverse, so a proposal bearing one exposes injected adoption before the effect commits). On ASB-OPI it reaches 0.00% attack success rate vs 59.80% undefended and 4.80% for the strongest baseline CaMel (while raising attack utility from 40.03% to 85.05%); on AgentDojo it gets 0.00% ASR vs 0.48% for AgentShield, the best of 13 baselines. Under adaptive attacks (AutoDojo, MCP-TIP, SkillElect) baselines degrade by up to +45 ASR points (MELON 41.90%→86.25%) while APEX holds 0% with 78.46–90.00% attack utility. ## 核心贡献

- **威胁重构（execution boundary 分解）**：不再枚举不断膨胀的注入载体（Tool 输出、MCP 内容、Skill 指令及其组合），而是把边界风险分解为两个可检验条件——**未授权效果**（A_unfr：提议的效果未被任务授权）与**未溯源信息使用**（A_unfr→A_auth：效果本身授权、却采纳了任务从未背书的注入信息），并证明这构成一个统一、跨载体且组合安全的检查点。
- **授权契约（Task Compilation）**：执行任何不可信内容之前，把可信任务 + 能力注册表编译为一个固定的 DAG 契约 C_q（Acquire / Derive / Conditional 三类取值子句 + Effect 子句），显式声明哪些外部效果被授权、其参数如何合法产生；契约一次编译、任务无关、可跨任务复用，无需手工编写任务安全策略或端到端数据流打标。
- **WRAP（证据门控预防）**：对 A_unfr，从边界提议反向追溯契约、从能力调用回执正向解析每个必需参数（Eq.1-2），只有当授权在效果提交前可完全重构时才放行；拒绝发生在提交之前，而非事后检测。
- **PLANT（欺骗式暴露）**：对 A_unfr→A_auth（契约无法预知哪些运行时值被背书），分析契约中 Acquire→Effect 路径上的可信表面，在"任何被授权执行都不可能携带效果的信道"上布设观察探针 / 依赖探针 / 基底探针（探针携带攻击者控制的信息）；任何带探针的提议即为"无被授权路径送达"的见证，配合 Safe Continuation（修复 / 重规划 / 中止）在效果提交前挽回。
- **统一覆盖 + 全面实证**：一次注册即统一覆盖 Tool、MCP、Skill 及其嵌套组合；在 6 个基准（AgentDojo、ASB-OPI、MCPTox、MSB、SkillInject、SCR-Bench）× 13 个基线上取得 5 个 0% ASR + 1 个 0.56%，并在三类自适应攻击与多 defender 骨干模型下保持 0% ASR。

## Key Contributions

- **Reframes IPI defense around the execution boundary**: instead of covering an expanding space of attack carriers (Tool outputs, MCP metadata/responses, Skill instructions, and their compositions), boundary risk is decomposed into *unauthorized effects* (A_unfr) and *authorized effects that adopt undersourced information* (A_unfr→A_auth), giving one carrier-agnostic enforcement point where all harm must materialize.
- **Authorization contracts compiled before untrusted execution**: a one-time, task-independent capability registry (Tools, MCP methods, Skill interfaces: I/O schemas, effect boundaries, agent-visible surfaces) plus a task compilation step produce a frozen DAG contract encoding which effects are authorized and how their arguments are legitimately derived — replacing per-attack detectors, handwritten task policies, and end-to-end taint labeling.
- **Two complementary primitives**: WRAP (evidence-gated prevention) resolves each proposed effect against the contract and runtime receipts and rejects before commitment; PLANT (deception-based exposure) instruments channels that no endorsed execution can carry, so adversarial adoption surfaces as a probe witness before the effect commits; Safe Continuation (repair/replan/abort) preserves utility after rejection without expanding authority.
- **Uniform, composition-safe coverage**: the same mediation logic applies to every registered capability unit and nested calls, with no capability-specific security logic; evaluated on 6 benchmarks across all three capability-unit types against 13 baselines plus 3 defense-aware adaptive attacks, achieving 0% ASR on five benchmarks and 0.56% on the sixth while retaining high benign/attack utility.

## Methodology

**Threat model & decomposition.** APEX considers an LLM agent executing a trusted user task through heterogeneous capability units (Tools, MCP servers, Skills). An injection becomes externally consequential only when the agent acts on the environment or releases output — the *execution boundary*. Endorsement-based integrity (Askarov & Myers 2011) decomposes boundary risk into: (1) *A_unfr* — an effect not authorized by the task (E_auth ∪ A_unfr ⊔ U_q); (2) *A_unfr→A_auth* — an authorized effect drawing on information the task never endorsed (e.g., a value both counted and harmful). Bypassing effects or state changes outside registered interfaces are explicitly out of scope, as is the residual gap A_auth where the task authorizes an action but the attacker controls content *within* it.

**Trusted capability registration.** Each unit is registered once from trusted environment metadata: M(u) = (Σ_in, Σ_out, χ_obs, χ_eff, S_u) — input/output schemas, whether it returns agent-visible observations or produces external effects, and its untrusted-carrying surfaces. Registration is task-independent and reusable across tasks; for open-ended MCP catalogs a conservative read-only default is applied.

**Task compilation.** The trusted task q and registry M are compiled into an authorization contract C_q — a DAG whose nodes are clauses and edges are endorsed dependencies. Three value-production clause types (Acquire: output x_c of a capability call; Derive: applying operator op_c to upstream values; Conditional: fixing x_c by op_c) plus one Effect type (⟨u_c, {⟨k, J_k⟩}_k⟩: an authorized action on unit u_c with argument positions each delegating to a capability output, runtime evidence, or the user's argument). C_q is validated against M and frozen before any untrusted content exists; values stay open until runtime.

**Evidence-gated prevention (WRAP), for A_unfr.** Every capability call produces a receipt recording the invoked unit, arguments, and return value. For a boundary proposal e = (a_e, {⟨k, v_k⟩}_k), WRAP finds candidate Effect clauses matching a_e, traces their justification J_k backward to required value clauses, resolves them forward from upstream receipts (Eq. 1: Acquire binds to receipt returns; Derive re-applies the operator; Conditional fixes uniquely), and rejects e if any resolution permits no argument (Eq. 2). Resolution is agent-driven within script-enforced bounds: scripts enumerate admissible values and recompute them exactly, while the agent only judges *which* admissible candidate fits a declared relation — it cannot introduce a value outside the contract's sources. Authorization-soundness: every execution in A_unfr produces a proposal WRAP rejects, so every adversarial execution surviving the check lies in A_unfr→A_auth.

**Deception-based exposure (PLANT), for A_unfr→A_auth.** The contract names *channels* along which endorsed runtime values may reach an effect but not which values. PLANT analyzes Acquire→Effect paths and instruments the registered interfaces on them with three probe planes: observation probes O (inject a synthetic untrusted span into agent-visible content), dependency probes D (record a decision premise out-of-band rather than gate on it), and substrate probes S (insert artifacts into registered resources). Each probe carries a token minted at runtime, unique to episode and carrier, that no endorsed execution can carry to an effect; a probe replaces the value rather than sitting beside it, so carrying it forward carries the token. A proposal e is committed only when neither ¬Req_e ⊢ ¬Hit (WRAP passes) nor a probe hit (Eq. 3) fires; on a hit, the exposure witness E_e lets Safe Continuation strip the implicated evidence.

**Safe continuation.** Rejection (or an incomplete contract) need not abort the task: a sanitized continuation state keeps established bindings W_e, invalidates implicated evidence E_e, and replicates completed work; Repair rebuilds the proposal, Replan repairs when repair is unavailable, Abort terminates on recurring conflict. Continuation never modifies C_q, and every repaired or replanned proposal re-enters the same boundary check.

**Experimental setup.** OpenAI SDK with native tool calling; MCPs exposed through the tool catalog, Skills through callable helpers. Task agent and defender: DeepSeek-V4-Flash; LLM judge: GPT-5.4 (all baselines share the same backbone; additional defender backbones in Appendix C). Benchmarks (two per capability type): Tools — AgentDojo (fixed environment injection) and ASB-OPI (Observation Prompt Injection subset); MCP — MCPTox (tool poisoning) and MSB (planning/tool-invocation/response handling); Skills — SkillInject (malicious instructions in individual skills) and SCR-Bench (attacks the *composition* of otherwise-legitimate Skills). 13 baselines: Spotlighting, Tool Filter, TaskShield, MELON, CaMel, DRIFT, Progent, AgentShield (Tools); MCPGuard, StackOne Defender, PipeLock (+ClawGuard) (MCP); Progent, TaskShield, ClawGuard, Dynamic Guardian (Skills). Metrics follow the L1 public protocol: Benign Utility (BU), Attack Utility (AU), Attack Success Rate (ASR). Adaptive attacks: AutoDojo (Tools), MCP-TIP (MCP), SkillElect (Skills).

## Results & Highlights

- **ASB-OPI (Tool, OPI subset): 0.00% ASR with the highest utility.** APEX reaches BU 90.20% / AU 85.05% / ASR 0.00%, versus 59.80% ASR undefended; the strongest prior is CaMel at 4.80% ASR but with AU collapsed to 40.03% (BU 80.18%); existing tool defenses span 9.80%–51.13% ASR (Progent 9.20%, PipeLock 11.83%, Spotlighting 51.13%) — APEX removes the entire remaining gap rather than shaving points.
- **AgentDojo (Tool): 0.00% ASR at state-of-the-art utility.** APEX: BU 86.60% / AU 80.29% / ASR 0.00% vs AgentShield (best prior security) at 0.48% ASR (BU 83.51%, AU 79.81%) and Progent at 0.00% ASR but 4.3/8.6 points lower utility (BU 76.29%, AU 71.74%); undefended ASR is 17.01%.
- **MCP and Skill benchmarks: 0%–0.56% across the board.** On MCPTox APEX attains ASR 0.00% (BU 66.67%, AU 75.52%) vs ClawGuard 3.08%, MCPGuard 5.00%, StackOne 5.00%, undefended 36.29%; on MSB APEX is 0.56% — the only nonzero result across all six benchmarks; on SkillInject APEX reaches 0.56% ASR (BU 81.11%, AU 78.89%) vs Dynamic Guardian 11.11% and undefended 28.89%; on SCR-Bench (composition attacks) APEX holds 0% ASR.
- **Robustness under defense-aware adaptive attacks: baselines collapse, APEX holds.** Adaptation raises undefended ASR by 21.08–45.25 points and baseline ASR by 2.27–27.27 points — e.g., CaMel on ASB-OPI jumps 4.80%→34.00%, MELON 41.90%→86.25%, ClawGuard on the MCPTox subset 15.60%→39.56%, Dynamic Guardian on SkillInject 6.82%→34.09% — while APEX maintains 0.00% ASR under both original and adaptive attacks on all three benchmarks, with AU 78.46%–90.00% under adaptation.
- **Ablation (Table 3) confirms the two primitives are complementary.** Removing WRAP on ASB-OPI raises ASR from 0.00% to 57.60% (nearly the undefended 59.80%) while removing PLANT leaves ASR at 0.00 — consistent with ASB-OPI attacks targeting unauthorized tool calls that WRAP directly rejects. On MCPTox, removing PLANT raises ASR to 6.45% and removing WRAP to 4.13%. Removing Safe Continuation provides no security benefit but slashes AU on ASB-OPI (85.05%→62.30%) and MCPTox (75.52%→48.15%).
- **Overhead is competitive.** Measured as utility-adjusted security (AU−ASR) vs average LLM tokens/call, APEX attains 85.1 AU−ASR on ASB-OPI against 14.9 for TaskShield and 10.9 for Spotlighting while using fewer tokens than TaskShield; on SkillInject it spends more inference than most baselines but buys far better utility + attack resistance. Overhead stems mainly from PLANT probe construction and Safe Continuation replans.

The writing shows deep fluency with the agent-security literature: the related-work section accurately taxonomizes content-based, task-alignment, policy-based, provenance-based, and deception-based defenses (Spotlighting, TaskShield, MELON, CaMel, DRIFT, Progent, AgentShield, MCPGuard, PipeLock, ClawGuard, etc.), and the formal framing builds explicitly on endorsement-based integrity from programming languages (Askarov & Myers 2011) — an unusual and rigorous import for an LLM-security paper. ## Critical Assessment

- **Novelty is real but the framing does heavy lifting.** The ingredients — pre-declared authorization (policy-based), provenance over runtime values, and honeypot-style deception — all exist; APEX's contribution is the *decomposition into exactly two boundary conditions* and the pairing of forward contract-tracing (WRAP) with deliberately unendorsable probe channels (PLANT). That synthesis is genuinely new and well-motivated, but papers like FAVA (evidence-backed permission graphs), AgentArmor, and AuthGraph are close neighbors the paper distinguishes mostly on "authorization fixed before untrusted content arrives."
- **The 0% ASR headline hides a benign-utility tax on AgentDojo.** Spotlighting posts BU 94.85% on AgentDojo versus APEX's 86.60% — an 8-point gap on clean tasks. APEX wins the security-utility frontier overall (and its ASB-OPI BU of 90.20% is excellent), but "0% ASR while preserving high task utility" should be read as high, not best, benign utility on the most standard tool benchmark. The Safe Continuation ablation (AU 85.05→62.30 on ASB-OPI without it) shows how much machinery is needed just to recover utility after rejections.
- **Contract compilation quality is assumed, not measured.** The whole guarantee rests on the LLM-compiled contract faithfully encoding the user's intent, yet the paper reports no metric for compilation fidelity (e.g., % of tasks where the contract over/under-restricts). The discussion concedes that ambiguous or deliberately delegated tasks ("execute the TODOs in this email") cannot be fully expressed beforehand — precisely the open-ended tasks real agents face — and defers them to future "controlled reauthorization."
- **Threat-model exclusions are significant for real deployments.** Effects or state changes that bypass registered interfaces are out of scope, and the residual class A_auth (task authorizes the action; attacker controls content *within* it, e.g., which email body to send within an authorized reply) is explicitly outside the guarantee — that is a common real-world IPI goal. PLANT also *abstains* when no behavior-preserving probe placement exists, falling back to WRAP alone, so undersourced-use coverage is placement-dependent.
- **Adaptive evaluation is strong but not probe-aware.** The three adaptive attacks (AutoDojo, MCP-TIP, SkillElect) optimize injected payloads against detectors and tool-selection feedback; none is specifically designed to detect and strip PLANT's probe tokens (the paper argues probe replacement makes stripping hard, and that stripping still must survive WRAP — plausible, but an attacker who recognizes the decoy channel could route around instrumented surfaces, which is exactly the caveat the authors borrow from the honeypot literature without an experiment closing it).
- **Reproducibility is good.** Code is public, benchmarks are standard with official evaluation releases, and results are reported across defender backbones (Appendix C). Single task-agent backbone (DeepSeek-V4-Flash) in the main tables means we don't see how a weaker, more injection-susceptible agent changes the boundary dynamics.
- **Overall:** this is a strong, unusually rigorous systems-security paper — the formal soundness argument (every A_unfr execution is rejected before commitment) is an actual proof-shaped claim, not vibes. The main overclaim risk is readers equating "0% ASR on these six benchmarks" with "IPI solved"; the boundary framing restricts scope precisely where many real attacks live.

## Strengths

- A carrier-agnostic invariant: one enforcement point (the boundary) covers Tools, MCP, Skills, and their compositions — including SCR-Bench-style attacks on *combinations of benign* capabilities that single-carrier defenses structurally miss.
- Rejection *before* commitment rather than detection-after-the-fact; WRAP's soundness argument (unauthorized effects cannot survive the check) is formalized, not just empirically suggested.
- PLANT is an elegant inversion of honeypots: probes are derived from the contract's own endorsed-path analysis, so a hit is logically conclusive evidence of undersourced adoption, and probe tokens are adversary-controlled yet unforgeable-by-endorsed-paths.
- Honest, unusually thorough discussion section: contract-fidelity dependence, delegated-authority limits, probe-coverage assumptions, and long-horizon compilation challenges are all named explicitly.
- Evaluation breadth is best-in-class for this subfield: 6 benchmarks, 13 baselines sharing one backbone, 3 defense-aware adaptive attacks, ablations of both primitives plus Safe Continuation, overhead analysis, and multi-backbone checks.

## Limitations

- Guarantee is conditional on contract fidelity: ambiguous or underspecified user requests yield over-restrictive contracts that block legitimate work; no compilation-quality metric is reported.
- Tasks that intentionally delegate authority to external content ("execute the TODOs in this email") cannot be expressed in a fixed pre-execution contract; the proposed fix (controlled reauthorization) is future work.
- A_auth residue: when the task authorizes an effect but the attacker controls content within it (task-specific content constraints), APEX does not help; real-world IPI often targets exactly this.
- Effects or state changes outside registered interfaces (bypass channels) are out of scope; PLANT abstains where probe placement would alter benign behavior, leaving undersourced-use coverage incomplete in those cases.
- Utility cost on benign tasks (AgentDojo BU 86.60% vs Spotlighting 94.85%) and inference overhead from PLANT probe construction and Safe Continuation replans; SkillInject costs more inference than most baselines.
- Long-horizon tasks: the mechanism theoretically extends, but compiling complex, conditional long-horizon objectives into faithful contracts is an open problem, and no long-horizon safety benchmark yet exists to test it.
- One benign-utility number (86.60% on AgentDojo) and 0.56% residual ASR on MSB suggest edge cases remain even within the defended scope; the paper does not dissect the MSB failure.

## Relevance

这篇论文与你关注的"长时程自主 Agent 系统的可靠性与可信性"高度相关：它给出了一个不依赖攻击模式、可形式化证明的 Agent 运行时授权防线（Tool/MCP/Skill 统一覆盖），正是自演化 Agent 在开放环境中安全执行外部操作的基础设施级问题。其"执行前编译授权契约 + 边界强制"的思路也可迁移到自动化科研循环中对不可信文献/网页内容的防御。

## Questions for Further Exploration

- How often does LLM-based contract compilation over- or under-restrict real tasks, and can compilation fidelity be measured (e.g., agreement between the compiled contract and human-stated intent) rather than assumed?
- Can PLANT's probe channels be made robust against a probe-aware adversary that detects the synthetic token and routes around instrumented surfaces — is there an adaptive attack that jointly evades WRAP and PLANT?
- What would "controlled reauthorization" look like for tasks that legitimately delegate decisions to external content, without letting the injection grant itself authority?
- Does the boundary check remain sound when the task agent itself is a weaker model more prone to following injections, or when capability units are dynamically registered at runtime (open-ended MCP catalogs)?
- Can the framework extend to long-horizon, conditional objectives (multi-day research loops) where the contract must be compiled from far less explicit instructions — and what benchmark would test that?
- The 0.56% residual ASR on MSB: what exactly slips through, and does it indicate a gap in WRAP's script-enforced resolution or in PLANT's placement?
