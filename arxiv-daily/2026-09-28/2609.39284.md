> **一句话总结：** MemoraX AI 与港中深提出 EngramBench——首个以"能力重叠但解法不重叠"公理构建的技能演化基准（30 个学习任务 + 13 个跨域迁移任务，多轮模拟用户驱动数小时开发周期），其 48 条严格审计轨迹的消融实验表明：静态技能库对 GPT-5.5 Medium 的正确率提升有限（微平均 CCPF 46.63%→51.25%，+4.62 pp，且 4 个任务中 1 个负增长），但能把纯开发时间从 189.0 分钟压到 84.5 分钟（−55.3%）、非缓存输入 token 削减 80.91%——程序化记忆是"执行罗盘"而非"最后一英里"的解药。

> **TL;DR:** The paper identifies an identifiability problem in skill-evolution evaluation: existing benchmarks (e.g., SWE-bench repurposed with same-repo histories) confound genuine capability abstraction with rote solution leakage. EngramBench enforces "capability overlap without solution overlap" via 30 learning tasks in 6 business domains and 13 unseen, multi-hour transfer tasks driven by an LLM-simulated user, scored by a fine-grained Confirmed-Case Pass Fraction (CCPF) under a frozen-skill-bank two-phase protocol. In a 48-trajectory ablation (4 transfer tasks × 4 configurations × 3 trials, GPT-5.5 Medium as coder), a 20-skill static bank distilled from historical trajectories lifts micro-average CCPF only from 46.63% (No Skills baseline) to 51.25% (+4.62 pp; gains concentrate in EscrowGuard +14.81 pp while CapacityLease regresses −1.45 pp) — but slashes coding time 55.3% (189.0 → 84.5 min/run) and non-cached input tokens 80.91%. Ablations show history volume is not skill value: a bank distilled from 69.66% less history even scores highest (52.60% CCPF), while removing core engineering skills (Coreless-3) causes token-heavy thrashing (+131.76% reasoning tokens) and worse-than-baseline time (≥190.87 min).

## 核心贡献

- **提出并形式化"混淆问题"（identifiability problem）**：现有技能演化评测中，下游得分 = f(蒸馏能力 × 历史证据是否在场)——高分可能只是模型零样本直觉或从历史轨迹中照抄相似 AST/本地 API（solution leakage），无法归因于真正的能力抽象。
- **确立设计公理"capability overlap without solution overlap"**：学习任务与迁移任务必须共享高层工程能力（事务幂等、故障恢复、状态版本控制等 6 类跨域能力），但业务逻辑、API、代码库零重叠，从物理上杜绝照抄答案。
- **构建 EngramBench**：30 个覆盖 6 个业务领域（预订物流、数据协作、交易账本、IoT 配置、安全审计、基础设施通信）的学习任务（归档 583 个交互轮次的反馈丰富轨迹）+ 13 个未见迁移任务；迁移任务是 25–30 轮交互、数小时的全栈开发（TypeScript/Node 22/React/PostgreSQL），由 DeepSeek V4 Pro 驱动的 LLM 模拟用户追问进度、拒绝不完整交付。
- **设计严格评测协议**：两阶段解耦（技能库 SHA-256 冻结 → 隔离迁移执行，迁移期禁止更新技能库）、隐藏评测器在开发期完全卸载；提出比二元 Pass@1 更细粒度的 **CCPF**（Confirmed-Case Pass Fraction，按适用隐藏测试用例比例计分）；隐藏评测含 64 并发同幂等键请求、SIGKILL worker 后恢复验证、破坏依赖的"fake-green"反幻觉检查，覆盖并发/恢复/UI 一致性/运维兼容 5 个维度。
- **48 条审计轨迹的实证发现**："最后一英里"精确代码实现仍受限于基座模型推理能力，静态技能库无法越过；但技能库是"执行罗盘"——通过避免灾难性架构错误，大幅压缩上下文膨胀与试错式代码翻修（编码时间 −55.3%）。行为审计显示 S-Full-20 的补丁调用比零样本少 29.8% 且单补丁行数从 47–64 行收敛为集中式编辑；去掉核心技能后 agent 退化为"重 token 榨取"范式（推理 token +131.76%、26 次上下文压缩）。

## Key Contributions

- Formalizes the **identifiability (confusion) problem**: downstream skill-evolution scores structurally confound distillation capability with the mere presence of similar solutions in the provided history, making current in-domain benchmarks (e.g., SWE-bench histories from the same repository such as Django/SymPy) uninterpretable.
- Proposes the strict design axiom **"capability overlap without solution overlap"** and instantiates it as EngramBench: 30 feedback-rich learning tasks across 6 business domains (583 archived interactive execution turns) and 13 unseen cross-domain transfer tasks sharing zero business logic or APIs with the learning set.
- Introduces a **two-phase decoupled protocol** — skill banks frozen with SHA-256 manifests, skill evolution disabled during transfer, hidden evaluators unmounted during development — plus the **CCPF metric** (fraction of applicable hidden test cases passed, micro-averaged) and adversarial multi-dimensional hidden verification (64 concurrent idempotent requests, SIGKILL-and-replace worker recovery, dependency-breaking fake-green checks).
- Empirical characterization of procedural memory on 48 audited GPT-5.5 Medium trajectories: static skill banks do **not** bypass the "last mile" of exact code implementation (correctness +4.62 pp micro-average CCPF, non-monotonic across tasks), but act as an **execution compass**, cutting coding time 55.3%, non-cached input tokens 80.91%, and patch-tool invocations 29.8% by steering agents away from catastrophic trial-and-error.
- Ablation insights: distilling from 69.66% less history (S-Ablated-20) yields the *highest* CCPF (52.60%) — evidence quality, not history volume, matters — while surgically removing core engineering skills (Coreless-3) collapses the benefit and pushes coding time above the no-memory baseline (≥190.87 min).

## Methodology

**Benchmark construction.** Rather than scraping GitHub commits, the authors hand-construct requirement-driven sandbox projects: each task has a definitive README contract, a frozen execution plan, and a scenario-driven scaffolding defining request/response contracts and public interface checks. The 30 learning tasks span 6 domains (Resource Booking & Logistics; Data, Files & Collaboration; Transaction, Account & Subscription; Device/IoT & Config Rollout; Security, Rules & Audit; Infrastructure & Communication), deliberately recurring six cross-cutting capabilities (transactional idempotency, concurrency control, state transitions, failure recovery, version management, end-to-end validation). The learning phase archives 583 interactive turns including initial mistakes, test failures, and repair loops, so harnesses have evidence to abstract from. Each of the 13 transfer tasks provides a clean V2 API scaffold (average 23.46 files, 622 non-empty LOC, 268 public operations) but demands full-stack behavior: DB migrations, background dispatchers, OpenAPI integrations, and browser-observable UI. An Appendix A table maps representative public requirements of every transfer task to concrete recorded learning episodes (failure-repair loops, fault-injection validations), audited at the mechanism level.

**Execution environment.** Isolated OCI/Docker sandboxes provision shell, file I/O, TypeScript/npm builds, PostgreSQL, and Chromium for E2E testing. A Simulated User Agent (DeepSeek V4 Pro, thinking/high mode) drives 25–30 interactive development turns over a multi-hour cycle, checking progress against the frozen plan and rejecting incomplete deliverables — a paradigm following tau-bench. Delivery is two-stage: iterate against a public interface checker, then freeze the commit (secure code digest) and dispatch to a separate hidden-evaluation container.

**Evaluation protocol.** The CCPF for task t is the fraction of applicable, non-excluded hidden test cases passed (P_t/|C_t|); self-authored agent tests are ignored and unresolved states count in the denominator, penalizing incompleteness — reported as micro-average. Hidden evaluators stress five dimensions (Contracts & Lifecycle; Data Idempotency & Concurrency; Worker Recovery & Durability; Cross-Layer UI Consistency; Operational Compatibility) with adversarial mechanisms: 64 concurrent requests with identical idempotency keys asserting exactly one business event; SIGKILL of a paused background worker with a replacement verifying non-duplicated resumption; and fake-green checks that dynamically break dependencies (swap the DB, unreachability, masking the Chromium path) to fail vacuous agent-written tests. Anti-cheating: Phase 1 distills trajectories into a frozen Skill Bank (SKILL.md, SHA-256 manifest); Phase 2 physically restricts the agent from mounting learning-phase workspaces, histories, or codebases, and forbids updating the bank from test feedback.

**Controlled ablation study.** Four representative transfer tasks (CapacityLease, EscrowGuard, MeterSettle, FlagFoundry) × four configurations × 3 trials = 48 strictly audited trajectories; the coding agent is GPT-5.5 Medium throughout, with the initial architectural plan fixed to isolate execution capability. Configurations: (1) **No Skills** (zero-shot); (2) **S-Full-20** — two-stage distillation (368 raw skill packages → global compression by DeepSeek V4 Pro at temperature 0) retaining exactly 20 cross-domain principles; (3) **S-Ablated-20** — same pipeline on a deliberately weakened history (69.66% less raw text), isolating evidence deprivation; (4) **Coreless-3** — S-Full-20 surgically stripped to 3 basic interface skills (exploratory capability ablation). Metrics: micro-average CCPF (deltas in absolute percentage points), total tokens (session-deduplicated caching), pure development wall-clock time (excluding user/evaluation phases), and behavioral dynamics (tool counts, patch invocations, reasoning tokens, context compactions, relative to baseline).

## Results & Highlights

- **Correctness: modest, uneven gains.** Micro-average CCPF across 12 runs per configuration: S-Full-20 51.25% vs No Skills 46.63% (**+4.62 pp**). Per-task: EscrowGuard 18.52%→33.33% (**+14.81 pp**), MeterSettle 76.42%→80.49% (+4.07 pp), FlagFoundry 46.34%→47.15% (+0.81 pp), but CapacityLease **regresses** 47.83%→46.38% (−1.45 pp) — supporting the "last mile" thesis that exact code implementation remains bottlenecked by the base model.
- **Efficiency: transformative.** Per run, S-Full-20 vs No Skills: coding time **189.00 → 84.46 min (−55.3%**, >104 min saved) with dev turns nearly unchanged (27.00→26.50, −1.85%, so the saving is not truncation); non-cached input tokens **3,211,135 → 612,849 (−80.91%)**; total input+output tokens 50.03M → 40.19M (−19.66%). Reduced external wait accounts for only ~6 minutes — the gain comes from avoiding catastrophic architectural rework.
- **History volume is not skill value.** S-Ablated-20, distilled from 69.66% less historical text, achieves the **highest CCPF (52.60%)** at 91.74 min (+8.6% time vs S-Full-20); Coreless-3 drops to 48.36% CCPF with ≥190.87 min coding time — worse than the 189.00-min no-memory baseline.
- **Behavioral audit (12-run aggregates).** S-Full-20 invokes the patch tool **29.8% less** than baseline (865→607 invocations) while added patch lines shrink only 3.66% (40,393→38,914), i.e., consolidated 47–64-line edits replace fragmented "small edit → check → small edit" loops. Coreless-3 shows token-heavy thrashing: tool invocations **+68.97%** vs S-Full-20 (4,850→8,195), reasoning tokens **+131.76%** (302,016→699,961), 14.76M chars of error-log return text, and 26 context compactions (vs 11 for S-Full-20, 21 for No Skills).
- **Scale of the benchmark.** 30 learning tasks / 6 domains with 583 archived interactive turns; 13 transfer tasks averaging 23.46 starter files, 622 LOC, and 268 public operations; a single run can consume up to **66 million tokens**, motivating the 4-task deep-audit scope.

## Authors & Credibility

The team is from **MemoraX AI** with Zhixuan Tan from The Chinese University of Hong Kong, Shenzhen. Corresponding author Jianye Hao (jianye.hao@fju.edu.cn) is a well-known researcher in LLM agents and reinforcement learning; MemoraX AI appears to be a company building agent-memory products (the "Engram" branding and citations of in-house work such as SkillHone, a continual skill-evolution harness, suggest the benchmark is infrastructure for their own product line). Equal contribution by the first two authors. The technical report is unusually candid: the Coreless-3 ablation is explicitly labeled exploratory (designed after inspecting the earlier comparison), the S-Full-20 bank selection is admitted to be qualitative rather than score-driven, and Appendix A repeatedly notes that mechanism-level evidence links are "not proof that entire transfer tasks were solved in the learning phase." Code is released at github.com/Virgil-Tan/EngramBench. The mix of industrial product motivation and explicit protocol discipline lends credibility, though the benchmark is effectively self-published with vendor-in-house tasks and no external validation yet.

## Critical Assessment

- **The demonstrated evaluation is much narrower than the benchmark's ambition.** Despite 13 transfer tasks, the deep ablation covers only 4 (CapacityLease, EscrowGuard, MeterSettle, FlagFoundry) with **3 trials per configuration (n=3)** and no significance testing; per-task deltas swing from +14.81 pp to −1.45 pp, so the +4.62 pp headline micro-average could easily be within noise. The other 9 transfer tasks have no published harness results.
- **Single-vendor, single-model stack.** One coding model (GPT-5.5 Medium), one user simulator and one distillation compressor (both DeepSeek V4 Pro), and a skill bank whose 20 entries were selected by qualitative coverage rather than scores. Generalization to open-weights models is deferred to future work by the authors' own admission. The paper also does not evaluate any third-party skill-evolution framework (Voyager, Expel, SkillHone, etc.) — only variants of the authors' own two-stage distillation pipeline — so "a reliable standard to measure true skill evolution across harnesses" is asserted, not yet demonstrated.
- **Exploratory ablation asymmetry.** Coreless-3 was designed *after* inspecting the S-Full/S-Ablated comparison, and its coding time is reported as "≥190.87 min" — the ≥ suggests capped or incomplete runs, weakening the "worse than baseline" claim's precision.
- **External validity of bespoke tasks.** All tasks are hand-constructed TypeScript/React/PostgreSQL sandboxes mirroring "business constraints" the authors designed; unlike SWE-bench's organic real-world issues, there is no evidence the difficulty distribution matches production engineering, and the simulated user (another LLM) is a source of unquantified variance in multi-hour runs.
- **Genuine strengths in honesty and anti-gaming.** The fake-green dependency-breaking checks, SHA-256-frozen banks, unmounted hidden evaluators, and the appendix's explicit caveats (e.g., QueueForge's fault-injection evidence "were not observed production incidents") are exemplary protocol hygiene — notably better than most agent-benchmark papers. The S-Ablated-20 > S-Full-20 result is reported rather than buried, which supports the paper's own "quality over volume" narrative.
- **The headline framing slightly overreaches.** "Reducing overall coding time by over 55%" is real, but it is efficiency on a self-defined benchmark with a simulated-user clock, not the correctness gain the skill-evolution field primarily optimizes; the correctness story (+4.62 pp, one of four tasks negative) is the more sobering result and is honestly reported as such.

## Strengths

- Crisp problem formulation: the Downstream Score = f(Distillation Capability × Evidence Presence) decomposition names exactly why in-domain skill-evolution results are uninterpretable, and the "capability overlap without solution overlap" axiom is an actionable design rule other benchmark builders can adopt.
- Rigorous, well-instrumented anti-cheating infrastructure: frozen SHA-256 skill manifests, physically isolated transfer containers, unmounted hidden evaluators, and adversarial fake-green checks that break dependencies to catch vacuous agent tests.
- CCPF is a strictly more informative metric than binary Pass@1 for long-horizon tasks, and the hidden-evaluation dimensions (concurrency, SIGKILL recovery, UI consistency, operational compatibility) probe real engineering competence rather than API surface behavior.
- The efficiency analysis is unusually deep: cached vs non-cached token decomposition, pure development time excluding off-cycle phases, and a behavioral audit that ties the Coreless-3 collapse to a measurable thrashing signature (+131.76% reasoning tokens, 26 compactions).
- Honest reporting throughout: non-monotonic per-task results, an ablation that beats the full system, exploratory status of Coreless-3, and appendix caveats distinguishing mechanism-level evidence from whole-task proof.

## Limitations

- Deep ablation restricted to 4 of 13 transfer tasks, 3 trials each, 48 total trajectories — statistically thin for a paper whose central claims are about measurement reliability; no variance or significance analysis is reported.
- Single coding model (GPT-5.5 Medium), single simulated-user/compressor model (DeepSeek V4 Pro); no open-weights results, no cross-model skill transfer.
- No third-party harness baselines: the benchmark's stated purpose (comparing skill-distillation frameworks) is exercised only on the authors' own pipeline variants.
- Frozen-skill-bank protocol deliberately excludes dynamic retrieval, Active RAG, and online adaptation — realistic for isolation but meaning the results say nothing about the memory mechanisms most current frameworks actually use.
- Cost of adoption is high: up to 66M tokens and manual trajectory auditing per run, which is precisely why the audit could not cover the full transfer set.
- Tasks are bespoke sandboxes (not organic repositories), and LLM-simulated users introduce unquantified interaction variance; the "≥190.87 min" reporting for Coreless-3 hints at run caps.

## Relevance

这篇论文正中你的第一优先方向 Self-Evolving Agents：它给出了技能演化/程序化记忆评测中的可识别性问题（解法泄漏 vs 真正能力抽象）的清晰形式化，并提供了带防作弊协议的基准与 48 条审计轨迹的实证结论（技能库是执行罗盘而非正确率解药），对评估长时自主 agent 系统的可靠性与可信度很有参考价值。如果你要做自演化 agent 的 benchmark 或 reward 设计，这篇的"capability overlap without solution overlap"公理和 fake-green 反幻觉检查是可直接借鉴的设计。

## Questions for Further Exploration

- Do the +4.62 pp micro-average CCPF gain and the 55.3% time reduction hold on the other 9 transfer tasks, and with more than 3 trials — or is the current delta within run-to-run variance?
- How do existing third-party harnesses (Voyager, Expel, SkillHone, AgentCI-style continual-learning systems) actually score under EngramBench's frozen-bank protocol, given none were evaluated here?
- Why does CapacityLease regress with the skill bank while EscrowGuard gains +14.81 pp — is there a task-feature taxonomy (e.g., surface-form overlap of principles vs idiosyncratic constraints) that predicts when static skills help or mislead?
- The skill bank was compressed by DeepSeek V4 Pro while the coder was GPT-5.5 Medium: how sensitive is the 20-skill bank to the compressor model, and would self-distillation (same model family) change the S-Ablated-20 > S-Full-20 ordering?
- The protocol freezes the bank and forbids online updates during transfer — how much of the 55.3% time saving survives if the harness is allowed to retrieve and adapt skills mid-task (the Active RAG setting explicitly excluded)?
- Can the simulated-user variance be quantified (e.g., by replaying scripted user sessions) to separate interaction noise from genuine skill-transfer effects in multi-hour runs?
