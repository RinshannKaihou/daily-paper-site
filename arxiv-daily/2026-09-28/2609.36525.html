Why this matters

Floating-point non-associativity, mixed precision, and parallel reduction order become a measurable, localizable, mitigable test target — a blueprint for silent-data-corruption sentinels and deployment-consistency acceptance in inference stacks.

把基础设施因素导致的输出分歧，变成可测量、可定位、可缓解的差分测试问题，可直接迁移到推理栈的静默数据腐蚀（SDC）哨兵检测。

Critical edge

The headline flip rate rests on one model (HuatuoGPT2-7B); SR ≈ 1.0 mostly proves an effectively unbounded gradient search can win a razor-thin margin — and no fp32/CPU oracle ever says which execution is actually correct.

01 — Methodology

Freeze everything except the stack

Paired oracle

HuggingFace single-device execution is the reference; DeepSpeed, FSDP, vLLM, or TensorRT-LLM on 2/4 GPUs is the matched deployment. Checkpoint, prompt template, and decision rule are frozen — any output difference is attributable to the serving stack alone.

VDST · visual

Inside an L∞ ball of radius 0.03, Adam searches an additive perturbation that keeps the reference prediction correct while forcing the distributed execution to flip (asymmetric oracle; λ=1.0, β=0.002). SR = fraction flipped within budget; Avg. Step = search cost.

TDST · textual

A gradient-guided discrete search appends tokenizer-stable invisible Unicode characters (Cc/Cf/Zs/…, e.g. U+FE00–FE0F) that equalize the top-two answer probabilities until the two stacks pick different options — the visible question never changes.

Localize → mitigate

Per-layer MAD and Relative Divergence Lift rank layers by how much they amplify execution divergence; the top-5% — overwhelmingly self.rotary_emb and self.norm — are elevated to float32, everything else untouched (see RQ4).

03 — What holds up

Strengths

  • Clean paired design that genuinely isolates the execution stack — a rigorous operationalization of an evaluation–deployment mismatch that medical-model evaluation has largely ignored.
  • TDST’s invisible-token construction (tokenizer-ID-stable, visually imperceptible) is a clever, reusable primitive for testing LLM serving stacks.
  • Breadth with discipline: 9 models × 4 frameworks × 2/4 GPUs, reporting both SR and search cost — the SR-vs-steps matrix is genuinely informative.
  • Closes the loop: phenomenon → test generation → mechanistic localization → minimal-change mitigation. More actionable than a pure measurement study.
03 — Where it cracks

Limitations

  • Single-node only: no multi-node parallelism, no quantized serving (INT8/AWQ/GPTQ), batching, or speculative decoding — exactly where divergence is worst in practice.
  • Natural flip rate quantified for one model; SR never calibrated against random-perturbation or fixed-budget baselines.
  • Mitigation is visual-track-only, leaves a 0.86 residual, and comes with no latency/memory/accuracy-side-effect measurements.
  • No fp32 ground-truth oracle — the reference-vs-deployment asymmetry is a modeling choice, not validated truth.
  • Small public benchmarks, unspecified test-set sizes and step budget T; no code or data release stated.
04 — Questions for further exploration

What to ask next

  1. Does the 25–46% natural flip rate generalize, or is HuatuoGPT2-7B an outlier — and is deployment ever more correct than the HuggingFace reference on flipped cases?
  2. Would random perturbations of matched L∞ magnitude reach comparable SR? A fixed-budget ablation would calibrate what SR actually means.
  3. How does targeted float32 elevation compare with full fp32 serving on accuracy, latency, and memory — does it shift ordinary task accuracy at all?
  4. Do critical-layer sets transfer across inputs and workloads, or must they be re-profiled — can architecture alone predict them?
  5. How does the phenomenon interact with quantized serving (INT8/AWQ) and multi-node tensor parallelism, where precision loss and reduction order compound?
