Frozen weights, self-edited harness code — design lessons for any long-horizon autonomous agent.

Critical Edge · 批判

Every number is a single stochastic run — no seeds, no error bars, no confidence intervals. The +0.2 EgoSchema edge over VideoHarness-RSI (78.2 vs 78.0) is indistinguishable from noise, yet the abstract claims gains “across four benchmarks.”

Method

方法 · 蒸馏版
01Solveanswer + trace + resource record
02Investigatere-query training videos, not just the trace
03Rewriteedit harness code: prompts, tools, memory, control
04Gatetwo-sided test on a private dev set
05Compoundaccepted candidate becomes incumbent

Every model weight stays frozen — only the harness evolves: ordinary executable code spanning prompt construction, tool implementation, observation processing, memory, and execution control. One DeepSeek-V4-Pro plays both roles. The Solver answers a video question and emits an answer, an execution trace, and a resource record; the Editor reads failed outcomes, traces, and code, then rewrites the harness.

The key move is active video investigation. A trace only records what the current harness happened to observe, so it cannot separate “missed the event” from “misread the observation” from “failed to use the evidence.” Before editing code, the Editor re-watches the training videos with targeted queries — varying temporal region, sampling density, and modality; perception requests never contain the gold answer — until a failure hypothesis is supported or explicitly left unresolved.

Each candidate then faces the gate below on a private, video-disjoint 72-question development set; between attempts the Editor sees only aggregate accuracy and frame counts.

accept Ĥt  iff  ΔAt > 0  ∧  Ĉt ≤ (1+α)·Ct

What Evolution Kept

进化产物

H_S2Structured perception

Timestamped findings — the Solver records what it saw and when, instead of raw frame dumps.

H_S4Evidence-reuse relation graph

Re-queries already-collected evidence; graph lookups consume zero new frames.

H_S7Selective observation routines

A Global-64 overview route plus an occurrence-counting tool — look less, miss less.

5 of 20 revision attempts survived the gate; these 3 are named in the paper. Together they show “how to look” and “how to reuse evidence” co-evolving.

03

Strengths

优势
  • +Sharp core insight: execution traces cannot distinguish competing failure explanations, so self-improvement needs evidence beyond the trace — operationalized via targeted video re-inspection.
  • +Two-directional gate makes efficiency a first-class evolution objective; the ablation is convincing.
  • +Evaluation hygiene above the bar: video-disjoint private selection set, aggregate-only feedback, gold-answer-free perception queries, same-backbone reproduction of the two nearest baselines.
  • +Honest reporting: the paper shows the first accepted revision lowering MLVU accuracy and warns that early dev gains give “an incomplete picture.”
  • +Verifiable retained code: structured perception → relation graphs → selective routines, with graph queries designed to cost zero new frames.
04

Limitations

局限
  • −Single run, no variance: +0.2-level claims (EgoSchema vs VideoHarness-RSI) are unsupported.
  • −Compute is understated: frames only; the offline evolution budget (investigation queries, 216-question runs, repeated dev evals over 20 attempts) is unreported.
  • −Small dev set: 72 questions; Fig. 3 shows dev gains do not transfer step-by-step (MLVU dipped after the first acceptance).
  • −Closed top-tier LLMs only: nothing shows the loop works with smaller/open models, where failure diagnosis itself is weaker.
  • −Narrow evaluation: MC accuracy on public long-video subsets only — no open-ended QA, no out-of-distribution video domains.
  • −Run-specific dynamics: the 20-attempt budget and retained revisions are specific to this run; convergence from a different initial harness is untested.
05

Questions for Further Exploration

待探索
  • Q1

    Would the accuracy–cost gains hold with an open-weights Solver/Editor (7B–72B), where the Editor’s failure diagnosis is itself weaker?

  • Q2

    Can the gate extend beyond accuracy + frames to latency, token cost, or robustness — and does multi-objective selection still converge within 20 attempts?

  • Q3

    Is the +8.2-pt investigation gain driven by video evidence specifically, or would any independent re-execution (e.g., new sampling seeds) recover most of it?

  • Q4

    How does the evolved harness behave out of distribution — egocentric or surveillance-style video — and does the 72-question gate overfit selection to benchmark style?

  • Q5

    Could the retained code changes be transplanted into the initial harness — and how much headroom does evolution actually add over good hand design?
