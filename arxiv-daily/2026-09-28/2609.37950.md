> **一句话总结：** Video-RSI 让一个冻结的 DeepSeek-V4-Pro 同时充当"求解器"和"编辑器"：编辑器通过主动回看训练视频验证失败假设（而非只看执行轨迹），再用一个同时权衡准确率与视觉帧开销的准入门（式 3）决定是否保留修订后的 harness 代码；20 次修订尝试后仅保留 5 次被接受的改动，最终在 MLVU 上从 62.4% 提升到 72.9%（+10.5 pts，且每题帧数从 68.5 降到 61.1），在四个长视频基准上全面超过同模型复现的 VideoHarness-RSI。

> **TL;DR:** Video-RSI recursively self-improves a video-QA agent's executable harness with the model weights frozen: the same DeepSeek-V4-Pro acts as Solver (answers questions) and Editor (revisits training videos to test competing failure explanations, then rewrites harness code). Candidate harnesses are accepted only by a cost-aware gate that requires either an accuracy gain with bounded frame-cost growth (α=0.1) or a cost reduction with bounded accuracy loss (β=0.2). Evolving on 216 LVBench questions and selecting on a private 72-question dev set, the final harness reaches 72.9% on MLVU vs 62.4% for its own initial harness (+10.5 pts) and 64.1% for the reproduced VideoHarness-RSI baseline (+8.8 pts, with 61.1 vs 83.2 frames/question), and 80.0% on Video-MME-Long vs 69.7% for VideoHarness-RSI at roughly a quarter of the frame usage (21.6 vs 92.8).

## 核心贡献

- **Video-RSI 框架**：在模型完全冻结的前提下，用同一个 LLM 既当 Solver（回答视频问答）又当 Editor（诊断失败并修订 harness 代码，涵盖提示构建、工具实现、观测处理、记忆与执行控制），实现可执行 harness 的递归自我改进。
- **主动视频调查（Active Video Investigation）**：核心洞察是执行轨迹只记录"当前 harness 看到了什么"，无法区分漏看事件、误读观测、还是没用好已有证据这三种失败解释；Editor 通过对训练视频发出带针对性的查询（变时间区域、采样密度、模态、感知问题，且感知请求不含标准答案）来区分这些假设，把修订建立在轨迹之外的证据上。
- **代价感知的准入门（Cost-Aware Harness Evolution）**：在私有的、与训练视频不相交的 72 题开发集上，候选 harness 只有在 (a) 准确率提升且帧开销增长 ≤(1+α)C，或 (b) 帧开销减少 ≥β·C 且准确率下降 ≤ε 时才被接受，保证"更准"与"更省视觉观测"两个方向都可持续积累。
- **实证结果与消融**：在 MLVU、LongVideoBench、Video-MME（长视频）、EgoSchema 四个基准上，进化后的 harness 比初始版本和 VideoHarness-RSI 准确率更高、帧数更少；消融证明主动调查（MLVU 上比只用轨迹的变体 +8.2 pts）和代价感知选择（Video-MME 上比只看准确率的门少用约一半帧数且更准）各自不可或缺。
- **对进化产物的定性分析**：保留下来的 5 次修订分别引入了结构化感知（H_S2）、证据复用关系图（H_S4，图查询不消耗新帧）、选择性观测例程（H_S7 的 Global-64 路线与 occurrence 计数工具），展示了"如何看"与"如何用证据"的协同进化。

## Key Contributions

- **Video-RSI framework**: recursive self-improvement of a video agent's executable harness where one frozen language model serves as both Solver and Editor, jointly revising prompts, tools, observation processing, memory, and execution control.
- **Active video investigation**: the key observation that an execution trace only records what the current harness observed, so it cannot distinguish "missed the event" vs "misread the observation" vs "failed to use available evidence"; the Editor issues targeted queries against the original training videos (varying temporal region, sampling density, modality, perceptual question; perception requests omit the gold answer) to test competing failure explanations before editing code.
- **Cost-aware acceptance gate**: on a private, video-disjoint 72-question development set, a candidate harness is accepted only if it achieves an accuracy gain with bounded cost growth (Ĉ ≤ (1+α)C) or a cost reduction with bounded accuracy loss (Ĉ ≤ (1−β)C), turning evolution into a two-directional accuracy–efficiency optimizer.
- **Evidence across four benchmarks with ablations**: the evolved harness beats both the initial harness and the reproduced VideoHarness-RSI on MLVU, LongVideoBench, Video-MME-Long, and EgoSchema with fewer frames; ablations isolate the value of investigation (+8.2 pts on MLVU over trace-only revision) and of the cost-aware gate (half the frames on Video-MME at higher accuracy than an accuracy-only gate).
- **Analysis of the evolved code**: the 5 retained revisions introduce structured perception with timestamped findings (H_S2), evidence-reuse relation graphs whose queries consume no new frames (H_S4), and selective observation routines like a Global-64 overview route and an occurrence-counting tool (H_S7).

## Methodology

**Problem formulation.** A harness H governs evidence acquisition for video QA: the Solver produces (ŷ, τ, c) = Run(H, V, q; M) — an answer, an execution trace, and a resource record. The harness is ordinary executable code spanning prompt construction, tool implementation, observation processing, memory, and execution control. Evolution is offline: a training set D_tr is used for investigation and revision, while a fixed, video-disjoint selection set D_g (kept private to the evaluator; per-example outcomes hidden from the Editor) decides acceptance.

**Active video investigation.** At each revision attempt the Editor examines training outcomes, traces, and code, prioritizing representative failures. It maintains an investigation context I_k and iteratively selects queries u_k = Query_Editor(I_k) and accumulates observations o_k = Investigate(u_k; H_t, D_tr, M). Queries vary temporal region, sampling density, modality (video frames, speech transcripts, on-screen text), or pose perceptual questions — including reruns of the unmodified incumbent — and perception requests never include the gold answer. Investigation ends with either a supported revision hypothesis or an explicitly unresolved case. A key design rule: diagnosis may use training annotations to locate informative intervals, but the resulting revision must rely only on cues available to the Solver on new questions.

**Cost-aware harness evolution.** The Editor maps the diagnosis to code edits, runs training-side checks, and submits a candidate Ĥ_t. On the selection set, with incumbent accuracy A_t and mean frames C_t, the gate accepts when:
- g_t = 1 if ΔA_t > 0 ∧ Ĉ_t ≤ (1+α)C_t (accuracy gain with bounded cost growth), or
- −ε ≤ ΔA_t ≤ 0 ∧ Ĉ_t ≤ (1−β)C_t (cost reduction with bounded accuracy loss).

The Editor then sees only aggregate accuracy and frame counts for the next attempt — per-example traces stay private. Accepted candidates become the incumbent; everything is ordinary code, so improvements compound.

**Experimental setup.** Solver and Editor: DeepSeek-V4-Pro (frozen); visual observations: Qwen3-6B-Plus (frozen). Evolution uses 216 LVBench questions plus a separate 72-question video-disjoint development set; 20 revision attempts with α=0.1, β=0.2, ε=1/|D_g|. The initial harness H_S0 supports global/local video inspection, transcripts, OCR, and observation memory. Baselines: MLLMs (GPT-4o, Gemini 1.5/2.0, GPT-5, Qwen2.5-VL-72B), video agentic models (VideoAgent, VideoTree, DrVideo, VCA, MR.Video, DVD, FrameThinker, LVAgent, EVA-GRPO, VideoSeek), and VideoHarness-RSI — with VideoSeek and VideoHarness-RSI reproduced under the same DeepSeek-V4-Pro backbone. Metrics: multiple-choice accuracy and mean visual frames per question (frames processed by successful visual-model calls over complete QA executions; offline Editor observations excluded).

## Results & Highlights

- **MLVU (Test):** Video-RSI reaches **72.9%** vs **62.4%** for its own initial harness (+10.5 pts) at *lower* frame usage (61.1 vs 68.5 frames/question), and vs **64.1% / 83.2 frames** for the same-backbone VideoHarness-RSI (+8.8 pts with ~27% fewer frames).
- **vs VideoSeek (MLVU):** +4.8 percentage points (72.9% vs 68.1%) while using 27.2% fewer frames (61.1 vs 83.9) — the paper's headline accuracy-efficiency combination.
- **Video-MME (Long):** **80.0%** vs 73.4% initial (+6.6 pts) with 21.6 vs 38.6 frames (~44% fewer), and vs **69.7% / 92.8 frames** for VideoHarness-RSI (+10.3 pts at ~a quarter of the frames). Caveat: VideoSeek scores 78.7% with only 17.8 frames, so Video-RSI is not uniformly dominant here.
- **LongVideoBench (Long val) & EgoSchema:** 71.1% (vs 67.7% initial, 41.1 vs 51.6 frames) and 78.2% (vs 71.4% initial, 42.4 vs 66.0 frames). Across all four benchmarks the final harness uses **10.8–44.1% fewer frames** than H_S0.
- **Ablation — investigation matters:** trajectory-only revision gets 64.7% on MLVU vs **72.9%** with active investigation (+8.2 pts) at nearly identical inference-time frames (60.3 vs 61.1); the investigation run also retains 5 of 20 revisions vs 3 for trace-only, and the gain holds (with fewer frames) on the other three benchmarks.
- **Ablation — cost-aware gate matters:** an accuracy-only gate improves accuracy over the initial harness but increases frames on three of four benchmarks; the full gate reaches higher accuracy than the accuracy-only variant on every benchmark — e.g., Video-MME **80.0% at 21.6 frames vs 74.9% at 43.1 frames** (roughly half the frames).
- **Evolution dynamics:** on the 72-question dev set the first accepted revision delivers most of the net frame reduction (64.3 → 45.5 frames) and a large accuracy jump (62.5 → 76.4); on MLVU the first accepted revision actually *lowers* accuracy before later revisions recover it, and the final two accepted revisions account for most of the net MLVU gain.

## Authors & Credibility

The three authors are from Tsinghua University (Bingjun Luo, Siqi Li) and Harbin Engineering University (Jialin Guo). This is a small academic team; no prior-track-record claims can be verified from the paper itself. Credibility positives: code is released (github.com/bingjunluo/Video-RSI); the paper includes an explicit AI-use statement covering code editing, figures/tables, and manuscript review; evaluation hygiene is unusually careful — the selection set is video-disjoint and private to the evaluator, the Editor only ever sees aggregate metrics, perception queries omit gold answers, and the two closest baselines (VideoSeek, VideoHarness-RSI) were reproduced under the identical backbone (DeepSeek-V4-Pro + Qwen3-6B-Plus) rather than quoted from different setups. The work builds openly on a clearly mapped 2026 literature (Self-Harness, VideoHarness-RSI, Meta-Harness, Darwin Gödel Machine, VideoSeek) with an honest related-work positioning.

## Critical Assessment

- **Incremental over VideoHarness-RSI / Self-Harness, and mostly upfront about it.** Harness evolution with a frozen model is inherited from prior work; the genuinely new pieces are the active-investigation step and the two-sided acceptance gate. The paper frames this correctly, but the headline framing ("recursive self-improvement") rests on an existing paradigm.
- **No statistical rigor.** Every number is a single run of an LLM-driven stochastic process; there are no error bars, seeds, or confidence intervals. The EgoSchema edge over VideoHarness-RSI is **78.2% vs 78.0% (+0.2)** — indistinguishable from noise — yet the abstract claims improvement "across four benchmarks." The selection set of 72 questions also makes ε = 1/72 ≈ 1.4% a coarse tolerance for a multiple-choice benchmark.
- **The cost metric understates true compute.** "Frames" counts only frames processed by successful visual-model calls during QA execution; the 20 offline attempts — each investigating failures on 216 training videos and repeatedly evaluating the 72-question dev set — are excluded. Self-improvement is amortized, which is fair for a deployed harness but means the accuracy-efficiency Pareto claim ignores the (unreported) Editor budget.
- **Mixed-provenance comparison table.** Only VideoSeek and VideoHarness-RSI were reproduced under the same backbone; the MLLM and agentic rows are copied from original publications with different models, subtitles settings, and frame budgets, so those comparisons are context, not evidence. Within the reproduced set, VideoSeek actually beats Video-RSI on frame efficiency at Video-MME (17.8 vs 21.6 frames) and nearly matches it on LongVideoBench (70.9 vs 71.1).
- **A small internal inconsistency.** Figure 3(c) annotates the final MLVU accuracy as 73.9 while Table 1 reports 72.9; Section 4.4 says MLVU was evaluated retrospectively, but the discrepancy is never explained.
- **Leakage guardrail is qualitative.** The rule "revisions must use cues available to the Solver on new questions" is a design intention, not a mechanically enforced check — an Editor that saw annotation-localized intervals could still bake in dataset-specific shortcuts that happen to survive the 72-question gate.
- **Dependency on closed models.** DeepSeek-V4-Pro and Qwen3-6B-Plus are proprietary; exact numbers are not reproducible even with the released code, and conclusions may not transfer to weaker or open models (a 6B visual model doing the perception leaves headroom for other failure modes the harness never had to fix).

## Strengths

- The core insight — execution traces cannot distinguish competing failure explanations, so self-improvement needs evidence *beyond* the trace — is sharp, well-motivated, and directly operationalized via targeted video re-inspection.
- The two-directional acceptance gate is a clean, simple mechanism that makes "efficiency" a first-class evolution objective; the ablation (accuracy-only gate inflates frames on 3 of 4 benchmarks) convincingly demonstrates its value.
- Evaluation hygiene is above the bar for this literature: video-disjoint private selection set, aggregate-only feedback to the Editor, gold-answer-free perception queries, and same-backbone reproduction of the two nearest baselines.
- Honest reporting of non-transfer: the paper explicitly shows the first accepted revision *lowering* MLVU accuracy while improving dev metrics, and warns that early dev-set gains "give an incomplete picture of evaluation behavior."
- The qualitative analysis of retained code (structured perception → relation graphs → selective observation routines) is concrete and verifiable, with graph queries designed to cost zero new frames.

## Limitations

- Single-run evaluation without variance estimates; +0.2-level claims (EgoSchema vs VideoHarness-RSI) are not supported.
- Efficiency is measured in visual frames only; the offline evolution compute (investigation queries, 216-question runs, repeated dev evaluations over 20 attempts) is unreported.
- Selection on a 72-question dev set is small, and Figure 3 shows dev gains do not reliably transfer step-by-step (MLVU dipped after the first acceptance).
- Evolution dynamics depend on closed, top-tier LLMs; nothing shows the loop works with smaller/open models where failure diagnosis itself is weaker.
- Multiple-choice accuracy on public long-video subsets is the only evaluation — no open-ended QA, no measuring of whether the evolved harness generalizes to out-of-distribution video domains or question types beyond the four benchmarks.
- The 20-attempt budget and the three named retained revisions (H_S2, H_S4, H_S7) are specific to this run; the paper does not test whether the loop converges similarly from a different initial harness.

## Questions for Further Exploration

- Would the same accuracy–cost gains hold if the Solver/Editor were an open-weights model (e.g., a 7B–72B Qwen), where the Editor's failure diagnosis is itself weaker?
- Can the acceptance gate be extended beyond two objectives (accuracy, frames) to include latency, token cost, or robustness — and does multi-objective selection still converge within 20 attempts?
- Is the active-investigation gain (+8.2 pts over trace-only on MLVU) driven by *video* evidence specifically, or would any independent re-execution of the incumbent (e.g., re-running with different sampling seeds) recover most of it?
- How does the evolved harness behave out of distribution — e.g., on egocentric or surveillance-style videos absent from LVBench-derived training data — and does the 72-question gate overfit selection to benchmark style?
- Could the qualitative code changes (relation graphs, occurrence counting) be transplanted into the *initial* harness as a stronger H_S0, and if so, how much headroom does the evolution loop actually add over good hand design?
