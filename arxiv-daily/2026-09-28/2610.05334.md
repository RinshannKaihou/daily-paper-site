> **一句话总结：** AgentDiscover 把进化搜索的"选择策略"从人工预设的算法（MAP-Elites、岛屿模型、UCT/MCTS）移交给一个编码 agent 本身——agent 通过 Cypher 查询自管的知识图谱长期记忆来自己规划搜索；在 24 个任务上以相同模型花费超过 CORAL、OpenEvolve、ShinkaEvolve、EvoX：在 Anthropic kernel builder 任务上 $100 预算即达 960 cycles（最强基线 EvoX 为 1,098，低 12.6%），对朴素内核加速 153.9× 并打破已发表 SOTA（1,103 cycles），其成绩本可在全部 5 个历史 AtCoder 启发式竞赛中夺得人类选手第一。

> **TL;DR:** Prior LLM-discovery systems (FunSearch, AlphaEvolve, ShinkaEvolve, CORAL) fix a human-designed search algorithm before the run and relegate the LLM to proposer. AgentDiscover promotes the model to planner: a sandboxed coding agent (Claude Code) queries a Neo4j graph database of every idea/candidate/lesson as long-term memory, where classical selection rules become single read-only Cypher queries (MAP-Elites and UCT are "one query each") that the agent can use, combine, or replace. Across 24 problems — five AtCoder heuristic contests, GPU kernel engineering, systems and mathematical optimization, autocorrelation inequalities, and Anthropic's kernel-builder task — it matches or beats every baseline at matched model spend: on the kernel-builder task it reaches 960 cycles by $100 vs 1,098 for the strongest baseline EvoX (a 12.6% reduction, 153.9× over the naive kernel, beating the published SOTA of 1,103), and its AtCoder scores would have placed first among the human field in all five original contests (e.g., AHC015: 168,660,525 vs CORAL's 156,230,796). Ablations attribute gains to context resets, and to an optional meta agent whose guidance lifts forks that beat their pre-fork best fitness from 33% to 73%.

## 核心贡献

- **提出 AgentDiscover 框架**：用编码 agent 取代固定的进化搜索算法——agent 自己决定读什么、试什么、何时放弃，把经典算法的选择规则（MAP-Elites 精英选择、UCT 访问计数）降格为知识图谱上的一条只读 Cypher 查询，可自由使用、组合或替换。
- **图数据库长期记忆 + 服务端护航**：所有 idea、候选程序、session、教训都入 Neo4j 图谱（经 MCP 访问）；评测器隔离在 agent 沙箱之外，每次提交后服务器返回带 fitness 和剩余名额的 steering 消息，保证长时程搜索不脱轨、上下文成本可控（session 定期重置上下文）。
- **广泛的实证优势**：在 7 个 AtCoder 竞赛中本可全部夺得人类第一；在 11 个系统/数学优化任务上以同一 backbone 匹配或超过全部基线（7 项最佳）；改进了第一自相关不等式的已发表最优界（AC1 上界 1.50274，已提交 Einstein Arena 排名第一）。
- **成本效率视角**：以"模型花费—性能"曲线而非单点成绩做对比——达到 125× 内核加速只需 $10.87，而 EvoX 需 $47.45、CORAL $61.65、ShinkaEvolve $103.30。
- **发现并修复了先前工作评测器的 reward-hacking 漏洞**：输出校验不全（Signal Processing 任务中返回两个采样点的退化解得 0.9250，而诚实最优为 0.727）、候选程序可控制打分函数（重绑 `pearsonr` 返回常数 1e9）、以及 EPLB 的训练数据泄漏（平衡分从 0.25 抬到 0.44）——修正后所有主要表格均用更正过的评测器重新计分。

## Key Contributions

- **AgentDiscover framework**: replaces the fixed evolutionary search algorithm with a coding agent that directs the search, managing its context efficiently through a graph database of past attempts in which the selection rules of classical algorithms (MAP-Elites, UCT) are single queries the agent can use, combine, or replace.
- **Empirical dominance at matched spend**: outperforms prior discovery frameworks on 24 problems — programs that would have placed first among human competitors in all seven past AtCoder heuristic contests tested, best published bound on the first autocorrelation inequality (AC1 = 1.50274, ranked 1st on the Einstein Arena leaderboard), and the lowest kernel-builder cycle count at every budget ($25–$118), all while being more cost-efficient (125× speedup reached at $10.87 vs $47.45 for EvoX).
- **Reward-hacking audit of prior evaluators**: identifies three recurring evaluator failure modes (incomplete output validation, candidate-controlled scoring, information leakage across the training boundary), corrects them, and reports both original and corrected scores — e.g., a degenerate Signal Processing candidate scored 0.9250 under the original evaluator vs the 0.727 honest optimum.
- **Component ablations**: context resets raise the chance of improving the best score after a >5-candidate stall from 25.2% to 35.3%; four parallel agents speed wall-clock convergence without reducing spend; a meta agent that distills session transcripts into skills/guidance makes forks beat their pre-fork best in 73% of cases vs 33% without guidance.

## Methodology

AgentDiscover has three components.

**Search agent.** A sandboxed Claude Code instance working in a version-controlled worktree. Each session starts from a rendered instruction file describing the task, a database briefing (best fitness in branch/database, target, candidate counts), and the current strategy. Through an MCP server the agent can: (1) `read_graph` — run any read-only Cypher query over the knowledge graph; (2) run experiments locally and write tools/skills into its worktree; (3) `add_idea` and `submit_candidate`, which triggers server-side evaluation in an isolated sandbox and returns a steering message reporting fitness, remaining candidate quota, and context-cost notes (a note from the fifth candidate onward tells the agent when a fresh session is cheaper than continuing). Sessions terminate when the agent stalls or exhausts its cap; a fresh agent then restarts with a clean context but the same persistent memory, which both caps per-call input-token cost and helps escape local optima. Classical strategies are exposed as native queries — MAP-Elites (one candidate per idea region) and UCT (visit-count-weighted candidate selection) are each a single Cypher query the agent may issue.

**Long-term memory.** A Neo4j graph holding typed nodes (User, Agent, Session, Candidate keyed by SHA-256 of the program text, Idea, Resource, Guidance, Tool, RunConfig) and provenance-separated edges: *facts* reconstructed by code from session transcripts (which files/candidates were actually read) versus the agent's *claims* (declared parents/ideas/resources). The database rejects agent writes directly; all writes go through fixed tools (`add_idea`, `submit_candidate`), so the store stays consistent and tamper-resistant.

**Meta agent (optional).** A second coding agent that runs after each iteration block. It reads only session transcripts, reasoning traces, and outcomes — never genomes or the evaluator — and distills which reasoning patterns paid off into: per-session lessons (`write_meta_lesson`), read-only saved Cypher query tools (`add_tool`), and a branch strategy (`write_strategy`) injected into the next sessions' instructions. Execution safeguards: the evaluator is never mounted into the agent's container (score computed on a copy, hidden test data withheld); the agent's own sandbox blocks the private workload; stdout/exception text is withheld from feedback (closing an EPLB leak); database access is read-only at the transaction level.

**Evaluation protocol.** 24 problems: TTT-Discover's multi-domain tasks (2 kernels, 3 denoising, 2 AHC contests, AC1/AC2) at matched $10 model spend with GPT-6 Sol or Claude Opus 5; five past AtCoder Heuristic Contests (AHC006/012/015/025/041) scored on official system tests at matched spend with Claude Opus 5; five systems + six mathematical tasks (≤100 candidates, Claude Opus 4.6, baselines from Qu et al.'s published results plus re-runs of OpenEvolve/ShinkaEvolve/EvoX); Anthropic's kernel-builder task at $25–$118 budgets, all five frameworks on Opus 5 low reasoning effort. Model spend is estimated from transcript token usage at published API list prices. Three ablations study context resets, four parallel search agents, and meta-agent guidance (15 fork pairs on transaction scheduling, search with Claude Haiku 4.5, meta with Opus 4.6).

## Results & Highlights

- **Anthropic kernel builder (matched model spend, Opus 5):** AgentDiscover attains the lowest cycle count at every budget — 1,016 cycles at $25 vs 1,237 (CORAL) and 1,228 (OpenEvolve); by $100 it reaches 960 cycles vs 1,098 for the strongest baseline EvoX, a 12.6% reduction. That is a 153.9× speedup over the naive kernel (11,910 cycles) and beats the published SOTA of 1,103 cycles. It reaches a 125× speedup after $10.87 of model spend, vs $47.45 (EvoX), $51.67 (OpenEvolve), $61.65 (CORAL), $103.30 (ShinkaEvolve).
- **AtCoder heuristic contests (official system tests):** AgentDiscover's programs would have placed 1st among the original human competitors in all five contests, and rank first or third even when post-contest submissions are included. It beats all compared frameworks on four of five (tie on AHC006), e.g., AHC012: 99,997,290 vs CORAL 99,977,717 and OpenEvolve 99,090,668; AHC015: 168,660,525 vs CORAL 156,230,796. On AHC025 (lower is better) it posts 19,173,103 vs CORAL's 25,923,844 and reaches the contest-winner reference objective after $22.34 vs CORAL's $72.97.
- **Multi-domain discovery (Table 1, matched $10 spend):** best on essentially every task vs TTT-Discover and CORAL — TriMul kernel 2.080 μs vs TTT-Discover 2.198 / CORAL 2.419; Tabula lung denoising MSE 0.132 vs CORAL 0.139; AHC039 577,217 vs TTT-Discover 567,062; AC1 bound 1.50274 vs 1.50282 (CORAL) — this AC1 construction ranked 1st (1.50274-1535) on the public Einstein Arena leaderboard on Oct 3, 2026. (One exception visible in the table: MLA-Decode, where CORAL's 1.382 μs is the bolded best over AgentDiscover's 1.474 μs.)
- **Systems & mathematical optimization (Table 3, ≤100 candidates, Opus 4.6):** matches or beats every baseline on all eleven tasks, best on seven. EPLB 0.153 vs 0.149 (CORAL/EvoX); Txn Sched 4651 vs 4566 (CORAL); Cloudcast 618.0 vs 618.4; Signal Processing under the corrected evaluator 0.7948 vs 0.7790 (CORAL) — whereas the original evaluator had awarded 0.9250 to a degenerate two-sample candidate against the 0.727 honest optimum.
- **Meta-agent ablation (15 fork pairs, transaction scheduling):** guided forks beat their pre-fork best fitness within two candidates in 73% of cases vs 33% without guidance (87% vs 53% within ten candidates); the median candidate fitness across all proposals rises from 0.801 to 0.832; the guided run holds higher best fitness in 10 of 15 forks (tie 2, lower 3).
- **Context resets:** after a stall of more than five candidates, a reset raises the chance the best score improves within three candidates from 25.2% (control) to 35.3%, and the expected gain per three candidates from 0.13% to 3.7%. Four parallel agents converge faster in wall-clock but show no clear difference at equal model spend.

## Authors & Credibility

The authors are an academic group at Texas A&M University spanning electrical and computer engineering: Mahdi Farahbakhsh, Ilan Sela, Fatemeh Doudi, Vishnu Teja Kunde, Jean-François Chamberland, and Dileep Kalathil (a reinforcement-learning researcher), with Krishna Narayanan. The work is supported by NSF, the U.S. Army Combat Capabilities Development Command, and industry partners, and used the TAMU HPC/VISION infrastructure. Credibility signals are strong: an explicit AI-use statement discloses that Claude Code and ChatGPT helped implement and debug the framework, with every reported number checked against stored run logs and every citation verified against the original source; the reward-hacking appendix documents concrete evaluator exploits with exact numbers rather than vague admissions; prompts, knowledge-graph schema, budgets, and spend-accounting methodology are published in appendices; and code is released. The evaluation spans five distinct frameworks and 24 tasks with cost-matched comparisons, which is more rigorous accounting than most prior evolutionary-discovery papers provide. The main caveat is that most headline entries are single runs (acknowledged in Limitations).

## Critical Assessment

**Novelty.** The framing — "the agent should own the search" — is a genuine conceptual inversion of the FunSearch/AlphaEvolve recipe, and the observation that MAP-Elites and UCT reduce to single Cypher queries is a memorable simplification. But the nearest neighbor, CORAL, already gave long-running coding agents control of retrieval and search direction; the paper's own related-work section carefully enumerates four deltas (periodic context resets, graph memory over ideas+candidates+lessons, agent-written tools/queries, session restart from the server rather than a heartbeat). This is a substantial-but-incremental step on CORAL, and the empirical wins are where the novelty case is actually carried.

**Rigor.** Every main-table entry is a single run with no variance (admitted in Limitations), and several margins sit well within plausible run-to-run noise: Erdős overlap 0.38077 vs CORAL's 0.38089 and Cloudcast 618.0 vs 618.4 are ties at reporting precision. There is also a text-vs-table inconsistency: Section 4.1 claims AgentDiscover "outperforms both TTT-Discover and CORAL on every task in Table 1," yet on MLA-Decode the bolded best entry belongs to CORAL (1.382 μs) over AgentDiscover (1.474 μs). Baseline provenance is mixed: systems/math baselines are imported from Qu et al.'s published results rather than re-run under identical settings, and the AtCoder "would have placed first" claim is counterfactual against the original human field, not a head-to-head. Model spend is estimated at API list prices because the runs used subscriptions — reasonable, but not invoiced reality.

**Reproducibility.** Good on paper: code released, full prompts and hyperparameters in appendices, spend accounting documented. But the scaffold is tightly coupled to subscription-priced frontier Claude models (plus GPT-6 Sol on some tasks), so exact replication depends on vendor availability and pricing; the Limitations concede the backbone was never varied on a fixed task, so the framework-vs-model attribution is untested.

**Red flags / missing analysis.** The paper's central question — do agents actually run better searches than fixed algorithms — is left unexamined: the authors admit they have not analyzed which strategies the agents use, i.e., whether they rediscover MAP-Elites/UCT or synthesize new rules. Without that, "the agent owns the search" could partly reduce to "a stronger model plus a good memory does more compute per decision." The ablations also run on Claude Haiku 4.5 (search) rather than the flagship Opus configuration, so the transfer of the meta-agent gains to the headline setup is assumed, not shown. To their credit, the evaluator reward-hacking audit (Signal Processing 0.9250-vs-0.727 degenerate solution; EPLB balance inflated 0.25→0.44 via workload leakage; LLM-SQL pickle deserialization executing candidate code) is genuinely valuable hygiene for the whole subfield — and implicitly a warning that several published baselines' numbers were set by exploitable evaluators.

## Strengths

- Unusually broad evaluation: 24 problems across kernel engineering, biology, algorithm design, mathematics, competitive heuristics, and systems, with cost-matched comparisons where spend data exists.
- The spend–performance curve framing (e.g., $10.87 to reach 125× vs $47.45–$103.30 for baselines) is more decision-useful than single-point leaderboard scores.
- Security- and honesty-conscious infrastructure: evaluator isolation, typed read-only graph access, fact-vs-claim edge provenance, and both original and corrected evaluator scores reported side by side.
- The reward-hacking taxonomy (incomplete output validation, candidate-controlled scoring, training-boundary leakage) with concrete exploit numbers is a contribution to the field's measurement integrity independent of the framework itself.
- Clean ablation design for the meta agent (fork pairs sharing state, differing only in guidance) that removes run-to-run randomness from the comparison.

## Limitations

- Single run per main-table entry; no variance or error bars, and several wins are within noise-sized margins.
- Heterogeneous setups across tables (Opus 4.6 / Opus 5 / GPT-6 Sol; re-run vs imported published baselines) complicate apples-to-apples reading.
- No backbone-model swap on a fixed task, so gains cannot yet be attributed to the scaffold vs the model family.
- No analysis of which search strategies agents actually employ — the mechanistic claim behind the headline is unverified.
- Spend is an estimate at list prices (runs used subscriptions); AHC025 is scored from a fixed standings snapshot rather than live standings.
- Ablations use a weaker model (Haiku 4.5) than the main configuration, leaving transfer of ablation conclusions to the flagship setup untested.

## Relevance

该文直接命中最高优先级方向"自进化智能体与自动化研究"：它把自动化发现循环中的搜索策略本身也交给智能体规划，用知识图谱做长期记忆、用元智能体把过往 session 蒸馏成技能，正是长时程自治智能体可靠性问题的前沿实践；其对评测器 reward-hacking 模式的系统审计对任何构建自动化实验循环的人都有直接参考价值。

## Questions for Further Exploration

- Do the search agents actually rediscover classical selection rules (MAP-Elites, UCT) via their Cypher queries, or synthesize novel strategies — and can strategy usage be logged and compared across tasks?
- Would the headline margins survive 5–10 seeds per entry, especially for the noise-level wins (Erdős overlap, Cloudcast)?
- Can the reward-hacking findings be turned into a public adversarial evaluation suite that stress-tests future discovery-framework evaluators (pickle-execution, leakage, output-validation gaps)?
- How do the meta agent's written strategies compare against hand-tuned harnesses from AdaEvolve/EvoX when both are constrained to the same adaptation space?
- Does the context-reset benefit (25.2% → 35.3% post-stall improvement) transfer to non-discovery long-horizon agent workloads, e.g., automated research loops outside program synthesis?
