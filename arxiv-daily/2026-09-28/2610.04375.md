> **一句话总结：** 本文定义了工具调用的"意图-执行一致性"(IEC)：LLM agent 发出的命令在到达程序前要经过 5 个"hops"（序列化→宿主包装器→shell 解析→进程接口→目标解析器），任何一跳都可能静默篡改调用。作者用"witness"（不执行调用的观测器）+ 接收方自己的解析器构建了逐跳检测协议 IEC，并在生产环境 47,828 条 shell 调用中实测：Claude Code 的 Bash 启动路径篡改 12.0% 的暴露调用，80.7% 的反斜杠被吞掉的调用无任何报错地跑错动作；轨迹归因（Who&When 系评委 κ≤0.04）把 95.1% 的失败错怪给 LLM，而 IEC 与人工标注一致度 κ=0.77 且零 LLM token。配套修复器 IntAct 在命名的那一跳"改道渲染或拒绝"，在 IEC-Bench 上恢复 79.2%（137/173）的路径致损失败，并把每个通过任务的 token 成本降低 2.4 倍（最差情形原本贵 12.3 倍），已以 Claude Code mod（4 ms/次）、商业桌面 agent 内核、shell shim、MCP server 四种形式部署。

> **TL;DR:** A tool call from an LLM agent passes through a 5-hop execution path (serialization, host wrapper, shell parse, process interface, target parser), and any hop can silently rewrite it. The paper defines **intent-execution correspondence (IEC)**, introduces a hop-by-hop **IEC protocol** (non-executing witnesses judged by each receiver's own parser), builds **IEC-Bench** (67 pattern pairs, 135 ToolHop chains, 46 Terminal-Bench 2 tasks, 6 transports), and ships **IntAct**, a deterministic repair that re-renders or refuses a call at the named hop. On **47,828 production shell calls**, Claude Code's Bash launch changes **12.0%** of exposed calls and **80.7%** of changed-backslash calls run with no reported error; trajectory-based attribution (Who&When judges) blames **95.1%** of failures on the LLM at **κ≤0.04** versus the IEC protocol's **κ=0.77** at zero LLM tokens. Against baselines, IntAct recovers **137/173 (79.2%)** lost pairs while QuoteBench's fixed replay detects only **37.2%**, and raises pooled Qwen2.5 pass@1 by **+30 pairs / +81 pairs** (exact McNemar p≤.001) while cutting token cost per passed task **2.4×** versus the unrepaired launch (up to 12.3×).

## 核心贡献

- **问题定义与新发现：** 首次为工具调用及依赖调用链定义"意图-执行一致性"（IEC）——执行动作是否等于发射调用在工具契约下所表示的动作。关键发现：**篡改调用的那一跳会把后续跳的改动全部隐藏**——在双跳改动的路径上，69 个路径致损失败中有 38 个只有修复第一跳后才会显现，这解释了为何单跳观测（如 QuoteBench）系统性低估问题。
- **首个真实世界测量：** 覆盖 261 个生产会话（47,828 条 shell 调用，Windows+Linux，9 名开发者，11 周）、10 个 harness、6 种 shell/终端、22 个 MCP server、203,710 条公开轨迹。Claude Code 的 Bash 启动改变 12.0% 携带代码/转义序列/长文本的调用；PowerShell 路径上 297 个调用在值内丢失双引号、127 个收到错误的参数个数；Qwen Code 的 `cmd.exe` 启动把 31 个多行命令中的 30 个跑成空程序；全部 10 个 harness 都会改调用，10 个 MCP server 中 10 个会改 payload，且每次改动都报告为"成功"。
- **评测方法（IEC 协议）：** 用 witness 观测每一跳收到的文本而**不执行调用**，由接收方自己的解析器（而非字符串比较或 LLM 裁判）判定动作是否改变，并命名第一个分歧跳。经变异测试（297 个变异体中 Bash 行为不同的 262 个全部检出）和故障注入（30/30 正确命名故障跳）验证；对比人工标注 κ=0.77（路径归因）/κ=1.00（动作改变，115/115），零 LLM token，而 Who&When 三个评委每个失败要花 2.04 万–4.26 万 token。
- **解决方案 IntAct 及验证：** 在协议命名的跳上"改道"——把调用渲染进该跳不解析的通道（source 文件、参数向量、stdin、`-EncodedCommand`），无法安全送达则拒绝并报告该跳。恢复 137/173（79.2%）带改动调用的丢失对，对照组（187 个无改动调用的丢失对）恢复 0（Fisher p<.001）；4 个 LLM 在 6 条传输路径上 pass@1 全部提升（合并 McNemar p≤.001）；已部署于生产会话与某公司桌面 agent 执行内核（197 个先前被改的中继调用修复后为 0）。

## Key Contributions

- **Problem and finding:** Defines intent-execution correspondence (IEC) for tool calls and chains of dependent calls, and shows that a hop that changes a call *hides* changes after it — on a path with 2 such hops, 38 of 69 path-caused failures appear only after the first hop is repaired, so single-hop observers systematically undercount.
- **First real-world measurement:** Over 47,828 shell calls in 261 production sessions (plus 203,710 public trajectories), 10.0% of the 11,982 "exposed" Windows calls change in replay; Claude Code's Bash launch changes 12.0% (67.0% of calls carrying a backslash pair), 80.7% of changed-backslash calls execute the wrong action with no reported error, and all 10 harnesses and 10 of 22 MCP servers change calls while reporting success.
- **Evaluation method (IEC protocol):** A witness observes each hop without executing the call; the receiver's own parser decides whether the action changed; the protocol names the first divergence hop. Validated by mutation testing (262/262 behavior-changing mutants detected) and fault injection (30/30 localization), achieving κ=0.77 with human labels on failure attribution at **zero LLM tokens**, versus Who&When judges at κ≤0.04 costing 20.4k–42.6k tokens per failure.
- **Solution IntAct, deployed:** Recomposes the call into a channel the named hop does not parse (rendering condition), or refuses it. Recovers 79.2% of IEC-Bench losses with a changed call (0 of 187 controls, Fisher p<.001), raises pass@1 for every LLM on every launch (pooled exact McNemar p≤.001), cuts token cost per passed task 2.4×, and ships as a Claude Code mod (4 ms/call, 227/227 production calls rerouted), a commercial desktop-agent kernel, a shell shim, and an MCP server.

## Methodology

**Concepts.** A call's *intended action* a is what the emitted text denotes under the tool contract (the receiver's language semantics), not the LLM's goal. A *launch*'s *execution path* Π = (h1,...,hn) is the hops the call traverses (tool serialization → host wrapper → shell parse → process interface → target parser). IEC holds when every hop receives the intended action; the *first divergence* FD(a,Π) is the first hop whose received action r_i ≠ a. A divergence is *silent* when the returned tool result contains neither an error flag nor a quoting/encoding message. In a chain, an earlier call's change propagates, so even a late, verbatim call can yield a wrong answer.

**Witnesses (observation without execution).** For Bash, the witness is a file sourced via BASH_ENV that parses the command string without executing it; for PowerShell 5.1 launches (append after `-Command` vs. one-argument), the witness computes the script that powershell.exe builds by its own documented command-line rules; at the process interface, an argv probe replaces the target program and native invocations are run with constant arguments; ancestor processes give the wrapper of a running harness. The verdict uses the *receiver's own parser*: comparison of operators, words, heredoc bodies of the Bash command, the parse tree of the PowerShell script, and the argument vector — string equality alone misclassifies 15 of 35 unchanged pairs (e.g., `a\b` vs `a\\b` denote the same word). The comparisons return a verdict for 99.98% of the 32,259 Bash calls of the production sessions.

**Attribution.** The protocol first parses the agent's text with execution disabled: text that does not parse was a *generation error* when emitted; text that parses is re-delivered through the witnesses, and any difference is attributed to the *path*; an error beyond the end of the agent's text (in the appended wrapper) is also the path; text that parses, arrives intact, and invokes a further interpreter falls at a *nested hop*. This is why a loud failure can still be path-caused.

**IntAct (repair at the named hop).** Input: the path Π, named hops H, call text x. If x is outside the *domain* of renderings for H (e.g., multi-line text under `cmd.exe`, which ends commands at the first line break), IntAct *refuses* and names the hop — the refusal is the only outcome that preserves IEC. Otherwise it renders the call into a channel the named hop cannot alter: native per-argument quoting for the process interface (Eq. 1, with backslash-doubling and quote-escaping rules for PowerShell 5.1), Base64/UTF-16 `-EncodedCommand` or a sourced file for the host wrapper, and a typed command that switches off history expansion and completion for the interactive-Bash shell parse. The repair changes the channel, not the call itself: cwd, environment, exit status, and side effects stay those of the original launch, and the selection uses only Π, H, x — no per-call measurement.

**IEC-Bench and setup.** 67 pattern pairs (hazard variant vs control differing in one literal, e.g., a space, backslash, quote), 10 multi-line programs, 135 ToolHop chains (3–7 steps drawn from 990 ToolHop queries needing quoting), 46 Terminal-Bench 2 tasks paired across 6 transports (direct JSON, Git Bash from a file, Claude Code Bash, Qwen Code cmd.exe, PS 5.1 one-argument, PS 5.1 appended). Four LLMs (qwen3-coder-plus, Qwen2.5-Coder-32B/72B, Hermes-3-Llama-3.1-70B) at temperature 0; plus fix/commit tasks with 15 LLMs from 4 vendors. Attribution baselines: 3 Who&When judges (all-at-once, step-by-step, binary search) on Qwen2.5-72B, Causal Agent Replay, QuoteBench's fixed replay, and 4 ablations of the protocol; human reference: 102 failures + 115 pairs double-labeled (κ 0.79/0.89). Repair baselines: QuoteBench's temp-file and boundary-disclosure repairs, structured feedback (Gupta et al.), and Reflexion.

## Results & Highlights

- **Real-world frequency (RQ1):** 1,199 of 11,982 exposed production calls change (10.0% changed-call rate); Claude Code's Bash launch changes 12.0% of its 7,491 exposed calls — 67.0% of calls with a backslash pair and 10% of calls ≥8,000 characters — and 80.7% (535 of 663) of changed-backslash calls run the wrong action with *no* reported error; a changed call occurs in 65 of 199 sessions (32.7%). On IEC-Bench, changed calls turn 2.4× more tokens per passed task on the original launch (12.3× for chains on the appended launch, 7.9× for pairs, 4.0× on Claude Code's Bash launch).
- **Attribution accuracy (RQ3, Table 5):** The IEC protocol attributes 54 of 56 reference path-caused failures correctly (κ=0.77) and agrees on all 115 action-change pairs (κ=1.00), at 0 LLM tokens; the all-at-once WhoWhen judge attributes 97 of 102 failures to the LLM (κ=0.00, 20.4k tokens/failure) and step-by-step/binary judges reach κ≤0.04 (37.8k/42.6k tokens); the no-witness ablation (error message alone) is near chance (κ=0.00). Trajectory-based judgment thus blames 95.1% of production failures on the LLM, though the path caused more than half (306 of 426 parse errors are path-caused per IEC, vs 84 generation, 36 nested). Causal Agent Replay detects nothing on shell-only losses; QuoteBench's fixed replay agrees at 0.73 but detects only 37.2% (51/137), including *none* of the 48 losses at the process interface.
- **Repair effectiveness (RQ4):** With recorded actions held fixed, IntAct recovers 137 of 173 lost pairs with a changed call (79.2%; per-launch share 68.6%–90.9%) and 0 of the 187 lost pairs without a changed call (Fisher p<.001); on the appended launch, repairing the process interface alone recovers 0 of 69 and the wrapper alone 31, versus 69 for both hops. With the agent in the loop (Table 7), IntAct raises pass@1 for every LLM on every launch — pooled over the 2 Qwen2.5 LLMs, +30 pairs on the one-argument launch (104→129) and +81 pairs / +7 chains on the appended launch (26→127, 9→74), p≤.001 by exact McNemar (Claude Code Bash p=.007); QuoteBench's temp-file repair gains nothing on the appended pairs (26→26), boundary disclosure recovers 38.9%–87.5% of IntAct's gain, and Reflexion with 1 trial reaches only 39–155 of IntAct's 129–181 while needing 22–913 retries per cell on 10 trials.
- **Score distortion (RQ2, Figure 4):** Qwen2.5-72B answers 29 more chains than Hermes-3 under direct JSON calls, but falls 3 chains *behind* on the PowerShell launches — and 4 ahead again once IntAct repairs them, i.e., the launch, not the LLM, reverses a model ranking. 737 of 1,165 calls of qwen3-coder-plus change on the appended launch (666 at a value containing a space); a changed call usually breaks the chain at its first step (483 of 524 affected chain-runs; argument parser rejects in 492).
- **False completion and cost of retry:** 565 of 949 failed hazard-variant runs report completion (70.1% false-confirmation rate); in the commit task, all 13 LLMs write a syntactically correct `git commit` but only 1 of 39 runs commits the intended message (19 end in false confirmation). In production, retries recover 162 of 306 path-caused failures in 2–8 steps, abandon 30, and never recover 114; each eventually-successful call costs 3.9× the tokens of one clean request.
- **Validation and deployment:** Fault injection (168 injections over 24 payloads × 7 faults × 5 hops): 30 change what the target receives, and the first divergence names the faulty hop in all 30 and none of the other 138. In deployment, the Claude Code mod reroutes all 227 would-change production calls at 4 ms each, and the commercial desktop-agent kernel eliminates 197 of 9,932 previously-changed relayed invocations to 0; the four release forms add 2.1–396 ms per call.

## Authors & Credibility

The author group spans Yanshan University, Zhejiang University, Nanjing University, and Aalto University, with Haoye Tian (Yanshan University) as corresponding author — a researcher known for work on automated program repair (co-author of the ACM TOSEM survey of LLM-based automated program repair, cited as ref. [52] of this paper). The project is released under the GLEAM-Lab GitHub organization (intact-bash-mod), and the paper reports deployment both in the authors' own production sessions (consented, hashed) and inside a company's Windows desktop-agent execution kernel, which suggests real engineering access rather than a purely academic simulation. The measurement methodology (mutation testing, fault injection, double-annotated human reference with reported κ, exact McNemar/Fisher statistics) reflects software-engineering empirical-strength conventions, and the paper includes an unusually concrete Threats-to-Validity section. Potential caveat: the production corpora come from the authors' own company context, which motivated the "exclude the project of this study" rule but is not independently auditable.

## Critical Assessment

**Novelty.** The core move — deciding whether a call "changed" by the *receiver's own parser* rather than string equality or an LLM judge — is genuinely new and correct: the paper shows string comparison misclassifies 15 of 35 unchanged pairs (`a\b` vs `a\\b`). The finding that a changed hop *hides* downstream changes (38/69 failures invisible until the first hop is repaired) is the most intellectually valuable result and directly indicts single-hop designs like QuoteBench. Prior work (QuoteBench's 1-hop wrapper on 56 tasks; Who&When's trajectory-only view; ToolBench-X's visible hazards) is fairly characterized and the deltas are quantified, not asserted.

**Rigor.** Strong overall: mutation testing (262/262 detected), fault injection (30/30 hop localization), a double-annotated human reference (κ 0.79/0.89), exact McNemar and Fisher tests, and — rare in this literature — a *negative control* (187 lost pairs without a changed call: 0 recovered, p<.001), which shows the repair fixes the named cause rather than anything. But there are real weaknesses. First, the **attribution baselines are somewhat soft**: the three WhoWhen judges were run with their released prompts/settings on Qwen2.5-72B, a model family none of them targeted, and κ≤0.04 reads partly as out-of-domain deployment rather than a fair ceiling; the strongest comparison is QuoteBench's fixed replay (κ=0.73), which the paper's own framing buries. Second, the **main IEC-Bench LLM pool is entirely Qwen/Hermes-family** — no Claude, GPT, or Gemini model runs the 6-transport benchmark (frontier vendors appear only in the 15-LLM fix/commit tasks), yet the paper's conclusion ("harnesses, not LLMs, establish IEC") is about LLM agents generally. Third, the headline **12.0% is conditioned on the "exposed" subset** (11,982 of 47,828 calls carrying code, escapes, or ≥1,000 chars); the abstract states this correctly but invites overreading to all calls. Fourth, the effect is **heavily Windows-shaped**: on Linux, 4 of 10 harnesses change none in 80 runs, and the dramatic silent-change mechanisms (PowerShell quote consumption, cmd.exe line break, MSYS2 backslash collapse) have no macOS/Linux analog outside typed-interactive-Bash harnesses — a Linux/Mac user's agent may see roughly none of this, which the paper reports honestly (Table 2/3) but the abstract's "All 10 measured harnesses change a call" flattens. Finally, the human reference is small (102 failures, 115 pairs) and, as the authors concede, annotators could have absorbed the IEC protocol's own conventions, slightly circularizing the κ=0.77.

**Reproducibility.** Mixed. IntAct and IEC-Bench are released (Claude Code mod on GitHub, plus shim and MCP server forms), and the benchmark construction (pattern pairs, ToolHop chains, Terminal-Bench 2 pairing, transports) is specified in enough detail to rebuild. However, the RQ1 measurement — arguably the paper's centerpiece — rests on non-public, hashed production corpora from a company context, so the 10.0%/12.0%/80.7% numbers cannot be independently re-derived; the public-trajectory analysis (203,710 runs, history expansion in 2,546 traces) is a partial, weaker substitute. There is no test framework or benchmark harness release mentioned for the witness stack across all 10 harnesses.

**Significance & red flags.** If the numbers generalize, benchmark practice is directly implicated: any leaderboard score taken under an unrepaired launch conflates model quality with path corruption (Qwen2.5-72B's 29-chain lead over Hermes-3 inverting to a 3-chain deficit under PowerShell is a memorable demonstration), and "harnesses should report and hold their launch fixed" is an actionable, cheap recommendation. Red flags to keep in view: the repair set is hand-engineered per launch/hop (Table 1 — one row per known launch), so coverage follows the authors' engineering effort, not a principle; refusals are unavoidable in a nontrivial part of the domain (multi-line under cmd.exe, CRLF, target-parser faults — 13 of 30 injected faults ended in refusal) and the agent-in-the-loop cost of refusals is not separately scored; and "we exclude the project of this study" is the only hygiene statement about the production data.

## Strengths

- Grounded in reality: 47,828 production calls, 261 sessions, 10 harnesses, 22 MCP servers, 4,356 public leaderboard trials, and 203,710 public trajectories — the problem is measured where it hurts, not synthesized.
- The IEC protocol is deterministic and LLM-free: zero tokens per failure, 0.1 s per Bash witness call, and receiver-native semantics that correctly handle escaping equivalence (a subtle point most prior work gets wrong by string comparison).
- Negative controls and statistical discipline: 0/187 recovery on changed-call-free pairs (Fisher p<.001), exact McNemar for pass@1, same-trials comparison for retry baselines.
- The "changed hop hides later changes" finding is a conceptual contribution that re-frames why single-hop monitors and trajectory judges systematically mis-attribute failures.
- End-to-end engineering credibility: four deployed forms, per-call overhead measured (2.1–396 ms), and the commercial kernel deployment (197 → 0 changed invocations) demonstrates the fix survives contact with production.
- Honest, granular reporting: per-hop/per-harness tables, explicit non-results (evidence-about-the-change ablation gains nothing, p≥.500), and a threats section that addresses construct validity of the witnesses themselves.

## Limitations

- The effect is concentrated on Windows launches (PowerShell 5.1, cmd.exe, MSYS2 Git Bash); on Linux only typed-interactive-Bash harnesses (Terminus-2, KIRA) change calls, so the 10–12% headline does not transfer to POSIX-only setups.
- Main IEC-Bench scores use 4 Qwen/Hermes-family models only; no frontier closed-model results on the 6 transports, leaving the generality of the score-distortion claim across model families untested on the main benchmark.
- Human reference is small (102 failures / 115 pairs, 2 annotators) and possibly convention-aligned with the IEC protocol itself.
- Production corpora (the 47,828-call measurement) are hashed company data and not released, so the flagship real-world numbers are not independently reproducible.
- IntAct's renderings are hand-specified per launch and hop; each new harness/launch needs new engineering, and a nontrivial slice of calls must be *refused* rather than delivered (multi-line text under cmd.exe), which shifts cost onto the agent rather than eliminating it.
- The protocol requires a parser per receiver; hops without one (some MCP backends, e.g., the fetch server turning backslash into slash, filesystem `a→b` writes) are only partially covered, and the authors note IEC-Bench must grow as new changes are observed.
- Only shell-family tools plus structured JSON tools are evaluated; interactive tools, browsers, and long-running processes are out of scope (authors plan typed-terminal launches next).

## Relevance

这篇论文与你"自主 agent 系统的可靠性与可信性"这一最高优先级方向高度吻合，同时恰好落在"Inference Reliability & SDC Detection"的核心命题上：它研究的正是**基础设施（执行路径）造成的、无报错的静默输出损坏**——只是损坏对象从比特和内存换成了工具调用文本，并给出了"检测协议 + 确定性修复"的完整闭环。对于任何用 Claude Code/Codex 类 agent 跑长任务的人（包括本 daily-paper pipeline 本身），其"逐跳观测、按接收方语义判定、修复或拒绝"的思路值得直接借鉴。

## Questions for Further Exploration

- Does intent-execution correspondence degrade frontier closed models (Claude, GPT, Gemini) the same way on the 6 transports, or do their harnesses already repair some hops?
- Can the witness mechanism be standardized (e.g., as an MCP-level contract) so hops self-report received text, removing the per-harness witness engineering?
- When does a *loud* divergence actually help the agent recover versus trap it — the paper shows retries recover only 162/306 production failures at 3.9× token cost; what policy best separates recoverable from unrecoverable path-caused failures?
- How should benchmarks combine "launch held fixed" reporting with the field's habit of comparing agents across heterogeneous harnesses — is there a standard harness specification waiting to be proposed?
- Do the same hidden-change dynamics exist for non-shell tools (browser automation, Python REPL state, database clients) where the "tool contract" is not a formal grammar?
