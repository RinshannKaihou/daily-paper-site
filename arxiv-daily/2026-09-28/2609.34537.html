01Methodology方法设计

paired live execution

620 verified problems from GPQA, SciBench, OlympiadBench and BixBench v1.5 (biology / chemistry / math / physics) are rebuilt by an LLM Task Planner into interdependent 3–13-turn tasks that follow the scientific reasoning structure — later turns consume earlier outputs, so cross-turn information reuse is mandatory. Each task ships as a matched clean / perturbed pair, dual-validated (LLM + human) for consistency, correctness and no reference leakage.

13 perturbation types are injected live, mid-trajectory — only at points where the corrupted information is provably reused downstream, and only before conclusion formation. The same agent then executes both versions under identical settings: fixed system prompt, temperature 0, 3 fresh repetitions per condition.

Metrics: end-to-end TACC plus per-turn IC (information correctness), TP (task progression), RV (reasoning validity); degradation Δ = Clean − Perturbed. Judged by a fixed evaluator blind to model identity, cross-checked by two human annotators (≥5 yrs research experience); disagreements conservatively count as incorrect.

05Strengths优势

  • Fills a real gap: trajectory-level robustness under non-adversarial, scientifically plausible perturbations — failures traced over time (onset → propagation → recovery), not scored only at the final answer.
  • Clean paired protocol: identical agent, settings and repetitions on both sides; perturbations fixed before execution and independent of the evaluated model.
  • The IC/TP decoupling is exactly the instrument that exposes silent failure — end-to-end accuracy alone would hide it.
  • Unusually strong quality control: dual LLM + human validation at both construction stages, two independent annotators, conservative disagreement handling, explicit AI-use disclosure.
  • Decision-relevant findings: capability–robustness decoupling and the 17.1% recovery rate directly challenge "bigger model = safer agent".

06Limitations局限

  • Single-type perturbations in the main evaluation (n=1, capped at 3); real long-horizon sessions accumulate heterogeneous corruptions simultaneously — untested.
  • No open-weights or sub-frontier models — the regime where most agentic deployments actually run.
  • No mitigation baseline (self-checking, consistency verification, re-derivation): the disease is quantified, not the cure.
  • LLM-heavy construction: generation counts, human-validation pass rates and inter-annotator agreement unreported — construction noise unquantifiable.
  • The judge is a defendant: Claude Opus 5 evaluates all models including itself; per-metric judge–human agreement not broken out.
  • Unreconciled numbers between main text and appendix (E1 clean-TACC comparison; frequency averages vs Table 14).
  • Narrow "agent": scripted multi-turn Q&A in a custom pipeline — no retrieval, code execution, or wet-lab action.

07Open questions待探索

from the paper's further-exploration list
Q1Can cheap defenses — forced re-verification of reused results, cross-turn consistency checks, calibrated uncertainty escalation — shrink the 82.9% persistence rate, and at what token / latency cost?
Q2Why does higher clean capability mean larger collapse (GPT-5.6 vs 5.5 under E1)? Stronger instruction-following on the corrupted premise — or overconfidence in fluent-but-wrong continuations?
Q3Do the dynamics — latent onset, propagation, 17.1% recovery — transfer to small open-weights agents, or are they a frontier-scale pathology?
Q4What happens when heterogeneous perturbations co-occur (E3 data corruption + R1 inconsistency), as they would in real research sessions?
Q5Would tool-grounded corruption — a bad database row, a miscalibrated instrument reading — reproduce the same failure profile as user-turn injection?
Q6Can the IC/TP "silent failure" signature be detected online from the agent's own trajectory statistics — turning this diagnostic into a runtime monitor?
