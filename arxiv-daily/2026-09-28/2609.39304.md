> **一句话总结：** 用一个优化器 Agent 自动进化视觉接口机器人 Agent 的 harness(提示词、工具、控制规则),并通过系统实验证明:进化是否可靠取决于两个杠杆——每轮决策背后的 rollout 规模(训练集从 5 扩到 100, held-out 成功率从 47% 升到 67%, 小批量会过拟合: B=10 训练分 70% 但 held-out 仅 54%)和选择规则(无条件接受修订在 10 轮内性能从 42% 漂移跌到 34%, 而最朴素的 Champion–Challenger 规则让同一循环 30 轮内 held-out 从 51% 升到 67%)。

> **TL;DR:** An optimizer coding agent (Codex + GPT-5.6 Sol) automatically rewrites the harness — prompts, MCP tool semantics, control and verification rules — of a visual-interface robot agent running on 10 robosuite/LIBERO tabletop tasks, with no model training. Two controlled studies: (1) with rounds fixed at 30, growing the per-round rollout budget B from 5 to 100 lifts final-champion held-out success on 100 disjoint LIBERO rollouts from 47% to 67% against a 51% hand-written baseline, while B=10 overfits (70% training, highest of any campaign, but only 54% held-out); (2) accepting every proposed revision unconditionally drives training success from 42% down to 34% within 10 rounds at B=100 (and 40%→0% at B=5), whereas Champion–Challenger selection — promote only on a strict win on the same fixed cases — turns the same loop monotone, 41%→60% on training and 51%→67% held-out. On RoboCasa kitchen tasks the baseline fails almost completely (2/100) and two promoted revisions raise it to 37/100; swapping the task-agent model from GPT-5.6 Sol to the stronger GPT-6 Astra (never seen during evolution) yields 83/100, so the harness gain is not absorbed by a better model.

## 核心贡献

- **首次将 harness 自动进化带入视觉接口机器人 Agent**:任务 Agent 是未经修改的编码 Agent(Codex + GPT-5.6 Sol),通过浏览器 3D 界面截图 + 少量 MCP 工具操纵虚拟目标夹爪控制仿真机械臂;优化器 Agent 读取 rollout 证据后对 harness(提示词、工具集与语义、控制规则、验证/终止逻辑)提出单次有界修订,两个模型均不训练。严格 train/test 划分下,30 轮进化使 held-out 成功率从 51% 升至 67%。
- **Rollout 规模决定可信度、泛化性与稳定改进**:固定 30 轮,训练集从 5 → 10 → 20 → 100 rollouts,最终冠军的 held-out 成功率为 47% / 54% / 51% / 67%(基线 51%);小批量不仅帮助有限还会过拟合——B=10 的冠军拿到全系列最高训练分 70%,held-out 却只有 54%;21 个评测节点上训练分与 held-out 分的相关系数仅 0.60,且几乎全部由 B=100 节点贡献。
- **优化器 Agent 不能被放任自流**:无条件接受每条修订时,训练成功率在所有批量下都先升后降(B=100: 42%→峰值 47%(第 5 轮)→34%(第 8 轮);B=5: 40%→0%),因为幸运批次上的错误修订会永久留在提交链上;Champion–Challenger(仅在相同固定案例集上严格胜出才晋级)过滤掉了 22/30 个不优于冠军的修订,使同一循环在 30 轮内单调改进。
- **跨环境与跨模型迁移验证**:在优化过程从未见过的 RoboCasa 厨房环境(10 任务 × 10 seeds),同一循环 2 轮内把基线的 2/100 提升到 37/100;用更强的 GPT-6 Astra 替换任务模型后,harness 增益反而扩大(+46 分 vs 在 Sol 上的 +35 分),说明收益不是对特定模型的过拟合。
- **把"每轮 rollout 规模"和"修订选择规则"从固定流程参数提升为研究对象**,回应了近期关于 harness 进化收益在匹配预算与 held-out 任务下常常消失的批评。

## Key Contributions

- **Automatic harness evolution for a visual-interface robot agent.** The task agent is an unmodified coding agent (Codex with GPT-5.6 Sol) controlling a simulated manipulator through screenshots of a browser-based 3D interface and a few MCP tools; an optimizer agent reads full rollout trajectories and proposes one bounded harness revision per round (prompt, tool semantics, control rules, verification logic), with neither model trained. On a strict train/test split, 30 rounds raise held-out success from 51% to 67%.
- **Rollout scale governs trust, generalization, and steady improvement.** With rounds fixed at 30, final-champion held-out success goes 47% / 54% / 51% / 67% for B = 5 / 10 / 20 / 100 (baseline 51%); small batches actively overfit — the B=10 champion posts the highest training score of any campaign (70%) but only 54% held-out, and across 21 evaluation nodes the training-vs-held-out correlation is just 0.60, carried almost entirely by the B=100 nodes.
- **The optimizer agent must not be given free rein.** Unconditional acceptance degrades at every batch size (B=100: 42%→34% within 10 rounds; B=5: 40%→0% within 20) because ill-judged edits on lucky batches are baked into a single commit chain; Champion–Challenger selection — promote only if the challenger strictly beats the incumbent on the same fixed cases — rejects 22 of 30 challengers at B=100 and turns the same loop monotone (41%→60% training, 51%→67% held-out).
- **Transfer checks.** On RoboCasa kitchen tasks (unseen during development), the identical loop lifts the baseline from 2/100 to 37/100 in two promoted rounds; re-running the evolved harness under the stronger GPT-6 Astra (never used during evolution) reaches 83/100, so the harness gain survives — and grows — under a model swap (+46 points under Astra vs +35 under Sol).
- **Reframes two fixed procedure knobs — per-round rollout scale and the revision-selection rule — as the variables under study**, directly engaging recent critiques that reported harness-evolution gains often vanish under matched budgets and held-out tasks.

## Methodology

**Setting.** The system is the visual-interface robot agent of Hu et al. (VIA): an off-the-shelf coding agent (Codex with GPT-5.6 Sol at highest reasoning effort) observes a browser-based 3D interface via screenshots and acts by calling a small set of MCP tools that pose a virtual target gripper, execute waypoints, and end the episode. The *harness* — system prompt and operating guide, MCP tool set and per-tool semantics (e.g., max translation per call), post-call observations, waypoint staging/control rules, and verification/termination logic — is ordinary code and text in the agent's repository and is the sole object of optimization. The task-agent model, simulator, task set, success detectors, and evaluation control plane are frozen.

**The evolution loop (Algorithm 1).** Each of T=30 rounds: (1) *Evaluate* the champion harness H_t on a fixed training sample D of B (task, seed) cases — each case is one full agentic rollout capped at 30 minutes wall-clock with a binary success verdict from the task's built-in detector; (2) *Collect evidence* — a manifest retaining the complete trajectory of every case (ordered model turns, tool calls, controller feedback, errors, verdicts, runtime stats); (3) *Propose* — a separate persistent optimizer session (same model) must identify one systemic, task-general failure mechanism and implement it as a single commit that leaves the evaluation control plane untouched and passes the repo's test suite (violations are returned for repair); the optimizer also sees reasons for recently rejected challengers; (4) *Select* — the challenger runs on the same B cases and a selection rule decides promotion.

**Experimental variables.** (a) Batch size B ∈ {5, 10, 20, 100}, each an independent campaign with its own optimizer session, branch, and result namespace (no information sharing). (b) Selection rule: unconditional acceptance (every revision becomes the next base — a single commit chain) vs Champion–Challenger (promote iff s(H_t′) > s(H_t) on the same fixed cases; ties and regressions are logged and discarded). Held-out performance (100 rollouts on 10 disjoint LIBERO tasks, 10 seeds each) is measured once, only after a campaign finishes, and never visible to the optimizer. Training tasks: lift/square/stack from robosuite plus 7 LIBERO tasks (Object, Goal, Spatial, 90, 10 suites); B=100 uses 10 seeds × 10 tasks. For each campaign, 5 harnesses (final champion + 4 from promoted/rejected challengers at different rounds) are evaluated held-out, giving 21 nodes total. Rollouts run concurrently in isolated sandboxes, so a B=100 evaluation takes about one episode of wall-clock time. A 4-round RoboCasa campaign (10 kitchen tasks × 10 seeds, no held-out set) tests environment transfer, and a harness×model cross-table (GPT-5.6 Sol vs the newer GPT-6 Astra) tests model transfer.

## Results & Highlights

- **Held-out success rises monotonically-ish with rollout scale.** Final champions of 30-round Champion–Challenger campaigns reach 47% (B=5), 54% (B=10), 51% (B=20), and 67% (B=100) held-out, against 51% for the hand-written baseline — a +16-point gain only at B=100, where all five held-out nodes are at or above baseline (three by 13–16 points); five-node means are 44.6% (range 35–49), 51.4% (48–54), 52.8% (50–55), and 61.0% (51–67).
- **Small batches overfit, not merely underperform.** The B=10 campaign's round-27 champion has the highest training score of any campaign (70% — 7 successes out of 10 fixed cases) yet only 54% held-out; the B=5 champion doubled its training score (20%→40%) yet all five of its held-out nodes sit below the 51% baseline, one by 16 points. Across all 21 nodes, training and held-out scores correlate at 0.60, and the correlation is carried by the B=100 nodes.
- **Larger batches also promote more.** Promotions in 30 rounds: 1 (B=5, promoted once at round 3 and rejected the remaining 27 challengers), 3 (B=10), 2 (B=20), 8 (B=100, at rounds 1, 7, 16, 18, 19, 23, 25, 29 — still improving when the campaign ended). With 5–10 cases most challengers tie the champion exactly and are rejected; with 100 cases a genuine few-point improvement registers as a strict count increase.
- **Unconditional acceptance drifts downward; Champion–Challenger is monotone.** Under unconditional acceptance, training success peaks then falls at every batch size: B=100 goes 42% → 47% (round 5) → 34% (round 8) → 38% (round 10); B=20 falls 40%→15% within 20 rounds; B=10 30%→10%; B=5 40%→0%. Under Champion–Challenger at B=100, training success climbs 41%→60% by round 29; 22 of 30 challengers scored at or below the champion, showing most proposals would have been regressions. Across the 20 evolved held-out nodes, promoted harnesses average 54.0% vs 50.9% for rejected ones — modest, but consistent with training gains being real rather than fits to fixed cases.
- **RoboCasa transfer: near-total failure to respectable in two rounds.** The tabletop-tuned baseline harness succeeds in 2/100 RoboCasa kitchen rollouts; two promoted revisions raise it to 26/100 then 37/100, and the next two challengers (28/100, 33/100) are correctly rejected. Crossed with models on the same 100 cases: baseline+Sol 2, baseline+Astra 37, evolved+Sol 37, evolved+Astra 83 — the harness is worth +46 points under the stronger Astra, more than its +35 under Sol, so its gains are not absorbed by a better model.

## Authors & Credibility

Zhijie Wei, Ferris Tan, and corresponding author Jinghui Wang are with **Novaxbot** (robotics company), an industry affiliation rather than an academic lab; no prior-publication list or external funding statement is given in the paper. Credibility signals are mixed but leaning positive: the work builds directly on the published VIA system (Hu et al., arXiv 2607.11119) and standard benchmarks (robosuite, LIBERO, RoboCasa), uses frozen success detectors and a strict train/held-out task split, and — notably — engages honestly with recent critical literature on harness-evolution evaluation (Jiang et al. on LIBERO significance; Wang et al. on gains vanishing under matched budgets), which suggests methodological self-awareness. The paper is short (12 pages including references), reports no code release, and depends on proprietary frontier models (GPT-5.6 Sol, GPT-6 Astra via Codex), which limits independent verification. The experimental design itself (fixed seeds, per-campaign isolation, held-out measured once post-campaign) is sound for the scale at which it operates.

## Critical Assessment

The paper's strength is its framing — treating rollout scale and selection rule as the experimental variables — but the execution has real weaknesses. **Most seriously, each batch size is a single campaign.** The headline ordering 47% / 54% / 51% for B = 5/10/20 is not monotone and comes from one 30-round run per B; given the paper's own point that single outcomes are noisy, campaign-level variance (different optimizer sessions propose different edits) is unquantified, so the safest conclusion is the coarse one — "B=100 clearly works, smaller B clearly doesn't" — rather than any trend among 5/10/20. The five held-out nodes per campaign mitigate but do not solve this, since they share one optimization trajectory. Second, **the selection rule is compared only against the weakest possible alternative.** Champion–Challenger with a raw strict-greater-than count on 100 binary rollouts still promotes revisions on luck (a ~2–3 point flip is well within binomial noise), and the authors — who cite Jiang et al.'s finding that most LIBERO improvements are not statistically significant — apply no significance testing or threshold to their own promotions; a paired test or minimum-margin rule is the obvious missing ablation. Third, the **unconditional-acceptance runs were stopped early** (10 rounds at B=100, 20 otherwise) "once the downward trend was clear," an asymmetric protocol relative to the 30-round Champion–Challenger runs. Fourth, generality is narrow: held-out evaluation uses only 10 LIBERO tasks (with robosuite in training), the RoboCasa result has no held-out set at all, and everything is simulation with parallel rollouts — the authors themselves concede that the B=100-per-decision scale they argue for is exactly what a real robot cannot afford. Finally, the scaling curve stops at B=100 while still rising, so the claim "rollout scale governs quality" rests on essentially two regimes (tiny vs large), and Champion–Challenger is standard practice being presented as a finding. That said, the core negative results (small-batch overfitting; unconditional drift) are clearly demonstrated and practically valuable.

## Strengths

- **Clean, well-motivated experimental design:** fixed (task, seed) cases reproducible across rounds and harness versions; frozen models, detectors, and control plane; held-out measured once post-campaign and never visible to the optimizer; per-campaign isolation of optimizer sessions and branches.
- **The two findings are actionable and quantified:** batch size and selection rule are the two knobs a practitioner actually controls, and both effects are shown with concrete numbers (47%→67% held-out across B; 42%→34% drift under unconditional acceptance vs monotone improvement under Champion–Challenger).
- **Honest negative results:** the paper shows its own method failing at small B (B=5's champion doubled training score yet landed below baseline held-out) and shows that 22/30 optimizer proposals at B=100 were regressions — a useful calibration of how unreliable optimizer-agent proposals are.
- **Two transfer checks beyond the headline:** an environment transfer (RoboCasa, 2/100→37/100 in two rounds) and a model transfer (evolved harness + GPT-6 Astra reaches 83/100, with the harness worth *more* under the stronger model), which addresses the natural "is this just overfitting to one model's failure modes?" objection.
- **Engages the critical evaluation literature** on harness evolution rather than ignoring it, and states its own limits (scaling untested beyond B=100; simulation-only) explicitly.

## Limitations

- **One campaign per condition:** no replicates across optimizer sessions, so campaign-level variance is unknown and the non-monotone 47/54/51 ordering at small B is within noise; conclusions are only robust at the coarse B=100-vs-small contrast.
- **No statistical treatment of promotions:** strict-greater-than on 100 binary rollouts admits lucky flips; no significance test or promotion margin, despite the paper citing work showing exactly this pitfall on LIBERO.
- **Asymmetric stopping:** unconditional-acceptance runs stopped at 10 (B=100) or 20 rounds on visible downward trend, versus full 30-round Champion–Challenger runs.
- **Narrow evaluation surface:** held-out is 10 LIBERO tasks only; RoboCasa reports training-sample numbers with no held-out set; success is a binary built-in detector with no partial-credit or efficiency/cost reporting (30-minute cap per rollout).
- **Simulation-only and expensive:** the argued-for rollout scale (100 rollouts per decision, plus challenger evaluations per round) is infeasible on physical hardware, and the paper does not test cheaper proxies (e.g., adaptive batch sizes, historical-case reuse across rounds — each round re-evaluates the same B cases from scratch).
- **Reproducibility:** no code or harness-artifact release; results depend on proprietary Codex/GPT-5.6 Sol/GPT-6 Astra behavior that will change over time.

## Relevance

这篇论文与你排名第一的研究方向"Self-Evolving Agents & Automated Research"高度吻合:它正是"自进化 LLM Agent + 长时自主系统的可靠性"这一交叉命题——用优化器 Agent 自动改写另一个 Agent 的 harness,并系统回答了"多少证据才够支撑一次自主修改、该用什么规则接受修改"这两个决定自进化循环是否可信的问题。其"小批量过拟合、无选择规则则性能漂移"的负结果,对任何设计长周期自主改进循环(包括自动化科研循环)的人都有直接参考价值。

## Questions for Further Exploration

- Would a **statistically grounded promotion rule** (paired significance test on the 100 fixed cases, or a minimum-margin threshold) further improve over raw strict-greater-than Champion–Challenger, or would it stall promotion frequency the way small batches do?
- Can the **same B fixed cases be reused across rounds without re-evaluation** (caching per-case outcomes and re-running only affected cases), cutting the per-round cost that currently makes B=100 the practical ceiling?
- Does the B-scaling result hold with a **weaker or open-weights task-agent model**, whose failure modes (and hence the evidence available to the optimizer) differ qualitatively from GPT-5.6 Sol?
- What happens **beyond B=100** — the curve was still rising at the largest affordable batch; where does held-out success saturate, and is there a batch size above which optimizer proposals start diluting (too much evidence per proposal)?
- How does the loop behave under **distribution shift within evolution** — e.g., training cases that drift over rounds — given the current design freezes the same B cases for all 30 rounds, and does the champion's monotonicity survive non-stationary evaluation sets?
- Can the findings transfer to **physical robots** via cheaper surrogates (shorter partial rollouts, off-policy trajectory reuse, or sim-to-real evalibration), or is per-decision rollout scale fundamentally the binding constraint on real hardware?
