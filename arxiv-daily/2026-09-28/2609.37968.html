Yields an agent solving 82.0% (73/89) of Terminal-Bench 2.1 — tying Codex, the top scorer among nine public harnesses. Evaluation-guided baselines paid 13–53% more for comparable or worse results.

Why this matters

Answers a key question for self-evolving agents: can the self-modification process itself — not external rewards — drive sustained improvement?

“Episode records as experience signal” directly informs the self-improvement stage of autonomous research loops.

Critical edge

Every configuration is a single search run — no seeds, no variance, no significance tests. Several ±1–3 pp deltas sit inside binomial noise (±4–5 pp), one lineage outright regresses (68.3→66.7), and “all six improve” partly rides on lineage averaging.

In one GPT ablation cell, the fixed-improver variant (75.8) even beats full SelfSearch (75.0). Treat 1–3 pp cells as provisional.

01 Methodology

SelfSearch treats the agent’s own revision history as its only search signal. From a repository agent B₀ — instructions, tools, and execution loop, with model weights frozen — each episode k hands the agent an editable copy of its repo plus read-only episode records Eₖ from every prior attempt: reasoning trajectories, tool calls, code diffs, check results. It decides what to change, edits itself, and verifies its work.

(Bₗ₋₁, eₖ) = SelfImprove(Bₖ; Eₖ, d)

Two lineages run 10 generations in parallel: capability (spot ability gaps → build reusable tools) and adaptive (improve the revision strategy itself), each able to adopt the other’s tools. Search runs in isolated, network-less containers; agents never see benchmark tasks or scores. Evaluation happens once, after search.

04 Strengths
  • Genuinely reward-free — a concrete, implementable mechanism (shared, read-only episode records) any repository-editing agent could adopt.
  • Evaluation matrix beyond a demo — 2 model families × 3 benchmarks, cost-matched head-to-head, cross-model transfer, ablations, generation-by-generation diffs.
  • Efficiency story is real — shared-success cost cuts (−8.7% to −38.5%) hold across benchmarks and model families, not just accuracy.
  • Mechanism made concrete — diff logs and traced examples (clipped records → text-search tool → Sphinx-task reuse) ground the “experience” claim.
  • Honest scoping — the paper itself names the single-run caveat and proposes hybridizing with evaluation-guided selection under one budget.
05 Limitations
  • Single run per configuration — no seeds, variance, or significance tests; ±1–3 pp deltas within noise; one lineage regresses (68.3→66.7 on Multilingual).
  • Weak baseline budget — evaluation-guided opponents use only a 10-task dev set; the Codex/Terminal-Bench comparison inherits a third-party evaluation rather than an in-house rerun.
  • Narrow domain — coding/terminal agents only, frozen model-tool loop; longer-horizon, non-coding domains unknown.
  • Asymmetric payoff — the evolving improver clearly helps DeepSeek but is marginal or negative in one GPT ablation cell.
  • No public code release identified in the main text — reproduction rides on appendix-described prompts and scaffolding.
06 Questions for further exploration
  1. How large is run-to-run variance — would 5 independent searches per configuration reproduce the population-mean gains, or do some regress?
  2. Under a matched total budget, does hybridizing SelfSearch with evaluation-guided selection dominate both pure approaches?
  3. Do episode records stay useful past 10 generations — is there a context/record-management bottleneck, and would summarization or pruning help or hurt?
  4. The evolving improver matters more for DeepSeek than GPT — do stronger improver models already internalize good revision strategies?
  5. Can the reward-free signal transfer beyond software engineering to scientific-discovery or research-automation loops, where evaluation is expensive or delayed?
