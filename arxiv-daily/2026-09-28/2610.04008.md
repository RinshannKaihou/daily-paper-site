> **一句话总结：** 港科大团队发布 SkillScriptBench——首个把"可执行 Agent Skill 包（SKILL.md + 脚本）"作为自进化单元的 350 任务基准（In-the-Wild 150 修复任务 + Controlled Repair 50 包×4 状态 200 任务），发现四家前沿 LLM 的全包修订虽然能修脚本却修不好文档（Doc 任务 Avg 仅 27.3%/23.2%，不高于纯 Markdown 基线的 27.0%）、还会破坏原本正确的行为；其提出的 AST-Guided Skill Revision 用 AST 节点和调用关系把维护需求锚定到具体代码位置、限制脚本编辑范围并同步对齐文档，在 4 个骨干模型上将整体修复成功率从 54.8%（Raw Package）提升到 76.7%（+21.9 pp）、从 48.8%（CoEvoSkills）提升到 76.5%（+27.7 pp），三次运行全过的任务占比最高提升 31.5 pp。

> **TL;DR:** SkillScriptBench is a 350-task benchmark (built from a survey of 35,554 GitHub Skill roots) that evaluates how LLM agents *revise existing executable Skill packages* — separating documentation repair, script repair, doc-script consistency, and preservation of already-correct behavior, which prior skill benchmarks (SkillsBench, SkillGenBench, SWE-Skills-Bench) do not distinguish. Across four backbones (GPT-5.5, GPT-5.6-Sol, Claude Opus 5, DeepSeek V4 Pro), full-package baselines (Raw Package 54.8%, CoEvoSkills 48.8% Overall Avg) fix scripts but fail documentation repair (27.3%/23.2% vs 27.0% for Markdown-only) and silently regress clean packages. The proposed AST-Guided Skill Revision stage — which grounds maintenance requests to AST nodes and call relations, restricts script edits to those targets, and aligns SKILL.md afterwards — lifts Overall Avg to 76.7% (+21.9 pp over Raw Package, 95% bootstrap CI [17.2, 26.3]) and 76.5% (+27.7 pp over CoEvoSkills, CI [22.9, 32.2]), while raising three-run all-pass consistency by up to +31.5 pp.

## 核心贡献

- **首个面向可执行 Skill 包自进化的基准 SkillScriptBench（350 任务）**：扫描 35,554 个 GitHub Skill 根目录，其中 4,981 个（14.0%）含 `scripts/` 或 `script/` 源码，最终选出 100 个可分发、可测试的包构建 150 个 In-the-Wild 修复任务；另用 50 个规范包 × 4 种匹配状态（Clean / 仅文档故障 / 仅脚本故障 / 双故障）构造 200 个 Controlled Repair 任务，支持包内对照。
- **实证发现"修得广 ≠ 修得好"**：跨 4 个骨干模型，能同时改文档和脚本的全包基线（Raw Package、CoEvoSkills）确实修复脚本与联合故障，但文档修复 Avg（27.3% / 23.2%）不优于纯 Markdown 修订（27.0%）；且在 Clean 任务上比 Markdown-only 平均低 7.8 / 3.7 pp——全包访问会破坏原本正确的行为。
- **AST-Guided Skill Revision 方法**：作为可叠加在现有修订方法之后的附加阶段，把维护需求经 AST 节点与 caller–helper 调用关系绑定到唯一代码位置，生成"修复目标 + 保持约束"的结构化反馈 R，限制脚本编辑只落在目标节点内，最后将 SKILL.md 对齐到修订后的实现。
- **大幅且一致的增益**：在 4 个骨干上全部指标同时提升；Doc 故障任务上 42.8% 的 task/run 对由失败转为成功，仅 0.8% 由成功转为失败；三次运行全部通过的任务占比（Hit³）在 In-the-Wild 上从 47.5%→65.0%（Raw）与 37.2%→64.0%（CoEvo）。
- **严格的评测协议**：行为测试 + 文档驱动执行双重验收，沙箱容器执行（无网络、非特权用户、512 MB 内存、35 秒超时），并用等价改写（20/20 通过、注释级伪修复 20/20 拒绝）和错误绑定对照（49/49 拒绝）校准行为检查。

## Key Contributions

- **A benchmark for executable skill self-evolution.** SkillScriptBench (350 tasks) is, per its Table 1 comparison, the only skill benchmark covering bundled scripts, skill refinement, doc–code consistency, and repair-and-preservation simultaneously — SkillsBench, SWE-Skills-Bench, SkillLearnBench, and SkillGenBench each cover at most two of the four.
- **An empirical finding on repair vs. preservation.** Full-package revision broadens repair coverage but does not consistently beat Markdown-only revision on documentation repair (27.3% and 23.2% vs 27.0% Avg) and damages clean-package behavior (mean 7.8 and 3.7 pp below Markdown-only on Clean tasks), motivating explicit separation of what must change from what must be preserved.
- **A structure-guided revision method.** AST-Guided Skill Revision converts requirement-level discrepancies into editable AST repair targets with preservation constraints, then aligns the Markdown — improving Overall Avg by +21.9 pp (Raw) and +27.7 pp (CoEvoSkills) across all four backbones, with all metrics improving for every backbone.
- **Calibrated, sandboxed evaluation.** Behavioral checks are calibrated with behavior-preserving rewrites and constructed faulty variants (100% correct verdicts in Table 8), and all execution runs in a network-disabled container, reducing false repairs and environment leakage.

## Methodology

**Benchmark construction.** The authors scanned 35,554 GitHub-hosted Skill roots (folders containing SKILL.md) and found 4,981 (14.0%) with source files under `scripts/` or `script/`; 100 packages with redistributable licenses and deterministically testable behavior were kept. The **In-the-Wild Repair** track injects script-level faults (parameter substitution, helper-call bypassing, default-value changes) observed in the survey into 100 packages, yielding 150 repair tasks across six application domains (Finance & Trading 35.3%, Software Engineering 30.7%, Content & Knowledge 10.7%, AI & Agents 10.7%, etc.) and languages (115 Python, 29 JavaScript, 3 TypeScript, 3 Shell). The **Controlled Repair** track takes 50 canonical packages and fixes the maintenance request while constructing four matched states: Clean (no faults, tests preservation), Doc (Markdown fault only), Script (script fault only), and Joint (both), giving 200 tasks partitioned into Single-Target (60), Multi-Target (45), and Cross-Call (45) repair scopes. Each faulty variant must fail task-specific checks while the reference implementation passes; fault and state labels are held out from method inputs.

**Evaluation framework.** A revised package passes only if *all* applicable checks in both families pass: (1) behavioral tests executing target functions, script entry points, and caller–helper workflows with controlled fixtures; and (2) documentation-driven tests that extract commands/workflows from the *revised* SKILL.md and execute them against the revised scripts. Execution is sandboxed (unprivileged user, network disabled, read-only filesystem, 1 CPU / 512 MB / 35 s timeout). Metrics over three runs per model–method–task: Avg (mean Pass@1), P@3 (solved in at least one run), and Hit³ (solved in all three runs).

**AST-Guided Skill Revision.** Given an initial revision S̃ from a base method M, the stage runs: (1) *Requirement–structure grounding* — an LLM interprets the request q and links requirements/claims to language-native AST nodes (Python `ast`, Babel for JS/TS, Tree-sitter for others) via snapshot + node-type + exact source-quotation bindings, resolving local call graphs for caller–helper context; (2) *Repair targets and preservation constraints* — each requirement is assessed separately in S and S̃ (REPAIR / SATISFIED / UNCERTAIN), mapping discrepancies to editable syntax nodes while behavior assessed as satisfied supplies preservation constraints; (3) *Coordinated revision* — the editor applies node-span replacements only inside admitted targets (budget: ≤8 targets and ≤4,096 bytes per snapshot), assembly retains validated edits from S or S̃, and a final Markdown-alignment pass (≤8 line-addressed edits) reconciles SKILL.md with the repaired scripts. The stage is applied unchanged to Raw Package outputs and to an adapted CoEvoSkills (surrogate-verifier loop) as generators, on four backbones (GPT-5.5, GPT-5.6-Sol, Claude Opus 5, DeepSeek V4 Pro), with paired source-package bootstrap CIs (10,000 resamples) for the gains.

## Results & Highlights

- **Headline repair gains.** Averaged over four backbones on the 300 faulty-package tasks, the AST stage raises Overall repair Avg from 54.8% (Raw Package) to 76.7% (+21.9 pp, 95% paired bootstrap CI [17.2, 26.3]) and from 48.8% (CoEvoSkills) to 76.5% (+27.7 pp, CI [22.9, 32.2]); P@3 reaches 86.1%/85.9% and Hit³ 65.0%/65.7%.
- **Documentation repair is the weak spot of full-package baselines.** Raw Package and CoEvoSkills reach only 27.3% and 23.2% Avg on Doc-fault tasks — at or below Markdown-only's 27.0% — and 65.8%/74.0% of their Doc-task outputs pass behavior checks while failing documentation checks; the AST stage lifts joint acceptance from 27.3%→69.3% and 23.2%→70.3%.
- **Consistency, not just coverage.** The share of tasks solved in all three runs rises by +20.8 pp (Raw, In-the-Wild: 47.5%→65.0%) and +31.5 pp (CoEvoSkills: 37.2%→64.0%); complete four-state success (Doc+Script+Joint+Clean all passing in every run) jumps from 17/200 (8.5%) to 67/200 (33.5%) for Raw and from 6/200 (3.0%) to 83/200 (41.5%) for CoEvoSkills.
- **Ablations (GPT-5.6-Sol, Controlled Repair):** full AST-Guided revision reaches 84.8% Avg over all states vs 69.2% without structural feedback, 67.3% without caller–helper call context, and 63.7% for plain Raw Package — structural feedback contributes the largest margin, especially on Joint tasks.
- **Where the gains concentrate.** Mean Avg gains by structural partition are +32.8 (Single-Target), +27.6 (Multi-Target, reaching 81.9%), +24.1 (Cross-Call, still hardest at 71.9%); by repair category, argument binding improves 50.5%→83.3% and helper/recovery 44.5%→70.4%, while branch/route moves only 27.8%→30.6% (3 tasks); JavaScript rises 55.5%→79.9% and Python 64.9%→78.0%, closing the language gap.
- **Corrections dominate regressions.** Pooled over 300 faulty-package tasks × 3 runs × 4 backbones, AST revision corrects 49.4–60.7% of initially failing task/run pairs while regressing only 0.9–4.7% of initially successful ones; on Clean tasks Hit³ rises from 85.5%→96.5% (Raw) and 93.0%→96.5% (CoEvo).

## Authors & Credibility

The paper comes from a large HKUST team led by Yangqiu Song's group (corresponding author), together with Harbin Institute of Technology (Shenzhen). The first author (Yuxuan Liu) and several co-authors have a visible track record in this exact problem space — the references include their own SkillRevise (Findings of EMNLP 2026) on trace-conditioned skill revision and "Rethinking Self-Evolving Agent Skills" — so the group knows prior skill-evolution work first-hand. Methodologically the team shows strong software-engineering rigor: mutation-testing-style fault injection with calibration controls, sandboxed execution, held-out fault labels, three repeated runs, paired source-package bootstrap confidence intervals, and composition-sensitivity analyses (task-/package-/category-weighted contrasts) that stress-test their own headline gains. The build-out (35K-repo survey, 350 executable-checked tasks) represents substantial engineering effort, and related-work positioning against SkillOpt, SkillAudit, CoEvoSkills, SkillEvolver, SkillGenBench, and classic program-repair systems (Astor, Getafix, TBar) is accurate and current.

## Critical Assessment

- **Synthetic faults may not model real skill decay.** All Controlled Repair faults — and the In-the-Wild faults — are mutation-style injections (argument substitution, helper-call bypass, default-value changes) derived from patterns in the survey. Real-world skill packages break through API drift, dependency rot, and environment changes, none of which appear; a model good at recovering injected parameter swaps may not handle organic breakage, so the "repair" framing is closer to fault-injection testing than to maintenance.
- **Compute is not cost-matched.** The AST stage adds three extra model stages (requirement discovery, script revision, Markdown alignment) on top of the generator's output, while Raw Package and CoEvoSkills (one verify + one revise call) get no equivalent budget. The +21.9/+27.7 pp gains therefore conflate structural grounding with extra inference; a stronger baseline would give the baselines an equal number of revise-and-check rounds.
- **After augmentation the two generators converge (76.7 vs 76.5), which implicitly questions what CoEvoSkills' surrogate-verifier machinery contributes** — its careful verify-revise loop is worth only 48.8 vs 54.8 without AST, and nearly nothing once the AST stage is present. The paper does not discuss this implication.
- **Ablations run on a single backbone.** The w/o-Structural-Feedback and w/o-Call-Context ablations use GPT-5.6-Sol only; whether structural feedback remains the dominant component for DeepSeek V4 Pro or Claude Opus 5 is unverified.
- **Thin slices drive some conclusions.** Shell (3 tasks) stays at 0.0 Avg even with AST — the structural grounding stack (Python ast, Babel, Tree-sitter) appears not to help it — and branch/route (3 tasks) and multi-file pipeline (3 tasks) categories are too small for their per-category numbers (e.g., 27.8%→30.6%) to mean much. The language analysis is 115/150 Python, so the "JavaScript catches up" claim rests on 29 tasks. The authors do run category-weighted contrasts (gains stay positive: 15.2/10.8/13.5 pp for Raw under the three weightings), which mitigates but does not eliminate this.
- **Positive notes:** the calibration of behavioral checks (comment-only "fake repairs" rejected 20/20; wrong bindings rejected 49/49) directly blocks the most likely form of gaming, and reporting regressions on Clean tasks alongside repairs is an honesty practice many agent benchmarks lack.

## Strengths

- First benchmark to make **documentation repair, script repair, doc–code consistency, and preservation** separately measurable for executable Agent Skills — an evaluation gap that is real and well-argued via Table 1.
- The **AST-grounded method is a genuine methodological contribution**: binding natural-language requirements to uniquely resolved syntax nodes with preservation constraints is a clean, reusable mechanism, and the ablation shows the structural feedback (not just extra calls) carries the gain.
- **Methodologically conservative reporting**: three runs, Hit³ consistency, paired bootstrap CIs, composition-sensitivity checks, and explicit regression rates on clean packages.
- **Practical, reproducible infrastructure**: sandboxed execution with calibrated checks, held-out fault/state labels, and budgeted edit interfaces (≤8 targets, exact source-quotation binding) that reject syntactically invalid or out-of-scope edits.
- Constructed from **35,554 surveyed real GitHub Skill roots**, so the packages and fault patterns reflect what the community actually publishes, not a synthetic corpus.

## Limitations

- Faults are injected, not harvested from real maintenance histories; no evidence the results transfer to organic skill breakage (API/dependency drift).
- Heavy Python skew in In-the-Wild (115/150); Shell effectively unsolved (0.0 even with AST) and TypeScript nearly absent (3 tasks), limiting cross-language generality.
- Gains shrink on coordinated repairs: Cross-Call remains the weakest partition (71.9% post-revision), and multi-file pipeline tasks improve least among categories.
- Single-backbone ablation; no cost-matched baseline giving non-AST methods equal revision rounds.
- Absolute performance is far from saturated (best Overall Avg 76.7%; Doc-fault tasks were ~27% before AST), so the benchmark will need headroom re-examination as models improve; the 100-package / 150-task In-the-Wild scale is modest for a field benchmark.

## Relevance

这篇论文正中你的第一优先方向"Self-Evolving Agents"：它把 Agent Skill 的自进化从"改 Markdown"推进到"文档+可执行脚本的一致性修订"，并给出了可靠性导向的评测协议（修复 vs 保持正确行为分离、可校准的沙箱验收），对你关注的长时程自主智能体系统的可信演化很有参考价值。AST 引导的"需求→语法结构→受限编辑"机制也可迁移到自动化研究闭环中的代码资产自维护场景。

## Questions for Further Exploration

- Would AST-Guided Skill Revision still help if the non-AST baselines (Raw Package, CoEvoSkills) received the same number of revision-and-verification rounds — i.e., how much of the +21.9/+27.7 pp is structure versus compute?
- Can the fault model be extended to organic breakage (dependency updates, API deprecations, environment changes) rather than mutation-style injections, and does the AST grounding survive when the surrounding call graph itself changed?
- Shell tasks remain at 0.0 even with AST — what representation is needed for shell and config-driven skills where no rich AST exists?
- The two +AST variants converge (76.7 vs 76.5): is the generator's verifier loop unnecessary once a structural grounding stage exists, or does it matter only for higher-failure-rate regimes?
- How would the benchmark's preservation checks behave under multi-round self-evolution (chains of maintenance requests), where preservation constraints compound across revisions?
