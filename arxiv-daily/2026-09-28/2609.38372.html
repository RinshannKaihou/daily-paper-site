01Methodology · harness evolution cast as training

A frozen GPT-5.6 Sol agent runs inside harness state Hₜ = (code Cₜ, evolution notes Nₜ). The seed is a single 49-line Python file — one system prompt, one bash tool, a minimal tool-calling loop; no truncation, timeouts, compaction, or error recovery. Each iteration has two steps, played by the same agent in fresh sessions: the solver runs the batch once per task, producing verbatim records; the proposer then reads those records plus the current code and rewrites the harness directly — what to fix, what to add, what to delete is entirely its call.

Acceptance = runnability only: edits confined to the harness workspace, at most αₜ new lines, one successful mock-model run. No validation set, no score-based selection, no regression tests — a deliberate consequence of the “minimal priors” principle the paper later interrogates as its main cost.

Cosine decay 500 → 100; re-warmed to 200 for stage 2

02Emergent machinery · what 7 iterations invented

M1Output truncation

Truncates to head + tail past 48k chars. Born from terminal/coding tasks; biggest win on the unseen retrieval benchmark (recovered 57 of 65 aborted BrowseComp-Plus runs).

M2History compaction

Fires past 360k chars. Double-edged: erased the customer’s original request in all 11 τ²-Bench runs where it triggered — the root cause of that regression.

M3Independent review

Re-checks the answer in a fresh context; runs on 93.1% of Terminal-Bench and 100% of OfficeQA Pro / SWE-bench Verified records. Example fix: 0.77667 → 0.88825.

M4Command time limits

Per-command timeouts replace the seed’s bare loop; part of why Terminal-Bench 2.1 climbed 66.7 → 83.8.

M5Image budget

≤4 images per reply, ≤24 per task, plus delivery deadlines: turned the M097 video task from 41 image requests + timeout + 0.2 into a clean 1.0.

+Strengths

  • The training analogy is operational, not rhetoric: it generates falsifiable choices — cosine budget decay, benchmark mixing, replay anchors — and a clean experimental structure prior work lacked.
  • Unusually strict generalization protocol: held-out tasks disjoint from evolution, five true OOD benchmarks, one shared harness across heterogeneous task types, generalization-oriented proposer prompt (“memorizing specific tasks is worthless”).
  • Mechanism analysis is quantitative: per-iteration code-change table, per-benchmark trigger-rate heatmap, task-level case studies that show why the harness wins.
  • Honest self-reporting: regressions get root-cause sections, the “costs of simplicity” are enumerated (skills/memory/sub-agents never emerged), near-ties labeled as near-ties.
  • The anti-reward-hacking pipeline (preventive clause + automated scan + per-record review + outlier inspection) is a template other evaluation papers could adopt.

−Limitations & costs

  • One model, one chain per stage — no error bars. Headline deltas ride on large per-benchmark swings (Terminal-Bench +17.1) with no repetition across chains.
  • Acceptance without validation: harmful edits surface only at final evaluation; the framework cannot detect or roll back a regression when it is introduced.
  • No empirical head-to-head with AHE / HarnessX or a hand-written-mechanism baseline ablation — Table 2 is qualitative only.
  • Partial reproducibility: seed code and proposer prompt are published, but evolved harnesses, run records, audit scripts and API cost are not; nothing indicates a code release.
  • Small training run: 7 iterations × 60 tasks; continual stage tested on a single new domain; whether gains continue (or edit scope narrows) is unknown.

05Questions for further exploration

  1. Would a cheap validation gate (e.g., replaying 10 success anchors before accepting each edit) have caught the τ²-Bench compaction and configure_run regressions — at what fraction of the current cost?
  2. How many independent evolution chains are needed to make the OOD “matches Codex” claim statistically meaningful — and do the mechanisms reproduce across chains, or diverge?
  3. Do gains shrink on a stronger or weaker base model? Cited literature says harness gains favor weaker models — is GPT-5.6 Sol near the point where self-evolution stops paying?
  4. Why did skills, memory, and sub-agents never emerge despite unrestricted edit freedom — model-capability ceiling, prompt effect, or artifact of only seven iterations?
  5. Can the two-stage schedule scale to a stream of incoming domains without the anchor-replay set growing unboundedly?
