> **一句话总结：** 提出 CDES（证书驱动进化搜索）：在 AlphaEvolve/ShinkaEvolve 式进化搜索之上，把失败候选代码的错误固化为可机器执行的"证书"（假设+检查器证据+限制），由控制逻辑强制拒绝冲突、回溯并定向修复，从而在无需微调 LLM 的情况下自进化；在 Geant4 两个粒子物理函数的 CPU→CUDA 移植上取得 13.78×（Compton）与 23.54×（Fermi）的函数级加速，Compton 吞吐比专家手写的 Celeritas 实现高 14.9%，消融显示证书反馈把候选通过正确性检查的比例从 55% 提升到 90%。

> **TL;DR:** The paper introduces CDES (Certificate-Driven Evolutionary Search), a self-improving agentic harness that extends an AlphaEvolve-style evolutionary loop (built on ShinkaEvolve) with an enforceable certificate database: failures detected by the evaluation harness (Lean proofs, CBMC array-bounds checks, differential/physics tests, Compute-Sanitizer, statistical distribution tests) are distilled into certificates whose restrictions are enforced by a control logic via rejection, backtracking, and targeted repair — not just prompt feedback. Applied to porting two Geant4 particle-physics functions (Compton scattering, Fermi fragmentation) from CPU C++ to CUDA on an NVIDIA H100 (~250k inputs), it achieves 13.78× (Compton: 30.162 ms → 2.189 ms) and 23.54× (Fermi: 340.090 ms → 14.447 ms) function-level speedups over the CPU reference; on the shared Compton benchmark its throughput beats the expert-written Celeritas GPU implementation by 14.9% (16.1% when hybridized with a Celeritas component), and an ablation with Qwen3-Coder-Plus shows certificate feedback raises the fraction of proposals passing correctness checks from 55% to 90% — at roughly 2.3× the model-call cost.

## 核心贡献

- **证书驱动进化搜索（CDES）**：将进化式程序搜索（AlphaEvolve 式核心，基于 ShinkaEvolve 实现）扩展为"自进化"系统——失败候选经评估工具检测后，把冲突选择、被违反的需求、支撑假设与证据记录为**证书**，后续搜索中由冲突检查器/分析器强制阻断同类错误，而非依赖 LLM 对 prompt 反馈的遵从。
- **可执行的控制逻辑（拒绝 + 回溯 + 定向修复）**：借鉴 CDCL SAT 求解器的冲突学习思想，在保留兼容编辑的前提下拒绝冲突组合、补充缺失组件、并做针对性修复；即使 LLM 重复提出冲突方案也会被强制拦截，且无需访问模型权重、无需额外训练。
- **超越单元测试的科学计算评估工具箱**：为 GPU 移植组合了多类检查——Lean 形式化证明（GPU 任务分配保证每个输入恰好处理一次且保留随机数标识符，Physlib/HepLean/Mathlib）、CBMC 数组越界检查、Alive2/VOLTA 代码片段等价性、差分数值测试、物理守恒律检查、Compute-Sanitizer 内存/同步错误检测、统计分布检验、Nsight Compute 剖析；并设一套**隔离验证集**（新随机数序列、数值边界输入），其结果对搜索端隐藏以防"应试"。
- **Geant4 CPU→GPU 移植实证**：对 Compton 与 Fermi 两个函数生成 CUDA 代码，获得 13.78×/23.54× 函数级加速；生成的代码还发现了超越专家实现（Celeritas）的优化模式（如复用 helper 内部计算值、用乘法替换幂运算并在舍入可能改变决策处保守保留原式），混合 Celeritas 组件后吞吐再提升 16.1%。
- **消融证据**：在相同正确性检查下，证书反馈将候选"编译并通过检查"的比例从 55% 提到 90%，将吞吐增益 >10% 的候选比例从 50% 提到 80%，每次通过提案的成本降低 10.7%。

## Key Contributions

- **Certificate-Driven Evolutionary Search (CDES)**: extends an AlphaEvolve-style core (implemented on ShinkaEvolve) so that failures caught by the evaluation harness are converted into *certificates* — machine-enforceable records of conflicting choices, violated requirements, supporting assumptions, and checker evidence — which a conflict checker/analyzer uses to block the same mistakes in later candidates, instead of relying on prompt-level compliance.
- **Enforceable control logic (rejection, backtracking, targeted repair)**: inspired by CDCL SAT conflict learning, the control logic rejects conflicting combinations, adds required components, and repairs choices while preserving compatible edits — working through API calls only, with no access to model weights and no additional training.
- **A scientific-computing evaluation harness beyond unit tests**: combines Lean formal proofs (GPU work-assignment: each input processed exactly once, random-sequence identifiers retained, via Physlib/HepLean/Mathlib), CBMC array-bounds checking, Alive2/VOLTA fragment-equivalence checks, differential numerical tests, physics conservation-law checks, Compute-Sanitizer memory/synchronization checks, statistical distribution tests, and Nsight Compute profiling; a separate *withheld validation suite* (fresh RNG sequences, inputs near numerical decision boundaries) is hidden from the search runs to prevent gaming.
- **Empirical demonstration on Geant4 CPU→GPU porting**: generates CUDA for the Compton and Fermi functions with 13.78× / 23.54× function-level speedups; the generated code exhibits optimization patterns that surpass the expert-written Celeritas implementation (reusing a value Celeritas computes inside a helper; replacing power computations with multiplication while conservatively keeping the original where rounding could change a decision), and a Celeritas+CDES hybrid reaches 16.1% higher GPU throughput than Celeritas alone.
- **Ablation evidence**: with identical correctness checks, certificate feedback raises the fraction of proposals that compile and pass checks from 55% to 90%, raises proposals with >10% throughput gain from 50% to 80%, and lowers cost per passing proposal by 10.7%.

## Methodology

CDES keeps the standard evolutionary-program-search skeleton: a seed initializes a program database; parent selection picks a stored program; a mutator LLM proposes code or execution settings; the evaluation harness returns scores (to the program database) and failures (to the certificate database). On top of this, CDES adds three mechanisms:

1. **Detection and certification.** The harness detects requirement violations; a conflict checker and analyzer reviews finished candidates against stored certificates and symbolic dependency checks between code components. A certificate records the conflicting choices, the violated requirement, and supporting assumptions and evidence. Proposed restrictions are themselves checked before being allowed to block the same conflict in future candidates.
2. **Undo and targeted repair.** Rather than restarting wholesale, the control logic rejects conflicting combinations, adds required components, and repairs choices while preserving compatible edits — the paper explicitly draws the analogy to CDCL SAT solvers learning clauses from conflicts and backtracking to earlier decisions.
3. **Layered acceptance criteria.** Geant4 source and specifications define expected behavior, with Celeritas as the expert performance reference where one exists. An evaluator LLM selects and orders tools under a fixed mandated-checks policy; every evaluation record carries a hash identifying the exact candidate source code tested; failed or unresolved mandatory checks block acceptance and enter the certificate database. Formal analysis (Lean package) covers *selected* requirements — GPU assignment proofs guarantee each input is processed exactly once and retains its random-sequence identifier, and restricted code generation translates Lean-checked GPU work-assignment rules into executable code; CBMC bounds-checks C array indexing in bounded executions; Alive2/VOLTA validate code-fragment equivalence in separate demonstrations. Execution-based validation adds differential tests within fixed numerical tolerances, exact output-count / random-number-consumption contracts, physics conservation checks, Compute-Sanitizer, statistical distribution tests, and Nsight Compute profiling. Acceptance explicitly means "passing required checks within their stated domains," not universal program equivalence.

**Experimental setup.** Two complementary Geant4 functions are ported: Compton (particle energies/directions after a photon scatters off an electron; Celeritas has an expert GPU version to compare against) and Fermi (assigning energy/motion to nuclear-fragment products; no Celeritas GPU implementation exists, which also reduces leakage risk since the LLM may have seen Celeritas code in pretraining). Speedups exclude search/evaluation runtime. The mutator uses GPT-5.6-Sol with medium reasoning; total model-call cost under $10.

## Results & Highlights

- **CPU→GPU function-level speedups (Table 1)**: CDES-generated CUDA reaches 13.78× over the Geant4 CPU Compton function (30.162 ms → 2.189 ms) and 23.54× over the CPU Fermi function (340.090 ms → 14.447 ms), with data conversion and transfers included; these are standalone-protocol numbers and exclude search/evaluation runtime.
- **Against the expert baseline (Table 2, shared Compton benchmark)**: CDES GPU throughput is 14.9% higher than Celeritas (0.4433 vs 0.5093 normalized throughput is inverted in reporting; CDES median execution time 2.4000 ms vs Celeritas 2.4753 ms, ≈3.0% lower including transfers). The Celeritas+CDES hybrid (Celeritas energy selection + CDES direction/output code) reaches 16.1% over Celeritas (2.3905 ms) and +1.2% over CDES alone, reported as the median gain across six paired timing rounds.
- **Ablation on certificate feedback (Table 3, Qwen3-Coder-Plus calls)**: proposals passing correctness checks rise from 55% (without certificates) to 90% (with); proposals with throughput gain >10% rise 50% → 80%; >20% rise 30% → 35%; best throughput on withheld validation inputs improves 66.3% → 68.6%; total model-call cost roughly doubles ($0.0335 → $0.0782), but cost per passing proposal drops 10.7%.
- **Qualitative optimization patterns**: in Compton the generated code hoists a squared-sine value out of Celeritas's helper and reuses an earlier calculation, guarding the square root with a conditional; in Fermi it replaces selected power computations with multiplication but deliberately keeps the original formulation where rounding could flip a decision — a precision-aware optimization choice.

## Authors & Credibility

Piyush Jha (Georgia Tech, School of Computer Science + School of Physics) and Vijay Ganesh (Georgia Tech, School of Computer Science) are affiliated with prior work on LLM feedback and verification: the paper builds directly on their own RLSF (symbolic feedback for LLMs, ECAI 2025) and CDRL (certificate-driven RL for Neutrino Flavor Model Discovery, 2026), suggesting genuine domain expertise in certificate/verification-driven ML systems. Aishik Ghosh (Lawrence Berkeley National Laboratory + Georgia Tech Physics) brings high-energy-physics credibility, and the choice of Geant4/Celeritas as targets is consistent with an LBNL-calibrated understanding of detector simulation (Celeritas is the LBNL-led Geant4 GPU effort). The work is a preprint submitted to the 9th Workshop on Machine Learning and the Physical Sciences (ML4PS 2026) — a workshop-length proof-of-concept rather than a full conference paper, which matches its two-function scope.

## Critical Assessment

- **Narrow empirical scope relative to the framing.** "Towards certificate-driven software porting" of "large scientific codebases" is demonstrated on exactly *two* functions (Compton, Fermi), explicitly assuming functions can be optimized independently — the paper itself defers whole-simulation validation to future work. The 13.78×/23.54× headline numbers are function-level and say little about end-to-end Geant4 speedup.
- **Table 1's timing protocol structurally favors the GPU side.** CPU timings include allocation while GPU timings use preallocated buffers — acknowledged, but it means the eye-catching 13.78×/23.54× are not like-for-like; the more honest comparison is the shared-benchmark Table 2, where the margin over the real expert baseline (Celeritas) is +14.9% throughput on *one* function, and the hybrid's +1.2% over CDES alone is within plausible run-to-run noise territory despite the paired-median methodology.
- **The ablation uses a different model than the headline results.** Table 3's certificate-feedback ablation runs on Qwen3-Coder-Plus while the main results use GPT-5.6-Sol, so the 55%→90% claim does not directly validate the configuration that produced the speedups. The ablation's total spend ($0.0335 vs $0.0782) also indicates a very small-scale run with no variance estimates, and no seeds/repeats are reported for it.
- **Correctness is deliberately partial.** Lean proofs cover only selected requirements (e.g., work-assignment), CBMC only bounded executions, Alive2/VOLTA only fragments — the authors are transparent that acceptance ≠ program equivalence, but the certificate mechanism's soundness then rests on how well the harness enumerates the *right* requirements; nothing is said about false certificates or how often proposed restrictions were themselves rejected by the "restrictions are checked before use" procedure.
- **Cost accounting is thin.** Certificate feedback doubles model-call cost in the ablation; the 10.7% cost-per-passing-proposal improvement is favorable but the absolute search costs (<$10) are so small that scaling behavior of the certificate database (retrieval noise, stale certificates on changed code) is untested.
- **Reproducibility**: no code or data release is mentioned, and the harness stitches many tools (Lean/Physlib/HepLean, CBMC, Alive2, VOLTA, Compute-Sanitizer, Nsight) whose integration and mandated-checks policy are described only at one-paragraph depth — reproducing this harness would be a substantial engineering effort.
- On the positive side, the withheld validation suite (fresh RNG sequences and boundary inputs hidden from the search loop) and hash-identified exact candidate code are genuinely good anti-gaming practices that many evolutionary-search papers lack.

## Strengths

- The core idea is clean and well-motivated: convert failure feedback from *advisory* (prompt text) to *enforceable* (certificates checked by a control logic), addressing a real failure mode of repair-feedback loops where LLMs repeat the same errors.
- The verification stack is unusually thorough for an LLM-code paper: formal proofs of GPU input-coverage and RNG-identifier retention, bounded model checking, fragment equivalence, sanitizers, physics conservation laws, and statistical distribution tests — layered rather than a single benchmark.
- Self-improvement without retraining: the certificate database changes future candidate quality via API-only interaction, which the ablation quantifies (55% → 90% passing rate).
- Intellectually honest reporting: absolute times are flagged as non-comparable across tables, acceptance is explicitly scoped to "required checks within stated domains," and the hybrid-vs-pure results are reported with medians over paired rounds.
- The discovered optimizations (helper-value reuse beating expert Celeritas code; precision-aware power→multiplication replacement) are concrete evidence the system can find non-obvious, correctness-preserving improvements.

## Limitations

- Only two functions evaluated; the leap to "porting large codebases" (whole-Geant4-scale) is untested, and the independent-optimizability assumption may not hold for interacting physics components.
- Function-level speedups exclude full-simulation runtime; Table 1's asymmetric allocation handling (CPU includes allocation, GPU preallocated) inflates headline speedups relative to the shared-benchmark numbers.
- The certificate-feedback ablation is run on a different LLM (Qwen3-Coder-Plus) than the main experiments (GPT-5.6-Sol), at very small cost scale, without variance reporting.
- Formal guarantees are fragment/requirement-scoped, not whole-program; no analysis of certificate false positives, staleness, or database growth.
- No code release stated; the multi-tool harness and fixed checks policy are underdocumented for independent reproduction.
- Fermi's evaluation reduces reliance on (but does not eliminate) possible pretraining contamination from Celeritas sources, and Compton's +1.2% hybrid margin is marginal.

## Relevance

这篇论文正中你"Self-Evolving Agents & Automated Research"的最高优先级方向：它展示了一个不重训模型、靠累积证书自进化的长时程 agentic 搜索系统，并用消融量化了自进化收益（55%→90% 通过率）。同时对"极端性能优化下的可靠性"也有直接关联——数值边界输入、舍入敏感决策处的保守改写、以及形式化+运行时双层正确性检查，正是该方向的典型方法论。

## Questions for Further Exploration

- How does the certificate database behave at scale — do stale or conflicting certificates accumulate, and how often does the "restrictions are checked before use" step reject a proposed certificate?
- Would the 55%→90% ablation result hold with the main GPT-5.6-Sol configuration, or is the certificate mechanism's benefit model-dependent?
- Can the fragment-scoped formal guarantees (Lean work-assignment proofs, Alive2/VOLTA equivalence) be composed into a whole-function or whole-simulation correctness argument?
- How does the approach handle functions that are *not* independently optimizable — i.e., when a certificate derived from one component invalidates an optimization in another?
- Does the +1.2% hybrid gain over pure CDES persist under more paired rounds and different GPU partition sizes, and what is the variance of the six-round medians?
