> **一句话总结：** 提出 SelfSearch——一种无奖励信号的智能体自改进搜索：智能体读取历次自我修改"情节记录"（轨迹、工具调用、代码 diff、检查结果）来指导下一轮对自身仓库（指令、工具、执行逻辑）的修改，搜索全程不做任何下游任务评估；在 GPT-5.6 与 DeepSeek-V4 两种模型配置 × SWE-bench Verified / SWE-bench Multilingual / Terminal-Bench 2.1 三个基准共六种设置中，种群平均成功率全部提升（Terminal-Bench 2.1 上单智能体最高 +11.2 个百分点，43.8%→55.1%），且以 $4.03 的搜索成本得到在 Terminal-Bench 2.1 上达 82.0%（73/89）的智能体，追平九框架对比中得分最高的 Codex，而搜索成本比评估引导式基线低 13–53%。

> **TL;DR:** SelfSearch replaces reward-guided agent search with the agent's own self-modification experience: an agent edits its entire repository (instructions, tools, execution logic) using read-only records of previous self-improvement episodes — trajectories, tool calls, code diffs, check results — across 10 generations in two lineages (capability/adaptive), with zero downstream evaluation during search. On SWE-bench Verified, SWE-bench Multilingual, and Terminal-Bench 2.1 with GPT-5.6 and DeepSeek-V4 configurations, population-mean success improves in all six settings (e.g., Terminal-Bench 2.1 with GPT: 43.8%→55.1%), and it matches or beats evaluation-guided linear/archive search baselines (e.g., 78.2% vs 77.3% on SWE-bench Verified with GPT) at 13.4–53.2% lower search cost; a $4.03 search yields an agent solving 82.0% of Terminal-Bench 2.1, tying Codex.

## 核心贡献

- **无奖励的智能体搜索范式**：不同于以往用下游任务评估分数引导智能体进化（每评一个候选都要花钱、且搜索被绑定在被评估的任务上），SelfSearch 完全依靠"自我修改过程本身产生的情节记录"（episode records：推理轨迹、工具动作、代码改动、验证结果）作为下一轮修改的经验信号，搜索期间不接触任何下游任务或评测分数。
- **双谱系并行搜索 + 共享记录**：同时维护 capability（能力缺陷→造可复用工具）与 adaptive（修改策略本身的改进）两条搜索谱系，两谱系共享彼此的情节记录，可互相借鉴对方开发的工具（论文观察到谱系间直接复用工具的实例，如 trajectory reader 在第 7 代被跨谱系采纳）。
- **能力、效率与迁移三方面验证**：六种模型×基准设置的种群平均成功率全部提升；在双方共同解出的任务上执行成本显著下降（SWE-bench Multilingual 上 −38.5%）；进化出的智能体可跨模型家族迁移（DeepSeek 搜出的智能体在 GPT 上执行仍 +4.2pp）。
- **机制消融与行为分析**：消融证明情节记录（−2.1/−2.9pp if removed）与"会进化的改进者"（−1.7/−2.9pp if fixed）两个组件各有贡献；逐代 diff 分析展示智能体如何从自己的失败中造出文本搜索、trajectory reader、输出截断等可复用工具，并在下游任务中真实复用（line-range file viewing 在 40.3%/33.9% 的下游任务中被使用）。
- **极端性价比的横向对比**：$4.03 搜索成本得到的智能体在 Terminal-Bench 2.1 上 82.0%（73/89），在公开九框架对比中追平最高分的 Codex。

## Key Contributions

- **Reward-free agent search as experience**: SelfSearch guides agent revisions using episode records of prior self-improvement attempts instead of downstream task evaluations; each successor agent becomes the next improver, and the entire repository (instructions, tools, execution loop orchestration) is editable while model weights stay fixed.
- **Two-lineage search with shared records**: capability and adaptive lineages explore different limitation types and share episode records, enabling cross-lineage tool reuse (e.g., the trajectory reader developed by the adaptive lineage is adopted by the capability lineage at generation 7).
- **Capability, efficiency, and transfer**: population-mean success improves in all six model-benchmark settings; evolved agents cut execution cost on commonly solved tasks (up to 38.5% on SWE-bench Multilingual) and their implementations transfer across model families without further search (e.g., GPT-searched agents lift DeepSeek V4 Flash from 81.7% to 83.3–85.0% on SWE-bench Verified).
- **Mechanism understanding**: ablations isolate the value of episode records and the evolving improver; generation-by-generation diffs show how agents turn record-inspection difficulties into reusable tools that are then used on downstream tasks (text search on 8.6%/23.6% of downstream tasks for GPT/DeepSeek agents; line-range file viewing on 40.3%/33.9%).
- **Cost-competitive with evaluation-guided search**: SelfSearch achieves comparable or better success than linear and archive search baselines while spending 13.4–47.2% (GPT) and 49.0–53.2% (DeepSeek) less on search.

## Methodology

**Self-improvement episode.** The initial agent B₀ is a repository (derived from DGM's released implementation, with modifications to policy routing and the execution loop) containing instructions, tools, and execution logic; the underlying LLM is frozen. In episode k, agent B_k receives (a) an editable copy of its repository and (b) read-only episode records E_k = {e₀,...,e_{k-1}} from all previous episodes. It decides what to change, edits the implementation, and verifies its edits; the model-tool interaction loop runs in a fixed runtime outside the editable repository (controlling model, reasoning effort, output limits, and execution budgets), so edits cannot corrupt execution bookkeeping. Formally: (B_{k+1}, e_k) = SelfImprove(B_k; E_k, d), where d is a qualitative search direction.

**Search directions and lineages.** Two lineages run in parallel for 10 generations. The *capability* direction asks the agent to identify ability limitations revealed by inefficient behavior or failed actions and to build reusable tools/procedures; the *adaptive* direction asks it to improve how it revises its approach when actions fail or evidence contradicts assumptions. Generation 0 is run once per direction to seed concrete episode records (edits discarded, records retained), so both lineages start from the same B₀ but share records thereafter.

**Search environment.** Episodes execute in isolated containers without network access (partial tool calls only). Agents see no downstream benchmark tasks or scores during search; they may use their own tool outcomes and local checks. All candidate agents are archived, and evaluation happens only after search finishes.

**Experimental setup.** Two configurations: GPT (gpt-5.6-sol for self-improvement, gpt-5.6-luna for downstream) and DeepSeek (deepseek-v4-pro-0813 / deepseek-v4-flash-0731). Downstream evaluation: 120 tasks from SWE-bench Verified, 60 tasks from SWE-bench Multilingual (8 programming languages), all 89 Terminal-Bench 2.1 tasks. Baselines: (1) initial B₀; (2) evaluation-guided *linear search* (always revise the latest candidate, select by 10-task SWE-bench development score); (3) *archive search* (choose parents from all previous candidates, same dev set). For the head-to-head, the ten dev tasks are excluded (110-task SWE-bench Verified comparison). Ablations: *no-record* (agent cannot read prior records) and *fixed-improver* (B₀ always performs the editing while edited implementations carry forward).

## Results & Highlights

- **Population-mean success improves in all six model-benchmark settings** (Table 1). Largest single-agent gain: Terminal-Bench 2.1 with GPT-5.6, capability lineage 43.8% → 55.1% (+11.3 pp on the table; the paper headline says up to 11.2 pp). Both DeepSeek lineages raise SWE-bench Verified from 81.7% to 86.7%; SWE-bench Multilingual with DeepSeek rises 68.3% → 73.3% (adaptive lineage).
- **Execution efficiency improves alongside accuracy**: on Terminal-Bench 2.1 with DeepSeek, the capability and adaptive agents cut average cost per task by 12.1% and 16.9% respectively while raising success; on SWE-bench Multilingual, the DeepSeek adaptive agent gains +5.0 pp overall while reducing cost by 38.5% on tasks solved by both the initial and evolved agents. On SWE-bench Verified, shared-success cost drops 19.7–36.1% (DeepSeek) and 8.7–13.6% (GPT).
- **Beats evaluation-guided search at lower cost** (Table 2, 110 SWE-bench Verified + 60 Multilingual tasks): with GPT, SelfSearch B^c reaches 78.2% on SWE-bench Verified vs 77.3% (linear search, $12.35) and 76.4% (archive search, $7.53) at $6.52 search cost; with DeepSeek, both lineages hit 87.3% vs 86.4% (archive) and 81.8% (linear) at $4.03 vs $7.90–8.59. Search costs are 13.4–47.2% lower with GPT and 49.0–53.2% lower with DeepSeek.
- **Cross-model transfer** (Table 3): agents searched with GPT-5.6 Sol and executed by DeepSeek V4 Flash score 83.3%/85.0% on SWE-bench Verified (vs 81.7% initial); agents searched with DeepSeek V4 Pro and executed by GPT-5.6 Luna reach 79.2%/76.7% (vs 75.0% initial) — implementations remain useful on a different execution model with no further search.
- **Terminal-Bench 2.1 harness comparison**: aligning inference settings (xhigh reasoning, expanded execution limits) with a public nine-harness evaluation using DeepSeek V4 Flash, the SelfSearch agent solves 73/89 tasks (82.0%), tying Codex, the highest-scoring harness in that comparison, with only $4.03 of search cost.
- **Ablations** (Table 4, SWE-bench Verified mean): removing episode records drops mean success from 76.2→74.2 (GPT) and 86.7→83.8 (DeepSeek); fixing the improver at B₀ drops it to 74.6 and 83.8 (−1.7 and −2.9 pp), confirming both components contribute.
- **Evolved tools are genuinely reused downstream**: across 269 downstream tasks, GPT and DeepSeek agents use their evolved text-search tools on 8.6% and 23.6% of tasks, and line-range file viewing on 40.3% and 33.9%; a traced example shows a text-search tool built to inspect clipped episode records later used to locate related tests in a Sphinx task.

## Authors & Credibility

The authors are from the Graduate School of Data Science, Seoul National University (Jungwoo Yang, Injin Kong, Yohan Jo; Jo is the corresponding author and leads an established NLP research group). The work builds directly on the Darwin Gödel Machine (DGM) codebase, indicating hands-on familiarity with self-modifying agent systems. The paper is a preprint (v2, Sep 2026) with no stated venue acceptance. It includes an unusually detailed AI-use statement (AI tools used for code, figures, drafting; humans verified all AI-assisted work) and a reproducibility statement pointing to appendices with implementation details, search prompts, model configurations, and task selection — but no public code repository URL is given in the main text. The evaluation protocol (cost accounting, task subsets, comparison alignment with the third-party Terminal-Bench harness evaluation) is documented in appendices, which is a good transparency sign, though the third-party comparison relies on a GitHub-published evaluation (Apache Maka) rather than a fully in-house rerun of all nine harnesses.

## Critical Assessment

**Novelty.** The core idea — use the self-modification *process itself* (episode records) as the search signal instead of downstream rewards — is a clean and genuinely useful reframing. It sits between evaluation-guided agent search (ADAS-style) and self-modifying agents (DGM, Gödel machine): prior work already reuses experience across candidates, but SelfSearch's insistence on zero downstream signal during search, plus the observation that record-inspection difficulties themselves drive useful tool creation, is a distinct and well-executed angle.

**Rigor — the main weakness is statistical.** Each configuration appears to be a single search run; there are no seeds, no variance estimates, and no significance tests, and the authors honestly flag this ("Further work should examine how consistently these gains arise across independent searches"). With n=89 (Terminal-Bench) and n=120 (SWE-bench Verified), binomial noise is roughly ±4–5 pp, so several headline-adjacent numbers are fragile: the GPT adaptive lineage is essentially flat on SWE-bench Verified (75.0→75.0) and Terminal-Bench (43.8→44.9); the DeepSeek *capability* lineage actually regresses on SWE-bench Multilingual (68.3→66.7). The universal "all six population means improve" claim partly benefits from averaging over two lineages even where one lineage loses. Ablation deltas are small (1.7–2.9 pp) and internally inconsistent — with GPT, the fixed-improver adaptive lineage (75.8) beats full SelfSearch (75.0) in that cell, suggesting the component contributions are within noise for that family even if clearer for DeepSeek.

**Baselines.** The evaluation-guided baselines (linear/archive search) are reasonable and cost-accounted, but they are guided by only a 10-task development set; a stronger evaluation-guided opponent with a larger dev budget, or budget-matched repeated evaluation, is not tested. The Codex comparison on Terminal-Bench inherits numbers from a third-party public evaluation with aligned-but-not-identical settings rather than a controlled in-house rerun.

**Reproducibility.** Good documentation in appendices, but no released code/artifact link in the main text that I could find — given the method's dependence on prompt engineering and runtime scaffolding details, an artifact release would matter a lot.

**Red flags.** Cost-per-task figures (~$0.01–0.05) come from presumably short-horizon task subsets; the 120-task SWE-bench Verified subset selection is deferred to an appendix I could not fully audit. Overall, the claims are candidly scoped (the discussion explicitly lists the single-run caveat and the complementarity of evaluation), which raises trust — but treat the 1–3 pp cells as provisional.

## Strengths

- A genuinely reward-free search procedure with a concrete, implementable mechanism (shared, read-only episode records) that any repository-editing agent could adopt.
- Comprehensive evaluation matrix: two model families × three benchmarks, plus head-to-head cost-matched comparison, cross-model transfer, mechanism ablations, and qualitative generation-by-generation change analysis — far beyond a single-benchmark demo.
- The efficiency story is real and consistent: cost reductions on shared successes (−8.7% to −38.5%) hold across benchmarks and model families, not just accuracy gains.
- Excellent mechanistic analysis: Table 5's generation-by-generation diff log and the traced examples (clipped record → text-search tool → downstream reuse on a Sphinx task) make the "experience" claim concrete rather than rhetorical.
- Honest limitations: the paper itself names the single-search-run caveat and proposes combining SelfSearch with evaluation-guided selection under the same budget.

## Limitations

- Single search run per configuration; no variance, seeds, or significance testing — several per-lineage deltas (±1–3 pp) are within plausible evaluation noise on 89–120-task sets, and one lineage actually regresses (DeepSeek capability on SWE-bench Multilingual, 68.3→66.7).
- Evaluation-guided baselines use only a 10-task development set; stronger or budget-matched evaluation-guided opponents are untested, and the Terminal-Bench/Codex comparison relies on a third-party published evaluation rather than an in-house controlled rerun.
- Evidence is confined to coding/terminal agents with a frozen model-tool loop; whether episode records remain informative for longer-horizon, non-coding agent domains is unknown.
- The evolved-improver benefit is asymmetric across model families (clear for DeepSeek, marginal or negative in one GPT ablation cell), hinting the mechanism's payoff may depend on the improver model's capability.
- No public code release identified in the main text; reproduction depends on appendix-described prompts and runtime scaffolding.

## Questions for Further Exploration

- How large is run-to-run variance? Would 5 independent SelfSearch searches per configuration reproduce the population-mean gains, or do some runs regress?
- Under a *matched total budget*, does hybridizing SelfSearch with evaluation-guided selection (as the authors propose) dominate both pure approaches?
- Do episode records stay useful as they accumulate over more than 10 generations — is there a context/record-management bottleneck, and would record summarization or pruning help or hurt?
- The ablations show the evolving improver matters more for DeepSeek than GPT — is this because stronger improver models already internalize good revision strategies?
- Can the reward-free signal transfer beyond software engineering to scientific-discovery or research-automation loops, where ground-truth evaluation is expensive or delayed?
