> **一句话总结：** 本文证明并用 Lean 4 机器验证了一个"平稳性二分法"：只要智能体可编辑集合（脚手架：工具/验证器/任务分解）保持固定，迭代式自我改进必然严格边际递减——在 SWE-bench Lite 的 55 任务×5 种子精炼循环中，每轮对当前最优的平均改进从 Haiku 0.097→0.036→0.033、Sonnet 0.156→0.008→0.029 衰减到近零，且 401 个生产会话的 churn 衰减形态与 9,395 个人类会话完全一致（ρ=0.77 vs 0.86），说明当前冻结权重的 agentic coding 处于"有界精炼编辑器"而非"逃逸式 RSI"状态；因此安全审计的对象应是脚手架而非权重检查点。

> **TL;DR:** This paper proves (machine-checked in Lean 4, no axioms, no sorry) a stationarity dichotomy for recursive self-improvement in agentic coding: whenever the agent's reachable set of edits is fixed, strict diminishing returns follow, and frozen weights alone guarantee only an eventual ceiling — so the right audit target is the scaffold (tools, verifiers, decomposition), not the checkpoint. Empirically, on 55 SWE-bench Lite tasks × 5 seeds with mini-swe-agent as the weak learner over T=4 rounds, mean per-round improvement on the running best decays 0.097→0.036→0.033 (Haiku) and 0.156→0.008→0.029 (Sonnet); best-of-k orchestration attains the best worker's ceiling exactly without raising it; and a majority vote over 30 same-family workers fails 23/55 (42%) tasks at maximal failure overlap (vote error 0.418 vs mean per-worker error 0.356), so a diversity vote is absent in realistic single-vendor pools. Across 401 production coding sessions, churn decays with the same shape as 9,395 pre-AI human sessions — bounded refinement, not runaway self-improvement.

## 核心贡献

- **平稳性二分法（Prop 3，Lean 4 验证）**：精炼博弈（refinement game）单调改进且必然饱和——只要可达编辑类固定，每轮改进 η_t → 0；要逃逸只能扩大可达类（改脚手架或改权重），二者必居其一。冻结权重本身不构成安全边界：检查点不是该审计的东西。
- **把 agentic coding 形式化为 boosting**：弱学习器 = 预测当前草稿与目标之间残差（git diff）的编码 agent；精炼循环 = 逐轮组合补丁。AdaBoost 的三条件协议（保留全部 T 个提案、显式重加权分布 D_t、多数表决所需多样性）在现实部署中一个都不满足，理论剩余物是"单调 + 饱和"，而非提升式收敛率。
- **天花板只在宽度方向起作用（Prop 5/6/7）**：best-of-k 精确等于最优 worker 的天花板（宽度买速率不买预算）；30 个同厂 worker 的失败重叠 m*=k 时多数表决错误率达 0.418（最大值）；复用固定池的可计算视野 T ≤ log(1/ε₀)/2^(−γ)——除非池早已能拟合工作，再次咨询注定枯竭。
- **三个互补实证**：Part A 合成决策桩验证机制；Part B 在 SWE-bench Lite 上以 mini-swe-agent 为弱学习器的受控精炼循环（1,650 条轨迹，2×3 设计）；Part C 401 个真实生产会话（1,211 提交、23 仓库）的生态学证据 + 9,395 个 pre-AI 人类会话基线。
- **可运行的开放工程清单**：保留全部 T 个提案、显式分布 D_t、跨模型家族的多样性表决（现成 cross-vendor 聚合器只报端到端收益不报重叠统计）、首轮 pass 后继续精炼——四项均为判定"有界 vs 逃逸"所必需而现下缺失的测量。

## Key Contributions

- **A stationarity dichotomy (Prop 3, Lean 4-checked)**: the refinement game yields monotone improvement with saturation — a fixed reachable edit class forces η_t → 0, and escape requires expanding that class (scaffold or weights). Frozen weights alone do not put a system in the safe regime: the checkpoint is not the thing to audit.
- **Agentic coding formalized as boosting**: the weak learner is a coding agent predicting the residual (git diff) between draft and target; a refinement loop composes patches. Real deployed loops satisfy none of AdaBoost's defining preconditions (retention of all T proposals, explicit reweighting distribution D_t, diversity enough for a majority vote), so what survives is monotone-improvement-with-saturation, not boosting's convergence rates.
- **The ceiling binds sideways (Props 5/6/7)**: best-of-k realizes the best worker's ceiling exactly (width buys rate, not budget); on 30 same-family workers with maximal failure overlap m*=k the vote error is 0.418 — at its maximum; re-consulting a fixed pool has a computable horizon T ≤ log(1/ε₀)/2^(−γ).
- **Three complementary empirical parts**: synthetic decision stumps (Part A), a controlled refinement loop on SWE-bench Lite with mini-swe-agent (Part B, 1,650 trajectories, 2×3 design), and ecological evidence from 401 production sessions (1,211 commits, 23 repos) against a 9,395-session pre-AI human baseline (Part C).
- **A buildable harness spec**: retention of all T proposals, an explicit distribution over specifications, a cross-model-family diversity vote, and continued refinement after the first pass — four cheap measurements whose absence is all that blocks distinguishing bounded regime (i) from escape.

## Methodology

**Framework.** A weak coding agent refines a draft z via a refinement operator R_t; the loop is sequential composition of patches, so it is order-dependent — the "refinement game." The boosting mapping reads each patch as a weak hypothesis h_t on specifications, the margin as f(x) = Σ α_t h_t(x_t). Under the idealized Agentic Boosting Protocol (AdaBoost over specifications), Theorem 2 gives E[V(z_T)] ≥ V(z₀) + Σ η_t with saturation at 1 − V(z₀). Dropping the protocol: Prop 3 (fixed ceiling ⟹ saturation; sustained edge on an expanding class ⟹ divergence), Corollary 4 (under assumptions M1 class-expandability and M2 ultimate ceiling, escaping requires raising V* — i.e., modifying weights or architecture, not merely rewriting the scaffold), Prop 5 (best-of-k orchestration attains max_i V*(W, C_i) exactly and saturates identically), Prop 6 (majority vote has zero training error iff per-task tight overlap m*_i < k/2, sharp at m*_i = k where error = 1), Prop 7 (a reused pool either admits a zero-error combination — surviving any run by a computable horizon — or some member has edge γ = b/2S and survives every round). All algebra is machine-checked in Lean 4 (Mathlib, no axioms, no sorry); Lean also refuted the authors' conjectured strict inequality in Prop 5 with a counterexample.

**Part A (synthetic validation).** Decision stumps on SWE-bench TF-IDF features with synthetic labels confirm the machinery (appendix only).

**Part B (controlled loop on SWE-bench Lite).** mini-swe-agent is the per-round weak learner inside a T=4 refinement outer loop over k=55 SWE-bench Lite tasks × 5 seeds at temperature 0.25 (1,650 trajectories), in a 2×3 design: Claude Haiku 4.5 (weaker) vs Claude Sonnet (stronger) × feedback modes (independent / blind / diagnostic). Scoring is a custom pytest-based FAIL_TO_PASS/PASS_TO_PASS evaluator with threshold τ=0.6 (fraction of a task's tests passing) — explicitly *not* SWE-bench resolve rates; the evaluator was audited against gold patches, which exposed 23/50 (46%) deterministically failing tasks in the original pool (5 root causes spanning evaluator and model errors), prompting a rebuild to k=55. Model calls stop once a task passes (back-filling), so per-round edges γ̂_t are estimated only on live cells.

**Part C (production dynamics).** 401 AI-assisted sessions (1,211 commits, 23 repositories; AI-authored commits with inter-commit gaps under 4 hours), reduced to structural git metrics only (no code content; developer identity salted-hashed). Tests whether churn across successive commits decreases, with a 9,395-session pre-AI human baseline for shape comparison, a version-resolved re-test of the capability null, and permutation tests (p=0.93 for the Opus-vs-Sonnet survival-ratio contrast).

## Results & Highlights

- **Saturation is real and quantified (Part B, k=55 SWE-bench Lite tasks × 5 seeds, T=4):** mean per-round improvement on the running best decays toward zero — Haiku 0.097 → 0.036 → 0.033 and Sonnet 0.156 → 0.008 → 0.029 across rounds 1→3 — placing the loop in bounded regime (i). An exchanged-round robustness ablation shows the transferred Schapire–Singer product bound still descends, to 0.81 and 0.67 over three rounds.
- **Capability dominates; prompt feedback does nothing detectable:** model tier explains roughly half the variance (F(1,54)=53.46, p<0.0001, partial η²=0.497) — Haiku passes 44–69% of tasks at τ=0.6 vs Sonnet 85–89% (at τ=1.0: 29–38% vs 71–75%) — while feedback mode (p=0.61) and the interaction (p=0.45) are null, with only 11%/17% power at this k (80% power would need 7–9× the sample). Estimated per-round edges γ̂_t are negative with intervals including zero (Haiku −0.345/−0.435/−0.411 on 194→158 live rows; Sonnet −0.084/−0.143/−0.276 on 113→49), so no sustained positive edge exists.
- **The diversity vote is absent in realistic pools (Prop 6 measured, Figure 1, 30 same-family workers, shared 55-task pool):** at maximal failure overlap m*=k a majority fails 23/55 (42%) of tasks — the vote's error (0.418; 95% CI [0.291, 0.545]) sits at its theoretical maximum versus a mean per-worker error of 0.356; the paired excess is +0.062 (95% CI [−0.018, +0.142]) and vanishes when the pool is restricted to one capability tier.
- **Production churn converges like a human editor's (Part C, 401 sessions):** 70.0% of multi-commit sessions show decreasing churn (median late/early churn ratio 0.49; 95% CI [0.410, 0.79]; temporal ordering p<0.0001 on n=70 sessions with ≥5 commits) — but 9,395 pre-AI human sessions show the same decay shape (ρ_human=0.86 vs AI-tier ρ=0.77), so the decay is not AI-specific. Opus sessions show no higher survival ratio than Sonnet (ψ≈0.55 vs 0.55, n=158 vs 177; gap −0.003, 95% CI [−0.075, +0.069], permutation p=0.93), leaving a bounded null: current frozen-weight agentic coding is consistent with saturation, without identifying its cause.
- **The evaluator audit found the cost of trust:** applying the known-correct gold patch to the originally sampled k=50 pool left 23/50 (46%) tasks failing deterministically — a concrete caution for anyone building custom SWE-bench harnesses.

Bobadilla-Suarez has an academic cognitive-science/ML background, and the acknowledgments list credible external reviewers (Brett Roads, Peter Reifer, Aristides Panos, Bradley Love, Simon Busch-Moreno). The work is unusually rigorous for an industry preprint: Lean 4 machine-checked proofs with no axioms and no sorry, an evaluator audited against gold patches, power analyses on its own nulls, and an explicit Responsible Use Statement disclosing substantial AI assistance in drafting. Caveats: it is a non-peer-reviewed preprint from a single company, and the flagship "production" evidence is proprietary-adjacent (structural-only release), so independent verification of Part C's semantics is limited.

## Critical Assessment

- **The core theorem is admittedly near-tautological — and that is both the strength and the ceiling.** Prop 3(i) is a bounded-monotone-sequence argument ("the claim is not that saturation was hard to prove but that the reachable class is the right thing to track"). The paper is refreshingly honest about this: (M1) and (M2) are modeling assumptions no proof discharges, and the criterion is checkable only through a scaffold-immutability proxy. Readers expecting a deep RSI theorem will find a framing result; the value is in what it tells you to measure, not in mathematical depth.
- **The diversity test is a strawman pool, and the headline overreaches slightly.** The 30 workers are one vendor, two tiers, three prompt variants at temperature 0.25 — the authors themselves concede the "effective diversity is nearer two configurations." The dramatic 42% majority-failure at m*=k therefore establishes that *this* pool cannot vote, not that real orchestrators (Claude + GPT + Gemini, say) would fail Prop 6's m*<k/2 bar. The cross-vendor case is explicitly left open, yet the abstract's "a diversity vote would be absent in real workers" reads stronger than the evidence.
- **The custom harness makes all Part B absolute numbers non-comparable.** τ=0.6 thresholding on a Delhi/Django/SymPy-weighted pool means the 44–69% / 85–89% figures are neither SWE-bench resolve rates nor pool-composition-neutral — the authors say so themselves ("so the tier contrast is the transportable result"). The evaluator audit (46% deterministic failures even with gold patches applied) is commendably disclosed but also underlines how fragile such custom scoring is.
- **Censoring by design.** The loop stops calling the model once a task passes, so the per-round edge is estimated on a shrinking, self-selected population (Sonnet 113→49 of 275 live rows). The authors admit they have "no clean unconditional estimate of the per-round edge" — which means the paper's central empirical quantity, γ, is never actually measured, only bounded qualitatively via the improvement-on-running-best decay.
- **Part C is observational with confounded tier assignment.** Opus was typically used for planning while Sonnet executed, so the capability null rests on a structural proxy (survival ratio) and a version-resolved re-test; "bounded null, not a demonstrated zero" is the right label, and the authors apply it, but Finding 2's force is accordingly weak.
- **Redeeming rigor:** the honest-power analysis (11%/17% power on the feedback-mode null), the gold-patch evaluator audit, and Lean catching their own false conjecture (two disjoint singleton classes with equal values) are exactly the practices most preprints skip. The self-critical posture is credible, not performative.

## Strengths

- A genuinely clarifying reframing: separating test-time search, training, and scaffold rewriting dissolves a recurring confusion in RSI discourse ("an auditor who checks only whether weights are frozen catches test-time training and misses scaffold expansion entirely").
- Machine-checked theory (Lean 4, Mathlib, no axioms, no sorry) with precise scoping of what remains assumption.
- Triangulated evidence design: synthetic validation + controlled benchmark loop + ecological production data + a pre-AI human baseline that kills the tempting "AI churn decay = recursive improvement" story.
- Exceptional error accounting: the 23/50 evaluator-failure audit and the underpowered-null power analysis model honesty the field needs.
- Concrete, cheap open problems (retention, explicit D_t, cross-family vote, post-first-pass refinement) that define a buildable harness rather than vague future work.

## Limitations

- The per-round edge γ — the paper's key quantity — cannot be cleanly estimated from this data because the harness stops querying after first pass (acknowledged critical caveat).
- Diversity claims rest on a single-vendor pool with effective diversity near two; no cross-model-family vote is tested.
- Part B absolute rates are harness-specific (custom τ=0.6 evaluator, non-standard pool weighting); the τ=1.0 figures are still not official resolve rates.
- T=4 rounds and k=55 tasks are small; the saturation trajectory is short.
- Part C is observational: tier assignment is not randomized, the survival ratio is a structural proxy for quality, and only structural git metadata is released.
- The theory's (M1)/(M2) assumptions are unverified in any deployed system; the criterion is checkable only via a scaffold-immutability proxy, not a general estimator for the hypothesis class.

## Relevance

这篇论文正中用户最优先的研究方向（Self-Evolving Agents & Automated Research）：它给出了自我改进智能体"何时饱和、何时逃逸"的可验证判据，并明确指出当前冻结权重、重写脚手架的 agent 系统（STOP、FunSearch、Darwin Gödel Machine 一类）处于有界精炼状态。对关注长时自主智能体可靠性与安全审计的人来说，"审计脚手架而非检查点"是一个可直接落地的监控原则。

## Questions for Further Exploration

- Would a genuinely cross-family pool (e.g., Claude + GPT + Gemini workers) clear Prop 6's m* < k/2 bar on SWE-bench Lite, or do correlated tool/environment failures keep overlap near k even across vendors?
- If a loop actually implemented the Agentic Boosting Protocol (retention of all T proposals + explicit distribution D_t), does the transferred product bound keep descending past T=4, or do correlated failures persist as the authors' measurement predicts?
- Can the per-round edge γ be identified with a design that keeps querying after the first pass — and what is the compute cost of that identification?
- Is there a statistic on structural git metrics alone that separates regime (i) saturation from ordinary human-like editing economics, given that the 9,395-session human baseline matches the AI decay shape?
- When scaffolds do self-expand (e.g., self-written verifiers/test harnesses), can the proposed audit detect reward-backing exploitation of L(X, Y, γ) before it masquerades as capability gain?
