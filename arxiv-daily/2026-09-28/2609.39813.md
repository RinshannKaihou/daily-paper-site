> **一句话总结：** 本文论证低精度训练中"反向传播每次读到的舍入值"（backward-state policy：前向用过的舍入值 R / 原始值 U / 重新随机舍入 N）是学习算法本身的一部分，而非显存细节：在 FOG 390M（Llama 3 设置、FineWeb-Edu 10B token）上，从同一 checkpoint 分叉、仅让 FP8 注意力修正项 D 复用前向舍入值的 run 发散到最终训练 loss 7.314，而读取同分布新随机舍入的 run 正常收敛到 3.256；TE 官方 FP8 注意力在 3 个 seed 全部训练失败（7.91/7.86/8.02 vs BF16 的 2.70/2.70/2.77），仅替换 backward 读取的 saved output 即可恢复到距 BF16 仅 0.0054–0.0076 nats；作者进一步给出逐 use 的可检验需求与免训练检查器，在 PyTorch 与 Transformer Engine 三个算子上的全部预先注册预测均命中。

> **TL;DR:** In low-precision training the backward pass re-reads rounded tensors, and for each such use the implementation picks a value: the forward's rounded value (R), the original (U), or a fresh stochastic rounding (N). The authors show this "backward-state policy" decides training outcomes and cannot be settled by copy accuracy or final loss. Forking a 390M Llama-3-style model (FOG setting, 10B FineWeb-Edu tokens) at step 999 of Transformer Engine FP8-attention training so the attention correction term D reuses the forward's rounding diverges to a final training loss of 7.314 vs 3.256 when D reads a new rounding from the identical distribution. NVIDIA TE's shipped FP8 attention fails on all 3 seeds from scratch (final loss 7.91/7.86/8.02 vs 2.70/2.70/2.77 for BF16), yet swapping only the backward — or only the saved output it reads — recovers training to within 0.0029–0.0076 nats of BF16. They define a per-use reference (gradients pass through rounding unchanged), prove no single substitute serves both uses of FP8 attention probabilities, ship a no-training checker, and every pre-registered prediction about reuse held on three operators (PyTorch checkpointing, log-softmax backward, TE FP8 attention).

## 核心贡献

- **概念贡献：** 提出 backward-state policy（反向状态策略）：反向计算每次读取被舍入张量时，实现必须三选一 —— 前向用过的舍入值（R）、原始值（U）、或对原始值按同分布重新随机舍入（N）。论证该选择属于学习算法，"副本足够精确"和"最终 loss 正常"两个常用检验都无法裁决它。
- **分叉实验（决定性证据）：** 在 FOG 390M 的 TE FP8 注意力训练第 999 步分叉出三条仅 D 读取值不同的 run：复用前向舍入 → 发散（最终 loss 7.314）；同分布新随机舍入 → 正常（3.256）；直接从概率计算 D 的对照 → 正常（3.256）。在更新的 PyTorch 2.13/TE 2.13 上复现（6.896 vs 3.255/3.257），证明"指定舍入分布"并不唯一确定学习算法。
- **定位并修复 shipped 代码故障：** TE 官方 FP8 注意力在 390M×20k 步、3 个 seed 全部失败（loss 跳升数 nats 且不回落，验证 loss 比 FP8 关闭的 BF16 高 5.097/5.120/5.225 nats）；仅把注意力 backward 换成 BF16（FlashAttention-2 重计算）→ 0.0029/0.0059/0.0052 nats；仅用 wrapper 替换 backward 读到的 saved output → 0.0054/0.0076/0.0067 nats，证明"backward 读到什么"本身就决定结局，且修复不需要更高精度的输出格式（1.5B 单 seed 复现 backward 替换）。
- **一个张量、两个使用的理论：** 证明 RMSNorm 输出在 forward 被舍入后，gain 的梯度需要原始值、下一层权重梯度需要舍入值 —— 原始值只在一个 use 匹配参考（390M 模型 16/16 层实测可检出非零权重-use 误差、gain-use 误差恰为零）；对 FP8 注意力概率证明定理：不存在同时在 softmax Jacobian 和 V 梯度两个 use 处平均正确的共享替代值；两参数模型中 R/R 策略停在偏离最小值 1/18 的驻点。
- **可检验的逐 use 需求 + 免训练检查器：** 参考定义为"梯度原样穿过舍入"，每个 use 的需求可在单算子上用小有限情形精确检验，无需训练；对 PyTorch checkpointing、log-softmax backward、TE FP8 attention 三个非自研代码的测试中，预先注册的预测全部命中（包括"复用不改变任何东西"的否定预测）。

## Key Contributions

- **Concept:** the backward-state policy — at every use where backpropagation re-reads a rounded tensor, the implementation chooses the forward's rounding (R), the original (U), or a new stochastic rounding (N) — is part of the learning algorithm, and neither copy accuracy nor final loss can settle whether a choice is right.
- **Decisive controlled forks:** three 390M runs forked from one checkpoint, differing only in what the attention correction term D reads, end in opposite outcomes (7.314 divergent vs 3.256 trained) despite identical rounding distributions; replicated on newer software stacks.
- **Root-cause and fix of a shipped-code failure:** TE's FP8 attention fails on all 3 seeds; replacing only the attention backward with BF16, or only the saved output the backward receives, restores training within ~0.003–0.008 nats of BF16 — showing the failure needs neither a more precise output format nor an architecture change (FOG's workaround).
- **One tensor, two uses:** proved and empirically confirmed that a normalization output rounded in the forward needs the original at the gain's gradient and the rounded value at the next layer's weight gradient; a theorem shows no shared substitute is right on average at both uses of FP8 attention probabilities; a two-parameter model shows R/R is stationary 1/18 above the minimum.
- **Per-use checkable requirements:** each requirement is checkable on a single operator without any training run; all predictions registered before testing three real-world operators held, including predictions that reuse changes nothing.

## Methodology

**Reference definition.** The paper declares a reference: the gradient of the forward pass as it actually ran, with gradients passed through each rounding unchanged. Under this reference, each use must read the forward's value, the original, or a substitute giving the same gradient on average conditional on the realized forward and the incoming gradient it actually receives.

**Controlled forks (Section 2.1).** FOG's 390M model (Llama 3 setting) is trained with TE FP8 attention; at step 999 (two parent seeds) each checkpoint forks into runs differing only in what D = rowsum(dO ⊘ O) reads: the forward's rounding, a new stochastic rounding (unbracketed entries drawn uniformly between neighbouring E4M3 values, so the consumed rounding averages to O), or no copy at all (D from probabilities P). TE's backward is emulated densely in FP32; among cast placements this emulation was closest to TE's gradients (relative distances 2.4–5.9% for dO, 2.8–7.6% for K on a held-out window). A failure/success rule was fixed before launch: fail on non-finite loss or a >1.5-nat excursion above the running minimum; train usefully only if attention logits stay below 10^3 and validation loss ends within 0.05 nats of the control's.

**Shipped-code runs (Sections 2.2–2.3).** FOG's 390M trained from scratch for 20k steps with TE's own FP8 attention (round-to-nearest backward) on 3 seeds; interventions replace only the attention backward with a BF16 FlashAttention-2 recompute, or, keeping TE's backward, replace only the saved output via a wrapper (the forward's own output, or a stochastic rounding of a BF16 recomputation of O cast into the same FP8 values). A 1.5B model replicates the backward swap on one seed.

**Theory (Section 3, Appendix B).** The normalization-store analysis derives dW = u_q^T dy and shows reading the original at the weight use adds −τ·1^T dy to dW; a probe inserts a 6-bit store at every RMSNorm of two BF16-trained 390M models and measures per-use errors against controls. A two-parameter model (gain γ, weight w) admits exact average updates for all nine policies. For attention, a theorem proves no shared substitute Z is right on average at both the softmax's backward and the gradient of V, with exact enumeration over rounding outcomes confirming the predicted errors.

**Checker and operator tests (Section 4, Appendix C).** A checker takes a policy's per-use rule plus the random draws its gap from the reference depends on, and reports held/missed/undecided per requirement — no training. Three tests on code the authors did not write (PyTorch checkpointing and CPU log-softmax backward; TE's FP8 attention backward on an H20 GPU) registered operator, setup, predictions, and reading rules before any measurement; predictions are exact constants (e.g., mean error ratios, −ε sinh ε shifts, the α² contrast in query gradients), tested with rational-arithmetic enumeration and mutation tests on the checker itself.

**Training setup (Appendix D).** 390M: 16 layers, width 1024, MLP 4096, 8 heads, tied embeddings; 1.5B: 16 layers, width 2048, MLP 8192, 16 heads. 10B-token FineWeb-Edu sample, FOG Mistral-NeMo tokenizer (131,072 tokens), 4096-token non-overlapping windows, 128×4096 tokens/step. AdamW (β₁ 0.9, β₂ 0.95, ε 10⁻⁸), weight decay 0.1, clip 1.0, BF16 autocast with FP32 master weights, 5000-step warmup, 20k schedule with linear decay. FP8: TE delayed scaling, HYBRID recipe (E4M3 forward, E5M2 gradients), margin 0; embeddings and head in BF16/FP32. Data-parallel on 8 NVIDIA H20 GPUs; software builds (PyTorch 2.10–2.14, TE 2.10/2.13, cuDNN 9.16/9.20) recorded per run.

## Results & Highlights

- **Same rounding distribution, opposite outcomes (Figure 1):** forking FOG's 390M (FineWeb-Edu 10B, TE FP8 attention) at step 999, the run whose correction term D reuses the forward's rounding fails with final training loss **7.314**, while a new stochastic rounding from the same distribution trains to **3.256** and the D-from-probabilities control reaches **3.256** — the two copies are equally accurate, only one survives. Replicated on the newer stack (PyTorch 2.13/TE 2.13): **6.896** vs **3.255**/**3.257**.
- **Shipped TE FP8 attention fails on all seeds (Figure 2):** 390M from scratch, 20k steps, TE's own FP8 attention ends at final training loss **7.91 / 7.86 / 8.02** on seeds 0/1/2 versus **2.70 / 2.70 / 2.77** for the same model with FP8 disabled (BF16) — validation losses **5.097 / 5.120 / 5.225 nats above** the BF16 runs. Keeping the FP8 forward and replacing only the attention backward with BF16 tracks BF16, ending just **0.0029 / 0.0059 / 0.0052 nats above** it.
- **Replacing only the saved output also fixes it (Section 2.3):** with TE's FP8 backward kept, wrapper-swapping only the saved output it reads lets all 3 seeds train, ending **0.0054 / 0.0076 / 0.0067 nats above** the BF16 runs in validation loss — while the unchanged runs fail — proving the backward's input, not its precision, decides the outcome.
- **One stored tensor needs two values (Section 3.1):** inserting a 6-bit store at every RMSNorm of two BF16-trained 390M models, the weight-use error exceeds the largest value any control layer reaches in **all 16 layers of the first sample and 16/16 layers of the second** (detectably nonzero on average), while the gain-use error is **exactly zero** — the original matches the reference at only one of its two uses.
- **Comparable final loss hides a different algorithm (Section 3.3):** 390M trained with a 6-bit store as the only low-precision rounding (8000 steps, 2 seeds, pre-fixed margin ±0.010 nats): R/R ends **0.00425 nats below** the reference U/R (interval excludes zero, inside the margin); at 5 bits R/R ends **0.00957 nats below**, crossing the margin — a *lower* held-out loss than the reference — yet its RMS normalization gain falls below U/R's in every layer on both seeds (mean gain ~0.7 for U/R vs ~0.55 for R/R at 8k steps), so equal loss does not mean the same trained model.
- **Every pre-registered operator prediction held (Section 4.3, Figure 6):** PyTorch checkpointing — the use's mean error shrinks to **0.19%** of baseline when recomputation stops at the rounding but stays at **106.12%** when it includes the loss; log-softmax backward (ε=0.1, CPU, double precision) — reuse shifts the gradient by **−ε sinh ε** under the constructed loss (relative error 0.002878) and leaves the NLL gradient unchanged (relative error 0.004385), while neither copy is right under the likelihood (cosh ε−1); TE FP8 attention (TE 2.13, cuDNN 9.20, H20) — the query-gradient contrast's predicted mean **α² = 0.0625** measured **0.0625**, all eight cells within α²/10, largest deviation **0**.

The author group spans TLAIC (Beijing Tongming Lake Information Technology Application Innovation Center), Fudan University's Institute of Systems for Advanced Computing, Harbin Institute of Technology, Peking University (Key Lab of HCST, MOE; School of Computer Science), and the Shanghai Institute of Systems for Open Computing. Corresponding authors are Dezhi Ran and Tao Xie (PKU); Tao Xie is a long-established software-engineering and software-testing researcher, and the paper's methodology bears that stamp: evaluation rules and per-operator predictions were registered before any measurement, checker verdicts were themselves validated by exact enumeration and mutation testing, and every registered statement — including the three that missed — is reported in appendix tables. The group has prior work on exactly this failure surface ("One QK channel, many sources: Guarding low-precision attention collapse", ref [50]), so the empirical claims come from a team with accumulated context on low-precision attention collapse rather than a one-off study. The paper engages the relevant prior literature precisely and in the right places (FOG, Qiu & Yao's FlashAttention analysis, Attn-QAT, ACTNN/GACT/CoAT activation compression), including crediting the PyTorch GitHub issue that first reported checkpointing's fresh-randomness hazard.

## Critical Assessment

**Novelty is real and well-honed.** Prior explanations for low-precision attention failure pointed at architecture (FOG avoided it by changing the architecture) or at biased rounding of the attention output (Qiu & Yao traced a BF16 FlashAttention failure to the correction term). The fork design isolates a sharper variable: holding the forward and the entire rounding distribution fixed and changing only *which copy of O the backward reads* flips the outcome. That is a genuinely new experimental fact, and the "one tensor, two uses" theorem (no shared substitute serves both uses of attention probabilities) upgrades the anecdote into a structural claim.

**Rigor is unusually high for a systems-flavored paper** — pre-registered predictions, pre-fixed failure/success rules, exact enumeration backing every theorem, replication across two software stacks, and honest reporting of three registered statements that missed (S6 missed because the authors' own probe included dropout, making the input random — a test-design flaw they then fixed in a second registered configuration; LS4's z-score of 2.033 exceeded its z<2 bound). This is the strongest aspect of the paper.

**Weaknesses worth weighing.** (1) Scale: the training evidence is 390M × 3 seeds, plus a single 1.5B seed for one intervention; whether the same per-use sensitivities matter at 70B+ scale, where FOG-style FP8 recipes actually run, is extrapolated rather than shown. (2) Evaluation is loss-only — no downstream task metrics, so "trains usefully" is defined entirely in nats. (3) The reference itself (gradients pass through rounding unchanged) is a definitional convention; the paper argues for it convincingly but concedes U/U errs at the loss's own gradient, and nothing beyond the two-parameter model and loss comparisons shows the reference yields *better models*, only that it is the unique self-consistent target. (4) The fork experiments use an FP32 *emulation* of TE's FP8 backward (closest found placement still 2.4–7.6% off TE's true gradients on a held-out window), so the cleanest causal result is one level removed from the shipped kernel — though Sections 2.2–2.3 and the H20 operator test cover the real one. (5) Version pinning: conclusions about TE's shipped attention are tied to specific builds (TE 2.10/2.13, PyTorch 2.10–2.13, cuDNN 9.16/9.20, H20); NVIDIA could change the backward's reads in any release. (6) No code release is mentioned in the text, which limits immediate adoption of the checker.

## Strengths

- The fork experimental design is close to a minimal causal experiment: same checkpoint, same forward, same rounding distribution, only the read differs — and the outcome flips reproducibly across seeds and software stacks.
- Rare methodological discipline: failure/success thresholds and all operator-test predictions registered before measurement; every registered statement, including misses, tabulated in the appendix.
- The theory is exactly checkable (two-parameter model computed in closed form; theorem confirmed by exhaustive enumeration over rounding outcomes), not hand-wavy asymptotics.
- Practical payoff: a no-training, per-operator checker plus a diagnosis that a one-line wrapper (swap the saved output) fixes a shipped-code failure — cheaper than FOG's architecture change or a full-precision backward.
- Honest scoping of what final-loss comparisons cannot show, demonstrated empirically rather than merely asserted (the 5-bit R/R run with lower loss but different weights).

## Limitations

- Small training scale (390M, 10B tokens; one 1.5B seed), loss-only evaluation, no downstream task benchmarks.
- Findings are operator- and version-specific: TE's FP8 attention backward, PyTorch 2.10–2.14 checkpointing/log-softmax, cuDNN 9.16–9.20 on H20; nothing bounds behavior of other kernels or future releases.
- The fork runs rely on an FP32 emulation of TE's backward rather than the fused kernel itself.
- The stochastic rounding used in forks is software-emulated; hardware stochastic rounding (as on recent NPUs) is only discussed, not tested.
- The checker can return "undecided" (e.g., a shared random draw whose distribution cannot be independently redrawn from a stored rounded value), so some policies remain formally unadjudicated.
- No released code or checker artifact is mentioned in the main text.

## Relevance

这篇论文同时命中"LLM 训练稳定性与可观测性"（把 FP8 训练中 loss spike / 发散的根因精确定位到 backward 读取的具体张量值，并给出逐 use 的检查手段）和"极限性能优化下的可靠性"（低精度/混合精度数值正确性）两个核心关注方向，是本周期内与用户兴趣重合度最高的一类工作：它提供的不是又一个 loss 曲线观察，而是可在算子层面免训练复验的故障判据，可直接用于训练异常的根因分析与内核验收。

## Questions for Further Exploration

- Do per-use backward-state sensitivities persist at 70B–trillion-parameter scale, where FP8 recipes are actually deployed, and do the tolerances (e.g., the 1.5-nat excursion rule) scale predictably?
- Can the checker be wired into CI for PyTorch/TE so that a new kernel release must certify each use's requirement before shipping — and would vendors adopt a pre-registration culture for numerics?
- How do the theorem's conclusions transfer to FP4 training and to hardware stochastic rounding, where the rounding distribution differs from the emulated software SR used here?
- Is there a useful dynamic policy — switching between U/R/N per use during training (e.g., warmup with N, then R) — or does any deviation from the reference accumulate irreversibly, as the store-probe results suggest?
- Since comparable final loss hid different trained weights (Section 3.3), what downstream-task or representation metrics would detect such discrepancies earlier and more cheaply than probing every layer's gains?
