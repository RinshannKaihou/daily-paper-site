Why This Matters

Reframes zeroth-order optimization as a trajectory-discovery operator for agent self-evolution — with budget-matched proof the gains aren't recoverable by brute-force sampling.

!Critical Edge

The controlled Qwen-3-8B ReAct baseline scores 15.5% on WebWalkerQA — 9 points below the authors' own Qwen-2.5-7B ReAct (24.2%), so the headline gain is partly a weak-baseline artifact.

01 Methodology

A standard multi-turn ReAct deep-research setup — a policy πθ talks to search / visit / code tools and emits a trajectory. Because actions are discrete and the environment is non-differentiable, θ → τ is a black-box stochastic map.

The core argument is a gradient decomposition ∇F = g_fixed + g_traj. A fixed-trajectory first-order update only realizes g_fixed — it raises answer likelihood under an already-failed context without changing tool selection. Outcome RL captures g_traj but degenerates to zero when every sampled trajectory on a hard example receives identical reward.

ZO sidesteps both. For each hard instance a fresh per-instance LoRA is perturbed along K random directions w = θ + (B+σε_B)(A+σε_A); a complete fresh rollout runs under each perturbed policy (so the trajectory distribution genuinely moves); an answer-perplexity loss — computed only on gold answer tokens conditioned on the sampled trajectory — scores each rollout; and one-sided finite differences against a shared baseline update the LoRA via Adam.

Successful (or low-loss) trajectories feed a buffer that SFTs a single shared agent — that SFT step is what converts per-instance adaptation into a general capability gain. Training: 304 QA pairs filtered from 500 WebShaper pairs; ~1152 GPU-hours on 8× RTX 3090.

03 Strengths & Limitations

Strengths

  • Central claim tested with the right experiment: matched-rollout Best-of-N, Best-of-45 recovery, and random-LoRA controls separate "loss-guided optimization" from "more sampling."
  • The g_fixed / g_traj decomposition gives a falsifiable reason fixed-traj FO (7/50) and outcome RL (16/50) plateau where ZO does not (23/50).
  • Genuine hyperparameter insensitivity — K, σ, rank r, η all land within 19–24/50; one-sided vs two-sided parity (23 vs 24).
  • Unusually forthcoming appendix: 1152 GPU-hours disclosed, exact tool stack named, single-run results labeled as such.

Limitations

  • Scale ceiling: largest backbone is 8B on 24 GB GPUs; no evidence the effect persists at 32B+ where the boundary is already far out.
  • ~3.8 GPU-hours per training question; no cost-matched comparison against teacher distillation or just training on more data.
  • Answer-perplexity loss needs gold answers at discovery — it is "no trajectory annotation," not "no annotation."
  • Headline 8B GAIA 47.5% is a single run; seed variance (28.6 ± 0.6) covers only the 4B setting.
  • No ablation isolating whether the adaptive lookup pool inflates discovery by serving stale-but-lucky observations across branches.

04 Questions for Further Exploration

  1. What is the exact "sufficiently low answer loss" threshold for SFT-buffer admission, and how much of the +24.2 GAIA gain survives with verified-correct trajectories only?
  2. Why does the 8B ReAct baseline underperform the 7B one on WebWalkerQA (15.5 vs 24.2)? Fixing it could shrink the reported delta.
  3. Does the shared-cache lookup pool bias discovery — do trajectories stay valid replayed against a live, uncached environment?
  4. At equal GPU-hours, how does ZO compare to (a) GPT-class teacher distillation and (b) RL with a dense answer-perplexity reward instead of binary correctness?
  5. The 0.85 consecutive-update cosine similarity suggests low-dimensional dynamics — would a small learned subspace (à la LOZO) recover the same trajectories with far fewer rollouts?
  6. Does ZO discovery help agents already near their scaffold's ceiling (e.g. starting from ARPO's checkpoint), or only those far from it?
