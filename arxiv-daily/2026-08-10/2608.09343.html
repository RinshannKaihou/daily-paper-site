Event-level simulation traces let an LLM diagnose and rewrite scheduling policies, beating every baseline on all 100 seeds.

Why this matters

Advances LLM-as-optimizer feedback from scalar scores and textual reflection up to structured event-level traces — a transferable diagnostic primitive for code search.

Critical edge

Baselines cannot control charging (9% of the score rewards it), so part of the ~15-point gap is a wider action space, not trace guidance. The honest missing baseline is a charging-augmented rule search.

01Methodology

A (1+k) hill-climber whose variation operator rewrites code, grounded in traces.

The optimizer maximizes J(π)=E_ξ[S(π;ξ)] estimated by R=10 replications. Evaluate_R returns both the mean score and a queryable event-level trace database. A manager agent reads the incumbent code, its score, retained traces, and prior history, then emits 3–4 distinct revision plans; each goes to a fresh-context editing agent in an isolated workspace. Candidates passing load/runtime checks (≤3 repair restarts) are scored with 10 replications plus one diagnostic replay — a deterministic re-execution of the worst-scoring replication, whose score is excluded from the selection mean. The best candidate replaces the incumbent only on strict improvement; a frozen snapshot of the trace feeds per-run parameter estimation, preventing within-batch leakage. Stop on T=10 iterations, target 80, or 3 stalls. The simulator is a three-line factory DES (SUPCON/FreezoneX hackathon) scored as a fixed weighted sum of eight normalized metrics over a 500-min horizon.

03Strengths & Limitations

Strengths

  • Rigorous protocol: independent seed sets for promotion, frozen matched-seed re-eval (100 seeds), Wilcoxon + Holm correction.
  • Horizon T_sim=500 empirically justified — 1000 reps, plateaus after ~500 min, ±2-pt 5–95% band.
  • Trajectory narrative shows the agent diagnosing then repairing its own over-correction — causal evidence a scalar cannot carry.
  • Parallel-candidate ablation isolates a clean mechanism: peak quality preserved (78.56≈78.61), variance explodes.

Limitations

  • Single DES environment; warehouse / port / hospital transfer is asserted, not tested.
  • No code, prompts, or instrumented simulator released; proprietary backbones, no decoding settings.
  • Worst-replication trace selection — the named contribution — is never ablated.
  • No-DB ablation conflates trace diagnosis with data-driven parameter estimation.
  • No LLM cost / wall-clock accounting vs the metaheuristics' 12,800 simulation runs.

04Relevance

研究价值

对关注 LLM-as-optimizer / 代码级策略搜索（EoH、FunSearch、ReEvo、AlphaEvolve、Eureka 一线）的读者很有价值：它把"反馈富化"这一维度从标量分数、文本反思推进到结构化事件轨迹，并给出可迁移的工程原语——最差复现的确定性回放 + 回放分数排除在选择均值之外 + 快照式参数估计防泄漏。同时也是多智能体评测与消融设计的正面样本（配对种子 Wilcoxon + Holm、独立种子晋升）与反面教材（消融把轨迹诊断和参数估计混在一起、基线动作空间比方法窄）。

05Open questions

Q1

Does worst-replication selection actually beat random or median? If any trace suffices, the central mechanism claim weakens considerably.

Q2

How much of the ~15-pt gap survives with a charging-augmented rule/metaheuristic action space?

Q3

Can trace diagnosis be separated from parameter estimation — keep the estimator, blind the manager to the trace?

Q4

How does it compare to a ReEvo-style textual-reflection controller on the same ~400-run budget? That is the missing apples-to-apples LLM baseline.

Q5

What is the token / dollar cost per point of score improvement, and how does it scale at T_sim=3000 (6× longer)?

Q6

Does the trace advantage grow with weaker backbones? GPT-5.4-mini (−3.56) vs Gemini (−1.35) hints traces substitute for capability.
