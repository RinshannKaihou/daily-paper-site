> **一句话总结：** 作者用 Claude Code 搭了一个"研究员议会 + 策展人 + 长时程 worker"的多智能体闭环，让 LLM 演化生成 coset-orbit balanced-product qLDPC 码族的可执行程序，并在 MAP-Elites 档案 + 确定性评估器（QDistEvol 距离上界 + MILP 精确认证）下搜索 n ≤ 400、权重 w ≤ 10 的二元 CSS 码；在每个权重类都拿到领先或有竞争力的有限长参数，代表性成果包括 w=7 的 [[288,16,18]]（Q = kd²/n = 18.00，超过该权重类此前由距离上界推出的 Q ≤ 17.78）、w=9 的 [[288,18,18]]（Q = 20.25）和 w=10 的 [[234,28,18]]（Q = 38.77），并且 [[400,16,≤22]] 在 BP-OSD 码容量解码下全程优于两个 bivariate-bicycle 基准 [[288,12,18]] 和 [[360,12,≤24]]。

> **TL;DR:** An LLM multi-agent loop (Claude Code; Opus 4.8 researchers/curator + Sonnet 5 worker) evolves executable generators of coset-orbit balanced-product CSS code families inside a MAP-Elites archive, scored by a deterministic evaluator using Q = kd²/n with QDistEvol distance upper bounds and post-hoc Gurobi MILP certification. Searching n ≤ 400 and overall weight 6 ≤ w ≤ 10 against a curated benchmark of 1,209 published codes from 91 sources, it finds leading or competitive codes in every weight class: [[288,16,18]] at w=7 with Q=18.00 (vs the Q ≤ 17.78 upper-bound-derived ceiling previously known for that class), [[288,18,18]] at w=9 with Q=20.25 (beats the prior best trivariate-tricycle result), [[234,28,18]] and [[372,44,18]] at w=10 with Q=38.77/38.32 (surpassing the strongest previous exact code), and [[336,12,20]] at w=6 with Q=14.29 (within 7% of the [[340,16,18]] generalized-bicycle leader at Q=15.25). Under a shared minimum-sum BP-OSD code-capacity depolarizing protocol, [[400,16,≤22]] beats both bivariate-bicycle benchmarks at every sampled p, and the ten parameter champions have pseudo-thresholds from 5.40% to 9.30%. Worth reading if you care about agentic scientific discovery loops or finite-length qLDPC construction; the main caveat is that there is **no ablation isolating the agentic scientific-reasoning loop from plain fitness-driven program evolution**.

## 核心贡献

- **搜索空间从 lifted product 扩展到 coset-orbit balanced product**：把可执行码族程序分成四个层级（L1 局部项 / L2 protograph 形状 / L3 子群作用 / L4 宿主群构造），相比前人 lifted-product 的三层 structured concept evolution（SCE），把"子群作用"提升为独立的结构变量，从而允许 non-normal 子群、进入真正的 balanced-product 区域（不能约化为 G/K 上的 lifted product）。
- **两层闭环架构**：上层"科学推理环"由三名分工不同的研究员（有限群与子群作用 / qLDPC / 距离与稀疏图结构）互相 cross-review，再由 curator 把结论沉淀为可证伪的 lesson（含 confidence 公式 C = (1+p+s)/(2+p+s+c)，0.60 / 0.85 两档阈值，反例可以降级已有 lesson，并单独记录 anti-lesson）；下层"程序演化环"由 MAP-Elites 调度器 + 长时程 worker + 固定评估器组成。
- **自适应距离验证预算**：距离估计是评估瓶颈，因此分级分配——每个新代表先跑 10⁴ 次 QDistEvol，若上界超过 1.3√n 自动升到 10⁵；10⁶ 次的高预算档只能由 curator 显式下发验证任务触发（每轮最多 3 个），把最贵的计算导向"不确定性会影响某条假设或选择决策"的候选。
- **严格的结果分层**：距离只有在 MILP（Gurobi 12.0.3）对每个逻辑生成元的子问题都证明全局最优、且有显式 witness 匹配时才标为精确值，否则一律标为上界（表中用 ≤ 表示），Q 相应地报告为"上界端点"。
- **实证发现与诚实的负面结论**：找到了 [[368,18,16]]（A₆ × ℤ₂，non-normal K）、[[336,12,≤24]]（PSL(2,11)）、[[248,12,18]]（PSL(2,13)）等五个真正的 balanced product；但作者自己指出，在 n ≤ 400 且 w ≤ 10 的双重约束下，这些真 balanced product 的 Q 明显不如 lifted product，并据此提出"lifted product 在该有限区间内本质占优"的猜想，而不是把它包装成卖点。

## Key Contributions

- A four-level executable-program representation (local terms → protograph → subgroup action → host group) for coset-orbit balanced-product CSS families, generalizing the three-level SCE representation used for lifted products and making the subgroup action an independent mutation target.
- A closed discovery loop coupling short-range program evolution (MAP-Elites, niches = host-group family × subgroup structure × rate bin × weight class) with a long-horizon scientific-reasoning loop (3-member researcher council + curator with falsifiable lessons/anti-lessons and explicit evidence grouping to avoid counting related descendants as independent support).
- Agent-directed, staged distance verification: 10⁴ → automatic 10⁵ escalation (triggered by the d_ub > 1.3√n credibility cap) → a 10⁶-iteration tier commissioned only by the curator, so the expensive verification budget follows active hypotheses rather than uniform escalation.
- A rigor protocol separating QDistEvol upper bounds from MILP-certified exact distances, plus a curated comparison set of 1,209 published binary CSS/stabilizer LDPC instances (n ≤ 400, k > 0) from 91 sources, each labeled by evidence type (exact / certified lower bound / upper bound / two-sided interval / unverified claim).
- Concrete finite-length codes: 20 parameter-frontier codes (Table I) plus 7 structurally distinct codes (Table II), with code-capacity BP-OSD performance and pseudo-thresholds reported for the champions of each weight class.

## Methodology

The unit of evolution is a **program that generates an entire parameterized code family**, indexed by a scaling parameter t, not a single parity-check matrix — the same design choice as IBM's evolutionary bivariate-bicycle search. Each family program specifies a finite host group G(t), two protograph matrices A(t), B(t) with their shapes and t-scaling, an assignment of subgroups to protograph row/column types, and local terms that are 𝔽₂ sums of double-coset orbits K_i g K_j. A deterministic assembler projects entries onto canonical double-coset representatives (repeated orbits cancel mod 2) and applies balanced-product incidence rules to produce H_X(t), H_Z(t).

The **fixed evaluator** instantiates the program over t ∈ [1,500], skips groups of order above 20,000, keeps only assemblies with 40 ≤ n ≤ 400, and retains a parameter point only if H_X H_Zᵀ = 0, k = n − rank(H_X) − rank(H_Z) > 0, and the overall weight constraint holds. The weight definition (Eq. 1) is deliberately conservative: w = max{max row weight of H_X, max row weight of H_Z, max_q [deg_X(q) + deg_Z(q)]}, i.e. it bounds both stabilizer weight and *total check interactions per qubit*. The paper notes this is stricter than common conventions — e.g. the [[300,60,14]] code of Ref. [34] has check weight 9 and per-sector qubit degree 6 but overall weight 12 under Eq. 1. Up to three representative t values are scored per family (largest k, highest k/n, next-largest k); each representative is canonically labeled as a three-colored Tanner graph via BLISS and discarded if isomorphic to an archived code. The proxy score is Q_proxy = k·d̃²/n with d̃ = min(d_ub, 1.3√n), the cap preventing a loose upper bound from dominating selection.

**Scheduling** balances quality, coverage and freshness. Weight class is sampled with an ε=0.3 uniform floor plus a √(1+M_w) term; niche weight W_j = q_j c_j f_j combines an annealed log-normalized quality factor (τ annealed 0.6 → 0.3), a coverage factor rewarding sparsely represented group families and rate bins (β=0.5), and a freshness factor f_i = 1/√(1+D_i+B_i) where B_i penalizes unproductive lineages. Mutation-level probabilities interpolate geometrically from (1/3, 1/3, 1/6, 1/6) to (0.50, 0.30, 0.08, 0.12) over the campaign, shifting from structural L3/L4 exploration toward L1/L2 refinement. The curator was invoked every 25 evaluated candidates; the researcher council every 50, or after eight consecutive unsuccessful evaluations. Worker sessions were capped at 40 agent turns and submit exactly one final family program plus a free-form note recording variants tried and dead ends, which is passed to later workers in the lineage.

**Evaluation of results**: MILP certification solves, for each of k logical generators in each Pauli sector, a minimum-Hamming-weight problem over operators commuting with the checks and anticommuting with the chosen dual generator (2k subproblems cover the logical group), warm-started by QDistEvol witnesses. Code-capacity simulations apply independent depolarizing noise (p/3 each for X, Y, Z), decode X and Z sectors separately with minimum-sum BP (parallel schedule, 5,000 iterations, scaling 1.0) followed by order-4 combination-sweep OSD via the `ldpc` package, at p = 0.02…0.10, with no per-code tuning.

## Results & Highlights

- **w = 7 headline:** the [[288,16,18]] code reaches Q = kd²/n = 18.00 with a MILP-certified exact distance, which the authors state is the strongest known code in this weight class under Q and *exceeds the highest value derivable from the distance upper bound of Ref. [18], Q ≤ 17.78*. The upper-bound companion [[384,16,≤24]] raises the w=7 endpoint to Q ≤ 24.00.
- **w = 6:** [[336,12,20]] attains Q = 14.29, i.e. within 7% of the leading exact code in the comparison, the [[340,16,18]] generalized-bicycle code at Q = 15.25 — so at w=6 the framework does *not* beat the literature on certified parameters. The upper-bound [[400,16,≤22]] reaches Q ≤ 19.36 vs Q ≤ 19.20 for the best-known weight-six bivariate-bicycle code [[360,12,≤24]] (a thin +0.16 margin, and both are upper-bound endpoints).
- **w = 8:** the finite-Heisenberg-group [[378,32,19]] gives Q = 30.56, with [[288,24,18]] at 27.00 and [[224,22,16]] at 25.14 from distinct constructions — described as *competitive with* (not beating) the recently reported strongest code in this class [42]. The upper-bound [[336,24,≤24]] reaches Q ≤ 41.14, just under the benchmark Q ≤ 41.41 of [[306,22,≤24]] — again a loss, honestly reported.
- **w = 9 and w = 10:** [[288,18,18]] gives Q = 20.25, exceeding the previously known best in that class [43]; [[234,28,18]] and [[372,44,18]] reach Q = 38.77 and 38.32, both surpassing the strongest previous *exact* code at w=10 [20]. Upper-bound candidates go much higher — [[390,32,≤32]] at Q ≤ 84.02 and [[384,18,≤28]] at Q ≤ 36.75 — but are uncertified.
- **Decoding performance:** under the shared BP-OSD protocol, [[400,16,≤22]] beats *both* bivariate-bicycle benchmarks ([[288,12,18]] and [[360,12,≤24]]) at every sampled physical error rate; the other three discovered codes at w=6,7 only "perform comparably". Pseudo-thresholds of the ten parameter champions span 5.40% ([[234,28,18]], w=10) to 9.30% ([[336,12,20]], w=6). At p = 0.03 all ten have per-logical error rate ε_L ≤ 1.68 × 10⁻⁵ and eight are below 10⁻⁶ (e.g. [[336,12,20]] at 3.07 × 10⁻⁷, a zero-failure upper confidence limit over 10⁶ shots).
- **A negative trend the paper flags itself:** pseudo-threshold decreases monotonically with w even though higher-w classes contain much higher-Q candidates (9.30% at w=6 → 5.40% at w=10). They verify this is not an artifact of their codes by measuring the weight-ten generalized-bicycle [[254,28,14–20]] under the same protocol, obtaining 5.44%, and conclude BP-OSD as implemented is simply better matched to lower-weight Tanner graphs.
- **Structural exploration:** five genuine balanced products with non-normal K were found — [[368,18,16]] over A₆ × ℤ₂ (Q = 12.52, exact), [[336,12,≤24]] over PSL(2,11) (Q ≤ 20.57), [[248,12,18]] over PSL(2,13) (Q = 15.68), [[396,8,≤32]] over ℤ₃₁ ⋊ ℤ₆ (Q ≤ 20.69), [[306,8,≤25]] over (ℤ₁₇²) ⋊_swap ℤ₂ (Q ≤ 16.34). Note these Q values are *well below* the lifted-product leaders in the same weight classes (e.g. 12.52 vs 20.25 at w=9).

## Authors & Credibility

Dongheng Qian (State Key Laboratory of Surface Physics, Department of Physics, Fudan University; Shanghai Research Center for Quantum Sciences) and Tianyi Li (University of Wisconsin–Madison), listed as equal contributors. This is a two-author paper with no institutional AI-lab affiliation, which cuts both ways: the qLDPC construction work is grounded in the balanced-product literature (Breuckmann–Eberhardt, Panteleev–Kalachev, Bravyi et al.) and the evaluation protocol (BLISS canonical labeling, QDistEvol/QDistRnd, Gurobi-attested MILP, the `ldpc` package) is standard and appropriately cited, but the agentic-systems side is engineering-heavy with no systems-level evaluation. Tianyi Li is a co-author of MadEvolve (evolutionary optimization of cosmological algorithms with LLMs, ref [40]), so the program-evolution machinery is a natural extension of prior work. The paper is transparent about concurrent work: a footnote acknowledges OmniQEC (arXiv:2607.25865), which also uses agents for QEC-code discovery, and distinguishes it by system architecture, optimization objective and search scope rather than claiming priority.

## Critical Assessment

**Novelty (moderate-to-good on the code side, unproven on the agent side).** The genuinely new technical piece is elevating the subgroup action to an independent mutation level (L3) so that coset-orbit balanced products with non-normal K enter the search space — this is a real generalization of ref [27]'s three-level lifted-product SCE. The reported codes appear to be new instances at several weight classes. But the paper's own stated "principal methodological advance over AlphaEvolve-style systems" — the explicit scientific-reasoning cycle with hypotheses, lessons and anti-lessons — is asserted, not demonstrated. There is **no ablation** removing the researcher council, removing the curator/lesson memory, or replacing the MAP-Elites niching with plain fitness selection. Given that the whole selling point is "structured agentic search can contribute to scientific discovery", the absence of even one control run (e.g. the same evaluator + same compute budget under fitness-only evolution) is the paper's largest hole. Similarly, the elaborate lesson-confidence formula C = (1+p+s)/(2+p+s+c) and the 10%-dispatch-budget guard for lesson-testing tasks are presented without any evidence that they changed the outcome.

**Rigor (mixed, but honest).** The distance methodology is unusually careful for this literature: exact distances require solver-attested global optimality with replayable 𝔽₂ evidence bundles, and the 1.3√n credibility cap on d_ub prevents loose bounds from hijacking selection. The literature comparison set is large (1,209 instances, 91 sources) and evidence-labeled. Against that, a large fraction of the flashiest numbers are *upper-bound endpoints*: [[390,32,≤32]] at Q ≤ 84.02 is more than 2× any certified result in the paper and could collapse if the true distance is materially below 32. The w=6 and w=8 comparisons are honest losses ([[336,12,20]] Q=14.29 vs 15.25; [[336,24,≤24]] Q ≤ 41.14 vs 41.41), which increases trust in the w=7/9/10 wins. Two smaller concerns: (i) the code-capacity comparison uses only two BB benchmarks, both from the same source [10], and non-BB codes stop after exactly 10,000 block errors while the BB references use the full 10⁶ shots — the confidence-interval construction differs (negative-binomial vs Clopper–Pearson) between the compared curves; (ii) no compute cost is reported anywhere — number of candidates evaluated, LLM token/dollar spend, wall-clock time, or how many independent campaigns were run. Without that, "the agent-guided allocation is *expected* to use the verification budget more efficiently than uniform escalation" (their wording) remains a hypothesis.

**Reproducibility (weak at present).** Construction, search and evaluation code, plus detailed records for the 1,209-instance comparison set, are all "made publicly available upon publication" — nothing is released now. Explicit constructions of the highlighted codes are in Supplementary Information, so the *codes* are checkable even if the *search* is not. The agent stack is also a moving target: it hard-depends on Claude Code with Opus 4.8 for the council/curator and Sonnet 5 for the worker, so exact replication will decay with model deprecation.

**Significance (real but bounded).** "Practical" is doing heavy lifting in the title. The practicality argument rests entirely on n ≤ 400, w ≤ 10 and code-capacity noise. There is no circuit-level or phenomenological simulation, no syndrome-extraction circuit depth or scheduling analysis, and no connectivity/routing feasibility check — all of which are exactly what separates a hardware-relevant qLDPC code from a good parameter tuple. The overall-weight definition bounds check degree, but degree is not layout. The paper's own discussion concedes that decoder feedback is not in the search loop and that girth ≥ 6 constraints were not imposed.

**Red flags.** Mild overclaiming in framing ("practical", "hardware-relevant candidates") relative to the code-capacity-only evidence; headline Q values that mix certified and uncertified distances in the same tables and figures (mitigated by distinct markers and ≤ notation, but easy to misread in the abstract, which lists [[336,12,≤24]] alongside exact codes); and a methodological claim about agentic reasoning with no controlled comparison. Nothing looks like cherry-picking of benchmarks — if anything the comparison set is broader than typical — and the losses are reported plainly.

## Strengths

- Genuinely careful distance handling: MILP certification with proven global optimality, replayable witnesses, and an explicit refusal to report uncertified distances as exact.
- Honest reporting of weight classes where the search loses to the literature (w=6, and the w=8 upper-bound endpoint), and a self-directed falsification check on the pseudo-threshold trend using a literature weight-ten generalized-bicycle code.
- The 1,209-instance, 91-source, evidence-labeled comparison set is a real contribution on its own and is far more thorough than the one- or two-baseline comparisons common in this area.
- The four-level program representation is a clean, mutation-friendly abstraction, and the discovered codes span 1×1 up to 5×5 base-matrix shapes and free/normal/non-normal actions, showing mutations fire at every level rather than one.
- A conservative overall-weight definition that penalizes the paper's own codes relative to looser conventions used elsewhere.
- Intellectual honesty on the negative result: genuine balanced products lose to lifted products in this regime, and the authors say so and conjecture why, instead of burying it.

## Limitations

- No ablation of the agentic architecture; the central methodological claim is untested against fitness-only program evolution or a single-agent baseline.
- No compute/cost accounting (candidates evaluated, tokens, wall clock, number of campaigns), so search efficiency claims cannot be assessed.
- Code-capacity noise only; no circuit-level noise, syndrome-extraction circuits, or hardware layout/routing analysis despite the "practical" framing.
- Several headline Q values are upper-bound endpoints (up to Q ≤ 84.02) that may not survive certification.
- Decoder is fixed BP-OSD with no per-code tuning and is not inside the search loop; the monotone pseudo-threshold decline with w suggests Q = kd²/n is a partially misaligned objective for operational performance.
- Search restricted to binary CSS codes, n ≤ 400, 6 ≤ w ≤ 10, host groups of order ≤ 20,000 — the conjecture that lifted products intrinsically dominate is scoped to exactly this window.
- Code and full data not yet released; agent stack tied to specific proprietary model versions.
- Asymmetric shot budgets and interval types between discovered codes (adaptive stop at 10,000 block errors) and BB references (fixed 10⁶ shots).

## Relevance

这篇论文对关注 **LLM 多智能体自演化研究循环**（researcher council / curator / MAP-Elites / 可执行程序演化 / 长时程记忆）的读者价值很高——它是一个把 AlphaEvolve 式程序演化与显式"假设-证据-lesson"科学推理层拼接起来、并且有确定性外部评估器（而非 LLM judge）的完整落地案例，架构细节（调度公式、lesson confidence、分级验证预算）写得足够具体可复刻。同时它也提供了一个反面教材：整套 agentic 设计缺少消融实验，正好说明自演化研究框架论文最该补的那个对照组是什么。

## Questions for Further Exploration

- What does the same evaluator + same candidate budget produce under (a) fitness-only program evolution with no council/curator, and (b) random mutation within the four-level representation? Without this the "structured agentic search" claim is unfalsifiable.
- How many candidates were evaluated in total, and what fraction of the 10⁶-iteration QDistEvol budget was spent on curator-commissioned versus automatically escalated verifications? Did agent-directed allocation actually tighten more bounds per unit compute?
- Do the upper-bound stars survive MILP certification — specifically [[390,32,≤32]] (Q ≤ 84.02) and [[384,18,≤28]] (Q ≤ 36.75)? If their true distances are, say, 26 and 22, the "substantially improve the known frontier" claim weakens considerably.
- Under circuit-level noise with a concrete syndrome-extraction schedule, do the w=9/10 champions retain any advantage, given their code-capacity pseudo-thresholds are already the worst in the set (5.40–6.55%)?
- Does the "lifted products intrinsically favored" conjecture break at n > 400 or w > 10, where the extra orbit geometry of genuine balanced products has room to pay off?
- Would putting decoder feedback (or a girth ≥ 6 Tanner-graph constraint) directly into Q change which niches the archive fills, given the observed Q-vs-pseudo-threshold anticorrelation across weight classes?
- How much of the lesson/anti-lesson memory was actually load-bearing — i.e. how many lessons reached the 0.85 "confirmed" threshold, and were any demoted by counterexamples during the reported campaign?
