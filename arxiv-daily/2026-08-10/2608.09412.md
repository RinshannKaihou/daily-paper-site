> **一句话总结：** KVDiagnosis 用「同源配对」的方式为 8 种 KV-cache 压缩方法在 Qwen3-8B 上跑满 59,800 次压缩推理，抽取 12,520 条「FullCache 答对、压缩后答错」(C→W) 失败行，并配上缓存保留率/似然漂移/注意力/解码四类可用性受控的诊断量——结果显示 63.2% 的失败源于证据 token 覆盖率低或部分丢失，10 个诊断量对 C→W vs C→C 的分层 AUROC 达 0.684–0.871，而对 96 条可复现的低 EAR 失败施加 4× 证据注意力加权可修复 29.2%（sham 对照仅 6.3%），证明失败原因可被定位而非只能被排名。

> **TL;DR:** Aggregate task scores tell you *that* KV-cache compression broke an answer, not *why*. KVDiagnosis runs all 8 verified compressors (StreamingLLM, SnapKV, TOVA, KeyDiff, ThinK, ChunkKV, AdaKV, QuantizedCache) × 3 settings × 2,600 sources (RULER-8K/16K, Qasper, HotpotQA) on Qwen3-8B — 59,800 supported runs, each paired against a per-source FullCache control — then extracts each cell's *own* 12,520 C→W failure rows and attaches only mechanism-valid diagnostics. Headline findings: at the light tier TOVA/AdaKV/SnapKV/QuantizedCache differ by ≤0.3 task points yet their C→W rates span 0.8–2.0% (a 2.5× gap invisible to aggregate scores); SnapKV vs TOVA have near-identical mean scores (84.8 vs 85.7) but failure-set Jaccard ≤0.38 in 11 of 12 workload–setting cells; 63.2% of failures show low/partial evidence coverage; all ten diagnostics separate failure from success (stratified AUROC 0.684–0.871, gold-rank shift best at 0.871); and a causal 4× evidence-attention boost repairs 29.2% of 96 low-EAR failures vs 6.3% for a count-matched sham (+22.9 pts, McNemar p=2.98e-6). Worth reading if you build or evaluate KV compressors; skip if you only want a compressor leaderboard — the paper explicitly refuses to produce one.

## 核心贡献

- **25 方法分类法与诊断适用性映射**：把 KV-cache 压缩方法按「主要压缩决策 + 被变换的缓存对象」归入五大机制族（token 驱逐/位置选择、预算分配/层级、query 感知访问/通道剪枝、张量/表示压缩、chunk/语义/学习状态），并明确标注每族哪些诊断量合法——例如 ThinK（剪 key 通道）和 QuantizedCache（降精度）只能记录「结构性位置可寻址」，ERR/ECov 必须记 N/A，而不是伪造成 1.0。
- **无选择偏差的配对评测协议**：FullCache 每个 source 只跑一次并复用；每个受支持的 (method, setting) 单元必须覆盖固定 split 的全部 source；只有在整个 run matrix 跑完之后，才从**该单元自己的结果**里抽取 C→W 行。这样任何一个压缩器都不会替别的压缩器定义测试集。
- **十个诊断量 + 显式缺失语义**：缓存侧（ERR 证据保留率、ECov 证据覆盖率，按 layer–KV-head slot 平均以避免跨头取并集造成虚假满覆盖）、似然侧（ΔNLL、GPR、KL、Top-50 重叠、gold-token 排名漂移）、访问侧（EAM/EAR/NEAE）、解码侧（首/均 gold rank、停止原因）。缺失值一律记 N/A 并附原因，绝不插补或当作 0。
- **可复现的配对经验资源**：62,400 条记录、59,800 次成功压缩推理、48,898 个 FullCache-correct 配对、12,520 条 C→W 行、2,094 个受影响 source，全部带模型 revision、prompt hash、软件版本与 checksum。
- **一次真正的干预实验**：不止相关性——对低 EAR 失败行的保留证据位置的 attention logits 加 log 4，在 cache 与 decoder 完全冻结的条件下修复 28/96；等量非证据位置的 sham 干预只修 6/96；对 92 条匹配的 C→C 成功样本只造成 3 条退化。
- **诚实的排除审计**：PyramidKV 因适配器缺陷（tracker 用通用固定预算路径覆盖了 `get_layer_budget`，导致 7,800 对样本的 retained-index 与输出 hash 与 SnapKV 完全相同）被整体剔除而非重新贴标签，并公开哈希证据。

## Key Contributions

- **A 25-method taxonomy tied to diagnostic validity.** Methods are placed by primary compression decision and transformed cache object into five families; the paper then states, per family, which measurements are even *definable*. This is the paper's real conceptual move: "50% retention" means half the token positions for SnapKV, fewer key channels for ThinK, and 4-bit tensors for QuantizedCache, so no byte-equivalence is assumed and settings rank severity only *within* a method.
- **Selection-bias-free failure extraction.** FullCache is executed once per source and reused as the matched control; every supported (method, setting) cell covers the entire fixed split; C→W rows are extracted only after the full run matrix completes, separately per cell. Unsupported settings, execution errors, and inapplicable traces carry distinct status codes instead of silently vanishing from denominators.
- **Ten diagnostics with explicit applicability states.** Four states are recorded: *measured* token coverage (direct position maps), *projected* coverage (ChunkKV's chunk→token map), *structural position addressability* (ThinK, QuantizedCache — positions addressable but representation fidelity unknown), and *N/A*. ERR/ECov are numeric only in the first two states.
- **A released paired dataset**: 62,400 records → 59,800 supported runs → 48,898 FullCache-correct pairs → 12,520 C→W rows over 2,094 unique sources, with regeneration scripts, dependency pins, artifact checksums, and license audits (RULER Apache-2.0, Qasper CC BY 4.0, HotpotQA CC BY-SA 4.0).
- **A controlled repair intervention** validating one diagnostic route (low EAR ⇒ evidence-access/routing deficit) against both a sham and a C→C safety control.
- **A negative-result audit** excluding PyramidKV after discovering its adapter silently collapsed to SnapKV's fixed-budget path — with hash-level evidence across 7,800 pairs from different Slurm jobs (84.2% different nodes).

## Methodology

**Scope.** Only inference-time transformations that change the stored KV representation or the entries available to one attention operation, with model parameters fixed. Architectural KV-head reduction, paging, offloading, scheduling, and cross-request reuse are explicitly out of scope, as are latency, throughput, byte, and energy measurements.

**Evaluation units.** Four record types prevent ambiguity: a *source* is one task prompt; a *run record* pairs a source with one method and configured setting (including settings the implementation does not support); a *supported run* completes compressed inference; a *failure row* is a supported run whose paired FullCache answer is correct and compressed answer is wrong. Because one source can yield several failures across cells, run-, row-, and unique-source counts differ (59,800 / 12,520 / 2,094).

**Adapters.** A task adapter fixes source ID, prompt template, model input, reference answer, scorer version, and context length *before* compression, and aligns evidence spans after final-prompt tokenization (offsets shift once instructions and chat formatting are added). RULER generators supply exact answer-bearing spans; Qasper and HotpotQA map official support text into the prompt. Crucially, a failed alignment never removes a source from the split — it only makes that one cache diagnostic unavailable. A method adapter returns status, configured setting, actual method parameter, output, scorer input, and code/config versions, plus retained token/block/chunk → original position maps where valid. Attention traces come from a separate eager-mode run used **only when compression behavior is unchanged**, so inspectability confers no evaluation advantage.

**Metrics.** Quality is the ordinary mean score over all sources. The compression-induced failure rate r^CW divides |F| by all FullCache-correct supported instances in the cell. Cache metrics: ERR_z averages |R∩E|/|E| over layer–KV-head slots u, and ECov_z counts spans with per-slot coverage ≥ τ=0.5 — slot averaging is deliberate, to stop a cross-head union from producing artificial perfect coverage. Predictive metrics: ΔNLL = NLL^C − NLL^F on teacher-forced reference tokens, GPR = e^(−NLL^C)/(e^(−NLL^F)+ε), plus KL, Top-50 overlap, and gold-token rank shift. Access metrics: EAM (answer-time attention mass on evidence over the common layer–head–answer-step domain), EAR = EAM^C/EAM^F on that same domain, NEAE = EAM normalized by the evidence share of context. Every diagnostic mean is taken over F ∩ A^q where A^q is the applicability set; empty intersections are N/A, never zero.

**Diagnostic categorization.** Six predeclared, mutually exclusive rules assign a category to each of the 12,520 rows; two or more matches → Conflicting, no match → Ambiguous. Missing fields cannot trigger a rule.

**Setup.** Qwen3-8B (pinned revision) in bf16 on one NVIDIA H200, PyTorch 2.11.0+cu128, Transformers 5.2.0, kvpress 0.5.3, greedy decoding, one deterministic result per cell (so figures carry no error bars). Cross-model transfer uses Falcon3-7B-Instruct and Mistral-Small-24B-Instruct-2501 with model-native slot geometry.

## Results & Highlights

- **Aggregate scores hide a 2.5× difference in failure frequency.** FullCache scores 90.0 mean / 81.8% binary accuracy over 2,600 sources. At the light tier (75% retention, 8b), TOVA (89.8), AdaKV (89.8), SnapKV (89.7), and QuantizedCache (89.9) all sit within 0.3 points of each other — yet their C→W rates are 1.1%, 1.3%, 2.0%, and 0.8% respectively, a 2.5× spread that the score column cannot express.
- **Similar mean scores, disjoint failure sets.** SnapKV and TOVA each contribute 7,800 compressed runs with mean scores of 84.8 vs 85.7 (a 0.9-point gap), but their failure-set Jaccard overlap is ≤0.385 in 11 of 12 workload–setting cells (RULER-8K: 0.24/0.14/0.28; RULER-16K: 0.29/0.14/0.17; HotpotQA falls 0.38→0.22 as compression tightens). The single exception is Qasper/25% at 0.70. Interchangeable rankings ≠ interchangeable compressors.
- **Aggressive-tier collapse is mechanism-specific, not uniform.** At 25%/2b, TOVA and AdaKV hold 79.1 and 80.0 mean task score, versus 33.3 for StreamingLLM and 54.8 for ChunkKV. QuantizedCache falls off a cliff between 4b (89.3, C→W 3.1%) and 2b (14.6, C→W 87.2%). ThinK collapses one tier earlier: 97.7/96.3 task score at 75% on RULER-8K/16K → **0.0 at 50%** with a 100% C→W rate, and 25% is unsupported entirely.
- **63.2% of failures are evidence-coverage failures.** Of the 12,520 C→W rows, 5,047 (40.3%) have low mapped ECov < 0.50 and 2,866 (22.9%) have partial coverage in [0.50, 0.90). On evidence-annotated QA the same combined share holds: 212/327 Qasper failures (64.8%) and 535/827 HotpotQA failures (64.7%). Within position-selection methods, mean ECov drops from 0.262→0.074 (StreamingLLM) and 0.951→0.445 (TOVA) between 75% and 25%.
- **"Positions retained" is not "information retained."** Only 19 rows (0.2%) combine mapped ECov ≥ 0.90 with ΔNLL ≥ 1, but 2,126 rows (17.0%) show the same drift under *structural* addressability (ThinK/QuantizedCache), where fidelity is unmeasurable. On RULER-16K, ThinK at 50% flips **all 951** FullCache-correct sources with mean ΔNLL 7.958 and GPR 0.015; QuantizedCache at 2b flips 883 of 951 with ΔNLL 2.230 and GPR 0.260. One Qasper case shows ThinK turning "Groningen Meaning Bank" into a repeated "The" sequence at ΔNLL 15.435 while every evidence position is still nominally addressable.
- **All ten diagnostics beat chance against a 4,936-run C→C control ledger.** Stratified AUROC: gold-rank shift 0.871, KL 0.869, ΔNLL 0.853, −log GPR 0.853, Top-50 disagreement 0.850, EAR loss 0.823, ERR loss 0.749, ECov loss 0.747, EAM loss 0.702, NEAE loss 0.684. So the diagnostics are not properties shared by *every* compressed run — they discriminate.
- **The causal intervention is the strongest single result.** Of 104 rows matching only the low-EAR rule, 96 reproduce under the eager-attention baseline. Adding log 4 to the attention logits of retained gold-evidence positions (cache and decoder frozen) repairs **28/96 = 29.2%**; boosting an equal number of deterministic non-evidence positions repairs **6/96 = 6.3%** — a paired difference of 22.9 pts (95% paired-bootstrap CI 14.6–32.3; two-sided exact McNemar p = 2.98×10⁻⁶). The same boost degrades only 3/92 = 3.3% of matched C→C controls.
- **Coverage diagnoses transfer across models; quantization drift does not.** Pooled QA C→W rate from light to aggressive tier rises 8.9%→38.7% (Qwen3-8B), 7.7%→29.5% (Falcon3-7B), 2.1%→15.9% (Mistral-24B). Slot-ECov across the 18 position-method setting cells correlates with Qwen at ρ = 0.969 (Falcon) and 0.957 (Mistral), both p < 10⁻⁹, with all six methods declining monotonically. But QuantizedCache's failure-row mean ΔNLL on RULER-16K is 2.153 on Qwen versus 0.348 (Falcon) and 0.021 (Mistral) — a two-order-of-magnitude model dependence.
- **Diagnostic-metric availability is itself a finding.** EAR is defined for only 7,038 rows (56.2%) and Top-50 for 8,400 (67.1%); 1,556 rows (12.4%) trigger conflicting rules and 397 (3.2%) match none. The paper reports these as N/A rather than imputing.

## Critical Assessment

**Novelty (moderate-high, but methodological rather than technical).** No new compressor, no new model, no new task. The contribution is an evaluation protocol — specifically the ordering constraint (complete the run matrix, *then* select each cell's own C→W rows) and the applicability-state discipline (ERR/ECov are N/A, not 1.0, for channel-pruning and quantization). Both are correct and both are genuinely absent from prior work; Table 1's comparison against Gao et al. [13] (thresholded negative-sample benchmark) and Chen et al. [5] (instruction-level failure study) is fair rather than strawmanned. The taxonomy itself is the least novel piece — 25 methods sorted into five families overlaps substantially with existing surveys [25, 41].

**Rigor (high, with specific soft spots).** The PyramidKV exclusion audit is exemplary and rare: rather than quietly dropping a method, the authors documented that the tracker replaced `compress` with a generic fixed-budget path bypassing `get_layer_budget`, verified identical retained-index and output hashes across all 7,800 pairs from distinct Slurm jobs (84.2% distinct nodes, ruling out file-copy artifacts), and excluded the rows rather than relabeling them. That said: **the Qasper and HotpotQA denominators are alarmingly small.** FullCache is correct on only 59/200 Qasper sources (task score 29.5) and 148/200 HotpotQA sources. Every Qasper C→W percentage in Table 11 is computed over 59 instances, so a single flipped answer moves the rate by 1.7 points — and the paper's headline "Qasper/25% Jaccard = 0.70" exception is drawn from that same 59-source pool. The paper does flag this ("their values describe this evaluation set"), but Figure 4A and Figure 9A still plot Qasper alongside the 968/951-source RULER workloads without visual weighting. Second, the QA scorer is explicitly **benchmark-specific rather than official**: it awards the fraction of references found as substrings and marks correctness only at 1.0. Substring containment on a 29.5-point FullCache baseline means the C→W label itself is noisy for Qasper in a way exact-match RULER scoring is not.

**Missing ablations.** (a) The intervention uses a single boost magnitude — log 4, i.e. 4× — with no sweep. Whether 2× repairs 15% or 29%, and whether 16× starts damaging C→C controls beyond 3.3%, is unknown, so the effect size is anchored to one arbitrary hyperparameter. (b) The low-EAR cohort is n=96 and Qwen-only; attention AUROC and all interventions are Qwen-only by the authors' own admission in §5.6. (c) ECov's threshold τ = 0.5 is asserted without sensitivity analysis, and the 0.50/0.90 category boundaries in Table 4 are equally unjustified — since 63.2% of the headline share is exactly the sum of two threshold-defined buckets, that headline number is threshold-dependent. (d) Only one setting-triple per method (75/50/25); ThinK's catastrophic 97.7 → 0.0 cliff between 75% and 50% is precisely the region a finer sweep would illuminate, and instead it is left as "collapses."

**Data quirks.** ThinK/25% is unsupported, so 2,600 records are N/A by construction and every "all methods" comparison at the aggressive tier is actually seven methods. QuantizedCache's 8b/4b/2b tiers are mapped onto the 75/50/25 columns in figures despite the paper insisting no byte equivalence holds — the visual grouping quietly reintroduces the cross-mechanism comparison the text forbids. Sources recur across cells, which the authors correctly handle by calling all AUROC confidence intervals "descriptive," but pooled percentage shares over 12,520 rows are still over rows, not independent sources (only 2,094 unique sources are involved — roughly 6 rows per source).

**Reproducibility (high).** Pinned model revision hash, exact library versions, single-GPU determinism (one result per cell, hence no error bars), released regeneration scripts, checksums, and verified dataset licenses. Determinism is genuine here because decoding is greedy and only the cache path varies. The main barrier to third-party reproduction is compute: 59,800 primary-model runs plus cross-model sweeps is not a weekend project.

**Significance (high for the subfield).** The finding that SnapKV and TOVA — routinely treated as interchangeable in the literature — fail on largely disjoint source sets (Jaccard ≤0.38) directly undermines how KV compression papers currently justify method choice. The structural-addressability point (2,126 rows drift while every evidence position remains "retained") is a concrete warning that quantization and channel-pruning papers reporting retention statistics are reporting something that does not measure what readers assume.

**Red flags.** Mild overclaiming in the abstract's framing of the taxonomy as a "contribution" when 17 of 25 methods are survey-only and never touched experimentally. The phrase "all ten diagnostics separate failed from successful compression" is true but the weakest (NEAE, 0.684) is barely above the 0.65 threshold most would call useful, and the two cache-side metrics (ERR 0.749, ECov 0.747) — which the paper's own 63.2% headline rests on — are mid-pack, weaker than the likelihood metrics that require no evidence annotation at all. That is an uncomfortable result the paper does not dwell on: if ΔNLL (0.853) predicts failure better than evidence coverage (0.747), the elaborate evidence-alignment machinery may be earning less than its cost. Also note the KDD '27 venue and 2027 copyright line on a 2026 preprint — this is a submission, not an accepted paper.

## Strengths

- The evaluation-ordering discipline (complete matrix → per-cell C→W extraction) is a genuinely correct fix for a real selection bias, stated precisely enough to be adopted by others.
- Applicability states with mandatory N/A semantics are the right answer to a problem the field has been papering over; "no imputation, no zeros, empty intersection is N/A" is stated and enforced.
- The layer–KV-head slot averaging in ERR/ECov is a thoughtful detail — a naive cross-head union would report near-perfect coverage for almost any method and quietly kill the metric.
- The intervention/sham/C→C-safety triad turns one diagnostic from correlation into something closer to a causal claim, with proper paired statistics (McNemar, paired bootstrap) rather than an unpaired t-test.
- The PyramidKV exclusion audit, published with hashes and job-distribution evidence, is the kind of negative result almost nobody bothers to write up.
- Cross-model validation is framed honestly: the *procedure* generalizes (ρ ≈ 0.96 rank correlation on slot-ECov), the *magnitudes* do not (QuantizedCache ΔNLL 2.153 vs 0.021).
- Explicit refusal to produce a composite score or a cross-mechanism ranking, repeated at multiple points, is intellectually consistent with the paper's own argument.

## Limitations

- **Single primary model.** All diagnostic-category shares, all AUROC values, all attention traces, and the entire intervention are Qwen3-8B-only. Falcon3-7B and Mistral-24B are used only for coverage-transfer and ΔNLL comparison on a subset (RULER-16K + QA).
- **Tiny QA denominators.** 59 FullCache-correct Qasper sources and 148 HotpotQA sources drive several highlighted percentages, including the one Jaccard cell (0.70) that contradicts the paper's main disjointness claim.
- **Non-official QA scorer.** Normalized substring containment with a 1.0 correctness cutoff; the Qasper FullCache score of 29.5 suggests the scorer is harsh, and C→W labels inherit that harshness.
- **Diagnostic availability is partial.** EAR exists for 56.2% of rows, Top-50 for 67.1%; 15.6% of rows are Conflicting or Ambiguous. The clean six-category story covers roughly 84% of the corpus.
- **No efficiency axis at all.** Latency, throughput, actual bytes, and energy are explicitly out of scope, so the benchmark cannot answer whether a method's failure rate is worth its memory saving — and since settings are not byte-equivalent across mechanisms, it cannot even normalize the comparison.
- **Threshold sensitivity unexplored.** τ=0.5 for ECov, 0.50/0.90 coverage boundaries, ΔNLL ≥ 1, EAR < 0.50, |ΔNLL| ≤ 0.10 — all six categorization rules are asserted, none swept.
- **Coarse setting grid.** Three settings per method; ThinK's 75%→50% collapse and QuantizedCache's 4b→2b collapse both happen inside a single unsampled interval.
- **One intervention magnitude, one signature validated.** Five of six diagnostic categories (low coverage, partial coverage, high-coverage drift, structural drift, decoding/scoring) receive no causal test — only low-EAR does.

## Relevance

如果关注长上下文推理的显存-质量权衡，这篇提供了一个可直接复用的诊断协议：它把「压缩后答错」拆成证据被驱逐 / 表示保真度受损 / 生成时访问不到 / 仅解码或打分变化四条可区分的路径，并给出每条路径对应的合法测量与不合法情形（例如量化和通道剪枝方法根本不能报 token 保留率）。对做 KV 压缩方法、LLM 评测方法论、或需要判断「两个压缩器是否可互换」的工作，其配对协议与失败集 Jaccard 分析比论文里的具体数值更有长期价值。

## Questions for Further Exploration

- Does the log 4 evidence-attention boost's 29.2% repair rate survive a magnitude sweep, and where is the crossover point at which C→C degradation exceeds C→W repair? A single point estimate at one hyperparameter is the weakest link in the paper's strongest claim.
- Given that ΔNLL (AUROC 0.853) outpredicts ECov (0.747), is the expensive evidence-span alignment pipeline actually necessary for triage — or could an annotation-free likelihood signal route most failures correctly, with coverage metrics reserved for confirmation?
- The 2,126 structural-position-drift rows are the paper's biggest unexplained bucket. Could per-layer reconstruction error (e.g. cosine distance between FullCache and dequantized K/V at evidence positions) turn "fidelity unknown" into a measured quantity, and would it separate ThinK's catastrophic failures from QuantizedCache's graded ones?
- Why is quantization drift so model-specific (ΔNLL 2.153 on Qwen3-8B vs 0.021 on Mistral-24B)? Is this an activation-outlier / RoPE-scaling property, a group_size=64 interaction with head dimension, or simply a capacity effect at 24B vs 8B?
- Would the SnapKV–TOVA disjointness (Jaccard ≤0.38) support an ensemble or router — pick the compressor per source using cheap features — and how much of the 12,520-row failure set is recoverable that way?
- ThinK's 97.7 → 0.0 collapse between 75% and 50% key-channel retention is a phase transition, not a degradation curve. Is it an implementation artifact of `window_size=32` in kvpress 0.5.3, or a real property of query-driven channel salience under Qwen3's GQA geometry? The paper excluded PyramidKV for exactly this class of adapter defect but did not apply the same scrutiny here.
- How does the protocol extend to reasoning-time compression, where the "evidence" is generated chain-of-thought rather than annotated context spans and no ground-truth support map exists?
