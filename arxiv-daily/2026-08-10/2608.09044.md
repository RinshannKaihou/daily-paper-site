> **一句话总结：** ToE 把 agent 的"经验库"从零散的轨迹/知识条目重构成一棵与推理层级对齐的「分析视角树」（根=任务目标，子节点=逐级细化的分析维度），每条根到叶的路径带一个由环境反馈校准的可靠性分数 Q，从而把 outcome-level 反馈精确归因到具体推理视角上；在 Game of 24 上准确率 85.3% vs ToT 基线 64.9%（+20.4 pts，相对 +31.4%）且平均 LLM 调用从 51.7 降到 11.0（−78.7%），在作者自建的 FinEvolveBench 上 12 个设置平均 tsIC 相对提升 41.24%，而 Mem0/MemRL 这类通用记忆方法反而普遍低于无经验基线。

> **TL;DR:** Tree-of-Experience (ToE) organizes an LLM agent's accumulated experience as a depth-constrained, width-expandable tree of *analytical perspectives* that mirrors the agent's own reasoning decomposition, with each root-to-leaf path carrying a reliability score Q calibrated by delayed environmental outcomes. On Game of 24 with DeepSeek-V4-Flash, ToT+ToE hits 85.3% accuracy vs 64.9% for experience-free ToT (+20.4 pts) and 58.4/61.6/61.1% for ToT+Mem0/MemRL/ReMe — i.e., all three prior memory methods are *worse than no memory* — while cutting LLM calls from 51.7 to 11.0 per puzzle (−78.7%). On FinEvolveBench (A-share industry sentiment → future excess return IC), ToE lifts tsIC by 41.24% on average over the Pipe baseline across 12 settings (e.g., 20d DeepSeek exploitation tsIC 0.1311 vs 0.0871). Read it if you work on agent memory / credit assignment under sparse, delayed, noisy rewards; skip it if you need statistically airtight financial results, since ICs are reported without variance or significance tests on a benchmark the same authors built.

## 核心贡献

- **提出 Tree-of-Experience (ToE)**：一种结构化经验管理范式，经验的组织方式直接对齐 LLM agent 的层次化推理过程，而非按轨迹相似度存取。经验单元定义为三元组 e_i = (Π_i, Q_i, M_i)：深度为 L 的分析路径、反馈驱动的可靠性状态、维护元数据（recall/hit 计数、节点索引、创建时间戳）。
- **明确提出经验抽象机制的四条评判标准**：可归因性（Attributability）、可迁移性（Transferability）、可演化性（Evolvability）、效率（Efficiency），并论证现有 intra-trajectory（Reflexion、MemRL、ReMe）与 inter-trajectory（FLEX、SkillGen、SkillRL）方法在至少一条上失败。
- **揭示一个反直觉的负面结论**：在复杂推理 + outcome-level 反馈的任务上，通用记忆机制会因归因错误而强化不可靠经验，performance 甚至低于完全不用经验的 baseline（Game of 24 上 Mem0 掉 6.5 pts；FinEvolveBench 上 Mem0/MemRL 在几乎所有 12 个设置都劣于 Pipe）。这是本文最有价值的实证发现之一。
- **设计了可靠性更新的两种实现**：formula-based 更新（带 usage-dependent 分母 1+log(1+n_hit) 与 boundary-aware 因子，实现"软遗忘"）与 LLM-based 更新；并做了消融证明前者更优。
- **双基准验证 + 效率证据**：在确定性反馈的数学推理任务（Game of 24）与延迟/隐式/噪声反馈的金融任务（FinEvolveBench，2025-01-02 至 2026-03-31）上分别验证，且效率提升（调用数 −78.7%）与精度提升同时达成。

## Key Contributions

- **ToE framework.** Experience pool E = {(Π_i, Q_i, M_i)} where Π_i is a depth-L path of analytical perspectives from a root (task objective / problem category) down to concrete decision criteria. Because the experience structure mirrors the reasoning structure, an observed outcome can be propagated to the *specific* perspectives that produced it, enabling localized reinforcement or revision instead of holistic re-summarization.
- **Four desiderata for experience abstraction** (attributability, transferability, evolvability, efficiency) used as an analytical lens on prior work, with a concrete argument for why flat semantic-similarity retrieval fails in *low-repetition* tasks where instances are semantically dissimilar but share analytical logic (financial news varies daily; the sentiment/fundamentals reasoning perspectives do not).
- **Negative result on existing memory systems.** Documented, on two benchmarks, that Mem0/MemRL/ReMe can degrade below experience-free baselines — attributed to their inability to attribute outcome feedback to individual reasoning components.
- **Two UpdateQ operators with an ablation.** A formula-based update with adaptive step size and soft forgetting (no hard pruning: low-reliability experience is retained as *negative* evidence), and an LLM-based updater; formula-based wins on both tsIC and csIC.
- **Task-specific instantiations.** Sequentially-dependent structure (Game of 24: nodes = canonicalized multisets of remaining numbers; binary verifier feedback η=1) vs independent-parallel structure (FinEvolveBench: 3-level industry → factor → analysis_direction tree stored as a path-based CSV, retrieving multiple complementary paths per query). Full prompt templates for reranking/expansion, merging, and prediction are released in the appendix.

## Methodology

**Tree structure and granularity.** The tree is depth-constrained but width-expandable. The root is the problem category or task objective; non-root nodes are critical reasoning perspectives, with parents capturing broad analytical dimensions and children refining/extending/diversifying them. The schema is explicitly *not* a predefined template — semantics and granularity are jointly determined by problem structure, task objective, and information needed. The initial hierarchy can be either hand-specified (tasks with well-defined reasoning procedures) or induced by recursively clustering and summarizing model-generated reasoning paths. Node creation obeys three rules: (1) semantic subsumption w.r.t. the parent, (2) genuine discriminative value (must let the model derive an additional conclusion or revise a judgment), (3) balanced granularity — too broad gives no guidance, too fine kills reuse. Expansion stops when further decomposition adds no reasoning-relevant information.

**Retrieval and path construction.** Retrieval runs *synchronously with* reasoning rather than as a one-shot pre-fetch. Given input x_t and prefix path Π^{l−1}, the context is H_l = (x_t, Π^{l−1}), and ToE reranks only the *children of the current node* — C_l = TopK(f_θ^rerank(H_l, Children(p^{l−1}))) — which is what makes retrieval cheap: the branch structure prunes the candidate set. The reranker is a prompt-based LLM that also filters irrelevant/redundant/incompatible perspectives. If nothing valid is retrieved, a prompt-based proposer generates at most k new perspectives A_l = f_θ^propose(H_l, k), each concatenated onto the prefix. New paths get a neutral reliability prior Q_i = q_0; existing paths get their stored Q. The final answer is a_t = f_θ(x_t, E_t) with E_t = {Π^L, Q(Π^L)} — the reliability values are fed to the model as activation strengths, explicitly documented in the prompt as non-directional.

**Feedback attribution and reliability update.** Delayed environmental feedback becomes r_t = ψ_τ(a_t, o_{t+h}); in FinEvolveBench r_env = a_t · o_{t+h} because performance is measured by IC. Every experience used for that outcome is updated. The formula-based rule is

Q(E_t) ← Q(E_t) + η · [1 − ((Q(E_t) − q_0)/q_0)²] / [1 + log(1 + n_hit)] · r_t,

clipped to [0, 2q_0]. The `1 + log(1 + n_hit)` denominator damps updates as evidence accumulates; the squared boundary term makes updates largest near the neutral prior and smallest near the bounds — repeatedly ineffective experiences decay in activation strength rather than being deleted (soft forgetting). The LLM-based alternative prompts the model to assign per-experience update magnitudes for finer credit assignment, at the risk of subjective bias.

**Maintenance.** Growth is controlled at the source (at most one new analysis direction per adaptive expansion in FinEvolveBench). A prompt-based LLM *merger*, triggered by embedding-based similarity search, consolidates semantically overlapping nodes. Notably, ToE deliberately does **not** prune on low reliability, since such nodes encode useful negative evidence about unreliable reasoning patterns.

**Task instantiations.** *Game of 24*: an analytical perspective is the canonicalized multiset of remaining numbers (e.g., {1,1,10,12} → {2,10,12}); operator selection and number grouping are encoded implicitly in parent→child state transitions; feedback is a deterministic verifier r_t = 1[Verify(a_t, x_t)] and the general update collapses to Q_new = r_t ∈ {0,1} (η_G24 = 1), so verifier-confirmed continuations are admitted and failures are rejected outright. *FinEvolveBench*: depth L=3 (industry / factor / analysis_direction), k₁ = 8 first-level candidates, leaf cosine-similarity threshold λ = 0.8, q₀ = 1, η = 10, separate reliability per horizon {10, 20, 40} trading days; a 5-day news window T−4…T filtered to importance ≥ 8; industry+factor routing is precomputed and cached ("decoupled execution") to speed up large-scale experimentation. Context window 32,768 tokens; backbones (DeepSeek-V4-Flash, Qwen3.6-35B-A3B) stay frozen; each method run 3× and averaged.

## Results & Highlights

- **Game of 24 accuracy (DeepSeek-V4-Flash):** ToT+ToE reaches **85.3%** vs **64.9%** for experience-free ToT — **+20.4 points, +31.4% relative**. Critically, every prior memory method *loses* to the no-memory baseline: ToT+Mem0 **58.4%** (−6.5 pts), ToT+MemRL **61.6%** (−3.3 pts), ToT+ReMe **61.1%** (−3.8 pts). The strongest experience-based baseline (MemRL, 61.6%) is beaten by **23.7 points**.
- **Game of 24 efficiency:** ToE averages **11.0 LLM calls** per puzzle vs **51.7** for ToT (**−78.7%**), while Mem0 (53.8), MemRL (51.2), and ReMe (53.0) give essentially no reduction — and ReMe additionally inflates token cost through long experience contexts at constant call count.
- **FinEvolveBench tsIC, headline:** average relative improvement over the experience-free Pipe of **+59.57% during the Exploitation phase** and **+22.92% Overall**, i.e. **+41.24% averaged across all 12 settings**. Per-backbone: **+48.61%** under DeepSeek-V4-Flash and **+33.88%** under Qwen3-35B-A3B.
- **FinEvolveBench tsIC, best single cells:** DeepSeek 40d Exploitation **0.1456 (ToE) vs 0.0843 (Pipe)** (+72.7%) and Overall **0.0899 vs 0.0595** (+51.1%); DeepSeek 20d Exploitation **0.1311 vs 0.0871** (+50.5%). Qwen 20d Exploitation **0.1387 vs 0.0746** (+85.9%).
- **The one failure case, honestly reported:** Qwen3-35B-A3B, 10d, Overall — ToE **0.0322 vs Pipe 0.0349**, i.e. ToE is *worse* than doing nothing; it still beats Mem0 (0.0132) and MemRL (0.0186) there. Gains concentrate at the 20d/40d horizons where the baseline itself is stronger.
- **Baselines collapse in the financial setting:** Pipe+MemRL Overall tsIC at Qwen 40d is **0.0135 vs Pipe 0.0677** — a 5× degradation; Pipe+mem0 at DeepSeek 40d Overall is **0.0288 vs 0.0595**. Under delayed, implicit rewards, conventional memory is actively harmful.
- **Cross-sectional IC (Table A2, Exploitation phase):** Pipe+ToE is best in all 6 backbone×horizon cells. DeepSeek 40d **0.1371 vs 0.0589** for Pipe (**+133%**) and vs 0.0356 for MemRL; DeepSeek 20d **0.1210 vs 0.0837**; Qwen 20d **0.1221 vs 0.0600** (+103%). MemRL bottoms out at **0.0064** on Qwen 40d.
- **Update-rule ablation (20-day horizon, DeepSeek, Table 3):** formula-based update **tsIC 0.0741 / csIC 0.0528** vs LLM-based **0.0598 / 0.0431** — a ~24%/22% relative advantage for the constrained numerical rule over letting the LLM adjust reliability directly.
- **Practical exclusion:** ReMe was dropped from FinEvolveBench because its day-level global extraction over 31 sector trajectories on a single date (2025-09-01) produced ~**324.5K tokens** of input, infeasible under realistic inference budgets.

## Authors & Credibility

Nine authors (Zihao Deng, Yining Zhu, Leiming Wang, Jingfei Lu, Junbo Wang, Chuncheng Ran, Yu Yang, Dixuan Yang, Jikun Shen), with no affiliation listed on the arXiv version — the paper appears to be under double-blind review (AAAI-style template). The exact same nine-author list is cited as "Deng et al. 2026" for **FinEvolveBench** (arXiv 2606.06960), the primary evaluation benchmark here. That is transparent — the citation is right there — but it means the headline benchmark is the group's own construct, and the "Pipe" baseline is the benchmark's own provided pipeline. Work is supported by a released supplementary code package. The related-work coverage is current and specific (Mem0, MemRL, ReMe, FLEX, SkillGen, SkillRL, G-Memory, MetaFlowLLM, Synapse), and the financial-prediction citations (Lopez-Lira & Tang, MANA-Net) show genuine domain familiarity rather than decoration.

## Critical Assessment

**Novelty (moderate-to-good).** "Hierarchical memory" is a crowded space — G-Memory, MetaFlowLLM, and Mem0 all structure memory. ToE's actual differentiator is narrow but real: the tree axis is *analytical perspectives aligned with the reasoning decomposition*, and each path carries a scalar reliability updated by delayed environmental reward. That combination (structure-for-attribution + bandit-flavored reliability calibration + soft forgetting) is a sensible and, as far as the related work shows, unoccupied point in the design space. The framing of four desiderata is useful but is not itself a contribution.

**Rigor (mixed; this is where the paper is weakest).** Several concrete problems:
- *The Game of 24 instantiation is arguably not the proposed method.* In the appendix, a "perspective" degenerates into a canonicalized multiset of remaining numbers, and each node stores a **verifier-confirmed successful solution suffix** reusable "when the same or a sufficiently overlapping state is encountered again." With η_G24 = 1 and binary Q, this is memoized subproblem-solution caching backed by an exact arithmetic verifier — no LLM reranker semantics, no soft reliability, no merger. That mechanism trivially explains both the +20.4 pts and the 78.7% call reduction, and it does not evidence the paper's central claim about hierarchical *analytical perspectives*. Worse, **the paper never states which Game of 24 puzzle subset is evaluated, how many instances, or the order/split between experience accumulation and scoring** — for a system that caches verified solutions across a stream of puzzles, this omission makes the number nearly uninterpretable.
- *No variance or significance testing anywhere.* The paper says each method is run 3× and averaged, but reports no std, CI, or test. IC values of 0.05–0.14 on 14 months of A-share data across ~31 industries are well inside the range where run-to-run and period-to-period noise dominate; a 0.0871 → 0.1311 difference is presented as decisive with zero uncertainty quantification.
- *Self-built primary benchmark.* FinEvolveBench, its Pipe baseline, its metrics, and its temporal splits are all from the same authors. The Exploitation/Cold-Start split (first one-third designated cold start) is applied uniformly to all methods, which is fair, but it is also a post-hoc partition that happens to be where ToE looks best (+59.57% vs +22.92% Overall).
- *Missing ablations that matter.* There is **no ablation on tree depth L** (fixed at 3), on k₁ = 8, on λ = 0.8, on η = 10, or on the merger module. There is no "flat list of the same experience content, no tree" control — which is the single most important ablation, because without it the gain could come from the *content* of the distilled perspectives rather than the hierarchical organization. There is no ToE result on Game of 24 with the Qwen backbone (Table 2 is single-backbone).
- *Baseline calibration.* The Baseline method (discrete {−1,0,1} per-news sentiment, importance-weighted) is defined in the appendix as one of "five main methods in RQ1/RQ2" but does not appear in Table 1 or Table A2. Mem0 is a production long-term-memory product not designed for outcome-calibrated reasoning credit assignment; showing it underperforms a no-memory baseline is informative but is not a hard comparison against a *well-tuned* structured-memory competitor. The strongest structurally similar prior systems (MetaFlowLLM's hierarchical workflow tree, G-Memory) are discussed but never run.

**Reproducibility (partial, honestly disclosed).** Prompts, hyperparameters, update formulas, evaluation definitions, and code are released; but the raw financial news corpus and price files are withheld for size reasons, so the headline financial results cannot be independently reproduced. Game of 24 should be reproducible in principle, except the puzzle subset is unspecified. Minor sloppiness: the backbone is written as both "Qwen3.6-35B-A3B" and "Qwen3-35B-A3B"; a section cross-reference renders as "Section ." Both backbones are unusual/very recent models, which will complicate replication.

**Significance (real, if the caveats hold).** The negative finding — that off-the-shelf agent memory can be net-harmful under delayed, implicit, multi-causal rewards — is the most transferable takeaway and is supported by 12+ settings, not one cherry-picked cell. The efficiency result (fewer calls *and* higher accuracy) matters for anyone paying for agent inference.

**Red flags.** (1) The abstract advertises "31.4% relative improvement" while the body advertises "+20.4 percentage points" for the same number — the relative framing is the flattering one and is what appears first. (2) The Game of 24 result is presented as evidence for perspective-level reasoning transfer when the implementation is solution-suffix caching. (3) Conclusion sentence "the experiments support that, under the current FinEvolveBench setting, the effectiveness and stability of structured, formula-updated experience management" is ungrammatical, suggesting a rushed submission. (4) 41.24% relative on a base tsIC of ~0.05 is a small absolute effect dressed in a large percentage.

## Strengths

- **The core insight is genuinely well-motivated:** if experience is stored in a shape unrelated to how reasoning happens, outcome feedback cannot be attributed to anything, and calibration becomes noise. Aligning the memory topology with the reasoning topology is the right response to that diagnosis.
- **Reports its own failure case.** The Qwen 10d Overall cell where ToE loses to the no-experience baseline is stated in the text rather than buried, and the authors correctly note that gains concentrate where the baseline signal is stronger.
- **The negative result on prior memory systems is the paper's most useful contribution** and is replicated across two very different feedback regimes (deterministic verifier vs delayed market returns) and two backbones.
- **Thoughtful mechanism details.** Soft forgetting instead of hard pruning (low-Q paths retained as negative evidence), the boundary-aware + usage-damped update that behaves like a decaying-learning-rate bandit, and the asymmetric success/failure treatment (success = direct evidence of feasibility, failure = probabilistic negative evidence) are all defensible design choices with stated rationales rather than arbitrary knobs.
- **Efficiency is measured, not assumed.** Reporting average LLM calls alongside accuracy, and explicitly noting that call count understates ReMe's cost because of context length, is more rigorous than most memory papers.
- **Fairness controls are enumerated:** identical backbone, context window, news pipeline, news window, importance threshold, prediction prompt, evaluation order, horizons, feedback definition, metrics, and the same pre-test historical tasks for experience initialization across all experience-based methods.
- **Full prompt templates published** (Tables A3–A5), including the format constraints that do real work — e.g., forcing analysis directions to be conclusion-free and entity-free ("From the perspective of [an intrinsic property of the factor]"), which is precisely what buys transferability across days of dissimilar news.

## Limitations

- **The paper has no Limitations section.** Everything below is inferred; the authors only concede that metadata-aware maintenance is "left for future work."
- **Only two tasks, one of which is self-authored** and the other of which is instantiated in a degenerate, verifier-dependent form. No general agentic benchmarks (WebArena, ALFWorld, SWE-bench, GAIA), no coding, no tool use — so "self-evolving agents" in the title is broader than the evidence.
- **Requires a decomposable reasoning structure and an environment reward signal.** ToE has nothing to say about tasks without a natural perspective hierarchy or without any outcome feedback.
- **Tree depth is fixed at L=3** and never varied; the "depth-constrained, width-expandable" design is asserted to be the right tradeoff rather than shown.
- **Cold-start cost is acknowledged but not quantified** — the first third of the timeline is discarded from the headline Exploitation numbers, and no measurement is given of how many interactions are needed before the tree pays for itself.
- **Financial results are single-market, single-period** (Chinese A-share industry indices, 2025-01-02 to 2026-03-31), a window that includes whatever regime happened to prevail; no walk-forward robustness across regimes, no transaction-cost or capacity analysis, and IC is not a P&L.
- **The FinEvolveBench implementation caches industry/factor routing offline** for speed. The authors argue the logical dependency is preserved, and that is plausible, but it means the reported system is not the end-to-end 3-stage router the method section describes.
- **Merger and reranker are prompt-based LLM calls** whose cost is folded into the pipeline but never separately accounted for in the FinEvolveBench efficiency discussion (only Game of 24 reports call counts).
- **No data release** for the financial corpus, so the headline 41.24% cannot be independently verified.

## Relevance

如果你关注 agent memory / self-evolving agent 的 credit assignment 问题，这篇的核心诊断（经验表示与推理结构脱节 → 反馈无法归因 → 记忆反而有害）以及"通用 memory 系统在稀疏延迟奖励下低于无记忆基线"的实证结论非常值得一读，可直接迁移到自建 agent 系统的记忆模块设计上。同时它给出了 LLM 驱动金融量化（A股行业情绪 → IC）的一套完整可复现 pipeline 与 prompt 模板，对做 LLM + 量化因子挖掘的场景有直接参考价值——但其 IC 数值缺少方差与显著性检验，不宜直接当作 alpha 结论采信。

## Questions for Further Exploration

1. **The missing control:** what happens if you take ToE's *distilled analysis directions* and dump them into a flat retrieval index with the same reliability scores, discarding the hierarchy? If the flat variant matches ToE, the contribution is the content/format constraints (conclusion-free, entity-free perspectives), not the tree.
2. **Which Game of 24 instances?** With verified solution suffixes cached across the puzzle stream, the accuracy number depends entirely on the evaluation protocol. Does 85.3% survive strict train/test separation with no state overlap between accumulation and evaluation sets?
3. **How does the tree scale?** Table A1 shows an experience with recall/hit of 22446/13209 — the tree is clearly dominated by a few heavily-reused paths. What is the node-count growth curve over 14 months, how often does the merger fire, and does the reliability distribution collapse toward the [0,2] bounds?
4. **Is the reliability score doing work, or is it the perspective text?** Ablating Q (feed retrieved paths without reliability values) would isolate how much of the gain comes from calibration versus from having good analytical scaffolds at all.
5. **Depth and width sensitivity:** does L=4 or k₁=16 help or cause fragmentation? The three node-construction rules imply an optimum, but none is empirically located.
6. **Generalization beyond the authors' benchmark:** does ToE beat Mem0/MemRL on an external, third-party low-repetition agentic benchmark with delayed rewards? Without this, the strong claim about conventional memory being harmful is entangled with FinEvolveBench's specific construction.
7. **Statistical validity:** with 3 runs already executed, what are the standard deviations on Table 1? Bootstrap CIs on tsIC/csIC would cost nothing and would settle whether 0.0741 vs 0.0517 is a real effect.
8. **Negative experience utilization:** the design keeps low-Q paths as "useful negative evidence," but no experiment tests whether the model actually avoids the associated reasoning patterns. Does showing a Q=0.2 path help more than hiding it?
