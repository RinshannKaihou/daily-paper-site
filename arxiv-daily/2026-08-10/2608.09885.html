Key metric
3.1× ↓

lower average Attack Success Rate on Agent-SafetyBench vs static SafeHarness (17.1% → 5.5%), while utility-under-attack rises 31.6% → 47.6%.

Why this matters

Treats agent guardrails as evolvable infrastructure — the four-artifact schema is reusable in your own stack even without running the evolution loop.

Critical edge

GPT-5.5 is simultaneously the evolution model writing the edits and the judge scoring Agent-SafetyBench — the anti-reward-hacking check shares the optimizer's blind spots.

Methodology

Optimize the harness, hold the model fixed.

SHE formalizes the agent stack as (πθ, E, H) and optimizes only H — the non-parametric harness — holding the base model, environment, and evaluation protocol constant. The harness decomposes into four artifacts with disjoint safety responsibilities, which is what makes failure attribution and localized editing possible:

P_sys · System Prompt
Global behavior contract & trust boundary.
R_bank · Rule Bank
allow / warn / block / sanitize / judge interventions.
M_safe · Safety Memory
Contrastive entries for failures surviving two rounds.
Q_tool · Tool Policy
Pre-call permissions + runtime detectors.

Each round rolls out a fixed 15-task evolution split under the current best harness, selects risk-relevant failures, and asks the evolution model for a structured diagnosis along three axes — harm domain, attack surface, failure mode. Diagnoses are routed to the responsible artifact, expanded into bounded edits (target, scope, operation, learned content, supporting trajectory), filtered by ValidEdit (rejects reward-hacking and unsupported capability removal), and accepted only under a strict monotone rule: safety must strictly improve and utility must not regress. Rejected edits flow back via a feedback buffer Frej to prevent re-proposal.

Eval: Agent-SafetyBench, first 200 of 2,000 tasks, 6 attack conditions × 2 reps = 180 trajectories/round; 20 rounds. Base agent DeepSeek-V3.2; evolution model & ASB judge both GPT-5.5; AgentHarm judge GPT-4o; temperature 0 throughout.

≈Two-thirds of the ASR gain over SafeHarness comes from the decomposed seed design, not the evolution loop. The loop's main purchase is utility recovery (+14.1 pts UA). This reframes the contribution: the architecture does most of the safety work; evolution unlocks utility.

Not uniformly better On tool tampering, SHE (evolved) is actually worse on ASR (8.2% vs SafeHarness 4.9%) — though its utility there is 38.6% vs 14.1%. Wins are concentrated on memory injection (6.0% vs 29.8%) and composite (1.1% vs 3.8%).
Headline isn't the safest point DeepSeek-V3.2 as evolution model converges at ASR 4.3% / UA 40.4% — strictly safer than the GPT-5.5 headline (5.5% / 47.6%). The reported config is the utility-preserving point on the frontier, not the safest.

Strengths

  • Strictly monotone acceptance rule (S must improve and U not regress) — stronger than scalarized self-evolution; 15 of 20 rounds rejected.
  • No safety–utility tradeoff: UA 47.6% beats even no-defense (38.7%); AgentHarm benign non-refusal 77.8% vs SafeHarness 68.2%.
  • Learns semantic boundaries, not keyword blocklists — e.g. "recommend apps, don't install them, don't claim you installed them" (R17).
  • Generalizes via held-out benchmark and cross-model transfer (Kimi K2.6 / GLM-5.2 / MiniMax M2.7), no re-evolution in either.
  • Unusually strong reproducibility: exact task IDs, artifact schemas, round-by-round history, temperature-0 determinism.

Limitations

  • Tiny evolution set — 15 tasks, ~180 trajectories/round is the entire safety-boundary corpus.
  • Only first 200 of 2,000 ASB tasks used; risk-category coverage of that slice unreported.
  • Single base agent (DeepSeek-V3.2) for the main run; cross-model is transfer-only.
  • No adaptive adversary — attacks are 6 fixed conditions; white-box routability of learned rules untested.
  • Safety Memory monotonically accumulates text — no pruning, conflict, or context-length analysis.
  • Strong-frontier-model dependency at development time (GPT-5.5 writes structured artifacts), though not at deployment.

Open questions

What this paper leaves on the table.

  1. How much gain survives when the ASB judge is switched outside the evolution model's family (Claude / DeepSeek), with a direct held-in test?
  2. What if PROGENT and Memskill-SafeHarness are re-evolved on the same 15-task split with equal rollout budget — the only fair adaptive comparison?
  3. Does the harness keep improving past 20 rounds, or does the R05–R16 plateau mean the 15-task evolution set is exhausted?
  4. Is the evolved harness robust to a white-box adaptive attacker who can read the Rule Bank and Tool Policy?
  5. What's the total API cost per evolution run, and how does safety-per-dollar compare to fine-tuning the base policy on the same failures?
  6. Can the four-artifact decomposition be validated causally (edit A, measure B's responsibility) rather than inferred from the coupled-framework ablation?
