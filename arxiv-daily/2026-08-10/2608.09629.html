Key finding

Delegating the optimization procedure to a frontier LLM beats prescribed pipelines — but the advantage inverts below a capability threshold.

“Rethinking Self-Evolving Agents: Do We Still Need Prescribed Optimization Pipelines?” · Hui Xue, Fan Yang · Microsoft Research

Why this matters
A reusable contract / meta-policy split, a counterintuitive capability ladder, and a warning that aggregate pass rates hide divergent correct-item sets.
Critical edge
Every headline score is a single run with no variance — strip the sub-3-point margins and “12 wins” shrinks to roughly 5 clear wins and 8 near-ties.
01

Methodology

Setup is persistent natural-language skill optimization: a target model M_tgt solves benchmark tasks using a reusable Markdown skill, while an optimizer M_opt improves that skill from interaction evidence. All three procedures — OEO, SkillOpt, GEPA — start from a byte-identical initial skill and share the same data split, target endpoint, evaluator, and permitted task-facing operations. Selection may use only the valid_seen split; the sealed test split is run exactly once after selection.

The only variable is who owns the procedure. SkillOpt fixes rollout/reflection batching, bounded-patch operators and validation-gated commits. GEPA owns parent selection, minibatch cadence and a Pareto pool inside a free-form evolutionary loop. OEO exposes the same five actions — INSPECT RUNTARGET REVISE SELECT STOP — through a contract-enforcing interface and delegates every procedural choice online; the runner only validates legality, bills tokens and seals the final split. Controls: a static, zero-interaction one-shot rewrite (same step-0 info, tools disabled), and a frozen-protocol capability ladder over Qwen3.5-4B → Qwen3.5-27B → GPT-5.5.

Zero-interaction control

A static GPT-5.5 one-shot rewrite regresses on LiveMath (Qwen 0.3065→0.2742, GPT-5.5 0.3871→0.3468) while OEO gains +34.68 / +29.84 pts. The wins are not “frontier prior rewrites.”

Efficiency — read the asterisk

OEO uses a median 34.3% of SkillOpt's target-interaction token budget (just 6.1% on SpreadsheetBench/GPT-5.5). But it overshoots the optimizer-token budget in 3/8 settings — and optimizer tokens are the expensive GPT-5.5 ones.

03

Strengths & limitations

Strengths

  • Crisp, immediately reusable contract / meta-policy factorization for any self-evolution harness.
  • Two structurally opposite baselines — GEPA beats SkillOpt in 3/6 cells, pre-empting the “weak comparator” objection with evidence.
  • The zero-interaction control is well-matched and yields the most convincing single result: one-shot rewrite regresses on both LiveMath targets.
  • Negative results (medium crossover, weak block) reported prominently, with explicitly conditional framing.
  • Trajectory diagnostics (churn, section breadth, gain-set Jaccard) separate “different text” from “different behavior” — correct-set Jaccard as low as 0.3778 behind near-identical scores.

Limitations

  • Single run per cell — no variance, seeds, or significance; several headline margins are just 4–6 evaluation items.
  • Small sealed splits (n = 124 / 172 / 280); only SearchQA (n=1,400) ties, precisely where the claim generalizes weakly.
  • One artifact type (Markdown skill), one frontier optimizer (GPT-5.5); no transfer test to memory, tool or code artifacts.
  • Capability ladder is thin (2 benchmarks, 1 target, 3 sizes) for a claim as general as “prescription becomes scaffolding.”
  • No OEO internal ablation; gains concentrate on low-initial-score settings, untested.
04

Questions for further exploration

  1. Would a single format-repair retry or constrained action decoding unblock the weak Qwen3.5-4B optimizer — making the “capability boundary” partly an interface-engineering artifact?
  2. Does the win margin track the initial skill's headroom (LiveMath 0.31/0.39 → huge gains; SearchQA 0.79 → ties)? Is OEO's edge “unbounded rewrite when the artifact is bad” rather than “better online meta-policy”?
  3. Which OEO freedom actually matters — evidence scheduling, unbounded edits, SELECT, or adaptive STOP? A leave-one-out ablation turns an observation into a design rule.
  4. Does the 34.3% target-token saving survive end-to-end matched dollar cost, counting optimizer tokens at frontier prices?
  5. Since OEO and SkillOpt reach complementary correct sets (J_C as low as 0.38), can their selected skills be ensembled above either score?
