> **一句话总结：** 该文用零阶（无梯度）优化扰动实例级 LoRA 参数、以“答案困惑度”作为稠密标量损失来在难题上挖掘出初始策略采不到的成功轨迹，再把这些轨迹拿去 SFT 形成自演化闭环——在 304 条 WebShaper 训练题上 Pass@1 成功率从 22.0% 提到 53.9%，Qwen-3-8B 在 GAIA 上从 ReAct 的 23.3% 提到 47.5%，WebWalkerQA 从 15.5% 提到 34.8%。

> **TL;DR:** Self-evolving agents can only learn from trajectories they can already sample, so they stall on hard examples where every rollout fails. This paper perturbs instance-specific LoRA modules, scores each perturbed rollout with a trajectory-conditioned negative log-likelihood of the *reference answer* ("answer perplexity loss"), and uses one-sided zeroth-order finite differences to update LoRA — no trajectory annotations, no backprop. Recovered successful trajectories then feed SFT. On the 304-example WebShaper training set, Pass@1 trajectory discovery rises from 22.0% to 53.9% (+31.9 pts); Qwen-3-8B goes from ReAct's 23.3% to 47.5% avg on GAIA (+24.2, and 8.3%→41.6% on Level 3) and 15.5%→34.8% on WebWalkerQA, beating the paper-reported ARPO (38.8 GAIA) — though ARPO/WebDancer numbers are copied from their papers on different backbones, and WebDancer's 36.0 WebWalkerQA average actually still edges out this work's 34.8. Worth reading if you care about breaking the sampling ceiling in agent self-training; skim the Table 1 caveats carefully.

## 核心贡献

- **提出零阶自演化框架**：在无任何轨迹标注的条件下，通过随机扰动实例级 LoRA 参数 + 有限差分估计梯度，让 agent 在“当前策略采不到正确轨迹”的难例上仍能被推动到成功区域，突破自演化方法固有的能力边界（capability boundary）。
- **答案困惑度损失（answer perplexity loss）**：把生成轨迹的 `<answer>` 段替换为 ground-truth 答案，只在答案 token 上算 token-归一化 NLL，作为零阶优化的稠密标量信号。相比二值正确性 / BERT 相似度 / LLM-as-a-Judge，这个损失连续可分辨，即使 rollout 答错、只要检索到了有用证据也能拿到梯度信号。
- **并行扰动推理**：注意到不同扰动只作用于 LoRA 分支，backbone 输出 θx 只算一次并在 K 个扰动分支间共享，K=4 时把序列化估计的 656s 压到 305s（-53.5%）。
- **自适应查表机制**：缓存近期工具调用结果，search 用语义匹配、visit 用 URL+目标的严格匹配，K=4/30 轮时命中 150 次 search、84 次 visit，估计节省 1290s。
- **系统性的“能力边界”分析**：与固定轨迹一阶梯度、RL（outcome reward）、随机 LoRA 扰动、答案条件轨迹搜索、Best-of-N 采样在等 rollout 预算下对比，并给出 PCA 参数轨迹诊断，论证增益来自“损失引导的定向优化”而非“多采样”。

## Key Contributions

- A zeroth-order self-evolution loop for LLM agents: perturb per-instance LoRA `w_i = [A_i, B_i]` by `θ + (B+σε_B)(A+σε_A)`, roll out the full agent in the real tool environment, and estimate `ĝ = (ℓ⁺ − ℓ⁰)/σ · ε` against a shared unperturbed baseline rollout (one-sided estimator), updated with Adam.
- An answer perplexity loss as a process-level surrogate: `ℓ_ans = −(1/M)Σ log π_θ(y_j | q, τ_\ans, y_<j)`, computed only on gold answer tokens conditioned on the sampled trajectory — dense where binary/similarity rewards are discontinuous.
- Two systems-level efficiency mechanisms (parallel perturbation inference with a shared backbone forward; adaptive tool-call lookup pool) that make multi-direction ZO estimation feasible on 8× RTX3090 24GB.
- A formal decomposition `∇F = g_fixed + g_traj` arguing that fixed-trajectory first-order updates only estimate `g_fixed` and that outcome-level RL yields `ĝ_RL = 0` when every sampled trajectory fails with identical reward — motivating why ZO over regenerated rollouts can move the trajectory distribution.
- Released code, sampled high-quality trajectories, and trained agents (github.com/hidk1911/ZOForLLMAgents).

## Methodology

The setup is standard multi-turn ReAct-style deep research: policy `π_θ` interacts with search / visit / code tools, producing `τ = (r_1,a_1,o_1,…,r_T,a_T,o_T,ŷ)`. Because actions are discrete and the environment is non-differentiable, `θ → τ` is a black-box stochastic map. Self-evolution is defined as training only from `D = {(q_i, y_i)}` QA pairs with no intermediate supervision.

The paper's core argument is a gradient decomposition (Eq. 5): the true objective gradient splits into `g_fixed` (answer loss with the trajectory held fixed) and `g_traj` (how parameter changes reshape the trajectory distribution). A fixed-trajectory first-order update only realizes a single-sample estimate of `g_fixed` — it raises answer likelihood under an already-failed context without changing tool selection or query formulation. Policy-gradient RL captures `g_traj` but degenerates to zero when all `M` sampled trajectories on a hard example receive the same correctness reward.

ZO sidesteps both. For each hard instance, a fresh instance-specific LoRA module is attached and optimized for ~15 rounds. Each round samples `K` random directions, runs a *complete* fresh rollout under each perturbed policy (so the trajectory distribution genuinely moves), computes `ℓ_ans` for each, and forms finite differences against one shared baseline rollout `ℓ⁰`. The authors compare one-sided vs two-sided SPSA under a matched 4-rollout-per-round budget and pick one-sided because it buys more directions per budget.

Trajectories that end with a correct answer *or a sufficiently low answer loss* are pushed into a high-quality buffer, which becomes the SFT dataset for a single shared agent — that SFT step is what actually converts per-instance ZO adaptation into a general capability gain. Training data: 304 QA pairs filtered from 500 WebShaper pairs. Backbones: Qwen-3-4B and Qwen-3-8B; vLLM for inference, modified LLaMA-Factory for LoRA SFT, Google Serper for search, Jina.visit for parsing, 20k-token context cap, ~1152 GPU hours total on 8× RTX3090.

## Results & Highlights

- **Trajectory discovery on the 304-example training set:** the initial policy solves 67/304 at Pass@1 (22.0%); after ZO optimization the agent solves 164/304 (53.9%), a +31.9 pt absolute jump. Pass@8 rises 33.5% → 63.8%.
- **GAIA, Qwen-3-8B:** Ours-SFT reaches 47.5% avg vs the controlled ReAct baseline's 23.3% (+24.2 pts), with the largest gain on Level 3 (41.6% vs 8.3%). Against paper-reported training-based methods on Qwen-3-8B, this beats ARPO (38.8%, +8.7) and GRPO (32.0%, +15.5). With Qwen-3-4B the gain is much smaller: 28.3% vs 19.6% (+8.7).
- **WebWalkerQA, Qwen-3-8B:** 34.8% avg vs ReAct 15.5% (+19.3) and vs ARPO 30.5% (+4.3) — **but WebDancer's paper-reported 36.0% on Qwen-2.5-7B is still higher than this method's 34.8%**, contradicting the abstract's "consistently outperforms strong baselines" on this benchmark.
- **Trajectory-source ablation (Table 2, Qwen-3-4B, GAIA):** training on the 67 self-sampled initial trajectories gives 20.4% avg (barely above the 19.6% untrained agent, +0.8), whereas training on ZO-discovered trajectories gives 28.3% (+8.7). This is the cleanest evidence that the gain comes from *new* trajectories, not from SFT per se.
- **vs first-order alternatives on 50 hard examples (matched rollout budget):** initial policy 6/50, fixed-trajectory FO 7/50, RL with outcome reward 16/50, ZO 23/50. Cost: FO needs 21–24 GB and 2.5–3.5 h; ZO needs 12–15 GB and 1.7–2.4 h.
- **Best-of-N discovery (Table 7):** at N=8, ZO hits 53.61% vs answer-conditioned trajectory search 37.82%, random LoRA perturbation 33.55%, and initial-policy sampling 32.23% (+15.8 over the best non-ZO alternative); the gap widens with budget (at N=1 it is only 26.97 vs 24.67, +2.3).
- **Sampling is not a substitute:** under a matched total budget of N_total=45 rollouts, the initial policy solves 102 training examples vs 194 for ZO; of the 97 examples newly solved by ZO, only 35 (36.1%) are recoverable by Best-of-45 sampling, and the initial policy already plateaus at Pass@8.
- **Non-retrieval / non-verbatim GAIA subsets:** on 56 questions needing no retrieval, initial 8.93% → RL 19.64% → ours 28.57%; on 68 questions where the gold answer never appears verbatim in any observation, initial 10.29% → ours 30.88%. This argues the answer-perplexity signal isn't just teaching verbatim copying.
- **Transfer without benchmark-specific ZO (Pass@8):** BrowseComp-en 2.29 (initial) → 3.40 (RL) → 4.11 (ours); BrowseComp-zh 17.64 → 21.45 → 23.53. The English numbers are near-floor.
- **Pass@N on GAIA vs RL:** ours 28.3/34.9/37.8/39.8/41.7 for N=1/2/4/6/8 vs RL 25.2/32.0/36.9/36.9/39.8 — the margin is +3.1 at N=1 but shrinks to **+0.9 at N=4**, so the advantage over RL is much thinner than the ReAct comparison suggests.
- **Efficiency:** parallel perturbation cuts sequential-estimate time 328s→232s at K=2 (-29.3%) and 656s→305s at K=4 (-53.5%). Adaptive lookup at K=4/30 rounds yields 150 search + 84 visit cache hits, ~1290s saved (3s/search, 10s/visit assumed latency).
- **Optimization dynamics (Table 9):** on a representative hard example answer loss falls 4.333 → 0.024 over 15 rounds; aggregated over 50 examples, mean loss decrease is 74.8% (ours) vs 13.4% (random perturbation), consecutive-update cosine similarity 0.85 vs 0.02, and 23 vs 5 solved.
- **Robustness:** hyperparameters are flat — K∈{1,2,4,6} gives 20/23/24/24 of 50; σ, LoRA rank r∈{8,16,64}, and η all vary within 19–23/50. Five seeds on the controlled setting: GAIA 28.6±0.6 vs initial 19.1±1.9; WebWalkerQA 28.3±0.8 vs 19.7±1.9.

## Authors & Credibility

Seven authors from the Beijing Key Laboratory of Intelligent Information Technology (School of CS, Beijing Institute of Technology), the Guangdong Laboratory of Machine Perception and Intelligent Computing at Shenzhen MSU-BIT University, and Alaya Lab. Bingzhen Liu and Xiaomeng Fan are co-first authors; Yuwei Wu, Zhi Gao and Yunde Jia are established in multimodal agents and tool-use tuning (they cite their own CLOVA, multi-modal agent tuning, and step-wise preference tuning line of work). The group has a credible track record in agent tool-use research, and the paper is unusually forthcoming in its appendix about compute (1152 GPU hours, 8× RTX3090 24GB), tool stack (Serper, Jina.visit, vLLM, modified LLaMA-Factory), and single-run reporting. Code and artifacts are promised at a public repo. The 24GB-GPU constraint is worth noting: it plausibly explains why the strongest controlled backbone is only 8B, and why RL baselines are compared mostly via paper-reported numbers.

## Critical Assessment

**Novelty (strong-ish).** ZO/MeZO-style optimization for LLMs is well established (MeZO, ZO-LLM, LOZO), and the actual algorithmic ingredients are individually familiar. The genuinely new move is the *target*: using ZO not to save memory during fine-tuning but as a **trajectory-discovery operator** that reaches examples the policy cannot sample, then recycling the discovered rollouts through SFT. The `g_fixed + g_traj` decomposition and the observation that outcome-RL's estimator is identically zero when all rollouts fail is a clean, correct framing that I have not seen made this explicitly in the agent self-evolution literature. The answer perplexity loss is a repurposed TT-SI-style idea, credited as such.

**Rigor (mixed — this is the weak spot).** Table 1 blends "paper-reported" rows (Search-o1, WebThinker, WebDancer, SimpleDeepSearcher, WebSailor, GRPO, ARPO) with only two genuinely controlled rows (ReAct vs Ours-SFT). The paper is honest that these are "contextual," but the abstract's "consistently outperforms strong baselines" leans on the uncontrolled comparison, and it fails on its own table: WebDancer's 36.0 WebWalkerQA average exceeds Ours-SFT's 34.8. More concerning, the controlled **Qwen-3-8B ReAct baseline on WebWalkerQA scores 15.5%, well below the paper's own Qwen-2.5-7B ReAct number of 24.2%** — a larger, newer backbone scoring 9 points *worse* under the authors' own scaffold suggests the headline +19.3 delta is partly a weak-baseline artifact of their prompt/tool configuration rather than pure method gain. There is no GRPO/ARPO trained in-house on the same 304 QA pairs and same tool stack for the main table; RL appears only in Pass@N/subset tables, where the margin is much smaller (+0.9 at Pass@4 on GAIA). The headline 47.5 GAIA number is a single run — the five-seed table (28.6±0.6) covers only the 4B configuration.

**Reproducibility (good by intent, moderate in practice).** Code and trajectories are promised, hyperparameters and the tool stack are named, and compute is disclosed. But results depend on live Google Serper + Jina.visit, so the "controlled" setting is not reproducible across time; and the paper explicitly caches tool calls (adaptive lookup) *during* discovery, which changes the effective environment between perturbation branches — there is **no ablation showing the lookup pool doesn't inflate success by serving stale-but-lucky observations across branches**, only a wall-clock-savings table.

**Significance (real, but narrow in scope).** The Best-of-45 analysis (only 36.1% of newly solved examples recoverable by brute-force sampling; initial policy plateaus at Pass@8) is the paper's most persuasive result and does support the "beyond the boundary" claim in a way that a simple accuracy table would not. Against that, BrowseComp-en at 4.11% Pass@8 is essentially floor-level and should not be presented as evidence of generalization; the BrowseComp-zh gain (+5.9 over initial at Pass@8) is more meaningful but still single-run.

**Red flags.** (1) The trajectory buffer admits rollouts with "correct final answers **or sufficiently low answer loss**" — a threshold that is never specified and that could inject wrong-answer trajectories into SFT data; no ablation isolates correct-only vs low-loss-included buffers. (2) `ℓ_ans` conditions on the gold answer, which is arguably a richer supervision signal than the binary reward given to the RL baseline; the RL comparison is therefore not supervision-matched, only rollout-matched. (3) Per-instance LoRA optimization over 15 rounds × K directions is expensive — 1152 GPU hours for 304 training questions is roughly 3.8 GPU-hours per question, and the paper never discusses how this scales to thousands of examples or compares against simply distilling from a stronger teacher at equal cost. (4) The 4B result (+8.7 GAIA) is a third the size of the 8B result (+24.2), which is the opposite of the usual pattern and is left unexplained.

## Strengths

- The central claim is tested with the right experiment, not just an accuracy table: matched-rollout Best-of-N, matched-total-budget Best-of-45 recovery analysis, and random-LoRA-perturbation controls all separate "loss-guided optimization" from "more sampling."
- The `g_fixed` / `g_traj` decomposition gives a crisp, falsifiable reason why fixed-trajectory FO (7/50) and outcome RL (16/50) plateau where ZO does not (23/50).
- The loss-function ablation is well designed: same question, easy vs hard, normalized scales, and it shows BERT-similarity and LLM-as-a-Judge losses fail to decrease at all on the hard example.
- Honest local caveats — the authors explicitly write that the GPU-memory/time comparison "does not imply that ZO is uniformly faster than first-order optimization," and label the cross-paper rows as contextual.
- Genuine hyperparameter insensitivity (K, σ, r, η all within 19–24/50) plus one-sided vs two-sided parity (23 vs 24), suggesting the effect is not a tuning artifact.
- Thorough appendix: compute budget, exact tool services, released-artifact filtering plan, and an explicit statement that accuracies are single-run unless noted.

## Limitations

- **Author-stated:** the method is only demonstrated on text LLM agents, not multimodal agents.
- Scale ceiling: largest backbone is Qwen-3-8B on 24GB GPUs; no evidence the boundary-breaking effect persists at 32B+ where the initial capability boundary is already much further out.
- Per-instance LoRA + repeated full rollouts is costly (~3.8 GPU-h per training question); no cost-matched comparison against teacher distillation or against simply training on more data.
- The answer perplexity loss requires gold answers at discovery time, so this is not applicable to genuinely unlabeled or open-ended tasks — it is "no *trajectory* annotation," not "no annotation."
- Only two primary benchmarks (GAIA, WebWalkerQA), one training corpus (WebShaper), and a single tool stack; BrowseComp transfer numbers are near-floor in English.
- Missing ablations: no isolation of the adaptive lookup's effect on discovery *quality*; no sensitivity study on the low-answer-loss buffer-admission threshold; no in-house RL baseline in the main results table.
- Table 11's seed variance covers the 4B controlled setting; the headline 8B GAIA 47.5% has no reported variance.

## Relevance

如果你关注 LLM agent 的自演化 / 自训练（SFT-on-self-sampled-trajectories、RLVR 在难例上梯度消失）以及 deep research agent 的训练数据合成，这篇给出了一个很有价值的视角：把零阶优化当作“轨迹发现算子”而不是省显存的微调技巧，并用 matched-budget Best-of-N 实验证明了增益不是简单的多采样。对做 agent RL / 数据飞轮的人，Table 6/7 和 Best-of-45 恢复率（36.1%）是最值得直接借鉴的实验设计。

## Questions for Further Exploration

- What exactly is the "sufficiently low answer loss" threshold for admitting a trajectory into the SFT buffer, and how much of the +24.2 GAIA gain survives if only verified-correct trajectories are used?
- Why does the Qwen-3-8B ReAct baseline underperform Qwen-2.5-7B ReAct on WebWalkerQA (15.5 vs 24.2) in the authors' own scaffold? Fixing that baseline could substantially shrink the reported delta.
- Does the adaptive lookup pool bias discovery? Since perturbation branches share cached observations, do the discovered trajectories remain valid when replayed against a live, uncached environment?
- How does ZO discovery compare, at equal GPU-hours, against (a) distilling GPT-class teacher trajectories and (b) simply running RL with a dense answer-perplexity reward instead of binary correctness? The latter would isolate the ZO estimator from the loss design.
- Can the instance-specific LoRA modules be amortized — e.g. a hypernetwork or a shared low-rank basis across examples — to avoid ~3.8 GPU-h per question?
- The consecutive-update cosine similarity of 0.85 suggests very low-dimensional effective dynamics. Does that mean a small learned subspace (à la LOZO) would recover the same trajectories with far fewer rollouts?
- Does the effect survive on a backbone that has already been RL-trained on agentic data (e.g. starting from ARPO's checkpoint rather than base ReAct), or does ZO discovery only help agents that are far from their scaffold's ceiling?
