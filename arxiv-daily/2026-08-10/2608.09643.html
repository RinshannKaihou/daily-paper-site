Key metric · OOD paired win-rate

61–67%

Probe ranks a vulnerable function above its own fix on 147 single-function CVEs from CWE types it never saw in training. Wilson 95% CI clears the 50% chance line for all five models.

Why this matters

A model's internal state carries security signals its text can't express — so how you read the model may matter more than how you prompt it.

Critical edge

No static analyzer (Bandit, Semgrep, CodeQL) is run on the same CVE slice — a 63% probe is only interesting if Semgrep doesn't already win for free.

Methodology

distilled

Five open-weight code LLMs — Qwen2.5-Coder 7B/14B, DeepSeek-Coder 33B, Devstral-Small, Llama-3.1-8B — act as readable proxy reviewers, run in float16 on a single H100. A single logistic probe is fit on residual-stream activations (extracted via nnsight at each layer's input layernorm); layer, token-pooling, and L2 strength are chosen by 5-fold GroupKFold AUC. Training uses only four SVEN Python CWEs (022, 078, 079, 089). Evaluation is 147 PatchEval CVEs whose entire CWE label set is disjoint from training. Both the train/eval split and the CV folds are grouped by repository to block duplication leakage. The headline metric is a paired win-rate: for each CVE, the probe must score the vulnerable function higher than its post-fix counterpart, with exact ties dropped. The prompted comparator gets three prompts (no-shot / few-shot / CoT) × two readouts (YES/NO logit ratio, written token), and is compared against the probe under paired McNemar on each model's best configuration.

Strengths

  • Anticipates the standard critiques: repo-grouped splits, held-out CWE types, real CVEs, and a seen-CWE reference quarantined to the appendix.
  • Comparator deliberately strengthened — best-of-3 prompts × 2 readouts, paired McNemar — a choice that cuts against the author's own thesis.
  • Verdict-collapse finding (72–97% identical; 1–13% correct) is clean and independently useful: it reframes prompting failure as a readout problem, not a knowledge gap.
  • Consistent across four architecture families and a 7B–33B size range.
  • Negative results (C/C++ at chance; probe vs CoT non-significant on 4/5) stated without hedging.

Limitations

  • Paired-only signal: needs both a function and its fix. Real review has no fix to rank against — the stated post-write hook can't consume it as-is.
  • Small and narrow: four CWEs, a 152-sample eval split, 147 headline CVEs.
  • Python + injection-style flaws only; C/C++-dominant classes sat at chance.
  • No static-analyzer baseline and no shallow-lexical-feature control.
  • Never tested on agent-generated code — the stated deployment target.
  • No artifact release (code, weights, prompts, data-processing scripts).

Credibility & provenance

Open questions

  1. Does a bag-of-tokens / TF-IDF baseline match the probe on the 147 unseen CVEs? (rules out lexical surface features)
  2. How do Semgrep / CodeQL / Bandit score on the same paired slice? (the missing incumbent baseline)
  3. Can the paired win-rate become a calibrated single-function score for real review-time triage?
  4. Does the probe direction transfer across models (fit Qwen-7B → apply to Llama-8B via affine map)?
  5. Why do selected layers vary so much (7 vs 21) — real localisation, or CV noise on 152 samples?
  6. On actual coding-agent output (the stated target), what fraction of flagged diffs are true positives?
