01Methodology

Six systems, one frozen split, one sealed run.

Six Qwen2.5-Coder systems (7B and 32B, quantised, temperature zero) run locally against two frozen synthetic DuckDB warehouses over read-only connections. Four baselines — 7B direct, 7B few-shot (cost-comparable), 7B + semantic-layer retrieval, and 32B direct (the larger-model reference) — face two treatments: QueryProof, with and without its routing layer.

QueryProof decides behaviour with a deterministic state machine that runs before the model is called: it parses the question, resolves terms against a semantic layer + physical catalog, and rules refuse / clarify / abstain by longest-match lexicon lookup and AST allowlists (no DML/DDL, no unknown or deprecated columns). The model is asked only two narrow, re-checked questions; every answer then passes post-execution verification (filter applied? time window? non-empty? impossible values?).

A pre-registered protocol fixed the metric list, permitted paired comparisons, claim-verb rule, and artifact hashes before any test call. The 80-task split was evaluated exactly once and declared spent. Statistics: paired percentile bootstrap, 2000 resamples, seed 9901.

QueryProof pipeline
PARSE→SEMANTIC_LOOKUP→RESOLVE→AMBIGUITY_CHECK→DRAFT_SQL→AST_VALIDATE→EXECUTE→VERIFY→SCORE→ROUTE
Terminal states: RETURN · ESCALATE · ABSTAIN · CLARIFY · REFUSE. Refusal is checked before the model is called, so injection payloads never reach it.

The author's own honest negatives — promoted to the body, not buried
  • Routing hurts on test: routed 0.537 vs unrouted 0.562 — the shipped operating point "illustrates rather than recommends." Not re-tuned (one-run rule).
  • Fitted confidence model loses to the heuristic it replaced: AURC 0.436 vs 0.164 — fitted only on answerable-question answers, so it never learned to doubt.
  • Cluster robustness kills the magnitude claim: resampling the 10 template families widens both CIs to include zero.
  • Self-disclosed contamination: five lexicon phrases matched the entire 16-task test ambiguous stratum — removed before any test call, but the author still refuses to call the split clean.

03Strengths & limitations

Credibility here rests on process, not pedigree — and the process is unusually strong for a solo preprint.

+ Strengths

  • Frames the right failure. The undetected danger is a query that runs and returns a wrong business number — invisible to any execution-match metric.
  • Pre-registration honoured. Claim-verb rule fixed before numbers existed; routing-vs-base is not claimed as a difference (intervals overlap, pair not registered).
  • Both verification error directions measured — including the embarrassing 0.333 false-clean rate on validation (0 false rejections / 140 golden SQL).
  • Three negative results promoted to the body, with a mechanistic diagnosis for the confidence-model failure.
  • Pinned denominators (Appendix E) plus two explicitly-named near-misses (per-task false-success ≠ FSR; cost-per-success ≠ CPCA).
  • One-command replay: reproduce.sh, zero model calls, per-artifact content hashes stamped into every figure footer.

− Limitations

  • Thin evidence base: 80 test tasks, 10 template families, two synthetic domains, one model family, one SQL dialect, no external benchmark.
  • Headline confounds scale with scaffolding — the matched-scaffold 32B run (the decisive experiment) is named as future work, not run.
  • No component ablation. "The gain tracks the deterministic layer" is inference from strata, not from removals.
  • Test split had disclosed contamination covering the entire test ambiguous stratum.
  • 7B direct is a strawman (BTR 0.100, FSR 1.000, zero correct) — exists only to make the plot dramatic.
  • Single-reviewer labels (test–retest, not inter-annotator); all disagreements clustered in one family. Post-training untested by design (pool 20 vs gate 100).

04Open questions for further exploration

Non-linear jumping points — the experiments that would actually settle the claim.

1
Same scaffold over the 32B. Does +0.237 survive when the baseline gets the semantic layer, catalog and verification? How much is information asymmetry vs reasoning?
2
Component ablation. Keep rule-based behaviour but drop post-execution verification — the 0.163/0.333 false-clean rates suggest verification's marginal contribution may be smaller than the abstention rules'.
3
Does lexicon-ambiguity scale? The two-defined-metrics path is literally never tested on held-out data here. Would it survive a real semantic layer with hundreds of metrics and stale definitions?
4
Fix the confidence model. Fit on the full behaviour distribution (including cases requiring clarification) — does it then beat the hand-weighted heuristic, or is the post-verification subpopulation structurally unrankable?
5
Maintenance cost in the ledger. The deterministic layer needs no retraining, but the rules and semantic layer must be maintained — and the golden-SQL incident shows the rules themselves carry defects.
6
Port BTR/FSR to Spider 2.0 enterprise workflows, where reference queries exist but ambiguity/unanswerability are unlabelled. What is the minimum annotation to add a behaviour contract?

◆ 核心贡献（精炼）

WarehouseReliabilityBench：400 个冻结任务（电商 + SaaS 两个确定性数仓），仅 184 个可答，其余靠"行为契约"打分——execution-match 类指标无法覆盖一半题目。

可靠性优先的评测：Business Truth Rate（分母=全部任务）、False Success Rate（分母=被标 ANSWER 的输出）、CPCA、ECE，每个分母显式钉死；配对 bootstrap 与"允许哪个动词"在测试前预注册。

确定性校验层：状态机先于模型调用判定拒绝/澄清/弃答，AST 白名单静态校验 + 只读执行 + 执行后校验。140 条 golden SQL 上 0 次误拒，但 validation 漏检率 0.333。

◆ 相关度 / Relevance

若你关注 LLM agent 可靠性评测、弃答/校准（selective prediction），或把 LLM 接入生产数据栈（semantic layer / dbt / text-to-SQL），这篇值得精读：它给出"正确答案往往不是答案"的基准设计范式，以及"确定性校验层优先、学习式置信度后置"的可迁移工程结论。

它本身也是一份关于预注册、单次运行规则、污染披露与可复现构建的优秀方法论样本，对写实证类论文（尤其 agent / benchmark 方向）有直接借鉴价值。
