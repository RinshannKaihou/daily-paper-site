How it was tested

Methodology

The studied system is one concrete instance, not a new algorithm. gpt-oss-20b (low reasoning effort) samples K solutions per AIME 2025 problem; a verifier labels each correct/incorrect. An external LLM judge (gpt-5-mini / gpt-5.6-luna) reads the prompt, reference solution, verdict, and full trace, then writes a "helpful" text C⁺ and a matched-but-wrong C⁻ — but text only. A frozen or earlier copy of gpt-oss-20b itself supplies the token probabilities, so this is not policy-as-judge. Two scores are defined: the one-sided teacher residual e⁺ = log q(v|s,C⁺) − log π_old(v|s), and the two-sided contrast d = log q(v|s,C⁺) − log q(v|s,C⁻), which cancels the policy term exactly. Six matched recipes share initialization, data, optimizer, verifier, and eval; they differ only in how the centered advantage A^C enters — outcome-only sets its coefficient to zero (verified in the log).

The three checks

  • Q1 — Meaning. Does the score actually track task success?
  • Q2 — Construction. Is the scored rollout compared under the same feedback rule (held-out / cross-fitted)?
  • Q3 — Update. What does the loss actually reinforce?

logically independent — passing one does not entail passing the others.

And yet the external judge solves the same pairwise comparison in 51/54 (94.4%) of calls — the privileged information is useful; the base model's token likelihood is the wrong readout.

Strengths what holds up

  • Separates three conflated claims the literature runs together: the score is measured correctly / means something / is used well.
  • The identical-feedback null (AUC 0.503) runs through the production scoring code and lands exactly where it should — validating the measurement pipeline itself.
  • Pre-empts rebuttals with data: truncation telemetry (token-score runs finished more often), 0.013% regrade change, update-1 equivalence proving the gap is dynamic, not init.
  • Names a concrete mechanism for how a chance signal becomes harmful: 55.8% zero-outcome groups, weight piled on high-entropy tokens.

Limitations what is open

  • One model, one benchmark, one seed (gpt-oss-20b, low effort; AIME 2025, 30 prompts; avg@4) — no scale or domain study.
  • Feedback templates unmatched on length, style, and formatting; the corrected-template rerun is unfinished.
  • No λ sweep, no isolated ablation of clip vs tanh vs entropy gate vs KL — so "token score hurts" is never separated from "this magnitude hurts."
  • 2,048 + 2,048 audit prompts and a 115-contest set were built and never run; outcome-only control was still improving when stopped.
Open follow-ups

Questions worth chasing

Does the collapse survive byte-matched feedback templates?
The single highest-value follow-up. If AUC rises and the training gap shrinks, the paper is about template hygiene, not likelihood-as-credit.
Is there a λ at which the token score is neutral-to-helpful?
A sweep from λ→0 would separate whether −30 pp is a dose effect or a direction effect.
Would the 94.4%-accurate judge reward beat outcome-only?
The natural positive control — same privileged information, different readout — which the paper gestures at but cannot run.
Do the published methods pass the held-out cross-fitting check?
RLSD, RLCSD, CriPO, OPSD — none appears to run the Q2 construction check on their own reported setups.
