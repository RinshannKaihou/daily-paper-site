Key Finding·Evaluation of Context Compaction

Context compaction tuned for the known question aces it — and silently fails the hidden questions that come later.

Evaluating Context Compaction on the Questions That Come Later ↗

Junwei Yao · Yongxi Zhou · Zike Yang · Zhijun Wang · et al. (7 authors, independent)  |  2026-10-19  |  arXiv 2610.27301

context-compaction prompt-compression llm-agents agent-memory evaluation-benchmark

一句话总结：该论文系统评估了面向“当前问题”的上下文压缩对“后续未知问题”的影响：在 MultiRC 上，按当前问题选句（typed selection，gpt-6-luna 打分）能把当前问题准确率提升 11.4 点，但对后续问题平均与随机删除无异（−0.4 点）；而不管问题的词级压缩器 LLMLingua-2 在同样 25% token 预算下比随机删句高 12.5 点，因为它保留了约两倍的证据实词，但该排序在 Evidence Inference 和 τ-bench 轨迹上又会反转。

Key Metric — the asymmetry

+11.4 → −0.4pts

typed selection vs. random deletion — accuracy on the known question collapses to parity on hidden ones (MultiRC, 25% budget, gpt-6-luna reader).

CI [+9.1, +13.8] → [−1.5, +0.6] · hidden effect not detected

Why This Matters

Compaction silently deletes evidence that later questions need, while label accuracy masks the loss — direct guidance for long-running agent memory and reliability.

Relevance（原文）：该论文直接命中“Agent & Pipeline Silent Failures”方向：上下文压缩是 agent 编排层中一个会“悄悄改变模型所见内容”的组件……对长时运行自主 agent 系统的可靠性与记忆设计有直接指导意义。

Critical Edge

The headline ranking flip on Evidence Inference is not token-matched (28.9% vs 25.8% of tokens kept), intervals go unadjusted across 51 predictions, and selector and reader are usually the same hosted model — gpt-6-luna — with no code release.

Pays for itself in input tokens only after 6.6–14.0 later questions (corpora average just 3.7–10.2)

Provenance

7 authors, all “Independent Researcher” · no institution, funding, or code · AI-assistance disclosed

Methodology 01

Every method is contrasted pairwise against seeded random deletion at matched budgets (25 / 50 / 75%) — then the compacted text must answer both the question it was packed for and the hidden ones.

  • Known vs. hidden: the first question is visible at selection time; all others are scored only after compaction.
  • Typed selection: gpt-6-luna (OpenAI Decisions API) answers one Boolean per sentence — “is this sentence needed?” — keeping the most probable; the same model then reads the result.
  • Baselines: question-agnostic selection, TF-IDF, lead, seeded random; word-level LLMLingua-2 and LongLLMLingua; MMR; two LLM-written summaries; a prespecified hybrid.
  • Statistics: paragraph-macro accuracy with 2,000-resample bootstrap 95% intervals; an effect is “detected” only when its interval excludes zero.
  • Causal diagnostics: evidence-content-word retention, KEEP–DROP same-size interventions, a three-way support read on FEVER, restore experiments.

Readers: gpt-6-luna 88.2% · qwen3.8-flash 89.2% · open-decider 2B 75.3% full-text; two small open readers fell below the all-“no” baseline (55.6%) and were excluded.

  • Mechanism: LLMLingua-2 keeps 48.0% of hidden questions’ evidence content words vs 26.1% for random sentence deletion; at equal retention its lead shrinks +12.5 → +7.3 (exploratory).
  • Overlap split: hidden questions sharing the known question’s evidence gain +4.3; disjoint ones lose −2.9 with only 18% of their evidence kept.
  • Identifiers decide τ-bench: typed keeps the hidden identifier 66.4% of the time (random 42.4%) — surviving identifiers score 85.9% vs 18.9% when lost.
  • Anticipation trades off: expected-coverage selection gains +12.8 hidden but costs −10.6 known; no selector beats typed on both. LLM summaries stay below LLMLingua-2; LongLLMLingua falls below random (−1.6).

Strengths 03

  • Asks the evaluation question everyone skipped: compaction is always scored on the question it was made for — never the ones that come later.
  • Random deletion at matched budget as universal control quietly indicts published compressors — LongLLMLingua lands below random on hidden questions.
  • Mechanistic, not just a leaderboard: content-word retention explains most of the word-level lead, validated out-of-sample.
  • Exemplary hygiene: 51 prespecified predictions with all 7 misses counted openly; ends with practitioner guidance — score hidden questions, report retention, count the token cost.

Limitations 04

  • Recorded trajectories, not live agents; τ-bench questions reduce to identifier lookup, retail domain only.
  • The word-vs-sentence verdict is corpus-dependent, and the pivotal Evidence Inference comparison is not token-matched.
  • Selector and reader are usually the same hosted model (gpt-6-luna) — a self-selection advantage; no code release.
  • Summaries tested on one corpus at one budget; KEEP–DROP covers one budget; evidence annotations incomplete.
  • LoCoMo is nearly uninformative: ten conversations, empty memory already scores 81.4%.

Questions for Further Exploration 05

  1. Does the Evidence Inference flip survive strict token-matched budgets, or is typed’s +12.2 advantage a budget artifact?
  2. Can any selector beat typed selection on both known and hidden questions, or is the trade-off (+12.8 hidden / −10.6 known) fundamental?
  3. Would provenance-linked answering close the FEVER gap between label accuracy and evidential support (56.0% unsupported endorsements)?
  4. Do the findings transfer to live agents that can re-fetch dropped state — recovery reached only 69.1% vs 88.8% full-state at 102% of tokens?
  5. Do KV-cache compression methods show the same hidden-question collapse, unifying prompt-level and KV-level compaction findings?
