Why this matters

If serving configs drift after calibration — exactly what quantized deployment creates — CP guarantees silently stop holding. This audit protocol catches it.

量化（int8/nf4）与温度这类推理栈数值配置，会在标定与部署之间静默摧毁保形预测的覆盖率保证；论文同时给出可复用的审计协议。

Critical edge

The headline collapse is dominated by one sensitive dataset — DBPedia-14 shows the effect is selective, and one model even overcovers (0.946 > 0.90) under mismatch — so "coverage always collapses" is the wrong takeaway.

Also bounded: models ≤ 7B, finite-label tasks only, temperature applied pre-scoring at the logit level.

01Methodology — distilled

  • Formalization. An inference configuration c = (q, t) — quantization × temperature — induces a score distribution F_c. "Inference-time model shift" = F_cal ≠ F_dep under a fixed task distribution. Proposition 3.2: different configs ⇒ calibration/test scores generally non-exchangeable ⇒ the split-conformal guarantee does not transport.
  • Clean isolation. Same checkpoint, prompt template, and data splits across all 12 configs; temperature applied to token logits, candidate scores are length-normalized log-likelihoods renormalized over the label set; quantization changes only the numerics.
  • Two conservative baselines. MAXTHR — max over per-configuration thresholds, provably ≥ 1−α coverage for any deployment mixture. LATENT-ROBUST — two-stage: a conformal logistic router infers plausible deployment configs from a set-size signature, guarantee 1−α₁−β₂. Both framed as reference baselines, not contributions.
  • Audit design. Deployment fixed to nf4@T=0.5 (plus one-axis variants); six procedures compared: MATCHED, MISMATCH-MEAN/WORST, POOLED, MAXTHR, LATENT-ROBUST.

  • Less reliable yet deceptively "efficient". DeepSeek-R1-Distill-Qwen-7B: coverage 0.904 → 0.443 (worst) while average set size shrinks 7.64 → 2.51 — mismatch makes CP look cheaper while it breaks.
  • Degradation is broad. CommonsenseQA falls 0.912 → 0.789 worst (all 8 models below target); MobileActions is most stable, yet 6/8 models still miss worst-case.
  • Neither axis alone explains it. Pinning temperature still yields 0.520 worst on MMLU-Pro (8/8 miss on every dataset); pinning quantization still yields 0.719 worst, and DBPedia-14 worst-case spans 0.220–0.890 — no monotone ordering of configs predicts severity.
  • Remedies restore coverage at a cost. MAXTHR ≈ matched set sizes; LATENT-ROBUST can hit 1.000 coverage with sets of 9.46 / 10 labels — near-useless prediction sets.
  • Not an artifact. Pattern persists across APS/RAPS scores and α ∈ {0.05–0.3}; run-to-run std is small relative to method gaps.

03Strengths

  • Clean problem isolation — same checkpoint, template, and splits across all 12 configs, so degradation is attributable solely to the inference configuration.
  • Names a genuine blind spot — the CP-for-LLM literature calibrates and evaluates under one fixed inference setup; matched protocols cannot expose this failure.
  • Honest baseline positioning — MAXTHR / LATENT-ROBUST carry explicit validity proofs and are labeled references, including the admission that LATENT-ROBUST can be more conservative.
  • Exhaustive robustness + a protocol — 3 scores, 4 α values, 3 runs, and an immediately adoptable three-step reporting recommendation for future CP evaluations.

04Limitations

  • Small models only (1.5B–7B) — no evidence about frontier scale, where quantization error structure may differ substantially.
  • Finite-label tasks only — open-ended generation (conformal factuality, selective generation) is explicitly out of scope.
  • Characterization without mechanism — no predictive theory of which config changes cause undercoverage vs overcoverage vs nothing.
  • Coarse grid — continuous temperatures, kernels, KV-cache precision, batching, and temporal serving drift are not covered.
  • Remedies trade coverage for set size — LATENT-ROBUST's efficiency frontier is unattractive in the worst cells; no adaptive method that beats MAXTHR is attempted.

05Questions for further exploration

  • Does the shift persist at 70B/405B scale, where quantization error and logit sharpness differ qualitatively?
  • Can DBPedia-14's heterogeneity be predicted from cheap observables (score entropy, logit gaps, set-size signatures) — turning the audit into a detector?
  • Does mild covariate/label shift plus config mismatch compound multiplicatively or saturate?
  • Would importance-weighted / non-exchangeable calibration over the config grid dominate MAXTHR's worst-case hedging at better set sizes?
  • Does the effect extend to open-ended generation scores computed over sampled generations?
  • Is the LATENT-ROBUST router robust when deployment mixes configs per-request — and can the α/2 + α/2 error budget be spent better?
