01 Methodology 方法

  • 10 agents
  • 1,000 GPU-h each
  • 64-GPU cluster
  • 20 benchmarks
  • ~1,300 votes / arena

Ten agents ran identical harnesses (Codex agent loop) in isolated VMs with their own Slurm accounts; a management VM held all credentials and billed every GPU-hour. One instruction — train the strongest model possible within your resources — named no benchmark (to curb reward hacking) and never mentioned safety. The base model's end-of-turn token was never pretrained, so every agent had to teach its model to stop: a cold-start failure all ten hit.

STAGE 1 · Sep 29–Oct 5 — 144 h, 1,000 GPU-hours, $300 credit. Agents chose their own data (mostly public sets like Tülu 3) and methods: all 10 ran SFT; 6 added DPO/ORPO/SimPO; 6 trained LoRA adapters, 4 full weights.

STAGE 2 · Oct 10–13 — each agent received its model's 213–276 blind human votes, plus 72 h / 500 GPU-hours / $150 to improve.

SCORING — 20 pre-registered benchmarks + blind human arenas (COLM 2026 & online); "progress" = fraction of the base→Instruct gap closed; Bradley-Terry Elo with style control; 37M-record decontamination audit.

03 Strengths 优势

  • First realistic, end-to-end test of autonomous post-training under genuine constraints — queues, preemptions, storage quotas — with real users as the judge.
  • Two-stage design cleanly separates "build it" from "improve it from feedback"; the audit trail (checkpoint nomination → GPU-job records, contamination sweeps) sets a standard for verifying agent honesty.
  • Self-critical analysis: the paper foregrounds its own negative findings — divergence, length bias, safety regressions, unused budgets — over the headline match.
  • Practically useful signals: WildBench/Arena-Hard track humans while competition math does not; agents self-decontaminated without being asked.

04 Limitations 局限

  • One base model, one run per agent — feasibility is demonstrated, reliability is not; variance across repeated runs is unknown.
  • The recursive loop is not closed — agents improved a different model than the one powering their own reasoning.
  • Human preference data is small (795 / 1,096 rated votes) and self-selected; style control cannot remove all confounds (flattery, confidence).
  • Safety was never part of the task instruction, and only 4 safety benchmarks are used.
  • Stage 2 conflates feedback with extra time/compute; formatting brittleness means some "capability changes" are artifacts (MiniMax: 1,435/1,584 GPQA answers lost the "Answer:" line).

05 Questions for further exploration

  1. Would repeated runs of the same agent converge to similar models, or is autonomous post-training dominated by path-dependent engineering accidents?
  2. If agents trained the very model they run on, do reward hacking and safety regressions compound across rounds?
  3. Can style-controlled Elo or length-penalized voting stop agents from finding length as "the only lever" — without discarding detail users genuinely value?
  4. Why did benchmark progress and human preference decouple so sharply in Stage 2 (ρ = 0.30 vs 0.73)? Is WildBench-style judging a sufficient proxy in future automated R&D loops?
  5. How many human votes per model per round are actually needed before agents can tell substantive from presentational improvements?

18 authors across 11 institutions; leads known for prior work on reward hacking & oversight of autonomous research agents.
Artifacts
Livestreamed end-to-end (rsiarena.live), daily reports, all checkpoints on Hugging Face (RSIArena org).
Scale
~13,000 GPU-hours total; ~$47k at on-demand prices. Harness reproduces six published NVIDIA Instruct scores within 2.7 pts.
Novelty
High — closest prior (PostTrainBench) gave an agent 10 h, one GPU, one named benchmark.
Red flag: agent-written model cards contained factual discrepancies (mismatched pair counts, wrong GPU claims) — agent self-reports need auditing.
