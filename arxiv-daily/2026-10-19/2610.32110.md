> **一句话总结：** 本文提出"扭曲的格式化器"（warped formatter）概念——工具计算正确但输出文本隐瞒搜索上限、截断、估计值或标识符命名空间——并通过 1,200 次配对实验证明：仅把这些遗漏信息写清楚，就能让三种失败类型下的 agent 无依据声明从 62–100% 降至 0–20%，并使验证器对同一错误答案的判决 90/90 全部从误接受翻转为正确拒绝。

> **TL;DR:** A single-author NeurIPS 2026 workshop study of a production RAG archive system (17,807 documents, Pilsudski Institute) shows that tool-output *formatters* — not the tools or models — silently mislead agents and verifiers by omitting scope/completeness/uncertainty/provenance facts. On a paired 32-case holdout benchmark (three model families: Claude Sonnet 5, GPT-5.6 Sol, Gemini 3.1 Pro), swapping warped wording for disclosing wording cut agent overclaim from 100% to 8% (scope) and 62% to 0% (completeness), and flipped 90/90 fixed-answer verifier verdicts from false acceptance to rejection; but identifier-provenance overclaim barely moved (100% → 94%), showing wording alone is not a panacea. Ships a reusable audit prompt that found real warped formatters in OpenClaw (fix merged) and Hermes (PR open).

## 核心贡献

- **定义并系统化了"扭曲的格式化器"（warped formatter）这一失败类别**：工具内部计算完全正确，但把内部结果渲染成模型可读文本的代码隐瞒了关键事实（搜索范围、截断、估计不确定性、标识符来源），从而误导下游的 agent 和验证器——这是以往工具学习与 agent 评测工作（AgentBench、τ-bench 等均把工具输出当作可信环境的一部分）没有检验的一层。
- **基于真实生产系统归纳出四类缺陷家族**：范围（漏报"只搜了前 100 万字符"）、完整性（"Found 20 document(s)" 实际命中 4,772 条）、不确定性（把比例估算的页码当确认值输出）、来源（文档 ID 与扫描 ID 两个命名空间几乎完全重叠，17,807 个文档 ID 中有 17,805 个同时是无关扫描的有效 ID）。
- **严格的配对因果实验**：同一工具结果仅更换措辞（A=扭曲版 / B=清晰版，哈希冻结文本），40 个案例中 8 个调参、32 个留出；1,200 次 agent 运行 + 240 个验证器判决，证明措辞本身足以改变 agent 声明与验证器判决。
- **诚实的负结果**：清晰措辞对来源（provenance）家族几乎无效（100% → 94%），说明标识符混淆需要类型系统/校验强制，而非更好的文本。
- **可复用的审计提示词**：用 Codex 和 Claude Code 在自家旧代码上重新发现仍存活的缺陷并新增 12 个未编目实例；对 OpenClaw 和 Hermes 两个开源 agent 系统各发现真实缺陷，OpenClaw 的修复 PR 已被维护者合并。

## Key Contributions

- **Names and taxonomizes "warped formatters"**: the code layer that renders a tool's internal result into model-readable text can omit what the computation actually did — even when every printed sentence is technically true. Prior agent benchmarks (AgentBench, τ-bench, GroundEval, NabaOS) start checking at or after the formatter boundary; none compares what the tool did with what its words tell the model.
- **Four defect families extracted from a deployed system** (a RAG research assistant over a 17,807-document digitized archive used by the Pilsudski Institute in New York): scope (false absence beyond a 1,000,000-character search cap), completeness (result caps reported as totals), uncertainty (proportional page estimates printed unlabelled), and provenance (overlapping integer ID namespaces).
- **A paired, hash-frozen, pre-registered-style evaluation**: identical tool results rendered under warped (A) vs. clear (B) wording; 40 cases (8 tuning, 32 holdout), 1,200 agent runs across Claude Sonnet 5, GPT-5.6 Sol, and Gemini 3.1 Pro (temperature 1.0, 5 replicates), graded by two cross-vendor model graders with human adjudication against pre-written claim lists.
- **A causal verifier measurement**: author-written false answers judged under both wordings isolate the formatter as the only varying input — 90/90 verdict flips from SUPPORTED (warped) to UNSUPPORTED (clear) across scope, completeness, and uncertainty.
- **A practical, transferable audit prompt** (verbatim in Appendix B) that ordinary coding agents can run on any codebase; it rediscovered the paper's own live defects, surfaced 12 uncatalogued instances, and found warped formatters in two popular open-source agentic systems (OpenClaw fix merged; Hermes PR open).

## Methodology

The study proceeds in three parts. First, an audit of the production system's formatter layer yields the four defect families, each anchored in reproduced database facts (e.g., a term first occurring at character 1,000,072 of a 1,031,201-character transcript — beyond the 1M cap the output never mentions; a 1920 date-range search returning "Found 20" of 4,772 true matches, with 90 distinct years exceeding one fetch).

Second, a paired experiment: each case is one concrete tool call with a known correct answer. Condition A carries the warped wording (some verbatim from production); Condition B carries the shipped clear wording that discloses scope, completeness, uncertainty, or provenance. Both texts are frozen by hash. Agents receive a minimal research-assistant prompt, the user question, and the tool output, then answer once (no tool loops, 4,000-token cap). Overclaim is graded against per-case forbidden-claim lists (hedging is accepted); two model graders from different vendors reach consensus at temperature 0.0, with a human author adjudicating the 53 disagreements. Verifiers are measured two ways: a *fixed-answer* measure (one planted false answer per case, judged under both wordings — pure causal isolation) and a *frequency* measure (real agent answers judged by cross-vendor verifiers). A control crosses two questions (supported vs. correct) with two evidence levels (tool output only vs. output + verified facts) on 46 real warped-wording false answers. Safeguards include a deterministic construction checker (40/40 warped texts flagged, 0/40 false positives), prespecified exclusions, and seeded sampling.

Third, an exploratory audit demonstration: a short frozen prompt instructs Codex / Claude Code to inventory every formatter in a codebase and compare "what the formatted output tells the model" against "what the code actually did," reporting findings without fixing them.

## Results & Highlights

- **Agent overclaim (32 holdout cases, 120 answers per family per condition, 960 total)**: clear wording cut overclaim from 100% → 8% for scope (+92 pp, 95% CI [+80, +100]), 62% → 0% for completeness (+62 pp, [+46, +78]), and 100% → 20% for uncertainty (+80 pp, [+73, +87]) — but only 100% → 94% for provenance (+6 pp, [+2, +11]).
- **Fixed-answer verifier measure**: the three cross-vendor verifiers accepted planted false answers 30/30 under warped wording and rejected them 30/30 under clear wording for each of scope, completeness, and uncertainty — 90/90 verdict flips from false acceptance to correct rejection; provenance moved only from 18/30 (60%) to 14/30 (47%).
- **Frequency measure (real warped-wording overclaim answers)**: verifiers accepted 229/240 (95%) of scope overclaims, 136/148 (92%) of completeness, 220/240 (92%) of uncertainty, and 120/240 (50%) of provenance — verifiers as deployed inherit the formatter's blind spot almost completely.
- **Control (46 real false answers, 92 verdicts per cell)**: asking "is it supported?" with output only → 88/92 (96%) false acceptance; adding verified facts alone → 56/92 (61%); asking "is it correct?" with output only → 90/92 (98%); facts + correctness framing together → **0/92 (0%)** — verifiers can catch the errors only when given the missing facts *and* the right question.
- **Robustness and cost**: strict document-level holdout left scope at 105/105 (100%) under A vs. 9/105 (9%) under B; grader consensus was 1,147/1,199 (96%) with human blind regrade matching 35/36; total API spend across all pilots and the full run was **$74.44**.
- **Audit transfer**: on the authors' own pre-fix snapshot, Codex and Claude Code rediscovered both live defects and reported 12 additional uncatalogued warped formatters (including a `semantic_search` formatter silently discarding 2 of 5 retrieved results); on OpenClaw it found `attachments_fetch` reporting messages outside its bounded history window as "not found" (fix merged, PR #131702); on Hermes it found `search_files` truncating matched lines at 500 characters with no marker (PR #96632, still open).

## Authors & Credibility

Single-authored by William Jeffries (independent, gmail contact), accepted at the NeurIPS 2026 Workshop "Who Verifies the Agents? Toward Reliable Agent Development." Credibility is unusually strong for a workshop paper: both condition texts frozen by hash before grading rules were fixed; claim lists written in advance; tuning/holdout separation with a prespecified robustness re-analysis; cross-vendor model grading with disclosed disagreement rates and human adjudication; a deterministic construction checker verifying the manipulation; and full release of experiment code, frozen cases, prompts, recorded answers, and adjudications at github.com/williamcodes/who-verifies-the-tools. External validation of the audit prompt comes from two real open-source projects (one maintainer-merged fix), not just the authors' own system. The production-system provenance (real incidents at the Pilsudski Institute archive) grounds the defect families in deployed failures rather than synthetic ones.

## Critical Assessment

- **Novelty**: genuine and well-positioned — the paper identifies a layer (formatter fidelity) that tool-use and groundedness work (Ragas, FActScore, FEVER-style verification) provably cannot check, because the omitted boundary/qualification never enters the text. That said, the core finding ("what the model sees determines what it claims") is an application of known prompt-sensitivity results to a new locus, not a new model of model behavior.
- **Rigor**: the paired design with hash-frozen texts, cross-vendor graders, prespecified claim lists, and an honest negative result (provenance +6 pp) is better methodology than many main-conference agent papers. But there are real soft spots. Condition B bundles factual disclosures with behavioral instructions ("do NOT tell the user…"), so the headline +62 to +92 pp effects cannot be attributed to disclosure alone — the authors admit this but it weakens the actionable claim. The 90/90 verifier flip uses author-written, deliberately maximal false answers, a worst-case construction likely to overstate real-world flip rates. The frequency measure is confounded (different wordings produce different answer sets), which the authors acknowledge. Scope cases rest on just 7 archive documents that can exceed the cap, so documents repeat across cases and one document landed on both sides of the tuning/holdout split — handled by a prespecified re-analysis, but the effective diversity of the scope family is thin.
- **Reproducibility**: excellent — code, frozen manifests, prompts, answers, and adjudications are public; API cost ($74.44) makes direct replication trivial. Model identifiers (claude-sonnet-5, gpt-5.6-sol, gemini-3.1-pro-preview) are named.
- **Significance**: the checklist (state searched scope, flag truncation, label estimates, namespace identifiers) is immediately actionable, and the merged OpenClaw PR demonstrates real-world bite. However, cases were adversarially selected from known defects in one system — the paper itself concedes this is a stress test with "no estimate of how often such defects occur," so no base rate for warped formatters in the wild is established.
- **Red flags**: single author and single production system; the audit-prompt demonstration was written by people who already knew their system's defects, ran with Codex memory disabled after a voided launch (the agent had read its own notes about the system), and its "confirmations" on the home system came mostly from adversarial *model* reviewers with human review of only a selection. The Hermes finding is unmerged at time of writing. Claude Code's non-disableable user-level instructions were checked but not eliminated as a channel.

## Strengths

- Identifies a previously unnamed, structurally invisible failure class and shows both the agent-side and verifier-side damage with a genuinely causal paired design.
- Exceptional methodological hygiene for its venue: hash-frozen stimuli, tuning/holdout splits, frozen grading rules, cross-vendor consensus grading, human adjudication, deterministic construction checks, prespecified exclusions.
- Reports its own failure honestly: wording fixes do not cure identifier confusion (94% residual overclaim), and "estimate laundering" (hedging the labeled estimate while stating the derived archive page as fact) survives the clear wording at 20%.
- The four-disclosure checklist and the frozen audit prompt are immediately usable by practitioners on any codebase, with external validity evidenced by merged upstream fixes.
- Near-zero cost ($74.44) demonstrates that this class of audit is cheap enough to be routine.

## Limitations

- Four failure families from one production system; other systems may have families the taxonomy misses (the authors even note a new one found while typesetting — a truncated font warning).
- Adversarially selected, stress-test cases: no estimate of how often warped formatting occurs naturally; the 8%–20% residual and 100% warped baselines should not be read as field rates.
- The harness strips real-agent capabilities: one tool output, one answer, no tool loops, no production system prompt — capable agents might sometimes investigate around the warp.
- Condition B conflates disclosure text with handling instructions, so the effect of the disclosure fields per se is unmeasured.
- Three model families at one time point; grader consensus is model-based with human adjudication of disagreements only; the fixed-answer measure rests on author-written false answers.
- The audit-prompt exercise is an unevaluated demonstration whose prompt was authored with prior knowledge of the target system's defects.

## Relevance

与"Agent & Pipeline Silent Failures"方向高度契合：本文研究的正是模型与世界之间被忽视的软件层——工具输出格式化器——如何静默地篡改模型接收到的信息，并给出了系统性的检测（审计提示词）与修复（措辞披露 + 上游 PR）方案；同时它直接回答了长程自主 agent 系统可信度中"谁来验证工具本身"这一问题，对构建可靠的 agent 评测与验证管线有直接工程价值。

## Questions for Further Exploration

- What is the base rate of warped formatters across popular agent frameworks — would a blind (author-unaware) version of the audit prompt find the same defect density as the knowledge-informed one used here?
- Can the +62 to +92 pp effects be decomposed into disclosure-only vs. instruction-only contributions with a third condition, and does instruction text generalize or merely patch the specific cases?
- Why do agents ignore explicit `[doc:…]` namespaces — is provenance failure a formatting problem at all, or does it require typed tool schemas / API-level validation (e.g., distinct ID encodings or cross-namespace 400s) to fix?
- Does estimate laundering (hedging the labeled value while asserting the derived one) generalize to other uncertainty-disclosure styles, such as confidence intervals or separate "derived-from" fields?
- How do warped formatters interact with multi-turn tool loops — can agents that re-query, paginate, or run read_page_scans recover the omitted facts, and at what cost in tokens and trust?
- Could verifier-side "fact injection + correctness framing" (the 0/92 control condition) be productized as a cheap post-hoc check that compensates for formatter defects until they are fixed?
