> **一句话总结：** 本文提出 RITE 基准（9 个腾讯工业级电商工作流、167 个匹配单元、501 个实例），通过在固定执行前缀中注入"语义合理但错误"的工具返回值来测 agent 韧性：10 个前沿 LLM 的任务成功率被静默错误几乎砍半（隐式 RSR 0.277–0.403 vs 正确条件 0.716–0.827），且"识别 → 重取 → 恢复"构成三级瓶颈；轻量 State Checker 能让模型更频繁地查证，却几乎无法提升最终成功率——"让模型去看容易，让它修好难"。

> **TL;DR:** RITE is an ICLR 2027 benchmark of 501 instances built from nine production Tencent e-commerce workflows, where every silent (schema-valid, plausible-but-wrong) tool error is injected at a fixed checkpoint with matched correct-value and explicit-failure twins. Across 10 LLMs, silent errors roughly halve task success (implicit Result Success Rate 0.277–0.403 vs 0.716–0.827 in the correct condition; Retention 0.345–0.526) and are consistently harder than matched explicit failures (paired explicit-minus-implicit gap +0.089 to +0.265, +0.214 pooled) — e.g., best model Claude-Opus-4.8 drops from 0.765 correct-condition RSR to 0.403 under silent error. The paper traces failures through recognition (Noticed only 0.208–0.336), verification (only 23.3% of Noticed rollouts end with the gold value), and integration (59.2% of refetches recover gold, yet ~1/3 of those still fail), and shows a lightweight State Checker triples GLM-5.2's refetch rate without commensurate RSR gains.

## 核心贡献

- **任务形式化（Silent-error Resilience Task）**：首次将"静默工具错误"定义为受控的交互式评测任务——一个语义合理、符合 schema、无失败信号的错误中间值进入 agent 执行历史后，agent 能否识别它、重新获取可靠证据、并完成原始查询而非把错误传播到最终答案。
- **RITE 基准**：基于真人编写的 9 个工业级电商工作流（部署于腾讯内部工作流平台）和另一内部数据平台的生产日志采样输入，构造 167 个匹配单元、501 个实例（每个单元含正确值 / 静默错误 / 显式失败三个条件，共享查询、结果约束和续跑环境）。
- **受控可复现的注入协议**：沿"生产者 → 槽位 → 消费者 → 下游结果"图选择业务相关槽位，按七类语义错误分类法（类目兄弟漂移、类目粒度失配、实体近重复、画像属性漂移、数值桶移位、语义同义漂移、时间过期）构造替代值，写入固定前缀；工具行为冻结为重放世界（已记录调用返回相同输出，未记录的有效调用转发到平台真实实现），保证所有模型在相同决策点面对相同错误。
- **三级瓶颈实证**：对 10 个 LLM 的系统分析表明，静默错误使成功率近乎减半，且失败沿"识别 → 生产者重取 → 证据整合"逐级累积；87.4% 的污染会改变下游电商业务输出。
- **轻量干预 State Checker**：在每次使用工具结果前强制反思其可靠性，能显著提高识别率与重取率（GLM-5.2 重取率提升三倍以上），但最终成功率提升有限——定位了"证据整合"这一真正瓶颈。

## Key Contributions

- **Task formulation.** The Silent-error Resilience Task: after a plausible, schema-valid, but incorrect tool result enters the agent's history with no failure signal, can the agent recognize it, reacquire trustworthy evidence, and still produce a correct final answer? Unlike prior fault-injection benchmarks where each agent only meets a fault if its own free-running trajectory reaches the perturbed call, RITE gives every model the same recorded execution prefix up to the same checkpoint.
- **RITE benchmark.** 167 matched units across nine human-authored industrial e-commerce workflows, expanded into 501 instances (167 each for silent-error/implicit, correct-value, and explicit-failure conditions sharing the same query and result oracle). Inputs are derived from production logs; 147 units intervene at tool output, 20 at tool input.
- **Semantic error taxonomy.** Seven leaf types in two groups — object/category selection errors (category sibling drift, category granularity mismatch, entity near-duplicate) and attribute/value errors (profile attribute drift, numeric bucket shift, semantic synonym drift, temporal staleness) — synthesized from adjacent failure taxonomies by two independent authors; six of seven are instantiated (temporal staleness excluded because detecting it needs time-indexed evidence the agent never observes).
- **Controlled, recoverable-by-design evaluation world.** Recorded calls replay identical outputs across models and conditions; unseen valid calls hit the live tool. Because the replay world stores the clean trace, re-querying the polluted slot's producer returns the unpolluted value — every instance has a built-in verification path, isolating whether agents use it.
- **Empirical findings across 10 LLMs.** Silent errors roughly halve task success; recognition, producer refetch, and evidence integration form successive bottlenecks; damage concentrates in category errors and early workflow slots; a lightweight State Checker increases noticing and refetching far more than final success.

## Methodology

Each workflow–log pair (W_i, x_i) is executed on a side-effect-free replica (writes, reporting, locks, and external sends neutralized) to reconstruct a clean trace τ_i. Along the trace's value-propagation graph, a slot qualifies when it carries business-relevant content, is consumed downstream, and plausibly affects the outcome. The trace is truncated at that slot and rendered as three matched prefixes: **correct** (recorded value), **explicit** (overt failure such as an empty argument or error-bearing observation), and **implicit** (a taxonomy-guided substitute that is type- and schema-compatible, locally plausible, but changes task-relevant meaning, written either into the producer observation or a downstream tool argument). Four gates verify each candidate: plausibility, explicit-failure clarity, non-leakage (query/prefix must not reveal an intervention), and discriminability (gold-grounded and polluted-grounded answers must be distinguishable under the result constraint). In parallel, a replay world E_i is built from the clean trace; the evaluated model continues from each prefix in a standard agentic loop (call / reason / stop). Measures: **Noticed** (explicit anomaly recognition plus a remedial action), **Result Success Rate (RSR)** (final answer resolves the query), and **Retention** (implicit RSR / correct RSR). Ten models were evaluated — closed frontier (Claude-Opus-4.8, GPT-5.5), open-weight frontier (GLM-5.2, Kimi-K3, DeepSeek-V4-Pro, Hy3, Qwen3.5-397B), and smaller open-weight (Qwen3.6-35B, Qwen3.5-35B, Qwen3.5-122B) — each on all 501 instances at temperature 0 with a 25-step budget. GLM-5 serves as the automatic Result/state judge, validated against three independent human annotators on 100 stratified rollouts.

## Results & Highlights

- **Silent errors roughly halve task success (RITE, 10 LLMs):** implicit-condition RSR falls to 0.277–0.403 across all models vs 0.716–0.827 in the matched correct condition — Retention only 0.345–0.526. Best model Claude-Opus-4.8: 0.403 implicit vs 0.765 correct (Retention 0.526); even the best model preserves barely half of its baseline performance.
- **Silent errors are consistently harder than matched explicit failures:** explicit-condition RSR is 0.507–0.564, giving a positive paired explicit-minus-implicit gap for every model (+0.089 to +0.265; +0.214 pooled). GPT-5.5: 0.363 implicit vs 0.526 explicit (+0.185); Kimi-K3 shows +0.228.
- **Recognition is the first bottleneck:** implicit-condition Noticed is only 0.208–0.336 (Claude-Opus-4.8 best at 0.336). In the latest valid producer observation, 99.6% of Unnoticed rollouts still carry the polluted value; even among Noticed rollouts, 57.8% still match the polluted value and only 23.3% match gold.
- **Verification pays but is rare:** among Noticed rollouts, RSR is 0.655 with a producer refetch vs 0.387 without; yet GLM-5.2, with Noticed 0.217, has a producer-refetch rate of just 0.071 and the lowest Retention (0.345). Across the eight open-weight models, refetch rate correlates with Retention only non-significantly (r = 0.491, p = 0.217).
- **Refetch does not guarantee recovery:** of 147 implicit rollouts with a producer refetch, 87 (59.2%) recover the gold value, 60 (40.8%) match neither, and none still match the polluted value; ~1/3 of Noticed-plus-refetch rollouts still fail the task. Manual inspection of the 60 mismatches yields three post-recovery failure patterns: reasoning overwrite, lossy selection, and unsupported synthesis.
- **Real business impact:** for 146/167 slots (87.4%) the gold vs polluted value changes the downstream e-commerce output (different recommendation, intervention, or topic suggestion); every non-numeric error type changes output in ≥82.6% of slots vs 65.6% for numeric bucket shift. Retention on the output-changing subset is 0.408 vs 0.416 overall.
- **Damage localization:** category granularity mismatch is hardest (Retention 0.180, RSR 0.140), followed by category sibling drift (0.292 / 0.199); entity near-duplicate is mildest (0.608 / 0.507). Early slots are noticed most (0.264) yet recovered least (RSR 0.309, Retention 0.399) vs late slots (Noticed 0.122, RSR 0.395, Retention 0.470).
- **State Checker intervention:** rerun on half the slots for Claude-Opus-4.8, DeepSeek-V4-Pro, and GLM-5.2, it raises Noticed and producer-refetch rates (GLM-5.2's refetch rate more than triples) but yields only modest implicit-RSR gains — Claude-Opus-4.8 gains no RSR despite noticing more errors.
- **Label quality (human validation, 100 rollouts × 3 annotators):** Noticed agrees with the human majority on 87/100 (Cohen's κ = 0.739); Result agrees on 76/100 (κ = 0.318) with precision 97.1% and recall 75.3% — a conservative judge that marks solved only 69/100 vs the human majority's 89/100.

## Authors & Credibility

A joint HKUST–Tencent team (Wenshuo Zhang et al., with Jikai Wang and Yifeng Rong as co-corresponding authors from Tencent), published as a conference paper at ICLR 2027 — peer-reviewed venue. The benchmark is grounded in real deployed systems: nine human-authored workflows running on an internal industrial workflow platform and inputs sampled from production logs of a separate internal e-commerce data platform, which is far more ecologically valid than synthetic tool benchmarks. Credibility is bolstered by transparent procedures: two authors independently synthesized the error taxonomy from prior literature; four verification gates check every injected instance; 100 rollouts were re-annotated by three independent paid human annotators with raw agreement, Cohen's κ, and Fleiss' κ all reported; and an AI-use statement discloses that GLM-5 is the automatic judge and that AI assisted screening, polishing, and coding. The authors also publish an honest negative-leaning result for their own intervention (State Checker improves looking more than repairing).

## Critical Assessment

- **Novelty (high).** The matched-prefix design is the genuine contribution: prior fault-injection work (e.g., Zhu et al. 2026; Tian et al. 2026; Chen et al. 2026) lets each agent meet a fault at a different point with a different history, so agents cannot be compared on the same error at the same decision point. RITE's correct/implicit/explicit triplets at an identical checkpoint with a frozen replay world is a clean experimental design that isolates the failure-signal variable.
- **Rigor (mostly strong, one soft spot).** Temperature 0, paired statistics, four construction gates, and disclosed judging procedures are commendable. However, the automatic Result judge — the basis of every headline RSR number — reaches only 76% raw agreement with the human majority and κ = 0.318 (humans labeled 89/100 solved vs the judge's 69/100; 22/24 disagreements in the conservative direction). The authors argue the strictness is by design and identical across conditions, which preserves internal validity of the paired gaps, but absolute RSR/Retention values likely underestimate real task success, and the 100-rollout validation sample is small.
- **Reproducibility (moderate).** Everything depends on two internal Tencent platforms; workflows are anonymized (wf01–wf09) and the live fallback for unseen tool calls requires the internal deployment. The replay-world recordings are said to be stable in released artifacts, but independent replication of the live-tool path and extension with new workflows is likely impossible outside Tencent.
- **Significance.** The three-stage bottleneck decomposition (recognize → refetch → integrate) and the "making agents look is easier than making them repair" finding are actionable for anyone building tool-agent reliability mechanisms.
- **Red flags / caveats.** (1) Taxonomy claims seven types but instantiates six — temporal staleness is excluded, so coverage of time-induced drift (a common real production failure) is untested. (2) The environment is recoverable-by-design: re-querying the producer always returns the clean value, i.e., single-site, non-persistent corruption; the authors concede persistent/system-wide faults invalidate the State Checker's verification path (Appendix G), so real-world recovery rates should be expected to be lower. (3) Small subgroup samples: the slot-position analysis rests on 128 early / 26 mid / 13 late slots, so the late-slot Retention of 0.470 carries wide uncertainty; only 20 of 167 units intervene at tool input. (4) 167 units is modest versus thousand-instance agent benchmarks, and e-commerce-only limits domain generality. (5) State Checker is tested on only three models over half the slots, with no cost/latency accounting for the extra reflection steps.

## Strengths

- First benchmark to place business-semantic silent errors at controlled, matched decision points, enabling apples-to-apples comparison across models and against correct/explicit twins.
- Ecologically grounded construction from production logs and deployed industrial workflows rather than synthetic tools.
- Careful measurement stack: Noticed/RSR/Retention plus paired explicit-minus-implicit gaps, with judge labels human-validated and κ reported.
- Diagnosis goes beyond headline numbers: quantifies the recognition → refetch → integration chain and names three concrete post-recovery failure patterns (reasoning overwrite, lossy selection, unsupported synthesis) with illustrative trajectories.
- Honest reporting, including a largely negative result for their own intervention and an explicit AI-use statement.

## Limitations

- Built entirely on internal Tencent platforms; workflows are anonymized and the live-tool fallback is not publicly replicable (the paper does not demonstrate full external reproduction).
- Recoverable-by-design, single-site corruption with a deterministic clean re-query path — real silent faults are often persistent, multi-site, or systemic (acknowledged in Appendix G).
- Temporal staleness, one of seven taxonomy types, is never instantiated, leaving time-drift errors untested.
- Small effective scale for subgroup analyses (13 late slots, 20 tool-input units) and a single domain (e-commerce customer-service/recommendation flows).
- The automatic Result judge is conservative (κ = 0.318 vs human majority), so absolute success rates are likely underestimates even if paired comparisons hold.
- State Checker evaluated on only three models at half scale, with no analysis of its token/latency overhead or behavior under persistent faults.

## Relevance

高度契合"Agent & Pipeline Silent Failures"方向：论文研究的正是工具调用/编排层静默篡改模型所接收证据（schema 合法但语义错误的工具返回值）的检测与修复问题，其"识别→重取→整合"瓶颈分解对设计 agent 可靠性机制（验证路径、状态检查、证据整合护栏）有直接参考价值。

## Questions for Further Exploration

- How do the recognition → refetch → integration bottleneck rates change when the corruption is persistent (re-query returns the polluted value again) or multi-site, requiring independent evidence sources or tool substitution rather than a single refetch?
- Can fine-tuning or test-time interventions specifically target the integration stage (reasoning overwrite, lossy selection, unsupported synthesis), which State Checker leaves untouched, rather than just raising detection rates?
- Does the finding that early-slot corruptions are noticed most but recovered least generalize to longer-horizon, multi-workflow agent systems where verification must be scheduled across many steps?
- What is the cost-benefit frontier of always-on suspicion (State Checker on every tool result) versus selective verification triggered by plausibility checks or cross-tool consistency signals?
- Could the matched-prefix replay methodology be ported to open, public tool ecosystems (e.g., code-execution or web agents) to produce an externally replicable version of RITE?
- Is the conservative automatic judge (precision 97.1%, recall 75.3% vs humans) systematically penalizing partially-correct answers that users would accept, and would a graded partial-credit metric reorder the model ranking?
