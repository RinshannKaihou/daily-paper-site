> **一句话总结：** 本文分析发现 MLA 缓存中两个张量角色不同——压缩潜在向量主要承担 value 角色、解耦位置键主导注意力打分（占 92.5% 的 logit 归因）——据此提出免训练的 RAQ-MLA：为每个张量学习一个针对"其送达注意力输出的误差"优化的可逆变换（value-aware + score-aware），把含位置键在内的完整 MLA 缓存压到约 2.5 bit/元素（理论容量提升 6.5 倍），在 GLM、DeepSeek、Moonlight 四个模型上推理与代码任务与 BF16 差距保持在 0.5 分以内。

> **TL;DR:** Prior KV-cache quantizers target standard-attention K/V and leave MLA's decoupled positional key in BF16. RAQ-MLA shows the positional key carries 92.5% of the attention-logit attribution while the compressed latent acts mainly as the value, then fits role-specific invertible transforms (training-free, folded into the up-projections at read time). Across GLM-4.7-Flash, GLM-5.2-FP8, Moonlight-16B-A3B, and DeepSeek-Coder-V2-Lite it quantizes the FULL MLA cache to 2.47-2.50 BPE vs 3.78 for OSCAR/QuaRot INT2 and 4.67 for KVarN INT3, staying within 0.5 points of BF16 on AIME25/GPQA/MATH-500/GSM8K/HumanEval (mean delta -0.08, 0.00, +0.05, -0.14) where QuaRot drops -4.35 (GLM-4.7) and -20.57 (Moonlight, MATH-500 collapsing from 63.20 to 32.20); on RULER-NIAH it matches OSCAR's average (93.66 vs 93.60) with a 29.6% smaller cache, though both trail BF16 (96.95).

## 核心贡献

- **角色分析（Role analysis）**：首次系统分析 MLA 缓存两个张量的分布与量化误差传播路径。固定通道离群值只出现在解耦位置键 kR（行为类似标准注意力的 Key cache），而不出现在压缩潜在向量 cKV（行为类似 Value cache）。汇聚全部 47 层，位置项占注意力 logit 归因的 92.5%，kR 中十分之一的离群通道独占 63.8%；因此潜在向量的误差主要经 value 读出抵达输出，而位置键的量化误差会被放大（INT4 下从缓存中的 9.1% 升至输出的 14.7%）。
- **角色感知量化（RAQ-MLA）**：免训练方法。潜在向量按 token 做 INT2 量化并配 value-aware 变换（以"注意力暴露度 × value 上投影"为权），位置键按通道做 INT4 量化并配 score-aware 变换（以位置 query 的二阶矩为权）；两个变换在同一 token 加权二次目标下通过交替最小化求解，带收敛性定理（Theorem 4.1），不需要对模型求梯度或微调。
- **推理期零重构开销**：变换在写入路径应用，逆变换在读出路径被折叠进上投影矩阵（Ac⁻¹ 并入 W^UK/W^UV；AR⁻ᵀ 施加于不落盘的位置 query 上），运行时只增加三个与上下文长度无关的小矩阵乘；变换参数仅占 GLM-4.7-Flash 参数量的 0.08%。
- **全缓存约 2.5 bit 的近乎无损压缩**：在四个 MLA 模型（GLM、DeepSeek、Moonlight 系列）上把含位置键在内的完整缓存压至 2.47-2.50 bit/元素，理论 KV 缓存容量提升 6.5 倍，推理/代码任务平均与 BF16 差距 ≤0.5 分。
- **验证了代理目标的忠实性**：value-aware 损失与真实注意力输出误差在 128 个随机变换上 Pearson r = 0.992，score-aware 为 r = 0.852，说明最小化角色度量确是在最小化输出误差。

## Key Contributions

- **Role analysis of the MLA cache.** The two cached tensors play asymmetric roles: fixed-channel outliers appear in the decoupled positional key kR (behaving like a standard Key cache) but not in the compressed latent cKV (behaving like a Value cache). Pooled over 47 layers, the positional term carries 92.5% of attention-logit attribution (content term only 7.5%), and a tenth of kR's 64 outlier channels alone carry 63.8%.
- **Role-aware, training-free quantization (RAQ-MLA).** Per-token INT2 for the latent with a value-aware transform, per-channel INT4 for the positional key with a score-aware transform; both invertible transforms (512x512 and 64x64) are fitted under a single token-weighted quadratic objective by alternating minimization with a proximal term, with a convergence guarantee (Theorem 4.1), no gradients through the model, no fine-tuning.
- **Zero-reconstruction inference.** The inverse transform is folded into the read path (Ac⁻¹ into the up-projections; AR compensated on the never-cached positional query), leaving only three per-token matrix products at decode time, all independent of context length; transform parameters cost 0.08% of GLM-4.7-Flash's parameters (23.5 MiB/GPU over 47 layers).
- **Full-cache quantization at ~2.5 bits.** Quantizes BOTH cached tensors — including the positional key that prior MLA quantizers (KVarN) exempt — to 2.47-2.50 effective BPE, a 6.47x/6.40x theoretical capacity gain over BF16, while staying within 0.5 points of BF16 on reasoning/coding across four MLA models.
- **Faithfulness validation of the proxy objectives.** Across 128 random transforms at layer 23, the value-aware loss tracks the exact attention-output error with Pearson r = 0.992 (Spearman 0.964); the score-aware metric with r = 0.852 — evidence that minimizing the role metric minimizes real output error.

## Methodology

RAQ-MLA targets Multi-Head Latent Attention as introduced in DeepSeek-V2, which caches per layer a compressed KV latent cKV (width dc = 512) and a decoupled RoPE positional key kR (width dR = 64, shared across heads, 11.1% of cached elements). **Step 1 — analysis.** Comparing activation distributions (Figure 2), kR shows channel-aligned outliers like a standard Key cache while cKV spreads magnitude like a Value cache; this dictates granularity: per-channel for kR (isolating outlier channels from a shared scale), per-token for cKV. Tracing INT4 error stage-by-stage (Figure 3), the latent's 12.3% cache error shrinks to 1.7% at the attention output through the content key but stays 8.3% through the value, while kR's error amplifies from 9.1% to 14.7% — the score-setting tensor is exactly the one prior work left in BF16. **Step 2 — role-aware objective.** Each tensor X is stored as Q(XA)A⁻¹ for a learned invertible A, fitted to minimize a token-weighted quadratic D whose role metric Mt encodes how attention consumes the tensor: for the latent, Mt = Σh γt,h (W_h^UV)ᵀ W_h^UV where γt,h = Σq S²h,q,t is the "attention exposure" of token t; for the positional key, Mt = Σ qRᵀqR, the second moment of positional queries probing token t. **Step 3 — optimization.** Because rounding makes the objective discontinuous, the fit alternates between (a) solving a proximal strongly-convex quadratic for the inverse transform B = A⁻¹ holding quantized codes fixed, and (b) requantizing in the new basis; Theorem 4.1 shows the objective decreases monotonically and converges. **Step 4 — deployment.** On the write path A is applied before caching; on the read path inverses are folded into W^UK/W^UV (absorbed as in MLA) and the positional query, so the dequantized cache is never materialized. Calibration uses 128 RedPajama sequences of 64K tokens; the latent uses asymmetric INT2 with 128-channel groups and 0.94-quantile clipping (2.25 eff. bits), kR uses per-channel INT4 within a cache page (4.25-4.50 eff. bits at P=128/64), giving BPE = (512·2.25 + 64·4.25)/576 = 2.47 (2.50 with GLM-5.2's 64-token pages). Pages are quantized once sealed, with an open BF16 page on a sawtooth schedule shared by all methods.

## Results & Highlights

- **Reasoning/coding at the lowest bit width (Table 1, five tasks).** On GLM-4.7-Flash, RAQ-MLA at 2.47 BPE has mean delta -0.08 vs BF16, while KVarN INT3 (4.67 BPE) loses -1.48, OSCAR INT2 (3.78 BPE) -1.84, and QuaRot INT2 (3.78 BPE) -4.35; on AIME25 specifically RAQ-MLA scores 92.22 vs BF16's 93.33, OSCAR 87.78, and QuaRot 86.67. On GLM-5.2, RAQ-MLA at 2.50 BPE is exactly 0.00 delta while OSCAR (3.78 BPE) is +0.49 and QuaRot -2.85.
- **Where baselines collapse, RAQ-MLA holds.** On Moonlight-16B-A3B, QuaRot INT2 drops -20.57 on average, with MATH-500 collapsing from 63.20 (BF16) to 32.20, whereas RAQ-MLA at 2.47 BPE averages +0.05 (MATH-500 61.80). On DeepSeek-Coder-V2-Lite, QuaRot loses -7.87 vs RAQ-MLA's -0.14.
- **Long-context retrieval (Table 2, RULER-NIAH, GLM-4.7-Flash, 8 subtasks x 100 samples, 4K-128K).** RAQ-MLA at 2.66 BPE (INT4 latent + INT8 kR at the first and last two layers) averages 93.66 vs OSCAR's 93.60 at 3.78 BPE — matched accuracy with a 29.6% smaller cache — though both trail the BF16 control (96.95), and at 128K the gap is 79.13 vs BF16's 87.22. LongBench-v1 (21 tasks) likewise: 52.19 vs OSCAR's 52.38 at 30% less cache.
- **Ablation isolates each component (Table 3, GLM-4.7-Flash).** With kR in BF16 at 3.78 BPE, the value-aware latent transform reaches 92.22 AIME25 / 76.09 GPQA vs OSCAR's 87.78 / 72.06 and Hadamard's 86.67 / 69.19; quantizing kR too, the score-aware transform (G) lifts AIME25 from 87.78 (direct INT4, step F) to 92.22 at the same 2.47 BPE.
- **Efficiency (H20 GPUs, TP2, batch 1).** Theoretical cache shrinks 6.5x vs BF16 (8.2 GiB vs 52.9 GiB for one 1M-token GLM-4.7-Flash sequence; 3.6x vs FlashMLA's FP8 cache); at 512 context the decode kernel drops from 17.4 to 12.6 µs/layer (1.38x) and TPOT from 6.56 to 5.97 ms (1.10x), with the latent transform costing only 1.7-2.4 µs/layer fused (<2% of TPOT) and TPOT 6.8-9.0% lower for 1K-8K output tokens.

## Critical Assessment

- **Novelty: solid, incremental.** The role analysis (latent = value, positional key = score-setter) is the genuinely new insight, and turning it into per-tensor role metrics is elegant; the machinery itself (invertible transforms, Hadamard-style rotation, alternating proximal fits) is assembled from known ingredients (QuaRot/OSCAR-style transforms, GPTQ-style second-order objectives, KVarN's page-quantize schedule).
- **Rigor: high on the method side, softer on evaluation noise.** The proxy-validation experiments (r = 0.992 for the value metric) and the step-by-step component ablation are exemplary. But AIME25 has only ~30 problems (93.33 vs 92.22 is one problem), evaluated at temperature 1.0, and the paper admits only "some of the reported results are averaged over three seeds" — the headline deltas (-0.08, +0.05) sit inside this noise band, so "within 0.5 points" is the defensible claim, not "lossless".
- **Baseline comparability caveats.** QuaRot and OSCAR were not designed for MLA and were re-implemented by the authors with kR forced to BF16, which floors them at 3.78 BPE; they cannot compete at 2.5 BPE by construction. To the authors' credit they report OSCAR actually WINNING on GLM-5.2 (+0.49 vs 0.00) and DS-V2-Lite (+0.11 vs -0.14) at the cost of ~1.5x cache — an honest result that slightly tempers the accuracy narrative.
- **Long-context is the weak spot.** "Nearly lossless" holds for reasoning/coding; on RULER-NIAH both quantized methods trail BF16 by ~3.3 points on average (93.66 vs 96.95) and by ~8 points at 128K (79.13 vs 87.22), and RAQ-MLA needs a hand-tuned wider quantizer (INT4 latent + INT8 kR) at the first/last two layers to get there — a mixed-precision configuration that is extra per-task tuning not fully ablated. Only OSCAR (not KVarN/QuaRot) is compared on RULER/LongBench, and LongBench lacks a BF16 row.
- **Reproducibility: good on paper, unverified.** Full configs, bit accounting, and pseudocode are given, but no code release is mentioned; the fitted transforms depend on calibration data and page sizes, so third-party reproduction requires re-running the fits.
- **Significance: strong if the claims hold at scale.** All evaluated models are relatively small (Moonlight-16B-A3B, DS-V2-Lite) or unspecified-size (GLM-4.7-Flash, GLM-5.2-FP8); no DeepSeek-V3/R1-class model is tested. The 6.5x is a *theoretical capacity* number — measured wall-clock gain is only 1.10x TPOT at batch size 1, and batching/prefill/paged-KV interactions (where capacity converts to throughput) are not benchmarked.

## Strengths

- Principled, evidence-driven motivation: the 92.5%/7.5% logit-attribution split and the stage-by-stage error-propagation measurements directly justify every design choice (granularity, transforms, bit allocation).
- The proxy objectives are validated against ground truth (exact attention-output error) before being used — rare and convincing methodology.
- Training-free, negligible runtime overhead (transforms folded into existing matrix products; <2% TPOT), and a convergence guarantee for the fitting procedure.
- Full-cache quantization: unlike KVarN/QuaRot/OSCAR, the positional key — 11.1% of elements but the dominant error source — is actually compressed.
- Honest reporting, including baseline wins, the 128K retrieval gap, and an explicit AI-use statement.

## Limitations

- Headline deltas on the smallest benchmarks (AIME25: ~30 items, sampled at temperature 1.0) are within run-to-run noise; only "some" results are seed-averaged.
- Long-context retrieval pays a real accuracy tax vs BF16 (-3.3 avg, -8.1 at 128K on RULER) and needs a per-task mixed-precision recipe (wider quantizers at boundary layers) that resembles tuning-to-the-benchmark.
- Wall-clock benefits are modest (1.10x TPOT) relative to the 6.5x theoretical capacity claim; throughput-vs-batch-size trade-offs — the actual serving win — are not measured.
- Score-aware metric correlates noticeably worse with exact error (r = 0.852 vs 0.992 for value-aware), so the kR transform is fit on a rougher proxy.
- The diagonal-only approximation of the attention Gram discards off-diagonal terms that still account for 14.2% of value-path distortion at the tested layer.
- No public code mentioned; evaluation limited to four models from three families, none at DeepSeek-V3 scale.

## Relevance

直接命中"极致性能优化下的可靠性"方向：本文正面研究超低位（~2.5 bit）KV 缓存量化引入的量化误差如何在 MLA 注意力中传播、放大并最终扰动模型输出，并给出控制该误差的分析框架与治理手段，是量化精度-正确性权衡的具体案例。对关心低位数值计算误差与推理服务栈数值行为的读者高度相关。

## Questions for Further Exploration

- Does the 92.5% positional-term logit attribution hold for other MLA variants (different dR, partial RoPE, sparse-attention hybrids like DeepSeek-V3.2), or is it specific to the GLM/DeepSeek configuration studied?
- Can the capacity gain be converted into measurable throughput at realistic batch sizes, and how does the packed cache interact with paged KV-memory allocation and prefix reuse?
- Why exactly do the first and last two layers need wider quantizers for retrieval — is it a RoPE-frequency effect on kR outlier channels, and can it be predicted rather than tuned per benchmark?
- Would a joint (non-diagonal) treatment of the attention Gram, recovering the ~14% off-diagonal value-path distortion, improve INT2 latent accuracy further?
- How does RAQ-MLA compose with weight quantization (e.g., the FP8 GLM-5.2 it already evaluates) and with sparse attention, where score errors interact with token selection?
- Are there failure signatures (task types, prompt positions, or layer indices) where 2.5-bit caches silently corrupt long-horizon agent outputs even when benchmark averages look clean?
