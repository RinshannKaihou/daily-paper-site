> **一句话总结：** 通过对掩码扩散语言模型（LLaDA-8B/Dream-7B）做掩码原生因果追踪，发现事实检索由"第0层注意力把关系词路由进可见实体位置 + 第1–8层MLP在融合表征上查表"两阶段完成；基于这一"事实访问态"（一个随关系措辞和查询方向变化的区域而非点），作者提出 Multi-View Edit——用模型自身的掩码算子构造前向/反向/关系遮蔽/上下文视图族，在每个方向拟合一个共享 value 写入早期 MLP——在 BAKE 上把反向问答从 22.35% 提到 63.24%（LLaDA-8B）、从 20.26% 提到 83.57%（Dream-7B），而已发表 AR 编辑器在 GPT-J/LLaMA-2 上仅提升不足 3 个点；读取同一状态又得到免训练的按实体检索向量，在双实体查询上以 41.94% vs ≤3.06% 的 All@2 大幅超越 BM25/Pooling/PromptReps 等单向量检索器。

> **TL;DR:** The paper reverse-engineers how masked diffusion LMs (LLaDA-8B, Dream-7B) look up facts: layer-0 attention routes the relation's wording into the visible entity's position (84% of that layer's causal effect), and MLPs 1–8 read the fact off this "factual access state" — which depends on relation surface form and query direction, so one fact occupies a region of state space, not a point. Writing across that region (Multi-View Edit: masked forward/reverse/relation/context views, one shared value per direction, installed in early MLPs) lifts BAKE reverse-QA from 22.35% to 63.24% on LLaDA-8B and 20.26% to 83.57% on Dream-7B (+40.89/+63.31 pts), where published AR editors (ROME/MEMIT/BIRD on GPT-J, LLaMA-2) gain at most +2.9. Reading the state gives training-free per-entity retrieval vectors that retrieve both evidence cards for two-entity queries at 41.94% All@2 (LLaDA Subject-L31) vs at most 3.06% for BM25, whole-query pooling, DiffRetriever, and PromptReps, at 1.5–2.0 ms/query from the first block. Honest caveat: QAEdit free-form paraphrase transfer stays partial (majority of answers still wrong).

## 核心贡献

- **机制发现（掩码原生因果追踪）**：把 ROME 式因果追踪改造成 DLM 原生版本（用 [MASK] 而非高斯噪声做扰动），在 LLaDA-8B 的 CounterFact 上定位出两阶段事实访问：恢复第 0–8 层即可达 IE=0.936（近乎全网天花板），其中仅第 0 层注意力单独贡献 IE≈0.238，MLP 1–8 单独 0.781，第 0 层 MLP 仅 −0.015，二者合并 0.943；18–25 层的"晚峰"只是滑窗堆叠的伪影。注意力手术表明主语→关系边的 IE 为 +0.199（占第 0 层效果的 84%），即第 0 层把关系措辞路由进实体位置。该机制在 Dream-7B 与"宾语可见、主语被掩"的角色互换设定下复现。
- **提出"事实访问态"概念**：a(e, r, d) 是早期块中实体位置上、经第 0 层注意力路由后融合了关系措辞与查询方向（前向/反向）的残差流表征；同一事实的各查询占据状态空间的一个区域而非一点——这解释了为何单视图 AR 式编辑在释义与反向查询上失效。
- **写入状态：Multi-View Edit 编辑器**：用模型自身掩码算子 q_t 构造视图族（V_obj 遮宾语、V_rel 以 ρ∈{0.4,0.7}×3 种模式部分遮关系、V_ctx 前后缀模板、V_rev 反向读键于新宾语），每个方向用 Adam 拟合一个共享 value（交而非并，安装秩不随视图数增长），沿白化方向（C 取随机掩码输入下键的二阶矩）以 MEMIT 式残差分配写入早期 MLP 下投影，不改注意力。
- **读取状态：免训练证据检索**：把每个实体位置的状态（块 0 输出或验证集选的深层，LLaDA 为 L31、Dream 为 L27）按余弦相似度作为关系特定的检索向量，双实体查询交替填充共享预算，无需训练或查询分解。
- **机制—应用闭环**：触发强度分析显示反向键把 Reverse-QA 的 α_fire 从 0.08 升到 0.56、全视图族到 0.61，而邻域提示 α=0.03（特异性保持）；检索侧，减去第 0 层关系消息使实体内关系选择降到四选一随机水平而实体识别保持 100%，替换为其他关系的消息则检索被重定向——写入与读取共享同一机制。

## Key Contributions

- **Mechanism via mask-native causal tracing.** Adapting ROME-style tracing to DLMs (corrupting with the native [MASK] operator, scoring masked-position prediction), the authors show on LLaDA-8B/CounterFact that restoring layers 0–8 reaches IE=0.936 — essentially the whole-network ceiling — with layer-0 attention alone at 0.238, MLPs 1–8 alone at 0.781, layer-0 MLP at −0.015, and the combination at 0.943. The apparent late peak (layers 18–25) is an artifact of window stacking (each individual MLP layer contributes ≲0.03). Attention surgery shows subject→relation edges alone carry 84% of layer-0's effect (IE +0.199), i.e., layer 0 routes relation wording into the entity position. Findings replicate on Dream-7B and with subject/object roles swapped.
- **The "factual access state" concept.** The state a(e, r, d) — the early-block residual at the visible entity after layer-0 routing — is a function of entity, relation surface form, and direction (fwd/rev). Queries about one fact form a region of state space, not a point, which directly explains why point-fitted AR edits fail on paraphrases and reverse questions in DLMs.
- **Writing: Multi-View Edit.** From one declarative statement it builds masked forward/reverse/relation-occluded/context views via the model's own corruption operator, fits one shared value per direction (an intersection, not a union, of view constraints — installed rank does not grow with the number of views), and installs it in early-MLP down-projections along a whitened direction, MEMIT-style; attention is never touched.
- **Reading: training-free evidence retrieval.** Per-entity access states (at block-0 output or a validation-selected deeper layer) serve as relation-specific retrieval vectors, alternating between entities' rankings under a shared budget — no training, no query decomposition.
- **Mechanism-to-application closure.** Trigger-strength analysis ties edit gains to key coverage (reverse α_fire 0.08→0.56→0.61 as keys are added; neighborhood prompts at α=0.03), and causal subtraction/substitution of layer-0 relation messages eliminates or redirects the retrieval advantage.

## Methodology

The paper proceeds in three stages. (1) **Localization**: mask-based causal tracing computes the indirect effect IE of restoring each hidden state during a corrupted (subject+object masked) pass; sliding windows (w=10) give a coarse profile, single-layer ablations decompose it, and five attention-surgery conditions (subject tokens restricted to relation / subject-internal / self / [MASK] edges, sink removed) isolate what layer 0 computes. (2) **Multi-View Edit**: given statement x with subject/relation/object spans and new object o*, views are constructed with the model's corruption operator — V_obj masks the object; V_rel additionally masks ⌈ρ|r|⌉ relation tokens (ρ∈{0.4,0.7}, 3 patterns each); V_ctx wraps prefix/suffix templates (DLMs also condition on what follows, so suffixes matter); V_rev swaps roles so the key is read at o*. One value z* per direction minimizes the averaged view loss under a relative-norm clamp; the key written along is the view-averaged key, whitened by the second moment C of keys from randomly masked inputs so the edit does not fire along high-variance ordinary-text directions; the residual is distributed across edit layers exactly as in MEMIT. (3) **Retrieval**: score(q-entity, card-subject) = cosine of pooled layer-ℓ readouts (last entity token at L0, span-mean deeper); a benchmark of 5,528 evidence cards over 19 relations is built from PopQA, with 10,800 test queries across three layouts (single entity; two entities with adjacent entity–relation clauses; crossed references), plus a second entity-conditioned protocol that hands every method the same four candidate cards per entity. Evaluation covers CounterFact, BAKE, QAEdit (editing) and the PopQA benchmark plus HotpotQA/2WikiMultiHopQA comparison questions (retrieval), on LLaDA-8B(-Instruct) and Dream-7B(-Instruct); baselines include FT+L, matched single-view/single-direction variants, ROME/MEMIT/BIRD published AR numbers (scale references), BM25, whole-query pooling, DiffRetriever, and PromptReps (Qwen2.5-7B-Instruct).

## Results & Highlights

- **CounterFact paraphrase transfer (Table 2)**: Multi-View reaches Rel 99.88 / Para 99.24 / Neigh 73.04 / Loc 88.29 on Dream-7B vs Single-View Para 72.05 (FT+L: Para 86.47 but Neigh only 18.95); on LLaDA-8B Para improves 53.65 → 67.92 while locality rises 68.31 → 89.92. Source reliability stays ≥97.6% everywhere (Multi-View 98.14 / 99.88).
- **BAKE reverse access (Table 3)**: on LLaDA-8B, Reverse-QA rises from the no-edit 22.35% to 63.24% with Multi-Binary (+40.89) vs +0.17 for Single-Forward and +19.68 for Single-Binary; on Dream-7B, 20.26% → 83.57% (+63.31). Reverse-Judge: +25.01 (LLaDA) and +37.60 (Dream). Published AR editors (ROME/MEMIT/BIRD on GPT-J-6B and LLaMA-2-7B) gain at most +2.9 Reverse-QA — though on different models and edit pools, so not controlled. The masking axis alone adds 21.2 points on LLaDA and 10.6 on Dream (21.8 at matched view budget).
- **QAEdit open-ended generation (Table 4)**: on 2,272 pre-edit-wrong examples, Multi-View's weighted source score is 0.250 (LLaDA-8B) and 0.342 (Dream-7B) vs FT+L's 0.206/0.243; ≥0.5-partial correct source answers reach 32.5% / 44.6%. Composing with Park & Jo's decoding-state views lifts LLaDA weighted scores further, 0.250→0.430 (source) and 0.187→0.352 (paraphrase).
- **Two-entity retrieval (Table 5)**: all single-vector baselines collapse on dual-target All@2 — BM25 1.38/1.01 (adjacent/crossed), Qwen2.5 pooling 1.28/0.00, PromptReps 1.58/1.56, DiffRetriever-hybrid 1.25–1.36/1.03–1.28 — while per-entity access states retrieve both cards for 41.94% adjacent / 38.08% crossed (LLaDA Subject-L31) and 38.28%/21.78% (Dream Subject-L27). The entity-conditioned protocol preserves the ordering (41.94/38.08 vs ≤16.35/16.26), locating the advantage in relation selection.
- **Early + cheap + causal**: the first-block readout already achieves 24.44%/13.33% (Dream) and 13.32%/9.44% (LLaDA) dual-target All@2 and costs 1.5–2.0 ms/query vs 13–26 ms for full-depth neural retrievers and 265 ms for PromptReps; on HotpotQA/2WikiMultiHopQA comparison questions, Both@2 is 41.82%/37.37% vs BM25's 25.15%/26.93% at 2.6 ms/query, and a frozen reader gains 4–8 F1. Subtracting layer-0 relation messages drops relation accuracy to 4-way chance with entity identification still 100%.

## Authors & Credibility

Yuchen Guo (University of Tokyo; work done during an internship at LIGHTSPEED), Zhuoyuan Mao (LIGHTSPEED, Tencent), and Yiwen Guo (independent researcher, corresponding author). The paper reads as a serious mechanistic-interpretability effort: code is released (github.com/Guoyuchen1/dlm-factual-access), a reproducibility statement specifies seed 42, hyperparameters, templates, precision and compute, and the appendix unusually includes self-critical analyses — e.g., a dissection showing BAKE's published pre-edit floor of 0.00 on the judgment probe is inherited from the QA probe rather than measured, and the authors measured their own DLM floors (30.6%/18.2%) instead of assuming zero. Matched-budget ablations (Single-View, Single-Binary, matched view count) rather than only cross-paper comparisons support the causal claims. No peer review yet (preprint, arXiv Oct 20 2026).

## Critical Assessment

- **Novelty**: High on mechanism (first mask-native causal tracing of factual recall in DLMs, to my knowledge, with the layer-0 relation-routing finding) and solid on application (multi-view key coverage is a natural but well-executed idea). The "access state" framing unifying editing and retrieval is genuinely elegant.
- **Rigor**: The strongest aspect. Window-tracing artifacts are decomposed via single-layer ablations; the editor's gains are attributed through matched single-view/single-direction ablations and a trigger-strength (α_fire) analysis rather than asserted; retrieval claims get both an entity-conditioned control and causal message-surgery. Replication across two DLMs and both mask directions guards against single-model stories.
- **Weak spots to flag**: (1) The headline "+40.9 vs <3 points vs AR editors" compares against published numbers on GPT-J/LLaMA-2 — different models and edit pools; the authors label them "scale references," but the abstract's "AR editors gain near zero" leans on this uncontrolled comparison. (2) The DLM baseline set is thin: no head-to-head with DiffER or other DLM-native editors beyond composing with Park & Jo; FT+L is the only external DLM baseline. (3) On Dream-7B CounterFact, Multi-View locality (88.29) is slightly below Single-View (89.91) and neighborhood specificity drops 74.48→73.04 — spillover is model-dependent, as the authors concede. (4) QAEdit paraphrase transfer remains weak in absolute terms (weighted 0.187/0.297; wrong answers still the majority), which the paper honestly states. (5) The retrieval benchmark is self-constructed from PopQA with exactly four relations per entity — a highly regular structure; the entity-conditioned protocol mitigates but the natural-text transfer (HotpotQA/2Wiki) is where generality actually gets tested.
- **Reproducibility**: Good — public code, fixed seed, full hyperparameter appendix, and deterministic components (no stochastic retraining; Adam optimizes a single vector z per direction).
- **Significance**: If the layer-0-routing / early-MLP-lookup architecture generalizes to larger DLMs, this becomes the reference "ROME/Geva et al. for diffusion LMs" paper, and the region-of-state-space view of keys is a transferable conceptual lesson for AR editing too.
- **Red flags**: None serious; the main risks are over-generalizing from 7–8B-scale models and the uncontrolled nature of the AR comparison that anchors the abstract's contrast.

## Strengths

- Clean mask-native adaptation of causal tracing (corrupting with [MASK], scoring masked-position prediction) that respects how DLMs are actually trained and decoded.
- The two-stage mechanism (layer-0 relation routing + early-MLP lookup) is established with converging evidence: window tracing, single-layer ablation, attention surgery, role reversal, and a second backbone.
- Multi-View Edit is directly motivated by the mechanism (fit the region of keys, not the single editing sentence), and the shared-value "intersection" design plus whitened key direction controls both locality and rank growth.
- The retrieval application recycles the same mechanism rather than bolting on an unrelated method; the causal subtraction/substitution experiment closes the loop.
- Efficiency by-product: first-block readout at 1.5–2.0 ms/query beats 265 ms PromptReps by two orders of magnitude on the dual-target metric.
- Unusual candor: measured (non-zero) BAKE pre-edit floors, explicit statement of QAEdit's incomplete transfer, and matched-budget ablations.

## Limitations

- The editor requires identifiable subject/relation/object spans, which CounterFact and BAKE supply but arbitrary user statements may not (stated by the authors).
- Free-generation transfer on QAEdit is partial — wrong answers remain the majority on paraphrased questions (Gen weighted 0.187 on LLaDA-8B).
- AR comparisons are cross-model/cross-pool references, not controlled; no comparison against recent DLM-native editors like DiffER beyond the Park & Jo composition.
- Mechanism claims rest on two 7–8B DLMs; behavior at scale and for LLaDA's mixture or larger Dream models is unverified.
- The dual-entity retrieval benchmark's regular structure (exactly four relations per entity, 19 relations, five domains) may flatter relation-binding readouts; crossed-reference performance on Dream (21.78%) is still far from the adjacent-layout numbers.
- Layer-0 attention is treated as a monolith; the paper does not dissect which heads or query/key subspaces perform the relation routing.

## Relevance

与"LLM Hidden States & Interpretability"方向高度相关：这是一篇对扩散语言模型做因果追踪与注意力手术的机制可解释性工作，把 ROME/Geva 式事实召回分析扩展到掩码 DLM，并演示了"机制→干预（知识编辑）→读取（检索）"的完整闭环，正是内部表征与电路分析这一兴趣线的核心样本。

## Questions for Further Exploration

- Does the layer-0 relation-routing + early-MLP lookup pipeline hold at 30B+ scale, or in DLMs with different pretraining mixtures (e.g., LLaDA's mixed AR/diffusion data)?
- Which heads in layer 0 carry the relation routing, and is the routing learned per relation type or driven by generic syntactic position signals?
- Can Multi-View Edit be extended to many sequential edits (MEMIT-style thousands of facts) without the view family amplifying interference between edits?
- Would fitting values over a sampled region of key space (a Monte-Carlo view family) also fix paraphrase/reverse brittleness in AR editors, given the same region-vs-point logic applies to their keys?
- Can the per-entity access-state retriever scale beyond 5,528 cards to corpus-scale retrieval, e.g., as a cheap first-stage filter feeding a full encoder?
- Does the access state support other region-respecting operations, such as fact deletion (unlearning) with the same locality guarantees?
- How does the access state interact with the reverse curse in practice — can Multi-View Edit install genuinely new reversed associations that were never in the pretraining data, and does that generalize to multi-hop compositions?
