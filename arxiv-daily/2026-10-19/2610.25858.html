Key Finding

Self-evolving agents are not yet continual learners — every evolution method trades new-skill plasticity for old-skill stability.

自修改方法产生跨任务干扰与覆盖性遗忘，检索式方法则存在外域记忆注入与检索冲突——现有自进化智能体仍不是合格的持续学习器。

Why This Matters

The first continual-learning audit of self-evolving agents exposes silent failures — cross-task interference, overwritten skills, memory collisions — that erode long-running autonomous systems.

对设计更可靠的自进化记忆与提示词更新机制有直接指导意义。

Critical Edge · Read It Critically

Every conclusion rests on a single backbone (Gemini 3.6 Flash) and short streams with one fixed block order — and the headline r = −0.72 comes from just n = 12 points: suggestive, not conclusive.

Methodology distilled from source

An LLM agent is a policy π(θ, c): frozen weights θ plus an evolvable harness c (system prompt, memory, skill files, controller code). After every episode an evolver rewrites the harness from accumulated experience, c′ = f(c, H), guided only by binary success reward. Classical continual-learning metrics are adapted to this loop: plasticity P (gain within a block) and stability S = −(pre-block interference + post-block forgetting), all in pp vs the seed harness.

Three methods, both paradigms

  • retrievalReasoningBank — distills episodes into memory items; top-1 cosine match re-injected at test time.
  • self-modGEPA — reflectively rewrites one shared strategy section of the system prompt.
  • self-modMeta-Harness — coding agent edits prompt + memory/skills + controller code; edits land only if validation accuracy improves.

Shared backbone: Gemini 3.6 Flash · temp 1.0 · 8 rollouts/instance · disjoint hold-out eval (50/group; 90 ScienceWorld) · checkpoints at every block boundary

  • Topic drift alone breaks evolutionNet terminal change: GEPA −1.7pp, Meta-Harness −1.5pp, ReasoningBank +0.3pp — new schemas nullify aggregate gains.
  • Interference arrives before the tasks doOn compound drift, BFCL-Miss sits at −6.8pp (GEPA) before any BFCL block; prompt autopsies show SQLite-exploration rules biasing behavior.
  • Forgetting is literally overwritingBIRD-F1’s share of GEPA’s prompt collapses 59.5% → 4.1% (7 SQL sections compressed into one); its +4.0pp gain is erased entirely.
  • Forgetting is a behavioral reversalClarification rate 29.8% → 11.2% once BFCL-Base arrives; BFCL-Miss slides +15.5pp → +2.5pp (−13.0pp). Meta-Harness repeats the pattern (60.8% → 8.5%).
  • Similarity retrieval collidesCross-group cosine 0.835–0.840 vs within-group 0.834–0.837 — no threshold can separate the workflows; 52% of BFCL-Miss episodes retrieve a foreign Base memory (−8.0pp).
  • Obvious fixes don’t workInterleaving drops GEPA +5.8 → +0.9pp; Meta-Harness’s stability is bought by its gate rejecting ≥half of candidate edits — rejection, not learning.

Strengths

  • Formal bridge from continual learning to harness evolution — reuses established metrics (Kemker; Lopez-Paz & Ranzato) instead of bespoke ones.
  • The four drift streams — especially BFCL-Miss vs Base — are a genuinely reusable evaluation design; a minimal, elegant workflow-conflict probe.
  • Failures are explained, not just scored: prompt character-share tracking and rollout-level behavior counts over 400 rollouts.
  • Sharp, quotable negative result: no retrieval threshold can separate the colliding workflows.
  • Appendix robustness checks (interleaving, gate ablation, per-group decomposition) pre-empt the two most obvious objections.

Limitations

  • One backbone only (Gemini 3.6 Flash) — whether the trade-off magnitude transfers to stronger models is untested.
  • Short horizons (T = 100–200, 2–4 groups), a single fixed block order per scenario, no variance over seeds or orderings reported.
  • ReasoningBank tested only top-1, threshold-free — its acknowledged worst case for foreign-memory injection.
  • Nonparametric evolution only; the comparison to gradient-based continual learning is conceptual, not empirical.
  • No code or benchmark-stream release; metrics are relative to each method’s own seed harness, so oracle headroom is hard to judge.

Questions for Further Exploration

  • Would an append-only constraint on GEPA’s edits preserve plasticity while killing overwriting — or does prompt bloat itself hurt?
  • Can retrieval keys go beyond query similarity (tool-call traces, environment identity, outcome-conditioned keys) to break the BFCL collision?
  • Does the trade-off worsen at scale — T = 1000+, K = 10+ — as the shared prompt saturates?
  • Do stronger base models shrink foreign-memory interference, or is it structural to top-1 retrieval?
  • What is the oracle headroom of a perfect per-group harness router, and can a learned one approximate it without group labels?
  • Would parametric evolvers (test-time weight updates) face the same wall under these streams and metrics?
