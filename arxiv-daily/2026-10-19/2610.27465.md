> **一句话总结：** 本文为"无人值守的智能体自我改进"提出两个可度量的前提——验证器强度 σ（验证器与参考验证器的 MCC 一致性）与可恢复性（撤销是否需要重新过闸、回滚能恢复多少行为）——并给出规则"只有旧版本被保留（g=0）且 σ 已被实测并达标时才允许免人工上线"；在 τ²-bench 航空域上的受控实验表明：保存副本的回滚可精确恢复行为（ρ−ρ₀=0.000），而重新生成的撤销不行（低 0.16）；已部署的修改会改变 17% 任务的结果且任何回滚都无法修复；同时其平台自己的 LLM 多样性闸门在 37 个配置中的 9 个里发生"静默坍缩"（对任何输入都返回同一分数且无报错）。

> **TL;DR:** A NeurIPS 2026 (AgenticOS workshop) paper from Uniphore asking how much of an agent self-improvement loop (read traces → derive change → verifier approves → deploy) can run without a human. It defines verifier strength σ (MCC vs a trusted reference) and recoverability (re-approval need g, restoration fidelity ρ, blast radius β), and proposes the rule: unattended deployment only if g=0 and σ ≥ σmin is measured. On the τ²-bench airline domain (50 tasks), the platform's own LLM judge shows σ=0.70 vs the program check but silently collapsed to a constant score in 9/37 production-gate settings with no error; restoring a saved prompt copy restores behavior exactly (ρ−ρ₀=0.000 vs baseline null floor ρ₀=0.95) while regenerated undos fall 0.16 short; and admitted changes altered outcomes on 17% of tasks beyond run-to-run noise (β−β₀=0.17 vs floor 0.08) — damage no rollback repairs. The σ→regret link rose (0.000 → 0.067 as σ dropped 1.0 → 0.001) but was not statistically significant at 20 test tasks.

## 核心贡献

- **两个可度量的免人工前提。** 定义"验证器强度" σ ∈ [−1,1]：候选验证器（常为 LLM judge）与可信参考验证器在轨迹集合上的 Matthews 相关系数（MCC）；选 MCC 而非准确率，是因为"永远给同一答案"的坍缩验证器 σ 恰为 0，而其准确率却可能体面。定义"可恢复性"三元组：g（撤销是否需要重新通过验证闸门）、恢复保真度 ρ（撤销后探针任务结果与改动前一致的比例）、爆炸半径 β（改动部署期间结果发生变化的任务比例）。
- **一条不可交换的自治规则。** 仅当 g=0（旧版本被保留，撤销是一次纯写回）且 σ 已实测且 ≥ σmin 时，改动才可免人工上线；两个量各自防范不同失败（弱验证器放行坏改动 / 不可逆改动让错误永久化），互不可补偿，任一未测则平台必须**拒绝**（refuse 是与 admit/reject 并列的第三种被记录的结局）。
- **一个落实该规则的平台。** 将四类改动（系统提示、工具 schema、技能、权重）按可恢复性分型：前三者 g=0 可自动晋升，权重更新因验证器是 §5.1 证明会静默失败的习得型 judge 而需人工签核；训练数据过滤闸门因无可信验证器而默认禁用；每个 agent 声明所用验证器及其实测 σ。
- **对规则假设的实证检验。** (a) 案例研究：生产多样性闸门发生"静默闸门坍缩"，两个廉价测试（删除信号、核查请求级保证）即可捕获；(b)(c) τ²-bench 受控实验分别单独变化 σ 与 g，支持"只有保留旧版本的改动才能无人恢复"与"已部署改动的影响无法被撤销修复"。

## Key Contributions

- **Two measurable preconditions for unattended self-improvement.** Verifier strength σ = MCC(v, v*) against a trusted reference on a trajectory set (constant-output verifiers score exactly 0, unlike accuracy); recoverability = {re-approval g ∈ {0,1}, restoration fidelity ρ, blast radius β}, all measured against stochastic noise floors from a null change.
- **A non-tradeable autonomy rule.** Unattended deployment iff g=0 and measured σ ≥ σmin; if either quantity is unmeasured the platform refuses. Verifier strength bounds the admit decision; recoverability bounds the live-system change; neither can compensate for the other, so autonomy is limited by the weaker one.
- **A platform enforcing the rule.** Changes typed by recoverability (prompt/tool-schema/skill edits: g=0, auto-promotable; weight updates: human sign-off; a data filter with no workable verifier: ships disabled); verifiers declared as resources with measured σ; refusal recorded as an auditable outcome with the missing precondition named.
- **Empirical tests of the rule's assumptions**, including a case study of silent gate collapse in their own production admission gate, two cheap acceptance tests that catch it, and controlled τ²-bench experiments varying σ and g one at a time.

## Methodology

The paper proceeds in three layers. **Definitions (§2):** an agent is A=(θ, p, T, K) (weights, system prompt, tool schemas, skills); a self-improvement step is a trace-derived change A→A′ admitted by a verifier with no human author, measured by Δk (change in solved-share over k repeated trials). Recoverability is measured with probe tasks P: g records whether the way back needs a new gate approval (kept old value → g=0; e.g. fine-tuning in place → g=1); ρ is outcome-agreement after undo; β is the share of tasks whose outcome changed while deployed — irrecoverable because those outcomes were already delivered. **The rule (§3)** and a platform that types changes by undo mechanism, declares verifiers with measured σ, and records refusals (§4). **Two evaluation settings (§5):** (1) a case study of the platform's pre-fine-tuning diversity gate — an LLM judge asked to reward breadth and penalize imbalance — tested over 172 settings × 10 runs (1,718 calls) across 3 judge models, 4 prompt variants, 4 imbalance levels, breadths 3–12, and two agents; (2) controlled experiments on τ²-bench's airline domain (50 tasks: 30 train / 20 test, natural-language assertions so a program verifier and an LLM judge score identical trajectories; reference = database-state equality plus communication checks; agent run twice per training and four times per test task), where experiment A corrupts σ by flipping reference verdicts with probability ε to get a known-strength verifier scale, and experiment B fixes the verifier and compares stored-copy rollback (g=0) against optimizer-regenerated undos (g=1, old prompt hidden). Statistics use 95% task-resampling bootstrap intervals, paired one-sided p-values, TOST equivalence, and Holm correction across candidates.

## Results & Highlights

- **Silent gate collapse in their own production gate (§5.1).** In the deployed configuration the LLM-judge diversity gate returned exactly 0.250 in all 40 runs with zero spread — the same score as when all imbalance information is deleted from the prompt. Full collapse (same score at all four imbalance levels) occurred in 9 of 37 configurations, all on the deployed judge (claude-haiku-4.5); on identical inputs the deployed judge stayed flat while both larger judges (claude-sonnet-5, claude-opus-5) tracked imbalance (p < 10⁻¹¹ each). This is not a greedy-decoding artifact (98 of 172 settings varied run-to-run), and the gate reported no error.
- **Real-verifier strength on τ²-bench airline (A1, 80 test trajectories).** The LLM judge reaches σ=0.70 against the program reference (Fisher p < 10⁻⁹) with false-admit rate α=0.10 and false-reject rate φ=0.21; errors cluster (all 4 false admits from one task, all 8 false rejects from two), so task-level resampling widens the interval to [0.36, 1.00]. A constant admit-all verifier scores exactly σ=0 while passing all 42 failing trajectories.
- **Weaker verifiers pick worse changes, but not significantly (A2).** Regret grows from 0.000 at σ=1.000 to 0.067 at σ=0.001 (calibration gap +0.0000 → +0.0671), but the fitted slope (−0.065, CI [−0.234, 0.120], one-sided p=0.23) includes zero; confirming it would need ~220 held-out tasks, 11× their 20. The bottleneck is the candidate pool: the best candidate is only 0.069 above average, so even a σ=0 random pick already incurs 98% of maximum regret. Secondary: with a perfect verifier the loop still overstated its own gain by 0.20 (p=0.08; does not replicate in retail at −0.02).
- **Only a stored copy restores behavior (B).** Null-change noise floors: ρ₀=0.95 (CI [0.89, 1.00]), β₀=0.08 (CI [0.02, 0.16]). Writing back a saved prompt gives ρ−ρ₀=0.000 (CI [−0.038, 0.038]; TOST equivalence within ±0.05, p=0.007); three regenerated undos reach ρ of 0.75/0.83/0.90 against a 0.98 floor — 0.16 below it jointly (CI [0.07, 0.27], one-sided p=0.0001, each significant after Holm) — and the gate refused all three, as the rule requires.
- **Blast radius is real (B).** Deploying the three admitted prompt changes altered the outcome of 17% of the 50 airline tasks beyond the noise floor (β−β₀=0.17, CI [0.08, 0.27], p=0.0002; individually 0.24/0.28/0.24 vs the 0.08 floor), with flips nearly balanced (18 up, 20 down) — the average pass rate barely moves while ~1 task in 6 is durably changed, and no undo repairs delivered outcomes.
- **σmin does not transfer.** The strength at which regret starts to rise moved from 0.41 (60 runs per candidate) to 0.56 (30 runs) and 0.49 (15 runs) — ±0.15 with the gate's averaging depth — so the paper supplies a calibration procedure (App. E) instead of a universal threshold.

## Authors & Credibility

De Wang and Peng Qi, both at Uniphore (a enterprise conversational-AI company), published at the NeurIPS 2026 AgenticOS workshop. The work is grounded in a real production platform (their diversity gate, their trace-driven repair loop), which gives the case study unusual ecological validity: the silent-collapse failure was found in a gate "treated as working because it always returned a score." The statistics are careful by workshop standards — task-level resampling (not run-level, correcting for clustered errors), TOST equivalence testing, Holm correction, Fisher exact tests, and an honest power analysis (220 tasks needed vs 20 available). Script and data "available from the authors on request," though not in a public artifact.

## Critical Assessment

- **Novelty:** The two definitions and the refuse-if-unmeasured rule are genuinely useful framing — connecting LLM-judge reliability (Zheng et al. 2023) with deployment-engineering admission control and Sagas-style compensating transactions. It is a positions-plus-measurements paper rather than a new method; the closest prior art (off-policy evaluation's lower-confidence-bound promotion, Thomas et al. 2015) is acknowledged, with σ playing the role of the confidence bound where no unbiased value estimate exists.
- **Rigor:** Asymmetric. The recoverability experiments (B) are well controlled and statistically conclusive (stored copy exactly equivalent, regenerated undo 0.16 short, blast radius 0.17 with tight CIs). But the central quantitative claim — that weaker verifiers (lower σ) pick worse changes — is **not confirmed**: slope CI [−0.234, 0.120], p=0.23, and the authors candidly diagnose their own candidate pool as "field-limited" (best-vs-average gap 0.069 vs noise ±0.24; ratio 0.62, below their pre-registered threshold of 1 — and they admit their first, rougher estimate wrongly put airline at 1.39 and was corrected *after* the runs). The retail domain shows no trend at all, so the σ→regret link is a one-domain suggestive result, not evidence.
- **Reproducibility:** Medium. τ²-bench is public and the corruption trick (flipping reference verdicts with probability ε) is easy to replicate; but the production case study depends on Uniphore-internal gates and gateway quirks (their own gateway silently dropped a fixed output format; the judge API rejects temperature settings), with data only "on request." The σmin numbers are explicitly non-transferable across platforms and gate configurations.
- **Significance:** The practical takeaways are strong: measure σ with MCC not accuracy; run the two cheap gate tests (delete-the-signal, check-the-guarantees) whenever model/prompt/format changes; treat refusal as a recorded outcome; keep old versions (g=0) before anything unattended. The 17% blast-radius result is a sobering number for anyone running agent self-modification in production.
- **Red flags:** (1) The headline rule's "verdicts for tool, skill and weight changes follow from the definitions and are not separately tested" — the platform's actual placement of weight updates under human sign-off rests on the g-typing table plus the (real) judge-collapse case study, not on end-to-end weight-update experiments. (2) Only prompt edits were tested end-to-end, on airline + retail, never in production. (3) The regenerated-undo test has three caveats the authors list themselves: training (not test) tasks, gate-refused undos measured counterfactually, and three undos that are near-rewrites of one another — one kind of undo, not many. (4) The "17% of tasks" blast radius is a lower bound over 50 probe tasks; real side effects (issued refunds) must be tracked at the tool boundary, which the platform does not yet do.

## Strengths

- Turns a fuzzy governance question ("how much autonomy is safe?") into two measurable quantities with a crisp, non-negotiable rule — and builds the rule into a platform (typed changes, declared verifier σ, recorded refusals) rather than leaving it on paper.
- The silent-gate-collapse case study is a valuable, honest negative result from production: a gate that always returned a score was constant (0.250 in all 40 deployed-setting runs) and hence meaningless, with two cheap, reusable tests to catch it (40 calls each).
- Statistically self-aware: cluster-aware task-level resampling, equivalence testing for "rollback restores behavior," Holm correction, an a-priori field-limited criterion for the candidate pool, and a power analysis explaining exactly why 20 test tasks could not confirm the σ effect.
- The blast-radius finding (17% of tasks durably altered while a change was live, flips balanced so the average hides it) formalizes a risk that pass-rate-based evaluation structurally cannot see.

## Limitations

- The core verifier-strength hypothesis (b) is unconfirmed at achievable scale: the σ→regret trend is in the predicted direction but non-significant (p=0.23), retail shows no trend, and both candidate pools are field-limited.
- Only prompt edits were tested end-to-end; the tool/skill/weight verdicts in the platform matrix are definitional, not empirical, and the rule "was applied after the fact" to one company's platform.
- The σmin threshold shifts ±0.15 with the gate's averaging depth, so each platform must recalibrate; no universal number is offered.
- The regenerated-undo experiment measures counterfactual undos the gate refused, on training tasks, with three near-identical undo candidates — breadth of undo strategies is untested.
- Production-side evidence (the collapse case study) is single-company, partially provider-dependent (judge models, gateway behavior measured on one day in Aug 2026), and data is available only on request.

## Relevance

高度契合"Self-Evolving Agents & Automated Research"方向：这篇论文正面回答了自改进/自演化智能体系统"多少环节可以无人值守"的可靠性与可信性问题，给出了可操作的安全闸门设计（σ 实测 + 可恢复性分型 + 记录式拒绝）。同时其"静默闸门坍缩"（LLM judge 恒定打分、网关悄悄丢弃输出格式等）也是"Agent & Pipeline Silent Failures"关注的基础设施层静默改写行为的直接实例。

## Questions for Further Exploration

- Would the σ→regret slope become significant with the ~220 held-out tasks the power analysis demands, and can a non-field-limited candidate pool be constructed from real production changes rather than section-deletion mutants?
- Can σmin be estimated online (multi-armed bandit over gate depth) instead of recalibrated per configuration, given the ±0.15 drift with runs-per-candidate?
- Does the collapse phenomenon depend on judge size, prompt phrasing, or their interaction — and do current frontier judges (2026) still collapse under THRESHOLD-style checkable-bound prompts at larger breadths?
- How should β be measured at the tool boundary (actually-issued refunds, sent emails) rather than as a lower bound over probe tasks, and can compensation actions (Sagas) shrink effective blast radius?
- Does the rule extend to multi-step improvement chains, where each admitted change shifts the distribution the next verifier is calibrated on?
- Could regenerate-and-verify undos (g=1) be made safe by requiring the undo's own σ and a held-out equivalence check, rather than refusing g=1 categorically?
