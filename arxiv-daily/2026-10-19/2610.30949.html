Key Metric
1.93×

Training efficiency vs a Qwen3-30B-A3B-style MoE baseline on identical data — same loss reached with ~52% of the compute.

Controlled scaling study. The fitted Critical Model Size framework extrapolates a stability ceiling of ~572B activated parameters.

Why This Matters

A fully disclosed recipe — architecture, optimizers, RL defenses — for a competitive open agentic CLI model, plus a stability lens for scaling past 500B.

前沿智能体基座模型技术报告：CMS 训练稳定性框架、多 harness RL 与 reward-hacking 防护、人在回路的 RSI 案例，分别对应训练稳定性、RL 后训练动力学与自进化智能体方向。

Critical Edge

The headline 1.93× gain is reported only as an aggregate — no component ablations exist, so a practitioner cannot tell which ingredients are worth copying.

MOPD and model merging are likewise never ablated against plain multi-teacher SFT or simple weight averaging. One Qwen3-style baseline only.

Methodology — Distilled

Five phases, one pipeline

01

Pre-training

29T tokens, two-stage curriculum; code share 40% → 70%. Stable SplitNorm + Muon + μP; learning rate searched on a tiny 896-hidden proxy and transferred zero-shot.

02

Mid-training

Natural corpora + QA + agent trajectories under token-level loss masks; context extended 32K → 128K → 512K; 1M+ containerized agent instances grown from GitHub repos.

03

SFT

Two stages over synthesized general / reasoning / coding tasks — 240B+ then 50B+ tokens — initializing from mid-training.

04

RL + MOPD

Multi-harness, multi-version GRPO (Claude Code, Codex, OpenCode) with failure attribution before updates; four frozen teachers distilled on-policy in MOPD.

05

Residual model merging

Parameter deltas vs reference checkpoints stitched with prescribed weights and global ℓ2 calibration, combining SFT, domain-RL, and MOPD checkpoints.

Reward-hacking defense (3 layers): environment sanitization → execution-time interception → trajectory auditing with no-op / reference-solution checks — among the most concrete published treatments of agentic RL's messiest failure mode.

Strengths

What holds up

  • Reference-grade disclosure — architecture, optimizer scalings, schedules detailed enough to serve as a recipe for a modern MoE agent base model.
  • Controlled scaling comparison — 1.93× vs a named, reproducible baseline on identical data; more meaningful than cherry-picked loss curves.
  • Practical RL hygiene — three-layer reward-hacking defense plus failure-attribution rules that mask environment/harness faults.
  • Self-honest reporting — openly prints the 10+ pt HLE deficit and TB 3.0/4.0 columns that undercut its own narrative.
  • Costed RSI — the self-improvement case reports concrete numbers (2.35B tokens, 938.7 GPU-h), not vibes.
Limitations

Where it breaks

  • Text-only — no native image, audio, or video input.
  • Proprietary template — IQuest-specific tool-call format forces serving-parser and harness-adapter work for third parties.
  • Still needs supervision — real CLI tasks still trigger repeated failed attempts and overlooked constraints; authors mandate human code review.
  • Zero component ablations — the contribution of every proposed technique remains unquantified (see Critical Edge above).
  • Behind on the hardest suites — TB 3.0/4.0 (17.9 / 22.7) and HLE (39.2) trail both frontier proprietary models and GLM-5.3-Flash.
Open Questions

Where to probe next

  1. How much of the 1.93× gain survives when SplitNorm, Muon, μP, hybrid SWA, and MTP are ablated independently — and does the baseline close the gap if given MTP layers too?
  2. Does the extrapolated Critical Model Size (~572B activated) hold empirically, or does the safe/optimal LR headroom shrink superlinearly at scale?
  3. Does multi-harness GRPO generalize to harnesses and schema formats unseen during training — and how is that measured?
  4. Is four-teacher MOPD better than one strong teacher or a simple checkpoint soup at equal compute?
  5. Can the proprietary IQuest-CLIBench be externalized or proxied so the community can verify the "CLI user experience" claims?
Authors & Credibility

Who is behind this

  • ~180 authors under the IQuest Research banner; names overlap the GLM / Kimi / DeepSeek technical-report ecosystems — an experienced industrial training team.
  • Methods explicitly build on Kimi K3's configurable-harness training and DeepSeek-V4's domain-specialized GRPO.
  • Credibility positives: unusually detailed hyperparameters; open weights + deployment configs; self-tested baselines marked (*) explicitly.
  • Weight the claims accordingly: arXiv preprint, no peer review; CMS ceiling is a trend extrapolation, not a measurement; many agentic baselines are self-reported under configurations that materially move scores.
