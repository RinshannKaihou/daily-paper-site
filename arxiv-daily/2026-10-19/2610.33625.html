Key finding

The positional key carries 92.5% of MLA's attention-logit signal — role-aware training-free transforms compress the full cache to 2.5 bits.

一句话总结 — MLA 缓存中两个张量角色不同：解耦位置键主导注意力打分（占 92.5% 的 logit 归因），压缩潜在向量主要承担 value 角色。据此对含位置键在内的完整缓存做角色感知的免训练量化，压至约 2.5 bit/元素，推理与代码任务与 BF16 差距保持在 0.5 分以内。

2.5

Full MLA cache including the positional key — 2.47–2.50 BPE across GLM-4.7-Flash, GLM-5.2-FP8, Moonlight-16B-A3B, DeepSeek-Coder-V2-Lite.

Why this matters

The KV cache is the memory wall of LLM serving — this work maps how far 2.5-bit compression can go, and exactly where it breaks.

直接命中「极致性能优化下的可靠性」：超低位量化误差如何在 MLA 注意力中传播、放大并扰动输出，是精度—正确性权衡的具体案例。

Critical edge — read before citing

AIME25 has only ~30 problems sampled at temperature 1.0, and only "some" results are seed-averaged — the headline deltas (−0.08, +0.05) sit inside run-to-run noise, so "within 0.5 points" is the defensible claim, not "lossless".

From Critical Assessment · rigor

Methodology — distilled
01

Role analysis of the two cached tensors

Per layer, MLA caches a compressed latent cKV (d=512, Value-like smooth magnitudes) and a decoupled RoPE key kR (d=64, Key-like channel outliers, 11.1% of elements). INT4 error tracing shows latent error mostly rides the value path (12.3%→8.3%) while kR error amplifies (9.1%→14.7%) — the tensor prior quantizers left in BF16 is the sensitive one.

02

Role-aware objective

Cache Q(XA)A⁻¹ with a learned invertible A minimizing a token-weighted quadratic whose role metric encodes how attention consumes each tensor: attention-exposure × value up-projection for the latent; positional-query second moment for kR.

03

Alternating fit, training-free

Alternate a proximal strongly-convex solve for B=A⁻¹ with requantization in the new basis; Theorem 4.1 guarantees monotone convergence. No gradients through the model, no fine-tuning. Calibration: 128×64K-token RedPajama sequences.

04

Folded into serving — zero reconstruction

A applied on the write path; A⁻¹ absorbed into the up-projections and positional query at read time. Only three context-length-independent matmuls are added; transform params = 0.08% of GLM-4.7-Flash (23.5 MiB).

  • Where baselines collapse, RAQ-MLA holds. QuaRot INT2 on Moonlight: MATH-500 falls 63.20 → 32.20; RAQ-MLA at 2.47 BPE keeps 61.80 (avg +0.05).
  • Long context is the trade-off. RULER-NIAH: 93.66 avg at 2.66 BPE (mixed precision at boundary layers) vs OSCAR's 93.60 at 3.78 — matched accuracy, 29.6% smaller cache; both trail BF16's 96.95, and −8.1 pts at 128K (79.13 vs 87.22).
  • Ablation isolates each part. The score-aware kR transform alone lifts AIME25 from 87.78 (direct INT4) to 92.22 at the same 2.47 BPE; proxy metrics track exact output error at r = 0.992 (value-aware) / 0.852 (score-aware).
  • Efficiency. 8.2 vs 52.9 GiB per 1M-token GLM-4.7-Flash sequence (6.5× theoretical, 3.6× vs FlashMLA FP8); decode 17.4→12.6 µs/layer (1.38×); TPOT 6.56→5.97 ms (1.10×) with transform overhead <2%.
Strengths
  • Evidence-driven design — the 92.5/7.5 logit-attribution split and stage-by-stage error tracing justify every choice of granularity, transform, and bit allocation.
  • Proxies validated before use — role metrics are checked against exact attention-output error (r = 0.992) rather than assumed. Rare and convincing.
  • Training-free, near-zero overhead — transforms fold into existing matrix products (<2% TPOT) with a convergence guarantee for the fit.
  • Full-cache quantization — first to compress the positional key: 11.1% of elements but the dominant error source.
  • Honest reporting — baseline wins (OSCAR +0.49 on GLM-5.2), the 128K gap, and an explicit AI-use statement.
Limitations
  • Noise-band deltas — AIME25 ≈ 30 items at temperature 1.0; only "some" results seed-averaged.
  • Long-context tax — −3.3 avg / −8.1 at 128K vs BF16, requiring a hand-tuned mixed-precision recipe at boundary layers that resembles tuning-to-the-benchmark.
  • 6.5× is theoretical — measured TPOT is only 1.10× at batch 1; throughput-vs-batch, the actual serving win, is unmeasured.
  • Rougher kR proxy — score-aware metric correlates at r = 0.852 vs 0.992 for value-aware.
  • Diagonal-only Gram — discards off-diagonal terms still carrying 14.2% of value-path distortion.
  • No public code; four models from three families, none at DeepSeek-V3 scale.
Open questions
  • Q1Does the 92.5% positional-term attribution hold for other MLA variants — DeepSeek-V3.2 sparse hybrids, partial RoPE, different dR?
  • Q2Does the 6.5× capacity gain convert into real throughput at serving batch sizes, with paged KV memory and prefix reuse?
  • Q3Why do the first and last two layers need wider quantizers for retrieval — a RoPE-frequency effect on kR outliers, predictable rather than tuned?
  • Q4Would a joint non-diagonal treatment of the attention Gram recover the ~14% off-diagonal value-path distortion?
  • Q5How does RAQ-MLA compose with weight quantization (FP8) and sparse attention, where score errors meet token selection?
  • Q6Are there failure signatures where 2.5-bit caches silently corrupt long-horizon agent outputs while benchmark averages look clean?
