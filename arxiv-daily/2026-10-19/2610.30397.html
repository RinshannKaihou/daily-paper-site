Why this matters

Rowhammer bit flips are a classic hardware source of silent data corruption — and address mapping is the prerequisite for targeting them on edge inference hardware.

Rowhammer 比特翻转是静默数据损坏的典型硬件来源；地址映射是定位可翻转地址的前提工具。

Critical edge

No Rowhammer bit flip is ever demonstrated — the promised attack payoff is entirely deferred. And verification is self-referential: recovery and checking share one latency side channel, with no external ground truth.

01Methodology — distilled

latency side channel → GF(2) linear algebra → two-stage software verification

The signal: two addresses hitting the same bank, different rows force a PRECHARGE + ACTIVATE — measurably slower than bank-parallel hits. Everything downstream is algebra on that timing gap.

  1. Measure. Collect 10,000,000 address-pair latency samples per platform, expressed in CPU clock cycles.
  2. Sweep. Every histogram-derived threshold τ splits the pairs: measured latency > τ ⇒ same-bank candidates.
  3. Solve. Bank masks are linear functions over GF(2): m(a)=m(b) ⇔ m·(a⊕b)=0. The nullspace of the pair-difference matrix (RREF, 100 subsampled pairs × 200 runs) yields the masks — polynomial-time linear algebra instead of exhaustive enumeration. No bank count is needed as input, which matters: LPDDR5 ships in BG / 8B / 16B bank modes a part number cannot disambiguate.
  4. Verify. Group verification (Heckel et al., ESORICS 2025): pool 20,000 addresses, 10 rounds — an iteration passes when a same-bank pair is slow and a different-bank pair is fast. Then single-function verification: remove each mask in turn; the pass rate should halve.

ppass(τ) = psame(τ) · pdiff(τ) — a threshold-sensitivity model that predicts the usable window before trusting any sweep point.

02Results — beyond the headline

Jetson Orin Nano (LPDDR5) · Raspberry Pi 4B (LPDDR4)

  • Five distinct mask sets recovered on Jetson; the champion 7-mask set hits 0.996907 @ τ=550, while lower-dimensional sets are “substantially lower” — several existing at only a single threshold point.
  • The 10M-sample model predicts a high-pass window of ≈ 500–570 cycles; the empirical best (550) lands inside it.
  • Scale: 10M samples · 200 solver runs × 100 pairs · 20k verify addresses · 10 rounds · 2 platforms.

Strengths

  • No privileged access, no DRAM docs, no bank-count input — user-space only, on cheap commodity boards; exactly the DRAM-agnostic property LPDDR5 requires.
  • Record-per-threshold workflow turns a hidden hyperparameter (the latency threshold) into an explicit, evidence-ranked search — a real improvement over single-point inference.
  • Raspberry Pi result is near-textbook discrimination: hypotheses differing by one mask (0x4000) split into ≈1.0 vs negligible pass rates.
  • Honest, well-scoped writing — prior-work limitations accurately stated; no overclaimed attacks.

Limitations

  • Bank functions only — no row, column, channel, or bank-group recovery; not yet sufficient for targeted double-sided Rowhammer.
  • No end-to-end Rowhammer validation — recovered masks never trigger a single bit flip; practical value unquantified.
  • Self-consistency evidence only — no external ground truth on either platform (a published RPi 4B mapping existed for comparison).
  • Hand-set threshold range (500–580 cycles) in platform-specific units, no porting guidance; single-function verification skipped on RPi; no runtime cost reported; no artifact release.

04Open questions

where this work points next

  1. Do the recovered 7 Jetson masks actually enable double-sided Rowhammer flips on LPDDR5 — and at what rates against its Target Row Refresh?
  2. Can the GF(2) framework extend to row, column, bank-group, and channel functions for a complete, attack-usable mapping?
  3. Do cycle-based thresholds survive DVFS, thermal drift, and OS interference — would percentile-based thresholds port across platforms?
  4. Can published Raspberry Pi 4B mappings serve as ground truth to measure the verifier’s false-positive rate?
  5. What does the 10M-sample phase cost in wall-clock time — could active sampling reach the same confidence 10× cheaper?
  6. Does LPDDR5’s 16B bank mode or refresh scheduling ever smear the same-bank distribution enough to break the Fig. 2 separation?
