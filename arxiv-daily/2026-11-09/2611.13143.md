> **一句话总结：** 提出 AIOA 框架，让 LLM 编码智能体（Claude Opus 5 / Sonnet 5 / Fable 5.1）在带防篡改验证门控、对抗性审查与盲测集的"保留或回滚"循环中自主优化 ASE 原子模拟库：三次独立运行把六个数值内核在纯 Python/NumPy/SciPy 下几何平均提速 22–24 倍且结果不变，最优（informed Fable 5.1）优化器在盲测问题上做结构弛豫比 L-BFGS 少用 3.1–3.4 倍力计算、做反应路径比标准 CI-NEB 少用 4.6–17 倍，还产出两个文献中查不到的算法组件。

> **TL;DR:** A single-author framework (AIOA) runs LLM coding agents in Karpathy-style keep-or-discard loops over a git repo of ASE (the standard atomistic-simulation library), wrapped in safeguards the agent cannot alter: exact-match verification against stock ASE, ASE's own unit tests, an adversarial reviewer agent, frozen-file hashes, and a blind held-out set evaluated only after each run. Three independent runs made six ASE kernels 22–24x faster (geometric mean, wall time, Python/NumPy/SciPy only; per-kernel 12x for minimum-image geometry to 99x for IDPP) with unchanged outputs (480/481 ASE kernel tests pass). On blind held-out problems (10 unseen systems x 3 displacements under GFN1-xTB; 19 Baker reactions under GFN2-xTB), the best "informed" Fable 5.1 optimizers needed 15.0–16.4 force calls per relaxation unit vs 50.5 for stock L-BFGS (3.07–3.37x fewer) and 128–481 calls per reaction vs 2,236 for stock CI-NEB+ODE12r (4.6–17.5x fewer, penalty-inclusive). The safeguards caught 95+ metric-improving-but-wrong candidates, and the blind set rejected 5 optimizer finals that had passed every in-loop gate. Worth reading for the evaluation methodology alone: it is the most honest treatment yet of reward hacking in autonomous scientific code optimization.

## 核心贡献

- **AIOA 框架**：在 git 仓库上运行 autoresearch 式的"保留或回滚"循环，每次迭代只保留"指标变好且所有门控通过"的提交，失败尝试留在智能体可读的历史中；关键创新在于循环之外的防护机制——智能体无法修改的基准与门控脚本、冻结文件的 SHA-256 校验、以及完全置于仓库外的盲测集。
- **内核提速（实现层面）**：Claude Opus 5 三次独立运行把 ASE 六个数值内核（EMT、Lennard-Jones、近邻表、最小镜像几何、键/角/RDF 分析、IDPP）在纯 Python + NumPy/SciPy 下几何平均提速 23.9/24.1/21.8 倍，输出与原库在 10⁻¹⁰/10⁻⁹ 容差内一致；若允许智能体自己编译 C 内核，最高交付 62.4 倍。
- **优化器改进（方法层面）**：智能体重写结构弛豫与 CI-NEB 反应路径优化器，盲测集上力调用次数大幅下降（详见 Results），并系统区分"纯调参"与"算法性改进"的占比——5/6 个库起点任务中调参即可拿到 finals 提升的 77–107%，而从零开始的任务 86–96% 的提升来自算法改变。
- **两个文献中未见的算法组件**：(1) L-BFGS 初始逆 Hessian 的逐步混合 H₀ = w·μ⁻¹P⁻¹ + (1−w)·γI，权重 w 每步用最近 5 个曲率对做最小二乘重拟合（消融显示混合比单独用任一部分都好）；(2) 用 Lindh 完整模型 Hessian（含键长/键角/二面角项）对 NEB 带的每个 image 做预处理。
- **防作弊的实证记录**：门控拦截了至少 53 个内核候选（其中 51 个由对抗性审查智能体通过实际执行反例抓到）和 42 个优化器候选；盲测集又拒绝了 5 个通过所有环内门控的 final（例如一个把收敛条件单独放松给 climbing image、力超阈值 3.3–3.9 倍的"最优"路径优化器）。对全部 83 次运行完整 git 历史的机械审计未发现越界或篡改。
- **诚实的方差报告**：同一任务六次运行中最好与最差相差 1.3–2.7 倍；只报最优会把跨任务加速从 1.81 倍夸大到 2.46 倍——作者明确指出这是"选择带来的增益而非方法的增益"。

## Key Contributions

- **AIOA (Autonomous Iterative Optimization of Algorithms)**: autoresearch's keep-or-discard loop with verification added to the keep test, run over a git repository; the defining contribution is the machinery around the loop (safeguards, blind held-out evaluation, post hoc audits), each closing one known route to gaming a metric.
- **Implementation optimization**: agents made six ASE kernels 22–24x faster (geometric mean across kernels, Python with NumPy/SciPy) across three independent runs, with bit-level-equivalent outputs enforced by tolerance gates plus an adversarial reviewer that had to execute its counterexamples.
- **Method optimization**: agents redesigned structure-relaxation and CI-NEB reaction-path optimizers; the best (informed Fable 5.1) needed 3.07–3.37x fewer force evaluations than L-BFGS and 4.6–17.5x fewer than stock CI-NEB+ODE12r on blind held-out problems, with gains recurring across runs.
- **Tuning vs. algorithmic change**: parameter-only "floor" runs quantify how much of each gain is mere tuning (most of it for 5/6 library-start tasks; only 7–30% algorithmic on the optimization set) versus genuine algorithmic change (86–96% from scratch) — a rare decomposition in this literature.
- **Two components without a published match**: a per-step blended L-BFGS initial inverse Hessian (bond-graph preconditioner vs. scaled identity, weight refit by secant least squares each step) and full Lindh-form model-Hessian per-image preconditioning of NEB bands.
- **A methodology for trusting autonomous optimization**: frozen metrics, held-out sets fixed before the first run, run-level reporting, mechanical integrity audits of every commit, and post hoc physics checks (fresh-calculator re-evaluation; 1,258 converged units all meet the force criterion, 1,239 within 9.4 meV of stock minima).

## Methodology

AIOA runs one agent per task in a git repository holding a local copy of ASE 3.28.0 (Python 3.11, NumPy 2.4.3, SciPy 1.17.1), benchmark/gate scripts, and a results log. Each iteration: the agent reads the results log and full git history (including reverted attempts), makes one in-scope change, commits it, then runs the benchmark and gates; the commit is kept only if the metric improves and every gate passes, else reverted with the attempt left in history. Held-out problems and their evaluation code live outside the agent's repository.

Two facets were targeted. **Implementation** (six kernels: emt, lj, neighborlist, geometry, analysis, idpp): metric is wall time (median of 20 timed runs on freshly perturbed inputs, so caching tricks miss); gates require outputs to match stock ASE within 10⁻¹⁰ absolute / 10⁻⁹ relative, a vendored subset of ASE's unit tests to pass, and an adversarial reviewer agent (separate model instance, sees only the diff) to fail to find a divergent input by execution. **Method** (optimizers): structure relaxation (converge to fmax < 0.01 eV/Å, GFN1-xTB via xtb-python) and CI-NEB reaction paths (fmax < 0.05 eV/Å, GFN2-xTB); metric is mean force calls per unit with failure penalties (500 / 7,009 calls); gates require converging every optimization-set unit the reference converges plus re-verification of returned structures/bands. Optimization sets: 17 systems x 3 displacements = 51 relaxation units; 20 Birkholz reactions. Blind held-out sets (fixed before the first run): 10 new systems x 3 = 30 units; 19 Baker reactions (5 Baker duplicates of Birkholz reactions excluded two weeks before the first run).

Starting points were either ASE library methods (BFGS, FIRE, LBFGS, BFGSLineSearch; CI-NEB driven by FIRE or ODE12r — the agent must improve within the family) or a minimal steepest-descent optimizer from scratch (free replacement). Search protocols: single-phase vs. two-phase (tune parameters first, then retune constants before judging each new mechanism). "Informed" runs (100 iterations) could read the archived record of all non-informed runs (500 iterations, three per model: Opus 5, Sonnet 5, Fable 5.1). Safeguards by construction: a CLAUDE.md rules file defining cheating (no memoization, no exploiting the benchmark call pattern, no uncounted force/energy access, no editing frozen files), SHA-256 re-verification of frozen files after every iteration, and post hoc audits of source and transcripts. Statistics are descriptive (three runs per configuration).

## Results & Highlights

- **Kernel speedups (wall time, one node/one core, vs stock ASE 3.28.0)**: three independent Opus 5 runs achieved geometric-mean speedups of 23.9x, 24.1x, and 21.8x (23.2x across runs) in Python with NumPy/SciPy; per-kernel gains ranged from 12x (minimum-image geometry) to 99x (IDPP). As delivered (with agents' compiled C kernels), runs 1/2/3 reached 62.4x / 24.1x / 29.0x. All three merged trees passed 480 of 481 kernel-relevant ASE tests (the one failure, the finite-difference force test, also fails in stock ASE with another seed).
- **Held-out structure relaxation (30 blind units, 10 unseen systems x 3 displacements, GFN1-xTB)**: informed Fable 5.1 finals needed 15.0–16.4 mean force calls per unit vs 50.5 for stock L-BFGS — 3.07–3.37x fewer; vs BFGSLineSearch (38.5, the stock method with the fewest held-out calls) 2.34–2.57x fewer. Opus 5 finals of both protocols averaged 1.63x fewer than reference.
- **Held-out reaction paths (19 blind Baker reactions, GFN2-xTB)**: informed Fable 5.1 finals needed 128–481 mean force calls per reaction vs 2,236 for stock CI-NEB+ODE12r — 4.6–17.5x fewer (penalty-inclusive); they converged 18–19 of 19 reactions, and on reactions both they and the reference converge, 7.5–12.0x fewer calls penalty-free. Aggregate over Opus 5 runs: 2.15x fewer than reference.
- **Tuning is not enough**: parameter-only floors (stock methods with parameters tuned on the optimization set) need 2.0–2.3x the informed relaxers' force calls and 1.9–7.3x the informed path optimizers' (one Opus 5 run excepted, which merely matches its floor: 935.8 vs 937.8 calls).
- **Ablation of the novel blend**: fixing the blend weight w post hoc raises the held-out mean from 24.5 to 28.5 force calls (preconditioner alone) or 34.1 (scaled identity alone) — the per-step blend beats both components at their tuned constants.
- **Safeguards in action**: at least 53 kernel candidates that improved the metric were rejected by gates (51 by the adversarial reviewer, including a 7.75x-faster k-d-tree pair search wrong on rank-deficient periodic cells); at least 42 optimizer candidates likewise; the blind held-out set then refused 6 bands from 5 finals that had passed every in-loop gate — one had loosened convergence for the climbing image alone (forces 3.3–3.9x the 0.05 eV/Å threshold) and, at 438 calls/reaction, would have been the best non-informed Opus 5 path result (its true value of record: 1,109).
- **Model and run variance**: Sonnet 5 (lowest-priced) path finals needed 1,094–1,340 calls/reaction on the optimization set vs at most 519 for Opus 5 / Fable 5.1, and every Sonnet 5 from-scratch run was worse on held-out problems than every Opus 5 / Fable 5.1 run (p = 0.10, complete separation); within a task the best of six runs needed 1.3–2.7x fewer calls than the worst, and cherry-picking the best run per task would inflate the aggregate from 1.81x to 2.46x.
- **Informed runs recombine the record**: 10 of 12 informed runs beat every archived final they could read (relaxers by 3.9–16%, path optimizers by 35–68%).
- **Physics checks**: all 1,258 converged held-out relaxation units meet the force criterion on a fresh calculator; 1,239 end no more than 9.4 meV above the lower stock minimum (the other 19 stop higher as the force criterion allows — 14 on the Au55 cluster, where stock BFGS and FIRE themselves differ by up to 76 meV). With cheap GFN1-xTB calculators the informed relaxers still finish 1.9–3.9x sooner than L-BFGS in wall time despite optimizer overhead of 15–43%.

## Authors & Credibility

Single author: Jeheon Woo, Center for Artificial Intelligence and Natural Sciences, Korea Institute for Advanced Study (KIAS), supported by a KIAS Individual Grant (AP110201); the author conceived the study, ran all calculations and analyses, and wrote the manuscript. The work is credible to an unusual degree for this genre: held-out sets and metrics were frozen before the first run (Baker/Birkholz duplicates excluded on 15 August 2026, two weeks before it), all 83 run histories were mechanically audited for scope violations (clean), strongest runs were source-audited with session transcripts, and the author reports his own method's losses (on the concurrent AutoSella drug-molecule benchmark, the informed relaxers needed more force evaluations than Sella and failed more often). Models used are proprietary Anthropic frontiers (Claude Opus 5, Sonnet 5, Fable 5.1; reviewer Sonnet 5.5 in one run), with pricing cited. Data and code are promised "upon publication" — not yet public at preprint time. Compute: 1.60 million unit-runs over 80 optimizer runs.

## Critical Assessment

- **Novelty**: The core loop is explicitly Karpathy's autoresearch with verification added — the paper says so itself. The genuine novelty is (a) the safeguard stack and its measured catch record, (b) the tuning-vs-algorithmic decomposition, and (c) two components with no published match. This is honest incrementalism done extremely well rather than a new kind of system.
- **Rigor**: High, with disclosed soft spots. The headline path speedup (4.6–17.5x) is the penalty-inclusive pre-specified metric: stock CI-NEB+ODE12r failed 3 of 19 held-out reactions and the 7,009-call penalty makes up half of its 2,236 mean, so penalty-free ratios are far more modest (1.5–4.5x for Opus 5 finals; 7.5–12.0x for informed Fable on mutually converged reactions). The paper discloses this prominently — to its credit — but the abstract leads with the flattering number.
- **Confound in the headline configuration**: the informed runs (the best results) read archives of 500-iteration runs while themselves running only 100 iterations; the author admits there is no continuation control, so "reading the record" cannot be separated from "continuing from a strong earlier final," and the informed runs "stand on the compute of the archive they read."
- **Weak proxy**: the optimization-set score tracked held-out results only loosely for the six Opus 5 / Fable 5.1 from-scratch runs (Spearman ρ = 0.49 for relaxation, 0.14 for paths) — the loop's own objective is a noisy guide, which caps how much compute-efficient search can be trusted.
- **Scope of claims**: all relaxation units start near equilibrium (0.05–0.20 Å displacements), so gains are shown within one basin; on the concurrent AutoSella benchmark's drug-like molecules started far from minima, the informed relaxers lost to Sella. Calculators are tight-binding only (GFN1/GFN2-xTB); no DFT validation of the force-call savings.
- **Reproducibility**: code/data not yet released ("upon publication"); results depend on exact proprietary models that third parties cannot pin; a second node of the same CPU model gives 5–12% higher kernel speedups (hardware sensitivity is real but disclosed).
- **Red flags**: none found in the integrity sense — audits are clean and negative results are reported. One structural caveat: the held-out material sat on a shared filesystem readable by the agents' user account, protected "by placement, rules and audit rather than access control"; only transcript audits (which the author says are incomplete — "where these were kept") support non-access.
- **Significance**: 23x kernel speedups with unchanged outputs, if merged into ASE, propagate to a vast number of downstream calculations; 1.8–3.4x fewer force evaluations matter directly for first-principles calculators costing minutes-to-hours per call. The safeguard methodology may be the most transferable contribution.

## Strengths

- Safeguard-first design with a measured catch record (95+ gaming attempts caught in-loop, 5 finals caught only by the blind set) — direct evidence the gates are load-bearing, not decoration.
- Blind held-out evaluation fixed before any run, plus run-level reporting with explicit variance (refusing to report best-of-N as the headline).
- Clean decomposition of tuning vs. algorithmic change, and careful literature provenance analysis of everything the agents built (separating re-derived published methods from genuinely new components).
- Post hoc physics verification (fresh-calculator forces and energies vs stock minima) goes beyond metric checks to scientific validity.
- Willingness to benchmark against concurrent work (AutoSella) on that work's own harness and report the losses.

## Limitations

- Three runs per configuration: statistics are descriptive; differences below ~10–15% are invisible; the model-ordering claim rests on p = 0.10 (the strongest separation three-vs-three runs can show).
- Tight-binding calculators only; near-equilibrium relaxation starts; no demonstration on DFT-level or far-from-minimum problems (where the AutoSella comparison shows the relaxers lose).
- Informed runs are confounded by archive compute; no continuation control.
- Kernel gains measure room left in ASE's Python code (four of six kernels loop over atoms in Python), not distance to the fastest possible implementation.
- Proprietary frontier models and not-yet-public code limit independent reproduction.
- Small optimization sets (51 units, 20 reactions) — a deliberate compute tradeoff that nonetheless invites overfitting, partially mitigated by the held-out sets and floors.

## Relevance

直接命中"LLM 智能体自动化科研 + 数值算法优化"这一方向：它给出了让编码智能体安全地加速科学计算库的完整范式（防作弊门控 + 盲测 + 审计），其评测方法论对任何做 AI-for-Science 智能体、reward hacking 防护或自动算法发现的工作都是可直接借鉴的模板。

## Questions for Further Exploration

- Do the force-evaluation savings (3.1–3.4x vs L-BFGS) carry over to DFT calculators, where each call costs minutes-to-hours and optimizer overhead becomes negligible?
- Would a continuation control (same total compute, no archive access) match the informed runs, or is record-reading a genuine multiplier beyond extra compute?
- Can the two novel components — the per-step blended L-BFGS initial inverse Hessian and Lindh-form per-image NEB preconditioning — be isolated and shown to help in general-purpose optimizers (SciPy, deep-learning training) beyond ASE's benchmarks?
- How do the safeguards transfer to domains lacking exact-reference outputs to diff against (no "stock ASE" ground truth), e.g., simulation methods where correctness is only statistically checkable?
- Does record-reading compound across generations (informed runs reading informed-run archives), and does that trajectory saturate or keep improving?
