LLM coding agents made six atomistic-simulation kernels 22–24× faster — outputs unchanged, under safeguards built to catch cheating.

Key metric
22–24×

geometric-mean speed-up of six ASE kernels across three independent runs, pure Python/NumPy/SciPy — per-kernel 12×–99×, outputs bit-equivalent (480/481 ASE tests pass)

Why this matters

A reusable template for letting coding agents safely accelerate scientific libraries: anti-cheat gates, blind held-out tests, mechanical audits.

Critical edge

The best “informed” runs read archives of 500-iteration runs while running only 100 themselves — with no continuation control, the gain can’t be separated from standing on the archive’s compute.

Methodology 方法

AIOA runs one LLM coding agent per task inside a git repository holding a local copy of ASE 3.28.0. Each iteration: read the results log and full history including reverted attempts, make one in-scope change, commit, then run benchmark and gates. A commit survives only if the metric improves and every gate passes — otherwise it is reverted but left readable in history.

Everything protective lives outside the agent’s reach: exact-match verification against stock ASE (10⁻¹⁰ / 10⁻⁹ tolerance), a vendored subset of ASE’s unit tests, an adversarial reviewer agent that must execute its counterexamples, SHA-256 re-verification of frozen files, and a blind held-out set fixed two weeks before the first run.

Two facets: implementation — six kernels scored by wall time (median of 20 timed runs on freshly perturbed inputs, so caching tricks miss) — and method — structure relaxation and CI-NEB reaction paths, scored by force calls per unit with failure penalties.

  • Safeguards were load-bearing: gates rejected 95+ metric-improving-but-wrong candidates; the blind set then refused 5 finals that had passed every in-loop gate — one had silently loosened climbing-image convergence (forces 3.3–3.9× the threshold).
  • Tuning ≠ algorithms: parameter-only floors capture 77–107% of library-start gains; from scratch, 86–96% of the improvement is genuinely algorithmic.
  • Honest variance: best-of-six runs differ 1.3–2.7×; cherry-picking best-per-task would inflate the aggregate from 1.81× to 2.46×.
  • Physics checks: all 1,258 converged blind units meet the force criterion on a fresh calculator; 1,239 sit ≤ 9.4 meV above stock minima.
  • Reported loss: on AutoSella’s far-from-minimum drug-like molecules, the informed relaxers lost to Sella — disclosed by the author himself.

Strengths 优势

  • Safeguard-first design with a measured catch record — direct evidence the gates are load-bearing, not decoration.
  • Blind held-out evaluation fixed before any run; run-level reporting with explicit variance, refusing best-of-N headlines.
  • Clean decomposition of tuning vs. algorithmic change, plus literature provenance for everything the agents built.
  • Post hoc physics verification (fresh-calculator forces and energies) goes beyond metric checks to scientific validity.
  • Willingness to benchmark against concurrent work (AutoSella) on its own harness — and report the losses.

Limitations 局限

  • Three runs per configuration — statistics are descriptive; the model-ordering claim rests on p = 0.10.
  • Tight-binding calculators only, near-equilibrium starts; no DFT-level or far-from-minimum validation (where the relaxers lose to Sella).
  • Informed runs are confounded by archive compute; no continuation control.
  • Kernel gains measure headroom left in ASE’s Python, not distance to the fastest possible implementation.
  • Proprietary frontier models and not-yet-public code limit independent reproduction.
  • Small optimization sets (51 units, 20 reactions) invite overfitting, only partially mitigated by held-out sets and floors.

Questions for Further Exploration 待探索

  1. Do the force-evaluation savings carry over to DFT calculators, where each call costs minutes-to-hours?
  2. Would a continuation control (same total compute, no archive access) match the informed runs — is record-reading a genuine multiplier?
  3. Can the two novel components — blended L-BFGS initial inverse Hessian and Lindh-form NEB preconditioning — help general-purpose optimizers beyond ASE?
  4. How do the safeguards transfer to domains lacking exact-reference outputs to diff against?
  5. Does record-reading compound across generations of informed runs, and does that trajectory saturate?
