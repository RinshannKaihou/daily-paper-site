> **一句话总结：** 本文在 [0.5, 2.5] 区间上对五种定点求倒数控件（直接查找表、线性插值、Newton-Raphson、Goldschmidt、混合"插值种子+一步 NR"）做了穷举式评测——Q16.16 全部 131,073 个输入码、Q8.24 全部 33,554,433 个输入码逐一对照精确整数参考评分，并给出带保护位的插值种子加一步 Newton-Raphson 再加一次整数残差校正（corrected Hybrid）的方案：在两种格式下对**每一个**输入都得到正确舍入的结果（最大理想误差恰为 0.5 LSB、0 个舍入失配），紧凑（乘积复用）实现以每周期 1 个输入的吞吐、10 周期时延通过全部穷举 RTL 验证，Q8.24 仅占用 Xilinx 7 系 9 个 DSP slice（全乘积校正器要 12 个），而无 DSP 的精确基数-2 对照则需 28 周期。

> **TL;DR:** Instead of sampled sweeps, this paper scores five fixed-point reciprocal datapaths (direct table, linear interpolation, Newton-Raphson, Goldschmidt, interpolated-seed Hybrid) on *every* representable input in [0.5, 2.5] — the full 131,073-code Q16.16 grid and 33,554,433-code Q8.24 grid — against an exact integer reference, then sweeps 306 guarded/refined/corrected configurations plus published baselines (Gutiérrez-Ramos quadratic seed + NR, Lunglmayr degree-4/10 polynomial corrections, exact radix-2 non-restoring divider). The headline result: one guarded interpolated seed + one Newton-Raphson step + a single integer residual check is correctly rounded on **all** inputs in both formats (0 mismatches, ideal max exactly 0.5 LSB), whereas the best polynomial baseline on the same exhaustive Q8.24 grid — Lunglmayr degree-10 with 11 products — reaches only 0.7106 LSB with 827,959 mismatches, and the quadratic seed + 1 NR reaches 4.4184 LSB with 9,341,442 mismatches. A compact product-reuse RTL sustains 1 input/cycle at 10-cycle latency and maps to 9 DSP slices in Q8.24 (12 for the full-product corrector), while the exact radix-2 control uses 0 DSPs but needs 28 cycles. Also notable: adding 8 fractional bits (Q16.16→Q8.24) cuts max relative error 205–223× for the refined paths but only ~1× (unchanged, ratio 0.969) for the direct table, whose error is address-width-limited.

## 核心贡献

- **穷举式评测方法论**：不再依赖采样扫描，而是对 [0.5, 2.5]（含端点）上**每一个**可表示的输入码打分——Q16.16 共 131,073 个、Q8.24 共 33,554,433 个——全部用精确整数算术对照"正确舍入参考" S²/k 评分；文中还量化了采样法的风险：此前 1,000,001 点的均匀扫描只覆盖 Q8.24 全部输入码的 2.98%，且把直接查找表的最大误差低估为 32,716.07 LSB（穷举真值为 32,732.04 LSB）。
- **正确舍入的极简充分方案**：带保护位的弦插值种子（Q16.16 用 6 位地址 / Q8.24 用 8 位地址，4 个保护位）加一步 Newton-Raphson，再加**一次整数残差检查**（比较 2R 与 ±k，至多 ±1 码的修正），即可在两种格式的全部输入上实现正确舍入——校正前最大理想误差仅 0.5973 / 0.6462 LSB（理论充分界约 0.705 / 0.715 LSB），校正后 0 个舍入失配、最大理想误差恰为半个 LSB。
- **紧凑（乘积复用）数据通路**：残差校正中复用精化阶段已算出的乘积 kZ，把新增乘法的一个操作数换成更窄的 D = 2^g·q0 − Z（式 15），在保护位同为 4 时把 DSP slice 从全乘积校正器的 6/12 个（Q16.16/Q8.24）降到 5/9 个；两种格式均以 10 周期时延、每周期 1 个输入通过穷举 RTL 验证。
- **跨格式误差预算**：量化回答"精度花在哪"——多 8 个小数位使三种精化路径的最大相对误差下降 205–223 倍（NR 220、GS 205、Hybrid 223），重建插值器降 68.2 倍，而直接查找表只变化 0.969 倍（地址宽度不变时误差被表间距锁死在 ~0.1%）。
- **按预算的确定性选型框架**：对每格式 166 种配置（地址宽 4–14 × 保护位 0–8 × 是否精化/校正）建立"系数比特数 × 乘法次数 × 最大理想误差"的非支配集，并检验选型对误差分辨率（0.25/0.5/1 LSB 分档）的敏感性；例如 4-LSB 预算下三乘法 guarded Hybrid 只需 1,056（Q16.16）/ 6,016（Q8.24）系数比特，而单乘法插值器要 14,848 / 335,872 比特。

## Key Contributions

- **Exhaustive verification methodology**: every representable input code in [0.5, 2.5] (both endpoints included) is scored against an exact integer reference — 131,073 codes in Q16.16, 33,554,433 in Q8.24 — eliminating sampling risk. The paper quantifies that risk: the earlier 1,000,001-point uniform sweep covered only 2.98% of Q8.24 codes and understated the direct table's max error (32,716.07 LSB observed vs 32,732.04 LSB exhaustive).
- **A minimal sufficient recipe for correct rounding**: a guarded chord-interpolation seed (6 address bits in Q16.16, 8 in Q8.24, 4 guard bits) + one Newton-Raphson step + a single integer residual check (Equation 11: compare 2R against ±k, adjust by at most one code) yields the correctly rounded result on **every** input in both formats — pre-correction max ideal error 0.5973 / 0.6462 LSB (sufficient bound ≈ 0.705 / 0.715 LSB), post-correction 0 mismatches and max ideal error exactly 0.5 LSB.
- **Compact product-reuse datapath**: the residual corrector reuses the k·Z product already computed during refinement, so the extra multiply takes the narrower operand D = 2^g·q0 − Z (Equation 15); at 4 guard bits this cuts DSP slices from 6/12 (Q16.16/Q8.24 full-product corrector) to 5/9, verified exhaustively in RTL at one accepted input per cycle with 10-cycle latency in both formats.
- **Cross-format error budget**: eight extra fractional bits (Q16.16 → Q8.24) reduce max relative error by 205–223× for the three refined paths (NR 220×, Goldschmidt 205×, Hybrid 223×) and 68.2× for the reconstructed interpolator, but only 0.969× for the direct table — with the address width unchanged, its error stays pinned near 0.1% by table spacing (confirmed: the discrete grid prediction of Equation 16 matches the exhaustive maxima to displayed precision).
- **Deterministic selection under explicit budgets**: 166 configurations per format are compared on (coefficient bits, products, max ideal error); non-dominated sets are reported and their sensitivity to error-class resolution (0.25/0.5/1 LSB classes) is tested (Q8.24: 91 → 24 non-dominated designs as classes coarsen to 1 LSB). Example: under a 4-LSB budget the 3-product guarded Hybrid needs 1,056 (Q16.16) / 6,016 (Q8.24) coefficient bits vs 14,848 / 335,872 bits for the 1-product interpolator; exact rounding via the 4-product two-code Hybrid needs 1,120 / 6,528 bits vs 28,672 / 655,360 bits for the 2-product corrected interpolation.

## Methodology

The evaluation reconstructs five fixed-point reciprocal arithmetic paths from an RTL source repository (pinned Git revision 49350ee): a 12-bit direct lookup table, an 11-bit linear (chord) interpolator, an 8-bit table with two Newton-Raphson steps, an 8-bit table with two Goldschmidt iterations, and a 9-bit interpolated seed with one Newton-Raphson step ("Hybrid"). Original coefficient images were unavailable, so all ROMs were regenerated from their defining equations; the paper is explicit that results describe this reconstruction.

All designs share the same input domain and scoring: signed 32-bit Q16.16 and Q8.24 words, inputs [0.5, 2.5] inclusive, every integer code from 2^(F−1) to 5·2^(F−1)−1 tested once. Outputs are compared to both the ideal reciprocal |q − S²/k| in LSB units and the *rounded reference* q* = round(S²/k); reported metrics include max absolute/relative ideal error, RMSE against both references, rounded-reference mismatch counts, and exact-match share. Guarded variants use an internal scale of S·2^g (g guard bits); the residual-corrected variants compute the signed integer residual R = S² − k·q0 and apply a one-code (or two-code) correction whose sufficiency is proven via Equation 12 (if the bound is < 1.5 LSB, one step gives q*). A closed-form address-width analysis (Equation 13, Table 1) shows that in ideal arithmetic a chord seed + one refinement needs only 6 address bits (Q16.16) / 8 (Q8.24) for a uniform one-LSB guarantee — exactly the widths adopted for the guarded Hybrid.

Baselines are evaluated under the same protocol: the Gutiérrez-Ramos et al. piecewise-quadratic seed (published coefficients, 17 fractional bits) with one or two NR refinements; Lunglmayr's degree-4 and degree-10 polynomial corrections of a power-of-two linearization (Horner evaluation, internal precision F+4); and an exact radix-2 non-restoring digit-recurrence control (F+2 unrolled steps: 18 in Q16.16, 26 in Q8.24), the algorithm family behind AMD's Divider Generator IP. A 153-configuration sweep per format (306 total: interpolation widths 5–14 and Hybrid widths 4–10, each × guard widths 0–8) feeds the budget-selection analysis.

On the hardware side, portable SystemVerilog was written for the direct table, guarded interpolation, guarded/corrected Hybrid (full-product and compact correctors), and the unrolled radix-2 divider. A Verilator 5.48.0 C++ scoreboard streams the entire input domain at one input per cycle and checks every output code *and its cycle* against the independent integer model; directed tests cover valid gaps and reset with transactions in flight. Yosys 0.52 maps every design to Xilinx 7-series primitives (LUTs, FFs, DSP slices, BRAM36-equivalents, CARRY4). Routed timing, clock frequency, power, and energy are explicitly out of scope.

## Results & Highlights

- **Correct rounding on the entire domain (the headline)**: on the exhaustive grids (131,073 Q16.16 and 33,554,433 Q8.24 inputs), the corrected Hybrid returns the rounded reference for *every* input — 0 mismatches — with max ideal error exactly 0.5000 LSB in both formats, using 4 products and only 2,560 (Q16.16) / 13,824 (Q8.24) coefficient bits at (N=6/8, g=4). The best published polynomial baseline on the same Q8.24 grid, Lunglmayr degree-10, reaches 0.7106 LSB max ideal error with 827,959 rounded-reference mismatches and 11 products; the quadratic seed + 1 NR reaches only 4.4184 LSB with 9,341,442 mismatches (a second refinement closes to 0.6133 LSB at 1,263,590 mismatches and 7 products).
- **Architecture ranking on the exhaustive grids (Table 5)**: in Q8.24, max ideal absolute error is 32,732.039 LSB (direct 12-bit table) vs 31.961 LSB (interpolation) vs 3.410 LSB (NR) / 4.221 LSB (Goldschmidt) / 1.498 LSB (Hybrid); in Q16.16 the Hybrid's 1.245 LSB also beats NR's 1.462 LSB and Goldschmidt's 2.535 LSB. Max relative error: Hybrid 0.002289% (Q16.16) and 1.0248×10⁻⁵% (Q8.24). Among reconstructed designs, NR strictly dominates Goldschmidt in both formats (same 8,192 coefficient bits and 4 products, lower max ideal error) — the sole strict dominance among the five.
- **Format sensitivity quantified (Table 8)**: Q16.16 → Q8.24 (8 more fractional bits) improves max relative error by 220× (NR), 205× (Goldschmidt), 223× (Hybrid), 68.2× (interpolation), but only 0.969× for the direct table — extra fractional precision is wasted when address width limits the error; the direct table stays near 0.1% max relative error in both formats.
- **Sampling risk made concrete**: the prior 1,000,001-point sweep captured 32,716.07 LSB of the direct table's Q8.24 max vs the exhaustive 32,732.04 LSB, and covered only 2.98% of Q8.24 codes; all Q16.16 codes were covered. Conditional on a mismatch occurring (Q8.24), interpolation's nonzero-error quartiles are 1/1/5 LSB while direct lookup's are 793/1,637/3,786 LSB.
- **RTL cost of exact rounding (Table 14/15)**: the compact corrected Hybrid sustains 1 input/cycle at 10-cycle latency in both formats, using 9 DSP slices in Q8.24 (vs 12 for the full-product corrector; 5 vs 6 in Q16.16) and no block RAM; the exact radix-2 control uses 0 DSP slices but 28 cycles in Q8.24 (20 in Q16.16) with the largest logic cost (1,410 LUTs / 1,514 FFs in Q8.24). For ≤1 output-code error, Q16.16's shortest pipeline is guarded interpolation at 4 cycles (2.5 BRAM36-equiv); without block RAM the guarded Hybrid at 8 cycles (8 DSPs) takes over.
- **Budget selection payoffs (Table 11)**: under a 4-LSB budget the 3-product guarded Hybrid uses 1,056 (Q16.16) / 6,016 (Q8.24) coefficient bits vs 14,848 / 335,872 bits for the 1-product alternative; for exact rounding the 4-product two-code Hybrid uses 1,120 / 6,528 bits vs 28,672 / 655,360 bits for the 2-product corrected interpolator — both remain non-dominated in both formats.

## Critical Assessment

- **Novelty**: the components are classical — chord interpolation, Newton-Raphson/Goldschmidt refinement, and residual-based fixing are all standard in the Oberman–Flynn / Ercegovac–Lang taxonomy, and one-step residual correction for last-bit correctness is a known technique. The paper's genuine contribution is the *evaluation*: complete-domain verification with exact integer scoring, a 306-point configuration sweep, and a budget-aware non-dominated-selection framework, not a new architecture.
- **Rigor**: very high on the numerical side (every claim is exhaustively checked; Equation 16's closed-form predictions match observed maxima digit-for-digit; the sufficiency bound of Equation 12 is derived, not just measured). But the five "reconstructed" designs are the authors' own regeneration — the original coefficient images and raw outputs were unavailable at the cited revision, and the Q16.16 Goldschmidt model deliberately deviates from the public module (8-bit address/9-bit shift per the manuscript vs the repo's 9-bit/8-bit). The paper is honest about this, yet readers should treat the reconstructed-path rows (Table 5) as "one reasonable instantiation", not the historical design.
- **Baseline fairness**: baselines are numerical-only re-evaluations with published coefficients. Lunglmayr's degree-4 correction collapses to 1,663.0002 LSB max ideal error in Q8.24 (33,535,744 of 33,554,433 inputs mismatched) — plausibly an artifact of coefficient/internal precision (F+4) and interval handling under this protocol rather than of the method itself; the paper does not dig into why d4 degrades so catastrophically from 6.7 LSB in Q16.16. Also, no baseline is re-synthesized in the same Yosys/7-series flow, so the hardware table compares only the authors' own designs plus the radix-2 control — vendor IP (e.g., the AMD Divider Generator they cite) is never mapped head-to-head.
- **Reproducibility**: strong — pinned Git revision, named tool versions (Verilator 5.48.0, Yosys 0.52, xc7), released archive with worst-case input codes, and a fully synthetic, self-describing dataset (the integer code range). The claim set is carefully scoped ("mapped resources depend on the tool version").
- **Significance**: for FPGA datapath designers on a bounded positive interval, the selection tables are directly actionable; the exact-rounding recipe (guarded seed + 1 NR + 1 residual check, 2,560/13,824-bit ROM, 10 cycles, 5/9 DSPs) is a tidy, verified data point. Significance drops outside [0.5, 2.5], since no normalization circuit, range check, or negative-input handling is costed.
- **Red flags**: (i) hardware conclusions rest on technology-mapped counts only — no routed timing, clock frequency, power, or energy, so "10 cycles vs 28 cycles" says nothing about wall-clock until both close timing at comparable f_max (the authors say this themselves, but the abstract's DSP/cycle framing still invites over-reading); (ii) the venue line is a template placeholder, so the "ACM TRETS" affiliation should not be read as acceptance; (iii) the exact-rounding guarantee is proven/verified only on the tested interval, not the full positive axis.

## Strengths

- Exhaustive, exact-integer verification on complete input grids — 33.5M points for Q8.24 — with per-input worst-case codes recorded; no sampling or statistical hand-waving anywhere in the error tables.
- A clean, provably sufficient, and exhaustively confirmed recipe for correct rounding: guarded interpolated seed (6/8 address bits) + one NR step + one integer residual check, at modest ROM (2,560 / 13,824 bits) and 4 products.
- The compact product-reuse corrector (Equation 15) is an elegant practical trick — reusing k·Z to shrink the correction multiply's operand width, cutting DSPs 6→5 and 12→9 — and it survives full-domain RTL verification at 1 input/cycle.
- Honest, unusually explicit scoping: reconstruction caveats stated up front, mapped-vs-routed distinction maintained, and the paper quantifies exactly how misleading the earlier sampled sweep was (2.98% coverage, understated maxima).
- The budget-selection framework (least memory vs fewest products per accuracy requirement, plus dominance-sensitivity to error-class resolution) turns a benchmark study into a design tool other engineers can reuse.

## Limitations

- Input domain is strictly positive [0.5, 2.5]; no normalization stage, output range checks, or their costs are analyzed, so the results do not transfer directly to arbitrary-magnitude operands without extra work the paper does not perform.
- Hardware evidence is Yosys technology-mapped counts on one 7-series family; no place-and-route, no f_max, no power/energy, no comparison against vendor IP in the same flow — resource and latency trade-offs may shift under Vivado.
- The five reconstructed paths depend on regenerated coefficients (originals unavailable), and the Q16.16 Goldschmidt numerical model differs from the public repo module; equivalence to the historical experiment is explicitly disclaimed.
- Published baselines are re-scored numerically only (with F+4 internal precision), not re-implemented in RTL; the Q8.24 collapse of the degree-4 polynomial is reported but not diagnosed.
- Correct rounding is established only on the tested interval and formats (32-bit Q16.16/Q8.24); scaling to 64-bit or other Q formats is not explored.
- No end-to-end application case study (e.g., inside a vector normalizer or filter) to demonstrate system-level benefit of correct rounding versus a ≤1-LSB design.

## Relevance

对在 FPGA 上做低精度/定点加速器 datapath 设计的工作直接相关：它给出了定点求倒数（除法、归一化的核心单元）在精确整数参考下的穷举误差预算、正确舍入的最低代价配方，以及"系数存储 × 乘法器 × 精度"的选型表，可作为硬件算术单元设计与评估的可复现参照。

## Questions for Further Exploration

- How does the guarded-seed + 1 NR + residual-check recipe extend to the full positive axis with a 2^e normalization stage — does the residual condition (Equation 11) remain sufficient, and what do the extra shifts/range checks cost in LUTs/DSPs?
- Would Vivado place-and-route (DSP packing, BRAM inference, retiming) preserve the 9-DSP / 10-cycle vs 0-DSP / 28-cycle trade-off against the radix-2 control, and how does AMD's Divider Generator IP compare in the same flow?
- Can the compact product-reuse corrector (reusing k·Z with narrow operand D) be generalized to full division x/y, reciprocal square root, and other function-evaluation datapaths?
- Why exactly does the Lunglmayr degree-4 correction degrade from 6.7 LSB (Q16.16) to 1,663 LSB (Q8.24) under this protocol — coefficient fractional width, F+4 internal rounding, or interval mapping — and is the published method fixable with wider coefficients?
- Does the exhaustive-verification-plus-budget-selection methodology change conclusions for 64-bit or FP16/BF16-adjacent fixed-point formats, where the Q8.24-style exhaustive grid (2^F·2 codes) becomes computationally interesting (33.5M was tractable; 2^29 would need smarter proofs)?
