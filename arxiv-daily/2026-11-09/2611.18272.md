> **一句话总结：** 本文提出一种"只观察、不修改"的 GPU 取证方法：用 cuda-gdb 附加到正在推理的 PyTorch 进程，通过在显存分配器（或 kernel 启动）上设置非停止断点记录每个张量的生死事件，再用一个不看模型结构的"盲选择器"从事件流中识别残差流（residual stream）分配链并在其后一次分配时读取字节，从而在 33 个开源 decoder-only 模型（9 类架构）上实现与 hook 参照逐字节一致的隐状态恢复；把标准框架激活上训练的线性探针套用到恢复出的状态，可在 142 条从未用过的 HarmBench/XSTest 提示上以 AUROC 0.876（prompt 文本分类器基线仅 0.559）判断 Qwen2.5-0.5B-Instruct 是否将拒绝该请求。

> **TL;DR:** A non-modifying cuda-gdb attach to a live, unmodified PyTorch inference process can recover per-layer residual-stream rows (last-token vectors) from VRAM without knowing the architecture or weights: breakpoints on the PyTorch caching allocator log every tensor birth/death, a blind two-step selector finds the residual hand-off chain, and bytes are read one allocation after birth. Recovery is byte-exact on 33 decoder-only models across 9 architecture classes (HuggingFace static-cache path) and validated against hook references on vLLM eager (all 228 Qwen2.5-0.5B prompts byte-identical), vLLM default with CUDA graphs (prefill 31/31, 23/23, 27/27 on 3 fresh models), llama.cpp incl. Q8_0/Q4_K_M (12/12), and SGLang (prefill 6/6). As a use case, a frozen refusal probe on recovered states reaches AUROC 0.876 [0.808, 0.929] on 142 pre-registered, untouched HarmBench+XSTest prompts (vs 0.559 for a prompt-text classifier and 0.725 accuracy for the majority baseline vs 0.803), but with a 28.2% false-positive rate, a 157–163 s/prompt collection cost (~15,000x native), and an envelope bounded to one 8 GB Turing GPU, batch 1, models ≤3.4B (one 7B 4-bit), and fixed-length prompts.

## 核心贡献

- **存在性证明（活体隐状态取证可行）**：首次展示"从正在运行的 GPU 推理进程"中恢复单次请求的逐层残差流状态，无需模型权重或架构参数，也不用 hook 注入目标进程——只依赖 ptrace/cuda-gdb 附加与只读取证原则，证明瞬态隐状态是可采集的法证证据源。
- **六阶段流程 + 适配器模型**：attach → clock → identify → read → validate → use 的平台无关流程；只有"时钟"与"识别规则"是平台特定的。实现两类适配器：(1) 分配器时钟（PyTorch caching allocator 上的非停止断点记录每个 malloc/free 的大小与设备指针）+ 盲两步选择器；(2) kernel 启动时钟（在每次 kernel 启动断点、读参数块 0x160 起的指针候选并给 64 字节末行做指纹），覆盖 vLLM 默认配置（编译 + CUDA graphs）、llama.cpp（含量化）与 SGLang prefill。
- **盲选择器与读取时机的经验规律**：主规则识别"交接链"——层输出在其后继层输出分配后立即释放（形式化：同大小且 n_alloc(b) = n_alloc(a) + ℓ(a) − 1）；回退规则用等步长、同寿命链（≥8 成员、≥90% 间隔一致）。读取必须发生在张量"出生后一次分配"（分配先于填充它的 kernel）——这是测量得出而非假设（提前读在所有层都失败）。选择器经两次修订，负结果（差分显存快照合并成一整块、事后镜像仅 1/13 输出存活等）全部如实报告。
- **从进程本身推导结构指纹**：仅凭首轮日志的 kernel 启动几何与参数字即可推导 token 数、隐藏宽度、层数（在预注册测试中全平台精确，SGLang decode 除外 4/6），但不识别模型身份——把证据分层为"结构（精确）> 计算（实验室验证的逐字节恢复）> 行为（初判 + 已知错误率）"。
- **请求级行为归因用例**：把标准框架激活上训练的深度探针与拒绝探针（行为标签 = 贪心 32-token 回复是否以拒绝短语开头）套到恢复状态上：在默认配置 vLLM 的 142 条未触碰提示上，冻结探针 AUROC 0.876，恢复态与 hook 态 AUROC 仅差 0.0003——证明探针结论对"取证 recovered 状态"迁移有效。

## Key Contributions

- **Existence proof for live hidden-state forensics**: per-layer residual-stream rows of an unknown small LLM can be extracted from a live, unmodified GPU process (ptrace + cuda-gdb attach, read-only), without architecture parameters or weights — establishing transient inference state as acquirable forensic evidence, in contrast to prior work on static artifacts (weights, prompts, cold-boot model recovery, LeftoverLocals-style stale memory).
- **Six-stage pipeline with platform adapters**: attach / clock / identify / read / validate / use, invariant across platforms except the clock and identification rule. Two adapters are built and tested: (a) an allocator clock (non-stopping breakpoints on PyTorch's caching-allocator malloc/free log every tensor's size and device pointer) with a blind two-step selector; (b) a kernel-launch clock (break on every kernel launch, read the parameter block from offset 0x160 on sm_75, fingerprint 64 bytes of the last token's row of 16-byte-aligned pointer candidates in [2^32, 2^48]) that works where memory management leaves the standard allocator (vLLM compile + CUDA graphs, llama.cpp, SGLang).
- **Blind residual-stream identification**: the primary rule extracts the longest hand-off chain — an allocation a links to b iff size(a) = size(b) and n_alloc(b) = n_alloc(a) + lifetime(a) − 1 (a layer's output is freed right after the next layer's output is allocated), requiring ≥8 members with end-trimming; the fallback finds a regular constant-stride chain grouped by size and lifetime (≥8 members, ≥90% of consecutive gaps equal one stride ≥2). The selector never receives the layer count. The read policy (one allocation after birth; at the free event for fallback chains) was established by measurement — reading at the allocation point failed for every layer.
- **Byte-exact validation at scale**: on HuggingFace with a static KV cache, the allocator-clock adapter recovers every true layer byte-exactly on 33 open-source decoder-only models across 9 architecture classes (decode 6/7), confirmed against a synchronised hook pass over 3 repeated passes; adapters for vLLM eager, vLLM default (compile + CUDA graphs), llama.cpp (incl. Q8_0/Q4_K_M quantised weights), and SGLang prefill are reported with their failure modes (Table I).
- **Request-level behavioural attribution**: linear probes (depth and refusal) trained on standard framework activations transfer to recovered states: on 228 byte-identical vLLM-eager recovered rows of Qwen2.5-0.5B-Instruct, a refusal call beats the dataset's own tag on both held-out sources; on a pre-registered test of 142 untouched HarmBench/XSTest prompts against default-configuration vLLM, the frozen probe reaches AUROC 0.876 with recovered-vs-hook AUROC differing by 0.0003 — demonstrating observational, request-level refusal attribution from VRAM alone.

## Methodology

The method is a six-stage pipeline (attach, clock, identify, read, validate, use) where only the clock and identification rule are platform-specific.

**Attach and clock.** A non-modifying debugger (cuda-gdb) attaches to the live PyTorch process. The allocator clock places non-stopping breakpoints at the entry of the native caching allocator's malloc (reading requested size, output slot, and object pointer from argument registers) and at the return addresses of the two relevant call sites (reading the resulting device pointer), plus a free-path breakpoint — yielding a complete log of tensor births and deaths without touching target code. Where the allocator clock is blind (vLLM default with CUDA-graph replay drops from 164–192 to ~17 allocations per call), the kernel-launch clock breaks on every kernel launch, retrieves the kernel name from the invocation column, and reads the parameter block from the debugger's parameter address space (offset 0x160 on the sm_75 GPU used; the block ends where a read fails).

**Blind identification.** From the log alone, the two-step selector picks the residual stream among other large tensors (KV caches, intermediate activations). Step 1 extracts the longest hand-off chain: allocation a links to b iff size(a) = size(b) and n_alloc(b) = n_alloc(a) + ℓ(a) − 1, where lifetime ℓ(a) = n_free(a) − n_alloc(a); chains need ≥8 members and are trimmed if an end gap is less than half the median gap (holds for pre-normalization models). Step 2 (fallback) groups allocations by size and lifetime and accepts a regular constant-stride chain (≥8 members, ≥90% of consecutive gaps equal to one stride ≥2). This rule was revised twice after initial failures.

**Read timing.** Because an allocation precedes the kernel that fills it, bytes are read at the return of the *next* allocation after a tensor's birth — when the output is final and not yet overwritten. For the last token, the read retrieves hidden-size × element-size bytes (the final row). Alternative designs were measured and rejected: differential diffing of two VRAM dumps merged all 13 outputs into one region; post-pass images kept only 1 of 13 outputs alive in 3 alternating addresses (depth is temporal, not spatial); reading at the allocation point failed on every layer; matching ground truth by pointer alone briefly selected an earlier temporary.

**Probes.** Two linear probes on standardized features (z = wᵀ((h − μ)/σ) + b, logistic/softmax loss with weight decay), trained on standard framework activations only: a depth probe (which layer a state comes from; trained on 16-token local-document sentences) and a refusal probe (reads the last prompt token at every layer of a chat-templated prompt; behavioural label = whether the greedy 32-token reply opens with a refusal phrase from a standard list).

**Experimental setup.** Single NVIDIA RTX 2080 Max-Q (8 GB, sm_75), driver 580.178.04, CUDA 13.0, PyTorch 2.13.0, cuda-gdb 13.0, vLLM 0.32.0, SGLang 0.5.23. Development (228 recovered rows + earlier hook analyses) strictly isolated from evaluation; 372 prompts previously exposed to hook-based analysis were excluded from the held-out set; frozen configuration files were SHA-256-hashed; pre-registered tests used hashed scripts before the run; all failures reported. Attribution study: Qwen2.5-0.5B-Instruct, 228 chat-templated prompts of 41–43 tokens (harmful from JailbreakBench/AdvBench, harmless from Alpaca). Allocator study: 33 decoder-only models over 9 architecture classes plus 5 frozen-rule models, prompt "The capital of France is", batch 1, three passes, ground truth via a synchronised hook pass kept separate from acquisition.

## Results & Highlights

- **Byte-exact recovery across 33 models / 9 architecture classes** (HuggingFace static-KV-cache path, allocator clock + two-step selector): every true layer matched byte-exactly to hook reference states, consistent over 3 passes, with the selector never given the layer count; decode-stage recovery succeeded 6/7. On vLLM eager, streams recovered 24/24 and 22/22; all 228 Qwen2.5-0.5B prompts were recovered at all layers byte-identically to the hook reference (max difference 0.0 on HuggingFace fp32).
- **Pre-registered refusal attribution (Experiment A)** on 142 untouched HarmBench-standard + XSTest prompts (39–40 tokens, 103/142 refused) against default-configuration vLLM, probe frozen in advance: **AUROC 0.876 [0.808, 0.929]** (hook reference 0.876; difference 0.0003), balanced accuracy 0.777 [0.696, 0.855], accuracy 0.803 vs 0.725 for the always-refused majority baseline; FPR 0.282 [0.143, 0.436], FNR 0.165. Baselines: dataset-label rule AUROC 0.557 (balanced accuracy 0.731) and a prompt-text classifier AUROC 0.559 — the recovered-state probe beats both by >0.3 AUROC. 142/142 prompts had all 23 claimed layer ends matched within 2%.
- **Offline evidence-standard call beats the dataset's own tag** on 228 vLLM-eager recovered rows: on JailbreakBench (71 prompts) error 15.5% [7.0, 25.4] vs the tag's own 26.8% error (FPR 13.3%, FNR 19.2%); on the other held-out source (157 prompts) error 4.5% [1.3, 7.6] vs tag error 8.3% (FPR 6.2%, FNR 3.3%). AUROC 0.879 / 0.986 on recovered states vs 0.878 / 0.986 on hook states.
- **Serving-stack adapters (kernel-launch clock)**: vLLM default (compile + CUDA graphs) prefill 31/31, 23/23, 27/27 layer ends on 3 fresh models (decode 6/6 runs, every step correct; a duplicate-stop pre-filter fixes long prompts up to ~100 tokens); llama.cpp CUDA backend prefill byte-exact with decode 10/10 runs including the last layer, and quantised Q8_0/Q4_K_M 12/12 runs; SGLang prefill 6/6 but decode only 4/6 (wrong token count on Llama-3.2-1B). TensorRT-LLM/TGI/other GPUs untested.
- **Derived structural attributes are exact in pre-registered tests**: token count, hidden size, and layer count derived from the running process alone with no model input — vLLM 6/6 prefill and decode, llama.cpp fp16 12/12 prefill and 10/10 decode, quantised 12/12; SGLang decode 4/6. Model identity is *not* derived. Length robustness (development-only): the unchanged rule held for token lengths 34, 48, 100, 160, and 230, with layer ends within 2% in 30/30 prompts.
- **Cost of observational access**: median prefill latency for Qwen2.5-0.5B on vLLM batch 1 was 17.5–17.8 ms (eager), 9.6–10.7 ms (default), and 17.3 ms with the debugger attached but no breakpoints; with the collector active, 157–163 s per prompt — roughly 15,000x the unattached default; debugger halts cause 46–192x slowdowns (allocator clock).

## Authors & Credibility

The six authors (Jonathan Pan, Yidi Yuan, Xin Wei Chia, Xinhui Su, Vincent Tan, Brenda Ong) are from the Home Team Science and Technology Agency (HTX), Singapore — the national homeland-security technology agency, a plausible institutional home for forensic-methods research. The paper's methodological hygiene is unusually strong for a short forensic paper: pre-registered tests with SHA-256-hashed scripts and frozen configurations before execution, strict separation of development data (228 recovered rows) from evaluation data (142 untouched prompts; 372 previously hook-exposed prompts excluded from the held-out set), ground truth via a synchronised hook pass kept separate from acquisition, and explicit reporting of negative results and both selector revisions (including an initial kernel-clock scoring defect that failed its pre-registered criterion and was corrected with a re-score that was itself pre-registered). No code release is mentioned. Claims are consistently scoped with explicit bounds rather than universalised.

## Critical Assessment

- **Novelty**: genuine and well-positioned. Prior ML memory forensics (cold-boot key recovery, DeepFreeze, AI Psychiatry) targets static artifacts (weights, framework objects) and LeftoverLocals reads *stale* cross-process leftovers; nobody has shown acquisition of the *live* per-request residual stream from an unmodified process. The refusal-probe result itself is deliberately not novel — the authors correctly frame it as replicating the known single-direction refusal property (Arditi et al.) on recovered states.
- **Rigor**: pre-registration, hash-frozen scripts, dev/eval isolation, byte-exact hook validation, and honest negative-results reporting are exemplary. However, the selector required **two revisions after initial failures** on dev data, and the authors themselves list "potential overfitting to test models after revisions" as a validity threat — the 33-model byte-exact claim is a map of what works, not a universal rule, and only 3 of the vLLM-default models were out-of-sample for the kernel-name rule.
- **Reproducibility**: moderate. The method depends on platform-specific details (PyTorch caching-allocator internals, a build-specific offset, kernel-name substrings like `rms_norm`/`FusedAddRMSNorm`, a parameter-block offset of 0x160 specific to sm_75), all disclosed but brittle across versions; no code is released; everything runs on one 8 GB RTX 2080 Max-Q with driver 580.178.04 / CUDA 13.0 / vLLM 0.32.0 — exact reproduction outside this stack is unlikely.
- **Significance**: bounded. The behavioural claim (refusal, 5–15% error, AUROC 0.88) rests on **a single 0.5B model (Qwen2.5-0.5B-Instruct)** at batch 1 with fixed 39–43-token prompts — no scaling to 7B dense (except one 4-bit 7B), no 3.4B+ behavioural test, no TensorRT-LLM/TGI, no non-Turing GPU, no variable-length or continuous batching. The baselines the probe beats (dataset-label rule AUROC 0.557, prompt-text classifier AUROC 0.559) are deliberately weak, content-only baselines; no comparison against, e.g., output-based refusal detection on the generated 32 tokens, which would likely be stronger than a 0.282-FPR activation probe.
- **Red flags / honest weaknesses admitted by the paper itself**: the technique is "non-modifying but not non-intrusive" — 46–192x halting slowdowns and 157–163 s per prompt make it useless for high-throughput monitoring and forensically non-neutral (the act of observation alters latency and cannot be independently verified in the field); refusal labels come from keyword matching on a 32-token prefix; confidence intervals are wide on small subsets (HarmBench n=18, JailbreakBench n=71); a 4-bit 7B MoE did not fit the 8 GB memory limit; XSTest-safe accuracy is only 0.696 with FPR 0.282 — the probe flags many safe prompts as refusals.

## Strengths

- First demonstration that live, per-request GPU hidden states are acquirable from an unmodified process with byte-exact fidelity (33 models, 9 architecture classes), turning an ephemeral forensic evidence class into a measurable one.
- Clean separation of a platform-invariant six-stage process from platform-specific clock/identifier adapters, with an adapter table (Table I) that reports where each combination worked *and* where it failed (HF growing cache 0/8, SGLang decode 4/6, content rule 2/9).
- Exemplary methodology: pre-registered hypotheses with hashed scripts, frozen probes, dev/eval isolation, hook-based ground truth kept separate from acquisition, and full negative-results reporting (failed read timings, failed diffing approaches, the pointer-identity trap).
- The three-level evidence taxonomy (structural = exact, computational = lab-verified, behavioural = preliminary with stated error rates) is a model of calibrated forensic claims — the paper resists every temptation to overclaim.
- Practical derived-attribute result: token count, hidden size, and layer count of an unknown target can be read from the process alone, exact in pre-registered tests across platforms and quantisation levels.

## Limitations

- **Narrow envelope**: batch size 1 only; fixed prompt lengths per session; decoder-only models ≤3.4B parameters (plus one 7B 4-bit); fp32/bf16 (fp16 on vLLM); a single 8 GB Turing (sm_75) GPU; dynamic/continuous batching untested; TensorRT-LLM, TGI, and other GPUs untested; a 4-bit 7B MoE exceeded memory.
- **Intrusive despite being non-modifying**: debugger halts cost 46–192x; full collection is ~15,000x native latency (157–163 s/prompt) — minutes per prompt, ruling out routine monitoring and raising forensic-neutrality concerns the authors acknowledge.
- **Platform-brittle**: allocator clock needs PyTorch's allocator and a build-specific offset; kernel adapter needs a known norm-kernel name and a GPU-architecture-specific parameter offset (0x160); the selector needed two revisions; no platform-independent identification rule was found; kernel-name rule initially failed at 88 tokens (duplicate stop reports, fixed by a pre-filter; tested envelope ~100 tokens at batch 1).
- **Behavioural evidence is preliminary**: one 0.5B model, keyword-matched refusal labels, high false-positive rate (0.282), weak calibration (ECE 0.160), lower accuracy on XSTest-safe (0.696) and the 18-prompt HarmBench subset (0.778); the probe predicts refusal behaviour, not harmfulness; no timing claims for the kernel clock.

## Relevance

这篇论文与"LLM 服务安全与可观测性"方向高度相关：它给出了一条不修改目标进程、从显存中恢复单次请求隐状态的取证路径，并演示了用线性探针做请求级拒绝行为归因——对于部署 LLM 的审计、合规检查与红队取证都是有用的技术底座，也提示了多租户 GPU 环境中隐状态泄露的现实风险。对研究拒绝方向的线性表征（single refusal direction）的读者，它提供了该结论在"非合作取证式采集"条件下仍然成立的新证据。

## Questions for Further Exploration

- Does the method scale to 7B–70B models on modern GPUs (H100/Blackwell, sm_90+) where the parameter-block offset, kernel names, and CUDA-graph behaviour all differ — or does the adapter surface grow linearly with every runtime version?
- Can the refusal call be improved beyond AUROC 0.876 / FPR 0.282 by probing multiple layers or token positions, and how does it compare against simply classifying the generated 32-token reply (an output-based baseline the paper does not run)?
- Does the hand-off-chain selector survive continuous/dynamic batching, speculative decoding, and multi-request concurrency, where lifetimes interleave and the fixed pass period breaks?
- Could the acquisition be made genuinely low-intrusive (hardware watchpoints, driver-level tracing, or sampled rather than exhaustive breakpoints) to close the 4–5 order-of-magnitude latency gap toward practical monitoring?
- What other behavioural properties beyond refusal — e.g., prompt-injection success, persona/system-prompt identity, memorised-content retrieval — can be read from forensically recovered residual states, and do difference-of-means directions transfer as cleanly as the refusal direction did?
