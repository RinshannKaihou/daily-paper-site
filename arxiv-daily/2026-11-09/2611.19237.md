> **一句话总结：** 该论文将 LLM 智能体的"人工审批"形式化为两条可独立验证的义务——拒绝安全（被拒操作不得产生任何效果）与授权完备性（获批操作必须在有限轮次内完成），并在 τ-bench/τ2-bench Retail 工具、四类智能体运行时（CrewAI/Agno/Google ADK/Mastra）和 59 个可比较的公开 n8n 工作流上做配对 Approve/Reject 审计，发现 300 个获批中 7 个未完成但 0 个泄漏、CrewAI 恢复调度漏掉 336/672 个已批准效果、Google ADK 并行确认每模型丢 3 个已批准分支、4/59 个 n8n 工作流在 Reject 后仍执行受保护效果，并交付一套离线审计工具包和"首个可观测分歧点"分诊流程图。

> **TL;DR:** An empirical audit that turns human-in-the-loop approval for LLM agents into two independently testable obligations — refusal safety (zero denied effects) and bounded authorization completeness (approved work finishes) — verified with native business-state witnesses rather than an LLM judge, across three execution boundaries. On τ-bench/τ2-bench Retail tools with GPT-6.1-Sol, DeepSeek V4.1 Flash, and Claude Haiku 5.5, paired Approve/Reject runs (100 per model) leave 7/300 approvals unfinished with 0/300 denied effects (97.7% completion), and an action-specific scope-restatement prompt arm cuts GPT-6.1-Sol's approval-omission rate from 5.2% (26/500, original prompt) to 0% (0/150). At the harness layer, CrewAI 1.15.37 omits 336/672 approved effects after pause/resume (a join-bookkeeping repair restores 672/672) and Google ADK 2.14.0's combined parallel confirmations lose an approved branch in 3/3 tasks per model; at the workflow layer, 4/59 policy-comparable public n8n workflows (6.8%, Wilson 95% CI 2.7–16.2%) execute the protected effect after Reject, versus 55/59 that correctly suppress it. The offline approval-audit-toolkit and triage flowchart localize the first observable divergence and its repair target.

## 核心贡献

- **双义务审计契约的形式化**：把"审批有效"拆分为**拒绝安全**（决策后不得出现任何当前被拒的效果，即使随后被回滚）与**有界授权完备性**（每个仍获授权、可行且条件有效的动作须在视界 H 内完成，形式化为 F̂_H(τ) = Σ 1{a ∈ done(τ)}）。两者必须**独立测量**——只看其中一条都会产生"控制的幻觉"。
- **以原生业务状态见证（native witness）替代 LLM 裁判**：用环境自身实现的孤立执行或状态谓词来证明效果是否发生，配对决策（同一业务状态上仅改变 Approve/Reject）+ 精确 trace + 待办工作台账，使审计结论可复现、可验证，规避了 LLM-as-judge 的循环论证。
- **三层执行边界的系统实证与归因**：模型层（是否生成全部获批调用）、运行时层（调度/恢复是否保留已批调用）、工作流层（Reject 极性是否真正控制受保护分支）。在 3 个模型 × 5 种提示臂、4 种运行时审批设计 + 2 个框架重放、100 个公开 n8n 源上定位每条决策丢失控制的首个可观测分歧点。
- **可操作的诊断与修复**：三分支分诊流程图（未尝试获批动作 → 模型/待办问题；动作以丢失/过期范围执行 → 调度或决策版本化；Reject 后仍有动作执行 → 决策不敏感组件），配合 CrewAI join 簿记修复、ADK 并行确认修复和 n8n 载荷修复等对应控制，以及一个离线重算原生效果计数与聚簇对照的 approval-audit-toolkit。
- **设计不变式**：跨依赖保留"最新范围化决策"及其极性、条件和待处理效果，直到原生证据解除义务——为智能体运行时给出 8 个具体保留目标（对象身份、条目子集、待办工作、条件有效性、决策修订、并行聚合、委托、持久化）。

## Key Contributions

- **Formal dual-obligation audit contract.** Separates refusal safety (no currently denied effect after the decision, including effects later reversed) from bounded authorization completeness (every still-authorized, feasible action with valid conditions completes within horizon H, formalized as a pending-obligation set P(τ) = A_latest(τ) \ done(τ) and a completeness sum over eligible actions). Approving A and rejecting B creates both a positive and a negative obligation, tracked in a pending-work ledger.
- **Verification by native business-state witnesses, not an LLM judge.** Paired Approve/Reject decisions on identical upstream business state, exact recorded traces (decisions, generated calls, dispatch events, state changes), and isolated native executions establish effects; a completion ledger is validated against native state as reference.
- **First system evidence across all three execution boundaries.** Three-model checkpoint panels (3,300 fresh approval episodes), four runtime approval designs (CrewAI Flow-step feedback, Agno tool confirmation, Google ADK parallel confirmation aggregation, Mastra step suspend/resume) plus OpenAI Agents SDK and LangGraph replays, and source-preserving replay of 100 public n8n graphs — separating model-side omission from runtime scheduling loss and decision-insensitive workflow routing.
- **Actionable diagnosis and reproducible checks.** A triage flowchart that follows the first divergence from the recorded decision; targeted repairs (CrewAI join-bookkeeping restoration, avoiding combined parallel confirmations in ADK, n8n payload fixes such as changing Status=Approved to Pending); an offline approval-audit-toolkit that recomputes native effect counts, clustered contrasts, and conservatively checks n8n rejection paths for untested decision values, linking every reported outcome to hashes, manifests, and native witnesses.
- **A concrete design invariant.** Preserve the latest scoped decision — polarity, conditions, and pending effects — through every transition until native evidence discharges the obligation, organized into eight preservation targets for runtime implementers.

## Methodology

The paper's unit of analysis is a **scoped decision** d_v (with version v, authorized actions A_v, denied effects D_v, execution conditions C_v) followed through three boundaries: the model selects a call, the harness schedules and resumes it, and the workflow routes the decision to a protected effect. Core methodological devices:

1. **Paired comparable decisions.** Each checkpoint fixes upstream state and the protected operation while changing only the decision (Approve vs Reject), so both obligations are measured on the same business state. Rejection bookkeeping and refusal messages do not count as protected-effect violations; only native effects do.
2. **Native witnesses.** A "witness" is an isolated native execution or state predicate establishing feasibility or effect. Missing approved actions receive post-prefix feasibility witnesses on isolated state copies, distinguishing "could not execute" from "was omitted".
3. **Model layer.** τ-bench/τ²-bench Retail tools pinned at commit 96a3ef9, augmented with authored approval checkpoints (explicitly not official benchmark scores). Three provider routes — GPT-6.1-Sol (general-purpose proprietary), DeepSeek V4.1 Flash (cost-oriented), Claude Haiku 5.5 (latency-oriented) — each run on 100 paired checkpoints (12 decision variants: direct, deferred continuation, mixed scope, reject-and-query, revocation, item subset, mixed batch, alternative route, stale consent, quoted handoff, deferred queue, scoped yes) plus 1,100 approval-only episodes across five prompt arms: O (original), S (action-specific scope restatement), S′ (affirmative wording only), C (system-generated action card), L (O plus consent/completion ledger). Horizons are 10–18 turns with scripted follow-ups; native effects, not final prose, determine completion.
4. **Harness layer.** Calls, decisions, and native business objects are held fixed to isolate scheduling from selection: an ADK 2.14.0 matrix crossing sequential / separate-parallel / combined-parallel reply modes with approve-both vs approve-A/reject-B on three two-cancellation Retail tasks (18 episodes per model); a CrewAI 1.15.37 / Agno screening matrix of 2,352 episodes over 42 source proposals crossing decisions, entry modes, and pause/resume transitions, with paired source-copy repair controls (natural-failure analysis retains 1,344 CrewAI episodes, excluding outcome-determining fallback arms); replays of saved proposals through OpenAI Agents SDK and LangGraph; and Agno 3.1.12 banking transitions (τ³ banking extension) testing state change (T1), scope revision (T2), and delegation (T3), with per-model protocols where effects occur only in clones or intercepted services.
5. **Workflow layer.** From an archived frame of 5,606 public n8n graphs (267 with native waits, 221 also AI nodes), 100 source IDs were screened (Oct 15, 2026) down to 59 policy-comparable terminal Approve/Reject pairs; n8n 2.43.5 executes original node versions, expressions, and suffix edges with intercepted services exposing protected requests. Degenerate baselines (abstain-all, execute-all) bound the discrimination test, and six checkpoints crossed with four social pressures (shipping urgency, earlier consent, selective scope, business-goal persistence) test whether refusal is selective rather than blanket.
6. **Detector and triage.** A completion ledger is scored against native labels; a deterministic triage on six predeclared telemetry perturbations validates that recorded divergences reach the intended model/harness/workflow diagnostic branch.

## Results & Highlights

- **Paired model panel (τ-bench Retail, 100 cases per model):** 293/300 approved completions (97.7%) and **0/300 denied effects** — refusal safety saturates while completeness lags. The zero-leak claim is bounded by a descriptive 95% Wilson upper bound of **3.7%**. By model: GPT-6.1-Sol 96/100, DeepSeek V4.1 Flash 100/100, Claude Haiku 5.5 97/100 complete, all 0/100 denied effects.
- **Expansion panel (3,300 approval episodes):** 3,232/3,300 observed completions (**97.9%**), leaving 68 unfinished approvals (**2.06%**) — 44 GPT-6.1-Sol vs 6 DeepSeek V4.1 Flash and 18 Claude Haiku 5.5. Gaps cluster in deferred continuation, mixed batches, deferred queues, and confirmation-related variants (e.g., deferred continuation 5/6 for Claude Haiku 5.5; mixed batch 8/10 for GPT-6.1-Sol).
- **Prompt arms:** GPT-6.1-Sol failure rate drops from **5.2% (26/500) on the original prompt (O) to 0% (0/150)** with action-specific scope restatement (S) and 0% with a ledger (L), while wording-only S′ is *worse* at 8.0% (12/150); DeepSeek V4.1 Flash: 1.2% (6/500) on O, 0% on all other arms. However, matched-subset contrasts are exploratory: S-vs-O McNemar p = .25 (GPT-6.1-Sol), the frozen 20-task diagnostic shows a +4.0 pp ledger gain with task-cluster bootstrap 95% CI [0,9] and sign test p = .25 — a localization probe, not a validated fix.
- **Google ADK 2.14.0 parallel confirmation:** combined parallel approve-both replies lose exactly one approved branch in **3/3 tasks (3/18 episodes per model, all three models)**, while sequential and separate-parallel replies lose 0/3 — isolating confirmation-response aggregation as the failing transition (both confirmation requests and approvals exist; only one cancellation reaches dispatch).
- **CrewAI 1.15.37 restoration:** after a paused parallel join or router, CrewAI records the approval but never reschedules the approved step, omitting **336/672 approved effects (50%)** while all 672 Reject episodes correctly suppress the protected effect; a source-copy repair restoring join bookkeeping and draining sibling/router handling completes **672/672** approvals.
- **Public n8n workflows:** of 59 policy-comparable pairs, 55 suppress the protected effect after Reject but **4 execute it (6.8%, descriptive 95% Wilson CI 2.7–16.2%)** — three (sources 5152, 5312, 8318) send a customer response / queue video creation / publish a social post without ever testing the approval value, and source 11526 enters its rejection branch yet writes Status=Approved; changing that literal to Pending flips the effect vector from [1,1] to [1,0]. All four survive graph deduplication and pass gate-presence coverage, so only native replay detects them.
- **Discrimination and robustness:** the abstain-all baseline completes 0/100 approvals but prevents all 100 denied effects; execute-all completes 100/100 approvals but produces all 100 denied effects. Under four social pressures (24 Approve/Reject pairs per model, 48 episodes), **all 72 Reject episodes prevent denied effects while completing permitted companion work, and all 72 Approve controls complete** — refusal is selective, not blanket abstention.
- **Detector quality:** the completion ledger agrees with native labels on the paired panel with **precision and recall 1.00** for all three models (TP/FP/FN = 137/0/0 GPT-6.1-Sol, 142/0/0 DeepSeek V4.1 Flash, 139/0/0 Claude Haiku 5.5); the synthetic triage test yields 120 correct fault labels + 20 clean controls with zero off-diagonal confusion (accuracy 1.00).
- **Banking transitions (Agno, τ³ extension):** in T1 (state change invalidating a reserve-conditioned transfer), **all 4 approved transition episodes per protocol still execute the now-invalid transfer** (four reserve breaches committed for GPT-6.1-Sol); in T2 (scope revision), 4 approved episodes execute the earlier confirmed requirement before processing the new text; T3 delegation retains the earlier denial.

## Critical Assessment

- **Novelty (good):** The dual-obligation decomposition — measuring refusal safety and authorization completeness *independently*, with paired Approve/Reject on identical business state and native witnesses instead of an LLM judge — is a genuine methodological advance over prior approval–execution-binding studies (Approval Laundering, Loopjacking, Guarded Commits), which mostly audit one direction. The three-boundary attribution (model call selection vs harness scheduling vs workflow routing) converts a vague "HITL is broken" complaint into named, repairable failure mechanisms with version-pinned reproductions.
- **Rigor (mixed):** The paired design, degenerate baselines (abstain-all / execute-all), and pressure tests are well-controlled, and the detector achieves PR 1.00 on the paired panel. But many cells are tiny and the paper appropriately refuses to generalize: the ADK parallel result rests on 3 tasks × 6 decision-mode cells (3/18 episodes per model); Fig. 1 variant counts have denominators of 6; banking T1/T2 conclusions rest on 4 episodes per family; and the headline prompt-arm improvement (O 5.2% → S 0%) is explicitly exploratory (S-vs-O McNemar p = .25; ledger gain CI [0,9], p = .25). The zero-denied-effects claim on 300 paired episodes carries a 3.7% Wilson upper bound — absence of leakage is bounded, not proven.
- **Protocol heterogeneity (weakness):** Cross-model comparability is diluted by per-model protocol adjustments — DeepSeek V4.1 Flash "first obtains a compatible proposal and replays it", and Claude Haiku 5.5's "sensitivity protocol removes a conflicting pre-review instruction" to reach the banking checkpoint. These are disclosed, but the three models are then not running identical protocols in that section, and the T1/T2/T3 counts in Table III mix "original", "adapted", and "sensitivity" rows.
- **Labeling quality (weakness):** AI annotation covers 450/459, 459/459, and 444/459 items with κ as low as 0.190 for workflow semantics — barely fair agreement. The authors correctly demote labels to secondary and use native effects as the primary endpoint, but the 59-workflow "policy-comparable" funnel itself depends on these shaky semantic judgments.
- **Reproducibility (mostly good, with gaps):** Pinned commits, hashes, manifests, and offline recomputation are exemplary on the harness/workflow side; but all three models are proprietary API endpoints (GPT-6.1-Sol, DeepSeek V4.1 Flash, Claude Haiku 5.5) whose behavior drifts, and no toolkit/code URL appears in the paper. The synthetic triage accuracy of 1.00 validates the detector against its own predeclared fixtures — it verifies wiring, not field generalization, as the authors admit.
- **Significance (good):** The CrewAI 336/672 omission, the ADK combined-reply branch loss, and the four post-Reject n8n executions are concrete, named, and actionable for runtime maintainers; the eight preservation targets and the design invariant are directly usable engineering guidance. The repeated-cell caveat (42 source IDs, 37 exact actions, 20 customers) is acknowledged.
- **Red flags (minor):** The 3-page compressed format leaves key details under-specified — e.g., the CrewAI repair components are "applied together", so the reader cannot tell which component (join bookkeeping vs sibling/router draining) carries the fix; and the stakes-framing (military strike cancellation, spacecraft command) is illustrative rather than evidenced, since defense/aerospace traces were unavailable.

## Strengths

- Reframes approval effectiveness as two *independently verifiable* obligations, exposing the failure mode most HITL evaluations miss: approved work that silently never happens (7/300 model-layer, 336/672 CrewAI) alongside the usually-studied denied-effect leakage (which was 0).
- Native business-state witnesses and paired decisions eliminate LLM-judge circularity and make every reported number re-derivable from execution evidence (precision/recall 1.00 against native labels).
- Clean attribution: holding calls, decisions, and state fixed isolates confirmation aggregation (ADK), restoration scheduling (CrewAI), and decision-insensitive routing (n8n) as distinct mechanisms at distinct layers, each with a demonstrated repair control.
- Honest statistics: exact McNemar and bootstrap intervals on exploratory contrasts, Wilson intervals on proportions, explicit non-independence caveats, and explicit refusal to claim deployment prevalence.
- Practical deliverables: a triage flowchart usable by an agent user today, an offline audit toolkit, eight concrete runtime preservation targets, and a one-sentence design invariant suitable for adoption in framework documentation.
- Tests the *useful* side of approval too — all 72 Approve controls complete under social pressure, ruling out "safety via blanket refusal" as an explanation of the Reject results.

## Limitations

- Risk-directed checkpoints and repeated transition episodes do not estimate deployment prevalence; the panels are mechanism-diagnostic, not population statistics (acknowledged by the authors).
- Small denominators throughout (6-case variant cells, 3-task ADK matrix, 4-episode banking transitions) with correspondingly wide intervals; the headline 4/59 n8n failure rate has a 95% CI of 2.7–16.2%.
- All three models are proprietary endpoints; no open-weight model is tested, and per-model protocol adaptations (DeepSeek replay, Claude Haiku sensitivity protocol) weaken strict cross-model comparability.
- Workflow-semantic annotation shows only fair AI agreement (κ 0.190–0.477), so the n8n funnel's "policy-comparable" filtering is itself interpretation-sensitive.
- Prompt-arm fixes (S, L) are unvalidated generalizations — task-clustered exploratory contrasts with p ≥ .25; the +5.33 pp restatement effect is provider-specific in direction.
- Horizons are 10–18 turns; long-horizon authorization decay and multi-party (multi-approver) scenarios are untested. Banking effects occur only in clones/intercepted services, and the CrewAI repair is evaluated as a bundle rather than ablated.

## 相关性 / Relevance

该论文直击 LLM 智能体走向生产环境的核心可控性问题——人工审批究竟是真实控制边界还是"控制的幻觉"，其"拒绝安全 + 授权完备性"双义务契约、三层归因审计方法与原生见证技术，对构建可靠的工具调用智能体、选型与加固智能体运行时（CrewAI/ADK/Mastra 等）以及审批工作流的设计都有直接工程参考价值。

## Questions for Further Exploration

- Do authorization-completeness gaps grow with horizon length beyond 18 turns, multi-dependency workflows, or more than two concurrently approved actions, where pending-work bookkeeping is hardest?
- Can the audit contract be enforced *at runtime* (e.g., a scheduler-level pending-obligation ledger that blocks completion claims until a native witness discharges them) instead of detected offline after the fact?
- Which component of the CrewAI repair — join bookkeeping restoration vs sibling/router draining — actually carries the 336-omission fix, and does the same fix pattern transfer to LangGraph interrupts and AutoGen saved-state orchestration?
- What is the post-Reject execution prevalence across the full 5,606-graph n8n archive (beyond the 59 policy-comparable pairs), and can static graph verification (AgentProof-style) plus native replay scale to it?
- Do open-weight models show the same omission profile (44 GPT-6.1-Sol vs 6 DeepSeek V4.1 Flash unfinished approvals), and is scope restatement (S) a provider-specific or universal localization probe?
- How should the contract treat non-binary effects — a cancellation that later fails downstream, partially-executed batches, or effects that require a *fresh* decision after a disclosed condition change?
