> **一句话总结：** 开源运行时 tritify 把稠密解码器 LLM、MoE 解码器和 SAM 2.1 的整条前向推理路径（含矩阵乘累加、重量化、RMSNorm、GELU/softmax 查找表、MoE 路由）全部改为精确整数运算，使输出在跨 CPU 指令集、CPU/GPU、乃至多机分布式切分下都逐位一致（以可复现 SHA-256 为证）；作者用三台机器（无一能容纳 427 GB 整数码）跑完 106B 参数的 GLM-4.5-Air，其 46 层每层的隐藏态哈希与单机流式参考完全相同。

> **TL;DR:** tritify is an open-source Rust runtime that runs the whole forward pass of real models (Qwen2.5 dense decoders, OLMoE/GLM MoE decoders, SAM 2.1) in exact integer arithmetic, making output bit-identical across hardware and across machines — e.g., Qwen2.5-0.5B produces the same logits SHA-256 on ARM/NEON (M3 Max) and x86-64/AVX-512 (EPYC 9454P), while keeping decision fidelity to the fp32 float reference (509/512 argmax matches on a 512-token probe; SAM 2.1 selected mask IoU = 1.0000 with 0/65,536 pixels differing vs the float twin; OLMoE-1B-7B routing agreement 508/512). The payoff is location independence: GLM-4.5-Air (106,852,251,264 params, 427 GB of integer codes) answered correctly across a 3-machine fleet, bit-identical at every one of its 46 layers to a single-host streamed reference. The cost is honest and stated: ~1.25x fp16 model size, no speed win over optimized float, ~90 network round-trips per decoded token, and determinism only under a fixed batching/schedule.

## 核心贡献

- **全整数、无校准的推理路径**：权重离线一次量化到 12-trit 平衡三进制网格（每符号 265,720 级，约 19 bits），激活按 tensor 动态量化，运行时路径（forward_int）完全无浮点——逆 RMS 用整数 isqrt，GELU/softmax 指数用整数查找表，无需校准数据、无需量化感知训练。
- **三条严格区分的可验证声明**：(1) 跨硬件可复现——输出跨指令集、CPU/GPU 逐位一致，由可复现 SHA-256 承载；(2) 对浮点参考的决策保真——异常被测量而非假设掉，并首次延伸到深度（OLMoE-1B-7B 全 16 层与 GLM-4.5-Air 前 16 层，无保真悬崖）；(3) 位置无关性——无论算子在哪台机器执行，拼接结果与单机逐位一致。
- **可验证分布式推理作为推论**：因为输出是 (权重, 输入) 的确定函数，427 GB 整数码的 GLM-4.5-Air 被切到三台都装不下它的机器上推理，逐位等于单机流式参考（每层隐藏态哈希相同）；诚实运行的一致性可被任何第三方用开放标量参考重算校验——针对不诚实服务器的协议留作未来工作。
- **自验证工程契约**：每个算子同时实现 forward_int 与 forward_ref（浮点孪生），验证门报告误差、确定性与输出哈希；不能给出浮点参考的算子不许发布。引擎冻结 + 每模型家族一个插件，稠密/MoE/SAM 2.1 共用同一精确整数引擎。
- **确定性 MoE 路由内省**：路由 trace 是字节可复现的测量而非印象——有界词表负载只用 64 专家中的 28 个，多样文本用 52 个；每层 24/64 的 LRU 专家缓存即可本地服务约三分之二的路由。

## Key Contributions

- An exact-integer, calibration-free inference path: weights quantized once offline to a 12-trit balanced-ternary grid (L_W = (3^12−1)/2 = 265,720 levels per sign, ~19 bits); activations dynamically quantized per tensor at run time (interchange level 2^28). The run-time path contains no floating point at all — the inverse-RMS is an integer isqrt, GELU and softmax-exp are offline integer lookup tables, and even scalar bookkeeping (scale composition, requantization) is integer with a pinned round-half-away-from-zero rule.
- Three claims deliberately separated and each verified: (1) cross-hardware bit-identical reproducibility (run-to-run, across CPU ISAs, CPU/GPU) carried by a reproducing SHA-256; (2) decision fidelity to the float reference with exceptions measured, extended to depth through 16 layers of OLMoE-1B-7B and of the 106B-parameter GLM-4.5-Air MoE, with no fidelity cliff; (3) location independence — splitting a model across ISAs, CPU/GPU, or networked machines has zero effect on output bits.
- A frontier-scale demonstration of Claim 3: GLM-4.5-Air (427,409,005,056 bytes of integer codes, more than any node's RAM in the run) generated its answer across three machines, bit-identical to a single-host streamed reference at every one of the 46 layers, verified by one hash (564f495c...).
- The verifiable-offload consequence: a fast untrusted server (or commodity fleet) runs the model while an open scalar oracle (local or third-party) re-derives the exact bytes — turning "trust me" cloud serving into a checkable computation. The paper is explicit that agreement of honest execution is demonstrated, not a protocol against a dishonest server.
- A frozen generic engine plus per-family plugin crates (dense decoders, MoE decoders, SAM 2.1) where every operation ships a forward_int/forward_ref two-method contract and a verification gate that refuses unverified operations.
- Deterministic MoE routing introspection: a read-only trace hook records which top-k experts fire per token, reproducibly on any machine, enabling workload-dependent expert-cache analysis (a 24-of-64-experts LRU cache serves ~two-thirds of routing across five real OLMoE workloads).

## Methodology

tritify represents every tensor as integer codes c_i together with a single fixed-point scale s = m·2^−k (64-bit integer mantissa, 32-bit shift); the denoted value is c_i·s. Weights are quantized once at build time to a balanced-ternary grid of b = 12 trits via c_i = round(w_i/Δ) with Δ = max|w_i|/L_W — post-hoc, with no fine-tuning, no quantization-aware training, and no calibration data. Activations entering a matmul are quantized dynamically per tensor by their own maximum; between operations they are carried at the interchange level 2^28.

The run-time data path is fully pinned integer arithmetic: (i) matmul accumulation is exact integer — the auto-vectorized kernel accumulates i32×i32→i64 products in i64 (exact because codes are bounded by L_W ≈ 2^18, so length-K sums stay below 2^63), with an i128 accumulator as reference for cases outside that bound; (ii) requantization is round(c·m/2^k) via i128 multiply plus an arithmetic shift with fixed round-half-away-from-zero; (iii) residual addition brings tensors to a common scale by integer scale composition; (iv) RMSNorm/LayerNorm compute the sum of squares as an exact integer reduction and the per-row inverse-RMS with an integer inverse square root (measured max relative error 5.8×10^−10 over 2×10^5 points); (v) GELU and softmax-exp are integer lookup tables built once offline (20-bit-index GELU: max abs error 4.8×10^−5); (vi) attention scores are exact integer dot products scaled by the fixed 1/√d_head with a max-shifted exp table; (vii) the MoE router scores experts in integer, top-k selection breaks ties by index, and the normalization ε is resolved by one fail-closed rule — config value > the architecture's recorded transformers default > hard refusal naming the missing key (never silently guessed).

Because integer addition (including two's-complement wraparound) is associative and commutative, reordered multi-lane SIMD reductions (NEON smlal on ARM, AVX-512 on x86-64 via -C target-cpu=native auto-vectorization) and multi-threaded computation over disjoint output blocks equal the scalar left-to-right order exactly — confirmed by a 200,000-case fuzz that deliberately includes i64-overflow magnitudes. This same property is what makes cross-machine splitting exact: which machine runs which layers, experts, or matmul rows has zero effect on the output bits. Verification is structural: every operation implements forward_int plus a floating-point forward_ref twin on dequantized inputs, and a gate reports max abs/rel difference, determinism on re-run, and a SHA-256 of the integer output — "is it faithful?" becomes a test rather than an assertion. The distributed seam keeps expert weights resident on workers; only activations and expert output vectors cross the wire (kilobytes per token), over QUIC.

## Results & Highlights

- **Cross-ISA bit-identity (Claim 1):** On Qwen2.5-0.5B (494M params, seq 512), the logits SHA-256 is byte-identical between Apple M3 Max (ARM/NEON) and AMD EPYC 9454P (x86-64/AVX-512) on byte-identical weights — scalar and vectorized, one thread and all cores (digest 6c139feb...). The ternary GEMM kernel is bit-identical CPU = GPU (Apple M3 Metal).
- **Decision fidelity vs the float reference (Claim 2):** On a 512-token synthetic probe of Qwen2.5-0.5B, integer argmax matched the fp32 reference at 509/512 positions (the 3 disagreements are near-ties; max abs logit error 2.1×10^−1). On SAM 2.1 (hiera-base-plus, 613-tensor checkpoint), the selected 256×256 mask is pixel-identical to the float twin — 0 of 65,536 pixels differ, IoU = 1.0000 — while raw mask logits differ by at most 4.9×10^−2.
- **Fidelity at depth, no cliff:** Across all 16 layers of OLMoE-1B-7B vs the fp32 transformers reference: median per-layer residual cosine 0.9999991, final logits cosine 0.9999998, router top-k exact agreement 508/512. Across the first 16 of 46 layers of GLM-4.5-Air: median residual cosine 0.9996717 (1 − median ≈ 3×10^−4 at the slice end), worst single probe position dipping to 0.9735 at one layer and recovering to 0.9988, routing agreement 448/480 (32 near-tie top-k set differences out of 480 decisions).
- **Fast paths move no bit:** SIMD hot kernel 4.76× (M3/NEON) and 4.68× (EPYC/AVX-512) vs the vectorizers-off baseline; Qwen2.5-0.5B forward_int (seq 512) 11.8× (133.7 s → 11.4 s) with SIMD × threads; SAM 2.1 base-plus end-to-end 7.0× (237.7 s → 34.0 s) — every cell reproduces the same output digest. Footprint: Qwen2.5-0.5B goes from 942 MiB (BF16) to ≈1.15 GiB (~20 bits/weight packed) = 1.25× fp16, with 5.80 GiB peak conversion working set and 13.6 s convert-plus-self-verify.
- **Six-machine distributed run:** OLMoE-1B-7B split across six machines (arm64 MacBook Pro coordinator + 96-core x86-64 server + two fanless x86 mini-PCs + two Raspberry Pis, two ISAs, three locations, QUIC): an 8-token probe cost 498 expert round-trips, 4.10 MB out / 8.43 MB in, 35.8 s wall — and the whole-model output hash (3dadb4f1...) equals the single-machine run. A two-layer loopback with cache-aware placement (24/64 experts per layer, in-sample) served 85% of routing (109/128) locally and cut remote wire traffic ~80% (1.19 MB → 0.24 MB) at identical output bits.
- **Frontier-scale capacity run:** GLM-4.5-Air — 106,852,251,264 parameters, 427,409,005,056 bytes of integer codes — ran across three machines (M3 Max 68.7 GB coordinator holding 28.8 GB of codes; EPYC 337.5 GB holding experts 0–74 = 233.6 GB; host B 238.5 GB holding experts 75–127 = 165.1 GB; workers resident total 398.6 GB), none able to hold the full codes. Asked "What is the capital of France?", the fleet produced the same 7 tokens, the same generated-logits hash (564f495c...), and the same hidden-state hash at every one of the 46 layers as the single-host streamed reference. Cost: 2,504 round-trips (~90 per decode position = 45 MoE layers × 2 workers), 633.6 s total wall (setup + prefill + decode not separated).
- **Routing introspection with cache implications:** On OLMoE-1B-7B layer 8 (top-8 of 64), a bounded narrow-vocabulary workload used 28/64 experts vs 52/64 for a diverse passage; across five real workloads, an LRU cache of c = 24 of 64 experts per layer served ~67% of routing on average (range 27%–90%), out-of-sample.

## Authors & Credibility

Single-author paper: Sayed Amir Karim of Pelloran Inc., an industry researcher; tritify itself is Apache-2.0 open source, while Section 11 discloses that Pelloran separately sells a commercial orchestrator and verifiable-inference/compliance products built on it — a conflict of interest that is at least stated plainly. The paper carries a Zenodo DOI (10.5281/zenodo.23986737) and is unusually disciplined epistemically: three claims kept separate, an explicit "what we do not claim" list, measured exceptions rather than assumed ones, and a disclosed-and-corrected ε misconfiguration (an earlier build defaulting OLMoE to ε = 1e−6 agreed on only 0.455 of routing decisions vs the shipped 1e−5; after aligning the family default, 508/512). Credibility caveats: it is a preprint draft whose reproducibility artifact — public repository URL, full-length digests, build configs, run logs — is "fixed at release" and not all present in the draft, so the central checkability promise cannot yet be exercised by a third party; and the headline verifiable-offload property against a dishonest server is explicitly future work, not a delivered protocol.

## Critical Assessment

- **Novelty — moderate, and honestly bounded.** Integer-only transformer inference is established (I-BERT, I-ViT, I-LLM, TFLite integer path), and the author concedes the closest project, Barry's detllm, already achieved a same-hash integer forward of Qwen3-0.6B across a broader hardware matrix (two NVIDIA GPU architectures + AMD/Intel/Apple CPUs) and — crucially — the batch/schedule invariance that tritify currently lacks, while int-llm already reported byte-reproducible pure-integer inference. The genuinely new parts are the breadth (dense + MoE + SAM 2.1 in one frozen engine), the forward_int/forward_ref per-operation gate, and above all the fleet-scale bit-identity demonstration on a 106B MoE with per-layer hashes.
- **Rigor — strong on determinism, weak on downstream accuracy.** Determinism evidence is exactly what it should be (reproducing SHA-256s, a 200,000-case overflow-including fuzz, per-layer depth curves). But there is no perplexity, no benchmark accuracy (no MMLU/GSM8K/HellaSwag, no SAM 2.1 benchmark suite like SA-1B mask AP) for any model — "decision fidelity" rests on a 512-token synthetic probe, 32-token depth probes, one SAM image, and a single "capital of France" prompt. The 3/512 argmax flips are near-ties, but autoregressive divergence from such flips over long generations is asserted as a mechanism, never measured.
- **Fidelity-at-depth is a 16/46-layer extrapolation (admitted).** No node in the run holds GLM-4.5-Air in fp32, so full-depth fidelity to float is unmeasured; the full-depth property actually established is bit-identity to tritify's own single-host reference, which is exactness, not accuracy.
- **Schedule dependence undercuts the serving story.** Because activation quantization is dynamic per tensor, a different batch composition or prefill/decode split changes a tensor's maximum and hence the output bits — measured on Qwen2.5-0.5B where the integer path is not schedule-invariant (argmax preserved on that probe, but the bits move). Determinism holds for fixed input AND fixed batching/execution schedule; there is no incremental KV-cache decode path yet, which also defers the same-state handoff capability of Section 8.3.
- **Missing ablations:** no comparison of trit's b = 12 (~19-bit) weight grid against cheaper grids (8/10 trits, int8/int4) to show the fidelity/speed/size frontier; no measurement of the distributed fleet's advantage over the single-host streaming reference (resident working set, latency, disk I/O) that the authors themselves name as the real quantity of interest; GPU bit-identity is shown only for one ternary GEMM on Apple M3 Metal, not whole models.
- **Red flags:** the flagship GLM run is one 21-position prompt generating 7 tokens in 633.6 s (no decode rate implied, as stated) — a capacity/verifiability existence proof, not a serving system; the six-machine OLMoE hash predates the ε correction (a 1e−6 build); and a single-author company preprint whose entire value proposition is third-party checkability, deferred to an artifact that does not yet fully exist, deserves skepticism until release.

## Strengths

- Exemplary claim hygiene: three precisely separated claims, an explicit non-claims list (no speed win, no bit-equality of raw intermediates, no confidentiality, no exclusive "runs at all"), and scope limits stated before a reader can raise them.
- Every quantitative statement is anchored to a reproducing SHA-256, and per-operation verification is structural (forward_int/forward_ref gate) rather than a one-off experiment — the kind of evidence culture reproducibility research should emulate.
- The ε misconfiguration in the OLMoE build is disclosed with numbers (0.455 → 508/512 routing agreement) and fixed by a fail-closed rule (missing ε resolves from the recorded family default or the build refuses), which is a genuinely good systems lesson about silent numeric defaults.
- The deterministic routing-trace capability converts MoE routing from an impression into a reproducible measurement, and the workload-dependent expert working-set observation (28/64 vs 52/64; 24-expert cache serving ~two-thirds) is immediately useful for edge MoE serving and placement.
- Real models at real scale: dense 0.5B–1.5B LMs, OLMoE-1B-7B, SAM 2.1, and a 106B frontier MoE across a genuinely heterogeneous fleet (Raspberry Pis to a 96-core EPYC) — not a toy-kernel demonstration.

## Limitations

- No throughput or accuracy advantage claimed or shown over optimized float inference: the model is 1.25× fp16 in size, intra-machine speedups (up to 11.8×) are relative to tritify's own scalar single-threaded baseline, and distribution adds ~90 round-trips per decoded token plus network latency.
- Decision fidelity is tolerance-bounded, not bit-equal: raw logits differ from the float reference (max abs 2.1×10^−1 on Qwen2.5-0.5B), near-ties can flip argmax, and autoregressive divergence after a flip is unquantified.
- Determinism requires a fixed batching/execution schedule (dynamic per-tensor activation quantization is schedule-dependent); per-token/static scaling (as detllm uses) and the incremental KV-cache decode path are future work.
- Float-fidelity at depth is measured only to 16 layers of GLM-4.5-Air (the fp32 limit of a single node); layers 17–46 are extrapolation. GPU bit-identity covers only the ternary GEMM on Metal.
- Verifiability against a dishonest server is a direction, not a protocol: no specified sampling rule, state binding, or attacker model; verification costs recomputation, and full re-execution erases the offload benefit. Confidentiality is explicitly not provided — servers see activations.
- The reproducibility artifact (repository URL, full-length digests, build configs, logs) is incomplete in this preprint draft, and an output hash proves identity, not implementation correctness.

## Relevance

这篇论文直接命中"Inference Reliability & SDC Detection"（推理数值可复现性、数值内核/服务栈导致的输出不可复现与可校验性）与"Reliability under Extreme Performance Optimization"（量化误差、低精度算术精确性）两个核心方向：它把浮点非结合性这一被忽视的可靠性缺陷从推理路径中根除，并用哈希使分布式推理结果可被第三方独立校验。其确定性 MoE 路由内省与跨机逐位一致的分布式切分，对关心大规模推理基础设施可靠性与可验证服务的研究者也是高相关读物。

## Questions for Further Exploration

- What is the end-task accuracy gap (perplexity, MMLU/GSM8K-style benchmarks, SA-1B mask AP for SAM 2.1) between the integer path and the float reference, and do the 3/512 near-tie argmax flips compound into divergent generations on long-form outputs?
- Can the per-token/static activation scaling that gives detllm batch- and schedule-order invariance be adopted without giving up tritify's i128-exactness, MoE breadth, and the forward_int/forward_ref gate — and what fidelity does that scaling choice cost?
- What would a sound audit protocol against a dishonest server look like (sampling rule over ops/tokens, binding of intermediate states, explicit attacker model), and what cheating-detection probability does each unit of local recomputation buy?
- Does the workload-dependent expert working set (28/64 for bounded vocabulary vs 52/64 for diverse text) persist on larger MoEs such as GLM-4.5-Air's 128-expert layers and on production traces, making expert caches and placement systematically cheaper for bounded workloads as models grow?
- Can GPU bit-identity be extended from a single ternary GEMM on Apple M3 Metal to whole models on discrete CUDA/ROCm GPUs, and how does the ~19-bit weight grid trade off against int8/int4 alternatives on the fidelity-size-speed frontier?
