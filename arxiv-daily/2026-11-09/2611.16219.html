⚠ Critical edge

The edge over Cake shrinks monotonically with batch — from 1.69× at B=1 to a 1.017× near-tie at B=256 — so the 1.387× headline leans on small and mid batches.

01 Methodology — how it works

  • Three persistent role kernels, one CUDA Graph, two Green Contexts. Role 1 (6 SMs) scans routes, pulls peer rows, publishes experts the instant their last row lands; role 2 runs grouped GEMM1+SwiGLU+GEMM2 plus the fused shared expert (4 math warps + TMA producer); role 3 combines k partial sums in FP32 → BF16.
  • Swap-AB block-scaled mainloop. FP4 weights occupy the QMMA A operand at fixed M=64; FP8 activations sit on B, so the token extent varies at run time without touching the weight pipeline. Four K32 scale bytes pack into one 32-bit register selected by MMA byte-id immediates — zero scale bookkeeping in the issue-bound loop.
  • Launch-time adaptive geometry. Tile tier, pipeline depth, handoff placement, and register ceiling derive from a run-time SMEM model with trap-on-exceed and co-residency checks before graph instantiation.
  • Streaming dispatch, relay returns. Deduplicating 64-bit (rank, token) pull cache collapses repeated PCIe reads; full-width BF16 returns drained by resident relay copier CTAs so slow experts never stall finished output.

CuTe DSL + hand-written PTX (m16n8k32 mxf8f6f4) · asserted exactly-once PTX rewrites · cubins & child graphs cached by SHA-256 · identical pre-quantized FP8/MXFP4 inputs for all operators

Numerics separate the confounds cleanly: both operators sit at 0.976–0.977 cosine vs the dense BF16 reference — the gap is purely MXFP4/FP8 quantization error, and the SM120 scheduling machinery is numerically invisible. The B=256 GLM5.2 near-tie is analyzed, not hidden: weight streaming saturates HBM (593 vs 583 GB/s) and relay copiers compete with the MMA grid for residency.

03 Strengths

  • Diagnoses exactly why a datacenter Blackwell kernel fails on SM120 — four structural reasons, each answered with a mechanism tied to that reason, not blanket retuning.
  • Swap-AB keeps the weight TensorMap, SMEM tile, and swizzle shape-invariant while the token extent changes at runtime — adaptive geometry costs nothing in the weight pipeline.
  • Scale-byte MMA immediates remove an entire instruction class (shf/prmt bookkeeping) from the innermost issue-bound loop.
  • Engineering honesty throughout: trap-on-exceed SMEM model, residency checks that reject rather than deadlock, exactly-one PTX assertions, build-time codegen validation.
  • Evaluation controls the right confound — identical quantized inputs and routes; cross-operator cosine isolates operator error from quantization error.

04 Limitations

  • Advantage compresses to 1.02–1.19× at B=256, where every operator is HBM-bound on the weight stream — the named open problem.
  • Only two model shapes, one hardware setup; no dispatch-SM-split sweep; adaptive-geometry tier boundaries exercised at just a handful of points.
  • No per-mechanism ablations — pull cache, mirrored metadata, relay vs direct return only contrasted through aggregate rate tables.
  • Occupancy-critical PTX rewrites are coupled to ptxas 13.2 behavior; a compiler update forces revalidation (asserted, but a maintenance hazard).
  • No public code or artifact link; assumes one shared expert, single-node PCIe; constraint range (H ≤ 8192, k ≤ 32) excludes some MoE configs.

05 Questions for further exploration

  1. How much of the 1.387× average survives on true consumer SM120 parts (fewer SMs, 16–24 GB VRAM) where the ≥32-SM compute partition and 256 MB relay arena may not fit?
  2. What is each mechanism's isolated contribution — pull cache, mirrored metadata, relay copiers, compact weights, shared-expert fusion?
  3. Can the return tail fold into the finalize kernel, freeing copier CTAs and recovering the B=256 GLM5.2 point currently tied with Cake?
  4. Would a learned or searched geometry policy beat the hand-derived tiers for shapes between the two tested (e.g., H=4096, k=4, uneven E/R)?
  5. Does the design hold on multi-node fabrics under uneven expert load, and does swap-AB generalize to SM100/SM110 fallbacks or attention-style dynamic extents?
