> **一句话总结：** 本文通过成对对照实验证明，依赖前缀缓存的 LLM Agent 服务存在亚稳态失效——一次仅 5 分钟的流量突发就能让 vLLM 服务器永久跌入约 10% 命中率、吞吐减半的退化状态（12 对实验中 9 对），且入口限流几乎无法恢复（7 次中仅恢复 1 次），而在回合边界挂起（park）已接入会话、按 KV 池容量限制常驻需求的 budgeter 能在 5 分钟内恢复全部 17/17 次崩溃并完全预防失效。

> **TL;DR:** Using paired runs that share an identical base arrival stream, the authors show that a 5-minute burst (+1.5λ) pushes a vLLM 0.20 server running Qwen3-8B on an AMD MI300X into a persistently degraded regime — prefix-cache hit ratio collapses from 0.94–0.95 to ~0.10–0.12, turn throughput falls from ~1.27 to ~0.4 turns/s (about half), and the session backlog grows past 100 for the remaining 70 minutes, while the no-burst twin stays healthy (9 of 12 pairs, sign test p = 0.00391; 0 reversals). The effect reproduces with Qwen3-32B replaying mini-SWE-agent trace shapes on SWE-bench Verified and on SGLang 0.5.22 (all 4 paired burst runs degraded at hit ratio 0.09–0.11 vs 0.93–0.95 for twins), is absent when prefix caching is disabled, and matches cache-disabled throughput (0.35–0.46 vs 0.33–0.43 turns/s) — i.e., a working-set thrashing loop rather than ordinary overload. Admission throttling alone recovered only 1 of 7 matched collapsed runs; a gateway "budgeter" that parks admitted sessions at turn boundaries to hold resident KV demand within 0.75–0.95 of the pool recovered 7/7 in under 5 minutes (17/17 across all experiments) and prevented collapse in every run tested.

## 核心贡献

- **现象的受控证明（同负载、不同历史结局）**：成对运行共享完全相同的基础到达流，仅在分钟 15 注入 5 分钟 +1.5λ（总计 2.5×）的突发。12 对 vLLM/Qwen3-8B 实验中 9 对出现"仅突发侧持续退化"（命中率 ~0.10–0.12、吞吐约减半、积压持续增长 70 分钟），反向为 0 对（符号检验 p = 0.00391）——这是亚稳态失效的直接证据，而非普通过载。
- **机理刻画（工作集颠簸的 Agent 服务版）**：闭环会话数服从 Little 定律 N = λT(Z+R)，服务变慢 → 在系统会话增多 → 前缀工作集超出 KV 池 → LRU 在下一回合前逐出各会话前缀 → 每回合全量重算 → 服务更慢。退化态中 99.6–100% 的回合缓存不足一半，吞吐（0.35–0.46 turns/s）与关闭缓存引擎（0.33–0.43 turns/s）持平。
- **可排空性的一阶判据**：独立标定冷预填成本 c(L) = −0.06 s + 0.146 ms × L（在禁缓存运行上回归得到），推出退化态可排空条件 λ < 1/S ≈ 0.013 会话/秒；实测崩溃后降载，积压在 λ=0.006 下降、λ=0.014 增长，收支平衡点 0.010–0.014 恰好括住模型预测。
- **恢复与预防的对照评估**：同一执行器（回合边界挂起）下比较五种控制器——budgeter（按 KV 池容量的滞回带限制常驻需求）7/7 在 5 分钟内恢复且 17/17 全实验无失手；会话上限+挂起 7/7（≤6 分钟）；延迟 AIMD 5/7（14–25 分钟）；仅限流新接入 1/7（21–23 分钟）；无控制 0/8。budgeter 从头启用时在所有触发下 0 次崩溃（含 32B + SWE-bench 轨迹）。
- **跨引擎、跨模型、真实轨迹的泛化**：现象在 Qwen3-32B（SWE-bench Verified 的 mini-SWE-agent 轨迹回放）与 SGLang（RadixAttention，需更大触发，4/4 成对运行退化）上复现；CPU 卸载层（128 GiB）只能把崩溃推迟到 40–60 分钟，不能消除。

## Key Contributions

- **The phenomenon, controlled.** Paired runs share every base session and differ only in a 5-minute injected burst (+1.5λ, 2.5× total arrivals) at minute 15. On vLLM 0.20 with Qwen3-8B, 9 of 12 pairs show persistent degradation on the burst side only (hit ratio ~0.10–0.12, ~half throughput, backlog growing for the remaining 70 minutes) versus healthy twins (0.94–0.95 hit ratio); zero pairs degrade in the reverse direction (two-sided sign test p = 0.00391). This isolates history dependence from load.
- **Mechanism: working-set thrashing for closed-loop agents.** Agent sessions are closed loops, so concurrent sessions N = λT(Z+R) grows with response time (Little's law). Slower service enlarges the resident working set beyond the KV pool; LRU evicts each session's prefix before its next turn; every turn becomes a full recomputation of a 10–40K-token context, slowing service further. In the degraded regime 99.6–100% of turns had less than half their prompt cached, KV usage sat at 83–100%, preemptions were rare (23–37 per 90-minute run), and throughput matched the cache-disabled engine — recomputation, not thrash on preemption.
- **A calibrated drain condition.** With per-miss cost c(L) regressed independently on cache-disabled runs (c(L) = −0.06 s + 0.146 ms × L, so a session costs S ≈ 78 s of cold work), the degraded regime can drain only if λ < 1/S ≈ 0.013 sessions/s. Empirically collapsing the server and lowering λ: backlog falls at 0.006, is flat at 0.010, grows at 0.014/0.018 — a measured break-even of 0.010–0.014 bracketing the model, well below the loads (≥0.035) where collapse occurs.
- **Recovery requires suspending admitted sessions, not just shedding new load.** All controllers share one gateway actuator (park sessions at turn boundaries into a FIFO queue). On 7 seeds collapsed in every arm: budgeter (park when resident KV demand D > 0.95C, admit while D + d ≤ 0.75C) recovered 7/7 in <5 min with 0.93–0.95 end hit ratio; session cap + park 7/7 in ≤6 min; latency AIMD + park 5/7 in 14–25 min; admission-only cap 1/7 (2/8 over all seeds, 21–23 min); no control 0/8. Across 8B, 32B, and threshold-sensitivity experiments the budgeter recovered 17 of 17 collapsed runs (paired p = 0.031 vs admission-only).
- **Generality and negative results.** The regime reproduces on Qwen3-32B with its full auto-sized pool replaying real SWE-bench Verified agent trace shapes (200 mini-SWE-agent trajectories, six 2026 frontier models) and on SGLang 0.5.22 (absorbs a 2×/2-min burst that collapses vLLM, but all 4 paired runs degrade at +1.5λ: hit ratio 0.09–0.11 vs 0.93–0.95 for twins). It is absent without prefix caching and prevented (0/10) by a session cap below pool capacity. A 128 GiB CPU KV offload tier only delays collapse from minutes 20–25 to 40–60 (4 of 6 paired burst runs still end degraded).

## Methodology

The paper runs controlled experiments on vLLM 0.20 (ROCm build) on single AMD MI300X GPUs, one engine per GPU, BF16 weights/KV, chunked-prefill FCFS scheduler, 40K max context, prefix caching on. The main configuration serves Qwen3-8B (144 KiB KV per token) with the KV pool fixed at 400K tokens (59 GB); a second configuration serves Qwen3-32B with the pool auto-sized at 80% GPU memory (≈365K tokens).

Workloads: (1) synthetic closed-loop sessions — Poisson arrivals, 2K shared system prompt + 4K unique task, 25 turns × 300 output tokens + 1K tool tokens, exponential think time (mean 5 s), contexts growing 6K→37K, random token content so reuse is only exact-prefix; (2) trace-shape replay of 200 real trajectories from public mini-SWE-agent leaderboard runs on SWE-bench Verified (six 2026 frontier models; median 42 calls/session, 16K median per-call context, truncated at 38K, removing 14% of turns), with unique task suffixes per session.

The core design is **paired runs**: both arms share one base arrival stream (same sessions, same times); the burst arm adds +1.5λ for 5 minutes at minute 15, so offered load after the burst is identical. Endpoints: token-weighted prefix hit ratio, turn throughput, sessions in the system, and arrival-cohort completion; a run is "persistently degraded" if every 5-minute window from the first degraded window (hit ratio < 0.5) to the end stays degraded. Controls isolate the cause: cache-disabled runs at matched sub-capacity load, session caps below pool capacity, cache-flush triggers, and no-burst twins. The mechanism is analyzed via a first-order workload-balance condition (drain iff λ < 1/S) with the per-miss cost c(L) calibrated independently on cache-disabled runs. Recovery and prevention are evaluated with five controllers built on one gateway actuator — park a session at a turn boundary into a FIFO queue, re-admit parked before new — differing only in the limit: budgeter (resident KV demand D in a 0.75C/0.95C hysteresis band), fixed session cap, EWMA-adaptive cap (K = ⌊0.95C/d̂⌋), latency AIMD, and admission-only cap. Thresholds 0.75/0.95 were fixed before experiments, not tuned.

## Results & Highlights

- **History dependence (8B paired runs):** at λ = 0.035 sessions/s (~70% of the cache-warm capacity ≈ 0.05 sessions/s), the 5-minute +1.5λ burst left 9 of 12 pairs persistently degraded — burst-arm hit ratio 0.10–0.12 vs no-burst twin 0.95 (e.g., seed 501: 0.12 vs 0.95; sessions in system 109 vs 8), with turn throughput ~0.4 turns/s vs the ~1.27 turns/s the engine sustains warm, and backlogs of 109–175 sessions vs 5–9 (sign test p = 0.00391, 0 of 12 reversals).
- **Not ordinary overload:** with prefix caching disabled at ~80% of no-cache capacity, the same absolute burst (≈16 extra sessions) produced backlogs of 17–43 that drained in every run; with a session cap below pool capacity, 0/10 burst runs degraded; 10 of 10 runs at λ = 0.04 with no burst stayed healthy for 30 minutes. In 7 of 11 degraded burst runs all injected sessions had already finished, yet the hit ratio stayed at 0.10–0.12.
- **Degraded regime = cache-off throughput:** degraded-run turn throughput 0.35–0.46 turns/s vs 0.33–0.43 turns/s for the same engine with caching disabled; 99.6–100% of completed turns (last 10 minutes) had less than half their prompt cached; the 0.10–0.12 residual hit ratio is exactly the shared system prompt.
- **Drain condition calibrated and validated:** c(L) = −0.06 s + 0.146 ms × L (fit on 48 cache-disabled windows) gives S ≈ 78 s and 1/S ≈ 0.013 sessions/s; measured backlog drift after collapse was ≈ −900 engine-s/hour at λ = 0.006, roughly flat at λ = 0.010 (−67 to +132/h), and +604/+663/h at λ = 0.014 — break-even 0.010–0.014, and no collapsed run's cache re-formed within 2 hours of observation.
- **Real traces and a second model:** Qwen3-32B with its full ≈365K-token pool replaying SWE-bench agent trace shapes at λ = 0.025: a 4-minute 2× burst left 1 of 4 runs persistently degraded and a second partially (end hit ratio 0.34/0.81) vs 0.95–0.97 for all four no-burst runs; at λ = 0.03 all runs degraded even without a burst (0.12–0.17), so 32B history-dependence evidence rests on λ = 0.025.
- **Second engine:** SGLang 0.5.22 absorbed the 2×/2-minute burst that collapses vLLM (4/4 runs, dips only to 0.27–0.29 in 1-minute windows, recovered in minutes), but the paired +1.5λ/5-minute burst degraded all 4 burst runs (hit ratio 0.09–0.11, backlog 52–112 sessions) while all 4 twins stayed at 0.93–0.95.
- **Recovery (8B, control switched on at minute 20, 7 seeds collapsed in every arm):** budgeter 7/7 recovered in <5 min (end hit ratio 0.93–0.95, 100% of the next-20-minute cohort completed); session cap + park 7/7 in ≤6 min; latency AIMD + park 5/7 in 14–25 min; admission-only cap 1/7 (2/8 overall, 21–23 min; four runs stayed below 0.1 hit ratio); no control 0/8 (0.12–0.13, cohort 0%). Across all recovery experiments the budgeter recovered 17/17 collapsed runs (paired p = 0.031 vs admission-only).
- **32B recovery:** at λ = 0.025 with a 3×/5-min trigger, no control left every run degraded (hit ratio 0.12–0.13, 142–175 sessions); the budgeter restored 0.92–0.97 hit ratio and completed 54–96% of the following 20-minute cohort (adaptive cap: 0.86–0.93, 83–97%) vs 0–7% without control — though the queue kept growing because this trace mix (1.5–1.6 arrivals/min vs 0.7–1.3 completions/min) slightly exceeds warm capacity.
- **Session-mix shift (no burst):** short→long session shift at minute 30 degraded the uncontrolled server in 2/2 seeds (end hit ratio 0.08); fixed caps of 22/34 collapsed like no control (4/4) while caps of 10/14 over-throttled the short phase (p90 first-turn gateway wait 0.7–13 min); the budgeter and adaptive cap collapsed 0/4 with no first-phase gateway wait and completed every session from the first 60 minutes.
- **Prevention and offload:** budgeter from the start: 0/5 collapsed under a 2×/2-min burst, 0/3 under a cache flush, 0/4 under 32B + SWE-bench traces; thresholds moved from 0.75/0.95 to 0.65/0.85 or 0.85/0.98 changed nothing. CPU offload (128 GiB, ≈0.9M tokens): 4 of 6 paired burst runs still ended degraded (hit ratio 0.12, 116–136 sessions) — collapse delayed from minutes 20–25 to 40–60, not prevented.

## Authors & Credibility

Wen Huang is at Microsoft; Jack Liu is an independent researcher. The work is a preprint (arXiv, 10 Nov 2026, cs.DC). Credibility signals are strong for a systems paper: paired-run experimental design with shared arrival streams and a two-sided sign test (p = 0.00391) rather than anecdotal single runs; an exact paired test (p = 0.031) for controller comparisons; a mechanism (per-miss cost c(L)) calibrated on independent cache-disabled runs and then validated against measured backlog drift; negative controls (cache off, session cap, no-burst twins) that rule out ordinary overload; replication across two engines (vLLM, SGLang), two models (Qwen3-8B, Qwen3-32B), and both synthetic and real SWE-bench-derived trace shapes; and a candid threats-to-validity section. The paper includes an explicit AI-usage disclosure: the authors designed and led the research and verified all numbers, with AI assistants (Claude, Codex) assisting with related-work checks, code, runs, figures, and writing. Limitations of provenance: no production deployment evidence, one GPU type (MI300X), single replica, and the 32B configuration sits close enough to its capacity edge that some no-burst runs degrade spontaneously.

## Critical Assessment

- **Novelty:** The feedback loop itself is not claimed as new — CONCUR, MISA-T, VAMP, and KAIROS have all observed cache-efficiency collapse in agentic serving, and the authors say so plainly (Table 4). The genuine novelty is the *paired same-load history-dependence design* (identical post-trigger load, different outcome), the measured drain condition, and the controlled comparison of *recovery of already-admitted sessions*, which none of the prior systems evaluated. This is an honest, well-scoped incremental contribution.
- **Rigor:** Generally high (paired runs, sign tests, independent calibration, controls), with two soft spots. First, the 32B evidence is weaker than the abstract implies: at λ = 0.03 all runs degrade without any burst and one no-burst run degraded on its own after ~55 minutes, so 32B history dependence rests on the single λ = 0.025 configuration with 1 of 4 runs persistently degraded and one partial. Second, the paper infers rather than measures eviction-driven misses ("the engine does not export per-block eviction events") — the working-set story is consistent with the demand/pool curves but the causal eviction chain is not directly instrumented.
- **Reproducibility:** Good on method detail (engine versions, pool sizes, λ values, thresholds fixed pre-experiment, per-seed tables) but the gateway controller and closed-loop driver are not released as far as the paper states, and results depend on a specific ROCm build (0.20.2rc1.dev253) whose scheduler behavior may not match upstream vLLM others run.
- **Significance:** Operationally relevant: it shows that restarts/weight updates (cache-flush triggers) are themselves collapse risks, that GPU-utilization and latency alarms misdiagnose the regime, and that admission throttling — the default operator reflex — is nearly useless once collapsed (1/7). The practical takeaway (bound resident KV demand, park at turn boundaries) is actionable at gateways without engine changes.
- **Red flags / overclaims:** The abstract's "prevented the failure in every run we tested" is accurate but the tested trigger matrix is modest (5 + 3 + 4 prevention runs); the Poisson escape-time model being off by an order of magnitude is disclosed but leaves entry dynamics unquantified; workload realism is limited — synthetic sessions use random tokens, trace replay preserves lengths/timing but not content and truncates at 38K tokens, while real production contexts (TraceLab median per-call 136K) would lower N* and worsen the miss penalty, a direction the authors flag as unmeasured; and the 32B recovery queues never drained (arrivals 1.5–1.6/min vs 0.7–1.3 completions/min), so queue-stability evidence comes only from the 8B setup.

## Strengths

- The paired-run design (shared base arrival stream, arms differing only in the burst) is the cleanest demonstration of metastability in LLM serving to date — it converts an anecdote ("the server got slow after a spike") into a statistically tested, history-dependent phenomenon with 0 of 12 reversals.
- Mechanistic depth: the loop is traced through Little's law, per-miss cost calibration, and a validated drain bracket (0.010–0.014 measured vs 0.013 predicted), connecting Denning's 1968 working-set thrashing theory to modern prefix-cached serving.
- The controller study isolates exactly one variable (the limit) over a shared park-at-turn-boundary actuator, making the comparison fair and the conclusion crisp: parking admitted sessions against a capacity-derived limit recovers what admission throttling cannot (7/7 + 17/17 vs 1/7).
- Practical, immediately deployable remedy: the budgeter needs only the engine-reported pool size C and two pre-fixed thresholds (0.75/0.95), with demonstrated insensitivity to threshold choice and automatic adaptation to session-mix shifts that break fixed session caps.
- Honest framing throughout: explicit non-claims of novelty for the loop and admission control, a Table 4 comparison against prior systems, disclosure of spontaneous-degradation twins, an order-of-magnitude model miss, and an AI-usage disclosure.

## Limitations

- No production evidence: one GPU type (MI300X), one replica, no routing/autoscaling/client retries, finite observation windows (70–120 minutes); production contexts (TraceLab median per-call context 136K, median starting context 19K) are longer than anything tested and would tighten the failure margin.
- The 32B configuration operates close to its capacity edge — at λ = 0.03 all runs degrade with no trigger, and no-burst runs degrade spontaneously — so cross-model generality of *history dependence* (as opposed to the collapse regime itself) leans heavily on the 8B results and the 32B λ = 0.025 runs.
- Trace replay preserves session shapes but not token content (unique random suffixes per session), truncates at 38K tokens (removing 14% of turns), and does not execute real agents, so cross-session prefix sharing — which would change hit-ratio dynamics — is absent.
- Eviction behavior is inferred, not measured: vLLM does not export per-block eviction events, so the claim that misses come from prefixes evicted between turns rests on aggregate demand/pool and hit-ratio curves.
- The 32B recovery experiments end with queues still growing (the trace mix slightly exceeds warm capacity), so controllers restore efficiency but the long-run queue-stability question is answered only on 8B; engine-side alternatives (session-aware eviction, prefix-resident scheduling) are discussed but not tested.

## Relevance

（对"LLM 服务系统 / Agent 推理基础设施"方向高度相关：）本文精确刻画了 Agent 多轮会话 + 前缀缓存服务中的亚稳态失效机理，并给出无需逐负载调参、可部署在网关侧的 KV 需求 budgeter 预防与恢复方案——对设计 Agent 推理集群的调度、准入控制与容量规划（如何按 KV 池而非 QPS 估算安全负载）有直接指导意义。

## Questions for Further Exploration

- How does the collapse threshold move with real cross-session prefix sharing (shared system prompts, tool-result templates, multi-tenant coding agents), which the random-token synthetic workload and unique-suffix trace replay both exclude?
- Can session-aware eviction or prefix-residency-aware scheduling inside the engine raise the trigger threshold as much as gateway parking, and at what fairness cost to new sessions?
- Does the metastable regime appear in prefill–decode disaggregated serving tiers beyond the concurrent Lu et al. (2026) observation (88% goodput cut), and does the budgeter need to become a distributed controller across prefill replicas?
- What is the quantitative entry dynamics: the Poisson fluctuation model was off by an order of magnitude — is a CTMC or fluid model calibrated on escape times from the healthy regime tractable?
- With production-length contexts (100K+ per call), does N* = C/L̄ shrink so far that even modest interactive concurrency is unstable without hierarchical KV storage, and can faster offload paths (GPU-direct, NVLink) push the threshold meaningfully above the 128 GiB CPU tier tested here?
