> **一句话总结：** 把 89 个已发表的 ML 系统算法(KV-cache 驱逐、权重剪枝、投机解码)改写为 Lean 验证的"证明图"、把算法的隐含假设显式化,再让 LLM 每次只放松一个假设并重新证明与生成代码;该搜索在 KV-cache 驱逐上得到 RULER-4K 75.7 分(最佳已发表方法 KVGrad 为 74.1)、在 LLaMA-7B 50% 稀疏度剪枝上得到 WikiText-2 困惑度 6.78(母算法 Pruner-Zero 为 6.89),两个领域均超越所有被测已发表算法。

> **TL;DR:** MIT CSAIL proposes AutoAssumption, an LLM harness that formalizes 89 published ML-systems algorithms as Lean-checked proof graphs (nodes = assumptions/definitions/theorems) and discovers new algorithms by relaxing ONE assumption at a time, re-proving only the dependent theorems. The discovered eviction algorithm RestoreKV-GM scores 75.7 on RULER-4K (2×–64× compression, Llama-3.1-8B-Instruct + Qwen3-8B) vs 74.1 for the best published baseline KVGrad, and the pruner Pruner-Zero-LG reaches WikiText-2 perplexity 6.78 on LLaMA-7B at 50% sparsity vs 6.89 for Pruner-Zero, best of 13 pruners on four LLaMA models. At equal budget the harness lands 0.4 points below OpenEvolve (79.3 vs 79.7) and 0.8 above AIDE on the same search task, with the smallest variance across repeats. The speculative-decoding variant is competitive but not state of the art.

## 核心贡献

- **假设是算法设计的产出单元**:论文观察到 ML 系统的每次重大突破往往来自推翻一个先前方法默认的隐含假设(投机解码打破了"每个 token 需要大模型一次前向",PagedAttention 打破了"KV cache 必须连续");在 KV-cache 驱逐领域,H2O 之后的 7 个记录中有 5 个引入了新假设(图 2)。而已有专家与 LLM 发现框架(AlphaEvolve、OpenEvolve、AIDE)都在**代码层**搜索,一次编辑同时改动多个设计决策,增益难以归因。
- **证明图(proof graph)形式化**:把每个算法写成有向无环图——节点是假设 A、定义 D、定理 T,边是引用,终点是问题陈述 P;只有 Lean 完整检查通过(无未证明步骤)才算数。配套"覆盖测试"把代码的每一行映射到证明中的某条陈述。89 个算法(44 个 KV-cache 驱逐、26 个投机解码、19 个剪枝)全部被形式化,假设合并成一个可追溯回每篇论文的假设池。
- **假设级搜索 harness(AutoAssumption)**:对母算法一次只做一个"假设动作"(放松或加强,理想情况带一个能复原母算法的"旋钮"参数),只重推重证受影响集合内的定理,再生成代码、跑基准;变体在上 GPU 前必须与所有已知算法不同、且在旋钮复原值处复现母算法。由此每个改动都可解释、可归因、可被证明检查。
- **两个新的 SOTA 算法 + 一个有竞争力的解码器**:RestoreKV-GM(KV-cache 驱逐)与 Pruner-Zero-LG(剪枝)在每个被测已发表算法之上;SVIP-LK(投机解码)保持精确性证明的同时在 batch 1 比 SVIP 快 4%。
- **副产品——形式化语料与正确性审计**:26 个投机解码算法的 Lean 证明为其中 8 个已发表解码器确立了精确性(exactness),其中 5 个此前只声称未证明;注错实验中 Lean 证明检查抓出 56/56 个突变体(0 误报),而基准分数只发现 53.6%(10% 误报)。

## Key Contributions

- Reframes algorithm discovery: assumptions, not code, are the productive unit of design. Both human experts and code-evolution harnesses (AlphaEvolve/OpenEvolve, AIDE) edit programs where one edit entangles several design choices; AutoAssumption makes each algorithm's assumptions explicit by writing it as a Lean-checked proof, so one change = one attributable, auditable design decision.
- Proof-graph formalization of 89 published algorithms across three ML-systems fields (44 KV-cache eviction, 26 speculative decoding, 19 weight pruning), with a coverage test that maps every line of an algorithm's code to a statement in its proof, and a merged pool of assumptions pointing back to every source paper.
- An automated three-stage harness: (1) identify the shared problem of a field from its benchmark and citation network; (2) formalize each algorithm in Lean (code as source of truth, paper as guide); (3) relax/strengthen one assumption of a parent, re-derive and re-prove only the impact set, generate code, benchmark, and iterate to form search chains.
- Two new state-of-the-art algorithms (RestoreKV-GM for KV-cache eviction, Pruner-Zero-LG for LLM weight pruning) plus a competitive exact speculative decoder (SVIP-LK), each exactly one assumption away from a published parent.
- Evidence that assumption-level search matches code-level search: at equal model/evaluator/budget it finishes 0.4 points below OpenEvolve and 0.8 above AIDE on a RULER-4K search task, with lower variance across repeats; and Lean proofs detect 100% of injected bugs where the benchmark score detects only 53.6%.

## Methodology

**Proof graphs (Section 2.1).** An algorithm is cast as a DAG whose nodes are assumptions A (what the argument takes as given), definitions D (what the program computes) and theorems T (what derives that the program solves the problem statement P); edges are citations. The worked example is speculative sampling (Leviathan et al., 2023; Chen et al., 2023): from assumptions such as "target and drafter are distributions over the same vocabulary", the graph defines one accept-or-resample step, proves the emitted token has the target's law, and derives expected tokens per target pass. A proof counts only if Lean (de Moura & Ullrich, 2021) checks it completely.

**Stage 1 — problem identification.** Starting from a field's benchmark (KVPress, Spec-Bench, the SparseGPT/Wanda protocol), the harness traces citation networks; a human keeps relevant, runnable algorithms; each is rewritten as one self-contained Python file that must reproduce the benchmark's reported scores (or, for ported algorithms, some of the paper's own results). An LLM then proposes one problem statement all of them can be proved to solve.

**Stage 2 — formalization.** One agent receives an algorithm's folder (code, scores, paper), verifies the code by hash, and writes a proof document with one definition per logic line, ending in a main theorem that the code meets the contract; a coverage test checks every code line is covered. A second agent transcribes the document into Lean and proves it. For speculative decoding this yielded proofs of exactness for 8 published decoders, 5 of which had claimed it without proof.

**Stage 3 — changing assumptions.** An agent receives a parent's code, proof, scores and the assumption pool, and makes ONE move on ONE assumption (relax: drop, weaken, or replace with another algorithm's answer from the pool; or strengthen), ideally with a "dial" parameter whose recovering value reproduces the parent. The new assumption and hypothesis are written before any code; before any GPU time the variant must be novel and, if it has a dial, reproduce the parent at the recovering value. Its proof is the parent's edited only within the impact set of the changed assumption. Benchmark scores then guide the next parent/assumption choice, forming a search chain.

**Experimental setup.** KV-cache eviction on RULER-4K in KVPress (13 tasks, 6,500 questions; Llama-3.1-8B-Instruct and Qwen3-8B; 2×–64× compression; ±1 SD over 10,000 paired bootstrap resamples), plus held-out RULER-8K/16K and LongBench, with TTFT/peak-memory profiling on dedicated H100s. Weight pruning under the SparseGPT/Wanda protocol on LLaMA-7B/13B/30B and LLaMA-2-7B (10–50% unstructured sparsity, 128 C4 calibration windows of 2,048 tokens, fp16; WikiText-2 test perplexity divided by the dense model's). Speculative decoding on Spec-Bench (480 questions, Vicuna-7B-v1.3 target + vicuna-68m drafter, and Llama-3.1-8B-Instruct + Llama-3.2-1B-Instruct) with paired timing on dedicated H200s. The harness comparison (Q2) runs OpenEvolve, AIDE, Fable-from-scratch and AutoAssumption from the same parent (RestoreKV), same model (Fable 5.1, high reasoning effort), same evaluator (200 subsampled RULER-4K questions) and budget (10 benchmarked algorithms), 3 repeats each.

## Results & Highlights

- **KV-cache eviction, main benchmark:** RestoreKV-GM scores 75.7 on RULER-4K (mean task accuracy averaged over Llama-3.1-8B-Instruct + Qwen3-8B and 2×–64× compression) vs 74.1 for KVGrad, the best published algorithm run — +1.6 points. Per model it leads 77.0 vs 75.4 (Llama) and 74.5 vs 72.9 (Qwen); the largest gains over its parent RestoreKV come at 16×–32× compression, up to +12.0 points.
- **KV-cache eviction, generalization beyond the 200-question search set:** on all 6,500 RULER-4K questions RestoreKV-GM beats its parent by +3.1 (Llama) and +2.4 (Qwen) points; at longer unseen contexts by +3.1 (8K) and +3.3 (16K) points; on LongBench (16 English tasks, 3,750 questions) by +1.5 points. Its time-to-first-token is 1.03× the parent's (not significant, p = 0.69) with identical peak GPU memory.
- **Weight pruning, main benchmark:** on WikiText-2 at 50% unstructured sparsity, Pruner-Zero-LG reaches 6.78 perplexity on LLaMA-7B vs 6.89 for its parent Pruner-Zero (best published; dense = 5.68), i.e. 1.195× the dense model vs 1.213×. It is the best of 13 pruning algorithms on all four LLaMA models (5.83 vs 5.93 on 13B, 4.93 vs 5.02 on 30B, 6.67 vs 6.71 on LLaMA-2-7B) and at every sparsity from 10% to 50% (tied at 10%), while pruning LLaMA-7B faster (48 s vs 53 s).
- **Speculative decoding (competitive, not SOTA):** SVIP-LK attains a 1.46× speedup over autoregressive decoding on Spec-Bench at batch 1, T = 0, vs 1.37× for its parent SVIP (1.31 vs 1.30 at T = 1), retains its exactness proof, and is the fastest plain-Python decoder run (only custom-kernel/forked implementations are faster). Pooled over batch sizes 1–16 it is 2.3% faster per output token than SVIP (90% CI 2.0–2.6%), though 11.7% slower at batch 32.
- **Harness comparison (equal model/evaluator/budget, 3 repeats):** after 10 evaluated algorithms AutoAssumption reaches 79.3 best-so-far RULER-4K score vs 79.7 for OpenEvolve, 78.5 for AIDE and 71.4 for Fable-from-scratch, with the narrowest repeat spread (1.3 points vs 2.5 and 7.1). Code-level harnesses jump early (after 2 algorithms: 76.1 and 75.4 vs 70.7) then add only 3.6/3.1 points over the remaining eight; AutoAssumption rises almost every step, +8.6 points over the same stretch.
- **Every parent got a better variant:** across 26 published parents (11 eviction, 7 pruning, 8 speculative decoding), the harness found a variant scoring higher than its parent on the field's search benchmark (smallest gains within benchmark noise).
- **Proof checks vs benchmarks (Appendix I.2):** on 14 realistic code mutants of 5 verified eviction algorithms, the Lean proof check flagged 56/56 mutant evaluations with 0/20 false alarms on 5 controls; the benchmark score flagged only 30/56 (53.6%) with 2/20 (10%) false alarms — some bugs even raised the score by silently exceeding the memory budget.

## Authors & Credibility

All four authors (Igor Sadalski, Minghao Guo, Benjamin Jones, Wojciech Matusik) are at MIT CSAIL; Matusik's group has a strong track record in ML-systems optimization and automated design (the related Axiomatic Atlas by Guo & Matusik is cited as the closest prior work). This is a preprint (arXiv, 10 Nov 2026), 52 pages with unusually thorough appendices: reproduction procedures for every external baseline (A.1), full hardware/software/checkpoint tables (Table 4), per-figure error-bar derivations (Appendix G), all 89 formalized algorithms (Appendix F), the Lean proof of speculative sampling in full (Appendix H), and prompt templates for every agent stage (Appendix D). Results are stated with explicit uncertainty (paired bootstrap SD/SE, three repeats with min–max), and negative results (the 64×-compression case where KVGrad leads by 0.8 points; the batch-32 slowdown of SVIP-LK) are reported rather than hidden. The formalization itself produced independent value: Lean proofs of exactness for 8 published decoders, 5 previously unproven.

## Critical Assessment

- **Novelty: high.** Searching over explicitly stated assumptions with a Lean-auditable proof per algorithm is a genuine departure from code-level evolution harnesses (AlphaEvolve/OpenEvolve, AIDE) and from one-algorithm-at-a-time formalization efforts (ProofLoom, SampCert, Algorithmist). The assumption pool shared across a field and the impact-set-limited re-proof (akin to proof repair) are the new ingredients; framing records as assumption changes (Figure 2) is a compelling motivation.
- **Rigor: mostly strong, with one soft spot.** Held-out evaluation is done properly (search on 200 questions, confirmation on all 6,500; unseen 8K/16K contexts, LongBench, and second/third/fourth models for pruning), and cost/latency claims come with significance tests and CIs. However, every pruning cell in Table 9/10 is a single seed-0 run — no calibration-seed variance is reported, and the SparseGPT/Wanda protocol is known to be seed-sensitive; the headline 6.78-vs-6.89 margin (1.6%) could partly be seed noise. The zero-shot accuracy table shows all pruners far below dense (means ~53–57 vs 60.4), so absolute quality loss at 50% sparsity remains large even for the winner.
- **The harness comparison is narrow.** One LLM (Fable 5.1), one parent (RestoreKV), one benchmark (RULER-4K), budget of 10 evaluated algorithms, 3 repeats. The claim "matches code-level harnesses with lower variance" is plausible but rests on a single task; the ranking of code-level harnesses could look different with other models or parents. The searched metric itself (mean over 12 cells) also slightly favors methods that are robust across the sweep — which happens to be their selling point.
- **Not fully automated.** Stage 1 requires a human to curate algorithms from citation networks, and the authors honestly note Lean checks a proof against the problem statement, not the statement against the field — so contract validity still depends on human review. The 89-algorithm corpus was expensive to build; the paper does not state a public code/Lean-corpus release.
- **Interpretation of "state of the art."** The claim is carefully worded as "every published algorithm we ran" — and they did run strong, very recent baselines (KVzip+, EchoPress, OBCache, KVGrad from 2025–26; Z-Pruner, RIA, DSnoT for pruning) — but the two winning algorithms are each a single-assumption perturbation of an equally recent parent (RestoreKV 2026, Pruner-Zero), so the per-field gains are incremental (+1.6 RULER-4K over KVGrad; −0.11 perplexity over Pruner-Zero), not category shifts.
- **Red flags: none serious.** Exceptions are disclosed (KVGrad leads by 0.8 points at 64× on Llama; SVIP-LK 11.7% slower at batch 32), and the assumption pool's non-canonicity — an LLM chooses how to split an algorithm into assumptions, and pool stability across repeated formalizations was not measured — is acknowledged as an open limitation.

## Strengths

- Turns algorithm design into a search over a small, structured, machine-auditable space; every accepted change is attributable to one named assumption and comes with a Lean-checked proof before any GPU time is spent.
- Empirically consequential, not just conceptual: two fields improved beyond every strong published baseline they ran, with generalization checked on question supersets, longer contexts, another dataset, and more models than the search saw.
- The mutant study (Lean 100% detection vs benchmark 53.6%) is a crisp, quantified argument that proof checks catch what benchmark scores miss — including bugs that raise the score by silently breaking memory budgets.
- At equal budget the harness is competitive with OpenEvolve/AIDE while improving more steadily and with far lower variance across repeats, supporting the paper's central hypothesis.
- Exceptional reproducibility documentation: reproduction protocol per external method, hardware/version/checkpoint tables, error-bar derivations, full prompt templates, and complete results tables for all 89 algorithms and all variants.

## Limitations

- Formalization needs a human reader: Lean verifies proofs against the stated problem, not the statement against the field's actual meaning (authors' own limitation #1).
- Only what mathematics can represent is provable — memory usage and sampling exactness yes; training dynamics and answer quality no, so benchmarks remain the only oracle for the quality-relevant half of each contract (limitation #2).
- Assumptions are not canonical: the LLM chooses the decomposition, some assumptions admit several granularities, and stability of the assumption pool across repeated formalizations is unmeasured (limitation #3).
- Single-seed pruning runs; pruning gains are modest in absolute terms; speculative decoding did not reach state of the art (SVIP-LK beats only its parent, and is slower at batch 32).
- The harness comparison covers one model/parent/benchmark/budget configuration; corpus construction (89 algorithms) is labor-intensive and the paper does not report a public release of code or the Lean corpus.

## Relevance

该论文是"Self-Evolving Agents & Automated Research"方向的典型工作:用 LLM 智能体驱动自动算法发现,但以 Lean 形式化证明替代纯代码进化作为搜索与审计单元,直接对应自动化科学发现与自主研究闭环的兴趣;同时其三个应用领域(KV-cache 驱逐、权重剪枝、投机解码)都属于 LLM 推理效率优化,证明检查能在基准分数无法发现的真实缺陷(100% vs 53.6% 检出率)这一点也与推理栈可靠性的关注点相呼应。

## Questions for Further Exploration

- How stable is the assumption pool across repeated independent formalizations of the same 89 algorithms, and would a different decomposition suggest materially different variants?
- Does the harness-comparison ranking (AutoAssumption ≈ OpenEvolve > AIDE) hold with other backbone LLMs, other parents, and larger budgets than 10 evaluated algorithms?
- Can the method handle fields whose contracts are statistical rather than exact (e.g., quantization error bounds under a noise model, or approximate eviction with provable error floors), where the paper currently relies on benchmarks alone?
- The authors propose searching for "principal assumptions" shared across fields — what does a cross-field assumption search over the merged 89-algorithm pool actually discover, e.g., between eviction and speculative decoding?
- Would adding calibration-seed variance to the pruning search objective (all current cells are single seed-0 runs) change which pruning variant wins, given the 1.6% margin over Pruner-Zero?
- Can the Lean-checking idea be ported into code-level harnesses as a cheap pre-GPU filter, combining OpenEvolve-style big early jumps with assumption-level attribution?
