Why This Matters

Controlled A/B shows the rate of reliable measurements — not agent count — limits search scale; the isolation and anti-reward-hack playbook transfers to any code-generation or automated-discovery pipeline.

Critical Edge

The “LLM controller beats a coded UCB tree” headline is really slot utilization: 2.4× more correct attempts at equal wall time — at equal candidate counts, the tree led 23–15.

comparator had no directions & idle narrowing slots · read as scheduler win, not LLM-planning superiority

Methodology — Four Nested Loops

1

Child agents each take one parent kernel + one direction, make a single change, compile, and time it on a dedicated B200 under the benchmark harness (10 warm-up + 50 timed iterations, L2 flushed).

2

LLM controller (Claude Opus 5.5, fixed) re-reads a read-only SQLite archive each round, expands any lineage node — not just the incumbent — and writes one distinct direction per free slot. No internal state.

3

Team loop: lead/helper agents patch the harness at warm restarts onto the same run and archive — progress never lost.

4

Humans decide what to send and how slots are allocated by gap-to-#1 — but official scores, ranks, and reference kernels never enter the search.

Reward = geometric-mean speedup over published baseline times, decided outside the model. Every send passes a 12-check gauntlet: per-workload correctness, unshipped shapes, compute-sanitizer, precision rules, reward-hack screens, build limits, site rehearsal, daily audit. Over a thousand agent sessions ran concurrently.

  • Stepping stones pay: 17% of best paths pass a ≥10% regression; 32% expanded a parent below 0.9× of the then-best. Quant/030's lineage reached 27.36×.
  • Throughput lever: one warm restart moving builds out of the GPU lock → 3.6× evaluated candidates/hour (lock time −71%), correct share ~98.4%.
  • Early gains dominate: first 2% of candidates delivered 81% of pooled improvement; first 15% of runtime gave 73–85% of each board's rise.
  • Null on guidance: mandatory references → geomean ratio 0.981 (233 pairs, p ≈ 0.24); only 1.19% of child sessions ever opened the skill doc.
  • Blackwell-native code: 214/235 CUDA C++ (median ~7,000 lines); 77% name tcgen05, 72% issue TMA, 94% inline PTX, zero Hopper wgmma.

Strengths

  • Complete, externally scored artifact — correct kernels for all 235 problems and simultaneous #1 on three NVIDIA-run boards that score submissions themselves.
  • Exemplary verification engineering — 12 layered checks, self-caught reward hacks (banned at 6% local cost), an admitted own-scorer bug, robustness preferred over raw speed.
  • Publishes null results with p-values and confessions — references 0.981, steering null, per-attempt parity with the tree. Rare honesty for a leaderboard report.
  • Quantitative case for full lineages in evolutionary search rather than greedy hill-climbing — the stepping-stone statistics.

Limitations

  • One benchmark, one model, one final run — transfer to other hardware, benchmarks, or models is untested.
  • Correctness is tested, not proved — formal verification ruled out for Blackwell's async tensor-core ops; robustness checks skip most candidates.
  • Local reward only approximates official score — unlocked clocks read ~1.19× fast; one fast local kernel failed the site's 300 s build limit three times.
  • Cost & reproducibility gap — compute never quantified, prompts unpublished, A/Bs single-run with confounds; rank margins as thin as 6×10⁻⁶ SOL and briefly lost on 2026-11-07/08.
