Key Finding arXiv 2611.13254

In failed multi-agent runs, the evidence contradicting the fatal belief is usually already there — and almost always ignored.

故障进入极早（中位在轨迹 18% 处），72% 的失败轨迹中早已存在与错误相矛盾的证据，但 88% 的情况下无任何 agent 利用它；真正有效的控制是读取这些证据（独立裁判 74% 覆盖），而非恢复 agent 状态（checkpoint 仅 1%）。

Why This Matters

For guardrail, validator, and failure-attribution designers: a reusable trajectory-level failure-annotation framework, plus first quantified proof that controls must read the evidence workers leave ignored.

为 guardrail / 验证器 / 失败归因研究者提供了可直接复用的轨迹级故障标注框架，以及"控制必须读取被忽略证据"的首批量化实证依据。

Critical Edge

The headline 74%-vs-1% control ranking is analytic reach, not measured prevention — no control was ever installed and re-run on the 95 failures.

from Critical Assessment — "reaches" is an expert counterfactual, not an intervention

How They Measured 方法

  • Corpus. 95 failed runs read end-to-end from two public corpora: Who&When (184 runs — 58 hand-crafted Magentic-One + 126 algorithm-generated AG2 CaptainAgent, on GAIA / AssistantBench questions) and the MAD / MAST human-labelled split (19 traces; 7 over 200k chars dropped).
  • Instrument. An "episode record" protocol — 38 fields, fixed vocabularies — ties each fault to origin phase (P0–P7) × state domain (R1–R6), propagation, detection, response. Every step-valued field anchors to a concrete trace line; refined on a 20-trace pilot (14 vocabulary fixes).
  • Annotation. One independent LLM annotator per trajectory, reading the full trace before writing; trajectories treated strictly as data (prompt-injection safeguard); all records schema-validated.
  • Annotator-independent checks. Origins compared against Who&When's human "decisive step" labels (n=88); the harness-fault finding comes from a deterministic text scan, no annotation involved.
  • Control mapping. Counterfactual: a family "reaches" an episode if its inspection basis would see the deviation and its boundary covers the affected state.

Strengths
  • Reframes failure analysis from symptom labels to episode structure — origin, propagation, unused evidence, ineffective response: exactly what a control designer needs.
  • The 72% / 88% / 0 evidence triple is one memorable, actionable number with a clear design implication.
  • Converts checkpoint folklore into data — restore suffices in only 35/95 runs.
  • Harness-fault discovery is deterministic, annotation-independent, and directly actionable for Who&When benchmark hygiene.
  • Exceptional transparency: pilot failures disclosed, threats enumerated, protocol / records / scripts all released.
Limitations
  • Single-LLM annotation, no human inter-annotator agreement; fault-kind shares (decision 42%, fabrication 26%) are provisional.
  • Control-reach numbers are counterfactual — never validated by re-running agents with controls installed.
  • Narrow corpus: QA and programming sandboxes; no external side effects, no human-in-the-loop; MAD contributes only 7 runs — effectively a two-system study.
  • 96 of 203 traces annotated, batch-balanced rather than randomly sampled — conclusions about the full corpora are extrapolations.
  • Diagnoses where controls attach, but no prototype, cost, or false-positive-rate analysis for any family.

Questions for Further Exploration 待探索

  1. Would 72%-present / 88%-ignored / 0-effective hold on corpora with irreversible external effects (τ-bench, TheAgentCompany) — where restore might also fare differently?
  2. Deploy each control family and re-run the 95 failures: what are the real prevention, false-positive, and cost numbers behind JUDGE 74% / TC 67%?
  3. How much do the fault-kind shares move under human double-annotation, given kind labels were the hardest part of the protocol?
  4. What is the causal link between content-filter crashes and the harness's fabricated FINAL ANSWER — should Who&When re-release a corrected attribution split?
  5. Can "restore reach" be predicted online at failure time, so an agent chooses rollback vs. replan vs. escalation without human diagnosis?
  6. Does replan-preserves-the-contaminated-belief generalize to single-agent systems, or is it specific to orchestrator-worker topologies?
