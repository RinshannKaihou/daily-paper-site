Why This Matters

Decouples input matching from expert allocation and removes balancing-loss gradient interference — directly useful for sparse MoE design and MixLoRA-style fine-tuning.

直击 MoE 路由两大痛点：匹配与分配的耦合、辅助均衡损失对梯度的干扰。

Critical Edge

All evidence sits at 0.43B–1.18B parameters / 4B–8B tokens, against only a vanilla linear router — deltas may not extrapolate to 30B-class MoE, and no loss-free-balancing baseline is ever run.

How It Works

方法 · Methodology

S1Context-Adaptive Prototype Matching

Each token is projected to a low-dim space (dp ≪ d) and ℓ₂-normalized, then matched against adapted prototypes: learnable unit-norm anchors pulled by exponentially-decayed short-term states that summarize preceding tokens. States reset at sequence boundaries and are read before written — causal by construction.

qₜ = softmax(M̃ᵗ⁻¹ᵀ zₜ / τₚ)

S2Prototype→Expert Association Table

A shared table B (row-softmax of price-adjusted scores, closed-form from an entropy-regularized objective) gives each prototype a conditional expert distribution. Expert probabilities mix by the law of total probability; mixing is non-expansive in TV, so similar prototypes yield similar routing. Many-to-many prototype–expert links stay separately inspectable.

πₜ = Bᵀ qₜ  ·  TV(Bᵀq, Bᵀq′) ≤ TV(q, q′)

⚖Loss-Free Congestion Pricing

Prices λ accumulate the signed residual of observed dispatch shares outside a tolerance band around 1/E, and are subtracted from each expert's whole column before the row softmax. Unlike Loss-Free Balancing, the feedback touches B only — never qₜ — so load regulation cannot corrupt the matching signal within a step, and no auxiliary balancing loss is needed.

⇉Causal Two-Pass Blockwise Approx.

Pass 1 predicts a whole block's responses in parallel from block-entry states; exclusive prefix sums estimate per-position preceding states; pass 2 corrects in parallel, carrying states across blocks. This replaces sequential tokenwise state updates during training/prefill — the source of the 21.82× throughput result.

Strengths vs. Limitations

批判性评估

Strengths

  • Conceptually clean factorization with a provable non-expansiveness property and closed-form entropy-regularized table.
  • Balancing provably leaves prototype responses untouched — load regulation can't corrupt matching within a step.
  • Rigorous paired-baseline pretraining protocol: identical experts & token budgets, <0.26% parameter overhead.
  • The two-pass blockwise scheme is the practical centerpiece — answers the "recurrent state kills MoE speed" objection.
  • Analysis depth above the norm: millions of matched token pairs, allocation diversity in nats, per-layer CV, a 64-intervention expert map.

Limitations

  • Evidence capped at ≤1.18B params / ≤8B tokens — far below the scales where MoE is actually deployed.
  • No baselines vs Loss-Free Balancing, X-MoE, L2R, or STAR — only the classic linear router.
  • Single runs, no seeds or error bars; several fine-tuning deltas are within plausible noise.
  • Regressions (WinoGrande −2.45pp on V3) reported but not diagnosed.
  • No sensitivity analysis for K, τp, τe, δ, block size — or the strikingly tiny dp = 7/15.
  • Decode-time cost of the recurrent state unmeasured; no code release stated.

Open Questions

进一步探索
  1. Does the +1.5–2.65pp advantage persist, shrink, or invert at 7B–30B params / 100B+ tokens?
  2. Head-to-head vs Loss-Free Balancing on the linear router: how much gain is the two-stage decomposition itself?
  3. Why do congestion prices flip input-dependent diversity Iπ in opposite directions on V2 (up) vs V3 (down)?
  4. Can dp = 7–15 be justified theoretically, and how sensitive is PMR to K, τp, τe, δ?
  5. Does the recurrent state hurt batch-1 decode latency — can two-pass blockwise extend to speculative decoding?
  6. Do task-dependent expert roles (hurting PIQA while helping LAMBADA) suggest a way to encourage format-generalizing experts?
