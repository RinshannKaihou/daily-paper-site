Why This Matters

Enables request-level auditing, compliance, and red-team forensics on deployed LLMs without touching the process — and exposes real hidden-state leakage risk in multi-tenant GPU environments.

⚠ Critical Edge

Observation is non-modifying but not non-intrusive: collection costs 157–163 s per prompt (~15,000× native), making it useless for routine monitoring — and forensically non-neutral.

Methodology 方法

attach→clock→identify→read→validate→use
  • Allocator clock: non-stopping cuda-gdb breakpoints on PyTorch's caching-allocator malloc/free log every tensor birth and death (size + device pointer) without touching target code.
  • Blind two-step selector finds the residual stream in the log alone: the primary rule tracks the hand-off chain (a layer's output is freed right after the next layer's is allocated); the fallback accepts constant-stride chains (≥8 members, ≥90% regular gaps). The selector is never told the layer count.
  • Read timing is measured, not assumed: bytes are read at the return of the next allocation after a tensor's birth — reading at the allocation point failed on every layer.
  • Kernel-launch clock adapter covers stacks that bypass the allocator: vLLM default (compile + CUDA graphs), llama.cpp (incl. quantized), SGLang prefill.
  • Probes stay standard: linear depth and refusal probes trained on normal framework activations; ground truth from a separate, synchronized hook pass.
  • Hygiene: pre-registered tests with SHA-256-hashed scripts; strict dev/eval isolation (372 hook-exposed prompts excluded); all failures reported.

Results 结果

  • Probe beats the dataset's own labels: on JailbreakBench, 15.5% error vs the tag's 26.8%; on a second held-out source, 4.5% vs 8.3% — with recovered-vs-hook AUROC differing by ≤0.001.

Strengths 优点

  • First demonstration that live, per-request GPU hidden states are acquirable from an unmodified process with byte-exact fidelity — turning ephemeral state into measurable forensic evidence.
  • Platform-invariant six-stage process cleanly separated from platform-specific adapters, with an adapter table that reports failures as prominently as successes.
  • Exemplary methodology: pre-registered hashed scripts, frozen probes, dev/eval isolation, full negative-results reporting.
  • The three-level evidence taxonomy resists every temptation to overclaim.
  • Practical byproduct: token count, hidden size, and layer count of an unknown target read exactly from the running process.

Limitations 局限

  • Narrow envelope: batch 1, fixed-length prompts, models ≤3.4B (one 7B 4-bit), a single 8 GB Turing GPU; TensorRT-LLM / TGI / other GPUs untested.
  • Intrusive despite read-only: debugger halts cost 46–192×; full collection ~15,000× native — minutes per prompt.
  • Platform-brittle: build-specific offsets (parameter block 0x160 on sm_75), kernel-name substrings, allocator internals; the selector needed two revisions; no code released.
  • Behavioural evidence is preliminary: one 0.5B model, keyword-matched refusal labels, FPR 0.282, ECE 0.160; predicts refusal, not harmfulness.

Questions for Further Exploration 待探索问题

  1. Does it scale to 7B–70B models on H100 / Blackwell (sm_90+), where offsets, kernel names, and CUDA-graph behaviour all differ?
  2. Can the refusal call beat AUROC 0.876 / FPR 0.282 via multi-layer probing — and how would it compare to simply classifying the generated reply?
  3. Does the hand-off-chain selector survive continuous batching, speculative decoding, and multi-request concurrency?
  4. Can acquisition become genuinely low-intrusive — hardware watchpoints, driver-level tracing, sampled breakpoints — closing the 4–5 order-of-magnitude latency gap?
  5. What other behaviours (prompt-injection success, persona identity, memorised content) can be read from recovered residual states?
  6. Do difference-of-means directions transfer as cleanly as the refusal direction did?
