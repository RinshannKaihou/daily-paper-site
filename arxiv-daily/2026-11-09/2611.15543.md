> **一句话总结：** 提出 isloss——一个确定性的规则测试预言机（oracle），通过共享中间表示 ConvIR 和 27 条保留规则检查 LLM API 翻译层（LiteLLM、Vercel AI SDK 等）是否静默丢失对话信息；在 685 个完成的翻译中 18.5% 通过目标 API 静态校验却仍引入可避免的提示/角色/工具信息改变，558 条翻译回复流中 36.4% 会在官方 OpenAI SDK 中抛异常或静默损坏。

> **TL;DR:** The authors build isloss, a deterministic rule-based test oracle that maps a source request (e.g., Anthropic Messages) and its translated counterpart (OpenAI/Gemini dialects) into a shared intermediate representation (ConvIR) and applies 27 preservation rules to flag silent information loss — no model calls or reference translation needed. On a held-out fault-injection suite it detects 95/125 planted faults (76.0%) with only 2/100 false alarms, beating reference-free Gemini LLM judges (J = 0.740 vs 0.516–0.704). Applied to a 51-shape synthetic suite across 14 paths of five translator codebases (LiteLLM, Vercel AI SDK v5/v7, LLM-Rosetta, @musistudio/llms, claude-code-proxy), 127/685 completed translations (18.5%) pass static target checks yet silently drop avoidable prompt/role/tool information (e.g., tool-result is_error flags — dropping it collapses tool-failure compliance from 30/30 to 0/30 on both tested Gemini models); 203/558 translated reply streams (36.4%) break official OpenAI SDKs, and 7 of 26 filed upstream issues were fixed and re-verified.

## 核心贡献

- **isloss 确定性测试预言机**：首个针对 LLM API 翻译边界的"对话信息保留"检查器。将源请求与翻译后的请求/回复/流都映射到共享中间表示 **ConvIR**（有序对话事件 + 显式生成控制），再用 **27 条保留规则**判断信息是否在翻译中存活，无需调用模型、无需参考翻译（思想源自编译器的翻译验证 translation validation）。
- **三分类输出而非二值判定**：T1（可避免的静默信息丢失——目标 API 明明有原生字段可以承载却被丢弃）、T2（单独报告的降级与提示，如系统指令被降级为用户消息、目标 API 本无法表示的损失）、T3（合法的表示变化，如角色名/容器结构重命名）。同时记录翻译器是否向调用方发出警告，区分"静默丢失"与"披露式降级"。
- **对预言机本身的严格验证**：留出集（held-out）规范驱动故障注入 95/125 检出（76.0%）、100 个允许变更中仅 2 个误报（2.0%）；辅以程序变异体（81.6–84.3% 检出）、公开 bug 复现（45/57 = 78.9%）与双人独立人工评审（54 个候选中确认 31 个真实缺陷）。
- **大规模实证刻画翻译生态**：主普查覆盖 5 个代码库的 6 种配置、14 条源→目标路径、51 个合成请求形状（357 个四因子覆盖数组生成后过滤）；发现 18.5% 的完成翻译"结构合法但信息被改"；另测 6 个网关、Google 官方 OpenAI 兼容端点、以及 Claude Code/Codex/Crush/Aider 等真实 coding-agent 流量回放。
- **行为后果与上游影响**：6 个模型上的定向实验显示 18 个机制中 10 个被测、9 个改变模型行为；向 12 个仓库提交 26 个 issue，7 个已被维护者修复且作者独立复核；全部 4,998 次测试执行可在 11 秒内字节级复现（固定版本/commit）。

## Key Contributions

- **A deterministic preservation oracle (isloss).** The first checker targeted at conversation-information preservation across LLM API translations (OpenAI Chat/Responses, Anthropic Messages, Gemini generateContent). It normalizes source and translated payloads into a shared intermediate representation, **ConvIR** (an ordered event sequence plus explicit generation controls, with per-event speaker, content type, payload, and flags such as `is_error`), then applies **27 preservation rules** inspired by compiler translation validation (Pnueli et al. 1998; Necula 2000). It needs neither a model call nor a reference translation, unlike round-trip testing (impossible for 10 of their 14 paths), schema validation, or reference-based diffing.
- **A three-tier change taxonomy.** T1 = unannounced, avoidable losses (target API has a documented native field that could carry the information — e.g., Anthropic's `is_error: true` dropped on the way to Gemini, which can represent errors via `functionResponse.response`); T2 = separately reported degradations (e.g., system-to-user role demotion, target-limitation losses, cache/usage notes); T3 = permitted representational changes. Each finding records whether the translator warned the caller, separating silent loss from disclosed degradation.
- **Rigorous self-validation of the oracle.** On six blind held-out batches authored by LLM agents without access to checker code: 95/125 activated planted faults detected (76.0%; Wilson 95% CI 67.8–82.6%), 2/100 allowed changes falsely flagged (2.0%). Extended: 160/220 (72.7%) and 5/170 (2.9%). Plus program-mutant suites (81.6–84.3% detection), 45/57 reproduced public bugs detected (78.9%), 10/14 bugs opened in the 50 hours after the rules were frozen, and independent two-rater human review confirming 31/54 request-side candidates as defects (23/24 = 95.8% of agreed avoidable cases).
- **An ecosystem-wide empirical census.** Main request study: 714 attempts → 685 completed translations (29 explicit rejections) over 51 statically valid source shapes × 14 paths across LiteLLM, Vercel AI SDK v5 and v7, LLM-Rosetta, @musistudio/llms, and claude-code-proxy, with 18 catalogued mechanisms (top: tool-result error flag dropped in 154 cells, text-after-tool-call reordered in 54, parallel-tool-use setting dropped in 41, functionResponse.id dropped in 37). Complementary studies cover six gateways (Bifrost, new-api, Portkey, CLIProxyAPI, one-api, ai-gateway), Google's hosted OpenAI-compatible endpoint, 50 consecutive LiteLLM releases, and replayed traffic from six CLI coding agents.
- **Behavioural consequences + real upstream impact.** Nine of ten tested mechanisms measurably alter model behaviour across six models (2 Gemini, 2 Claude, 2 open-weight); 26 upstream issues filed, 7 fixed and independently re-verified as of 15 Oct 2026; artifacts (checker, suite generator, captured payloads, audit records) released for replication.

## Methodology

1. **Shared representation (ConvIR).** Because API dialects encode roles, tool calls, error flags, and generation controls differently (direct JSON diff would flag harmless renames; schema validation accepts semantically altered payloads), both source S and translation T are mapped to an ordered sequence of conversation events (speaker: user/developer/assistant/tool; content type; payload; flags) plus an explicit control block (`tool_choice`, declared tools, sampling params, token limits). Anthropic's top-level `system` and an OpenAI leading system message map to the same instruction event; `assistant` and Gemini's `model` map to the same speaker.
2. **Comparison and classification.** IR(S) vs IR(T) is compared after permitted changes (consistent role/ID renames, merging adjacent same-author messages, OpenAI's split text/tool-call fields). Violations are graded T1/T2/T3 as above; avoidability is decided against vendor documentation, and 17 under-specified cross-dialect mappings were probed against the live Gemini endpoint (13 resolved).
3. **Capture harness.** Each self-hosted translator is driven through its documented public interface into a local mock server; the payload is captured at the last self-hosted hop. Explicit rejections are counted separately as fail-closed (29/714). LiteLLM's pre-serialisation dict is the primary capture point, with a serialised-body sensitivity check (127→132 of 685). The full suite (4,998 executions) replays byte-for-byte in 11 s from a fresh checkout.
4. **Test suites.** Main suite: 357 shapes from a four-way covering array over 14 feature dimensions → static source-contract filtering → 51 shapes. Separate 170-shape mid-conversation-system-instruction suite; 36 recorded requests (28 unique, 14 shapes) from six CLI agents; 1,115 reply cells and 558 reply streams from seven translators, read back by official OpenAI Python and Node SDKs.
5. **Oracle evaluation.** Blind, specification-based fault injection (planted losses vs allowed changes, authored post-freeze by LLM agents), mutant suites, public-bug reproduction, dual-rater human review with disagreement → Grade C, and judge comparisons (normalised diff and Gemini LLM judges, with and without a reference translation).
6. **Behavioural probes.** "Distinguishing conversations" whose correct answer depends on a selected field, run 30 (or 10) trials per arm on gemini-3.5-flash-lite, gemini-3.8-flash, claude-sonnet-4-6, claude-haiku-5-5, Llama-3.1-8B, Qwen2.5-7B; Fisher exact / sign-flip permutation tests with Holm correction; a 100-item GSM8K control for task-level effects. Statistics: cluster bootstrap by shape (10,000 resamples) or Wilson CIs; each criterion labelled pre-specified / fixed-before-run / post hoc.

## Results & Highlights

- **Oracle accuracy (held-out fault injection):** isloss detects **95 of 125 activated planted faults (76.0%, Wilson 95% CI 67.8–82.6%)** with **2 of 100 allowed changes falsely flagged (2.0%)**. Without a reference translation, its J (recall − false-alarm rate) = 0.740 beats both Gemini LLM judges (J = 0.516 and 0.704); with a reference, normalised diff reaches J = 0.842 and Gemini judges 0.804/0.840 — but obtaining a trusted reference is exactly the impractical part.
- **Primary silent-loss rate (main synthetic suite, 6 configs × 14 paths):** **127/685 completed translations (18.5%, cluster-bootstrap 95% CI 15.01–22.06%)** pass static target checks while silently making at least one avoidable change to prompt, role, or tool information. Robust across strata: 18.7% (34/182) on the 13 shapes claude-sonnet-4-6 accepts live, 20.5% (23/112) for claude-opus-4-8-accepted shapes, 25.0% (22/88) when both endpoints accept. Sensitivity: 12.9–19.6% under alternative validity rules, 16.5–25.7% under alternative counting conventions (role-demotion-inclusive variant: 134/685 = 19.6%).
- **Human validation:** reviewers confirm **31 of 54 request-side candidates as genuine defects** across 18 mechanisms; among avoidable candidates, 23/24 agreed cases (95.8%, CI 79.8–99.3%) are confirmed defects vs only 6/16 (37.5%) for unavoidable ones — supporting the paper's conservative avoidable-only primary count.
- **Behavioural consequences (live models):** dropping the tool-result `is_error` flag cuts tool-failure compliance from **30/30 to 0/30 on both tested Gemini models**; dropping `functionResponse.id` collapses parallel tool-call attribution from 30/30 to 0/30 (Holm-adjusted p = 0.0039); a translator raising `max_tokens` from 100 to 1,124 reduces compliance with the caller's 100-token limit from 30/30 to 0/30 on both Claude models; on claude-sonnet-4-6, dropping `top_p: 0.05` raises mean distinct outputs per scenario from 3.8 to 4.8 (p = 0.0156). Nine of ten tested mechanisms alter at least one measured outcome; the GSM8K control (100 items, gemini-3.5-flash-lite) shows no detectable accuracy drop (p ≥ 0.25) — effects are field- and task-dependent.
- **Replies and streams:** across 1,115 judged reply cells from seven translators, **391 (35.1%) change meaning** (278 avoidable); **203/558 translated reply streams (36.4%) raise an exception or silently corrupt the assembled message in at least one official OpenAI SDK** (Python 170/558 = 30.5%, Node 182/558 = 32.6%), and 199/203 (98.0%) of these failures are avoidable. Per-translator stream failures range from 21.2% (Bifrost) to 72.5% (one-api) and 55.0% (LLM-Rosetta).
- **Gateways, first-party layer, real agent traffic:** Bifrost + new-api introduce T1 changes in 187/204 judged cells (91.7%) on the 51-shape suite and 978/1,020 (95.9%) on the 170-shape corpus; Portkey instead explicitly refuses every tested Anthropic→OpenAI/Gemini request (fails closed). Google's OpenAI-compatible endpoint passes 10/11 behavioural probes but keeps only the last of two top-level system messages and charges unnamed reasoning tokens against `max_tokens` (98.0% of output tokens across 45 calls). Replaying recorded coding-agent requests yields a lower primary rate — 4/98 (4.1%) cells — plus 23/98 (23.5%) counting all avoidable changes.
- **Persistence and upstream response:** 2,630/2,745 flagged cells (95.8%) remain flagged in later source snapshots; every one of 50 consecutive LiteLLM releases changes the meaning of ≥31/51 shapes toward OpenAI. Of 26 filed issues, 7 were fixed upstream and independently re-verified.

## Critical Assessment

- **Novelty: high and well-positioned.** Applying translation validation to LLM API dialects is genuinely new; the authors carefully delineate it from LLM-Rosetta's round-trip equality (which cannot see information omitted from its IR), schema validation, and differential testing. The avoidable-vs-unavoidable distinction (backed by endpoint probes resolving 13/17 under-specified mappings) is the paper's sharpest conceptual move.
- **Rigor: well above average, with honest self-limitation.** The oracle is validated independently of its development data, mutants and public bugs corroborate planted faults, and counting-policy sensitivity (12.9–25.7%) is reported instead of a single fragile number. The GSM8K negative control is a model of intellectual honesty.
- **Reproducibility: excellent** (pinned versions, 11-second byte-for-byte replay, released artifacts), though the "held-out" blind batches were authored by LLM agents, a slight circularity risk the authors mitigate by withholding checker code from the authors of the batches.
- **Significance caveats.** (1) The headline 18.5% is measured on a synthetic, Anthropic-source-only suite (51 shapes from a covering array; only 13/51 even accepted live by claude-sonnet-4-6); on recorded real agent traffic the primary rate drops to 4.1% (4/98 cells), so the paper proves prevalence in its test suite, not production — the authors say so repeatedly, but casual readers will over-quote 18.5%. (2) The oracle misses ~24% of planted faults (95/125), so absence of a finding is weak evidence of preservation. (3) "Avoidable" hinges on the authors' reading of vendor docs; the T1/T2 boundary is consequential — excluding system-to-user role demotion (LiteLLM's rewrite) from the primary count is defensibly conservative but understates a change with demonstrated behavioural teeth. (4) Behavioural probes cover only 10/18 mechanisms, no GPT models, and 277/685 OpenAI-bound cells were never submitted to a live OpenAI endpoint; benchmark-score impact (τ-bench/BFCL) is flagged as future work rather than measured. (5) Capture-point sensitivity was analysed only for LiteLLM (pre-serialisation dict vs serialised body moves the count 127→132).
- **Red flags: minimal.** No cherry-picked leaderboards; the one pre-specified prediction that failed (claude-sonnet-4-6 refusal 10/30→0/30) is disclosed rather than buried. The naming "isloss" is awkward, and the mid-conversation system-instruction experiment that opens the paper is technically separate from the main census — clearly labelled, but it front-loads a dramatic result with different denominators.

## Strengths

- Attacks a real, previously unformalized failure mode that sits in the hot path of nearly every production agent (LiteLLM/AI SDK/gateways), with a crisp formal framing (translation validation + preservation rules).
- The oracle needs no model calls and no reference translation — deployable as a cheap regression gate — and outperforms reference-free LLM judges (J 0.740 vs 0.516–0.704).
- Exceptional measurement hygiene: explicit denominators for every claim, cluster-bootstrap/Wilson CIs, Holm-corrected permutation tests, pre-specified vs post hoc labels, and sensitivity analyses across validity rules, counting conventions, and capture points.
- Triangulates five evidence sources (fault injection, mutants, public bugs, human review, live models) and closes the loop with maintainers (7 verified upstream fixes), plus deployment findings with security relevance (silent safety-filter disabling, cross-provider fallback returning HTTP 200, forwarded auth headers, mid-stream errors billed as completed).

## Limitations

- Rates are synthetic-suite rates, not production prevalence; the source dialect is exclusively Anthropic-format, and only 7/14 recorded agent shapes pass static source checks, shrinking the real-traffic evidence base (98–196 cells).
- 76% fault recall means roughly a quarter of planted losses go undetected; false-alarm CI is wide at 2.0% (0.6–7.0%) on only 100 controls.
- Rule authoring and avoidability judgements involve interpretation of vendor documentation that is itself incomplete (17 unspecified mappings; 13 resolved by probing).
- Behavioural coverage is partial: 10/18 mechanisms, 6 models (no GPT models), Claude probes limited to three mechanisms, OpenAI-bound translations untested against live OpenAI endpoints; effects shown to be task-dependent (GSM8K null result).
- isloss is an offline research checker; CI/CLI integration, streaming coverage beyond the tested SDKs, and impact on published benchmark rankings are future work. Temporal validity is bounded — translators and specs evolve, so findings reflect the studied snapshots.

## Relevance

直接命中"Agent & Pipeline Silent Failures"方向：论文研究的正是模型与世界之间这一软件层（API 翻译器、网关、SDK）如何静默篡改模型实际收到的对话内容，并提供了系统性的检测（isloss/ConvIR 保留规则）与修复（26 个上游 issue、7 个已验证修复）方案。对任何依赖 LiteLLM/Vercel AI SDK 等互操作层的 agent 系统与评测基准的可信性评估都有直接参考价值。

## Questions for Further Exploration

- How much do these translation-induced changes actually move published benchmark scores and leaderboard rankings on tool-heavy suites (τ-bench, BFCL, SWE-bench) that route through LiteLLM or the AI SDK — the paper explicitly leaves this unmeasured?
- Can isloss be extended beyond its 27 rules to cover mid-conversation system instructions, signed thinking blocks, and media inputs inside the primary census rather than separate probes, and what recall does it achieve there?
- Would a production-scale capture of real gateway traffic (rather than 36 recorded agent requests) confirm the ~4–7% primary rate, or do popular agent workloads concentrate on the lossy feature combinations?
- Can the avoidable/unavoidable classification be automated against machine-readable OpenAPI/vendor specs instead of author judgement, given 17 under-specified cross-dialect mappings?
- Do translator-induced control changes (dropped `top_p`, inflated `max_tokens`, injected default temperature) bias greedy-decoding evaluations or reproducibility studies that assume deterministic settings?
- Could preservation checking be embedded as a runtime assertion in translators/gateways (reject-or-warn on T1) with acceptable latency, turning today's silent substitutions into explicit degradation contracts?
