> **一句话总结：** SciMARS 针对闭环科学发现中"证据孤岛"与"固定执行流程重蹈覆辙"两大问题，用共享证据图（Mycelium 式六命名空间+溯源）加"角色/协调/（+Memory 的）记忆策略三个独立编辑器→公共探针→证据引导组合→选择"的任务内递归自适应循环来改写多智能体团队的行事方式：在 Autonomous Science Bench 上 GPT-6-Astra 组从基础团队的 8/18 提升到 12/18，ScienceAgentBench 38 个机器评分任务从 11/38（28.9%）升至 14/38（36.8%），AppWorld 20 任务子集从 5/20 升至 11/20；但换用较弱的 GLM-5.3 后优势几乎消失（2/18 vs 1/18）。

> **TL;DR:** SciMARS recursively adapts a multi-agent scientific-discovery team *within a task*: independent editors propose scoped changes to role procedures, coordination contracts, and (in SciMARS + Memory) memory policy over a shared evidence graph; every candidate is probed on public evidence, and a composer/selector that can only combine already-tested coordination and memory options picks the next harness — the meta-optimizer never rewrites itself and the official evaluator is never queried during revision. On Autonomous Science Bench (6 biology/chemistry/materials campaigns via data replay + digital twin), SciMARS + Memory resolves 12/18 GPT-6-Astra attempts vs 8/18 for the base team and 10/18 for a MASS-RHI integrated-workflow-search baseline; on ScienceAgentBench's 38 machine-graded tasks it solves 14/38 (36.8%) vs 11/38 (28.9%); on a 20-task AppWorld music/finance subset it wins 11/20 vs 5/20. Caveat: with the weaker GLM-5.3 backend the gain shrinks to 2/18 vs 1/18, and no statistical significance is reported anywhere.

## 核心贡献

- **任务内递归自适应框架（SciMARS）**：把多智能体"执行挽具"（harness：角色规程 P + 协调契约 C）的自适应分解为相互独立的编辑面——角色编辑器只改角色规程、协调编辑器最多改一条路由/契约、SciMARS + Memory 再加一个独立的记忆策略编辑器 M（写录职责、检索规则、订阅类型）。各编辑器从同一参考执行出发提案，互不阅读对方的提案，避免单点大改带来的耦合错误。
- **共享证据图与"存证"与"用证"分离**：借鉴 Mycelium 的主动上下文图，六命名空间（context/work/decisions/status/procedures/log）+ 类型化边（支持/矛盾/派生/依赖）+ 溯源与不可覆盖的数据集/观测记录。关键设计是把图内容 G 与记忆策略 M 分开：固定策略的 Multi-Agent + Memory 对照证明"能存证据"不等于"会用证据"，必须自适应策略。
- **公共探针引导的组合与选择（propose–probe–compose，继承 Harness²）**：每个候选在隔离工作区、匹配的公共输入下试探；组合器只能从**已被试探过的**协调/记忆选项中挑选（不能凭空发明第三种策略），新组合再单独试探；若后继挽具与某同轮试探完全匹配且程序通过完整性校验则直接复用该执行。选择只依赖公共证据，官方评测器仅用于最终提交——从机制上杜绝了评测泄漏。
- **跨三基准的实证**：GPT-6-Astra 上 12/18（ASB）> 基础团队 8/18 与集成搜索 10/18；ScienceAgentBench 14/38 > 11/38；AppWorld 11/20 > 5/20，且消融链条清晰（基础团队 < 固定记忆 < 集成搜索 ≲ SciMARS < SciMARS+Memory）。
- **案例级机理证据**：BBBC002 细胞计数任务（SAB #11）中，同一失败参考被"只改角色"（MAE 78.0→6.17）与"只加一条 verifier→finalizer 契约"（MAE→11.8）两种正交手段分别修复，直观展示两个编辑面各自的修复机理。

## Key Contributions

- **A task-local recursive self-improvement framework for closed-loop scientific discovery.** SciMARS targets two failure modes of multi-agent science teams: evidence siloed in individual agent histories, and fixed role procedures/handoffs that repeat mistakes even when the evidence is retained. Adaptation is strictly task-local: accepted edits govern later rounds of the *same* task and are reset for each new evaluation task.
- **Separate adaptation surfaces with independent, scope-validated editors.** The harness is H = (P, C) — or H = (P, C, M) with memory. A role editor revises role instructions while preserving the entire coordination object; a coordination editor changes exactly one route or contract (version, shared fields, sender/receiver instructions) while preserving all role instructions; the memory-policy editor in SciMARS + Memory revises write duties, retrieval filters, query hints, retrieval limits (bounded 0–12), and subscriptions while preserving the graph's provenance rules and stored measurements. A validator enforces schema, component ownership, permitted fields, version increments, and required evidence citations; rejected proposals fall back to the current harness.
- **A shared evidence graph with an explicit contents-vs-policy split.** Records carry keys, types, authors, versions across six namespaces; typed edges express support/contradiction/derivation/dependency; dataset and observation records cannot be overwritten. The default policy retrieves up to six records per logical role with lexical relevance ranking and recency tie-breaking. The fixed-policy "Multi-Agent + Memory" control isolates access to shared evidence from adaptation of its use.
- **Evidence-guided composition, execution reuse, and leak-proof selection.** Coordination and memory in the successor must come from probed candidates (Eq. 8); a same-round execution is reused only if the full harness (including memory policy) matches and the saved program passes an integrity check (Eq. 9); selection considers up to four (SciMARS) or five (+Memory) runnable outcomes using public checks only — a train–validation probe even excludes held-out labels from the graph. A reflector distills grounded lessons (cue, procedure, cited events, limitations) for later rounds.
- **Controlled multi-benchmark evaluation.** Against the base team, fixed memory, and MASS-RHI integrated workflow search on Autonomous Science Bench (two model cohorts), ScienceAgentBench (38 machine-graded tasks), and AppWorld (20 music/finance tasks), with matched total model allowances within each benchmark and cohort.

## Methodology

The execution harness at round t is H_t = (P_t, C_t) for SciMARS and (P_t, C_t, M_t) for SciMARS + Memory. The role set R contains seven logical responsibilities — analyzer, planner, coder, verifier, router, debugger, finalizer — wired through eight handoff interfaces (e.g., planner–coder, coder–verifier, verifier–router, router–planner, verifier–planner, verifier–finalizer, coder–finalizer); the executor produces o = (p, τ, a, c) (program, trace, artifacts/state, resource use). The optimizer observes only public inputs, tool responses, and generated artifacts; the official evaluator V is invoked once after final commitment.

One adaptation loop: (1) execute the current harness for reference evidence; (2) each scoped editor proposes a candidate (role-only H^P, coordination-only H^C, and, with memory, H^M); validators check scope and evidence citations; (3) probe every validated candidate in isolated workspaces under matched public inputs and limits — memory branches start from the same permitted seed with separate writes, and a public train–validation probe keeps held-out labels out of both inputs and graph; (4) the composer builds a successor, but coordination/memory must equal one of the tested options — it cannot invent an unprobed policy; (5) reuse a verified same-round execution when the complete harness matches, else probe the successor; (6) select among up to 4 (SciMARS) / 5 (+Memory) runnable outcomes via public checks (the scientific selector may inspect code, replay observations, and run bounded structured checks; a campaign adapter can compare objectives on a public validation panel); (7) the reflector emits at most one grounded lesson, and adaptation continues from the selected harness.

Shared memory follows Mycelium's active context-graph design: six namespaces, typed provenance edges, immutable dataset/observation records, host-enforced schema; handoffs deliver policy-filtered records plus a feed of new records from other roles. The memory policy M_t = {(w, q, s) per role} governs recording duties, retrieval, and subscriptions; the policy editor can only change access to evidence, never the evidence itself. Crucially, this is recursion over the *execution* harness only — the meta-optimizer's prompts, validators, selector, and evaluator are outside the editable surface, and no accepted edit becomes a shared learned harness across evaluation tasks.

Resource control is explicit: all stages (executions, editors, probes, selection, reflection, retries) draw from the task allowance; one SciMARS round costs 3 team executions when the successor reuses a probe and 4 otherwise (4–5 for SciMARS + Memory), excluding editor/reflection calls. The implementation builds on the DS-STAR agent pipeline (Nam et al., 2026) and the propose–probe–compose principle of Harness² (Xu et al., 2026).

## Results & Highlights

- **Autonomous Science Bench (GPT-6-Astra cohort):** SciMARS + Memory resolves **12/18 attempts** vs **8/18 for the base multi-agent team** (+4), 10/18 for SciMARS, 10/18 for Multi-Agent + Integrated Search (MASS-RHI), and 9/18 for fixed Multi-Agent + Memory — each method gets 3 runs on each of 6 campaigns (nuclease/biosensor engineering, propylene/Suzuki reactions, oxygen-evolution/coercivity materials), with success requiring both discovery and held-out learning gates.
- **Autonomous Science Bench (GLM-5.3 cohort):** SciMARS + Memory resolves only **2/18 attempts vs 1/18 for the base team**; the base team misses both gates in 11/18 attempts and leaves 4/18 incomplete, while SciMARS + Memory misses both in 7/18 with 3/18 incomplete — the weaker backend dominates the outcome distribution.
- **ScienceAgentBench (38 machine-graded tasks, GLM-5.3-flashx):** SciMARS + Memory passes **14/38 (36.8%) vs 11/38 (28.9%)** for the base team, fixed memory, and integrated search alike; SciMARS alone reaches 13/38 (34.2%). Task-level overlap: SciMARS and integrated search share 7 successes, with 6 SciMARS-only vs 4 integrated-search-only wins.
- **AppWorld (20-task music/finance subset, GLM-5.3-flashx):** SciMARS + Memory succeeds on **11/20 tasks (7/10 music, 4/10 finance) vs 5/20 for the base team (5/10 music, 0/10 finance)**; fixed memory gets 6/20, integrated search 8/20, SciMARS 10/20.
- **Case study (ScienceAgentBench task 11, BBBC002 Drosophila KC167 cell counting):** the reference finalizer's path-search heuristic redirects the training directory to the test directory and overwrites ten predictions with zeros (official MAE 78.00, evaluator threshold MAE ≤ 30); the role-only repair yields ten nonzero predictions with **official MAE 6.17**, and the coordination-only repair (one new verifier→finalizer contract) achieves **MAE 11.80** — both pass where the reference fails.
- **Cost accounting:** one SciMARS round requires 3 team executions when the successor reuses a probed execution (4 with a fresh successor probe); SciMARS + Memory requires 4–5 — all charged against the same total model allowance as the baselines.

## Authors & Credibility

The paper is a two-author work from Northwestern University — Weimin Wu (Center for Foundation Models and Generative AI) and Han Liu (Center for Foundation Models and Generative AI, Computer Science, and Statistics & Data Science). Han Liu's group has a dense track record in scientific ML and foundation models (DNABERT-S, Genome-Factory, DIMOS, POLO), and — importantly — the group also authored the Autonomous Science Bench evaluation benchmark (Wen & Liu, 2026), giving them deep familiarity with the discovery protocol while creating a self-evaluation dynamic worth noting. The method honestly positions itself as building on DS-STAR (execution harness), Harness² (propose–probe–compose), MASS (the integrated-search baseline component), and Mycelium (graph memory) rather than claiming to invent each piece. A public project page (github.com/WeiminWu2000/SciMARS) is provided. The writing is unusually precise about what validation does and does not establish ("Validation establishes protocol compliance, not a gain in task performance"; "stochastic executions do not establish a causal effect from one trial"), which raises confidence in the protocol description.

## Critical Assessment

- **Novelty:** Moderate-to-good. The individual ingredients — workflow search (AFlow, MASS), propose–probe–compose (Harness²), shared graph memory (Mycelium), verbal self-improvement (Reflexion) — all exist; the contribution is the clean *factorization* of the adaptation surface into role/coordination/memory-policy editors with tested-option-only composition, applied to closed-loop scientific discovery. It is a systems contribution, not a new learning algorithm.
- **Rigor / statistical weakness:** The headline ASB numbers rest on 18 attempts per method (3 runs × 6 campaigns) on *fixed* fixtures — the paper itself concedes "repeated runs measure variation on fixed campaign fixtures, not independent campaign samples" — and no significance test, confidence interval, or per-campaign breakdown is reported anywhere. A 12/18 vs 8/18 gap is suggestive, not established; the GLM-5.3 result (2/18 vs 1/18) is literally a single-attempt difference and is still headlined as an improvement.
- **Benchmark subsetting:** ScienceAgentBench uses only the 38 machine-graded tasks out of the 102-task verified snapshot, excluding all 64 visualization tasks *before* evaluation; AppWorld uses a 20-task subset with one task per scenario. The paper flags "no claims are made about the full benchmark," but the selection shrinks the evidence base considerably.
- **Design/evaluation mismatch:** to reduce cost, the GPT-6-Astra cohort runs a *two-agent worker–reviewer* team covering the seven logical roles, so the strongest headline numbers do not come from the full seven-role harness the method section describes.
- **Baseline construction:** the integrated-search baseline is the authors' own adapter of the released MASS workflow-search/RHI component with two revision iterations — fair-ish, but adapter quality (not the original authors') determines its score, and it was not tuned here.
- **Reproducibility:** good on protocol detail (pinned models z-ai/glm-5.3-flashx via OpenRouter with low reasoning effort, AppWorld package 0.1.3.post1 / data 0.1.0, seeded task selection, allowance matching) and a public GitHub page; but the case study reveals the verifier still answered "Yes" after the coordination repair, i.e., the trace shows evidence delivery, not full instruction compliance — a candid but telling indicator of how loosely these contracts bind.
- **Missing ablations:** no ablation over the number of outer rounds (fixed at two for SAB/AppWorld), the retrieval-limit bound (0–12, default 6 records), editor order, or per-campaign attribution; the only mechanism-level evidence is a single case study. There is also no wall-clock or dollar-cost table, despite adaptation tripling-to-quintupling team executions per round.
- **Red flags:** borderline framing — the abstract's GLM-5.3 line ("2/18 vs 1/18") presents a one-attempt delta as a result; and 3–4 of 18 GLM attempts are "incomplete" (no official outcome), which the tables display but the narrative does not discuss.

## Strengths

- The contents-vs-policy split for memory (graph G vs policy M), operationalized by the fixed-memory control, is a genuinely clean experimental design that cleanly attributes gains to *adapting the use of evidence* rather than merely storing it.
- Leak-proofness is engineered into the protocol, not asserted: official scores reserved for final evaluation, isolated probe workspaces, held-out labels excluded from both inputs and graph, untrusted candidate code treated as evidence rather than instructions.
- Tested-option-only composition (the composer cannot invent untested coordination or memory policies) plus execution reuse with integrity checks is a disciplined answer to combinatorial blowup in harness search.
- Honest scoping throughout: the meta-optimizer does not rewrite itself; accepted edits are task-local and never transferred to evaluation tasks; validators check compliance, not performance.
- Consistent monotone ordering across three benchmarks (base ≤ fixed memory ≤ integrated search ≤ SciMARS ≤ SciMARS + Memory) with matched compute allowances strengthens the causal story.
- The BBBC002 case study is a rare, trace-level demonstration that role edits and coordination edits repair the *same* failure through orthogonal mechanisms (MAE 78.0 → 6.17 vs → 11.8).

## Limitations

- The discovery evaluation uses experimental-data replay and a digital twin, not new physical wet-lab experiments — the closed loop is closed only in simulation (acknowledged by the authors).
- Only two model cohorts (GPT-6-Astra, GLM-5.3) and one harness family (DS-STAR-based) are tested; the GLM cohort operates near the floor (2/18), so nothing is learned about mid-strength backbones.
- Sample sizes are small and untested for significance: 18 ASB attempts, 38 SAB tasks, 20 AppWorld tasks, with 64/102 SAB tasks and most of AppWorld excluded.
- Adaptation is deliberately task-local — no cross-task transfer of harnesses or lessons is attempted or measured, leaving the "does it compound?" question open.
- Compute overhead is real: 3–5 full team executions per round plus editor/probe/reflection calls, all charged to the task allowance; no cost-effectiveness analysis is given.
- The memory policy search space (write duties, retrieval filters, limits 0–12, subscriptions) is explored by a single LLM editor call per round with no exploration strategy or theoretical grounding.

## Relevance

与"LLM 智能体/多智能体系统的自我改进与自动化科研"方向高度契合：SciMARS 把 harness 搜索、共享记忆与递归自我改进三条主线在闭环科学发现中统一了起来，其对"存证据≠用证据"的对照设计、防评测泄漏的探针协议，对任何做多智能体工作流优化或科学智能体的人都可直接借鉴；但小样本与弱模型上的地板效应提醒其结论的适用边界。

## Questions for Further Exploration

- Do task-local accepted harnesses or reflector lessons transfer across tasks, and can a cross-task harness library compound gains without leaking held-out information?
- Why does the framework barely help GLM-5.3 (2/18 vs 1/18) — is the bottleneck editor quality, probe fidelity, or the base team's inability to execute any harness well, and would a mid-tier model show proportional gains?
- How do results scale with the number of outer rounds, and does the 2-round budget leave most of the achievable adaptation on the table?
- Can selection-time public probes be calibrated against official outcomes, so that probe-based selection is provably correlated with final evaluation rather than just protocol-compliant?
- What happens with real wet-lab feedback latency/noise instead of replay and a digital twin, where a bad probe cannot be undone?
- Does the memory-policy editor converge to stable policies, or does it oscillate (e.g., retrieval limit swinging between 0 and 12) across rounds within a task?
