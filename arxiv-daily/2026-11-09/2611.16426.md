> **一句话总结：** 华为提出 SoScale，把层级式 FP4 量化（MXFP4/NVFP4/HiF4）中的 scale-code 选择从局部 MSE 拟合改造成 Hessian 加权的层级重建问题，并与 GPTQ 式误差补偿交错执行；在 Qwen3-8B/14B 的 W4A4 实验中，各 model-format 组均取得最佳平均准确率，相对最强非 SoScale 基线提升 0.21–0.77 个百分点，Qwen3-14B 上 BF16 精度保持率达 97.17%（MXFP4）至 99.40%（HiF4）。

> **TL;DR:** The paper targets scale-code selection in hierarchical FP4 quantization (MXFP4/NVFP4/HiF4) and shows that default max-abs scaling and local-MSE scale search (ScaleSearch) optimize tensor fidelity, not layer-output fidelity. SoScale instead searches hardware-legal scale codes under a Hessian-weighted layer reconstruction loss (H = X^T X from 128x2048-token WikiText calibration), interleaved with GPTQ-style error back-propagation so later blocks are searched on compensated weights — all offline, with no change to the FP4 format or serving path. On Qwen3-8B/14B across GSM8K, HellaSwag, MMLU, ARC-C/E, BoolQ, and PIQA under W4A4, the best SoScale variant wins every model-format group, improving average accuracy over local ScaleSearch by 0.47–1.10 points (e.g., Qwen3-8B NVFP4: 0.7356 vs 0.7281) and over the strongest baseline (GPTQ/ScaleSearch) by 0.21–0.77 points, with the largest headroom under MXFP4's coarse E8M0 power-of-two scales; an ablation shows MSE-search + recovery alone can even hurt NVFP4 (0.7270 vs 0.7281), so the Hessian-aware objective — not the recovery — is the key ingredient.

## 核心贡献

- **识别出层级式 FP4 量化中的离群值诱导 scale 错配问题**：默认的 max-abs 缩放为覆盖离群值而拉伸 FP4 网格，导致最外侧的可表示电平无人使用（在真实 Qwen3-8B 权重块上，两个最外层电平没有被任何值占用），密集分布于零附近的权重反而分辨率不足。
- **提出 SoScale**：一种二阶（Hessian 感知）的离线 scale-code 搜索方法，在目标 FP4 格式的合法 scale 码空间内搜索，用 Hessian 加权的层级重建损失 ℓ = e^T H_b e 给候选 scale 打分，而不改变 FP4 格式本身、不引入部署期搜索开销。
- **将 scale 搜索与 GPTQ 式误差补偿交错耦合**：每个块提交量化后，其误差经阻尼逆 Hessian 因子回代传播到未来块，后续 scale 搜索在补偿后的权重上进行——消融表明误差补偿只有与 Hessian 感知搜索耦合时才持续有效。
- **方法格式无关**：同一套"合法码空间 + 量化器"抽象直接实例化到 MXFP4（E8M0 块指数）、NVFP4（E4M3 块码 + FP32 张量尺度）和 HiF4（E6M2 + 派生 E1 尺度），并可正交地与块 Hadamard 预处理叠加。
- **实验证明层级感知的 scale 选择优于局部张量拟合**：在 Qwen3-8B/14B × 三种 FP4 格式共 6 个 model-format 组中，最佳 SoScale 变体全部取得最高平均准确率；并给出部署友好的 direct-RTN 激活变体（SoScale-w），同样在所有组胜出。

## Key Contributions

- **Identify an outlier-induced scale mismatch in hierarchical FP4 quantization**: default range-preserving max-abs scaling stretches the 16-level FP4 grid to cover outliers, leaving extreme levels unassigned (on a real Qwen3-8B weight block, the two outermost representable levels receive no values) and starving the dense mass near zero of resolution.
- **Propose SoScale**, an offline second-order scale-code search: it scores each hardware-legal scale code c by a Hessian-weighted block loss ℓ_i,b(c) = e_i,b(c)^T H_b e_i,b(c) (with H_b the calibration-activation Hessian submatrix), directly optimizing layer-output fidelity rather than element-wise tensor error.
- **Interleave scale search with GPTQ-style error recovery**: after each block is committed, its error is propagated to future blocks via back-substitution through the damped inverse-Hessian factor U^T U = (H + λI)^{-1}, so subsequent scale searches run on compensated weights; the ablation shows recovery alone (with MSE search) gives mixed results, while the coupling with Hessian-aware search is what consistently wins.
- **A format-agnostic formulation**: given the legal scale-code set and quantizer of any hierarchical FP4 format, the same search-and-recovery procedure applies — instantiated for MXFP4 (E2M1 payload + E8M0 exponent, 4.25 bits/element), NVFP4 (E2M1 + E4M3 block scale + FP32 tensor scale, ≳4.5 bits), and HiF4 (E1M2 + E6M2/E1/E1 hierarchy, 4.5 bits) — and composes with block Hadamard preprocessing.
- **Empirically validate layer-aware scale selection across 6 model-format groups**: on Qwen3-8B/14B under W4A4 (7 tasks: GSM8K, HellaSwag, MMLU, ARC-C, ARC-E, BoolQ, PIQA), the best SoScale variant achieves the top average score in every group, beating RTN, GPTQ, local ScaleSearch, and BlockRotation; a deployment-oriented direct-RTN-activation variant (SoScale-w) also beats ScaleSearch-w in every group.

## Methodology

SoScale is a post-training quantization method that optimizes weight scale codes for a fixed pretrained model without retraining or altering the target FP4 format.

**Setup and objective.** For a linear layer Y = XW^T with calibration inputs X ∈ R^{T×n}, SoScale minimizes the layer reconstruction loss L = Σ_i e_i^T H e_i, where e_i is the row error and H = X^T X is the empirical Hessian. Unlike element-wise MSE, this objective penalizes weight errors by their effect on calibrated layer outputs.

**Hierarchical FP4 abstraction.** Each weight row is partitioned into format-specific blocks; a block is quantized as Q_F(w; c) with c drawn from the format's legal scale-code space (e.g., for MXFP4, an E8M0 exponent code c with scale s(c) = 2^c). Increasing s(c) expands covered range but coarsens level spacing; decreasing it contracts range and improves resolution near zero.

**Hessian-aware scale search.** Full joint optimization over all blocks is combinatorial (the Hessian couples blocks), so SoScale uses a block-local second-order surrogate: for block b with input indices I_b, H_b = H[I_b, I_b], and each candidate c is scored by ℓ_i,b(c) = e_i,b(c)^T H_b e_i,b(c). The candidate set C_{i,b} is a small format-specific offset window around the default scale code, clipped to the legal codebook range; each row-block pair picks c* = argmin_c ℓ_i,b(c).

**Second-order error recovery.** Following GPTQ, an upper-triangular factor of the damped inverse Hessian, U^T U = (H + λI)^{-1}, is precomputed. After block Q is quantized with the searched codes, its error E_Q is propagated to future columns F via W̃_:,F ← W̃_:,F − E_Q U^{-1}_{Q,Q} U_{Q,F}; the next scale search runs on these compensated weights. Search and recovery are thus interleaved per block.

**Activations and pipeline.** Activations use a lightweight online per-token dynamic FP4 rule (per-token-block scale chosen by element-wise MSE), or a direct RTN path in the deployment-oriented "-w" setting. Optionally, block Hadamard preprocessing (W ← WR, H ← R^T HR) is applied first. Token embeddings, LM head, and normalization layers stay in BF16. Calibration uses 128 sequences of 2,048 tokens from the first WikiText shard. Everything runs offline; inference uses only stored FP4 payloads and legal scale codes, keeping compatibility with existing FP4 hardware paths (no serving-time search).

## Results & Highlights

All numbers are W4A4 average scores over GSM8K (5-shot), HellaSwag, MMLU, ARC-C, ARC-E, BoolQ, PIQA (zero-shot) on the LM Evaluation Harness.

- **Best SoScale variant wins all 6 model-format groups.** Example (Qwen3-8B, NVFP4): SoScale reaches Avg. 0.7356 (98.99% of the BF16 reference 0.7431) vs 0.7281 for the strongest baseline ScaleSearch (+0.75 pp), 0.7257 for GPTQ, and 0.7262 for RTN. Example (Qwen3-14B, HiF4): SoScale 0.7652 (99.40% of BF16 0.7698) vs 0.7613 for GPTQ (+0.39 pp) and 0.7605 for ScaleSearch.
- **Largest gains under MXFP4**, whose coarse E8M0 power-of-two codes leave the most headroom: on Qwen3-8B MXFP4, SoScale w/ Had. achieves Avg. 0.7166 (96.44% of BF16) vs 0.7089 for the strongest baseline GPTQ (+0.77 pp) and 0.7056 for local ScaleSearch (+1.10 pp); RTN and BlockRotation both sit at 0.6971.
- **Gains over local ScaleSearch range from 0.47 to 1.10 pp; over the strongest non-SoScale baseline in each group, 0.21 to 0.77 pp.** BF16 retention across both models: 96.44%–97.17% (MXFP4), 98.99%–99.20% (NVFP4), 98.38%–99.40% (HiF4).
- **Direct-RTN-activation setting (SoScale-w vs ScaleSearch-w, Table 3)**: SoScale-w wins every model-format group by 0.08–1.92 pp average accuracy; e.g., Qwen3-8B MXFP4: 0.7195 (w/ Had., 96.83% BF16) vs 0.7003 for ScaleSearch-w (+1.92 pp); Qwen3-14B HiF4: 0.7662 (w/ Had., 99.53%) vs 0.7580.
- **Ablation (Table 4, Qwen3-8B) isolates the Hessian objective as the key ingredient**: adding GPTQ-style recovery to an MSE scale search (MSE + recovery) is marginal under MXFP4 (0.7061 vs 0.7056 ScaleSearch), actually *decreases* accuracy under NVFP4 (0.7270 vs 0.7281), and only helps HiF4 (0.7263 vs 0.7242) — whereas full SoScale (Hessian search + recovery) is best in all three formats (0.7092 / 0.7356 / 0.7295).
- **Motivating evidence (Figure 1)**: on a real Qwen3-8B weight block, scale search moves the MXFP4 scale from 0.125 to 0.0625, leaving default-scaling's two outermost levels unoccupied while substantially reducing mid-region (near-zero) element errors; and local element-wise scale search does not consistently reduce perplexity, while SoScale does.

## Authors & Credibility

The six authors (Pengxiang Zhao, Xing Li, Hui-Ling Zhen, Weizhe Lin, Xianzhi Yu, Zhenhua Dong) are all from Huawei Technologies Co., Ltd. — an industrial lab with an active record in efficient LLM inference (the last author's group has prior ICML work on non-uniform quantization, GANQ). The paper is a preprint (arXiv:2611.16426v1, 12 Nov 2026, cs.LG), formatted for a AAAI-style venue. The related-work coverage of very recent FP4 methods (Four Over Six, ScaleSearch, ARCQuant, HiF4, Block Rotation, QuaRot, SpinQuant) is current and fair, and the experimental protocol (LM Evaluation Harness, 128×2048-token WikiText calibration following GPTQ) follows standard PTQ practice. No code release is mentioned.

## Critical Assessment

- **Novelty**: The core insight — score discrete scale codes by Hessian-weighted layer error instead of block MSE, and interleave with GPTQ recovery — is a clean and well-motivated, if incremental, combination of known components (GPTQ's second-order machinery + ScaleSearch's discrete code search). The format-agnostic abstraction over MXFP4/NVFP4/HiF4 is the most novel part; the closest prior work (Four Over Six, ScaleSearch) is either format-specific or purely local.
- **Rigor**: The main claim ("best in every model-format group") holds, but margins over the strongest baseline are often small (0.21–0.77 pp) with no variance estimates, seeds, or statistical significance reported — single runs on 7 benchmarks. Notably, the flagship "consistent gains" summary partly relies on taking the *best of two SoScale variants* (with/without Hadamard) per group, a mild form of post-hoc selection: plain SoScale loses to GPTQ on Qwen3-8B MXFP4 (0.7092 vs 0.7089 is a tie at best, and ARC-C drops to 0.5000 vs ScaleSearch's 0.5171), and SoScale w/ Had. is worse than plain SoScale on Qwen3-8B NVFP4 (0.7308 vs 0.7356).
- **Reproducibility**: Setup is described in detail (calibration size, damping, benchmarks, harness batch size), but no code is released, the search-window size and damping λ values are never stated, and their sensitivity is unexamined — the method has at least two hyperparameters with no ablation.
- **Missing analyses**: no perplexity table in the main results (perplexity appears only qualitatively in Figure 1c); no measurement of offline quantization cost (Hessian computation plus per-block code search is strictly heavier than GPTQ, but by how much?); no calibration-data sensitivity; no evaluation beyond one model family.
- **Data quirks / weak spots**: BlockRotation is applied to NVFP4/HiF4 even though it was proposed for MXFP4 (disclosed, but it weakens that baseline outside its home format); and the paper itself observes that some direct-RTN activation rows exceed their searched-activation counterparts in Table 2 — an inconsistency of the online activation rule that is acknowledged but not resolved, and it slightly undercuts the W4A4 main-table framing.
- **Significance**: Practical and real — FP4 hardware paths (MXFP4/NVFP4) are shipping, and a drop-in offline scale search that keeps the format intact is exactly what deployment needs. But the evaluation breadth (2 Qwen3 models, 7B–14B scale) limits confidence that gains persist at 70B or across architectures.

## Strengths

- Directly optimizes the quantity that matters (layer-output fidelity) while staying inside the hardware-legal scale-code space — no format changes, no serving-time overhead, fully compatible with existing FP4 inference paths.
- Clean format-agnostic formulation, demonstrated on all three practically relevant hierarchical FP4 formats (MXFP4, NVFP4, HiF4) with a useful comparison table of their scale hierarchies.
- The ablation is genuinely informative: it shows MSE search + recovery can hurt (NVFP4: 0.7270 < 0.7281), pinpointing the Hessian-aware objective — not the recovery — as the source of the gains.
- The deployment-oriented "-w" setting (direct RTN activations) anticipates real hardware constraints and still beats ScaleSearch-w in every group (up to +1.92 pp).
- Honest reporting of format-dependent effects (Hadamard helps MXFP4 most; plain SoScale is best for NVFP4 on 8B and HiF4 on 14B) rather than a one-size-fits-all claim.

## Limitations

- Evaluation covers only two models from a single family (Qwen3-8B/14B); no Llama/Mistral-class or larger (70B+) models, so generalization is unverified.
- Gains over the strongest baseline are modest (as low as +0.21 pp average) with no error bars or repeated runs; per-task results show regressions in some cells (e.g., ARC-C on Qwen3-8B MXFP4 drops from 0.5171 with ScaleSearch to 0.5000 with SoScale).
- The "best variant" per group switches between SoScale and SoScale w/ Had. depending on format and model, so practitioners need a format-model-specific recipe; the paper offers a qualitative explanation but no selection rule.
- No runtime/cost analysis of the offline search (candidate-window size, added wall-clock over GPTQ), and no sensitivity study for the damping λ or the calibration set (single WikiText shard).
- Activation quantization remains a local heuristic (per-token MSE); the paper itself notes searched activation scales can be worse than direct RTN in some groups, indicating the activation side is under-optimized.
- No code release mentioned at the time of the preprint.

## Relevance

这篇论文与低比特量化、LLM 推理效率方向高度相关：它在不改变 MXFP4/NVFP4/HiF4 硬件格式的前提下，用二阶 Hessian 信息优化 scale 码选择，是 PTQ for LLM 部署的实用技术；对关注 FP4 量化、GPTQ 系误差补偿以及量化格式比较的工作有直接参考价值。

## Questions for Further Exploration

- Do the gains persist at larger scale (Qwen3-32B/235B, Llama-class models) and under stronger baselines that jointly optimize rotations and scales (e.g., learned rotations like SpinQuant combined with scale search)?
- What is the offline cost of SoScale relative to GPTQ and ScaleSearch (wall-clock and peak memory for Hessian construction plus per-block code search), and how does accuracy scale with the candidate-window size and damping λ?
- Can the activation side benefit from the same layer-aware treatment — e.g., jointly searching weight scale codes and activation scale rules — given that direct RTN activations sometimes beat the searched per-token rule in Table 3?
- Why exactly does Hadamard preprocessing help MXFP4 most and occasionally hurt NVFP4/HiF4 — can the E8M0 power-of-two quantization error be predicted analytically from block statistics, enabling an a-priori decision of when to rotate?
- Would replacing the block-local Hessian surrogate with a wider (multi-block or layer-global) coupling further close the remaining 0.8–3.6 pp gap to BF16, especially under MXFP4 where retention is still only ~96.4–97.2%?
