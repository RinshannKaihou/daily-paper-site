Bigger is not better:
static proxies predict cost,
but not precision.

Params, FLOPs and loaded-memory correlate almost perfectly with inference cost (Pearson R ≈ 0.95–1.0) — yet barely with precision (R ≈ 0.36–0.48). A four-objective Pareto front then proves the largest model is rarely the right pick at the edge.

01Methodology

Reproducible · Docker + cpupower · Intel RAPL

Models & benchmarks

6 quantized lightweight LLMs (default Ollama Q4):

  • TinyLlama-1.1B (Q4_0)  ·  Qwen2.5-1.5B (Q4_K_M)
  • Gemma-2B (Q4_0)  ·  Phi-2 2.7B (Q4_0)
  • Phi-3-mini 3.8B (Q4_0)  ·  Mistral-7B (Q4_K_M)

3 tasks: HumanEval (pass@1, all 164) · GSM8K (200/1319) · MMLU-Pro (280/12032). Sub-sampling compresses ~200 eval-days to ~7.

Measurement protocol

  • One warm-up run discarded; fixed cool-down interval between configs.
  • Greedy decoding (temperature = 0) — keeps precision deterministic across envelopes.
  • Accuracy judged outside the T/M/E window to avoid interference (Alg. 1–3).
  • Paired non-parametric stats: Cochran's Q + McNemar (precision) · Friedman + Nemenyi (continuous), α = 5%.

02Results & highlights

RQ1 · RQ2 · RQ3
R1Proxies track cost, not precision.

Across all envelopes, params/FLOPs/loaded-memory correlate strongly with T/tok, M and E/tok — but only weakly with precision. Even rank information is soft.

Rcost ≈ 0.95–1.0Rprecision ≈ 0.36–0.48Spearman ρ ≈ 0.524
R2Small models upset big ones.

On E1 HumanEval, Qwen2.5-1.5B is simultaneously more accurate, faster and greener than Mistral-7B. On GSM8K, Phi-3-mini leads (66.5% vs Mistral's 29.0%).

Qwen 48.8% vs Mistral 42.7%520 J vs 3372 J
R3Pareto front is task-specific.

No single model dominates on all four PTME axes. Non-dominated sets differ per benchmark — single-metric rankings would pick the wrong model.

HumanEval: {TinyLlama, Qwen2.5}GSM8K: +Phi-3MMLU-Pro: +Mistral
R4Tightening the envelope inflates latency more than energy.

E1 vs E5: per-token time balloons 5.3–6.3× and TTFT 4.8–8.1× — but energy only 2.7–3.5×. Wider envelopes run at higher average power; precision stays identical (deterministic decoding).

time 5.3–6.3×TTFT 4.8–8.1×energy 2.7–3.5×
R5Largest model is penalised hardest.

3D PTME trajectories show TinyLlama and Qwen2.5 clustered in the low-cost region across all envelopes, while Mistral drifts sharply into high-cost space as the envelope tightens — potentially cancelling its accuracy edge.

Implication: optimising latency ≠ optimising energy
R6"Statistical tie" is over-read on MMLU-Pro.

Mistral beats Qwen2.5 by 6.4 pts (34.6% vs 28.2%) yet is deemed non-significant on 280 items — a low-power read of equivalence that favours the cheaper model.

Δ 6.4 pts1 item ≈ 0.36 pts

03Strengths & limitations

Critical Assessment

+ Strengths

  • Precision promoted to a first-class axis alongside physical resources — escapes the Green-AI "energy-vs-accuracy" binary.
  • Rigorous comparison framework: four-objective Pareto + paired non-parametric stats — far stronger than "bold the max" tables.
  • Systematic envelope tightening (cores / freq / memory) makes RQ3 a genuinely quantifiable finding.
  • Full-stack reproducibility: fixed Docker stack + runtime hardware caps + public code + complete PTME tables.
  • Counter-intuitive practitioner insight: "latency inflates more than energy" + the edge double-energy-burden.

! Limitations

  • Desktop + Docker ≠ real edge HW. No ARM, no differing ISA or memory bandwidth; RQ3 is platform-relative only.
  • CPU-only. Omits Jetson / NPU / Apple-Silicon GPU-edge, where T/E/M behaviour differs substantially.
  • RAPL = CPU package only. DRAM, board, peripherals excluded; "directly measuring energy" is incomplete at system level.
  • Small model set (6, all ≤7B); no 7B–13B or MoE. Tasks are three objectively-judged benchmarks only — no open generation / agents / multi-turn.
  • Single backend (Ollama), single quant (Q4), greedy decoding. No Q5/Q8/FP16 or sampling exploration.
  • Mechanism gap: no root-cause split of "tighter envelope → higher average power" (freq? cache? memory BW?).

04Open questions for follow-up

Non-linear entry points
Does the PTME ranking — and the time/energy decoupling — survive on ARM (Pi 5, Snapdragon) or NPU (Jetson Orin, Apple ANE)?
If energy were measured system-wide (DRAM + storage + peripherals), would "latency inflates more than energy" flip? How representative is the RAPL CPU package?
How do Q5_K_M / Q8_0 / FP16 and backends (llama.cpp, vLLM, MLC-LLM) reshape PTME? Does default Q4 hide a better precision–energy knee?
Is the GSM8K Qwen-vs-Phi gap (53.5% vs 66.5%) significant at scale? Is 280-item MMLU-Pro powerful enough to license "non-significant = equivalent"?
Under sampling (T>0) precision becomes a random variable — how does the PTME variance structure change, and is E[pass@k] needed?
In multi-turn / agent / long-context settings, how do TTFT vs per-token cost rebalance, and does KV-cache memory become the new non-dominated constraint?
What is the mechanism behind "tighter envelope → higher average power" — frequency, cache hit-rate, or memory-bandwidth bottleneck — and can scheduling mitigate it?
