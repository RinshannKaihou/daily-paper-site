Key finding

VibeVoice-ASR is compressed 2.9× via heterogeneous quantization — INT8 for the VAE tokenizer, ternary BitNet weights for the LM — hitting real-time RTF < 1 on just three CPU threads.

通过对 VAE 分词器（全流水线 INT8）与 LM 解码器（BitNet 三值权重）做异构量化，模型从 4.62 GB 压缩到 1.58 GB（2.9×），仅用 3 个 CPU 线程即实现 RTF<1 实时识别。

Why this matters

Brings ternary-weight BitNet quantization to real-time multilingual ASR on commodity CPUs — private, offline, GPU-free speech recognition.

Privacy · Offline · Edge deploy
Critical edge

Validated on a single AMD EPYC 7V13 server CPU — real mobile / ARM edge SoCs untested — and the accuracy cost of the 7B → 1.5B shrink is never isolated from quantization.

⚠ Single hardware · un-decomposed loss

Methodology 01

Two ASR stages with opposite compute bottlenecks get opposite quant recipes.

Architecture

  • VAE tokenizer — acoustic + semantic ConvNeXt encoders (7 blocks each); 3200× time down-sampling, 24 kHz → 7.5 Hz.
  • LM decoder — autoregressive, Qwen2.5-1.5B (28-layer Transformer) replacing the original 7B.

I8_S — for the activation-bound VAE

  • Full-pipeline INT8: weights, activations, intermediates, every op boundary unified — no precision hops.
  • Driven by per-stage Act/W ratio up to 50,909× (16.4× aggregate): weight-only quant leaves the dominant memory path uncompressed.
  • INT4 rejected: pack/unpack overhead cancels IO gain, weak SIMD support, sharp ConvNeXt accuracy loss.

I2_S — for the weight-bound LM

  • BitNet ternary weights {−1, 0, +1} @ 2-bit; per-token online INT8 activation. 8× weight-traffic cut vs FP16.
  • Embeddings & LM-head use Q6_K (6-bit) since they map the full vocabulary.

Progressive QAT

  • x̂ = (1−α)·x + α·FakeQuant(x), α ramped 0 → 1; then trained fully quantized.
  • Direct QAT diverges (loss ≈ 3.3); progressive converges to ≈ 0.91. GELU swapped → ReLU for INT8 friendliness.

Inference kernels

  • Fused ops: im2col_asym, mul_mat_add_relu, add_scaled, rms_norm_scaled — kill intermediate tensors.
  • Unified maddubs → madd → hsum pipeline shared by I8_S & I2_S (online 2-bit → INT8 unpack); AVX2 + NEON, x86 & ARM.

Accuracy — vs 7B FP16 upper bound

  • MLC-EN WER 8.25 vs 7.82 (+0.43)
  • AMI-ihm WER 21.36 vs 17.42 (+3.94)
  • VoxPopuli WER 5.18 vs 4.92 (+0.26)
  • Typical degradation +1–4 % absolute WER; lowest WER/CER among equal-size models on MLC-EN, AMI, VoxPopuli.

Where the speed comes from

  • VAE I8_S: 1.3–2.0× over FP16.
  • LM I2_S: ~2.5× prefill, ~4× decode (batch=1 is pure weight-IO — the 8× weight compression pays off most).

Strengths & limitations 03

Strengths

  • Principled, not blind — Act/W-ratio analysis justifies the heterogeneous split.
  • Progressive QAT fixes a real divergence; the α-blend recipe is transferable.
  • Deep engineering — op fusion, SIMD, ARM+x86, and fully open code & weights.
  • 1.6–2.3× over Whisper.cpp at equal size is directly useful for CPU ASR.

Limitations

  • Scheme validated only on VibeVoice-ASR — other VAE-LM / encoder-decoder ASR untested.
  • Offline batch only; no streaming (chunked VAE + incremental LM).
  • 7B → 1.5B shrink vs quant cost not decomposed.
  • Single server CPU; no real edge / mobile device numbers.
  • Multilingual lead is thin — most baselines don't cover MLC's non-EN/ZH languages.

Open questions 04

Where the work points next — for follow-up research.

  1. Ported to Whisper / Qwen-Audio-style VAE-LM, does I8_S still beat W8A32? What is the accuracy–cost curve?
  2. Can an ablation (1.5B-FP16 vs 1.5B-I2_S vs 7B-I2_S) cleanly split the shrink cost from the quant cost?
  3. How to deliver streaming chunked VAE + incremental LM at RTF<1 — and handle chunk boundaries under 3200× down-sampling?
  4. Real mobile ARM SoC RTF, power, memory — is a 3-thread budget realistic on a low-end quad-core?
  5. Is there a better mixed-precision point between Q6_K and ternary for attention projections?

Reproducibility

Code and weights are public — the heterogeneous-quant claim is independently checkable, not just a paper assertion.
