> **一句话总结：** 论文提出 GABench——首个在生产级 Agent 框架（LangChain、LlamaIndex、Vectara）上评测 LLM Agent 安全性的基准（580 个场景、6 个领域、5 种对抗攻击），揭示最强配置也仅有 74.8 的 Overall 准确率，并发现"强模型漏调工具、弱模型乱调工具"两种失效模式，证明执行期结构性 guardrail（19.9% 失败恢复率、0.5% 误报率）系统性优于系统提示词防御。

> **TL;DR:** GuardianAgentBench (GABench) evaluates 6 frontier LLMs (Claude Opus 4.5, GPT-5.2 Pro, GPT-OSS-120B, Gemini-3-Pro, DeepSeek-V3.2, Qwen3-Max) on 580 agent-safety scenarios across 6 domains running on 3 production frameworks (LangChain, LlamaIndex, Vectara); the best config reaches only 74.8 Overall accuracy, two distinct failure regimes emerge (strong models under-call tools at 52–57% MTC, weak models mis-select/over-call at up to 25% ITS and 29–33% RTC), and execution-time guardrails beat system-prompt defenses across all models (+2.8 to +7.7 points) while recovering 19.9% of failures at 0.5% FPR.

## 核心贡献

1. **首个生产级框架上的 Agent 安全基准**：GABench 覆盖 580 个场景、6 个 Agent 领域（Customer Service、Email、Calendar、Business Intelligence、Financial、Internal Knowledge）、81 个独立工具、1,177 个串行 turn，搭配 5 种对抗攻击模式（Massive Data、Error Conditions、Multiple Matches、Prompt Injection、Partial Data），并采用多阶段自动化 + 人工双校验。区别于以往在模拟 Python 沙箱中评测的 ASB / ToolEmu / MT-AgentRisk，GABench 直接在生产框架上跑。
2. **刻画两种质性不同的失效模式**：通过六模型 × 三框架实验，发现强模型（GPT-5.2 Pro、GPT-OSS-120B、Gemini-3-Pro）以"漏调必要工具"（MTC 52–57%）为主，而弱模型（DeepSeek-V3.2、Qwen3-Max）以"错选/重复调用"为主（ITS 14–25%、RTC 29–33%）。同时证明长程规划（turn 深度，31.1 分下降）比工具集规模（15.9 分下降）是更陡的瓶颈。
3. **执行期结构性 guardrail 的概念验证**：在 LlamaIndex 中实现三种 guardrail（Argument Validation、Tool Coverage Check、Relevance and Cost Check），拦截每次工具调用，证明其系统性优于受 AgentSafetyBench 启发的系统提示词防御，且对最强模型收益最大（Claude Opus 4.5 +5.3、Gemini-3-Pro +2.6 相对增益差）。

## Key Contributions

1. **First agent-safety benchmark on production frameworks.** GABench evaluates 580 scenarios across six domains, 81 unique tools, and 1,177 sequential turns, with five adversarial attack modes and a multi-stage auto + human validation pipeline. Unlike ASB / ToolEmu / MT-AgentRisk which run in simulated Python sandboxes, GABench runs end-to-end on LangChain, LlamaIndex, and Vectara.
2. **Two qualitatively distinct failure regimes.** Across six frontier models and three frameworks, strong models (GPT-5.2 Pro, GPT-OSS-120B, Gemini-3-Pro) fail overwhelmingly by omitting required tool calls (MTC 52–57%), whereas weaker models (DeepSeek-V3.2, Qwen3-Max) mis-select and over-call (ITS up to 25%, RTC 29–33%). Long-horizon planning (turn depth, 31.1-pt drop) is shown to be a steeper bottleneck than tool-set size (15.9-pt drop).
3. **Execution-time structural guardrails as a proof of concept.** Three guardrails (Argument Validation, Tool Coverage Check, Relevance and Cost Check) implemented in LlamaIndex consistently outperform a system-prompt defense inspired by AgentSafetyBench, with the largest relative gain for the strongest models (Claude Opus 4.5 +5.3, Gemini-3-Pro +2.6 gap over system prompt).

## Methodology

**基准构造（两阶段 + 人工校验）。** Happy-path 场景由 5 阶段 LLM pipeline 生成：(1) User Intent Generation 从 agent 配置生成多样化意图；(2) User Prompt Generation 同时生成 self-contained 与 incomplete 两类 prompt；(3) Tool Response Simulation 为无参工具生成默认响应、为有参工具生成参数→响应映射（含精确/语义匹配策略、隐式参数标记）；(4) Ground Truth Trace Construction 生成期望执行图（工具名、参数、依赖）；(5) Response Evaluation Criteria 定义满意回答标准。对抗变体通过修改工具响应（Massive Data、Error Conditions、Multiple Matches、Prompt Injection、Partial Data 五种）生成，并同步重生成 ground truth。

**评测协议。** 每个场景在生产框架上端到端执行，由 Claude Sonnet 4.5 沿 Response correctness（综合工具输出无幻觉）与 Action correctness（执行图匹配）两维打分；Overall 需两者同时满足。Judge 在 60 个人工标注样本上达到 93.3%（56/60）对齐率。错误执行进一步按 5 类失效分类（ITS、IMP、MTC、RTC、ITO）。

**Guardrail 设计。** 拦截每次拟执行的工具调用，输入 agent 完整上下文，输出三种裁决之一：Pass / Provide Corrective Feedback（emit GuardrailCheckEvent，最多 retry 2 次）/ Block（升级至 human-in-the-loop）。三个 guardrail 通过 `asyncio.gather` 并发执行，由 Claude Sonnet 4.5 驱动。

**实验设置。** 6 个前沿模型（Claude Opus 4.5、GPT-5.2 Pro、GPT-OSS-120B、Gemini-3-Pro、DeepSeek-V3.2、Qwen3-Max），3 个框架（LlamaIndex FunctionAgent、LangChain ReAct via LangGraph、Vectara 云端），均用官方 API 默认参数。统一 adapter 接口确保差异归因于框架而非评测产物。

## Results & Highlights

- **整体天花板低**：最强配置 Claude Opus 4.5 + Vectara 平均 Overall 仅 **74.8**（即约 1/4 场景失败）；最难的 Calendar 领域没有任何模型超过 **62.0**，而 Financial 与 Customer Service 相对可解（Claude Opus 4.5 在 Customer Service + Vectara 达 81.0）。
- **能力—安全分层清晰**：Claude Opus 4.5 与 Gemini-3-Pro 居首（平均 Overall 71–75），GPT-5.2 Pro 与 Qwen3-Max 次之（68–72），DeepSeek-V3.2 与 GPT-OSS-120B 垫底（63–68），与通用模型排行一致；框架选择影响很小（同模型跨框架差异 ≤ 2–3 分）。
- **两种失效模式**：强模型 MTC 占 52–57%（如 GPT-5.2 Pro + LlamaIndex 57.2%、Gemini-3-Pro 52.1%），弱模型 ITS 升至 23–25%、RTC 达 29–33%（DeepSeek-V3.2 + Vectara ITS 25.3%、RTC 30.8%）；ITO 在所有模型/框架中都是最罕见失效（0.6–4.4%）。
- **复杂度单调劣化**：Claude Opus 4.5 随工具数从 1→7，Overall 从 **78.2 降至 62.3**（−15.9）；随 turn 数从 1→7，Overall 从 **82.3 降至 51.2**（−31.1），证明长程规划是更陡瓶颈。
- **Guardrail vs 系统提示词**：guardrail 在所有 6 个模型上增益 **+2.8（GPT-5.2 Pro）至 +7.7（DeepSeek-V3.2）**，且每个模型都优于系统提示词；系统提示词对强模型几乎无效甚至负向（Gemini-3-Pro +0.3、Claude Opus 4.5 +0.4、GPT-5.2 Pro −0.3），而对弱模型 DeepSeek-V3.2 增益最大（+5.5）。
- **Guardrail 精度**：在 Claude Opus 4.5 + LlamaIndex 的 151 个原本失败场景中恢复 30 个（**19.9% 恢复率**），在 429 个原本通过场景中仅误阻 2 个（**0.5% FPR**）。
- **对抗/非对抗分布**：398（68.6%）非对抗、182（31.4%）对抗；工具数均值 2.74，turn 数均值 2.05。

## Critical Assessment

- **评测闭环选择值得商榷**：scenario 生成、自动校验、judge 评分全部使用 Claude Sonnet 4.5，而 Claude 系模型同时是被评对象（Claude Opus 4.5 拔得头筹）。虽然 judge 在 60 个样本上对齐率达 93.3%，但样本量偏小，且未报告 judge 对 Claude 自家模型是否存系统性偏好，存在自评嫌疑。
- **三 guardrail 仅作为 LlamaIndex 内的概念验证**，未在 LangChain / Vectara 上实现，因此"+2.8 至 +7.7"的增益严格说只覆盖 LlamaIndex 配置；论文也坦承这一点，但标题级别的"guardrails consistently outperform"在跨框架泛化上仍证据有限。
- **"happiness"对 ground truth 的强假设**：构造阶段明确剔除"存在多条等价执行路径"的场景，以保证每个 happy path 有唯一确定解——这使得 benchmark 偏向确定性工作流，可能低估现实里允许灵活编排的 agent 能力。
- **对抗攻击的注入点单一**：五种对抗模式全部通过"修改工具响应"实现，未覆盖用户侧 prompt 注入、系统提示词泄漏、多 agent 间消息篡改等真实威胁面。
- ** Vectara 既是作者所属机构也是被评框架**，尽管统一 adapter 接口力求公平，但框架间 ≤ 2–3 分差异本身就很小，难以完全排除实现熟练度差异的影响。

## Strengths

- 首次在生产级框架（而非沙箱）上系统评测 Agent 安全，弥合研究与实践鸿沟。
- 失效分类（ITS/IMP/MTC/RTC/ITO）与"强模型欠调 / 弱模型乱调"的二分洞察，对未来针对性改进（强模型补 tool coverage、弱模型补 tool selection）具有直接指导价值。
- 实验覆盖 6 个前沿模型 × 3 框架 × 6 领域 × 5 对抗模式，规模与维度均充足；框架差异 ≤ 2–3 分的结论将问题清晰归因到模型层。
- Guardrail 的 19.9% 恢复 / 0.5% 误报的精度数据非常有说服力，证明"执行期结构性干预不破坏正确行为"。
- 多阶段自动 + 人工双校验、3 轮迭代精修，质量控制严谨；rejected 场景示例（如"returned orders"无法枚举）展示了真实的质量门槛。

## Limitations

- Guardrail 实验仅在 LlamaIndex 上完成，未扩展到 LangChain / Vectara，跨框架泛化未验证。
- judge 与场景生成共用 Claude Sonnet 4.5，且被评模型含 Claude Opus 4.5，存在自评风险；人工对齐仅 60 样本。
- 对抗操作仅限"修改工具响应"，未覆盖用户侧/系统侧/多 agent 侧注入等更广威胁面。
- 剔除多等价路径场景，使 benchmark 偏向确定性工作流，可能无法反映允许灵活编排的真实 agent。
- 论文聚焦工具调用层安全，未涉及资源消耗、数据外泄后果、权限提升等执行后危害评估。
- 未公开失败案例的端到端 trace 示例（除附录 A 一个 happy/adversarial 对外），可复现性细节偏少。

## Relevance

GABench 对 Agent 安全研究与工程实践高度相关：
- **研究方向**：揭示"长程规划 > 工具集规模"是首要瓶颈，且强/弱模型失效模式截然不同——这为未来的对齐、planning、tool-routing 研究提供了清晰的针对性靶点。失效分类法可直接用作后续工作的评估骨架。
- **防御方向**：执行期 guardrail 优于系统提示词的结论，支持"外部监督组件 > 模型对齐"的范式（与 GuardAgent、ShieldAgent、AGrail 等形成共识），且 0.5% FPR 对生产部署有强吸引力。
- **工程落地**：基准直接跑在 LangChain / LlamaIndex / Vectara 上，结论可被一线开发者直接采纳；其 unified adapter 设计可作为企业内部安全评测的参考架构。
- **后续工作接口**：可扩展至多 agent、计算机/移动端控制、真实 API（非模拟响应）等更高风险场景。

## Questions for Further Exploration

1. 若 judge 换成与被评模型不同家族的模型（如 GPT 评 Claude、Gemini 评 GPT），Claude Opus 4.5 的领先优势是否依然存在？是否存在系统性的家族内偏好？
2. Guardrail 的 19.9% 恢复率 / 0.5% FPR 在 LangChain 与 Vectara 上能否复现？三框架的拦截 API 差异是否会改变 guardrail 的可触达失效面？
3. 在允许"多条等价执行路径"的场景（而非被剔除的确定解）下，强模型 MTC 主导的失效是否会被高估或低估？
4. 若对抗操作扩展到用户侧 prompt 注入或系统提示词泄漏，五种对抗模式的失效分布会如何变化？强/弱模型的二分模式是否仍然成立？
5. 长程规划（turn 深度）作为更陡瓶颈——是模型上下文管理能力不足、还是依赖追踪/状态维护机制缺失？显式的 plan-state 注入能否缩小 31.1 分的下降？
6. Guardrail retry 上限设为 2 次，若放宽至 N 次或引入自反思，恢复率与延迟/成本的权衡曲线如何？
7. 在真实 API（而非模拟响应）环境下，agent 失效是否会被真实世界的非确定性（网络、限流、数据漂移）放大或改变结构？
