01

Methodology

3-stage pipeline · LangGraph

Given dataset D and natural-language query q, produce analysis function f whose validity depends on untestable identification assumptions (parallel trends, exclusion, continuity). A valid analysis must estimate accurately when assumptions hold and explicitly declare them.

PI · Reviewer
STAGE 01
Automated study design
Adversarial PI–Reviewer loop (gpt-5.2), Tavily + Chroma RAG, ≥2 review rounds enforced.
planner · coder
STAGE 02
SCM synthetic data
Plans failure scenarios (DiD/RDD/IV violations); builds effect-present & null datasets with known ground truth.
spec/planner/coder/auditor/fixer
STAGE 03
Code gen + adversarial validation
Iterative quality gates: syntax → smoke → auditor → synthetic-data test; up to 12 iterations, ground-truth isolated.
  • Engineering safeguards. Ground-truth isolation, external method verification, design-consistent diagnostics, version-controlled intermediate states.
  • Evaluation. Automated Causal Reasoning Benchmark, 33 cases via stratified round-robin; baseline = vanilla Claude Opus 4.6 single-script generation.

03

Strengths & Limitations

honest, self-critical reporting

↑ Strengths

  • Novel framing. Identification assumptions as executable adversarial tests, not prose — clean and transferable.
  • Honest negatives. Documents where ARA underperforms vanilla (vague-prompt error, missing CIs) without overselling.
  • Reproducible. Anonymized code repo, full hyperparameter & model-version tables, stratified case selection.
  • Domain-grounded. Target-trial-emulation orientation; flags immortal time bias, informative censoring, outcome misclassification.

↓ Limitations

  • n = 33. Single events (e.g. the vanilla sign flip) are not statistically robust; CIs on fractions are wide.
  • Validity flags ≠ ground truth. LLM-generated "concerns" are hypotheses, not verified diagnostics.
  • Model-dependent. Whole pipeline hinges on gpt-5.2 + claude-opus-4.6; no cross-model robustness study.
  • Cost & complexity. ~85× cost premium; final checkpoint ≠ approved script (may just be budget-exhausted).

Questions for Further Exploration

open threads
  1. Validity-flag accuracy. If "causal-validity concerns" were independently audited by experts, what fraction are true positives?
  2. Scaling. Does the 0/33 sign-flip edge hold across the full benchmark and beyond (e.g. ICE-CREAM pitfalls)?
  3. Model & prompt robustness. Sensitivity to LLM choice, phrasing, and the 12-iteration budget?
  4. Auditing vs. convergence. Can the auditor be adaptive — enforcing compliance only on non-blocking dimensions?
  5. Cost-effectiveness threshold. For which users (clinicians, methodologists, students) is the safety premium worth ~85×?
  6. Approved vs. non-approved terminal outputs. Accuracy/safety gap between converged and budget-exhausted runs?
