Tells practitioners which interpretability findings transfer across code models — and which must be re-localised per model.

SCOPE
Critical edge

01Methodology

A 2×2 factorial: language × model, over a shared concept inventory

Two languages (Python, Rust) crossed with two independently-trained code models (Qwen2.5-Coder-7B, DeepSeek-Coder-V1-6.7B) — the minimal design that separates task-, language-, and model-dependent variation. The unit of analysis is a structured concept inventory: 58 Python + 57 Rust testable grammatical constructs, measured identically in all four cells.

For each concept, concept prompts place the construct in its structural role and checker prompts place the same token elsewhere (strings, comments, names); ~50 of each, with variance along lexical / structural / padding axes. Marginalising across variants washes out incidental features, leaving the concept.

  1. 1 · Prompt gen
    concept vs checker prompt families, 50 each
  2. 2 · Extraction
    MLP output at last token, every layer, single forward pass
  3. 3 · Binarisation
    active if |a| > ε; ε = 0.5 used throughout
  4. 4 · Marginalisation
    universal mask A = ∩ active sets; checker mask B
  5. 5 · Decomposition
    concept-only A\B, shared A∩B, token-only B\A — concept fraction = |A\B| / |A|

The same Python & Rust concepts live in a late band in Qwen and an early band in DeepSeek — the offset holds within each model across both languages. Circuit placement and growth dynamics are model-determined; only the concept ranking transfers.

03Strengths

  • Minimal, exact design. The 2×2 is precisely large enough to expose the What/Where/How separation, with orthogonal language and model axes.
  • Principled common yardstick. The concept inventory sidesteps the per-model basis problem of sparse autoencoders, making cross-model numerical comparison meaningful.
  • Radically honest reporting. Marginal/null clusters and the failed Break ablation are published alongside the strong type-trait cluster; the degenerate consistency parameter is disclosed.
  • Best-in-class reproducibility. Frozen extraction, a locked-number test suite (±0.005), one script per figure, ~24 GPU-hours on a single A100.
  • Strikes past its target. The Rust type-trait cluster recovers a semantic dimension invisible in surface syntax and the AST.
  • Actionable rule. "What transfers vs what must be re-localised" is an immediate decision rule for porting interpretability work.

04Limitations

  • Causal scope. Double-dissociation runs on Qwen × Python only; DeepSeek, Rust and cross-language claims are correlational and geometric.
  • Sub-threshold structure missed. The binary ε = 0.5 mask sees only high-amplitude neurons; probes decode concepts where ablation has no effect (concept-only sets < ~20 neurons).
  • Imperative languages only. Generalisation to declarative languages or proof assistants (Lean) is open.
  • Layer-count mismatch. Qwen 28 vs DeepSeek 32 layers; body comparisons use absolute indices — a stated choice.
  • Degenerate consistency parameter. For these dense SwiGLU models the second binarisation parameter does no work; the sweep shrinks to ε alone, with ε = 0.5 justified post hoc.
  • Only two models. Enough to show the axes separate, but cannot test the two-styles dimensionality claim or third-model predictions.

05Open questions for further work

Q1Does the two-styles fingerprint (late/sharp vs early/smooth) predict a third model's band, flow type and cross-language sharing? The author's own "designed next test" — the cleanest falsifier.
Q2What drives the Where/How divergence — corpus, architecture, initialisation, or training trajectory? A checkpoint-resolved developmental study could isolate the factor.
Q3Does the Rust type-trait cluster (Jaccard 0.535, p<0.001) appear in models trained with little or no Rust — an intrinsic attractor, or a training artifact?
Q4Does the What/Where/How decomposition survive natural language, where the concept inventory is far messier? Named as the method's "eventual home" but untested here.
