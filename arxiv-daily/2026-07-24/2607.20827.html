Why This Matters

Separates "relevant" from "authorized" — surfacing benign residues (stale memory, neighboring records) that outcome-correctness benchmarks miss.

Critical Edge

The same-role matched control reverses the comparison (−0.018): the "excess" may stem from competition semantics, not authorization — weakening strong isolation claims.

Methodology 01

Source response

Vary only provenance authority (trusted vs. untrusted); observe target-score & action change.

Isolation

After degrading valid evidence, can an unauthorized competitor still move the action?

Localization

Which factor coalitions show non-additive score dependence on unauthorized rivals?

Target labeling

Per target×factor: authority × relation → Valid / Invalid / Neutral / Excluded.

Target score

Log-odds over token sequence for fixed target y; pairwise, string & token-fixed.

Partial-evidence interaction

Exact Harsanyi/Shapley over all subsets (256 for 8 factors); empty- & full-context anchors.

  • Suite: 450 tasks · 1,350 targets · 10,800 labels (AgentAudit-250 + Tau2Audit-100 + BFCLAudit-100).
  • Annotator reliability: 3 external PhD labelers, blind; invalid/non-invalid agreement 0.854 (κ=0.626); 4-label Fleiss κ=0.608.
  • Models: Qwen3-4B/30B, Mistral-Small-3.2-24B, Llama-3.3-70B (main); DeepSeek-V2-Lite, Ministral-8B (extended).

Strengths & Limitations 03

▲ Strengths

  • Disentangles relevance from authorization, and source-response from behavioral isolation.
  • Target-specific labeling captures the multi-layer structure of agent context (one record, different authorization per target).
  • Triangulates 4 estimators (LOO, matched, Shapley, empty/full anchors), each scope-bounded.
  • Honest boundary statements throughout (stress-set ≠ deployment rate).
  • Commits to releasing data, labels, prompts, code, seeds, relabeling logs.

▼ Limitations

  • Exact enumeration only feasible for short factor sets; 12/16 factors need pairwise screening.
  • Score audit relies on open-weight token probabilities — closed APIs get only weak forced-choice proxies.
  • 2.4% is a controlled stress rate, not a natural deployment prevalence.
  • Role-matched reversal (−0.018) & full-context near-zero (−0.004) bound the coalition diagnostic.
  • Human factor decomposition & target-specific labels not invariant to arbitrary refactorings.

Critical Assessment 04

The core value: separating "correct" from "legitimate" — a tool call can be outcome-correct yet still score-sensitive to stale memory or an unauthorized note. Three layered findings support it:

  • Score layer: DID +0.481, positive in every model — provenance authority is a real causal proxy, not noise.
  • Behavior layer: 5.4% vs 1.7% competing/supporting, plus the strict retained-invalid pattern at 2.4%, directly show an unauthorized rival flipping the action after valid evidence is removed.
  • Structure layer: Shapley excess positive in all 12 runs (+0.027), yet full-context transform ≈ 0 (−0.004) — the authors treat the "cliff" as an honest scope limit, not a buried caveat.

Likely reviewer pressure points: stress-vs-deployment gap; the role-matched reversal; sample composition bias toward sensitive scenarios (self-authored AgentAudit-250).

Questions for Further Exploration 05

  1. Deployment prevalence. Can real agent logs (enterprise mail, customer-service systems) measure the actual density of unauthorized competing context, converting the 2.4% stress rate into a deployment error estimate?
  2. Role-matched reversal mechanism. Why does same-role control drive fractional excess to −0.018 — true insensitivity to authority, or insufficient statistical power? Needs finer ablation.
  3. Closed-model proxy protocols. Beyond forced-choice, can logit-bias APIs or multi-sample consistency extend this audit to GPT-4o / Claude / Gemini?
  4. Train-time vs. inference-time fix. If authorization is a training target (DPO with unauthorized-competitor flips as negatives), can we cut both the 5.4% disagreement and 2.4% retained-invalid rate?
  5. Long trajectories & evolving memory. Can Shapley approximation be maintained incrementally across multi-turn ReAct / A-Mem traces, isolating which turn injected the unauthorized dependency?
  6. Target-label conflict structure. Can the tool-vs-argument authorization conflict be weaponized as an attack surface — injecting unauthorized values only at a specific argument?
