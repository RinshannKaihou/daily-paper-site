Why this matters

If your pipeline auto-evolves prompts, rules, or tools and keeps them by accuracy alone, it is probably retaining strategies that are logically wrong.

对“用 LLM 自动生成规则、并按准确率保留”的一切自我改进工作，都有直接方法论警示价值。

⚠ Critical edge

The +4.4 headline is carried by two benchmarks — 81% of the gain from FANToM + SimpleToM alone — and on seven test-only benchmarks the reader loses to plain self-consistency, 65.2 vs 66.2.

Methodology — three layers

CogRSI separates procedure evolution, principle evolution, and a grounded test-time reader, then audits what the loop actually learned.

C1 · Grounded reader (test time)
Annotate who perceived each event
→
6 reads: 4 annotated + 2 plain (= SC k=6 budget)
→
Conflict / close split? Arbiter decides under written principle
→
Answer — a 5-6 vote consensus is never overturned
C2 · RSI over principles (training)
Dev failures on ExploreToM
→
Builder writes library of ≤5 conditioned rules
→
Register only if gain > +3 pts over 3×80 fresh trials (one variant adds a 96-pair counterfactual gate)
↺ loop repeats; 181/183 evolved tools encode perceptual access
C3 · Semantic audit
Each learned rule
→
2 independent LLMs translate to applies()/predict() code
→
Run on ~85k questions over 6,000 formal worlds
→
Same wrong answer twice ⇒ rule invalid

Backbone: Qwen3.5-35B-A3B (also 122B, Llama-3.3-70B, GLM-4.6V-Flash, 9B). All loops train only on ExploreToM; evaluation spans 8 benchmarks (3,349 main + 2,470 confirmatory questions), 7 test-only benchmarks, and 800 never-seen BigToM-U pairs.

Transfer, 800 unseen BigToM-U pairs (pair validity): gated library 96.6 > expert principle 94.5 (CI +1.0…+3.5) > SC(k=9) 93.0 > GEPA 84.4 — every learned principle beats the human-written one.

  • The gate is a null: gated − accuracy-only on test Main = −0.2 (CI −1.4…+0.8). Evolution, not counterfactual gating, drives transfer.
  • Margin discipline, not the gate: raising the registration margin 1→3 pts lifts genuinely helpful updates 63.6%→83.3% and halves harmful ones (31.8%→16.7%).
  • Audit roll-up: invalid among decided kept rules — 14/14 (accuracy-only loop), 5/5 (accuracy-only library), 7/9 (gated library), 3/4 (gated single principle). Trial gains separate nothing.
  • Dev gains don't carry: the evolved principle wins on new dev questions (63.8 vs 59.7) yet loses test Main (71.8 vs 73.1).
  • Open frontier: backward belief inference (belief from action) unsolved for every system — ~68.0% pair validity, 37.2% on flip pairs, no principle helps.

Strengths

  • Crisp dissociation — behavioral usefulness ≠ semantic validity; a cautionary, general lesson for the self-improvement literature.
  • Evaluation discipline — pre-registered contrasts, confirmatory samples, held-out counterfactual pairs, fully unseen transfer set (BigToM-U).
  • Constructive audit — interpretable counterexamples (the sleeping character) trace each error to a blind spot in the training generator.
  • Honest costs, broad robustness — 7.3 calls / 1.51× tokens reported; beats SC(k=9) on all five backbones (+5.1 to +8.6 on a 4-benchmark mean).
  • Public code, data, prompts, and scripts that regenerate every figure and number.

Limitations

  • One generator, narrow worlds — loops train only on ExploreToM; the audit model covers one-room physical access + testimony (no desires, emotions, higher-order beliefs).
  • Audit inherits translation noise — two LLM translators “can still miss what a rule's author meant,” even with the shared-counterexample guard.
  • Underpowered arms — 3–6 seeds; some arms missing on some test sets (Table 1).
  • Concentrated gains — English, mostly synthetic benchmarks; conversation-heavy suites dominate Main; test-only transfer slightly negative.
  • Backward belief inference unsolved (~68.0% / 37.2% flip pairs) for every system.
  • Audit-in-the-loop registration proposed but unimplemented — a replay suggests few candidates would pass.

Questions for further exploration

  1. Would rejecting invalid candidates inside registration improve test Main — or starve the loop of admittable candidates, as the replay suggests?
  2. Do the 13.3% valid rules differ linguistically (generality, hedging, condition specificity) from invalid ones — can a validity predictor be trained from audit counterexamples?
  3. Does the usefulness/validity dissociation persist under more diverse training generators, or is it an artifact of ExploreToM's narrow event space?
  4. Can the formal world model extend beyond one-room physical access to desires, emotions, and multi-party dialogue?
  5. Is the conditioned-rule format even load-bearing — would a single unconditioned heuristic match the library (conditions removed: only −0.5 on BigToM-U)?
  6. Is 86.7% invalidity actually bad — how would the human expert principle score under the same audit?
