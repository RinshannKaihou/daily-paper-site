> **一句话总结：** ProCerDCL 用单个序贯统计检验（Clopper–Pearson 校正区间或 anytime-valid 置信序列）对"编译后模型与参考模型决策不一致的概率是否低于阈值 θ"给出三值（接受/拒绝/不确定）且带方向性错误预算的黑盒验证，在与 PROVERO 相同数值参数下节省 3.6–4.2 倍采样，并在 840 个 TorchInductor/TensorRT 输入–后端实例上以 θ=10⁻³ 得到 817 个接受、19 个不确定、4 个拒绝，还用两个真实编译器缺陷（Torch-TensorRT #3674、#4379）展示了拒绝判决的诊断价值。

> **TL;DR:** DL compilers (TorchInductor, TensorRT) can reorder floating-point ops and flip predictions, and differential testing on fixed inputs cannot bound how often this happens. ProCerDCL certifies, via a single sequential test (no interval family), that the violation probability p of a binary oracle satisfies p ≤ θ (YES), p > θ + η (NO), or returns NONE, with direction-specific error budget δ. On paired one-model clean-label radius searches the PROVERO baseline needs 3.6–4.2x as many unique samples (e.g., 348.7k vs 82.6k draws on ResNet-18/CIFAR-10 under Inductor) while satisfying only a weaker indifference-zone contract (forced-decision like-for-like: 2.30–2.41x). Pointwise reference-vs-compiled consistency checks at θ = 10⁻³ over 840 input–backend instances from 21 tasks yield 817 YES / 19 NONE / 4 NO; a real Torch-TensorRT interpolation-swap bug (issue #3674) is rejected on 30/30 inputs while the patched build certifies YES on 30/30. The catch, which the authors themselves demonstrate: the celebrated robustness radius is model-dominated (correlation 1.000 with the uncompiled reference model), so the compiler-relevant signal is the two-model disagreement density, which needs millions of executions at tight thresholds (θ = 10⁻⁴).

## 核心贡献

- **将 DL 编译优化验证形式化为概率阈值验证问题**：给定固定可采样的输入分布 D 与二元违反预言机 ψ（如"参考模型与编译模型对同一输入预测不一致"），定义 p = Pr[ψ(x)=1]，并给出三值判决契约——接受断言 p ≤ θ、拒绝断言 p > θ + η（η 为分离裕度）、不确定（NONE）表示证据不足，每个方向的错误判决概率均被误差预算 δ 控制。
- **提出比基线 PROVERO 更严格的契约，且用单个序贯检验实现**：关键洞察是"验证只需确立阈值断言，无需把 p 估计到指定绝对精度"，因此在每个检查点用置信上界 U_t ≤ θ 判接受、置信下界 L_t > θ + η 判拒绝；重复检查通过按联合界校正的精确 Clopper–Pearson 区间或 anytime-valid 置信序列（Beta(1/2,1/2) 混合 + Ville 不等式）保持覆盖率，从而无需 PROVERO 的自适应区间族与误差预算分配，并给出方向性可靠性定理与 Chernoff 型有限采样上界。
- **大规模跨编译器实证（24 个任务、2 个后端、3 个文本分类器）**：系统评估采样效率、结论性与参数敏感性，覆盖量化（INT8）、跨硬件（RTX 6000 Ada vs A4500）、L∞ 与补丁/词元替换等非范数球分布——只需更换采样器即可保持同一保证。
- **诚实区分"单模型鲁棒性半径"与"双模型语义一致性"**：通过参考模型对照实验证明认证半径主要由模型自身噪声敏感度主导（相关系数 1.000），因此编译器一致性必须用双模型（点-wise 不一致 / 参考稳定）性质评估；并用两个真实编译器缺陷（插值模式交换、fp16 channels-last Linear 误编译）展示局部判决（拒绝/接受/弃权）的诊断语义。
- **经验假阳性率验证**：在 12 个已知密度的合成流上各跑 1000 次验证，带外 10,000 次运行零错误判决（合并单侧 95% 上界 0.06%，低于 1% 预算），带内 2000 次仅 1 次判决（恰在 p = θ+η 处）。

## Key Contributions

- **Problem formulation**: first framework (to the authors' knowledge) for black-box probabilistic verification of model semantic consistency between reference and compiled executions under a specified input distribution, with direction-specific error guarantees: Pr[YES ∧ p > θ] ≤ δ and Pr[NO ∧ p ≤ θ + η] ≤ δ under independent sampling (A1), black-box oracle access (A2), and a stateless oracle (A3).
- **Query-efficient single sequential test**: eliminates PROVERO's adaptive interval family; stopping decisions are based on bounds whose coverage holds across checkpoints (union-bound-corrected exact Clopper–Pearson intervals, or an anytime-valid confidence sequence via Ville's inequality), with a Chernoff-derived truncation cap bounding worst-case cost (Theorem 3.1). A stricter contract than the baseline's indifference zone — any decisive answer inside (θ, θ+η] counts as an error, so abstention is the intended outcome there.
- **Optional compatibility mode with ablations**: interval scheduling, inverse-width error allocation, and a shared observation pool that turns the family's cost from a sum into a max; ablations show removing reuse costs 1.96–2.21x draws and uniform allocation 1.17–1.23x.
- **Empirical evaluation across models and compilers**: 24 image tasks (LeNet-5, ResNet-18/34/50, VGG-16-BN, DenseNet-121, MobileNetV2, ViT-B/16, DeiT-Small on MNIST, CIFAR-10/100, SVHN, ImageNet-1k) plus BERT-base/DistilBERT text classifiers, under TorchInductor and TensorRT; quantization, cross-GPU, L∞, token-substitution, and 3×3 patch distributions; injected constant-folding faults and two documented real bugs.
- **Self-critical diagnostics**: reference-model controls showing the clean-label radius is model-dominated (95.1–99.8% of counted flips also flip the reference), oracle audits for batch-composition independence, seed-stability studies, and an empirical false-certification-rate experiment.

## Methodology

ProCerDCL verifies whether the violation probability p of a binary oracle ψ under a fixed distribution D meets a threshold. For model semantic consistency the oracle is ψ(x, C, M) = I[C(x) ≠ M(x)] — the compiled and reference executions disagree at the decision level on the same input; a "reference-stable" variant counts the joint event that the reference keeps the seed label while the compiled model leaves it. Local instantiations use D = Unif(B_q(x₀, ε) ∩ X), q ∈ {2, ∞}, around a seed input; text uses fixed-length token substitutions with embedding neighbours; other supports (e.g., a 3×3 image patch) are allowed since only the sampler changes.

The core is Algorithm 2 (SequentialTest): draw Bernoulli observations in batches of B (default B = 1, GPU evaluation batch 256), and at each checkpoint t compute a two-sided confidence interval [L_t, U_t] for p; stop with YES if U_t ≤ θ, NO if L_t > θ + η, else continue to a Chernoff-derived cap N (Eq. 3, O(log(1/δ)/η²)); return NONE at truncation. Error control under repeated checking uses either exact Clopper–Pearson intervals with per-checkpoint budget δ/T (union bound, Corollary 3.3) or an anytime-valid Beta-mixture confidence sequence. Soundness (Lemma 3.4, Theorem 3.1): a wrong YES requires an upper-bound coverage failure, a wrong NO a lower-bound failure, so each direction's error is bounded by δ. An optional interval-family mode (Algorithms 1, 3–5) reproduces the PROVERO-style family with inverse-width budget allocation and prefix reuse of a shared observation pool (soundness by union bound over the pre-registered family, Lemma 3.6/3.7); forced-decision variants (…-F) that guess at truncation satisfy only the baseline's weaker contract and are reported separately. A radius search probes ε = 0, doubles to a cap, and bisects to resolution 0.1, reporting the largest tested radius certified YES. Protocol defaults: θ = 1%, η = 0.5%, δ = 1%, seed 123, one search per input; 8× RTX 6000 Ada GPUs.

## Results & Highlights

- **Query efficiency vs PROVERO (paired, matched θ/η/δ, one-model clean-label radius searches, 50 inputs × 4 settings)**: PROVERO consumes 375.0k / 348.7k / 473.0k / 508.5k unique draws vs 102.3k / 96.0k / 131.5k / 142.5k for ProCerDCL-CP and 90.7k / 82.6k / 118.9k / 130.3k for the anytime-valid CS variant (LeNet-5/MNIST-TensorRT, ResNet-18/CIFAR-10-Inductor, VGG-16-BN/SVHN-Inductor, ResNet-34/SVHN-TensorRT) — 3.6–4.2x fewer samples, though under different decision contracts; the like-for-like forced-decision comparison gives 2.30–2.41x (CS-F vs PROVERO). Wall-clock on the paired cohort: 0.3–6.5 s (CS) vs 0.8–25.9 s (PROVERO).
- **Consistency verdicts at θ = 10⁻³**: across 840 input–backend instances (20 inputs × 21 non-ImageNet tasks × TorchInductor/TensorRT, each at its ε_Hard under uniform L2), 817 certify YES, 19 return NONE, 4 are rejected, after a median of 13,312 double-execution draws; Inductor's pointwise disagreement density exceeds TensorRT's on 19 of 21 tasks (medians 4.1×10⁻⁴ vs 6.6×10⁻⁵), while architecture (ViT vs CNN) matters little.
- **Tight thresholds expose separation (Table 3)**: at θ = 10⁻⁴ and full radius, reference-stable certification passes 50/50 inputs on ResNet-34/SVHN but only 12/50 on ResNet-18/CIFAR-10 (24 rejected) and 40/50 on VGG-16-BN/SVHN, at 682.4k / 1,584.8k / 903.1k mean draws — i.e., millions of model executions; at half the radius all 199 inputs certify. The main single test reaches the same verdicts as the interval family with 0.58–0.90 of its draws (0.25 on rejections).
- **Fault detection (real bug, Torch-TensorRT issue #3674 interpolation-mode swap)**: the buggy engine flips 52/10,000 clean predictions with reference-stable density 6.5×10⁻² (per-input 3.8×10⁻³–0.34) and is rejected on 30/30 inputs after a median of ~1,000 draws; the patched engine agrees on 10,000/10,000, density 5.7×10⁻⁶, YES on 30/30. Second bug (#4379, fp16 channels-last Linear miscompile): buggy engine flips 1,942/10,000, density 0.17 overall (0–0.99 per input) — rejected on 21/30, NONE on 6, YES on 3; workaround engine 9,997/10,000, density 3.1×10⁻⁵, YES 30/30.
- **Injected miscompilation sweep (ResNet-18/CIFAR-10, Inductor)**: a clean test set is nearly blind — a 2% constant-folding fault changes 0/1000 predictions, a 120% fault only 18/1000 — while the reference-stable density rises monotonically from 2.5×10⁻⁴ to 3.8×10⁻² over nine fault magnitudes (4×10⁶ draws each, even the 2% fault raises density by half, z = 10.5); at θ = 10⁻³ the 20% fault is rejected on 16/30 inputs vs 30/30 YES for the clean build.
- **Empirical error rate**: 1,000 synthetic verifications at each of 12 known densities: zero wrong decisive verdicts in 10,000 out-of-band runs (pooled one-sided CP 95% bound 0.06% < 1% budget) and 1 in 2,000 in-band runs (a NO at exactly p = θ + η); near threshold the certifier abstains on 88–100% of streams, away from the band it answers on 1000/1000.
- **Radius–attack agreement and its limits**: certified radii correlate positively with the white-box compilation-inconsistency attack budget on 46/48 task–backend cells (significant on 42 at 5% level, mean Pearson 0.55–0.56, Spearman 0.63), but the reference-model control shows the radius is model-dominated (correlation 1.000, median per-input difference 0.00); seed stability on LeNet-5/MNIST-TensorRT: 20/20 verdicts unchanged over 10 seeds, median ε_Hard 6.28–6.65.
- **Configurations**: conclusive on 397/400 simulated-INT8 inputs; real TensorRT INT8 engines 100/99 of 100 conclusive (Pearson 0.82/0.76 vs attack); radii reproduce across RTX 6000 Ada vs A4500 at correlation 1.000; on the 3×3 patch distribution, 199/200 certificates conclusive with Spearman 0.80/0.89.

## Critical Assessment

- **Novelty**: the statistical machinery is standard (exact binomial intervals, union bounds, confidence sequences, statistical model checking à la PROVERO/SPRT); the genuine contribution is the stricter three-valued contract (decisive answers inside (θ, θ+η] are errors, not free passes) realized by a single sequential test, plus the first instantiation of probabilistic verification to reference-vs-compiled consistency. This is a solid, well-scoped contribution rather than a conceptual breakthrough.
- **Rigor**: strong. Direction-specific soundness proofs, a finite truncation cap, an empirical false-certification study matching the 1% budget, oracle audits for batch-composition independence, ten-seed stability, and Holm-corrected significance tests. The contract mismatch with PROVERO is handled with unusual honesty — the 3.6–4.2x headline is explicitly flagged as cross-contract, with the 2.30–2.41x forced-decision like-for-like number reported alongside.
- **The model-dominated radius undercuts one headline use case**: the paper's own reference-model control shows the clean-label radius correlates 1.000 with the uncompiled model's radius and that 95.1–99.8% of counted flips also flip the reference — so the one-model robustness results (INT8, cross-hardware, L∞) validate the verifier, not the compiler. The compiler-relevant two-model densities (10⁻⁵–10⁻⁴) are near the resolution limit of plain Monte Carlo: Table 3 shows up to 1,584.8k draws (3.2M executions) at θ = 10⁻⁴ on ResNet-18/CIFAR-10, and the authors concede importance sampling / multilevel splitting is future work.
- **Fault evidence is anecdotal**: exactly one injected fault type (single-layer constant folding on ResNet-18/CIFAR-10) and two cherry-picked documented bugs; the paper admits "two cases do not establish comparative detection recall," and clean differential testing also exposes both real bugs. The stronger claim — perturbation-neighbourhood density detects faults a clean test set misses (2% fault: 0/1000 clean flips but +50% density, z = 10.5) — is demonstrated only for the injected model.
- **Selection and coverage caveats (mostly self-acknowledged)**: radius–attack agreement is computed on attack-success inputs only (MobileNetV2/CIFAR-10 carries almost no signal at r = 0.05); ImageNet-scale ResNets show r between −0.07 and 0.20; one sampling seed outside the ten-seed study; a radius search spends δ per probe, so a whole search carries only 68–78% confidence unless the budget is split (1.49–1.54x cost); bisection assumes p(ε) monotonicity, with an explicit counterexample given.
- **Reproducibility**: good — public GitHub repo, all numerical parameters stated, per-task tables fully disclosed (Table 2), and the verification protocol (θ = 1%, η = 0.5%, δ = 1%, B = 1, batch 256) is specified in enough detail to re-run.
- **Significance**: practical value is real but conditional: as a regression gate ("does this build's disagreement density stay below θ around these seeds?") it is immediately usable; as a compiler-verification technique it certifies distributions, not equivalence — a YES explicitly permits rare violations and implies nothing about unchecked inputs.

## Strengths

- A clean, stronger-than-baseline statistical contract with proofs, and an implementation that is actually cheaper (3.6–4.2x fewer samples) rather than paying for strictness with more queries.
- Three-valued output (YES/NO/NONE) is the epistemically right design: near-threshold cases abstain on 88–100% of streams instead of guessing, while away from the band it is decisive 1000/1000.
- Genuinely broad evaluation: 24 image tasks plus 3 text classifiers, two compiler backends, quantization (simulated and real INT8), two GPU generations, and four distribution families — all handled by swapping the sampler.
- Exceptional self-criticism: the reference-model control that shows the radius is model-dominated, the cross-contract caveat on the headline speedup, and the named threats-to-validity section build real trust.
- Honest separation of what a verdict means (a bound for one distribution and oracle) from what it does not (global equivalence, compiler correctness).

## Limitations

- Verdicts hold only for the specified distribution, oracle, and execution configuration (TensorRT's batch-size-dependent kernel selection ties each certificate to batch 256; audits found 4/25,088 and 1/25,600 decision changes at batch 1).
- Cost explodes at tight thresholds: θ = 10⁻⁴ requires 0.4–2.0 million draws per cohort (each draw = two executions); rare-event estimators are left as future work.
- Inconclusive probes consume 61% of the main test's draws and 43% of searches end on a NONE probe inside the band — the price of the stricter contract.
- No guidance on selecting seeds, thresholds, or margins; the framework "neither selects seeds, calibrates thresholds, nor diagnoses faults," and no regression workflow is evaluated.
- Fault detection is illustrated with two documented bugs and one injected fault pattern; comparative recall against differential testing is unmeasured.
- Agreement-with-attack claims rest on attack-success inputs, one seed, and drop to r ∈ [−0.07, 0.20] on ImageNet-scale subjects; unclipped uniform perturbations are a test distribution, not deployment traffic, and token substitutions need not preserve meaning.

## Questions for Further Exploration

- Can importance sampling or multilevel splitting bring θ = 10⁻⁴ two-model checks from millions of executions down to a practical regression-gate budget?
- What is the actual detection recall of density-based rejection versus clean-set differential testing across a large corpus of historical DL-compiler bugs (e.g., from NNSmith/fuzzer issue trackers)?
- How should seeds, θ, and η be chosen automatically — e.g., calibrating θ near a build's historical disagreement density, or concentrating samples on inputs where the reference model is itself unstable?
- Does the contract survive oracles with batch/execution-state dependence (TensorRT kernel selection by batch size), for example by defining the certificate over the randomized batch composition itself?
- Can the three-valued sequential test be combined with worst-case (complete) verification or randomized smoothing to give both distributional and adversarial guarantees on compiled models?
- Does the approach extend to non-classifier outputs — LLM token streams, detectors, diffusion models — where a decision-level oracle is harder to define?
