LLM agents assume a tool call that returns did its work — this “return assumption” fails silently, and Receipt repairs it.

一句话：关闭输入时 11.5% 的交互式命令返回 status 0 却没做动作（假成功）；开放输入则令 token 消耗放大 2.9 倍并扭曲 LLM 排名。Receipt 从系统调用读取进程真正等待的对象，把 5 个 LLM 的假成功声明从 34 降到 9，每次检测中位开销仅 0.54 毫秒。

Why this matters

False success is a real failure mode for agents operating web services — and harness input wiring silently reorders LLM leaderboards (Kendall's τb = 0.47).

distilled from the Relevance section

▲ Critical edge

The “−24.4% tokens” headline is measured against a plain terminal — against closed input, Receipt actually costs ~80% more tokens (4.4M → 7.9M).

closed input is “cheap” precisely because it skips the work

Methodology

measure → detect → verify — a harness wrapper, no changes to agent or programs

01

Measure

Instrument 91,469 production tool calls (6 developers, 19 repos) and 89,047 public trajectories; probe 8 harnesses for how they connect stdin headless. Litmus catalogs 158 checked interactive invocations; WaitAtlas (4,855 commands) shows pre-launch wait prediction caps at AP 0.477 — waits must be caught at run time.

02

Detect

Receipt keeps stdin open but never answers. Every 0.1 s it samples each thread's syscalls, waited-on descriptors, and CPU ticks; a read/poll on the controlled pipe or tty becomes a confirmed wait after 1 s of silence with ≤5 CPU ticks. The receipt reports program, prompt, read class (password / line / keypress / full-screen) and marks earlier effects unverified.

03

Verify & evaluate

Input / interrupt / report ordering is model-checked (TLA+/TLC, 499 states, 7 properties) and tested in Docker with real tmux; plugged unmodified into mini-SWE-agent and Terminus 2, against closed input, plain terminal, text hints, a trajectory classifier, an outcome monitor, and DeepSeek's stdin inspector — 3 reps, task-paired bootstrap.

Strengths

what this paper gets right

  • First to define, measure at scale, and repair a failure mode every shell-driven agent has — but that no benchmark scores.
  • Minimal-pair benchmark design (trap vs control differ in exactly one change) makes the causal cost of a question cleanly measurable — a template for agent evaluation.
  • Matched-streams ablation isolates the receipt text itself as the gain: 161 → 174 trap successes, 20 → 8 false successes vs detector-only.
  • Model-checked intervention protocol (TLA+/TLC, 7 invariants, counterexamples when rules are removed) instead of ad-hoc synchronization.
  • Real deployment with measured per-call latency, plus an honest threats-to-validity section (benchmark–detector co-design risk stated).

Limitations

where to read carefully

  • Tripwire is small (25 pairs) and self-authored; 8 open-weight LLMs, no frontier closed models, all at temperature 0.
  • The Terminus-2 “25/25” headline rests on single runs — no repetitions, no variance reported.
  • Detector assumes quiet waits: npm spinners and sub-second waits slip through; 15% of Litmus waits go unreported.
  • Linux-centric syscall sampling; Windows validated on only 26 native cases; macOS not addressed.
  • Costs ~80% more tokens than closed input (4.4M → 7.9M); interruption kills the process tree, losing interactive session state.

Questions for further exploration

open threads worth pulling

  • Does the receipt format generalize beyond the shell — to non-shell tools like HTTP APIs that block on confirmation tokens?
  • Would frontier closed models show the same −73.5% false-success reduction, or do they already infer waits from silence in tool output?
  • Can a spinner-aware heuristic replace the 1-s-quiet + ≤5-tick rule and recover the remaining 15% of unreported waits (incl. 3 npm cases)?
  • What would a “harness-normalized” Terminal-Bench 2.0 leaderboard look like — should input connection be a first-class reported variable?
  • Does returning process state transfer to async function calling, where a returned call id implies a started job?
