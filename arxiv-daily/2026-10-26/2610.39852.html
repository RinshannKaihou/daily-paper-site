Key Finding · DWISE · arXiv 2610.39852

DWISE cuts diffusion-LLM serving latency 5.4× by ranking requests on remaining denoising work — not AR-inherited prefill priority.

以「剩余 prefill 块数 + 预估去噪轮数」统一度量剩余工作量并做 SRPT 抢占调度；用第一轮去噪后的隐藏状态免费校准估计，dLLM 服务平均端到端延迟较 SGLang 默认策略降低 5.4×（最高 14.9×），任务精度保持在 1 分以内。

Key Metricvs SGLang v0.5.20

5.4×

geometric-mean latency reduction across 10 model × arrival settings on one GH200 — up to 14.9× on SDAR-8B (9,053 s → 609 s); throughput up to 2.2×.

Why This Matters

Existing serving stacks waste diffusion LLMs' speed; DWISE ships as a SGLang runtime patch today — and its free first-round workload signal transfers to cost-aware routing.

Critical Edge⚠

Gains are architecture-bound: on DiffusionGemma — where prompt encoding can't share a round — the speedup collapses to 1.1×, and 44% of long-context requests finish later than under SGLang.

01

Methodology

runtime patch · SGLang v0.5.20

Built on two measured facts: after one denoising round, remaining work becomes far more predictable than from the prompt (Spearman ρ 0.74 → 0.87); and in block-diffusion models a prefill block and a denoising block fill the same batch slot at equal cost — so neither phase deserves priority.

Ri = Pi + r̂i P = exact unprocessed prefill blocks · r̂ = estimated remaining denoising rounds

One scale lets SRPT compare a still-prefilling request with one already denoising. Every round packs B = 128 slots with the smallest-R requests, mixing phases; outranked requests pause with KV cache resident on GPU. Resident set capped at k·B = 1,024 with KV reservations, so preemption never deadlocks memory. Model, kernels, KV manager, and CUDA graphs untouched — total overhead 2.1% of the 95 ms median round.

03

Strengths

what holds up
  • Exploits a clean structural fact — prefill and denoising blocks cost the same — with minimal machinery: a runtime patch, no kernel or memory-manager changes.
  • One round of hidden states lifts rank correlation with remaining work from ρ 0.74 to 0.87 (0.16 → 0.64 within a category) and generalizes to unseen categories where prompt features are useless.
  • Overhead engineered to near-noise: 2.1% of a round; predictor is 0.01% of model size, run on the forward stream with no extra sync point.
  • Honest, mechanism-level diagnosis of why each baseline fails, plus an oracle bound showing 84% of achievable headroom captured.
  • Wins across every model, arrival pattern, GPU count, and output budget tested, with task accuracy within one point.
04

Limitations

read before adopting
  • Architecture-dependent: where prompt encoding is a separate pass (DiffusionGemma), mixed-phase batching is impossible — 1.1× mean latency, throughput −2.4%, p99 worse under burst+Poisson.
  • SRPT fairness: 44% (burst) / 39% (burst+Poisson) of long-context requests finish later individually; no SLO-aware variant explored.
  • Single GH200 per instance, no pipeline parallelism, no real production traces; gains shrink to 1.9–4.5× at low load. The 14.9× headline is inflated by synthetic 10K-token prompts (3.7% of requests, 40.7% of work).
  • Per-model, per-budget predictor retraining required (2,048 profiled FCFS requests each time).
  • Code promised but not yet released at submission time.
05

Questions for Further Exploration

open threads
  • Does the one-shot estimate go stale under decoding accelerations that change round counts dynamically (KV-cache reuse, confidence thresholds, parallel decoding)?
  • Can the first-round hidden-state signal predict more than round count — per-block difficulty, revision hotspots — enabling block-level SRPT within a request?
  • What fairness mechanism (SLO- or age-boosted Ri) preserves the 5.4× mean win while guaranteeing no long-context request regresses?
  • Does the approach transfer to remasking / self-correction diffusion, or non-block diffusion LLMs where output length and round count entangle differently?
  • Can the 2,048-request per-model training set shrink further, or be shared across a model family?
