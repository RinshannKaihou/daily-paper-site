> **一句话总结：** RoboArchitect 用一个编程模型（claude-opus-5）观察冻结 VLA 策略的 rollout 轨迹、诊断失败模式并迭代改写策略外围的 agent harness（最多 5 轮、平均成本低于 150 美元），不更新任何权重就把 11 个基准×策略组合的留出集平均成功率从 9.7% 提到 43.3%（unseen scenes，4.5×）、从 12.7% 提到 40.2%（unseen tasks，3.2×），且 harness 会自发演化出持久记忆（如按物体高度比例记录有效抓取深度，每 episode 读取 3.4–13.0 次、92–99% 命中）。

> **TL;DR:** Stanford's RoboArchitect replaces hand-written robot agent harnesses with an automated loop: a coding model (claude-opus-5, ≤5 iterations, <$150 avg.) reviews full rollout traces of a frozen VLA policy, diagnoses failures, and rewrites the harness code around it — no weight updates. Across 11 benchmark×policy setups (LIBERO-Pro-10, RoboCerebra, VLABench, RoboCasa-365, SimplerEnv WidowX), mean held-out success rises from 9.7% to 43.3% on unseen scenes and 12.7% to 40.2% on unseen tasks versus the bare policy; on VLABench the evolved harness around general X-VLA hits 52.6% (unseen scenes) vs 35.2% for the same policy finetuned on VLABench, and on SimplerEnv WidowX 87.5% vs 70.8% finetuned (though on WidowX unseen tasks it loses to finetuning, 66.7% vs 87.5%). The harness also evolves its own persistent memory (e.g., grasp depths as a fraction of object height) that survives into held-out episodes. Simulation only; biggest gains are where the bare policy is at/near zero.

## 核心贡献

- **把 harness 设计变成自动化优化问题**：以往 VLA 机器人 agent（VoLo、Harness VLA 等）的外围控制代码全靠人工设计、每个机器人/基准重写一遍；RoboArchitect 用编程模型复刻人类工程师的"跑—看—诊断—改代码"循环，从零演化出完整的 harness（初始状态只是冻结策略的直通透传）。
- **证明不调权重也能"特化"**：在策略完全域外（out-of-domain）的设置下，演化出的 harness 常常超过在同一基准上微调过的同一策略——为"采数据+微调"这条传统适配路径提供了廉价替代（一次演化 <6 小时、平均 <$150，无需采集任何演示）。
- **统一了 code-as-policy 与 VLA 两种范式**：优化过程自主决定控制权分配——策略有用就保留策略，策略完全没信号（如 X-VLA 在 SimplerEnv WidowX 上恒定输出张开夹爪）就演化为纯视觉 code-as-policy agent；微调专家策略表现好时则正确地保留策略、仅在失败时接管。
- **持久记忆的自主涌现**：不指定任何记忆模式（schema），harness 自己决定存什么、怎么存、怎么取。涌现出可复用执行经验（按物体实测高度索引的有效抓取深度、每个物体成功的握法）、任务/环境线索（哪些指令需要持物、RoboCerebra 每 150 步的场景重置周期）、以及跨本体校准（记录各机器人手指闭合方向以校正腕部姿态）。
- **跨本体统一 harness**：单个 harness 在 2,201 个程序化生成 episode 上演化，即可同时服务 Franka Panda、WidowX、Google 移动操作臂三台机器人，运行时从动作规格与本体感知读取差异，不硬编码本体常数。

## Key Contributions

- **Automates robot agent harness design**: where prior agentic-VLA systems (VoLo, Harness VLA) hand-write the orchestration code per robot/benchmark, RoboArchitect runs the human engineer's trial-and-error loop automatically — a coding model reviews complete execution traces (per-step camera frames, robot readings, all tool outputs), diagnoses failure modes, and proposes harness revisions, starting from a bare pass-through of the frozen policy.
- **Shows harness optimization can substitute for finetuning**: wrapping an out-of-domain general policy (X-VLA), the evolved harness often beats the same policy finetuned on the target benchmark — on VLABench and SimplerEnv WidowX unseen scenes — at a cost of <6 hours and <$150 average coding-model time, with zero demonstrations collected.
- **Empirically unifies code-as-policy and VLA policies**: the coding model is never told how to divide control; the evolved harness decides autonomously, from ignoring a useless frozen policy entirely (X-VLA on WidowX) to keeping finetuned specialists in charge and intervening only on failure.
- **Persistent memory emerges without any prescribed schema**: evolved memories include effective grasp heights indexed by measured object height, per-object grip styles (pinch vs. spread), which instructions require holding objects, the 150-step scene-reset period of RoboCerebra, and cross-embodiment finger-closing calibration — read 3.4–13.0 times per held-out episode with 92–99% actionable reads.
- **A single unified harness generalizes across embodiments**: evolved once on a pool of 2,201 procedurally generated episodes, one harness operates Franka Panda, WidowX, and the Google mobile manipulator, reading embodiment differences at runtime rather than hardcoding constants.

## Methodology

RoboArchitect optimizes the **harness** — the program sitting between environment observations (camera images, depth maps, gripper pose/status, language instruction) and low-level action vectors — around a **frozen** VLA policy.

- **Initialization**: the harness starts as a pure pass-through (forward observations to the policy, return its actions), so the "Bare Policy" baseline is just standard policy evaluation.
- **Auxiliary tool API**: the harness may call pretrained tools — Qwen3-30B-A3B-Instruct (language), Molmo2-8B / Qwen3-VL-8B (vision-language), Grounding-DINO (detection), SAM 3 (segmentation), Molmo2-8B (pointing), GraspGen (grasp poses) — plus geometric utilities projecting pixel-depth pairs into 3D robot-base coordinates and generating relative trajectory primitives.
- **Optimization loop (≤5 iterations)**: run the current harness on the "training" episodes with full trajectory logging; claude-opus-5 (via Claude Code, maximum effort) reviews the traces, diagnoses failure patterns, and proposes a candidate revision; the candidate is accepted only if it beats the current harness on the same training episodes, enforcing a monotonic optimization trajectory.
- **Persistent memory**: an empty memory is provided at the start of each evaluation and persists across episodes at execution time, as data structures inside the agent (not the coding model's context). No schema or storage/retrieval rules are imposed.
- **Evaluation protocols**: every harness is scored on held-out episodes never used for optimization, under (1) **unseen scenes** — same tasks, permuted scene arrangements; (2) **unseen tasks** — different tasks sharing underlying manipulation skills; (3) **unified harness** — one harness across LIBERO-Pro, VLABench, SimplerEnv WidowX/Google, evolved on procedurally generated episodes, evaluated on the benchmarks' standard episodes. Setups are further characterized by training-source distance: in-distribution, spatially swapped, cross-benchmark, out-of-domain.

## Results & Highlights

- **Headline (Table 1, 11 setups)**: mean held-out success rises from **9.7% (bare policy) to 43.3% (evolved harness) on unseen scenes (+345%, 4.5×)** and from **12.7% to 40.2% on unseen tasks (+216%, 3.2×)**; restricted to cross-benchmark/out-of-domain setups the jump is 7.3% → 58.4% and 6.3% → 48.7%.
- **Beats finetuning in 3 of 4 protocol cells (X-VLA)**: on VLABench the harness around general X-VLA reaches **52.6% unseen scenes / 72.5% unseen tasks vs 35.2% / 32.1%** for the same policy finetuned on VLABench; on SimplerEnv WidowX it wins unseen scenes **87.5% vs 70.8%** but loses unseen tasks **66.7% vs 87.5%** (0.0% bare policy in all four cells).
- **Large per-setup gains**: RLinf-π0.5 on LIBERO-Pro-10 unseen scenes 2.0% → 40.0% (+38.0); SmolVLA on RoboCerebra unseen tasks 26.0% → 80.0% (+54.0); OpenVLA-7B on LIBERO-Pro-10 0.0% → 26.0% / 22.5%. The single failure case is RLDX-1 on RoboCasa-365 unseen scenes: 27.9% → 27.8% (−0.2), an in-distribution policy with little harness headroom.
- **Iterative refinement matters (Table 1)**: the one-shot design averages 21.4% on unseen scenes; iterating to 5 revisions roughly doubles it to 43.3%, and some one-shot designs fall below the bare policy on held-out sets while iterative ones surpass it nearly everywhere.
- **Persistent memory is actively used (Table 3)**: held-out episodes read memory 3.4–13.0 times per episode with 92–99% actionable reads; e.g., the grasp-depth memory learned that closing the gripper at 18% of object height lifts nothing while 45% (1.4 cm on the carrot, 3.9 cm on the eggplant, ≥0.8 cm floor) succeeds — and every evaluation starts from an empty memory, so the memory *design* is what transfers.
- **Unified cross-embodiment harness (Table 2)**: around general X-VLA (1.9% bare held-out), the unified harness reaches 28.8% held-out / 41.6% training-pool (+1417% / +2228%); around finetuned specialists it correctly preserves competence (45.9% → 47.0%). An arrival-based move-termination routine (vs fixed time budget) alone raised the training-pool success on the slower Google robot from 11.0% to 30.2%.
- **Cost**: a full 5-iteration evolution takes <6 hours of coding-model time and averages <$150, with no demonstrations collected and no weights updated.

## Authors & Credibility

Stanford University team (Shengguang Wu, Suning Huang, Cherie Ho, Ria Doshi, Hao Zhu, Serena Yeung-Levy — the Yeung-Levy lab, active in robot learning and embodied AI), with a public project page (roboarchitect-ai.github.io). The experimental design is unusually careful for a systems paper: a strict train/held-out split for harness optimization (the exact overfitting trap one would expect is explicitly controlled), two generalization protocols, finetuned reference checkpoints evaluated on identical held-out sets and step limits, and an honest taxonomy of training-source distance. Related-work coverage of 2025–2026 agentic-VLA and automated-code-optimization literature is thorough and positions the contribution precisely.

## Critical Assessment

- **Novelty**: genuine and timely — prior agentic-VLA systems (VoLo, Harness VLA) hand-design the harness, and prior LLM-optimization loops in robotics (Eureka, ENPIRE, EXIMO) automate *finetuning artifacts* (rewards, configs, data) rather than the inference-time agent itself. The closest prior finding (Berman et al. 2026: coding models do better with high-level access to policies) is a special case RoboArchitect rediscovers automatically.
- **Rigor caveats**: the finetuning comparison covers only two setups (X-VLA on VLABench and SimplerEnv WidowX), and "often outperforms the finetuned version" is really 3 of 4 protocol cells — on WidowX unseen tasks finetuning clearly wins (87.5% vs 66.7%). There is also **no memory-off ablation**: memory reads are 92–99% actionable, but the causal contribution of memory to success rate is never isolated, so "persistent memory" in the title rests on illustrative cases plus access statistics.
- **Confounded gain source**: on the most spectacular results (X-VLA on WidowX: 0% → 87.5%) the harness *bypasses the useless frozen policy entirely* and becomes a code-as-policy agent built on a strong tool stack (Grounding-DINO, SAM 3, GraspGen, Molmo2 pointing). The paper is transparent about this and frames it as unifying the paradigms, but readers should note that in these cells the gains come from the tool stack, not from "wrapping the frozen policy".
- **Metric mixing**: VLABench numbers are official *progress scores* with partial credit, folded into the "mean success rate" rows alongside binary success rates on other benchmarks — flagged in a footnote, but it slightly muddies the 43.3%/40.2% headline.
- **Split subjectivity**: the unseen-task splits are author-designed so that held-out tasks "share underlying manipulation skills" — a reasonable but unverifiable judgment call that all policies share.
- **Reproducibility**: good on benchmarks/checkpoints (public, standard LIBERO/VLABench/SimplerEnv/RoboCasa suites, finetuned checkpoints public) and costs are reported; but the optimizer is a proprietary frontier model (claude-opus-5 at "maximum effort"), so exact reproduction depends on access to it, and per-episode *runtime* cost (VLM/detector/pointing calls at execution time) is not reported.
- **Red flags**: none severe — the paper itself surfaces the RLDX-1 failure case (−0.2) and the WidowX unseen-tasks loss to finetuning rather than hiding them.

## Strengths

- Reframes adaptation of robot policies: harness design as a cheap (<$150), weight-free alternative to demonstration collection and finetuning, with a clean automation recipe (trace review → monotonic candidate acceptance).
- Rigorous held-out evaluation under two generalization axes (unseen scenes, unseen tasks) plus a cross-embodiment unified-harness protocol — precisely the tests hand-tuned systems usually skip.
- Fully interpretable revisions: each accepted change targets a named failure mode (jam detection and clearing, side approach under a shelf, force rescaling for door latching, redirecting to the named object instead of a memorized location), making the agent auditable in a way weight updates are not.
- Emergent persistent memory with concrete, physically meaningful content (grasp depth as a fraction of measured object height, finger-closing direction per embodiment) that transfers to held-out episodes starting from an empty memory.
- Honest reporting of failure cases (RLDX-1 non-gain, loss to finetuning on WidowX unseen tasks) and of what the harness actually converges to (pure code-as-policy when the policy is useless).

## Limitations

- **Simulation only**: all evaluations are in simulation (LIBERO, RoboCerebra, VLABench, RoboCasa, SimplerEnv); no real-robot validation, and the authors list sim-to-real transfer as future work.
- **Task complexity**: evaluated almost exclusively on pick-and-place-style manipulation; dexterous in-hand manipulation and tool use — with far richer contact dynamics — are untested.
- **Budget cap unexplored**: fixed maximum of 5 optimization iterations; the saturation point of harness evolution is unknown.
- **No memory ablation or hand-written-harness baseline**: the causal impact of persistent memory is not quantified, and the system is not compared head-to-head against manual harnesses (VoLo, Harness VLA) on the same benchmarks.
- **In-distribution policies gain little**: when the policy is already trained on the benchmark (RLDX-1 on RoboCasa-365), harness evolution adds ≈0 on unseen scenes — the method substitutes for missing competence rather than augmenting existing competence.
- **Runtime cost opaque**: the evolved harness calls VLMs/detectors/pointing models at execution time; per-episode latency and inference cost are not reported, which matters for real-time control.

## Relevance

这篇论文直接命中"LLM agent 自动化设计 + 具身智能"的交叉兴趣：它把 AI-coding 模型的自我改进循环（审查执行轨迹→改代码→经验证接受）应用到机器人 VLA 策略的外围 harness 上，并展示了持久记忆结构的自主涌现，与 LLM 推理时 scaling、agent 架构搜索等主题高度相关。对关注"不调权重如何让大模型/大策略适配新环境"的工作（推理时优化、harness/ scaffold 自动化）有直接参考价值。

## Questions for Further Exploration

- How much of the X-VLA-on-WidowX gain survives if the tool stack is weakened (e.g., no GraspGen, no SAM 3) — i.e., how much is harness *design* versus tool *capability*?
- What is the causal contribution of persistent memory: does disabling memory reads at evaluation time (keeping the harness code identical) drop success measurably on unseen tasks?
- Does harness evolution saturate at 5 iterations, or do 20–50 iterations keep improving held-out performance — and does training-set monotonic acceptance eventually cause held-set overfitting?
- Can the same loop run on a real robot, where rollouts are expensive and slow — e.g., with offline trace replay or a handful of on-robot episodes per iteration?
- Since finetuning wins on WidowX unseen tasks (87.5% vs 66.7%), do finetuning and harness evolution compose — wrapping a harness around a finetuned specialist on out-of-domain shifts beyond the +2% seen in Table 2?
- Can the unified cross-embodiment harness be evolved once per robot *family* and transferred with only calibration memory, avoiding per-setup evolution entirely?
