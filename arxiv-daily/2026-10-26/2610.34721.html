Key metric
2.3×

faster decoding than exact routing + LRU on OLMoE-1B-7B (RTX 4090, 50% experts resident): 10.7 vs 24.7 ms/token (95% CI 2.19–2.44).

2.2× at 25% residency (19.2 vs 42.5 ms) · 25–30% faster than Cache-Prior · all-experts-resident floor 6.8 ms

Why this matters

Batch-1 MoE decoding on consumer GPUs is transfer-bound; the logical-cache determinism fix matters for every cache-aware offloading system — and for how they're evaluated.

With routing on the physical cache, perplexity drifts with PCIe timing (8.755 → 8.627); the logical cache pins it at 8.509 with zero run-to-run variance.

⚠ Critical edge

The headline 2.2–2.3× is against the weakest baseline (exact routing + LRU) under emulated memory pressure — OLMoE fits in the 4090 — and the edge vanishes on compute-bound Qwen3.6.

vs the authors' best exact-routing cache+prefetch config: 1.9× · on Qwen3.6 FP8, Cache-Prior is 4–6% faster in free generation.

01 Methodology — how PSR works

Setting: batch-1 greedy decoding · non-expert weights on GPU · per-layer cache of C<E expert slots · experts pinned in host memory · RTX 4090 on PCIe 4.0 ×16 (22.9 GB/s; one expert copy = 0.55 ms)

pre-gate @ ℓ−1

Next layer's router applied one layer early — ranking arrives ~0.4 ms before the copy would need to start.

insert ≤ n=1

Top non-resident pre-gate candidate enters the logical cache (evict lowest-A-priority victim); a copy is queued.

biased top-K @ ℓ

Cache-Prior-style routing bonus, restricted to logical residents only — bias lands on experts the router prefers and that are already in flight.

execute

Demand-copy selected misses; run with unmodified softmax weights, waiting only on slots actually executed.

  • Determinism contract: routing reads logical state only; physical copy scheduling affects latency, never output. Harness and engine implement the identical policy (perplexity 8.684 vs 8.683; Table 1 variance 0.000).
  • A-priority eviction: fast/slow EMAs (decay 0.5 / 0.98) of the router's own top-K membership plus a token prior — tracks preference, not execution, so the bias can't reinforce itself.
  • Why bounded: unbounded insertion (n=8) tracks exact routing most closely but at 17.0 ms is slower than Cache-Prior without prefetch — the budget caps copies to what the link can overlap.

  • Quality: mean paired difference vs Cache-Prior across 8 benchmarks is +0.1 / +0.5 pts (95% lower bounds −0.8 / −0.3); at matched latency PSR leads +1.7±1.0 / +2.2±1.0, significant after Holm on HellaSwag (both residencies) and MMLU (25%) — worse on no task.
  • Mechanism: PSR issues 13.8 copies/token but only 2.2 are demand stalls; effective cost 0.28 ms/copy vs 0.70 ms for Cache-Prior (10.5 copies, all demand). Popularity prefetch under Cache-Prior backfires: 13.8 → 16.3 ms.
  • Pareto: every Pareto-optimal point except exact routing is a PSR configuration, at all three cache sizes tested on Moonlight.
  • Free generation is workload-dependent: at 50%, +12% on GSM8K, +18% on IFEval, but −4% on HumanEval; at 25%, PSR stays 19–28% faster on all three.
  • Negative results kept: distillation-trained gates cut the KL diagnostic 17–30% but not benchmarks; AcceptMoE-style drafting with a 1B drafter is 1.41–1.99× slower than PSR on OLMoE — yet a DFlash block drafter on Qwen3.6 decodes at 11.2/8.4 ms, 2.1–2.9× faster than any same-memory autoregressive config (64 prompts).

Protocol: 8 benchmarks (MMLU, ARC-C, HellaSwag, GSM8K, BBH, IFEval, HumanEval, MBPP) via lm-eval-harness · per-question paired McNemar + Holm · IFEval clustered by prompt · latency: 12×1024-token windows × 3 interleaved rounds, paired t-tests on log latency (Kalibera & Jones) · OLMoE operating points fixed after seeing the suite — flagged, not pre-registered.

03 Strengths

  • Solves a real correctness/evaluation bug — timing-dependent outputs — and measures it: perplexity shifts up to 0.13 from scheduler parameters alone, 0.054 run-to-run.
  • Clean design insight: bias the bonus onto in-flight, router-preferred experts so caching and prefetching reinforce instead of fight.
  • Unusually honest evaluation: three architectures including real offload, iso-latency and iso-quality comparisons, copy-level decomposition, negative results reported in full.
  • Statistics well above the systems norm: paired McNemar + Holm, cluster-robust SEs, repetition-paired latency tests, declared exploratory findings.

04 Limitations

  • Transfer-bound only: the edge vanishes (Qwen3.6 FP8) or reverses (−4% on HumanEval greedy at 50%) when compute dominates or generated text reuses experts.
  • Headline latencies are teacher-forced and exclude prompt processing; free-generation gains shrink to 12–18%.
  • One GPU (RTX 4090), one PCIe link; pre-gate window retuned per model; OLMoE pressure is emulated; operating points not pre-registered.
  • No Mixtral-style few-large-experts model; no external-system baselines (llama.cpp, MoE-Infinity, Fiddler); no code release; single-author, not yet peer-reviewed.
  • Cache-aware routing still perturbs quality: 16–25% of BBH items flip vs exact routing under every configuration; ~−2 pts BBH at 25% residency for all methods.

05 Questions for further exploration

  1. Would the benefit persist on few-large-expert models (Mixtral 8×7B) or bandwidth-starved links (laptop SoC memory, flash-to-DRAM) where copy latency dwarfs layer compute?
  2. Can logical-cache determinism extend to batched serving, where batch composition already perturbs exact-routing outputs — does a per-sequence logical cache make sense when copies are shared?
  3. Is there a hybrid that uses cross-layer prefetch to also hide speculative-decoding verification copies, which the paper measures as fully exposed at 0.57–0.60 ms each?
  4. Trained gates improved the KL diagnostic but not benchmarks — would a reward aligned with generative benchmarks change that conclusion?
  5. The n=1 insertion budget is fixed per layer; could an adaptive budget conditioned on measured link utilization dominate the fixed-n frontier?
