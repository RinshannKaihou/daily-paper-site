Why this matters

Low-bit inference quantization destroys long-tail factual knowledge first — this paper explains why, and fixes it, for anyone trading precision against memory and throughput.

Critical edge

The headline 11–31% throughput gain comes from the bigger KV cache — a plain uniform 1-bit table (no gate logic) hits the same plateau. The gate’s real contribution is accuracy-per-bit, not speed.

Methodology

Gate-driven residual quantization (GateRQ)

Targets the hashed n-gram tables beside frontier models — DeepSeek-V4.1-Flash Engram (768M rows, 202.8 GB FP8 = 39.7% of checkpoint) and Qwen3.8-Flash-Next PLE (320M rows, 51.2 GB). Training-free; ships as a native vLLM 0.30 patch. Per-lookup importance decomposes as:

Iₜₖₖ = Gₜ · τₖ · ‖eₜₖ‖²  (gate energy × head gain × row error energy)
01 · LADDER

1-bit residual codes

Each row = ≤3 levels of 1-bit residual codes (TCQ default; INT/PQ also tested). Level 1 (1.06 b/el) stays in GPU memory; levels 2–3 sit packed in pinned host memory, shared via /dev/shm.

02 · GATE

Gate from 1 bit

Every lookup decodes level 1; the model’s own gate is computed from it — correlation 0.989–0.9998 with the FP8 gate, so precision decisions precede any high-precision read.

03 · RANK

Importance ranking

Î = G·τ·‖ê‖² ranks the batch’s lookups; per-batch quantile thresholds set read fractions (e.g. 60% / 37.65% for 2.10 bits) via the classical marginal-return bit-allocation rule — applied to lookups, not rows.

04 · REFINE

Selective deep reads

Only top-ranked lookups fetch levels 2–3 from host, refining values alone — keys and injection gates always come from level 1. Precision becomes a per-access property, not per-row storage.

Strengths

What holds up

  • Identifies and measures the mechanism — gate-weighted error anti-correlating with access frequency — across five corpora and both models.
  • The 1-bit gate breaks the circularity (“need precision to find where precision is needed”): level-1 gates select lookups carrying 96–99.99% of the importance FP8 gates would select.
  • Training-free, checkpoint-compatible, leaves the model’s own gating math untouched; works with any residual codec (TCQ, INT, PQ validated).
  • Exemplary evaluation hygiene: pre-registered predictions, paired bootstrap intervals, bit-identical budgets across competing rules.
  • Real systems work, not emulation: Triton quantile kernels, CUDA-Graphs-compatible vLLM patch, /dev/shm sharing, per-layer microbenchmarks.

Limitations

Where it strains

  • Knowledge-QA only (PopQA, TriviaQA, NQ-open, CMMLU); no reasoning, code, or long-form generation — NQ-open barely separates the rules.
  • Each configuration run once; throughput is single-run over two synthetic 32K workloads; native-path accuracy not yet cross-checked against emulated runs (authors’ own caveat).
  • No head-to-head with other conditional-memory compression lines (TN-gram, FactorEngram, CXL pooling) or plain FP8 offloading with ample host RAM.
  • Per-batch quantile thresholds make read depth batch-dependent — the same text can decode at different precisions under different batch compositions.
  • Full ladder stores 2.13–3.19 b/el to read 1.50–2.10; the win shrinks on smaller tables (Qwen’s 51.2 GB PLE).
  • Importance proxy assumes isotropic, uncorrelated errors — verified on two checkpoints only.

Relevance · 相关性

为何值得读

高度契合“极限性能优化下的可靠性”方向：这是对推理端激进量化（1–2 bit）引入的精度损失所做的机理级分析与修复——不仅证明推荐系统式“按频率分配精度”的混合精度策略在门控条件记忆中会失效（比随机更差），还量化了长尾事实知识最先被低比特量化破坏（最稀有四分位 −6.24 vs 最热门四分位 −1.51 PopQA 分）。对任何关心大模型低比特推理精度—内存—吞吐权衡的人，这篇是必读的实证参考。

Questions for further exploration

Open threads

  1. Does per-batch depth selection change outputs for the same request under different batch compositions — a serving inconsistency, or even an attack surface via batch padding?
  2. Would jointly calibrating deeper levels with level 1, or learning a tiny gate-prediction head, beat the greedy ladder — and at what cost to the training-free property?
  3. Does the gate–frequency anti-correlation hold under other gate parameterizations or shorter training (the 8B follow-up initially favored frequent n-grams before reversing)?
  4. Can per-lookup allocation extend to training (gradient-aware mixed precision) or other table-lookup structures — token embeddings, MoE expert weights with access gates?
  5. Do reasoning and code benchmarks show the same importance concentration — and does the gate estimate stay reliable far from the English calibration corpus (43% of Chinese-text lookups hit never-seen rows)?
