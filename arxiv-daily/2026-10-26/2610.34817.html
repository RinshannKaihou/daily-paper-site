90% of prompt-caching defects in LLM agents fail silently — outputs stay correct, only the bill climbs.

Silent and Costly: Characterizing and Detecting Prompt-Caching Mis-Integration in LLM Agents

Ying Zhang · Ruoqi Guo · Yi Liu · Gelei Deng · et al. 2026-10-26 prompt-caching llm-agents static-analysis empirical-study cost-efficiency

一句话总结 — 首个针对 LLM Agent 中“提示词缓存集成错误”的实证研究：10 个热门开源 Agent 系统的 120 个真实缺陷中 90% 静默失效——模型照常回答，账单悄悄变贵；据此构建的静态检测器 CacheLint 在真实仓库上以 0.86 精确率发现 32 个未知缺陷，18 处已获上游修复。

Key metric · defect symptoms

90%

silent — 108 / 120 real defects raise no error at all

pure silent waste 72% lying telemetry 18% crash 10%

Only 12/120 crash — crash-based test oracles miss this class by construction. One silent defect (hermes-agent#754, per-turn prefix reassembly) lifted cost by ~75%.

Why this matters

Agent bills climb invisibly when caching breaks — no errors, no failing tests. A dated-oracle detector makes this silent waste class finally visible.

直接命中“Agent 静默失效”研究方向：无报错但成本上涨的故障，正是可观测性与成本可靠性的盲区。

Critical edge

The 0.78 recall is an in-sample upper bound — rules were mined from the same 120 fixes — and the single-site model excludes the multi-snapshot defects behind 24 / 26 of its misses.

01

Methodology

From 148,947 merged PRs to a checkable defect model, in three stages.

581 repos→ top-10 agents · 44k–379k★→ 148,947 merged PRs→ 622 candidates→ 120 defects→ 8 root causes
1

Empirical corpus, open-coded

Keyword search over cache markers (cache_control, cached_tokens, …) found 581 repos; the top-10 general-purpose agents by stars (OpenClaw, Hermes-Agent, AutoGPT, OpenHands, Cline, …). Three authors screened 622 candidate PRs down to 120 genuine defects (Fleiss' κ=0.76), open-coded into 8 root causes / 2 symptom classes / 6 fix strategies. Dataset released.

2

One uniform formalization

Every defect = ⟨call site m, unchecked precondition j⟩, with j ∈ {STAB prefix stability, CAP provider capability, ACCT accounting safety} — a mis-integration is a site reached with no guard discharging its precondition.

3

CacheLint, hybrid by design

CodeQL mines invocation sites (Python, JS/TS, Ruby, Go, C#). CAP is settled off-program against a dated provider-capability matrix — every entry carries last_verified, because providers change semantics unilaterally (Anthropic silently cut its default TTL from 1h to 5min). STAB/ACCT are settled on-program by an LLM guard check (gpt-5.4-mini). Each warning ships its modal fix.

  • Real-world traction: 21/32 reports maintainer-confirmed, 18 fixed upstream, 0 rejected — including Anthropic's official .NET SDK, n8n, langchain, litellm, gemini-cli, Zed, iTerm2.
  • Fixes are predictable: the modal root-cause→fix map alone predicts 95/120 (79%) fixes; 68% are small, static, local edits.
  • Stable, and honest about the guard: precision varies ≤ ±0.02 over 5 runs; asked 33 dated TTL facts, the guard LLM answers only 5 correctly — exactly why the dated oracle exists.
  • Stakes: cached tokens cost ≈ 1/10 the standard rate and cut latency up to 80%; enterprise LLM API spend hit $8.4B by mid-2025 — a silently disabled cache is a material line item.
03

Strengths

What makes this study hold up.

  • Owns an unstudied, expensive class — first characterization of application-side caching mis-integration, with a public 120-defect dataset from systems at 44k–380k★.
  • The 90%-silent stat earns its design conclusion — it is turned into an argument for static analysis over crash oracles, and the argument holds: any single test run catches the 12 crashers; nothing catches the other 108.
  • Principled hybrid discharge — time-varying external facts go to a dated, sourced oracle; program-internal facts go to an LLM guard standing in for a backward slice. The 0.86 / 0.31 / 0.05 ablation proves both halves earn their keep.
  • Tight study→tooling loop — every warning carries the fix class developers actually apply; 79% of fixes predictable from root cause alone.
  • External validation rare for the genre — 32 new defects, 21 confirmed, 18 merged upstream (incl. a vendor's own SDK), 0 rejected, artifacts released.
04

Limitations

Where the claims thin out — read with the Critical Edge above.

  • No recall on the 571 held-out repos — the in-sample 0.78 is an optimistic proxy, as the authors themselves flag.
  • Multi-snapshot classes are out of scope by construction — prefix reassembly and cross-turn mutation (24/120 known defects) account for 24 of the 26 misses.
  • Implicit provider-side caching excluded — OpenAI/Gemini auto-caching, where a defect shows only as consistently zero cached tokens, is future work.
  • Maintenance burden shifted, not removed — depends on a manually dated capability matrix (2026-05-10 snapshot) and one guard LLM (gpt-5.4-mini) whose behavior can drift; the unsound guard means both false warnings and misses remain possible.
  • Corpus bias — SDKs/frameworks excluded from study, and defects without a merged fixing PR are invisible: the taxonomy is a lower bound.
  • No automated fix generation or dollar-impact profiling yet (stated future work).
05

Questions for further exploration

  • Catch the excluded multi-snapshot classes by pairing CacheLint with a lightweight runtime prefix-recorder that snapshots the bytes actually sent per turn?
  • Wire the dated oracle into CI, so a provider-side change (TTL 1h→5min) automatically re-opens previously green builds as regressions?
  • How much money does each defect pattern waste? One ~75% case is suggestive; a longitudinal spent-per-pattern study would sharpen priorities.
  • Replace or cross-check the guard LLM with deterministic abstract interpretation of serialization order (dict/kwargs/JSON key sorting)?
  • Does the taxonomy transfer to implicit caching (OpenAI, Gemini), where the only signal is zero cached_tokens — and would a response-side cache-hit linter complement the code-side detector?
  • Why is in-sample precision (0.71) below held-out (0.86)? If precision depends on codebase size/polymorphism, what does that mean for monorepo deployment?
