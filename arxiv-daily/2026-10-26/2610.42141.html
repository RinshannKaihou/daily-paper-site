Why this matters

Adapting a frozen robot policy to new environments without weight updates or demonstrations — cheap, auditable, directly relevant to harness automation.

不调权重、不采演示，让冻结机器人策略适配新环境——对推理时优化与 harness 自动化有直接参考价值。

⚠ Critical edge

On the most spectacular gains (WidowX, 0% → 87.5%) the harness bypasses the useless frozen policy entirely — the gains come from the tool stack, not from "wrapping" the policy.

Also: simulation-only throughout, and no memory-off ablation isolates memory's causal contribution.

Methodology — the evolution loop

What gets optimized: the harness — code sitting between observations and actions — around a frozen VLA policy.

Observationscamera · depth · gripper pose · instruction

Harness (evolved)VLMs · detection · segmentation · pointing · grasp poses · freeform memory

Frozen VLAweights locked
→
Actionslow-level control
  1. Run — roll out the current harness on training episodes with full trajectory logging: per-step frames, robot readings, all tool outputs.
  2. Diagnose — claude-opus-5 reviews the complete traces and names each failure mode (gripper jams, shelf occlusion, mislatched doors…).
  3. Rewrite — proposes a harness revision; it is accepted only if it beats the incumbent on the same episodes — monotonic improvement.
  4. Repeat — ≤5 iterations starting from a bare pass-through; ≈<6 h and <$150 of coding-model time, zero demos collected.

Control allocation is never prescribed: when the frozen policy carries no signal (X-VLA on WidowX), the loop converges to a pure code-as-policy agent; when a finetuned specialist works, it stays in charge and the harness intervenes only on failure.

  • Emergent memory is physically concrete: grasp at 18% of object height lifts nothing, 45% succeeds — and every evaluation starts from an empty memory, so the memory design is what transfers.
  • One unified harness, evolved on 2,201 procedural episodes, serves Franka Panda, WidowX, and the Google mobile manipulator: 1.9% → 28.8% held-out around general X-VLA.
  • Large per-setup swings: RLinf-π0.5 on LIBERO-Pro 2.0% → 40.0%; SmolVLA on RoboCerebra 26.0% → 80.0%.
  • The lone failure is honest: in-distribution RLDX-1 on RoboCasa-365, 27.9% → 27.8% — no headroom when the policy already fits.
03

Strengths

  • Weight-free adaptation — <$150 and <6 h instead of demonstration collection + finetuning.
  • Rigorous held-out protocols — unseen scenes, unseen tasks, and a cross-embodiment unified-harness test; the exact evaluations hand-tuned systems skip.
  • Auditable by construction — every accepted revision targets a named failure mode, in a way weight updates never are.
  • Emergent memory with physical meaning (grasp depth as a fraction of measured object height) that transfers from an empty start.
  • Honest reporting — the RLDX-1 non-gain and the WidowX unseen-tasks loss are surfaced, not buried.
04

Limitations

  • Simulation only — LIBERO, RoboCerebra, VLABench, RoboCasa, SimplerEnv; no real-robot validation.
  • Task range — pick-and-place-style manipulation only; dexterous in-hand and tool use untested.
  • No memory ablation, no hand-written baseline — memory's causal impact is unquantified; VoLo / Harness VLA never compared head-to-head.
  • Substitutes, doesn't augment — in-distribution policies gain ≈0; it fills missing competence rather than boosting existing skill.
  • Runtime cost opaque — per-episode VLM/detector/pointing latency is unreported; the 5-iteration budget cap leaves saturation unknown.
05

Questions for further exploration

  • Q1How much of the WidowX gain survives a weakened tool stack (no GraspGen, no SAM 3) — harness design or tool capability?
  • Q2Does disabling memory reads at evaluation (identical harness code) measurably drop success on unseen tasks?
  • Q3Does evolution saturate at 5 iterations, or do 20–50 keep improving — and does monotonic training acceptance eventually overfit the held set?
  • Q4Can the loop run on a real robot, where rollouts are slow and expensive — via offline trace replay or a few on-robot episodes per iteration?
  • Q5Since finetuning wins one cell (87.5% vs 66.7%), do finetuning and harness evolution compose beyond the +2% already observed?
  • Q6Can one harness be evolved per robot family and transferred with only calibration memory, avoiding per-setup evolution?
