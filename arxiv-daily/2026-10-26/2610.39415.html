Key finding · arXiv 2610.39415

Evo 2 checkpoints fail on Blackwell GPUs because the platform's FP8 is more accurate — they depend on H100's sloppier arithmetic.

Key metric · Application recovery

0.434 → 0.869

BRCA1 variant-classification AUROC · Evo 2 40B · RTX 5070 Ti

Restored by swapping one FP8 projection for a 512-entry lookup table — weights untouched. H100 reference: 0.868 (paired Δ +0.435, 95% CI 0.360–0.507).

Why this matters

FP8 accumulation differences between GPU generations can silently corrupt model outputs with weights unchanged — a portability warning for every low-precision inference deployment.

相关性 · 它精确刻画了低精度（FP8）张量核心累加算术的代际差异如何在权重完全不变的情况下静默破坏模型输出（下游 AUROC 跌破 0.5），并提供了定位、筛查与低成本修复的完整方法论——对任何依赖低精度推理栈的模型部署与检查点可移植性评估都有直接参考价值。

Critical edge

The recovery is application-level only: the 40B table restores BRCA1 scoring yet still misses the forward-test tolerance by 0.0011 (0.2170 vs 0.2159 ± 0.001) — and every 40B conclusion extrapolates an emulator validated only on the 1B.

Methodology · Controlled numerical intervention

A bisection experiment on fixed weights: GPU, checkpoints, and FP8 operands never change — only the accumulation arithmetic does. Pass criterion is the upstream forward test (mean bf16 next-base cross-entropy within 0.001 of expected), under a SHA-256-hashed analysis plan (PLAN_C) frozen before the GPU runs.

  1. Baseline matrix — official 1B/7B/40B on reference GPUs (H100 PCIe, RTX 4060) vs Blackwell sm_120 (RTX 5070 Ti, RTX PRO 6000); only the FP8 projections vary (21 GEMMs in the 1B, 42 in the 40B).
  2. mmaemu — bit-exact emulator of whole library GEMM calls: tensor-core FMA chains (13-fraction-bit truncation), split-K merges, bf16 epilogue. Bit-for-bit on all 168 captured H100 outputs; the split-K rule hits 2,416/2,416 later calls.
  3. Single-projection bisection — each projection swapped among native / emulated (hopper-te, ada-te) / fp32 / float64 / bf16 / a block-0 lookup table.
  4. Mechanism probes at block 0 — truncation width (13→25 bits), round-to-nearest, exact sums × sampled gains, matched-norm Gaussian perturbations of the residual stream.
  5. Application recovery — 500 BRCA1 variants (111 LoF, Findlay et al. saturation-genome-editing assay) scored zero-shot over 8,192-bp windows; AUROC with 2,000-resample bootstrap and paired deltas.

Strengths

  • A fully controlled causal chain: arithmetic change → single-projection dependence → candidate property → application recovery, with weights fixed.
  • mmaemu is a reusable tool beyond this paper: bit-exact emulation of whole library GEMM calls, Apache-2.0 with archived validation logs and CI replay.
  • The matched-perturbation control — same-norm Gaussian noise passes while the structured difference collapses the model — cleanly rules out "big perturbation = broken model".
  • Conceptually clarifying distinctions: operator agreement vs model function vs application agreement; determinism ≠ compatibility.
  • Exceptional transparency: hashed analysis plans, deviation log, per-number provenance ledger, unfunded-status and AI-assistance disclosure.

Limitations

  • One model family (Evo 2); the 20B checkpoint, B200, and B300 were never run; prevalence of accumulation dependence across checkpoints is unknown.
  • Reference evidence rests on exactly two configs (one H100 PCIe, one RTX 4060); all 40B conclusions extrapolate a 1B-validated emulator — no direct H100 captures of 40B projections.
  • The 1.4% shrinkage gain is fitted in-sample and no rescaling correction was validated as a fix; the training-origin explanation is untested conjecture.
  • The 40B table misses the forward tolerance by 0.0011; the PRO table's forward loss was never recorded; 40B generation untested — full compatibility is not restored.
  • Biology evidence is one assay on a 500-of-3,893 variant subset; bootstrap intervals condition on single recorded runs.

Questions for further exploration

  1. How common is accumulation-arithmetic dependence across other released FP8/FP4 checkpoints — and would the fp32-accumulation screen find many false negatives?
  2. Did the dependence arise during training — can controlled fine-tuning under truncated vs exact accumulation create (or remove) it?
  3. Why does block 0 dominate when its residual addition largely cancels the branch output (12.5–13.4× relative amplification)?
  4. Can the shrinkage diagnosis become a validated correction — e.g. a per-projection learned rescale — that passes the 40B forward test everywhere?
  5. Should releases ship application-level reference outputs alongside operator-level tests, and what tolerance bands separate platform noise (84.2% cross-reference sign agreement) from genuine failure?
