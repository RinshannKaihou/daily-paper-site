> **一句话总结：** 针对 DeepSeek Engram / Qwen PLE 这类挂在大模型旁的巨型 n-gram 哈希表（条件记忆，占 DeepSeek-V4.1-Flash 检查点的 39.7%），本文发现量化误差由检索门控加权——高频 n-gram（功能词）门控小、长尾实体门控大，因此推荐系统"给高频行更多比特"的老经验反而比随机还差；提出的免训练 GateRQ 把每行存成 1-bit 残差码阶梯，仅用驻留 GPU 的 level-1（约 1.06 bit）算出门控并为每次查表排序，只对最重要的查表从主机内存读取更深层级：在 PopQA 上以 2.10 bits/元素读取仅损失 0.20 分（52.18 vs FP8 的 52.39），1.50 bits 时损失约 1 分，而频率法则在同预算下损失 2.85 分；同时 GPU 表内存从 23.6 GiB 降到 3.04 GiB（7.8×），KV cache 扩大 8.1×，vLLM 长上下文吞吐提升 11%–31%。

> **TL;DR:** A post-training quantization scheme for the huge hashed n-gram tables ("conditional memory": DeepSeek's Engram, Qwen's PLE) that dominate frontier checkpoints. The core finding inverts the recommender-system playbook: a lookup's quantization error is weighted by the model's retrieval gate, which is small for frequent function-word n-grams and large for rare long-tail entities, so allocating bits by access frequency is worse than allocating them at random — and the gate itself is computable from a 1-bit code (correlation 0.989–0.9998 with the FP8 gate). GateRQ stores each row as a ladder of 1-bit residual codes, keeps level 1 in GPU memory, and reads deeper levels from host memory only for the lookups the gate ranks highest. On PopQA with DeepSeek-V4.1-Flash it loses just 0.20 points vs FP8 tables (52.18 vs 52.39) reading 2.10 bits/element and ~1 point at 1.50 bits (51.37 vs frequency-selection's 49.53 at identical budget), winning all 36 paired comparisons against prior/random/frequency rules across 2 models x 3 codecs x 2 budgets; it cuts GPU table memory 23.6 -> 3.04 GiB per GPU on 8x RTX PRO 6000, enlarging the KV cache 8.1x and raising vLLM throughput 11%–31% over GPU-resident FP8. Read it for the analysis (why frequency-based mixed precision backfires in gated memory); the engineering is a clean marginal-return bit-allocation scheme applied per lookup.

## 核心贡献

- **误差归因分析**：把条件记忆层的量化失真分解到每次查表（lookup），证明误差由门控（gate）加权——门控误差可忽略（量化后仅门控用 1-bit 表，PopQA 变化 +0.08~+0.15 分），损失几乎全部来自数值（value）通路；且门控可以用 1-bit 码算出，与 FP8 门控的相关性达 0.989–0.9998。
- **推翻"按频率分配精度"的经验**：在 Engram/PLE 中门控与访问频率负相关（Spearman −0.02 至 −0.63）。以 PopQA 的 2-gram 头为例，访问超过 1,000 次的行承担 32% 的查表却只携带 3.8% 的重要性（importance），从未见过的行承担 14% 查表却携带 23% 重要性——因此按频率选精化对象比随机选择还差（消融中分别只移除 26% vs 41% 的可移除误差）。
- **重要性高度集中且由上下文决定**：held-out 英文上排名前 10% 的查表携带 block 2 的 48%、block 15 的 69% 的重要性；同一行的门控随上下文变化（p90/p10 中位数达 4.3×），行级统计量（期望门控）无法替代当前门控。
- **GateRQ 方法**：免训练、后训练即可用的方案——每行存为最多 3 级 1-bit 残差码阶梯（默认 TCQ，也支持 INT/PQ），level 1 常驻 GPU 用于算门控，按每次前向批内分位数阈值（marginal-return 比特分配规则）决定哪些查表从主机内存读取 level 2/3，精度成为"每次访问"的属性而非"每行存储"的属性。
- **系统实现与实测**：给出 vLLM 0.30 的原生补丁（Triton 核、CUDA Graphs 兼容、/dev/shm 共享主机副本），在 8× RTX PRO 6000 上 GPU 表内存 23.6 -> 3.04 GiB，KV cache 扩 8.1×，吞吐提升 11%–31%；还采用"预注册预测"（66 条中 57 条误差 <0.4 分）保证分析可信度。

## Key Contributions

- **Error attribution for gated conditional memory.** Decomposes quantization distortion of a conditional-memory layer into per-lookup terms: expected error energy factors into `I_t,j = G_t * tau_j * ||e_t,j||^2` (gate energy x head gain x row energy). Table 1 shows the gate path is immune — computing only gates from a 1.06-bit table shifts PopQA by at most +0.15 points, while quantizing only values costs as much as quantizing everything (−4.03 vs −3.87 points at level 1) — and gates from a 1-bit code correlate 0.989–0.9998 with FP8 gates, so precision decisions can be made *before* reading any high-precision data.
- **Refutes frequency-based mixed precision for this setting.** Importance runs *against* access frequency: over 4,000 PopQA questions, rows accessed >1,000 times serve 32% of 2-gram lookups but carry only 3.8% of importance, while never-seen rows serve 14% and carry 23%. Refining the 41% most-frequent lookups removes only 26% of the removable weighted error vs 41% for a random choice — the standard recommender-system heuristic actively backfires.
- **Shows row-level statistics cannot find the important lookups.** Importance is concentrated (top 10% of lookups carry 48%/69% of importance in blocks 2/15 on held-out English; top 1% carries 54% in block 15 on PopQA) and context-dependent (a row's 90th-percentile lookup has 4.3x the gate energy of its 10th-percentile in block 15), so precision must be decided per lookup from the gate at hand, not per row.
- **GateRQ: gate-driven residual quantization.** A training-free scheme: each row is a ladder of up to 3 levels of 1-bit residual codes (TCQ by default; INT and PQ also tested); level 1 (1.0625 bits/element on DeepSeek) stays in GPU memory, deeper levels sit packed in pinned host memory; per-batch quantile thresholds send the top s2 fraction of lookups (by the level-1 importance estimate) to level 2 and the top s3 to level 3, meeting a fixed bits-per-lookup budget via the classical marginal-return rule of bit allocation applied to lookups instead of rows.
- **End-to-end validation with registered predictions.** 2 models (DeepSeek-V4.1-Flash, Qwen3.8-Flash-Next) x 3 codecs x 2 budgets = 12 settings; all 36 paired PopQA comparisons against prior/random/frequency selection favor GateRQ; an offline proxy registered before the runs predicts rule ordering correctly in all 12 settings. Ships a native vLLM patch with measured serving throughput.

## Methodology

The paper studies two production conditional-memory models: **DeepSeek-V4.1-Flash** (Engram layers in blocks 2 and 15; 24 hash heads of 2/3/4-grams, row dimension 256; 768M rows; 202.8 GB in FP8 = 39.7% of the 510.3 GB checkpoint) and **Qwen3.8-Flash-Next** (one PLE layer in block 2; 16 heads of 2/3-grams, d_e = 160; 320M rows; 51.2 GB = 27.6% of checkpoint). In these layers, each token hashes its suffix n-grams to table rows; a scalar gate computed from the current hidden state (sigmoid of normalized hidden-key dot product, shared value projection across 4 branches) scales the retrieved rows into the residual stream.

**Analysis (Section 3).** The gated update error splits into gate error and value error (Eq. 4-5); under isotropic, uncorrelated errors the expected distortion is a sum of per-lookup importances `I_t,j = G_t * tau_j * ||e_t,j||^2`. Three observations are measured on records of every lookup the FP8 models make on 4,000 PopQA questions, held-out English, RACE, Chinese, and code: (1) gate error is negligible and 1-bit gates match FP8 gates (top-10% importance lookup overlap 92.8–99.3%); (2) gate negatively correlates with row access count (Spearman −0.02 to −0.63 across 18 layer/order/corpus combinations), so frequency-based allocation fails; (3) importance concentrates in few, context-dependent lookups, so per-row statistics miss them.

**GateRQ (Section 4).** Two components. (i) *Residual ladder*: each row is encoded as up to L = 3 levels of 1-bit residual codes, level k quantizing the residual left by levels 1..k−1, with one FP16 scale per row and level (1.0625 bits/element per level on DeepSeek with TCQ). Level 1 lives in GPU memory (3.04 GiB/GPU); levels 2–3 are packed into fixed-size host records shared by the 8 ranks through /dev/shm. (ii) *Per-lookup depth allocation*: every lookup decodes level 1, the model's original gate is computed from it, an importance estimate `I_hat = G_t * tau_j * ||e_hat||^2 / (1 − eps_1)` ranks the batch's lookups, and fixed fractions (s2, s3) — e.g. (41.2%, 0) for 1.50 bits and (60%, 37.65%) for 2.10 bits on DeepSeek — read deeper levels, which refine only the value; keys and injection gates always come from level 1. This is the classical marginal-return bit-allocation rule (refine when `I_t,j > mu * theta_k`) applied to lookups rather than rows.

**Evaluation protocol.** Full test sets of PopQA (14,267), TriviaQA (9,960), NQ-open (3,610), CMMLU (11,582) via LM Evaluation Harness 0.4.13 as a client of vLLM (TP8/TP4, greedy, fixed prompts); paired bootstrap 95% intervals over questions (10,000 resamples). Accuracy runs emulate the read rule with a hook inside vLLM; serving runs use a native vLLM 0.30 patch (Triton quantile kernel, fixed-size CUDA-Graphs-compatible buffers, UVA host reads). Quantizers are calibrated on 65,536 rows/head; access counts from 1.15e8 RedPajama tokens. An offline error proxy was *registered before each run* and checked against measurements afterward.

## Results & Highlights

- **Near-FP8 accuracy at ~2 bits (PopQA, DeepSeek-V4.1-Flash, TCQ ladder):** GateRQ at 2.10 bits/lookup scores **52.18% vs FP8's 52.39%** (−0.20 points, not significant; paired 95% half-width 0.28–0.47); at 1.50 bits it scores **51.37% (−1.02 points)**. On Qwen3.8-Flash-Next, 2.10 bits gives **39.38% vs FP8's 39.55%** (−0.18).
- **Selection rule comparison at equal budget:** in **all 36 paired PopQA comparisons** (2 models x 3 codecs x 2 budgets vs 3 rules), gate-based selection wins by **0.39 to 2.86 points** — e.g. on DeepSeek TCQ at 1.50 bits: GateRQ 51.37 vs Prior 50.23 (+1.14), Random 49.75 (+1.62), Frequency 49.53 (+1.84). Frequency is the *worst* rule in 11 of 12 settings, confirming the anti-heuristic.
- **Bits saved vs uniform ladder:** reading 1.50/2.10 bits instead of the full 2-level (2.13-bit) / 3-level (3.19-bit) ladder saves **0.63–1.20 bits per element** with no statistically significant PopQA difference at those working points (e.g. DeepSeek TCQ 2.10: 52.18 vs uniform 1–3's 52.24, diff +0.06 [−0.27, +0.37]).
- **Why: long-tail fragility and error concentration.** Zeroing the tables costs DeepSeek **−36.76 PopQA points** (~70% of its 52.39 accuracy) and Qwen −12.90; uniform 1-bit (level 1 only, 1.06 bits) costs **−3.87 points overall but −6.24 on the rarest popularity quartile vs −1.51 on the most popular**. Rows accessed >1,000 times serve 32% of lookups but carry only 3.8% of importance; the top 1% of lookups in block 15 carry 54% of importance on PopQA.
- **Ablation (Figure 4):** at the 1.50-bit setting (41.2% of lookups refined), gate ranking removes **93%** of the weighted error removable by refining everyone, vs 70% for expected-gate (Prior), 41% for Random, and 26% for Frequency; measured PopQA gap recovery agrees: 96% / 58% / 41% / 34%.
- **Serving (vLLM, 8x RTX PRO 6000, TP8, 32K-input workloads):** GPU table memory drops **23.6 -> 3.04 GiB per GPU (7.8x)**, KV-cache capacity grows **8.1x**, and output throughput rises **11%–31% over FP8 tables in GPU memory** (254.0 vs 228.3 tok/s at 64 req/1K out; 458.6 vs 349.6 at 128 req/2K out). vs FP8 host offloading, throughput matches within 1.5% (458.6 vs 460.1) while pinned host memory falls **188.7 -> 25.8–48.6 GiB**. Table-side layer time at 8,192 tokens: 1.3–1.6 ms vs 3.1 ms (FP8 in GPU) and 3.9 ms (FP8 in host).
- **Predictive rigor:** the registered offline proxy predicted PopQA deltas before the runs; **57 of 66 predictions land within 0.4 points** of measurement, and it ranks the four rules correctly in all 12 settings.

## Authors & Credibility

The credibility signals are unusually strong for a systems/quantization paper: full-test-set evaluation with paired bootstrap intervals; *pre-registered* predictions of every configuration written to files before runs and audited afterward; controlled selection baselines that share the identical ladder, read fractions, and bits-per-lookup; and honest caveats (e.g., "Entries above FP8 should not be read as consistent accuracy improvements"). Access to production checkpoints (DeepSeek-V4.1-Flash's 510 GB Engram checkpoint, Qwen3.8-Flash-Next) and an 8-GPU RTX PRO 6000 node indicates substantial industry-grade resources; no code release is mentioned, and the models' own training details (Engram, mHC) are cited from arXiv 2026 preprints.

## Critical Assessment

- **Novelty:** The per-lookup (access-time) precision allocation is genuinely new for conditional memory, and the central negative result — frequency-based refinement doing *worse than random* because gate magnitude anti-correlates with access count — is a crisp, falsifiable inversion of the mixed-dimension/mixed-precision embedding literature (which the authors test head-on rather than merely cite). The enabler (gate computable from a 1-bit code, correlation ≥0.989) is a well-argued, well-measured observation.
- **Rigor:** High. Full test sets, paired 95% intervals, registered predictions (57/66 within 0.4 points), identical ladder and read fractions across rules, and an appendix verifying the isotropy/uncorrelatedness assumptions behind the importance proxy. Weak spots: each configuration was run **once** (intervals cover question sampling, not run-to-run variation), and the throughput table is single-run, two synthetic workloads (32K in, 1K/2K out) — the authors themselves flag that "native four-task accuracy remains to be cross-checked against the accuracy runs."
- **Reproducibility:** Moderate-to-good in principle (vLLM 0.30 patch described in detail, quantizers calibrated on 65,536 rows/head, counting corpus = 1.15e8 RedPajama tokens, exact few-shot/seed protocol) but hard in practice: it requires the DeepSeek-V4.1-Flash / Qwen3.8-Flash-Next checkpoints and a multi-GPU node; no code or ladder artifacts are stated to be released.
- **Significance:** The headline numbers are real but should be read precisely. The 11%–31% throughput gain over GPU-resident FP8 comes from the larger KV cache — a *uniform 1-bit* table (3.04 GiB, no gate logic at all) sits on the same throughput plateau (256.0/464.5 tok/s), so the throughput win is a property of any aggressive compression, not of GateRQ's gate selection; the gate mechanism's actual contribution is accuracy-per-bit (e.g. +1.84 PopQA points over frequency at 1.50 bits). Compared to the strongest simple alternative — just reading the full 3-level uniform ladder — GateRQ saves 0.63–1.20 bits/element at no significant PopQA cost, a solid but incremental margin.
- **Red flags:** (1) Accuracy was measured via an emulation hook inside vLLM, not the native kernel path used for throughput, and the throughput runs used a *simpler* variant (every rank reads all heads) than the per-rank variant timed in Figure 5. (2) Per-batch quantile thresholds make a lookup's depth depend on whatever else is in the batch — identical text can be decoded at different precisions under different batch compositions, a serving-time nondeterminism the paper does not discuss. (3) NQ-open barely separates the rules (GateRQ significantly better in only 1 of 36 comparisons), and Frequency is even significantly *better* once (DeepSeek TriviaQA, TCQ 2.10 bits, +0.35), so the dominance story is PopQA-centric — consistent with the method targeting long-tail factual recall, but worth stating. (4) Equation (5) is a local proxy that ignores Qwen's depthwise convolution and is only validated end-to-end post hoc.

## Strengths

- Identifies and *measures* a mechanism (gate-weighted quantization error anti-correlating with access frequency) that makes a widely used heuristic actively harmful, with the evidence spread over five text corpora and both models.
- The 1-bit-gate insight elegantly breaks the circularity ("you need precision to decide where precision is needed") — gates computed from level 1 select lookups carrying 96–99.99% of the importance that FP8 gates would select.
- Training-free, checkpoint-compatible, model-mechanism-preserving (the model's own gate and gating math are untouched); works with any residual-encodable codec (TCQ, INT, PQ all validated).
- Evaluation hygiene is exemplary: registered predictions, paired intervals, controlled baselines at bit-identical budgets, honest footnotes against over-reading entries above FP8.
- Real systems work, not just emulation: a CUDA-Graphs-compatible vLLM patch with Triton quantile kernels, /dev/shm sharing, and per-layer microbenchmarks (1.3–1.6 ms vs 3.9 ms for host-resident FP8 at 8,192 tokens).

## Limitations

- Only knowledge-QA benchmarks (PopQA, TriviaQA, NQ-open, CMMLU); no reasoning, code, or long-form generation results, and NQ-open shows essentially no separation between selection rules.
- Throughput claims rest on single runs of two 32K-input workloads on one node type; native-path accuracy has not been cross-checked against the emulated accuracy runs (stated by the authors).
- The comparison target is FP8 tables and self-constructed selection baselines; there is no comparison against other conditional-memory compression lines (TN-gram, FactorEngram, TF-Engram, CXL pooling) beyond a related-work discussion, nor against simply offloading FP8 with more host RAM when host memory is plentiful.
- Per-batch thresholds make read depth context- and batch-dependent — reproducibility of a single request's output across batching regimes is not analyzed.
- Storage cost of the full ladder (2.13–3.19 bits/element stored to read 1.50–2.10) plus one pinned host copy per node is only cheap relative to 189 GiB FP8; on smaller PLE tables (Qwen's 51.2 GB) the practical win is smaller.
- The importance proxy assumes uncorrelated, isotropic errors and drops the gate-error term; the authors verify these assumptions on the two checkpoints studied, but generality to other conditional-memory implementations (different gating, convolutions) is untested.

## Relevance

高度契合"极限性能优化下的可靠性"方向：这是对推理端激进量化（1–2 bit）引入的精度损失所做的机理级分析与修复——不仅证明推荐系统式"按频率分配精度"的混合精度策略在门控条件记忆中会失效（比随机更差），还量化了长尾事实知识最先被低比特量化破坏（最稀有四分位 −6.24 vs 最热门四分位 −1.51 PopQA 分）。对任何关心大模型低比特推理精度—内存—吞吐权衡的人，这篇是必读的实证参考。

## Questions for Further Exploration

- Does per-batch depth selection change outputs for the *same* request under different batch compositions, and could this become a subtle serving-time inconsistency (or even an attack surface where padding a batch shifts another request's read depths)?
- Would calibrating the deeper levels jointly with level 1 (rather than greedily encoding residuals) or learning a tiny gate-prediction head beat the current greedy ladder, and at what cost to the training-free property?
- How does the gate-frequency anti-correlation behave in models where Engram is trained for fewer tokens or with different gate parameterizations — the paper itself notes an 8B follow-up where the gate initially *favors* frequent n-grams before reversing during training?
- Can the per-lookup allocation idea extend to the *training* side (gradient-aware mixed precision for memory tables), or to other table-lookup structures like token embeddings and MoE expert weights with access gates?
- Do reasoning and code benchmarks (where Bi et al. find conditional memory can *hurt*) show the same concentration of importance, and would gate-ranked precision retrieval change failure modes there?
- What happens under query distributions far from the calibration corpus (the counting corpus is mostly English RedPajama — 43% of Chinese-text lookups hit never-seen rows); is the gate estimate still reliable for multilingual serving?
