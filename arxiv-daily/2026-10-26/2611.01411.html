Why this matters

DP guarantees certify the computation, not module labels — any batch-level data-dependent operator (quantization routing, FP8 scaling, MoE routing) can silently break record isolation.

from Relevance · batch-invariance testing as reusable methodology

Critical edge

No shipping default is shown vulnerable: Safe-Synthesizer's default physical batch of 1 is immune to the union effect, the natural excess is only 6.5% on the smallest OPT model, and the 2M-draw release audit detects no violation of the advertised ε.

Methodology

theory → fix contract → native audit · three layers

01 · Influence analysis — Prop. 1

The audited object is the clipped sum F(D) = Σ hr(D). If routing changes flip m unchanged records' clipped contributions, the triangle inequality inflates add/remove sensitivity from C to (2m+1)C. A single measured pair above C refutes separability (DP is worst-case); the Gaussian hockey-stick maps µ = 1.065 to ε 4.38 → 4.71 at δ = 1e−5.

02 · Record-isolation contract — Prop. 2 / Alg. 1

If every op producing record r's contribution reads only r's data, public state, and r's randomness, sensitivity ≤ C is restored. Record-owned precision dispatch meets it with the same INT8 + FP16 GEMMs as batched LLM.int8 — only the per-record masks change.

03 · Native audit — Alg. 2

Pinned stack (H100 · PyTorch 2.8.0+cu126 · bitsandbytes 0.49.1 · PEFT 0.18.1 · Opacus 1.5.4 · Transformers 5.12.0 — versions pinned by NeMo Safe-Synthesizer). Evidence ladder from operator → composition → pretrained OPT-125M, each rung with four matched controls, FP64 recomputation, and a pre-registered 1e−4 exceedance margin.

Strengths
  • Real premise violation, clean mechanism — batch-wide outlier union in an off-the-shelf stack, not a vague "quantization leaks" claim; Opacus's validator accepts the violating config at every batch size because it checks parameter ownership, not data dependence.
  • Template audit design — constructed witness → natural coupling → sensitivity → causal intervention → release audit, each rung with matched controls and explicit "establishes / does not establish" labels.
  • Fix is principled and essentially free — same GEMMs, only masks change, 1.5–7.5% less correction work; simpler compliant configs (singleton batches, τ=0, NF4, BF16) all restore the bound.
  • Contract-checking vs release-auditing cost analysis — a few native runs vs ~206× more Monte-Carlo draws (≈350 GPU-h); a reusable methodology takeaway.
  • Exceptional provenance — machine-readable records, source digests, retained failed attempts, FP64 reconciliation, bitwise anchors.
Limitations
  • Narrow natural-data evidence — one small model (OPT-125M), one corpus (TinyStories), one baseline batch, one training step (q = 1); prevalence across batches, models, and multi-step training unmeasured.
  • Small practical gap — natural excess 6.5% → one-step ε 4.71 vs 4.38 advertised; the 2M-draw release audit detects no advertised-guarantee violation.
  • Fix not shipped — record-owned dispatch is a specification costed on traces, not an optimized kernel; no comparison vs QUIK-style masks or singleton isolation at equal privacy.
  • Exploratory selection — screen 64 candidates × 9 radii, then pick the top; the 10/64 rate is not an unbiased prevalence estimate.
  • Entry point not audited — Safe-Synthesizer's default physical batch of 1 is a null case for the union; no shipping default shown vulnerable end-to-end.
  • Independence not fully established — residual ~10⁻⁶ gradient changes after the forced mask remain unattributed.

Questions for Further Exploration

  • Does the 6.5% excess at 125M grow toward the 15× ceiling at 7B/70B, where outlier features strengthen and persist?
  • Does the exploratory 10/64 exceedance rate survive a pre-registered confirmation study across random batches, corpora, and adapter ranks?
  • Does multi-step DP-SGD composition (Poisson sampling, momentum) compound the 4.38 → 4.71 per-step ε gap, or wash it out?
  • What is the realized throughput of an optimized record-owned kernel vs QUIK-style public masks and vectorized singleton isolation at equal privacy?
  • Does the same batch-invariance screen flag dynamic FP8 scaling, capacity-limited MoE token dropping, and reduction-order dependence — productizable alongside Opacus's module validator?

相关性：DP-SGD 的敏感度证明认证的是计算本身而非模块标签——任何对物理 batch 做数据依赖决策的算子（LLM.int8 异常列路由、动态缩放 FP8、容量受限 MoE 路由）都可能悄悄破坏记录隔离；契约检查（几次原生运行）远比发布级审计便宜。
