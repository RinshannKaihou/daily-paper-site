◆ Why this matters

When GPUs saturate, long-context agentic workloads can lean on CPUs for prefill — this is a drop-in, tuning-free recipe for exact CPU attention.

◆ Critical edge

All microbenchmarks run at batch size 1, which flatters cache-aware designs — multi-tenant concurrent prefill would contend for the very shared L3 budget the scheme depends on.

Also: “up to 2.01×” is the 128K best case (1.65× at 4K; 1.45–1.58× on desktop). The 2.45× scheduling figure is vs. their own static schedule — only +4–14% vs. a plain FIFO queue. Intel-only platforms; no public code release.

01 Methodology

Same exact math — only the work scheduling changes

FlashAttention's exact online-softmax arithmetic is untouched; CACPU reorganizes work around the CPU cache hierarchy.

  1. L3

    Group & pack for L3. Q heads are grouped so each group's K/V fit a fixed fraction of shared L3; K/V packed once per group, eliminating refetch of blocks evicted before reuse.

  2. L2

    Invert the loops for L2. KV steps become the outer loop; G consecutive q-blocks reuse one L2-resident KV step. G = (fL2·L2 − U) / Qb — derived in closed form, no per-CPU tuning (default within 0.58–2.34% of optimum).

  3. LPT

    In-kernel cost-prioritized dispatch. Each q-group's cost = exact count of non-masked tiles; lock-free shared queue per L3 chunk, sorted by descending cost; threads grab work atomically — fast P-cores self-balance on hybrid CPUs, no pinning.

  4. AMX

    Instruction-level overlap. Step j's QKT runs on AMX systolic arrays while AVX-512 applies online-softmax to tile j−1 (FA3-style pipelining).

Evaluated on Xeon 6767P (336 MB L3, AMX + AVX-512) and Core Ultra 7 265K (hybrid P/E, 30 MB L3, no AMX) · bf16, batch 1, head dim 128/192 · MHA & GQA 32:8 · 4K–256K tokens · FP64 reference + MMLU/RULER end-to-end.

Cache blocking removes the memory bottleneck but aggravates thread imbalance — on hybrid P/E cores, blocking alone is counterproductive.

  • End-to-end: SGLang TTFT up to 1.74× better at 128K (Llama-3.1-8B); consistent gains on Qwen3-8B & Mistral-7B; speedup grows with context length.
  • Queue design: up to 1.71× vs. static partitioning (Xeon) and 2.45× (265K); +14.33% / +4.16% average vs. plain FIFO.
  • Accuracy: cosine ≥ 0.999 and max abs diff 0.01 vs. FP64 reference; MMLU 66.2% vs. 66.7% official baseline; RULER reported consistent (qualitative).

03 Strengths

  • Exact, drop-in. FlashAttention arithmetic unchanged — no retraining, no approximation; plugs into PyTorch and SGLang with pretrained LLMs.

  • Analytical, tuning-free budgets. Closed-form L2/L3 sizing; default G within 0.58–2.34% of optimum across two very different CPUs (336 MB vs 30 MB L3).

  • Mechanism verified in hardware. Claims backed by DRAM-volume and L3-hit-rate counters plus an FP64 numerical reference — not just end latency.

  • Portable scheduling. Load balancing lives inside the kernel, so it transfers across serving frameworks — beats vLLM's framework-level CPU scheduler without framework changes.

04 Limitations

  • Standard causal masks only. Attention sinks, custom sparsity, and non-standard prefill break both the cost model and locality assumptions; decode not covered.

  • Intel-only evaluation. No AMD/ARM data; the GEMM/softmax overlap needs AMX, so the full recipe is x86-server-specific — portability asserted, not demonstrated.

  • Batch 1 only. Multi-request concurrent prefill — the paper's own agentic-AI motivation — is never benchmarked; tenants would contend for the shared L3.

  • Reproducibility gap. No code release; Algorithm 1 omits constants (L3 fraction, tile sizes); the RULER claim carries no numbers in the main text.

05 Open questions

  1. Q1

    Does the L3-budget model survive concurrent multi-request prefill, where several sequences share one L3 — is a runtime admission controller needed?

  2. Q2

    Can the exact-cost queue extend to decode and custom masks (sliding window, sinks, document masks) where unmasked-tile counts aren't derivable from the q-block index?

  3. Q3

    On AMD Zen 5 or ARM SVE/SME without AMX, how much of the 1.5–2.0× survives once the overlap mechanism is rewritten?

  4. Q4

    Does cache blocking stack with approximate CPU attention (top-k / LSH over the L3-resident chunk), or do the two locality strategies conflict?

  5. Q5

    Does the byte-footprint model (and the AMX pipeline) extend cleanly to fp8 / INT8 attention for further bandwidth savings?
