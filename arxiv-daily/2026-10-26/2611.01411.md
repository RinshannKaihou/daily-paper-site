> **一句话总结：** 揭示 DP-SGD + LoRA + LLM.int8 量化骨干这一主流"私有微调"组合中一个被忽视的前提失效：LLM.int8 用**整个 batch 的异常值并集**决定哪些激活列走 FP16 路径，因此加入一条记录会改变其他未变记录的算术，使裁剪和的敏感度从 C 膨胀至理论上界 (2m+1)C——构造见证在真实 CUDA 栈（bitsandbytes 0.49.1 + PEFT + Opacus）上实测 14.998C（≈15C 最坏情形），在 OPT-125M/TinyStories 自然文本上 64 个候选邻居中 10 个在完全裁剪区间超出界 1.4–6.5%（最优对原生复核 κ=1.0653C），因果定位到单一层新增一列的掩码，强制该掩码后超额消失；作者给出与批式 LLM.int8 完全相同 GEMM 的"记录私有精度分发"契约（修正工作量反而少 1.5–7.5%），并用 200 万次真实发布审计表明：发布级 ε 下界（δ=1e-5 时 3.25）仍低于宣称保证（4.38），但要在发布层面分辨如此小的超额需要约 206 倍（≈1e8 次/邻居）的抽样——直接检查敏感度契约只需几次原生运行，故契约检查才是私有量化训练的实用审计手段。

> **TL;DR:** DP-SGD's per-record clipping bound (sensitivity ≤ C for add/remove neighbors) silently assumes each record's clipped gradient depends only on that record. This paper shows LLM.int8() breaks that assumption in the standard private-QLoRA stack: its outlier set O(D) = {j : ∃r,t |A_r,t,j| ≥ τ} is a union over the whole batch, so one added record can move an activation column of every other record from the INT8 path to FP16 and change their adapter gradients — even though weights are frozen and quantization scales are row-local. On the exact CUDA stack pinned by NVIDIA NeMo Safe-Synthesizer (bitsandbytes 0.49.1, PEFT 0.18.1, Opacus 1.5.4, Transformers 5.12.0, H100), a constructed LoRA–Opacus witness reaches 14.998C vs the (2m+1)C = 15C worst case of their Proposition 1 (m=7 altered records); on pretrained OPT-125M with TinyStories, 20.1% of record–layer precision splits at batch size 16 are altered by other records (4.8% at B=2), and once every gradient is clipped (C ≤ 0.25) 10 of 64 candidate neighbors exceed the bound by 1.4–6.5%, with the top pair natively revalidated at 1.0653C while all four controls (record isolation, threshold zero, BF16, NF4) stay within C. A forward/backward factorial traces the entire excess to one column joining one layer's union (decoder layer 6 fc1: {422} → {422, 706}); forcing that mask drops the distance to 0.999998C. A 2-million-draw audit of actual released adapters finds ε lower bounds (3.25 at δ=1e-5) below the advertised 4.38 — no detected guarantee violation — but a power analysis shows resolving this 6.5% excess at the release level would need ~200× more draws, whereas contract checking exposes it in a few native runs. Their record-owned dispatch fix uses the same GEMMs and does 1.5–7.5% less correction work.

## 核心贡献

- **识别"冻结参数 ≠ 记录独立"的隐秘耦合通道**：LLM.int8 对异常激活列的判定是对整个物理 batch 取并集（任一记录的某行 |A| ≥ τ=6 即把该列送入 FP16 路径），并把这个 batch 级集合套用到每一行——于是在 DP-SGD + LoRA + 量化冻结骨干的私有微调栈里，增删一条记录会改变其他未变记录的前向算术和适配器梯度。与共享量化尺度的泄露（Quantamination）不同，这里没有任何数值统计量跨记录池化，共享的是"每列走哪条精度路径"这一**决策**本身，因此 Opacus 验证器（只拒绝 BatchNorm 这类已知跨样本层、只检查可训练参数）完全检测不到。
- **敏感度膨胀的精确刻画与紧界（命题 1）**：若 m 个未变记录的裁剪贡献因路由变化而改变，加/删邻居的敏感度上界从 C 膨胀为 (2m+1)C（替换邻居从 2C 到 2(m+1)C）；构造见证在真实 CUDA 栈上达到 14.998C，距 m=7 的最坏情形 15C 仅差 0.02%，证明该界是紧的。
- **记录隔离契约 + 零算力开销的修复（命题 2 与算法 1）**：只要产生记录 r 贡献的每个前向/反向操作只读取 r 的数据、公开状态和 r 的随机性（路由决策与持久暂存亦然），可分离界即恢复。据此定义"记录私有精度分发"：每条记录用自己的异常集 O_r 做行掩码，与批式 LLM.int8 调用**完全相同的 INT8 与 FP16 GEMM**，只改掩码构造；在 OPT-125M 轨迹上（B=2–16）分组核反而比批式少做 1.5–7.5% 的修正乘法。更简单的等价配置：单例物理 batch、阈值归零、公开校准掩码（QUIK 式）、逐向量稀疏异常（KVQuant 式）、纯权重 NF4 或 BF16。
- **一条四层证据阶梯的系统性原生审计**：算子级 → LoRA–Opacus 组合级 → 预训练 OPT-125M 自然文本级，每级配四个匹配对照（记录隔离、阈值零、BF16、NF4），逐例验证 Opacus grad_sample 与独立 autograd 一致、追踪原生 CUDA 内核分发（cint8_vector_quant / cigemmlt_32 / cdequant_mm_int32_fp16）、重复运行距离精确为零、FP64 复算，且保留全部失败尝试（附录 B）——把"在仿真器上算敏感度"与"验证过的原生计算"严格区分开。
- **"检查契约优于审计发布"的定量结论**：对选定配对做 200 万次真实 FP32 适配器发布（每邻居 1e6 次，经未修改的 Opacus 噪声 + SGD），Clopper–Pearson ε 下界（δ=1e-5 时 3.25）低于理想高斯在宣称敏感度 µ=1 的曲线（4.38），未检测到保证被违反；但功效分析表明要在发布层面分辨 µ=1.065 的超额需要约 1.0e8 次留出抽样/邻居（206 倍于其审计，≈350 GPU 时），而原生敏感度检查几次运行就确定性暴露同一超额——对小型超额，直接验证敏感度契约远比检测其发布后果便宜。

## Key Contributions

- **Identifies a hidden coupling channel: frozen parameters ≠ record independence.** LLM.int8's outlier decision is a union over the whole physical batch (any record's row with |A| ≥ τ=6 sends that column to FP16 for *every* record), so adding or removing one record changes the arithmetic — and the adapter gradients — of all other records in a DP-SGD + LoRA + quantized-backbone private fine-tuning stack. Unlike shared-quantization-scale leakage (Quantamination), no numerical statistic is pooled; what is shared is the *decision* of which precision path each column takes, which is why Opacus's validator (which rejects known cross-example layers like BatchNorm and checks only trainable parameters) accepts the violating configuration at every batch size.
- **A tight influence bound (Prop. 1).** If routing changes flip m unchanged records' clipped contributions, add/remove sensitivity inflates from C to (2m+1)C (replacement: 2C to 2(m+1)C); a constructed witness on the real CUDA stack attains 14.998C against the m=7 worst case of 15C (within 0.02%), proving tightness. A single measured pair above C refutes the separable bound, since DP is a worst-case guarantee.
- **A record-isolation contract and a zero-arithmetic-cost fix (Prop. 2, Alg. 1).** If every operation producing record r's contribution reads only r's data, public state, and r's randomness, the separable bound is restored. Record-owned precision dispatch meets it with the *same* INT8 and FP16 GEMMs as batched LLM.int8 — only the masks change — and a grouped kernel does 1.5–7.5% *less* correction work on OPT-125M traces (B=2–16). Simpler compliant configurations: singleton physical batches, threshold zero, public calibrated masks (QUIK-style), per-vector sparse outliers (KVQuant-style), weight-only NF4, or BF16.
- **A four-rung native audit with matched controls.** Operator → LoRA–Opacus composition → pretrained OPT-125M, each rung paired with four controls (record isolation, threshold zero, BF16, NF4), per-case validation of Opacus grad_sample against independent autograd, tracing of the actual CUDA kernel dispatch, exactly-zero repeat-distance floors, FP64 recomputation, and retained failed attempts — cleanly separating a validated native computation from a sensitivity calculation on an emulator.
- **A quantitative case for contract checking over release auditing.** A 2-million-draw audit of actual released adapters yields ε lower bounds (3.25 at δ=1e-5) below the advertised guarantee (ideal Gaussian at µ=1: 4.38) — no detected violation — but the power analysis shows resolving the measured 6.5% excess at the release level would take ~1.0×10⁸ held-out draws per neighbor (206× their audit, ≈350 GPU-hours), whereas the native sensitivity check exposes the same excess deterministically in a handful of runs.

## Methodology

The paper proceeds in three layers: theory, a fix specification, and a native audit.

**Influence analysis (Prop. 1).** The audited object is the clipped sum F(D) = Σ_r h_r(D), where h_r is record r's adapter gradient as computed *inside* batch D, clipped to norm C. If routing changes flip m unchanged contributions, the triangle inequality gives ∥F(D)−F(D′)∥ ≤ (2m+1)C for add/remove neighbors. Crucially, a *single measured pair* above C refutes the separable bound for that computation (DP is a worst-case guarantee), while pairs below C prove nothing — an asymmetry the audit exploits. They connect sensitivity to the release via the exact hockey-stick divergence of the Gaussian mechanism (Balle & Wang): µ = 1.065 instead of 1 raises one-step ε at δ=1e-5 from 4.38 to 4.71.

**Record-isolation contract and dispatch (Prop. 2, Alg. 1).** The contract requires every op producing record r's contribution (forward, backward, routing, persistent scratch, numerical choices) to read only r's data, public state, and r's randomness; an induction over a topological order of the computation graph then restores sensitivity ≤ C. Algorithm 1 implements record-owned LLM.int8: a per-entry threshold test, a segmented reduction builds per-record outlier sets O_r, rows are masked with their owner's O_r, and one dense INT8 GEMM plus per-record FP16 corrections are issued — the same kernels as batched LLM.int8, with the union of weight columns fetched once per batch (weights are public) but never allowed to decide another record's correction. The backward pass needs the same ownership audit; the authors stress that Opacus validating only directly trainable parameters cannot establish isolation, since frozen quantized layers feed data-dependent activations into trainable adapters.

**Native audit (Alg. 2).** Stack: one NVIDIA H100 NVL, PyTorch 2.8.0+cu126, bitsandbytes 0.49.1, PEFT 0.18.1, Opacus 1.5.4, Transformers 5.12.0 — the versions pinned by NVIDIA NeMo Safe-Synthesizer commit 7f3b767c (they execute the pinned components, not the entry point). Evidence ladder: (1) an operator witness on a real `Linear8bitLt` layer with weight [1,0], eight activation rows, τ=6, C=0.005, where a replacement row crossing τ flips seven unchanged rows' bias-gradient signs so each clipped contribution moves by 2C; (2) the same construction with a real rank-one PEFT LoRA adapter under full Opacus clipping/noise/SGD; (3) pretrained OPT-125M with rank-8 LoRA on query/value projections (294,912 trainable parameters, 48 tensors) on the first 16 TinyStories training windows (256 tokens, official masks, masked next-token loss, q=1, fixed public divisor). For natural data: a 7-record baseline batch, 64 candidate additions, a screening radius C=1, then an exploratory re-clipping of saved native per-record gradients at nine radii, native revalidation of the top pair in 40 fresh cases across all five arms, a forward factorial and forced-mask backward intervention for causal localization, and finally a release audit replaying the accepted clipped sums through unmodified Opacus noising and Torch SGD for 2×10^6 draws (≈3 ms per release, 1.7 GPU-hours), with threshold selection on half the draws and held-out evaluation on the other half, family-wise 95% Clopper–Pearson bounds. Exceedance is declared only above the bound plus a 1e-4 absolute margin fixed before screening; FP64 measurement from saved FP32 contributions; identical-batch repeats give exactly zero distance.

## Results & Highlights

- **Constructed LoRA–Opacus witness on the pinned CUDA stack reaches 14.998C vs the (2m+1)C = 15C worst case of Prop. 1 (m=7), i.e., 15.0× the add/remove bound C; the operator-level witness hits exactly 14C_f, i.e., 7.000× the 2C replacement bound** — while all four controls (record-isolated INT8, threshold zero, BF16, NF4) stay within their bounds (add/remove 0.99999979C–1.000C, replacement 0) and an identical-input null gives exactly 0. Under Eq. (5), a pair this far apart would raise one-step ε at δ=1e-5, σ=1 from 4.38 to about 176.
- **Coupling is routine on natural text (OPT-125M, TinyStories, τ=6): 4.8% of (record, layer) precision splits in the 42 outlier-carrying layers compute some column in FP16 only because another record crossed τ at B=2, rising to 20.1% at B=16; 7.0% of all FP16 columns applied to a record were triggered by others.** Per-layer at B=16: all 16 records are coupled in layer 7's attention input, 13–14 records in layer 9's attention input and layer 11's fc1, while 15 of 22 outlier-carrying cells show no coupling (most outlier columns are shared by all records — only 3–7 columns per batch are single-record-owned).
- **Sensitivity excess on natural data appears only once clipping is active: the initial screen at C=1 is negative (max 0.99999921C over 64 candidates), but re-clipping saved native gradients at nine radii (C ≤ 0.25, all gradients clipped) finds 10 of 64 candidates exceeding the bound by 1.4–6.5%; the top pair, revalidated in 40 fresh native cases, measures ∆ = 0.2663144763 = 1.065257905C at C=0.25 (same ratio at C=0.001), four orders of magnitude above every control's deviation (≤ 2.4×10⁻⁶ for isolation/threshold-zero/BF16; NF4 4.7×10⁻⁴ below C).**
- **Causal localization: of the 72 INT8 layer unions exactly one differs between D and D′ — decoder layer 6's first feed-forward projection grows from {422} to {422, 706}; the seven common records' LoRA gradients differ by 0.048–0.071 in ℓ2. A forward factorial shows the captured activations are bitwise identical under D and D′ while swapping only the mask reproduces the entire logit change (max abs diff 0.36630, ℓ2 309.3763); forcing the frozen union through native backward drops the clipped-sum distance from 1.065257905C to 0.999997838C and shrinks each common record's gradient change from 0.048–0.071 to 1.1–2.7×10⁻⁶ (four orders of magnitude).**
- **Release audit (2×10⁶ actual FP32 adapter releases, 10⁶ per neighbor): held-out counts 1,043/500,000 for D′ vs 23/500,000 for D at threshold 5.2083 give ε lower bounds 2.53 / 3.25 / 3.26 at δ = 1e-3 / 1e-5 / 1e-6 — below the ideal real-Gaussian curve at the advertised µ=1 (3.14 / 4.38 / 4.89), so no violation of the advertised guarantee is detected; the power analysis shows an audit would need ≈1.0×10⁸ held-out draws per neighbor (206× theirs, ≈350 GPU-hours) before the expected bound for the measured µ=1.065 pair first exceeds the advertised ε=4.38 at δ=1e-5.**
- **Record-owned dispatch is arithmetic-neutral: it issues the same INT8 and FP16 GEMMs as batched LLM.int8, and on the OPT-125M traces at B=2–16 a grouped kernel skipping zeros does 1.5–7.5% less correction work than batched LLM.int8 (correction covers at most 8 of a layer's 768 or 3,072 input columns).**

## Authors & Credibility

Annan Zhang, Shengjie Song, Wenshuai Yao, and Lihao Zhang are at Peking University; Tianmiao is at Beihang University (the author list reads like a preliminary MLSys submission — "Under review by the Machine Learning and Systems (MLSys) Conference", arXiv v1, 1 Nov 2026). No prior flagship-track track record is claimed, but the execution is unusually careful for a first audit paper: every number traces to machine-readable provenance records with package-source and CUDA-library digests (Appendix B); failed attempts are retained and reported (e.g., a rejected 128-token shape assumption, four BF16 controls that failed initialization checks and were completed via a separately versioned supplement); measurements are cross-validated three ways (Opacus grad_sample vs independent autograd in all 20 constructed measurements, FP64 CPU reconciliation of all 40 selected-radius cases, bitwise anchor reproduction in the release audit); and the exceedance margin (1e-4) plus the "declared outcome" convention were fixed in the protocol before screening. The AI-usage disclosure limits LLM assistance to language and figure polish. The framing is consistently anti-overclaiming: Table 1 states for each rung what it establishes *and does not* (e.g., the release audit establishes "no detected guarantee violation (not: a privacy proof)").

## Critical Assessment

- **Novelty: genuine and well-differentiated.** The failure channel — a data-dependent *precision-routing decision* pooled over the batch, with row-local scales — is distinct from shared-scale leakage (Quantamination, Foerster et al. 2026) and from architectural backdoors (Küchler et al. 2026), and the observation that Opacus's validator accepts the violating configuration at every batch size because it checks parameter ownership rather than data dependence is the sharpest systems-level lesson. The theoretical content (Prop. 1 is a triangle inequality; Prop. 2 an induction) is deliberately elementary — the authors say so — with the value in the native measurement machinery.
- **Rigor: exemplary in measurement, honest in scope.** Bitwise kernel-dispatch tracing, zero measurement floor, a pre-registered margin, retained failures, and a power analysis that quantifies *why* their release audit could not have detected the excess are all above the norm. The constructed witness attaining 14.998C against the 15C bound is convincing evidence the kernels execute the coupling.
- **Practical significance: currently modest, and the paper admits it.** The natural-data excess is 6.5% on OPT-125M — the smallest model in the relevant family, where outlier features are weakest (Dettmers et al. show outliers strengthen with scale, which cuts both ways: bigger models may couple more, but this is untested here) — and the 2M-draw audit finds *no* violation of the advertised ε. Worse for immediacy, the audited NVIDIA Safe-Synthesizer's own default entry point uses physical batch size 1, which is a null case for the union; the threat requires practitioners who batch physically through LLM.int8 under DP, a configuration the paper demonstrates is possible and passes validation but does not show is common in deployment.
- **Statistical caveats the authors mostly own.** The OPT-125M sensitivity result comes from one exploratory study on one baseline batch: 64 candidates screened across 9 radii (576 scores), then the top-ranked candidate selected and revalidated — a selection procedure with multiple-comparison risk that native revalidation mitigates but does not eliminate; the paper says "these results show that the separable premise fails for a natural pretrained configuration; they do not estimate how often it fails across batches or models." Missing ablations/settings: no larger OPT models, no second corpus, no multi-step training audit (one step at q=1 only), no optimized-kernel implementation of record-owned dispatch (Algorithm 1 is a specification plus traces, not a shipped kernel), and the forced-mask intervention is post hoc — a diagnostic, not a deployable policy. The residual 1.1–2.7×10⁻⁶ gradient change after forcing the mask is unattributed (batch-shape-dependent kernel numerics is a candidate), so exact independence is not established even for the fixed pair.
- **Red flags: minimal.** The µ=1.065 → ε 4.38→4.71 arithmetic is correct but small; the abstract's "15.0×" headline is a constructed witness, clearly labeled "not a natural task." One could quibble that "10 of 64 above the bound" comes from an exploratory re-clipping analysis whose radius was then chosen post hoc — but the 40-case native validation at the pre-committed margin, with all four controls passing, is the right controls for exactly this worry.

## Strengths

- Identifies a real, previously unstated premise violation in an off-the-shelf, widely composed private-fine-tuning stack (DP-SGD + LoRA + LLM.int8), with a clean causal mechanism (batch-wide outlier union) rather than a vague "quantization leaks" claim.
- The evidence ladder design is a template for systems privacy audits: constructed witness → natural coupling → natural sensitivity → causal intervention → release audit, each with matched controls and explicit "establishes / does not establish" labels.
- The proposed fix is principled and essentially free (same GEMMs, only masks change, 1.5–7.5% *less* correction work), and simpler record-local configurations (singleton batches, τ=0, NF4, BF16) are validated as restoring the bound in every measured setting.
- The contract-checking-vs-release-auditing cost analysis (a few native runs vs ~206× more Monte-Carlo draws / ≈350 GPU-hours) is a genuinely useful methodological takeaway for anyone auditing DP training.
- Exceptional provenance discipline: machine-readable records, source digests, retained failures, FP64/CPU reconciliation, bitwise anchors.

## Limitations

- Natural-data evidence covers one small model (OPT-125M, 125M params), one corpus (TinyStories), one baseline batch, and one training step with q=1; prevalence across batches, models, corpora, and multi-step Poisson-sampled training is unmeasured.
- The measured natural excess (6.5%) translates to a one-step ε of 4.71 vs 4.38 advertised at δ=1e-5 — a real but small gap, and the release-level audit detects no violation of the advertised guarantee at 2M draws.
- Record-owned dispatch is specified (Algorithm 1) and costed on traces but not implemented as an optimized kernel; no quality/resource comparison against optimized alternatives (QUIK-style public masks, KVQuant-style sparse outliers, vectorized singleton isolation) at equal privacy.
- The discovery pipeline (screen 64 candidates × 9 radii, pick the top) is exploratory; the 10/64 exceedance rate is not an unbiased prevalence estimate, and the authors' repeated single-batch design limits generalization.
- They audited Safe-Synthesizer's pinned components but not its entry point, whose default physical batch of 1 is immune to the union effect — so no currently shipping default configuration is shown to be vulnerable end-to-end.
- Exact record independence is not established even for the audited pair (residual ~10⁻⁶ gradient changes after the forced mask remain unattributed), and backward dispatch/schedules/caches beyond the audited paths are not verified.

## Relevance

对"私有微调 + 量化 + LoRA"这一效率与隐私交叉的技术栈给出了前提级的安全审计：它说明 DP-SGD 的敏感度证明认证的是**计算本身**而非模块标签，任何对物理 batch 做数据依赖决策的算子（LLM.int8 的异常列路由、动态缩放 FP8、容量受限 MoE 路由）都可能悄悄破坏记录隔离——这对构建高效 LLM 训练/微调系统并关心其可信性的人来说，既是具体的坑（批式 LLM.int8 + DP），也是一套可复用的"批不变性"测试方法学。

## Questions for Further Exploration

- How does the excess scale with model size? Larger OPT/Llama models have stronger, more persistent outlier features (per Dettmers et al.) — does the 6.5% excess at 125M grow toward the constructed 15× ceiling at 7B/70B, and do more layers become single-record-coupled?
- What is the prevalence of bound violations across random baseline batches, corpora, and adapter ranks, rather than one selected pair from one batch — and does the 10/64 exploratory rate survive a pre-registered confirmation study?
- Do multi-step DP-SGD training runs (Poisson sampling, accumulation, momentum) compound the one-step ε gap (4.38 → 4.71), or does the accountant's composition wash out a per-step 6.5% sensitivity excess?
- An optimized record-owned INT8 kernel exists only as a specification: what is its realized throughput vs batched LLM.int8, QUIK-style public calibrated masks, and vectorized singleton isolation at equal privacy and equal model quality?
- Does the same batch-invariance screen flag the other candidate channels the authors list — per-tensor dynamic FP8 scaling, capacity-limited MoE token dropping, batch-shape-dependent reduction orders — and can it be productized as a standard validator check alongside Opacus's module validation?
