> **一句话总结：** 首个针对 LLM Agent 中"提示词缓存集成错误"的实证研究——从 10 个热门开源 Agent 系统的 148,947 个已合并 PR 中提炼出 120 个真实缺陷（90% 静默失效、只会推高账单），并据此构建静态检测工具 CacheLint（CodeQL 定位调用点 + 带日期的提供商能力矩阵 + LLM 守卫检查），在 120 个标注缺陷上取得 0.71 精确率 / 0.78 召回率，在 571 个真实仓库上以 0.86 精确率发现 32 个未知缺陷，获维护者确认 21 处、上游修复 18 处（含 Anthropic 官方 .NET SDK）。

> **TL;DR:** Prompt caching cuts cached-token cost to ~1/10 of standard price, but agent code integrates it wrongly far more often than anyone noticed: an empirical study of 120 real defects across 10 star open-source agent systems (OpenClaw, Hermes-Agent, AutoGPT, Cline, OpenHands, ...) finds 90% fail silently — outputs stay correct, only the bill climbs. The resulting detector CacheLint reaches 0.71 precision / 0.78 recall on those 120 labeled defects and 0.86 precision (32 TP / 5 FP) on 571 held-out repositories, yielding 21 maintainer confirmations and 18 upstream fixes; the ablation shows both components are load-bearing — removing the dated capability oracle collapses precision from 0.86 to 0.05, and removing the LLM guard check drops it to 0.31.

## 核心贡献

- **首个提示词缓存集成错误的实证研究**：从 GitHub 搜索到的 581 个仓库中选出 10 个最流行的开源 Agent 应用（合计约 148,947 个已合并 PR），人工筛出 120 个提示词缓存相关缺陷，用开放编码法建立"8 类根因 / 2 类症状 / 6 类修复"的完整分类体系，并公开数据集。
- **揭示"静默昂贵"的缺陷本质**：120 个缺陷中 108 个（90%）不报任何错误——模型照常给出正确答案，唯一痕迹是缓存命中率下降带来的额外开销（如 hermes-agent#754 中网关每轮重组系统提示词使成本上升约 75%）；这使得基于崩溃/断言的动态测试预言（oracle）在结构上失效。
- **定位缺陷的两大来源**：请求侧错误 97 个（81%），其中提供商兼容性问题 47 个（39%，如按模型名硬编码开启缓存）、前缀不稳定 41 个（34%，如系统提示词里嵌入秒级时间戳、未排序的序列化键）；读取侧用量误计 23 个（19%）。
- **发现修复高度模式化**：仅按根因映射到最常见修复策略即可正确预测 95/120（79%）个修复；68% 的修复是小型、静态、局部的代码改动。
- **构建 CacheLint 检测器**：把缺陷统一建模为"调用点 m + 未被守卫解除的前提条件 j（前缀稳定性 STAB / 提供商能力 CAP / 计账安全 ACCT）"，用 CodeQL 定位调用点，CAP 对照带日期的能力预言机（oracle）、STAB/ACCT 用 gpt-5.4-mini 做守卫检查，每条告警附带建议修复模板。
- **真实世界验证**：在 571 个未见过的仓库上以 0.86 精确率发现 32 个未知缺陷，21 处获维护者确认、18 处被上游修复，其中包括 Anthropic 官方 .NET SDK（anthropic-sdk-csharp）中的缓存用量字段空值缺陷。

## Key Contributions

- **First empirical study of prompt-caching mis-integration**: from 581 GitHub repositories, the 10 most popular open-source agent applications were selected; three authors manually screened 622 keyword-matched merged PRs (from 148,947 total) down to 120 genuine prompt-caching defects (Fleiss' κ = 0.76), then open-coded them into 8 root causes, 2 symptom classes, and 6 fix strategies. Dataset and artifacts are publicly released.
- **Establishes that this defect class is overwhelmingly silent**: 108/120 defects (90%) raise no exception and preserve model output; 86 (72%) are pure "silent waste" and 22 (18%) produce wrong telemetry (e.g., cline#10266 hardcodes cache-creation tokens to zero, so the usage meter itself lies). Only 12/120 (10%) crash — so crash-based oracles miss the class by construction.
- **A generalizable taxonomy**: request-side defects dominate (97/120, 81%) — provider compatibility (47, 39%; model-name gating 37, incompatible markers 10) and prefix instability (41, 34%; prefix reassembly 15, volatile values 13, nondeterministic serialization 10, misplaced markers 3) — plus cross-turn mutation (9, 8%) and read-side usage miscounts (23, 19%).
- **A uniform formalization enabling detection**: every mis-integration is a pair ⟨invocation site m, unchecked precondition j ∈ {STAB, CAP, ACCT}⟩; CacheLint locates sites with CodeQL (Python, JS/TS, Ruby, Go, C#), discharges CAP against a dated provider-capability oracle (with last_verified dates and reject/ignore/unknown behavior), and STAB/ACCT via an LLM guard check (gpt-5.4-mini) that asks whether a discharging barrier (e.g., date() truncation, sort_keys, a .get(..., 0) guard) reaches the site.
- **Practical impact**: on 571 held-out real-world repositories, CacheLint found 32 previously unknown mis-integrations at 0.86 precision; maintainers confirmed 21 reports and fixed 18, including one in Anthropic's official .NET SDK — evidence the patterns recur even in provider-maintained code.

## Methodology

The work proceeds in three stages.

**1. Empirical study (RQ1–RQ3).** A keyword search over provider cache markers (cache_control, cachePoint, cachedContent, prompt_cache_key), usage fields (cached_tokens, cache_read, cache_creation), and the phrase "prompt caching" returned 581 repositories; filtering for general-purpose end-user agents with active maintenance and verified source-level caching integration yielded the top-10 by stars (OpenClaw 379k stars, Hermes-Agent 199k, AutoGPT 185k, OpenCode 177k, LobeHub 79k, OpenHands 78k, Cline 64k, Goose 50k, Aider 47k, Nanobot 44k — spanning TypeScript, Python, Rust, and the major providers). The GitHub Search API over their 148,947 merged PRs returned 622 candidates, manually screened to 120 genuine defects. Three authors (each with 2+ years of agent development experience) independently open-coded every defect; disagreements were resolved by consensus.

**2. Integration modeling.** The 120 fixes expose a shared structure: each defect is an invocation site m (attaching a cache marker to a prefix span, or consuming a usage field) reached on a path where a required precondition conjunct j is not guaranteed. STAB conjuncts cover volatile values, nondeterministic serialization, and markers on unstable spans; CAP conjuncts cover predicates that gate markers on model names or marker shapes a provider rejects; ACCT conjuncts cover unguarded consumption of nullable usage fields. Multi-snapshot causes (prefix reassembly, cross-turn mutation) fall outside this single-program-state grammar by design. A mis-integration is the triple ⟨m, j, ¬GUARD⟩.

**3. Detection (CacheLint, Algorithm 1).** For each mined anti-pattern pair, CodeQL queries locate invocation sites. CAP conjuncts are settled off-program: the code's capability assumption is diffed against a dated capability matrix sourced from provider documentation — over-claims against a rejecting provider yield a hard BUG, unknown behavior yields SUSPECTED, silently-ignoring providers are benign, and under-claims (cacheable model excluded by the code) yield a silent LATENT miss. Because provider semantics evolve (Bedrock's one-hour TTL; Anthropic silently cutting its default cache TTL from 1 hour to 5 minutes), every matrix entry carries a last_verified date, and provider changes enter through the matrix rather than the rules. STAB/ACCT conjuncts are settled on-program by the gpt-5.4-mini guard check, which replaces a brittle inter-procedural backward slice under dynamic dispatch and reflection. Each warning ships with a fix hint from the empirical cause-to-fix map (e.g., capability lookup for model-name gating, cache-boundary fix for volatile values, usage-counter fix for miscounts).

## Results & Highlights

- **On Dataset A (the 120 labeled mis-integrations in the 10 studied agent systems), CacheLint achieves 0.71 precision and 0.78 recall** — 132 warnings, 94 TP, 38 FP, 26 FN. Within its stated single-site scope it recovers 94 of the 96 in-scope defects; 24 of the 26 false negatives are multi-site/multi-turn defects (15 prefix reassembly, 9 cross-turn mutation) that the single-site model excludes by design.
- **On Dataset B (571 held-out real-world repositories), CacheLint reports 37 warnings: 32 true positives and 5 false positives across 33 projects — precision 0.86** (vs 0.71 in-sample), finding defects in flagship projects such as n8n (194,717 stars), langchain, litellm, gemini-cli, and Zed. All 32 TPs were manually reproduced (runtime errors triggered for the 5 crash defects; request/response cache-usage fields inspected for the 27 silent ones).
- **Ablation on Dataset B shows both components are essential: full CacheLint 0.86 precision (32 TP / 5 FP); without the LLM guard check, 0.31 (18 TP / 41 FP); without the dated capability oracle, 0.05 (17 TP / 349 FP)** — the oracle-less variant drowns in 349 mostly-benign model-name branches, and the guard-less variant flags sites whose preconditions are already satisfied (e.g., unsloth's day-granularity date() timestamp, litellm's .get(..., 0) guarded accounting).
- **The defect class is 90% silent: 108/120 defects raise no error**; only 12/120 crash, and 8 of those 12 come from a single root cause (incompatible markers, e.g., nanobot#2687 attaching Anthropic cache_control to OpenRouter-routed GPT/Gemini/DeepSeek calls → 401 errors). Request-side defects dominate at 97/120 (81%), with provider compatibility (47, 39%) and prefix instability (41, 34%) as the two biggest root-cause groups.
- **Fixes are small and predictable**: assigning each root cause its modal fix strategy correctly predicts 95/120 (79%) fixes (U(fix | rc) = 0.72); five cause→strategy mappings are deterministic (e.g., 23/23 usage miscounts → usage-counter fixes, 13/13 volatile values → cache-boundary fixes), and 68% of all fixes are small, static, local edits.
- **Real-world deployment: 21 of the 32 reported findings confirmed by maintainers, 18 fixed upstream, 11 awaiting response, 0 rejected** — including AutoGPT, n8n, Zed, altimate-code (hard-coded model-path gating fixed with a capability check), iTerm2 (request-varying value moved out of the cached system prompt), and Anthropic's official .NET SDK (nullable cache-usage fields consumed without a null check).
- **Stability and oracle necessity**: across five runs precision deviated by at most +0.02; and when quizzed on the 33 dated one-hour-TTL capability facts encoded in the matrix, the guard LLM (gpt-5.4-mini) answers only 5 confidently and correctly — quantifying why the dated oracle must exist as a component.
- **Cost context**: prompt caching prices cached input tokens at roughly 1/10 of the standard rate and cuts latency by up to 80%; enterprise LLM API spend reached $8.4B by mid-2025, so a silently disabled cache is a material line item (hermes-agent#754: per-turn system-prompt reassembly lifted cost by ~75%).

## Authors & Credibility

The team spans Wake Forest University, Griffith University, Nanyang Technological University (Singapore), UNSW Sydney, and Southern University of Science and Technology (Shenzhen) — experienced software-engineering empirical-research groups (the same community that produced the LLM-inference-engine and agent-framework bug characterization literature they cite). Ying Zhang and Ruoqi Guo share first authorship; Yi Liu (Griffith) is corresponding author. Methodological credibility is high: three-author independent screening with a reported Fleiss' κ of 0.76, consensus-based open coding, a second screening pass that found no additional false matches, manual reproduction of all 32 out-of-sample true positives, and upstream validation — 21 maintainer confirmations and 18 merged fixes (none rejected) is unusually strong external evidence for a bug-finding paper. Dataset and source code are released. The paper is a 13-page cs.SE submission (arXiv v2, 27 Oct 2026) in IEEE conference format.

## Critical Assessment

- **Novelty**: genuine and well-motivated. Prior work either catalogs prompt defects (Tian et al.) or tunes caching strategies (Lumer et al.); nobody had characterized application-side caching mis-integration. The "silent performance defect that defeats crash oracles" framing and the dated-oracle idea (CAP facts are time-varying external truths no static rule can encode) are the two most original ideas.
- **Rigor caveats the authors themselves flag**: the 0.78 recall is an in-sample upper bound — the detection rules were mined from the same 120 fixes, and the authors say so honestly. The only independent recall-free evidence is Dataset B's 0.86 precision, which has no recall denominator (the true defect count in those 571 repos is unknown).
- **An unexplained inversion worth noting**: precision on the in-sample corpus (0.71) is lower than on the held-out 571 repositories (0.86). The paper does not analyze why its own derivation corpus yields more false positives; one plausible factor (Dataset A's larger, more polymorphic codebases vs Dataset B's many small tools) is left unexamined.
- **Scope hole by construction**: the single-site model excludes the two multi-snapshot root causes (prefix reassembly, cross-turn mutation), which account for 24 of the 26 false negatives — CacheLint covers 96/120 (80%) of known defect types and cannot see the rest.
- **LLM-guard brittleness is quantified but not solved**: the guard check is admitted to be unsound (it can overlook a real guard or posit a spurious one), is tied to one specific model (gpt-5.4-mini) with no comparison against alternative guard models, and gpt-5.4-mini's 5/33 score on dated TTL facts shows how quickly stale model knowledge goes wrong — the mitigation (the oracle) shifts the maintenance burden onto manually updating a capability matrix tied to a 2026-05-10 snapshot.
- **Mild confirmation risk in RQ6**: 11 of 32 reports were still awaiting response at writing time, and the confirmations (0 rejections) are self-reported; the two reproduction categories are also asymmetric — "inspected request/response pairs" for silent defects is weaker evidence than triggering a runtime crash.
- **Benchmark quirks**: the ground truth is bounded by merged fixing PRs (defects fixed without a PR, or never noticed, are invisible), and the keyword search over PR text plus the exclusion of SDKs/frameworks from the study corpus may bias the taxonomy toward application code — though the confirmed Anthropic-SDK defect partially rebuts this.

## Strengths

- Defines and owns a previously unstudied, practically expensive defect class, with a public 120-defect dataset from systems with 44k–380k stars.
- The 90%-silent finding is not just a statistic — it is turned into a design argument for static analysis over dynamic oracles, and the argument holds up (the 12 crashing defects would have been caught by any single test run; the other 108 would not).
- The hybrid discharge mechanism is principled: time-varying external facts (CAP) go to a dated, sourced, versioned oracle; program-internal facts (STAB/ACCT) go to an LLM guard check standing in for a backward slice — and the ablation (0.86 vs 0.31 vs 0.05) proves both halves earn their keep rather than assuming it.
- Fixes are predictable (79% from a modal map) and every warning ships with the fix class developers actually apply — a rare tight loop from empirical study to actionable tooling.
- External validation is exceptional for this genre: 32 new defects, 21 confirmed, 18 fixed upstream including a vendor's own official SDK, with artifacts released.

## Limitations

- No recall measurement on the 571 held-out repositories; in-sample recall (0.78) is an optimistic proxy, as the authors acknowledge.
- Multi-snapshot defect classes — prefix reassembly and cross-turn mutation (24/120 known defects) — are out of scope of the current single-site model and constitute 24 of its 26 misses.
- Implicit provider-side caching (e.g., OpenAI/Gemini auto-caching, where a defect is visible only as consistently zero cached tokens in responses) is explicitly outside current scope.
- Dependence on a manually maintained, dated capability matrix (2026-05-10 snapshot) and on a single guard LLM (gpt-5.4-mini) whose behavior can drift with provider and model updates; guard-check unsoundness means both false warnings and misses remain possible.
- The empirical corpus excludes SDKs and frameworks, and defects without a merged fixing PR are unobservable, so the taxonomy is a lower bound on the phenomenon.
- No automated fix generation or validation yet (stated as future work), and no runtime/performance profiling is integrated to estimate the dollar impact of each detected defect.

## Relevance

直接命中"Agent & Pipeline Silent Failures"方向：这是关于 Agent 软件层（提示词构造、缓存配置、用量统计）如何静默地改变模型实际收到/计费的内容及其检测与修复的研究，且 90% 静默失效的核心发现与该方向关注的"无报错但出问题"的故障模式完全一致；对构建自进化/长程 Agent 系统的成本可靠性与可观测性也有直接参考价值。

## Questions for Further Exploration

- Could the two out-of-scope multi-snapshot root causes (prefix reassembly, cross-turn mutation) be covered by pairing CacheLint with a lightweight runtime prefix-recorder that snapshots the actual byte-level prompt sent per turn, rather than a full dynamic oracle?
- Since providers change caching semantics unilaterally (e.g., Anthropic's TTL cut from 1 hour to 5 minutes), could CI integrate the dated oracle so a provider-side change automatically re-opens previously green builds as regressions?
- How much money do these defects actually cost? The paper shows one ~75% cost-increase case; a longitudinal study quantifying wasted spend per defect pattern would sharpen prioritization.
- Can the guard check be replaced or cross-checked by a deterministic abstract-interpretation of serialization order (dict ordering, kwargs, JSON key sorting) to remove the single-LLM dependency and its unsoundness?
- Does the taxonomy transfer to implicit-caching providers (OpenAI, Gemini), where the only signal is zero cached_tokens in responses — and could a response-side "cache-hit linter" complement the code-side detector?
- The 0.71 in-sample vs 0.86 out-of-sample precision inversion: is precision a function of codebase size/polymorphism rather than in-sample familiarity, and what does that imply for deploying such detectors on very large monorepos?
