Methodology — distilled

Learner Megatron-Core + Transformer Engine, BF16 master weights / FP32 optimizer. Decoder linear GEMMs (fprop · dgrad · wgrad) run MXFP8 — E4M3 elements, 1×32 blocks, E8M0 scales inside Blackwell's block-scaled MMA.
↓ every optimizer step — quantize W with the learner's own TE quantizer
Sampler vLLM / SGLang receives the learner's exact FP8 grid (byte-identical, ~600 MB). A refit cycle (record → stage → load → reprocess → fold) rebuilds engine-side kernel layouts in place, so CUDA-graph-captured addresses stay valid.
kept high-precision: embeddings · lm_head · MoE router · norms · attention  |  padding lcm 16 → 32 (MXFP8 wgrad scales run along tokens)

How it fails · silent weight-sync breakage
7 / 7CONDITIONS
Seven real failures on B200 — each broke exactly one of the C1–C7 sync conditions; five were silent. Complementary run-time guards (kernel self-check, engine-state audit, step sentinel) caught the silent ones; 108 CPU fault-injection tests reproduce five of them.
  • F1 lm_head quantized → NaN logits; reward 0.000 for all 20 steps (healthy: 0.316) — looked like a normal run.
  • F2 vLLM 0.24 substring matching silently left gate_up_proj — 52% of each layer's linear weights — in BF16 (56/311 params); caught only by the engine-state audit. The dense "MXFP8/MXFP8" results were therefore run half-matched.
  • F4 stale MoE expert layout — probe rel. error 1.74 vs healthy 0.05, yet KL 0.047 sits below any plausible divergence alarm; caught only by the kernel self-check.
Quality & entropy signals

Held-out gsm8k acc. after 60 steps: 0.9393 (MXFP8/MXFP8) vs 0.9363 (BF16) vs 0.9249 (FP8-TW) — within author-quantified noise (samplers alone differ by 1.9 pts). Policy entropy: flat/rising under MXFP8 (+4%, MoE +6%) vs −74% collapse under FP8-TW with inflated training reward (0.240 vs 0.150). FP8 memory cost: MoE actor peak +25% (60.0 → 75.0 GiB).

Strengths

  • Answers exactly what practitioners ask — what matching buys, when FP8 pays, how it fails — with controlled experiments (fixed weights, paired prompts, replayed data), not end-to-end anecdotes.
  • Break-even model validated four independent ways (sweep, within-run crossing, held-out workload, host dependence); mechanism traced to host-side dispatch gaps; remedies — CUDA graphs, TE ≥ 2.18 preswizzled weight scales — already implemented upstream.
  • Seven silent failures turned into reusable infrastructure: a correctness spec (C1–C7), guards whose blind spots are stated by construction, and 108 CPU-injectable tests in verl.
  • Exceptional honesty: scope limits in the abstract, discarded measurement rounds disclosed, baseline pathology separated from the matching effect, no final-quality overclaim.

Limitations

  • Single seed per arm; runs of 10–60 steps (controlled runs 3–12) — no statement about final model quality is possible; entropy effects on learning left open.
  • Matching gain measured only at the initial checkpoint, in one engine; conflates weight grid, activation quantization, and kernel terms — the proposed dequantized-sampler ablations were not run.
  • Setting B's FP8 KV cache confounds every arm; dense rollout speed effectively unmeasured (SGLang's default Triton path was 1.9× slower than BF16 generation).
  • Break-even fit from one model and one host type; the sweep ran each configuration once (BF16's 8-seq point falls off its linear model); byte verification sampled 3/36 dense layers offline — MoE never compared.

Questions for further exploration

  1. Q1Does the 16% consistency gain from matching grow, shrink, or reverse at trained, outlier-heavy checkpoints — and how does it interact with an FP8 KV cache on the sampler side?
  2. Q2What share of the 16% is weight grid vs activation quantization vs kernel/accumulation? The proposed dequantized-MXFP8-weight and rounded-input sampler arms would split it cleanly.
  3. Q3Is MXFP8's flat/rising policy entropy useful exploration — and is FP8-TW's −74% entropy collapse with the highest training reward early over-exploitation? Needs multi-seed, long-horizon runs.
  4. Q4Does m* shrink as predicted with wider models, CUDA-graph capture, and TE ≥ 2.18 preswizzled scales — and do the C1–C7 conditions and guards transfer unchanged to NVFP4 RL pipelines?

Provenance & credibility

  • Single author (Wengee Zhang, independent affiliation) — measurement contribution, honestly positioned against concurrent industrial efforts (Miles, LMSYS/Ant Group; SkyRL, Anyscale) that use the same shared-grid design principle.
  • Implementation partially upstreamed: verl PRs #7986 / #7987 / #8062 plus the 108 CPU fault-injection tests — shippable without GPUs.
  • Drafting and implementation AI-assistant disclosed; the author states he reviewed every line and takes responsibility.
  • Hardware fault-injection campaign (detection rates, false alarms, delay) is specified but not run.
