> **一句话总结：** 提出 PSR（预取导向路由）：让 MoE 卸载解码中的路由只依赖确定性的"逻辑缓存"，并每层每 token 至多把 1 个由下一层 router 预测的专家以路由加成的方式"预取进"缓存——在 OLMoE-1B-7B（RTX 4090，50%/25% 专家驻留）上比 LRU 精确路由快 2.2–2.3×（10.7/19.2 vs 24.7/42.5 ms/token）、比 Cache-Prior 快 25–30%，八个基准平均分差 +0.1/+0.5（95% 下界 −0.8/−0.3），同时消除了缓存感知路由 + 异步预取组合下"输出取决于 PCIe 传输时机"的非确定性问题。

> **TL;DR:** For batch-1 decoding of offloaded MoE LLMs, PSR conditions the routing bonus on a deterministic *logical* cache and inserts at most n=1 next-layer-router-predicted expert per layer/token, so prefetching steers routing toward experts already in flight instead of away from the router's preference. On OLMoE-1B-7B (RTX 4090, 50%/25% experts resident) it decodes at 10.7/19.2 ms per token — 2.3×/2.2× faster than exact routing with LRU (24.7/42.5 ms, vs the Cache-Prior baseline 14.3/27.5 ms: 25–30% lower latency) — while the mean difference over eight benchmarks (MMLU, ARC-C, HellaSwag, GSM8K, BBH, IFEval, HumanEval, MBPP) vs Cache-Prior is only +0.1/+0.5 points (95% lower bounds −0.8/−0.3); at matched latency it is ahead +1.7±1.0 / +2.2±1.0 points, significantly better on HellaSwag and MMLU (25%). The speed edge is specific to transfer-bound decoding: on compute-bound Qwen3.6-35B-A3B (FP8) it shrinks to 1.25× over exact LRU and Cache-Prior is 4–6% faster in free generation, though PSR keeps 0.56× the KL divergence and significant MMLU/HellaSwag gains.

## 核心贡献

- **识别并量化了"计时依赖路由"问题**：当缓存感知路由（如 Cache-Prior 的驻留加成）与异步预取组合、且路由读取的是**物理**驻留状态时，模型输出会随 PCIe 传输时机变化。作者实测：只改变在途预取拷贝数（1→4，模型与参数完全不变），OLMoE 困惑度在 8.755→8.627 间漂移，同一 GPU 重复运行最大差 0.054；此时离线 harness 评测的根本不是被部署的那个模型（SpecMD、SMoE、MoE-CORE 等系统均未讨论此问题）。
- **提出确定性"逻辑缓存"（logical cache）**：路由策略只依赖 token 历史与策略参数的确定函数；引擎按逻辑状态调度物理拷贝，拷贝与调度时机只影响延迟、绝不影响输出。评测 harness 与部署引擎因此实现**同一个**路由策略（困惑度一致：8.684 vs 8.683），重复运行逐位可复现（Table 1 逻辑缓存行方差 0.000）。
- **有界预取导向（prefetch steering）**：利用跨层预测（pre-gate：下一层 router 作用于本层输入，提前一层可用）产生候选，每层每 token 至多插入 n（1 或 2）个非驻留候选进入逻辑缓存使其获得路由加成——偏置于是把选择拉向 router 本来就偏好、且已在传输中的专家，而不是远离 router 偏好；小预算保证新增拷贝不超过链路可重叠的容量（无界插入 n=8 虽最接近精确路由但 17.0 ms 反而慢于无预取的 Cache-Prior）。
- **A 驱逐优先级**：pe = 快/慢两个指数移动平均（衰减 0.5/0.98，追踪 router 自身 top-K 的选择频率而非实际执行集，避免偏置自我强化）+ token 先验，替代 LRU；需求插入会保护本步访问/插入过的专家。
- **三模型系统评测 + 两个诚实的负面/条件性结果**：蒸馏训练 gate（含 LoRA）在同等拷贝预算下降低了自生成困惑度（KL 诊断改善 17–30%）但基准质量无提升；块级专家选择的投机解码（AcceptMoE 式 + 置信度加权 + top-1 补救）在 OLMoE 上配 1B 自回归 drafter 时比 PSR 慢（1.41–1.99×），但在 Qwen3.6 上配 DFlash 块 drafter 后反而比任何同显存的自回归配置快 2.1–2.9×。

## Key Contributions

- **Names and measures a real evaluation-validity bug**: when cache-aware routing reads the *physical* residency set that an async prefetcher fills, the evaluated model becomes a function of PCIe timing. Concrete evidence: varying only the number of prefetch copies in flight (1/2/4) moves OLMoE perplexity from 8.755 to 8.627 with up to 0.054 run-to-run variance on the same GPU; a logical cache fixes it at 8.509 with zero variance. The author argues SpecMD, SMoE and MoE-CORE all share this undisclosed nondeterminism.
- **PSR's core design**: routing conditions on a deterministic logical cache; physical copies are scheduled separately and affect latency only. The evaluation harness and the deployed engine implement the identical routing policy (unit-tested decision-for-decision; perplexity 8.684 vs 8.683).
- **Bounded prefetch steering**: a per-layer, per-token budget of n (1 or 2) insertions from the *pre-gate ranking* (next layer's router applied one layer early, available ~0.4 ms ahead vs 0.55 ms per copy). The routing bonus (Cache-Prior's Eq. 1) then applies to experts the router ranks highly AND that are already in flight — turning the bias and prefetching from competitors (prefetch-by-popularity actually *hurts* Cache-Prior: 13.8→16.3 ms) into complements.
- **Router-informed eviction ("A priority")**: fast/slow EMAs (decay 0.5/0.98) of the router's own top-K membership plus a token prior; tracks preference, not execution, so the bias cannot reinforce itself through eviction.
- **Speculative execution and speculative decoding placed in the same framework**: speculative execution (run predicted experts) is a special case of the algorithm; AcceptMoE-style block-level expert selection is evaluated head-to-head with PSR including drafter cost, with a clean break-even analysis (drafting would need to cost ≤24 ms/16 tokens on HumanEval to match PSR on OLMoE — OLMo-1B needs 56–61 ms).

## Methodology

**Setting.** Batch-1 greedy decoding with all non-expert weights on GPU, a per-layer cache of C < E expert slots, experts in pinned host memory; RTX 4090 (24 GB) on PCIe 4.0 ×16 (measured 22.9 GB/s; one OLMoE expert copy = 0.55 ms). Three models: OLMoE-1B-7B-Instruct (16 MoE layers × 64 experts, top-8; fits on GPU so pressure is emulated by capping C to 32/16), Moonlight-16B-A3B (DeepSeek-V3-style, 26 layers × 64 routed experts + 2 shared, 31 GB — real offload), Qwen3.6-35B-A3B FP8 (40 layers, Gated DeltaNet + attention, 256 routed experts, 33 GB routed — real offload).

**Algorithm (per layer step, two parts).** Part 1 runs at layer l−1 as soon as its MoE compute launches: visit the top-8 of the pre-gate ranking in rank order, protect visited/inserted experts from eviction this step, and insert at most n non-resident candidates into the logical cache R_l (evicting the lowest-A-priority unprotected victim), queueing a copy for each insertion. Part 2 runs at layer l: biased top-K selection z + λΔ̄·1[∈R_l] with Cache-Prior's bonus restricted to logical residents; demand-copy any selected non-resident expert; execute with unmodified softmax weights, waiting only for executed slots' copy events. The cache resets to a fixed warm set (top-C experts per layer on held-out text) at sequence start.

**Physical scheduling.** The engine mirrors Algorithm 1: demand copies issued immediately; prefetch copies queued at layer boundaries, ≤2 in flight, dropped if their slot is reassigned; one ordered copy stream; layer compute waits only on events of slots it executes. All decisions are made on logical state, so scheduler choices affect latency alone.

**Implementation.** PyTorch engine replaying two CUDA graphs per layer (attention/router/pre-gate, then vLLM's fused MoE kernel over a slot-indexed expert cache), routing policy compiled with numba (biased top-K in numpy, ~20 µs/layer), static KV cache. The harness is a HuggingFace OLMoE whose MoE blocks call the *same* logical-cache model with state carried across decode steps.

**Evaluation protocol.** Eight benchmarks via lm-evaluation-harness (MMLU 0-shot 14,042 q; ARC-Challenge; HellaSwag; GSM8K 5-shot strict; BBH 3-shot CoT; IFEval; HumanEval and MBPP pass@1), compared as per-question *paired* differences with exact McNemar tests and Holm's correction (IFEval clustered by prompt with sign-flip permutation). Latency: 12 teacher-forced windows ×1024 tokens, 3 interleaved rounds, paired t-tests on log latency with the repetition as the unit (Kalibera & Jones). Divergence diagnostic: excess NLL ("selfgen") on text sampled from the exact model, estimating KL from exact routing. Operating points: Cache-Prior λ=0.2 (largest λ without significant generative loss) and nearest PSR points — chosen after seeing the full suite, which the paper flags as not pre-registered.

## Results & Highlights

- **OLMoE latency (headline)**: at 50% residency (C=32), PSR (λ=0.3, n=1) decodes at 10.7 ms/token (p99 19 ms) vs 24.7 ms for exact routing with LRU — 2.31× faster (95% CI 2.19–2.44) — and 1.92× faster than the best exact-routing cache+prefetch configuration (20.5 ms); vs the Cache-Prior operating point (λ=0.2, 14.3 ms) it is 25% faster. At 25% residency (C=16): 19.2 vs 42.5 ms (2.2×) and 30% lower than Cache-Prior (27.5 ms). All-experts-resident floor: 6.8 ms/token.
- **Quality vs Cache-Prior operating point**: mean paired difference over the eight benchmarks is +0.1 points at 50% (PSR λ0.3, 10.7 ms) and +0.5 at 25% (PSR λ0.25, 19.2 ms), 95% lower bounds −0.8 and −0.3. At *matched latency* PSR leads +1.7±1.0 (50%, vs CP λ0.3) and +2.2±1.0 (25%), significant after Holm on HellaSwag (both residencies) and MMLU (25%), worse on no task.
- **Where the speed comes from**: PSR (λ0.3) makes 13.8 copies/token but only 2.2 are demand copies (full 0.55 ms stall); 10.4 prefetch copies are used, 9.9 issued a layer early; effective cost per copy is 0.28 ms vs 0.70 ms for Cache-Prior λ0.2 (10.5 copies, *all* demand). Speculative execution needs 29.1 copies/token (13.3 demand) and runs 1.9–2.0× slower than PSR (20.0/38.1 ms at 50%/25%).
- **Determinism evidence (Table 1)**: with routing on the physical cache, perplexity moves 8.755→8.674→8.627 as in-flight prefetches go 1→2→4 (model unchanged), run-to-run spread up to 0.054; with the logical cache it is 8.509 with 0.000 spread at every setting.
- **Moonlight-16B-A3B (real offload)**: at 37.5% residency PSR λ0.2 runs 22.6 ms/token, 1.9× faster than exact LRU (43.6 ms); at Cache-Prior's latency (CP λ0.4, 21.5 ms) PSR is +1.6±0.9 points ahead on average, significant after correction on MMLU, HellaSwag and IFEval-instruction (+5.3). KL ranking (0.021 < 0.028 ≈ 0.029 < 0.072) matches mean benchmark-loss ranking (−0.48 < −1.37 ≈ −1.03 < −2.03). Every Pareto-optimal point except exact routing is a PSR configuration at all three cache sizes.
- **Qwen3.6-35B-A3B FP8 (compute-bound)**: every cache-aware config runs within 3 ms of the fastest (22.0–24.9 ms); PSR is only 1.25× faster than exact LRU at 25% residency (24.1 vs 30.0 ms) and Cache-Prior is equally fast (23.6 ms) — but PSR's KL is 0.029 vs Cache-Prior's 0.051 (0.56×), and in the direct comparison it is significantly better on MMLU (+0.85) and HellaSwag (+0.57) after correction; in free generation Cache-Prior is 4–6% faster (24.8 vs 25.8 ms on GSM8K).
- **Free generation is workload-dependent**: on 77 benchmark prompts at 50% residency PSR is 12% faster than Cache-Prior on GSM8K and 18% on IFEval but 4% *slower* on HumanEval (short repetitive code reuse: Cache-Prior needs only 1.4 copies/token there); at 25% residency PSR stays 19–28% faster on all three tasks.
- **Negative results**: distillation-trained gates (persistent active set + learned margins + LoRA) cut selfgen excess 17–30% at matched host loads but move benchmarks within noise (8-task mean +0.3±0.8 for trained PSR); speculative decoding with block-level selection + OLMo-1B drafter is 1.41× (HumanEval) / 1.99× (GSM8K) *slower* than PSR per token, while with a DFlash block drafter on Qwen3.6 it decodes at 11.2/8.4 ms/token — 2.1–2.9× faster than the fastest autoregressive configuration within its GPU memory (24.0 ms), on 64 prompts.

## Authors & Credibility

Single-author preprint by Siming Huang, HKUST (Guangzhou), dated one day after the arXiv stamp; no public code release is mentioned in the paper. The empirical craftsmanship is unusually high for a systems paper: per-question paired designs with exact McNemar tests and Holm's correction, cluster-robust SEs for IFEval, latency compared with repetition-paired t-tests on log latency following Kalibera & Jones (2013), explicit distinction between pre-correction (exploratory) and post-correction findings, an engine-vs-harness consistency check with its power stated (±3.2–4.8 points), and two negative results (trained gates; speculative decoding on OLMoE) reported in full. Citations are comprehensive and the related-work table (Table 11) cleanly decomposes methods by prediction/execution/cache-reads. The one-GPU/three-model scope and the non-registered operating points are disclosed rather than hidden.

## Critical Assessment

- **Novelty**: The two ingredients (cache-aware routing bonus; cross-layer expert prefetching) both exist; the contribution is the *composition* — routing on a deterministic logical cache plus a budgeted rule for which predicted experts get the bonus — plus the (measured, not just argued) timing-nondeterminism observation, which is genuinely novel and important for evaluation methodology. Incremental but real.
- **Rigor**: Statistics are exemplary, but the operating points (Cache-Prior λ=0.2, the PSR comparison points) were "fixed after seeing these results" on the same benchmark suite (§6.1) — a mild garden-of-forking-paths risk the paper itself flags; only Moonlight's and Qwen's comparison configs were fixed in advance.
- **Baseline framing**: the headline 2.2–2.3× is against exact routing with LRU, the weakest cache policy; against the authors' own best exact-routing cache+prefetch configuration it is 1.9×, and against Cache-Prior 25–30%. The abstract leads with the biggest number.
- **Emulated memory pressure**: OLMoE-1B-7B *fits* in the 4090's 24 GB, so its 50%/25% "residency" is a self-imposed cache cap emulating a smaller GPU; only Moonlight and Qwen genuinely require offloading. The 2.2–2.3× headline comes from the emulated setting.
- **Workload dependence / adverse cases**: the greedy-generation HumanEval reversal (4% slower than Cache-Prior at 50% residency) and the +5.5 HumanEval benchmark delta (treated as noise) show the advantage depends on expert locality of the generated text; at 25% residency every cache-aware config loses ~1.7–2.6 points on BBH (PSR −2.6, p=0.002, not surviving correction) — multi-step reasoning is not free at low residency.
- **Generalization limits**: on compute-bound Qwen3.6-35B-A3B (FP8, small 3.2 MB experts) PSR's speed advantage over Cache-Prior disappears entirely (and reverses 4–6% in free generation); the paper is honest that the latency benefit is specific to transfer-bound decoding, but a reader skimming the abstract could miss how conditional the win is. Models with few large experts (e.g., Mixtral) are untested.
- **Evidence limits**: the DFlash/speculative-decoding superiority claim on Qwen rests on 64 prompts ("detect only large losses"); Moonlight/Qwen benchmarks were decoded in batches with one logical cache per row, slightly different from the batch-1 engine; no comparison against tuned external systems (llama.cpp, MoE-Infinity, Fiddler-style CPU execution) — all baselines are reimplementations in the authors' engine, which isolates policies but inflates none/alls equally.
- **Red flags**: none serious. Single-author, not yet peer-reviewed, no code link — treat exact numbers as needing reproduction.

## Strengths

- Solves an actual correctness/evaluation problem (timing-dependent outputs) rather than only chasing latency, and demonstrates the effect quantitatively (perplexity shifts up to 0.13 from scheduler parameters alone; 0.054 run-to-run).
- The design insight is clean and well-motivated: steer the bonus onto in-flight, router-preferred experts so bias and prefetch reinforce rather than fight (popularity-based prefetch under Cache-Prior *raises* latency 13.8→16.3 ms).
- Comprehensive, honestly-reported evaluation: three architectures including a real-offload DeepSeek-V3-style model and an FP8 hybrid-attention model, iso-latency *and* iso-quality comparisons, copy-level decomposition explaining the mechanism, and negative results kept in the paper.
- Statistical care well above the norm for ML systems papers (paired McNemar + Holm, repetition-level latency tests, declared exploratory findings).

## Limitations

- Latency benefit requires transfer-bound decoding; it vanishes (Qwen3.6 FP8) or reverses (HumanEval greedy at 50%) when computation dominates or generated text reuses experts heavily.
- Teacher-forced headline latencies exclude prompt processing; free-generation gains are smaller (12–18% at 50%).
- One GPU (RTX 4090) and one PCIe link; pre-gate window had to be retuned per model (8→4 candidates on Moonlight) as it depends on link saturation.
- OLMoE results are emulated pressure; no Mixtral-style few-large-experts model; no external system baselines; no code release mentioned.
- Cache-aware routing still perturbs quality: 16–25% of BBH items flip vs exact routing under every configuration, and at 25% residency BBH drops ~2 points for all cache-aware methods.

## Relevance

（对关注大模型高效推理与系统优化的读者）本文直接针对消费级 GPU 上 MoE 模型 batch-1 卸载解码这一实用场景，提出的"逻辑缓存使路由可复现、有界预取导向使偏置与预取协同"思路对所有缓存感知推理系统（包括 SpecMD、SMoE、MoE-CORE 一类工作）都有方法论意义，跨层专家预测 + 路由加成的组合也是 MoE 推理优化的活跃方向。

## Questions for Further Exploration

- Would PSR's benefit persist on models with few large experts (Mixtral 8×7B) or on bandwidth-constrained links (laptop SoC memories, flash-to-DRAM as in the original Cache-Prior setting) where copy latency dwarfs layer compute?
- Can the logical-cache determinism idea be extended to batched serving, where batch composition already perturbs exact-routing outputs — does a per-sequence logical cache make sense when copies are shared across sequences?
- The DFlash block-drafter result suggests block-level speculative selection dominates PSR when drafting is cheap; is there a hybrid that uses PSR's cross-layer prefetch to also hide *verification* copies (the paper measures them fully exposed at 0.57–0.60 ms each)?
- Trained gates improved the KL diagnostic but not benchmarks — would a reward aligned with generative benchmarks (rather than KL to the exact model) change that conclusion?
- The n=1 budget was fixed per layer; could an adaptive budget conditioned on measured link utilization (as in ExpertFlow's horizon adaptation) dominate the fixed-n frontier?
