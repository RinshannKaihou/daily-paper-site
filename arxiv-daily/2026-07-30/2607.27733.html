Why This Matters

Any agent that self-evolves skills from noisy tool feedback — SMT solvers, compilers — needs to ask first whether a failure is even fixable before rewriting the skill.

⚠ Critical Edge

The expert-authored "Human Skill" baseline scores below No-Skill on Dafny (7.7% vs 14.0%) — an anomaly the paper never investigates or explains.

Methodology — three-stage evolution loop
1

Failure attribution & filtering discard noise

Every failed task is classified as task-unsatisfiable, prover-limited (both discarded — not skill problems), skill-noncompliance, or skill-knowledge-gap (both kept as evolution signal). Raw verifier output is never treated as reusable knowledge on its own.

2

Pattern-level lesson abstraction cluster

Kept failures get a 3-part signature — where the proof breaks, which verification responsibility is missing, why the skill text failed. Same-signature failures cluster; instance-specific details (constants, variable names) are stripped so the lesson generalizes.

3

Executable validation & admission gate

A localized skill edit is revise-tested on attribution + transfer cases, then must strictly improve a frozen validation set while preserving program semantics before it's admitted. Rejects/accepts all logged to an evolution memory.

Strengths vs. Limitations

Strengths

  • Precise domain-specific formulation of why generic skill-evolution fails on verification.
  • 3 verifiers × 2 backbones × 7 baselines — broad, not a single-config win.
  • Ablation quantifies each stage's marginal contribution, not just an aggregate score.
  • Cross-model transfer tests true skill portability, not just single-model tuning.
  • Qualitative case study makes the attribution advantage concrete and interpretable.

Limitations

  • No variance/significance reporting over only 3 trials — some deltas (+3.3pp) may be noise.
  • Human Skill baseline underperforming No-Skill is unexplained.
  • Evolution memory's own contribution is never ablated.
  • The LLM-driven attribution classifier is never checked against human-labeled ground truth.
  • Custom author-built datasets; no stated plan to release code/prompts/data.
Questions for Further Exploration
  1. How accurate is the LLM-driven attribution step against human-labeled ground truth?
  2. Why does the expert Human Skill baseline underperform No-Skill on Dafny?
  3. What's the per-round wall-clock / API-cost budget to converge?
  4. Does ablating evolution memory itself change PASS rate or convergence speed?
  5. Do gains hold for full functional-correctness proofs, not just annotation/translation tasks?
  6. How does it compare against concurrent 2026 baselines (SkillCAT, CoEvoSkills) not in the main table?
