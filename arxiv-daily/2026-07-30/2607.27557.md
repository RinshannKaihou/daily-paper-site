> **一句话总结：** 论文把"扩散模型的加噪-去噪"思想搬到智能体的技能学习上——用人类专业剧本压缩成的故事大纲当"加噪"输入，让智能体重建剧本再与人类原作对比生成文本损失，通过"前向-损失-反向"的类神经网络训练闭环，把更新对象从模型权重换成一个 MoE 式的外部技能库，在短剧剧本生成任务上，+Memory 版本在 9 个指标中的 7 个上优于空记忆库的 Base 版本（如"不可拍摄的动作描写"从每集 1.1 条降到 0.3 条，与人类的 0.3 条基本持平）。

> **TL;DR:** The authors propose a diffusion-inspired, fully unsupervised framework where an LLM agent's external textual skill library (not its weights) is trained by reconstructing human screenplays from corrupted story outlines and contrasting the reconstruction against the human original as a "semantic loss." On six held-out short-drama novels (385 episodes/group), the memory-equipped agent beats the empty-memory Base agent on 7/9 metrics, cutting unfilmable-action-line density from 1.1/episode (Base) to 0.3/episode (matching the human 0.3) and raising hard-cut-ending rate from 40% (Base) to 59% (vs. human 61%), while a token-capped memory-regularization ablation is the only variant to improve both rule-based and LLM-judge metric families simultaneously.

## 核心贡献

- 提出一种**无监督的智能体自我进化框架**，灵感来自扩散模型的"腐蚀-重建"范式：将人类专业剧本压缩为粗粒度故事大纲（"加噪"），再让智能体从大纲重建完整剧本，用重建结果与人类原作的对比构造自监督信号，避免依赖昂贵的人工标注或不可靠的 LLM-as-a-Judge 打分。
- 将"前向-损失-反向"的神经网络训练范式**迁移到纯文本领域**：前向生成剧本、损失智能体撰写"密集文本损失报告"（而非 token 级匹配）、反向智能体据此对外部记忆库做细粒度的信用分配（credit assignment）编辑。
- 设计了一个 **Mixture-of-Experts 风格的紧凑记忆架构**：规则卡片被路由到三个专家文件夹（通用原则、具体技巧、类型惯例），并用"linter"强制执行 token/行数上限作为正则化，防止记忆无限膨胀、案例过拟合。
- 提出**数据并行 + 序列化微步**的训练调度方案：多部小说的前向生成与损失计算并行执行，而记忆更新被拆成一系列短小、聚焦的反向微步（类比梯度累积），解决了单一长程编排智能体的效率与稳定性问题。
- 在短剧剧本生成任务上做了较为全面的实证验证，包括跨模型迁移（Sonnet 4.6 训练的记忆库直接用于 Opus 4.8）和外部第三方生产流水线的插拔测试。

## Key Contributions

- An **unsupervised self-evolving agent framework** inspired by the corruption-and-reconstruction paradigm of diffusion models: professional screenplays are compressed into condensed story outlines (the "noising" step), and the agent must reconstruct the original from the outline, with the reconstruction-vs-original contrast serving as the free self-supervised signal (no human expert annotation or LLM-as-judge scoring needed).
- A **textual analogue of forward/loss/backward neural-network training**: a script agent performs the forward pass, a loss agent writes a dense qualitative "loss report" comparing the reconstruction to the human original anchor (avoiding meaningless token-level matching), and a backward agent performs credit assignment, editing individual memory items rather than model weights.
- A **Mixture-of-Experts-style compact memory architecture**: rule cards are routed into three expert folders (general writing principles, concrete craft techniques, genre-specific conventions), with a linter enforcing hard token/line budgets as a regularizer — explicitly shown to be necessary via ablations (uncapped pools balloon to 148 cards / 500K+ tokens and over-suppress certain style dimensions).
- A **data-parallel-with-serialized-micro-step scaling scheme**: forward generation and loss computation run concurrently across novels while memory updates are serialized into short, focused backward micro-steps (analogous to gradient accumulation), which the authors report eliminated repeated multi-hour orchestration failures from an earlier monolithic-agent design.
- Empirical validation across four axes: out-of-distribution held-out novels, in-distribution training dynamics over epochs, cross-model transfer (Sonnet 4.6 → Opus 4.8), and deployment inside an external, previously-unseen production screenwriting pipeline.

## Methodology

The framework treats an agent's external textual memory library as its "trainable parameters," optimized through a corruption-and-reconstruction loop (Figure 1):

1. **Corruption (3.1):** A corruption agent compresses each professionally written short-drama episode into a condensed story-outline chapter — dialogue, physical actions, and pacing decisions are stripped away, leaving only a coarse plot skeleton. This mirrors the forward (noising) process of diffusion models. Each (outline, original episode) pair is a free self-supervised training example.
2. **Forward script generation (3.2):** Given an outline chapter, the script agent writes the episode back into a full Hollywood-format screenplay. Before writing, it scans one-line descriptions of all memory rule cards and reads the full text of those it judges relevant; this "read trace" is logged for later credit assignment.
3. **Semantic loss (3.3):** Because token-level matching is meaningless for creative writing (two excellent episodes can share no surface text), a loss agent reads the reconstruction side-by-side with the human original and writes a dense textual loss report itemizing where the human version is structurally or stylistically superior — anchored on a concrete human artifact rather than the judge's own taste.
4. **Backward credit assignment (3.4):** A backward agent acts as the optimizer: it reads the loss report plus the read trace and edits the memory — strengthening cards that guided the agent well, narrowing the scope of misleading cards, creating new cards for recurring uncovered mistakes, and merging redundant items. To avoid diluting the signal (analogous to vanishing gradients from digesting too much at once), reports across novels are hierarchically reduced into cross-novel commonality summaries before any single update, and one global update is decomposed into a sequence of small, traceable backward micro-steps.
5. **Compact memory architecture (3.5):** Memory is organized MoE-style into three expert folders (general principles, craft techniques, genre conventions) with a linter enforcing hard length caps (ultimately 1,200 tokens per card body, 200 for its description, 50-line max) — shown empirically necessary: with no limit the pool grew to 148 cards / 500K+ tokens with one 2,500-line "card" that was really an incident log of a single novel.
6. **Data-parallel scaling (3.6):** Forward generation and loss computation run in parallel across the 20 training novels; backward updates are serialized into a micro-step queue, each an independent short-lived single-agent process (median ~10 minutes) reading one reduced summary plus its novel group's traces. Staleness introduced by serialization is handled simply by instructing the backward agent to judge suggested edits against the current pool state before committing, rather than via any explicit correction weighting.

Base agent throughout training is Claude Sonnet 4.6; training runs 3 epochs over 20 production-quality short-drama novels (1,127 episodes/epoch total), completing 174 consecutive micro-steps without a single failed update and converging to a stable pool of ~18 rule cards / ~20,000 tokens.

## Results & Highlights

- **Out-of-distribution evaluation** (six held-out novels never seen in training, 385 episodes per group — Base, +Memory, Human): the +Memory agent outperforms Base on **7 of 9 metrics** (Table 2). Unfilmable action lines drop from **1.1/episode (Base) to 0.3/episode (+Memory)**, matching the human baseline of **0.3**, cutting the 1-Wasserstein distance-to-human from 0.83 to 0.03. Longest dialogue volley shrinks from **4.5 turns (Base) to 4.3 turns (+Memory)** against a human **3.6**, narrowing the distance from 0.89 to 0.67.
- **LLM-judge craft metrics** (Gemini 3.1 Pro as judge, different model family from the generator; re-judging a 16-episode subset with Claude Opus 4.8 reproduces **84%** of verdicts): hard-cut-ending rate rises from **40% (Base) to 59% (+Memory)**, closely approaching the human **61%** (gap shrinks from −21.5pp to −1.7pp). Cold-open rate surges from **64% (Base) to 84% (+Memory)**, exceeding the human reference of **72%**. Prop-activation rate goes from **59% (Base) to 78% (+Memory)** against a human **70%**.
- **One clear regression**: redundant voice-over incidence *worsens* from **1% (Base) to 5% (+Memory)** against a human baseline of **0%** — traced by the authors to a single memory card that teaches when voice-over is effective but not that the human default is to write none at all.
- **Cross-model transfer** (memory pool trained exclusively on Sonnet 4.6, attached unchanged to Claude Opus 4.8, same six held-out novels): both models converge to nearly identical levels on the three "craft discipline" judge metrics once equipped with the pool — hard-cut endings reach **59% on both Sonnet and Opus** (vs. human 61%), cold opens reach **84% (Sonnet) and 87% (Opus)** (vs. human 72%), prop activation reaches **78% and 79%** respectively (vs. human 70%). Opus's baseline voice-over overuse (1.01 cues/episode) is only partly corrected to 0.88, well above the human 0.22 — showing the pool addresses each model's own weaknesses rather than imposing one fixed target.
- **Regularization ablation** (Figure 6, three historical pool generations tested on the same 25-episode exam per held-out novel): an **uncapped pool (148 cards, >500K tokens)** over-suppresses style, driving stimulus words down to **1.6/episode** (vs. human 7.32) and inflating inference cost ~3x; a **line-limited pool (75 cards, 25-line cap)** actually *collapses below the Base agent* on rule-based metrics (5.2-turn dialogue volleys vs. Base's 4.9, 1.02 unfilmable action lines vs. Base's 0.95); only the **token-capped production pool (18 cards, 1,200-token cap)** improves both rule-based and judge-metric families simultaneously, reaching the best hard-cut-ending rate of the four configurations (61%, vs. human 65% in this subset).
- **External production pipeline case study** (Appendix A.2, five episodes of an unseen third-party title, "Second Bloom"): with the memory active, **4 of 5 episodes** end on a hard cut at the climax, versus the control group extending scenes with extra shots after the climax. In the most voice-over-heavy episode, the intervention drops voice-over lines from **15 to 4** (out of 24 vs. 18 total lines). A documented failure case (Episode 5) shows the ending rule card was simply never retrieved (only 3 of a possible larger set of cards were read, after a first draft was already written), and voice-over climbed to 17 of 21 lines — isolating retrieval, not the memory content itself, as the operational bottleneck.

## Authors & Credibility

Authors are Mo Li, Zixin Yin, Ting Cao, and Yunxin Liu, affiliated with Tsinghua University, Shanghai AI Laboratory, The Hong Kong University of Science and Technology, and Xiaobing.AI. The paper is marked "Preprint. Work in progress." It builds directly on the authors' own concurrent/related work cited in the bibliography (e.g., "Learning to commit: Generating organic pull requests via online repository memory," "One sentence, one drama: Personalized short-form drama generation via multi-agent systems"), suggesting an active research program around agentic memory and short-form drama generation rather than a one-off paper. All experiments use proprietary Claude models (Sonnet 4.6, Opus 4.8) as both agent and generator, and Gemini 3.1 Pro as judge — no independent third-party replication is presented.

## Critical Assessment

**Novelty:** The diffusion-inspired corruption/reconstruction framing for *textual skill* learning (as opposed to weight updates) is a genuinely distinctive angle, and the explicit analogy to forward/loss/backward with hierarchical reduction (≈ gradient accumulation) and micro-steps (≈ small-batch updates) is carried through consistently rather than being a superficial metaphor.

**Rigor:** The evaluation is unusually careful for an agentic-memory paper — it uses held-out novels, reports Wasserstein distances rather than only means, cross-validates its LLM judge against a different model family (84% agreement on a 16-episode subset), and — notably — reports a **negative result on its own method**: the line-limited historical pool variant performs *worse than the no-memory Base agent* on rule-based metrics (Figure 6), and the paper does not hide this. The redundant-voice-over regression (1%→5%, vs. human 0%) is also disclosed rather than omitted.

**Reproducibility concerns:** The training corpus is "internal high-quality human scripts" — proprietary and not released (only the training framework and "representative memory examples" are promised as open-source). The task domain (Chinese short-drama screenwriting) and base models (closed-source Claude/Gemini) limit independent verification. The improvement over 148-card/500K-token uncapped pools versus the 18-card production pool is described as a "natural-history comparison" across mechanism generations rather than a strictly controlled ablation, which the authors themselves flag.

**Missing baseline/comparison:** The only comparison point is the same base model with an *empty* memory pool ("Base"). Despite citing several closely related externalized-skill-library methods in the related work (Voyager, Expel, ReasoningBank, Skillopt, Skillgrad), the paper never quantitatively compares its memory pool against any of them — so it is unclear whether the gains come specifically from the diffusion-inspired self-supervised signal versus simply from having *any* well-curated MoE-style skill library with regularization.

**Significance:** The cross-model transfer result (training on Sonnet 4.6, deploying unchanged on Opus 4.8, converging to near-identical craft-discipline rates) is the most compelling evidence that the learned memory encodes portable domain knowledge rather than model-specific prompt-engineering artifacts.

**Red flags:** The paper's own stated limitation — "If the agent reads a memory rule and still ignores it, updating the text yields no behavioral change" and "A rule that is never read cannot fire" — is a fundamental dependency on the base model's instruction-following and retrieval reliability that the framework does not solve, only diagnoses (Episode 5 case study).

## Strengths

- Fully self-supervised skill acquisition with no external scoring model, human expert annotation, or reward model — a real solution to the "expensive human annotation vs. unreliable LLM-as-judge" dilemma in agentic continual learning.
- Careful multi-metric evaluation with rule-based direct counts (immune to LLM judge bias) alongside binary LLM-judge verdicts cross-validated against a different judge model.
- Demonstrated cross-model transfer of the learned memory (Sonnet-trained pool applied unchanged to Opus), providing evidence the memory captures generalizable domain rules rather than model-specific quirks.
- Honest reporting of negative/regression results (line-limited pool underperforming Base; redundant-VO regression; the Episode 5 retrieval failure), which strengthens the paper's credibility.
- Practical systems-engineering contribution: the data-parallel/serialized-micro-step scheduling section documents a real failure mode (orchestration overhead dominating actual work) and a concrete fix, useful independent of the core method.

## Limitations

- No quantitative comparison against other externalized-skill-library methods (Voyager, Expel, ReasoningBank, Skillopt, Skillgrad), only against a no-memory Base agent.
- Single narrow domain tested (short-drama screenwriting in Hollywood format), with a modest training corpus (20 novels) and held-out set (6 novels); generalization to other creative or non-creative domains is untested.
- Depends entirely on the base model's multi-instruction-following and retrieval reliability — a rule the agent fails to retrieve or chooses to ignore produces no learning signal, and the paper's own case study (Episode 5) shows this failure occurring in a real deployment.
- Training data (professional screenplays) and part of the pipeline are proprietary/internal, limiting reproducibility.
- The regularization-strength comparison across historical pool generations is explicitly a "natural-history" comparison rather than a controlled ablation isolating one variable at a time.
- One metric (redundant voice-over) regresses relative to Base, and stimulus words show zero statistically significant change across training epochs (Section 4.3), indicating the method's effect is uneven across style dimensions.

## Relevance

该工作提供了一种把"技能作为可训练参数"落地的具体机制（腐蚀-重建 + MoE 记忆 + 反向信用分配），对关注 agentic continual learning、无监督自我进化、以及如何用人类高质量产出物构造自监督信号的研究方向具有较高参考价值；其跨模型迁移实验和对记忆正则化（token/行数上限）必要性的消融也为设计外部技能库提供了可复用的工程经验。

## Questions for Further Exploration

- How would this framework perform if compared head-to-head against existing skill-library methods (Voyager, ReasoningBank, Skillopt) on the same corpus and evaluation protocol, rather than only against a no-memory Base agent?
- Would the corruption-and-reconstruction paradigm transfer to non-narrative domains where a "coarse skeleton" of the target artifact is harder to define (e.g., code, technical writing, scientific papers)?
- Can the retrieval bottleneck identified in Section 4.6/Appendix A.2 (rules that are never read cannot fire) be addressed architecturally — e.g., via mandatory card-relevance checks or forced re-reading before final drafts — rather than left as future work?
- How sensitive is the final memory pool's content and size to the choice of loss-agent and backward-agent models, given that all agents in the reported training loop are instantiated with the same model (Claude Sonnet 4.6)?
- Does the redundant-voice-over regression persist if the memory pool is allowed additional training epochs or a dedicated corrective micro-step targeting that specific card, and would fixing it via the described closed-loop mechanism (as done for the voice-over overshoot-and-return effect in Figure 4) trade off against other metrics?
