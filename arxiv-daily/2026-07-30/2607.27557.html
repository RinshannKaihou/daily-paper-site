Coverage report — agent memory training

Train an agent's skills like weights: corrupt a screenplay into an outline, reconstruct it, then diff the rewrite against the human original to edit an external memory.

Training Skills Like Parameters via Self-Supervised Semantic Diffusion ↗

Key metric
7/9
held-out metrics won by +Memory vs. empty-memory Base (385 episodes, 6 unseen novels)
Sharpest single win — unfilmable action lines: 1.1→0.3/episode, exactly matching the human baseline of 0.3.
Why this matters

Gives agentic continual learning a concrete recipe: train external skill memory, not weights, using a human artifact as free self-supervision instead of costly LLM judges.

Critical edge

The only comparison is against a no-memory Base agent — Voyager, Expel, ReasoningBank, Skillopt, and Skillgrad are cited but never benchmarked head-to-head.

Method — corrupt, reconstruct, diff, edit

1 · corruptionStrip dialogue/action/pacing from a pro episode down to a bare plot skeleton — the "noising" step.
→
2 · forwardScript agent rewrites the outline into a full screenplay, logging which memory cards it consulted.
→
3 · semantic lossA loss agent diffs the rewrite vs. the human original, writing a dense qualitative report — not token-matching.
→
4 · backwardA backward agent edits cards — strengthen, narrow, create, merge — using the loss report + read-trace as credit assignment.
→
5 · MoE memoryCards route into 3 expert folders (principles / techniques / genre); a linter caps size to stop bloat.

Scaling trick: forward generation + loss run concurrently across novels, while backward updates serialize into short, focused micro-steps — a textual analogue of gradient accumulation that the authors say fixed repeated multi-hour orchestration failures in an earlier monolithic-agent design.

Regularization ablation — why the token cap matters
  • Uncapped (148 cards / 500K+ tokens) — over-suppresses style: stimulus words fall to 1.6/ep (human 7.32); ~3× inference cost.
  • Line-capped (75 cards, 25-line cap) — collapses below Base on rule-based metrics (5.2-turn volleys vs. Base 4.9).
  • Token-capped production (18 cards, 1,200-token cap) — only variant to lift both rule-based and judge metrics together; best hard-cut rate of the four, 61%.
Cross-model transfer

Sonnet-4.6-trained pool moved unchanged onto Opus 4.8: hard-cut 59% / 59%, cold-open 84% / 87%, prop-activation 78% / 79% (human 61/72/70) — near-identical craft rates across models, evidence the pool encodes portable rules, not prompt quirks.

External pipeline case study
"Second Bloom," 5 unseen episodes: memory pushes 4/5 to a hard-cut climax. The one failure (Ep. 5) traced to the ending rule card simply never being retrieved.

Strengths

  • Fully self-supervised — no reward model, human scoring, or LLM-judge dependency for the training signal itself.
  • Rule-based counts (judge-immune) reported alongside LLM-judge verdicts, cross-checked against a different judge model.
  • Cross-model transfer shows the memory holds portable domain knowledge, not prompt quirks tied to one model.
  • Honestly reports its own regressions and failures: the line-capped collapse, the voice-over regression, the Episode 5 retrieval miss.
  • Documents and fixes a real orchestration failure mode via data-parallel + micro-step scheduling.

Limitations

  • No head-to-head comparison against Voyager, Expel, ReasoningBank, Skillopt, or Skillgrad — only vs. an empty Base.
  • One domain only (Chinese short-drama screenwriting), small corpus: 20 training / 6 held-out novels.
  • Requires the base model to retrieve and follow a rule — an unretrieved or ignored card yields no learning signal.
  • Training screenplays and part of the pipeline are proprietary; only the framework and "representative" cards ship open.
  • The regularization sweep is a "natural-history" comparison across pool generations, not a controlled single-variable ablation.

Open questions

  • How does this compare head-to-head with Voyager / ReasoningBank / Skillopt on the same corpus and protocol?
  • Does corrupt-and-reconstruct transfer to domains without an obvious "coarse skeleton" — code, technical writing, papers?
  • Can the retrieval bottleneck be fixed architecturally (mandatory relevance checks, forced re-reading) rather than left diagnosed-only?
  • How sensitive is the final pool to using a different model for the loss/backward agents (all currently Sonnet 4.6)?
  • Would extra epochs or a dedicated corrective micro-step fix the voice-over regression without trading off other metrics?
