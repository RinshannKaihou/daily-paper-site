> **一句话总结：** LabEvolver 用一个训练-free 的双循环框架（状态驱动的内层安全执行 + 外层经验蒸馏）让湿实验室机器人从执行轨迹中积累技能/策略/安全三类经验，在真实 pH 调节任务上把完成时间和安全门拦截次数分别降低 48.2% 和 60.0%，在 ALFWorld 上把 20 步内累计成功率从 ReAct 的 76.2% 提升到 91.4%（比自建 MemP 基线高 3.8 个百分点）。

> **TL;DR:** LabEvolver equips foundation-model-driven wet-lab agents with a training-free dual-loop architecture: an inner trial loop that grounds actions in a hierarchical lab state and validates them through a tri-layer runtime safety gate, and an outer evolution loop (the "Strategist") that distills completed trajectories into reusable skill/strategy/safety experience stored in a bounded memory bank. On real pH-regulation robotic tasks it cuts completion time by 48.2% and safety-gate intercepts by 60.0% relative to baselines, and on ALFWorld it raises cumulative Success@20 across 500 continual tasks from 76.2% (ReAct) / 87.6% (MemP) to 91.4%, while keeping the memory bank at 372 (or 281 with forgetting) entries versus MemP's 1,177 at episode 500.

## 核心贡献

- **提出"状态锚定 + 双循环"的训练-free 框架**：内层由 Observer（视觉感知/状态跟踪）、Operator（LabSkill 三层动作接口）、Supervisor（长时程上下文压缩）组成，外层由 Strategist 负责经验抽取（skill/strategy/safety 三元组）、经验维护（Add/Update/Upvote/Downvote + Ebbinghaus 式软遗忘）和经验检索，全程不更新模型权重。
- **提出 Tri-layer Runtime Safety Gate**：在动作下发前从接口合法性（Γ_intf）、流程一致性（Γ_proc）、物理可行性（Γ_phys）三层联合校验，任一维度不通过即阻断执行并生成结构化异常日志用于重规划，从而把"事后检测错误"转为"事前阻断违规动作"。
- **把经验与状态而非任务关键词绑定**：Strategist 将每条可复用经验关联到触发它的物理状态条件，使检索对当前物理情境敏感，而非像 MemP 等方法那样把轨迹程序化为无状态文本日志。
- **在真实湿实验室机器人平台（RealMan RM75-B 机械臂 + RGB-D 相机 + 电子天平 + 水质计）上完成端到端验证**：涵盖定量倾倒、单目标 pH 调节、耦合 pH-EC 调节三类任务家族，并额外在 ALFWorld 上验证方法可扩展到 134 个 valid_unseen 任务、500 个连续训练任务流，证明经验蒸馏机制具有跨场景通用性。
- **证明经验积累不会导致内存爆炸**：通过 Strategist 的合并/淘汰机制，500 个连续 ALFWorld episode 后记忆库仅增长到 372 条（引入遗忘机制后为 281 条），远低于 MemP 的 1,177 条，说明该方法在长时程持续学习下具有有界的内存增长特性。

## Key Contributions

- **A training-free, state-grounded dual-loop architecture.** The inner trial loop couples an Observer (VLM-based perception + state tracking), an Operator (a three-level LabSkill interface: atomic actions, digital-tool calls, semantic skill templates), and a Supervisor (periodic state compression for long-horizon replanning); the outer evolution loop's Strategist extracts, maintains, and retrieves state-paired skill/strategy/safety experience — no model weights are ever updated.
- **A tri-layer Runtime Safety Gate** Γ(s_t, a_t) = Γ_intf ∧ Γ_proc ∧ Γ_phys that validates every proposed action for interface well-formedness, procedural consistency with progress, and physical feasibility under the current state before dispatch, halting execution and logging a structured exception for replanning on any violation.
- **State-conditioned (not keyword-conditioned) experience storage and retrieval**, distinguishing LabEvolver from procedural-memory baselines like MemP that log trajectories as stateless text, and enabling retrieval to stay sensitive to the physical context at hand rather than only the task description.
- **Physical validation on a real wet-lab robotic platform** (RealMan RM75-B arm, Inspire Robots EG2-4B gripper, Intel RealSense D435 RGB-D camera, an electronic balance, and a water-quality meter) across quantitative pouring, single-objective pH regulation, and coupled pH–EC regulation, plus a scalability study on ALFWorld (500 shuffled train-split episodes, 134 valid_unseen tasks) to test generality beyond wet-lab settings.
- **A bounded, forgetting-aware memory-maintenance mechanism** (Add/Update/Upvote/Downvote plus an Ebbinghaus-style decay-and-delete rule) that keeps memory growth sub-linear in the number of trials, unlike a proceduralize-every-trajectory baseline (MemP) whose memory grows almost linearly with episode count.

## Methodology

LabEvolver formulates autonomous wet-lab experimentation as a constrained closed-loop problem: given a high-level goal g, find a physically viable trajectory τ that reaches the target condition under real-world constraints. The architecture has two nested loops (Figure 2):

**Inner trial loop (state-driven safe execution).** The shared laboratory state s_t = (A_t, E_t, O_t) tracks agent embodiment (robot pose, gripper status, held instruments), environment (object identities, poses, attributes), and multimodal observations (visual perception, sensor readings, actuator feedback). The Observer reconstructs the initial state via a four-stage pipeline (VLM object identification → VLM 2D pointing/localization → 3D localization → SAM point-guided segmentation, Figure 3) and updates state from environmental feedback after each action. The Operator receives context c_t = (g, s_t, I_LS) and generates a high-level intent u_t, then grounds it into a parameterized action a_t = (k_t, θ_t) using the three-level LabSkill interface (atomic robot primitives, digital-tool calls/runtime records, and semantic task-level templates). Before dispatch, every action must pass the tri-layer Runtime Safety Gate; if it fails, execution halts immediately and a structured exception guides Operator replanning; if it passes, the physical platform executes it and the state updates via s_{t+1} = U(s_t, a_t, y_{t+1}). The Supervisor periodically compresses accumulated transitions into checkpoints to control context saturation and goal drift during long-horizon tasks.

**Outer evolution loop (state-paired experience refinement).** After a trial terminates, the Strategist maps the trajectory τ and goal g to a structured experience tuple e = Ψ(τ, g) = (e_skill, e_strategy, e_safety): e_skill records effective LabSkill parameters and boundary conditions, e_strategy captures reusable procedural knowledge (e.g., "if initial pH is 7.74, add ~8g acid before re-measurement"), and e_safety stores blocked-action diagnoses and failure-avoidance rules. New experience is merged into a global memory bank M via Add/Update/Upvote/Downvote operations, with an Ebbinghaus-style soft-forgetting mechanism periodically decaying and deleting low-score entries to bound long-term growth. Before each trial, the Strategist retrieves the top-K relevant, state-matched experience fragments to seed the inner loop, refreshing retrieval at Supervisor checkpoints during long-horizon execution — without replaying entire past trajectories.

The default LLM backbone is DeepSeek-V4-Pro; cross-model comparisons additionally use Claude-Sonnet-4.6, Qwen3.5-35B-A3B, and GPT-5. Baselines compared: Act (direct one-shot action prediction), ReAct (reasoning + acting), Inner-only (the full inner loop with no historical experience), MemP (an online procedural-memory baseline, ALFWorld only), and CLAIRify (a chemistry-LLM controller baseline, pouring task only).

## Results & Highlights

- **ALFWorld cumulative Success@20 over 500 continual train-split episodes (DeepSeek-V4-Pro):** LabEvolver reaches 91.4%, versus MemP 87.6% (+3.8 pts), ReAct 76.2% (+15.2 pts), and Act (+18.8 pts lower than LabEvolver) (Figure 4a).
- **ALFWorld Success@20 on 134 valid_unseen tasks, generalized across backbones:** LabEvolver achieves the highest Success@20 for every tested backbone — Claude 84.3% (+9.7 pts over its ReAct baseline), GPT 81.3% (+5.8 pts), DeepSeek 85.8% (+8.5 pts, up from Act's 72.4%), and Qwen3.5-35B-A3B 73.9% (+12.5 pts, the largest gain, i.e., +8.2 pts specifically over ReAct) (Figure 4b).
- **Memory-bank growth control:** at episode 500, MemP's bank grows to 1,177 memories (near-linear in episode count) while LabEvolver holds at 372, and 281 with the Ebbinghaus forgetting mechanism enabled (Figure 4c).
- **Quantitative pouring (20 g water) controller comparison (Table 1):** LabEvolver achieves MAE 0.083 g / SD 0.117 / time 11.179 s, versus manually-tuned Adaptive pre-stop PD (MAE 0.133 g / SD 0.153 / time 20.360 s), Fixed PD (MAE 0.500 g / time 21.035 s), and CLAIRify (MAE 0.867 g / time 61.930 s) — a 37.5% MAE reduction and 45.1% time reduction versus the best non-evolving baseline (Adaptive pre-stop PD).
- **Pouring skill transfer across liquids/masses:** on 43 locked-parameter validation trials across water, sucrose solution, and olive oil at 10/20/30/40 g targets, 41/43 trials fall within ±0.2 g of target mass (95.3% success rate), trial-weighted MAE 0.081 g, with LabEvolver auto-assigning condition-specific k_p, k_d, pre_stop parameters instead of manual retuning per liquid-target pair (Figure 6).
- **pH-5 regulation across 3 backbones (Table 2):** Act fails to reach the target on all three backbones (DeepSeek/Qwen/Claude); relative to ReAct, LabEvolver reduces mean additions from 5.67 to 2.33 and mean completion time from 25.83 to 13.37 minutes, and relative to Inner-only (same state mechanism, no outer experience) reduces mean safety-gate intercepts from 6.00 to 0.67 — with the largest gains for the weaker Qwen3.5-35B-A3B backbone, where Inner-only alone produces 15 gate intercepts and 2,311 s completion time versus LabEvolver's 2 intercepts and 609 s.
- **Coupled pH–EC regulation (Figure 7):** going from no retrieved experience to full task-relevant experience reduces required additions from 21 to 11, eliminates safety-gate intercepts entirely (2 → 0), and shortens completion time by 55.0% (≈7,947 s → ≈3,574 s), and LabEvolver is the only setting reaching all four admissible pH–EC target regions.

## Critical Assessment

**Novelty:** The core techniques — LLM-agent experience distillation into reusable memory (cf. Reflexion, Expel, MemP, Voyager) and safety-gated closed-loop execution — are individually established in the embodied-agent literature; LabEvolver's contribution is combining them into a state-grounded, tri-layer-gated architecture specifically for physical wet-lab robotics, plus the three-way (skill/strategy/safety) experience typing and an Ebbinghaus-inspired forgetting rule for bounding memory growth. This is an incremental-but-meaningful systems contribution rather than a fundamentally new algorithm.

**Rigor:** The ALFWorld evaluation is reasonably thorough (500 continual episodes, 134 valid_unseen tasks, 4 backbones, ablation against MemP/ReAct/Act/Inner-only). However, the real-world wet-lab numbers rest on small sample sizes — the pouring controller comparison in Table 1 repeats each baseline only 3 times, and the pH-regulation results in Table 2 appear to be single runs per backbone/method cell (no reported variance), which makes point-estimate percentage claims like "48.2%" and "60.0%" fragile without confidence intervals. Notably, the paper's own Inner-only ablation on Qwen3.5-35B-A3B produces 15 safety-gate intercepts and 2,311 s completion time — far worse than even ReAct (4 intercepts, 706 s) — showing that the inner loop alone can hurt weaker backbones and that the outer-loop experience is doing much of the real work, which the paper appropriately surfaces rather than hides.

**Reproducibility:** The method is training-free and a GitHub project page is provided, which helps for the ALFWorld results. The physical wet-lab results, however, depend on a specific hardware stack (RealMan RM75-B arm, Inspire Robots EG2-4B gripper, Intel RealSense D435, a particular electronic balance and water-quality meter) that most labs will not have, and on proprietary/large backbone models (DeepSeek-V4-Pro, Claude-Sonnet-4.6, GPT-5) whose behavior can drift across API versions, limiting exact replication of the real-robot numbers.

**Significance:** If the safety-gate and experience-evolution mechanisms generalize to other lab protocols and hardware, this is a practically useful step for self-driving labs, since it targets a genuine gap (systems that improve across repeated trials without retraining, while still enforcing hard physical/safety constraints). The significance claim is bounded, though, by the narrow task suite (pouring, single- and coupled-objective pH/EC regulation) — all single-manipulator, tabletop, liquid-handling tasks — so generalization to more complex protocols (e.g., multi-step synthesis, solid handling, multi-arm coordination) remains unverified.

**Red flags / weak baselines:** The primary wet-lab comparisons (Act, ReAct, Inner-only) are all internally-defined ablations of the authors' own pipeline sharing the same state and LabSkill infrastructure, not independent third-party systems — CLAIRify is the only external baseline, and it is only used for the pouring task, not for pH or coupled pH–EC regulation, where a domain-specific comparison would be more informative. The paper's own limitations section acknowledges reliance on human-designed LabSkills and safety rules, which "may constrain adaptation to unseen operations and novel failure modes" — a genuine, specific limitation rather than boilerplate.

## Strengths

- Real physical-robot validation (not just simulation) across three distinct wet-lab task families, with concrete, itemized metrics (additions, gate intercepts, completion time, task accuracy).
- Explicit, auditable tri-layer safety gate that halts unsafe/invalid actions before physical dispatch, directly addressing a practical deployment concern for lab robotics.
- Demonstrated bounded memory growth (372 or 281 vs. MemP's 1,177 entries at episode 500) via principled merge/forgetting rules, addressing a known failure mode of naive experience-accumulation methods.
- Cross-backbone generalization results (4 LLMs on ALFWorld) showing consistent, and sometimes large, gains — particularly benefiting weaker/budget-sensitive models.
- Public code/project page for the ALFWorld and framework components, aiding independent verification.

## Limitations

- Real-world experiments use small trial counts (e.g., 3 repeats per pouring baseline, apparently single-run pH-regulation cells), so reported percentage improvements lack confidence intervals or statistical testing.
- All wet-lab baselines except CLAIRify (pouring only) are internal ablations of the same framework rather than independent competing systems, limiting external validity of the safety/efficiency claims.
- The framework depends on human-designed LabSkills and hand-specified safety rules (acknowledged by the authors), constraining adaptability to unseen operations, new instruments, or novel failure modes not covered by the predefined skill/gate library.
- Task scope is limited to single-arm, tabletop liquid-handling operations (pouring, pH/EC regulation); no evidence is given for more complex multi-step synthesis, solid handling, or multi-robot coordination.
- Real-world evaluation relies on large proprietary backbone LLMs (DeepSeek-V4-Pro, Claude-Sonnet-4.6, GPT-5) accessed via API, introducing cost, latency, and version-drift dependencies for reproducibility.

## Relevance

该工作把 LLM-agent 的经验蒸馏/记忆管理思路与实体机器人安全执行结合，为自动化科学发现（Fifth Paradigm/自驱动实验室）提供了一个训练-free 的可落地范式，对关注具身智能体记忆机制、安全约束规划、以及 LLM 驱动机器人自动化的研究方向有direct参考价值。

## Questions for Further Exploration

- How does LabEvolver's tri-layer safety gate handle genuinely novel failure modes not anticipated by the hand-designed procedural/physical constraint rules (Γ_proc, Γ_phys)?
- What is the sample efficiency of the outer evolution loop — how many trials are needed before experience retrieval yields diminishing returns, and does this scale to protocols with far larger state/action spaces (e.g., multi-step organic synthesis)?
- How sensitive are the reported real-world gains to backbone model version drift, given that DeepSeek-V4-Pro, Claude-Sonnet-4.6, and GPT-5 are all closed, frequently-updated APIs?
- Would a head-to-head comparison against other domain-specific self-driving-lab controllers (beyond CLAIRify, e.g., ChemOS, Organa) on the pH/EC tasks change the relative ranking?
- Can the Strategist's skill/strategy/safety experience be transferred across different robot embodiments/hardware, or is it tightly coupled to the specific LabSkill definitions and the RealMan RM75-B platform used here?
