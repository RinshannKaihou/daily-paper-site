> **一句话总结：** 论文提出 Albilich——一个基于持久化 SQLite 证明状态、角色分离验证（研究者/对抗研究者/文献员/博士导师/严格验证器/整合验证器）与 CAS/文献检索 MCP 工具调用的开源数学自动化研究框架，在 RealMath 的 10 道题上全部达到内部 solved_final 状态（9/10 经人工核对无误），在 Kourovka 第 17.91 题的消融中开启 CAS 使 token 消耗降低 32.0%（678.4 万 vs 998.2 万），在第 21.142 题的消融中关闭 PhD 导师角色导致 110 次子会话后仍未证出（token 用量约为开启导师情形的 1.85 倍），并声称已用该系统解决群论中的两个公开问题（21.142 反例、20.2 加强版证明），由人类专家核实。

> **TL;DR:** Albilich is an open-source agentic harness for autoresearch in mathematics that pairs a persistent SQLite proof-state (claims, routes, debts, artifacts) with role-separated agents (researcher, adversarial researcher, literature reviewer, PhD advisor, strict verifier, integration verifier) and MCP tool calls to CAS backends (SageMath, GAP, Macaulay2, Singular) and theorem search. On 10 RealMath Math_arXiv problems it reaches its internal `solved_final` state on all 10 (9/10 confirmed against reference solutions) using ~28.1M gross tokens; on Kourovka Notebook Problem 17.91, enabling CAS cuts gross token usage by 32.0% (6.78M vs 9.98M tokens) versus a matched CAS-off run at similar active-compute time, and on Problem 21.142, disabling the PhD-advisor role leaves the proof unsolved after 110 child runs (1.85x the raw tokens, 1.53x the compute time of the advisor-on run's single successful proof). The system also reports two Kourovka group-theory results checked by human experts: a counterexample to Problem 21.142 and a proof of a strengthening of Problem 20.2.

## 核心贡献

- **持久化 SQLite 证明状态**：将一次证明尝试表示为带版本的图（claim、route、inference 及其依赖边），外加债务账本（debt ledger）、文献库、工件库、已接受补丁与状态转移历史，支持长程、可审计、可回溯的研究过程。
- **角色分离的验证权威**：研究者、对抗研究者、文献研究员、PhD 导师均无权修改数学状态；只有严格验证器（局部验证）、整合验证器（路径-根一致性）、反例验证器（Refute）三种角色能改变声明的正式状态，从架构上避免"自己构造论证、自己判定正确"。
- **PhD 导师 + 图分解应对长程卡顿**：当研究反复回到同一障碍、同一推断被反复拒绝、多条路径卡在同一债务、或核心声明被反驳时触发导师角色，对目标做归约、重新优先排序、暂停低产分支，但导师本身没有验证/整合权限。
- **两类 MCP 工具调用**：CAS（SageMath/GAP/Macaulay2/Singular，异步执行、并发上限、超时与输出上限）与文献检索（TheoremSearch、Matlas），并将"有限计算/检索候选"与"被验证的数学证据"严格区分——CAS 结果与检索结果都需要严格验证器核实其与目标声明的接口才能生效。
- **在真实开放问题上给出可复核的成果**：在 Kourovka Notebook（群论未解问题集）第 21.142 题给出反例，在第 20.2 题给出显式见证 G = PSL2(7)，并将后续工作推进为 PSLn(q) 系列几乎完整的分类（仅剩 PSLn(2), n≥5 未决）。

## Key Contributions

- **Persistent, versioned SQLite proof-state** that records claims, routes, and inferences with typed dependency edges, plus a debt ledger for unresolved obligations, a library of literature records, an artifact store for CAS/source evidence, and an event history of accepted and rejected patches — enabling long, auditable runs where superseded work is retained rather than discarded.
- **Role-separated verification authority**: research roles (researcher, adversarial researcher, literature researcher, PhD advisor) may propose claims, routes, and counterexamples but hold no authority to change mathematical status. Only the strict verifier (local proof/citation/CAS-interface checks), the integration verifier (route-sufficiency and root-alignment checks), and a counterexample validator can mark claims as verified, integrated, or refuted — preventing an agent from certifying its own argument.
- **A PhD-advisor role plus graph-based decomposition for test-time scaling**, invoked after a configured number of unproductive steps, repeated rejection of the same inference, several routes converging on the same debt, or refutation of a central claim; the advisor may reduce the problem, reprioritize routes, or pause a branch, but cannot itself verify, close debts, or integrate routes.
- **Two dedicated MCP tool families** — CAS (SageMath, GAP, Macaulay2, Singular, each run under concurrency/timeout/output limits with an archived transcript of code, output, and backend version) and literature retrieval (TheoremSearch, Matlas) — with an explicit trust boundary: neither a CAS transcript nor a retrieved theorem can support a claim until the strict verifier checks its interface (hypotheses, notation translation, scope) against the target claim.
- **Concrete, human-checked results on open group-theory problems** from the Kourovka Notebook: a counterexample showing that for some m≥9 (depending on primes p, q), the alternating group A_m cannot embed into any finite group invariably generated by elements of orders p and q (Problem 21.142), and an explicit witness G = PSL2(7) resolving whether a nonabelian simple group of Lie type can be totally 3-closed (Problem 20.2), with follow-up work extending toward a near-complete PSL_n(q) family classification (only PSL_n(2), n≥5 open).

## Methodology

Albilich represents a proof attempt as a state S_t = (q⋆, G_t, D_t, L_t, A_t, P_t, H_t, M_t), where q⋆ is the immutable root problem statement, G_t is a typed graph of claims/routes/inferences with dependency edges, D_t is the debt ledger, L_t the literature library, A_t the artifact store (CAS outputs, source adaptations, verification reports), P_t/H_t the accepted-patch and state-transition history, and M_t resource measurements. Agent sessions never edit the database directly; each proposes a patch π = (role, base revision, affected objects, requested operations, supporting evidence), which is validated (role authorization, revision compatibility, schema, evidence presence) and applied atomically or rejected with a logged diagnostic — an invalid patch never touches the mathematical state. A deterministic rule-based scheduler selects the next role/target from unresolved "obligations" (unproved premises, unchecked inferences, open debts, claims awaiting verification, routes awaiting integration), prioritizing items that block an active route to the root, giving separate budget allocations to research versus verification so speculative search cannot starve checking. A route may only be integrated when its terminal inference and every premise in its dependency closure are verified and no blocking debt remains; integration is automatically withdrawn and the route returns to repair if any dependency later changes (reconciliation).

Two MCP tool families are exposed to the researcher and adversarial roles: (1) CAS access (SageMath, GAP, Macaulay2, Singular) via an asynchronous server — a session starts a computation, keeps reasoning, and polls for the result; the artifact records the question, finite scope, exact code, output, and backend version, but the strict verifier reads this transcript without independently re-executing the computation, so correctness ultimately depends on verifying the reduction from the finite computation to the claimed conclusion, not on rerunning the code; (2) literature retrieval via TheoremSearch and Matlas, where retrieved candidates are untrusted until the literature researcher records the exact source location, hypotheses, notation translation, and the specific implication needed, which the strict verifier then checks. All reported experiments use a single LLM backend, "gpt-5.6-sol" with "xhigh" reasoning effort. Four experiments are run: (a) the RealMath Math_arXiv subset with CAS enabled throughout; (b) a paired one-hour CAS-on/CAS-off ablation on Kourovka Problem 17.91, matched on problem statement, model, reasoning effort, and number of recorded child sessions (20 each); (c) two open-ended Kourovka case studies (Problems 21.142 and 20.2); and (d) a paired PhD-advisor-on/off ablation on Problem 21.142, matched on model, reasoning effort, an 80M-token budget, a 12M-token verification reserve, max reduction depth 4, and the `full_proof_first` completion policy, differing only in `ALBILICH_ADVISOR_ENABLED`.

## Results & Highlights

- **RealMath Math_arXiv (10 problems, CAS enabled throughout, Table 3)**: all 10 attempts reached Albilich's internal `solved_final` state; human comparison against the benchmark's reference solutions confirmed 9/10 as clear matches, while for Problem 08 the equivalence between Albilich's derived convolution formula and the reference expression remained unresolved. Total cost was ~28.10M gross tokens across the 10 runs. No no-CAS RealMath condition is reported in the body despite the abstract's claim of "9/10 with no CAS" (see Critical Assessment).
- **CAS ablation, Kourovka Problem 17.91 (Table 4)**: with CAS enabled, the run used 6.590M input + 0.194M output = 6.784M total tokens; with CAS disabled, 9.787M input + 0.195M output = 9.982M total tokens — a 32.0% reduction in gross tokens with CAS, concentrated almost entirely in input tokens (output tokens essentially unchanged), despite similar active backend compute (5244.145s with CAS vs 5410.717s without). Neither condition solved the root problem; both reached "certified partial."
- **PhD-advisor ablation, Kourovka Problem 21.142 (Table 5)**: the advisor-enabled run solved the root (1 integrated root-concluding route) across 80 child sessions, 6.81 hours of active compute, 29.7M raw / 6.00M charged tokens, with 10 of 11 claims verified and a 1% patch-rejection rate. The advisor-disabled run remained unsolved (0 root-concluding routes) after being stopped at 110 child sessions, 10.44 hours of compute (1.53x the advisor-on solve time), 54.9M raw / 9.67M charged tokens (1.85x raw, 1.61x charged tokens), despite producing more verified claims (18 of 20) and a higher patch-rejection rate (8% vs 1%).
- **Kourovka Problem 20.2, advisor comparison**: the advisor-on run certified the explicit witness G = PSL2(7) using 23 child sessions, 1h16m, and 6,714,757 tokens via a theory-based direct argument (coset-action reduction + GAP-verified finite configurations + synchronization argument); a separate advisor-off run certified the same witness using 18 child sessions, 1h47m (~31 minutes longer), and 6,306,998 tokens (comparable token count), but via an exhaustive computational certificate rather than the conceptual argument — evidence that, on this instance, the advisor's main effect was on proof character/organization rather than raw success/failure.
- **Kourovka Problem 21.142 case study**: Albilich reported and internally certified a negative answer — for some m≥9 (depending on primes p,q), the alternating group A_m cannot embed into any finite group invariably generated by elements of orders p and q — via a reduction to a group between S^t and Aut(S)≀Sym(t) and a terminal simple-factor obstruction, using 80 child sessions, 5h51m lifecycle time, 6.81h active compute, and 29,684,464 gross tokens, with 10 of 11 claims verified and one route integrated.
- **Broader informal trials (not counted as benchmark results)**: on separate graduate-level group theory/representation theory projects, Albilich completed 2 of 3 master's/early-PhD-level problems and repaired a gap in one associated paper, but did not solve the third (also unresolved by the human students); on harder open problems, brute-force search performed poorly on a codegree-set construction problem and an open character-vertex problem received only preliminary ideas.

## Authors & Credibility

The authors are Ting Gong and Michael Ruofan Zeng (University of Washington, Seattle) and Yong Yang (Texas State University), with the project described as part of the "UW Math AI Lab." Acknowledgements name several individuals (advisor Max Lieblich, testers Yuan Lu, Lu Qi, Shitan Xu, Yu Shen, and discussants Bin Dong, Jarod Alper, Vasily Ilin, Gergely Bérczi) but no large, established research lab or industry co-author is listed. The paper appears to be an unreviewed arXiv preprint (AAAI-style two-column formatting, no venue/acceptance stated). All reported experiments use a single proprietary backend, "gpt-5.6-sol" with "xhigh" reasoning — a model name not otherwise documented or independently verifiable in this text, which limits external reproducibility of the exact cost numbers. The authors state they will release an open-source MCP server for the CAS and literature-search tool calls alongside the paper, and that the two Kourovka results were "verified by human experts," though no named reviewers or independent audit trail are provided beyond the acknowledgements.

## Critical Assessment

**Novelty**: The core architectural ideas — a typed, event-sourced SQLite proof state that retains rejected/superseded claims, an explicit debt ledger, a hard separation between local claim verification and root-level route integration, and dependency-triggered re-verification (reconciliation) — are a genuinely distinctive combination relative to the cited comparators (Danus, QED, ProofCouncil), as the paper's own Table 1 architectural comparison shows (Albilich is the only system checking all six listed capabilities). The PhD-advisor role as a dedicated, non-authoritative long-horizon planning agent is a reasonable operationalization of "test-time scaling via structured redirection" rather than raw compute.

**Rigor**: The CAS and advisor ablations are reasonably controlled (matched model, reasoning effort, and either time or token budget), but each condition is a single run, not a repeated trial across seeds — so a headline number like "32.0% token reduction" or "1.85x tokens without the advisor" rests on n=1 per condition, and the paper does not report variance. The advisor-off run on Problem 21.142 was explicitly stopped before its intended two-times compute allowance, which the authors themselves flag as limiting the comparison to "had not solved the problem by the stopping point" rather than a clean negative result. There is also an internal inconsistency: the abstract states Albilich "solved... 9/10 [RealMath problems] with no CAS," but the Experiments section only reports a CAS-enabled RealMath run (Table 3 has a single RealMath row); no no-CAS RealMath condition, success count, or token figure appears anywhere in the body or tables.

**Reproducibility**: The strict verifier explicitly does not re-execute CAS computations — it reads the archived transcript and checks only the mathematical interface between the CAS artifact and the claim, meaning a CAS-supported claim's correctness ultimately rests on trusting a transcript rather than on independently re-run code. Combined with reliance on an undocumented proprietary model ("gpt-5.6-sol," "xhigh" reasoning) and Albilich's own admission that `formally_verified` status (Lean-backed) is deferred to a future version, the two headline group-theory results (Problems 21.142 and 20.2) currently carry only `informally_verified` status plus an unspecified human-expert check, not machine-checked formal proofs.

**Significance**: Genuine research-level contact (two Kourovka Notebook problems addressed, with follow-up progress toward a PSL_n(q) family classification) is a stronger significance signal than most agentic-math papers that report only benchmark scores, and the authors are commendably candid about failures (the unresolved Problem 08 equivalence, the codegree-set and character-vertex problems on which the system made no progress). That said, the RealMath evaluation (n=10, hand-selected from one benchmark subset) and the single-run ablations mean the quantitative claims (token savings, advisor value) should be read as preliminary/directional rather than statistically established, a limitation the paper itself acknowledges in its final "Limitations" section.

## Strengths

- Solves and human-verifies concrete, previously-open group-theory problems (Kourovka 21.142 counterexample, Kourovka 20.2 explicit witness), going beyond static benchmark-solving into genuine mathematical research contact.
- Architecturally separates who can *propose* mathematical content from who can *certify* it (research roles have zero verification authority), directly targeting the "system produces plausible but false arguments" failure mode named in the introduction.
- Persistent, versioned, auditable proof state with an explicit debt ledger and dependency-triggered reconciliation, so a long run's failed routes and open obligations remain inspectable rather than silently discarded.
- Transparent cost accounting (tokens, active compute time, child-session counts) reported for every experiment, enabling direct before/after comparisons for both the CAS and PhD-advisor ablations.
- Unusually candid reporting of negative and partial results (unresolved RealMath Problem 08, poor performance on a codegree-set construction problem, advisor-off run producing more verified claims yet failing to reach the root) rather than only showcasing successes.

## Limitations

- All ablations (CAS on/off, advisor on/off) are single, unreplicated runs rather than multi-seed trials, so reported deltas (32.0% token reduction, 1.85x tokens without the advisor) lack variance estimates.
- The advisor-off run on Problem 21.142 was stopped before reaching its intended full compute allowance, so the ablation cannot fully rule out that more compute would eventually have solved the problem without the advisor.
- The RealMath evaluation covers only 10 hand-picked Math_arXiv problems with CAS enabled in every run; the authors state this "does not estimate performance on the full benchmark," and no no-CAS RealMath results are reported despite the abstract's claim of a 9/10 no-CAS outcome.
- Mathematical status is currently capped at `informally_verified`; formal (Lean-backed) verification is explicitly deferred to a future version, and the strict verifier does not re-execute CAS computations, so both headline group-theory results rely on transcript-trust plus an unspecified human check rather than machine-checked proofs.
- No quantitative head-to-head comparison against the cited competing systems (Danus, QED, ProofCouncil, Aletheia, AI Co-Mathematician) on a shared problem set — Table 1 is a qualitative capability checklist, not a benchmark comparison.
- All experiments depend on a single, seemingly unreleased proprietary model ("gpt-5.6-sol" with "xhigh" reasoning) that is not independently documented, constraining external reproducibility.

## Relevance

该论文展示了将持久化状态管理、角色分离验证与 CAS/文献检索工具调用结合用于长程数学研究 agent 的具体架构，对设计可审计、可人类介入的多智能体科研系统（不限于数学领域）具有直接参考价值；其"债务账本 + 局部验证/整合验证分离"的思路也可迁移到其他需要长程推理与可信验证的 agentic 系统设计中。

## Questions for Further Exploration

- How would Albilich's RealMath success rate and token cost change on the full benchmark rather than 10 hand-picked problems, and what would a matched no-CAS RealMath run actually show given the abstract's unreported "9/10 no-CAS" claim?
- Do the 32.0% CAS token-reduction and 1.85x advisor-off token-inflation results replicate across multiple seeds/runs, or are they sensitive to the particular problem instance and reasoning trace sampled?
- Since the strict verifier trusts CAS transcripts without re-execution, how would Albilich's soundness guarantees hold up against an adversarial or buggy CAS backend, and would independently re-running flagged computations change any accepted claims?
- What would formal (Lean-checked) verification of the Kourovka 21.142 counterexample and 20.2 witness reveal, given that `formally_verified` status is currently unimplemented?
- How does Albilich's architecture and cost profile compare quantitatively (not just qualitatively, as in Table 1) to Danus, QED, ProofCouncil, and Aletheia on a shared set of open or benchmark problems?
- Does the debt-ledger/reconciliation mechanism remain tractable (in SQLite size, retrieval latency, and context-window management) for runs far longer than the ~5-10 hour case studies reported here?
