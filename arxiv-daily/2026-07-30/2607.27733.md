> **一句话总结：** VeriSkill 提出了一套面向程序验证的专用技能自演化框架——通过"失败归因→模式级教训抽象→可执行验证准入"三阶段流水线，把不可靠的验证器失败信号转化为可信的技能更新，在 Dafny/Frama-C/VeriFast 三个验证工具、Claude Code+Opus 4.8 与 Codex+GPT 5.6 Sol 两套智能体上相较最强基线 SkillOpt-Lite 仍提升 3.3–17.0 个百分点的 PASS 率。

> **TL;DR:** VeriSkill is a domain-specific skill self-evolution framework for LLM-agent program verification that (1) attributes each verification failure to task-unsatisfiability, prover-limitation, skill-noncompliance, or skill-knowledge-gap and keeps only the latter two as evolution signals, (2) clusters failures by a three-part diagnostic signature to abstract reusable, instance-agnostic lessons, and (3) validates candidate skills on held-out transfer cases and a frozen validation set before admission. On the Dafny benchmark with Claude Code/Opus 4.8, VeriSkill reaches 57.3% PASS versus 14.0% for No-Skill and 42.3% for the strongest baseline SkillOpt-Lite (+15.0 pp); with Codex/GPT 5.6 Sol it hits 66.0% vs 17.0% (No Skill) and 62.7% (SkillOpt-Lite). Gains hold across Frama-C and VeriFast too (up to +51.3 pp over No Skill), and an ablation shows removing the executable-validation loop costs the most (−21.3 pp on Dafny).

## 核心贡献

- 首次针对"程序验证技能"提出专用自演化框架，指出通用技能自演化方法（如 EvoSkill、SkillOpt-Lite、Trace2Skill）在验证任务上失效的根本原因：验证失败不等价于技能缺陷（可能源于任务本身不可满足或 SMT 求解器能力局限），且验证器输出的失败条件不是可直接复用的过程性知识。
- 提出三阶段流水线：(1) 责任归因——将失败分为任务不可满足、求解器局限（两者丢弃）、技能未被遵循、技能知识缺口（两者保留）四类；(2) 模式级教训抽象——用"哪里出错、缺失何种验证责任、技能为何失败"三元诊断签名对失败聚类，剥离具体路径细节生成可泛化教训；(3) 可执行验证与准入——教训先在归因集和迁移集上做本地探测（revise-test loop），再在冻结验证集上要求严格超过当前技能且保持语义不变才准入。
- 通过消融实验定位三个组件的贡献度：可执行验证影响最大（去除后 Dafny PASS 从 57.3% 降至 36.0%，−21.3pp），其次是责任归因（−13.0pp），教训抽象最小但仍显著（−8.3pp）。
- 用跨模型迁移实验证明演化出的技能是可复用的验证知识而非模型特定提示：在 Codex 上演化的技能迁移到 Terminus 框架下的 5 个不同 LLM 后端，PASS 率均有 +15.3 至 +43.7 个百分点的提升。

## Key Contributions

- First self-evolution framework specialized for program-verification skills; explicitly diagnoses why domain-agnostic skill evolution (EvoSkill, SkillOpt-Lite, Trace2Skill, etc.) underperforms here: a failed verification is not always a skill defect, and raw verifier output (failed verification conditions) is not directly reusable procedural knowledge.
- A three-stage pipeline: (1) responsibility attribution classifying failures into task unsatisfiability / prover limitation (discarded) vs. skill noncompliance / skill knowledge gap (retained as evolution signals); (2) pattern-level lesson abstraction using a diagnostic signature (proof-obligation localization, verification-responsibility abstraction, skill failure mechanism) to cluster failures and abstract instance-agnostic lessons from human-verified references; (3) executable validation and admission — candidates are revise-tested on attribution/transfer sets, then admitted only if they strictly improve a frozen validation-set PASS rate while preserving program semantics.
- Component ablation isolates the contribution of each stage: executable validation is the single largest contributor (−21.3 pp when removed on Dafny), followed by responsibility attribution (−13.0 pp) and lesson abstraction (−8.3 pp).
- Cross-model transferability experiment: a skill evolved with Codex/GPT 5.6 Sol, deployed unchanged in the Terminus terminal-agent wrapper, improves five other backbones (GLM-5.2, Kimi-K2.7, Qwen3.7-Max, DeepSeek-V4-Pro, Qwen3-Coder) by +15.3 to +43.7 pp PASS on the same Dafny benchmark, arguing the extracted lessons are portable verification knowledge rather than model-specific prompting.

## Methodology

VeriSkill formalizes the objective as finding a skill S that maximizes the expected verifier-pass rate J(S) = E_x~D E_a~π(·|x,S)[V(x,a)] subject to a semantic-preservation constraint M(x,a)=1 (the candidate must not alter the underlying executable program). The framework runs an iterative loop (Algorithm 1) with three stages, driven by a persistent "evolution memory" (EM) that records every accepted/rejected/skipped revision with its attribution, lesson, and validation outcome so later rounds avoid repeating known-ineffective updates.

1. **Failure Attribution and Filtering (Stage 1):** For each failed task, VeriSkill jointly examines the generated artifact, verifier log, current skill, a human-verified reference solution, and evolution memory to classify the failure as: task unsatisfiability (the program/annotations don't support the goal), prover limitation (SMT solver capability gap), skill noncompliance (skill has relevant guidance but the agent didn't follow it), or skill knowledge gap (skill lacks the needed procedural knowledge). Only the latter two — "evolvable" failures — proceed.

2. **Lesson Abstraction via Pattern-Level Defect Clustering (Stage 2):** Each evolvable failure gets a three-part diagnostic signature (i) where the proof breaks (e.g., invariant initialization/preservation, memory safety, termination), (ii) which reusable verification responsibility is missing (e.g., establishing entry facts, supplying an intermediate lemma), and (iii) how the skill text caused the failure (missing/unclear/overly abstract/hard-to-locate guidance). Failures sharing a signature form a cluster; the cluster's common responsibility is abstracted into a candidate lesson. Human-verified reference artifacts are consulted for evidence but their example-specific details (concrete invariant forms, constants, variable names) are deliberately stripped so the lesson generalizes with explicit applicability and inapplicability conditions.

3. **Executable Validation and Admission (Stage 3):** A candidate skill S' = Revise(S_t, lesson, EM) is a controlled, localized edit (not a blind append) that preserves unrelated skill sections and the task contract. It is rerun on the attribution cases (A_c, used to build the lesson) and disjoint same-pattern transfer cases (T_c) to compute local repair/transfer effects (τ̂_attr, τ̂_trans in Eq. 5); pass-to-fail regressions or edits to executable code are auto-rejected, triggering a revise-test loop until local checks pass or a per-pattern budget is exhausted. Only locally valid candidates proceed to a frozen validation set V; a candidate is admitted (S_{t+1} = S') only if it strictly improves Ĵ_V(S) and preserves M(x,a)=1 for every validation task — otherwise the skill stays unchanged. All outcomes (accepted/rejected/skipped) are logged to evolution memory.

The method is evaluated as a prototype tool across three formal verification back-ends (Dafny, Frama-C, VeriFast), using custom C-to-spec translation datasets the authors constructed (sampled/scraped from DafnyBench and GitHub repositories, manually checked by two experts with formal-verification experience), each split into train/validation/benchmark subsets.

## Results & Highlights

- **Main comparison (Table 1), PASS rate (%) averaged over 3 runs**, Claude Code + Opus 4.8: VeriSkill scores 57.3 on Dafny vs. 14.0 for No Skill and 42.3 for the strongest baseline SkillOpt-Lite (Δ vs. No Skill = +43.3 pp; vs. best baseline = +15.0 pp); 74.5 on Frama-C vs. 56.9 (No Skill) and 65.4 (SkillOpt-Lite, +17.6/+9.1 pp); 84.0 on VeriFast vs. 38.0 (No Skill) and 78.3 (SkillOpt-Lite, +46.0/+5.7 pp).
- With Codex + GPT 5.6 Sol: VeriSkill reaches 66.0 on Dafny vs. 17.0 (No Skill) and 62.7 (SkillOpt-Lite, +49.0/+3.3 pp); 83.0 on Frama-C vs. 57.5 (No Skill) and 66.7 (SkillOpt-Lite, +25.5/+16.3 pp); 93.0 on VeriFast vs. 41.7 (No Skill) and 76.0 (SkillOpt-Lite, +51.3/+17.0 pp).
- Notably, weaker baselines (one-pass **LLM Skill** and expert-written **Human Skill**) are inconsistent and sometimes fall *below* No Skill — e.g., Human Skill on Dafny/Claude Code scores only 7.7% versus 14.0% for No Skill at all, and LLM Skill on Frama-C/Claude Code scores 47.1% versus 56.9% for No Skill.
- **Ablation (Table 2, Dafny, Opus 4.8):** Full VeriSkill = 57.3%. Removing Executable Validation drops PASS to 36.0% (−21.3 pp, the largest single drop); removing Responsibility Attribution drops it to 44.3% (−13.0 pp); removing Lesson Abstraction drops it to 49.0% (−8.3 pp).
- **Cross-model transfer (Figure 2):** a Codex-evolved skill deployed via the Terminus wrapper improves No-Skill PASS on the same Dafny benchmark for GLM-5.2 (12.0→55.7, +43.7 pp), Kimi-K2.7 (10.3→51.7, +41.4 pp), Qwen3.7-Max (7.7→44.3, +36.6 pp), DeepSeek-V4-Pro (6.0→41.0, +35.0 pp), and Qwen3-Coder (2.0→17.3, +15.3 pp).
- **Case study (Table 3):** on a Dafny null-pointer-guard translation task, EvoSkill's generic evolution loop concludes the lesson "preserve failure-guard branches" (matching source control flow literally), yielding 32.3% Dafny PASS, whereas VeriSkill's verification-specific attribution concludes "do not fabricate branches for untranslatable failure guards" (recognizing the guard as a host-level executability check with no verified data-state behavior), yielding 57.3% Dafny PASS — the same underlying case numbers reported in the main ablation table.
- The full evaluation (baselines × ablations × cross-model transfer, each averaged over 3 trials) cost approximately US$15K in API spend, per the paper's own disclosure.

## Authors & Credibility

Authors are affiliated with Peking University, Zhongguancun Laboratory, and Shanghai Jiao Tong University — reputable Chinese CS/SE research institutions with active LLM-agent research groups. As a brand-new (submitted 2026-07-30) arXiv preprint with no listed venue/acceptance, there is no external citation record or peer-review signal yet to corroborate the claims; the paper should be read as an unreviewed preprint. The related-work section cites a dense cluster of near-simultaneous 2026 arXiv preprints on "skill self-evolution" (EvoSkill, SkillOpt, SkillOpt-Lite, SkillCAT, CoEvoSkills, AutoSkill, Trace2Skill, SkillsBench, SkillGenBench — many all dated 2026), suggesting this is a fast-moving, crowded, and possibly saturated micro-topic; readers should weigh novelty claims against this backdrop of many structurally similar concurrent papers.

## Critical Assessment

**Novelty:** The core idea — that not every verifier failure should trigger a skill edit, and that verification-specific failure taxonomy (task-unsatisfiability vs. prover-limitation vs. skill-noncompliance vs. skill-knowledge-gap) is needed before lesson abstraction — is a reasonable and fairly specific insight rather than a generic "add more validation" claim. The three-stage design (attribute → abstract → validate-and-admit) is a sensible instantiation of this insight for the program-verification domain specifically.

**Rigor:** The ablation study (Table 2) and cross-model transfer experiment (Figure 2) are genuine strengths — they isolate each component's contribution and test a real generalization claim (skill portability across 5 unrelated backbones) rather than just reporting an aggregate number. However, rigor is undercut in a few concrete ways: (1) results are reported as 3-trial means with no variance/standard deviation or significance testing, so a Δ of e.g. +3.3 pp (Dafny, Codex, VeriSkill vs. SkillOpt-Lite) cannot be judged against noise; (2) the **Human Skill** baseline — written and validated by a formal-verification expert with seven years of experience — scoring *below* No Skill on Dafny (7.7% vs. 14.0%) is a genuine red flag: either the expert-authored skill was poorly matched to this specific translation task, or the No-Skill/Human-Skill comparison methodology has some confound (e.g., skill length triggering distraction), and the paper does not investigate or explain this anomaly, despite it undermining the premise that "well-written human skills work."

**Reproducibility:** The datasets for Dafny (200 sampled tasks with manually constructed plain-C inputs), Frama-C (85 tasks scraped and filtered from 4 GitHub repos), and VeriFast (200 tasks similarly constructed) are custom-built by the authors via a manual/expert-checked pipeline; the paper gives construction procedure but does not state whether the datasets, prompts, or code will be released. Given the reliance on proprietary model backbones (Opus 4.8, GPT 5.6 Sol, GLM-5.2, Kimi-K2.7, Qwen3.7-Max, DeepSeek-V4-Pro) and an estimated $15K experimental cost, independent replication is likely to be expensive and dependent on the authors publishing artifacts that are not yet confirmed.

**Significance:** If the numbers hold up, the gains are large and consistent (VeriSkill wins in all 6 verifier×backbone configurations in Table 1), and the cross-model transfer result is a meaningfully different and harder-to-fake claim than a single-model benchmark win. The domain (LLM-assisted formal verification) is niche but practically important given the expertise bottleneck the paper opens with.

**Red flags:** No ablation isolates evolution-memory's contribution specifically (memory is discussed extensively in the method but not ablated in Table 2, which only tests attribution/abstraction/validation). The paper does not report how many evolution rounds were needed to converge, nor wall-clock/iteration cost per skill, which matters for a framework whose main selling point is practical automation. The "task unsatisfiability" and "prover limitation" categories that are excluded from evolution are determined by an LLM-driven attribution step whose own accuracy is never independently validated against ground truth (e.g., no confusion-matrix or human-agreement check on the attribution classifier itself) — this is a load-bearing component of the whole method that is asserted but not verified.

## Strengths

- Clear, domain-specific problem formulation (Eq. 1–3) that precisely identifies why generic skill self-evolution methods fail on formal verification.
- Comprehensive evaluation across 3 distinct verification tools (Dafny, Frama-C, VeriFast) and 2 agent/backbone pairs, plus 7 baselines spanning no-skill, one-pass, human-authored, and multiple prior self-evolution methods.
- A genuinely informative ablation (Table 2) that quantifies each stage's marginal contribution, with executable validation shown as the dominant factor.
- The cross-model transfer experiment (Figure 2) is a stronger and rarer form of evidence than typical single-model benchmarking — it tests whether the "skill" is truly reusable external knowledge.
- The qualitative case study (Table 3) gives a concrete, interpretable illustration of the attribution-driven design's advantage over a generic evolution baseline, rather than relying purely on aggregate numbers.

## Limitations

- No variance/statistical-significance reporting despite averaging over only 3 trials — several reported deltas over the strongest baseline are modest (e.g., +3.3 pp on Dafny/Codex) and could be within noise.
- The Human Skill baseline underperforming No Skill on Dafny is unexplained and raises questions about baseline construction fairness.
- Evolution memory's independent contribution is not ablated, despite being described as integral to attribution and lesson generation.
- The responsibility-attribution classifier (task unsatisfiability / prover limitation / skill noncompliance / skill knowledge gap) is itself LLM-driven and its accuracy is never validated against human-labeled ground truth.
- Custom, author-constructed datasets (rather than fully independent, pre-existing, widely-used benchmarks) for Dafny/Frama-C/VeriFast tasks raise some risk of dataset construction favoring the proposed method, even with the described expert cross-validation.
- No stated plan for releasing code, prompts, or datasets, which limits independent verification of the $15K, multi-model experimental pipeline.

## Relevance

该工作面向"LLM Agent + 形式化验证"这一细分方向，提出的失败责任归因思路（区分任务不可满足/求解器局限 vs. 技能缺陷）对任何依赖不透明工具反馈做技能/提示自演化的系统都有参考价值，尤其是 SMT 求解器、编译器报错等"噪声大、难以直接转化为可执行知识"的反馈场景。

## Questions for Further Exploration

- How accurate is the LLM-driven responsibility-attribution step itself (task unsatisfiability vs. prover limitation vs. skill noncompliance vs. skill knowledge gap) when checked against human-labeled ground truth, and how sensitive is final PASS rate to attribution errors?
- Why does the expert-authored Human Skill baseline underperform No Skill on Dafny, and would a differently-authored or longer human skill close that gap?
- What is the per-round wall-clock and API-cost budget for VeriSkill to converge, and how does that compare to the cost of the 7 baselines, beyond the aggregate $15K figure for the whole study?
- Does removing or ablating evolution memory (as opposed to only the three pipeline stages) materially change PASS rate or convergence speed?
- Would the framework's gains persist on verification tasks requiring substantially more complex auxiliary lemmas (e.g., full functional-correctness proofs) rather than the annotation/translation-style tasks studied here?
- How does VeriSkill compare against the other very recent 2026 skill-self-evolution baselines (SkillCAT, CoEvoSkills) not included in the main comparison table, given how many similarly-named contemporaneous methods exist in this space?
