> **一句话总结：** MANTA 让多智能体系统在推理阶段而非部署前决定"谁跟谁说话"——通过 Topology Planner 规划初始拓扑、Trace Auditor 只诊断协作过程异常（不评判答案对错）、Controller 触发一次有界的拓扑突变（如展开过载分支、插入验证者、重排执行顺序），并用跨任务的长期 playbook 沉淀经验；在 BrowseComp、StableToolBench、PlanCraft、WorkBench、MATH 五个基准上平均得分 74.0，比最强基线 ADAS（68.2）高 5.8 分，PlanCraft 上以 76.7 对 73.3 夺魁，但在 WorkBench 上其实落后 ADAS 23.4 分、在 StableToolBench 上落后 AgentSquare 6.7 分——优势来自"稳定不崩"而非"每项都赢"。

> **TL;DR:** MANTA revises a multi-agent system's communication topology *during* task execution rather than fixing it beforehand, using an LLM Trace Auditor that flags process anomalies (not answer correctness) and a Controller that applies at most one bounded structural mutation (add/expand an agent, rewire an edge, change a group pattern, or adjust visibility). Across five benchmarks (BrowseComp, StableToolBench, PlanCraft, WorkBench, MATH) with Gemma 4 31B, MANTA reaches an average success rate of 74.0, beating the strongest baseline ADAS (68.2 avg) by 5.8 points and topping PlanCraft (76.7 vs. 73.3 for the best static workflow) — but it actually trails ADAS by 23.4 points on WorkBench (43.3 vs. 66.7) and AgentSquare by 6.7 points on StableToolBench (82.2 vs. 88.9), so the headline gain is a consistency win, not benchmark-by-benchmark dominance.

## 核心贡献

- **将"拓扑"定义为可在推理时自我改进的对象**：此前工作（MASS、AFlow、ADAS、AgentSquare）把通信拓扑当作部署前的离线搜索/优化目标；MANTA 提出"topology-level self-improvement"，让拓扑可以随任务进行中的协作痕迹被诊断和局部修复，不需要更新模型权重。
- **一个具体框架 MANTA**：由 Topology Planner（任务条件化初始规划）、Orchestrator（校验拓扑、生成/派发智能体）、Turn Executor（执行一轮协作）、Trace Auditor（LLM 审计员，只标记"过程异常"而不判断答案对错）、Controller（终止或触发一次有界拓扑突变）、Finalizer（综合投票产出最终答案）组成，并配有 Skill Reflector 周期性提炼跨任务运行的长期 playbook。
- **有界的拓扑突变算子集**：add_agent、expand_agent_to_group（把一个 worker 展开成一个子群的枢纽）、set_group_pattern（star/chain/debate/voting 之间切换）、add_edge/remove_edge、set_context_policy，每次修复最多 3 个算子、每个 run 最多触发 1 次突变。
- **两层 playbook 记忆**：run 内的短期 playbook 记录每轮的拓扑、审计发现与决策；跨 run 的长期 playbook 每 12 次 run 由 Skill Reflector 用"过程信号"（不接触真实答案）重写，可跨基准迁移（PlanCraft↔WorkBench 迁移带来 +3.3 分的平均提升）。
- **消融和突变预算实验**表明：初始拓扑规划贡献最大（去掉后从 71.7 掉到 57.5），其次是执行期修复（掉到 60.8），长期 playbook 贡献较小但一致（冻结/移除分别掉到 67.5/66.7）；且大部分收益来自"第一次修复机会"，第二、三次修复带来的边际增益递减。

## Key Contributions

- **Reframes topology as an inference-time self-improvement target.** Prior automated-design methods (MASS, AFlow, ADAS, AgentSquare) search for or optimize a fixed topology offline before execution; MANTA argues topology should instead be revisable *while* the system is solving a task, based on intermediate collaboration traces — without any weight updates.
- **A concrete architecture**: Topology Planner (query-conditioned initial plan) → Orchestrator (validates and instantiates the topology) → Turn Executor (runs one collaboration turn) → Trace Auditor (LLM component that flags process-observable anomalies, explicitly never judging answer correctness) → Controller (stops or authorizes exactly one bounded repair) → Finalizer (votes/synthesizes the final answer), plus a Skill Reflector that periodically rewrites a long-term playbook from batches of past runs.
- **A bounded mutation language** (Table 6: add_agent, expand_agent_to_group, set_group_pattern, add_edge/remove_edge, set_context_policy), capped at ≤3 operations per repair and exactly one mutation per run, applied by deterministic code that validates structural constraints (acyclicity, role legality, agent budget ≤10).
- **Two-horizon playbook memory**: a within-run short-term log and a cross-run long-term markdown playbook that the Skill Reflector rewrites from process-signal-only summaries (never ground-truth correctness), shown to transfer both in-domain (+3.3 pts) and cross-domain between PlanCraft and WorkBench (+3.3 pts mean), unlike baselines whose "learned" structures often transfer neutrally or catastrophically negatively.
- **Ablation and mutation-budget analyses** isolating where the gains come from: initial topology planning is the single largest contributor (removing it drops average success from 71.7% to 57.5%), topology repair is the second largest (60.8% without it), and the long-term playbook adds a smaller but consistent boost (67.5%/66.7% when frozen/removed); a budget sweep (0–3 mutations) shows the first repair captures most of the benefit.

## Methodology

MANTA's per-task loop has an inner "target multi-agent system" (the task-solving agents) wrapped by an "orchestration layer" (the self-improvement machinery), plus cross-run memory (Figure 2):

1. **Topology representation.** A versioned, validated spec assigns each agent a *structural role* (coordinator, worker, verifier, debater, voter) and a *stage role* (worker vs. critic). Agents belong to nestable *pattern groups* (singleton, star, chain, debate, voting), and each agent has a context policy controlling which relay packets, evidence, and how much of it, it can see. Agents communicate via structured "relay packets" (answer, evidence, confidence, unresolved issues) rather than raw transcripts, deduplicating identical tool calls and preserving an append-only evidence ledger.
2. **Query-conditioned initial planning.** The Topology Planner sees the task and the long-term playbook (never the benchmark identity or a hand-designed topology), analyzes task type/attributes/failure risks, and emits a compact JSON plan (interaction pattern, agent count, optional verifier/nested groups) that deterministic code expands and validates.
3. **Trace auditing and bounded repair.** After each turn, an LLM Trace Auditor scans structured artifacts, tool records, relay packets, confidence, and evidence visibility for a fixed taxonomy of nine deterministic "process-anomaly" flags (Table 7: tool_error_cascade, branch_collapse, unsupported_impossibility_claim, unverified_impossibility_consensus, evidence_lost_before_synthesis, premature_consensus, message_compaction_loss, insufficient_search_coverage, duplicate_state_mutation, missing_validator — 10 listed but described as 9 modes), plus open-set findings that must quote verbatim trace evidence (invented quotes are rejected). A run is "flagged" when a medium/high-severity repairable flag appears; the Controller then either finalizes or authorizes one bounded mutation, applied to a copy of the topology and validated (role/reference/membership/nesting/budget constraints); invalid proposals fall back to a conservative compiler or are skipped.
4. **Two-horizon memory.** Short-term playbook: per-turn log of topology, audit flags, repair, and decision, used within the current run. Long-term playbook: a markdown "Topology Planning Skill" document with protected "standing principles" and "how-to-choose" sections plus a Reflector-rewritten "lessons from experience" section, updated every 12 runs, using process signals only (whether the auditor flagged anomalies and whether the run reached "decision-grade consensus") — ground-truth correctness is never exposed to the Planner or Reflector.
5. **Agent harness.** Every task agent runs a shared, stateless harness with a bounded agentic loop (8 tool iterations/stage, 2 raw iterations kept verbatim, older iterations summarized, duplicate-call/stagnant-search/failure-circuit-breaker/read-gate/forced-final-answer guards) so mutations are cheap and lossless: a mutation just re-points a shared context controller at the new topology spec without migrating or truncating any packets, evidence, or candidate answers (Figure 8).

Evaluation uses Gemma 4 31B (medium reasoning effort) as the single backbone for all methods, 30 questions per benchmark, 3 independent runs each, across BrowseComp (info-seeking/evidence synthesis), StableToolBench (tool selection/execution), PlanCraft (long-horizon dependency-aware action planning), WorkBench (realistic workplace multi-step workflows), and MATH (structured reasoning, included as a generalization check since it needs little topology adaptation).

## Results & Highlights

- **Overall average**: MANTA scores 74.0±1.8 averaged over five benchmarks (Table 1), versus the strongest baseline **ADAS at 68.2±3.2** — a gain of **5.8 percentage points**, and it improves over the plain **Single Agent baseline (59.3±2.5) on every one of the five benchmarks**.
- **PlanCraft (its strongest relative result)**: MANTA gets **76.7±3.3**, ahead of the best static baseline (Orchestrator w/o Discussion and Fully Linked Debate, both 73.3±2.7) and far ahead of adaptive baselines like MASS (70.0±0.0) and AgentSquare (34.6±6.8).
- **But MANTA is not uniformly best per benchmark**: on **WorkBench** it scores only 43.3±2.7, well below **ADAS's 66.7±0.0** (a 23.4-point deficit), and on **StableToolBench** it scores 82.2±3.1, below **AgentSquare's 88.9±3.1** (a 6.7-point deficit). On MATH, MANTA (91.1±5.7) trails Self-Consistency, AFlow, and AgentSquare, all at 96.7. The paper's own abstract only advertises the PlanCraft win and the average lead, which somewhat obscures these individual losses.
- **Ablation study** (Table 2, averaged over BrowseComp/WorkBench/PlanCraft/StableToolBench): full MANTA gets 71.7% success; removing the initial Topology Planner (replacing it with a fixed coordinator–worker star) drops this to **57.5%** (−14.2 pts, the largest single contributor); disabling topology repair drops it to **60.8%** (−10.9 pts); freezing or removing the long-term playbook gives smaller drops to 67.5%/66.7%.
- **Mutation-budget sweep** (Figure 4): success rate rises steeply from budget 0→1 mutation and then flattens, i.e., "the first change captures most of the benefit, while up to three changes extend coverage to the most difficult tasks."
- **Token efficiency**: MANTA has the **lowest total token usage among all evaluated multi-agent systems** — 77,652 mean tokens/run (Table 4) vs. static workflows in the 80k–200k range (e.g., Group Chat Debate 201,651; Orchestrator w/ Discussion 184,207) and adaptive baselines (AFlow 151,070; ADAS ~275k; AgentSquare ~158k; MASS ~181k); MANTA's meta-level (Planner/Auditor/Controller/Reflector) overhead is only ~12% of its inference budget.
- **Cross-domain playbook transfer** (Table 3): transferring MANTA's long-term playbook from WorkBench→PlanCraft or PlanCraft→WorkBench yields a mean **+3.3 point** gain, while automated-design baselines transfer neutrally or badly — most strikingly, **MASS collapses from 46.7%→0.0% and 70.0%→0.0%** when its learned design is moved across these two benchmarks (mean Δ = −58.3), suggesting its optimized prompts/topologies are highly benchmark-specific and brittle.
- **Trace-auditing statistics** (Tables 8–10, 450 runs total): the initial audit flags 64.1% of incorrect answers (37.5% precision, 37.5% FPR, 35.9% FNR); clean (unflagged) runs are correct 83.2% of the time vs. 62.5% for flagged runs (a 20.7-point separation). MANTA applies 151 repairs; 60.9% of them reduce the number of process flags, 59.6% make the named repair target disappear from the next audit, and repaired runs are subsequently correct 69.5% of the time. Four of nine process-anomaly modes (evidence_lost_before_synthesis, missing_validator, branch_collapse, give_up_shaped_candidate) each correlate with a >30-point drop in success rate when present, while two modes (message_compaction_loss, tool_error_cascade) show a small *positive* association, meaning they are often recoverable and not true correctness signals.

## Critical Assessment

**Novelty**: The core idea — treating communication topology as a target for online, trace-conditioned self-repair rather than offline search (as in AFlow, ADAS, AgentSquare, MASS) — is a genuinely distinct and well-motivated framing, and the paper is careful to position itself clearly against this prior "Level 6" self-improvement literature (Figure 1's "levels of self-improvement" taxonomy is a nice organizing device).

**Rigor**: The experimental design constrains all multi-agent baselines to the same max agent count and comparable inference budget, and includes an ablation study, a mutation-budget sweep, and a cross-domain transfer study — more thorough than many topology-search papers. However, sample sizes are modest (30 questions × 3 runs per benchmark), producing large standard deviations for some cells (e.g., ADAS on PlanCraft is 57.8±13.4), which makes some individual benchmark comparisons statistically fragile even though the aggregate 5.8-point average gain looks robust given MANTA's own ±1.8 spread. A specific, paper-acknowledged rigor gap: the Trace Auditor's "process flags" are evaluated only as a *correctness proxy* (Table 8's FPR/FNR use benchmark-incorrect as the positive class, not any ground-truth label for whether a coordination defect actually existed) — the authors themselves state that human annotation of a stratified trace sample and a paired-replay comparison "would provide further resolution" but leave both as future work, meaning the causal claim "repair fixed a real structural defect" is not directly validated.

**Reproducibility**: Extensive prompt templates (Planner, Auditor, Reflector, task-agent system prompts) and hyperparameter tables are reproduced verbatim in the appendix, which is good practice; however, no code/data release is mentioned in the reviewed pages, and results depend on a single specific backbone (Gemma 4 31B with "medium reasoning effort," a somewhat unusual and hard-to-replicate setting), so exact reproduction by others would be difficult without released code.

**Significance**: The result that MANTA achieves the best *average* while losing by a large margin to ADAS on WorkBench (43.3 vs. 66.7, a 23.4-point gap) and to AgentSquare on StableToolBench (82.2 vs. 88.9) is a meaningful nuance the abstract elides — describing the average gain as "consistent across five benchmarks" is only true in the sense of "no catastrophic failure," not "best on each task." This doesn't invalidate the contribution (adaptivity that avoids the worst case is itself valuable), but it does mean readers should not take "state-of-the-art everywhere" as the takeaway.

**Red flags / weak points**: (1) The MASS baseline's cross-domain transfer collapsing to exactly 0.0% success in two directions (Table 3) is an unusually extreme failure mode that reads more like a baseline configuration artifact (e.g., MASS's optimized prompt referencing benchmark-specific formatting that breaks entirely out-of-domain) than a graceful degradation, and the paper does not diagnose why MASS fails so completely rather than just underperforming. (2) A single backbone model (Gemma 4 31B) is used for the entire evaluation, so it is unknown whether MANTA's topology-adaptation gains generalize to other model families or scales, despite Figure 7's caption claiming the harness loop "is identical for both LLM backends" — implying a second backbone existed somewhere in the study but was not included in the main results table shown here. (3) The Trace Auditor's own precision is modest (37.5% aggregate, ranging benchmark-to-benchmark from 0.20 F1 on PlanCraft to 0.78 F1 on WorkBench per Table 8), meaning many "repairs" are triggered by flags that do not actually correlate with wrong answers — the paper is commendably transparent about this but it does limit how much of the improvement can be attributed to precise diagnosis versus beneficial exploration/randomness from adding agents.

## Strengths

- A clearly novel problem framing (topology as an inference-time, not just design-time, object of adaptation) backed by a genuinely new taxonomy of "levels of self-improvement" (Figure 1) that cleanly situates the contribution relative to a large body of related work.
- Strong empirical breadth: five benchmarks spanning three capability categories (info-seeking/tool-use, planning/workflow, reasoning), 10+ baselines spanning single-agent, static multi-agent, and automated-topology-search categories.
- Thoughtful mechanism design for making mutation "cheap and lossless" (stateless agents, append-only shared stores, context controller re-pointing) that avoids the common pitfall of losing accumulated evidence when a topology changes mid-run.
- Honest, detailed diagnostic analysis of the Trace Auditor's own precision/recall as a correctness proxy (Tables 8–10) rather than simply asserting the auditor "works," including explicit discussion of which process-anomaly modes are and are not predictive of failure.
- Concrete, interpretable case studies (Figures 3, 5, 6) showing exactly what kinds of structural repairs occur (branch expansion, serialization of duplicate state-changing calls, critic insertion, edge rewiring) rather than only reporting aggregate numbers.

## Limitations

- Single backbone model (Gemma 4 31B, medium reasoning effort) for all experiments; no evidence of generalization across model families/sizes in the main results.
- Underperforms strong baselines on 2 of 5 benchmarks (WorkBench vs. ADAS by 23.4 points; StableToolBench vs. AgentSquare by 6.7 points), a fact not surfaced in the abstract's framing.
- Modest sample size (30 questions/benchmark × 3 runs) yields wide confidence intervals for several baseline/benchmark cells, limiting the statistical strength of some pairwise comparisons.
- The Trace Auditor's process flags are validated only against a correctness proxy, not ground-truth process-defect labels; the authors explicitly note this gap and propose (but do not execute) human annotation and paired-replay studies as future validation.
- Only one topology mutation is allowed per run (by hyperparameter choice), so the framework's behavior under repeated/iterative repair beyond budget 3 is not explored, and the cost/benefit of relaxing this cap on harder tasks is unknown.
- No public code/data release identified in the reviewed material, which combined with a somewhat unusual backbone configuration ("medium reasoning effort" on Gemma 4 31B) may make exact replication difficult.

## Relevance

对于关注多智能体系统架构自适应、workflow/topology 自动化设计（如 AFlow、ADAS、AgentSquare、MASS）以及 LLM 推理期自我改进机制的研究方向，本文提供了一个把"拓扑"当作可在线诊断和局部修复的新层次，其消融实验和跨域 playbook 迁移结果对设计生产级多智能体协作系统有直接参考价值；同时其审计器精度与个别基准落后于基线的诚实披露，也值得作为"如何客观报告多智能体基准结果"的参考案例。

## Questions for Further Exploration

- Why does the MASS baseline's success rate collapse to exactly 0% in both cross-domain transfer directions (Table 3) — is this a genuine limitation of jointly-optimized prompts/topologies, or an artifact of how the baseline was re-configured for a new benchmark?
- Would MANTA's advantage on WorkBench close if given a larger mutation budget or multiple mutations per run, given that its WorkBench score (43.3) is far below several static baselines, not just ADAS?
- How sensitive are the reported gains to the choice of a single backbone (Gemma 4 31B, "medium reasoning effort") — would the same topology-adaptation benefits hold with a smaller/larger model or a different model family (e.g., GPT- or Claude-class models), especially given the harness explicitly supports "two LLM backends"?
- What would a human-annotated process-defect ground truth reveal about the Trace Auditor's true precision/recall, versus the correctness-proxy numbers reported here (Table 8), and would that change which process-anomaly modes are trusted enough to trigger automatic repair?
- Does allowing more than one mutation per run (beyond the current cap of 1, with an operations-per-mutation cap of 3) change the shape of the diminishing-returns curve in Figure 4, or would it introduce new failure modes (e.g., oscillating topologies, runaway agent counts)?
