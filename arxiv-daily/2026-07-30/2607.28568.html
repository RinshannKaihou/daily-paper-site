Key Finding

The same Draft/Improve/Debug/Crossover operators can be trained and redeployed into the evolutionary harness that uses them — a real meta-evolution loop.

Frontis-MA1: Training an AI4AI Model towards Recursive Self-Improvement in Machine Learning Engineering ↗

Junlin Yang, Che Jiang, Yu Fu, Tianwei Luo et al. (24 authors) · 2026-07-30 · AI4AI Evolutionary Search ML Engineering Agents Recursive Self-Improvement
Horizon Research / Frontis.AI & Tsinghua University-led, with Zhejiang, Shanghai Jiao Tong, and Georgia Tech co-authors; Kaiyan Zhang corresponding. Framed as “OpenRSI” — an open technical report (not yet peer-reviewed), released with full datasets, training/eval code, sandbox infrastructure, and model checkpoints.

Why This Matters
A reproducible framework for testing how LLM agents improve on long, verifiable engineering tasks — and for isolating training gains from search gains.
Critical Edge
The headline “exceeds GPT-5.5+Codex” claim compares Medal Average under different compute budgets and hardware — not a controlled, compute-matched comparison.
OpenMLE-Gym
5,758 quality-gated executable tasks (8 modalities) — 10× MLE-Smith's scale.
OpenMLE-ERL
SFT warm start + RL trains reusable Draft/Improve/Debug/Crossover operators, not full trajectories.
OpenMLE-Evo
Experience-card-guided population search deploys the same trained operators at test time.

Methodology how it works

task τ→ operator a ∈ {Draft, Improve, Debug, Crossover}→ policy gθ→ sandbox exec→ scalar score
  • MLE is framed as executable program evolution: SFT and RL both maximize the same weighted log-likelihood over (task, operator, context, program) tuples — they differ only in how the weight is derived from the execution score.
  • Gym: tasks built from 156 curated anchors, 3,362 Kaggle-dataset tasks, and 2,240 Kaggle-competition tasks (MLE-Bench overlaps excluded); an LLM-assisted pipeline packages each competition and an LLM quality filter keeps only “recommended” ones.
  • ERL: SFT collects 26,259 examples (17,245 parallel Drafts + 9,014 evolutionary Improve/Debug/Crossover segments); RL remaps raw metrics to task-adaptive reward bounds and applies an “entropic advantage” that concentrates signal on the best candidate per rollout group (4× sharper best-candidate advantage).
  • Evo: deterministic per-node “experience cards” feed a 3-factor (quality / progress / novelty) non-greedy parent-selection utility, with LLM memory synthesis triggered on-demand rather than eagerly serialized.

Strengths

  • Unifies task construction, operator-level training, and evolutionary search under one shared operator interface — addressing a fragmentation problem versus MLE-Dojo, MLE-Smith, AIRA, and AIDE.
  • Controlled ablations isolate post-training gains (same harness, different model) from search gains (same model, different harness), not just an end-to-end number.
  • Concrete mechanism-level case studies (e.g., a Crossover step cutting validation RMSE 8.2% by combining a physics-informed GNN with a robust-parser parent).
  • Unusually candid, specific limitations section naming exactly which capabilities are still missing for genuine RSI.

Limitations

  • Evaluation runs on 12 GPU-hours/task on a single 12GB-capped RTX 4090 — self-acknowledged as smaller than most reported MLE-Bench evaluations.
  • Learns only from final execution scores, not from reasoning or research-strategy quality — bounding how much “judgment” the model actually acquired.
  • NatureBench Lite transfer evidence is confined to a 10-task, web-search-disabled, 4-hour-budget subset.
  • The evolutionary search framework itself (parent-selection weights, memory triggers) is fixed and hand-designed, not learned or evolved.
  • Full task-package data is withheld for 4,343 of 5,758 Gym tasks due to source-data licensing, partially limiting reproducibility.

Questions for Further Exploration

  • How would results change under compute-normalized (wall-clock/FLOPs-matched) comparison against GPT-5.6 Sol / Kimi K3, rather than differing hardware/model-size regimes?
  • Can the hand-tuned quality/progress/novelty weights in parent selection be learned per-task or per-domain instead of fixed?
  • Does entropic-advantage upper-tail weighting risk reward hacking or mode collapse over search horizons longer than the 12-hour budgets tested?
  • How sensitive is the Gym's “recommended” quality-filter verdict to the specific LLM judge used?
  • Would the same train-then-redeploy-operators recipe transfer to non-MLE AI4AI domains, e.g. kernel engineering or evolving the harness itself?
