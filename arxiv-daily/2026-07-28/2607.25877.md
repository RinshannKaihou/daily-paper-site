> **一句话总结：** 论文构建了一个由数据准备、建模、审阅、解释四个智能体经中心枢纽协调的LLM多智能体精算风险建模系统，创新点是把每个智能体输出的长度归一化对数概率（logprobs）经校准函数转换为置信度证据后接入贝叶斯网络，对跨智能体阶段的不确定性传播建模；在三种小型开源LLM后端上，系统整体RMSE（0.867–0.886）与非智能体基线模型（0.8853）相当，但Qwen2.5-7B后端在20个扰动数据集上的错误检测率达90%，显著优于Llama2-7B的45%和Llama3.1-8B的65%。

> **TL;DR:** This paper builds a 4-agent LLM system (Data Preparation, Modelling, Reviewing, Explanation agents coordinated by a central hub in a star topology) for actuarial risk modelling, and propagates uncertainty across the workflow using a Bayesian Network whose node priors/CPT evidence come from calibrated, length-normalized log-probability ("logprobs") confidence scores rather than treating logprobs as direct correctness probabilities. Tested on an actuarial claims dataset (10 baseline runs plus 20 systematically perturbed variants) across three small open-source LLM backends (Llama 2 7B, Llama 3.1 8B, Qwen2.5 7B), the MAS reproduces a non-agentic baseline model's predictive accuracy (baseline RMSE 0.8853 vs. MAS mean RMSE 0.8839–0.8856 on the original data, Table 2) while exposing large backend differences in reliability: Qwen2.5 7B reaches a 90% error-detection rate on perturbed datasets versus only 45% (Llama 2 7B) and 65% (Llama 3.1 8B), despite similar task success rates (80%/90%/80%). A controlled temperature-sweep experiment shows the Bayesian Network's inferred P(WorkflowOK) dropping from 87.1% (all agents at low temperature 0.2) to 42.8% (one agent pushed to high temperature 1.2), demonstrating the framework's sensitivity to injected uncertainty (Table 1).

## 核心贡献

- 提出一个面向精算风险建模的LLM多智能体框架：数据准备、建模、审阅、解释四个专职智能体在星型拓扑下由中心枢纽协调（避免智能体间直接通信），中心枢纽根据审阅智能体的反馈决定工作流是否修订或终止（如触发"reclean"、"retrain"）。
- 明确区分"logprobs作为置信度信号"与"logprobs作为正确性概率"：将每个智能体输出的长度归一化对数概率求和得到置信特征 $q_i=\exp(s_i)$，再经校准函数 $f_{cal}$（基于验证集拟合）映射为任务成功概率 $P(X_i=\text{success})$，作为证据输入贝叶斯网络，而非直接把logprobs当作正确性概率使用。
- 用贝叶斯网络显式建模工作流各阶段（DataOK→ReviewDataOK→ModelOK/ReviewModelOK/ExplainOK→WorkflowOK）之间的条件依赖，给出AND门式CPT示例（WorkflowOK仅在三个父节点全部为真时取高概率0.99），并可视化不确定性如何从单个智能体（约80%置信度）累积成显著更低的整体工作流置信度（约55%）。
- 设计了一套系统化的数据集扰动/严重度指标体系（稀疏度、行/列变化、缺失率、目标漂移、总体稳定性指数PSI、相关性漂移等，7类指标），在3个LLM后端×(10个原始+20个扰动)数据集上评估任务成功率、RMSE、错误检测率与逐智能体不确定性得分。
- 通过温度扫描实验（4种场景：全低温、混合温度、全默认中温、单智能体高温）证明贝叶斯网络能捕捉"单一环节不确定性升高会显著拉低整体工作流成功概率"这一传播效应（87.1%→42.8%）。

## Key Contributions

- **A centralized star-topology multi-agent actuarial workflow.** A Central Hub coordinates four specialized agents — Data Preparation, Modelling, Reviewing, Explanation — via message passing only through the hub (no direct agent-to-agent communication), routing tasks based on Reviewing Agent feedback (revise/terminate) and decomposing each agent's task into layers (planning, code generation, evaluation, explanation) to reduce prompt complexity (Section 3, Fig. 1).
- **Calibrated confidence from token-level logprobs, not raw correctness probability.** For agent $i$, a length-normalized log-probability summary $s_i = \tfrac{1}{L_i}\sum_t \log p_\theta(z_t|z_{<t},x)$ is exponentiated into a bounded confidence feature $q_i=\exp(s_i)$, then passed through a calibration function $f_{\text{cal}}$ fit on validation runs to obtain $P(X_i=\text{success}\mid q_i)$ (Eqs. 3–5) — explicitly avoiding the common pitfall of treating raw logprobs as success probabilities.
- **Bayesian Network for structured uncertainty propagation across agents.** Each workflow stage is a BN node; directed edges encode stage dependencies; CPTs (e.g., an AND-gate for the final WorkflowOK node, Fig. 3) combine per-agent confidence evidence into posterior estimates of overall workflow reliability, giving an interpretable graph (Fig. 2) that can flag which stage contributes most to end-to-end uncertainty.
- **A 7-indicator dataset-perturbation suite for stress-testing.** Row/column change, missingness, target shift, sparsity, population shift (PSI), and correlation shift (Appendix A) are used to generate 20 controlled perturbed datasets (Table 3), enabling systematic measurement of error-detection rate and adaptability (retraining/re-cleaning behavior) per LLM backend.
- **Empirical backend comparison exposing reliability differences invisible to accuracy alone.** All three backends (Llama 2 7B, Llama 3.1 8B, Qwen2.5 7B) reproduce baseline RMSE and achieve ≥80% task success, but differ sharply in workflow uncertainty (0.55–0.73), error-detection rate under perturbation (45%–90%), and qualitative behavior (Llama 2 approves workflows more readily; Llama 3.1/Qwen more often raise critical notes) despite identical prompts (Table 2, Section 5).

## Methodology

The system (Fig. 1) is a centralized "Actuarial Agent Framework": a Central Hub orchestrates four LLM-based agents — Data Preparation (ingestion/cleaning/encoding), Modelling (predictive model development), Reviewing (evaluates both data-prep and modelling outputs, can trigger "reclean" or "retrain"), and Explanation (interpretability and fairness guardrails, using Testing with Concept Activation Vectors (TCAV) for concept alignment and group-level predicted-vs-observed comparisons across sensitive attributes like age for fairness). Each agent logs outputs/metadata to shared memory; a "Guardrails" layer tracks logging/memory, uncertainty propagation, belief/concept probing, and fairness. Three small, locally-runnable open-source decoder-only LLM backends are tested: Llama 2 7B, Llama 3.1 8B, and Qwen2.5 7B.

Uncertainty quantification (Section 4) starts from the standard autoregressive decomposition $p_\theta(y|x)=\prod_t p_\theta(z_t|z_{<t},x)$ (Eq. 1), takes its log (Eq. 2), and length-normalizes to get $\bar\ell(y)$ (Eq. 3). Per agent $i$, the length-normalized log-probability summary $s_i$ (Eq. 4) is exponentiated to a bounded confidence feature $q_i=\exp(s_i)$, then mapped through a calibration function $f_{\text{cal}}$ (fit on validation runs) to a task-success probability $P(X_i=\text{success}\mid q_i)$ (Eq. 5) — the paper is explicit that this calibrated value, not the raw logprob, is what feeds the Bayesian Network as evidence.

The Bayesian Network (Section 4.2, Pearl's formalism) represents each workflow stage as a node $X_i$ (e.g., $X_1$=successful data preparation, $X_2$=successful data review, $X_3$=successful model training), with the joint distribution factorizing as $P(X_1,...,X_n)=\prod_i P(X_i\mid \text{Pa}(X_i))$ (Eq. 6). Nodes without parents get their prior directly from the calibrated confidence score $c(y_i)$; nodes with parents combine that confidence with a CPT (Fig. 3 shows an AND-gate CPT for the terminal WorkflowOK node, which requires all three of ModelOK, ReviewModelOK, and ExplainOK to succeed to reach its 0.99 prior). The authors explicitly note the BN abstracts an execution trace rather than the full control logic: it does not model temporal ordering beyond parent-child edges, task priority, repeated execution, or feedback/revision loops — if an agent requests a revision, only the final accepted output is used as evidence, keeping the graph acyclic.

## Results & Highlights

- **Task Success Rate (Table 2, main workflow metrics, N=10 original-dataset runs per backend):** Llama 2 7B = 0.80, Llama 3.1 8B = 0.90, Qwen2.5 7B = 0.80 — all three backends succeed on the large majority of runs, with Llama 3.1 highest.
- **Predictive accuracy vs. baseline (Table 2):** the non-agentic baseline actuarial model achieves RMSE = 0.8853; the MAS's mean RMSE is 0.8856 (Llama 2), 0.8839 (Llama 3.1), and 0.8671 (Qwen2.5) — i.e., the agentic workflow reproduces (and for Qwen2.5, slightly beats) the baseline's predictive performance on the original dataset.
- **Error detection under 20 perturbed datasets (Table 2, "Test perturbed dataset metrics"):** Qwen2.5 7B achieves a 90% error detection rate, versus 65% for Llama 3.1 8B and only 45% for Llama 2 7B — the paper's clearest quantitative claim about backend reliability differences, with Qwen2.5 also showing stronger adaptability (retraining/adjusting strategy) under perturbation.
- **Workflow-level uncertainty (Table 2):** mean workflow uncertainty (derived from the BN) is 0.7345 (Llama 2), 0.5506 (Llama 3.1), and 0.6012 (Qwen2.5) on original data, versus 0.7342, 0.5573, and 0.5833 respectively on perturbed data — showing the BN-derived uncertainty is fairly stable across original/perturbed runs for a given backend even though error-detection behavior differs sharply.
- **Scenario-based temperature sweep (Table 1):** with all agents at low temperature (0.2), P(WorkflowOK) = 87.1% (Scenario A); a mixed setting (low temp for Data Prep/Modelling, medium 0.7 for Reviewing/Explanation) drops this to 69.0% (Scenario B); uniform medium/default temperature (0.7) gives 59.2% (Scenario C); and raising just one agent's temperature to 1.2 (Scenario D) drops P(WorkflowOK) to 42.8% — a roughly 2x reduction in inferred workflow reliability from a single component's increased randomness.
- **Agent-level uncertainty breakdown (Table 2):** per-agent uncertainty scores are consistently high (0.80–0.92) across all backends and stages (Data Preparation, Reviewing, Modelling, Explanation agents), yet the combined Overall Workflow score falls to 0.55–0.73 — the paper's Fig. 2 example shows individual-stage certainty around 80% collapsing to about 55% once combined, illustrating how independent per-agent confidence compounds into materially lower end-to-end reliability.

No dataset name (e.g., a specific public actuarial corpus) or its size/features is given in the main text; the paper states only that code, datasets, and evaluation notebooks are released on GitHub (https://github.com/bart-custers/actuarial_agents).

## Critical Assessment

**Novelty:** The specific combination — calibrating token-level logprobs into task-success evidence and feeding that into a Bayesian Network that mirrors the multi-agent workflow's dependency structure — is a sensible, interpretable design, and the explicit stance that "logprobs are not direct probabilities of correctness" (contrasting with cruder prior work like ref. [23]) is a good methodological choice. However, the individual pieces (logprob-based confidence, Bayesian Networks for dependency modeling, TCAV for concept alignment) are each drawn from existing literature; the contribution is the integration into an actuarial multi-agent pipeline rather than a new uncertainty-quantification technique.

**Rigor:** The evaluation is small-scale: only 10 original-dataset runs and 20 perturbed datasets per backend, across three ~7–8B-parameter open models. There is no baseline comparison against a simpler uncertainty-aggregation method (e.g., a plain product or minimum of per-agent confidence scores, without the BN's conditional structure) to isolate whether the Bayesian Network's structure adds value beyond naive aggregation — this is a missing ablation for a paper whose central claimed contribution is the BN itself. The calibration function $f_{\text{cal}}$ is described only abstractly ("estimated using validation runs"); no calibration/reliability curve or calibration error is reported, so it is unclear how well-calibrated the confidence-to-success mapping actually is. With only n=10 runs per backend, no confidence intervals or significance tests accompany the headline percentage differences (e.g., 90% vs. 45% error detection).

**Reproducibility:** Code, datasets, and notebooks are released on GitHub, which is commendable. However, the actuarial dataset itself is never named, described (size, features, source), or characterized in the main text beyond being subjected to the 7 perturbation indicators in Appendix A — a data-quirk gap that limits independent replication of the specific numeric results without inspecting the repository directly.

**Significance:** The insurance/actuarial framing (regulatory transparency, fairness, unfair pricing risk) gives the work a concrete high-stakes motivation, and the finding that per-agent confidence (~80–92%) compounds into markedly lower end-to-end workflow certainty (~55–73%) is a useful, generalizable observation for anyone chaining LLM agents. That said, the study remains a proof-of-concept: four agents, one (unnamed) dataset, and three small open-source backends, with no human-actuary evaluation of whether the reported uncertainty numbers are actionable in practice.

**Red flags:** The paper explicitly acknowledges that the BN "does not explicitly represent execution sequence, task priority, repeated execution, or feedback loops" and instead uses only the final accepted output as evidence after a revision — which could hide exactly the instability that a review/retry cycle is meant to catch, yet this limitation is not empirically probed (e.g., how often revisions occur, or how much uncertainty a revision resolves). The claimed backend behavioral differences (Llama 2 approving more readily; Llama 3.1/Qwen raising more critical notes) are described qualitatively without a quantitative metric to back them beyond the Table 2 numbers already discussed.

## Strengths

- Clear, domain-grounded motivation (actuarial risk modeling under regulatory scrutiny) rather than a generic multi-agent benchmark exercise.
- Principled treatment of logprobs as calibrated evidence rather than raw probabilities, addressing a well-known pitfall in LLM confidence estimation.
- Interpretable Bayesian Network with concrete CPT/AND-gate examples (Fig. 3) and posterior visualizations (Fig. 2) that make it possible to see which workflow stage drives overall uncertainty.
- A reusable, well-specified 7-indicator dataset-perturbation suite (sparsity, row/column change, missingness, target shift, PSI, correlation shift; Appendix A) for stress-testing agentic data pipelines beyond this specific paper.
- Code, data, and notebooks publicly released on GitHub.

## Limitations

- Small evaluation scale: only 10 baseline runs and 20 perturbed datasets per backend, across three ~7–8B parameter models; no larger/production-grade LLM backends were tested.
- The Bayesian Network is a static DAG that explicitly ignores temporal ordering, task priority, repeated execution, and feedback/revision loops — a limitation the authors acknowledge and defer to future dynamic-BN work.
- No named/described dataset (size, features, source) is given in the main text, limiting interpretability of the absolute RMSE/uncertainty numbers without consulting the code repository.
- No comparison against simpler non-BN uncertainty-aggregation baselines, so the specific added value of the Bayesian Network's conditional structure over naive confidence aggregation is not empirically isolated.
- The calibration function $f_{\text{cal}}$ mapping confidence scores to success probabilities is not quantitatively validated (no reliability diagram or calibration error reported).

## Relevance

该论文提供了一个把LLM多智能体系统的token级置信度校准后接入贝叶斯网络、实现跨阶段不确定性传播与可解释性追踪的具体范式，对关注LLM agent可靠性评估、runtime monitoring以及高风险行业（金融/保险）agentic工作流部署的研究方向有较好的参考价值。

## Questions for Further Exploration

- How well-calibrated is $f_{\text{cal}}$ in practice (e.g., reliability diagrams, calibration error), and how sensitive are the reported workflow-uncertainty numbers to the quality of this calibration step?
- Would a simpler non-Bayesian-Network baseline (e.g., a weighted product or minimum of per-agent confidence scores) produce materially different overall workflow-uncertainty estimates, isolating whether the BN's conditional structure adds real value over naive aggregation?
- How do the uncertainty estimates and error-detection rates change with larger, more capable LLM backends (e.g., GPT-4/Claude-class models) rather than the three ~7–8B open models tested here?
- Can the static DAG be extended to a dynamic Bayesian Network or influence diagram that explicitly models the observed revision/retrain feedback loops (Reviewing Agent triggering "retrain" or "reclean"), and how would that change the WorkflowOK posteriors shown in Fig. 2?
- What is the actual dataset used for the actuarial risk-modelling task (size, features, source), and how would the framework's results transfer to other actuarial tasks (e.g., reserving, underwriting) beyond claim-frequency/RMSE-style prediction?
