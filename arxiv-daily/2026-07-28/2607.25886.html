RSIBench-Data: Benchmarking Data-Centric Research for Recursive Self-Improvement ↗

Key metric 78.26%

of continued searches (18 of 23 settings) finish with a final candidate scoring below the agent's own historical-best selection score.

Discovery still happens: 58.33% of the 24 agent×benchmark settings beat the first valid attempt at least once.

Why this matters

Tests whether LLM agents can automate data-centric post-training research for recursive self-improvement — a question central to unattended AI development pipelines today.

Critical edge

Every one of the 24 main results comes from a single run — no error bars anywhere — and checkpoint selection shares its task subset with official evaluation.

Methodology

Fixed infrastructure, free-roaming research loop

RSIBench-Data isolates one capability — data-centric research skill — by freezing everything else an agent could otherwise game.

Fixed for everyone Base target: Qwen3.5-35B-A3B-Base · shared Tinker-backed LoRA SFT · Harbor + E2B sandboxed official eval (Mini-SWE-Agent / Terminus-2 runners). Agents submit data + a whitelisted config only — never training code.
Agent-controlled Capability-gap diagnosis, synthesized training experience (tasks, trajectories, success/failure states), validation/filtering/curriculum, and the stop/continue decision.

  • Matrix: 4 agents (Claude Code Opus-4.8 & Sonnet-5; Codex CLI gpt-5.6-sol & gpt-5.6-terra) × 6 benchmarks (SWE-bench Verified / Multilingual / Pro, Terminal-Bench 2.0, GPQA Diamond, AIME 2026), one representative run per setting.
  • Feedback is narrow: agents see selection scores, trajectories, and verifier/execution diagnostics — never full official-eval details — before deciding whether to keep searching.
  • Final step: the agent picks one checkpoint from selection history alone; only that pick is scored officially on a fresh split.
  • A reasoning-effort ablation (Sonnet-5, high vs. max) and an exploratory same-family pilot (Kimi-K2.6 improving itself) probe two edge cases.

Regression is costly, not just harmless: Codex gpt-5.6-sol's Terminal-Bench 2.0 selection score rises 7.87% → 15.73% peak at $69.07 cumulative cost, then falls to 13.48% after further spend. Claude Code Sonnet-5 improves 4.49% → 7.87% then spends another $81.77 without refreshing the frontier, ending at just 5.62% official.

Exploratory same-family pilot: a Claude-Code-driven researcher trains Kimi-K2.6 on itself, rising 8% → 22% peak across 7 attempts on a fixed SWE-bench Pro subset — yet every checkpoint stays below the unadapted Kimi-K2.6's own 33% score on that subset. A genuine negative result.

Strengths

  • Cleanly separates the fixed infrastructure (Tinker + Harbor/E2B) from the agent-controlled research loop — the exact ambiguity that made prior automated post-training benchmarks hard to interpret.
  • Broad, heterogeneous coverage (SWE, terminal use, science QA, math) shows that task-family similarity doesn't produce a stable agent ranking — three different agents win the three SWE-bench variants.
  • Transparent resource accounting: every run reports wall-clock hours and Tinker dollar cost, enabling real cost-vs-score analysis instead of score-only leaderboards.
  • Rich trajectory analysis ties process-level decisions (diagnosis accuracy, validation grounding, checkpoint preservation) to concrete score changes.
  • Reports an outright negative result (Kimi-K2.6 pilot never beats its own base model) rather than omitting it.

Limitations

  • Single run per agent-benchmark setting throughout — no repeated trials, so reported deltas (especially the reasoning-effort ablation) cannot rule out run-to-run noise.
  • Checkpoint selection and official evaluation share the same task subset — measures fresh-environment performance, not generalization to a held-out split.
  • "Researcher identity" bundles the LLM, agent scaffold, and reasoning-effort setting together, so no clean attribution of which factor drives a given result.
  • High cost ($500 per main run, up to $2,000 for the RSI pilot) and reliance on managed third-party services limit independent, low-cost reproduction.
  • Absolute ceilings stay low on several benchmarks (9% SWE-bench Pro, ~20% Terminal-Bench 2.0) — unclear how much reflects agent limits vs. task difficulty for a 35B target under a tight budget.
Questions for further exploration

Open threads the authors leave dangling

  1. Would open-weight, non-proprietary agent scaffolds reproduce the same 78.26% post-peak regression rate, or is this specific to Claude Code / Codex CLI?
  2. Could an explicit stop/rollback policy, separate from the agent's own judgment, close much of the discovery-reliability gap without changing the underlying LLM?
  3. How would results change if checkpoint selection and official evaluation used disjoint task splits, as the authors themselves suggest is needed?
  4. Does the reasoning-effort tradeoff (larger dataset, fewer attempts, better final score) generalize beyond SWE-bench Verified to the other five benchmarks?
  5. Would scaling the target model beyond Qwen3.5-35B-A3B-Base change which data-synthesis strategies work, and would it change the discovery-reliability gap itself?
  6. What specifically drove Claude Code Opus-4.8 below the base model on SWE-bench Multilingual (5.00% vs. 7.00%) — could the mechanism taxonomy explain regressions below baseline, not just below a prior peak?
