Beyond Self-Knowledge: Propagating Uncertainty Across Reasoning and Retrieval in LLMs

Chandan Kumar Sah, Xiaoli Lian, Li Zhang · Beihang University · posted 2026-07-28

retrieval-augmented-generation adaptive-retrieval llm-uncertainty verbalized-confidence question-answering black-box-llm
Key Finding

A single verbalized-confidence probe routes retrieval decisions in black-box LLMs, beating both always-retrieve and never-retrieve baselines.

一句话总结：用一次性口头置信度作为检索路由信号，平均 F1 优于"总是检索"和"从不检索"，但总 token 消耗反而上升。

Why This Matters

Delivers a rare honest verdict on adaptive RAG routers: retrieval-saving but not token-saving — real guidance for production deployment decisions.

Critical Edge

Only 3 of 18 confidence-vs-always-retrieve comparisons survive statistical correction — the authors themselves call this "not evidence of universal dominance."

Methodology

For each question, a black-box LLM is probed once for a compact JSON state: a provisional answer, verbalized confidence c₀ ∈ [0,1], and a short summary — no logits, hidden chain-of-thought, or fine-tuning required. A frozen, per-model-family threshold τm (selected on validation data before testing, never touched after) decides routing.

Question q
→
Probe call: â₀ + c₀ + summary (1 JSON call)
→
Router: c₀ < τm ?
No → return â₀ directly (1 call total)
Yes → TF‑IDF top‑5 passages → 2nd call → final answer

Three model families (gpt‑5.5, gemini‑3.5‑flash, claude‑sonnet‑5) run three policies — No Retrieval, Always Retrieve, BeyondUncertainty — across 3,000 questions from NQ, HotpotQA, 2WikiMultiHopQA, SQuAD, TriviaQA, and MuSiQue, yielding 27,000 policy rows. API and parsing failures are scored as zero and kept in the denominator, not filtered out.

Strengths

  • Single structured black-box call — no logits, hidden CoT, or fine-tuning — works against any proprietary API.
  • 27,000-row paired evaluation with pre-registered thresholds and a genuine route-count-matched control.
  • Unusually transparent statistics: Holm-corrected significance, retained failures, per-cell heterogeneity all surfaced.
  • Clear calibration-vs-decision-utility framing (poor ECE, useful AUROC 0.628 ranking).
  • Honest conclusion that separates "retrieval-saving" from "token-saving" instead of overclaiming.

Limitations

  • Small benchmark-derived TF-IDF corpora (6,299–17,687 docs) — not a production-scale open-domain retriever.
  • Total token usage rises 28.2% vs. always-retrieve; the probe call trades one cost for another.
  • Model aliases are gateway-reported and explicitly not verified against direct providers.
  • OpenAI's router saturates near 96–100% retrieval, collapsing to Always Retrieve for one of three families.
  • Route-matched control and oracle are post-hoc recombinations, not execution-matched randomized baselines.
  • Only 3/18 confidence-vs-always-retrieve cells survive multiplicity correction.

Questions for Further Exploration

  1. 01Would an execution-matched randomized controller (same probe + two-call structure) confirm the +0.024 F1 allocation advantage, or does some gain come from the probe itself giving extra "thinking time"?
  2. 02Can a cheaper confidence probe (e.g. a distilled model producing just the score) preserve routing benefit while eliminating the 28.2% token overhead?
  3. 03How does the method fare on a production-scale open-domain retriever, where retrieval quality itself is more variable?
  4. 04Why is gpt‑5.5's confidence so concentrated (≥95.8% routed everywhere) versus Gemini and Claude — epistemic property, prompt sensitivity, or a decoding effect?
  5. 05Could a cheap secondary signal (query complexity, sampling consistency) close some of the 0.040 F1 gap to the oracle without a second full model call?
