> **一句话总结：** 作者对自己此前发布的"5个VLM生成胸片报告"基准做了一次法证式复查，发现Claude的A/B两个提示词其实执行的是同一个第三提示词、4张图片的灰度极性被搞反、30例研究其实来自28名患者、分裂集未保留、部分报告在自动抽取时被截断——这些问题使Cochran's Q从154.73"修正"为182.29、McNemar显著对比数从26/45变为27/45，但作者明确撤回所有性能/排名/提示词效应结论，并提出一套八条款的"机器可验证基准契约"作为补救方案。

> **TL;DR:** This is a single-author forensic reproducibility audit of the author's own prior VLM radiology-report benchmark (5 vision-language models on 30 MIMIC-CXR studies). The audit finds the Claude "System A vs. System B" prompt contrast never executed (both conditions were silently bound to prompt C due to a Python import-then-monkeypatch bug), 4 of 30 images had inverted MONOCHROME1 polarity, the 30 "independent" studies came from only 28 patients, and 5 reports were silently truncated at 4000 characters before automated labeling. Recomputing the archived confusion matrix with proper (case, finding) keys instead of positional truncation changes Cochran's Q from the originally reported 154.73 to 182.29 (+17.8%) and the McNemar significant-comparison count from 26/45 to 27/45 raw (18/45 to 20/45 after Holm correction) — but a reviewer-cited count of 28/45 could not be reproduced by any of four McNemar variants. All clinical-performance, model-ranking, and prompt-effect claims are withdrawn; the paper's actual contribution is a documented failure taxonomy and an 8-clause machine-verifiable "benchmark contract" (cohort/pixel/prompt/model/output/annotation/analysis/release) with a 36-test reference implementation.

## 核心贡献

- 提出"计算结果的六个状态"框架（Intended → Executed → Observed → Analyzed → Reported → Released），用于系统性追踪一个基准声明在从协议到公开产物的链条上哪一步发生了偏移。
- 对一个已发布的胸片VLM报告生成基准（5个模型家族、30例MIMIC-CXR研究、2个提示词条件）进行法证审计，发现跨越提示词路由、DICOM极性、患者/研究独立性、数据集切分、输出完整性、自动标签抽取、统计配对等7个层面的系统性偏差。
- 用显式的(case, finding)键重新拼接369个"全条件完整"的案例-发现块，重算Cochran's Q（154.73→182.29）与45对McNemar检验的显著数（原始26/45→27/45，Holm校正后18/45→20/45），并明确指出原审稿人引用的28/45计数在四种McNemar变体下均无法复现（均得到27/45）。
- 建立"三级可修复边界"：转录/算术错误可修正；测量或分母问题可描述但需限定解释范围；处理/输入/参照标准的身份丢失则无法通过重新分析弥补——并据此撤回所有关于模型性能、排名、提示词效应的原始结论，只保留可由留存证据直接支撑的算术事实。
- 设计并实现一套八条款"机器可验证基准契约"（队列、像素、提示词、模型、输出、标注、分析、发布），附36项离线回归测试（使用合成记录级夹具，不含受限临床数据），作为防止此类静默漂移的参考实现（而非已验证的完整框架）。

## Key Contributions

- A six-state taxonomy of a computational result (Intended, Executed, Observed, Analyzed, Reported, Released) used to localize exactly where a benchmark's claims diverge from what was actually executed and released.
- A forensic audit of the author's own previously released chest-radiograph VLM report-generation benchmark (5 model families, 30 MIMIC-CXR studies, 2 nominal prompt conditions), uncovering systemic divergences across prompt routing, DICOM photometric polarity, patient/study independence, dataset split provenance, output completeness, automated label extraction, and statistical pairing.
- Reconstruction of the historical confusion-category matrix using explicit (case, finding) keys instead of positional truncation: Cochran's Q changes from the originally reported 154.73 to a keyed value of 182.28998 (+27.56, +17.8%), and the count of McNemar comparisons with p<0.05 (of 45 pairs) changes from 26/45 (raw) / 18/45 (Holm-adjusted) to 27/45 / 20/45 — while a reviewer-cited 28/45 count is shown to be non-reproducible under any of four tested McNemar variants.
- A three-level "repair boundary" (arithmetic/transcription errors are correctable; measurement/denominator problems can be described but not reinterpreted; identity failures in treatment/input/reference standard cannot be repaired by reanalysis) that governs which original claims are withdrawn versus retained as narrow artifact facts.
- An 8-clause machine-verifiable benchmark contract (cohort, pixel, prompt, model, output, annotation, analysis, release) with a 36-test offline regression suite (6 control families) shipped as a reference implementation, explicitly scoped as unvalidated at prospective scale.

## Methodology

The audit is a **retrospective, non-preregistered, single-author forensic review** of a project snapshot frozen on 27 July 2026 — not a rerun of the original experiment. No model API was called again, no image was re-rendered, and no report or label was newly annotated; the audit unit is "an artifact, transformation, or scientific claim," not a patient outcome.

**Evidence hierarchy and identity checks (Sections 2–3).** For each of the six states (Intended/Executed/Observed/Analyzed/Reported/Released), the audit defines the preferred evidence and an explicit fail-closed rule that rejects convenient proxies (e.g., a filename or console label is insufficient proof of image or prompt identity — a rendered-image hash or a request-side payload trace is required). Six domains get dedicated rules: prompt identity (payload trace vs. request text), image identity (DICOM attributes + rendered bytes), model identity (resolved provider identifier, not a mutable alias), completion (atomic record with nonzero bytes/request ID/finish state, not just a logged "ok" flag), pairing (explicit (case, finding) keys, not equal vector length after deletion), and public release (bytes retrievable from the dated archive, not just "corrected" local files).

**Execution trace.** The audit traced Python imports, function arguments, module-level mutable state, and adapter calls from the batch runner to the API boundary — because a name reassigned in one module does not update a value already bound (by import-by-value) in another module. This uncovered that the Claude adapter path imported the report-generation function from a pipeline module *before* a later monkey-patch replaced the "System A"/"System B" prompt variable in a different module — so both nominal Claude conditions were silently bound to a third, unintended prompt ("System C") for all 60 labeled calls.

**Cohort/pixel audit.** DICOM headers (ViewPosition, PhotometricInterpretation) and a pseudonymous patient alias were cross-checked against the case manifest at both study and patient level. The DICOM standard defines MONOCHROME1 and MONOCHROME2 with inverted minimum/maximum sample-value semantics; the audit found the renderer applied identical processing to both encodings, reversing displayed polarity for 4 MONOCHROME1 inputs.

**Output reconciliation.** Every one of the nominal 30×5×2=300 planned model-prompt calls was reconciled against logged path, byte count, and status — distinguishing "missing," "zero-byte," and "logged-ok-but-empty" as different failure states (an important distinction because a naive completion count of "300 minus zero-byte" would silently differ from "300 minus zero-byte-or-missing").

**Statistical reconstruction.** Each retained observation got a scientific key from (case, finding) identifiers (10 nominal model×prompt columns, k=10). The historical procedure had deleted missing values independently per column and then truncated all columns to the shortest remaining length (n=383) — a **positional** join that silently mispairs observations after the first asymmetric gap. The audit instead built one globally complete 369-block matrix using key-based joins, and recomputed Cochran's Q (Cochran 1950) and all C(10,2)=45 pairwise McNemar tests (uncorrected, continuity-corrected, exact binomial, exact mid-p variants; Holm 1979 multiple-comparison correction).

**Claim adjudication.** Each headline claim from the original manuscript was assigned one of four statuses — *retained as an artifact fact*, *restricted* (valid only for the archived automated-label matrix, not a clinical claim), *unverifiable* (identity/config/source not retained), or *withdrawn* (the executed condition/input/measurement did not match the reported contrast). This adjudication was explicitly author-led and not independently replicated.

**Benchmark contract design.** Eight clauses (cohort, pixel, prompt, model, output, annotation, analysis, release) each specify required fields, an identity check, and a fail-closed behavior; a subset is implemented as a reference validator (JSON Schema + Python cross-field tests) exercised against 36 offline regression tests using synthetic record-level fixtures (no real MIMIC data is redistributed).

## Results & Highlights

- **Cochran's Q (global test over the archived automated-label matrix):** original reported value **Q = 154.73**; keyed, globally-complete-cohort reconstruction (n=369 case-finding blocks, MIMIC-CXR-derived) gives **Q = 182.28998** (df=9, nominal p=1.684×10⁻³⁴) — a delta of **+27.56 (+17.8%)** attributable to fixing the positional-truncation mispairing bug, not to any change in model behavior.
- **McNemar pairwise comparisons (45 pairs across 10 nominal model×prompt conditions):** the original manuscript reported **26/45** raw comparisons with nominal p<0.05 and **18/45** after Holm adjustment; the keyed common-cohort reconstruction yields **27/45** raw and **20/45** Holm-adjusted, identical across all four implemented McNemar variants (asymptotic, continuity-corrected, exact binomial, exact mid-p).
- **Non-reproducible reviewer count:** a reviewer-cited **28/45** raw McNemar count could not be reproduced by any tested route — all four pairwise available-case variants (each pair using its own available blocks) converged on **27/45** raw / **20/45** Holm-adjusted, not 28/45, showing the discrepancy predates this audit and was never resolved during pre-submission review.
- **Output completeness:** of the nominal design's 300 planned model-prompt calls, only **297/300 (99.0%)** yielded genuinely nonempty reports — 2 Qwen files were zero-byte despite a logged "ok" status and 1 Gemini file was entirely absent, versus the "near-complete output set" claimed in the original report.
- **Cohort/global completeness:** of 420 possible case-finding blocks (30 studies × 14 CheXpert-style labels), only **369 (87.9%)** were complete across all 10 nominal conditions, leaving 51 incomplete blocks — the number underlying the corrected Q and McNemar statistics.
- **Cohort identity failure:** the 30 "independent" studies were drawn from only **28 patients** (2 patients contributed 2 studies each), invalidating the claimed independent-sampling-unit design; and DICOM headers showed **14 PA / 11 AP / 1 lateral (LL) / 4 undocumented-view** studies against a claimed "frontal-only" (PA/AP) cohort.
- **Prompt-routing failure (the headline finding):** all 60 Claude calls labeled "A" and "B" were traced, via Python import-order analysis, to have executed the **same third prompt ("System C")** — meaning the reported "Claude A vs. B" contrast never existed as an executed treatment.
- No independent baseline model or external comparator is used anywhere in this paper — the entire "comparison" is the paper's own prior release versus its forensically reconstructed self, which is the appropriate design for a self-audit but means the CONTENT CONTRACT's usual "paper vs. baseline" framing is best read as "corrected reconstruction vs. originally reported/claimed values" as tabulated above.

## Authors & Credibility

Single author: Mateusz Kozłowski, an independent researcher (Kraków, Poland; ORCID linked), corresponding via a personal Gmail address, with no institutional affiliation listed and no external funding. The author explicitly discloses using OpenAI Codex for "code review, synthetic test scaffolding, figure generation code, and language editing" but states it did not supply clinical labels or new experimental observations. Critically, the author states in Limitations: "The same author designed the original project, performed the audit, adjudicated claims, and prepared this report... creates risks of selective attention and confirmation bias... The audit was retrospective, not preregistered, and no independent laboratory repeated it." This is a self-correction of the author's own prior work (originally deposited on Zenodo, DOI 10.5281/zenodo.21427298, with a corrective archive at 10.5281/zenodo.21629849), not an external audit of a third party's benchmark — a fact that should recalibrate how much independent-oversight credit the paper deserves, even though the transparency is commendable.

## Critical Assessment

**Novelty:** The six-state (Intended/Executed/Observed/Analyzed/Reported/Released) taxonomy and the "three-level repair boundary" are a genuinely useful conceptual contribution distinct from prior reproducibility checklists (CLAIM, FAIR, PROV-O) — those frameworks ask whether components are *disclosed*, while this paper's contribution is asking whether disclosed components *actually executed as described*, verified via Python import-order tracing and DICOM-level checks rather than documentation review. The Claude A/B-collapse bug specifically (caught only by execution-path tracing, invisible to any artifact-level check because filenames and directory structure remained consistently labeled A/B) is a sharp, concrete illustration of why documentation-based reproducibility audits are insufficient.

**Rigor:** The statistical reconstruction is careful and appropriately humble — the paper explicitly states the nominal p-values are "forensic reproductions of historical arithmetic, not a corrected inferential analysis" and flags that the chi-square/binomial reference distributions used for Q and McNemar have no defensible population-level calibration given that 14 finding labels are nested within each study and 2 patients contributed repeated studies (i.e., the "369 independent blocks" are not actually independent — a limitation the paper itself surfaces rather than hides). A genuine paper-specific weak point: Section 6.2 explicitly states "Because the defects were not isolated, this audit does not estimate the contribution of any single one" — i.e., there is no ablation isolating how much of the Q/McNemar delta came from the truncation-join fix versus the (unaddressed) prompt-collapse or polarity-inversion issues, leaving readers unable to attribute the +17.8% Q change to any specific mechanism.

**Reproducibility (of the audit itself):** Ironically strong for a paper about reproducibility failures — 36 offline regression tests using only Python's standard library, a dependency-free JSON Schema validator, SHA-256 manifests, and a documented three-tier verification boundary (public / controlled / unreconstructable). But the paper is candid that a third party cannot independently regenerate the reported 27/45 and 20/45 study-specific counts from the public release candidate alone, because the record-level MIMIC-CXR matrix cannot be redistributed (credentialed data) — so the headline numerical claims in this very paper are themselves only independently checkable by someone with separate MIMIC-CXR/PhysioNet credentials re-deriving the same intermediate files, which is a meaningful residual opacity for a paper whose whole thesis is about verifiability.

**Significance / overclaiming check:** The paper is unusually disciplined about *not* overclaiming — it explicitly withdraws all five original headline claims (System B reduces hallucinations; five-model performance ranking; Claude A/B behavior difference; scale/open-vs-proprietary explanation; "released bundle reproduces the paper") in Table 5, and states outright that "presenting corrected performance estimates would... exceed the evidence." This self-restraint is the paper's strongest asset. The one place restraint could be questioned: describing 550/551 historical false-positive cells as "minor" via "a deterministic finding-name rule" (not radiologist adjudication) while simultaneously arguing severity labels were never clinically valid — the paper does flag this contradiction itself ("All clinical interpretations of this variable were therefore withdrawn"), so it is transparent rather than a red flag, but the original severity labeling scheme (assigning clinical severity by string-matching finding names) is a fairly weak design choice worth naming explicitly as a weak baseline/methodological choice in the original (now-withdrawn) benchmark.

**Red flags:** (1) n=30 studies / 28 patients was always a "pilot comparison," not a benchmark at scale — this was true even before the audit and is somewhat undersold relative to how the original "five-model performance ranking" claim was likely presented; (2) the benchmark contract's coverage table (Table 7) honestly marks Model and Annotation clauses as "Specification only" (no executable component), meaning roughly a quarter of the proposed 8-clause contract is not yet enforceable code, which tempers the "machine-verifiable" framing in the abstract; (3) single-author, self-adjudicated, non-preregistered — appropriate disclosure, but it does mean this is a case study of n=1 benchmark, and the paper is explicit that "it cannot estimate how often similar failures occur in medical AI" and should not be read as a prevalence-derived taxonomy.

## Strengths

- Unusually rigorous and specific failure diagnosis: pinpoints a Python import-by-value plus module-level monkey-patch bug as the exact mechanism that silently collapsed a designed A/B prompt contrast into a single unintended condition — a failure mode that would be invisible to any artifact-level (filename/table/figure) check.
- Principled, well-justified three-level repair boundary that cleanly separates "we can fix the arithmetic" from "we cannot reinstate the scientific claim," and consistently applies it to withdraw claims rather than quietly patching numbers and moving on.
- Concrete, actionable machine-verifiable contract (8 clauses) accompanied by a working 36-test reference implementation using synthetic fixtures, directly translatable to other VLM-benchmark pipelines.
- Exceptional intellectual honesty: explicitly disclosing conflict-of-interest-like risks (self-audit, non-preregistered, no independent replication), disclosing generative-AI tool use, and choosing precise, non-inflated terminology ("automated report-label discordance" instead of "hallucination").

## Limitations

- Single case study from one small, low-n (30 studies/28 patients) radiology VLM pilot; explicitly not a prevalence estimate of how common these failure modes are across medical AI benchmarks generally.
- Audit is retrospective and not preregistered, performed and adjudicated entirely by the same author who built the flawed original benchmark, with no independent lab or reviewer replication.
- Cannot recover several ground-truth elements at all: provider-side request payloads (so the Claude C/C-prompt finding is an inference from code, not from logged API traffic), historical resolved model identifiers/snapshots, raw extractor responses, full decoding configuration, and final train/test split membership.
- The reconstructed Cochran's Q and McNemar statistics use chi-square/binomial reference distributions that do not account for within-study clustering (14 nested finding labels per study) or repeated patients — the paper flags this but does not offer a corrected, clustering-aware inferential alternative.
- The proposed benchmark contract is only partially implemented as executable code (Model and Annotation clauses remain "specification only"), and has not been prospectively validated on an independent project or measured for false-alarm/missed-failure rates.

## Relevance

这篇论文对做"用LLM/VLM自动生成或评判医学报告/基准"的研究极具参考价值：它具体展示了提示词绑定、DICOM极性、患者独立性、自动标签抽取等环节如何在人不知情的情况下悄悄破坏一个看似严谨的基准，其六状态框架和八条款契约可直接用作日常评审/自建基准时的检查清单。

## Questions for Further Exploration

- Could the proposed 8-clause contract be prospectively trialed on a different, independently-run VLM radiology benchmark to measure real false-alarm and missed-failure rates, as the author suggests is needed future work?
- How much of the +17.8% Cochran's Q change is attributable specifically to the positional-truncation-vs-keyed-join fix, versus confounded effects from the (separately unresolved) prompt-collapse and polarity-inversion defects — could a controlled synthetic-data simulation isolate each contribution?
- Would a clustering-aware statistical model (accounting for findings nested within studies and repeated patients) meaningfully change the McNemar/Cochran conclusions, even under the "forensic reproduction only" framing?
- Is the "automated report-label discordance" framing (replacing "hallucination") likely to be adopted more broadly, and how does it relate to the taxonomy proposed in Brooks & Anastasio (2026), which this paper cites?
- What would it take to make the Model and Annotation clauses of the benchmark contract executable rather than specification-only, given that provider-resolved model identifiers and raw extractor responses are often not exposed by commercial VLM APIs?
