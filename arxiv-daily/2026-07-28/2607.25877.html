Runtime Uncertainty Monitoring for LLM-Based Multi-Agent Systems Using Bayesian Networks

Bart Custers & Koorosh Aslansefat — University of Hull, UK · 28 Jul 2026

multi-agent systems uncertainty quantification Bayesian networks actuarial modeling LLM runtime monitoring

Four LLM agents run an actuarial workflow while a Bayesian Network turns their calibrated confidence into a live reliability signal.

Key metric — Table 1, temperature sweep
87.1% → 42.8%

P(WorkflowOK) roughly halves when just one of four agents has its temperature pushed from 0.2 to 1.2, everything else unchanged.

Why this matters

Turning per-agent confidence into a Bayesian Network gives a concrete, interpretable way to monitor LLM agent reliability before deploying agentic workflows in regulated, high-stakes fields.

Critical edge

No baseline against a simpler confidence-aggregation method means the Bayesian Network's own added value over naive averaging is never actually isolated.

Methodology

A Central Hub coordinates four LLM agents in a star topology — Data Preparation, Modelling, Reviewing, and Explanation — so agents never talk to each other directly; the Reviewing agent's feedback decides whether the Hub triggers a "reclean" or "retrain" cycle, and the Explanation agent applies TCAV concept checks plus group-level fairness comparisons across sensitive attributes.

For uncertainty, each agent's output yields a length-normalized log-probability summary si, exponentiated into a bounded confidence feature qi = exp(si), then passed through a calibration function fcal — fit on validation runs — to produce a task-success probability. This deliberately avoids treating raw logprobs as correctness. The calibrated probabilities become evidence in a Bayesian Network (Pearl's formalism) whose nodes mirror workflow stages and whose CPTs — e.g. an AND-gate for the terminal WorkflowOK node — combine them into a posterior. The BN is a static DAG: it captures dependency structure but not temporal order, retries, or revision loops; only the final accepted output after any revision enters as evidence.

Illustrative — schematic of the workflow-stage DAG described in Section 4.2 / Fig. 2–3. Independent per-stage confidence (~80–92%) compounds through the CPTs into a markedly lower end-to-end WorkflowOK probability (~55–73%, backend-dependent).

Strengths

  • Domain-grounded motivation: actuarial risk modelling under real regulatory scrutiny, not a generic multi-agent benchmark.
  • Treats logprobs as calibrated evidence rather than raw probabilities, addressing a known LLM-confidence pitfall.
  • Interpretable Bayesian Network with a concrete CPT/AND-gate example and posterior visualizations showing which stage drives uncertainty.
  • Reusable 7-indicator dataset-perturbation suite (sparsity, row/column change, missingness, target shift, PSI, correlation shift) for stress-testing agentic pipelines beyond this paper.
  • Code, data, and evaluation notebooks are publicly released on GitHub.

Limitations

  • Small scale: only 10 baseline runs and 20 perturbed datasets per backend, across three ~7–8B open models.
  • The Bayesian Network is a static DAG that ignores temporal order, task priority, repeated execution, and feedback/revision loops.
  • The actuarial dataset itself is never named or described (size, features, source) in the main text.
  • No comparison against simpler non-BN confidence-aggregation baselines to isolate the BN's own added value.
  • The calibration function fcal is not quantitatively validated — no reliability diagram or calibration error reported.

Questions for Further Exploration

  1. How well-calibrated is fcal in practice, and how sensitive are the reported workflow-uncertainty numbers to that calibration quality?
  2. Would a simpler baseline — a weighted product or minimum of per-agent confidence scores — give materially different overall uncertainty estimates than the BN?
  3. How do uncertainty estimates and error-detection rates change with larger, more capable backends (e.g. GPT-4/Claude-class models) instead of the three ~7–8B open models tested here?
  4. Can the static DAG be extended into a dynamic Bayesian Network or influence diagram that explicitly models the observed retrain/reclean feedback loops?
  5. What is the actual dataset used (size, features, source), and how would the framework transfer to other actuarial tasks such as reserving or underwriting?
