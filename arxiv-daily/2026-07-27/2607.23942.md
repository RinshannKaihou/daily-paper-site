> **一句话总结：** 本综述用七字段机制重构法和 E1–E4/E0–D4 双轴证据编码，将 10 个历史认知架构、8 个通用语言智能体运行时和 42 个机制导向系统映射为可审计的迁移账本，发现现代系统已通过收敛（而非继承）迁移了大量控制机制，最终用 GraSP 关闭了 1 个技能治理候选包，留下 5 个可证伪的残差控制包（激活-延迟-效用、类型化僵局-子态-编译、内容竞争-广播-准入学习、意图-重考虑-方法权威、不确定性-资源-中断-停止）作为后续运行时研究议程。

> **TL;DR:** A mechanism-level (not feature-label) review that maps 10 historical cognitive architectures (ACT-R, Soar, CLARION, LIDA, Hearsay-II, BDI, MIDCA, ICARUS, EPIC, Sigma) against 8 general language-agent runtimes (Letta, LangGraph, AutoGen, AgentScope, OpenHands, Microsoft Agent Framework, OpenAI Agents SDK, AIOS) and 42 mechanism-focused modern systems, using a seven-field reconstruction K=⟨S,C,T,P,F,L,R⟩ plus an independent evidence-relation axis (E1 lineage → E4 convergence) and migration-depth axis (D0 concept → D4 adaptive control law). The frozen-corpus coding (frozen 26 July 2026) shows the landscape is uneven: modern specialized systems reach D3/D4 on memory, failure, workspace, commitment, meta-control, skill, resource and uncertainty edges, mostly via E3/E4 convergence rather than E1 lineage. Adversarial closest-baseline screening closes the skill-governance candidate (B5) because GraSP already composes calibrated multi-skill routing + typed verification + bounded repair + global replanning/ReAct fallback, leaving 5 residual bundles (B1–B4, B6) as falsifiable runtime-invariant hypotheses with named insertion points, baselines, and rejection conditions. No quantitative benchmark deltas are reported — this is a mapping review whose deliverables are the coding ledger and the agenda.

## 核心贡献

- **机制级（而非功能标签级）的对比框架**：将每个机制通过七字段元组 K=⟨S, C, T, P, F, L, R⟩（状态、控制、触发、持久化、失败、学习、资源/治理）重构，强制"内存""规划"等共享标签暴露出不同的权威状态与控制语义。
- **双轴独立证据编码**：E1–E4 编码证据关系（文档化谱系 / 结构迁移 / 功能近似 / 结构收敛），D0–D4 编码迁移深度（概念 / 接口 / 状态组件 / 运行时控制律 / 自适应控制律），两者正交——一个高 D 值可与缺失的历史不变量共存，一个 E1 谱系也可停留在 D1。
- **可审计的冻结语料与方法**：冻结于 2026-07-26 的语料包含 10 个历史架构、8 个通用运行时、42 个机制系统；提供带排除测试的编码规则、claim-packet 格式、可复现的查询模板日志，并明确声明不主张 PRISMA 完备性或因果性能。
- **残差抽取 + 合并/拆分规则产出 6→5 个候选包**：用对抗式最近基线筛查关闭 B5（GraSP 已完整实现选择-验证-修复-回退链），把 5 个存活包转化为带运行时插入点、基线、可观测量和失败条件的可证伪干预议程。
- **可证伪的研究转向**：把历史架构的价值从"概念复用"重新定义为"控制律深度 + 可组合运行时不变量"，要求任何新机制必须相对已编码的 D3/D4 强基线（如 GraSP、SCALAR、Utility-Guided Orchestration、CURATOR）证明组合增量价值。

## Key Contributions

- A **mechanism-level comparison framework** that replaces feature-label comparison with seven-field reconstruction K=⟨S,C,T,P,F,L,R⟩, forcing shared labels (memory, planning, reflection) to reveal their authoritative state, transition trigger, failure semantics, and learning consequence.
- **Two orthogonal coding axes** decoupling evidence relation (E1 documented lineage → E4 structural convergence) from migration depth (D0 conceptual → D4 adaptive control law), with operational coding rules, exclusion tests, and a "highest-depth reviewed instance" claim packet format that explicitly forbids conflating a high D-level with complete migration.
- An **auditable frozen corpus and protocol** (frozen 26 July 2026): 10 historical architectures, 8 general runtimes, 42 mechanism-focused systems, with documented search/screening, four equivalence tests (checkpoint≠impasse, message-bus≠workspace, handoff≠intention, guardrail≠meta-control), and explicit "no PRISMA, no causal-performance, no inter-rater-reliability-yet" validity boundaries.
- **Residual-extraction + merge/split rules producing a 6→5 bundle partition**: adversarial closest-baseline screening closes B5 via GraSP (calibrated routing + typed DAG verification + bounded repair + global replanning/ReAct fallback), converting the five survivors into pre-registration-ready interventions with insertion points, closest baselines, and primary falsifiers.
- A **reframing of historical value**: cognitive architectures become sources of precise, falsifiable runtime invariants rather than wholesale inheritance targets; any new mechanism must demonstrate compositional value against the strongest D3/D4 baselines already in the corpus (GraSP, SCALAR, CURATOR, Utility-Guided Orchestration, etc.).

## Methodology

The paper conducts a **bounded mechanism-level mapping review** (not a meta-analysis, not a benchmark). Its unit of analysis is a *documented mechanism* — an operation that consumes explicit state, is triggered identifiably, exercises control over a transition, and may change later behavior.

**Corpus (frozen 26 July 2026):**
- **Corpus H** — 10 historical architecture families: ACT-R, Soar, CLARION, LIDA, Hearsay-II/blackboard, BDI, MIDCA, ICARUS, EPIC, Sigma (theory papers + manuals as source).
- **Corpus M-A** — 8 general runtime families: Letta, LangGraph, AutoGen, AgentScope, OpenHands, Microsoft Agent Framework, OpenAI Agents SDK, AIOS (plus Magentic-One and Agent Spec as supporting cases) — used to locate *implementable insertion boundaries*.
- **Corpus M-B** — 42 mechanism-focused modern records (AgeMem, Memory-R1, CURATOR, PALADIN, Shepherd, Reflexion, DyLAN, Global Workspace Agents, hybrid/self-aware BDI-LLM, ADAS, AFlow, Voyager, SkillOps, SkVM, GraSP, AIOS, KnowNo, Utility-Guided Orchestration, etc.) used to determine the *highest migration depth*.
- **Corpus B** — explicit historical–modern bridges (CoALA, LLM-ACTR, hybrid BDI-LLM).

**Coding scheme:** Every mechanism is reconstructed via the seven-field tuple K=⟨S,C,T,P,F,L,R⟩. Each correspondence gets exactly one E-code (precedence rule: E1 if modern source attributes the mechanism to the historical architecture; else E2 for implemented source-like state+control; else E3 for same problem solved with different organization; else E4 for node-edge similarity without transfer evidence) and one D-code (D0 concept → D1 callable interface → D2 explicit state/components → D3 runtime trigger executing the mapped transition → D4 outcome updates future policy).

**Residual derivation:** Each mapping row contributes its smallest missing invariant; atoms are merged only when they share an insertion boundary and one supplies state/authority for another; split when they have independent triggers/baselines/falsifiers. A bundle survives only if every constituent edge has a reviewed modern precedent, the coupling is absent from the frozen corpus, and the composition has a concrete insertion point and rejection condition. This produced 6 candidates; closest-baseline screening then closed B5 (GraSP), leaving 5.

**Adversarial discipline:** Two coding passes (extraction then adversarial review); every D3/D4 claim is exposed in Appendix C as an independent recoding packet for a second author; Appendix E records version-pinned repository revisions (full commit hashes in bibliography) so repository evidence is admissible only as an implementation surface, never as scientific evidence of mechanism quality.

## Results & Highlights

This is a mapping review; its quantitative deliverables are corpus counts, the E/D coding ledger, and the bundle partition rather than task-accuracy deltas. The concrete quantitative claims:

- **The corpus spans 10 historical architectures + 8 general runtime families + 42 mechanism-focused modern systems** (Corpus M-B), with AIOS cross-indexed because it is both a general runtime proposal and a resource-governance implementation; the counts describe analytical roles, not disjoint publications.
- **The 6-candidate bundle partition reduces to 5 residual bundles after closest-baseline screening closes exactly 1 candidate (B5)** via GraSP, which already composes the complete E3/D4 chain of calibrated multi-skill routing + typed precondition–effect DAG verification + bounded typed repair + global replanning/ReAct fallback; B5 is therefore retained as a "closed negative case," not a residual hypothesis.
- **Most (8 of 10) historical families reach D3 or D4 in specialized modern systems**: ACT-R (memory E3/D4), Soar (typed recovery E2/D3–E3/D4, chunking E3/D4), LIDA (workspace E2/D3, learned competition E3/D4), BDI (E1/D3), MIDCA (design-time E3/D4), CLARION (SCALAR E2/D4), ICARUS (induction/governance/adaptive compilation E3/D4; static compilers E3/D3), EPIC (AIOS/AgentRM E3/D3), Sigma (UALA/KnowNo/CTA E3/D3). **Hearsay-II is the lone holdout at E4/D2** (only explicit shared-state structure; no partial-solution value model or opportunistic agenda scheduler).
- **The E-level distribution skews heavily toward convergence, not lineage**: only BDI-related mappings reach E1 (documented lineage via hybrid/self-aware BDI-LLM); CLARION→SCALAR is E2 (structural migration); the vast majority of the 16+ mapping rows in Appendix B are E3 (functional approximation) or E4 (structural convergence with no transfer evidence) — i.e., modern systems reinvent the control solutions independently.
- **The migration ledger names a specific preserved invariant vs. missing invariant for every row** (e.g., for ACT-R→adaptive memory: preserved = "experience-dependent selection and value-cost governance"; missing = "no unified activation–latency–action-utility law"; provisional code E3/D4), giving each residual bundle a concrete falsifier (e.g., B1 rejects when "a simpler selector matches performance or relevant recall falls").

No quantitative results reported for task/benchmark performance — the paper explicitly states it "establishes feasibility and architectural hypotheses, not cross-domain causal value" and that "existing systems report local gains in their own settings."

## Critical Assessment

- **Novelty:** Genuinely novel framing. Treating cognitive architectures as a *catalog of executable control mechanisms* and decoupling lineage (E-axis) from implementation depth (D-axis) is a real methodological advance over CoALA-style concept import and feature-label surveys. The four equivalence tests (checkpoint≠impasse, message-bus≠workspace, handoff≠intention, guardrail≠meta-control) are sharp and reusable.
- **Rigor:** High on protocol transparency (frozen corpus, dated query log, exclusion tests, version-pinned commits, Appendix C recoding packets, Appendix D pre-registration templates). But **the entire coding is single-author and provisional** — the paper itself flags that "the present manuscript does not claim independent inter-rater reliability," and a second-author recoding of all D3/D4 claims is promised *before submission*. The reader is effectively looking at one coder's provisional judgment, which materially weakens any strong claim about the E/D distribution.
- **Reproducibility:** Strong *at the query-template and evidence-packet level* (Appendix F gives per-record analytical roles; Appendix E pins commit hashes; result counts were explicitly *not* frozen, so no stable-hit-count claim is made). A re-coder following the rules could reproduce the partition only "conditional on the provisional source codes," which the authors honestly admit.
- **Significance:** The 5-bundle agenda is the most valuable concrete artifact — it converts vague "agents should be more cognitive" appeals into named, falsifiable, baseline-anchored interventions (e.g., B6 against Utility-Guided Orchestration, which "uses heuristic uncalibrated uncertainty and supplies no cross-stage propagation"). The GraSP-closes-B5 demonstration is a nice methodological touch: the framework removes an agenda item rather than inflating the gap count.
- **Red flags / overclaiming risk:** (1) The "Primary/Primary/Primary/Primary/Primary" self-positioning in Table I is self-awarded and slightly self-serving — the comparison axes are defined by the authors, so unsurprisingly they win all five. (2) The D-coding of modern systems (e.g., reaching D4 for AgeMem, SkVM, GraSP) rests on accepting those systems' own claimed learning loops at face value; if a "D4" system's outcome update is shallow (e.g., Reflexion's textual reflection is arguably more D2-with-a-prompt than a true control-law update), the entire residual analysis shifts. (3) DAM is included as a "conceptual comparator" that is *not* an evaluated algorithm — yet it sits in the same ACT-R row as CURATOR, risking an impression of equivalent evidence weight that the prose has to qualify. (4) The bundle merge/split rules are stated but their application is not fully mechanized — "different source codes can change" the partition, so the "five" is provisional, not a discovered fact.

## Strengths

- Mechanism-level reconstruction (the K-tuple) forces apples-to-apples comparison where feature labels fail; the historical anatomy of each architecture is presented as an *operational chain* (state→trigger→control→transition→learning→problem solved), not a feature list.
- The E/D decoupling is the paper's sharpest insight and is enforced by an evidentiary precedence rule, preventing two symmetric overclaims (lineage≠depth; depth≠lineage).
- Closest-baseline screening that *closes* a candidate (B5 via GraSP) rather than only opening gaps demonstrates the method can falsify its own agenda — a mark of intellectual honesty rare in survey/review papers.
- The residual bundles are concretely actionable: each has a named runtime insertion point (Letta/LangGraph for B1, error/interrupt boundary for B2, pre-inference admission for B3, workflow/governor boundary for B4, scheduler/tool-authorization for B6), a named closest baseline, and a primary falsifier — making them pre-registration-ready.
- Cross-bundle dependency analysis (Section VI-D) gives a defensible implementation order (externalize intentions/uncertainty/budgets/recovery first, then typed failure and admission, then adaptive memory and compiled skills), which is useful engineering guidance.

## Limitations

- **Single-coder, provisional codes:** No inter-rater reliability; all D3/D4 scores are provisional pending second-author recoding. This is the single biggest threat to the validity of the reported E/D distribution and the resulting bundle partition.
- **No causal/performance evidence:** The review explicitly cannot show that the 5 residual bundles *improve* reliability, efficiency, or autonomy when composed — only that they are unimplemented couplings. GraSP closing B5 is architectural completeness, not proof of universal transfer.
- **Corpus is bounded and rapidly changing:** Frozen 26 July 2026; later systems could raise any row's D-level. arXiv preprints and official repositories differ in review status and stability, and repository evidence establishes only an interface surface, not mechanism quality.
- **Purpose mismatch between historical architectures (stable cognitive accounts) and modern agents (task-specific prompt/model/tool compositions):** A mechanism useful for cognitive modeling may add unnecessary engineering overhead — the authors flag this but cannot resolve it without the proposed controlled interventions.
- **The partition is not unique:** The merge/split rules are stated but the paper concedes "five is the unique partition" is *not* claimed; different source codes (or a different coder) can change the number of residual bundles.
- **Some modern evidence is thin/uneven:** DAM contributes a design framework without an evaluated algorithm; Hearsay-II maps only to D2; MIDCA's D4 precedents adapt *between trials*, not in-run — so several "depth" claims are at the weaker end of each band.

## Relevance

对研究"智能体运行时架构与认知机制迁移"方向高度相关：它把 ACT-R/Soar/BDI 等经典认知架构与 LangGraph/Letta/AutoGen/GraSP 等现代语言智能体运行时做了机制级映射，并给出 5 个可证伪的残差控制包（记忆激活-延迟-效用、类型化僵局-恢复编译、工作空间竞争-广播学习、意图-重考虑-方法权威、不确定性-资源-中断-停止），直接为"如何在 LLM agent 运行时中引入显式控制律与可组合不变量"提供了研究议程和基线清单。

## Questions for Further Exploration

- Would independent second-author recoding change the E/D distribution materially — in particular, do the D4 codes for Reflexion (textual reflection), AgeMem, and SkVM survive scrutiny, or do several drop to D2/D3 and thereby reopen closed portions of the ledger?
- For bundle B1 (activation–latency–utility), does adding a single equation-level coupling over CURATOR's value-per-byte admission actually improve *relevant recall* without inflating token cost, or does a simpler top-k selector stay non-inferior?
- Can B6's "one calibrated uncertainty object propagated through memory/planning/tools/execution/stopping" be implemented on top of AIOS/OpenAI Agents SDK without a shared state model, given that the paper identifies fragmented control ownership as the #1 structural barrier to migration?
- Is the GraSP-closes-B5 result robust beyond GraSP's evaluated domains, or does the architectural completeness mask a transfer gap that a controlled cross-domain ablation would expose?
- Does the proposed implementation order (externalize intentions/uncertainty/budgets/recovery before typed failure and admission, before adaptive memory/compiled skills) hold empirically, or does starting with skill compilation (the cheaper path) sometimes dominate because state/failure boundaries are too expensive to instrument first?
