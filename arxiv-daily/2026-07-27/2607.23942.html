03 / ASSESSMENT

Strengths & limitations

+ Strengths

  • Mechanism-level K-tuple forces apples-to-apples comparison where feature labels fail — each architecture read as an operational chain, not a feature list.
  • E/D decoupling is the sharpest insight, enforced by an evidentiary precedence rule: lineage ≠ depth, depth ≠ lineage.
  • Closes a candidate (B5 via GraSP) rather than only opening gaps — the method can falsify its own agenda.
  • Bundles are pre-registration-ready: each has a named insertion point, closest baseline, and primary falsifier.
  • Cross-bundle dependency analysis yields a defensible implementation order for engineering.

− Limitations

  • Single-coder, provisional codes — biggest validity threat; all D3/D4 scores pending second-author recoding.
  • No causal/performance evidence — cannot show the 5 bundles improve reliability when composed, only that they are unimplemented couplings.
  • Corpus bounded & fast-moving — frozen 26 Jul 2026; later systems could raise any row's D-level.
  • Purpose mismatch — mechanisms useful for cognitive modeling may add engineering overhead.
  • Partition is not unique — "five" is provisional; different source codes or a different coder change it.
  • Some modern evidence is thin — DAM has no evaluated algorithm; Hearsay-II only D2; MIDCA adapts between trials.
Overclaim risk   Table I's "Primary × 5" self-positioning is self-awarded on axes the authors define; D4 codes for Reflexion/AgeMem/SkVM rest on accepting those systems' own claimed learning loops at face value.
04 / OPEN

Questions for further exploration

Would independent second-author recoding change the E/D distribution materially — do the D4 codes for Reflexion, AgeMem, and SkVM survive scrutiny, or do several drop to D2/D3 and reopen closed portions of the ledger?

For B1, does a single equation-level coupling over CURATOR's value-per-byte admission actually improve relevant recall without inflating token cost, or does a simpler top-k selector stay non-inferior?

Can B6's "one calibrated uncertainty object propagated through memory/planning/tools/execution/stopping" be built on AIOS/OpenAI Agents SDK without a shared state model, given fragmented control ownership is the #1 structural barrier?

Is the GraSP-closes-B5 result robust beyond GraSP's evaluated domains, or does architectural completeness mask a transfer gap a cross-domain ablation would expose?

Does the proposed implementation order (externalize intentions/uncertainty/budgets/recovery first) hold empirically, or does starting with skill compilation — the cheaper path — sometimes dominate?
