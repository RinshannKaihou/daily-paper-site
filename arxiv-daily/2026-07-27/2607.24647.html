01

Methodology

Autonomous research is a search loop: a proposer generates candidate edits, a verifier scores them, a search structure records explored states. Because LLMs make generation cheap, verification is the binding constraint — so the budget is counted in evaluations, not tokens.

Four fixed search families — greedy, beam, tree (MCTS-style), evolutionary — run at matched frontier width 64, budget 500, 3 seeds across 12 AutoLab tasks, with a single Qwen3-Coder-480B completion per proposal. Search structure is the only experimental variable.

fluid search is a budget-adaptive portfolio bandit over a forest of hill-climbing chains (≤64, warm-start restricts to 16 through eval 150). At each step a UCB index picks the next idle chain; up to 32 evaluations fly asynchronously. Five optional levers import ideas from the fixed policies, each individually disable-able so the bare bandit is the ablation baseline.

Uk = ρk + w·qk + c·√( ln(n+1) / (nk+1) ) w = 1, c = ½
ρk — recent improvement rate (fraction of last 5 edits that improved the incumbent)
qk — incumbent reward, normalized to best artifact so far
nk — chain's evaluation count

  • L2Crashed-parent adoption: keep editing a crashed artifact a few steps with the error in context

Strengths & Limitations

▲ Strengths

  • Clean reframing. Efficiency (AUC) vs. outcome as orthogonal axes, backed by the r = 0.40 measurement.
  • Rigorous controls. Fixed proposer, single completion, matched width / budget / seeds isolate search structure as the single variable.
  • Principled & simple. One UCB index + five composable levers; non-trivial win (0.780 vs 0.718) reaching the oracle (0.784).
  • Honest framing. Explicitly limits scope to "the first autonomous level" of the Cao–Yang ladder; vocabulary / verifier gaps left as future work.
  • Reproducible. Code + pseudocode released.

▣ Limitations

  • Easy-verification only. All 12 tasks are systems-optimization; the costly-verification motivation is untested.
  • Homogeneous portfolio. fluid adapts allocation among hill-climbing chains, not the form of search.
  • Single proposer. Only Qwen3-Coder-480B tested; cross-scale generalization unverified.
  • No per-lever ablation. Gains could come from smuggled fixed-policy mechanisms, not adaptivity.
  • Vocabulary-gap ceiling. Plateaus suggest fluid improves within-frame efficiency but cannot escape representational limits.

Questions for Further Exploration

  1. Q1Would fluid's near-oracle performance hold with a heterogeneous portfolio (greedy / beam / tree / evolutionary chains in parallel)?
  2. Q2Does the per-task ranking of fixed structures stay stable across proposers of different scale/family?
  3. Q3What is the per-lever marginal contribution of each of fluid's five mechanisms in isolation?
  4. Q4Can the AUC-of-frontier metric extend to costly-verification domains — wet-lab, fabrication, clinical?
  5. Q5How does fluid interact with the vocabulary-gap plateau — can adaptivity delay it, or is it proposer-limited?
  6. Q6Could the oracle be strengthened to allow mid-run policy switching for a tighter upper bound?
