> **一句话总结：** 提出 SciConsolidate 框架，将科学计算任务中经过执行验证的成功/失败经验抽象为跨任务"程序性知识"（SOP），再用更强的 27B 模型把这些抽象规则"具体化"成可执行代码作为监督数据做标准 SFT；在 SciCode 上，运行时注入程序对 27B 提升 +3.85/+6.26、对 9B 几乎无效（揭示了"抽象-执行鸿沟"），而经过程序引导的具体化后，9B 学生模型在无程序部署下比无程序 SFT 对照提升 +3.89/+6.25、比原 9B 提升 +5.62/+11.25。

> **TL;DR:** SciConsolidate turns verified execution experience on SciCode into transferable procedural knowledge (SOPs) and then bridges an "abstraction–execution gap" by letting a stronger Qwen3.6-27B concretize validated procedures into executable code supervision for a Qwen3.5-9B student via standard SFT. Runtime procedure injection helps the 27B model (+3.85/+6.26 sub-step/main points) but not the 9B model; after procedure-guided concretization the 9B student, deployed procedure-free, beats a matched no-procedure SFT control by +3.89/+6.25 points and the original 9B by +5.62/+11.25 points, with a modest +1.46/+3.33 on the frozen held-out split.

## 核心贡献

- 首次将"科学计算经验固化（experience consolidation）"形式化为一个独立系统问题：把已验证的运行时经验（成功/部分成功/失败轨迹）转换为可复用的跨任务程序性知识，并转化为模型持久能力的提升，作为迈向自我进化科学助手的起点。
- 提出并实证刻画了"抽象-执行鸿沟（abstraction–execution gap）"：同一份经开发集验证、对更强 27B 模型有效的程序，对更弱的 9B 模型在运行时几乎不起作用——说明程序的"有效性"是消费者依赖的，而非文本上"看起来合理"即可。
- 设计了 SciConsolidate 完整流程：对比式失败归因 → 开发-验证门控（development-validation gate）的程序版本化筛选 → 失败先验驱动的免答案（answer-free）科学计算查询合成与均衡 → 用更强模型做"程序引导的具体化（procedure-guided concretization）"生成代码监督 → 标准、无程序 SFT。配套设置了一条"无程序教师"对照分支来隔离程序性引导本身的贡献。

## Key Contributions

- Formalizes scientific-computing experience consolidation as a distinct problem: converting verified runtime evidence (success/partial/failure rollouts) into reusable cross-task procedural knowledge and persistent model improvement, as a starting point toward self-improving scientific assistance.
- Empirically characterizes the abstraction–execution gap: the same development-validated procedure bundle that lifts the Qwen3.6-27B concretizer by +3.85/+6.26 (sub-step/main) yields essentially no aggregate main-problem gain for the Qwen3.5-9B target, showing procedure utility is consumer-dependent rather than an intrinsic property of the text.
- Proposes the SciConsolidate pipeline (contrastive failure attribution → versioned development-validation gate → failure-informed, answer-free query synthesis with balancing → procedure-guided concretization by a stronger model → standard procedure-free SFT), and isolates the value of procedural guidance via a pipeline-matched no-procedure teacher control that reuses the same source pool, budget, and construction protocol.

## Methodology

SciConsolidate is a data-centric framework that implements one evaluated pass through an "execution → abstraction → guided synthesis → learning" pathway. The task set is split into three disjoint subsets (Dtrain / Dval / Dtest), with Dtest frozen for generalization; this discipline matters because both the natural-language procedures and the synthetic data mixtures are optimized artifacts that could otherwise encode source-specific regularities.

1. Task structuring. Each task gets a descriptor vector z(x) (domain, subdomain, task type, difficulty, failure-family labels) used for stratified splitting, cross-task failure discovery, and distribution control.
2. Verified experience collection and failure attribution. The target 9B model is rolled out K times per task; executable evaluation separates success / partial / failure at task and sub-step levels. Within-task contrasts between attempts are clustered into cross-task failure families {F_l} (e.g., specification/interface, array/numerical reasoning, logic/dependency flow, knowledge/capacity gap). GLM-5.1 is used to label failure modes and families, which are then distilled/refined into procedural artifacts.
3. Validation-gated procedural knowledge synthesis. Procedures are versioned artifacts; a candidate revision is promoted only if it beats the previous version on a paired utility gate G over Dval. This makes "transfer" part of the operational definition of knowledge, not just textual plausibility.
4. Knowledge-guided, answer-free query synthesis. Because the seed pool is small and pattern-concentrated, new problem specifications, function interfaces, dependencies, and candidate executable tests are generated under z(x) and the validated failure structure, with balancing over source-problem concentration, domain/task-type shares, and failure-family coverage. No pre-existing reference answers are required.
5. Procedure-guided concretization. A stronger model MT (Qwen3.6-27B) receives concat(x, s*) and produces a concrete code solution; the student input stays procedure-free, so the training pair is (x, y^T). Only verifier-passing solutions are kept for original tasks; for synthetic tasks, locally available executable checks serve as filters and the supervised target is the final code answer (not the concretizer's reasoning trace) to limit privileged-text leakage. A no-procedure control uses identical construction but removes the procedure at teacher generation (yielding 1,985 vs 2,095 retained examples after executable filtering).
6. Training. Both 9B students are trained by full-parameter SFT for one epoch, lr 2e-6, cosine schedule with 0.03 warmup, AdamW (wd 0.1), bf16, max seq len 49,152, effective batch size 32 (8 GPUs × 4 accumulation), DeepSpeed ZeRO-2, gradient checkpointing, seed 42.

## Results & Highlights

- **Abstraction–execution gap (Table 1, aggregate, SciCode, sub-step/main %):** Runtime procedure injection improves Qwen3.6-27B by **+3.85 / +6.26** (42.60/14.99 → 46.45/21.25) but gives the Qwen3.5-9B base model **−0.30 / +0.00** (29.88/8.75 → 29.58/8.75). On the frozen held-out split the 27B model's main accuracy jumps from 3.30 to 13.33 while the 9B model barely moves.
- **Procedure-free capability consolidation (Table 3, aggregate):** Procedure-guided SFT beats the pipeline-matched no-procedure SFT control by **+3.89 / +6.25** (35.50/20.00 vs 31.61/13.75) and beats the original 9B base by **+5.62 / +11.25** (35.50/20.00 vs 29.88/8.75), all under procedure-free inference.
- **Generalization on frozen held-out (Table 3):** Guided student beats no-procedure SFT control by **+1.46 / +3.33** on the never-touched Dtest split — positive but modest, and the authors are explicit that most improvement is concentrated on the development distribution.
- **Fine-grained task-type/domain gains (Table 4, sub-step %, guided vs no-procedure SFT):** Simulation **+9.4** (35.8→45.3), Material Science **+8.6** (44.8→53.4), Math +6.1, Chemistry +5.7, Scientific calculation +3.0; the only negative bucket is Numerical method **−3.1** (32.3→29.2), flagged as a remaining bottleneck.
- **Failure-family diagnostic (Table 5, dev-train sub-step %):** Largest gain on F2 array/numerical reasoning (**+19.6**, 17.9→37.5), with F3 logic/dependency flow +6.8 and F4 knowledge/capacity +3.8; F1 specification/interface is slightly negative (−2.6), showing interface-auditing transfer is not yet stable.
- **Reintroducing procedures after SFT (Table 7):** Runtime procedures actively hurt the trained 9B students (procedure-guided SFT: −4.47/−6.25 with vs without), confirming procedures are best used as data-construction conditions rather than runtime prompts for the smaller deployed model.
- **Data composition (Table 6):** 2,095 guided SFT examples (395 original + 1,700 synthetic, 81.1% synthetic) vs 1,985 control examples (395 + 1,590, 80.1% synthetic); the 110-example yield difference is a post-generation filtering artifact, not an unmatched budget.

## Authors & Credibility

Authored by Liwei Dong (corresponding), Jiahao Zhao, and Nan Xu of XScience Lab at Wenge AI (Wenge AI / 文澜智库-affiliated). The work engages seriously with the recent (2025–2026) literature on agent skills and skill internalization (SKILL0, Skill1, SkillRL, Skill-to-LoRA, SkillsBench, MemSkill, EvolveR, etc.) and clearly positions its contribution relative to them. Code is referenced at github.com/ScienceOne-AI/SciConsolidate. The experimental protocol is unusually disciplined for this subfield: a three-way split with a frozen Dtest, a pipeline-matched no-procedure control that isolates procedural guidance from generic stronger-model distillation, and explicit acknowledgment that the development-valid split participates in selection and therefore only Dtest counts as an independent generalization estimate.

## Critical Assessment

- **Novelty:** Genuinely incremental-but-real. The framing of "experience consolidation" as a systems problem, the explicit operational definition of the abstraction–execution gap via the utility contrast U(M_T, s) vs U(M_θ, s), and the design choice of moving procedure consumption to a temporary stronger "concretizer" while keeping the student procedure-free are a coherent and non-obvious contribution beyond prior skill-internalization work (SKILL0/Skill1), which mostly starts from a pre-existing skill and optimize a skill→skill-free-policy path.
- **Rigor:** Strong on split discipline and controls — the matched no-procedure teacher branch is the right experiment and is what makes the +3.89/+6.25 claim interpretable rather than confounded with generic 27B distillation. The authors are commendably honest about effect concentration: the held-out gain is only +1.46/+3.33, and they repeatedly caveat that "aggregate" mixes in development data.
- **Weak baselines / external dependence:** A substantive red flag is heavy dependence on stronger external models — GLM-5.1 for failure labeling, Qwen3.6-27B for concretization. The "self-improving" framing is therefore partly undercut: the improving model (9B) cannot itself produce the labels or the procedures it learns from, and the paper's own Limitations section concedes a "fully autonomous self-improving system would need these roles to converge toward the improving model itself."
- **Missing ablations:** The abstraction–execution gap is demonstrated only across two model sizes of two different Qwen series (Qwen3.5-9B vs Qwen3.6-27B), so the gap could be partly a pretraining-distribution difference rather than pure capacity; the authors acknowledge a "broader scaling study and controlled procedure-complexity analysis are needed" but do not provide one. There is no ablation isolating the contribution of the validation gate itself (e.g., random-procedure vs gated-procedure), nor of the balancing step in query synthesis.
- **Reproducibility:** Good on paper — full hyperparameters, data statistics, seed 42, code link, SciCode is public. But the procedural artifacts are distilled via GLM-5.1 prompts (Appendix A.2) that are only partially reproducible, and the synthetic-query generator relies on proprietary-model judgment, so an exact replication would depend on access to those models.
- **Significance:** A solid, honestly-reported single-testbed study that establishes a plausible building block rather than a finished system. The data quirk that guided and control pools differ by 110 examples after filtering (2,095 vs 1,985) means the headline +3.89/+6.25 is "not a perfectly size-matched causal estimate" by the authors' own admission — a caveat readers should weigh.

## Strengths

- Clean conceptual contribution: the operational, consumer-dependent definition of the abstraction–execution gap is a useful lens that future skill-internalization work can build on.
- Methodologically careful: three-way split with a genuinely frozen held-out set, plus a pipeline-matched no-procedure control that does the hard work of separating "procedural guidance" from "generic stronger-model SFT."
- Intellectual honesty: limitations are itemized in detail (single testbed, one pass not multi-round, dependence on stronger external models, non-uniform transfer, final-answer-only supervision), and the paper resists overclaiming autonomous self-evolution.
- Fine-grained diagnostics (task type, domain, failure family) go beyond headline numbers and usefully locate where the method works (simulation, array/numerical families) and where it stalls (numerical-method task type, specification/interface transfer).

## Limitations

- Single scientific testbed (SciCode only); no cross-benchmark, cross-model-family, long-horizon-tool-use, or physical-experimentation evidence.
- Only one pass through the consolidation loop is evaluated; "sustained continual self-improvement" is explicitly not demonstrated.
- The abstraction–execution gap is operational, not mechanistic — two differently pretrained model sizes cannot isolate capacity as the causal driver.
- Heavy reliance on stronger external models (GLM-5.1 for labeling, Qwen3.6-27B for concretization) limits how "self" the improvement really is.
- Procedural knowledge is narrow (computational practices like interface/array/numerical/dependency-flow discipline), not scientific discovery or hypothesis generation.
- Gains are non-uniform: numerical-method reasoning and specification/interface behavior remain weak or negative; subsequent iterations risk negative interference with already-consolidated behavior.
- Final-answer-only supervision discards the concretizer's deliberative reasoning and leaves reasoning-preserving consolidation unresolved.

## Relevance

与本工作关注的方向高度相关：它正是一项"自我进化 / 经验固化"的研究，把 agent 的运行时轨迹沉淀为可复用的程序性知识并回流到模型参数，与 skill internalization、self-improving agent、记忆与技能系统这一脉工作直接对接，可作为构建长期科学计算助手的参考范式。其"开发-验证门控 + 免答案查询合成 + 强模型具体化"的数据构造流水线，对任何想把执行反馈转化为持久模型能力的研究都有借鉴价值。

## Questions for Further Exploration

- Does the abstraction–execution gap hold when capacity is varied within a single model family and pretraining recipe (e.g., Qwen3.6-7B / 14B / 27B), isolating capacity from pretraining distribution?
- What happens over multiple consolidation rounds with the updated student as the new target — does improvement compound, saturate, or suffer negative interference on already-consolidated failure families?
- Can the validation gate's contribution be isolated by comparing gated procedures against random or textual-plausibility-only procedures at matched size?
- How much of the +3.89/+6.25 guided-over-control gain survives if the guided/control pools are force-matched to exactly 1,985 examples each, removing the 110-example yield confound?
- Can the labeling and concretization roles be moved onto the improving 9B model itself (or a same-size sibling) without collapsing the abstraction–execution gap, to test the "autonomy" claim?
- Do the induced procedures transfer to other scientific-computing benchmarks (e.g., ResearchCodeBench, CFD-LLMBench, FEM-Bench) beyond SciCode?
