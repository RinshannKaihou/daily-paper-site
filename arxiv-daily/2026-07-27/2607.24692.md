> **一句话总结：** 本文揭示分布式推理管线（本地快速路径 + 远端慢速路径 + 路由/合并协调层）存在一种新的攻击面——攻击者用 Yo-Yo 式突发有效请求挤占慢速路径的共享资源（云自动扩缩容瓶颈），使良性的高精度云端预测超时被合并器丢弃，导致"精度坍塌"；在 Argoverse-HD 自动驾驶多目标跟踪仿真中，约 4000 条突发请求将慢路径 p99 延迟从 92ms 抬到 2s，使 HOTA 平均下降 7.0 分，部分稀有类别（如停车标志、卡车）损失近半精度。

> **TL;DR:** This paper introduces "accuracy collapse," a new coordination-layer attack on two-system inference pipelines (a fast local path + a slow remote path coordinated by a router and merger). By submitting shaped Yo-Yo-style bursts of valid requests that exploit cloud auto-scaling lag along the shared slow path, an attacker with no access to model weights or victim data pushes benign slow-path predictions past the merger's freshness deadline so they are discarded while the fast path keeps the service "available." On a simulated edge-cloud Argoverse-HD multi-object-tracking pipeline (YOLOX-Nano edge, YOLOX-X cloud, 250 ms SLO), ~4,000 burst requests raise benign slow-path p99 latency from 92 ms to >2 s, cutting HOTA by 7.0 points on average (and up to 18.7 points in worst-case targeted intervals), erasing nearly all cloud-assistance benefit and halving accuracy for rare classes like stop signs.

## 核心贡献

- **跨领域的分布式推理系统抽象：** 将多种"快速路径 + 慢速路径"系统（边缘-云视频分析、级联模型、拆分/早退出 DNN、带远程辅助的自主系统）统一抽象为 fast path、slow path 与一个由 router（决定何时调用慢路径）+ merger（决定是否使用慢路径结果）组成的协调层。
- **协调层攻击与"精度坍塌"概念：** 揭示该协调层是一个新的攻击面——shaped workload 攻击（如 Yo-Yo 突发）可在共享慢路径资源上制造争用（排队、自动扩缩容滞后、合并截止时间），把良性的高精度辅助预测推迟到有效窗口之外被丢弃，导致慢路径带来的精度增益消失，且攻击不需要模型权重或对受害者数据的访问。
- **延迟放大 + 应用级精度评估：** 在 COSMOS 测试床仿真中，对比突发攻击、无攻击基线与扁平高流量 DDoS 基线，量化展示突发攻击在相同平均请求速率下造成的尾延迟与"过期辅助"周期更多。
- **聚合/时序/按类别的精度退化分析：** 在 Argoverse-HD 上展示平均、不同目标视频片段、以及按类别（稀有类别如停车标志、卡车损失近半）的差异化退化，指出聚合指标会掩盖安全关键类别的灾难性退化。
- **研究议程：** 将工作负载攻击的演进定位为"可用性 → 效用（成本）→ 精度"的新阶段，并提出路由、合并、准入控制、调度与资源隔离等开放研究方向。

## Key Contributions

- A cross-domain abstraction of distributed "assisted" inference as a fast path, a slow path, and a router–merger coordination layer that decides when remote assistance is invoked and whether its result contributes to the application output.
- A new coordination-layer attack mechanism ("accuracy collapse"): an adversary that submits only valid, content/timing-controlled requests exploits contention on shared slow-path resources (cloud queues, autoscaling warmup lag, merge deadlines) to discard benign high-accuracy predictions, requiring no model weights or privileged access.
- A latency-amplification evaluation on a simulator of the NSF COSMOS testbed, showing shaped bursts push benign slow-path p99 latency from ~92 ms to several seconds (vs. a 250 ms SLO), outperforming flat high-volume DDoS at the same average rate in creating stale-assistance periods.
- An application-level accuracy evaluation on the Argoverse-HD autonomous-driving multi-object-tracking pipeline (YOLOX-Nano edge, YOLOX-X cloud, SORT + Kalman/CMC, 250 ms deadline, HOTA metric), quantifying aggregate (−7.0 HOTA), temporal (2.0–18.7 HOTA range), and per-class degradation (rare classes lose up to ~half their accuracy).
- A positioning of the attack as a new stage ("availability → utility → accuracy") in the evolution of burst-shaped workload attacks (Shrew, Yo-Yo, denial-of-wallet), plus a research agenda for resilient routing, merging, admission control, scheduling, and isolation.

## Methodology

The paper combines a conceptual abstraction with a simulation-driven evaluation in two stages.

**Threat model.** A workload-shaping adversary that interacts only through the normal request interface, submitting valid inputs (e.g., complex scenes likely to trigger slow-path assistance) as an ordinary user. It has no infrastructure control, no access to model weights, routing thresholds, or merger rules, and cannot modify other users' traffic. It may infer routing behavior through probing and observable signals (response latency, returned model id). The leverage is asymmetric: modest average request rates produce disproportionate delay and accuracy loss, aligning the attack with Yo-Yo-style bursts rather than volumetric DDoS.

**Attack mechanism.** (1) Attacker sends a bursty load of requests likely to invoke slow-path assistance; (2) the router forwards them to the shared slow path; (3) contention at shared resources (queueing + delayed scale-out) delays results beyond the freshness deadline, so the merger discards them as stale; (4) benign users lose the cloud-assistance accuracy benefit while the fast path keeps the service responsive. The attacker spaces bursts so scaled-out workers are reclaimed after cooldown, forcing each new burst to re-encounter baseline capacity and another warmup delay.

**Latency simulation (Sec. 4.1).** A two-tier simulator of the COSMOS urban video-analytics testbed. Fast path = finite multi-server edge station; slow path = multi-server FCFS cloud service whose warm workers are controlled by an autoscaler (cold-start warmup before added workers are available; cooldown before idle workers reclaimed). Benign traffic is a provisioned Poisson process with rate λ_b = N·f·p for N streams at f fps and routing probability p; compared against the shaped-burst attacker and a flat high-volume DDoS baseline, against a 250 ms SLO.

**Accuracy replay (Sec. 4.2).** Edge tier = YOLOX-Nano; cloud tier = YOLOX-X on Argoverse-HD; one frame sent to the cloud every 5–10 frames; cloud detections propagated forward with Kalman-filter motion forecasting + camera-motion compensation, then associated by the SORT tracker; a 250 ms deadline discards late cloud predictions, leaving the edge prediction as output. Reported metric is HOTA. The attack-induced completion-time trace is replayed across the whole video, across targeted intervals, and per class.

## Results & Highlights

- **Latency amplification:** In the COSMOS-based simulation, the shaped attack raised benign slow-path p99 completion time from **~92 ms (no-attack)** to **over 2,000 ms (>2 s)** with roughly **4,000 burst-shaped requests**, far exceeding the configured **250 ms SLO**, while benign mean latency also exceeded the SLO during each burst. Without attack, benign p99 stayed near 100 ms.
- **Aggregate accuracy collapse:** On the Argoverse-HD multi-object-tracking pipeline, the shaped attack reduced tracking quality by **7.0 HOTA points on average**, leaving the two-system pipeline close to the edge-only (YOLOX-Nano) baseline — erasing nearly all of the average benefit provided by cloud (YOLOX-X) assistance.
- **Temporal variation (targeted intervals):** Replaying the identical latency trace over different video intervals produced sharply varied harm — **2.0 HOTA points** in the least-damaging targets versus **18.7 HOTA points** in the most-damaging targets, a **>9× difference** in prediction-quality harm despite operationally equivalent attack executions (same load, latency, deadline-misses, autoscaling, and cost).
- **Per-class degradation:** The most-affected class (**Truck**) lost nearly half of its accuracy under the attack, and several low-frequency classes — **bicycles, motorcycles, and stop signs** — also lost substantial fractions of tracking quality, showing aggregate metrics can hide severe class-specific regressions even for operationally critical (if rare) objects.
- **Shaped vs. flat attack:** Compared with a flat high-volume DDoS baseline at the same average request rate, the shaped (Yo-Yo) attack created more stale-assistance periods and was therefore more harmful to accuracy over time, demonstrating burst shaping's disproportionate potency.

## Critical Assessment

- **Novelty:** High and well-positioned. The framing of a coordination-layer attack that converts networking contention into AI accuracy loss — explicitly extending the Shrew → Yo-Yo → denial-of-wallet lineage into a new "availability → utility → accuracy" stage — is genuinely fresh. The router/merger abstraction usefully unifies otherwise disparate pipelines (cascaded LLMs, split DNNs, edge-cloud video analytics, robot remote assistance).
- **Rigor:** Mixed. The latency simulation is a queuing/autoscaler model rather than a full system implementation, and the accuracy drop is obtained by *replaying* simulated completion-time traces over an offline Argoverse-HD pipeline rather than running YOLOX-X under actual contention. The paper is transparent about this ("replay of slow-path completion times"), and the methodology is reasonable for isolating the latency→accuracy effect, but a closed-loop end-to-end demonstration would be materially stronger.
- **Reproducibility:** Moderate-to-good. Models (YOLOX-Nano/X), dataset (Argoverse-HD), tracker (SORT), deadline (250 ms), and metric (HOTA) are all standard and named, but the COSMOS simulator, autoscaler parameters (warmup/cooldown), benign Poisson rates (λ_b = N·f·p with unspecified N, f, p), and the exact attacker request distribution are not fully specified in the body, and no code release is referenced — so reproducing the specific 92 ms → 2 s and 7.0/18.7 HOTA numbers would require assumptions.
- **Significance:** Conceptually significant for the systems-security and ML-systems communities; it identifies a realistic threat for safety-critical edge-cloud perception (autonomous driving) that current availability metrics and DDoS defenses would miss.
- **Red flags / overclaiming:** Mostly restrained. The headline "7.0 HOTA on average" is solid, but the more alarming per-class numbers (e.g., "stop signs lose nearly half") rest on a small per-class sample (0.6% frequency for stop signs/motorcycles), so per-class claims should be read as indicative rather than statistically tight. The threat model's claim that the attacker "may infer routing behavior through probing" is asserted but not demonstrated empirically. Defense is entirely deferred to the discussion — there is no evaluation of any mitigation, so the paper cannot yet say which defenses work.

## Strengths

- Identifies and cleanly names a genuinely new failure mode ("accuracy collapse") that is invisible to availability-only monitoring because the fast path keeps the service "up."
- The router/merger abstraction is general and is backed by a thoughtful cross-domain survey (Table 1) spanning vehicle perception, robot planning, mobile video analytics, and LLM routing.
- Strong latency result with the headline 92 ms → >2 s p99 amplification on a real testbed's parameters.
- The temporal-variation finding (2.0 vs. 18.7 HOTA from identical latency traces) is a sharp, non-obvious insight: attack severity depends on *which* predictions are late, not just how many — a point with direct implications for how distributed-attack potency should be measured.
- Honest about limitations (replay-based accuracy evaluation, weak-adversary assumption, no demonstrated defense) and refrains from overclaiming model-level compromise.

## Limitations

- Accuracy impact is measured via offline replay of simulated latencies over Argoverse-HD, not a live two-tier system running YOLOX-X under real contention; autoscaler and queuing dynamics are modeled, not measured end-to-end.
- Per-class degradation claims rely on very low-frequency classes (stop signs and motorcycles each ~0.6% of detections), so the reported "nearly half" losses have wide uncertainty.
- Several key simulator parameters (number of streams N, frame rate f, routing probability p, autoscaler warmup/cooldown constants, attacker request distribution) are under-specified in the paper body and no code/config is referenced.
- No defense is evaluated — admission control, priority scheduling, traffic isolation, and overprovisioning are only discussed qualitatively.
- The empirical demonstration that an attacker can actually *infer* routing behavior through probing (a load-bearing part of the threat model) is not provided.
- Evaluation is limited to one application domain (autonomous-driving perception); the abstraction's predictions for routed LLMs and robot VLA pipelines remain untested.

## Relevance

与本仓库关注的多模态/大模型推理系统与 AI 基础设施安全方向高度相关：它直接覆盖"边缘-云端两段式推理"（含路由式 LLM、级联模型）这一新兴架构，并揭示了网络层/调度层扰动如何转化为大模型推理的精度退化，对评估分布式推理管线的鲁棒性与可信赖性具有直接参考价值。

## Questions for Further Exploration

- How does accuracy collapse manifest in routed/cascaded LLM pipelines (e.g., RouteLLM, FrugalGPT, Hybrid-LLM), where the "merger" picks one of two text answers rather than fusing detections — does latency-driven fallback to the SLM measurably degrade answer quality on hard queries?
- Which concrete defense (admission control, per-tenant traffic isolation, slow-path priority scheduling, predictive autoscaling, or deadline-aware merge buffers) most cheaply bounds the worst-case HOTA loss, and by how much in simulation?
- Can the attack be detected online without ground-truth labels, using only observable signals like slow-path discard rate, p99 latency, or autoscaler churn — and what is the detection latency vs. the burst duration?
- Does the temporal-variation effect (2.0 vs. 18.7 HOTA from identical traces) generalize beyond Argoverse-HD, and can it be predicted from input difficulty features available at the router?
- How does the attack interact with split/early-exit DNNs and on-device–edge–cloud continua where the merger semantics and freshness budgets differ from object tracking?
