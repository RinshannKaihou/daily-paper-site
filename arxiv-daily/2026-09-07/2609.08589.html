Why this matters

Agent frameworks already consume model-emitted stop signals — this quantifies that control channel failing, and the task-success cost of trusting it.

⚠ Critical edge

“Who reports” hinges partly on a parser judgment call — gpt-6-astra scores 0.0% under the strict parser but 100.0% mid-task after envelope-stripping.

Methodology — two instruments

Score the report, never trust the reporter

1 · τ²-bench + a reporting duty. One instruction block obliges every customer-facing reply to end with exactly one lifecycle tag — NEEDS_INFO / READY / POST_OBS / COMPLETED. The correct tag is derived mechanically by replaying the conversation in a fresh environment before the model's tag is read, so scoring never uses the model's own claim as truth.

2 · StageIF, a controlled testbed. 12 scripted two-tool scenarios × 5 checkpoints (four duty-active, one duty-inactive where a pure tool call is correct), with gold answers frozen by a runtime-state oracle. A deterministic parser assigns exactly one failure code per checkpoint — divergence (acting instead of reporting) > omission > malformed > wrong value — feeding end-to-end adherence θ and conditional validity φ.

3 · Bounded interventions + a rollout. Gold injection, constant tag, trailing reminder, thinking-mode A/B; a tool-withdrawal/delegation probe; and a live termination-configuration rollout. 50,400 checkpoint positions across 7 deployments, scenario-clustered bootstrap with exact sign-flip tests and a pooled GEE replication.

Evidence discipline: corruption gates, matched negative controls, hash-frozen scenario contracts, disclosed exclusions (never imputed), an explicit evidence label on every result, and a 112M-token compute report. Artifact release still pending at submission.

The pattern inverts across generations: the newest models (gemini-3.8-flash, gpt-6-astra, claude-opus-5) hold 74–100% mid-task but turn conservative at the finish line — 48–64%, every wrong value naming an earlier stage. Last two rows read after envelope-stripping.

  • No tested patch closes the gap. Gold injection covers at most one sixth of it; a trailing reminder's best gain is +9.3 points vs 29–89-point gaps; a constant tag can even hurt (−22.0).
  • Context drift, not task change. Withdrawing a needed tool and delegating the unfinished step lifts false completion from 6.2% to 64.4% while task truth stays fixed.
  • Operational cost. Termination driven by marker reports completes 13.0 fewer tasks per hundred than a no-tool-call config (CI +7.1 to +19.4); 22.7% of marker runs stop on a missing marker.
  • Failure shape differs by setting. On τ²-bench, 82–90% of mid-task errors are well-formed but name an already-passed stage; on StageIF the drop is driven by omission and tool-call-instead-of-report; after completion, false alarms reach 63.3–100%.

Strengths

  • Separates task success from protocol adherence — a task can succeed with wrong reports and fail with correct ones.
  • Oracle-before-output scoring is a clean, copyable instrument for any agent evaluation.
  • The four-layer failure taxonomy turns a vague “models are unreliable” claim into measurable per-layer rates.
  • Honest evidence labeling, disclosed exclusions, explicit confounding caveats, and a refusal to rank vendors.
  • English + second-FSM replication and the operational termination experiment give internal and external credibility.

Limitations

  • Stage and trajectory position are construct-confounded; the “stage pattern” is descriptive and no intervention isolates a mechanism.
  • StageIF is 12 short scripted two-tool tasks — coding agents and long-horizon loops untested; 50,400 positions are repeated measures over 12 clusters.
  • Deployments are point-in-time API bundles (rolling aliases, silent endpoint changes) — measurements can't be pinned to weights.
  • Headline numbers depend on the strict-vs-stripped parser regime; some subgroup analyses rest on partial, heterogeneous lanes.
  • No mitigation proposed beyond “don't trust the report alone” — repair is left to future work.

Questions for further exploration

  1. Does lost-mid-task persist in long-horizon coding or research agents — hundreds of tool calls — or only in short scripted tasks?
  2. Can a runtime-owned state machine fully replace the model-emitted signal, and at what accuracy cost when stage is derived from tool-event traces alone?
  3. Is the collapse a prospective-memory failure or a mis-estimated posterior over task state — could an obligation-activation head close what prompting cannot?
  4. Are premature COMPLETED claims contagious across agent hand-offs in multi-agent delegation settings?
  5. Would calibrating runtime trust — k consistent reports, or an independent verifier before stopping — recover the 13-point task-success loss?
