01 · MethodologyThe alternating loop, two phases per round

Explicit textual state is treated as an intermediate experience representation — fast to edit, structured enough to feed slow parametric consolidation.

Phase I — State evolution · validation-gated

The deployed (state, policy) pair accumulates trajectories, frozen into a reflection batch. Cross-trajectory reflection extracts recurring procedures and failure modes — not per-example fixes — into candidate edits of the textual state. An edit is accepted only if it improves held-out validation under the current policy.

Phase II — Selective policy consolidation

  1. Transition-aware selection. The frozen policy runs each instance three ways — state-free r⁰, previous state r⁻, updated state r⁺ — labeling experience newly useful (0→1), persistently useful (1→1), regressive (1→0), or inactive (0→0). Only the first two are distilled (weights 1 and α).
  2. Token attribution. Per-token Jensen–Shannon divergence between state-conditioned and state-free branches localizes the decisions the state actually causes.
  3. Commit gate. A state-free student trains with GRPO reward + weighted KL toward the privileged state-conditioned teacher branch — committed only if state-free validation improves.

Setup — Qwen3.5-4B student · fixed Qwen3.5-27B OPD teacher · Ascend 910B3 NPUs · 5 evolution rounds, 2 accepted (rounds 1 & 4)

03 · StrengthsWhat holds up

  • Clean framing — textual state as an intermediate representation between raw trajectories and parametric competence, with fast/slow timescales made concrete.
  • Two-sided validation gates (state edits and policy commits) give regression safety most self-evolution pipelines lack.
  • Teacher-capacity control rules out "gains from a bigger teacher": state-free 27B distillation lands below base (56.29 < 58.14).
  • Residual-state experiment demonstrates the funnel promise — consolidated guidance removable with zero loss — rather than merely arguing for it.
  • Growing compatibility gap (0.8 → 2.2 pts) is direct evidence for the central co-evolution thesis.

04 · LimitationsWhat to watch

  • Task assumptions — needs repeated, related tasks with informative environment feedback; one-shot or subjective domains would need signals not built here.
  • Compute-heavy — three-condition rollouts per instance per round, plus GRPO per accepted consolidation; async scheduling adds staleness.
  • Narrow evidence — single scale (4B / 27B), one deep-dive benchmark (SearchQA); ALFWorld / WebShop budgets uncontrolled.
  • No statistics — single runs, no significance tests, and only two accepted consolidation events observed in five rounds.

05 · Open questionsWhere this goes next

  1. Convergence — does the textual state shrink toward a stable minimal core, and does the 2.2-pt compatibility gap keep growing or plateau?
  2. Sensitivity — how do α and λdistill shape results, and can transition credit be isolated from plain success filtering?
  3. Self-taught — a 4B teacher actually hurt (57.57%); what teacher capacity is truly necessary?
  1. Robustness — do the +0.5 (SearchQA) and +1.4 (average) margins survive multiple seeds and compute-matched budgets?
  2. Generality — does the loop extend to sparse / subjective feedback via learned verifiers, and to the coding setting claimed in the conclusion but absent from the experiments?
