> **一句话总结：** SE-GoS 在不训练参数、不改检索代码、不编辑任何 SKILL.md 的前提下，用执行轨迹对技能检索图做三类离线更新（拓扑诱导/剪枝、边权强化、描述文本梯度优化），在 SkillsBench（87 任务、1000 技能）上把静态 GoS 的任务奖励从 52.4% 提升到 59.4%（+7.0 点），同时输入 token 比"全量加载"省约三分之一，并在不相交的留出任务上保持 +5.4 点的迁移增益。

> **TL;DR:** As skill libraries scale to ~1,000 entries, retrieval — not skill use — becomes the bottleneck. SE-GoS takes the static Graph-of-Skills (GoS) retrieval substrate and evolves it offline from execution traces via three training-free updates (topology induction/pruning, Hebbian edge-weight reinforcement, single-round ProTeGi-style description rewriting), leaving the PPR retrieval pipeline untouched. On SkillsBench (87 tasks, 1,000 skills) with deepseek-v4-flash-0731, one evolution round lifts reward from 52.4% (static GoS) to 59.4% (+7.0 pts, vs SkillDAG's 55.3% and Vanilla full-loading's 46.2%) while cutting input tokens from 5.06M to 3.45M per attempt (−32% vs full loading); the evolved graph transfers to a disjoint 37-task held-out split at +5.4 pts over static GoS — though the authors themselves flag that this held-out gain sits inside their ±6–7-point noise band, and repeating evolution past round 2 overfits (59.8% → 54.0%).

## 核心贡献

- **指出并解决静态技能图的瓶颈**：GoS/SkillDAG 等图式技能检索的图结构一旦建好就不再更新；本文观察到每次执行轨迹其实已经免费记录了"哪些技能被检索、哪些被真正使用、任务是否成功"，这些信号足以修复图的错误依赖与缺失关系。
- **三个互补的免训练更新算子**：(1) 拓扑更新——从成功轨迹的"检索→使用"共现诱导 workflow 边、从有序使用+I/O schema 重合（ζ=0.6）认证 dependency 边、从失败共现诱导 avoid 边（刻意不诱导 GoS 的 alternative 关系，因为可替换性是观测轨迹无法证明的反事实命题），并对"被检索≥2 次却从未被使用"的节点减半其入边权重（软剪枝）；(2) 边权更新——Hebbian 式强化 `w ← w + η·r_t`（η=0.1），只对成功轨迹中真正被使用的技能的入边加权；(3) 节点更新——对"被使用但排名靠后（>nrank=3）且任务失败（r<0.9）"的技能，用单轮 textual-gradient（改编自 ProTeGi）优化检索面向的描述，候选描述离线重放检索来挑选，附带 no-eviction 防护。
- **"LLM 先验无关"的结构来源**：冷启动图是纯确定性的 token 重叠相似图（k=1，1000 节点 863 条语义边），不需要嵌入服务，也不需要 LLM 判断技能间关系——与 SkillDAG（约 200 次 LLM 调用冷启动）形成本质区别；结构完全由执行的计数与算术供给。
- **不动检索管线的演化机制**：PPR 的转移算子直接读边权，重连/重加权图即可改变检索结果，检索代码保持固定消费者；每次更新可审计、可回滚，边权成为跨 agent 共享的"成功执行压缩记录"。
- **系统性评估**：全量基准（对照 Vanilla/Vector/静态 GoS/SkillDAG）、2^3 全因子消融、不相交留出集、多轮演化曲线、检索接口消融，并显式标定噪声带（87 任务配对标准误约 3–3.6 点，判读带宽 ±6–7 点）。

## Key Contributions

- Identifies the static-graph bottleneck of structural skill retrieval (a limitation GoS itself acknowledges) and shows the repair signal — which skills were retrieved, which were used, whether the task succeeded — is already recorded for free in every trial.
- Proposes SE-GoS: three complementary, training-free, offline updates over the retrieval substrate — topology induction (workflow/dependency/avoid edges, never the counterfactual "alternative" relation) plus soft pruning of never-used heads; edge-weight reinforcement toward skills actually used on rewarded trials; and single-round, skill-local textual-gradient description optimization for used-but-poorly-ranked skills.
- Replaces the LLM-supplied prior over skill relatedness with execution evidence: the cold-start graph is a deterministic signature-token-overlap similarity graph requiring no embedding service and no LLM pass, unlike GoS's typed graph (LLM relation validator) or SkillDAG's pair classifier (~200 LLM calls).
- Explains why editing the graph suffices: Personalized PageRank reads edge weights directly, so re-wiring/re-weighting the graph changes retrieval while the pipeline stays a fixed consumer — no retraining, no re-indexing, no edits to any SKILL.md.
- Deploys unusually careful measurement discipline for this genre: an explicit noise floor (±6–7-point band from paired SEs over 87 task means), a full 2^3 factorial ablation, a disjoint held-out split separating transfer from memorization, a multi-round overfitting curve, a retrieval-interface ablation, and a byte-level benchmark-fidelity audit against upstream SkillsBench v1.1.

## Methodology

SE-GoS inherits the GoS retrieval procedure unchanged and only evolves the graph it reads. Each execution trial yields a trace `T_t = (q_t, r_t, B_t, U_t, tokens_t)` — query, verifier reward, retrieved bundle, and the used-skill set extracted from tool-call source paths. Evolution is a two-phase offline procedure run once per window.

**Cold-start substrate.** A deterministic semantic-only similarity graph over the official 1,000-skill library: each skill linked by signature-token overlap (k=1, 863 semantic edges), no LLM pass, no embedding service. The authors verify retrieval-equivalence with GoS's embedding-kNN base on the 87 task queries (hit@5 = 70/73 = 0.959 and mean best rank 1.19 for both; max degree 141 vs 484, so PPR is less prone to hub collapse). Retrieval itself uses lexical-only seeding (ξ=0 — justified by GoS's own ablation showing the lexical channel is the dominant contributor), reverse-aware typed diffusion via Personalized PageRank (restart α=0.2), and budgeted rerank/hydration (top-N=5, seed-K=4, 1,800-char per-skill / 9,000-char global budget).

**Update 1 — Topology.** (a) Induction: a retrieved seed `u` and a different used skill `v` co-occurring on a successful trial creates a workflow edge with weight `min(0.9, 0.6 + 0.05(c_uv − 1))` (frequency-capped); ordered usage matching GoS's I/O-schema rule (overlap ≥ ζ=0.6) certifies a dependency edge; pairs failing together ≥ θ_avoid=2 times and never succeeding get a zero-weight avoid edge consumed only at bundle composition. (b) Pruning: a skill retrieved ≥ θ_obs=2 times but never used has all incoming semantic edges halved (×0.5), with below-floor edges removed.

**Update 2 — Edge weights.** Hebbian reinforcement: for every positive-reward trial and each used skill `v`, every edge `u→v` gains `η·r_t` (η=0.1). Failed trials contribute no credit; because PPR reads weights directly, this shifts future retrieval without touching scoring code.

**Update 3 — Node descriptions.** For skills used on failed trials (r < r_succ=0.9) but ranked worse than nrank=3 in the bundle: one round of ProTeGi-style textual gradient descent — an LLM critic critiques why the description fails to match the query, an editor revises it (≤50 tokens of edits), p=2 paraphrase variants are generated, and the best candidate is selected by offline replay of the actual retrieval (no agent runs). A no-eviction guard (on by default) rejects rewrites that would push a used skill out of the top-K on any training query. Cost is O(|Q_s|·(1+p)) LLM calls per affected skill, independent of library size.

**Protocol.** One evolution round: static GoS runs all 87 SkillsBench tasks, traces are collected, the three updates apply once in dependency order (topology → weights → node), and all tasks are re-measured on the evolved graph (SkillDAG's deployment-utility convention). A held-out variant evolves on 50 stratified training tasks and tests on the disjoint 37. Agent: deepseek-v4-flash-0731 via tcodex, two attempts per task, up to 8 concurrent Docker trials; cross-backbone context on minimax-m2.7 and gpt-5.2-codex.

## Results & Highlights

- **Main benchmark (SkillsBench, 87 tasks, n=174 scored attempts, deepseek-v4-flash-0731):** one evolution round lifts reward from 52.4% (static GoS) to 59.4% (+7.0 pts), beating SkillDAG at 55.3% (+4.1 over it), Vanilla full-loading at 46.2%, and Vector retrieval at 38.7%. Input tokens drop from 5.06M (Vanilla) to 3.45M per attempt (−32%, "approximately one-third" per the abstract) — close to the vector-compression regime (3.11M) at a far higher reward.
- **Held-out transfer (evolve on 50 tasks, test on disjoint 37, n=74):** SE-GoS reaches 58.3% vs 52.9% for static GoS (+5.4 pts) with tokens essentially unchanged (3.30M → 3.19M) — the paper itself notes this gain sits *inside* the ±6–7-point noise band, so the authors claim direction, not resolved magnitude.
- **Noise calibration:** paired standard error over the 87 task means is ~3–3.6 reward points, so all comparisons are read against a ±6–7-point (two-SE) band; only the full method (+7.0) and the edge-containing pairwise cells (+6.4, +6.7) reach or exceed the band edge.
- **2^3 factorial ablation (n=174 per cell):** single levers — +Topology 54.1% (+1.7), +Edge 57.3% (+4.9), +Node 53.6% (+1.2); pairwise best Edge+Node 59.1%, Topology+Edge 58.8%; full method 59.4% is the best cell. Main effects: edge +4.7, topology +1.4, node +1.3; leave-one-out confirms edge weights carry the gain (−3.6 when removed, vs −0.6 node, −0.3 topology). All single-lever gains are inside the noise band.
- **Multi-round evolution (Table 4):** reward is 52.4 (static) → 59.4 (round 1) → 59.8 (round 2, flat) → 54.0 (round 3, overfit) as induced edges grow 863 → 990 → 1,375 → 1,502 — supporting one-shot deployment rather than a training loop.
- **Cross-backbone (SkillsBench):** minimax-m2.7: SE-GoS 28.5% vs static GoS 18.7% (+9.8 pts) vs SkillDAG 27.3%; gpt-5.2-codex: SE-GoS 38.1% vs GoS 34.4% (+3.7 pts) vs SkillDAG 36.6% — gains vary across model families but the ordering is stable.
- **ALFWorld (dev split):** deepseek-v4-flash-0731 SE-GoS 91.2% vs GoS 88.1% and minimax-m2.7 68.5% vs GoS 54.3%; gpt-5.2-codex is saturated (93.6% for all graph rows), so ALFWorld serves as a sanity check, not a discriminative setting.
- **Interface ablation (same evolved graph, same ranking):** fused bundle 0.569 vs SkillDAG-style three-channel output 0.572 pooled reward — a +1.0 pp paired difference with 3.4 pp SE, i.e., no measurable presentation effect at this scale.

## Critical Assessment

- **Novelty:** moderate but real. The individual ingredients (PPR retrieval, Hebbian weight updates, ProTeGi description editing, trace mining) are all known; the contribution is the composition and the "LLM-prior-free structure" axis — the cleanest separation from SkillDAG, whose cold start costs ~200 LLM calls. The deliberate refusal to induce "alternative" edges because interchangeability is counterfactual is a thoughtful epistemic boundary.
- **Rigor:** above average for this genre, but the headline is fragile under the authors' own calibration. The +7.0 full-benchmark gain barely clears the ±6–7-point band, the held-out +5.4 is admitted to be inside it, and every single-lever ablation gain (+1.2 to +4.9) is unresolved against noise — meaning the paper can credibly claim "evolution helps, edge weights most" but not the precise magnitudes. With only 87 tasks (37 held-out), one more noisy run could reorder several cells.
- **Baseline construction caveat:** the "+7.0 over static GoS" is measured over a deliberately weakened substrate — a k=1 semantic-only graph (863 edges) with lexical-only seeding, stripped of GoS's typed {dep, wf, sem, alt} edges and LLM validation. This is well-motivated (it isolates evolution from LLM prior) but means the comparison is not against GoS at its published full configuration; the quoted Vanilla/Vector/GoS rows in the minimax and gpt-5.2-codex blocks come from the GoS paper, mixing quoted and measured numbers within one table.
- **Untested machinery:** the avoid edges — one of the three advertised relation types — are effectively never exercised: the induced avoid set is empty on the k=1 full-benchmark traces and contains a single edge on the denser k=8 cell. Likewise the confidence-weighted interpolation (Eq. 14) is "retained purely as a deployment safeguard" and never evaluated, and the SkillDAG interface comparison runs with a near-empty conflicts channel, so it mostly tests presentation, as the authors concede.
- **Reproducibility:** strong — stdlib-free-of-training, deterministic cold start, hyperparameters tabulated (α=0.2, η=0.1, θ_obs=2, θ_avoid=2, nrank=3, p=2), algorithms spelled out in pseudocode, split file named (evo_data/split.json), and a benchmark-fidelity audit. The main reproducibility hazards are the tcodex/Docker harness complexity and dependence on proprietary backbone models.
- **Significance / red flags:** no outright red flags — the paper is unusually candid about its own noise band and overfitting curve. The biggest overclaim risk is the "self-evolving" framing: what is delivered is a one-shot offline batch update (rounds ≥3 hurt), not continual learning, and all headline gains come from a single flash-tier backbone on a single 87-task benchmark at one library scale (1,000 skills); the 200/500/2,000-skill scales are explicitly untested.

## Strengths

- Genuinely training-free and deployment-light: no embedding service, no LLM cold-start pass, no inference-time overhead, no edits to skill content or retrieval code; every delta is interpretable and reversible.
- Clean attribution design: the LLM-prior-free structural channel is what makes the 2^3 factorial meaningful — the gain cannot be confounded with an LLM prior the baseline would already contain.
- Honest statistics: the noise band, the held-out split, and the multi-round overfitting curve are exactly the experiments most papers in this area skip.
- Practical economics: the −32% input-token reduction versus full loading arrives together with the best reward, and the evolved graph is a shareable, auditable artifact across agents reading the same library.
- The benchmark-fidelity audit (byte-identical verifiers and instructions vs upstream) rules out silent task weakening, a common failure mode of agent-benchmark reproduction.

## Limitations

- Single-round headline: repeating the update plateaus at round 2 (59.8%) and overfits by round 3 (54.0%), so evolution is a one-shot deployment step, not a learning loop; finer-grained rewards and longer horizons are uncharacterized.
- Small evaluation surface: 87 SkillsBench tasks (37 held-out) at one library scale (1,000 skills) on three backbones, two of which saturate ALFWorld; no claims extend to other backbones or the 200/500/2,000-skill scales.
- Used-set extraction depends on matching hydrated skill source paths inside tool calls; indirect skill use can undercount execution evidence, which feeds all three updates.
- Avoid edges and the confidence-weighted interpolation are designed but essentially unexercised in the reported results (empty avoid set on the main substrate).
- Most component-level gains, and the held-out +5.4, sit inside the authors' own ±6–7-point noise band — the direction is supported, the magnitudes are not resolved.

## Relevance

对"LLM Agent 技能/工具检索规模化"这一方向高度相关：它回答了当技能库涨到上千条时，如何用执行反馈免训练地演化检索图（PPR 边权+拓扑+描述），同时降 token 成本。其"经验应该沉淀在检索基础设施而非模型或技能内容里"的论点，对 agent 记忆/技能库架构设计有直接参考价值。

## Questions for Further Exploration

- Would per-domain or per-task-cluster evolution windows (instead of one global round) prevent the round-3 overfitting and enable continual deployment?
- Can the "alternative" relation be recovered without an LLM prior if traces logged step-ordered skill use (abandoned-attempt evidence), as the paper hypothesizes?
- How do the gains behave at 2,000+ skills, where hub collapse and lexical-seed sparsity stress the token-overlap substrate far more?
- Does execution-derived structure compose with, rather than replace, GoS's typed LLM prior — e.g., initializing from the typed graph and letting traces re-weight it?
- Since the interface ablation shows the binding constraint sits downstream of selection once used skills are reachable, what is the failure-mode breakdown of the remaining ~40% of SkillsBench attempts?
