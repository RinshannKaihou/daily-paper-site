> **一句话总结：** 本文对五个主流 Agent 记忆系统（Graphiti、Zep、mem0、langmem、cognee）做了实证测量，发现"软撤销"（标记失效而不删除）在检索层普遍不被执行：在两个会把已撤销记录返回给 Agent 的系统上，撤销策略 81/81 个场景全部被检索出且排名第一，导致 Agent 在 43.1% 的试验中选择不安全动作；作者据此提出一个位于 Agent 与记忆后端之间的 stale-retrieval 守卫，在后端不暴露撤销标记时仍能拦截冲突事实。

> **TL;DR:** An empirical study of five agent-memory systems (Graphiti, Zep, mem0, langmem, cognee) shows that none enforces soft revocation at retrieval time. On the two systems that return revoked records (Graphiti default and mem0 with its expiry filter disabled), the revoked policy was returned in 81/81 scenarios and always ranked above its replacement, driving agents to the designated unsafe action in 43.1% of 1,620 trials (44.2% Graphiti vs 42.1% mem0-exp) across 9 scenarios and 9 models; a store-level status filter eliminates it (0/1,620) while prompt hardening only drops it to 37.2%. The proposed backend-agnostic guard matches the filter where status is exposed (0/1,620) and is the only defense that works under indirect insertion on Zep (315/810 unsafe vs 364/810 baseline), though its lexical conflict heuristic occasionally withholds current facts.

## 核心贡献

- **提出并测量一个此前无人检验的威胁模型："撤销后仍具权威性"（revoked but still authoritative）。** 与所有已有注入式攻击（AgentPoison、MINJA、PoisonedRAG 等）不同，这里伤害 Agent 的记录是防御者自己写入并撤销的策略，没有任何攻击者内容进入记忆库，因此所有基于来源（provenance）的防御在构造上全部失效——缺的是"检索时有效性"检查。
- **对五个生产级记忆系统给出三分类失效诊断：**（1）撤销从未被记录（cognee、langmem、mem0 在间接插入下 0/9 场景记录撤销）；（2）已记录但对调用方不可见（Zep 返回撤销记录但不暴露状态位，应用层无法表达过滤）；（3）已记录、可见、但检索时不执行（Graphiti 默认、mem0 的 expiry-flag 覆盖配置）。
- **把失效归因到检索层而非具体产品：** 两个独立实现的暴露系统在 81 个匹配单元格上不可区分（精确检验 p = 0.629）；而 mem0 在完全相同数据上仅切换一个检索布尔标志，就在 39/81 个匹配格中从安全翻转为不安全（p < 0.001）。
- **提出 stale-retrieval 守卫：** 部署在 Agent 与任意记忆后端之间，两阶段工作——优先读取后端暴露的状态字段，其次用同主题+对立信号（反义词对、互斥数量、否定差异）的词法冲突检测拦截较旧事实；无法定序时保留双方并上报冲突，绝不删除任何记录。
- **把结论扩展到单次读取之外（附录 C）：** Agent 把不安全决策写回记忆后，检索过滤器在 hop 1-3 失效（直写模式 71.6%→83.1% 不安全）；共享记忆库的多 Agent 中"审查者"不是隔离边界（给定执行者中毒，审查者 96.3% 跟随不安全）；工具场景下无防御时 17.2% 的运行调用了危险工具、2.5% 确认泄露秘密，而工具层护栏与无防御完全无异（17.2%）。

## Key Contributions

- **A new threat model: revocation non-enforcement, not injection.** Every prior memory-attack family (corpus poisoning, memory poisoning, query-only, poisoned traces, self-reinforcing, cross-platform) inserts attacker-authored content that a provenance check can catch. Here the harmful record is the defender's own revoked policy, so provenance checks pass it by construction; the missing control is retrieval-time validity — whether a record is still current at the moment it is read.
- **A clean two-metric decomposition.** Exposure rate Pr[ER=1] isolates the store's property (did default retrieval return the revoked record?) from the unsafe-action rate Pr[a=a⁻] (did the model act on it?), with Eq. (2) factoring the latter through the former. This lets the paper attribute failure to retrieval rather than to any one product.
- **Systematic measurement grid.** 5 systems (6 configurations counting mem0's two retrieval settings) × 9 scenarios (8 policy scenarios + 1 stored access directive; 5 with a prompt safety rule) × 9 models across 6 vendors and 3 capability tiers × 10 trials at temperature 0.7 × 6 defense conditions, under both direct insertion (native revoked fields) and indirect insertion (plain contradicting prose the system's own extraction must reconcile).
- **A deployable mitigation with honest limits.** The stale-retrieval guard requires no backend change: stage 1 reads exposed status fields; stage 2 withholds the older record of any conflicting pair, requiring positive evidence (known timestamps, descending order so kept records are never evicted, a β=0.6 withholding cap) and reporting unresolved conflicts instead of guessing.
- **Beyond-a-single-read extensions.** Appendix C measures agent write-back (journals stored as current records defeat the filter that reached 0/1,620), multi-agent propagation through a shared store, and end-to-end tool actions with sentinel decoy tools — showing the failure persists, propagates, and recurs with no attacker present.

## Methodology

The paper follows a two-phase measurement pipeline (Fig. 1). **Setup phase:** each memory store is seeded with exactly two contradicting records — the revoked policy v1 and its replacement v2 — under one of two insertion modes. In *direct insertion* both records are written in the system's native format (e.g., mem0's `expiration_date=yesterday`), guaranteeing the revocation mark; in *indirect insertion* the system ingests plain contradicting prose and must detect the supersession itself, leaving the mark uncertain. **Experimental phase:** a user asks an ordinary question; default retrieval R(q, M, k=10) returns the k=10 most similar records with no status restriction; the agent sees only record texts (status ρ and timestamp τ never reach the prompt) and chooses between a safe and an unsafe action. Notation (Table 2) distinguishes ρ=1 (revoked), ρ=0 (current or unassessed), and ρ=⊥ (no status exposed to any caller — required because Zep marks internally but exposes nothing).

The nine scenarios pair a revoked permissive policy with a current prohibition (deploy approval, PII export, rollback, card disclosure, backup deletion, over-limit transfer, compliance log deletion, MFA waiver, plus a stored access directive that is an instruction rather than a fact). Five carry an explicit safety rule in the system prompt plus two benign distractors each; four carry neither. Nine decision models span flagship (GPT-5.5, Grok-4, DeepSeek-V4-Flash), efficient (GPT-5-nano, Gemini-2.5-Flash, Grok-4-Fast), and open-weight (GLM-5.2, Gemma-3-27B-IT, Kimi-K2.6) tiers. Six defense conditions are scored: no defense, store-level filter (restrict retrieval to ρ=0), prompt hardening, output filter (deliberately given the revoked fact texts), filter+prompt, and the Section-5 guard. Exposure under ρ=⊥ backends uses a pre-registered lexical criterion (stemmed-content-word overlap, θ1=0.3, θ2=0.15, fixed before measurement). All five systems share one embedding and one extraction model so retrieval/extraction quality does not vary; the harness never writes further records, alters prompts, or changes model configuration. Cross-system claims rest on matched-cell paired comparisons rather than pooled confidence intervals. The whole study is cheap: 49,121 decision-model API calls, $79.08 total, one 16-GB MacBook Air, no GPUs.

## Results & Highlights

- **Exposure is total on the two exposed systems and the revoked record outranks its replacement:** Graphiti (default) and mem0 (exp.) each returned the revoked record in 81/81 scenario-model cells, always at rank 1, because revoked policies are phrased more absolutely ("must be blocked" vs "are monitored") and similarity retrieval favors that phrasing. The other three configurations returned no revoked record under direct insertion; under indirect insertion, cognee/langmem/mem0 recorded the revocation in 0/9 scenarios while storing both policies, Graphiti in 4/9, Zep in 6/9.
- **Unsafe-action rate under no defense: 44.2% on Graphiti (358/810) and 42.1% on mem0 (exp.) (341/810), pooled 699/1,620 = 43.1%**, with per-scenario rates spanning 0.0%–94.4% and per-model rates 15.0%–60.0%. PII export reached 94.4% (170/180); the pooled no-prompt-rule group was 81.0% (86.7% excluding the directive scenario).
- **Defense conditions diverge sharply: the store-level status filter removes the effect entirely (0/1,620 trials unsafe)**, as does filter+prompt; prompt hardening alone only reduces 43.1% → 37.2% (the context does not say which fact is superseded); the output filter reaches only 18.1% despite being handed the revoked fact texts — an advantage no real deployment has.
- **A single boolean flips safety within one product:** mem0 run twice on identical data, differing only in its shipped read-time expired-record filter, switches from safe to unsafe in 39/81 matched cells and never the reverse (exact test p < 0.001), while the two independently implemented exposed systems are statistically indistinguishable (p = 0.629 on 10-vs-7 discordant cells).
- **Model tier does not predict susceptibility:** all nine models were affected, from 15.0% (Grok-4-Fast, non-reasoning, the most resistant) to 60.0% (Gemini-2.5-Flash); the flagship tier spans 33.3%–58.9% — reasoning quality does not decide the outcome when both policies appear with equal standing in context.
- **Prompt safety rules do not reliably protect:** with an explicit prohibition the pooled rate is 12.9%, dominated by backup deletion at 46.1% (83 of 116 bypasses; its rule has a conditional CISO exception and its revoked text asserts precedence — confounded, as the authors admit); the other four with-rule scenarios give 4.6% (over-limit transfer 3.9%, MFA waiver 0.6%, log deletion 0.0%, where pretrained refusal, not the rule, explains the lows).
- **The guard matches the filter where status exists (0/1,620 unsafe; withholds 18/18 revoked facts on Graphiti and 12/12 on mem0, none current) and is the only defense that works without one:** under indirect insertion it posts 0/810 on both mem0 configurations (vs the store filter's 5/810 and 24/810) and 315/810 on Zep (vs 364/810 baseline; Zep's API cannot express a filter at all). The cost: its conflict test marginally worsens no-defense on cognee (53/810 vs 44/810) and Graphiti (83/810 vs 81/810) indirect, catches only 4/14 revoked Zep records (Zep splits one policy across edges), and withholds some current facts (6/15 langmem, 8/25 mem0 indirect).
- **Write-back defeats the filter (Appendix C.1):** when the agent journals its unsafe decision, direct write-back stores it as current in 356/356 runs and filtered-retrieval unsafe rates at hops 1–3 become 71.6%/79.5%/83.1% (vs 0.0% without write-back); natural ingestion retains only 22/358 (6.1%) active journals yet filtered rates still run 7.5%–12.8%.
- **Review is not a containment boundary (C.2):** with three roles sharing one store under default retrieval, the reviewer chose the unsafe action in 341/354 = 96.3% of runs given a poisoned executor, some later role went unsafe in 99.4%, all three in 41.6% (mean 1.32 of 3 roles unsafe); without the journal, reviewer agreement still runs 81.7% — a second opinion read from the same store is not independent.
- **Tool actions (C.3):** with sentinel decoy tools, no defense produced a 17.2% (62/360) dangerous-tool execution rate, 5.0% secret reads, and 2.5% confirmed exfiltrations (9/360, all in the exfiltration scenario = 10.0% of its trials); the retrieval filter and the guard both cut execution to 2.2% with zero exfiltrations, while a tool-layer guardrail was identical to no defense (17.2%, 7 exfiltrations) — the revoked policy licenses actions the rule does not classify as dangerous. A second agent later repeated the dangerous action in 42/62 = 67.7% of runs from the journal alone.

## Authors & Credibility

The three authors — Yi Ting Shen (corresponding), Kentaroh Toyoda, and Alex Leung — are all at Vulcan Research, AIFT, Singapore, the group behind the open-sourced VulcanLab GitHub organization; the repo (Memory-Rebirth-Attack) releases the measurement harness, trial data, and the guard (`guard/stale_guard.py`). The paper reads as a security-empiricism study in the USENIX-Security tradition (it cites PoisonedRAG/USENIX'25 and frames Table 1 as a threat-model taxonomy) rather than an ML-conference paper. Credibility signals are strong: a pre-registered lexical detection criterion with thresholds fixed before measurement; matched-pair exact tests instead of pooled CIs, with the test's power bound stated explicitly (17 discordant pairs cannot detect less than a ~3:1 systematic split); a footnote documenting that mem0's and langmem's measured behavior deviates from their papers/documentation; a transparent AI-usage declaration (Claude Opus 4.8 and GLM-5.3-Flash for language editing); and a full compute/cost table ($79.08 total, no GPUs). No venue is indicated — this is a preprint dated 8 Sep 2026.

## Critical Assessment

- **Novelty: high and well-positioned.** The core reframing — the harmful record is authored by the defender, so every provenance defense (SMSR signatures, TMA-NM origin binding) passes it by construction — is genuinely new relative to the six injection-attack families in Dash et al.'s taxonomy, and the paper's Table 1 contrast is crisp. The nearest prior line (MemStrata's bi-temporal invalidation, VersionRAG) assumes the retrieval layer consults validity; this paper shows deployed agent-memory systems largely do not.
- **Rigor: above average, with honest self-criticism.** The exposure/unsafe-action decomposition, the mem0 single-flag ablation (39/81 one-way flips, p < 0.001), and the refusal to over-read the p = 0.629 cross-system test are exemplary. The authors also concede that the guard's stage-1 agreement with the store filter "is not independent evidence" since both read the same field — a level of candor rare in defense papers.
- **Weaknesses in experimental scope.** The scenario set is nine authored cells, not a sample from any population — the authors say so (between-cell dispersion is "descriptive," not a generalization interval), but headline rates like 43.1% and 94.4% are properties of this grid. The with-rule vs no-rule comparison is explicitly uncontrolled (different scenarios, action sets, distractor counts), and backup deletion — the scenario carrying 83 of 116 rule bypasses — confounds a conditional rule exception with a precedence-asserting revoked text, so the "prompt rules don't protect" claim rests partly on a cell whose two features cannot be separated. The output-filter baseline is scored with an unfair advantage (given the revoked texts), which the paper discloses, but its weak 18.1% result should be read as an upper bound on that defense, not a field measurement.
- **The guard's stage 2 is brittle.** Conflict detection is lexical: stemmed content-word containment (α=0.45) plus antonym pairs, disjoint quantity sets, or a negation-cue difference. It demonstrably withholds current facts (8/25 on mem0 indirect, 6/15 on langmem indirect), misses revoked records that paraphrase cleanly (4/14 on Zep because one policy is split across edges), and its τ=⊥ tie-breaking means a backend exposing no metadata gets only partial protection. An earlier version that broke ties by result order "converted a 0% unsafe rate into 100%" — the authors kept this failure in the paper, which is honest, but it shows how knife-edge the heuristic is.
- **Indirect-insertion exposure is judged by the same kind of lexical matching the guard uses** (θ1=0.3, θ2=0.15), so "a cell labeled unexposed is one the detector failed to recognize" (their words, Section A.1) — some indirect-insertion zeros may be measurement error, not safety.
- **Reproducibility: excellent.** Open-source code and trial data, fixed pre-registered thresholds, a full algorithm listing (Algorithm 1), per-experiment call counts and costs, and a $79/no-GPU budget lower than almost any contemporary LLM paper. Anyone can re-run this.
- **Significance: practically important.** Graphiti/Zep and mem0 are widely deployed production memory layers; the finding that one boolean in mem0's shipped defaults separates safe from 42.1%-unsafe is actionable today. The Zep finding — status marked internally but never exposed, so no application can even express the filter — is a concrete API defect the paper effectively files against the vendor.
- **Red flags: minimal.** The study only measures policies it seeded; it does not test how often revoked-and-retained states arise organically in production stores. The "stored access directive" scenario is included separately and excluded from pooled rates (properly). Nothing suggests cherry-picked reporting — negative guard results (cognee/Graphiti indirect regressions) are reported in the main table.

## Strengths

- First empirical answer to a precise, previously unasked question — is soft revocation enforced at retrieval? — with a taxonomy of three failure forms (never recorded / recorded-but-invisible / recorded-but-unenforced) that maps directly onto vendor fix responsibilities.
- Causal attribution done properly: the within-system mem0 flag ablation isolates retrieval as the failing layer far more convincingly than any cross-product comparison could.
- The threat model is elegant: no attacker, no write access, no new content — the attack surface is the store's own supersession semantics, which neutralizes the entire provenance-defense literature by construction.
- The guard is deployable and backend-agnostic, and its evaluation reports false positives (current facts withheld) beside true positives rather than only headline unsafe-rate reductions.
- Appendix C's write-back, multi-agent, and tool-action extensions convert a static measurement into a lifecycle story: the revoked conclusion survives as a *current* journal record that no status filter can touch, and a tool-layer guardrail is indistinguishable from no defense.
- Exceptional transparency: documented deviations between measured and documented system behavior, stated test-power bounds, a disclosed earlier design failure of the guard, and an AI-usage declaration.

## Limitations

- Nine hand-authored scenarios × nine models is a fixed grid, not a sample; per-scenario extremes (94.4% PII export, 0.0% log deletion) reflect scenario design as much as system behavior, and the paper's pooled rates should not be read as population estimates.
- The main grid measures one agent reading once and deciding once; the richer write-back/multi-agent/tool settings run only on Graphiti (chosen because its API can express both write-back and filtered retrieval), so those rates are properties of one system's pipeline.
- Stage 2 of the guard is shallow lexical analysis — no embeddings, no LLM judge — which is a deliberate deployability trade but caps recall on paraphrased or structurally split records (4/14 on Zep) and costs precision (current facts withheld).
- Zep's exposure status was read "directly from its store, which is labeling instrumentation rather than a capability an application has" — so the Zep column partially measures a capability no Zep user possesses.
- The study seeds the contradicting pair itself; it does not measure how frequently real-world memory churn produces retained-but-revoked records, leaving the prevalence of the precondition an open question.
- The with-rule group's headline outlier (backup deletion, 46.1%) confounds two unseparable scenario features, and the paper's narrower claim ("a prompt prohibition does not reliably prevent the unsafe action") is the only one the data supports.

## Relevance

对"自进化 Agent 与自动化研究"方向高度相关：长时运行自主体依赖持久记忆，本文系统性地证明了五个生产级记忆系统的软撤销在检索层不被执行、并通过 Agent 自身写回与多 Agent 共享记忆自我传播（无攻击者参与），这正是自进化 Agent 可靠性与可信任性问题的具体失效模式；其"检索时有效性 vs 来源检查"的防御定位对构建长期可靠的 Agent 记忆基础设施有直接工程价值。

## Questions for Further Exploration

- How often do retained-but-revoked records arise organically in production agent stores, as opposed to being seeded as in this study — is the precondition common under real conversational churn?
- Can stage 2 of the guard be upgraded to a lightweight NLI or embedding-based contradiction check without losing its deployability (no backend change, no LLM call per read), and how do the false-positive and Zep-split-edge rates move?
- Would fine-tuning or system-prompt changes that surface record timestamps/status in the retrieved context (violating the paper's "agent sees text only" assumption) let models self-enforce revocation, or does the 37.2% prompt-hardening result show that path is capped?
- Does the write-back poisoning loop (journal stored as current, filter defeated at 71.6–83.1%) stabilize into a fixed point, and can provenance on *self-authored* records (marking agent conclusions as derived) break it?
- The most resistant model was the non-reasoning Grok-4-Fast (15.0%); is susceptibility driven by specific instruction-following calibration rather than capability, and can it be predicted from cheap probes?
- Could memory vendors expose a mandatory `valid_at(now)` read API (retrieval-time validity as a first-class query constraint) so the store-level filter the paper recommends becomes the default rather than an opt-in flag?
