81/81 scenario-model cells where the revoked record was returned by default retrieval — always at rank 1, above its own replacement.
Why this matters

Long-running agents depend on persistent memory; unenforced revocation is a concrete trust failure that self-propagates through write-back and shared memory — no attacker required.

Critical edge

Nine hand-authored scenarios × nine models is a fixed grid, not a sample — headline rates like 43.1% and 94.4% are properties of this grid, not population estimates.

— Critical Assessment · experimental scope

01 Methodology

Each store is seeded with exactly two contradicting records — a revoked permissive policy v1 and its replacement v2 — under direct insertion (native revoked fields, e.g. mem0’s expiration_date) or indirect insertion (plain contradicting prose the system must reconcile itself). The agent then asks an ordinary question; default retrieval returns the top-10 records with no status restriction, the prompt sees record text only — status and timestamps never reach it — and the agent chooses between a safe and an unsafe action.

Two metrics keep the store’s fault separate from the model’s: exposure rate Pr[ER=1] (did retrieval return the revoked record?) and unsafe-action rate Pr[a=a⁻], factored through the former. Cross-system claims rest on matched-cell paired exact tests, not pooled intervals.

02 Results beyond the headline

Exposure is total on the two exposed systems (Graphiti default, mem0 with expiry filter off): the revoked policy always ranked above its replacement — revoked policies are phrased more absolutely (“must be blocked” vs “are monitored”), and similarity retrieval favors that phrasing. Per-model rates spanned 15.0%–60.0%; model tier did not predict susceptibility — the most resistant model was non-reasoning Grok-4-Fast (15.0%).

03 Strengths

  • First empirical answer to a precise, previously unasked question — is soft revocation enforced at retrieval? — with a three-failure taxonomy (never recorded / recorded-but-invisible / recorded-but-unenforced) that maps onto vendor fix responsibilities.
  • Causal attribution done properly: the within-system mem0 flag ablation isolates retrieval as the failing layer far better than any cross-product comparison.
  • Elegant threat model: no attacker, no write access, no new content — neutralizes the entire provenance-defense literature by construction.
  • Deployable, backend-agnostic guard whose evaluation reports false positives (current facts withheld) beside true positives.
  • Exceptional transparency: pre-registered thresholds, documented vendor deviations, a disclosed earlier guard design that flipped 0%→100% unsafe.

04 Limitations

  • Fixed grid, not a sample: per-scenario extremes (94.4% PII export, 0.0% log deletion) reflect scenario design as much as system behavior.
  • Deeper extensions run on Graphiti only — write-back, multi-agent, and tool rates are properties of one system’s pipeline.
  • Guard stage 2 is shallow lexical analysis (no embeddings, no LLM judge): withholds current facts (8/25 mem0 indirect) and misses paraphrased or split records (4/14 on Zep).
  • Zep’s status was read from internal instrumentation — a capability no Zep application user actually possesses.
  • Prevalence unmeasured: the study seeds the contradicting pair itself; how often real memory churn produces retained-but-revoked records remains open.

The narrower claim the data supports: “a prompt prohibition does not reliably prevent the unsafe action.”

05 Questions for further exploration

  • How often do retained-but-revoked records arise organically in production stores, versus being seeded as here?
  • Can guard stage 2 upgrade to a lightweight NLI / embedding contradiction check without losing deployability — and how do its false-positive and Zep-split rates move?
  • Would surfacing record timestamps/status in the retrieved context let models self-enforce revocation, or does the 37.2% prompt-hardening result cap that path?
  • Does the write-back poisoning loop stabilize into a fixed point — and can provenance on self-authored records break it?
  • Is susceptibility driven by instruction-following calibration rather than capability (most resistant: non-reasoning Grok-4-Fast, 15.0%), and can it be predicted from cheap probes?
  • Should memory vendors expose a mandatory valid_at(now) read API, making retrieval-time validity a first-class query constraint?

06 Credibility

  • USENIX-Security-style empiricism from Vulcan Research, AIFT (Singapore); harness, trial data, and guard open-sourced (VulcanLab / Memory-Rebirth-Attack).
  • Pre-registered lexical criterion, thresholds fixed before measurement.
  • Matched-pair exact tests with the power bound stated openly.
  • AI-usage declaration and a full compute/cost table — reproducible for $79, no GPUs.
