Claude Sonnet 5 across the 9-task benchmark — GPT-5 trails at 80.6, and the five-model spread exceeds 72 points on identical tasks (Gemini 2.5 Flash: 22.6).

Why this matters

A reusable, open-source skeleton for auditing LLM-agent trust — tool-call reliability, prompt-injection and memory-poisoning robustness — where pass/fail benchmarks fall short.

⚠ Critical edge

All 45 traces were judged by a single model — Claude Sonnet 5 — which also tops the ranking at 95.1. No second judge, no agreement study, no human validation.

01Methodology — three decoupled layers

Execution. The agent (LLM + planner + tools + memory) runs against simulated environments — Banking, Email, Identity Docs, Trip Planner, Marketplace, Payments, plus adversarial ones — each holding hidden ground truth that only tools can touch, with deliberately irrelevant decoy tools to test selection discipline.

Trace. Every interaction is recorded post-hoc as a timestamped structured-JSON trace. The evaluator never perturbs the running agent, so any framework (OpenAI Agents SDK, LangGraph, CrewAI, AutoGen, MCP) can be audited — and stored traces can be re-scored with new judges without re-running agents.

Evaluation. Four categories over the trace: seven capability metrics, tool-faithfulness grounding, a risk-weighted six-attack security suite (jailbreak, direct/indirect injection, memory & tool poisoning, MCP attacks), and behaviour. Module scores combine into a 0–100 Composite Trust Score with a critical-failure cap: any safety-critical module ≤ 29.9 pins the CTS at 30, so one severe failure cannot hide behind nine competent scores.

The 10 scored dimensions (default weights)

Instruction integrity .15 Planner .10 Memory .10 Tool selection .10 Tool invocation .10 Tool correctness .15 Alignment .10 Tool faithfulness .07 Security .07 Execution integrity .06

Safe_Correcthandled the task — or refused malice — correctly

03Strengths

  • Failure attribution + four-class taxonomy separates security violations from capability gaps — exactly what pass/fail scoring cannot do.
  • Agent-attached, trace-only architecture: cleanly decoupled evaluation, framework-agnostic, and re-scorable without re-running agents.
  • The critical-failure cap is a sensible guard against score averaging — and visibly reshuffles the rankings.
  • Hidden ground truth never exposed to the LLM, plus decoy tools, make tool metrics hard to game.
  • Exceptional transparency: harness bugs, the Pro→Flash substitution, and the single-trial caveat are all disclosed.

04Limitations

  • Judge = contestant. The single fixed judge is the top-scoring model; self-preference bias in LLM judges is well documented.
  • Nine tasks, one trial per model×task cell — no error bars; authors admit one lucky or unlucky run can move a score.
  • Module and attack weights are uncalibrated defaults with no sensitivity analysis; the 30-cap pins multiple cells at exactly 30.
  • Planner, alignment, and tool-faithfulness modules inherit the LLM judge's capabilities and biases.
  • Single-agent scope only; assumes full trace access and costly per-task hidden ground truth.

05Open questions worth chasing

  1. Does the Claude > GPT-5 ranking survive an independent judge — or a human panel — scoring the same 45 traces?
  2. Are the CTS rankings stable under uniform weights or an ablated cap?
  3. Do Sarvam's Unsafe_Compliance classifications replicate under repeated sampling, or are they single-run artifacts?
  4. Can failure attribution be validated against injected faults (poisoned memory/tool) at measurable accuracy?
  5. How does the framework extend to multi-agent systems and mid-execution, real-time auditing?
