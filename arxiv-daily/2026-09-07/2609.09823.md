> **一句话总结：** AMEND 利用先前解码步"已审计"的 BLASST 边际（margin）历史提前预测当前步哪些 KV 块可丢弃——GPU 只读预测存活的块，HBM 近存储体 PIM 单元并行计算被丢弃补集的 QK 以审计预测并把结果折叠进下一步掩码，从而同时消除 post-QK 稀疏化的全量 K 读取和 current-query PIM 过滤的串行阶段；在 LongBench/RULER 质量近无损（距 BLASST 平均 0.45 分以内）的前提下，8K–64K 上下文模拟解码取得 1.40–3.63× 端到端加速与 28–66% 动态能耗下降。

> **TL;DR:** Long-context LLM decode is GPU-bandwidth-bound on the KV cache: post-QK selectors like BLASST still read every K block (at 90% sparsity K is ~91% of remaining K+V traffic), while current-query PIM filters (BLASST-PIM, Quest-PIM) put a serial PIM stage on the critical path. AMEND breaks both dependencies by predicting each block's BLASST verdict from margins audited at earlier steps (89.2% of verdicts persist to the next step), running GPU survivor attention concurrently with PIM QK over the omitted complement, and eagerly generating the next step's mask. On LongBench (16 tasks) and RULER with Llama-3.1-8B-Instruct and Qwen3-8B it stays within 0.12/0.45 points of Dense and BLASST while beating Quest by 6.47 RULER points on average; in AttAcc-based simulation at batch 8 it achieves 1.40–3.63× end-to-end decode speedup over dense attention across 8K–64K contexts (3.63× vs 3.17× for Quest-PIM at 64K) and 28–66% lower dynamic decode energy, at a realized false-drop rate of 1.50–2.24%.

## 核心贡献

- **识别并量化两个关键瓶颈**：post-QK 稀疏化选择器（如 BLASST）虽跳过 softmax/V/PV，但 K 读取量与 Dense 完全相同（在 Llama-3.1-8B 上 K 占剩余 K+V 流量的 91.1–93.3%）；而 current-query PIM 过滤器虽在 K 读取前出掩码，却把串行 PIM 阶段留在了"查询→分数→掩码→注意力"的关键路径上。
- **因果（pre-QK）verdict 预测**：利用相邻解码步间 BLASST 判决的高度持续性（Qwen3-1.7B 追踪中 89.2% 的判决下一步不变），从每格的边际 EMA μ、二阶矩 M2、连丢年龄 a 和 2-bit 施密特计数器 c 组成的状态，在当前 QK 之前生成存活掩码，使 GPU 对预测丢弃块零 K 读取。
- **补集审计消除"选择性标签"观察洞**：预测丢弃的块永不再被 GPU 打分，预测器会陷入自我强化的错误丢弃循环；AMEND 用 PIM 近存储体 GEMV 对全局遗漏块并发计算 QK 最大值，控制器合并 GPU/PIM 两路观测、重构全缓存 BLASST 证据并折叠进预测器状态——受控消融显示该反馈使滚动假丢率从 0.087 降至 0.028（降 68%）。
- **急切下一掩码生成 + 执行契约**：当前 token 输出 Oₜ 只依赖 Qₜ 与上一步的掩码（"不等待、不修复"边），审计结果只用于 t+1 步掩码，因此每个预测丢弃都被重新观测且不阻塞当前步；映射到 AttAcc 派生的 HBM-PIM 衬底，控制器仅含比较/归约/位图等窄功能（无指数、除法、softmax 数据通路）。
- **SCBO 离线选工作点**：五个混合类型旋钮 θ=(r, δ, α, R, z) 通过可扩展约束贝叶斯优化在经验假丢率约束（τ=2×10⁻²）下离线标定；200 次评估即达 0.651 最优可行召回率，优于同预算随机搜索的 0.597。

## Key Contributions

- Identifies the K-traffic gap left by post-QK sparsity (BLASST's K bytes equal Dense's at every setting; K is 91.1–93.3% of its remaining K+V traffic on Llama-3.1-8B-Instruct) and the serial-PIM-stage problem of current-query PIM filters, unifying both in a "when does the mask become available" taxonomy (Figure 1).
- Causal pre-QK verdict prediction: a strictly-causal per-cell predictor (margin EMA + volatility penalty + drop-age floor + 2-bit Schmitt hysteresis + recency-window/seam hard keeps) reproduces the full-cache BLASST verdict before current QK, exploiting the measured 89.2% adjacent-step verdict persistence.
- Complement audit: PIM near-bank GEMV units concurrently score every globally omitted block, and a stack-level controller reconstructs full-cache margins (QK_surv + QK_omit = QK_full, so no work is deleted, only relocated), closing the selective-labels observation hole that a survivors-only predictor would create; the fold cuts rolling false-drop rate from 0.087 to 0.028 (−68%) in a controlled ablation.
- Eager next-mask generation under an explicit execution contract: the current output has no dependency on the current audit; the only cross-step hard dependency is that audit finishes before the next step's predict — making every PIM byte off the critical path (0.0 µs/token serial PIM vs 36.1–286.7 µs/token for BLASST-PIM).
- SCBO-adapted offline selection of the five mixed-type predictor knobs under an empirical false-drop budget, with code released (attention emulation + trace-based GPU/PIM simulation).

## Methodology

The method builds on three observations and one loop. **Observation 1 (traffic):** a max-relative post-QK selector like BLASST must read all K to compute block maxima, so at 90% block sparsity its V traffic drops ~10× but K traffic does not move at all — the remaining opportunity is skipping GPU-side K reads *before* current QK. **Observation 2 (predictability):** verdicts persist across steps (89.2% unchanged at lag-1, pooled over layers/heads/examples on Qwen3-1.7B LongBench traces), and the continuous margin behind each verdict (block max minus exclusive-prefix max minus a context-length offset η) is more informative than the binary mask: a strictly causal EMA replay (α=0.3) already agrees with 93.4% of current DROP verdicts. **Observation 3 (the observation hole):** once a cell is predicted-dropped, the GPU never computes its true margin, so a survivors-only predictor trains on a self-selected sample (selective-labels problem) and can lock in wrong drops forever.

The per-step loop (one layer) has five stages: ① **Predict** — evaluate the predictor on state S_t⁻ (margin EMA μ, second moment M2 → volatility σ, drop-run age a, 2-bit counter c), drop a cell only if age ≥ r, μ + zσ < −δ, base-eligible, and the counter saturates; hard keeps (block 0, last block, partial tail, last R blocks) override; form per-KV-head mask P_t, its physical union U_t (GQA: a block is fetched if any head keeps it), and the complement A_t. ② **GPU survivor attention** — QK/online-softmax/PV over U_t only, tightened by survivor BLASST (which can only shrink V/PV, never add false drops among survivors, since γ^P ≥ γ^U ≥ γ★). ③ **Complement QK (PIM, concurrent with ②)** — AttAcc-derived power-capped near-bank GEMV units compute QK block maxima for globally omitted blocks and return only maxima. ④ **Reconstruct** — the controller merges GPU and PIM maxima in block order, runs the exclusive-prefix and GQA reductions, and recovers the full-cache margin γ★ for every cell of A_t (exactly matching an FP32 reference in the functional path). ⑤ **Fold** — both observation channels update S_{t+1}, from which step t+1's mask is eagerly generated. The output O_t depends only on Q_t and P_t^keep — the "no wait, no repair" edge.

The five knobs θ = (r, δ, α, R, z) trade drop recall against false drops through a cross-token recursion with no usable gradient, so calibration is cast as constrained mixed-variable black-box optimization: Scalable Constrained Bayesian Optimization (independent GPs for recall and the constraint, constrained Thompson sampling in a local trust region) maximizes drop recall subject to a calibration false-drop budget τ = 2×10⁻², frozen per model/setting. Evaluation: quality on LongBench (16 tasks, 3,750 inputs/model) and RULER (13 tasks × 1,300 examples per setting; Llama-3.1-8B-Instruct at 8K–64K, Qwen3-8B at 32K) in BF16 against Dense, Quest, and BLASST; performance/energy in an AttAcc-based trace-driven simulator (H100 80GB + AttAcc GEMV units in five 16-GB HBM3 stacks, 670 GB/s external vs 9× internal per-stack bandwidth under the HBM power constraint, batch 8, dynamic energy only), against BLASST-PIM and Quest-PIM whose serial PIM selector stages sit on the critical path.

## Results & Highlights

- **LongBench quality (16 tasks, avg):** AMEND scores 49.76 vs Dense 49.69 and BLASST 49.88 on Llama-3.1-8B-Instruct (within 0.12 points of both, +0.82 over Quest's 48.94), and 49.37 vs Dense 49.41 / BLASST 49.44 on Qwen3-8B — near-baseline quality at a realized false-drop rate of 2.24%.
- **RULER quality (avg over five settings):** AMEND 85.13 vs BLASST 85.58 (−0.45), Dense 85.30, and Quest 78.66 (+6.47); at every individual setting AMEND is within 0.91 points of BLASST and 1.45–11.52 points above Quest — e.g., at 8K multi-key-3 retrieval, AMEND 99.00 vs Quest 14.00.
- **End-to-end decode speedup (simulated, batch 8, Llama RULER):** 1.3989× at 8K, 1.7922× at 16K, 2.5230× at 32K, and 3.6257× at 64K over Dense — the highest of all evaluated methods at every context length, beating Quest-PIM's 3.1673× and BLASST-PIM's 2.9619× at 64K (a widening gap, from ~1.0% at 8K to +14.5% at 64K, as attention grows from 32% to 80% of Dense decode time).
- **Attention-path speedup and PIM latency:** AMEND reaches 8.39×/9.82×/11.27×/10.89× (8K–64K) vs at most 7.05× for Quest-PIM and 5.95× for BLASST-PIM, with **0.0 µs/token of serial PIM** inside the attention path (BLASST-PIM: 36.1–286.7 µs/token serial; Quest-PIM: 9.4–68.4) because the complement audit (28.5–247.6 µs/token, 0.79–0.86× of BLASST-PIM's PIM time) runs concurrently.
- **Dynamic decode energy (normalized to Dense, batch 8):** 0.72 at 8K (−28.14%) down to 0.34 at 64K (−66.39%), within 0.03–0.06 of Quest-PIM, the lowest-energy method (e.g., 0.2790 vs AMEND's 0.3361 at 64K).
- **Audit-fold ablation (10 LongBench gov_report examples, Llama-3.1-8B-Instruct, frozen operating point):** rolling false-drop rate 0.028 with the per-step audit fold vs 0.087 without — a 68% reduction that empirically validates the selective-labels fix.
- **FDR sweep (Llama RULER 4K, 1,300 rows):** realized recall rises monotonically 0.560→0.956 and attention speedup 3.71×→35.5× as the target false-drop rate relaxes, while the RULER score stays within 0.005 of BLASST's 0.871 down to 5×10⁻³ and collapses to 0.335 only at 8×10⁻² — bounding the useful operating range; realized false-drop rates on full evaluations land at 1.50–2.24% against the 2% target with drop recall 72.60–90.75%.
- **Batch scaling:** AMEND keeps the highest speedup through N=64, but at N=128 it is within 0.6% of Quest-PIM (5.86× vs 5.89×) once the audit stall is exposed (49.2 µs/token at N=128; hiding it would yield 7.18×).

## Critical Assessment

- **Novelty:** The core insight — predicting a max-relative sparsity verdict from audited margin history so the mask exists before current QK, with PIM auditing the complement off the critical path — is a genuinely new dependency-role design, cleanly distinguished from GVR/PRR (which repair the *current* step) and from temporal-prediction methods (which lack the complement audit and can drift via the observation hole). The selective-labels framing is unusually rigorous for a systems paper.
- **Rigor:** Strong on determinism (QK_surv + QK_omit = QK_full invariant, FP32-exact reconstruction claim, execution-contract invariants, macro-averaged false-drop/recall metrics, appendix operating points). But the headline speed/energy numbers all come from an AttAcc-derived trace simulator with the GPU and PIM lanes modeled *without bandwidth contention* — a generous assumption — and no real HBM-PIM hardware exists to validate against. Quality runs execute the AMEND software path on A100 BF16, while performance is replayed on a simulated H100, so quality and speed are measured on different paths.
- **Reproducibility:** Good in principle (code link, full operating-point table, per-task RULER breakdowns), but the SCBO calibration is per model *and per benchmark setting* on 50 sampled examples — anyone reusing AMEND on a new domain must re-run the search, and the paper does not test cross-setting transfer of a frozen θ.
- **Significance:** If near-bank HBM-PIM ever ships, this is a credible blueprint for nonblocking sparse decode; until then its practical impact is indirect (the predict-and-audit idea transfers to GPU-only pipelines as a software technique).
- **Red flags:** (1) The default batch size 8 is small for serving; AMEND's advantage over Quest-PIM vanishes at N=128 (5.86× vs 5.89×) and the audit stall becomes exposed, and beyond N=16 at 32K the KV footprint exceeds one H100's post-weight capacity so the cost model is *extrapolated* (shaded region of Figure 10). (2) The Quest baseline is tuned with modest budgets (256–2,048 tokens) and collapses on RULER MK-3 (14.00 vs Dense 100.00 at 8K), which inflates AMEND's +6.47 average quality margin; the honest reference is BLASST, which AMEND trails everywhere. (3) The per-task appendix reveals gaps the averages hide — e.g., common-words-extraction at 16K: AMEND 64.80 vs BLASST 78.20 (−13.4 points) and vs Dense 86.30. (4) No empirical comparison against the temporal-prediction competitors the related-work section itself names (TidalDecode, IndexCache, AttentionPredictor, LFPS, SpargeAttention). (5) The 68% audit-fold ablation rests on only 10 gov_report examples. (6) Energy counts dynamic energy only — static/leakage of extra PIM silicon is ignored.

## Strengths

- Precise problem decomposition: the "when does the mask become available" taxonomy (Figure 1) turns a vague systems claim into four concrete dependency structures, and the traffic model cleanly quantifies why post-QK sparsity leaves K bytes untouched.
- The complement audit is the right fix to a real, well-named failure mode (selective-labels censoring), and the controlled ablation isolates exactly that mechanism (−68% false-drop rate at a frozen operating point).
- The design conserves work rather than deleting it (QK_surv + QK_omit = QK_full) and proves survivor BLASST cannot add false drops among survivors (γ^P ≥ γ^U ≥ γ★) — quality loss is bounded to the predictor's false drops by construction.
- Hardware-plausible controller scope (no exponentiation, division, or softmax datapath), explicitly budgeted against AttAcc's 1.38 mm² buffer-die unit.
- Honest knob-level disclosure: per-setting realized false-drop rates vs targets, per-task RULER tables, FDR sweep with a sharply bounded useful range, and the batch-size regime where the advantage disappears.

## Limitations

- Simulation-only performance evaluation; the AttAcc-style HBM-PIM substrate is not commercially available, and GPU–PIM bandwidth contention is assumed away.
- Small default batch (8); at N=128 the advantage over Quest-PIM is gone, and N>16 at 32K already exceeds one H100's KV capacity, making large-batch claims extrapolated.
- Contexts capped at 64K; no prefill-stage story (decode only), no integration into a full serving stack.
- Drop recall is 72.60–90.75%, so up to ~27% of BLASST's true drops are never predicted — real sparsity is left on the table in exchange for safety.
- Offline SCBO calibration per model/setting adds deployment friction; transferability of operating points is untested.
- Baseline coverage is narrow (Quest, BLASST, and their PIM variants); no empirical head-to-head with other history-based or verification-based sparsity methods; energy is dynamic-only.

## Relevance

与"大规模 ML 计算基础设施"方向直接相关：这是面向长上下文 LLM 解码的 GPU–PIM 异构架构与稀疏注意力内核设计，核心是内存带宽瓶颈的系统性消除。此外，其"在激进稀疏化优化下用审计机制严格约束错误丢弃（假丢率预算）"的思路，与"极端性能优化下的可靠性/正确性"主题也有方法论上的呼应——把性能优化的质量损失变成可标定、可有界控制的量。

## Questions for Further Exploration

- How much of the 1.40–3.63× speedup survives when GPU–PIM bandwidth contention, PIM-lane sharing with the controller's reconstruction/state-update traffic, and static leakage energy are modeled honestly?
- Can a single operating point θ transfer across domains (e.g., code vs narrative QA) or across fine-tuned variants of the same base model without re-running SCBO, and how much recall is lost?
- Does margin-based verdict prediction survive aggressive KV-cache quantization (FP8/INT4), where margins are computed on dequantized keys but decisions affect quantized reads?
- How does the design interact with speculative decoding (multiple query positions per step) or GQA groups with heterogeneous head behavior — does verdict persistence degrade?
- Could the predict-and-audit loop be ported to a pure-GPU software stack (e.g., CUDA async copies standing in for PIM) to capture part of the K-traffic saving on commodity hardware today?
- What happens beyond 64K (128K–1M contexts), where the recency window R and the one-step audit-hiding budget face a much larger complement per step?
