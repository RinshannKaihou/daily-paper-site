Why this matters

Exact ground truth, well-defined cross-system joins, and byte-reproducible estates — a reusable recipe for controlled enterprise agent evaluation.

Critical edge

The headline ranking rests on one curated 33-question estate — 33 of 36 pairwise model comparisons are statistically inconclusive.

And the question-conditioned generator is not released: clients receive finished estates, so the pipeline cannot be independently audited.

01 · Methodology

How the estate is built

IN4 params + 1 seed→ GENentity graph→ PROJ66 simulators→ KEYScomputed

Four parameters — industry, company size, business model, application portfolio — plus one seed deterministically generate a complete fictional company: workforce with employment history, customers, sales pipeline, tickets, recorded calls, chats, documents. A CI test regenerates from seeds and asserts byte-identity. Each of the 66 product simulators (Salesforce, HubSpot, Zendesk, Jira, Gong, Slack, Stripe, S3…) stores a projection of that single entity graph in the vendor's real format under canonical join keys — so cross-system questions are well defined by construction, and determinism replaces inter-simulator synchronization.

For internal databases, an author writes business questions; an LLM designs the schema and generation plan once, then deterministic code plants qualifying rows plus near-miss rows — each violating exactly one condition — and computes every answer key by running the questions against the finished tables. Serving is read-only over MCP; grading is fully mechanical.

Only one LLM step exists in the whole pipeline — schema design, run once per benchmark.

  • Lazy-solver panel — any question a deliberately lazy solver answers exactly is reported as measuring nothing
  • Near-miss planting — ignoring any single filter condition yields a wrong answer
  • Boosted-tree two-sample test vs column-shuffled copies, with a measured noise floor
  • Answer-key defect search — ties, self-answering text, precision tolerance
  • Reachability audit through native APIs — caught a real cross-system join invisible via the product interface

Scorecard and generator were co-developed by the same authors; held-out seeds and a single-instrument recompute mitigate — but do not eliminate — the circularity.

05 · Strengths

What holds up

  • Exact computed ground truth — mechanical grading, no LLM judge, no data/answer drift
  • Cross-system consistency by construction — one entity graph, deterministic projections; reachability audit caught a genuine join defect
  • Validation with teeth — lazy-solver panels, near-miss planting, dependency tests with noise floor, adversarial artifact detector
  • Cheap extension — a new scenario is just industry + size + seed; a new template applies to all 83 scenarios
  • Statistical honesty — wide CIs reported; fairness via isolation, read-only data plane, equal budgets, serving verified before grading

06 · Limitations

What to weigh

  • One estate, 33 of 67 questions, three systems, simulator track only — internal-database and document tracks go unevaluated in the paper
  • Realism targets rest partly on Eon's own operational data and estimates; a wrong target steers the generator wrong, undetectably
  • Template-generated text has an acknowledged ceiling below human idiosyncrasy — a stronger detector might flag it
  • Generator unreleased — clients get finished estates; no external audit of the question → schema → records pipeline
  • Small buckets — capability figures like 3.7% multi-hop rest on 12 composed + 2 abstention questions: large sampling noise

07 · Open questions

Where this leads

Q1How do the unevaluated tracks behave — internal-database questions with planted near-misses and dirty values, and the document/unstructured track?
Q2Does the 3.7% multi-hop / 6.2% superlative collapse hold across estates, industries, and size tiers — or is it one fintech-small artifact?
Q3Can realism scorecard targets be replaced with third-party auditable statistics, unhooking the 97.0 from Eon's own data?
Q4With ~290 MCP tools behind 3 meta-tools, how much failure is tool-discovery overhead versus genuine data reasoning?
Q5Do the 3 repeats expose instability (gpt-5.5: 17/99 false abstentions) that single accuracy numbers hide — and how do day-1 vs day-2 states shift failure modes?
Q6Could the question-conditioned generator be opened so independent groups plant their own questions and reproduce the design-validity outcomes?
