> **一句话总结：** 提出 IdeaAMBIG 基准（660 个证据支撑的单缺陷研究方法规范实例，163 个真实缺口 + 497 个受控注入缺口），评测 13 个 LLM 的"可编码就绪性"判断、缺陷定位与澄清动作生成三项能力；发现最强模型 GPT-5.6-Sol 在真实实例上的缺陷恢复率仅 9.6%，但给定缺陷后澄清成功率高达 80.6%（Oracle 研究中下游就绪率从 14% 升至 98%），证明"定位缺陷"是当前 LLM 科研代理的核心瓶颈。

> **TL;DR:** This 74-page paper from Yale + TCS Research introduces IdeaAMBIG, a 660-instance benchmark (163 real-world gaps from GitHub issues and MLRC/ECIR/TMLR reproducibility reports + 497 controlled synthetic gaps injected into codification-ready references) testing whether LLMs can (1) judge if a research-method specification is implementation-ready, (2) localize the method-defining defect, and (3) generate a targeted clarification. Across 13 LLMs, the best model (GPT-5.6-Sol) scores only 9.6 Macro Defect Recovery Rate on real-world localization vs 80.6 Macro-CAS when handed the annotated defect (+67.0 in a controlled same-model comparison, p<0.001), and an oracle study shows supplying the gold resolution lifts downstream codification-ready rate from 14% to 98% — blocker discovery, not clarification, is the bottleneck for research agents.

## 核心贡献

- **形式化"可编码就绪性"（codification readiness）概念**：一个研究想法的方法学规范，若胜任的实现者（或编码代理）能在不做无支撑假设的前提下忠实实现核心方法，则称其"就绪"。这是首次将"想法"与"可执行规范"之间缺失的这一环节形式化，并定义了三项评测任务。
- **构建 IdeaAMBIG 基准（660 个单缺陷实例）**：163 个真实缺口（来自 50 个仓库的 4,106 个已关闭 GitHub issue 以及 174 份 MLRC/ECIR/TMLR 可复现性报告），加上 497 个受控合成缺口（在经独立验证成功复现的论文参考规范中只改动一个实现关键细节）。每个实例带 3 个一级 + 10 个二级缺陷分类标签、证据支撑的解决方案和黄金澄清动作。
- **三项递进任务的评测协议**：就绪性判断（Macro-F1）、无提示的缺陷定位（Macro DRR）、给定缺陷的澄清动作生成（Macro-CAS），将"发现阻塞点"与"已知阻塞点后的行动"解耦。
- **对 13 个 LLM 的系统评测与瓶颈定位**：发现缺陷定位是主要瓶颈（最强模型真实实例 Macro DRR 仅 9.6%），并通过 End-to-End vs Defect-Guided 对照实验（13.6 → 80.6 Macro-CAS）与 Oracle 研究（就绪率 14% → 98%）证明其因果。
- **严格的基准验证**：盲评人工研究（真实/合成实例的效度、关键性、充分性、真实性分别达 92/92/96/93% 与 96/94/98/91%）、Cohen's κ（就绪性 0.84/0.92）、源聚类 bootstrap 稳健性分析、无分类器消融与可执行验证研究。

## Key Contributions

- **Formalizes "codification readiness"** of implementation-facing research-method specifications: a spec is ready when a competent implementer (or coding agent) can build a faithful initial implementation without unsupported assumptions about the core method — filling the unmeasured gap between scientific ideation and execution.
- **Constructs IdeaAMBIG**: 660 evidence-grounded, single-defect instances — 163 real-world gaps mined from 4,106 closed GitHub issues across 50 paper-linked repos and 174 reproducibility reports (MLRC, ECIR, TMLR), plus 497 controlled synthetic gaps created by altering exactly one implementation-critical detail in verified, codification-ready references (358 from reproducibility reports + 139 from 43 AI-Researcher executed projects). Each instance carries Level-1/Level-2 taxonomy labels, a supported resolution, and a gold clarification action (3 Level-1 types: Ambiguity, Incompleteness, Inconsistency; 10 Level-2 categories).
- **Defines three diagnostic tasks** that separate capabilities: readiness assessment (Macro-F1), defect localization without a defect hint (Macro Defect Recovery Rate), and clarification action generation given the annotated defect (Macro-CAS) — decoupling blocker discovery from the response once the blocker is known.
- **Evaluates 13 LLMs** (GPT-5.6-Sol, Claude Sonnet 5, Gemini 3.1 Pro Preview, DeepSeek-V3.2, Qwen3.5-397B-A17B, DeepSeek-R1-0528, GLM-5.2, Kimi-K3, GPT-OSS-120B, Gemma-4-31B-IT, Qwen3-8B/32B, Qwen3.5-9B) and identifies defect localization as the universal bottleneck.
- **Validates the benchmark rigorously**: blind two-annotator human studies (positive judgments 92/92/96/93% real-world, 96/94/98/91% synthetic), inter-annotator κ of 0.84/0.92 for readiness labels, a target-uniqueness audit (94.5% of original targets valid/primary/unique), source-clustered bootstrap robustness checks, a taxonomy-free localization ablation, an oracle clarification-utility study, and an executable validation on 20 controlled instances with reference implementations.

## Methodology

The benchmark is built from three complementary sources. (1) **Reproducibility reports**: 396 reports from MLRC/ECIR/TMLR were converted to Markdown (MinerU), filtered to 174 single-open-access-paper pairs with open-source code; DeepSeek-V4-Pro routed pairs into real-gap / synthetic / unusable tracks, extracting 210 gap mentions that decompose into 233 atomic candidates, of which human verification retained 42 real instances; 106 successfully-reproduced pairs yielded 358 controlled synthetic instances by altering up to five implementation-critical details in the reconstructed reference. (2) **GitHub issues**: from 1,000 paper-linked repos (2017–2025), 4,106 closed issues across the top-50 repos were crawled, 800 gap-signal threads prefilters, DeepSeek-V4-Pro classification plus GPT-5.5 validation reduced 152 resolved candidates to 121 benchmark instances. (3) **Ideation–execution trajectories**: 43 executed projects from the AI-Researcher study (19 human-, 24 LLM-generated ideas) provided paper–code pairs from which codification-ready references were reconstructed and single details removed/abstracted, yielding 139 synthetic instances. Environment, runtime, resource, and credential issues were excluded so every instance is a method-core gap.

All construction paths used two-stage human review (primary annotator + independent second reviewer), with disagreements adjudicated against source evidence. The task suite formalizes each instance as a NOT-READY spec with exactly one target defect plus its READY counterpart: Task 1 classifies READY vs NOT-READY from the spec alone; Task 2 outputs a Level-1 label, Level-2 label, and natural-language defect description; Task 3 receives the annotated defect and must produce a clarification action typed as either Clarification Question (ask an author/implementer) or Evidence Seeking (inspect paper text, code, configs, logs). Evaluation used fixed task-specific prompts, structured outputs, and Claude Opus 4.8 as semantic judge validated against adjudicated human annotations; a controlled Defect-Guided vs End-to-End comparison (same GPT-5.6-Sol, schema, decoding, protocol) isolates the information bottleneck; an oracle study on 50 stratified real instances and an executable study on 20 controlled instances measure the downstream value of supplying the gold resolution.

## Results & Highlights

- **Defect localization is near-failing for every model**: on the 163-instance real-world subset, the best model GPT-5.6-Sol achieves only 9.6 Macro Defect Recovery Rate (Task 2), vs 12.2 on the controlled synthetic sample; the runner-up frontier models score 3.4–6.8 (Claude Sonnet 5: 6.8, Kimi-K3: 6.6). Component analysis: GPT-5.6-Sol reaches 60.1 Level-1 accuracy and 25.2 Level-2 accuracy but just 16.0 localization accuracy — models often guess plausible categories without recovering the actual unresolved decision (66.3% of Task 2 predictions identify a *different* blocker, 17.8% a neighboring one).
- **Given the defect, clarification is strong**: GPT-5.6-Sol scores 80.6 Macro-CAS on real-world and 96.2 on synthetic Task 3, vs Claude Sonnet 5's 76.8/94.5 and Kimi-K3's 60.6/92.5. In the controlled bottleneck comparison (same model, same instances), removing the defect hint drops Macro-CAS from 80.6 to 13.6 (∆ = 67.0, 95% CI [59.0, 75.2], p < 0.001) and Sufficiency from 80.4 to 8.6, while No-Assumption stays flat (95.7 vs 96.3) — the failure mode is not unsupported guessing but not knowing *what* to ask.
- **Readiness assessment is unreliable on real specs**: GPT-5.6-Sol reaches 67.5 Macro-F1 on real-world Task 1 (86.4 on synthetic) vs Claude Sonnet 5's 59.3; it wrongly accepts 31% of underspecified specifications and rejects 34% of codification-ready ones. Its best Reason Grounding Score is only 0.36 (real) / 0.49 (synthetic), and only 1.5% of Task 1 predictions are both correct and fully grounded.
- **Oracle clarification utility is large**: on 50 paired real-world instances, supplying the gold resolution raises the downstream codification-ready rate from 14% to 98% (+84, CI [72.0, 92.0], p < 0.001), completeness from 30% to 98%, and missing-detail recovery from 14% to 98%; unsupported-assumption rate falls 6% → 0% (descriptive only — 3 discordant instances, McNemar p_adj = 0.250).
- **Executable validation**: on 20 controlled instances with reference implementations, oracle-resolved specs raise implementations passing all predefined tests from 45% to 85% and faithful instantiation of the target method detail from 30% to 90% (runnability 70% → 95%) — code can pass tests while implementing a *different* methodological choice, which is precisely the failure IdeaAMBIG targets.
- **A taxonomy-free ablation on 50 real instances** shows GPT-5.6-Sol improves from 10.0% to 40.0% when evaluated only for same-blocker identification (dropping Level-1/2 label requirements): taxonomy prediction adds substantial difficulty, but localization remains hard even label-free; human evaluators substantially outperform the model on the same sample.
- **Annotation quality**: pre-adjudication Cohen's κ is 0.84/0.92 (readiness), 0.89/0.89 (Level-1), 0.92/0.85 (Level-2) on real/synthetic subsets, with target-defect agreement 87.7%/84.0%; source-balanced estimates shift GPT-5.6-Sol's numbers by at most 0.6 points, preserving all main findings.

## Authors & Credibility

The team is from Yale University (Yiling Ma, Yilun Zhao — corresponding author of the LILY/DRAMATIC group known for code-generation and scientific-LLM benchmarks, e.g., work cited here as Zhao et al. 2025a — Sihong Wu, Arman Cohan) and TCS Research (Manasi Patwardhan). Arman Cohan's group has a strong track record in NLP for science, reproducibility, and LLM evaluation, which fits this paper's positioning exactly. The benchmark pipeline is unusually transparent for its scale: a 74-page artifact with full appendices documenting taxonomy derivation, annotation protocols, judge validation against humans, source-clustered bootstrap CIs, and code released ("Code: IdeaAMBIG"). The instance construction leans on commercial models (DeepSeek-V4-Pro for extraction/routing, GPT-5.5 for validation, Claude Opus 4.8 as judge), but each stage is cross-checked against adjudicated human annotations, and the headline κ values (0.84–0.92) are solid for this kind of taxonomy task.

## Critical Assessment

- **Novelty: high.** The specific question — is the *method-defining mechanism* of an idea specified well enough to implement faithfully — is genuinely under-explored between idea-quality benchmarks (Novex, ResearchAgent-era evaluations) and paper–code consistency checks. The decomposition into localization vs clarification, and the Defect-Guided/End-to-End controlled comparison, is a clean experimental design that many benchmark papers skip.
- **Rigor: strong, with caveats.** The bottleneck claim (+67.0 Macro-CAS) rests on a same-model paired design with bootstrap CIs and survives source-clustered analysis. However, the source-level analysis also concedes that **five of six paired GPT-5.6-Sol vs Claude Sonnet 5 comparisons are not reliable** — model rankings on Tasks 1–2 should be read as noise-level except for the localization-is-hard finding itself.
- **Reproducibility concerns**: instances were machine-generated and machine-filtered (DeepSeek-V4-Pro, GPT-5.5) before human verification; residual construct noise from LLM-authored specs is plausible even with κ ≈ 0.85–0.92 on labels. The judge (Claude Opus 4.8) is validated against humans but remains automated; contamination of eval models with GitHub/MLRC sources is not discussed.
- **Scale quirks**: the real-world subset is only 163 instances (42 from reproducibility reports + 121 from GitHub issues), drawn from just 3 source families concentrated in CV/NLP — the "9.6% Macro DRR" headline generalizes to AI-adjacent ML papers, not all research software. Task 1 is scored on a balanced 200-spec sample (100 READY/100 NOT-READY per subset), a small evaluation base; the oracle study uses N=50 and the executable study N=20, so several striking deltas (98% ready rate, 90% fidelity) carry wide CIs the paper does report but that get lost in the abstract.
- **Single-defect abstraction**: real specs often have multiple interacting gaps; the paper audits this (94.5% target uniqueness; a 50-pair multi-defect ablation finding no added difficulty) but admits the ablation has a response-count asymmetry, so the abstraction's ecological validity is only partially tested.
- **Overclaiming risk**: the abstract's "14% to 98%" is an *oracle* upper bound (gold resolution supplied), not end-to-end agent performance — the paper says so explicitly, but readers skimming the abstract may over-credit current systems. Conversely, the 9.6% DRR partially reflects the strict joint criterion (blocker + both taxonomy labels); the taxonomy-free ablation (40.0%) shows models are less hopeless than the headline suggests.

## Strengths

- Clean conceptual contribution: "codification readiness" names and operationalizes a failure mode (silently implementing a *different* method) that sits between ideation and execution in research agents.
- Three-task design that surgically separates discovery from action; the End-to-End vs Defect-Guided paired experiment turns a benchmark observation into a causal bottleneck claim.
- Evidence-grounded instances with supported resolutions sourced from real reproducibility failures — rare among synthetic-gap benchmarks — plus genuinely thorough validation (blind human studies, κ, uniqueness audit, source-clustered CIs, executable fidelity check).
- The executable study's observation that test-passing code can still implement the wrong method (45% pass-all-tests vs only 30% target fidelity under Direct generation) is a quietly important result for anyone equating unit-test success with implementation faithfulness.

## Limitations

- Domain concentration in AI/NLP/ML (inherited from MLRC/ECIR/GitHub sources); transfer to other computational sciences is untested.
- Small real-world subset (163) and small oracle (N=50) / executable (N=20) studies; several key deltas have wide confidence intervals.
- Clarification is evaluated as a single action with the gold resolution supplied in utility studies; multi-turn clarification, choosing between asking vs inspecting artifacts, and knowing when enough information has been gathered remain open.
- Heavy reliance on frontier commercial models for instance construction and judging; potential contamination and construct-shift risks are not analyzed.
- Front-model ranking (GPT-5.6-Sol vs Claude Sonnet 5) is mostly not statistically reliable under source-clustered analysis, so the leaderboard table should be read as tiers, not orderings.

## Relevance

直接命中"LLM 科研代理 / 研究自动化"与"评测基准"两个方向：它量化了从研究想法到可信代码实现之间被忽视的规范缺口问题，并给出可复用的基准、缺陷分类法（3 级一级 + 10 级二级）与"定位-澄清"解耦的评测协议，对设计能主动提问而非默默臆测的编码/科研 agent 有直接指导意义。

## Questions for Further Exploration

- Can agent scaffolds (iterative self-questioning, artifact inspection tools, retrieval over the source repo) close the 67-point localization-vs-clarification gap without being handed the defect, or is blocker discovery a fundamental perception limitation of current LLMs?
- Does training on IdeaAMBIG-style single-defect instances transfer to naturally multi-defect specifications, given the paper's own admission that the multi-defect ablation was underpowered and response-budget asymmetric?
- Could the benchmark extend to non-AI computational sciences, and would the 10 Level-2 taxonomy categories (e.g., Conflicting Objective, Missing Evaluation Specification) survive re-annotation there?
- Since oracle resolutions raise test-passing from 45% to 85% but target fidelity from 30% to 90%, what test suites would actually discriminate faithful implementations from plausible-but-wrong ones — can fidelity-aware test generation be automated?
- How do defect-granularity effects (coarse missing-component vs local ambiguity) interact with model scale and reasoning budget — is the 9.6% DRR dominated by fine-grained blockers?
