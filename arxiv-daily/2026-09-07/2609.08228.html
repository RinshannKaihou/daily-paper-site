…together with −32% input tokens per attempt (5.06M → 3.45M) — near the vector-compression regime (3.11M) at far higher reward.

Why this matters

Experience should be deposited in retrieval infrastructure — not model weights or skill files — as agent skill libraries scale past a thousand entries.

「经验应该沉淀在检索基础设施，而非模型或技能内容里。」

⚠ Critical edge

Every gain except the full method's +7.0 sits inside the authors' own ±6–7-point noise band — direction supported, magnitudes unresolved.

The held-out +5.4 is admitted to be inside the band; with only 87 tasks, one more noisy run could reorder cells.

01 · Methodology

Three training-free operators on a frozen retrieval pipeline

SE-GoS keeps GoS's Personalized-PageRank retrieval untouched and evolves only the graph it reads. Cold start is deterministic — a signature-token-overlap graph over the 1,000-skill library (863 edges), with no embedding service and no LLM pass. Every trial logs (query, reward, retrieved bundle, used skills); one offline round then applies three updates in dependency order:

  1. Topology — induce workflow edges from retrieve→use co-occurrence on successes; dependency edges from ordered use with I/O-schema overlap (ζ=0.6); avoid edges from repeated joint failure; soft-prune skills retrieved ≥2× but never used (halve their in-edges).
  2. Edge weights — Hebbian reinforcement w ← w + η·r (η=0.1) on edges into skills actually used on rewarded trials; failed trials give no credit.
  3. Descriptions — for used-but-poorly-ranked skills on failed trials, one ProTeGi-style textual-gradient rewrite, selected by offline retrieval replay, with a no-eviction guard.

Because PPR reads edge weights directly, editing the graph changes retrieval with zero code changes. Protocol per round: run 87 tasks → collect traces → update (topology → weights → node) → re-measure. Held-out variant evolves on 50 tasks, tests on the disjoint 37. Backbones: deepseek-v4-flash-0731 (main), minimax-m2.7, gpt-5.2-codex.

03 · Strengths

What holds up

  • Genuinely training-free and deployment-light: no embedding service, no LLM cold-start, no inference-time overhead, no edits to skill content or retrieval code; every delta is interpretable and reversible.
  • Clean attribution: the LLM-prior-free structural channel makes the 2³ factorial meaningful — gains can't be confounded with an LLM prior the baseline would already contain.
  • Honest statistics: noise band, disjoint held-out split, and a multi-round overfitting curve — the experiments most papers in this area skip.
  • Practical economics: −32% input tokens arrive together with the best reward; the evolved graph is a shareable, auditable artifact across agents.
  • Benchmark-fidelity audit (byte-identical verifiers vs upstream) rules out silent task weakening.

04 · Limitations

What doesn't

  • One-shot, not continual: round 2 plateaus (59.8%), round 3 overfits (54.0%) — evolution is a deployment step, not a learning loop.
  • Small evaluation surface: 87 tasks (37 held-out), one library scale (1,000 skills), three backbones; 200/500/2,000-skill scales explicitly untested.
  • Used-set extraction fragility: matching hydrated source paths in tool calls can undercount indirect skill use — the input to all three updates.
  • Untested machinery: avoid edges (empty on the main substrate) and the confidence-weighted interpolation are designed but essentially unexercised.
  • Unresolved magnitudes: most component gains and the held-out +5.4 sit inside the ±6–7-pt noise band.

05 · Open questions

Where this leads

  1. Would per-domain or per-task-cluster evolution windows (instead of one global round) prevent round-3 overfitting and enable continual deployment?
  2. Can the “alternative” relation be recovered without an LLM prior if traces logged step-ordered skill use — abandoned-attempt evidence, as the paper hypothesizes?
  3. How do the gains behave at 2,000+ skills, where hub collapse and lexical-seed sparsity stress the token-overlap substrate far more?
  4. Does execution-derived structure compose with, rather than replace, GoS's typed LLM prior — e.g., initializing from the typed graph and letting traces re-weight it?
  5. Given selection isn't the binding constraint once used skills are reachable — what is the failure-mode breakdown of the remaining ~40% of attempts?

06 · Provenance & credibility

Who and how solid

  • Team: Peking U. / Tencent · U. Edinburgh · Northwestern · Tencent · Tsinghua — an industry–academia mix.
  • Lineage: builds on GoS (arXiv:2604.05333); re-measures SkillDAG (arXiv:2606.03056) under its own protocol rather than quoting numbers.
  • Fidelity: byte-level audit vs upstream SkillsBench v1.1 — 0/87 task packages differ (one dependency pin, next@14.2.10).
  • Reproducibility: strong — deterministic cold start, tabulated hyperparameters (α=0.2, η=0.1, θobs=2, θavoid=2, nrank=3), pseudocode, named split file; hazards: Docker harness complexity, proprietary backbones.
  • Red flags: none outright — the chief overclaim risk is the “self-evolving” framing for what is a one-shot batch update.
