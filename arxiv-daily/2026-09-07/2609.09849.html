01Methodology — How the Trap Is Built

Each instance is a real experiment package — Batfish, Zeek, P4C, Open vSwitch artifacts — with exactly one integrity violation injected, grounded in the source project's own semantics (scope containment, trace provenance, metadata binding, temporal ordering).

  1. Freeze with a validation gate. An instance ships only after a reference repair passes and seeded incorrect repairs fail.
  2. Run in isolation. Fresh workspace per execution; the agent sees only the public package and task contract (permitted commands, required outputs, citation rules). Mutation, required repairs, and preservation obligations stay hidden.
  3. Score deterministically. A contract scorer matches structured findings against expected violations, then checks repair completeness, claim preservation, parseability, and traceability (valid evidence references, exact public claim identifiers). Pass = every obligation jointly — no partial credit.

23 configurations × 52 instances × 5 repetitions, runtime builds pinned (Codex CLI 0.142.3–0.144.5; Cursor 2026.07.01/.23; OpenCode 1.17.15). Network-specialized agents (Confucius, NetAssistant, ArachNet) are deliberately excluded to isolate pure artifact-integrity reasoning.

02What the Paper Introduces

  • “Artifact integrity” as an evaluation dimension. Every claim in a record must stay supported, scoped, and traceable — absent from SWE-bench, NetAgentBench, NIKA, Cornetto.
  • Claim–Evidence–Scope model. Experiment packages as graphs with a decidable integrity condition; observed / supported / unsupported labels. A light adaptation of PROV-DM / RO-Crate provenance lineage.
  • Five auditable failure modes:
    • residual inconsistency
    • unsupported replacement
    • support damage
    • lost traceability
    • invalid package
  • The 5,980-output empirical study quantifying the local-correction vs record-level-repair cliff, plus run-to-run instability.

04 · Strengths

  • New evaluation axis. Record-level integrity is genuinely absent from SWE-bench, NetAgentBench, NIKA, Cornetto, and FEVER-style fact verification.
  • Gaming-resistant scoring. Deterministic, oracle-grounded joint contract; instances frozen only after reference repairs pass and seeded wrong repairs fail.
  • Real artifacts, not toys. All 52 instances derive from public Batfish, Zeek, P4C, and Open vSwitch repositories.
  • A measurable difficulty curve. The five-tier axis plus the label-vs-pass gap cleanly localize the failure: coordinated propagation, not classification.
  • Honest instability reporting. 27.7% mixed pass/fail pairs — a number many benchmark papers omit.

05 · Limitations

  • Small, narrow pool. 52 instances from 4 repositories; ~10 per tier makes tier curves noisy; no routing at scale, telemetry, or wireless artifacts.
  • Injected, not natural, drift. Probes repair capability only — says nothing about how often drift occurs in real deployments.
  • Strict scorer. Parseability and exact-identifier requirements can fail semantically valid repairs; 65.3% may understate semantic competence.
  • No failure-mode attribution. The five-mode taxonomy is never bound to the 2,076 failures.
  • Hidden costs. Cost, latency, and tokens are tracked but never reported; the +8.8-pt effort gain's price is invisible.
  • Scope & variance. Specialized agents excluded by design; free-inference endpoint adds unmodeled variance (MiniMax M2.5 ±10.0 pts); no public release yet.

06Open Questions

  1. Which failure mode drives the Tier 4–5 collapse — context management, the runtime's edit model, or the LLM's relation inference?
  2. Would network-specialized agents (Confucius, ArachNet) with built-in simulators and telemetry close the Tier 4–5 gap — or is record-level repair a different capability than task completion?
  3. Does a more permissive semantic scorer raise or lower the 65.3% average contract pass?
  4. Can naturally occurring drift be harvested from real agent-assisted workflows (CI logs, measurement campaigns) to build a distributionally valid benchmark?
  5. Would provenance tooling as a runtime primitive (claim-to-evidence linking) beat effort scaling, which only bought +8.8 points from low to xhigh?
  6. Is the 27.7% run-to-run instability sampling noise or genuine near-boundary competence — and can a five-repetition protocol tell them apart?
