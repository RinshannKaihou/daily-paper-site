> **一句话总结：** 本文把端到端"自主科研"代理（单代理 autoresearch 循环与多代理 AutoScientists 团队，底层用 Claude Sonnet 5 / Cursor Composer 2.5 / GPT-OSS 120B）首次搬到开放式的工业级任务——电信工单检索（25 万工单 + 20.4 万故障分析 + 8.9 万技术分析），代理发现的最优单模型微调 MPNet 检索器达到 Recall@1 0.343（人工微调 MPNet 为 0.200、人工集成系统 0.251、内部人工 SoTA 0.380 的约 90%），且只用 10 周 / 每个 Cursor campaign 约 150–200 美元（对比人工 10 个月）；但多代理结构、代理选择、是否告知 SoTA 配方对峰值性能几乎无影响，代理始终不会提出重排序、数据增强、模型集成这类"跳出框架"的方案。

> **TL;DR:** A case study running autonomous LLM-research agents (Karpathy-style single-agent loop and AutoScientists multi-agent teams, powered by Claude Sonnet 5, Cursor Composer 2.5, or GPT-OSS 120B) on an open-ended industrial task: telecom ticket retrieval over a proprietary Nokia dataset of 250k tickets / 204k fault analyses / 89k technical analyses, evaluated with Recall@k on 7.6k held-out queries. The best agent-discovered system — a single fine-tuned MPNet bi-encoder with cluster-aware pair sampling — reaches Recall@1 = 0.343 vs 0.251 for the human-designed ensemble baseline (+9.2 pts) and 0.380 for the human internal SoTA (−3.7 pts, i.e., ~90% of SoTA), at $150–200 per Cursor campaign and 10 weeks end-to-end vs ~10 months of human engineering. Surprisingly, framework structure, agent choice, and informing agents of SoTA recipes all had negligible impact on peak performance; agents never attempted re-ranking, data augmentation, or ensembling, and needed human "babysitting" for operational failures.

## 核心贡献

- **首个面向"开放式"工业级任务的自主科研实证研究**：此前的端到端自主 ML 研究（AI Scientist、autoresearch 等）多局限于窄搜索空间（如语言建模 loss）；本文将其推广到电信工单检索（TTR）——自由度涵盖文档表示/预处理 P、训练数据生成（正/负样本采样）、架构与超参数 λ、编码器权重 θ 的联合搜索。
- **给出可复用的"运行稳定性"harness 设计**：显式的任务/环境文档、强制拓宽的搜索空间定义（单代理用变量抽象、多代理按"表示 / 数据生成 / 架构超参"分三个团队）、以及用确定性 bash 外层循环取代不可靠的代理自管理循环——这些是让当今代理跑通长周期科研 campaign 的关键工程手段。
- **系统的三维消融**：跨框架结构（单代理 vs 多代理）、底层代理（Claude Sonnet 5 / Cursor Composer 2.5 / GPT-OSS 120B）、知情程度（是否在文档中告知人工 SoTA 组件）共 8 个 campaign（Table 3），发现三者对峰值下游性能影响均可忽略——与窄搜索空间任务上"多代理更强"的既往结论相反。
- **诚实的成本-收益核算**：自主科研 10 周达到人工 10 个月成果的约 90%（Recall@1 0.343 vs 0.380），每个 Cursor campaign 约 $150–200（Claude 约 2–3 倍，本地 GPT-OSS 近零 API 成本）；结论是"自主科研 + 人类直觉互补"是当前最优工作方式。
- **详尽记录代理的失败模式**：GPT-OSS 数十次尝试仅 1 次成功 spawn 子代理；各代理普遍低估可用 GPU 显存、提前停止或闲置；Cursor 重复执行相同实验；Claude 倾向去调试环境脚本而非跑实验；即便文档明示，也没有代理尝试重排序/增强/集成。

## Key Contributions

- **First empirical study of autonomous research on an open-ended, industry-grade ML task.** Prior end-to-end autonomous-research successes were confined to narrow search spaces (language modeling loss, biomedical benchmarks); this work targets telecom ticket retrieval (TTR), where the search space jointly spans document preprocessing/representation P, training-data generation (positive/negative pair mining), architecture/hyperparameters λ, and encoder weights θ.
- **A reusable "operational stability" harness.** Explicit task/environment documentation, a forced search-space definition (variable abstraction for the single agent; three teams covering representation, data generation, and architecture/hyperparameters for multi-agent), and a deterministic outer bash `while` loop replacing unreliable agent self-management — concrete engineering recipes for making today's agents survive long research campaigns.
- **A systematic three-axis ablation across 8 campaigns** (Table 3): framework structure (single- vs multi-agent), underlying LLM (Claude Sonnet 5, Cursor Composer 2.5, GPT-OSS 120B), and informedness (whether human SoTA components are documented). All three axes had negligible impact on peak Recall@1 — contradicting both multi-agent superiority findings and benchmark-based expectations that stronger reasoning yields stronger research.
- **Honest cost accounting.** Autonomous research reached ~90% of the human internal SoTA (Recall@1 0.343 vs 0.380) in 10 weeks versus ~10 months of human engineering, at $150–200 per Cursor campaign (Claude ~2–3x; locally hosted GPT-OSS near-zero API cost).
- **Detailed documentation of agent failure modes**: GPT-OSS succeeded in spawning sub-agents only once across dozens of attempts; all agents underutilized GPU memory, went idle or stopped prematurely; Cursor re-ran duplicate experiments; Claude debugged environment scripts instead of experimenting; and no agent ever attempted re-ranking, data augmentation, or model ensembling even when explicitly informed of these SoTA techniques.

## Methodology

**Task formalization.** TTR is dense document retrieval: given incident queries q (tickets T), retrieve relevant resolution documents (fault analyses FA, technical analyses TA) via cosine similarity of encoder embeddings. The objective jointly optimizes a preprocessing function P, hyperparameters λ, and encoder weights θ to maximize top-K recall. Documents form clusters (one FA spanning multiple Ts, each T possibly with TAs), and a retrieval is correct when query and retrieved document belong to the same cluster. The dataset contains 250k tickets, 204k fault analyses, and 89k technical analyses; evaluation uses 7.6k held-out queries competing against the entire corpus for 1.2k gold resolution documents, reported as Recall@k.

**Autonomous research implementations.** Two framework structures are studied: a single-agent loop extended from Karpathy's `autoresearch` (a CLI coding agent that reads repo state, modifies parameters, runs trials, and commits/reverts based on metric change) and a multi-agent team extended from AutoScientists (an orchestrator spawns sub-agents for hypothesis generation, code modification, and data analysis, communicating via a messaging board). Three backends: Claude Sonnet 5, Cursor Composer 2.5, and GPT-OSS 120B hosted on Ollama behind the open-source Pi coding agent.

**Operational harness.** (1) Explicit documentation of data structure, task scope, agent role, and the Recall@1 metric plus available hardware; (2) explicit search-space definition — the multi-agent runs assign representation / data-generation / architecture-hyperparameter search to three agent teams, while single-agent runs initialize variables mapping to representation and dataset-generation decisions (with the admitted trade-off that agents toggle predefined options rather than writing novel code); (3) a deterministic outer bash loop that resumes the agent session with a fixed "continue experimenting" prompt, replacing unreliable agent self-looping.

**Comparison systems** (all human-designed): BM25, a fine-tuned MPNet retriever, an ensemble of fine-tuned models (Trabelsi & Uzunalioglu 2026), and an unpublished internal SoTA incorporating LLM-based data augmentation, model ensembling, and re-ranking. Training used 4x NVIDIA RTX A6000 GPUs (48 GB each).

**Best discovered system (Appendix A).** A bi-encoder initialized from all-mpnet-base-v2, fine-tuned for 2 epochs (batch 32, lr 2e-5, max length 384) with Multiple Negatives Ranking Loss (InfoNCE) over cosine similarity with inverse temperature 20. Document preprocessing converts JSON-style documents to dense text with field markers and applies a two-stage cleaning pipeline (drop empty fields; strip boilerplate lines appearing in ≥5 documents). Training pairs: T-to-FA (270k base) and T-to-T peer-ticket pairs (245k base) with 2x oversampling of T-T, expanding to 760k instances; one hard negative per positive, mined from out-of-cluster tickets sharing the same product and feature metadata.

## Results & Highlights

- **Main result (Table 2, internal TTR benchmark, 7.6k held-out queries):** the agent-discovered single fine-tuned MPNet reaches **Recall@1 = 0.343**, vs **0.251** for the human-designed ensemble (+9.2 pts), **0.200** for the human fine-tuned MPNet (+14.3 pts), and **0.072** for BM25 — but falls **3.7 pts short of the human internal SoTA at 0.380** (~90% of SoTA). At Recall@10 the discovered model scores **0.630 vs 0.783** for internal SoTA and 0.400 for the fine-tuned MPNet baseline; at Recall@50 it scores **0.768** vs 0.571 (single model) and 0.627 (ensemble). Secondary metrics for the best system: MRR@10 = 0.4350, NDCG@10 = 0.2210, MAP@10 = 0.1370.
- **Efficiency (RQ2):** the best campaign (single-agent Cursor, informed) found the top model in **17 unique experiments**; a 10–20-experiment Cursor campaign costs an estimated **$150–200** in API charges, Claude Sonnet 5 roughly **2–3x more ($300–600)**, and locally hosted GPT-OSS has near-zero API cost. The 17-run campaign finished in **1 GPU-week of compute and 10 weeks end-to-end, versus ~10 months of human engineering** for the comparison systems.
- **Design axes barely matter (Table 3):** best per-campaign Recall@1 spans **0.3433** (single/Cursor/informed, 17 exps), **0.3378** (single/Claude/uninformed, 9 exps), **0.3353** (single/GPT-OSS/uninformed, 12 exps), down to **0.2400–0.2652** for multi-agent runs and **0.2043** for multi-agent GPT-OSS (only 4 experiments); half the campaigns converged to a tight 0.30–0.34 band — a locally hosted open-weight GPT-OSS with no prior knowledge matched a Claude Sonnet 5 team.
- **Informedness ablation null — for the wrong reason:** documenting the human SoTA's data augmentation, re-ranking, and ensembling did not improve performance because **no agent ever attempted to implement any of them**, regardless of documentation — even the winning "informed" run ignored the provided SoTA information (footnote 7).
- **Operational failures are agent-specific and frequent:** GPT-OSS 120B failed to reliably orchestrate sub-agent spawning (**succeeding only once across dozens of attempts**, also with the pi-subagents extension; Qwen Coder 30B campaigns failed entirely); all agents underutilized GPU memory (proposing smaller batches than fit), went idle or stopped prematurely despite "never stop" instructions; Cursor re-executed duplicate experiments (132 experiments in its multi-agent campaign for a best R@1 of only 0.2652).

## Authors & Credibility

The work is by Junghyun Min (Georgetown University; the work was performed during a summer internship at Nokia Bell Labs) together with Huseyin Uzunalioglu and Mohamed Trabelsi (both Nokia Bell Labs). The Bell Labs affiliation gives direct access to the real-world telecom ticket corpus and to the internal SoTA system (TeleDoCTR-line work by Trabelsi & Uzunalioglu) that serves as the strongest baseline, making the case study genuinely industrial rather than simulated. The authors are notably candid: they openly report null results for their own hypotheses (multi-agent superiority, reasoning-ability correlation, informedness), admit the human-vs-agent comparison is not controlled, and disclose agent failure modes in detail. The paper builds on well-known frameworks (Karpathy's autoresearch, AutoScientists, AI Scientist) and cites the relevant autonomous-research literature; no code or data release accompanies the paper, and the corpus and internal SoTA numbers are proprietary.

## Critical Assessment

- **Novelty:** Genuinely useful positioning — most autonomous-research papers demonstrate on self-contained benchmarks with a scalar loss; this is one of the first to ask whether the paradigm survives an open-ended industrial task where representation and data generation are also in the search space. The value is less in the discovered model (an MPNet variant) than in the empirical map of what breaks.
- **Rigor — the weakest flank.** The three-axis ablation is explicitly *not* a controlled experiment: campaign budgets are wildly unequal (4 experiments for multi-agent GPT-OSS vs 132 for multi-agent Cursor), axes co-vary across campaigns, and the authors themselves state the effects "are difficult to isolate" and were "not evaluated under a controlled experimental design." The multi-agent-vs-single-agent conclusion in particular rests on under-powered multi-agent runs. There is no seed-level variance reporting, and the headline 0.3433 comes from a single best campaign.
- **Reproducibility:** Low for outsiders — the corpus (250k real Nokia telecom tickets) and the internal SoTA baseline (Recall@1 0.380) are proprietary and unverifiable; no code or harness release is mentioned; cost figures are estimates ("the structure of the group's billing system" prevents exact numbers). The harness recipes and the winning model's hyperparameters are described in enough detail to imitate on similar data, though.
- **Confounds in the headline claim:** the "10 weeks vs 10 months" comparison is acknowledged as not apples-to-apples — the campaigns start from human-built documentation, dataset, codebase, evaluation pipeline, and baselines, and a human monitors and stops the loop. The single-agent search-space "variable abstraction" also pre-packages representation/data-generation decisions as toggles, so the autonomy is narrower than the framing suggests (agents pick from a menu humans wrote).
- **Red flags:** the informedness manipulation effectively failed (agents ignored the documentation), so "informing agents doesn't help" is over-read — the correct conclusion, which the authors mostly state, is that documentation alone is insufficient to induce architectural changes. The 90%-of-SoTA framing also masks that the gap (0.343 vs 0.380 R@1; 0.630 vs 0.783 R@10) is exactly the structural SoTA machinery (re-ranking, augmentation, ensembling) agents never attempted.

## Strengths

- Rare honesty: null results, failed manipulations, operational breakages, and uncontrolled-comparison caveats are reported in detail rather than buried.
- The operational harness (documentation, forced search-space definition, deterministic outer bash loop) is immediately reusable by anyone running long agentic ML campaigns, and the failure taxonomy per agent (GPT-OSS sub-agent spawning, Cursor duplicate runs, Claude environment-debugging) is actionable.
- Real industrial scale and a real SoTA target: 250k tickets and a strong internal system make the ~90%-of-SoTA claim meaningful rather than a toy comparison.
- The discovered model itself carries a transferable insight: oversampling peer-ticket (T-T) pairs 2x alongside T-FA pairs (760k effective instances) beat the human single-model and ensemble baselines built on T-FA mappings alone.
- Cost transparency per agent backend ($150–200 Cursor, $300–600 Claude, ~$0 GPT-OSS local) is the kind of grounded economics rarely reported in agent papers.

## Limitations

- Single task, single (proprietary) dataset, three agents, eight campaigns — generalization to other open-ended problems, newer agents, or other domains is unverified, as the authors concede.
- Human-vs-agent comparison is confounded: campaigns inherit human-designed data, code, evaluation, documentation, and human monitoring/stopping.
- The ablation axes (framework, agent, informedness) co-vary across campaigns and lack a controlled design or significance testing; multi-agent runs are especially under-powered (4–18 experiments).
- The evaluation covers only downstream retrieval metrics and campaign cost — no measurement of scientific-process quality, novelty, or reproducibility of the agents' research itself.
- The single-agent variable abstraction trades breadth for control: agents mostly toggle predefined options instead of writing novel code, artificially constraining "open-endedness."

## Relevance

该论文直接关乎用户对 LLM 代理自动化机器学习研究（AI for Science / autonomous research）的兴趣：它给出了当今自主科研框架在开放式工业任务上的能力边界、成本核算与运行 harness 的第一手实证。其"代理擅长窄域超参优化但缺乏架构级创造力、需要人类引导"的结论，对设计任何 agent 驱动的自动实验流水线都有直接参考价值。

## Questions for Further Exploration

- Would the null results for multi-agent structure and agent choice persist under controlled budgets (equal experiments per campaign) and multiple seeds per campaign?
- Can scaffolded interventions — e.g., tool APIs for re-ranking or ensembling, or reward shaping that credits architectural diversity — push agents beyond single-model fine-tuning, given that documentation alone failed?
- The winning insight (2x oversampled peer-ticket T-T pairs) was found by the agent — would a human-guided hybrid that combines the discovered retriever with the SoTA's re-ranking/augmentation stack exceed the internal SoTA (0.380 R@1)?
- How do the findings transfer to open-ended tasks outside retrieval (e.g., generation, structured prediction), and to more recent agent systems that may not need the operational harness?
- What is the minimum viable harness? Which of the three components (documentation, search-space definition, deterministic outer loop) contributes most to campaign stability?
- Can campaign-level cost be predicted from task openness (size of the P/λ/θ search space), enabling a build-vs-buy decision between agentic and human research upfront?
