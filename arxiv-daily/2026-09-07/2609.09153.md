> **一句话总结：** 提出 Procedural Graph（PG）——把"接下来该做什么"的程序性知识表示成 (步骤, 关系, 步骤) 三元组构成的有向属性图：在线时定位当前节点并由指导 LLM 把 2-hop 子图翻译成情境化建议注入 solver，离线时由 LLM 精炼器对比成败轨迹做"验证集门控"的图编辑自进化；在 7 个基准 × 4 个 LLM 的 24 个设置中 21 个排名第一（如 BFCL v3 上 67.00% vs 最强基线 58.00%，+9.00 分），且从零开始自进化出的图能超过手工设计图、还能修复有害的专家先验（MultiChallenge 上从 58.93% 恢复到 92.86%）。

> **TL;DR:** Analogous to how a knowledge graph stores (entity, relation, entity) facts, a Procedural Graph stores (procedure, relation, procedure) triplets — an editable attributed graph whose edges carry condition/guidance/pitfall text. At each step the agent localizes its active node, and a guidance LLM translates the 2-hop neighborhood into soft situational guidance; offline, an LLM refiner contrasts failed vs. successful trajectories and edits the graph, with edits committed only if held-out validation score does not drop (plus a rejection memory to discourage repeated bad edits). With an identical ReAct solver across 7 benchmarks and 4 LLMs, PG ranks first or joint-first in 21/24 settings (19 wins / 2 ties / 3 losses vs. the strongest baseline per setting, sign test p = 4.3e-4), e.g. +9.00 points on BFCL v3 over the best baseline with Gemini 3.5 Flash (67.00% vs 58.00%), while its gains are marginal on HotpotQA (−0.90 to +1.30) and it costs ~2.5x tokens. Self-evolution from scratch beats the hand-crafted expert graph on HotpotQA (78.79 F1 vs 76.61) and repairs an initially harmful expert prior on MultiChallenge (58.93% → 92.86%).

## 核心贡献

- **程序性知识图谱（Procedural Graph, PG）表示**：首创性地将 agent 的"该做什么、什么顺序、什么条件"知识组织为有向属性图 G = (V, R, E, Φ)，边是 (步骤, 关系, 步骤) 三元组，每条边带三个文本属性（condition / guidance / pitfalls），与知识图谱的 (实体, 关系, 实体) 形成直接类比。
- **在线生成式指导（Generative Guidance）**：每步用上一动作精确匹配定位当前节点，抽取 2-hop 连通子图（匹配失败则回退全图），由指导 LLM 结合最近 w=3 步轨迹窗口生成情境化建议，以"软注入"方式加进 solver 提示——引导而不强制，保留推理自由度。
- **离线自进化闭环 + 验证门控**：LLM 精炼器对比高/低分轨迹，提出 Add/Delete/Update 结构化图编辑；只有当独立验证集分数不下降时才提交（否则回滚），被拒编辑进入 rejection memory 作为负证据反馈给下一轮，避免重复提出失败编辑。
- **免人工的图构建与专家先验修复**：从最小骨架出发自进化的图（Scratch + Online Evolution）在 HotpotQA 上超过手工专家图（F1 78.79 vs 76.61）；当专家图本身有害时（MultiChallenge 上把成功率从 87.50% 拉低到 58.93%），迭代进化能恢复到 92.86%（+33.93 分）。
- **大规模系统评测**：7 个基准（HotpotQA / MultiChallenge / GDPval / ALFWorld / τ-bench / BFCL v3 / EnterpriseArena）× 4 个 LLM（Claude Sonnet 4.6、Gemini 3.1 Pro、Gemini 3.5 Flash、Grok 4.1 Fast）× 7 个基线（共享同一 ReAct solver），21/24 设置第一。

## Key Contributions

- **A procedural-knowledge graph representation**: a directed attributed graph G = (V, R, E, Φ) whose edges are (procedure, relation, procedure) triplets with three textual attributes — condition, guidance, pitfalls — making admissible transitions explicit the way knowledge graphs make facts explicit.
- **Online generative guidance**: at each decision step the agent localizes its active node by exactly matching its last action (e.g. a tool call) to a node, extracts the h=2-hop neighborhood, and a guidance LLM (sharing the solver's underlying model) translates the subgraph plus a w=3-step trajectory window into situational guidance appended to the solver prompt — steering without dictating.
- **Offline self-evolution with validation gating and rejection memory**: an LLM refiner partitions diagnostic rollouts into successes vs. failures, identifies repeated error loops and multi-step shortcuts, and proposes structured Add/Delete/Update edits; a candidate graph is committed only if its held-out validation score is ≥ the cached score, and rejected candidates are logged as negative evidence for the next round.
- **Graph construction without experts**: starting from a minimal skeleton, self-evolution matches or surpasses hand-designed graphs and can repair a flawed expert prior that initially *hurts* performance.
- **A broad, controlled evaluation**: 7 benchmarks × 4 frontier LLMs × 7 memory/workflow baselines, all sharing an identical ReAct solver and greedy (temperature-0) decoding, with 95% CIs and a sign test across 24 model–benchmark settings.

## Methodology

The framework alternates two phases. **Online inference (graph frozen)**: given query q and trajectory T_t, the agent's most recent action is matched against node set V to localize u_t; the h-hop directed neighborhood N_h(u_t) (or the full graph if matching fails) is extracted, and a guidance LLM Ψ generates step-level guidance g_t from the subgraph, query, and a recent trajectory window. g_t is appended to the solver prompt, and the solver samples a_t ~ P_solver(q, T_t, g_t) — soft integration that steers toward valid tool sequences while preserving reasoning freedom. Edge attributes (condition/guidance/pitfalls) are read in topological context so prerequisites and consequences of the next step stay connected, which independent top-k retrieval of rules (à la AutoGuide) loses.

**Offline evolution**: each round runs four steps. (1) Diagnostic rollout on a training batch records traces with scores; (2) an LLM refiner contrasts high- vs low-scoring traces and emits a structured edit set ΔG (Add missing verification nodes/edges, Delete transitions that repeatedly cause failure; attribute updates are encoded as delete-then-re-add), with cycle repair on application; (3) validation gating evaluates structurally valid candidates on an independent D_val and commits only non-degrading edits; (4) rejected candidates plus their trajectories go into a rejection memory supplied to the refiner next round as negative evidence. Experiments use identical ReAct solvers across PG and all baselines (Vanilla ReAct, MemoryBank, RAP, ExpeL, AutoGuide, AWM, KnowAgent), with every learning-based baseline consuming the same training trajectories; guidance model and refiner always share the solver's LLM; all calls use temperature-0 greedy decoding. Splits are documented per benchmark (e.g. HotpotQA 1000/1000/1000 train/val/test; EnterpriseArena 50/50 episodes, 132-month horizon with three undisclosed crises).

## Results & Highlights

- **Main grid (Table 1)**: PG ranks first or joint-first in **21 of 24** model–benchmark settings; vs. the strongest baseline per setting: **19 wins, 2 ties, 3 losses** (one-sided exact binomial sign test, **p = 4.3×10⁻⁴**).
- **Largest margins**: on **BFCL v3 with Gemini 3.5 Flash, PG reaches 67.00% vs. 58.00%** for the best baseline (**+9.00 pts**); on **GDPval with Gemini 3.1 Pro, 78.78 rubric score vs. 71.37 (RAP), +7.41**; on **τ-bench with the same model, 80.00% Pass@1 vs. 73.04% (RAP), +6.96**. On GDPval and BFCL v3, PG beats every baseline under all four LLMs.
- **Weak spot is honest**: on **HotpotQA margins over the strongest baseline range from −0.90 to +1.30 points** (e.g. Claude Sonnet 4.6: PG 74.50 vs. AutoGuide 75.40) — the headline gains do not generalize uniformly across task types.
- **Long-horizon resilience (EnterpriseArena, up to 132 months, 3 undisclosed crises)**: PG raises full-horizon survival from **44.0% → 58.0%** (Claude Sonnet 4.6), **6.0% → 34.0%** (Gemini 3.1 Pro), and **26.0% → 40.0%** (Grok 4.1 Fast, also best average enterprise score $39.62M). The key learned behavior is anticipatory fundraising: unguided Gemini 3.5 Flash raises **$0.00M** capital vs. **$9.39M** for PG-guided Flash (PG-guided Grok: $30.11M); guidance cuts redundant tool calls from **18.94 to 12.53 per month** on Flash while *increasing* calls on under-active models (Gemini 3.1 Pro: 0.89 → 3.18/month) — it changes *which* tools are called and when, not just how many.
- **Construction study (Table 2, HotpotQA)**: **Scratch + Online Evolution (Mode 5) achieves 78.79 Ans F1 / 66.30 EM vs. 71.21 / 58.8 for the unguided baseline (+7.58 F1, +7.50 EM)**, beating the hand-crafted expert graph (76.61 F1). On MultiChallenge, the hand-crafted expert graph *hurts* (58.93% overall vs. 87.50% unguided) and a single static update hurts more (53.57%), while iterative evolution **recovers to 92.86% (+33.93 over expert initialization)**.
- **Self-evolution trace (EnterpriseArena, 10 rounds)**: validation survival goes 0.0% → 45.0% in Round 1 (sequential backbone: audit cash → forecast runway → financing) → 80.0% in Round 2 (adds recall_notes; tool usage drops from **17.23 to 3.08 calls/month**) → 90.0% by Round 8; Round 10 is rejected and the loop terminates. The returned graph achieves **85.0% test survival vs. 0.0% baseline (Fisher's exact p = 2.6×10⁻⁸)** — the authors report 85.0% rather than the 95.0% best round observed, explicitly to avoid selecting on the test set.
- **Efficiency ablation (Gemini 3.5 Flash, Table 3)**: localized generative guidance is best on all three benchmarks — MultiChallenge **89.31** acc, GDPval **63.99** rubric, ALFWorld **81.53** success — exceeding the best alternative configuration by **2.0 / 6.8 / 9.0 points**; full-graph generative guidance crashes ALFWorld to **54.48 (vs. 72.58 no-graph)**. Localization cuts tokens vs. full-graph generative by 70.9% (ALFWorld) / 18.1% (GDPval) / 14.8% (MultiChallenge) and reduces solver steps on GDPval/ALFWorld (28.20 → 18.57; 21.84 → 18.80), but total tokens remain **+33.4% (GDPval) and +55.4% (ALFWorld) over the no-graph baseline**; on HotpotQA, Mode 5 uses 10,116 tokens / 31.53 s latency vs. 4,003 / 18.06 s for the baseline (~2.5× tokens, ~1.75× latency).

## Authors & Credibility

Author team is Yuxing Lu (Google, Georgia Tech, Peking University), Yicheng Chen and Shanchan Wu (Google), and Sercan Ö. Arık (Google, corresponding author) — an established LLM/efficiency research group with prior agent and ML-systems work. The paper reads as an industrial research lab effort: frontier commercial models (Claude Sonnet 4.6, Gemini 3.1 Pro, Gemini 3.5 Flash, Grok 4.1 Fast), careful statistical reporting (95% CIs on every cell, sign test, Fisher's exact test), full prompt templates and dataset splits in appendices, and an 8-dimension comparison of 24 related methods (Appendix A). Statistical hygiene is above average for this literature: they report the returned checkpoint rather than the best test round, and explicitly flag that EnterpriseArena's 20-episode splits make accept/reject decisions "a search trace rather than significance tests."

## Critical Assessment

- **Novelty**: The core idea is a *unification* rather than a fundamentally new mechanism — it combines AWM's induced workflows, KnowAgent's action-transition rules, and AutoGuide's state-conditioned guidelines into one editable attributed graph, then adds validation-gated topology evolution. The (procedure, relation, procedure) triplet framing is elegant and the connected-neighborhood retrieval (vs. independent top-k rule retrieval) is a genuine, well-motivated design point, but practitioners of AWM/AutoGuide will find the incremental delta modest.
- **Rigor**: Strong overall — identical ReAct solver across all seven baselines, temperature-0 greedy decoding, 95% CIs everywhere, and honest treatment of the EnterpriseArena small-n setting. However, several test sets are small with wide CIs (GDPval n=44, τ-bench n=115, BFCL v3 n=100; e.g. GDPval CIs span ±15 points), so many per-cell "wins" are within noise even if the sign test across settings is convincing. The paper never states which construction mode produced the Table-1 graphs (the construction study itself uses only Gemini 3.5 Flash), leaving a gap between the headline grid and the mode analysis.
- **Reproducibility**: Prompts, splits, hyperparameters (h=2, w=3, stride S=100/20, locked token budgets) are all in appendices, but all four solvers are commercial frozen snapshots — exact replication depends on API access, and no code or graph artifacts release is mentioned.
- **Significance**: The EnterpriseArena result is the most compelling part: a 0% → 34–58% survival flip driven by a *learned anticipatory-fundraising* behavior, with mechanism-level analysis (tool-call timing, capital raised) rather than just end scores. The expert-prior-repair result (58.93% → 92.86%) is a practically important finding: hand-written procedural priors can actively hurt, and gated evolution is a fix.
- **Red flags**: (1) Guidance is generated at *every* step, costing ~2.5× tokens and ~1.75× latency — the conclusion admits this and defers mitigation to future work; (2) the validation gate accepts ties ("≥ cached score"), which under greedy decoding can accumulate neutral-but-risky edits untested against variance; (3) HotpotQA — the one benchmark with a large test set — shows essentially no gain (−0.90 to +1.30), so the method's benefit concentrates on tool/procedure-heavy tasks, which the abstract's "consistent gains" phrasing slightly oversells; (4) LLM-judged metrics (Gemini 3.1 Pro judge for HotpotQA/MultiChallenge) make scores judge-dependent; (5) the self-evolution loop's total compute cost (training rollouts + full validation re-evaluation each round) is not reported.

## Strengths

- Clean conceptual framing: procedural knowledge as queryable triplets, directly analogous to knowledge graphs for factual knowledge.
- Connected-neighborhood retrieval demonstrably beats both raw full-graph injection and independent rule retrieval (Table 3), with the full-graph ALFWorld collapse (81.53 → 54.48) neatly isolating *why* localization matters.
- Self-evolution is well safeguarded: validation gating, structural checks before rollout, rejection memory, and rollback — the loop cannot silently degrade the graph.
- Works from a minimal skeleton with no human prior, and repairs harmful expert priors — directly addresses the manual-design bottleneck of workflow/state-machine approaches.
- Exceptional experimental breadth (7 benchmarks × 4 LLMs × 7 baselines) with statistically honest reporting, including disclosing its own weakest benchmark.

## Limitations

- Substantial token and latency overhead (every step triggers an extra guidance call; +33–55% total tokens even with localization; ~2.5× tokens on HotpotQA), acknowledged but unresolved.
- Gains are task-dependent: near-zero effect on HotpotQA multi-hop QA; benefit concentrates on procedure/tool-heavy tasks (function calling, embodied, policy-compliant, financial simulation).
- EnterpriseArena evolution conclusions rest on 20 episodes per split — the authors themselves note individual gating decisions hinge on one or two episodes.
- Learned graphs' transfer across solvers, tool interfaces, and task families is untested (deferred to future work); graphs are per-benchmark.
- Compute cost of the evolution loop (per-round training rollouts plus validation-set re-evaluation) is not quantified, and no public code/graph release is mentioned.

## Relevance

与对 LLM Agent 自我改进、程序性记忆与工具使用的关注高度相关：PG 提供了一个把"经验→可编辑结构→在线指导"闭环化的具体方案，其验证门控自进化设计对构建长时程、可靠的 agent 系统有直接参考价值。EnterpriseArena 上的提前融资行为涌现也展示了程序结构如何改变 agent 的决策时机，而不仅是决策数量。

## Questions for Further Exploration

- Can guidance be generated selectively (only at uncertain or branching steps) or cached across steps to remove the ~2× token/latency overhead without losing the gains?
- Do graphs evolved with one solver (e.g. Gemini 3.5 Flash) transfer to a different solver or tool interface, and does a cross-model validation gate change which edits get committed?
- Would a stricter validation gate (requiring a significant improvement, or evaluating under sampled decoding rather than temperature-0 ties) produce more robust graphs, or stall evolution?
- Why does PG fail to help on HotpotQA — is it that multi-hop QA lacks exploitable procedural structure, or that search-tool loops are already near the solver's ceiling?
- How does PG compare against simply fine-tuning the solver on the same successful trajectories, in both performance and total compute?
- Can the rejection memory scale: after hundreds of rounds, does the accumulated negative evidence help or saturate the refiner's context?
