Why this matters

With QKT and PV already in FP4, softmax exponentials are the remaining bottleneck — this pulls probability generation into the low-bit pipeline too.

相关性：落在 SageAttention 之后 FP4/FP8 注意力加速的关键瓶颈上，是构建「全低比特 attention kernel」的直接进展；Ascend 实测量测对推理系统选型与复现有参考价值。

!Critical edge

The 40.33% is a per-stage kernel number — no end-to-end model latency or throughput is reported, so wall-clock serving gains cannot be inferred.

And on language tasks the +0.0024 mean gain sits within the ≤0.006 batch-to-batch variation the paper itself reports.

01

Methodology

5 fused steps · 2 params

EFQ-Softmax touches only the probability path of low-bit attention. Where an FP4 kernel evaluates exp(x) in FP16/FP32, materializes a probability tile, then quantizes it to E2M1, EFQ generates the block-scaled operand directly from row-max-shifted scores:

  1. 1
    Shift & block max x = S − mi ≤ 0 · Mb = maxt∈b xt
  2. 2
    Exponent-only scale kb = ⌊(Mb + log(2/9)) / log 2⌋ · sb = 2k_b so 6·sb ≈ eM_b
  3. 3
    Residual log-domain normalization zt = xt − kb·log2 − log6 ⇒ ex_t = sb·6·ez_t
  4. 4
    Affine code generation ct = clip[0,7](⌊(zt − τ)·h⌋ + 1) → E2M1 set C8 = {0, ½, 1, 3⁄2, 2, 3, 4, 6}
  5. 5
    One operand, both branches (sb, QP) feeds ΔA = P̃V and Δl = P̃·1 — numerator/denominator stay consistent

The FlashAttention online recurrence — row-max update, α-rescaling, FP16/FP32 accumulation, final O = A/l — is untouched; masks are applied before the shift. Only (τ, h) are fitted, offline, by minimizing the relative Frobenius error of the attention output, then frozen for inference (no test-time adaptation).

03

Strengths

  • Attacks the real post-FP4 bottleneck; the producer–consumer precision mismatch is cleanly articulated.
  • Disciplined scope — only the probability path changes, making it drop-in for existing MXFP4 attention kernels.
  • Two parameters total, calibrated offline against an output-level objective; forecloses test-time adaptation concerns.
  • Evaluation breadth: three modalities, batch-size replication, an explicit 16-code ablation, per-stage µs timing.
  • Honest framing of "Exp-Free" — dense elementwise exp removed, row-level rescaling exp retained.
04

Limitations

  • Language gains are marginal (+0.0024, within batch noise) and the FP16 gap is not closed; the quality win concentrates in VL grounding.
  • 40.33% is a vector-stage number; end-to-end attention or inference latency is not reported.
  • Hardware-specific: tied to Ascend 950PR; NVIDIA/AMD FP4 transfer is claimed but not demonstrated.
  • No long-context accuracy, no perplexity, no block-size B ablation, no calibration-sensitivity study.
  • VBench rests on 14 prompts, with reduced dynamic degree and aesthetic quality vs FP16.
  • No code release — independent verification is limited.
05

Questions for Further Exploration

open threads from the paper
  1. What are the end-to-end serving latency and throughput gains (not just vector-stage), and how do they scale with head dimension and context length?
  2. How does it behave on genuinely long-context tasks (RULER, needle-in-a-haystack) — kernels are tested to 128K, but accuracy only on short-context classification?
  3. How sensitive are (τ, h) to the calibration set, model family, and value-side quantization — should per-layer calibration replace one fixed operating point?
  4. Does the exponent-only scale + affine rule transfer to NVIDIA FP4 kernels and other probability formats (INT8 attention, FP6/E3M2 codes)?
  5. Would ablating the microscaling block size B reveal an accuracy–scale-metadata trade-off that matters at very long sequence lengths?
