> **一句话总结：** 通过精心设计的测试向量系统性逆向刻画 AMD CDNA 1/2/3 三代矩阵核心（MI100、MI210/250、MI300A/X）的未公开数值行为（FMA 尺寸、对齐位宽、舍入链、次正规数处理），构建了经 10^6–2×10^7 组随机向量逐位验证的 MATLAB 位级精确模型（CDNA 3 需 4 轮迭代精化才发现"两段式向下舍入+中间归一化"链条），并用多字算术与宽带信号处理两个应用证明 AMD 的 RNE 最终舍入在 GEMM 精度上优于 NVIDIA B200 的 RTZ。

> **TL;DR:** GPU 矩阵乘法器不遵守 IEEE 754 且各架构行为未公开，导致跨设备结果不可复现。本文用特征定向测试向量加"随机测试→失配驱动的隐藏特征发现"迭代环，完整刻画了 AMD CDNA 1（MI100，fp16 N_FMA=4、bf16 N_FMA=2、全精度 Kulisch 式累加）、CDNA 2（MI210/250，成对求和、次正规数清零）与 CDNA 3（MI300A/X，N_FMA=8，24/32 位两段式向下舍入链、c=0 按指数 −126 处理、binary8 奇偶交错累加）的矩阵核心，并发布 MATLAB Tensor Core v0.6 位级模型。验证上，CDNA 1/2 在 10^6 随机样本下零失配（失配概率贝叶斯上界 1.38×10^-5），CDNA 3 经 4 轮精化后在 10^7（fp16/bf16/tf32）与 2×10^7（binary8）样本下零失配（上界 1.38×10^-6 / 6.91×10^-7）。应用层面：在 Mary–Mikaitis 多字算术高精度 GEMM 仿真中，fp16/bf16 输入下三代 CDNA 误差相当而 NVIDIA B200 误差随维度 n（至 10^6）持续更大（归因于 RTZ vs RNE）；在 8×8、8 阶多项式矩阵的 SMD/PEVD 实验（ε=μ=10^-4、250 次迭代）中 fp8 被判定不适用。相对 MMA-Sim（arXiv:2511.10909），本文修正了其对 CDNA 3 对齐位宽的报告（32 而非 31 个小数位）。

## 核心贡献

- **三代 CDNA 矩阵核心的完整数值刻画**：首次给出 AMD CDNA 1（MI100）、CDNA 2（MI210/MI250）、CDNA 3（MI300A/MI300X）矩阵核心在全部支持输入格式（fp32、fp16、bf16、tf19/XF32、fp8-E4M3/E5M2 FNUZ）下的详细数值特征——FMA 尺寸 N_FMA、对齐位宽 n_eab、最终舍入模式、次正规数与无穷/NaN 处理——并**附带全部测试向量及其推导理由**，使方法论可扩展到未来架构。
- **若干与已有文献相矛盾的新发现**：MI100 的 fp16/bf16 矩阵核心为全精度累加（n_eab=∞，Kulisch 式），与 FTTN（Li 等，CCGrid 2024）报告的"3 个额外对齐位"矛盾；CDNA 3 移位后的乘积和被向下舍入到 32 个小数位（而非 MMA-Sim 论文报告的 31 位，但与其 GitHub 仓库实现一致）；c=0 被视作指数为 −126 的次正规数（NVIDIA 则直接丢弃 c）。
- **位级精确 MATLAB 模型（MATLAB Tensor Core v0.6）**：扩展了此前仅含 10 余个 NVIDIA 张量核心模型的工具箱，新增三种 CDNA 架构模型与一个可实例化自定义变体的广义模型（correct_rounding / pair_wise_sum / global_alignment / odd_even_grouping 四类配置），兼容 GNU Octave，可经 Oct2Py 或 MATLAB Engine 从 Python 调用。
- **随机测试驱动的迭代模型精化 + 贝叶斯置信量化**：用"指数-尾数采样"与"独立位采样"两种策略生成随机输入，失配即指示特征空间不完备；用 Beta 后验给出失配概率上界（ε=10^-6 时 10^6 与 10^7 样本分别对应约 1.38×10^-5 与 1.38×10^-6）。
- **两个演示性应用量化跨厂商精度差异**：多字算术仿真高精度 GEMM（对比 MI300X 与 NVIDIA B200）与宽带阵列信号处理中的 SMD 多项式特征值分解，证明舍入模式等"微小"数值差异会经迭代算法传播并改变最终结果。

## Key Contributions

- Complete numerical characterization of AMD matrix cores across three CDNA generations (MI100, MI210/MI250, MI300A/MI300X) for every supported input format (fp32, fp16, bf16, tf19/XF32, fp8-E4M3/E5M2 in FNUZ encoding) — FMA size, alignment width, rounding modes, subnormal/special-value handling — with all test vectors and their derivations published, unlike prior work (MMA-Sim) that reported behaviours without vectors.
- Corrections to the literature: MI100 fp16/bf16 cores accumulate in full precision (n_eab = ∞, Kulisch-style), contradicting the 3-extra-alignment-bits claim of FTTN (Li et al., CCGrid 2024); the CDNA 3 shifted product sum is rounded down to 32 fractional bits, not the 31 reported in the MMA-Sim paper (though the MMA-Sim GitHub repo agrees with this paper); c = 0 is treated as a subnormal with exponent −126 on CDNA 3, whereas NVIDIA tensor cores discard c entirely.
- Bit-accurate MATLAB models released as MATLAB Tensor Core v0.6, extending a toolbox that previously contained only NVIDIA tensor-core models, with four generalized configurations (correct_rounding, pair_wise_sum, global_alignment, odd_even_grouping) that also allow user-defined variants; runs in GNU Octave and is callable from Python.
- An iterative refinement loop combining feature-targeted testing with randomized mismatch-driven hidden-feature discovery, plus a Bayesian (Beta-posterior) bound quantifying residual mismatch probability: at confidence 1−10^-6, 10^6 and 10^7 error-free trials bound p by ~1.38×10^-5 and ~1.38×10^-6 respectively.
- Two demonstration applications (multi-word-arithmetic high-precision GEMM emulation and the broadband SMD polynomial-eigenvalue-decomposition algorithm) quantifying application-level accuracy differences between AMD matrix cores and NVIDIA tensor cores.

## Methodology

The paper treats the matrix fused-multiply-add (MFMA) D = AB + C as its object of study, focusing on a single output element d = Σ a_l b_l + c. The workflow has three layers:

1. **Feature-targeted test vectors.** For each architecture × input format, bit-pattern inputs (products p_i and accumulator c built from exact powers of two) are permuted to detect: sequential-FMA vs multi-term addition structure, FMA size N_FMA (how many products enter one multi-term add), alignment bits n_eab, final rounding mode, subnormal support in inputs/outputs, and infinity/NaN semantics. Example: permuting 1, 2^-23, 2^-24 among p_1, p_2, c distinguishes ordering; varying n_eab sweeps the alignment width. Each vector's expected output is derived analytically for every candidate hardware behaviour, so a single observation can rule features in or out.

2. **Iterative model refinement with randomized testing.** An initial feature space pools everything from prior NVIDIA work (the authors' own TACO 2026 paper, Hickmann & Bradford's V100 study, Fasi et al., FTTN, MMA-Sim) plus newly discovered features. Random ensembles are generated on GPU and replayed in MATLAB; any mismatch signals an incomplete feature space and triggers investigation (this is how the CDNA 3 two-stage round-down chain and intermediate normalization were found). Two sampling strategies are used: exponent–mantissa sampling (significand uniform in [−2+2^-f+1, 2−2^-f+1], exponents uniform integers, covering normal and subnormal ranges separately) and independent bit sampling (each bit Bernoulli, redrawing infinities). Each 10^6-sample test costs ~13±1.5 min on the MATLAB side and 1–2 min on the GPU.

3. **Probabilistic validation.** With a uniform prior, the mismatch probability p_S has a Beta posterior; zero mismatches in N_ens trials gives an ε-upper bound p_ε ≈ |log ε|/(N_ens+1).

The resulting hardware models are summarized in block diagrams and two accumulation algorithms (Algorithm 1 for CDNA 3 fp16/bf16/tf19; Algorithm 2 for binary8 odd-even interleaving), and a comparison table aligns AMD features against NVIDIA V100–B200 generations. Hardware access: MI100/210/300A/300X via COSMA (Durham), MI100/250/300 via Argonne.

## Results & Highlights

- **Bit-level validation scale and bounds:** CDNA 1 and CDNA 2 models matched hardware with **0 mismatches in 10^6 random test vectors** per format per sampling strategy (Bayesian upper bound on mismatch probability 1.38×10^-5 at ε=10^-6); the CDNA 3 model needed **4 refinement iterations** and then passed at **10^7 samples for fp16/bf16/tf32 (0 mismatches, bound 1.38×10^-6)** and **2×10^7 for binary8 (0 mismatches, bound 6.91×10^-7)** — versus the initial CDNA 3 iteration which still had 1 mismatch in 10^6 samples for fp16 and tf32 (bounds 1.69×10^-5).
- **FMA-size and accumulation structure per generation:** CDNA 1 fp16 uses N_FMA=4 and bf16 N_FMA=2 with **full-precision accumulation (n_eab = ∞)** — contradicting FTTN's reported 3 extra alignment bits for MI100; CDNA 2 uses pairwise sums with **group size 4** (fp16, and bf16 with the _1k intrinsic subscript) or **2** (bf16 without), flushing subnormals to zero; CDNA 3 uses **N_FMA=8** for fp16/bf16, **4** for xf32/tf19, and **16 with odd-even interleaved accumulation** for binary8.
- **CDNA 3 rounding chain (new finding):** the shifted accumulator significand s_c is rounded down to **24 fractional bits**, the shifted product sum S_p,sum is rounded down to **32 fractional bits** — contradicting the 31 bits reported in the MMA-Sim paper (arXiv:2511.10909), though matching that paper's GitHub implementation — followed by a subnormal-aware normalization, a second RD on S_acc to 31 fractional bits, and final RNE.
- **Multi-word-arithmetic GEMM emulation (vs NVIDIA B200, matrices A∈R^10×n, B∈R^n×10, n up to 10^6, error vs binary64 reference):** for fp16 and bf16 inputs, **all three CDNA generations yield similar relative norm-wise error while B200 shows consistently larger error that grows with n**, attributed to NVIDIA's RTZ vs AMD's RNE final rounding; for fp8-e5m2, MI300X and B200 differ mainly at large n or when 6 words are used.
- **SMD/PEVD broadband signal-processing case (8×8 parahermitian polynomial matrix, order 8, ε=μ=10^-4, 250 iterations, double-precision reference):** replacing only the dominant GEMM with the bit-accurate models gives absolute dominant-eigenvalue differences of roughly **10^-3–10^-1** for fp16/bf16 across normalized frequency, with **MI210 deviating most** from the other models (SFMA structure + no subnormal support) and B200 closest to MI100 for fp16; **fp8 estimates deviated significantly more and were judged unsuitable** for this application.

## Critical Assessment

- **Novelty:** The core novelty is modest relative to the authors' own pipeline — the methodology (feature-targeted vectors + randomized refinement + Bayesian bounds) is imported from their NVIDIA TACO 2026 paper; what is new is applying it to AMD CDNA 1–3, the published test vectors, and the specific feature corrections. Those corrections are genuinely valuable: the 31-vs-32-fractional-bit discrepancy with MMA-Sim's paper text, the n_eab=∞ finding against FTTN's MI100 claim, and the undocumented c=0-exponent-−126 behaviour are exactly the kind of details that break cross-platform reproducibility.
- **Rigor:** High on the modelling side — every feature claim is backed by a derivable test vector, and validation carries explicit probabilistic bounds rather than a bare "it matches". A weak spot: the Bayesian bound quantifies mismatch probability under the two chosen sampling strategies only; the authors themselves note the input space is too large to explore exhaustively, so "bit-accurate" is a probabilistic claim (p < ~10^-6–10^-7), not a proof — the CDNA 3 model took 4 iterations precisely because targeted tests initially suggested a wrong 31-bit interpretation that only randomized testing exposed.
- **Reproducibility:** Excellent. Test vectors with derivations, the full MATLAB toolbox, and experiment code are public; models run in Octave and Python. One caveat: replicating the hardware side requires MI100/MI210/MI250/MI300A/MI300X data-centre GPUs (obtained via COSMA/Argonne), which most readers cannot access — that is precisely why the software models matter.
- **Significance:** The application studies are honest but preliminary. The authors themselves flag that the SMD/PEVD results "are not conclusive" — a single 8×8, order-8 example matrix whose error propagation is iteration-dependent and hard to attribute to any single feature; no systematic sweep over problem sizes or seeds is provided. The multi-word-arithmetic comparison uses B200 as the only NVIDIA representative (no H100/A100 curves in the plots), so the "AMD RNE beats NVIDIA RTZ" message rests on a narrow baseline.
- **Red flags:** Minor. The headline "10 million sets of random input vectors" in the abstract is the per-run order of magnitude (10^6 per format per iteration, extended to 10^7–2×10^7 for CDNA 3), not a single uniform guarantee across everything; CDNA 4 is listed in the format table but not tested (no hardware access). Discrepancies with the MMA-Sim paper's text vs its repo are reported carefully, which is a credit rather than a flaw.

## Strengths

- Supplies the missing documentation for AMD MFMA units: exact N_FMA, alignment widths, rounding chain, subnormal and special-value semantics for every input format on three GPU generations, with reproducible test vectors rather than assertions.
- The mismatch-driven refinement loop is a genuinely effective engineering pattern: randomized testing falsifies incomplete feature spaces, and the CDNA 3 two-stage RD + subnormal-aware normalization chain was discovered exactly this way.
- Probabilistic validation with explicit Beta-posterior upper bounds is more honest than most hardware-verification papers.
- The released toolbox (four generalized configurations) doubles as a design-space simulator for hypothetical matrix multipliers, not just a mirror of existing ones.
- Cross-vendor comparison table (B200/H100/A100 vs MI100/MI210/MI300A/X) is compact and immediately useful for anyone reasoning about low-precision reproducibility.

## Limitations

- No CDNA 4 (MI350) results — the authors had no hardware access at the time of writing.
- Validation is probabilistic under two specific sampling strategies; rare input regimes outside the sampled exponent combinations could still hide mismatches.
- The application studies use a single example each (one multi-word-arithmetic setup, one 8×8 polynomial matrix); the SMD error-propagation analysis is explicitly labelled inconclusive by the authors, and fp8 is dismissed as "unsuitable" from one case.
- NVIDIA comparison in applications is limited to B200; no H100/A100 application curves, so the RNE-vs-RTZ conclusion is drawn from one NVIDIA representative.
- The MATLAB-side validation is slow (~13 min per 10^6 samples), which the authors acknowledge and plan to address by porting the backend to C.
- Models cover the MFMA inner computation only; they abstract matrix shapes to the maximum supported k per instruction and do not model scheduling, tiling, or memory-layout effects of real GEMM libraries.

## Questions for Further Exploration

- How do the characterized rounding differences (RNE vs RTZ, two-stage RD chain) propagate into real DNN training/inference workloads — do FP16/BF16 gradients and activations show measurable cross-vendor divergence on identical seeds, and can the models predict it bit-for-bit?
- Does the c=0 exponent-−126 quirk on CDNA 3 (and the odd-even binary8 interleaving) interact adversely with split-K GEMM algorithms or gradient-accumulation schemes that frequently pass zero or tiny C matrices?
- Will CDNA 4 (MI350) reuse the CDNA 3 accumulation chain, or move toward the wider N_FMA=32-style designs seen on NVIDIA B200 — and can the published test vectors detect the difference in one run?
- Can the Bayesian validation be strengthened with adversarial/coverage-guided sampling (e.g., fuzzing driven by input distributions near alignment-boundary bit patterns) to push mismatch bounds below 10^-9 at feasible cost?
- For the multi-word-arithmetic route to high precision, is there an optimal word count and format choice per architecture once its exact rounding behaviour is known, and does AMD's RNE advantage persist on NVIDIA Blackwell successors if they switch to RNE?
