> **一句话总结：** 本文在 τ²-bench（加装阶段汇报义务）和自建受控测试台 StageIF 上系统测量 LLM Agent 的"任务进度自报"可靠性：大多数已部署模型在任务执行中途的汇报准确率暴跌（如 gpt-4.1 从行动前 90.6% 跌至中途 5.8–11.5%，qwen3.5-35b-a3b 在 StageIF 中途仅 1.2–2.9% 而收尾时 97.9%），且提供真值提示、常量标签、提醒、推理模式等干预均无法弥合 29–89 个百分点的缺口，因此 Agent 框架不应仅凭模型自报状态来控制任务流转。

> **TL;DR:** The paper asks whether LLM agents can act as their own progress bar. On τ²-bench telecom with an added per-reply stage tag (NEEDS_INFO/READY/POST_OBS/COMPLETED), gpt-4.1 and gpt-5.5 are correct at 90.6–99.4% of pre-action checkpoints and 87.3–88.9% after completion, but only 5.8–11.5% mid-task; the newest generation (gpt-6-astra envelope-stripped: 100.0% mid-task but 48.1% at completion) inverts the pattern and grows conservative at the finish line. A controlled testbed (StageIF, 12 scripted scenarios, 50,400 checkpoint positions, oracle-frozen gold) reproduces a significant nonterminal–terminal gap of 29.4–89.3 points on 6/7 deployments, and none of the tested interventions (gold injection, constant tag, reminder, thinking mode) closes it — while a marker-based termination config completes 13.0 fewer tasks per hundred than a no-tool-call config. Bottom line: agent frameworks should not gate control flow on model-emitted progress signals alone.

## 核心贡献

- **发现"中途失灵"（lost-mid-task）模式**：在 τ²-bench 电信域加装阶段标签汇报义务后，多数已部署模型在任务开始前和结束后汇报准确，唯独在任务实际执行中途准确率崩塌（gpt-4.1/gpt-5.5 中途仅 5.8–11.5%）；而最新一代模型（gemini-3.8-flash、gpt-6-astra、claude-opus-5）反过来中途保持 74–100% 却在收尾点过度保守（48–64%）。
- **区分"失败在哪里"与"失败长什么样"**：τ²-bench 上的中途错误多为格式正确但取值错误（82–90% 命名已过阶段）；StageIF 受控环境的下降则主要由漏报和"用工具调用代替汇报"（divergence）造成——两种环境暴露同一契约的不同失效面。
- **StageIF 测量仪器与四层失效分类法**：将汇报义务放在脚本化任务生命周期的任意位置（可关闭），在读模型输出前由 oracle 冻结正确答案，把"该不该报/报没报/报得对不对"三问解耦，逐检查点打分为 divergence / omission / malformed / wrong value。
- **有界干预检验**：真值注入、常量标签、尾部提醒、思考模式切换均不能消除缺口（提醒最大增益 +9.3 分 vs 29–89 分缺口）；撤走工具并把未完成步骤外包给他人系统使虚假完成率从 6.2% 飙升至 64.4%，说明汇报随上下文漂移而任务事实不变。
- **操作层面后果**：以标记汇报驱动的终止配置比无工具调用配置少完成 13.0 个百分点的任务（CI [+7.1, +19.4]），直接证明把控制权交给模型自报信号会伤害任务成功率。

## Key Contributions

- **Stage-dependent reporting reliability.** A systematic measurement of lifecycle-report accuracy across task stages on 19 deployed model-and-configuration bundles, showing almost every deployment is reliable at some stages and unreliable at others — mid-task collapse for most, completion-stage conservatism for the newest generation.
- **A dual-setting evaluation protocol.** τ²-bench (natural trajectories, reporting duty added without touching tasks/tools/policies) plus StageIF (12 scripted scenarios × 5 checkpoints, gold frozen by a runtime-state oracle before the model's output is read), which together separate report delivery, stage correctness, and correct withholding.
- **A four-layer failure taxonomy** (acting instead of reporting, omission, malformed report, wrong value) with a primary end-to-end metric θ (adherence) and a diagnostic conditional-validity metric φ, plus a false-completion measure — making "where" and "how" a report fails independently measurable.
- **Bounded intervention tests** showing the gap is not closed by supplying the true stage, replacing the value with a constant, adding a trailing reminder, or toggling reasoning mode; reports move when continuation context changes (false completion 6.2% → 64.4%) while task truth stays fixed.
- **Operational evidence** that termination design built on model-emitted markers costs task success (−13.0 points vs no-tool-call config), grounding the recommendation that frameworks should verify progress against independent runtime state rather than treat the model's report as control authority.

## Methodology

The study runs two complementary instruments. (1) **τ²-bench with an added reporting duty**: one instruction block requires every customer-facing reply to end with exactly one of four lifecycle tags (NEEDS_INFO, READY, POST_OBS, COMPLETED). The correct tag at each checkpoint is derived mechanically by replaying the conversation prefix in a fresh environment and reading environment state — before the model's tag is read — so report accuracy is scored independently of the benchmark's own task-success machinery (environment assertions in telecom, database comparison in retail). Eleven deployments ran the full telecom split (a twelfth, claude-opus-5, a partial split). A strict deterministic parser is primary; an envelope-stripping diagnostic separates JSON-wrapped replies from genuine non-reporting. (2) **StageIF, a controlled testbed**: 12 synthetic scenarios (6 scheduling, 6 customer support, primary language Chinese; an English breadth replication sentence-by-sentence mirrors them), each scripted from clarification through confirmation, action, reporting, and completion, yielding 5 checkpoints per scenario — four duty-active (covering all four stages) and one duty-inactive where the correct behavior is a pure tool call with no report. Assistant turns inside frozen histories are fixed script text, so checkpoints are independent. An oracle maps trusted runtime state to (duty-active?, gold stage) before model output is opened; a deterministic parser then reads presence, well-formedness, uniqueness, and final placement of the report, and exactly one failure code is assigned by priority (TRANSPORT > APP_MISS/APP_DIVERGENCE/APP_FALSE_ALARM > MALFORMED > STATE_WRONG > CLEAN). Reports are elicited in two encodings (XML `<stage>...</stage>` and JSON `{"stage": "..."}`) under three arms (baseline = stage inferred, gold-injected = true stage stated in context, static-value = constant tag), later extended to a five-arm batch (inert value, trailing reminder). Seven of nine planned deployments passed identity prechecks, contributing 50,400 checkpoint positions (a repeated-measures count over 12 scenario clusters × 20 repetitions × arms/encodings; gpt-4.1 and gpt-4.1-mini were excluded for repeated transport failures — disclosed, never imputed). Statistics use scenario-cluster bootstrap and exact sign-flip tests, with a pooled logistic GEE (deployment fixed effects) for replication; corruption gates and matched negative controls validate the oracle and verifier. Two further studies probe mechanisms and consequences: bounded interventions (tool withdrawal + delegation bundle, fully crossed follow-up; matched obligations — deferred sigil vs status sentence vs machine tag; thinking-mode A/B) and a validating rollout (12 scenarios × 6 repetitions × 8 deployments) where task success is read from environment state under alternative reporting-and-termination configurations.

## Results & Highlights

- **On τ²-bench telecom, mid-task reporting collapses for most deployments.** gpt-4.1 and gpt-5.5 (no reasoning tokens returned) are correct at 90.6–99.4% of pre-action checkpoints and 87.3–88.9% after completion, but only **5.8–11.5% mid-task**; with claude-sonnet-5, accuracy falls by at least a factor of 2.5 from the first to the last mid-task quintile even though the gold stage stays POST_OBS (e.g., gpt-4.1: 393/434 = 90.6% before acting vs 3/136 = 2.2% at Mid Q2). Across four generations of one family (gpt-4.1 → gpt-5.5 → gpt-5.6-sol → gpt-6-astra), mid-task rate moves 5.8% → 11.5% → 42.3% → 100.0% while completion rate falls 88.9% → 87.3% → 67.5% → 48.1% (last two read after envelope stripping) — the newest generation inverts the pattern: accurate mid-task, conservative at the finish line (gemini-3.8-flash, gpt-6-astra, claude-opus-5 hold 74–100% mid-task but only 48–64% at completion, and every completion-stage wrong value names an earlier state).
- **Failure composition differs by setting.** On the five deployments whose worst stage is mid-task (τ²-bench), 82–90% of well-formed mid-task errors name a pre-action state already passed and 10–18% prematurely name COMPLETED; errors cluster within trajectories (44–67% of multi-checkpoint trajectories have every mid-task report wrong on the three collapsing deployments vs 0–4% entirely correct). On StageIF, omission and tool-call divergence account for much of the decline, while wrong values contribute at most 13.6 points (post-action checkpoint) and <2 points elsewhere. Parsing matters: gpt-6-astra scores 0.0% everywhere under the strict parser but 99.6% before acting / 100.0% mid-task / 48.1% at completion after envelope stripping (Table 1).
- **StageIF reproduces a significant nonterminal–terminal gap.** Baseline-arm end-to-end adherence θ: qwen3.5-35b-a3b reports 21.7% (Wait) / 1.2% (Ready) / 2.9% (Step) / **97.9% (Done)** — Δ = −89.3 points [−93.8, −83.9]; deepseek-v4-pro 81.9/5.8/14.0/75.0 (Δ = −41.1); glm-5.1 62.5/4.2/6.7/59.0 (Δ = −34.5); qwen3.5-122b-a10b 83.5/0.0/0.0/66.2 (Δ = −38.4); qwen3.6-27b 70.2/0.8/4.6/54.6 (Δ = −29.4); deepseek-v4-flash Δ = −44.3; only gpt-5.5's CI includes zero (Δ = −4.2 [−11.5, +2.6]). In the all-arms pooled view the most extreme deployment reaches 97.4% terminal adherence but only 8.2% across intermediate checkpoints — "nineteen in twenty when the work is finished, fewer than one in ten while it is happening."
- **No tested intervention closes the gap.** Gold-injection's upper confidence limits cover at most one sixth of the observed gap on the six significant-gap deployments; the static-value arm can even hurt (Δ up to −22.0 points vs baseline, e.g., ds-v4-pro); a trailing reminder's largest gain is +9.3 points pooled against gaps of 29–89 points; a matched thinking-mode A/B shifts intermediate adherence by only −12.5 to +7.5 points against gaps of −52 to −88. By contrast, jointly withdrawing a needed tool and delegating the unfinished step raises false completion from **6.2% to 64.4%** across nine deployments with task truth unchanged. Matched obligations on the same histories: a final-reply duty reaches 99.0% vs 43.7% (status sentence) and 57.4% (machine stage report) at duty-active checkpoints — all near ceiling at the terminal checkpoint — so the deficit is stage-conditional, not an inability to emit structured output.
- **Terminal withholding fails too, and the pattern generalizes.** At post-done checkpoints most deployments re-emit a report where emitting is itself the error (false-alarm rates 63.3–100%, e.g., glm-5.1 90.4%); 6% of post-done false alarms are a bare lifecycle tag as the entire reply. A single-step IT-helpdesk task and an English translation reproduce a significant intermediate–terminal gap on 7 of 9 deployments (pooled GEE intermediate coefficient −5.435, OR 0.004; gaps from −0.8 to −76.1 points). Operationally, the marker-reporting termination configuration completes **13.0 points fewer tasks** than the no-tool-call configuration (scenario-clustered CI [+7.1, +19.4]), with premature completion stops on 1.6% of marker trajectories and missing-marker stops on 22.7%.

## Authors & Credibility

Boyang Wang (independent researcher, corresponding author), Yunhan Wang (Beihang University), and Yalun Wu (NExT++ Lab, School of Computing, National University of Singapore). The work is unusually measurement-disciplined for an evaluation paper: gold values are frozen by a runtime-state oracle before model output is read; corruption gates must collapse every success metric on blanked and value-inverted outputs; matched negative controls and an auditable evidence path (hash-frozen scenario contracts, stored raw responses, mechanically recomputed parser claims) are provided; every result carries an explicit evidence label (OBSERVATIONAL / CONTROLLED INTERVENTION / POST-TREATMENT DESCRIPTIVE / AUDIT/ENGINEERING) with interpretation boundaries. Exclusions are disclosed rather than imputed (e.g., gpt-4.1 and gpt-4.1-mini failed StageIF identity prechecks; gpt-5.5 dropped from the rollout after a serving-side outage), vendor identifier strings were verified against provider pages, and the authors explicitly refuse to present a model ranking. The 112M-token compute lower bound (111,998,943 prompt+completion tokens for successful responses across 25 run summaries) is reported in the ethics statement. The artifact release was still "planned" at submission time, subject to privacy/licensing review.

## Critical Assessment

- **Novelty:** High and well-motivated. Prior agent benchmarks score what an agent does; this paper scores what the model *tells the runtime* about remaining work, anchoring the truth in independently derivable environment state. The four-layer failure taxonomy (divergence vs omission vs malformed vs wrong value) and the duty-active/duty-inactive design are genuinely new instruments; a structured literature scan (Appendix U) found no existing benchmark doing this.
- **Rigor:** Very strong. Oracle-before-output scoring, scenario-clustered bootstrap with exact sign-flip agreement, leave-one-scenario-out GEE refits, corruption tests, breadth replication in English and a second FSM shape, and honest bundling caveats (the tool-withdrawal effect is explicitly labeled a bundle total effect). The authors repeatedly flag their own descriptive limits — e.g., stage and dialogue depth are construct-confounded by the reachable (NEEDS_INFO/READY/POST_OBS/COMPLETED) lattice (Appendix B), and the mid-task position bins are "descriptive position differences, not a causal effect of depth."
- **Reproducibility:** Mixed. Protocol, prompts (with SHA-256 prefixes), arm renderings, per-deployment generation configs, and per-checkpoint denominators are all in the appendices, but the artifact repository was not yet released at submission, and two deepseek identifiers are rolling API aliases whose weight snapshots cannot be recovered from the identifier — so exact reproduction of the *deployments* is inherently impossible over time. Proprietary endpoints (gpt-6-astra, claude-opus-5, gemini-3.8-flash) may silently change serving behavior; the authors acknowledge this and deliberately avoid rankings.
- **Significance:** Practically important for agent-framework design: LangGraph/LangChain, OpenAI Agents SDK, Google ADK, AutoGen and peers (audited in Appendix F) already consume model-emitted stop signals, and the paper quantifies a 13-point task-success cost for one such configuration plus a 6.2% → 64.4% false-completion swing under context drift.
- **Red flags / weaknesses:** (1) The strict-vs-stripped parser choice materially changes headline numbers — gpt-6-astra is 0.0% everywhere strict but 100.0% mid-task stripped — so "who reports" is partly a protocol-format artifact, and the paper's choice to strip for two JSON-wrapping deployments but keep strict for others is a judgment call (disclosed, but a reader must track two scoring regimes). (2) StageIF's scenario coverage is narrow: 12 two-tool scheduling/customer-support scripts (Chinese-primary), far from coding or long-horizon research agents the motivation evokes; the 50,400 positions are repeated measures over 12 clusters, not independent tasks. (3) Four of twelve telecom deployments were dropped from wrong-value analysis because they usually omit the tag — an analytically sensible but results-shaping selection. (4) claude-opus-5's lane mixes a partial split, a mid-run simulator swap after a quota interruption, and a thinking-mode difference from other lanes, so its "newest generation" grouping rests on 106 heterogeneous trajectories (plus an 8-task claude-fable-5.1 probe). (5) The interventions are explicitly checks, not mechanism identifications — the paper cannot say *why* the mid-task collapse happens, only that several plausible patches fail.

## Strengths

- Separates task success from protocol adherence — a task can succeed with wrong reports and fail with correct ones — avoiding the circularity of using the model's own report as ground truth.
- The frozen-oracle design (truth computed from runtime state before the model's answer is opened) is a clean methodological contribution other agent evaluations can copy.
- Failure taxonomy with a fixed priority code per checkpoint turns a vague "models are unreliable" claim into measurable, per-layer rates.
- Honest evidence labeling, disclosed exclusions, no rankings, and explicit confounding caveats throughout.
- The breadth replication (English + single-step FSM) and the operational termination experiment (−13.0 points task success) give both internal and external credibility to the core finding.

## Limitations

- Stage and trajectory position are construct-confounded in the lifecycle design, so the "stage pattern" is descriptive; no intervention isolates a mechanism, and the tested prompts/configurations do not rule out memory or reasoning as contributing factors.
- StageIF scenarios are short scripted tasks with two tools in two domains; generalization to coding agents, long-horizon research loops, or higher-action-count settings is untested.
- Deployment identifiers are point-in-time model-and-serving bundles (rolling aliases, silent endpoint changes), so measurements cannot be pinned to weights and are unsuitable for vendor comparison — a limitation the authors state but that also caps the study's durability.
- The τ²-bench analysis excludes the four usually-omitting deployments from wrong-value patterns, and claude-opus-5 rests on a partial, simulator-swapped split; per-subgroup counts are given but the groupings remain post-hoc descriptions, not a model taxonomy.
- No mitigation is proposed beyond "do not trust the model's report alone"; the paper measures the capability gap but leaves repair (e.g., runtime-owned state machines, verifier-paired early exit) to future work.

## Relevance

与"自进化 Agent 与自动化研究"中高优先级的"长程自主 Agent 系统的可靠性与可信性"方向直接相关：本文正是量化了 Agent 循环中模型自报进度/终止信号这一控制通道的可靠性，其结论（自报信号不可作为唯一控制依据、终止配置选择直接影响任务成功率）对构建可靠的长运行 Agent 和自动化研究循环具有直接的工程警示意义。

## Questions for Further Exploration

- Does the lost-mid-task pattern persist in long-horizon coding or research agents (hundreds of tool calls), or is it specific to short two-tool scripted tasks?
- Can a runtime-owned state machine (e.g., StateFlow-style explicit workflow state) fully replace the model-emitted progress signal, and what is the accuracy cost of deriving stage from tool-event traces alone?
- Is the mid-task collapse a prospective-memory failure (forgetting the obligation under action pressure) or a mis-estimated posterior over task state? The reminder and matched-obligation results hint at the former — could a per-turn obligation-activation head or a protocol-aware decoder close the gap that prompting cannot?
- How do the false-completion dynamics (6.2% → 64.4% under tool withdrawal + delegation) interact with multi-agent settings where subtasks are routinely delegated — are premature COMPLETED claims contagious across agent hand-offs?
- Would calibrating the runtime's trust in the report (e.g., requiring k consistent terminal reports or an independent verifier before stopping) recover the 13-point task-success loss of marker-based termination at acceptable cost?
