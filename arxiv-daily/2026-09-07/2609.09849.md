> **一句话总结：** 本文提出 NetArtifactBench（52 个从 Batfish/Zeek/P4C/Open vSwitch 真实工件构造、注入不一致性的修复任务），用确定性评分评测 23 种通用 AI Agent 配置在 5,980 次输出上的"工件完整性"修复能力：平均契约通过率仅 65.3%，直接矛盾修复接近满分（Tier 1 高达 98.9%），但需要推断隐式跨工件关系并传播修改的任务（Tier 4–5）通过率崩塌至 17.0–49.3%，且 27.7% 的配置-实例对五次重复中出现通过/失败混合结果——揭示"局部修正"与"完整记录级修复"之间的尖锐边界。

> **TL;DR:** A new benchmark, NetArtifactBench, measures whether AI agents can repair injected inconsistencies in network experiment records (derived from public Batfish, Zeek, P4C, and Open vSwitch artifacts) while preserving claims that remain supported by evidence. Across 5,980 outputs from 23 agent configurations (Codex, Cursor, OpenCode runtimes), the average contract pass rate is 65.3% — the best configs are GPT-5.5/xhigh on Codex (81.9%) and Claude Opus 4.8 on Cursor (80.8%), while local Qwen3 8B collapses to 1.2% — but every runtime drops sharply from directly exposed contradictions (Tier 1: 98.9%/93.8%/60.8% for Codex/Cursor/OpenCode) to inferred cross-artifact relations (Tier 5: 26.3%/28.4%/17.0%), and two hard instances receive zero passes in 115 attempts each. The paper argues artifact integrity (claims supported, scoped, traceable) must become a first-class evaluation requirement for network agents, beyond outcome-centered benchmarks like SWE-bench or NetAgentBench.

## 核心贡献

- **提出"工件完整性"（artifact integrity）这一新评测维度**：定义网络实验记录（配置、日志、报告、结构化声明）的完整性为三重性质——每条声明须有证据支持、限定在证据确立的范围内、并通过工件可追溯——并指出"结果导向"的现有基准（SWE-bench、NetAgentBench、NIKA 等）完全遗漏了这一维度。
- **形式化"声明–证据–范围"（Claim–Evidence–Scope）模型**：将实验包表示为声明、证据、范围约束、来源/阶段关系的图；给出可判定的完整性条件（存在有效支持路径 p 使得 scope_eff(c) ⊆ ctx(p)），并区分 observed / supported / unsupported 三类声明标签。
- **建立五类可审计的失败模式分类法**：残留不一致（residual inconsistency）、无根据替换（unsupported replacement）、支持损伤（support damage）、可追溯性丢失（lost traceability）、无效包（invalid package）——每种均以真实网络工件（Open vSwitch 流表、Batfish 过滤器、P4 转发、Zeek 日志）图示说明。
- **NetArtifactBench 基准本体**：52 个源自四个公开仓库的实例，按五个结构层级组织（Tier 1 直接矛盾 → Tier 5 推断未陈述的跨工件关系），配合隐藏 oracle、逐次执行全新工作区、确定性契约评分器（recall / repair / label / accusation / residual 五项指标联合判定）。
- **大规模实证发现**：23 种配置 × 52 实例 × 5 次重复 = 5,980 次输出的系统评测，量化了"局部修正 vs 完整记录级修复"的断崖，以及运行间不稳定性（27.7% 的配置-实例对出现混合结果）。

## Key Contributions

- **Names and formalizes "artifact integrity"** as a missing evaluation dimension for AI agents in network systems: every claim in an experiment record must remain supported by available evidence, confined to the scope that evidence establishes, and traceable through the artifacts encoding its support. Existing outcome-centered benchmarks (SWE-bench, Cornetto, NIKA, NetAgentBench) never test this.
- **A claim–evidence–scope formal model** (Section 3): experiment packages as graphs of claims, evidence, scope constraints, and provenance/phase relations, with a decidable integrity condition (∃ valid support path p ∈ P+c with scope_eff(c) ⊆ ctx(p)) and an observed/supported/unsupported label taxonomy, drawing on database provenance and research-object models (PROV-DM, RO-Crate).
- **A five-mode taxonomy of repair failures** (Figure 1): residual inconsistency, unsupported replacement, support damage, lost traceability, invalid package — each illustrated with concrete artifacts from Open vSwitch flow dumps, Batfish filter analysis, P4 program provenance, and Zeek logs.
- **NetArtifactBench itself**: 52 source-grounded instances from public Batfish, Zeek, P4C, and Open vSwitch repositories, organized into five structural tiers (Tier 1: fix one directly exposed contradiction → Tier 5: infer an unstated relation across tables/contexts/control-and-runtime artifacts), with a deterministic contract scorer, hidden oracle annotations, and a fresh public workspace per execution.
- **A systematic 5,980-output evaluation** across 23 agent configurations spanning three general-purpose runtimes (Codex CLI, Cursor Agent, OpenCode) and many backend LLMs, quantifying the sharp boundary between local correction and record-level repair and exposing run-to-run instability.

## Methodology

The benchmark pipeline has three stages (Figure 2). (1) **Instance construction**: facts from public Batfish, Zeek, P4C, and Open vSwitch artifacts (tests, traces, compiler outputs, expected results, phase-ordered state) are assembled into a coherent experiment package; a declared mutation injects one controlled integrity violation grounded in source-project semantics (scope containment, trace provenance, metadata binding, temporal ordering) without changing the underlying facts. A validation gate freezes each instance only after a reference repair passes and seeded incorrect repairs fail. (2) **Isolated agent execution**: the agent receives only the public package and task contract (permitted commands, required outputs, citation rules) in a fresh workspace; hidden annotations (mutation, required repairs, preservation obligations) are never exposed. (3) **Contract evaluation**: a deterministic scorer matches structured findings against expected violations (claim, field, artifact scope, observed-to-corrected value relation) and checks the repaired report for repair completeness, claim preservation, parseability, and traceability (valid evidence references plus exact preservation of required public claim identifiers). An output passes the contract only if every scored violation is identified, every repair completed, all protected claims preserved, no residual violation remains, and all artifacts are parseable and traceable. Metrics: recall = detected/|M|, repair = satisfied/|R|, label = correct/|L|, plus accusation events (attacks on protected claims) and residual violations; results are averaged within each of five repetitions and reported as mean ± sample std. The evaluation spans 23 configurations × 52 instances × 5 repetitions = 5,980 outputs, with runtimes fixed to specific builds (Codex CLI 0.142.3–0.144.5; Cursor builds 2026.07.01 and 2026.07.23; OpenCode 1.17.15, running Qwen3 8B/14B locally via Ollama and other backends via a free inference endpoint). The authors deliberately exclude network-specialized agents (NetAssistant, Confucius, ArachNet) to isolate pure artifact-integrity reasoning from environment-specific tooling.

## Results & Highlights

- **Overall contract pass rate on NetArtifactBench is 65.3%** (3,904 of 5,980 outputs). By runtime: Codex 74.2%, Cursor 71.2%, OpenCode 44.0% — a 30.2-point spread driven largely by backend choice.
- **Pass rates collapse across structural tiers**: from Tier 1 (one directly exposed contradiction) to Tier 5 (infer an unstated cross-artifact relation), Codex falls 98.9% → 26.3%, Cursor 93.8% → 28.4%, OpenCode 60.8% → 17.0% (Table 3); Tier 4 (propagate one correction across several artifacts) already drops to 49.3% (Codex), 40.0% (Cursor), 23.3% (OpenCode). No runtime exceeds 30% on Tier 5.
- **Agents satisfy individual obligations but fail the joint contract**: at Tier 5, Codex's label accuracy is 96.2% and repair rate 59.6% against a contract pass of just 26.3% (Cursor: 93.4%/58.1% vs 28.4%; OpenCode: 60.2%/35.0% vs 17.0%) — a ~70-point gap between labeling claims correctly and completing the full record-level repair.
- **Two instances are never solved**: one Tier 4 scope-propagation task and one Tier 5 join task (programmable data-plane metadata) receive zero contract passes in 115 outputs each — every returned package violates at least one declared obligation.
- **Backend and effort scaling**: GPT-5.5 under Codex rises from 73.1% (low effort) to 81.9% (xhigh); top configs are Claude Opus 4.8/Cursor at 80.8%, GPT-5.5 xhigh/Codex at 81.9%, Grok 4.5/Cursor at 78.5% and GPT-5.6 Sol at 78.5%; the weakest, Qwen3 8B local via Ollama, manages 1.2% (residual violations 3.219 per output), and OpenCode configs span 1.2–72.3% (best: DeepSeek V4 Flash at 72.3%).
- **Failure anatomy** (2,076 failing outputs; categories overlap): 68.5% leave at least one required diagnosis or repair incomplete, 47.9% omit required report information, 33.6% fail a supported-content preservation check (support damage), 22.6% return invalid structured output, 7.1% omit required artifacts, and 3.9% retain the injected unsupported conclusion outright.
- **Run-to-run instability is substantial**: 331 of 1,196 configuration–instance pairs (27.7%) produce both passing and failing outputs across five repetitions (Codex 19.9%, Cursor 25.0%, OpenCode 42.9%); for the smallest Cursor backend (GPT-5.4 nano), the first-execution pass rate is 59.6% but only 45.4% averaged over five executions.

## Critical Assessment

- **Novelty**: Genuinely novel framing. The contribution is not "another network agent benchmark" but a shift of the evaluation unit — from whether the immediate task outcome is correct to whether the surrounding experiment record remains evidence-grounded, scoped, and traceable. The claim–evidence–scope formalization and the five failure modes (residual inconsistency, unsupported replacement, support damage, lost traceability, invalid package) are reusable conceptual artifacts beyond networking. That said, the formal model (Section 3) is a light adaptation of established provenance models (PROV-DM, RO-Crate, database provenance), and the intellectual core is the benchmark + empirical finding rather than new theory.
- **Rigor**: Strong for a benchmark paper. Deterministic scoring with a hidden oracle, fresh workspaces per execution, an instance validation gate, tiered structural difficulty, mean ± std over five repetitions, and a joint contract-pass criterion that prevents partial-credit inflation. The Tier-5 gap analysis (label 96.2% vs pass 26.3% for Codex) is a well-designed probe showing the failure is in coordinated propagation, not classification.
- **Reproducibility**: Partially undermined. The paper pins runtime and model versions (Codex CLI 0.142.3–0.144.5, Cursor builds 2026.07.01/2026.07.23, OpenCode 1.17.15) but provides no artifact/benchmark release link in the text; several backends also route through a community free-inference endpoint, and MiniMax M2.5's ±10.0-point std on contract pass suggests endpoint-level variance that is reported but not dissected. Figure 2 claims time/token metrics are tracked, yet no cost, latency, or token analysis appears anywhere in the paper — a tracked-but-unreported ablation.
- **Significance**: The headline finding — near-perfect Tier 1 correction (98.9%) collapsing to Tier 5 (26.3% best runtime), with two instances unsolved in 115 attempts — is a crisp, quotable result that should concern anyone deploying agents on operational or experimental network records. The 27.7% mixed pass/fail instability is equally important for deployment decisions.
- **Red flags / weaknesses to weigh**: (1) The 52-instance pool is drawn from only four repositories, so domain breadth is narrow even within networking; per-tier cell sizes are therefore small (roughly 10 instances per tier), making the tier curves noisy at the extremes. (2) Drift is injected, not natural — the authors concede this probes repair capability, not the prevalence of real integrity failures. (3) The contract scorer is strict about parseability and identifier preservation; a semantically correct but format-divergent repair fails, and the authors defer "more permissive semantic evaluation" to future work, so 65.3% may slightly understate semantic competence — though the high label rates suggest the partial-completion interpretation is the dominant effect. (4) The 23-configuration range is padded by very weak baselines (local Qwen3 8B at 1.2%, Qwen3 14B at 15.4%, DiffusionGemma at 48.1%) that mostly measure whether small open models can follow the harness at all. (5) No link is established between the Figure 1 failure-mode taxonomy and the measured residuals — the paper never reports which of the five modes drives Tier 4–5 failures most, leaving the diagnosis taxonomy empirically unbound to the headline result.

## Strengths

- Reframes agent evaluation from task outcomes to record-level integrity — a dimension genuinely absent from SWE-bench, NetAgentBench, NIKA, Cornetto, and FEVER-style fact verification.
- Deterministic, oracle-grounded scoring with a joint contract criterion that resists partial-credit gaming; instances are validated before freezing (reference repair passes, seeded wrong repairs fail).
- All instances derive from real public network artifacts (Batfish, Zeek, P4C, Open vSwitch), avoiding synthetic-toy artifacts.
- The five-tier structural difficulty axis turns "repair quality" into a measurable curve, and the label-vs-contract-pass gap analysis cleanly localates the failure mode (coordinated propagation, not classification).
- Honest, quantified reporting of run-to-run instability (27.7% mixed pairs) — a finding many benchmark papers omit.

## Limitations

- Small benchmark (52 instances) from only four source repositories; per-tier subsets are tiny, and coverage within networking (no routing configs at scale, no telemetry pipelines, no wireless/5G artifacts) is narrow.
- Injected inconsistencies probe repair capability but say nothing about how often artifact drift occurs naturally in real agent deployments — explicitly acknowledged in the conclusion.
- Strict contract scoring (parseability, exact identifier preservation) may penalize semantically valid repairs; more permissive semantic evaluation is left to future work.
- No failure-mode attribution: the five-mode taxonomy of Figure 1 is never mapped onto the 2,076 failures, so which mode dominates the Tier 4–5 collapse remains unknown.
- Cost, latency, and token usage are tracked per Figure 2 but never reported; comparing effort levels (low → xhigh) without token counts hides the price of the +8.8-point gain.
- Network-specialized agents (Confucius, NetAssistant, ArachNet) are excluded by design, so results characterize general-purpose agents only; the free-inference endpoint for several OpenCode backends adds unmodeled variance (e.g., MiniMax M2.5 ±10.0).

## Relevance

对研究"LLM Agent 可靠性与评测"的方向高度相关：本文提供了一个可复用的"过程/记录完整性"评测范式和五层结构化难度曲线，可直接迁移到代码仓库、数据管线或科研自动化等任何 Agent 修改工件生成证据链的场景；其"局部正确 ≠ 记录可审计"的发现对设计自我纠错与 provenance 感知的 Agent 系统是重要警示。

## Questions for Further Exploration

- Which of the five failure modes (residual inconsistency, unsupported replacement, support damage, lost traceability, invalid package) drives the Tier 4–5 collapse — is coordinated propagation bottlenecked by context management, by the runtime's edit model, or by the LLM's relation inference?
- Would network-specialized agents (Confucius, ArachNet) with built-in simulators and telemetry close the Tier 4–5 gap, or does record-level repair require a different capability than task completion?
- How do the results change under a more permissive semantic scorer that accepts format-divergent but evidence-correct repairs — does the 65.3% average contract pass understate or overstate semantic artifact integrity?
- Can naturally occurring artifact drift be harvested from real agent-assisted network workflows (CI logs, measurement campaigns) to build a distributionally valid version of this benchmark?
- Does providing explicit provenance tooling (e.g., claim-to-evidence linking as a runtime primitive rather than an output obligation) improve Tier 4–5 pass rates more than scaling model effort, given that effort scaling only bought +8.8 points from low to xhigh on Codex?
- How much of the 27.7% run-to-run instability is sampling noise versus genuine near-boundary competence, and can a five-repetition protocol distinguish the two?
