> **一句话总结：** NeoHorse-1（4B/9B，基于 Qwen3.5）证明了一个部署中的路由 harness 本身就能产出自我改进所需的数据：它把"路由器预测的能力需求 + 实际执行轨迹 + 结果"转成带交错推理与工具调用的训练样本，用路由分数驱动三阶段课程 SFT 与 on-policy 蒸馏，在 10 项基准上把 4B 模型宏平均分从 58.94 提到 64.87、9B 从 65.60 提到 69.04，并给出"评估–选择–更新"闭环作为递归自我改进（RSI）的初始原型。

> **TL;DR:** A technical report from the NeoHorse Team (TokenRhythm et al.) arguing that a deployed LLM routing harness already contains the feedback mechanism recursive self-improvement (RSI) needs. Harness records (predicted capability tier, served model, resulting interaction) are converted into user-turn training examples with interleaved reasoning and tool calls, quality-gated by structural validation + 6-dimensional semantic evaluation, then used for routing-score-ordered 3-stage curriculum SFT and routing-guided on-policy distillation (reverse-KL, top-K coarsened). Across 10 benchmarks (QwenClawBench, WorkBuddy, PinchBench, VitaBench, BFCL V4, tau2-Bench, HumanEval, LiveCodeBench v6, IFEval, IFBench), agentic post-training lifts the macro-average of the Qwen3.5-4B base from 58.94 to 64.87 (+5.93) and of Qwen3.5-9B from 65.60 to 69.04 (+3.44); the 9B even edges past the 3x-larger Muse-Glimmer-30B (67.86). A controlled ablation shows routing-harness trajectories beat the public Toucan agent dataset by +6.26 average under the identical recipe — but the recursive part (gains compounding across iterations) is explicitly future work: only one pass of the loop has been run.

## 核心贡献

- **把路由 harness 重新定义为 RSI 的数据引擎**：论证了一个已在部署的路由系统（异构模型池 + 逐 turn 智能选路）天然产出三类可复用信号——执行轨迹、能力需求路由信号、可观测结果——构成"系统学会做什么决定它接下来从什么学"的评估–选择–更新闭环。
- **harness 轨迹 → 高质量训练数据的完整管线**：以 user turn 为训练单元（保留当前 turn 的交错推理/工具调用、省略历史推理），经规则化结构校验（完整/可恢复/隔离三态）、六维语义评估（目标达成、指令遵循、工具使用、证据一致性、错误恢复、终止）和 subscene 级 Scene/Goal/Outcome 三轴标注；对评测集做去污染筛查。
- **路由引导的课程学习**：用路由器输出的 C0–C3 能力需求分数（硬排序用 tier 索引、软排序用分数加权均值）把 SFT 数据组织成三阶段课程，逐步引入高需求样本同时保留低分覆盖，阶段间不重置优化器。
- **路由引导的 on-policy 蒸馏（OPD）**：把同一课程扩展到蒸馏场景——学生在记录的上下文上自己生成回复，固定教师只在 top-K + 余概率桶粗化分布上提供逐 token 反向 KL 监督；rollout checkpoint 随训练刷新。
- **能力引导的数据分配**：用分层评测得到"模型短板画像"，据此调整下一轮训练混合的构成（改变数据组成而非引入新目标函数），是闭环的关键闭环步骤。
- **双规模实证 + 数据侧消融**：4B/9B 上十项基准一致提升；同配方下 harness 轨迹数据显著优于公开合成智能体数据（Toucan）；监督 token 从 2M 扩到 10M 带来持续增益。

## Key Contributions

- Reframes a deployed routing harness as the data engine for recursive self-improvement: every turn already records a prediction–action–outcome triple (predicted capability tier, served model, resulting interaction), which is exactly the capability evidence RSI needs.
- A full trajectory-to-training-data pipeline: user-turn training units that preserve interleaved reasoning, tool calls, and harness context (dropping earlier-turn reasoning), admitted through rule-based structural validation, a six-dimension semantic evaluation (goal attainment, instruction adherence, tool use, evidence consistency, error recovery, termination — each PASS/WARN/FAIL/NOT_EVALUATED with evidence coverage), and subscene-level Scene/Goal/Outcome labeling, with decontamination screening against all evaluation suites.
- Routing-guided curriculum learning: capability-demand scores from the router (hard tier index or soft score-weighted mean over C0–C3) order SFT examples into a three-stage curriculum that progressively introduces higher-demand examples while reserving lower-scored ones for later stages, without optimizer resets between stages.
- Routing-guided on-policy distillation: the same staged progression schedules the starting contexts in which the student generates its own responses; a fixed teacher provides token-level supervision via a response-normalized reverse KL over top-K-plus-bin coarsened distributions, with rollout checkpoints refreshed as training proceeds.
- Capability-guided data allocation: per-iteration evaluation produces a model-deficiency profile that reallocates the next training mixture toward underperforming strata — changing data composition rather than adding a failure-specific loss — closing the evaluation–selection–update loop.
- Empirical validation at two scales (4B and 9B, initialized from Qwen3.5) across ten benchmarks, plus controlled data-source and data-scale ablations isolating the value of routing-harness trajectories.

## Methodology

The system rests on three connected components.

**Data from the routing harness (Section 3).** The corpus is organized at three granularities: full trajectories (10^5–10^6 harness-generated ones, supplemented with public instruction/reasoning/tool/code/preference data), user turns (the serialized training unit — a user request plus the assistant responses and tool interactions up to the next request), and subscenes (adjacent turns sharing a local goal, the unit for semantic characterization). Serialization uses the Qwen3.5 chat template; reasoning is kept only within the current turn. Quality control is layered: exact/near-dedup and decontamination against evaluation suites; deterministic structural validation (tool-call/result closure, causal event order, orphan detection) sorting trajectories into complete / partially-recoverable / quarantined; then a semantic judge restricted to trajectory-internal evidence scores the six quality dimensions. Routing records retain the router's raw C0–C3 tier prediction, the policy-adjusted decision, and the tier actually served as separately analyzable fields — the predicted demand (not the served model identity) drives curriculum ordering, while outcome fields feed deficiency detection.

**Agentic post-training (Section 4).** SFT minimizes a token-masked cross-entropy where loss lands only on current-turn assistant spans (reasoning, tool calls and arguments, visible responses, end-of-response tokens); history, system instructions, user messages, and tool results get zero loss. Routing scores order examples into a three-stage curriculum (each stage ~1/3 of examples, shifting toward higher capability demand). Because SFT still imitates recorded responses while deployment conditions on the model's own prefixes, the same routing progression schedules on-policy distillation: the student generates a response from each recorded starting context, and a fixed teacher supervises via response-normalized reverse KL computed on coarsened top-K+1-bin distributions; only the student is updated, and the rollout checkpoint is refreshed during training.

**The RSI loop (Sections 3.5, 6).** After each iteration, the checkpoint is evaluated on a stratified suite; results aggregated over attributes, quality dimensions, outcome states, and routing tiers form a deficiency profile that reshapes the next training mixture. Updated checkpoints return to the harness, generating new trajectories whose capability gaps seed the next round — an operational evaluation–selection–update loop. Evaluation uses 10 benchmarks (agentic: QwenClawBench, WorkBuddy, PinchBench, VitaBench, BFCL V4, tau2-Bench; coding: HumanEval, LiveCodeBench v6; instruction following: IFEval, IFBench) against open-weight baselines at both scales, with QwenClaw/WorkBuddy/tau2 averaged over three runs, SGLang v0.5.17 serving, and identical harnesses/budgets for all self-evaluated models.

## Results & Highlights

- **Headline macro-averages (10 benchmarks):** agentic post-training lifts NeoHorse-1-4B from 58.94 (Qwen3.5-4B base) to 64.87 (+5.93 pts) and NeoHorse-1-9B from 65.60 (Qwen3.5-9B base) to 69.04 (+3.44 pts); the post-trained 4B beats the 9B base on several individual benchmarks, and NeoHorse-1-9B (69.04) also edges the roughly 3x-larger Muse-Glimmer-30B (67.86).
- **Largest 4B gains concentrate on harness-based and execution-intensive tasks:** VitaBench 21.50 → 32.00 (+10.50 pts over Qwen3.5-4B), WorkBuddy Bench 24.62 → 34.41 (+9.79), HumanEval 87.20 → 96.95 (+9.75), QwenClawBench 38.47 → 44.68 (+6.21), PinchBench 71.19 → 77.33 (+6.14), LiveCodeBench v6 53.71 → 59.43 (+5.72); tau2-Bench 84.29 → 88.46 (+4.17); smallest movement is BFCL V4 (+0.77) — function calling was already near the base's strength.
- **9B track:** gains persist on the stronger base — tau2-Bench 88.04 → 90.82 (+2.78), BFCL V4 64.88 → 67.43 (+2.55), PinchBench 74.55 → 82.25 (+7.70) — while instruction following stays flat with a minor IFEval decrease (89.46 → 89.09, −0.37).
- **Data-source ablation (Table 3, identical recipe, same Qwen3.5-4B init, matched budgets):** routing-harness trajectories beat the public Toucan tool-agent dataset on all five comparable benchmarks — average 70.57 vs 64.32 (+6.26 pts), with tau2-Bench +11.31 (84.85 vs 73.54) and HumanEval +8.54 (96.34 vs 87.80) — evidence the gain comes from the data source, not just the curriculum algorithm.
- **Supervision scaling (Figure 7):** with everything else fixed, the five-benchmark dev-suite average rises monotonically from 69.31 (base) to 71.45 as unique supervised tokens grow from ~2M to ~10M (log axis), indicating headroom in routing-harness data volume.
- **Qualitative trace analysis:** in a PinchBench data-analysis case where pandas is unavailable, NeoHorse-1-9B abandons the blocked approach and switches to Python's standard csv/math libraries, cutting model requests, execution time, and token usage by ~70.8%, ~76.7%, and ~83.6% respectively versus the flailing NeoHorse-1-4B; appendix case studies (ticket reporting, time-leakage auditor, Gomoku game) show more faithful requirement grounding and artifact consistency over Qwen3.5-9B.

## Authors & Credibility

Authored by the "NeoHorse Team" — TokenRhythm Technologies with Infinigence AI, Tsinghua University, Peking University, CUHK, Alibaba Group, and two capital firms; ~19 core contributors plus ~19 additional contributors, with corresponding authors Yu Wang (Tsinghua) and Yunhe Wang. The report is unusually candid about scope: it repeatedly labels itself "an initial prototype" of harness-mediated RSI rather than a demonstration, and it states outright that only a single pass of the evaluation–selection–update loop has been run. Code and model collections are promised at github.com/TokenRhythm/NeoHorse and a HuggingFace collection. Infrastructure provenance is transparent: the harness (OpenSquilla), the predecessor work (Agentic Routing, arXiv:2607.11399), base models (Qwen3.5-4B/9B), serving stack (SGLang v0.5.17), and inference parameters are all named. Evaluation hygiene is decent (decontamination screening, three runs on the noisiest benchmarks, identical harnesses for self-evaluated models, blog-sourced numbers marked with an asterisk), though key training details (teacher model for OPD, exact mixture sizes, compute) are not fully disclosed.

## Critical Assessment

- **Novelty:** The individual ingredients — trajectory SFT (AgentTuning, Agent-FLAN), on-policy distillation (Agarwal et al.), curriculum learning, routing (RouteLLM/FrugGPT) — are all established. The genuine novelty is the composition: using the router's *predicted capability demand* as a free curriculum signal for both SFT context ordering and OPD context scheduling, and closing the loop with deficiency-driven data reallocation. It is a systems contribution, not a new learning algorithm.
- **The RSI claim is not demonstrated — and the authors say so.** The title says "Towards Recursive Self-Improvement," and the conclusion concedes the results "reflect a single pass of the evaluation–selection–update loop." Every number in the paper is therefore evidence for *agentic post-training from harness data*, not for recursion; whether gains compound across generations is untested. Readers should weigh the paper as a strong data-pipeline report wearing an RSI frame.
- **Missing ablations.** There is no curriculum-vs-random/uniform-ordering ablation (Table 3 compares data *sources* under the same routing-guided recipe, so the curriculum's own contribution is unmeasured), no SFT-only vs SFT+OPD decomposition for the final models, and the OPD teacher model is never named. The 10-benchmark headline gains cannot be attributed to any single mechanism.
- **Baseline and protocol quirks.** Several baseline numbers are taken from official blogs/reports (marked *) rather than re-run (e.g., Nanbeige-4.2-3B's LiveCodeBench 72.50); Muse-Glimmer-30B is labeled a "contextual reference"; PinchBench and VitaBench are single-run evaluations; and the VitaBench user-simulator/judge was swapped to DeepSeek-V4-Flash because the originally recommended models are unavailable — a deviation that muddies cross-paper comparability. Gemma-4-E4B-it collapses on the agentic benchmarks (avg 42.95), padding the 4B track.
- **Distributional alignment concern.** The biggest gains appear on harness-based benchmarks (QwenClawBench, PinchBench) evaluated with OpenSquilla — the same harness family that generated the training trajectories. This is the paper's own thesis (train on deployment data, win on deployment-like tasks), but it means the transfer claim rests mainly on the five-benchmark ablation suite rather than the headline agentic tables.
- **Reproducibility:** moderate. Data pipeline rules, loss formulations, and routing-tier semantics are specified in detail, and a GitHub repo is referenced; but the private 10^5–10^6-trajectory corpus, the undisclosed OPD teacher, and unreleased mixture statistics make exact reproduction impossible for outsiders.

## Strengths

- A coherent, well-engineered answer to "where does RSI's feedback actually come from?" — the routing harness as a capability-measuring instrument that already exists in deployment.
- The data pipeline is the most rigorous part: deterministic structural gates, a six-dimension semantic evaluation that never converts missing evidence into positive verdicts, provenance-preserving three-granularity organization, and decontamination against every eval suite.
- Clean, controlled ablations: the Toucan comparison isolates data source with matched init/seed/schedule/budget, and the nested-subset scaling study isolates unique-supervision effects.
- Consistent gains across both scales and ten benchmarks, with honest per-benchmark reporting (including the flat IFEval at 9B) and unusually self-aware framing of what is and is not demonstrated.
- Trace-level analysis (request/time/token reductions of 70.8/76.7/83.6% in the pandas-blocked case) goes beyond leaderboard deltas to characterize *why* the larger model wins: abandoning unproductive strategies rather than searching harder.

## Limitations

- Only one iteration of the improvement loop has been run — the central recursive claim is unvalidated by construction.
- No ablation of the curriculum ordering itself, no SFT/OPD contribution split, and the OPD teacher is undisclosed.
- Training data is proprietary harness traffic; corpus composition (ratio of harness vs public data, total tokens per stage) is characterized only as "10^5–10^6 trajectories," hindering quantitative comparison.
- Evaluation is text-only and skewed toward agentic/coding tasks; the broader capability surface the harness serves (including multimodal and long-horizon research tasks) is untested.
- Protocol compromises: single-run PinchBench/VitaBench, swapped VitaBench judge, and asterisked blog-sourced baseline numbers reduce confidence in fine-grained rankings; instruction-following gains at 9B are marginal to negative.

## Relevance

这篇论文把"路由系统日志"变成课程驱动的智能体后训练数据源，与我们对 agentic 模型训练、数据飞轮和自我改进闭环的兴趣高度契合——它给出了一个可落地的 RSI 工程原型（harness 数据 → 路由课程 SFT + on-policy 蒸馏 → 短板驱动再分配），也是理解生产级 agent 轨迹数据如何超越公开合成数据（+6.26 平均分）的少数受控实证之一。

## Questions for Further Exploration

- Does the +5.93/+3.44 macro-average gain survive a second and third pass of the evaluation–selection–update loop, or does the deficiency-driven reallocation saturate once the low-hanging strata are fixed?
- How much of the curriculum's benefit comes from routing scores specifically versus any difficulty proxy — a random-ordering or length-based curriculum control is absent?
- What is the SFT vs on-policy distillation contribution split at each scale, and how sensitive is OPD to the (undisclosed) teacher's strength relative to the student?
- Would the routing-harness-data advantage over Toucan (+6.26 avg) persist if the public data were quality-filtered to match the harness corpus's structural-validity and semantic gates?
- Can the C0–C3 tier predictions be calibrated into genuine difficulty estimates (as the authors propose for the router itself), enabling the harness to select not just what data to train on but what tasks the model should attempt next?
- Do the harness-alignment gains (QwenClaw/Pinch trained on OpenSquilla-like traffic, evaluated in OpenSquilla) transfer to unseen harnesses, i.e., is the model learning agent skills or harness-specific conventions?
