> **一句话总结：** 微软 Froggy 团队基于 Qwen3.5-4B,仅用约 1500 个由 TaskPilot 在当前策略"可学习边界"(目标解题率≈0.5)在线合成、动态修订的 SWE 任务做五轮 RL(无任何大模型蒸馏轨迹),配合为小模型设计的轻量 Leaf 工具接口(把基础模型 SWE-bench Verified 从 8.3% 提到 37.2%),最终在 SWE-bench Verified 达到 61.5%、SWE-bench Pro 达到 37.6%,超过用同量级真实任务训练的 RL 基线 8.1 个百分点,以 1/10 成本媲美 GPT-5 mini 级别的专用大模型。

> **TL;DR:** FrogNano turns Qwen3.5-4B into a competitive coding agent using ONLY RL over ~1,500 synthetic tasks synthesized online at the current policy's learnability frontier (TaskPilot targets ~50% solve rate per task, refining problem statements via policy rollouts) — no distillation of larger-model trajectories. On SWE-bench Verified it reaches 61.5% vs 53.4% for an RL baseline trained on 1,500 learnability-filtered REAL tasks (+8.1 pts), plus 37.6% SWE-bench Pro, 31.1% Terminal-Bench 2.0, 47.3% PatchEval-Verified — matching models 6-8x larger at ~$0.21/task. A key enabler is the lightweight Leaf harness: switching Qwen3.5-4B from R2E-Gym to Leaf alone lifts SWE-bench Verified from 8.3% to 37.2% (a 72B-class model is unaffected at 66.5% on both), showing harness design is a first-order bottleneck for compact models.

## 核心贡献

- **FrogNano 本身**:一个 4B 参数(基于 Qwen3.5-4B)的仓库级编码智能体,纯 RL 后训练(五轮迭代,每轮约 300 个合成任务,共约 1500 个环境),不使用任何来自更大模型的行为轨迹、蒸馏 SFT 或大模型裁判奖励,证明小模型可以仅靠"合成任务 + RL"达到过去 32B–100B+ 模型的编码水平。
- **TaskPilot 在线任务合成管线**:从真实仓库快照(SWE-rebench / Scale-SWE)出发,由任务生成模型联合生成 issue、gold patch 和隐藏 F2P 测试;再用**当前策略的 rollout 估计解题率 p̂**,只录取落在可学习区间(1–4 轮目标 p̂≈0.5,第 5 轮下调至 (0, 0.5])的任务;太难/太易的任务会被**语义级修订**(补充行为契约或删除定位解法的线索)后重新评估,而非简单丢弃——任务分布随策略共同演化。
- **Leaf 轻量工具接口**:仿 Claude Code 风格的五个类型化工具(read/write/edit/glob/bash)+ 自然终止规则。发现 harness 对小模型是首要瓶颈:Qwen3.5-4B 在 R2E-Gym 下约 96% 轨迹撞回合上限,换到 Leaf 后 SWE-bench Verified 从 8.3% 升至 37.2%,而大模型(MiniMax-M2.5)完全不受影响(两种 harness 均 66.5%)。
- **完整 RL 配方**:DPPO 组相对优势 + 异步 rollout(SGLang)与非对称轨迹重要性采样纠偏,成功轨迹的对数长度惩罚控制推理轨迹膨胀,截断但正确的轨迹给 0.5 部分奖励;单节点 8×B200(2 卡训练 + 6 卡推理)。
- **扎实的分析**:pass@k 证明 RL 在推能力边界而非蒸馏 pass@1;两阶段奖励作弊检测(regex 召回 + 三方 LLM 仲裁,κ=0.746)确认 0 次有效作弊;失败模式聚类(90.8% 属推理缺陷);工具使用动力学(验证行为从 53.4% 升至 94.3%)。

## Key Contributions

- **FrogNano, a 4B repository-level coding agent** post-trained from Qwen3.5-4B purely via RL over ~1,500 synthetic SWE environments (5 iterations × ~300 tasks) — no SFT on, or distillation of, stronger-model trajectories, and no LLM-judge rewards.
- **TaskPilot, an online policy-adaptive task-synthesis pipeline**: starting from real repository snapshots, a generator model jointly produces problem statement, gold patch, and hidden fail-to-pass tests; blind rollouts from the *current* checkpoint estimate each candidate's resolve rate p̂; only tasks in the learnable band are admitted (target p̂=0.5 for iterations 1–4; a stronger generator and lower band (0, 0.5] for the redesigned iteration 5). Out-of-band tasks are semantically *revised* (tightening behavioral contracts, removing solution-localizing hints) and re-evaluated — synthesis adapts to the policy instead of filtering a fixed pool.
- **Leaf, a lightweight Claude-Code-style harness** with five typed tools (read, write, edit, glob, bash) and a natural termination rule (any response without a tool call ends the episode). Harness choice is shown to be a first-order bottleneck for compact models: Qwen3.5-4B goes from 8.3% → 37.2% on SWE-bench Verified when moved from R2E-Gym to Leaf, while MiniMax-M2.5 is insensitive (66.5% on both).
- **A complete, stable RL recipe at 4B scale**: DPPO group-relative advantages with asymmetric trajectory importance sampling for policy-lag correction (no KL, no entropy bonus), a success-gated logarithmic length penalty (introduced at iteration 3 to curb reasoning-trace growth), 0.5 partial reward for truncated-but-correct trajectories, async rollouts on one 8×B200 node (2 training GPUs + 6 inference GPUs, 256 trajectories per update).
- **Unusually thorough analyses**: pass@k curves showing the gap to the base model stays static as k grows (capability-frontier expansion, not pass@1 distillation); a two-stage reward-hacking audit (regex funnel + 3-way LLM judge, 93.02% agreement, Fleiss' κ=0.746) finding 0 *effective* hacks; failure-mode taxonomy; tool-use choreography (inspect–edit–verify) across curricula; cross-harness generalization to mini-SWE-agent; and a self-summarization context-compaction study.

## Methodology

**Task synthesis and calibration (TaskPilot).** Each task = problem statement + repository snapshot + runtime + gold patch + grading tests (F2P specify the repair; P2P guard regressions; both hidden from the solver; the gold patch is used only for validation). A candidate is *executable* if its F2P tests fail on the original snapshot, pass after the gold patch, and the existing P2P suite stays green. For each executable candidate, TaskPilot collects N full multi-turn trajectories from the current 4B Leaf policy and estimates the resolve rate p̂ = (1/N)ΣRj. The learnable region is 0 < p̂ < 1, with an iteration-specific admission target inside it. The flagship mechanism is the generate–evaluate–refine–re-evaluate loop: a task at 0% (underspecified contract) gets missing behavioral requirements added; a task at 100% (solution-localizing — naming the class/method/failing input) gets those hints stripped; the accepted middle variant states a precise behavioral contract without localizing the fix, yielding mixed success/failure trajectories. After a checkpoint saturates on validation, it becomes the solver for the next generation phase — a closed loop where the policy shapes the tasks it learns from.

**Curriculum evolution.** Iterations 1–4 use the original generator with target 0.5; iteration 5 (after the same regime showed weak gains) switches to a stronger task-generation model, a lower target band, shorter less-scaffolded problem statements (116.6 words vs 227.0 in iteration 4), and a broader task mix (bug-fix share falls from 85.2% in iteration 1 to 40.7%; feature requests 24.0%, refactors 17.0%, perf optimizations 12.4%).

**RL training.** Each iteration runs a 200-update climb with DPPO: 32 tasks × 8 trajectories per update (global batch 256), group-standardized shaped advantages, zero-variance groups discarded (rare, thanks to calibration). Tool outputs stay in context but are masked from the loss; the trajectory advantage is broadcast to model-generated tokens. Asynchronous SGLang rollouts create policy lag, corrected by asymmetric trajectory importance sampling that drops tokens whose training/rollout probability ratio moved more than 0.2 in the already-reinforced direction. The efficiency reward is a success-gated log penalty R(N) = 1 − α·ln(n/N) for n > N assistant tokens, applied only to completed successful trajectories; truncated-but-solving trajectories get partial reward 0.5. No KL, no entropy bonus — stability comes from the DPPO mask, small policy lag, and gradient clipping. Hardware: one node, 8× NVIDIA B200 (context parallelism 2 for training; six 1-GPU inference engines), 65K context / 75 turns for iterations 1–4, then 131K / 150.

**Evaluation.** Leaf harness on SWE-bench Verified (500 Python tasks — also used as the validation set for iteration scheduling), SWE-bench Pro (731 tasks, 11 repos, Python/JS/TS/Go), Terminal-Bench 2.0 (89 hard terminal tasks), and PatchEval-Verified (230 real CVE repairs, 2015–2025). Budget: 150 steps, 131K context, temperature 0.6, scores averaged over 3 seeds.

## Results & Highlights

- **SWE-bench Verified (validation set): 61.5%** after five TaskPilot iterations (averaged over 3 runs), climbing monotonically from 43.0% → 49.1% → 53.1% → 56.9% → 59.1% → 61.5%; each iteration's within-climb gain was +11.7, +3.4, +5.6, +3.0, +5.4 points (4 of 5 block-bootstrap CIs exclude zero), showing regenerated curricula keep providing signal rather than saturating after round one.
- **Synthetic beats real at equal scale:** the same RL recipe on ~1,500 REAL tasks (SWE-rebench + Scale-SWE mixture, filtered by the same 4B learnability criterion) reaches only **53.4%** on SWE-bench Verified — FrogNano's 61.5% is **+8.1 points**; even ~300 real learnability-filtered SWE-rebench tasks yield just 48.0% vs 49.1% for the first synthetic iteration.
- **Harness effect alone is massive:** switching Qwen3.5-4B from the R2E-Gym harness to Leaf lifts SWE-bench Verified from **8.3% to 37.2%** (≈96% of R2E-Gym trajectories hit the turn limit), while MiniMax-M2.5 is unchanged at 66.5% on both — interface design matters specifically for compact models.
- **Held-out generalization: 37.6% SWE-bench Pro** (competitive with models 6–8× its size at a quarter of the cost), **31.1% Terminal-Bench 2.0**, **47.3% PatchEval-Verified** — beating or matching Qwen3.5-9B and Devstral Small 2 despite being 4B.
- **Inference cost: $0.21 per SWE-bench Verified task** (131K context, avg 53.5 steps) — GPT-5-mini-comparable performance at roughly one-tenth the cost.
- **Capability frontier, not pass@1 distillation:** the pass@8 gap between FrogNano and base Qwen3.5-4B stays constant as k grows; test-time scaling adds more — a round-robin verifier tournament with 3 candidates reaches **62.8%** pass@1 on SWE-bench Verified (vs 61.4% single verifier call, 61.53% random pick, 60.4% pass@short).
- **Cross-harness transfer:** in the bash-only mini-SWE-agent, FrogNano scores 56.4% vs the base model's 43.8% (+12.6), using fewer turns (87.1 vs 100.5), hitting the turn cap on 9.8% vs 31.6% of trajectories, and never overflowing context (base model: 26 times).
- **Self-compaction works:** FrogNano summarizing its own trajectory recovers full 131K-context performance within a 64K window (compaction fired in 87% / 51% / 4% of rollouts at 16K / 32K / 64K).
- **Safety/honesty audits:** confirmed reward-hacking attempts stayed at 2.5–3.1% of trajectories across iterations with **0 effective hacks** (blocked by the harness overwriting test files); failure analysis shows 90.8% of failures are reasoning gaps (38.8% wrong root cause/layer, 31.5% misread spec) rather than infrastructure limits, and passed trajectories are 8.1 points more likely to run a test after their final edit (verification behavior rose from 53.4% → 94.3% of paired rollouts).

## Authors & Credibility

From the Froggy Team at Microsoft Research Montréal (17 authors; core contributors include Minseon Kim, Zhengyan Shi, Alessandro Sordoni, Marc-Alexandre Côté, Xingdi Yuan, and interns), the group behind debug-gym and BugPilot — a credible, established agentic-RL lab with a track record in this exact area. The report is atypical in its candor: it explicitly labels SWE-bench Verified as its *validation* set (chosen because it is Python-heavy like the training data), details the two-stage reward-hacking audit with inter-annotator statistics (93.02% agreement, Fleiss' κ=0.746), publishes a dedicated Limitations section covering language/stack narrowness and test-reward blind spots, and its contribution statement itemizes who built TaskPilot vs. Leaf vs. training. ## Critical Assessment

- **Novelty: solid but composite.** The paper itself concedes "our RL setup is not individually novel" — DPPO, async rollouts, group-relative advantages, and log-length penalties are all prior work; the contribution is the 4B-scale combination with policy-calibrated task synthesis. TaskPilot's nearest neighbors (CalibForge, SPADE, Socratic-SWE, Envs-FORGE) are concurrent and honestly cited; TaskPilot differs in NOT co-training the generator with the solver and in using blind rollouts purely for admission/refinement. The refinement example (Figure 5) is compelling but is a single hand-picked showcase.
- **Rigor caveats worth noting.** (1) The headline 61.5% is on SWE-bench Verified, which the authors themselves designate as the *validation* set used to schedule iterations — the honest held-out numbers are the weaker 37.6% / 31.1% / 47.3%. (2) A large share of the final score is unlocked before any RL: the harness switch alone takes the base model from 8.3% to 37.2%, and iteration 0 already sits at 43.0%, so RL contributes +18.5 of the 53 points above the R2E-Gym floor. (3) The "no distillation" claim is carefully worded — stronger LLMs *do* author the tasks, gold patches, and hidden tests (iteration 5 even switches to a "stronger task-generation model", unnamed in the main text); what is excluded is imitation of stronger-model *solution trajectories*, and the consolidation experiments (excluded from FrogNano proper) do use GPT-5.6-Sol-generated privileged information and SFT.
- **Reproducibility: medium.** Full RL hyperparameters are published (Appendix A.1), and the analysis appendices are exemplary, but the pipeline depends on SWE-rebench/Scale-SWE snapshots, an unspecified task-generation model family, and an 8×B200 node — "runs on minimal hardware" is true at *inference* ($0.21/task) but not at training time. Base model (Qwen3.5-4B) is open-weight; FrogNano's own release status is not stated in the paper.
- **Significance: high if it holds.** The core empirical claim — 1,500 synthetic frontier-calibrated tasks beat 1,500 extensively rollout-filtered real tasks by 8.1 points — is the kind of controlled, decision-relevant result the field needs, and the harness-sensitivity finding (small models live or die by the interface) is arguably the most immediately actionable observation in the paper.
- **Minor red flags:** small numeric inconsistencies between main text and appendix (pass@short 62.8% vs 62.6%; iteration-3 score 56.9% vs 56.7%; a garbled author-email line in the header), and the "matches models a year old of 32B–100B+" framing is a slightly generous comparison against a moving frontier.

## Strengths

- Clean central experiment: synthetic-at-the-learnability-frontier vs real-filtered-by-learnability under the identical RL recipe — the +8.1-point gap on SWE-bench Verified isolates the variable of interest.
- The Leaf harness finding is a genuinely important, underappreciated result: a 29-point swing (8.3% → 37.2%) from interface design alone, with the 72B-class control (MiniMax-M2.5 flat at 66.5%) proving it is small-model-specific.
- Task *refinement* (not just filtering): Figure 5's three problem-statement variants over one fixed snapshot/test pair shows the mechanism operating on requirement semantics — behavioral contracts vs solution-localizing hints — which is more instructive than a difficulty filter.
- Exceptional analysis depth: pass@k frontier analysis, reward-hacking taxonomy with adjudication statistics, failure clustering by trajectory step, tool-composition dynamics across curricula, self-compaction ablation with documented configuration pitfalls.
- Honest scoping: explicit Limitations section, validation/test split disclosed, contribution/role statement, multi-seed reporting.

## Limitations

- Python-heavy, English-only training distribution; generalization to other languages, stacks, under-specified requirements, or repos without reliable tests is unestablished (authors' own admission) — and the 47.3% PatchEval-Verified number covers JS/Go only via zero-shot transfer.
- Trained and evaluated in a single harness (Leaf); multi-harness training (as in Orchard-SWE) is not attempted, and multimodal inputs of the Qwen3.5-4B base were never post-trained or evaluated.
- Test-passing is the sole reward and metric: a patch can pass F2P/P2P yet be incorrect or insecure; the paper correctly warns against over-trusting such agents.
- Only 5 iterations shown; whether the curve keeps climbing (or the synthetic-task well runs dry) is open. The consolidation and verifier add-ons use SFT and stronger-model information, weakening the purity of the distillation-free story if one counts them as part of the recipe.
- Training compute (8×B200) is far from "minimal hardware"; the resource-constrained claim applies to serving only.

## Relevance

与我的研究方向高度相关:本文展示了"按当前策略可学习边界在线合成任务 + 纯 RL"的训练范式如何在 4B 小模型上做出顶级编码智能体,其中 harness 设计对小模型的决定性影响、课程随策略演化(task distribution co-evolves with policy)的思路,以及 pass@k/奖励作弊审计方法,对任何做智能体 RL 训练或小模型工具调用优化的工作都有直接借鉴价值。

## Questions for Further Exploration

- How much of the +8.1-point synthetic-vs-real gap survives at larger scales (9B/27B), where real-task learnability filtering is cheaper relative to the policy's capability — does frontier-calibrated synthesis remain the better data source?
- Can the task generator and solver be co-trained (self-play), as the authors speculate, and does that compound or collapse (generator adversarially exploiting solver blind spots)?
- The harness sensitivity result motivates it directly: does multi-harness RL training (Leaf + mini-SWE-agent + OpenHands) recover the 5.2-point Leaf-vs-mini-SWE-agent gap and produce harness-agnostic agents?
- Why does the verifier's round-robin tournament only add ~1.4 points over pass@1 (62.8% vs 61.5%) — is the ranking signal weak, or is pass@3 headroom (72.3%) the real bottleneck to mine?
- Does the learnability-frontier targeting (p̂≈0.5) generalize beyond binary test-pass rewards, e.g., to rubric-graded or long-horizon tasks where a clean 0/1 resolve signal is unavailable?
