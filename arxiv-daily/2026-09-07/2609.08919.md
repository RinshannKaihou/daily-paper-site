> **一句话总结：** 提出 Experience Funnel（状态–策略交替循环）：先把交互轨迹蒸馏为经 held-out 验证门控的文本状态更新，再用"转移感知技能蒸馏"（跨状态版本的轨迹级 01/11 筛选 + token 级 JS 散度归因）把状态启发的有用行为选择性内化为无状态策略参数；在 SearchQA/ALFWorld/WebShop 上平均 57.6%，超过最强协同演化基线 SkillRL 1.4 个百分点，并把 SearchQA 无状态策略准确率从 58.1% 提升到 61.3%。

> **TL;DR:** Self-evolving agents face a fast-vs-slow adaptation dilemma: textual states (skills/memory) are editable but context-hungry; parametric policies are compact but slow to update. Experience Funnel alternates the two — trajectory batches become validation-gated state edits, and Transition-Aware Skill Distillation internalizes only behavior that stays useful across state revisions (trajectory-level newly-useful/persistently-useful selection + token-level JS-divergence attribution) into a state-free policy trained with GRPO. With Qwen3.5-4B as student and fixed Qwen3.5-27B as teacher it averages 57.6% over SearchQA/ALFWorld/WebShop vs 56.2% for SkillRL (+1.4) and 53.9% for SkillOpt (+3.7); on SearchQA, state-free accuracy rises 58.1% → 61.3%, and after consolidation a residualized state preserves full performance.

## 核心贡献

- **状态–策略交替循环（Experience Funnel / State–Policy Consolidation Loop）**：将快速的显式文本状态适应与慢速的参数化策略固化耦合为 (S_k, π_k) → S_{k+1} → π_{k+1} → … 的迭代演化——轨迹先沉淀为可编辑状态，有用行为再内化为参数能力，更新后的状态–策略对生成新轨迹进入下一轮。
- **转移感知技能蒸馏（Transition-Aware Skill Distillation）**：对每个实例在无状态 / 旧状态 / 新状态三种条件下评估结果，形成转移标签（新有用 0→1、持续有用 1→1、退化 1→0、无效 0→0），据此选择参与固化的轨迹；再用 token 级 Jensen–Shannon 散度对比有/无状态条件下的策略分布，定位真正归因于状态条件的决策 token，实现"选哪些轨迹 + 蒸馏哪些 token"的双重聚焦。
- **双向验证门控**：候选状态修订必须在 held-out 验证集上提升环境结果才被接受；候选策略也必须通过无状态性能验证才被提交——为自演化流程提供了少见的回退安全机制。
- **系统实证**：跨三个智能体环境平均 57.6%，一致超过仅状态演化（SkillOpt 53.9%）、仅策略内化（OPID 55.4%）与现有协同演化方法（SkillRL 56.2%）；并实证显式经验的价值随策略共同演化而增强（最终阶段协同配对 62.4% vs 同状态+初始策略 60.2%）。

## Key Contributions

- **A state–policy alternating loop** that treats explicit textual state as an *intermediate experience representation*: flexible enough for rapid validation-gated adaptation, structured enough to expose reusable behavior for parametric consolidation, and re-queried each round as the evolving policy generates fresh evidence for retaining, revising, or retiring guidance.
- **Transition-aware rollout selection**: by contrasting environment outcomes of the frozen policy under state-free (r⁰), previous-state (r⁻), and updated-state (r⁺) execution, the method classifies experience as newly useful (0,1), persistently useful (1,1), regressive (1,0), or inactive (0,0), and consolidates only the first two (weights 1 and α respectively) — going beyond prior skill-internalization signals that measure utility relative to a single skill version.
- **State-responsive token attribution**: per-token Jensen–Shannon divergence between state-conditioned and state-free branches of the same frozen policy, normalized within each trajectory, concentrates the distillation loss on decisions actually caused by the accepted state rather than on all tokens.
- **Combined objective with a commit gate**: L_consolidate = L_RL^state-free + λ_distill · L_distill (GRPO reward optimization + privileged state-conditioned teacher via weighted KL), committed only when state-free validation performance improves.
- **Empirical validation of the co-evolution thesis**: the compatibility gap between the co-evolved state–policy pair and the same state paired with the initial policy grows over rounds (2.2 pts at the final stage), directly showing that explicit experience is policy-dependent, not policy-independent guidance.

## Methodology

The framework runs as an alternating loop with two phases per round:

**Phase I — State Evolution.** The deployed (state, policy) pair accumulates interaction trajectories, which are frozen into a reflection batch. Cross-trajectory reflection summarizes *recurring* procedures, failure modes, and corrective strategies (not per-example fixes) into candidate edits of the current textual state. Each candidate edit is evaluated on a held-out validation set under the current policy and accepted only if it improves environment-level outcome — filtering sample-specific or unreliable updates.

**Phase II — Selective Policy Consolidation.**
1. *Transition-aware rollout selection*: for each instance x_i, the frozen policy π_k is executed three ways — state-free (r⁰), with previous state S_k (r⁻), with validated updated state S_{k+1} (r⁺). Indicator pair (b⁻, b⁺) ∈ {0,1}² relative to state-free execution yields four transitions; newly useful (0,1) gets weight 1, persistently useful (1,1) gets weight α, regressive/inactive get 0.
2. *Token attribution*: p⁺ and p⁰ are the frozen policy's next-token distributions with and without S_{k+1} under identical prefixes; d_{i,t} = D_JS(p⁺ ‖ p⁰) is normalized within each trajectory to token weights w_{i,t}, localizing which decisions the state actually changes.
3. *Consolidation training*: a trainable state-free policy π_θ is optimized with a weighted KL toward the privileged state-conditioned branch p⁺ (Eq. 8) plus state-free RL (GRPO) with reward r (Eq. 9). The candidate π̃_{k+1} is committed only if state-free validation improves; otherwise the loop keeps the previous pair.

The updated (S_{k+1}, π_{k+1}) pair is redeployed, generating the next round's trajectories. **Setup**: Qwen3.5-4B as the evolving policy, fixed Qwen3.5-27B as the OPD teacher, hard-answer accuracy (ACC) as primary metric, 910B3 Ascend NPUs, strict train/validation/test role separation, and five state-evolution rounds of which rounds 1 and 4 passed the validation gate (the rest retained the preceding checkpoint).

## Results & Highlights

- **Main table (hard ACC / success rate, %)**: Experience Funnel reaches **62.4 on SearchQA (vs 61.9 for SkillRL, +0.5), 67.9 on ALFWorld (vs 66.4, +1.5), and 42.4 on WebShop (vs 40.2, +2.2), averaging 57.6% vs SkillRL's 56.2% (+1.4)**; it beats the strongest explicit-state method SkillOpt by 3.7 points on average (53.9 → 57.6) and the strongest policy-internalization baseline OPID by 2.2 points (55.4 → 57.6). Versus the raw Qwen3.5-4B base, WebShop jumps 10.8 → 42.4 (+31.6) and ALFWorld 32.1 → 67.9 (+35.8).
- **Ablation (SearchQA, Table 2)**: the full loop hits **63.6% vs 61.1% for State-Only evolution (+2.5) and 62.8% for Policy-Only consolidation (+0.8)** — the two mechanisms are complementary, though parametric consolidation is the stronger standalone adaptation on SearchQA.
- **Progressive internalization (Fig. 2, Table 5)**: across accepted consolidation rounds, state-free policy accuracy rises **58.1% → 61.3% (+3.2)**; adding the full evolved state gives 62.4%; and a *residualized* state still yields 61.3% — i.e., after consolidation the absorbed guidance can be dropped with zero loss.
- **Co-evolution compatibility (Table 3)**: the final co-evolved state–policy pair reaches **62.4% vs 60.2% when the same evolved state is paired with the initial policy (2.2-pt gap**, growing from 0.8 pts at the intermediate stage) — the value of explicit experience increasingly depends on the policy it evolved with.
- **Cross-version experience selection (Fig. 3)**: after the second consolidation round, selective distillation on (0→1)+(1→1) transitions reaches **63.0% vs 58.9% for unfiltered consolidation (+4.1)** and beats the better single-transition subset (1→1 only, 59.9%) by 3.1 points; 0→1-only collapses to 55.2%.
- **Teacher-capacity control (Table 4)**: the 27B teacher helps **only when conditioned on the updated state — 61.21% vs 56.29% without state conditioning (which is below the 58.14% no-teacher base)**; a 4B teacher with state conditioning actually hurts (57.57% vs 59.79% state-free), supporting the asymmetric teacher choice.

## Authors & Credibility

Authors are from The Hong Kong Polytechnic University, Huawei, and Renmin University of China; the corresponding author (Weizhe Lin) is at Huawei. The work carries hallmarks of an industrial LLM-agent research lab: experiments on Huawei Ascend 910B3 NPUs, a Qwen3.5-4B/27B student–teacher configuration, and dense engagement with the very recent (2026) preprint literature — SkillOpt, SKILL0, SkillC, OPID, SkillRL, SEED, UCOB, HarnessForge are all cited and compared. The paper itself is an unreviewed v1 arXiv preprint (8 Sep 2026, cs.CL), as are essentially all of its baselines, so both the results and the baseline reproductions lack external verification; no code release is mentioned. Internal credibility is decent: the authors explicitly flag single-run configurations, uncontrolled cross-environment OPD budgets, and a confound in their own selection analysis rather than hiding them.

## Critical Assessment

- **Novelty**: genuinely incremental but well-scoped. The distinctive piece over OPID/SkillC/UCOB-style internalization is *cross-version* transition tracking (utility measured across state revisions, not relative to one skill snapshot) plus token-level JS-divergence attribution; the overall fast/slow loop is a synthesis of known ingredients (validation-gated skill editing, privileged-teacher distillation, GRPO) rather than a new primitive.
- **Rigor — single runs, small margins**: the paper states "each trained configuration corresponds to a single run," yet the headline SearchQA margin over SkillRL is only +0.5 (62.4 vs 61.9) and the average margin +1.4; no variance or significance numbers appear anywhere in Table 1 despite the setup section promising "repeated-run uncertainty ... for the final comparison." These margins could plausibly be seed noise.
- **The ablation partly undercuts the headline**: Policy-Only consolidation already reaches 62.8% on SearchQA, capturing most of the gain; the full loop adds only +0.8. Moreover, the ablation's full-loop 63.6% vs the headline 62.4% configuration difference is never explained (presumably different rounds/settings, but the text is silent).
- **Selection-analysis confound (self-admitted)**: under binary transitions, the (0,1)+(1,1) subset equals "instances successful under the updated state," so the 63.0-vs-58.9 result establishes the value of *success filtering*, not of transition-specific credit — the authors say so themselves.
- **Uncontrolled cross-environment evidence**: ALFWorld/WebShop use different OPD budgets, so per the authors those numbers are "descriptive summaries rather than controlled comparisons" — yet they still headline the all-environments-best claim.
- **Overclaim in the Conclusion**: it asserts results "across embodied interaction, web navigation, and execution-verified coding," but no coding benchmark appears anywhere in Section 3 — apparent leftover text from a longer version.
- **Short horizon**: only five evolution rounds with two accepted consolidations are observed; the long-run "funnel" behavior (state shrinking toward a stable core, compatibility gap plateau) is asserted, not demonstrated.
- **Reproducibility**: Ascend-specific infrastructure, Huawei-deployed models, and baselines that are all 2026 arXiv preprints make independent reproduction hard; hyperparameters α and λ_distill are introduced but their values are not reported in the extracted text.

## Strengths

- A clean and useful conceptual framing: explicit state as an *intermediate experience representation* between raw trajectories and parametric competence, with fast/slow timescales made concrete through the alternating loop.
- Two-sided validation gates (state edits accepted only on held-out improvement; policy checkpoints committed only on state-free improvement) provide regression safety that most self-evolution pipelines lack.
- The teacher-capacity control (Table 4) is a genuinely careful experiment: showing the 27B teacher *degrades* the student below base when state-free (56.29 < 58.14) rules out "gains come from a bigger teacher" in a way most distillation papers never test.
- The residual-state experiment (Table 5) directly demonstrates the funnel promise — consolidated guidance can be removed with zero loss — rather than merely arguing for it.
- Growing co-evolution compatibility gap (Table 3) is direct, well-designed evidence for the central thesis that experience is policy-dependent.

## Limitations

- Assumes repeated, related tasks with sufficiently informative environment-level feedback; one-shot tasks or subjective/sparse-feedback domains would need alternative utility signals (learned verifiers, preference feedback) that are not built here.
- Substantial compute–adaptation trade-off: every instance requires three-condition rollouts (state-free, previous-state, updated-state) with the frozen policy per round plus GRPO training per accepted consolidation; asynchronous off-path scheduling mitigates serving latency but introduces staleness between experience acquisition and model updates.
- Single model scale (4B student / 27B teacher) and a single deep-dive benchmark (SearchQA); ALFWorld/WebShop are budget-uncontrolled side evidence.
- No statistical significance testing, single runs for most configurations, and only two accepted consolidation events observed.

## Relevance

该论文处于 LLM 智能体自演化研究的前沿，直接涉及记忆/技能演化、on-policy 蒸馏与 agentic RL 的交叉主题：它回答了"外部经验何时应保留为文本、何时应内化为参数能力"这一核心问题。对关注智能体持续学习、经验管理与技能内化方向的研究者具有较高参考价值。

## Questions for Further Exploration

1. Does the funnel *converge* over many rounds — does the textual state shrink toward a stable minimal core, and does the 2.2-pt co-evolution compatibility gap keep growing or plateau?
2. How sensitive is performance to α (the weight on persistently-useful (1,1) trajectories) and λ_distill, and can transition-specific credit be isolated from simple success filtering using non-binary utility estimates?
3. Can the loop run self-taught (no larger teacher), given that a 4B teacher with state conditioning actually hurt (57.57%) — what teacher capacity is truly necessary?
4. Are the +0.5 (SearchQA) and +1.4 (average) margins over SkillRL robust across seeds and under compute-matched budgets for all baselines?
5. Does the framework extend to sparse/subjective-feedback domains via learned verifiers, and to the execution-verified coding setting claimed in the Conclusion but absent from the experiments?
