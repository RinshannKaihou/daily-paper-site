> **一句话总结：** SkillAdam 把 Adam 优化器的两个矩估计"功能化"地搬到离散的技能文档优化中——用 Evolving Issue Tracker（一阶矩类比）累积问题与历史解以稳定更新方向，用波动率驱动的编辑预算（二阶矩类比）自适应控制每轮修改幅度——在 7 个基准上取得 SOTA，且在 DeepPlanning 上比最强基线 SkillOpt 总 token 消耗降低 67.3%、DP-Avg 提升 6.7 个百分点（21.7% → 28.3%）。

> **TL;DR:** The paper turns Agent Skills (frozen-model instruction documents) into an optimization target and imports Adam's two moments as functional analogues: an Evolving Issue Tracker (first-moment analogue, a persistent memory of issues + past solution outcomes) stabilizes *what* to revise, while a volatility-driven edit budget (second-moment analogue, EMA of case-level improvement variance) adapts *how much* to revise. Across 7 benchmarks (SearchQA, SpreadsheetBench, OfficeQA, DocVQA, LiveMathematicianBench, ALFWorld, DeepPlanning) it beats the strongest baseline SkillOpt on 4 and ties on 1, with the decisive gains on long-horizon DeepPlanning: DP-Avg 28.3% vs SkillOpt 21.7% (+6.7 pp) and DP-Travel 11.7% vs 1.7% (+10.0 pp), while cutting total optimization tokens by 67.3% (74.0M vs 226.6M) and API requests by 68.8% on DeepPlanning. Worth reading if you care about agent self-improvement, prompt/skill optimization, or optimizer-inspired control of LLM editing loops.

## 核心贡献

- **提出 SkillAdam 框架**：将 Adam 的两条优化原则（聚合历史信号稳定方向、按信号幅度缩放有效步长）功能化地迁移到离散、不可微的技能文档（Markdown 自然语言指令）的自进化过程中，而非数值上照搬 Adam。
- **优化记忆 / Evolving Issue Tracker（一阶矩类比）**：以结构化条目（问题模式、当前状态、历次解决方案及其结果）持久记录已识别的问题，使每轮更新同时考虑当前反馈与跨迭代累积的证据，避免有效修正被迭代局部的反馈反复覆盖（解决"方向稳定性"挑战）。
- **波动率驱动的编辑预算（二阶矩类比）**：计算候选技能在 mini-batch 上逐 case 改进的方差，经 β2 指数移动平均得到历史加权波动率 Vt，再映射为下一轮编辑预算 σt+1 = max(b_min, b_base·(1 − clip(Vt/Vmax, 0, 1)))——改进越不一致，允许修改的范围越小（解决"更新自适应性"挑战）。
- **轨迹感知的初始化 + 多指标接受门控**：从执行轨迹与评估反馈构造初始技能；每轮候选修订在同一 mini-batch 上评估，只有至少一个指定指标达到改进阈值且所有受保护指标不越界时才被接受。
- **系统实验验证**：在 7 个基准、10 个评测切片上取得 SOTA，同时优化成本大幅下降，且技能跨模型迁移（GPT-5.5 → GPT-5.4-mini）与文档质量（盲评 judge）均优于 SkillOpt。代码开源于 github.com/ruc-datalab/SkillAdam。

## Key Contributions

- Proposes **SkillAdam**, an Adam-inspired framework for optimizing discrete, non-differentiable skill documents, importing Adam's two principles (aggregate history to stabilize direction; rescale effective step size by accumulated signal magnitude) functionally rather than numerically.
- Introduces an **optimization memory (Evolving Issue Tracker, EIT)** as a functional first-moment analogue: a persistent structured list of issue patterns, their status, and the outcomes of prior solution attempts, so each update conditions on accumulated evidence and effective corrections are not overwritten by iteration-local feedback (the Direction Stability challenge).
- Introduces a **volatility-driven edit budget** as a functional second-moment analogue: case-level improvements δt,i on the mini-batch yield a variance estimate, EMA-smoothed into Vt, which shrinks the next edit budget when recent effects are inconsistent and permits broader edits when improvements are uniform (the Update Adaptivity challenge). Maps onto σt+1 = max(bmin, bbase(1 − clip(Vt/Vmax, 0, 1))).
- Provides a clean formal problem statement (skill space S, case-level evaluator E(S,d) = (metrics, diagnostics), aggregation to scalar objective J(S)) and an explicit Adam↔SkillAdam correspondence table (loss↔evaluation feedback, gradient↔skill patch, m̂t↔EIT, v̂t↔volatility, effective step↔edit budget).
- Demonstrates state-of-the-art results on 7 benchmarks / 10 slices, substantially lower optimization cost, better cross-backbone skill transfer, and higher blind-judged skill-document quality; code released at github.com/ruc-datalab/SkillAdam.

## Methodology

SkillAdam optimizes a Markdown skill document S guiding a frozen LLM agent on task dataset D, maximizing a scalar objective J(S) = Φ(E(S,d)) aggregated by the benchmark's native evaluator.

**Initialization.** Before iterative optimization, an initial skill S0 is constructed by an LLM from a fixed set of baseline execution trajectories and their evaluation feedback (shared with SkillOpt for controlled comparison).

**Iteration loop (Algorithm 1).** At iteration t: (1) *Rollout* — sample mini-batch Bt ⊂ D, execute the agent under St−1, collect trajectories Tt and case-level feedback Ft_roll (metrics + diagnostics). (2) *Patch generation* — an LLM patch generator produces gt = G_LLM(St−1, Tt, Ft_roll, Mt−1, σt), conditioned on both current evidence and the two persistent optimizer states carried from the previous iteration. (3) *Candidate evaluation* — the candidate Se_t is evaluated on the same mini-batch, giving directly comparable case-level feedback Ft_val. (4) *Acceptance gate* — a benchmark-specific gate accepts the candidate only if at least one designated metric reaches its improvement threshold and every protected metric stays within its regression boundary; no separate validation set is used. (5) *Moment estimation* — the EIT evolves (link failures to existing issues, record attempt outcomes, reopen recurring issues), and the case-level improvement variance feeds the EMA volatility Vt = β2·Vt−1 + (1−β2)·V̂t, which sets the next edit budget σt+1.

**Key design points.** The EIT Mt = {Ij}, Ij = (problem pattern pj, status zj, prior attempts with outcomes Aj) plays the role of Adam's first moment; the volatility Vt plays the role of the second moment; the edit budget σt+1 plays the role of the effective step size. High volatility (a revision helping some cases while hurting others) shrinks the allowed edit scope, protecting accumulated guidance; consistent improvements license broader edits. The authors are explicit that the analogy is functional, not numerical — no gradients are computed in skill space.

**Setup.** Direct-chat, no-harness setting; frozen target models: GPT-5.5 (medium reasoning, temperature 1.0, 16,384 max output tokens) for six benchmarks, Claude Sonnet 4.5 (temperature 0.0) for DeepPlanning. One pass through the optimization pool with benchmark-specific stopping; seed 42; each test case evaluated once. Compared against NoSkill, HumanSkill (expert-written), LLMSkill (single-call LLM-written), Trace2Skill, TextGrad, GEPA, and SkillOpt (the closest prior work, which applies bounded textual edits with validation-gated acceptance).

## Results & Highlights

- **Short-horizon sweep (Table 2, GPT-5.5):** SkillAdam posts the best score on 4 of 5 benchmarks and ties SkillOpt on the fifth: SearchQA Exact Match 87.5 vs SkillOpt 87.3 (+0.2 pp; GEPA 84.8), SpreadsheetBench hard success 81.1 vs 80.7 (+0.4 pp; GEPA 73.6), OfficeQA EM 72.1 vs 72.1 (tie), DocVQA ANLS-hard 92.3 vs 91.2 (+1.1 pp), LiveMathematicianBench EM 67.7 vs 66.9 (+0.8 pp; vs TextGrad 49.2 and NoSkill 37.6).
- **Long-horizon gains are the headline (Table 3):** on DeepPlanning with Claude Sonnet 4.5, SkillAdam raises DP-Avg from SkillOpt's 21.7% to 28.3% (+6.7 pp from unrounded accuracies) and DP-Travel Case Accuracy from 1.7% to 11.7% (+10.0 pp) while NoSkill scores 0.0 on Travel; on ALFWorld goal completion it reaches 89.6 vs SkillOpt 87.3 (+2.3 pp) and NoSkill 83.6.
- **Ablation isolates both mechanisms (Table 4, DeepPlanning):** full SkillAdam DP-Avg 28.3%; removing the volatility-driven edit budget drops it to 21.7% (DP-Travel collapses 11.7% → 1.7%); removing the optimization memory as well drops it to 19.2% (NoSkill 15.8%). With memory fixed, the edit budget alone is worth +6.7 pp DP-Avg, with the largest gain on DP-Travel.
- **67% cheaper optimization at higher quality (Table 6, DeepPlanning):** total optimization tokens 74.0M vs SkillOpt's 226.6M (−67.3%), output tokens 1.5M vs 4.5M (−66.8%), API requests 2,830 vs 9,071 (−68.8%) — while *improving* DP-Avg by +6.7 pp; tokens per request are similar (SkillAdam slightly higher), so the saving comes from fewer unproductive attempts, and DP-Avg per million optimization tokens is roughly 4× SkillOpt's.
- **Cross-backbone transfer (Table 5, skills trained on GPT-5.5 deployed verbatim on GPT-5.4-mini):** average target-model score 67.8% vs SkillOpt's 63.1%, average retention ratio 81.3% vs 76.2%; SkillAdam wins target scores on 5 of 6 benchmarks (SearchQA the exception, 78.9 vs 80.8) and retention on 4 of 6 (e.g., ALFWorld retention 92.4% vs 76.1%).
- **Blind skill-quality judging (Figure 3):** a frozen GPT-5.5 judge (3 independent calls, median over 6 dimensions, method names hidden) scores SkillAdam's skills higher than SkillOpt's on **all 10** benchmark slices, mean 3.88 vs 3.30 on the 1–5 scale.
- **Optimization dynamics (Figure 4, DeepPlanning Shopping L1):** SkillAdam accepts a strong revision in iteration 1 and every subsequent accepted skill stays above the 40% initial accuracy (reaching 56% test accuracy after ~4M tokens), whereas SkillOpt's accepted updates fluctuate around/below its starting point and a comparably strong candidate appearing at ~20M tokens is never accepted — about one-fifth the token cost in this run.

## Authors & Credibility

A Renmin University of China (Gaoyuan Li, Meihao Fan, Yizhe Liu, Shaolei Zhang — corresponding author, Ju Fan) + Tencent (Siyi Wang, Jiaheng Hou, Xudong Weng, Honghan Tian, Zang Li) collaboration; the RUC side (ruc-datalab) has a strong track record in data-preparation and agent systems (DeepPrep, DA-Studio, DeepAnalyze, CoDA-Bench are cited from the same group), and Tencent contributes the production-side perspective. The paper is unusually candid for an empirical agent paper: it repeatedly flags what its own analyses do *not* isolate (cumulative ablation does not separate memory's effect when the budget is enabled; the transfer and judge experiments evaluate the whole framework, not individual components; Figure 4 is a single run). Code is promised at github.com/ruc-datalab/SkillAdam. The experimental matrix (7 benchmarks, 7 baselines, ablation, transfer, judge study, cost accounting, dynamics) is well above the field's median rigor.

## Critical Assessment

- **Novelty: good, but the "Adam" framing is an analogy, not a theory.** The two persistent states are a sensible engineering recipe (a structured issue log + a variance-scaled edit budget), and the explicit Adam correspondence table is elegant. But nothing is proven: there is no convergence or stability analysis in the discrete setting, and the EIT is itself LLM-maintained, so "first moment" quality is bounded by the tracker LLM's reliability. Readers wanting a formal discrete optimizer will find a heuristic wrapped in optimizer vocabulary.
- **Rigor: the SOTA claim leans on thin margins over one baseline.** On the five short-horizon benchmarks the deltas over SkillOpt are +0.2 (SearchQA), +0.4 (Spreadsheet), 0.0 (OfficeQA tie), +1.1 (DocVQA), +0.8 (LiveMath) points, and each test case is evaluated exactly once with temperature 1.0 — no repeats, no variance, no significance tests. A 0.2–0.4 pp margin from a single noisy run is within run-to-run noise for LLM agents; only the DeepPlanning and ALFWorld gains look robust.
- **Borrowed baselines.** The five short-horizon baseline columns are not re-run: they are taken from the GPT-5.5 no-harness numbers *reported by SkillOpt* (only ALFWorld NoSkill/SkillOpt and DeepPlanning are reproduced). The comparison is fair within a benchmark, but any setup drift between SkillOpt's runs and this paper's is unmeasured. Also, SkillAdam merges SkillOpt's train+selection partitions into one optimization pool while SkillOpt retains its original split — a small but real protocol asymmetry that favors SkillAdam.
- **Tiny test slices inflate granularity.** DeepPlanning Shopping L3 has only 10 test cases (each case = 10 pp on that slice) and DP-Travel has 60; the headline 11.7% Travel accuracy is 7/60 cases, and NoSkill/SkillOpt's 0.0%/1.7% baseline means the relative story is "from near-zero to still-low" — 11.7% absolute is far from usable travel planning.
- **Missing ablations and knobs.** The ablation is cumulative, run only on DeepPlanning, and (as the authors admit) does not isolate memory-with-budget interactions, nor are the short-horizon benchmarks ablated at all. The method introduces many per-benchmark hyperparameters (acceptance thresholds, protected-metric regression boundaries, bbase, bmin, Vmax, β2, stopping rules) whose sensitivity is not reported in the main text — tuning opacity is the practical adoption risk.
- **Judge-study circularity risk.** The blind quality judge is the same GPT-5.5 family that serves as the optimization backbone; self-preference bias in LLM judges could inflate the 3.88-vs-3.30 quality gap. The all-10-slice consistency mitigates but does not eliminate this.
- **Red flags: none serious.** Claims are mostly scoped correctly, negative details (rejected high-test-score revision at iteration 8; SearchQA transfer loss) are disclosed, and cost accounting excludes only initial-skill generation and final evaluation — reasonable exclusions, stated openly.

## Strengths

- Attacks the two genuinely painful failure modes of iterative skill/prompt refinement — oscillating revisions that undo each other, and edit scope that ignores evidence reliability — with mechanisms that directly target each.
- The functional Adam correspondence (Table 1) is a clarifying conceptual contribution that makes the design legible to the optimization community and suggests a template for other discrete-optimization-by-LLM settings.
- Cost accounting is exemplary: per-phase token/request counts, the observation that tokens-per-request are similar (so gains come from fewer attempts), and a token-efficiency ratio (~4× DP-Avg per million tokens) — exactly the numbers a practitioner needs.
- Strong and broad evidence on the hard setting: the +6.7 pp DP-Avg / +10.0 pp DP-Travel improvement and −67.3% token cost against the strongest recent baseline (SkillOpt) is a convincing simultaneous quality+efficiency win.
- Unusual candor: the paper repeatedly states which experiments do not isolate which components, and discloses its single-run and unrounded-delta caveats.

## Limitations

- Short-horizon margins over SkillOpt are small (≤1.1 pp, one tie) and come from single, unseeded-variance evaluations — statistical significance is not established.
- Baseline numbers on five benchmarks are imported from the SkillOpt paper rather than re-run; SkillAdam also optimizes over a merged train+selection pool that SkillOpt does not use.
- Absolute performance on the hardest slice (DP-Travel 11.7%) remains low; test slices are small (Shopping L3: 10 cases), so slice-level numbers are coarse.
- The ablation is cumulative, DeepPlanning-only, and does not disentangle memory–budget interactions; no sensitivity analysis for the budget parameters (bbase, bmin, Vmax, β2) or benchmark-specific acceptance thresholds.
- The Adam analogy brings no formal guarantees, and both the issue tracker and the patch generator depend on a strong frozen LLM (GPT-5.5 / Claude Sonnet 4.5); behavior under weaker backbones during optimization is untested (only post-hoc transfer to GPT-5.4-mini is shown).

## Relevance

与"智能体自我进化 / 技能库自优化"方向高度相关：把 Anthropic Agent Skills 的迭代打磨形式化为带持久优化状态的离散优化问题，对做 agent 记忆、prompt/技能优化与"用优化器思想控制 LLM 编辑循环"的研究都有直接借鉴价值，尤其是其用执行反馈方差自适应控制修改幅度的设计可迁移到其他自进化流水线。

## Questions for Further Exploration

- Would replacing the LLM-maintained Evolving Issue Tracker with a deterministic, embedding-based issue clustering change stability — i.e., how much of the first-moment benefit is the LLM's bookkeeping vs. simply having *any* persistent issue log?
- How sensitive is the volatility→budget mapping to its hyperparameters (β2, Vmax, bmin) and to mini-batch size k=2 edge cases, and can the budget rule be learned rather than hand-mapped?
- Since the rejected iteration-8 revision had a high post-hoc test score, would a small held-out acceptance set (rather than same-batch acceptance) recover useful revisions without reintroducing instability?
- Do the gains persist when the optimization backbone is a weak/open model, or does the EIT degrade into noise (the paper only transfers final skills to GPT-5.4-mini)?
- Can the memory-plus-budget decomposition be ported to other discrete self-evolution targets — multi-file skill packages, tool libraries, or agent workflows — where the current single-document setting does not obviously apply?
