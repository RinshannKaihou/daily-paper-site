Verification interface · self-evolving agents

Two updates can give the verifier byte-identical readouts and opposite safety outcomes — so compare each against a same-readout twin.

两个更新在验证器读数上逐位相同，安全后果却可能相反。这不是阈值没调好，而是证据层面的不可分辨——所以要在等价类里造一个"替身"，让两者从同一状态各自回放，再问比较模型谁更危险。

Why this matters

Long-running agents that rewrite their own memory need a cheap pre-commit gate: compare against a twin, abstain, roll back.

冻结验证器、两次比较调用、不带安全标签训练——是一个能直接挂到 agent memory / skill library 上的接口。

Critical edge

The 0.940 lives on a benchmark where harmful twins are abundant; the realistic τ²-Bench gain is 0.662 → 0.694, and its decisive comparisons rest on 24 and 6 units (p = 0.094).

— Critical Assessment: benchmark distribution favours the method

01Methodology — turn an impossibility into a procedure

DoppelVet never asks for more evidence about one trace. It manufactures a matched sibling inside the verifier's own equivalence class, then makes the two race.

Setup. Persistent state st (skills, memories, prompts) plus a fixed replay bank. A native verifier emits a readout recording every value its rule consumes — reward, episode length, test outcomes — not just the final pass/fail.

Stage I · the twin. Enumerate a bounded neighbourhood of edits, keep only candidates whose canonical readouts are byte-for-byte equal, and rank survivors by visible trace distance (board-cell Hamming plus per-step reward mismatch; for text, difflib over tool order and rendered dialogue). Take the most divergent. If nothing diverges, abstain rather than admit.

Stage II · the comparison. Replay candidate and twin from the same starting state, score them twice with semantic roles fixed and display order swapped, then average the logit margin. Thresholds θA ≤ θR give admit / reject / abstain; order disagreement forces abstention.

Stage III · the ledger. A commit needs both a deterministic contract check and the comparison's admission. A rollback receipt binds the pre-update state, both updates, replay bank, scores and thresholds. The twin is never auto-committed — a relative preference is not a safety certificate.

02The pipeline in one column

  1. I

    Search the class

    Equal readout, maximal visible divergence. No sibling → abstain with st untouched.

  2. II

    Replay both

    Same start state, two display orders, averaged margin. Two model calls per proposed update.

  3. III

    Gate the write

    Deterministic checks + receipt + post-activation monitoring; violation restores the validated state.

  4. ↺

    Keep going

    464 starting programs, ten generations, safe-update retention still 89.58%.

05Strengths

  • A crisp, falsifiable framing of an interface defect, with a demonstration instance you can check by hand (reward 50 / 5 steps, safety 50 vs 0).
  • A wrapper, not a new model: frozen verifier, no retraining, two calls — and fewer tokens than the four-critic baseline it beats.
  • Two tracks that argue the phenomenon is not a Gridworld curiosity: executable programs with deterministic hidden labels, and τ²-Bench memory notes with real tool traces.
  • Abstention, deterministic checks and rollback receipts instead of pretending a relative preference certifies safety.
  • Unusually strong provenance hygiene for a preprint — pre-registered plan, withheld label artifact, SHA-256 stage linkage, class-grouped splits.
  • It publishes its own failures: the "stronger" two-pass guardrail scoring below chance, p = 0.094, and 17/28 on its text comparator.

06Limitations

  • Coverage is never reported: how often Stage I finds no twin — and therefore abstains — is missing for the 446-case Grid test set and per backbone.
  • The benchmark is the method's best case: twin prevalence runs ~50–75% in Sushi variants and 0% in Vase and Island, with no reweighting to a realistic update stream.
  • A frontier ceiling: GPT-5.6 Sol +0.002, Claude Opus 5 +0.001. The value proposition narrows to "useful when your verifier is mid-tier", which the mean-of-nine framing hides.
  • Cost is counted in executions, not tokens, wall-clock or environment rollouts — N×m real API/DB calls per proposed memory in deployment.
  • Text-side construction is hand-tuned and low-yield: 364 contrasts → 168 exact reward matches → 28 safety splits (7.7%), comparator right 17/28 (61%).
  • No released code, benchmark artifact or public evidence paths; single lab, single benchmark, no external replication.

07Questions worth chasing

  1. What is Stage I's coverage, and how does the admit / reject / abstain split vary by backbone? Abstention is the missing half of the utility story.
  2. Does order averaging earn its second call — and how often do the two orders disagree?
  3. Would a random eligible twin do nearly as well as maximum divergence, especially where dgrid rides visible rewards that may correlate with hidden harm?
  4. Could a non-LLM comparator — a program diff or symbolic side-effect checker — match the LLM on Grid?
  5. Why does the "deliberately stronger" two-pass AgentDoG condition score below its own single pass (0.419 vs 0.454)?
  6. Can an attacker who knows DoppelVet craft a pair where the more divergent trace is also the safer one, flipping the verdict?
