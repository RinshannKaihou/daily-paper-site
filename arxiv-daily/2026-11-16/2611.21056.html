Why it matters

Self-improving scaffolds can now get better without grading candidates on tasks — cheaper, and plausibly less overfit to the benchmark being optimized.

Direct hit on the “self-evolving agent / auto-designed scaffold” line: it isolates one design choice — task feedback inside the loop — instead of stacking engineering tricks.

Read it critically

Removing the deterministic gates collapses the average from 76.1% to 52.0% — below the 60.0% starting agent — so “evaluation-free” is really “cheap-static-check-gated.”

The gates’ own precision is unmeasured; 6 of 7 exploration rejections were type-check false positives.

Methodology 方法

  1. Diagnose. Read the current scaffold source, name concrete implementation defects, emit K = 7 hypotheses — each with a capability, a limitation, a mechanism and completion conditions.
  2. Patch in parallel, same parent. Every hypothesis is implemented against the identical parent, so children differ only by mechanism and are directly comparable — no sequential accumulation. K = 7 children · T = 10 generations · 8 workers
  3. Admissibility gate Gexp. Deterministic: non-empty patch, key modules compile, imports / tool loading work, modification scope and dependency rules respected. It tests admissibility, not capability.
  4. Integrate mechanisms. The LLM reads hypotheses, patch summaries and gate results (full diffs on request), labels compatibility, then rewrites a coherent descendant — not a diff merge. complementaryredundantconflictingoverly complexincomplete
  5. Acceptance gate Gacc. Call/return protocol, message ordering, bounded execution, main-loop smoke tests. Failure keeps the parent untouched.

The evolutionary state S_t never receives a task outcome: only implementation artifacts and deterministic gate results enter the loop.

Dynamics & spread 后验动态

Integration is not omnipotent
Step one: seven children score 83.3 / 81.7 / 80.0 / 80.0 / 80.0 / 76.7 / 3.3%; the integrated child lands at 81.7% — better than five of seven, worse than the best.
Gates do reject real breakage
Two integrated descendants fail G_acc (tool-order violation, call-limit violation); three generations fail at hypothesis composition.
Gains are repository-wide
Improves 8 of 11 repos, ties 2, declines 1 — e.g. Tutanota 13/15 → 15/15, Qutebrowser 4/9 → 8/9, Navidrome 2/3 → 1/3. Not a single-repo artifact.

Strengths 优点

  • A clean, falsifiable question. Names the shared “evaluate-and-select” assumption behind DGM, HGM, GEA, SIFT and MGM, then removes exactly that one ingredient.
  • Unusually candid reporting: losing numbers in the abstract, per-run tables with SDs, and an explicit admission that budgets are not compute-matched.
  • Transfer is the substantive finding — +8.0 Verified, +4.6 Polyglot over HGM without any adaptation, plus a second scaffold (mini-swe-agent + Claude-opus-5.5, 71.7 → 83.3 Pro).
  • Mechanism-level evidence, not just scores: exit-code feedback and streaming reads composed into one tool that returns 100,000 lines and reports exit code: 7.
  • Breadth checks: width sweep K ∈ {3, 5, 7, 9}, cross-backbone scaffold portability in both directions, repository breakdown, six code-level case studies.

Limitations 局限

  • No compute-matched comparison. Different patch counts, worker pools and imported baseline resources — the 8.8× cannot be separated from implementation and hardware.
  • Small, fixed, public subsets (60 / 50 / 50 tasks) with no task-sampling error bars and no contamination check; all three benchmarks are likely in pretraining data.
  • Single runs for the comparisons the argument leans on: Qwen baselines and every selection-strategy ablation.
  • Single lineage, no archive — so the HGM comparison conflates selection paradigm with search architecture.
  • Opaque, brittle gates. Documented false positives, no precision/recall; “permitted modification scope” is enforced by prompt, not by the checker.
  • Coding-only evidence; integration quality is judged by an LLM whose compatibility claims are never verified.

Questions for further exploration 待解问题

  1. Under a matched self-modification budget (equal patches, equal tokens), does integration still beat evaluation-based selection on Pro — or was 91.7 vs 85.6 a budget artifact?
  2. How much of the transfer advantage survives on a contamination-resistant suite instead of public Verified / Polyglot subsets?
  3. Which gate is doing the work — admissibility or acceptance? A 2×2 ablation is missing.
  4. Does the integrator’s mechanism reasoning add anything beyond “seven concrete patches in one context”?
  5. Would an archive of historical agents escape the 85.6% local optimum, or is archive scheduling uninformative without task feedback?
  6. What happens past 50+ generations, once missing exit codes and brittle parsers are exhausted?
  7. Can stronger static analysis or property-based tests replace the gates while cutting the 6/7 false-positive rate?

Method > headline: the gate ablation (76.1 → 52.0) and the K-sweep say more about why this works than the 85.6% itself.
