Critical assessment

03 — Methodology / 方法

Design for the chip, not for the paper

Architecture MLA + DSA + cross-layer IndexShare; 45 shallow-wide layers; DSpark decoding.
Systems FSDP instead of pipeline parallelism; owner-rank Muon; knapsack recompute.
Post-training TeleGym + async server + Slime; partial rollout across policy versions.
  • Hardware-first objective. Ascend 910C has strong Cube throughput but constrained Vector compute and HBM bandwidth, so the design targets “matrix-dominant compute, structural avoidance of Vector bottlenecks, sparse memory access.”
  • Attention. MLA compresses the KV cache; DSA’s lightning indexer keeps only Top-K historical KV; IndexShare reuses sparse indices across layers so the indexer graph is walked once per group.
  • Depth–width. 45 layers, hidden 4,096, 256 routed experts of width 2,048, 8 selected per token plus one shared expert. A 60-layer / 1,536 / 6-expert baseline loses on prefill, decode and training throughput.
  • Decoding. DSpark block-wise speculative decoding: a 5-layer DFlash draft, a Markov head and an acceptance-confidence head.
  • No pipeline parallelism. HyperParallel-FSDP shards inside each SuperPoD and replicates across; per-parameter collectives remove copy-in/copy-out; a three-way schedule overlaps ReduceScatter, AllGather and inter-SuperPoD AllReduce.
  • Post-training. TeleGym puts heterogeneous harnesses behind one episode interface; sampling-time log-probs, bounded oversampling and execution-level reward grouping handle long, uneven agent tasks. All systems profiling: 1,024 NPUs, 262,144-token sequences, global batch 16, TP4 / EP64 / CP32.

05 — Strengths

What earns trust

  • A rare artifact: a full engineering account of a 285B MoE on a non-NVIDIA stack, naming the hardware, the frameworks and the 8,192-card production cluster.
  • Disciplined attribution: each systems change is isolated against a fixed baseline with the parallelism layout held constant.
  • Unusual candour: memory budgets called “heuristics,” overlap called “opportunistic,” the indexer path explicitly “not a zero-memory-cost design.”
  • Clean, generalisable finding: the same host-side change buys 1–2% at 512 cards and 5–10% at 8,192 cards.
  • Recompute as a knapsack: measured forward time versus measured output bytes, plus address-keyed boundary placeholders — more principled than “checkpoint every k-th layer.”
  • TeleGym’s bookkeeping: execution identity separated from token trajectories; stale groups rejected whole rather than per segment.
06 — Limitations

What the report never shows

  • Zero capability numbers in 32 pages: no MMLU, GPQA, SWE-bench, τ-bench or agent success rate — not even for the released 29B.
  • No GPU control group, so Ascend-specific adaptation cannot be separated from generally good practice.
  • Simulation dressed as measurement: both the attention and depth–width wins come from Zhanlu; the caveat sits in body text, not the abstract.
  • No combined ablation: 9.1% + 6.9% + 15.2% are never run together, and obviously do not sum.
  • No training telemetry: token budget, data mixture, learning-rate schedule, loss curves and stability events are all absent.
  • TeleGym is described, never evaluated: no RL curve, no sync-vs-async comparison at matched compute.
  • Internal inconsistencies: 16.1% in the abstract versus 12.6% in Table 7; a 31.8 s versus 28.9 s baseline; 516 MiB versus 656 MiB “largest output.”
07 — Open questions

Questions the next report should answer

  1. What does Xing4.0-29B-A4B actually score against Qwen3-30B-A3B or Hunyuan-A13B at matched activated parameters — and did 45 layers cost quality versus 60?
  2. Do the 2.67×–3.77× DSpark gains survive at 256K context, and what are the acceptance length and per-token accuracy delta there?
  3. What is the step time with owner-based Muon, selective recomputation and layer-wise indexer backward all enabled — additive, sub-additive, or conflicting?
  4. Where does the abstract’s 16.1% pipeline-parallelism gain come from when Table 7 shows a 12.6% step-time reduction?
  5. Would the same architecture choices still win on an H800-class cluster with abundant HBM bandwidth?
  6. How sensitive is the recomputation knapsack to the activation-memory budget M, given it is solved from one rank-0 layer profile?
