Self-WSP: Can Language Models Improve Themselves Through Weight-Space Programming?

Guoming Ling, Shanshan Zhong, Kaixuan Zhang, Zhongzhan Huang  ·  CMU / MilkThink

让 Qwen3.5-0.8B 读取自己的 318 个张量目录、直接改写权重，再由带参考答案的固定外层循环决定保留与否——GSM8K 从 11.8% 提到 62.2%。但行为诊断显示：它并没有“理解”自己改了什么。

Why this matters

The cleanest closed-loop test of recursive self-improvement through weights, and the first to price it against a same-budget random search.

It converts an RSI narrative into a measurable, falsifiable effect size.

Critical edge

If ~90% of the original model's failures are unfinished 32k-token generations, the headline mostly counts timeouts converted into completed attempts, not mathematics learned.

— Critical Assessment

One checkpoint, two roles

Editor = thinking off  ·  Solver = thinking on, 32,768 tokens  ·  every kept edit changes both

  1. 01
    Read

    A catalog of the 318 editable tensors (all 24 layers, opaque IDs). After naming one or two, the editor gets shape, mean/std, up to 64 raw values with positions, and row/column norms — plus two practice batches with reference answers, accuracy, unfinished share and repetition score. No Python environment: the host precomputes everything.

  2. 02
    Propose

    A JSON grammar derived from tensor shapes. Seven operations — zero, scale, add, fill, redraw from mean and |v|·std, direction removal, bounded NumPy expression — over flat entries, whole rows or whole columns. Values in [−10, 10], at most 8M BF16 values.

  3. 03
    Judge

    The edit is applied to a copy and scored on two disjoint practice batches. It is kept only if the combined gain clears a threshold and neither batch regresses; otherwise the copy is discarded and the current weights survive.

  4. 04
    Keep, then repeat

    The surviving copy becomes the solver and the next round's editor. Practice questions are the only optimization signal; validation is never fed back and only ranks finished runs.

Rejected outright: uniform whole-tensor rescaling, repeats of an evaluated edit, no-ops after BF16 rounding, >8M changed values. Embeddings, output layer and final norm are not editable. The grammar guarantees format, never semantics — the host never repairs an edit.

Random search uses the same tensors, operations, selection rule and budget. It is measured only under the shuffled catalog, where the comparable self-edit scores 31.9% (GSM8K) and 17.3% (MATH500) — a tie on GSM8K, a clear loss on MATH500. The ordered interface, source of 61.0% and 24.7%, has no matched random baseline. GPT-6 numbers are its direction-removal edit re-evaluated in the same pipeline (its zeroing edit: 22.0% / 13.8%), with different tools, feedback and budgets.

How small is the winning edit?

No selected model changes more than 0.2% of its weights

16numbers

The best MATH500 model differs from the original in 16 BF16 values: layer-0 A_log, which sets each head's forgetting rate in the gated-delta layers. A 32-number GSM8K edit reaches 59.9%; one continued MATH model gains 6.8 pts from two numbers.

1,000 cells ≈ the parameter space. Two lit cells = 0.2%. For contrast, one shuffled-interface model edits 1,048,686 values and reaches only 28.7%.

The probes: what the editor actually does

Four behavioural diagnostics plus one retention check — this is the paper's real contribution

62% vs 2.9%

Share of valid edits landing in layer 0 with a layer-sorted catalog versus a shuffled one (fair share: 4.4%). All 15 ordered winners edit layer-0 A_log; 0 of 9 shuffled ones do. The bias appears in each round's first proposal, before any outcome is seen.

9–28%

Share of edited values that equal a mean, std or norm the editor read in the same call. The number −1.979 appears as a scale or shift in four selected models.

“$11”

One kept edit's entire rationale is “The cost of one chair is $11.” — copied verbatim from a practice response. Hypotheses are generated, not derived.

69%

of 11,580 proposals were rejected as invalid; only 12% of valid edits were kept; direction removal and bounded expressions — the two operators that could express structure — were never used.

Keeping an edit is not the same as improving: under the shuffled catalog more than 40% of edit-keeping rounds lower validation accuracy, and a third still do on MATH under the ordered interface. The loop succeeds as search plus selection over a tolerant proxy, not as introspection.

Strengths

  • Reports the evidence against itself: the random-search tie, the frozen-editor null, the spot-check collapse and the “$11 chair” rationale all sit in the main text.
  • The catalog-order ablation cleanly separates “reasons about weights” from “reads the list top-down” — 62% vs 2.9% is hard to explain away.
  • The mechanism story (repetition → unfinished answers → near-linear accuracy loss) is concrete and retrospectively explains a published negative result on Gemma 3 270M.
  • Complete artifact trail: every kept edit for all 24 selected models, the verbatim prompt, random-sampler distributions and exact splits.
  • Methodologically careful where it counts: disjoint practice batches, validation never fed back, pre-registered spot checks, paired bootstrap with Bonferroni.

Limitations

  • One 0.8B checkpoint, two math benchmarks, and a repetition pathology that is unusually easy to perturb. Says little about models that already finish their answers, or about code and agentic tasks.
  • The outer loop is supervised: it needs reference answers on practice questions, so this is self-editing, not unsupervised self-improvement.
  • No random-search control under the ordered interface, and no reversed-catalog test — the most quotable numbers lack their matched baseline.
  • Headline figures are best-of-12/24 after validation selection. Pre-registered spot-check runs average +24.7 / +7.7 pts, roughly half the selected models' +49.2 / +17.7.
  • The GPT-6 comparison is explicitly not apples-to-apples: different tooling, feedback and budgets.

Questions for further exploration

The controls the paper did not run

  1. What does random search score under the ordered interface at equal budget? If it also lands near 61%, the gain is interface engineering, not self-editing.
  2. How much of the +49 points survives a zero-parameter intervention that only breaks repetition — a no-repeat n-gram penalty, forced \boxed{} termination, or a length cap?
  3. Does the loop still work on a model that finishes >95% of GSM8K generations within budget? The paper's own mechanism predicts much smaller gains.
  4. Is the layer-0 A_log effect causal and transferable? Editing it by hand, with no search, would show whether the loop finds something real or a lucky basin.
  5. Does a cheap hypothesis–edit consistency filter recover most of the gain with a fraction of the 11,580 proposals?
