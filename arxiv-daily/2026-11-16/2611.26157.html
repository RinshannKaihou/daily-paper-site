Key metric

DeepSWE v1.1 tasks solved at 3.0 bpw — BF16 solves 44. The same model's 3.00 bpw GSQ-RCO file manages only 29.

84.9% vs 83.0% of new tests passed

Why this matters

Short benchmarks miss agent collapse: AIME barely moved while DeepSWE fell to 63%. Anyone shipping quantized agents should measure long-horizon tasks directly.

Critical edge

Every non-BF16 agent number is transcribed from Unsloth's harness — mini-swe-agent, ≥3 attempts per task — and normalized by that harness's own BF16, so the headline gap is not measured on one instrument.

01 · Method

4 changes

Format unchanged: randomized power-of-two Hadamard rotation · QTIP bitshift trellis · computed codebook decoded inside the matmul (EXL3-style) · YAQA two-sided rounding when it beats input-only by ≥5%.

  1. 1

    Model-token loss

    End-to-end KL is computed only at positions BF16 generated in real agent traces. Tool output and file contents remain in the prefix — masked out of the loss, kept as context.

  2. 2

    Per-module loss, then allocation

    RCO's first-order width score collapses for trellis codes, so estimate the current width's loss from ⟨G, Wc−Wk⟩, extrapolate by the code's measured MSE (≈4× per bit), then solve a multiple-choice knapsack with a mean + 2 s.e. margin.

  3. 3

    Banded output layer

    248,320 lm_head rows ranked by mean predicted probability into 16 bands of ~15,500, each allocated separately and floored at 2 bits. The 2.0 bpw file also bands embeddings by input frequency.

  4. 4

    Scale tuning

    Coded-matrix scales and all norm weights tuned on a 70:30 mix of coding-agent traces and BF16 replies to general prompts (math, science, chat, long documents).

Leakage control: calibration split by repository; every repo shared with DeepSWE removed. A reserve KL set is never used for any decision.

05 · Assessment

read both columns

Strengths

  • Names a real, under-measured failure mode and quantifies it across four published baseline families before proposing anything.
  • Unusually cheap intervention: no new format, no weight fine-tuning — four changes to the loss mask, allocator objective, output layout, scale data.
  • Mechanistic bit-allocation result: curvature cosine of 0.035 / 0.009 / 0.004 explains why RCO's width score degenerates for trellises.
  • Strong leakage hygiene — repository-level DeepSWE exclusion, a reserve KL set untouched by every decision.
  • Complete artifacts: GGUF weights, a working inference fork, and an appendix re-scoring every competitor with the authors' own KL code.
  • Reports the 2.0 bpw regression with its mechanism (AIME 77.3 → 86.0 from general data), not a vague "future work".

Limitations

  • One model, one scaffold, two agent benchmarks, one attempt per task; no seed replication and no second architecture.
  • Non-BF16 baselines transcribed from Unsloth charts under a different harness; the offset is acknowledged but never measured.
  • Cumulative, not factorial ablation — the central masking claim is entangled with the 2 s.e. margin, and no per-component ablation exists at 2.5 or 2.0 bpw.
  • Low statistical power: s.e. 3.2–3.6 on 113 tasks; a 3-task solved-count gap carries no interval at all.
  • "Sub-3-bit" holds at 2.5/3.0 only; the loss model is documented to break at 1 bit — exactly the regime the title advertises.
  • Calibration trace cost unquantified; quantizer, allocator and traces not released; throughput tied to SM120.

06 · Open questions

4 missing experiments
  1. Does masking alone carry the gain? A factorial ablation at 2.5 bpw (mask × margin × bands × 70:30 data) would separate the four changes.
  2. How much calibration data is needed? Sessions, repository diversity, and the fraction of tokens that are tool output are never swept.
  3. Would one Unsloth GGUF scored in the authors' own harness recover the claimed 28-point DeepSWE gap — or is it mostly mini-swe-agent's ≥3-attempt protocol?
  4. Is RCO's score degenerate for all decorrelated codes, or only for trellis codes? Scalar and vector codes would test the mechanism.
  5. How many tasks certify "within 2 points of BF16" at 95% confidence — and is a multi-attempt protocol cheaper than more tasks?
  6. Does the banded lm_head interact with tokenizer fertility? MGSM still drops 3.4 pts at 2.0 bpw, so the 2-bit floor looks necessary rather than sufficient.
