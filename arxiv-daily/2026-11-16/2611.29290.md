> **一句话总结：** 作者用 9 个 benchmark × 4 个模型 × 4 种 skill × 4 级 harness × 3 档 budget（约 90 万条轨迹）的配对因子实验证明"干预的增益高度依赖配置"——同一个 SQuAD skill 在 Qwen3.5-9B 上从 H0 的 +66.2 分掉到 H2 的 +2.2 分，而自演化 skill 很少能打赢一段几十词的人工 skill，换模型即崩。

> **TL;DR:** A matched factorial study (1,872 test instances, 9 benchmarks, 4 models, 4 skill conditions, H0–H3 harness ladder, 3 budgets, 898,560 executions) shows that intervention gains are conditional rather than additive: on SQuAD/Qwen3.5-9B the same frozen Trace2Skill skill is worth **+66.2 EM points at H0 but +2.2 at H2** (interaction −64.0, CI [−69.9, −58.2]), because NoSkill already reaches 96.1 under a content-based rescoring — the "skill gain" was answer formatting that a standardized interface supplies for free. Symmetrically, a harness can rescue a skill-induced failure (Hotpot FullWiki + Direct: −22.0 at H1 → +1.7 at H2) or leave it untouched (UCSB SOP +13.3 at H2). Feedback only repairs failures that expose a visible signal (SQuAD 76.9% rescued vs 1.3% for silent failures), evolved skills collapse across models (GPT-5.6-sol on Hotpot Context: 62.0 → 13.6), and the one policy that pays is a 20-task labeled pilot per benchmark (57.4 vs 53.5 for always using GPT-5.6-sol, at 36% lower cost).

## 核心贡献

- **配对因子实验协议**：固定 task instance 与其他轴，每次只动一个轴（model / skill / harness / budget），因此每个增益都是同实例配对差，而不是跨设置的平均数。
- **技能增益随 harness 变化的三类现象**：absorbed（被 harness 吸收）、rescued（被 harness 救回）、preserved（保持不变），并给出 96 个 skill–model–benchmark 组合的全矩阵统计（18 absorbed / 12 preserved / 4 rescued / 11 persistent harm / 45 无实质效应）。
- **失败类型 → 修复轴的映射与检验**：先冻结失败标签、再看结果；执行类失败对应更富 harness（+9.58 分，CI [+4.77, +13.93]），能力类失败对应更强模型（+64.54，CI [+58.68, +70.16]），而过程类失败并不能可靠映射到 skill（+3.77，CI [−5.66, +14.47]）。
- **"反馈不等于恢复"的分阶段诊断**：把恢复拆成暴露 → 模型响应 → 局部修好 → 最终答案正确四级，指出多数失败卡在中间或最后一级（BigCode 暴露率 70–76%，修复率 ≤2%）。
- **自演化 skill 的四条瓶颈**（打不过短人工 skill、学到数据集捷径、换模型即失效、无法补充缺失事实），并用三个额外实验（更强构造器、同构造器不同流程、被拒候选 vs 人工种子、SimpleQA 检索臂）分别验证。
- **可操作产物**：一份按"残余失败"提问的诊断清单、完整的 instance-level 结果账本、冻结 skill 工件与哈希、冻结失败标签，以及可复现每张表图的脚本。

## Key Contributions

- A **matched factorial protocol**: one axis changed at a time on identical task instances and repeats, so every reported gain is paired and attributable, with leave-one-cell-out interaction tests.
- A **taxonomy of skill–harness regimes** (absorbed / rescued / preserved / persistent harm / no material effect) applied to all 96 Default-budget skill × model × benchmark combinations, plus the format-versus-content rescoring that explains the largest apparent gains.
- A **failure-to-fix analysis**: 2,225 frozen root-cause labels (1,920 after excluding LiveMath) assigned before any matched outcome was inspected, validated by an independent judge plus an author check of 200 samples, then replayed under each intervention axis.
- A **stage-wise recovery decomposition** (exposure → response → local repair → final success) showing that feedback converts failures only when they leave a visible, actionable, locally correctable error signal.
- **Four empirical shortfalls of self-evolving skills**, each tested against an alternative explanation (weak constructor, wrong procedure, missing knowledge), plus a SimpleQA retrieval arm that reaches 72.0% where skills reach 6.3%.
- A **decision analysis**: per-task routers and signal-triggered escalation do not beat a fixed configuration, while a 20-task per-benchmark labeled pilot does, at lower cost.

## Methodology

**Design.** Five crossed factors: task instance, model, skill, harness, budget. Test pool: 1,872 instances (1,829 in the eight comparable benchmarks plus 43 appendix-only BigCodeBench-Hard) drawn from nine benchmarks chosen for *different dominant bottlenecks*: SimpleQA (parametric knowledge), SQuAD (answer contract), HotpotQA with provided context and with full-wiki retrieval (multi-hop integration), BigCodeBench-Hard (code), Amazon SOP and UCSB SOPBench (procedure following), SpreadsheetBench (stateful tool use), LiveMathematicianBench (multiple-choice reasoning). Each benchmark uses its native evaluator; cross-benchmark summaries are equal-weight macro averages. Splits are 70 train / 20 method-validation / 15 harness-validation / 300-ish locked test, seed 42, with `split_manifest.json` and `ids.json` released.

**Models.** Qwen3.5-9B (served locally, thinking disabled, temperature 0), Sonnet 4.6, Sonnet 5, GPT-5.6-sol.

**Skill axis.** Four conditions: NoSkill; Direct (one-shot generation from training items); SkillOpt (optimized from scored rollouts); Trace2Skill (distilled from successful and failed trajectories). In the main matrix **every skill is built once by Qwen3.5-9B and frozen**, then reused unchanged for all four models — a deliberate choice that turns the cross-model cells into a transfer test.

**Harness ladder (one mechanism per rung, no rung sees gold answers or evaluator outcomes).** H0 minimal (benchmark prompt + skill); H1 standardized answer/tool interface with legal-action guidance; H2 H1 + execution errors or observations fed back with up to three bounded retries; H3 H2 + one outcome-blind revision. Per-benchmark implementations are in Appendix A.1.3/Table 11.

**Budget axis.** Low/Medium/High ceilings on completion tokens, turns and wall-clock (Table 12), swept at H1 and H2 only; on single-turn QA the ceilings are non-binding by construction, which the authors state explicitly (Table 13).

**Statistics.** Cell means over three repeats; task-instance/UID cluster bootstrap CIs; paired sign-flip or stratified permutation tests; BH correction on the three root-aligned contrasts; leave-one-cell-out reconstruction to test additivity (pairwise-interaction model vs additive model); regime labels use a descriptive 5-point tolerance, which the authors flag as *not* certified against A/A noise.

**Failure labels.** Repeat-1 common-support cohort: 3,939 source failures (NoSkill + H1 + Medium), of which 2,225 are labeled (56.5%) across eight root causes using logged errors, evaluator records, deterministic answer rules, and (for LiveMath only) model judgments. LiveMath's 305 labels fail independent-judge replication and the whole benchmark is dropped from every failure-conditioned analysis.

**Additional experiments.** (a) rebuild both skill methods with GPT-5.6-sol on UCSB SOP and SimpleQA; (b) compare Direct vs SkillOpt under a fixed constructor; (c) score Trace2Skill's *rejected* candidates against their human-written seeds; (d) four SimpleQA knowledge-access arms at H1 (no skill, own-data facts, knowledge-boundary skill, ask-then-retrieve, always-retrieve); (e) offline replays of routers, signal cascades, and benchmark-level pilots.

## Results & Highlights

- **A skill's value is set by the harness, not by the skill.** On SQuAD with Qwen3.5-9B, Trace2Skill beats NoSkill by **+66.2 EM at H0**, +18.4 at H1, **+2.2 at H2** and −0.1 at H3 (H0→H2 interaction −64.0, 95% CI [−69.9, −58.2]). Rescoring the same saved trajectories by "does the response contain a gold answer" puts **NoSkill at H0 at 96.1** versus 10.7 native, i.e. essentially the entire headline gain is answer format that the H1 interface supplies for free.
- **The same harness can turn a loss into a gain.** Hotpot FullWiki with Direct goes **−22.8 at H0, −22.0 at H1, +1.7 at H2** (interaction +24.4, CI [+19.1, +29.8]), and **215 of the 221** failure-to-success transitions in that cell follow a returned malformed-action error. On Amazon SOP, SkillOpt moves from **−19.5 at H0 to +6.2 at H2** (+25.7, CI [+12.1, +39.8]).
- **...or leave it exactly as it was.** On UCSB SOP, SkillOpt holds **+13.5 / +15.2 / +13.3** across H0/H1/H2 (H2 interaction −0.2, CI [−4.8, +4.4]) because the failure it fixes — a payment executed while its precondition silently fails — raises no error for H2 to feed back.
- **Format dominates the two largest harness "gains".** Re-scored on answer content, the harness envelope on SQuAD falls from **44.34 to 2.12** points and on Hotpot Context from **48.18 to 0.00**, while Amazon SOP's barely moves (**48.03 → 46.33**), so only Amazon SOP's harness gain is substantive. Consistent with this, 16 of 512 Default cells sit at a native-score floor below 2.0, 12 of them at H0, and Amazon SOP + Direct on Qwen3.5-9B returns exactly **1.7 at H0, H1, H2 and H3** — one failure signature, not four graded outcomes.
- **Feedback repairs only signalled failures.** Among Qwen3.5-9B H1 failures coded from their own trajectories, H2 rescues **76.9% of signalled vs 1.3% of silent failures on SQuAD**, 63.5% vs 1.8% on Hotpot Context, 24.2% vs 1.5% on Hotpot FullWiki, and only 21.5% vs 17.4% on Spreadsheet (CI [+0.0, +8.1], touching zero). On UCSB SOP the difference reverses (−6.6, CI [−13.0, +3.3]).
- **Exposure ≠ recovery.** BigCode exposes an error in **70–76%** of executions but the model repairs at most **2%** of them, because a coarse pass/fail verdict does not point at a fix; Spreadsheet repairs roughly **two thirds** of the errors it responds to, yet only about **one fifth** of those runs end with a correct workbook. Pooled across models, H2 rescues **27.1%** (322/1,187) of Hotpot FullWiki failures that were visible, actionable and locally correctable, versus **1.3%** (2/149) on Spreadsheet.
- **Evolved skills break when moved.** The Qwen-built SkillOpt skill on Hotpot Context takes GPT-5.6-sol from **62.0 at H1 to 13.6**, and neither H2 nor H3 recovers it (**12.2, 12.2**), because the skill makes the model fill the answer field with a fact-extraction worksheet; a correct answer is still present in **74.1%** of responses with the skill versus 76.8% without. So the model did not lose knowledge — the intervention destroyed the interface contract.
- **Shortcuts are learnable and measurable.** On LiveMath the evolved skill encodes "pick the recurring meta-option": for Qwen3.5-9B it lifts accuracy from **11.2% to 71.5%** on the 53 items carrying that option and *lowers* it from **52.7% to 43.7%** on the other 71, netting ≈0 — the same pattern that makes the benchmark-level average (Trace2Skill 53.2 vs NoSkill 34.1 at H0) look like a 19-point win.
- **No skill can supply missing facts; retrieval can.** On SimpleQA at H1, NoSkill scores **5.0%**, the agent's own-data facts skill **6.3%**, a knowledge-boundary skill **2.0%**, ask-then-retrieve **60.0%**, and always-retrieve **72.0%** — a +67-point swing from outside information against +1.3 from self-evolution. The asking skill alone "removes most wrong guesses" (wrong answers 263 → 45) without raising accuracy.
- **A short human-written skill is a hard baseline.** Trace2Skill's evolved candidate fails to beat its 17–85-word human-written seed on **five of seven** benchmarks, and the seed also beats SkillOpt by **10–15 points** on three QA benchmarks. Where the validation gate kept the seed, it adds a median **4%** tokens and helps in 28 of 80 comparisons; the one evolved skill that passed the gate (LiveMath, **2,603 words**) costs a median **+195%** tokens.
- **Interventions interact, they do not add.** Allowing every pair of axes to interact predicts held-out cells better than an additive model on **7 of 8** benchmarks, mean leave-one-cell-out **R² 0.729 → 0.812** (paired sign-flip p = 0.0078).
- **Per-task routing fails; per-benchmark pilots work.** A router choosing from task text or predicted failure type reaches **39.42% / 40.10%** against **45.29%** for the fixed Trace2Skill+H2 configuration (oracle 49.24%). Escalating only signalled H2 failures gives **42.1% vs 41.6%** for always-H2, cuts regressions from **2.20 to 0.87 per 100 instances**, but costs **68% more tokens** because H1 must run first — 89% of H2 failures are silent, so the signal is too sparse. A **20-task labeled pilot** per benchmark reaches **57.4 at $5.31 per 1,000 tasks** versus **53.5 at $8.32** for always using GPT-5.6-sol: +3.9 points and 36% cheaper, because the stronger model is genuinely worse on some benchmark–skill cells (e.g. SQuAD).
- **Cost is invisible in a single accuracy number.** Direct and SkillOpt roughly double token use (median **+106%** and **+94%**) while staying within ±5 points in 69 and 61 of 96 comparisons, and when they do move the score they hurt about as often as they help (15 better/12 worse; 14 better/21 worse). The H0→H1 and H1→H2 steps are nearly free (+2%, +0%) and H1→H2 never loses 5+ points, whereas H3's outcome-blind revision doubles tokens (**+103%**) and helps in only 7 of 96.

## Authors & Credibility

Seven authors, six at USC (Zihan Jin, Jiate Li, Dongze Ye, Shawn Li, Yue Zhao, Defu Cao) and one at Amazon (Gaoyuan Du, with an explicit footnote that the work is unrelated to his Amazon position). Yue Zhao's group at USC has a visible track record on agent reliability and evaluation infrastructure, and the reference list leans on that line of work (FORTIS on skill over-privilege, the "autonomy tax" paper on defense training breaking agents, PersonaCUABench, MemoHarness, SkillCenter). The paper is an arXiv v1 dated 22 Nov 2026 with no venue listed, so it has not been peer reviewed. Credibility signals are strong on the engineering side: code, split identifiers, frozen skill artifacts with SHA-256 hashes, the instance-level outcome ledger, and the frozen failure labels are all released, and the paper reports null and negative results about its own proposed policies (routers, escalation, most failures out of reach). Statistical hygiene is better than typical for this genre — paired designs, cluster bootstrap, BH correction, and an explicit refusal to call 5-point regime labels "effects".

## Critical Assessment

The paper's central move — rescoring trajectories by answer content instead of the native scorer — is the most valuable thing in it, and it is also the paper's own strongest self-criticism: two of the three biggest harness envelopes (SQuAD 44.34 → 2.12, Hotpot Context 48.18 → 0.00) are bought almost entirely by giving the model a parseable answer format. That undercuts the framing that "execution support repairs execution failures", and the authors say so, but the abstract's "missing knowledge to a stronger model, execution errors to a richer harness" reads much cleaner than the evidence, which is that on three of eight benchmarks the harness axis is confounded with the scorer's formatting assumption. **Specific gaps I would press on:**

- **`H2` is a bundle.** Error feedback plus up to three bounded retries are never separated (the limits section admits this), so the "feedback is not recovery" claim actually measures "feedback+retry". A cell with retries but no feedback, or feedback with a single retry, would be cheap to run and would sharpen the main mechanism claim considerably.
- **The rescue regime is a one-model phenomenon.** Regimes, signal coding and pre-recovery prediction are all Qwen3.5-9B; the authors state that rescue "appears only for it" because stronger models show no large skill-induced penalty to remove. That is a real scope limit, not a footnote: the "harness rescues a skill's failure" headline rests on penalties of −19.5 and −22.8 in a 9B model at H0/H1, two of which sit on floor cells.
- **Failure labels cover 56.5% of source failures and are validated at the axis level, not the class level.** The three root-aligned contrasts pool down to n = 53 (procedural) and n = 267 (capability), and the procedural row is not significant (BH q = .456) while the paper still uses it to say "procedural → try a skill, but test it". Fine as advice, weak as a measured mapping. Hotpot Context contributes exactly **one** labeled failure and Hotpot FullWiki **ten**, so the two benchmarks that carry the biggest skill penalties are essentially unlabeled — a genuine hole given that the rescued case lives on FullWiki.
- **LiveMath is dropped from every failure-conditioned analysis** because the independent judge does not reproduce its labels, yet LiveMath is precisely where the shortcut finding is sharpest. The shortcut result survives (it needs no labels), but the paper cannot say *which failure* the shortcut repairs — an asymmetry with its own thesis.
- **Benchmark saturation and ceiling effects are under-discussed.** Amazon SOP ends at 100.0 for Sonnet 4.6 NoSkill+H2 and GPT-5.6-sol NoSkill+H2, so its +48 harness envelope and its +81 budget envelope are partly a floor-to-ceiling artifact (Table 20 flags the floors, not the ceilings). UCSB SOP's "preserved" claim rests on 175 test items from a rebalanced 830-item pool; the "silent precondition failure" story is compelling but n = 25 signalled failures in Table 45.
- **Proprietary snapshots are unreproducible.** Sonnet 4.6, Sonnet 5 and GPT-5.6-sol are API models with no pinned weights; only Qwen3.5-9B is local. The whole cross-model collapse argument therefore depends on snapshots that a reader cannot re-run, even though the trajectory ledger lets them re-analyze.
- **The skill set is narrow.** Two self-evolving procedures (SkillOpt, Trace2Skill) both produce prompt-level text artifacts, and the evolved LiveMath skill is 2,603 words. "Self-evolving skills stall" is well supported for *prompt-distillation* methods; it is not evidence about skills that carry executable tools, retrieval policies, or code, which is a large part of what "skill" means in deployed agents.
- **The 59.7% "out of reach" figure is bounded by the tested action set** (one action per axis in the uniform expectation, temperature 0, budgets swept only at H1/H2). The authors flag it; readers should not read it as a capability ceiling.
- **Minor but real:** the AI-use statement names "GPT-6-sol" as the independent judge while the rest of the paper uses "GPT-5.6-sol", the abstract says "nearly 0.9 million trajectories" where Table 17 says 898,560 nominal *executions* (some cells unavailable), and three repeats at temperature 0 cannot estimate execution noise — which the paper itself concedes when it calls the regime counts "thresholded descriptions of cell means, not effects certified against A/A noise."

None of these are fatal, and several are candidly disclosed. But a reader should discount the "interventions interact rather than add" claim to "interact on 7 of 8 benchmarks under a two-way model", and treat the diagnostic checklist as expert-informed design guidance supported by a strong descriptive matrix rather than as a validated controller.

## Strengths

- **The design is the contribution.** Changing exactly one axis on identical instances with matched repeats is the right way to attribute a gain, and almost nobody in the agent-intervention literature does it at this scale (898,560 executions, 1,872 instances, 9 benchmarks).
- **The format-versus-content rescoring** is a reusable methodological weapon; it demolishes a class of published harness/skill gains in two lines of analysis.
- **Genuine negative results, reported as such**: routers lose to a fixed configuration, escalation costs 68% more for +0.5 points, evolved skills rarely beat a 20-word seed, 59.7% of failures are beyond every tested action.
- **The stage-wise recovery decomposition** (exposure / response / local repair / final success) is a better vocabulary than "self-correction works or not", and the BigCode (exposed but unactionable) versus Spreadsheet (locally fixed but globally wrong) contrast is a clean, memorable pair.
- **Shortcut detection with a counterfactual split**: 11.2 → 71.5 on the 53 meta-option items and 52.7 → 43.7 on the other 71 is exactly the analysis a benchmark maintainer should run on any evolved skill.
- **Artifacts**: hashed frozen skills, split manifests, an instance-level ledger that lets a new intervention be compared pair-by-pair without re-running the matrix, and scripts that regenerate every table.
- **Honest limits section** that names the skill-construction confound, the H2 bundling, the label coverage, and the single-model scope.

## Limitations

- **H2 bundles feedback with three retries**; the paper cannot separate "the error was shown" from "the model got more attempts", which matters because retries alone can fix format failures.
- **Regime, signal and prediction analyses are Qwen3.5-9B only**, and rescue does not appear for the three stronger models, so the rescue mechanism is demonstrated on one 9B model.
- **Skill construction is single-source**: main-matrix skills are built by Qwen3.5-9B and frozen, so cross-model cells test transfer, not per-model construction; the stronger constructor (GPT-5.6-sol) is tested on two benchmarks only and even it does not rescue SkillOpt (−6.05 on UCSB SOP).
- **Failure labels**: 56.5% coverage, axis-level validation, one labeled failure on Hotpot Context and ten on FullWiki, LiveMath excluded entirely.
- **Floor and ceiling cells**: 16 sub-2.0 cells concentrate on the three benchmarks with the largest harness envelopes; Amazon SOP saturates at 100.0 for two model/skill combinations, so its budget (+81.13) and harness (+48.03) envelopes are partly artifacts.
- **No A/A noise calibration** and only three repeats at temperature 0, so the 5-point regime thresholds are descriptive rather than inferential.
- **Narrow intervention space**: prompt-text skills, a fixed four-rung harness ladder, budgets swept only at H1/H2, one action per axis in the "out of reach" analysis.
- **Unpinned API models** (Sonnet 4.6/5, GPT-5.6-sol) make the cross-model results hard to reproduce; only the ledger re-analysis is reproducible.
- **No cost model for local Qwen** (no per-token price, no comparable latency), so the pilot's 36% saving is computed only for the API-model arms.
- **Benchmarks are convenience-selected for bottleneck diversity**, not sampled; equal-weight macro averaging over 8 benchmarks with 50–300 test items each gives small benchmarks the same influence as larger ones.

## Relevance

这篇直接命中"自演化 agent"这一条主线：它用近 90 万条配对轨迹给出自演化 skill 的四条硬性失败模式（打不过几十词人工 skill、学数据集捷径、换模型即崩、补不了缺失事实），对判断任何 self-evolving / self-improving agent 论文的实际增量都极有用。同时对"Agent & Pipeline 静默失败"也高度相关——Hotpot Context 上那个 62.0 → 13.6 的崩塌不是模型变笨（74.1% 的回复里仍含正确答案），而是 skill 与 harness 强制答案接口交互后把答案字段写成了抽取草稿，这正是软件层静默改写模型输出的典型样本。

## Questions for Further Exploration

1. Can H2 be factorized into {feedback, retry budget} × {1, 3} retries? The paper's central mechanism claim ("feedback is not recovery") rests on a bundle that would take four extra cells per benchmark to unpack.
2. Why does rescue appear only for Qwen3.5-9B? Is it a capability threshold (a stronger model never produces a repairable-but-wrong intermediate state), or an artifact of the floor cells these benchmarks exhibit at H0/H1?
3. Does the collapse generalize? The intro shows one benchmark (Hotpot Context) and one skill transfer; a 4-model × 9-benchmark map of "skill built on A, run on B" degradation curves would turn an anecdote into a transfer law.
4. What would a non-textual skill do? If skills carried executable checks (a validator, a retrieval call, a precondition assertion), would the "cannot supply missing facts" and "learns shortcuts" failures persist, or does the bottleneck live specifically in prompt distillation?
5. Can the shortcut audit (split items by whether the encoded rule applies) be made a standard gate before any evolved skill is accepted, and does it catch skills that pass a held-out validation split?
6. The benchmark-level pilot uses 20 labeled tasks; how sensitive is the 57.4-vs-53.5 result to the switching threshold δ and to pilot ordering, and does it still pay when the candidate set is larger than two configurations?
