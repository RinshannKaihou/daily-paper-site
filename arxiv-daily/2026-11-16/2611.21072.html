How it is built two cheap ideas, one big training stack

The scientific branch is deliberately minimal — everything expensive stays frozen. The agent branch is where the data engineering lives.

Frozen 320B MoE sparse + linear attention; one projector per modality, disambiguated by instruction text

Frozen: encoderslanguage backbone  ·  Trained: projectors only

  1. Sci-Perception. Each modality yields a token matrix (atoms, residues, segments, numerical windows); the projector lifts it into the backbone's embedding space, with a residual step so states of the same molecule or protein can exchange context.
  2. GRPO on the interface. Encoders and backbone stay frozen; rewards are verifiable scientific outcomes — classification correctness, site/set overlap, numerical tolerance, chemical equivalence. Auxiliary questions about the input itself (count atoms, compare measurements) force the interface to expose evidence rather than paraphrase.
  3. ToolSpace. Treat tools as atoms, recover a typed composition graph from real MCP / web traces (data, state and retry edges), materialise only the environments needed for persistent state, then generate tasks by state-aware random walks plus reverse instruction / verifier synthesis. Teacher rollouts are kept only if they replay-verify.
  4. Environment recipes. Search from cyclic knowledge graphs, agentic coding from SWE-smith / OpenSWE / mined commits, ML coding from versioned data–code pairs, security from vulnerable-vs-patched differentials, plus workspace deliverables and visual CUA curricula.

Unresolved provenance. The backbone sentence cites the GLM-5.3-Flash model card — which is also one of the five baselines. The report never states whether Sage is initialised from it. No active-parameter count, expert count, layer count or token budget is disclosed either.

Reward-hacking guardrails that are worth copying. State/artifact checking instead of self-reported completion, deliberately wrong negative controls, Git-history scrubbing, permission-separated solver / target / evaluator domains, and behavioural review of recorded tool access — the authors found a real leakage channel in their own harness this way.

Evidence for the science claim is five application demos (CT slice recovery, Blender / CAD builds, Fiji / EEGLAB / QGIS runs, an HTML explainer) — no baselines, no success criteria, no repeated trials.

  • No ablation of the interface: not w/o projector, not w/o identity embedding, not w/o GRPO. Its value versus serialising a molecule as SMILES text is unmeasured.
  • A reader cannot tell whether Sci-Perception beats plain captioning — the paper's defining claim has no number attached.
  • The 48-pair trajectory analysis is qualitative only: no win/loss counts, no significance test, pairs chosen by the authors.

Strengths vs limitations read side by side

What holds up

  • Verifiable environments are the reusable core: state- and artifact-based checks, differential vulnerable-vs-patched validation, negative controls, and scoring scripts kept out of the agent's context.
  • Honest reward-hacking section with a concrete leakage channel found in the authors' own harness and a behavioural mitigation.
  • Clean, swappable scientific interface — one projector per modality, task disambiguated by instruction — reproducible on a smaller backbone.
  • GRPO on a frozen backbone is a cheap way to add a modality without catastrophic forgetting; evidence-probing questions are a good diagnostic.
  • Appendix B documents harnesses, timeouts, step caps and judge identity per benchmark, and flags the non-comparable reference columns.

What does not

  • No quantitative scientific result and no Sci-Perception ablation, so the paper's headline identity is unsupported by measurement.
  • Harness and context-budget asymmetry (Claude Code vs OpenHands, 512K context on some rows) breaks the like-for-like ranking.
  • Non-standard MLE-bench metric, mixed-provenance PostTrainBench and a 120-task Harvey subsample make both headline margins fragile.
  • Architectural opacity: 320B total parameters, but no active-parameter count, expert count, data mixture or token budget.
  • Training volume is given as inventory (4,936 Kaggle sources, 2,960 papers) not as accepted tasks; no compute budget, no training curves, no contamination audit beyond Git-history removal.

What would settle it questions for further exploration

01

What happens if the projectors are removed and the same inputs are serialised as text (SMILES, FASTA, peak lists)? Without that ablation the interface's value is unmeasured.

02

Do the agentic margins survive a fully harness-matched re-run — same scaffold, same 512K allowance, same judge for every model?

03

Is Sage initialised from GLM-5.3-Flash? If so, how much of each win is post-training rather than base capacity?

04

How many tasks survive ToolSpace's replay verification and judge filtering, and what is the acceptance rate per environment type?

05

Does projector-only GRPO change calibration on out-of-distribution spectra — does outcome-based reward make the model overconfident?

06

Can “verification coverage” (fraction of requirements explicitly re-checked before submission) be turned into a metric that predicts success better than pass rate?
