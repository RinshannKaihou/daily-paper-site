One 16-byte PCIe store lets a GPU kernel call any host function — and reverse offload then beats GPUDirect Async.

一句话：把通信请求交还给 CPU 代理线程，不但不慢，还能更快——而且可编程。

Exactly the raw wave-wide-store floor (1.92 µs) — the queue adds nothing. p99 1.98 µs.
Why this matters

It decouples GPU producer count from NIC endpoint count — GDA's real scaling wall — and turns a new collective into a plain host function.

Critical edge

NVSHMEM and rocSHMEM were re-implemented for AMD, and rocSHMEM's copy is anomalously ~5× slow — exactly the kind of number that flatters the proposed design.

→ Critical Assessment, baseline fairness

Method — three verbs, one queue

register_callback(fn) → id invoke(cb_id, args) progress(ep)

A KIWI context holds a callback registry and a set of endpoints. Inside a kernel, a wave grabs a handle and calls invoke; KIWI serializes the arguments into a descriptor and publishes it. The call is asynchronous and non-blocking — if the endpoint is full it returns false and the kernel retries. KIWI spawns no threads: the application's own proxy threads call progress, pop descriptors, and run ordinary host callbacks that drive LCI / ibverbs / libfabric.

04 · CPU
Proxy thread
Polls signal in L1, runs callback, posts to NIC

Why it is free: the slot becomes visible atomically in host memory, so a valid signal implies the descriptor arrived — no flag write, no fence, no atomic. The fullness check is register arithmetic; the consumer index is re-read over PCIe only when the ring may be full. Device-side code is not tied to HIP: FlyDSL and Triton kernels publish the same descriptors and hit the same C++ callbacks.

Above it: KIWI-P2P (<1,000 lines of C++) pairs KIWI with LCI for SHMEM-style puts. KIWI-EP rebuilds MoE dispatch/combine as three workload-defined ops — multicast put, non-blocking count all-to-all, non-blocking barrier — plus HIP-graph-safe dynamic endpoint counts and skewed round-robin proxy assignment (digit-sum of the endpoint index in base P, mod P).

Reverse offload's residual cost is LCI's per-put overhead, not the handoff: throughput is 2.88 vs 2.97 Mops/s, while flag + raw ibverbs reaches 3.40 Mops/s. Programmability is nearly free — real callbacks leave the 1.92 µs / 0.12 µs path unchanged; only 256-wave throughput falls to 62% of the bare queue. FlyDSL and Triton kernels land within 2% of HIP C++ round trip.

The ladder decomposes each step: proxy-MPSC alone is 27% under GDA at one token; per-wave SPSC queues add 14%; callbacks that fuse payload + signal and coalesce multicasts add 21%; skewed round-robin adds 19% at 8 tokens and 9% at 64.

The honest part: plain round-robin proxy variants are 28–29% worse than GDA at 64 tokens. The endpoint assignment scheme, not reverse offload itself, is what rescues large batches — and at 64 tokens the paper's own data says GDA is roughly fine.

Strengths

  • A three-verb abstraction that composes with any host transport instead of forking a vendor library's internals.
  • Reaches the raw-store floor — the cleanest possible evidence the mechanism adds no overhead.
  • Negative results published: the 1.77× → 1.08× decay and the round-robin failure at 64 tokens.
  • Engineering details others omit: HIP-graph-safe dynamic endpoint ranges, epoch-tagged 64-bit counts, digit-sum endpoint skew.
  • Real hardware end to end: vLLM + GLM-5.3 FP8 with accuracy checks, public code, Triton/FlyDSL parity.

Limitations

  • One vendor, one topology: MI300X + ConnectX-7 RoCE, one NIC per GPU, 1:1 PCIe switch; no InfiniBand, multi-rail, or congestion.
  • CPU cores treated as free: four proxy cores per GPU (32 of 112 per node); no sweep over core count.
  • High batch is only 1.08× — hierarchical token routing is left to future work.
  • Only TPOT reported end to end: no throughput, cost-per-token, or tail latency under load.
  • Two baselines are re-implementations and one is anomalously slow, so the queue ranking is not definitive. Barrier is borrowed, not a new algorithm.

Questions for further exploration

  1. How much of the 29% TPOT gain survives with one or two proxy cores per GPU instead of four — is the win reverse offload, or otherwise-idle CPU cores?
  2. What do decode throughput (tokens/s/GPU) and p99 TPOT look like at high concurrency, where the edge over GDA falls to 1.08×?
  3. Does the queue comparison hold on InfiniBand, and does the no-atomics, register-resident design still reach the store floor there?
  4. If KIWI-EP adopted MORI-style hierarchical routing, where does the crossover move on 8 nodes at 64–256 tokens/GPU?
  5. Can the callback model absorb copy engines, storage I/O, or CPU-side sparse work without breaking the single-producer assumption?
  6. How sensitive is skewed round-robin to non-power-of-two wave and proxy counts — is there a general assignment rule with a bound?
