> **一句话总结：** 把自主 AI 研究的第一等状态从「代码库状态」换成显式的「问题状态（Problem State）」——记录是什么瓶颈限制了性能、有哪些候选解法、以及每条解法的置信度——用单变量控制实验去证伪/确认这些信念，再据此设计实现；在完整 75 任务 MLE-Bench 上 24 小时拿到 70.7% 奖牌率（追平此前最好），48 小时 76.0%（新高），但金牌率 25.3% 仍低于 MARS+ 的 33.8%。

> **TL;DR:** Pro2 Agent replaces the usual "codebase + score history" research state with an explicit Problem State — a nested structure of performance-limiting problems, candidate solutions per problem, and belief scores backed by profiling evidence and literature — and uses single-variable, Git-branched hypothesis tests to update those beliefs before committing code. On the complete 75-task MLE-Bench it reaches 70.7% Any-Medal at 24 h (matching AIBuildAI-2's 70.7% with Claude Opus 4.7) and 76.0% at 48 h, and on the 22-task MLE-Bench Lite its very first complete solution already medals on 57.6% of tasks versus 28.8% for MARS. On PostTrainBench it scores 30.69 vs 28.56 for Opus 4.7 on Claude Code but well behind Fable 5 (41.79) and the official instruct models (51.14).

## 核心贡献

- **提出 Problem State 作为自主 AI 研究的第一等状态**：形式化为嵌套结构 $S_t = \{P_i, \mathcal{E}^p_i, \{C_{i,j}, b_{i,j}, \mathcal{E}^c_{i,j}\}\}$，即「性能瓶颈问题 → 其诊断证据 → 每问题的候选解法 → 每解法的置信度 $b_{i,j}\in[0,1]$ 与证据集」，并与可执行的 Git 代码快照一一映射。
- **三阶段框架**：(1) 初始化——沙箱内动态 profile 出显存/IO/延迟瓶颈，把瓶颈映射成文献检索 query，构造模块化基线 $M_0$；(2) 科学探索——在假设树 $\mathcal{T}_{sci}$ 上做资源受限的 best-first 搜索，用频率惩罚分 $Pri(H_t)=b_{k,m}/(N(P_k)+1)$ 排序，严格执行单变量隔离，成功则 $b \leftarrow \min(1, b+\Delta b_{pos})$，失败则硬回滚并 $b \leftarrow \max(0, b-\Delta b_{neg})$；(3) 工程优化——在 UCT 驱动的 MCTS 上做超参/集成搜索，奖励函数 $R(N_k)=\Delta h(N_k)-\gamma\ln T_{exec}(N_k)$ 惩罚算力浪费，并用 diff 审计防火墙禁止改动 model/algo/data。
- **三角色多智能体环**：PI Agent（Gemini 3.1 Pro，每 10 步检查一次轨迹）、Implementation Agent（Gemini 3.5 Flash，ReAct 循环）、Reviewer Agent（审计单变量合规与防作弊），配套 Experience Bank 记录错误签名/根因/修复以供跨迭代检索。
- **可审计的研究过程产物**：每次运行产出研究笔记，把瓶颈标注为 Resolved / Resource-Limited / Unresolved 三态分类，使失败也可被人类复用。
- **完整基准上的强结果**：完整 75 任务 MLE-Bench 24h 70.7%、48h 76.0%（100% 有效提交、84.0% 超人类中位数、57 枚奖牌），PostTrainBench 加权平均 30.69。

## Key Contributions

- **A new primary state.** Reframes automated model development from $m^*=\arg\max_{m\in\mathcal{M}} h(m)$ (search over code) to maintaining and revising an explicit, evidence-grounded Problem State $S_t$ that is physically one-to-one with a Git snapshot $M_t$, so that refuted hypotheses can be deterministically rolled back.
- **Problem Probing as the initialization step.** Rather than starting from a static "write a baseline" prompt, the agent runs dynamic runtime profiling probes (latency, memory footprint, multimodal visual diagnosis), extrapolates to full-dataset scale against compute bounds to surface OOM / I/O-starvation risks, then does a *bottleneck-conditioned* literature review that seeds candidate solutions with initial belief scores — so the baseline $M_0$ is designed around diagnosed constraints, not around the LLM's default preferences.
- **Controlled attribution instead of score-chasing.** Every hypothesis is a triple $H_t=(P_k, C_{k,m}, \Delta m_t)$ with a declared target improvement $\delta_{target}$; the Reviewer Agent enforces that the code diff introduces exactly one variable, and the same Reviewer blocks architecture/algorithm/data edits during Phase 3 engineering tuning via the invariance constraint $\mathcal{C}_{Diff}(M_{root},M_{child})\cap\{\text{model},\text{algo},\text{data}\}=\emptyset$.
- **Continual belief revision matters, not just better planning.** An ablation separates constructing, grounding, and updating the Problem State, showing that a *static* grounded state captures most of the initialization gain but loses the tail of the trajectory.
- **Two-benchmark evaluation** spanning competition-style ML engineering (MLE-Bench) and LLM post-training (PostTrainBench), plus mechanism-level analyses: initial-solution quality, Medal@k / Node AUC convergence efficiency, expert-technique recall, and four qualitative case studies including two honest failures.

## Methodology

**Phase 1 — Problem State Initialization.** The agent runs lightweight diagnostic scripts on raw tensors inside the sandbox to measure real processing latencies, memory footprints, and domain-specific structural signals (e.g. visual inspection for multimodal tasks). These empirical numbers are extrapolated mathematically to full dataset scale against strict compute bounds, yielding a set of bottlenecks $\{P_i\}_{i=1}^{K}$ (OOM risk, I/O starvation, resolution loss, class imbalance...). Each bottleneck is mapped to targeted web/academic search queries; retrieved architectures, augmentations, and losses are structured into candidate solutions $C_{i,j}$ with literature references and initial beliefs $b_{i,j}$, completing $S_0$. The baseline $M_0$ is then built under those constraints, subjected to a mini-batch sanity gate (memory, GPU efficiency, loss stability) before being committed as the reference anchor. Validation is deliberately decoupled from the sandbox: grading happens via an HTTP service with isolated ground-truth labels, preventing self-grading and target leakage.

**Phase 2 — Scientific Exploration.** A resource-bounded best-first search over a hypothesis tree. At each step the agent picks the highest-priority untested hypothesis using the frequency-penalized score $Pri(H_t)=b_{k,m}/(N(P_k)+1)$, which explicitly discourages retrying bottlenecks that have already failed repeatedly. A branch `hypothesis/H_t` is forked from the current best node $M_{best}$ in Git, the minimal mutation $\Delta m_t$ is applied, and the Reviewer verifies single-variable isolation (confounded updates are rejected unless structurally necessary, e.g. batch size or LR when swapping backbones). Execution runs under resource watchdogs and a blind grading interface. On $\Delta h \ge \delta_{target}$ the branch is retained and $M_{best}$ advances; otherwise (or on crash) a hard VCS rollback purges the branch. Beyond per-solution belief updates, the framework distills post-hoc insights (telemetry, loss curves) into a contextual summary that propagates through the *unexecuted* queue, re-scoring pending hypotheses in light of new attribution evidence.

**Phase 3 — Engineering Optimization.** Rooted at the best scientific snapshot, a symmetric Git-branch tree is searched with MCTS/UCT and the cost-aware reward $R(N_k)=\Delta h(N_k)-\gamma\ln T_{exec}(N_k)$, which penalizes configurations that buy marginal accuracy with lots of wall-clock. The audit firewall restricts diffs to engineering variables (LR schedules, batch size, weight decay, ensemble weights). The best trajectory merges back to the primary branch.

**Tripartite loop and budgeting.** PI Agent (Gemini 3.1 Pro) sets goals, budgets, and inspects the trajectory every 10 steps; Implementation Agent (Gemini 3.5 Flash) runs a ReAct loop with file and diagnostic tools; Reviewer Agent (also Gemini 3.5 Flash) gates every launch. Budget is dynamically partitioned across preprocessing / training / blind evaluation, with a monitoring sentinel that halts on NaN/∞ loss divergence, kills stalled I/O beyond preprocessing caps, and grants soft-margin extensions to nearly-finished runs. An Experience Bank stores (error signature → root cause → verified fix) tuples, queried before each mutation and written after each novel fault.

**Evaluation protocol.** MLE-Bench: all 75 Kaggle competitions, one A100 per task, 24 h and 48 h wall-clock, one run per budget; priors are the official leaderboard, excluding submissions that used test-set feedback. MLE-Bench Lite: official 22-task split, 24 h, three independent runs, plus a normalized bronze gap $G_{bronze}(s_t)=(b_t-s_t)/(|b_t-m_t|+\epsilon)$ (negative = medal-level) and Node AUC $\text{NodeAUC}_t=\frac{1}{T}\sum_k \frac{s^*_{t,k}-b_t}{|b_t-m_t|+\epsilon}$. PostTrainBench: 28 model×benchmark configurations, three runs each, 24 h on one A100.

## Results & Highlights

- **Complete 75-task MLE-Bench, Any-Medal rate:** Pro2 Agent reaches **70.7%** at 24 h — a tie with AIBuildAI-2 (70.7%, Claude Opus 4.7, A100 24 h), and above MLEvolve 65.3%, ScienceFlow 70.2%, Iris 64.9%, Famou-Agent 2.0 64.4%, AIBuildAI 63.1%, MARS+ 62.7% and MARS 56.0%. At 48 h it reaches **76.0%**, the highest reported on the complete benchmark (+5.3 pts over AIBuildAI-2, +13.3 over MARS+).
- **Medal mix reveals where the gain sits:** at 48 h Pro2 Agent earns 57 medals (22 bronze / 16 silver / 19 gold). Its combined Bronze+Silver rate is **50.7%** versus **28.8%** for MARS+, even though MARS+ has a *higher* Gold rate (33.8% vs 25.3%). Above-Median rate is **84.0%** vs 74.2% (MARS+) and 76.0% (MLEvolve). So the improvement is breadth of competitive solutions, not more top-ranked wins — the paper states this openly.
- **MLE-Bench Lite first complete solution (Table 3, 3 runs, mean±SE):** Any-Medal **57.6±1.5%** vs **28.8±4.0%** for MARS and 12.1±3.0% for a Direct Coding Loop; Above-Median **81.8±2.6%** vs 50.0±2.6% (MARS) and 25.8±1.5% (Direct Loop); normalized bronze gap flips sign from **0.96±0.20** (MARS, below bronze) to **−0.57±0.05** (inside the medal region). Crucially the initialization is *faster*, not longer: 11.2±4.4 min vs MARS's 14.8±2.6 min.
- **Iteration efficiency within each method's own trajectory:** Medal@3 **63.6±2.6%** vs 34.8±3.0% (MARS); Medal@5 **66.7±1.5%** vs 39.4±5.5%; Node AUC **+0.58±0.17** vs **−0.39±0.09**. The sign flip means MARS's intermediate nodes sit *below* the bronze threshold on average while Pro2 Agent's stay above.
- **Problem State ablation (Table 4, MLE-Bench Lite, 24 h):** Codebase State 10.6 → 56.1 final medal (Node AUC 0.06); ungrounded Problem State 47.0 → 77.3 (0.27); static grounded Problem State 56.1 → 83.3 (0.45); full Pro2 Agent 57.6 → **89.4** (0.66). Static vs full initial solution is nearly identical (56.1 vs 57.6) but the final differs by **6.1 pts** — i.e. continual revision is worth ~1.3 extra medaled tasks per run, not just a better start.
- **PostTrainBench (28 configs, weighted average):** Pro2 Agent **30.69±3.1** vs **28.56±1.7** for Opus 4.7 on Claude Code, 27.23±0.6 for GPT 5.5 (Codex), 21.99±1.8 for Gemini 3.1 Pro (OpenCode) — but *behind* Fable 5 (Claude Code) **41.79±1.7** and far behind official instruct models at **51.14**. Per-benchmark: ArenaHard 28.59 vs 19.59, HumanEval 50.63 vs 42.07, GSM8K 64.47 vs 60.72; weaker on AIME 2025 (5.75±4.4 — weakest benchmark overall) and GPQA (26.45).
- **Case-study specifics:** on `bms-molecular-translation` the two-stage fix moved validation Levenshtein from **>15.0 → 4.61** (crop + 384² patch tokenization) then **→ 1.7257** (valency-constrained beam search with RDKit), scoring **1.8860** on the hidden test and crossing the bronze threshold where no inspected AIRA/MARS/MARS+ run medaled. On `gemma3-4b-gsm8k`, CoT-SFT lifted accuracy **0.0% → 52.50%** and GRPO with SymPy-equivalence rewards pushed it to **56.50%**. On `rsna-breast-cancer-detection`, high-res + focal loss improved pF1 **0.2577 → 0.3514**, but scaling to `convnextv2_tiny` collapsed validation pF1 to **0.0441** and hit the 4 h per-hypothesis budget.

## Authors & Credibility

Yixiong Chen (Johns Hopkins, work done during a Google internship) with Liqian Peng, Tian Tan, Ziqian Lin, Blake Jianhang Chen, Chao Zhao, Yaojie Liu and Alec Go at Google, plus Alan Yuille (JHU). The group is publishing squarely inside the current autonomous-AI-research agent race, and the paper is positioned as a Google-internal response to MARS (an internal Google/DeepMind-adjacent system by Chen et al. 2026) and to AIBuildAI-2. Credibility signals: the paper is unusually careful about *whose* numbers it is quoting — it explicitly flags that published rows use different backbones, different hardware and different budgets, and it runs its own matched-backbone controlled variants (Direct Coding Loop, Search-Augmented) with identical models, tools, environments, data splits and budgets. It also states that implementation and review run on the *lighter* Gemini 3.5 Flash while the PI is Gemini 3.1 Pro, which is a deliberately un-flattering configuration to advertise if you're chasing a leaderboard. Counterweight: it is a lab-internal system report built on unreleased proprietary models (Gemini 3.1 Pro / 3.5 Flash), no code or trajectory release is promised, and several baselines are cited from a leaderboard rather than re-run.

## Critical Assessment

**Novelty.** The core move — an explicit belief state over *problems* rather than over *solutions* — is a real reframing, and the nested formalization plus the one-to-one Git mapping is a clean engineering contract. But it is not as fresh as the paper's framing implies: §2 itself concedes that Arbor's Hypothesis Tree Refinement, the Hypothesis Evolution Protocol (belief probabilities over an auditable hypothesis registry, with proposed/supported/refuted/dormant transitions) and MLE-STAR's ablation-guided refinement already externalize hypotheses with evidence and confidence. The genuine delta is *Problem Probing first* — constructing the bottleneck taxonomy from runtime profiling plus bottleneck-conditioned literature search *before* any solution is attempted — and the insistence on single-variable isolation as an enforceable code-review constraint. That is a narrower contribution than "a new primary state of autonomous AI research," though it is the more defensible one.

**Rigor — where the comparisons are and are not apples-to-apples.** The headline MLE-Bench table is a leaderboard table: Pro2 Agent's 70.7% at 24 h ties AIBuildAI-2's 70.7%, and the "highest medal rate" claim only holds at 48 h. The paper is honest about this, but it also reports **one run per budget** on the complete 75-task benchmark with no error bars, while [Table 3] Lite numbers carry ±SE over three runs. Two consecutive budgets (24 h, 48 h) producing *identical* Above-Median rates of 84.0% and identical Silver 21.3% is statistically odd for single-run measurements — plausible (the same tasks clear the same thresholds) but it means the 24h→48h "5.3-point gain" is effectively 2 bronze + 1 gold reclassification on 75 tasks, i.e. 4 medals. A 4-medal difference from a single run is well inside the run-to-run variance the Lite split shows (e.g. 20/22 vs 19/22 medaled across three runs, ±SE 1.5 on a 22-task split ⇒ ±5 pts on 75 tasks).

**The MARS comparison is the weakest link.** MARS numbers come from its *publicly released trajectories* under its native configuration with Gemini 3 Pro Preview — a different backbone, a different harness, and, critically, "method-specific node indices" that the paper itself footnotes: the methods do not begin from a shared root. Comparing Medal@3 and Medal@5 across trajectories with different node granularity is not a controlled comparison; MARS's Node AUC of −0.39 partly reflects that its node 1 is a near-empty baseline (2.1 min build time for the Direct Loop vs 14.8 min for MARS). The matched-backbone Direct Coding Loop and Search-Augmented variants are the right idea, but they are the authors' own re-implementations and both are *much* weaker than MARS (12.1% and 28.8% initial medal vs MARS 28.8%), so they establish "our state beats no-state" without establishing "our state beats the best published state under matched conditions."

**Ablation design.** Table 4 is informative and the static-vs-full gap (83.3 → 89.4) is the strongest single piece of evidence for continual revision. But the "Codebase State" row at 10.6% initial / 0.06 Node AUC is a strawman: it is the authors' own no-state loop, and its 2.1-minute initialization almost guarantees a bad first solution. A fairer no-state control would be AIDE or MLE-STAR under the same Gemini stack. Also, the ablation varies three things at once across four rows (state type, grounding, dynamics), so "grounding" and "construction" contributions are confounded with each other.

**PostTrainBench.** The 30.69 vs 28.56 comparison against Opus 4.7 is framed as "comparable to Claude Code powered by Opus 4.7," which is technically true but selectively so: Fable 5 at 41.79 is the strongest agent and is 11 points ahead, and the official instruct models are 20 points ahead. The paper does say this, but the abstract and intro only carry the Opus 4.7 comparison. Worse, the budgets differ — published rows use **10 h on H100**, Pro2 Agent uses **24 h on A100** — so a 2.4× longer wall-clock on different silicon is being compared against fixed published numbers. High per-benchmark variance (BFCL ±32.9 for Fable 5, ArenaHard ±13.5 for GPT 5.6; and Opus 5's BFCL of 1.50 looks like a harness failure rather than a model result) means the 2-point average gap is not resolvable.

**Red flags and quirks.** (i) No released code, prompts, Problem State artifacts or trajectories, on a system whose entire contribution is a state representation — this makes the central claim essentially unverifiable by third parties, and the proprietary Gemini 3.x backbones make replication impossible in principle. (ii) The "expert technique recall" analysis (§4.5) is run on only the 5 hardest tasks with unbounded regression lines and no confidence intervals or significance test; the claim that Pro2 Agent's line sits "above" the baseline is asserted visually. (iii) The four case studies, while refreshingly honest about two failures, are selected by the authors and one of them (`bms-molecular-translation`) is chosen precisely because MARS failed it — a favorable-selection risk that the paper does not discuss. (iv) Absolutely no cost accounting: tokens, dollars, or PI-Agent supervision overhead are never reported, so "48 h on one A100" hides an unknown and possibly large LLM inference bill behind every medal. (v) The claim that the agent "correctly identified" resource-limited versus unresolved bottlenecks is a post-hoc narrative label assigned by the same agent being evaluated — there is no external adjudication of whether the diagnosis was right.

**Overall.** This is solid, well-engineered work with an above-average honesty level in the tables and a genuinely useful formalism, and the bronze/silver breadth result (50.7% vs 28.8% combined) is the most convincing number in the paper because it is the one the authors did not headline. It is not, however, a clean demonstration that the Problem State is *the* cause of state-of-the-art performance: the matched-backbone evidence is against weak self-built baselines, the strongest external baseline is compared across different backbones and unshared roots, and the top-line numbers rest on single runs.

## Strengths

- **A formalism that pays for itself.** The Problem State is not decoration: the ablation isolates a concrete 6.1-point final-medal gap between a static and an updated state, and shows the *initial* solution is nearly identical in both — a clean dissociation between "plan better" and "revise better."
- **Mechanistically enforced scientific hygiene.** The single-variable isolation constraint in Phase 2 and the diff-audit firewall $\mathcal{C}_{Diff}\cap\{\text{model},\text{algo},\text{data}\}=\emptyset$ in Phase 3 are enforced by a separate Reviewer agent in code, not by prompt instruction. This is the part most likely to be adopted by other systems.
- **Validation decoupled from the sandbox.** Grading through an HTTP service with isolated ground-truth labels, plus explicit exclusion of test-set-feedback submissions, closes the most obvious cheating channel in agentic MLE benchmarks.
- **Unusually honest reporting.** The paper volunteers that MARS+ has a higher gold rate, that Pro2 Agent ties rather than beats AIBuildAI-2 at 24 h, that the PostTrainBench average sits 20 points below official instruct models, and that two of four case studies are failures. Those are the admissions a weaker paper would omit.
- **Efficiency, not just accuracy.** The paper measures Medal@3, Medal@5 and Node AUC, and the Node AUC sign flip (+0.58 vs −0.39) shows the gain is a trajectory property rather than a lucky final node. Most agent papers only report the endpoint.
- **Failure taxonomy with practical value.** Resolved / Resource-Limited / Unresolved is a genuinely useful vocabulary — the RSNA case (correctly diagnosing micro-calcification loss, correctly concluding the better model is compute-infeasible, and stopping) is exactly the behavior you want from an autonomous researcher, and it is rewarded rather than penalized.

## Limitations

- **No code, prompts, state artifacts or trajectories released**, and proprietary backbones (Gemini 3.1 Pro / 3.5 Flash) make the central representation claim unfalsifiable by outsiders. For a paper whose thesis is "the state is the contribution," this is the most serious gap.
- **Single run per budget** on the complete 75-task MLE-Bench, with no variance estimate, while the 24h/48h delta is only 4 medals.
- **Backbone-confounded leaderboard comparison.** AIBuildAI-2 uses Claude Opus 4.7, MLEvolve Gemini 3.1 Pro Preview on H200 at 12 h, MARS+ 2×H100 — Pro2 Agent is one A100. The paper says this, but the headline "matches the best reported" is then a statement about heterogeneous systems, not about the method.
- **The MARS trajectory comparison is not controlled** (different backbone, method-specific node indexing, unshared roots), so it cannot support fine-grained efficiency claims like "MARS typically evaluates more than 70 repository variants."
- **PostTrainBench budget mismatch** (24 h A100 vs 10 h H100) plus very large per-benchmark error bars make the ranking against Opus 4.7 / GPT 5.5 / Fable 5 statistically unresolved.
- **No cost or token accounting anywhere.** Compute budgets are wall-clock GPU hours only; LLM inference cost, PI-agent supervision overhead, and total dollar cost per medal are omitted, which makes the efficiency argument incomplete for anyone deciding whether to deploy this.
- **The belief update rule is deliberately crude** ($\pm\Delta b$ constants, no uncertainty, no repeated measurement, no noise model) — the authors admit this in §5, and it means belief scores are effectively a heuristic priority queue rather than a calibrated posterior.
- **Narrow benchmark coverage.** Only MLE-Bench and PostTrainBench — no RE-Bench, no PaperBench, no SciCode — so "general autonomous AI research" is established on two Kaggle/post-training pipelines.
- **Selection effects in the analysis sections**: 5 tasks for the technique-recall study, 4 hand-picked case studies, and one case study selected because the strongest baseline failed it.

## Relevance

正中「Self-Evolving Agents & Automated Research」核心：把研究状态从「代码+分数」显式化为「瓶颈—候选解法—置信度」并用受控实验更新，是对长时程自主研究智能体可靠性与可审计性的一次实质性推进；它的三态瓶颈分类（resolved / resource-limited / unresolved）对判断 agent 何时该停手尤有价值。对关注 agent 长时程失败模式与「智能体自我诊断是否可信」的读者，第 4.6 节的两个失败案例比主表更值得读。

## Questions for Further Exploration

1. How much of the 70.7% → 76.0% gain is Problem Probing specifically, versus simply spending 2× wall-clock on a system that never saturates? A 24 h run with a *larger* budget for the no-state control would isolate this.
2. What is the per-medal LLM inference cost (tokens / dollars), and how does it compare to MARS+ and AIBuildAI-2? A 30× cheaper bronze medal is a different result from a 30× more expensive one.
3. How sensitive is the result to the PI/Implementation model split? §5 lists "other model allocations" as future work — does a single strong model with the same Problem State machinery do as well, or is the tripartite loop doing independent work?
4. The belief dynamics use fixed $\pm\Delta b$. Does a calibrated probabilistic update (e.g. Beta-Bernoulli per solution, or noise-aware repeated measurement) actually improve final medal rate, or does the priority queue saturate because $b$ is only ever used for ordering?
5. Would an independent adjudicator agree with the Resolved / Resource-Limited / Unresolved labels? Annotating those 4 (or 40) trajectories by humans would turn the taxonomy from narrative into measurement.
6. How much does the bottleneck-conditioned literature search contribute versus ordinary retrieval? The Search-Augmented control retrieves *before* the task, so it does not test retrieval *conditioned on a diagnosed bottleneck* — that is the specific mechanism claimed.
7. On the tasks Pro2 Agent still fails (the 24% at 48 h), is the failure mode predominantly unresolved reasoning, compute infeasibility, or misdiagnosis? The three-state taxonomy makes this measurable but the paper does not report the distribution.
