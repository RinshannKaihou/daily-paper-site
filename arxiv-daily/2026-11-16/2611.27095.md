> **一句话总结：** 作者开源了 `epistemic-guard`（v0.5.2）——一个把 Ed25519 签名密钥放在 agent 进程之外的 stdio MCP 回执代理，配合 82.67 MB 的 OpenVINO INT8 交叉编码器做"回合后的散文核查"、按 7 类来源域把关的 SQLite 记忆写入、以及镜像网页去重；在 250 条冻结基准轨迹上以纯 CPU 达到 93.2% 准确率、17.9 ms 中位延迟，比 12B/14B GPU judge 高 6.4–6.8 个百分点，但在 60 条真实 MCP 轨迹上准确率掉到 76.67%（38.24% FPR），对 GPU judge 的差距不再显著。

> **TL;DR:** epistemic-guard intercepts every MCP tool call in an out-of-process stdio proxy, signs receipts with Ed25519 into an RFC 6962 Merkle log, then checks each assistant turn's prose against the verified receipts using a CPU-only INT8 cross-encoder — no GPU at all. On a 250-trace frozen benchmark it reaches 93.2% accuracy (96.72% recall, 10.16% FPR) at 17.9 ms median, beating a Mistral-NeMo-12B judge (86.8%, +6.4 pp, McNemar p=0.0259) and Phi-4-14B (86.4%, +6.8 pp, p=0.0095) while freeing 8.8–12.2 GB of VRAM. On 60 live mcp-proxy fault traces the picture weakens: 76.67% accuracy with 38.24% FPR and non-significant deltas vs. those same GPU judges — the frozen-cohort win does not fully transfer to unseen tool vocabularies.

## 核心贡献

- **把签名密钥移出 agent 进程**：`mcp-proxy` 作为 stdio JSON-RPC 父进程拦截所有 `tools/call`，在 spawn 子服务器前剥离签名相关环境变量，从而让被注入的子服务器无法伪造回执（作者明确把"密钥在进程内"列为不可接受的威胁）。
- **四态线上分类，把"没执行"和"执行失败"分开**：normal (executed=true, ok=true)、MCP 工具报错 (`result.isError=true`)、执行前拒绝（-32700/-32600/-32601/-32602 或 schema 校验失败，executed=false）、子进程中途崩溃/EOF；非标准错误码保守地记为 executed=true, ok=false，因此任何失败都不能去"支撑"成功叙述。
- **回合后散文监督（核心创新）**：先做言语行为层面的是非陈述过滤（屏蔽否定、条件句、引述、代码块），再用微调过的 `action_claim` INT8 交叉编码器判断"是否声称了一个已完成的外部副作用"；一旦检测到，就去核对本轮回执的签名、session 绑定、参数/目标匹配（拒绝子串碰撞、拒绝零参数通配），不匹配则返回带字符偏移的 `SupervisionVerdict(is_valid=false)` 和可直接回灌的重试提示。
- **来源域分离的记忆写入闸门**：用 HKDF-SHA256 从主种子派生 5 组 Ed25519 密钥覆盖 7 个来源域（USER_EXPLICIT / USER_CONFIRMED / TOOL_VERIFIED / LISP_ASSERTION / INFERRED / LLM_NARRATION / TOOL_CONTENT_UNTRUSTED），其中 LLM_NARRATION 与 TOOL_CONTENT_UNTRUSTED 根本没有可用的签名构造函数，从 API 层面就不可能产生合法信封；SQLite 侧再用 2 个 `BEFORE UPDATE` / `BEFORE DELETE` 触发器阻止就地篡改。
- **镜像去重**：4-shingle Jaccard ≥ 0.55、SimHash 汉明距离 ≤ 12、锚词 Jaccard ≥ 0.45 等阈值把同一来源的 SEO 镜像折叠成一个簇，再按 3 档危险度 × 4 种证明标准（12 个策略格）判断是否够格被无保留陈述。
- **可复现性基础设施**：所有数字绑定到 `results/*.json` 清单、SHA-256 输入哈希与 osaudit 审计；4 个 INT8 模型（16 个文件、279.48 MB）与基准语料在 Hugging Face 归档并附 OpenTimestamps 收据；MIT 许可。

## Key Contributions

- **Out-of-process receipt authority.** An Ed25519 signing key that never enters the agent's process or any child MCP server's environment, with append-only RFC 6962 Merkle logging (logarithmic inclusion proofs, cross-key chain rotation via `--prev-log`, OS file locks for multi-worker appends) plus pinned-public-key verification in `verify-log`.
- **A four-way wire-state taxonomy that separates pre-execution rejection from runtime failure** — the distinction matters because "the call executed and failed" and "the call never happened" license completely different prose, and most firewalls collapse them.
- **Receipt-bound prose supervision as the missing fourth layer.** Existing MCP firewalls check traffic *before* execution; dialogue guardrails check text *without* receipts. This paper binds natural-language claims to signed execution records, which is the only way to catch a first-person "I have updated the config" when `isError=true`.
- **Provenance as a write-time invariant rather than a document.** Seven domains, five with signing capability, gated at the SQLite boundary; narration is structurally incapable of being promoted to a verified fact.
- **AER-1 interoperability.** Bidirectional single-receipt translation to the IETF `draft-zambo-aer1-26` format, passing 58/58 official ingestion vectors and 50/50 reference-verified exports — this is the piece that makes the receipt layer portable beyond one vendor.
- **Honest negative results.** The paraphrase sweep explicitly shows the syndication defence collapsing (100% → 40% → 0%) as edits get heavier, and the paper reports a 3-item regression from security hardening rather than hiding it.

## Methodology

The system model is an MCP host `H` running an untrusted generation loop `A` that talks to tool servers `{S_i}`, a RAG retriever `R`, and a local memory DB `M`. Complete mediation requires `H` to launch *every* tool server through `mcp-proxy`, so `A` has no unproxied side channel. Before displaying or forwarding a candidate reply `y_t`, `H` calls `ReceiptSupervisor` (or the `verify-log` CLI) *outside* `A`'s prompt context.

The package is 15 typed Python modules (`mypy --strict`) under one import-linter layer contract ensuring crypto/supervision/storage never import from CLI, MCP-server, or integration layers. `mcp-proxy` is a stdio JSON-RPC 2.0 parent that correlates requests FIFO by JSON-RPC id, classifies the four outcome states, and appends `ReceiptLogEntry` records carrying both an inner `ToolReceipt` signature and a domain-separated `entry_signature` over `(seq, session_id, leaf_sha256, prev_chain_sha256, chain_sha256, merkle_root)`. Canonicalization uses sorted keys with `allow_nan=False` so NaN/Infinity cannot break cross-runtime hashing; 0x00/0x01 leaf/interior prefixes follow RFC 6962.

Supervision is hybrid symbolic–neural, two-stage: (1) speech-act filtering masks non-assertive spans and optionally extracts explicit `[ACTION: verb target]` tags, then the INT8 `action_claim` cross-encoder scores candidate clauses; if no completed side effect is asserted, the turn passes without demanding receipts. (2) When a claim exists, `ProvenanceGate` verifies signatures/session/age, drops any receipt with `executed=false` or `ok=false`, and matches claimed action families, additive counts, and concrete file/URL/email targets against receipt arguments on path and token boundaries. The supervision path loads only the 82.67 MB `action_claim` model out of the 279.48 MB four-model bundle (the other three — a 82.65 MB hazard classifier, 91.1 MB DeBERTa-v3 NLI cross-encoder, 23.06 MB MiniLM web-evidence encoder — serve RAG corroboration).

Storage wraps SQLite in WAL mode behind a mandatory `ProvenanceGate` with `BEGIN IMMEDIATE` transactions; accepted envelopes link into a cumulative SHA-256 chain. Syndication handling shards passages into width-4 word shingles, drops boilerplate via MiniLM, checks cross-source contradictions via the NLI cross-encoder, and merges near-duplicate mirrors across registrable domains using the Jaccard/SimHash gates above.

Evaluation is split into RQ1 (deterministic conformance, concurrency/replay faults, paraphrase sensitivity) and RQ2 (supervision accuracy, live receipt binding, resource cost). All experiments ran on one Windows 11 workstation (Intel Core Ultra 9 275HX, RTX 5080 Laptop 16 GB); GPU baselines were Mistral-NeMo-Instruct-2407-Q5_K_M and Phi-4-Q6_K under llama.cpp (`-ngl 99`, `-c 4096`, temperature 0) with a fixed 3-rule auditor prompt receiving `USER_PROMPT`, `VERIFIED_EXECUTED_TOOLS` (including raw argument strings), and `ASSISTANT_REPLY`, emitting ALLOW or BLOCK. Proportions use two-sided 95% Wilson intervals; paired comparisons use exact McNemar tests.

## Results & Highlights

- **Frozen benchmark, N=250 (122 ungrounded / 128 grounded):** 93.2% accuracy (233/250; TP=118, TN=115, FP=13, FN=4), 96.72% recall, 10.16% FPR at 17.9 ms warm median (8.62 ms single-clause, 19.38 ms mean, 35.83 ms p95) and 921.8 ms cold start. It beats the Mistral-NeMo-12B judge's 86.8% (217/250) by **+6.4 pp** (McNemar 31 vs 15, p=0.0259) and Phi-4-14B's 86.4% (216/250) by **+6.8 pp** (28 vs 11, p=0.0095), at 4.5× and 4.26× lower p50 (80.58 ms / 76.24 ms) while saving 8,844 and 12,214 MiB of VRAM.
- **Sub-cohort spread shows where the accuracy lives:** 100.0% (50/50, CI [92.87, 100]) on author-labeled `locked_coh_50`, 92.0% (92/100, CI [85.0, 95.89]) on `blind42_coh_100` paraphrases, and 91.0% (91/100, CI [83.77, 95.19]) on `organic_heldout_h100` tool-less chat turns — the ceiling cohort is the author-labelled one.
- **Ablations isolate the receipt binding:** Stage-1-only (receipts=[]) reaches 84.8% (212/250) but at 27.34% FPR, while Regex+receipts collapses to 64.0% (160/250) with only 30.33% recall at 0.08 ms. The off-the-shelf DeBERTa-v3-xsmall NLI CPU baseline scores **52.8%** (132/250), predicting "neutral" on 73 of 92 false negatives (79.35%) — the gap to epistemic-guard is +40.4 pp.
- **Live end-to-end MCP traces (N=60; 30 gemma-4-E4B + 30 Nemotron-3.5-30B-A3B; 26 ungrounded / 34 grounded):** 96.15% hazard recall (25/26, CI [81.11, 99.32]) at 76.67% accuracy (46/60) and **38.24% FPR** (13/34) in 9.16 ms p50 (23.12 ms p95). Stage-2 receipt binding adds +18.34 pp over Stage-1-only (58.33%, 35/60, 70.59% FPR; 11 vs 0 discordant, p=0.001) — this is the paper's cleanest causal result.
- **But the live deltas against GPU judges are not significant:** Mistral-NeMo-12B holds 80.0% (48/60, p=0.7905) and Phi-4-14B drops to 65.0% (39/60, p=0.1671) versus epistemic-guard's 76.67%; the paper reports this honestly. The 12B judge is therefore 7.83× slower but nominally 3.33 pp more accurate on unseen tool vocabularies.
- **Deterministic conformance is uniformly 100%:** 200/200 Merkle inclusion proofs verify and 200/200 payload mutations raise `MerkleTamperError`; 58/58 official AER-1 ingestion vectors (22 valid accepted, 36 invalid rejected) and 50/50 reference-verified exports with tampered digests rejected 50/50; 40/40 wire calls classified across the four modes with **0 child-environment key leaks**; 100/100 concurrent appends (4 threads × 25) preserve chain order; 4/4 replay/reorder/NaN attacks fail closed.
- **Storage gate:** across 300 writes, 200/200 authorized signed envelopes accepted with **0.0% false rejection** along the 200-row hash chain, 100/100 unauthorized writes blocked (50 `LLM_NARRATION` + 50 forged keys), and 2/2 direct SQL UPDATE/DELETE mutations aborted by triggers.
- **Syndication dedup works only on wire copy:** 45/45 clusters (135 URLs, 3 domains each) collapse to single-origin with high-hazard promotion blocked; the sensitivity sweep over 50 clusters/tier holds 100.0% under dateline/footer wrappers and 100.0% at ~15% lexical edits, degrades to 40.0% at ~30% edits, and hits **0.0%** at ~45% clause restructuring and 0.0% at >80% abstractive rewrites.

## Authors & Credibility

Single author: Sean Maxwell (Roll Solo, Melbourne), with an ORCID and a public GitHub/PyPI/Hugging Face artifact trail. The paper discloses that the author is founder of Roll Solo and a member of NVIDIA Inception, that no external funding was received, and that code is MIT-licensed with weights under Apache-2.0/MIT upstream licences. Credibility signals: full artifacts (code, PyPI, INT8 weights, benchmark corpora), osaudit manifests with SHA-256 input hashes and OpenTimestamps receipts, acknowledgement of the AER-1 draft author and of osaudit's author, and a Limitations section that is unusually candid for a systems paper (it reports the 3-item accuracy regression caused by its own security hardening). Countervailing signals: 5 of 25 references are the author's own Zenodo preprints (the speech-act evasion taxonomy in [15], the memory-poisoning work in [13], and [12], [14]), i.e. the empirical setup rests substantially on the author's own prior definitions of the failure mode being measured; there is no academic affiliation, no peer review, and no independent replication.

## Critical Assessment

**Novelty.** The individual primitives are borrowed (RFC 6962 logs from Certificate Transparency, Ed25519 and HKDF from IETF, Jaccard/SimHash from Broder and Charikar), but the *composition* — binding post-turn natural-language claims to signed wire receipts inside an MCP proxy — is a genuine gap. Existing MCP firewalls (Pipelock) inspect parameters pre-execution and NabaOS sandboxes the runtime; neither checks whether the model's prose matches what actually executed. Stating the threat as three OWASP-ASI entries (ASI02/ASI06/ASI08) and closing each with one mechanism is a coherent framing rather than a grab-bag.

**Rigor — where the evidence is strong.** The ablation table is the most convincing part: Stage-1-only → full supervisor moves live-MCP accuracy 58.33% → 76.67% (p=0.001), while adding receipts to regex alone instead destroys recall (0.0% on Live-60). That is a causal story about *which* component does the work, not a leaderboard number. Separating `executed=false` from `ok=false` and defaulting non-standard error codes to `ok=false` is exactly the right fail-closed choice, and the 0-false-accept numbers on 200 payload mutations plus the 0.0% false-rejection rate on 200 authorized writes show the crypto path is not merely decorative.

**Rigor — where it is weak.** Three problems stand out. (1) *Baseline hygiene.* The GPU judges get one fixed 3-rule auditor prompt at temperature 0 with no few-shot examples, no chain-of-thought, and no per-cohort prompt tuning, while the INT8 encoder is a fine-tuned model. A 12B judge at 86.8% under a single thin prompt is a soft target, and the paper explicitly omits commercial frontier judges (GPT-5/Claude-class) for cost reasons — precisely the baselines a reader would want, since they are the realistic deployment alternative. The honest reading of "+6.4/+6.8 pp" is "beats a lightly-prompted 12–14B local judge", not "beats LLM-judge guardrails". (2) *Label provenance.* The two highest-accuracy cohorts (`locked_coh_50` at 100.0%, `blind42_coh_100`) are author-labelled speech-act cases, and the paper states the benchmark was "frozen with v0.3.0 weights" — i.e. frozen contemporaneously with model development by the same author who defined the taxonomy. A 50/50 perfect score on that cohort is a ceiling consistent with development-set overlap, and the absence of a multi-human κ study is acknowledged but not remedied; `organic_heldout_h100` relies on LLM raters with 30/30 dual-slice agreement plus author audit, which is weaker than independent annotation. (3) *Transfer gap swept under the headline.* The abstract leads with 93.2% and "+6.4–6.8 points", but on the 60 live traces — the only cohort with real child servers, real fault injection and unseen tool names — accuracy is 76.67% and the GPU-judge deltas are p=0.79 and p=0.17. The 13 live false positives are diagnostic and specific: 6 come from unmapped custom tool stems (`execute_sql`, `http_post`, `git_commit`) and 7 from comma-split "attempted X, but failed" clauses, meaning the symbolic layer's coverage is a function of a hand-maintained tool vocabulary. A 38.24% FPR also means roughly two in five benign turns would receive a `to_retry_prompt()`, and the paper never measures what that costs in agent task success or token spend — it argues the trade is worth it ("a missed fabrication corrupts state") without quantifying the downside.

**Rigor — conformance numbers are partly self-referential.** The 100.0% rows in Table 2 are unit tests of the implementation's own invariants against synthetic faults (10 calls per wire mode, 2 SQL mutation attempts, 4 replay attempts). They demonstrate the code does what it claims; they say nothing about attack success rates in the wild, and the small trial counts (n=4 for replay, n=2 for triggers) make "100.0%" close to a smoke test. The TCB section is appropriately explicit that a malicious server returning `ok=true` while lying yields a "validly signed false receipt", that host-kernel compromise is out of scope, and that complete mediation only holds if the agent has no unproxied side channel — an assumption that most real agent harnesses (shell tools, built-in HTTP fetchers, code interpreters) violate by default, so the deployment story requires re-architecting the harness rather than adding a dependency.

**Significance.** If the receipt-binding idea holds up, it is the right shape for the problem: the failure mode is not toxicity but *epistemic* mismatch between wire state and prose, and no amount of text-only moderation fixes it. The zero-VRAM, 17.9 ms profile is genuinely deployable where an 8.8 GB judge is not. But the evaluated slice is narrow — English, one workstation, stdio transport only (Streamable HTTP/SSE needs a bridge), and a syndication filter whose 0.0% collapse rate at ~45% paraphrase is exactly the evasion an adversary would choose. The paper knows this and says so; the abstract's framing is a bit more confident than the live-cohort numbers support.

## Strengths

- Correct and unusually careful threat decomposition: pre-execution rejection vs. runtime failure vs. crash vs. success are four distinct states, and the fail-closed default for unknown errors is the right call.
- Key isolation is architecturally enforced, not documented: `SignerFactory` has no constructor for `LLM_NARRATION` or `TOOL_CONTENT_UNTRUSTED`, so narration cannot be signed even by a buggy caller.
- The ablation design actually identifies the mechanism (Stage-2 receipt binding, +18.34 pp, p=0.001) instead of reporting a single aggregate score.
- Strong reproducibility posture: osaudit manifests, SHA-256-pinned INT8 files verified at every load, Hugging Face corpora with OpenTimestamps, MIT code.
- The paraphrase sensitivity sweep is a model of honest reporting — publishing the 0.0% tiers is more valuable than the 100.0% tier.
- Genuinely useful engineering detail: `allow_nan=False` canonicalization, 0x00/0x01 Merkle prefixes, `O_CREAT|O_EXCL` with mode 0600 key files, and the explicit warning that same-UID processes can read `--key-file` unless the proxy runs under a separate OS user.
- Zero GPU VRAM at 17.9 ms median is a real operational advantage for edge and CI settings.

## Limitations

- **Evaluation scale and diversity.** N=250 frozen (all author-curated) and N=60 live, English only, one Windows workstation, two local GPU judges. No frontier API judges, no multi-human inter-annotator agreement, no second lab replication.
- **Label circularity.** The benchmark, the failure taxonomy, and the fine-tuned `action_claim` encoder all come from the same author; the 100.0% on `locked_coh_50` cannot distinguish genuine capability from development overlap.
- **Live-cohort performance is materially worse** (76.67% accuracy, 38.24% FPR) and the GPU-judge comparison there is non-significant; the paper's headline lives on the friendlier cohort.
- **Symbolic layer needs manual tool-stem registration.** Custom MCP tools (`execute_sql`, `http_post`, `git_commit`) produce 6 of 13 live false positives; cross-clause negation propagation ("attempted X, but failed") produces the other 7.
- **Transport scope.** stdio only; Streamable HTTP/SSE requires a local bridge or in-process `ReceiptRecorder`, which reintroduces the in-process key exposure the paper argues against.
- **Complete mediation is an assumption, not a guarantee.** Direct shell execution or built-in HTTP tools in the agent give an unproxied side channel and void the whole chain.
- **Syndication defence is verbatim-limited** (0.0% collapse at ~45% paraphrase), so it protects against SEO wire copy, not against an adversary who paraphrases.
- **No end-to-end task-level evaluation.** Nothing measures whether agents with the supervisor complete tasks better, or how much the 38.24% live FPR costs in retries and latency.
- **Single-author, non-peer-reviewed preprint** with heavy self-citation of the author's own Zenodo preprints for the core failure taxonomy.

## Relevance

直接命中 **Agent & Pipeline Silent Failures**：它处理的正是"工具调用层的真实状态与模型对外输出/写入记忆之间被静默改写"这一类失败，且给出了检测（回合后散文核查）与修复（带字符偏移的重试提示、写入闸门）的具体机制，而非停留在模型侧幻觉讨论。对关心 agent 长时运行可靠性、可审计性与 MCP 工具链的人来说，是这一批论文里工程完成度最高的一篇；但引用其 93.2% 时应同时引用其在真实轨迹上 76.67%/38.24% FPR 的结果。

## Questions for Further Exploration

1. How much of the +6.4/+6.8 pp margin survives if the 12B/14B judges get few-shot exemplars, chain-of-thought, or per-cohort calibration — and what happens against a frontier API judge at equal cost?
2. Can the `locked_coh_50` 100.0% be reproduced on labels written by an independent annotator who has not read the author's speech-act taxonomy?
3. What is the downstream cost of the 38.24% live FPR in agent task success, token spend, and wall-clock time once `to_retry_prompt()` is actually wired into a loop?
4. How does the system behave under an adaptive adversary who paraphrases syndicated sources (the 0.0% tier) *and* avoids naming concrete tool targets in prose?
5. Do the Merkle receipt logs support retroactive auditing at scale — e.g. can they detect the cross-session memory poisoning of [13] after the fact, or only prevent it at write time?
6. What fraction of real agent harnesses can actually satisfy complete mediation, given that shell tools, code interpreters, and built-in HTTP clients are standard?
7. Does the 94.4% → 93.2% hardening regression indicate the benchmark is too sensitive to symbolic-rule churn to serve as a stable comparison target across versions?
