> **一句话总结：** Clover-35B-A3B-Preview 直接把 Qwen3.6-35B-A3B 的 35B/3B MoE 主干改造成块扩散模型，核心改动是 BD-GDN——让"已完成前缀的循环记忆读出"与"当前块内的双向 softmax 注意力"共用同一个 softmax，用可学习块长校准项 c_h·log(N_b/32) 抵消历史槽位在块变大时被稀释的问题，右向短卷积三抽头零初始化，只新增 740,160 个参数（占 35B 的 0.002%）；配合熵启发的自投机解码，在自建同协议评测中 SWE-bench Verified 得 73.6（Qwen3.6 基线 65.8）、Terminal-Bench 2.1 得 51.7（基线 43.1），但同时 HLE 掉到 12.8（基线 21.2）、AIME 2026 掉到 83.3（基线 90.4），而速度只有在 agent replay 上快（556.6 vs 396.7 tok/s），在 MATH-500 上反而慢于 Qwen3.6 + DFlash 2（465.2 vs 604.3 tok/s）。

> **TL;DR:** Clover is a 35B-total/3B-active MoE block-diffusion LM obtained by adapting the Qwen3.6-35B-A3B text backbone, with a Block-diffusion Gated DeltaNet that folds one compressed history readout into the same softmax as the current block's tokens (plus a zero-initialized right-context convolution, 740,160 new parameters in total). Evaluated entirely in-house under one protocol, it beats its own Qwen3.6-35B-A3B backbone on all seven agent benchmarks — SWE-bench Verified 73.6 vs 65.8 (+7.8), Terminal-Bench 2.1 51.7 vs 43.1 (+8.6), SWE-Pro 46.5 vs 42.7, GDPval-AA v2 1091 vs 1049 Elo — while losing on knowledge and math (HLE text-only 12.8 vs 21.2, AIME 2026 83.3 vs 90.4). Self-speculative decoding reaches 680 tok/s on one GB300 and 515 tok/s on one H200 on a 64-prefix agent replay, but only 465.2 tok/s on MATH-500 versus 604.3 for Qwen3.6 + DFlash 2. No component ablation is reported, so which of BD-GDN, dMoE, the diffusion objective, or the post-training data produces the agent gains remains unidentified.

## 核心贡献

- **把"写"和"读"彻底分开的 BD-GDN**：已完成上下文走门控 delta 规则递推（保留预训练的因果 GDN），当前待去噪块走块内双向 softmax；关键是两边不是拼接而是**竞争**——历史读出 r_j 只占 softmax 里的一个 logit，与 N_b 个块内 token 的 logit 一起做一次归一化（式 11）。
- **指出并修掉了一个真实的归一化缺陷**：历史只有 1 个槽位、块内竞争者却有 N_b 个，块长一大历史权重就被系统性稀释；他们给历史 logit 加了一个可学习偏置 b_h + c_h·log(N_b/N_ref)，并给出式 12 的推导说明 c_h=1 时该权重与 N_b 无关，初始化 (s_h, b_h, c_h) = (10, 5, 1)。
- **极低成本的架构改造**：右向卷积用独立的三抽头核、初始化为零，使模型在初始化时与预训练因果卷积完全等价；30 个 BD-GDN 层合计只新增 737,280 个右核参数 + 2,880 个 softmax 标量，共 740,160 个。
- **块级专家路由 dMoE 的扩散化适配**：先按块内 token 的 top-8 概率聚合出覆盖 τ=0.9 专家质量的最小专家核集（coreset），再在核集内做 token 级 top-8；每个模块 256 个 routed expert + 1 个 shared expert，SwiGLU 中间宽度 512。
- **训练侧的双流因果隔离**：把 [带噪块 | 干净块] 交错打包，用显式 example/stream/block 身份保证带噪 query 只能看块前的干净 token 和本块内的带噪 token；块长从 {4, 8, 16, 32} 均匀采样，扩散损失与辅助因果 NTP 损失联合优化。
- **把扩散模型真正推到 agent 任务上并开源**：权重（HuggingFace）、SFT 代码、推理引擎全部放出，另外给了消费级单卡（RTX 5070 Ti 16GB）的 INT4 + KTransformers 部署结果，以及与决策模型变体（一次去噪同时回答最多 8 个相关问题）的联合预测实验。

## Key Contributions

- **BD-GDN separates writing from reading.** Completed context is written into a gated delta-rule recurrent state (the pretrained causal GDN is kept as-is); the active block is read with bidirectional softmax attention. The novel part is that the two are not concatenated but made to compete: the history readout r_j = S_b q̂_j / √d_k occupies exactly one softmax slot alongside the N_b block-local logits, so a query can spend probability mass on either the compressed prefix or individual in-block tokens (Eq. 11).
- **A diagnosed normalization defect with a learnable fix.** Because history has one slot while local competitors scale with N_b, a fixed history bias systematically starves the prefix as block size grows. Adding b_h + c_h·log(N_b/N_ref) with N_ref = 32 removes this dependence when c_h = 1 (Eq. 12), and c_h lets each head deviate from the exact compensation as its local logit spread changes.
- **A genuinely cheap architectural delta.** The bidirectional short convolution is an independent three-tap right kernel summed onto the pretrained four-tap causal kernel before a single SiLU, with all right taps initialized to zero — so at step 0 the model is numerically the causal model it came from. 737,280 right-kernel parameters plus 2,880 per-head scalars across 30 BD-GDN layers, i.e. 740,160 new parameters total.
- **Block-aware expert routing (dMoE).** A per-layer, per-denoising-pass block coreset is formed by aggregating each valid token's top-8 router probabilities over the block, then keeping the smallest expert set covering τ = 0.9 of that mass; token-level top-8 routing is re-run inside the coreset. 256 routed experts + 1 shared expert per module, SwiGLU width 512.
- **An infrastructure recipe for two-stream diffusion training at 128K.** Megatron-Core / Megatron Bridge extensions carry the clean/noisy distinction through sequence packing (the 128K semantic sequence becomes ~256K stored positions), attention masks (FlexAttention with structured metadata), recurrent state, expert routing, context parallelism (Ulysses or FLA-KCP for the linear-attention layers) and activation recomputation.
- **A released artifact and a deployment story.** Weights, SFT code and inference engine are public; the report additionally documents a 16GB-consumer-GPU INT4 path (SGLang + KTransformers, 96 GPU / 160 CPU experts per layer) and a decision-model variant that answers up to eight related questions in one denoising pass.

## Methodology

### Backbone and shape

Clover adapts the text backbone of Qwen3.6-35B-A3B. 40 decoder layers, hidden width D = 2048, a repeating group of three BD-GDN layers followed by one full-attention layer, ten times — thus 30 recurrent mixers and 10 full-attention mixers, each followed by a dMoE module with pre-norm and residual connections. BD-GDN uses H_k = 16 query/key heads and H_v = 32 value heads with d_k = d_v = 128 (each Q/K head serves two V heads); full-attention layers use 16 query heads, 2 K/V heads, head dimension 256, QK-norm, partial RoPE and a sigmoid output gate. Context is 131,072 tokens across prompt plus response, vocabulary is 248,320, input/output embeddings are untied. The 256-expert, width-2048 shape is inherited from Qwen, and it is where essentially all of the 35B lives; top-8 routing plus the shared expert gives the 3B active budget.

### BD-GDN: one softmax over memory and tokens

For a clean token i the retention and write gates are α_i = exp(−exp(a_log)·softplus(w_aᵀh_i + b_Δ)) and β_i = σ(w_βᵀh_i); the state update is the standard delta rule S_i = α_i S_{i−1} + β_i (v_i − α_i S_{i−1} k̂_i) k̂_iᵀ with L2-normalized keys and queries and a 1/√d_k output scale. Packed examples each start from a zero state and padding neither writes nor decays memory.

For denoising, let b index the block, S_b the state at the block boundary (fixed for the whole block), and A_b the set of valid positions in the block. The history readout is r_j = S_b q̂_j / √d_k — note it deliberately does *not* apply the noisy query's decay gate, since α and β govern clean writes. The logits are ℓ_ji = s_h·q̂_jᵀk̂_i for i ∈ A_b and ℓ_j,hist = b_h + c_h·log(N_b/N_ref) with N_b = |A_b| and N_ref = 32, and one softmax normalizes all N_b + 1 of them: o_j = p_j,hist·r_j + Σ_i p_ji·v_i. Every valid block position participates, including the query itself and unresolved mask tokens; padding is excluded. Because N_b counts mask positions, partial blocks use their actual valid length, so the calibration term automatically tracks how many competitors history faces.

### Independent bidirectional short convolution

Q/K/V projections form C = 2H_k d_k + H_v d_v = 8,192 channels. Each channel gets a depthwise causal kernel of width W = 4 (the pretrained one) plus an independent right-context kernel of width 3, summed *before* a single SiLU, then split into Q/K/V. Left inputs come from committed convolution history plus earlier positions of the current block; right inputs are restricted to valid successors within the block, and missing inputs contribute zero, so no right tap ever crosses a block or packed-example boundary. Clean prefill and causal commit use only the causal kernel. All three right taps start at zero.

### dMoE and decoding

Router probabilities a_je = softmax(W_r f_j)_e over 256 experts; the block's coreset is the smallest expert prefix (after sorting aggregated per-expert mass) covering τ = 0.9, computed per layer and per denoising pass. Router logits outside the coreset are masked, token-level top-8 is re-run inside it, weights are renormalized, and the shared expert is always evaluated with a sigmoid gate: dMoE(f_j) = g_s(f_j)E_s(f_j) + Σ p_je E_e(f_j). Clean causal processing uses ordinary token-level routing so its expert choices never depend on later tokens.

Decoding is predict-and-commit inside a block: append B masks, predict all B in parallel, commit those above a confidence threshold, remask the rest. Clover's deployed mode is instead self-speculative — the causal GDN verifies the draft block produced by one diffusion step, accepting drafts sequentially until the first rejection under either exact greedy match or the entropy rule p(d) ≥ δ·exp(−H) with δ = 0.6 (all reported results use the entropy rule). History-aware presence and repetition penalties (0.9 and 1.05) plus length-dependent positive logit biases on stop tokens and the end-of-thinking token suppress the repetition diffusion decoding occasionally produces.

### Training recipe

Two streams per example, stored as [x_t | x_0 | x_t | x_0 | …]. Clean queries are token-causal; a noisy query can read clean tokens strictly before its block and noisy tokens within it, but never its clean target block or another noisy block. Block size is sampled uniformly from {4, 8, 16, 32} per microbatch and applied consistently to attention, BD-GDN, right-context convolution and routing. The denoising loss uses no-shift alignment (logit i predicts x0_i) with the standard 1/(1−α_t) weighting; the auxiliary clean-stream loss is shifted next-token prediction. The joint objective is L = λ_BD·L_BD + λ_AR·L_AR, computed over the union of selected positions in one backbone pass with one fused cross-entropy and separate reductions. **The values of λ_BD and λ_AR are never reported.**

### Evaluation protocol

18 benchmarks across knowledge, math, code, reasoning, instruction following, long context and agents. All main-table baselines are reproduced in-house under the same protocol with each model's officially recommended decoding settings; LLaDA2.2 flash runs as an instruct model with no thinking mode, Mercury 2.5 runs thinking at medium effort. Coding-agent tasks use Terminus 2 for Terminal-Bench and Codex for SWE-bench, three runs per task averaged; GDPval-AA v2 is run locally with the NVIDIA NeMo Gym recipe; Terminal-Hard is 21 hard tasks from Terminal-Bench Core v0.1.1; everything else uses EvalScope.

## Results & Highlights

- **Agent benchmarks are where the gains are, and they are large.** SWE-bench Verified 73.6 vs 65.8 for its own Qwen3.6-35B-A3B backbone (+7.8) and 61.4 for Qwen3.5-35B-A3B, against 49.3 for LLaDA2.2 flash (104B-A7.4B) and 23.8 for DiffusionGemma (26B-A4B). Terminal-Bench 2.1 51.7 vs 43.1 (+8.6); Terminal-Hard 38.1 vs 31.8 (+6.3); SWE-Pro 46.5 vs 42.7 (+3.8).
- **The remaining four agent metrics also lead**, giving the "seven of seven" claim: τ3 Overall 65.3 vs 60.9 (+4.4), BFCL-v4 67.9 vs 63.4 (+4.5), GDPval-AA v2 1091 vs 1049 Elo (+42; Elo, not percentage points). Against the non-Qwen diffusion baselines the margins are enormous — τ3 65.3 vs 32.1 for DiffusionGemma, GDPval 1091 vs 721.
- **But on knowledge and math the model is worse than the backbone it was built from.** HLE text-only 12.8 vs 21.2 (−8.4, a 40% relative drop) — it does beat every external diffusion baseline there (DiffusionGemma 10.9, Mercury 2.5 8.9, LLaDA2.2 flash 5.3), but not the AR model it started from. AIME 2026 avg@8 83.3 vs 90.4 (−7.1), SciCode 30.9 vs 31.3 (−0.4), MMLU-Pro 84.8 vs 85.2 for Qwen3.5 (−0.4). MATH-500 is a tie with Qwen3.6 at 96.2 but below Qwen3.5's 97.2; LiveCodeBench v6 72.6 vs 71.4 for Qwen3.6 (+1.2) but below Qwen3.5's 74.3.
- **The big non-agent wins are exactly the "structured, format-following" tasks.** ZebraLogic 95.8 vs 89.2 for Qwen3.5 (+6.6) and 78.6 for Qwen3.6 (+17.2); IFBench 72.3 vs 67.7 (+4.6) and 61.3 (+11.0); AA-LCR 72.0 vs 66.0 (+6.0); GPQA Diamond 83.8 vs 83.3 (+0.5).
- **Speed is workload-dependent.** On one H200, BF16, batch 1, block 16, greedy: MATH-500 465.2 tok/s vs 604.3 for Qwen3.6 + DFlash 2 (a 23% shortfall) despite committing more tokens per verification round (6.8743 vs 6.5897); agent replay 556.6 vs 396.7 (+40%, committed yield 8.2096 vs 4.1548); daily chat 356.7 vs 286.5 (+24%, 4.9970 vs 2.9500).
- **On the full 64-prefix agent replay, block 16 with no penalties, Clover reaches 708.0 end-to-end tok/s and 11.516 committed tokens/round, vs 485.5 tok/s and 4.445 tokens/round for Qwen3.6 + DFlash 2** — but at matched block size 8 the gap is 540.1 vs 485.5 (+11%), and DFlash 2's block-16 setting is flagged "experimental" in the paper's own note. Applying the repetition penalty the paper says it needs drops Clover to 531.5 tok/s (−25%); the headline 680 tok/s figure is the GB300, block-16, controls-enabled configuration, and 515 tok/s is the same setting on H200.
- **Daily-chat answer phase:** body-only decode throughput 415.8 vs 262.6 tok/s for DFlash 2, mean body length 1770.5 vs 1703.1 tokens, and fully-accepted draft rounds 5.16% vs 0.47% — a 11× difference in the fraction of blocks needing no remasking.
- **Consumer-GPU INT4 deployment on MATH-500 (RTX 5070 Ti, 16GB, 32K context, single request):** routing-statistics-informed expert placement lifts decode from 66.64 to 97.52 tok/s at 97.6% reviewed accuracy (up from 96.8%), and dropping verification to top-6 reaches 106.25 tok/s at 96.0%. Same-box baselines: MiniCPM-V 4.7 97.4% at 49.51 tok/s, Qwen3.6-35B-A3B 93.8% at 47.04 tok/s — so Clover is roughly 2× faster at comparable accuracy.
- **Decision-model variant, one denoising pass, up to 8 questions:** on 500 internal groups / 2,420 questions, question accuracy 90.37 → 93.88 and all-correct-group accuracy 65.4 → 77.0; on 50 partially completed 4×4 Sudoku (364 cells), 78.30 → 95.60 and complete-board accuracy 22.0 → 76.0. Group latency at 8 questions is 164 ms vs 1,243 ms sequential (7.58×) and 249 ms parallel (1.52×). External: JevBench 88.31 vs 86.58 for the frozen Jev v1.13 reference; Decision Index 0.2.1 58.23 vs 57.93.

## Authors & Credibility

All authors are at DiffuSpace (diffuspace.ai), a company shipping this as a product-oriented technical report rather than a peer-reviewed paper. The roster is unusually strong for the specific claim being made: Shansan Gong and Mukai Li are DiffuSeq / DiffuSeq-v2 / DiffuCoder authors and Lingpeng Kong is a co-author on that line, while Jiacheng Ye appears throughout the masked-diffusion / AR-to-diffusion adaptation literature that Section 1 and 2 build on. This is the group that has spent years on exactly the "adapt a pretrained AR checkpoint to discrete diffusion" problem, so the architectural reasoning reads as first-hand rather than borrowed.

Counterweights: the report is self-published, the entire benchmark table is reproduced in-house by the authors with the model being promoted, there is no limitations section, and the artifact is explicitly a "Preview." They do credit the Qwen, SGLang and llama.cpp communities in the acknowledgments, and they release weights, SFT code and the inference engine — which is more than most first-party reports at this stage and does let a third party check the numbers.

## Critical Assessment

**Attribution is the central problem: the paper's headline win is against its own backbone, and it never separates architecture from post-training.** Clover is literally "the text backbone of Qwen3.6-35B-A3B" (Section 3.1) with 740,160 new parameters added to it — 0.002% of 35B — and the 256-expert, width-2048 MoE shape, the 131K context and the 248,320 vocabulary all come from Qwen. The claim is then "Clover leads the seven evaluated agent metrics," and the comparison set in Table 1 includes exactly that backbone (SWE-bench Verified 73.6 vs 65.8, Terminal-Bench 2.1 51.7 vs 43.1). That is a legitimate comparison, but it does not identify a cause. A +7.8 on SWE-bench from an SFT-style adaptation is, if anything, more plausibly attributable to the corpus of agent trajectories and to the decoding policy that generates them than to a bidirectional attention slot inside a recurrent layer. The report notes it releases "supervised fine-tuning code," yet never says whether any RL stage was run — which matters enormously, because Qwen3.6 presumably has one and a pure-SFT adaptation beating it by 7.8 points on agentic coding is either a very strong result or a sign that the base/recipe differ in ways not disclosed. The corroborating evidence in the paper cuts against the architecture story too: the model gets *worse* than its backbone exactly on knowledge and competition math (HLE −8.4, AIME −7.1) while getting *better* on format-heavy, constraint-following, tool-use tasks (ZebraLogic +17.2, IFBench +11.0, AA-LCR +6.0, τ3 +4.4). That is the signature of capability redistribution under targeted post-training, not of a general representational improvement from block diffusion. The report does not acknowledge this inversion anywhere.

**There is not a single component ablation.** Four separate mechanisms are introduced — BD-GDN's shared-softmax history readout, the learnable block-size calibration c_h·log(N_b/32), the zero-initialized right-context convolution, and dMoE's block coreset — and none is ablated. Takeaway 1 is a pure assertion ("our architectural exploration led us to prioritize bidirectional interaction within Clover's current active block") with zero numbers attached, which is precisely the claim that needs evidence. The missing experiments are specific and cheap: history-readout-off (revert to plain block-diffusion causal prefix), c_h frozen at 0 or 1, right-taps-off (a 737K-parameter intervention that should be trivially ablatable), coreset vs token-level routing at matched speed, and a τ sweep measuring quality rather than throughput. The only sweep reported is over block size 4/8/16/32 — and that is a *sampled training hyperparameter*, not an ablation of the adaptation. The paper's own Eq. 12 derivation is the strongest argument in the whole methodology section, and it is never tested empirically even though a single run with c_h ∈ {0, 1, learned} would settle it.

**The objective is underspecified in ways that block reproduction.** Eq. 16 defines L = λ_BD·L_BD + λ_AR·L_AR and the surrounding text says only that "the coefficients λ_BD and λ_AR weight the two losses." No values, ever. The choice of λ_AR is not cosmetic: it controls how much of the pretrained causal capability survives the conversion, which is exactly the axis along which the observed agent-vs-knowledge trade-off runs, so omitting it removes the one hyperparameter most likely to explain the headline pattern. Equally absent: any description of the training corpus, token counts, data mixture for the agent trajectories and tool-use traces, whether RL was used, GPU-hours, total FLOPs, and how much of the Qwen3.6 checkpoint was frozen versus trained. The width-512 SwiGLU experts, the τ = 0.9 coreset fraction, the (10, 5, 1) init of (s_h, b_h, c_h), and δ = 0.6 are all pinned down precisely, which makes the silence on λ and on data/compute look like a deliberate boundary rather than an oversight — especially in a report that otherwise documents its engineering in unusual detail (FlexAttention metadata, FLA-KCP vs Ulysses sharding).

**The speed claim is workload-dependent, and the abstract quotes the best case.** The abstract's "680 tokens/s using one NVIDIA GB300" comes from a 64-prefix agent replay corpus, block 16, penalties and thinking controls enabled, single concurrency. The same paper's Table 2 shows the opposite sign on MATH-500: 465.2 tok/s versus 604.3 for Qwen3.6 + DFlash 2, a 23% *loss* despite committing more tokens per round (6.8743 vs 6.5897), because Clover pays a second full denoising pass to draft where an external drafter pays roughly a 1B-parameter forward. So the honest range across the three workloads is 356.7–604.3 tok/s relative to competitors, and Clover wins two of three. Figure 4 adds two more caveats the abstract drops: at *matched* block size 8 the advantage over DFlash 2 is 540.1 vs 485.5 (+11%, not +58%), with the 708.0 vs 448.7 headline coming partly from comparing against DFlash 2's own block-16 setting that the paper's note calls "experimental"; and the repetition penalty Clover needs because it "can sometimes produce repetitive outputs" costs 25% (708.0 → 531.5 tok/s). To their credit, Section 3.7 states outright that these are "system-level comparisons: different target models, verification trees, and decoding policies prevent isolating the effect of the drafting algorithm, and task success is not measured in replay." That sentence is the most honest one in the paper — and it is not in the abstract.

**Smaller but real defects.** No confidence intervals anywhere in the 18-benchmark table despite coding-agent tasks being averaged over only three runs; Terminal-Hard is 21 tasks, so 38.1 vs 31.8 is roughly a 1.3-task difference with no error bars. TTFT is explicitly not reported on the grounds that prefill is identical, which is arguable for a scheme whose whole point is extra drafting passes before the first committed token. The decision-model results (90.37 → 93.88, 22.0 → 76.0 complete-board) are on "internal sets [that] have been used repeatedly during development" by the authors' own admission, so they are capability checks, not measurements; the +1.73 on JevBench over 231 questions is a ~4-question difference and the +0.30 on Decision Index is noise. Table 3 mixes in-house runs with numbers lifted from other vendors' reports across different coding-agent harnesses (Codex vs OpenCode vs NVIDIA's); the notes are commendably explicit about this, but the "Clover leads" reading does not survive it — LFM2.5 at 24B-A2B beats Clover on IFBench 74.7 vs 72.3, and Gemma 4 at 26B-A4B beats it on IFBench (77.2), HLE (17.2) and LiveCodeBench (77.1). Finally, the whole quantized-deployment comparison rests on MATH-500, a benchmark where every configuration scores 93.8–97.6%, leaving almost no headroom to detect damage from INT4 or from top-6 verification.

## Strengths

- **The architecture idea is genuinely good, not a repackaging.** Making the compressed history readout a single competitor inside the same softmax as the block tokens, rather than concatenating it or adding it as a bias, is the cleanest formulation of "read the past cheaply, read the present fully" that this literature has produced. It also makes the block-size dilution problem visible — which is what motivates the calibration term.
- **Eq. 12 is a correct and non-obvious observation.** A fixed history bias does systematically starve the prefix as N_b grows, because history holds one slot while competitors multiply; the log(N_b/N_ref) correction and c_h = 1 default are principled rather than tuned.
- **The intervention is honest about cost.** 737,280 right-kernel parameters plus 2,880 scalars, with right taps initialized to zero so the model is numerically its pretrained self at step 0 — a conversion that cannot have broken the checkpoint on day one. That is disciplined engineering.
- **It reports a benchmark where it loses.** Section 3.7 shows MATH-500 throughput below DFlash 2 and explains why (drafting cost), rather than quietly dropping the row. Table 2 and Figure 4 both keep the unfavorable numbers.
- **The measurement definitions are unusually careful.** Eq. 18 defines committed tokens per round and decode TPS as cumulative ratios rather than averages of per-request rates; the agent replay corpus construction is stated deterministically (64 prefixes, one per trajectory, alternating 8K/16K targets); body-only throughput explicitly excludes thinking tokens and time, and the paper warns that the two metrics "cover different output phases and should be interpreted separately."
- **The on-device result is the most useful thing in the report.** Routing-statistics-informed expert placement gives 66.64 → 97.52 tok/s at no accuracy cost (96.8 → 97.6% on MATH-500) on a 16GB RTX 5070 Ti, roughly 2× the throughput of MiniCPM-V 4.7 and Qwen3.6-35B-A3B on the same box. That is a concrete, checkable, practically valuable claim, and it does not depend on the agent-benchmark narrative at all.
- **A real release.** Weights, SFT code and inference engine, plus an honest acknowledgment that the decision model is "planned for a subsequent release" rather than pretending it shipped.

## Limitations

- No component ablation of BD-GDN, the block-size calibration, the right-context convolution, or dMoE — so the architectural contribution is asserted, not demonstrated.
- λ_BD and λ_AR are never given; no data mixture, token counts, compute budget, RL disclosure, or frozen-vs-trained split.
- The model regresses against its own backbone on HLE (−8.4) and AIME 2026 (−7.1) with no discussion of why or whether that is acceptable for the intended agentic use case.
- Speed is reported as workloads allow: the abstract quotes 680 tok/s (GB300, agent replay, penalized config) without the MATH-500 loss or the matched-block-size caveat.
- No variance or confidence intervals on any of the 18 benchmarks; three-run means for coding agents, 21 tasks for Terminal-Hard, no per-task breakdown.
- Agent replay "measures inference speed, not a complete agent rollout or task success" by the authors' own statement, so no end-to-end agent latency or cost-per-resolved-task is reported.
- Decision-model gains rest on internal sets reused throughout development; the external margins (JevBench +1.7, Decision Index +0.30) are within noise.
- Table 3 mixes harnesses and sources across vendors; the comparative claims there are weaker than the table's bold formatting implies.
- Quantized deployment is validated only on MATH-500, where accuracy is nearly saturated.
- "Preview" status: no statement of what is missing relative to the intended final model, and multimodal capability and longer context are listed as future work.

## Relevance

对关注离散扩散语言模型工程化落地（块扩散 + 混合专家 + 自投机解码）的读者高度相关：它给出了"如何把预训练 AR 主干改成块扩散而只动 0.002% 参数"的具体配方，以及单卡 16GB 上 97 tok/s 的可复现实测。对 agentic coding（SWE-bench / Terminal-Bench）方向也有直接参考价值，但引用其"七项 agent 指标全面领先"的结论时必须同时引用 HLE 掉 8.4 分、MATH-500 吞吐落后 23% 这两条，并注意全文没有任何消融能证明这是架构的功劳。

## Questions for Further Exploration

1. What are λ_BD and λ_AR, and how sensitive is the agent-vs-knowledge trade-off to λ_AR? A sweep would directly test whether the HLE regression is a diffusion-objective cost or a data-mix artifact.
2. If you ablate the history readout (plain block diffusion over the causal prefix), the learned c_h (frozen at 0 or 1), and the 737K right taps one at a time, how much of the +7.8 SWE-bench survives? My prior is that most of it does, and that the right-tap ablation in particular will be within noise.
3. Was any RL or preference optimization applied? If the answer is "SFT only," beating Qwen3.6 on agentic coding deserves a much louder claim than the report makes; if the answer is "yes, on agent trajectories," the architecture story needs to be scaled back accordingly.
4. How much of the 248K vocabulary and 131K context were actually exercised during the conversion training, and how much of the pretrained checkpoint was frozen? A frozen-vs-full comparison would separate "adaptation" from "continued pretraining."
5. Why does the split-K/GDN verification pass not increase TTFT before the first committed token, and what is the actual end-to-end latency including drafting on the MATH-500 workload where throughput is 23% worse?
6. Does the block-size calibration term c_h converge to 1 (exact compensation), or does it learn something workload-specific? Publishing the learned c_h per head per layer would be a cheap, unusually informative diagnostic.
7. What is cost-per-resolved-task on SWE-bench for Clover vs Qwen3.6 + DFlash 2, once the 680 tok/s replay number is replaced by measured rollout time including tool-call round trips?
