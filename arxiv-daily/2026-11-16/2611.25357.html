Track the problem, not the code.

An autonomous research agent's primary state should be an explicit map of performance bottlenecks, candidate fixes and their belief scores — revised by one-variable, Git-branched experiments before any commit is kept.

Any-Medal on the complete 75-task MLE-Bench at 48 h — the highest reported, +5.3 pts over AIBuildAI-2. At 24 h it reaches 70.7%, a tie.

Why this matters

Makes long-horizon agent research auditable and falsifiable — and its resolved / resource-limited / unresolved labels show when an agent should stop.

Critical edge

For a paper whose thesis is that the state is the contribution, no code, prompts, state artifacts or trajectories are released — the central claim stays unfalsifiable.

01Method — probe, test, then engineer

Three phases; only the first two are allowed to change the model.

St = { Pi, Epi, { Ci,j, bi,j, Eci,j } }  ⟷  Git snapshot Mt
  1. 01

    Probe — profile before planning

    Diagnostic scripts on raw tensors measure real latency, memory footprint and structural signals, then extrapolate to full-dataset scale against the compute bound. The result is a bottleneck list (OOM risk, I/O starvation, resolution loss, class imbalance). Each bottleneck becomes a targeted literature query that seeds candidate solutions with prior beliefs. Baseline M₀ is built under those constraints and must clear a memory / GPU-efficiency / loss-stability gate.

  2. 02

    Explore — one variable at a time

    Best-first search over a hypothesis tree, prioritised by b/(N+1) so repeatedly failed bottlenecks lose priority. Each hypothesis forks a hypothesis/Ht branch; the Reviewer rejects any diff that touches more than one variable. Blind HTTP grading returns Δh: keep the branch and raise belief, or hard-rollback and lower it. Telemetry re-scores the still-unexecuted queue.

  3. 03

    Engineer — cheapest accuracy

    MCTS/UCT from the best scientific snapshot, rewarding Δh − γ·ln Texec so wall-clock is priced in. A diff firewall forbids edits to model, algorithm or data, so tuning cannot quietly become a new experiment.

02The loop around it

Deliberately split models — a lighter one does the work.

  • PI · Gemini 3.1 ProSets goals and budgets, inspects the trajectory every 10 steps.
  • IMPLEMENTATION · Gemini 3.5 FlashReAct agent with file and diagnostic tools; writes the diffs.
  • REVIEWER · Gemini 3.5 FlashGates every launch: single-variable compliance, anti-cheat, and the Phase-3 invariance constraint.
  • EXPERIENCE BANKError signature → root cause → verified fix, queried before each mutation and written after each novel fault.
  • GRADINGOutside the sandbox, via an HTTP service with isolated ground-truth labels — no self-grading, no target leakage.

Budget is partitioned across preprocessing / training / blind evaluation, with a sentinel that halts on NaN or diverging loss and kills stalled I/O.

Strengths

  • The formalism pays rent. A 6.1-point static-vs-full final gap with near-identical starts cleanly separates “plan better” from “revise better”.
  • Hygiene enforced in code. The single-variable Reviewer and the Phase-3 diff firewall are constraints, not prompt suggestions — the most copyable part.
  • Grading outside the sandbox. Isolated labels over HTTP, plus exclusion of test-set-feedback submissions, closes the obvious cheating channel.
  • Unusually honest tables. It volunteers MARS+'s higher gold rate, the 24 h tie, and two of four case studies as failures.

Limitations

  • Nothing released. No code, prompts, state artifacts or trajectories, on proprietary Gemini 3.x backbones — replication is impossible in principle.
  • One run per budget. The 24→48 h “+5.3 pts” is four medals, well inside the ±5-pt run-to-run noise the Lite split implies.
  • Baseline integrity. MARS is compared across a different backbone and unshared node roots; the no-state control is a 2.1-minute-init strawman.
  • No cost accounting. Beliefs update by fixed ±Δb (a priority queue, not a posterior), and only two benchmarks are covered.

07Questions for further exploration

  1. Is the 24→48 h gain Problem Probing, or just 2× wall-clock on a system that never saturates?
  2. What is the LLM inference cost per medal in tokens and dollars, versus MARS+ and AIBuildAI-2?
  3. Does the PI / Implementation split matter, or would one strong model with the same state do as well?
  4. Would a calibrated Beta-Bernoulli belief update beat the ±Δb priority queue?
  5. Do independent human annotators agree with the resolved / resource-limited / unresolved labels?
  6. How much comes from retrieval conditioned on a diagnosed bottleneck, rather than ordinary pre-task search?
