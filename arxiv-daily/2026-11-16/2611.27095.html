Why it matters

Silent agent failures live between the wire and the words: the tool errored, the reply says “done”. Signed receipts make that gap visible and auditable.

让“工具真的执行了”成为可验证的事实，而不只是模型的自述。

Critical edge · read before citing

The 93.2% comes from an author-labelled frozen cohort; on 60 live traces accuracy falls to 76.67% with a 38.24% false-positive rate, and the edge over GPU judges is no longer significant (p=0.79).

two in five benign turns would be sent back for retry

How it works 方法

An out-of-process stdio proxy owns the signing key; supervision happens after the turn, outside the generation prompt.

01 Intercept mcp-proxy parents every tool server and correlates JSON-RPC calls by id.
02 Sign Ed25519 receipt appended to an RFC 6962 Merkle log; chain links every entry.
03 Read the prose Speech-act filter drops negation, quotes, code; an INT8 encoder flags “completed side effect” claims.
04 Reconcile Gate checks signature, session and target; mismatch returns a verdict plus a retry prompt with char offsets.

ToolReceipt · executed · ok · args · sig  →  entry · seq · session_id · leaf_sha256 · prev_chain_sha256 · merkle_root

  • Key never enters the agent. Signing env vars are stripped before each child server spawns, so an injected server cannot forge a receipt.
  • Hybrid symbolic–neural, two stages. Only the 82.67 MB action_claim model loads for supervision (the four-model bundle is 279.48 MB); cold start 921.8 ms.
  • Memory is gated at the SQLite boundary. HKDF-SHA256 derives five Ed25519 keys across seven provenance domains — narration has no signing constructor at all — and triggers abort in-place UPDATE/DELETE.
  • Engineered for portability. 58/58 AER-1 ingestion vectors and 50/50 exports; 15 typed modules under mypy --strict with an enforced import-layer contract.

Four wire states 线上四态

“Executed and failed” and “never happened” license different prose. Most firewalls collapse them.

StateexecutedokGrounds “done”?
Normal✓✓yes
Tool error result.isError = true✓✗no
Pre-execution reject -32700 / -32602 / schema✗✗no
Crash or EOF✓*✗no

*Unknown and non-standard error codes default to executed=true, ok=false — fail closed, so a failure can never support a success claim.

Receipts bind a claim to a signed record; a validly signed lie from a malicious server is explicitly out of scope.

Strengths 优点

  • Isolation is structural, not documented. No constructor exists for narration or untrusted tool content, so even a buggy caller cannot sign prose.
  • The ablation names the mechanism. Stage-2 receipt binding is worth +18.34 pp on live traces (p=0.001), not just an aggregate score.
  • The crypto path earns its keep. 200/200 payload mutations rejected, 0.0% false rejection across 200 authorized writes, 0 key leaks in 40 wire calls.
  • Reproducibility with receipts. osaudit manifests, SHA-256-pinned INT8 weights, Hugging Face corpora with OpenTimestamps, MIT code.
  • Negative results published. Syndication dedup falls from 100% to 0% under paraphrase, and a 3-item hardening regression is reported rather than hidden.

Limitations 局限

  • The baselines are soft. GPU judges get one fixed 3-rule prompt, no few-shot, no chain-of-thought; frontier API judges are omitted for cost. “+6.4 pp” means “beats a lightly prompted 12B”.
  • Labels are circular. Benchmark, failure taxonomy and fine-tuned encoder share one author, and the set was frozen with v0.3.0 weights. No multi-human κ study.
  • Transfer is worse than the abstract. 76.67% / 38.24% FPR on live traces; the symbolic layer depends on a hand-maintained tool vocabulary.
  • Coverage is assumed. stdio only, and complete mediation needs no unproxied shell, HTTP or code side channel — which most harnesses have by default.
  • No task-level evaluation. Nothing measures what the 38.24% FPR costs in retries, tokens or task success; single-author, non-peer-reviewed, 5/25 self-citations.

Open questions 待解

What a follow-up, or a skeptical reader, would want measured next.

  1. How much of the +6.4/+6.8 pp survives few-shot, chain-of-thought or per-cohort calibration — and what happens against a frontier API judge at equal cost?
  2. Can the 100.0% on locked_coh_50 be reproduced by an annotator who has never read the author’s speech-act taxonomy?
  3. What does a 38.24% live FPR cost in task success, tokens and wall-clock once to_retry_prompt() is wired into a loop?
  4. How does it hold against an adversary who paraphrases syndicated sources (the 0.0% tier) and avoids naming concrete tool targets?
  5. Can the Merkle log detect cross-session memory poisoning after the fact, or only block it at write time?
  6. What fraction of real agent harnesses can satisfy complete mediation when shell tools, interpreters and built-in HTTP clients are standard?
