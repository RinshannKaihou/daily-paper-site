2611.22426 · looped transformers · 16 Nov 2026

Parallel looped transformers throw away the cross-trajectory states their own schedule has already finished. InfuseLoop routes them back in as one attention residual.

并行循环 Transformer 每个循环边界只回传同一条轨迹的前一状态，把并行调度早已算完的其他轨迹隐状态全部丢弃；InfuseLoop 用一层带学习伪 query 的注意力残差把这些状态注入当前循环，八循环下游平均 +0.84 分，解码只慢 0.3%。

Key metric

−17.1%

LAMBADA final-word perplexity at 8 loops: 50.69 → 42.04, vanilla PLT to InfuseLoop.

WikiText-2 −3.4% (36.82 → 35.55) · 7-task mean +0.84 pts · decode +0.3%

Why it matters

It traces the loss spikes that appear at only four loops to one missing edge in the compute graph — and repairs it without breaking causality.

Critical edge

The headline 17.1% comes entirely from LAMBADA, a last-token metric measured on the one loop that receives the most injected state; WikiText-2 moves just 3.4%.

Mechanism

One missing edge, read from the schedule

0.6B Qwen3-style backbone, R = 4 / 8 loops, shared weights

Diagnosis
At every loop boundary PLT passes h(r−1) only — the same trajectory one loop back — while the overlapped schedule has already produced r−1 other outputs on later trajectories. Depth scaling stalls on an information-flow gap, not just on diminishing refinement.
Source set
Receiver h(r)t draws on { h(j)t+r−j−1 : 1 ≤ j < r }: the in-trajectory base plus r−2 completed Post states from the immediately preceding cycle. Admissible Pre states are ≥ 2 cycles old and are excluded (ablation confirms staleness hurts).
Aggregation
A learned pseudo-query per loop, parameter-free RMSNorm on sources, per-source bias, zero residual when the set is empty, document boundaries masked pre-softmax. The first loop is untouched, so injection starts at r = 3.
m(r) = ρr · Σj<r αt,j→r · RMSNorm( h(j)t+r−j−1 )
 h(r)t = Fθ( Embed(xt−R+r) + m(r)t )

Validation loss, 6B FineWeb-Edu tokens

61% of the PLT→LT gap at R=4, 52% at R=8 — still 0.59 accuracy points behind sequential LT-8.
Spikes
Vanilla PLT spikes "with as few as four loops"; both InfuseLoop curves are spike-free. No spike counts or magnitudes reported.

Verdict

Strengths

  • The diagnosis is checkable. "Only the preceding in-trajectory state crosses the boundary, although r−1 causally available states exist" is a statement about the graph, not an appeal to saturation.
  • System constraints shaped the design — previous-cycle-only sources, per-loop query, document masking, zero-residual fallback — not benchmark maximisation.
  • Appendix A is unusually careful: separate availability and prefix-causality lemmas, an explicit training ≡ decoding theorem, and a scope note that these are consistency, not expressivity, results.
  • Efficiency is measured, not asserted — kernel-time breakdown, throughput, per-token cache at three context lengths, arithmetic intensity.
  • The ablation is informative in a non-flattering direction: a bigger source set hurts.

Limitations

  • One operating point: a single 0.6B dense backbone, 6B tokens, 1,024-token sequences, one dataset. The central claim rests there.
  • No seeds, no error bars; the stability claim rests on visual inspection of two loss curves.
  • No compute-matched control. R=8 sees ~8× the backbone FLOPs of Single; a Single trained on 8× tokens, or a larger non-looped model at matched inference FLOPs, is absent.
  • Stabilisation is under-ablated. Component ablations run at 1B tokens, where spikes do not occur; dropping looping normalization shows no harm (3.2482 vs 3.2436).
  • G-SWA (w=64) is inherited and never ablated, though injected states carry exactly the long-range information the window drops.
  • Still behind sequential LT (0.028 nats, 0.59 pts at R=8) with no explanation offered.
  1. Headline range driven by a benchmark structurally aligned with the mechanism
  2. No seeds or error bars for any table entry
  3. No compute-matched non-looped control
  4. Ablations at 1/6 the main budget, in the regime where the failure never appears
  5. Baseline fidelity unstated — no confirmation PLT reproduces the original numbers

Open questions

  1. Does the WikiText-2 gain over vanilla PLT survive 60B tokens and a decayed LR schedule?
  2. Why is the LAMBADA gap so much larger than every other benchmark? A per-position perplexity breakdown would test the "final-loop enrichment" story.
  3. What if the query wr is shared across loops, or sources are weighted by loop index — routing, or just extra capacity?
  4. Is the FullState degradation softmax dilution? A fixed uniform average over O(R²) candidates would separate the two.
  5. How does the mechanism interact with G-SWA window size?
  6. At matched inference FLOPs, how does InfuseLoop-8 compare with a ~1.6B non-looped model?
