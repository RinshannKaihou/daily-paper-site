> **一句话总结：** 上海 AI Lab 联合复旦等机构发布 320B MoE 模型 Sage S2.1 Flash，用冻结的科学编码器（MoleculeSTM / ESM-2 / DNABERT-2 / RNA-FM）+ 可训练投影器把分子图、序列、谱图接入语言主干，再用 ToolSpace 等可验证环境做 agent 后训练，在 33 个基准中拿下 OfficeQA Pro（72.2）、MLE-bench Lite（90.3 HumanRank）、Harvey LAB（25.0）、SpreadsheetBench 2（37.1）四项第一，但在仓库级编码与部分视觉基准上落后 Claude Opus 5 达 16–23 分。

> **TL;DR:** A 320B-parameter MoE "science + agent" flagship from Shanghai AI Lab. Its scientific contribution is modular and cheap to copy — frozen domain encoders (MoleculeSTM, ESM-2, DNABERT-2, RNA-FM, Diffspectra-style spectral patching) feed trainable projectors into an otherwise frozen-language-model interface, tuned by GRPO on verifiable scientific rewards. Its agentic contribution is heavier: ToolSpace synthesizes cross-environment long-horizon tool tasks (77,760 tool-call pattern nodes, 2,042 tools, 804 environments, mean 18.86 calls per trajectory) with replay-verified state checks. On 33 benchmarks it beats the five primary baselines on MLE-bench Lite (90.3 vs 89.2 DeepSeek-V4.1-Flash, +1.1 HumanRank), OfficeQA Pro (72.2 vs 69.7, +2.5) and Harvey LAB (25.0 vs 24.2 Qwen3.8-Max, +0.8), but loses SWE-bench Pro by 15.9 points (60.6 vs 76.5 Claude Opus 5) and NL2Repo-Bench by 22.7 (57.2 vs 79.9) — read it for the data-synthesis pipeline, not for the headline "frontier" claim.

## 核心贡献

- **统一的科学感知接口 Sage Sci-Perception**：为分子图（MoleculeSTM）、蛋白序列（ESM-2）、DNA（DNABERT-2）、RNA（RNA-FM）配专用编码器，谱图（质谱/XRD/ECG/EEG/光变曲线）则按 Diffspectra 的数值分块（numerical patching）方案切成本地 patch；每个模态一个投影器，把「本地特征 + 身份/位置嵌入（+ 可选 side / readout 分支 + 对象内 context 残差）」映射进语言主干嵌入空间。
- **科学接口的强化学习适配**：编码器与语言主干全部冻结，只训投影器；用 GRPO 以可验证科学结果（分类正确性、位点/集合重叠、数值容差、化学等价性）为奖励，并混入「关于输入证据本身」的辅助问答（数原子、查图关系、比较测量值）来迫使接口暴露证据。
- **ToolSpace 跨环境 agent 数据合成**：把工具当作原子单位，从真实 MCP / Web 轨迹恢复工具组合图（数据依赖 / 状态依赖 / 重试依赖三类边），再做状态感知随机游走 + 反向任务合成 + 回放验证，产出可执行、可校验的长程任务；规模为 77,760 个工具调用模式节点、2,042 个归一化工具、804 个环境。
- **六大类可验证环境的规模化**（工具使用、搜索、Agentic Coding、ML Coding、网络安全、Workspace 交付物、视觉 CUA），统一以「执行结果 / 环境状态 / 提交产物」而非自报完成度作为检查依据，并显式做了 reward hacking 防护（清除泄漏 Git 历史、权限隔离、轨迹-产物一致性检查）。
- **33 个基准、七大类能力的完整对照表**（含 5 个主基线 + 3 个公开参考列），并附一份 48 对配对轨迹的定性分析，指出「同分不同质」——差别常出现在验证覆盖度与产物一致性上。

## Key Contributions

- **Sage Sci-Perception**: a modality-agnostic interface where frozen scientific encoders plus deterministic numerical patching produce local states, and a per-modality projector injects them into a shared MoE backbone's embedding space. Identity/position embeddings are concatenated explicitly so that residue-level or atom-level questions remain answerable.
- **Scientific RL adapter**: GRPO is applied to the projectors only (encoders and backbone frozen), with task-specific verifiers for classification, site/set overlap, numerical tolerance, and chemical equivalence; auxiliary evidence-probing questions share each scientific input to test whether the interface actually exposes the evidence.
- **ToolSpace**: a tool-centric synthesis framework that reconstructs a typed tool-composition graph from real execution traces, materializes only the environments needed for persistent state, and generates long-horizon tasks by state-aware random walks plus reverse instruction/verifier synthesis, keeping only tasks that replay successfully.
- **Environment scaling recipes** for search (forward synthesis from knowledge graphs + reverse synthesis from seed-query structures), agentic coding (SWE-smith / SWE-rebench V2 / OpenSWE / SWE-Lego / TMax / SETA plus mined commits), ML coding (4,936 Kaggle sources, 2,960 papers, versioned data–code pairs with controlled degradation), cybersecurity (differential vulnerable-vs-patched validation), workspace deliverables (presentations, spreadsheets, CAD, Blender), and visual CUA (perception→grounding→long-horizon curriculum).
- **A paired-trajectory analysis protocol** (coordinator / analyzer / counter-reviewer / cycle synthesis) over 48 paired runs, used to argue that benchmark scores hide differences in verification breadth and artifact fidelity.

## Methodology

**Architecture.** Sage S2.1 Flash is a 320B-parameter MoE with sparse-plus-linear attention for long context; the paper does not disclose active-parameter count, expert count, or pre-training token budget. Notably, the backbone sentence cites the GLM-5.3-Flash model card ([12]), suggesting the base model may be initialized from one of its own baselines — the report never says this explicitly.

**Scientific representations.** For modality $m$, an encoder (or patching procedure) yields $H^m \in \mathbb{R}^{N_m \times d_m}$ whose rows are atoms, residues, segments, or numerical windows. A projector $P_m$ combines each row with a learned identity embedding, applies LayerNorm → Linear → GELU → Linear, optionally adds side (time/channel/scale) and readout (predicted scores) contributions, then a residual context-exchange step lets states of the same scientific object share information: $S_m = P_m(H_m, I_m, A_m) \in \mathbb{R}^{N_m \times d_{LM}}$. One projector per modality serves all tasks in that modality; the operation is disambiguated by the instruction text.

**Post-training.** General agent capabilities come from verifiable environments trained with XTuner. ToolSpace supplies the tool-use data: trajectory corpus from MCP executions and web trajectories (three authenticity tiers), a typed tool graph with frequency-weighted edges and value-transfer checks to avoid spurious "shared constant" links, environment materialization (operation / state-query / stateless), then state-aware walks with rollback sampling and reverse task synthesis with verifier scripts; teacher agents solve tasks and only trajectories passing the same verification are kept. Search data uses cyclic knowledge graphs (main reasoning chain + auxiliary constraints + withheld answer relation, names replaced by descriptions, exact values replaced by ranges) plus reverse synthesis from seed-query structures; an independent model checks answer uniqueness, leakage, and shortcuts. Coding data spans SWE, terminal, and web-development tracks with containerized reproducible environments, negative controls (deliberately wrong solutions must fail), judge agents, and explicit anti-leakage sweeps. ML-coding tasks are built from versioned data–code pairs with the target computation masked; cybersecurity tasks require a vulnerability to trigger only in the vulnerable build and not in the patched one, with solver/target/evaluator separated into distinct permission domains. Scientific projectors are then refined with GRPO on verifiable scientific rewards, with one checkpoint selected per modality by a prespecified multitask criterion.

**Evaluation.** 33 benchmarks in seven domains (Agentic Coding, Productivity, Tool Use, ML Engineering, Deep Research, Search, Vision) against GLM-5.3-Flash, DeepSeek-V4.1-Flash-1017, Qwen3.8-Max, GPT-5.6 Sol, and Claude Opus 5, plus three published-only reference columns (GPT-6 Astra, GPT-6.1 Sol, Claude Opus 5.5) excluded from ranking. Appendix B documents per-benchmark harnesses, timeouts, and judges.

## Results & Highlights

- **MLE-bench Lite (HumanRank, Claude Code harness, 12h/run): 90.3 vs 89.2 for DeepSeek-V4.1-Flash (+1.1), 88.0 for Claude Opus 5 (+2.3), 84.3 for GLM-5.3-Flash (+6.0), and 80.7 for GPT-5.6 Sol (+9.6)** — the single largest first-place margin among the four wins, though HumanRank is a non-standard "percentage of human leaderboard surpassed" metric (following Frontis-MA1) rather than MLE-bench's usual medal rate, so cross-paper comparison is unsafe.
- **OfficeQA Pro (133 tasks, zero-tolerance exact match, Claude Code): 72.2 vs 69.7 DeepSeek-V4.1-Flash (+2.5), 67.2 Claude Opus 5 (+5.0), 66.4 GPT-5.6 Sol (+5.8), 66.2 Qwen3.8-Max (+6.0), 64.7 GLM-5.3-Flash (+7.5)** — a clean, harness-matched win on document-evidence extraction, the most defensible result in the table.
- **Harvey LAB (120-task subsample of 1,200, all-rubric-criteria-must-pass, GLM-5.2 judge): 25.0 vs 24.2 Qwen3.8-Max (+0.8), 22.7 Claude Opus 5 (+2.3), 20.0 GLM-5.3-Flash (+5.0), 11.7 DeepSeek-V4.1-Flash (+13.3), 5.0 GPT-5.6 Sol (+20.0)** — first place, but the top-2 gap is 0.8 points on 120 tasks, i.e. roughly one task.
- **SpreadsheetBench 2 (321 tasks, weighted accuracy, Qwen3.7-plus VLM verifier for charts): 37.1 vs 35.8 DeepSeek-V4.1-Flash (+1.3), 34.9 Qwen3.8-Max (+2.2), 33.6 Claude Opus 5 (+3.5), 32.7 GPT-5.6 Sol (+4.4), 32.4 GLM-5.3-Flash (+4.7)** — absolute performance is low for every model (<40%), so the "verifiable workbooks" claim rests on a narrow band.
- **Terminal-Bench 2.1: 87.9 vs 87.6 DeepSeek-V4.1-Flash (+0.3) and 84.3 GLM-5.3-Flash (+3.6), but 89.6 Qwen3.8-Max (−1.7) and 90.2 Claude Opus 5 (−2.3)** — a third-place finish that the abstract's "competitive in terminal execution" phrasing softens.
- **Repository-level coding is the clearest weakness: SWE-bench Pro 60.6 vs 76.5 Claude Opus 5 (−15.9) and 61.8 DeepSeek-V4.1-Flash (−1.2); NL2Repo-Bench 57.2 vs 79.9 Claude Opus 5 (−22.7) and 63.2 Qwen3.8-Max (−6.0); DeepSWE 67.9 vs 74.1 GPT-6 Astra (−6.2) and 72.6 Claude Opus 5 (−4.7)**.
- **Vision is mixed rather than strong: OSWorld-Verified 85.2 (second, −1.2 vs Claude Opus 5's 86.4) and WebArena-Verified 67.6 (second, −1.5 vs 69.1), but WeaveBench 68.4 vs 86.4 Claude Opus 5 (−18.0), BabyVision 75.8 vs 83.8 Qwen3.8-Max (−8.0), OSWorld-G 84.8 vs 88.6 Qwen3.8-Max (−3.8)** — the headline "acts on visual feedback" claim is contradicted by three of six vision rows.
- **Search/deep research are near-miss second places: DeepResearch Bench II 54.2 vs 55.1 DeepSeek-V4.1-Flash (−0.9), BrowseComp 91.2 vs 93.8 (−2.6), WideSearch 81.5 vs 86.3 (−4.8), DeepSearchQA 94.4 vs 95.3 (−0.9)**; the paper's own conclusion concedes "room to improve in … web search".
- **Tool-use spread is uneven: BFCL V4 75.5 vs 80.6 Claude Opus 5 (−5.1), JobBench 58.8 vs 68.0 (−9.2), τ3-bench Banking 45.4 vs 55.2 Qwen3.8-Max (−9.8), while AutomationBench 56.7 vs 57.8 DeepSeek (−1.1) is close**.
- **PostTrainBench 39.2 leads among primary baselines (vs 36.8 GLM-5.3-Flash, 35.7 Claude Opus 5, 31.0 GPT-5.6 Sol)** but trails the published GPT-6 Astra (41.9) and Claude Opus 5.5 (43.8), and its own score comes from in-house runs while baselines come from the official leaderboard.
- **Data-scale numbers worth quoting**: ToolSpace SFT trajectories average 18.86 tool calls (max 209) spanning 2.29 environments (max 22), minimum 5 calls; ML-coding inventory includes 4,936 Kaggle sources, 2,960 research papers, 129 Hugging Face datasets, 11 base-model cards.
- **Application demos (qualitative only)**: recover 139 slices out of 12,487 mixed CT images and rebuild them in 3D Slicer; produce an editable Blender model of the Pujiang building, a parametric turbofan engine, and a truck chassis in CAD; run Fiji / EEGLAB / QGIS analyses; build an interactive HTML explainer around a 62%-efficiency optical quantum-memory experiment.

## Authors & Credibility

The author list is the collective "Sage S2.1 Flash Team" with core contributors named in Appendix A — a large Shanghai AI Laboratory / InternLM-lineage effort with Fudan (Tao Gui, Qi Zhang as corresponding authors) and co-authorship from ISCAS, Renmin, CASIA, ECNU, HIT, and PKU. Credibility markers are real: a public homepage, GitHub org (InternLM/Sage-S2.1-Flash), a promised Hugging Face release, and reuse of the group's own infrastructure (XTuner, ToolSpace, Sage-SciPerception repo). The report is unusually candid in places — it admits reward-hacking residuals ("an agent accessing task-related repository content through dependencies installed by the harness itself"), reports a case where its own model produced inconsistent counts in a HelpScout report, and concedes weakness in repo-level coding and web search. That candor raises trust in the negative results more than the positive ones.

## Critical Assessment

**Novelty.** The scientific-input machinery is competent engineering, not new science: MoleculeSTM, ESM-2, DNABERT-2, RNA-FM, and Diffspectra's patching scheme are all off-the-shelf, and the "identity embedding + LN-Linear-GELU-Linear + context residual" projector is a straightforward LLaVA-style adapter with extra branches. The genuinely interesting idea is training *only* the projector with GRPO on verifiable scientific rewards while both the encoders and the language backbone stay frozen — a cheap, well-scoped adaptation story. ToolSpace's typed tool-composition graph with data/state/retry edge semantics and rollback-based walk repair is the stronger contribution, but it is largely a restatement of the authors' own prior arXiv 2611.05036 and is cited as such.

**The central gap: no scientific benchmark.** The paper brands itself "science-first" yet Table 2 contains **zero** scientific benchmarks — no molecular property prediction, no protein function or structure task, no spectra elucidation, no macro-F1 or correlation number anywhere, despite Section 3.2.2 explicitly saying formal evaluation "retains native dataset-level metrics such as macro-F1 and correlation." The scientific capability is evidenced only by five unreviewed application demos (Section 5) with no baselines, no success criteria, and no repeated trials. A reader cannot tell whether Sci-Perception beats simply captioning a molecule as SMILES text. There is also **no ablation of the interface at all** — no w/o-projector, no w/o-identity-embedding, no w/o-GRPO comparison — so the claimed benefit of the whole scientific branch is unmeasured.

**Harness asymmetry is the biggest threat to the agentic numbers.** In several rows Sage S2.1 Flash and GLM-5.3-Flash run under Claude Code while DeepSeek-V4.1-Flash, Qwen3.8-Max, GPT-5.6 Sol, and Claude Opus 5 run under OpenHands (NL2Repo-Bench, SWE-bench Pro, GDPval); on Terminal-Bench 2.1 every model runs Claude Code but Sage is additionally given a 512K context window, 64K output per generation, and max thinking effort. Multi-run averaging is inconsistent too: four runs on Terminal-Bench 2.1 and DeepSWE, but effectively single reporting elsewhere, and OLMo-style variance on a 120-task Harvey LAB subsample (25.0 vs 24.2) is well inside noise. Judges are also heterogeneous and sometimes weak proxies — GLM-5.2 judging GDPval against Claude Opus 4.8 deliverables, GLM-5.2 again on Harvey LAB, Grok-4.3 on JobBench, doubao-seed-2-1-lite on Workspace-Bench — with no human agreement study.

**Metric substitution.** MLE-bench Lite is reported as "HumanRank" following Frontis-MA1 rather than the benchmark's standard medal-rate/any-medal metric, which makes the 90.3 headline incomparable to published MLE-bench numbers and to the same authors' own claim of "+9.6 over GPT-5.6 Sol" if that baseline was scored under a different protocol. PostTrainBench mixes in-house Sage runs with official-leaderboard baseline scores in one column.

**Overclaiming relative to the table.** The abstract foregrounds four first places and three second places but never states that the model is behind on roughly a dozen rows, including three by double digits (SWE-bench Pro −15.9, NL2Repo-Bench −22.7, WeaveBench −18.0) and PaperBench −7.1 vs Qwen3.8-Max. Describing the profile as "competitive in desktop and browser workflows" is fair; describing a 320B flagship as broadly "frontier" is not supported by rows where a same-size competitor wins by 20 points. The trajectory analysis, while methodologically careful, is **purely qualitative on 48 hand-paired runs with no win/loss counts, no significance test, and pairing chosen by the authors** — it illustrates mechanisms but cannot support a capability claim.

**Red flag worth flagging neutrally.** The backbone is introduced with a citation to the GLM-5.3-Flash model card, which is also one of the five baselines and loses to Sage on 20+ rows. If Sage is initialized from that model, several "wins" are post-training deltas rather than architecture wins, and the paper should say so explicitly.

## Strengths

- The verifiable-environment design is the most reusable part: state-based and artifact-based checking, differential vulnerable-vs-patched validation for security tasks, negative controls (deliberately wrong solutions must fail), and a public/private split that keeps scoring scripts out of the agent's context.
- Honest, specific reward-hacking discussion, including a concrete leakage channel the authors discovered in their own harness and the mitigation they adopted (behavioral review of recorded tool access, not just static scans).
- Clean, modular scientific interface: one projector per modality, task disambiguated by instruction rather than by separate heads, encoders swappable — easy to reproduce on a smaller backbone, which is exactly what an academic lab would want.
- GRPO-on-frozen-backbone is a cheap and sensible way to adapt a scientific interface without catastrophic forgetting of language skills; the auxiliary evidence-probing questions are a nice diagnostic idea.
- Appendix B is far more detailed than typical technical reports: per-benchmark harness, timeouts, step caps, judge identity, and explicit flagging that published reference columns use different settings.
- Candor about its own failures (HelpScout count inconsistency; the concession that repo-level coding and web search need work).

## Limitations

- No quantitative scientific evaluation and no Sci-Perception ablation, so the paper's defining claim is unsupported by measurement.
- Harness and context-budget asymmetry across models (Claude Code vs OpenHands; 512K context granted to Sage on several rows) undermines the comparison as a like-for-like model ranking.
- Non-standard MLE-bench metric (HumanRank), mixed-provenance PostTrainBench, and a 120-task Harvey LAB subsample make the two headline margins (+1.1 and +0.8) fragile.
- Architectural opacity: 320B total parameters but no active-parameter count, expert count, layer count, pre-training data mixture, or token budget; the backbone's provenance is only implied by a citation.
- Training-data scale for the agentic stacks is described in inventory counts (4,936 Kaggle sources, 2,960 papers) rather than in final accepted task counts — Table 1 itself warns these "do not represent counts of final training tasks," so the actual SFT volume is unknown.
- Trajectory analysis has no quantitative win rate, and the paired cases were selected by the authors; the qualitative "same score, different quality" claim is plausible but untested at scale.
- No compute budget, no training curves, no data-contamination audit beyond Git-history removal on SWE-bench Pro.

## Relevance

对关注「科学多模态接口 + 可验证 agent 环境」的研究者价值很高：Sci-Perception 的「冻结编码器 + 只训投影器 + GRPO」是一条低成本可复现的路线，ToolSpace 的工具图合成与回放验证也是可直接借用的数据工程范式。若关心的是 320B 级 agent 模型的真实能力排序，则需谨慎——科学基准完全缺席，且 harness 不对等使部分对比失真。

## Questions for Further Exploration

1. What happens to scientific performance if the modality projectors are removed and the same inputs are serialized as text (SMILES, FASTA, peak lists)? Without this ablation the interface's value is unmeasured.
2. Would the reported agentic margins survive a fully harness-matched re-run, i.e. every model under the same scaffold, the same 512K context allowance, and the same judge?
3. Is Sage S2.1 Flash initialized from GLM-5.3-Flash? If so, how much of each win is post-training rather than base-model capacity, and what does GLM-5.3-Flash score under the identical post-training recipe?
4. How many tasks actually survive ToolSpace's replay verification and judge filtering, and what is the acceptance rate per environment type? The inventory numbers do not answer this.
5. Does GRPO on the projectors change calibration and uncertainty on scientific predictions (e.g., does the model become overconfident on out-of-distribution spectra), given that rewards are outcome-based?
6. Can the "verification-coverage" difference identified in the trajectory analysis be turned into a measurable metric (e.g., fraction of task requirements explicitly re-checked before submission) that predicts success better than pass rate?
