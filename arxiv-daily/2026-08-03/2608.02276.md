> **一句话总结：** Harness-R1 首次将"对执行中的 agent 运行时框架（harness）做失败条件化的全生命周期编辑"建模为一个可学习的强化学习任务——用一个独立的 9B 工程师模型，通过冷启动 SFT + 在线 GRPO，把冻结目标 agent 的成功率从 44.3% 提升至 53.6%（+9.3 个百分点），并在直接对 agent 做 SFT 后还能再加 5.0 个百分点。

> **TL;DR:** Harness-R1 is the first method to make failure-conditioned, lifecycle-wide editing of an existing executable agent runtime a *learned* capability: a dedicated 9B "harness engineer" is post-trained with cold-start SFT and online GRPO over the realized rerun rewards of executable patches it writes against a frozen Qwen3.5-9B target. Across WebShop, ALFWorld, and DBBench, it lifts the vanilla target from 44.3% to 53.6% (+9.3 pts), beating the strongest frontier-model editor (GLM-5.2 at 48.8%) and a supervised-only engineer by 7.1 pts; after direct target-agent SFT, a retrained engineer adds a further +5.0 pts (59.2% → 64.2%).

## 核心贡献

- **首次将框架（harness）编辑形式化为在线强化学习问题**：明确区分"优化目标 agent 权重"与"优化围绕冻结模型的运行时框架"，提出一个独立的、可训练的 harness 工程师，由真实任务结果（而非文本合理性）驱动学习，填补了既有 harness 优化工作（Meta-Harness、AutoHarness、AHE、HarnessX 等）"提议器参数从不被更新"的空白。
- **构建了从失败到编辑到重跑的闭环训练范式**：冷启动 SFT（GPT-5.5 教师筛出 877 条可执行示例）初始化策略，再以 group-relative policy optimization（GRPO，K=8 候选）在线优化补丁的全批次真实效用，工程师与目标 agent 严格解耦——只更新工程师权重。
- **定义了可执行补丁的动作空间**：限制为四个生命周期 hook（`on_init` / `make_pre_hint` / `on_before_action` / `on_post_step`），所有补丁经校验后安装，非法补丁零奖励，避免无限制代码编辑破坏运行时。
- **实证证明框架构建是一个可学习的能力**：9B 工程师（53.6%）超过 GLM-5.2（48.8%）、Qwen3.5-397B、GPT-5.5 等大型前沿模型充当的编辑器，并强于 ReAct/Self-Refine/Reflection 等固定策略（Self-Refine 在三个 benchmark 上平均降低 2.6 pts）。
- **展示工程师与目标 agent 可协同演化**：在直接对目标 agent 做 SFT 之后，针对更强 actor 重新训练的工程师仍能再加 5.0 个百分点，并为多轮 co-evolution 留出方向。

## Key Contributions

- **Formulates harness editing as a standalone online RL problem.** Separates "updating target weights" from "optimizing the executable runtime surrounding a frozen model," and trains a dedicated 9B harness engineer from the realized task utility of its patches — unlike prior systems (Meta-Harness, AutoHarness, AHE, HarnessX) whose proposer weights are never updated.
- **Builds a failure-to-edit-to-rerun loop.** Cold-start SFT on ~877 GPT-5.5-teacher-filtered executable examples initializes the policy, then online GRPO (K=8 candidates per failure packet) optimizes the full-batch mean reward change Δ_B(P); only engineer parameters θ are updated, with the target agent and its base runtime otherwise frozen.
- **Defines a constrained, validated action space.** Patches are restricted to four lifecycle hooks (`on_init`, `make_pre_hint`, `on_before_action`, `on_post_step`); invalid, no-op, or incomplete patches receive zero reward, preventing unbounded code edits from breaking interfaces.
- **Empirically shows a 9B trained engineer beats larger fixed editors.** Harness-R1 at 53.6% average surpasses GLM-5.2 (48.8%), Qwen3.5-397B, GPT-5.5, and other frontier models prompted as engineers, and also beats the supervised-only engineer by 7.1 pts and fixed strategies (Self-Refine lowers reward by 2.6 pts on average).
- **Demonstrates co-evolution with the target agent.** After direct target-agent SFT raises the baseline to 59.2%, a target-specific engineer adds a further +5.0 pts to 64.2%, indicating harness editing does not saturate once the actor improves.

## Methodology

**Problem setup.** Given a frozen target agent A (Qwen3.5-9B plus its base runtime) and a batch B of n tasks in environment E, run the unmodified agent to obtain baseline trajectories and rewards R⁰ᵢ. A deterministic extractor retains only failed episodes and compacts their task constraints, action–observation excerpts, and outcomes into a failure packet s_B. The engineer H_θ reads s_B once and emits a batch-conditioned executable overlay P; it neither answers tasks nor participates in rollouts.

**Action space — four lifecycle hooks.** The overlay wraps the agent loop as validated hooks that touch only inputs/outputs surrounding the frozen policy, never the weights:
1. `on_init` — sets up starting context, episode state, skills, or a tool hint.
2. `make_pre_hint` — injects a state-conditioned message before the agent decides.
3. `on_before_action` — runtime guardrail that may canonicalize, rewrite, block-and-reprompt, or force the pending action before it reaches the environment.
4. `on_post_step` — inspects the returned observation and triggers recovery (e.g., loop breaking) when the trajectory stalls.

Each hook returns a structured effect (e.g., `block_and_prompt`, `rewrite_action`, `force_action`, `inject_hint`) interpreted by the host runtime. DBBench v1 accepts only soft guidance and blocking — no SQL rewrites or forced commits.

**Reward.** After validation, the overlay is installed and the same frozen target reruns every task in B (including originally successful ones):

  Δ_B(P) = (1/n) · Σ_i (Rᴾ_i − R⁰_i),    r(B, P) = Δ_B(P) if valid and complete, else 0.

This is non-differentiable and observable only after an edit changes target behavior.

**Two-stage training.**
- *Cold-start SFT:* a GPT-5.5 teacher proposes serialized editing responses from failure packets; responses are validated, evaluated by rerunning the frozen target, and at most one executable, complete, non-regressive response per packet is retained, yielding 877 examples (381 WebShop / 248 ALFWorld / 248 DBBench). The 9B engineer (Qwen3.5-9B base) is trained by teacher-forced next-token prediction (2 epochs, lr 1e-5, full-parameter, BF16, 8×H800).
- *Outcome-grounded GRPO:* starting from the SFT policy, sample K=8 candidate patches per failure packet, parse/validate each, rerun the frozen target on the full batch for each valid patch, normalize rewards within the group into advantages Â_k = (r_k − μ_B)/σ_B, and maximize a token-averaged clipped surrogate with asymmetric clipping (ε_ℓ=0.20, ε_h=0.28), truncated importance sampling (max weight 2.0), rollout temperature 0.7 / top-p 0.95. No format-validity bonus or explicit KL term. Training uses ~1,500 failure packets from a disjoint task split.

The entire pipeline — collect failures, condition the engineer, validate, install, rerun, reward — updates only the engineer; the target stays frozen.

## Results & Highlights

- **Main lift on the frozen vanilla target (Table 1).** Across WebShop, ALFWorld, and DBBench, Harness-R1 raises the equal-weight average success from **44.3% to 53.6% (+9.3 pts)** for vanilla Qwen3.5-9B. The largest absolute gain is on ALFWorld, where success rises from **40.6% to 53.2% (+12.6 pts)**, with the "Heat" sub-task jumping from 28.8% to 43.8% and "Cool" from 9.2% to 34.5%.
- **Beats all frontier-model editors.** The strongest prompted frontier editor is GLM-5.2 at **48.8% average**, **4.8 pts below** Harness-R1's 53.6%; GPT-5.5 reaches only 47.9% and Qwen3.5-397B only 45.8%. Fixed strategies are unstable: ReAct adds +3.2 pts while Self-Refine *reduces* the average by **−2.5 pts** (and lowers reward on all three benchmarks by an average of 2.6 pts).
- **Outcome training beats supervised-only.** Harness-R1's outcome-grounded engineer (53.6%) outscores the supervised-only engineer (**46.4%**) by **+7.1 pts**, confirming that realized rerun outcomes — not teacher demonstrations — drive the gain.
- **Co-evolution after target SFT.** Direct task-agent SFT raises the unmodified target to a 59.2% average; a target-specific Harness-R1 engineer raises it further to **64.2% (+5.0 pts)**, with ALFWorld "All" climbing from 71.2% to 84.0%.
- **Cross-model transfer to 20 unseen targets (Figure 3).** A single training recipe gives a benchmark-averaged gain of **+7.06 pts**, with every target-level average positive; **56 of 63 target–benchmark combinations improve**, four unchanged, and all three regressions ≤2.0 pts. Standouts include Qwen3-4B (+12.3), Gemma-3-4B (+12.0), Llama-3.1-8B (+10.5).
- **Held-out task generalization (Figure 4a).** From only 10 observed failures per benchmark, Harness-R1 improves pooled held-out success on 1,270 tasks by **+8.9 ± 1.5 pts** (positive on all three seeds); the same protocol yields **−4.3 ± 2.5** for Qwen3.5-397B and **−0.4 ± 3.6** for DeepSeek-V4-Pro, both straddling zero.
- **Lifecycle-position ablation (Figure 4b).** Removing pre-action mediation costs **−3.9 pts**, removing post-feedback recovery costs **−3.3 pts**, while episode-start (−0.9) and pre-decision (−0.6) matter less. The dominant position is environment-dependent: pre-action on WebShop, post-feedback on ALFWorld.

## Critical Assessment

- **Novelty is genuine but narrow.** The paper is the first to post-train the *editor* of an executable harness with online RL grounded in rerun outcomes; prior work (Meta-Harness, AutoHarness, AHE, HarnessX) updates the resulting harness or the task model but not the proposer's weights. The framing as "a separate 9B engineer whose action space is constrained lifecycle hooks" is a clean contribution, though it sits close to concurrent HarnessX (cross-harness GRPO on the task model) and AEGIS (symbolic harness editing).
- **Rigor is mostly solid, with one weak comparator.** The Reflection baseline is reported under a separate **two-episode success@2 protocol** (55.8% cumulative), explicitly "not directly comparable" to the single-episode rows — readers must remember Reflection is not actually beaten on a like-for-like basis. The frontier-model editors are also evaluated as one-shot prompted editors with no rerun-based filtering, which stacks the comparison in Harness-R1's favor (the paper acknowledges frontier editors "never rerun the target").
- **Strong cross-model transfer but uneven.** Several small targets barely move: Llama-3.2-1B averages +2.2 pts (WebShop +0.0, ALFWorld +0.2), Gemma-3-1B averages +1.2 (WebShop +0.0), and Qwen2.5-72B only +1.0 — the gains concentrate on small/mid Qwen and Gemma models, raising questions about whether the recipe generalizes to very weak or very strong targets without per-target tuning.
- **Reward signal is same-batch and transductive.** The reward is computed only on the tasks mined for failures, with no explicit held-out regression term during training — a held-out check exists only at evaluation. The authors flag this as future work (enriching the reward with held-out performance and inference-efficiency terms).
- **Cold-start depends on a frontier teacher.** SFT data is generated and filtered by GPT-5.5; the resulting 877 examples are the prior the RL stage starts from, so the method is not fully self-bootstrapping.
- **Single-round co-evolution only.** The "co-evolution" claim is supported by *one* vanilla → SFT-target step with a retrained engineer; iterative multi-round co-evolution (the more ambitious claim) is left entirely for future work.
- **DBBench action space is restricted.** DBBench v1 supports only soft guidance and blocking, not SQL rewrites or forced commits, so the harness's leverage on DBBench is structurally smaller than on WebShop/ALFWorld — and indeed DBBench gains are the smallest in most rows.

## Strengths

- Clean problem formulation that isolates harness editing as a learning target distinct from both model training and prompt/workflow optimization.
- Outcome-grounded reward (rerun the frozen target, take the realized Δ_B(P)) is principled and avoids rewarding plausible-but-useless edits.
- Constrained, validated action space (four lifecycle hooks, structured return effects, zero reward for invalid patches) keeps edits executable and safe.
- Honest, paper-specific comparisons: a Self-Refine rule that hurts all three benchmarks, frontier editors that straddle zero on held-out tasks, and an explicit acknowledgment that Reflection is not comparable under one-episode scoring.
- Public code, models, and prompt templates (Appendix A) plus full hyperparameter tables (Appendix B) materially help reproducibility.
- Strong and broad generalization evidence: 20 unseen targets and 1,270 held-out tasks, with positive average gains everywhere.

## Limitations

- Only one co-evolution round is studied; the compelling multi-round co-evolution story is future work, not demonstrated.
- The reward is tied to the same tasks used to mine failures (transductive, same-batch), with no held-out regression penalty during training and no persistent patch memory across batches.
- Cross-target transfer is uneven at the extremes — very small (Llama-3.2-1B, Gemma-3-1B) and very large (Qwen2.5-72B, Qwen3.5-35B-A3B) targets gain the least.
- Cold-start SFT relies on a GPT-5.5 teacher, so the method is not fully self-bootstrapping.
- The evaluation suite is only three benchmarks, all single-agent and text/SQL/Web — no multimodal, no long-horizon tool-use beyond DBBench, no real-world deployment traces.
- DBBench v1 restricts the hook effects (no SQL rewrite / forced commit), capping achievable gains there.
- Inference-efficiency cost of installing and rerunning patched hooks is not measured or bounded.

## Relevance

与"自我演化 agent / harness 优化 / 在线 RL 后训练"方向高度相关——直接展示了用 GRPO 训练一个独立 editor 来改写围绕冻结 LLM 的可执行运行时，可为自演化 agent 与 agent-harness 协同训练的研究提供方法论基础和可复现基线。对关注 LLM agent 自主改进、工具中介、失败恢复机制的研究者，这是一篇值得精读的工作。

## Questions for Further Exploration

- Does iterating target-SFT ↔ engineer-GRPO for multiple rounds produce compounding gains, or does the editing signal saturate once the target agent stops failing in characteristic ways?
- Can the reward be enriched with a held-out task term and an inference-cost term so patches are optimized for transfer and runtime overhead, not just same-batch success?
- Why do very small (Llama-3.2-1B, Gemma-3-1B) and very large (Qwen2.5-72B) targets benefit least — is it failure-mode diversity, action-format mismatch, or something intrinsic to the engineer's prior?
- Would giving the frontier editors the same rerun-based filtering Harness-R1 enjoys close the gap, and by how much?
- How does Harness-R1 interact with multimodal or long-horizon real-world agent deployments where failure modes are rarer and more heterogeneous than in WebShop/ALFWorld/DBBench?
- Can the four-hook action space express conditional coordination across hooks (e.g., state set in `on_init` consumed by `on_post_step`), and does scaling the hook vocabulary continue to help?
