02Methodology · six stages

collection → reconstruction → slice → encode → attend → diagnose
1STAGE

Non-intrusive collection

Cupti/NVTX injected via env vars + LD_PRELOAD. Five layers covered: engine, frontend, CUDA runtime/driver, GPU kernel, NCCL. stdout/stderr captured in parallel — no binary edits.

2STAGE

Request-level reconstruction

Events normalized to a shared time base; stack-scan recovers NVTX ranges; host/device bound via (tid, cid); per-request vertical+horizontal trees; logs aligned by request id / time window.

3STAGE

Causal-context slice

Per-family GMM gives suspiciousness; relevance score combines ancestry (β), temporal decay (γ), communication coupling (η); induced subgraph + h ancestor hops answers who / where / when / with whom.

4STAGE

Trace Pair Encoding (TPE)

BPE-style, but the merge rule preserves parent index, depth, and accumulates duration — so call structure and time budgets survive compression. Emits vocab.json + merges.json.

5STAGE

Graph-aware Trace Encoder

Token init = token + depth + duration MLP. Parent indices induce a graph; L GCN-style propagation layers. Pooled per step and projected to the LM backbone's hidden size.

6STAGE

Multimodal MoT RCA head

Causal LM encodes logs; Trace Encoder feeds trace stream; per layer they're concatenated through shared attention then split to modality FFNs. Dual head emits fault type, suspicious operators, and free-text reason.

04Strengths & limitations · side by side

read across, not down

+Strengths

  • Truly non-intrusive. Env vars + LD_PRELOAD, no source edits, yet reaches kernel / NCCL granularity.
  • Unified request-level view bridging the vertical execution stack with horizontal communication — exposes the cross-layer contradiction single-layer tools miss (vLLM/Mamba SSM-state-contamination case study).
  • TPE's merge rule is a clean, reusable idea — explicitly maintains parent / duration / depth, unlike flat BPE on trace text.
  • Honest, extensive ablations. Vocab sensitivity, modality, low-prior (50 repeats), overhead, strengthened baselines — the paper states where its numbers are optimistic.

−Limitations

  • Injected faults only. Balanced controlled benchmark, not a production-fault prior — real incidents may be noisier and more entangled.
  • Split is request-disjoint, not workload/run/injection-disjoint — acknowledged as making in-distribution estimates optimistic.
  • Single, small dataset. 300 traces on one dual-node 6×A40 cluster serving Qwen3-8B; larger clusters / newer GPUs / multi-tenant behavior unverified.
  • Explanation quality is self-audited against labels, not blinded SRE scoring; BLEU is a weak proxy. No per-fault-category confusion reported.

05Open questions for follow-up

where the work points next
Q1

How does TELLER perform under workload/run/injection-disjoint splits — and how wide is the gap from in-distribution to true OOD generalization?

Q2

Can TPE merges be learned in a fault-aware (supervised) manner rather than purely by frequency, and would that shift the optimal vocabulary?

Q3

What is the per-fault-category reliability (memory vs. CUDA/kernel vs. communication vs. scheduling), and which categories drive the remaining errors?

Q4

Does the framework scale beyond 6× A40 — to multi-node H100/B200 clusters with TP/PP and heavier NCCL collectives?

Q5

Would blinded SRE scoring preserve the high explanation scores, and do generated explanations ever hallucinate operators not in the reconstructed trace?

Q6

Can the +9.8% overhead be cut via adaptive / sampled tracing while keeping operator-localization quality above the strong baselines?
