> **一句话总结：** HarnessCompass 通过三条"纪律性"原则（受约束的演化、主动式第一人称反馈、组件分轨优化）来驯服自动 harness 演化中的过拟合、信号不足与组件间干扰问题，在 SWE-Bench Verified 上用 GPT-5.4 仅 5 轮迭代就把 Pass@1 从 54% 提到 66%，并在 450 个未见任务和 Claude-Sonnet-4.6 上都展现出显著优于 SOTA 方法 AHE 的泛化能力。

> **TL;DR:** HarnessCompass is a disciplined automatic harness evolution framework for LLM coding agents that enforces task-agnostic edits, augments trajectory evidence with grounded first-person feedback, and optimizes structural vs. guidance components on separate tracks before merging. On SWE-Bench Verified with GPT-5.4, it lifts Pass@1 from 54% to 66% in just 5 iterations (vs. AHE's 63% in 20 iterations), reaches 60.4% on 450 held-out tasks (vs. AHE's 54.7%, a +5.7 point gap), and the GPT-5.4-evolved harness transfers frozen to Claude-Sonnet-4.6, raising total Pass@1 from 70.0% to 73.8%.

## 核心贡献

- **诊断现有自动 harness 演化的三大病灶：** 明确指出当前方法（如 AHE）的 ❶ 搜索任务过拟合（在 disjoint 评估集上泛化差）、❷ 仅依赖轨迹外部信号导致误归因（无法知道 agent 为什么觉得 harness 难用）、❸ 所有组件联合优化导致编辑互相干扰。
- **提出三条对症的"纪律性"设计原则：** (1) Constrained Evolution 用一个全局 Generalization Gate 强制每个编辑都是 task-agnostic 且放在正确位置（capability 进可执行代码，guidance 进 prompt/memory）；(2) Proactive Feedback 用 blind + hindsight 双报告再 grounding 到轨迹的方式，得到可信的第一人称反馈；(3) Component-wise Optimization 把 structural 与 guidance 两类组件分轨并行演化，再用 R3（Revision/Recombination/Refinement）合并。
- **SWE-Bench Verified 上的强结果：** 在 50 任务演化集上 5 轮达 66% Pass@1（AHE 20 轮仅 63%），在 450 个 held-out 任务上 60.4%（AHE 54.7%），任务加权总分 61.0%（AHE 55.5%，seed 51.8%）。
- **跨模型与跨任务的真泛化证据：** 用 GPT-5.4 演化出的 harness 冻结后直接搬到 Claude-Sonnet-4.6，total Pass@1 从 70.0% 升到 73.8%；per-repository 分析显示 sphinx-doc 35.2%→58.0%、pytest-dev 52.6%→68.4%、django 59.3%→70.1%，且这些增益在两个模型上都成立。
- **消融清楚归因：** 累积消融显示 Generalization Gate 单独就把 held-out 从 51.6% 拉到 58.4%，Proactive Feedback 把 sample 拉到 66% 但牺牲了泛化（held-out 跌到 55.8%、轮数涨到 12），R3 在保住 66% sample 的同时把 held-out 拉回 60.4%、轮数压回 5——三条原则互补且各司其职。

## Key Contributions

- Identifies and formalizes three concrete failure modes of existing automatic harness evolution (AHE): search-task overfitting, trajectory-only signal causing misattribution, and joint optimization of all components causing edit interference.
- Introduces HarnessCompass, a disciplined evolution framework combining (a) a global Generalization Gate that vetoes task-specific edits and mis-placed guidance/code, (b) Proactive first-person Feedback from the code agent itself that is grounded against the trajectory before use, and (c) Component-wise Optimization with two parallel tracks plus an R3 merge procedure.
- Reports strong gains on SWE-Bench Verified with GPT-5.4: +12 points Pass@1 over the seed (54% → 66%), beating AHE (63%) while using 4x fewer iterations (5 vs 20).
- Demonstrates genuine generalization: +5.7 points over AHE on the 450 held-out tasks (60.4% vs 54.7%), plus cross-model transfer of a frozen GPT-5.4-evolved harness to Claude-Sonnet-4.6 (+3.8 total points, 70.0% → 73.8%).
- Provides clean ablations isolating each principle's marginal contribution, and a per-repository breakdown showing gains concentrate where the seed harness is weakest (sphinx-doc, pytest-dev, django).

## Methodology

HarnessCompass keeps the base model M (GPT-5.4, non-thinking mode) fixed and evolves only the harness H, which is decomposed into seven orthogonal component types grouped into two families: **structural components** (tool implementations, middleware, sub-agent configs) and **guidance components** (system prompt, tool descriptions, skills, long-term memory). The loop deliberately starts from a minimal seed harness H0 (one shell tool, a short system prompt, nothing else) so every later component is attributable to evolution. Each iteration performs three disciplined stages:

1. **Constrained evolution (Generalization Gate).** Before any edit is applied it must pass a global gate with two requirements. The *content* requirement rejects anything mentioning a specific task instance, test function, private symbol, or token-conditional branch, admitting only a reusable decision criterion paired with an applicability condition. The *placement* requirement forces capability edits (new executable functionality) into middleware/tools/sub-agents and guidance edits (pure instructions) into the system prompt/memory, preventing guidance from being smuggled into executable code where it would behave non-deterministically.

2. **Proactive feedback.** To go beyond "the task failed and where," the code agent M itself is queried twice per failed task: a *blind report* (trajectory shown without the verdict, to avoid hindsight bias) asking where the harness hindered it, and a *hindsight report* (verdict revealed) that attributes the failure to one of harness / agent_reasoning / task_ambiguity / environment. The two reports are reconciled, then *grounded against the trajectory*: existing-component complaints require direct trace evidence, new-capability requests require a trace-revealed gap. Unsupported items are dropped; survivors are aggregated by component with a confidence score (agreement × distinct tasks × blind/hindsight consistency) and handed to the meta agent as supplementary evidence.

3. **Component-wise optimization.** Two variants are evolved in parallel per round, one restricted to structural components and one to guidance components, so their updates cannot interfere. Both are evaluated; the higher-Pass@1 variant wins. The loser is not discarded: an **R3** merge (Revision keeps only independently beneficial loser edits, Recombination applies them with winner precedence, Refinement removes redundant overlapping edits) folds the loser's complementary gains back in, so each iteration compounds rather than discards half its exploration. Algorithm 1 makes the meta agent accept the merged harness only if it beats the current best.

## Results & Highlights

- **Main comparison (SWE-Bench Verified, GPT-5.4 non-thinking, Table 1):** HarnessCompass reaches **66.0% Pass@1 on the 50-task evolution sample in 5 turns**, vs **AHE's 63.0% in 20 turns** and the seed H0's 54.0% — a +12 point lift over seed and +3 points over AHE at one quarter of the iterations.
- **Held-out generalization (450 disjoint tasks, Table 1):** HarnessCompass scores **60.4%** vs AHE's **54.7%** (+5.7 points) and seed's 51.6%; the task-weighted **Total over all 500 tasks is 61.0%** vs AHE's 55.5% and seed's 51.8%. The held-out gap (5.7) is nearly double the sample gap (3.0), evidencing generalization rather than overfitting.
- **Cumulative ablation (Table 2):** Adding the Generalization Gate alone lifts Sample from 54.0% to 62.0% and Held-Out from 51.6% to 58.4% in 2 turns; adding Proactive Feedback pushes Sample to 66.0% but drops Held-Out to 55.8% and burns 12 turns; adding R3 restores Held-Out to 60.4% while holding Sample at 66.0% and cutting turns back to 5.
- **Cross-model transfer (Table 3):** The harness evolved with GPT-5.4, frozen and re-evaluated on Claude-Sonnet-4.6 with no further evolution, raises Total Pass@1 from **70.0% (seed) to 73.8%**, with Sample 68.0% → 76.0% and Held-Out 70.2% → 73.6% — indicating the learned improvements are model-agnostic engineering, not model-specific fixes.
- **Per-repository (Figure 3, GPT-5.4):** Largest gains land on harness-sensitive repos: sphinx-doc **35.2% → 58.0%** (+22.8), pytest-dev **52.6% → 68.4%** (+15.8), django **59.3% → 70.1%** (+10.8); scikit-learn barely moves (73.4%, already strong). On Claude-Sonnet-4.6 astropy rises 45.5% → 63.6%.
- **Efficiency curve (Figure 2):** HarnessCompass climbs steeply and peaks at iteration ~5–6 at 66%; AHE improves slowly and plateaus below it only after ~20 iterations.

## Authors & Credibility

The work is led by Beijing Institute of Technology (Luan Zhang and Yuhang Tian et al., corresponding author Dandan Song of BIT) with a contributor from City University of Hong Kong (Ruochen Zhou). The framing builds directly on a recent, explicitly cited line of automatic harness evolution work (AHE / Lin et al. 2026; Self-Harness; Darwin Gödel Machine; Live-SWE-agent) and motivates its three principles by quoting that literature's own reported poor held-out generalization (Wang et al. 2026 evaluation study). Methodologically the paper is careful: all four agent roles (code agent, trajectory analyzer, feedback agent, meta agent) share the single base model GPT-5.4 so no gain can be attributed to a stronger meta agent, all agents run in non-thinking mode to avoid reasoning gains masking harness gains, and both automatic methods start from the identical seed H0 — a clean attribution setup. The verbatim appendix reproducing the gate prompts and the four-stage reflection pipeline supports reproducibility. The manuscript is marked as a preprint under review.

## Critical Assessment

- **Novelty:** The framing of harness evolution as a *discipline* problem rather than a *search* problem is a genuinely useful reframe. The three principles individually echo known ideas (constraint-based search, self-reflection feedback, modular optimization), but their composition — especially the content+placement Generalization Gate that hard-bans instance ids, test function names, private symbols, and token-conditional branches across all seven component surfaces, plus the blind/hindsight dual-report design to suppress hindsight bias — is non-trivial and well-motivated against AHE's specific failure mode on disjoint evaluation sets.
- **Rigor:** Attribution is unusually clean: shared base model, identical seed, non-thinking mode, cumulative ablation, per-repository breakdown, and a cross-model transfer test. The ablation honestly exposes a real tension — Proactive Feedback *alone* overfits (Held-Out drops 58.4% → 55.8%, turns balloon to 12) and only R3 rescues generalization — which is more than rubber-stamp reporting.
- **Reproducibility:** Verbatim prompts for the gate, the four reflection stages, and R3 are in the appendix, the benchmark is public, and the eval splits (50/450) are described; however, no code release or seed harness files are referenced, and the meta-agent's GatedEvolve/R3 prompts rely on judgment that may not be fully captured in text.
- **Significance:** The headline result (54% → 66% in 5 turns) is on a single benchmark with a single primary base model, and the "SOTA" being beaten is essentially one method (AHE). Comparisons against the broader agent-optimizer space (ADAS, AFlow, Darwin Gödel Machine, Live-SWE-agent, end-to-end optimizers) are discussed in Related Work but not in the result tables, so the practical lead over those families is unmeasured here.
- **Red flags / data quirks:** (1) SWE-Bench Verified's repository distribution is highly skewed — django alone has 231/500 tasks, so the task-weighted Total is dominated by a few repos; the per-repo figure is therefore the more honest view, and several repos (mwaskom, pallets) have only 1 task making their numbers noise. (2) The 50-task evolution set is small, so the +12 point Sample number has high variance that is not discussed with confidence intervals. (3) Non-thinking mode is used to "isolate harness design," but real deployments use thinking mode, so the 66% is a lower bound that may not reflect deployed performance. (4) The cross-model transfer to Claude-Sonnet-4.6 starts from a *different* seed (68.0% Sample) than GPT-5.4's, so the +3.8 total is not a like-for-like transfer delta — it shows the GPT-evolved harness beats Claude's own seed, which is suggestive but not a controlled transfer experiment. (5) No missing ablation on the *blind vs hindsight* split is reported, so the claim that blind-reporting reduces hindsight bias is asserted rather than measured.

## Strengths

- Clear problem decomposition: three named failure modes mapped one-to-one to three named principles, each with an ablation row isolating its marginal effect.
- The Generalization Gate's two requirements (content + placement) are concrete and enforceable, and the explicit "HARD BAN" list in the meta-agent prompt is an unusually operationalized constraint.
- Honest about a weakness: the paper openly shows Proactive Feedback *hurts* held-out performance without R3, rather than hiding it.
- Cross-model and per-repository analyses go beyond a single headline number and directly address the generalization claim.
- 4x iteration efficiency over AHE (5 vs 20 turns) is a practically meaningful cost reduction, since each turn requires expensive benchmark rollouts.

## Limitations

- Single benchmark (SWE-Bench Verified) and single primary base model (GPT-5.4); generalization to other agent benchmarks (e.g., terminal-tool, web-agent, long-horizon coordination tasks) is untested.
- The 50-task evolution sample is small and no variance/confidence intervals are reported; the +3 point Sample edge over AHE may not be statistically robust.
- Non-thinking mode is used throughout to isolate harness effects, leaving open how much of the gap survives when extended reasoning is enabled.
- The comparison field is narrow: only AHE and the seed are in the result tables, despite Related Work citing many other automatic optimizers (ADAS, AFlow, Darwin Gödel Machine, Live-SWE-agent, TextGrad, OPRO).
- The Generalization Gate is rule-based (keyword/symbol bans), so subtler task-specific shortcuts that avoid banned tokens could still slip through; no analysis of gate evasion is provided.
- Cost in tokens/dollars per iteration is not reported, so "5 vs 20 turns" understates total compute if HarnessCompass's turns are heavier (two parallel tracks + R3 + feedback queries per turn).

## Relevance

这项工作直接落在 "LLM agent / 自动化 harness 与 scaffold 演化" 这条主线上，是 AHE、Darwin Gödel Machine、Live-SWE-agent 的最新对照工作——如果你关注 agent 自我改进、agent-computer interface 设计、或 SWE-Bench 上的代码 agent，它提供了可操作的约束式演化方法论和清晰的过拟合/泛化诊断框架，值得作为 baseline 与设计参考。

## Questions for Further Exploration

- Do the three principles still compound when the base model uses *thinking* mode, or does extended reasoning absorb the gains the harness provides?
- How robust is the rule-based Generalization Gate to subtler task-specific shortcuts that avoid banned symbols — e.g., latent-feature triggers or paraphrased instance descriptions?
- How does HarnessCompass compare empirically (not just in Related Work) against ADAS, AFlow, Darwin Gödel Machine, and Live-SWE-agent on the same SWE-Bench Verified split?
- What are the per-turn token and dollar costs of the two-track + R3 + feedback loop, and does the 5-vs-20-turn advantage survive when measured in total compute rather than turns?
- Does the framework transfer beyond code-repo fixing to other executable agent tasks (terminal workflows, web/tool coordination, long-horizon planning)?
- Would adding confidence intervals / multiple seeds on the 50-task evolution sample change the +3 point edge over AHE?
- Can the blind-vs-hindsight feedback split be ablated to *measure* the hindsight-bias reduction, rather than asserting it?
