> **一句话总结：** 针对记忆增强智能体中"记忆已更新但响应仍依赖旧状态"的隐式策略适配(IPA)缺陷,本文提出 StateAuditor,通过反向(从存储状态到草稿)的双向审计与"溯源+时序"验证的状态转移组装(VTA)机制,在 Stale 全协议下严格单查询 VTA 取得 .736(对比锁定的前序版本 .686,+5.0 配对增益,95% CI[+2.9,+7.2]),并由跨模型家族的 Gemini 评分复现(.738 vs .680)。

> **TL;DR:** The paper identifies draft-anchored verification blindness (stale premises in open-ended personalized responses often go unstated), and introduces StateAuditor with provenance-verified transition assembly (VTA); on the Stale full-history benchmark's strict single-query protocol, strict VTA scores .736 vs .686 for the locked predecessor (+5.0 paired points, 95% CI [+2.9, +7.2]), reproduced by a disjoint Gemini judge (.738 vs .680), while a matched no-transition control (.692) and a harder authored lifecycle set (no gain) explicitly bound the claim.

## 核心贡献

- **结构性诊断(关键发现):** 首次形式化"草稿锚定验证盲区"(draft-anchored verification blindness)——在开放式个性化请求中,过时状态常以隐式依赖而非显式声明的形式出现。论文图1显示:在显式(SR)与预设(PR)探针上,过时前提召回率为 0.44–1.0,但在开放式 IPA 探针上骤降至 0.06–0.38,且少样本/思维链提示反而使其恶化(0.38→0.13),即使前沿模型(gpt-5.5)也无法消除。
- **方法创新 VTA(Provenance-Verified Transition Assembly):** 反转验证方向,做"状态→草稿"审计;由 LLM 提出候选 old→new 转移,再用确定性代码将每个证据引文 pin 到唯一记忆条目、校验 t_new > t_old、要求至少两节点的因果路径。验证对象是溯源与时间顺序,而非语义取代;只有通过验证的转移才能触发修复。
- **生命周期感知的有类型修复:** 用 VALID/STALE/UNKNOWN 三态裁决取代传统蕴含/矛盾二分;有类型指令(repair / correct-and-inform / verify(answer, then ask))由确定性规则驱动,避免模型自由生成指令时的过度确认。
- **严格的对照实验边界:** 通过"匹配对照实验"(同样证据、适配器、调用预算,仅移除转移机制)证明 Stale 上的增益(仅 +0.6,n.s.)来自转移机制本身,而非增加的上下文或调用次数;在 HorizonBench 上坦承外部增益主要来自草稿侧审计本身。
- **过度纠正与开销的量化分析:** 引入 repair-only 部署默认点(在冲突无关样本上重写率仅 3% vs 全 VTA 的 80%),并提供 4B 蒸馏失败、T2-SR 回归口袋(12:21)、自偏好评审风险等明确边界。

## Key Contributions

- **Structural diagnosis (the finding):** Formalizes "draft-anchored verification blindness" — in open-ended personalized requests, stale user state typically appears as an unstated implicit dependency rather than an explicit claim. Stale-premise recall collapses from 0.44–1.0 on explicit/presupposed probes to 0.06–0.38 on IPA probes (Fig. 1), a pattern that persists at frontier scale (gpt-5.5: 0.38) and worsens under few-shot / chain-of-thought prompting (0.38→0.13).
- **Provenance-Verified Transition Assembly (VTA):** A bidirectional (state→draft, not only draft→state) lifecycle auditing pipeline. An LLM proposes candidate old→new transitions from timestamped evidence; deterministic code (i) pins each quotation to ≥80% content-token overlap within a single memory entry, (ii) checks t_new > t_old using the matched entry's timestamp (not a model-emitted date), and (iii) requires a causal path with at least two nodes. What is verified is provenance and chronology, not semantic supersession; only verified transitions can authorize repair.
- **Lifecycle-aware typed repair:** Three-state verdicts (VALID / STALE / UNKNOWN) replace the entail/contradict scheme — a STALE verdict carries the attribute's current value and UNKNOWN can trigger a user-confirmation request, distinctions an entailment scheme cannot represent. Typed directives (repair, correct-and-inform, verify) are emitted by deterministic rules because model-generated directives over-asked for confirmation.
- **Honest, controlled evidence with explicit boundaries:** A full-scale matched control (same evidence, adapter, call budget, transition machinery removed) scores only .692 (+0.6 over predecessor, n.s.), attributing the Stale gain to the transition machinery itself; on HorizonBench, the authors openly state most external gain is the draft-side audit, with the transition channel adding only a non-significant increment.
- **Over-correction and cost analysis:** A "repair-only" deployment operating point rewrites only 3% of conflict-free examples (vs 80% for full VTA) at .723 macro — still beats the baseline (83:48, p=2.8×10⁻³). Cost ≈ $0.34/scenario for strict VTA; ≈ 5.1s/8.1s mean/P95 incremental latency on the critical path.

## Methodology

StateAuditor is a fixed, role-structured post-generation audit pipeline (Fig. 2) with four roles plus an Arbiter/Adapter:

1. **Evidence role (§4.1):** Indexes each session's user turns as overlapping sentence windows and selects evidence in four deterministic steps — (i) question-anchored lexical match with per-session deduplication and temporal diversity, (ii) reserved "change-scan" slots for query-independent update disclosures, (iii) per-session strongest disclosure + best question-matching window, and (iv) antecedent search pairing each update with the assertion it supersedes. On the frozen dev slice this raises strict old/new pair window-level recall from .125 to .708 within a ~5.7K-token budget and no retrieval-time LLM calls.

2. **Dependency role (§4.2, draft-anchored):** Extracts atomic premises the draft states or presupposes, evaluated VALID / STALE / UNKNOWN against M with a materiality bit.

3. **Temporal role (§4.3, state-anchored):** Reverses the direction — extracts an attribute timeline (current value, previous value, change status) from M and tests whether the draft's substance is consistent with each current value. This is what surfaces premises the draft never states.

4. **Provenance-Verified Transition Assembly (§4.4):** The transition proposer emits attribute / old value / new value / two quotations / causal path / affected dimensions. The validator enforces (a) each quotation ≥80% content-token overlap within a single rendered entry, (b) t_new > t_old from the matched entry's timestamp, (c) both state values present, (d) material application, (e) causal path ≥2 nodes. Candidates with reversed chronology, cross-entry quotations, ungrounded evidence, or parse failures cannot authorize a STALE verdict.

5. **Arbiter and Adapter (§4.5):** Combines both audit passes with validated VTA paths. Verified-only authority constrains the *transition channel*, not the base audit — unverified material STALE/UNKNOWN findings can still fire repair or verify directives. Directives are deterministic (model-authored directives over-asked confirmation); if no directive fires, the draft passes through unchanged; if the audit output cannot be parsed, the unmodified draft is returned.

6. **Fine-tuned auditor (§4.6, negative result):** A Qwen3-4B auditor trained with QLoRA on 599 synthetic examples (30 attribute types × 20 domains × 5 change patterns × 4 draft modes) where gold labels are derived by construction. A contamination audit found no collisions, but the model does not yet match the frontier auditor — included as a documented failed distillation.

## Results & Highlights

- **Stale strict single-query protocol (headline, n=400):** Strict VTA scores **.736 [95% CI .707, .767]** vs **.686** for the locked predecessor — a **+5.0 paired-point gain (95% CI [+2.9, +7.2])**, 84 scenarios better and 37 worse (p<10⁻⁴). IPA alone moves 53:6 (T2 implicit conflicts 33:2), PR 31:10, SR flat (24:32).
- **Cross-family judge reproduction:** The benchmark's released **Gemini judge (disjoint from the gpt-5.5 proposer/adapter/judge stack) reproduces the gain (.738 vs .680; 92:40, p=7×10⁻⁶)**, mitigating same-family self-preference risk.
- **Stability across runs:** 3 independent full-400 draws score **.733 ± 0.002**; the lowest draw is still +4.5 over the predecessor.
- **Matched control isolates the mechanism:** A matched no-transition control on all 400 scenarios (same evidence, adapter, call budget) scores only **.692 (+0.6 over predecessor, n.s., 53:45)** — strict VTA beats it by **+4.4 points (52:7, p<10⁻⁹)**. The budget/evidence/adapter recover almost none of the gain.
- **Scenario-joint upper bound (privileged, scope-confounded):** .879 [.853, .904] vs .680 predecessor and .375 retrieval-only; the authors explicitly flag this as a non-protocol-matched upper bound because it jointly reads all three probes. 616 cells fixed, 11 broken (cluster-robust 331:1, p<10⁻⁹⁷).
- **Development setting (oracle memory):** Bidirectional StateAuditor raises overall accuracy from 28.3% to 67.3% (PR 145:0, IPA 135:9, both p<10⁻³); the state-anchored pass alone improves IPA by 31.5 points.
- **HorizonBench adaptation (external benchmark, 120 items, 61 users):** Full draft→audit→repair raises current-preference accuracy **.308→.458** and lowers reversion to the superseded value **.29→.20** (23:5, p=.001, user-clustered p=.007); however, the matched no-transition control already reaches .417, so the transition channel itself adds only a non-significant increment (10:5, p=.30) — the authors openly attribute most of this external gain to the draft-side audit.
- **Over-correction safety suite (277 items, seven regimes):** Predecessor reaches .975 true-change recall but .05–.58 false invalidation by regime; **strict VTA cuts false material-STALE to .00–.05** while still catching .875 of true changes; on hard-negative injection the gate accepts every valid candidate, rejects all 900/900 chronology/grounding/path violations, and passes 290/290 semantically non-superseding ones.
- **Repair-only deployment point:** Composing actual responses end-to-end, the repair-only policy lands at **.723** (splice-predicted .726), still beats baseline (83:48, p=2.8×10⁻³), and rewrites only **3% of conflict-free examples vs 80%** for full VTA.
- **Cost / latency:** Strict VTA ≈ **$0.34/scenario** (six calls, 9,328 audit tokens); scenario-joint ≈ $0.49; critical path is three sequential calls — measured 5.1s / 8.1s mean / P95 incremental latency.

## Authors & Credibility

- **Haofei Sun** (The University of Texas at Arlington) and **Lin He** (The University of Tennessee, Knoxville) — a small two-author academic team.
- Methodological credibility is high: pre-fixed configurations for the headline Stale and external sets, frozen dev slices (≤50 items, seed 42, committed ID lists), no prompt tuning on full test sets, all API calls cached with config/git-hash/seed logged, a contamination audit before 4B training, a blind two-annotator human protocol with McNemar tests, and three judge families (gpt-5.5 / Gemini / Qwen3-4B re-judge) used to triangulate the ranking.

## Critical Assessment

- **Novelty:** Genuine and well-scoped. The state→draft verification direction and the three-state lifecycle verdict (carrying the current value and admitting UNKNOWN) are a real structural advance over PPA's static persona entailment and PrefEval's prompt-based self-critique; the framing of "verified = provenance + chronology, not semantic supersession" is precise and defensible.
- **Rigor:** Strong on controls. The matched no-transition control on all 400 Stale scenarios is the key credibility anchor — it cleanly attributes the gain to the transition machinery (+0.6 n.s. without it vs +5.0 with it). The disjoint Gemini judge and a deterministic local Qwen3-4B re-judge (.858/.717; 125:32, p<10⁻¹³) reproduce the ordering. However, the **headline strict arm's proposer, adapter, and primary judge all share the gpt-5.5 family** — a documented self-preference risk (Pombal, Rei, and Martins 2026) that the single disjoint Gemini reproduction only partially offsets, and each arm is a single sampled run (n=100 replicate shifts ≈2 points).
- **Reproducibility:** High in principle — frozen drafts/base audits are reused, decoding is greedy where supported, configs and git hashes are logged, and a 674 MB cache+checkpoint artifact is promised. Caveat: the Anthropic API samples at T=1.0 without a seed and neither Gemini nor the gateway exposes a seed, so each arm is one sampled output per item unless explicitly a replicate.
- **Significance:** Bounded but honest. The .879 scenario-joint number is explicitly flagged as a scope-confounded post-development upper bound (it jointly reads all three probes while the official runner processes them independently). The harder 120-scenario cross-family authored lifecycle set yields **no accuracy gain (.533/.542 deterministic, .600/.633 semantic, both n.s.)** — a real boundary that many papers would have omitted.
- **Red flags / weaknesses to scrutinize:**
  - The headline Stale result is essentially a single benchmark; HorizonBench's external gain mostly evaporates under matched control, and the harder authored set shows no gain — so generalization beyond Stale is thin.
  - A persistent **T2 (implicit conflict) SR regression pocket of 12:21** is acknowledged and not fully resolved; full VTA actually deepens it to 8:32 against the predecessor.
  - The 4B distillation fails to match the frontier auditor — the small-verifier recipe (MiniCheck-style) does not yet transfer to lifecycle verdicts.
  - Human evaluation covers only the scenario-joint ranking (κ=0.126 — low absolute agreement even though the ordering is reproduced).
  - "Verified" is provenance and chronology only; a provenance-valid path can still encode a wrong state relation, so the claim is narrower than it sounds.
  - Verbalizing sensitive transitions can entrench a wrong inference; audit logs help developers, not end-user correction.

## Strengths

- Diagnoses a real, named failure mode (draft-anchored verification blindness) with quantitative recall evidence across auditor scales, rather than asserting it.
- The reverse direction (state→draft) is a simple, well-motivated structural fix, and the deterministic provenance/chronology gate is auditable rather than opaque.
- Exceptional honesty about boundaries: scenario-joint upper bound flagged, HorizonBench attribution to draft-side audit admitted, hard authored set reported as a null result, 4B distillation reported as a failure, T2 SR regression disclosed.
- Over-correction is measured, mitigated with a recommended repair-only deployment default, and quantified on a dedicated safety suite (false material-STALE cut to .00–.05).
- Multiple judge families and a blind human protocol triangulate the ranking.

## Limitations

- Single-benchmark headline: the strict +5.0 paired gain is essentially on Stale only; HorizonBench's external lift is mostly from the draft-side audit, and the harder authored lifecycle set shows no accuracy gain.
- Same-family self-preference risk in the headline strict arm (proposer/adapter/judge all gpt-5.5); each arm is one sampled run.
- Scenario-joint .879 is post-development and scope-confounded; the authors correctly decline to treat it as protocol-matched.
- T2 implicit-conflict SR shows a regression pocket (12:21, deepening to 8:32 under full VTA) that is not resolved.
- The 4B fine-tuned auditor does not match the frontier, so the cost-reduction story is unproven.
- Human agreement is low in absolute terms (κ=0.126); the validation supports only the ranking, not the absolute .879 estimate.
- "Verified" means provenance + chronology, not semantic correctness — a narrower guarantee than the name implies.
- No claims about general-purpose agent memory; verify-question noise remains (109/32/21 preserved/weakened/changed; 56–94% unnecessary, 10–42% intrusive by judge family).
- Verbalizing sensitive transitions may entrench wrong inferences; deletion/correction controls remain necessary.

## Relevance

对研究"长期记忆 + 个性化智能体"与"记忆冲突/时效性"方向高度相关:本文精确刻画了"记忆已更新但响应未更新"的 IPA 缺口,提出的"状态→草稿"双向审计与溯源-时序验证的转移机制,以及明确的过度纠正与开销边界,对评估和构建可靠的记忆增强 Agent 系统具有直接的方法学参考价值。

## Questions for Further Exploration

- Would the strict +5.0 paired gain survive a fully powered, multi-seed, multi-judge-family evaluation on a held-out Stale split that VTA never touched during development?
- Can the deterministic provenance/chronology gate be strengthened with a lightweight *semantic* supersession check (the authors sketch one that cuts the hard set's trap over-repairs 18→6 without losing accuracy) without reintroducing the over-asking that model-authored directives caused?
- Why does the 4B MiniCheck-style distillation fail to transfer to lifecycle verdicts, and what training signal (beyond construction-derived labels) would close the gap to the frontier auditor?
- The T2 (implicit conflict) SR regression pocket (12:21, deepening to 8:32 under full VTA) — is this a verifier artifact, an adapter artifact, or a genuine conflict-type interaction, and can a typed-repair variant fix it without inflating verify-question noise?
- How does StateAuditor compose with write-time governance (CUPMem, Mem0, Memora) — is the response-side repair orthogonal to write-side adjudication, or do they double-correct in pathological ways?
- Can the methodology extend beyond personal state to other implicit dependencies (e.g., tool-version, policy, or world-knowledge supersession), where the draft-anchored blindness diagnosis should in principle also apply?
