Key finding

Qwen-CUA: Native Computer Use for (almost) Everything

A pure screenshot-only native computer-use agent — observing only pixels, emitting only keyboard & mouse events — beats Qwen3.7, GPT-5.5 and Claude Opus 4.8 on OSWorld-Verified (86.2), while cutting indirect-prompt-injection attack success from 36.6 → 16.4.

Methodology

how it's built

LOOP Native computer-use loop

Each step: screenshot → action from a keyboard/mouse space (click, drag, type, scroll, + control: screenshot/wait/terminate/call-user). Deliberately avoids DOM, accessibility tree, shell and task-specific APIs — the interface is identical to a human at a desktop.

CTX Long-horizon context manager

  • Active visual history: 20 screenshots.
  • Chunked folding: every 10 steps older shots collapse to a text placeholder — prefix stays stable across steps 21–30 for KV-cache reuse.
  • Training-time slicing reuses the same fold operator; each slice inherits terminal reward.

SCALE Agentic training at scale

  • Alibaba Cloud ECS: ~100k vCPUs, tens of thousands of concurrent isolated desktops.
  • ~40k verifiable tasks: env-operation, simulated-user clarification, and phase-state-chained workflows.
  • Human trajectories from CAD, Blender, personalized desktops, augmented with filtered chain-of-thought.

RL SAPO + trajectory slicing

RLVR with Soft Adaptive Policy Optimization: group G=16 (oversampled N=20), group-relative advantage routed through an asymmetric temperature gate — τpos=1.0, τneg=1.05 — so off-policy tokens decay and negative-advantage tokens decay faster. Gradients flow only through model-generated tokens. 512 H200 GPUs, ~61,440 GPU-hours per 1k-update run.

Strengths & Limitations

side by side

＋ Strengths

  • Broad, consistent evaluation across 8 complementary benchmarks — everyday desktop, long-horizon, personalized, scientific, web, macOS, cross-software breadth, and adversarial safety — all under one pure-native protocol.
  • Honest efficiency analysis: tokens/task and turns/task reported separately; the interface-packaging confound for turn counts is explicitly acknowledged.
  • Chunked-folding context manager is a clean, deterministic, training-inference-consistent mechanism that improves KV-cache reuse without an extra summarizer model.
  • Engineering transparency: appendices cover action space, slicing algorithm, full SAPO objective & gradients, RL hyperparameter table, distributed-training topology, and per-environment results.
  • Honest hybrid framing: reports the Bash trade-off (shorter trajectories but lower success) rather than cherry-picking.

！ Limitations

  • Pixel-only latency: serialized low-level actions incur substantial interaction cost; visual operation is inefficient when a task could be expressed via code, shell, or APIs.
  • Tool routing not learned: adding Bash reduced perfect-task rate (58.7→55.1) despite shortening trajectories — models have not learned when not to use the GUI.
  • Residual safety risk: RedTeamCUA ASR still 16.4; Rocket.Chat's low task success can mask ASR — improved resistance, not a deployment guarantee.
  • Comparability confounds: turn-count metric is interface-dependent (1 action/turn vs multi-action turns for GPT-5.5/Opus-4.8); Qwen3.7 run in non-thinking mode vs Qwen-CUA in thinking.
  • Coverage gaps: 100/197 Gym-Anything environments omitted (Windows/Android/Linux setup failures); 12 MacAgentBench clock tasks scored 0 from an evaluator bug.
  • Not reproducible: the ~40k verifiable tasks and mock web services are not released — the RL data pipeline needs Alibaba-scale infrastructure.

Questions for Further Exploration

open fronts
How much of the OSWorld-Verified gain over Qwen3.7 survives when Qwen3.7 is also run in thinking mode with an equivalent scaffold, isolating CUA post-training from the inference-setting asymmetry?
Can the chunked-folding operator be replaced by a learned visual summarizer to recover information lost in text placeholders, and does it help where early screenshots carry load-bearing state?
Tool routing is the bottleneck in the Bash-hybrid experiment — would explicit tool-routing supervision recover the lost perfect-task rate while keeping the ~22% turn reduction?
How does SAPO's asymmetric temperature (τneg > τpos) interact with MoE routing stability at 397B scale, and is the asymmetry still beneficial at the >1T Qwen-CUA-Max scale?
Given 100/197 omitted Gym-Anything environments, what is Qwen-CUA's score on the full benchmark once Windows/Android images are provisioned — does the ranking vs Opus-4.8 (47.3) change?
The 16.4 residual RedTeamCUA ASR — what failure modes account for it, and does targeted safety RL on injection trajectories close the gap to Opus-4.8's 0.7 without sacrificing task success?
