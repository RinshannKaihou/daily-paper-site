> **一句话总结：** TELLER 提出一种非侵入式的 LLM 推理根因分析框架，通过 CUPTI/NVTX trace + 服务日志重建每请求的跨层调用链，并用结构保持的 Trace Pair Encoding (TPE) 压缩 trace 切片，再配合多模态根因模型；在 300 条多引擎 (SGLang/Torch FSDP/vLLM) 推理 trace 上，水平视图 step-level Accuracy 0.930、operator Macro+ F1 0.898，远超 Robustlog/LAnoBERT/Logs2Graphs/MAD-GAN 及经典聚类基线，且中等 TPE 词表在压缩 83.88% 的同时取得最佳精度。

> **TL;DR:** TELLER is a non-intrusive cross-layer RCA framework for LLM inference that reconstructs per-request call-chain trees from NVTX/CUPTI traces plus service logs, compresses dependency-aware causal-context slices with a structure-preserving Trace Pair Encoding (TPE) tokenizer, and feeds a multimodal root-cause model. On its 300-request / 2,482-step / 5.63M-node multi-engine dataset, TELLER reaches 0.930 step-level Accuracy and 0.898 operator Macro+ F1 on the horizontal view, beating the strongest log/deep baseline (Logs2Graphs 0.825 step Accuracy) and all classical detectors, while a moderate TPE vocabulary (256) cuts per-step trace length by 83.88% with the best diagnosis quality; aggressive compression (vocab 1024, 99.83% reduction) collapses step Accuracy to 0.617.

## 核心贡献

- **非侵入式跨层 trace-日志诊断管线**：通过环境变量与动态库预加载注入 CUPTI/NVTX tracing，覆盖推理引擎 / 计算前端 / CUDA runtime & driver / GPU kernel / 通信库 (NCCL) 五层，同时捕获 stdout/stderr，无需修改模型二进制或引擎源码。
- **请求级调用链重建与日志对齐**：将异构原始事件 (NVTX range、CUPTI runtime/driver/kernel、communication) 规约到统一时间基，按栈扫描重建嵌套层级，用 (tid, cid) 绑定 host 与 device，最终投影为每请求的纵向 + 横向调用链树，并将日志按 request id/时间窗对齐。
- **依赖感知的 causal-context slice**：在 GMM 数值候选定位之后，以 suspiciousness、祖先关系、时间邻近、通信耦合四种权重抽取实例级紧凑子图 (含 h 跳祖先)，回答 who/where/when/with whom。
- **结构保持的 Trace Pair Encoding (TPE)**：类 BPE 的 trace 专用 tokenizer，合并时保留 parent index / depth / 累积 duration，使压缩不破坏调用关系与时间预算；配合 graph-aware Trace Encoder 与双头 MoT 多模态根因模型，同时输出错误类型、可疑算子集合与自然语言解释。
- **系统化实验评估**：覆盖 step-level 检测、operator-level 定位、解释质量 (BLEU)、低故障先验 (AUPRC/AUROC)、模态消融、跨引擎泛化、tracing 开销与强化结构特征基线，明确揭示 "压缩–精度" 权衡并非单调。

## Key Contributions

- A non-intrusive, end-to-end cross-layer trace-log diagnosis pipeline that injects CUPTI/NVTX via environment variables and dynamic-library preload across engine, frontend, CUDA runtime/driver, GPU kernel, and communication layers, collecting stdout/stderr in parallel without touching model binaries or engine source.
- A request-level call-chain reconstruction procedure (event normalization, stack-based NVTX range recovery, host/device binding via `(tid, cid)`, per-request vertical+horizontal projection, and request-id/time-window log alignment) that reconciles asynchronous, batched execution into per-request trees.
- A dependency-aware causal-context slice that, after GMM-based numeric candidate localization, retains suspicious nodes plus their ancestry (up to h hops), temporal-succession neighbors, and communication partners, yielding a compact "who/where/when/with whom" subgraph.
- Trace Pair Encoding (TPE), a BPE-style structure-preserving tokenizer whose merge rule keeps parent index, depth, and accumulates duration, plus a graph-aware Trace Encoder and a dual-head mixture-of-traces/logs (MoT) multimodal RCA model that jointly predicts fault type, suspicious operator set, and free-text explanation.
- A comprehensive evaluation (step detection, operator localization, BLEU explanation quality, low-prior AUPRC/AUROC, modality ablation, cross-engine generalization, tracing overhead, and strengthened structured-feature baselines) that surfaces a non-monotonic compression-accuracy trade-off.

## Methodology

**Stage 1 - Non-intrusive collection.** A tracing wrapper launches the target command with CUPTI callbacks/activity records and Python-level NVTX push/pop hooks (installed via import-time wrapping). Step-level wrappers in vLLM encode request IDs into NVTX messages, creating a semantic anchor back to serving context. Stdout/stderr are captured in parallel.

**Stage 2 - Request-level reconstruction (Algorithm 1).** Events are normalized onto a shared time base `τ`. Per `(process, thread)`, events are stack-scanned to recover NVTX ranges; ranges are classified as STEP / FRONTEND / BACKEND / COMM. Host runtime/driver calls are attached to ranges by timestamp inclusion, and kernels are bound to host calls via `(tid, cid)` correlation. Step ranges carry a request set `Q(s)`; for each request `q`, vertical descendants and communication nodes are projected into a per-request tree `C_q(s)`. Log lines `(ts, rid, level, msg)` are aligned by request id, otherwise by overlap with the step interval (with tolerance).

**Stage 3 - Candidate localization and causal-context slicing.** Per operator instance, a feature vector (self-time, runtime/driver time and counts, kernel counts/totals, bytes moved, stream overlap, communication size) is `log(1+·)`-transformed and robustly standardized. A per-family GMM yields an anomaly score `a(x)=1-ρ(x)`; the family-level suspiciousness `A_{s,t}` aggregates the least-confident quantile, producing a candidate family set. A relevance score `R_s(v)` then combines suspiciousness (`α`), ancestry (`β`), temporal proximity (`γ`, exponential decay with scale `τ_0`), and communication coupling (`η`); the slice `G_s` is the induced subgraph of nodes with `R_s(v)≥κ` plus up to `h` ancestor hops.

**Stage 4 - Trace Pair Encoding (TPE, Algorithm 2).** The slice is serialized into `(X, P, Δ, D)` (symbols, parent indices, durations, depths). The merge rule replaces a frequent adjacent pair `(w_i, w_{i+1})` by a new token, setting parent to the left token's parent, accumulating durations, keeping depth, and shifting/redirecting parent indices so call structure and time budgets stay valid. Training iteratively merges the most frequent pair to a target vocab size, emitting `vocab.json`/`merges.json`.

**Stage 5 - Trace Encoder.** Per-token initial state `h_i^(0) = E_tok(w_i) + E_depth(d_i) + MLP_Δ(log(1+λΔ_i))`. Parent indices induce a graph on which `L` GCN-style propagation layers `H^(ℓ+1)=σ(ÂH^(ℓ)W^(ℓ))` are run; token states are pooled per step and projected to the LM backbone's hidden size.

**Stage 6 - Multimodal RCA (MoT).** A causal LM backbone encodes the log stream while the Trace Encoder produces the trace stream; at each layer the two are concatenated, passed through shared causal self-attention, then split back into modality-specific FFNs. The trace head produces fault-type probabilities; the log head drives the LM head for explanation generation. Training loss `L_mot = λ_f·L_CE + λ_r·L_NLL`. A single-stream variant (serialize trace+log, autoregressively emit `<fault_type>y</fault_type>∘r`) is kept as an alternative.

## Results & Highlights

- **Step-level detection dominates baselines (Table 2, horizontal view).** On the horizontal cross-node view, TELLER reaches step-level Accuracy **0.930**, Precision **0.945**, and F1 **0.916**, versus the strongest log/deep baseline LAnoBERT at Accuracy 0.882 / F1 0.783 and Robustlog at 0.874 / 0.771; classical unsupervised methods collapse (KMeans Acc 0.457, IsolationForest 0.433, GMM 0.494).
- **Operator-level localization is the largest gap.** On the horizontal view, TELLER's operator Macro+ F1 is **0.898** with Macro+ Jaccard **0.873**, whereas the best deep baseline LAnoBERT only reaches Macro+ F1 0.672 / Jaccard 0.507 and Robustlog 0.597 / 0.425 — i.e., TELLER improves operator-positive F1 by +0.226 over LAnoBERT.
- **TPE compression-accuracy trade-off is non-monotonic (Table 3 + Table 6).** Raw traces average **2241.92 events/step**. Vocab 256 compresses to 361.43 events/step (6.20×, **83.88% reduction**) and gives the best horizontal Accuracy 0.930 / BLEU-1 0.910; vocab 512 (25.90 events/step, 98.84%) drops Accuracy to 0.800; vocab 1024 (3.88 events/step, 99.83%, 577.81×) collapses Accuracy to **0.617** and horizontal operator Macro+ F1 to 0.226 — showing localization is far more compression-sensitive than coarse step detection.
- **Modality contribution (Table 5).** Combining trace+log gives fault Macro F1 **0.476** and fault Accuracy **0.743**, vs. w/o trace (0.292 / 0.667) and w/o log (0.446 / 0.653) — both modalities are necessary, and trace adds the larger Macro-F1 lift.
- **Cross-engine generalization (Table 7).** Across SGLang, Torch FSDP, vLLM v0, and vLLM v1, horizontal step F1 stays in **0.901–0.912** and vertical operator Macro+ F1 in **0.867–0.881**, supporting the engine-agnostic claim.
- **Low-fault-prior robustness (Table 8).** At a 10% fault prior, horizontal F1 stays **0.807** and vertical F1 **0.883**; AUROC remains essentially flat (0.945–0.967) even at 5% prior, while AUPRC degrades as expected (vertical 0.942 → 0.564).
- **Reference explanation quality (Table 9).** Overall score **0.968**; anomaly correctness and fault-type correctness both 1.000, evidence locator validity 0.963, actionability 0.963.
- **Tracing overhead (Table 10).** Non-intrusive but not zero-cost: wall time **64.77s → 71.15s (+9.8%)**, CPU utilization +8.8%, max resident memory +3.25%, swap count 0.

## Critical Assessment

- **Novelty:** Genuine. The combination of (a) request-level cross-layer call-chain reconstruction from generic NVTX/CUPTI tuples (engine-agnostic, no binary edits), (b) a dependency-aware causal-context slice that mixes ancestry/temporal/communication edges, and (c) a structure-preserving BPE-style trace tokenizer (TPE) with parent/duration/depth side channels is not a straightforward port of prior log-RCA or subword compression work; the explicit "non-monotonic compression" finding is a usable design lesson.
- **Rigor:** Mixed. The compression-accuracy study (Table 3 → 6), modality ablation (Table 5), generalization table (Table 7), low-prior resampling (50 repeats, Table 8), and overhead measurement (Table 10) are thorough. However, the headline step-level numbers in Table 2 sit above most baselines partly because several baselines (KMeans/DBSCAN/IsolationForest/GMM) score near chance (~0.45–0.55 Accuracy) and the strengthened structured-feature classical learners (Table 4: LinearSVM/RF/XGB w/ struct) only reach H Step F1 0.340–0.402 — i.e., the gap is partly a weak-baseline artifact, not purely TELLER's strength.
- **Reproducibility:** Good on paper (figshare artifact, fixed shuffle seed, request-disjoint 80/10/10 split, named hardware). But the authors explicitly flag that the split is only index-disjoint: correlated traces from the same workload, run, or fault-injection campaign can cross train/test splits, so the reported numbers are in-distribution estimates, not workload-disjoint generalization. Faults are injected (five categories with controlled magnitudes), not mined from production incidents.
- **Significance:** Practically relevant — LLM serving RCA across scheduler/CUDA/kernel/NCCL is a real and under-served problem, and the vLLM/Mamba SSM-state-contamination case study shows the cross-layer signal that single-layer tools miss.
- **Red flags:** (1) Single, small dataset: 300 request traces, 2,482 steps, 5.63M nodes, all from one dual-node A40 cluster serving Qwen3-8B — external generalization to larger clusters, newer GPUs, or long-running multi-tenant workloads is unverified. (2) Explanation-quality audit (Table 9) is the authors' own check of reference explanations against labels, not independent blinded expert scoring of TELLER's generated explanations; BLEU is only a lexical-overlap proxy. (3) The "non-intrusive" label is carefully scoped — +9.8% wall-time overhead is non-trivial for always-on serving. (4) No fault-type-level confusion analysis is reported, so per-category reliability is opaque.

## Strengths

- Truly non-intrusive collection design (env vars + `LD_PRELOAD`, no source edits) that still reaches kernel/NCCL granularity.
- Unified request-level representation bridging vertical execution stack and horizontal communication, with a concrete case study showing the cross-layer contradiction it exposes.
- TPE's structure-preserving merge rule is a clean, reusable idea — it explicitly maintains parent/duration/depth, unlike flat BPE on trace text.
- Honest, extensive ablations: vocab sensitivity, modality, low-prior, overhead, strengthened baselines — the paper states where its numbers are optimistic rather than overselling.

## Limitations

- Injected faults only; balanced step-level dataset is a controlled benchmark, not a production-fault prior. Real incidents may be noisier, longer, and more entangled.
- Train/test split is request-disjoint but not workload/run/injection-disjoint — acknowledged as making in-distribution estimates optimistic.
- Generalization is tested only on a dual-node 6×A40 cluster with Qwen-based serving; larger clusters, newer GPUs, and long-running multi-tenant behavior remain future work.
- Explanation quality is self-audited against labels, not independently validated by blinded SREs; BLEU is a weak proxy for diagnostic correctness.
- +9.8% wall-time / +8.8% CPU tracing overhead is bounded but non-zero, and the paper does not report per-fault-category confusion or end-to-end latency under sustained load.

## Relevance

高度相关：TELLER 直接面向 LLM 推理系统的可观测性与根因分析，覆盖 vLLM/SGLang 等主流推理引擎与 CUPTI/NVTX/NCCL 软硬栈，对研究 LLM serving 的可靠性、调试与 trace 表示学习的读者具有直接参考价值，其 "结构保持压缩优于激进压缩" 的结论对后续 trace 编码工作有指导意义。

## Questions for Further Exploration

- How does TELLER perform under workload/run/injection-disjoint splits, and what is the gap between in-distribution and true out-of-distribution generalization?
- Can TPE merges be learned in a fault-aware (supervised) manner rather than purely by frequency, and would that shift the optimal vocabulary?
- What is per-fault-category reliability (memory vs. CUDA/kernel vs. communication vs. scheduling), and which categories drive the remaining errors?
- How does the framework scale beyond 6 A40 GPUs — e.g., to multi-node H100/B200 clusters with TP/PP and heavier NCCL collectives?
- Would replacing the self-audited explanation-quality check with blinded SRE scoring preserve the high scores, and do generated explanations ever hallucinate operators not in the reconstructed trace?
- Can the +9.8% tracing overhead be reduced via adaptive/sampled tracing while keeping operator-localization quality above the strong baselines?
