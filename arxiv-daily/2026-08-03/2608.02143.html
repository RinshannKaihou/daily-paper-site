02 Methodology Inquiry ↔ Revision loop

Decision State

At step t, state s_t = (x_t, I_t, b_t): retained valid solution, information state, and remaining budget. Five LLM roles (Planner, Executor, Analyst, Summarizer, Knowledge Manager) implement the loop.

I_t = (E_t, S_t, K_t)   — evidence, summaries, task knowledge

Adaptive Action Topology

Instead of a fixed tree/graph/chain, the Planner emits a local plan conditioned on the current state. Same-layer actions run concurrently; global topology emerges from successively generated local plans. Only actions schedulable within b_t are emitted.

Epistemic vs. Interventional Actions

Interventional actions modify and evaluate the retained solution. Epistemic actions produce discriminative evidence without modifying x_t — error stratification, validation-reliability checks, feature-interaction probing. Triggered when next steps are indistinguishable or progress stalls.

Revisable Task Knowledge

Claims carry claim / scope / E⁺ / E⁻ / status (active · qualified · invalidated), revised via Add / Update / Invalidate. The retained solution updates as the arg-max over a valid set that always contains the previous x_t — guaranteeing a valid submission.

x_{t+1} = argmax_{x∈V_t} F_q(x)

04 Strengths / Limitations side-by-side

Strengths

  • Conceptually clean paradigm: formal decision-state + Algorithm 1 that is actually implementable.
  • Epistemic/interventional split fixes a real failure mode of solution-centric search — you can finally "just look" without committing a new candidate.
  • Revisable claims with provenance, scope & three-valued status give a falsifiable conflict-resolution mechanism beyond verbal reflection.
  • Best-in-class headline at half the budget of the closest model-matched rival, plus positive transfer to four genuinely different task types.
  • Honest about backbone sensitivity: 18pp gold swing between Claude-Opus-4.6 and Qwen3.7-Max is reported, not hidden.

Limitations

  • Ablations cover only 15 Small-Data tasks at 6h with Qwen3.7-Max — no controlled decomposition exists for the headline 75-task / 12h / Claude setting.
  • Cross-domain & ablation tables are single-run; per-task gains of a few points could sit within noise.
  • Reliance on proprietary frontier models + one H20-3e GPU per task; no code or prompts released.
  • MLE-Bench baselines transcribed from prior papers/leaderboard, not re-run — confounds in backbone, budget & implementation.
  • Kuzushiji trajectory is illustrative but singular; no systematic count of how often epistemic actions find decisive bugs.
  • No paired significance test vs. AIBuildAI; the +1.8pp any-medal delta is small vs. the budget gap.
05 Open Questions for follow-up work
i.

How much of the 64.9% is attributable to each component on the full 75-task set under the headline 12h / Claude-Opus-4.6 setting — not the 15-task subset?

ii.

How often do epistemic actions surface decisive, non-obvious bugs (like the detection-cap=100) vs. confirm what interventional actions would have found anyway?

iii.

Can the claim store be evaluated for calibration — fraction of "active" claims later invalidated, and correlation with downstream success?

iv.

Do the modest cross-domain gains (e.g. +4.0pp on τ3-Banking, single-run) survive paired multi-run evaluation with statistical tests?

v.

Does the paradigm compose with cheaper open-weight backbones, or is claim-revision quality tightly coupled to frontier-model reasoning?

vi.

Could the epistemic/interventional partition be learned (a small value-of-information head) rather than emitted by the Planner?
