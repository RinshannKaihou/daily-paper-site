HPFA: Hypergraph-Based Paired Failure Attribution for LLM Reasoning

Runchuan Zhu · Hongbin Lai · Bowen Jiang · Junrui Zhang · Zhangheng Li · Ostap Kilbasovych · Junyuan Hong (corresponding)

Why This Matters
A structured, scalable root-cause labeling pipeline that doubles as a data-synthesis baseline for PRMs, self-reflection, and agent debugging — especially for long-horizon math and code traces.
Critical Edge
The hypergraph hurts on short traces (GSM8K −4.5 pts), and counterfactual repair spans are LLM-generated, not ground-truth — so localization success conflates root-cause ID with the model's ability to produce a working repair.

01 Methodology

Three stages turn a query into a verified root cause; a lightweight attributor then learns to mimic and refine the procedure.

1

Paired trajectory generation

Roll out the target model (cap K = 8) until both a success T+ and failure T− appear; keep the closest-length pair. This drops counterfactual search from per-step probing to O(1/p), where p is the single-shot success probability.

2

Dependency hypergraph construction

Segment each trace into atomic steps (one arithmetic move, tool call, or subgoal). Semantic clustering induces an equivalence over the union of steps so that V = {[s]~}; per-trace prerequisites become hyperedges, giving G = (V, E_h). Built by an LLM (Qwen3-8B for math/code, GPT-4o for privacy).

3

Iterative root-cause localization (Algorithm 1)

Walk backward from T+'s output until the first vertex shared with T− (the meeting vertex v⋆). Unaligned successors on T− form candidates; each is counterfactually tested via R(T−, idx(v), s′). A verifying candidate is returned as the root; otherwise re-anchor at v⋆ and repeat.

4

Attributor training — SFT + GRPO

A lightweight π_φ maps (Q, T_fail) to a structured diagnosis. SFT: 5 epochs, batch 16, AdamW lr 5e-5, on templated diagnoses from HPFA-verified roots. GRPO: group size 4, lr 2e-6, on-policy failures, reward R = Rfmt + λ·Rrollout where the rollout term tests whether the diagnosis enables a correct re-rollout. Trained on 4× A100-80GB.

03 Strengths & Limitations

An honest split: where the method earns its keep, and where it leaks.

Strengths

  • Directly attacks the cost bottleneck of step-wise counterfactual attribution; the O(1/p) paired-rollout reduction is simple and well-motivated.
  • Trajectory-length-vs-hypergraph-gain analysis (Table 3) is an unusually honest characterization of when the method helps and when it hurts.
  • Two-stage SFT + GRPO with a rollout-grounded reward is a clean, actionable recipe other attribution / PRM works could adopt.
  • Cross-dataset, cross-backbone evaluation plus an out-of-domain AIME / LogiQA transfer test go beyond single-benchmark claims.
  • Public code, prompt templates (Appendix D), and explicit LLM-use disclosure.

Limitations

  • Hypergraph benefit is negative on short trajectories (GSM8K −4.5 pts); method is not uniformly dominant.
  • Privacy benchmark is tiny (108 cases) and uses GPT-4o for all LLM components — narrow statistical and model coverage.
  • Hypergraph builder (Qwen3-8B) is the same model that generates trajectories; cross-model agreement is stability, not correctness.
  • No gain on Gemma3-4B (20→21%); attribution only helps when the backbone can execute repaired reasoning.
  • Algorithm 2 hyperparameters (τ, B) and the LLM judge for agreement scoring are not numerically reported.
  • Only one model-generated repair span s′ tested per candidate; sensitivity to repair-span quality is not ablated.
  • Localization success conflates root-cause ID with repair-span adequacy — s′ is not a ground-truth edit.

04 Questions for Further Exploration

Open threads a follow-up would have to pull.

Q1

Does decoupling the hypergraph builder from the reasoner (e.g. builder = Claude Opus, reasoner = Qwen3-8B) change localization accuracy, given the current shared-LLM correlation?

Q2

What is HPFA's sensitivity to the verbal-confidence threshold τ and repair budget B — and were these tuned on the test set?

Q3

Can the conflation between root-cause ID and repair-span quality be separated by using oracle (ground-truth) repair spans s′ in the counterfactual test?

Q4

Why does the hypergraph hurt on 8.2-step GSM8K — small candidate set, failure-mode distribution, or noisy semantic merging — and could an adaptive "graph-only-when-long" policy recover the loss?

Q5

How does HPFA scale to truly long-horizon agent tasks (hundreds of steps, multi-tool) where the 1/p paired-rollout assumption may break down?

Q6

Can the rollout-grounded GRPO reward be combined with process-reward-model pretraining to further improve attribution calibration?
