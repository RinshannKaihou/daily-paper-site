> **一句话总结：** 该工作在 BrowseComp-Plus 上对 6 个长程搜索 Agent（gpt-oss-120b 到 GLM 5.1）做轨迹级诊断，发现搜索量与准确率几乎不相关（r=0.16 的上下文相关性），而累积检索召回与准确率高度对齐（r=0.99）；错误可二分为 retrieval gap 和 utilization gap，且最有力的 Agent（GLM 5.1, 74.1%）靠的是查询纪律（更少的重复查询、更少的浪费尾部）而非更多搜索。

> **TL;DR:** The paper opens up the trajectory (not just the final answer) of six ReAct long-horizon search agents on BrowseComp-Plus using human-annotated qrels, and shows that search effort (calls/context) is uncorrelated with accuracy (context r=0.16) while cumulative gold-evidence recall tracks it almost perfectly (r=0.99). On BrowseComp-Plus, GLM 5.1 tops accuracy at 74.1% with the fewest searches (~14 calls) versus gpt-oss-120b's 38.0% with the most (~33 calls); errors split into retrieval gaps (51.6–64.1% of failures for 5 of 6 agents) and utilization gaps, requiring opposite fixes (better queries vs. better verification). Findings replicate on a 200-question BrowseComp-en open-web sample where accuracy-coverage r=0.99 vs accuracy-calls r=0.12.

## 核心贡献

- 提出了一个**基于人工标注文档级相关性（qrels）的轨迹级诊断框架**，把 Agent 行为拆成"检索了什么证据"和"如何使用这些证据"两个阶段，使错误归因变得**确定性**（不依赖 LLM judge）。
- 在共享 ReAct 框架 + 共享 retriever（Qwen3-Embedding-8B）下，**横向对比 6 个 Agent**（Tongyi-DR、Qwen3.5-35B-A3B、gpt-oss-120b、Kimi K2.6、GLM 5.1、Deepseek V4 Pro），消除 setup 混淆。
- 提炼出 5 条贯穿症状→机制→处方的发现，最重要的两条是：(i) 累积召回是准确率的近乎完美预测器（Pearson r=0.99），而搜索量/上下文预算则否（r=0.16）；(ii) 错误二分为 retrieval gap（RG）与 utilization gap（UG），相同准确率的 Agent 可能需要完全相反的修复。
- 给出可操作的工程处方：弱 Agent 修查询（识别失败假设、避免重复查询），强 Agent 转向验证与答案归一化，对两者都需在 harness 层做 snippet-stream 管理、visit gating、evidence-driven stopping。
- 在 BrowseComp-en 开放网页 200 题复现主要结论，证明结论不是固定语料库伪迹。

## Key Contributions

- A **trajectory-level diagnostic framework** grounded in human-annotated document-level qrels, separating retrieval-side from utilization-side behavior so failure attribution is **deterministic** (decided by qrels, not an LLM judge).
- A **controlled cross-agent study of six agents** under one shared ReAct harness and one shared retriever (Qwen3-Embedding-8B, top-K=5), spanning two scale tiers (mid: Tongyi-DR / Qwen3.5-35B-A3B / gpt-oss-120b; frontier: Kimi K2.6 / GLM 5.1 / Deepseek V4 Pro).
- **Five durable findings**: effort ≠ accuracy; recall tracks accuracy; failures split into RG vs UG; evidence lands early or never with a wasted tail; strong agents win by query discipline.
- A **four-way error decomposition** (directional / last-hop RG; true-extraction / boundary UG) that prescribes agent-specific fixes rather than leaderboard-driven ones.
- An **oracle-reader ceiling analysis** (Oracle-E = 87.5%) and a **within-question panel regression** (4,919 trajectories) showing recall absorbs 56–60% of the stronger-agent edge and that closed-book success is ~2.2%.
- **Open-web replication** on BrowseComp-en (200 questions, 4 agents) confirming the coverage-effort dissociation.

## Methodology

- **Paradigm**: ReAct loop. Each step emits a reasoning trace τₜ and an action aₜ (either `search(query)`, `visit(doc_id)`, or terminal `answer`). A trajectory ξ = (τ₁,a₁,o₁,…,τₜ,aₜ).
- **Benchmark**: BrowseComp-Plus (830 English questions, ~100K-doc fixed corpus, human qrels in two layers: broader evidence-qrels E(q) averaging 6.10 docs/question, stricter gold-qrels G(q) ⊆ E(q) averaging 2.90 docs/question).
- **Retriever held fixed**: Qwen3-Embedding-8B, top-K=5 results per search, 512-token snippets. Only the agent policy varies.
- **Harness cap**: 128 turns / 150 minutes; exceeding either is "incomplete."
- **Episode decomposition**: trajectory split into episodes (one search + subsequent visits). Rₖ = evidence surfaced in episode k; Cₖ = cumulative; Δₖ = new evidence. k* = last episode with new evidence (productive phase); M−k* = wasted tail.
- **Failure labels**: correct / utilization gap (UG: failed but G*(ξ)≠∅) / retrieval gap (RG: failed and G*(ξ)=∅).
- **Oracle ladder**: strip search/visit tools, inject E(q) or G(q) directly into GPT-4o reader at temp 0 → Oracle-E ceiling.
- **String-similarity error typing** of wrong answers (subtle ≥0.85 / format 0.6–0.85 / misunderstanding <0.6) using normalized SequenceMatcher.
- **Query move classification**: repeat (Jaccard ≥0.85), pivot (<0.25), add/drop_constraint in between.
- **Within-question inference**: linear probability model on agent×question panel (4,919 trajectories) with question fixed effects, z-scored predictors, SEs clustered by question.
- **Open-web replication**: 200-question BrowseComp-en sample with a live commercial search API; since no qrels, an LLM judge supplies per-step "productive/redundant/unproductive" labels and per-question sufficiency.

## Results & Highlights

- **Effort dissociates from accuracy.** Final-context size vs accuracy Pearson r=0.16 (bootstrap CI [-0.06, 0.35]); search volume is anti-correlated at ρ=-0.77. The strongest agent GLM 5.1 (74.1% acc) uses a median of 14 search calls / 52K context; the weakest gpt-oss-120b (38.0% acc) uses 33 calls / 86K context.
- **Cumulative retrieval recall is the strongest correlate of accuracy**, r=0.99 (bootstrap CI [0.96, 1.00]) at K=25 padded cumulative recall; visit precision r=0.50 (fragile, CI [0.37, 0.62]).
- **A K=20-episode search cap retains 86.3–92.4% of each agent's accuracy**, and K=40 retains 97.0–99.8%, even though median rollouts use 14–33 calls — early stopping barely shortens typical trajectories.
- **Failure-mode split**: RG accounts for 51.6–64.1% of errors for 5 of 6 agents; Kimi K2.6 is the exception with 52.0% UG. Directional RG (no evidence doc reached) dominates at 55–67% of each agent's RG, peaking at 66.7% for Qwen3.5-35B-A3B.
- **Post-gold redundancy is high**: after the first gold hit, 57.9–74.0% of later episodes add no new evidence. 77.5–93.6% of all episodes are non-productive.
- **Oracle reader ceiling** Oracle-E = 87.5%, Oracle-G = 87.4% (only 0.1pp apart, so distractor density doesn't bind); Hard UG (irreducible even with evidence) is 12.5%. Per-agent Net Gain (Oracle-E − real accuracy) ranges from +13.4pp (GLM 5.1) to +49.5pp (gpt-oss-120b), with Spearman ρ>0.95 to qrels-RG ranking.
- **Within-question panel**: on 366 gold-hit-disagreement questions, retrieving agents answer correctly 73.8% of the time vs 2.2% for non-retrievers. Cumulative gold recall dominates the regression (+30pp per SD, t=34); recall absorbs 56–60% of each stronger agent's edge over gpt-oss-120b. Correct trajectories issue ~14 fewer search calls on average while achieving 54pp higher gold recall.
- **Format/subtle-error free loss**: Kimi K2.6 has 19.9% format-or-subtle error rate, GLM 5.1 18.6%, Qwen3.5-35B-A3B 17.7% — essentially recoverable by stripping markdown and normalizing case.
- **Repeat-querying is the cleanest behavioral predictor of failure**: gpt-oss-120b repeats on 5.0% of moves vs ≤1.5% for the other five; repeat rate correlates with accuracy at ρ=-0.83; reduces gold-hit probability by 1.9pp per SD (t=-3.4).
- **Search snippets dominate the context budget**: 66–85% of tokens come from snippets (Tongyi-DR at 85.0%), visit content only 2–16%, reasoning 3–25%. Tongyi-DR's 38.0% overflow is driven by snippet accumulation, not by documents it opens; its 11.3% "Bad-call" rate is a JSON-array schema mismatch artifact.
- **Open-web replication (BrowseComp-en, 4 agents)**: GLM 5.1 tops at 64.0% accuracy with ~65 calls; Deepseek V4 Pro spends the most at 81 calls for 61.5%; mid-scale Tongyi-DR 42.5% and Qwen3.5-35B-A3B 30.5%. Accuracy-coverage r=0.99 vs accuracy-calls r=0.12; RG dominates 68–88% of errors.

## Critical Assessment

- **Novelty**: High. The conjunction of (a) per-query document-level qrels, (b) multiple agents, and (c) a single shared harness+retriever is what makes the RG/UG attribution deterministic and the cross-agent comparison fair — the paper explicitly argues no prior process-level agent study (Ning et al.'s 14M-log analysis, Chen et al.'s BrowseComp-Plus retrieval-backend comparison, AgentIR, TRACE, BrowseConf, the overthinking work of Cuadron et al.) combines all three. The deterministic (qrels-based) failure taxonomy is the genuine new contribution; much prior process work relies on LLM judges and is therefore entangled with answer-correctness noise.
- **Rigor**: Strong. The authors are honest that the cross-agent Pearson correlations are over only six points and treat them descriptively, then back them up with (i) a paired bootstrap with B=10,000 and leave-one-agent-out, (ii) a within-question panel with question fixed effects and clustered SEs, and (iii) a held-out open-web replication. The four-way error decomposition and oracle-reader ladder are well-designed controls. They also pre-register caveats (e.g., the dAcc_K upper bound assumes the eventual answer is unchanged under early stopping).
- **Reproducibility**: Good in principle. Same retriever, same corpus, open-weights models, planned code/data release. Caveats: frontier-tier models (Kimi K2.6, GLM 5.1, Deepseek V4 Pro) are accessed via provider APIs whose checkpoints/sampling may drift; the GPT-4o judge (gpt-4o-2024-08-06, temp 0) is a single point of failure for end-to-end accuracy; BrowseComp-Plus is the sole fixed-corpus benchmark (the authors justify this by noting it is the only public benchmark with the required per-query qrels).
- **Significance**: Practically important. It cleanly refutes the implicit "more search = better" assumption underlying deep-research leaderboards and prescribes per-agent interventions. The 26-point gold-recall spread on a fixed retriever is by construction query-side, quantifying how much headroom lies in query formulation alone.
- **Red flags / specific concerns**:
  - **Tongyi-DR comparisons are confounded by a harness–scaffold mismatch**: 11.3% Bad-call rate (JSON-array query passed to a single-string schema) means ~1 in 9 intended searches never reach the retriever; the authors are transparent about this and treat it as a harness artifact, but it does mean Tongyi-DR's numbers are not clean.
  - **Tongyi-DR's overflow subset is systematically harder** (other five agents score 10.5–59.0% on it vs full set), so its 84.1% answered-only accuracy vs 52.2% overall partly reflects an easier residual — the paper concedes this in footnote 3.
  - **The within-question panel cannot separate query skill from knowledge-informed querying** — the authors explicitly note recall "cannot separate query skill from parametric knowledge," so the strong causal story (queries drive accuracy) is technically an upper bound.
  - **Missing ablations**: no controlled intervention experimentally validates that the prescribed fixes (reformulation guards, snippet-stream management, evidence-driven stopping) actually reclaim the predicted headroom; the paper is candid that "our numbers are upper bounds rather than realized gains."
  - **The open-web replication has only 4 agents and uses an LLM judge as a qrels proxy**, weakening the strongest claim (r=0.99 accuracy-coverage) to a 4-point correlation; the authors note this is "directional" and lean on BrowseComp-Plus for the ordering.
  - **Benchmarks are contemporary/fictional 2025–2026 systems** (Kimi K2.6, GLM 5.1, Deepseek V4 Pro technical reports), so absolute numbers will age quickly; the qualitative findings should be more durable.

## Strengths

- Deterministic, qrels-grounded attribution that does not rely on an LLM judge for the failure taxonomy — a methodological advance over prior process analyses.
- Clean experimental control via shared harness + shared retriever; the 26-point recall spread is provably query-side.
- Layered evidence (cross-agent correlations → bootstrap → within-question panel with FE → oracle reader → open-web replication) is more rigorous than typical agent-analysis papers.
- Honest about limitations: acknowledges correlations are over six points, that intervention gains are upper bounds, that Tongyi-DR has a schema artifact, that LLM-judge open-web replication is underpowered.
- Actionable, per-agent prescriptions rather than one-size-fits-all recommendations.
- Reproducible setup: open-weights agents, public benchmark, promised code/data release.

## Limitations

- **Single fixed-corpus benchmark** (BrowseComp-Plus). The authors justify this but it limits generalization to multi-hop QA, math, or code agents.
- **No experimental validation of the prescribed fixes** — the paper quantifies headroom but does not implement and test reformulation guards, snippet management, or evidence-driven stopping.
- **Frontier-tier models via proprietary APIs** introduces potential drift and reduces exact reproducibility.
- **End-to-end accuracy rests on a single GPT-4o judge**; the authors localize judge noise to the accuracy axis but do not double-judge.
- **Six agents is a small N for cross-agent correlation**; the bootstrap and within-question analyses mitigate but do not eliminate this.
- **The within-question regression cannot fully separate query skill from knowledge-informed querying**, leaving the causal interpretation as an upper bound.
- **Tongyi-DR's harness mismatch** (JSON-array query schema) inflates its apparent failure rate; comparisons involving it should be read with this caveat.
- **No human evaluation** of the subtle/format error categories; the SequenceMatcher thresholds (0.85/0.6) are heuristic.

## Relevance

对构建长程 deep research / search agent 系统具有直接诊断价值：它告诉我们搜索量与上下文预算不能预测准确率，真正的瓶颈在查询质量与证据召回（cumulative gold recall），并给出 RG/UG 错误二分法来指导 per-agent 的修复（查询改写 vs 验证归一化），同时提出 evidence-driven stopping 和 snippet-stream 管理等可落地的 harness 级改进。

## Questions for Further Exploration

- Do the prescribed interventions (reformulation guards, snippet dedup/aging, evidence-driven stopping, visit gating, answer normalization) actually reclaim the predicted headroom when implemented and ablated in isolation?
- How do the RG/UG ratios shift on multi-hop reasoning benchmarks (e.g., MuSiQue, FRAMES) where the question structure forces sequential evidence dependence?
- Can the deterministic qrels-grounded taxonomy be extended to open-web settings without an LLM judge, perhaps via cached page-level annotations or retrieval-aware synthetic qrels?
- Is the within-question "73.8% vs 2.2%" gap partly attributable to parametric knowledge guiding queries, and how would a closed-book control separate the two?
- Does query batching (the only behavior surviving agent FE) transfer causally, or is it a marker of models that happen to be strong for other reasons?
- How stable are the findings as frontier models update — will GLM 5.1-class agents still sit near the oracle ceiling in 6–12 months, or will the bottleneck shift back to retrieval?
- Can the wasted-tail metric (M−k*) be used as a training signal for RL-based stopping policies, complementing BrowseConf-style confidence scaling?
