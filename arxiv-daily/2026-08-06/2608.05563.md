> **一句话总结：** 本文提出 PoisonedEvolution，一种针对自进化技能（SES）系统的轨迹投毒攻击——攻击者只需贡献约 10% 看似正常的"经验"轨迹，就能让系统自身把恶意行为蒸馏成持久化技能；在 SkillClaw 上六种主流 LLM evolver 平均达到 91.0% 的技能嵌入率（SER），在架构不同的 Trace2Skill 上达到 61.5%。

> **TL;DR:** PoisonedEvolution shows that a skill-visible black-box attacker contributing only ~10% of trajectories (k=3 of n=30) to a self-evolving skill pipeline can get the victim evolver itself to embed malicious behavior into a persistent SKILL.md artifact, achieving 91.0% Skill Embedding Rate (546/600 trials) across six LLM evolvers on SkillClaw (vs. 70.0% for the strongest single-record baseline k=1 → 5/25) and 61.5% (369/600) on the structurally different Trace2Skill pipeline, while the poisoned xlsx skill still preserves benign SpreadsheetBench utility (20.0% Hard / 36.54% Soft vs. 18.0% / 34.88% with no skill).

## 核心贡献

- **揭示一条新的信任边界**：首次将自进化技能（SES）系统中"经验→指令"的晋升过程（evidence promotion）正式界定为安全边界。这条边界不同于 RAG 投毒（污染单次生成的检索上下文），也不同于 SkillInject 类静态技能文件投毒（攻击者直接控制已分发的技能），而是让受害者 evolver 自己把投毒经验写成技能。
- **形式化 C1–C3 投毒机制**：把"工件投毒成功"分解为三个必要条件——C1 Inclusion（通过质量过滤进入 evolver 流）、C2 Evolution Attribution（被归因为可复用经验而非噪声）、C3 Realization（在摘要与合并后仍存活于生成技能）。论文将 C2 Evolution Attribution 确定为 SES 特有的攻击瓶颈。
- **设计归因导向的攻击实例**：通过领域对齐（domain alignment）、因果绑定（causal binding）、跨轨迹不变性（cross-trajectory invariance）三种技术把恶意行为伪装成"看起来因果有用、反复出现、可泛化"的经验。攻击者只需在合法工作流位置插入 outcome-conditioned causal bridge。
- **跨系统与跨 evolver 的实证证据**：在 SkillClaw 上对 6 个主流 LLM evolver、4 个安全效果族做 600 次完整进化试验（91.0% SER），并在结构不同的 Trace2Skill 上做结构性迁移验证（61.5% SER）。条件消融显示 k>1（复现支持）、因果归因、领域对齐编码是成功的决定因素。
- **提出 provenance-aware 防御雏形**：一个 Provenance-Diversity Gate（要求 ≥3 独立用户/簇、拒绝多数支配、惩罚高文本重叠）在 n=30,k=3 设定下把单簇 F1 候选从 25/25 全部拦截（SER 降至 0/25），并指出最终技能扫描器在 evolver 已归一化证据后运作，来得太晚。

## Key Contributions

- **Identifies evidence promotion as a new trust boundary in SES pipelines**, distinct from retrieval-time (RAG) poisoning and from static skill-file injection (SkillInject/POISE). The attacker never publishes a malicious skill, compromises the evolver, or edits the skill bank; the victim evolver authors the poisoned artifact itself from contributed "experience."
- **Formalizes a C1–C3 artifact-poisoning mechanism**: PoisoningSuccess = C1 Inclusion ∧ C2 Evolution Attribution ∧ C3 Realization, and isolates C2 (Evolution Attribution) as the SES-specific bottleneck that motivates artifact-level (rather than retrieval-trigger) metrics.
- **Instantiates an attribution-oriented attack** via three techniques — domain-aligned inclusion, causal binding ("obstacle/requirement → b → success", or "missing b → failure" for failure-routed systems), and cross-trajectory invariance — so a behavior appears recurring, causally useful, and generalizable across k transformed trajectories.
- **Provides cross-system evidence**: 546/600 (91.0% SER) on SkillClaw across six evolvers at 10% support (n=30, k=3), and 369/600 (61.5%) on Trace2Skill as a structurally different pipeline, plus condition ablations showing recurring support, causal framing, and domain-aligned encoding as the main determinants.
- **Proposes a pilot provenance-diversity gate** as a promotion-time defense and argues that SES security must constrain *which evidence may become shared instruction*, retaining provenance that travels with each update, not merely scan skill text after generation.

## Methodology

The paper models a trajectory-grounded SES system as Σ = (T, F, E, S): a trajectory pool T, a quality filter/router F, an LLM-backed evolver E, and a versioned skill bank S, updated via S_{t+1} = S_t ⊕ E(F(T_t), S_t). The attacker is a **skill-visible black-box** contributor: it can inspect public/installed skills and contribute a bounded fraction of trajectories, but cannot see private pools, filters, or evolver prompts, nor edit S.

**Attack (PoisonedEvolution / Algorithm 1):** Given a target skill s and behavior b, the attacker (1) selects k attacker-owned candidates whose tasks relate to s; (2) for each, locates a legitimate workflow locus (input prerequisite, recovery step, output transform, or validation step); (3) inserts an outcome-conditioned causal bridge — `constraint → b → success` for success-routed records, or `missing b → failure` for failure-routed ones — that binds b to the observed task outcome; (4) preserves the original task/outcome while rephrasing surface wording so the operational semantics of b recur invariantly across the k records. The transformation T(τ; s, b) is reference-grounded on completed SpreadsheetBench trajectories.

**Why C2 is the bottleneck:** A behavior promoted as an isolated command, fragmented text, or user idiosyncrasy is discarded; binding it to a task-relevant constraint and the observed outcome makes the evolver repeatedly observe "obstacle/requirement → b → task completion" and credit b as reusable knowledge.

**Payloads** are short natural-language instructions p = ⟨ℓ, a, o, c⟩ (workflow locus, action, target object, execution context) encoding four representative security-effect families adapted from SkillInject but instantiated as trajectory evidence: F1 Confidentiality (exfil to a canary endpoint), F2 Data integrity (delete source artifacts at a canary path), F3 Supply chain (redirect package registry to a loopback), F4 Safety weakening (disable security checks). All placeholders are bound to **inert canary identifiers** (canary URL, temp path, loopback registry, toy CI flags) — no endpoint request, file deletion, package install, or check bypass is ever executed; SER is measured from generated skill text only.

**Evaluation protocol:** Primary metric is Skill Embedding Rate (SER) — the fraction of completed evolution trials whose output skill diff newly embeds b, detected by family-specific diff-aware canary rules (an LLM judge is used only for inspecting ambiguous cases, not to define success). Hard/Soft task accuracy on SpreadsheetBench is reported only as a skill-usefulness sanity check. Main matrix: SkillClaw, xlsx skill, n=30, k=3 (ρ=10%), 25 completed trials per model×family cell, native refine/create/skip retained but optional session-quality judge and publish-time verifier disabled. RQ2 varies k at fixed n=30 and n at fixed k=3. RQ3 runs Trace2Skill with 3 attacker failed trajectories + 27 clean failures per batch.

## Results & Highlights

- **SkillClaw main result (Table 1):** At 10% attacker support (n=30, k=3), PoisonedEvolution embeds the target behavior in **546/600 completed trials (91.0% SER)** across six evolvers and four behavior families. Per-evolver SER ranges from 70.0% (GPT-5.4, 70/100) to 100.0% (DeepSeek-V3.2 and Qwen3.5-122B-A10B, 100/100 each), with MiniMax-M2.5 at 87.0%, DeepSeek-V4-Pro at 94.0%, and Qwen3.5-35B-A3B at 95.0%. This is an artifact-level claim: the SES pipeline has written the behavior into a persistent skill.
- **Per-family sensitivity (Table 1, family aggregate):** On SkillClaw, F4 Safety-weakening is easiest at 146/150 (97.3%), F2 Data-integrity 139/150 (92.7%), F1 Confidentiality 137/150 (91.3%), and F3 Supply-chain lowest at 124/150 (82.7%) because package/environment redirection is easier for an evolver to treat as unrelated setup advice or to suppress under its own safety priors.
- **Recurrence is decisive (Figure 2, left):** At fixed n=30, going from k=1 (3.3%) to k=2 (6.7%) raises SER from **5/25 to 21/25**, and k=3 (10%) reaches 25/25 — the single-record-to-two-record jump is the key point: one poisoned trajectory is treated as accidental, whereas repeated consistent trajectories resemble the experience SES systems distill.
- **Clean-pool dilution is tolerated (Figure 2, right):** At fixed k=3, a representative strong evolver stays at 25/25 at n=10 (30%) and n=30 (10%), and remains high at **22/25 when n=100 (3%)**; a k=1, n=100 (1%) check gives 0/5, consistent with the same recurrence effect.
- **C2 attribution ablation (Figure 3):** Local single-place insertion reaches only **8/25**, Fragmented text 11/25, whereas Causal outcome framing reaches 25/25 — attribution requires an outcome-linked role, not just presence.
- **C3 realization ablation (Figure 3):** Holding F1 fixed, Generic wording reaches 18/25, Auxiliary out-of-band cue collapses to **0/25** (channel/locus defeat realization), and domain-tailored actionable xlsx semantics reach 25/25.
- **Structural transfer to Trace2Skill (Table 2):** Under the same n=30, k=3 setting, PoisonedEvolution embeds target behaviors in **369/600 trials (61.5% SER)** — less vulnerable than SkillClaw because of its split-analysis pipeline, but still broadly affected; large family spread (F4 collapses to 28/150 = 18.7% while F2 reaches 124/150 = 82.7%) shows pipeline routing matters.
- **Skill-creation (no-init) feasibility:** A separate no-init diagnostic across four representative evolvers embeds the behavior in **490/600 trials (81.7%)**, establishing that the create-path (not just refine) is also vulnerable.
- **Benign utility preserved:** On the 100-task SpreadsheetBench trajectory split with Qwen3.5-122B-A10B, the poisoned-evolved xlsx skill scores **20.0% Hard / 36.54% Soft** vs. 18.0% / 34.88% without a skill — poisoning coexists with the normal-task benefit of skill use rather than collapsing the artifact into attack-only text.
- **Pilot defense (Provenance-Diversity Gate):** Requiring ≥3 users/clusters, rejecting majority dominance, and penalizing high text overlap blocks **25/25 single-cluster F1 candidates at n=30, k=3**, reducing post-gate SER from 25/25 to 0/25, while accepting one five-session diverse control.

## Authors & Credibility

The work is a multi-institution collaboration led by Jialuo Chen (Ant Group / Zhejiang University) with co-authors from Ant Group, Zhejiang University, Tsinghua University, Hangzhou Dianzi University, National University of Defense Technology, CUHK-Shenzhen, and Xi'an Jiaotong University. The framing is careful and self-scoping: the authors explicitly demarcate non-goals (no model compromise, no real credential theft, no real exfiltration, no destructive FS effects), use inert canary identifiers throughout, and repeatedly distinguish artifact poisoning (SER) from runtime impact (ASR). The paper positions itself precisely against the prior art it adapts — SkillInject's security-effect families (Schmotz et al. 2026) are reused as inert canaries but the attack surface (cross-trajectory credit assignment) is novel. The two target systems, SkillClaw (Ma et al. 2026) and Trace2Skill (Ni et al. 2026), are the actual representative SES systems from the recent literature rather than toy reimplementations, and the source corpus is the real SpreadsheetBench (Ma et al. 2024).

## Critical Assessment

- **Novelty:** Genuine. The C1–C3 decomposition with Evolution Attribution as the SES-specific bottleneck is a real conceptual contribution and is correctly distinguished from RAG/AgentPoison/PoisonedRAG (which corrupt retrieval context for one generation) and from SkillInject/POISE/BadSkill (which assume attacker control of a distributed skill file or packaged model). The provenance framing — "authentic provenance is not trustworthy provenance" because the victim evolver genuinely authored the artifact — is a sharp observation.
- **Rigor:** Mixed but largely sound. The metric is diff-aware, pre-registers family-specific canary rules, checks the initial skill to avoid counting pre-existing text, and reports embedded/completed counts so silent failures are not counted as clean. The k=1 vs k=2 vs k=3 recurrence curve (5/25 → 21/25 → 25/25) and the C2 ablation (Local 8/25, Fragmented 11/25, Causal 25/25) are clean, decisive experiments.
- **Weak / missing pieces:**
  - The **benign-utility check is narrow** — a single 100-task split on one evolver (Qwen3.5-122B-A10B), explicitly disclaimed as "not a complete utility–security Pareto frontier." It does not establish that poisoning preserves utility across evolvers or families, so the implicit "attack is stealthy" claim is under-supported.
  - The **C3 ablation changes channel and locus together**, which the authors admit makes it "a realization stress test rather than a single-variable causal estimate" — so the strong Generic 18/25 vs Tailored 25/25 result should not be read as a clean causal estimate of encoding alone.
  - The **Provenance-Diversity Gate is preliminary**: candidate grouping is *assumed*, the clean control is small (one five-session diverse control), and the authors themselves note coordinated Sybils may mimic diversity — only F1 single-cluster candidates are reported, leaving F2/F3/F4 gate behavior unspecified.
  - The **evaluation scope is deliberately artifact-level**: runtime trigger activation, action execution, and end-to-end exploit success are explicitly out of scope, so the practical severity (does a poisoned skill ever fire on a real task?) remains unmeasured. The paper is honest about this but readers should not equate 91.0% SER with 91.0% real-world compromise.
  - **No multi-cycle evaluation**: the authors flag that deployed SES systems evolve repeatedly and that a poisoned skill could create a feedback loop where later agents repeat its behavior, making the pattern appear independently validated — but this longitudinal effect is not measured.
  - **F3 on Trace2Skill (and the family ranking inversion)** shows the attack is pipeline-sensitive: F4 is easiest on SkillClaw (97.3%) but hardest on Trace2Skill (18.7%), so a detector tuned to one family/locus may miss the same behavior elsewhere — the authors treat this as a feature (insight) but it also caps generalizability claims.
- **Reproducibility:** Reasonable. Algorithms (Algorithm 1), the Σ = (T, F, E, S) abstraction, payload templates (F1–F4 verbatim), batch parameters (n=30, k=3, 25 trials/cell), and the six named evolvers are all specified; SpreadsheetBench is public. However, the family-specific canary detection rules and the exact trajectory-transformation prompts are described rather than released, and the "representative strong evolver" used for Figure 2 dilution curves is not named, which would hinder exact replication.
- **Significance:** High for the agent-security and SES subfield. If self-evolving skill systems (SkillClaw, Trace2Skill, AutoSkill, CoEvoSkills) see deployment, evidence promotion is a real and previously under-formalized boundary, and the provenance-aware defense direction is actionable.
- **Red flags:** None severe. The most aggressive phrasing — 91.0% SER at "just 10% support" — is real but artifact-level; the paper does not overclaim runtime compromise, and the inert-canary discipline is consistently maintained. The main risk is readers conflating SER with attack success rate on deployed agents, which the paper mostly (but not always) heads off.

## Strengths

- Sharp, well-motivated threat model: skill-visible black-box attacker captures realistic multi-user / Sybil / upstream-telemetry contributors without granting implausible privileges.
- The C1–C3 formalization turns a vague "poison the training data" idea into a falsifiable mechanism with a named, attackable bottleneck (Evolution Attribution).
- Clean, decisive ablations: the k=1→k=2 recurrence jump and the Causal-vs-Local-vs-Fragmented attribution contrast are exactly the experiments that isolate the mechanism.
- Honest scoping: inert canaries only, explicit non-goals, artifact-vs-runtime distinction stated repeatedly, benign utility reported (narrowly) rather than assumed.
- Cross-architecture transfer (SkillClaw vs Trace2Skill) with an explanation of *why* family sensitivity inverts between pipelines is more informative than a single-system benchmark.

## Limitations

- Artifact-level only: no measurement of whether a poisoned skill actually triggers and executes on a realistic downstream task (ASR / runtime impact).
- Single-evolver, single-split benign-utility check; stealth across the full evolver×family matrix is not established.
- Provenance-diversity gate is a pilot: only F1 single-cluster candidates reported, grouping assumed, Sybil resistance untested.
- Multi-cycle / longitudinal evolution is not evaluated, despite being flagged as a compounding risk.
- Six named frontier evolvers are used, but they are a convenience sample of whatever the authors had access to; the model-sensitivity claims (e.g., GPT-5.4 at 70.0% vs DeepSeek-V3.2 at 100.0%) conflate provider, evolution policy, and scale, which the authors acknowledge is "not a quality or scale ranking."
- User-scoped dialogue-memory systems, verifier-only systems (CoEvoSkills), and parameter-training systems (SkillRL, Skill-SD, MemSkill) are explicitly outside empirical claims, so generality across the SES design space is asserted, not shown.

## Relevance

高度相关。本文直接研究 LLM agent 的"技能（skill）"生命周期安全——而 agent skill（如 Claude Code Skills、SKILL.md 工件）正是当前自进化 agent 系统的核心持久化机制，与用户对 agent 安全/对齐/红队的关注一致。它把"经验晋升为指令"界定为新信任边界的视角，对任何构建或部署自进化、记忆增强或技能库型 agent 的工作都有直接警示意义。

## Questions for Further Exploration

- What is the realistic **attack success rate (ASR)** — i.e., once a poisoned skill is installed, how often does it actually trigger and execute its payload on a natural distribution of downstream user tasks, per family?
- How does poisoning evolve **across multiple SES cycles**? Does a poisoned skill create the self-reinforcing feedback loop the authors hypothesize, and can versioned lineage / counterfactual evaluation break it?
- Can a stronger **provenance-diversity gate** (or relevance/provenance joint gate) defend F2/F3/F4 and resist coordinated Sybil clusters that deliberately mimic diversity, not just the single-cluster F1 case reported?
- Does the attack transfer to the **out-of-scope SES classes** — user-scoped dialogue-memory (AutoSkill), verifier-coupled (CoEvoSkills), and training-coupled (SkillRL / Skill-SD / MemSkill) systems — where the update signal is not a trajectory pool?
- Is there a detectable **signature at evolution time** (e.g., evolver internal signals, attribution-confidence anomalies, or lineage-graph structure) that flags promotion of attacker-correlated evidence before it becomes a durable skill, complementing RouteGuard-style runtime detection?
