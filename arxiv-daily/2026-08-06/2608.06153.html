Why This Matters

It models a skill bank as a globally optimized, relation-aware structure and turns local traces into reusable capabilities — a directly portable blueprint for composable, self-evolving LLM agents.

02

Methodology 方法

A feedback loop over a skill-augmented agent; expected success is treated as a function of the skill bank D.

Goal: find D* = argmaxD 𝔼task∼𝒯[ success(D, task) ]
  1. Trace collection. Instrument OpenHands / mini-SWE-agent to log reasoning, tool calls, params, env feedback, outcome. A simplification pass strips find/grep dumps & raw file reads, keeping commands, paths, key errors.
  2. Evolution proposal. Update agent (DeepSeek-V4-Flash) does hierarchical failure diagnosis → navigation / reasoning / execution root cause, then consults the SRG (nodes = skills; edges ∈ dependency, co-usage, conflict). Each proposal is DSL-encoded (target / op / content / rationale / expected / relations) and locally replayed; failures discarded before any generalization cost.
  3. Skill generalization (Alg. 1). Cluster proposals by affected-skill set or semantic similarity; a merge agent abstracts shared patterns (e.g. "collection-size bug" + "auth-state bug" → value-triggered vs. state-triggered). Candidate bank is committed only if replay preserves/improves performance — the regression gate. State in SQLite; skill bank versioned via Git worktree.
What the Skill Relation Graph actually encodes

A directed graph whose three edge types let proposals propagate: when a skill is edited, GSE retrieves neighbors plus semantically related skills (via capability-category / task-type / execution-stage metadata) and emits auxiliary proposals that co-evolve them — preserving global consistency. The ablation shows removing the SRG costs ~4 F1 points on both tasks.

06

Strengths vs Limitations 长处与局限

▲ Strengths

  • Global-optimization framing with SRG as a first-class co-evolved object, not an afterthought.
  • Replay-driven acceptance is a model-agnostic defense against the exact failure mode it diagnoses (overfitting + regression).
  • Broad coverage: two tasks · two open harnesses · one industrial agent · two languages · held-out protocol.
  • Honest cost analysis — GSE is cheaper at inference than every skill-bearing baseline.
  • Ablation cleanly isolates both mechanisms; generalization is decisive on filtering.

▼ Limitations

  • 108 focal methods on the headline benchmark; no per-project variance / CIs despite API-level non-determinism at temp 0.
  • Live-SWE-agent & Trace2Skill evaluated off primary design intent → favors GSE.
  • SRG quality never measured — no edge-inference precision, conflict-detection accuracy, or graph-growth curve.
  • No artifacts, prompts, or datasets released — main reproducibility risk.
  • Absolute test-gen F1 still ≤ 0.38; clustering & replay heuristics under-specified.
07

Open Questions 待探索

  1. Does GSE degrade gracefully when SRG edges are noisy — or does propagation amplify errors?
  2. Could the SRG be pruned to conflict-edges only without losing much?
  3. Do generalized skills transfer cross-language / cross-domain (evolve on Java, eval on Python)?
  4. Can the replay gate be made cheaper (a learned regressor) to cut the +12.3% evolution tax?
  5. Does the framing extend to policy-level skills (agentic RL), where SRG models policy compatibility?
