> **一句话总结：** APQF 是一个由 LLM 智能体驱动的端到端模型压缩流水线，用 profiling 智能体测量逐层敏感性、再由 LLM 决定逐层剪枝比例与混合精度位宽、最后用 PEFT/知识蒸馏恢复精度，在 ImageNet 与 CIFAR-10 上把 ResNet/VGG/ViT/DeiT/Swin 的计算量压到原始 BOP 的 5.6%–7.7%（13–18 倍）的同时保持接近基线的精度。

> **TL;DR:** APQF is the first framework to couple LLM-guided, profiling-grounded planning with a fully training-aware pipeline of structured pruning + mixed-precision QAT + recovery, applied across both CNNs and vision transformers. On ImageNet-1K (under a 200K-image budget) it stays ~17 Top-1 points above the joint pruning–quantization baseline GETA (68–77% vs 51–59%) while reaching 5.6–7.7% relative BOPs (13–18× reduction); on VGG7/CIFAR-10 it hits 93.15% accuracy at just 0.41% Rel. BOPs, beating GETA's 92.57% and improving over its own FP32 baseline (+0.20) — the only sub-0.5% method to do so.

## 核心贡献

- **Profiling 智能体作为决策依据：** 用 ptflops + torch.profiler 测量逐层 MAC/参数/时延分布，再通过 DepGraph 对每个结构组做不同剪枝比例下的经验敏感性扫描，生成一张逐组 accuracy–cost 敏感性表（CSV）+ 由 LLM 聚合的架构简报，使后续所有压缩决策都建立在"实测证据"而非手工启发式之上。
- **LLM 引导的多阶段结构化剪枝 + 自适应恢复：** PrunerAgent 让 LLM 基于敏感性数据为每个依赖组分配不同的剪枝比例，并通过"累积式回放"（从原始模型重剪而非在已剪枝模型上再剪）避免增量剪枝停滞；每阶段根据 Top-1 掉幅 δ（阈值 τ1=2%、τ2=4%）自适应决定跳过恢复 / PEFT 恢复 / 两阶段（PEFT+全量）恢复。
- **LLM 引导的混合精度 QAT + 蒸馏：** QuantAgent 让 LLM 从 {2,4,6,8,16,32} 位中为每层选位宽（用户可选 conservative/balanced/aggressive 提示），用 Brevitas 模拟量化并以冻结的全精度 teacher 做温度缩放 KL + 硬标签交叉熵的联合蒸馏训练，再加可选的 post-QAT KD 恢复阶段。
- **架构无关 + LLM 无关：** 同一套流水线在 ResNet/VGG（CNN）和 ViT/DeiT/Swin（Transformer）上无改动运行；通过 OpenRouter 标准接口接入，对 Swin-Tiny 测试的 6 个 LLM（含 DeepSeek、Gemma 等免费开源权重模型）精度都稳定在 97.4%–97.9%，不绑定任何高端商业模型。
- **数据高效的压缩范式：** 与 GETA 那种"端到端把整个网络重优化成稀疏低精度子网"不同，APQF 直接从预训练权重按实测敏感性剪枝、再用蒸馏/PEFT 恢复，因此在 200K 图像的小预算下大幅领先需要海量数据才能收敛的联合优化方法。

## Key Contributions

- **ProfilingAgent producing a measured sensitivity map:** Combines ptflops + torch.profiler for per-layer MAC/parameter/latency distribution with an empirical DepGraph sensitivity sweep (prune each dependency group at each candidate ratio, evaluate, record Δaccuracy + parameter/MAC cut), then uses an LLM to aggregate the verbose raw profile into a compact architecture brief. This measured evidence, rather than hand-designed magnitude/norm heuristics, grounds all downstream decisions.
- **LLM-guided multi-stage structured pruning with cumulative replay:** The PrunerAgent lets the LLM assign per-group pruning ratios (not a single uniform ratio), and crucially accumulates selected groups across stages and replays them from the original model — sidestepping the well-known DepGraph failure mode where pruning an already-pruned checkpoint yields little extra reduction and stalls before the target.
- **Adaptive, recovery-aware fine-tuning via thresholds:** After each stage the Top-1 drop δ triggers different recovery (τ1=2%, τ2=4%): skip / PEFT (LoRA, DoRA, rsLoRA, PiSSA, LoRA+) / two-stage PEFT-then-full fine-tune on the final stage. Intermediate recovery is explicitly framed as an accuracy-feedback mechanism that keeps the next LLM decision from being overly conservative.
- **LLM-guided mixed-precision QAT with knowledge distillation:** QuantAgent lets the LLM pick a per-layer bit-width from {2,4,6,8,16,32} under a user-set aggressiveness prompt, instruments the model with Brevitas, and trains the quantized student against a frozen full-precision teacher with `L = α·L_KD + (1−α)·L_CE` (temperature-scaled KL + cross-entropy), followed by an optional post-QAT KD recovery pass kept only if it improves accuracy.
- **Architecture-agnostic and LLM-agnostic pipeline:** One framework covers both CNNs (ResNet, VGG) and vision transformers (ViT, DeiT, Swin) with no architecture-specific rules; planning goes through OpenRouter so any LLM can be swapped in. Validity checks reject invalid layer names/bit-widths before execution (e.g., PiSSA is auto-rejected for conv-only models).

## Methodology

APQF is organized as five cooperating agents forming an end-to-end pipeline over a pretrained vision model:

1. **ProfilingAgent** (Section 3.1) — Produces (a) a static cost map via ptflops (per-layer MACs/parameters) and torch.profiler (CPU/GPU execution time), LLM-aggregated into an *architecture brief*; and (b) a *DepGraph sensitivity sweep*: for each dependency group and each candidate pruning ratio, prune + evaluate + record the accuracy drop and achieved parameter/MAC cut, yielding a per-group sensitivity CSV. The brief + CSV together are the measured evidence consumed by every downstream decision.

2. **PrunerAgent** (Section 3.2) — Given a user target reduction ρ* and max stages N, the LLM proposes a per-group pruning strategy conditioned on the profiling data, current reduction, remaining gap, and history. Validated groups are accumulated and replayed from the original model (cumulative replay), not incrementally from the pruned checkpoint. After each stage, δ is measured and the FineTuningAgent is invoked adaptively (Algorithm 1).

3. **QuantAgent** (Section 3.3) — The LLM proposes a per-layer bit-width from {2,4,6,8,16,32} (2-bit reserved for architectures like VGG), conditioned on the profiling brief, pruning sensitivity, surviving-module list, and a user-set prompt type (conservative/balanced/aggressive). The model is instrumented with Brevitas fake-quant modules, calibrated, and trained via KD against a frozen full-precision teacher with loss `L = α·L_KD + (1−α)·L_CE`, where `L_KD = T²·KL(q_t‖q_s)`. The LLM also picks QAT hyperparameters (LR, epochs, warmup, weight decay, batch size, calibration samples).

4. **FineTuningAgent** (Section 3.4) — A shared recovery component. Post-pruning it supports full fine-tuning, five PEFT variants (LoRA, DoRA, rsLoRA, PiSSA, LoRA+), and a two-stage PEFT-then-full mode for the largest final-stage drops; post-quantization it runs an optional KD pass (teacher configurable as the pruned or original model), retained only if accuracy improves.

5. **EvaluationAgent** (Section 3.5) — Deterministic, no LLM. Uses a single fixed-seed, class-balanced validation manifest so baseline/pruned/quantized models are compared on identical examples. Reports Top-1, Top-5, parameter count, and *Rel. BOPs* — `BOPs = Σ_l M_l · b_w^(l) · b_a^(l)` normalized to the FP32 model, capturing both pruning (lower M_l) and quantization (lower b_w,b_a) in one architecture-normalized number.

The experimental setup covers ImageNet-1K (1.28M train / 50K val) and CIFAR-10, on ResNet-20/50, VGG7, ViT-Small, DeiT-Tiny, Swin-Tiny, implemented in PyTorch 2.6.0 + CUDA 12.4 on H200 (141GB) / A100 (40GB) nodes. ImageNet compression results use a deliberately constrained 200K-image (200/class) subset; the GETA comparison additionally activates the optional post-QAT KD on the full set for ~5 epochs.

## Results & Highlights

- **ImageNet-1K, conservative QAT, 200K-image budget (Table 1):** APQF cuts compute to **Rel. BOPs 5.63%–7.74% of FP32 (≈13–18× reduction)**. DeiT-Tiny *gains* accuracy (66.52% → 67.90%, Δ +1.38), ViT-Small drops only −3.37 (79.87% → 76.50%), while heavier-compression ResNet-50 (80.13% → 72.73%, Δ −7.40) and Swin-Tiny (80.61% → 74.16%, Δ −6.45) show moderate drops.
- **ImageNet under the same 200K budget vs GETA (Figure 5):** APQF retains **68–77% Top-1** while GETA's single-run joint optimization collapses to **51–59% Top-1 — roughly a 17-point gap** — because GETA's end-to-end re-optimization needs large data to converge, whereas APQF prunes from measured sensitivity and recovers via KD/PEFT.
- **ImageNet full-data comparison (Table 2):** With APQF additionally running ~5 epochs of post-QAT KD, APQF achieves **~3× lower Rel. BOPs than GETA** at comparable accuracy: ViT-Small APQF 78.26% at 5.73% BOPs vs GETA 80.12% at 19.37% BOPs; DeiT-Tiny APQF 69.51% (+2.99) at 6.11% BOPs vs GETA 72.88% (+0.87) at 16.95% BOPs; Swin-Tiny APQF 77.59% at 7.23% BOPs vs GETA 80.09% at 21.84% BOPs.
- **CIFAR-10 vs GETA, baseline-matched checkpoints (Table 3):** APQF reaches lower Rel. BOPs on **4 of 5 architectures** and improves over its own baseline on 3 of them. Standouts: DeiT-Tiny APQF **95.01% (+3.11) at 8.49% BOPs** vs GETA 91.05% (−0.70) at 11.90%; Swin-Tiny APQF **97.92% (+1.14) at 5.11% BOPs** vs GETA 91.46% (−5.74) at 15.12%; ResNet-50 APQF **96.62% (+0.79)** vs GETA 93.09% (−3.46).
- **VGG7/CIFAR-10 vs quantization and joint methods (Table 4):** At the same 0.41% Rel. BOP budget, APQF achieves **93.15% vs GETA's 92.57% (+0.58 pp)**; at 0.36% BOPs APQF still beats GETA by 0.11 pp. APQF lands within 0.08 pp of Bayesian Bits' best 93.23% while using ~20% fewer BOPs (0.41% vs 0.51%), and is **the only sub-0.5%-BOPs method to beat its own FP32 baseline (ΔAcc +0.20)**. Quantization-only baselines (TWN, LR-Net, RQ, WAGE) cost 4–17× more BOPs.
- **LLM-planner robustness (Figure 7, Swin-Tiny):** Six different LLM planners — including free/open-weight ones like DeepSeek and Gemma — all reach **97.4–97.9% Top-1**, matching far more expensive Claude Opus 4.8 and GPT-5.5; the framework does not depend on a premium model.
- **Ablation (Figure 6, CIFAR-10):** At matched compute, the *Uniform* variant (single ratio + single bit-width) loses the most accuracy on all four models, and the *w/o profiling* variant (LLM decides without measured sensitivity) reduces accuracy on **every model tested** — confirming both the LLM's per-layer decisions and the measured profiling evidence independently contribute.

## Authors & Credibility

The work comes from Iowa State University's Department of Computer Science (Jafari, Bilwal, Zhou, Jannesari) with a co-author from Agricultural & Biosystems Engineering (Gelder), and explicitly builds on the group's prior *ProfilingAgent* work [69]. The framing is honest about being a thesis ("the main contributions of this thesis"), and the paper credits Hugging Face, DepGraph, Brevitas, and ptflops as the actual machinery rather than implying a from-scratch system. The comparison against GETA is reproduced by the authors themselves using the released code under matched settings rather than quoted from the original paper, which strengthens the head-to-head. Compute (H200/A100 + NCSA Delta via ACCESS allocations) is appropriate and disclosed.

## Critical Assessment

- **Novelty — genuine but incremental, and the "first" claim is carefully scoped.** The real contribution is the *coupling* of LLM-guided planning with measured profiling evidence inside a fully training-aware prune→QAT→recover pipeline, across both CNN and ViT families. Individually, profiling-guided pruning, mixed-precision QAT, PEFT recovery, KD, and LLM-as-compression-planner (incl. the authors' own ProfilingAgent) all exist; the paper is honest that it "builds on this prior work." The "first to combine … across both CNNs and ViTs" claim is plausible but narrow.
- **Rigor — the GETA comparison is the strongest and the weakest part at once.** Strong: the authors reran GETA themselves on matched checkpoints and openly report that *they could not enable activation quantization in GETA* without "nontrivial modifications … no longer the authors' original method," so GETA runs weight-only while APQF runs weight+activation — an asymmetry that actually makes APQF's win harder, which is fairly presented. Weak: that same asymmetry means the headline "APQF beats GETA" is not a strictly apples-to-apples comparison on the quantization axis, and GETA's ImageNet full-data numbers come from a single reproduced configuration per architecture, not a sweep.
- **The ImageNet accuracy drops are non-trivial and the training budget is unusual.** Under the headline 200K-image setting, ResNet-50 loses 7.40 Top-1 points and Swin-Tiny loses 6.45 — far from "keeping accuracy close to the baseline" as the abstract implies; the close-to-baseline story only holds for DeiT-Tiny (+1.38) and ViT-Small (−3.37). The 200K-image subset is a self-imposed constraint chosen partly to disadvantage the data-hungry baseline; the paper does not report a standard full-data ImageNet top-line for APQF itself (only "+ ~5 epochs post-QAT KD" grafted on for Table 2), which makes the absolute ImageNet numbers hard to situate against the broader compression literature.
- **Reproducibility concerns.** The LLM planner is nondeterministic by nature — the paper acknowledges this and mitigates with prompt design and temperature control, but reports no variance/seed analysis and no failure-rate numbers per planner, so the reader cannot gauge run-to-run stability of the headline numbers. The agent prompts themselves are not shown in detail. The ~17-point ImageNet lead over GETA is real but is measured at an unusually small training budget that flatters APQF's recovery-based design philosophy.
- **Missing ablations.** There is no ablation isolating the contribution of (a) cumulative-replay vs incremental pruning, (b) the multi-stage interleaving vs single-shot pruning, (c) KD-vs-no-KD inside QAT, or (d) PEFT choice (which of LoRA/DoRA/rsLoRA/PiSSA/LoRA+ mattered). The w/o-profiling ablation is the right one to run, but it conflates "no measured data" with "LLM uses priors," and the effect is reported only visually (Figure 6), not numerically.
- **Red flag — VGG7 baseline mismatch is disclosed but material.** APQF's VGG7 is compressed from the authors' own 92.95% FP32 reproduction while competing numbers use the literature's 93.05% baseline; the ∆Acc and Rel. BOPs are therefore computed against *different* denominators, slightly inflating APQF's "+0.20 vs FP32" framing even though the footnote is transparent about it.
- **Significance.** If the agent-planner pattern holds up, it is a useful blueprint for automating compression expertise; but the empirical bar set here (small-budget ImageNet, baseline-matched CIFAR, one self-reproduced competitor) is below what a top-tier venue would demand for a "new SOTA in joint compression" claim.

## Strengths

- Genuinely end-to-end and architecture-agnostic — one pipeline, no per-architecture rules, validated on both CNN and ViT families.
- The profiling-grounded design is well-motivated: the w/o-profiling ablation cleanly shows measured evidence beats LLM priors alone on every model.
- Practical and deployable: Rel. BOPs is the right unified metric (captures pruning + quantization in one architecture-normalized number), and the framework supports real hardware-friendly structured sparsity + integer-friendly bit-widths.
- Strong LLM-planner robustness result — 6 planners within a 0.5-point band on Swin-Tiny means the method is not a "GPT-only" artifact, and the OpenRouter design is explicitly future-proof.
- Honest about GETA's activation-quantization limitation and about the VGG7 baseline discrepancy; the GETA reruns are the authors' own rather than quoted.

## Limitations

- ImageNet headline accuracy drops of 6–7 points on ResNet-50 and Swin-Tiny contradict the abstract's "keeping accuracy close to the baseline"; the close-to-baseline story is really a DeiT/ViT story at the chosen 200K budget.
- LLM nondeterminism is acknowledged but not quantified — no per-planner variance, no failure-rate table, no seed study.
- The 200K-image training budget is a deliberate choice that disadvantages GETA; a standard full-budget ImageNet comparison for APQF itself is absent (Table 2 grafts on only ~5 epochs of post-QAT KD).
- Scope is image classification only; extension to segmentation (SAM), detection, LLMs, and VLMs is stated as future work, not demonstrated.
- Compute-heavy: each configuration involves repeated prune→recover→QAT cycles on ImageNet, and the authors note this limited how many configurations/seeds they could run.
- Residual human involvement: the user still chooses the LLM per agent, some sampling settings, distillation hyperparameters, and the pruning/quantization aggressiveness — the "automated" framing is slightly overstated.
- The VGG7 baseline-denominator mismatch and the weight-only-vs-weight+activation asymmetry against GETA complicate direct numerical comparison.

## Relevance

与高效深度学习/模型压缩方向高度相关：APQF 直接展示了结构化剪枝 + 混合精度量化 + 自适应恢复在 CNN 与 ViT 上的统一自动化方案，其"LLM 智能体基于实测 profiling 证据做逐层决策"的范式对自动化模型优化与边缘部署都有借鉴价值，可作为剪枝/量化/LLM-agent 工作的重要参考。

## Questions for Further Exploration

- How does APQF behave at a *standard* full-ImageNet training budget (1.28M images, full schedule) rather than the 200K subset — does the ~17-point lead over GETA persist, shrink, or disappear once GETA has enough data to converge?
- What is the run-to-run variance of the headline numbers given LLM nondeterminism, and what is each planner's strategy-validity failure rate (especially for the free/open-weight models)?
- How much does each design piece actually contribute — cumulative-replay vs incremental pruning, multi-stage vs single-shot, KD-vs-no-KD inside QAT, and which PEFT variant matters most? The current ablation only isolates "Uniform" and "w/o profiling."
- Can the framework move beyond classification to segmentation (SAM), detection, and especially decoder/generative models where activation distributions and layer sensitivity profiles differ sharply from classifiers?
- Does the LLM's per-layer bit-width assignment generalize across datasets for the same architecture, or does it need re-profiling — i.e., how portable is the planner's strategy?
- What are the real on-device latency/energy numbers (not just Rel. BOPs) on an integer-only edge target, where 2-bit and mixed-precision kernels often do not map cleanly to available hardware?
