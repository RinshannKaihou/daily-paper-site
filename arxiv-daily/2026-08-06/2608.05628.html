SkillHEX: Improving Agent Skills via Hypothesis-Driven Autonomous Exploration and Exploitation

Yuru Feng, Yaoqi Chen, Beidi Zhao, Qianxi Zhang, Xinjiang Wang, Jianan Lu, Zhirui Wang, Shusen Xu, Zengzhong Li, Qi Chen

Microsoft · UC San Diego · USTC · University of British Columbia

Key finding

Hypothesis-driven self-verification plus a PUCT-style patch-tree search lets agents self-evolve skills, beating the strongest baseline by +9.5 / +8.5 pp.

Directly tackles test-time self-evolution of agent skills under sparse reward — core to building self-improving LLM agents, and the mechanisms transfer beyond this paper.

01 Methodology

SkillHEX frames skill evolution as a meta-policy over a bounded budget (K=5). Two coupled modules share four persistent state structures: a patch tree, a hypothesis store, a validated test bank, and a binary evidence matrix.

Module 1 · Self-verification

Hypothesis-driven falsifiable tests

On a failed node, a reflection agent maintains failure-cause hypotheses via Add / Refine / Refute. For each, the self-verifier writes deterministic, one-property tests, validated for syntax, then replayed on cached outputs — producing dense diagnostic signal (“semantic gradients”) without extra executor calls.

  • ≤ C=10 new tests / call, ≤ 2 repair rounds
  • reflection↔verifier loop ≤ L=3 rounds
  • tests use only public info, never hidden oracles
  • refuted hypothesis → its test column pruned (Eq. 7)

Module 2 · Tree search

Evidence-guided PUCT over a persistent patch tree

The tree keeps all candidate revisions (never overwrites). On expansion the reflection agent proposes ≤ B=5 patches, each “one root cause,” and gives an ordinal rank rather than noisy absolute confidence. Selection couples the rank-prior with max-backup value via PUCT.

  • prior P(v,u): softmax over ranks, β=1.0 (Eq. 8)
  • value: Q = max(s(v), max child Q) (Eq. 9)
  • selection: PUCT, cpuct=1.4, FPU=0.1 (Eq. 10)
  • all hyperparams fixed across tasks & models
Strict isolation harness: fresh Docker rebuild per attempt · only run_bash + finish tools exposed · binary verifier hidden from every LLM → the skill is the sole experimental variable.

03 Strengths & limitations

What raises the credibility bar for the agent-skills subfield — and the gaps that keep the headline numbers provisional.

+ Strengths

  • Principled, clean ablations. −11.1 pp and −6.8 pp are large, well-separated effects diagnosing the “exploitation trap.”
  • Co-evolving evidence matrix with row/column expansion + refutation pruning amortizes test cost — empirically cheaper and more accurate than the baseline.
  • Real isolation: fresh container, minimal tool surface, hidden binary verifier — the skill is the only variable.
  • Robust to seed quality: works from no skill (51.7%) through LLM-seeded (+16.4) to human-curated (+20.7).
  • Improves human skills in every domain within 5 iterations.

− Limitations

  • Single benchmark. Relies on deterministic verifiers + inspectable outputs; open-ended / subjective tasks untested.
  • Narrow baselines. CoEvoSkills re-implemented from text; SkillEvolver, SkillOpt, APEX cited but not run.
  • No sensitivity analysis on K, B, cpuct, β — the regime where tree search pays off is uncharacterized.
  • Self-verifier fidelity unquantified: how often tests mislead, or hypotheses get refuted, is never measured.
  • Closed-model + no code release; depends on two specific frontier APIs.

04 Questions for further exploration

  1. Does the tree-search advantage scale with K — grow, plateau, or erode at K=10 / K=20 where overhead may dominate?
  2. What is the empirical accuracy and misleadingness of self-verifier tests, and how often are hypotheses refuted vs. confirmed?
  3. Does the method transfer off SkillsBench — e.g. to non-deterministic web navigation where cached-output replay breaks?
  4. How sensitive are the +9.5/+8.5 pp gains to cpuct and β, and were these tuned on SkillsBench (overfitting risk)?
  5. Would benchmarking against APEX or SkillEvolver shrink the margin, given CoEvoSkills was re-implemented from text?
  6. Can the evidence matrix be shared across tasks, turning SkillHEX into a continual-learning skill library?
