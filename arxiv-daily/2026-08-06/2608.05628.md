> **一句话总结：** SkillHEX 通过"假设驱动的自验证"把模糊的失败转化为可证伪的可执行测试（充当稠密语义梯度），并用证据引导的持久技能补丁树搜索（PUCT 式）在有限交互预算下平衡探索与利用，在 SkillsBench 的 87 个任务上以 GPT-5.3-Codex 和 Claude Opus 4.7 分别达到 55.9% 和 57.9% 的 pass@5，超越人工编写技能并领先最强基线 CoEvoSkills 9.5 / 8.5 个百分点。

> **TL;DR:** SkillHEX addresses test-time skill evolution under sparse binary rewards by converting falsifiable failure hypotheses into executable self-verifier tests (replayed on cached outputs for dense "semantic gradients") and steering a PUCT-style persistent patch-tree search that preserves competing skill revisions instead of greedily overwriting. On SkillsBench (87 tasks) with a 5-iteration budget, it reaches 55.9% (GPT-5.3-Codex) and 57.9% (Claude Opus 4.7) average pass@5, beating the strongest baseline CoEvoSkills by +9.5/+8.5 pp and surpassing human-curated skills (+2.5/+3.5 pp) while using ~18% fewer tokens than CoEvoSkills.

## 核心贡献

- **假设驱动的自验证（Hypothesis-Driven Self-Verification）**：把任务级二元失败信号分解为可证伪的失败原因假设 Hk，由 reflection agent 对假设做 Add/Refine/Refute 三种生命周期操作；self-verifier 再为每个活跃假设生成"一次只测一个属性、确定性、可复算"的可执行测试，经过规则校验器保证语法正确后，在**已缓存的执行输出**上重放，从而无需额外环境交互即可产生稠密的诊断证据（"语义梯度"）。
- **动态证据库（Dynamic Evidence Bank）**：维护一个二元证据矩阵 M[v,j]，行=已评估的技能版本节点，列=已验证的测试；新补丁补一行、新测试补一列，对称扩展；当某假设被 Refute 时按公式 (7) 删除其关联测试列以剪除误导信号。该矩阵跨迭代轮次持续累积并共同验证"版本×测试"两个轴。
- **证据引导的技能补丁树搜索（Evidence-Guided Tree Search）**：用持久补丁树 Gk 保存所有候选技能版本；用 reflection agent 的序数排名 ρ 经公式 (8) 归一化为策略先验 P(v,u)，配合 max-backup 价值 Q̄(u)（公式 9）和 PUCT 选择规则（公式 10），动态在"证据支持分支（利用）"与"被低估的替代分支（探索）"之间切换，避免过早锁定错误诊断。
- **跨双骨干、超越人工技能的实证**：在 SkillsBench 的 8 个领域 87 个任务上，用两套不同家族的模型（GPT-5.3-Codex、Claude Opus 4.7）一致验证；消融显示 self-verifier 贡献 11.1pp、patch tree 贡献 6.8pp，两者互补且均不可或缺。

## Key Contributions

- **Hypothesis-Driven Self-Verification** converts the binary terminal reward into dense diagnostic evidence by maintaining falsifiable failure-cause hypotheses (each a tuple h=(d, q, σ, C) of description, observable behavior, lifecycle state, linked tests) and synthesizing public-only, deterministic executable tests that are replayed on cached node outputs — yielding "semantic gradients" without spending extra executor attempts.
- **Dynamic Evidence Bank** stores a binary matrix M[v,j] co-evolving along both axes (new patch = new row, new test = new column) and prunes obsolete test columns when a hypothesis is refuted (Eq. 7), keeping the gradient faithful despite LLM reasoning biases.
- **Evidence-Guided Tree Search** keeps all valid candidate skill revisions in a persistent patch tree, ranks children with an ordinal reflection prior (Eq. 8), backs up subtree value with a max operator (Eq. 9), and selects via a PUCT rule (Eq. 10) that couples the semantic prior with empirical backups — letting the search abandon a degraded branch the moment new evidence weakens it.
- **Strong, consistent empirical validation** across two backbone families and eight diverse domains, including ablations that cleanly isolate each component and a token-cost analysis showing SkillHEX is simultaneously more accurate and cheaper than the strongest baseline.

## Methodology

SkillHEX is a closed-loop framework that evolves an agent skill S over a bounded number of executor attempts (budget K=5 evolved executions after the root). It frames skill evolution as a meta-policy πevo that proposes S^(k+1) from the admissible skill space, where the objective is to maximize expected success G_T(S)=E[Vξ(Y(τ))] (Eqs. 2-4). Because directly optimizing under a sparse binary reward is intractable, SkillHEX replaces it with two coupled modules sharing four state structures (patch tree Gk, hypothesis store Hk, validated test bank Ck, evidence bank Bk).

**Module 1 — Hypothesis-Driven Self-Verification.** When an executed skill node v fails (R_v=0), the reflection agent manages a hypothesis set Hk via Add/Refine/Refute. For each active hypothesis the self-verifier's generator writes executable test cases (one property each, deterministic, SELF_VERIFIER_RESULT=PASS/FAIL), which a rule-based validator checks for syntax/executability; up to C=10 new cases per invocation with up to V−1=2 repair rounds. Validated tests are tagged with an assertion strength (hard_contract, environment_preflight, deterministic_oracle, proxy_quality, diagnostic) and run against cached outputs Y_v to fill M[v,j]=ϕ(cj,Y_v)∈{0,1} (Eq. 5). The reflection↔self-verifier loop iterates up to L=3 rounds per node expansion until evidence is judged sufficient or must_emit_patch is forced in the final round. Crucially, tests use only *public* information (task instruction, visible inputs, restored answer artifacts) and never hidden oracles, and a refuted hypothesis triggers column pruning (Eq. 7).

**Module 2 — Evidence-Guided Tree Search.** The root of Gk is the initial skill. When node v is expanded, the reflection agent (acting as evidence-conditioned transition dynamics) proposes up to B=5 candidate patches, each "one root cause per candidate," and gives an ordinal rank ρu rather than a noisy absolute confidence. Ranks map to a normalized prior P(v,u) via a softmax with temperature β=1.0 (Eq. 8). Node evaluation uses a hierarchical gate (hard constraints must pass before semantic metrics count) and a **max-backup** value Q(v)=max(s(v), max_{u∈Ch_eval(v)} Q(u)) (Eq. 9) so failed exploratory children do not drag down a strong parent. Selection follows a PUCT variant (cpuct=1.4) over normalized Q̄(u) and the prior P(v,u), with the max{1,N(v)} convention keeping the exploration bonus nonzero before any child is visited (Eq. 10). FPU reduction is 0.1. All parameters (Table 4) are fixed across tasks and models except executor timeouts.

A deliberately lightweight executor harness enforces strict isolation: each attempt destroys and rebuilds the Docker container from the base task image, injects only the selected skill revision, exposes only `run_bash` and `finish` tools, and returns only a binary verifier signal — making the skill the sole experimental variable.

## Results & Highlights

- **Overall pass@5 on SkillsBench (87 tasks), Table 1:** SkillHEX reaches **55.9±1.8%** with GPT-5.3-Codex and **57.9±2.4%** with Claude Opus 4.7, vs. the strongest baseline CoEvoSkills at **46.4±0.7%** and **49.4±5.0%** — a gain of **+9.5 pp** and **+8.5 pp** respectively.
- **vs. No Skill baseline:** SkillHEX improves by **+22.6 pp** (GPT-5.3-Codex, from 33.3%) and **+23.8 pp** (Claude Opus 4.7, from 34.1%), and also **surpasses human-curated skills** (52.9% / 54.4%) by +3.0/+3.5 pp overall.
- **Ablation (Table 2, GPT-5.3-Codex):** removing the self-verifier drops pass rate from 55.9% to **44.8%** (−11.1 pp, roughly collapsing to SkillRevise-level performance); removing the patch tree (in-place refinement) drops it to **49.1%** (−6.8 pp). The two components are complementary.
- **Token efficiency (Table 3):** SkillHEX uses **2,356.1K** average per-task tokens vs. CoEvoSkills' **2,874.3K** — **18.0% fewer tokens** at higher accuracy. Notably, in-place refinement (w/o patch tree) actually *increases* token use by 6.2% while *lowering* accuracy, because it keeps grinding an unproductive revision path.
- **Domain extremes (Table 1):** largest gains over human skills are in Mathematics & OR (SkillHEX 83.3% vs. Human 50.0% on GPT-5.3-Codex, +33.3 pp) and Office & White Collar (61.9% vs. 42.9%, +19.0 pp). SkillHEX falls short of human skills in knowledge-heavy domains — Natural Science (61.9 vs. 76.2) and Finance & Economics (29.6 vs. 37.0) — which the authors attribute to a knowledge-acquisition bottleneck rather than a search limitation.
- **Initialization effect (Figure 3):** SkillHEX works even with *no* initial skill (51.7%, +17.2 pp over None baseline), and improves further with LLM-generated (+16.4) and human-curated (+20.7) seeds, confirming robustness to starting-skill quality.
- **Human-skill evolution (Figure 4):** when initialized from human skills, SkillHEX raises every domain's pass rate within 5 iterations, e.g. Cybersecurity 71.4→81.0, Software Engineering 47.9→75.0, Mathematics & OR 50.0→75.0.

## Authors & Credibility

The work is authored by a Microsoft-led team (Yuru Feng, Beidi Zhao, Qianxi Zhang, Xinjiang Wang, Jianan Lu, Zhirui Wang, Shusen Xu, Zengzhong Li, Qi Chen are Microsoft-affiliated) with collaborators from UC San Diego, USTC, and University of British Columbia. The methodology section is unusually rigorous for an LLM-agent paper: it gives a formal task definition with hidden success criteria, explicit objective (Eq. 3-4), a controlled evaluation paradigm (SkillsBench isolates the skill as the sole variable; fresh Docker container per attempt; only `run_bash`/`finish` tools; binary-only verifier feedback hidden from all LLMs), fixed hyperparameters across both backbones (Table 4), three-seed runs with reported standard deviations, and full prompt templates reproduced in Appendix A. The evaluation frontier model names (GPT-5.3-Codex, Claude Opus 4.7) and benchmark (SkillsBench, Li et al. 2026a) are contemporaneous, which is expected for a system paper in this fast-moving subfield.

## Critical Assessment

- **Novelty** is genuine but incremental rather than paradigm-shifting: the two ingredients — falsifiable-hypothesis self-tests and PUCT-style tree search — are individually well-established (LATS/rStar for tree search; Yuksekgonul et al. 2025 / GEPA for language-gradient text optimization). The contribution is the *coupling*: persistent skill-revision nodes (not transient reasoning traces) as the search state, with a co-evolving evidence matrix as the reward. A reader already familiar with APEX (policy-level exploration) or self-refinement work may find the framing familiar.
- **Rigor** is the paper's strongest axis: the executor harness enforces real isolation (container rebuild per attempt, no task-specific APIs, hidden verifier), ablations cleanly isolate each module, and standard deviations are reported. The framing of "exploitation trap" and "exploration constraint" is well-motivated by Figure 1's trajectory plot.
- **Baselines are a weak point.** Only *two* self-evolution baselines are compared (CoEvoSkills and SkillRevise); CoEvoSkills' source code "is not publicly available" so the authors *re-implemented it from the paper* — a known source of unfairness, and the re-implementation could underperform the original. Notably absent: SkillEvolver, SkillOpt, SkillOS, SkillForge, SkillRL, SkillFoundry, and Trace2Skill are all cited in Related Work but **none are benchmarked**, even though several (SkillEvolver, SkillOpt) fit the self-evolution setting. APEX (Li et al. 2026b) is the closest exploration-exploitation competitor and is also not run.
- **Cherry-picking risk in domain reporting.** The headline "surpasses human skills" claim rests on aggregating domains where SkillHEX wins big (Mathematics & OR: +33.3 pp) with ones where it *loses* to humans (Natural Science −14.3 pp, Finance −7.4 pp on GPT-5.3-Codex). The honest statement is "matches or exceeds in workflow-heavy domains, underperforms in knowledge-heavy domains" — which the paper does make in the text but not in the abstract.
- **Missing ablations:** no sensitivity analysis on the PUCT constant cpuct, the rank temperature β, the budget K (only K=5 is reported), or the child cap B. Whether the 5-iteration budget is the regime where SkillHEX's tree advantage is *maximal* (small K → pruning hurts; large K → tree overhead dominates) is unexamined. There is also no analysis of *how often* the self-verifier tests are actually correct vs. misleading (the paper acknowledges they "may be incomplete, overly local, or incorrect" but never quantifies error rates or the refutation rate).
- **Generalizability concerns.** Evaluation is on a single benchmark (SkillsBench). All 87 tasks share SkillsBench's deterministic-verifier assumption, which is exactly what makes replaying self-verifier tests on cached outputs cheap — it is unclear how the method degrades on tasks with non-deterministic environments or no clean output artifacts to test against.
- **Reproducibility** is moderate: full prompt templates are provided and hyperparameters are fixed, but the method depends on the (unreleased) SkillsBench harness and on two frontier closed models whose APIs may change. No code release is mentioned.
- **Significance** is solid for the agent-skills subfield: if the numbers hold up under independent reproduction, the combination of lower token cost + higher accuracy + cross-backbone consistency is a meaningful practical advance for test-time skill adaptation.
- **Red flags:** the "semantic gradient" / "semantic gradients" language is somewhat overclaimed — the self-verifier produces *correlated binary probes*, not gradients in any differentiable sense; calling them gradients is marketing. The claim that self-verifier tests use "only public information" is architecturally true but the paper never audits whether the LLM inadvertently leaks verifier-internal knowledge into test expectations.

## Strengths

- Cleanly diagnoses *why* greedy self-refinement fails under sparse reward (the exploitation trap) and designs a principled two-part fix with complementary ablation evidence (−11.1 pp and −6.8 pp are large, clean separations).
- The dynamic evidence matrix with symmetric row/column expansion and refutation-based pruning is an elegant way to amortize the cost of test generation across all candidate revisions — and it is empirically validated as *cheaper* than the strongest baseline while more accurate.
- Controlled experimental setup that genuinely isolates the skill as the variable (fresh container, minimal tool interface, hidden verifier) raises the credibility bar for agent-skill papers.
- Works from *no* initial skill through to human-curated initialization (Figure 3), and improves human skills further in every domain (Figure 4) — a strong practical property.
- Full prompt templates (Appendix A) with explicit hard rules, assertion-strength taxonomy, and JSON output contracts make the method reproducible in principle.

## Limitations

- **Single benchmark.** Only SkillsBench is evaluated; the method's reliance on deterministic verifiers and inspectable output artifacts may not transfer to open-ended, non-deterministic, or subjective tasks.
- **Narrow baseline set.** CoEvoSkills was re-implemented from the paper (original code unavailable), and several directly relevant self-evolution methods (SkillEvolver, SkillOpt, APEX) are cited but not benchmarked.
- **No hyperparameter sensitivity.** K, B, cpuct, β, L, C are all fixed; the regime where tree search pays off vs. overhead is uncharacterized.
- **Knowledge-heavy domains underperform humans** (Natural Science, Finance & Economics) — acknowledged as a knowledge-acquisition bottleneck, implying the method cannot *invent* missing domain expertise, only reorganize existing procedural structure.
- **Self-verifier fidelity unquantified.** The paper never measures how often generated tests are wrong or misleading, nor the refutation rate of hypotheses — a key failure mode given LLM self-bias concerns (Xu et al. 2024) that the paper itself cites.
- **Closed-model dependency** on two specific frontier APIs (GPT-5.3-Codex, Claude Opus 4.7); no open-weight backbone results, and no code/SkillsBench-harness release mentioned.
- **"Semantic gradient" terminology** overstates what are binary correlated probes, risking misreading by readers expecting differentiable signals.

## Relevance

Highly relevant to autonomous-agent and agent-skill research interests: SkillHEX directly tackles test-time self-evolution of agent skills under sparse reward and bounded interaction budgets — a core problem for building self-improving LLM agents. The hypothesis-driven self-verification and evidence-guided tree search mechanisms are transferable ideas for anyone working on agent self-refinement, skill libraries, or LLM-as-judge failure attribution.

## Questions for Further Exploration

- How does SkillHEX's advantage scale with the iteration budget K — does the tree-search benefit grow, plateau, or get eroded by overhead at K=10 or K=20, and is there a crossover where in-place refinement becomes competitive?
- What is the empirical accuracy and misleadingness rate of self-verifier-generated tests, and how often are active hypotheses ultimately refuted vs. confirmed — i.e., how faithful are these "semantic gradients" in practice?
- Can the method transfer beyond SkillsBench to tasks with non-deterministic environments (e.g., web navigation on WebArena) where cached-output replay is no longer valid?
- How sensitive are the +9.5/+8.5 pp gains to the PUCT constant cpuct and rank temperature β, and were these tuned on SkillsBench (raising overfitting concerns)?
- Would benchmarking against APEX (the closest exploration-exploitation self-evolving agent) or SkillEvolver shrink or enlarge the reported margin, given CoEvoSkills was re-implemented from text rather than original code?
- Can the evidence matrix be shared *across tasks* to amortize hypothesis/test generation, turning SkillHEX into a continual-learning skill library rather than a per-task loop?
