> **一句话总结：** FinEvo-Bench 是一个面向金融专业工作流的纵向自演化 Agent 基准，包含 120 个真实案例任务和 20 个业务场景，通过"全局交错流 + 状态重置对照"配对协议度量跨任务经验复用增益；在同一 Qwen3.7-Max 骨干下，四种 Agent 支架（Letta、Codex、Claude Code、GenericAgent）的演化得分比对照组提高 9.33–19.37 分，合规问题数下降 0.12–0.44 个/任务，Letta 取得最高演化得分 91.65，Codex 取得最大自演化增益 +19.37。

> **TL;DR:** FinEvo-Bench is a longitudinal benchmark of 120 real-case-grounded financial tasks (20 scenes across 6 domains, 775 input files) that measures whether self-evolving agents turn prior-task experience into later improvement, using three independently shuffled globally interleaved streams paired with state-reset controls and an independent Claude Opus 4.6 rubric judge (ICC(A,1)=0.95 vs. a financial expert). With a shared Qwen3.7-Max backbone, all four scaffolds beat their no-evolution controls — scores rise by +9.33 to +19.37 points and compliance issues fall by 0.12–0.44 per task; Letta tops evolved score (91.65), Codex tops self-evolution gain (+19.37), and within-scene late ranks (4–6) gain 6.10–8.70 points more than early ranks (1–3).

## 核心贡献

- **首个"专业工作流 + 开放式产出 + 多维评估"三位一体的纵向自演化基准**：FinEvo-Bench 同时覆盖金融机构真实流程、开放式可交付物（报告/评估/建议）和多维度评分（含合规），弥补了 LifelongAgent-Bench、SEA-Eval、Evo-Memory、StuLife、Frontier-Eng 等既有基准只覆盖部分维度的空白。
- **120 个真实案例、20 个业务场景、6 大金融领域**：任务来自机构提供且公开文档化的案例，每个场景包含 6 个共享专业流程但事实/结论实质性不同的子任务，平均每任务 6.46 个输入文件（共 775 个），并经过双专家构建与审核的场景级 100 分评分量表评估。
- **配对式纵向协议隔离"经验复用增益"**：通过 3 次独立打乱的全局交错任务流 + 每任务前重置状态的非演化对照，配合独立的 Claude Opus 4.6 评分 Agent，精确度量自演化能力而非骨干模型本身的强度。
- **系统性比较 4 种支架及多种演化维度**：在同一骨干下对比 Letta / Codex / Claude Code / GenericAgent，并进一步剖析经验载体（记忆/技能/组合）、反馈形式（评分量表 vs. 参考答案）、能力维度增益，以及跨场景执行影响。
- **方法学结论具有可迁移性**：rubric 反馈优于参考答案反馈（+3.95–7.93 分），技能型演化在 Claude Code 上优于记忆型与组合型，且所有能力维度均有提升——为后续 Agent 设计提供可操作建议。

## Key Contributions

- **First benchmark jointly covering professional workflows, open-ended deliverables, and multi-aspect evaluation for self-evolution.** Prior work (LifelongAgent-Bench, SEA-Eval, Evo-Memory, StuLife, Frontier-Eng) covers ordered reuse, situated adaptation, or iterative artifact optimization in isolation; FinEvo-Bench combines all three in recurring financial workflows.
- **120 real-case-grounded tasks across 20 business scenes and 6 financial domains**, built from institution-provided scene descriptions, validated professional procedures, and an eligible case pool, with PII/sensitive fields removed or replaced while preserving data relationships and decision logic. Tasks average 6.46 input files (range 2–11, total 775) and require open-ended reports/assessments.
- **A paired longitudinal protocol that isolates retained-experience gains**: three independently shuffled, globally interleaved task streams with per-task state-reset controls, so the measured delta is attributable to cross-task experience rather than backbone strength or task ordering.
- **Expert-validated rubric and an independent judge.** Two domain experts construct each 100-point scene rubric; an independent Claude Code scoring agent (Claude Opus 4.6) achieves ICC(A,1) = 0.95 (95% CI [0.93, 0.97]) against a financial expert on 120 outputs, with mean/max absolute differences of 1.6 and 5 points.
- **Shared-backbone comparison of four scaffolds and multiple design axes**: experience carriers (memory/skill/combined), feedback form (rubric vs. reference answer), per-capability-dimension gains, and scene-isolated vs. mixed execution.

## Methodology

**Benchmark construction (Section 3).** Each scene *s* is built from three sources — an institution-provided scene description *D_s*, a reference professional procedure *P_s* validated in practice, and an eligible candidate pool *C_eligible* drawn from institution-provided and publicly documented cases (with identifiers/sensitive fields removed or replaced while preserving data relationships, chronology, and decision conditions). A domain expert consolidates these into a five-part specification *S_s = (O_s, E_s, A_s, Y_s, K_s)* covering objective/scope, required inputs, operations/checks, expected deliverable, and compliance constraints. Six substantively distinct cases (different business situations, input files, judgment conditions, or conclusions — superficial variants excluded) are selected per scene, each becoming a task with a natural-language request, input files, metadata, and a reviewed reference answer.

**Scene-level rubrics (Section 3.3).** The six tasks in a scene share a 100-point rubric derived from the professional procedure. The rubric checks correct file use, complete analysis, and supported conclusions without requiring lexical match to a reference answer, and additionally checks financial compliance (fabricated/unsupported data, definitive claims on insufficient information, decisions beyond the agent's role, guarantees on credit/returns). Two domain experts construct each rubric (one drafts, one cross-checks against all six tasks).

**Scaffolds.** Four self-evolving agent scaffolds are evaluated with the same backbone: **Claude Code** and **Codex** (can distill experience into reusable skills, project-scoped memory, and global memory), **Letta** (editable core memory blocks injected into every model call), and **GenericAgent** (compact Markdown experience files with a title-only L0 index for selective loading).

**Longitudinal protocol (Section 4.1).** The 120 tasks are independently shuffled three times into globally interleaved streams. Each evolving run processes tasks sequentially with an execute → score-and-feedback → reflect-and-consolidate cycle; after each task the raw conversation is closed while stored experience persists. The paired non-evolving condition resets state before every task but shares order, backbone (Qwen3.7-Max, 1M context, 64K max output, greedy, temperature 0), and scoring procedure. The scaffold never sees the complete rubric or the judge's item-level record — only rubric-based feedback summarizing problems and reasons, forcing generalization rather than answer reproduction.

**Metrics.** Four are reported: (1) task quality (0–100 rubric score), (2) financial compliance (issues per task), (3) self-evolution ability (paired ΔScore and ΔComp vs. the state-reset control), and (4) agent-side cost (tokens in units of 10^4 per task). For longitudinal evolution, tasks are ranked by their within-scene occurrence order; ranks 1–3 are "Early" and 4–6 are "Late."

## Results & Highlights

- **All four scaffolds beat their state-reset controls on all three shuffled streams.** Mean scores rise by **+9.33 to +19.37 points** and mean compliance issues fall by **0.12–0.44 per task** relative to paired non-evolving controls (Table 3).
- **Letta achieves the highest evolved score (91.65) and fewest compliance issues (0.09/task); Codex achieves the largest self-evolution gain (+19.37) and tied-lowest compliance (0.11/task).** GenericAgent has the lowest evolved score (83.34) and smallest gain (+9.33) but the lowest token cost (21.78 × 10^4/task total — less than one-third of Claude Code's 76.50) (Table 3).
- **Late within-scene ranks gain more than early ranks.** Across scaffolds, mean gains over ranks 4–6 exceed those over ranks 1–3 by **6.10–8.70 points**; Codex's late gain reaches 23.62 vs. 15.12 early, and Letta shows the largest early-to-late increase (+8.70) (Figure 3, Table 3). The trend holds in each of the three independently shuffled streams.
- **Experience activation correlates with higher scores.** For the three selective-retrieval scaffolds, activated tasks score **8.31–9.06 points higher** than non-activated tasks (Codex 102/120 activated at 92.42 vs. 84.11; Claude Code 87/120 at 91.82 vs. 83.29; GenericAgent 71/120 at 87.04 vs. 77.98) (Table 4).
- **Skill-only evolution beats memory-only and combined memory–skill in Claude Code.** Skill-only reaches **93.71 points with 0.05 compliance issues/task**, vs. memory-only 90.42/0.09 and full evolution 89.47/0.11; the combined setting improves neither quality nor compliance. A fixed expert skill (86.67/0.13) beats no evolution (71.58/0.55) but trails all dynamically updated carriers (Table 5).
- **Rubric feedback beats reference-answer feedback across all scaffolds.** Rubric feedback raises scores by **+3.95 to +7.93 points**, reduces compliance issues by 0.06–0.14, and yields 4–9 more experience activations per run (Table 6).
- **All five capability dimensions improve, with report quality the biggest gainer** (6.85–18.17 percentage points across scaffolds); normalized compliance gains range 1.93–6.74 points (Figure 4).
- **Scene-isolated vs. mixed execution: score differences are small and mixed in direction** (Claude Code −0.84, Letta −1.00, Codex +0.46, GenericAgent +1.63 on a 5-scene/30-task sample), but **scene isolation triggers 0.01–0.05 more compliance issues per task for every scaffold**, consistent with cross-scene transfer of general practices like evidence checking and cautious wording (Table 7).
- **Rubric judge reliability: ICC(A,1) = 0.95 (95% CI [0.93, 0.97])** against a financial expert on 120 deliverables, with mean/max absolute differences of 1.6/5 points on the 0–100 scale (Section 4.2).

## Authors & Credibility

The work is a collaboration between **Beihang University** and the **Qwen DianJin Team at Alibaba Cloud Computing**, with the lead author's work conducted during an Alibaba internship — giving the team direct access to institution-provided financial procedures and case material, which materially strengthens the "real-case-grounded" claim. The methodology is unusually careful for an agent benchmark: they use a shared backbone (Qwen3.7-Max) across all scaffolds to isolate scaffold effects, run each configuration three times, pair every evolving run with a state-reset control on the same permutation, and validate the automated judge against a human financial expert with a proper ICC analysis (not just ranking correlation). The independent Claude Opus 4.6 scoring agent is kept separate from the evaluated scaffolds, avoiding self-preference. The worked Financial-Statement-Analysis appendix (Tables 8–17) discloses concrete file groups, rubric point allocations, and red-flag checks, enabling readers to audit construction quality.

## Critical Assessment

- **Novelty is genuine but incremental.** The four-axis framing (cross-task, open-domain, open-ended, multi-aspect) and the paired interleaved-stream protocol are the real contributions; the underlying scaffolds (Claude Code, Codex, Letta, GenericAgent) and the rubric-judge pattern are off-the-shelf. Table 1 honestly positions FinEvo-Bench against five close relatives rather than overclaiming novelty.
- **Carrier comparison is limited to Claude Code.** The headline finding that "skill-only > memory-only > combined" comes from a single scaffold (Section 4.4, Table 5); the paper itself flags that "later tasks often load only one" store, so the null result for the combined setting may be a retrieval-engineering artifact rather than a deep property of memory-plus-skill. Generalizing this conclusion to Letta/Codex/GenericAgent is not supported.
- **Single backbone is a real constraint.** Only Qwen3.7-Max is tested (plus Opus 4.6 as judge). Whether the +9 to +19 point evolution gains survive on weaker or differently-aligned backbones is unaddressed; the authors flag this in limitations. Parameter-updating evolution (fine-tuning, RAGEN-style RL) is entirely out of scope.
- **Cross-scene diagnostic is underpowered.** The "scene isolation" experiment (Table 7) uses only 5 scenes / 30 tasks and a single shuffle, yet draws substantive conclusions about cross-scene transfer of compliance practices. A 30-task sample is too small to support the 0.01–0.05 compliance-issue deltas confidently.
- **Self-evaluation risk is partially mitigated but not eliminated.** The judge is Claude Opus 4.6 and three of four evaluated scaffolds are Claude-Code-family or Qwen-family; although evaluated Claude Code uses Qwen3.7-Max (not Opus), there is residual same-vendor exposure. The human-expert ICC validation (0.95) is on one run's 120 outputs, not cross-run, so judge drift across the three streams is not measured.
- **Reference answers are available but their role is underspecified.** The appendix shows reviewed reference answers exist for every task, yet the main text emphasizes rubric-over-reference feedback. It is unclear whether reference answers influenced rubric construction, which would be a mild circularity.
- **"Real-case-grounded" is strong but not fully auditable.** PII removal and case eligibility are described procedurally; no quantitative release audit (e.g., identifier-detection pass) is reported, and the institution-provided cases cannot be independently verified.
- **Reproducibility is moderate.** Backbone, decoding, run count, and metrics are fully specified, and Appendix B promises "three-stage pipeline code and prompts," but the 775 input files and scene rubrics are institution-derived and may not be releasable in full, limiting third-party replication.

## Strengths

- **Methodological rigor above the field average**: paired state-reset controls, three independent shuffles, shared backbone, and ICC-validated judge make the self-evolution deltas credible rather than confounded.
- **Real professional content**: institution-provided procedures and eligible cases give tasks ecological validity that synthetic or purely web-scraped benchmarks lack.
- **Honest, fine-grained reporting**: separate reporting of evolved score vs. self-evolution gain (which produce different rankings — Letta vs. Codex) prevents the common conflation of "strongest final agent" with "best learner."
- **Actionable design insights**: skill-over-memory carrier preference, rubric-over-reference feedback, and the late-rank-gains-more trend are directly useful to agent builders.
- **Compliance as a first-class metric** — rare in agent benchmarks and essential for finance.

## Limitations

- **Scope**: 20 scenes in 6 financial domains, one backbone (Qwen3.7-Max), non-parametric evolution only — generalization to other professions, models, and learning mechanisms is untested (acknowledged by the authors).
- **Carrier ablation limited to Claude Code**; the combined memory–skill null result is mechanistically under-explained.
- **Cross-scene diagnostic uses only 5 scenes / 30 tasks / one shuffle** — underpowered for the compliance-transfer claims.
- **Cost reported only as tokens**, not latency, dollar cost, or number of model calls — Letta's always-on memory injection may have very different wall-clock behavior than its token count suggests.
- **No parametric or RL-based evolution baselines** (e.g., RAGEN, AFlow, offline function-weight training) are evaluated, despite being cited.
- **Rubric judge validated on one run**; cross-run/cross-stream judge consistency is not reported.
- **Open-ended deliverables scored by an LLM judge** inherit the usual concerns about judge bias, even with strong human agreement on the validated subset.

## Relevance

FinEvo-Bench 直接命中"自演化 Agent 评估"与"金融领域 LLM Agent"两条研究主线，对于关心 Agent 长期记忆/技能积累机制、纵向（longitudinal）评估方法学、以及金融专业工作流（信贷、理赔、基金诊断、客户触达等）自动化的研究者都具有高参考价值；其配对式状态重置协议和评分量表反馈优于参考答案的结论，可作为通用 Agent 基准设计的方法学模板。

## Questions for Further Exploration

- Do the +9 to +19 point self-evolution gains and the skill-over-memory carrier ranking hold on backbones other than Qwen3.7-Max (e.g., smaller open models, or non-Qwen families), and on parametric/RL evolution methods (RAGEN, AFlow, offline function-weight training)?
- Why does the combined memory–skill setting underperform skill-only in Claude Code — is it a retrieval bottleneck (later tasks load only one store), a context-length dilution effect, or a reflection-quality issue, and can a better retrieval policy recover the combination gain?
- How robust is the rubric judge across the three independently shuffled streams (not just the one validated run), and does judge-agent self-preference (Claude judging Claude-family scaffolds) bias the cross-scaffold ranking?
- Would scaling the cross-scene diagnostic beyond 5 scenes/30 tasks change the mixed-score / consistent-compliance conclusion, and is there a scene-pair structure that predicts when cross-scene transfer helps vs. hurts?
- Can the paired interleaved-stream protocol be ported to non-financial professional domains (legal, medical, engineering) where shared procedures recur across distinct cases, and do the same carrier and feedback-form conclusions transfer?
- What is the relationship between experience-activation rate and task difficulty — GenericAgent's low 71/120 activation may reflect its title-only L0 index; would a semantic index close the gap to Codex's 102/120 without sacrificing its token-efficiency advantage?
