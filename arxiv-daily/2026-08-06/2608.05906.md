> **一句话总结：** MERIT 提出一种无需训练的 Text-to-SQL 修复 agent，通过"因果"跨查询记忆（仅允许已完成先前 episode 的经验被检索）维护正负双极性修复经验，并用确定性错误类型分类器引导混合词法-稠密检索；在 Spider 上相对无状态迭代修复将执行准确率从 66.34% 提升至 69.79%（+3.45pp，95%CI [1.97, 4.96]），但在 BIRD 上仅 +1.09pp（证据较弱），且与无类型化的 Dynamic RAG 在两个基准上都无法可靠区分。

> **TL;DR:** MERIT is a training-free Text-to-SQL repair agent that accumulates oracle-verified corrections (positive) and observed unsuccessful directions (negative) in an online, "causally" time-restricted memory — only finalized earlier episodes are retrievable. Using a frozen Qwen2.5-7B-Instruct, it lifts Spider execution accuracy from 66.34% (stateless Iterative) to 69.79% (+3.45pp, paired 95% CI [1.97, 4.96]) and BIRD from 47.35% to 48.44% (+1.09pp, CI touching zero). However, MERIT ties Dynamic RAG on Spider and beats it by only 0.28pp on BIRD, and Reflexion-style memory beats MERIT on BIRD (51.24% vs 48.44%) at roughly 1.3x the token cost — so the case for structured polarity + type conditioning over untyped dynamic retrieval is not established.

## 核心贡献

- **形式化"因果情景记忆"修复问题**：将 Text-to-SQL 修复建模为在线跨查询记忆问题，规定只有已终结（finalized）的先前 episode 才可被当前查询检索——当前查询自身的中间尝试不能进入全局记忆，未来 episode 也尚未发生。"因果"在此特指时序可用性，而非缺乏正确性监督。
- **双极性在线记忆结构**：每条记忆条目形如 ⟨上下文 c, 失败类型 τ, SQL 变换 Δ, 极性 o, 出处 ρ⟩；正例记录 oracle 确认的"失败→正确"转移，负例仅记录未解决 episode 中最后尝试的方向（不声称普遍无效）。每个 episode 至多贡献一条记忆。
- **确定性错误类型分类器作为检索先验**：基于执行状态与可观测 DBMS 错误文本，用有序规则映射到 8 个粗类（RESULT MISMATCH、DENOTATION MISMATCH、EXECUTION SCHEMA LINKING、AGGREGATION、FILTER/VALUE、EXECUTION、SYNTAX、UNKNOWN），不解析 SQL AST，不推断语义错误。
- **类型条件化混合检索**：对每个极性分别构造候选池，当同类型条目 ≥3 时仅在同类内检索，否则回退到整个合法同极性池；稠密（0.75）与 BM25（0.25）分数在池内独立 min-max 归一化后加权；至多检索 3 正 + 1 负。
- **受控的三种子流序评估**：在冻结 Qwen2.5-7B-Instruct、共享初始预测、K=7 修复预算下，跨三种查询顺序比较 MERIT 与无状态 Iterative、无类型 Dynamic RAG、Reflexion-style 记忆，并用保持跨种子配对的 query-cluster bootstrap 给出 95% 置信区间，使结果具有统计可解释性。

## Key Contributions

- Formulates Text-to-SQL iterative repair as **causal episodic memory**: only outcomes from finalized earlier episodes may guide the current query, while current-query attempts stay local and future episodes are not yet available. "Causal" denotes temporal memory availability, not absence of correctness supervision.
- Introduces **MERIT** (Memory-Augmented Error-Typed Retrieval for Iterative Text-to-SQL repair), a training-free agent that combines a deterministic error classifier, an online dual-polarity memory, and a type-conditioned hybrid lexical-dense retriever in front of a frozen LLM.
- Defines memory entries as ⟨context c, failure type τ, SQL transformation Δ, polarity o, provenance ρ⟩, with positive entries recording oracle-confirmed failed-to-correct transitions and negative entries recording only the last direction attempted in an unresolved episode (no claim of universal invalidity). Each episode contributes at most one memory entry.
- Proposes **error-guided hybrid retrieval** that partitions candidates by polarity, narrows to same-type entries when ≥3 exist (else falls back to the full same-polarity legal pool), and ranks via 0.75·dense + 0.25·BM25 with per-pool min-max normalization.
- Provides a **controlled three-seed evaluation** isolating repair strategy: identical frozen Qwen2.5-7B-Instruct backbone, identical cached initial predictions (Spider 58.90%, BIRD 38.40%), identical K=7 budget, identical execution feedback — with query-cluster bootstrap 95% CIs that preserve query outcomes across stream orders.

## Methodology

MERIT runs an online correction-accumulation loop over a stream of queries. At stream position t, the agent receives question qₜ, schema Sₜ, optional dataset evidence aₜ, executable database Dₜ, and a **shared initial SQL prediction** yₜ⁽⁰⁾ generated once with greedy decoding by the frozen Qwen2.5-7B-Instruct and reused by every method (isolating the effect of the repair strategy).

**Feedback regime.** Experiments use the `denotation_confirmed` regime: after attempt k, the benchmark evaluator returns V(Dₜ, yₜ⁽ᵏ⁾) = (zₜ, ϵₜ) where z is CORRECT / DENOTATION MISMATCH / EXECUTION ERROR / TIMEOUT and ϵ carries the latest observable DBMS error. Spider uses the pinned test-suite execution protocol; BIRD compares predicted vs. reference rows under a pinned timeout. The reference SQL and reference rows are isolated inside the evaluator and never fed to the model — the model sees only attempt status, DBMS error, and the predicted failure type. Hence the setting is **oracle-assisted benchmark repair**, not autonomous correction from DBMS feedback alone.

**Failure classifier.** A deterministic, ordered-rule classifier maps the current unsuccessful query to one of eight coarse categories using only execution status and observable DBMS text. The first matching rule wins; other nonempty DBMS errors map to UNKNOWN; executable-but-oracle-incorrect SQL maps to RESULT MISMATCH. It does not inspect the SQL AST or infer semantic errors (e.g., wrong joins). The label is recomputed after each unsuccessful revision and used only as a retrieval prior.

**Online dual-polarity memory.** Memory is partitioned into M⁺ (verified corrections) and M⁻ (observed unsuccessful directions). A memory entry x is eligible for the current query only if sourcePos(x) < t and sourceQuery(x) ≠ qₜ; global memory is updated only upon episode finalization (Eq. 2). Current-query attempts remain in the local history Hₜ and cannot enter cross-query retrieval.

**Type-conditioned hybrid retrieval.** For each polarity p, MERIT constructs the legal same-polarity pool Lₜ,ₚ (after temporal/query/database constraints) and its same-type subset Tₜ,ₚ. Full MERIT selects Cₜ,ₚ = Tₜ,ₚ when |Tₜ,ₚ| ≥ 3, else Lₜ,ₚ (Eq. 1). Dense and BM25 scores are independently min-max normalized within each selected pool; candidates are ranked by r(x,u) = 0.75·b_d + 0.25·b_b. MERIT retrieves at most 3 positive and 1 negative entry. The retrieval query concatenates the current question, SQL, failure context, and error type.

**Repair generation.** The prompt includes question, schema, evidence, current SQL, attempt status, DBMS error, predicted failure type, local history, and retrieved memories (positive framed as confirmed successful directions; negative as observed unsuccessful ones). No separate system prompt; each template is one user message through the model's chat template. Greedy decoding produces one revision, which is appended to Hₜ and evaluated by the oracle.

**Episode finalization.** On success at step k*, MERIT creates one positive entry from yₜ⁽ᵏ*⁻¹⁾ → yₜ⁽ᵏ*⁾. If the budget K=7 is exhausted without a correct revision, it creates at most one negative entry from the final observed direction. Memory update happens only at finalization (Eq. 2): M_{<t+1} = M_{<t} ∪ {xₜ} \ {∅}.

**Type-Reliability-Aware variant.** A controlled variant sets h(τ)=1 for SYNTAX, SCHEMA LINKING, and EXECUTION (types expected to be directly supported by observable DBMS diagnostics) and h(τ)=0 otherwise; it applies hard type filtering only for high-reliability types and uses type agreement as a soft ranking bonus (weight 0.10) for low-reliability types.

## Results & Highlights

- **Spider execution accuracy (mean ± SD over 3 stream orders):** MERIT 69.79 ± 0.59%, Dynamic RAG 69.79 ± 0.28%, Reflexion-style 68.38 ± 0.12%, Iterative (stateless) 66.34 ± 0.14%. MERIT's gain over Iterative is +3.45pp with paired 95% CI [+1.97, +4.96] — clear evidence that earlier finalized repair experience benefits later queries on Spider.
- **BIRD execution accuracy:** MERIT 48.44 ± 0.46%, Dynamic RAG 48.15 ± 0.19%, Iterative 47.35 ± 0.04%, Reflexion-style 51.24 ± 0.15%. MERIT's gain over Iterative is only +1.09pp with CI [0.00, +2.17] (touching zero), and MERIT-minus-Reflexion is −2.80pp with CI [−4.15, −1.46], making Reflexion-style the strongest BIRD method.
- **MERIT not reliably separated from Dynamic RAG:** They tie at 69.79% on Spider (Δ 0.00, CI [−1.00, +0.97]) and MERIT leads by only +0.28pp on BIRD (CI [−0.43, +1.00]) — the polarity separation and hard type conditioning do not establish an aggregate benefit over untyped dynamic retrieval.
- **Schema-locality is the most consistent ablation effect:** restricting retrieval to cross-database memories lowers accuracy by −0.93pp on Spider and by −2.74pp on BIRD, the largest BIRD ablation decline, indicating cross-schema analogies do not replace same-database join paths and domain terminology.
- **Dense reranking matters most on Spider (−1.12pp when removed, the largest Spider ablation decline); BM25 matters more on BIRD (−0.40pp when removed).** The No-BM25 variant actually *raises* the Spider mean by +0.58pp, so the relative value of the two ranking channels is dataset-dependent.
- **Negative memory contributes modestly:** removing it costs only −0.13pp (Spider) and −0.09pp (BIRD); Random Same Type is only 0.05–0.09pp below full MERIT, so verified corrections provide most of the signal.
- **Error classifier is coarse:** population-weighted accuracy ≈48.71% (Spider) / 48.10% (BIRD), Macro-F1 0.317 / 0.355. Spider failures are 84.71% RESULT MISMATCH; BIRD has substantially more SCHEMA LINKING (33.65%) and other types (8.36%).
- **Inference cost is higher, not lower, than stateless repair:** Spider MERIT uses 5.274M tokens / 3,419 calls vs. Iterative 2.529M / 3,619; BIRD MERIT 17.569M / 7,325 vs. Iterative 9.325M / 7,429. Reflexion-style is the most expensive (Spider 6.597M / 6,309; BIRD 22.407M / 13,568). MERIT makes slightly fewer calls but each prompt is lengthened by retrieved memories. Cost accounting excludes embedding, indexing, retrieval latency, and memory-maintenance overhead.
- **Initial prediction quality (shared):** Qwen2.5-7B-Instruct greedy decoding yields 58.90% (609/1,034) on Spider and 38.40% (589/1,534) on BIRD; all repair gains are measured on top of this fixed starting point.

The group has a track record in agent and Text-to-SQL research. The methodology is unusually disciplined for a memory-paper: it fixes the backbone, fixes the initial predictions, fixes the feedback and budget, varies only the stream order, and reports query-cluster bootstrap 95% CIs that preserve per-query outcomes across seeds. The paper is also notably self-critical — it foregrounds the null result against Dynamic RAG rather than burying it.

## Critical Assessment

- **Novelty:** The framing of repair as *causal episodic memory* (time-restricted, finalized-only) is a clean conceptual contribution, but the individual components — dual-polarity memory, deterministic error typing, hybrid lexical-dense retrieval — are recombinations of established ideas (Reflexion, ExpeL, DAIL-SQL, CRITIC). The genuine novelty is the controlled isolation of these components under an oracle-assisted regime.
- **Rigor:** Strong on experimental control (shared initial predictions, fixed backbone, three stream orders, paired bootstrap CIs). The honest reporting of the MERIT-vs-Dynamic-RAG tie and the BIRD loss to Reflexion-style is commendable and rare.
- **Key weakness — the headline "win" is narrow:** The clean, positive result is Spider-only (+3.45pp over Iterative). On BIRD the gain over stateless repair has a CI touching zero, and the structured-memory hypothesis (polarity + hard type conditioning) is *not* supported — MERIT cannot be reliably distinguished from **untyped Dynamic RAG** on either benchmark (Spider Δ 0.00; BIRD +0.28). The paper's own conclusion states "no single memory organization is uniformly best," which is scientifically honest but means MERIT's specific design choices are not vindicated as necessary.
- **The deterministic classifier is too weak to justify hard type filtering:** ~48% population-weighted accuracy and Macro-F1 ≈0.32–0.36, with the dominant Spider category being RESULT MISMATCH (84.71%) — a bucket that "combines multiple underlying semantic errors." This directly explains why relaxed filtering (Type-Reliability-Aware) and even No-Type-Filter remain competitive on BIRD, and it undermines the motivation for treating type as a "definitive partition."
- **Missing ablations / sensitivity:** The authors fix retrieval weights (0.75/0.25), memory allocation (3 pos + 1 neg), and the fallback threshold (|T|≥3) across both benchmarks and explicitly note they did not run "a comprehensive sensitivity study." Given that BM25 helps on BIRD but slightly hurts on Spider, a sweep over the mixture weight is a conspicuous gap.
- **Cost framing is half-honest:** MERIT is not cheaper than stateless repair in total tokens (5.274M vs 2.529M on Spider; 17.569M vs 9.325M on BIRD) — the paper admits this. But it omits embedding/indexing/retrieval-latency/memory-maintenance overhead entirely, so the real deployment cost gap is larger than reported.
- **Reproducibility:** Good — frozen open backbone (Qwen2.5-7B-Instruct), standard public benchmarks (Spider/BIRD dev sets), deterministic classifier with rules in Appendix C, full prompts in Appendix B. The main non-reproducibility risk is the oracle correctness signal: real deployments lack denotation-level confirmation, a scope the authors acknowledge.
- **Significance:** The honest negative/nuanced findings (structured memory not reliably beating untyped retrieval; schema-locality as the dominant factor; classifier coarseness limiting type conditioning) are arguably more valuable to the field than a marginal accuracy bump, because they redirect future work toward schema-local experience and better failure diagnostics rather than ever-fancier memory polarities.
- **Red flags:** None severe. The "causal" naming slightly oversells the contribution — it is a temporal availability constraint, not a causal-inference method, and the paper is careful to clarify this. No state-of-the-art Text-to-SQL claim is made (the comparison set excludes specialized agents like CHASE-SQL, DIN-SQL, SQL-PaLM, SQL-o1).

## Strengths

- Exceptionally clean experimental design: identical backbone, identical cached initial predictions, identical feedback and budget, only repair strategy and stream order vary.
- Paired query-cluster bootstrap with 95% CIs that preserve per-query outcomes across seeds — a statistically principled way to compare on identical query sets.
- Honest, self-limiting reporting: explicitly states where MERIT does *not* beat baselines (Dynamic RAG tie; BIRD loss to Reflexion-style), rather than cherry-picking the Spider win.
- The schema-locality ablation produces a clean, actionable finding (cross-database retrieval is a weak substitute; same-database experience is consistently valuable, especially on BIRD's larger domain-specific schemas).
- Training-free, single open backbone, full prompts and classifier rules in appendices — high reproducibility for the core protocol.

## Limitations

- **Oracle-assisted regime:** MERIT requires a denotation-level correctness signal during repair. This is stronger than the feedback available in most deployed databases (where an agent sees only execution errors, incomplete tests, or delayed user confirmation). The paper does not test the DBMS-error-only regime.
- **Single backbone, single-language, dev-set-only evaluation:** Only Qwen2.5-7B-Instruct; only Spider and BIRD *development* sets; no multilingual/conversational/production-DB evaluation. No claim that gains transfer to other model families.
- **MERIT is not reliably separated from untyped Dynamic RAG** on either benchmark, so the polarity-separation and hard-type-conditioning design choices are not proven necessary.
- **Deterministic classifier is coarse** (~48% accuracy, Macro-F1 ≈0.32–0.36; dominant RESULT-MISMATCH bucket conflates semantic errors), limiting how strongly the results support type-conditioned retrieval and explaining why relaxed filtering stays competitive on BIRD.
- **No comprehensive sensitivity study** over retrieval mixture weights (0.75/0.25 fixed), memory allocation (3 pos + 1 neg fixed), or fallback threshold (≥3 fixed) — despite evidence that BM25 vs. dense value is dataset-dependent.
- **Not cheaper than stateless repair** in total tokens; cost accounting excludes embedding, indexing, retrieval latency, and memory-maintenance overhead.
- **Query-order sensitivity:** Three stream orders capture only a limited portion of accumulation-order variation; memory contents depend on order.

## Relevance

对于关注 LLM agent 自我修复、跨 episode 记忆与执行反馈驱动调试的研究方向高度相关：MERIT 把"修复经验如何跨查询表示与复用"这一问题形式化，并提供受控实验与统计置信区间，可作为评估 agent 长程记忆设计的范式参考；其关于 schema-local 经验与错误分类器精度的负面发现对构建健壮 Text-to-SQL/代码生成 agent 尤具实践价值。

## Questions for Further Exploration

- Would a learned or calibrated failure classifier (e.g., Macro-F1 > 0.6) finally let hard type-conditioned retrieval beat untyped Dynamic RAG, or is the RESULT-MISMATCH bucket inherently too coarse to partition?
- How do the gains change under a realistic DBMS-error-only regime (no denotation oracle), where the polarity signal must be approximated — does the positive-memory advantage collapse?
- Is the BM25-vs-dense dataset-dependence explained by schema size/vocabulary, and would a schema-aware mixture weight (rather than a fixed 0.75/0.25) recover the lost Spider BM25 penalty while keeping the BIRD BM25 benefit?
- Does scaling the backbone (e.g., Qwen2.5-32B/72B) widen or narrow MERIT's advantage over stateless repair, given that stronger models may already internalize the repair patterns MERIT retrieves?
- Can the schema-locality finding be exploited explicitly via a per-database memory index with bounded growth, and does that close the BIRD gap to Reflexion-style at lower cost?
- Since current-query attempts cannot be retrieved, does allowing limited intra-episode reuse of the best same-query prior attempt (with anti-leakage guards) help without violating the "causal" framing?
