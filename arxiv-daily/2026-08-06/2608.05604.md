> **一句话总结：** SkillZip 把 agent skill 库从"整包检索"重构为"带契约的 section 级过程图"，通过 MotifZip 把契约兼容的可复用子图可逆地压缩成宏、PathHydrate 按预算水合最小可执行上下文、ReZip 用执行证据增量维护，在 SkillsBench/ALFWorld 上相对最强基线 SkillDAG 最高提升 12.2 个点，同时达到 3.46× 压缩比、99.2% 依赖保持率与 98.7% 验证器可达率。

> **TL;DR:** SkillZip reframes agent skill libraries as source-grounded, contract-bearing section-level procedural graphs and compresses recurring contract-valid motifs into reversible macros (MotifZip), hydrating only the budget-closed executable subgraph per task (PathHydrate) and maintaining it incrementally from execution traces (ReZip). On SkillsBench with MiniMax-M2.7 it lifts task reward from SkillDAG's 27.3 to 33.3 (+6.0) and on ALFWorld from 67.1% to 79.3% (+12.2 points), while achieving a 3.46× compression ratio with 99.2% dependency preservation and 98.7% verifier reachability; at 100K skills its Ret@1 advantage over SkillDAG widens to 23.3 points.

## 核心贡献

- **统一 section 级过程单元**：提出 Sec2Graph，把每个 skill 包拆成带 9 种执行角色（Intent/Trigger/Input/Precondition/Operation/Resource/Failure/Verifier/Output）、源可追溯、携带 I/O 与验证器契约的 section 节点，并通过 typed 依赖边、skill 成员边、等价原型边构建过程图，从根本上消除"整包检索/文本压缩/事后建图"的单位错配。
- **契约保持的图压缩 MotifZip**：用 typed attributed graph grammar，仅在边界清晰、签名稳定、依赖闭合、验证器可达四项硬约束同时满足时，把反复出现的子图提升为可逆 ported 宏（可按 name/contract/outline/full source 四级水合），并给出组合式结构提升性质（命题 1）保证压缩-展开同构。
- **预算受限的可执行上下文水合 PathHydrate**：任务侧做 dual-level seed fusion（subgoal + raw-query 视图，配合 skill-doc 与 node-max 排序的 RRF 融合），再在压缩图上做约束子图搜索、scaffold 修复、按最低充分级别渲染宏；budget 是"选择额度"而非"必填配额"，水合在锚点覆盖、依赖闭合、验证器可达后即终止。
- **执行感知的增量维护 ReZip**：新 skill 先复用旧宏、未匹配残差进 buffer；残差在支持度≥m、增益>0、契约有效时晋升为新宏；用执行轨迹中的 expansion/verifier-failure/downstream-repair 信号做风险评分 ρ，超阈值时升级水合级别、拆分或退役高风险宏，始终保留源展开规则。
- **跨骨架、可扩展到 100K skill 的实证**：作为 plug-and-play 过程记忆层在 6 个 LLM 骨架上稳定改进；检索优势随库增大而扩大；离线结构构建在 100K skill（4.77M section 节点）上 178 秒完成。

## Key Contributions

- **Section-level procedural memory (Sec2Graph)**: Each skill package is opened into typed, source-grounded section nodes (nine execution roles) connected by typed dependency, membership, resource, and equivalence edges, with a procedural contract spanning interface, execution, and verification aspects. This unifies retrieval, compression, and execution over the same contract-bearing unit.
- **Contract-preserving macro compression (MotifZip)**: A typed graph grammar mines recurring motifs only inside interface-compatible buckets and accepts them as ported macros iff BoundaryClear ∧ SignatureStable ∧ DependencyClosed ∧ VerifierReachable. Macros carry typed ports, executable contracts, verifier hooks, and source pointers, and are scored by an MDL-style gain Δ(g) = freq·L(g) − L(Mg) − L(rule) + α·Reuse − λ·Cut − μ·Risk. Proposition 1 proves compositional structural lifting so ξ(κ(P)) ≅ P.
- **Budgeted executable hydration (PathHydrate)**: Dual-level seed fusion (subgoal and raw-query views, fused with skill-doc and node-max rankings via reciprocal-rank fusion) feeds a constrained connected-subgraph search; scaffold repair walks back/forward to close Input/Precondition/Resource and Failure/Verifier/Output; macros are rendered at the lowest sufficient level (name → contract → outline → full source) and expanded only when the contract is insufficient.
- **Execution-aware incremental maintenance (ReZip)**: New skills reuse existing macros, unmatched residuals buffer until cross-skill support ≥ m with positive gain and valid contract, and execution traces compute a macro risk score ρ = λe·(n_exp/n_use) + λv·(n_fail/n_use) + λd·(c_repair/n_use) that triggers hydration upgrade, split, or retirement while preserving the lifting invariant.
- **Comprehensive, plug-and-play evaluation**: Validated as a procedural-memory layer across six LLM backbones (MiniMax-M2.7, gpt-5.2-codex, Qwen 3.5, Kimi K2.5, Claude Sonnet 4.5, Gemini 3 Pro) on SkillsBench and ALFWorld, with scaling analyses from 200 to 100K skills and structural-fidelity audits (DPR/VR/recovery/downstream-inflation).

## Methodology

SkillZip replaces the conventional "retrieve-compress-execute" pipeline (operating on three different units: whole packages, text, and post-retrieval graphs) with a single contract-bearing section-level unit processed by four stages.

**Sec2Graph** segments a package using headings, lists, code blocks, warnings, argument descriptions, tool references, and tests as boundary cues, then assigns each candidate an execution role via a model-assisted parser. Each section node v = ⟨τ_v, c_v, X_v, Y_v, R_v, G_v, src_v⟩ carries typed I/O, resources, guards/verifiers, and a source pointer. Weak-order, dependency (Requires/Binds/UsesResource/Verifies/Repairs), skill-membership, resource, and equivalence edges connect them; a canonical prototype links contract-compatible occurrences without erasing occurrence identity. Nine operational roles are used: Intent, Trigger, Input, Precondition, Operation, Resource, Failure, Verifier, Output.

**MotifZip** avoids unrestricted frequent-subgraph mining by bucketing sections on role signature + resource family + I/O shape, growing candidates only along dependency and weak-order edges. For each supported motif it builds a contract (I_g, O_g, χ_g) and accepts it only after four hard checks (boundary clear, signature stable, dependency closed, verifier reachable). Accepted motifs become production rules M_g[I_g, O_g] ⇒ (V_g, E_g, π_g, χ_g) in a typed attributed graph grammar; rewriting removes internal nodes, inserts M_g, and reconnects external edges via the port map φ_ω, while expansion is the exact inverse. Candidates are rewritten greedily in descending Δ(g); the policy explicitly does not claim global optimality over overlapping motifs.

**PathHydrate** analyzes the query into a structured task object z_q = (g_q, O_q, Γ_q, I_q, D_q, {d_i}), scores sections by max{cos(e(d_i),e(v)), cos(e(q),e(v))}, builds two skill-level rankings fused by RRF, and solves a constrained objective P* = argmin η·T(P) + β|P| + γ·E(P) − δ·Match(P,q) subject to anchor coverage, dependency closure, verifier reachability, and T(P) ≤ B. Scaffold repair recovers Input/Precondition/Resource backward and Failure/Verifier/Output forward; context filling is sufficiency-gated (terminates once anchors covered, dependencies closed, verifier reachable). Rendering outputs intent, bound inputs, preconditions, hydrated operations, resources, guards, failure handlers, verifiers, and source expansion pointers — not concatenated snippets.

**ReZip** assimilates new skills by matching connected regions to existing macros via typed ports and the three contract aspects; unmatched regions enter a residual buffer B_res and are promoted to new macros only when support ≥ m, Δ > 0, and the contract is valid. Execution traces populate Σ_t(M) (uses, expansions, verifier failures, downstream repair cost) and yield a risk score ρ_t(M); when it exceeds threshold η, ReZip performs controlled demotion (raise hydration level, then split into narrower contract-compatible rules, then retire to source sections), always preserving source expansion so the lifting invariant used by PathHydrate survives.

## Results & Highlights

- **End-task performance (Table 1):** On SkillsBench with MiniMax-M2.7, SkillZip reaches 33.3 task reward vs SkillDAG 27.3 (+6.0) and Vector Skills 10.4 (+22.9); on ALFWorld with MiniMax-M2.7, 79.3% episode success vs SkillDAG 67.1% (+12.2 points) and Vector Skills 50.7%. With gpt-5.2-codex the gains are +6.2 on SkillsBench (43.0 vs 36.8) and +2.8 on ALFWorld (96.4% vs 93.6%, where SkillDAG/GoS already plateau at 93.6%).
- **Retrieval quality:** On SkillsBench (MiniMax-M2.7) SkillZip raises Ret@1 from SkillDAG's 66.7 to 73.6, Ret@5 from 78.2 to 92.0, and MRR by 10.0; on ALFWorld Ret@1 improves by 27.8 (MiniMax) / 30.3 (codex) points over SkillDAG.
- **Compression & structural fidelity (Table 2):** 3.46× compression ratio with DPR=99.2, VR=98.7, recovery=14.8%, reward=33.3, vs text compression (LLMLingua-2) at the same 3.46× ratio but DPR=65.0, VR=60.0, recovery=45.0%, reward=25.5 — i.e., SkillZip improves reward by 7.8 over text compression at equal compression.
- **Active storage (Table 4):** 71.0% reduction (18.6 MB → 5.4 MB) on the 1K-skill library while source packages (112.4 MB) remain for reversible expansion; removing contract checks saves only another 0.5 MB but raises fallback from 7.2% to 24.7% and downstream inflation from 2.7% to 23.4%.
- **Retrieval scalability (Table 6):** Ret@1 drops only 13.2 points (78.3 → 65.1) from 200 to 100K skills vs SkillDAG's 30.3-point drop (72.1 → 41.8); the gap widens from 6.2 to 23.3 points; similar-skill confusion stays at 12.4% (SkillZip) vs 48.2% (SkillDAG) at 100K; online retrieval+hydration latency 248.3 ms at 100K skills; offline MotifZip on 4.77M section nodes finishes in 178 s.
- **End-to-end cost (Table 11):** vs SkillDAG, total prompt processing −47.0% (2.78M → 1.47M tokens), completion tokens −35.5% (31,963 → 20,601), tool calls −21.7% (36.9 → 28.9), task time −21.1% (429.7s → 339.0s), while reward rises 27.3 → 33.3.
- **Context compactness (Figs. 5–6):** PathHydrate renders 1,941 tokens/task (median 1,947) against a 3,000-token budget — 72.1% fewer than top-5 whole-skill loading (6,958) and 88.8% fewer than top-12 (17,384); 51.7% of tasks use <2,000 tokens.
- **Cross-backbone (Table 14):** 2.0–3.2× relative reward gains over Vector Skills across six LLMs on SkillsBench (e.g., MiniMax 10.4→33.3, Claude Sonnet 4.5 26.2→52.4, Gemini 3 Pro 19.3→44.4).
- **Statistical reliability (Table 13):** Paired bootstrap 95% CIs exclude zero in all four settings; smallest gain +2.8 [0.4, 5.2] on ALFWorld/gpt-5.2-codex (p=.031), largest +12.2 [7.5, 16.8] on ALFWorld/MiniMax (p<.001).
- **Contract robustness (Table 5):** Under 10% synthetic contract corruption reward only drops 33.3 → 31.6 with DPR 96.8 / VR 95.1; at 40% corruption reward 24.1, VR 77.2, expansion 41.3%, fallback 34.7%. Contract extraction itself: 91.6 macro-F1, 84.6 exact match (source pointers easiest at 96.2/93.5, preconditions/guards hardest at 88.7/79.6).
- **Ablations (Table 3):** Removing section-level nodes costs −5.4 reward, −6.9 Ret@1, +59.9% context; removing MotifZip keeps DPR/VR perfect but +52.9% tokens and reward 31.0; removing dependency closure drops DPR to 82.3; removing verifier constraints drops VR to 76.4; removing adaptive hydration costs +33.3% tokens.
- **Streaming maintenance (Table 12):** ReZip matches full recompression (3.64× vs 3.71× CR, 33.2 vs 33.6 reward, 98.6 vs 99.1 VR) at 0.22× the cost and recovers injected contract drift in 1.4 batches on average, vs static graph degrading to 28.7 reward / 91.2 VR.

## Authors & Credibility

The work is a joint UNSW + CSIRO team (Xingyu Tan, Xiaoyang Wang, Wenjie Zhang at UNSW; Qing Liu, Xiwei Xu, Liming Zhu, Xin Yuan at CSIRO). The framing builds directly on the Agent Skills line of work and positions itself against very recent (2026) and credible baselines: Graph-of-Skills (GoS, arXiv:2604.05333), SkillDAG (arXiv:2606.03056), LLMLingua-2 (arXiv:2403.12968), SkillsBench (arXiv:2602.12670), ALFWorld, and SkillOps. The methodology is formal (typed attributed graph grammar, a stated and sketched Proposition 1 on compositional structural lifting, explicit closed-loop invariants) and the evaluation is unusually thorough: 18 research questions across the main text and appendices, paired bootstrap CIs and permutation tests over five runs, six LLM backbones, library scales from 200 to 100K skills, controlled procedural-overlap and contract-corruption studies, and deterministic verifiers for SkillsBench reward (verifier code withheld from all agents). The paper is honest about what MotifZip does not guarantee (no global optimality over overlapping motifs; Proposition 1 is structural not semantic — it does not establish correctness of the verifiers themselves).

## Critical Assessment

- **Novelty** is genuine and well-motivated: the "unit mismatch" framing (retrieve packages / compress text / build graphs post-retrieval) is a real diagnosis, and the contract-preserving graph grammar with four hard acceptance checks (BoundaryClear, SignatureStable, DependencyClosed, VerifierReachable) plus reversible ported macros is a concrete, non-trivial mechanism — not just another prompt-compression variant. The idea of rendering macros at four hydration levels (name/contract/outline/full source) and expanding lazily is a clean contribution over progressive-disclosure systems that operate only at package granularity.
- **Rigor** is the paper's main strength. Every claim has a structural counterpart metric (DPR, VR, expansion, fallback, downstream inflation) designed precisely to catch the failure mode where compression just pushes missing information downstream. The DI metric (paired against raw-graph execution) and the recovery-vs-storage audit (Table 4) are exactly the right controls. The controlled-overlap experiment (Table 7) isolates the compression mechanism from task difficulty, and the contract-corruption sweep (Table 5) stress-tests the assumed bottleneck.
- **Reproducibility** is high on the deterministic parts: the paper releases algorithm pseudocode for all four modules (Appendix A), discloses all hyperparameters (α=0.5, λ=0.3, μ=0.2, η=0.4, β=γ=δ=0.2), the encoder (BGE-M3), budget caps, decoding settings, and exact benchmark splits. The weak link is LLM-assisted contract extraction (Sec2Graph), which is provider-dependent and only cached after construction; the paper does not release the extraction prompts' model identity per-run and the 88.7 F1 on preconditions/guards is a real ceiling on fidelity.
- **Significance** is strong for the agent-skills subfield: a 12.2-point ALFWorld gain over SkillDAG and a 23.3-point Ret@1 gap at 100K skills are large enough to matter, and the 47% end-to-end prompt reduction with *higher* reward is the kind of result that could change how skill libraries are built. The result that even Claude Sonnet 4.5 and gpt-5.2-codex benefit by 2.0× over Vector Skills is important evidence that stronger executors do not erase the granularity-mismatch penalty.
- **Red flags / weaknesses worth naming:**
  - Only two benchmarks (SkillsBench, ALFWorld). Both are skill-friendly; there is no evaluation on, e.g., SWE-Bench-style software engineering, multi-step math/tool-use, or open-ended web agent tasks where procedural contracts look very different.
  - The ALFWorld gpt-5.2-codex gain (+2.8, 93.6→96.4) is close to ceiling and the CI just excludes zero ([0.4, 5.2], p=.031) — the headline "up to 12.2 points" is the MiniMax/ALFWorld number, the easiest non-trivial setting; readers should not assume that magnitude generalizes.
  - The named failure attribution (Fig. 7) concedes SkillZip-controlled stages still cause 58% of remaining failures (retrieval 26%, contract extraction 18%, hydration 14%), so the framework's own bottleneck is the dominant remaining error source — the paper is commendably honest about this but it tempers the "solved" framing.
  - Contract extraction is the load-bearing assumption: at 40% corruption reward collapses to 24.1 and VR to 77.2, yet the only mitigation proposed is conservative re-expansion. There is no learned or calibrated confidence-aware extraction; the Risk(g) term inside MotifZip scores motifs, not the underlying field quality.
  - MotifZip's greedy, non-overlapping rewrite explicitly disclaims global optimality; no approximation bound is given, and the description-length gain Δ(g) has four hand-tuned weights whose sensitivity is not reported.
  - The "100K skills" scaling uses 4.77M section nodes but the added packages beyond 2K are "not paired with evaluation queries and serve only as retrieval distractors" — so the scaling claim is about distractor robustness, not about true 100K-skill task coverage.

## Strengths

- Diagnoses a precise, structural problem (unit mismatch across retrieve/compress/execute) and solves it with one unified representation rather than three stacked heuristics.
- Contract preservation is enforced as hard constraints with explicit, measured structural metrics (DPR/VR/recovery/DI), not assumed — the evaluation is designed to falsify the paper's own claim.
- Reversible macros with four hydration levels give a clean compression-expansion duality backed by Proposition 1, and PathHydrate's sufficiency-gated filling (terminate when anchors covered, dependencies closed, verifier reachable) avoids greedy fill-to-budget.
- ReZip closes the loop with execution evidence (risk-driven demotion/split/retire), addressing the maintenance problem most one-shot compressors ignore.
- Exceptionally thorough experimental matrix: scaling, overlap sensitivity, domain partitioning, budget sensitivity, streaming maintenance, repeated-run statistics, six backbones, and failure attribution.
- Plug-and-play across six LLM backbones without backbone-specific fine-tuning, and the largest gains accrue to weaker executors — a practical, deployable property.

## Limitations

- Benchmark coverage is narrow (SkillsBench + ALFWorld only); generalization to code-centric, web-agent, or long-horizon reasoning settings is unverified.
- LLM-assisted contract extraction is the fragile foundation: preconditions/guards F1 is only 88.7, and 40% field corruption collapses reward by 9.2 points and VR by 21.5 points. No confidence-aware or self-correcting extraction is proposed.
- The headline 12.2-point gain is the best case (MiniMax/ALFWorld); on the strongest backbone (gpt-5.2-codex/ALFWorld) the gain is 2.8 points with a CI that barely excludes zero.
- 100K-skill scaling adds distractor-only packages, so it tests retrieval ambiguity under scale rather than true large-library task success.
- MotifZip is greedy with no optimality bound and four un-sensitivity-analyzed weights (α, λ, μ, η).
- Proposition 1 is structural, not semantic — it guarantees recovery of recorded contracts, not correctness of the verifiers themselves or equivalence of unrecorded behavior.
- Offline LLM extraction cost is excluded from the scaling table and is provider-dependent; amortization assumptions for a production library are not quantified.
- Retrieval (26%) and contract extraction (18%) remain the largest failure sources inside SkillZip's own scope, indicating the framework's ceiling is still internal.

## Relevance

对关注 LLM agent 技能库/程序性记忆的研究兴趣高度相关：SkillZip 直接解决"技能库扩张后如何检索、压缩、维护可执行过程"这一核心问题，其 section 级契约图、可逆宏压缩与执行证据驱动维护的思路，对构建可扩展、可验证的 agent 基础设施具有直接参考价值，尤其在技能检索与图压缩方向上提供了可复用的形式化框架。

## Questions for Further Exploration

- Can contract extraction be made self-correcting — e.g., by having the executor flag verifier failures back to Sec2Graph to re-extract the missing guard, closing the loop at the field level rather than only at the macro level?
- How does SkillZip behave on code-centric benchmarks (SWE-Bench, RepoBench) where sections are functions/tests rather than natural-language instructions, and where verifiers are executable test suites?
- What is the sensitivity of MotifZip's selection to the four weights (α, λ, μ, η), and is there a principled (e.g., Bayesian or bandit) way to set them per-library?
- Does the four-level hydration (name/contract/outline/full source) generalize to a learned policy that predicts the right level from task features instead of expanding reactively on contract failure?
- Can the framework handle conflicting verifiers across skills (same operation, different success conditions) without silently picking one — i.e., is there a contract-conflict detector before macro acceptance?
- How much of the 47% end-to-end prompt reduction is due to fewer agent turns (trajectory shortening) vs. smaller per-turn context, and does the split hold for multi-skill tasks where breadth-fill dominates?
- Could the typed graph grammar be extended with learned motif proposals (e.g., from execution traces) rather than relying on interface-bucketed structural mining, to capture reusable procedures that are not textually recurring?
