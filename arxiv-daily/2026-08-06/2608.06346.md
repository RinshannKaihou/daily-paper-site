> **一句话总结：** 针对 LLM 智能体失败轨迹定位"关键错误步骤"的难题，TRAJDEBUG 提出三阶段"错误生命周期追踪"框架（多粒度历史压缩 + 证据驱动触发检测 + 错误状态分类 + 候选集归因），并构建了 486 条人工标注的 TrajErrBench 基准；平均准确率达 34.11%，比同骨干直接提示（25.69%）提升 +8.42，在长轨迹（119.7 步）场景优势更明显，反馈式应用可把下游成功率提升约 5.7%–10.8%。

> **TL;DR:** TRAJDEBUG reframes critical-error detection in failed LLM-agent trajectories as an error-lifecycle tracing problem with three stages (evidence-grounded trigger detection, error-state classification over four states, candidate-set-guided causal attribution) on top of multi-granularity history compression. On a new 486-trajectory TrajErrBench (400 from τ²-Bench, 86 from SWE-Bench Pro, ~119.7 steps) plus AgentDebugBench/WhoAndWhen, it reaches 34.11% macro-average exact-step accuracy vs. 25.69% for direct prompting with the same Qwen3-235B-A22B-Thinking backbone (+8.42 absolute), stays above 20% on the 141+ step bucket where the best baseline drops to ~14%, and its feedback lifts GLM-5.1 task success by 10.80% (per-trajectory repair) and 5.70% (cross-trajectory failure-memory transfer).

## 核心贡献

- 提出基于"错误生命周期（error lifecycle）"视角的 TRAJDEBUG 框架，将关键错误检测从"对整条轨迹做一次端到端判断"重新分解为三个可控阶段：证据驱动触发检测、错误状态分类、候选集因果归因，缓解长上下文和多局部错误共同造成的歧义。
- 设计多粒度历史压缩（th1/th2/th3，分别约 3000/1200/600 字符），在不丢失本地证据的前提下压缩远端上下文，使每个阶段按需检索最细粒度视图。
- 提出基于"引用对象（reference object）"的对象锚定错误实例聚类，并用四类错误状态（Clean Resolution / Costly Resolution / Manifest Active / Latent Active）区分"已修复/无影响"与"对最终失败有终态影响"的错误，把候选集合 F(τ) 限制到真正可能致命的实例。
- 构建并发布 TrajErrBench：486 条人工标注的失败轨迹（400 来自 τ²-Bench，86 来自 SWE-Bench Pro），覆盖现实工具交互与长程代码任务，平均长度 29.3 与 119.7 步；关键错误标注在 τ²-Bench 上 Fleiss' κ=0.91（接近完美一致），SWE-Bench Pro 上 κ=0.67。
- 通过两个应用场景证明诊断可落地：每条失败转反馈注入后重跑同一任务平均成功率提升 10.80%；将少量历史失败诊断聚合为"失败记忆"迁移到未见任务，平均提升 5.70%。

## Key Contributions

- An error-lifecycle tracing framework (TRAJDEBUG) that decomposes critical-error detection into three auditable stages — evidence-grounded error trigger detection, object-anchored error-state classification, and candidate-set-guided causal attribution — instead of one brittle end-to-end judgment over the full trajectory.
- A multi-granularity compression scheme that produces three views per step (th1 ≤ 3000 chars / th2 ≤ 1200 / th3 ≤ 600) and lets each downstream stage retrieve the finest detail it needs, preserving local evidence while compressing distant context.
- An object-anchored error-instance clustering (by shared violated reference object) and a four-state error taxonomy (Clean Resolution, Costly Resolution, Manifest Active, Latent Active) that filters to terminal-relevant candidates F(τ).
- TrajErrBench: 486 manually annotated failed trajectories from τ²-Bench (airline/retail) and SWE-Bench Pro, with inter-annotator Fleiss' κ of 0.91 (τ²-Bench) and 0.67 (SWE-Bench Pro) for the critical-error step.
- Two application studies showing the diagnosis is actionable: per-trajectory feedback injection lifts average success by 10.80%; aggregated failure-memory transfer improves held-out tasks by 5.70% on average.

## Methodology

TRAJDEBUG takes a failed trajectory τ = (x₁ … x_N) and finds the critical (earliest decisive) error step through an error-lifecycle pipeline:

1. **Multi-granularity compression (§3.1).** For each step, an LLM produces three views: th1 keeps instruction/action/observation and locally relevant reasoning (≤3000 chars), th2 keeps the main intent and state update (≤1200), th3 keeps only coarse progress and salient entities (≤600). The detector uses th1 for the current step and the previous two, th2 for steps 3–5 away, th3 for the distant past.

2. **Error trigger detection (§3.2).** For each step, the detector extracts atomic triggers e = (t, c, p, q_w, q_r) where q_w is an erroneous commitment in the current step and q_r is a verbatim-citable violated reference. The reference category c ∈ {Task Conflict, History Conflict, Intra-Step Conflict, Environment Anomaly}; the execution phase p ∈ {planning, reasoning, action, observation, verification}. A hard verbatim-evidence condition requires both q_w and q_r to be explicitly quotable, otherwise the trigger is discarded — this is the anti-hallucination guard.

3. **Error state classification (§3.3).** Triggers sharing the same violated reference object O are clustered into an instance E = (E, O), avoiding double-counting a constraint violation that surfaces in planning/action/verification. Each instance is labelled along two axes: (i) resolved vs. active (only later explicit re-visiting of O with citable supersession counts as resolved); (ii) terminal footprint — irreversible state change, semantic footprint in the terminal state, or budget debt (resolved only after consuming >k% of the trajectory, k=50). The cross product yields four states: Clean Resolution, Costly Resolution, Manifest Active, Latent Active. Only Costly Resolution and Manifest Active instances survive into F(τ).

4. **Candidate-set-guided causal attribution (§3.4).** An LLM attribution head selects from F(τ) the instance whose origin step best explains the terminal failure, explicitly not using temporal-earliest as a tie-breaker (an earlier budget-debt instance is not automatically chosen over a later semantic instance unless the wasted budget plausibly prevented avoiding the later failure). A strict out-of-set prediction path is allowed only when the model can produce the missing trigger, reference, origin step, and terminal footprint.

Implementation: Qwen3-235B-A22B-Thinking as the backbone for TRAJDEBUG and all multi-agent baselines; temperature 0. TrajErrBench construction: 400 τ²-Bench rollouts (DeepSeek-Reasoner/GPT-5/Qwen3-Max) and 86 SWE-Bench Pro rollouts (Claude-Opus-4-6, Kimi-K2.6-Coding, Gemini-3.1-Pro, Grok-4.20-Beta, GPT-5.4 via OpenHands). Human labels come from 20 trained annotators (3 per trajectory, majority vote), supported by model-assisted pre-annotations from GPT-5.4/Gemini-3.1-Pro/Claude-Opus-4-6 whose exact-match with the final human label ranges 48.8%–76.8%.

## Results & Highlights

- **Critical-step detection (macro-avg over 7 datasets):** TRAJDEBUG reaches **34.11%** vs. **25.69%** for direct prompting with the same Qwen3-235B-A22B-Thinking backbone (**+8.42 absolute**), and beats every frontier direct-prompting baseline (best: Gemini-3.1-Pro at 31.29%) and every multi-agent system (AgentDebugger 23.72%, CHIEF 18.77%, AgentRX 23.10%).
- **Longest-horizon wins:** On ALFWorld (avg 60.0 steps) TRAJDEBUG scores 26.00 vs. direct-prompting 13.00 (**+13.00**); on SWE-Bench Pro (avg 119.7 steps) it scores 24.41 vs. direct-prompting 17.44 (**+6.97**). On the new TrajErrBench subsets it scores **52.75 (τ²-Bench)** and **24.41 (SWE-Bench Pro)**.
- **Length robustness (Fig. 5):** across length buckets (1-35 / 36-70 / 71-105 / 106-140 / 141+ steps, n=534/237/35/35/28), baselines collapse from 35–50% on short trajectories to below 15% on the longest bucket, while TRAJDEBUG retains **over 20%** accuracy on the 141+ bucket where the best baseline drops to ~14%.
- **Ablation (Table 2):** removing multi-granularity compression cuts AVG from 38.58 → 17.56 (**−21.02 points**); removing evidence-grounded triggers → 33.59 (−4.99); removing state classification → 31.27 (−7.31); removing all → 30.10. On SWE-Bench Pro, dropping state classification falls to 16.28, *below* the direct-prompting baseline (17.44), confirming the state filter is the key to disambiguating many coexisting local errors.
- **Downstream agent improvement (Table 3, GLM-5.1 actor on Airline/Retail/SWE-Bench):** per-trajectory oracle-repair raises average success from 78.07 → **88.87** with TRAJDEBUG feedback (+10.80 avg), beating Vanilla Debug (85.57) and Self-Reflection (85.57); the largest single-task gain is **Retail +11.40** (84.21 → 95.61). In the more realistic failure-memory transfer setting (no per-instance oracle, held-out split), TRAJDEBUG adds **+6.06 / +6.57 / +4.48** across Airline/Retail/SWE-Bench (avg +5.70), whereas Vanilla Debug *hurts* Airline by −3.03 and Self-Reflection *hurts* Retail by −1.32.
- **Benchmark annotation quality:** TrajErrBench critical-step Fleiss' κ = 0.91 on τ²-Bench (near-perfect) and 0.67 on SWE-Bench Pro (substantial); majority-vote yields usable labels on 98.2% / 91.9% of trajectories.
- **Failure-mode statistics from TrajErrBench:** reasoning is the dominant failure phase in both subsets (**60.7%** in τ²-Bench, **57.1%** in SWE-Bench Pro); on SWE-Bench Pro the single subtype `reason.WrongChoice` accounts for **40.7%** of critical errors, and `verify.NoVerification` for 9.3%.

## Critical Assessment

- **Novelty (genuine).** The error-lifecycle decomposition is a real reframing. The most novel piece is the four-state classification (Clean/Costly Resolution vs. Manifest/Latent Active) with the *terminal footprint* axis — most prior attribution work either stops at candidate detection (AgentRX, AgentDebugger) or uses graph connectedness as a proxy for terminal responsibility (CHIEF, AgentTrace). The paper itself supplies the killer piece of evidence for this: without state classification on SWE-Bench Pro, accuracy falls to **16.28, *below* the 17.44 direct-prompting baseline**, i.e. the candidate detector alone is net-negative on long coding trajectories with many coexisting local errors — exactly the failure mode the paper predicts in §2.3.
- **Rigor (mixed-positive).** Strong points: all multi-agent baselines run on the *same* Qwen3-235B-A22B-Thinking backbone at temperature 0; annotation uses 3 annotators with majority vote and reports Fleiss' κ; the pilot study (§2) quantifies the two motivating challenges (length → accuracy decay; 7.62 local errors per failed trajectory, 61.9% of which get repaired) instead of just asserting them. Weak points:
  - **Absolute numbers are low.** Even the best system finds the exact critical step only 34% of the time overall and 24% on SWE-Bench Pro. The downstream gains partly hinge on the gap between "best detector" and "mediocre detector" being small enough that even imperfect feedback helps — which is plausible but under-powered given the per-task sample sizes (100 SWE-Bench Verified rollouts, two τ²-Bench subsets).
  - **Anchoring risk in TrajErrBench.** Annotators were given model-assisted pre-annotations from GPT-5.4/Gemini-3.1-Pro/Claude-Opus-4-6 *plus* the full benchmark failure signal (database constraints for τ²-Bench, failing test cases for SWE-Bench Pro). The reported model-vs-human exact-match (48.8%–76.8%) suggests meaningful but not dominant anchoring; the paper honestly discloses this but does not run an anchoring-free control.
  - **SWE-Bench Pro subset shrank from 110 → 86** by dropping trajectories where no two annotators agreed — a defensible but reviewer-worthy pruning step that may inflate κ.
  - **Self-evaluation of "resolved".** Whether a wrong commitment is resolved (and hence whether an instance leaves F(τ)) is itself an LLM judgment that can cascade errors into the candidate set; the paper acknowledges this as a limitation ("staged pipeline may inherit false negatives") but only allows out-of-set predictions "under strict evidence requirements" — no quantitative bound on how often this path fires.
- **Reproducibility (good).** MIT-licensed release promised; backbone, temperature, compression character budgets (3000/1200/600), budget-debt threshold (k=50%), and full system prompts are all disclosed; all datasets used (τ²-Bench, SWE-Bench Pro, WhoAndWhen, AgentDebugBench) are public.
- **Significance (moderate-high).** The downstream application framing — critical-error diagnosis as an inference-time feedback interface rather than a standalone benchmark scorecard — is the most valuable contribution, and the failure-memory transfer experiment (which works on held-out tasks with no per-instance oracle) is the harder and more realistic test. If it holds up at scale, it directly affects how agent teams triage rollouts.
- **Red flags.** None severe. One minor: the abstract's "best overall performance over existing baselines" is true but obscures that TRAJDEBUG is out-scored on individual columns (e.g., GLM-5.1 direct prompting wins WebShop at 26.00 vs. TRAJDEBUG 26.00 tied, and Gemini-3.1-Pro wins the WhoAndWhen-Hand-Crafted column with 20.69 vs. TRAJDEBUG 22.41 — actually TRAJDEBUG wins that one; but on WebShop several direct-prompting models tie or approach it). The macro-average is the honest metric and they report it correctly.

## Strengths

- The error-lifecycle taxonomy (four states along resolved × footprint axes) is a clean, reusable abstraction that directly addresses the "multiple local errors with different downstream effects" problem most prior work hand-waves.
- Evidence-grounded trigger detection with a hard verbatim-citation requirement is a principled anti-hallucination guard, and the ablation quantifies its contribution (+4.99 AVG).
- Multi-granularity compression is the single largest contributor (+21.02 AVG when removed) and a transferable technique beyond this paper.
- Honest about limitations: explicitly notes the pipeline can inherit false negatives from earlier stages, and that it still relies on LLM judgment for final attribution.
- Includes both an idealized (per-trajectory oracle) and a realistic (cross-trajectory transfer) downstream evaluation — the latter is rare in this literature.
- Comprehensive related work positioning TRAJDEBUG against prompt-based, taxonomy-based, replay/spectrum-based, and graph-based attribution methods.

## Limitations

- All stages still depend on LLM reasoning; the authors implemented with an open-source backbone (Qwen3-235B-A22B) to mitigate "stronger judge" concerns, but frontier models might change the ranking.
- The staged design means trigger-detection false negatives cannot be recovered except via a strict out-of-set path; no upper bound on missed critical errors is reported.
- TrajErrBench is concentrated in two domains (customer-service tool use, Python repo repair); coverage of scientific, mathematical, or multi-modal agent failures is absent.
- Downstream experiments use small samples (two τ²-Bench subsets, 100 SWE-Bench Verified rollouts) and a single actor (GLM-5.1); the reported 5.70%–10.80% improvements come without confidence intervals or significance tests.
- Budget-debt threshold (k=50%) and compression character budgets (3000/1200/600) are hand-set hyperparameters with no sensitivity sweep.
- Annotation anchoring on model pre-annotations is disclosed but not controlled for.

## Relevance

This work sits squarely in the user's interest in LLM-agent failure analysis, trajectory debugging, and benchmark construction. The error-lifecycle framing and the TrajErrBench data are directly reusable for building self-improving agents and for evaluating process-supervision methods, which aligns with current research on agent reliability and post-hoc diagnosis.

## Questions for Further Exploration

- How much of TRAJDEBUG's gain over direct prompting is simply from the multi-granularity compression (the +21.02 ablation), and would giving direct-prompting baselines the same compressed trajectory close the gap further?
- Can the four-state classifier be distilled into a smaller/cheaper model so the full pipeline runs within a single agent rollout budget rather than as post-hoc analysis?
- How sensitive is TrajErrBench difficulty to the model-assisted pre-annotation anchoring — would a from-scratch human annotation produce harder or easier labels?
- Does the failure-memory transfer result (avg +5.70%) hold when the actor is a frontier model (e.g., GPT-5.4, Claude Opus 4.6) rather than GLM-5.1, where the marginal room for improvement is smaller?
- The reasoning phase accounts for 57–61% of critical errors in both subsets — can the trigger taxonomy's `reason.InvalidInference` / `reason.WrongChoice` / `reason.MissingAssumptionCheck` subtypes be turned into online guardrails that fire at generation time rather than post-hoc?
- Is the candidate-set-guided attribution head's "not just earliest" rule robust to adversarial trajectories where the earliest local error *is* the principal cause but is also a budget-debt instance?
